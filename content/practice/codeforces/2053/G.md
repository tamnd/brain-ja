 ## 解決策
 ## 問題の理解

 各テスト ケースには 2 つの文字列が与えられます。`s`長さの`n`そして文字列`t`長さの`m`。 課題は、すべての分割方法を検討することです`s`プレフィックスに`x`そして接尾語`y`位置で`1`を通して`n-1`、分割ごとに、文字列が`t`のみの連結として書くことができます`x`そして`y`。 形式的には、それぞれが次のいずれかに等しい一連の文字列が存在するかどうかを知りたいのです。`x`または`y`、連結すると生成される`t`。 出力は長さのバイナリ文字列です。`n-1`、ここで、`1`はその位置での分割が「美しい」ことを示し、`0`さもないと。 

この制約により、強引なアプローチが困難になります。 長さの合計は、`t`すべてのテストケースにわたって、$10^7$、個々の文字列は長さに達する可能性があります$5 \cdot 10^6$。 これにより、可能性のあるすべての部分文字列をチェックするアルゴリズムが即座に除外されます。`t`～との平等のために`x`または`y`ネストされたループ内 (必要になる場合がある)$O(nm)$テストケースごとの操作が遅すぎます。 長さにわたって線形またはほぼ線形に機能するソリューションが必要です。`t`。 

微妙なエッジケースには、次のような状況が含まれます。`x`または`y`は空です (ここでは不可能です`1 \le i < n`) またはどこ`x`そして`y`内部で複雑に重なり合う`t`。 例えば、`s = "aa"`そして`t = "aaaa"`最初の文字の後に分割すると次の結果が得られることを示しています`x = "a"`、`y = "a"`、それは些細なことです。 不用意に実装すると、次の処理を反復しようとする可能性があります。`t`固定増分では、ある部分文字列が別の部分文字列の途中で始まる部分の重複が欠落します。 

## アプローチ

 素朴なアプローチでは、すべての分割を反復することになります。`s`、 抽出する`x`そして`y`、再構築を試みます`t`マッチングを繰り返すことで`x`または`y`最初から。 これは文字通り定義を実装しているため正しいですが、時間がかかる場合があります。$O(n \cdot m / n) = O(m)$分割ごとに、次のようになります$O(n m)$テストケースごとの全体的な。 最大長の場合、これは次の値に達する可能性があります$10^{13}$実行可能性をはるかに超えた操作。 

最適なアプローチでは、文字列ハッシュを活用して、文字列の任意の部分文字列を迅速に比較します。`t`と`x`または`y`。 ローリングハッシュを事前計算することで、`t`可能なすべてのハッシュ`x`そして`y`の部分文字列かどうかを確認できます。`t`マッチ`x`または`y`一定時間内に。 反復処理`t`、現在位置を次のいずれかに一致させようとします。`x`または`y`貪欲に：もし`x`一致すると、次のように進みます`len(x)`; そうでない場合は、チェックしてください`y`。 どちらも一致しない場合、分割は美しくありません。 これにより、複雑さが軽減されます。$O(n m)$に$O(m + n)$テストケースごとに。 ハッシュの事前計算とローリング検証により、重複する出現も正しく検出されます。 

重要な洞察は、`x`そして`y`部分文字列を定数時間で比較できるようになると、左から右に貪欲に一致させることができます。 ハッシュにより、部分文字列の比較が保証されます。$O(1)$衝突確率は無視でき、制約に適合します。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに文字列を読み取ります。`s`そして`t`そして長さを計算します`n`そして`m`。 
2. ローリングハッシュを事前計算します。`t`そのため、任意の部分文字列ハッシュを一定時間内に取得できます。 衝突確率を下げるには、大きな素数係数と基本値を使用します。 また、高速ハッシュ計算のためにベースの累乗を事前計算します。 
3. すべての分割を反復処理します。`s`位置で`i = 1`に`n-1`。 抽出する`x = s[0:i]`そして`y = s[i:n]`。 
4. のハッシュを計算します。`x`そして`y`。 
5. 最初から始める`t`。 各位置で、このインデックスで始まる部分文字列が一致するかどうかを確認します。`x`ハッシュを比較することによって。 一致する場合、インデックスを増分します。`len(x)`そして続けます。 それ以外の場合は、一致するかどうかを確認します`y`; 存在する場合は、増加します`len(y)`。 どちらも一致しない場合は、この分割を美しくないとマークし、分割します。 
6. 終了した場合`t`マッチングのみで到達`x`または`y`、この分割を美しいとマークします。 
7. 追加`1`または`0`このテストケースの結果文字列に。 
8. すべてのテスト ケースのすべての分割を処理した後、結果文字列を出力します。 

なぜ機能するのか: 貪欲な左から右へのマッチングは有効です。`x`そして`y`どちらかでしか始められない`x`または`y`。 ローリング ハッシュにより、定数時間の部分文字列チェックが可能になり、正確性が保証されます。 どこかの時点で不一致が発生した場合、その位置から始まる有効な連結は存在しないため、分割は美しくないと正しくマークされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
BASE = 31

def compute_hash_and_powers(s):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)
    for i in range(n):
        h[i+1] = (h[i] * BASE + ord(s[i]) - ord('a') + 1) % MOD
        p[i+1] = (p[i] * BASE) % MOD
    return h, p

def substring_hash(h, p, l, r):
    return (h[r] - h[l] * p[r-l]) % MOD

def is_beautiful(x, y, t, th, tp):
    i = 0
    lx, ly = len(x), len(y)
    hx = 0
    for c in x:
        hx = (hx * BASE + ord(c) - ord('a') + 1) % MOD
    hy = 0
    for c in y:
        hy = (hy * BASE + ord(c) - ord('a') + 1) % MOD
    m = len(t)
    while i < m:
        if i + lx <= m and substring_hash(th, tp, i, i+lx) == hx:
            i += lx
        elif i + ly <= m and substring_hash(th, tp, i, i+ly) == hy:
            i += ly
        else:
            return False
    return True

T = int(input())
for _ in range(T):
    n, m = map(int, input().split())
    s = input().strip()
    t = input().strip()
    th, tp = compute_hash_and_powers(t)
    res = []
    for i in range(1, n):
        x, y = s[:i], s[i:]
        if is_beautiful(x, y, t, th, tp):
            res.append('1')
        else:
            res.append('0')
    print(''.join(res))
```このソリューションは、複数のテスト ケースを慎重に処理します。 事前に計算された基数の累乗により、効率的な部分文字列ハッシュの計算が可能になります。 マッチングは貪欲に行われ、モジュロによって整数がオーバーフローしないことが保証されます。 端に到達するなどのエッジ条件`t`、ループ条件によって自然に処理されます。
