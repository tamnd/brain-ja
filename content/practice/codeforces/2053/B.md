 ## 問題の理解

 一連のインプレッションが与えられ、各インプレッションは可能な整数値の範囲で表されます。 エリックが覚えているのは、$i$-この印象は中間のどこかにあります$l_i$そして$r_i$。 課題は、他のインプレッションが同じ値をとらないように、インプレッションごとに値を割り当てることが可能かどうかを判断することです。 言い換えれば、各インプレッションについて、その特定のインプレッションを一意にするすべてのインプレッションの実行可能な割り当てが存在するかどうかを判断する必要があります。 

制約はかなり大きく、最大で$2 \cdot 10^5$すべてのテストケースにわたるインプレッション数。各範囲は最大で$2n$。 これにより、可能なすべての割り当てを明示的に試行しようとするアプローチは除外されます。これは、組み合わせの爆発につながる可能性があるためです。 ナイーブ$O(n^2)$アプローチ - すべての潜在的な値をテストすることで、各インプレッションを他のすべてのインプレッションと比較してチェックする - おおよそのパフォーマンスが得られます$10^{10}$最悪の場合の操作は許容範囲をはるかに超えています。 この問題には、よりスマートな、線形または線形に近い解決策が必要です。 

不注意な実装に陥る可能性のあるエッジケースには、同じ値に強制されるインプレッションが含まれます。たとえば、2 つのインプレッションが両方とも範囲内にある場合などです。$[1, 1]$、独自性が不可能になります。 もう 1 つの注意が必要なシナリオは、範囲が重複しているが、1 つのインプレッションが他のインプレッションよりもはるかに狭い場合です。 素朴で貪欲な割り当ては、正しく処理されれば狭い割り当てを常に分離できることに気づかない可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、各インプレッションの範囲内で可能な値の割り当てをすべて生成し、特定のインプレッションを一意にできるかどうかを確認します。 これは考えられるすべてのシナリオを検討するため、原理的には正しいですが、中程度の範囲サイズの適度な数のインプレッションでも指数関数的に多くの組み合わせが生成されるため、完全に非現実的です。 

重要な洞察は、インプレッションを最小値と最大値の境界で分類すると、すべての割り当てを列挙するのではなく、極値に基づいて一意性を推論できることに気づくことから得られます。 具体的には、インプレッションの範囲が、取り得るすべての数値を「消費」する他の範囲で完全にカバーされている場合、そのインプレッションは一意ではないことが保証されます。 逆に、その範囲内に他のインプレッションが同時に占有することができない値が少なくとも 1 つ存在する場合、その値を一意にすることができます。 

左から右および右から左の両方で上限の最小値と下限の最大値を追跡することで、各インプレッションが他のすべてのインプレッションと衝突しない値を持つかどうかを迅速に判断できます。 これにより、問題は組み合わせ検索ではなく並べ替えと線形スイープに限定されます。

 | ブルートフォース | O((2n)^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のテスト ケースのすべてのインプレッションを読み取り、それらを次のペアとして保存します。`(l_i, r_i)`元のインデックスと一緒に。 元のインデックスを保持することは、入力順序で出力を再構築するために不可欠です。 
2. インプレッションを最小値で並べ替えます`l_i`。 これにより、各インプレッションが他のインプレッションと比較して取り得る最も早い値を推測することができます。 
3. 2 つの配列を構築する`prefix_max_l`そして`suffix_min_r`。 の`prefix_max_l[i]`最大値を保存します`l_j`インデックスの左側またはインデックスにあるすべてのインプレッションに対して`i`。 の`suffix_min_r[i]`最低限のものを収納する`r_j`右側またはインデックスにあるすべてのインプレッションに対して`i`。 これらの配列は、範囲の実現可能な重複を効率的に要約します。 
4. それぞれの印象について`i`、一意の値を割り当てることができるかどうかを判断します。 これを行うには、範囲内に番号が存在するかどうかを確認します。`[l_i, r_i]`それは他の印象ではカバーされません。 これは要するに比較することになります`l_i`以前のすべての下限の最大値 (`prefix_max_l`） そして`r_i`後続のすべての上限の最小値 (`suffix_min_r`）。 もし`l_i`残りの最大下限より大きい、または`r_i`が残りの最小上限よりも小さい場合、印象を独特にすることができます。 
5. 固有のインプレッションの場合は「1」を書き込み、それ以外の場合は「0」を書き込み、元の入力順序を復元して出力文字列を構築します。 

機能する理由: このアルゴリズムは、インプレッションごとに、その範囲内に他のすべての範囲と競合しない整数が少なくとも 1 つ存在するかどうかを効果的にチェックします。 プレフィックスの最大値とサフィックスの最小値を事前に計算することで、他のすべてのインプレッションを繰り返しスキャンすることを回避し、効率を維持しながら正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        impressions = []
        for i in range(n):
            l, r = map(int, input().split())
            impressions.append((l, r, i))

        # Sort by left boundary
        impressions.sort()
        prefix_max_l = [0] * n
        suffix_min_r = [0] * n

        prefix_max_l[0] = impressions[0][0]
        for i in range(1, n):
            prefix_max_l[i] = max(prefix_max_l[i-1], impressions[i][0])

        suffix_min_r[-1] = impressions[-1][1]
        for i in range(n-2, -1, -1):
            suffix_min_r[i] = min(suffix_min_r[i+1], impressions[i][1])

        res = ['0'] * n
        for i in range(n):
            l, r, idx = impressions[i]
            left_ok = i == 0 or l > prefix_max_l[i-1]
            right_ok = i == n-1 or r < suffix_min_r[i+1]
            if left_ok or right_ok:
                res[idx] = '1'

        print(''.join(res))

solve()
```コードは、次を使用して入力をすばやく読み取ります。`sys.stdin.readline`。 各インプレッションは、出力順序を維持するために元のインデックスとともに保存されます。 並べ替え順`l_i`これにより、現在のインプレッションに対する他のすべてのインプレッションの影響を効率的に要約するプレフィックス最大値とサフィックス最小値を構築できます。 一意性をチェックする場合、現在のものと比較します。`l_i`そして`r_i`これらの事前計算された配列に基づいて、他のインプレッションでは取得できない範囲に数値が存在するかどうかが判断されます。
