 ## 解決策
 ## 問題の理解

 この問題は、スティックの長さを表す整数の配列を提示します。 整数のセットは、そこから選択された 3 つの要素 (繰り返しの可能性あり) が非縮退三角形を形成できる場合に安定であると定義されます。 目的は、各サブセグメントが安定するように配列を連続サブセグメントに分割できるかどうか、またこれを行うための少なくとも 2 つの異なる方法が存在するかどうかを判断することです。 

入力は複数のテスト ケースを提供します。 各テスト ケースには整数が含まれます$n$配列の長さの後に続く$n$スティックを表す整数。 出力は次のいずれかです`YES`少なくとも 2 つの有効なパーティションが存在する場合、または`NO`さもないと。 

配列の長さは最大 200 で、各値は最大です。$10^5$。 これは、次のアルゴリズムを使用できることを意味します。$O(n \log n)$または$O(n^2)$複雑。 サブセグメントは連続しているため、任意のトリプレットではなく隣接する要素に基づいてプロパティを調べることができます。 考えられるすべてのパーティションを試す単純なアプローチでは、指数関数的な効果が得られます。$n$、それは不可能です。 

エッジ ケースには、すべての要素が等しい配列、要素が 2 つだけの配列、または連続する要素間の最大差が三角形を形成するためのしきい値を超える配列が含まれます。 たとえば、配列`[1, 100000]`には 1 を超える長さの安定したサブセットがないため、単一要素のサブセグメントのみが可能で、パーティションが 1 つだけ提供されます。 不注意なアプローチでは、1 要素よりも長い配列には常に複数のパーティションがあると想定される可能性がありますが、これは誤りです。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての連続サブセグメント パーティションを列挙し、それぞれについて、すべてのサブセグメントが安定しているかどうかを確認します。 安定性チェックでは、サブセグメント内のすべてのトリプレットの三角不等式を検証する必要があります。 パーティションの数は指数関数的に増加します$n$、各サブセグメントの安定性を検証するには、$O(n^3)$操作。 のために$n=200$、これはまったく不可能です。 

重要な洞察は、最大のスティックと最小のスティックの差が、最大の 2 本のスティックから最小のスティックを差し引いた合計より小さい場合にのみ、一連のスティックが安定しているということです。 ソートされたサブセグメントでは、これは、トリプレット内の最大のスティックが他の 2 つのスティックの合計よりも小さいことをチェックすることになります。 連続したサブセグメントが考慮されるため、配列で隣接する要素を調べることができます。配列が厳密に増加または減少しており、最初と最後の要素の差が十分に大きい場合、有効なパーティションは 1 つだけ存在します。 

最適なアプローチは、前の要素が次の要素より大きい連続したペアが配列に存在するかどうかを確認することです。 このようなペアが存在する場合、その時点で分割することにより、少なくとも 2 つの異なるパーティションが可能になります。 それ以外の場合、唯一の有効なパーティションは配列自体または単一要素のサブセグメントであり、パーティションは 1 つだけになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、長さを読み取ります。$n$そして配列$a$。 
3. 配列のインデックスを順番にチェックします。$i$そのような$a[i] > a[i+1]$。 見つかった場合は出力します`YES`このテストケースでは。 これは、複数のパーティションを生成できる少なくとも 1 つの分割ポイントの存在に対応します。 
4. そのようなインデックスが存在しない場合、出力`NO`。 
5. すべてのテスト ケースに対して繰り返します。 

ステップ 3 が機能する理由は、厳密に増加する配列または厳密に減少する配列では、サブセグメント全体で安定性を維持する方法が 1 つしかないためです。 前の要素が次の要素を超えるペアでは、分割が可能な不連続性が生じ、少なくとも 2 つの有効なパーティションが生成されます。 この不変式により正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        found = False
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                found = True
                break
        print("YES" if found else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`各テスト ケースを個別に処理します。 配列を 1 回反復して、分割が可能なポイントを特定します。 小切手`a[i] > a[i + 1]`複数のパーティションに必要な条件を直接特定します。 配列を超える余分なスペースは必要ありません。 ループの境界には注意が必要です`n-1`インデックスエラーを避けるため。

 インデックス 1 で減少するペアが見つかりました。複数のパーティションが存在します。 出力：`YES`。 

これらのトレースは、複数のパーティションを有効にする有効な分割が少なくとも 1 つ存在することをアルゴリズムが識別していることを確認します。

 ## 特殊なケース

 長さ 2 の配列の場合、アルゴリズムはペアが増加しているか減少しているかを正確に識別します。 両方の要素が等しい場合、配列は安定しており、複数のパーティションを作成できません。 すべての要素が等しい配列の場合も同じロジックが適用されます。つまり、減少するペアは存在しないため、1 つのパーティションのみが可能です。 どこかに反転がある配列の場合、最初に発生した反転で十分です。`YES`。 例えば、`[1, 100, 50, 200]`インデックス 1 が減少していることを識別し、`YES`。
