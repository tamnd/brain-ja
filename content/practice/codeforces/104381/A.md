 ## 解決策
 ## 問題の理解

 サイズの正方形のゲームボードが与えられます$n \times n$、各セルは海または船のいずれかです。 単一のクエリ、つまり座標のペアが作成されます。$(r, c)$このボード上の推測されたセルを表します。 タスクは、その正確な位置に何が存在するかを判断することです。 推測されたセルに船が含まれている場合、相手はそれに成功し、答えは「いいえ」になるはずです。 セルが海洋の場合、推測は外れ、答えは「はい」になるはずです。 

入力形式は意図的に最小限になっています。 まず、ボードのサイズと推測の座標が来ます。 次に、完全なグリッドが行ごとに続き、ボードの状態が説明されます。 問題全体は、静的行列内の正確に 1 つのセルを検査することに帰着します。 

制約は小さいです。$n \le 100$。 これは、ボードのフル スキャンでさえコストがわずかであることをすぐに示唆します。$10^4$細胞は存在します。 グリッド全体を読み取り、定数時間ルックアップを実行するソリューションは、十分に制限内にあります。 ここでは、時間計算量の問題は、入力サイズを線形に保つこと以外には本質的に無関係です。 

このような問題の主な微妙な点は、インデックス作成の一貫性です。 グリッドは行とそれに続く列として指定され、座標は 0 から始まります。 よくある間違いは、行と列を交換したり、入力書式を誤って解釈したりすることです (たとえば、グリッド内のスペースを区切り記号ではなくセル構造の一部として扱うなど)。 

いくつかの特殊なケースが重要です。 

最も小さなケースが発生するのは、$n = 1$。 唯一のセルが海洋であり、クエリが$(0,0)$の場合、出力は「はい」になります。 船舶の場合、出力は「No」となります。 素朴な読者は、より大きな構造が必要であると誤って仮定するかもしれませんが、そんなことはありません。 

もう 1 つのエッジ ケースは、クエリなどの境界選択です。$(0,0)$または$(n-1,n-1)$。 これらは、インデックス付けが正しく位置合わせされ、ずれていないかどうかをテストします。 

最後の実践的なエッジ ケースは入力の書式設定です。同様の問題では、グリッドがスペースで区切られているか、連続して表示されることがよくあります。 ここで、各行にはスペースで区切られた文字が含まれているため、間違った解析 (分割せずに文字列全体を読み取る) により、間違ったインデックス付けやセルの誤読が発生する可能性があります。 

## アプローチ

 ブルートフォース解釈でも、グリッド内のすべてのセルをスキャンし、クエリされた座標と一致するかどうかをチェックすることで問題を解決できます。 これが機能するのは、ターゲット セルを見つけたら、その値を直接検査できるためです。 ただし、このアプローチでも、パフォーマンスが高いため、不必要に重くなります。$O(n^2)$必要なセルが 1 つだけであるという事実に関係なくチェックします。 

重要な点は、検索する必要がまったくないということです。 グリッドは明示的に提供されており、対象の座標はすでにわかっています。 これにより、問題は直接配列アクセスに軽減されます。つまり、グリッドをメモリに読み取り、一定時間内に必要なセルにインデックスを付けます。 問題の構造により、トラバース、検索、または前処理の必要がなくなります。 

ブルートフォースはすべてのセルを盲目的に検証するため機能しますが、グリッドが大きくなると非効率的になります。 クエリが固定されているという観察により、グリッドを静的行列として扱い、単一のルックアップを実行できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース スキャン | O(n²) | O(n²) | 受け入れられるが不要 |
 | 直接インデックス作成 | O(n²) で入力を読み取り、O(1) でクエリ | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$n, r, c$。 これらは、基板のサイズと、重要な正確な位置の両方を定義します。 
2. を読んでください。$n \times n$グリッドを 2D 構造に変換します。 各行は後で一定時間内に任意のセルにアクセスできるように保存されます。 
3. 各行が個々のセルに正しく分割されていることを確認します。 入力にはスペースで区切られた文字が使用されるため、これが必要です。 
4. 行のセルにアクセスします$r$、 カラム$c$。 
5. そのセルの値が「S」の場合、船が衝突したので「いいえ」を出力します。 
6. それ以外の場合は、「はい」を出力し、海洋であるためミスを示します。 

セルが 1 つだけ必要な場合でも、グリッド全体を読み取る背後にある重要な考え方は、入力が完全に消費されなければならないということです。 競技プログラミングの制約では、常に入力ストリームの完全な取り込みが必要です。 

### なぜ効果があるのか

 グリッドはゲームの状態を直接表現します。 各座標は、曖昧さや隠れた変換を持たずに、正確に 1 つのセルに対応します。 クエリは計算や近傍に依存しないため、正確性は入力を正しく解析し、単一のルックアップを実行することによって決まります。 集約や推論が含まれないため、インデックス付けが正しく行われると、アルゴリズムが失敗することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, r, c = map(int, input().split())
    grid = []

    for _ in range(n):
        row = input().strip().split()
        grid.append(row)

    if grid[r][c] == 'S':
        print("No")
    else:
        print("Yes")

if __name__ == "__main__":
    main()
```入力は行ごとに消費する必要があるため、ソリューションではグリッド全体を保存します。 個々のセルを正しく抽出するために、各行は空白で分割されます。 重要な操作は直接検索です`grid[r][c]`、クエリされた位置を正確に反映します。 

よくある実装上の間違いは忘れることです`.split()`これにより、行がスペースを含む単一の文字列として扱われ、インデックス作成ロジックが壊れます。 もう 1 つの問題は、行と列の順序を混同することです。グリッドは入力では当然行優先ですが、座標は慎重に解釈する必要があるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    out = []

    n, r, c = map(int, sys.stdin.readline().split())
    grid = [sys.stdin.readline().split() for _ in range(n)]

    return "No\n" if grid[r][c] == 'S' else "Yes\n"

 ## 特殊なケース

 シングルセルボードの場合、アルゴリズムは 1 行を読み取り、直接アクセスします。`grid[0][0]`。 セルが「O」の場合は「Yes」を出力します。 「S」の場合は「いいえ」を出力します。 同じインデックス作成ロジックが均一に適用されるため、特殊なケースの処理は必要ありません。 

(0,0) や (n-1,n-1) などの境界座標の場合、アルゴリズムは同じように動作します。 たとえば、次の場合$n = 2$グリッドは次のとおりです。```
O O
O S
```クエリが (1,1) の場合、アルゴリズムは 2 行目と 2 列目にアクセスし、「S」を見つけて「No」を出力します。 これにより、入力がすでにゼロベースであるため、off-by-1 調整が必要ないことが確認されます。
