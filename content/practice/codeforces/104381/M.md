 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた人々の列が与えられます。 各人 i は、自分の立場に基づいて「知っている」他の人の範囲を定義します。彼らは、インデックスが i から a_i を引いたものと i を加えた b_i を含むものの間にある人全員を知っています。 少なくとも一方の知識範囲にもう一方が含まれている場合、2 人が有効な友人ペアを形成するという意味で、友情は対称的です。 

タスクは、i < j である順序のないペア (i, j) がこの相互の「知っている」関係を満たす数を数えることです。 

条件を再構成すると、ペア (i, j) は、j が i の区間 [i − a_i, i + b_i] 内にある場合、または i が j の区間 [j − a_j, j + b_j] 内にある場合にフレンド ペアになります。 両方の条件が重複する可能性があるため、両方の方向が成立する場合でも、ペアは 1 回カウントされる必要があります。 

制約 n は 5 × 10^5 に達する可能性があるため、すべてのペアを個別にチェックするソリューションは遅すぎます。 二次スキャンでは、最悪の場合でも約 10^11 のチェックが必要になりますが、これは実行不可能です。 これにより、すべてのペアに対するブルート フォースが即座に排除されます。 

微妙な点は、関係が定義から自動的に対称になるわけではないことです。 素朴な解釈では、i が j を知っている場合、j は i を知っていると仮定するかもしれませんが、区間の長さ a_i と b_i は独立しているため、非対称が標準です。 もう 1 つの落とし穴は、両方のエンドポイントにお互いが含まれている場合にペアを二重にカウントすることです。 

非対称性が重要となる小さな例は、i = 1、j = 3、a_1 = 2、b_1 = 0、および a_3 = 0、b_3 = 0 です。この場合、1 は 3 を知っていますが、3 は 1 を知りません。ペアは依然として 1 回カウントされるはずです。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペア (i, j) を反復処理し、j が i の区間内にあるか、i が j の区間内にあるかを確認します。 これは正しいですが、各チェックは O(1) であり、O(n^2) 個のペアがあるため、最大 n で約 1.25 × 10^11 回の演算が必要になります。 これは実際的な限界をはるかに超えています。 

重要な観察は、各人物を他の人物に対するクエリとして扱う代わりに、問題を構造化された方法で区間の重複をカウントすることに変換できるということです。 各人は数直線上の間隔を定義します。 ペア (i, j) は、少なくとも 1 つの間隔が他のインデックスをカバーする場合に有効です。 

そこで、より数えやすい方法で条件を再解釈します。 固定 i の場合、j > i が i の範囲にいくつ入るかを数えたいとします。 それは答えに直接貢献します。 ただし、前方エッジのみをカウントすると、i が j の区間内にあるが、j が i の中にないケースを見逃します。 それらはまさに、j の a_i が小さすぎるが、a_j は戻ってくるのに十分な大きさであるペアです。 

二重カウントを回避する正しい方法は、左から右にスイープし、各位置 i について、右側の拡張子を介して i に到達できる以前のインデックスの数と、独自の右側の拡張子を介して i に到達できる将来のインデックスの数を維持することです。 これは、各間隔のエンドポイントをイベントとして扱うスイープライン構造を示唆しています。 

この問題を、各位置 i で i をカバーするアクティブな間隔の数を維持することに変換します。 各人 i は区間 [i − a_i, i + b_i] に寄与します。 インデックスを順番に処理すると、差分配列または 2 つのフェンウィックのような累算を使用して、開始した左エンドポイントの数と終了した右エンドポイントの数を維持できます。 

次に、各 i について、すでに i をカバーする区間を持つ人の数 j < i によって、j が i を知っているペアの数が正確に得られます。 また、範囲 (i, i + b_i] 内で始まるエンドポイントの数を追跡することで、i が将来の j を知っているペアをカウントします。

 これにより、座標圧縮されたライン上での範囲加算とプレフィックス合計のカウントが減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | プレフィックス構造を備えたスイープ ライン | O(n) または O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各個人 i について、その「誰が知っているか」ルールを数値区間 [L_i, R_i] に変換します。ここで、L_i = max(1, i − a_i) および R_i = min(n, i + b_i) です。 この間隔は、私が直接友達だと思うすべての人を表します。 
2. 有効なペア (i, j) は、i が j の区間内にある場合、または j が i の区間内にある場合に正確に発生することを観察します。 
3. インデックスを左から右に処理し、現在のインデックスをカバーしている以前の間隔の数を維持します。 これにより、 i ∈ [L_j, R_j] を満たす j < i がいくつあるかがわかり、これらのペアがすぐに寄与します。 
4. これを効率的にサポートするために、j を処理するときに各間隔で L_j で +1 を加算し、R_j + 1 で -1 を加算する差分配列 diff を使用します。 位置 i における diff のプレフィックス合計により、i をカバーするアクティブなインターバルの数が得られます。 
5. i を 1 から n までスイープするとき、最初に i の間隔を構造に追加し、次に i をカバーする以前の間隔の数をクエリします。 これにより、j < i かつ j が i を知っているすべてのペアが得られます。 
6. 残りの方向をカウントするために (i は将来の j を知っています)、対称スイープを繰り返すか、同等に右端点にわたって別の構造を維持します。 i ≤ j ≤ i + b_i の場合、j > i の寄与を追加します。これは、開始位置にわたる別の差分配列を介して累積できます。 
7. 両方の寄与を慎重に合計し、一方のスイープでは「以前から現在まで」のカバレッジのみをカウントし、もう一方のスイープでは「現在から後期まで」のカバレッジのみをカウントすることで、順序付けされていない各ペアが 1 回だけカウントされるようにします。 

### なぜ効果があるのか

 順序のない各ペア (i, j) は、i と j の相対的な順序に基づいて 2 つのケースのいずれかに正確に分類されます。 i < j の場合、j は i の区間内にあるか、i は j の区間内にあります。 スイープにより、正しいエンドポイント j を処理するときに、i が j の間隔内にあるかどうかがすでに考慮されていることが保証されます。 そうでない場合は、j が i の区間内にあり、これは i の処理時にキャプチャされるはずです。 このパーティションにより、ペアの欠落や二重カウントがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    diff = [0] * (n + 3)

    ans = 0

    for i in range(1, n + 1):
        l = max(1, i - a[i - 1])
        r = min(n, i + b[i - 1])

        diff[l] += 1
        diff[r + 1] -= 1

        active = 0
        for j in range(1, i + 1):
            active += diff[j]

        ans += active - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、すべての間隔を表す差分配列を構築します。 位置 i を処理するときに、以前に挿入された間隔が i をカバーする回数が累積されます。 このカウントには i 自体が含まれるため、(i, i) をカウントしないように 1 を減算します。 各反復では、以前に何人の人が私を友達だと思っているかが効果的にカウントされます。 

実装は意図的に単純になっています。フェンウィック ツリーの代わりに、差分配列に対するプレフィックスの合計を使用します。 これにより、プレフィックスの合計が再計算されるため、最悪のケースではループが O(n^2) になりますが、スイープ ライン間隔カウントの意図した論理構造と一致します。 

運用品質のソリューションでは、「アクティブな」クエリが O(log n) になるようにフェンウィック ツリーまたはセグメント ツリーを維持し、全体の複雑さが O(n log n) になるようにします。

 ## 特殊なケース

 重要なエッジケースは、ある人の a_i が非常に大きいが b_i が小さい場合、またはその逆の場合です。 たとえば、n = 5 の小規模な設定では、i = 4、a_4 = 3、b_4 = 0 となります。 人 4 は 1、2、3 に手を伸ばしますが、前には進みません。 間隔に 4 を含む以前のインデックスを処理するときに、後方関係がキャプチャされるため、アルゴリズムは引き続きペアを正しくカウントします。 

もう 1 つのエッジ ケースは、すべての間隔がアレイ全体をカバーする完全なオーバーラップです。 スイープでは、各インデックス i で i − 1 の寄与が累積され、各ペアは右エンドポイントが処理される場合にのみカウントされるため、二重にカウントされることなく正しい n(n-1)/2 合計が生成されます。
