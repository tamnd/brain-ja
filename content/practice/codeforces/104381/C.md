 ## 解決策
 ## 問題の理解

 整数のコレクションが与えられており、割り算に基づいてインデックス間の順序関係を数えたいと考えています。 すべてのポジションのペアについて$i$そして$j$の値があるかどうかを確認します。$i$の値で割り切れます$j$2 つのインデックスが異なることを確認しながら。 有効な各ペアは、最終的な答えに 1 つ貢献します。 

入力サイズにより、すべてのペアに対するブルート フォースは不可能になります。 まで$2 \cdot 10^5$数値的には、すべてのペアにわたる二次スキャンには次のものが含まれます。$4 \cdot 10^{10}$チェックは 1 秒で実行できる範囲をはるかに超えています。 一部のケースをスキップしようとするわずかに最適化されたネストされたループでも、このスケールでは依然として崩壊します。 

値自体は次の制限を受けます。$5 \cdot 10^5$、これが重要な構造的制約です。 これは、考えられる値の範囲が要素の数よりもはるかに小さいため、要素ごとの比較から値と頻度の推論に思考を移行できることを意味します。 

素朴なアプローチは、重複が存在する場合に微妙な方法で失敗する傾向があります。 多くの要素が同じ値を共有する場合、入れ子になったループ内で各要素を個別に処理すると、冗長な作業が繰り返され、正確性が向上することなく実行時間が増大します。 

たとえば、配列がすべて 1 の場合、自己ペアを除くすべての順序付きペアが有効です。 ブルート フォース アプローチでもすべてのペアを個別にチェックしますが、周波数ベースのアプローチでは、計算がすぐに単純な式にまとめられます。 

## アプローチ

 ブルート フォース ソリューションは、順序付けされたすべてのペアを反復処理し、割り算を直接チェックします。 これは概念的には単純です。$i$、すべてスキャンします$j \neq i$かどうかをテストします$a_i \bmod a_j = 0$。 これは定義に正確に従っているため機能しますが、すべての順序付きペアに対して割り算チェックを実行するため、次のような結果が得られます。$O(n^2)$操作。 と$n = 2 \cdot 10^5$、これは実現不可能です。 

重要な観察は、割り算は位置ではなく値のみに依存するということです。 各値が何回出現するかがわかっていれば、繰り返しのチェックを集計したカウントに置き換えることができます。 要素を反復する代わりに、可能な値を反復し、その倍数について推論します。 

固定値の場合$x$、すべての有効なパートナー$y$それを満たさなければなりません$y$分割する$x$。 したがって、問題は次のようになります。各値について$x$、すべての約数の度数を合計します。$y$順序の制約を尊重しながら。 

これにより、計算はふるいのような累積プロセスに移行します。 周波数を事前に計算し、値を反復処理して、寄与を倍数に伝播します。 各数値はそれ自体のすべての倍数に寄与し、明示的なペアの列挙なしで割り切れる関係を自然にエンコードします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 周波数ふるい |$O(V \log V)$または$O(V \log V)$みたいな |$O(V)$| 承認済み |

 ここ$V = 5 \cdot 10^5$。 

## アルゴリズムのチュートリアル

 まず入力を周波数配列に圧縮します。`freq[x]`何倍の値を保存するか`x`が表示されます。 

次に、倍数にわたるふるいを使用して寄与度を計算します。 

1. 入力内のすべての値に対して周波数配列を構築します。 これにより、各出現を個別に処理するのではなく、同一の値をグループとして扱うことができます。 すべての相互作用はインデックスではなく値のみに依存するため、これは不可欠です。 
2. 各値について$x$、それを潜在的な約数として考慮します。 倍数ごと$k \cdot x$とペアになる値を表します$x$割り切れる条件下で。 
3. そのような倍数ごとに、次の形式の貢献を追加します。`freq[x] * freq[kx]`。 これは、2 番目の要素が最初の要素で割り切れる順序ペアをカウントします。 
4. 順序制約が誤って二重にカウントされないことも確認する必要があります。 条件は方向性がある (i、j の順序) ため、除数を昇順に反復する場合、有効な各ペアは自然に 1 回だけカウントされます。 
5. すべての貢献を合計してグローバルな答えを作成します。 

重要なのは、複数の反復処理により、無関係なペアをスキャンすることなく、すべての有効な割り算関係が 1 回だけ確実に取得されることです。 

### なぜ効果があるのか

 注文したすべてのペア$(i, j)$そのような$a_i$の倍数です$a_j$値のペアに一意に対応します$(x, y)$どこ$x = a_i$、$y = a_j$、 そして$x$の倍数です$y$。 直すときは$y$すべての倍数を反復処理します$x$、それらのペアを正確に列挙します。 頻度積はすべてのインデックスの組み合わせをカウントするため、ペアが見逃されることはなく、二重にカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    MAXV = 500000
    freq = [0] * (MAXV + 1)
    
    for x in a:
        freq[x] += 1

    ans = 0

    for y in range(1, MAXV + 1):
        if freq[y] == 0:
            continue
        for x in range(y * 2, MAXV + 1, y):
            if freq[x]:
                ans += freq[x] * freq[y]

    print(ans)

if __name__ == "__main__":
    solve()
```入力を読み取った後、すべての同一の値が集計されるように度数表を作成します。 次に、二重ループは約数と倍数の関係を調べます。 それぞれの基準値について`y`、すべての倍数を反復処理します。`x`、蓄積します`freq[y] * freq[x]`これは、大きい値が小さい値で割り切れるすべての順序付きペアを表します。 

内部ループは次から始まります`2*y`なぜなら`y`分割自体は自己ペアに対応しますが、問題ステートメントでは明示的に除外されます。 

## 実用的な例

 ### 例 1

 入力:```
1 2 3 4 5
```頻度はすべて 1 です。寄与を列挙します。 

| y | xの倍数 | 貢献 |
 | --- | --- | --- |
 | 1 | 2、3、4、5 | 4 |
 | 2 | 4 | 1 |
 | 3 | - | 0 |
 | 4 | - | 0 |
 | 5 | - | 0 |

 合計 = 5

 すべての数値は 1 で割り切れ、4 は 2 で割り切れるため、これはサンプルと一致します。

 ## 特殊なケース

 重要なエッジケースは、配列に 1 のような小さな数値の重複が多数含まれている場合です。その場合、他のすべての数値が 1 を通じて寄与し、答えは二次関数的に増加します。 周波数ベースの方法ではこれを自然に処理します。`freq[1]`他のすべての周波数を乗算しますが、単純なアプローチでは依然として冗長なペアごとのチェックが行われます。 

もう 1 つのエッジ ケースは、上限近くで値がまばらな場合です。 ふるいは、空の周波数をスキップし、既存の除数のみを処理するため、不必要な作業を防ぐため、引き続き正しく反復されます。
