 ## 解決策
 ## 問題の理解

 私たちは毎週進化するランダム化されたパスワード システムを追跡しています。 固定リストがあります$n+1$個別のパスワード。 最初の第 1 週に、システムはリストの最初のパスワードを使用します。 

毎週、パスワードは同じか変更されます。 確率で$1/m$、何も起こらず、パスワードは変更されません。 確率で$(m-1)/m$、変更が発生し、新しいパスワードが他のパスワードから一律に選択されます。$n$現在のパスワードを除くパスワード。 

このプロセスを実行した後、$T$数週間、私たちは現在使用されているパスワードを観察します。 次に、ユーザーはリストの順序でパスワードを試行してシステムのロックを解除しようとします。パスワードは最大で許可されます。$k$試み。 問題は、現在のパスワードが次の週に使用される確率です。$T$最初のものの一つです$k$リスト内のエントリ。 

したがって、実際のタスクは試行をシミュレートすることではなく、試行後にどのパスワードが現在アクティブになるかの確率分布を計算することです。$T$ランダムな遷移を実行し、サイズのプレフィックスにわたる確率を合計します。$k$。 

重要な難点は、$n$そして$m$と同じ大きさにすることができます$10^9$したがって、パスワードごとの確率を維持したり、マルコフ過程を直接シミュレートしたりすることはできません。 のみ$T$時間の経過とともに反復できるほど小さいです。 

複雑さの観点から見ると、サイズのベクトルを追跡するソリューションはすべて$n$コストがかかるため、ステップごとに実行することは直ちに不可能です$O(nT)$まで可能です。$10^{14}$。 平$O(n)$ステップあたりのサイズが大きすぎます。 状態空間を大幅に削減しなければなりません。 

微妙なエッジケースが現れるのは、$k = n+1$。 この場合、答えは常に 1 になります。$T$、考えられるすべてのパスワードが許可された試行範囲内にあるためです。 単純な実装では、依然として不必要な確率計算が実行され、モジュールの間違いが発生する可能性があります。 

もう 1 つの例外的なケースは次のような場合です$m = 1$。 それから$(m-1)/m = 0$, そのため、初期化後にパスワードが変更されることはありません。 答えは、初期パスワードが最初のパスワードにあるかどうかによってのみ決まります。$k$位置、これは決定的です。 

最後に、いつ$n = 1$、可能な代替パスワードは 1 つだけです。 システムは、縮退遷移構造を持つ単純な 2 状態プロセスになり、多くの単純な「他よりも均一」実装は、ゼロまたは空のサンプリング セットによる除算によりここで破綻します。 

## アプローチ

 強引な解釈では、すべての確率分布が維持されます。$n+1$パスワード。 最初は、確率 1 がパスワード 1 に設定されています。毎週、確率を更新します。各状態は因子に留まります。$1/m$、または、その出力確率質量を他のすべてに均等に分配します。$n$州。 

これは、密な遷移行列を含むマルコフ連鎖です。 直接シミュレーションのコスト$O(T \cdot n)$, すべてのステップで確率質量がすべての状態に再分配されるためです。 と$n, T$大きいので、これでは遅すぎます。 

重要な観察は対称性です。 最初のパスワードを除くすべてのパスワードは区別できません。 常に、現在のパスワードとその他のパスワードの 2 種類の状態のみが存在します。$n$パスワード。 さらに重要なことは、最初のステップの後、最初以外のすべてのパスワードは永久に対称のままであるということです。 これにより、状態空間が崩壊します。$n+1$値は、パスワード 1 である確率と、その他の特定のパスワードである確率の 2 つの集約された確率にのみ適用されます。 

この縮小により、プロセスは非常に単純な反復を伴う 2 状態マルコフ連鎖に変わり、各ステップは初期状態での現在の質量と、それが他のステップにどのように広がるかのみに依存します。 

個々のパスワードが現在アクティブである確率を計算できたら、対称性を再度利用します。つまり、初期値以外のすべてのパスワードの確率は等しいことになります。 したがって、現在のパスワードが最初のパスワードにある確率は、$k$位置は、インデックス 1 が含まれるかどうか、および残りのインデックス 1 がいくつあるかによってのみ決まります。$k-1$対称状態も含まれます。 

これにより、問題は 2 つの量の閉形式発展の計算に変換されます。$T$で実行できる手順$O(T)$、そしてそれらを算術的に組み合わせます。

 | 最適 |$O(T)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.確率の初期化$p$その後も元のパスワードを使用している確率として$t$ステップ。 最初は$p = 1$。 また、他のすべてのパスワードが残りの確率質量を均等に共有していることも追跡します。そのため、それぞれが確率を持ちます。$(1-p)/n$。 この対称性は遷移規則によって維持されます。 
2. 1 から 1 までの毎週の処理$T$。 各ステップで、現在の状態から確率がどのように変化するかを計算します。 確率で$1/m$、システムは同じパスワードのままであるため、各状態の質量は次のように乗算されます。$1/m$。 確率で$(m-1)/m$、遷移が発生し、質量が他のすべてのパスワードに均一に再分配されます。 
3. 元のパスワードに到達する確率は、その場に留まるか、別の状態から移行して均一選択を介して戻ることによって到達できるという事実を利用して更新します。 漸化式は次の線形変換に帰着します。$p$、更新します$p = a \cdot p + b$、ここで定数は$a$そして$b$のみに依存する$n$そして$m$。 
4.その後$T$ステップを実行し、各非初期パスワードの確率を次のように計算します。$(1-p)/n$。 これは対称性から直接得られるものであり、すべての非初期状態はプロセス下で交換可能のままです。 
5. 最終的な答えを計算します。 パスワード 1 が最初の範囲内にある場合$k$、 追加$p$。 次に、残りからの貢献を追加します$\min(k-1, n)$それぞれが貢献する対称的なパスワード$(1-p)/n$。 
6. モジュラー逆関数を使用して、結果の有理式をモジュラー形式に変換します。 すべての分数は以下を含む項の線形結合であるため、$m$そして$n$、すべてをモジュロで計算します$10^9+7$逆数に対してべき乗剰余を使用します。 

### なぜ効果があるのか

 正しさは対称性の不変条件によって決まります。どのステップでも、元のパスワードを除くすべてのパスワードは交換可能です。 すべての「変更」ステップでは他のすべてのパスワードの中から均一に選択されるため、移行ルールではそれらが区別されません。 これにより、確率分布が常に正確に 2 つの自由度を持つことが保証されます。つまり、元のパスワードの質量と、他のすべてのパスワードで共有される等しい質量です。 これら 2 つの量の発展によってシステムが完全に決定されるため、状態空間を折りたたんでも情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m, k, T = map(int, input().split())

    if k >= n + 1:
        print(1)
        return

    # probabilities:
    # p = prob we are still at password 1
    # recurrence derived from symmetry:
    # p' = (1/m)*p + (m-1)/m * (1/n)
    invm = modinv(m)
    one_minus = (m - 1) * invm % MOD
    stay = invm

    invn = modinv(n)

    p = 1

    for _ in range(T):
        p = (stay * p + one_minus * invn) % MOD

    # total answer
    ans = 0
    if k >= 1:
        ans = (ans + p) % MOD

    if k > 1:
        ans = (ans + (k - 1) * ((1 - p) % MOD) % MOD * invn) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは 2 状態の繰り返しを直接実装しています。 変数`p`初期パスワードが残る確率を追跡します。 用語`stay = 1/m`変化しないことに対応しますが、`one_minus/n`は、変更後にランダムな選択によって初期状態に戻る確率質量を表します。 

最終的な答えは 2 つの部分に分かれています。最初のパスワードが許可範囲内にあるかどうかと、残りのパスワードの対称グループからの確率質量が最初のパスワードにどれだけ含まれるかです。$k-1$ポジション。 

よくある実装上の間違いは、変更後の再配布では現在のパスワードが除外されることを忘れていることです。そのため、再帰では残留サンプリング条件と均一サンプリング条件の両方が混合されます。

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k, T = map(int, sys.stdin.readline().split())

    if k >= n + 1:
        return "1\n"

    def modinv(x):
        return pow(x, MOD - 2, MOD)

    invm = modinv(m)
    invn = modinv(n)

    stay = invm
    one_minus = (m - 1) * invm % MOD

    for _ in range(T):
        p = (stay * p + one_minus * invn) % MOD

    ans = 0
    if k >= 1:
        ans = (ans + p) % MOD
    if k > 1:
        ans = (ans + (k - 1) * ((1 - p) % MOD) % MOD * invn) % MOD

    return str(ans % MOD) + "\n"

# no change

 ## 特殊なケース

 いつ$m = 1$、変化する遷移確率はゼロです。 再発は次のように減少します$p_{t+1} = p_t$、 それで$p$すべてにおいて 1 のままです$T$。 最終的な答えは純粋にインデックス 1 が最初のインデックス内にあるかどうかです。$k$、実装によって即座に処理されます。 

いつ$k \ge n+1$、すべてのパスワードを使用できます。 このアルゴリズムは、モジュラー計算を実行せずに短絡して 1 を返すため、不必要な演算が回避され、オーバーフローの蓄積が防止されます。 

いつ$T = 0$、プロセスはまったく進化していません。 システムは確率 1 の最初のパスワードを使用し続けるため、次の場合、答えは 1 になります。$k \ge 1$、それ以外の場合は 0。再帰ループは当然更新をスキップし、正確さを維持します。
