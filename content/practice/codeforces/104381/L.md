 ## 解決策
 ## 問題の理解

 パスで接続された交差点の有向または無向グラフが与えられます。 各パスには積雪の深さの値があり、マイケルは交差点 1 から開始し、目標の交差点 T に到達したいと考えています。面白いのは、彼の歩行コストが通常の意味で加算されないことです。 その代わり、雪の端を横断するコストは、彼がすでに歩いた雪の端の数によって決まります。 

マイケルが雪のエッジに沿って歩くたびに、カウンター d が 1 ずつ増加します。エッジが深さ x の雪に覆われている場合、それを横断するには d × x のエネルギーがかかります。 端に雪が積もっていない場合、コストはかからず、d も増加しません。 目標は、総エネルギーを最小化する 1 から T までのパスを選択することです。 

重要な詳細は、同じ深さの場合、早い段階の雪のあるエッジの方が後のものよりも安価であるため、雪のあるエッジを取得する順序が重要であるということです。 

制約は、状態拡張された最短パスのアプローチにとって十分小さいものです。 n が最大 1000、m が最大約 1000 であるため、遷移が効率的である限り、O(n × n) または O(n × m) 状態の状態グラフでもダイクストラ スタイルの処理で処理できます。 n での 3 次の動作を伴う解は依然として遅すぎますが、O(n² log n) または O(nm log n) は実現可能です。 

微妙なエッジ ケースは、到達不能なノードと、T が 1 に等しい可能性から生じます。T = 1 の場合、移動は必要なく、コストはゼロです。 もう 1 つのエッジ ケースは、T につながるすべてのエッジが雪に覆われているが、利用可能な唯一のパスによって早期に d が大量に蓄積されるため、貪欲な選択が不正確になる場合です。 

よくある間違いは、これを各エッジの重み x が固定されている最短パスのように扱うこと、または d をノードの一部として扱うが、雪の遷移とともに重みが増加し、将来のコストに乗算的に影響することを忘れていることです。 

## アプローチ

 単純なアプローチでは、1 から T までのすべての可能なパスを試行し、各パスに沿ったエネルギーを計算します。 固定パスの場合、トラバースをシミュレートできます。これまでに使用された雪のエッジの数を維持し、増分コストを正確に計算します。 これは定義に直接従うため、正しいです。 

ただし、グラフ内の単純なパスの数は指数関数的に増加します。 中程度の分岐しかないグラフであっても、1 から T までのすべてのルートを列挙すると、可能性が爆発的に広がります。 最悪の場合、完全なグラフでは階乗数の多いパスの探索が必要になりますが、これは完全に不可能です。 

重要な観察は、システムの状態が現在のノードだけでなく、すでに使用されている雪のエッジの数も反映しているということです。 この数によって、今後のすべての雪のエッジに適用される乗数が決まります。 これは、各状態が (ノード、d) である拡張状態空間上の最短経路として問題を再定式化できることを意味します。 各遷移は、d を変更しない (ドライ エッジ) か、d を 1 つ増やす (雪のエッジ) かのいずれかで、d の新しい値に依存するコストに寄与します。 

これにより、問題が層状グラフ上の標準的な最短経路に変換されます。 単純なパスでは d が n を超えることはなく、m ≤ 1000 であるため、状態空間は管理可能なままです。

 ## アルゴリズムのチュートリアル

 各状態をペア (ノード、d) としてモデル化します。ここで、d は、これまでに使用された雪に覆われたエッジの数です。

1. 距離テーブル dist[node][d] を無限大で初期化し、雪のエッジを使用しないノード 1 から開始するため、dist[1][0] = 0 に設定します。 
2. 蓄積されたエネルギーによって順序付けされた優先キューを使用します。 これにより、状態を処理するときは常に、その状態に到達するための現時点で既知の最も安価な方法であることが保証されます。 
3. 状態 (u, d) からすべてのエッジ (u → v, x) を考慮します。 
4. エッジが乾燥している (x = 0) 場合は、d を変更せず、追加コストも発生せずに状態 (v, d) に移行します。 これは、ドライエッジはエネルギーにも乗数にも寄与しないためです。 
5. エッジに雪が降っている場合 (x > 0)、状態 (v, d + 1) に遷移します。 このエッジはパス内の (d + 1) 番目の雪に覆われたエッジになるため、この遷移のコストは (d + 1) × x です。 
6. より小さいコストが見つかった場合は dist[v][d'] を緩和し、更新された状態を優先キューにプッシュします。 
7. すべての状態を処理した後、答えはすべての可能な d に対するすべての dist[T][d] の最小値になります。 

目的地ですべての d の最小値を取る理由は、使用された雪のエッジの数は気にせず、総エネルギーだけを気にするためです。 

### なぜ効果があるのか

 このアルゴリズムは、すべての有効な歩行を一連の状態遷移としてエンコードします。雪に覆われた各エッジは、使用されると正確に d を増分します。 実際のパスはすべて、正確に 1 つの状態シーケンスに対応し、状態グラフに蓄積されたコストは真のエネルギー定義と段階的に一致します。 ダイクストラのアルゴリズムは常にコストの昇順に状態を展開し、展開されたグラフ内のすべてのエッジの重みは負ではないため、最初に状態を確定するときに、その状態に到達するための最適なコストが見つかります。 これにより、すべての宛先状態の最小値がグローバルに最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, m, T = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        a, b, x = map(int, input().split())
        g[a].append((b, x))
        g[b].append((a, x))

    INF = 10**18

    # dist[node][d] = min energy reaching node having used d snowy edges
    dist = [[INF] * (n + 1) for _ in range(n + 1)]

    dist[1][0] = 0
    pq = [(0, 1, 0)]  # (cost, node, d)

    while pq:
        cost, u, d = heapq.heappop(pq)

        if cost != dist[u][d]:
            continue

        for v, x in g[u]:
            if x == 0:
                nd = d
                ncost = cost
            else:
                nd = d + 1
                ncost = cost + (d + 1) * x

            if nd <= n and ncost < dist[v][nd]:
                dist[v][nd] = ncost
                heapq.heappush(pq, (ncost, v, nd))

    ans = min(dist[T])
    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```このソリューションでは、グラフの隣接リストを構築し、拡張された状態空間に対してダイクストラのような検索を実行します。 重要な詳細は、状態にこれまでに使用された雪のエッジの数が含まれていることです。これにより、将来の雪の遷移のコストが直接決まります。 

優先キューにより、状態がエネルギーの昇順で処理されることが保証され、緩和ステップにより、特定の (ノード、d) ペアに到達するためのより良い方法のみが保持されるように強制されます。 最適なパスでは任意の数の雪のエッジが使用される可能性があるため、最終的な答えは、ターゲット ノードで考えられるすべての d にわたって集約されます。

 ## 特殊なケース

 T が 1 に等しい場合、アルゴリズムは dist[1][0] = 0 を初期化し、すぐに答えを 0 とみなします。遷移は必要ないため、dist[1][d] 全体の最小値は 0 のままです。 

グラフが切断されると、T の状態には到達しないため、dist[T] 内のすべてのエントリは無限のままになります。 最終チェックでは正しく -1 が返されます。 

すべてのエッジがドライの場合、d は決して変化せず、問題はコストゼロ遷移の標準的な重み付けされていない最短経路に帰着します。すべてのコストがゼロのままであり、不正な乗数が導入されていないため、状態グラフは正確に保存します。 

high-x の積雪エッジのみが存在する場合、アルゴリズムは当然、積雪の使用を遅らせるパスを優先します。これは、d が小さい状態がダイクストラ次数の早い段階で優勢となり、乗算ペナルティの正しい順序が確保されるためです。
