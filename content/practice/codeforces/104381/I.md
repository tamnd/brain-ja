 ## 問題の理解

 長さのシーケンスが与えられます$n$そして、それが何らかの隠された順列から生成された可能性があるかどうかを判断したいと考えています。$1$に$n$。 非表示のプロセスは、すべてのステップで非常に具体的な方法で制約されます。$i$、値$a_i$は、順列でまだ使用されていない最小値または最大値のいずれかです。 

したがって、順列の要素を直接選択する代わりに、この構築は現在の最小残り値または現在の最大残り値のいずれかを繰り返し削除するように動作します。 問題は、与えられた一連の選択肢が正しいかどうかです。$a$何らかの有効な置換に対するそのようなプロセスに対応する可能性があります。 

出力は順列そのものではなく、実行可能性のチェックのみです。 記述されたルールに基づいてシーケンスを生成できる順列が少なくとも 1 つ存在するかどうかを判断する必要があります。 

制約$n \le 1000$おおよその解決策が可能$O(n^2)$または$O(n^2 \log n)$ただし、順列を明示的に列挙しようとしたり、各ステップですべての可能性をシミュレートしようとするものは除外されます。 各位置は利用可能な値の縮小セットに依存するため、正しいアプローチでは動的間隔または残りの候補のセットを効率的に追跡する必要があります。 

すべてのことを欲張って仮定すると、微妙な故障モードが現れます。$a_i$将来の制約を考慮せずに、現在の最小値または最大値に直ちに一致する必要があります。 たとえば、常に一致を受け入れて境界を縮小しようとすると、有効な割り当てが存在するにもかかわらず、以前の選択が異なる解釈をされてしまう可能性があります。 

もう 1 つのエッジ ケースは、値が繰り返される場合です。$a$。 以来$a_i$順列の繰り返しからの値であると考えられます$a$直接的には何も違反しませんが、強い制約が課せられます。値が最小値または最大値として使用されると、残りの極値と一致しない限り、その値は再度使用できなくなります。 

## アプローチ

 強引な解釈では、次のすべての順列を試すことになります。$1$に$n$、各順列について、シーケンスを生成できるかどうかをシミュレートします。$a$。 これはすぐに爆発します。$n!$順列と各シミュレーションのコスト$O(n)$、につながる$O(n! \cdot n)$、これは実現可能な限界をはるかに超えています。 

重要な観察は、各ステップで重要な唯一の情報は、現在残っている未使用の値の範囲であり、これは常に間隔であるということです。$[L, R]$。 最初は$L = 1$、$R = n$。 各ステップで、次のいずれかを削除します。$L$または$R$、削除された値は一致する必要があります$a_i$。 

したがって、順列の観点から考えるのではなく、残りの候補者の間隔を維持する観点から考えます。 それぞれのポジションで$i$かどうかを確認します。$a_i$等しい$L$または$R$。 どちらにも一致しない場合、シーケンスは不可能です。 両方に一致する場合 (これは次の場合にのみ発生します)$L = R$)、間隔は決定論的に縮小します。 それ以外の場合は分岐しますが、分岐は非常に限定されており、一貫性によって貪欲に解決できます。 

より深い洞察は、選択肢は分岐のように見えますが、実現可能性はすべてを尊重しながら一貫して間隔を短縮できるかどうかによって完全に決まるということです。$a_i$。 これは、単純な妥当性チェックを備えた決定論的なシミュレーションになります。

 ## アルゴリズムのチュートリアル

 2 つの指針を維持します$L = 1$そして$R = n$、残りの未使用の値の最小値と最大値を表します。 

1. から始める$L = 1$、$R = n$。 これらは、非表示の順列でまだ使用可能なすべての値を表します。 
2. シーケンスを左から右に処理します。 ステップで$i$、調べます$a_i$。 
3. もし$a_i$等しい$L$、これを現在の最小値を削除すると解釈します。 更新します$L \leftarrow L + 1$。 これが唯一の有効な解釈です。$R$値と矛盾します。 
4. それ以外の場合$a_i$等しい$R$、これを現在の最大値を削除すると解釈します。 更新します$R \leftarrow R - 1$。 
5. もし$a_i$どちらとも一致しない$L$または$R$、有効な順列はシーケンスを生成できないとすぐに結論付けます。 
6. すべての要素が処理されるまで続行します。 
7. シーケンス全体が矛盾なく処理される場合、答えは YES です。 

これが機能する理由: 各ステップで、残りの未使用の値が連続した間隔を形成します。 このプロセスでは、次に削除される値がこの間隔の 2 つのエンドポイントのいずれかであることが保証されます。 これらのエンドポイントは履歴によって一意に決定されるため、有効なシーケンスは各ステップでいずれかのエンドポイントと一致する必要があります。 値が厳密に区間内にある場合、構築規則に従ってそのステップで値を削除することはできないため、シーケンスは有効な置換に対応できません。 残りのセットが常に正確であるというこの不変式$[L, R]$隠れた分岐の決定が見逃されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    L, R = 1, n

    for x in a:
        if x == L:
            L += 1
        elif x == R:
            R -= 1
        else:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```このソリューションは、前述の間隔シミュレーションを直接実装します。 変数`L`そして`R`現在未使用の範囲をエンコードします。 各ステップで、現在の最小値または最大値のいずれかであると一致する値のみを受け入れます。 無効な値を早期に終了することで、実現可能性が損なわれた場合に不要な作業が防止されます。 

よくある実装上の間違いは、残りの値が常に連続した間隔を形成することを忘れていることです。これにより、セットの代わりに 2 つのポインターを使用することが正当化されます。 もう 1 つの微妙な問題は、次のような場合に平等を誤って扱うことです。`L == R`ただし、両方の条件が正しく崩壊するため、同じロジックが引き続き機能します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n = 1$。 間隔は$[1,1]$したがって、唯一の有効なシーケンスは 1 に等しい単一の要素です。アルゴリズムは次のように設定します。$L = R = 1$、読みます$a_1 = 1$、両方のエンドポイントに一致し、すぐに受け入れられます。 

もう 1 つのケースは、シーケンスが非単調な方法でエンドポイント間を交互に移動する場合です。$n=3$、$a = [3,1,2]$。 シミュレーションは次のように進みます$L=1, R=3$: 最初に 3 セットを削除します$R=2$、その後 1 セットを削除します$L=2$、最後に 2 を削除すると区間が完了します。 これは、アルゴリズムが単調な動きを必要とせず、現在のエンドポイントとの一貫性のみを必要とすることを確認します。 

失敗ケースは、次のような内部値です。$a_i = 2$いつ$L=1, R=5$。 プロセス定義では内部要素を削除できないため、アルゴリズムはそのようなケースを即座に拒否し、バックトラックすることなく正確さを直接強制します。
