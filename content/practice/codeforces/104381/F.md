 ## 解決策
 ## 問題の理解

 小さな整数の配列が与えられ、インデックスの順序付けされたトリプルが何個あるかを数えたいとします。$(x, y, z)$選択した 2 つの要素の積が配列内の 3 番目の要素と等しいという条件を満たします。 言い換えれば、配列内の任意の 2 つの位置 (同じ位置でも異なる位置でもよい) を選択し、それらの値を乗算し、その積と正確に一致する 3 番目の位置の選択肢がいくつあるかを確認します。 

配列の長さは最大 100 ですが、各値は最大でも 100 です。$10^4$。 これにより、インデックスに対するかなり単純な 3 次または 3 次に近い解法でも実行可能であることがすぐにわかります。$n^3 = 10^6$最悪の場合でも、これは Python の制限内に十分収まります。 実行不可能なのは、次の値までのすべての値のペアを反復処理することです。$10^4$また、値ごとの重い計算を繰り返し実行すると、小さな機能を活用せずに不必要なオーバーヘッドが発生するためです。$n$。 

この問題の微妙な問題は多重度です。 値が配列内に複数回出現する場合、各出現箇所は有効なインデックスとして個別に寄与します。 したがって、同じ数値トリプルが出現する場合でも、異なるインデックスの組み合わせはすべて個別にカウントされる必要があります。 たとえば、配列では$[1, 1, 1]$、トリプル$(x, y, z)$はあらゆるインデックスの選択に対して有効であり、次の結果が得られます。$3^3 = 27$1 つだけではなく、有効なトリプル。 

もう 1 つのエッジ ケースは、積が配列内の最大値を超える場合です。 これらのケースは依然として重要です。なぜなら、私たちは値の制限された範囲を対象としてではなく、入力配列内の実際の出現を対象として作業しているからです。 製品が大きい場合でも、配列内に出現する要素があれば一致する可能性があります。 

最後に注意してください$x, y, z$順序付けられたインデックスなので、$(x, y)$とは異なります$(y, x)$値が同じであっても。 この順序付け効果は、正確に計数するために不可欠です。 

## アプローチ

 最も直接的なアプローチは、インデックスの可能なすべてのトリプルを反復処理することです。$(x, y, z)$、計算する$a_x \times a_y$と等しいかどうかを確認します$a_z$。 これは、考えられるすべての順序付き選択に対して条件を直接適用するため、正しいです。 このようなトリプルの数は$n^3$、最悪の場合は$100^3 = 1{,}000{,}000$、これはループがタイトな Python では許容されます。 

少し異なる強引な方法は、最初に修正することです$z$、すべてのペアを試してください$(x, y)$そしてその製品が等しいかどうかをテストします$a_z$。 これは論理的には同じですが、ターゲット値を生成ペアから分離するため、構造化が容易になることがよくあります。 

値ドメイン上のハッシュ積や頻度マップなどのより高度な技術は必要ありません。これは、ドメイン サイズが十分に小さいため、直接列挙がすでに快適に行われているためです。 辞書を使用してすべてのペア積を事前計算しようとすると、依然としてコストがかかります$O(n^2)$そして、さらに別の値を掛けます。$O(n)$マッチングのための係数を調整し、定数を改善することなく同じ複雑さのクラスをもたらします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (トリプル ループ) |$O(n^3)$|$O(1)$| 承認済み |
 | ペア積の列挙 + マッチング |$O(n^3)$|$O(1)$| 承認済み |

 したがって、最適な解決策は、慎重に順序を付けた強引なアプローチです。 

## アルゴリズムのチュートリアル

 1. 配列を読み取り、リストに保存します。 この問題は基本的にインデックスベースであるため、インデックスによって値に直接アクセスする必要があります。 
2. カウンタをゼロに初期化します。 これにより、有効な順序付きトリプルの数が累積されます。 
3. インデックスを修正する$z$、配列内の積の結果の位置を表します。 各要素を潜在的な目標値として扱います。 
4. それぞれについて$z$、インデックスのすべてのペアを反復処理します。$(x, y)$。 コンピューティング$a_x \times a_y$そしてそれを比較してください$a_z$。 それらが一致するたびに、カウンターがインクリメントされます。 
5. すべての反復が完了したら、最終的なカウンター値を出力します。 

この構造により、順序付けられた入力のすべてのペアが、考えられるすべてのターゲットに対してテストされるため、有効な構成が見逃されることはありません。 

### なぜ効果があるのか

 すべての有効なトリプル$(x, y, z)$アルゴリズムが固定インデックスに到達したときに、明示的に 1 回だけ遭遇します$z$すべてのペアを反復処理します$(x, y)$。 すべてのインデックスは独立して列挙され、順序が維持されるため、順序付きトリプルの定義で意図されている以上の重複や省略はありません。 したがって、計数プロセスは完全かつ正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    
    for z in range(n):
        az = a[z]
        for x in range(n):
            ax = a[x]
            for y in range(n):
                if ax * a[y] == az:
                    ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、アルゴリズムのチュートリアルで説明されている構造に直接準拠しています。 外側のループはターゲット インデックスを固定します$z$、一方、2 つの内側のループはすべての順序付きペアを列挙します。$(x, y)$。 比較は中間積の保存を避けるためにインラインで行われるため、メモリのオーバーヘッドが最小限に抑えられ、定数係数が向上します。 

微妙な点の 1 つは、乗算が反復ごとに行われることです。 すべての値は次のように制限されているため、$10^4$、積は 32 ビット整数の範囲内に安全に収まるため、Python ではオーバーフローの問題は発生しません。 もう 1 つの詳細は、条件付きロジックのオーバーヘッドによって漸近動作が改善されず、実行時定数が悪化する可能性があるため、早期の枝刈りを試行しないことです。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての要素が 1 に等しい場合です。入力の場合:```
3
1 1 1
```すべてのペアは 1 に乗算され、すべてのインデックスは有効なターゲットになります。 アルゴリズムはすべてをカウントします$3 \times 3 \times 3 = 27$それぞれのため、トリプルになります$z$、 全て$(x, y)$ペアは有効です。 ネストされたループはすべての組み合わせを自然に列挙するため、特別な処理は必要ありません。 

もう 1 つのケースは、積がすべての配列値を超える場合です。 のために：```
3
2 2 3
```(2,2) のようなペアは 4 を生成しますが、これは配列内に存在しないため、これらの寄与は自動的に無視されます。$a_z = 4$存在します。 等価性チェックでは、反復中にそれらを直接除外します。 

3 番目のケースでは、値が繰り返されて大きな多重度が作成されます。 のために：```
4
1 1 2 2
```1 が出現するたびに、セットベースの解釈と比較して寄与度が 2 倍になります。 このアルゴリズムはインデックスを独立して処理し、有効な一致ごとに重複排除なしでカウンターをインクリメントするため、これを正しく処理します。
