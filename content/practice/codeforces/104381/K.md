 ## 解決策
 ## 問題の理解

 番号付きタイルの 2 つの平行な行が与えられ、各行には次の内容が含まれます。$n$ポジション。 すべてのインデックスで$i$、左の行には値があります$a_i$そして右の行には値があります$b_i$。 プレイヤーは左足で左列の最初のタイルに立ち、右足で右列の最初のタイルに立ちます。 次に、一度に片足ずつ正確に同じ列の次の位置に移動することを繰り返して前進し、決して後退しません。 

足がタイルに着地するたびに、そのタイルの値がスコアに追加されます。 このプロセスは両足が所定の位置に到達するまで続きます$n$。 目標は、収集された合計金額を最大化することです。 左足が所定の位置にある場合、制約によって 2 つの足の間隔がどのくらい離れていてもよいかが制限されます。$i$そして右足はその位置にあります$j$、 それから$|i - j| \le K$常に保持しなければなりません。 

重要な点は、移動が 2 つの結合されたパスに沿って連続的に行われることです。 それぞれの状態は位置だけでなく、両足の相対的な位置によっても定義されます。これは、片側を前に踏み出すとその差が変化するためです。 

制約は小さく、$n \le 300$これは、二次または三次動的計画法のアプローチが受け入れられることを即座に示唆しています。 立方体$O(n^3)$解決策はほとんど合格しないかもしれないが、うまく設計された$O(n^2)$DPは問題なく制限内にあります。 

単純なアプローチでは、考えられるすべての一連の動きをシミュレートしようとします。 各ステップで、距離の制約を尊重しながら、左足または右足のいずれかが前方に移動します。 このようなシーケンスの数は、おおよそ長さの二項パスのように指数関数的に増加します。$2n$、たとえブルートフォースを実行不可能にする$n = 30$。 

より微妙な問題は、一方の足が数歩進んでいる間にもう一方の足が「待機」している場合に発生します。 状態を注意深くエンコードしないと、両足が足並みをそろえて進むと誤って仮定することが容易になり、より高い値を収集するために片側が一時的に速く進むという最適な解を逃すことになります。 

負の値が存在する場合、別のエッジ ケースが発生します。 常に前に進んだり、常に足のバランスをとったりする貪欲なアプローチは、大失敗する可能性があります。距離の制約を尊重しながら、より大きな正のセグメントへのアクセスをロック解除するために、一時的に負の値に踏み込む価値がある場合があるためです。 

## アプローチ

 ブルートフォースのアイデアは、これを州全体にわたる最短パスのような検索として扱うことです。$(i, j)$、 どこ$i$は左足の位置であり、$j$右足の位置です。 各州からどちらかに移動できます$i \to i+1$または$j \to j+1$、インデックスが範囲内にある限り、$|i-j| \le K$。 移動するたびに、踏まれているタイルの値が加算されます。 

これは、有効な一連の動きをすべて調査するため、正しいです。 ただし、状態の数は、$O(n^2)$、各状態から 2 つの遷移に分岐するため、単純な再帰では指数関数的な数のパスが探索されます。 注意して順序付けせずにメモ化した場合でも、再計算や大きなオーバーヘッドが発生する危険があります。 

重要な観察は、これが状態のグリッドに関する古典的な動的計画法の問題であるということです。 各状態は、前の 2 つの状態のみに依存します。$(i-1, j)$そして$(i, j-1)$、制約が与えられた場合$|i-j| \le K$尊敬されている。 これにより、問題は、制限された対角帯域にわたる DP の計算に変換されます。$n \times n$グリッド。 

私たちは定義します$dp[i][j]$左足踏み時の最高得点として$i$そして右足は$j$。 最後の移動は左に進むか右に進むかのいずれかであるはずなので、トランジションは簡単です。 

制約$|i-j| \le K$単に無効な状態を取り除き、DP 領域を対角線の周りのバンドに縮小します。 以来$n \le 300$、すべての有効なペアを反復処理するのが効率的です。

 ## アルゴリズムのチュートリアル

 距離制約を尊重しながら、それぞれの行に沿って独立して移動する 2 つの同期されたポインターとしてプロセスをモデル化します。 

1. 各状態が両足の有効な構成を表す DP テーブルを定義します。 私たちが使用するのは$dp[i][j]$左足がその位置にあるときのベストスコアとして$i$そして右足はその位置にあります$j$。 これにより、ゲームの状態に関する必要な情報がすべて直接エンコードされます。 
2. 起動状態の初期化$dp[1][1]$最初のタイルの合計で$a_1 + b_1$。 これは、動きが発生する前の初期スコアを反映します。 
3. すべてのペアを反復処理します。$(i, j)$昇順で。 各ペアについて、次の場合にのみ処理します。$|i-j| \le K$無効な状態はすべて禁止されており、遷移に寄与できないためです。 
4. それぞれの有効な状態から、左足を次の状態に進めることを検討します。$i+1$。 新しい状態は次のようになります$(i+1, j)$と追加します$a_{i+1}$スコアに。 更新します$dp[i+1][j]$これにより価値が向上する場合。 これは、右足を固定したまま左列を一歩踏み出すことを表します。 
5. 同様に、右足を次の位置に進めることを検討してください。$j+1$に移行中$(i, j+1)$そして追加$b_{j+1}$。 更新します$dp[i][j+1]$それに応じて。 これは対称的なアクションを反映しています。 
6. 遷移を伝播する際、制約を満たす状態のみを更新するようにします。$|i-j| \le K$。 これに違反する遷移は無効な物理構成を表すため、直ちに破棄されます。 
7. 答えは、に格納されている値です。$dp[n][n]$、両足が最後の位置で終わる必要があるためです。 

DP はインデックスの昇順で処理されるため、状態を計算するときに、考えられるすべての先行処理がすでに評価されています。 

### なぜ効果があるのか

 すべての有効な動きのシーケンスは、DP グリッドを通る 1 つのパスに正確に対応します。$(1,1)$に$(n,n)$。 各トランジションでは、新しく踏まれたタイルの値が正確に加算され、タイルが二重にカウントされたりスキップされたりすることはありません。 制約$|i-j| \le K$すべてのステップで適用され、すべての DP 状態が有効な物理構成に対応することが保証されます。 すべてのパスは DP 緩和によって探索され、各状態はそこに到達するすべての方法の中で最大スコアを維持するため、最終状態は$dp[n][n]$最適な答えが含まれている必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, K = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

INF = -10**18
dp = [[INF] * (n + 1) for _ in range(n + 1)]

dp[1][1] = a[0] + b[0]

for i in range(1, n + 1):
    for j in range(1, n + 1):
        if abs(i - j) > K:
            continue
        if dp[i][j] == INF:
            continue

        if i + 1 <= n and abs((i + 1) - j) <= K:
            dp[i + 1][j] = max(dp[i + 1][j], dp[i][j] + a[i])

        if j + 1 <= n and abs(i - (j + 1)) <= K:
            dp[i][j + 1] = max(dp[i][j + 1], dp[i][j] + b[j])

print(dp[n][n])
```この実装は DP 定式化を直接反映しています。 DP テーブルは、到達不能な状態を表すために大きな負の数で初期化されます。 初期状態には両方の開始位置が含まれます。 各遷移では、更新する前に配列の境界と距離制約の両方を注意深くチェックします。 

インデックス付けは DP では 1 ベースですが、配列では 0 ベースであるため、`a[i]`からの左足の移動に対応します。$i$に$i+1$。 この変化は移行全体を通じて一貫しています。 

ループ順序により、状態が処理されるときに、以前に到達可能なすべての状態がすでに考慮されていることが保証されるため、追加の順序付けロジックは必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, K = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    INF = -10**18
    dp = [[INF] * (n + 1) for _ in range(n + 1)]
    dp[1][1] = a[0] + b[0]

    for i in range(1, n + 1):
        for j in range(1, n + 1):
            if abs(i - j) > K:
                continue
            if dp[i][j] == INF:
                continue

            if i + 1 <= n and abs((i + 1) - j) <= K:
                dp[i + 1][j] = max(dp[i + 1][j], dp[i][j] + a[i])

            if j + 1 <= n and abs(i - (j + 1)) <= K:
                dp[i][j + 1] = max(dp[i][j + 1], dp[i][j] + b[j])

    return str(dp[n][n])

 ## 特殊なケース

 微妙なエッジケースは次のような場合です$K$が大きいということは、足が自由に発散できることを意味します。 たとえば、次の場合$K = n$、制約はなくなり、問題はグリッド上の純粋なパス DP になります。 アルゴリズムはこれを自然に処理します。$(i,j)$状態は有効なままであるため、DP は格子全体を探索し、両方の行を独立して最大化できます。 

もう一つのケースは次のような場合です。$K = 1$これにより、2 つのインデックスがほぼ同期した状態に保たれます。 のような場合には$a = [0, 100, 0]$、$b = [0, 0, 100]$、最適な戦略には慎重な変更が必要です。 DP は、次のような州を決して許可しないことで実現可能性を保証します。$(1,3)$、これは制約に違反するため、正しいインターリーブが強制されます。 

負の負荷が大きい入力は、DP が当面の損失よりも将来の利益を正しく優先するかどうかをテストします。 たとえば、後の高価値領域へのアクセスのロックを解除するには、ネガティブ タイルに足を踏み入れる必要がある場合があります。 DP は、ローカルの望ましさに基づいて枝刈りするのではなく、到達可能な最大スコアを常にすべての状態に伝播するため、そのような遷移を保存します。
