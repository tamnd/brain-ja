 ## 解決策
 ## 問題の理解

 一連のリクエスト全体の総取得時間を最小限に抑えるために、カラーボールの入ったボックスを 2 台のロボットに割り当てるように求められます。 各ボックスには、固有の色が無限に供給されます。 ロボットが色を検索するとき、割り当てられたリストからボックスを順番に検査します。 最初のロボットが費やすのは`s1`ボックスあたりの秒数、秒`s2`ボックスごとに秒数。 1 台のロボットが要求された色を見つけるとすぐに検索が停止します。 私たちの目標は、ボックスを 2 つのシーケンスに分割して、すべてのリクエストが行われたときに費やされる時間の合計を最小限に抑えることです。 

入力はボックスの数を与えます`n`、速度`s1`そして`s2`2 つのロボットと整数のリスト`r`どこ`r[i]`カラーボールの回数です`i`要求されます。 ロボットに割り当てられた 2 つのシーケンスを出力する必要があります。 すべてのボックスは 1 回だけ出現する必要があり、各ロボットのリスト内の順序が時間に影響します。 

制約が意味するのは、`n`最大 2×10^5 とすべての合計を指定できます`n`テスト ケース全体の値は 2×10^5 で制限され、テスト ケースごとの線形時間操作が可能になります。 各ロボットのボックスあたりの時間は小さい (最大 10) ですが、色ごとのリクエスト数は最大 10^6 になります。 すべてのリクエストの各検索をシミュレートする単純なアプローチは、操作の数が 10^11 に達する可能性があるため、実行できません。 最適なソリューションでは、ロボットの速度によって重み付けされ、より重い要求のボックスが早期に見つかるような方法でボックスを割り当てる必要があります。 

エッジ ケースには、一方のロボットが他方のロボットよりも速い状況、またはすべてのリクエストの頻度が等しい状況が含まれます。 たとえば、次の場合`s1=1`、`s2=10`、 そして`r=[5,1]`、頻繁にリクエストされるボックスを最初に高速なロボットに割り当てることが重要です。 ボックスを恣意的に配布する不用意なアプローチでは、合計検索時間が最小値の数倍になる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、2 台のロボット間のボックスの可能なすべてのパーティションと、各パーティション内のすべての順列を試します。 それぞれについて、すべてのリクエストにわたる合計検索時間をシミュレートできます。 これは原理的には正しいですが、パーティションの数が 2^n であり、置換のサイズが階乗であるため、実行不可能です。 n=20 の 1 つのテスト ケースでも、制限時間をはるかに超える数十億の可能性が生成されます。 

重要な観察は、総検索時間はロボットのシーケンス内の各ボックスの位置とロボットの速度に依存するということです。 スピードのあるロボットなら`s`検査する`k`色の箱に到達する前に箱`i`、各リクエストの時間寄与は次のとおりです。`(k+1)*s*r[i]`。 したがって、高いボックスが必要です。`r[i]`より速いロボットのリストの早い段階で登場します。 すべてのボックスを降順に並べ替える`r[i]`そして、その時点でより小さな増分寄与が発生するロボットにそれらを貪欲に割り当てることで、合計時間が最小になります。 これが機能するのは、この問題が重み付けされた 2 台のマシンのスケジューリング問題の構造を持っており、重みがリクエスト数に対応し、処理時間がロボットの速度に対応しているためです。 この貪欲なアプローチが適用されると、ボックスの割り当てや並べ替えによって寄与を減らすことはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n × n!) | O(n) | 遅すぎる |
 | 重み付けされた速度による貪欲な割り当て | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ペアのリストを作成する`(r[i], i)`各ボックスごとに。 ここ`r[i]`ボックスのリクエスト数です`i`そして`i`はボックス番号です。 並べ替え順`r[i]`最もリクエストの多いボックスが最初に処理されるようにします。 
2. このリストを降順に並べ替えます。`r[i]`。 最も頻繁に要求されたボックスが最初に考慮されるため、アルゴリズムは最も重みの高いボックスの時間を最小化することを優先します。 
3. ロボット用の 2 つの空のシーケンスを初期化します。`a`そして`b`、カウンターが 2 つあり、`time_a`そして`time_b`、最初はゼロです。 これらのカウンターは、各ロボットに次のボックスを追加した場合の現在の合計増分時間を追跡します。 
4. ソートされたリストを繰り返し処理します。 ボックスごとに、ロボットに割り当てられている場合の増分時間を計算します。`a`として`(current_length_a + 1) * s1 * r[i]`そしてロボットへ`b`として`(current_length_b + 1) * s2 * r[i]`。 
5. 増分時間が小さいロボットにボックスを追加します。 そのロボットのカウンターをインクリメントします。 
6. すべてのボックスを割り当てた後、シーケンスを出力します`a`そして`b`割り当てられた順序で。 

これが機能する理由: 不変条件は、各ステップでボックスをロボットに割り当てることで、合計時間の増加が最小限になるということです。 リクエストは独立しており、合計時間は位置とリクエスト数の積で線形であるため、この貪欲な選択により、最初に最大の重みの寄与が最小限に抑えられます。 分類することで、遅いロボットに重量の重い箱を不必要に遅れて配置することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s1, s2 = map(int, input().split())
        r = list(map(int, input().split()))
        boxes = [(r[i], i + 1) for i in range(n)]
        boxes.sort(reverse=True)
        
        # ensure s1 is the smaller time per box for simpler assignment
        if s1 > s2:
            s1, s2 = s2, s1
            swap = True
        else:
            swap = False
        
        a, b = [], []
        len_a, len_b = 0, 0
        for count, idx in boxes:
            if (len_a + 1) * s1 <= (len_b + 1) * s2:
                a.append(idx)
                len_a += 1
            else:
                b.append(idx)
                len_b += 1
        
        if swap:
            a, b = b, a
        
        print(len(a), *a)
        print(len(b), *b)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、速度を交換することで、ロボット 1 がロボット 2 よりも遅い可能性を処理します。 ソートにより、リクエスト数の多いボックスが最初に処理されるようになります。 増分寄与に基づく貪欲な割り当てにより、各ステップで合計時間の増加が最も少ない場所にボックスを配置することが保証されます。 出力では、両方のシーケンスが正しい順序で印刷されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | リクエスト数によるボックスの並べ替えが優先されます。 代入は O(n) |
 | スペース | O(n) | シーケンス a と b およびソートされたリストを格納します |

 テスト ケース全体の n の合計 ≤ 2×10^5 という制約がある場合、各リストを個別に並べ替えるのは十分高速です。 メモリ使用量は n で線形であり、512MB の制限を大幅に下回っています。
