 ## 問題の理解

 ロボットは原点から開始し、最初は脚の長さを持ちます。`1`。 いつでも、脚の長さを 1 つ増やすか、x 軸または y 軸に沿って現在の脚の長さを正確にジャンプすることができます。 

目的地は`(a, b)`。 脚の長さの増加とジャンプの両方をカウントして、アクションの合計数を最小限に抑えたいと考えています。 

この問題を考えるのに役立つ方法は、最終的な脚の長さの選択を想像することです。`m`。 座標に到達するには`a`、すべての水平ジャンプが正確に寄与します`m`、したがって、少なくとも必要です`ceil(a / m)`水平ジャンプ。 同様に、到達座標`b`少なくとも必要です`ceil(b / m)`垂直ジャンプ。 

使用前の脚の長さ`m`、ロボットは脚を から増やす必要があります。`1`に`m`、費用がかかります`m - 1`動く。 

制約はテストケースの数は少ないですが、座標値は大きくなります。 以来`a`そして`b`と同じ大きさにすることができます`10^9`、位置に対する状態空間検索は不可能です。 に比例するアルゴリズムでも`a`または`b`遅すぎるでしょう。 最適な答えを数学的に特徴付ける必要があります。 

見落としやすいケースがいくつかあります。 

考慮する`a = 1, b = 1`。 答えは`2`。 脚の長さを長くすると、ジャンプが大きくなるとすぐにターゲットをオーバーシュートしてしまうため、有害です。 脚が大きいほど常に優れていると仮定するソリューションでは、誤ってより大きな値が返されます。 

考慮する`a = 1, b = 6`。 脚の長さを利用した最適な戦略`2`。 脚を伸ばすのに 1 回の移動を費やし、その後、水平ジャンプを 1 回、垂直ジャンプを 3 回行い、合計で`5`動く。 両方の座標を分割するまで脚の長さを増やし続けるという貪欲な戦略は、これを見逃してしまいます。 

考慮する`a = b = 10^9`。 最適な脚の長さは、`10^9`。 トレードオフは微妙です。脚が大きくなるとジャンプの回数は減りますが、より多くのアップグレード動作が必要になります。 約数をチェックするだけのアプローチ`a`そして`b`通常、最適な脚の長さはどちらの座標も分割しないため、失敗します。 

## アプローチ

 ブルートフォースの観点は、アップグレードとジャンプの可能なすべてのシーケンスを試すことです。 これは、目的地に到達するためのすべての有効な方法を探索するため、明らかに正しいです。 残念なことに、州の数は天文学的に増加しています。 座標の大きさは次のとおりです`10^9`、位置の検索は完全に不可能になります。 

最初の有益な観察は、ジャンプの順序は重要ではないということです。 脚の長さがある程度の値に達すると`m`、すべてのジャンプには長さがあります`m`、方向に関係なく。 

これまでに到達した最大の脚の長さを次のように決定したとします。`m`。 それ以上増やす理由がない`m`脚の長さが長くなると、余分な移動コストがかかるだけになるためです。 到達後`m`、すべての水平ジャンプが貢献します`m`に向かう単位`a`、すべての垂直ジャンプが貢献します`m`に向かう単位`b`。 

距離をカバーするには`a`、少なくとも必要です`ceil(a / m)`水平ジャンプ。 最後のジャンプがオーバーシュートしても、代わりに早めに停止して適切な割り当てを選択できるため、問題ありません。 同じ推論により、`ceil(b / m)`垂直ジャンプ。 

固定費の総額`m`になる`(m - 1) + ceil(a / m) + ceil(b / m)`。 

ここで問題は、すべての正の整数に対するこの式の最小値を見つけることに縮小されます。`m`。 

一見すると、選択肢は無限にあります。 重要な観察は、最適な`m`決して大きくはありません。 式は大まかに次のように動作します`m + a/m + b/m`。 

これは近くで最小化されます`sqrt(a + b)`。 一度`m`平方根よりもはるかに大きくなると、アップグレードのコストが支配的になります。 

のために`a, b ≤ 10^9`、すべてをチェック`m`くらいまで`50000`で十分です。 実際、公式のソリューションでは境界を使用しています。`sqrt(10^9)`プラス若干のマージン。 以来`sqrt(10^9)`おおよそです`31623`まで繰り返します`100000`100 個のテスト ケースには十分な速度です。

 ## アルゴリズムのチュートリアル

 1.読む`a`そして`b`。 
2. 応答を非常に大きな値で初期化します。 
3. 脚の長さの候補を列挙する`m`から`1`などの安全な上限まで`100000`。 
4. それぞれについて`m`、アップグレードの移動数を計算します。`m - 1`。 
5. 必要な水平ジャンプの最小数を計算します。`ceil(a / m) = (a + m - 1) // m`。 
6. 必要な垂直ジャンプの最小数を計算します。`ceil(b / m) = (b + m - 1) // m`。 
7. この脚の長さの合計移動数は次のとおりです。`(m - 1) + ceil(a / m) + ceil(b / m)`。 
8. これまでに確認された最小値で答えを更新します。 
9. 候補となるすべての脚の長さを確認した後、最小の答えを出力します。 

### なぜ効果があるのか

 戦略を修正して、`m`これまでに到達した最大の脚の長さになります。 

脚の長さに達する`m`正確に必要です`m - 1`アップグレード操作。 それ以降に行われるすべてのジャンプの長さは最大です`m`。 距離をカバーするには`a`、 少なくとも`ceil(a / m)`水平ジャンプは必須。 同じ議論は少なくとも次のようになります`ceil(b / m)`垂直ジャンプ。 

これは、有効な戦略には少なくとも少なくともコストがかかることを意味します。`(m - 1) + ceil(a / m) + ceil(b / m)`。 

逆に、選択したものについては、`m`、まず正確に実行できます`m - 1`アップグレードしてから、必要な数の水平および垂直ジャンプを行います。 それは同じコストを実現します。 

したがって、最適解は、可能な限りこの式の最小値となります。`m`、アルゴリズムは関連するすべての候補を評価します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    LIMIT = 100000
    
    for _ in range(t):
        a, b = map(int, input().split())
        
        ans = 10**18
        
        for m in range(1, LIMIT + 1):
            cur = (m - 1)
            cur += (a + m - 1) // m
            cur += (b + m - 1) // m
            ans = min(ans, cur)
        
        print(ans)

solve()
```この実装では、候補となる脚の長さごとにコスト式を直接評価します。 

表現`(a + m - 1) // m`標準的な整数のみを計算する方法です`ceil(a / m)`。 浮動小数点演算の使用は不必要であり、より大きな入力では精度の問題が発生する可能性があります。 

上限`100000`安全に上にいます`sqrt(10^9)`。 目的関数は次のように動作します`m + (a+b)/m`したがって、最適値は平方根領域付近で発生する必要があります。 までチェック中`100000`非常に高速なままで、関連するすべての候補者をカバーします。 

応答変数は非常に大きな整数に初期化され、より小さいコストが見つかるたびに更新されます。

def solve():
    input = sys.stdin.readline

    sys.stdout = backup_stdout
