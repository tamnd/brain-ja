 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられています。`a`そして`b`、同じ長さです。 許可される操作は通常とは異なります。2 つの文字を交換したり、1 つの位置を変更したりする代わりに、インデックスを選択します。`i`そしてすべてを逆転させます`i`現在の文字列の最後まで。 課題は、次のように変換する一連の接尾辞の反転を見つけることです。`a`の中へ`b`、またはそれができないことを証明します。 シーケンスには最大 2000 個のオペレーションを含める必要があります。 公式声明では、長さ 1000 までの文字列に対するこの変換の問題について説明されています。 

入力サイズは十分小さいため、線形に近いアルゴリズムは必要ありませんが、それでも十分大きいため、考えられるすべての操作を盲目的に試すことは不可能です。 長さ 1000 の文字列の場合、あらゆる瞬間に 1000 回のサフィックス反転が発生する可能性があります。 すべての選択肢を探索する検索ツリーは次のように成長します$1000^k$したがって、深さ 10 でさえ、すでに処理できる量をはるかに超えています。 

重要な観察は、接尾辞の反転には強力な構造があるということです。 これらは、ある点から右へのすべての位置に影響します。これは、選択したインデックスが固定される前のプレフィックスを意味します。 正しい解決策は、文字を左から右に決定し、二度と邪魔することがないという事実を利用する必要があります。 

よくある間違いは、後で同じサフィックスを反転するだけですべての操作を元に戻せると考えることです。 それは事実ですが、任意の変換が可能であるという意味ではありません。 例えば：```
Input:
3
deb
fyf

Output:
-1
```最初の文字列には文字が含まれています`d`、`e`、`b`、ターゲットが持っている間、`f`、`y`、`f`。 接尾辞の反転は既存の文字を並べ替えるだけなので、新しい文字を作成することはできません。 キャラクターの利用可能性を確認せずに位置をシミュレートするだけの不注意な実装は、シーケンスを構築しようとして後で失敗する可能性があります。 

もう 1 つの特殊なケースは、文字列がすでに等しい場合です。```
Input:
1
m
m

Output:
0
```操作は必要ありません。 すべての位置に対して常に反転を実行する実装では、不要な操作が誤って出力されたり、操作の制限を超えたりする可能性があります。 

最後の注意が必要なケースは、必要な反転が接尾辞のみに影響を与える変換です。```
Input:
4
emog
egom

Output:
1
2
```位置 2 から始まるサフィックスを反転すると変更されます`emog`の中へ`egom`。 完全な文字列の反転のみを許可するソリューションでは、これらのケースが見逃されます。 

## アプローチ

 この強引なアイデアは、サフィックス反転のあらゆる可能なシーケンスをシミュレートすることです。 操作は簡単に適用でき、シーケンスがターゲット文字列に到達すれば、それは明らかに正しいです。 状態を幅優先で検索すると、最短のシーケンスも見つかります。 問題は州の数です。 まであります$26^n$可能な文字列を含めることができ、到達可能な状態のみを保存するだけでは十分ではありません。$n=1000$。 2000 という操作制限は役に立ちません。選択肢を探索すると分岐が多すぎるためです。 

重要な観察は、最終的な位置を観察することによって得られます。 ターゲット文字列の最後の文字は、元の文字列の一部の文字に由来する必要があります。 少なくとも 2 の長さの接尾辞を反転すると、最後の文字が反転された接尾辞の最初の文字に変更されます。 これは、必要なキャラクターをそこに持ってくる反転を選択することで、現在の最後の位置を制御できることを意味します。 

キャラクターを最後に配置すると、再度タッチする必要はありません。 これは、文字列を右から左に処理することを示唆しています。 各ステップで、現在の最後の未固定位置に表示される文字を確認します。 すでに存在する場合は無視してかまいません。 それ以外の場合は、そのキャラクターが現在どこにいるかを調べます。 1 回のサフィックス反転で終了することはできますが、残りの部分の向きが不便になる可能性があります。 2 回目の反転で方向を戻すことができます。 

これにより、問題は貪欲な構造に帰着します。 各位置には最大 2 回の操作が必要です。$n=1000$操作の合計数は最大 2000 です。

 ## アルゴリズムのチュートリアル

 1. 弦の最後の位置から開始して、最初の位置に向かって移動します。 現在の位置の後のサフィックスはすでに正しいので、再度変更されることはありません。 
2. 現在の最後の文字が`a`はすでに対応する文字と等しくなります`b`、次の位置に移動します。 正しい文字はすでに固定されているため、操作は必要ありません。 
3. それ以外の場合は、残りのプレフィックス内の必要な文字の位置を見つけます。 この文字は文字列のアクティブ部分の末尾に移動する必要があります。 
4. 見つかった位置からサフィックスを反転します。 目的のキャラクターがアクティブ端に移動します。 
5. 見つかった位置がアクティブ パーツの最初の位置ではない場合は、アクティブ パーツ全体を反転します。 これにより方向が復元され、残りの未固定の文字が使用可能な順序を維持できるようになります。 
6. すべての位置を処理した後、記録された操作を出力します。 いずれかの時点で必要な文字が残りの部分に存在しない場合、変換は不可能です。 

それが機能する理由: 各反復の後、現在のサフィックス`a`の接尾辞と一致します`b`。 この操作はまだ固定されていない位置にのみタッチするため、すでに正しいサフィックスは変更されません。 文字を配置するとき、最初の反転では、必要な文字が目的地に到達することが保証され、オプションの 2 回目の反転では、残りのプレフィックスが、さらに 1 文字削除されることを除き、配置前と同等の状態に変更されます。 各ステップで未解決の位置の数が 1 つずつ減るため、プロセスは最終的に終了するか、不可能な文字要件を検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(input().strip())
    b = input().strip()

    ans = []

    for end in range(n - 1, -1, -1):
        if a[end] == b[end]:
            continue

        pos = -1
        for i in range(end + 1):
            if a[i] == b[end]:
                pos = i
                break

        if pos == -1:
            print(-1)
            return

        if pos != 0:
            ans.append(pos + 1)
            a[pos:] = reversed(a[pos:])

            ans.append(1)
            a[:end + 1] = reversed(a[:end + 1])
        else:
            ans.append(1)
            a[:end + 1] = reversed(a[:end + 1])

    print(len(ans))
    for x in ans:
        print(x)

if __name__ == "__main__":
    solve()
```接尾辞の反転により多くの文字が変更されるため、実装では現在の文字列を変更可能なリストとして保持します。 代入を伴う Python スライスを使用すると、完全に別の文字列を作成せずに、必要なセクションを正確に反転できます。 

ループ処理`end`右から左へ。 インデックス`end`はまだ変更が許可されている最後の位置を表します。 それ以降のすべてはすでにターゲットと等しくなります。 

必要な文字が見つかると、問題のステートメントでは 1 から始まる位置が使用されるため、ストアド操作では 1 から始まるインデックスが使用されます。 実際の Python インデックスはゼロベースであるため、`pos + 1`と印刷されています。 

操作数には当然制限があります。 それぞれの`n`位置では最大 2 つの演算を使用し、最大で`2n`、これは必要な制限に一致します`n ≤ 1000`。
