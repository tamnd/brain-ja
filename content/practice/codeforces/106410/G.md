 ## 解決策
 ## 問題の理解

 各エッジが 2 つの異なる頂点を接続し、繰り返されるエッジがない無向グラフが与えられます。 このタスクは、連続するペアがエッジを形成するような 4 つの異なる頂点を見つけることです。最初の頂点は 2 番目に、2 番目は 3 番目に、3 番目は 4 番目に接続されます。 言い換えれば、正確に 3 つのエッジで構成される単純なパスを探しています。 

出力は、パスに沿って順番に並んだ 4 つの頂点の 1 つ、またはそのような構造が存在しないというステートメントのいずれかです。 

グラフは、最大 20 万の頂点と 30 万のエッジを含む大規模なものにすることができます。 このサイズにより、すべての頂点 4 倍、さらにはすべての長さ 3 のウォークを単純に列挙しようとするアプローチが除外されます。 各頂点の周囲のすべての隣接ペアを反復処理するだけでも、密な領域では二次関数の動作に低下する可能性があるため、すべてのトリプル エッジに対するブルート フォースはすでに許容時間を大幅に超えています。 

重要な制約は、有効なパスを 1 つだけ見つければよいということです。 これにより、問題はグローバル構造のカウントまたは検証から、ローカル構成の効率的な検出へと移行します。 

いくつかのエッジケースでは、不注意なロジックが失敗する場所が明らかになります。 

グラフのエッジが 3 つ未満の場合、長さ 3 エッジのパスには少なくとも 4 つの頂点が連続して接続されている必要があるため、答えは常に -1 になります。 たとえば、入力の場合```
4 1
1 2
```正しい出力は -1 です。 

より微妙なケースは、グラフに多くのエッジがあるものの、星型のような構造になっている場合です。 たとえば、中心ノードが多数のリーフに接続されているとします。 たとえエッジが数百あるとしても、葉と葉の接続は存在しないため、長さ 3 のパスは存在しません。 「エッジが多いとパスが長いことを意味する」と仮定するアプローチは、ここでは失敗します。 

もう 1 つのエッジ ケースは、パスは存在するが、単純なトラバーサルによって頂点が再訪され、誤って単純なパスではなくウォークが生成される場合です。 たとえば、三角形に追加のノードがアタッチされている場合、明示的に区別を強制しない限り、DFS は三角形をループして、間違って繰り返される頂点を返す可能性があります。 

## アプローチ

 直接的な総当りのアイデアは、順序付けられたエッジのトリプルをすべて処理することです。$(a,b), (b,c), (c,d)$すべてのエンドポイントが異なるかどうかを確認します。 すべての頂点を反復してみることもできます$b$、次に隣人の上に$a$そして$c$、そしてそこからさらに拡張します$c$。 すべての有効な答えは中間エッジの中心にある必要があるため、これは概念的に機能します。$b \to c$しかし、単純な実装では、最悪の場合、度数の 3 乗を大まかに合計することになります。 密なグラフでは、次のように縮退します。$O(n^3)$、それは不可能です。 

重要な観察は、必要な構造が非常に局所的であるということです。私たちは、あるエッジを中心とする長さ 2 のパスのみを考慮します。$b-c$、そしてどちらかの側からもう 1 つの拡張機能が追加されます。 任意のトリプルを探索する代わりに、中央のエッジを固定して外側に拡張してみることができます。 これにより、問題はエッジの局所的な近傍をチェックすることだけになります。 

近傍のすべての組み合わせを試す必要がないことがわかると、さらに単純化できます。 エッジを修正したら$b-c$、その後、それを拡張する有効なソリューションを選択する必要があります$a$近所の人たちから$b$除く$c$、 そして$d$近所の人たちから$c$除く$b$。 存在チェックは、いずれかのエンドポイントに、パス内でまだ使用されていない「新しい」ネイバーが少なくとも 1 つあるかどうかを検出することになります。 両側が拡張できれば、すぐに有効なパスが得られます。 

これは線形時間戦略を示唆しています。つまり、エッジを反復処理し、エッジがパスの中間として機能できるかどうかをテストします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | トリプルに対するブルートフォース |$O(n^3)$|$O(n + m)$| 遅すぎる |
 | エッジ中心の拡張チェック |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成します。 これにより、すべての頂点の高速な近傍検索が可能になります。これは、局所的な近傍を繰り返し検査するために必要です。 
2. すべてのエッジを反復処理します。$(b, c)$。 このエッジを、目的のパスの潜在的な中間セグメントとして扱います。 
3. このようなエッジごとに、隣接するエッジをスキャンします。$b$任意の頂点を選択します$a$それは等しくありません$c$。 これにより、$a \neq c$この段階では区別性が保たれます。 
4. 同様に、隣接するものをスキャンします。$c$任意の頂点を選択します$d$それは等しくありません$b$。 
5. そのような頂点が両方とも存在する場合、有効な構造が見つかりました。$a-b-c-d$。 すぐに出力します。 
6. エッジがそのような拡張を生成しない場合は、-1 を出力します。 

この手順で十分である理由は、有効な長さ 3 の単純なパスには中間エッジが必要であるためです。$b-c$。 そのエッジが識別されると、パスの終点は近傍に存在する必要があります。$b$そして$c$、反対側の内部頂点を除きます。 したがって、すべてのエッジをチェックすることで、有効な構成を見逃さないことが保証されます。 

正確かどうかは、長さ 3 の単純なパスには一意の中間エッジがあり、そのエッジがエンドポイントの存在を完全に決定するという事実にかかっています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]

edges = []
for _ in range(m):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)
    edges.append((u, v))

for b, c in edges:
    a = -1
    d = -1

    for x in adj[b]:
        if x != c:
            a = x
            break

    if a == -1:
        continue

    for x in adj[c]:
        if x != b:
            d = x
            break

    if d == -1:
        continue

    print(a)
    print(b)
    print(c)
    print(d)
    sys.exit()

print(-1)
```この実装は隣接リストに依存して、近隣ノードに対する定数時間の反復を可能にします。 各エッジについて、各辺で有効な拡張が見つかるまでスキャンするだけなので、候補が見つかったら不必要に完全な次数リストを走査することはありません。 

微妙な点は、4 つの頂点がすべて異なることを確認する必要があることです。 小切手`x != c`そして`x != b`グラフには自己ループやマルチエッジがないため、反対側のエンドポイント以外の近傍はパスに沿った区別性を保証するため、これで十分です。 

また、隣接リストからペアを再構築するのではなく、実際のエッジに対する繰り返しを保存するためにエッジを個別に保存するため、冗長なチェックが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)
        edges.append((u, v))

    for b, c in edges:
        a = -1
        d = -1
        for x in adj[b]:
            if x != c:
                a = x
                break
        if a == -1:
            continue
        for x in adj[c]:
            if x != b:
                d = x
                break
        if d == -1:
            continue
        return f"{a}\n{b}\n{c}\n{d}\n"

    return "-1\n"

# provided sample 1
assert run("4 1\n3 4\n") == "-1\n"

# provided sample 2
assert run("6 7\n1 3\n1 5\n2 3\n2 5\n2 6\n4 5\n4 6\n") in ["1\n5\n2\n3\n", "3\n2\n5\n1\n"], "sample 2"

# custom: line graph
assert run("4 3\n1 2\n2 3\n3 4\n") != "-1\n", "path exists"

# custom: triangle + tail
assert run("4 3\n1 2\n2 3\n3 4\n") != "-1\n", "simple chain"

 ## 特殊なケース

 星型のグラフは、単に多くのエッジがあるだけでは解決策を意味しない理由を示しています。 すべてのエッジが単一の中心を共有する場合、1 つの端点には中心以外に隣接する端点がないため、すべてのエッジは拡張条件を満たしません。 

純粋なパス グラフは逆のケースを示し、エッジの小さなサブセットのみが中間セグメントとして認められます。 このアルゴリズムは、両方のエンドポイントに空きネイバーがある内部エッジを正しく検出します。 

少なくとも 4 の長さのサイクルには長さ 3 の有効なサブパスが含まれており、エッジを反復処理するときにそのサブパスの中間エッジが検出されるため、サイクルを含むグラフは依然として正しく動作します。
