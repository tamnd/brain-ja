 ## 解決策
 ## 問題の理解

 いくつかの文字列が与えられます。 各文字列について、隣接する 2 つの文字を繰り返し交換することがあります。 問題は、これらの交換によって文字列を 2 つの同一の連続する部分に変換できるかどうかです。 言い換えれば、文字を任意の順序で並べ替えた後、最終的な文字列は次のようになりますか?`t + t`ある文字列に対して`t`?

 入力には複数のテスト ケースが含まれています。 各テスト ケースは 1 つの小文字文字列であり、その文字列の出力は次のようになります。`YES`そのような再配置が存在する場合、そうでない場合`NO`。 

キー制約はすべての文字列の合計の長さであり、最大でも`2 * 10^5`。 これは、すべての文字を一定の回数スキャンするソリューションを用意できることを意味します。 可能な限り多くの再配置を試みたり、スワップをシミュレートしたりするアプローチは、単一の長さの文字列でさえ不可能であるため、不可能です。`200000`膨大な数の可能な置換があります。 

明らかではない部分は、隣接するスワップで何が許可されるかを理解することです。 隣接するスワップではキャラクターを自由に移動できますが、キャラクターを作成したり削除したりすることはできません。 重要なのは、元の文字列内の各文字の数だけです。 

単純な実装では、長さが偶数であるかどうかのみをチェックする可能性があります。 例えば：```
1
aabbc
```長さが 5 であるため、すぐに失敗しますが、長さが偶数の場合、より興味深い間違いが発生します。```
1
aabbcdef
```不注意な解決策では、文字列を半分に分割し、並べ替え後に 2 つの半分を比較するだけになる可能性があります。 ただし、使用可能な文字は、`a, a, b, b, c, d, e, f`。 文字`c`、`d`、`e`、 そして`f`は一度だけ出現するため、両方の半分で同じ位置に属することはできません。 正しい出力は次のとおりです。```
NO
```もう 1 つの特殊なケースは、単一の文字です。```
1
a
```長さ 1 の文字列を 2 つの等しい部分に分割する方法はないため、答えは次のようになります。```
NO
```反対のエッジ ケースは、すべての文字に一致するコピーがすでに存在する文字列です。```
1
abba
```それを次のように並べ替えることができます`ba + ba`したがって、正しい出力は次のようになります。```
YES
```## アプローチ

 この問題を考える強引な方法は、文字列の可能な再配置をすべて試して、それらのいずれかが次の形式を持つかどうかを確認することです。`t + t`。 これは正しいです。隣接する入れ替えによって文字の並べ替えが生じる可能性があるからです。 ただし、長さの文字列`n`まで持つことができます`n!`異なる順列は、非常に小さな値であっても不可能になります。`n`。 

重要な点は、実際には最終的な取り決めを知る必要がないということです。 最後の文字列が`t + t`、すると、すべてのキャラクターが前半に 2 回、後半に 2 回まったく同じ場所に登場します。 つまり、文字列全体のすべての文字が偶数回出現する必要があります。 

逆方向も同様です。 すべての文字が偶数回出現する場合、すべての文字の半分を前半に、残りの半分を後半に配置できます。 隣接スワップにより任意の再配置が可能になるため、この構造は常に到達可能です。 

問題は、順列による検索から頻度のカウントまでに縮小されます。 すべての周波数が 2 で割り切れるかどうかを確認するだけで済みます。

 ## アルゴリズムのチュートリアル

 1. 文字列内に各小文字が何回出現するかを数えます。 最終的な配置では既存の文字のみを使用できるため、これらのカウントには必要な情報がすべて含まれます。 
2. すべての文字数を確認します。 任意の文字が奇数回出現する場合、答えは次のようになります。`NO`。 奇数の量を 2 つのコピー間で均等に分割することはできません。`t`。 
3. すべての文字数が偶数の場合、出力`YES`。 各文字は、最終的な文字列の半分ごとに 1 つずつ、合計 2 つの等しいグループに分割できます。 

これが機能する理由: 不変条件は、隣接する交換によってすべての文字の頻度が維持されることです。 形式の文字列`t + t`は、出現する文字が 2 つの同一の部分に均等に分割されるため、すべての文字が偶数回存在する必要があります。 すべてのカウントが偶数の場合、各側のすべての文字の出現のちょうど半分を取得して、2 つの半分を構築できます。 隣接するスワップを使用して任意の順列を実現できるため、常に必要な形式に到達できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()
        freq = [0] * 26

        for ch in s:
            freq[ord(ch) - ord('a')] += 1

        ok = True
        for count in freq:
            if count % 2:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```このソリューションはテスト ケースの数を読み取り、各文字列を個別に処理します。 頻度配列には小文字ごとに 1 つのスロットがあるため、更新には文字ごとに一定の時間がかかります。 

最後のループでは、2 で割り切れるかどうかをチェックします。 このような再配置の有無は文字数のみに依存するため、再配置された文字列を構築する必要はありません。 

この実装では、文字の元の順序に関する仮定が回避されます。 よくある間違いは、入力文字列の前半と後半を比較することですが、入れ替えが許可されているため、入力順序には特別な意味はありません。

 ## 特殊なケース

 単一文字の場合:```
1
a
```の頻度`a`は 1 つです。 アルゴリズムは、一方の半分がもう一方の半分と同じ文字を受信できないことを検出したため、次のように出力します。`NO`。 

奇数頻度の文字を含む偶数長の文字列の場合:```
1
aabbcdef
```の数`c`、`d`、`e`、 そして`f`みんな一つです。 これらの文字は 2 つの同一の半分に分割できないため、アルゴリズムはその文字列を拒否します。 

すでに条件を満たしている文字列の場合:```
1
abba
```の数`a`そして`b`どちらも2つです。 最終的な配置を構築しない場合でも、アルゴリズムはそれを受け入れます。 考えられる最終的な取り決めは、`ba + ba`。 

有効な入力が大きい場合:```
1
abababab...
```どこ`ab`が何度も繰り返される場合、アルゴリズムは文字数をカウントするパスと定数チェックを 1 回だけ実行します。 可能なスワップや取り決めの数には依存しません。
