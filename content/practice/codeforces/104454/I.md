 ## 解決策
 ## 問題の理解

 大きな値から始まる連続する整数の間隔が与えられます。`s`、具体的には範囲内のすべての整数`[s, s + w - 1]`。 すべての整数に対して`n`、事前定義された値があります`t(n)`、これは必要なステップ数です。`n`Collat​​z プロセスで 1 に到達するには:`n`2で割ってもいいですか、それ以外の場合は次のように置き換えます`3n + 1`、1に達するまで繰り返します。 

指定された間隔内で、概念的に各整数をコラッツ停止時間の値に変換し、長さの配列を生成します。`w`。 タスクは、これらの値がすべて同一である最長の連続セグメントを見つけることです。 複数のセグメントが最大長に達した場合は、最も早く開始するセグメントが選択されます。 

出力について直接考える方法は、Collat​​z の停止時間から導出された数値シーケンスをスキャンし、固定ウィンドウ内で最長の定数実行を検索しているということです。 

制約は非常に重要です。 インターバルの長さ`w`までです`10^6`したがって、範囲全体で線形スキャンを実行する余裕はありますが、再利用せずにコラッツ停止時間を数値ごとに個別に再計算するものは、高価な計算を最大 100 万回繰り返す危険があります。 開始値`s`と同じ大きさにすることができます`10^10`したがって、次の値までは事前計算できません。`s`または、事前に計算された高密度のテーブルに依存します。 唯一実現可能な方向は計算することです`t(n)`オンデマンドで効率的に実行し、可能な限り結果を再利用します。 

単純なアプローチでは、完全な Collat​​z チェーンをそれぞれの`w`数字。 これは、各チェーンが最終的に減少するとしても、中間値が縮小する前に大幅に増加する可能性があり、コストのかかる作業を繰り返すことになるため、遅すぎます。 

不注意な実装を壊す重要なエッジケースが 2 つあります。 まず、結果をキャッシュするのを忘れると、同一のサブチェーンが再計算されることになります。 例えば、`t(13)`そして`t(40)`両方ともすぐに重複状態に達します。 両方の重複を最初から再計算すると機能します。 第 2 に、「完全に区間内にあるセグメント」を解釈する際のオフバイ 1 エラーにより、特に一定の実行が右側の境界付近で開始され、部分的に外側にこぼれてしまう場合に、許可されたウィンドウの端を超えて実行が誤って延長される可能性があります。 

## アプローチ

 ブルートフォース ソリューションは次のように計算します。`t(n)`それぞれに対して独立して`n`で`[s, s + w - 1]`1 に達するまで直接 Collat​​z シミュレーションを使用します。各計算には多くのステップが必要であり、`10^6`これはすぐに不可能になります。 たとえ 1 つの Collat​​z チェーンが平均して数百ステップであっても、総作業量は数億の操作に達する可能性があり、共有サブパスを繰り返し通過するため、実際にはさらに悪化します。 

重要な観察は、コラッツの軌道が重なり合っているということです。 多くの異なる開始値は、最終的には同じ中間状態に陥ります。 つまり、一度知ってしまえば、`t(x)`中間値の場合`x`に達するすべての番号に対してそれを再利用できます。`x`。 

これは自然にメモ化につながります。 停止時間を再計算する代わりに、シミュレーション中に発生したすべての中間数値の計算値をキャッシュします。 すべての中間ノードが一度計算され、その後再利用されるため、各コラッツ ウォークは新しく発見された値ごとに償却定数になります。 

計算できるようになると`t(n)`それぞれに効率的に`n`ウィンドウ内の 2 番目の部分は、結果の配列に対する単純な線形スキャンになります。 現在のランの長さとその開始位置を維持しながら、等しい値の最長ランを追跡します。

 ## アルゴリズムのチュートリアル

 ソリューションを 2 つのフェーズに分割しました。キャッシュを使用して Collatz 停止時間を計算するフェーズと、結果として得られたシーケンスをスキャンして最長の定数セグメントを探します。 

1. 私たちは辞書を管理します`memo`整数を既知の Collat​​z 停止時間にマッピングします。 で初期化します`memo[1] = 0`1 はそれ自体に到達するまでにゼロステップを必要とするためです。 
2. 数字ごとに`n`合間に`[s, s + w - 1]`、計算します`t(n)`反復的なコラッツ シミュレーションを使用します。 一時的なリストを保管しています`path`から始まる訪問された値の`n`。 
3. からシミュレーションしながら`n`にすでに存在する値に遭遇した場合、`memo`、すぐに停止します。 これは、チェーンを継続する代わりに、以前に計算された結果を再利用できるため、非常に重要です。 
4. 停止すると、保存されているパスを通じて既知の結果を逆伝播します。 既知の値に達した場合`x`と`memo[x] = k`、パス内の前の値が値を持つ場合`k + 1`、その前のもの`k + 2`、 等々。 これらすべての計算値を次の場所に保存します。`memo`。 
5. 計算されたそれぞれを保存します`t(n)`配列内で`vals`間隔に合わせて。 
6.スキャンします`vals`左から右に、現在のラン値、現在のランの長さ、およびランの開始インデックスを維持します。 
7. 前の値と等しい値に遭遇すると、実行を延長します。 それ以外の場合は、現在の位置から開始する実行をリセットします。 
8. ランレングスが既知の最良の長さを超えるたびに、回答を更新します。 最適な長さに等しい場合は、厳密に大きな実行時にのみ更新するため、より早い開始インデックスを保持します。 

### なぜ効果があるのか

 正しさは 2 つのリンクされた不変条件に依存します。 まず、メモ化により、すべての`t(x)`は正確に 1 回計算され、永続的に保存されるため、同じ中間値が再び発生するたびに、再計算せずに正確な正確な停止時間を再利用します。 コラッツ停止時間が再帰式を満たすため、逆伝播ステップでは正確さが保たれます。`t(n) = 1 + t(next(n))`したがって、既知のエンドポイントから逆方向に値を再構築すると、パス内のすべてのノードの正確な値が保持されます。 

第二に、スキャン段階ではすべての位置でそれが維持されます。`i`、またはそれ以前で終わる最長の定数セグメントを正確に追跡します。`i`。 各セグメントは、拡張または破損したときに 1 回だけ考慮され、厳密な改善が行われた場合にのみ更新が行われるため、最後に格納されたセグメントは、左端の最大長のランであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

memo = {1: 0}

def collatz(n):
    if n in memo:
        return memo[n]

    path = []
    x = n

    while x not in memo:
        path.append(x)
        if x % 2 == 0:
            x //= 2
        else:
            x = 3 * x + 1

    base = memo[x]

    for v in reversed(path):
        base += 1
        memo[v] = base

    return memo[n]

s, w = map(int, input().split())

vals = []
for i in range(w):
    vals.append(collatz(s + i))

best_len = 1
best_start = s

cur_len = 1
cur_start = s

for i in range(1, w):
    if vals[i] == vals[i - 1]:
        cur_len += 1
    else:
        cur_len = 1
        cur_start = s + i

    if cur_len > best_len:
        best_len = cur_len
        best_start = cur_start

print(best_len, best_start)
```機能`collatz`コアの最適化です。 すべての入力に対して完全なチェーンを再計算する代わりに、中間結果をグローバルに保存します。`memo`。 パス リストには軌跡の目に見えない部分のみが記録され、反転ステップでは既知の結果に正しい距離が割り当てられます。 

最後のスキャンは、隣接する値を比較する単一パスです。`vals`。 開始インデックスは絶対値で維持されます (`s + i`) なので、後処理をせずに必要な位置を直接出力できます。 

微妙な点は、メモ化がすべてのクエリとすべての中間値にわたってグローバルであることです。 これは、近くの数値からのコラッツの軌跡が重なり合い、共有しないと最悪の場合の実行時間が大幅に低下するため、不可欠です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    memo = {1: 0}

    def collatz(n):
        if n in memo:
            return memo[n]
        path = []
        x = n
        while x not in memo:
            path.append(x)
            if x % 2 == 0:
                x //= 2
            else:
                x = 3 * x + 1
        base = memo[x]
        for v in reversed(path):
            base += 1
            memo[v] = base
        return memo[n]

    s, w = map(int, sys.stdin.readline().split())
    vals = [collatz(s + i) for i in range(w)]

    best_len = 1
    best_start = s
    cur_len = 1
    cur_start = s

            cur_len += 1
        else:
            cur_len = 1
            cur_start = s + i
        if cur_len > best_len:
            best_len = cur_len
            best_start = cur_start

    return f"{best_len} {best_start}"

 ## 特殊なケース

 1 つのエッジ ケースはサイズ 1 のウィンドウです。 スキャンがループに入ることはなく、答えはそのままでなければなりません`(1, s)`。 の初期化`best_len = 1`そして`best_start = s`特別な処理を行わなくても正確性が保証されます。 

最長ランが右側の境界に接触した場合、別のエッジ ケースが発生します。 スキャンは隣接する値を比較するときにのみ更新されるため、最終ランの長さは継続的に追跡され、拡張ごとに比較されるため、ループの後でも最終ランが考慮されます。 

最後の微妙なケースは、複数の最大セグメントが存在する場合です。 条件`if cur_len > best_len`タイが以前のセグメントを上書きしないようにします。 厳密な改善のみを更新するため、最も左のセグメントを選択するという要件に合わせて、最も古い最大値が自動的に保存されます。
