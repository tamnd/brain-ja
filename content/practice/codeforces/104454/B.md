 ## 問題の理解

 この問題の各動きは、次のいずれかに着弾するショットです。$k$同心円状のリングであり、各リングはそのインデックスに等しい固定スコアに寄与します。 したがって、ショットは単純に 1 から 1 までの値です。$k$。 アイラは取る$n$ショット、つまりすべての長さを考慮しています-$n$各要素が 1 ～ の範囲にあるシーケンス$k$、そしてその数列の合計を気にします。 

イゴールはすでに固定スコアを生成しています$p$。 課題は、アイラのショットの合計が厳密に次の値より大きくなる可能性のあるシーケンスが何回あるかを数えることです。$p$。 

重要な構造は、このステートメントでは可能性が等しいと言及しているにもかかわらず、これは確率や期待値に関するものではないということです。 これは、制限された要素の合計を使用したシーケンスの純粋な組み合わせカウントです。 

入力サイズにより、動的プログラミングが必要になります。 シーケンスの数は、$k^n$、これは中程度の場合でも天文学的に大きいです$n$なので、総当たりで列挙することは不可能です。 合計制約$n, k \le 300$と最大合計額$n \cdot k \le 90000$有効なソリューションはシーケンスを列挙するのではなく、達成可能な合計を明示的に追跡する必要があることを示します。 

単純なアプローチでは、すべてを生成しようとします。$k^n$シーケンスを調べてその合計をチェックしますが、$n=20$そして$k=10$、これはすでに$10^{20}$、実現可能性をはるかに超えています。 

2 番目の単純なアイデアは、残りのショットと現在の合計に対して再帰を使用することですが、メモ化を使用しないと、同じ部分問題が指数関数的に繰り返されます。 

唯一実行可能な構造は、ショット数と達成された合計に対する DP です。 

微妙なエッジケースが現れるのは、$p = 0$。 この場合、すべてゼロサムの場合を除くすべてのシーケンスが適格になりますが、最小スコアは次のとおりです。$n$、答えは簡単になります。$k^n$。 もう一つの境界線は、$p \ge nk$、どのシーケンスも Igor のスコアを超えることはできず、ゼロが生成されます。

## アルゴリズムのチュートリアル

 ダイナミック プログラミング テーブルを定義し、ショットを 1 つずつ処理し、それぞれの可能な合計に至る方法の数を追跡します。 

1. 正確に 1 つの方法で合計 0 のみが可能なゼロ ショットの DP 配列を初期化します。 これは、ショットが行われる前の空のシーケンスを表します。 
2. 1 から 1 ショットまで$n$、そのショットの後に到達可能なすべての合計を表す新しい DP 配列を計算します。 新しい状態はそれぞれ、1 ～ から 1 つの値を選択することに対応します。$k$。 
3. 一定枚数の場合$i$、合計に達する方法の数$s$合計に到達するすべての方法の合計です$s-1$を通して$s-k$前のレイヤーで。 これは、最後のショットが 1 から 1 までの任意の値に寄与した可能性があるという事実を直接エンコードします。$k$。 
4. 合計する代わりに$k$すべての状態の値を計算する場合、各範囲の合計を定数時間で計算できるように、前の DP 配列のプレフィックスの合計を維持します。 これにより、重複する間隔を繰り返し再計算することが回避されます。 
5.すべての処理が完了したら$n$ショットの場合、すべての DP 値を合計して 0 から$p$。 これにより、負けたシーケンスまたは勝てなかったシーケンスの数が得られます。 
6. シーケンスの総数を次のように計算します。$k^n \bmod (10^9+7)$負けた回数を引いて答えを求めます。 

### なぜ効果があるのか

 すべてのステップで、DP 層は、固定長のすべてのシーケンスの合計による完全で互いに素なパーティションを表します。 すべてのシーケンスの長さが異なるため、各トランジションは正確さを維持します。$i$に 1 つの値を追加することによって一意に形成されます。$[1, k]$一定の長さのシーケンスに$i-1$。 スライディング ウィンドウ式により、すべての有効な拡張子が 1 回だけカウントされ、許容範囲外に無効な合計が導入されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k, p = map(int, input().split())

    max_sum = n * k

    # dp[s] = ways to get sum s after current number of shots
    dp = [0] * (max_sum + 1)
    dp[0] = 1

    for _ in range(n):
        new_dp = [0] * (max_sum + 1)
        prefix = [0] * (max_sum + 2)

        for s in range(max_sum + 1):
            prefix[s + 1] = (prefix[s] + dp[s]) % MOD

        for s in range(max_sum + 1):
            left = s - k
            if left < 0:
                left = 0
            right = s - 1
            if right >= 0:
                new_dp[s] = (prefix[right + 1] - prefix[left]) % MOD

        dp = new_dp

    total_bad = sum(dp[:p + 1]) % MOD

    total = pow(k, n, MOD)
    print((total - total_bad) % MOD)

if __name__ == "__main__":
    solve()
```DP 配列は、各ショット後に、可能性のある各スコアを達成したシーケンスの数を追跡します。 プレフィックス配列は反復ごとに再構築され、遷移に対する定数時間の範囲合計クエリを可能にします。 トランジションは、1 から 1 までの最後のショット値を選択することによって、過去の合計が現在の合計に至るまでの回数を計算します。$k$。 

最後の減算ステップは重要です。なぜなら、「より大きい」を直接計算するためです。$p$」を実行するには、移動するしきい値を追跡する必要がありますが、代わりに、モジュロ演算の下で数値的に安定した補集合を計算します。

import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    max_sum = n * k

    dp = [0] * (max_sum + 1)
    dp[0] = 1

    for _ in range(n):
        new_dp = [0] * (max_sum + 1)

 ## 特殊なケース

 いつ$p = 0$、すべてのシーケンスには少なくとも合計があります$n$, したがって、すべてのシーケンスが勝利します。 DP はすべての質量をゼロより上に配置し、dp[0] のみを減算すると正しく残ります。$k^n - 1$そのときだけ$n = 0$、それ以外の場合はフルカウント。 

いつ$p = nk$、どのシーケンスもそれを超えることはできません。 DP はすべてのシーケンスを合計して合計します。$nk$、減算するとすべてが削除され、ゼロが生成されます。 

いつ$k = 1$、すべてのシーケンスは同じ合計を持ちます$n$。 もし$n > p$の場合、答えは 1 になり、それ以外の場合は 0 になります。DP は単一のパスに縮退し、スライディング ウィンドウは単一の遷移に正しく縮小されます。
