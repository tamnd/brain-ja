 ## 解決策
 ## 問題の理解

 部分的に指定されたものが与えられています$n \times n$グリッドですが、実際には最初の行だけが固定されています。 その行は 1 から 1 までの数値の順列です。$n$、つまり、すべての値が 1 回だけ出現することを意味します。 タスクは残りの部分を構築することです$n-1$最後の正方形がラテン方陣になるように行を追加します。各行には 1 から 1 までの各数字が含まれます。$n$正確に 1 回、すべての列にも各数値が正確に 1 回含まれます。 

主な制限は、最初の行が任意のデータではなく、構造全体を定義するシードになることです。 1 つおきの行は、行方向と列方向の一意性の両方において、その行と一致している必要があります。 

制約は小さく、$n \leq 100$。 これにより、効率に関する懸念がすぐに解消されます。 たとえ$O(n^3)$セルの総数はわずかなので、建設は快適に実行されます。$10^4$。 本当の難しさはパフォーマンスではなく、有効な補完の構造を実現することです。 

単純な試みでは、未使用の数値を貪欲に列に配置することで、各行を独立して埋めようとする可能性があります。 列制約によりすべての行が結合されるため、これはすぐに失敗します。 たとえば、最初の行が$[1,2,3,4]$、グローバル パターンを使用せずにローカルで選択肢をシフトすることで行 2 を独立して構築しようとすると、列内で誤って数値を繰り返し、ラテン語のプロパティが壊れてしまう可能性があります。 

行ごとにランダムなシャッフルを試みると、別の失敗例が現れます。 各行が有効な順列であっても、列の一意性は保証されません。 たとえば:

 入力:```
3
1 2 3
```次のような行を個別に生成するとします。```
1 2 3
2 1 3
3 2 1
```列 2 は次のようになります。$[2,1,2]$、これは 2 を繰り返しており、条件に違反しています。 問題は、列構造では行全体にわたる決定的な位置合わせが必要であることです。 

したがって、問題は数値を埋めることではなく、一貫した周期的動作を持つ構造化オブジェクトに順列を拡張することです。 

## アプローチ

 ブルートフォースの観点では、列の制約を段階的に検証しながら、行ごとにすべての順列を試行してグリッドを行ごとに構築します。 それぞれについて、$n-1$残りの行はあります$n!$可能性があり、各チェックには次のことが必要です$O(n)$列の検証。 これはおおよそ爆発します$(n!)^n$、それはたとえ小さなものであっても完全に実行不可能です$n$。 

重要な点は、最初の行でシンボルの完全な順序がすでに定義されており、この順序をすべての行で一貫して再利用できることです。 最初の行を参照シーケンスとして扱う場合、後続のすべての行は、このシーケンスの巡回シフトによって形成できます。 

より具体的には、最初の行が$a_0, a_1, \dots, a_{n-1}$、そして漕ぎます$i$最初の行を次のようにシフトすることで得られます。$i$左側に位置します。 各行は最初の行の単なる並べ替えであるため、これにより行の有効性が維持されます。 また、各列が同じシーケンスの巡回置換となり、すべての値が列ごとに 1 回だけ出現することが保証されるため、列の有効性も維持されます。 

これにより、問題は組み合わせ検索から線形時間での決定論的な構築へと軽減されます。

 ## アルゴリズムのチュートリアル

 1.読む$n$そして最初の行配列$a$。 この行は、グリッド全体で保持する必要がある数値の正確な順序を定義します。 
2. 各行を作成します$i$配列を左にシフトすることで$i$ポジション。 前から出た要素が最後まで回り込みます。 これにより、すべての行が最初の行の順列のままになります。 
3. 構築されたすべての行を直接印刷します。 

シフトが正しい変換である理由は、位置を回転する際に相対的な順序が維持されるためです。これはまさに列内の繰り返しを避けるために必要なことです。 

### なぜ効果があるのか

 各行は最初の行の順列であるため、行の制約は自動的に満たされます。 列の場合は、列インデックスを修正します。$j$。 複数の行にわたって、その列の値は次のようになります。$a[(i+j) \bmod n]$。 として$i$0から$n-1$、この式はすべてのインデックスを法として循環します。$n$正確に 1 回。つまり、各列にすべての値が一度だけ含まれます。 この不変条件により、行と列の両方の条件が同時に保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

for i in range(n):
    row = []
    for j in range(n):
        row.append(a[(i + j) % n])
    print(*row)
```コアの構築は二重ループで行われます。 行インデックスごとに$i$、元の配列の巡回シフトを生成します。 表現`(i + j) % n`ラップアラウンド動作を強制するメカニズムです。 

微妙な点は、元の配列を決して変更しないことです。 すべての行は固定参照から直接導出されるため、シフトが繰り返し適用された場合に発生する累積エラーが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    n = int(input().strip())
    a = list(map(int, input().split()))
    for i in range(n):
        row = []
        for j in range(n):
            row.append(a[(i + j) % n])
        print(*row)

    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

 ## 特殊なケース

 のために$n = 1$、グリッドには単一のセルが含まれており、シフトは発生しません。 このアルゴリズムは、すでに有効な入力行を正確に生成します。 

次のような反転された最初の行の場合$[4,3,2,1]$、モジュラーインデックスは数値の順序には依存せず、位置の回転のみに依存するため、シフト操作は依然として正確さを維持します。 各インデックスのシフトは行全体で 1 回だけ使用されるため、各列はすべての値を 1 回循環します。
