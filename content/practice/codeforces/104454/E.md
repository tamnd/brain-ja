 ## 解決策
 ## 問題の理解

 各プレイヤーはコインのスタックを持ち、各コインには 1 から n までの額面があります。 スタックは下から上の順序で配置され、いつでも各スタックの一番上のコインのみにアクセスできます。 

1 回の操作は、額面を選択し、その額面と一致する値を持つ 4 つのスタックの上部のコインをすべて同時に削除することで構成されます。 現在一番上にないコインには触れることができないため、各スタックの進行はそれ自体の一番上の要素によって厳密に制限されます。 

このプロセスは、4 つのスタックがすべて空になるまで続行されます。 タスクは、すべてのスタックを完全にクリアするために必要なそのような操作の最小数を決定することです。 

重要な構造は、各スタックを独立してポップしないことです。 代わりに、選択した 1 つの金種が現在の最高値に偶然一致した場合、複数のスタックを一度に進めることができます。 

制約はどの次元においても小さいです。 スタックごとに最大 30 の金種と最大 30 枚のコインがあります。 これは、結合された状態空間が最大 314、約 80 万構成であるため、すべてのスタックの完全な状態を追跡するソリューションが実行可能であることを直ちに示唆しています。 実現不可能なのは、将来の調整を考慮せずに各操作を貪欲に処理することです。早期に選択すると、スタック間の同期の機会が永久に破壊される可能性があるためです。 

単純なアプローチでは、考えられるすべての操作シーケンスをシミュレートします。 有効な選択肢だけを考慮したとしても、各ステップには最大 30 の選択肢があり、プロセスの長さは最大 120 に達する可能性があります。これにより、天文学的に大きな分岐係数が生成され、総当り攻撃は不可能になります。 

貪欲な推論が微妙に失敗するケースは、2 つのスタックが最上部ではなく内部の奥深くで額面を共有している場合に現れます。 貪欲な順序で上位の一致を時期尚早に「追いかける」と、スタックの位置がずれて、一度に複数のコインを削除する将来の機会が失われる可能性があります。 

たとえば、あるスタックが金種 1 の長い連続で始まり、別のスタックは異なる値で始まり、後で 1 も含まれるとします。 アライメントを考慮せずに、利用可能な場合は常に 1 を積極的に削除すると、最初のスタックの 1 実行が早すぎて消費され、後で同時に削除できなくなり、操作の数が増加する可能性があります。 

最大の問題は、コストが個々のシーケンスだけでなく、時間の経過とともにスタックがどのように調整されるかによって決まることです。 

## アプローチ

 ブルートフォース解釈では、各スタックをそのシーケンスへのポインターとして扱い、可能な額面選択のすべてのシーケンスを試します。 4 つすべてのスタックの現在残っているサフィックスによって定義された状態から、最大 n 個の選択肢に分岐し、各操作の効果をシミュレートします。 

これは、すべての有効な操作シーケンスを明示的に探索するので正しいですが、4 つのポインターの同じ状態には指数関数的に多くの方法で到達する可能性があり、検索ツリーは 1 ステップあたり 30 の選択肢として最大 120 ステップまで成長するため、失敗します。 

重要な観察は、プロセスがすべてのスタック内の現在のサフィックスの位置によって完全に決定されるということです。 各スタックに残っているコインの数がわかれば、そこにどのように到達したかに関係なく、未来は決まります。 これは、問題が状態グラフ上の最短経路問題になることを意味します。 

各状態は 4 タプルの位置です。 どの状態からでも、額面を選択すると、最上位のコインがその額面と一致するすべてのスタックをポップすることで、新しい状態に確定的に移行します。 各操作には単位コストがあるため、初期状態からすべてのスタックが空である最終状態までの最短パスを探します。 

これにより、問題は最大 304 状態にわたる多次元 BFS に変換されます。

 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | お(1) | 遅すぎる |
 | 状態グラフ上の BFS | O(n · m₁·m₂·m₃·m₄) | O(m₁・m₂・m₃・m₄) | 承認済み |

## アルゴリズムのチュートリアル

 配列の前ではなく後から効率的に削除できるように、各スタックを逆の順序で表します。 各状態は、各スタックに残っているコインの数を示す 4 つの整数によって定義されます。 

すべてのスタックがいっぱいの状態から開始して幅優先検索を実行し、すべてが空の状態に到達することを目指します。 

### ステップ

 1. 各スタックを反転して、一番上のコインが配列の最後の要素になるようにします。 これにより、インデックスに対するポップのような操作を使用した O(1) の削除が可能になります。 
2. 初期状態を 4 つのスタックすべての全長のタプルとして定義します。 これは、コインが収集される前の状況を表します。 
3. この初期状態で BFS キューを初期化し、それに距離 0 を割り当てます。 
4. キューが空でない間に、現在の状態を抽出します。 空ではない各スタックの最後の要素のみが重要であるため、この状態によって現在どのコインにアクセスできるかが完全に決まります。 
5. 1 から n までのすべての可能な金種について、その金種を選択する 1 つの操作の実行をシミュレートします。 現在のトップがこの額面に等しいスタックごとに、そのポインタをデクリメントします。 
6. その操作を適用した結果、新しい状態が得られます。 この状態をまだ訪れていない場合、またはより少ないステップで到達できる場合は、その距離を更新してキューにプッシュします。 
7. 到達可能なすべての状態が処理されるまで続行します。 答えは、4 つのスタックすべてが空の状態で記録された距離です。 

### なぜ効果があるのか

 このアルゴリズムは、各州が将来の決定に関連するすべての情報を完全に取得するという不変条件に依存しています。 将来の操作は各スタックの現在の最上位要素のみに依存するため、同じ残りのサフィックスにつながる 2 つの異なる履歴は同等です。 BFS は、すべての遷移のコストが等しいため、最初に状態に到達するときは最小限の操作で完了することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    m = list(map(int, input().split()))
    
    stacks = []
    for i in range(4):
        arr = list(map(int, input().split()))
        arr.reverse()
        stacks.append(arr)
    
    # state: (p1, p2, p3, p4)
    start = (m[0], m[1], m[2], m[3])
    target = (0, 0, 0, 0)
    
    # distance dictionary
    dist = {start: 0}
    q = deque([start])
    
    while q:
        s = q.popleft()
        d = dist[s]
        
        if s == target:
            print(d)
            return
        
        p1, p2, p3, p4 = s
        tops = []
        
        if p1 > 0:
            tops.append(stacks[0][p1 - 1])
        if p2 > 0:
            tops.append(stacks[1][p2 - 1])
        if p3 > 0:
            tops.append(stacks[2][p3 - 1])
        if p4 > 0:
            tops.append(stacks[3][p4 - 1])
        
        # try all denominations
        for c in range(1, n + 1):
            np1, np2, np3, np4 = p1, p2, p3, p4
            
            if p1 > 0 and stacks[0][p1 - 1] == c:
                np1 -= 1
            if p2 > 0 and stacks[1][p2 - 1] == c:
                np2 -= 1
            if p3 > 0 and stacks[2][p3 - 1] == c:
                np3 -= 1
            if p4 > 0 and stacks[3][p4 - 1] == c:
                np4 -= 1
            
            ns = (np1, np2, np3, np4)
            if ns not in dist:
                dist[ns] = d + 1
                q.append(ns)

solve()
```このコードでは、最後の要素が常に現在の最上位になるように、各スタックを反転して格納します。 BFS 状態は、反転された配列への明示的なインデックスではなく、残りの長さを使用します。 各トランジションではあらゆる額面が試行され、すべてのスタックに一貫して適用されます。 

微妙な点は、ある州でどの宗派が利用できるかを明示的に計算する必要がないことです。 すべての n 値を反復処理するのは少し無駄ですが、n は最大 30 までなので、全体の作業量は管理可能です。

 ## 特殊なケース

 すべてのスタックが同一である場合、まれなケースが発生します。 その状況では、すべての操作で一度に最大 4 枚のコインが削除され、BFS は状態空間を急速に崩壊させます。 初期状態からはすべての金種の選択が同一の状態遷移をもたらし、BFS は引き続き最適なピックを繰り返す最短パスを見つけるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、スタックが整列されたポイントで共通の上部値を共有しない場合です。 すべての操作は一度に 1 つのスタックにのみ影響するため、アルゴリズムは各スタックを個別に効果的に処理するように縮退します。 BFS は、完了するまでスタック間で交互に行われるシーケンスを自然に探索するため、引き続き機能します。 

より微妙なケースは、初期の選択が後の同期に影響を与える場合です。 たとえある額面がすべてのスタックに表示される場合でも、異なる深さに表示される場合があります。 BFS 状態表現では、状態は過去の決定ではなく残りのサフィックスにのみ依存するため、これらの遅延アライメントが正しくキャプチャされることが保証されます。
