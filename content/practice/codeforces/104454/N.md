 ## 解決策
 ## 問題の理解

 すでに非降順でソートされたシーケンスが与えられています。 その後、配列は挿入や削除によって変更されませんが、左または右に何度も循環的に回転する可能性があります。 

これらのローテーションに加えて、2 種類のクエリが尋ねられます。 1 つの種類は、何らかのオフセットによる回転を実行し、配列を円状に実質的にシフトします。 もう 1 つの種類では、現在の回転された配列に値が存在するかどうかを尋ねます。存在する場合は、現在のレイアウトで最初に出現した位置を報告する必要があります。そうでない場合は、-1 を出力します。 

このステートメントに隠されている重要な観察は、回転によって値の複数セットや、元の並べ替えられた配列内のそれらの相対的な順序が変更されないということです。 インデックス作成の開始点のみが変わります。 したがって、構造は常に、移動する円形ウィンドウを通して表示されるソートされた配列になります。 

制約は大きく、最大 200,000 個の要素と最大 300,000 個のクエリがあります。 これにより、シフトごとに配列を物理的に回転させるアプローチは即座に除外されます。これは、1 回の回転にコストが O(N) となり、制限をはるかに超える最悪のケースでは O(NQ) になるためです。 クエリごとに配列をスキャンするだけでも遅すぎます。 

複数の回転後のインデックス付けでは、微妙な問題が発生します。 シフトのシミュレーションを誤ると、インデックス 1 が現在どこにあるのか簡単に見失い、値の重複や境界の折り返しに対する誤った答えが発生する可能性があります。 もう 1 つの注意が必要なケースは、値が繰り返される場合です。この場合、「最初の出現」は元の順序ではなく、現在の回転開始位置に依存します。 

たとえば、次のように考えてみましょう`a = [1,1,2]`。 1 だけ右シフトすると、配列は次のようになります。`[2,1,1]`。 のクエリ`1`回転されたビューの最初の 1 は位置 2 にあるため、インデックス 3 ではなくインデックス 2 を返す必要があります。回転を調整せずに値の元の位置だけを記憶するソリューションでは、誤った報告が行われます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 配列を明示的に管理します。 各シフト操作は、スライス操作またはデキュー操作を使用して、実際の循環回転を実行します。 各クエリは配列全体をスキャンして、ターゲット値の最初の出現を見つけます。 

これは、説明されているプロセスを文字通りシミュレートしているため、これは正しいです。 ただし、各ローテーションには O(N) のコストがかかり、各クエリには O(N) のコストがかかります。 最大 300,000 回の操作では、最悪の場合、約 10^10 回の操作が必要になりますが、これは実行不可能です。 

重要な観察は、配列が回転するまで静的であるということです。 相対的な順序は変更せず、開始インデックスのみを変更します。 これは、要素をまったく移動する必要がないことを意味します。 どのインデックスが現在位置 1 と見なされているかを示す論理オフセットを維持する必要があるだけです。このオフセットを修正すると、すべてのクエリは単純なインデックス変換の問題になります。 

高速なメンバーシップ クエリをサポートするために、配列がソートされていることを利用して、元の配列に対して二分検索が機能します。 唯一の複雑な点は、元の配列で見つかったインデックスを回転された位置に変換することです。 

回転のためのランニング オフセットと、値を見つけるための二分探索という 2 つのアイデアを組み合わせます。 これにより、各クエリが O(log N) に削減されます。

 | --- | --- | --- | --- |

 | 最適 (オフセット + 二分探索) | O(Q log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列をメモリ内に固定されたものとして扱い、変数を維持します`shift`これは、配列が元の構成に対して右に回転された位置の数を表します。 

1.初期化`shift = 0`。 これは、インデックスの配置が元の配列から変更されていないことを意味します。 
2. シフト動作の場合`s k`、それを法的に正規化します`N`そしてシフトを更新します。 右シフトによる`k`オフセットを増やすとオフセットが増加し、左にシフトするとオフセットが減少します。 すべてをモジュロで保存します`N`したがって、シフトは範囲内に留まります。 この手順により、アレイの物理的な回転が回避されます。 
3. お問い合わせの場合`? x`、最初に元のソートされた配列に対して二分検索を実行して、最初に出現するインデックスを見つけます。`i`価値のある`x`。 見つからない場合はすぐに出力します`-1`。 
4. インデックスを取得したら`i`元の配列では、シフトを使用して回転された配列内の現在の位置に変換します。 オリジナルのインデックス`i`によって前進する`shift`したがって、その新しい位置は`(i + shift) mod N`、1 から始まるインデックスに変換されます。 
5. この計算された位置を出力します。 

重要な考え方は、すべての要素がその同一性と相対的な順序を維持するため、唯一変わるのはインデックスの解釈方法であるということです。 

### なぜ効果があるのか

 どの時点でも、配列は元のソートされた配列を取得し、それをある位置で切り取ることと同じです。`shift`、次に 2 つの部分を交換します。 これは剛体循環変換であるため、すべての要素の相対的な順序は維持されます。 したがって、元の配列内の値の k 番目の出現は、回転された構造でも k 番目の出現のままであり、そのインデックスのみが均一にシフトします。 シフト変数はこの変換を完全にキャプチャするため、それを介してインデックスをマッピングすると正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    shift = 0

    def first_occurrence(x):
        lo, hi = 0, n - 1
        ans = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if a[mid] >= x:
                hi = mid - 1
            else:
                lo = mid + 1
        if lo < n and a[lo] == x:
            return lo
        return -1

    for _ in range(q):
        parts = input().split()
        if parts[0] == 's':
            k = int(parts[1])
            k %= n
            shift = (shift + k) % n
        else:
            x = int(parts[1])
            i = first_occurrence(x)
            if i == -1:
                print(-1)
            else:
                pos = (i + shift) % n + 1
                print(pos)

if __name__ == "__main__":
    main()
```この解決策は、配列を変更せずに維持し、回転オフセットのみを維持します。 二分検索では、元の並べ替えられた配列内で最初に出現するものが検索されます。これは、並べ替えが回転下でも保持されるため有効です。 最後のステップでは、モジュラー演算を使用してインデックスを調整します。 唯一の微妙な点は、モジュロ演算が負のシフトを正しく処理することを保証することです。これが、シフトが適用される前に正規化される理由です。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列のサイズが 1 である場合です。すべての回転が同一であるため、シフト操作は目に見える影響を及ぼしません。 シフトは常にモジュロ N で行われ、モジュロ 1 は常に 0 であるため、アルゴリズムはこれを処理します。したがって、位置マッピングは安定したままになります。 

もう 1 つのケースは、値が繰り返される場合です。 常に元の配列の最初の出現を返すため、左端の一致を返すバイナリ検索に依存します。 ローテーション後、重複がブロックとして移動しても、内部の順序は保持されるため、マップされたインデックスは有効なままになります。 

最後のエッジケースは、大きな負のシフトです。 これらは、適用される前にモジュロ演算を使用して正規化されます。 これにより、シフト値が配列範囲外にドリフトするのを防ぎ、左右の操作を何度も交互に行った後でも一貫したマッピングが保証されます。
