 ## 問題の理解

 異なる整数の奇数長の配列があります。 操作では、連続する 3 つの現在の要素が選択され、それらの 3 つの要素が中央値で置き換えられるため、配列は 2 つ短くなります。 トリプルの選択は完全に柔軟であり、((N-1)/2) 演算の後は元の値が 1 つだけ残ります。 

元の位置 (i) ごとに、(a_i) が最終的に生き残る一連の操作が存在するかどうかを判断する必要があります。 出力はバイナリ文字列であり、文字 (i) は以下に等しい。`1`(a_i) が生き残れるのはまさにいつだろう。 

固定候補 (x=a_i) について考える便利な方法は、正確な値を忘れることです。 他のすべての要素は、(x) との関係に従ってのみ重要です。 (x) より小さい値は次のようになります。`-1`、(x) より大きい値は次のようになります。`+1`、そして (x) 自体は次のようになります。`0`。 したがって、中央値の演算はこれら 3 つの符号のみに依存します。 

公式の制約では (N\le 5000) が許可されており、すべてのテスト ケースにわたる (N) の合計は最大で (10^4) です。 これにより、(O(N^2)) ソリューションは実用的になります。これは、極端な分布では総作業量がせいぜい (10^8) 程度の非常に単純な操作であるためです。一方、(O(N^3)) ソリューションは明らかにコストが高すぎます。 元のコンテスト制限は 1 秒であるため、実装では内部ループを単純にし、大きな定数を含むデータ構造を避ける必要があります。 

誤った実装を簡単に破壊してしまういくつかの特殊なケースがあります。 (N=1) の場合、数値のみが生き残る必要があるため、次のように入力します。`1 / 1`出力があります`1`。 少なくとも 1 つの操作が存在することを前提とした実装は、ここで失敗する可能性があります。 

2 番目のケースは、候補より小さい数値と候補より大きい数値が同じ頻度で発生する場合です。 たとえば、`3 / 2 3 1`、候補者`2`には、小さい要素が 1 つと大きい要素が 1 つあります。 3 つの要素はすでに小さい、候補、大きいという形式を持っているため、`2`は中央値であり、すぐに存続します。 正しい出力は次のとおりです`100`。 候補をその同じ側の 2 つの要素で囲む必要があるアプローチでは、このケースは誤って拒否されます。 

3 番目のケースは、値の順序の終点に近い候補です。 のために`3 / 1 2 3`、 のみ`2`唯一可能な演算は 3 つの数値すべての中央値をとるため、生き残ることができます。 正しい出力は次のとおりです`010`。 要素の順序によってどのトリプルを形成できるかも制御されるため、より大きな配列の場合、候補が全体的に中央値に近いかどうかをチェックするだけでは十分ではありません。 

このステートメントは個別の値を保証するため、すべてが等しい入力は有効な公式テストではありません。 それでもそのような入力が供給された場合でも、候補に等しいすべての要素は次のように分類されるため、比較ベースのアルゴリズムは依然として自然に動作します。`0`。 例えば、`3 / 7 7 7`生み出すだろう`111`。 これは堅牢性テストとしては役立ちますが、公式の問題の制約に関する証拠として使用するべきではありません。

重要な観察は、1 つの候補 (x) を固定し、(x) が生き残れるかどうかだけを尋ねることです。 1 つおきの値を (x) との比較によって置き換えます。 (x) 以下の値は、`-1`、(x) を超える値は次のようになります。`+1`、そして (x) は`0`。 (x) を含まないトリプルの場合、その中央値の符号は、その 3 つの符号の中央値と正確に一致します。 したがって、実際の大きさは問題から消えます。 公式社説では、まさにこの方法をバイナリ比較シーケンスに変換しています。

 [
 S=#(+1)-#(-1)。

 (S=0) の場合、2 つの側面は同じ頻度で発生します。 その状況では、候補を保持し、その周囲の残りを減らすことができるため、答えはすぐに肯定的になります。 同じステートメントは次の場合に対称です。`-1`が多数派です。 

興味深いケースは (S>0) です。`+1`が多数派です。 操作によって (S) に対して何ができるかを考えてみましょう。 両方の符号を含むトリプルには生き残る多数派の符号があるため、`+1`そして1つ`-1`がなくなり、差（S）は変化しません。 トリプル`111`シングルになる`1`、それで2つ`+1`値が消え、(S) が 2 減少します。 他の操作は減少できません (S)。 したがって、候補者が生き残るためには、(S) をゼロに減らすのに十分な多数決符号のトリプルを作成できなければなりません。 

配列の順序によって、これらの多数決トリプルが実際に形成できるかどうかが決まります。 現在利用可能な未使用の大部分の素材の量を維持しながら、左から右にスキャンできます。 多数元素はこの量を増加させます。 反対符号の要素は 1 単位を消費します。これは、その周囲に 2 つの多数要素を使用して、全体的な差を変えることなく要素を削除できるためです。 数量がマイナスになることは決して許可されません。 

過半数ユニットが 3 つ蓄積されると、次の操作を実行できます。`111 -> 1`削減。 これにより、2 つの多数要素が削除され、(S) が 2 ずつ減少します。 この貪欲な戦略は、形成できる多数決トリプルの数を最大化します。これは、多数決が (S) がゼロになるのを妨げている場合にまさに必要なものです。 社説では、シーケンスをスキャンし、連続する多数要素を使用して多数決数を減らすという同じ貪欲なアイデアについて説明しています。 

候補者自体が障壁として機能します。 比較シーケンスを減らしている間は操作が単純に通過することはできないため、スキャンが候補に到達すると可用性カウンターがリセットされます。 これは、固定候補のテストを 1 回のリニア スキャンで実行できる理由でもあります。 

この総当り攻撃は、すべての法的削減を調査するため機能しますが、階乗のような多数の削減命令があるため失敗します。 候補との比較のみが重要であるという観察により、各候補は 1 次元の貪欲スキャンに還元されます。 すべて (N) 個の候補に対してそのスキャンを繰り返すと、(O(N^2)) アルゴリズムが得られます。

 ## アルゴリズムのチュートリアル

 1. 位置 (i) を固定し、(x=a_i) を生存候補者とします。 すべての位置 (j) について、(a_​​j) を次のように分類します。`-1`(a_j<x) の場合、`+1`if (a_j>x)、および`0`(j=i) のとき。 これにより、中央値が (x) より小さいか、等しいか、または大きいかに影響する情報が正確に保持されます。 
2. これらすべての符号の合計 (S) を計算します。 (N-1) 個の非ゼロ符号があり、(N-1) が偶数であるため、(S) は偶数です。 (S=0) の場合、候補を直ちに可能な限りマークします。 候補を中央値として保持しながら、同数の小さい要素と大きい要素を候補の周囲でペアにすることができます。 
3. (S\ne0) の場合は、`majority = sign(S)`。 多数派の符号は、カウントを減らす必要がある唯一の符号です。 完全に多数決符号で構成されるトリプルは、(S) を変更する唯一のタイプの演算であり、(S) を 0 に向かってちょうど 2 だけ変更します。 
4. 比較シーケンスを左から右にスキャンします。 維持する`tp`、現在利用可能な大部分のマテリアルの量。 現在の符号が過半数に等しい場合、増加します`tp`。 逆符号の場合は減少します`tp`ただし、ゼロ以下になることはありません。 これは、多数の要素を使用して、全体的な違いを維持しながら反対の要素を排除するモデルです。 
5. いつ`tp`3 に達すると、過半数要素の 3 倍を費やします。 減少`tp`3 つの等価多数決記号が 1 に置き換えられ、(S) が 0 の方向に 2 ずつ減少するため、2 ずつ減少します。 (S) がゼロに達した場合、候補は可能であり、スキャンは停止できます。 
6. スキャンが候補自体に到達したら、リセットします`tp`ゼロに。 候補は、両側を単純化するために使用される操作によって交差することはできないため、候補の前に蓄積された大部分のマテリアルを、候補の後のマテリアルと組み合わせることができません。 
7. スキャン後、正確に (S=0) の時点で候補が可能になります。 このテストを位置ごとに個別に繰り返します。 

### なぜ効果があるのか

 固定候補の場合、候補の同じ側にあるすべての値は中央値演算に関して交換可能であるため、元の配列を符号シーケンスで置き換えることができます。 2 つの符号が同じ頻度である場合、候補を保持し、その周囲の他の要素を削減できます。 

それ以外の場合は、1 つの記号が厳密な多数決となります。 両方の符号を含む操作では、それぞれの一方が削除され、差は変更されません。 差をゼロに近づけることができる唯一の操作は、3 つの等価多数決記号を 1 つの多数決記号にして、多数決数を 2 減らすことです。 したがって、成功するすべての削減では、最初の差を除去するのに十分なだけの多数決トリプルを正確に実行する必要があります。 

スキャンでは、候補の各側で形成できるこのようなトリプルの数を貪欲に最大化します。`tp`は現在使用できるマジョリティ構造の量を記録し、反対の符号はそのリソースの 1 ユニットを消費します。 過半数単位が 3 つある場合は常に、必要な過半数の数が減少し、同じポジション範囲内に過半数代表者 1 名が残るため、即座に削減を行っても将来の削減に悪影響を与えることはありません。 候補でのリセットは、候補が左部分と右部分を分離しているという事実を尊重します。 したがって、(x) が最終中央値を維持できる程度に比較シーケンスを削減できるとき、スキャンは正確に (S=0) に達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    answer = []

    for i in range(n):
        x = a[i]

        # Compare every value with the candidate.
        signs = [0] * n
        sm = 0

        for j, v in enumerate(a):
            if v < x:
                signs[j] = -1
                sm -= 1
            elif v > x:
                signs[j] = 1
                sm += 1

        # Equal numbers below and above x.
        if sm == 0:
            answer.append('1')
            continue

        majority = 1 if sm > 0 else -1
        tp = 0

        for s in signs:
            if s == 0:
                # The candidate separates the two independent sides.
                tp = 0
            elif s == majority:
                tp += 1
            else:
                tp = max(tp - 1, 0)

            # Three majority signs can be reduced to one.
            if tp >= 3:
                sm -= 2 * majority
                tp -= 2

                if sm == 0:
                    break

        answer.append('1' if sm == 0 else '0')

    return ''.join(answer)

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(solve_case(a))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    main()

の`sm == 0`場合は、多数決の符号を選択​​する前に処理されます。 この境界線は不可欠であるため、`sign(0)`そうしないと、候補者が候補者になる可能性があることがすでにわかっているにもかかわらず、過半数の方向性が示されないことになります。 

いつ`sm`非ゼロ、`majority`どちらかです`1`または`-1`。 スキャンで使用されるのは、`tp`前述した貪欲なリソースとして。 多数派の要素は 1 単位を追加し、反対の要素は 1 単位を削除しますが、それをマイナスにすることはできません。 の`max(tp - 1, 0)`重要です。 許可する`tp`負になると、一致しない反対の要素の前の大部分の要素が将来の削減に誤って影響を与えることになります。 

過半数のユニットが 3 つある場合、`tp -= 2`それよりも`tp -= 3`。 3 つの等号が 1 つの等号に置き換えられるため、アクティブな電源から 2 つのユニットが消えます。 同時に、`sm`によって変化します`-2 * majority`、多数派とマイナス少数派の差の変化と正確に一致します。 

ゼロ記号は候補そのものです。 リセットする`tp`これにより、スキャンで候補の反対側からのリソースが結合されなくなります。 これは実装において最もデリケートな境界条件です。 

すべての値は Python の整数に快適に収まります。`sm`常に間にあります`-(N-1)`および (N-1) であるため、整数のオーバーフローは問題になりません。 

実装では使用します`sys.stdin.readline`出力をリストに蓄積することで、I/O オーバーヘッドが 1 秒間のコンテスト制限に十分小さく保たれます。

        answer.append('1' if sm == 0 else '0')

    return ''.join(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        t = int(sys.stdin.readline())
        out = []

        for _ in range(t):
            n = int(sys.stdin.readline())
            a = list(map(int, sys.stdin.readline().split()))
            assert len(a) == n
            out.append(solve_case(a))

        return '\n'.join(out)
    finally:
        sys.stdin = old_stdin

```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`1`| 最小サイズとゼロオペレーションの場合 |

 最大サイズのソート順列の場合、期待される出力を直接導き出すことができます。 候補に (L) 小さい要素と (R) 大きい要素がある場合、その多数決符号の 3 倍を使用して多数決を減らす必要があります。 どちらの側も他方の 3 倍を超えた場合にのみ、候補となる可能性があります。 (N=4999) の場合、候補ポジション (1251) ～ (3749) が与えられ、2499 個の連続したポジションが生成されます。`1`文字。 

## 特殊なケース

 単一要素の場合`N=1`、候補の比較シーケンスには、`0`、 それで`sm=0`すぐに。 アルゴリズムの出力`1`, 消去するものがないため、これは正しいです。 

のために`3 / 1 2 3`、候補を検討します`1`。 その兆候は、`[0,+1,+1]`、与える`sm=2`。 大多数は`+1`ですが、多数派要素は 2 つしか存在しないため、`tp`3に達することはありません。 決勝戦`sm`2 のままで、位置 1 の答えは次のとおりです。`0`。 候補者`2`兆候がある`[-1,0,+1]`、 それで`sm=0`そして受け入れられます。 候補者`3`候補と対称です`1`。 最終的な出力は次のとおりです`010`。 

のために`3 / 2 3 1`、 候補者`2`兆候がある`[0,+1,-1]`。 初期の差はゼロであるため、アルゴリズムはスキャンを実行する前にそれを受け入れます。 これは、候補者が 1 つのより小さな近傍と 1 つのより大きな近傍でも生き残ることができることを示す最小の例です。 出力は`100`。 

候補者など、一方の側が多数派を占める候補者の場合`1`ソートされた配列内で`[1,2,3,4,5]`、その兆候は`[0,+1,+1,+1,+1]`。 から始めます`sm=4`。 スキャンは次の 3 つの 1 つのトリプルを形成できます。`+1`、削減`sm`4人から2人になりましたが、残りの2人は`+1`値が別のトリプルを形成することはできません。 アルゴリズムは候補を拒否します。 これは、カウントが正しいパリティであるという理由だけで過半数を常に減らすことができると想定するというよくある間違いを捕らえます。 

候補位置も真の境界です。 で`[3,1,2,5,4]`、 候補者`3`は最初の位置にあるため、ゼロ記号はすぐに発生し、`tp`他の値が処理される前にリセットされます。 右側は独立して単純化することができます。 このアルゴリズムでは、候補の両側に要素は必要ありません。これは、有効な生存者が元の配列を開始または終了する可能性があるため必要です。 

最後に、すべてが等しい場合`3 / 7 7 7`公式の区別性保証に違反しますが、候補との比較では結果がゼロになります。 したがって`sm=0`すべての候補に対して、アルゴリズムは次の値を返します。`111`。 このテストは、公式の入力がそのプロパティを保証しているにもかかわらず、実装が誤って 1 つの配列要素が候補と等しいと仮定していないことを確認するのに役立ちます。
