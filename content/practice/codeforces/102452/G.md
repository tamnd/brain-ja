 ## 解決策
 ## 問題の理解

 根が基礎を表す根付きツリーを構築する必要があります。 すべての葉にはモンスターが含まれており、そのモンスターは根に向かって移動します。 頂点に配置されたタワーは、その頂点に到達するすべてのモンスターを殺すため、ルートから葉へのすべてのパスに少なくとも 1 つのタワーが含まれている場合に、タワーのセットは正確に有効になります。 

各頂点には正の構築コストがかかります。 すべての有効なタワー セットの中で、合計コストが最小になる正確に (K) 個の異なるセットが必要です。 入力には (1\le K\le 10^9) を含む (K) のみが含まれています。 ツリーとすべての頂点コストの両方を自由に選択できます。 

出力では、ルートを除くすべての頂点の親と、その後にすべての頂点コストが続くことによってツリーが記述されます。 ツリーには少なくとも 2 つ、最大で (10^5) 個の頂点が含まれている必要があり、すべてのコストは (1) から (10^9) の間でなければなりません。 

(K) の大きな上限が主な手がかりです。 (K) は 10 億になる可能性があるため、最適解ごとに 1 つの頂点を作成することはできません。 したがって、構築では、最適解の数が頂点の数よりもはるかに速く増加するようにする必要があります。 0.5 秒のコンテスト制限により、(O(K)) 構築は特に不適切になります。 

誤って処理されやすい境界ケースがいくつかあります。 (K=1) の場合、出力ツリーには少なくとも 2 つの頂点が必要であるため、単一のリーフは許可されません。 正しい最小構造は次のとおりです。```
1
```概念的には、コスト (2,1) を持つ 1 つの葉を持つルートによって表されます。 リーフの方が安価なので、最適解は 1 つだけです。 

(K=2) の場合、最小の構造は次のようになります。```
2
1
1 1
```根が1つ、葉が1つあります。 ルートの構築には (1) のコストがかかり、リーフの構築にも (1) のコストがかかるため、最適なソリューションは 2 つあります。 ルートを常に厳密に安価にするか、厳密に高価にするような不注意な実装では、誤って 1 つの最適なソリューションしか生成されません。 

(K=3) の場合、3 つの独立した選択肢を使用せずに 3 つの最適解が必要です。 有効な構造の 1 つは、```
5
1 2 1 4
2 2 1 1 1
```ルートには 2 つの子サブツリーがあります。 左側のサブツリーには 2 つの最適なソリューションがあり、右側のサブツリーには 2 つの最適なソリューションがあります。 ルートを使用しない場合、選択肢は 4 つに増えます。 ルート自体はこれら 4 つの選択肢と同じコストを持ち、追加の最適値が 1 つ作成され、3 つではなく合計 5 つになります。 これは、コストと再帰構造を一緒に設計する必要がある理由を示しています。 

## アプローチ

 直接的なアプローチでは、いくつかの候補ツリーから開始し、塔の位置の可能なセットとして頂点のすべてのサブセットを列挙します。 各サブセットについて、すべてのリーフからルートへのパスをチェックし、サブセットがすべてのパスをブロックしているかどうかを判断し、そのコストを計算し、最小コストとその多重度を保持することができます。 (2^N) 個のサブセットがあり、1 つのサブセットをチェックするには (O(N)) 個の作業が必要になる可能性があるため、最悪の場合の作業は最大でも (N2^N) 個の頂点訪問になります。 (N=10^5) では、これは完全に不可能です。 

問題を考察するためのより有効な方法は、1 つのサブツリー内で何が起こっているかを尋ねることです。 (dp(v)) を (v) のサブツリー内のすべてのリーフを保護するために必要な最小コストとし、(ways(v)) をその最小値を達成するための方法の数とします。 

(v) が子 (u_1,u_2,\ldots,u_t) を持つ内部頂点であるとします。 このサブツリー内の最適解には、意味のある可能性が 2 つあります。 (v) で (c_v) のコストをかけてタワーを建設できます。 すべてのコストは正であるため、(v) をすでに使用している最適解では、その下に追加のタワーを配置する理由はありません。 これにより、コストの 1 つの解 (c_v) が得られます。 

もう 1 つの可能性は、(v) にタワーを置かないことです。 その場合、すべての子サブツリーを個別に保護する必要があります。 費用は

 [
 S=\sum_i dp(u_i),
 ]

 そしてその方法の数は

 [
 P=\prod_i 通り (u_i)、
 ]

 なぜなら、私たちはすべての子どもに最適な解決策を独立して選択できるからです。 

したがって、局所的な動作は、(c_v) と (S) を比較することによって完全に決定されます。 (c_v<S) の場合、最適解は 1 つあります。 (c_v>S) の場合、(P) 個の最適解が存在します。 (c_v=S) の場合、両方の可能性が最適となり、(P+1) 個の解が得られます。 

この繰り返しが構築の鍵となります。 (K) 個のソリューションを含むツリーを検索する必要はありません。 最適解の数が子の数の積、またはその積より 1 つ多い頂点を意図的に構築できます。 

特に便利な ID は次のとおりです。 

[
 K=2\左\l床\frac K2\右\r床
 ]

 (K) が偶数の場合、および

 [
 K=2\左\l床\frac K2\右\r床+1
 ]

 (K) が奇数の場合。 

したがって、(K>2) ごとに 2 つの子サブツリーを作成します。 1 つ目は正確に (\lfloor K/2\rfloor) の最適解を持ち、2 つ目は正確に (2) を持ちます。 その積は、偶数 (K) の場合は (K) ですが、奇数 (K) の場合は (K-1) になります。 次に、ルートコストを適切に選択します。 偶数 (K) の場合、両方の子を保護するよりもルートの方が厳密に高価になるため、積は (K) のままになります。 奇数 (K) の場合、ルート自体がタワーを取得する 1 つのソリューションを追加して、ルートを両方の子を保護するのと同じくらい高価にします。 

重要な部分は、(\lfloor K/2\rfloor) が再帰的に使用されることです。 各レベルはおよそ半分 (K) になるため、再帰レベルの数は (O(\log K)) のみになります。 2 番目の子は常に、2 つの最適なソリューションの小さな固定構造です。 

これは、まさに、この問題に対して承認されたコンテストのソリューションで使用されている構造です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N2^N)) | (O(N)) | 遅すぎる |
 | 最適 | (O(\log K)) | (O(\log K)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 再帰的構造を定義する`solve(k, parent)`これにより、正確に (k) 個の最適解を持つサブツリーのルートが作成されます。 そのサブツリーの最小コストを返します。 
2. (k=1) または (k=2) の場合、ルートとリーフを 1 つ作成します。 葉のコスト(1)を与えます。 (k=1) の場合、ルート コスト (2) を与えると、リーフのみが最適になります。 (k=2) の場合、ルート コスト (1) を与えるため、ルートの選択とリーフの選択は結びつきます。 
3. (k>2) の場合、新しいルートを作成し、(\lfloor k/2\rfloor) 最適解を使用して子サブツリーを再帰的に構築します。 
4. 固定 (k=2) 構造を使用して 2 番目の子を作成します。 その最小コストは (1) であり、ちょうど 2 つの最適解があります。 
5. (S) を 2 人の子供から返される最小コストの合計とします。 (k) が偶数の場合、新しいルート コスト (S+1) を割り当てます。 この場合、ルートは高価すぎるため、すべての最適解は両方の子から独立して最適解を選択する必要があります。 解の数は、

 [
 \frac{k}{2}\cdot2=k。 
]

 1. (k) が奇数の場合、新しいルート コストを正確に割り当てます (S)。 現在、2 種類の最適解があります。 1 つはルート自体を使用しますが、もう 1 つはルート自体を使用せず、両方の子で最適なソリューションを独立して選択します。 したがって、その数は

 [
 \frac{k-1}{2}\cdot2+1=k。 
]

 1. 再帰呼び出しに指定された親の下に新しく作成されたすべてのサブツリーを接続します。 頂点はその子孫の前に作成されるため、すべての親インデックスはその子のインデックスよりも小さく、必要な親配列形式が即時に適用されます。 

なぜ機能するのか: の不変条件`solve(k, parent)`構築されたサブツリーには正確に (k) 個の最小コストの有効なタワー セットがあり、戻り値はそのサブツリーの最小コストであるということです。 基本ケースはこの不変条件を直接満たします。 (k>2) の場合、最初の子には (\lfloor k/2\rfloor) 個の最適解があり、固定された 2 番目の子には 2 つの最適解があります。 (k) が偶数の場合、新しいルートは意図的に 1 ユニット高すぎるため、すべての最適解は独立した子の選択から得られ、そのカウントは (k) に乗算されます。 (k) が奇数の場合、ルートは子のみの解と結び付けられ、ちょうど 1 つの可能性が (k-1) に追加されます。 したがって、すべての再帰呼び出しは、元の (K) に到達するまで不変式を保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def construct(k):
    parent = [0]
    cost = [0]

    def add_node(p):
        parent.append(p)
        cost.append(0)
        return len(parent) - 1

    def solve(k, p):
        v = add_node(p)

        if k <= 2:
            leaf = add_node(v)
            cost[leaf] = 1

            # k = 1: root costs 2, so only the leaf is optimal.
            # k = 2: root costs 1, tying the leaf.
            cost[v] = 3 - k
            return 1

        left_cost = solve(k // 2, v)
        right_cost = solve(2, v)

        best_without_root = left_cost + right_cost

        # Odd k: tie, giving one extra solution.
        # Even k: root is more expensive, so only child choices remain.
        cost[v] = best_without_root + (k % 2 == 0)

        return best_without_root

    solve(k, 0)

    n = len(parent) - 1

    out = [str(n)]
    out.append(" ".join(map(str, parent[2:])))
    out.append(" ".join(map(str, cost[1:])))

    return "\n".join(out)

def main():
    k = int(input())
    sys.stdout.write(construct(k) + "\n")

if __name__ == "__main__":
    main()
```2 つの配列`parent`そして`cost`出力に必要な情報を正確に保存します。 インデックス 0 はダミー エントリであるため、頂点 (1) はインデックス (1) に格納され、ステートメントの 1 から始まる番号付けと一致します。 

基本ケースでは、1 つの頂点ツリーを許可するのではなく、意図的に 2 つの頂点を作成します。 (k=1) の場合、コストは (2,1) であるため、固有の最適解はリーフになります。 (k=2) の場合、コストは (1,1) となり、2 つの同点の選択肢が生成されます。 

(k>2) の再帰呼び出しの場合、`left_cost + right_cost`新しいルートにタワーがない場合の最小コストです。 表現`(k % 2 == 0)`Python のブール値であり、次のように評価されます。`1`偶数 (k) の場合と`0`奇数 (k) の場合。 したがって、ルートは偶数の場合は 1 単位高くなりますが、奇数の場合はまったく同じになります。 

再帰の深さは (O(\log K)) のみで、(K\le10^9) の場合は最大でも約 30 なので、Python の再帰制限は問題になりません。 頂点の総数も少ないです。 実際、(T(k)) が頂点の数である場合、(k>2) の場合、

 [
 T(k)=1+T(\lfフロアk/2\rフロア)+T(2)
 ]

 そして (T(1)=T(2)=2)。 (K=10^9) の場合、頂点の数は 100 未満になります。 

すべてのコストは非常に小さいままです。 返される最小コストは再帰レベルごとに 1 だけ増加するため、最大コストは (O(\log K)) となり、許容される (10^9) よりもはるかに低くなります。 

## 実用的な例

 付属のサンプルは (K=2) です。 再帰呼び出しはすぐに基本ケースに到達します。 

| ステップ | (k) | 新しいルートコスト | 子供料金 | 最適な方法 |
 | --- | --- | --- | --- | --- |
 | 基礎工事 | 2 | 1 | 1 | 2 |

 結果として得られるツリーは、```
2
1
1 1
```最適な解決策は 2 つあります。 1 つはタワーを根元に配置し、もう 1 つは葉に配置します。 どちらもコストは(1)です。 

(K=3) の場合、ルートは (k=1) サブツリーと (k=2) サブツリーを再帰的に構築します。 

| ステップ | (k) | 子供の数 | 子供料金 | ルートコスト | 結果のカウント |
 | --- | --- | --- | --- | --- | --- |
 | 左の子 | 1 | 1 | 1 | 2 | 1 |
 | 右の子 | 2 | 1 | 1 | 1 | 2 |
 | 最終ルート | 3 | (1,2) | (1,1) | 2 | (1+1\cdot2=3) |

 結果の出力は次のとおりです。```
5
1 2 1 4
2 2 1 1 1
```左側の子サブツリーには 1 つの最適解があり、右側の子サブツリーには 2 つの最適解があります。 ルートが選択されていない場合、最適な組み合わせは (1\cdot2=2) 通りあります。 ルート自体の合計コストはまったく同じであるため、ルートのみを選択すると、より 1 つの最適なソリューションが得られます。 合計は(3)となります。 

(K=4) などの偶数値の場合、両方の再帰的な子には 2 つの最適解があります。 

| ステップ | (k) | 子供の数 | 子供料金 | ルートコスト | 結果のカウント |
 | --- | --- | --- | --- | --- | --- |
 | 左の子 | 2 | 2 | 1 | 1 | 2 |
 | 右の子 | 2 | 2 | 1 | 1 | 2 |
 | 最終ルート | 4 | (2,2) | (1,1) | 3 | (2\cdot2=4) |

 ここでは、ルートのコストは (3) ですが、2 つの子サブツリーのコストは合わせて (2) のみです。 したがって、最適解はルートを使用できません。 各子で 2 つの最適解のうち 1 つを独立して選択し、(2\cdot2=4) 個の可能性を生成する必要があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(\log K)) | 各再帰レベルは (k) を (\lfloor k/2\rfloor) に置き換え、1 つの一定サイズ (k=2) のサブツリーを追加します。 |
 | スペース | (O(\log K)) | 構築されたツリーには (O(\log K)) 個の頂点があり、再帰の深さは (O(\log K)) です。 |

 (K\le10^9) なので、基本ケースに到達するまでの半分の回数は 30 回未満です。 したがって、この構築では数十個の頂点のみが作成され、(10^5) 制限を十分に下回ります。 コストも (O(\log K)) しかないため、(10^9) をはるかに下回ります。 これは、コンテストの 0.5 秒および 512 MB の制限に簡単に適合します。 

## テストケース

 これは建設的な問題であるため、出力は一意ではありません。 完全な出力文字列と 1 つの固定された答えを比較するアサーションは、完全に有効な構造を拒否します。 代わりに、以下のテスト ヘルパーは生成されたツリーを解析し、その最小コストと最適解の数を個別に再計算します。```python
import sys
import io

def construct(k):
    parent = [0]
    cost = [0]

    def add_node(p):
        parent.append(p)
        cost.append(0)
        return len(parent) - 1

    def solve(k, p):
        v = add_node(p)

        if k <= 2:
            leaf = add_node(v)
            cost[leaf] = 1
            cost[v] = 3 - k
            return 1

        a = solve(k // 2, v)
        b = solve(2, v)
        s = a + b
        cost[v] = s + (k % 2 == 0)
        return s

    solve(k, 0)

    n = len(parent) - 1
    return (
        str(n) + "\n" +
        " ".join(map(str, parent[2:])) + "\n" +
        " ".join(map(str, cost[1:])) + "\n"
    )

def run(inp: str) -> str:
    k = int(inp.strip())
    return construct(k)

def validate(output: str, wanted_k: int) -> bool:
    data = output.split()
    pos = 0

    n = int(data[pos])
    pos += 1

    if not (2 <= n <= 100000):
        return False

    parents = [0, 0]
    for v in range(2, n + 1):
        p = int(data[pos])
        pos += 1
        if not (1 <= p < v):
            return False
        parents.append(p)

    costs = [0]
    for _ in range(n):
        c = int(data[pos])
        pos += 1
        if not (1 <= c <= 10**9):
            return False
        costs.append(c)

    if pos != len(data):
        return False

    children = [[] for _ in range(n + 1)]
    for v in range(2, n + 1):
        children[parents[v]].append(v)

    dp = [0] * (n + 1)
    ways = [0] * (n + 1)

    for v in range(n, 0, -1):
        if not children[v]:
            dp[v] = costs[v]
            ways[v] = 1
            continue

        child_cost = 0
        child_ways = 1

        for u in children[v]:
            child_cost += dp[u]
            child_ways *= ways[u]

        if costs[v] < child_cost:
            dp[v] = costs[v]
            ways[v] = 1
        elif costs[v] > child_cost:
            dp[v] = child_cost
            ways[v] = child_ways
        else:
            dp[v] = costs[v]
            ways[v] = child_ways + 1

    return ways[1] == wanted_k

# Provided sample.
assert validate(run("2\n"), 2), "sample 1"

# Minimum K.
assert validate(run("1\n"), 1), "K = 1"

# Small odd value, exercises the tie case.
assert validate(run("3\n"), 3), "K = 3"

# Small even value, exercises the product case.
assert validate(run("4\n"), 4), "K = 4"

# Maximum allowed K.
assert validate(run("1000000000\n"), 1000000000), "K = 10^9"

print("all tests passed")

 |`1`| 最適解が 1 つだけある有効なツリー | 最小値 (K) と必須値 (N\ge2) |
 |`3`| 正確に 3 つの最適解を含む有効なツリー | 奇数 (K)、ルートが 1 つの結合された解を追加します。 
|`4`| 正確に 4 つの最適解を持つ有効なツリー | 偶数 (K)、子ソリューションのカウントは乗算されます。

 ## 特殊なケース

 (K=1) の場合、アルゴリズムは基本ケースに入り、2 つの頂点を作成します。 葉のコストは (1)、根のコストは (2) です。 最小コストで有効な唯一の解決策は、タワーをリーフに配置することです。 正確な出力は次のとおりです```
2
1

偶数 (K>2) の場合、ルートは厳密に 2 つの子サブツリーを合わせたよりも高価でなければなりません。 (K=6) の場合、最初の子には 3 つの解があり、2 番目の子には 2 つの解があります。 彼らの独立した選択は (3\cdot2=6) を与えます。 ルートには、子コストの合計より 1 多く割り当てられ、別の最適値になるのを防ぎます。 ここで等式を使用すると、誤って 7 つの解が生成されてしまいます。

最後に、正のコストはカウントの議論に不可欠です。 タワーが頂点に配置されている場合、追加のタワーごとに少なくとも (1) のコストがかかるため、不要な子孫タワーを追加しても最小コストを維持することはできません。 したがって、「この頂点にあるタワー」という選択肢は、その頂点の下にある解のコレクション全体ではなく、まさに 1 つの最適な解を提供します。 これにより、再帰 (1+\prod ウェイ) が正確になります。
