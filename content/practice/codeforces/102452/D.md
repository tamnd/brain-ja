 ## 解決策
 ## 問題の理解

 ラベルは、順序付けられた文字列のシーケンスを形成します。 選択した基数 (k) については、正確に (k) 個の 10 進数が許可されます: (10-k, 11-k, \ldots, 9)。 ラベルは最初に長さによって順序付けされ、同じ長さ内で許可された桁を使用して辞書順に順序付けされます。 

たとえば、(k=7) の場合、使用可能な桁は (3,4,5,6,7,8,9) です。 最初の 7 つのラベルは 1 文字の文字列です`3`を通して`9`。 これらの後には、(7^2) 個の 2 文字の文字列がすべて続きます。`33`、`34`、で終わる`99`。 これらの後には (7^3) 個の 3 文字の文字列がすべて続きます。 

各テスト ケースでは、基数 (k) と 1 から始まる位置 (X) が与えられます。 タスクは、その位置を占めるラベルを出力することです。 

制約から得られる重要な観察は、(X) は最大でも (10^9) ですが、独立したテスト ケースは最大 (10^5) 個存在する可能性があるということです。 ラベルを 1 つずつ調べるソリューションでは、1 つのケースに対して最大 (10^9) 回の反復が必要になりますが、これはすでに大きすぎます。 (10^5) の場合では、(O(X)) メソッドでさえ完全に非実用的です。 答えを含むブロックに直接ジャンプし、その答えの数字だけを構築する必要があります。 

解答の長さも非常に短いです。 長さ (L) の (k^L) 個のラベルがあるため、(k=2) の場合、最初の (29) 個の長さにはすでに (2^{30}-2=1,073,741,822) 個のラベルが含まれています。 したがって、最も成長の遅い基底であっても、(X\le 10^9) の答えには最大でも (29) 文字が含まれます。 これにより、ケースごとの (O(\log_k X)) アルゴリズムが十分に高速になります。 

いくつかの境界ケースにより、直接実装が失敗する可能性があります。 

(k=10) と (X=1) の場合、答えは次のようになります。```
0
```位置は 1 から始まるため、最初のラベルは最初のブロック内の数値オフセット 0 に対応します。 (X) から直接変換を開始する不注意な実装では、`1`その代わり。 

(k=10) と (X=11) の場合、答えは次のようになります。```
00
```最初の 10 桁は 1 桁のラベルです`0`を通して`9`。 位置 (11) は最初の 2 桁のラベルです。 実装で、前のブロック全体と比較する代わりに条件 (X \ge k^L) を使用すると、この位置が 1 桁のブロックに誤って割り当てられる可能性があります。 

(k=7) と (X=8) の場合、答えは次のようになります。```
33
```許可される数字は次のとおりです`3`を通して`9`, したがって、最初の 7 つのラベルは (1) から (7) の位置を占めます。 位置 (8) は 2 桁のブロックを開始します。 数字が常にゼロから始まると仮定した解決策は、次のようになります。`00`、これはこのベースでは有効なラベルではありません。 

(k=2) と (X=15) の場合、答えは次のようになります。```
8888
```長さ 1 ～ 3 のラベルが (2+4+8=14) 個あるため、位置 (15) が最初の 4 文字のラベルになります。 許容される最小の桁は次のとおりです。`8`、すべての長さの最初のラベルは完全に次のもので構成されます。`8`s. これにより、ブロック境界と数字変換の両方でエラーが検出されます。 

## アプローチ

 最も直接的な解決策は、ラベルを実際の順序で生成することです。 最初はすべて 1 文字のラベル、次にすべての 2 文字のラベル、次にすべての 3 文字のラベルというように続きます。 各長さ内で、通常の基数 (k) カウントにより、正しい辞書編集順序が得られます。 カウンターを保持し、それをラベルに変換し、(X) 番目のカウンターを生成した後で停止することができます。 

この強引な方法は、問題によって定義された順序に正確に従っているため、正しいです。 問題はその仕事量です。 (X=10^9) の場合、10 億のラベルを生成する必要があります。 (k=2) の場合、答えの長さは (29) になり、最初の (10^9) 個のラベルを生成するには、およそ (2.79\times10^{10}) 個の文字操作が必要になります。 Python のオーバーヘッドを考慮する前でさえ、これは実用的な競技プログラミング ソリューションをはるかに超えています。 

シーケンスの構造により、はるかに優れたカウント方法が得られます。 (L) 個の位置には (k) 個の選択肢があるため、すべての長さ (L) ブロックには正確に (k^L) 個のラベルが含まれます。 したがって、回答の長さを決定するために何も生成する必要はありません。 残りの位置が 1 つのブロック内に収まるまで、ブロック全体を減算できます。 

答えの長さが (L) であると仮定し、そのブロック内のゼロから始まるインデックスを (r) とします。 (r) の (L) 桁の基数 (k) 表現は、先頭にゼロが埋め込まれており、必要なラベルを識別します。 唯一の違いは、問題の桁が 0 ではなく (10-k) から始まることです。 したがって、すべての基数 (k) の数字 (d) は、印刷された数字 (d+(10-k)) に変換されます。 

このブルート フォース ソリューションは、インデックスを作成する必要があるのと同じシーケンスを明示的に実行するため機能しますが、シーケンスには 10 億のエントリが含まれる可能性があるため失敗します。 各長さが正確に (k^L) 個のラベルの完全なブロックを形成するという観察により、それらのブロックを算術的にスキップし、最大 (29) 文字のみを構築できます。

 ## アルゴリズムのチュートリアル

 1. 要求された位置 (X) から開始し、長さ (1) のラベルのブロックを検討します。 そのブロックには正確に (k) 個のラベルが含まれています。 (X) がこのブロックより大きい場合は、(k) を減算して長さ (2) に移動します。 同じように続けます。 

短い長さをすべて処理した後、残りの値 (X) は、正しい長さ (L) のブロック内の 1 から始まる位置になります。 
2. (X) を (X-1) に置き換えて、この残りの位置をゼロベースのオフセットに変換します。 ブロック内の最初のラベルは数値 1 ではなく 0 に対応するため、これは重要です。 
3. ゼロベースのオフセットをベース (k) に変換します。 結果の表現には正確に (L) 桁の数字が含まれている必要があるため、長さが (L) になるまで先頭にゼロを追加します。 

(0) から (k^L-1) までのすべての (L) 桁の基数 (k) の数値が、ラベルと同じ順序で長さ (L) のブロック内に 1 回だけ出現します。 
4. 各基数 (k) の数字を問題の実際の 10 進数に変換します。 基数 (k) の数字が (d) の場合、(d+(10-k)) を出力します。 たとえば、基数 (7) では、内部数字 (0,1,2,\ldots,6) が印刷数字 (3,4,5,\ldots,9) になります。 
5. 変換された数字を元の順序で追加し、結果の文字列を出力します。 入力には最大 (10^5) 個のケースが含まれるため、それぞれを個別に処理し、出力を書き込む前に蓄積します。 

### なぜ効果があるのか

 すべての長さ (L) に対して、正確に (k^L) 個の可能なラベルがあり、問題は長さ (L) に達するまでの短い長さをすべてリストします。 減算ループは、ターゲット ブロックに先行する完全なブロックを正確に削除するため、残りの (X) は、ターゲット自体の長さ内での 1 から始まるターゲットの位置になります。

(X-1) に変更すると、値は (0) から (k^L-1) の範囲になります。 これらの値と内部数字セット (0,\ldots,k-1) のすべての (L) 桁の文字列の間には 1 対 1 の対応関係があります。 Base-(k) 表現では、すべての表現が長さ (L) になるまでパディングされる場合、これらの文字列が辞書編集上の昇順で与えられます。 最後に、すべての内部数字に (10-k) を追加すると、その表現が許可された 10 進数字に正確にマップされます。 したがって、構築された文字列はまさに要求されたラベルです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_label(k, x):
    length = 1
    block = k

    while x > block:
        x -= block
        length += 1
        block *= k

    # Convert from one-based position inside the block
    # to a zero-based base-k value.
    value = x - 1

    digits = ['0'] * length
    shift = 10 - k

    for i in range(length - 1, -1, -1):
        digits[i] = chr(ord('0') + shift + (value % k))
        value //= k

    return ''.join(digits)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        k = int(input())
        x = int(input())
        out.append(get_label(k, x))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```の`length`変数は現在検査されているブロックを表します。 それに対応する`block`値は (k^{length}) で、ちょうどその数の文字を持つラベルの数です。 このループは、ターゲットが現在のブロック内に収まるまで、ブロック全体を減算します。 

ライン`value = x - 1`キーオフの調整です。 ターゲットが固定長ブロック内に入ると、最初のラベルは内部値 0 に対応し、2 番目のラベルは 1 に対応する必要があります。 

変換ループは、以下を使用して右から左に基数 (k) 桁を抽出します。`value % k`。 (k) で除算すると、処理したばかりの数字が削除されます。 出力配列は正確に初期化されます。`length`そのため、先頭のゼロは自動的に保持されます。 これが必要な理由は、`00`そして`0`先行ゼロが無視された場合、両方が同じ数値を持つ場合でも、異なるラベルを表します。 

表現`shift = 10 - k`数字の変換を実行します。 たとえば、(k=7) の場合、内部桁のゼロは次のようになります。`3`、内部の数字 6 は`9`。 

Python には整数オーバーフローの問題はありません。 ターゲットがブロック内にあり (X\le10^9) になるとループが停止するため、必要な最大の中間ブロックは十分に小さいです。 固定幅言語では、十分な幅の整数型を使用することをお勧めします。 

出力はリストに蓄積され、一度書き込まれます。 (10^5) 個のテスト ケースでは、`print`通常はまだ管理可能ですが、文字列を収集することで不必要な出力オーバーヘッドが回避されます。
