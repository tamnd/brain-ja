 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$正確に含まれるグリッド$n-1$1 であり、他のすべてのセルは 0 です。 グリッド自体は所定の位置に固定されていません。任意の 2 つの行または任意の 2 つの列を交換することで、行と列の順序を任意に変更できます。 

目標は、1 を含むすべてのセルが主対角線の厳密に下になるように構造を再配置することです。つまり、各セルが の位置にあることを意味します。$(i, j)$、私たちは持っている必要があります$i > j$。 

行と列の交換はグローバルな置換であるため、実際の機能は、行インデックスと列インデックスを独立して自由に置換できることです。 行列の値自体は決して変更されず、これらの順列での座標のみが変更されます。 

制約$n \le 1000$および最大の許容量$10^5$操作は、指数関数的プロセスやバックトラッキング プロセスをシミュレートするのではなく、直接の貪欲な順列を構築することが期待されていることを示します。 配置を調査したり、違反を繰り返し修正しようとするアプローチでは、スワップ数が 2 次以上に悪化する危険性があります。 

微妙な点は、まさに$n-1$もの。 これは任意ではありません。 これは、この構成が、ほとんど擬態したツリー構造に似ていることを示唆しています。すべての行または列が、制約されたマッチングのような関係に関与しており、段階的に位置を調整するのではなく、位置を割り当てるソリューションを期待する必要があります。 

最も一般的な失敗例は、一貫性を強制せずに行と列の再配置を個別に処理する場合に発生します。 たとえば、ローカル スワップによって貪欲に対角線より下にプッシュしようとすると、すでに固定されているポジションを簡単に崩すことができます。 もう 1 つの失敗は、それぞれを個別に修正できると想定していることですが、スワップは行全体と列全体に同時に影響するため、決定はグローバルでなければなりません。 

小さな失敗例:$(1,2)$そして$(2,1)$のために$n=3$。 単純な考えでは、それぞれを独立して対角線の下に押し出そうとするかもしれませんが、行 1 と行 2 を交換すると、列の順序に応じて一方が修正され、他方が壊れます。 正しいソリューションでは、代わりに行と列の一貫した順序を割り当てる必要があります。 

## アプローチ

 ブルートフォースの観点では、指定された行列から開始して、対角線上または上にある行列を繰り返し選択し、その行または列を交換して下に移動しようとすることになります。 1 つの要素を移動すると、その行または列内の他のすべての要素に影響を与えるため、このアプローチはすぐに複雑になります。 最悪の場合、1 つのポジションを固定することを目的とした 1 回のスワップにより、他の場所での進行が取り消される可能性があり、潜在的に$O(n^3)$あるいは、スワップのたびに制約を再評価し続けると、動作がさらに悪くなります。 

重要な構造的洞察は、個々の行と列について考えるのをやめ、代わりに行と列のラベル付けを検討して、行インデックスと列インデックスの間の順序制約をすべての行が尊重するようにすることです。 それぞれに「行は列の後にある必要がある」という形式の制約が課されます。 

まさにあるので、$n-1$ものと$n$インデックスの場合、これを有向グラフとして解釈できます。$n$それぞれが存在するノード$(x, y)$エッジを定義します$y \rightarrow x$。 各列インデックスは行インデックスを指します。$n-1$エッジオーバー$n$ノードを含む場合、この構造はルートが 1 つだけあるフォレストです。 条件$i > j$これは、すべてのエッジに対して次のようなノードのトポロジー的順序付けが必要であることを意味します。$y \rightarrow x$、ノード$x$ノードの後に​​表示されます$y$。 これはまさにグラフのトポロジカルな順序です。 

このような順序を計算したら、それを行と列の新しい順序として同時に使用します。 その後、すべてのエッジ$y \rightarrow x$順序付け制約が自動的に満たされ、すべての 1 が対角線の下に配置されるようになります。 

残りのタスクは、スワップを使用してこの順序付けを実現することです。これは、次に必要な要素を選択し、それを行配列と列配列の両方の所定の位置に個別に交換することで貪欲に実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ローカル修正) |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | トポロジカルな順序付け + 順列の構築 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点を含むグラフを作成する$1 \ldots n$。 一人一人に対して$(x, y)$から有向エッジを追加します。$y$に$x$。 これは、列インデックスの要件をエンコードします。$y$行インデックスの前に置く必要があります$x$。 
2. このグラフのトポロジー的順序付けを計算します。 あるので$n-1$有効なソリューションではエッジとサイクルが存在しません。これにより、すべてのインデックスの有効な順序が生成されます。 
3. この順序で、必要な行の順序と列の順序の両方を定義します。 直感的には、すべての制約が満たされるように、元の各インデックスに新しい位置を割り当てています。 
4. 現在の行位置と列位置を表す 2 つの配列を維持します。 最初は、両方とも恒等順列です。 
5. 左から右の順序でターゲット内の各位置について、必要な要素を行の置換の正しい位置に交換し、交換操作を記録します。 
6. 列に対して同じことを個別に実行し、再びスワップを記録します。 
7. 最初に行スワップを適用し、次に列スワップを適用します。 行と列の置換は独立した操作であるため、その順序は正確さに影響しません。 
8. すべてのスワップが適用された後、行列はすべてのスワップが対角線より下にあるという条件を満たすことが保証されます。 

### なぜ効果があるのか

 それぞれ$(x, y)$最終的な順序付けで次のような制約が生じます。$y$前に現れる必要があります$x$。 これらの制約から構築されたグラフは、$n$ノードと$n-1$したがって、コンポーネントの順列までの有効な順序が 1 つだけあるフォレストになります。 トポロジカルな順序付けにより、すべての有向エッジが確実に尊重されます。 

行と列の両方が同じトポロジー順序に従って並べ替えられると、すべての行と列が次の位置から移動します。$(x, y)$ポジションへ$(pos[x], pos[y])$と$pos[x] > pos[y]$。 これはまさに対角線より下にあるための要件です。 

スワップ構造は、単純に順列を機械的に実現したものです。 一度固定されると相対的な順序は決して変更されないため、順序付けの正確さは最終的な行列の正確さに直接反映されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
ones = []
for _ in range(n - 1):
    x, y = map(int, input().split())
    ones.append((x - 1, y - 1))

g = [[] for _ in range(n)]
indeg = [0] * n

for x, y in ones:
    g[y].append(x)
    indeg[x] += 1

from collections import deque
q = deque([i for i in range(n) if indeg[i] == 0])
order = []

while q:
    v = q.popleft()
    order.append(v)
    for to in g[v]:
        indeg[to] -= 1
        if indeg[to] == 0:
            q.append(to)

pos = [0] * n
for i, v in enumerate(order):
    pos[v] = i

# build swaps to transform identity -> order
cur = list(range(n))
ops = []

for i in range(n):
    if cur[i] != order[i]:
        j = cur.index(order[i])
        cur[i], cur[j] = cur[j], cur[i]
        ops.append((2, i + 1, j + 1))  # columns (or rows, reused later)

cur = list(range(n))
for i in range(n):
    if cur[i] != order[i]:
        j = cur.index(order[i])
        cur[i], cur[j] = cur[j], cur[i]
        ops.append((1, i + 1, j + 1))  # rows

print(len(ops))
for t, i, j in ops:
    print(t, i, j)
```コードはまず、1 によって誘導される依存関係グラフを構築します。 次に、カーンのアルゴリズムを使用してトポロジカルな順序付けを計算します。 配列`pos`は概念的にのみ使用されますが、`order`は、行と列の両方に必要な実際の置換です。 

2 番目の部分は、貪欲にスワップを構築します。インデックスごとに、正しい要素が現在どこにあるかを見つけて、それを所定の位置に交換します。 これは、順列を実現する標準的な方法です。$O(n^2)$最悪の場合ですが、ここで$n \le 1000$, そのため、簡単に制限内に収まります。 同じロジックが列と行に個別に適用されます。 

微妙な実装の詳細は、再構築することです。`cur`行を処理する前に、行のスワップが列のスワップから独立していることを確認します。 両方の変換を 1 つの配列に混在させると、2 つの操作が誤って絡み合ってしまいます。

## 特殊なケース

 微妙なエッジ ケースは、構築されたグラフ内に 1 つのノードに入力エッジがない場合です。 その状況では、それはトポロジー順序付けの最初の要素となり、行と列の両方の置換の先頭に配置されます。 他のノードよりも遅く表示する必要があるという制約がないため、この配置はいずれの制約にも違反することはできません。 

もう 1 つのケースは、すべてのノードが前のノードに依存する長いチェーンです。 アルゴリズムはこれをカーンのキューで線形に処理し、各ノードが正確に 1 回追加されるようにします。 各ノードはすべての前提条件が indegree 構造から削除された後にのみ表示されるため、すべてのエッジが尊重されます。これにより、順列後にすべてのノードが厳密に対角線の下に配置されることが直接保証されます。
