 ## 解決策
 ## 問題の理解

 2 種類の操作を通じて、時間の経過とともに変化する配列が与えられます。 1 回の操作でセグメント全体が 1 つの値で上書きされ、その間隔内の以前の情報が効果的に消去されます。 もう 1 つの演算では、セグメント全体にわたる加重和を求めます。各位置はその値を最大 5 乗した値に寄与し、すべての寄与は大きな素数を法として加算されます。 

重要な点は、更新は破壊的で範囲ベースであるのに対し、クエリには現在のセグメントの状態に関する非線形情報が必要であるという点です。 値は何度も置き換えられる可能性があるため、クエリごとに回答を最初から再計算するソリューションは拡張できません。 

この制約により、操作ごとの複雑さが対数的に大きくなります。 最大 100,000 回の操作では、二次関数は直ちに不可能であり、クエリごとの線形ですら遅すぎます。 これにより、範囲の割り当てと集約された電力和の高速な取得の両方をサポートする構造が強制されます。 

微妙なエッジ ケースは、べき乗指数 k がゼロになる可能性があるという事実から生じます。 この場合、すべての要素が 1 を与えるため、答えはセグメントの長さに縮退します。 もう 1 つのエッジ ケースは繰り返し割り当てです。キャッシュされた集計を部分的に更新する単純なソリューションは、以前のコントリビューションを調整せずに完全に破棄する必要があるため、静かに壊れます。 

値の合計のみを維持しようとすると、さらなる障害モードが発生します。 クエリには最大 5 の累乗が含まれるため、Σa だけを知っているだけでは不十分です。 同じ合計の異なる分布は、異なるより高い累乗を生成します。 

## アプローチ

 ブルート フォース アプローチでは、各操作を直接シミュレートします。 割り当てでは、範囲内のすべての要素を上書きします。 クエリの場合、区間にわたって反復し、各値を k まで上げることによって、べき乗の合計を計算します。 これは定義に正確に従っているため、正しいです。 

ただし、最悪の場合、各割り当てには O(n) 時間がかかる可能性があり、各クエリにも O(n) 時間がかかります。 最大 10^5 の操作では、最悪の場合、およそ 10^10 の操作が必要となり、これは実行可能な制限をはるかに超えています。 

重要な観察は、クエリは現在のセグメントの合計電力和のみに依存し、割り当てはセグメント全体を均一に上書きするということです。 この組み合わせは、ノードごとに、0 から 5 までの p の a[i]^p の合計を維持するセグメント ツリーを示唆しています。セグメントが x に設定されている場合、すべてのべき乗の合計は単にセグメント長 * x^p であるため、範囲の割り当てはこれらすべての値を決定論的に置き換える遅延操作になります。 

したがって、この構造は、ノードごとにサイズ 6 の完全なベクトルを格納する遅延伝播を備えたセグメント ツリーになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 遅延伝播を使用したセグメント ツリー | O(m log n * 6) | O(n * 6) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがその区間にわたる a[i]^0 から a[i]^5 までの合計を表す 6 つの値を格納するセグメント ツリーを維持します。 また、保留中の割り当てを示す遅延タグも維持します。

1. 各要素の最大 5 までの累乗を計算し、それらをリーフ ノードに格納することにより、初期配列からセグメント ツリーを構築します。 内部ノードは、対応する電力レベルの合計によって子を結合します。 これが機能するのは、べき乗和が互いに素な結合に分散されるためです。 
2. 長さ len のセグメントをカバーするノードの場合、そのノード内のすべての値を x に代入すると、格納されている情報を即座に再計算できます。 各べき乗 p の合計は len * x^p になります。 これにより、個々の要素に触れることがなくなります。 
3. 範囲の割り当てが到着すると、遅延伝播を使用してそれを適用します。 ノードが完全にカバーされている場合、その状態を上書きし、割り当てタグを保存します。 部分的に覆われている場合は、再帰する前に押し下げます。 
4. 遅延割り当てを親から子にプッシュするとき、両方の子を同じ割り当て値で上書きし、それに応じて格納されている電力合計を更新します。 これにより、古い投稿が残らないようになります。 
5. クエリに答えるために、ツリーを走査し、セグメントの寄与を収集します。 ノードが完全にクエリ範囲内にある場合、そのノードに格納されている k のベクトル コンポーネントを直接返します。 部分的に重なる場合は降下する必要があります。 
6. べき乗と加算により値が大きくなる可能性があるため、更新のたびにモジュラー演算が適用されます。 

### なぜ効果があるのか

 すべてのノードで、保存されているベクトルは、すべての保留中の更新を適用した後のセグメントの電力和を正確に表します。 遅延伝播により、セグメントに影響を与える割り当てが完全に適用されるか、古い値と新しい値が混在することなく正しく延期されることが保証されます。 割り当てによって値が完全に上書きされるため、履歴的な依存関係が残らないため、更新後に各ノードを独立して扱うことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [[0]*6 for _ in range(4*self.n)]
        self.lazy = [None]*(4*self.n)
        self.build(1, 0, self.n-1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            x = arr[l] % MOD
            val = 1
            for p in range(6):
                self.tree[v][p] = val
                val = val * x % MOD
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        for p in range(6):
            self.tree[v][p] = (self.tree[v*2][p] + self.tree[v*2+1][p]) % MOD

    def apply(self, v, l, r, x):
        length = r - l + 1
        val = 1
        for p in range(6):
            self.tree[v][p] = val * length % MOD
            val = val * x % MOD
        self.lazy[v] = x

    def push(self, v, l, r):
        if self.lazy[v] is None or l == r:
            return
        m = (l + r) // 2
        self.apply(v*2, l, m, self.lazy[v])
        self.apply(v*2+1, m+1, r, self.lazy[v])
        self.lazy[v] = None

    def update(self, v, l, r, ql, qr, x):
        if ql <= l and r <= qr:
            self.apply(v, l, r, x)
            return
        self.push(v, l, r)
        m = (l + r) // 2
        if ql <= m:
            self.update(v*2, l, m, ql, qr, x)
        if qr > m:
            self.update(v*2+1, m+1, r, ql, qr, x)
        for p in range(6):
            self.tree[v][p] = (self.tree[v*2][p] + self.tree[v*2+1][p]) % MOD

    def query(self, v, l, r, ql, qr, k):
        if ql <= l and r <= qr:
            return self.tree[v][k]
        self.push(v, l, r)
        m = (l + r) // 2
        res = 0
        if ql <= m:
            res += self.query(v*2, l, m, ql, qr, k)
        if qr > m:
            res += self.query(v*2+1, m+1, r, ql, qr, k)
        return res % MOD

n, m = map(int, input().split())
arr = list(map(int, input().split()))

st = SegTree(arr)

out = []
for _ in range(m):
    tmp = input().split()
    if tmp[0] == '=':
        l, r, x = map(int, tmp[1:])
        st.update(1, 0, n-1, l-1, r-1, x)
    else:
        l, r, k = map(int, tmp[1:])
        out.append(str(st.query(1, 0, n-1, l-1, r-1, k)))

print("\n".join(out))
```この実装は、セグメントごとに 6 つの事前計算された集計を保存することを中心に展開されます。 ビルド ステップでは、リーフでパワー値を直接初期化し、再計算のオーバーヘッドなしでより高いパワーが段階的に構築されるようにします。 

適用関数は最適化の中核ポイントです。 要素を反復処理する代わりに、べき乗の幾何学的構造を使用してノード状態全体を再構築します。 遅延タグは、6 つの集計値すべてを完全に決定するため、割り当てられた値のみを保存します。 

押すことで下降時の正確性が保証されます。 保留中の割り当ては、さらに部分的な更新またはクエリを実行する前に、子で実体化する必要があります。 

更新とクエリは標準のセグメント ツリー パターンに従いますが、主な違いはベクトル集約ロジックと上書きセマンティクスです。

 ## 特殊なケース

 重要なエッジ ケースは k = 0 です。値の合計を追跡するだけの単純な実装では、空のセグメントまたは間違ったスケーリングに対して誤って 0 が生成されてしまいます。 正しい動作は、要素ごとに 0 乗を 1 として明示的に格納するかどうかに依存します。 たとえば、次のように入力します。```
3 1
7 8 9
? 1 3 0
```すべての要素が 7^0 = 1、8^0 = 1、9^0 = 1 に寄与するため、正解は 3 です。セグメント ツリーはこれを各ノードの最初のコンポーネントに直接格納するため、クエリは特別なケースを使用せずに 3 を返します。 

もう 1 つの特殊なケースは、完全な上書きが繰り返されることです。 セグメントが複数回割り当てられる場合、最後の割り当てのみが問題になります。 Lazy タグにより、中間状態が部分的にマージされることがなくなります。 例えば：```
3 3
1 2 3
= 1 3 5
= 1 3 7
? 1 3 1
```最初の割り当ては完全に破棄する必要があるため、正しい結果は 15 ではなく 21 になります。 apply 関数は 6 つの集計をすべて上書きするため、以前の割り当てからの残余は残りません。
