 ## 解決策
 ## 問題の理解

 私たちは石の列を与えられ、それぞれが 3 色のいずれかで塗られています。 目標は、削除した後に隣接する 2 つの石が同じ色にならないように、できるだけ少ない数の石を削除することです。 

言い換えれば、元の文字列を取得し、残りの連続する文字のペアがすべて異なるまで文字を削除する必要があります。 残りの石の順序は変更されない必要があるため、順序を変更するのではなく、要素を削除するだけです。 

投入サイズは非常に小さく、最大でも 50 個の石です。 これは、単純な線形スキャンやさらに高価な推論であっても、制限時間内で快適に機能することを意味します。 ここでは、二次複雑度までの解は事実上瞬時に得られますが、問題の構造は、もっと単純なものが存在することを示唆しています。 

ここでの単純な間違いは、周波数を並べ替えたり数えたりすることを考えることです。 たとえば、与えられた`RRG`と考えると、R が 2 つあるので、位置に関係なく必ず 1 つを削除する必要があると考える人もいるかもしれません。 この場合は正しいですが、隣接性が重要であるため、一般に頻度だけでは十分ではありません。 

もう 1 つのよくある間違ったアプローチは、色の全体的な「バランス」を試みることです。たとえば、固定パターンで R、G、B を交互に配置しようとすることです。 これは次のような入力では失敗します`RGRGRG`、厳密なパターンの仮定によって有効な石が誤って削除される可能性がある場合でも、削除の必要はありません。 

正しいソリューションは、グローバルな分散ではなく、ローカルの隣接関係のみに依存する必要があります。 

## アプローチ

 この強引なアイデアは、石のすべてのサブセットを試し、どのサブセットが隣接する 2 つの石が等しくないという条件を満たすかを確認することによって除去をシミュレートすることです。 各サブセットについて、線形時間で妥当性を検証します。 あるので$2^n$サブセット、これは次のことにつながります$O(n \cdot 2^n)$時間の複雑さ。 たとえ$n = 50$、これは天文学的に大きくなり、実行不可能になります。 

重要な観察は、どの石を世界中で保持するかを選択する必要がないということです。 代わりに、以前に保持していた石との関係のみに基づいて、石を削除する必要があるかどうかを左から右に貪欲に決定できます。 

問題の構造は古典的な局所制約の削減です。つまり、妥当性条件は隣接する保持された要素にのみ依存します。 これは、維持するものを修正したら、その位置を維持することを意味します$i-1$、ポジションでの決断$i$最後に保存された色と一致するかどうかによって完全に決定されます。 

これにより、問題は組み合わせ選択からシングル パス フィルタリング プロセスに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 取り除かれる石の数を表すカウンターをゼロに設定して開始します。 
2. 最後に保存された石の色を追跡します。 最初は、石がまだ処理されていないため、これは未定義です。 
3. 文字列を左から右にスキャンし、一度に 1 つの石を処理します。 
4. 各石について、その色を最後に保存した色と比較します。 同じ場合、この石をそのままにしておくと隣接ルールに違反するため、この石を削除する必要があります。 
5. 最後に保持した色と異なる場合は、それを保持し、最後に保持した色を現在の色に更新します。 
6. 文字列の終わりまで続けて、削除した石の数を蓄積します。 

### なぜ効果があるのか

 スキャンのどの時点でも、維持されたシーケンスは、隣接する 2 つの石が等しくないという条件を満たすことが保証されます。 これは、最後に保持された石と異なる場合にのみ石を追加するため、維持されます。 一致する場合、それを削除することは将来の決定には役に立たないため、常に安全です。将来のすべてのチェックは、以前の石ではなく、最も最近に保持された石にのみ依存するため、それを保持しても利益はなく、無効な隣接が導入されるだけです。 これにより、保持されるプレフィックスがその長さに対して常に最適であるという貪欲な不変条件が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    removed = 0
    last = None
    
    for c in s:
        if c == last:
            removed += 1
        else:
            last = c
    
    print(removed)

if __name__ == "__main__":
    solve()
```コードは単一の変数を維持します`last`最も最近保管された石を表します。 現在の文字が一致する場合`last`、それは捨てられ、除去としてカウントされます。 それ以外の場合は、新しいものになります`last`。 これにより、アルゴリズム ウォークスルーからの貪欲ルールが 1 つのパスで直接実装されます。 

重要な点は初期化です。`last = None`最初の文字はそれ以前の文字と一致しないため、常に保持されます。 すべての比較は安全かつ均一であるため、これを超える境界の問題はありません。

 ## 特殊なケース

 単一の石のような`B`、アルゴリズムセット`last = None`、石を維持し、除去をゼロにします。 単一の要素が常に有効であるため、削除をトリガーする比較はありません。これは要件に一致します。 

次のような完全に均一な文字列の場合`RRRRR`、 最初`R`が保持され、後続のすべての文字が等しい`last`, そのため、それぞれが削除されたものとしてカウントされます。 スキャンが更新されない`last`、結果が正確であることを保証します。$n-1$、最大同一ブロックの代表を 1 つ保持することと一致します。 

次のような交互文字列の場合`RGRGRG`、すべての文字は異なります`last`, したがって、何も削除されません。 等しい隣接ペアのみが無効であるという不変条件により、この構造がすでに最適であることが保証され、アルゴリズムはすべての要素を正しく保存します。
