 ## 解決策
 ## 問題の理解

 文字列として表される子供の行が与えられ、各文字は男の子か女の子のいずれかになります。 このラインは時間の経過とともに個別のステップで進化します。 1 秒ごとに、男の子が女の子の直前に立っていたすべての隣接するペアの位置が同時に入れ替わります。 言い換えれば、すべての有効な「BG」パターンは同じ秒内に「GB」になり、すべてのスワップは左から右に順番にではなく並行して発生します。 

タスクは、この変換ルールを適用してからちょうど t 秒後に回線の構成を決定することです。 

制約は非常に小さく、n と t は両方とも最大 50 です。これにより、最悪の場合の操作数は n と t の乗算のオーダーであり、実行ごとに最大 2500 のスワップ チェックであるため、単純なシミュレーションでも許容できることがすぐにわかります。 文字スキャンを 1 秒ごとに繰り返したとしても、2 秒の制限内では合計の作業はわずかです。 

スワップの同時性により、微妙な特殊なケースが発生します。 左から右に処理し、すぐに文字をその場で交換すると、更新された情報を同じ秒内に誤って再利用してしまう可能性があります。 たとえば、「BGBG」について考えてみましょう。 最初のペア「BG」を貪欲に交換すると、「GBBG」が得られますが、ステップの途中で構造がすでに変更されているため、次のペアは誤って評価されます。 正しく解釈するには、1 秒間のすべてのスワップが文字列の同じスナップショットに基づいている必要があります。 

もう 1 つの特殊なケースは、スワップが重複する場合です。 「BGB」のようなパターンでは、最初のペアのみが 1 ステップでスワップされ、中央のキャラクターは 1 秒あたり最大 1 回のスワップに参加します。 これにより、単一時間単位内での二重移動が防止されます。 

## アプローチ

 プロセスをモデル化する最も直接的な方法は、文字通り毎秒シミュレーションすることです。 各タイム ステップで、文字列を左から右にスキャンし、「BG」パターンが表示されるたびに、それを「GB」に交換し、交換の一部としてすでに移動しているため、次の位置をスキップします。 このアプローチは、現在の状態を新しいパスを使用して一度に 1 秒ずつシミュレーションするため、問題の定義と正確に一致し、正確性が維持されます。 

このブルート フォース シミュレーションは、毎秒文字列を 1 回通過する必要があり、1 秒あたり O(n) の作業が行われるため、すでに十分なパフォーマンスを発揮します。 t 秒間の合計作業量は O(n・t) で、これは 2500 回の操作で制限されます。 

制約によって漸近的な改善が行われるわけではないため、より高度な最適化を行う必要はありません。 重要な洞察は、計算の高速化ではなく、1 秒以内に更新が連鎖しないようにすることで、同時スワップを正しくモデル化することです。

 ## アルゴリズムのチュートリアル

 1. 文字の変更可能なリストとして初期キューから開始します。 これにより、効率的な交換が可能になります。 
2. このプロセスを t 秒間繰り返します。 各反復は、1 つの完全な同期変換ステップを表します。 
3. 1 秒ごとに、0 から始まるインデックス i を使用して左から右にスキャンします。 
4. 現在の位置 i と次の位置 i+1 が「B」の後に「G」が続くパターンを形成している場合、それらを交換します。 
5. スワップを実行した後、新しくスワップされた文字の再処理を避けるために、i を 2 ずつ増分します。 
6. 位置 i でスワップが発生しない場合は、i を 1 だけ前に移動します。 
7. フル スキャンの終了後、1 秒後の結果のリストにキューが表示されます。 
8. すべての t 秒がシミュレートされるまで続行します。

スワップ後にインデックスをスキップする主な理由は、スワップされた「GB」ペアを同じ秒内に再検討すべきではないということです。 スキップしなかった場合、同じ女の子が 1 つのタイム ステップで複数のスワップに関与する可能性があり、これは同時スワップ ルールに違反します。 

### なぜ効果があるのか

 正確さは、各秒の開始時に、配列が正確にその数の完全な変換後の状態を表すという不変条件に基づいています。 1 秒以内に、各スワップはその秒の元の構成のみに基づいて適用されます。これは、左から右にスキャンし、スワップが発生すると、そのステップで両方の位置が確実に消費されるためです。 これにより、同じ秒内でのカスケード効果が防止され、すべてのスワップが現在のスナップショット内の素の「BG」ペアに正確に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, t = map(int, input().split())
s = list(input().strip())

for _ in range(t):
    i = 0
    while i < n - 1:
        if s[i] == 'B' and s[i + 1] == 'G':
            s[i], s[i + 1] = s[i + 1], s[i]
            i += 2
        else:
            i += 1

print("".join(s))
```このソリューションではキューをリストとして保存するため、スワップは O(1) になります。 1 秒ごとに独立してシミュレーションされます。 内側のループは、1 回スキャンしてインデックスを適切に進めることにより、スワップが 1 秒あたり 1 つの凍結された構成に基づくというルールを慎重に適用します。 

よくある間違いは、交換後にインデックスをスキップせずに文字列を左から右に更新することです。 これは、移動したばかりのキャラクターを二重に処理することになり、変換の同時性の性質に違反します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, t = map(int, input().split())
    s = list(input().strip())

    for _ in range(t):
        i = 0
        while i < n - 1:
            if s[i] == 'B' and s[i + 1] == 'G':
                s[i], s[i + 1] = s[i + 1], s[i]
                i += 2
            else:
                i += 1

    return "".join(s)

# provided sample
assert run("5 1\nBGGBG\n") == "GBGGB"

# all same
assert run("4 3\nGGGG\n") == "GGGG"

# all boys
assert run("4 2\nBBBB\n") == "BBBB"

# alternating pattern
assert run("6 1\nBGBGBG\n") == "GBGBGB"

# multiple steps
assert run("5 2\nBGGBG\n") == run("5 1\n" + "GBGGB\n")

# max small stress
assert run("1 50\nB\n") == "B"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 4 3 / GGGG | ぐぐぐ | スワップは発生しません |
 | 4 2 / BBBB | BBBB | 有効な BG ペアがありません |
 | 6 1 / BGBGBG | GBGBGB | 複数の独立したスワップ |
 | 1 50/B | B | 最小境界サイズ |

 ## 特殊なケース

 主なエッジケースは、「BGB」など、スワップが隣接している場合です。 1 秒の間に、最初の「BG」のみが交換され、「GBB」が生成されます。 インデックス 0 と 1 を交換した後、ポインターはインデックス 2 にジャンプし、2 番目の文字が同じ秒内に別の交換に参加するのを防ぐため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、「BGBGBG」のような完全に交互の文字列です。 このアルゴリズムにより、素のペアごとにスワップが独立して行われるようになり、スワップ後のスキップによってオーバーラップの破損が防止されます。 

最後に、すべて「G」文字列またはすべて「B」文字列などの no-op ケースでも安定性が確認されます。 「BG」パターンが存在しないため、スキャンでは瞬時にスワップが実行されず、すべての反復にわたって不変状態が維持されます。
