 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた家の列が与えられます。 各家は初期の銀行残高から始まります。 その後、時間の経過とともに一連のイベントが発生します。 一部のイベントは、正または負の値を追加することによって、ハウスの間隔全体のバランスを変更します。 他のイベントでは、特定の家に対する「調査」が開始され、後に終了します。 調査が終了すると、調査期間全体を通じてその家がこれまでに残した最小残高を報告するよう求められます。 

重要な点は、範囲の更新によりバランスが時間の経過とともに変化するため、調査期間中のみ住宅ごとの最小時間を追跡する必要があるということです。 したがって、各ハウス i には「非アクティブ」、「アクティブな調査」、そして「再び非アクティブ」という複数のフェーズがあり、アクティブなフェーズでは継続的にその値を観察し、その値が到達する最小値を記憶します。 

制約は最大 200,000 の家と 200,000 のイベントまでであり、更新ごとにすべての家をスキャンしたり、完全な配列を繰り返し再計算したりするソリューションは即座に除外されます。 各範囲の更新が影響を受けるすべての家に影響を与える単純なシミュレーションでは、コストは O(nq) となり、実現可能性をはるかに超えています。 各ハウスは多くの更新の影響を受ける可能性があるため、ハウスごとの履歴を明示的に維持するだけでも、時間とメモリの両方で大きすぎます。 

微妙な問題は、更新とクエリが完全にインターリーブされることです。 すべての更新を最初に処理したり、すべてのクエリを最初に処理したりすることはできません。 範囲の追加と、いつでも単一の家の現在値への迅速なアクセスをサポートする動的な構造を維持する必要があります。 

もう 1 つの隠れたエッジ ケースは、調査間隔にさまざまな兆候の複数の更新が含まれる可能性があることです。 家の最小値は、必ずしも最初や最後ではなく、アクティブなセグメントの中央で発生する可能性があります。 したがって、エンドポイント値だけでなく、過去の最小値を継続的に追跡する必要があります。 

## アプローチ

 直接シミュレーションでは、配列全体が維持され、l から r まで反復して各「郵便配達員」イベントが適用され、影響を受ける各家が更新されます。 調査中は、更新のたびにチェックすることで、その家の最低価格も追跡します。 これは概念的には機能しますが、すべての更新が O(n) 要素に影響する可能性があり、最悪の場合は O(nq) となり、200000 には大きすぎます。 

重要な点は、すべての操作がセグメント全体にわたって線形で均一であることです。更新ごとに、範囲内のすべての要素に定数 x が追加されます。 これは、対数時間での範囲の追加とポイント クエリを自然にサポートするため、遅延伝播を備えたセグメント ツリーを示唆しています。 

ただし、最終値だけでなく、一定期間中の各住宅の最小値も追跡する必要があります。 重要な構造の単純化は、固定住宅の場合、その価値が時間の経過とともに追加されるシーケンスとして進化することです。 現在の値がわかっており、調査開始以降に到達した最小値も維持している場合、それに影響を与えるすべての更新は、現在の値と過去の最小値の両方を同じ量だけシフトさせるだけです。 これにより、住宅ごとに両方の量をローカルに維持することが可能になります。 

したがって、各家は完全な履歴を追跡する代わりに、現在の値と最後の「開始」イベント以降の最小値の 2 つの値を保存します。 範囲の追加は、影響を受けるすべての住宅の両方の量に等しく影響します。 セグメント ツリーは、遅延伝播を使用してこれらの値を効率的に維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(nq) | O(n) | 遅すぎる |
 | 遅延伝播を使用したセグメント ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

一連の住宅にわたってセグメント ツリーを維持します。 各リーフには、その家の現在の残高と、最後に調査が開始されてから到達した最低残高という 2 つの情報が保存されます。 内部ノードは、範囲の更新に必要なものだけを集約します。 

操作は次のように処理されます。 

1. 初期残高を使用してセグメント ツリーを構築します。 最初はまだ調査が開始されていないため、最後の開始以降の最小値は初期値と等しくなります。 
2. 値 x による間隔 [l, r] の範囲更新の場合、影響を受けるすべてのノードに x を追加する遅延伝播更新を適用します。 現在の値と過去の最小値の両方が正確に x だけシフトするため、影響を受けるすべてのセグメントの両方のフィールドに x を追加します。 これにより、そのセグメント内のすべての過去の値が均一に変換されるため、正確さが保たれます。 
3. ハウス i の調査が開始されると、まず保留中の遅延更新をそのリーフに伝播することによって、そのリーフで正しい​​現在値が得られていることを確認します。 次に、「開始以来の最小値」を現在の値にリセットします。 これにより、新しいベースラインが確立されます。この瞬間からは、この開始点に相対的な値のみが考慮されます。 
4. 調査中、アップデートは引き続きその家に影響を与えます。 現在値と最小値の両方が範囲加算で一緒に更新されるため、最小値は常に、最後のリセット以降に確認された最小値を正確に追跡します。 
5. 家 i の調査が終了すると、すべての更新が適用されていることを確認するために再度伝播し、その家に保存されている最小値を出力します。 

重要な不変条件は、どの住宅でも、いつでも、その保存された最小値が、最後のリセット イベントからの時間間隔にわたる真の残高の最小値と等しいということです。 範囲更新では、すべての履歴値を均一にシフトし、リセット イベントは最小値を現在の値と同期させることで新しい間隔の開始を正しく再定義するため、この不変条件が保持されます。 すべての更新は均一なシフトまたは境界のリセットのいずれかであるため、格納された最小値に含まれていない値を操作で導入することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr) - 1  # 1-indexed
        self.size = 4 * self.n
        self.val = [0] * self.size
        self.mn = [0] * self.size
        self.lazy = [0] * self.size
        self._build(1, 1, self.n, arr)

    def _build(self, idx, l, r, arr):
        if l == r:
            self.val[idx] = arr[l]
            self.mn[idx] = arr[l]
            return
        mid = (l + r) // 2
        self._build(idx*2, l, mid, arr)
        self._build(idx*2+1, mid+1, r, arr)
        self.mn[idx] = min(self.mn[idx*2], self.mn[idx*2+1])

    def _push(self, idx):
        if self.lazy[idx] != 0:
            v = self.lazy[idx]
            for child in (idx*2, idx*2+1):
                self.val[child] += v
                self.mn[child] += v
                self.lazy[child] += v
            self.lazy[idx] = 0

    def _range_add(self, idx, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self.val[idx] += v
            self.mn[idx] += v
            self.lazy[idx] += v
            return
        self._push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self._range_add(idx*2, l, mid, ql, qr, v)
        if qr > mid:
            self._range_add(idx*2+1, mid+1, r, ql, qr, v)
        self.mn[idx] = min(self.mn[idx*2], self.mn[idx*2+1])

    def _query_val(self, idx, l, r, pos):
        if l == r:
            return self.val[idx]
        self._push(idx)
        mid = (l + r) // 2
        if pos <= mid:
            return self._query_val(idx*2, l, mid, pos)
        else:
            return self._query_val(idx*2+1, mid+1, r, pos)

    def reset_min(self, pos):
        self._reset_min(1, 1, self.n, pos)

    def _reset_min(self, idx, l, r, pos):
        if l == r:
            self.mn[idx] = self.val[idx]
            return
        self._push(idx)
        mid = (l + r) // 2
        if pos <= mid:
            self._reset_min(idx*2, l, mid, pos)
        else:
            self._reset_min(idx*2+1, mid+1, r, pos)
        self.mn[idx] = min(self.mn[idx*2], self.mn[idx*2+1])

    def get_min(self, pos):
        return self._get_min(1, 1, self.n, pos)

    def _get_min(self, idx, l, r, pos):
        if l == r:
            return self.mn[idx]
        self._push(idx)
        mid = (l + r) // 2
        if pos <= mid:
            return self._get_min(idx*2, l, mid, pos)
        else:
            return self._get_min(idx*2+1, mid+1, r, pos)

def main():
    n, q = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    st = SegTree(a)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == 'C':
            l, r, x = map(int, tmp[1:])
            st._range_add(1, 1, n, l, r, x)
        elif tmp[0] == 'I':
            i = int(tmp[1])
            st.reset_min(i)
        else:
            i = int(tmp[1])
            print(st.get_min(i))

if __name__ == "__main__":
    main()
```セグメント ツリーには、現在の値と、各リーフでの最後のリセット以降の実行最小値の両方が保存されます。 遅延伝播により、範囲の加算が対数時間で適用されることが保証されます。 リセット操作は、最小値をその時点の現在の値と同期させるポイント更新として実装され、その住宅の新しい追跡ウィンドウを効果的に開始します。 

微妙な点は、リーフにアクセスする前に常に遅延更新をプッシュすることです。 これがないと、リセットおよびクエリ操作で古い値が読み取られ、正確性が損なわれる可能性があります。 

## 実用的な例

 最初は 3 軒の家がある小規模なシナリオを考えてみましょう`[5, 2, 7]`。 家 2 の調査を開始し、範囲更新を適用して追加するとします。`-3`全戸に通報し、調査を終了します。 

| ステップ | 操作 | ハウスの価値観 2 | 開始以来の最小値 |
 | --- | --- | --- | --- |
 | 1 | 調査を開始 | 2 | 2 |
 | 2 | すべてに -3 を適用する | -1 | -1 |
 | 3 | 調査を終了 | -1 | -1 |

 このトレースは、最小値が更新によるシフトに正しく追従しており、間隔内の最低値がキャプチャされていることを示しています。 

ここで、重複する更新が家に部分的にのみ影響することを考えてみましょう。 ハウス 1 の初期値を 10 とします。調査を開始し、[2,3] に +5 を適用し (効果なし)、次に [1,1] に -7 を適用して終了します。 

| ステップ | 操作 | 値 | 最小 |
 | --- | --- | --- | --- |
 | 1 | 開始 | 10 | 10 |
 | 2 | +5 から [2,3] | 10 | 10 |
 | 3 | -7 から [1,1] | 3 | 3 |
 | 4 | 終わり | 3 | 3 |

 これにより、関連する更新のみが追跡対象の家に影響を与え、その値が変更されたときに最小限の更新が正確に行われることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log n) | 各範囲更新とポイント操作はセグメント ツリー パスを横断します。 
| スペース | O(n) | セグメントツリーはノードごとに一定の情報を格納します。 

この制約では最大 200,000 回の操作が許可されるため、操作ごとに対数係数があれば十分です。 この構造により、更新ごとにすべての家に触れることがなくなり、影響を受けるセグメントのみが処理されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、範囲の更新直後に調査が開始される場合です。 その状況では、ハウスの値には、リセット前にすべての保留中の遅延更新がすでに含まれている必要があります。 実装では、リーフにアクセスする前に遅延値をプッシュすることでこれを処理します。 たとえば、保留中の更新後に家から開始すると、リセットされたベースラインが正しいことが保証されます。 

もう 1 つのケースは、調査がアクティブである間に複数の更新が結合されていない範囲に影響を与える場合です。 影響を受けるセグメントのみが変更を伝播し、リーフの最小値が一貫して更新されるため、アルゴリズムは引き続き機能します。 

最後の微妙なケースは、同じ家に対して繰り返しリセットが行われることです。 リセットするたびに最小値が現在の値に正しく再初期化され、以前の履歴が新しい調査ウィンドウに漏れないようになります。
