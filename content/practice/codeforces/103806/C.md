 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられ、それぞれが劇場に出席する友人のグループを説明します。 各友人にはすでに座席が割り当てられており、行と列を表す整数のペアで指定されます。 

座席のレイアウトは、列に番号が付けられている点で珍しいです。 左から右に単調に増加するのではなく、列 1 と列 2 が行の中央に位置し、互いに隣接するように列が配置されます。 そこから、列が外側に対称に伸びます。奇数は中心から離れる方向に片側に広がり、偶数は中心から離れる方向に反対側に広がります。 ただし、問題自体に関しては、この構造は、列番号を通じて隣接性を定義する場合にのみ関連します。 

テスト ケースごとに、すべての友人が「一緒」であるとみなせるかどうか、つまり、友人全員が同じ列に座っており、列の位置が連続している一連の席を占めているかどうかを判断する必要があります。 隣接性の要件は厳密です。行内の列を並べ替えた後、隙間のない連続したブロックを形成する必要があります。 

各テスト ケースには最大多数の友人を含めることができ、すべてのテスト ケースの合計は 100 万に達することがあります。 これにより、テスト ケースごとの友達の数が 2 次である解決策はすぐに除外されます。10^6 log 10^6 の操作でも問題ありませんが、ペアごとのチェックに似たものは遅すぎるためです。 

友人が同じ行を共有しているが、その列が連続していない場合、微妙な特殊なケースが発生します。 たとえば、3 人の友人が同じ行の列 1、2、および 4 にある場合、列 3 が欠落しているため、答えは「いいえ」でなければなりません。 もう 1 つのエッジ ケースは、すべての友人が異なる列にいる場合です。 たとえ列が完全に整列していても、単一の行に一緒に配置されていないため、答えは依然として「NO」です。 

主な困難は、奇妙な列番号付けではなく、行の等価性と間隔の連続性のみが重要であることを認識することです。 

## アプローチ

 この問題を推論する簡単な方法は、すべての友人のペアをチェックして 2 つの条件を検証することです。すべての行が等しい必要があること、およびすべての列を収集した後、セットが連続したシーケンスを形成していることです。 この強引なアイデアは概念的には単純です。テスト ケースごとに、すべての行を最初の行と比較し、最小列と最大列の間のすべての整数が出現するかどうかを確認します。 

ただし、このアプローチは単純に実装すると非効率になります。 すべての友人のペアをチェックするには O(n²) が必要で、最悪の場合は約 10¹² の操作が必要となり、実行可能な制限をはるかに超えます。 各テスト ケースのブール プレゼンス配列を繰り返し保存してスキャンするだけでも、メモリのリセットや大きな座標範囲が原因で問題が発生します。 

重要な点は、実際には座席の完全な構造を知る必要はないということです。 テスト ケースごとに必要な情報は、すべての行が同一かどうか、最小列、最大列の 3 つだけです。 すべての友人が同じ行にある場合、個別の列の数が最大列マイナス最小列プラス 1 に等しい場合に限り、それらは連続しています。 これにより、単純な集計以外の並べ替えや頻度配列の必要がなくなります。 

これにより、問題はテスト ケースごとに 1 回の線形スキャンに削減され、いくつかの変数が追跡されます。

 ## アルゴリズムのチュートリアル

1. テスト ケースごとに、友人の数を読み取り、行の一貫性、最小列、最大列、およびエントリ数の追跡変数を初期化します。 行を最初の友人の行として初期化し、参照点を確立します。 
2. すべての友人を反復処理し、各 (行、列) ペアを読み取ります。 友人ごとに、その行と参照行を比較します。 不一致が発生した場合、それらがすべて一緒に座れないことはすでにわかっていますが、正確さを維持するために入力の読み取りを続けます。 
3. 反復中に、列の最小値と最大値を継続的に更新します。 これは、その列の占有座席の全体の広がりを捉えています。 
4. 友達の数を数えます。 これは、後で最小列と最大列で定義された間隔の長さと比較するため必要です。 
5. すべての友人を処理した後、すべての行が参照行と一致するかどうかを確認します。 そうでない場合、答えは即座に「NO」です。 
6. 行に一貫性がある場合は、max_column - min_column + 1 が友人の数と等しいかどうかを確認して、列が連続セグメントを形成しているかどうかを確認します。 

### なぜ効果があるのか

 すべての友人が同じ列を共有する場合、彼らの座席は整数位置に関する 1 次元の問題に帰着します。 整数のセットは、その最大値から最小値を引いた値がサイズから 1 を引いた値に等しい場合に限り、連続ブロックを形成します。 列が欠落していると、占有座席数を増やさずに範囲が厳密に拡大され、この平等が崩れます。 最小値、最大値、およびカウントを正確に追跡するため、順序付けの仮定は必要なく、ギャップを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n = int(input())

        first_row = None
        same_row = True

        min_col = 10**30
        max_col = -10**30

        for i in range(n):
            f, c = map(int, input().split())

            if i == 0:
                first_row = f

            if f != first_row:
                same_row = False

            if c < min_col:
                min_col = c
            if c > max_col:
                max_col = c

        if not same_row:
            out.append("NO")
        else:
            if max_col - min_col + 1 == n:
                out.append("SI")
            else:
                out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、単一パス中に参照行のみを維持し、列の境界を更新することに依存しています。 変数`same_row`行に逸脱が発生するかどうかをキャプチャします。 最小-最大追跡により、ソートなしでスパンを再構築できることが保証されます。 

よくある実装上の間違いは、すべての列をリストに格納して並べ替えようとすることです。これは正しいことですが、不要です。 もう 1 つの間違いは、残りの入力行を消費せずに行の不一致が発生した場合に早期に終了することです。これにより、入力解析が中断されてしまいます。

 ## 特殊なケース

 主なエッジケースは、すべての列が完全な間隔を形成しているが、行が異なる場合です。 例えば：```
1
3
1 1
2 2
1 3
```スキャンは正しく設定されます`same_row`2 番目の要素で False に設定されますが、引き続き最小値と最大値が更新されます。 min と max は連続した範囲を示唆しますが、列の不一致により NO が強制され、一緒に座るには単一の列が必要であるという要件と一致します。 

もう 1 つのエッジ ケースは n = 1 です。友人が 1 人だけの場合、min は max に等しく、条件 max - min + 1 == n が自明に成り立ちます。 行の一貫性と連続性の両方が空に満たされているため、アルゴリズムは SI を正しく返します。 

3 番目のケースには、最大 10^9 の大きな座標値が含まれます。 最小値と最大値のみを追跡するため、オーバーフローや大きな配列の割り当ては発生せず、解は座標範囲に関係なく一定の空間のままになります。
