 ## 解決策
 ## 問題の理解

 整数の配列と固定モジュラス値が与えられます。$m$。 1 人のプレイヤー、Berta は、同じグループになる 2 つの要素を選択し、それら 2 つの要素の合計が次で割り切れる場合に勝ちます。$m$。 もう 1 人のプレイヤーであるブランカは、すべての要素をグループ (パイルと呼ばれる) に分割する責任があります。ただし、各パイルには少なくとも 2 つの要素が含まれている必要があり、それが唯一の山でない限り、すべてを 1 つのパイルに入れることは許可されません。 

ブランカの目標は、ベルタがどの山を見てその中でどのペアを選んでも、合計が次で割り切れるペアを決して見つけられないように山を配置することです。$m$。 これを達成するすべての有効な配置の中で、可能な限り最小限の杭の数が必要であるか、それは不可能であると報告します。 

各数値はその剰余モジュロを通じてのみ寄与します。$m$、和の割り算は剰余のみに依存するためです。 したがって、問題は、グループ内のどのペアも合計が 0 を法にしないように残基を組織化することです。$m$。 

制約により、最大で$3 \cdot 10^5$最大の数値と大きな値$10^9$これにより、すべてをモジュラー演算に還元し、すべての要素にわたる二次ペアリングやグラフ構築を回避することが即座に強制されます。 すべてのペアをチェックしたり、パーティションを明示的にシミュレートしようとしたソリューションは失敗します。 

すべての数値が不可避の不良ペアを強制する構造を共有する場合、微妙な特殊なケースが発生します。 たとえば、すべての数値が 0 を法として合同である場合、$m$の場合、任意のペアの合計も 0 を法として計算されます。$m$、どのグループ分けもベルタの勝利を妨げることはできません。 もう 1 つの例外的なケースは、残基が相補的なペアで存在し、その残基が多すぎて分離できない場合です。 

## アプローチ

 中心的な観察は、剰余のみが剰余であるということです。$m$案件。 それぞれの数値を約次のようにします。$a_i = b_i \bmod m$。 残りが 2 つ存在する場合、ベルタはパイルで勝ちます$x$そして$y$同じ山でそのように$x + y \equiv 0 \pmod m$。 つまり、$y \equiv -x \pmod m$、または同等の$y = m - x$のために$x \neq 0$、および特殊な場合$0$そしておそらく$m/2$いつ$m$は均等です。 

したがって、パイル内の禁止された構造は、相補的な残基の任意のペアです。 

ブルートフォースアプローチを試みる場合、配列の可能なすべての分割を有効なパイルに試み、パイルに禁止されたペアが含まれているかどうかを確認します。 固定用でも$n = 15$、パーティションはベル数のように増加し、各パーティション内では依然としてペア チェックが必要なため、要素の数は指数関数的に増加します。 これは、小さな制約を超えるとすぐに実行不可能になります。 

重要な構造的洞察は、競合関係は純粋に残基クラス間であり、個々の要素間ではないということです。 各残基クラス$x$とのみ競合します$m-x$。 これにより、問題は剰余クラスのペアリングまたはグループ化のカウントに縮小されます。 個々のカードについて推論する代わりに、剰余の頻度について推論します。 

ここで問題は、どの山にも相補ペアの両方のメンバーが含まれないように、各剰余のカウントを少なくとも 2 つのサイズの山に分配することです。 目標は、杭の数を最小限に抑えることです。 

このようなグループ化を最小限に抑える古典的な方法は、ペアごとの制約の観点から考えることです。$(x, m-x)$。 このようなペアごとに、一方の要素をもう一方の要素から分離する必要があります。 これは当然のことながら、各パイルが各競合するペアの最大で 1 つの側を含むことができることを考慮して、できるだけ多くの互換性のある残基を 1 つのパイルにまとめようとする構築につながります。 

最適な戦略は、残基ペアに対して貪欲であることが判明しました。つまり、相補的な残基を可能な限り異なるパイルにペアにして、残りを分配します。 唯一の軽減不可能な障害は残基 0 から生じます。$m$偶数、残差$m/2$、自分自身と矛盾しているからです。 

残留物がある場合$r \in \{0, m/2\}$2 つのコピーを少なくとも 2 のサイズの同じ山に強制的に配置し、必然的に悪いペアが作成されるという奇妙な構造で出現すると、答えは不可能になります。 

実行可能性を処理した後、各杭は競合する各ペアの最大 1 つの「ユニット」を運ぶことができるため、杭の最小数は残余衝突の最大荷重に対応します。

 ## アルゴリズムのチュートリアル

 1. すべての数値の剰余を減算します。$m$。 これにより、問題は純粋に剰余ベースのグループ化タスクに変換されます。 
2. 配列内の各残基の出現をカウントします。`cnt`。 これにより、入力の完全な構造が圧縮形式で得られます。 
3. 自己逆剰余を個別に処理します。 これらは残基 0 と残基です$m/2$もし$m$は均等です。 これらの残基のいずれかが、有効なパイル構造内で不可避のペアリングを強制する形で出現した場合、それらがすべての要素を有効なパイルに分離するのを妨げる形で構成を支配している場合、直ちに不可能であると結論付けます。 
4. 相補的残基のペア$x$そして$m-x$。 このような各ペアについて、概念的にはそれらを 2 つの対立するグループとして扱い、両方を含むパイルがないようにパイル全体に分散する必要があります。 
5. 各相補ペアに必要なパイルの数を計算します。 各杭は、競合することなくどちらの側からも最大 1 つの「ユニット」を取得できるため、必要な杭の数は、そのようなすべての制約の最大値によって決定されます。 
6. すべてのパイルに少なくとも 2 つの要素があることを確認します。 これにより、全体的な実現可能性の制約が課せられます。要素の総数は、必要な数の杭を配置するのに十分でなければなりません。 
7. 計算された杭の最小数を返します。実現可能性がない場合は -1 を返します。 

### なぜ効果があるのか

 重要な不変条件は、有効なパイル内に両方の残基を配置することは決してできないということです$x$そして$m-x$。 これにより、各パイルは各相補剰余クラスから最大でも 1 つの側を選択できるコンテナのように動作します。 したがって、すべてのパイルは、すべての相補ペアの中で最も頻度の高い側によって制限されます。 各杭は各剰余ペア制約に独立して容量 1 を与えるため、杭の最小数はまさにこれらの制約上の最大輻輳となります。 これにより、問題は独立した競合クラスに対する最大負荷スケジューリングの議論に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))
    
    cnt = {}
    for x in arr:
        r = x % m
        cnt[r] = cnt.get(r, 0) + 1

    if m == 1:
        return -1

    used = set()
    piles = 0

    for r in list(cnt.keys()):
        if r in used:
            continue
        if r == 0:
            piles = max(piles, 1)
            used.add(r)
        else:
            comp = (m - r) % m
            if comp not in cnt:
                piles = max(piles, cnt[r])
            elif comp == r:
                piles = max(piles, (cnt[r] + 1) // 2)
            else:
                used.add(r)
                used.add(comp)
                piles = max(piles, max(cnt[r], cnt[comp]))

    if piles == 0:
        print(-1)
    else:
        print(piles)

if __name__ == "__main__":
    solve()
```モジュール関係のみが重要であるため、コードは最初に値を剰余カウントに圧縮します。 次に、残基を反復して、それぞれをその補数とペアにします。 残基に補体が存在しない場合、その残基自体の頻度が必要なパイルの数を決定します。 両側が存在する場合、各パイルは禁止ペアを作成せずに各側から最大 1 つしか吸収できないため、制限係数は 2 つの周波数のうち大きい方になります。 

自己補完の場合、特に残基 0 と$m/2$、それ自体と矛盾するため、内部制約として扱われます。 彼らの貢献は、必要に応じて天井分割によって処理されます。 

すべての杭はすべての剰余ペア制約を同時に満たさなければならないため、最終的な答えは、すべての制約にわたる最大杭要件となります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値がモジュロ 0 になる場合です。$m$。 その状況では、すべてのペアの合計もゼロになるため、少なくとも 2 のサイズの山はすぐにブランカに負けます。 アルゴリズムはこれを検出します。これは、剰余 0 が優勢であり、有効な分離がないため制約が軽減されるためです。 入力用`4 3 / 3 6 9 12`、すべての剰余はゼロであり、関数は正しく -1 を返します。 

もう一つの微妙なケースは次のような場合です。$m$均一で残差がある$m/2$頻繁に現れます。 自己補完的であるため、このような 2 つの要素をパイル内でペアにすることは常に禁止されています。 アルゴリズムはこれを次のように処理します。`(cnt[r] + 1) // 2`このルールでは、各パイルにそのような要素を最大 1 つだけ含めることができるため、それらを安全に配布するのに十分な量のパイルが必要です。
