 ## 解決策
 ## 問題の理解

 多くの独立したクエリが与えられ、各クエリは間隔を定義します。$[L, R]$値は最大 100 万です。 そのような間隔ごとに、すべての部分間隔を想像する必要があります$[l, r]$それは完全にその中にあります、つまり$L \le l \le r \le R$。 

固定サブインターバルの場合$[l, r]$、すべての数字を見ます$x$その中には 3 で割り切れるものが含まれています。そのような数値ごとに、10 進数表現で「3」が何桁現れるかを数えます。 値$g(l, r)$すべての有効な数字「3」の合計数です。$x$で$[l, r]$。 

クエリに対する最終的な答えは 1 つだけではありません$g(l, r)$、ただし、合計は$g(l, r)$内部のすべての部分区間にわたって$[L, R]$。 部分区間の数は範囲の長さに対して 2 次であるため、すべての部分区間を直接列挙します。$(l, r)$ペアが大きすぎます。 

制約によってこれが明確になります。 まで$10^5$テストケースと最大値$10^6$、クエリごとに線形であっても解決策はすでに困難であり、二次関数は不可能です。 この問題では、「すべての部分配列の合計」を個々の位置の寄与に関する計数問題に変換する必要があります。 

局所的に考えると、微妙な問題が発生します。33 のような数値は 2 桁の「3」に寄与しますが、その寄与はそれを含む部分区間の数によって重み付けされ、また 3 の制約による割り算も考慮されます。 もう一つのエッジケースは、$x = 0$、これは 3 で割り切れ、ゼロ桁の '3' に寄与するため、構造には影響しますが、直接カウントされません。 

## アプローチ

 直接的なアプローチでは、すべてを反復することになります$l$そして$r$、各サブ配列に対してすべてをスキャンします。$x$内部で 3 で割り切れるかどうかをテストし、桁「3」を数えます。 これは正しいですが、非常に高価です。 ある長さの範囲内のサブ配列の数$n$についてです$n^2/2$、各サブアレイは最大でスキャンできます。$n$要素、$O(n^3)$最悪の解釈でのテストごとに。 桁数のプレフィックス合計を再利用するように最適化されたとしても、サブ配列ごとに割り算の制約を評価する必要があるため、$n = 10^6$。 

重要な観察は、問題は線形であるということです。$x$その核心部分にある。 それぞれの数字$x$独立して寄与しますが、その寄与はサブ配列の数によって異なります$[l, r]$それを含めてください。 固定位置$x$まさにに現れます$(x-L+1)\cdot(R-x+1)$の部分配列$[L, R]$。 ただし、内部条件が「すべてを合計しています」であるサブ配列のみが必要です。$l, r$、その中ですべてを合計します$x \in [l,r]$これは置き換えることができます。サブ配列を反復してから数値を反復する代わりに、数値を反復し、それらが含まれるサブ配列の数を数えます。 

したがって、それぞれの有効な数値は$x$貢献します:$$\text{digit\_3\_count}(x) \times \#\{(l,r): L \le l \le x \le r \le R\}$$これは以下に等しい:$$\text{digit\_3\_count}(x) \times (x-L+1)(R-x+1)$$でもそのときだけ$x \equiv 0 \pmod{3}$。 

これにより、問題全体が最大で合計に変換されます。$10^6$クエリ範囲ごとの値。 桁数を効率的に計算する必要がありますが、境界が小さいため、「3」桁の数と割り算マスクの両方を 1 回で事前計算できます。 

したがって、前処理桁数は次のようにカウントされます。$10^6$各クエリ内で 3 の倍数を反復するだけで十分になります。 残りの課題は、$10^5$クエリを効率的に実行します。これは、各範囲内の 3 の倍数のみをスキャンすることで実行されます。

 ## アルゴリズムのチュートリアル

 問題を個々の数値の合計として書き直し、それらの寄与を効率的に累積します。 

1. 配列を事前計算する`cnt3[x]`に何桁の「3」が現れるかを保存します。`x`。 

これは、以下のすべての数値に対して 1 回実行されます。$10^6$これは、数字の構造がクエリとは独立して繰り返されるためです。 
2. 各テスト ケースについて、次の内容を読んでください。$L$そして$R$、そして答えのアキュムレータを初期化します。 
3. すべての数値を反復処理する$x$で$[L, R]$満足するもの$x \bmod 3 = 0$。 

この制限は問題の状態に直接一致するため、他の値はすべて無視されます。 
4. それぞれについて$x$、その寄与を次のように計算します。$$cnt3[x] \cdot (x-L+1) \cdot (R-x+1)$$要因$(x-L+1)(R-x+1)$サブ配列の数を数えます$[l, r]$含む$x$、 以来$l$からの範囲が可能です$L$に$x$、 そして$r$からの範囲が可能です$x$に$R$。 
5. 寄与分を答えのモジュロに追加します$998244353$。 
6. クエリの結果を出力します。 

これが機能する主な理由は、すべてのペアが$(l, r)$立場を超えて独立して貢献する$x$、そして各位置は数字の出現に対して独立して寄与します。 合計を交換することで、部分配列の列挙を完全に回避し、問題をカバレッジのカウントに軽減します。 

### なぜ効果があるのか

 正しさは二重カウントの議論に依存します。 本来、計算はすべてのトリプルにわたって行われます$(l, r, x)$そのような$L \le l \le x \le r \le R$そして$x \equiv 0 \pmod{3}$。 このような各トリプルは、次の数字「3」の数に寄与します。$x$。 

繰り返す代わりに$(l, r)$まず、修正します$x$有効な数を数えてください$(l, r)$それを含めてください。 各サブ配列は含まれるそれぞれに対して独立して寄与するため、すべての有効なペアは 1 回だけカウントされます。$x$。 異なる位置間には相互作用が存在しないため、合計の順序を並べ替えると、合計の寄与が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 10**6 + 5

# precompute digit '3' counts
cnt3 = [0] * MAXN
for i in range(1, MAXN):
    cnt3[i] = cnt3[i // 10] + (1 if i % 10 == 3 else 0)

def solve():
    L = int(input())
    R = int(input())
    
    ans = 0
    
    # iterate only multiples of 3
    start = (L + 2) // 3 * 3
    for x in range(start, R + 1, 3):
        c = cnt3[x]
        if c == 0:
            continue
        left = x - L + 1
        right = R - x + 1
        ans = (ans + c * left * right) % MOD
    
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装は、整数を 10 で割る単純な再帰を使用して、最大 100 万までのすべての数値の桁数を事前計算することから始まります。これにより、各エントリは、その前のエントリがわかってから定数時間になります。 

他のすべての数値は何も寄与しないため、クエリごとに 3 の倍数のみを繰り返します。 算術用語`(x - L + 1) * (R - x + 1)`を含む部分配列の数を直接エンコードします。`x`。 これに事前に計算された数字の寄与を乗算し、必要な素数を法として累積します。 

主な微妙な点は、反復が間隔内の最初の 3 の倍数で開始されるようにすることです。 これにより、すべての数値をチェックする必要がなくなり、実行時間は関連する候補の数にのみ比例するようになります。 

## 実用的な例

 小さな間隔を考えてみましょう。$L = 1$、$R = 6$。 

| × | 3で割り切れる | cnt3[x] | 左 = x-L+1 | 右 = R-x+1 | 貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 3 | はい | 1 | 3 | 4 | 12 |
 | 6 | はい | 0 | 6 | 1 | 0 |

 最終的な答えは 12 です。これは、6 には数字の「3」がないため、数字の 3 だけが意味のある貢献をしていることを反映しています。 この表は、サブ配列カウントの重みが間隔の中央に向かってどのように増加するかを示しています。 

ここで考えてみましょう$L = 10$、$R = 15$。 

| × | 3で割り切れる | cnt3[x] | 左 | 右 | 貢献 |

 どちらの数値にも数字「3」が含まれていないため、多くの部分配列に含まれているにもかかわらず、何も寄与しません。 これは、桁数カウント関数が値の唯一のソースであり、組み合わせ論は重みを決定するだけであることを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$x$は 3 で割り切れますが、数字「3」が含まれていません。 例えば$x = 6$。 アルゴリズムは引き続きアクセスしますが、`cnt3[x]`はゼロなので、何も寄与しません。 これにより、そのような数値を事前にフィルタリングする必要がなくなります。 

もう 1 つのエッジケースは最小範囲です$L = R$。 単一の値が 3 で割り切れない場合、ループは空の範囲にわたって実行され、すぐに 0 を返します。 割り切れる場合、貢献度は次のようになります。$\text{cnt3}(L)$、左右の多重度が両方とも 1 に等しいためです。 

最後の微妙なケースは、間隔が 3 の倍数の境界付近で開始または終了する場合です。 の計算`start = (L + 2) // 3 * 3`最初の有効な候補を決して見逃さないようにします。 たとえば、次の場合$L = 4$、範囲外の包含を防ぐために、3 ではなく 6 から正しく開始します。
