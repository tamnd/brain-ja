 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。各値はパンダに書かれたラベルです。 個別のインデックスの順序付きペアごとに$(i, j)$、2 つの数字を取ることを想像します。$x_i$そして$x_j$そしてそれらをその順序で連結して新しい整数を形成します。 飼育員は、この連結された数値が固定数で割り切れる場合にのみペアを保持します。$K$。 私たちのタスクは、この可分性条件を満たす順序ペアの数を数えることです。 

重要な問題は、連結が前処理なしでモジュロ トリックを直接適用できる算術演算ではないことです。 連結された値は、その桁数によって異なります。$x_i$, そのため、各ペアは不均一な方法で桁の長さを通じて相互作用します。 

この制約により、ペアの二次列挙が即座に除外されます。 と$N$まで$10^5$、すべての順序ペアをチェックすると、$10^{10}$実行可能な限界をはるかに超えた最悪の場合の操作。 すべてのペアごとの連結値を格納することさえ、時間と数値サイズの両方の制約により不可能です。$10^{14}$またはそれ以上。 

注文時に微妙な特殊なケースが発生します。 以来$(i, j)$そして$(j, i)$が異なるため、ペアを逆にすると、算術構造と割り算の結果の両方が変わります。 たとえば、次の場合$x_i = 12$そして$x_j = 3$、 それから$123$そして$312$モジュロでまったく異なる動作をする$K$。 誤って問題を順序のないペアとして扱う解決策は、対称性の仮定に応じて過小評価または過大評価してしまいます。 

もう 1 つの重要なケースは、値の繰り返しです。 多くのパンダが同じラベルを共有する場合、単純な周波数ベースのアプローチでは、明示的に除外しない限り、誤って自己ペアリングを許可することを慎重に回避する必要があります。 

## アプローチ

 ブルートフォース手法では、順序付けられたすべてのペアが試行されます$(i, j)$、連結された数値を構築し、次のように割り切れるかどうかを確認します。$K$。 これは簡単です。次の桁数を計算します。$x_j$、計算する$y = x_i \cdot 10^{d_j} + x_j$、そしてテスト$y \bmod K = 0$。 これは正しいですが、実際には機能します$O(N^2)$テスト ケースごとの操作、これにより約$10^{10}$最悪の場合、チェックが遅すぎます。 

重要な観察は、連結された数値全体が必要ではなく、その剰余のモジュロのみが必要であるということです。$K$。 連結式は次のように書き換えることができます。$$y = x_i \cdot 10^{\text{digits}(x_j)} + x_j$$それで：$$y \bmod K = \big((x_i \bmod K) \cdot (10^{d_j} \bmod K) + x_j \bmod K\big) \bmod K$$これは、値の剰余という 2 つのプロパティによって数値をグループ化することを示唆しています。$K$、およびその桁の長さ。 指定された剰余と桁長を共有する数値がいくつあるかがわかれば、個々のインデックス間ではなくグループ間の互換性を評価できます。 

各数値について、その剰余と桁数を事前に計算します。 次に、固定の「2 番目の要素」について$j$、何個か数えたいです$i \neq j$のみに依存するモジュラー方程式を満たす$x_i \bmod K$と桁の長さ$x_j$。 これにより、問題は、ペアの列挙ではなく、構造化されたバケットに対する繰り返しの頻度ルックアップに変換されます。 

桁のべき乗を繰り返し再計算することを避けるために、事前に計算します。$10^d \bmod K$関連するすべての桁の長さ (最大 10)$x_i \le 10^9$）。 そうすれば、ペアごとに一定時間で互換性をテストできますが、さらに重要なのは、残りのクラスごとにカウントを集計できることです。 

各要素を 2 番目の要素として反復処理します。$j$、必要なターゲット条件を計算します。$x_i$、そして剰余のハッシュマップからカウントを蓄積します。 これにより、問題は 2 次ペアリングからハッシュ ルックアップを使用した線形スキャンに軽減されます。

 | 最適 |$O(N \cdot D)$どこ$D \le 10$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての数値について、その桁数を計算します。 これにより、連結がどのようにスケールされるかが決まります。 連結は位置のずれに依存するため、これだけが必要です。 
2. 事前計算$10^d \bmod K$これにより、ループ内で累乗剰余演算が繰り返されることがなくなります。 
3. 周波数マップを構築する`cnt[r][d]`、 どこ`r`は$x \bmod K$そして`d`桁の長さです。 この構造により、両方のプロパティを共有する数値がいくつあるかを問い合わせることができます。 
4. 各インデックスについて$j$、 扱う$x_j$ペアの 2 番目の要素として。 桁の長さを計算する$d_j$とその残り$r_j$。 何個か数えたい$i$満足する：$$(x_i \cdot 10^{d_j} + x_j) \bmod K = 0$$5. 条件を制約に再配置します。$x_i$:$$x_i \cdot 10^{d_j} \equiv -x_j \pmod K$$これは、考えられるすべての桁長バケットの検索になります。$x_i$。 
6. 各桁の長さについて$d_i$、必要な剰余クラスを計算します。$x_i$モジュラー演算を使用して追加します`cnt[required_remainder][d_i]`答えに。 
7. ペアに誤って 1 件が含まれている場合は、1 件を減算します。$i = j$、度数表には自己計数が含まれているためです。 

### なぜ効果があるのか

 すべての連結は 2 つの独立した属性 (最初の数値の剰余) にのみ依存するため、このアルゴリズムは正しいです。$K$、および 2 番目の数値の桁長。 連結からモジュラー演算への変換では等価性が維持されるため、グループ化された属性が同じモジュラー方程式に一致する場合に限り、2 つのペアは同じ割り算の結果を生成します。 個々のインデックスではなく、考えられるすべての構造化バケットを列挙することにより、有効な順序付きペアをそれぞれ 1 回ずつ正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digits(x):
    return len(str(x))

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    # precompute digit lengths and mod values
    d = []
    rem = []
    for x in a:
        d.append(len(str(x)))
        rem.append(x % k)
    
    # precompute powers of 10 mod k
    pow10 = [1] * 11
    for i in range(1, 11):
        pow10[i] = (pow10[i - 1] * 10) % k
    
    from collections import defaultdict
    
    # cnt[d][r] = how many numbers with digit length d and remainder r
    cnt = [defaultdict(int) for _ in range(11)]
    for i in range(n):
        cnt[d[i]][rem[i]] += 1
    
    ans = 0
    
    for j in range(n):
        dj = d[j]
        xj = rem[j]
        
        # we need (xi * 10^dj + xj) % k == 0
        # => xi * 10^dj % k == (-xj) % k
        
        need = (-xj * 1) % k
        
        for di in range(1, 11):
            pw = pow10[dj]
            # xi * pw ≡ need (mod k)
            # This is linear congruence in xi mod k
        
            # brute over remainders in this bucket
            for r, c in cnt[di].items():
                if (r * pw + xj) % k == 0:
                    ans += c
    
        # remove self pair if counted
        ans -= 1  # since i = j always satisfies loop once

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、バケット化されたカウントのアイデアに直接準拠していますが、インデックス ペアごとに連結を再計算するのではなく、剰余クラスごとに有効性を評価します。 重要な詳細は、10 のべき乗による乗算が一貫性を持つように桁長グループを分割することです。 

各反復の最後に 1 を減算すると、ペアのカウントが補正されます。$(j, j)$度数テーブルには要素自体が含まれているため、同じバケット内に配置されます。 

## 実用的な例

 ### 例 1

 入力:```
3 11

```桁の長さを計算します。すべて 1 です。11 を法とした剰余は 2、4、3 です。 

| j | x_j | 必要な条件 | 有効に数えました |
 | --- | --- | --- | --- |
 | 0 | 2 | (10*i + 2) % 11 == 0 | i=1 は 42 を返し、有効です |
 | 1 | 4 | (10*i + 4) % 11 == 0 | i=0 は 24 を返し、有効です |

 これは、順序がいかに重要であるかを示しています。(2,4) と (4,2) は両方とも有効ですが、独立しています。

```数字はすべて一桁です。 

| j | x_j | 有効な i |

 これにより、繰り返される値が強調表示されます。同一のラベルが複数の有効な順序ペアに寄与します。

 ## 特殊なケース

 単一要素の入力により、自己ペアが誤ってカウントされているかどうかが明らかになります。 注文したペアがないため$(i, j)$と$i \neq j$存在する場合、答えはゼロでなければなりません。 このアルゴリズムは交差項のカウントを回避しますが、自己減算ロジックにより負のアーチファクトが残らないようにする必要があります。 

all などの繰り返し値$x_i = 1$周波数の集約を強調します。 すべてのペアは同一の連結構造を生成するため、正確かどうかは、剰余バケットを通じて多重度を正確にカウントするかどうかに依存します。 

大きな桁のギャップ$[1, 10, 100]$値の大きさごとではなく、桁の長さごとに 10 のべき乗スケーリングが適用されるかどうかをテストします。 桁の長さが誤って計算されると、モジュラー シフトに一貫性がなくなり、すべてのクロスペアが誤って分類されます。 

最後の微妙なケースは次のような場合です。$K = 1$。 すべての連結は割り切れるので、答えは次のようになります。$N(N-1)$。 モジュラー方程式は縮退するため、正しい実装ではゼロで除算したり、逆計算を試みたりしてはなりません。
