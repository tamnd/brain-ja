 ## 解決策
 ## 問題の理解

 高さと長さの 2 つの配列が与えられます。$n$、殺せんせーの残像の2本の線を表しています。 各曲中、あらゆるポジションで$i$の間でペアを形成します$i$最初の行の -th 要素と$i$2 行目の - 番目の要素であり、相互作用コストは高さの絶対差です。 

曲間では、2 つのラインが逆方向に回転します。最初のラインは右に 1 位置シフトし、2 番目のラインは左に 1 位置シフトします。 多くの曲を経て、すべてのオリジナル要素が時間の経過とともに繰り返し異なるパートナーと出会います。 

すべての残像について、すべてのダンスで経験する合計のぎこちなさを計算し、これらの値を両方の行で合計するように求められます。 

したがって、実際のタスクは単一のマッチングに関するものではなく、両方の配列の各要素が、周期的な回転によって引き起こされるパートナーの構造化されたシーケンスとどのように繰り返し相互作用するかを追跡することです。 

この制約により、ブルート シミュレーションは不可能になります。 各テストには最大で次のものを含めることができます$2 \cdot 10^5$要素と曲数$k$と同じ大きさにすることができます$10^{18}$。 曲ごとの直線的なパスですら遅すぎますし、$O(n \log n)$テストごとに全体的に厳しいでしょう$10^4$テストケース。 したがって、構造は、繰り返される回転をサイクルベースまたは算術分解に折りたたむ必要があります。 

微妙なエッジケースが現れるのは、$k$非常に大きいです。 単純なシミュレーションは小さな入力を正しく処理する可能性がありますが、システムが完全に周期的であり、その周期性を無視すると過大な計算や冗長な計算が発生するため、回転が繰り返されると静かに失敗します。 別の特殊なケースが発生するのは、$n = 2$、サイクル構造が退化し、パリティベースの推論が自明になりますが、実装がより大きなサイクルを想定している場合、誤って処理されやすくなります。 

## アプローチ

 直接シミュレーションでは、配列を回転させ、各ステップですべてのペアごとの絶対差を合計し続けます。 各ステップにかかる費用$O(n)$、そして、あります$k$手順が複雑になるため、$O(nk)$。 と$k$まで$10^{18}$、これはまったく不可能です。 

重要な観察は、回転が決定論的であり、高度に構造化されているということです。 両方の配列の各要素は任意に相互作用するわけではありません。 代わりに、パートナーの固定サイクルに従います。 シフト パターンは要素を 2 つの位置のモジュロ単位で移動します。$n$つまり、パリティ クラスは独立して進化します。 これにより、問題が 2 つの独立したサイクルに分割され、それぞれの長さが異なります。$n/2$。 

各要素が反対側の配列の固定パリティ クラスの要素とのみ対話することが認識されると、プロセスは 1 サイクルにわたって繰り返される走査になります。 残る唯一の困難は、発生する完全なサイクルの数と、残りの部分サイクルをどのように考慮するかを処理することです。 

フル サイクルは、パリティ グループ内のグローバル ペアワイズ距離のみに依存する固定量を提供します。 部分的なサイクルは、循環順序の連続したセグメントを導入します。 すべての要素の順序を明示的に追跡するのではなく、すべての要素を集計すると、パリティ サイクルのすべての開始点にわたってすべてのエッジが均一に訪問されることが観察されます。 これにより、残りの寄与を均等に分散し、要素ごとのシミュレーションではなく集計合計を使用して計算できるようになります。

 ## アルゴリズムのチュートリアル

 2 ずつシフトするとパリティが維持されるため、配列を 2 つのパリティ グループに分割します。 偶数インデックスの要素は偶数インデックスとのみ相互作用し、奇数は奇数と相互作用します。 

一度に 1 つのパリティ グループを処理します。 

### ステップ

 1. 両方のアレイをパリティ グループに分割します。 パリティごとに$p \in \{0,1\}$、すべて集めてください$a_i$そして$b_i$ここでインデックス$i \bmod 2 = p$。 各グループにはサイズがあります$m = n/2$。 
2. 各パリティ グループについて、ペアごとの絶対差の合計を事前計算します。$$\text{total}_p = \sum_{x \in A_p} \sum_{y \in B_p} |x - y|$$この値は、2 つのグループ間の 1 つの完全なサイクル相互作用の寄与を表します。 

これは次のように計算できます。$O(m \log m)$値の並べ替えとプレフィックス合計を使用します。 
3. 完全なサイクルと残りのステップが何回発生するかを決定します。$$\text{cycle length} = m,\quad \text{full} = k // m,\quad \text{rem} = k \% m$$4. 全サイクルは以下に貢献します。$$\text{full} \cdot \text{total}_p$$なぜなら、すべての要素がそのパリティ クラス内のすべてのパートナーをサイクルごとに 1 回経験するからです。 
5. 残りについて$rem$ステップでは、サイクル全体にわたって貢献を均一に分配します。 二部相互作用グラフの各エッジは、すべての開始位置にわたって同じ頻度で現れるため、残りの寄与の合計は次のように比例します。$rem / m$全サイクル合計の倍:$$\text{rem contribution} = \frac{rem}{m} \cdot \text{total}_p$$6. 両方のパリティ グループと両方のアレイからの寄与を合計します。 

### なぜ効果があるのか

 2 による回転により、各パリティ クラスにわたって完全な循環グループが作成されます。 の各要素$A_p$のあらゆる要素を満たしています$B_p$全サイクルに 1 回だけ、相互作用コストは順序ではなくペアにのみ依存します。 

シフトプロセスによって引き起こされるすべての開始位置にわたって、長さの部分セグメント$rem$すべての要素にわたって集約されると、サイクル全体にわたって均一に分散されます。 これにより、剰余項の順序への依存がなくなり、フルサイクル相互作用合計の単純な比例スケーリングに減ります。 

不変条件は、システムがパリティ クラス間の 2 部完全グラフにわたる一様な走査のように動作することです。ここで、全サイクルは完全なカバレッジに対応し、残りは一様な部分カバレッジに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def calc_total(a, b):
    a.sort()
    b.sort()

    prefix = [0] * (len(b) + 1)
    for i in range(len(b)):
        prefix[i+1] = prefix[i] + b[i]

    res = 0
    j = 0
    m = len(b)

    for x in a:
        while j < m and b[j] < x:
            j += 1
        left = j * x - prefix[j]
        right = (prefix[m] - prefix[j]) - (m - j) * x
        res += left + right

    return res

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        groups = [[], []]
        for i in range(n):
            groups[i % 2][0:0]  # placeholder to emphasize structure

        # split by parity
        a_par = [[], []]
        b_par = [[], []]

        for i in range(n):
            a_par[i % 2].append(a[i])
            b_par[i % 2].append(b[i])

        ans = 0

        for p in [0, 1]:
            A = a_par[p]
            B = b_par[p]
            m = len(A)

            if m == 0:
                continue

            total = calc_total(A, B)

            full = k // m
            rem = k % m

            ans += full * total
            ans += (rem * total) // m

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各テスト ケースを 2 つの独立したパリティ システムに分割します。 システムごとに、絶対差分に対する標準のソート済み 2 ポインター手法を使用して、すべてのペア間の総相互作用コストを計算します。 

フルサイクルの寄与は、完全な回転が何回発生するかによって決まります。 残りの寄与は、全サイクルの合計を比例的に分配することによって処理され、順序を明示的にシミュレートする必要がなくなります。 

すべての寄与は最終的には整数であり、サイクル全体にわたって均一に適用されるため、集計では割り算が維持されるため、剰余項での整数の除算には注意が必要です。 

## 実用的な例

 ### 例 1

 次のような小さなパリティ グループを考えてみましょう。$A = [1, 3]$、$B = [2, 4]$、 そして$k = 3$、サイクル長付き$m = 2$。 

| ステップ | 全サイクル | 残り | 基本合計 | 貢献 |
 | --- | --- | --- | --- | --- |
 | 計算 | 1 | 1 | 8 | 8 + (1/2)*8 |

 フルサイクルでは、すべてのペアの相互作用が 1 回行われます。 2 ステップ サイクルのうち 1 ステップのみが使用されるため、残りは全サイクル合計の半分に相当します。 

これは、循環構造が回転の明示的なシミュレーションをどのように回避するかを示しています。 

### 例 2

 テイク$A = [5, 10, 15, 20]$、$B = [1, 2, 3, 4]$、 と$k = 10$、 それで$m = 2$。 

各パリティ グループは独立して動作します。 このアルゴリズムは、サイクルごとに完全なペアごとの相互作用を 1 回計算し、完了したサイクルの数によってスケールし、残りを比例的に分配します。 

これは、より大きな配列の場合でも、解決策は順序付けではなく、集約されたペアごとの構造にのみ依存することを示しています。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$n = 2$。 この状況では、各パリティ クラスのサイズは$1$, そのため、すべての要素が同じパートナーと繰り返し遭遇します。 このアルゴリズムは、単一の絶対差に次の乗算を行います。$k$、サイクル長が 1 であるため、サイクル分解は依然として正しく動作します。 

もう 1 つの特殊なケースは、すべての値が等しい場合です。 すべての絶対差がゼロになるため、フルサイクルの寄与と残りの寄与の両方がきれいに崩壊します。 これは、アルゴリズムがスケーリングを通じて人為的な非ゼロ寄与を導入しないことを確認します。 

3 番目のエッジケースは次の場合に発生します。$k$サイクル長の倍数ではありません。 剰余処理により、全サイクル合計の小数部分のみが追加されることが保証されます。これは、停止前に循環走査の一部のみが実行されるという事実と一致します。
