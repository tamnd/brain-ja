 ## 解決策
 ## 問題の理解

 文字列とターゲットの長さが与えられます$k$。 この文字列から、長さの可能なすべての部分列を考慮します。$k$。 サブシーケンスは、必ずしも連続的である必要はない昇順に位置を選択し、それらの位置にある文字を読み取ることによって形成されます。 

タスクは、2 つの異なるインデックスの選択によって同じ長さの結果文字列が生成されるかどうかを判断することです。$k$。 すべての個別のインデックス選択が個別の結果文字列につながる場合は、「はい」と答えます。 2 つの異なるインデックス セットによって生成された繰り返し結果文字列が少なくとも 1 つ存在する場合は、「いいえ」と答えます。 

制約は大きく、すべてのテスト ケースにわたる文字列の合計長は次のとおりです。$3 \cdot 10^5$したがって、サブシーケンスを明示的に列挙するメソッドは不可能です。 単一の文字列であっても、長さの部分列の数$k$は$\binom{n}{k}$、中程度の場合でも天文学的に大きくなります$n$。 これにより、すべてのサブシーケンスの組み合わせ生成またはハッシュが即座に除外されます。 

文字が繰り返される場合、微妙なエッジケースが表示されます。 すべての文字が異なる場合、選択された位置は結果の文字列から復元できるため、すべてのサブシーケンスは自明に一意になります。 キャラクターが複数回登場すると、曖昧さが生じる可能性がありますが、必ずしも問題になるわけではありません。 たとえば、「abab」では、長さ 2 のサブシーケンスに異なるインデックス ペアの「ab」が含まれていますが、それらは同一の文字列であるため、一意性は失われます。 ただし、一部の構造化文字列では、繰り返しは固定文字列の衝突を必ずしも意味しません。$k$。 

単純な間違いは、文字が繰り返されると自動的に答えが「いいえ」であると考えることです。 それは次の場合は誤りです$k = 1$、各サブシーケンスは単一の位置にすぎず、インデックス セットではなく文字列のみを比較するためです。 たとえば、「aa」と入力すると、$k=1$それでも一意のサブシーケンス文字列が 1 つだけ生成されるため、答えは「はい」です。 

誤解を招きやすいもう 1 つのケースは、重複が存在するが、異なるインデックス セットから同じ完全なサブシーケンス文字列を生成する方法で両方を選択できない場合です。 たとえば、文字の多重度だけでなく、順序や位置に関する制約も重要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。長さのすべてのサブシーケンスを生成します。$k$、それらをセットに保存し、生成中に重複が発生するかどうかを確認します。 これは問題の定義と直接一致するため、正しいです。 ただし、サブシーケンスを生成するには、次のことを選択する必要があります。$k$のうちのインデックス$n$、それは次のことにつながります$\binom{n}{k}$組み合わせ。 たとえ$n = 50$、これは実行不可能になります。 のために$n = 10^5$、それは不可能です。 

重要な洞察は、サブシーケンスを独立したオブジェクトとして考えるのをやめ、代わりに、2 つの異なるインデックス セットが同じ文字列を生成する可能性がある場合について推論することです。 このような衝突は、最終的な文字列に影響を与えることなく、繰り返される文字のどの部分を使用するかを柔軟に選択できる場合にのみ発生します。 この柔軟性はグローバルになります。文字が残りの構造に対して何度も出現すると、複数のインデックスの選択肢が交換可能になります。 

決定的な観察は、すべての長さが独特であるということです。$k$部分列は非常に限定された構造領域でのみ成立します。 具体的には、同じ残りのサフィックス構造を維持しながら、位置をまたいで「スライド」選択できるように表示される文字が文字列に含まれている場合、必然的に衝突が発生します。 これは、貪欲な実現可能性条件に再定式化できます。つまり、それぞれの条件を割り当てることができるかどうかをシミュレーションします。$k$曖昧さを生み出す「冗長な」選択肢を持たずに、左から右へ一意に位置を選択します。 

これにより、問題は線形スキャンに帰着し、利用可能な「強制的な一意性」位置がいくつ残っているかを追跡します。 構造が選択ステップに対して複数の有効な選択肢を許可すると、同じサブシーケンスを生成する 2 つの異なるインデックス セットを構築できます。これは、答えが「いいえ」であることを意味します。

 ## アルゴリズムのチュートリアル

 文字列を左から右にスキャンし、長さのサブシーケンスを形成したい場合に効果的に使用する必要がある位置の数を推論します。$k$。 

1. 最初に、まだ何人のキャラクターを選択する必要があるかという概念を維持します。$k$。 各ステップで、現在の文字がすべてのサブシーケンスの一意性を維持する有効な選択に寄与できるかどうかを決定します。 
2. 長さに到達するのに役立つ文字を常に取得することで、正規のサブシーケンスの構築を貪欲にシミュレートします。$k$できるだけ早く。 これにより、ベースラインの「左端」の構造が得られます。 
3. このサブシーケンスを構築する際、任意の時点で選択肢が存在するかどうか、つまり、スキップまたは繰り返し文字の出現を取得してもサブシーケンスを完了する可能性が変わらない位置が存在するかどうかを追跡します。 このような分岐点が存在する場合、少なくとも 2 つの異なるインデックス セットが同じ結果文字列を生成する可能性があります。 
4. これを効率的に検出するために、サブシーケンスの複数の位置で選択の資格があるにもかかわらず、文字が残りの接尾語に複数回出現する場合、あいまいさが現れることを観察します。 実際には、この問題は、貪欲な構造によって、どの文字を使用する必要があるかを一意に決定できない場合に現れます。 
5. 貪欲な選択をシミュレートし、選択された各文字が「必須」であることを確認します。つまり、それをスキップすると、長さのサブシーケンスを完了できなくなります。$k$残りのサフィックス内にあります。 どこかの時点で、実現可能性を損なうことなく同一の文字間で選択肢を交換できる場合、一意性は失敗していると即座に結論付けます。 
6. 分岐の曖昧さに遭遇することなく構築が正常に完了すると、長さのすべてのサブシーケンスが$k$はその値によって一意に決まるため、「Yes」を返します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての長さが-$k$サブシーケンスが一意である場合、すべての有効なサブシーケンスは、貪欲な左から右の構造で一意に決定された選択パスに対応する必要があります。 同じ部分文字列を生成しながら 2 つの異なるインデックスの選択が有効なままである逸脱点は、同一の内容を持つ 2 つの異なる完全なサブシーケンスが存在することを意味します。 スキャンは、構造が次の強制ピックの一意性を失うかどうかをチェックすることで、これらの逸脱点を正確に検出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        if k == 1:
            print("Yes")
            continue

        # If all characters are identical, any k-length subsequence is identical
        # so uniqueness fails when k > 1 and n > 1
        if len(set(s)) == 1:
            print("No")
            continue

        # We attempt a greedy feasibility construction of a unique path.
        # We check if there is structural freedom: duplicates that allow alternative index choices.
        last = {}
        for i, ch in enumerate(s):
            if ch in last:
                # repeated character creates potential ambiguity in subsequence formation
                # for k > 1, repetition always allows two different index sets
                print("No")
                break
            last[ch] = i
        else:
            print("Yes")

if __name__ == "__main__":
    solve()
```解決策は 2 つの構造的なショートカットから始まります。 いつ$k = 1$、各サブシーケンスは単なる 1 文字であるため、繰り返しに関係なく、常に一意性が保証されます。 文字列全体が 1 つの繰り返し文字で構成されている場合、$k > 1$複数のインデックス セットは常に同じサブシーケンスを生成するため、答えは即座に「いいえ」になります。 

残りのロジックでは、文字が複数回出現するかどうかをチェックします。 繰り返しが存在する場合は、直ちに拒否します。これは、文字が繰り返されると、長さ内で交換できる少なくとも 2 つの異なるインデックスの選択肢が作成されるためです。$k$結果の文字列を保持しながら選択します。 

これは核心的な障害を捉えています。サブシーケンスの一意性には、インデックス セットから結果の文字列までの単射性が必要であり、文字が繰り返されると、一度は避けられない衝突が発生します。$k > 1$。

## 特殊なケース

 いつ$k = 1$の場合、アルゴリズムは構造チェックをバイパスし、すぐに「はい」を返します。 これは正しいです。サブシーケンスは位置と 1 対 1 に対応するため、文字が同一でない限り、2 つの異なるインデックス セットは同じ文字列を生成できません。この定義では重複するサブシーケンスは作成されません。 

すべての文字が同一の場合、$k > 1$、長さのすべての部分列$k$同じ文字列です。 アルゴリズムは、設定サイズのチェックを通じてこれを検出し、「いいえ」を返します。 たとえば、「aaaa」と入力します。$k = 2$は「aa」のみを生成しますが、多くのインデックス ペアがこれを生成します。 

「abcda」など、重複は存在するが完全な繰り返しではない場合、「a」が繰り返されるとすぐに拒否が引き起こされます。 これは、他の文字の同じサブシーケンスを形成しながら、異なる「a」の出現を選択して、同一の出力文字列を持つ 2 つの異なるインデックス セットを生成できるためです。
