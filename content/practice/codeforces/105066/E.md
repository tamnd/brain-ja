 ## 解決策
 ## 問題の理解

 値の配列と、配列がソートできるかどうかを「テスト」するたびに、ジンシが繰り返し適用するインデックス スワップの固定シーケンスが与えられます。 重要なのは、すべてのテスト後にアレイを復元するため、スワップ シーケンスは常に新しいコピーで実行されることです。 

猫猫は毎日、独立して配列内の 2 つの位置を永久に交換します。 この変更後、Jinshi は同じ固定スワップ シーケンスを再度実行し、結果の配列が非降順で並べ替えられているかどうかを確認します。 

したがって、毎日のプロセスは次のとおりです。現在の配列から開始し、既知のスワップの順列をインデックスに適用し、結果として並べ替えられた配列がソートされているかどうかを確認します。 

重要な問題は、スワップ シーケンスが値に依存せず、位置の固定された並べ替えを定義することです。 毎日、2 つの位置を交換することで基礎となる配列を少し変更します。位置の固定順列を適用した後、値がソートされるかどうかを答えなければなりません。 

制約は大きく、最大 100,000 のポジション、100,000 の固定スワップ、および 100,000 のクエリがあります。 スワップ シーケンスの効果を再計算したり、クエリごとにプロセス全体を再シミュレーションしたりするソリューションでは、クエリごとに少なくとも線形時間が必要となり、これには約 10^10 の操作が必要となり、制限時間を大幅に超えます。 

単純なアプローチでは、各クエリの後に m 個のスワップをシミュレートし、クエリごとに O(n + m) の並べ替えをチェックします。 これはすぐに制約を破ります。 

より巧妙で単純な試みでは、各クエリの後でのみ順列を再構築して再計算を試行しても、最終的には O(mq) になる可能性があります。 

重要なエッジ ケースの 1 つは、キャンセルが繰り返されるため、スワップ シーケンスが長くても事実上小さい場合です。 たとえば、位置 1 と 2 を 2 回交換すると同一性が返されますが、単純なシミュレーションでは依然として毎回 2 つの操作として扱われ、作業が無駄になります。 

もう 1 つの注意が必要なケースは、猫猫のスワップが最終的な置換構造内の遠く離れた位置に影響を与える場合です。この場合、固定置換によってインデックスがどのように再配置されるかを注意深く追跡しない限り、局所的な仮定が無効になります。 

## アプローチ

 重要な観察は、m 個のスワップのシーケンスが値に依存しないため、インデックスの固定順列を定義するということです。 この順列を P とします。これは、すべてのスワップを実行した後、もともと位置 i にあった値が位置 P(i) に移動することを意味します。 

ID の位置から開始して各スワップをインデックスのスワップとして適用することで、この順列を 1 回計算できます。 これにより、位置がどのように再配置されるかについての固定マッピングが得られます。 

次に、特定の日のアレイのスナップショットを考えてみましょう。 固定順列 P を適用した後、固定インデックス順序に従って配列を効果的に並べ替えることになります。 値の移動という観点から考える代わりに、配列が読み取られる位置の新しい順序を定義するものとして P を考えることができます。 

Q を P の逆順列とします。スワップ シーケンスを適用した後の最終的な配列は次のようになります。 

Q(1)、Q(2)、…、Q(n) の順序で位置を読み取ります。 

したがって、質問は次のようになります。元の配列での毎日の交換後のシーケンスは次のとおりです。 

A[Q(1)]、A[Q(2)]、…、A[Q(n)]は減少していませんか?

 これにより、問題は、並べ替えられたビューが並べ替えられているかどうかを確認しながら、固定順序で配列を維持し、基になる配列でのポイントの交換をサポートするという問題に変換されます。 

ブルート フォース ソリューションでは、各更新後にシーケンス A[Q(i)] を再構築してスキャンし、クエリごとに O(n) のコストがかかります。 それはまだ遅すぎます。 

主な改善点は、元の配列の交換が 2 つの位置にのみ影響することです。 Q 順序のビューでは、これはちょうど 2 つの位置を変更することに対応します。 並べ替えは隣接する比較にのみ依存するため、これら 2 つのインデックスの周囲のローカル近傍のみをチェックする必要があります。

Q オーダー内の隣接する要素間の「反転」の数を維持します。 各クエリは一定数の隣接ペアのみを更新するため、クエリごとに O(1) の正確性を維持できます。

 ## アルゴリズムのチュートリアル

 ### 1. 固定スワップによって引き起こされる順列を構築する

 インデックスの恒等配列から始めます。 交換 (x, y) ごとに、このインデックス配列内の位置 x と y を交換します。 m 回すべてのスワップを処理した後、この配列は P(i)、つまりスワップ シーケンス後のインデックス i の最終宛先を表します。 

### 2. 逆順に変換する

 配列を構築します`rank[pos]`そのような`rank[pos]`の位置を与える`pos`最終的な並べ替え順序で。 これは、すべてのスワップの効果をシミュレートするために元の配列を読み取る必要がある順序を定義します。 

### 3. 最初の順序付けされたシーケンスを構築する

 インデックス 1 から n までの概念配列 S を定義します。ここで、

 S[i] = A[inverse_rank[i] ]。 

これは、固定順列を適用した後の配列を表します。 

### 4. S の局所障害を数える

 S[i] > S[i+1] を満たすインデックス i がいくつあるかを計算します。 このカウントにより、シーケンスがソートされているかどうかがわかります。 カウントがゼロの場合、配列はソートされます。 

### 5. 各クエリを処理します (元の配列と入れ替えます)

 クエリごとに、A 内の l と r の位置を交換します。 

Q オーダーにおけるそれらの位置、つまり、rank[l] と Rank[r] を特定します。 S のこの 2 つの位置のみが変更されます。 

隣接性チェックへの寄与を一時的に削除し、A の値を交換してから、rank[l] と Rank[r] の周囲の隣接するペアのみを再評価します。 

### 6. 結果の出力

 更新後に隣接する違反がない場合は「Y」を出力し、それ以外の場合は「N」を出力します。 

### なぜ効果があるのか

 スワップ シーケンスによって引き起こされる順列は固定されているため、最終チェックにおけるインデックスの相対順序は一定です。 唯一の動的コンポーネントは、これらのインデックスに配置された値です。 

並べ替えは固定順序での隣接する比較のみに依存し、各クエリはその順序で 2 つの位置のみを変更するため、影響を受けるすべての比較はローカルです。 隣接するペアに影響を与えずに非ローカルな反転は発生しないため、隣接違反のみを維持するだけで十分かつ正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))

    # Build permutation P from swaps
    p = list(range(n))
    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        p[x], p[y] = p[y], p[x]

    # inverse permutation: rank[position] = order index
    rank = [0] * n
    for i in range(n):
        rank[p[i]] = i

    # S[i] = a[p[i]] conceptually, but we store via inverse mapping
    S = [0] * n
    for i in range(n):
        S[i] = a[p[i]]

    def bad(i):
        return 1 if 0 <= i < n - 1 and S[i] > S[i + 1] else 0

    bad_cnt = 0
    for i in range(n - 1):
        bad_cnt += bad(i)

    def fix(pos):
        nonlocal bad_cnt
        for i in (pos - 1, pos):
            if 0 <= i < n - 1:
                bad_cnt -= bad(i)
        # recompute local position already updated outside

        for i in (pos - 1, pos):
            if 0 <= i < n - 1:
                bad_cnt += bad(i)

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        i1, i2 = rank[l], rank[r]

        # remove old contributions
        for i in (i1 - 1, i1, i2 - 1, i2):
            if 0 <= i < n - 1:
                bad_cnt -= bad(i)

        # swap in original array
        a[l], a[r] = a[r], a[l]

        # update S only at affected positions
        S[i1] = a[p[i1]]
        S[i2] = a[p[i2]]

        # add back contributions
        for i in (i1 - 1, i1, i2 - 1, i2):
            if 0 <= i < n - 1:
                bad_cnt += bad(i)

        out.append('Y' if bad_cnt == 0 else 'N')

    print(''.join(out))

if __name__ == "__main__":
    solve()
```この実装では、静的な置換構造が動的な配列値から分離されます。 配列`p`固定スワップ シーケンスの効果をエンコードします。`rank`元のインデックスを最終的な順序にマッピングしてみましょう。 

配列`S`完全に再構築されることはありません。 クエリごとに影響を受ける 2 つの位置のみが更新されます。 変数`bad_cnt`並べ替えられた順序で隣接する違反がいくつ存在するかを追跡し、変更されたインデックスを中心にのみ調整されます。 

アップデートの際は注意が必要`bad_cnt`: 各クエリは、変更されたインデックスごとに最大 4 つの隣接位置に触れるので、更新は一定時間維持されます。 周囲の境界チェックが欠落している`i-1`そして`i`これは、off-by-one エラーの一般的な原因です。 

## 実用的な例

 ### サンプル 1 トレース

 関連する構造、つまり順序付けされた配列 S と隣接関係違反のみを追跡します。 

| ステップ | 操作 | 影響を受けるポジション | 悪いペア |
 | --- | --- | --- | --- |
 | 0 | イニシャル | フルビルド | S | から計算
 | 1 | l=1、r=3を交換 | ランク 1 と 3 | ローカルを更新 |
 | 2 | クエリ結果 | なし | bad_cnt をチェックしてください |

 最初の更新後、シーケンスは固定順列でソート可能になるため、答えは Y になります。 

後続のスワップにより、Q オーダー内の隣接する要素間に必要な順序関係が壊れるため、 bad_cnt がゼロ以外になり、N が生成されます。

 | ステップ | 操作 | 影響を受けるポジション | 悪いペア |

 | 1 | スワップは順序に影響します。 2 つのインデックス | ローカル修正 |
 | 2 | スワップは順序を部分的に復元します。 2 つのインデックス | ローカル修正 |

 この例は、ローカルな隣接構造のみが重要であるため、中断後でもグローバルな再計算を行わずに並べ替えを復元できることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、クエリ内の交換された両方の位置が、置換順序で隣接するインデックスにマップされる場合です。 この場合、両方の位置が S 内の同じ隣接ペアに影響します。不正なペアは更新前に削除され、後で再追加されるため、アルゴリズムはこれを正しく処理し、二重カウントを防ぎます。 

もう 1 つのケースは、n が 1 または 2 の場合です。n = 1 の場合、シーケンスはスワップに関係なく常にソートされます。 n = 2 の場合、隣接ペアは 1 つだけであるため、更新では 1 つの比較のみが切り替えられ、アルゴリズムは 1 つのブール条件を追跡するように正しく縮小されます。
