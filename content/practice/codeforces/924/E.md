 ## 問題の理解

 一連のボックスが与えられます。各ボックスには正の高さと、ボックスが重要かどうかを示すバイナリ ラベルが付いています。 これらのボックスを任意に並べ替えて垂直に積み重ねて、個々の高さの合計が高さになる 1 つの連続した列を形成することができます。 

各ボックスは、最終的な積み重ね順序における下端の高さという 1 つの重要な値に寄与します。 ボックスを高さから配置する場合$x$、 それから$x$得点するために重要なことです。 

インターバルも設けております$[l, r]$。 この間隔内に下端があるすべての重要なボックスは、スコアに 1 を与えます。 目標は、できるだけ多くの重要なボックスの下端がこの高さウィンドウ内に収まるように、すべてのボックスの順序を変更することです。 

この制約により、高さの合計が最大でも 10000 であることがわかります。$n \le 10000$。 これは、配置の複雑さではなく全高に依存するあらゆる解決策が実行可能であることを直ちに示唆しています。 二次関数のオーバー$n$最適化された形式では依然として許容される可能性がありますが、順列に対する指数関数的または階乗的推論は完全に除外されます。 

主な問題は、1 つのボックスを配置すると、その後のすべての最下位の位置に影響を与えるため、ローカルな決定によって全体的な実現可能性が変化することです。 プレフィックスの合計を追跡せずに「重要なボックスを間隔に詰め込む」という素朴な貪欲なアプローチは失敗します。 

いくつかの特殊なケースでは、その繊細さが明らかになります。 

すべての重要なボックスの高さが非常に高く、単一の順序によって間隔の境界が異なる方向に押し出される場合、貪欲な配置により多くの下端が外側に移動する可能性があります。$[l, r]$。 たとえば、重要なボックスがすべて早めに配置されている場合、その下端は小さくなり、下に落ちます。$l$、たとえボックスのセットが最適であっても、それらは役に立たなくなります。 

別の障害モードは、パディングとして使用できる小さな重要でないボックスが十分にある場合に発生します。 単純な戦略ではそれらを無視する可能性がありますが、重要なボックスを得点枠に移動するには重要です。 

最後に、間隔は完全に全体の高さの中央に位置する可能性があるため、選択したアイテムの下端をナップザックのようなプレフィックス構造内の固定ウィンドウに効果的に「位置合わせ」しようとしています。 

## アプローチ

 この強引なアイデアは、ボックスのすべての順列を試し、順序ごとにプレフィックスの合計を計算し、重要なボックスの下端がいくつあるかを数えるというものです。$[l, r]$。 これは、定義を直接評価するため、正しいです。 ただし、$n!$順列、さらに 1 つの順列の評価にもコストがかかります$O(n)$、全体的に複雑になります$O(n! \cdot n)$、これは実現不可能です。 

重要な観察は、選択されたボックスの相対的な順序のみが重要であり、選択された重要なボックスが寄与するかどうかに影響を与える唯一のことは、その前に累積された合計の高さであるということです。 合計の高さは 10000 で制限されているため、プレフィックス合計タイムラインを構築し、どの重要なボックスがターゲット間隔内に収まるかを決定するという問題として再構成できます。 

順列という観点から考えるのではなく、重要なボックスのサブセットを選択し、それらの下端が下端に収まるように配置するという観点から考えます。$[l, r]$。 重要でないボックスは純粋にパディングとして機能します。つまり、スコアには寄与せずにプレフィックスの合計をシフトするだけです。 

これにより、高さに関する動的プログラミングが行われ、指定された合計高さまでに重要なボックスをいくつ配置できるか、またそのうちのいくつがターゲット間隔に収まるかを追跡します。 構造は全高にわたってナップザック スタイルの DP になり、重要なボックスを配置するか重要でないボックスを配置するかによって遷移します。

## アルゴリズムのチュートリアル

 最終的なスタックを段階的に構築し、各合計の高さに配置した重要なボックスの数を追跡する DP を定義します。 

1. インデックスが現在のスタックの合計の高さを表し、値がこれまでに配置され、答えに貢献した重要なボックスの最大数を表す DP 配列を定義します。 また、新しく配置された重要なボックスの下端が内側にあるかどうかを追跡する必要もあります。$[l, r]$、これは配置前の現在の高さのみに依存します。 
2. DP を高さ 0、寄与率 0 で初期化します。 
3. 各ボックスを繰り返し処理します。 同じボックスが複数回再利用されることを避けるために、ボックスごとに逆の高さの順序で DP を更新します。 
4. ボックスが重要でない場合は、高さのみを変更します。ボックスを配置すると、スコアに影響を与えることなく、後続のすべての位置が前方に移動します。 
5. ボックスが重要な場合は、手の届くあらゆる高さの状態に配置することを検討します。 現在の身長が$h$、このボックスを配置すると、その下端が次と等しくなります。$h$。 もし$h \in [l, r]$、この配置の答えに 1 を獲得します。 
6. ボックスを高さの状態に分配するすべての方法の最大値を取得します。 

重要なアイデアは、DP が最終的な構造を直接最適化しているのではなく、達成可能なプレフィックス合計に対する重要なボックスの下端の分布を最適化しているということです。 

### なぜ効果があるのか

 構築のどの時点でも、DP 状態はボックスのサブセットを配置した後の到達可能な合計高さのセットを完全にキャプチャします。 ボックスの順序は任意であるため、すべてのサブセットはプレフィックス合計の可能な配置に対応します。 重要な各ボックスは、それが配置されている高さのみに基づいて独立して貢献します。 今後の配置では高さのみが増加するため、下端が位置するかどうかに遡って影響を与えることはできません。$[l, r]$。 これにより、DP 遷移に対して局所的に追加的な決定が行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l, r = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    H = sum(a)
    NEG = -10**9

    dp = [NEG] * (H + 1)
    dp[0] = 0

    for i in range(n):
        ai, bi = a[i], b[i]
        new = dp[:]
        for h in range(H - ai + 1):
            if dp[h] == NEG:
                continue
            nh = h + ai
            val = dp[h]
            if bi == 1 and l <= h <= r:
                val += 1
            new[nh] = max(new[nh], val)
        dp = new

    print(max(dp))

if __name__ == "__main__":
    solve()
```DP アレイは、合計のスタック高さによってインデックスが付けられます。 各トランジションでは、重要でないボックスまたは重要なボックスが追加されます。 大切な箱を高所に置く場合$h$、その下端がスコアに貢献しているかどうかを直接チェックします。 ここでは、逆の反復が配列のコピーによって置き換えられ、各ボックスが最大 1 回使用されることが保証されます。 

微妙な点は、順列を明示的にモデル化する必要がないということです。 DP は本質的に、異なる次数を同じ高さ構成に到達するための異なる方法として扱います。問題となるのは下端の高さのみであるため、これで十分です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、間隔が 0 で始まる場合です。その状況では、最初に配置された重要なボックスの下端は常に 0 になるため、ボックスが重要であれば、高さ 0 の有効な DP 状態がすぐに影響します。 アルゴリズムは条件をチェックするため、これを処理します。`l <= h <= r`トランジション前の高さ 0 に直接配置されます。 

すべてのボックスが非常に大きく、間隔の境界に収まるのが 1 つまたは 2 つだけである場合、別のエッジ ケースが発生します。 DP は引き続き高さのすべてのサブセットを考慮し、高さの遷移が正確であるため、無効な配置はカウントされません。 

最後の微妙なケースは、複数の異なるシーケンスによって全体の高さは同じになるが、重要な下端の分布が異なる場合です。 DP は、高さごとの最良のスコアを維持することでこれらの状態を自然にマージし、達成可能な最良の配置を維持しながら、同等の高さが二重にカウントされないようにします。
