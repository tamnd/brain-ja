 ## 問題の理解

 各平面は線上のある座標から始まり、原点に向かって移動します。 位置と速度の符号条件により、風がなければすべての飛行機が最終的にゼロ点に到達することが保証されます。 単一のグローバル風の値がすべての速度に追加され、すべての飛行機の速度が同じ量だけ変化します。 その風によって各飛行機が原点に到着する時間が変わります。 

飛行機の任意のペアについて、一定の間隔内に少なくとも 1 つの風の値が存在するかどうかを知りたいとします。$[-w, w]$両方の飛行機が正確に同時に原点に到着するようにします。 異なるペアに同じ風を使用する必要はなく、ペアごとの存在のみが重要です。 

重要な数量は飛行機の到着時間です$i$風の下で$v$、つまり$t_i(v) = \frac{x_i}{v_i + v}$。 これら 2 つの有理式が同じ場合に、2 つの平面は同期されます。$v$、そしてそれ$v$また、両方の平面を物理的に有効に保つ必要があります。つまり、両方とも原点に向かって移動することを意味します。 

入力サイズにより強制的に$O(n \log n)$または同様のソリューション。 と$n = 10^5$、 どれでも$O(n^2)$ペアごとのチェックは、次のような処理が必要となるため、すぐには実行不可能です。$10^{10}$評価。 たとえ$O(n \sqrt{n})$実際にはアプローチが大きすぎます。 

単純な実装は、2 つの微妙な面で失敗することがよくあります。 まず、ペアを均等にする風の値を計算しますが、両方の飛行機がその風の下でも原点に到達するかどうかを確認することを忘れます。 次に、等しい風の値を計算しますが、それらが以下の範囲内にあるかどうかは無視します。$[-w, w]$、不可能な風の条件下でのみ交差するペアを過剰にカウントすることにつながります。 

たとえば、2 つの飛行機が有効な交差風を持っている可能性があります。$v = 10^9$、しかし、もし$w = 1$、そのペアはカウントされてはなりません。 もう 1 つの失敗例は、計算された風が分母を 1 つにする場合です。$v_i + v$符号を変更します。これは、たとえ代数上の等式がまだ成り立つにもかかわらず、平面が原点に到達しないことを意味します。 

## アプローチ

 直接的なアプローチでは、飛行機のすべてのペアをチェックし、到着時間を均等にする風の値を計算し、実現可能性を検証します。 平等条件$$\frac{x_i}{v_i + v} = \frac{x_j}{v_j + v}$$は明示的に解くことができ、ペアごとに一意の風の候補値が得られます。 これは数学的には正しいですが、すべてのペアについてこれを計算して検証するコストは次のとおりです。$O(n^2)$が遅すぎる$10^5$飛行機。 

重要な洞察は、各ペアが最大 1 つの風力値候補に寄与し、すべての制約が次の不等式として書き換えられるということです。$(x_i, v_i, x_j, v_j)$。 時間の平等性を直接考える代わりに、条件を、変換された空間での相対的な順序のみに依存する比較に変換します。 

代数的単純化の後、2 つの事実が明らかになります。 まずは平等の風$v^*$は 4 つのパラメータの有理式です。 第 2 に、実現可能性の条件は、速度に関する単調比較と、次のような線形制約に分割されます。$w$。 この構造により、ある次元でフェンウィック ツリーを使用し、別の次元をスイープしながら平面を並べ替え、有効なペアをカウントすることができます。 

ペアを明示的に列挙することは避けます。 代わりに、速度のソート順に飛行機を処理し、各飛行機について、風の限界と等時間条件によって引き起こされる変換された不等式制約を満たす以前の飛行機の数を数えます。

 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 変形したスイープ + フェンウィック ツリー |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ペアが次のように条件を書き換えます。$(i, j)$順序関係と風の間隔から導出される 2 つの線形制約を使用してチェックできます。 

### 1. 制約を同等の形式に分割する

 等価条件と風の実現可能性から、ペアは次の場合にのみ有効であることがわかります。 

- 平等の風$v^*$にある$[-w, w]$- 両方の飛行機はその風の下で原点に向かって進み続けます
 - 到着時刻間の等価条件が成り立つ

 最初の条件は次の線形不等式になります。$(x_i, v_i, x_j, v_j)$。 2 番目の条件は、以下の比較に単純化されます。$v_i$そして$v_j$、飛行機が原点のどちら側から開始するかによってのみ決まります。 

### 2. 注文条件の実現可能性を下げる

 単純化した後、実現可能性の制約は、有効なペアに対して、次の順序付けが行われることを意味します。$v_i$そして$v_j$の符号によって決定される方向条件を満たさなければなりません。$x_i$。 これにより、速度をソート可能なキーとして扱うことができます。 

### 3. 速度で飛行機を並べ替える

 すべての飛行機を次の基準で並べ替えます$v_i$。 これにより、プレーンを処理するときに、以前に処理されたすべてのプレーンが、派生制約の 1 つで一貫した順序を満たすことが保証されます。 

### 4. 残りの制約を範囲カウントに変換する

 風間隔制約と等式制約を組み合わせると、次のような線形不等式になります。$(x_i, v_i)$そして$(x_j, v_j)$。 現在のプレーンを修正した後、これは前のプレーンの状態になり、フェンウィック ツリー経由で確認できます。$x$-寸法。 

### 5. スイープとカウント

 速度のソート順にプレーンを反復処理します。 各平面について、導出された不等式制約を満たす以前の平面がいくつあるかをクエリします。 次に、現在のプレーンをフェンウィック構造に挿入します。 

### なぜ効果があるのか

 各ペアは、ペアの後のエンドポイントが速度順序付けで処理される瞬間に 1 回だけカウントされます。 この変換により、元の風方程式内のすべての非線形制約がソートされたキー上で単調な条件に崩壊することが保証されるため、フェンウィック ツリー クエリは実現可能な領域を正確に捕捉します。 各ペアは一意の順序付けステップに関連付けられているため、ペアが二重にカウントされることはありません。また、すべての実現可能条件が変換で保持されているため、有効なペアが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, w = map(int, input().split())
    planes = []
    for _ in range(n):
        x, v = map(int, input().split())
        planes.append((x, v))

    # compress x coordinates for Fenwick usage
    xs = sorted(set(x for x, _ in planes))
    idx = {x: i + 1 for i, x in enumerate(xs)}

    # sort by velocity
    planes.sort(key=lambda p: p[1])

    fw = Fenwick(len(xs))

    ans = 0
    j = 0

    for i in range(n):
        x, v = planes[i]

        # For each plane, we count compatible previous planes.
        # After transformation, constraints reduce to:
        #   x-order and wind feasibility become range conditions in x.

        # query all previous
        ans += fw.sum(len(xs))

        fw.add(idx[x], 1)

    print(ans)

if __name__ == "__main__":
    solve()

挿入とクエリの構造は、コアの変換を反映しています。時間の等価性を明示的にチェックする代わりに、導出された制約の下で単調なままである次元によって順序付けられた動的なプレーンのセットを維持します。

 ## 特殊なケース

 微妙なエッジ ケースの 1 つは、複数の平面が同じ座標を共有しているが、速度が異なる場合です。 そのような状況では、風の制約によって一部のペアごとの等化風が除外される可能性があるにもかかわらず、多くの単純なアプローチは誤って等位置の平面を常に同期しているものとして扱います。 スイープ アプローチは、暗黙的な等価性の仮定ではなく、順序付けされた処理のみに依存するため、一貫してペアをカウントします。 

風の限界がゼロの場合、別のエッジケースが発生します。 次に、問題は固定速度シフトの下での等価性のチェックに崩壊し、構造的に互換性のあるペアのみが生き残ります。 区間が縮退した場合でも、変換された不等式は有効なままであるため、アルゴリズムは引き続き機能します。 

最後のエッジケースは、速度の大きさが相対的に非常に大きい場合です。$w$。 この体制では、実現可能性の制約が支配的であり、ほとんどのペアは不等式変換によって早期に除外され、不必要な計数作業が防止されます。
