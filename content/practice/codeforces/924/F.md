 ## 解決策

 ## 問題の理解

 この問題の各数値は、10 進数のレンズを通して表示されます。 与えられた整数について、すべての数字を抽出し、それらを 2 つのグループに分割しようとします。 スプリットの品質は、各グループの桁の合計の差によってのみ測定されます。 数値はしきい値として有効であるとみなされます$k$この差が超えないように桁を分割する方法が少なくとも 1 つ存在する場合$k$。 

クエリごとに範囲が与えられます。$[l, r]$そして値$k$, そして、その範囲内の整数がこの数字分割条件を満たす個数を数えなければなりません。 

この制約により、問題はすぐに全範囲にわたってクエリごとの桁 DP から遠ざけられます。 数値の上限に達しました$10^{18}$、これは最大 19 桁を意味します。 まであります$5 \cdot 10^4$したがって、クエリごとに個別に数字 DP を再計算したり、範囲にわたって反復したりするソリューションは、実行可能な限界をはるかに超えています。 平$O(10^{18})$不可能ですし、$O(n \cdot 10^6)$実際には大きすぎるでしょう。 

微妙な問題は、このプロパティが数字のみに依存することですが、数字のマルチセットは最大の数字の位置構造によって制約されることです。$r$、これは数字の DP を示唆します。 ただし、この条件自体は数字の境界分割問題に帰着し、単純な数値不変式で表現できることが判明します。 

1 桁および 2 桁の番号では、キー エッジ ケースが表示されます。 1 桁の数値の場合、分割は自明であり、条件は桁の値に直接依存します。 2 桁の数値の場合、条件は桁の違いの比較に限定されるため、小さなケースを一貫して処理せずに急いで一般化しようとするソリューションは誤解を招く可能性があります。 もう 1 つの微妙なケースは、100 のような数字です。この場合、ゼロの存在により、達成可能なサブセットの合計が、ゼロ以外の数字に基づく直感とは異なる方法で変化します。 

## アプローチ

 ブルートフォース手法では、各数値が個別に評価されます。 数字の場合$x$、その数字を抽出し、各数字の 2 つのグループのいずれかへの可能なすべての割り当てを試みます。 もし$x$もっている$d$数字、あります$2^d$課題。 割り当てごとに、グループの合計の差を計算し、それが最大かどうかを確認します。$k$。 以来$d \le 19$、これは、最悪の場合でも、1 つの番号につき最大で約 50 万回の操作になります。 以上$10^{18}$範囲内の数値を指定する場合、単一のクエリであってもこれは不可能です。 

重要な観察は、私たちが扱っているのは任意の数値ではなく、次から抽出された数字であるということです。$\{0,\dots,9\}$。 条件は、最大でも誤差以内に合計桁の合計のおよそ半分に桁を分割できるかどうかによって決まります。$k$。 桁の和を次のようにします$S$。 数字を 2 つのサブセットに分割することは、合計を使用してサブセットを選択することと同じです。$T$違いを生む$|S - 2T|$。 私たちが欲しいのは$|S - 2T| \le k$、または同等の$T$周囲の間隔になければなりません$S/2$。 

そこで問題は、次のとおりです: の半分に十分近い桁のサブセット和を形成できるか?$S$? 桁が小さく最大 19 個であるため、合計は最大でも$9 \cdot 19 = 171$。 この制限された合計空間により、唯一の関連する状態が現在の桁の合計とその半分にどれだけ近づくことができるかという桁 DP が可能になります。 

したがって、考えられる各桁マルチセットについて、それが各桁に対して有効かどうかを事前計算します。$k \in [0,9]$。 数字を列挙する代わりに、数字の接頭辞に数字 DP を使用します。$10^{18}$、残りの柔軟性を追跡し、桁の合計を蓄積します。 実現可能性はその桁マルチ​​セット内の達成可能なサブセット合計にのみ依存するため、DP 状態には位置、タイト フラグ、および現在の累積桁合計のみが必要です。 

関数を計算したら$F(x, k)$有効な数値を次まで数えます$x$、各クエリは次のようになります。$F(r, k) - F(l-1, k)$。 

重要な構造の単純化は、定義が数字に対するサブセット DP を示唆している一方で、小さな桁の範囲によって複雑さが解消され、境界のあるサブセット合計の実行可能性チェックと組み合わせた数値に対する数字 DP が扱いやすくなることです。

 ## アルゴリズムのチュートリアル

 1. 圧縮形式で考えられる各桁マルチセット署名を生成する数値が、指定された制限までにいくつあるかをカウントする桁 DP テーブルを事前計算します。 実現可能性チェックはこれらの集計値のみに依存するため、圧縮は実行中の桁の合計と位置のみを追跡することによって行われます。 
2. 数字ごとに$x$、10 進表現に対して数字 DP を実行します。 各位置で、プレフィックスがまだタイトであるかどうかを維持しながら桁を決定します。$x$。 範囲内のすべての数値を列挙するのではなく効率的にカウントする必要があるため、この手順が必要です。 
3. DP 内の完成した数値状態ごとに、桁の合計を計算します。$S$。 パーティションを列挙する代わりに、サブセット合計が存在するかどうかを判断します$T$そのような$|S - 2T| \le k$。 これは、数値を超えた制限されたナップザック スタイルの到達可能性を使用してチェックされますが、最大合計は 171 のみであるため、これは 1 回だけ事前計算できます。 
4. 桁 DP カウントと実現可能性検索を組み合わせます。完全な数値が形成されるたびに、事前に計算された実現可能性テーブルが指定された条件に対して有効であることが示されている場合にのみ、その構成のカウントが増加します。$k$。 
5. 間の接頭辞の減算を使用して各クエリに答えます。$r$そして$l-1$、各範囲クエリが 2 つの DP 評価に確実に削減されます。 

正確性は、すべての DP 状態が固定プレフィックスを持つ数値のセットを正確に表すという不変条件に依存し、実現可能性は最終的な数値の複数の桁セットにのみ依存します。 桁の順序はサブセット合計の実現可能性に影響を与えないため、桁の合計によって状態を折りたたむと正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute feasibility: can we partition digits with sum S
# so that difference <= k for k in [0..9]?
# We precompute subset sums up to max possible digit sum (171)

MAX_SUM = 9 * 19

# dp[s][t] = can we reach subset sum t using digits processed so far
dp = [[False] * (MAX_SUM + 1) for _ in range(MAX_SUM + 1)]
dp[0][0] = True

for digit in range(10):
    new_dp = [row[:] for row in dp]
    for s in range(MAX_SUM - digit + 1):
        for t in range(s + 1):
            if dp[s][t]:
                new_dp[s + digit][t + digit] = True
                new_dp[s + digit][t] = True
    dp = new_dp

# ok[s][k] = whether there exists subset sum t with |s - 2t| <= k
ok = [[False] * 10 for _ in range(MAX_SUM + 1)]

for s in range(MAX_SUM + 1):
    for t in range(s + 1):
        diff = abs(s - 2 * t)
        for k in range(10):
            if diff <= k:
                ok[s][k] = True

from functools import lru_cache

def count_upto(x, k):
    s = str(x)

    @lru_cache(None)
    def dfs(pos, tight, sum_digits):
        if pos == len(s):
            return 1 if ok[sum_digits][k] else 0

        limit = int(s[pos]) if tight else 9
        res = 0
        for d in range(limit + 1):
            res += dfs(pos + 1, tight and d == limit, sum_digits + d)
        return res

    return dfs(0, True, 0)

n = int(input())
for _ in range(n):
    l, r, k = map(int, input().split())
    print(count_upto(r, k) - count_upto(l - 1, k))
```桁分割条件は桁の順序ではなく合計桁合計のみに依存するため、サブセット合計に対する DP はクエリとは独立して 1 回構築されます。 次に、DFS 桁 DP は、桁の合計を累積しながら、境界まですべての数値を列挙します。 メモ化キーには位置、厳密さ、現在の桁の合計が含まれており、重複するプレフィックスにわたる再計算を防ぎます。 

微妙な点は、範囲クエリで減算を使用していることです。 以来`count_upto`ゼロを含む、`l - 1`次の場合には慎重に取り扱う必要があります`l = 1`ただし、完全な実装で適切に保護されていれば、関数は非正の入力に対して当然ゼロを返します。

 ## 特殊なケース

 1 桁の数字は、パーティションの基本的な動作を明らかにします。 任意の桁の場合$d$、唯一考えられるパーティションの違いは次のとおりです。$d$、したがって、有効性は次のように減少します。$d \le k$。 端末の状態がチェックされるため、DP はこれを自然に処理します。`ok[d][k]`、この条件を正確に反映するように事前に計算されます。 

10 ～ 99 のような数字は、桁の順序が重要かどうかをテストします。 DP は、桁の合計に関して 10 と 01 を同等に扱いますが、実現可能性はマルチセットにのみ依存するため、次の場合には両方が有効です。$|a-b| \le k$。 数字 DP により、両方のプレフィックスが個別に調査されることが保証されます。 

100 などのゼロを含む数値は、末尾のゼロと内部のゼロがサブセットの合計構造を歪めないことを確認します。 桁の合計は安定しており、実現可能性は事前計算されたテーブルに正しく取り込まれた非ゼロの桁にのみ依存します。
