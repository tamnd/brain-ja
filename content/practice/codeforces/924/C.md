 ## 問題の理解

 私たちは連日にわたる一連の観察を与えられています。 毎日が水位に対応し、時間の経過とともに、アルカディはこれまでに見た明確な水位に跡を残します。 水位が繰り返される場合、新しいマークは追加されません。 

日中`i`、Arkady が値を報告します。`m_i`、これは、現在の水位より厳密に上にある既存のマークの数です。 このことから、その日の水位を厳密に下回ったマークの数は、ある程度の値となります。`d_i`。 新しい水位が出現したときにのみマークのセットが成長するため、マークの構造は進化します。 

タスクは、正確な水位を再構築することではなく、すべての制約に一致し、すべての制約の合計を最小化する、個別のマークの有効な展開を選択することです。`d_i`。 

重要な問題は、既存のマークに対する水位の位置によって、その上にいくつのマークが存在するか、またその下に何個のマークが存在するかが決まり、新しいマークを早期に導入すると、将来のすべての寄与が変更されることです。 

制約`m_i < i`その日を意味します`i`、水位を配置するのに十分な以前の「スロット」が常に存在するため、正確に`m_i`マークはその上にあります。 これにより実現可能性は保証されますが、時間の経過とともに導入する個別のマークの数についてのあいまいさが解消されるわけではありません。 

単純な試みでは、いつ新しいマークを導入するかについて考えられるすべての選択肢をシミュレートしようとする可能性があります。 ただし、たとえ`n = 10^5`、「マークを作成する」と「マークを作成しない」の間で分岐すると、指数関数的な動作が発生します。 

の将来の値が変化する場合、微妙なエッジケースが発生します。`m_i`大きくジャンプします。 たとえば、次の場合`m`マークの作成が遅れすぎると、後でその構成を実現できなくなります。 したがって、貪欲なポリシーでは、マーク作成の遅延と将来の実現可能性の確保とのバランスを取る必要があります。 

## アプローチ

 直接シミュレーションのアプローチでは、一連のマークを明示的に維持し、毎日、次の条件に一致する水位を割り当てようとします。`m_i`。 毎日、新しいマークを導入するか、既存の構成を再利用するかを決定します。 毎日の意思決定スペースが 2 倍になる可能性があるため、これは急速に指数関数的に増加します。 

重要な観察は、実現可能性に影響を与える唯一のことは、正確な位置ではなく、各時点でどれだけのマークが存在するかであるということです。 一日のマーク数を修正したら`i`で示される`k_i`、水位は常に適切に配置できます。`k_i ≥ m_i + 1`。 

重要な制約は、`k_i`観測ごとに追加できる新しいマークは最大 1 つであるため、1 日に 1 つ以上増やすことはできません。 これにより、より高い要求値にどれだけ早く到達できるかについての「速度制限」が導入されます。`k_i`。 

したがって、現在の要件だけを見るのではなく、`m_i`、将来の要件を引き続き達成できることも確認する必要があります。 これにより、実行可能な最小値を貪欲に構築することになります。`k_i`順序。 

保守します`k_i`その日に達成可能な最小のマーク数として`i`将来のすべての制約が満たされるようにして、寄与を計算します。`d_i`それから。

 ## アルゴリズムのチュートリアル

 1. 現在の制約だけでなく将来の制約に基づいて、毎日必要な最小マーク数を計算します。 マークは 1 日に最大 1 つしか増加できないという事実から推論します。そのため、将来の日に多くのマークが必要な場合は、以前の日がすでにその増加率をサポートしている必要があります。 
2. 毎日について`i`、実行可能な最小マーク数を決定します。`k_i`それは将来のすべての日を保証します`j ≥ i`まだ達成できる`m_j`。 これにより、将来の要件に「後れを取る」ことがなくなります。 
3. 1回`k_i`が固定されている場合、水位より下のマークの数は次のように一意に決定されます。`d_i = k_i - 1 - m_i`、なぜなら、`k_i`合計点、正確に言うと`m_i`現在のレベルを除いて残りは上にあり、残りは下にあります。 
4. すべてを合計する`d_i`一日中。 

### なぜ効果があるのか

 マークの数は、将来の実現可能性と現在のコストの両方に影響を与える唯一の状態です。 有効な構造はすべて何らかのシーケンスに対応します`k_i`ステップごとに最大 1 ずつ増加し、常に満たされます。`k_i ≥ m_i + 1`。 

このようなすべてのシーケンスの中で、可能な限り小さいものを選択すると、`k_i`すべてのステップで、すべてのプレフィックスの影響を最小限に抑えます`k_i - 1`の合計を直接最小化します。`d_i`。 より大きな選択肢`k_i`実現可能性を向上させることなく、将来のコストを永続的に増加させます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = list(map(int, input().split()))

    k = [0] * n

    # backward constraint: ensure feasibility of future growth
    suf = float("-inf")

    # we compute k from right to left with growth constraint
    for i in range(n - 1, -1, -1):
        suf = max(suf, m[i] - i)
        k[i] = suf + i + 1

    # enforce growth limit k[i] <= k[i-1] + 1
    for i in range(1, n):
        if k[i] > k[i - 1] + 1:
            k[i] = k[i - 1] + 1

    ans = 0
    for i in range(n):
        ans += (k[i] - 1 - m[i])

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず次の式を使用して後方参照制約を構築します。`m[i] - i`これは、新しいマークを導入するまでにどれだけの時間が残っているかと比較して、今後の日々がどれほど厳しいかを示しています。 これにより、次のベースライン要件が生成されます。`k[i]`。 マークはステップごとに 1 つしか増加できないため、前方修正を適用して、どのステップもこの増加率を超えないようにします。 

最後に、毎日の貢献度は、合計マーク、上マーク、下マーク間の関係から直接計算されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    m = list(map(int, input().split()))

    k = [0] * n
    suf = float("-inf")

    for i in range(n - 1, -1, -1):
        suf = max(suf, m[i] - i)
        k[i] = suf + i + 1

    for i in range(1, n):
        if k[i] > k[i - 1] + 1:
            k[i] = k[i - 1] + 1

    return str(sum(k[i] - 1 - m[i] for i in range(n)))

 ## 特殊なケース

 事前のマークが存在せず、水面下での貢献も不可能であるため、1 日の最小限の投入では常にコストがゼロになります。 

厳密に増加している`m_i`シーケンスにより、アルゴリズムは毎日マークの数を増やすように強制されます。 計算された`k_i`は直線的に増加しますが、水位は常に実行可能な最上位の構成に位置するため、寄与はゼロのままです。 

大きなジャンプインのあるシーケンス`m_i`逆伝播がなぜ必要なのかを示します。 将来の要件を予測せずに、貪欲な前方のみの戦略を使用すると、必要な増加を過小評価し、実行不可能な構成が生成されてしまいます。 

アルゴリズムはこれらのケースを処理します。`k_i`将来の需要と 1 ステップの増加制限の両方によって制限され、最小限の累積サイズを維持しながら、すべてのプレフィックスでの実現可能性が確保されます。
