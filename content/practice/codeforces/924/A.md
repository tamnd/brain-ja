 ## 解決策

 ## 問題の理解

 グリッドは完全に空から始まり、黒と白のセルの最終パターンが与えられます。 黒のセルを作成するプロセスは、任意の描画ではなく、構造化された操作です。各操作では、いくつかの行といくつかの列が選択され、選択された行と列の間のすべての交差点が描画されます。 つまり、1 つの操作で、選択された行と列の間の完全な長方形の外積が常に生成されます。 

構造を厳格にする追加の制限があります。 各行と各列は、全体で最大 1 つの操作に参加できます。 したがって、行が 1 つの操作で使用されると、他の操作に寄与することはできなくなり、同じことが列にも独立して当てはまります。 これにより、構築は一連の独立した塗装ステップではなく、分割の問題に変わります。 

タスクは、特定の白黒グリッドがそのような操作の有効なセットによって生成されたかどうかを判断することです。 

制約は小さく、どちらの次元も最大 50 です。これは、二次関数付近の解決策、またはチェックごとにわずかに悪い解決策で十分であることをすぐに示唆しています。 演算の構造には高度な制約があるため、すべてのサブセットにわたる組み合わせ論や演算のバックトラックは必要ありません。 

ローカルで考えると微妙な問題が見えてきます。 素朴な直感では、各黒セルは独立して処理できる、または黒セルが表示される場所に基づいて行または列を貪欲にグループ化できると思われるかもしれません。 依存関係が共有行と列を介して循環を形成する場合、これは失敗します。 

たとえば、行 1 が列 1 および列 2 と黒のセルを共有し、行 2 もそれらの列と相互作用する構成を考えてみましょう。 貪欲なグループ化により、それらの一部が誤ってマージされ、ターゲット グリッドに存在しない余分な黒いセルが強制的に作成される可能性があります。 

もう 1 つの失敗例は、グリッド内の各黒の連結コンポーネントだけで十分であると想定することから生じます。 操作により完全なデカルト積が生成されるため、ここでは接続性だけでは十分ではありません。 2 つの行と 2 つの列が同じ操作に属する場合、4 つの交点はすべて黒でなければなりません。 たとえすべてが他の黒いセルを介して接続されていたとしても、そのうちの 1 つでも白い場合、構造は壊れます。 

したがって、本当の困難は到達可能性ではなく、すべての暗黙の四角形が完全に塗りつぶされるように強制することです。 

## アプローチ

 ブルートフォース解釈では、操作を直接推測しようとします。 各操作は行のサブセットと列のサブセットによって定義され、これらのサブセットは操作間で互いに素である必要があります。 このようなパーティションをすべて試すことは、実行可能な限界をはるかに超えています。行だけをグループに割り当てるだけでも指数関数的であり、列もグループに合わせて調整する必要があるからです。 

重要な簡素化は、操作効果を再構成することで実現します。 操作という観点から考えるのではなく、すべての操作によってルールが作成されることがわかります。行セット内のすべての行は、その列セット内のすべての列に対して同じように動作します。 特に、少なくとも 1 つの黒いセルに一緒に表示される行と列は、同じ非表示操作インデックスに属している必要があります。 

これは統一のアイデアを示唆しています。 各行と各列を単一の構造内のノードとして扱います。 セルが黒の場合は常に、その行と列が同じグループに属するように強制されます。 つまり、共用体構造を使用してそれらをマージできるということです。 すべての黒いセルを処理した後、すべての連結成分が潜在的な操作ラベルを表します。

次に、この構造が誤って黒セルを過剰に生成しないことを確認する必要があります。 2 つのノードが同じコンポーネント内にある場合、それらは同じ操作に属しているものとして扱われます。これは、コンポーネント内のすべての行と列のペアが黒になることを意味します。 したがって、行と列が同じコンポーネント内にある白いセルが存在する場合、構造により誤ってそのセルが黒に設定されてしまいます。 それが実現可能性を侵害する唯一の方法です。 

したがって、チェック全体は、黒のセルから接続されたコンポーネントを構築し、単一のコンポーネント ペア内に白のセルが存在しないことを検証することになります。 

この変換により、複雑な組み合わせプロセスが、2 部構成の Union-Find 構造に対する一貫性チェックに縮小されます。

 | --- | --- | --- | --- |
 | 操作に対するブルートフォース | 指数 | 指数 | 遅すぎる |
 | Union-Find の整合性チェック | O(nm α(n+m)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての行とすべての列を、union-find 構造内の個別のノードとしてモデル化します。 行には 0 から n-1 のインデックスが付けられ、列には n から n+m-1 のインデックスが付けられるため、同じ DSU 内に存在します。 

1. n + m ノード上で DSU を初期化し、最初は各行と列を独自のコンポーネントとして扱います。 これは、制約がまだ適用されていないことを表します。 
2. グリッド内のすべてのセルをスキャンします。 セル (i, j) が黒の場合、DSU で行 i と列 j + n をマージします。 これにより、この黒いセルを生成する操作には両方のエンドポイントが含まれる必要があり、同じ非表示ラベルを共有する必要があります。 
3. すべての結合が処理された後、グリッドを再度スキャンします。 すべての白いセル (i、j) について、行 i と列 j + n が同じ DSU コンポーネントに属しているかどうかを確認します。 そうなった場合は、有効な構造ではセルが強制的に黒になるため、すぐに不可能に戻ります。 
4. この条件に違反する白セルがない場合は、返品可能です。 

これが機能する理由は、黒いセルが行と列の間の等式制約を定義し、union-find がそれらの等式の推移閉包を計算するためです。 一貫した演算の割り当ては、これらの等価性を尊重する必要があります。 等式が修正されると、各コンポーネントは単一の原子ラベルのように動作します。 残りの唯一の要件は、白セルを単一の原子ブロック内に強制的に配置しないことです。これはターゲット グリッドと矛盾するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    dsu = DSU(n + m)

    def row(i):
        return i

    def col(j):
        return n + j

    for i in range(n):
        for j in range(m):
            if g[i][j] == '#':
                dsu.union(row(i), col(j))

    for i in range(n):
        for j in range(m):
            if g[i][j] == '.':
                if dsu.find(row(i)) == dsu.find(col(j)):
                    print("No")
                    return

    print("Yes")

if __name__ == "__main__":
    solve()
```DSU は、黒セルによって引き起こされる行と列の同一性を崩壊させるために使用されます。 列のマッピング関数は、行と列が衝突することなく 1 つの構造内に存在するように、インデックスを n だけオフセットします。 2 番目のパスは、明示的に何かを構築するのではなく矛盾をチェックするため、不可欠です。 

よくある間違いは、黒のセルだけを結合して、すぐに有効であるとみなしてしまうことです。 これにより、結合によってグリッドに存在しない余分な黒セルが暗黙的に強制されるケースが見逃されます。

 ## 特殊なケース

 主なエッジ ケースは、黒いセルによってすべての行と列が 1 つのコンポーネントに強制的に組み込まれるが、1 つの白いセルが残る場合です。 その状況では、DSU はすべてを折りたたみ、白いチェックは両方のエンドポイントが同じコンポーネント内にあることを即座に検出し、グリッドを正しく拒否します。 

もう 1 つのケースは、黒セルがまったくない場合です。 DSU は完全に分離されたままであり、結合は発生しません。 強制的な同じコンポーネントのペアに白セルを含めることはできないため、答えは自明に有効であり、操作がゼロであることに対応します。 

3 番目のケースは、黒セルが複数の切断された領域を形成し、それらが交互の行と列の関係によって偶然接続される場合です。 DSU はこれを自然に処理します。これは、任意のパスを介した接続によってコンポーネントがマージされ、グリッド内で明示的でない場合でも、隠れた推移的制約が確実に尊重されるためです。
