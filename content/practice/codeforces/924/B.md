 ## 問題の理解

 私たちには、厳密に増加する一連のエネルギーレベルが与えられています。 3 つのインデックスを選択する必要があります$i < j < k$そしてそれらを、有効エネルギーと消費エネルギーの比率を生み出す 3 段階の物理プロセスとして解釈します。 

このプロセスは、選択した値の違いのみに依存します。 消費されたエネルギーは、$i$に$k$、一方、有用なエネルギーはからの放出です。$k$まで$j$。 したがって、効率は次のようになります。$$\eta = \frac{E_k - E_j}{E_k - E_i}.$$追加の制約があります。それは、合計ジャンプ量です。$i$に$k$超えることはできません$U$、 それで$E_k - E_i \le U$。 有効なトリプルが存在しない場合、答えは次のようになります。$-1$。 

この構造は単調な値を持つ純粋に 1 次元であり、有効な最適解は任意の組み合わせの選択ではなく間隔の観点から推論できることを示唆しています。 難しいのは、スライド距離の制約の下ですべてのトリプルにわたる比率を最適化していることです。 

制約は大きく、最大で$10^5$状態なので、どれでも$O(n^2)$あるいは最悪の場合、アプローチが遅すぎます。 解決策は本質的に線形または線形でなければなりません。 これは、有効な移動ウィンドウを維持することを直ちに示唆します。$k$それぞれの候補者$i$そしてそのウィンドウ内で最良のものを選択します$j$効率的に。 

微妙なエッジ ケースは、配列が相対的に「まばら」すぎる場合です。$U$、トリプルは不可能になります。 たとえば、次の場合$n = 3$、$E = [1, 100, 200]$、 そして$U = 50$、その場合はペアがありません$i,k$満足する$E_k - E_i \le U$、したがって、答えは次のようになります。$-1$。 トリプルの存在を前提とした不用意な解決策は、無意味な比やゼロ除算を生成します。 

もう 1 つの故障モードは数値の不安定性です。 答えは整数ではなく比率であるため、注意深い最大化ロジックを使用せずに浮動小数点演算で繰り返し再計算すると、精度の問題が発生します。 

## アプローチ

 ブルートフォースメソッドはすべてのトリプルを列挙します$i < j < k$、どうかをチェックします$E_k - E_i \le U$、比率を計算します。 これは、定義を直接評価するため、正しいです。 ただし、費用がかかります$O(n^3)$が遅すぎます。$n = 10^5$。 修正にまで減らしても$i$そして$k$そしてスキャン$j$与える$O(n^2)$、まだ無理です。 

重要な観察は、固定された$i$そして$k$、 最高の$j$を最大化することによってのみ決定されます$E_j$下$i < j < k$、分子が$E_k - E_j$。 比率を最大化するには、最小化する必要があります。$E_j$スパンに対して相対的ですが、依存関係は部分的であり、簡単には線形ではありません。 

式を書き直すと次のことが役立ちます。$$\eta = \frac{E_k - E_j}{E_k - E_i} = 1 - \frac{E_j - E_i}{E_k - E_i}.$$固定用$i,k$、効率を最大化することは最小化することと同じです。$E_j$。 しかし、$j$それらの間に厳密に存在しなければなりません。 したがって、各間隔ごとに$(i,k)$、内部では最小の値が必要です。 

これにより、問題が 2 ポインタ構造に変わります。修正します。$i$、 拡大する$k$尊重しながら$E_k - E_i \le U$、最小値を追跡できるデータ構造 (または単調観測) を維持します。$E_j$中部地域にある。 配列は増加しているため、どのセグメントでも最小値は常にその左端にあります。$i,k$、 最高の$j$単純に$i+1$。 これにより問題が大幅に軽減されます。 

したがって、それぞれについて$i$、および有効なそれぞれについて$k$、確認するだけで済みます$j = i+1$、比率は次のようになります。$$\frac{E_k - E_{i+1}}{E_k - E_i}.$$ここで必要なのは、有効なスライディング ウィンドウを維持することだけです。$k$値を設定し、この式を効率的に評価します。

 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左側のエンドポイントを修正します$i$最小のインデックスから始まります。 これにより、すべてのトリプルが左境界の昇順に考慮されるようになります。 
2. ポインタを維持する$k$それは前に進むだけです。 それぞれについて$i$、 伸ばす$k$満足できる限り$E_k - E_i \le U$。 これにより、有効な正しいエンドポイントのみを考慮することが保証されます。 
3. 固定ペアごとに$(i, k)$、最適な中間状態を決定します。 エネルギーは厳密に増加しているため、有効な最小値は$E_j$のために$i < j < k$いつもいる$j = i+1$、 提供された$k \ge i+2$。 これにより、内部のスキャンを回避できます。 
4. 効率候補を計算します。$$\eta = \frac{E_k - E_{i+1}}{E_k - E_i}.$$次の場合にのみ評価します$k \ge i+2$3 つの異なるインデックスが必要であるためです。 
5. すべての有効な構成にわたる最大値を追跡します。 設定が存在しない場合は戻ります$-1$。 

### なぜ効果があるのか

 固定の場合$i$そして$k$、分母$E_k - E_i$は一定です。 分子$E_k - E_j$最大化されるのは$E_j$最小化されます。 配列は厳密に増加しているため、可能な限り小さい$E_j$で$(i,k)$いつもです$E_{i+1}$。 したがって、インテリアの選択はありません$j$その上$i+1$比率を向上させることができ、この候補のみをチェックすることで最適性が維持されます。 

スライド ポインタ$k$すべての有効な間隔が 1 回だけ考慮されることを保証し、配列の単調性により後方移動のスキップの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, U = map(int, input().split())
    E = list(map(int, input().split()))

    ans = -1.0
    k = 0

    for i in range(n):
        if k < i + 2:
            k = i + 2

        while k < n and E[k] - E[i] <= U:
            if i + 1 < k:
                val = (E[k] - E[i + 1]) / (E[k] - E[i])
                if val > ans:
                    ans = val
            k += 1

        # step back one because k is now invalid or out of range
        # but k only moves forward globally, so no reset needed

    if ans < 0:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```実装では、グローバル ポインターを使用した単一パスを使用します。$k$決して後戻りすることがないため、直線的な複雑さが保証されます。 重要な点は、次の場合にのみ候補者を評価するということです。$k$有効であり、$i+1 < k$、3 つの異なるインデックスを保証します。 

微妙な点は、リセットしないことです。$k$それぞれに$i$。 増えるのでこれは安全です$i$制約を強化するだけです$E_k - E_i \le U$、したがって、以前に有効だったものは$k$有効な開始点のままであるか、すでに大きすぎます。 これにより、償却されたリニア スキャンが維持されます。

 ## 特殊なケース

 いつ$n = 3$、可能なトリプルは 1 つだけです。 ループは次の場合にのみ評価するため、アルゴリズムは依然として正しく動作します。$k = 2$、およびチェック$i = 0$、制約が許可する場合は有効な比率が生成されます。 

どのペアも満たさない場合$E_k - E_i \le U$、ポインタ$k$常に有効範囲を超えて進み、`ans`残っている$-1$。 これにより、不可能なケースが正しくトリガーされます。 

値が非常に近い場合、浮動小数点の精度が重要になります。 このアルゴリズムは候補ごとに 1 つの除算のみを実行し、累積誤差を最小限に抑え、必要な範囲内に留まります。$10^{-9}$許容範囲。
