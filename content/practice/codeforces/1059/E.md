 ## 解決策
 ## 問題の理解

 すべての頂点に正の重みが含まれる根付きツリーが与えられます。 タスクは、すべての頂点を最小数の垂直パスに分割することです。 垂直パスは、常にノードからその子の 1 つに移動するチェーンです。この定式化では、親リンクを介してノードからルート方向に上向きに移動します。 

各パスは 2 つの制約を同時に満たさなければなりません。 その長さは指定された制限を超えることはできません$L$、パス内のすべての頂点の重みの合計は次を超えることはできません。$S$。 すべての頂点は 1 つのパスに属している必要があるため、パスを選択するのではなく、ツリー全体を分解します。 

重要な問題は、パスが構造と蓄積された重量の両方によって制約されることです。 ツリー構造を無視すると、これは順序付け制約のあるビン パッキングに似ています。 重みを無視すると、深さの制限の問題になります。 深さと合計の相互作用により、慎重な構築が必要になります。 

この制約は、$O(n \log n)$または$O(n)$解決策が必要です。 と$n \le 10^5$、各候補分解の実現可能性を個別に再計算しようとするアプローチは失敗します。 平$O(n^2)$パスまたはノードを介した戦略は直ちに除外されます。 

いくつかの特殊なケースでは、よくある落とし穴が明らかになります。 

最初の障害モードは、パスの貪欲な拡張が深さを無視した場合に発生します。 たとえば、次の場合$L = 2$そして、合計が許す限り 3 つのノードのチェーンを拡張しようとすると、たとえ重みが適切であっても、構造的に無効なパスを形成してしまう可能性があります。 

2 番目の障害モードは、ツリーの依存関係を完全に無視することです。 星型ツリーでは、ノードを独立して扱うと、垂直方向のパスが不可能になります。これは、すべてのリーフがルートを介して接続する必要があり、ルートの容量がボトルネックになるためです。 

3 番目の障害モードは、ノードの重みが次の値よりも大きい場合に発生します。$S$。 その場合、答えは即座に不可能ですが、多くの実装はこの初期の拒否を忘れて、間違った処理を進めます。 

## アプローチ

 素朴な考えは、ルートからリーフへの各チェーンを独立して扱い、それを両方の制約を満たすセグメントに貪欲に分割することです。 これにより、有効な垂直パスがすでに生成されています。これは、垂直パスはルートからリーフへのトラバーサルのサブチェーンであるためです。 ただし、これは重要な相互作用を無視しています。つまり、ルート近くの共有プレフィックスを慎重に再利用することによってのみ、異なるブランチ間でパスを再利用できます。 

代わりにローカルに考えると、パスを拡張しても制約が破られない限り、各ノードはその祖先のアクティブなパスの 1 つに接続されることを望みます。 これは、貪欲な戦略を示唆しています。つまり、すべてのノードについて、そのサブツリー内に必要な有効なパスの数を維持し、子パスを上向きの親パスにマージしようとするというものです。 

重要な洞察は、ノードをリーフから上に処理するときに、各ノードはその子からの「開いた」パスをいくつ延長できるかを考慮するだけでよいということです。 各ノードでは、残りの長さと残りの合計容量の両方を考慮して、できるだけ多くの子パスを単一の上向きパスにマージしようとします。 残ったパスは、そのノードから始まる最終的なセグメントになります。 

これにより、問題はツリー DP に縮小され、各ノードがその下で開始する必要があるパスの数と、最適な上向き拡張にどれだけの容量が残っているかを計算します。 

長さと合計の両方に対する制約は単調に動作します。つまり、パスを拡張すると、残りの長さと残りの合計の両方が常に減少します。 これにより、後戻りすることなく子コントリビューションを貪欲にマージできます。

 | 貪欲なマージを使用したツリー DP |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 子が親の前に完全に解決されるように、ツリーをポストオーダー方式で処理します。 

1. 各ノードについて、そのサブツリー内に必要な垂直パスの数を計算し、このノードを通って上向きに来る単一の「最適な拡張可能なパス」も追跡します。 このパスは、まだ開いており、親に拡張できるチェーンを表します。 
2. すべてのノードについて、まずその子からのすべての拡張可能なパスを収集します。 このような各パスには、残りの許容長と残りの許容合計という 2 つの情報が含まれます。 
3. できるだけ多くの子パスを、現在のノードを通過する 1 つのパスにマージしようとします。 私たちはこれを貪欲に実行し、常に最も「有用な」拡張機能、通常は最も残存容量が多い拡張機能を優先します。 直感的には、最も強力なパスを維持すると、将来のマージの可能性が最大化されるということです。 
4. 選択したメイン パスにマージできないすべての子パスが確定されます。 ファイナライズとは、最上位のエンドポイントが現在のノードまたはその下にある別の垂直パスになることを意味します。 
5. マージ後、長さの 1 単位を消費し、ノードの重みを追加することにより、現在のノードで上向きのパスを作成または更新します。 これがいずれかの制約に違反する場合、このパスはそれ以上拡張できず、ここで最終決定する必要があります。 
6. 答えは、すべてのノードにわたる最終的なパスの数を累積します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのノードで上向きの拡張可能なパスを最大 1 つ保存し、そのサブツリー内の他のすべての候補パスがすでにこのノードの下またはこのノードで最適に終了していることです。 有効なグローバル ソリューションは、パスの数を増やすことなくこの構造に変換できます。ノードを通過する複数の上向きパスのうち、それらを早期にマージしても実現可能性が損なわれることはなく、将来の柔軟性が低下することもないためです。 

これは本質的にツリーに関する貪欲な統合の議論です。すべての制約は拡張下では単調であるため、マージを遅らせても実現可能性は向上しません。そのため、ローカルで最適なマージはグローバルに最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, L, S = map(int, input().split())
w = [0] + list(map(int, input().split()))
parent = [0] * (n + 1)
children = [[] for _ in range(n + 1)]

for i in range(2, n + 1):
    p = int(input().split()[0])
    parent[i] = p
    children[p].append(i)

INF = 10**18

# dp[u] returns:
# (number of finished paths in subtree, (remaining_len, remaining_sum) for open path or None)
def dfs(u):
    total_paths = 0
    best = None  # (len_used, sum_used) represented as remaining capacity

    # collect all child contributions
    for v in children[u]:
        child_paths, child_open = dfs(v)
        total_paths += child_paths

        if child_open is None:
            continue

        # try to attach child open path to current candidate
        if best is None:
            best = child_open
        else:
            # greedily keep the one with more remaining capacity (lexicographic)
            if child_open[0] > best[0] or (child_open[0] == best[0] and child_open[1] > best[1]):
                # previous best becomes a finished path
                total_paths += 1
                best = child_open
            else:
                total_paths += 1

    if best is None:
        rem_len = L
        rem_sum = S
    else:
        rem_len, rem_sum = best

    # include current node
    rem_len -= 1
    rem_sum -= w[u]

    if rem_len < 0 or rem_sum < 0:
        total_paths += 1
        return total_paths, None

    return total_paths, (rem_len, rem_sum)

ans, open_path = dfs(1)

if open_path is not None:
    ans += 1

# check feasibility
if any(w[i] > S for i in range(1, n + 1)):
    print(-1)
else:
    print(ans)
```このコードは、ツリーに対してポストオーダー DFS を実行します。 各呼び出しは 2 つの情報を返します。そのサブツリー内のすでに完成したパスの数と、上向きに拡張できる部分的に構築された最大 1 つの垂直パスです。 

ループ内のマージ ステップにより、各ノードで候補パスが 1 つだけ残ることが保証されます。 2 人の候補者が競合すると、弱い方の候補者がすぐに完成したパスに閉じ込まれます。 これは、セグメントの最小数を強制するメカニズムです。 

子をマージした後、ノード自体が生き残ったパスに追加され、長さの 1 単位を消費し、残りの容量からその重みが減算されます。 これが制約に違反する場合、パスはこのノードで終了する必要があります。 

ルートでは、残っている開いたパスが最終セグメントとしてカウントされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, L, S = map(int, input().split())
    w = [0] + list(map(int, input().split()))
    parent = [[] for _ in range(n + 1)]
    for i in range(2, n + 1):
        p = int(input().split()[0])
        parent[p].append(i)

    sys.setrecursionlimit(10**7)

    INF = 10**18

    def dfs(u):
        total = 0
        best = None
        for v in parent[u]:
            c, o = dfs(v)
            total += c
            if o is None:
                continue
            if best is None:
                best = o
            else:
                if o > best:
                    total += 1
                    best = o
                else:
                    total += 1
        if best is None:
            rem = (L, S)
        else:
            rem = best
        rem = (rem[0] - 1, rem[1] - w[u])
        if rem[0] < 0 or rem[1] < 0:
            total += 1
            return total, None
        return total, rem

    ans, openp = dfs(1)
    if openp is not None:
        ans += 1

    if any(w[i] > S for i in range(1, n + 1)):
        return "-1"
    return str(ans)

1 2 3
1 1
""") == "3"

# all equal minimal

""") == "1"

""") == "-1"

 ## 特殊なケース

 より大きい重みを持つ単一ノード$S$即座に不可能を強います。 アルゴリズムでは、これはノードが処理されるときに捕捉され、初期化直後に残りの合計が負になり、最終的に -1 が生成されます。 

深い連鎖が起こる$L$一定の間隔で分裂する小さな力です。 各ノードは 1 単位の長さを消費するため、$L$開いたパスがステップごとに閉じます。 DFS は自然に正確に生成します。$\lceil n / L \rceil$制限を超えて上向きマージが存続しないためです。 

星型ツリーは、マージに関するすべての決定をルートに集中させます。 それぞれの葉は開いた道を作り出しますが、上向きに生き残ることができるのは 1 枚だけです。 残りはルート レベルで最終決定され、最も強力な残りのパスの貪欲な選択と一致します。
