 ## 解決策
 ## 問題の理解

 インク セルで構成されるターゲット描画を表すバイナリ グリッドが与えられます。 各セルはすでに塗りつぶされているか空になっており、この最終的なパターンが、特定のスタンピング ツールを使用して最初は空のグリッドから生成されたかどうかを判断したいと考えています。 

このツールは任意の形状をペイントしません。 代わりに、常に 3 × 3 の正方形の境界線が描画され、中央のセルはそのまま残ります。 すべてのアプリケーションはあるセルを中心としており、その 3 × 3 の近傍にある周囲の 8 つのセルを描画します。 センター自体は影響を受けません。 この操作は、完全な 3 x 3 ブロックがグリッド内にある場合にのみ使用できます。 

問題は、すべての空のセルから開始して、指定されたグリッドを正確に生成する一連のスタンプ操作が存在するかどうかです。 

グリッド サイズは最大 1000 x 1000、つまり最大 100 万個のセルにすることができます。 可能なすべての位置でスタンプをシミュレートし、単純な方法でグリッドを繰り返し更新しようとするソリューションは、各チェックにコストがかかると遅くなりすぎる危険があります。 したがって、各セルが一定の回数だけ処理されるか、少なくとも各潜在的なスタンプが一定の時間で評価される方法が必要です。 

有効なスタンプの境界に属する可能性のないインク セルが存在する場合、微妙な問題が発生します。 たとえば、単一の孤立した`#`ドットの海の真ん中にあるということは説明できません。なぜなら、すべてのスタンプが隣接する 8 つのスタンプの輪の中にペイントされるからです。 もう一つの問題のパターンは、`#`このセルは、どの 3 × 3 構成でもサポートされていません。つまり、有効な境界線の一部ではありません。 

素朴な推論における重要な故障モードは、すべての`#`何らかのスタンプの中心であるか、すべてのスタンプの中心である必要があります。`#`それ自体を直接ペイントする必要があります。 実際には、問題となるのは国境だけであり、適用範囲は複雑に重複する可能性があります。 

## アプローチ

 強引なアイデアは、スタンピングをシミュレートすることです。 3 x 3 ブロックの考えられるすべての中心に対して、ターゲット グリッドと矛盾しない場合はスタンプの適用を試み、ペイントするセルにマークを付けることができます。 考えられるすべての配置を試した後、結果としてペイントされたグリッドとターゲットを比較します。 

このアプローチは概念的には正しいですが、必要性を強制しないという弱点があります。 必要のないスタンプを適用する可能性があり、さらに悪いことに、スタンプがいくつかあるという事実を見逃してしまう可能性があります。`#`カバレッジ制約を注意深く確認しない限り、セルがカバーされることはありません。 最悪の場合、すべてのセルを潜在的なセンターとして検査し、センターごとに最大 9 個のセルを検査することになり、約 900 万回の手術が行われますが、これは境界線ではありますが、まだ管理可能です。 ただし、すべてのことを保証する必要があるため、正確性を保つのは難しくなります。`#`任意のスタンピングによって再現できるだけでなく、説明可能です。 

重要な洞察は、考え方を逆転させることです。 グリッドを前方に構築する代わりに、すべての`#`セルは、少なくとも 1 つの有効なスタンプの境界に属するものとして「位置調整」できます。 セルは、3 x 3 の境界パターン内に位置するようにその周囲に中心が存在する場合にのみペイントできます。 つまり、それぞれに`#`、それが有効な中心の上下左右の隣にあるかどうかを確認します。 そのようなセンターが存在しない場合、構成は不可能です。 

これにより、問題は各セルの周囲での局所的な実現可能性の検証に軽減されます。 考えられるすべての中心をスキャンし、どの境界細胞が生成できるかをマークし、すべての中心が存在することを確認します。`#`少なくとも 1 つの有効なスタンプ センターによってカバーされています。

 ## アルゴリズムのチュートリアル

 1. ブール値グリッドを作成します`good`これは、特定の位置を中心とする 3 x 3 スタンプが有効かどうかをマークします。 8 つの境界セルがすべて揃っている場合、中心は有効です。`#`。 これにより、スタンプを適用しても不正なドットが発生することがなくなります。 
2. 考えられるすべての中心を反復処理します`(i, j)`完全な 3 x 3 ブロックが収まる場所。 各中心について、周囲の 8 つの位置を確認します。 それらがすべてである場合`#`、このセンターを使用可能としてマークします。 
3. 別のブールグリッドを作成します`covered`入力グリッドと同じサイズで、最初はすべて false。 これにより、どのセルが少なくとも 1 つの有効なスタンプで説明できるかを追跡します。 
4. 有効なセンターごとに`(i, j)`で、その 8 つの境界セルをマークします。`covered`本当のように。 これは、このスタンプがそれらのセルにインクを与えた可能性があるという事実をシミュレートします。 
5. すべての中心を処理した後、グリッド全体を反復処理し、すべての中心をチェックします。`#`細胞。 もしあれば`#`はマークされていません`covered`の場合、有効なスタンプ構成では説明できないため、答えは NO です。 
6. もしすべてが`#`セルがカバーされている場合は、YES を返します。 

### なぜ効果があるのか

 重要な不変条件は、有効な最終的なすべての`#`セルは、中心がグリッド内にある少なくとも 1 つの 3 x 3 境界線の一部として説明可能でなければなりません。 有効な構造はそのようなスタンプのみで構成され、すべてのスタンプはその境界セルにのみインクを提供します。 したがって、セルが有効な境界線にない場合、一連のスタンプによってセルが生成されることはありません。 逆に、すべての場合、`#`少なくとも 1 つの有効な境界線内にある場合、重複が許可され、インクが削除されることがないため、スタンプを任意の順序で貪欲に割り当てることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]
    
    covered = [[False] * m for _ in range(n)]
    
    def ok(i, j):
        return (g[i-1][j-1] == '#' and g[i-1][j] == '#' and g[i-1][j+1] == '#' and
                g[i][j-1] == '#'                     and g[i][j+1] == '#' and
                g[i+1][j-1] == '#' and g[i+1][j] == '#' and g[i+1][j+1] == '#')
    
    for i in range(1, n - 1):
        for j in range(1, m - 1):
            if ok(i, j):
                covered[i-1][j-1] = True
                covered[i-1][j] = True
                covered[i-1][j+1] = True
                covered[i][j-1] = True
                covered[i][j+1] = True
                covered[i+1][j-1] = True
                covered[i+1][j] = True
                covered[i+1][j+1] = True
    
    for i in range(n):
        for j in range(m):
            if g[i][j] == '#' and not covered[i][j]:
                print("NO")
                return
    
    print("YES")

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`ok`スタンプが中央に配置されているかどうかをチェックする関数`(i, j)`有効です。 境界の中心は 3 x 3 のパターンを形成できないため、完全にグリッドの内側にある中心のみを考慮します。 

の`covered`マトリックスは、すべての有効なスタンプ センターからの到達可能性を追跡します。 それぞれの有効な中心は正確に 8 つの周囲のセルに寄与し、スタンピング ルールと正確に一致します。 最終スキャンにより、必要なインク セルがサポートされていない状態になることがなくなります。 

ここでは境界の処理が重要です。 ループが終わる`i in range(1, n-1)`そして`j in range(1, m-1)`3 x 3 ブロックをチェックするときに、範囲外の隣接ブロックにアクセスしないようにします。
