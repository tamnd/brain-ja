 ## 解決策
 ## 問題の理解

 平面内に一連の点が与えられ、それぞれが動物の位置を表します。 これらすべての点をカバーする円を配置する必要があります。 同時に、固定された水平方向の川があり、変換後はそれが X 軸になるため、ラインは次のようになります。$y = 0$。 

円は、単にすべての点をカバーするだけでなく、2 つの幾何学的制約を満たす必要があります。 まず、少なくとも一度は川に触れなければなりません。これは円の中心から線までの距離を意味します。$y = 0$最大でも半径でなければなりません。 第二に、円は複数の点で川と交差してはなりません。 円と線の場合、複数の共通点があるということは、線が円を横切ることを意味するため、中心から線までの距離は厳密に半径より小さくなければなりません。 両方の制約を組み合わせると、非常に特殊な構造が強制されます。つまり、円は X 軸に正接する必要があります。 

それでセンターは$(x, y)$満たさなければなりません$|y| = r$、円にはすべての点が含まれている必要があるため、すべての点が$(x_i, y_i)$以下を満たす必要があります:$$(x - x_i)^2 + (y - y_i)^2 \le r^2.$$以来$|y| = r$、問題は、離れたところにある水平線上の中心を見つけることになります。$r$最小化する X 軸から$r$全てのポイントを網羅しながら。 

入力サイズが到達しました$10^5$これは、すべてのペアの距離を再計算したり、点のペアごとに候補円を試行したりするものを即座に除外します。 どのようなソリューションでも、問題を少数の変数に対する単一の連続最適化に落とし込み、推測ごとに線形時間で評価する必要があります。 

すべての点が対称的に X 軸に非常に近くにある場合、微妙なエッジ ケースが発生します。 正しい解決策では、分布に応じて中心を上または下に配置する必要があるため、円の中心がすべての点の上または下に独立してあると仮定しようとする単純なアプローチは失敗する可能性があります。 

中心が重心の真上または真下にあると仮定すると、別の失敗ケースが発生します。 それは保証されません。最適な円は被覆と接線の両方によって制約されるため、x 座標と y 座標は相互作用します。 

## アプローチ

 ブルートフォース手法では、円の中心と半径を推測し、すべての点が内側にあることを確認して実現可能性をチェックします。 中心は二次元的に連続しているため、無限の探索空間となる。 細かいグリッド上で x と y を離散化することさえ不可能です。各チェックは$O(n)$、グリッドでは非常に多くの評価が必要になります。 

重要な構造的洞察は、円が常に X 軸に接しているため、その中心がどちらかの上に位置するように制約されるということです。$y = r$または$y = -r$。 兆候を修正して、1 つのケースに焦点を当てることができます。 対称性は他のものを処理します。 

中心を固定する$(x, r)$、ポイントの条件は次のようになります。$$(x - x_i)^2 + (r - y_i)^2 \le r^2.$$展開して単純化すると、次の 2 次式が削除されます。$r$:$$(x - x_i)^2 + r^2 - 2r y_i + y_i^2 \le r^2$$これは次のようになります。$$(x - x_i)^2 + y_i^2 \le 2r y_i.$$これにより、点ごとに下限が課されます。$r$の関数として$x$:$$r \ge \frac{(x - x_i)^2 + y_i^2}{2y_i}.$$もし$y_i < 0$、不等号の方向が反転します。これは、軸より上の中心ではそのような構成が不可能であることを意味します。 これにより、実行可能条件がすぐに得られます。選択された中心高さの符号について、すべての点が厳密に軸の正しい側に存在する必要があります。 

したがって、固定記号の場合、問題は最小化されます。$$r(x) = \max_i \frac{(x - x_i)^2 + y_i^2}{2y_i}.$$これは凸関数です$x$、凸二次関数の最大値であるためです。 これにより、三項検索を適用できるようになります。$x$、評価中$r(x)$線形時間で。 

両方が実行可能な場合、最終的な答えは 2 つのケース (軸の上または下の中心) の最小値になります。

 ## アルゴリズムのチュートリアル

 ポイントを扱います$y > 0$軸上の中心の候補として、および点$y < 0$その下のセンターの場合。 

1. 問題を 2 つの独立したケースに分割します。$y = r$そして中心に$y = -r$。 これは、接線方向を選択すると固定されるため必要です。 
2. 「軸上」の場合、ポイントが存在するかどうかを確認します。$y_i \le 0$。 その場合、接線から導出される不等式は一貫して成立しないため、このケースは破棄してください。 
3. 関数を定義する$f(x)$固定水平座標に必要な半径を計算します。$$f(x) = \max_i \frac{(x - x_i)^2 + y_i^2}{2y_i}.$$この関数は、中心が高さで軸の上に垂直に固定されている場合に必要な最小半径を取得します。$r$。 

1. 三項検索を使用する$x$すべての点を含む十分に大きな間隔で、通常は$[-10^7, 10^7]$。 の凸性$f(x)$単一のグローバル最小値を保証します。 
2. 各ステップで評価します。$f(x)$で$O(n)$すべての点をスキャンし、最大制約を計算することによって。 
3. すべての符号を反転した後、「軸の下」の場合でも同じプロセスを繰り返します。$y_i$。 
4. 両方のケースから最小の有効な結果を取得します。 どちらも有効でない場合は、出力$-1$。 

### なぜ効果があるのか

 この変換により、幾何学的カバー問題が 1 次元の凸関数の上包絡線の最小化に縮小されます。 各点は次の制約を定義します。$r$の凸二次関数として$x$、実行可能な半径はこれらの曲線の最大値です。 凸関数の最大値は凸のままであり、一意の最小値が保証されます。 関数には大域最小値以外の極小値がないため、三分探索は有効です。 接線拘束により、次の自由度が削除されます。$y$、問題を 1 変数の最適化にまとめます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve_case(points):
    def calc(x):
        res = 0.0
        for xi, yi in points:
            res = max(res, ((x - xi) * (x - xi) + yi * yi) / (2.0 * yi))
        return res

    lo, hi = -1e7, 1e7
    for _ in range(80):
        m1 = (2 * lo + hi) / 3
        m2 = (lo + 2 * hi) / 3
        if calc(m1) > calc(m2):
            lo = m1
        else:
            hi = m2
    return calc((lo + hi) / 2)

def solve(points):
    best = INF

    # case 1: center above axis
    if all(y > 0 for _, y in points):
        best = min(best, solve_case(points))

    # case 2: center below axis (flip)
    flipped = [(x, -y) for x, y in points]
    if all(y > 0 for _, y in flipped):
        best = min(best, solve_case(flipped))

    return best if best < INF else -1

def main():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]
    ans = solve(points)
    print(ans)

if __name__ == "__main__":
    main()
```この実装では、評価関数内で符号制約が混在することを避けるために、2 つの幾何学的構成を明示的に分離します。 の`calc(x)`関数は固定された水平中心位置に必要な半径を計算し、三分探索により最適な x 座標を絞り込みます。 

反復数は 80 に固定されており、必要な精度で浮動小数点を収束するには十分です。 各評価はポイント数で線形であるため、パフォーマンスは次のようになります。$O(n \log C)$。 

よくある落とし穴は、分母を忘れることです。$2y_i$一貫した標識処理が必要です。 そのため、両方を 1 つの式に統合するのではなく、「軸の下」の場合に座標を明示的に反転します。

 ## 特殊なケース

 重要なエッジ ケースは、点が X 軸の両側にあり、上下の円の接線が強制的に失敗する場合です。 たとえば、ポイントがある場合$(0, 1)$そして$(0, -1)$、軸の上に接する円に下点を含めることはできませんし、その逆も同様です。 各実現可能性チェックがその符号条件に失敗するため、アルゴリズムは両方のケースを正しく拒否します。 

もう 1 つの微妙なケースは、すべての点が軸に非常に近いものの、軸と交差していない場合です。 このような場合、数値精度が三項探索の収束に影響を与える可能性があります。 反復回数が固定されているため安定性が確保されており、必要な精度は 1 つだけであるため、浮動小数点での作業で十分です。$10^{-6}$。 

最後のケースには、最適な x がどの入力 x 座標にも存在しない対称分布が含まれます。 三分探索では、目的が凸面であるため、これをスムーズに処理できます。そのため、離散的な候補位置を必要とせずに、最小値が点間の連続空間に存在する可能性があります。
