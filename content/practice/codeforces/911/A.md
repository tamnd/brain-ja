 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 配列内のすべての値の中に最小値があり、この問題ではこの最小値が少なくとも 2 回出現することが保証されます。 

私たちのタスクは、その最小値が 2 つ出現する間の最小距離を見つけることです。 位置間の距離は、単にそれらのインデックス間の差です。 

たとえば、配列では次のようになります。```
[5, 2, 7, 2, 9]
```最小値は`2`、インデックスに表示されます`1`そして`3`。 彼らの距離は`3 - 1 = 2`、したがって、答えは次のとおりです`2`。 

配列のサイズは次のように大きくできます。`100000`。 この制約がある場合、位置のすべてのペアを比較するアルゴリズムには、大まかに次のものが必要になります。`10^10`最悪の場合、2 秒の制限時間内で実行できる範囲をはるかに超えた操作が行われます。 配列を線形時間で処理するソリューションが必要です。 

いくつかの特殊なケースは注目に値します。 

すべての要素が最小である配列を考えてみましょう。```
4
1 1 1 1
```最小値はインデックスに表示されます`0, 1, 2, 3`。 最も近いペアは隣接しているため、答えは次のようになります。`1`。 最初と最後の出現のみを比較する不注意な実装では、誤った値が返されます。`3`。 

最小値が不均等に分離されている場合を考えてみましょう。```
5
2 8 2 3 2
```最小値はインデックスに表示されます`0, 2, 4`。 距離は`2`そして`2`、したがって、答えは次のとおりです`2`。 We must examine all consecutive occurrences, not just one pair.

 Another important case is the smallest valid input:```
2
3 3
```最小値は両方の位置で発生し、答えは次のようになります。`1`。 インデックス計算におけるオフバイワンの間違いは、この境界ケースでよく発生します。 

## アプローチ

 簡単な解決策は、最初に最小値の出現をすべて見つけてから、それらの出現のすべてのペアを比較して最小距離を取得することです。 

これは、答えが最小値を含む 2 つの位置間の最小距離として定義されるため機能します。 あれば`k`すべての出来事を調べることができます`k(k-1)/2`ペアを作成し、それらの距離を計算します。 

この問題は、多くの要素が最小値に等しい場合に発生します。 最悪の場合、すべて`100000`要素は最小限です。 その場合、次のものが必要になります。```
100000 × 99999 / 2 ≈ 5 × 10^9
```ペアの比較は遅すぎます。 

重要な観察は、最小値がわかった後は、その位置だけが問題になるということです。 最小値が次の位置で発生すると仮定します。```
p1 < p2 < p3 < ... < pk
```任意の 2 つの出現間の最小距離が必要な場合は、この並べ替えられたリスト内の 2 つの連続する位置の間に出現する必要があります。 

なぜ？ ポジションを取れば`pi`そして`pj`と`j > i + 1`の場合、それらの間に少なくとも 1 つのオカレンスがあります。 距離`pj - pi`その間隔内の隣接するギャップよりも大きい。 このようなペアでは最小距離を生み出すことはできません。 

つまり、最小値の連続発生を調べるだけで済みます。 

まず配列の最小要素を見つけます。 次に、配列を再度スキャンして、最小値が現れた最新の位置を記憶します。 別の出現を見つけるたびに、前の出現までの距離を計算し、答えを更新します。 

これにより、線形時間の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. 配列内の最小値を見つけます。 
3.初期化`last = -1`最小値の出現がまだ見られていないことを表します。 
4.初期化`answer`非常に大きな値を持つ。 
5. アレイを左から右にスキャンします。 
6. 現在の要素が最小値と等しい場合は常に次のようになります。 

1. もし`last`すでに以前の発生を保存しているため、距離を計算します`current_index - last`。 
2.アップデート`answer`この距離が小さければ。 
3. 現在のインデックスを次の場所に保存します。`last`。 
7. スキャンが完了したら、印刷します。`answer`。 

これが機能する理由は、スキャンではインデックスの昇順で最小の出現が自然に発生するためです。 計算された各距離は、最小値が 2 回連続して出現する間の正確なギャップです。 

### なぜ効果があるのか

 最小値の位置を次のようにします。```
p1 < p2 < p3 < ... < pk
```アルゴリズムはすべての距離を計算します。```
p2 - p1
p3 - p2
...
pk - p(k-1)
```連続しないペアを考慮します`pi`そして`pj`と`j > i + 1`。 その距離は次のとおりです。```
pj - pi
```この間隔内には、少なくとも 1 つの連続したギャップがあります。 その連続ギャップは次の値以下です`pj - pi`。 したがって、連続する出現の中で、2 つの出現間の距離が可能な限り最小になる必要があります。 

このアルゴリズムは、連続するすべてのペアを 1 回だけチェックし、それらの距離の最小値を取得するため、常に正しい答えを返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    mn = min(a)

    last = -1
    ans = n

    for i in range(n):
        if a[i] == mn:
            if last != -1:
                ans = min(ans, i - last)
            last = i

    print(ans)

if __name__ == "__main__":
    solve()
```最初のステップは、配列の最小値を見つけることです。 この値の出現のみが答えに寄与できるため、その後は他のすべての要素を無視できます。 

変数`last`最小値が出現した最新のインデックスを格納します。 別の出現が見つかった場合、2 つのインデックス間の距離は、正確に連続する最小値間のギャップになります。 

変数`ans`これまでに見られた最小のギャップを追跡します。 に初期化されます`n`これは、長さの配列内の 2 つのインデックス間の最大距離であるため、有効な答えよりも安全に大きくなります。`n`は`n - 1`。 

よくある間違いはアップデートです`last`距離を計算する前に。 これを行うと、インデックスとそれ自体が比較され、常にゼロが生成されます。 正しい順序は、最初にギャップを計算し、次に更新することです。`last`。 

インデックスの差は最大でも小さいため、オーバーフローの懸念はありません。`99999`、Python の整数の範囲内に十分収まります。

 ## 特殊なケース

 ### すべての要素は等しい

 入力:```
4
1 1 1 1
```最小値は`1`、インデックスに表示されます`0, 1, 2, 3`。 

アルゴリズムは距離を計算します。```
1 - 0 = 1
2 - 1 = 1
3 - 2 = 1
```これらの値の最小値は次のとおりです。`1`、これが正解です。 最初と最後の出現だけを見ると、誤って生成されます。`3`。 

### 不等間隔の最小値

 入力:```
5
2 8 2 3 2
```最小値は`2`、インデックスに表示されます`0, 2, 4`。 

アルゴリズムは以下を計算します。```
2 - 0 = 2
4 - 2 = 2
```答えは次のようになります`2`。 

これは、連続した出現をチェックするだけで十分な理由を示しています。 連続しないペア`(0, 4)`距離がある`4`、これは大きく、最適化できません。 

### 最小の有効な入力

 入力:```
2
3 3
```最小値はインデックスに表示されます`0`そして`1`。 

最初の出現セット`last = 0`。 2 番目に発生すると、以下が生成されます。```
1 - 0 = 1
```アルゴリズムの出力`1`、これは 2 要素配列で唯一可能な距離です。 このケースでは、初期化と境界処理が正しいことを確認します。
