 ## 解決策
 ## 問題の理解

 1 から _n_ までの整数の順列が与えられます。これは、その範囲内のすべての数値が何らかの順序で 1 回だけ現れることを意味します。 反転とは、大きいインデックスが小さいインデックスよりも小さい数値を保持する位置のペアであり、事実上局所的な「無秩序」です。 たとえば、順列 [4, 1, 3, 2] では、インデックス 2 の数字 1 はインデックス 1 の数字 4 より小さく、反転を形成します。 

このタスクは、順列のサブセグメントをそれぞれ逆にする複数のクエリを処理することです。 各反転の後、反転の正確な数は必要ありませんが、それが奇数か偶数かだけが必要です。 

制約は微妙です。 順列長 _n_ は最大 1500 で、必要に応じて _n_ で 2 次演算を行うのに十分な大きさです。 ただし、クエリ _m_ の数は非常に多く、最大 2·10^5 です。 この組み合わせでは、クエリごとに反転を最初から再計算するソリューションは即座に除外されます。これは、クエリあたりの反転数が O(n^2) であっても、最悪の場合、およそ 4.5 · 10^11 の演算が必要になるためです。 最悪でも O(1) または O(n) でクエリを処理するアプローチが必要です。 

エッジ ケースは、非常に短いセグメントまたは長さ 1 のセグメントから発生します。 長さ 1 のセグメントを反転しても、反転カウントはまったく変化しないはずです。 すでに昇順または降順になっている置換は、パリティ フリップが正しく計算されるように慎重に処理する必要があります。 たとえば、サイズ 2 の順列全体を反転すると、1 つの反転が切り替わり、パリティが偶数から奇数に反転します。 

## アプローチ

 ブルートフォースアプローチは簡単です。順列を読み取った後、クエリごとにインデックスのすべてのペアを反復処理し、反転をカウントできます。 これは反転定義が明示的であるため機能しますが、クエリの数が数千を超えるとすぐに非実用的になります。これは、各カウントが O(n^2) になるためです。 

効率的なソリューションを導き出す重要な洞察は、正確な反転数ではなくパリティに焦点を当てることから得られます。 長さ _k_ の部分配列を反転すると何が起こるかを考えてみましょう。 部分配列内の要素の各ペアは、相対的な順序を 1 回だけ入れ替えます。 長さ _k_ のセグメントには _k・(k-1)/2_ のペアがあります。 したがって、セグメント内の反転数のパリティは、_k・(k-1)/2_ が奇数である場合にのみ反転します。 これにより、各クエリはこの単純な算術値が奇数か偶数かを計算するだけになり、一定時間で実行できます。 

どの特定の要素が交換されるかを追跡する必要はありません。 不変条件は、反転セグメント内の要素ペアの数が奇数の場合にのみ、全体の反転カウントのパリティが変化することです。 この観察により、本質的にクエリあたり O(n^2) であると思われる問題が、クエリあたりのパリティ更新 O(1) に変換されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(m・n^2) | O(n) | 遅すぎる |
 | 最適 | O(n^2 + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、順列における初期の反転数を数えます。 これは、すべてのペアを反復処理することによって行われます。`(i, j)`と`i > j`かどうかを確認します`a[i] < a[j]`。 パリティのみを保存します: 偶数または奇数。 
2. セグメントを含む各クエリについて`[l, r]`、セグメントの長さを次のように計算します。`k = r - l + 1`。 
3. セグメント内のペアの数を計算します。`k * (k - 1) / 2`。 この数値が奇数か偶数かを確認してください。 奇数の場合、反転の現在のパリティを反転します。 偶数の場合は、パリティを変更しないでください。 
4. 更新されたパリティに基づいて「奇数」または「偶数」を出力します。 

機能する理由: 順列における反転のパリティは、セグメント内で順序を逆にするスワップによってのみ影響を受けます。 逆セグメントの各ペアは、ちょうど 1 つのスワップを反転カウントに寄与します。 したがって、クエリに関連する唯一の情報は、そのようなペアの数が奇数であるか偶数であるかであり、これにより、パリティの更新がどのような順列およびクエリの長​​さに対しても正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
m = int(input())

# compute initial inversion parity
parity = 0  # 0 = even, 1 = odd
for i in range(n):
    for j in range(i):
        if a[i] < a[j]:
            parity ^= 1  # flip parity

for _ in range(m):
    l, r = map(int, input().split())
    k = r - l + 1
    if (k * (k - 1) // 2) % 2 == 1:
        parity ^= 1
    print("odd" if parity else "even")
```最初の二重ループは、初期パリティを正しく計算します。 1 との XOR を使用すると、スワップが奇数に寄与するたびにパリティが反転されます。 クエリ処理は定数時間です。長さを計算し、ペアの数を計算し、パリティをチェックし、反転します。 計算するため、off-by-one エラーはありません。`k = r - l + 1`包含インデックスの場合は正しくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 + m) | 初期反転パリティは O(n^2) をとり、各クエリは O(1) |
 | スペース | O(n) | 順列配列のみを保存する |

 n ≤ 1500 および m ≤ 2・10^5 の場合、O(n^2) の初期ステップはおよそ 2.25・10^6 回の演算であり、これは許容範囲内です。 O(1) でのクエリ処理はそれぞれ 2・10^5 回の演算であり、十分に制限内です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    parity = 0
    for i in range(n):
        for j in range(i):
            if a[i] < a[j]:
                parity ^= 1
    for _ in range(m):
        l, r = map(int, input().split())
        k = r - l + 1
        if (k * (k - 1) // 2) % 2 == 1:
            parity ^= 1
        output.append("odd" if parity else "even")
    return "\n".join(output)

# provided samples
assert run("3\n1 2 3\n2\n1 2\n2 3\n") == "odd\neven", "sample 1"
assert run("4\n1 2 4 3\n4\n2 4\n1 3\n1 4\n3 3\n") == "even\nodd\nodd\nodd", "sample 2"

# custom cases
assert run("1\n1\n1\n1 1\n") == "even", "single element"
assert run("2\n2 1\n1\n1 2\n") == "even", "two element swap flips parity"
assert run("5\n5 4 3 2 1\n3\n1 5\n2 4\n3 3\n") == "even\nodd\nodd", "descending with mixed queries"
