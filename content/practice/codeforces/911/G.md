 ## 解決策
 ## 問題の理解

 整数の 1 次元配列が与えられ、部分配列内の値を選択的に置き換える一連のクエリを処理する必要があります。 各クエリでは、配列内の範囲と 2 つの整数 _x_ と _y_ を指定します。 _x_ に等しい範囲内のすべての要素を _y_ に置き換えます。 すべてのクエリが順番に適用された後、配列の最終状態を出力することがタスクとなります。 

配列サイズは 200,000 要素に達する可能性があり、各要素は 1 ～ 100 の範囲に制限されます。クエリの数も 200,000 に達する可能性があります。 すべてのクエリが配列全体をカバーする場合、クエリごとにサブ配列をループする単純なアプローチでは、最悪の場合、およそ 4 × 10^10 の演算が発生する可能性があります。 明らかに、O(n・q) 解は 3 秒の制限時間内では実行不可能であり、通常は 1 秒あたり約 10^8 の演算が実行できます。 

明らかではないエッジ ケースには、複数の置換で同じ要素をターゲットとする重複クエリ、_x_ と _y_ が等しいクエリ、または一致する _x_ 値を含まない範囲をカバーするクエリが含まれます。 たとえば、配列が次の場合、`[1, 2, 1]`そしてクエリは`(1, 3, 1, 2)`に続く`(2, 3, 2, 3)`、単純な置換では、更新された配列を注意深く追跡して生成する必要があります。`[2, 3, 2]`。 これらの更新を無視したり、不適切に適用すると、間違った最終配列が生成される可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、クエリごとに配列を反復処理し、指定された範囲内の各要素が _x_ に等しいかどうかを確認するだけです。 存在する場合、要素は _y_ に置き換えられます。 このメソッドは、問題で説明されている操作を文字通り実行するため、正しく機能します。 この問題はその非効率性から発生します。最悪の場合、すべてのクエリで配列のほぼ全体が変更され、演算回数が O(n·q) に達します。これは、最大の入力に対して 4 × 10^10 のオーダーであり、実用的な制限をはるかに超えています。 

最適化の重要な観察点は、配列要素が 100 で区切られた小さな整数であるということです。これにより、考えられる値ごとに、それが出現するインデックスの並べ替えられたリストを保存できるようになります。 クエリで範囲内のすべての _x_ を _y_ に置き換えるよう要求された場合、二分検索を使用して _x_ の位置の並べ替えられたリストから関連するインデックスをすばやく見つけ、それらのインデックスを更新して _x_ と _y_ のリストを調整できます。 各数値は独自のリストにインデックスしかないため、無関係な要素をスキャンすることは避けられます。 

これにより、問題は配列全体のスキャンから、実際に置換する必要がある値の位置のみのスキャンに変換されます。 各インデックスは個別の数値変更ごとに最大 1 回アクセスされるため、合計実行時間は O(n + q·log n) 以上に比例します。 1 ～ 100 の数値からインデックスのリストへのマッピング (合計 O(n)) を保存するため、空間の複雑さは管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・q) | O(n) | 遅すぎる |
 | インデックスリストによる最適化 | O(n + q・log n) | O(n + 100) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る`a`そして辞書を初期化します`pos`1 ～ 100 の各値を、それが表示されるインデックスの並べ替えリストにマッピングします。 これにより、あらゆる値の位置をすばやく見つけることができます。 
2. クエリごとに`(l, r, x, y)`、_x_ が _y_ と等しいかどうかを確認します。 それらが同じ場合は、変更する必要がないため、このクエリをスキップします。 
3. それ以外の場合は、二分探索を使用して、インデックスのサブリストを見つけます。`pos[x]`内にあるもの`[l-1, r-1]`。 これらの位置のみを更新する必要があります。 
4. このサブリストのインデックスごとに、次のように設定します。`a[index] = y`。 インデックスを追加します`pos[y]`。 
5. 更新されたインデックスを`pos[x]`リストを正確に保つため。 
6. すべてのクエリが完了したら、配列を出力します。`a`。 

機能する理由: 各クエリは現在値 _x_ を保持している位置のみを変更し、すべての値の位置の最新のリストを維持します。 二分探索により、関連するインデックスのみに触れることが保証されます。 各インデックスの更新が反映されるため、`pos`すぐに、後続のクエリで正しい現在の値が表示されます。 これにより、操作の順序が維持され、正確さが保証されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

pos = {i: [] for i in range(1, 101)}
for idx, val in enumerate(a):
    pos[val].append(idx)

for _ in range(q):
    l, r, x, y = map(int, input().split())
    if x == y:
        continue
    indices = pos[x]
    left = bisect.bisect_left(indices, l - 1)
    right = bisect.bisect_right(indices, r - 1)
    for idx in indices[left:right]:
        a[idx] = y
        pos[y].append(idx)
    del indices[left:right]

print(' '.join(map(str, a)))
```コードはまず、すべての可能な値のインデックス リストを構築します。 クエリごとに二分検索を使用して、関連する範囲内のインデックスをすばやく見つけます。 アップデート後は、`pos[x]`置き換えられたインデックスは含まれなくなりますが、`pos[y]`更新された位置を受け取ります。 これにより、変更されていない要素を再度参照することがなくなります。
