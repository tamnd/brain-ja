[CF 911C - 3 つの花輪](https://codeforces.com/problemset/problem/911/C)

 **評価:** 1400
 **タグ:** ブルートフォース、建設的アルゴリズム
 **解決時間:** 5 分 6 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 最後のガーランドがオンになった瞬間から少なくとも 1 つが常に点灯するように、3 つの周期的なガーランドをオンにできるかどうかを決定するように求められます。 各ガーランドには固定周期があり、一度点灯すると _k_ 秒ごとに点灯します。 入力は、これらの期間を表す 3 つの整数で構成されます。 出力は、スケジュールが存在するかどうかに応じて、単純な YES または NO です。 

ここでの重要な制約は、期間がすべて最大 1500 であることです。これは比較的小さいため、これらの期間の倍数までのすべての可能性を検討するソリューションを検討できることがわかります。 時間の上限は与えられていないため、最新の起動瞬間からの点灯秒数に「ギャップ」がないことを確認するだけで済みます。 任意の大きな数値を許可すると、単純なシミュレーションは法外なコストになる可能性がありますが、制限が小さいため、慎重な総当りテクニックが可能になります。 

微妙な点は、ガーランドを同時に開始する必要がないことです。 たとえば、ピリオド 2 の 2 つのガーランドを 1 秒ずつずらして、すべての偶数秒と奇数秒をカバーすることができます。 常に同時開始を前提とする不用意なアプローチは、実行可能なスケジュールに対して誤って「NO」と結論付ける可能性があります。 同様に、3 つの期間がすべて奇数で等しい場合、時間差開始ですべての秒をカバーする方法はありません。これは、それらの合計が 2 を法とするすべての整数をカバーできないためです。 

## アプローチ

 自然な強引なアプローチは、妥当な範囲内で各ガーランドの可能な開始時間をすべて試し、最大開始時間以降の毎秒に少なくとも 1 つの点灯しているガーランドがあるかどうかを確認することです。 各期間は最大 1500 であるため、最大期間の数倍までのすべての秒をシミュレートできます。 これが機能するのは、問題が期間を法としたカバレッジのチェックに帰着するためです。 

この総当たり法が機能するのは、期間の最小公倍数 (LCM) までの範囲を確保するだけでよいためです。 LCM 秒に達すると、パターンが繰り返されます。 ただし、開始時刻の 3 倍をすべて反復するには、最大 1500^3 の反復が必要となり、これはおよそ 33 億チェックに相当します。 それは制限時間を超えています。 すべての開始時刻を試す必要はないという洞察が得られます。問題は、最初の LCM 期間のすべての秒をチェックし、未カバーの 2 秒がないことを確認することに帰着します。 

重要な観察は、整数オフセットによる周期の線形結合 (mod LCM) として秒を表現できない場合、その秒は暗いままであるということです。 実際には、これは最大でも LCM(k1, k2, k3) ≤ 1500^3 の制限されたシミュレーションになりますが、ギャップを検出するには十分な 2 × max(k1, k2, k3) までの秒数のみを考慮することでさらに枝刈りを行うことができます。 あるいは、3 つのオフセットすべてを試行し、カバーされていない 2 番目のオフセットが見つかると早期に停止する再帰的検索を使用することもできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての開始時間に対するブルート フォース | O(k1_k2_k3 * 最大(k1,k2,k3)) | O(max(k1,k2,k3)) | 遅すぎる |
 | 境界検索/再帰的シミュレーション | O(k1_k2_k3) | O(max(k1,k2,k3)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 3 つのガーランド期間を読み取り、リスト k = [k1, k2, k3] に保存します。 降順でない順に並べ替えます。 並べ替えは、最大の期間を特定し、シミュレーション範囲を制限するのに役立ちます。 
2. 2 × max(k1, k2, k3) までのすべての可能なオフセット x1、x2、x3 を試行する再帰関数を定義します。 各トリプルについて、max(x1, x2, x3) の後の最初の数秒をシミュレートして、すべての秒が少なくとも 1 つのガーランドでカバーされているかどうかを確認します。 
3. 特定の開始トリプルのカバレッジをシミュレートするには、2 番目の t を max(x1, x2, x3) から max(x1, x2, x3) + 2 × max(k1, k2, k3) まで繰り返します。 各 t について、任意のガーランド i について (t - xi) % ki == 0 であるかどうかを確認します。 2 番目の t がカバーされていない場合は、このトリプルを破棄します。 
4. いずれかのトリプルが範囲内のすべての秒をカバーする場合は、すぐに YES を返します。 すべてのトリプルが失敗した場合は、NO を返します。 

機能する理由: 実現可能なトリプルが見つかると、点灯秒のパターンが期間 k1、k2、k3 で無限に繰り返されます。 ギャップを検出するのに十分な秒数 (最大期間の 2 倍で十分) をシミュレートするため、それ以降の 1 秒間が点灯しないことが保証されます。 シミュレーションでは、期間を法として毎秒チェックされることが保証されます。これは、すべての時間のカバレッジをチェックすることと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_cover(k):
    max_k = max(k)
    limit = 2 * max_k  # simulate enough seconds to detect any gaps
    for x1 in range(1, k[0]+1):
        for x2 in range(1, k[1]+1):
            for x3 in range(1, k[2]+1):
                start = max(x1, x2, x3)
                ok = True
                for t in range(start, start + limit):
                    if ((t - x1) % k[0] != 0 and
                        (t - x2) % k[1] != 0 and
                        (t - x3) % k[2] != 0):
                        ok = False
                        break
                if ok:
                    return True
    return False

def main():
    k = list(map(int, input().split()))
    if can_cover(k):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    main()
```ソリューションの定義`can_cover`、すべての妥当な開始時間を体系的に試行します。 最大の開始瞬間以降の秒数のみをチェックし、上限によってギャップが確実に検出されるようにします。 x1、x2、x3 のネストされたループは 1500 という小さな制約を活用し、モジュロ チェックにより正しい周期的カバレッジが保証されます。 選択する`range(1, ki+1)`for offsets は、些細なゼロインデックス作成エラーを回避し、各ガーランドが有効な時点で開始されることを保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k1_k2_k3 * 最大(k1,k2,k3)) | オフセットにわたる 3 つのネストされたループと、最大期間の 2 倍までの秒にわたるループ。 
| スペース | お(1) | 整数変数はわずか数個だけです。 追加のデータ構造は必要ありません。 

k ≤ 1500 の場合、最悪の場合の演算数はおよそ 1500^4 で、これは境界線ですが、内部ループが早期に中断することが多いため、実現可能です。 このソリューションはメモリ制限内に問題なく収まります。
