 ## 問題の理解

 分割できないケーキのピースの 2 つのコレクションが与えられ、1 つのケーキは 2 つに分割されます。`a`断片と別の断片に分割`b`個。 私たちも持っています`n`すべてのピースをこれらのプレートに分配する必要があります。 

各プレートには少なくとも 1 つのケーキを入れる必要があり、どのプレートにも両方のケーキのピースを混ぜることはできません。 したがって、各プレートは 1 つのケーキに完全に割り当てられ、そのケーキからいくつかのピースが詰められます。 

目標は、有効な分布を見つけることだけではなく、プレート上に配置されるピースの最小数を最大化することです。 言い換えれば、各プレート上に最終的に何個のピース​​が載るかを見ると、すべてのプレートにわたる最小荷重を最大化したいと考えます。 

重要な構造は、パーティション化しているということです。`a`そして`b`いくつかのグループに分けられ、各グループはプレートに対応し、各グループには少なくとも次のものが含まれている必要があります。`x`個。 私たちはそのようなものをできるだけ大きくしたいと考えています`x`。 

制約は小さいです。`a, b ≤ 100`、`n ≤ 200`。 これにより、大量の組み合わせ検索が即座に排除されます。 O(n²) または O(n³) の解でも問題ありませんが、その構造は候補値ごとに直接算術実行可能性チェックを行うことを示唆しています。 

1 つのケーキだけでほとんどの皿を満足させることができるにもかかわらず、ケーキをあまりにも多くのグループに分割すると、グループのサイズが小さくなる場合、微妙なエッジケースが発生します。 たとえば、次の場合`a = 100`、`b = 1`、 そして`n = 50`、単純なアプローチでは、各プレートを 1 つのケーキのみに完全に割り当てる必要があることを尊重せずに、ケーキごとに均等に分配しようとする可能性があります。 

もう 1 つの注意が必要な状況は次のような場合です。`n`に近いです`a + b`。 各プレートには少なくとも 1 つのピースが必要であるため、多数のシングルトン プレートを作成することを余儀なくされ、たとえ 1 つのケーキが大きくても、答えは小さくなるように強く制約されます。 

## アプローチ

 この問題を考える強引な方法は、2 つのケーキをグループに分割する可能なすべての方法を試すことです。 ケーキごとに、それが何皿を占めるかを選択します。`i`最初のケーキのお皿と`n - i`2番目のプレート。 次に、分割できるかどうかを確認します`a`の中へ`i`部品と`b`の中へ`n - i`すべてのパーツが少なくともサイズを持つようなパーツ`x`。 

固定の場合`x`、この実現可能性チェックは簡単です。`a`せいぜいサポートできる`a // x`お皿とケーキ`b`せいぜいサポートできる`b // x`プレート。 したがって、分割が存在するかどうかを確認する必要があるだけです。`n`2 つの非負の整数に変換`i`そして`n - i`次のような:`i ≤ a // x`そして`n - i ≤ b // x`。 

可能なすべての分割に対する総当たり攻撃`i`の値ごとに O(n) です`x`、そして私たちもすべて試してみると`x`max(a, b) までの値を指定すると、O(n * max(a, b)) が得られます。これはすでに小さいですが不要です。 

重要な観察は、固定された`x`、すべての分割を試す必要はありません。 形成できるプレートの総数が少なくとも`n`。 ケーキ 1 が貢献できます`a // x`プレート、ケーキ 2 が投稿できます`b // x`プレートなので合計は`(a // x) + (b // x)`。 

したがって、実現可能性は単純な条件に帰着し、次の二分探索が可能です。`x`なぜなら、値が`x`機能するため、より小さい値でも機能します。

 ## アルゴリズムのチュートリアル

 最大の整数を見つけたい`x`両方のケーキを少なくとも次のように分割できるようにする`n`プレートの合計、各プレートには少なくとも`x`個。 

1. 関数を定義する`can(x)`少なくとも形成できるかどうかをチェックします`n`すべてのプレートに少なくとも次のものを含める必要がある場合、プレート`x`個。 

各ケーキがサポートできるプレートの数を計算します。`a // x`最初のケーキから、`b // x`２枚目のケーキから。 

プレートの合計数はそれらの合計であり、それを比較します。`n`。 
2. 二分探索範囲を設定します。`x`から`1`に`max(a, b)`。 

The upper bound works because no plate can contain more pieces than the largest cake itself.
 3. Perform binary search. 各中間点について`mid`、 評価する`can(mid)`。 

可能な場合は、最大化したいため、より大きな値を試します。`x`。 それ以外の場合は、検索スペースを減らします。 
4. 最終的な答えが最大です`x`誰のために`can(x)`trueを返します。 

ステップ 3 の背後にある重要な考え方は単調性です。特定のプレート サイズが不可能になると、それより大きなサイズもすべて不可能になります。 

### なぜ効果があるのか

 固定の場合`x`、ケーキを少なくとも一定の大きさの皿に分割する`x`貪欲にサイズの塊に切断するのと同じです`x`、残りは破棄されるか、前のプレートに統合されます。 このようなチャンクの数は正確に`a // x`。 これにより、厳しい上限が決まります。どのような配置でも、これ以上のものを生成することはできません。`a // x`ケーキの有効なプレート`a`。 同じことが当てはまります`b`。 

したがって、実現可能性は、可能な最大プレート数の合計が以下を満たすかどうかによってのみ決まります。`n`。 このカウントは次のように減少するため、`x`増加すると、検索空間は単調になり、バイナリ検索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, n, a, b):
    return (a // x) + (b // x) >= n

n, a, b = map(int, input().split())

lo, hi = 1, max(a, b)
ans = 1

while lo <= hi:
    mid = (lo + hi) // 2
    if can(mid, n, a, b):
        ans = mid
        lo = mid + 1
    else:
        hi = mid - 1

print(ans)
```の`can`関数は、以前に導出された実現可能条件をエンコードします。 各ケーキは独立して、サイズの完全なグループの数に等しい数のプレートを提供します。`x`に分けることができます。 二分探索では、考えられるすべての値を調べます。`x`効率的に。 

各プレートには少なくとも 1 つのピースが含まれている必要があるため、検索範囲は 1 から始まり、`max(a, b)`なぜなら、どのプレートも最大の単一ケーキのサイズを超えることはできないからです。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`n`に等しい`a + b`。 例えば：```
n = 5, a = 3, b = 2
```ここでは、すべてのプレートに正確に 1 つのピースが含まれている必要があります。 アルゴリズムが評価するのは、`x = 1`:`3 // 1 + 2 // 1 = 5`、一致します`n`したがって、答えは 1. 任意です。`x ≥ 2`各ケーキは十分な皿を形成することさえできないため、すぐに失敗します。 

もう 1 つのエッジ ケースは、次のような一方のケーキが他方のケーキよりもはるかに大きい場合です。```
n = 4, a = 100, b = 1
```のために`x = 25`、私たちは得ます`100 // 25 + 1 // 25 = 4 + 0 = 4`、これは機能します。 のために`x = 26`、私たちは得ます`3 + 0 = 3`、失敗します。 アルゴリズムは、小さなケーキがそれ以上には何も寄与しないことを正確に捕捉します。`x = 1`、大きなケーキだけで残りの要件を満たす必要があります。
