 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられます。 私たちは、ローカル ルールに基づいて文字を繰り返し削除します。つまり、現在の隣接文字の少なくとも 1 つがそれ自体よりもアルファベットの 1 文字前にある場合にのみ、文字を削除できます。 たとえば、`d`隣接している場合は削除できます。`c`、そして`c`隣接している場合は削除できます。`b`。 

削除するたびに文字列内の隣接関係が変化するため、移動するたびに新しい削除の機会が現れたり消えたりする可能性があります。 このプロセスは、削除ができなくなるまで続行されます。 課題は、そのような安定状態に達するまでに削除する文字の数を最大化することです。 

入力サイズは最大 100 文字です。 これにより、100 ステップを超える 2 という大まかな分岐係数でさえ天文学的に大きいため、すべての削除順序にわたる指数関数的な検索が即座に除外されます。 将来の構造を考慮せずにすべてのシーケンスを試行したり、貪欲に削除をシミュレートしたりするソリューションは信頼できません。最善の策は、目先の利益だけではなく、将来の隣接関係をどのように再形成するかに依存するためです。 

削除によって遠隔操作のロックが解除されると、微妙な困難が生じます。 たとえば、中央の文字を削除すると、遠く離れた 2 つの文字が隣り合って、以前には存在しなかった新しい有効な削除チェーンが作成される場合があります。 

単純な欲張りな考えは、現在削除可能なキャラクターを常に削除することです。 「ローカルに適切な」文字を削除すると、その後の長い削除チェーンを許可する唯一の構成が破壊される可能性があるため、これは失敗します。 最適な戦略は、現在の状態だけでなく、文字列の構造全体について推論する必要があります。 

2 番目の失敗モードは、有効なペアの数などの単純な統計においてプロセスが単調であると仮定することです。 小さな例がすでにこの直感を打ち破っています。構成によってすべての移動が一時的にブロックされる一方で、別の早期削除順序によって長いカスケードのロックが解除される可能性があります。 

## アプローチ

 ブルート フォース ビューでは、有効な削除の考えられるすべてのシーケンスをシミュレートします。 現在の文字列からすべての位置をスキャンし、ルールを満たすすべての削除を試み、再帰的に実行し、最良の結果を取得します。 これは、すべての有効なプロセスを調査するため、正しいです。 ただし、削除するたびに文字列が変更されるため、状態の数は文字数に応じて階乗的に増加します。 生の文字列をメモ化した場合でも、状態空間は基本的に順序付けされたすべてのサブシーケンスであり、あまりにも大きすぎます。 

進歩するために、私たちは削除されても生き残る構造を探します。 重要な観察は、削除は隣接性にのみ依存し、隣接性は各連続セグメントに何が残っているかによって完全に決定されるということです。 これは、区間動的計画法の定式化を示唆しています。増加する文字列のセットをシミュレートする代わりに、境界の相互作用を除いて外界とは独立して、固定部分文字列の内部で何が達成できるかを推論します。 

中心的なアイデアは、エンドポイント内の他のすべてを削除した後にエンドポイントのどのような構成が残ることができるのか、また、それによって生じる削除の数を間隔ごとに計算することです。 この方法で区間を特徴付けることができたら、最後に削除された文字として各位置を試し、左右の部分からの解決策を組み合わせることができます。 

これにより、削除順序の探索から、間隔の結果を構造化された方法で組み合わせるという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 すべての部分文字列を部分問題として扱い、境界効果を追跡しながら、その内部を最適に削除した後に何が残るかを計算します。 

1. 間隔にわたる DP を定義する`[l, r]`これは、このセグメントを完全に処理した後にどのような結果が得られるかを示しています。 間隔ごとに、削除後にどの文字が左端と右端の生き残る文字として表示されるか、および達成された削除の最大数に関する情報が保存されます。 これが必要なのは、2 つの区間がマージされると、それらの境界文字のみが相互作用するためです。 
2. 基本ケースを初期化します。`l > r`削除も境界文字も生成しない空のセグメントとして。 単一の文字の場合、それを削除するか (より大きなコンテキストで外部的に許可されている場合)、それを保持します。 スタンドアロン間隔内では、削除がゼロの存続エンドポイントとして処理されます。 
3. 一般的な間隔の場合`[l, r]`、位置が`k`この間隔内にあるのは、このセグメントから削除された最後の文字です。 もし`k`最後に削除されたもので、その後にある他のすべてが削除されます`[l, r]`2 つの独立した部分問題に分割する必要がある`[l, k-1]`そして`[k+1, r]`、両方とも最終ステップの前に完全に解決されました。 
4. 左右のパーツを組み合わせると、残った境界文字は結合後に隣接します。`k`が削除されます。 この隣接性は、削除の瞬間に、`k`、それに等しい隣接要素があります`s[k] - 1`。 の左隣`k`は、左の間隔 (または外部境界) から最も右に残っている文字であり、右の隣接文字は、右の間隔から最も左に残っている文字です。 
5. 以下の選択肢のみを受け付けます。`k`マージされた構成で、隣接する文字の少なくとも 1 つが次の文字と等しい場合、間隔の最後の削除された文字として使用されます。`s[k] - 1`。 次に、左右の間隔からの最適な結果と削除のための 1 つの削除を組み合わせて DP 値を更新します。`k`。 
6. 可能なすべての分割点の最大値を取得します。`k`およびサブインターバルのすべての互換性のある境界構成。 

### なぜ効果があるのか

 すべての有効な削除シーケンスには、選択された間隔内に固有の最後の削除があります。 最後の削除を条件付けると、問題が独立した部分区間に分割され、その相互作用は境界文字を介したもののみとなります。 DP は各間隔で考えられるすべての境界結果を明示的に列挙するため、有効な構成が失われることはありません。 すべての有効なシーケンスは、間隔分割と最後の削除の選択の 1 つのシーケンスに正確に対応するため、すべての DP 遷移にわたる最大値が最適な答えを取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # dp[l][r] is a dictionary:
    # key = (left_char, right_char) or None for empty interval
    # value = maximum deletions achievable inside [l, r]
    #
    # left_char/right_char are characters or None if no boundary remains.

    dp = [[dict() for _ in range(n)] for _ in range(n)]

    for i in range(n):
        dp[i][i][(None, None)] = 0  # keep single character, no deletion inside

    def merge(left_states, right_states):
        res = {}
        for (ll, lr), v1 in left_states.items():
            for (rl, rr), v2 in right_states.items():
                # connect right end of left with left end of right
                left_right = lr
                right_left = rl

                # merged interval boundaries
                new_l = ll if ll is not None else rl
                new_r = rr if rr is not None else lr

                key = (new_l, new_r)
                val = v1 + v2
                if key not in res or res[key] < val:
                    res[key] = val
        return res

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            cur = {}

            # case: keep interval without deleting boundary structure (empty deletions inside)
            cur[(s[l], s[r])] = 0 if l == r else 0

            for k in range(l, r):
                left_states = dp[l][k]
                right_states = dp[k + 1][r]
                merged = merge(left_states, right_states)

                for (cl, cr), val in merged.items():
                    # try removing s[k] as last operation of this interval
                    need = chr(ord(s[k]) - 1)

                    ok = False
                    if cl == need or cr == need:
                        ok = True

                    if ok:
                        if (cl, cr) not in cur or cur[(cl, cr)] < val + 1:
                            cur[(cl, cr)] = val + 1

            dp[l][r] = cur

    ans = 0
    for v in dp[0][n - 1].values():
        ans = max(ans, v)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は間隔 DP 構造に直接に従います。 DP テーブルには、セグメントごとに、生き残った境界文字の ID とともに、得られる最良の結果が保存されます。 これらの境界は、セグメント内の最後の削除候補が有効かどうかを決定するため、不可欠です。 

マージ関数は、境界状態を接続することによって 2 つの隣接する区間を結合します。 2 つのセグメントがマージされると、どの文字が隣接するかが正確にわかります。これが、削除の検証に必要な唯一の情報です。 

移行ステップでは、可能なすべての位置が試行されます`k`間隔内の最後に削除された文字として。 サブ区間をマージした後、少なくとも 1 つの近傍が`s[k]`必要な前任者と等しい場合、この構成を許可し、削除数に 1 を追加します。 

最終的な答えは、全間隔の結果として生じる可能性のあるすべての境界構成にわたる最大削除数です。

 ## 特殊なケース

 単一の文字列には隣接する文字列がないため、削除される可能性はありません。 DP は、内部操作がゼロの基本間隔としてこれを正しく初期化します。 

次のような厳密に増加するアルファベットの連鎖`abcde`各文字は以前に削除された後、最終的にその前の文字に隣接するようになるため、完全なカスケード削除が可能になります。 間隔 DP は、有効な最後の削除候補を一貫して見つけることでこれを捕捉します。 

次のような均一な文字列`aaaaa`隣接する文字の間に先行文字がないため、どの段階でも有効な動きは生成されません。そのため、すべての DP 遷移は正確に削除ゼロのままです。
