 ## 解決策

 ## 問題の理解

 長さの 2 つの固定バイナリ文字列が与えられます。$n$、一連のタスクにわたって 2 台のロボットがどのように動作するかを説明します。 タスクごとに$i$、最初のロボットがそれを解決するかどうかのどちらかであり、2 番目のロボットも同様です。 Polycarp は正の整数のスコアを割り当てます$p_i \ge 1$ロボットの合計スコアは、ロボットが解決したタスクのスコアの合計になります。 

自由は価値観の選択にあります$p_i$ただし、制約があります。最初のロボットの合計スコアが 2 番目のロボットよりも厳密に大きくなる必要があります。 このようなすべての有効な割り当ての中で、最大の割り当て値を最小化したいと考えます。 

タスク間の相互作用は、このグローバル最大制約を除いて完全に独立しています。 各タスクは両方のロボットに均等に貢献するか、一方のロボットにのみ貢献するか、まったく貢献しません。 この構造は、重要なのは絶対値ではないことを示唆しています。$p_i$、しかし、それらが2つのロボット間の違いをどのように増幅するか。 

制約$n \le 100$これは、タスクに対する 2 次または 3 次の推論も実行可能ですが、正しい集計が特定されると、最終的には解決策が線形になることを意味します。 重要な難点は、それぞれが$p_i$は小さなセットに固定されておらず、独立して変化する可能性があるため、代入に対する単純な検索は不可能です。 

両方のロボットがすべてのタスクで同じ動作をする場合、微妙なエッジケースが発生します。 その状況では、どの課題も同じスコアを生成するため、厳密な優位性は不可能です。 別の失敗ケースは、2 番目のロボットが解決するタスクを 1 番目のロボットが決して解決しない場合に発生します。その場合、1 番目のロボットは得点に関係なく決して有利になることができません。 

## アプローチ

 ブルートフォース手法では、考えられるすべての値の割り当てが試行されます。$p_i$ある程度の限度までは$K$を選択し、最初のロボットのスコアを大きくする割り当てが存在するかどうかを確認します。 固定の場合でも$K$、 それぞれ$p_i$もっている$K$選択肢、だからこれは$K^n$、それはたとえ小さなものであっても実現不可能です$n$。 

重要な観察は、スコアの差が、選択された値において線形であるということです。 それぞれのタスクは、ロボット間の違いにプラスまたはマイナスの影響を与えるか、まったく寄与しません。 各係数を制御しているので$p_i$内部で独立して$[1, K]$、最適な戦略は、プラスの寄与をできるだけ高くし、マイナスの寄与をできるだけ低くすることです。 

これにより、問題全体が、最初のロボットを支援するタスクの数と 2 番目のロボットを支援するタスクの数を数え、極端な割り当ての下でそれらの貢献度のバランスをとることに帰着します。$p_i$。

 ## アルゴリズムのチュートリアル

 ロボットの動作を比較することで、各タスクを分類します。 両方のロボットによって解決されるタスク、最初のロボットのみによって解決されるタスク、および 2 番目のロボットのみによって解決されるタスクの 3 つのグループを定義しましょう。 

次に、最大値を尊重しながら、最初のロボットを優先してスコア差を最大化する値を割り当てる方法を検討します。$K$。 

1. 2 番目のロボットではなく、最初のロボットによって解決されたタスクの数を数えます。 これに電話してください$A$。 これらのタスクはプラスの差異を生み出すため、できるだけ大きなタスクに値を割り当てる必要があります。$K$。 
2. 最初のロボットではなく、2 番目のロボットによって解決されたタスクの数を数えます。 これに電話してください$B$。 These tasks create negative difference, so we want them as small as possible, meaning we assign them value$1$。 
3. 両方によって解決されたタスク、またはどちらも解決されなかったタスクは、両方のロボットに同等に貢献するため、割り当てに関係なく、両者の貢献は差として相殺されます。 
4. 最適な割り当ての下では、スコアの差は次のようになります。$A \cdot K - B$。 
5. この差が厳密に正である必要があるため、$A \cdot K > B$。 
6. もし$A = 0$、その場合、違いは常にあります$-B$、そうでない限りポジティブになることはできません。$B = 0$, しかし、それでも両方のロボットは同等のままであるため、厳密な不平等は不可能です。 
7. それ以外の場合、有効な最小値$K$を満たす最小の整数です$K > \frac{B}{A}$、つまり$\left\lfloor \frac{B}{A} \right\rfloor + 1$。 

### なぜ効果があるのか

 重要な不変条件は、すべてのタスクがスコア差と各係数に独立かつ線形的に寄与することです。$p_i$上下のみに制限されます。 正と負の寄与は分離され、独立して極端に押し上げられる可能性があるため、最適な解はこれらの境界を飽和させる必要があります。正の差のタスクの重みを最大化し、負の差異タスクの重みを最小化します。 これにより、混合代入が構築された極値代入を上回ることができないことが保証されるため、不等式チェックは$A \cdot K - B$実現可能性を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
r = list(map(int, input().split()))
b = list(map(int, input().split()))

A = 0
B = 0

for i in range(n):
    if r[i] == 1 and b[i] == 0:
        A += 1
    elif r[i] == 0 and b[i] == 1:
        B += 1

if A == 0:
    print(-1)
else:
    K = (B // A) + 1
    print(K)
```このソリューションでは、違いに影響を与えるタスクを 2 つのカテゴリのみに分類します。 ループは線形であり、カウントを直接構築します。 最終的な式は不等式を解くことで直接得られます。$A \cdot K > B$整数制約の下で。 

よくある間違いは、考えられる 4 つのパターンすべてに個別に値を割り当てようとすることです。 最適化には非対称パターンのみが重要です。 もう一つの微妙な点は取り扱いです$A = 0$、この場合、割り算は無効であり、答えは常に不可能です。 

## 実用的な例

 ### 例 1

 入力:```
5
1 1 1 0 0
0 1 1 1 1
```ここでの分類は次のとおりです。 

| 私 | r | b | タイプ | 効果 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | あ | + |
 | 2 | 1 | 1 | ニュートラル | 0 |
 | 3 | 1 | 1 | ニュートラル | 0 |
 | 4 | 0 | 1 | B | - |
 | 5 | 0 | 1 | B | - |

 それで$A = 1$、$B = 2$。 必要です$1 \cdot K > 2$、 それで$K = 3$。 

これは、最大許容値を増やすことによってのみ、単一の非常にポジティブなタスクが複数のネガティブなタスクをどのように補うことができるかを示しています。 

### 例 2

 入力:```
3
1 0 1
1 0 1
```どちらのロボットもすべてのタスクで同じように動作するため、$A$または$B$貢献。 得ます$A = 0$、$B = 0$。 差は常にゼロであるため、厳密な優位性は不可能であり、$-1$。 

これは、スコアを任意に割り当てることができるにもかかわらず、同一の動作では制御可能な影響力が失われることを示しています。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input())
    r = list(map(int, input().split()))
    b = list(map(int, input().split()))

    A = 0
    B = 0

    for i in range(n):
        if r[i] == 1 and b[i] == 0:
            A += 1
        elif r[i] == 0 and b[i] == 1:
            B += 1

    if A == 0:
        print(-1)
    else:
        print(B // A + 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

# provided sample
assert run("5\n1 1 1 0 0\n0 1 1 1 1\n") == "3"

# both identical
assert run("3\n1 0 1\n1 0 1\n") == "-1"

# first dominates completely
assert run("3\n1 1 1\n0 0 0\n") == "1"

# second dominates completely
assert run("3\n0 0 0\n1 1 1\n") == "-1"

# mixed case
assert run("4\n1 0 1 0\n0 1 0 1\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 同一の配列 | -1 | 不可能な厳密な不等式 |
 | 完全な優位性 | 1 | 最も単純な肯定的なケース |
 | 逆優位 | -1 | 対称性の失敗 |

 ## 特殊なケース

 両方のロボットがまったく同じ一連の問題を解決する場合、すべてのタスクは中立のカテゴリに分類されます。 アルゴリズムが生成するのは、$A = 0$、すぐに不可能条件が発生します。 スコアは任意に割り当てることができますが、どの割り当てでも合計は同じになるため、厳密な優位性を満たす構成はありません。 

2 番目のロボットがすべてのタスクを支配する場合、すべての貢献は否定的または中立的になります。 計算された$B > 0$と$A = 0$再び失敗を強いられます。 これは、条件が合計だけに関するものではなく、最初のロボットが相対的な優位性を得ることができる少なくとも 1 つのレバーの存在に関するものであることを示しています。
