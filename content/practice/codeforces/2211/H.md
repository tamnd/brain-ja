 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$。 この問題により、連続する 3 つの要素を選択し、その中で 2 番目に小さい要素を削除するという操作が可能になります。 タスクは、置換の各要素について、操作を何回適用した後でもその要素が存続できる配列の最小サイズを決定することです。 

The input consists of multiple test cases, each with a permutation of size up to 200,000, and the sum of all$n$オーバーテストケースも 200,000 に制限されます。 これは、$O(n^2)$あるいはそれより悪いアルゴリズムは実行不可能です。 必要なのは$O(n)$または$O(n \log n)$制限時間を守るためのアプローチ。 

サイズ 3 の考えられるすべての部分配列を試して中央値を削除するという単純なシミュレーション アプローチでは、組み合わせ的に爆発します。 たとえ$n=10$、削除の考えられる順序は多数あり、その数は次のように急速に増加します。$n$。 したがって、この問題では、どの要素が「安全」で、どの要素がより大きいまたはより小さい隣接要素との相対的な位置に基づいて削除されやすいのかを構造的に洞察する必要があります。 

エッジ ケースには、削除が不可能なサイズ 1 または 2 の配列や、注目する要素が境界にある配列が含まれます。 たとえば、単一要素の配列の場合、$[1]$、答えは自明のことですが 1 です。$[2,1,3]$、要素 1 は、削除が注意深く適用されていれば生き残ることができますが、要素 2 が部分配列の中央値として繰り返し配置されると、強制的に排除されることがあります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。要素ごとに、サイズ 3 のすべての部分配列で考えられる中央値の削除のすべてのシーケンスをシミュレートします。要素がまだ含まれている最小の配列長を追跡します。 これは、許可された操作を正確に反映しているため機能しますが、次のことが必要です。$O(n^3)$各削除はスキャンに依存するため、テスト ケースごとの操作$O(n)$サブ配列と複数のステップの適用。 のために$n \sim 10^5$、これは明らかに不可能です。 

重要な洞察は、要素に関するローカルな順序のみが重要であるということです。 削除ごとに、連続する 3 つの要素の中央値が削除されます。 したがって、要素が削除される危険があるのは、値がその要素を挟む 2 つの要素の間にある場合のみです。 これは、トリプレットが削除される可能性のあるトリプレットの中央値になるのを防ぐために、その周囲にどれだけの要素を残さなければならないかを推論できることを示唆しています。 ターゲット要素を含み、ソートされている、またはその要素に関して単調な境界を持つ連続セグメントについては、それを「保護」できる最も左と右の要素に基づいて、存続する配列の最小長を計算できます。 これにより、問題は、要素ごとに、強制的に削除されずに存続できるセグメントの最大長を決定する線形スキャンに帰着します。 

したがって、最適な解決策は、プレフィックス スキャンとサフィックス スキャンの組み合わせを使用して、どちらかの側で最も近い小さいものと大きいものを決定します。 要素を含む配列の最小長は、事実上、「保護境界」間の最大スパンとなり​​ます。 これにより、複雑さが軽減されます。$O(n^3)$に$O(n)$テストケースごとに。

 ## アルゴリズムのチュートリアル

 1. 特定の順列に対して配列を作成します。`pos`サイズの$n+1$どこ`pos[x]`要素のインデックスを格納します$x$順列の中で。 これにより、各要素の位置の O(1) ルックアップが可能になります。 
2. 2 つのポインタを初期化します。`left`そして`right`、値を削除から「保護」できる最小および最大のインデックスを追跡します。 当初は、`left`=`right`= 要素の位置。 
3. 展開する`left`サブ配列の長さを維持しながら、できるだけ左に移動します。`left`に`right`要素が中央値にならないようにすることができます。 同様に展開すると、`right`同じルールを使用して右に移動します。 重要なのは、要素は 3 つの連続する値の中央値である場合にのみ削除できるため、最も近い小さいまたは大きい近傍を超えて拡張すると削除が防止されるということです。 
4. 要素の最小存続長は次のようになります。`right - left + 1`。 現在の要素のこの値を保存します。 
5. 順列の要素ごとに手順 2 ～ 4 を繰り返します。 

機能する理由: このアルゴリズムは、考慮中の要素がセグメント内のサイズ 3 のサブ配列の中央値として決して配置されないという不変条件を維持します。`[left, right]`。 保護隣接要素を含むようにセグメントを拡張し、セグメントの長さを計算することにより、要素が削除されても存続することが保証されます。 これは、削除ではトリプルの中央値のみが削除されるという特性に依存しているため、要素が端点にあるか、より小さいまたはより大きい隣接要素に囲まれると、強制的に取り出すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        pos = [0] * (n + 1)
        for i, val in enumerate(p):
            pos[val] = i

        answers = [0] * n
        left = right = pos[1]  # start with the smallest element

        for val in range(1, n + 1):
            idx = pos[val]
            if idx < left:
                left = idx
            if idx > right:
                right = idx
            answers[val - 1] = right - left + 1

        print(' '.join(map(str, answers)))

if __name__ == "__main__":
    solve()
```このソリューションでは、高速アクセスのためにまず要素にインデックスを付けます。 次に、要素を昇順に繰り返し検討します。 各ステップで境界を更新します`left`そして`right`1 から現在の要素までのすべての要素を安全に保つために残す必要があるセグメントを追跡します。 違い`right - left + 1`現在の要素の最小存続長を示します。 

微妙な選択には、1 から始まるインデックスを使用することが含まれます。`pos`要素の値を直接照合し、境界の更新が正しく行われるようにし、要素を昇順で反復して、計算されたスパンが常に必要な保護要素をカバーすることを保証します。
