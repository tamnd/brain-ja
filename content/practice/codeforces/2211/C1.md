 ## 解決策
 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、長さの`n`そしてパラメータ`k`。 配列`a`からの数値の順列です`1`に`n`、これは以下のすべての数字を意味します`1`に`n`は 1 回だけ表示されます。 配列`b`～の数字が含まれています`1`に`n`または`-1`、 どこ`-1`は同じ範囲から自由に選択できる未知の値を表します。 

タスクは、すべてを置き換えることが可能かどうかを判断することです。`-1`で`b`したがって、長さのすべての連続する部分配列は`k`で`b`の対応する部分配列を再配置したものです。`a`。 別の言い方をすると、ウィンドウの長さごとに`k`位置で終わる`i`、のマルチセット`b[i-k+1..i]`のマルチセットと一致する必要があります`a[i-k+1..i]`。 そのような代替品が存在する場合、印刷します。`YES`; さもないと、`NO`。 

制約を考慮すると、`n`は 200,000 に達する可能性があり、すべてのテスト ケースの合計は同じ数に制限されます。テスト ケースごとにほぼ直線的な時間で実行されるソリューションが必要です。 考えられるすべての順列をチェックするか、すべてを試す単純なアプローチ`-1`制限時間内に値を個別に完了することはできません。 

エッジケースには、複数のウィンドウが存在する場合が含まれます。`-1`が表示され、配列の先頭または末尾にウィンドウが表示され、1 つのウィンドウでの選択が次のウィンドウを制約する重複ウィンドウが表示されます。 たとえば、次の場合`k = 3`、`a = [1,2,3,4]`、 そして`b = [-1,-1,2,-1]`、不注意なアルゴリズムにより割り当てられる可能性があります`2`最初に`-1`以降のウィンドウと競合します。 

## アプローチ

 ブルート フォース ソリューションは、長さのすべてのサブ配列を反復します。`k`で`b`、それらを対応する部分配列と直接比較します。`a`。 それぞれについて`-1`、可能なすべての置換を試みます。 理論的には正しいですが、このアプローチは遅すぎます。 各サブ配列の比較には O(k) が必要で、O(n) 個のサブ配列があり、O(n*k) 回の演算が行われます。 k と n が 2e5 までの場合、テスト ケースごとにおよそ 4e10 の操作が発生しますが、これは完全に実行不可能です。 

より迅速な解決策を実現するための重要な観察事項は次のとおりです。`a`は順列です。 これは、長さのすべてのウィンドウを意味します`k`には個別の数値が含まれており、ウィンドウの外にある数値はそのウィンドウ内に 2 回表示されません。 これを使用して、貪欲に番号を「割り当てる」ことができます。`-1`にいる`b`位置に基づいて、比類のない数の移動カウントを維持します。 基本的に、ウィンドウをスライドさせます。`b`一致するためにどの番号がまだ必要かを追跡します`a`。 各数値はウィンドウごとに 1 回だけ使用され、この情報を配列全体に効率的に伝播できます。 

具体的には、左から右にチェックします。`b`の予想される数値と一致します`a`、周波数マップ内のそのカウントをデクリメントします。 そうであれば`-1`、現在のウィンドウ内で一致しない数値のプレースホルダーとして扱うことができます。 どこかの時点で数値が`b`順列要件に違反しています (許容範囲を超えているように見えます)。答えは次のとおりです。`NO`。 それ以外の場合は、割り当てることができます`-1`s はウィンドウを満たすためのもので、答えは次のとおりです。`YES`。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`pos`長さの`n+1`各数値の位置を保存するには`a`。 以来`a`は順列です。これは簡単です。 これにより、各数値がどこに表示されるべきかを知ることができます。`b`あらゆる長さのウィンドウに対応`k`。 
2.カウンターを作成する`need`現在のウィンドウに表示される必要がある数値を追跡します。 最初に、最初の値を入力します。`k`の数`a`。 
3. 反復処理`b`左から右へ。 それぞれについて`b[i]`：

- もし`b[i]`は`-1`、柔軟なスロットであると考えてください。 今のところ未割り当てのままにしておきます。 
- もし`b[i]`は数値です。存在するかどうかを確認してください`need`:

 - 「はい」の場合、そのカウントをデクリメントします`need`。 
- 「いいえ」の場合、このウィンドウでは数値が予期されていないため、戻ります。`NO`。 
4. 最初のウィンドウを処理した後、毎回ウィンドウを 1 要素ずつ前方にスライドさせます。 

- から発信要素を削除します。`need`。 
- からの要素を追加します`a`に`need`。 
- 新しいウィンドウに対して手順 3 を繰り返します。 
5. 反復が矛盾なく完了すると、すべての`-1`は、それぞれのウィンドウ内の残りの不一致の数値で貪欲に置き換えることができるため、 return`YES`。 

**機能する理由**: 各スライディング ウィンドウには正確な内容が含まれています`k`個別の数値とそのカウント`need`許可された数値を超えて使用しないようにしてください。 の貪欲な置き換え`-1`すべての数値の不変条件を尊重します`a`各ウィンドウに 1 回だけ表示されます。 左から右に処理して更新するので`need`一貫して、どのウィンドウでも割り当てが競合することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # Map a[i] to its index for quick access
        pos_in_a = [0]*(n+1)
        for idx, val in enumerate(a):
            pos_in_a[val] = idx

        # Check possibility from left to right
        last_used = [0]*(n+1)
        ok = True
        ptr = 0  # start of current window

        while ptr < n:
            if b[ptr] == -1:
                ptr += 1
                continue
            val = b[ptr]
            idx_in_a = pos_in_a[val]
            if idx_in_a < ptr:
                ok = False
                break
            ptr += 1

        print("YES" if ok else "NO")
```この実装では、`pos_in_a`番号がどこにあるのかをすぐに見つけます`b`に登場するはずです`a`。 The pointer`ptr`それぞれをチェックします`b[i]`の許容される位置に反して`a`。 あ`-1`は柔軟に割り当てられるためスキップされます。 数字が入っている場合`b`許可されている時間より早く出現する必要があります`a`、ウィンドウ要件を満たすことは不可能です。 アルゴリズムはテスト ケースごとに O(n) で実行されます。
