 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、以下の各整数を含む配列です。$1$に$n$ある順序で 1 回だけ。 許可される唯一の操作は、連続する 3 つの要素を取得し、それらの中で最大または最小の要素を削除することです。 私たちのタスクは、順列内のすべての要素について、その要素を含む配列の最小サイズを決定することです。 

入力は複数のテスト ケースを表し、それぞれが独自の順列を持ちます。 各テスト ケースの出力は長さの配列です。$n$、ここで、$i$- 番目の数値は、次の内容を含む配列の達成可能な最小サイズです。$p_i$。 

制約は小さいです。$n$は最大 100、テスト ケースは最大 500 です。 これは、次のようなソリューションを提供できることを意味します。$O(n^2)$タイムアウトを気にすることなく、テスト ケースごとの複雑さを軽減できます。 ただし、問題の構造は、注意深く観察することでより良い解決策が得られることを示唆しています。 

エッジケースには次のような場合が含まれます。$n < 3$、削除できないためです。 たとえば、$n=1$、配列を減らすことはできないため、唯一の要素の答えは次のようになります。$1$。 もう 1 つの微妙なケースは、要素が配列の端の 1 つにある場合です。 この操作には連続する 3 つの要素が必要であるため、境界にある要素をその側面から削除することはできず、達成可能な最小長に影響します。 

## アプローチ

 ブルートフォース手法では、考えられるすべての削除シーケンスを試行して、各要素を含む最小の配列を確認します。 これは再帰またはシミュレーションによって実装できます。 要素ごとに、長さ 3 のすべての部分配列を試し、最小値または最大値を削除し、削除できなくなるまで繰り返します。 このアプローチは正しいとはいえ、最悪の場合には階乗数の可能性があり、これはたとえ$n=20$。 

重要な洞察は、どの要素についても、最小値または最大値を削除してサブ配列を減らすことができる限り、削除によってその要素を含む最小のサブ配列の外側の要素のみを削除できることを認識することです。 特定の要素の達成可能な最小長は、配列の端までの距離によって完全に決まります。 具体的には、位置にある要素を考慮します。$i$。 左から次の要素まで削除できます。$i$は左端付近で、右から最後まで$i$は右端付近にあり、貪欲に操作を使用します。 結果として、この要素を含む最小サイズの配列は、どちらかの端までの最大距離に 1 を加えたものになります。 注意して確認すると、両側から同時に削除する場合は、左側と右側の最小限の削除も考慮する必要があることがわかります。 

したがって、位置の要素の最小配列長は$i$は：$$\text{min\_length} = \min(i, n-i-1) + 1$$0 ベースまたは 1 ベースのインデックスに合わせて適切に調整されます。 これにより、単純な結果が得られます$O(n)$テストケースごとのソリューション。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そして順列配列$p$。 
3. 各要素について$p_i$インデックスで$i$(0 ベースのインデックス付け)、達成可能な最小長は、左右の要素数の大きい方に 1 を加えたものとして計算されます。 式では:$$\text{min\_length} = \max(i+1, n-i)$$これが機能するのは、次の要素を含むセグメントの外側の要素を貪欲に削除できるためです。$p_i$、配列の長さは、まだ含まれている最も遠い端までの距離よりも小さくすることはできません。$p_i$。 
4. テスト ケースの最小長をすべて収集し、印刷します。 

機能する理由: サブ配列を適切に選択した場合、すべての操作でターゲット要素の位置の厳密に外側にある要素のみを削除できます。 削除ではトリプル内の要素を削除できますが、ターゲット自体を削除することはできないため、最小の長さは要素から配列の最も遠い端によって制限されます。 不変条件は、要素が配列内に残り、辺からの貪欲な削除により、長さが最も遠い辺までの距離に 1 を加えたものに短縮されることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))
    res = []
    for i in range(n):
        # min length is max(distance from left, distance from right) + 1
        min_len = max(i + 1, n - i)
        res.append(str(min_len))
    print(" ".join(res))
```ソリューションはテスト ケースの数を読み取り、各テスト ケースを反復処理します。 要素ごとに、配列の両端からの距離が計算されます。 Python は 0 から始まるインデックスを使用するため、$i + 1$左端までの距離を与え、$n - i$要素自体を含む右端までの距離を示します。 これら 2 つの最大値を取得すると、配列の最小長の制限要因となる最も遠い側が確実にカウントされます。

 ## 特殊なケース

 のために$n=1$、入力`[1]`、アルゴリズムは次のように計算します。`max(0+1,1-0) = 1`。 削除はできないため、これは最小配列サイズに一致する 1 を正しく返します。 

たとえば、端の要素の場合、`[2,1,3]`、 要素`2`インデックス 0 には`max(0+1, 3-0) = 3`これは、右側から貪欲に削除したとしても、右側のすべての要素がトリプルで処理されるまで最初の要素を削除できないことを反映しています。 これにより、境界要素が処理されることが確認されます。
