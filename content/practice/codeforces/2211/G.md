 ## 解決策
 ## 問題の理解

 各要素の範囲が 0 から 10^6 の整数の配列が与えられます。 許可される操作は、任意の 2 つの隣接する要素を選択し、その平均を計算し、両方の要素をその平均に設定することです。 質問は、これらの演算を任意の数だけ使用して、配列を非減少シーケンスに変換できるかどうかを尋ねます。 

重要な観察は、この操作では数値を自由に並べ替えることができないということです。 各操作では 2 つの隣接する数値をブレンドし、それらを効果的に近づけます。 1 つの数値が右側の隣の数値よりもはるかに大きい場合、平均を繰り返しても小さい数値に向かってのみ減らすことができ、もう一方の側から平均を繰り返すと、大きい数値が小さい数値に向かって減少します。 したがって、配列は、最大の数値が小さい数値と比較してシーケンス内で「早すぎない」場合にのみソートできます。 

入力制約では、すべてのテスト ケースにわたって合計 10^6 までの要素が許可されます。 テスト ケースごとに O(n) よりも複雑なソリューションは遅すぎます。 たとえば、平均化演算の総当りシミュレーションには O(n^2) 以上の時間がかかる可能性がありますが、これは明らかに実行不可能です。 注意すべきエッジ ケースには、すべての要素が等しいシーケンス、すでに減少していないシーケンス、開始または終了に大きなピークがあるシーケンスなどがあります。 例えば、`[10, 0, 0]`非減少順に並べ替えることはできませんが、`[0, 5, 0]`できる。 

## アプローチ

 ブルートフォース手法では、それ以上の変更が発生しなくなるまで、または配列がソートされるまで、平均化操作が繰り返し実行されます。 各操作は O(1) ですが、収束するにはペアごとに O(n) の操作が必要になる場合があります。 n=10^5 の場合、このアプローチは最悪の場合 10^10 の演算を必要とする可能性があるため、非現実的です。 

最適なアプローチは、平均化の効果を分析することから生まれます。 隣接するペアを選択すると`(a_i, a_{i+1})`両方を次のように置き換えます`(a_i + a_{i+1}) / 2`、ペアの合計が保持され、各要素の値がもう一方の要素に向かって移動することがわかります。 操作を繰り返すと、連続する部分配列はその要素の平均に収束します。 これは、数値を恣意的に交換できないことを意味します。大きな数値がはるかに小さな数値の左側にある場合、配列が属するセグメントの最小値よりも小さくできないため、配列のソートがブロックされる可能性があります。 

重要な洞察は、配列が非減少になるためには、最初の要素を除くすべての要素が、その時点までのプレフィックスの最大値によって制限される可能性があるということです。 要素が最初の要素より小さく、最後ではない場合は、より大きな値を満たすように要素を徐々に上に移動する操作を実行できます。 より形式的に言えば、この問題は、配列内の最初の要素が最後の要素以下であるかどうかをチェックすることに帰着します。 そうである場合、配列は平均化演算によって常に非減少にすることができます。 それ以外の場合はできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | プレフィックス/最終チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、要素の数を読み取ります。`n`そして配列`a`。 
2. 最初の要素を比較します`a[0]`最後の要素で`a[-1]`。 

もし`a[0] > a[-1]`、出力`"No"`。 これは、最初の大きな要素を、配列を非減少にするほど十分に削減できないためです。 
3. それ以外の場合は出力`"Yes"`。 平均化操作により、境界に違反することなく内部要素を非減少構成に向けて徐々に調整できます。 
4. すべてのテスト ケースに対して繰り返します。 

これが機能する理由: 不変条件は、各平均化操作が連続するプレフィックスの最小値を減らさず、連続するサフィックスの最大値を増加しないことです。 最初の要素がすでに最後の要素よりも大きい場合、最後の要素を最初の要素よりも大きくする一連の平均化操作は存在しないため、並べ替えは不可能です。 逆に、最初の要素が最後の要素以下の場合、演算は値を内側に「流し」、各セグメントを平均して単調なシーケンスにすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    if a[0] > a[-1]:
        print("No")
    else:
        print("Yes")
```説明: 最初にテスト ケースの数を読み取ります。 各テスト ケースでは、配列を読み取り、最初と最後の要素を単純に比較します。 最初と最後の比較で十分であるため、操作をシミュレートする必要はありません。 使用する`sys.stdin.readline`ソリューションが大量の入力を効率的に処理できるようにします。

 ## 特殊なケース

 次のような単一要素の配列`[0]`非減少特性を自動的に満たします。 アルゴリズムは戻ります`"Yes"`なぜなら`a[0] <= a[-1]`自明に成り立つ。 

等しい 2 つの要素を持つ配列の場合、次のようになります。`[5, 5]`、操作は必要ありません。 アルゴリズムは引き続き正しく出力します`"Yes"`最初の要素が最後の要素より大きくないためです。 

次のような厳密に降順の配列の場合`[5, 4, 3, 2, 1]`、最初の要素が最後の要素を超えています。 アルゴリズムの出力`"No"`これにより、どの平均化シーケンスもこの初期構成を克服できないことが確認されました。 

この社説は、複雑な平均演算のように見えるにもかかわらず、問題は配列の最初と最後の要素間の単純な比較に帰着することを示しています。 洞察は、演算の不変特性とそれが単調性とどのように相互作用するかを理解することで得られます。
