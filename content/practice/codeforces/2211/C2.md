 ## アルゴリズムのチュートリアル

 同じ「制約クラス」に属さなければならない位置がマージされる、素の集合結合構造内のノードとしてインデックスをモデル化します。 

1. インデックス上に DSU を作成します$1 \ldots n$。 あらゆる人にとって$i > k$、私たちは組合します$i$と$i-k$。 

これは、連続するウィンドウの対応する場所に現れる位置が一貫していなければならないことをエンコードします。 
2. これらの共用体を構築した後、各 DSU コンポーネントは、すべてのスライディング ウィンドウ間で交換可能である必要がある一連のインデックスを表します。 
3. 配列からコンポーネントごとの周波数要件を計算します$a$。 インデックスごとに$i$、私たちは価値を付加します$a_i$そのコンポーネントの周波数マップに。 
4. 配列からコンポーネントごとに利用可能な供給量を計算します$b$。 もし$b_i \neq -1$、同じコンポーネントの周波数マップに追加します。 それ以外の場合は、柔軟な容量として処理されます。 
5. 各コンポーネントについて、必要な周波数を比較します（$a$) 利用可能な固定周波数 (から$b$）。 超過要件は、次の方法でカバーする必要があります。$-1$同じコンポーネント内のスロット。 
6. いずれかの時点でコンポーネントが、使用可能な値よりも多くの固定値の出現を必要とする場合$b$、答えは不可能です。 
7. すべてのコンポーネントが内部周波数制約を満たすことができる場合、YES が出力されます。 

重要な実装の詳細は、ウィンドウを明示的に構築しないことです。 DSU は、重複する制約によって引き起こされる等価性を取得します。 

### なぜ効果があるのか

 不変条件は、繰り返しのスライディング ウィンドウのオーバーラップによって接続された 2 つのインデックスが、それらが参加するすべてのウィンドウに常に同じように寄与する必要があるということです。これにより、それらは単一の同値クラスに強制されます。 各クラス内では、次からの複数の貢献セットが含まれます。$a$の固定エントリを使用して実現できるものと一致する必要があります$b$プラス柔軟な$-1$スロット。 以来$-1$ポジションはフリートークンとして機能し、ギャップを埋める役割を果たすだけで、固定値のあり得ない不一致を補うことはできません。 

すべての制約は独立した DSU コンポーネントに分解されるため、コンポーネント間の相互作用は不可能であり、各コンポーネントを個別に満たすことが必要かつ十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        dsu = DSU(n)

        for i in range(k, n):
            dsu.union(i, i - k)

        comp_a = {}
        comp_b = {}
        free = {}

        for i in range(n):
            root = dsu.find(i)

            if root not in comp_a:
                comp_a[root] = {}
                comp_b[root] = {}
                free[root] = 0

            comp_a[root][a[i]] = comp_a[root].get(a[i], 0) + 1

            if b[i] == -1:
                free[root] += 1
            else:
                comp_b[root][b[i]] = comp_b[root].get(b[i], 0) + 1

        for root in comp_a:
            for val, cnt in comp_a[root].items():
                if comp_b[root].get(val, 0) > cnt:
                    print("NO")
                    break
            else:
                print("YES")
                continue
            break
        else:
            print("YES")

solve()

コンポーネントごとのカウントにより、固定寄与分が分離されます。$b$必要な寄付金から$a$。 の数$-1$エントリは追跡されますが、各コンポーネント内で無制限のフィラーとして機能するため、明示的な割り当ては必要ありません。 

よくある落とし穴は、ウィンドウを直接シミュレートしようとすることです。$O(nk)$行動。 もう 1 つは、制約が推移的に伝播することを忘れていることです。これがまさに DSU が必要な理由です。
