 ## 解決策
 ## 問題の理解

 各ノードが整数の重みを格納するツリーが与えられます。 任意の 2 つのノードについて、それらの間の一意のパスを調べ、そのパスに沿ったすべてのノードの重みのビットごとの XOR を計算できます。 ノードのペアの寄与は、それらのパスの XOR 値であり、タスクは、ツリー内の順序付けされていないすべてのノードのペアにわたってこの値を合計することです。 ツリーを構築した後、単一ノードの重みを変更する更新も受け取ります。更新のたびに、このグローバル合計を再計算する必要があります。 

入力サイズにより、問題の構造が即座に制限的になります。 ツリーには最大 100,000 のノードと最大 10,000 の更新があります。 更新のたびにすべてのペアごとのパス XOR を再計算するソリューションは、1 回の完全な再計算でもすでにおよそ n 個の二乗ペア (最悪の場合は約 10^10 の演算) を必要とするため、遅すぎます。 クエリごとの線形時間再計算でも、約 10^9 の操作が必要になるため、それでも遅すぎます。 

微妙な問題は、1 つのノードの寄与が非常に非局所的であることです。 単一のノードを変更すると、パスにそのノードが含まれるすべてのペアの XOR 値に影響します。 これには、ノードがエンドポイントだけでなくパス上の任意の場所にあるペアも含まれます。 ツリーのトラバースによって「影響を受けるペアを更新」しようとする単純なアプローチでは、依然として多くのペアに触れることになります。 

簡単な例で非局所性を示します。 重み [1, 2, 3] を持つ 3 つのノード 1-2-3 のチェーンがあるとします。 ペア (1,3) は 3 つのノードすべてに依存します。 ノード 2 を変更すると、1 つのノード更新だけで、それに直接関係しないペアの結果が変わります。これは、グローバルな再定式化が見つからない限り、エッジベースまたはローカル推論では不十分であることを示しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 ノードの各ペア (u、v) について、ツリーを上っていくか、事前に計算された LCA 構造を使用して、パスに沿って XOR を計算し、すべての結果を合計します。 LCA の前処理を使用すると、各クエリはパス XOR ごとに O(n^2) ペアと O(log n) または O(1) の積になりますが、これは依然として制限をはるかに超えています。 更新のたびに再計算すると、このコストが q 倍になりますが、これは不可能です。 

重要な点は、ツリー内のパス XOR は、ルートからのプレフィックス XOR を使用して書き換えられるということです。 ツリーを任意にルートし、ルートから x までの値の XOR として pref[x] を定義すると、パス u から v の XOR は pref[u] XOR pref[v] XOR w[lca(u, v)] になります。 これにより、パスを明示的に歩く必要がなくなります。 

これでも、すべてのペアの合計は二次関数のように見えます。 2 番目の重要な変化は、ノードのペアの観点から考えるのをやめ、代わりにビット単位で考えることです。 最終的な答えの各ビットは独立しています。 固定ビットの場合、パス XOR にそのビットが設定されているかどうかだけが問題になります。 これにより、問題は、各ビット位置で XOR パリティ 1 を持つペアがいくつあるかを数えるようになります。 

残りの構造は古典的なツリー XOR カウント問題になります。各ノードは多くのパス XOR に寄与しますが、各ビットの寄与はプレフィックス XOR 状態に対するグローバル カウンターを通じて維持できます。 ルート付きツリーでは、プレフィックス XOR 値のマルチセットによってすべてのペアごとのパス XOR が決まります。 

すべての pref[x] を維持すると、すべてのペアにわたるグローバルな答えはプレフィックス XOR 値の数の関数として表現でき、1 つのノードの更新はそのサブツリーに沿った pref 値にのみ影響します。 これは、サブツリー XOR 更新とグローバル頻度構造を維持することを示唆しています。 最後のステップは、サブツリー XOR 伝播とグローバル カウントを効率的にサポートするデータ構造を使用することです。通常は、XOR タグとビットごとの周波数集計を備えたオイラー次数のセグメント ツリーです。

サブツリーの更新が範囲の更新になるように、ツリーのオイラー ツアーを維持します。 ノードの重みが変更されるたびに、そのサブツリーに沿って XOR 値が切り替わります。 私たちは、各ノードがビットごとに、セグメント内のそのビットが設定されているプレフィックス XOR 値の数を格納するセグメント ツリーを維持します。 これから、セグメント ツリー ノードの組み合わせごとに O(1) の各ビットに寄与するペアの数を計算できます。 

これにより、問題は範囲 XOR 更新下での動的配列の維持と、グローバル ペアの寄与のクエリに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² q) | O(n) | 遅すぎる |
 | プレフィックス XOR + セグメント ツリー | O((n + q) log n · 32) | O(n · 32) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーのルートを固定し、各サブツリーが連続したセグメントに対応するようにオイラー ツアーを計算します。 また、初期重みを使用して、ルートからノードまでの XOR を表す各ノードの初期値を計算します。 

次に、オイラー次数の位置に関するセグメント ツリーを構築します。 各セグメント ツリー ノードには、セグメント内の値の数と、ビットごとに、そのビットが設定されている値がいくつあるかという 2 つの情報が格納されます。 

また、そのセグメント内のすべての値に適用する必要がある保留中の XOR マスクを示す、セグメント ツリー ノードごとの遅延 XOR タグも維持します。 

すべてのセグメントの寄与を組み合わせることにより、セグメント ツリーからグローバルな答えを計算できます。 各ビットについて、そのビットが設定されている値の数がわかれば、異なるビットを持つペアの数を計算できるため、XOR に寄与できます。 

### アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、DFS を使用して親と深さの情報を計算します。 これにより、サブツリー範囲を定義できるようになります。 
2. 各ノードが配列内の位置に対応し、各サブツリーが連続した区間になるようにオイラー ツアーを実行します。 これにより、ツリーの更新が範囲の更新に変換されます。 
3. DFS を使用して、ルートから各ノードまでの初期プレフィックス XOR 値を計算します。 これらの値は、動的に維持する必要がある XOR 状態を表します。 
4. オイラー配列上にセグメント ツリーを構築します。 各ノードは、その間隔内のすべての値の各ビット位置の設定ビットのカウントを保存します。 
5. XOR マスクをセグメントに適用すると、それに応じてビット数が反転する遅延伝播メカニズムを定義します。 ビットごとに、マスクにビットが設定されている場合、そのビット位置の 1 と 0 の数が交換されます。 
6. グローバルな答えを計算するには、ビットごとに、ビット 1 とビット 0 の要素の数を使用します。このビットに寄与するペアの数は、合計でペアの順序付けに調整された cnt1 × cnt0 × 2 の寄与になります。 
7. ノードの重みが更新されると、差分デルタ = 古い XOR 新しいを計算し、セグメント ツリーの範囲更新を使用して XOR デルタをそのノードのサブツリー全体に適用します。 
8. 更新のたびに、セグメント ツリー ルートから集計されたビット数を読み取ることによって、グローバルな応答を再計算します。 

### なぜ効果があるのか

 不変条件は、すべての更新後にセグメント ツリーが常にすべてのノードのプレフィックス XOR 値の正しいマルチセットを表すことです。 各ノードの重みの変更は、そのサブツリー内のすべてのノードのプレフィックス XOR に正確に影響し、オイラー ツアーにより、これらのノードが正確に連続したセグメントであることが保証されます。 XOR はインボリューティブであり、プレフィックス変換全体に分散されるため、遅延 XOR 伝播では正確さが維持されます。 すべてのパス XOR は 2 つのプレフィックス XOR 値と定数 LCA 項の関数として表すことができるため、すべてのペアの寄与を維持するには正しいプレフィックス XOR マルチセットを維持するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
w = list(map(int, input().split()))
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
order = []
tin = [0] * n
tout = [0] * n

def dfs(u, p):
    parent[u] = p
    tin[u] = len(order)
    order.append(u)
    for v in g[u]:
        if v == p:
            continue
        dfs(v, u)
    tout[u] = len(order)

dfs(0, -1)

pref = [0] * n

def dfs2(u, p, x):
    pref[u] = x ^ w[u]
    for v in g[u]:
        if v == p:
            dfs2(v, u, pref[u])

dfs2(0, -1, 0)

pos = [0] * n
for i, u in enumerate(order):
    pos[u] = i

B = 30

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.ones = [[0] * B for _ in range(2 * self.size)]
        self.lazy = [0] * (2 * self.size)

        for i in range(self.n):
            x = arr[i]
            for b in range(B):
                if x >> b & 1:
                    self.ones[self.size + i][b] = 1

        for i in range(self.size - 1, 0, -1):
            for b in range(B):
                self.ones[i][b] = self.ones[2 * i][b] + self.ones[2 * i + 1][b]

    def apply(self, i, mask, length):
        for b in range(B):
            if mask >> b & 1:
                self.ones[i][b] = length - self.ones[i][b]
        self.lazy[i] ^= mask

    def push(self, i, l, r):
        if self.lazy[i]:
            m = self.lazy[i]
            mid = (l + r) // 2
            self.apply(2 * i, m, mid - l)
            self.apply(2 * i + 1, m, r - mid)
            self.lazy[i] = 0

    def pull(self, i):
        for b in range(B):
            self.ones[i][b] = self.ones[2 * i][b] + self.ones[2 * i + 1][b]

    def range_xor(self, i, l, r, ql, qr, mask):
        if ql <= l and r <= qr:
            self.apply(i, mask, r - l)
            return
        self.push(i, l, r)
        mid = (l + r) // 2
        if ql < mid:
            self.range_xor(2 * i, l, mid, ql, qr, mask)
        if qr > mid:
            self.range_xor(2 * i + 1, mid, r, ql, qr, mask)
        self.pull(i)

    def get_answer(self):
        res = 0
        for b in range(B):
            c1 = self.ones[1][b]
            c0 = self.n - c1
            res += (1 << b) * c1 * c0
        return res

base = pref[:]
seg = SegTree([pref[u] for u in order])

q = int(input())
out = []

def subtree_xor(u, val):
    seg.range_xor(1, 0, seg.size, tin[u], tout[u], val)

out.append(str(seg.get_answer()))

for _ in range(q):
    x, v = map(int, input().split())
    x -= 1
    delta = w[x] ^ v
    w[x] = v
    subtree_xor(x, delta)
    out.append(str(seg.get_answer()))

print("\n".join(out))
```実装の中核は、生の値の代わりにビット数を保存するセグメント ツリーです。 各ノードは、ビットごとに 0 と 1 のカウントを交換することによって XOR フリップをサポートします。これにより、値の明示的な再計算が回避されます。 

オイラー ツアーでは、サブツリーの更新が連続した範囲の更新になることが保証されるため、更新は対数的なままになります。 最終的な答えはルート集合体からのみ導出されるため、ペアごとの寄与の再計算が回避されます。 

## 実用的な例

 重み 1、2、3 を持つ 3 つのノード 1-2-3 の小さなチェーンを考えてみましょう。 

ルート 1 からプレフィックス XOR 値を計算します。 

ノード1:1

 ノード 2: 1 XOR 2 = 3

 ノード 3: 1 XOR 2 XOR 3 = 0

 配列は[1, 3, 0]になります。 

次に、ペアの寄与をビット単位で計算します。 

| ステップ | 配列 | ビット数 (ビット 0 の例) | 貢献 |
 | --- | --- | --- | --- |
 | イニシャル | [1,3,0] | 1 = 2、0 = 1 | 2 |

 これは、XOR 合計に正しく寄与するすべてのペアに対応します。 

ここで、ノード 2 を 2 から 5 に更新するとします。デルタは 2 XOR 5 = 7 であるため、2 をルートとするサブツリーはそれに応じて反転されます。 

更新後、プレフィックス値は一貫して調整され、再計算によりペアを反復することなく新しいグローバル合計が得られます。 

このトレースは、サブツリーの XOR 変更のみが重要であり、ペア構造はプレフィックス表現を通じて保持されることを示しています。

 ## 特殊なケース

 まれなケースとして、更新がリーフのみで発生する場合があります。 この状況では、単一のオイラー セグメントのみが影響を受け、サブツリー範囲は単一点に縮退します。 セグメント ツリーは、正確に 1 つの位置でビット数を反転することによって XOR を正しく適用し、影響を受けないすべてのパスの正確さを維持します。 

もう 1 つのケースは、すべてのノード値が最初にゼロである場合です。 すべてのプレフィックス XOR はゼロであるため、すべてのペアの寄与はゼロです。 1 回の更新で非ゼロ値が導入されると、そのノードのサブツリーのみが変更され、セグメント ツリーは XOR を正しく伝播するため、影響を受けるプレフィックスのみが反転し、パスにそのサブツリーが含まれる場合にのみ非ゼロの寄与が生成されます。
