 ## 解決策
 ## 問題の理解

 私たちには一連のポジションが与えられており、どのポジションでも 2 つの可能な「アクション」が利用可能です。 各アクションは、固定値の加算または固定値による乗算のいずれかです。 人々のグループがその位置からスタートするとき`l`初期カウント付き`u`、彼らは一歩一歩、`r`。 エンドポイントを含むすべての訪問位置で、その位置で利用可能な 2 つのアクションのうち 1 つを選択し、現在の人数に適用する必要があります。 各クエリの目標は、セグメントに沿ったアクションを選択することです。`[l, r]`最終的な人数ができるだけ大きくなるように、998244353 を法とする最大値を出力します。 

重要な点は、各クエリは独立していますが、セグメントに沿った変換は連続的に行われることです。 現在の値が`x`、各ステップは次のいずれかに適用されます。`x -> x + a`または`x -> x * a`、この選択は、最終結果を最大化するためにすべての位置で行われます。 

制約は大きく、最大 100,000 のポジションと 100,000 のクエリ、値は 10^9 に達します。 これにより、セグメントに対するクエリごとのシミュレーションが即座に除外されます。これは、クエリごとの単純な走査のコストが O(nq) となり、大きすぎるためです。 

微妙な問題は、各位置での決定が現在の値に依存し、その値自体が以前のすべての選択に依存することです。 「乗算を優先する」または「加算を優先する」などの貪欲なルールは、初期の乗算によってその後のすべての演算の影響が変化するため、全体的には正しいとは言えません。 

素朴な推論によるよくある失敗例は次のとおりです。 オペレーションを含むセグメントがあるとします。`+100`に続く`*2`から始まる`u = 1`。 可能であれば欲張って最初に乗算を行う場合、他の例では乗算を早い段階で選択する可能性がありますが、ここでは正しい順序は次のとおりです。`(1 + 100) * 2 = 202`、しながら`1 * 2 + 100 = 102`。 順序と選択は非ローカルな方法で相互作用します。 

主な課題は、各セグメントが初期値に対して複雑な変換を引き起こすことであり、多くのクエリに対して可能な限り最良の結果を効率的に計算する必要があることです。 

## アプローチ

 直接的な総当たりアプローチでは、クエリ セグメント内の各位置に対してすべての操作の選択肢が試行されます。 各位置には 2 つのオプションがあるため、長さ k のセグメントには 2^k 通りの可能性があります。 それぞれの可能性について、u から開始して結果の値を評価します。 これは正しいですが、k = 40 の場合でも完全に実行不可能です。 

より構造化されたビューは、各操作を関数として扱うことです。 各位置は次の 2 つの機能を提供します。`f(x) = x + a`そして`f(x) = x * a`。 フルセグメントは、位置ごとに 1 つの選択された機能を構成することに対応します。 選択の固定シーケンスは、次の形式の関数になります。`f(x) = A x + B`。 加算と乗算の両方が合成時に線形性を維持するため、これは非常に重要です。 

これにより、問題は次のように変換されます。セグメントごとに、位置ごとに 1 つの関数を選択し、結果として得られるアフィン関数が次のようになります。`A x + B`最大化する`A * u + B`。 

すべての関数構成を列挙するため、ブルート フォースは失敗します。 重要な観察は、すべての可能性を追跡するのではなく、達成可能なアフィン変換のセットを維持し、関連する候補のみを保持するデータ構造を使用してそれらを効率的に組み合わせることができるということです。 ここで自然に現れる構造は、線形関数上の凸包です。これは、常に固定 x で線形式を最大化しているためです。 

各セグメントは候補線のセットとして表現できます。`(A, B)`、セグメントの結合は新しい行を生成する合成機能に対応します。 合成後、多くのラインが支配的になるため、小さなハルを残して破棄することができます。 

これにより、各ノードがそのセグメント上で可能なすべての変換を表すアフィン関数の凸包を格納するセグメント ツリーが得られます。 範囲をクエリするとマージされたハルが生成され、x = u での評価はその点での最適なライン値を見つけることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(2^n) | O(n) | 遅すぎる |
 | アフィン凸包を持つセグメント ツリー | O(n log n) 前処理、O(log n) クエリ評価 | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 各操作を一次関数として解釈します。 「+a」操作は`f(x) = x + a`、「*a」演算は`f(x) = a x`。 これにより、あらゆる一連の操作をアフィン関数として表現できるようになります。 
2. アフィン関数を構成するとアフィン形式が維持されることに注目してください。 もし`f(x) = a x + b`そして`g(x) = c x + d`、 それから`f(g(x)) = (a c) x + (a d + b)`。 これにより、すべてのセグメントが 1 つの行に対応することが保証されます。 
3. 各位置に、1 つではなく 2 つの候補アフィン関数を保存します。 これは、その位置で利用可能な 2 つの選択肢を反映しています。 
4. 各ノードが配列のセグメントを表すセグメント ツリーを構築します。 リーフ ノードには、その位置からの 2 つのアフィン関数が格納されます。 
5. 左側の子のすべての関数と右側の子のすべての関数を合成して、2 つのノードをマージします。 これにより、結合されたセグメントの候補線の小さなセットが生成されます。 
6. マージ後、支配的な行を削除します。 x の最大値が得られない場合、ラインは役に立ちません。これは、斜面上の凸包メンテナンスを使用して検出できます。 
7. お問い合わせの場合`[l, r]`、セグメント ツリーを使用して、そのセグメントのアフィン関数の結合ハルを取得します。 
8. クエリ値ですべての候補行を評価します`u`そして、998244353 を法とする最大の結果を取得します。 

この正しさは、考えられるすべての選択シーケンスが 1 つのアフィン変換に正確に対応し、セグメント ツリーの構築ではそのような変換をすべて列挙し、入力値に対して決して最適ではないものだけを破棄するという事実から得られます。 単一の固定値でのみ評価するため、`u`、ラインの上部エンベロープを維持すると、最適なラインが削除されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class Node:
    __slots__ = ("lines",)
    def __init__(self):
        self.lines = []  # list of (A, B)

def add_line(hull, A, B):
    hull.append((A, B))

def merge(h1, h2):
    # compose every line in h1 with every line in h2
    res = []
    for a1, b1 in h1:
        for a2, b2 in h2:
            # (a2*(a1*x + b1) + b2)
            A = a2 * a1
            B = a2 * b1 + b2
            res.append((A, B))

    # build upper hull (sorted by slope)
    res.sort()
    hull = []

    def bad(l1, l2, l3):
        (a1, b1), (a2, b2), (a3, b3) = l1, l2, l3
        return (b3 - b1) * (a1 - a2) <= (b2 - b1) * (a1 - a3)

    for line in res:
        while len(hull) >= 2 and bad(hull[-2], hull[-1], line):
            hull.pop()
        hull.append(line)

    return hull

def eval_hull(hull, x):
    best = 0
    for a, b in hull:
        best = max(best, (a * x + b) % MOD)
    return best % MOD

def build(n, ops):
    size = 1
    while size < n:
        size <<= 1

    seg = [None] * (2 * size)

    for i in range(size):
        seg[size + i] = Node()

    for i in range(n):
        a0, a1 = ops[i]

        def parse(op):
            sign = op[0]
            val = int(op[1:])
            if sign == '+':
                return (1, val)
            else:
                return (val, 0)

        seg[size + i] = Node()
        seg[size + i].lines = [parse(a0), parse(a1)]

    for i in range(size - 1, 0, -1):
        left = seg[2 * i].lines if seg[2 * i] else []
        right = seg[2 * i + 1].lines if seg[2 * i + 1] else []
        if not left:
            seg[i] = Node()
            seg[i].lines = right
        elif not right:
            seg[i] = Node()
            seg[i].lines = left
        else:
            seg[i] = Node()
            seg[i].lines = merge(left, right)

    return seg, size

def query(seg, size, l, r):
    l += size
    r += size + 1

    left_res = []
    right_res = []

    while l < r:
        if l & 1:
            left_res = merge(left_res, seg[l].lines) if left_res else seg[l].lines
            l += 1
        if r & 1:
            r -= 1
            right_res = merge(seg[r].lines, right_res) if right_res else seg[r].lines
        l >>= 1
        r >>= 1

    if not left_res:
        return right_res
    if not right_res:
        return left_res
    return merge(left_res, right_res)

def solve():
    n = int(input())
    ops = [input().split() for _ in range(n)]

    seg, size = build(n, ops)

    q = int(input())
    out = []

    for _ in range(q):
        u, l, r = map(int, input().split())
        hull = query(seg, size, l - 1, r - 1)
        best = 0
        for a, b in hull:
            best = max(best, (a * u + b) % MOD)
        out.append(str(best % MOD))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では各操作をアフィン ペアに解析します。`(A, B)`。 セグメント ツリーは、各ノードに、候補変換の縮小されたセットを格納します。 マージ ステップでは、2 つの子にわたるすべてのペアを構成し、支配的な行を削除します。 

クエリでは、関連するセグメントを収集してそれらのハルを結合し、指定された開始値ですべての候補行を評価します。`u`。 中間係数が大きくなる可能性があるため、モジュラー演算は評価時にのみ適用されます。 

微妙な点は、合成は可換ではないため、マージ順序が重要であるということです。 左側のセグメントは、実際の走査順序を反映して、常に右側のセグメントより前に作成する必要があります。 

## 実用的な例

 2 つのポジションがある小さなセグメントを考えてみましょう。`(+3, *2)`に続く`(+4, +1)`から始まる`u = 1`。 

| ステップ | 現在の船体 | アクション |
 | --- | --- | --- |
 | 1 | {x+3, 2x} | 最初のポジションの選択 |

 | 3 | {2x+6、2x+4、4x+12、4x+6} | 合成後 |

 トレースは、複数のアフィン変換がどのように出現し、より小さな代表的なセットに剪定されるかを示しています。 

次に、乗算の優位性を強調する場合を考えてみましょう。`(+1, *3)`それから`(*2, +5)`と`u = 2`。 

| ステップ | 現在値の範囲 | 最良の選択の直感 |
 | --- | --- | --- |

 | 位置 1 | 3 または 6 | 乗算が優勢 |
 | 位置 2 | 12 または 11 | 乗算優先パスが勝つ |

 これは、ローカルでの貪欲な選択が失敗する理由を示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、セグメント内のすべての演算が加算である場合です。 この場合、すべての変換には勾配 1 があり、アルゴリズムはハルの枝刈り中に異なる切片が誤って破棄されることを回避する必要があります。 マージ ステップでは、支配されていない切片がすべて保存されるため、最終ハルには正しい最大加算チェーンが含まれています。 

もう 1 つのケースは、早い段階では乗算が優勢であるが、後半では加算が優勢である場合です。 たとえば、乗算が多いプレフィックスから始まり、その後に大規模な加算が続きます。 合成順序により、初期の傾き増加が後の加算を増幅することが保証され、評価時に勝者が決定されるまでセグメント ツリーは両方の候補パスを正しく保存します。
