 ## 解決策
 ## 問題の理解

 私たちは長い文字列を与えられ、元のテキストからそれらを「切り取った」後、それらを自由に並べ替えることができます。 この複数の文字セットから、大文字と小文字は関係なく、できるだけ多く繰り返して「Shanghai」という単語を形成したいと考えています。 その単語の完全なコピーを 1 つ組み立てることに成功するたびに、概念的にそれらの文字を削除し、賞品を 1 つカウントします。 

課題は、利用可能な文字数から「Shanghai」という単語のばらばらのコピーをいくつ作成できるかを決定することです。 再配置には制限がないため、元の文字列の順序は関係ありません。 各文字の頻度のみが重要です。 

入力サイズは最大 1e6 文字まで可能であり、これは、すべての解が文字列の長さにおいて線形である必要があることを直ちに意味します。 繰り返しのスキャンや実行シミュレーションを伴うものは、遅くなりすぎます。 単一パスのカウント頻度は実現可能ですが、ネストされたシミュレーションやワードごとの貪欲な削除は実現できません。 

微妙な点は、大文字と小文字を区別しないことです。 これは、「S」と「s」が同一であることを意味し、「Shanghai」のすべての文字も同様です。 正規化を忘れた実装では、有効な文字が二重にカウントされたり、有効な文字が欠落したりします。 

周波数の不均衡以外に、難しい構造上のエッジケースはありません。 たとえば、文字列に「a」が含まれていない場合、単語ごとに少なくとも 1 回出現すると想定する単純な実装では、ゼロで除算されたり、誤った処理が行われる可能性があります。 もう 1 つの特殊なケースは、1 つの文字が優勢であるものの、他の文字が完全に欠落しており、入力サイズが大きいにもかかわらず有効な単語がゼロになる場合です。 

## アプローチ

 ブルートフォース戦略では、単語の構築を 1 つずつシミュレートしようとします。 利用可能なマルチセットを繰り返しスキャンし、必要な各文字を 1 つずつ削除し、単語を構成できなくなるまでカウンターをインクリメントします。 これは単語を構成するプロセスを直接反映しているため、これは正しいです。 

しかし、これは非効率的です。 最悪の場合、「上海」の k 個のコピーを作成できるとします。 各試行では最大 O(n) 文字をスキャンして可用性を確認し、これを k 回繰り返します。 これは O(k・n) につながり、k が n に比例する場合、O(n²) に縮退します。 n が 1e6 までの場合、これは明らかに実行不可能です。 

重要な観察は、各単語の構成がカウントに関して独立していることです。 どの文字を使用するかを動的に選択しているわけではありません。 必要な各文字が合計で何回出現するかを知る必要があるだけです。 「上海」という各単語には一定の文字数が必要なので、答えはボトルネックの文字の頻度によって決まります。 

具体的には、「上海」は S、h、a、n、g、h、a、i の文字で構成されます。 正規化後はカウントが必要になります。 

S:1、h:2、a:2、n:1、g:1、i:1。 

したがって、形成できる完全な単語の数は、次の必要な文字すべてに対する最小数となります。 

頻度(文字)をrequired_count(文字)で割った値。 

これにより、問題は単純な頻度カウントといくつかの整数除算に軽減されます。

 | ブルート フォース シミュレーション | O(n²) | O(n) | 遅すぎる |
 | 周波数カウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列内のすべての文字を小文字に変換します。 これにより、大文字と小文字の区別が均一に処理されることが保証されます。 これがないと、大文字と小文字の頻度バケットが別々になると、使用可能な文字が誤って分割されてしまいます。 
2. サイズ 26 の配列を使用して各文字の頻度をカウントします。英語の文字のみを扱うため、これで十分であり、辞書のオーバーヘッドを回避できます。 
3. 単語「shanghai」に必要な頻度パターンを定義します。

s→1、h→2、a→2、n→1、g→1、i→1。 
4. これらの必要な文字のそれぞれについて、利用可能な周波数を必要な量で割ることにより、何回満たせるかを計算します。 たとえば、5 つの「h」がある場合、2 つの完全なコピーが提供されます。 
5. 答えは、これらすべての商の最小値です。 この最小値は、必要なすべての文字の中でリソースを制限することを表します。 

最小値を採用する理由は、各単語が必要なすべての文字束の 1 単位を消費するためです。 1 つを除くすべての文字が豊富な場合でも、文字の制限により完全な構造の数が制限されます。 

### なぜ効果があるのか

 有効な「上海」はそれぞれ、固定された文字のマルチセットを消費します。 どの解決策も、グローバル周波数プールからこのマルチセットの k 個のコピーを選択することに対応します。 固定 k の場合、実現可能性としては、入力内のすべての文字数が、必要な頻度の少なくとも k 倍であることが必要です。 文字は順序を無視した独立したリソースであるため、これは必要かつ十分です。 したがって、最大 k は、必要なすべての文字にわたる正確な最小比率になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip().lower()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1

    need = {
        's': 1,
        'h': 2,
        'a': 2,
        'n': 1,
        'g': 1,
        'i': 1
    }

    ans = float('inf')
    for c, req in need.items():
        ans = min(ans, freq[ord(c) - 97] // req)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、文字列を正規化し、大文字と小文字が同じ周波数空間に収まるようにすることから始まります。 次に、固定頻度の配列を構築し、任意の文字数への O(1) アクセスを許可します。 

辞書`need`ターゲット単語の構造をエンコードします。 必要な文字ごとに、現在の供給がサポートする完全なコピーの数を計算します。 最後の最小値が制限要因になります。 

よくある実装上の間違いは、単語内に「h」と「a」が 2 回出現することを忘れることです。 それらを単一の出来事として扱うと、答えが過大評価されてしまいます。

 ## 特殊なケース

 重大なエッジケースは、1 つ以上の必須文字が表示されない場合です。 たとえば:

 入力:```
5
aaaaa
```ここでは「a」のみが存在します。 他の必須文字の頻度はゼロであるため、それらの比率はゼロです。 アルゴリズムは最小比 = 0 を計算し、正しく 0 を返します。単純なシミュレーションでは、除算を試みたり、少なくとも部分的な構築を想定したりして、論理的に失敗する可能性があります。 

もう 1 つのケースは不均一な分布です。 

入力:```
12
shanghaishh
```カウントではほとんどの文字は十分に得られますが、「a」または重複した「h」の要件は不十分です。 このアルゴリズムは引き続き、必要な多重度で正しく除算して最小値を取得し、過剰に表現された文字によって結果が膨らむことがないようにします。 

これらの事例は、問題を独立したリソースに対するボトルネックとして扱うことが必要かつ十分であることを裏付けています。
