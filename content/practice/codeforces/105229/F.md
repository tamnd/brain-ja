 ## 解決策
 ## 問題の理解

 各ヒーローには 2 つのラベルがあり、2 つの「絆タイプ」として考えてください。 すべての絆タイプは合計で最大 2 人のヒーローに表示されます。 絆は、それを含む両方のヒーローが選択された場合にのみアクティブになります。 

課題は正確に選択することです$L$英雄たち、あらゆる人にとって$L$1から$n$、アクティブになる結合タイプの数を最大化します。 

構造を再解釈する便利な方法は、すべての絆タイプを、それを共有する 2 人のヒーローを結び付けるものとして扱うことです。 すべてのヒーローにはちょうど 2 つの結合があり、すべての結合は最大 2 回出現するため、この暗黙のグラフではすべてのヒーローの次数がちょうど 2 になり、すべての結合がエッジに対応します。 これにより、すべての接続コンポーネントが単純なサイクルになります。 

そこで問題は次のようになります。ヒーローの互いに素なサイクルがいくつかあり、両方のエンドポイントが選択されている場合、頂点のサブセットを選択するとエッジがアクティブになります。 それぞれについて$L$、選択したサブセット内に完全に端点があるエッジの最大数が必要です。 

制約が十分に大きいため、指数関数的なサブセットの列挙は不可能です。 と$n\le 10^5$、おおよそを超えるもの$O(n \log n)$または$O(n \sqrt n)$すでに疑わしいし、世間知らずだ$O(2^n)$あるいは$O(n^2)$サブセットに対する動的プログラミングは実行不可能です。 

サイクルが部分的に実行される場合、微妙なエッジ ケースが発生します。 たとえば、長さ 5 のサイクルで頂点を選択すると、$\{1,2,3\}$選択中に 2 つのエッジをアクティブにします$\{1,3,5\}$0 エッジをアクティブにします。 これは、内部順序が重要であり、最良の戦略は常にサイクル内の連続したセグメントを選択することであることを示しています。 

もう 1 つの特殊なケースは、サイクルのすべての頂点を取得することです。 サイズのサイクルについて$c$、すべての頂点を選択するとアクティブになります$c$エッジ、これは厳密には$c-1$部分選択から得られるエッジ。 

これら 2 つの動作、「部分的なセグメントは線形ゲインから 1 つのペナルティを差し引いたもの」と「全サイクルはボーナスを与える」により、ソリューション全体を推進します。 

## アプローチ

 強引なアイデアは、ヒーローのすべてのサブセットを処理し、各サブセットで完全にカバーされるサイクルの数を計算することです。 これは正しいです。なぜなら、すべての結合は 2 つのエンドポイントが選択されるかどうかのみに依存するからです。 ただし、サブセットの列挙は指数関数的であるため、サブセット全体にわたって DP によって最適化しようとしても、依然として次のような問題が発生します。$O(n2^n)$スタイルの遷移はすぐに失敗します。 

重要な構造的洞察は、接続された各コンポーネントがサイクルであり、サイクルはグローバルな制限を介さない限り相互作用しないということです。$L$。 サイクル内では、部分選択は最良の場合、単一の連続セグメントのように動作し、正確に「選択された頂点の数から 1 を引いた」エッジに寄与します。 唯一の偏差は、サイクル全体が選択されている場合に発生し、余分なエッジが 1 つ得られます。 

これにより、各サイクルを小さな選択肢のセットに圧縮することができます。何も取らない、サイクル全体を取る、または任意の長さの部分セグメントを取るなどです。 部分セグメントのコストは、その長さに関係なく常に 1 つの「ペナルティ」ですが、完全な選択にはペナルティはなく、ボーナスが与えられます。 

したがって、問題はサイクル全体にわたるナップザックとなり、各サイクルでさまざまなサイズと異なるペナルティを持つ柔軟なアイテムが提供されます。 次に、合計サイズごとに計算します。$L$、ペナルティの最小数を計算し、それを答えに変換します。

 ## アルゴリズムのチュートリアル

 まず、ヒーローと絆によって形成されるグラフ内のすべてのサイクルを特定します。 すべてのノードには次数 2 があるため、これは簡単で、未訪問のノードをたどってそのサイクルを追跡できます。 

サイクルに分解した後、選択した合計サイズに対して動的プログラミングを実行します。 させて`dp[x]`正確に選択するために必要な部分サイクルの最小数を表します。`x`処理されたサイクルを使用するヒーロー。 

初期化する`dp[0] = 0`それ以外はすべて無限です。 

各サイズのサイクルごとに`c`、3 つの方法で DP を更新します。 

1. サイクルを完全にスキップすると、DP は変更されません。 
2. サイクル全体を実行できます。 これはから移動します`x`に`x + c`ペナルティを増やすことなく。 
3. サイズの部分セグメントを取得できます`t`どこ`1 ≤ t ≤ c - 1`。 これはから移動します`x`に`x + t`ペナルティをちょうど 1 だけ増やします。 

3 番目の遷移は、唯一重要な部分です。 これは、スライディング ウィンドウの最小値を取得することと同じです。$$dp_{\text{new}}[x+t] = \min(dp_{\text{old}}[x] + 1)$$すべて有効な$t$サイクル範囲内です。 これは、以前の状態に対するウィンドウ最小値を維持することで効率的に計算できます。 

すべてのサイクルを処理した後、次の関係を使用して DP を回答に変換します。$L$ペナルティのある頂点$p$、活性化された結合の数は$L - p$。 

### なぜ効果があるのか

 重要な不変条件は、各サイクル内で、選択された頂点の数を変更したり、アクティブ化されたエッジの数を減らしたりすることなく、完全ではない選択を連続したセグメントに再配置できることです。 これは、すべての部分的な選択肢には、そのサイズに関係なく、ちょうど 1 つの固定ペナルティがあることを意味します。 完全選択は、サイクルが閉じて最終エッジに寄与するため、このペナルティが消える唯一のケースです。 

サイクルは独立しているため、それらを結合してもサイズとペナルティが追加されるだけです。 したがって、DP は常に、合計サイズごとに達成可能な最適なペナルティを追跡し、正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    g = [[] for _ in range(n)]
    
    # map bond -> list of heroes
    pos = {}
    
    for i in range(n):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        
        for x in (a, b):
            if x not in pos:
                pos[x] = i
            else:
                j = pos[x]
                g[i].append(j)
                g[j].append(i)
    
    # find cycles
    vis = [False] * n
    cycles = []
    
    for i in range(n):
        if vis[i]:
            continue
        cur = []
        p = -1
        u = i
        
        while not vis[u]:
            vis[u] = True
            cur.append(u)
            for v in g[u]:
                if v != p:
                    nxt = v
            p, u = u, nxt
        
        cycles.append(len(cur))
    
    INF = 10**18
    dp = [INF] * (n + 1)
    dp[0] = 0
    
    for c in cycles:
        new = [INF] * (n + 1)
        
        # prefix min for sliding window (partial selection)
        best = [INF] * (n + 1)
        
        for i in range(n + 1):
            best[i] = dp[i]
        
        # partial: add 1 cost for any t in [1, c-1]
        for i in range(n + 1):
            if best[i] == INF:
                continue
            for t in range(1, c):
                if i + t <= n:
                    new[i + t] = min(new[i + t], best[i] + 1)
        
        # full cycle
        for i in range(n + 1):
            if dp[i] == INF:
                continue
            if i + c <= n:
                new[i + c] = min(new[i + c], dp[i])
        
        # skip cycle
        for i in range(n + 1):
            new[i] = min(new[i], dp[i])
        
        dp = new
    
    res = []
    for L in range(1, n + 1):
        if dp[L] == INF:
            res.append(0)
        else:
            res.append(L - dp[L])
    
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、最初に各結合を 2 人のヒーロー間の無向エッジとして扱うことによってサイクル グラフを再構築します。 次に、すべてのノードに次数 2 があるため、単純な走査を使用してサイクルを抽出します。 

動的プログラミング配列は、可能な選択サイズごとに最小限のペナルティを追跡します。 遷移は、スキップ、全サイクルの取得、および部分セグメントの取得という 3 つのサイクル操作の直後に続きます。 最終的な変換`L - dp[L]`これは、部分的なサイクルごとに、完全な線形寄与と比較して効率がちょうど 1 だけ低下するという観察から来ています。 

実装の主な点は、部分的な遷移が以前の DP 状態からのみ適用されるようにすることです。 同じサイクル内で更新された値を混合すると、単一サイクルから複数の部分的なペナルティが誤って許可されてしまいます。

 ## 特殊なケース

 すべてのヒーローが選択された単一サイクルは、最もデリケートなケースです。 アルゴリズムがすべての選択を誤って線形セグメントとして扱う場合、次の出力が行われます。$c-1$の代わりに$c$。 DP では、これは明示的な「フルサイクル」遷移によって処理され、ペナルティを維持しながらサイズを正確に増加させます。$c$。 

もう 1 つの微妙なケースは、部分選択が混在する複数のサイクルから頂点を選択することです。 DP は、各サイクルが部分モードで最大 1 つのペナルティに寄与することを保証するため、ペナルティの合計はサイクル全体で加算されます。 これにより、選択内容がサイクル間で不均等に分散されている場合にペナルティが過大にカウントされるのを防ぎます。
