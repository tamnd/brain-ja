 ## 解決策
 ## 問題の理解

 私たちには一連のミッションが与えられており、各ミッション i には時間コスト Ai と価値 Bi があります。 ユーザーには合計時間予算 M があり、費やした合計時間が M を超えない限り、ミッションのサブセットを選択して、それぞれ最大 1 回、任意の順序で完了できます。 

おもしろいのは、通常のように報酬が加算されないことです。 ミッションが完了しても、直接的に固定報酬が与えられるわけではありません。 代わりに、ミッションが完了するたびに、人はこれまでに完了したすべてのミッションを思い出し、再び Bi 値を取得します。 したがって、完了時の報酬は、すでに完了したミッションの数によって異なります。 

順序の観点から考えると、シーケンス内の k 番目のミッションが完了すると、その時点での自分自身を含まない、以前に完了したすべてのミッションの Bi の合計に寄与します。 

目標は、時間制約の下で蓄積されたメモリ報酬の合計を最大化するミッションの順序とサブセットを選択することです。 

この制約は、ミッションの数は N ≤ 30 と小さいですが、時間予算 M は最大 10^9 と非常に大きく、コスト Ai は最大 10^9 です。 これにより、時間を次元として追跡する DP は直ちに除外されます。 M以上のクラシックなナップザックは不可能です。 

代わりに、N は指数関数的なサブセットに対して十分小さいため、構造はミッションよりもサブセットの選択を提案します。 

順序を無視すると、微妙な失敗例が現れます。 たとえば、次の 2 つのミッションが存在するとします。 

入力:

 N = 2、M = 10

 A = [6, 6]

 B = [100, 1]

 両方を選択する場合、順序が重要になります。 最初に高 B ミッションを実行すると 0 が得られ、次に低 B ミッションでは 100 が得られます。合計は 100 です。逆の場合、合計は 1 になります。順序を無視する単純なサブセット合計スタイルのソリューションでは、この区別を見逃してしまいます。 

別の失敗ケースは、各ミッションがその後に完了したミッションの B 倍の数に寄与すると仮定した場合に発生します。 それは正しいですが、それは注文が慎重に処理された場合に限ります。 

## アプローチ

 重要な問題は、報酬が相対的な順序に依存することです。先に完了したミッションは後のミッションに恩恵をもたらしますが、後のミッションは今後のミッションから恩恵を受けられません。 

ブルートフォースアプローチは、すべてのサブセットと各サブセットのすべての順列を試し、合計時間と報酬を計算し、最も有効な構成を採用することです。 サイズ k のサブセットの場合、順列は k! に寄与し、すべてのサブセットを合計すると、合計の複雑さは ∑ k! のオーダーになります。 C(N, k) は、N = 30 の場合でも実現可能性をはるかに超えて増加します。 

重要な観察は、固定サブセットの場合、最適な順序付けはミッションを Bi でソートすることによって完全に決定されるということです。 より大きな Bi でミッションを早期に完了すると、それに適用される将来の乗数の数が増加します。 ただし、慎重に推論する必要があります。完了した各ミッションは、その後完了するすべてのミッションに Bi を与えます。つまり、ミッションの Bi は、その後に来るミッションの数に応じて複数回カウントされる重みのように機能します。 

視点を逆にすると、「各完了が過去の Bi を収集する」と考える代わりに、次のように考えることができます。j より前の i とのすべてのペア (i, j) が、j の報酬の蓄積に Bi を貢献します。 したがって、各 Bi は、選択した順序でその後に続くミッションごとに 1 回だけカウントされます。 

したがって、選択したサブセット S が s1、s2、...、sk として順序付けされる場合、合計報酬は次のようになります。 

B[s1]・(k-1) + B[s2]・(k-2) + ... + B[sk]・0

 より大きな Bi が先に現れると、より大きな係数が乗算されるため、これは最大になります。 

したがって、固定サブセットの場合は、Bi を減少させることによって並べ替えて、次のように計算します。 

位置 i の合計: B[i] × (k - 1 - i)

 ここで問題は、この値を最大化する合計時間 ≤ M のサブセットを選択することになります。 

これは、N ≤ 30 での古典的な中間集合ナップサックです。ミッションをサイズ 15 の 2 つの半分に分割します。各半分について、すべてのサブセットを列挙し、(時間、貢献度) を計算して保存します。 次に、ソートと優先枝刈りを使用して時間をかけてマージします。

次に、左と右のサブセットを結合します。左のサブセットの時間が tL で、右のサブセットが tR である場合、tL + tR ≤ M が必要です。右のサブセットごとに、ソートされた左の状態に対するプレフィックス最大値を使用して、残りの容量の達成可能な最良の値を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(N! · 2^N) | お(1) | 遅すぎる |
 | 中間サブセット列挙 | O(2^(N/2) log 2^(N/2)) | O(2^(N/2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ミッションを 2 つに分割します。 これにより、各半分には最大 15 個の要素が含まれ、2^15 の状態が実現可能になるため、列挙が管理しやすくなります。 
2. 半分ごとに、ビットマスクを使用してすべてのサブセットを列挙します。 サブセットごとに、合計時間を計算し、そのサブセット内の最適な順序を仮定して報酬を計算します。 
3. サブセットの報酬を計算するには、サブセット内のすべての Bi を収集し、降順に並べ替えて、前の要素の多重度が高くなる加重合計を適用します。 
4. 各サブセット状態をペア (時間、値) として保存します。 
5. 左半分のすべての状態を時間でソートし、値のプレフィックス最大値を計算します。 これにより、時間制約の下で、最適な左サブセットの高速クエリが可能になります。 
6. 右側のサブセットごとに、残りの容量 M - tR を計算し、左側の配列で二分探索を行って、最適な互換性のあるサブセットを見つけます。 
7. 左右のサブセットのすべての組み合わせにわたる最大値を追跡します。 

それが機能する理由: 最適なソリューションは、左のサブセットと右のサブセットに一意に分割されます。 各サブセット内で、Bi を減少させてソートすることにより、順序付けが局所的に最適になります。 中間結合マージは、組み合わせを欠落させることなくすべての実行可能な分割をチェックし、プレフィックス maxima により、各右側の状態に対して最適な互換性のある左側の状態が常に選択されるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gen_half(A, B):
    n = len(A)
    states = []
    for mask in range(1 << n):
        t = 0
        vals = []
        for i in range(n):
            if mask & (1 << i):
                t += A[i]
                vals.append(B[i])
        if t > 0 or mask == 0:
            vals.sort(reverse=True)
            k = len(vals)
            score = 0
            for i, v in enumerate(vals):
                score += v * (k - 1 - i)
            states.append((t, score))
    return states

def solve():
    n, m = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    mid = n // 2
    leftA, rightA = A[:mid], A[mid:]
    leftB, rightB = B[:mid], B[mid:]

    left = gen_half(leftA, leftB)
    right = gen_half(rightA, rightB)

    left.sort()
    # prune dominated by time
    filtered_left = []
    best = -1
    for t, v in left:
        if v > best:
            best = v
        filtered_left.append((t, best))

    times = [t for t, _ in filtered_left]
    vals = [v for _, v in filtered_left]

    import bisect

    ans = 0
    for tR, vR in right:
        if tR > m:
            continue
        rem = m - tR
        idx = bisect.bisect_right(times, rem) - 1
        if idx >= 0:
            ans = max(ans, vR + vals[idx])
        else:
            ans = max(ans, vR)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、配列を 2 つの半分に分割して、サイズ 15 のグループのみで指数列挙を有効にすることから始まります。 サブセット ジェネレーターは、各サブセットの時間コストと報酬値の両方を計算します。 報酬の計算では、選択された Bi 値が降順で明示的に並べ替えられ、ペアごとの寄与の解釈から導出された位置の重み付けが適用されます。 

左右の状態を生成した後、左側は単調構造に処理されます。時間によってソートし、達成可能な報酬の実行最大値を維持します。 これにより、時間を長くしてもより良い報酬が得られない支配的な状態が削除されます。 

次に、二分探索を使用して、各右サブセットが最も互換性のある左サブセットとペアになります。 これにより、合計時間の制約を遵守しながら、合計の報酬を最大化することができます。 

実装の微妙な点は、空のサブセットを正しく含める必要があることです。 時間も報酬もゼロで、有効なベースラインとして機能します。 

## 実用的な例

 小さな例を考えてみましょう。 

N = 4、M = 10

 A = [3、4、5、2]

 B = [8, 1, 7, 6]

 [0,1]と[2,3]に分割します。 

左側のサブセット:

 | マスク | 時間 | B を選択 | ソート済み B | スコア |
 | --- | --- | --- | --- | --- |
 | 00 | 0 | [] | [] | 0 |
 | 01 | 3 | [8] | [8] | 0 |
 | 10 | 4 | [1] | [1] | 0 |
 | 11 | 7 | [8,1] | [8,1] | 8 |

 右のサブセット:

 | マスク | 時間 | B を選択 | ソート済み B | スコア |
 | --- | --- | --- | --- | --- |
 | 00 | 0 | [] | [] | 0 |
 | 01 | 5 | [7] | [7] | 0 |
 | 10 | 2 | [6] | [6] | 0 |
 | 11 | 7 | [7,6] | [7,6] | 7 |

 ここで結合すると、たとえば右マスク 11 の時間は 7 であるため、左マスクは時間 ≤ 3 に収まる必要があります。左マスク 00 と 01 のみが適合し、最良の値は 0 になります。合計は 7 です。 

右マスク 10 (時間 2) の場合、左マスク 11 (時間 7)、合計時間 9、値 8 + 0 = 8 を使用できます。 

このトレースは、時間フィルタリングがサブセット値の集計とどのように相互作用するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、Ai 値が大きいためにミッションを選択しないことが最適な場合です。 この場合、空のサブセットを除くすべてのサブセット時間が M を超えます。 アルゴリズムには当然、両方の半分に空の状態が含まれているため、それらを組み合わせると (0, 0) が生成され、これは正しく考慮されます。 

もう 1 つの特殊なケースは、すべての Bi が同一である場合です。 その状況では、順序は重要ではなく、報酬はサブセット サイズの関数に減少します。 すべての順列が同じ合計のペアごとの寄与をもたらすため、サブセットのスコアリングでも一貫した結果が得られます。 

最後のケースは、M がすべてのミッションを含むのに十分な大きさである場合です。 次に、中間結合マージによって両方の半分が完全に選択され、Bi を減少させることによって計算された順序付けにより、導出されたペアごとの構造と一致する大域最適が得られます。
