 ## 解決策
 ## 問題の理解

 各ノードが拡散プロセスの状態を表すルート付きツリーが与えられます。 トークンはルートから始まり、リーフに到達するまで下方向に移動します。 すべてのノードで、特別なことを何も行わない限り、次のステップは制御されません。プロセスは現在のノードの子に移動する可能性があり、すべての出力エッジが継続の可能性があることを意味します。 

一部の葉は望ましい結果としてマークされています。 目標は、下降中にランダムな選択がどのように動作するかに関係なく、プロセスが常にこれらのマークされた葉の 1 つで終了することを保証することです。 

オプションの「コントロール」のセットも提供されます。 各コントロールは、特定のノード u と u の特定の子 v に関連付けられます。 このコントロールをアクティブにすると、トークンが u にあるときは常に、ランダムに分岐することがなくなり、強制的に決定的に v に移動するようになります。 

これらのコントロールの任意のサブセットを選択できますが、優先順位ルールがあります。選択した複数のコントロールが同じノードに影響を与える場合、入力順序で最も古いコントロールのみが有効になり、残りは無視されます。 

タスクは、プロセスがマークされたリーフに確実に到達できるように、アクティブ化する必要があるコントロールの最小数を見つけることです。 それが不可能な場合は、-1 を出力します。 

ツリー サイズはテスト ケース全体で最大 5×10^5 になる可能性があるため、どのソリューションも線形または線形に近いものでなければなりません。 すべての子に対するノードごとの再計算を繰り返し行うもの、またはコントロールに対するサブセットの列挙を含むものは、直ちに遅すぎます。 

微妙な点は、失敗がどのようにして起こるかということです。 いずれかのノードで分岐動作をアクティブのままにしておくと、一連の敵対的な子選択により、プロセスが意図的にすべての適切な葉から遠ざかる可能性があります。 これは、正しさは確率ではなく、最悪の場合の保証であることを意味します。 

よくある間違いは、すべてのノードに少なくとも 1 つの「適切な」子サブツリーがあれば十分だと考えることです。 たとえ良い子が存在したとしても、ランダムな分岐では依然として悪い子が選択される可能性があるため、これでは不十分です。 

## アプローチ

 強引なアイデアは、コントロールのすべてのサブセットを試すことです。 各サブセットについて、最悪の場合の分岐の下でプロセスをシミュレートします。強制されていないすべてのノードで、敵対者が考えられる最悪の子を選択すると仮定します。 それでもマークされた葉に到達することが保証できる場合は、回答を更新します。 

M 個のコントロールには 2^M のサブセットがあり、M は N と同じくらい大きくなる可能性があるため、これはすぐに爆発します。1 つのサブセットをチェックするだけでも、ツリーを走査してすべてのパスについて推論する必要があるため、このアプローチは完全に実行不可能です。 

重要な観察は、問題は多くの道を個別に探索することではなく、不確実性を排除することであるということです。 ノードが危険なのは、安全でないサブツリーにつながる可能性のある分岐選択肢がまだ残っている場合です。 この危険を排除する唯一の方法は、すべての子が安全であることを確認するか、ノードを強制的に 1 つの安全な子にするかのどちらかです。 

これはボトムアップの視点につながります。 各ノードは、そのノード以降、分岐がどのように解決されるか (または許可された制御をどのように適用するか) に関係なく、マークされたリーフで終わることが保証できる場合、「安全」として分類できます。 安全性が定義されると、制御を最小限に抑えるかどうかはローカルな決定になります。何も支払わずにすべての子供が安全であることに依存するか、または 1 つの制御を支払って単一の安全な方向を強制し、他のすべての子供を完全にバイパスするかのどちらかです。 

これにより、グローバル最適化問題がツリー DP に縮小され、各ノードが「ここにコントロールなし」か「ここで 1 つのコントロールだけをアクティブにする」かを決定します。

 ## アルゴリズムのチュートリアル

 ツリーを葉から上に向かって処理し、ノードごとに安全にできるかどうか、必要な制御の最小数はいくらであるかを計算します。

1. まず、各葉が対象の葉の 1 つであれば、安全であるとマークします。 ターゲット セットに含まれていないリーフは、そのリーフに到達すると要件に違反するため、直ちに安全ではなくなります。 これは再帰のベースを定義します。 
2. 各内部ノードについて、2 つの根本的に異なるモードを考慮します。 最初のモードでは、このノードでコントロールをアクティブにしないため、プロセスはすべての子の間で自由に分岐します。 この状況では、最悪の場合にはどの子も選択される可能性があるため、安全性を確保するには、すべての子のサブツリーがすでに安全であることが必要です。 
3. すべての子が安全であれば、このノードで制御をアクティブにしなくても、そのノードは安全であると考えることができます。 この場合のコストは、子の決定が独立しているため、単純に子のコストの合計になります。 
4. 子が 1 つでも安全でない場合、プロセスがその安全でないサブツリーに移動する可能性があるため、ノードを制御されないままにすることは受け入れられません。 その場合、このノードでコントロールをアクティブにすることを検討する必要があります。 
5. コントロールがノード u でアクティブ化されると、特定の子 v への移動が強制されます。これにより、u でのすべての分岐が削除されるため、他のすべての子は無関係になります。 v が安全であるコントロール u → v を選択できるとき、ノードはまさに安全になります。 このオプションのコストは、1 に v を安全にするコストを加えたものです。 
6. 各ノードの答えを、非制御オプション (有効な場合) とすべての有効な制御オプションの間の最小値として計算します。 どちらのオプションも存在しない場合、ノードは安全ではありません。 
7. 最終的な答えは、ルートが安全でない場合を除き、ルートで計算されたコストです。安全でない場合、答えは -1 です。 

### なぜ効果があるのか

 重要な不変条件は、そのノードから開始して、プロセスのあらゆる可能な展開が強制的にターゲット リーフで終了するようにコントロールを選択する戦略が存在する場合にのみ、ノードが安全であるとマークされるということです。 制御されていないケースは敵対的分岐をモデル化したもので、すべての子供が安全な場合にのみ安全です。 制御されたケースでは、すべての分岐が単一の選択された子に折りたたまれます。そのため、安全性は完全にその選択された子に依存します。 すべての制御はノードですべての不確実性を取り除くか、完全に露出したままにするかのいずれかであるため、安全性が上方に伝播できる唯一の方法はこれら 2 つであり、DP は両方の可能性を漏れや二重カウントなしに網羅します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

INF = 10**18

def solve():
    T = int(input())
    for _ in range(T):
        N, M, K = map(int, input().split())
        
        children = [[] for _ in range(N + 1)]
        parent = [0] * (N + 1)
        
        for i in range(1, N + 1):
            arr = list(map(int, input().split()))
            ki = arr[0]
            for v in arr[1:]:
                children[i].append(v)
                parent[v] = i
        
        cand = [[] for _ in range(N + 1)]
        for _ in range(M):
            u, v = map(int, input().split())
            cand[u].append(v)
        
        target = set(map(int, input().split())) if K > 0 else set()
        
        # order nodes by reverse BFS / topo from leaves
        order = []
        stack = [1]
        while stack:
            u = stack.pop()
            order.append(u)
            for v in children[u]:
                stack.append(v)
        
        # postorder by reversing is not guaranteed safe due to reuse,
        # so we compute explicit order via DFS iterative
        order = []
        stack = [(1, 0)]
        while stack:
            u, state = stack.pop()
            if state == 0:
                stack.append((u, 1))
                for v in children[u]:
                    stack.append((v, 0))
            else:
                order.append(u)
        
        safe = [False] * (N + 1)
        cost = [0] * (N + 1)
        
        for u in order:
            if not children[u]:  # leaf
                safe[u] = (u in target)
                cost[u] = 0
                continue
            
            all_children_safe = True
            sum_cost = 0
            for v in children[u]:
                if not safe[v]:
                    all_children_safe = False
                sum_cost += cost[v]
            
            best = INF
            if all_children_safe:
                safe[u] = True
                best = min(best, sum_cost)
            
            # try forcing at u
            for v in cand[u]:
                if safe[v]:
                    safe[u] = True
                    best = min(best, 1 + cost[v])
            
            cost[u] = best if best < INF else 0
            if best < INF:
                safe[u] = True
        
        print(cost[1] if safe[1] else -1)

if __name__ == "__main__":
    solve()
```コードはまずツリーを構築し、開始ノードごとにグループ化された候補コントロールを保存します。 次に、すべての子がその親の前に計算されるように、ノードを事後順序で処理します。 

ノードごとに、すべての子が安全かどうかを確認します。 「はい」の場合、非制御モードが有効であり、子のコストの合計に寄与します。 次に、そのノードから始まるすべてのコントロールを評価します。各コントロールは、ノードを 1 つの子状態に折りたたみ、コストに 1 を追加します。 

微妙な点は、安全性とコストが一緒に追跡されていることです。 ノードは少なくとも 1 つの有効な構造が存在する場合にのみ安全であるとみなされます。それ以外の場合、そのコストは無関係であり、ノードは安全でないものとして伝播します。 

## 実用的な例

 ノード 1 に 2 つの子 2 と 3 があり、リーフ 3 のみがマークされている小さなツリーを考えてみましょう。 2 と 3 は両方とも葉だとします。 コントロールがなければ、ノード 1 は分岐が 2 に進む可能性があるため安全ではありません。1 → 3 を強制するコントロールがある場合、それを選択すると、コスト 1 でノード 1 が安全になります。

 ## 特殊なケース

 重要なエッジ ケースは、複数の子を持つノードですが、すべての子はすでに安全です。 この状況では、分岐が存在しても、考えられるすべての分岐が許容されるため、制御は必要ありません。 アルゴリズムは、「すべての子が安全」という条件を通じてこれを処理し、ノードが制御されない状態を維持できるようにします。 

もう 1 つのエッジ ケースは、ノードに安全な子と安全でない子の両方があるが、そのノードに対するコントロールが存在しない場合です。 その場合、安全でない子が選択される可能性があるため非制御モードは失敗し、リダイレクトする方法がないため制御モードは不可能です。 ノードは安全ではないと正しくマークされ、障害が上方に伝播し、最終的にはルートが不可能になります。 

最後の重要なエッジ ケースは、K が空の場合です。 その場合、どの葉も受け入れられないため、すべての葉のノードが安全でなくなり、これが上向きに伝播して根も安全でなくなります。
