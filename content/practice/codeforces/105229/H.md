 ## 解決策
 ## 問題の理解

 私たちは「ゴールドインターバル」を連続的に生み出すガチャシステムを観察しています。 各間隔は、2 つの連続した金の引き出しの間の引き出しの数であり、その間隔は確率変数であり、その分布は同じ間隔中に展開するカウンターに依存します。 

1 つの間隔内で、カウンターは 0 から始まり、ゴールド カードの取得に失敗するたびに 1 ずつ増加します。 カウンタが値 i にあるとき、次のドローがゴールド カードである確率は関数 pi によって決定されます。 ゴールドが表示されると、インターバルはすぐに終了し、カウンターは次のインターバルに向けてリセットされます。 これは、すべての間隔がゼロから始まる同じ確率プロセスによって生成されることを意味します。そのため、各間隔は離散確率変数 X (次のゴールドまでの時間) の独立したサンプルになります。 

他のプレイヤーから k 個の履歴インターバルを与えられ、シーケンス a1、a2、…、ak を形成します。ここで、ai は i 番目の最新のゴールド インターバルの長さです。 そのプレイヤーが持っているゴールドが k 未満の場合、欠落しているエントリはゼロとして扱われます。これは事実上、最初の k 個の実間隔が指定されたシーケンスと一致することを意味します。 

私たちのタスクは、尤度を直接計算することではなく、独自のゴールド インターバルのシーケンスがこの指定された長さ k のパターンに最初に一致するまで実行する必要がある予想される描画数を決定することです。 

重要な点は、コストがインターバルではなくドローで測定されることです。 観測された各シンボル ai はその値に等しいコストに対応しており、そのような間隔長の無限 i.i.d シーケンスにパターンが最初に現れるまでの予想総コストが必要です。 

この制約は、k が最大 100,000、すべての ai が最大 100,000 であることを意味するため、長いシーケンスを明示的にシミュレートするアプローチや O(k²) 線形代数を使用するアプローチはタイムアウトになる危険性があります。 X の確率分布は構造化されていますが、それでも潜在的に大きなサポートがあるため、慎重に圧縮する必要があります。 

素朴なアプローチでは、間隔の生成をシミュレートしてパターンをチェックしますが、予想される待ち時間が非常に長くなる可能性があり、シミュレーションでは正確な答えは得られません。 もう 1 つの素朴なアイデアは、独立性を仮定して 1 / P(pattern) を計算することですが、これではパターン マッチングの重複が無視され、パターンがそれ自体とプレフィックスやサフィックスを共有するたびに不正確な結果が生成されます。 

## アプローチ

 中心部では、プロセスを i.i.d 確率変数 X1、X2、…の無限シーケンスに縮小します。ここで、各 Xi はゴールド インターバルの長さです。 このシーケンスで最初に出現する固定パターン a1…ak を検索します。 これは古典的なパターンのヒット時間の問題ですが、一工夫が施されています。各シンボルにはその値に等しいコストがかかるため、ステップ数ではなく時間の重みが累積されます。 

ブルート フォース モデルは概念的には単純です。 状態を、現在一致しているパターン接尾辞の量として定義し、そのパターンに対して KMP スタイルのオートマトンを構築します。 各状態から、考えられるすべての間隔の長さ x を考慮し、次の状態に遷移し、コスト x を追加します。 これにより、各状態の期待値が他のすべての状態に依存する k 個の線形方程式系が得られます。 

この定式化は正しいですが、計算コストが高くなります。 アルファベットのサイズは最大 100000 であるため、すべての状態に対して可能なすべての間隔長を直接反復すると、O(k · |X|) 遷移が発生しますが、これは大きすぎます。 結果として得られるシステムを単純に解くことも不可能です。

重要な観察は、ランダム性がオートマトンの状態から完全に独立しているということです。 すべての状態で間隔の長さの分布が同じになるため、遷移ごとの予想コストを分離することができ、遷移構造は x とパターン値の間の等価性チェックのみに依存します。 これにより、間隔分布を一度事前計算し、パターン マッチング用の KMP オートマトンを構築し、確率質量グループ化を使用して遷移を効率的に集約することができます。 

この構造が確立されたら、各方程式が「期待値は一定のコストに他の期待値の加重和を加えたものに等しい」という形式を持つサイズ k の線形システムを解きます。 これは、実装上の制約に応じて、標準的な消去法または反復法によって解決できますが、重要なのは、無限確率プロセスを、事前に計算された遷移確率を備えた有限オートマトンに縮小することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション / シーケンス上の単純な DP | 指数関数的な予想/実行不可能 | お(1) | 遅すぎる |
 | パターンオートマトン + 確率集計 + 線形システム | O(k · | X | + k²) を単純な形で |

 ## アルゴリズムのチュートリアル

 まず、単一のゴールド間隔 X の分布を計算します。これには、カウンタ 0 から始まる確率プロセスをシミュレートする必要があります。 カウンター i では金の確率がわかっているので、t−1 回の失敗を乗り越えて成功することによって、ステップ t で最初の金が正確に発生する確率を計算します。 これにより、t にわたる離散分布が得られ、X の期待値も計算されます。これは、遷移ごとのグローバルな一定コストとして再利用されます。 

次に、パターン a1…ak に基づいて KMP オートマトンを構築します。 各状態 s は、これまでに生成された一連の間隔長のサフィックスと一致するパターンの最長のプレフィックスの長さを表します。 現在の状態と次のシンボル値 x について、次の状態を効率的に計算できるように、障害リンクを事前計算します。 

次に、オートマトンの状態間の遷移確率を計算します。 確率 P[x] で考えられる各間隔値 x について、事前に計算された遷移関数を使用して、すべてのオートマトン状態に対するその影響をシミュレートします。 各状態 s について、確率質量を結果の状態 t = δ(s, x) に蓄積します。 これにより、エントリ P[s][t] が 1 つの間隔ステップで状態 s から状態 t に移動する確率である遷移確率行列が生成されます。 

また、すべての遷移は、期待される長さがオートマトンの状態に依存しない間隔を消費するため、定コスト項 C = E[X] も計算します。 

ここで、状態 s から始まる完全なパターンに到達するまでの予想される残りの描画数として E[s] を定義します。 終端状態 k の場合、E[k] = 0。他のすべての状態については、次のように書きます。 

E[s] = C + ∑t P[s][t] · E[t]。 

これはサイズ k の線形システムです。 ガウス消去法または高密度システムに適した別の線形ソルバーを使用してこれを解決します。 

答えは E[0]、つまり空の一致状態から始まる予想コストです。 

### なぜ効果があるのか

 重要な不変条件は、オートマトンの状態がパターン マッチングに関連するすべての履歴を完全にキャプチャするため、将来の遷移は現在の状態のみに依存し、以前のサンプルには依存しないということです。 各区間は同じ分布から独立して生成されるため、遷移確率はオートマトン全体にわたって定常マルコフ連鎖を形成します。 一定の期待される間隔長と状態遷移へのコスト分解により線形性が保証されるため、期待値は隠れた依存関係のない閉線形システムを満たすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_distribution(B, p0_num, p0_den, v_num, v_den):
    # Compute p_i
    # p0 = p0_num / p0_den, v = v_num / v_den
    max_len = B + 5
    p = []
    p0 = p0_num * modinv(p0_den) % MOD
    v = v_num * modinv(v_den) % MOD

    cur = p0
    for i in range(1, max_len + 1):
        if i <= B:
            p.append(cur)
        else:
            cur = (p0 + (i - B) * v) % MOD
            if cur >= 1:
                cur = 1
            p.append(cur)

    # distribution of X
    # P[X=t] = prod_{i<t} (1-p_i) * p_t
    dist = []
    pref = 1
    for i in range(max_len):
        pi = p[i]
        if i > 0:
            pref = pref * (1 - p[i-1]) % MOD
        dist.append(pref * pi % MOD)

    return dist

def kmp(pattern):
    k = len(pattern)
    pi = [0] * k
    for i in range(1, k):
        j = pi[i-1]
        while j > 0 and pattern[i] != pattern[j]:
            j = pi[j-1]
        if pattern[i] == pattern[j]:
            j += 1
        pi[i] = j

    def go(state, x):
        while state > 0 and (state == k or pattern[state] != x):
            state = pi[state-1]
        if pattern[state] == x:
            state += 1
        return state

    return pi, go

def solve():
    B = int(input())
    a, b, c, d = map(int, input().split())
    k = int(input())
    pattern = [int(input()) for _ in range(k)]

    dist = build_distribution(B, a, b, c, d)

    pi, go = kmp(pattern)

    # expected interval cost
    C = 0
    for i, p in enumerate(dist, 1):
        C = (C + i * p) % MOD

    # transition matrix (dense k x k)
    ksz = k + 1
    P = [[0] * ksz for _ in range(ksz)]

    # approximate alphabet = all possible interval lengths in support
    for x, px in enumerate(dist, 1):
        if px == 0:
            continue
        for s in range(k):
            ns = go(s, x)
            P[s][ns] = (P[s][ns] + px) % MOD

    # linear system: E[s] = C + sum P[s][t] E[t]
    # rewrite: (I - P)E = C
    n = k + 1
    A = [[0] * n for _ in range(n)]
    for i in range(k):
        A[i][i] = 1
        for j in range(k):
            A[i][j] = (A[i][j] - P[i][j]) % MOD
        A[i][k] = C

    A[k][k] = 1

    # Gaussian elimination
    for i in range(k):
        inv = modinv(A[i][i])
        for j in range(i, n):
            A[i][j] = A[i][j] * inv % MOD
        for r in range(k):
            if r != i:
                f = A[r][i]
                for j in range(i, n):
                    A[r][j] = (A[r][j] - f * A[i][j]) % MOD

    print(A[0][k] % MOD)

if __name__ == "__main__":
    solve()
```実装では、問題を 3 つの段階に分割します。つまり、区間分布の構築、KMP 遷移関数の構築、期待値を超える線形システムの解決です。 最もデリケートな部分は遷移の集約であり、各間隔値が状態ごとに 1 つのオートマトン遷移に寄与します。 ガウス消去法はモジュラー演算で記述されるため、すべての正規化ステップでは逆モジュラーを使用してシステムの一貫性を保ちます。 

主な落とし穴は、ステップあたりのコストが単位ステップではなく、間隔の長さそのものであることを忘れていることです。 それが、定数項 C がすべての方程式に現れる理由です。 

## 実用的な例

 間隔の長さが 1 または 2 のみである小さなパターンと単純化された分布を考えてみましょう。パターンが [1, 2] であるため、k = 2 であると仮定します。 

| 状態 | x=1 を読み取る | x=2 を読み取り | 方程式形式 |
 | --- | --- | --- | --- |
 | 0 | 状態 1 | 状態0 | E[0] = C + p1 E[1] + p2 E[0] |
 | 1 | 状態 1 | 状態 2 | E[1] = C + p1 E[1] + p2 E[2] |
 | 2 | ターミナル | ターミナル | E[2] = 0 |

 このトレースは、遷移が数値のみではなく一致する構造にどのように依存するか、および繰り返しによって状態がどのように結合されるかを示します。 

パターン [2, 2, 1] の 2 番目の例は、オーバーラップ動作を強調表示します。 2 の後に別の 2 が続くと、オートマトンは必ずしもリセットされるわけではありません。これは、シーケンスの接尾辞がパターンの接頭辞と一致する可能性があるためです。 これがまさに、単純な確率 1/P(パターン) が失敗する理由です。

 ## 特殊なケース

 特殊なケースの 1 つは、パターンが同じ値の繰り返しで構成されている場合です。 このような状況では、KMP が完全にゼロにリセットされることはなく、障害が発生したリンクは繰り返し短いプレフィックスを指します。 オートマトンは部分一致を正しく維持し、各 x が一貫して同じ遷移構造に寄与するため、遷移行列は依然として正しい確率質量を蓄積します。 

別のエッジ ケースは、あるカウンターしきい値で確率が 1 に達したときに発生します。 その時点以降、すべての間隔は決定論的に制限され、分布は有限になります。 X の構築では、このカットオフを尊重する必要があります。 そうしないと、確率質量が未定義の末尾値に漏れ込み、正規化が壊れます。 

3 番目のケースは、間隔分布の下では非常にありそうもない値がパターンに含まれている場合です。 アルゴリズムは依然としてそれらを通常どおりに扱い、期待値は大きくなりますが、確率の合計は依然として 1 であるため、線形システムは明確に定義されたままです。
