 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは正の整数の配列を提供します。 この配列から、すべての連続するセグメントを考慮し、その合計を計算します。 その合計が合成数である場合、つまり厳密に 1 より大きく、素数ではない場合、セグメントは有効であるとみなされます。 

各テスト ケースでは、合計が合成される、可能な限り短い連続セグメントが必要です。 答えは、セグメントの長さから 1 を引いた、セグメントの両端間のステップ数として報告されます。 合成和を持つセグメントがない場合、答えは -1 になります。 

制約はグローバルな意味で小さいです。各配列の要素は最大 1000 個で、すべてのテスト ケースの合計の長さも最大 1000 です。これにより、テスト ケースごとのおよそ 2 次の動作よりも悪いものはすぐに除外され、すべてのテストで 2 次であっても問題ありません。 前処理を行わずに三次的な動作やチェックごとの大量の計算を伴うものは、不必要なオーバーヘッドとなります。 

微妙な問題は、合成数の定義に起因します。 値 1 は素数でも合成でもないため、セグメントの合計が 1 になるものは拒否されます。 もう 1 つの一般的な落とし穴は、単一要素セグメントです。これらは有効なセグメントであり、考慮する必要があるため、単一要素が複合である場合、答えは 0 になります。 

もう 1 つのエッジ ケースは、すべての数値が 2、3、5 などの小さな素数である場合です。その場合でも、より大きなセグメントは合成和を生成する可能性があるため、複数長のセグメントを無視すると有効な答えが失われる可能性があります。 逆に、すべての要素が 1 の場合、要素を結合する場合を除いてセグメントの合計が 1 を超えることはなく、これらの合計は依然として慎重にチェックする必要があります。 

## アプローチ

 最も直接的なアイデアは、考えられるすべての連続する部分配列を調べてその合計を計算し、その合計が合成であるかどうかを確認することです。 プレフィックスの合計を使用すると、各部分配列の合計を一定時間で計算できます。 これにより、l と r に対する二重ループが発生し、テスト ケースごとにおよそ O(n²) 個の部分配列が得られます。 n の合計は最大 1000 なので、これで十分です。 

ブルートフォースアプローチは、すべての候補セグメントを明示的にチェックするため、正しいです。 その弱点は冗長性です。作業のほとんどは、他のセグメントですでにチェックされている可能性のある値の合計を再計算し、素数を繰り返しテストすることです。 

この改善は、すべての部分配列の合計が制限された範囲内にあることに気づいたことによって得られます。 各 ai は最大 1000、n は最大 1000 であるため、合計は最大 1,000,000 になります。 これにより、一度ふるいを使用してすべての可能な合計の素数を事前計算することができます。 その後、各セグメント チェックは O(1) になり、ソリューション全体が非常に小さな定数を含む純粋な O(n²) スキャンに変わります。 

セグメント長を昇順に繰り返すことで、最小の答えの検索をさらに改善できます。 与えられた長さの有効なセグメントが初めて見つかったとき、その長さは最適です。

 ## アルゴリズムのチュートリアル

 私たちは最適化されたアプローチに重点を置いています。

1. サブ配列の合計を定数時間で取得できるように、プレフィックス合計配列を計算します。 これにより、合計を繰り返し再計算することが回避され、各候補セグメントを効率的に評価できるようになります。 
2. エラトステネスの篩を使用して、可能な最大合計までの素数をマークするブール配列を事前計算します。 素数のマークが付いていない 1 より大きい数値は、自動的に合成されます。 これにより、素数チェックが O(1) ルックアップに変わります。 
3. 1 から始めて、可能なすべてのサブ配列長にわたって反復します。 長さの順序を増やす理由は、可能な限り最小のセグメント サイズが必要であるため、最初の有効なオカレンスがすでに最適になっているためです。 
4. 各長さについて、配列全体でウィンドウをスライドさせ、プレフィックスの差を使用してその合計を計算します。 合計が 1 より大きく、素数でない場合は、長さから 1 を引いた値がすぐに返されます。 
5. すべての長さをチェックした後、有効なセグメントが見つからない場合は、-1 を出力します。 

### なぜ効果があるのか

 このアルゴリズムは基本的に、セグメント長を増加させることによって順序付けされた有限の候補セットを検索します。 すべてのセグメントは、長さが考慮されたときに正確にテストされ、前処理により素数分類が正確になります。 最初の有効なセグメント長で停止するため、より小さい解をスキップすることはできず、より大きな解が途中で選択されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(n):
    is_prime = [True] * (n + 1)
    if n >= 0:
        is_prime[0] = False
    if n >= 1:
        is_prime[1] = False
    i = 2
    while i * i <= n:
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_prime[j] = False
        i += 1
    return is_prime

def solve():
    data = sys.stdin.read().strip().split()
    t = int(data[0])
    idx = 1

    tests = []
    max_sum = 0

    for _ in range(t):
        n = int(data[idx])
        idx += 1
        arr = list(map(int, data[idx:idx+n]))
        idx += n
        tests.append(arr)
        max_sum = max(max_sum, sum(arr))

    # safe upper bound for any subarray sum is also sum of full array max
    is_prime = sieve(max_sum)

    out = []

    for arr in tests:
        n = len(arr)
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + arr[i]

        ans = -1

        for length in range(1, n + 1):
            found = False
            for l in range(0, n - length + 1):
                r = l + length
                s = pref[r] - pref[l]
                if s > 1 and not is_prime[s]:
                    ans = length - 1
                    found = True
                    break
            if found:
                break

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```解決策は、すべてのテストにわたって可能な最大サブ配列合計までふるいを構築することから始まります。 これにより、その後のすべての素数チェックが直接配列検索になることが保証されます。 

次に、各テスト ケースは、すべての部分配列の合計が O(1) で計算されるようにプレフィックス合計配列を構築します。 ネストされたループはセグメントの長さを増やして、最初の一致が最適であることを保証します。 合成合計セグメントが見つかった瞬間に、内部スキャンと長さループの両方から早期に中断されます。 

よくある実装ミスは、1 が合成ではないことを忘れていることです。そのため、条件では明示的に`s > 1`。

 ## 特殊なケース

 アルゴリズムでは最初に長さ 1 がチェックされるため、4 などの合成数を含む単一要素配列はすぐに処理されます。 そのセグメントのプレフィックスの合計は 4 ですが、4 は素数ではなく 1 より大きいため、受け入れられ、アルゴリズムは 0 を返します。 

すべて 1 の配列は、合計が 1 に等しいことを拒否することの重要性を示しています。長さ 1 のすべてのセグメントは合計 1 を持ち、より長いセグメントは 2、3、4 などの合計を生成します。最初の合成は、セグメントが 4 または 6 のような合計に達した場合にのみ表示され、アルゴリズムは長さを昇順にスキャンするため、そのような最小のセグメントを正しく見つけます。 

のようなすべての素数の場合`[2, 3, 5]`は、合成和はより長いセグメントにのみ現れる可能性があり、アルゴリズムはふるいベースのチェックにより素数和を時期尚早に受け入れないことを示しています。
