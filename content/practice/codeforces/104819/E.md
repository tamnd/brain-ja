 ## 解決策
 ## 問題の理解

 各ノードが都市を表し、各都市が数値的な魅力値を持つ有向非巡回グラフが与えられます。 旅行者は指示された道路に沿って都市 1 から都市 n まで行かなければなりません。 グラフ構造ではサイクルがないことが保証されているため、すべての有効なルートは DAG 内の単純なパスになります。 

経路上のどこかに、訪問都市 x → y → z が 3 つ連続して存在し、その魅力値の合計が小さい場合、特に ax + ay + az ≤ k である場合、そのルートは不良とみなされます。 タスクは、最適なルートを見つけたり、何かを数えたりすることではなく、この禁止されたトリプル条件を回避する 1 から n までの有効なパスが少なくとも 1 つ存在するかどうかを判断することだけです。 

主な問題点は、制約がエッジやノードのペアに対してローカルではなく、パスに沿った長さ 3 のすべてのスライディング ウィンドウに依存することです。 これにより、標準的な DAG 到達可能性の問題が、最後の 2 つの頂点のメモリに関する制約付きパスの実現可能性の問題に変わります。 

制約は大きく、テストあたり最大 3×10^5 のノードとエッジ、最大 10^3 のテスト ケースがあります。 これにより、パスを明示的に列挙しようとするアプローチは即座に除外されます。これは、中程度の分岐 DAG であっても、指数関数的に多くのパスが生成されるためです。 すべての状態のペアまたはトリプルに対する動的プログラミングであっても、慎重に圧縮しない限り、サイズが大きすぎます。 

DAG 内にパスが存在するが、可能な継続によって少なくとも 1 つの禁止トリプルが強制される場合、微妙な例外ケースが発生します。 もう 1 つの特殊なケースは、パスが非常に短い場合、つまりノードが 3 つ未満である場合です。この場合、制限はトリガーされず、有効なパスはすべて自動的に受け入れられます。 

## アプローチ

 ブルートフォースのアイデアは単純です。ノード 1 からノード n までのすべてのパスを探索し、パスを延長するたびに最後の 3 つのノードが条件に違反するかどうかを確認します。 グラフは DAG であるため、パス上の DFS または BFS は終了します。また、すべての候補ルートの制約を明示的に検証するため、正確さがすぐにわかります。 

問題は、DAG 内の個別のパスの数が n で指数関数的に増加する可能性があることです。 層ごとに 2 つの選択肢がある単純な層状グラフでも、実行可能な計算をはるかに超える 2^(n/2) 個のパスが生成されます。 欠けている構造は、パスが多数あるにもかかわらず、条件が完全な履歴ではなく最後の 2 つのノードにのみ依存するということです。 

これは、トラバースの状態を最後の 2 つの頂点のみを記憶するものに圧縮することを示唆しています。 ただし、状態 (u, v) に対する単純な DP は、u から来て v にいることを意味し、O(mn) 以上の遷移につながり、最悪の場合でもまだ大きすぎます。 

重要な観察は、何も最適化しておらず、存在をチェックしているだけであるということです。 したがって、考えられるすべての (u, v) ペアを追跡する代わりに、すぐに不良トリプルを作成する遷移を枝刈りしながら、どのペアが到達可能であるかを伝播するだけで済みます。 各有向エッジ u → v は、p + u + v > k の場合にのみ状態 (p, u) から拡張できます。 

これにより、問題は、ノードが元のノードの順序付きペアであるリフト グラフの到達可能性に変換されます。 実際には、このグラフには最大 m 個の状態を含めることができますが、有効な拡張を形成する場合にのみ各エッジが処理されるように遷移を制限できます。 グラフは DAG であるため、ノードをトポロジカルな順序で処理し、各ノード v について、制約に違反せずに到達できる可能性のある前のノード p のセットを維持できます。 

有効な遷移に対してのみ隣接関係を維持し、無効なトリプルをオンザフライでフィルタリングしながら、エッジを介して到達可能性を効果的に伝播することで、すべてのペアを明示的に保存することを回避します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス | 指数 | O(n) | 遅すぎる |
 | DAG 上のペア状態 DP | O(n^2) 最悪 | O(n^2) | 遅すぎる |
 | 枝刈りされたペア遷移によるエッジ緩和 | 状態遷移ごとに平均 O(m)、全体で O(m) から O(2m) まで償却 | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DAG のトポロジー的順序を計算します。 これにより、ノードを処理するときに、考えられるすべての先行ノードがすでに考慮されることが保証されます。 トランジションは有向エッジに沿ってのみ前方に移動するため、この順序付けは不可欠です。 
2. 各ノード v について、v で終わるトリプルの条件に違反しない p → v で終わるパスが存在するように、すべての有効な先行ノード p を記録するセットまたは隣接構造を維持します。これは、パスを正しく拡張するために必要なメモリを表します。 
3. ノード 1 を先行状態なしで到達可能としてマークして初期化します。 概念的には、ノードが 1 つだけある開始状態を許可するため、トリプル制約はまだ適用できません。 
4. トポロジ順にノードを処理します。 各有向エッジ u → v について、u のすべての有効な先行エッジ p を考慮します。 このような各ペア (p, u) は、u で終わるパスの有効なサフィックスを表します。 
5. このような各状態 (p、u) について、p + u + v > k を検証することによって、v を追加すると不正なトリプルが形成されるかどうかを確認します。 それが有効であれば、到達可能性を拡張し、p に関する v の有効な先行者として u を記録できます。 
6. これらの遷移を前方に伝播し続け、必要に応じて重複した状態をマージします。 重要なのは、絶対パスを保存せず、制約を適用するために必要な最後の 2 つの頂点のみを保存することです。 
7. 最後に、ノード n に到達可能な有効な先行状態があるかどうかを確認します。 「はい」の場合、制約に違反しない絶対パスが少なくとも 1 つ存在します。 

### なぜ効果があるのか

 このアルゴリズムは、格納されているすべてのペア (p, u) が、連続するトリプルがすべてすでに検証されている 1 から u までの実パスに対応するという不変条件を維持します。 v への拡張は、新しいトリプル (p、u、v) が有効な場合にのみ受け入れられるため、無効なパスが導入されることはありません。 考えられるすべての有効な拡張がトポロジ順に 1 回だけ考慮されるため、1 から n までの有効なパスは最終的にノード n の状態で表現され、完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        g = [[] for _ in range(n)]
        indeg = [0] * n
        
        edges = []
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            indeg[v] += 1
            edges.append((u, v))
        
        # topological sort
        q = deque([i for i in range(n) if indeg[i] == 0])
        topo = []
        while q:
            u = q.popleft()
            topo.append(u)
            for v in g[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)
        
        # dp[v] = set of possible predecessors p such that (p -> v) is valid suffix
        dp = [set() for _ in range(n)]
        
        dp[0].add(-1)  # virtual predecessor
        
        for u in topo:
            for v in g[u]:
                for p in dp[u]:
                    if p == -1:
                        # only two nodes so far
                        dp[v].add(u)
                    else:
                        if a[p] + a[u] + a[v] > k:
                            dp[v].add(u)
        
        if dp[n - 1]:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```コードは、グラフを読み取り、トポロジカル ソートのための次数カウントとともに隣接リストを構築することから始まります。 トポロジカルな順序付けにより、ノードを処理するときに、ノードに到達するすべての方法がすでに考慮されていることが保証されます。 

動的プログラミング配列`dp[v]`は、遷移を通じて前のステップを暗黙的に記憶しながら、有効なパスの v の直前に出現する可能性のあるすべてのノードを保存します。 センチネル値`-1`は、トリプル制約がまだ存在しない、長さ 1 のパスを表します。 

遷移中、すべてのエッジ u → v は、u で終わるすべての既知の有効な接尾辞を拡張しようとします。 サフィックスが 3 ノードより短い場合は、常に遷移を受け入れます。 それ以外の場合は、伝播を許可する前に合計条件を明示的にチェックします。 

最後に、答えは、有効な先行状態がノード n に存在するかどうかによって異なります。 

微妙な点は、状態圧縮が非対称であることです。履歴の 1 レベルのみを明示的に保存し、u のすべての有効な先行データを表すために dp[u] に依存します。 これは、すべてのトリプル チェックで dp[u] にエンコードされている u の直前の要素のみが必要なため、機能します。 

## 実用的な例

 a1 = 1、a2 = 2、a3 = 3、k = 10 の単純なチェーン 1 → 2 → 3 を考えてみましょう。 

dp[1] = {virtual} から始めます。 ノード 1 でノード 2 に伝播し、dp[2] に 1 を追加します。 ノード 2 では、先行ノードが仮想であるため、ノード 3 への遷移を受け入れ、dp[3] に 2 を追加します。 ノード 3 は到達可能であるため、答えは「はい」です。 

| ノード | dp 状態 | 理由 |
 | --- | --- | --- |
 | 1 | {-1} | 開始 |
 | 2 | {1} | 最初の遷移 |
 | 3 | {2} | トリプル制約はまだありません |

 ここで、トリプル制約ブロックが 1 → 2 → 3 → 4 と進行するケースを考えます (a = [5, 5, 5, 5]、k = 12)。 

ノード 3 では、トリプル (1,2,3) がすでに 15 を与えており、条件に違反しているため、dp[3] は空になり、ノード 4 に到達できなくなります。 

| ノード | dp 状態 | 有効なトランジション |
 | --- | --- | --- |
 | 1 | {-1} | 開始 |
 | 2 | {1} | わかりました |
 | 3 | {} | ブロックされました |
 | 4 | {} | 到達不能 |

 これは、中間ノードのすべての状態が無効になると、継続は回復できないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) 平均、O(m · S) 最悪 | 各エッジは有効な先行状態のみを伝播します。 
| スペース | O(n + m) | 隣接関係と DP セット |

 有効な状態遷移はそれぞれ 1 回だけ作成されるため、アルゴリズムは一般的な DAG 構造のエッジの数において線形です。 テストあたり最大 3x10^5 エッジという制約を考慮すると、無効なトリプルを早期に枝刈りすることで状態セットが制御され続ける限り、これは時間制限内に問題なく収まります。

 ## 特殊なケース

 長さ 2 の短いパスは制約をトリガーしません。 たとえば、エッジが存在する場合、トリプルが形成されないため、任意の値を指定した 1 → 2 は常に Yes を返します。 dp[2] は仮想先行関数を使用して dp[1] から直接初期化され、三重チェックを完全にバイパスするため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、ノードに複数の先行ノードが存在するが、有効な継続につながるのは 1 つだけである場合です。 そのノードで設定された dp には複数の候補が含まれている可能性がありますが、三重制約を通過したものだけがさらに伝播します。 これにより、無効な履歴が将来の状態を汚染することがなくなります。 

最後の微妙なケースは、dp が大きくなる場合です。 dp は先行ノードを格納するため、段階的に増加する可能性があります。 ただし、保存されているすべてのエントリは少なくとも 1 つの有効なパス プレフィックスに対応しており、重複はセット セマンティクスによって自然に回避され、冗長な伝播が防止されます。
