 ## 問題の理解

 単一の小文字文字列が与えられ、そのパターンが含まれる部分文字列がいくつあるかを数えるように求められます。`"sysu"`続編として。 部分文字列は文字列の連続したセグメントを選択することによって定義されますが、部分シーケンスでは順序を変更せずに文字をスキップできます。 部分文字列内で、その綴りの順序で 4 つの文字を選択できる場合、その部分文字列は有効であるとみなされます。`s → y → s → u`。 

入力長は 100 万文字まで可能です。 すべての部分文字列を明示的に検査しようとするソリューションはすぐに除外されます。$O(n^2)$部分文字列や部分文字列ごとの線形スキャンでさえ、実行可能な限界を何桁も超えてしまいます。 これにより、各位置が償却定数または対数時間に寄与する方法が求められます。 

文字列に重複するパターン文字が多数含まれる場合、微妙なエッジ ケースが発生します。 たとえば、`"ssyyssuu"`、複数の部分文字列は、同じ文字位置をさまざまな方法で再利用して部分シーケンスを形成します。 部分文字列ごとの単純な貪欲スキャンも、部分列インデックスを選択するための複数の有効な方法が正しく考慮されていない場合、失敗する可能性があります。 正しい答えは、一意性ではなく、存在にのみ依存します。 

## アプローチ

 ブルートフォース戦略では、すべての部分文字列が列挙されます。$[l, r]$、それぞれについて次のことを確認します。`"sysu"`サブシーケンスとして作成できます。 単一の部分文字列のチェックは長さが線形であるため、総コストは次のようになります。$$\sum_{l=1}^{n} O(n-l) = O(n^2)$$それは遅すぎる$n = 10^6$。 

重要な観察は、実際には、すべての部分文字列について部分列の実現可能性を最初から再計算する必要がないということです。 代わりに、視点を逆転させて、終了位置を修正します。$r$、有効な開始位置の数を数えます$l$で終わる部分文字列を生成します$r$。 

固定された右端点の場合、部分文字列に次の部分列一致が含まれるように、すべての左端点が必要です。`"sysu"`。 部分一致の数を維持しながら文字列を左から右にスキャンすると、`"sysu"`各ポジションで終了すると、この問題を、完全な試合が何回完了したか、そしてそれとペアになることができるより早い開始の回数を数えるということに変換できます。 

これを表現する標準的な方法は、パターン状態に対する動的プログラミングです。 パターンをこうしましょう$p =$ `"sysu"`。 文字列のスキャン中に、パターンの各プレフィックス状態になれる方法 (または開始アンカーの数) が何通りあるかを追跡します。 キャラクターを見つけると、パターン内で前方へのトランジションを更新します。 最後の文字に到達するたびに`'u'`、現在のインデックスで終わる完全なサブシーケンスが形成され、状態 3 に到達するのに寄与したすべての有効な開始位置が、ここで終わる有効な部分文字列を形成します。 

問題は、文字列の接頭辞ごとに、どれだけの方法で接頭辞を一致させることができるかを維持することに帰着します。`"sysu"`現在の位置で終了するサブシーケンスとして、パターンが完了したときに寄与を合計します。

 ## アルゴリズムのチュートリアル

 治療します`"sysu"`4 状態のオートマトンとして。 状態 0 は何も一致しなかったことを意味し、状態 1 は一致したことを意味します`'s'`、状態 2 は、`"sy"`、状態 3 は、`"sys"`、状態 4 はフルを意味します`"sysu"`。 

1. 配列を初期化する`dp`サイズ 5 の場合`dp[i]`最初のものと一致した方法が何通りあるかを表します`i`現在の位置までのサブシーケンスとしてのパターンの文字。 最初は`dp[0] = 1`は空のサブシーケンスを表し、その他はすべて 0 です。この設定により、文字列内の任意の位置から一致を開始できることが保証されます。 
2. 文字列を左から右にスキャンします。 トランジションが 1 つのステップで同じ文字を複数回再利用しないように、文字ごとに DP 配列を右から左に更新します。 これにより、サブシーケンスのカウントの正確さが維持されます。 
3. 現在のキャラクターが`'u'`の部分一致を拡張できます。`"sys"`フルマッチに入る`"sysu"`。 追加します`dp[3]`の中へ`dp[4]`。 このような各拡張は、現在の位置で終了する有効なサブシーケンスを形成する以前のインデックスの個別の選択に対応します。 
4. 現在のキャラクターが`'s'`、以前の一致に応じて、パターンの最初または 3 番目の文字として機能します。 更新します`dp[3] += dp[2]`そして`dp[1] += dp[0]`。 後の更新では同じ反復ですでに変更された値を使用してはいけないため、順序は重要です。 
5. 現在のキャラクターが`'y'`、延長することができます`"s"`の中へ`"sy"`ので、更新します`dp[2] += dp[1]`。 
6. 文字列全体を処理すると、答えは次のようになります。`dp[4]`に等しいサブシーケンスの数を数えます。`"sysu"`存在する。 このような各サブシーケンスは、最初と最後に選択された文字によってエンドポイントが定義されるサブストリングに一意に対応するため、この数は適切なサブストリングの数と一致します。 

### なぜ効果があるのか

 どのインデックスでも、`dp[k]`長さの接頭辞に一致する現在の位置で終了するサブシーケンスを選択する方法の数を表します`k`の`"sysu"`。 不変条件は、各文字が以前の状態を拡張するか無視されるため、すべての有効なサブシーケンス構造が 1 回だけ考慮されるということです。 更新は常にパターンに沿って前進し、単一の遷移で文字を 2 回再利用することはないため、無効な重複は発生しません。 すべての完了した状態 4 は、形成されるインデックスの一意の選択に対応します。`"sysu"`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    # dp[i]: number of ways to form prefix of pattern "sysu" of length i
    dp = [0] * 5
    dp[0] = 1

    for ch in s:
        if ch == 's':
            dp[1] += dp[0]
            dp[3] += dp[2]
        elif ch == 'y':
            dp[2] += dp[1]
        elif ch == 'u':
            dp[4] += dp[3]

    print(dp[4])

if __name__ == "__main__":
    solve()
```この実装では、単一の DP 配列が保持され、それがインプレースで更新されます。 重要な点は、同じ反復内でコントリビューションが誤って再利用されないように、更新が文字ごとに固定された順序で適用されることです。 この構造は、パターンのオートマトンの遷移を直接反映しています。

 ## 特殊なケース

 次のような最小限の文字列`"s"`または`"sy"`DP は最終状態に到達しないため、ゼロが生成されます。 アルゴリズムは、次のようにしてこれを処理します。`dp[4]`スキャン全体を通じて変化しません。 

のような文字列`"sysu"`は、すべての状態を 1 回だけ通過する最も単純な正常な遷移を示しており、各キャラクターがオートマトンを正しく進めることを確認しています。 

次のような繰り返しの多い文字列`"ssssyyyyuuuu"`蓄積動作を実行します。 それぞれ`'s'`可能な開始点が増加します。`'y'`部分的な乗算`"s"`に一致します`"sy"`、そしてそれぞれ`'u'`組み合わせを確定します。 DP はこれらの寄与を再計算せずに蓄積し、完了したすべての状態が有効なサブシーケンスに対応するため、最大限の繰り返しでも正確性が保証されます。
