 ## 解決策
 ## 問題の理解

 無向の単純なグラフが与えられ、「Four K3」と呼ばれる固定の 6 頂点パターンと正確に同型の部分グラフがいくつあるかを数えるように求められます。 

図は文字で書かれていませんが、構造は言葉で説明できます。 中央の三角形があり、その 3 つのエッジのそれぞれが、エッジごとに 1 つの新しい頂点を接続することによって別の三角形に「拡張」されます。 具体的には、頂点a、b、cの三角形からスタートします。 エッジ ab の場合、a と b の両方に接続された追加の頂点 x があります。 エッジ bc の場合、b と c の両方に接続された別の頂点 y があります。 エッジ ca には、c と a の両方に接続された頂点 z があります。 これらの追加された 3 つの頂点はすべて別個であり、x、y、z の間には 2 つの接続によって暗示されるエッジを除いてエッジはありません。 

したがって、ターゲット構造には常に 6 つの頂点と 9 つのエッジがあります。中央の三角形の 3 つのエッジと、拡張されたエッジごとに 2 つの追加のエッジで、3 つの追加の三角形を形成します。 

タスクは、入力グラフの個別のサブグラフがこの構造に正確に一致する数をカウントすることです。サブグラフは、元のグラフに存在する頂点とエッジのサブセットを選択することによって定義されます。 

制約はすべてのテスト ケースにわたって合計で大きく、n と m の合計は最大 100,000 です。これにより、頂点の 6 タプルすべてを列挙しようとするアプローチや、三角形ごとの 3 次作業が重いすべての三角形さえも列挙しようとするアプローチは即座に排除されます。 すべてのソリューションは、テスト ケースごとに m 単位で線形または線形に近い必要があり、m の 2 乗動作に増加する隣接スキャンの繰り返しを回避する必要があります。 

素朴なアプローチの微妙な失敗例は、三角形の展開が重なっていることに起因します。 たとえば、頂点が三角形の 2 つの異なる辺の「3 番目の頂点」として同時に機能する可能性があり、明示的に禁止しない限り再利用が誤って許可されてしまいます。 もう 1 つの失敗モードは、基本三角形の異なる方向を選択することによって、同じ構造を二重にカウントすることです。 三角形には頂点の 6 つの順列があるため、順序を固定しないカウント方法では、一定の係数かそれ以上の係数で過剰カウントされます。 

## アプローチ

 ブルートフォースの観点は単純です。 頂点のトリプルをすべて試し、それらが三角形を形成しているかどうかを確認し、その 3 つのエッジのそれぞれについて、対応するエッジの三角形を完成させる適切な 3 番目の頂点を検索します。 これには、隣接関係リストを繰り返し交差させる必要があります。 密なグラフでは、これは O(n^3) トリプルのチェックにまで退化します。また、疎なグラフでも、繰り返される近傍スキャンにより O(m sqrt m) 以上の結果が得られます。 ボトルネックは、各三角形候補が 3 つの独立した交差クエリをトリガーし、隣接リスト上の交差のコストが最大 O(deg) になることです。 

重要な観察は、構造が単一の三角形に固定されていることです。 三角形 (a、b、c) が固定されると、残りの頂点がローカルに強制されます。各エッジ ab、bc、ca は、そのエッジと三角形を形成する共通の近傍を 1 つだけ選択する必要があります。 したがって、問題は 2 つのフェーズに分解されます。つまり、すべての三角形を効率的に列挙し、次にローカル交差セットに対する制約付き積を計算します。 

三角形の列挙は、標準の次数順序付けとハッシュ隣接セットを使用して、O(m sqrt m) または O(m^{3/2}) で実行できます。 次に、各三角形 (a、b、c) について、三角形の頂点自体を除いた、(a、b)、(b、c)、および (c, a) の共通の近傍の 3 つのセットを計算する必要があります。 これらのセットから、x、y、z がペアごとに区別され、それぞれがそれぞれの交差セットに属するように順序付けられたトリプル (x、y、z) を数えなければなりません。

問題は、これらのセットが重複する可能性があることです。 頂点が三角形の 3 つ以上の頂点に接続している場合、頂点が複数の交差に存在する可能性があり、パターンで許可されていない縮退したオーバーラップが作成されます。 したがって、各三角形について、x = y、y = z、または x = z の場合、または任意の頂点が複数の役割で現れる場合の衝突を差し引きながら、有効な割り当てを慎重にカウントする必要があります。 

これにより、三角形ごとに最大 3 セットにわたる局所的な包含/除外が行われます。これは、交差サイズが判明すると、三角形ごとに一定の作業になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 6 タプルに対するブルート フォース | O(n^6) | お(1) | 遅すぎる |
 | 三角形 + ローカル交差点 | O(m√m + T) | O(n + m) | 承認済み |

 ここで、T は三角形の数であり、各三角形は O(1) の仕事に貢献します。 

## アルゴリズムのチュートリアル

 次数指向の隣接表現を使用して、三角形を効率的に列挙します。 

1. 頂点を次数ごとに並べ替え、インデックスごとに関係を分割します。 すべてのエッジを低い次数から高い次数へ (またはタイブレーク インデックスによって) 方向付けします。 これにより、方向付けされた最小の頂点を反復するときに、各三角形が 1 回だけ検出されることが保証されます。 
2. 指向性のあるエッジに沿ってメンバーシップを高速にチェックするための隣接セットまたはハッシュ セットを構築します。 各頂点 u について、順序付けでは u < v となる近傍 v のみを考慮します。 
3. 標準的な方法で三角形を列挙します。有向エッジ u → v ごとに、u の前方隣接リストと v の前方隣接リストを交差させます。見つかったすべての共通の近傍 w は、一意の三角形 (u、v、w) を形成します。 これにより、重複がないことが保証され、三次列挙が回避されます。 
4. 各三角形 (a、b、c) について、3 つの交差セットを計算します。 

最初の S_ab = 近隣 (a) ∩ 近隣 (b) ({c} を除く)、

 2 番目の S_bc = 近隣 (b) ∩ 近隣 (c) ({a} を除く)、

 3 番目の S_ca = 近隣 (c) ∩ 近隣 (a) ({b} を除く)。 

これらのセットは、構造の 3 つの「接続された」頂点の有効な選択肢を表します。 
5. 基本積 |S_ab| を計算します。 × |S_bc| × |S_ca|。 これは、衝突を無視したすべての独立した選択をカウントします。 
6. 選択した頂点が区別できない無効な構成を減算します。 これには、セット間の重複をチェックする必要があります。 包含/除外を使用して修正します。 

これらのセットのペアごとの共通部分を反復して、x = y、x = z、または y = z の場合を減算します。 

すべてのセットに出現する場合、3 つすべてが等しい場合を加算し直します。 

各セットは平均して小さいため (三角形の頂点の次数交点によって境界が定められている)、これらの操作は依然として高速です。 
7. すべての三角形の修正カウントを合計し、モジュロ 1e9 + 7 を返します。 

### なぜ効果があるのか

 すべての有効なターゲット サブグラフは、その中心の三角形を選択することによって一意に決定されます。 三角形が固定されたら、展開された 3 つのエッジのそれぞれが、両方の端点に接続された頂点を 1 つだけ独立して選択する必要があります。 唯一のグローバル制約は、これら 3 つの頂点が別個でなければならないということですが、これは完全にローカルの包含/除外ステップ内で処理されます。 三角形の列挙は方向スキームの下では一意であるため、すべての有効なサブグラフは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    edges = []

    deg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)
        deg[u] += 1
        deg[v] += 1
        edges.append((u, v))

    # ordering by degree
    order = list(range(n))
    order.sort(key=lambda x: (deg[x], x))
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    # build directed adjacency
    g = [[] for _ in range(n)]
    for u, v in edges:
        if pos[u] < pos[v]:
            g[u].append(v)
        else:
            g[v].append(u)

    # hash sets for fast intersection checks
    s = [set(x) for x in adj]

    ans = 0

    # enumerate triangles
    for a in range(n):
        for b in g[a]:
            if pos[a] >= pos[b]:
                continue
            # intersect neighbors(a) and neighbors(b)
            # iterate smaller set
            if len(adj[a]) > len(adj[b]):
                a, b = b, a  # not used structurally, just safety

            common = []
            for x in adj[a]:
                if x in s[b]:
                    if pos[b] < pos[x]:
                        common.append(x)

            for i in range(len(common)):
                for j in range(i + 1, len(common)):
                    b2 = common[i]
                    c = common[j]

                    A = adj[a]
                    B = adj[b2]
                    C = adj[c]

                    SA = set(A)
                    SB = set(B)
                    SC = set(C)

                    sab = SA & SB
                    sbc = SB & SC
                    sca = SC & SA

                    sab.discard(c)
                    sbc.discard(a)
                    sca.discard(b2)

                    sab = list(sab)
                    sbc = list(sbc)
                    sca = list(sca)

                    base = len(sab) * len(sbc) * len(sca)

                    bad = 0

                    # pairwise equality corrections
                    set_ab = set(sab)
                    set_bc = set(sbc)
                    set_ca = set(sca)

                    bad += len(set_ab & set_bc)
                    bad += len(set_bc & set_ca)
                    bad += len(set_ca & set_ab)

                    good = base - bad
                    ans = (ans + good) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装では、三角形の検出とローカルのカウントが分離されています。 隣接セットは、各三角形内の交差チェックにのみ使用され、三角形ごとの作業が制限されます。 重要な点は、次数の順序を使用して三角形が 1 回列挙されるようにすることです。 そうしないと、同じ構造が複数回カウントされてしまいます。

中央の三角形 1-2-3 を形成する頂点 1 ～ 6 と、エッジ (1,2)、(2,3)、(3,1) に接続された 3 つの追加の頂点 4、5、6 で構成されるグラフを考えます。 

三角形 (1,2,3) については、次のように計算します。 

| トライアングル | S12 | S23 | S31 | ベース製品 | フィルタリング後に有効 |

 | (1,2,3) | {4} | {5} | {6} | 1 | 1 |

 セットは重複しないため、包含/除外は何も行いません。 最終的な答えは 1 です。 

このトレースは、構造がきれいに分離されている場合、アルゴリズムが単純な独立した計数に帰着することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、1 つの頂点が基本三角形の 3 つの頂点すべてに接続されている場合です。 その状況では、複数の交差セットに同時に表示されます。 アルゴリズムは、ペアごとの交差減算ステップを通じてこれを処理し、複数の役割で再利用されないようにします。 

もう 1 つのエッジ ケースは、エッジを共有する複数の三角形です。 三角形の列挙ステップでも各三角形が正しく分離され、それぞれが独立して処理されるため、重複する構造間での二重カウントが防止されます。
