 ## 問題の理解

 正の整数が与えられます$a$。 関数を構築したい$f$正の整数の場合、それを 2 回適用すると、次の乗算のように動作します。$a$、任意の値から開始することを意味します$x$、私たちが適用する場合$f$何度も何度も、私たちは正確に着陸します$a \cdot x$。 同時に、$f$は厳密に増加する必要があるため、自然数の順序は維持されます。 

このようなすべての関数の中で、辞書編集的に最小のものを検討するように求められます。 つまり、私たちが決めるのです$f(1)$、 それから$f(2)$など、関数の有効な完了を可能にする可能な限り最小の値が常に選択されます。 

入力は複数のペアを提供します$(a, x)$、各ペアについて、この辞書編集上の最小関数の値を位置で計算する必要があります。$x$と表します$g(x)$。 

制約は以下に達します$10^5$テストケースと最大値$10^9$したがって、すべての解はテスト ケースごとに線形または対数に近くなければなりません。 大きなプレフィックスを使用して関数を明示的に構築またはシミュレートしようとする試みは、たとえ 1 つのプレフィックスであっても直ちに実行不可能になります。$10^9$範囲の横断は不可能です。 

微妙な問題は、この関数が一度は任意ではないということです。$f(f(x)) = ax$が施行される。 たとえば、次の場合$a = 3$、 それから$f(f(1)) = 3$、 それで$f(1)$そして$f(f(1))$密結合している。 いつもマッピングするような素朴で貪欲な選択$x$に$x+1$2 ステップ後に乗算制約を満たすことができないため、すぐに壊れます。 

もう 1 つの明白ではない落とし穴は、次のように仮定することです。$f$順列または線形スケーリング関数のように動作します。 それはどちらでもありません。厳密には増加していますが、グローバル構造を強制する関数方程式によって定義されます。 

## アプローチ

重要な観察は、次のことによって引き起こされる構造です。$f(f(x)) = ax$整数を独立したチェーンに分割します。 各数値は、次の乗算によって支配される循環のようなペア構造に属します。$a$ただし、厳密な単調性により、これらは非常に特殊なインターリーブ順序になります。 この構造が認識されると、辞書編集的に最小の解決策は、貪欲ではあるが決定論的な方法でソートされた順序で要素をペアリングすることに対応します。 この関数は基本的にペアリング システムのように動作します。すべての値が別の値と照合されるため、$f$2 倍のスケールで$a$、これは次のことを意味します$f$順序制約の下では乗算マップの平方根のように機能します。 

これにより、問題は、位置の構築または特定に縮小されます。$x$を乗算した軌道の因数分解から導出された構造化シーケンスの内部$a$。 各チェーンは単純な交互マッピングを提供し、辞書編集上の最小性により、常に最小の未使用の有効なパートナーを選択することが強制されます。

 ## アルゴリズムのチュートリアル

 1. すべての数値を観察します。$x$固有のパートナーとペアにする必要があります$y$関数を 2 回適用すると、次の結果が返されます。$ax$。 これは、接続する構造上の制約を意味します。$x$、$f(x)$、 そして$a x$。 
2. 条件を次のように書き換えます。$f(f(x)) = ax$。 と表すと$y = f(x)$、 それから$f(y) = ax$。 これは、値が長さ 2 の有向チェーンで接続されていることを示しています。 
3.以来$f$が厳密に増加している場合、これらのチェーンは順序を尊重する必要があります。$x < y$、 それから$f(x) < f(y)$。 これにより、任意のペアリングが防止され、ソートされた一致構造が強制されます。 
4. 整数を次の乗算を繰り返しながら軌道に分解することを検討します。$a$。 それぞれの軌道は次の形式になります。$x, ax, a^2 x, \dots$ただし、2 つのステップを適用するだけなので、構造はペアリングに崩壊します。$x \leftrightarrow f(x) \leftrightarrow ax$。 
5. 各軌道内では、辞書編集上の最小性により、常に利用可能な最小の要素を最初に一致させる必要があります。 これにより、各チェーン内に決定的なペアリング順序が生じます。 
6. いかなる場合でも$x$、軌道上の位置を決定し、ペアリング内で前方または後方にマッピングされるかどうかを決定します。 もし$x$チェーンの順序付けにおいて偶数の位置にある場合、前方にマップされます。 それ以外の場合は、逆方向にマップされます。 
7. コンピューティング$g(x)$完全な関数を構築せずに、このパリティベースの構造を直接使用します。 

### なぜ効果があるのか

 関数制約により、すべての要素が次の乗算によって管理される 2 段階の依存関係チェーンに強制的に参加します。$a$。 厳密な単調性により、チェーン間の交差依存性が排除されます。これは、グローバル構造が独立した順序付けられたシーケンスにきれいに分解されることを意味します。 辞書編集的な最小限性により、各シーケンス内でペアリングが常に後戻りすることなく昇順で行われることが保証され、マッピングが決定的になります。 この順序が固定されると、すべての$x$には有効なパートナーが 1 つだけあるため、計算されたマッピングが制約と矛盾することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        a, x = map(int, input().split())

        # We determine how many times x can be divided by a
        # while staying in the same structural chain.
        # This identifies the "level" of x in its orbit.
        depth = 0
        cur = x

        while cur % a == 0:
            cur //= a
            depth += 1

        # If depth is even, x maps forward; otherwise backward.
        if depth % 2 == 0:
            print(x * a)
        else:
            print(x // a)

if __name__ == "__main__":
    solve()
```コアの実装は、除算を繰り返すという考えに基づいています。$a$どこを特定するか$x$暗黙的な乗法チェーンの中にあります。 そのチェーンは、マッピングを決定するために重要な唯一の構造です。 

この深さのパリティによって、次のことが決まります。$x$は、ローカルの 2 ステップ サイクルでソースまたはシンクとして機能します。 偶数の位置にある場合は、前方にペアリングされます。$ax$。 奇数の位置にある場合は、前の割り当ての逆である必要があるため、次のようにマッピングされます。$x/a$。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        a, x = map(int, input().split())

        depth = 0
        cur = x
        while cur % a == 0:
            cur //= a
            depth += 1

        if depth % 2 == 0:
            out.append(str(x * a))
        else:
            out.append(str(x // a))

    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$x$で割り切れない$a$。 この状況では、除算ループは直ちに終了し、深さは 0 のままになります。 次にアルゴリズムがマッピングします$x$に$ax$、これはチェーンの前方構造と一致しています。 たとえば、$a = 3, x = 2$、深さゼロを取得して出力します$6$これは、2 がチェーン セグメント内の最小要素であることを正しく反映しています。
