 ## 解決策
 ## 問題の理解

 棒の長さのコレクションが与えられ、それらを単純な多角形の辺として機能させるために正確に k 個を選択できるかどうかを尋ねられます。 

私たちが注意する必要がある唯一の幾何学的要件は、一般化された多角形の不等式です。k 個のセグメントのセットは、他のセグメントと比較して長すぎる単一のセグメントがない場合に限り、非縮退の単純な多角形を形成できます。 具体的には、選択した長さをソートすると、選択した最大の長さが残りの k − 1 個の長さの合計より厳密に小さくなければならないという条件になります。 

入力は n 個の候補スティックで構成されており、この不等式を満たすサイズ k のサブセットが存在するかどうかを判断する必要があります。 ポリゴンを構築するのではなく、実現可能性をチェックするだけです。 

n ≤ 3000 という制約は、2 次または 2 次に近いアプローチはギリギリ許容されますが、3 次またはすべてのサブセットの列挙を伴うものは完全に実行不可能であることを意味します。 主な困難は、単に固定セットをチェックするのではなく、グローバルな不等式制約の下でサブセットを選択することです。 

微妙なエッジケースは、多数のスティックが同一である場合、または 1 つのスティックが他のすべてのスティックと比較して極端に大きい場合です。 たとえば、k = 3 で配列が [100, 1, 1] の場合、100 は大きすぎるため、答えは明らかに No になります。 k 個の要素を慎重に選択せずに合計をチェックするだけの単純なアプローチでは、サブセットの選択が重要であることを見落としがちです。 

k が大きい場合、別の失敗ケースが発生します。 たとえば、ほとんどのスティックが小さいが、いくつかのスティックが大きい場合、決定は、大きい要素 (最大値を増やす) と小さい要素 (他の要素の合計を増やす) の選択のバランスに依存します。 貪欲な選択が必要ですが、それは正当化されなければなりません。 

## アプローチ

 ブルートフォース手法では、サイズ k のすべてのサブセットを試し、その合計を計算し、その最大要素を特定し、最大値の 2 倍が合計よりも小さいかどうかを確認します。 これは正しいです。どの候補サブセットでも、ポリゴン条件は 2 * 最大値 < サブセットの合計になるからです。 しかし、部分集合の数は C(n, k) であり、n では指数関数的であり、中程度の k であってもこれは完全に不可能になります。 

条件の構造は、選択された最大の要素と合計の関係のみが重要であることを示唆しています。 すべてのスティックをソートすると、有効なサブセットは、最大の要素が固定されているいくつかの k 個の選択された要素と考えることができ、条件を満たす最良の可能性は、残りの k − 1 要素の合計を最大化することです。 これは、候補の最大値を固定する場合、常にそれよりも小さい残りのスティックのうち k − 1 個の最大の可能性のある残りのスティックとそれをペアにする必要があることを直ちに示唆しています。 

これにより、ソートされた配列に対する貪欲なスイープが行われます。つまり、各要素を潜在的な最大値として扱い、その前の k − 1 個の最大要素が不等式を満たすのに十分であるかどうかを確認します。 プレフィックスの合計を維持することで、ソート後に一定時間で各候補を評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(C(n, k) · k) | O(k) | 遅すぎる |
 | ソート + 貪欲なプレフィックス チェック | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

1. すべてのスティックの長さを昇順に並べ替えます。 これにより、任意の位置を潜在的な最大値として扱うことができると同時に、その左側にあるすべての候補がそれより小さいか等しいことを保証できます。 
2. ソートされたリストに対してプレフィックス合計配列を構築して、任意のセグメントの合計を O(1) 時間で計算できるようにします。 これは、選択したサブセットの合計を繰り返し評価するために必要です。 
3. k − 1 から n − 1 までの各インデックス i について、a[i] を選択した多角形の辺の最大要素として扱います。 
4. ソートされた配列の i の直前の k − 1 要素を考えます。 これらは、a[i] と組み合わせるのに最適な候補です。これより小さい選択肢を選択すると、合計が減少するだけであり、不等式を満たすことが難しくなります。 
5. プレフィックス合計配列を使用して、これらの k − 1 要素の合計を計算します。 
6. 2 * a[i] < sum_of_previous_k_minus_1 + a[i] かどうかを確認します。 これは、a[i] < sum_of_previous_k_minus_1 (多角形の不等式) かどうかをチェックするのと同じです。 
7. いずれかのインデックスが条件を満たす場合は、すぐに Yes を返します。 機能するインデックスがない場合は、No を返します。 

### なぜ効果があるのか

 有効な k セットには一意の最大要素があるため、選択した最大要素を固定するだけで十分です。 固定最大値の場合、ポリゴン条件を満たす可能性を最大化する最適な戦略は、残りの k − 1 個の要素の合計を最大化することです。これは、その下にある k − 1 個の最大の要素をソート順に選択することによって達成されます。 これにより、問題は候補の最大値ごとに 1 つの不等式をチェックすることになります。 すべての有効なサブセットがソートされた配列内の最大候補位置に対応するため、有効な解が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    # prefix sums
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    
    # try each possible maximum position
    for i in range(k - 1, n):
        # sum of k-1 elements before i
        left_sum = pref[i] - pref[i - (k - 1)]
        
        # check polygon condition:
        # largest side a[i] must be < sum of others
        if a[i] < left_sum:
            print("Yes")
            return
    
    print("No")

if __name__ == "__main__":
    solve()
```ソートのステップにより、最大辺の有効な候補のみを昇順で考慮することが保証されます。 プレフィックス配列を使用すると、k − 1 個の最良のコンパニオンの合計を定数時間で計算できます。 重要な実装詳細はウィンドウです`[i - (k - 1), i)`これは常に、サポート側の可能な限り最良の選択を表します。 

不等式は最も単純な形式でチェックされます`a[i] < left_sum`これにより、合計を再計算したり、ポリゴン全体を明示的に推論したりする必要がなくなります。

### 例 2

 入力:```
6 4
1 1 4 5 1 4
```ソートされた配列: [1, 1, 1, 4, 4, 5]

 | 私 | 選択された最大値 | ウィンドウ | 合計(左) | 状態 |
 | --- | --- | --- | --- | --- |
 | 3 | 4 | [1,1,1] | 3 | 4 < 3 false |
 | 4 | 4 | [1,1,4] | 6 | 4 < 6 true |

 i = 4 では、最大の要素として 4 を選択し、先行する 3 つの最良の要素の合計は 6 になります。これは多角形の不等式を満たすのに十分です。 So the answer is Yes.

 このトレースは、各候補最大値に対して可能な限り最良のコンパニオンを選択することが、実現可能性を検出するのに十分であることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    solve()
    sys.stdout = sys.__stdout__
    return output.getvalue().strip()

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    for i in range(k - 1, n):
        left_sum = pref[i] - pref[i - (k - 1)]
        if a[i] < left_sum:
            print("Yes")
            return
    print("No")

# samples
assert run("3 3\n1 2 3\n") == "No"
assert run("6 4\n1 1 4 5 1 4\n") == "Yes"

# minimum n=k=3
assert run("3 3\n1 1 1\n") == "Yes"

# impossible large dominant element
assert run("4 3\n100 1 1 1\n") == "No"

# all equal large k
assert run("5 4\n10 10 10 10 10\n") == "Yes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 3 / 1 1 1 | はい | 有効な最小ポリゴン |
 | 4 3 / 100 1 1 1 | いいえ | 支配的な最大値が条件に失敗する |
 | 5 4 / すべて等しい | はい | 多くの有効なサブセットを持つ対称ケース |

 ## 特殊なケース

 一般的なエッジ ケースは、最大の要素が他のすべての要素と比較して極端に大きい場合です。 入力用`4 3: 100 1 1 1`、ソートすると、`[1, 1, 1, 100]`。 唯一の候補最大値は 100 で、それ以下の最良の 3 要素の合計は 3 です。`100 < 3`はすぐに失敗するため、アルゴリズムは正しく No を返します。 

もう 1 つのケースは、すべての要素が等しい場合です。 のために`5 4: 10 10 10 10 10`、すべての候補最大値には 3 つのサポート要素があり、合計すると 30 になります。`10 < 30`が成立する。 アルゴリズムは有効な i を見つけて、早期に Yes を返します。 

微妙な状況は、k が n に近い場合です。 ウィンドウが存在するため、アルゴリズムはまだ機能します。`[i-(k-1), i)`ほぼ全体のプレフィックスになります。 これにより、1 つまたは 2 つの要素だけが除外された場合でも、不等式が可能な限り最良のサブセットに対して正しく評価されることが保証されます。
