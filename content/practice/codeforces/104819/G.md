 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられており、このシーケンスはポイントの更新によって変更されます。 変更を加えるたびに、多項式を含むかなり特殊なカウント プロセスから得られる値を計算する必要があります。 

多項式は標準​​的な方法で、非負の整数係数を持つ無限の形式的な合計として定義されますが、ゼロ以外の係数は有限の数だけです。 次に、各多項式が配列から取得された特定の値で評価されます。 

固定多項式の場合、配列内の個別のインデックスの順序付きペアをすべて調べます。 最初のインデックスに格納されている値で多項式を評価すると、2 番目のインデックスに格納されている値が正確に生成され、多項式係数がすべて最初のインデックスの値よりも厳密に小さい場合、ペアは寄与します。 

各更新後のキー出力は、1 つの多項式に関するものではなく、考えられるすべての有効な多項式に対するこの寄与の合計に関するものです。 

したがって、入力は動的配列になります。 更新のたびに、概念的には非負の整数係数を持つすべての多項式を考慮し、そのような多項式ごとに、評価時に正しくマッピングされたインデックス ペアの数を数え、これをすべての多項式で合計します。 

この制約により、更新ごとに一定時間で答えを再計算するソリューションが求められます。 最大 20 万回の更新では、配列または多項式構造に対するクエリごとの再計算が遅すぎます。 クエリごとの O(n) でさえすでに境界線に達しており、多項式評価やペアごとの組み合わせカウントを伴うものは実現不可能です。 

微妙な点は、係数の条件がペアの最初のインデックスに依存することです。 つまり、評価の入力として使用されるインデックスに応じて、同じ多項式が異なる係数制限の下で考慮されます。 これは、単純な解釈が間違いやすい主な場所です。 

よくある落とし穴は、多項式の動作が実際の係数の大きさに大きく依存している、またはさまざまな多項式が複雑に重複して寄与していると想定していることです。 もう 1 つの間違いは、多項式を明示的に列挙しようとしたり、多項式を誘導値マッピングを超えて組み合わせオブジェクトとして扱ったりしようとすることですが、これは制限時間内では不可能です。 

## アプローチ

 ブルートフォースの観点は、多項式を修正し、すべてのインデックスのペアをチェックすることから始まります。 各ペアについて、1 つの配列値で多項式を評価し、それを別の配列値と比較すると同時に、最初の値に対する係数制約もチェックします。 多項式の次数を有限のカットオフに制限したとしても、係数割り当ての空間には原理的に制限がなく、小さな切り捨てでさえ組み合わせ論的に爆発します。 これにより、多項式の直接列挙は完全に不可能になります。 

重要な変化は、個々の多項式について考えるのをやめ、代わりに係数の制限の下で多項式がどのような値を生成できるかを推論することです。 非負の整数係数を持つ多項式は、本質的には基本表現メカニズムです。ある点で評価すると、係数が位置記数系の数字に変換されます。 

値 c で評価すると、多項式は a0 + a1 c + a2 c^2 + … という形式の合計になり、ai は非負で厳密に c より小さくなるように制約されます。 これは、c が 0 または 1 の場合の縮退の場合を除き、有効範囲 0 から c-1 の数字を使用して、基数 c の整数を表す定義とまったく同じです。 

この観察により、無限の多項式空間が 1 つの事実に分解されます。つまり、固定評価点 c の場合、c ≥ 2 の場合、すべてのターゲット整数は有効な係数割り当てを 1 つだけ持ち、c が 0 または 1 の場合は非常に限定された動作になります。

各ペアがゼロまたは 1 つの有効な多項式に寄与することを受け入れると、すべての多項式の合計は、単純な表現可能条件を満たすペアの数を数えることになります。 

次に、問題は配列値に関する純粋な組み合わせになります。各値を 0、1、または少なくとも 2 であるかどうかで分類し、グローバルに存在するゼロの数を維持します。

 ## アルゴリズムのチュートリアル

 1. 各配列値を 0、1、または少なくとも 2 つの 3 つのカテゴリのいずれかに分類します。 これは、あるインデックスを別のインデックスにマップできる多項式の数に影響を与える唯一のプロパティです。 
2. 2 つのグローバル カウンタを維持します。配列内のゼロの数と 2 つ以上の要素の数です。 
3. 各インデックス i について、その値カテゴリのみに基づいて、答えへの寄与を決定します。 ci が少なくとも 2 の場合、すべての整数 cj が 1 つの有効な多項式マッピングを持つのに十分な大きさの基底として機能するため、i に等しくないすべての j に対して 1 つの有効な多項式が提供されます。 ci が 1 の場合、係数制限によりすべての係数がゼロになることが強制されるため、多項式はまったくゼロとなり、ゼロに等しいターゲットのみに一致します。つまり、配列内のゼロごとに 1 回寄与します。 ci がゼロの場合、係数制限を満たす多項式はないため、何も寄与しません。 
4. すべての指数に対する寄与度を組み合わせて、合計の答えを形成します。 少なくとも 2 つの値を持つインデックスはそれぞれ (n-1) に寄与し、1 に等しいインデックスは現在のゼロの数に寄与します。 

この削減の背後にある中心的な考え方は、制限された係数を使用した ci での評価により、多項式が ci を基数とする数値体系に変換されるということです。 ci ≥ 2 の場合、この系は完全であり、非負の整数に対して全単射であるため、存在と一意性が保証されます。 ci が 1 または 0 の場合、システムは縮退し、対応関係が崩れ、例外的なケースのみが生成されます。 

不変条件は、すべての有効な多項式が、ci ≥ 2 の場合はペア (i, j) ごとに 1 つのマッピングに寄与し、それ以外の場合は 0 へのマッピングが 1 つだけ寄与し、係数制約によって表現の一意性が強制されるため、隠れた多重度は存在しないということです。 これにより、値カテゴリに基づいたカウントが、過大カウントまたは省略なしですべての多項式の合計と正確に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    c = list(map(int, input().split()))

    zeros = sum(1 for x in c if x == 0)
    ge2 = sum(1 for x in c if x >= 2)

    def recompute():
        return ge2 * (n - 1) + sum(1 for x in c if x == 1) * zeros

    ones = sum(1 for x in c if x == 1)

    # maintain full consistency via counts
    ones = sum(1 for x in c if x == 1)

    for _ in range(q):
        i, y = map(int, input().split())
        i -= 1

        old = c[i]
        if old == 0:
            zeros -= 1
        elif old == 1:
            ones -= 1
        else:
            ge2 -= 1

        c[i] = y

        if y == 0:
            zeros += 1
        elif y == 1:
            ones += 1
        else:
            ge2 += 1

        print(ge2 * (n - 1) + ones * zeros)

if __name__ == "__main__":
    solve()
```最終的な式では厳密には 2 つだけが必要ですが、実装は 3 つの単純なカウントを暗黙的に維持することに依存しています。 少なくとも 2 の値を持つインデックスの寄与は n にのみ依存するため、固定乗数とそのカウントの積に減少します。 1 に等しいインデックスにはグローバル ゼロ カウントが必要なため、ゼロを追跡することが不可欠です。 

実装の微妙な詳細は、答えを再計算する前にカウントを更新することです。 新しい値を挿入する前に古い値が正しく削除されないと、0 と 1 のカテゴリがドリフトし、最終的な乗算で誤ったクロスターム寄与が生じます。 

## 実用的な例

 長さ 3 の配列 [2, 0, 1] を考えてみましょう。 ここで、0 = 1、1 = 1 です。 

値 2 のインデックスは (n−1) = 2 に寄与します。値 0 のインデックスは 0 に寄与します。値 1 のインデックスはゼロの数 (1) に寄与します。合計は 3 です。 

次に、2 番目の要素を 0 から 2 に変える変更を処理し、[2, 2, 1] を与えます。 これで、ゼロ = 0、1 = 1 になります。 

2 値のインデックスはそれぞれ 2 を寄与し、1 値のインデックスは 0 を寄与します。合計は 4 になります。 

| ステップ | 配列 | ゼロ | もの | ゲ2 | 計算された答え |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | [2,0,1] | 1 | 1 | 1 | 3 |
 | 更新 | [2,2,1] | 0 | 1 | 2 | 4 |

 トレースは、回答の構造がカテゴリ数のみに依存し、しきい値分類を超える実際の数値には依存しないことを示しています。 カテゴリごとの貢献度に関する不変条件は、更新後も安定しています。 

## 複雑さの分析

 ## 特殊なケース

 すべての値がゼロの場合、すべてのインデックスは、係数制約を満たす多項式が存在しない禁止されたカテゴリに分類されます。 両方の寄与項が消滅するため、アルゴリズムは正しくゼロを生成します。つまり、1 も大きな値も存在しません。 

すべての値が 1 の場合、係数制限により、すべての多項式が強制的にゼロ多項式に折りたたまれます。 各インデックスはゼロの数を正確に反映しており、この場合はゼロであるため、すべての更新にわたって答えはゼロのままです。 

値が 1 から少なくとも 2 の間で変動する場合、支配項はゼロカウント スケーリングと (n-1) スケーリングの間で切り替わります。 アルゴリズムはカテゴリ数を段階的に更新するため、再計算せずにこれらの遷移を正確に追跡します。
