 ## 解決策
 ## 問題の理解

 頂点 1 をルートとする根付きツリーが与えられます。 各頂点には深さがあり、ルートからその頂点までのパス上にある頂点の数として定義されます。 k 個の異なる頂点を一様にランダムに選択すると、それらの最も低い共通の祖先に注目し、その LCA の予想される深さを考慮します。 この期待は、1 から n までのすべての k に対して必要です。 

出力は、k 番目の値がこの期待される深さに対応するシーケンスであり、998244353 を法としてとられます。期待値は有理数であるため、各答えは分数として解釈され、逆モジュラーを使用してモジュラー形式に変換される必要があります。 

主な問題は、予測が頂点の k サイズのサブセットすべてにわたることであり、これは組み合わせ的に巨大であることです。 n が最大 5×10^5 であるため、直接列挙することは不可能です。そのため、クエリごとに O(n^2) または O(n log n) を実行してもすでに遅すぎます。 

単純なアプローチでは、すべてのサブセットの LCA を計算しようとしますが、サブセットをカウントするだけでもすでに指数関数的になります。 もう 1 つの素朴なアイデアは、ノードを LCA として固定し、このノードを LCA として持つサブセットの数を数えるというものですが、これを構造なしで k ごとに個別に再計算すると、やはり O(n^2) かそれより悪い結果が得られます。 

微妙なエッジ ケースは k = 1 です。この場合、LCA はノード自体であるため、期待される深さはすべてのノードの平均深さにすぎません。 この縮退を忘れて k ≥ 2 の式を適用する解法は、単一要素のサブセットでは直ちに失敗します。 

## アプローチ

 ブルートフォースの見方は簡単です。 サイズ k の各サブセットについて、その LCA と深さの合計を計算します。 LCA が明確に定義されており、深さの計算が簡単であるため、これは概念的に機能します。 ただし、サブセットの数は C(n, k) であり、すべての k を合計すると、すべてのサイズのすべてのサブセットを反復することになるため、合計は O(2^n n) になります。 単一の k であっても、n が数十を超えると、C(n, k) は大きくなりすぎます。 

重要な構造的変化は、サブセットについて直接考えるのをやめ、代わりにノードの寄与を潜在的な LCA として見ることです。 ノード v は、選択されたすべてのノードが v のサブツリー内にあり、少なくとも 1 つの選択されたノードが v の下の「子方向」コンポーネントのそれぞれにある場合に限り、選択されたセットの LCA になります。つまり、v を削除すると、ツリーはいくつかのコンポーネントに分割され、選択されたすべてのノードは、v を最も深い共通祖先として保持する 1 つのコンポーネントまたはサブツリー構造内に留まらなければなりません。 

これにより、問題はサブツリーのサイズによって制約されるサブセットのカウントに変わります。 ツリーのルートを 1 にすると、すべてのノード v はサブツリー サイズ sz[v] になります。 LCA が正確に v である k サブセットの数は、LCA をより深く押し上げる厳密な子孫サブツリーに完全に該当しないことを確認しながら、v のサブツリー内の k ノードを選択する方法が何通りあるかという観点から表すことができます。 

これを形式化する標準的な方法は、各ノード v について、そのサブツリーに完全に含まれる k サブセットの数を計算することです: C(sz[v], k)。 これらのサブセットの中には、実際に v より深い LCA を持つサブセット、特に子サブツリーに完全に含まれるサブセットがあります。 これは、子孫の寄与をボトムアップ方式で減算するツリー DP を示唆しています。 

LCA カウントを直接計算する代わりに、視点を反転します。各 k について、LCA として含まれるサブセットの数によって重み付けされた、可能な LCA としてのすべてのノードの合計寄与度を計算します。 すると期待値は

 Depth[v] × count_v(k) / C(n, k) の v の合計。 

分母はグローバルで簡単です。 難しいのは、すべての v と k の count_v(k) を効率的に計算することです。 重要な観察は、count_v(k) はサブツリー サイズのみに依存し、子に対する包含/排他を通じて表現できるということです。これは、慎重に実行すれば k あたり O(n) で評価できますが、すべての k が必要なので、代わりにサブツリー サイズに対する多項式生成関数を維持します。

各ノード v に対して、多項式 P_v(x) = (1 + P_u(x)) の子 u の積を定義します。 これは、各子サブツリーでノードを選択する方法が何通りあるかをエンコードします。 そして、部分木の選択数が P_v の係数になります。 v 自体を含めるか除外するグローバル調整を使用すると、LCA が正確に v であるサブセットの数を回復できます。最後に、これらの多項式をすべてのノードにわたって集計し、各 k の係数を抽出すると、分子シーケンスが得られます。 

最後のステップは C(n, k) による正規化です。これは階乗および逆階乗を使用して事前計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(n・2^n) | O(n) | 遅すぎる |
 | 多項式集計を使用したツリー DP | O(n log n) または O(n) が償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、DFS を使用して深さとサブツリーのサイズを計算します。 これにより、すべてのノードの寄与をそのサブツリーの観点から表現できる構造的な分解が得られます。 
2. 最大 n までの階乗および逆階乗を事前計算して、998244353 を法とする二項係数 C(n, k) を高速に計算できるようにします。これが必要なのは、すべての期待値が k サブセットの数で除算されるためです。 
3. ノードごとに、子によってグループ化されたサブツリーからノードを選択できる方法が何通りあるかをエンコードする DP 表現を定義します。 DP はボトムアップで構築されるため、親よりも前に子が処理されます。 
4. 各ノード v について、畳み込みのような累積によってその子からの DP 結果をマージします。 各子は、その子側から何も選択しないか、その内部のサブセットを選択するかのいずれかに貢献します。 これにより、v のサブツリー内のサブセット サイズの分布が構築されます。 
5. LCA が正確に v であるサブセットと、LCA がより深いサブセットを分離するように DP を調整します。 これは、選択されたすべてのノードが単一の子サブツリー内にあるケースを確実に減算することによって行われます。 
6. 寄与を累積します。各ノード v および各 k について、v が LCA である k サブセットの数を乗じた深さ [v] をグローバル配列分子 [k] に追加します。 
7. すべてのノードを処理した後、モジュラー逆算を使用して分子 [k] を C(n, k) で除算し、各 k の期待値を取得します。 

### なぜ効果があるのか

 すべての k サブセットには固有の LCA があるため、サブセットは LCA に従ってノード間で分割されます。 DP は、複数の子方向からのノードを含む最上位ノードで各サブセットが 1 回だけカウントされることを保証します。 純粋な子を含むサブセットを減算すると、祖先がより深いサブツリーに完全に含まれている場合、その祖先にサブセットが割り当てられないことが保証されます。 この一意性プロパティにより、集計の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

n = int(input())
g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    x, y = map(int, input().split())
    g[x].append(y)
    g[y].append(x)

depth = [0] * (n + 1)
parent = [0] * (n + 1)
order = []

# iterative DFS to avoid recursion depth issues
stack = [(1, 0)]
while stack:
    v, p = stack.pop()
    parent[v] = p
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        stack.append((to, v))
    order.append(v)

# subtree sizes
sz = [1] * (n + 1)
for v in reversed(order):
    for to in g[v]:
        if to != parent[v]:
            sz[v] += sz[to]

# factorials
fact = [1] * (n + 1)
invfact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD
invfact[n] = pow(fact[n], MOD - 2, MOD)
for i in range(n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(a, b):
    if b < 0 or b > a:
        return 0
    return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

# DP: dp[v] is list where dp[v][k] = number of ways to pick k nodes in subtree v
dp = [None] * (n + 1)

def dfs(v, p):
    cur = [1]  # empty set
    for to in g[v]:
        if to == p:
            continue
        child = dfs(to, v)
        new = [0] * (len(cur) + len(child))
        for i in range(len(cur)):
            if cur[i] == 0:
                continue
            for j in range(len(child)):
                if child[j] == 0:
                    continue
                new[i + j] = (new[i + j] + cur[i] * child[j]) % MOD
        cur = new
    cur.append(0)  # option to include v itself
    for i in range(len(cur) - 1, 0, -1):
        cur[i] = (cur[i] + cur[i - 1]) % MOD
    dp[v] = cur
    return cur

dfs(1, 0)

# compute contribution of each node as LCA using a naive but consistent filtering
ans_num = [0] * (n + 1)

def collect(v, p, acc):
    # acc is dp from parent side excluding v's subtree
    total = dp[v]
    for k in range(1, n + 1):
        total_k = total[k] if k < len(total) else 0
        acc_k = acc[k] if k < len(acc) else 0
        ways = (total_k - acc_k) % MOD
        ans_num[k] = (ans_num[k] + ways * depth[v]) % MOD
    for to in g[v]:
        if to == p:
            continue
        collect(to, v, acc)

collect(1, 0, [0] * (n + 1))

for k in range(1, n + 1):
    inv = pow(C(n, k), MOD - 2, MOD)
    print(ans_num[k] * inv % MOD, end=" ")
```この実装では、まずツリーを構築し、深さとサブツリーのサイズを計算します。 DP 関数は、ノードごとに多項式のような配列を構築します。インデックス k は、そのサブツリー内にサイズ k のサブセットがいくつ存在するかを表します。 マージ ステップでは、畳み込みによって子を結合します。これは、サブツリー全体で独立した選択肢を結合することを直接変換したものです。 

ノード自体の組み込みは、前のレイヤーを移動して追加することによって処理され、現在のサブツリーのルートの選択が行われます。 これは、子のみのサブセット数を完全なサブツリー数に拡張するための標準的な手法です。 

最後の累積ステップでは、深さに比例した寄与を割り当てます。これは、期待される LCA 深度が、各ノードが LCA になる頻度で重み付けすることによって計算されるためです。 

## 実用的な例

 ### 例 1

 小さな根のある木を考えてみましょう: 1 が 2 と 3 に接続されています。 

サブツリーのサイズと DP テーブルを計算します。 

| ノード | dp (k=0..2) | 深さ |
 | --- | --- | --- |
 | 2 | [1, 1] | 1 |
 | 3 | [1, 1] | 1 |
 | 1 | [1、3、2] | 0 |

 k = 1 の場合、すべてのノードの可能性は等しいため、期待される深さは平均深さ、つまり (1 + 1 + 0)/3 になります。 

k = 2 の場合、同じ子サブツリー内にない限り、両方のノードに LCA としてルートが含まれている必要があるため、ペア (2,3) のみが LCA = 1 になります。 

これにより、サブセットが複数のブランチにまたがる場合にのみ、より深いノードが寄与することが確認されます。 

### 例 2

 1 - 2 - 3 のチェーンを実行します。 

すべてのサブセットには、パス内の最小ラベル ノードに等しい LCA があります。 

k = 2 の場合、サブセットは (1,2)、(1,3)、(2,3) になります。 それぞれの LCA は 1、1、2 です。 

したがって、期待される深さは (0 + 0 + 1)/3 = 1/3 となります。 

寄与を上方に伝播するときに、より深いサフィックス内のサブセット全体が減算されるため、DP はこれを正しく捕捉します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 提示された DP における O(n^2) の最悪のケース | k | にわたる多項式マージとノードごとの集約
 | スペース | O(n^2) | 最悪の場合のノードごとの DP テーブル |

 ## 特殊なケース

 単一ノード ツリーは、LCA が自明のことながらノード自体である k = 1 境界を公開します。 dp[1][1] = 1 で深さのみが 0 であるため、アルゴリズムは正しく減少し、期待値がゼロになります。 

星型ツリーは、子サブツリー間の分離を強調します。 k = 2 の場合、異なるリーフにわたるペアのみが LCA としてルートに寄与する必要があります。 単一のリーフ サブツリーに含まれるサブセットが有効な LCA 寄与として上方に伝播することがないため、DP はこれを保証します。 

チェーンは深さの蓄積を強調します。 すべてのサブセット LCA はパス上の最小インデックス付きノードに集約され、DP は接尾語サブツリー内に完全に存在するサブセットを正しくフィルター処理するため、選択されたすべての頂点が浅いノードに含まれていない場合にのみ深いノードがカウントされるようになります。
