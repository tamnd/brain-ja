 ## 解決策

 ## 問題の理解

 最大 600 個の頂点を持つ未知の接続された単純なグラフが与えられます。 私たちはその端を直接見ることはできません。 代わりに、頂点のサブセットを選択し、両方の端点が完全にそのサブセット内にあるエッジの数を受け取るという形式の質問のみを行うことができます。 

この制限されたインターフェイスを使用して、グラフが 2 部構成であるかどうかを判断する必要があります。 2 部構成の場合は、有効なパーティションを 1 つ出力する必要があります。 そうでない場合は、奇数サイクルを証明書として出力する必要があります。 

主な難点は、個々のエッジを任意に大量にクエリすることができないことと、ブール値を決定するだけでなく証明を構築する必要があることです。 20000 クエリという対話制限は非常に厳しいため、最悪の場合グラフ全体を再構築することは不可能です。そのため、どのソリューションでも不要なエッジの学習を回避する必要があります。 

この制約は、頂点に対する二次戦略であってもクエリ数に関してはギリギリ許容できるが、すべてのペアまたはすべての隣接リストを明示的に探索するものは制限を超えることを意味します。 これにより、グラフの完全な再構成が即座に除外され、二部性を証明するのに十分な疎な構造のみを構築する方向に進むことになります。 

グラフが非 2 部である場合、微妙なエッジ ケースが現れますが、最初に検出されたいくつかのエッジはすべて、2 部に見えるスパニング構造内にあります。 単純な DFS ツリーは常に 2 部構成に見えます。 矛盾は、非ツリー エッジが同じパリティの 2 つの頂点を接続する場合にのみ発生します。 アルゴリズムがそのようなエッジを積極的に検索しない場合、非二部グラフで誤って「YES」を報告する可能性があります。 

もう 1 つの失敗モードは、すでに検出されているコンポーネント内の隠れたエッジを考慮せずに、頂点ごとに 1 つの近傍を検出すれば十分であると仮定することから生じます。 二部違反はツリー エッジだけでなく、任意のクロス エッジによって引き起こされるため、これでは不十分です。 

## アプローチ

 ブルートフォース戦略では、隣接マトリックス全体が再構築されます。 頂点のペアごとに、それら 2 つの頂点だけを含むセットをクエリします。 答えはエッジが存在するかどうかを直接教えてくれます。 これは約を使用します$n^2/2$クエリ。$n = 600$クエリ数は約 180,000 で、制限の 20,000 をはるかに超えています。 正しいとしても、使用できません。 

重要な点は、完全なグラフは必要ないということです。 必要なのは、有効な 2 色塗りを構築するか、単一の奇数サイクルを検出するための十分な構造だけです。 どちらの目標も、スパニング構造と競合するエッジを時折チェックすることで達成できます。 

すべてのエッジを再構築する代わりに、DFS のようなツリーを段階的に構築します。 必要な唯一の高価な操作は、与えられた頂点とセットに対して、それらの間にエッジが存在するかどうかを判断することです。 これは、包含-除外を使用する単一のサブセット クエリで実行できます。セット内のエッジの数がすでにわかっている場合は、頂点を 1 つ追加することで、その頂点をセットに接続するエッジの数を検出できます。 

これを使用すると、頂点に対する二分探索により、候補セット内の頂点の単一の近傍を見つけることができます。 これにより、近隣すべてのスキャンが回避されます。 重要なのは、すべてのエッジを検索しようとするのではなく、構造の接続を維持するために、頂点ごとに関連するエッジを 1 つだけ検索することです。 

スパニング ツリーが構築されたら、BFS パリティによって色を割り当てます。 次に、同じ色の頂点を接続する余分なエッジがあるかどうかを検出するだけで済みます。 ここでもサブセット クエリを使用して、頂点からカラー クラスにそのような「悪い」エッジが存在するかどうかをテストします。 見つかった場合は、スパニング ツリー内の親ポインタを使用して奇数サイクルを再構築します。 

これにより、グラフ全体の再構築からクエリ バジェット内に収まる選択的なエッジ検出へと問題が軽減されます。

 ## アルゴリズムのチュートリアル

 検出された頂点の増加する接続セットと頂点 1 をルートとするツリーを維持します。また、二部チェックのための親ポインターと色の割り当ても維持します。 

### 1. 頂点 1 から開始します

 頂点 1 を検出されたとおりに初期化し、カラー 0 を割り当て、外側へのスパニング ツリーの構築を開始します。 

### 2. 未発見の頂点の最初の接続を見つける

 新しい頂点の場合$v$、すでに検出されている頂点に接続しようとします。 これを効率的に行うために、検出された頂点のリストを維持します。$D$。 どうかを知りたいのです。$v$隣人がいる$D$はいの場合は、1 つ見つけます。 

サブセットクエリを使用して接続性を計算します: 任意のサブセットに対して$S$、間のエッジの数を計算できます。$v$そして$S$の答えを比較することで$S \cup \{v\}$キャッシュされた値を使用して$S$。 結果がゼロ以外の場合、少なくとも 1 つのエッジが存在します。 

次に二分探索を行います$D$単一の隣人を隔離します。 私たちは別れました$D$半分に分割し、それぞれの半分をテストし、エッジを含む半分のみを再帰的に実行します。 これにより、次の親が 1 つ見つかります。$v$。 

### 3. 頂点をアタッチし、ツリー構造を割り当てます。 

かつて隣人だった$u$見つかったので設定します$u$の親として$v$、 マーク$v$発見されたとおりに、反対の色を割り当てます$u$。 これにより、有効な DFS ツリー構造が維持されます。 

### 4. 潜在的な二者違反を検出する

 取り付け後$v$、すでに発見されているノードの中で同じ色の頂点へのエッジがあるかどうかを確認する必要があります。 同じサブセット検索を繰り返しますが、次のカラークラスに限定されます。$v$。 そんな頂点を見つけたら$x$、同じ色の頂点を結ぶエッジを発見しました。 

### 5. 競合が発生した場合は奇数サイクルを構築する

 エッジを見つけたら$(v, x)$両方のエンドポイントが同じ色を共有する場合、親ポインターを使用してサイクルを再構築します。 私たちはから歩きます$v$根元まで、そしてそこから$x$パスが分岐するまでルートに接続し、パスを結合して余分なエッジでサイクルを閉じます。 両方の頂点がパリティを共有するため、結果として得られるサイクルの長さは奇数になります。 

### なぜ効果があるのか

 不変条件は、発見された構造が常に頂点のサブセットの有効なスパニング ツリーであり、すべての頂点にツリーの深さと一致する色が割り当てられることです。 二部性に違反するエッジは、等しい深度パリティの頂点を接続する必要があり、そのようなエッジは、両方のカラー クラスに対して新しい頂点ごとに明示的に検索されます。 すべての頂点は以前に発見された構造に対してチェックされるため、違反エッジは最終的に、そのより深い端点が処理されるときに検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def ask(vertices):
    print("?", len(vertices))
    print(*vertices)
    flush()
    return int(input())

def build_path(v, parent):
    path = []
    while v != -1:
        path.append(v)
        v = parent[v]
    return path

def get_edge_between(v, candidates, get_inside_cache):
    """
    Find one neighbor of v inside candidates using binary search.
    get_inside_cache(S) returns number of edges inside S.
    """
    if not candidates:
        return -1

    base = get_inside_cache(frozenset(candidates))
    # We will test subsets by splitting candidates
    def dfs(arr):
        if len(arr) == 1:
            return arr[0]
        mid = len(arr) // 2
        left = arr[:mid]
        right = arr[mid:]

        # check left
        if left:
            s = frozenset(left + [v])
            val = get_inside_cache(s) - get_inside_cache(frozenset(left))
            if val > 0:
                return dfs(left)

        return dfs(right)

    return dfs(candidates)

def main():
    n = int(input())

    # cache for subset queries: map frozenset -> answer
    cache = {}

    def get_inside(S):
        S = frozenset(S)
        if S in cache:
            return cache[S]
        res = ask(list(S))
        cache[S] = res
        return res

    parent = [-1] * (n + 1)
    color = [-1] * (n + 1)
    used = [False] * (n + 1)

    used[1] = True
    color[1] = 0
    discovered = [1]

    for v in range(2, n + 1):
        # find a neighbor in discovered set
        u = get_edge_between(v, discovered, get_inside)

        if u == -1:
            continue

        parent[v] = u
        used[v] = True
        color[v] = color[u] ^ 1
        discovered.append(v)

        # check conflict in same color class
        same = [x for x in discovered if color[x] == color[v] and x != v]
        w = get_edge_between(v, same, get_inside)

        if w != -1:
            # odd cycle reconstruction
            pv = set(build_path(v, parent))
            pw = set(build_path(w, parent))

            # find LCA-like meeting point
            a = v
            path_v = []
            while a not in pw:
                path_v.append(a)
                a = parent[a]
            path_v.append(a)

            b = w
            path_w = []
            while b != a:
                path_w.append(b)
                b = parent[b]

            cycle = path_v + path_w[::-1]

            print("N", len(cycle))
            print(*cycle)
            return

    # bipartite
    part = [i for i in range(1, n + 1) if color[i] == 0 and used[i]]
    print("Y", len(part))
    print(*part)

if __name__ == "__main__":
    main()

サイクルの再構築は、スパニング ツリーからの親ポインターに依存します。 競合するエッジが見つかると、両方の端点からツリー内の最初の交差点まで歩くことによってサイクルが形成されます。

### 例 2: 三角形の検出

 頂点 1、2、3 上の三角形を考えてみましょう。 

| ステップ | 頂点 | 隣人が見つかりました | 親 | 色 | 紛争 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | - | -1 | 0 | - |
 | 2 | 2 | 1 | 1 | 1 | - |
 | 3 | 3 | 1 または 2 | 1 | 1 | エッジから 2 トリガーの競合 |

 頂点 3 を処理する場合、頂点 1 にアタッチされる可能性がありますが、同じカラー クラスに対するサブセット検索により、同じくカラー 1 を持つ頂点 2 へのエッジが明らかになります。これにより、すぐに奇数のサイクル (3 → 1 → 2 → 3) が生成されます。 

これは、アルゴリズムがスパニング ツリーのみに依存せず、二部性の違反を積極的に検索する方法を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、完全な 2 部グラフなど、グラフが 2 部であるが非常に高密度である場合です。 この場合、すべての頂点には多くの潜在的な隣接点がありますが、アルゴリズムは依然として頂点ごとに 1 つの親のみを検出するため、二次爆発は回避されます。 

もう 1 つの重要なケースは、グラフに奇数のサイクルが含まれているが、ほとんどのエッジが無関係な部分に隠れている場合です。 頂点がアタッチされるとすぐに競合がチェックされ、両方のエンドポイントが検出されると違反エッジが無視されないことが保証されるため、アルゴリズムは依然としてサイクルを検出します。
