 ## 解決策
 ## 問題の理解

 まず、辺が長い正方形の布を作ります。$a$。 1 つの角から見た、小さな正方形の辺$b$切り取られています。 残った布は L 字型の領域であり、その面積は単純に大きな正方形の面積から削除された正方形の面積を引いたものになります。$a^2 - b^2$。 

タスクは、出力のためにこの領域を直接計算することではなく、結果として得られる数値が素数であるかどうかを判断することです。 

各テスト ケースはペアを提供します$(a, b)$かどうか答えなければなりません。$a^2 - b^2$プライムです。 

制約は非常に大きいです。$a$そして$b$まで行くことができます$10^{11}$、つまり$a^2$到達できる$10^{22}$。 これにより、すべてのテスト ケースについて、単純な方法で値自体またはその平方根までの試行除算によって数値を因数分解しようとするアプローチは即座に除外されます。 平$O(\sqrt{n})$テストケースごとに繰り返し実行すると境界線になるため、$\sqrt{10^{22}} = 10^{11}$、これは大きすぎます。 

ここでの重要な構造は、任意の数値が与えられるわけではないということです。 値は常に 2 平方の差であり、因数分解の動作を制限する強い代数的性質があります。 

微妙なエッジケースが現れるのは、$a$そして$b$とても近いです。 例えば、$a=34, b=33$与える$34^2 - 33^2 = 67$、これは素数です。 ただし、次のようなわずかに大きなギャップの場合は、$16, 13$、私たちは得ます$87$, 数字は小さいですが、合成されています。 もう 1 つの特殊なケースは、式が偶数になる場合です。 2 より大きい偶数は自動的に非素数となり、これにより計算なしで多くのケースがすでに除外されます。 

## アプローチ

 ブルートフォースアプローチでは、次のように計算されます。$a^2 - b^2$次に、試行除算を使用して素数性をテストします$\sqrt{a^2 - b^2}$。 正しいですが、その差は次のように大きくなる可能性があるため、これは実行不可能です。$10^{22}$、素数性テストには最大で次のことが必要になります。$10^{11}$最悪の場合のテスト ケースごとの反復回数。 

重要な洞察は、式を書き直すことで得られます。$$a^2 - b^2 = (a-b)(a+b)$$この因数分解が決定的です。 この数値は常にゼロより大きい 2 つの整数の積であり、その構造は非常に制限されています。 

以来$a > b$、どちらの因数も正の整数です。 また、$a+b > a-b$、両方とも 1 以上です。 2 つの整数の積が素数になる唯一の方法は、それらの 1 つが 1 に等しい場合です。 

そこで私たちは、いつできるのか尋ねます。$(a-b)(a+b)$素数に等しいですか？ 

素数には、1 とそれ自体の 2 つの正の約数があります。 したがって、因数の 1 つは 1 でなければなりません。$a+b \ge 2$したがって、唯一の可能性は次のとおりです。$$a - b = 1$$もし$a-b = 1$の場合、式は次のようになります。$$(1)(2b+1) = 2b+1$$したがって、次の場合に限り、結果は素数になります$2b+1$プライムです。 

これにより、問題は次の数値に対する単一の素数テストに縮小されます。$2 \cdot 10^{11}$までの決定論的な試行分割で管理可能です。$\sqrt{n}$、または奇数の除数のみを使用したより高速なチェック。

 | 最適 |$O(\sqrt{b})$有効なケースごと (早期拒否により一定の場合が多い) |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 重要なアイデアの設定

 1. コンピューティング$d = a - b$。 これにより、因数分解を素数のようなものに還元できる唯一の部分が分離されます。 
2. もし$d \neq 1$、すぐに「NO」を返します。 これは、数値が厳密に 1 より大きい 2 つの整数の積となり、合成されるためです。 
3. もし$d = 1$、計算する$x = a^2 - b^2 = (a-b)(a+b) = 2b + 1$。 
4. かどうかを確認します。$x$までの試行除算を使用する素数です$\sqrt{x}$。 
5. プライムの場合は「YES」を返し、それ以外の場合は「NO」を返します。 

重要な観察は、すべての複雑さが、構造が候補素数に縮退する単一の特殊なケースに崩壊することです。 

### なぜ効果があるのか

 不変条件は、すべての有効な値が$a^2 - b^2$まさに次のように因数分解します$(a-b)(a+b)$。 以来$a+b > a-b$両方とも 1 以上の整数である場合、一方の因数が 1 でない限り、式は合成になります。これを満たす唯一の方法は次のとおりです。$a-b = 1$、これは問題を単一の導出数値の素数テストに独自に削減します。$2b+1$。 自明でない因数分解は直ちに素数に違反するため、他の構造は素数を生成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(n: int) -> bool:
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2
    i = 3
    while i * i <= n:
        if n % i == 0:
            return False
        i += 2
    return True

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    
    if a - b != 1:
        print("NO")
    else:
        val = 2 * b + 1
        print("YES" if is_prime(val) else "NO")
```実装は、些細な拒否ケースの分離に依存しています。$a-b \neq 1$唯一意味のあるケースから。 これにより、大きな数値の演算が回避されます。$a^2$直接的に、オーバーフローの懸念や不必要な計算を防ぎます。 

素数チェックは、2 を処理した後に偶数をスキップすることによって最適化されます。これは、次の構造を考慮すると十分です。$2b+1$、いつも奇妙です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def is_prime(n: int) -> bool:
        if n < 2:
            return False
        if n % 2 == 0:
            return n == 2
        i = 3
        while i * i <= n:
            if n % i == 0:
                return False
            i += 2
        return True

    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        if a - b != 1:
            out.append("NO")
        else:
            out.append("YES" if is_prime(2 * b + 1) else "NO")
    return "\n".join(out)

 ## 特殊なケース

 ### ケース:$a-b > 1$入力用$a=10, b=7$、私たちは得ます$a-b=3$。 アルゴリズムはすぐに「NO」を返します。 これは正しいです。なぜなら、$a^2-b^2 = (a-b)(a+b) = 3 \cdot 17 = 51$、これは複合です。 

計算が素数テストに到達することはなく、不必要な作業が回避されます。 

### ケース: 最小限の差

 のために$a=3, b=2$、私たちは得ます$a-b=1$, そこで計算します$2b+1=5$。 素数性テストにより 5 が素数であることが確認されるため、出力は「YES」になります。 これは、ロジックが 2 番目のブランチをアクティブにする最小の非自明なケースです。 

### ケース: 大きな値

 のために$a=10^{11}, b=10^{11}-1$、アルゴリズムは次のように計算します。$2b+1 \approx 2 \cdot 10^{11}$。 素数チェックが実行されます$O(\sqrt{b})$ただし、必要な反復回数は数十万回だけであるため、これでも簡単に適合します。$t \le 5$。 

これにより、上限に達してもソリューションが適切にスケーリングされることが確認されます。
