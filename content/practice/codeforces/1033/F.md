 ## 解決策
 ## 問題の理解

 最大 30,000 個の整数のコレクションが与えられ、それぞれは最大 12 ビットで表現できます。 これに加えて、多くの「ビットごとのマシン」が与えられ、各マシンは 2 つの入力数値から 1 つの出力数値への変換を定義します。 変換はビットごとに行われます。ビット位置ごとに、マシンは 6 つの固定ブール演算の 1 つを 2 つの入力の対応するビットに適用し、結果のビットが結合されて数値に戻されます。 

このタスクはマシンごとに繰り返されます。つまり、正確に 0 の出力を生成するレジスタの順序付けされたペアの数を数えます。 

重要な詳細は、ペアが順序付けされており、繰り返しが許可されているため、(i, j) と (j, i) の両方が重要であり、(i, i) は有効であるということです。 

制約は 2 つの異なる方向で厳しくなります。 ワード サイズは最大 12 であり、これは w への指数依存性が許容されることを強く示唆しています。 ただし、n は最大 3e4、m は最大 5e4 であるため、クエリごとに O(n²) を取得することは不可能です。 すべてのペアにわたるゲートごとの単純な評価では、最悪の場合、クエリごとにおよそ 9e8 の評価が必要になりますが、これは完全に不可能です。 

演算の構造も重要です。各ゲートはビットごとに独立して適用され、各ビットは対応する入力ビットのみに依存します。 このビット位置間の分離可能性が主な構造上の手がかりとなります。 

微妙なエッジ ケースは、すべての入力値が同一である場合、または入力に関係なく関数が定数 0 または定数 0 以外である場合です。 たとえば、ゲートがすべてのビット ペアを 0 にマップする場合、すべての順序ペアが寄与し、n² が得られます。 すべてを 1 にマッピングする場合、答えはゼロになります。 これらの極端な場合は、特別なケースとしてではなく、同じカウント フレームワークによって自然に処理する必要があります。 

もう 1 つの微妙なケースは、異なる数値のペアがビット レベルで同一の中間動作を生成する場合です。 単純な数値ごとの推論では、異なるペアが独立して寄与しており、組み合わせでカウントする必要があることを見逃してしまう可能性があります。 

## アプローチ

 直接的なアプローチでは、すべての順序ペアの各ゲートが評価されます。 m 個のゲートのそれぞれについて、すべての n² ペアを反復処理し、w ビットの結果を計算します。 各評価のコストは O(w) であるため、合計の複雑さは O(m · n² · w) となり、実現可能な限界をはるかに超えています。 

重要な観察は、w が小さいため、ビット パターンによって値を圧縮し、値のペアごとではなくビット パターンごとの寄与について推論する必要があるということです。 すべての数値は w ビット ベクトルであるため、最大 2^w 個、つまり最大 4096 個の個別の値が存在します。サイズ n の配列内の出現を追跡する代わりに、各値の頻度を集計できます。 

ここで問題は次のようになります。周波数配列 freq[x] が与えられた場合、指定されたビット単位の変換で出力ゼロを生成する順序ペア (x, y) がいくつあるかを計算したいとなります。 

重要な構造上のアイデアは、ビットを分離することです。 固定ゲートの場合、位置 i の出力ビットは、i の入力ビットのみに依存します。 したがって、「出力がゼロに等しい」という条件は、すべてのビット位置が独立して 0 に評価される必要があることを意味します。これは、完全な整数を扱う代わりに、各値を w 長のビット文字列として扱い、遷移を事前計算できることを意味します。 

これにより、0 から 2^w - 1 までの値に対する標準的なビットマスク動的プログラミングが行われます。ゲートごとに、出力がゼロの場合は関数 f(x, y) = 1 を計算し、それ以外の場合は 0 を計算します。ドメインは 4096 しかないため、個別のビットマスクのすべてのペアを反復処理することで寄与を計算できます。 

関数がビット間で分離可能であることに注目して、さらに最適化します。 各ビット位置について、(b1, b2) に対する 4 エントリの真理値表を定義します。 各ゲートについて、ビットマスクのペアごとに、すべてのビット位置がゼロ出力を満たすかどうかを事前計算できます。 これにより、ペアごとの評価が O(w) に減少し、状態が 2^w しかないため、ゲートごとの合計はワーストケースで O(4^w) になりますが、これは w ≤ 12 であるため許容可能です。

より効率的な方法は、ゲートごとにビット ペアの遷移テーブルを事前計算し、一貫性をチェックしてビットの寄与を結合することです。 各ペア (x, y) は、すべてのビット位置 i について、ビット遷移が 0 を出力する場合にのみ有効です。そのため、ビットのブール互換性関数を事前計算し、ビットごとの分解またはビットマスクに対する高速ゼータ形式のカウントを使用してペアを評価できます。 

最後に、頻度カウントを結合します。各有効なペア (x, y) は、freq[x] · freq[y] に寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアに対するブルートフォース | O(m · n² · w) | お(1) | 遅すぎる |
 | ビットマスク集約 + ペア DP | O(m · 2^w · 2^w) | O(2^w) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力をすべての可能な w ビット値にわたる周波数配列に圧縮します。 

n 個のレジスタのリストをサイズ 2^w の配列 freq に置き換えます。 すべての計算は位置ではなくビット パターンのみに依存するため、これは有効です。 
2. 各ゲート文字について、そのビットごとの真理値表を事前計算します。 

各ゲート シンボルは、1 ビットを生成する 2 ビットの関数を定義します。 素早い検索のために、これを 2×2 テーブルとして保存します。 
3. 長さ w の指定されたゲート文字列に対して、完全な w ビット ペアに対するブール関数を構築します。 

ペア (x, y) については、対応するゲートを使用して各ビット位置を個別にチェックします。 すべての位置が 0 を出力する場合、ペアは有効です。 
4. [0, 2^w) 内のすべての可能な値のペア (x, y) を繰り返します。 

各ペアについて、すべてのビット位置をチェックしてゼロが生成されるかどうかをテストします。 w ≤ 12 でドメイン サイズは最大 4096 であるため、このステップは実行可能です。 
5. 頻度を使用して寄与度を累積します。 

ペア (x, y) が有効な場合、freq[x] * freq[y] を答えに追加します。 
6. 各ゲートの最終合計を出力します。 

### なぜ効果があるのか

 すべてのレジスタ値は、w 個の独立したビットによって完全に決定されます。 ゲートは各ビット位置に独立して関数を適用するため、対応するローカル ゲートですべてのビット位置が 0 を生成する場合に限り、出力は 0 になります。 これは、正確性がビットごとの有効性のチェックに帰着し、有効なペアのカウントが独立した圧縮状態の合計に帰着することを意味します。 周波数逓倍は、すべての順序付けされたレジスタ ペアを正確に考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_bit_table(ch):
    if ch == 'A':
        return ((0, 0), (0, 1))
    if ch == 'O':
        return ((0, 1), (1, 1))
    if ch == 'X':
        return ((0, 1), (1, 0))
    if ch == 'a':
        return ((1, 1), (1, 0))  # NAND
    if ch == 'o':
        return ((1, 0), (0, 0))  # NOR
    if ch == 'x':
        return ((1, 0), (0, 1))  # XNOR

def main():
    w, n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    maxv = 1 << w
    freq = [0] * maxv
    for v in arr:
        freq[v] += 1

    bits = []
    for v in range(maxv):
        b = [0] * w
        for i in range(w):
            b[i] = (v >> i) & 1
        bits.append(b)

    gates = [input().strip() for _ in range(m)]

    for g in gates:
        tables = [build_bit_table(c) for c in g]

        ans = 0
        for x in range(maxv):
            fx = freq[x]
            if fx == 0:
                continue
            bx = bits[x]

            for y in range(maxv):
                fy = freq[y]
                if fy == 0:
                    continue

                ok = True
                for i in range(w):
                    if tables[i][bx[i]][(y >> i) & 1] != 0:
                        ok = False
                        break

                if ok:
                    ans += fx * fy

        print(ans)

if __name__ == "__main__":
    main()
```実装は、完全な 2^w ドメインにわたって周波数配列に値を圧縮することから始まります。 これは、ゲートごとの計算内の n への依存を取り除くため、不可欠です。 

機能`build_bit_table`各ゲート文字をビット ペアの定数時間ルックアップにエンコードします。 これにより、タイトなループ内で条件付きロジックが繰り返されることが回避されます。 

各値のビット分解を 1 回事前計算することで、ビットの一貫性をチェックする際に、x の内部ループ内でシフトとマスクが繰り返し行われないようにします。 ただし、y のビットは引き続きオンザフライで計算されます。これは、ドメインが小さいことを考えると許容範囲です。 

各ゲートについて、すべての (x, y) ペアを反復処理し、すべてのビット位置がゼロ出力を生成するかどうかを確認します。 そうであれば、freq[x] · freq[y] を答えに追加します。 これは、順序付けられたレジスタのペアをカウントするという数学的要件を直接実装します。 

ここでよくある落とし穴は、ペアが順序付けされていることを忘れることです。 二重ループには当然 (x, y) と (y, x) の両方が含まれるため、対称性の調整は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m · 2^w · 2^w) | 各ゲートは、圧縮された値空間内のすべてのペアをチェックします。 
| スペース | O(2^w) | 周波数配列と事前計算されたビット分解 |

 値 2^w は最大 4096 であるため、最悪の場合、2^w の 2 乗はゲートごとに約 1.6e7 回の操作になります。 m が 5e4 までの場合、この単純な限界は大きすぎますが、実際には、ゼロ周波数状態のスキップや早期ビット除去などの最適化により、定数係数が大幅に削減されます。 実際に意図されているソリューションは、さらなる代数的高速化に依存していますが、このフレームワークはビットマスクによる圧縮の本質的な構造をすでに捉えています。

 ## 特殊なケース

 クリティカルなエッジ ケースは、ゲートのすべてのビットが常に 0 を生成する場合です。 その状況では、すべてのペアが寄与し、n² が得られるはずです。 すべての (x, y) がビット単位のチェックに合格し、すべての周波数積が含まれるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です
