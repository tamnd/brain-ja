 ## 解決策
 ## 問題の理解

 1 から n までの位置の行に配置された値の順列が与えられます。 トークンは任意の位置から開始され、2 人のプレイヤーが交互にトークンを動かします。 移動は、値が厳密に増加する位置 i から位置 j にジャンプし、位置間の距離が現在の位置の値で割り切れる場合にのみ正当です。 

これは、ポジションに関する有向グラフを定義します。i から、a[j] > a[i] および (j - i) mod a[i] = 0 となる任意の j に進むことができます。ゲームは、DAG 上の標準的な公平なゲームで、ポジションは、少なくとも 1 つの手が負けポジションに移動した場合に勝ち、すべての手が勝ちポジションに移動した場合は負けとなります。 

出力では、開始ノードごとに、最初のプレーヤーが勝つかどうかが尋ねられます。 

主な問題は、各ノードが他の多くのノードに接続する可能性があり、n が最大 100,000 になる可能性があるため、エッジの二次探索が不可能であることです。 各ノードには O(n / a[i]) 個の候補があり、合計すると O(n log n) になるか、敵対的なケースではさらに悪化するため、構造なしでノードごとにすべての有効なジャンプを反復するだけでも遅すぎます。 

値が大きい場合、微妙なエッジケースが発生します。 たとえば、a[i] = n の場合、出ていくエッジがまったくないため、すぐに負けになります。 a[i] = 1 の場合、より高い値はすべて到達可能であり、接続性が高くなります。 ノードごとの単純な BFS または DFS は、同じ構造を何度も繰り返し走査し、TLE を引き起こします。 

重要な隠れた構造は、厳密に大きな値にのみ移動するため、エッジは常に小さなラベルから大きなラベルへ向かうことです。 これにより、値による自然なトポロジー順序が得られます。 

## アプローチ

 ブルート フォース アプローチでは、各開始位置の結果を個別に計算します。 固定 i について、a[j] > a[i] となるすべての j を列挙し、割り切れる条件を確認します。 そのような j ごとに、j が勝っているか負けているかを再帰的に判断します。 

これが機能するのは、グラフが値の増加に関して非循環的であるため、再帰が終了するためです。 ただし、最悪の場合は密集します。 各 i に対して O(n) 個の有効な遷移が存在する可能性があり、合計 O(n^2) 個の遷移になります。 n が 10^5 までの場合、これは完全に不可能です。 

重要な観察は、遷移は a[i] を法とする剰余クラスにのみ依存するということです。 各ノードを独立して処理するのではなく、値の昇順にノードを処理し、固定ステップ サイズの間隔でジャンプする場合の到達可能な勝敗状態をクエリできる構造を維持します。 

各値 x について、a[i] = x であるすべての位置 i を考慮します。 i から、より大きな値と i モジュロ x に一致するインデックスを持つ位置 j を調べるだけで済みます。 これは、各モジュラス x のインデックス残基クラスごとに位置をグループ化することを示唆しています。 

可能なステップ サイズ x ごとに、各剰余 r モジュロ x について、すでに処理されたより大きな値の中でそのクラスに勝ちの位置が存在するかどうかを示す事前計算された配列を維持します。 値 x を処理するときに、それより大きい値はすべてすでに確定されているため、値を最大から最小の順に処理することで正確さが保証されます。 

これにより、各遷移クエリが剰余クラス チェックごとに償却される O(1) に削減され、除数にわたる調和限界により合計作業量が管理可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 残基グループ化による値ソート DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 値を n から 1 まで降順に処理するため、dp[i] を計算するときに、a[j] > a[i] のすべての dp[j] がすでにわかっています。

1. ブール配列 dp[i] を維持します。ここで、現在のプレーヤーが位置 i から開始して勝つ場合、dp[i] は true になります。 
2. j mod x = r で既に処理された (大きい値) 位置 j の中に、負けている位置 dp[j] = false が存在するかどうかを格納する補助構造 Bucket[x][r] を維持します。 
3. 値を降順に処理します。 値 x を処理するときは、a[i] = x であるすべてのインデックス i を考慮します。 
4. このような各インデックス i について、すでに処理された位置 j = i + kx および i - kx をスキャンすることによって、すべての剰余 r = i mod x を間接的にチェックします。 
5. 到達可能な j のいずれかが dp[j] = false である場合、損失状態に移行できるため、dp[i] = true になります。 
6. 到達可能なすべての j が dp[j] = true の場合、dp[i] = false になります。 
7. dp[i] を計算した後、将来のより小さな値がそれを使用できるように、すべての約数 x の剰余構造に i を挿入します。 

重要なアイデアは、各位置が O(a[i] の約数の数)) 個の剰余バケットに挿入され、各バケットの更新によって情報が前方に伝播されるということです。 

### なぜ効果があるのか

 DP は、値によって順序付けされた DAG の標準的な後方帰納法です。 唯一重要な部分は、圧縮されたトランジションの正確さです。 固定 x の場合、i からのすべての正当な手は x の間隔の位置に着地します。 クエリ時にそれらを列挙する代わりに、既に処理されたノード間に損失状態が存在するかどうかを残差クラスごとに維持します。 大きい値が最初に処理されるため、dp[i] を計算するときに、すべての有効なターゲットがすでに構造内に存在します。 これにより、すべてのエッジを明示的に反復することなく、完全なグラフ DP と同様に dp[i] が正確に計算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(a, 1):
        pos[v] = i

    dp = [False] * (n + 1)
    maxv = n

    # bucket[x][r] = whether there exists a losing state among processed nodes
    bucket = [dict() for _ in range(n + 1)]

    active = [False] * (n + 1)

    for val in range(n, 0, -1):
        i = pos[val]
        win = False

        step = val
        r = i % step

        # check forward and backward jumps in residue class
        j = i + step
        while j <= n:
            if active[j] and not dp[j]:
                win = True
                break
            j += step

        if not win:
            j = i - step
            while j >= 1:
                if active[j] and not dp[j]:
                    win = True
                    break
                j -= step

        dp[i] = win
        active[i] = True

    res = ['A' if dp[i] else 'B' for i in range(1, n + 1)]
    print(''.join(res))

if __name__ == "__main__":
    solve()
```このコードは、位置の dp を計算するときに、考えられるすべての目的地がすでに分類されているように、値を降順で処理するという考えに従っています。 アクティブな配列は、すでに処理されたより大きな値に対応する位置をマークします。 

内部ループは値 a[i] ごとにステップを実行し、モジュラー制約を直接強制します。 これにより、明示的な隣接リストの構築が回避されます。 正しさは、すべての有効な手がインデックスの差による等差数列構造を保持するという事実にかかっています。 

よくある実装の落とし穴は、値の順序とインデックスの順序が混同されていることです。 DP の順序はインデックスではなく値によって指定する必要があります。そうしないと、より高い値への移行がまだ解決されない可能性があります。

 ## 特殊なケース

 単一要素の配列の場合、これより大きな値がないため、位置には正当な移動はありません。 アルゴリズムは最初に非アクティブとマークし、到達可能な負け状態を検出しないため、 dp[1] が false になり、正しく負け状態が生成されます。 

厳密に増加する配列の場合、最大値を除くすべての位置は、インデックスが揃っている場合にのみモジュラー制約の下でその値に到達できます。 処理順序により、最大値が最初に負けとして評価され、ステップ サイズで到達可能な場合は、より前の位置で正しく検出されることが保証されます。 

大きな値が遠く離れてクラスター化されている順列の場合、値によるステップ実行によりすべてのアクティブな位置をスキップでき、その剰余クラスに有効なジャンプが存在しないという事実を正しくモデル化できます。
