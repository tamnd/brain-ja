 ## 解決策
 ## 問題の理解

 を含むデッキがあります`n`カードのうち、`m`ジョーカーたちだ。 カードは均等に分配されます`k`すべてのプレイヤーが正確に受信できるように、`n / k`カード。 

スコアはジョーカーがどのように分配されるかによってのみ決まります。 あるプレイヤーが最終的に最大数のジョーカーを獲得したとします。 させて`x`をそのプレイヤーの手札にあるジョーカーの数とし、`y`他のすべてのプレイヤーの中で最大のジョーカー数になること。 勝者のスコアは、`x - y`。 複数のプレイヤーが最大のジョーカー数で同点の場合、スコアは次のようになります。`0`。 

勝者のスコアを最大化するジョーカーの配分を自由に想像できます。 タスクは、可能な最大スコアを計算することです。 

制約はわずかです。 最大 500 のテスト ケースがあり、`n ≤ 50`。 かなり非効率なアプローチであっても、制限内であれば快適に実行できます。 それでも、問題の構造は、テスト ケースごとに一定時間で実行される直接的な数学的解決策につながります。 

最初の微妙なケースは、1 人のプレイヤーの手札の容量よりもジョーカーの数が少ない場合に発生します。 

例：```
n = 8, m = 3, k = 2
```各プレイヤーが保持できる`4`カード。 1人のプレイヤーがすべてを手に入れることができます`3`ジョーカーズ、他のプレイヤーには何も残さない。 答えは`3`、ジョーカーを均等に分配することから派生したものではありません。 

2 番目の微妙なケースは、1 人のプレイヤーが保持できる数を超えるジョーカーがある場合に発生します。 

例：```
n = 8, m = 7, k = 2
```プレイヤーが保持できるのは最大`4`ジョーカーの手には次のようなものしか含まれていないため、`4`カード。 プレイヤーを1人与えた後`4`ジョーカー、まだあるよ`3`ジョーカーたちは去った。 残ったジョーカーは他のプレイヤーに渡さなければならないので、スコアは次のようになります。`4 - 3 = 1`。 

単に返すだけの不注意な解決策`min(m, n/k)`間違って戻ってきます`4`。 

もう 1 つの重要なケースは、残りのジョーカーが他のプレイヤーに均等に分配される場合です。 

例：```
n = 12, m = 9, k = 3
```勝者が獲得するのは、`4`ジョーカーたち。 ジョーカーは5人残っています。 最強の敵を最小限に抑えるために、2 人のプレイヤーにできるだけ均等に敵を分散させます。 対戦相手の 1 人が受け取る必要があります`ceil(5/2) = 3`ジョーカーたち。 スコアは`4 - 3 = 1`。 

ここでフロア分割を使用すると、誤って生成されます。`4 - 2 = 2`。 

最後に、ジョーカーがまったく存在しない場合:```
n = 42, m = 0, k = 7
```全員がジョーカーを持っていないため、全員が同点となり、スコアは`0`。 

## アプローチ

 ブルートフォースの考え方は、どのようにしてジョーカーをプレイヤーに分配できるかを考えることから始まります。 考えられるすべての分布を列挙することができます。`m`ジョーカーズ・アクロス`k`プレイヤーはハンドサイズの制限を尊重しながら`n/k`。 分布ごとに勝者のスコアを計算し、最大値を維持できます。 

スコアはジョーカーの数のみに依存するため、これは概念的に機能します。 問題は、有効な分布の数が組み合わせによって増加することです。 実際の制約は小さいにもかかわらず、このアプローチは拡張性がなく、ゲームの構造を完全に無視しています。 

重要な観察は、勝者のジョーカー数が最初に最大化されるべきであるということです。 各プレイヤーが持っているのは`n/k`プレイヤーはこれ以上のカードを持つことはできません`n/k`ジョーカーたち。 したがって、可能な限り最高の勝者が受け取ります```
x = min(m, n/k)
```ジョーカーたち。 

すべてのジョーカーが片手に収まる場合、つまり`m ≤ n/k`、その場合、残りのプレイヤーはジョーカーを受け取りません。答えは単純です。`m`。 

興味深いケースは、勝者の手を満たした後にいくつかのジョーカーが残る場合です。 させて```
remaining = m - x
```これらのジョーカーは他のジョーカーに分配する必要があります`k - 1`選手たち。 

スコアを最大化するには、最強の対戦相手のジョーカーをできるだけ少なくする必要があります。 最善の戦略は、残りのジョーカーを他のプレイヤーにできるだけ均等に分配することです。 

もし`remaining`ジョーカーは以下に配布されます`k - 1`プレイヤーの最大の対戦相手ジョーカー数は```
ceil(remaining / (k - 1))
```整数演算を使用する:```
(remaining + k - 2) // (k - 1)
```最終的なスコアは、```
x - ceil(remaining / (k - 1))
```これにより、問題全体が数回の算術演算に減ります。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的`m`そして`k`| 指数 | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 勝者が受け取ることができるジョーカーの最大数を計算します。```
x = min(m, n / k)
```どのプレイヤーもこれ以上保持することはできません`n/k`したがって、どのプレイヤーもその枚数以上のジョーカーを保持することはできません。 
2. 勝者にできるだけ多くのジョーカーを与えた後に残るジョーカーの数を計算します。```
remaining = m - x
```3. 残りのジョーカーを他のジョーカーに分配します。`k - 1`プレイヤーはできるだけ均等に。 

最強の敵はこうなるだろう```
y = ceil(remaining / (k - 1))
```ジョーカーたち。 
4. 戻る```
x - y
```これはまさに勝者のスコアだからです。 

### なぜ効果があるのか

 勝者がより多くのジョーカーを受け取ると勝者のスコアは増加し、対戦相手がより多くのジョーカーを受け取ると減少します。 

与える量が以下の場合`min(m, n/k)`勝者にジョーカーを与えることは決して役に立ちません。`x`直接、または別の場所に存在しながら変更せずに残します。 したがって、最適解は常に最大化されます。`x`。 

一度`x`が修正された場合、残る唯一の目標は、最大の敵ジョーカー数を最小限に抑えることです。 すべてのディストリビューションの中で、`remaining`ジョーカーズ・アクロス`k - 1`プレーヤーの最大負荷は、できるだけ均等に分散することで最小限に抑えられます。 その最大負荷はまさに`ceil(remaining / (k - 1))`。 

両方の部分が独立して最適であるため、結果のスコアが達成可能な最大スコアになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m, k = map(int, input().split())

        max_jokers = min(m, n // k)
        remaining = m - max_jokers

        opponent = (remaining + k - 2) // (k - 1)

        ans.append(str(max_jokers - opponent))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```最初の計算では、勝者が保持できるジョーカーの最大数が求められます。 手の大きさの制限により、`n // k`絶対的な上限。 

変数`remaining`他のプレイヤーに割り当てる必要があるジョーカーを追跡します。 

表現```
(remaining + k - 2) // (k - 1)
```浮動小数点演算を使用せずに上限除算を計算します。 ここは間違いが最も起こりやすい場所です。 通常のフロア分割を使用すると、残りのジョーカーが均等に分割されない場合、最強の対戦相手を過小評価することになります。 

すべての算術演算は Python 整数内に簡単に収まります。 制約は小さいですが、式ははるかに大きな値であっても安全なままです。

 ## 特殊なケース

 次のことを考慮してください。```
1
8 3 2
```私たちは計算します`x = min(3, 4) = 3`。 ジョーカーは残っていないので、`remaining = 0`。 最強の相手は、`0`ジョーカーたち。 答えは`3 - 0 = 3`。 

これは、すべてのジョーカーが 1 人のプレイヤーの手の中に収まる場合を処理します。 アルゴリズムは、どの対戦相手もジョーカーを受け取ることができないことを即座に認識します。 

考慮する：```
1
8 7 2
```私たちは計算します`x = min(7, 4) = 4`。 ジョーカーは3人残っています。 対戦相手は 1 人だけなので、その対戦相手は残り 3 つのジョーカーをすべて受け取る必要があります。 アルゴリズムは計算します```
y = ceil(3 / 1) = 3
```そして戻ってきます`4 - 3 = 1`。 

これにより、ハンド サイズの制限が尊重され、残ったジョーカーが依然として重要であることが確認されます。 

考慮する：```
1
12 9 3
```私たちは計算します`x = 4`、`remaining = 5`、 そして```
y = ceil(5 / 2) = 3
```答えは次のようになります`1`。 

これは古典的な天井分割ケースです。 フロア分割を使用したソリューションでは、誤った結果が生成されます。`2`。 

考慮する：```
1
42 0 7
```私たちは計算します`x = 0`、`remaining = 0`、 そして`y = 0`。 答えは`0`。 

このアルゴリズムは、ジョーカーがまったく存在しない状況にも自然に対処し、予想される同点スコアを生成します。
