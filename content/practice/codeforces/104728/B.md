 ## 解決策
 ## 問題の理解

 長さ n の制約の配列が与えられます。 各位置 i について、値 a[i] は、最終シーケンスの最初の a[i] 文字が位置 i で終わる長さ a[i] のブロックに一致する必要があることを示します。 言い換えれば、すべての i について、セグメント s[1..a[i]] は強制的に s[i-a[i]+1..i] と同一になります。 

したがって、各インデックス i は、接頭辞内の位置と i で終わるシフトされたウィンドウの間の一連の等価関係に寄与します。 これらすべての等式が適用されたら、すべての制約が満たされるように に値を割り当てる必要があります。 すべての有効な構造の中で、 に現れる個別の値の数を最大化する必要があり、複数の解が存在する場合は、辞書編集的に最小のシーケンスを出力する必要があります。 

この制約は、位置が独立していないことを意味します。 a[i] が正の場合は常に、接頭辞の位置を i の周囲の位置に結び付け、多くのインデックスを 1 つの強制等価クラスに連鎖させる可能性があります。 単純な間違いは、各 i を独立して扱い、以前の制約の推移的な効果を伝播せずに 2 つのセグメントをローカルでのみ比較することです。 たとえば、位置 1 が 3 に等しく、3 が 5 に等しい場合、それらの間に直接の制約がない場合でも、1 は 5 に等しくなければなりません。 

もう 1 つの微妙な失敗は、i ごとにペアごとの条件をチェックするだけで同値クラスをグローバルに統一しない実装で制約が一貫性なく重複するときに発生します。 このようなアプローチは、小規模な場合は通過できますが、複数の重なり合う境界線が等価性の長い連鎖を作成するとすぐに破綻します。 

入力サイズ n は最大 2×10^5 にすることができ、セグメント比較の二次シミュレーションは除外されます。 各制約は最大 O(n) 位置にまたがる可能性があるため、i ごとにセグメントを明示的にコピーすると、O(n^2) の動作と TLE が発生します。 ソリューションでは、すべての制約を、線形に近い結合と割り当てをサポートする構造に削減する必要があります。 

## アプローチ

 直接シミュレーションのアプローチでは、各 i について部分文字列 s[i-a[i]+1..i] を s[1..a[i]] にコピーし、既に処理された位置を書き換える可能性があります。 これはすぐにコストが高くなります。単一の大きな a[i] は O(n) 個の割り当てをトリガーする可能性があり、すべての i にわたってこれは O(n^2) に縮退します。 

重要な点は、制約が処理中に明示的な値を必要としないことです。 ポジション間の平等関係を強制するだけです。 各条件は、すべてのオフセット j について、位置 j が位置 i-a[i]+j に等しくなければならないことを示します。 これはコピー操作ではなく、インデックスのペアが同じ同値クラスに属するというステートメントです。 

等価制約としてみなされると、問題は等しい位置のグラフを構築し、連結成分に値を割り当てることになります。 個別の値の数を最大化するには、すべてのコンポーネントが独自の値を取得する必要があります。 辞書編集上の最小順序を実現するには、左から右にスキャンしたときに最初に出現する順序でコンポーネントに値を割り当てる必要があります。 

これにより、問題は、位置全体にわたって素のセットを維持し、すべての制約されたペアを統合し、コンポーネントごとにラベルを貪欲に割り当てるという問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースセグメント伝播 | O(n²) | O(n) | 遅すぎる |
 | DSU 等価圧縮 | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各インデックスを Union-find 構造内のノードとして扱います。同じセット内のノードは同じ値を受け取る必要があります。

1. 各位置 i がそれ自身の親である、素のセット共用体構造を初期化します。 この時点では、すべてのインデックスは独立していると見なされるため、可能な最大数の個別の値から開始します。 
2. 1 から n までのインデックス i ごとに、1 から a[i] までのすべてのオフセット j を繰り返します。 各 j について、位置 j を DSU 内の位置 (i - a[i] + j) とマージします。 これにより、プレフィックス セグメントと長さ a[i] の終了セグメントが位置ごとに同一になることが強制されます。 
3. すべての制約を処理した後、各接続コンポーネントは、同じ値を共有する必要があるインデックスのグループを表します。 異なるコンポーネント間にはこれ以上の制限はありません。 
4. インデックスを 1 から n まで走査します。 代表値がまだ割り当てられていないコンポーネントに遭遇した場合は、そのコンポーネントに未使用の最小の整数を割り当てます。 このマッピングをルートから値に保存します。 
5. 各位置 i について、その DSU 代表に割り当てられた値を出力します。 

この順序付けにより辞書編集的に最小のシーケンスが生成される理由は、コンポーネントが最初に出現するときに、可能な限り最小の値が割り当てられるためです。 後のコンポーネントは必然的により高いインデックスに表示されるため、辞書編集上の最小性を維持しながら、より大きなラベルまたは同等のラベルが付けられます。 

### なぜ効果があるのか

 すべての制約は純粋な等式であるため、解空間はまさに等式グラフの連結成分上の代入定数のセットになります。 すべての制約は一致する必要があるインデックスの直接結合であり、結合操作の推移性によってすべての間接的な依存関係がキャプチャされるため、DSU はこれらのコンポーネントを正しく計算します。 不等式や順序制約が存在しないため、コンポーネントごとに個別の値を割り当てることは常に有効であり、最初に表示されたラベル付けを使用すると、最初の位置が可能な限り最小の値を取得します。これは、すべての有効なラベル付けの中で正確に辞書編集上最小の値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    parent = list(range(n + 1))
    size = [1] * (n + 1)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        rx, ry = find(x), find(y)
        if rx == ry:
            return
        if size[rx] < size[ry]:
            rx, ry = ry, rx
        parent[ry] = rx
        size[rx] += size[ry]

    for i in range(1, n + 1):
        ai = a[i - 1]
        start = i - ai
        for j in range(1, ai + 1):
            union(j, start + j)

    comp_val = {}
    cur = 1
    res = [0] * (n + 1)

    for i in range(1, n + 1):
        r = find(i)
        if r not in comp_val:
            comp_val[r] = cur
            cur += 1
        res[i] = comp_val[r]

    print(*res[1:])

if __name__ == "__main__":
    solve()
```DSU は、すべての等価制約を圧縮するために使用されます。 各結合操作は、接頭辞インデックスを接尾辞セグメント内の対応する位置合わせされた位置に接続します。 サイズによるパスの圧縮と結合により、ほぼ線形のパフォーマンスが保証されます。 

2 番目のパスでは答えが作成されます。 辞書 comp_val は、コンポーネントが左から右の順序で最初に見つかった場合にのみ新しいラベルを割り当てます。これにより、辞書編集上の最小限性が強制されます。 

よくある実装の落とし穴は、結合操作中に値を割り当てようとすることです。 共用体は順序付けではなく構造のみを定義するため、これは正確性を損ないます。 割り当ては、すべての制約がわかった後に行う必要があります。 

## 実用的な例

 ### 例 1

 入力:```
5
0 0 1 2 3
```私たちは労働組合を概念的に追跡します。 

| 私 | a[i] | ユニオンが追加されました | 成分効果 |
 | --- | --- | --- | --- |
 | 1 | 0 | なし | {1} |
 | 2 | 0 | なし | {2} |
 | 3 | 1 | (1 ↔ 3) | {1,3} |
 | 4 | 2 | (1↔3、2↔4) | {1,3}、{2,4} |
 | 5 | 3 | (1↔3,2↔4,3↔5) | {1,3,5}、{2,4} |

 次に、値を順番に割り当てます。 

1→1、2→2、3株1→1、4→2、5→1。 

出力:```
1 2 1 2 1
```これは、特に後の制約が前の制約を拡張する場合に、推移的マージによってより大きな等価クラスが徐々に構築される様子を示しています。 

### 例 2

 入力:```
11
0 0 0 0 2 1 0 0 3 0 1
```私たちは構造の形成に重点を置いています。 

| 私 | a[i] | キーのマージ |
 | --- | --- | --- |
 | 5 | 2 | 1↔4、2↔5 |
 | 6 | 1 | 1↔6 |
 | 9 | 3 | 1↔6、2↔7、3↔8 |
 | 11 | 1 | 1↔11 |

 これにより、初期のインデックスをルートとする複数のコンポーネントが作成され、伝播によってそれらが前方に広がります。 

最終的な割り当ては左から右に進みます。 

1→1、2→2、3→3、4→1、5→2、6→1、7→2、8→3、9→3、10→4、11→1。 

出力：```
1 2 3 1 2 1 1 2 3 4 1
```トレースは、以前に存在しなかった DSU ルートに遭遇した場合にのみ、新しいコンポーネントがどのように導入されるかを示します。

 ## 特殊なケース

 n=1 で a[1]=0 の場合、和集合は存在せず、単一の位置が独自のコンポーネントを形成します。 DSU ルートが最初に検出されるため、アルゴリズムは直ちにそれにラベル 1 を割り当てます。 

すべての a[i]=0 の場合、すべてのインデックスは分離されたままになります。 2 番目のパスでは、各位置に新しいルートが導入され、新しいラベルが順番に受け取られ、辞書編集上最小の厳密に増加する配列が生成されます。 

a[i]=i-1 のような完全に連鎖した制約の場合、すべての共用体がプレフィックス構造全体を接続します。 DSU はすべてのノードを 1 つのコンポーネントにマージし、出力はすべての位置で定数 1 になり、強制された等価性と一致します。 

交互に長い a[i] と短い a[i] など、重複する混合制約の場合、DSU は、接続が間接的な場合でも、推移的閉包が正しく形成されることを保証します。 最終的なラベル付けは、個々の結合の順序ではなく、コンポーネントの構造のみに依存します。
