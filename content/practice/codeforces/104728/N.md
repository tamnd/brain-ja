 ## 解決策
 ## 問題の理解

 各入力は 2 つの単一の大文字で構成され、各文字は基数 26 の数値を表します。`A`0に対応し、`B`1 まで、以下同様に最大`Z`タスクは、各文字を 1 桁の基数 26 の数値として解釈し、2 つの値を加算して、その結果を先頭のゼロを除いた基数 26 の数値として再度出力することです。 

入力文字列の長さは常に 1 ですが、基数 26 桁を 2 つ追加するとキャリーが発生する可能性があるため、結果には複数の文字が必要になる場合があります。 例えば、`Z`25に相当するので、`Z + B`に対応する`25 + 1 = 26`、基数 26 では次のように書かれます。`BA`なぜなら`26 = 1 × 26 + 0`。 

文字のペアは 1 つだけであるため、制約は非常に小さいです。 これは、一定時間で実行されるソリューションであればどれでも十分であることを意味します。 繰り返しのテスト ケースを仮説的に考えたとしても、問題はテスト ケースごとの単純な算術に帰着します。 

主なエッジケースは、境界でのキャリー動作です。 合計が 26 未満の場合、出力は 1 文字になります。 合計が 26 以上の場合、出力は 2 文字になります。 単純な間違いは、加算後の出力を単一の文字として扱うことです。これは、次のような入力では失敗します。`Z Z`または`Z B`。 

失敗例：入力`Z Z`与える`25 + 25 = 50`、これは基数 26 に変換されます。`1 * 26 + 24 = BA`。 単純なモジュロ 26 のみのアプローチでは、誤って出力されます。`Y`。 

## アプローチ

 ブルートフォース解釈では、各文字を数値に変換して加算し、除算を繰り返すことで基数 26 の文字列を繰り返し構築しようとします。 これは 1 桁の加算としては過剰ですが、それでも正しいです。整数の合計を計算し、モジュロ 26 を繰り返し実行して桁を抽出します。 長い文字列を使用する一般的な設定では、O(k) がかかります。ここで、k は結果の桁数です。 

ただし、この問題には 2 つの 1 桁のみが含まれるため、最大 2 つの出力文字を除き、複数の桁を反復する必要はありません。 この構造は、キャリーが可能な 2 つの基数 26 桁を単純に加算したものです。 重要な観察は、次の 2 桁の合計が`[0, 25]`にある`[0, 50]`、これは最大 2 進数の 26 桁に収まります。 これにより、問題は 26 による除算の商と余りを 1 回だけ計算するだけになります。 

したがって、一般的な基数変換として扱う代わりに、上位桁を次のように直接計算します。`sum // 26`そして下位の桁は`sum % 26`、次に両方を文字にマッピングし直します。 上位の桁がゼロの場合は、先行ゼロを避けるために省略されます。

 ## アルゴリズムのチュートリアル

 1. 2 つの文字を読み取り、ASCII コードを減算してそれぞれを数値に変換します。`'A'`。 このマップは`A..Z`に`0..25`。 このステップが必要なのは、算術演算は文字形式よりも整数形式の方が簡単であるためです。 
2. 2 つの整数値を加算して、範囲内の生の合計を取得します。`[0, 50]`。 この合計は、文字に変換する前の値を基数 26 で表します。 
3. 26 による整数除算を使用して上位桁を計算します。これにより、キャリーが発生するかどうか、および結果の先頭桁が何になるべきかがキャプチャされます。 
4. モジュロ 26 を使用して下位桁を計算します。これにより、base-26 表現の剰余部分が得られます。 
5. 上位桁が 0 以外の場合は、文字に変換し直して最初に出力します。 これにより、最終文字列の最上位桁が最初に来るようになります。 
6. 常に下位桁を文字に変換して出力します。 これは最下位桁であり、常に存在します。 

### なぜ効果があるのか

 このアルゴリズムは、最大 50 であることが保証されている数値に対して、10 進数から 26 進数への基数変換を正確に実行します。任意の整数は次のように一意に表現できます。`high × 26 + low`どこ`0 ≤ low < 26`。 除算とモジュロ演算は、この表現を直接計算します。 この分解では情報が失われることはないため、これら 2 桁から数値を再構成することは正確です。 出力形式では先頭のゼロが許可されていないため、先頭のゼロ桁の省略は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s, t = input().split()
    
    a = ord(s) - ord('A')
    b = ord(t) - ord('A')
    
    total = a + b
    
    high = total // 26
    low = total % 26
    
    res = []
    
    if high != 0:
        res.append(chr(ord('A') + high))
    
    res.append(chr(ord('A') + low))
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```コードはまず 2 つの入力文字を解析し、0 ～ 25 の範囲の整数に変換します。次に、整数空間で加算を実行します。 商と剰余の分割では、base-26 分解が実装されます。 上位桁の条件付き追加により、次のような結果が得られます。`A`(合計が0の場合)不要な接頭辞を付けません。`A`高い位置でゼロを表します。 

の使用`ord`そして`chr`ルックアップ テーブルを回避して、アルファベットと数字の間の直接マッピングを保証します。 解決策は、一定時間と一定メモリです。

 ## 特殊なケース

 エッジ ケースの 1 つは、両方の入力が`Z`。 ここで、値は 25 と 25 で、合計は 50 になります。アルゴリズムは次のように計算します。`high = 50 // 26 = 1`そして`low = 50 % 26 = 24`、生産`B`そして`Y`したがって、出力は次のようになります`BY`。 これは、可能な最大の入力合計を正しく処理し、キャリーが適切にエンコードされていることを示しています。 

もう 1 つのエッジ ケースは、1 つの入力が`A`そしてもう一つは`Z`。 合計は25なので、`high = 0`そして`low = 25`、生産`Z`。 このアルゴリズムは上位の桁を省略して下位の桁のみを出力し、先行ゼロなしの要件を維持しながら正しい値を表現します。 

最後の境界ケースは、両方の入力が`A`。 合計はゼロとなり、`high = 0`そして`low = 0`したがって、出力は単一です`A`。 これは、空の文字列や無効な先行ゼロを生成することなく、ゼロの表現が一貫して処理されていることを示しています。
