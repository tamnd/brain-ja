 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられており、特別な種類の再構築操作を使用して、それをソートされたシーケンス 1、2、3、...、n に変換したいと考えています。 この操作は柔軟です。配列をいくつかの連続した部分に分割し、必要に応じてそれらの部分の一部を反転し、それらの部分を任意の順序で再配置してから、それらを単一のシーケンスに連結することができます。 

費用は完全な作業そのものではなく、切断ステップを何回実行するかによって決まります。 質問は、許可された並べ替えと反転を適用した後、順列が並べ替えられるようにするために必要な最小限のカット数を求めています。 

重要な難点は、一度切断すると、多くの自由度が得られることです。セグメントは任意に反転したり、並べ替えたりすることができます。 つまり、本当の制約はローカル スワップに関するものではなく、順列を昇順に並べることができる「可逆ブロック」にどのように分解できるかということです。 

入力サイズは最大 10^6 になるため、操作をシミュレートしたりパーティションを探索しようとしたソリューションはすぐに遅すぎます。 一定のオーバーヘッドが大きい O(n log n) であっても問題ありませんが、セグメンテーションや貪欲な試行に関する O(n^2) の推論は問題です。 

順列がすでにソートされている場合、または完全に逆になっている場合は、微妙なエッジ ケースが発生します。 たとえば、配列がすでに [1, 2, 3, 4] である場合はカットする必要はありません。また、n = 3 で [3, 2, 1] である場合は、配列全体を反転してゼロカットで終了できます。 隣接する増加ランのみをチェックする単純な解決策では、反転された配列が「不良」であると誤って判断され、カットが必要になりますが、セグメントの反転により完全に有効になります。 

もう 1 つの重要なシナリオは、順列が値の順序に沿っていない複数の単調ブロックで構成されている場合です。 たとえば、[1, 3, 2, 4] は、両方にローカル反転があるにもかかわらず、[1, 2, 4, 3] とは異なる動作をします。 連続した値の位置の構造は、ローカルな順序付けよりも重要です。 

## アプローチ

 強引なアイデアは、順列をセグメントに分割するあらゆる方法を試し、各セグメントごとに反転したセグメントのすべてのサブセットとセグメント順序のすべての順列を試し、並べ替えられたシーケンスを生成できるかどうかを確認することです。 この操作ではこれらの変換が明示的に許可されているため、これは概念的には正しいです。 

ただし、セグメントに分割する方法の数は n で指数関数的であり、各分割の並べ替えの数はセグメントの数の階乗になります。 n が 20 程度の場合でもこれは実行不可能になり、n が 10^6 まででは完全に不可能になります。 

重要な観察は、切断後、セグメントが内部順序を反転できるが、相対的な配置が完全に柔軟である原子ブロックのように動作するということです。 これは、重要なのは、最終的にソートされた配列内で連続している必要がある要素を、追加のカットを強制することなくグループ化できるかどうかだけであることを意味します。 

値の位置の観点から順列を見ると、1 から n までのソート順序を構築し、新しいカットを導入せずに修正できる方法で、「予想される次の値」が前の値に隣接していない回数をチェックすることを考えることができます。 セグメント内での反転では修復できない形で連続性が途切れるたびに、新しいカットの導入を余儀なくされます。 

これにより、順方向隣接の可能性と逆方向隣接の可能性の両方を考慮する場合、問題は順列内に「正しい隣接構造の連続した値のセグメント」が何個存在するかを数えることに減ります。 

最終的な構造は、順列において i と i+1 がいずれの順序でも隣接するかどうかに依存することがわかります。 存在する場合、それらは同じセグメントに属することができます (逆の場合もあります)。 それ以外の場合は、新しいセグメント境界が必要です。

次に、連続する整数がいずれかの方向に隣接するすべての最大チェーンをマージすることで、カットを最小限に抑えます。

 ## アルゴリズムのチュートリアル

 1. 順列内の各値の位置を計算します。 

これにより、配列を繰り返しスキャンすることなく、各整数がどこに出現するかをすばやく確認できます。 
2. 1 から n-1 までのすべての値 i について、i と i+1 が順列で隣接しているかどうかを確認します。 

それらの位置がちょうど 1 だけ異なる場合、それらは隣接しているとみなされます。 
3. i と i+1 が隣接する場合、それらが配列内で昇順または降順のどちらで現れるかを判断します。 

セグメントを反転できるため、どちらの方向も有効です。 
4. 値 1 ～ n にわたるグラフのような接続性を構築します。配列内で隣接する場合、i は i+1 に接続されます。 
5. このチェーン構造内の接続されたコンポーネントの数を数えます。 

各コンポーネントは、反転の可能性の後に単一セグメント内に配置できる連続する整数の最大グループに対応します。 
6. 答えは、コンポーネントの数から 1 を引いたものになります。これは、これらのグループを分離するために必要なカットの数に相当します。 

なぜ効果があるのか:

 順列はセグメント境界でのみ自由に再配置できますが、セグメント内では、ソート順で連続するすべての値が順方向または逆方向の配置によって隣接できるようにする必要があります。 元の順列で 2 つの連続する値が隣接していない場合、単一セグメント内でいくら反転しても、それらの間にカットを導入せずにそれらを隣接させることはできません。 したがって、有効なセグメントは、連続して配置された値の最大チェーンに正確に対応し、各カットでは 1 つのコンポーネントが 2 つに分割されることで、そのようなチェーンの数が増加します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i
    
    components = 1
    
    for i in range(1, n):
        if abs(pos[i] - pos[i + 1]) != 1:
            components += 1
    
    print(components - 1)

if __name__ == "__main__":
    solve()
```コードは最初に各値が出現する場所を記録するため、隣接性チェックは O(1) になります。 次に、並べ替え順序で 2 つの隣接する値が並べ替えで隣り合わない場合は常に、連続する値をスキャンし、コンポーネントの数を増やします。 有効なセグメントには両方の値を同時に含めることはできないため、このような各ブレークは必要なカット ポイントを示します。 

k 個のセグメントを分離するには k-1 個のカットが必要であるため、最後の 1 の減算によりセグメントの数がカットの数に変換されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    data = inp.strip().split()
    n = int(data[0])
    p = list(map(int, data[1:]))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i
    
    components = 1
    for i in range(1, n):
        if abs(pos[i] - pos[i + 1]) != 1:
            components += 1
    
    return str(components - 1)

 ## 特殊なケース

 [1] のような単一要素の置換の場合、位置配列は自明であり、検査する連続したペアがないため、コンポーネント数は 1 のままで、答えは 0 になります。これにより、アルゴリズムが無効なインデックス アクセスを試みることなく縮退入力を正しく処理していることが確認されます。 

完全にソートされた配列 [1、2、3、4、5] の場合、元の配列では連続するすべてのペアが隣接しているため、コンポーネントの中断は発生しません。 構造は単一のチェーンのままであり、予想どおりカットはゼロです。 

完全に反転した配列 [4、3、2、1] の場合、すべての連続するペアは、位置が逆方向に隣接したままになります。 隣接性は絶対的な位置の差によって定義されるため、すべてのペアは接続されたままとなり、アルゴリズムは 1 回の反転で十分であることを反映してゼロ カットを正確に生成します。
