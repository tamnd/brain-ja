 ## 解決策
 ## 問題の理解

 それぞれがアルファベット {A、C、G、T} にわたる DNA 文字列のコレクションが与えられています。 順序付けされた文字列のペアから、最初の文字列の接頭辞を取得し、それを 2 番目の文字列の接尾辞と連結することによって、新しい文字列を形成することができます。 選択した両方の部分が空であることが許可されるため、一方の側が何も寄与しない場合でも、カット位置のすべてのペアが有効になります。 

インデックスのトリプル (i、j、k) ごとに、S_i のプレフィックスと S_j のサフィックスを取得すると正確に S_k が生成されるような分割点が少なくとも 1 つ存在するかどうかを知りたいと考えています。 タスクは、k が i と j の両方とは異なるという制限付きで、この条件を満たす順序付きトリプルの数を数えることです。 

主な問題点は、S_i でのプレフィックス カットと S_j でのサフィックス カットの両方が自由に選択でき、同じターゲット文字列 S_k が複数の方法で形成される可能性があることです。 答えは、個別の構造だけでなく、有効な順序付きトリプルをすべてカウントする必要があります。 

この制約により、文字列に関する 2 次または 3 次の推論から遠ざけられます。 すべての文字列の合計の長さは 2 × 10^6 で制限されるため、各文字を一定回数触れるアプローチは受け入れられますが、多数の文字列のペアを直接比較しようとするアプローチは受け入れられません。 

多くの文字列が同一であるか、長い共通のプレフィックスまたはサフィックスを共有する場合、微妙な例外が発生します。 このような場合、S_k 自体は他のすべての文字列と同様にプレフィックスとサフィックスの構造に参加するため、「一致するプレフィックス」と「一致するサフィックス」を単純にカウントすると、同じインデックス k からの寄与を簡単にカウントしすぎてしまう可能性があります。 

もう 1 つのエッジ ケースは、非常に短い文字列が長い文字列と相互作用する場合です。 空のプレフィックスとサフィックスが許可されるため、単一の文字列であっても複数の有効な分割位置に寄与し、空のカット位置を忘れると寄与が失われることになります。 

## アプローチ

 直接的なアプローチでは、すべてのトリプル (i、j、k) を試し、各ペア (i、j) について、S_k 内のすべての分割位置を試し、S_i のプレフィックスの一致と S_j のサフィックスの一致を検証することによって、S_k を形成できるかどうかを確認します。 ハッシュを介して文字列の一致を事前に計算したとしても、最悪の場合、制限をはるかに超える O(n^2 * L) の動作が発生します。 

重要な観察は、構造の構造が S_k 内の分割点によって完全に決定されるということです。 S_k の位置 p を固定すると、条件はきれいに分解されます。接頭辞 S_k[:p] は S_i の接頭辞として現れ、接尾辞 S_k[p:] は S_j の接尾辞として現れる必要があります。 この分離により、i と j の間の相互作用が排除されます。 

これは、固定 k の場合、すべての分割点を合計し、独立したカウントを乗算できることを意味します。 残りの課題は、k ごとにすべての文字列を繰り返しスキャンすることを避けることですが、それでも遅すぎます。 

この問題は、2 つのグローバル構造を事前計算することで解決します。1 つは特定のプレフィックスを持つ文字列の数を数えるプレフィックス構造、もう 1 つは特定のサフィックスを持つ文字列の数を数えるサフィックス構造です。 すべての文字列に対するトライはプレフィックスを効率的に処理し、反転した文字列に対するトライはサフィックスを処理します。 

これらのカウントが利用可能になると、両方の試行でそのパスをたどり、すべての分割位置にわたる寄与を集計することによって、各 S_k を評価できます。 

残る唯一の複雑な点は、S_k 自体がプレフィックスとサフィックスの両方のカウントに含まれるが、有効なトリプルの定義により i = k または j = k が禁止されていることです。 これには、選択されたソース文字列として k に関係する寄与を除去する慎重な修正項が必要です。

 ## アルゴリズムのチュートリアル

2 つのグローバル Try を構築します。1 つは元の形式のすべての文字列に対するもの、もう 1 つはすべての文字列を反転したものに対するものです。 各ノードは、ノードを通過する文字列の数を保存します。これは、そのノードによって表されるプレフィックスを共有する文字列の数に対応します。 

また、各文字列 S_k について、そのパスに沿ったプレフィックス ノードのシーケンスをプレフィックス トライに格納し、そのパスに沿ったサフィックス ノードのシーケンスを逆トライに格納します。 

次に、次のように進めます。 

1. すべての文字列を接頭辞 trie に挿入し、パスに沿ってカウンターをインクリメントします。 これにより、すべてのノードがそのプレフィックスを持つ文字列の数を知ることができます。 
2. すべての反転文字列を 2 番目のトライに挿入し、同様にサフィックスのカウントを維持します。 
3. 各文字列 S_k について、プレフィックス内でそれをトラバースして、分割位置 p ごとにプレフィックスが S_k[:p] に等しい文字列の数である cnt_prefix[p] を記録します。 
4. 同じ S_k について、サフィックス内の逆 S_k をトラバースして、サフィックスが S_k[p:] に等しい文字列の数である cnt_suffix[p] を記録します。 
5. 分割位置 p ごとに、cnt_prefix[p] * cnt_suffix[p] を累積します。 これは、i または j が k に等しい場合を含め、分割 p を使用して S_k を生成できるすべての順序付きペア (i, j) をカウントします。 
6. i = k を固定するとプレフィックス条件が自動的に強制されるため、すべての p に対して cnt_suffix[p] の合計を減算することによって、i = k の寄与を減算します。 
7. すべての p に対して cnt_prefix[p] の合計を減算することにより、j = k の場合の寄与を同様に減算します。 
8. i = k と j = k の両方が 2 回減算された場合を加算し直します。 これは分割位置ごとに 1 つだけ寄与するため、(len(S_k) + 1) を加算し直します。 
9. すべての k について結果を合計します。 

k を含むすべての無効な選択がすべての分割位置にわたって均一にカウントされるため、修正は機能します。 

### なぜ効果があるのか

 固定 k と固定分割位置 p の場合、すべての有効な構造は、接頭辞 S_k[:p] を持つ文字列のセットから i を選択し、接尾辞 S_k[p:] を持つ文字列のセットから j を選択することによって独立して決定されます。 この独立性により、問題は 2 つの頻度クエリの積に変わります。 唯一の歪みは S_k 自体を両方のセットに含めることによって発生しますが、その寄与はすべての p で同一であるため、分解を壊すことなく線形補正項を使用して除去できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "cnt")
    def __init__(self):
        self.next = {}
        self.cnt = 0

def insert(root, s):
    node = root
    node.cnt += 1
    for ch in s:
        if ch not in node.next:
            node.next[ch] = Node()
        node = node.next[ch]
        node.cnt += 1

def collect_prefix_counts(root, s):
    node = root
    res = []
    res.append(node.cnt)
    for ch in s:
        node = node.next[ch]
        res.append(node.cnt)
    return res

def collect_suffix_counts(root, s):
    node = root
    res = []
    res.append(node.cnt)
    for ch in s:
        node = node.next[ch]
        res.append(node.cnt)
    return res

def solve():
    n = int(input())
    arr = [input().strip() for _ in range(n)]

    trie = Node()
    rtrie = Node()

    for s in arr:
        insert(trie, s)
        insert(rtrie, s[::-1])

    ans = 0

    for s in arr:
        m = len(s)

        pref = collect_prefix_counts(trie, s)
        suf = collect_suffix_counts(rtrie, s[::-1])

        total = 0
        sum_pref = 0
        sum_suf = 0

        for p in range(m + 1):
            total += pref[p] * suf[m - p]
            sum_pref += pref[p]
            sum_suf += suf[m - p]

        total -= sum_pref
        total -= sum_suf
        total += (m + 1)

        ans += total

    print(ans)

if __name__ == "__main__":
    solve()
```トライ構造では、すべてのプレフィックス クエリが共有構造に圧縮されるため、各文字は挿入ごとに 1 回だけ処理されます。 逆トライは、サフィックスを逆文字列のプレフィックスに変換することによって、サフィックス クエリに対して同じことを行います。 

各ターゲット文字列 S_k について、配列 pref と suf は 2 回の試行でそのパスをたどることによって計算されます。 suf の位置合わせでは、suf[m - p] が位置 p から始まる接尾辞に正確に対応するように、逆インデックスが使用されます。 

最後の修正ステップでは、インデックス k をどちらのソース文字列としても使用できないという制約を強制します。

 ## 特殊なケース

 すべての文字列が同一である場合、重要なエッジ ケースが発生します。 その状況では、すべてのプレフィックスとサフィックスの一致がすべての分割位置に存在するため、生の積の数は組み合わせ的に爆発的に増加します。 補正項は、選択した i または j が k と一致する寄与を除去するために不可欠です。そうしないと、すべてのトリプルが複数回オーバーカウントされてしまいます。 

もう 1 つのエッジ ケースは、文字列がすべて個別であり、共通のプレフィックスまたはサフィックス構造を共有しない場合です。 この場合、少数のパスに沿ってのみすべてのトライ カウントが 0 または 1 になり、答えはゼロに崩壊します。 プレフィックスカウンターとサフィックスカウンターがどの分割位置にも整列しないため、アルゴリズムはこれを自然に処理し、すべての積が消滅します。
