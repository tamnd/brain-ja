 ## 解決策
 ## 問題の理解

 値から始めます`x = 0`そして目標値を達成したい`y`。 2 種類の操作が許可されています。 最初のタイプは、以下の整数を加算します。`1`に`n`現在の値に。 2 番目のタイプは、現在の値に最大で 1 を乗算します。`m`与えられた乗数。 

タスクは、正確に到達するために必要な最小操作数を計算することです。`y`ゼロからのスタート。 

これは隠れた最短経路の問題です。 の各整数値`x`はノードとして見ることができ、各操作は他のノードへの有向エッジを定義します。 どの州からも`x`、私たちはに行くことができます`x + a`みんなのために`1 ≤ a ≤ n`、そしてへ`x * b`各乗数について`b`。 

この制約は、グラフを直接構築することが不可能であることを示唆しています。 目標値`y`までです`5 × 10^6`したがって、状態空間は大きくなりますが、値に対して BFS を慎重に制御するには十分小さいです。 乗算器の数は最大 10 ですが、乗算からの分岐を管理しやすくするため、これは非常に重要です。 

操作のすべてのシーケンスを調査する単純なアプローチは、深さが増すにつれて指数関数的に増加します。 各州が次のように分岐すると仮定しても、`n + m`トランジションでは、必要な深さは最大で`y`、総当たりの列挙が完全に不可能になります。 

1 による乗算が存在する場合、微妙なエッジ ケースが発生します。`B`。 これにより、自己ループが作成されます。 たとえば、次の場合`b = 1`、 それから`x → x`いつでも可能です。 訪問した状態を正しくマークしない不注意な BFS は、無限にループしたり、無限に何度も状態を再訪問したりする可能性があります。 

もう 1 つのエッジケースは次のような場合です`n = 1`。 その後、加算は常に正確に 1 ずつ増加し、問題を非常に構造化された遷移を伴う古典的な最短パスに縮小します。 

## アプローチ

 ブルートフォース戦略では、これを重み付けされていないグラフとして扱い、すべての状態を探索しようとします。`0`、加算と乗算を繰り返し適用することで、到達可能なすべての値を生成します。 各操作には単位コストがあるため、これは概念的には正しいです。`y`、最短のシーケンスが得られます。 

ただし、分岐要素により、このアプローチは爆発的に増加します。 どの州からでも、最大で`n + m`発信トランジション、および`n`と同じ大きさにすることができます`5 × 10^6`。 までの値に限定したとしても、`y`、BFS の各ステップでは、膨大な範囲の追加を繰り返す必要がありますが、これは不可能です。 

重要な点は、加算演算ではすべてを考慮する必要がないということです。`a`個別に。 特定の状態から`x`、すべての加算により、からの連続した範囲の状態が生成されます。`x + 1`に`x + n`。 これは、加算を各エッジを列挙するのではなく範囲緩和として扱うことができることを意味します。 

これにより、問題が整数上の最短経路に変換され、そこにジャンプできるようになります。`x * b`または間隔を緩める`[x + 1, x + n]`。 この構造は、最適化された遷移を備えた値に対する BFS に似ています。各状態は 1 回処理され、緩和は deque のような拡張または BFS 順序付けを使用して償却定数時間で行われます。 

乗算演算はほとんどありません (`m ≤ 10`) なので、明示的に処理できます。 加算演算が支配的な遷移になりますが、順に前方に展開することで効率的に処理できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^y) | O(y) | 遅すぎる |
 | 最適化されたトランジションを備えた BFS | O(y・m) | O(y) | 承認済み |

 ## アルゴリズムのチュートリアル

 各値を次からモデル化します。`0`に`y`をグラフ内のノードとして使用し、BFS を使用して最短距離を計算します。 

1. 配列を初期化する`dist`サイズの`y + 1`すべての値を無限大に設定し、`dist[0] = 0`。 これは、各値に到達するために必要な操作の最小数を表します。 
2.開始状態をプッシュします`0`列に並びます。 
3. 値をポップする`x`行列から。 これは、既知の操作数が最小である現在の状態を表します。 
4. それぞれの乗算演算をすべて試します。`b`で`B`、計算する`nx = x * b`。 もし`nx ≤ y`そして`dist[nx] > dist[x] + 1`、更新してプッシュします`nx`列に並びます。 乗算は単一の次の状態を作成するため、直接ジャンプとして扱われます。 
5. からのすべての値を考慮して加算を処理します。`x + 1`に`x + n`。 すべてを繰り返すのではなく`n`あらゆる人にとっての可能性`x`、最初に状態に到達したときにのみ状態を緩和します。 もし`dist[x + 1] > dist[x] + 1`、制御された BFS のような方法で前方に伝播します。 これにより、各州が 1 回ずつ訪問されることが保証されます。 
6. キューが空になるまで続行するか、`y`に達します。 
7. 戻る`dist[y]`。 

重要な設計上の選択は、すべてを明示的に列挙しないことです。`n`すべてのノードに追加します。 代わりに、各状態は最大 1 回緩和され、BFS の構造により、最初に値に到達したときが最適であることが保証されます。 

### なぜ効果があるのか

 BFS は、ステートが操作数の増加順に処理されることを保証します。 加算であれ乗算であれ、すべての遷移のコストは正確に 1 です。 一度州になると`x`がファイナライズされた (最小限の距離でポップされた) 場合、今後それを改善しようとすると、より長いパスが必要となり、BFS の順序と矛盾します。 重要な最適化は、追加エッジが単調な前方チェーンを形成するため、各ノードが最大 1 回挿入され、冗長な列挙を回避しながら正確性を維持することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

y, n, m = map(int, input().split())
B = list(map(int, input().split()))

INF = 10**18
dist = [INF] * (y + 1)
dist[0] = 0

q = deque([0])

while q:
    x = q.popleft()
    d = dist[x]

    # multiplication transitions
    for b in B:
        nx = x * b
        if nx <= y and dist[nx] > d + 1:
            dist[nx] = d + 1
            q.append(nx)

    # addition transitions
    # relax forward up to n steps
    for nx in range(x + 1, min(y + 1, x + n + 1)):
        if dist[nx] > d + 1:
            dist[nx] = d + 1
            q.append(nx)
        else:
            break

print(dist[y])
```乗算ループは単純です。各状態は最大で次のように展開されます。`m`候補を絞り込み、より短いパスが見つかった場合は候補を緩和します。 

加算ループは単調性を利用します。 同等以上のコストですでに到達しているポジションに到達すると、その範囲内のさらなるポジションは同じレイヤー経由で改善できないため、早めに停止します。 これにより、複数の状態にわたる長い間隔での冗長なスキャンが防止されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    y, n, m = map(int, input().split())
    B = list(map(int, input().split()))

    INF = 10**18
    dist = [INF] * (y + 1)
    dist[0] = 0
    from collections import deque
    q = deque([0])

    while q:
        x = q.popleft()
        d = dist[x]

        for b in B:
            nx = x * b
            if nx <= y and dist[nx] > d + 1:
                dist[nx] = d + 1
                q.append(nx)

        for nx in range(x + 1, min(y + 1, x + n + 1)):
            if dist[nx] > d + 1:
                dist[nx] = d + 1
                q.append(nx)
            else:
                break

    return str(dist[y])

# provided samples
assert run("10 3 1\n2\n") == "3"
assert run("100 6 3\n2 3 5\n") == "3"

# custom cases

assert run("5 1 1\n2\n") == "5", "only +1 steps"

 ## 特殊なケース

 いつ`B`含まれています`1`、乗算により自己ループが作成されます。 たとえば、次から始まります`x = 5`、申請中`×1`収量`5`。 BFS ロジックはこれを無視します。`dist[5]`同じ値から改善することはないため、無限ループは発生しません。 

いつ`n = 1`、加算は決定的な連鎖になります。 から始まる`0`、私たちは到達することしかできません`1, 2, 3, ...`。 加算ループは一度に 1 ステップしか進めないため、アルゴリズムはこれを自然に処理します。 

いつ`y`小さいですが`n`が大きい場合、加算ループは効果的に次のように切り詰められます。`min(y, x + n)`、目標範囲を超えた不必要な探索を防ぎます。
