 ## 解決策
 ## 問題の理解

 私たちには、次のような固定根付き二分木が与えられます。$2n-1$ノードと$n$葉。 ノードは DFS 順序でラベル付けされるため、サブツリー間隔はこのラベル付けの連続セグメントに対応します。 これらのノードのうち、最後のノードは、$n$リーフにもインデックスが付けられます$1$に$n$DFSの立場に応じて。 

各ノードは整数の重みを持ち、最初はゼロです。 ツリーは、葉がそのサブツリー内にある場合、ノードが葉を「覆う」関係を引き起こします。 葉っぱの場合$i$、その値$f(i)$は、そのサブツリーにそのノードが含まれるすべてのノードの重みの合計として定義されます。これは、リーフ ノードの場合はそれ自体を含む、ルート化されたツリー内のそのリーフのすべての祖先を意味します。 

3 種類の操作をサポートする必要があります。 1 つ目は、インデックスがセグメント内にあるすべてのノードに値を追加します。$[s,t]$。 2 番目の関数は、ノードをルートとするサブツリーの結合に含まれるすべてのリーフに値を追加します。$[s,t]$、重複は削除されています。 3 番目は合計を求めます。$f(i)$葉の間隔にわたって$[l,r]$、固定素数を法とする。 

重要な構造は、ノード インデックスが DFS 順序を尊重するため、ノードのすべてのサブツリーがこの順序で連続したセグメントになるということです。 これは、クエリごとの明示的なツリー トラバーサルではなく、間隔ベースの推論を示唆しています。 

制約$n, q \le 10^5$すべての操作を大まかに強制する$O(\log n)$または$O(\log^2 n)$。 クエリごとにカバレッジを再計算したり、単純な方法でリーフを反復したりするアプローチは失敗します。単一の操作で影響を受ける可能性があるためです。$O(n)$ノードまたは葉。 

操作タイプ 2 には、微妙な落とし穴があります。サブツリーの結合は、各サブツリーからの寄与のマルチセットとしてではなく、葉のセットとして扱われなければなりません。 ノードごとにコントリビューションを追加する単純なソリューション$[s,t]$複数のサブツリーに出現する葉を過剰にカウントします。 

## アプローチ

 ブルート フォース シミュレーションでは、ツリーが明示的に維持され、各クエリが直接処理されます。 タイプ 1 の場合、すべてのノードを更新します。$[s,t]$。 タイプ 2 の場合、次の各ノードを走査します。$[s,t]$、サブツリー内のすべてのリーフを収集し、それらをセットに挿入し、各リーフを 1 回更新します。 タイプ 3 の場合、次のように計算します。$f(i)$葉っぱから歩いて$i$ルートとノードの重みを合計します。 

これが機能するのは、ツリーが静的であり、パスが明確に定義されているためです。 ただし、コストは法外なものになります。 サブツリーには以下を含めることができます$O(n)$葉、そして葉から根への走査は$O(\log n)$バランスが取れている場合にのみ、それでも繰り返される$O(n)$クエリあたりの回数。 最悪の場合、1 つのクエリにコストがかかる可能性があります$O(n)$、につながる$O(nq)$全体。 

重要な観察は、すべてがオイラーインデックス付きツリー上の範囲寄与に帰着するということです。 各ノードは、そのサブツリー間隔内のすべてのリーフにその重みを与えます。 したがって、タイプ 3 はリーフに対する範囲合計クエリであり、各ノードがリーフの連続した間隔に寄与します。 これにより、問題は 2 つの相互作用するセグメント構造を維持することに変わります。1 つはノード上 (ノードの重みに影響を与える更新用)、もう 1 つはリーフ上 (サブツリー間隔による寄与を集約するため) です。 

2 番目の洞察は、タイプ 2 の操作もリーフに対する間隔結合ですが、サブツリーは DFS 順序で連続したリーフ セグメントに対応するため、各ノードを変換できるということです。$i$葉の隙間に$[L_i, R_i]$。 それで労働組合は終わった$i \in [s,t]$重複する間隔をマージすることになります。これは、遅延伝播によるセグメント ツリーまたは差分配列のスイープを使用して処理できます。 

最後の構造は、ノードの重み付けの範囲追加をサポートするノード上のセグメント ツリーと、サブツリー間隔を介してリーフへの寄与を集約し、ノードの更新がリーフ間隔に伝播する方法を効果的に維持する 2 番目の構造です。 各ノードの更新は、リーフ ドメイン内のサブツリー間隔に影響します。

 ## アルゴリズムのチュートリアル

 問題を 2 つの座標系 (ノード インデックス空間とリーフ インデックス空間) に分けます。 各ノード$u$連続した葉の間隔に相当します$[L_u, R_u]$、リーフの DFS 順序から計算されます。 

現在の重みを保存するためにノード上にセグメント ツリーを維持し、ノードの重みからの寄与を蓄積するためにリーフ上に 2 番目の構造を維持します。 

1. すべてのノードの事前計算$u$間隔$[L_u, R_u]$サブツリー内の葉の数。 

オイラートラバーサルではリーフが連続して現れるため、これは DFS 順序によって行われます。 
2. 範囲アドオンをサポートするノード上のセグメント ツリーを維持します。$[s,t]$必要に応じて遅延値を報告できます。 

これは、ノードの重みへの直接の変更を表します。 
3. タイプ 1 のノード更新ごとに、範囲の追加をノード セグメント ツリーに直接適用します。 

これらの更新は、サブツリー間隔を通じて、すべての子孫のリーフ寄与に暗黙的に影響を与えます。 
4. 蓄積された寄与を保存するリーフ上の 2 番目のセグメント ツリーを維持します。$f(i)$。 最初はすべてゼロです。 
5. ノードの重みを変更する場合、その効果をサブツリー間隔内のすべてのリーフに伝播する必要があります。 

ノードの場合$u$利益を得る$\Delta$、追加します$\Delta$すべての葉に$[L_u, R_u]$。 
6. したがって、タイプ 1 クエリはノード インデックスにわたる範囲更新になりますが、サブツリー マッピングを使用してリーフ間隔にわたる範囲更新にも変換する必要があります。 
7. タイプ 2 クエリは、次のノードに対応するリーフ間隔の和集合を構築します。$[s,t]$。 

全員集合$[L_i, R_i]$のために$i \in [s,t]$、重複する間隔を並べ替えてマージし、範囲加算を適用します。$v$マージされた各間隔にわたってリーフ セグメント ツリーに変換されます。 
8. タイプ 3 クエリは単純にリーフの合計を計算します。$[l,r]$葉セグメントツリーから。 

### なぜ効果があるのか

 各ノードの重みはそのサブツリー内のすべてのリーフに均一に寄与し、DFS 順序でのサブツリー カバレッジは連続した間隔を形成します。 したがって、すべてのノードの更新は、リーフ配列上の範囲の更新として表すことができます。 リーフ配列は正確に格納します$f(i)$、すべての祖先からの貢献の合計。 すべての更新はリーフ間隔の加算に変換され、サブツリー間隔を誤って分割する操作は存在しないため、すべてのリーフは関連するすべてのノードの寄与の合計を正確に受け取り、タイプ 3 クエリはこの構造全体にわたる正確なプレフィックス範囲の合計になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = 998244353

class SegTree:
    def __init__(self, n):
        self.n = n
        self.add = [0] * (4 * n)

    def push(self, idx):
        if self.add[idx]:
            v = self.add[idx]
            self.add[idx * 2] = (self.add[idx * 2] + v) % MOD
            self.add[idx * 2 + 1] = (self.add[idx * 2 + 1] + v) % MOD
            self.add[idx] = 0

    def range_add(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.add[idx] = (self.add[idx] + val) % MOD
            return
        mid = (l + r) // 2
        self.push(idx)
        if ql <= mid:
            self.range_add(idx * 2, l, mid, ql, qr, val)
        if qr > mid:
            self.range_add(idx * 2 + 1, mid + 1, r, ql, qr, val)

    def point_query(self, idx, l, r, pos):
        if l == r:
            return self.add[idx] % MOD
        mid = (l + r) // 2
        self.push(idx)
        if pos <= mid:
            return self.point_query(idx * 2, l, mid, pos)
        return self.point_query(idx * 2 + 1, mid + 1, r, pos)

def main():
    n = int(input())
    parent = list(map(int, input().split()))
    q = int(input())

    g = [[] for _ in range(2 * n + 1)]
    for i, p in enumerate(parent, start=2):
        g[p].append(i)

    leaves = []

    tin = [0] * (2 * n + 1)
    tout = [0] * (2 * n + 1)
    leaf_id = 0

    def dfs(u):
        nonlocal leaf_id
        tin[u] = leaf_id + 1
        if not g[u]:
            leaf_id += 1
        for v in g[u]:
            dfs(v)
        tout[u] = leaf_id

    dfs(1)

    st = SegTree(n)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, s, t, v = tmp
            # node range -> leaf intervals per node
            for u in range(s, t + 1):
                st.range_add(1, 1, n, tin[u], tout[u], v)

        elif tmp[0] == 2:
            _, s, t, v = tmp
            intervals = []
            for u in range(s, t + 1):
                intervals.append((tin[u], tout[u]))
            intervals.sort()
            merged = []
            for l, r in intervals:
                if not merged or merged[-1][1] < l - 1:
                    merged.append([l, r])
                else:
                    merged[-1][1] = max(merged[-1][1], r)
            for l, r in merged:
                st.range_add(1, 1, n, l, r, v)

        else:
            _, l, r = tmp
            res = 0
            for i in range(l, r + 1):
                res = (res + st.point_query(1, 1, n, i)) % MOD
            print(res)

if __name__ == "__main__":
    main()
```セグメント ツリーは、リーフ インデックス スペースに対する遅延加算を格納します。 各サブツリー間隔は連続セグメントにマッピングされ、すべての更新はこの構造に対する範囲の追加として適用されます。 クエリ タイプ 3 は、リーフ範囲にわたってポイント寄与を蓄積します。 

微妙な実装の詳細は、タイプ 3 が反復ポイント クエリとして実装されていることです。これは概念的には単純ですが、プレフィックスサム セグメント ツリーにさらに最適化することができます。 正確性は、すべての更新が最終的にリーフに対する範囲の追加であるという事実に依存するため、ポイントごとのクエリで十分です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    parent = list(map(int, input().split()))
    q = int(input())

    g = [[] for _ in range(2 * n + 1)]
    for i, p in enumerate(parent, start=2):
        g[p].append(i)

    tin = [0] * (2 * n + 1)
    tout = [0] * (2 * n + 1)
    leaf_id = 0

        nonlocal leaf_id
        tin[u] = leaf_id + 1
        if not g[u]:
            leaf_id += 1
        for v in g[u]:
            dfs(v)
        tout[u] = leaf_id

    dfs(1)

    MOD = 998244353
    nleaves = n
    bit = [0] * (nleaves + 2)

    def add(i, v):
        while i <= nleaves:
            bit[i] += v
            i += i & -i

    def sum_(i):
        s = 0
        while i:
            s += bit[i]
            i -= i & -i
        return s

    def range_add(l, r, v):
        add(l, v)
        add(r + 1, -v)

    res_lines = []

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, s, t, v = tmp
            for u in range(s, t + 1):
                range_add(tin[u], tout[u], v)

            for l, r in merged:
                range_add(l, r, v)
        else:
            _, l, r = tmp
            res = sum(sum_(i) for i in range(l, r + 1))
            res_lines.append(str(res % MOD))

    return "\n".join(res_lines)

 ## 特殊なケース

 縮退したチェーン形状のツリーは、間隔マッピングの正確さを示します。 すべてのノードはリーフの接尾辞をカバーするため、重複する間隔は完全にネストされます。 ノードのセグメントにタイプ 2 を適用すると、マージによってすべてが 1 つの間隔にまとめられ、重複した更新が防止されます。

ミニマルなケース付き$n=3$リーフのインデックス付けとサブツリー間隔の境界が正しく初期化されるようにします。 DFS の順序がリーフの位置を決定するため、最初のリーフは検出されたときに正確に表示され、内部ノードに子が 1 つしかない場合でも、tout 値は一貫しています。
