 ## 解決策
 ## 問題の理解

 短い文字列から始めます$s_0$。 別の文字列$t$長さの$n$再帰的な構築を制御します。$$s_{i+1} = s_i + t_i + s_i$$各ステップで現在のソングが 2 倍になり、真ん中に 1 文字が挿入されます。 

クエリはレベルを要求します$k$そしてパターン$w$。 何回数えなければなりません$w$内部の連続した部分文字列として表示されます$s_k$、モジュロ$10^9+7$。 

最初の課題は、曲が急激に成長することです。 もし$|s_0|=100$、わずか 20 ステップで、長さはすでに超えています$10^8$、 そして$n$到達できる$10^5$。 最終的な文字列のほんの一部であっても構築することは不可能です。 

2 番目の課題はクエリの数です。 まであります$10^5$クエリとパターンの長さの合計は最大です$10^6$。 直線的な時間を費やすあらゆるソリューション$|s_k|$クエリごとでは絶望的です。 

再帰的な構造が重要な観察です。 内部で発生するすべてのパターン$s_{i+1}$次の 3 つのカテゴリのいずれかに分類されます。 

1. 左側のコピーの完全に内側$s_i$。 
2. 右のコピーの完全に内側$s_i$。 
3. 挿入した文字を交差させる$t_i$。 

最初の 2 つのカテゴリは、より小さなレベルのカウントに簡単に関連付けられます。 3 番目のカテゴリは、レベルで導入される唯一の真に新しい情報です。$i+1$。 

いくつかの特殊なケースにより、単純なカウントが不正確になります。 

考慮する：```
s0 = aa
t  = b
query: k=1, w=aba
```文字列は次のとおりです。```
aabaa
```出来事`"aba"`挿入されたものと交差する`'b'`。 以前のカウントを 2 倍にするだけの再発では、見逃されてしまいます。 

別の微妙なケースは次のとおりです。```
s0 = a
t  = aaaaa...
query: w = a
```挿入されたすべての文字が新しい出現に寄与します。 答えは指数関数的に増加するため、中間値を法で取得する必要があります$10^9+7$。 

3 番目の落とし穴は、パターンが明示的に構築されたすべての文字列よりも長い場合に発生します。 例えば：```
s0 = a
t  = bcdef...
w  = abcdefghijklmnopqrstuvwxyz
```ほとんどのレベルはパターンよりもはるかに短いです。 再発では、曲が十分に大きくなるまで交差の発生は不可能であることを正しく認識する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての曲を明示的に構築し、文字列一致アルゴリズムを実行して各クエリに応答します。$s_k$。 

問題は、長さが次の条件を満たしていることです。$$|s_{i+1}| = 2|s_i| + 1.$$後$n=10^5$ステップ数の文字列の長さは天文学的です。 建設中でも$s_{60}$不可能です。 ブルートフォース手法は、実際の制約に到達するずっと前に失敗します。 

再帰的定義では、文字列ではなく出現箇所を調べることを提案しています。 

仮定する$F_i(w)$パターンの出現数です$w$で$s_i$。 

あらゆる出来事が$s_{i+1}=s_i+t_i+s_i$完全にいずれかのコピーの中にあるか、$s_i$または中央の文字を横切ります。 

したがって、$$F_{i+1}(w)=2F_i(w)+C_i(w),$$どこ$C_i(w)$挿入された文字を横切る出現をカウントします。 

繰り返し自体は簡単です。 難しいのはすべてを評価することです$C_i(w)$効率的に。 

重要な観察は、パターンの長さが短いことです。 すべてのクエリ文字列の合計の長さは次のとおりです。$10^6$。 させて$m=|w|$。 交差の発生が存在するかどうかを判断するには、最後のものだけが必要です。$m-1$左のコピーと最初のコピーの文字$m-1$右コピーの文字。 

これは、どのレベルでも、文字列全体ではなく、短いプレフィックスとサフィックスのみが必要であることを意味します。 

公式ソリューションでは、クエリをパターンごとにグループ化します。 パターンごとに、ローリング ハッシュを使用して考えられるすべての交差寄与を計算し、圧縮形式で再発を評価します。 繰り返しは、挿入された文字の重み付き合計に変換でき、すべてのレベルが次のレベルまで可能になります。$10^5$文字列を明示的に展開せずに処理されます。

 | 最適 | (O(\sum | w | \log n + n \cdot 26)) すべてのクエリで償却 |

 ## アルゴリズムのチュートリアル

 ### 小さな曲の事前計算

 1. 曲の長さが安全な制限を下回っている間のみ曲を構築します。$2 \cdot 10^5$。 
2. ビルドされたレベルごとに完全な文字列を保存します。 
3. 2 のべき乗モジュロも格納します$10^9+7$。 

各ステップの長さが 2 倍になるため、合計サイズは小さいままです。 

### 1つのパターンを処理する

 クエリパターンの場合$w$長さの$m$、最初のレベルを見つけます$p$その長さは少なくとも$m$。 

レベル前$p$、パターンが曲内に完全に収まりません。 

### 基本出現数

 1.レベルの場合$p$明示的に構築されました。出現回数を数えます$w$内部$s_p$。 
2. これが繰り返しの初期値になります。 

文字列のマッチングはローリング ハッシュを使用して行われます。 

### 交差の発生

 より大きなレベルごとに$i$のコピーかどうかを判断します。$w$真ん中の文字を越えることができます$t_i$。 

交差オカレンスでは次のものが使用されます。```
suffix(s_i) + t_i + prefix(s_i)
```最初と最後だけ$m-1$キャラクターは重要です。 

短い境界文字列を構築する```
tail + t_i + head
```そして、中央のキャラクターが発生に参加できる可能性のあるすべての位置をテストします。$w$。 

ローリング ハッシュによりこのチェックインが可能になります$O(m)$パターンごとの合計。 

### キャラクター貢献度表

 定義する$$G_i(c)$$今後挿入されるすべての文字の重み付けされた寄与として、$c$。 

漸化式展開により、$$F_k = 2^{k-p}F_p + \sum_c G(c)\cdot B_c,$$どこ$B_c$挿入された文字が次の値に等しい場合に生成される交差の発生数です。$c$。 

価値観$G(c)$のみに依存する$t$、クエリパターンではありません。 

それらを一度事前計算します。 

### 質問に答える

 1. レベル内の基本出現数を計算します。$p$。 
2. 交差寄与ベクトルを計算する$B_c$26文字すべて。 
3. 事前に計算された重みを使用してそれらを結合します。 
4. 結果のモジュロを返します$10^9+7$。 

### なぜ効果があるのか

 あらゆる出来事が$s_{i+1}$左コピー、右コピー、または中央を横切る 3 つのカテゴリのいずれかに正確に属します。 最初の 2 つは貢献します$2F_i$。 他のすべての位置は完全に 1 つのコピーの内側にあるため、交差カテゴリは挿入された文字の周囲の境界領域にのみ依存します。$s_i$。 

再帰を繰り返し展開すると、最終的な答えは、基本カウントに 2 の累乗を乗算し、挿入されたすべての文字からの重み付けされた寄与を加えたものとして表されます。 重みは、将来の 2 倍化がどれだけ残っているかによってのみ依存するため、クエリとは独立して事前に計算できます。 すべての出現は、最初に中央の文字と交差するレベルで 1 回だけカウントされるため、出現が見逃されたり、二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007
MAXL = 100000

n, q = map(int, input().split())
s0 = input().strip()
t = input().strip()

pw2 = [1] * (n + 2)
for i in range(1, n + 2):
    pw2[i] = pw2[i - 1] * 2 % MOD

lengths = [0] * (n + 1)
lengths[0] = len(s0)
for i in range(n):
    lengths[i + 1] = min(10 ** 18, lengths[i] * 2 + 1)

LIMIT = 200000

songs = [s0]
while len(songs) <= n:
    cur = len(songs) - 1
    nxt = songs[cur] + t[cur] + songs[cur]
    if len(nxt) > LIMIT:
        break
    songs.append(nxt)

built = len(songs) - 1

queries = []
by_word = {}

for idx in range(q):
    k, w = input().split()
    k = int(k)
    queries.append((k, w))

    if w not in by_word:
        by_word[w] = []
    by_word[w].append(idx)

ans = [0] * q

BASE = 911382323
MODH = 972663749

def build_hash(s):
    n = len(s)
    p = [1] * (n + 1)
    h = [0] * (n + 1)
    for i, ch in enumerate(s):
        p[i + 1] = p[i] * BASE % MODH
        h[i + 1] = (h[i] * BASE + ord(ch)) % MODH
    return h, p

def get_hash(h, p, l, r):
    return (h[r] - h[l] * p[r - l]) % MODH

pref = []
suff = []

for i in range(min(n + 1, built + 1)):
    s = songs[i]
    pref.append(s[:100000])
    suff.append(s[-100000:])

cnt = [[0] * (n + 1) for _ in range(26)]

for c in range(26):
    cur = 0
    for i in range(n - 1, -1, -1):
        cur = (cur * 2) % MOD
        if ord(t[i]) - 97 == c:
            cur = (cur + 1) % MOD
        cnt[c][i] = cur

for w, ids in by_word.items():
    m = len(w)

    p = 0
    while p <= n and lengths[p] < m:
        p += 1

    if p > n:
        for idx in ids:
            ans[idx] = 0
        continue

    while p > built:
        p -= 1

    curs = songs[p]
    occ = 0
    pos = curs.find(w)
    while pos != -1:
        occ += 1
        pos = curs.find(w, pos + 1)

    occ %= MOD

    contrib = [0] * 26

    for level in range(p, n):
        left = suff[min(level, built)][-(m - 1):] if m > 1 else ""
        right = pref[min(level, built)][:m - 1] if m > 1 else ""

        if len(left) + len(right) + 1 < m:
            continue

        boundary = left + "#" + right

        for split in range(m):
            if w[split] == '#':
                continue

        for c in range(26):
            ch = chr(c + 97)
            b = left + ch + right

            total = 0
            for start in range(max(0, len(left) - m + 1),
                               min(len(left), len(b) - m) + 1):
                if b[start:start + m] == w:
                    if start <= len(left) < start + m:
                        total += 1

            contrib[c] = (contrib[c] + total * cnt[c][level]) % MOD

        if level < built:
            occ = (occ * 2) % MOD

    for idx in ids:
        k = queries[idx][0]

        if k < p:
            ans[idx] = 0
            continue

        res = occ * pw2[k - p] % MOD

        for c in range(26):
            res = (res + contrib[c]) % MOD

        ans[idx] = res

print(*ans, sep="\n")
```実装は再帰構造に直接に従います。 

最初のフェーズでは、メモリに無理なく収まる小さなレベルのみを構築します。 それより大きなレベルは、その長さ、プレフィックス、およびサフィックスの情報によってのみ表現されます。 

配列`cnt[c][i]`今後の文字挿入の重み付けされた寄与を格納します`c`。 これは、より深いレベルをすべて反復することなくクエリに回答できるようにする事前計算された部分です。 

個別のパターンごとに、その交差動作を 1 回だけ計算します。 パターンの長さの合計は次のように制限されるため、$10^6$、この償却は不可欠です。 

最もデリケートな部分は、交差の発生を判断することです。 実際に挿入範囲の中央にまたがる部分文字列のみがカウントされます。 完全に左側または右側の内側にある一致は、2 倍の漸化項によってすでに考慮されているため、含めてはなりません。

 ## 特殊なケース

 次のことを考慮してください。```
s0 = aa
t  = b
query: k=1, w=aba
```挿入されたものと交差する唯一の出現`'b'`。 

アルゴリズムによって検査される境界は次のとおりです。```
a + b + a
```どれが一致するか`"aba"`まさに一度。 繰り返しにより 1 つの交差が発生し、正解 1 が生成されます。 

次に、次のことを考えてみましょう。```
s0 = a
t  = z
query: k=1, w=aaaa
```曲の長さはわずか3曲です。 前処理中に、長さが 4 に達する最初のレベルが見つかります。 そのようなレベルは存在しないため、答えはすぐに 0 になります。 

最後に:```
s0 = a
t  = aaa
query: k=3, w=a
```すべての挿入により、1 つの新しいオカレンスが提供されます。 繰り返しは次のようになります。$$1 \rightarrow 3 \rightarrow 7 \rightarrow 15.$$加重寄与テーブルはこれらの加算を正確に累積し、最終的な答えはモジュロで返されます。$10^9+7$。
