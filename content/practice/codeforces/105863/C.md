 ## 解決策
 ## 問題の理解

 ツリーが与えられます。これは、サイクルのない接続されたグラフを意味します。 このツリーのいくつかの頂点はリーフであり、次数 1 の頂点です。 タスクは、すべての頂点が最も近い葉からどのくらい離れているかを測定し、次にどの頂点が葉から最も遠いかを決定し、その距離を自然な処理順序でこの最大値が発生する最初の頂点とともに出力することです。 

概念的に、各葉が時間 0 で信号を発し始め、その信号が木に沿って単位時間当たり 1 つのエッジに広がると想像してください。 すべての頂点は、信号が到達した最も早い時間を記録します。 この伝播が終了したら、すべての頂点をスキャンし、記録された到着時間が最も大きい頂点を選択し、最小のインデックスを選択することで同点を解消します。 

入力サイズは、一般的な Codeforces 制約で最大約 100,000 個の頂点を持つツリーを意味します。 二次的な動作を伴うソリューションには、100 億のオーダーの演算が必要となり、直ちに実行不可能になります。 平$O(n \log n)$許容可能ですが、ここでは不要なオーバーヘッドです。 均一な伝播プロセスと組み合わされたツリーの構造は、BFS や DFS などの線形トラバーサルを強く示唆しています。 

ツリーが単純なチェーンの場合、微妙なエッジケースが表示されます。 この場合、リーフはちょうど 2 つあり、チェーンの中心の距離は最大になるはずです。 1 つのリーフのみを考慮したり、リーフごとに独立した検索を実行したりする単純なアプローチでは、誤って距離に偏りが生じたり、誤って再計算されたりする可能性があります。 もう 1 つのエッジ ケースは、中心以外のノードがすべて葉である星型ツリーです。 正解は距離 1 の中心ですが、マルチソースの初期化を忘れた不注意な実装では、誤って距離 0 の葉が返される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、BFS または DFS を使用して、各リーフから個別に開始して、すべてのノードからすべてのリーフまでの距離を計算することです。 葉ごとに最短経路検索を実行し、距離を更新します。 これは正しいです。なぜなら、木のエッジは重み付けされておらず、最短パスが明確に定義されているからです。 ただし、ある場合は、$L$葉と$N$ノード、各 BFS コスト$O(N)$、につながる$O(NL)$最悪の場合。 星型のツリーには、$L$は$O(N)$に退化します。$O(N^2)$、遅すぎます。 

重要な観察は、すべての葉が同時に発生源として機能するということです。 各リーフを個別に処理する代わりに、すべてのリーフを距離 0 の単一の BFS キューに配置し、一緒に外側に拡張することを想像できます。 BFS は自然に距離の増加順に状態を処理するため、最初にノードに到達するときは、どのリーフからの最短パスを経由することが保証されます。 これにより、問題はツリー上の標準的なマルチソース BFS に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (リーフごとの BFS) | O(n²) | O(n) | 遅すぎる |
 | マルチソース BFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 距離配列を大きな値で初期化し、まだノードに到達していないことを表します。 どのノードの次数が正確に 1 であるかを確認することで、すべてのリーフを識別します。 これらのリーフは伝播の開始点であるため、距離 0 のキューに挿入されます。 

次に、標準的な BFS を実行します。 ノードをポップするたびに、その近隣ノードをリラックスさせようとします。 現在のノードを介して隣接ノードに到達すると、保存されている値よりも短い距離が得られる場合、その値を更新し、隣接ノードをキューにプッシュします。 これにより、各ノードがリーフまでの最小距離の昇順に処理されることが保証されます。 

BFS が完了したら、すべてのノードをスキャンし、最大距離を選択します。 複数のノードが同じ最大距離を共有する場合、それらの中で最小のインデックスが選択されます。 

## なぜ機能するのか

 BFS キューは、すべてのノードがリーフから可能な最短のパスを通じて最初に検出されるという不変条件を維持します。 すべてのリーフは距離 0 で同時に初期化されるため、各拡張ステップは、最も近いソースからの距離がレイヤーごとに増加することに対応します。 ツリーでは、任意の 2 つのノード間には単純なパスが 1 つだけ存在するため、ノードに到達すると、後でその距離を改善できる代替パスは存在しません。 これにより、保存された値がリーフまでの真の最小距離であることが保証され、したがってこれらの値の最終的な最大値が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input().strip())
    g = [[] for _ in range(n)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    
    dist = [10**18] * n
    q = deque()

    for i in range(n):
        if len(g[i]) == 1 or n == 1:
            dist[i] = 0
            q.append(i)

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] > dist[u] + 1:
                dist[v] = dist[u] + 1
                q.append(v)

    best_dist = -1
    best_node = 0

    for i in range(n):
        if dist[i] > best_dist:
            best_dist = dist[i]
            best_node = i

    print(best_node + 1, best_dist)

if __name__ == "__main__":
    solve()
```実装は、ツリーの隣接リストを構築することから始まります。 葉の検出は純粋に次数チェックによって行われるため、次のような場合でも安全です。$n = 1$ここで、単一ノードは開始ノードとリーフの両方です。 すべてのリーフが距離 0 の BFS キューにプッシュされ、マルチソース セットアップが確立されます。 

BFS ループが標準です。 条件`dist[v] > dist[u] + 1`リーフからのより短いパスが見つかった場合にのみ各ノードが更新されるようにします。 すべてのエッジの重みが等しいため、これは優先キューのないダイクストラのように動作します。 

最後に、最大距離をスキャンします。 厳密に大きな距離が現れた場合にのみ更新することによって、それを達成する最初のノードを保存します。 

## 実用的な例

 小さなチェーンを考えてみましょう。$1 - 2 - 3 - 4 - 5$。 

リーフをノード 1 と 5 として初期化します。 

| ステップ | キュー | 現在のノード | 距離の最新情報 |
 | --- | --- | --- | --- |
 | 初期化 | [1、5] | - | 距離[1]=0、距離[5]=0 |
 | 1 | [5、2] | 1 | 距離[2]=1 |
 | 2 | [2、4] | 5 | 距離[4]=1 |
 | 3 | [4、3] | 2 | 距離[3]=2 |
 | 4 | [3] | 4 | 変化なし |
 | 5 | [] | 3 | 変化なし |

 これにより、中心ノード 3 の距離が最大 2 であることが確認されます。 

ここで、中心 1 が 2、3、4、5 に接続されている星を考えてみましょう。 

| ステップ | キュー | 現在のノード | 距離の最新情報 |
 | --- | --- | --- | --- |
 | 初期化 | [2,3,4,5] | - | すべての葉の距離は 0 |
 | 1 | [3,4,5,1] | 2 | 距離[1]=1 |
 | 2 | [4,5,1] | 3 | 変化なし |
 | 3 | [5,1] | 4 | 変化なし |
 | 4 | [1] | 5 | 変化なし |

 中心ノード 1 は、最大の距離 1 を取得します。

 ## 特殊なケース

 単一ノード ツリーは、通常、リーフ検出では次数 1 のノードを除外するため、最も単純なトラップですが、ここでは唯一のノードをリーフとして扱う必要があります。 アルゴリズムはこれを明示的に許可することでこれを処理します。$n = 1$キューを初期化して、距離がゼロのままであることを確認します。 

2 ノード ツリーでは、両方のノードがリーフです。 マルチソース BFS は両端から同時に開始され、各ノードは距離 0 に留まります。 最終的な最大値はゼロであり、どちらのノードも選択できますが、実装では一貫性のある最初のノードが選択されます。 

パス状のツリーでは、BFS 層が両端から対称的に展開されます。 中心ノードは両方のソースから最も遠いため、最大距離が累積されます。 BFS は、両方の方向が同時に考慮されることを保証し、1 つのエンドポイントへの偏りを防ぎます。
