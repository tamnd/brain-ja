 ## 解決策
 ## 問題の理解

 一連の数値と、それらに適用される一連のモジュロ演算が与えられます。 数値が係数値で処理されるたびに、数値はその剰余に置き換えられます。 重要な問題は、これらの操作が単なる表面的なものではないということです。係数に対して値が十分に小さくなると、それ以上の削減によって値が変更されなくなるからです。 

課題は、このような多数の操作を効率的にサポートすることですが、影響を受けるすべての数値に単純なモジュロ更新を繰り返し適用するのは遅すぎます。 これを静的な変換と考えるのではなく、各数値を時間の経過とともに進化するもの、時には大幅に変化する場合もあれば、完全に安定したままになる場合もあると考えると役立ちます。 

この制約は、値と演算の数が両方とも十分に大きくなり得ることを意味します。$O(n \cdot q)$シミュレーションは不可能です。 操作ごとに繰り返しスキャンまたは値を直線的に更新するソリューションは、制限時間を超過します。 これにより、個々の数値が操作ごとではなく、全体として少数回のみ処理されるという戦略にすぐに進むことになります。 

値が早期に係数よりも小さくなる場合、微妙なエッジ ケースが発生します。 たとえば、数値がすでに次の係数より小さい場合、操作は何も行いません。 単純な実装でも再挿入または再処理が行われる可能性があり、時間が無駄になり、作業が重複する可能性があります。 もう 1 つの問題は、複数の係数によって値が大きい状態と小さい状態の間で変動する場合に発生します。これは、値が実際にいつ変化するかを明示的に追跡しないと、再計算が繰り返される可能性があります。 

## アプローチ

 この問題を考える簡単な方法は、問題を直接シミュレートすることです。 モジュラス演算ごとに、関連するすべての数値をスキャンし、各値を置き換えます。$x$と$x \bmod c$。 これは操作の定義と正確に一致するため、正しいです。 ただし、コストが法外に高くなります。$q$操作と$n$数値、最悪の場合のパフォーマンス$O(nq)$両方が上限に達する可能性がある場合、更新は大きすぎます。 

重要な構造上の観察は、係数を適用しても必ずしも数値が変化するとは限らないということです。 値の場合$x$すでに よりも小さいです$c$、その後は変更されません。 さらに重要なのは、値が変化すると、その値が大幅に低下することです。 声明で与えられた主張は、これを正式に示しています: 適用後$x \bmod c$、結果は次のいずれかです$x$それ自体、またははるかに小さくなり、プロセス全体にわたる値ごとの実際の変更の対数のみを保証する方法で制限されます。 

これは、ほとんどの数値に対して、ほとんどの操作が実質的に役に立たないことを意味します。 すべての演算をすべての数値に適用するのではなく、数値が実際に変更できるほど大きい場合にのみ数値を処理したいと考えています。 

これを利用するために、すべてのアクティブな値を、常に最大の現在の値に効率的にアクセスできる構造に維持します。 ここでは優先キューが自然に機能します。 繰り返し最大値を抽出し、それを今後の係数演算と比較します。 値がすでに現在の係数よりも小さい場合、その値は、今後順番に処理される大きな係数の下でも変化しないため、そのステップではそのままにしておくことが安全です。 それが大きい場合は、係数を適用して更新し、今後のステップで変更される可能性がある場合は再挿入します。 

重要な改善点は、値が変更されるたびに値が大幅に低下することです。 値が有意に減少できる回数には対数制限があるため、各要素は少数回のみ再挿入されるため、プロセス全体が効率的になります。

 ## アルゴリズムのチュートリアル

 現在の値のセットを最大指向の構造で継続的に維持しながら、一連のモジュラス演算を順番に処理します。 

1. 現在の最大値を常に効率的に取得できるように、すべての初期数値を max-heap に挿入します。 係数の下では大きな値のみが変更される可能性があるため、これは重要です。 
2. 各係数値を反復処理します。$c$指定された順序で。 
3. ヒープ内の最大値が以上である間、$c$、抽出します。 これにより、操作によって実際に影響を受ける値のみを処理することが保証されます。 
4. 新しい値を次のように計算します。$x \bmod c$。 いずれにせよ、変更されていない値はすべてスキップされるため、これが正確性にとって重要な唯一の変換です。 
5. 新しい値がまだ将来の操作によって影響を受ける可能性があるほど大きい場合は、それをヒープに再挿入します。 そうしないと、自然に安定した状態が維持され、繰り返し処理されなくなります。 
6. すべてのモジュラス演算が適用されるまで続行します。 

常に現在の最大値を使用して作業する理由は、現在の係数の影響を受けるにはすでに小さすぎる値に無駄な労力を費やすことがないことを保証するためです。 

### なぜ効果があるのか

 正確さは単調収縮特性に依存します。 値が更新されるたびに、厳密に減少します。 このステートメントの主張は、値が将来のすべての操作の下で永続的に安定する前に、そのような意味のある減少は限られた回数だけしか受けられないことを保証します。 

値が影響を受けるほど大きい場合にのみ値を処理するため、値を変更する更新を見逃すことはありません。 更新された値はすぐに再挿入されるため、必要に応じて将来の操作でそれらの値に影響を与える機能が保持されます。 不必要な演算は適用されず、必要な変換もスキップされません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    ops = list(map(int, input().split()))

    # max heap via negative values
    heap = [-x for x in a]
    heapq.heapify(heap)

    for c in ops:
        # process only values that can change
        while heap and -heap[0] >= c:
            x = -heapq.heappop(heap)
            x %= c
            heapq.heappush(heap, -x)

    print(-min(heap) if heap else 0)

if __name__ == "__main__":
    solve()
```この実装では、Python の min-heap を介して実装された max ヒープを使用して、現在の値のマルチセットをエンコードします。 各モジュラス演算は、影響を受けるのに十分な大きさの要素のみを繰り返し取得します。 重要な実装詳細はループ条件です`-heap[0] >= c`これにより、変更されない要素には決して触れないことが保証されます。 

もう 1 つの微妙な点は、変更されていない要素を「再割り当て」しようとしないことです。 値が現在の係数より小さい場合、その値は変更されずにヒープ内に残ります。これは効率にとって非常に重要です。 

## 実用的な例

 値から始める入力を考えてみましょう`[10, 7, 3]`とモジュラス`[5, 4]`。 

最初のモジュラスの間`c = 5`、5 以上の値を繰り返し抽出します。 

| ステップ | ヒープ (最大表示) | 抽出された x | x mod c | 新しいヒープ |
 | --- | --- | --- | --- | --- |
 | 1 | [10、7、3] | 10 | 0 | [7、3、0] |
 | 2 | [7、3、0] | 7 | 2 | [3、2、0] |
 | 停止 | すべて < 5 | - | - | [3、2、0] |

 5 を処理すると、5 未満の値のみが残るか、その範囲に減らされます。 

今すぐ処理してください`c = 4`。 

| ステップ | ヒープ (最大表示) | 抽出された x | x mod c | 新しいヒープ |
 | --- | --- | --- | --- | --- |
 | 1 | [3、2、0] | 3 | (変更なし) | [3、2、0] |
 | 停止 | すべて < 4 | - | - | [3、2、0] |

 これは、値が十分に小さいと、その後の操作は no-op になり、ヒープがすぐに安定することを示しています。

import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        ops = list(map(int, input().split()))

        heap = [-x for x in a]
        heapq.heapify(heap)

        for c in ops:
            while heap and -heap[0] >= c:
                x = -heapq.heappop(heap)
                x %= c
                heapq.heappush(heap, -x)

        print(-min(heap) if heap else 0)

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdout = old_stdout
    return out

# small cases
assert run("3 1\n10 7 3\n5\n") == "3"
assert run("1 1\n8\n3\n") == "2"
assert run("2 2\n5 9\n10 4\n") in ["1", "0"]

# edge case: already small
assert run("3 2\n1 2 3\n5 6\n") == "1"

# large identical values
assert run("5 1\n10 10 10 10 10\n3\n") in ["1", "0"]

 ## 特殊なケース

 重要なエッジケースは、すべての数値がすでに係数よりも小さい場合です。 たとえば、入力`[1, 2, 3]`弾性率あり`10`何も変化を生じません。 ヒープの状態が次のとおりであるため、アルゴリズムがこれを処理します。`-heap[0] >= c`はすぐに失敗するため、ポップは発生せず、構造は変更されません。 

もう一つのケースは、大から小への遷移を繰り返す場合です。 考慮する`[100, 99]`モジュライ付き`[50, 10]`。 最初の操作は両方の値を大幅に削減し、2 番目の操作はサブセットにのみ影響を与える可能性があります。 ヒープは、各縮小後に新しく大きな値のみが再検討されることを保証するため、安定した要素が再処理されることはありません。 

最後に、多数の小さな係数とそれに続く大きな係数を考慮します。 小さな係数は初期に積極的に値を減らしますが、その後の大きな係数は何も行いません。 値が将来のすべての係数を下回ると、それらは無期限に変更されないため、ヒープはこれを自然に吸収します。
