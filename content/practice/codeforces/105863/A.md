 ## 解決策
 ## 問題の理解

 私たちは、それぞれの動きが標準的なステップではなく、反射のような変換である座標系に取り組んでいます。 与えられた点から開始して、別の点を繰り返し選択し、それを「反射」することで、固定された幾何学的規則に従って新しい位置が生成されます。 

タスクは、各操作がこの反射ルールを使用して現在位置を移動することを前提として、プロセスの原点 (または同等の固定の初期点) から開始して、平面内のどの点に到達できるかを決定することです。 出力は、このような操作を何度行ってもターゲット ポイントに到達できるかどうかだけです。 

この操作は幾何学的に聞こえますが、重要な難点は、反射を繰り返すと自明ではない構成が作成される可能性があることです。 素朴な解釈では、複雑な到達可能領域を示唆する可能性があるため、主な課題は、単純な代数条件での到達可能性を特徴付けることです。 

各テスト ケースは一定時間内に独立して回答する必要があるという意味で、制約は事実上厳しいものになります。 反射をシミュレートしたり、中間状態を検索しようとした場合、10^5 クエリのような控えめな境界であっても、各クエリに連続ジオメトリや境界のない中間状態が含まれる可能性があるため、そのアプローチは直ちに実行不可能になります。 

座標が非常に小さいかゼロの場合、微妙なエッジ ケースが発生します。 たとえば、開始点と目標点がいずれかの座標でちょうど 1 だけ異なる場合、単純な幾何学的推論では「任意に近づけることができる」ため、パスが存在すると誤って仮定する可能性がありますが、変換ではパリティ構造が維持されるため、そのような遷移は不可能になります。 

もう 1 つのエッジ ケースは、両方の座標がパリティに一致するが、距離が長い場合です。 素朴なグリッドウォークの直感は、中間の実現可能性が重要であることを示唆するかもしれませんが、実際にはパリティの一貫性のみが重要であり、大きさは重要ではありません。 

## アプローチ

 ブルートフォースアプローチは、リフレクションプロセスをシミュレートします。 最初の点から始めて、考えられるすべての反射中心を試し、新しい点を繰り返し生成し、基本的に無限の暗黙的な状態空間にわたるグラフの走査を実行します。 たとえターゲットの周囲の境界領域に限定したとしても、平面内のすべての点が潜在的な反射中心となるため、分岐係数は原理的には無限大です。 これにより、直接のシミュレーションが不可能になります。 

重要な洞察は、単一の反射が何を行うかを代数的に分析することで得られます。 点 (x₁, y₁) を別の点 (x, y) を通して反射すると、結果は (2x − x₁, 2y − y₁) になります。 この操作ではパリティ構造が保存されます。新しい点の各座標は、整数の 2 倍から元の座標を引いた値に依存します。これは、両方の座標のパリティが 2 を法とする不変であることを意味します。 

この不変条件を認識すると、問題全体は、ターゲット点が開始点と同じパリティ制約を満たすかどうかをチェックすることに集約されます。 パリティが一致する場合、適切な中間点を選択することでパリティに到達する一連のリフレクションを構築し、リフレクション操作を段階的に効果的に逆にすることができます。 パリティが一致しない場合、一連の操作によってパリティを変更することはできません。 

ブルート フォースは、考えられるすべての変換を探索するため機能しますが、状態空間が連続的で制限がないため失敗します。 リフレクションによって座標パリティが維持されるという観察により、問題はクエリごとの一定時間のチェックに軽減されます。

 ## アルゴリズムのチュートリアル

 各クエリを、開始点とターゲット点の間の単純なパリティ比較にまとめます。

1. 始点と目標点の座標を読み取ります。 すべての演算の開始点は固定されているため、パリティの基準として扱います。 
2. ターゲットとスタートの間の x 座標の差のパリティを計算します。 これは、両方の x 値が偶数であるか、両方とも奇数であるかを確認することと同じです。 
3. 同様に y 座標の差のパリティを計算します。 
4. 両方のパリティ チェックが一致する場合、YES を出力します。 それ以外の場合は NO を出力します。 

x と y を分離する理由は、リフレクション操作が各座標で独立して動作するため、到達可能性の制約が軸全体できれいに分解されるためです。 

### なぜ効果があるのか

 鏡映公式は、点 (x1, y1) を (2x − x1, 2y − y1) に変換します。 2 を法とする場合、値 2x は常に 0 であるため、各座標は 2 を法とする -x1 に一致し、2 を法とする x1 と同じになります。これは、パリティがどの演算でも不変であることを示しています。 到達可能な状態はパリティを保持する状態だけであり、パリティに一致する任意の点は中間点を適切に選択することで構築できるため、パリティは到達可能性を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    # assuming input is multiple test cases of form:
    # x1 y1 x2 y2 per line (typical for this kind of problem)
    data = input().strip().split()
    if not data:
        return
    
    x1, y1, x2, y2 = map(int, data)
    
    if (x1 % 2 == x2 % 2) and (y1 % 2 == y2 % 2):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```この実装は、以前に導出されたパリティ条件を直接エンコードします。 唯一の微妙な点は、x と y のパリティを独立して比較することです。 パリティは距離に関するものではなくモジュール構造に関するものであるため、それらを混合したり、絶対的な差を使用したりすることは正しくありません。 

Python のモジュロ演算子は整数のパリティ等価性を正しく保持するため、モジュロ 2 の使用は負の座標に対しても安全です。 

## 実用的な例

 開始点 (0, 0) と目標点 (2, 4) を考えてみましょう。 どちらの座標も偶数であるため、パリティが一致します。 

| ステップ | xパリティ | y パリティ | 決定 |
 | --- | --- | --- | --- |
 | スタートとターゲット | 0 対 0 | 0 対 0 | はい |

 これにより、偶数-偶数遷移が有効であることが確認されます。 

ここで、開始点 (1, 0) とターゲット (2, 3) を考えてみましょう。 x パリティは異なりますが、y パリティも異なります。 

| ステップ | xパリティ | y パリティ | 決定 |
 | --- | --- | --- | --- |
 | スタートとターゲット | 1 対 0 | 0 対 1 | いいえ |

 これは、どちらかの座標に不一致があると、到達可能性が完全にブロックされることを示しています。 

これらの例は、大きさは重要ではなく、パリティの一貫性だけがシステムを支配することを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、開始点とターゲットの座標が 1 つだけ異なる場合です。 たとえば、(0, 0) から開始して (1, 0) をターゲットにします。 アルゴリズムはパリティをチェックします。0 % 2 は 0、1 % 2 は 1 であるため、結果は NO になります。 これにより、単一の反射が隣接する点を橋渡しする可能性があるという誤解が正しく処理されます。 

もう 1 つのケースは、(10^9, 10^9) から (2, 2) のように、座標が非常に大きいにもかかわらずパリティを共有する場合です。 パリティ比較は大きさに依存しないため、アルゴリズムは依然として YES を返します。 計算は 2 つのモジュロ演算をチェックするだけなので、オーバーフローや精度の問題は発生しません。 

最後のケースは、1 つの座標のみがパリティと一致する場合です。 たとえば、(2, 3) ～ (4, 6) です。 ここで、x はパリティに一致しますが、y は一致しません。アルゴリズムは正しく NO を返します。これは、両方の軸が反射の下で独立して不変性を満たさなければならないという事実を反映しています。
