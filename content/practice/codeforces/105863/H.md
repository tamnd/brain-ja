 ## 解決策
 ## 問題の理解

 整数の複数セットが与えられます。 このタスクは、要素を直接並べ替えたり選択したりすることではなく、合計が固定されたペアを形成するときにこれらの値がどのように相互作用するかを理解することです。 

固定目標金額の場合$k$、概念的に、合計すると次の順序の値のペアをすべて調べます。$k$。 毎回の値$x$が表示される場合は、次の出現と組み合わせることができます。$k-x$、そのようなペアごとに 1 単位のスコアが貢献します。 両方の数値が同じ場合、つまり$x = k-x$の場合、同じバケット内の要素を効果的にペアにすることになるため、寄与はその周波数内で形成できるペアの数によって決まります。 

出力では、考えられるすべての合計に対してこの合計寄与度を計算する必要があります。$k$、入力周波数によって誘発されたすべてのペアにわたって集計されます。 

重要な構造は、入力を周波数配列に圧縮できることです。$b[i]$、 どこ$b[i]$は何倍の値ですか$i$が表示されます。 すべての推論は、生のリストではなく、これらの周波数で行われます。 

素朴な解釈では、すぐに二次構造が示唆されます。$k$、すべてを繰り返します$x$からの貢献を蓄積します$b[x]$そして$b[k-x]$。 これはすでに示唆しています$O(n^2)$テストごとの動作、または全体的に悪い動作。 

一般的な Codeforce 設定 (大規模な) によって暗示される制約$n$、あたりまで$2 \cdot 10^5$）各状態のすべてのペアを繰り返しスキャンするアプローチは実行不可能になります。 一枚でも$O(n^2)$パスが遅すぎる。 

同一の値が多数存在する場合、微妙なエッジケースが発生します。 たとえば、すべての数値が同じ場合、すべての合計が 1 つの対角項に集中し、対称ペアを 2 倍にカウントしたり、自己ペアを 2 で割るのを忘れたりする不注意な実装により、結果が過大評価されてしまいます。 もう 1 つの失敗例は、周波数が不均一な場合に発生します。1 つの値が非常に頻繁に出現し、他の値がまばらな場合、単純な畳み込みのようなロジックは概念的には機能する可能性がありますが、最適化しないと遅すぎます。 

## アプローチ

 ブルートフォースソリューションは合計を修正します$k$可能なすべての分割を直接チェックします$x + (k-x)$。 すべての有効なペアはそのような分割によって一意に表現されるため、これは正しいです。 ただし、それぞれについて、$k$、これには周波数配列全体をスキャンする必要があり、約$O(n^2)$オペレーション全般。 大きな制約がある場合、これは完全に非現実的になります。 

重要な観察は、多くの周波数層にわたって同じタイプの畳み込みのような構造を繰り返し計算しているということです。 各ペアを個別に扱うのではなく、頻度によって数値をグループ化します。 周波数レベルを固定する場合$f$、どの値が正確に表示されるかだけを考慮します。$f$回および少なくとも出現するもの$f+1$回。 これにより、問題はこれらのグループ間の構造化されたセットの相互作用に変わります。 

このように表現すると、グループ間の寄与は多項式の畳み込みになります。合計が次の 2 つの値を選択します。$k$は、指標多項式の乗算と係数の読み取りに正確に対応します。 標準の畳み込みでは同一のインデックスを含む順序付きペアがカウントされるため、自己ペアには補正項が必要です。 

残る課題は効率性だ。 周波数レベルは疎であるため、繰り返し処理することができ、各レベルは、そのレベルに存在する値の数に応じて、FFT ベースの畳み込みまたは総当たりのいずれかを使用して処理されます。

 ## アルゴリズムのチュートリアル

 入力を配列に圧縮します`freq`、 どこ`freq[v]`値の出現数です`v`。 

次に、この視点を逆転させます。値に焦点を当てる代わりに、周波数レベルを処理します。 周波数ごとに$f$、出現するすべての値を正確に識別します$f$回、および少なくとも表示されるもの$f+1$回。 

### アルゴリズムのステップ

 1. 周波数配列を構築する`freq`。 これにより、入力リストが構造化ヒストグラムに変換されます。これがペア形成に関連する唯一の情報です。 
2. 頻度値からその頻度を持つ数値のリストへのマッピングを構築します。 これにより、同じ出現数を共有するすべての値をまとめて処理できるようになります。 
3. 周波数を昇順に繰り返します。 より高い周波数のグループは相互作用構造の下位層をすでに占めていることに依存するため、この順序付けは重要です。 
4. 固定周波数の場合$f$、値に対して 2 つのインジケーター配列を定義します。`S(x) = 1`もし`freq[x] == f`、それ以外の場合は 0、そして`T(x) = 1`もし`freq[x] > f`。 

この分離により、相互作用は正確に分離されます。$f$要素と高周波要素。 
5. 間の相互作用を計算します。`S`そして`T`畳み込みを使用します。 各ペアは正確に貢献します$f$このような値はすべてペアにすることができるため、対応する合計インデックスに変換されます。$f$独特のやり方。 
6. 内部相互作用を計算する`S`。 直接畳み込みでは、自己ペアリングや重複を含むすべての順序付けされたペアがカウントされます。 畳み込み構造内の要素とそれ自体のペアに対応する寄与を差し引くことで、これを修正します。 
7. 重み付けされた寄与を追加します$f \cdot (\text{S} * \text{T} + \text{S}^2 - \text{correction})$グローバル回答配列に追加します。 
8. アクティブな要素の数が少ないレベルの場合は、畳み込みを直接ペア列挙に置き換えます。 これにより、有益でない場合の FFT オーバーヘッドが回避されます。 

### なぜ効果があるのか

 すべての周波数レベルで、ペアリングに参加できる各値のコピーの数に応じて寄与を分割しています。 すべての有効なペアは、両方のエンドポイントがまだ「利用可能」である最小の頻度で正確に考慮されます。 これにより、各貢献が 1 回カウントされ、正しい多重度で重み付けされることが保証されます。$f$。 畳み込みステップは、明示的に列挙することなく、すべてのペアの合計を一括で計算する効率的な方法にすぎません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def fft(a, invert):
    import cmath
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        ang = 2 * cmath.pi / length * (-1 if invert else 1)
        wlen = complex(cmath.cos(ang), cmath.sin(ang))
        for i in range(0, n, length):
            w = 1
            half = length // 2
            for j in range(i, i + half):
                u = a[j]
                v = a[j + half] * w
                a[j] = u + v
                a[j + half] = u - v
                w *= wlen
        length <<= 1

    if invert:
        for i in range(n):
            a[i] /= n

def convolution(a, b):
    n = 1
    while n < len(a) + len(b):
        n <<= 1
    fa = list(map(complex, a)) + [0] * (n - len(a))
    fb = list(map(complex, b)) + [0] * (n - len(b))

    fft(fa, False)
    fft(fb, False)
    for i in range(n):
        fa[i] *= fb[i]
    fft(fa, True)

    return [int(round(x.real)) for x in fa]

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    maxv = max(arr)
    freq = [0] * (maxv + 1)
    for x in arr:
        freq[x] += 1

    buckets = {}
    for v, f in enumerate(freq):
        if f:
            buckets.setdefault(f, []).append(v)

    active = [0] * (maxv + 1)
    ans = [0] * (2 * maxv + 1)

    for f in sorted(buckets):
        vals = buckets[f]

        S = [0] * (maxv + 1)
        T = [0] * (maxv + 1)

        for v in vals:
            S[v] = 1
        for v in range(maxv + 1):
            if freq[v] > f:
                T[v] = 1

        cntS = len(vals)

        if cntS <= 500:
            for i in vals:
                for j in vals:
                    if i == j:
                        continue
                    ans[i + j] += f
            for i in vals:
                if f >= 2:
                    ans[i + i] += f * (f // 2)
        else:
            st = convolution(S, T)
            ss = convolution(S, S)

            for i, v in enumerate(st):
                if i < len(ans):
                    ans[i] += f * v

            for i, v in enumerate(ss):
                if i < len(ans):
                    ans[i] += f * v

            for i in vals:
                ans[2 * i] -= f

    print(*ans)

if __name__ == "__main__":
    solve()
```FFT は、周波数レベルでのアクティブ セットが大きくなる場合にのみ使用されます。これは、畳み込みが有益になるのは、ペアの 2 次列挙がコストが高すぎる場合のみであるためです。 ブルート ブランチは小さな周波数レイヤーを直接処理し、FFT セットアップによる一定のオーバーヘッドを回避します。 

実装の微妙な詳細は、逆 FFT 後の丸めです。 丸めを行わないと、浮動小数点ドリフトは、特に密な畳み込みで不正確な整数係数を生成します。 もう 1 つの重要な詳細は、体系的に過大にカウントされる自己ペアを分離することです。$S * S$明示的に修正する必要があります。

 ## 特殊なケース

 微妙なケースの 1 つは、すべての要素が同一である場合です。 その状況では、すべての周波数レベルの操作が自己ペア補正に陥ってしまいます。 畳み込み部分が簡単になり、ブルート ブランチが単一バケット内の組み合わせを正確にカウントするため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、1 つの値が現れるなど、周波数が大きく偏っている場合です。$n-1$回と他の人が一度登場します。 このアルゴリズムは、しきい値に応じてブルート フォースまたは FFT によって大きなバケットを処理しますが、重要なのは、各シングルトンが正しい周波数レベルで 1 回だけ相互作用し、レベル間での二重カウントを防ぐことです。 

最後のエッジ ケースは、周波数レベルが 1 つだけ存在する場合に発生します。 この状況では、`T`そのレベルでは空であり、すべての貢献は純粋に`S * S`自己修正機能を使用すると、単一セットの内部ペアを正確にカウントできます。
