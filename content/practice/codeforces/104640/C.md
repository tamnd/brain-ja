 ## 問題の理解

 頂点がユニバースを表し、エッジがポータルを表すグラフが与えられています。 各ポータルには最小エネルギー要件があり、現在のエネルギー レベルが所定のしきい値以上である場合にのみそのポータルを通過できることを意味します。 エネルギーはゼロから始まります。 

初めて宇宙に入ると、あなたのエネルギーはその宇宙に割り当てられた値だけ永続的に増加します。 あなたは固定された宇宙からスタートし、そこから一連の使用可能なポータルに沿って移動し、新しい宇宙を発見するにつれて徐々にエネルギーを増加させることができます。 

課題は、このプロセスの終了までに蓄積できる最大総エネルギーを決定することです。これは、これらの制約の下で到達可能になるすべての宇宙の値の合計に相当します。 

制約サイズにより、すべての可能なパスを繰り返しシミュレートするソリューションは即座に除外されます。 最大 10 万のユニバースと 20 万のポータルがあるため、「現在のノードと訪問先セット」の形式の状態を調査するアプローチは実行不可能です。 エネルギーはノードが訪問される順序に依存するため、拡張状態に対する最短パス スタイルのアルゴリズムであっても、組み合わせ爆発が起こります。 

微妙な問題は循環依存性から生じます。 ポータルは、要件が高すぎるため、初期には使用できなくなる可能性がありますが、他のユニバースから十分なエネルギーを収集すると、使用できるようになり、より多くのユニバースのロックを解除できる可能性があります。 これは、到達可能性が静的ではないことを意味します。 

よくある落とし穴は、これを標準的な到達可能性の問題として扱い、単純に重みを無視したり、エッジの重みを持つノードに対してダイクストラを実行したりすることです。 これは、制約がエッジに沿って追加的ではなく、グローバルに変化するしきい値であるため、失敗します。 

別の障害ケースは、大きなエネルギーを提供するノードに高しきい値エッジ経由でのみアクセスできる場合に発生します。 ブロックされたエッジを決して再訪問しない単純な貪欲なトラバーサルでは、そのようなノードがグラフの残りの部分のロックを解除するために重要であるにもかかわらず、見逃されてしまいます。 

## アプローチ

 この強引なアイデアは、宇宙を訪れるあらゆる可能な方法をシミュレートすることです。 初期ユニバースから開始して、各ステップで現在到達可能なすべてのポータルを試し、許可されている場合はポータル内を移動し、再帰的に続行します。 各州は、どの宇宙を訪れたか、そして現在のエネルギーを記憶する必要がある。 新しい宇宙ごとにエネルギーが変化し、将来の到達可能性も変化するため、分岐要素は急速に成長します。 最悪の場合、これはノードのサブセットに対する指数関数的な探索につながります。 

重要な観察は、エッジのロックを解除するために重要なのは現在の総エネルギーだけであり、これはすでに訪問したノードの値の合計であるということです。 ノードが到達可能になると、そのノードにアクセスするとエネルギーが増加するだけで、より多くのエッジのロックを解除できるだけです。 柔軟性を低下させるメカニズムはありません。 

この単調な構造は、到達可能な集合プロセスが増大していることを示唆しています。 到達可能なノードの最終セットがわかっている場合、それらの合計が最終的なエネルギーを決定し、その同じエネルギーによってどのエッジが使用可能であるかが決まります。 この循環依存関係は、現在のエネルギー推定値を使用して到達可能な範囲を繰り返し拡張することで解決できます。 

要件がすでに満たされているエッジのセットを維持し、それらのエンドポイントを接続されたコンポーネントにマージできます。 開始ノードを含むコンポーネントが十分に大きくなると、その合計ノード値はエネルギーを増加させ、潜在的により多くのエッジのロックを解除し、より多くのコンポーネントを開始コンポーネントにマージする可能性があります。 これにより、自然な固定点プロセスが作成されます。

 ## アルゴリズムのチュートリアル

 私たちは宇宙全体にわたって素の集合結合構造を維持しており、エネルギーが増加するにつれてポータルを徐々に活性化します。 各アクティベーションによってコンポーネントがマージされる可能性があり、開始ユニバースを含むコンポーネントのみが将来のエネルギーの増加に寄与します。 

1. すべてのユニバースにわたる素集合共用体を初期化します。 各ユニバースは独自のコンポーネントとして開始され、各コンポーネントはそのノード値の合計を格納します。 開始宇宙はすぐに訪問済みとみなされ、初期エネルギーはその値と等しくなります。 
2. すべてのポータルを必要なエネルギーの昇順に並べ替えます。 これにより、エネルギーが十分に大きくなったら、段階的にそれらを活性化することができます。 
3. 並べ替えられたポータルの上にポインタを置きます。 最大でも現在のエネルギーを必要とするすべてのポータルを繰り返しアクティブにします。 アクティベーションとは、DSU でユニオン操作を実行することを意味します。 
4. 現在使用可能なすべてのポータルをアクティブ化した後、開始ユニバースを含むコンポーネントを見つけます。 その合計を計算します。これは、現在ロックが解除されている構造で達成可能な最良のエネルギーを表します。 
5. この新しいエネルギーが以前の値より大きい場合は、エネルギーを更新してプロセスを繰り返します。これは、より高いエネルギーにより、以前にブロックされていた追加のポータルのロックが解除される可能性があるためです。 
6. ポータル リストを完全に通過しても新しいポータルがアクティブ化されない、または到達可能なコンポーネント サイズが増加しない場合は停止します。 

重要なアイデアは、エネルギーが増加するたびに、使用可能なエッジのセットを拡張し、そのような拡張は開始コンポーネントの接続性を高めるだけであり、決して減らすことはできないということです。 

### なぜ効果があるのか

 いつでも、すべてのアクティブ化されたエッジから構築された DSU は、使用されているすべてのポータルの要件が最大でも現在のエネルギーであるという制約の下での接続を正確に表します。 この構造の開始ノードのコンポーネントは、そのエネルギー レベルで実際に到達可能なすべての宇宙を表します。 エネルギーは訪問した宇宙の値の合計として定義されるため、このコンポーネントからエネルギーを再計算することは、到達可能になったときに各宇宙を 1 回訪問するプロセスと一致します。 エネルギーとアクティブ化されたエッジのセットは時間の経過とともに増加するだけであるため、プロセスは、新しいエッジをアクティブ化できず、新しいノードが開始コンポーネントに参加できない固定点に収束する必要があります。 その固定点が達成可能な最大エネルギーです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, val):
        self.parent = list(range(n))
        self.size = [1] * n
        self.sum = val[:]  # component sums

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.sum[a] += self.sum[b]
        return True

def solve():
    n, m, s = map(int, input().split())
    s -= 1

    a = list(map(int, input().split()))

    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    dsu = DSU(n, a)

    energy = a[s]
    prev_energy = -1

    i = 0
    while energy != prev_energy:
        prev_energy = energy

        while i < m and edges[i][0] <= energy:
            _, u, v = edges[i]
            dsu.union(u, v)
            i += 1

        root = dsu.find(s)
        energy = dsu.sum[root]

    print(energy)

if __name__ == "__main__":
    solve()
```DSU は接続性と値の合計の両方を各コンポーネント内に保存するため、マージのたびに合計を再計算する必要がなくなります。 ポインタ`i`しきい値が満たされると永続的にアクティブなままになるため、各エッジが 1 回だけ処理されることが保証されます。 

エッジをアクティブにすると開始コンポーネントが拡大され、エネルギーが増加し、より多くのエッジのロックが解除される可能性があるため、外側のループは不可欠です。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのエッジのしきい値が初期エネルギーよりも大きい場合です。 その状況では、アルゴリズムは開始ノードを超えて結合を正しく実行せず、答えは開始ユニバースの値のみのままになります。 

別のエッジ ケースは、単一の低しきい値エッジがより高い値のノードの大規模チェーンに接続するときに発生します。 このアルゴリズムは、エネルギーが十分に増加した後にのみチェーンのロックを解除します。また、反復ループにより、最初の接続が確立されると、以前のロジックを手動で再検討することなく、後続の拡張が自然にトリガーされます。 

最後の微妙なケースは、かなり後でアクティブになるエッジを介してコンポーネントが間接的にマージされる場合です。 DSU はこれをクリーンに処理します。エッジが一度アクティブになると、その効果は永続的であり、後でエネルギーが増加しても、古いエッジを再処理したり、決定を覆したりする必要がないからです。
