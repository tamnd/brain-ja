 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$ここで、各セルは黒または白です。 行全体を反転したり、列全体を反転したりして、その行のすべての色を切り替える操作を適用できます。 このような一連の操作の後、グリッドに左上のセルからの単調パスが含まれるようにします。$(1,1)$右下のセルへ$(n,m)$、右または下のみに移動し、黒いセルのみを訪問します。 

主な難点は、完全な黒の領域を構築する必要はなく、いくつかの行と列を反転した後に少なくとも 1 つの有効なパスの存在を保証するだけであることです。 各行または列の反転はバイナリ トグルとして機能するため、すべてのセルの色は元の値とその行と列の反転状態の XOR になります。 

制約$n, m \le 2000$最大 400 万個のセルを意味します。 すべての反転サブセットを試したり、変更後にすべてのパスをチェックしたりする解決策は不可能です。 平$O(nm \cdot (n+m))$はすでに境界線にあるため、問題を線形または線形に近い構造に還元する構造が必要です。 

両方のエンドポイントを黒にすることができる場合でも、必要なパスが不可能な場合、微妙なエッジ ケースが発生します。 たとえば、次のようなグリッドがあります。$(1,1)$そして$(n,m)$個別に修正できますが、一貫した行および列パリティの単調チェーンは存在しません。 

もう 1 つのエッジ ケースは、グリッドがすでに適切であるにもかかわらず、単純な推論で反転が必要であると示唆される場合に発生します。 フリップはオプションであるため、正解は操作がゼロになる可能性があります。 

## アプローチ

 中心的な観察は、行と列の反転によって各セルのバイナリ ラベリングが定義されることです。$(i,j)$になる$$a_{i,j} \oplus r_i \oplus c_j$$どこ$r_i, c_j \in \{0,1\}$。 これは、セルを自由に変更するのではなく、行と列に対して 2 部パリティ変換を強制することを意味します。 

強引なアイデアは、行と列のすべてのサブセットを試してみることです。$2^{n+m}$。 構成ごとに、BFS または DP を使用して、黒のモノトーン パスが存在するかどうかを確認できます。 構成を保存することさえ不可能なため、これはすぐに爆発します。 

重要な構造的洞察は、視点をグリッド全体からパス制約のみに移すことです。 からのモノトーンの小道$(1,1)$に$(n,m)$常に正確に構成されています$n+m-1$セルに移動し、すべての移動は行方向または列方向に留まります。 これにより、制約された一連の遷移に沿って一貫した「黒の状態」を維持するという観点から考えることができます。 

最初にフリップを決定するのではなく、有効なパスに沿ってどのような条件が保持されなければならないかを検討します。 パスが存在する場合、そのパス上のすべてのセルは黒になる必要があるため、そのような各セルには制約が課されます。$$r_i \oplus c_j = a_{i,j}$$並べ替えると、これは単調なパスに沿った XOR 方程式系です。 重要なアイデアは、$r_1 = 0$、パス全体により、関係するすべての行と列の値が一貫したものになります。 矛盾がある場合は、パスを完全に黒にすることができないことを意味します。 

したがって、問題は、この誘導された制約システムが矛盾しない単調パスが存在するかどうかをチェックすることに帰着する。 パスは指数関数的であるため、代わりにグリッド上の動的な伝播を使用して実現可能性をエンコードします。セルが、一貫した割り当て状態とともに部分的に構築された有効なパスの最後の位置になり得るかどうかを維持しますが、これにはまだ簡素化が必要です。 

最後の単純化は、制約が遷移のみに依存することに気づくことから来ています。 行内で右に移動すると、連続する列の間に制約が導入されます。 列内で下に移動すると、連続する行の間に制約が導入されます。 これにより、暗黙的なグラフ内のパスに沿った 2 部ラベリングの一貫性を強制するものとしてグリッドを扱うことができ、実現可能性はパリティの矛盾を生じないパスを見つけることになります。これは、行ラベルと列ラベルの状態圧縮を備えた 0-1 BFS スタイルの伝播を使用してテストできます。 

実行可能なパスが特定されると、必要な行と列の反転がパスによって暗示されるパリティ割り当てから直接再構築され、条件を満たすために切り替える必要があるすべての行と列が選択されます。$r_i \oplus c_j = a_{i,j}$途中で。 各変数はグローバル フリップまで一意に固定されるため、フリップの数は最小限に抑えられます。

 ## アルゴリズムのチュートリアル

 1. 各セルを制約として解釈します$r_i \oplus c_j = a_{i,j}$。 これにより、問題は、単調なパスに沿って行ビットと列ビットの一貫した割り当てを見つけることに変わります。 
2. セルが正常に動作するかどうかを追跡する動的プログラミング テーブルを構築します。$(i,j)$以前に暗示された行および列の値との一貫性を維持しながら、単調なパスで到達できます。 状態にはすべての割り当てが明示的に保存されるのではなく、そのセルに到達するために一貫した割り当てが存在するかどうかのみが保存されます。 
3. 次の場所でプロセスを初期化します。$(1,1)$ここで、開始パリティを任意に修正し、最初のセルから最初の行と列の制約を導出します。 
4. 右下に伝播します。 右に移動すると、現在の行を基準にして次の列に制約が適用され、下に移動すると、現在の列を基準にして次の行に制約が適用されます。 暗黙のパリティに矛盾が生じた場合、その遷移は無効になります。 
5. 到達するまで続ける$(n,m)$。 一貫した制約の下で到達できない場合、有効な反転戦略は存在しません。 
6. 到達可能性が確認されたら、選択したパスに沿って暗黙のパリティ関係をバックトラックして行と列の反転を再構築し、それぞれに割り当てます。$r_i$または$c_j$一貫して。 
7. Output all indices where$r_i = 1$そして$c_j = 1$、これらは反転する必要がある行と列に対応しているためです。 

### なぜ効果があるのか

 このアルゴリズムは、候補単調パスに沿ったすべてのステップが、すべての訪問セルと一致する部分 XOR 割り当てを維持するという不変式に依存しています。 パスを拡張するたびに、新しい方程式が 1 つだけ導入されるため、一貫性は 2 部のラベル付けに矛盾がないかどうかをチェックすることになります。 すべての行と列の変数はこれらの方程式によってのみ制約されるため、実行可能な完全なパスはグローバルに一貫した割り当てを誘導し、矛盾がある場合はパスを拡張しても修正できないことを意味します。 これにより、状態空間での到達可能性は、有効な変換の存在と同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    # We maintain parity constraints via DP:
    # dp[i][j] = whether cell (i,j) can be reached with consistent constraints
    dp = [[False] * m for _ in range(n)]
    parent = [[None] * m for _ in range(n)]

    dp[0][0] = True

    for i in range(n):
        for j in range(m):
            if not dp[i][j]:
                continue

            if i + 1 < n:
                if not dp[i + 1][j]:
                    dp[i + 1][j] = True
                    parent[i + 1][j] = (i, j)
            if j + 1 < m:
                if not dp[i][j + 1]:
                    dp[i][j + 1] = True
                    parent[i][j + 1] = (i, j)

    if not dp[n - 1][m - 1]:
        print(-1)
        return

    # reconstruct any monotone path
    path = []
    x, y = n - 1, m - 1
    while True:
        path.append((x, y))
        if (x, y) == (0, 0):
            break
        x, y = parent[x][y]

    path.reverse()

    # assign row/col flips greedily along path constraints
    r = [0] * n
    c = [0] * m

    r[0] = 0
    for x, y in path:
        for nx, ny in [(x + 1, y), (x, y + 1)]:
            if 0 <= nx < n and 0 <= ny < m:
                # enforce consistency
                need = int(g[nx][ny])
                if nx == x + 1:
                    r[nx] = r[x] ^ c[y] ^ need
                else:
                    c[ny] = r[x] ^ c[y] ^ need

    rows = [i + 1 for i in range(n) if r[i] == 1]
    cols = [j + 1 for j in range(m) if c[j] == 1]

    print(len(rows), len(cols))
    print(*rows)
    print(*cols)

if __name__ == "__main__":
    solve()
```この解決策は、まずグリッドを単調なパス上の到達可能性の問題に落とし込み、次にそのようなパスの 1 つを再構築します。 配列`r`そして`c`行と列の反転決定をそれぞれ保存します。 再構成ステップでは、各訪問セルが必要な XOR 条件を満たすように、パスに沿って制約を伝播します。 

重要な実装の詳細は、ここでの DP は構造的にパスの存在を保証しているだけであるということです。 実際の正確さは、行と列の値がグローバルに推測されるのではなく段階的に導出される、再構築中の一貫性の強制によって実現されます。

 ## 特殊なケース

 1x1 のような最小限のグリッドは、反転後に単一のセルが黒である場合にのみ一貫性があります。 アルゴリズムはこれを遷移が存在しない縮退パスとして扱うため、唯一の制約は直接パリティであり、行または列の反転によって独立して修正されます。 

完全に均一なゼロのグリッドでもパスは許可されますが、そのパス上のすべてのセルが反転によって強制的に修正されます。 選択したパスに沿ったすべての制約が一致するため、再構成では一貫した行と列の値が割り当てられます。また、XOR 方程式はツリー状の構造にわたって線形で一貫したままであるため、矛盾は発生しません。
