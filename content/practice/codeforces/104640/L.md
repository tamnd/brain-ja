 ## 問題の理解

 長さの隠し配列が与えられます$n$。 配列は厳密に増加しています。つまり、次のすべての値が前の値よりも大きくなります。 ただし、配列を直接見ることはできません。 

代わりに、インタラクティブな機能があります$f(x)$。 各クエリは位置の値を要求します$x$、ただし、配列は未知の値による隠れた巡回シフトを使用してアクセスされます。$c$。 具体的には、ポジションを尋ねるとき、$x$、実際には、もともと位置にあった値を受け取ります$x+c$、必要に応じて配列をラップします。 

したがって、クエリを通じて観察する配列は、ソートされた増加配列の回転バージョンにすぎません。 私たちの課題は回転量を回復することです$c$、最大 42 個のクエリを使用します。 

制約が意味するのは、$n$と同じ大きさにすることができます$10^5$したがって、直線的なものを買う余裕はありません。$n$。 程度に制限されています$O(\log n)$インタラクションクエリ。 すべての位置をスキャンするアプローチは直ちに不可能です。 

重要な構造上の事実は、厳密に増加する配列を回転すると、順序が大きな値から小さな値にリセットされる「ブレーク ポイント」が 1 つだけある循環的にソートされた配列になるということです。 この構造は安定しており、二分探索が可能です。 

素朴な試みは、すべての位置をクエリして完全な配列を再構築し、次に最小値を見つけてシフトを推定することです。 これは、$n$クエリを実行し、制限に失敗します。 

もう 1 つの素朴なアイデアは、隣接する位置を比較して、増加が途切れる場所を見つけることです。 概念的には正しいですが、それでも必要です$O(n)$クエリ。 

唯一の効率的な方法は、回転ソートされたシーケンス内の 1 つの不連続性を利用することです。 

## アプローチ

 インタラクションの制限を無視する場合、最も簡単な方法は、すべてのインデックスをクエリすることです。$1$を通して$n$、配列を再構築し、最小要素位置を見つけて、シフトを計算します。 これが機能するのは、元の配列が厳密に増加しているため、最小値が回転ポイントを一意に識別するためです。 問題は、これが消費することです$n$クエリは、許可されている 42 をはるかに超えています。$n$大きいです。 

重要な観察は、観察された配列が回転されたソート配列であるということです。 このような配列は、1 つのピボット ポイントを除いて単調な構造を持ちます。 これは、既知の境界値と比較することにより、二分探索を使用して最小要素を特定できることを意味します。 

回転増加配列では、「左セグメント」のすべての要素が「右セグメント」の要素より大きく、最小要素が右セグメントの先頭に位置するという事実を利用します。 中間点を固定基準と比較することで、どの半分に最小値が含まれているかを判断し、残りの半分を破棄できます。 

クエリされた配列内の最小要素の位置を特定したら、そのインデックスを回転シフトに変換して戻すことができます。$c$。

 ## アルゴリズムのチュートリアル

 クエリされたシーケンスを、回転されたソートされた配列として扱います。 目標は、このシーケンス内の最小要素のインデックスを見つけることです。 

1. まず、固定の参照位置をクエリします。通常は、$f(n)$。 この値は、回転された配列内の最初にソートされたセグメントの最後の要素に対応し、2 つの単調部分を分離するしきい値として機能します。 この値との比較により、回転のどちら側にいるかを検出できるようになります。 
2. 以下のインデックスに対して二分検索を実行します。$1$に$n$。 それぞれの中間点で$mid$、クエリします$f(mid)$。 
3. もし$f(mid) > f(n)$、 それから$mid$は左側のソートされたセグメントにあります。つまり、最小要素は右側にある必要があります。$mid$。 検索間隔を右半分に移動します。 
4. それ以外の場合は、$f(mid) \le f(n)$、 それで$mid$は右側のセグメント (最小値を含むラップされた部分) にあります。 この場合、最小値は次のとおりです。$mid$またはその左側にあるので、間隔を左半分に縮小します。$mid$。 
5. 二分探索が終了すると、左側の境界は、回転された配列内の最小要素の位置と等しくなります。 このポジションに電話をかける$pos$。 
6. 最後に、この位置をシフト値に変換し直します。$c$。 回転は周期的であるため、関係は次のようになります。$c = (n + 1 - pos) \bmod n$。 

### なぜ効果があるのか

 回転された配列には、大きな値の後に小さな値が続く不連続点が 1 つだけあります。 この点の片側のすべての要素は、反対側のすべての要素よりも厳密に大きくなります。 との比較$f(n)$は、元の配列を直接知る必要がなく、これら 2 つの領域を一貫して区別します。 二分検索の不変条件は、最小要素が常に現在の検索間隔内に残り、更新ルールがそれを含むセグメントを決して破棄しないことです。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def ask(x):
    print(f"? {x}", flush=True)
    v = int(input().strip())
    if v == -1:
        exit(0)
    return v

def main():
    n = int(input().strip())
    if n == 1:
        print("! 0", flush=True)
        return

    fn = ask(n)

    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        vm = ask(mid)

        if vm > fn:
            l = mid + 1
        else:
            r = mid

    pos = l
    c = (n + 1 - pos) % n
    print(f"! {c}", flush=True)

if __name__ == "__main__":
    main()
```このソリューションは対話型クエリに依存しているため、すべての出力はすぐにフラッシュされます。 最初に保存される値は$f(n)$、ピボット コンパレータとして機能します。 二分探索ステップごとに、最小値の位置を維持しながら候補間隔が半分に減ります。 

位置からシフトへの最終変換では、循環インデックス付けが慎重に処理されます。 モジュロ式により、最小値が位置 1 または位置 にある場合でも正確さが保証されます。$n$。

 ## 特殊なケース

 いつ$c = 0$、配列はすでにソートされており、最小値は位置 1 にあります。二分探索では、すべての中点が満たされるため、右境界が 1 に収束するまで常に左に押し出されます。$f(mid) \le f(n)$。 

いつ$c = n-1$、最小の要素は最後の位置に表示されます。 二分探索では、最初に左側のセグメントで大きな値が観察され、最終的な位置が分離されるまで右にシフトを繰り返します。 

のために$n = 1$、クエリは必要なく、回転が不可能であるため、答えは自明のことながらゼロになります。
