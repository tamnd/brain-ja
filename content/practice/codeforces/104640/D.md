 ## 問題の理解

 長さの文字列を構築するように求められます$n$ラテン文字の小文字の上に。 文字列を出力した後、マシンは、どの文字が出現するか、およびそれぞれの文字が何回出現するかのみに依存する方法で文字列を評価します。 

マシンはまず、文字列内で使用されている個別の文字の数を数えます。これを呼び出します。$k$。 次に、それらに割り当てます$k$文字と異なる整数の重み$1$に$k$、最終スコアを最小にする課題を選択します。 スコアは、文字列内に出現するすべての文字の重みを合計することによって計算されます。 

したがって、マシンは重みの割り当て方法において事実上敵対的ですが、それでも次の順列を使用するように制約されます。$1 \ldots k$。 文字頻度の固定マルチセットの場合、マシンはより頻度の高い文字に小さな重みを割り当てます。これは、合計が減少するためです。 

長さの文字列を構築する必要があります$n$これは、この最終的な最小化されたスコアを最大化します。 

入力できるサイズは、$n \le 10^5$、したがって、$O(n)$または$O(n \log n)$工事。 すべての文字列または順列の検索を伴うものは、文字列の数が膨大であるため、直ちに実行できません。$26^n$また、1 つの構成を評価する場合でもソート頻度が必要ですが、繰り返し実行すると時間がかかりすぎます。 

すべての文字が同一である場合、微妙なエッジケースが発生します。 たとえば、次の場合$n = 3$そして文字列は`"aaa"`、 それから$k = 1$、重量は強制的に$1$、スコアは$3$。 代わりに使用する場合`"abc"`、 それから$k = 3$、そしてマシンが重みを割り当てます$1,2,3$可能な限り最良の方法で、より大きなスコアにつながります。 これは、多様性の増加によりスコアが増加する傾向があることを示唆していますが、マシンは常に私たちに対して最適な重みを割り当てるため、相互作用は単に「異なる文字を最大化する」だけではありません。 

## アプローチ

 文字列を修正すると、マシンの動作は決定的になります。つまり、文字を頻度によって降順に並べ替え、重みを割り当てます。$1$最も頻繁な手紙に、$2$2 番目に頻度の高いものまで、というように続きます。 これは、頻繁に出現する文字ごとに小さい重みが乗算されるため、合計を最小限に抑えるのに最適です。 

したがって、値は次のようになります。$$T = \sum_{i=1}^{k} f_i \cdot w_i$$どこ$f_i$周波数は昇順でない順にソートされており、$w_i$の順列です$1 \ldots k$として最適に割り当てられます。$w_i = i$。 

したがって：$$T = \sum_{i=1}^{k} f_i \cdot i$$ここで文字列を選択します。つまり、合計が最大 26 文字にわたる頻度分布を選択します。$n$、この加重合計を最大化します。 

重要な観察は、インデックスが高いほど価値が高いため、大きな周波数を大きな重みと一致させる必要があるということです。 重みは次のように固定されているため、$1$を通して$k$、最大化する$k$だけでは十分ではありません。 代わりに、より大きなインデックスが大きなカウントを取得できるように頻度を構造化したいと考えています。 

ただし、より強力な単純化があります。 固定の場合$k$、私たちができる最善のことは、最大のインデックスにできるだけ多くの質量を集中させることです$k$、その文字が最も重要視されるためです。 最大化するには$T$を最大化したい$k$、増加して以来$k$項の数と最大可能重みの両方が増加します。 

しかし$k \le 26$, したがって、常に最大 26 個の異なる文字を使用できます。 26 個すべてを使用したら、残る選択肢は周波数をどのように分配するかだけです。 固定用$k$を最大化するには:$$\sum i \cdot f_i$$最大の周波数を最大のインデックスに割り当てる必要があります。 これは、インデックスの逆順で厳密に増加する周波数割り当てが必要であることを意味します。 

これは典型的な貪欲な構造になります: 配布する$n$次のような最大 26 文字の文字。$$f_{26} \ge f_{25} \ge \cdots \ge f_1 \ge 0$$そして加重和を最大化します。 最適な戦略は、26 文字すべてを使用することです (場合によってはそれより少ない文字も使用します)。$n < 26$) を可能な限り均等に分散し、最初にインデックスの高い文字に余分な文字を与えます。

 ## アルゴリズムのチュートリアル

 1. 異なる文字の数を決定する$k = \min(26, n)$。 これにより、可能な限り多様性を最大化しながら、アルファベットの制限を決して超えないようにすることができます。 
2. 文字の頻度を表すサイズ 26 の配列をすべてゼロで初期化します。`'a'`に`'z'`。 
3. 最初のそれぞれに 1 つのオカレンスを割り当てます。$k$文字。 これにより、可能な限り最大の個別の文字を使用することが保証されます。 
4. 残りの文字を$rem = n - k$。 これらは、配布する必要がある追加のオカレンスです。 
5. からの文字に追加の 1 文字を繰り返し割り当てます。`'a' + k - 1`下向きに`'a'`、残りのすべての文字が配布されるまで、最高のインデックスから最低のインデックスまで循環します。 これにより、重みの高い文字ほど多くの頻度が受信され、重み付けされた合計が最大化されます。 
6. 頻度に従って各文字を繰り返して、最終的な文字列を作成します。 

### なぜ効果があるのか

 最終的なスコアは、高周波数と高重みの一致に依存します。 マシンは頻度の低い文字に高い重みを割り当てるため、マッピングによって大きなカウントが大きな重みに強制されるように、頻度の順序を制御する必要があります。 追加の出現を逆アルファベット順に分散することにより、インデックスの高い文字の頻度がインデックスの低い文字よりも低くなることはありません。 これにより、マシンのソートされた周波数順序が構築された順序と一致した状態に保たれ、より高い重みの寄与が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    k = min(26, n)
    freq = [0] * 26
    
    for i in range(k):
        freq[i] = 1
    
    rem = n - k
    idx = k - 1
    
    while rem > 0:
        freq[idx] += 1
        rem -= 1
        idx -= 1
        if idx < 0:
            idx = k - 1
    
    res = []
    for i in range(26):
        res.append(chr(ord('a') + i) * freq[i])
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```この解決策では、まず、最初の文字のそれぞれに 1 つの出現を割り当てることで、最大の異なる文字を確保します。$k$文字。 残りの文字は、最も高いインデックスが付けられたアクティブな文字から開始して貪欲に分散されます。これにより、ソート後に機械によって割り当てられたより高い重みに対応する、辞書編集的に後の文字の頻度が上方に偏ります。 

構築フェーズは単純です。計算された頻度に従って各文字を繰り返すことによって文字列を再構築します。 

実装の微妙な詳細は、次の循環デクリメントです。`idx`これにより、インデックスが完全に枯渇するのではなく、選択されたすべての文字間で公平な分散が保証されます。$rem$大きいです。
