 ## 解決策
 ## 問題の理解

 1 から n までの同じ頂点ラベルのセットを共有する 2 つの別個の有向非重み付き重み付きグラフが与えられます。 これらは、同じ座標に n 個の高層ビルが配置されている 2 つの平行した都市と考えることができますが、各都市内で許可される移動ルートは異なります。 

最初の都市の内部では、いくつかの超高層ビルのペアが、指定された移動時間の双方向エッジによって接続されています。 2 番目の都市には、独自の移動時間を持つ独自の双方向エッジのセットがあります。 これらの内部的な動きに加えて、特別な移行があります。最初の都市の超高層ビル i から、固定コスト x 秒を支払うことで、即座に 2 番目の都市の超高層ビル i に「世界を切り替える」ことができ、同じことが逆に機能します。 

最初の世界の超高層ビル s からスタートし、内部移動と世界切り替えを組み合わせて、最小の合計時間で 2 番目の世界の超高層ビル t に到達したいとします。 

重要な構造は、これが 2 つの別々の最短経路問題ではないということです。 ワールド間の移動は 2 つのグラフを結合するため、コストが削減される場合は、最適なルートがワールド間で複数回切り替わる可能性があります。 

制約はアルゴリズムの選択に直接関係します。 n が最大 100,000 で、ワールドごとに最大 10^6 のエッジがあるため、結合されたグラフには数百万のエッジと 100,000 の交差エッジが含まれます。 クエリごとに最短パスを再計算しようとしたり、密な表現を使用したりするソリューションは失敗します。 ヒープを使用したダイクストラなど、対数係数を使用した線形または線形に近いグラフの走査が唯一の現実的なオプションです。 

単純な間違いは、各世界の最短経路を個別に計算してから、貪欲に答えを組み合わせようとすることです。 世界を切り替えると厳密に安価なルートがロック解除される可能性があるため、これは失敗します。 

たとえば、ワールド 1 では s から t へのパスは非常に高価ですが、s からある i へのパスは安く、ワールド 2 では i から t へのパスが安いとします。 最適なルートは i で世界を切り替える必要がありますが、分離された計算では決して正しく考慮されません。 

もう 1 つの微妙な失敗例は、ワールド スイッチが 1 つだけで十分であると想定している場合です。 これは誤りです。なぜなら、ワールド 1 の長いセグメントをバイパスするためにワールド 2 に早く入ってから、別のインデックスを介してワールド 1 に戻り、後で必要に応じて再び切り替える可能性があるからです。 

## アプローチ

 ブルートフォースメンタルモデルは、両方の世界にわたるあらゆる可能な一連の動きを状態空間探索として扱うことです。 各状態は、現在のノードだけでなく、現在のワールドによっても定義されます。 ある状態 (ノード、ワールド) から、そのワールド内のすべてのエッジをトラバースしたり、同じインデックス コスト x で他のワールドに切り替えることができます。 

これにより、2n 個の頂点を持つグラフが形成されます。 すべての元のエッジは正確に 1 つのレイヤーに寄与し、すべてのインデックス i は (i, world1) と (i, world2) の間のクロスエッジに寄与します。 この展開されたグラフ上で最短経路を実行すると、正しい答えが得られます。 

単純な実装はすでにダイクストラのアルゴリズムに直接つながっています。 重要な洞察は、問題は 2 つのグラフのように見えますが、実際には 2n 個のノードを持つ単一の疎な重み付きグラフであるということです。 クロスワールド移行は単なる追加のエッジです。 この再定式化が見られれば、それ以上のトリックは必要ありません。 

より遅い代替案は、「スイッチの数」にわたって動的プログラミングを試みたり、グラフ間のパスを繰り返し緩和したりすることですが、これは最短パスの計算を繰り返すことになり、10^6 エッジの下では遅すぎます。 

正しいアプローチは、結合されたグラフに対してダイクストラを 1 回実行するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パスに対するブルート フォース / 繰り返しの再計算 | 指数 / O(k・(n+m) log n) | O(n+m) | 遅すぎる |
 | 2 層グラフ上のダイクストラ | O((n + m1 + m2) log n) | O(n + m1 + m2) | 承認済み |

 ## アルゴリズムのチュートリアル

We construct a graph with 2n nodes. ノード i はワールド 1 の超高層ビル i を表し、ノード i + n はワールド 2 の超高層ビル i を表します。 

次に、最初の世界のすべてのエッジを前半の内側に追加し、2 番目の世界のすべてのエッジを後半の内側に追加し、i と i + n の間にコスト x の交差エッジを追加します。 

ワールド 1 の開始ノード s からダイクストラを実行し、すべてのノードまでの距離を計算します。 答えはワールド 2 の t までの距離、または到達できない場合は無限大です。 

## アルゴリズムのチュートリアル

 1. 2n 個の頂点を持つグラフを構築し、問題を 2 つのレイヤー (各世界に 1 つずつ) に分割します。 この分離により、世界の切り替えを特別なロジックではなく明示的なエッジとしてエンコードできるようになります。 
2. 最初の世界のすべてのエッジ u、v、c に対して、レイヤー 1 の u と v の間に重み c を持つ双方向エッジを追加します。 これにより、ワールド 1 内で許可されたすべての動きが指定されたとおりに正確に保存されます。 
3. 2 番目の世界のすべてのエッジ u、v、c に対して、u + n と v + n の間に重み c を持つ双方向エッジを追加します。 これにより、2 番目の世界がグラフの後半に反映されます。 
4. 1 から n までのインデックス i ごとに、コスト x の i から i + n および i + n から i の 2 つのエッジを追加します。 これは、世界中の同一の超高層ビル間のテレポートをモデル化します。 正確さは、ワールドを切り替えてもインデックスは変更されず、レイヤーのみが変更されるという事実に依存します。 
5. ワールド 1 (ノード s) の s からダイクストラを実行します。 これは、ワールド内の移動と切り替えの可能なすべての組み合わせを合計時間の短い順に調査します。 
6. ワールド 2 のノード t までの距離 (ノード t + n) を抽出します。 If this distance is still infinite, output -1.

 ### なぜ効果があるのか

 元の問題のすべての移動タイプはエッジとして表されるため、有効な行程は、構築された 2n ノード グラフ内のパスに正確に対応します。 逆に、構築されたグラフ内のすべてのパスは、元の設定における正当な一連の動きに対応します。 すべてのエッジの重みが負ではないため、ダイクストラは、最初にノードを完成させるときに、そのノードに到達するための最小コストが見つかったことを保証します。 これにより、(ワールド 2 の t) までの計算された距離が、考えられるすべての混合ワールド ルートの中で最適な移動時間となることが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, x = map(int, input().split())
    
    m1 = int(input())
    g = [[] for _ in range(2 * n)]
    
    for _ in range(m1):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, c))
        g[v].append((u, c))
    
    m2 = int(input())
    for _ in range(m2):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        u += n
        v += n
        g[u].append((v, c))
        g[v].append((u, c))
    
    for i in range(n):
        g[i].append((i + n, x))
        g[i + n].append((i, x))
    
    s, t = map(int, input().split())
    s -= 1
    t -= 1
    
    dist = [INF] * (2 * n)
    dist[s] = 0
    pq = [(0, s)]
    
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        if u == t + n:
            break
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    
    ans = dist[t + n]
    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```コードは 2 層グラフ構造を直接実装します。 隣接リスト`g`は両方のワールドを同時に保持します。インデックス [0, n-1] はワールド 1 を表し、[n, 2n-1] はワールド 2 を表します。 

最もデリケートな部分はインデックスの処理です。 すべての頂点はゼロベースのインデックスに変換され、2 番目の世界は +n だけシフトされます。 クロスエッジは i ごとに均一に追加され、スイッチング方向間の対称性が保証されます。 

ダイクストラ ループでは、標準の優先キューが使用されます。 ターゲットに到達したときの早期ブレイクはオプションですが、ダイクストラは最小距離でターゲットを初めてポップすることが最適であることを保証しているため、安全です。

 ## 特殊なケース

 エッジ ケースの 1 つは、ワールド内エッジがまったく存在しない場合です。 可能な移動はワールド スイッチのみであるため、パスは交互のスイッチの単純なチェーンになります。 ダイクストラは通常どおりクロス エッジを探索し、到達可能な場合は答えが x の倍数になるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、最適なパスに複数のスイッチが必要な場合です。 たとえば、ワールド 2 を使用して旅の一部をショートカットし、ワールド 1 に戻って別の地域に到達し、その後再び切り替えます。 2n ノードのグラフでは当然これが可能であり、ダイクストラはそのようなシーケンスを制限なく探索します。 

最後のケースは、s が t と等しい場合です。 その場合でも、目的地は特にワールド 2 にあるため、答えは必ずしもゼロではありません。s が既に t に等しく、ワールド 2 から離れることなくゼロコストのパスが存在する場合を除き、アルゴリズムは少なくとも 1 つの遷移を正しく強制します。
