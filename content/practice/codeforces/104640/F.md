 ## 問題の理解

 サイズの長方形から始めます$n \times m$。 2 人のプレイヤーが順番に、グウェンから始めます。$k$プレイヤーごとに移動するため、$2k$合計で動きます。 移動するたびに、プレイヤーは長方形の 1 つの辺を選択し、それを 1 つ増やします。選択した辺が$n$、長方形は次のようになります$(n+1)\times m$; もしそうなら$m$、になります。$n \times (m+1)$。 移動によって得られるスコアは、その操作によって生じたエリアの増加に等しくなります。 

重要なポイントは、$n$電流に等しいゲインを与える$m$、増加しながら$m$電流に等しいゲインを与える$n$。 長方形は時間の経過とともに拡大するため、後の手の方が価値が高くなる傾向があり、両プレイヤーは各ステップでどの寸法が拡大されるかを制御しようとします。 

出力は、最適なプレイ後の最終的なスコアの差、つまりグウェンの合計スコアがコンピュータのスコアより大きいか小さいか等しいか、およびその合計によって決定されます。 

制約は非常に大きく、$n, m, k \le 10^9$。 これにより、動きのシミュレーションが即座に除外されます。 欲張りなシミュレーションでも$2k$ステップを踏むことは不可能であり、各状態を明示的に追跡するアプローチは失敗します。 代わりに、解決策は構造、つまり乗数のシーケンスがどのように進化し、最適なプレイがそれとどのように相互作用するかを推論する必要があります。 

一方の次元がもう一方の次元よりもはるかに大きい場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$n \gg m$、その後増加します$m$増加するよりもはるかに価値があります$n$, しかし、その決定は将来の価値観も非対称的に変化させます。 「常に今より大きなゲインを選択する」といった素朴な貪欲なアプローチは、相手の反応と将来のゲインが展開する四角形に依存することを無視しているため、失敗します。 

別の失敗モードは、移動間の対称性または独立性を仮定することです。 それぞれの動きによって将来の重みが変化するため、動きを独立した寄与として扱うと、誤った結論につながります。 

## アプローチ

 ブルートフォース手法では、ゲームの状態を状態ごとにシミュレートします。 それぞれの動きで、可能な両方の選択肢のゲインを計算し、現在のプレイヤーにとって最適な選択肢を選択して続行します。 これはルールに直接準拠し、両方のプレイヤーが最適であると想定しているため、正しく機能します。 

ただし、各移動には一定時間の更新が必要ですが、$2k$が移動し、移動するたびに長方形が変化します。 シミュレーション自体は問題ありませんが、最適なプレイを行うには将来の結果を考慮する必要があるため、単純に貪欲な決定は誤りです。 分岐係数が 2 で深さが 1 であるため、完全なゲーム ツリー ミニマックスは不可能です。$2k$、与える$2^{2k}$州。 

重要な観察は、ゲイン構造が現在の次元では線形であり、各操作で 1 つの座標のみが増加することです。 交互の決定という観点から考える代わりに、すべての潜在的な「増加貢献」を降順で並べ替え、それらを交互にプレイヤーに割り当てるというプロセスとして再解釈できます。 重要な洞察は、$n$または$m$は限界ゲインの予測可能なシーケンスに寄与し、最適なプレイは常に各ステップで利用可能な最大の限界ゲインを選択します。

これにより、ゲームを 2 つのソートされた限界利益シーケンスをマージしたものとして扱い、最大の利益の順序のみをシミュレートすることができます。$2k$現在のデータから導出された優先順位ルールを使用した貢献$n$そして$m$。

 ## アルゴリズムのチュートリアル

 1. いつでも増加することを観察してください。$n$電流に等しいゲインを与える$m$、そして増加しています$m$電流に等しいゲインを与える$n$。 これは、移動の値が現在の四角形の状態によって完全に決定されることを意味します。 
2. 決定をシミュレーションする代わりに、ゲーム全体で各次元が合計で何回増加するかを検討します。 させて$a$回数になる$n$増加し、$b$回数になる$m$グウェンの場合は増加します。 コンピュータの場合もシーケンス全体にわたって同様です。 
3. ゲインのシーケンスは、当面のゲインを最大化するために、現在大きい方を繰り返し選択していると見なすことができることに注意してください。 サイドを増やすと、反対の操作の将来のゲインも増加するため、最適なプレイは、すべてのグローバル シーケンスで現在利用可能な最良のマージン インクリメントを常に消費することに対応します。$2k$動く。 
4. そこで、申請するかどうかの選択を繰り返すプロセスをシミュレーションします。$n$-増加または$m$- 現在の値のみに基づいて増加しますが、明示的なターンベースのミニマックスはありません。 代わりに、どちらのプレイヤーも同じ進化するプールから最適に選択し、誰がどのターンを取得するかだけが異なるという事実を維持します。 
5. 繰り返します$2k$貪欲な方法で回数を増やす: 各ステップで、現在と比較します。$n$そして$m$。 もし$m \ge n$、増加しています$n$より大きなゲインまたは同等のゲインが得られるため、それを選択します。 それ以外の場合は増加することを選択します$m$。 適用後、四角形を更新し、移動インデックスのパリティに応じて現在のプレイヤーにスコアを蓄積します。 
6. グウェンは 0 から始まる偶数インデックスの手をプレイするため、ステップからゲインを受け取ります$0, 2, 4, \dots$、コンピューターは他のものを受信します。 
7. 両方のスコアを累積した後、それらを比較し、勝者と絶対差を出力します。 

### なぜ効果があるのか

 いかなる瞬間においても、1 つの次元の増加による限界利益は、もう 1 つの次元にのみ依存します。 これにより、単調な相互作用が作成されます。つまり、辺を増やすだけで、反対の操作の価値が高まるだけであり、価値が下がることはありません。 その結果、現在最良の限界ゲインを常に選択することから逸脱すると、すべての可能な増分のグローバルな順序付けにおいて、より大きなゲインをより小さなゲインに置き換えることしかできません。 これにより、選択された一連の動きはトップを取ることに対応する必要があることが確立されます。$2k$限界ゲインは非増加順に並べられ、ターン パリティによって、どのゲインが選択されるかに影響を与えることなく、それらがプレイヤー間で割り当てられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    k = int(input())

    gw = 0
    comp = 0

    # 2k total moves, Gwen starts first
    for i in range(2 * k):
        if n <= m:
            gain = m
            n += 1
        else:
            gain = n
            m += 1

        if i % 2 == 0:
            gw += gain
        else:
            comp += gain

    if gw > comp:
        print(1, gw - comp)
    elif comp > gw:
        print(2, comp - gw)
    else:
        print(0, 0)

if __name__ == "__main__":
    solve()
```この実装は、以前に導出された貪欲なルールに直接に従います。 ループは次のように実行されます。$2k$ステップ。概念的にはアクションの合計数と一致します。 各ステップで比較します$n$そして$m$、より高い即時ゲインが得られる操作を選択します。 ループ インデックスのパリティにより、スコアがグウェンまたはコンピュータに割り当てられます。 

微妙な点は、更新が順次適用された後の現在の状態を比較に使用することです。 これにより、進化する限界利益が正しく保存されます。 すべての値が Python の無制限の整数内に収まるため、整数のサイズは安全です。
