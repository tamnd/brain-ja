 ## 問題の理解

 バイナリ文字列の長さが与えられます$n$私たちが構築しなければならないこと。 文字列のコストは、その長さのすべての連続する部分文字列によって定義されます。$k$。 そのような長さごとに-$k$ブロックには事前に割り当てられたペナルティがあり、文字列の総コストは、サイズの各スライディング ウィンドウのペナルティの単純な合計です。$k$。 

タスクは、この合計コストができるだけ小さくなるように文字列を選択することです。 

これを言い換えると便利な方法は、すべての位置がスライディング ウィンドウ コストに寄与し、各ウィンドウが最後のものにのみ依存するバイナリ文字列に沿って歩いているということです。$k$ビット。 これは、問題が強い意味で局所的なものであることを直ちに示唆しています。$k-1$ビットが固定されると、次の決定によって、どの新しいウィンドウが作成されるかが正確に決まります。 

制約により、この構造が悪用可能になります。 文字列の長さは最大 1000 です。$k$最大でも 10 なので、可能な数は$k$-bit Windows は最大でも$2^{10} = 1024$。 これは十分に小さいため、生の文字列について推論するのではなく、各ウィンドウ パターンを状態として扱うことができます。 

素朴なアプローチではすべてを試してしまうだろう$2^n$文字列を取得してそのコストを計算することは不可能です。$n=1000$。 もう 1 つの少し単純ではないアイデアは、次のビットを貪欲に選択するというものですが、コストが重複するウィンドウに依存するため、これは失敗します。そのため、局所的に最適な拡張が将来のより良い移行をブロックする可能性があります。 

微妙なエッジケースは、初期の選択は同等に見えても、後で異なる重複が生じる場合です。 たとえば、2 つのプレフィックスの末尾が異なる場合、$(k-1)$-bit サフィックスを使用すると、現在のコストが同じであっても、将来まったく異なるウィンドウが強制される可能性があります。 このサフィックスの状態を無視するソリューションは、暗黙のうちに不正確になります。 

## アプローチ

 ブルート フォース メソッドは、長さのすべてのバイナリ文字列を列挙します。$n$、すべてを計算します$n-k+1$長さの部分文字列$k$、それらのコストを合計します。 それぞれの評価にかかる費用$O(nk)$、につながる$O(2^n \cdot nk)$、これは実現可能性をはるかに超えています。 

重要な観察は、新しいキャラクターのコスト寄与は以前のキャラクターにのみ依存するということです。$k-1$ビット。 最後がわかったら$k-1$現在のプレフィックスのビットに 0 または 1 を追加すると、決定的に新しい長さが作成されます。$k$ウィンドウ、つまり既知のコストです。 これにより、問題は、ノードが表す有向グラフで最小コストのパスを見つけることに変わります。$(k-1)$-bit の状態とエッジはビットの追加を表します。 

各状態には最大 2 つの発信遷移があり、状態の総数は次のようになります。$2^{k-1}$、これは最大でも 512 です。次に、正確に次の最短パスが必要になります。$n-k+1$各遷移は、最初のウィンドウの後に 1 つの新しいウィンドウを生成することに対応するため、$k$文字は固定されています。 

これは、プレフィックス長に関する動的プログラミングによって自然に処理されます。

 ## アルゴリズムのチュートリアル

 構築プロセスを、最後の文字列を追跡しながら左から右に文字列を構築するものとして扱います。$k-1$状態としてのビット。 

1. 状態が文字列内の現在位置と最後の位置である DP テーブルを定義します。$k-1$プレフィックスのビット。 今後のウィンドウはこれらのビットと次の文字のみに依存するため、この状態で十分です。 
2. 位置ですべての状態を初期化します$k-1$コストゼロで。 これは、最初の完全なウィンドウを形成する前に、ペナルティを支払うことなく任意のプレフィックスを自由に選択できるという事実を反映しています。 
3. から位置を反復します。$k$に$n$。 各ステップで、0 または 1 を追加して現在のプレフィックスを拡張することを検討します。 
4. 少し追加すると、新しいものが形成されます$k$- 前のウィンドウで構成される長さのウィンドウ$(k-1)$-ビット状態と新しいビット。 対応するコストを追加します$d_t$その窓のために。 
5. 最後の状態で定義された新しい状態の DP 値を更新します。$k-1$シフト後のビット数を減らし、それに到達するすべての方法の中で最小コストを維持します。 
6. 親ポインタを保存して最終文字列を再構築し、以前の状態と選択したビットの両方を記録します。 
7. すべてのポジションを処理した後、そのポジションで最適な終了状態を選択します$n$そして、保存されている親を遡って文字列を再構築します。 

これが機能する理由は、すべての有効な文字列がこの状態グラフ内の 1 つのパスに正確に対応し、すべての遷移コストが元の文字列内の 1 つのウィンドウに正確に一致するためです。 したがって、DP は重複することなくすべての有効な構造を探索し、各ステップで特定の接尾辞の状態に到達するための最も安価な方法のみを保持します。将来のコストはその接尾辞にのみ依存するため、これで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    if k == 1:
        # each bit independently contributes
        if d[0] <= d[1]:
            print("0" * n)
        else:
            print("1" * n)
        return

    m = 1 << (k - 1)
    INF = 10**18

    dp = [ [INF] * m for _ in range(n + 1) ]
    parent = [ [None] * m for _ in range(n + 1) ]

    for state in range(m):
        dp[k - 1][state] = 0

    for i in range(k - 1, n):
        for state in range(m):
            if dp[i][state] == INF:
                continue

            for b in (0, 1):
                if i + 1 >= k:
                    full = (state << 1) | b
                    cost = d[full]
                else:
                    cost = 0

                new_state = ((state << 1) & (m - 1)) | b

                if dp[i + 1][new_state] > dp[i][state] + cost:
                    dp[i + 1][new_state] = dp[i][state] + cost
                    parent[i + 1][new_state] = (state, b)

    best_state = min(range(m), key=lambda s: dp[n][s])

    res = []
    cur_state = best_state
    i = n

    while i > k - 1:
        prev_state, bit = parent[i][cur_state]
        res.append(str(bit))
        cur_state = prev_state
        i -= 1

    prefix = []
    state = cur_state
    for i in range(k - 1):
        prefix.append(str((state >> (k - 2 - i)) & 1))

    print("".join(prefix + res[::-1]))

if __name__ == "__main__":
    solve()
```DP テーブル`dp[i][state]`長さのプレフィックスを構築するための最小コストを格納します`i`特定の語で終わる$(k-1)$-ビット接尾辞。 十分な文字が蓄積された場合にのみ、トランジションによって新しいウィンドウが明示的に構築されます。 ビット操作により、サフィックスの更新とウィンドウの形成が O(1) のままになることが保証されます。 

再構成ステップでは、保存されている親を使用して逆方向に進み、ビット選択の正確なシーケンスを復元します。 長さの最初のプレフィックス$k-1$最終状態から直接導出されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    d = list(map(int, input().split()))

    if k == 1:
        return "0" * n if d[0] <= d[1] else "1" * n

    m = 1 << (k - 1)
    INF = 10**18

    dp = [[INF] * m for _ in range(n + 1)]
    parent = [[None] * m for _ in range(n + 1)]

    for s in range(m):
        dp[k - 1][s] = 0

    for i in range(k - 1, n):
        for s in range(m):

    return "ok"

 ## 特殊なケース

 いつ$n < k$、完全なウィンドウが形成されることはないため、すべての文字列のコストはゼロになります。 DP は位置にあるすべての状態を初期化します。$k-1$したがって、ウィンドウコストを「支払う」ことはありませんが、再構築によって有効な任意の文字列が生成されます。 遷移によってコスト検索がトリガーされることはないため、アルゴリズムはこれを自然に処理します。 

いつすべて$d_t$値が等しい場合、すべての文字列のコストは同じになります。 DP は任意のパスを選択できますが、状態ベースの定式化では有効な遷移が伝播されるため、一貫性が保証されます。 再構成では、任意の順序に依存せずに、多くの最適なパスのうちの 1 つが返されます。
