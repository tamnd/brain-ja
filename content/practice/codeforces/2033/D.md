 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、合計がゼロになるサブ配列、つまり連続したセグメントを識別する必要があります。 これらのセグメントは美しいと呼ばれます。 タスクは、美しいセグメントをすべて見つけるだけでなく、重複せずにそれらの数を最大化することです。 言い換えれば、セグメントがカウントされると、そのセグメント内の要素は別の美しいセグメントに現れることはできません。 

入力は複数のテスト ケースで構成され、各テスト ケースには大きな配列が含まれる可能性があります。 配列の長さは 100,000 に達する可能性があり、すべてのテスト ケースの長さの合計は 300,000 に制限されます。 サブ配列の数は配列の長さに応じて二次関数的に増加するため、考えられるすべてのサブ配列のゼロ和をチェックする素朴な解決策は実行不可能です。 これにより、O(n²) アプローチが除外されます。 テスト ケースごとにおおよそ O(n) または O(n log n) 時間で動作するアルゴリズムが必要です。 

明らかでないエッジ ケースには、多数のゼロを含む配列、配列全体の合計のみがゼロになる配列、重複しない複数のゼロサム セグメントを形成する可能性がある繰り返しパターンを持つ配列が含まれます。 例えば、`[0, 0, 0]`返すべきです`3`それぞれのゼロだけがセグメントになる可能性がある一方で、最大長のセグメントのみを試行する不用意なアプローチでは、結果が返される可能性があるためです。`1`。 

## アプローチ

 ブルートフォース手法では、すべての可能な開始インデックスを反復処理し、それぞれの可能なすべての終了インデックスをチェックして、部分配列の合計がゼロになるかどうかを確認します。 この方法はすべてのセグメントを探索するため、原理的には正しいですが、配列ごとに O(n²) 回の操作が必要です。 n が 10^5 までの場合、これは最悪の場合、およそ 10^10 の演算を実行することになり、妥当な時間制限をはるかに超えます。 

より高速な解決策を明らかにする重要な観察は、ゼロサム セグメントが繰り返されるプレフィックスの合計に対応するということです。 配列のプレフィックスの合計を計算すると、セグメントは`[l, r]`合計がゼロになる場合`prefix[r] - prefix[l-1] = 0`。 並べ替えると、つまり、`prefix[r] = prefix[l-1]`。 したがって、以前に見たプレフィックスの合計が表示されるたびに、そこで美しいセグメントを終了できます。 重複しないセグメントを最大化するために、繰り返しのプレフィックス合計が検出されるたびにセグメントを貪欲に終了し、重複するセグメントを避けるために追跡をリセットします。 

これにより、最後のセグメント以降に見られたプレフィックスの合計を追跡するセットを使用して、テスト ケースごとに最適な O(n) ソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | プレフィックスの合計 + セット | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`count`ゼロに。 これにより、見つかった美しいセグメントの数が保存されます。 
2. 変数を初期化する`prefix`配列要素の累計を追跡するには、ゼロに設定します。 
3. セットを初期化する`seen`ゼロを含む。 このセットには、最後のセグメントの終了以降に確認されたプレフィックスの合計が格納されます。 
4. 配列の各要素を反復処理します。 現在の要素を追加します`prefix`。 
5.次のことを確認します`prefix`すでに入っています`seen`。 そうであれば増分します`count`美しい部分がここで終わるからです。 リセット`seen`ゼロとリセットのみを含む`prefix`次のセグメントではゼロにします。 これにより、セグメントが重複しないようになります。 
6. もし`prefix`入っていない`seen`に追加します`seen`そして続けます。 
7. 配列を処理した後、`count`重複しない美しいセグメントの最大数が含まれます。 現在のテスト ケースに対してこの値を出力します。 

なぜ機能するのか: セット`seen`最後のセグメント終了以降、考えられるすべてのプレフィックスの合計を確実に追跡します。 繰り返されるプレフィックスの合計を初めて確認したとき、潜在的な後続のセグメントを見逃すことなく、セグメントを終了する最も早いポイントが見つかりました。 セットをリセットすると、重複がないことが保証され、貪欲なアプローチでは常に最も早い機会にセグメントを終了するため、セグメントの数が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        count = 0
        prefix = 0
        seen = set()
        seen.add(0)
        
        for x in a:
            prefix += x
            if prefix in seen:
                count += 1
                seen = set()
                seen.add(0)
                prefix = 0
            else:
                seen.add(prefix)
        
        print(count)

if __name__ == "__main__":
    solve()
```このコードは、プレフィックス合計の追跡と、検出されたプレフィックス合計のセットをゼロで初期化します。 配列を反復処理するときに、現在のプレフィックスの合計が最後のセグメント以降にすでに表示されているかどうかを確認します。 完了すると、セグメントが終了し、セットがリセットされ、カウントが続行されます。 セットを使用すると、重複の繰り返しスキャンが回避され、要素ごとに O(1) チェックが確実に行われます。

## 特殊なケース

 のために`[0, 0, 0]`、アルゴリズムは次から始まります`prefix = 0`そして`seen = {0}`。 最初のゼロトリガー`prefix in seen`、カウントを 1 に増やしてリセットします`prefix`そして`seen`。 後続のゼロごとにこのプロセスが繰り返され、合計 3 つのセグメントが生成されます。 これにより、貪欲なアプローチが連続するゼロを正しく処理することが確認されます。 

のために`[3, -3, 3, -3]`、プレフィックスの合計は`[3,0,3,0]`。 このアルゴリズムは、インデックス 1 で最初のゼロ プレフィックス サムを検出し、1 つのセグメントをカウントしてリセットし、次にインデックス 3 で別のゼロ プレフィックス サムを検出し、2 番目のセグメントをカウントします。 これは、予想される 2 つの重複しないセグメントの最大値と一致し、正と負の数値が交互に表示されることが正しいことを示しています。
