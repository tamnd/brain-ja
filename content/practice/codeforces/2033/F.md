 ## 解決策
 ## 問題の理解

 固定整数の場合$k$、フィボナッチ数列を見て、フィボナッチ値が次の値で割り切れるすべての位置にマークを付けます。$k$。 

たとえば、次のようなとき$k=2$:$$1,1,\mathbf{2},3,5,\mathbf{8},13,21,\mathbf{34},\dots$$マークされた位置は、$3,6,9,\dots$。 

定義する$G(n,k)$の位置として$n$-th はフィボナッチ数をマークします。 私たちは与えられています$n$そして$k$、そして計算する必要があります$G(n,k)$モジュロ$10^9+7$。 

主な難点は、$n$と同じ大きさにすることができます$10^{18}$。 フィボナッチ数を生成したり、割り切れる項を 1 つずつ数えたりすることはできません。 たとえ$O(n)$アルゴリズムは完全に不可能です。 

もう 1 つの重要な制約は、$k \le 10^5$、およびすべての合計$k$テスト ケース全体の値は最大でも$10^6$。 これは、大まかに支出する必要があることを強く示唆しています$O(k)$テストケースごとに動作し、のみに依存する構造を利用します。$k$。 

微妙なエッジケースが現れるのは、$k=1$。 すべてのフィボナッチ数は次で割り切れます。$1$したがって、マークされた位置は単純に$1,2,3,\dots$。 したがって$G(n,1)=n$。 可分性イベントがスパースであると仮定する解決策は、ここでは失敗する可能性があります。 

例えば：```
Input:
1
5 1
```正しい答えは次のとおりです。```
5
```もう 1 つの簡単な間違いは、$n$-th 番目に直接割り切れるフィボナッチ数。 考慮する：```
Input:
1
1000000000000000000 2
```答えは次のインデックスにあります$3 \times 10^{18}$。 ポジションを一つ一つシミュレーションするのは絶望的です。 

3 番目の落とし穴は、最終的な答えが法で求められることを忘れていることです。$10^9+7$。 実際のインデックス$G(n,k)$次の場合、64 ビットの制限をはるかに超える可能性があります。$n$巨大です。 モジュロは、完全な値を構築するのではなく、モジュラー演算を使用して適用する必要があります。 

## アプローチ

 最も直接的なアイデアは、フィボナッチ数のモジュロを生成することです。$k$、各項が次で割り切れるかどうかを確認します。$k$、そのようなポジションが何回出現したかを数えます。 カウントが達したらすぐに$n$、現在のインデックスを出力します。 

これは正しいです。なぜなら、$k$フィボナッチ値のモジュロのみに依存します$k$。 問題はそれです$n$できる$10^{18}$、そのため、処理が必要になる可能性があります$10^{18}$ポジション。 それは可能性を何桁も超えています。 

重要な観察は、フィボナッチ数の剰余であるということです。$k$定期的です。 シーケンス$$(F_i \bmod k)$$はピサーノ数列と呼ばれます。 各状態はペアによって決定されるため、$$(F_i \bmod k,\; F_{i+1} \bmod k),$$あるだけです$k^2$可能な状態。 最終的には状態が繰り返され、状態が繰り返されるとシーケンス全体が繰り返されます。 

実際、フィボナッチ数列モジュロ$k$常に開始ペアに戻ります$(0,1)$。 このサイクルの長さがピサーノ時代です。 

1 つのピリオド内の位置は、$F_i \equiv 0 \pmod k$繰り返しのパターンを形成します。 最初のそのような位置を次のようにします$z$。 フィボナッチ数列の古典的な特性では、すべてのインデックスは次のように割り切れます。$z$の倍数も与えます$k$、そしてそれより小さい正のインデックスはそうではありません。 したがって、すべての分割可能な位置は、$$z,\;2z,\;3z,\dots$$の$n$したがって、 - 番目の割り切れるフィボナッチ数は、 の位置に配置されます。$$n \cdot z.$$問題全体は、最小の正のインデックスを見つけることに帰着します。$z$そのような$$F_z \equiv 0 \pmod k.$$ピサーノ時代から$k \le 10^5$せいぜい$6k$、フィボナッチ数のモジュロをシミュレートすることでこのインデックスを見つけることができます。$k$最初のゼロが表示されるまで。

 ## アルゴリズムのチュートリアル

 1. しましょう`MOD = 1_000_000_007`。 
2. テストケースの場合$(n,k)$、フィボナッチ数のモジュロを生成します$k$。 
3. ペアから始めます$(1,1)$、に対応$F_1$そして$F_2$。 
4. 次のフィボナッチ剰余モジュロを繰り返し計算します。$k$、そのインデックスを追跡しながら。 
5. 最初のインデックス$z$剰余がゼロになる場所は、次を満たす最小の正のインデックスです。$F_z \equiv 0 \pmod k$。 

この指標は、しばしば「出現のランク」と呼ばれます。$k$。 
6. 次で割り切れるすべてのフィボナッチ数$k$の倍数のインデックスで発生します$z$。 
7.$n$したがって、割り切れるフィボナッチ数はインデックスにあります$n \cdot z$。 
8. 出力$$(n \bmod MOD)\cdot(z \bmod MOD)\bmod MOD.$$### なぜ効果があるのか

 しましょう$z$最小の正のインデックスになる$F_z \equiv 0 \pmod k$。 

標準的なフィボナッチの可分性プロパティでは、次のように述べられています。$$\gcd(F_a,F_b)=F_{\gcd(a,b)}.$$この事実を使用すると、次のことがわかります。$F_m$で割り切れます$k$、 それから$z$分割する$m$。 さもないと$F_{\gcd(z,m)}$も割り切れます$k$のミニマルさと矛盾します。$z$。 

逆に、フィボナッチ数は次の条件を満たします。$$F_z \mid F_{tz}$$すべての正の整数に対して$t$。 以来$F_z$はすでに割り切れます$k$、 毎$F_{tz}$で割り切れます$k$同じように。 

したがって、割り切れる位置は正確に次のようになります。$$z,2z,3z,\dots$$そして$n$- 番目のそのような位置は$nz$。 アルゴリズムは次のことを見つけます$z$この値を法として計算します$10^9+7$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def first_zero_index(k):
    if k == 1:
        return 1

    a, b = 1 % k, 1 % k
    idx = 2

    while True:
        a, b = b, (a + b) % k
        idx += 1

        if b == 0:
            return idx

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())

        z = first_zero_index(k)
        ans.append(str((n % MOD) * (z % MOD) % MOD))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```機能`first_zero_index`値が次の値で割り切れる最初のフィボナッチ インデックスを検索します。`k`。 変数`a`そして`b`常に 2 つの連続するフィボナッチ残基のモジュ​​ロを表します`k`。 

インデックスは次から始まります`2`なぜなら`a`そして`b`最初は対応する`F1`そして`F2`。 それぞれの移行後、`b`は次のフィボナッチ値になるので、`b == 0`、の現在値`idx`まさに目的のインデックスです。 

特別な場合`k == 1`すべてのフィボナッチ数は次の数で割り切れるため、個別に処理されます。`1`、答えのインデックスは次と等しくなります`1`。 

最後の乗算ではすぐにモジュラー演算が使用されます。 以来`n`と同じくらい大きいかもしれない`10^18`、モジュロを計算すると、最初にすべての値が小さく保たれ、不必要な大きな整数が回避されます。

 ## 特殊なケース

 次のことを考慮してください。```
1
5 1
```すべてのフィボナッチ数は次で割り切れます。`1`。 アルゴリズムはすぐに戻ります`z = 1`。 答えは次のようになります`5 × 1 = 5`。 シーケンスの生成は必要ありません。 

考慮する：```
1
1 2
```フィボナッチ数列モジュロ`2`は：```
1, 1, 0, 1, 1, 0, ...
```最初のゼロはインデックスで発生します`3`、 それで`z = 3`。 答えは`1 × 3 = 3`。 これは、最初の割り切れるフィボナッチ数が必ずしもインデックスにあるわけではないことを検証します。`1`。 

考慮する：```
1
1000000000000000000 2
```同じ`z = 3`が見つかりました。 アルゴリズムは計算します$$(10^{18} \bmod 10^9+7)\cdot 3 \bmod 10^9+7$$巨大なインデックスを構築することなく$3 \times 10^{18}$。 まさにこれが、モジュラー演算が最後に適用される理由です。
