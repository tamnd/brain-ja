 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられます。 任意の 2 つの位置を繰り返し交換することができます。 いくつかのスワップを実行した後、順列がすべてのインデックス i の構造条件を満たすようにします。 

各位置 i では、値はすでに独自の場所に存在しており、p[i] = i を意味するか、または正しい位置と相互ペアを形成しています。つまり、p[i] = x の場合、p[x] は i に等しくなければなりません。 したがって、すべての要素は固定点または 2 サイクルの一部です。 最終配置ではこれ以上のサイクルは許可されません。 

タスクは、指定された順列をこの条件を満たす任意の順列に変換するために必要なスワップの最小数を計算することです。 

ここでは制約が非常に重要です。 すべてのテスト ケースの合計 n は最大 10^6 であり、テストごとに二次関数が除外されます。 スワップをシミュレートしたり、アレイをスキャンしてサイクルを繰り返し修正しようとするソリューションは失敗します。 テスト ケースごとに線形または線形に近い分解アプローチが必要です。 

素朴な考えによる微妙な失敗例は、スワップがグローバルにどのように相互作用するかを考慮せずに、すべてのサイクルを固定式で独立して修正できると仮定することです。 たとえば、[2, 3, 1] のような 3 サイクルの場合、1 回のスワップで修復できると誤って考えるかもしれませんが、実際には、有効な固定点または 2 サイクルに分割するには 2 回のスワップが必要です。 

もう 1 つの微妙なケースは、異なる長さの複数の独立したサイクルなど、サイクルの混合です。 サイクルごとの貪欲なローカル修正は、構造全体にわたって正しく合計される必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、順列が有効になるまでスワップをシミュレートしようとします。 各スワップの後、すべてのインデックスをスキャンし、すべてのポジションが条件を満たしているかどうかを確認します。 各スキャンのコストは O(n) で、最悪の場合は O(n) のスワップが必要になる可能性があり、テスト ケースごとに O(n^2) が必要になりますが、これは最大 10^6 の n には大きすぎます。 

重要な観察は、最終的な構造が非常に制約されていることです。順列グラフ内のすべての連結成分は固定点またはペアになる必要があります。 これは、順列のサイクルの観点から機能することをすぐに示唆しています。 

各順列は互いに素なサイクルに分解できます。 長さ k のサイクル内で、それを有効な構造に変換するために必要なスワップの数を決定する必要があります。 重要な洞察は、スワップでは意図的にサイクルを中断しない限りサイクルが混合しないため、各サイクルが独立して答えに寄与するということです。 

長さ 1 のサイクルの場合は何も必要ありません。 長さ 2 のサイクルの場合、相互ペアとしてすでに有効です。 長さ k ≥ 3 のサイクルについては、スワップを使用して有効なペアと固定小数点に分割する必要があります。 最適な戦略は、k - 1 スワップ分の構造を使用してそのような各サイクルを削減することですが、より正確には、スワップ分解から最適なペアリング動作が出現した後、長さ k のすべてのサイクルが Floor((k - 1) / 2) スワップに寄与します。 

この問題は、各サイクルを 1 サイクルと 2 サイクルのセットに変換するために必要なスワップの数を数えることと同じです。 各スワップでは、サイクル内で最大 2 つの誤って配置された要素を修正でき、これはペアリングの解釈に直接つながります。 

サイクルに分解した後、サイクルごとのコストを累積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サイクルシミュレーション / ブルートスワップ | O(n^2) | O(n) | 遅すぎる |
 | サイクル分解カウンティングペア | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 訪問済みの配列を構築し、1 から n までのすべてのインデックスを反復処理します。 未訪問のインデックスごとに、新しいサイクル トラバースが開始されます。 
2. このインデックスから開始して、訪問したノードに戻るまで順列をたどります。 サイクルのサイズを収集します。 このステップでは、独立した構造コンポーネントを分離します。これは、あるサイクル内のスワップが別のサイクルに影響を与えないために必要です。 
3. 発見されたサイクルごとに、答えに対するその寄与を計算します。 サイクル長が 1 または 2 の場合、スワップは 0 になります。 サイクル長が k ≥ 3 の場合、floor((k - 1) / 2) に寄​​与します。 これは、スワップを使用してサイクル内で要素を最適にペアリングすることで実現されます。各スワップにより、達成可能な最適な配置で 2 つの間違った位置が解決されます。 
4. すべてのサイクルにわたる寄与を合計し、結果を出力します。 

### なぜ効果があるのか

 順列は互いに素なサイクルに一意に分解でき、サイクルをマージするために明示的に使用しない限り、スワップはサイクル内の要素にのみ影響します。 ただし、ターゲット構造も独立した固定点と 2 サイクルに分解されるため、サイクルをマージしても最適性は向上しません。 したがって、元の各サイクルは独立して解決できます。 

長さ k のサイクル内でできることは、有効な固定小数点と 2 サイクルに変換することだけです。 スワップごとに未解決の要素の数を最大 2 つ減らすことができるため、下限は形成できるペアの数によって決まり、floor((k - 1) / 2) が得られます。 この限界は建設的再配置によって達成できるため、サイクル全体の合計により全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        visited = [False] * (n + 1)
        ans = 0

        for i in range(1, n + 1):
            if not visited[i]:
                cur = i
                cycle_len = 0
                while not visited[cur]:
                    visited[cur] = True
                    cycle_len += 1
                    cur = p[cur - 1]

                if cycle_len >= 3:
                    ans += (cycle_len - 1) // 2

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、標準の置換トラバーサルを使用してサイクルを構築します。 各位置は正確に 1 回訪問されるため、線形の複雑さが保証されます。 サイクルから回答への変換では、派生した式を直接使用し、スワップのシミュレーションを回避します。 

重要な実装の詳細はインデックス付けです。順列はロジックでは 1 ベースですが、格納されるのは 0 ベースなので、すべての遷移では p[cur - 1] が使用されます。

 ## 特殊なケース

 p[i] = i のような単一要素のサイクルは何も寄与しません。 トラバースは、訪問したことを即座にマークし、固定点がすでに有効であるという要件に一致して、寄与をスキップします。 

[2, 1] のような 2 要素のサイクルは、すでに有効な相互ペアです。 サイクル長は 2 であるため、式の寄与はゼロとなり、スワップは実行されません。 

[2, 3, 4, 5, 1] などの長い奇数サイクルは、サイクル長 5 を生成します。このアルゴリズムは 2 つのスワップを提供します。これは、有効な構造のみが残るまで、スワップごとに 2 つの間違った位置の要素を繰り返し修正することに相当します。 

サイクルの素の結合は独立性を示します。 たとえば、[2, 1, 4, 3, 5] はサイズ 2、2、および 1 のサイクルに分割され、すべて寄与率が 0 であるため、アルゴリズムがコンポーネントを誤って混合していないことが確認されます。
