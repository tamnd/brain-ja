 ## 解決策
 ## 問題の理解

 私たちは同一のカードを与えられ、ピラミッドと呼ばれる構造物を繰り返し構築します。 高さ 1 のピラミッドは可能な限り最小の構造であり、それより高いピラミッドはすべて層状に構築されます。より高いピラミッドは、追加のカードで作られた幅広のベースの上に小さなピラミッドが置かれて構成されます。 この構築ルールにより、各高さのカードのコストは固定されます。 

このプロセスは貪欲かつ連続的です。 ある程度の数のカードから始めて、私たちは常に可能な限り高いピラミッドを構築しようとします。 1 つ構築した後、消費したカードを差し引き、どの高さのピラミッドも形成できなくなるまで残りについて同じ決定を繰り返します。 出力は、各テスト ケースで合計でいくつのピラミッドが構築されたかを単純に示します。 

ここで重要な隠しオブジェクトは幾何学的なピラミッドではなく、高さ h のピラミッドのコスト関数です。 そのコストが判明すると、問題は決定論的なリソース枯渇プロセスになります。つまり、実現可能な最大のコストを繰り返し差し引くことになります。 

この制約により、最大 1000 のテスト ケースが許可され、すべてのテストにわたるカードの合計は最大 10^9 になります。 これにより、各カードをシミュレートしたり、テスト ケースごとにコストが高すぎるコストを再計算したりするアプローチは即座に除外されます。 最大の高さを繰り返し検索して減算する単純なシミュレーションは、高さの計算が高速であればまだ機能する可能性があります。各ピラミッドは少なくとも 2 枚のカードを消費するため、最悪の場合でも最大で O(n) 回の反復が行われるためですが、n が 10^9 になる可能性がある場合、テスト ケースあたり O(n) は不可能です。 

さらに微妙な失敗例は、ピラミッド コストの誤った解釈に起因します。 よくある間違いは、間違った定数を使用して線形成長または三角成長を想定することです。 たとえば、高さ h のピラミッドのコストが h^2 であると仮定すると、n = 14 のような小さな入力であっても、不正確な構築カウントが発生します。この場合、正しい動作は正確な組み合わせスタッキング ルールに依存します。 

もう 1 つのエッジ ケースは、n = 1 や n = 2 など、n が小さいことです。これらの場合、より高度な構造は不可能であり、実現可能な高さを過大評価すると、あまりにも多くのカードが差し引かれ、負のまたは不正確な残差ロジックが生成されます。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 ピラミッドの高さ h ごとに必要なカードの枚数を事前に計算または導出します。 次に、各テスト ケースについて、まだカードがある間に、可能な最大の高さから下方向にスキャンし、コストが残りのカードを超えない最大の h を選択します。 そのコストを差し引いて、答えを増やします。 

これが機能するのは、各ステップが局所的に最適であり、問​​題によって貪欲な構築が必要であることが明示的に強制されるためです。 ただし、最大の有効な高さを繰り返し見つけることがボトルネックとなります。 毎回最初から再計算し、可能な最大の高さが O(√n) 程度である場合、各選択には O(√n) のコストがかかり、最悪の場合は O(√n) 個のピラミッドを構築する可能性があり、最悪のシナリオではテスト ケースあたりの動作が O(n) になる可能性があります。 

重要な観察は、ピラミッドのコストは高さに応じて急速に増加し、n が 10^9 までの場合、最大高さはわずか数百程度であるということです。 これにより、すべてのピラミッド コストを一度に事前計算できます。 その後、繰り返されるプロセスは、コストの固定リストに対する単純な貪欲な減算になります。 コスト シーケンスは急速に増加しているため、選択ステップを事前計算された値に対する小さなループに減らすこともできます。 

これにより、問題は、ソートされた小さなリストから合計がなくなるまで繰り返し最大値を選択するという問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n √n) 最悪の場合の直感 | O(√n) | 遅すぎる |
 | 最適 | O(H² + T·H) ただし、H ≤ 450 | O(H) | 承認済み |

 ## アルゴリズムのチュートリアル

1. コストが 10^9 を超えるまで、ピラミッドの高さ h ごとに必要なカードの数を事前計算します。 n がこの範囲を超えないことが制約により保証されているため、これは安全です。 新しいレイヤーごとに予測可能な数のカードが追加されるため、各 h のコストは前のレイヤーから増分的に導出されます。 
2. すべての有効なコストを増加する配列cost[]に格納します。 各エントリは、その高さのピラミッドを構築するために必要なカードの正確な数を表します。 
3. 各テスト ケースについて、指定された n から開始し、カウンター ans = 0 を初期化します。 
4. n が少なくとも最小のピラミッドを構築するのに十分な大きさである間に、コスト配列を最大から最小の順にスキャンして、≤ n である最大のコストを見つけます。 
5. n からそのコストを減算し、ans を 1 ずつ増分します。 
6. 残りの n にコストが収まらなくなるまで繰り返します。 

最大のものから下に向かってスキャンすることが正しい理由は、このプロセスでは毎回、可能な限り高いピラミッドを構築することが明示的に要求されるためです。 コストは高さに応じて厳密に増加するため、これにより、常に最大有効な高さが選択されることが保証されます。 

### なぜ効果があるのか

 このアルゴリズムは、各減算後のカードの残りの枚数が常に、各ステップでの最適な貪欲な選択の残りであるという不変条件を維持します。 ピラミッド コストは厳密に増加するシーケンスを形成し、各ステップは残りのリソースにのみ依存するため、実現可能な最大のピラミッドを選択する決定は、n を減らすこと以外の以前の選択とは独立しています。 これにより、より大きなピラミッドは常に、より小さな未使用の部分構造の組み合わせよりも多くのカードを消費するため、より小さなピラミッドを先に選択すると、後で合計数を増やすことができるというシナリオが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# precompute pyramid costs
# cost[h] = number of cards needed for pyramid of height h

MAX_N = 10**9
cost = []

h = 1
curr = 2  # cost of height 1 pyramid
while curr <= MAX_N:
    cost.append(curr)
    h += 1
    # derive next cost incrementally
    # recurrence: cost[h] = cost[h-1] + 3*h - 1
    curr += 3 * h - 1

cost.sort()

t = int(input())
for _ in range(t):
    n = int(input())
    ans = 0

    while n >= 2:
        # pick tallest possible pyramid
        for c in reversed(cost):
            if c <= n:
                n -= c
                ans += 1
                break
        else:
            break

    print(ans)
```実装の中核は事前計算ステップです。 各テスト ケース中にピラミッド サイズを繰り返し導出する代わりに、コストのグローバル リストを一度作成します。 これにより、すべてのクエリが効率的に処理されます。 

各テスト ケース内の貪欲ループは、常に最大のコストから下方向にスキャンします。 リストが小さいため (最大でも数百エントリ)、リニア スキャンでも十分高速であるため、これは安全です。 

微妙な点は終了条件です`n >= 2`。 高さ 1 のピラミッドにはすでに 2 枚のカードが必要なので、2 未満のものは構造を形成できません。 これにより、答えがすでに確定している場合に不必要なスキャンを防ぐことができます。 

## 実用的な例

 ### 例 1: n = 14

 まず、最大 14 までの利用可能なピラミッド コストを計算します。これは次のとおりです。 

2、7、15 (ここでは 2 と 7 のみ使用可能)

 | ステップ | n | 選択したコスト | 残り n | ピラミッド |
 | --- | --- | --- | --- | --- |
 | 1 | 14 | 7 | 7 | 1 |
 | 2 | 7 | 7 | 0 | 2 |

 このプロセスは、貪欲な選択により可能な限り最大のピラミッドが毎回選択されることを示しています。 高さ 2 のピラミッド (コスト 7) を使用した後でも、同じ高さの別のピラミッドを構築できます。 

これにより、等コストの選択の繰り返しが有効であること、およびアルゴリズムが使用された高さをグローバルに追跡する必要がないことが確認されます。 

### 例 2: n = 15

 | ステップ | n | 選択したコスト | 残り n | ピラミッド |
 | --- | --- | --- | --- | --- |
 | 1 | 15 | 15 | 0 | 1 |

 ここでは、最大のピラミッドがすべてのリソースを即座に消費し、残りを残しません。 これは、完全一致が発生した場合、追加のロジックなしでアルゴリズムが自然に停止することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(H² + T・H) | 事前計算により H コストが増加します。 各テストはステップごとの H 値をスキャンします。 
| スペース | O(H) | ピラミッド コストを実現可能な最大の高さまで格納します。 

最大高さ H は小さい (n ≤ 10^9 の場合、500 をはるかに下回る) ため、テスト ケースごとの二次事前計算と線形スキャンでも効率的です。 このソリューションは、時間とメモリの制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAX_N = 10**9
    cost = []
    curr = 2
    h = 1
    while curr <= MAX_N:
        cost.append(curr)
        h += 1
        curr += 3 * h - 1

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        ans = 0
        while n >= 2:
            for c in reversed(cost):
                if c <= n:
                    n -= c
                    ans += 1
                    break
            else:
                break
        out.append(str(ans))
    return "\n".join(out)

# provided samples
assert run("""5
3
14
15
24
1
""") == """1
2
1
3
0"""

# minimum input
assert run("1\n1\n") == "0"

# exact single pyramid
assert run("1\n2\n") == "1"

# repeated same pyramid
assert run("1\n14\n") == "2"

# large value
assert run("1\n1000000000\n") is not None
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n1 | 0 | 建設不可能 |
 | 1\n2 | 1 | 最小のピラミッドケース |
 | 1\n14 | 2 | 貪欲に再利用を繰り返す |
 | 1\n1000000000 | 有効な出力 | 応力上限 |

 ## 特殊なケース

 n = 1 の場合、コスト リストには 2 から始まる値のみが含まれるため、スキャンでは有効なピラミッドがすぐに見つかりません。 ループに入ることはなく、答えは正しく 0 のままです。 

n = 2 の場合、アルゴリズムは最小のコストを 1 回だけ選択し、それを減算してゼロにし、正常に終了します。 これにより、特別な大文字小文字を必要とせずに完全一致が処理されることが確認されます。 

10^9 などの大きな n の場合、アルゴリズムは小さな固定リストから繰り返し選択します。 最大のピラミッド コストは依然として n をはるかに下回っているため、最初の数回の反復では繰り返し大きなピラミッドが選択される可能性がありますが、n が縮小する性質により、非常に少ないステップでの終了が保証されます。
