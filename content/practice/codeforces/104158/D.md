 ## 解決策
 ## 問題の理解

 文字 T と C のみからなるターゲット文字列が与えられています。課題は、固定のスタンプ セットを使用してこの文字列を形成できる方法が何通りあるかを数えるということです。 

文字列内の各位置は、4 つのスタンプ タイプのいずれかを選択することによって生成されます。 スタンプには、1 文字を書くものと、2 文字を同時に書くものがあります。 重要な制約は、操作としてスタンプを順番に配置していないことです。 代わりに、文字列の分解を、重複せずに正確にカバーするスタンプされたブロックに割り当てます。 それぞれの有効なウェイは、許可された部分を使用した文字列のタイリングに対応し、そのようなすべてのタイリングを大きな素数を法として数えます。 

文字列の長さは最大 1,000,000 です。 部分文字列に対する二次またはそれより悪い解は、状態ごとに繰り返される線形スキャンでさえ、すでに許容限界を超えているため、実現不可能です。 これにより、線形時間で実行される動的プログラミング アプローチが必要になります。 

複数文字のスタンプの解釈が重複すると、微妙な問題が発生します。 早い段階で長いスタンプを選択すると、後で有効な分解がブロックされる可能性があるため、貪欲な解釈は失敗します。 たとえば、文字列 TCC で、常に 2 文字のスタンプ TC を最初に取得しようとすると、最初の文字が別個に扱われる構成を見逃す可能性があります。 

主なエッジケースは、TTTT や CCCC などの繰り返しパターンを持つ文字列で、セグメンテーションの組み合わせ爆発が発生します。 パーティションを明示的に列挙するアプローチでは、タイムアウトになるか再帰制限をオーバーフローします。 

## アプローチ

 直接的なアプローチは、これを分割問題として扱うことです。あらゆる方法で文字列を長さ 1 または 2 のセグメントに分割し、各セグメントが有効なスタンプと一致するかどうかを確認します。 すべてのタイリングがそのようなセグメンテーションに対応するため、これは正しいです。 ただし、各位置で最大 2 つの選択肢に分岐することになり、セグメンテーションの数が指数関数的に増加します。 長さ n の文字列の場合、これはほぼフィボナッチのような増加をもたらしますが、これは、10^6 どころか、50 近くの n にとってもすでに大きすぎます。 

問題の構造は動的プログラミングを示唆しています。 重要な観察は、プレフィックスを形成する方法の数は、少数の固定数の前の状態にのみ依存するということです。 各スタンプは 1 つまたは 2 つの文字に寄与するため、状態遷移は dp[i-1] と dp[i-2] にのみ依存します。 これにより、問題は文字列全体にわたる線形反復に帰着します。 

位置 i では、最後のスタンプがどのように終了するかを検討します。 最後のスタンプが 1 文字をカバーしている場合は、S[i-1] と一致する必要があります。 2 文字をカバーする場合は、S[i-2:i] と一致する必要があります。 有効な一致はそれぞれ dp[i-1] または dp[i-2] に寄与します。 

位置 i で終了するすべての有効な方法からの寄与を効果的に合計しています。これにより、各分解は最後の部分によって一意に決定されるため、二重カウントが回避されます。

 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング | O(2^n) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[i] を、0 ベースのインデックスを使用してプレフィックス S[0:i] を形成する方法の数として定義します。ここで、dp[0] は空の文字列に対応します。

1. dp[0] = 1 を初期化します。これは、空のプレフィックスを構築する方法が 1 つだけあるため、スタンプを選択しないことです。 これは、すべての長いプレフィックスを構築するための基本ケースとして機能します。 
2. i を 1 から n まで繰り返します。 各位置 i で、位置 i で終わる可能性のあるすべての有効なスタンプを考慮して dp[i] を計算します。 
3. まず、1 文字のスタンプを考えます。 最後の文字 S[i-1] は常に 1 つのスタンプで覆われます。 S[i-1] に一致する単一文字スタンプは許可されるため、すべての dp[i-1] ウェイを拡張できます。 これは、dp[i-1] を dp[i] に寄与します。 
4. 次に 2 文字のスタンプを考えます。 i ≥ 2 の場合、S[i-2:i] が 2 文字のスタンプで形成できるかどうかを確認します。 その場合、このスタンプを最後に配置することで、dp[i-2] を形成するあらゆる方法を拡張できます。 これは dp[i-2] を dp[i] に寄与します。 
5. 両方の寄与を 10^9 + 7 を法として加算します。 

なぜそれが機能するかは、単純な分解特性に基づいています。 プレフィックスの有効なスタンプにはそれぞれ、固有の最後のスタンプがあります。 最後のスタンプは 1 文字または 2 文字をカバーしており、それを削除すると、より小さい接頭辞の有効なスタンプが残ります。 これにより、dp[i] の有効な構成と、最後のスタンプによって拡張された dp[i-1] および dp[i-2] の有効な構成の間の全単射が得られます。 複数の方法で同時に工事を終了することはできないため、二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    s = input().strip()
    n = len(s)
    
    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]  # single-character stamp always usable
        
        if i >= 2:
            # any two-character block is always valid as a stamp
            dp[i] = (dp[i] + dp[i - 2]) % MOD

        else:
            dp[i] %= MOD

    print(dp[n])

if __name__ == "__main__":
    solve()
```実装は繰り返しを直接反映します。 dp 配列にはプレフィックス数が格納され、各状態は 2 つの可能なスタンプ長からの寄与を集約します。 オーバーフローを防ぐために、各ステップでモジュロが適用されます。 

唯一の微妙な点は、正しいインデックス付けを保証することです。dp[i] は最初の i 文字を表すため、遷移では i-1 と i-2 が使用されます。 これにより、プレフィックス DP の定式化で一般的に発生する off-by-one エラーが回避されます。 

## 実用的な例

 ### 例 1: 「TCC」

 dp を段階的に計算します。 

| 私 | プレフィックス | dp[i-1] の貢献 | dp[i-2] の貢献 | dp[i] |
 | --- | --- | --- | --- | --- |
 | 0 | "" | - | - | 1 |
 | 1 | "T" | 1 | - | 1 |
 | 2 | 「TC」 | 1 | 1 | 2 |
 | 3 | 「TCC」 | 2 | 1 | 3 |

 これにより、出力 3 が確認されます。表は、各プレフィックスが短いプレフィックスからどのように蓄積されるかを示し、有効なタイリングの組み合わせ構造と一致します。 

### 例 2: 「TT」

 | 私 | プレフィックス | dp[i-1] | dp[i-2] | dp[i] |
 | --- | --- | --- | --- | --- |
 | 0 | "" | - | - | 1 |
 | 1 | "T" | 1 | - | 1 |
 | 2 | 「TT」 | 1 | 1 | 2 |

 これは、2 つの有効な分解、つまり 2 つの単一スタンプまたは 1 つの二重スタンプを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各位置は O(1) 回の遷移で 1 回処理されます。 
| スペース | O(n) | サイズ n+1 の DP 配列 |

 n = 10^6 の場合でも、アルゴリズムは文字ごとに単純な算術演算を数回しか実行しないため、この解は制約内に簡単に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    s = sys.stdin.readline().strip()
    n = len(s)

    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]
        if i >= 2:
            dp[i] = (dp[i] + dp[i - 2]) % MOD

    return str(dp[n])

# provided sample
assert run("TCC\n") == "3"

# single character
assert run("T\n") == "1"

# two identical characters
assert run("TT\n") == "2"

# alternating pattern
assert run("TCTC\n") == "5"

# long uniform string
assert run("T" * 10 + "\n") == "89"

 | --- | --- | --- |
 | た | 1 | 基本ケースの 1 文字 |
 | TT | 2 | 1+1 と 2 の両方の分解 |
 | TCTC | 5 | 繰り返し枝分かれ成長 |

 ## 特殊なケース

 「T」のような単一文字の文字列の場合、単一のスタンプでカバーできるのは 1 つだけであるため、アルゴリズムは dp[1] = dp[0] = 1 を設定します。 dp[i-2]項がないため、不正アクセスは発生しません。 

「TC」のような 2 文字の文字列の場合、dp[2] = dp[1] + dp[0] = 2 となります。最初の項は 2 つの単一スタンプに対応し、2 番目の項は 1 つの 2 文字スタンプに対応します。 インデックス付けにより、両方の可能性が正確に 1 回カウントされることが保証され、各構造は最後のスタンプの選択によって一意に識別されるため、重複は発生しません。
