 ## 解決策
 ## 問題の理解

 私たちには次のシーケンスが与えられています$N$各スロットには 3 つの独立したオファーが含まれています。ジムから 1 つ、ドワイトから 1 つ、ケビンから 1 つです。 スロット内$i$、ジムを選択すると利回りが得られます$a_i$アイデア、ドワイトの譲歩$b_i$とケビンは譲る$c_i$。 各スロットについて、3 つのうち最大 1 つを選択することも、スロット全体をスキップすることもできます。 

構造を大幅に変更する追加の制限があります。 スロットを選択した場合、すぐ次のスロットを選択することはできません。 これは、選択したスロットが隣接していない必要があり、選択した各スロット内で 3 つの値のうち 1 つを正確に選択することを意味します。 

目標は、選択した値の合計を最大化することです。 

制約$N \le 1000$二次動的計画法ソリューションが可能になります。 スロットのサブセットを列挙したり、構造を持たずにスロットごとにすべての選択肢を独立して試行したりするものは、各スロットに 4 つの選択肢 (スキップするか、3 つのうち 1 つを選択) があるため、指数関数的に増大します。$4^N$素朴な検索の可能性。 

貪欲な思考による微妙な失敗例は、スロットに大きな値があるものの、その後に別の大きなスロットが続く場合に発生します。 たとえば、スロットの場合、$i$価値観がある$100, 1, 1$そしてスロット$i+1$価値観がある$99, 1, 1$、スロットの選択$i$貪欲にスロットをブロックする$i+1$、ローカルな決定はグローバルな最適化と一致しない可能性があります。 依存関係は純粋に連続するインデックス間のものであるため、ローカルな決定が前方に伝播します。 

もう 1 つの間違いは、常に選択することで各スロットを独立して扱うことから生じます。$\max(a_i, b_i, c_i)$。 たとえば、連続する 2 つのスロットの両方に大きな最大値がある場合、両方を取得することは違法であるため、独立した最大化はすぐに失敗します。 

## アプローチ

 この強引なアイデアは、スロットを左から右に処理し、各スロットで、前に選択したスロットが隣接してはいけないというルールを尊重しながら、スロットをスキップするか 3 人の従業員の 1 人を選択するかを決定することです。 これにより、当然のことながら、各状態が前のスロットが使用されたかどうかに依存する再帰が発生します。 

ただし、各立場が 4 つの選択肢に分岐し、有効性が以前の決定に依存するため、これは指数関数的に拡大します。 枝刈りを行ったとしても、最悪の場合でも、隣接しない選択のすべての組み合わせを探索します。これは指数関数的です。$N$、はるかに超えた$2^{1000}$。 

重要な観察は、決定の間の唯一の依存関係は、前のスロットが使用されたかどうかであるということです。 スロットを修正すると、最後のスロットが使用されたかどうか以外に、以前の選択内容のアイデンティティは問題になりません。 これにより、問題は線形動的計画法構造に縮小され、各状態は前のインデックスと現在のスロットの取得が許可されているかどうかのみに依存します。 

スロットごとの決定を単一の値に圧縮できます$v_i = \max(a_i, b_i, c_i)$、スロットを取ることにした場合$i$, 私たちは常にそのスロットに最適な従業員を選択します。 この場合、問題は古典的な非隣接要素の最大合計と同じになります。

 ## アルゴリズムのチュートリアル

 1. スロットごと$i$、計算する$v_i = \max(a_i, b_i, c_i)$。 これにより、スロットごとに複数の従業員を採用することがないため、各スロットが 1 つの達成可能な最高の貢献に縮小されます。 
2. DP 配列を定義します。$dp[i]$は、スロットのみを使用して取得できるアイデアの最大合計を表します。$1$に$i$、連続する 2 つのスロットが選択されないというルールを尊重します。 
3.初期化$dp[0] = 0$スロットがなければ何も得られないからです。 こちらもセット$dp[1] = v_1$利用可能なスロットが 1 つしかないため、それを採用するかしないかのどちらかであり、肯定的な場合は採用することが最適です。 
4. それぞれについて$i \ge 2$、次を計算します。$$dp[i] = \max(dp[i-1], dp[i-2] + v_i)$$最初の項はスキップスロットに対応します$i$、2番目はスロットの取得に対応します$i$、スキップを強制されます$i-1$。 
5. 戻る$dp[N]$答えとして。 

すべての最適解にはスロットが含まれるため、移行は完了します。$i$またはそうではありません。これら 2 つのケースは関連性がなく、すべての可能性をカバーします。 

### なぜ効果があるのか

 すべてのインデックスで$i$、DP 状態は、その時点までの制約の下で達成可能な最良の合計を表します。 有効な選択はいずれかを除外します$i$、この場合、それは完全に含まれます$dp[i-1]$、または含まれます$i$の除外を強制します。$i-1$、問題を最適な解決策にまで絞り込みます。$i-2$。 これにより、どの状態も最後の 1 つまたは 2 つの位置を超える決定に依存しないという不変条件が作成され、すべてのグローバル構成が最適なローカル選択に分解されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))
    
    v = [max(a[i], b[i], c[i]) for i in range(n)]
    
    if n == 1:
        print(v[0])
        return
    
    prev2 = 0
    prev1 = v[0]
    
    for i in range(1, n):
        cur = max(prev1, prev2 + v[i])
        prev2 = prev1
        prev1 = cur
    
    print(prev1)

if __name__ == "__main__":
    solve()
```各状態は前の 2 つにのみ依存するため、実装では DP 配列を 2 つのローリング変数に圧縮します。 前処理ステップの選択$v_i$これにより、従業員の選択を二度と見直すことがなくなり、DP における不必要な 3 番目の側面が回避されます。 

境界条件$n = 1$初期化によって暗黙的に処理されますが、明確にするために明示的にしておきます。 ローリング アップデートの順序は重要です。`prev1`上書きする前に保存する必要があります`prev2`そうでない場合、再発は中断されます。

 ## 特殊なケース

 最小限の入力で$N=1$アルゴリズムがアクセスを試行しないようにします$dp[-1]$または以前の状態に依存します。 その場合、解は直接返されます。$v_1$、これは繰り返しの初期化と一致します。 

のような大きな値が交互に現れる場合$[100, 0, 100]$は、両端を取得することが有効であり、より高い合計が得られるため、最適な戦略では中央のスロットがゼロの場合でもスキップする必要があることを示しています。 

すべてのスロットで値が等しい場合、DP は取得とスキップを効果的に切り替え、反復が値の一意性に依存せず、同点でも安定していることを確認します。
