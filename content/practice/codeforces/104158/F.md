 ## 解決策
 ## 問題の理解

 ボウルと蓋という 2 種類の部品の数を表す大きな整数のペアが与えられます。 各ペアから、トーマスが組み立てることができる完成したトイレの数は、これら 2 つの数量の最大公約数によって決まります。 その gcd は、完全にバランスのとれたアイテムの選択を使用して、ボウルと蓋の完全なペアを何組形成できるかを表します。 

各テスト ケースのタスクは、gcd 自体を計算することではなく、その主要な構造を記述することです。 gcd を見つけたら、それを素数の積として表現し、それぞれの異なる素数を因数分解で出現する回数とともに報告する必要があります。 出力は、行ごとに 1 つのプライムを昇順にフォーマットし、その後にゼロを含む終了行が続きます。 

この制約により、私たちは慎重な算術処理を必要とするようになります。 各数値は 10^12 に達する可能性があり、n までの繰り返し除算による単純な因数分解は即座に排除されます。 n までの割り算自体をテストすることさえ不可能です。 平方根因数分解に近いかそれ以上のものが必要であり、gcd が最大でも 10^12 であるという事実にも依存する必要があります。 

微妙なエッジ ケースは、gcd が 1 の場合です。この場合、素因数がまったく存在しないため、ゼロを含む 1 行のみが出力されます。 もう 1 つのケースは、gcd が 5 などの素数そのものである場合です。この場合、出力は多重度 1 とその後にゼロが続く素数だけで構成されます。 最後のゼロが欠落していたり​​、gcd = 1 に対して何かが誤って出力されたりすることは、一般的な書式設定の間違いです。 

## アプローチ

 問題を解決する直接的な方法は、各ペアの gcd を計算し、試行除算を使用して因数分解することです。 g を取得したら、2 から g までのすべての整数をテストし、割り切れるかどうかを確認できます。 これは正しいですが、遅すぎます。 g が約 10^12 である最悪のケースでは、テスト ケースごとに最大 1 兆回の操作が必要になりますが、これは実行不可能です。 

より構造化されたブルート フォースでは、sqrt(g) までの除数のみをチェックすることでこれを改善します。 各候補 i について、g を除算する場合は、g を i で繰り返し除算し、多重度をカウントします。 sqrt(10^12) は 10^6 であるため、これにより複雑さが大幅に軽減されます。これは境界線ですが、注意深く実装すれば、最適化された Python で最大 100 個のテスト ケースを許容できます。 

重要な洞察は、b と l を別々に因数分解する必要がないということです。 gcd はすでに問題を単一の数値に分解しており、その構造はどちらの入力よりも単純です。 g を分離したら、sqrt(g) までの試算による標準的な素因数分解で十分です。 制約が十分に小さいため、Pollard Rho のような高度な手法は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | gまでのブルートフォース | O(g) | お(1) | 遅すぎる |
 | √gまでの試算 | テストごとに O(√g) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ

 1. 各テスト ケースの整数 b と l を読み取ります。 必要な情報はすべて共有要素に完全に依存するため、目標は gcd のみを使用して作業することです。 
2. g = gcd(b, l) を計算します。 これにより、問題は、バランスのとれたペアの最大可能数を表す単一の数値の因数分解に圧縮されます。 
3. g が 1 に等しい場合は、すぐに 0 を出力します。 報告すべき主因数がないため、さらに計算する必要はありません。 
4. 素因数の空のリストを初期化し、2 から始まる約数のチェックを開始します。 
5. 2 から sqrt(g) までの各整数 i について、i が g を除算するかどうかを確認します。 そうなった場合は、その回数を数えながら g を i で割ることを繰り返します。 この数は素因数 i の多重度です。 
6. sqrt(g) までのすべての i を処理した後、g の残りの値が 1 より大きい場合、g 自体は素数であり、多重度 1 で記録する必要があります。 
7. 収集されたすべての素数を昇順に出力し、その後に多重度を続け、0 を含む行で終わります。 

### なぜ効果があるのか

1 より大きいすべての整数には、一意の素因数分解があります。 試行分割プロセスでは、各素因数のすべての出現が昇順に系統的に削除されます。 sqrt(g) までしかテストしないため、合成数はすでに小さい成分に因数分解されているため、残りの値は 1 または sqrt(g) より大きい素数でなければなりません。 これにより、すべての素数が正確に 1 回、正しい多重度でキャプチャされることが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def factorize(x):
    res = []
    i = 2
    while i * i <= x:
        if x % i == 0:
            cnt = 0
            while x % i == 0:
                x //= i
                cnt += 1
            res.append((i, cnt))
        i += 1
    if x > 1:
        res.append((x, 1))
    return res

def solve():
    t = int(input())
    for _ in range(t):
        b, l = map(int, input().split())
        g = math.gcd(b, l)

        if g == 1:
            print(0)
            continue

        factors = factorize(g)
        for p, c in factors:
            print(p, c)
        print(0)

if __name__ == "__main__":
    solve()
```この解決策は懸念事項をきれいに分離します。最初に gcd を使用して問題を圧縮し、次に標準の試行除算を使用して削減された数を因数分解します。 因数分解関数は、次に進む前に各素数を注意深く完全に除算するため、正しい多重度が保証されます。 ループ条件 i * i <= x は、x が減少するにつれて動的に縮小し、実際のパフォーマンスが向上します。 

よくある間違いは、更新された x に対してバインドされたループを再計算するのを忘れることです。 この実装では、条件で x の現在の値を直接使用することでこれを回避します。 もう 1 つの微妙な点は、ループによって完全に削減されていない可能性があるため、残りの x > 1 が素因数として扱われるようにすることです。

 ## 特殊なケース

 エッジ ケースの 1 つは、両方の入力が大きいにもかかわらず、gcd が 1 に崩壊する場合です。 たとえば、b = 83 および l = 24 はすぐに 1 を生成します。アルゴリズムは、因数分解の前に g == 1 をチェックすることでこれを処理し、不正な出力行が生成されないようにします。 

もう 1 つのエッジ ケースは、gcd 自体が素数である場合です。 たとえば、b = 17 および l = 34 の場合、g = 17 となります。ループでは約数が見つからず、最後に残った値によって「x > 1」条件がトリガーされ、多重度 1 で 17 が正しく出力されます。 

3 番目のケースは、gcd が 2^k などの完全累乗である場合です。 この場合、同じループ反復内で除算を繰り返すと、次の除数候補に移動する前に x が継続的に減少するため、完全な多重度の累積が保証されます。
