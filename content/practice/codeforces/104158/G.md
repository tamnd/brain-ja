 ## 問題の理解

 従業員の列が与えられ、それぞれの従業員には固定の入力時間が関連付けられています。 がある$N$従業員が整然と立っているので、配置することができます$M$目の前にはコンピューター。 時間ゼロで、最初の$M$従業員はそれぞれ 1 台のコンピュータを占有し、入力を開始します。 コンピューターが空くと、次に並んでいる従業員がすぐにそのコンピューターを受け取り、テストを開始します。 これは従業員全員が終了するまで続きます。 プロセス全体の終了時間は、最後の従業員が入力を完了した瞬間です。 

タスクは、コンピュータの最小数を決定することです$M$キュー全体が指定された期限内に終了するようにする$D$。 

重要な点は、割り当てが厳密に FIFO であるということです。コンピューターは残っている最も短いジョブを選択するのではなく、常に次に並んでいる人にサービスを提供します。 各マシンは独立して動作し、一連のジョブを繰り返し処理します。 

制約$N \le 10^5$そして$t_i \le 10^4$候補ごとに完全なプロセスをシミュレートするソリューションであることを示します$M$効率的でなければなりません。 時間を段階的に進めることを繰り返したり、非効率的な方法でキューをスキャンしたりする単純なシミュレーションでは、遅すぎます。 ヒープなしで各従業員の完了イベントをシミュレートしても、パフォーマンスが低下する可能性があります。$O(N^2)$最悪の場合、実行不可能になります。 

次の場合、微妙なエッジケースが発生します。$M = 1$。 完了時間は単純にすべての合計です。$t_i$、貪欲なスケジューリングの直感はこの境界と一致する必要があります。 もう 1 つのエッジケースは次のような場合です$M \ge N$、すべての従業員に専用のコンピューターが与えられ、答えは次のようになります。$\max(t_i)$。 これらのケースを明示的に処理しない、または自然に組み込む実装では、境界動作が正しくない危険があります。 

## アプローチ

 直接的なアプローチは、固定数のコンピューターをテストすることです。$M$プロセス全体をシミュレーションします。 最初のものを割り当てます$M$ジョブを実行し、最も早く空いたマシンを繰り返し選択し、そのマシンに次のジョブを割り当て、その可用性を更新します。 プライオリティキューを使用すると、ジョブ割り当てごとにコストがかかります$O(\log M)$なので、すべてをシミュレートします$N$人件費$O(N \log M)$。 これはプロセスを忠実にモデル化しているため正しいですが、候補ごとに 1 回しか役に立ちません$M$。 

実際の問題を解決するには、最小値を見つける必要があります。$M$期限条件を満たしていること。 重要な点は、次のような構成の場合です。$M$機械は時間内に終了します$D$、その場合、マシンの数が増えても待ち時間は短縮されるだけです。 並列サーバーを追加してもジョブが遅くなるわけではないため、実現可能性は単調です。$M$。 

この単調な構造により、二分探索が可能になります。$M$。 固定の場合$M$では、マシンの可用性時間の最小ヒープを使用してプロセスをシミュレートします。 各ジョブは最も早い仕上げ機に割り当てられ、最大完了時間を追跡します。 二分探索によりシミュレーションの数が削減されます。$O(\log N)$、全体の複雑さは次のようになります。$O(N \log N \log N)$、これは許容範囲です。

 ## アルゴリズムのチュートリアル

 私たちは問題を決定問題として扱います。$M$、時間内に終わることができるでしょうか？$D$?

 1. 候補を確定する$M$サイズの最小ヒープを使用してスケジューリング プロセスをシミュレートします。$M$。 各ヒープ要素は、コンピューターが解放される時間を表します。 最初はすべて$M$時間 0 ではコンピューターは無料です。 
2. 従業員を順番に繰り返します。 従業員一人ひとりにとって$i$、ヒープから最小値を抽出します。これは、使用可能な最も古いコンピューターを表します。 これは、現在のロードを最初に終了するマシンです。 
3. 従業員を割り当てる$i$をそのコンピュータに追加して$t_i$利用可能時間に合わせてヒープにプッシュし直します。 これにより、ヒープには各マシンの次の空き時間が常に含まれるという不変条件が維持されます。 
4. すべての従業員を処理した後、この構成の最終的な答えは、すべてのヒープ要素の最大値であり、最後の完了時間を表します。 
5. この完了時間が最大でも$D$、 それから$M$実現可能です。 
6. 二分探索オーバー$M$1から$N$、実現可能性チェックを使用して、より小さい有効な値に向かって検索をガイドします。 

これが機能する理由は、単調な負荷分散特性に基づいています。 増加中$M$以前はビジーなマシンの後ろでキューに入れられていたジョブが、より早い実行機会を得ることができるため、マシンごとの負荷を軽減または維持することしかできません。 ヒープ シミュレーションでは常に、各ジョブが最も早い利用可能なマシンに割り当てられます。これが、FIFO 制約と一致する、ローカルで最適な唯一の選択です。 すべての割り当ては利用可能時間のみに依存し、将来の決定には依存しないため、シミュレーションによって特定の割り当てのスケジュールが完全に決定されます。$M$、実現可能性は明確に定義されており、単調です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def can(M, t, D):
    # initialize M machines, all free at time 0
    heap = [0] * M
    heapq.heapify(heap)

    for x in t:
        cur = heapq.heappop(heap)
        cur += x
        heapq.heappush(heap, cur)
        if cur > D:
            # optional early exit
            pass

    return max(heap) <= D

def solve():
    N, D = map(int, input().split())
    t = list(map(int, input().split()))

    lo, hi = 1, N

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, t, D):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```コア シミュレーションでは、マシンが利用可能になったときに各値が追跡される最小ヒープが使用されます。 貪欲な割り当てはモデルによって強制されます。次の従業員は常に最も早く空いたマシンを使用します。 

二分探索により、実行可能な最小値が絞り込まれます$M$。 チェック関数は実際の完了時間を計算します。 それを比較します$D$。 

実装の微妙な詳細は、実行終了時間を注意深く維持しようとするのではなく、最後に最大ヒープ値を追跡することです。 これにより、中間状態に関する部分的な推論における間違いが回避されます。 もう 1 つの詳細は、正確性を慎重に維持せずにループ内での早期停止に頼ることはできないため、クリーン バージョンでシミュレーションが完了するだけであることです。

 ## 特殊なケース

 のために$N = 1$、ヒープには 1 つのマシンがあり、完了時間は 2 分だけであるため、アルゴリズムはすぐに 1 を返します。$t_1$、要件に一致します。 

いつすべて$t_i$が等しく小さい場合、ヒープはタスクをマシン間で均等に分散します。 たとえば、$N = 4$、$t = [2,2,2,2]$、そして大きい$D$、シミュレーションでは、次の場合には 1 台のマシンで十分であることが示されています。$D \ge 8$ただし、二分探索では有効な最小値が正しく検出されます。$M$過大評価せずに。 

あるタスクが他のタスクよりもはるかに大きい場合。$t = [100,1,1,1]$、ヒープにより、長いタスクが早期にマシンを占有し、短いタスクが他のタスクを埋めます。 小付き$M$、長いタスクがボトルネックとなり、十分なマシンが存在しないと実現可能性が失われます。
