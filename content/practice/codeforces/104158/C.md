 ## 解決策
 ## 問題の理解

 2D 平面上の円形のターゲットと、従業員がオブジェクトを投げる場所を表す一連の点が与えられます。 タスクは、これらの点のうちのいくつが円の内側、または正確に円の境界上に着地するかを数えることです。 

各スローは平面上の座標にすぎません。 ターゲットはその中心によって定義されます$(c_x, c_y)$そして半径$r$。 円の中心までの距離が以下の場合、投げは成功します。$r$。 

必要な主な量は、各点と中心の間のユークリッド距離です。 ただし、平方根を計算すると、$10^5$ポイントは不要であり、浮動小数点の精度の問題が発生する可能性があります。 代わりに二乗距離を使用して決定を行うこともできます。 

制約が十分に厳しいため、$O(n)$解決策が期待されています。 以来$n \leq 10^5$、各ポイントを一定時間で処理するアプローチであれば十分です。 並べ替えやペアごとの比較を伴うものは過剰になります。 

点が円の境界上に正確に位置する場合、微妙なエッジ ケースが発生します。 たとえば、中心が$(0, 0)$、半径は$5$、そしてポイントは$(3, 4)$、距離は正確に$5$したがって、成功としてカウントされる必要があります。 包括的な比較の代わりに厳密な不等号が使用される場合、これは誤って処理されやすくなります。 

もう 1 つの潜在的な落とし穴は、固定幅の整数を使用する言語での整数オーバーフローです。これは、座標が次のように大きくなる可能性があるためです。$10^9$。 差の二乗は最大に達する可能性があります$10^{18}$, そのため、64 ビット整数が必要です。 Python ではこれは安全ですが、翻訳には推論が依然として重要です。 

## アプローチ

 簡単なアプローチは、すべての点のユークリッド距離を計算し、平方根をとり、それが以下であるかどうかを確認することです。$r$。 これは、円の幾何学的定義を直接実装しているため、正しいです。 ただし、すべての従業員に対してコストのかかる平方根演算が実行されるため、$O(n)$平方根呼び出し。 これは線形ではありますが、必要以上に遅くなり、境界付近の浮動小数点値を比較するときに精度の問題が発生する危険性があります。 

重要な観察は、平方根が単調であるということです。 距離の比較は、距離の 2 乗を比較することと同じです。 チェックする代わりに$$\sqrt{(x - c_x)^2 + (y - c_y)^2} \le r$$安全に両辺を正方形にすることができます。$$(x - c_x)^2 + (y - c_y)^2 \le r^2$$これにより、浮動小数点演算が完全に削除され、ポイントあたりの演算が数回の整数の減算と乗算に減ります。 問題は、一定時間チェックを伴う単純な線形スキャンになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (sqrt 付き) | O(n) | お(1) | 受け入れられるが、遅くてリスクが高い |
 | 二乗距離チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 投球数とサークルパラメータを読み取ります。$c_x, c_y, r$。 これにより、すべての計算の固定基準点としきい値が定義されます。 
2. 事前計算$r^2$。 これにより、すべての点での再計算が回避され、すべての比較が整数演算に留まることが保証されます。 
3. カウンタをゼロに初期化します。 これにより、円の内側または境界に何本の投球が着地したかが追跡されます。 
4. 各従業員の取り組みについて$(x_i, y_i)$、中心からの水平オフセットと垂直オフセットを計算します。$dx = x_i - c_x$、$dy = y_i - c_y$。 これにより、問題は、シフトされた座標系での原点からの距離の測定に変換されます。 
5. 二乗距離を計算します$d = dx^2 + dy^2$。 これは中心からの正確な二乗ユークリッド距離を表します。 
6. 比較する$d$と$r^2$。 もし$d \le r^2$、カウンターをインクリメントします。 境界上の点は成功したと見なされるため、等しい場合が含まれます。 
7. すべてのポイントを処理した後、カウンタを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、二乗が非負の値に対して厳密に単調であるという事実に基づいています。 二乗距離と$r^2$は負ではないため、二乗値を比較すると実際の距離の順序が維持されます。 すべての点は同等の条件に基づいて分類されるため、幾何学的ケースが誤って分類されることはありません。 ユークリッド距離から二乗距離への変換は、浮動小数点計算を完全に削除しながら正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, cx, cy, r = map(int, input().split())
    r2 = r * r
    ans = 0

    for _ in range(n):
        x, y = map(int, input().split())
        dx = x - cx
        dy = y - cy
        if dx * dx + dy * dy <= r2:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、ラインごとにすべての入力を一定時間で読み取ることから始まります。 平方半径は 1 回計算されるため、ループ内での乗算の繰り返しが回避されます。 各点は独立して処理され、二乗距離条件を評価する前に中心からのオフセットが計算されます。 

比較には、`<=`それよりも`<`、境界点は有効なヒットであるため、これは不可欠です。 すべての算術演算は Python 整数を使用して実行され、オーバーフローすることなく大きな値を自然に処理します。

 ## 特殊なケース

 エッジケースの 1 つは、点がちょうど離れたところにある場合です。$r$。 たとえば、中央$(0,0)$、半径$5$、 ポイント$(3,4)$。 アルゴリズムは計算します$dx^2 + dy^2 = 25$、これは次と等しい$r^2$なので、正しくカウントされています。 これにより、包含境界条件が確認されます。 

もう 1 つのエッジ ケースは、座標が非常に大きい場合です。$(10^9, -10^9)$。 二乗距離は約になります$2 \cdot 10^{18}$、これは依然として Python 整数に安全に適合します。 アルゴリズムは浮動小数点精度に依存しないため、正しいままです。 

最後のケースは、すべての点が中心と一致する場合です。 毎$dx$そして$dy$がゼロになるため、すべての点がカウントされ、その中心を含む円の幾何学的定義と一致します。
