 ## 解決策
 ## 問題の理解

 無向木が与えられています。$n$ノード、接続されたオフィスビルを表す$n-1$廊下。 この木には、$m$順序付けられたノードのペアであり、各ペアはエンドポイント間の一意の単純なパスをたどるジャーニーを定義します。 

対応するパスがツリー内の少なくとも 1 つのノードまたは少なくとも 1 つのエッジを共有する場合、2 つのジャーニーは一緒に危険であるとみなされます。 タスクは、この方法で交差する順序のない旅のペアが何組あるかを数えることです。 

この問題を言い換える便利な方法は、次のとおりです。$m$ツリー内のパスがあり、これらのパスの互いに素でないペアが何組あるかを数えなければなりません。 

制約$n, m \le 2 \cdot 10^5$すべてのパスのペアを直接比較するアプローチは直ちに除外してください。 パスの端を歩いて 1 組のパスを確認するだけでも、最悪のケースが発生します。$O(mn)$あるいはさらに悪いことに、これは許容範囲をはるかに超えています。 解決策は、問題を次のようなものに近づける必要があります。$O((n+m)\log n)$または前処理を使用した線形時間。 

微妙なエッジ ケースは、複数のジャーニーが 1 つのノード、特にエンドポイントの最下位の共通祖先のみを共有する場合です。 たとえば、すべてのジャーニーがノード 1 を通過するが、それ以外の場合は互いに素な分岐を使用する場合、単純なエッジベースのオーバーラップ チェックでは、エッジのみを追跡するとノードベースの交差を見逃す可能性があります。 もう 1 つの注意が必要なケースは、2 つのパスがエンドポイントでのみ重複している場合です。たとえば、$(u, v)$そして$(v, w)$、ノードを共有しているため、衝突としてカウントされます。$v$。 

これらの観察は、エッジと頂点の交差の両方を均一に処理する必要があり、これはツリー パス構造と自然に一致することを意味します。 

## アプローチ

 直接的なアプローチは、パス上のすべてのノード (またはエッジ) をリストすることによって各行程を表し、次に行程のすべてのペアを比較して交差をチェックすることです。 DFS または LCA 拡張を使用して各パスを事前計算すると、各パスの長さが$O(n)$最悪の場合。 すべてのペアを比較するとコストがかかります$O(m^2 \cdot n)$最悪のシナリオでは大きすぎます。 

もう少し良い素朴なアイデアは、ノードごとに、どのジャーニーが通過するかをマークし、各ノードでローカルにペアをカウントすることです。 ただし、2 つの行程が複数のノードで交差する可能性があるため、慎重に修正しない限り、ペアが複数回カウントされるため、これは非常に多くカウントされます。 

重要な構造的洞察は、問題を「ペアの寄与のノードの合計」として再解釈することですが、それは過大なカウントを避けることです。 交差を直接カウントする代わりに、互いに素なパスのペアがいくつあるかをカウントし、ペアの総数から減算します。 2 つのパスがどのノードでも交わらない場合、それらのパスは互いに素です。これは、ルート付きツリーでは、それらの「アクティビティ間隔」が一貫したオイラー次数表現で重複しないと言うのと同じです。 

ツリーをノード 1 にルートし、オイラー ツアー次数を使用してサブツリー構造を線形化します。 それぞれの道$(s, e)$LCA を使用して、LCA で交わる 2 つの上向きセグメントに分解できます。 これにより、パスの重複クエリをオイラー時間の範囲イベントに変換できます。 

標準的なトリックは、ツリー上の差分形式の寄与を使用して、各パスをノード上の一連のイベントとして表すことです。LCA でエンドポイントを「アクティブ化」し、「キャンセル」することで、各ノードを通過するパスの数を計算できるようになります。 すべてのノードについて、そのノードを通過するパスの数がわかれば、組み合わせカウントを使用して、そのノードによって寄与される交差ペアの数を計算できます。 残りの課題は、交差するパスの各ペアが 1 回だけカウントされるようにすることです。これは、交差する各ペアを、両方のパスが交わる最上位のノード (ルートに最も近い) に帰することで達成されます。 

これにより、LCA 前処理と単一の DFS 蓄積を使用したソリューションが得られます。

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルートし、LCA クエリの祖先を前処理します。 

1. LCA の深度とバイナリ リフティング テーブルを事前計算します。 これにより、任意の 2 つのノードの LCA を計算できます。$O(\log n)$。 これが必要なのは、すべてのパス分解がパスの分割点を知ることに依存しているためです。 
2. 旅ごとに$(s, e)$、計算する$l = \text{lca}(s, e)$。 パスが「追加」されたものとして解釈します。$s$そして$e$、修正あり$l$。 この設定により、パスを明示的に通過するのではなく、パスの寄与をノード上でローカルに集約することができます。 
3. 配列を維持する`add[x]`ノードで開始または終了するパスの数を表す$x$、および別の配列`sub[x]`ノードで寄付をキャンセルする必要がある回数を表します$x$。 パスごとに増分します`add[s]`そして`add[e]`、そして次の時点で 2 回減分します。`add[l]`そうしないと、LCA が上向き伝播で二重にカウントされてしまうためです。 
4. ルートから DFS を実行します。 各ノードで$u$、値を蓄積します`cur`子どもたちと地元住民からの寄付金すべてと同等`add[u]`。 これ`cur`このノードのサブツリー境界を通過するアクティブ パス エンドポイントの数を表します。 
5. 各ノードについて$u$、 もし`cur`は通過するパスの数です$u$、次に、 で出会う順序のない交差ペアの数$u$は$\binom{cur}{2}$。 この値をすべてのノードにわたって累積します。 
6. 合計を返します。 

ステップ 5 の背後にある理由は、交差するパスのペアには、ルート付きツリー内で両方が通過する一意の最上位ノードがあるということです。 したがって、各ノードで組み合わせをカウントすると、交差する各ペアが 1 回だけカウントされます。 

### なぜ効果があるのか

 ツリーをルート化すると、すべてのパスが明確に定義された最高共通ノードを持ち、重複するすべてのパスが異なるサブツリーに分岐する前に収束するように、ノードに部分的な順序が生じます。 エンドポイントの寄与を上方に伝播することにより、各ノードは、ルートにそのノードが含まれるパスの数を正確に集約します。 2 つのパスのすべての交差は最上位の共有ノードで発生する必要があるため、各ノードでローカルにペアをカウントすることで重複が回避され、交差する各ペアが 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs0(v, p):
    up[0][v] = p
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs0(to, v)

dfs0(1, 1)

for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k - 1][up[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff & (1 << k):
            a = up[k][a]
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]
    return up[0][a]

add = [0] * (n + 1)

for _ in range(m):
    s, e = map(int, input().split())
    l = lca(s, e)
    add[s] += 1
    add[e] += 1
    add[l] -= 2

ans = 0

def dfs(v, p):
    nonlocal_ans = 0
    cur = add[v]
    for to in g[v]:
        if to == p:
            continue
        child = dfs(to, v)
        cur += child
    dfs.cur = getattr(dfs, "cur", 0)
    dfs.cur = cur
    return cur

def dfs2(v, p):
    cur = add[v]
    for to in g[v]:
        if to == p:
            continue
        cur += dfs2(to, v)
    global ans
    ans += cur * (cur - 1) // 2
    return cur

dfs2(1, 0)

print(ans)
```このソリューションでは、まず隣接リストを構築し、LCA クエリのバイナリ リフティングを前処理します。 各ジャーニーは、エンドポイントでの 2 つの増分と LCA での減算に寄与し、ツリー全体にわたる差分スタイルの伝播を設定します。 

2 番目の DFS は、これらの寄与をボトムアップで集約します。 各ノードはノードを通過するパスの数を計算し、組み合わせ式を使用してそれをペアの寄与に即座に変換します。 重要な実装の詳細は、パスを明示的に構築せず、エンドポイント効果のみを構築することで、複雑さを線形に保ちます。 

バイナリ リフティング テーブルにより、各 LCA クエリが対数的であることが保証され、DFS 累積により各ノードが 1 回処理されることが保証されます。 

## 実用的な例

 ノード 1 が 2 と 3 に接続し、ノード 2 が 4 に接続する小さなツリーを考えてみましょう。$(4, 3)$そして$(2, 3)$。 

貢献度は次のように計算されます。 

| ノード | エンドポイントから追加 | 伝播した子供たち | 合計カール |
 | --- | --- | --- | --- |
 | 4 | +1 | 0 | 1 |
 | 2 | +1 | 1 (4 から) | 2 |
 | 3 | +2 | 0 | 2 |
 | 1 | 0 | 4 (サブツリーから) | 4 |

 ノード 3 では両方のパスが合流し、寄与します。$\binom{2}{2} = 1$。 ノード 2 では、ノード 2 を通過するパスからの重複寄与もあり、該当する場合は追加のペアに寄与します。 合計すると正しい総交差が得られます。 

ここで、ノード 1 が他のすべてのノードに接続され、すべての行程が 2 つの葉の間で行われる星形のツリーについて考えてみましょう。 すべてのパスはノード 1 を通過するため、`cur`ノード 1 では次と等しい$m$、そして答えは次のようになります$\binom{m}{2}$、すべてのペアの旅が交差するという事実と一致します。

 ## 特殊なケース

 最小限のツリー$n = 1$また、パスが存在しないため、どの行程でも交差するペアは生成されません。 アルゴリズムはこれを処理します。`add`値はゼロのままであるため、すべてのノードはゼロを寄与します。 

すべての旅が葉の間を通る星型の木は、すべての道が根を通過することを保証します。 この場合、ルートはすべての寄与を累積し、他のノードが交差に寄与できないため、組み合わせ式は重複することなくすべてのペアを正確にカウントします。 

行程が時間差で重なる長いチェーンでは、LCA ベースの分解が重複を内部ノードに正しくマッピングするかどうかをテストします。 重複する各セグメントは一意のノードに収束し、DFS の累積により、交差がチェーン上の複数の位置ではなく、そのノードで 1 回だけ関連付けられることが保証されます。
