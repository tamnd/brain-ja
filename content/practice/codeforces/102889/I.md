 ## 解決策
 ## 問題の理解

 時間の経過とともに収集された評価を表す一連の整数が与えられます。 これらの評価は、受け取った順にすでに並べ替えられています。 タスクは、順序を保持しながら、このシーケンスを正確に k 個の連続グループに分割することです。ここで、各グループは 1 日に対応し、すべての要素は正確に 1 日に属している必要があります。 

各グループについて、部分配列から値を計算します。グループ内のすべての数値のビット単位の AND を計算し、同じグループ内のすべての数値のビット単位の OR も計算します。 次に、これら 2 つの結果を XOR します。 パーティションの合計スコアは、k 個のグループすべてにわたるこの値の合計です。 この合計スコアを最大化するパーティションを選択したいと考えています。 

したがって、問題の主な構造は配列上のパーティション DP ですが、セグメントのコスト関数は自明ではなく、セグメント全体にわたるビットごとの相互作用に依存します。 

n ≤ 2000 および k ≤ n という制約は、O(n²k) 以上の解が必要であることを示唆しています。 重い定数を含む n の 3 次関数はすべて通過する可能性がありますが、O(n³k) やパーティションを明示的に列挙するのは遅すぎます。 

k = 1 または k = n の場合、微妙なエッジ ケースが発生します。 k = 1 の場合、配列全体を 1 つのセグメントとして取り、範囲全体にわたって AND/OR 式を計算する必要があります。 k = n の場合、すべてのセグメントの長さは 1 であり、単一の数値の AND と OR が等しいため、各セグメントの寄与率は 0 となるため、答えは常に 0 になります。単一要素セグメントを明示的に考慮しない単純なパーティション DP は、あらゆる場所で非ゼロ寄与率を誤って仮定する可能性があります。 

もう 1 つの重要なエッジ ケースは、値が同一である場合です。 すべての a[i] が等しい場合、どのセグメントでも AND は OR と同じ値に等しいため、XOR は常に 0 になります。 これにより、分割に関係なく、答えが強制的にゼロになります。また、最適化では、誤って分割から値を「得よう」と試みてはなりません。 

## アプローチ

 ブルートフォースソリューションでは、配列を k 個のセグメントに分割するためにあらゆる方法が試行されます。 ウェイの数は組み合わせであり、およそ C(n-1, k-1) であり、n で指数関数的になります。 各パーティションについて、各セグメントをスキャンして AND と OR を計算することでセグメント値を計算し、セグメントごとに O(n) のコストがかかり、O(n *number_of_partitions) のような結果になりますが、これは中程度の n の場合でも完全に実行不可能です。 

より構造化されたブルート フォース アプローチでは、動的プログラミングが使用されます。 dp[i][j] は、j 個のセグメントに分割された最初の i 要素を使用して最良の値を表すものとします。 各 dp[i][j] について、以前のすべてのカット位置 p < i を試し、セグメント [p, i] を計算します。 これにより、遷移 dp[i][j] = max(dp[p][j-1] +cost(p+1, i)) が得られます。 単純にコスト(p+1, i) を計算するには O(n) が必要となるため、合計の複雑さは O(n³k) になりますが、これは 2000 までの n には大きすぎます。 

重要な洞察は、セグメントコストの構造を活用することです。 どのセグメントでも、値は (セグメントの AND) XOR (セグメントの OR) になります。 AND と OR はどちらもセグメントの拡張に対して単調です。AND は拡張するにつれて減少するか同じままであり、OR は増加するか同じままです。 これは、セグメントを拡張すると、ビット単位の構造が制御された方法で変化することを示唆しています。 

セグメントごとに AND と OR を最初から再計算するのではなく、増分的に維持します。 固定 i の場合、i で終わるセグメントを後方に拡張し、ステップごとに O(1) の AND と OR を更新できます。 これにより、クエリあたりのコスト計算が O(n) から O(1) に減り、DP 遷移が O(n²k) に変わります。 

さらに、k ≤ n ではセグメント全体にわたる標準 DP が可能であり、実行中の AND/OR 値を維持しながら前の位置をスキャンすることで遷移を最適化できることがわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | 指数関数 | O(n) | 遅すぎる |
 | 再計算を伴う DP | O(n3k) | O(nk) | 遅すぎる |
 | インクリメンタル AND/OR による最適化された DP | O(n²k) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

dp[j][i] を、j 個のセグメントに分割された最初の i 個の要素を使用して取得できる最大スコアとして定義します。 答えは dp[k][n] です。 

1. 1 から n までのすべての i に対して dp[1][i] を初期化します。 単一セグメントの場合、実行中の AND 値と OR 値を維持することによって、プレフィックス [1..i] のコストを計算します。 これにより、より大きなパーティションを構築するための基本値が得られます。 

2. 2 から k までのセグメント j の各数について、j から n までのすべての i について dp[j][i] を計算します。 セグメントよりも少ない要素を計算することはできないため、i は j から始まります。 

3. dp[j][i] を計算するには、j-1 ≤ p < i であるすべての可能な最後のカット位置 p を考慮します。 最後のセグメントは [p+1..i] であるため、 dp[j][i] = dp[j-1][p] の p にわたる最大値とセグメント [p+1..i] のコストを加算します。 

4. 各セグメントの AND と OR を最初から再計算する代わりに、i を固定し、p を i-1 から j-1 まで逆方向に移動し、2 つの実行変数 cur_and と cur_or を維持します。 a[p] を含めてセグメントを左に拡張すると、cur_and &= a[p] と cur_or |= a[p] が更新されます。 これにより、各セグメントのコスト計算が O(1) になります。 

5. 各候補 p について、cur_and XOR cur_or を計算し、それに応じて dp[j][i] を更新します。 

重要なアイデアは、固定右端点 i について、p を逆方向にスキャンすると、増分更新で可能なすべてのセグメント終了が得られるため、各 dp[j][i] が O(n) 時間で計算されるということです。 

### なぜ効果があるのか

 DP は、すべてのパーティションが最後のカット位置によって正確に 1 回表現されることを保証します。 AND と OR の増分保守は、両方の操作が結合的であり、セグメント内の順序には依存せず、要素のメンバーシップのみに依存するため、正しいです。 考えられるすべてのセグメントは、逆方向スキャンによって dp 状態ごとに 1 回だけ列挙されるため、有効なパーティションが見逃されることはなく、無効なパーティションが二重にカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    INF = -10**18
    dp = [[INF] * (n + 1) for _ in range(k + 1)]

    # base: 1 segment
    for i in range(1, n + 1):
        cur_and = a[0]
        cur_or = a[0]
        for j in range(1, i):
            cur_and &= a[j]
            cur_or |= a[j]
        dp[1][i] = cur_and ^ cur_or

    for seg in range(2, k + 1):
        for i in range(seg, n + 1):
            cur_and = a[i - 1]
            cur_or = a[i - 1]
            best = INF

            for p in range(i - 1, seg - 2, -1):
                cur_and &= a[p]
                cur_or |= a[p]
                val = cur_and ^ cur_or
                best = max(best, dp[seg - 1][p] + val)

            dp[seg][i] = best

    print(dp[k][n])

if __name__ == "__main__":
    solve()
```DP テーブルは、セグメント数ごとに行ごとに構築されます。 最初の行は完全なプレフィックス セグメント コストとして明示的に事前計算されるため、余分なダミー遷移の導入が回避されます。 後の各行について、エンドポイント i を修正し、逆方向にスキャンして、考えられるすべての最後のセグメントを効率的に計算します。 

内側のループで最適化が行われます。候補セグメントごとに AND と OR を再計算する代わりに、セグメントを左方向に拡張するときに以前に計算された値を再利用します。 

cur_and と cur_or の初期化には注意が必要です。 これらは i ごとにリセットする必要があります。そうしないと、異なるエンドポイント間で値が漏洩してしまいます。 また、バックワード ループ境界により、各パーティションにセグメント数の制約を満たすのに十分な要素が確実に含まれるようになります。

### 例 2
 入力:
 7 4
 11 45 14 19 19 8 10

 DP は、段階的にさらに多くのセグメントを構築します。 この場合の重要な観察は、より積極的に分割すると、OR が大きいままで AND がすぐに崩壊し、より高い XOR 値が生成されるセグメントを分離できることです。 

重要な遷移は、19, 19 のような繰り返し値が寄与率ゼロのセグメントを形成するときに発生します。これは、同一またはほぼ同一の値をグループ化することは、分散の高いブロックを分離するのに役立つ場合を除き、最適ではないことが多いことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(n²k) | 各 dp 状態 (k・n 状態) について、O(1) 更新で最大 n 個の遷移をスキャンします。 
| スペース | O(nk) | サイズ n | k 行を格納する DP テーブル

 n ≤ 2000 の場合、最悪の場合の演算は生の形式で約 8×10⁹ ですが、セグメント制約とタイトな内部ループによる実際的な枝刈りにより、境界線に達しますが、最適化された Python または目的の C++ ソリューションでは許容可能になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import inf

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        INF = -10**18
        dp = [[INF] * (n + 1) for _ in range(k + 1)]

        for i in range(1, n + 1):
            cur_and = a[0]
            cur_or = a[0]
            for j in range(1, i):
                cur_and &= a[j]
                cur_or |= a[j]

    return solve()

 ## 特殊なケース

 k が n と等しい場合、すべてのセグメントには 1 つの要素が含まれます。 このような各セグメントには AND と OR が等しいため、XOR はゼロになり、DP はすべての単一要素の寄与をゼロとして正しく初期化します。 

すべての要素が同一の場合、考えられるすべてのセグメントは同一の AND および OR を持ち、寄与はゼロになります。 DP では分割や結合によってプラスの利益が得られることは決してないため、最適解はゼロのままです。 

k が 1 に等しい場合、アルゴリズムは単一のプレフィックス セグメントを計算します。 dp[1][n] の初期化では配列全体のコストが直接計算され、遷移を必要とせずに正確性が保証されます。 

大きな値が AND をすぐに 0 に減らす場合でも、cur_and が 0 で安定するため、逆方向スキャンは引き続き正しく機能し、OR は累積し続け、再計算することなくセグメント値が正確に計算されます。
