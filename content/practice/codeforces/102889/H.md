 ## 問題の理解

 あります`n`ポケモンの種族。 種`1`は進化ファミリーのルートであり、他のすべての種には、進化元となった親種が 1 つだけあります。 これにより、親から子への移動が 1 つの進化ステップを表すルート付きツリーが作成されます。 

庭には以下が含まれています`m`ポケモンが左から右へ固定された順序で配置されています。 元の順序を維持しながら、できるだけ多くのものを選択したいと考えています。 選択した 1 つのポケモンが別のポケモンより先に出現する場合、2 番目のポケモンは進化ツリーの最初のポケモンの子孫である必要があります。 目標は、そのようなサブシーケンスの最大長を見つけることです。 

シーケンスの順序とツリー構造は相互作用します。 選択したポケモンは、前のポケモンの直接の子である必要はありません。 進化ステップはいくつでも許可されるため、次に選択される種は、前の種のサブツリー内のどこかに存在するだけで済みます。 

この制約により、二次動的計画法による解決策は不可能になります。 庭内の種の数とポケモンの数の両方に達することができます`5 * 10^5`、つまり、アルゴリズムは次のことを行います`O(nm)`あるいは`O(m sqrt(n))`操作は 1 秒の制限時間内に収まりません。 線形に近いか、`O((n+m) log n)`仕事。 

よくある間違いは、これを通常の最長増加部分列問題として扱うことです。 樹木の関係は数値ラベルに基づいていないため、種の番号を比較しても意味のない結果が得られます。 もう 1 つの微妙なケースは、次に選択されるポケモンが同じ種ではなく、適切な子孫である必要があることです。 例えば：```
2 2
1
1 1
```正しい答えは、`1`。 両方のポケモンを選択するには 2 番目の種族が必要になります`1`最初の種から進化する`1`、しかし進化は起こりませんでした。 

もう一つの特殊なケースは、根の種類です。 これには祖先がないため、最初に出現したルートが以前のチェーンを拡張することはできません。 例えば：```
3 3
1 1
2 1 3
```正しい答えは、`2`、種を使用して`1`続いて種`3`。 ルートを誤って親を持つものとして扱うソリューションでは、無効な遷移が作成される可能性があります。 

反復種にも注意が必要です。 例えば：```
3 4
1 2
2 2 3 3
```正しい答えは、`2`。 種の 2 つのコピー`2`種はそれ自体に進化しないため、連鎖することはできません。 最良の連鎖は種である`2`続いて種`3`。 

## アプローチ

 直接的な動的プログラミングのアイデアは、ヤードを左から右に処理することです。 その位置にいるポケモンごとに`i`、 定義する`dp[i]`このポケモンで終わる最長の有効なサブシーケンスとして。 以前のすべての位置を調べることで計算できます`j`かどうかを確認します`a[j]`の先祖です`a[i]`。 そうであれば、その連鎖を拡張することができます。 

考えられるすべての以前の選択が考慮されるため、このアプローチは正しいです。 しかし、それは遅すぎます。 最悪の場合には、`5 * 10^5`ポケモン、以前のすべての位置を確認するには約`2.5 * 10^11`比較、それは不可能です。 

重要な観察は、以前のポケモンから必要な唯一の情報は、現在の種の祖先の中で最適なチェーンの長さであるということです。 特定の種類のポケモンの処理が完了したとき`x`の将来の子孫に対する答えの候補として、そのチェーンの長さを追加します。`x`。 今後のクエリでは、ルートからノードまでのパスに保存されている最大値が要求されます。 

これにより、問題は 2 つのツリー操作に変わります。 ノード自体を除くルートからノードへのパスの最大値をクエリする必要があり、1 つのノードをより大きな値で更新する必要があります。 重光分解では、ツリー パスが少数の連続したセグメントに分割されます。 重い-軽い順序のセグメント ツリーは、これらのセグメントに応答し、効率的に更新できます。 

ブルート フォース ソリューションは、考えられるすべての先行者を明示的にチェックするため機能しますが、数が多すぎるため失敗します。 ツリー パスの最大値の観測では、関連するすべての先行データが少数の範囲に圧縮されます。

 ## アルゴリズムのチュートリアル

 1. 親情報から進化ツリーを構築します。 すべての子を保存して、後で重軽度分解のためにツリーを走査できるようにします。 
2. すべてのサブツリーのサイズを計算し、すべてのノードの重い子を特定します。 重い子は、最大のサブツリーを持つ子です。 重い子をフォローすると、重要なパスがまとめられるため、すべてのルートからノードへのパスが対数的な数の部分のみに減ります。 
3. すべてのノードに、重いものから軽いものの順に位置を割り当てます。 各重鎖はこの順序で連続セグメントになるため、パス クエリをセグメント ツリー範囲クエリに変換できます。 
4.庭のポケモンを左から右に処理します。 現在の種に関しては`x`、ルートからパスに保存されている最大値をクエリします。`parent[x]`。 これにより、次のように進化できる最適な以前のチェーンが得られます。`x`。 
5. 現在のチェーンの長さを、そのクエリ結果に 1 を加えた値に設定します。 次に、の位置を更新します`x`この値をセグメントツリーに含めます。 の子孫となる未来のポケモン`x`このチェーンを使用できるようになりました。 
6. スキャン中に生成された最大値を追跡し、すべてのポケモンが処理された後に出力します。 

クエリが次で停止する理由`parent[x]`は不可欠です。 移行には少なくとも 1 つの進化ステップが必要であるため、現在の種をそれ自体の前種として使用することはできません。 

正確さは、最初の処理後の不変条件から導き出されます。`i`ポケモン、すべてのツリー ノードには、まさにその種の処理されたポケモンの中で最適な部分シーケンス長が保存されます。 したがって、現在の種の祖先をクエリすると、その種に先立つ可能な限り最良のポケモンが正確に返されます。 更新ではこの不変条件が保持され、考えられるすべての終了位置が考慮されるため、保存されている最大値が答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    children = [[] for _ in range(n + 1)]
    parent = [0] * (n + 1)
    parent[1] = 0

    if n > 1:
        arr = list(map(int, input().split()))
        for i, p in enumerate(arr, 2):
            parent[i] = p
            children[p].append(i)

    a = list(map(int, input().split()))

    depth = [0] * (n + 1)
    order = [1]
    for x in order:
        for y in children[x]:
            depth[y] = depth[x] + 1
            order.append(y)

    size = [1] * (n + 1)
    heavy = [0] * (n + 1)
    for x in reversed(order):
        best_size = 0
        for y in children[x]:
            size[x] += size[y]
            if size[y] > best_size:
                best_size = size[y]
                heavy[x] = y

    head = [0] * (n + 1)
    pos = [0] * (n + 1)
    rev = [0] * (n + 1)
    cur = 0

    stack = [(1, 1)]
    while stack:
        x, h = stack.pop()
        while x:
            head[x] = h
            cur += 1
            pos[x] = cur
            rev[cur] = x

            for y in children[x]:
                if y != heavy[x]:
                    stack.append((y, y))

            x = heavy[x]

    size_seg = 1
    while size_seg < n:
        size_seg *= 2
    seg = [0] * (size_seg * 2)

    def update(i, val):
        i += size_seg - 1
        if seg[i] >= val:
            return
        seg[i] = val
        i //= 2
        while i:
            nv = seg[i * 2] if seg[i * 2] >= seg[i * 2 + 1] else seg[i * 2 + 1]
            if seg[i] == nv:
                break
            seg[i] = nv
            i //= 2

    def query(l, r):
        if l > r:
            return 0
        l += size_seg - 1
        r += size_seg - 1
        ans = 0
        while l <= r:
            if l & 1:
                if seg[l] > ans:
                    ans = seg[l]
                l += 1
            if not (r & 1):
                if seg[r] > ans:
                    ans = seg[r]
                r -= 1
            l //= 2
            r //= 2
        return ans

    def path_query(x):
        ans = 0
        while head[x] != head[1]:
            val = query(pos[head[x]], pos[x])
            if val > ans:
                ans = val
            x = parent[head[x]]
        val = query(pos[1], pos[x])
        if val > ans:
            ans = val
        return ans

    answer = 0
    for x in a:
        best = 0
        if x != 1:
            best = path_query(parent[x])
        dp = best + 1
        if dp > answer:
            answer = dp
        update(pos[x], dp)

    print(answer)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、ツリーを構築し、重光分解を計算します。 ツリーには次のものを含めることができるため、走査順序は反復的に保存されます。`5 * 10^5`ノード、および再帰的 DFS は Python の再帰制限を超える可能性があります。 

の`size`そして`heavy`配列は、どの子が同じ重鎖に属するかを決定します。 分解では、すべての重鎖が連続した間隔になるように、各ノードに位置が割り当てられます。 

セグメント ツリーには、各種で終わる最適なサブシーケンス長が保存されます。 更新操作では次を使用します。`max`なぜなら、同じ種の後のポケモンは、子孫が利用できる価値を向上させることしかできないからです。 

の`path_query`関数は祖先のクエリに応答します。 クエリを実行する前に、メインループは次のようになります。`parent[x]`、現在の種が考慮から削除されます。 これにより、同じ種間の無効な遷移が防止されます。 

すべての値は最大でも`m`, そのため、Python の整数はそれらを簡単に処理できます。 反復セグメント ツリー操作により、再帰の深さの問題が回避され、実装が必要な制限内に保たれます。

import sys
import io

def solve_data(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())

    children = [[] for _ in range(n + 1)]
    parent = [0] * (n + 1)
    if n > 1:
        for i, p in enumerate(map(int, input().split()), 2):
            parent[i] = p
            children[p].append(i)

    a = list(map(int, input().split()))

    depth = [0] * (n + 1)
    order = [1]
    for x in order:
        for y in children[x]:
            depth[y] = depth[x] + 1
            order.append(y)

    size = [1] * (n + 1)
    heavy = [0] * (n + 1)
    for x in reversed(order):
        best = 0
        for y in children[x]:
            size[x] += size[y]
            if size[y] > best:
                best = size[y]
                heavy[x] = y

    head = [0] * (n + 1)
    pos = [0] * (n + 1)
    cur = 0
    stack = [(1, 1)]
    while stack:
        x, h = stack.pop()
        while x:
            cur += 1
            head[x] = h
            pos[x] = cur
            for y in children[x]:
                if y != heavy[x]:
                    stack.append((y, y))
            x = heavy[x]

    s = 1
    while s < n:
        s *= 2
    seg = [0] * (2 * s)

    def update(i, v):
        i += s - 1
        seg[i] = max(seg[i], v)
        i //= 2
        while i:
            seg[i] = max(seg[2 * i], seg[2 * i + 1])
            i //= 2

    def query(l, r):
        if l > r:
            return 0
        l += s - 1
        r += s - 1
        res = 0
        while l <= r:
            if l & 1:
                res = max(res, seg[l])
                l += 1
            if not r & 1:
                res = max(res, seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

    def get(x):
        res = 0
        while head[x] != head[1]:
            res = max(res, query(pos[head[x]], pos[x]))
            x = parent[head[x]]
        return max(res, query(pos[1], pos[x]))

    ans = 0
    for x in a:
        dp = 1
        if x != 1:
            dp = get(parent[x]) + 1
        ans = max(ans, dp)
        update(pos[x], dp)
    return str(ans) + "\n"
