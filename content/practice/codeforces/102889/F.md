 ## 解決策
 ## 問題の理解

 正の整数の長いシーケンスが与えられます。 シーケンスの最初の部分のみが明示的に提供され、残りは線形再帰を使用して決定論的に生成されます。 この完全なシーケンスを構築した後、2 つの位置を見つける必要があります\(i < j\)後の値が前の値と比較して小さすぎたり大きすぎたりしないようにします。 正式には比率としては、\(a_j / a_i\)一定の間隔内になければなりません\([p, q]\)。 

より使いやすい方法で条件を書き直すと、分割が削除されます。有効なペアの場合、後の要素は次の条件を満たす必要があります。\[
p \cdot a_i \le a_j \le q \cdot a_i.
\]したがって、タスクは、現在の各要素の周囲の乗法ウィンドウに該当する以前の値を見つけることになります。 

シーケンスの長さは非常に長くなる可能性がありますが、明示的に指定されるのは最初の部分だけです。 残りは前の値のみに依存する繰り返しによって生成されます。 これは、配列全体が決定的であり、必要に応じて線形時間で再構築できることを意味します。 

制約は重要なトレードオフを意味します。 すべてのペアにわたる二次スキャンは、中程度のサイズであっても不可能です。\(n\)ステートメントでは最大数千万までになる可能性があります。 \(O(n \log n)\) でさえ、注意しないとタイトになってしまうため、どのソリューションでも効率的な範囲クエリを使用して単一パスで要素を処理する必要があります。 

シーケンスが繰り返しからオンラインで生成されるという事実から、微妙な問題が発生します。 処理を遅らせたり、部分的なデータのみを保存しようとすると、遠く離れたインデックスにまたがる有効なペアが失われる危険があります。 条件は純粋に値ベースですが順序に依存するため、正しいソリューションでは、高速範囲クエリをサポートする方法で以前の値をすべて記憶する構造を維持する必要があります。 

単純な落とし穴は、連続した要素のみ、またはサイズの最初のセグメントのみをチェックすることです。\(m\)。 これは、有効なペアが生成されたサフィックスのどこにでも出現する可能性があり、反復では単調な構造が保持されないため、失敗します。 

## アプローチ

 ブルートフォース戦略は簡単です。完全なシーケンスを生成し、すべてのペア \((i, j)\) をテストします。 各ペアについて、次のことを確認します。\(p \cdot a_i \le a_j \le q \cdot a_i\)。 これは条件を直接検証するため、正しいです。 問題はコストです。\(n\)まで\(3 \cdot 10^7\)、比較の数は次のとおりです。\(10^{14}\)、これは実行可能なランタイムをはるかに超えています。 

重要な観察点は、それぞれの固定値について、\(j\)、以前のすべてのインデックスは気にせず、少なくとも 1 つ存在するかどうかだけを気にします。\(i < j\)その値は特定の間隔内にあります。 これにより、問題が動的な先行構造に変換されます。配列を反復処理する際、以前に確認されたすべての値が維持され、「値は存在しますか?」という形式のクエリがサポートされます。\([a_j / q, a_j / p]\)?」。 

これは、オフラインからオンラインへの古典的な削減です。 値をキーとしたデータ構造を維持しながら左から右にスイープし、各ステップで範囲クエリを実行します。 初めて有効な先行データが見つかったら、すぐにそのペアを出力できます。 

値は小さな範囲に制限されていないため、配列を直接カウントすることはできません。 代わりに、値を圧縮し、値ランクにわたってセグメント ツリー (またはバランスの取れた BST) を維持します。各ノードには、そのセグメント内の値が表示される最小インデックスが格納されます。 これにより、以下のインデックスが存在するかどうかを答えることができます。\(j\)値の範囲内で効率的に調整します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | \(O(n^2)\) | \(O(1)\) | 遅すぎる |
 | 値に対するセグメント ツリー | \(O(n \log n)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定された初期セグメントと繰り返しを使用して完全なシーケンスを生成します。 これが必要なのは、その後のすべての決定が単なる公式表現ではなく実際の値に依存するためです。 

2. すべての値を収集し、ソートされた一意の値の配列に圧縮します。 セグメント ツリーは連続したインデックス スペースで動作するため、圧縮が必要です。 

3. 各位置が圧縮値に対応するセグメント ツリーを構築し、この値がこれまでに出現した最小のインデックスを格納します。 すべてのポジションを空として初期化します。 

4. インデックスを左から右にスイープします。 ポジションごとに\(j\)、値の間隔を決定します\([L, R]\)したがって、有効な先行処理はすべてこの範囲内になければなりません。\[
   L = \left\lceil \frac{a_j}{q} \right\rceil,\quad R = \left\lfloor \frac{a_j}{p} \right\rfloor.
   \]5.変換\([L, R]\)圧縮されたインデックス範囲に格納し、その範囲内に格納されている最小のインデックスをセグメント ツリーにクエリします。 この最小インデックスが存在し、それが以下の場合\(j\)、有効なペアが見つかりました。 

6. 有効な先行データが存在しない場合は、インデックスを使用して現在の値をセグメント ツリーの圧縮位置に挿入します。\(j\)、最も古い発生を保存します。 

7. 有効なクエリが初めて成功すると、対応する \((i, j)\) ペアを出力して終了します。 

### なぜ効果があるのか

 あらゆる段階で\(j\)、セグメント ツリーには、以下のインデックス間で各値の最も古い出現が正確に保存されます。\(j\)。 したがって、有効な\(i\)不等式を満たすものは、クエリされた値の範囲内に表示され、そのインデックスがセグメント ツリーに反映されます。 常に最も古いインデックスを保存するため、有効な候補を見逃すことはありません。また、前の要素のみをクエリするため、順序付けの制約が維持されます。\(i < j\)。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.inf = 10**18
        self.t = [self.inf] * (4 * n)

    def update(self, v, tl, tr, pos, val):
        if tl == tr:
            self.t[v] = min(self.t[v], val)
            return
        tm = (tl + tr) // 2
        if pos <= tm:
            self.update(v*2, tl, tm, pos, val)
        else:
            self.update(v*2+1, tm+1, tr, pos, val)
        self.t[v] = min(self.t[v*2], self.t[v*2+1])

    def query(self, v, tl, tr, l, r):
        if l > r:
            return self.inf
        if l == tl and r == tr:
            return self.t[v]
        tm = (tl + tr) // 2
        return min(
            self.query(v*2, tl, tm, l, min(r, tm)),
            self.query(v*2+1, tm+1, tr, max(l, tm+1), r)
        )

def main():
    n, p, q = map(int, input().split())
    m, b, c, t = map(int, input().split())
    a = list(map(int, input().split()))

    # generate sequence
    a = a[:]
    for i in range(m, n):
        a.append(((b * a[i-1] + c) % t) + 1)

    vals = sorted(set(a))
    comp = {v:i for i, v in enumerate(vals)}
    st = SegTree(len(vals))

    for j, val in enumerate(a):
        L = (val + q - 1) // q
        R = val // p

        # find compressed range
        import bisect
        l = bisect.bisect_left(vals, L)
        r = bisect.bisect_right(vals, R) - 1

        if l <= r:
            i = st.query(1, 0, len(vals)-1, l, r)
            if i < j:
                print(i+1, j+1)
                return

        st.update(1, 0, len(vals)-1, comp[val], j)

    print(-1)

if __name__ == "__main__":
    main()
```この実装では、最初に完全なシーケンスが再構築され、次に範囲クエリがインデックスベースになるように値が圧縮されます。 セグメント ツリーには各値バケットの最小インデックスが格納され、有効な以前の要素が存在するかどうかクエリで正しく検出されるようになります。 

微妙な詳細は、ループ内の操作の順序です。現在の要素を挿入する前にクエリを実行する必要があります。 これにより、厳密な要件が維持されます\(i < j\)。 挿入が先に行われた場合、アルゴリズムにより誤って許可されてしまいます。\(i = j\)。

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    n, p, q = map(int, input().split())
    m, b, c, t = map(int, input().split())
    a = list(map(int, input().split()))

    for i in range(m, n):
        a.append(((b * a[i-1] + c) % t) + 1)

    vals = sorted(set(a))
    comp = {v:i for i, v in enumerate(vals)}

    INF = 10**18
    st = [INF] * (4 * len(vals))

    def update(v, tl, tr, pos, val):
        if tl == tr:
            st[v] = min(st[v], val)
            return
        tm = (tl + tr)//2
        if pos <= tm:
            update(v*2, tl, tm, pos, val)
        else:
            update(v*2+1, tm+1, tr, pos, val)
        st[v] = min(st[v*2], st[v*2+1])

        if l > r:
            return INF
        if l <= tl and tr <= r:
            return st[v]
        tm = (tl + tr)//2

            i = query(1, 0, len(vals)-1, l, r)
            if i < j:
                print(j, i)  # dummy format safety
                return "found"

        update(1, 0, len(vals)-1, comp[val], j)

    return "-1"

 ## 特殊なケース

 まれなケースとしては、すべての値が同一である場合があります。 その状況では、どのペアも自動的に満たされます。\(a_j / a_i = 1\), そのため、最初に繰り返された出現により、すぐに回答がトリガーされるはずです。 最初の挿入でセグメント ツリーにインデックス 0 が配置され、同じ値範囲に対する後続のクエリですぐにインデックス 0 が見つかるため、アルゴリズムはこれを処理します。 

次の場合には、別のエッジケースが発生します。\(p\)大きくて、\(q\)値に比べて小さいため、空の有効間隔が生成されます。 その場合、計算された範囲は\([L, R]\)は無効になり、セグメント ツリー クエリは完全にスキップされます。 アルゴリズムは検索を試行せずに正しく続行されます。 

最後の重要なケースは、有効なペアが、生成されたサフィックス内の遠く離れたインデックスにまたがる場合です。 以前のすべての値をセグメント ツリーに保存し、情報を決して破棄しないため、非常に遅い一致でも検出可能です。
