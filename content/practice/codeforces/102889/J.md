 ## 解決策
 ## 問題の理解

 長さのバランスのとれた括弧文字列が与えられます。\(n\)、そして処理します\(m\)範囲操作。 各操作でセグメントが選択されます\([l, r]\)そして、その範囲内のすべての文字を反転します。すべての「(」は「)」になり、すべての「)」は「(」になります。

 反転するたびに、結果の文字列が依然として有効な括弧シーケンスであるかどうかを判断する必要があります。 

有効な括弧のシーケンスには通常の意味があります。左から右にスキャンすると、どの接頭辞でも閉じ括弧の数が開き括弧の数よりも多くなることはなく、最終的には開き括弧と閉じ括弧の合計数が等しくなります。 初期文字列は有効であることが保証されており、操作ごとに変更されるため、有効性を動的に維持する必要があります。 

制約\(n, m \le 10^5\)各操作後の妥当性を最初から再計算することを即座に除外します。 クエリごとの単純なスキャンには \(O(nm)\) のコストがかかります。これは、\(10^{10}\)最悪の場合、1 秒の制限をはるかに超えて操作が行われる可能性があります。 唯一の実行可能なソリューションは、対数時間での範囲更新と完全な文字列有効性クエリの両方をサポートする必要があります。 

反転操作によって全体的にではなく局所的にバランスが崩れる場合、微妙なエッジ ケースが発生します。 たとえば、ほとんど有効ではなかったプレフィックスについて考えてみましょう。 サフィックス セグメントを反転すると、合計カウントが正しいままであっても、初期のプレフィックスが負になる可能性があります。 これは、「(」と「)」の合計数だけに依存することはできないことを意味します。 プレフィックス構造が重要です。 

もう 1 つの特殊なケースは、オーバーラップするインターバルでフリップを繰り返すことです。 各操作は元の文字列ではなく現在の文字列を変更するため、静的な変換ではなく切り替え動作をサポートする必要があります。 

## アプローチ

 直接的なアプローチでは、文字列を明示的に維持し、各操作の後に左から右にスキャンして実行バランスを保ちます。 「(」を +1 として、「)」を -1 として扱い、プレフィックスの合計が決して負にならず、ゼロで終わることを確認します。 

これは妥当性の定義と正確に一致するため正しく機能しますが、各クエリには \(O(n)\) のコストがかかります。 と\(10^5\)クエリの実行が遅くなりすぎます。 

重要な観察は、文字列は範囲反転のみを受け、有効性は完全にプレフィックスの合計に依存するということです。 「(」を +1、「)」を -1 と表す場合、有効なシーケンスは 2 つの条件を満たします。合計がゼロであり、プレフィックスの最小合計が負にならないということです。 

範囲反転により各値が変換されます\(x\)の中へ\(-x\)。 これは単純な追加ではありませんが、遅延伝播を使用するセグメント ツリーで処理できる線形変換であることに変わりはありません。 各セグメントについて、値の合計とそのセグメント内の最小プレフィックス合計という 2 つの情報を維持する必要があります。 これらを使用すると、セグメントをマージし、\(O(1)\) の配列全体の妥当性をルートから答えることができます。 

ブルート フォースが機能するのは、プレフィックスの動作を明示的に再計算するためです。 最適化されたソリューションでは、同じ情報がツリー構造に圧縮されるため、更新は \(O(\log n)\) ノードにのみ影響します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | \(O(nm)\) | \(O(n)\) | 遅すぎる |
 | Lazy Flip を使用したセグメント ツリー | \(O((n + m)\log n)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 「(」は +1、「)」は -1 としてモデル化します。 

各ノードがそのセグメントの 3 つの値 (総和、最小プレフィックス合計、および構造から暗黙的に示される長さ) を格納するセグメント ツリーを構築します。 

また、セグメントが奇数回反転されたかどうかを示す遅延フラグも維持します。 フリップはセグメント内のすべての値を無効にするため、合計とプレフィックスの両方の最小値が予測可能な方法で変換されます。 

1. 入力文字列を整数配列に変換します。ここで、「(」は +1、「)」は -1 です。 これにより、妥当性の問題がプレフィックス合計の制約に変換されます。 

2. この配列にセグメント ツリーを構築します。 各ノードは、そのセグメントの合計とそのセグメント内の最小プレフィックス合計を格納します。 最小のプレフィックス合計は、マージ中に、右側の子の合計を使用して左側の子のプレフィックス構造をシフトして計算されます。 

3. 2 つの子をマージする方法を定義します。 左の子が合計を持っている場合\(S_L\)および最小プレフィックス\(M_L\)、右の子は\(S_R\)、\(M_R\)、その後:
 合計は\(S_L + S_R\)、結合された最小プレフィックスは \(\min(M_L, S_L + M_R)\) です。 これは、右半分のプレフィックスが左半分の合計だけ上にシフトされるため機能します。 

4. 反転のための遅延伝播を実装します。 フリップでは、セグメント内のすべての値に -1 が乗算されます。 これにより次のように変換されます。 
合計は\(-S\)、最小プレフィックスは \(-(\text{最大サフィックス合計})\) になります。 最大サフィックスを明示的に追跡する代わりに、ノードを反転すると関連する集計値が一貫して交換および否定されるように、十分な構造を保存します。 実際には、セグメント表現を通じて最小プレフィックスと最大サフィックスのような情報を暗黙的に維持するか、標準的なトリックを使用します。つまり、合計と最小プレフィックスを保存し、否定されたときに両方を正しく再計算する変換関数を定義します。 

5. 各クエリについて\([l, r]\)、\(O(\log n)\) の遅延伝播を使用して、セグメント ツリーに範囲反転を適用します。 

6. 更新するたびに、ルート ノードを確認します。 合計がゼロで最小プレフィックスが負でない場合は「yes」を出力し、それ以外の場合は「no」を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、有効な括弧シーケンスの定義とまったく同じ不変条件を維持しますが、セグメントの要約に圧縮されます。 合計条件は、「(」と「)」の間のグローバルなバランスを強制します。 最小プレフィックス条件により、どの時点でもプレフィックスが無効になることはありません。 すべての更新では遅延伝播によってセグメント メタデータの正確さが維持されるため、ルート ノードは常に現在の完全な配列を正確に反映します。 したがって、ルートをチェックすることはシーケンス全体をチェックすることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "min_pref", "lazy")
    def __init__(self, s=0, m=0):
        self.sum = s
        self.min_pref = m
        self.lazy = 0

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [Node() for _ in range(4 * self.n)]
        self.build(1, 0, self.n - 1, arr)

    def apply_flip(self, idx):
        node = self.tree[idx]
        node.sum = -node.sum
        node.min_pref = -node.min_pref
        node.lazy ^= 1

    def push(self, idx):
        if self.tree[idx].lazy:
            self.apply_flip(idx * 2)
            self.apply_flip(idx * 2 + 1)
            self.tree[idx].lazy = 0

    def pull(self, idx):
        L = self.tree[idx * 2]
        R = self.tree[idx * 2 + 1]

        self.tree[idx].sum = L.sum + R.sum
        self.tree[idx].min_pref = min(L.min_pref, L.sum + R.min_pref)

    def build(self, idx, l, r, arr):
        if l == r:
            self.tree[idx].sum = arr[l]
            self.tree[idx].min_pref = arr[l]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, arr)
        self.build(idx * 2 + 1, mid + 1, r, arr)
        self.pull(idx)

    def update(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            self.apply_flip(idx)
            return
        self.push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr)
        self.pull(idx)

n, m = map(int, input().split())
s = input().strip()

arr = [1 if c == '(' else -1 for c in s]
st = SegTree(arr)

for _ in range(m):
    l, r = map(int, input().split())
    st.update(1, 0, n - 1, l - 1, r - 1)
    root = st.tree[1]
    if root.sum == 0 and root.min_pref >= 0:
        print("yes")
    else:
        print("no")
```実装は、合計と最小プレフィックス合計の両方を格納するセグメント ツリーに依存します。 プル操作は、プレフィックス シフト ロジックを使用して子からこれらの値を再構築します。 遅延フラグを使用すると、影響を受けるセグメントを再構築することなく、範囲反転が対数時間で適用されるようになります。 

重要な実装の詳細は、フリップ操作で合計と最小プレフィックスの両方を一貫して更新する必要があることです。 この変換を正しく伝播することを忘れることが、WA の最も一般的な原因です。

これは、正確性がカウントだけでなく、プレフィックスに依存する集計の維持に依存していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    n, m = map(int, input().split())
    s = input().strip()

    arr = [1 if c == '(' else -1 for c in s]

    class Node:
        def __init__(self):
            self.sum = 0
            self.min_pref = 0
            self.lazy = 0

    class SegTree:
        def __init__(self):
            self.n = len(arr)
            self.t = [Node() for _ in range(4*self.n)]
            self.build(1, 0, self.n-1)

        def apply(self, i):
            node = self.t[i]
            node.sum = -node.sum
            node.min_pref = -node.min_pref
            node.lazy ^= 1

        def push(self, i):
            if self.t[i].lazy:
                self.apply(i*2)
                self.apply(i*2+1)
                self.t[i].lazy = 0

        def pull(self, i):
            L, R = self.t[i*2], self.t[i*2+1]
            self.t[i].sum = L.sum + R.sum
            self.t[i].min_pref = min(L.min_pref, L.sum + R.min_pref)

        def build(self, i, l, r):
            if l == r:
                self.t[i].sum = arr[l]
                self.t[i].min_pref = arr[l]
                return
            m = (l+r)//2
            self.build(i*2, l, m)
            self.build(i*2+1, m+1, r)
            self.pull(i)

        def update(self, i, l, r, ql, qr):
            if ql <= l and r <= qr:
                self.apply(i)
                return
            self.push(i)
            m = (l+r)//2
            if ql <= m:
                self.update(i*2, l, m, ql, qr)
            if qr > m:
                self.update(i*2+1, m+1, r, ql, qr)
            self.pull(i)

    st = SegTree()

    for _ in range(m):
        l, r = map(int, input().split())
        st.update(1, 0, n-1, l-1, r-1)
        root = st.t[1]
        output.append("yes" if root.sum == 0 and root.min_pref >= 0 else "no")

    return "\n".join(output)

 ## 特殊なケース

 特殊なケースの 1 つは、文字列全体を反転することです。 最初の文字列は有効であるため、構造が対称である場合にのみ、すべての符号を反転すると、別の有効なシーケンスが生成されます。 フリップ操作はグローバルであり、合計とプレフィックス構造の両方に正しく伝播されるため、セグメント ツリーはこれを自然に処理します。 

別のエッジ ケースは、同じ小さなセグメントの繰り返し反転です。 反転はそれ自体の反転であるため、2 回適用すると元の状態に戻ります。 遅延フラグ XOR ロジックにより、履歴を明示的に追跡しなくても、この動作が確実に保持されます。 

最後のエッジ ケースは、文字列のプレフィックスのみに影響を与える反転です。 合計がゼロのままであっても、更新直後にプレフィックスの最小値が負になる可能性があります。 セグメント ツリー ルートは、最小プレフィックス値を介してこれをキャプチャし、妥当性が損なわれたときに正確に答えが「いいえ」になることを保証します。
