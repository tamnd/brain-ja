 ## 解決策
 ## 問題の理解

 バトルチームには n 匹のポケモンが含まれており、各プレイヤーは 2 匹のポケモンから 1 匹を選択します。 1 つの選択はボーナスの前に 100 の攻撃力に貢献し、もう 1 つの選択肢は 200 の攻撃力に貢献します。 最初の選択肢は特別です。そのようなポケモンはすべて、チーム全体の攻撃力を 1.1 倍にするからです。 特殊ポケモンがt匹いる場合、チーム全体の攻撃力が1.1のt乗倍になる。 

タスクは、最終的な合計攻撃ができるだけ大きくなるように、n 人のプレイヤーのうち何人がブースト ポケモンを選択するかを決定することです。 入力はプレイヤー数のみで、出力は攻撃可能な最大値です。 

n ≤ 50 という制約は非常に小さいです。 これは、チェックできる値が 51 個しかないため、ブーストするポケモンをすべて試してみることに依存する解決策ですでに十分であることを示しています。 より複雑な検索手法は不要であり、主な課題は、大きな入力サイズに合わせて最適化するのではなく、数学的構造を認識することです。 

よくある間違いは、攻撃力 200 のより強力なポケモンを選択することが常に最善であると仮定することです。 たとえば、n = 2 の場合、攻撃力 200 のポケモンを 2 匹選ぶと 400 になりますが、強化ポケモンを 2 匹選ぶと 200 × 1.1² = 242 となり、単体の攻撃力が強い方が勝ちになります。 ただし、n = 10 のような大規模なチームの場合、ブースト ポケモンをすべて選択すると 100 × 10 × 1.1¹⁰ が得られ、攻撃力 200 のポケモンだけを選択するよりも大きくなります。 乗算はすべてのポケモンに影響するため、グローバルボーナスを無視すると間違った答えが得られます。 

もう 1 つのエッジ ケースは、n = 1 です。すべてのポケモンが乗数を受け取るべきかどうかだけをチェックする不注意な実装では、110 が出力される可能性がありますが、正しい選択肢は 100 または 200 であるため、答えは 200 になります。ボーナスは、増加したポケモンの数が低い基本攻撃を補う場合にのみ役立ちます。 

## アプローチ

 直接的なアプローチは、あらゆる数のブースト ポケモンを試してみることです。 固定 t の場合、チームには基本攻撃 100 のポケモンが t 匹、基本攻撃 200 のポケモンが n - t 匹いるため、修正されていない攻撃は 100t + 200(n - t) となり、単純化すると 200n - 100t になります。 チーム全体の乗数を適用した後の最終値は次のようになります。 

100t + 200(n - t) に 1.1^t を掛けます。 

t は 0 から n までの整数のみであるため、最適値を見つけるにはすべての可能性をチェックするだけで十分です。 n が小さいため、この強引な方法が実際には最終的な解決策になります。 最悪の場合、51 回の評価が実行されますが、これは簡単です。 

n がはるかに大きい場合は、より多くの数学的特性を利用する必要があります。 候補者の数が限られているため、総当り攻撃は機能しますが、プレイヤーの数が数百万人に増加すると、その魅力は薄れてしまいます。 ここで、唯一の決定変数はブーストするポケモンの数であるという観察により、問題は 2^n 個のチーム構成の中から選択することから、n + 1 個の可能な数を確認することへと軽減されます。

 ## アルゴリズムのチュートリアル

 1. 最良の回答をゼロに初期化します。 t の考えられるすべての値をこの変数と比較します。 
2. 0 から n までのすべての t を考慮します。t はブーストするポケモンの数を表します。 同じ選択を持つすべてのプレイヤーは同一であるため、どのプレイヤーがそれらを選択したかを知る必要はありません。 
3. 正確にtブーストポケモンが選択されたときのチームの基本攻撃を計算します。 値は 100t + 200(n - t) です。 
4.基本攻撃力に1.1^tを乗算し、すべての強化ポケモンの効果を適用します。 すべての強化ポケモンはチーム全体に影響するため、乗数はすべての基本攻撃を追加した後に適用されます。 
5. これまでに確認された最大値で最良の回答を更新し、すべての選択肢がチェックされた後に結果を出力します。

これが機能する理由: 考えられるすべてのチーム構成は、t の 1 つの値 (ブーストするポケモンの数) によって表されます。 固定 t の場合、個々のプレイヤーの ID は重要ではないため、同じカウントを持つすべての選択肢は同じ攻撃値を生成します。 アルゴリズムは考えられるすべての t を評価するため、検出される最大値は可能な限り最良のチーム攻撃である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = 0.0

    for t in range(n + 1):
        base = 100 * t + 200 * (n - t)
        attack = base * (1.1 ** t)
        if attack > ans:
            ans = attack

    print("{:.15f}".format(ans))

if __name__ == "__main__":
    solve()
```プログラムはプレーヤーの数を読み取り、t のすべての可能な値をテストします。 ループは使用します`range(n + 1)`両極端が重要であるため、t = 0 はすべてのプレイヤーが攻撃力 200 のポケモンを選択することを意味し、t = n は全員が強化ポケモンを選択することを意味します。 

変数`base`マルチプライヤーの前に攻撃を保存します。 答えは必ずしも整数ではないため、乗数は浮動小数点のべき乗で計算されます。 Python の浮動小数点精度は、必要なエラー許容量を十分に満たしています。 

出力では小数点以下 15 桁が使用されます。 これは問題では必須ではありませんが、フォーマットの問題を回避するのに十分な精度が得られます。

## テストケース```python
import sys
import io

def solve_input(data: str) -> str:
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n = int(input())
    ans = 0.0

    for t in range(n + 1):
        base = 100 * t + 200 * (n - t)
        attack = base * (1.1 ** t)
        ans = max(ans, attack)

    return "{:.15f}".format(ans)

def close(a, b):
    return abs(float(a) - b) <= 1e-9

# provided samples
assert close(solve_input("2\n"), 400.000000000000000), "sample 1"
assert close(solve_input("10\n"), 2593.742460100002063), "sample 2"

# custom cases
assert close(solve_input("1\n"), 200.0), "minimum size input"
assert close(solve_input("50\n"), 129687.1230050001), "maximum size input"
assert close(solve_input("3\n"), 600.0), "small case where strong attacks win"
assert close(solve_input("20\n"), 6727.499902672), "case with many multipliers"

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは t = 0 と t = 1 をチェックします。t = 0 の場合、アタックは 200 × 1 = 200 です。t = 1 の場合、アタックは 100 × 1.1 = 110 です。アルゴリズムは 200 を維持し、正しい選択と一致します。 

n = 2 の場合、入力は次のようになります。```
2
```アルゴリズムは t = 0、1、2 を評価します。値はそれぞれ 400、330、242 であるため、最終的な答えは 400 になります。これは、攻撃力 200 のポケモンが追加の乗数を受け取るよりも優れている場合を処理します。 

n = 10 の場合、入力は次のようになります。```
10
```アルゴリズムは 0 から 10 までのすべての値をチェックします。最良の値は t = 10 に表示され、攻撃は 1000 × 1.1¹⁰ = 2593.742460100002063 になります。 これは、十分な数のポケモンが参加すると、グローバル乗数が優位になる可能性があることを裏付けています。 

n = 50 の場合、ループは依然として 51 回の反復のみを実行します。 この実装では、最終計算に浮動小数点値を使用することで整数のオーバーフローが回避されるため、最大制約が安全に処理されます。
