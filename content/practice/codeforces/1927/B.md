 ## 解決策
 ## 問題の理解

 配列が与えられています`a`これは、隠し文字列がどのように構築されたかを説明しています。 

ポジションごとに`i`、値`a[i]`文字がその位置にある回数を教えてくれます`i`はすでに文字列の前の方に現れています。 もし`a[i] = 0`, このキャラクターはこれまでに登場したことがありません。 もし`a[i] = 2`、同じ文字がその位置の前にすでにちょうど 2 回出現しています。`i`。 

私たちのタスクは、トレースが指定された配列と一致する小文字の文字列を再構築することです。 

重要な点は、トレースでは特定の文字が使用されていることは関係ないということです。 考慮するのは、その文字が配置されたときにすでにその文字が以前にどれだけ出現したかだけです。 

すべてのテスト ケースの合計の長さは最大でも`2 · 10^5`したがって、解は線形時間に近いものでなければなりません。 アン`O(n²)`アプローチは大まかに実行します`4 · 10^10`限界をはるかに超えた最悪の場合の操作。 線形または線形に近い解決策が必要です。 

再構築ロジックを慎重に選択しないと、いくつかの状況で間違いが発生する可能性があります。 

考慮する：```
a = [0, 1, 2, 3]
```同じ文字を繰り返し使用する唯一の有効な構文は次のとおりです。```
aaaa
```3 番目の位置には、すでに 3 回登場しているキャラクターが必要です。 新しい文字を選択すると、直ちにトレースに違反します。 

別の例は次のとおりです。```
a = [0, 0, 0, 0]
```有効な答えは次のとおりです。```
abcd
```同じ文字を繰り返し使用するとトレース値が生成される`[0,1,2,3]`その代わり。 

より微妙なケースは次のとおりです。```
a = [0, 0, 1]
```3 番目の文字は、最初の文字ではなく 2 番目の文字と一致する必要があります。 トレースには、直前に 1 回発生したことが必要です。 最初の文字を選択すると、その出現数はすでに 1 になりますが、それを使用すると、トレースは別のコンストラクション ヒストリに対応します。 すべての文字の現在の頻度を注意深く追跡する必要があります。 

このステートメントは、少なくとも 1 つの有効な答えが存在することを保証するため、不可能性を検出する必要はありません。 

## アプローチ

 直接的な総当たりの再構築は容易に想像できます。 

文字列を左から右に処理します。 ポジションについて`i`、からのすべての文字を試してください`'a'`に`'z'`。 各候補文字について、部分的に構築された文字列内でそれが以前に出現した回数を数えます。 そのカウントが等しい場合`a[i]`、文字を配置して続行します。 

これは、トレースの定義を直接確認できるため機能します。 問題は効率です。 構築済みのプレフィックス コストをスキャンして以前の発生をカウントする`O(n)`文字ごとに。 各位置で最大 26 文字をテストすると、複雑さは次のようになります。`O(26·n²)`が遅すぎる`n = 2 · 10^5`。 

トレースの構造により、はるかに単純な解決策が得られます。 

すべての文字の現在の頻度がわかっていると仮定します。 手紙が出てきたら`k`これまでに 2 回配置した場合、今配置するとトレース値が生成されます`k`、まさに`k`以前の出来事はすでに存在します。 

それは位置を意味します`i`現在の頻度が等しい文字のみが必要です`a[i]`。 

小文字は 26 個しかないため、各文字の頻度を維持し、その数が一致する文字を検索できます。`a[i]`。 それを選択した後、その頻度を 1 つ増やします。 

このステートメントは有効な回答が存在することを保証するため、そのようなレターは常に利用可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(26・n) = O(n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`cnt`サイズは 26、ゼロで初期化されます。`cnt[j]`文字を何回保存するか`j`すでに使用されています。 
2. トレースを左から右に処理します。 
3. 現在値について`a[i]`、現在の頻度が以下に等しい文字を検索します。`a[i]`。 
4. その文字を応答文字列に追加します。 
5. もう一度出現したので、その文字の頻度を 1 つ増やします。 
6. すべての位置が処理されるまで続行します。 
7. 構築された文字列を出力します。 

ステップ 3 の検索では最大 26 文字がチェックされますが、これは事実上一定時間です。 

### なぜ効果があるのか

 あらゆる瞬間に、`cnt[c]`文字の出現数に等しい`c`すでにプレフィックスに配置されています。 

現在の周波数が であるキャラクターを配置すると、`k`、 その通り`k`その文字のコピーは、現在の位置より前に存在します。 定義上、この位置で生成されるトレース値は次のようになります。`k`。 

アルゴリズムは常に、頻度が必要な値と等しい文字を選択します。`a[i]`、したがって、位置で生成されたトレース`i`まさに正しいです。 

文字を配置した後、その頻度は 1 つ増加し、将来の位置に対して不変式が保存されます。 入力は有効な文字列からのものであることが保証されているため、適切な文字が常に存在します。 したがって、すべての位置が正しく構築され、最終的な文字列には必要なトレースが正確に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * 26
        ans = []

        for x in a:
            for j in range(26):
                if cnt[j] == x:
                    ans.append(chr(ord('a') + j))
                    cnt[j] += 1
                    break

        print("".join(ans))

solve()
```配列`cnt`すべての小文字の現在の出現数を保存します。 各トレース値について`x`、頻度が正確に一致する文字を検索します。`x`。 

そのような文字が見つかると、それを回答に追加し、その頻度を増やします。 不変条件は、位置を処理する前に、`cnt[j]`文字の出現数に等しい`j`構築されたプレフィックスにすでに存在します。 

よくある間違いは、最後に使用した文字だけ、または以前に登場した文字だけを追跡しようとすることです。 トレースは正確な出現数に依存するため、26 個の周波数すべてを維持する必要があります。 

もう 1 つの微妙な点は、操作の順序です。 比較しなければなりません`cnt[j]`と`x`増やす前に。 最初にインクリメントすると、すべてのトレース値が 1 ずつシフトされ、不正確な結果が生成されます。

import io

 ## 特殊なケース

 次のことを考慮してください。```
n = 1
a = [0]
```最初はすべての文字の頻度が 0 です。アルゴリズムは`'a'`、カウントを 1 に増やし、次を出力します。```
a
```その痕跡は、`[0]`、それは正しいです。 

次に、次のことを考えてみましょう。```
n = 4
a = [0, 0, 0, 0]
```周波数は次のように始まります。```
a:0 b:0 c:0 d:0 ...
```アルゴリズムは、カウントが 0 である最初の文字を繰り返し選択します。`'a'`、そのカウントは 1 になるため、次に使用可能なカウント 0 の文字は次のようになります。`'b'`、 それから`'c'`、 それから`'d'`。 

結果は次のとおりです。```
abcd
```すべての位置は最初の出現に対応し、トレースと正確に一致します。 

最後に次のことを考慮してください。```
n = 3
a = [0, 0, 1]
```最初の 2 つの位置を処理した後、次のようになります。```
string = "ab"
counts = {a:1, b:1}
```必要なトレース値は 1 になりました。頻度 1 の最初の文字は次のとおりです。`'a'`したがって、アルゴリズムは次のように出力します。```
aba
```トレースは次のようになります。```
[0, 0, 1]
```これは入力と一致します。 この例は、正確な周波数を追跡する必要がある理由を示しています。 決定は、文字が以前に出現したかどうかではなく、現在の出現回数に依存します。
