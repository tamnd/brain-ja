 ## 解決策
 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、および偶数の整数`k`。 正確に選択する必要があります`k/2`選択された要素のマルチセットに **からのすべての整数が含まれるように、各配列の要素を配置します。`1`に`k`**。 要素を選択する順序は重要ではありません。 重要なのは全範囲をカバーすることです`[1, k]`。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは配列の長さを指定します。`n`そして`m`、配列自体、および の値`k`。 出力は、選択が可能かどうかに応じて、単純な「YES」または「NO」です。 

制約は適度ですが重要です。`n`そして`m`まで可能です`2 * 10^5`個別に、すべてのテスト ケースの合計が次を超えない`4 * 10^5`。 これにより、サイズの**考えられるすべてのサブセット**を検査するアプローチは除外されます。`k/2`どちらの配列でも、サブセットの数は組み合わせによって増加するためです。 代わりに、各アレイを線形またはほぼ線形にスキャンできるソリューションが必要です。 の値`k`は常に均等であり、満足します`k <= 2 * min(n, m)`を選択することを保証します。`k/2`各配列の要素は、カウントの観点から常に実現可能です。 

エッジケースは微妙です。 1 つは、配列に繰り返し要素が含まれている場合です。 たとえば、次の場合`k=4`、`a=[1,1,1,1]`そして`b=[2,3,4]`、私たちが選択できるのは`1`から`a`(必要な数だけ追加できますが、重複すると新しい番号はカバーされません)、カバレッジ要件を満たすことができないため、答えは「いいえ」です。 もう一つのケースは次のような場合です。`k/2`は配列の長さに等しいため、そこにあるすべての要素を選択する必要があります。 他の配列が残りの数値をカバーできるかどうかを確認する必要があります。 これらのニュアンスを無視すると、微妙な間違いが発生します。 

## アプローチ

 素朴なアプローチは強引です。 サイズのすべてのサブセットを列挙することができます`k/2`から`a`サイズのすべてのサブセット`k/2`から`b`、次に、それらの共用体が以下のすべての数値をカバーしているかどうかを確認します。`1`に`k`。 これは理論的には機能しますが、複雑さは次のとおりです。`O(n choose k/2 * m choose k/2 * k)`、これは不可能です`n, m`まで`2*10^5`。 

重要な洞察は、特定のサブセットは気にせず、**どの数値が存在する**だけを気にするということです。 各配列は、複数の重複がある場合でも、カバレッジに数値を提供できるのは 1 回だけです。 したがって、各配列を ** 以下の数値のセットとして扱うことができます。`k`**。 次に、問題は、最大でも選択できるかどうかを確認することになります。`k/2`各セットの要素をすべて網羅しながら、`1..k`。 

実際には、次からいくつの数値を計算するだけで済みます。`1..k`が各配列に存在します。 させて`count_in_a`の数字の数になります`1..k`に登場する`a`、同様に`count_in_b`のために`b`。 もし`count_in_a > k/2`、私たちは選ぶことしかできません`k/2`からの数字`a`なので、事実上、カバーされる数値の数は次のようになります。`a`は`min(count_in_a, k/2)`。 同様に、`b`。 次に、問題は、これらの寄与の合計が少なくとも`k`。 そうであれば、有効な選択が存在します。 それ以外の場合は、そうではありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n は k/2 を選択) * (m は k/2 を選択) * k) | O(k) | 遅すぎる |
 | 最適 | テスト ケースごとに O(n + m + k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、`k`そして配列`a`そして`b`。 
3. 2 つのブール配列 (またはセット) を初期化します。`present_a`そして`present_b`長さの`k+1`どの番号を追跡するか`1..k`に登場する`a`そして`b`それぞれ。 
4. の各数字について`a`、間の場合`1`そして`k`、存在するものとしてマークします`present_a`。 
5. 繰り返します`b`、マーキング`present_b`。 
6. の数を数えます`1..k`各配列に表示されるものは次のとおりです。`count_in_a`の合計です`present_a[1..k]`、 そして`count_in_b`の合計です`present_b[1..k]`。 
7. 各配列の実効寄与を計算します。`contrib_a = min(count_in_a, k/2)`、`contrib_b = min(count_in_b, k/2)`。 
8. もし`contrib_a + contrib_b >= k`、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

**これが機能する理由:** 不変条件は、各配列が最大で寄与できるということです。`k/2`カバレッジの数値。 存在する実際の数を数えて、その上限を設定することにより、`k/2`、各アレイが提供できる最大カバレッジをシミュレートします。 合計の補償範囲が次の範囲に達した場合`k`、次に有効な選択`k/2`各配列の要素が存在します。 そうでなければ不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    present_a = [0] * (k + 1)
    present_b = [0] * (k + 1)
    
    for x in a:
        if 1 <= x <= k:
            present_a[x] = 1
    for x in b:
        if 1 <= x <= k:
            present_b[x] = 1
    
    count_in_a = sum(present_a[1:])
    count_in_b = sum(present_b[1:])
    
    contrib_a = min(count_in_a, k // 2)
    contrib_b = min(count_in_b, k // 2)
    
    print("YES" if contrib_a + contrib_b >= k else "NO")
```このソリューションは入力を効率的に読み取り、ブール配列を使用して利用可能な数値を追跡します。 の使用`min(count, k//2)`これにより、各配列から選択できる要素の数の制限が確実に遵守されます。 外側の数値は無視されるため、プレゼンス配列の合計は安全です`1..k`。 これにより、off-by-one エラーが回避されます。
