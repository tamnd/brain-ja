 ## 解決策
 ## 問題の理解

 以下の数値の順列を構築する必要があります。`1`に`n`連続するすべての長さのセグメントが`k`ほぼ同じ金額になります。 より正確には、長さの各ウィンドウの合計を計算すると、`k`、それらの合計の最大値と最小値は最大で異なる場合があります。`1`。 

タスクは、順列が有効かどうかをチェックすることではありません。 すべてのテスト ケースに対して明示的に 1 つを構築する必要があります。 

制約が大きすぎるため、順列を検索できません。 の合計値`n`すべてのテスト ケースで最大でも`2·10^5`したがって、受け入れられる解決策は、合計入力サイズがほぼ線形である必要があります。 Anything quadratic would perform about`4·10^10`限界をはるかに超えた最悪の場合の操作。 

この問題の最も危険な部分は、すべての引き違い窓がこの状態に関係していることです。 全体的にバランスが取れているように見える順列でも、隣接するウィンドウの合計間に大きな変動が生じる可能性があります。 

考慮する`n = 6, k = 2`。 

順列```
1 2 3 4 5 6
```ウィンドウ合計を生成します```
3 5 7 9 11
```最大値と最小値の差は、`8`, したがって、それは有効とは程遠いです。 

もう一つの微妙なケースは次のような場合です。`k = n`。 この場合、ウィンドウは 1 つだけ、つまり順列全体だけになります。 ウィンドウの最大値と最小値の合計が等しいため、すべての順列は自動的に有効になります。 ここでは、誤って複数のウィンドウの存在に依存した構造が依然として機能するはずです。 

例えば：```
n = 4, k = 4
```順列```
1 2 3 4
```ウィンドウ合計は 1 つだけなので、すでに有効です。`10`。 

3 番目のトラップは、最後の不完全なグループを処理します。`n`で割り切れない`k`。 最後のグループに含まれる内容が`k`ポジション。 

例えば：```
n = 7, k = 4
```最後の残基クラスには位置が 1 つだけ含まれます。 すべてのグループのサイズが等しいと仮定するスキームは失敗します。 

## アプローチ

 強引なアイデアは、順列を生成し、それらが条件を満たすかどうかをチェックすることです。 単一の順列のチェックは次のように実行できます。`O(n)`スライディングウィンドウを使用した時間。 残念ながら、`n!`順列。 たとえ`n = 10`、これはすでに何百万もの候補者を意味します。 探索空間はほぼ即座に不可能になります。 

重要な観察は、隣接するウィンドウの合計を比較することで得られます。 

させて```
s(i) = p[i] + p[i+1] + ... + p[i+k-1]
```それから```
s(i+1) - s(i) = p[i+k] - p[i]
```2つのウィンドウが共有しているため、`k-1`要素。 

もし作ることができたら`p[i+k] - p[i]`小さな正の値と小さな負の値を交互に繰り返すと、すべてのウィンドウの合計が非常に近くに留まります。 

これは、インデックスモジュロによってポジションを調べることを示唆しています`k`。 

固定剰余クラスの場合```
r, r+k, r+2k, ...
```隣接するウィンドウの合計間のすべての差は、そのようなチェーン内の連続する要素から生じます。 

公式の構造では、各剰余クラスのモジュロに個別に番号が割り当てられます。`k`。 

以来`k`が偶数であれば、分割できます`k`剰余クラスを 2 つに分割します。 

偶数のインデックスを持つ剰余クラスの場合、現在未使用の最小の番号を昇順に位置に埋めます。 

奇数のインデックスを持つ剰余クラスの場合は、現在未使用の最大の番号で降順に位置を埋めます。 

これにより、低い列と高い列が交互に作成されます。 スライディング ウィンドウが 1 ステップ移動すると、出ていく要素と入ってくる要素は、数値範囲の両端から値が割り当てられた隣接する剰余クラスから来ます。 結果として得られるウィンドウの合計は同じ値を中心に変動し、その差が超えることはありません。`1`。 

この構造は純粋に決定論的であり、すべての数値を 1 回だけ使用します。

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`p`長さの`n`。 
2. 2 つのポインタを維持します。`L = 1`、未使用の最小数。`R = n`、未使用の最大数。 
3. 残差クラスを反復処理する`r = 0, 1, ..., k-1`。 
4. この残基クラスに属するすべての位置を収集します。```
r, r+k, r+2k, ...
```5. もし`r`が偶数の場合、以下の位置に値を割り当てます。`L`上向きに。 

すべての割り当てでは、現在最も小さい未使用の数値が使用され、増分されます。`L`。 
6. もし`r`奇数である場合は、次の位置に値を割り当てます。`R`下向きに。 

すべての割り当てでは、現在使用されていない最大の数値が使用され、デクリメントされます。`R`。 
7. すべての剰余クラスを処理した後、次のすべての数値が`1`に`n`ちょうど 1 回使用されているため、`p`は順列です。 
8. 順列を出力します。 

### なぜ効果があるのか

 ポジションは次のように分割されます`k`剰余クラスのモジュロ`k`。 すべてのクラスは値の単調シーケンスを受け取ります。 偶数インデックスのクラスは小さな値を受け取り、奇数インデックスのクラスは大きな値を受け取ります。 

ウィンドウが 1 位置移動すると、1 つの要素が去り、別の要素が入ります。 これら 2 つの位置は、ウィンドウの移動によって引き起こされる巡回順序付けにおける隣接する剰余クラスに属します。 隣接する剰余クラスは残りの値の範囲の両端から埋められているため、ゲインと損失はほぼ相殺されます。 

正式な分析では、すべてのウィンドウ合計が他のウィンドウ合計と最大で異なることが示されています。`1`。 これはまさに社説で証明された特性であり、この交互の低-高割り当てが選択される理由です。 からの各整数なので、`1`に`n`が 1 回だけ割り当てられると、結果は有効な順列となり、必要なバランス条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())

        p = [0] * n
        low = 1
        high = n

        for r in range(k):
            pos = list(range(r, n, k))

            if r % 2 == 0:
                for idx in pos:
                    p[idx] = low
                    low += 1
            else:
                for idx in pos:
                    p[idx] = high
                    high -= 1

        ans.append(" ".join(map(str, p)))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列`p`最終的な順列を保存します。 

ループオーバー`r`1 つの剰余クラスのモジュロを処理します`k`一度に。 すべての位置は正確に 1 つの残基クラスに属するため、各位置は正確に 1 回割り当てられます。 

変数`low`そして`high`未使用の最小値と最大値を追跡します。 偶数の剰余クラスは下位からの数値を消費しますが、奇数の剰余クラスは上位からの数値を消費します。 

よくある実装の間違いは、残基クラスごとではなく位置ごとに交互に配置することです。 バランスの議論は、モジュロ クラス全体が一貫して割り当てられることに依存します。 もう 1 つの間違いは、パリティ チェックで 1 から始まる剰余インデックスを使用することです。 この構築では、剰余クラスが次のように処理されることを前提としています。`0,1,2,...,k-1`。 

特別な処理は必要ありません。`n`で割り切れない`k`。 表現`range(r, n, k)`は自動的に正しい位置を生成し、一部のクラスには他のクラスよりも 1 つ多くの要素が含まれているだけです。
