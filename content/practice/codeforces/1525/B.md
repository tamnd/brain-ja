 ## 解決策
 ## 問題の理解

 からの数値の順列が与えられます。`1`に`n`。 1 回の操作で、配列の任意の連続セグメントを選択し、そのセグメント内の要素を好きなように再配置できます。 唯一の制限は、選択したセグメントを配列全体にすることはできないことです。 

目標は、並べ替えを並べ替えられた順序に変換するために必要なこのような操作の最小数を決定することです。`[1, 2, ..., n]`。 

重要な点は、選択したセグメントの再配置が非常に強力であるということです。 スワップやリバーサルに限定されません。 セグメントを選択すると、そのコンテンツを任意の順序で配置できます。 唯一の制限は、セグメントがすべてをカバーできないという事実から生じます。`n`ポジション。 

制約は非常に小さいです。 配列の長さが 50 を超えることはなく、テスト ケースの数は最大 2000 です。 高価な計算も快適に行えます。 それでも、この問題は、動作のシミュレーションではなく、単純な構造の観察を発見することを中心に設計されています。 

いくつかの特殊なケースは見落とされがちです。 

すでにソート済みの順列を考えてみましょう。```
1 2 3 4
```答えは`0`、 ない`1`。 作業は必要ないため、何らかの操作を適用しても配列のソートが低下するだけです。 

考慮する：```
2 1 3 4
```答えは`1`。 不注意な解決策では、最初の要素が間違っているため、複数の操作が必要であると考える可能性があります。 実はポジションを選べるのです`[1,2]`そしてそれらを並べ替えます。 

より微妙なケースは次のとおりです。```
4 2 3 1
```ここでは最初の要素はそうではありません`1`最後の要素はそうではありません`n`。 答えは`3`。 多くのソリューションが誤って返されます`2`。 その理由は、両端が間違った位置にあり、両端に属する値も間違った場所に閉じ込められているためです。 これは、3 つの操作を必要とする特殊な状況であることがわかります。 

## アプローチ

 ブルートフォースの観点は、考えられるすべてのセグメントと、それらのセグメントの考えられるすべての並べ替えを考えることです。 セグメントは任意に再配置できるため、分岐要素は膨大です。 たとえ`n = 50`、可能な状態を列挙することは完全に不可能です。 

この問題の興味深い部分は、操作を構築するように求められていないことです。 必要なのは最小限の数だけです。 これは、答えを探すのではなく、答えの特徴を探すことを示唆しています。 

重要な観察は、答えは次のとおりであるということです。`0`、`1`、`2`、 または`3`。 

順列がすでにソートされている場合、答えは明らかに次のようになります。`0`。 

順列がソートされていないと仮定します。 最初の位置にすでに次のものが含まれている場合、`1`または最後の位置にすでに含まれています`n`であれば、1回の操作で十分です。 配列の残りの部分を選択して、正しい順序に並べ替えることができます。 

例えば：```
1 4 3 2
```最初の位置はすでに正しいです。 ポジションを選択できます`[2,4]`そしてそれらを並べ替えます。 

次に、どちらの端も正しくない場合を考えてみましょう。 

値が`1`現在、最後の位置と値にあります`n`が現在最初の位置にある場合、答えは`3`。 これは、エンドポイントの考えられる最悪の配置です。 配列全体が禁止されており、一方の側を修正してももう一方の側も自動的に修正されないため、単一の操作で両端を同時に操作することはできません。 

残りのすべてのケースの答えは次のとおりです。`2`。 どちらのエンドポイントもすでに正しくありませんが、順列は特別な最悪の場合の構成ではありません。 

これにより、いくつかのエンドポイント チェックから答えが完全に決定されます。

 ## アルゴリズムのチュートリアル

 1. 順列を読み取ります。 
2. 順列がすでにソートされているかどうかを確認します。 

どのポジションでも`i`含まれています`i + 1`、操作は必要ないので出力します。`0`。 
3. 最初の要素が`1`または最後の要素は`n`。 

どちらかの条件が成立した場合に出力`1`。 

その理由は、配列の残りの部分が適切なサブ配列を形成し、ソートを完了するために自由に再配置できるためです。 
4. 最初の要素が`n`そして最後の要素は`1`。 

両方の条件が成立する場合、出力`3`。 

これは、最大数の操作を必要とする独自の構成です。 
5. それ以外の場合は出力`2`。 

どちらのエンドポイントもすでに正しいわけではありませんが、配置は最悪のものではないため、常に 2 回の操作で十分です。 

### なぜ効果があるのか

 問題全体はエンドポイントによって制御されます。 

配列がすでにソートされている場合、答えは次のようになります。`0`。 

1 つの端点がすでに正しい場合、残りの位置は有効な適切な部分配列を形成します。 選択した部分配列を任意に再配置できるため、1 回の操作で十分です。 

両方のエンドポイントが正しくない場合、1 回の操作で順列を並べ替えることはできません。 適切なサブ配列では少なくとも 1 つの端点が欠落しているため、少なくとも 1 つの間違った端点が残ることになります。 

その中で、との取り決めは、`n`初めにそして`1`最後が一番難しいです。 配列全体が選択されない可能性があるため、誤って配置された両方の極値を修正することは 2 回の操作だけでは実行できません。 公式分析によると、この構成には正確に 3 つの操作が必要です。 

ソートされていない他のすべての順列は残りのカテゴリに分類され、2 つの操作で修正できます。 

これらのケースは相互に排他的であり、すべての順列をカバーするため、アルゴリズムは常に正しい最小数の演算を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if a == list(range(1, n + 1)):
            print(0)
        elif a[0] == 1 or a[-1] == n:
            print(1)
        elif a[0] == n and a[-1] == 1:
            print(3)
        else:
            print(2)

solve()
```最初の条件は、順列がすでにソートされているかどうかをチェックします。 これはエンドポイント ロジックの前に処理する必要があります。それ以外の場合は、次のような並べ替えられた順列が処理されます。`[1,2,3]`2 番目のケースと誤って一致し、返されます`1`。 

2 番目の条件は、1 回の操作で十分な状況を検出します。 すでに正しいエンドポイントが 1 つだけあれば十分です。 

3 番目の条件は、固有の最悪の場合の配置を特定します。 との順列があるため、前の条件の後にチェックする必要があります。`a[0] = n`そして`a[n-1] = 1`いずれにせよ、ワンオペレーション条件を満たすことはできません。 

残りのすべての順列は 2 操作カテゴリに属します。 

小さいものには特別な取り扱いはありません`n`が必要です。 ロジックはすべての有効な入力に対して均一に機能します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    out = []

    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if a == list(range(1, n + 1)):
            out.append("0")
        elif a[0] == 1 or a[-1] == n:
            out.append("1")
        elif a[0] == n and a[-1] == 1:
            out.append("3")
        else:
            out.append("2")

    return "\n".join(out) + "\n"

# provided samples
assert run(
"""3
4
1 3 2 4
3
1 2 3
5
2 1 4 5 3
"""
) == "1\n0\n2\n", "sample"

# already sorted
assert run(
"""1
3
1 2 3
"""
) == "0\n"

# first element correct
assert run(
"""1
5
1 5 4 3 2
"""
) == "1\n"

# last element correct
assert run(
"""1
5
2 5 4 1 5
"""
) != "1\n"  # not a valid permutation, avoid using

assert run(
"""1
5
2 1 3 4 5
"""
) == "1\n"

# worst case
assert run(
"""1
5
5 2 3 4 1
"""
) == "3\n"

# generic two-operation case
assert run(
"""1
5
2 1 4 5 3
"""
) == "2\n"

 ## 特殊なケース

 すでにソートされた順列を考えてみましょう。```
1
3
1 2 3
```アルゴリズムは最初に配列全体が以下に等しいかどうかをチェックします。`[1,2,3]`。 それはそうなので、答えは次のとおりです`0`。 これにより、配列が 1 操作の場合に誤って一致するのを防ぎます。 

考慮する：```
1
4
1 4 3 2
```配列はソートされていませんが、最初の要素はすでにソートされています`1`。 アルゴリズムは戻ります`1`。 部分配列をソートできます`[4,3,2]`それは適切な部分配列であるため、直接。 

考慮する：```
1
4
4 2 3 1
```配列はソートされていません。 どちらのエンドポイントも正しくありません。 最初の要素は次と等しい`n`最後の要素は以下に等しい`1`、したがってアルゴリズムは戻ります`3`。 これはまさに、証明によって特定された特別な最悪の場合の構成です。 

考慮する：```
1
5
2 3 1 5 4
```配列はソートされていません。 どちらのエンドポイントも正しくありませんが、最悪の場合の配置ではありません。 アルゴリズムは最後の分岐に到達して戻ります。`2`、これはこのカテゴリの最小操作数です。
