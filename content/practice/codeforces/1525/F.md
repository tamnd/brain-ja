 ## 解決策
 ## 問題の理解

 都市は有向非巡回グラフです。 この声明は、ゴブリンが一度ホールから出たら二度と戻ってこないことを保証しており、これがまさに DAG の定義です。 

ウェーブ中`i`、 その通り`i`ゴブリンが現れる。 各ゴブリンは方向性のある道を選択します。 異なるゴブリンが同じホールを訪れることはできません。 ゴブリンは協力して、できるだけ多くのホールをカバーする頂点の切り離されたパスの集合を選択します。 

ゴブリンがグラフのすべてのホールを略奪できる場合、Monocarp はウェーブを失います。 

ウェーブの前に、Monocarp は頂点のすべての入力エッジまたは頂点のすべての出力エッジを永続的に無効にすることがあります。 このような操作にはそれぞれ 1 分かかります。 ブロックされたトンネルは永久にブロックされたままになるため、時間の経過とともにグラフは弱くなるだけです。 

ウェーブのスコア`i`前のウェーブの後とこのウェーブの前に実行されたブロック操作の数によって異なります。 もし`t_i`操作がその間隔で実行されると、スコアの貢献度は次のようになります。$$\max(0, x_i - t_i y_i).$$このタスクは、最大スコアを計算するだけでなく、ブロック操作とウェーブ コールの実際のシーケンスを出力することも行います。 

グラフには最大 50 個の頂点が含まれます。 それが決定的な制約です。 最大値の一致を繰り返すことを伴う解決策は、完全に現実的です。 一方、指数関数的な状態空間は、`n`不可能です。 

最も危険な間違いは、個々のゴブリンの動きについて考えることです。 可能なパス システムの数は膨大です。 正しい観点は、攻撃全体を DAG 上のパス カバー問題に変換することです。 

頂点を持つ DAG を検討してください`1 -> 2 -> 3`。 

波用`1`、単一のゴブリンが 3 つの頂点すべてを通過できるため、Monocarp は負けます。 

波用`0`これは不可能でしょう。 

決定的な量は、特定の開始頂点からの到達可能性ではなく、すべての頂点をカバーするために必要な頂点に分離されたパスの最小数です。 

もう 1 つの微妙なケースは、グラフですべての頂点をカバーするためにすでに多くのパスが必要な場合です。```
1    2    3    4
```エッジは存在しません。 

パス カバーの最小サイズは次のとおりです。`4`。 たとえブロック作戦を行わなかったとしても、ゴブリンが 2 匹しかいないウェーブではすべてのホールをカバーすることはできません。 

何らかの準備が常に必要であると想定する解決策は間違っています。 

## アプローチ

 攻撃自体から始めます。 

グラフが固定されているとします。 ゴブリンが選ぶ`i`頂点を切り離して有向パスを作成し、カバーされる頂点の数を最大化します。 

古典的な DAG の事実によれば、カバーされる頂点の最大数は最大でも`i`頂点の結合されていないパスが等しい`n`まさに、DAG が最大で次のサイズのパス カバーを許可するときです`i`。 

させて`pc`現在の DAG の最小パス カバー サイズを示します。 

そうすれば、次の場合にすべての頂点を略奪できます。`i ≥ pc`。 

つまりMonocarpは波を生き延びる`i`もし$$pc > i.$$これにより、ゲームは直ちにパスカバーのメンテナンスの問題に変わります。 

DAG の場合、$$pc = n - M,$$どこ`M`標準の DAG 2 部構造における最大マッチング サイズです。 

こうして波は生き残る`i`と同等です$$M \le n-i-1.$$次に、ブロック操作を見てみましょう。 

DAG パス カバー用の通常の 2 部グラフを作成します。 元の頂点はすべて、左側に 1 回、右側に 1 回ずつ表示されます。 

頂点から出るすべてのエッジをブロックする`v`の左側のコピーを削除します`v`。 

頂点のすべての入力エッジをブロックする`v`の正しいコピーを削除します`v`。 

したがって、許可されるすべての操作は、2 部グラフからの 1 つの頂点の単純な削除です。 

強引なアイデアは、`2n`削除の可能性を確認し、最大一致がどのように変化するかを判断します。 と`n = 50`、これは絶望的です。 

重要な観察ははるかに強力です。 

現在の最大一致サイズが正であると仮定します。 

ケーニッヒの定理により、すべての最大マッチングには同じサイズの最小頂点カバーが含まれます。 最小頂点カバーに属する頂点はすべて削除でき、削除後は最大一致サイズが 1 つだけ減少します。 

つまり、削除によって一致が 1 つ減少する頂点を繰り返し見つけることができます。 

元の一致サイズの場合`F`、シーケンスを構築できます$$v_1,v_2,\dots,v_F$$最初のものを削除した後、`t`シーケンスの頂点の一致するサイズが正確になります`F-t`。 

このようなシーケンスが存在すると、問題のグラフ部分は終了します。 

残りのタスクはスケジュール設定です。 

させて`j`ウェーブの前にすでに実行された削除の数になります。 

次に、一致するサイズは次のようになります`F-j`。 

波`i`安全であれば$$F-j \le n-i-1.$$これで、1 次元の DP だけが残ります。 

州`dp[i][j]`最初の処理後の最大スコアを意味します`i`波と正確なパフォーマンス`j`合計で削除。 

トランジションは、wave の前に追加の削除が挿入される数を決定します。`i`。 

グラフ構造は DP から完全に消えます。 実行された削除の数のみが重要です。

### なぜ効果があるのか

 DAG 攻撃条件は、すべての頂点を最大でカバーできるかどうかを尋ねることと同じです。`i`頂点が分離されたパス。 最小パス カバーは、これを最大一致条件に変換します。 

各ブロッキング操作は、パス カバーの 2 部グラフ内の 1 つの頂点を正確に削除します。 

マッチングが正の場合は常に、最小頂点カバーから頂点を削除してマッチングを 1 つ減らすことができるため、削除シーケンスは有効です。 このプロセスを繰り返すと、最初のシーケンスが作成されます。`t`削除により常に一致が正確に減少します`t`。 

その後、関連する数量は、すでに実行された削除の数だけになります。 DP は、各削除を実行する実行可能なすべての瞬間を列挙し、最大の合計スコアを持つスケジュールを選択します。 すべての有効な戦略は 1 つの DP パスに対応し、すべての DP パスは有効な戦略に対応するため、最適な戦略が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 30

n, m, K = map(int, input().split())
edges = [tuple(map(int, input().split())) for _ in range(m)]
xy = [tuple(map(int, input().split())) for _ in range(K)]

alive = [True] * (2 * n)

def max_matching():
    g = [[] for _ in range(n)]

    for u, v in edges:
        if alive[u - 1] and alive[n + v - 1]:
            g[u - 1].append(v - 1)

    match_r = [-1] * n

    def dfs(v, vis):
        for to in g[v]:
            if vis[to]:
                continue
            vis[to] = True
            if match_r[to] == -1 or dfs(match_r[to], vis):
                match_r[to] = v
                return True
        return False

    res = 0
    for v in range(n):
        if not alive[v]:
            continue
        vis = [False] * n
        if dfs(v, vis):
            res += 1
    return res

F = max_matching()

deleted_order = []

for step in range(1, F + 1):
    target = F - step
    for v in range(2 * n):
        if not alive[v]:
            continue

        alive[v] = False
        if max_matching() == target:
            deleted_order.append(v)
            break
        alive[v] = True

dp = [[-INF] * (F + 1) for _ in range(K + 1)]
par = [[-1] * (F + 1) for _ in range(K + 1)]

dp[0][0] = 0

for i in range(1, K + 1):
    x, y = xy[i - 1]

    for j in range(F + 1):
        if F - j > n - i - 1:
            continue

        for k in range(j + 1):
            if dp[i - 1][k] <= -INF:
                continue

            gain = x - y * (j - k)
            if gain < 0:
                gain = 0

            cand = dp[i - 1][k] + gain

            if cand > dp[i][j]:
                dp[i][j] = cand
                par[i][j] = k

best_j = max(range(F + 1), key=lambda j: dp[K][j])

actions = []

cur_j = best_j

for i in range(K, 0, -1):
    prev_j = par[i][cur_j]

    actions.append(0)

    for t in range(cur_j, prev_j, -1):
        idx = deleted_order[t - 1]

        if idx < n:
            actions.append(idx + 1)
        else:
            actions.append(-(idx - n + 1))

    cur_j = prev_j

actions.reverse()

print(len(actions))
print(*actions)
```マッチング ルーチンは標準の Kuhn アルゴリズムです。 各辺の頂点が 50 個しかないため、マッチングを何度も再計算するコストは低くなります。 

欠失配列の構築は最も珍しい部分です。 頂点は、削除によって一致が 1 だけ減少する場合にのみ受け入れられます。 承認されると、削除は永続的なものとなり、次の検索は小さい方のグラフから続行されます。 

DP 寸法は初期一致サイズによって制限されます`F`、最大でも`n-1`。 すべての状態は、すでに実行された特定の削除数を表します。 

再構築フェーズでは、親テーブルを逆方向​​に処理します。 最適な遷移によって削除数が増加した場合、`p`に`q`、それではまさに`q-p`削除操作は、その Wave の直前に挿入する必要があります。

 ## 特殊なケース

 エッジのないグラフには一致するサイズがゼロになります。 最小パス カバーはすでにあります`n`、したがって、すべての波は自動的に安全になります。 DP では、生存条件がすでに満たされているため、どこでも削除ゼロが正しく許可されます。 

最小パス カバーが 1 に等しいグラフは、その逆の極端になります。 単一の指向性チェーンは、1 匹のゴブリンによって完全に略奪できます。 一致するサイズは次から始まります`n-1`、最初の波の前に多くの削除が必要になる可能性があります。 削除シーケンス構造は、一致するユニットを一度に 1 つずつ減らし続けるため、これに対処します。 

波によって大きなペナルティが発生する場合、別の微妙な状況が発生します。`y_i`。 最適な戦略では、一度に多数の削除を実行することになる場合でも、後のウェーブまで削除を遅らせることができます。 DP はあらゆる移行を考慮しているため、`k → j`、そのようなすべてのスケジュールを評価し、最適なスケジュールを選択します。
