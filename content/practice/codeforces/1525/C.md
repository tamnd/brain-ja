 ## 解決策
 ## 問題の理解

 0 から 0 までの 1 次元の線分に沿って移動するロボットのセットがあります。$m$。 各ロボットは、0 から 0 までの異なる整数位置から開始します。$m$1 秒あたり 1 単位の一定速度で左右に移動します。 エンドポイント 0 と$m$壁として機能します。ロボットが壁に到達すると、即座に反射し、反対方向に動き続けます。 2 つ以上のロボットが同じ整数座標で正確に出会うと、それらは衝突して消滅します。 非整数の位置で出会ったロボットは衝突しません。 

入力によりすべてのロボットの開始位置と方向が与えられ、目標は各ロボットの爆発または報告の時間を決定することです。$-1$衝突しなければ。 

制約が示すのは、$n$まで可能です$3 \cdot 10^5$すべてのテストケースの合計と$m$と同じ大きさにすることができます$10^8$。 毎秒総当りのシミュレーションを行うと、明らかに制限時間を超えてしまいます。 どのソリューションも、ロボットごと、秒ごとにサブリニアでなければなりません。 理想的には、何かが必要です$O(n \log n)$テストケースごと、またはそれ以上のもの。 

ロボットが非整数の位置で交差する場合、微妙なエッジ ケースが発生します。 たとえば、位置 1 のロボットが右に移動し、位置 2 の別のロボットが左に移動すると、1.5 秒で交差します。 通過しても、座標が非整数であるため衝突は発生しません。 位置が一致するとすぐにすべてのインタラクションをシミュレートする単純なアプローチでは、間違った答えが生成されます。 もう 1 つの注意が必要な状況は、ロボットが壁に跳ね返る場合です。 反射によってロボットが最初は遠くにあったロボットと衝突する可能性があるため、壁の相互作用を無視することはできません。 

## アプローチ

 素朴なアプローチは、毎秒ロボットをシミュレートし、位置を追跡し、整数の衝突を検出することです。 毎秒、すべての位置を更新し、同じ整数を占める 2 つの位置があるかどうかを確認します。 これは概念的には正しいですが、潜在的に$O(m \cdot n)$テスト ケースごとの操作。これは受け入れられません。$m$できる$10^8$。 

最適化するための重要な洞察は、開始位置のパリティに基づいて衝突が決定論的に発生することを観察することです。 同じパリティ (2 を法とする奇数/偶数位置) のロボットは、整数座標でのみ相互に衝突できます。 異なるパリティ間での衝突は、整数回では決して発生しません。 さらに、壁での反射は、線分を仮想的にマイナスまで延長することでシミュレートできます。$m$これにより、明示的に壁で跳ね返ることなく、すべての衝突を正面衝突として扱うことができます。 

したがって、ロボットを奇数と偶数の開始位置に分けて並べ替えることができます。 次に、最初または壁の反射後に、互いに向かって移動するロボットをペアにして、衝突時間をそれらの間の距離の半分として計算できます。 同じ方向に移動するロボットの場合、両方が壁に反射した後に最初の衝突が発生しますが、これは直接計算することもできます。 パリティと方向に基づいてロボットを処理することで、衝突時間を系統的に計算できます。$O(n \log n)$using sorting and stack-based pairing.

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n・m) | O(n) | 遅すぎる |
 | Sorting & Parity + Stack | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのロボットを、開始位置の均等性に基づいて、奇数と偶数の 2 つのグループに分割します。 これにより、整数倍で発生する可能性のある潜在的な衝突のみを考慮することが保証されます。 
2. パリティ グループごとに、ロボットを開始位置で並べ替えます。 
3. パリティごとに 2 つのスタックを維持します。1 つは右に移動するロボット用、もう 1 つは左に移動するロボット用です。 ロボットを順番に反復し、移動するロボットをスタックにプッシュします。 左に移動しているロボットに遭遇した場合は、衝突のためにペアとなるロボットが右側のスタックにあるかどうかを確認します。 
4. 2 台のロボットが正面衝突した場合、衝突時間は開始位置間の距離の半分になります。 
5. 直接衝突を処理した後、壁に反射する前に一度も遭遇しなかったロボットを処理します。 ラインの仮想延長をシミュレートします。0 未満の左に移動するロボットの位置は負の位置にミラーリングされ、右に移動するロボットはそれを超えます。$m$向こうに映る$m$。 これらの仮想位置でスタックベースのペアリングを繰り返します。 
6. ペアリング後、衝突が見つからなかった残りのロボットが割り当てられます。$-1$。 
7. 結果をロボットの元の順序で組み立てます。 

機能する理由: 同じパリティのロボットのみを考慮し、スタック内で正しく移動するロボットを追跡することで、各衝突が発生順に処理されるようにします。 反射は仮想的に位置を拡張することで考慮されるため、バウンス後に発生する衝突を見逃すことはありません。 これにより、各ロボットの最初の整数衝突があれば、それが正しく計算されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        x = list(map(int, input().split()))
        d = input().split()
        ans = [-1] * n

        robots = [(x[i], d[i], i) for i in range(n)]
        for parity in [0, 1]:
            group = [r for r in robots if r[0] % 2 == parity]
            group.sort()
            stack = []
            times = {}

            for pos, dirc, idx in group:
                if dirc == 'R':
                    stack.append((pos, idx))
                else:
                    if stack:
                        last_pos, last_idx = stack.pop()
                        collision_time = (pos - last_pos) // 2
                        ans[idx] = ans[last_idx] = collision_time
                    else:
                        stack.append((-pos, idx))

            stack2 = []
            while stack:
                a_pos, a_idx = stack.pop()
                if stack2:
                    b_pos, b_idx = stack2.pop()
                    collision_time = (2 * m - a_pos - b_pos) // 2
                    ans[a_idx] = ans[b_idx] = collision_time
                else:
                    stack2.append((a_pos, a_idx))
        print(*ans)

solve()
```最初のセクションは入力を読み取り、結果ストレージを初期化します。 ロボットはパリティごとにグループ化され、衝突計算が簡素化されます。 ソートにより、ロボットが左から右の順序で処理されるようになります。 最初のスタックは、右と左の移動者間の正面衝突を処理します。 2 番目のパスでは、位置をミラーリングすることで壁の反射を処理します。 2 で割ると、正面衝突時の相対速度が計算されます。 適合しないまま放置されたロボットはそのまま残ります$-1$。 整数除算を使用すると、衝突が整数倍で発生した場合にのみ記録されるようになります。
