 ## 解決策
 ## 問題の理解

 モノカープには次の帝国があります`n`都市をコントロールしたい`m`地図上の点。 各都市は記念碑を 1 つ建設できます。 記念碑が建設されると、毎ターン 1 ずつ増加する距離内のすべてのポイントを制御します。 具体的には、記念碑が順番に建てられる場合`t`、遠くにあるすべてのポイントを制御します`≤ (turns elapsed since its construction)`。 モノカープはランダムに記念碑を建設します。各ターン、彼は記念碑のない残りの都市の 1 つを選択します。 

**すべての都市に記念碑が設置された後に制御される予想ポイント数**を法で計算するように求められます。`998244353`。 各ポイントは各都市までの距離が固定されているため、問題は、ポイントが終了時にカバーされる確率を計算することになります。`n`曲がる。 

制約が教えてくれる`n ≤ 20`そして`m ≤ 50,000`。 すべてをシミュレートする素朴なアプローチ`n!`都市建設の順序を入れ替えることは不可能である。`20!`巨大です。 このため、私たちは**確率**と期待の線形性の観点から考える必要があります。 制御されるポイントの予想数は各ポイントの予想される確率の合計であるため、各ポイントは独立して分析できます。 

エッジケースには、すべてのポイントが遠く離れている状況（距離）が含まれます。`> n`）そのため、制御されない場合、または複数の都市がある点までの距離が同じ場合。 各都市がポイントを即座に制御すると仮定する不注意な実装は、カバレッジを過剰にカウントすることになります。 

## アプローチ

 ブルートフォースソリューションでは、すべてのものが生成されます。`n!`都市が記念碑を受け取るオーダーを作成し、オーダーごとにターンごとに制御半径の拡大をシミュレートし、最後にカバーされたポイントの数を数えます。 このアプローチは正しいですが、複雑です`O(n! * n * m)`、これは不可能です`n = 20`そして`m = 50,000`。 

重要な洞察は、**問題はポイントごとに分解できる**ということです。 一点を考えてみる`p`。 都市からの記念碑に覆われている確率`i`2 つのことのみに依存します: 距離`d[i][p]`そして記念碑が建てられる番。 すべての都市からの距離を並べ替えてみましょう。`p`その前にいくつの記念碑を建てなければならないかを数えます`p`制御されることが保証されています。 組み合わせ論を使用すると、次の確率を計算できます。`p`その後は_対象外_になります`n`をターンし、1 から減算してカバーされる確率を取得します。 

これにより、検討する必要がなくなる問題が軽減されます。`n!`への順列`O(n^2)`動的プログラミングまたは都市の包含/除外を使用して、ポイントごとに。 期待の線形性により、これらの確率をすべての確率で合計することができます。`m`ポイント。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(n! * n * m) | O(n * m) | 遅すぎる |
 | 最適 | O(n^2 * m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`expected`予想される制御点の合計を保存します。 
2. 各点を反復処理します。`p`。 ポイントについて`p`、各都市からの距離の配列を作成します。 
3. 距離を昇順に並べ替えます。 これにより、記念碑が制御できる最も早いターンという観点から推論することができます。`p`。 
4. 定義する`prob_not_controlled[t]`その確率として`p`その後もまだ制御されていない`t`記念碑が建てられています。 最初は`prob_not_controlled[0] = 1`。 
5. ソートされた距離を繰り返します。 距離ごとに`d`、この都市に建てられた記念碑がカバーできない確率を計算します。`p`記念碑の建設が遅すぎたからです。 これらの確率を累積的に乗算します。 
6. すべての都市を検討した後、`1 - prob_not_controlled[n]`次の確率を与える`p`結局コントロールされてる`n`曲がる。 
7. この確率を`expected`。 すべての点を処理した後、`expected`予想される制御ポイントの合計です。 
8. 最終的な分数モジュロを減算します。`998244353`モジュラーインバースを使用します。 

**機能する理由**: 各ポイントは独立しているため、予想されるカバレッジをポイントの合計として扱うことができます。 距離を並べ替えることにより、初期の記念碑と後期の記念碑の配置の確率的影響が正しく適用されることが保証されます。 累積確率の計算では、すべてを列挙することなく、記念碑の配置順序の組み合わせの可能性が正確に考慮されます。`n!`順列。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    dist = [list(map(int, input().split())) for _ in range(n)]
    expected = 0
    
    for j in range(m):
        dists = [dist[i][j] for i in range(n)]
        dists.sort()
        prob_not = 1
        for i, d in enumerate(dists):
            if d > i + 1:
                continue
            prob_not = prob_not * (i + 1 - d + 1) % MOD
            prob_not = prob_not * modinv(i + 1) % MOD
        prob_controlled = (1 - prob_not) % MOD
        expected = (expected + prob_controlled) % MOD
    
    print(expected)

if __name__ == "__main__":
    solve()
```**コードの説明**: 各ポイントを反復処理し、都市までの距離を並べ替えます。 ループ`for i, d in enumerate(dists)`都市がその位置にある確率を計算します`i`ポイントをコントロールできていない。 確率を累積的に乗算し、逆モジュラーを適用して除算を処理します。 最後に、ポイントを合計すると、制御される予想されるポイント数が得られ、剰余が得られます。`998244353`。
