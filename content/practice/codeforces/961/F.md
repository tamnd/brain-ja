 ## 解決策
 ## 問題の理解

 文字列が与えられています$s$長さの$n$、そのすべての接尾辞を考慮します。 スタートポジションごとに$k$、対応する部分文字列は次のとおりです。$s[k..n]$。 タスクは、これらの接尾辞をそれぞれ個別に分析することです。 

固定サフィックスの場合$T$、文字列を見つけたい$t$それは接頭辞でもあり接尾辞でもあります$T$、厳密には以下より短い$T$、長さが奇数です。 このようなすべての候補の中で、可能な限り最大の長さが必要です。 そのような文字列が存在しない場合は、次のように出力します。$-1$。 

言い換えれば、すべてのサフィックスについて、長さが奇数で文字列全体と等しくない、そのサフィックスの最長の境界線を検索します。 

制約により許可されるのは、$n$まで$10^6$これにより、接尾辞ごとに独立してプレフィックス関数またはハッシュを二次時間または二次時間に近い時間で再計算するアプローチが除外されます。 平$O(n \sqrt{n})$すでに危険です。 正しいソリューションでは、サフィックス全体で構造を再利用するか、文字列全体にわたって線形時間で境界情報を計算する必要があります。 

「奇数の長さ」という制約により、微妙な問題が発生します。 標準的な境界計算 (接頭関数や Z 関数推論など) では、パリティに関係なくすべての境界が得られます。 接尾辞ごとに再計算する場合は、すでに遅すぎるため、事後のフィルタリングだけでは十分ではありません。 

単純な実装では、各接尾辞の接頭辞関数を個別に計算する可能性があります。 これは、不用意に実装するとパフォーマンスと正確性の両方で失敗します。サフィックスの prefix-function は完全な文字列の prefix-function と同じではなく、それを個別に再計算すると共有構造が無視されます。 

もう 1 つの罠は、完全な文字列の最長の境界が単純なシフトによってサフィックスとして再利用できると仮定していることです。 境界線は絶対的な位置合わせに依存するため、シフトすると一致動作が変わります。 

## アプローチ

 ブルートフォースのアイデアは簡単です: 各サフィックスに対して$s[k..n]$、から可能なすべての境界線の長さを試します。$n-k+1$1 まで下げると、その長さのプレフィックスが同じ長さのサフィックスと等しいかどうか、また長さが奇数かどうかを確認します。 それぞれのチェックは、$O(n)$すべてのサフィックスに対してこれを実行すると、最悪の場合には三次的な動作が発生します。 

ハッシュを使用して比較を最適化したとしても、接尾辞ごとに多くの候補境界を評価することになり、結果的に$O(n^2)$ハッシュの比較。 と$n = 10^6$、これは実現不可能です。 

重要な点は、サフィックスがネストされていることです。$k+1$サフィックスから取得されます$k$先頭から 1 文字を削除します。 これは、境界構造が段階的に進化する必要があることを示唆しています。 最初から再計算するのではなく、境界情報を動的に維持します。 

境界線を表現する標準的な方法は、接頭辞関数 (KMP 失敗関数) を使用することです。 ただし、サフィックスごとに独立して必要とするわけではありません。 代わりに、文字列全体に対して接頭辞関数を 1 回計算し、それを再解釈します。 

重要な洞察は、サフィックスの境界は元の文字列のプレフィックスと関数のチェーンに対応するが、完全にサフィックスの内側にある境界だけが有効であるということです。 したがって、次の接頭辞関数を事前に計算できます。$s$次に、各サフィックスに対してこのチェーンへのポインターを維持し、開始インデックスを移動しながらポインターを調整します。 

すべてのサフィックスを効率的に処理するために、事前に計算された障害リンクを使用して最長の有効な境界を維持し、プレフィックスと関数のチェーンに沿ってジャンプしながら、開始をシフトする効果をシミュレートします。 これにより、サフィックスごとの作業が償却定数時間に削減されます。 

最後に、チェーンを横断する際に奇数の長さのみを追跡します。

 ## アルゴリズムのチュートリアル

 プレフィックス関数配列に依存します$pi$、 どこ$pi[i]$の最長の適切なプレフィックスの長さを格納します$s[0..i]$それはその接尾辞でもあります。 

また、あらゆるポジションに対する「次のボーダーチェーン」の解釈も構築します。$i$、からジャンプできます$i$に$pi[i-1]$を繰り返して、で終わるプレフィックスのすべての境界を列挙します。$i$。 

接尾辞を左から右に処理し、各接尾辞について、その接尾辞内で有効な現在の境界線候補の長さを維持します。 

1. 接頭辞関数配列を計算します。$pi$文字列全体に対して。 これにより、プレフィックスのすべての境界関係が得られます。$s$。 
2. 位置で始まる各サフィックスについて$k$、候補の長さを初期化します$cur$として$n-k+1$、その後、それが接尾辞の適切な境界になるまで、接頭辞と関数のチェーンを使用してすぐにそれを減らします。 実際には、次から始めます。$pi[n-1]$サフィックスが縮小するにつれて動的に調整します。 
3. サフィックスから移動する場合$k$に$k+1$、最初の文字を効果的に削除します。 新しいサフィックスの長さより長い境界線は無効であるため、繰り返しジャンプします。$cur = pi[cur-1]$それまで$cur \le n-k$。 
4. 有効性を確認した後、「奇数長」制約を強制する必要があります。 その間$cur > 0$そして$cur$均等な場合は、国境チェーンに沿ってジャンプを続けます。 
5. この削減後の場合$cur = 0$、出力$-1$。 それ以外の場合は出力$cur$。 

これが効率的に機能する理由は、プレフィックスと関数のチェーンに沿った各ジャンプによって境界候補の長さが厳密に減少するためです。 すべてのサフィックスにわたって、各値は償却される一定の回数だけアクセスされるため、合計作業量は線形のままです。 

### なぜ効果があるのか

 文字列プレフィックスのすべての境界には、プレフィックス関数リンクを繰り返すことで到達できます。 ある接尾辞から次の接尾辞に移動するときは、新しい長さを超えた境界線のみが無効になります。 無効な境界線を削除することは、実行可能な長さに達するまでプレフィックスと関数のチェーンをたどることに正確に対応します。 

プレフィックス関数チェーンはすべての有効な境界長を厳密に降順で列挙するため、奇数長フィルターは正確性を損ないません。 偶数の長さをスキップしても、有効な奇数の境界線は削除されません。これは、より長い有効な奇数の境界線が、短い偶数の境界線の前にチェーンの先頭に表示されるためです。 

アルゴリズムは、サフィックスの処理後に不変条件を維持します。$k$、$cur$は、そのサフィックスの有効な奇数ボーダーの最大長です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    pi = [0] * n
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j

    res = []
    cur = pi[-1]

    for k in range(n):
        limit = n - k

        while cur > limit:
            cur = pi[cur - 1]

        while cur > 0 and cur % 2 == 0:
            cur = pi[cur - 1]

        if cur == 0:
            res.append("-1")
        else:
            res.append(str(cur))

        if k < n - 1:
            nxt = pi[cur - 1] if cur > 0 else 0
            cur = nxt

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```プレフィックス関数の構築は標準的な KMP 前処理であり、すべての境界関係を定義する障害リンクを構築します。 変数`cur`現在のサフィックスの最適な境界長を追跡し、最初から再計算するのではなく段階的に更新します。 

重要な実装の詳細は、削減の順序です。最初に境界線が現在のサフィックス内に収まることを確認し、次にパリティを適用します。 これにより、境界の移動によってのみ無効になる有効な候補が誤って破棄されることが回避されます。 

移行`cur = pi[cur - 1]`各ステップの後に行うことが重要な減価償却の秘訣であり、スキャンを最初からやり直すことがないようにします。

 ## 特殊なケース

 のような繰り返し構造を持たない文字列の場合、`abcde`、プレフィックス関数配列はすべてゼロです。 アルゴリズムセット`cur = 0`最初は有効な境界線が見つからないため、すべての接尾辞が出力されます`-1`。 これは、完全な文字列を除いて、空でない接頭辞は接尾辞と等しくないという事実と一致します。 

次のような非常に周期的な文字列の場合`aaaaa`、接頭辞と関数のチェーンは次のようになります。`4 → 3 → 2 → 1 → 0`。 このアルゴリズムは 4 から開始し、すぐに偶数の値をフィルターし、サフィックスごとに減少する奇数の境界線を正しく出力します。 移行ステップにより、最初から再スキャンすることはなく、チェーンの下に移動するだけになります。 

長さ 2 の短い文字列の場合、可能な境界の長さは 1 だけであり、これは長さ 2 の接尾辞と比較する場合にのみ有効です。プレフィックス関数が等しい文字に対して 1 を与え、パリティ フィルタリングがそれを保持するため、アルゴリズムはこれを正しく処理します。
