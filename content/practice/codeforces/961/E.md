 ## 問題の理解

 私たちはテレビのシーズンのコレクションを与えられます。 季節`i`含まれています`a[i]`エピソードには 1 から までの番号が付けられています`a[i]`。 異なる季節のペアを数えたい`(x, y)`と`x < y`such that two conditions are simultaneously possible:

 季節`x`少なくとも`y`エピソード、つまりエピソード`y`季節に存在する`x`。 

季節`y`少なくとも`x`エピソード、つまりエピソード`x`季節に存在する`y`。 

したがって、有効な各ペアは非常に特殊な方法で対称的です。一方のシーズンのインデックスは他方のシーズンのエピソード数内になければならず、その逆も同様です。 

これを純粋に配列用語で書き直すと、ペアを数えています。`(i, j)`と`i < j`そのような`a[i] ≥ j`そして`a[j] ≥ i`。 

制約は次のとおりです`n = 2 · 10^5`、これは直ちに除外します`O(n^2)`ペアチェック。 二次スキャンは約`4 · 10^10`最悪の場合、制限時間をはるかに超えて比較することになります。 

の値が多数ある場合、微妙な問題が発生します。`a[i]`大きく、潜在的には最大`10^9`。 エピソード数が多くても、インデックスは までしか上がりません。`n`、上記のものを意味します`n`有効性チェックの観点からは同じように動作します。 この観察は不可欠になります。 

単純な間違いは、すべてを反復処理することです`j`それぞれに`i`条件を直接確認してください。 もう 1 つの間違いは、条件が値だけではなく元のインデックスに依存することを認識せずに並べ替えを試みることです。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべてのペアについて`(i, j)`と`i < j`かどうかを確認します。`a[i] ≥ j`そして`a[j] ≥ i`。 これは、有効性の定義を直接エンコードしているため、正しいです。 ただし、以下については確認が必要です`n(n-1)/2`ペアでは遅すぎます`n = 2 · 10^5`。 

重要な洞察は、この条件が範囲カウント問題に変換できる方法でインデックスと値を結合しているということです。 固定の場合`i`、すべてを数えたい`j > i`そのような`j ≤ a[i]`そして`a[j] ≥ i`。 最初の制約は次のことを制限します`j`で終わるプレフィックスに`a[i]`、一方、2 番目の制約はそれらの位置の値に依存します。 

これは、右から左にスキャンし、すでに処理されたインデックスのデータ構造を維持することを示唆しています。 私たちが位置にいるとき`i`、すべてのインデックス`j > i`はすでに挿入されており、そのうちのいくつが満たされるかを数える必要があります。`a[j] ≥ i`ありながら`j ≤ a[i]`。 

これは古典的な 2D 条件問題になり、アクティブなインデックスとその境界の数を維持する場合、フェンウィック ツリーによるプレフィックス カウントに還元できます。

 ## アルゴリズムのチュートリアル

 位置を処理するときに次のようにインデックスを右から左に処理します。`i`、すべての候補者`j > i`すでに活動中です。 

インデックス上にフェンウィック ツリーを維持します。`j`逆の順序で到達すると挿入されます。 これにより、アクティブな数をすばやくクエリできます。`j`任意のプレフィックスに嘘をつきます`[1, x]`。 

2 番目の条件も強制する必要があります`a[j] ≥ i`したがって、インデックスのみをアクティブにします`j`正しい瞬間に実行するか、値によるフィルタリング用の 2 番目の構造を維持します。 

よりクリーンな変換により、二重フィルタリングの複雑さが回避されます。 条件を再解釈します。 

各ペアごとに`(i, j)`、次のものが必要です。`i < j ≤ a[i]`そして`i ≤ a[j]`。 

だから固定のために`i`、 有効`j`は次の交差点にあります:`j ∈ (i, a[i]]`そして`a[j] ≥ i`。 

掃除します`i`から`n`まで`1`。 

ステップで`i`、ポジションをアクティブにします`i`インデックスをキーとするフェンウィック ツリーに変換しますが、次の場合に限ります。`a[i] ≥ current threshold`。 これを達成するために、インデックスを降順で処理します。`a[i]`、それらをインデックスを介してフェンウィックツリーに挿入します。 このようにして、限界に達したときに`i`、すべてのポジション`j`と`a[j] ≥ i`すでに活動中です。 

次に、有効なポジションがいくつあるかをクエリします。`(i, a[i]]`。 

手順は次のようになります。 

1. インデックスを並べ替える`a[i]`降順で。 
2. すべてのインデックスをアクティブにするポインタを維持します。`a[index] ≥ current i`。 
3. ポジションに対してフェンウィック ツリーを使用して、アクティブなインデックスを追跡します。 
4. それぞれについて`i`から`n`まで`1`、適格なインデックスをアクティブ化し、アクティブなインデックスの数をクエリします。`j`いる`(i, a[i]]`。 
5. 結果を蓄積します。 

フェンウィック ツリーを使用すると、範囲内のアクティブなインデックスを対数時間でカウントできるようになります。 

### なぜ効果があるのか

 しきい値を処理するときはいつでも`i`、アクティブ セットにはそれらのインデックスが正確に含まれます`j`そのような`a[j] ≥ i`。 その中で、以下のもののみをカウントします。`j > i`そして`j ≤ a[i]`。 これは、元のペア定義の 2 つの制約と正確に一致します。 有効な各ペアは、小さいインデックスを処理するときに 1 回だけカウントされます。`i`、それは両方の条件が同時に強制される瞬間だからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

n = int(input())
a = list(map(int, input().split()))

# cap values since indices beyond n are irrelevant
for i in range(n):
    if a[i] > n:
        a[i] = n

pos_by_value = [[] for _ in range(n + 1)]
for i, v in enumerate(a):
    pos_by_value[v].append(i + 1)

bit = Fenwick(n)
ans = 0

# pointer over values from high to low
ptr = n

for i in range(n, 0, -1):
    while ptr >= i:
        for idx in pos_by_value[ptr]:
            bit.add(idx, 1)
        ptr -= 1

    # we need j in (i, a[i]]
    ans += bit.range_sum(i + 1, a[i])

print(ans)
```このコードは、エピソード数の有効範囲を最大で 2 まで圧縮します。`n`有効なインデックス比較ではこれを超える値は使用されないため、`n`。 

インデックスをそれらの基準に基づいて分類します`a[i]`すべてのポジションをアクティブ化できるように値を設定します。`a[j] ≥ i`しきい値を下げると効率的になります。 フェンウィック ツリーには現在有効なインデックスが格納され、範囲クエリでは必要なインデックス間隔内にあるインデックスの数がカウントされます。 

実装によくある落とし穴は、上限を忘れることです。`a[i]`で`n`。 これがないと、配列のインデックス付けや不要なアクティブ化ロジックが機能しなくなったり、時間が無駄になったりする可能性があります。
