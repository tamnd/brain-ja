 ## 解決策

 ## 問題の理解

 整数グリッド上の一連の点が与えられ、最大 2 本の無限の直線を使用してそれらすべてをカバーできるかどうかを判断することが課題となります。 各点はこれらの直線の少なくとも 1 つに位置する必要がありますが、2 つの直線が重なったり、同一になったりする場合もあります。 

これについて考えると便利な方法は、点を最大 2 つの同一線上のグループに分割することです。 1 つのグループは 1 行目に配置され、残り (存在する場合) は 2 行目に配置されます。 

入力サイズは最大 100,000 ポイントに達します。 点のすべてのトリプルまたは候補線のすべてのペアを直接検査しようとするソリューションは、非常に遅すぎます。 点を越える 3 次または 2 次の構築はすぐに実行不可能になります。$O(n^2)$Python ではすでに限界に達しており、最悪の場合、通常は遅すぎます。 

重要な難点は、ラインが与えられていないことです。 すべての可能性を明示的に試すことなく、そのようなペアが存在するかどうかを発見する必要があります。 

いくつかのエッジケースは、単純な推論が失敗する理由を明らかにします。 

すべての点がすでに同一線上にある構成では、すぐに YES が返されます。 例えば：```
3
0 0
1 1
2 2
```常に 2 つの異なる行を構築しようとする不用意なアプローチは、行が異なるはずであると想定している場合、これを誤って拒否する可能性があります。 

もう 1 つの注意が必要なケースは、最適な最初のラインを少数の初期点の中から選択する必要があるが、入力順序の最初の 2 点である必要はない場合です。```
4
0 0
1 1
2 2
0 1
```ここで、(0,0)-(1,1)-(2,2) を通る線ともう 1 つの垂直線 x = 0 を使用すると、正解は YES です。 最初の 2 つの点が「正しい」線を定義するという貪欲な仮定は、それらの 2 点がグローバル構造を表さない小さなサブセットと同一直線上にある場合には失敗する可能性があります。 

中心的な課題は、正しいペアを見逃さないことを保証しながら、任意のラインの推測を回避することです。 

## アプローチ

 ブルートフォース戦略では、すべてのポイントのペアを最初のラインの候補として試します。 このようなラインごとに、その上にあるすべてのポイントを収集し、残りのポイントが同一線上にあるかどうかを確認します。 これが機能するのは、有効な解には最初の線を定義する点のペアが含まれている必要があるためです。 

ただし、このアプローチでは次のことを検討します。$O(n^2)$候補線を作成し、各線についてすべての点をスキャンすると、$O(n^3)$最悪の場合の行動。 と$n = 10^5$、これはまったく不可能です。 

重要な点は、実際にはすべてのペアを試す必要はないということです。 有効な解が存在する場合、2 番目のラインの一部ではない 2 つの点を選択した後、2 つのうちの 1 つが起こる必要があります。それらはすでに正しい最初のライン上にある、または初期の点を含む一定数のスワップを試行することで間違いを修正できるかのどちらかです。 

これは建設的な貪欲な削減につながります。最初の線がいくつかの初期選択肢 (具体的には最初のいくつかの点を含む) の 1 つによって決定されると仮定し、すでに適合している点を削除した後、残りの点を同一直線上にできるかどうかを検証します。 

これが機能する根本的な理由は幾何学的剛性です。 2 つのラインが固定されると、構造により、ほとんどの初期ポイントがそのうちの少なくとも 1 つに強制的に配置されます。 候補が失敗した場合、最初のいくつかの点の 1 つが和集合構造の外側にあるために失敗しているはずであり、その点を定義ペアに交換するだけで構造を修復できます。 

これにより、探索空間が二次候補から定数候補に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのポイント ペアを行 1) | O(n3) | O(n) | 遅すぎる |
 | 最適化された候補の固定 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 外積を使用して 3 つの点が同一線上にあるかどうかをチェックするという幾何学的ヘルパーに依存しています。 

1. 最初の線が点 0 と 1 によって定義されていると仮定して始めます。 

すべての点がこの線上にある場合、答えはすぐに「YES」になります。 これは 1 行で十分な場合に相当します。 
2. それ以外の場合は、点 0 と 1 を通る線上にない点を特定します。これらを「オフライン ポイント」と呼びます。 

そのような点が最大 2 つある場合は、いつでも 2 行目に配置できるため、答えは「YES」です。 
3. 少なくとも 3 つのオフライン ポイントがある場合、2 番目の線が存在する場合は、これらのポイントのいずれか 2 つを通過する必要があります。 最初の 2 つのオフライン点を取得し、それらを使用して 2 番目の線を定義しようとします。 
4. 次に、残りのオフライン ポイントがすべてこの 2 番目の線上にあるかどうかを確認します。 「はい」の場合は、「はい」と答えてください。 
5. この試みが失敗した場合は、0 と 1 の代わりにポイント 0 と 2 を使用して最初の行を再定義し、同じプロセスを繰り返します。 
6. すべての試行が失敗した場合は、NO を返します。 

数回の試行だけで済む理由は、有効な構成では、最初の 3 つのポイントのうち少なくとも 1 つが 2 つのカバー ラインのそれぞれに属している必要があるためです。 最初のいくつかの点の間で異なる選択を強制することで、最終的には有効な分解が存在する場合はそれと一致します。 

### なぜ効果があるのか

 有効な解はすべて、点を 2 つの線 L1 と L2 に分割します。 最初の 3 つの点を考慮してください。 鳩の巣原理によ​​り、それらのうちの少なくとも 2 つは同じ線上、たとえば L1 上にあります。 これら 2 つを最初の行の定義ペアとして選択すると、L1 が正しく識別されます。 L1 が固定されると、残りのすべての点が L2 上に存在する必要があり、アルゴリズムがこれを検出します。 最初のペアが L1 に対応しない場合、最初の 3 つの点の間で他の組み合わせを試すと、最終的には同じ真のラインから 2 つの点が選択されることが保証されます。 これにより完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def collinear(a, b, c):
    return (b[0] - a[0]) * (c[1] - a[1]) == (b[1] - a[1]) * (c[0] - a[0])

def check(p0, p1, pts):
    bad = []
    for p in pts:
        if not collinear(p0, p1, p):
            bad.append(p)

    if len(bad) <= 2:
        return True

    p2 = bad[0]
    p3 = bad[1]

    for x in bad:
        if not collinear(p2, p3, x):
            return False
    return True

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    if n <= 4:
        print("YES")
        return

    candidates = [(0, 1), (0, 2), (1, 2)]

    for i, j in candidates:
        if check(pts[i], pts[j], pts):
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```この実装では、3 つの候補ベースラインのみをテストする必要があるという考えがエンコードされています。 の`collinear`この関数は外積を使用して浮動小数点精度の問題を回避し、完全に整数演算で動作します。 

の`check`関数は、ポイントを最初のライン上のポイントとそれ以外のポイントに分割します。 オフライン セットが小さい場合は、2 番目の行に簡単に適合します。 それ以外の場合は、最初の 2 つの問題のあるポイントを使用して 2 番目の行を強制的に試行し、残りのすべてのポイントを検証します。 

外側のループは、最初の 3 つの点の間で最初の線を固定する関連するすべての方法を試みます。これは、2 つのカバー線に関する鳩の巣引数による正確性を保証するのに十分です。

 ## 特殊なケース

 古典的な故障モードでは、最初の 2 つの点が常に正しい線を定義していると想定されます。 例えば：```
4
0 0
0 1
1 1
2 2
```(0,0) ～ (0,1) を選択すると、多くの点がオフラインとして分類され、不可能であると誤って結論付けられる可能性があります。 このアルゴリズムは、最初の 3 つの点の間で代替のペアを再試行することでこの問題を修正し、最終的には真の基礎となるラインからのペアが選択されるようにします。 

もう 1 つの微妙なケースは、すべての点が 1 つの線上にある場合です。 最初のチェック後にオフライン セットが空になると、アルゴリズムはこれを直ちに検出し、2 行目を構築する必要なく YES を返します。 

ちょうど 2 つの点が 2 番目の線を定義する場合、境界例が発生します。 実装では明示的に許可されています`len(bad) <= 2`、任意の 2 点が常に有効な線を定義するため、最小限の構成で不必要な拒否が防止されます。
