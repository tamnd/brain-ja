 ## 解決策
 ## 問題の理解

 正方形が 1 つずつ到着し、列に積み重なるプロセスをシミュレートしています。 がある`n`入ってくる各正方形は列を選択し、すでにそこにあるものの上に着地し、その列の高さを 1 つ増やします。 

キー イベントは、すべての列が同時に空でなくなるたびに発生します。 その時点で、最下層を 1 つ完全に「クリア」します。つまり、すべての列がちょうど 1 つの正方形を失い、1 ポイントを獲得します。 削除後、残りのスタックはすべて実質的に下にシフトしますが、ここでは高さのみを考慮しているため、これは各列の現在の高さから 1 を減算することと同じです。 

つまり、プロセス全体は、実際には列の高さを追跡し、すべての列がゼロ以外であるときに、すべての列の最小高さが少なくとも 1 に達する回数をカウントすることになります。 

入力により、列の数と正方形を受け取る列の順序が与えられます。 出力は、行全体の削除が発生した回数です。 

制約`n, m ≤ 1000`O(mn) シミュレーションはすでに安全ですが、それより悪いものは不要であることを明確にします。 更新ごとにすべての列をリニア スキャンすることはまだ問題ありませんが、構造は増分状態を維持することでフル スキャンの繰り返しを回避できることを示唆しています。 

列が最初のスクエアを受け取るのが遅い場合、微妙なエッジケースが発生します。 最後の空の列が空でなくなるまでは、他の列がどれだけ大きくなっても削除は行われません。 もう 1 つのエッジ ケースは、削除が連続して発生する場合です。削除後、すべての列が 1 つ減るため、一部の列がすぐに再び空になり、補充されるまで次の削除がブロックされる可能性があります。 

たとえば、次の場合`n = 2`そしてシーケンスは`[1, 2, 1, 2]`、ステップ 2 で両方の列が空ではなくなり、1 つの削除が得られます。 その後、高さは次のようにリセットされます`[0, 0]`、次の 2 つの挿入が再び同期され、別の削除が行われます。 高さを適切にリセットすることを忘れた単純なアプローチでは、過剰にカウントされてしまいます。 

## アプローチ

 直接シミュレーションでは配列が保持されます`h`サイズの`n`、増加します`h[c_i]`受信する正方形ごとに、更新のたびにすべてのエントリが少なくとも 1 であるかどうかをチェックします。そうであれば、答えを増分し、すべてのエントリから 1 を減算します。 

これが機能するのは、プロセスが文字通りグローバル チェックとグローバル デクリメントに関して定義されているためです。 ただし、コストがかかる部分は、すべての列の完全スキャンを繰り返してゼロの列があるかどうかを確認し、その後、すべての値をデクリメントするために別の完全なパスを実行することです。 最悪の場合、これは O(mn) になります。ここではまだ許容されますが、概念的には無駄です。 

重要な観察は、高さを明示的にシミュレートする必要がないということです。 行の削除は、最後の削除ポイント以降、各列に少なくとも 1 つの正方形が蓄積されたときに正確に行われます。 削除するたびに、すべての列が 1 つ減ります。これにより、システムは事実上、「最後にクリアされたレイヤーを超えた余分な正方形」のみを追跡するようにリセットされます。 これは、現在のフェーズで各列が少なくとも 1 つの正方形を受け取ったかどうかだけを知る必要があることを意味します。 

前回のリセット以降に列が出現したかどうかを示すブール配列と、現在「このフェーズで埋められている」列の数を示すカウンターを維持します。 現在のフェーズで初めて列が埋まるたびに、このカウンターがインクリメントされます。 届いたら`n`、ポイントを獲得し、すべてのフラグとカウンターをリセットします。

 ## アルゴリズムのチュートリアル

 現在のサイクルでどの列が出現したか、および現在埋められている個別の列の数を追跡します。 

1. 配列を初期化する`seen`サイズの`n`すべての値が false、およびカウンター`filled = 0`。 これは、最後の行の削除以降、どの列が少なくとも 1 つの正方形を受け取ったかを表します。 
2. 列の各入力正方形を反復処理します。`c`。 
3. もし`seen[c]`false の場合、true としてマークしてインクリメントします`filled`。 同じ列に正方形を追加しても完全な行を完成させることはできないため、このステップでは現在のサイクルで最初に出現した列のみがカウントされます。 
4. もし`filled`と等しくなる`n`、すべてのコラムを完全に網羅することができました。 これは、現在の状態で完全な最下行を形成することに正確に対応します。 
5. これが起こったら、答えを 1 つ増やし、リセットします。`seen`すべて false に設定し、リセットします`filled`ゼロに。 これは、最下層を削除し、残りのすべての正方形を 1 つずつ下げることをシミュレートします。 
6. 残りの正方形も同様に処理を続けます。 

なぜそれが機能するかは、プロセスのフェーズ分解に基づいています。 行をクリアするたびに、すべての列の高さが 1 単位失われ、すべての列からちょうど 1 つの「保証レイヤー」が削除されます。 この層の上に残っているものは、次の行全体の完了の検出には無関係です。 最後の削除以降、各列が少なくとも 1 つの新しい正方形を受け取ったかどうかのみが重要です。 したがって、各サイクルは独立しており、列の完全なセットを完了した回数を数えると、除去の数が正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cols = list(map(int, input().split()))

    seen = [False] * n
    filled = 0
    ans = 0

    for c in cols:
        c -= 1
        if not seen[c]:
            seen[c] = True
            filled += 1

        if filled == n:
            ans += 1
            seen = [False] * n
            filled = 0

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、フェーズベースの解釈を直接反映しています。 の`seen`配列は、各列が現在のサイクルで少なくとも 1 つの正方形に貢献したかどうかを追跡します。 の`filled`カウンタは、完全性をチェックするために配列を繰り返しスキャンすることを回避します。 

よくある実装上の落とし穴は、両方をリセットするのを忘れることです。`seen`そして`filled`完全な列が形成されたとき。 もしそうなら`seen`リセットされますが、`filled`そうでない場合、アルゴリズムは誤って完了数のカウントを継続します。 

もう 1 つの微妙な点は、入力列が 1 ベースであるのに対し、Python 配列は 0 ベースであるため、列インデックスをデクリメントすることです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 最小限の列数 (`n = 1`) は、すべての単一の正方形がすぐに完全な行を完成させるため、動作が異なります。 アルゴリズムはこれを自然に処理します。`filled`新しい列が出現するたびに 1 になり、そのたびにリセットがトリガーされるため、答えは次のようになります。`m`。 

1 つの列が他の列が現れる前に多くの正方形を受け取るケースは、フェーズの動作を示しています。 入力用`3 4: 1 1 1 2`、列 3 は決して埋められないため、行は完成しません。`filled`3 に達することはないので、答えは 0 のままです。 

次のようなフルサイクル境界ケース`3 3: 1 2 3`は最後のステップでちょうど 1 サイクルを完了します。これは、完了が更新の頻度ではなく、最初にすべての列がカバーされた時間に関係していることを示しています。
