 ## 解決策
 ## 問題の理解

 私たちには小さなチェス盤とその上に置かれた二人の騎士が与えられます。 1 人の騎士は白で最初に動き、もう 1 人の騎士は黒です。 各ターンで、プレイヤーは標準の騎士の動きを使用して自分の騎士を動かします。 インタラクションは、一方が勝つか、350 手に到達するまで続きます。 

勝利とは、相手の騎士を捕まえることだけを意味するわけではありません。 各面には、ボードの中央近くに指定された「ターゲット セル」もあります。 白騎士は中央左のマスを狙い、黒騎士は中央右のマスを狙います。 目標に到達しても、その時点で目的地が敵の攻撃を受けていなければ、すぐに勝利となります。 

タスクは、白としてプレイするか黒としてプレイするかを選択し、対戦相手がどのように反応するかに関係なく、アリスが選択した側が常に勝利をもたらすように、対話的に動きを出力することです。 

ボードのサイズは最大 40 x 40 と小さいですが、インタラクションと敵対的な対戦相手により、ゲームの状態を単純に探索することは実行できません。 完全なゲーム ツリーはポジションごとに最大 8 つの手で分岐し、手数制限が 350 であっても簡単に爆発する可能性があります。 

重要な微妙な点は、問題は両方の騎士の完全な勝利戦略を同時に計算することを求めているわけではないということです。 最初に 1 人のナイトにコミットするだけでよく、その後は適応的な対戦相手に対して最適にプレイする必要があります。つまり、解決策はゲームを決定論的なパスまたは単純な不変量主導の戦略に縮小する必要があります。 

よくある落とし穴は、両方のナイトを対称的にシミュレートしようとしたり、「攻撃チェックされたターゲットの勝利」条件を考慮せずにそれらの間で最短経路の競争を試みたりすることです。 もう 1 つの間違いは、相手が適応的であることを無視していることです。そのため、傍受に対する安全性が保証されない事前に計算された固定パスは失敗する可能性があります。 

## アプローチ

 最初の自然なアイデアは、各セルがノードであり、ナイトの動きがエッジである重みのないグラフとしてボードを扱うことです。 この観点から、各騎士は、必要に応じて相手をブロックまたは捕らえながら、ターゲットに到達しようとします。 このグラフに対してミニマックス検索を試みるかもしれません。 ただし、状態空間は両方の位置と誰の順番の積であり、最大でも$40 \cdot 40 \cdot 40 \cdot 40 \cdot 2 = 2560000$州。 この数は管理可能に見えますが、各状態には最大 8 の分岐係数があり、相互作用の制約により、対戦相手の応答をシミュレートせずに遷移を自由に事前計算することはできません。 インタラクティブな環境では、これはすぐに現実的ではなくなります。 

重要な観察は、ボードのサイズが十分小さいため、ターゲットまでのナイトの距離が安定しており、事前に計算できること、そしてさらに重要なことに、勝利の条件は、世界的な位置の優位性ではなく、固定された正方形に安全に到達することのみに依存するということです。 これにより、ゲームは競合状態に陥ります。各ナイトは、相手が妨害したり捕らえたりするよりも早くターゲットに到達しようと効果的に試みます。 

両方の騎士は同じ移動ルールで移動するため、対称性が主なツールになります。 勝利の戦略は、ナイト距離がより近いターゲットを持つナイトを選択すると同時に、相手が自分のターゲットに到達するよりも早くターゲットに到達できないようにすることです。 なぜなら$n, m \le 40$で、BFS を使用してすべてのペアのナイト距離を事前計算できます。$O(nm)$、各開始位置から両方のターゲットまでの距離を比較します。 

より良い方を選択すると、実際のゲームプレイ戦略は貪欲な最短経路ナビゲーションになります。つまり、常に事前に計算された最短経路に沿ってターゲットに向かって移動します。 対戦相手は、迂回をしても自分たちの進歩を遅らせるだけであり、安全に到着するとすぐに勝利条件が発動するため、これを効果的に妨害することはできません。 

したがって、コアの縮小は、インタラクティブな敵対ゲームから、2 つの固定された目的地を持つナイト グラフ上の最短パス レースへと変わります。

 | --- | --- | --- | --- |
 | 完全なゲーム ツリー/ミニマックス | 指数関数 | 指数関数 | 遅すぎる |
 | BFS 距離 + グリーディ パス |$O(nm)$前処理 +$O(1)$移動ごと |$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのセルから BFS を使用してボード上のナイト距離を事前計算します。 これにより、任意の 2 つのマス目間のナイトの最短移動回数が得られます。この設定では最適なプレイは常に最短パスに対応するため、これで十分です。 

1. ナイト移動グラフを構築します。$n \times m$グリッド。 各セルは最大 8 つの有効なナイト宛先に接続します。 この表現には、すべての法的移動オプションが含まれています。 
2. 白いターゲットセルからBFSを実行します。$(n/2, m/2)$黒のターゲットセルとは別に$(n/2+1, m/2)$。 これら 2 つの BFS 実行では、ポジションが各ゴールにどれだけ早く到達できるかを計算します。 
3. 各ナイトの開始位置について、両方のターゲットまでの距離を計算します。 白でプレイするか黒でプレイするかの 2 つの可能な選択肢を比較します。 
4. 白騎士が黒騎士よりも厳密に早く目標に到達できる場合、または開始時に即座に捕獲されるリスクも回避できる場合は、白を選択します。 それ以外の場合は、黒を選択してください。 決定は最初に一度行われ、再度検討されることはありません。 
5. サイドを選択した後、BFS からの親ポインターを使用して、選択したナイトの開始位置からターゲットまでの最短パスを再構築します。 
6. インタラクション中は、常にこの事前計算された最短パスの次のステップに沿って移動します。 対戦相手が移動するたびに、対戦相手が隣接していて捕獲の脅威を強いられない限り、我々は単にパスに沿って前進を続けるだけです。その場合、最短パスの特性により、最小時間の軌道にとどまることが保証されます。 

### なぜ効果があるのか

 重要な不変条件は、各ステップにおいて、現在位置からターゲットまでの最短経路上に留まるということです。 ナイトの動きは重み付けされておらず対称であるため、最短経路からの逸脱によって到着時間を短縮することはできません。また、対戦相手も同じ制約の下で移動するため、開始時にすでに BFS 距離が近かった場合を除き、迎撃するためのより速いルートを作成することはできません。 最初にサイドを選択することで、この条件が有利なターゲットのみにコミットすることが保証されます。 これにより、私たちが安全に中央に到達する前に、勝利条件が無効になるような方法で相手が追いつくことを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def inb(x, y, n, m):
    return 1 <= x <= n and 1 <= y <= m

def bfs(n, m, sx, sy):
    dist = [[10**9] * (m + 1) for _ in range(n + 1)]
    q = deque()
    dist[sx][sy] = 0
    q.append((sx, sy))
    dirs = [(1,2),(1,-2),(-1,2),(-1,-2),
            (2,1),(2,-1),(-2,1),(-2,-1)]
    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if inb(nx, ny, n, m) and dist[nx][ny] > dist[x][y] + 1:
                dist[nx][ny] = dist[x][y] + 1
                q.append((nx, ny))
    return dist

def reconstruct(n, m, start, goal):
    sx, sy = start
    gx, gy = goal
    dist = bfs(n, m, gx, gy)
    dirs = [(1,2),(1,-2),(-1,2),(-1,-2),
            (2,1),(2,-1),(-2,1),(-2,-1)]
    parent = {}
    q = deque()
    q.append((gx, gy))
    parent[(gx, gy)] = None

    while q:
        x, y = q.popleft()
        if (x, y) == (sx, sy):
            break
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if inb(nx, ny, n, m) and (nx, ny) not in parent and dist[nx][ny] == dist[x][y] + 1:
                parent[(nx, ny)] = (x, y)
                q.append((nx, ny))

    path = []
    cur = (sx, sy)
    while cur is not None:
        path.append(cur)
        cur = parent[cur]
    path.reverse()
    return path

n, m = map(int, input().split())
x1, y1, x2, y2 = map(int, input().split())

tx_w, ty_w = n//2, m//2
tx_b, ty_b = n//2 + 1, m//2

dist_w = bfs(n, m, tx_w, ty_w)
dist_b = bfs(n, m, tx_b, ty_b)

white_time = dist_w[x1][y1]
black_time = dist_b[x2][y2]

if white_time <= black_time:
    print("WHITE")
    sys.stdout.flush()
    path = reconstruct(n, m, (x1, y1), (tx_w, ty_w))
    path_idx = 1
    my_turn = True
else:
    print("BLACK")
    sys.stdout.flush()
    path = reconstruct(n, m, (x2, y2), (tx_b, ty_b))
    path_idx = 1
    my_turn = False

while True:
    if my_turn:
        if path_idx < len(path):
            x, y = path[path_idx]
            print(x, y)
            sys.stdout.flush()
            path_idx += 1
        else:
            break
        my_turn = False
    else:
        line = input().strip()
        if not line:
            continue
        a, b = map(int, line.split())
        if a == -1 and b == -1:
            break
        my_turn = True
```BFS は各ターゲットからの距離マップを計算するために 2 回使用され、これにより白と黒の間の最初の決定が可能になります。 再構成ステップでは、選択したナイトからそのターゲットまでの最短パスを構築し、インタラクション中に各動作を一定時間内に発射できるようにします。 

インタラクションループは意図的に最小限に抑えられています。 選択した戦略が単調であるため、ゲーム中にパスを再計算しません。最短パスにコミットすると、逸脱してもターゲットまでの時間が増加するだけです。 

微妙な点は、再構築 BFS が距離マップを使用してターゲットから逆方向に実行され、最短パスのエッジのみをたどることが保証されることです。 これにより、親の選択における曖昧さが回避され、生成されたパスが有効であることが保証されます。

 入力:```
8 8
2 3 1 8
```両方のターゲットからの距離を計算します。 白は 1 回の手で中央のターゲットに到達しますが、黒は自身のターゲットに到達するまでにさらに多くのステップが必要だとします。 

「白」を選択し、再構築された最短パスに従います。 

| ステップ | ポジション | アクション |
 | --- | --- | --- |
 | 0 | (2,3) | 開始 |
 | 1 | (4,4) | ターゲットに移動 |

 この時点で、白い騎士は即座に目標に到達します。攻撃を受けていなければ、これはすでに勝利の構成です。 黒騎士は遠くにいるので干渉は起こらない。 

これは、BFS の距離比較の重要性を示しています。ゲームは 1 つの手の解決策に崩壊します。 

### 例 2

 両方のナイトがターゲットまで等距離にあり、一方のナイトのアクセス性がわずかに優れているという対称的なケースを考えてみましょう。 

BFS 距離を比較します。 

| ナイト | 開始 | ターゲット | 距離 |
 | --- | --- | --- | --- |
 | ホワイト | (x1,y1) | (n/2,m/2) | d1 |
 | 黒 | (x2,y2) | (n/2+1,m/2) | d2 |

 もし$d2 < d1$、私たちはBLACKを選択します。 

トレース:

 | ターン | プレーヤー | 移動 |
 | --- | --- | --- |
 | 1 | 黒 | BFS パスステップ 1 に従います。 
| 2 | ホワイト | 相手の動き（構造的に無視） |
 | 3 | 黒 | 最短経路を続ける |

 これは、事前に計算された最短ルートに沿って常に前進することを保証する以上に、アルゴリズムが敵の行動に依存しないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(nm)$| 40x40 グリッド上の各 BFS は、最大 8 つのエッジを持つ各セルを 1 回処理します。 
| スペース |$O(nm)$| 距離配列と親再構築ストレージ |

 この制約により、このアプローチは非常に安全になります。 複数の BFS 実行があっても、合計の作業量は制限に比べて小さく、インタラクション ループは 1 移動あたり一定時間であり、350 移動の上限を大幅に下回ります。

 ## 特殊なケース

 重要なエッジケースの 1 つは、ナイトがターゲットに隣接して開始し、最初の動きですぐに勝利を収めることができる場合です。 その状況では、BFS 距離は 1 であり、アルゴリズムは自然にその手をすぐに選択します。 インタラクション ループは常に再構築されたパスの次のステップを出力するため、最初の出力移動によりゲームが直接終了します。 

もう 1 つのケースは、両方の騎士がターゲットまでの距離が等しい場合です。 アルゴリズムのタイブレークでは一方の側が恣意的に選択されますが、最適なプレイの下ではどちらの側も平等だけから厳密に良い結果を強制することは対称性によって保証されないため、正確性は保たれます。 

3 番目のケースは、相手のナイトが選択した側のターゲットマスからスタートしたときに発生します。 それでも、BFS ベースの推論は依然として機能します。選択されたパスが合法性に応じてそのマスを即座にキャプチャするか回避するためであり、インタラクション プロトコルにより、パスが自然にトリガーするキャプチャに勝利した場合の即時終了が許可されます。
