 ## 解決策
 ## 問題の理解

 数値のリストが与えられ、2 つの異なる位置を選択して両方の値を 1 減らす操作を繰り返し実行します。 目標は、このような一連の操作を使用して、最終的にすべての値を正確にゼロにできるかどうかを判断することです。 

各操作は、2 つの異なる要素から正確に 1 つのユニットを消費します。 「作業単位」の観点から考えると、各操作で合計 2 つのユニットが削除されますが、それらは 2 つの異なる山から同時に取り出される必要があります。 問題は、アレイ全体にわたるユニットの初期分布を、何も残らないまでこのように完全にペアにすることができるかどうかです。 

の制約`n`まで$10^5$までの値$10^9$操作のシミュレーションは直ちに除外されます。 たとえデクリメントを貪欲にシミュレートしようとしたとしても、合計操作数は次のオーダーになる可能性があります。$10^9$、これは実現可能な限界をはるかに超えています。 代わりに、解決策は線形時間でチェックできる構造的条件に依存する必要があります。 

素朴な推論を試みると、いくつかの微妙な失敗例が現れます。 たとえば、合計が偶数である限り、答えは「YES」であると考える人もいるかもしれません。 これは失敗します: 検討してください`[1, 1, 1]`、合計は 3 (すでに奇数であるため拒否されました) ですが、また`[2, 2, 1, 1]`合計は 6 であり、期待できそうです。 ただし、1 つの要素が優勢すぎる場合は、ペアリングの制約により不可能になる可能性があります。 

もう 1 つの単純なアイデアは、最大の要素を使い果たされるまで貪欲に組み合わせることです。 これは次のような場合に失敗する可能性があります`[3, 3, 1, 1]`、貪欲なペアリングが機能しますが、`[4, 1, 1, 1]`、構造自体がすでに不可能であることが保証されているにもかかわらず、貪欲なペアリングはすぐに行き詰まります。 

したがって、本当の困難はシミュレーションではなく、有効なペアリング構造がいつ存在するかを認識することです。 

## アプローチ

 各操作は 2 つの異なるインデックスから 1 つのユニットを削除するため、このプロセスは、異なるインデックスにわたる個々のユニットの寄与をペアにするものとして解釈できます。 配列の各要素をユニット トークンのスタックとして想像してください。 すべてのトークンを別のスタックのトークンと照合する必要があります。 

配列をユニット トークンのマルチセットに拡張すると、タスクは次のようになります。同じインデックスからのペアが存在しないようにすべてのトークンをペアにできるか? これはすぐに 2 つの必要な条件を示唆します。 

まず、各操作でちょうど 2 つのユニットが削除されるため、トークンの総数は偶数である必要があります。 合計が奇数の場合、少なくとも 1 つのユニットがペアになっていないままになります。 

第二に、単一の要素が他の要素と比較して大きすぎることはできません。 1 つの値が他のすべての値の合計を超える場合、そのユニットを個別の要素とペアにし続けることは不可能になります。最終的には、それに一致する外部トークンが不足するためです。 正式に言うと、`max(a)`より大きい`sum(a) - max(a)`の場合、最大の山を完全に一致させることはできません。 

この 2 つの条件も十分です。 それらが保持されている場合、大きな杭はその減少を吸収するのに十分な小さな杭によって常にサポートされているため、行き詰まることなく貪欲にペアリングを構築できます。 

ブルートフォースのアイデアでは、操作をシミュレートし、常に 2 つの非ゼロ要素を選択し、手がなくなるかすべてがゼロになるまでそれらをデクリメントします。 これは概念的には機能しますが、潜在的に$O(\sum a_i)$値が大きい場合は実行できません。 

重要な洞察は、ペアリングをシミュレートする必要がないということです。 単位の保存とペアリングの制約から導き出される実現可能性の条件を検証するだけで済みます。

 | 数学的チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 これは、すべての操作で必要なユニット除去の合計数を表します。 各操作では正確に 2 単位が削除されるため、どのような解も存在するにはこの合計が偶数になる必要があります。 
2. 合計が奇数の場合は、すぐに不可能と判断します。 どのような一連の操作を行っても、単一の残ったユニットを削除することはできません。 
3. 配列内の最大の要素を特定します。 この値は、その中のすべてのユニットが別のインデックスのユニットとペアになる必要があるため、最も制約されたパイルを表します。 
4. 最大値を除く残りのすべての要素の合計を計算します。 これは、最大のパイルと組み合わせることができる利用可能な「外部容量」の合計を表します。 
5. 最大要素がこの残りの合計より大きい場合は、「NO」を返します。 これは、たとえ他のすべての要素を最適に使用したとしても、最大のパイル内のすべてのユニットと一致するのに十分な個別のユニットがまだないことを示しています。 
6. それ以外の場合は、グローバル パリティ制約とローカル実現可能性制約の両方が満たされるため、「YES」を返します。 

### なぜ効果があるのか

 このプロセスは、各インデックスがその値と同じ数の頂点に寄与する完全なマッチングでエッジを構築しているとみなすことができます。 この制約により、自己ペアリングなしで完全な一致が存在することが保証されます。 

パリティ条件により、原則として完全な一致が可能になります。 優勢条件により、外部で一致できないほど大きすぎる頂点セットが存在しないことが保証されます。 これらを組み合わせることで、最大の山から選択されたユニットとペアリングするための代替インデックスが各段階で少なくとも 1 つ残るため、貪欲なペアリング プロセスが行き詰まることなく常に継続できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mx = max(a)
    
    if total % 2 != 0:
        print("NO")
        return
    
    if mx > total - mx:
        print("NO")
        return
    
    print("YES")

if __name__ == "__main__":
    solve()
```コードはまず、単一パスで合計と最大値を計算します。 パリティ チェックは厳密な必要条件であるため、何よりも前に実行されます。 2 番目のチェックでは、最大の要素を他のすべての要素と組み合わせて実行できるかどうかを確認します。 順序は、正確さではなく、早期終了の効率性のためにのみ重要です。

def run(inp: str) -> str:

    from collections import deque

 ## 特殊なケース

 重要なエッジケースは、1 つの要素が他のすべての要素の合計と正確に等しい場合です。 例えば、`[4, 1, 1, 2]`。 合計は 8 で偶数、最大値は 4、残りの合計も 4 になります。 条件`mx > total - mx`は false であるため、アルゴリズムはこのケースを受け入れます。 これは正しいです。なぜなら、最大の山は残り物を残さずに残りのすべてのユニットと正確に組み合わせることができるからです。 

もう一つの微妙なケースは、`[1, 1]`。 合計は偶数の 2 で、最大値は 1 ですが、残りの合計も 1 です。アルゴリズムはそれを受け入れ、両方の要素を直接ゼロに減らす単一の可能な演算と一致します。 

のようなケース`[3, 3, 3]`合計が 9 であるため拒否され、直ちにパリティが失敗します。 値のバランスが取れていても、ペアリングすると必ず 2 つのユニットが削除されるため、必然的に 1 つのユニットが残ります。
