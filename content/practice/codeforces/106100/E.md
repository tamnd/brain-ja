 ## 解決策
 ## 問題の理解

 次の文字で構成される文字列で表される風船の行が与えられます。`B`そして`R`。 

すべての赤い風船の直前に青い風船がある場合、その構成は正しいとみなされます。 文字列用語では、次のすべての出現が`R`次の 2 つの条件を満たす必要があります。 

1. 最初の文字にすることはできません。 
2. そのすぐ左の文字は、`B`。 

これは、有効な構成にはその位置に赤いバルーンが含まれていないことを意味します。`0`部分文字列はありません`"RR"`。 

隣接するバルーンの交換は最大 1 回のみ実行できます。 タスクは、そのようなスワップを 0 回または 1 回行った後に有効な構成に到達できるかどうかを判断することです。 

文字列の長さは最大 100 です。制限がこのように小さいため、可能なすべての隣接スワップを試して、結果の文字列をチェックするだけでも十分に高速です。 各スワップ後にすべての位置を調べて文字列を検証するソリューションでは、数千回の操作しか実行されません。 

微妙な点は、何が構成を有効にするのかを理解することです。 

考慮する：```
BBR
```答えは`YES`唯一の赤い風船のすぐ前に青い風船があるからです。 

よくある間違いは、配置が次のように交互になる必要があると想定することです。`BRBRBR...`。 それは必須ではありません。 

見落としやすいもう 1 つのケースは次のとおりです。```
RB
```答えは`YES`。 

隣接する 2 つのバルーンを交換すると、次のようになります。```
BR
```そして今度は赤い風船が青い風船を追いかけます。 

もう 1 つの例:```
RR
```答えは`NO`。 

可能な唯一の交換では、文字列が次のように維持されます。`"RR"`最初の赤いバルーンの前に青いバルーンがないため、これはまだ無効です。 

## アプローチ

 最も直接的なアイデアはブルートフォースです。 

まず、元の文字列がすでに有効かどうかを確認します。 そうであれば、答えはすぐに出ます`YES`なぜなら、スワップは最大 1 回しか実行できないからです。 

それ以外の場合は、隣接するすべてのペアを試してください。 ポジションごとに`i`、交換`s[i]`そして`s[i+1]`、結果の文字列が有効かどうかをテストし、元の順序に戻します。 何らかの試行が成功した場合は、印刷します`YES`。 

なぜこれが正しいのでしょうか? この問題により許可される操作は 1 つだけであり、その操作では隣接するバルーンを交換することしかできないためです。 このようなスワップをすべて列挙することで、あらゆる可能な動きをカバーできます。 

長さが最大 ​​100 の場合、隣接するスワップは最大 99 個になります。 有効性のチェックには時間がかかります`O(n)`時間。 総作業量は、`O(n²)`、これは最大でも約 10,000 文字の検査です。 

制約が小さいため、より高度な観察は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n²) | O(n) | 承認済み |

 この問題に対しては、ブルートフォースアプローチがすでに十分に最適です。 

## アルゴリズムのチュートリアル

 1. 文字列を読み取ります。 
2. 関数を定義する`valid(t)`。 

この関数は文字列を左から右にスキャンします。 

キャラクターが`R`、左の隣接要素があるかどうか、およびその隣接要素が`B`。 

いずれかの条件が失敗した場合は戻ります`False`。 

If the scan finishes, return`True`。 
3. 元の文字列が有効な場合は、次のように出力します。`YES`。 

問題では「最大 1 つのスワップ」と表示されているため、ゼロ スワップが許可されます。 
4. 文字列を変更可能な文字リストに変換します。 
5. すべてのインデックスについて`i`から`0`に`n-2`:

 ポジションを交換する`i`そして`i+1`。 

新しい取り決めが有効かどうかを確認してください。 

そうであれば、印刷してください`YES`そしてやめてください。 

続行する前にスワップを復元してください。 
6. 有効な配置を生成する隣接スワップがない場合は、次のように出力します。`NO`。 

### なぜ効果があるのか

 このアルゴリズムは、ゼロ移動で到達可能なすべての構成と、1 つの隣接するスワップで到達可能なすべての構成をチェックします。 

これらはまさに、問題によって許可されるすべての状態です。 妥当性テストは、すべての赤い風船が青い風船の直後に続く必要があるという要件に正確に一致します。 

すべての法的結果が検査され、ルールを満たす場合に正確に受け入れられるため、アルゴリズムは有効な解決策を見逃したり、無効な解決策を誤って受け入れたりすることができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid(s):
    n = len(s)
    for i in range(n):
        if s[i] == 'R':
            if i == 0 or s[i - 1] != 'B':
                return False
    return True

def solve():
    s = input().strip()

    if valid(s):
        print("YES")
        return

    arr = list(s)
    n = len(arr)

    for i in range(n - 1):
        arr[i], arr[i + 1] = arr[i + 1], arr[i]

        if valid(arr):
            print("YES")
            return

        arr[i], arr[i + 1] = arr[i + 1], arr[i]

    print("NO")

solve()
```の`valid`関数は、正しい配置の定義を直接エンコードします。 すべての赤い風船のすぐ左側に青い風船がなければなりません。 

ゼロスワップが許可されているため、メイン ルーチンは最初に元の文字列をチェックします。 その後、隣接するすべてのスワップを体系的に試行します。 

各テスト後にスワップを復元することが重要です。 復元しないと、後の反復では元の構成ではなく、変更された文字列が処理されることになります。 

文字列の長さは非常に短いため、これらの候補構成の構築とチェックは問題なく制限内に収まります。

## 特殊なケース

 次のことを考慮してください。```
RB
```赤いバルーンが先頭にあるため、初期設定は無効です。 アルゴリズムは隣接するスワップのみを試行し、次の結果を取得します。```
BR
```赤い風船の直前に青い風船があるので、答えは次のようになります。`YES`。 

考慮する：```
BBR
```アルゴリズムは、交換を試みる前に元の文字列をチェックします。 唯一の赤いバルーンの前に青いバルーンがあるため、構成はすでに正しいです。 ゼロスワップが許可されているため、答えは次のようになります。`YES`。 

考慮する：```
RR
```最初の赤い風船はルール違反です。 唯一の隣接するペアを交換しても、文字列は変更されません。 到達可能なすべての構成は無効なままであるため、アルゴリズムは正しく出力します。`NO`。 

考慮する：```
RBRR
```最初は、最後の赤い風船が別の赤い風船に続きます。 最後の 2 文字を交換すると、次のようになります。```
RBRR
```これは何も変わりませんが、中間のペアを交換すると次のようになります。```
BRRR
```まだ無効です。 このアルゴリズムは、隣接するすべてのスワップをチェックし、有効な到達可能な配置が存在する場合はそれを見つけます。 徹底的な列挙により、考えられるワン スワップ ソリューションが見落とされないことが保証されます。
