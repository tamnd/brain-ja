 ## 解決策
 ## 問題の理解

 私たちに最初に与えられたのは、`m`数値の順列の要素`1...n`。 これらの要素は固定されており、変更できません。 

残り`n - m`固定プレフィックスに表示されない番号を正確に使用して位置を埋める必要があります。 これらの位置を埋めた後、配列全体は次のすべての数値を含む有効な順列でなければなりません。`1`に`n`まさに一度。 

順列を完了するためのすべての有効な方法の中で、反転の数ができるだけ少ない方法が必要です。 

反転は位置のペアです`(i, j)`と`i < j`そして`p[i] > p[j]`。 

制約により許可されるのは、`n`まで`10^5`。 可能なすべての完了に対して反転を明示的にカウントするアルゴリズムは、絶望的に高価です。 残りの数値のすべての順列をチェックする場合でも、`(n-m)!`可能性はありますが、それはすぐに不可能になります。 大まかに直接施工が必要です`O(n log n)`時間以上。 

いくつかの特殊なケースは見落とされがちです。 

固定プレフィックスがすでに増加していると仮定します。```
n = 5
m = 4
prefix = [1, 2, 3, 4]
```唯一欠けている番号は、`5`したがって、答えは次のようになります。```
5
```もう 1 つの興味深いケースは次のとおりです。```
n = 4
m = 2
prefix = [4, 1]
```欠落している数字は、`{2, 3}`。 

それらを次のように配置すると、`[3, 2]`、接尾辞自体には反転が 1 つ含まれています。 

それらを次のように配置すると、`[2, 3]`、接尾辞には反転が含まれません。 

固定プレフィックスを伴う反転は両方の補完で同一であるため、2 番目の配置が最適です。 

不注意なアプローチでは、より大きなプレフィックス要素がサフィックスとより適切に相互作用するようにしようとする可能性がありますが、それらの相互反転は、欠落している値が配置される順序ではなく、どの値が欠落しているかによってのみ決定されます。 

## アプローチ

 ブルートフォースソリューションでは、欠落している数値のすべての順列を生成し、それを固定プレフィックスに追加し、結果として得られる順列の反転をカウントし、最良のものを保持します。 

これは、すべての有効な完了を検査するため、正しいです。 問題はクリア数です。 あれば`k = n-m`欠落番号があります`k!`可能性。 たとえ`k = 15`、これはすでに実用的な限界をはるかに超えています。 

重要な観察は、反転を 2 つのグループに分割することです。 

最初のグループは、完全に接尾辞内部の倒置で構成されます。 これらは、欠落している番号に対して選択した順序によって異なります。 

2 番目のグループは、左側の要素が固定プレフィックス内にあり、右側の要素がサフィックス内にある反転で構成されます。 

1 つの固定プレフィックス値を考慮します。`x`。 より小さいすべての欠損数`x`との反転を作成します`x`、および より大きいすべての欠損数`x`しません。 カウントは欠落している数値のセットのみに依存し、順序には依存しません。 接尾辞をどのように配置しても、接頭辞と接尾辞の反転の数は変わりません。 

つまり、影響を与えることができる唯一の部分は、接尾辞自体内の反転の数です。 

個別の数値のセットの中で、反転の可能な最小数は 0 であり、これは昇順に並べ替えることによって達成されます。 

したがって、最適な補完は、単に欠落している数値を昇順に並べ替えることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n-m)! · n²) | O(n) | 遅すぎる |
 | 最適 | O(n) または O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. 固定プレフィックスを読み取ります。 
3. プレフィックスにすでに表示されているすべての番号にマークを付けます。 
4. 以下の番号をスキャンします。`1`に`n`。 
5. マークされていない番号はすべて欠落番号であり、サフィックスに属している必要があります。 
6. 欠落している数値をすべて昇順に出力します。 

ステップ 6 が最適な理由は、接尾辞の順序に関係なく接頭辞と接尾辞の反転数が固定されるのに対し、順序が増加すると接尾辞自体の反転が 0 (可能な最小値) になるためです。 

### なぜ効果があるのか

 欠落している番号のセットは、固定プレフィックスによって完全に決定されます。 

すべてのプレフィックス要素について`p[i]`、より小さい接尾辞要素の数`p[i]`サフィックスには常にまったく同じ欠損値のセットが含まれるため、この問題は修正されました。 これらの値を並べ替えても、次の値より小さい値の数を変更することはできません。`p[i]`。 

したがって、少なくとも 1 つの接頭辞要素を含むすべての反転は、答えに一定量寄与します。 

残る唯一の反転は、完全に接尾辞内のペアによって形成される反転です。 一連の個別の数値は、厳密に増加している場合に限り、反転がゼロになります。 ゼロは可能な最小反転数であるため、欠落している数値をソートすると最適な補完が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
prefix = list(map(int, input().split()))

used = [False] * (n + 1)

for x in prefix:
    used[x] = True

ans = []
for x in range(1, n + 1):
    if not used[x]:
        ans.append(str(x))

print(" ".join(ans))
```実装は証明に直接続きます。 

の`used`配列には、固定プレフィックスにすでに出現している値が記録されます。 プレフィックスには順列からの個別の値が含まれるため、すべての値は最大 1 回マークされます。 

その後、1回のスキャンで`1`に`n`使用されなかったすべての番号を収集します。 スキャンは昇順で実行されるため、結果のサフィックスはすでにソートされています。 

反転カウントは必要ありません。 この証明は、ソートされた欠損数値が常に最適であることを示しています。 

微妙な点の 1 つは、順列全体ではなく接尾辞のみを出力することです。 この問題は位置を占める値を尋ねます`m+1`を通して`n`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    prefix = list(map(int, input().split()))

    used = [False] * (n + 1)

    for x in prefix:
        used[x] = True

    ans = []
    for x in range(1, n + 1):
        if not used[x]:
            ans.append(str(x))

    print(" ".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided samples
assert run("10 7\n5 1 2 9 3 4 6\n") == "7 8 10", "sample 1"
assert run("5 4\n1 2 3 4\n") == "5", "sample 2"

# custom cases
assert run("2 1\n2\n") == "1", "minimum valid size"
assert run("4 2\n4 1\n") == "2 3", "sorted missing values"
assert run("6 5\n6 5 4 3 2\n") == "1", "single missing value"
assert run("8 3\n2 4 6\n") == "1 3 5 7 8", "multiple gaps"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次のことを考慮してください。```
4 2
4 1
```欠落している数字は、`{2, 3}`。 

アルゴリズムは次を出力します。```
2 3
```完成した置換は次のようになります。```
4 1 2 3
```接尾辞のその他の順序 (例:`3 2`、接尾辞内に追加の反転が導入されます。 欠落しているセットがまだ残っているため、プレフィックスとサフィックスの反転は変更されません。`{2,3}`。 アルゴリズムは、接尾辞の反転がゼロの配置を正しく選択します。 

次に、次のことを考えてみましょう。```
5 4
1 2 3 4
```唯一の欠損値は`5`。 

からのスキャン`1`に`5`マークされていない数値を 1 つだけ見つけて出力します。```
5
```選択の自由はなく、アルゴリズムはこの境界ケースを自然に処理します。 

最後に、次のことを考慮してください。```
7 3
7 6 5
```欠落している番号は次のとおりです。```
1 2 3 4
```アルゴリズムはそれらを昇順に出力します。 

プレフィックスに大きな値が含まれているため、サフィックスとの反転が多く発生しますが、欠損値はすべてプレフィックスの値よりも小さいため、これらの反転は避けられません。 サフィックスを再配置しても、その数を減らすことはできません。 制御可能な反転はサフィックス自体の内部のみであり、順序を増加させると反転がゼロに最小化されます。
