 ## 問題の理解

 長い配列が与えられました`A`とターゲット配列`B`。 

選択したセグメントに対して`A[L..R]`、セグメントの長さが長くなるまで要素を繰り返し削除できます。`m = |B|`。 削除ルールは特殊です。要素は、右隣の要素があり、2 つの値が異なる場合にのみ削除できます。 

タスクは、次のセグメントが何個あるかを数えることです。`A`正確に変換できます`B`。 

重要な制約は、`n`と同じ大きさにすることができます`2 · 10^5`、 その間`m ≤ 100`。 すべてを検査するソリューション`O(n²)`セグメントはすぐには不可能です。 平`O(n² / 10)`大きすぎるでしょう。 の小さな値`m`が本当のヒントです。 これは、複雑さがおおよそ次のような動的プログラミング ソリューションを構築する必要があることを示唆しています。`O(nm)`。 

問題の危険な部分は、どの要素が実際に削除可能かを理解することです。 

次のセグメントを考えてみましょう。```
1 1 2
```2枚目は削除させていただく場合がございます`1`、最初のを削除します`1`、残すのみ`2`。 

次に、次のことを考えてみましょう。```
1 1
```削除はできません。 最初の要素はその右隣の要素と等しく、2 番目の要素には右隣の要素がまったくありません。 

等しい値の末尾ブロック全体が特別です。 セグメントが次で終わる場合:```
... 5 5 5
```その後、3つすべてが後続します`5`彼らは生き残ることを余儀なくされています。 それらを削除することはできません。 

この観察が解決策の基礎となります。 

### 明らかではないエッジケース 1```
A = [1, 1]
B = [1]
```答えは`0`。 

不用意に解釈すると、次のいずれかが考えられるかもしれません。`1`は取り外し可能です。 それはできません。 一連のサフィックス全体は等しい値で構成されているため、どちらの要素も削除できません。 

### 明らかではないエッジケース 2```
A = [1, 2, 1]
B = [1, 1]
```答えは`1`。 

真ん中`2`右隣のものとは異なるため、削除できます。 結果は次のようになります`[1,1]`。 

実行を個別に保存することだけを考えるソリューションでは、実行全体を削除すると 2 つの等しい値が隣接してマージされる可能性があることを見落としがちです。 

### 明らかではないエッジケース 3```
A = [7, 7, 7]
B = [7, 7]
```答えは`0`。 

後続ランレングスは`3`、その実行内のすべての要素は強制的に残されます。 目安の長さはあくまで目安なので、`2`、変身は不可能です。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのセグメントを検査し、次のように変換できるかどうかを判断します。`B`。 

がある`O(n²)`セグメント。 たとえ`O(m)`検証手順の全体的な複雑さは次のとおりです。`4 · 10^10`最悪の場合の操作は完全に不可能です。 

重要な観察は、セグメントから取得可能なすべての最終配列を特徴付けることです。 

任意のセグメントを取得し、同じ値の最後のランを調べます。```
x x x x
```その実行のあらゆる要素は生き残らなければなりません。 

最終滑走前のすべての順位はオプションです。 それを保持することも、最終的には削除することもできます。 

結果として、セグメントは`B`次の場合にのみ:

 1. 後続実行全体が次の接尾辞にマッピングされます。`B`。 
2. 残りのプレフィックス`B`その実行の前のサブシーケンスとして表示されます。 

これにより、問題は部分列のカウント問題に変わります。 

以来`m ≤ 100`、スキャンできます`A`一度実行して、すべてのプレフィックスの動的プログラミング値を維持します。`B`。 考えられるすべてのトレーリング実行に対して、次の 1 つの質問をします。```

```民主党は次のように答えています。`O(1)`前処理後の時間。

 ## アルゴリズムのチュートリアル

 1. すべてのインデックスで終了する等しい値の実行の開始位置を計算します。 

インデックスの場合`R`で始まる実行に属します`s`の場合、必須のサフィックスの長さは次のようになります。```
k = R - s + 1
```2. 配列を左から右にスキャンし、サブシーケンスの DP 値を維持します。`B`。 

させて`dp[j]`は、次の値に等しいサブシーケンスの可能な最大の最初の位置を示します。`B[1..j]`処理されたプレフィックス内。 
3. 走行開始位置ごとに`s`、すべてのスナップショットを保存します`dp[j]`位置処理後の値`s - 1`。 

後で正確にこれらの値が必要になります。 
4. すべての接尾辞の長さを事前計算する`k`最後かどうか`k`の要素`B`すべてある値に等しい`v`。 
5. 各実行を処理します。`A`。 

実行が開始されるとします。`s`、価値があります`v`、長さ`len`。 

考えられるすべてのサフィックスの長さについて:```
k = 1 .. min(len, m)
```次で終わるセグメントに対応します:```
R = s + k - 1
```最後かどうかを確認してください`k`の要素`B`すべて等しい`v`。 
6. そうしないと、このセグメントは決して機能しません。 

「はい」の場合は、次のようにしましょう。```
p = m - k
```実行前に取得する必要がある要素の数になります。 
7. いつ`p = 0`、ターゲット全体は必須の実行によって形成されます。 任意の開始位置:```
1 ≤ L ≤ s
```有効です、貢献しています`s`セグメント。 
8. いつ`p > 0`に等しい部分列が必要です。`B[1..p]`走る前に。 

位置に保存された DP スナップショット`s - 1`与える:```
mx = maximum first position of such a subsequence
```すべての開始位置:```
L ≤ mx
```動作します。 

追加`mx`答えに。 

### なぜ効果があるのか

 セグメントの最終実行は不変です。 その実行内のすべての要素は、すべての有効な変換で存続します。 

最終ラン前のすべてのポジションは取り外し可能です。 不要な要素を削除することで、実行に先立つプレフィックスのサブシーケンスを正確に保持できます。 

したがって、有効な変換は、次のプレフィックスに等しいサブシーケンスを選択することによって完全に決定されます。`B`実行前に、必須の実行をサフィックスと照合します。`B`。 

DP は、一致した各プレフィックスの可能な最新の開始位置を保存します。`B`。 試合がその位置から開始できる場合`x`、その後、すべてのセグメントが始まります`L ≤ x`その一致が含まれています。 このような開始をカウントすると、有効なセグメントの数が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
A = list(map(int, input().split()))
B = list(map(int, input().split()))

# run starts
run_start = [0] * n
run_start[0] = 0
for i in range(1, n):
    if A[i] == A[i - 1]:
        run_start[i] = run_start[i - 1]
    else:
        run_start[i] = i

# group positions by run start
runs = []
i = 0
while i < n:
    j = i
    while j + 1 < n and A[j + 1] == A[i]:
        j += 1
    runs.append((i, j, A[i]))
    i = j + 1

# snapshots[s] = dp state after processing prefix ending at s-1
snapshots = {}

dp = [0] * (m + 1)

for pos in range(n + 1):
    snapshots[pos] = dp[:]

    if pos == n:
        break

    x = A[pos]

    for j in range(m, 0, -1):
        if x == B[j - 1]:
            if j == 1:
                dp[1] = max(dp[1], pos + 1)
            elif dp[j - 1]:
                dp[j] = max(dp[j], dp[j - 1])

# suffix information of B
suffix_ok = [False] * (m + 1)
suffix_val = [None] * (m + 1)

for k in range(1, m + 1):
    v = B[m - 1]
    good = True
    for t in range(m - k, m):
        if B[t] != v:
            good = False
            break
    suffix_ok[k] = good
    suffix_val[k] = v

ans = 0

for start, end, value in runs:
    length = end - start + 1

    limit = min(length, m)

    state = snapshots[start]

    for k in range(1, limit + 1):
        if not suffix_ok[k]:
            continue
        if suffix_val[k] != value:
            continue

        p = m - k

        if p == 0:
            ans += start + 1
        else:
            ans += state[p]

print(ans)
```DP アレイには、`m + 1`状態なので更新にはコストがかかります`O(m)`配列要素ごとに。 

の意味`dp[j]`微妙です。 一致したサブシーケンスの可能な最大の最初の位置を格納します。`B[1..j]`。 最大の最初の位置を使用することはまさに必要なことです。その位置を超えないすべてのセグメントの開始が有効だからです。 

スナップショットは、各位置を処理する前に取得されます。 実行がインデックスで開始されるとき`s`で終わるプレフィックスからの情報のみが必要です。`s - 1`、だからこそ`snapshots[s]`が正しい状態です。 

この実装では、DP 値内の 1 から始まる位置を使用します。 これにより、有効な開始の数が保存された位置と正確に一致するため、カウント式が簡単になります。

 ## 特殊なケース

 のために```
A = [1, 1]
B = [1]
```後続のランレングスは`2`、 その間`|B| = 1`。 

アルゴリズムはチェックのみを行います`k ≤ m`。 有効な構成が存在しないため、寄与はゼロです。 

のために```
A = [1, 2, 1]
B = [1, 1]
```最後のランには長さがある`1`の最後の要素と一致します。`B`。 

実行前の DP スナップショットには有効なサブシーケンスが記録されます`[1]`位置から開始`1`、有効なセグメントが 1 つだけ生成されます。 

のために```
A = [7, 7, 7]
B = [7, 7]
```後続のランレングスはすでに`3`。 

3 つの要素はすべて必須の存続要素であるため、最後の位置で終了するセグメントの長さを縮小することはできません。`2`。 必要なサフィックスの長さを満たせないため、アルゴリズムは自動的に拒否します。
