 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`そしてバイナリパターン`t`。 

の文字を反転することができます`s`。 フリップごとに変化します`0`の中へ`1`または`1`の中へ`0`、1単位の費用がかかります。 

あらゆる可能な値に対して`k`から`0`に`n - m + 1`、結果の文字列にパターンが含まれるように、必要なフリップの最小数を決定する必要があります。`t`その通り`k`部分文字列として回します。 

文字列の長さは満たしています`m ≤ n ≤ 500`。 これが制約に関する重要な観察です。 長さ 500 は、すべての変更された文字列に対して総当たりするには大きすぎます。`2^n`可能性。 同時に、500 は十分小さいので、およその動的プログラミングを実行できます。`500 × 500`州は現実的です。 

難しいのは、`t`重複する可能性があります。 たとえば、次の場合`t = "101"`の場合、2 つのオカレンスで文字を共有できます。 出現を独立して処理するソリューションでは、不正確な答えが生成されます。 

考慮する：```
n = 3, m = 2
s = 00
t = 00
```元の文字列にはすでに 1 つの出現箇所が含まれています。 

のために`k = 0`、最初の文字のみを変更すると、次のようになります。```
00 -> 10
```現在、何も発生していないため、答えは次のようになります。`1`。 

現在存在する一致のみをチェックして貪欲に削除する不用意なソリューションでは、安価な変更を簡単に見逃す可能性があります。 

もう 1 つの重要なケースは、重複する一致です。```
n = 5
s = 11111
t = 111
```文字列には次の 3 回の出現が含まれています。`111`:```
11111
^^^
 ^^^
  ^^^
```単一の中間ビットを変更すると、複数のオカレンスが一度に破棄されます。 発生を個別にカウントするアプローチでは、コストが過大評価されます。 

最後のエッジケースは、次の値が存在する場合に発生します。`k`不可能です。 変更された文字列に正確に同じ数の出現を含めることができない場合は、次のように出力する必要があります。`-1`。 

例えば：```
n = 2
m = 2
```長さ 2 のサブストリングは 1 つしか存在しないため、2 つ出現することは不可能です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 長さのすべてのバイナリ文字列を列挙します`n`からハミング距離を計算します。`s`、何回数えますか`t`が発生し、発生回数ごとに最良の回答を保持します。 

これは、考えられるすべての最終文字列を直接チェックするため、正しいです。 残念ながら検査が必要です`2^n`文字列。 たとえ`n = 50`これはすでに絶望的ですが、実際の限界は`500`。 

問題の構造は、最終的な文字列を一度に 1 文字ずつ構築することを示唆しています。 新しいビットを追加するとき、将来の一致に関して重要なのは 1 つだけです。それはパターンの量です。`t`現在、接尾辞として一致します。 

それはまさに KMP オートマトンによって追跡される状態です。 

次のことがわかっているとします。```
current matched prefix length of t
```そして、どちらかを追加します`0`または`1`。 

KMP 遷移テーブルを使用すると、次のことをすぐに判断できます。```
new matched length
whether a full occurrence of t was completed
```これにより、文字列構築プロセスが有限状態オートマトンに変換されます。 

次に、動的プログラミングを実行します。 位置を左から右に処理する際に、以下を追跡します。```
automaton state
number of occurrences created so far
minimum modification cost
```すべての位置について、可能な両方のビットを配置してみます。 選択したビットが元の文字と異なる場合、コストは 1 増加します。`s`。 

以来`n ≤ 500`、可能な出現回数も最大です。`500`、この DP が実現可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | お(1) | 遅すぎる |
 | 最適な DP + KMP オートマトン | O(n · m · (n - m + 1)) | O(m · (n - m + 1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### オートマトンの構築

 まず、次の KMP プレフィックス関数を計算します。`t`。 

すべての州について`j`現在一致しているプレフィックスの長さと両方の文字を表します`0`そして`1`、事前計算:```
next_state[j][bit]
add_occurrence[j][bit]
```ビットを追加するとパターン全体が完成する場合、`add_occurrence`になる`1`。 

### 動的プログラミング

 しましょう:```
dp[state][cnt]
```現在のプレフィックスを処理した後の最小変更コストであり、オートマトン状態で終了します`state`そして正確に作成した`cnt`出来事。 

初期化:```
dp[0][0] = 0
```他のすべての状態は無限として開始されます。 

すべてのポジションについて:

 1. 新しい DP テーブルを作成します。 
2. 到達可能なすべてのものに対して`(state, cnt)`。 
3. 置いてみる`0`。 
4. 置いてみる`1`。 
5. オートマトン遷移を使用して新しい状態を取得します。 
6. 一致が完了した場合は、出現回数を増やします。 
7. 選択したビットが元の文字と異なる場合は、コストに 1 を加算します。`s`。 
8. 新しい DP 状態を緩和します。 

すべての位置を処理した後、すべてのオートマトンの状態を調べます。 

出現回数ごとに`k`、すべての終了状態の中で最小コストを取得します。 

正確に到達する状態がない場合`k`、出力`-1`。 

### なぜ効果があるのか

 KMP 状態には、すでに構築されたプレフィックスに関して必要なすべての情報が含まれています。 今後の一致は、接頭辞でもある最長の接尾辞のみに依存します。`t`、構築された文字列全体ではありません。 

DP は、変更された可能性のあるすべてのバイナリ文字列を調査します。 このような文字列ごとに、以下を正確に記録します。```
its modification cost
its current automaton state
its number of completed occurrences
```すべての遷移は、最後の文字列に 1 文字を追加することに対応します。 すべての可能性が検討され、DP は常に各状態の最小コストを維持するため、すべての出現回数に対する最終的な答えは最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 9

n, m = map(int, input().split())
s = input().strip()
t = input().strip()

pi = [0] * m
for i in range(1, m):
    j = pi[i - 1]
    while j and t[i] != t[j]:
        j = pi[j - 1]
    if t[i] == t[j]:
        j += 1
    pi[i] = j

nxt = [[0] * 2 for _ in range(m)]
add = [[0] * 2 for _ in range(m)]

for state in range(m):
    for bit in range(2):
        ch = str(bit)
        cur = state

        while cur and t[cur] != ch:
            cur = pi[cur - 1]

        if t[cur] == ch:
            cur += 1

        if cur == m:
            add[state][bit] = 1
            cur = pi[m - 1]

        nxt[state][bit] = cur

max_occ = n - m + 1

dp = [[INF] * (max_occ + 1) for _ in range(m)]
dp[0][0] = 0

for i in range(n):
    ndp = [[INF] * (max_occ + 1) for _ in range(m)]

    for state in range(m):
        row = dp[state]

        for cnt in range(max_occ + 1):
            cur_cost = row[cnt]

            if cur_cost == INF:
                continue

            for bit in range(2):
                ns = nxt[state][bit]
                nc = cnt + add[state][bit]

                if nc > max_occ:
                    continue

                cost = cur_cost + (bit != (ord(s[i]) - ord('0')))

                if cost < ndp[ns][nc]:
                    ndp[ns][nc] = cost

    dp = ndp

ans = [INF] * (max_occ + 1)

for state in range(m):
    for cnt in range(max_occ + 1):
        ans[cnt] = min(ans[cnt], dp[state][cnt])

for k in range(max_occ + 1):
    if ans[k] == INF:
        print(-1, end=" ")
    else:
        print(ans[k], end=" ")
print()
```prefix-function は KMP 障害リンクを構築します。 これらのリンクを使用して、オートマトン遷移テーブルが一度構築され、DP 全体で再利用されます。 

DP テーブルの位置がロールオーバーされます。 現在のレイヤーと次のレイヤーのみが必要になるため、メモリが 3 次元から 2 次元に削減されます。 

微妙な点は、完了した試合の処理です。 長さに達してから`m`、出現を 1 つ数えてすぐにジャンプします。`pi[m - 1]`。 これにより、重複する一致を正しくカウントできるようになります。 

もう 1 つの詳細は、オートマトンの状態の範囲が次のとおりであることです。`0`に`m - 1`。 州`m`永久に保存されることはありません。 一致が完了するたびにそれをカウントし、プレフィックス関数を介してフォールバックします。

 ## 特殊なケース

 次のことを考慮してください。```
2 2
01
01
```長さ 2 の部分文字列は 1 つだけあります。 

このアルゴリズムでは、一致が完了するたびにカウントが 1 つずつ増加し、長さ 2 のパターンが終了できる位置は 1 つだけであるため、1 を超える出現カウントは生成されません。 

次に、次のことを考えてみましょう。```
5 3
11111
111
```重複する現象が 3 つあります。 

オートマトンが一致を完了すると、次の状態に戻ります。`pi[m - 1]`ゼロにリセットするのではなく。 これにより、重複情報が保存され、次の発生が前の発生のすぐ内側で開始できるようになります。 

ついに：```
3 2
000
11
```一部の出現回数は修正に関係なく不可能な場合があります。 

これらの DP 状態は、計算全体を通じて無限大に留まります。 それらは次のように印刷されます`-1`、必要な出力形式と正確に一致します。
