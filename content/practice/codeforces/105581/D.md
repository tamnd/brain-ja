 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$N \times M$。 各セルは、初期の「明るさ」値を持つウィンドウを表します。 その明るさは局所的な影響を表すだけでなく、建物自体を含む建物内のすべての窓に蚊を送り込む源として機能します。 

位置にあるウィンドウ$(i, j)$対象の窓に蚊を侵入させる$(a, b)$チェビシェフ距離に基づく減衰規則によると、次のようになります。$$\left\lfloor \frac{F_{i,j}}{2^{\max(|a-i|, |b-j|)}} \right\rfloor$$すべてのソース ウィンドウはすべてのターゲット ウィンドウに独立して寄与し、ウィンドウに到達する最終的な蚊の数は、すべてのソースからのすべての寄与の合計になります。 

各ウィンドウで最大でホストできるのは、$S$蚊。 それを超える超過分は$S$その窓では地面に落ちたと考えられます。 このタスクは、すべての窓に正常に定着した蚊の総数 (窓ごとの収容力制限を適用した後) と、落下した蚊の総数の 2 つの値を計算することです。 

制約$N, M \le 500$最大 250,000 セルを意味します。 ソースとターゲット間の単純な全ペアの相互作用は、最悪のケースをすでに示唆しています。$6.25 \times 10^{10}$これは 1 秒にしては大きすぎるインタラクションです。 それぞれの貢献があったとしても、$O(1)$、これは不可能です。 

重要な構造特性は、寄与がチェビシェフ距離のみに依存することです。これは、寄与が各光源を中心とする正方形上で一定であることを意味します。 この対称性により、すべてのペアを明示的に列挙するのではなく、集計が可能になります。 

明るさがゼロの場合、微妙なエッジケースが発生します。 このようなセルはどこにでも何も貢献しませんが、単純な実装ではセルを伝播するのに時間を無駄にする可能性があります。 

もう 1 つの問題は、セルごとの中間合計のオーバーフローです。 最終的なクランプは次の時点で行われますが、$S \le 10^9$、慎重に管理しないと、中間合計がこれを大幅に超える可能性があります。 

最後に、減衰は距離が指数関数的になります。 距離が約 9 ～ 10 を超えると、最大輝度 500 に対してほとんどの寄与がゼロになります。これは、2 による除算を繰り返すとすぐに値がゼロになるためです。 このカットオフを無視すると、パフォーマンスに大きな違いが生じます。 

## アプローチ

 ブルート フォース手法は簡単です。すべてのソース セルに対して、すべてのターゲット セルを反復処理し、チェビシェフ距離を計算し、次の整数除算を適用します。$2^d$、結果をターゲットに追加します。 これは定義に直接従うため、正しいです。 ただし、完全なパフォーマンスを実行します。$N^2 M^2$計算、つまり約$2.5 \times 10^{10}$実現可能性をはるかに超えた最悪の場合の作戦。 

重要な観察は、各ソースが距離レイヤーのみに依存するパターンで値を分布していることです。 固定ソースの場合、チェビシェフ距離にあるすべてのセル$d$四角いリングを形成します。 各セルを個別に更新する代わりに、層ごとに貢献を蓄積するという観点から考えることができます。 各層$d$はソースを中心とする正方形に対応し、その層全体の寄与値は一定です。 

これにより問題は、各ソースが生成するグリッド上に多数の正方形の範囲加算を適用することになります。$O(\log F_{i,j})$2 で十分に除算すると値がゼロになるため、意味のあるレイヤーになります。このような平方更新は 2D 差分配列を使用して効率的に処理できます。各平方更新は 2 次元で行われます。$O(1)$、最終的な値はプレフィックスの合計で再構築されます。 

入ってくる蚊の合計の完全なグリッドを構築した後、最終パスでセルごとに容量制約を適用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N^2 M^2)$|$O(NM)$| 遅すぎる |
 | レイヤー + 2D 差分 |$O(NM \log F)$|$O(NM)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各セルをソースとして処理し、その影響を距離レイヤーに分解します。 

1. 各セルについて$(i, j)$、 扱う$F_{i,j}$この値は、最初のレイヤー内のそれ自体にのみ影響します。 
2. 距離ごとに$d \ge 1$、値を計算します$v_d = \left\lfloor \frac{F_{i,j}}{2^d} \right\rfloor$。 もし$v_d = 0$、より深い層もすべてゼロになるため、このソースからさらに離れた場所では処理を停止します。 
3. 一定距離ごと$d$、チェビシェフ距離を正確に持つすべてのセル$d$一辺の長さを持つ正方形の境界線を形成する$2d+1$。 境界線のみを明示的に更新する代わりに、ネストされた正方形からレイヤーごとに寄与が蓄積されるという事実を利用します。 
4. 各レイヤーの効果を正方形上の加算に変換します。$[i-d, i+d] \times [j-d, j+d]$。 この正方形の表現は、レイヤーの寄与が累積的であるため有効です。つまり、距離内のすべてのセルです。$d$少なくとも受け取る$v_d$、より深い層は内部領域を洗練します。 
5. 2D 差分配列を使用してこれらの平方更新を適用します。 各更新は追加によって実行されます$v_d$左上隅に追加し、境界で適切に減算し、後でプレフィックス合計を介して再構成します。 
6. すべてのソースとすべてのレイヤーを処理した後、差分配列に対する 2D プレフィックス合計を使用して、入ってくる蚊の総数の最終グリッドを構築します。 
7. 最後に、各セルについて、定着した蚊を次のように計算します。$\min(\text{total}[i][j], S)$決済額とオーバーフロー額の両方を累積します。 

### なぜ効果があるのか

 各ソースは独立して寄与し、減衰はチェビシェフ距離のみに依存し、一定の寄与レベルのネストされた正方形領域が作成されます。 各ソースを単調減少する正方形の層に分解することにより、すべてのセルは、その正方形がそれをカバーするすべての有効な層の寄与の正確な合計を受け取ります。 2D 差分構造は、軸に沿った長方形領域の加算的な重ね合わせを正確に表現し、各正方形のレイヤーがそのような長方形の組み合わせとして表現されるため、正確性が保たれます。 各レイヤーは独立して適用され、線形に再構築されるため、寄与が二重にカウントされたり欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add(diff, n, m, x1, y1, x2, y2, val):
    if x1 > x2 or y1 > y2:
        return
    x1 = max(0, x1)
    y1 = max(0, y1)
    x2 = min(n - 1, x2)
    y2 = min(m - 1, y2)
    diff[x1][y1] += val
    if x2 + 1 < n:
        diff[x2 + 1][y1] -= val
    if y2 + 1 < m:
        diff[x1][y2 + 1] -= val
    if x2 + 1 < n and y2 + 1 < m:
        diff[x2 + 1][y2 + 1] += val

def solve():
    n, m, s = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    diff = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n):
        for j in range(m):
            f = g[i][j]
            if f == 0:
                continue
            d = 0
            while f > 0:
                val = f >> d
                if val == 0:
                    break
                x1, x2 = i - d, i + d
                y1, y2 = j - d, j + d
                add(diff, n, m, x1, y1, x2, y2, val)
                d += 1

    pref = [[0] * (m + 1) for _ in range(n + 1)]

    for i in range(n):
        for j in range(m):
            pref[i][j] = diff[i][j]
            if i > 0:
                pref[i][j] += pref[i - 1][j]
            if j > 0:
                pref[i][j] += pref[i][j - 1]
            if i > 0 and j > 0:
                pref[i][j] -= pref[i - 1][j - 1]

    total_ok = 0
    total_fall = 0

    for i in range(n):
        for j in range(m):
            v = pref[i][j]
            if v <= s:
                total_ok += v
            else:
                total_ok += s
                total_fall += v - s

    print(total_ok, total_fall)

if __name__ == "__main__":
    solve()
```この実装では、各ソースが指数関数的に減少する値を持つ拡大平方更新のシーケンスに寄与する 2D 差分配列を構築します。 ビットシフト`f >> d`2 の累乗による除算を直接エンコードします。 プレフィックス再構成ステップでは、差分表現をセルごとの実際の累積値に変換します。 

最後のループでは、セルごとの容量制約を適用し、定着した蚊をオーバーフローから分離します。 

微妙な詳細は、差分配列内の境界グリッドです。 サイズは次のとおりです$n+1 \times m+1$そのため、境界減算ではメイン ロジック内で条件処理を繰り返す必要がありません。 もう 1 つの重要な点は、輝度ゼロのセルを早期にスキップすることです。これにより、不必要なレイヤー ループが回避されます。 

## 実用的な例

 伝播を説明するために、単純化したケースをトレースします。 

入力:```
2 2 4
4 0
0 0
```ここではセル (0,0) のみが寄与します。 

| ソース (i,j) | d | 値 (f>>d) | 影響を受ける地域 | メモ |
 | --- | --- | --- | --- | --- |
 | (0,0) | 0 | 4 | 距離 0 内のすべてのセル | それ自体だけ |
 | (0,0) | 1 | 2 | 平方 (0..1,0..1) | すべてのセルは少なくとも 2 | を取得します。 
| (0,0) | 2 | 1 | 平方 (0..1,0..1) | まだ有効です |
 | (0,0) | 3 | 0 | 停止 | 今後の更新はありません |

 再構築後の最終グリッド:```
7 3
3 3
```もし$S = 5$、合計決済額は$5 + 3 + 3 + 3 = 14$、秋は$(7-5)=2$。 

このトレースは、入れ子になった正方形がレイヤーごとに寄与を蓄積する様子と、より遠くのレイヤーが同じ領域に影響を与え続ける様子を示しています。

 ## 特殊なケース

 重要なエッジケースは、すべての輝度値がゼロの場合です。 アルゴリズムはすべての更新を即座にスキップし、プレフィックス グリッドはゼロのままになります。 したがって、すべてのセルには蚊がゼロになるため、定着した蚊と落下した蚊の合計は両方ともゼロになります。 

別のケースは、各セルの最大輝度です。 各セルは約 10 レイヤーに寄与しますが、値はすぐにゼロに低下します。 差分配列は、セルごとの爆発を起こすことなく、重複する大きな正方形の更新を処理します。 

最後に、次の場合$S = 1$ほぼすべての余分なものを強制的に落とします。 このアルゴリズムは依然として最初に合計を計算し、最後にクリッピングのみを適用するため、容量の制約に関係なく正確性が保証されます。
