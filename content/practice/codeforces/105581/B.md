 ## 解決策
 ## 問題の理解

 2 つの固定点 A と B の間の直線セグメントに沿って単位速度で往復し続けてパトロールする警察官が与えられています。 この動作は完全に周期的です。時間 0 の A から始まり、B に進み、すぐに向きを変えて A に戻り、これを一時停止することなく無限に繰り返します。 

ある時点 T で、外部イベントがこの動作を中断します。 まさにその瞬間、警察官が現在セグメント上のどこにいるかに関係なく、巡回を停止し、代わりに同じ線上の 3 番目の点 C に向かって再び単位速度で直接歩きます。 タスクは、時刻 T から C に到着するまでにかかる時間を計算することです。 

入力により、パトロール セグメントの終点として A と B が与えられ、次に T と C が与えられます。重要な隠れたタスクは、この往復運動による時刻 T における警察官の正確な位置を特定し、C までの残りの直線移動時間を計算することです。 

この制約により、最大 10^5 の座標と最大 10^9 の時間が許可されます。 T が大きくなる可能性があるため、1 秒ずつステップを進めるシミュレーションは不可能であるため、どのソリューションでも周期運動の算術構造を使用して位置を計算する必要があります。 

単純な落とし穴は、警察官が常に A から B へのみ移動し、方向の反転を無視していると仮定することです。 もう 1 つは、方向はセグメント長の完全な走査が何回行われたかによって決まるということを忘れていることです。 

具体的なエッジケース:

 入力:

 A = 3、B = 8、T = 10、C = 1

 t = 0 では彼は 3 にあり、t = 5 では彼は 8 にあり、t = 10 では彼は 3 に戻ります。単調な動きを想定した間違ったアプローチでは、彼は誤って 13 に配置されますが、これはセグメントの外側で無効です。 

正しい出力は実際の振動から計算され、再び T = 3 での位置が与えられるため、C までの時間は |3 − 1| となります。 = 2。 

別のエッジ ケースは、T がちょうど転換点に着地したときに発生します。この場合、方向は瞬時に反転しますが、位置は終点のままです。 

## アプローチ

 ブルート フォース シミュレーションでは、現在の位置と方向を維持しながら、終点に到達するたびに方向を反転しながら、警察官を 1 秒ずつ進めます。 1 秒ごとに O(1) のコストがかかるため、合計の複雑さは O(T) になります。 これは正しいですが、T が 10^9 に達すると完全に実行不可能になります。 

重要な観察は、その動きが長さ L = |A − B| のセグメント上で周期的であるということです。 1 つの完全なサイクルは、A から B への往復の移動で構成され、時間 2L で距離 2L をカバーします。 段階的にシミュレーションする代わりに、サイクル長 2L を法として時間 T を短縮し、警察官がこのサイクル内のどこにいるかを判断できます。 

サイクル内の残り時間が分かると、位置は単純な線形関数になります。つまり、最初に A から B に移動し、次に B から A に戻ります。これにより、すべてのシミュレーションが削除され、問題が定数時間の演算に削減されます。

 | ブルートフォースシミュレーション | O(T) | お(1) | 遅すぎる |
 | サイクル削減 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 WLOG では A と B がセグメントを定義すると仮定し、L = |A − B| を定義します。 A をサイクルの開始エンドポイントとして扱います。 

1. L = |A − B| を計算します。 これは巡回員の片足の距離なので、一周すると2Lの長さになります。 
2. 現在のサイクル内での士官の有効時間を決定します: t = T mod (2L)。 動作は正確に繰り返されるため、これより前の完全なサイクルは最終位置に影響しません。 
3. t ≤ L の場合、警察官は A から B に向かって前足で立っているため、彼の位置は A + 方向 * t になります。ここで、方向は A < B かどうかによって決まります。 
4. t > L の場合、彼はリターンレグにいます。 これを B からの残りの前方距離に変換します: t' = t − L、その場合、位置は B − 方向 * t' となります。 
5. 時間 T における位置 P がわかったら、単位速度で C まで直接移動するため、答えを |P − C| として計算します。

微妙な点は、一貫した方向性を扱うことです。 A を常に小さいものとして扱う代わりに、方向を明示的にエンコードして、両方の場合に同じ式が機能するようにします。 

### なぜ効果があるのか

 この動きは、反射境界を持つ線分上を決定論的に歩くものです。 2L 時間単位ごとに、状態 (位置と方向) は、B に向かって移動する A の開始構成に正確に戻ります。これにより、完全な周期軌道が作成されます。 周期を法として時間を短縮すると、その軌道内の正確な状態が保存されるため、計算された位置は完全なシミュレーションで生成されるものと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

A, B = map(int, input().split())
T, C = map(int, input().split())

L = abs(A - B)
period = 2 * L

# If A == B (degenerate, though constraints say A != B)
# motion still handled normally since L > 0 guaranteed

t = T % period

# normalize direction: start moving from A toward B
if A < B:
    start = A
    end = B
    forward = 1
else:
    start = A
    end = B
    forward = -1

if t <= L:
    pos = start + forward * t
else:
    t2 = t - L
    pos = end - forward * t2

ans = abs(pos - C)
print(ans)
```このソリューションでは、まずセグメントの長さを計算し、モジュロ演算を使用して時間を短縮します。 方向は正規化されており、A > B であっても、「前方」は常に A から B への移動を意味します。 

最初のフェーズでは、A から B への移動が処理されます。短縮された時間がまだそのフェーズ内にある場合、位置は直線運動によって計算されます。 それ以外の場合は、B から始まる戻りフェーズに切り替えて、対称的に戻ります。 

T の後の運動は無制限の直線運動であるため、最終的に答えは C までの直線距離になります。 

## 実用的な例

 ### 例 1

 入力:

 A = 3、B = 8、T = 10、C = 1

 ここで、L = 5、周期 = 10 であるため、t = 10 mod 10 = 0 となります。 

| ステップ | t | フェーズ | ポジション |
 | --- | --- | --- | --- |
 | 開始 | 0 | Aで| 3 |

 t = 0 では、役員は完全なサイクルの後、再び A に正確にいます。 そこから C までの距離は |3 − 1| です。 = 2。 

これは、完全なサイクルがモジュロによって正しく折りたたまれることを示しています。 

### 例 2

 入力:

 A = 2、B = 6、T = 7、C = 5

 L = 4、周期 = 8、つまり t = 7。 

| ステップ | t | フェーズ | ポジション |
 | --- | --- | --- | --- |
 | 開始 | 7 | 前方 2、後方 3 | 計算する |

 t ≤ L は false なので、リターンフェーズに入ります。 t2 = 7 − 4 = 3 を計算するため、位置は 6 − 3 = 3 となります。 

C までの距離は |3 − 5| = 2。 

これは、後方移動セグメントの正しい処理を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    A, B = map(int, input().split())
    T, C = map(int, input().split())

    L = abs(A - B)
    period = 2 * L
    t = T % period

    if A < B:
        start, end, f = A, B, 1
    else:
        start, end, f = A, B, -1

    if t <= L:
        pos = start + f * t
    else:
        t2 = t - L
        pos = end - f * t2

    return str(abs(pos - C))

# sample-like cases
assert run("3 8\n10 1\n") == "2"
assert run("6 1\n7 9\n") == "2"

# minimum movement
assert run("0 1\n0 0\n") == "0"

# immediate stop
assert run("2 5\n0 4\n") == "2"

# mid forward phase
assert run("1 5\n2 10\n") == "8"

# mid backward phase
assert run("1 5\n6 2\n") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 8 / 10 1 | 2 | フルサイクルリセット |
 | 6 1 / 7 9 | 2 | 逆方向 |
 | 0 1 / 0 0 | 0 | すでに目標を達成しています |
 | 2 5 / 0 4 | 2 | エンドポイントから開始 |
 | 1 5 / 2 10 | 8 | 前進運動 |
 | 1 5 / 6 2 | 3 | 後進運動 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、T が全サイクル長 2L の正確な倍数である場合です。 この場合、モジュロリダクション後に t は 0 になります。これは、警察官が正確に A にいて、再び B に向かって移動していることを意味します。 t ≤ L の場合は前進フェーズに移行し、位置 A が得られるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、警察官が時刻 T で正確に B にいる場合、つまり t = L である場合に発生します。条件 t ≤ L により、これが前進フェーズの終点として扱われることが保証され、曖昧さのない位置 B が生成されます。これは瞬間的な方向反転と一致します。 

3 番目のケースは、A > B の場合です。方向は順序に依存するのではなく明示的にエンコードされるため、同じ式が適用されます。 たとえば、A = 8、B = 3 の場合、前方ステップでは座標が減少する方向に移動し、後方ステップではそれが正しく反転され、特殊な場合を使用せずに対称性が確保されます。
