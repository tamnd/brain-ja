 ## 解決策
 ## 問題の理解

 凸多面体を形成する 3D の点のセットが与えられます。 タスクは、多面体自体を組み合わせ的な意味で再構成することではなく、その平面「ネット」を出力することです。つまり、すべての面が 2D で平らな多角形になり、隣接する面が共有エッジに沿って接続されたままになるように、その表面を平面に展開する必要があります。 

重要な詳細は、入力が面やエッジを明示的に提供しないことです。 頂点座標のみを受け取るので、そこから多面体の構造を推測する必要があります。 点は凸多面体を形成するため、面は 3D の凸包の面とまったく同じになります。 

出力は、展開されたネット内の頂点の出現のリストです。 各面はその頂点のコピーを提供し、各コピーには平面内の 2D 座標が割り当てられます。 同じ元の頂点インデックスが複数回出現する場合があります。これは、その頂点で出会う異なる面によってネット内の異なる位置に配置されるためです。 

構造的な意味での制約は小さく、面の数は最大でも 20 です。これが本当の制限要因です。 頂点の数が多くても、面グラフは小さいため、面をノードとして扱い、隣接関係を処理するアルゴリズムであれば、リスクなく面ごとの立方体ジオメトリの計算が可能です。 これにより、完全な幾何学的最適化をシミュレートしたり、グローバルな埋め込み問題を解決したりする試みは即座に排除されます。 むしろ、建設的な展開が期待されています。 

いくつかの特殊なケースは微妙なため、切り分ける価値があります。 

問題の 1 つは、点から顔を再構成する際のあいまいさです。 たとえば、点が立方体上にある場合、単純な三角形分割では面が一貫性なく分割され、きれいに展開できない構造が生成される可能性があります。 正しい解釈は、任意の三角形分割ではなく、凸包表面を構築する必要があるということです。 

複数の面が頂点を共有しているにもかかわらず、一貫した走査順序で処理されていない場合には、別の問題が発生します。 ツリー状の展開構造を保証しない場合は、矛盾する拘束を使用して面を 2 回配置しようとする可能性があります。 たとえば、四面体について考えてみましょう。ルートと伝播順序を固定せずに、頂点の周りに 4 つの面すべてを独立して配置しようとすると、回転の一貫性がなくなる可能性があります。 

3 番目の問題は、回転中の浮動小数点誤差の蓄積です。 座標は高精度で印刷し、境界を維持する必要があるため、幾何学的変換を不注意に繰り返すとドリフトする可能性があります。 安定したアプローチでは、近似変換を連鎖させるのではなく、常に正確なエッジ ベクトルとそこから導出された正規直交基底を使用して面を回転します。 

## アプローチ

 強引な解釈は、考えられるすべての面の平面配置を試し、各面を剛体ポリゴンとして扱い、重なりを避けながらエッジに沿ってそれらを接着しようとすることです。 概念的には、これは、面隣接グラフのすべてのスパニング ツリーと、各面に平面方向を割り当てるすべての方法を検索することを意味します。 面が 20 個しかない場合でも、スパニング ツリーの数はすでに膨大であり、各候補ではポリゴン間の重なりの幾何学的検証が必要ですが、これ自体がコストがかかります。 このアプローチは、組み合わせ論と幾何学の両方で急速に指数関数的になります。 

重要な観察は、有効なネットにはグローバルな最適化が必要ないということです。 必要なのは、面のツリー構造に沿った一貫した展開だけです。 1 つの面をルートとして選択し、それを平面内に固定すると、すべての隣接する面は、「展開」時にちょうど 1 つの自由度を持ちます。つまり、エッジの長さの制約を変更せずに、共有エッジを中心に回転して平面内に入れることができます。 多面体は凸面であるため、スパニング ツリーに沿って展開すると、面が矛盾した方法でオーバーラップすることを強制されないことが保証され、問題ステートメントはそのようなネットが少なくとも 1 つ存在することを保証します。

これにより、タスクが 2 つの部分に減ります。凸包を再構築して面と隣接関係を取得し、次に面隣接グラフに対して BFS を実行して、各面にルート面の平面に徐々に回転する剛体 3D 方向を割り当てます。

 ## アルゴリズムのチュートリアル

 まず凸多面体構造を再構築し、それを面ごとに共通の平面に展開します。 

## アルゴリズムのチュートリアル

 1. 入力ポイントの 3D 凸包を計算し、その面と隣接構造を抽出します。 各面は、船体の支持面上にある多角形です。 また、どの面がエッジを共有しているかも記録し、面隣接グラフを形成します。 入力が組み合わせ構造を提供しないため、このステップが必要です。 
2. ルート面として任意の面を選択します。 この面を出力ネットの XY 平面に直接配置します。 これを行うには、2 つのエッジ ベクトルを使用して顔のローカル 2D 座標系を構築し、それらを正規化し、顔の頂点を 2D 座標にマッピングします。 
3. ルート面から開始して面隣接グラフ全体にわたる BFS または DFS を維持します。 配置された面から未配置の隣接面までエッジを横断するたびに、共有エッジを横切って隣接面を「展開」します。 
4. 共有エッジ (u、v) を横切る面 A から面 B への遷移の場合、エッジの 3D ベクトルと両方の面の法線ベクトルを計算します。 面間の二面角によって、面 B を面 A の平面内に移動させるのに必要な回転量が決まります。 
5. 面 B を、エッジ (u, v) で定義された軸を中心に適切な符号付き角度だけ回転させ、その平面が面 A と同一平面上になるようにします。この回転により、u と v の位置が維持され、ネットが正しく接続されたままになります。 
6. 回転したら、面 B のすべての頂点をルート面に使用したのと同じ 2D 座標系に投影し、その位置を出力オカレンスとして保存します。 面 B を訪問済みとしてマークし、BFS を続行します。 
7. すべての面が処理されたら、すべての面からすべての頂点の出現を収集します。 各オカレンスには、元の頂点インデックスとその計算された 2D 座標が保存されます。 

正しさは、凸多面体の面隣接グラフが接続されており、ツリーでまたがることができるという事実に依存しています。 各展開ステップではエッジの長さと共有端点が保持されるため、トラバース全体にわたって一貫性が維持されます。 

### なぜ効果があるのか

 不変条件は、訪問されたすべての面がルート面と同じ平面座標系にすでに厳密に埋め込まれており、すべての共有エッジが正確に一致しているということです。 共有エッジを横切って新しい面を展開すると、共有エッジを固定したまま面が親と同一平面上になるという要件によって、回転が一意に定義されます。 各面はトラバーサル ツリー内で 1 回だけアタッチされるため、矛盾する制約が発生する可能性はありません。 凸性により、展開の際に自己交差制約をグローバルに解決する必要がなくなります。 それぞれの局所的な展開は、有効なネットの存在と幾何学的に一致しています。

import sys

from collections import defaultdict, deque

EPS = 1e-12

def dot(a, b):
    return a[0]*b[0] + a[1]*b[1] + a[2]*b[2]

def cross(a, b):
    return (
        a[1]*b[2] - a[2]*b[1],
        a[2]*b[0] - a[0]*b[2],
        a[0]*b[1] - a[1]*b[0]
    )

def sub(a, b):
    return (a[0]-b[0], a[1]-b[1], a[2]-b[2])

def norm(a):
    return math.sqrt(dot(a, a))

def scale(a, t):
    return (a[0]*t, a[1]*t, a[2]*t)

def add(a, b):
    return (a[0]+b[0], a[1]+b[1], a[2]+b[2])

def normalize(a):
    n = norm(a)
    if n < EPS:
        return (0.0, 0.0, 0.0)
    return scale(a, 1.0/n)

def rotate_around_axis(p, a, b, angle):
    axis = sub(b, a)
    axis = normalize(axis)
    x, y, z = axis
    ux, uy, uz = p[0]-a[0], p[1]-a[1], p[2]-a[2]

    cos = math.cos(angle)
    sin = math.sin(angle)

    dotu = ux*x + uy*y + uz*z
    rx = (ux*cos +
          (y*uz - z*uy)*sin +
          x*dotu*(1-cos))
    ry = (uy*cos +
          (z*ux - x*uz)*sin +
          y*dotu*(1-cos))
    rz = (uz*cos +
          (x*uy - y*ux)*sin +
          z*dotu*(1-cos))

    return (rx + a[0], ry + a[1], rz + a[2])

 ## 特殊なケース

 最小四面体は、最も直接的なストレス テストです。 完全に接続されたグラフでは 4 つの面すべてがエッジを共有しており、BFS 展開は、共有エッジの回転によって一貫性が保たれるかどうかを示します。 1 つの三角形面から開始して、残りの 3 つの面が 1 つずつ取り付けられ、各取り付けは共有エッジによって一意に決定されるため、配置に曖昧さが生じません。 

ピラミッド構造は、フェイス グラフの分岐を強調表示します。 ベース面は複数の側面に接続されており、アルゴリズムは各側面が他の側面の配置を妨げることなくベースから独立して展開されることを保証する必要があります。 各面は BFS を通じて 1 回だけアタッチされるため、単一の面に二重制約が発生するリスクはなく、最終的な埋め込みの一貫性が保たれます。
