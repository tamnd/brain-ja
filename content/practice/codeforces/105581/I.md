 ## 解決策
 ## 問題の理解

 正方形の戦場を表す n 行 n 列のグリッドが与えられます。 一部のセルは最初は燃えていますが、残りは空です。 ナイトは空のセルから開始し、最終的にグリッドの外に移動して逃げようとします。 

時間は離散的なステップで進みます。 各ステップでは、2 つのことが順番に起こります。まず、ナイトが標準的なチェスのナイトの動きを行い、次に、現在燃えているセルからナイトの動きによって到達可能なすべてのセルに火が広がります。 ナイトがすでに燃えているセル、または拡散後に燃え始めたセルに着地した場合、捕らえられたとみなされます。 ナイトは、火のある部屋を共有する前に、最終的にグリッドの外に踏み出すことができた場合にのみ成功します。 

タスクは、この結合された動的プロセスの下で、ナイトがグリッドの外に安全に到達できる開始セルの数を数えることです。 

グリッド サイズは最大 500 x 500 で、最大 250,000 個のセルが可能です。 各セルは最大 8 つの動きに分岐し、同時に火が進化するため、すべてのセルから可能なすべてのナイト パスを直接シミュレーションすることは不可能です。 最悪の場合、250,000 の州にさらに 250,000 の係数が乗算されるため、セルごとに 1 つの BFS であっても大きすぎます。 

単純な間違いは、騎士の動きと延焼を独立して扱うことです。 たとえば、火の到達時間を事前に計算して、タイミングを慎重に同期せずにナイトへの最短経路を実行できると仮定すると、等時間の競合が誤って処理された場合、誤った結果が生じます。 

もう 1 つの微妙な失敗例は、パリティのようなタイミング制約を無視することです。 ナイトとファイアーは両方とも個別のステップで移動するため、ナイトが同じタイムステップでファイアーの前に到着するか後に到着するかによって生存が決まり、オフバイワンの処理が重要になります。 

## アプローチ

 直接的なシミュレーションの視点では、空の各セルから開始して、考えられるすべてのナイトの動きをシミュレートすると同時に、火災の拡大を段階的にシミュレートします。 これは直ちに状態空間の爆発につながります。 各陣地は最大 8 つの次の陣地に分岐し、火も同様に拡大するため、組み合わせた状態は実質的に陣地と時間の産物となります。 最悪の場合、脱出または死亡するまでのすべての経路を探索すると、異なるタイミングで同じ状態を何度も再訪し、指数関数的な動作が発生する可能性があります。 

重要な点は、実際にはすべてのナイト パスを個別にシミュレートする必要はないということです。 火災の広がりはナイトとは独立しているため、各セルが火災により危険になる最も早い時期を事前に計算できます。 それが分かれば、問題は制約された最短経路に帰着します。訪問した各セルに火が到達する前に、騎士は境界に到達できるかということです。 

これにより、問題は発火タイミングに関するマルチソース BFS に変換され、その後に時間制限のあるナイト到達可能性に関する BFS が続きます。 火災 BFS は各セルに「危険時間」を与えます。 開始セルからのナイト BFS は、厳密にその時刻より前に到着した場合にのみ有効です。 すべてのセルからこの BFS を実行する代わりに、視点を逆にします。つまり、どのセルが境界に安全に到達できるかを計算し、その情報をタイミング制約のある逆ナイトの動きで逆方向に伝播します。 

この反転が機能するのは、エスケープが特定のターゲット セルに到達することではなく、純粋にグリッドの外側に到達することによって定義されるためです。そのため、境界エスケープをグローバル シンクとして扱うことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 起動ごとのシミュレーション | 指数 | O(n²) | 遅すぎる |
 | Fire BFS + 制約付きリバース到達可能性 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を解決するには、まず各セルが火災により危険になる時期を計算し、次にどのセルがその瞬間よりも前にまだ境界に到達できるかを判断します。 

1.行列を計算する`fire_time`ここで、各セルには火災が到達する最も早いステップが保存されます。 すべての発射セルを時間 0 で初期化し、BFS キューにプッシュします。 他のすべてのセルは無限として始まります。 騎士のように火が広がるため、騎士の動きで展開します。 
2. すべての初期ファイアセルからマルチソース BFS を同時に実行します。 時間 t でセルから拡張する場合、まだ割り当てられていない場合、到達可能なすべてのナイト移動ネイバーには時間 t + 1 が割り当てられます。 BFS は時間の増加順に探索するため、これにより、火災が各セルに到達できる最小時間が得られます。 
3. 1 回のナイトの動きでどのセルがすぐにグリッドから脱出できるかを特定します。 これらは、少なくとも 1 つのナイトの動きがボードの外に出るセルです。 これらの境界に隣接するセルは、最初は「勝利」状態として扱われますが、これは騎士が火が到着する前にそこに立っているのに十分長く生き残った場合に限られます。 
4. ナイトの動きの逆グラフを作成します。 各セルについて、1 回のナイト移動で到達できるすべての先行位置がわかります。 
5. すぐにエスケープ可能なすべてのセルから開始して BFS (またはキューの伝播) を実行します。 t が厳密に より小さい時間 t にナイトがそこに到着できた場合、そのセルは勝利したとみなされます。`fire_time[cell]`、そこから勝利状態に到達することができます。 
6. 逆方向に伝播する場合、セル u から先行セル v への遷移のみを受け入れます。ただし、v に早く到着しても安全が保たれる場合、つまり伝播時間が超えない場合に限ります。`fire_time[v] - 1`。 
7. 最後に勝利としてマークされたすべてのセルを数えます。 

重要なアイデアは、火災をノードごとの期限制約として機能させて、境界までの時間に配慮した安全なパスが存在するすべての状態のセットを効果的に計算しているということです。 

### なぜ効果があるのか

 火災 BFS は、ナイトに依存しない各セルの固定の最早到着時刻を計算します。 これにより、セルごとに厳しい期限が設定されます。 有効なナイト パスはすべてのステップでこれらの期限を遵守する必要があります。 

ナイトエッジ上のリバース BFS は、単調時間の実現可能性を尊重しながら、最終的に脱出につながる可能性のあるすべての状態を探索します。 このリバース グラフのすべてのエッジは有効なフォワード ナイトの動きに正確に対応し、タイミング制約が満たされた場合にのみ伝播するため、マークされたすべての状態は実際に実行可能な脱出戦略に対応します。 逆に、有効なエスケープ パスは境界で終了する必要があり、有効な先行状態を介して逆方向にたどることができます。これは、この伝播によって発見されることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    INF = 10**18
    fire_time = [[INF] * n for _ in range(n)]

    q = deque()

    for i in range(n):
        for j in range(n):
            if grid[i][j] == '#':
                fire_time[i][j] = 0
                q.append((i, j))

    moves = [(2,1),(2,-1),(-2,1),(-2,-1),(1,2),(1,-2),(-1,2),(-1,-2)]

    while q:
        x, y = q.popleft()
        for dx, dy in moves:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < n:
                if fire_time[nx][ny] == INF:
                    fire_time[nx][ny] = fire_time[x][y] + 1
                    q.append((nx, ny))

    rev = [[[] for _ in range(n)] for _ in range(n)]
    for i in range(n):
        for j in range(n):
            for dx, dy in moves:
                ni, nj = i + dx, j + dy
                if 0 <= ni < n and 0 <= nj < n:
                    rev[ni][nj].append((i, j))

    dist = [[INF] * n for _ in range(n)]
    dq = deque()

    def can_escape_cell(i, j):
        for dx, dy in moves:
            ni, nj = i + dx, j + dy
            if not (0 <= ni < n and 0 <= nj < n):
                return True
        return False

    for i in range(n):
        for j in range(n):
            if can_escape_cell(i, j) and fire_time[i][j] > 0:
                dist[i][j] = 0
                dq.append((i, j))

    while dq:
        x, y = dq.popleft()
        for px, py in rev[x][y]:
            nd = dist[x][y] + 1
            if nd < fire_time[px][py] and nd < dist[px][py]:
                dist[px][py] = nd
                dq.append((px, py))

    ans = 0
    for i in range(n):
        for j in range(n):
            if dist[i][j] < INF:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初の BFS は、マルチソース拡張を使用して火災到達時間を計算します。 第 2 フェーズでは、境界隣接セルからエスケープの実現可能性を後方に伝播できるように、逆ナイト隣接関係を構築します。 の`dist`配列は、逆の時間単位で最も早い安全な避難距離を追跡します。 鍵となる条件`nd < fire_time[px][py]`騎士が火事に到着したり火事後に到着したりする状態を決して許可しないことを強制します。 

単一のナイトの移動がグリッドから出た場合にのみ脱出が可能であるため、境界チェック機能は非常に重要です。 これらのセルは、逆伝播の最初のシンクとして機能します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | 各セルは 2 回の BFS トラバーサルと 8 回のナイト移動にわたるエッジ構築で一定の回数処理されます。 
| スペース | O(n²) | 発射時間、逆隣接関係、および距離の配列を格納します。

 ## 特殊なケース

 エッジ ケースの 1 つは、セルがボードからすぐに脱出できるが、時刻 1 に到着する火災にも隣接している場合です。アルゴリズムは、次の場合にのみ境界脱出セルを初期化することでこれを処理します。`fire_time[i][j] > 0`、騎士が脱出の動きをするのに十分な長さ生き残ることを保証します。 

例えば：```
#..
...
...
```セル (0,1) は上に逃げることができますが、(0,0) の火災は 1 ステップでセルに広がります。 BFS は、火災が到着する前に脱出が発生した場合にのみそれを受け入れるため、安全な場合にのみ正しく含まれます。 

もう 1 つのエッジ ケースは、火災が特定の地域に到達しない孤立した安全な島です。 それらの細胞では、`fire_time`は無限のままであるため、常に伝播の対象となります。 リバース BFS は追加の処理なしで自然に拡張され、最終的なカウントに完全に貢献します。
