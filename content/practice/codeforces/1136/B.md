 ## 解決策
 ## 問題の理解

 あります`n`マンホールが一列に並んでいます。 各マンホールには最初、その上にちょうど 1 つの石があり、その下に 1 つのコインが含まれています。 ナスティアはマンホールからスタート`k`。 

コインは現在のマンホールに石が置いていない場合にのみ収集できます。 マンホールから石を取り除くには、ナスティアはそこに立って、1 つの移動を費やして石を他のマンホールに投げなければなりません。 隣接するマンホール間の移動にも 1 回の移動コストがかかります。 

目標は、最小限の移動数ですべてのコインを収集することです。 

制約はわずかですが、`n ≤ 5000`, しかし、これは実際には数学的な構成問題です。 アクションのシーケンスを出力するように求められるのではなく、最小限の動きの数だけを出力するように求められます。 答えは、最適な戦略の構造から直接導き出すことができます。 

難しいのは、何が移動数に影響を与えるのかを理解することです。 すべてのマンホールは 1 つの石から始まります。 コインを回収する前に、その石を捨てなければなりません。 あるので`n`少なくともマンホールは`n`投石作戦は避けられない。 開始位置に依存するのは動きだけです。 

よくある間違いは、すべての石が何らかの方法で正確に除去できると考えることです。`n`投げます。 最後に訪れたマンホールは特別だ。 どこかに投げられた石はすべて、最終的には再び取り除かれなければなりません。 最適な戦略は 1 つのエンドポイントで終了し、石はクリアされる前にそのエンドポイントに向かって押し込まれます。 これにより、見逃しがちな追加コストが発生します。 

考慮する`n = 2, k = 2`。```
2 2
```答えは`6`、 ない`4`。 元の石ごとに 1 回の投げが必要ですが、石を移動した後、エンドポイントには複数の石が蓄積され、コインを収集する前にそれらも投げる必要があります。 

もう 1 つの見落としやすいケースは、開始位置がすでに終了点にある場合です。```
5 1
```答えは`16`。 ラインを 1 回通過することのみに基づいた単純な計算式では、石を再分配して除去する必要があるため、コストが過小評価されてしまいます。 

センターポジションも面白いですね。```
5 3
```最適な戦略では、終了する一方の側を選択し、最初にもう一方の側を通過します。 仕上げ面の選択は移動コストに影響します。 

## アプローチ

 強引なビューでは、ナスティアの位置、すべてのマンホール上の石の数、およびどのコインがすでに収集されているかなど、すべての状態をモデル化します。 状態から、移動したり、石を投げたり、コインを集めたりすることができます。 

これは、考えられるすべてのアクションのシーケンスを調査しているため、明らかに正しいです。 残念ながら、状態空間はすぐに爆発します。 小さいものでも`n`、可能な石の配布数は膨大です。 そのような検索は完全に不可能です。 

重要な観察は、石の操作がほぼ固定されていることです。 

マンホールからコインを集めるには、ある時点でマンホールが空になる必要があります。 すべてのオリジナルの石は少なくとも 1 回は投げる必要があります。 それはすでに貢献しています`n`動きます。 

では動きを見てみましょう。 すべてのコインを集めるために、ナスティアはすべてのマンホールを訪れる必要があります。 マンホールは一列に並ぶため、最適なルートは中間から始まり、最終的に 1 つの終点で終了します。 すべてのポジションを訪問するために必要な最小限の動きは次のとおりです。```
(n - 1) + min(k - 1, n - k)
```用語`n - 1`は 2 つの端点間の距離です。 追加項は、開始位置から最初に訪問したエンドポイントまでの距離です。 

オリジナルを超えた投石についてはどうですか`n`?

 左の終点で終了すると決めたとします。 一番左のマンホールを除くすべてのマンホールは、コインを回収する前に元の石を捨てなければなりません。 それは与える`n - 1`投げます。 一番左のマンホールは最終的にそれらの石をすべて受け取るので、それらも取り除く必要があり、別のマンホールが必要になります。`n - 1`投げます。 

正しいエンドポイントで終了した場合にも、同じ議論が当てはまります。 

したがって、スロー操作の合計数は常に次のようになります。```
2(n - 1)
```移動と投げを組み合わせると次のようになります。```
2(n - 1) + (n - 1) + min(k - 1, n - k)
= 3(n - 1) + min(k - 1, n - k)
```これはほぼ正しいですが、もう 1 つ手があります。 私たちが終了する終点は、独自のオリジナルの石から始まります。 その石もプロセスの一部であり、以下をもたらします。```
3n - 3 + min(k - 1, n - k) + 1
= 3n - 2 + min(k - 1, n - k)
```最も受け入れられているソリューションで使用される形式に再整理すると、次のようになります。```
3n + min(k - 1, n - k) - 2

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`k`。 
2. 開始位置からより近い終点までの距離を計算します。```
d = min(k - 1, n - k)
```反対側の終点で終了する場合は、まず 1 つの終点に到達してから、ライン全体を横断する必要があります。 より近い終点を選択すると、動きは最小限に抑えられます。 
3. 導出された式を使用して答えを計算します。```
answer = 3 * n + d - 2
```4. 結果を出力します。 

### なぜ効果があるのか

 すべての最適解はすべてのマンホールを訪問する必要があり、これにより、ライン全体と最初に訪問したエンドポイントまでの距離を横断するのに相当する移動が強制されます。 そのような最小の動きは、`(n - 1) + min(k - 1, n - k)`。 

石の操作では、コインを収集する前に、すべての元の石をマンホールから取り除く必要があります。 最適な戦略は、プロセスが終了するエンドポイントに向かって石を押し進めます。 最終以外のマンホールはすべて、元の石に対して 1 回のスローに貢献し、最終エンドポイントは後で蓄積された石をすべてクリアする必要があります。 結果として得られるスロー操作の数は固定されており、正確なルートには依存しません。 

避けられない移動コストと投擲コストを追加すると、閉じた形式の式が得られます。```
3n + min(k - 1, n - k) - 2
```どちらの成分も削減できる代替戦略はないため、この式は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    print(3 * n + min(k - 1, n - k) - 2)

if __name__ == "__main__":
    solve()
```すべての作業が数学的導出で行われるため、実装は短くなります。 

表現`min(k - 1, n - k)`より近い端点までの距離を計算します。 インデックス作成には注意が必要です。 左の端点は位置です`1`、したがって、その距離は`k - 1`。 右端は位置です`n`、したがって、その距離は`n - k`。 

答えは 32 ビット整数内に簡単に収まります。`n ≤ 5000`, しかし、Python の整数はとにかく自然にそれを処理します。

開始マンホールが終了エンドポイントとして選択されていない場合、エンドポイント自体の石を正しく処理するには、さらに 2 つの操作が必要です。 受け入れられるコンパクトな式は次のとおりです。```

3 * n + min(k - 1, n - k) - 2

```これは、完全な石除去プロセスを考慮した後に一致します。
