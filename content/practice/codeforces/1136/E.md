 ## 解決策
 ## 問題の理解

 配列があります`a`そして別の配列`k`。 

配列は常に単調型制約を満たします。$$a_{i+1} \ge a_i + k_i$$隣接するペアごとに。 

操作は2つあります。 

最初の操作で位置が 1 つ増加します`a[i]`ある値によって`x`。 この増加後、次の要素で制約に違反する可能性があります。 そうであれば、私たちは引き上げなければなりません`a[i+1]`制約を復元する最小値に設定します。 その変更により強制される可能性があります`a[i+2]`増やすなど。 更新は、制約が再び有効になるまで右に伝播します。 

2 番目の操作では、連続したセグメントの合計を求めます。 

難しいのは、どちらも`n`クエリの数は最大です`100000`。 1 回の更新が、配列のサフィックスのほぼ全体に影響を与える可能性があります。 その伝播を明示的に実行するには、`O(n)`更新ごとの時間は次のようになります`O(nq)`最悪の場合、おおよそ`10^10`操作。 それは限界をはるかに超えています。 

主な課題は、更新と範囲合計の両方を対数時間で処理できる形式で伝播された構造を表現することです。 

微妙な点は、更新によって要素が減少することはありません。 一度ポジションが大きくなると、その後小さくなることはありません。 この単調性が、効率的なデータ構造が存在する理由です。 

もう 1 つの簡単な間違いは、隣接する 1 つを変更するとすぐに伝播が停止すると考えることです。 考慮する：```
a = [5, 7, 9]
k = [3, 3]
```追加後`2`に`a[1]`、次のようになります。```
a[1] = 7
```今：```
a[2] < a[1] + 3
```それで`a[2]`になる`10`。 

それから：```
a[3] < a[2] + 3
```それで`a[3]`になる`13`。 

効果はサフィックス全体に及びます。 

もう 1 つの危険なケースは、次の負の値から発生します。`k`。```
a = [10, 20]
k = [-100]
```制約は```
20 >= -90
```それはすでに真実です。 

増加中`a[1]`わずかに制約が満たされたままになる可能性があります。 すべての更新が少なくとも 1 つのステップを伝播すると仮定するソリューションは正しくありません。 

最後の罠は、多数の重複更新後の範囲合計です。 実際の配列値は暗黙的に変更されます。 更新位置のみを保存し、誘発されたサフィックス変更を忘れた場合、後の合計クエリは間違ったものになります。 

## アプローチ

 ブルートフォースソリューションは文字通りこのステートメントに従います。 

受け取るとき`+ i x`、増やします`a[i]`、右方向にスキャンします。 いつでも$$a_{j+1} < a_j + k_j$$私たちは交換します`a[j+1]`による`a_j + k_j`。 

合計クエリの場合は、要求された要素を追加するだけです。 

これはプロセスを直接シミュレートするため、これは正しいです。 問題は複雑さです。 1 回の更新で残りのすべてのポジションに影響を与える可能性があります。 と`100000`アップデート、最悪のケースは約$$100000 \times 100000 = 10^{10}$$操作。 

何かをより速く見つけるには、制約の構造を理解する必要があります。 

プレフィックス合計配列を定義します。$$d_1 = 0$$

$$d_i = \sum_{j=1}^{i-1} k_j$$ここで定義します$$b_i = a_i - d_i$$元の状態$$a_{i+1} \ge a_i + k_i$$になる$$b_{i+1} \ge b_i$$したがって、この変換の後、配列全体が`b`単に減少していないだけです。 

アップデートって何をするの？ 

増加中`a[i]`による`x`増加する`b[i]`による`x`。 

その後、伝播によって再び非減少特性が適用されます。 値が新しい値より小さい右側のすべての位置`b[i]`まさにその値まで引き上げられます。 

つまり、更新は次のようになります。 

「追加`x`位置にある`i`で始まる最大の連続セグメントを置き換えます。`i`1 つの定数値ごとに。」

 これで、構造がより明確になりました。 

以来`b`が常に減少しない場合、二分探索で最後に影響を受けた位置を見つけることができます。 更新は 1 つの値への範囲の割り当てになります。 範囲の合計は加重合計になります。$$a_i = b_i + d_i.$$配列`d`決して変化しないため、その寄与を事前に計算できます。 ダイナミック部分は完全に内側にあります`b`。 

以下をサポートするデータ構造が必要です。 

1. 定数への範囲の割り当て。 
2. 範囲合計クエリ。 
3. 非減少配列内の値の二分探索。 

遅延セグメント ツリーは 3 つすべてを提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O(q log² n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 変換

 しましょう$$d_1 = 0$$そして$$d_i = k_1 + k_2 + \dots + k_{i-1}.$$定義する$$b_i = a_i - d_i.$$与えられた保証は、次のことを意味します。`b`非減少から始まります。 

### セグメントツリーの内容

 セグメント ツリーには以下が保存されます。 

1. の合計`b`各セグメントで。 
2. 各セグメントの最大値。 
3. 遅延範囲割り当てタグ。 

最大値を使用すると、更新範囲の終わりを二分探索できます。 

### アップデートを処理しています

 次のものを受け取ったとします。```
+ i x
```1. 現在値を読み取る`b[i]`。 
2.セット$$v = b[i] + x.$$3. 最大の位置を見つける`r`すべての要素が`[i,r]`よりも厳密に小さいです`v`。 

以来`b`が減少していない場合、影響を受ける位置は 1 つの連続したセグメントを形成します。 
4. 値の割り当て`v`全範囲に`[i,r]`。 

代入後、配列は減少しないままになります。 

### 合計クエリの処理

 のために```
s l r
```私たちは必要です$$\sum_{i=l}^{r} a_i.$$以来$$a_i=b_i+d_i,$$私たちは計算します$$\sum b_i$$セグメントツリーから、そして$$\sum d_i$$静的なプレフィックスサム配列から。 

それらの合計が答えです。 

### なぜ効果があるのか

 変換された配列`b`常に減少しません。 要素を 1 つ増やすと、その右側の単調性のみに違反する可能性があります。 新しい値より小さい位置はすべてその値になる必要があり、大きい位置はすべて変更されません。 配列はソートされているため、影響を受ける位置は 1 つの連続した間隔を形成します。 その間隔を新しい値に割り当てると、ステートメントで説明されている伝播が正確に再現されます。 

セグメント ツリーには常に現在のセグメントが保存されます。`b`配列、およびすべてのクエリが計算します$$a_i=b_i+d_i$$その通り。 以来`d`決して変化せず、動的部分から合計を再構築します`b`そして静的部分`d`すべての操作で正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr) - 1

        size = 4 * self.n + 5
        self.sum = [0] * size
        self.mx = [0] * size
        self.lazy = [None] * size

        self._build(1, 1, self.n, arr)

    def _build(self, v, tl, tr, arr):
        if tl == tr:
            val = arr[tl]
            self.sum[v] = val
            self.mx[v] = val
            return

        tm = (tl + tr) // 2
        self._build(v * 2, tl, tm, arr)
        self._build(v * 2 + 1, tm + 1, tr, arr)
        self._pull(v)

    def _pull(self, v):
        self.sum[v] = self.sum[v * 2] + self.sum[v * 2 + 1]
        self.mx[v] = max(self.mx[v * 2], self.mx[v * 2 + 1])

    def _apply(self, v, tl, tr, val):
        self.sum[v] = (tr - tl + 1) * val
        self.mx[v] = val
        self.lazy[v] = val

    def _push(self, v, tl, tr):
        if self.lazy[v] is None or tl == tr:
            return

        tm = (tl + tr) // 2
        val = self.lazy[v]

        self._apply(v * 2, tl, tm, val)
        self._apply(v * 2 + 1, tm + 1, tr, val)

        self.lazy[v] = None

    def assign(self, l, r, val):
        self._assign(1, 1, self.n, l, r, val)

    def _assign(self, v, tl, tr, l, r, val):
        if l > r:
            return

        if l == tl and r == tr:
            self._apply(v, tl, tr, val)
            return

        self._push(v, tl, tr)

        tm = (tl + tr) // 2

        self._assign(v * 2, tl, tm, l, min(r, tm), val)
        self._assign(v * 2 + 1, tm + 1, tr,
                     max(l, tm + 1), r, val)

        self._pull(v)

    def query_sum(self, l, r):
        return self._query_sum(1, 1, self.n, l, r)

    def _query_sum(self, v, tl, tr, l, r):
        if l > r:
            return 0

        if l == tl and r == tr:
            return self.sum[v]

        self._push(v, tl, tr)

        tm = (tl + tr) // 2

        return (
            self._query_sum(v * 2, tl, tm, l, min(r, tm))
            + self._query_sum(v * 2 + 1, tm + 1, tr,
                              max(l, tm + 1), r)
        )

    def query_point(self, pos):
        return self._query_point(1, 1, self.n, pos)

    def _query_point(self, v, tl, tr, pos):
        if tl == tr:
            return self.mx[v]

        self._push(v, tl, tr)

        tm = (tl + tr) // 2

        if pos <= tm:
            return self._query_point(v * 2, tl, tm, pos)
        return self._query_point(v * 2 + 1, tm + 1, tr, pos)

    def first_ge(self, l, value):
        return self._first_ge(1, 1, self.n, l, value)

    def _first_ge(self, v, tl, tr, l, value):
        if tr < l or self.mx[v] < value:
            return -1

        if tl == tr:
            return tl

        self._push(v, tl, tr)

        tm = (tl + tr) // 2

        res = self._first_ge(v * 2, tl, tm, l, value)
        if res != -1:
            return res

        return self._first_ge(v * 2 + 1, tm + 1, tr, l, value)

def solve():
    n = int(input())

    a = list(map(int, input().split()))
    k = list(map(int, input().split()))

    d = [0] * (n + 1)

    for i in range(2, n + 1):
        d[i] = d[i - 1] + k[i - 2]

    b = [0] * (n + 1)

    for i in range(1, n + 1):
        b[i] = a[i - 1] - d[i]

    seg = SegmentTree(b)

    pref_d = [0] * (n + 1)
    for i in range(1, n + 1):
        pref_d[i] = pref_d[i - 1] + d[i]

    q = int(input())
    out = []

    for _ in range(q):
        s = input().split()

        if s[0] == '+':
            pos = int(s[1])
            x = int(s[2])

            cur = seg.query_point(pos)
            nv = cur + x

            nxt = seg.first_ge(pos + 1, nv)

            if nxt == -1:
                r = n
            else:
                r = nxt - 1

            seg.assign(pos, r, nv)

        else:
            l = int(s[1])
            r = int(s[2])

            dyn = seg.query_sum(l, r)
            static = pref_d[r] - pref_d[l - 1]

            out.append(str(dyn + static))

    sys.stdout.write("\n".join(out))

```変換後、問題全体は非減少配列を中心に展開します。`b`。 セグメント ツリーには、次の合計と最大値が保存されます。`b`、遅延範囲割り当てとともに。 

更新では、まず 1 つの位置で現在値が読み取られます。 新しく伝播された値は、単にその値に値を加えたものです。`x`。 次に、値がすでに少なくとも新しい値である右側の最初の位置を検索します。 その位置より前のすべてのものを引き上げる必要があります。 そのような位置が存在しない場合、更新は配列の末尾に到達します。 

検索では、保存されているセグメントの最大値が使用されます。 なぜなら`b`非減少、少なくとも値を持つ最初の位置`nv`影響を受ける間隔を一意に決定します。 

範囲合計クエリは、次の動的寄与に分割されます。`b`そして、からの静的貢献`d`。 後者は、プレフィックス合計を使用して 1 回事前計算されます。 

よくある実装上の間違いは、更新範囲に変更された位置自体が含まれていることを忘れることです。 もう1つはから検索しています`pos`の代わりに`pos + 1`これにより、新しく更新された要素がすぐに検出され、空の間隔が生成されます。
