 ## 解決策
 ## 問題の理解

 同じサイズの 2 つの行列が与えられています。`A`そして`B`。 

許可された操作は驚くほど強力です。内部の任意の正方部分行列を選択できます。`A`そしてそれを移調します。 転置すると、正方形の主対角線を基準にして位置が交換されます。 この操作は任意の回数、任意の正方形サイズで実行できます。 

タスクは、行列が`A`マトリックスに変換できる`B`。 

マトリックスの次元は最大でも`500 × 500`, したがって、最大 250,000 個のセルが存在する可能性があります。 転置シーケンスを明示的にシミュレートする解決策は、考えられる正方部分行列の数が膨大であるため、直ちに疑わしいものとなります。 考えられるすべての操作を一度確認するだけでも、すでにコストがかかりすぎます。 

重要な課題は、許可されたすべての操作において行列のどの特性が変更されないのかを理解することです。 

よくある間違いは、行または列を個別に比較することです。 転置では要素を行と列の間で移動するため、行の内容も列の内容も保持されません。 

もう 1 つの簡単な罠は、行列全体を任意に再配置できると仮定することです。 この操作は柔軟ですが、特定の構造上の制約は維持されます。 

考慮する：```
A:
1 2
3 4

B:
1 3
2 4
```出力：```
YES
```行列全体を 1 回転置できます。 

次に、次のことを考えてみましょう。```
A:
1 2
3 4

B:
1 4
3 2
```出力：```
NO
```行列要素のマルチセットは同一ですが、許可された転置シーケンスでは要素を任意の対角線間で移動​​できません。 グローバル周波数のみを比較するソリューションでは、YES と誤って答えてしまいます。 

より微妙な例は次のとおりです。```
A:
1 2 3
4 5 6

B:
1 2 3
4 6 5
```出力：```
NO
```最後の 2 つの要素のみが異なります。 これらは異なる保存対角グループに属しているため、交換することはできません。 

何が保存されているかを正確に理解することが問題のすべてです。 

## アプローチ

 ブルートフォースアプローチでは、転置をモデル化し、変換する一連の操作を検索しようとします。`A`の中へ`B`。 

すべての有効な変換は最終的に発見される可能性があるため、これは理論的には正しいです。 残念なことに、状態空間は天文学的なものです。 行列には最大 250,000 個の要素を含めることができます。`O(nm · min(n,m))`異なる正方部分行列。 操作シーケンスを調査することはまったく不可能です。 

このブレークスルーは、転置が行列座標に対して実際に何を行うかを研究することで得られます。 

左上隅が`(r,c)`。 その正方形の内側のローカル座標のセル`(x,y)`に移動します`(y,x)`移調後。 

移動前:```
global row    = r + x
global column = c + y
```移動後:```
global row    = r + y
global column = c + x
```次に値を調べます。```
(row - column)
```前に：```
(r + x) - (c + y)
= (r - c) + (x - y)
```後：```
(r + y) - (c + x)
= (r - c) + (y - x)
```見る代わりに`row - column`、次のように見ると簡単です。```
row + column
```前に：```
(r + x) + (c + y)
= r + c + x + y
```後：```
(r + y) + (c + x)
= r + c + x + y
```合計`row + column`決して変わりません。 

つまり、すべての要素が常に同じ対角線上に留まります。 

許可される操作はすべて、1 つの対角線内の要素を並べ替えるだけです。 要素を別の対角線に移動することはできません。 

ここで、もう 1 つの観察が必要です。 の転置`2 × 2`square は、2 つの非対角要素を交換します。 局所的な転置を繰り返すことで、固定された対角線内で任意の順列を実現できます。 したがって、各反対角線にとって重要なのは、それに含まれる複数の値セットだけです。 

したがって、問題は次のようになります。 

すべての対角線に対して`i + j`からすべての値を収集します`A`およびからのすべての値`B`。 マルチセットがすべての対角線に一致する場合、答えは「YES」です。 それ以外の場合は「NO」です。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数/状態空間検索 | 巨大な | 遅すぎる |
 | 最適 | O(nm log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセルについて`(i,j)`マトリックスで`A`、その値を対角に対応するコンテナに配置します。`i + j`。 
2. すべてのセルについて`(i,j)`マトリックスで`B`、その値を対角に対応する別のコンテナに置きます。`i + j`。 
3. 各対角インデックスについて、`0`に`n + m - 2`、収集された値を並べ替えます`A`。 
4. 収集した値を並べ替えます。`B`同じ対角線に対して。 
5. ソートされた 2 つのリストを比較します。 
6. 反対角が異なる場合は、出力`"NO"`なぜなら、何らかの値がその対角線から離れる必要があるからですが、それは不可能です。 
7. すべての対角線が一致する場合、出力します。`"YES"`。 

### なぜ効果があるのか

 すべての転置では数量が維持されます`row + column`したがって、要素は対角線から離れることはありません。 したがって、各対角線上の複数の値セットは、許可されたすべての操作の下で不変です。 

残りの問題は、反対角マルチセットのマッチングで十分かどうかです。 彼らです。 正方部分行列の転置により、同じ反対角上の隣接する位置間のスワップが生成され、隣接するスワップにより任意の置換が生成されます。 固定された対角内で値を任意に配置することができます。 

したがって、すべての反対角が同じ値の複数セットを含む場合、2 つの行列は正確に相互に到達可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    da = [[] for _ in range(n + m - 1)]
    db = [[] for _ in range(n + m - 1)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j, x in enumerate(row):
            da[i + j].append(x)

    for i in range(n):
        row = list(map(int, input().split()))
        for j, x in enumerate(row):
            db[i + j].append(x)

    for k in range(n + m - 1):
        da[k].sort()
        db[k].sort()
        if da[k] != db[k]:
            print("NO")
            return

    print("YES")

solve()
```実装は証明を直接反映しています。 

配列のインデックス`i + j`対角線を識別します。 可能な最大値は```
(n - 1) + (m - 1) = n + m - 2
```まさに必要です`n + m - 1`コンテナ。 

各行列の読み取り中に、すべての要素がその反対角に対応するリストに追加されます。 挿入後に行列を保存する必要がないため、実装が単純になります。 

ソートにより、各反対角マルチセットが正規表現に変換されます。 2 つのマルチセットは、それらのソートされたシーケンスが等しい場合に限り、等しくなります。 

不一致を検出した後の早期復帰により、不要な作業が回避されます。
