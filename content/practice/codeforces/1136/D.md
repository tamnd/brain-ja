 ## 解決策
 ## 問題の理解

 キューは最初は固定されており、キューの最後の人は Nastya です。 一部の注文ペア$(u,v)$が与えられます。 ペアとは、生徒がいつでも$u$生徒のすぐ前に立つ$v$、その二人の生徒は喜んで場所を交換します。 

Nastya は、このような隣接スワップを繰り返し使用して、キューの先頭にできるだけ移動したいと考えています。 私たちは彼女が何ポジションまで昇進できるかを判断する必要がある。 

キューには最大で次のものが含まれます$3 \cdot 10^5$生徒と最大で$5 \cdot 10^5$スワップ関係を許可します。 これらの制限により、スワップのシミュレーションは直ちに除外されます。 たとえ$O(n^2)$アルゴリズムは次のように実行します$9 \cdot 10^{10}$制限時間を大幅に超えた最悪の場合の作戦。 入力サイズは線形に近い値が必要です。 

問題の微妙な部分は、Nastya が任意の人物と直接交換しないことです。 すべての交換には隣接する 2 人の生徒が関与する必要があり、許可はこれら 2 人の生徒の ID によって異なります。 

よくある間違いは、ナスティアが生徒を追い越せると考えることです$x$直接の許可がある場合$(x,\text{Nastya})$。 時々彼女は迂回できる$x$他の生徒を再配置した後、間接的に。 

考慮する：```
Queue: [1, 2, 3]
Nastya = 3

Permissions:
1 -> 3
1 -> 2
```Nastya は生徒 2 を通過できません。1 と 3 を交換することはできますが、生徒 2 はアクセスをブロックし、横切ることはできません。 答えは0です。 

もう 1 つの簡単な間違いは、目先の機会だけをシミュレートすることです。```
Queue: [1, 2, 3, 4]
Nastya = 4

Permissions:
1 -> 4
2 -> 4
3 -> 4
```Here Nastya can move all the way to the front. 3 を通過すると、2 に隣接し、次に 1 に隣接します。答えは 3 です。 

課題は、どの生徒が避けられない障害となっているかを正確に特定することです。 

## アプローチ

 ブルート フォース ビューでは、キューを状態として扱い、Nastya が関与する利用可能な隣接スワップを繰り返し実行します。 到達可能なすべての構成を検索したり、スワップを貪欲にシミュレートしたりすることができます。 難しいのは、他の生徒間の配置換えによって、後で新たな機会が生まれる可能性があることです。 The state space is enormous, up to$n!$, なのでこの方向は絶望的です。 

重要な観察は、キューを右から左に見ることで得られます。 

させて$x$順列の最後の要素である Nastya の数になります。 

ナスティアの前に立っている生徒たちを、彼女に近い生徒から順に前に向かって調べていくところを想像してみてください。 

何があってもナスティアの前に留まらなければならない一組の生徒をすでに特定していると仮定します。 このセットを**ブロック**と呼びます。 

次に、別の生徒について考えてみましょう$v$さらに左へ。 

ナスティアは最終的に合格できるだろうか$v$?

 合格するには$v$、彼女はある瞬間に隣接する必要があります$v$。 現在ブロックされている生徒は全員、何らかの方法で後ろに移動する必要があります$v$初め。 それが起こり得る唯一の方法は、$v$それを横切る必要があるすべてのブロックされた瞳孔と交換する意欲があります。 

一人でも瞳孔を塞いだら$u$許可が存在する$(v,u)$不在の場合$u$決して後ろに進むことはできません$v$。 したがって、ナスティアは決して隣接することができません$v$、 それで$v$それ自体がブロックされてしまいます。 

一方、次の場合は、$v$現在ブロックされているすべての生徒に対する権限がある場合、ブロックされているすべての生徒を背後に移動できます$v$、最終的にナスティアのパスを許可します$v$。 

これにより、非常にコンパクトな貪欲なプロセスが実現します。 

ブロックされた瞳孔のセットを維持します。 最初はナスティア自身のみが含まれています。 

Nastya を除いて、右から左にキューを処理します。 

生徒一人一人に対して$v$、ブロックされた生徒の数を数えます$u$許可を満たす$(v,u)$。 

このカウントがブロックされたセットの現在のサイズと等しい場合、$v$最終的には回避できます。 

さもないと$v$ブロックされたセットに参加します。 

結局のところ、ナスティアを除くすべての遮られた生徒は、ナスティアが決して追い越すことができない人物を表しています。 あれば$k$そのような生徒であれば、彼女は残りの生徒を合格させることができます$n-1-k$生徒たち。

 ## アルゴリズムのチュートリアル

 1. キューを読み取り、順列の最後の要素である Nastya の番号を特定します。 
2. すべての権限ペアについて$(u,v)$、 店$v$の隣接セット内で$u$。 
3. というセットを作成します。`blocked`そして最初にNastyaをその中に置きます。 
4. Nastya の直前の生徒から始めて、右から左にキューを処理します。 
5. 在校生へ$v$、メンバーの数を数えてください`blocked`に登場する$v$の隣接関係セット。 
6. このカウントが次のサイズと等しい場合`blocked`、 それから$v$最終的には Nastya によって横切られる可能性があるため、何もしないでください。 

その理由は、現在ブロックされているすべての生徒が後ろに移動できるためです。$v$、許可します$v$いつかナスティアと隣接することになる。 
7. それ以外の場合は追加します$v$に`blocked`。 

少なくとも 1 人のブロックされた生徒は後ろに移動することはできません$v$、作る$v$避けられない障害。 
8. すべての生徒が処理されたら、次のようにします。`ans = len(blocked) - 1`。 

これらは彼女より先に残らなければならない非ナスティアの生徒たちです。 
9. 出力`(n - 1) - ans`。 

### なぜ効果があるのか

 不変条件は、キューのサフィックスを処理した後、`blocked`そこには、ナスティアの後ろに決して移動できない、その接尾辞の生徒が正確に含まれています。 

新入生を診察するとき$v$、現在ブロックされているすべての瞳孔は、最終的には交差する必要があります$v$ナスティアが合格するなら$v$。 このような横断には許可が必要です$(v,u)$。 必要な許可が 1 つでも欠けている場合、少なくとも 1 人のブロックされた生徒が永久に前に残ります。$v$、ナスティアが到達するのを妨げます$v$。 したがって、$v$もブロックする必要があります。 

ブロックされているすべての生徒に対して権限が存在する場合、すべての生徒を背後に移動できます。$v$、 それで$v$永続的な障害にはなりません。 

不変式は各ステップの後でも true のままであり、キュー全体が処理されると、ブロックされたセットには、Nastya が通過できない瞳孔が正確に含まれます。 答えは残りの生徒の数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))

    adj = [set() for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].add(v)

    blocked = {p[-1]}  # Nastya

    for v in reversed(p[:-1]):
        cnt = 0
        s = adj[v]

        for u in blocked:
            if u in s:
                cnt += 1

        if cnt != len(blocked):
            blocked.add(v)

    cannot_pass = len(blocked) - 1
    print((n - 1) - cannot_pass)

solve()
```隣接構造には、各生徒からのすべての権限が保存されます。 会員テストは、$O(1)$平均して。 

セット`blocked`がソリューションの核心です。 そこには、まさにナスティアより先を行くことが保証されている生徒が含まれています。 生徒のステータスは、生徒自身よりもナスティアに近い人々にのみ依存するため、右から左にスキャンします。 

微妙な詳細は、カウントを現在のサイズと比較することです。`blocked`現在の瞳孔を挿入する可能性がある前に。 この順序を逆にすると、誤って生徒が自分自身に依存することになります。 

もう一つの詳細は、答えはそうではないということです`len(blocked)`。 Nastya 自身は常にブロックされたセット内にあるため、彼女の前に何人が残っているかを計算する前に 1 を減算します。

 ## 特殊なケース

 キューについて考えてみましょう。```
4 0
1 2 3 4
```権限はまったくありません。 右から左に処理すると次のようになります。```
blocked = {4}
3 cannot reach all blocked -> add
blocked = {4,3}
2 cannot reach all blocked -> add
blocked = {4,3,2}
1 cannot reach all blocked -> add
blocked = {4,3,2,1}
```すべての生徒がブロックされてしまいます。 答えは`0`これは正しいです。スワップは決して発生しないためです。 

次に、次のことを考えてみましょう。```
4 3
1 2 3 4
1 4
2 4
3 4
```処理すると以下が得られます。```
blocked = {4}
3 reaches all blocked
2 reaches all blocked
1 reaches all blocked
```ブロックされたセットに追加の生徒が入ることはありません。 答えは`3`、つまり、ナスティアは誰でも追い越すことができます。 

最後に次のことを考慮してください。```
4 2
1 2 3 4
2 4
3 4
```処理すると以下が得られます。```
blocked = {4}
3 reaches all blocked
2 reaches all blocked
1 does not reach 4
blocked = {4,1}
```生徒１は避けられない障害となる。 答えは`2`つまり、Nastya は生徒 2 と 3 を追い越すことはできますが、生徒 1 より先に進むことはできません。これはまさに貪欲不変式が捉える動作です。
