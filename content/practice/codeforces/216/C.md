 ## 問題の理解

 各従業員は厳格な繰り返しスケジュールに従っています。 当日採用後`x`、従業員が働いている`n`数日連続してその後は休みます`m`連続した日々が永遠に繰り返されます。 したがって、サイクルの長さは`n + m`、各サイクル内で、従業員は最初にアクティブになります。`n`日々。 

店舗はその日から永久に2つの条件を満たさなければなりません`1`。 

まず、少なくとも`k`従業員は毎日働かなければなりません。 

次に、ストア キーは、現在働いている従業員の接続されたグループ内に常に存在する必要があります。 鍵は、最初の従業員の最初の勤務日から始まります。 従業員が別の従業員に鍵を渡すことができるのは、両方が同時に勤務している日に限ります。 ある時点で、現在働いているすべての従業員が将来の従業員から切り離されると、鍵が閉じ込められ、最終的に店舗は機能しなくなります。 

従業員の総数を最小限に抑え、この最小限を達成する雇用日数を出力する必要があります。 

制約は、1 サイクル全体について推論できるほど十分に小さいです。 社員全員が毎回同じことを繰り返すので、`n + m`システム全体が定期的に行われます。 と`n, m ≤ 1000`、周りのアルゴリズム`O((n+m)^2)`まったく問題ありませんが、指数関数的なものや大規模な状態検索を伴うものは不要です。 

難しいのは、少なくとも毎日をカバーできないことです。`k`労働者。 それだけでも簡単です。 微妙な要件は、キーを永久に転送可能に保つことです。 

考慮する`n = 2, m = 2, k = 1`。 

一日に従業員を1人雇用した場合`1`そしてその日にはもう一つ`3`、カバレッジの作品:

 - 従業員 A の勤務日`1,2,5,6,...`- 従業員 B の勤務日`3,4,7,8,...`毎日 1 人のワーカーが存在しますが、それらは決して重ならないため、キーを A から B に移動することはできません。 店は日が経つと死んでしまう`2`。 

毎日の補償範囲のみをチェックする不注意なソリューションでは、従業員 2 名で十分であると誤って主張することになります。 

もう 1 つの注意が必要なケースは、ワーカーがほとんど重なっていない場合です。 

例：```
n = 4, m = 3, k = 1
```従業員を雇う日`1`そして`4`作品:

 - 従業員 1 が働いています`1..4`- 従業員 2 が勤務します`4..7`日が重なる`4`, そのため、キーは永遠に前進することができます。 

オーバーラップ グラフは、時間が経過しても接続されたままでなければなりません。 

もう 1 つの微妙な点は、スケジュールが循環モジュロであることです。`n + m`。 同じ日に雇用された 2 人の従業員は、永遠に同じように行動します。 実際の絶対的な雇用日は、このサイクル期間までのみ重要です。 

## アプローチ

 強引な考え方は、採用可能日をモジュロで検討することから始まります。`n + m`従業員のタイプとして。 多くてもあります`2000`そのようなタイプ。 すべてのサブセットを試して、次のことを確認できます。

単一のサブセットのチェックは管理可能ですが、サブセットの数は指数関数的に増加します。 周期の長さでも`20`、これはすでに実行不可能になります。 

次の観察により、問題は完全に変わります。 

当日採用の社員`x`周期的な間隔で動作します。```
[x, x+n-1] modulo (n+m)
```キーを永久に存続させるには、アクティブな従業員がサイクル全体にわたって重複する間隔のチェーンを形成する必要があります。 以来`m ≤ n`、連続した雇用日数の差は最大でも`n-1`オーバーラップしたい場合。 

次に、必要な従業員の最小数について考えてみましょう。`k = 1`。 

社員一人ひとりがカバーする`n`の日数`n+m`。 サイクル全体をオーバーラップしながら継続的にカバーするには、従業員を正確に配置するのが最適な構築です`n-1`数日違います。 すべての新入社員は前任者の最終勤務日から勤務を開始し、キーを前方に渡す単一の重複日を作成します。 

そのような従業員は何人必要ですか?

 従業員が追加されるたびに貢献するのは、`n-1`1 日は前の従業員と重なって費やされるため、新しい日になります。 長さのサイクルをカバーする`n+m`ニーズ：$t(n-1) \ge n+m$それで：$t = \left\lceil \frac{n+m}{n-1} \right\rceil$一般向け`k`、この構造を単純に複製することができます。`k`回。 コピーは同じ採用日に重なる場合があります。 各コピーは独立してキーの接続を維持し、連携して正確な情報を提供します。`k`毎日の労働者たち。 

素晴らしい点は、これも最適であるということです。 1 つのレイヤーに接続された循環カバーは最大でも露出できます。`n-1`隣接する従業員が少なくとも 1 日重複する必要があるため、従業員ごとに新しい日数がかかります。 その下限は構造と一致します。

## アルゴリズムのチュートリアル

 1. 1 つの接続された層に必要な従業員の最小数を計算します。 

サイクル全体を一周するのに十分な重複間隔が必要です。 すべての連続するペアは少なくとも 1 日重複する必要があるため、各新入社員は最大でも貢献します。`n-1`新鮮な日々。 

それで：$t = \left\lceil \frac{n+m}{n-1} \right\rceil$2. 最適な従業員層を 1 層構築します。 

次の日に従業員を雇用します。```
1, 1+(n-1), 1+2(n-1), ...
```連続した従業員がちょうど 1 日に重なるため、キーを転送するには十分です。 
3.同じレイヤーを繰り返す`k`回。 

毎日、単一レイヤーにすでに 1 人のアクティブなワーカーが存在します。 レイヤーを複製する`k`回は正確に与えます`k`毎日アクティブに働く人たち。 
4. すべての雇用日を出力します。 

従業員の総数は、`k * t`。 

### なぜ効果があるのか

 1 つのレイヤー内では、開始日が異なるため、連続するワーカーが重複します。`n-1`。 それぞれの労働者が働いているので、`n`連続した日の場合、それらはちょうど 1 日を共有します。 鍵はこのチェーンに沿って永久に移動できます。 

カバーされる全長が少なくとも次の値に達したため、サイクルは終了します。`n+m`したがって、最後のワーカーもサイクルを法として最初のワーカーと重複します。 

工事は毎日継続的に行われます。 レイヤーを複製する`k`毎日のアクティブなワーカーの数を乗算します。`k`, したがって、人員配置要件は満たされています。 

最適性はオーバーラップ要件から生まれます。 有効な接続協定では、追加の各従業員が貢献できるのは最大でも`n-1`新しい周期的な日々。 カバーリング`n+m`周期的な日には少なくとも次のものが必要です。$\left\lceil \frac{n+m}{n-1} \right\rceil$レイヤーごとの従業員数なので、合計の最小値は正確に次のようになります。`k`その値の倍になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    t = (n + m + (n - 2)) // (n - 1)

    ans = []

    for _ in range(k):
        for i in range(t):
            ans.append(1 + i * (n - 1))

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```の計算`t`天井分割を使用します:```
(n + m + (n - 2)) // (n - 1)
```なぜなら：```
ceil(a / b) = (a + b - 1) // b
```と`a = n+m`そして`b = n-1`。 

雇用日数は間隔を使用して生成されます`n-1`。 これにより、隣接する従業員が 1 日重複することが保証されます。 

同じパターンが繰り返される`k`回。 従業員は同一のスケジュールを持つ独立した人間であるため、同一の雇用日を再利用することは完全に合法です。 

実装に関する微妙な詳細の 1 つは、`n ≠ 1`ステートメントによって保証されているため、除算は`n-1`常に安全です。 

もう 1 つの簡単な間違いは、レイヤーごとに異なる方法でコピーを配布しようとすることです。 それは不必要です。 完全な複製により、すでに最適な人員配置が実現されています。

import io

def solve():
    input = sys.stdin.readline

    n, m, k = map(int, input().split())

    for _ in range(k):

    print(len(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    sys.stdout = backup_stdout
