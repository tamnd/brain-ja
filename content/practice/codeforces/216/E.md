 ## 解決策
 ## 問題の理解

 Base で書かれた一連の数字が与えられます。`k`。 すべての数字は次の間にあります`0`そして`k - 1`、および 1 つの特殊な数字`b`幸運と呼ばれます。 

数字シーケンスのすべての部分文字列について、その部分文字列をベースとして解釈します。`k`先頭のゼロを許可する数値。 部分文字列のデジタルルートが等しい場合、その部分文字列は幸運であるとみなされます。`b`。 

タスクは、幸運な部分文字列がいくつあるかを数えるということです。 

最初の課題は、任意のベースにおけるデジタル ルートが何を意味するかを理解することです。 10 進数では、数字を繰り返し合計すると、最終的には数値の剰余に相当する値が得られます。`9`。 基地内`k`、同じ現象が係数でも起こります。`k - 1`。 

Baseに数値が書かれているとします。`k`:$$x = d_0 + d_1 k + d_2 k^2 + \dots$$以来$$k \equiv 1 \pmod{k-1}$$私たちにもあります$$x \equiv d_0 + d_1 + d_2 + \dots \pmod{k-1}$$数字の合計プロセスを繰り返すと、モジュロ値が維持されます。`k - 1`、残り 1 桁になるまで。 その最後の数字はまさにデジタルルートです。 

これにより、1 つの特殊な状況が生じます。 通常のモジュロ演算では、剰余`0`デジタルルートに対応`0`。 ただし、次で割り切れる正の数の場合、`k - 1`、デジタルルートは次のようになります`k - 1`、 ない`0`。 これは、10 進数のデジタル ルートの動作と同じです。`18`デジタルルートがあります`9`、 ない`0`。 

この制約により、二次作業を回避せざるを得なくなります。 と`n = 100000`、約あります`5 * 10^9`部分文字列なので、すべての部分文字列を列挙することは不可能です。 部分文字列をチェックインしても`O(1)`それぞれがまだ遅すぎるでしょう。 線形時間に近いものが必要です。 

見落としやすいエッジケースがいくつかあります。 

考慮する：```
2 0 1
0
```唯一の部分文字列は`"0"`。 そのデジタルルートは`0`、したがって、答えは次のとおりです`1`。 

正の数のみに標準のデジタルルート公式を使用する不注意な実装では、誤ってゼロが拒否されます。 

次に、次のことを考えてみましょう。```
10 9 2
1 8
```部分文字列`"18"`桁の合計があります`9`、したがって、そのデジタルルートは`9`、 ない`0`。 

確認だけしていたら`sum % 9 == 0`、誤って root として分類されてしまいます。`0`。 

別の微妙なケースが現れるのは、`k = 2`。 

それから`k - 1 = 1`したがって、すべての数値は次のように一致します。`0 mod 1`。 剰余演算は個別に処理しないと役に立たなくなります。 

例：```
2 1 3
1 0 1
```ゼロ以外のすべての 2 進数にはデジタルルートがあります`1`。 デジタルルートを持つ唯一の部分文字列`0`完全にゼロで構成される部分文字列です。 

すべてのプレフィックス合計が同一のモジュロであるため、直接モジュロベースのソリューションはここで完全に破綻します。`1`。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべての部分文字列について、その桁の合計を計算し、繰り返しそれを単一の基数に減らします。`k`数字を入力し、結果が次と等しいかどうかを確認します`b`。 

がある`O(n^2)`部分文字列。 プレフィックスの合計を事前に計算して、各部分文字列の合計を`O(1)`、それでもすべての部分文字列を検査する必要があります。 と`n = 100000`、これはおおよそになります`5 * 10^9`部分文字列、これは制限をはるかに超えています。 

重要な観察は、デジタル ルートがベースにあることです。`k`桁和モジュロのみに依存します`k - 1`。 

正の数の場合:$$\text{digital root}(x) = \begin{cases} k - 1 & \text{if } x \equiv 0 \pmod{k-1} \\ x \bmod (k-1) & \text{otherwise} \end{cases}$$部分文字列は連続する数字の範囲に対応するため、その数字の合計は接頭辞の合計から取得できます。$$S(l, r) = pref[r] - pref[l-1]$$これにより、問題は、特定の差分を法とするプレフィックスの合計のペアをカウントすることになります。`k - 1`。 

もし`b > 0`の場合、必要なのは次のとおりです。$$S(l,r) \equiv b \pmod{k-1}$$もし`b = 0`、桁の合計がちょうど 0 である部分文字列のみが適格となります。 数字は非負であるため、部分文字列内のすべての数字はゼロでなければならないことを意味します。 

この区別が問題全体です。 

プレフィックス和モジュロに変換されると、`k - 1`、線形時間の周波数マップを使用して有効な部分文字列をカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ベースを読む`k`、幸運の数字`b`、および数字のシーケンス。 
2. 特殊なケースに対処する`b = 0`。 

数値にはデジタルルートがあります`0`数値自体がゼロの場合のみ。 すべての数字は非負であるため、部分文字列は、その中のすべての数字がゼロである場合に正確にゼロを表します。 

配列をスキャンして、連続するゼロ ブロックの長さをカウントします。 一定の長さのブロック`L`貢献します:$$\frac{L(L+1)}{2}$$ゼロのみの部分文字列。 
3. 特殊なケースに対処する`k = 2`。 

バイナリでは、可能な唯一のデジタル ルートは次のとおりです。`0`そして`1`。 

もし`b = 0`、ステップ 2 ですでに処理されています。 

もし`b = 1`、ゼロ以外の部分文字列はすべて幸運です。 部分文字列の合計数は次のとおりです。$$\frac{n(n+1)}{2}$$前にカウントしたゼロのみの部分文字列を減算します。 
4. 一般的な場合`k > 2`そして`b > 0`、 させて：$$m = k - 1$$5. プレフィックス合計の剰余を構築する`m`。 

定義する：$$pref[i] = (a_1 + a_2 + \dots + a_i) \bmod m$$6. 各ポジションについて`r`、以前のプレフィックスが次の条件を満たす必要があります。$$pref[r] - pref[l-1] \equiv b \pmod m$$並べ替え:$$pref[l-1] \equiv pref[r] - b \pmod m$$7. 周波数マップを維持する`cnt`以前に見られたプレフィックス残基の。 

当初は、`cnt[0] = 1`空のプレフィックスが存在するためです。 
8. 各プレフィックス残基について`cur`:

 計算:$$need = (cur - b) \bmod m$$残差を含む以前のすべてのプレフィックス`need`ここで終わるラッキーな部分文字列を形成します。 
9.追加`cnt[need]`答えに応じて増加します`cnt[cur]`。 

### なぜ効果があるのか

 どの部分文字列でも、その桁の合計は 2 つの接頭辞の合計の差に等しくなります。 モジュラー演算では、この差をモジュロで保存します。`k - 1`。 

正のデジタル ルートの場合、値はそのモジュロ クラスによって一意に決定されます。 アルゴリズムによってカウントされたすべての部分文字列は、デジタル ルートに対応する正確なモジュラー条件を満たします。`b`、すべての有効な部分文字列は、一致するプレフィックス ペアを 1 つだけ生成します。 

の`b = 0`モジュロ演算ではデジタルルートを区別できないため、大文字と小文字が区別されます。`0`デジタルルートから`k - 1`。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    k, b, n = map(int, input().split())
    a = list(map(int, input().split()))

    # count zero-only substrings
    zero_substrings = 0
    cur = 0

    for x in a:
        if x == 0:
            cur += 1
        else:
            zero_substrings += cur * (cur + 1) // 2
            cur = 0

    zero_substrings += cur * (cur + 1) // 2

    # digital root 0
    if b == 0:
        print(zero_substrings)
        return

    # base 2 special case
    if k == 2:
        total = n * (n + 1) // 2
        print(total - zero_substrings)
        return

    mod = k - 1

    cnt = defaultdict(int)
    cnt[0] = 1

    ans = 0
    pref = 0

    for x in a:
        pref = (pref + x) % mod

        need = (pref - b) % mod
        ans += cnt[need]

        cnt[pref] += 1

    print(ans)

solve()
```最初のセクションでは、完全にゼロで構成されるすべての部分文字列をカウントします。 これは両方の場合に必要です。`b = 0`ケースとバイナリの特殊なケースの場合。 

ゼロ カウント ロジックは連続したブロックを使用します。 ブロックに長さがある場合`L`とすると、そのブロック内の左右のエンドポイントのすべての選択が有効なゼロ部分文字列を形成し、次のようになります。`L(L+1)/2`。 

次のセクションでは、数学的に厄介なケースを個別に扱います。 

いつ`b = 0`、ゼロ値の数値のみが対象となるため、ゼロのみのカウントをすぐに出力できます。 

いつ`k = 2`、ゼロ以外のすべての数値にはデジタルルートがあります。`1`。 答えは、すべての部分文字列からゼロのみの部分文字列を引いたものになります。 

メインループは prefix-modulo メソッドを実装します。`pref`現在のプレフィックス合計のモジュロを保存します`k - 1`。 新しい位置ごとに、どの前の残基が部分文字列残基を以下と等しくするかを計算します。`b`。 ハッシュマップ`cnt`各残基がこれまでに出現した回数を保存します。 

順序が重要です。 まず、一致する以前のプレフィックスの数をクエリし、次に現在のプレフィックスをマップに挿入します。 この順序を逆にすると、空の部分文字列が誤ってカウントされます。 

Python の整数は、大きな応答サイズを自動的に安全に処理します。 部分文字列の最大数は約`5 * 10^9`とにかく 64 ビット整数に快適に適合します。

    def solve():

            need = (pref - b) % mod
            ans += cnt[need]

            cnt[pref] += 1

        return str(ans)

    return solve()

 ## 特殊なケース

 次のことを考慮してください。```
2 0 1
0
```このアルゴリズムでは、最初にブロックが 0 個カウントされます。 長さは1ブロックあります`1`、 それで：$$\frac{1 \cdot 2}{2} = 1$$以来`b = 0`、アルゴリズムはすぐに戻ります`1`。 

これは、数値ゼロがデジタルルートゼロを持つという事実を正しく処理します。 

次に、次のことを考えてみましょう。```
10 9 2
1 8
```部分文字列の合計は次のとおりです。$$1 + 8 = 9$$モジュロ`9`、これは`0`。 単純なモジュロのみのアプローチでは、デジタル ルートとして分類されます。`0`。 

アルゴリズムはその間違いを回避します。`b = 9`剰余は一般的な正根論理で処理されます。`0`デジタルルートに対応`9`。 

最後に、バイナリの場合を考えてみましょう。```
2 1 3
1 0 1
```以来`k - 1 = 1`、すべてのプレフィックスの和を法的に計算します`1`ゼロになる。 通常のモジュール式ソリューションでは、すべての正の部分文字列を誤ってカウントしてしまいます。`b`。 

特別な処理では以下が計算されます。```
total substrings = 6
zero-only substrings = 1
```そして戻ってきます`5`これは正しいです。ゼロ以外のすべての 2 進数にはデジタル根があるからです。`1`。
