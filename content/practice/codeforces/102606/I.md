 ## 解決策
 ## アプローチ

 直接的なアプローチでは、候補文字列を構築し、そのすべてのサフィックスを生成し、それらを並べ替えて、元のサフィックスが必要なランクを持っているかどうかを確認します。 これはサフィックス配列の定義に正確に従っているため、これは正しいです。 ただし、可能性のある文字列の膨大なスペースを検索する有効な方法はありません。 がある`n`接尾辞があり、それらを生成するにはすでに必要な場合があります`O(n^2)`それらの全長は二次関数であるため、メモリになります。 のために`n = 100000`、最悪の場合、すべてのサフィックスを保存するだけで約 50 億の文字位置が必要になります。 

重要な点は、サフィックス配列を構築する必要がないということです。 サフィックス間の比較を強制する必要があるだけです。 

答えの最初の文字が次であると仮定します。`'b'`。 で始まる任意の接尾辞`'a'`は自動的に小さくなりますが、より大きい文字で始まる接尾辞はすべて`'b'`自動的に大きくなります。 これにより、ランクを簡単に決定できます。 

正確に置くことができます`k - 1`で始まる最初の位置の後の接尾辞`'a'`。 これらの接尾辞はすべて文字列全体の前に来ます。 次に、残りのすべての接尾辞が次で始まるようにします。`'c'`, したがって、それらはすべて文字列全体の後に来ます。 

文字列は次のようになります。```
b + (k-1 times 'a') + (n-k times 'c')
```内で始まるサフィックス`a`ブロックの最初の文字が小さいため、ブロックは小さくなります。`'a'`。 内で始まるサフィックス`c`ブロックの最初の文字が大きいため、ブロックは大きくなります。`'c'`。 文字列全体が次で始まる唯一の接尾辞です。`'b'`、したがって、それはちょうど`k-1`小さな接尾辞。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`k`。 答えの最初の文字は次のようになります`'b'`辞書編集順を使用して、小さな接尾辞を大きな接尾辞から分離したいためです。 
2.追加`k - 1`のコピー`'a'`。 このブロック内で始まる各接尾辞は次で始まります。`'a'`したがって、最初の文字が次のような完全な文字列よりも小さくなります。`'b'`。 これらはまさに、回答の前に表示される接尾辞です。 
3. 追加`n - k`のコピー`'c'`。 このブロック内で始まるすべての接尾辞は次で始まります`'c'`なので、文字列全体よりも大きくなります。 これらの接尾辞は回答の後に表示されます。 
4. 構築された文字列を出力します。 

これが機能する理由: サフィックスは 3 つのグループに分類されます。 最初のグループは次で構成されます。`k - 1`で始まるサフィックス`a`ブロックであり、それらのそれぞれは完全な文字列よりも小さいです。 2 番目のグループはインデックスで始まるサフィックスです。`0`で始まる`b`。 3 番目のグループは、`c`ブロックであり、それらはすべて大きいです。 で始まる接尾辞は他にないため、`b`、完全な文字列は正確に`k - 1`その前に接尾辞。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    ans = ['b']
    ans.append('a' * (k - 1))
    ans.append('c' * (n - k))
    print(''.join(ans))

if __name__ == "__main__":
    solve()
```最初の追加により、ランク付けするサフィックスが作成されます。 次の追加では、入力に必要な数の小さいサフィックスが正確に追加されます。 最後の追加では、サフィックスが大きくなることが保証されている文字で残りの位置を埋めます。 

計算`k - 1`重要な境界の詳細です。 完全な文字列自体は、その前のサフィックスとしてカウントされないため、位置 0 以降のサフィックスのみがカウントを小さくすることができます。 

いつ`k = 1`、中央のブロックの長さは 0 で、答えは`b`に続く`c`文字。 いつ`k = n`、最後のブロックが消え、それ以降のすべてのサフィックスは次のように始まります。`a`、完全な文字列が最大の接尾辞になります。

## テストケース```python
import sys
import io

def make_solution(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    n, k = map(int, sys.stdin.readline().split())
    ans = ['b']
    ans.append('a' * (k - 1))
    ans.append('c' * (n - k))
    print(''.join(ans))

    result = sys.stdout.getvalue().strip()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

def rank_of_string(s):
    suffixes = sorted(s[i:] for i in range(len(s)))
    return suffixes.index(s) + 1

assert rank_of_string(make_solution("4 2")) == 2, "sample 1"
assert rank_of_string(make_solution("8 3")) == 3, "sample 2"

assert rank_of_string(make_solution("1 1")) == 1, "minimum size"
assert rank_of_string(make_solution("5 5")) == 5, "largest rank"
assert rank_of_string(make_solution("10 1")) == 1, "smallest rank"
assert rank_of_string(make_solution("100000 50000")) == 50000, "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1`| 任意の 1 文字の文字列 | 単一のサフィックスの場合を処理します |
 |`5 5`| 4 つの小さな接尾辞を持つ文字列 | 可能な最大のランクを確認します |
 |`10 1`| これ以上の接尾辞を持たない文字列 | 可能な最小のランクをチェックします |
 |`100000 50000`| ランク`50000`| 線形構築スケールを確認 |

 ## 特殊なケース

 のために`n = 5, k = 5`、アルゴリズムが作成する`baaaa`。 最初の位置の後の接尾辞は次のとおりです。`aaaa`、`aaa`、`aa`、 そして`a`。 から始まるため、それらはすべて小さくなります。`a`。 小さなサフィックスが 4 つあるため、完全な文字列は 5 番目になります。 

のために`n = 4, k = 1`、アルゴリズムが作成する`bccc`。 接尾辞は次のとおりです。`bccc`、`ccc`、`cc`、 そして`c`。 最初の接尾辞の後のすべての接尾辞は次で始まります`c`より大きい`b`なので、完全な文字列が最初になります。 

のために`n = 1, k = 1`、アルゴリズムが作成する`b`。 他にサフィックスがないため、ランク 1 を持つ唯一のサフィックスになります。 繰り返されるブロックは両方とも長さが 0 であるため、構築ではこれを自然に処理します。
