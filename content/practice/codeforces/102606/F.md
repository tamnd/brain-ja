 ## 解決策
 ## 問題の理解

 入力はファイルシステムのスナップショットを記述します。 各行はファイルまたはディレクトリを表す絶対パスですが、行はランダムな順序で混在しています。 ディレクトリは、その中に何らかのファイルが存在するためにのみ表示されるため、リスト内のすべてのディレクトリは、少なくとも 1 つのリストされたファイルの祖先になります。 タスクは、名前が次で終わるファイルがリストされているエントリの数を回復することです。`.eoj`。 

問題は、入力ではどのパスがファイルでどのディレクトリであるかがわからないことです。 で終わるパス`.eoj`ディレクトリにもそのサフィックスが付いている可能性があるため、これは自動的に有効な答えにはなりません。 例えば、`/a.eoj/b`それを証明します`/a.eoj`はファイルではなくディレクトリです。 

入力サイズが十分に大きいため、すべてのパスを効率的に処理する必要があります。 パスは 100000 個存在する可能性があり、すべてのパスにわたる文字の合計量は最大 1000000 です。パスのすべてのペアを比較するアプローチは除外されます。これは、約 10^10 の操作が必要になる可能性があるためです。 合計入力サイズにおいて線形に近いアプローチが必要です。 

厄介なケースは、名前とファイルの種類を混同することが原因で発生します。 考慮する：```
1
/a.eoj
```答えは`1`下に子供がいないので`/a.eoj`したがって、このエントリはファイルである必要があります。 

ここで次のことを考えてみましょう。```
2
/a.eoj
/a.eoj/b
```答えは`0`。 サフィックスのみをチェックする不用意なソリューションは重要です`/a.eoj`、しかし 2 番目のパスはそれを証明します`/a.eoj`ディレクトリです。 

別のケースは次のとおりです。```
2
/a.eoj/b.eoj
/a.eoj
```答えは`1`。 パス`/a.eoj`で終わってもディレクトリです`.eoj`、 その間`/a.eoj/b.eoj`ファイルです。 

## アプローチ

 簡単な解決策は、すべてのパスを保存し、次で終わるすべてのパスを保存することです。`.eoj`、入力を検索して、別のパスにスラッシュが続くプレフィックスとしてその文字が含まれているかどうかを確認します。 このような長いパスが存在する場合、候補はディレクトリになります。 すべてのディレクトリには少なくとも 1 つの子孫が必要であるため、これは正しいです。 ただし、パスが 100,000 ある場合は、パスのすべてのペアを比較する必要がある場合があります。 文字列比較のコストを無視しても、これでは約 10^10 のチェックが行われ、遅すぎます。 

重要な観察は、考えられるすべての祖先関係をテストする必要はないということです。 必要な情報は、パスに子があるかどうかだけです。 少なくとも 1 つの他のパスがそのパスで始まり、その後に続く場合、そのパスはディレクトリです。`/`。 

This turns the problem into a prefix problem. すべてのパスをトライに挿入すると、子を持つすべてのノードがディレクトリを表します。 すべてのリーフ ノードは子孫のないパスを表します。これはファイルである必要があります。 次に、完全なパスが次で終わるリーフ ノードのみをカウントします。`.eoj`。 

入力はすでに階層化されているため、トライは自然に適合します。 共有ディレクトリのプレフィックスは 1 回保存され、総作業量は総文字数に比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²L) | O(nL) | 遅すぎる |
 | トライ | O(S) | O(S) | 承認済み |

 ここ、`L`は最大パス長であり、`S`is the total number of characters in all paths.

 ## アルゴリズムのチュートリアル

 1. すべてのパスをコンポーネントに分割し、コンポーネントをトライに挿入します。 各トライ エッジは、1 つのディレクトリまたはファイル名コンポーネントへの移動を表します。 

トライには、シャッフルされたリスト内に隠された親子関係が格納されます。 パスは挿入中に自動的にその先祖に接続されるため、入力順序は重要ではなくなりました。 

1. すべての完全な入力パスの終端を表すノードをマークします。 

入力からの実際のエントリに対応するノードのみをカウントする必要があります。 中間トライ ノードは、より長いパスの先祖であるという理由だけで存在する可能性があります。 

1. Traverse the trie after construction. マークされたすべてのノードについて、子があるかどうかを確認します。 

子を持つマークされたノードは、その下に別の入力パスが続くため、ディレクトリを表します。 子のないマークされたノードは、その下に何も存在しないため、ファイルを表します。 

1. マークされたすべてのリーフ ノードについて、そのフル パス名を再構築または保存し、最終コンポーネントが次で終わるかどうかを確認します。`.eoj`。 あれば答えを増やしてください。 

サフィックスは最後のコンポーネントにのみ属します。 で終わるディレクトリ名`.eoj`葉ではないため無視されます。 

なぜ効果があるのか:

 不変条件は、子を持つすべてのトライ ノードが、その下に少なくとも 1 つの長い入力パスを持つパスに対応するということです。 ディレクトリはその中にファイルがなければ存在できないため、そのようなノードはディレクトリである必要があります。 逆に、子のないマークされたノードは入力に子孫を持たないため、ディレクトリにすることはできず、ファイルにする必要があります。 このアルゴリズムは、応答の定義と一致する、必要な拡張子を持つリーフ エントリを正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("children", "terminal", "name")

    def __init__(self, name=""):
        self.children = {}
        self.terminal = False
        self.name = name

def solve():
    n = int(input())
    root = Node()

    for _ in range(n):
        path = input().strip()
        parts = path.split("/")[1:]
        cur = root
        for part in parts:
            if part not in cur.children:
                cur.children[part] = Node(part)
            cur = cur.children[part]
        cur.terminal = True

    ans = 0

    def dfs(node):
        nonlocal ans
        if node.terminal and not node.children and node.name.endswith(".eoj"):
            ans += 1
        for child in node.children.values():
            dfs(child)

    dfs(root)
    print(ans)

if __name__ == "__main__":
    solve()
```挿入フェーズでは、親の下に一意のパス コンポーネントごとに 1 つのトライ ノードが作成されます。 先頭のスラッシュは意味のあるディレクトリ名ではないため、最初のコンポーネントはルートの下に挿入されます。 

の`terminal`flag は、入力に実際に出現するパスを、祖先としてのみ作成されたノードから分離します。 ディレクトリはリストされたエントリとして存在する可能性がありますが、中間ノードだけでは応答内のファイルまたはディレクトリを表さないため、これは重要です。 

DFS 中の状態は、`not node.children`葉を識別します。 サフィックスチェックは、ノードがファイル候補であることを確認した後にのみ適用されます。 Python の整数には任意の精度があるため、回答数のオーバーフロー処理は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S) | すべての文字が 1 回挿入され、すべてのトライ ノードが 1 回アクセスされます。 
| スペース | O(S) | トライにはパス構造 | が格納されます。 

入力の合計長は最大 1000,000 文字であるため、線形ソリューションは制約に快適に適合します。 このトライでは、繰り返しのプレフィックス比較が回避され、ファイルシステム構造が直接使用されます。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    class Node:
        def __init__(self, name=""):
            self.children = {}
            self.terminal = False
            self.name = name

    n = int(data())
    root = Node()

    for _ in range(n):
        parts = data().strip().split("/")[1:]
        cur = root
        for p in parts:
            if p not in cur.children:
                cur.children[p] = Node(p)
            cur = cur.children[p]
        cur.terminal = True

    ans = 0

    def dfs(x):
        nonlocal ans
        if x.terminal and not x.children and x.name.endswith(".eoj"):
            ans += 1
        for y in x.children.values():
            dfs(y)

    dfs(root)
    sys.stdin = old
    return str(ans) + "\n"

assert run("""3
/secret/eoj
/secret
/secret.eoj
""") == "1\n", "sample 1"

assert run("""2
/cuber.eoj/qq.eoj
/cuber.eoj
""") == "1\n", "sample 2"

assert run("""1
/a.eoj
""") == "1\n", "single file"

assert run("""2
/a.eoj
/a.eoj/b
""") == "0\n", "directory with eoj suffix"

assert run("""4
/a.eoj/b.eoj
/a.eoj
/x
/y.eoj
""") == "2\n", "mixed files and directories"

 | --- | --- | --- |
 |`/a.eoj`|`1`| 単一の接尾辞一致ファイル |
 |`/a.eoj`そして`/a.eoj/b`|`0`| 名前が次で終わるディレクトリ`.eoj`|
 | 混合木 | 写真 混合木`2`| 複数の独立したブランチ |

 ## 特殊なケース

 ディレクトリの名前が次で終わる場合、サフィックス チェックだけでは失敗します。`.eoj`。 

入力：```
2
/a.eoj
/a.eoj/b
```トライ施工中、`/a.eoj`子ノードを取得します`b`。 DFS は次のように認識しています。`/a.eoj`葉ではないのでカウントされません。 結果は`0`。 

接尾辞が一致する祖先を持つネストされたファイルは、祖先に影響を与えてはなりません。 

入力：```
2
/a.eoj/b.eoj
/a.eoj
```トライには子が含まれています`a.eoj`, そのため、そのノードはディレクトリとして扱われます。 のノード`b.eoj`子はなく、次で終わります`.eoj`, したがって、1 カウントに貢献します。 出力は`1`。 

最短の有効な入力にはパスが 1 つだけ含まれます。 

入力：```
1
/x
```トライには 1 つの末端リーフ ノードが含まれます。 以来`x`では終わらない`.eoj`、DFS が返します`0`。 これは、アルゴリズムがすべてのファイルをカウントするのではなく、必要な拡張子を持つファイルのみをカウントすることを確認します。 

必要に応じて、これをさらに短いコンテストの編集形式、またはより説明的なブログ形式のバージョンに適応させることができます。
