 ## 解決策
 ## 問題の理解

 ゲラルトは常に最初の一撃を受ける怪物と戦います。 ゲラルトは、戦闘前に攻撃と防御の 2 つの統計を向上させることができます。 攻撃力が1ポイント増加します`a`クラウン、防御力を1ポイントコスト増加させながら`b`王冠。 アップグレードは小数で行うことができるため、最終的な攻撃力と防御力の値は整数である必要はありません。 

アップグレード後、Geralt は取引します`max(0, attack - monster_defense)`毎ターンダメージを与える。 モンスターはゲラルトが攻撃するたびに HP を失い、生き残った場合にのみ反撃します。 モンスターセール`max(0, monster_attack - Geralt_defense)`ダメージ。 ゲラルトの HP は無限であるため、最小限に抑えられる唯一の量は、モンスターが死ぬ前に受ける合計ダメージです。 

各テスト ケースの入力により、両方の戦闘機の初期攻撃力と防御力、モンスターの HP、利用可能なクラウン、および 2 つのアップグレード価格が得られます。 出力は、ゲラルトが受ける可能性のある最小のダメージであり、換算された分数として記述されます。`-1`アップグレード計画がなければ彼を勝たせることはできない。 

単一の値の場合、制約は小さくなります。`n`、ただし、最大で`10^4`テストケース。 支出するアルゴリズム`O(n)`すべてのケースにかかる時間は約`10^8`このようなループ内で高価な分数演算を使用すると、Python では遅すぎます。 ソリューションでは、アップグレードの可能性をシミュレートするのではなく、最適化の数学的形状を利用する必要があります。 

危険なケースは、継続的なアップグレードが不連続な数の攻撃と相互作用するケースです。 

ゲラルトが効果的な攻撃を何もせずに開始した場合、最大ターン数が固定されていると考えるのは間違いです。 例えば：```
1
1 10 100 1
10 5 1 100
```ゲラルトの攻撃力はモンスターの防御力を下回っているため、初期ダメージはありません。 彼は任意の小さな攻撃増加を購入できるため、攻撃の数は元の攻撃値に制限されません。 

もう 1 つのよくある間違いは、最後のモンスターの攻撃を数えるということです。 モンスターがゲラルトの攻撃で死亡した場合、反撃はされません。 例えば：```
1
5 1 1 1
1 1 1 1
```ゲラルトはすでに取引しています`4`ダメージを与えてモンスターを即座に殺します。 答えは次のとおりです。```
0/1
```ゲラルトのターンごとにモンスターのダメージを追加するシミュレーションで、誤って正の値が出力される問題を修正しました。 

分数の処理も重要です。 計画では攻撃の部分的な増加が必要になる場合があり、最終的な答えは整数ではない可能性があります。 たとえば、最適な防御力の低下により、ヒットごとに合理的な量のダメージが残る可能性があるため、浮動小数点演算の精度が失われる可能性があります。 

## アプローチ

 直接的なアプローチでは、攻撃のアップグレードを可能な限り試し、防御に費やされる残りの金額を計算し、必要な攻撃の数をシミュレートして、最良の結果を維持します。 すべての合法的なアップグレードの選択がチェックされるため、これは正しいです。 ただし、アップグレード値は継続的であるため、選択肢は無限にあります。 必要な攻撃回数だけを見ても、`n`テストケースごとの可能性。 横切って`10^4`場合によっては、これでは遅すぎます。 

有益な観察は、攻撃のアップグレードはモンスターを倒すのに必要なターン数だけが重要であるということです。 ゲラルトがまさに必要としていると仮定します`k`攻撃します。 これを達成する最も安価な方法は、次の条件を満たすのに十分なダメージを与えることです。```
k * damage >= n
```追加の攻撃ダメージはモンスターの攻撃数を減らすものではないため、防御に費やすことができたクラウンを無駄にするだけです。 

固定の場合`k`、最小攻撃投資を計算し、残りのすべてのクラウンを防御に投入できます。 問題は可能な限り最善のものを見つけることになる`k`。 

ゲラルトがすでにプラスのダメージを持っている場合、可能な攻撃の数には制限があります。 せいぜい必要な攻撃のアップグレードがなければ`ceil(n / base_damage)`攻撃の数を減らすことはできますが、攻撃をアップグレードしてもその数を減らすことはできません。 この範囲内で最小化することはできますが、すべての値をチェックするのではなく数学的に実行します。 

攻撃回数の候補について`k`、受けたダメージは次の形式の関数です。```
(k - 1) * max(0, C - T/k)
```定数の場合`C`そして`T`。 最大演算を削除すると、これは整数に対する凸関数または単調関数になります。 つまり、最小値は境界付近、または導関数がゼロになる点の近くにのみ現れる可能性があります。 いくつかの隣接する整数値をチェックするだけで十分です。 

ゲラルトがダメージゼロで開始する場合、2 つの特殊なケースがあります。 守備を完全に無力化して攻撃に少しでもお金を残せれば、答えは即座にゼロになります。 それ以外の場合は、機能が増加しているため、攻撃の最適な数は実行可能な最小の攻撃になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(n) | お(1) | 多くのケースで遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ゲラルトの現在の実効攻撃ダメージと、ゲラルトに対するモンスターの現在の実効ダメージを計算します。 ゲラルトの攻撃がすでに十分である場合、後の計算式ではこの値が開始点として使用されます。 
2. ゲラルトの攻撃ダメージがゼロの場合に対処します。 防御にクラウンを費やすことでモンスターのダメージをゼロにできる場合、答えは次のとおりです。`0/1`。 それ以外の場合は、可能な限り最小の攻撃数を計算し、その選択のみを評価します。 
3. 初期攻撃ダメージをプラスするには、次のようにします。`h`必要な攻撃回数になります。 可能な限り最大の`h`攻撃アップグレードなしの攻撃の数です。 最適な`h`は境界値、またはダメージ関数の連続バージョンが最小値に達する点に近い値です。 
4. 必要な候補値を確認します。`h`。 すべての候補について、必要な最小限の攻撃アップグレードを計算し、残りのクラウンをすべて防御に使用し、受けるダメージを分数として計算します。 
5. 最小の端数を保持し、縮小して印刷します。 

機能する理由: 攻撃回数が固定されている場合、追加のクラウンを攻撃に費やしてもターン数を改善することはできないため、最適な解決策は常にそのターン数に必要な最小限の攻撃アップグレードを使用し、残りを防御に費やします。 残りの最適化は 1 変数関数です。 その形状は単調または凸状であるため、境界と静止点の近傍をチェックすることによって最小値が捕捉されます。 

## Python ソリューション```python
import sys
from fractions import Fraction

input = sys.stdin.readline

def solve_case(ag, dg, ac, dc, n, m, a, b):
    base_attack = max(0, ag - dc)
    base_taken = max(0, ac - dg)

    def evaluate(k):
        need = Fraction(n, k)
        add_attack = max(Fraction(0), need - base_attack)
        remain = Fraction(m) - Fraction(a) * add_attack
        defense_gain = remain / b
        taken = max(Fraction(0), Fraction(base_taken) - defense_gain)
        return (k - 1) * taken

    if base_attack == 0:
        if b * base_taken < m:
            return Fraction(0)
        k = (n * a + m - 1) // m
        return evaluate(k)

    kmax = (n + base_attack - 1) // base_attack

    if kmax == 1:
        return Fraction(0)

    candidates = {1, kmax}

    last = kmax - 1
    if last >= 1:
        c = b * base_taken - b * m + a * base_attack
        t = a * n

        if c <= 0:
            candidates.add(last)
        else:
            root = int((t / c) ** Fraction(1, 2))
            for x in range(root - 3, root + 4):
                if 1 <= x <= last:
                    candidates.add(x)

    ans = None
    for k in candidates:
        if 1 <= k <= kmax:
            cur = evaluate(k)
            if ans is None or cur < ans:
                ans = cur

    return ans

def main():
    out = []
    t = int(input())
    for _ in range(t):
        ag, dg, ac, dc = map(int, input().split())
        n, m, a, b = map(int, input().split())

        ans = solve_case(ag, dg, ac, dc, n, m, a, b)
        out.append(f"{ans.numerator}/{ans.denominator}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```機能`evaluate`これは固定回転観測の直訳です。 まず、フィニッシュするために必要な最小の攻撃力の増加を見つけます。`k`攻撃します。 攻撃と防御は同じクラウン予算を使用するため、残りのお金は常に防御に変換されます。 

攻撃ゼロのケースは、考えられる攻撃の数が元の統計によって制限されないため、分離されます。 防御を完全に解除できる場合、小さな攻撃アップグレードと多くの攻撃を使用すると、受けるダメージはゼロになります。 

プラスの攻撃ダメージを得るには、`kmax`攻撃を購入しない攻撃の数です。 アップグレードは攻撃を増加させるだけなので、これ以上多くの攻撃を最適化することはできません。 候補検索では、残りの関数の凸型を使用し、数学的最小値に近い値のみをチェックします。`Fraction`は、最終的な少数の候補セットにのみ使用されます。 実行時間を短くしながら浮動小数点エラーを回避します。 Python の整数は、すべての中間値も安全に処理します。

 ## 特殊なケース

 ゲラルトが攻撃ダメージをゼロで開始した場合、アルゴリズムは攻撃数を列挙しようとしません。 防御力が受けるダメージをゼロにできるかどうかをチェックします。 それができる場合、ゲラルトは攻撃に任意の少額を費やし、残りを防御に費やすことができるため、答えはゼロになります。 

ゲラルトが 1 回の攻撃でモンスターを倒すと、乗数は`(k - 1)`ゼロになります。 実装ではこの正確な条件が維持されるため、最終的なモンスターストライクが誤ってカウントされることはありません。 

最適なアップグレードに分数が必要な場合、すべての計算は有理数として保持されます。 最後の分数は Python によって自動的に約定されます。`Fraction`、四捨五入された 10 進数値によるエラーを回避します。
