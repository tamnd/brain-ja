 ## 解決策
 ## 問題の理解

 この問題は次の行を説明しています`n`所定の位置に置かれたカップ`1`を通して`n`。 骨は最初のカップの下から始まります。 一部の位置には穴があります。 カップ位置のペア間で一連のスワップが実行されます。 交換中、2 つのカップの位置が即座に入れ替わるため、骨は交換されたカップの一方の内側にある場合にのみ動きます。 交換後に骨が穴に達すると、骨は抜け落ちて永久に消えます。 タスクは、骨の最終的な位置を決定するか、骨が落ちたことを報告することです。 

入力により、カップ ポジションの数、ホールの数、スワップの数、ホールの位置、そしてスワップ操作が与えられます。 出力は、ボーンが穴の中で失われた場合を除き、すべての操作後のボーンを含む最終位置です。 

制約により、意図したソリューションが明確になります。 操作の数が十分に大きいため、指定されたスワップを超えるものをシミュレートする必要がない場合があります。 各スワップは 2 つのポジションにのみ影響するため、スワップごとに一定の時間を費やすソリューションが理想的です。 高価なデータ構造を構築したり、操作のたびにすべてのカップをチェックしたりすると、回避可能なオーバーヘッドが発生します。 

厄介なケースは、穴に落ちるとその後の動きがすべて止まってしまうという事実から生じます。 よくある間違いは、ボーンが消えた後もスワップを適用し続けることです。 

たとえば、入力が次の場合:```
3 1 2
2
1 2
2 3
```ボーンは次の位置から始まります`1`。 最初の交換により、次の位置に移動します。`2`、ここには穴があるため、正しい出力は次のようになります。```
-1
```最後まで穴を無視した不注意なシミュレーションにより、ボーンが所定の位置から移動してしまいます。`2`位置を決める`3`そして間違った答えを出力します。 

もう 1 つのエッジ ケースは、スワップに現在のボーンの位置が関与しない場合です。 例えば：```
5 0 2
1 2
4 5
```骨は次から始まります`1`。 最初の交換により、次の場所に移動します。`2`、2回目の交換は影響しません。 答えは次のとおりです。```
2
```ボーンの位置を正しく追跡せずにカップを交換する実装では、誤ってボーンが再び移動する可能性があります。 

## アプローチ

 直接的なアプローチは、現在のボーンの位置を保持し、すべてのスワップを処理することです。 各操作で、ボーンが 2 つの交換された位置のいずれかにある場合、ボーンはもう一方の位置に移動します。 移動後、新しい位置が穴であるかどうかを確認します。 そうなると骨がなくなってしまいます。 

入力自体が答えを変えることができる唯一のイベントを記述するため、この強引なアプローチはすでに最適です。 カップの配置全体を再構築する必要はありません。 関連する情報は、骨の位置と、その位置が穴であるかどうかだけです。 

より複雑なシミュレーションでは、すべてのカップを保存し、交換のたびにオブジェクトを移動させる可能性があります。 これは概念的には機能しますが、重要ではない情報を追跡します。 カップは骨の周囲にラベルを付けているだけであり、質問は骨のみについて尋ねています。 スワップでは、ボーンの現在位置がスワップされた位置の 1 つである場合にのみボーンの位置が変更されるため、プロセス全体を 1 つの整数更新に減らすことができます。 

直接的なシミュレーションはすでに最小限の作業であるため、総当たり解と最適解はここでは同じです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(k) | O(n) | 承認済み |
 | 最適 | O(k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての穴位置をセットに保存します。 セットを使用すると、一定の平均時間で移動後にボーンが落ちたかどうかを確認できます。 
2. ボーンの位置を次のように初期化します。`1`、骨は最初のカップの下から始まるためです。 
3. スワップを 1 つずつ処理します。 ポジション間の交換の場合`u`そして`v`からボーンを移動します。`u`に`v`またはから`v`に`u`それが現在それらのカップのいずれかの下にある場合のみ。 どちらの位置にもボーンが含まれていない場合、交換は答えに影響を与えません。 
4. 各移動の後、新しいボーンの位置が穴かどうかを確認します。 そうなっている場合は、ボーンを失われたものとしてマークし、今後のスワップの処理を停止します。 
5. ボーンを失わずにすべてのスワップが処理された場合は、その最終位置を出力します。 

なぜ効果があるのか:

 どの瞬間においても、カップの配置で重要なのは、現在カップが骨を隠している部分だけです。 スワップでは、そのカップがスワップに参加するときに正確にボーンの位置が変更されます。 アルゴリズムはこれらの変更を正確に適用し、ボーンに影響を与えないスワップを無視します。 あらゆる動きを行った後、すぐに穴の状態をチェックし、プロセスのルールと一致させます。 状態は操作のたびに更新されるため、最終的に保存された位置は正確に実際の結果になります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    holes = set(map(int, input().split()))

    pos = 1
    alive = True

    for _ in range(k):
        u, v = map(int, input().split())

        if alive:
            if pos == u:
                pos = v
            elif pos == v:
                pos = u

            if pos in holes:
                alive = False

    print(pos if alive else -1)

if __name__ == "__main__":
    solve()
```スワップのたびにメンバーシップのチェックが行われるため、このソリューションではハッシュ セットにホールが保存されます。 リストも機能しますが、セットは、位置が危険かどうかを尋ねる、必要な操作を直接表します。 

変数`pos`シミュレーションの完全な状態です。 スワップはこの位置に触れた場合にのみ問題となるため、カップの内容を保存する必要はありません。 

の`alive`フラグは、骨が落ちた後に後のスワップによって答えが変更されるのを防ぎます。 これは、骨が穴に到達すると、カップ内に骨が存在しないという問題のルールと一致します。 

操作の順序は重要です。 骨は新しい位置に到着した後にのみ落下する可能性があるため、交換は穴を確認する前に行う必要があります。 移動前にチェックすると、スワップによってボーンが穴に直接配置されるケースが見逃されます。

## テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    holes = set(map(int, input().split()))

    pos = 1
    alive = True

    for _ in range(k):
        u, v = map(int, input().split())

        if alive:
            if pos == u:
                pos = v
            elif pos == v:
                pos = u

            if pos in holes:
                alive = False

    ans = str(pos if alive else -1)

    sys.stdin = old_stdin
    return ans

assert solve_io(
    "3 1 2\n"
    "2\n"
    "1 2\n"
    "2 3\n"
) == "-1"

assert solve_io(
    "5 0 2\n"
    "1 2\n"
    "4 5\n"
) == "2"

assert solve_io(
    "1 1 0\n"
    "1\n"
) == "1"

assert solve_io(
    "4 0 3\n"
    "1 2\n"
    "2 3\n"
    "4 1\n"
) == "3"

assert solve_io(
    "5 5 1\n"
    "1 2 3 4 5\n"
    "1 5\n"
) == "-1"

 | ボーンに必ずしも影響を与えるわけではないスワップ |`2`または`3`動き次第 | 現在のカップの正しい追跡 |

 ## 特殊なケース

 骨が穴に落ちた場合、将来の交換によって骨が復活してはなりません。 で：```
3 1 2
2
1 2
2 3
```最初の交換によりボーンが移動します`1`に`2`。 アルゴリズムはすぐにそれを認識します`2`穴とセットです`alive`偽に。 2 番目のスワップは読み取られますが、答えを変更できないため、出力は次のようになります。`-1`。 

スワップにボーンが関与しない場合、位置は変更されないままでなければなりません。 で：```
5 0 2
1 2
4 5
```最初の交換によりボーンが移動します`1`に`2`。 2回目の交換はカップ交換のみ`4`そして`5`、したがって骨は に留まります。`2`。 アルゴリズムは次のことのみをチェックします。`pos`スワップされたエンドポイントの 1 つと一致し、正しい状態が保存されます。 

スワップがない場合、その位置がすでにホールでない限り、答えは単純に最初の位置になります。 アルゴリズムは次から始まります`pos = 1`更新は実行しないため、このケースは自然に処理されます。
