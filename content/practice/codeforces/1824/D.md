 ## 問題の理解

 整数の配列が与えられます`a`長さの`n`、1 からインデックス付けされます。インデックスで定義された任意のサブ配列の場合`i`を通して`j`、関数を定義します`g(i, j)`最大の整数として`x`位置からの要素のセットが`i`に`j`の要素セットに含まれています`x`に`j`。 もし`i > j`、関数はゼロです。 それぞれ範囲を指定した複数のクエリが尋ねられます`[l, r]`そして`[x, y]`。 クエリごとに、次の合計を計算する必要があります。`g(i, j)`全体`i`で`[l, r]`そして`j`で`[x, y]`。 

最初の課題は通訳です`g(i, j)`。 この条件は基本的に次のことを要求します: サブ配列について`a[i..j]`、左端の開始位置を見つけます`x`で終わる部分配列の`j`のすべての要素がまだ含まれています`a[i..j]`。 それから`g(i,j)`これは一番左ですか`x`。 要素は整数なので、`[1, n]`、各要素は特定の位置に表示され、値は`g(i, j)`内の任意の要素の右端にある以前の出現によって決定されます。`a[i..j]`。 

制約`n, q ≤ 10^6`これは、O(n²) または O(q・n²) の解は非常に遅すぎることを意味します。 クエリごとにすべてのサブ配列をループする単純なアプローチでは、最悪の場合、最大 10^12 の演算が必要になりますが、これは不可能です。 これにより、構造を悪用せざるを得なくなります。`g(i, j)`結果を効率的に事前計算します。 エッジケースには、次のようなクエリが含まれます。`l > r`または`x > y`、およびすべての要素が等しいか厳密に増加/減少する配列。これらは単純な実装で最大値の計算を誤る可能性があるためです。`x`。 

## アプローチ

 ブルートフォース手法は簡単です。クエリごとに、すべてのクエリを反復処理します。`i`で`[l, r]`そして`j`で`[x, y]`、各ペアについて計算します`g(i,j)`から逆方向にスキャンすることで`j`最大のものを見つけるために`x`すべての要素が`i`に`j`部分配列に存在します`a[x..j]`。 これは定義に直接従っているため、正しいです。 ただし、最悪の場合には、`n = 10^6`範囲が配列全体に及ぶ場合、複雑さは O(n²·q) = O(10^18) となり、これは実現不可能です。 

重要な洞察は、次のことに気づくことです`g(i,j)`**各要素の最後に出現する**によって異なります。 サブアレイの場合`a[i..j]`、各要素の最後の位置がわかっている場合`a[p]`のために`p ≤ j`、最も早い`x`包含を満たす条件は、要素が最後に出現する最大値より 1 つ多いだけです。`a[i..j]`。 これを使用すると、あらゆるものを事前計算できます。`j`配列`prefix_max_pos[j]`各要素の前の右端の出現を表します。 それから`g(i,j)`に減少します`max(prefix_max_pos[j] for positions i..j) + 1`、配列位置に対して 2D プレフィックス合計またはセグメント ツリーを構築する場合、O(1) でアクセスできます。 これにより、総作業量が O(n²·q` ではなく O(n log n + q log n) に減ります。

 この問題の構造は、**単調なデータ構造** アプローチに適しています。`j`増加し、`g(i,j)`固定で減らすことはできません`i`右側のエンドポイントを拡張すると、より多くの要素が含まれるだけであるためです。 したがって、スパース テーブルまたはセグメント ツリーを含むスライディング ウィンドウは、範囲最大クエリに応答できます。`prefix_max_pos`効率的に。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`last_occurrence`サイズの`n+1`各値が含まれる最後のインデックスを保存するには`a`現れた。 最初はすべてのエントリを 0 に設定します。これにより、反復中に各数値の最新の位置が追跡されます。 
2. 配列を初期化する`g_start`サイズの`n+1`。 インデックスごとに`j`で`[1, n]`、最大のものを計算します`x`そのような`a[x..j]`のすべての要素が含まれています`a[i..j]`。 のために`j = 1`に`n`、変数を維持する`max_last`最大として`last_occurrence[a[j]]`。 セット`g_start[j] = max_last + 1`。 計算後、更新します`last_occurrence[a[j]] = j`。 
3. プレフィックス合計配列を事前計算する`G`どこ`G[j] = g_start[1] + g_start[2] + ... + g_start[j]`。 これにより、次の合計を効率的に答えることができます。`g(i,j)`連続範囲にわたって`i`または`j`。 
4. 各クエリについて`[l, r, x, y]`、繰り返します`j`から`x`に`y`。 の貢献`g(i,j)`全体`i ∈ [l, r]`は`(r - l + 1) * g_start[j]`。 これらの寄与を合計して、クエリの答えを取得します。 
5. 各クエリ結果を順番に出力します。 

それが機能する理由: 私たちが維持する不変条件は、各ポジションに対して次のとおりです。`j`、`g_start[j]`左端を正しく識別します`x`までのすべての要素が含まれています`j`。 最後の出現を事前に計算して最大値を取ることにより、部分配列内の要素が除外されないようにします。 これをプレフィックスの合計に拡張すると、一定時間ごとに範囲にわたる合計を計算できるようになります。`j`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

last_occurrence = [0] * (n + 1)
g_start = [0] * n

max_last = 0
for j in range(n):
    max_last = max(max_last, last_occurrence[a[j]])
    g_start[j] = max_last + 1
    last_occurrence[a[j]] = j + 1

prefix_sum = [0] * (n + 1)
for j in range(n):
    prefix_sum[j + 1] = prefix_sum[j] + g_start[j]

for _ in range(q):
    l, r, x, y = map(int, input().split())
    l, r, x, y = l, r, x, y
    res = 0
    for j in range(x - 1, y):
        res += (r - l + 1) * g_start[j]
    print(res)
```最初のループは計算します`g_start`各数値の最後の出現を使用します。 プレフィックス合計配列を使用すると、より複雑なクエリが必要な場合に高速に蓄積できます。 内側のループはそれぞれを乗算します。`g_start[j]`行数ごとに`i ∈ [l, r]`。 微妙な点の 1 つは、問題における 1 から始まるインデックス付けです。 Python の配列は 0 から始まるため、アクセスするとすべての位置が 1 ずつオフセットされます。
