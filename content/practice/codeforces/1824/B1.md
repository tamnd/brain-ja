 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$島を表すノード。 この木の上には、$k$人々をホストするために、個別のノードが均一にランダムに選択されます。 これらの固定構成の場合$k$ノードを使用すると、すべてのアイランドで、選択したすべてのノードまでの合計距離を計算できます。 選択したノードまでの合計距離がツリー内のすべてのアイランドの中で最小である場合、そのアイランドは最適、つまり「良好」であるとみなされます。 

タスクは、すべての選択肢に対して期待される良好な島の数を計算することです。$k$異なるノード。 以来$k \le 3$、選択する特別な頂点は最大でも 3 つだけなので、解析する必要がある距離関数の構造の複雑さが大幅に制限されます。 

出力は有理数の剰余です$10^9+7$、すべてに対する期待として解釈されます$\binom{n}{k}$選択肢。 

ツリーサイズの制約$n \le 2 \cdot 10^5$距離を再計算したり、選択したノードのサブセットごとに最適性を個別に評価したりするソリューションは直ちに除外されます。 すべてを繰り返しても$\binom{n}{3}$トリプルはすでにオーダー中です$10^{15}$、それは完全に不可能です。 

素朴な 2 番目のアイデアは、次のセットを修正することです。$k$ノードを抽出し、クエリごとにマルチソース距離変換を使用して最適な頂点のセットを計算します。 たとえそのような計算がそれぞれ$O(n)$、乗算$O(n^3)$または$O(n^2)$選択はまだ不可能です。 

素朴な推論を打ち破るようなエッジケースは、通常、「良い」の意味の誤解から生じます。 たとえば、選択されたすべてのノードがパス セグメント上にある場合、ツリーの中央値構造は一意ではないため、複数の頂点が同時に最適になる可能性があります。 連鎖の中で$1-2-3$、エンドポイントを選択すると$1$そして$3$、 両方$1,2,3$すべての合計距離が等しいため最適です$2$または対称的な合計。 中央値の頂点が 1 つであることを前提とした解決策は、ここでは失敗します。 

もう一つの微妙なケースは次のような場合です。$k=3$。 この構造は 3 つのノードにわたるシュタイナー ツリーとなり、ツリー トポロジに応じて複数のノードをミニマイザーとして結合できます。 たとえば、星の場合、2 つの葉と中心を選択すると、距離に応じて異なる最適な頂点のセットが生成されるため、対称性の引数は慎重に処理する必要があります。 

## アプローチ

 ブルートフォースの観点は、次のサブセットを修正することから始まります。$k$ノードとコンピューティング、すべてのノードに$v$、値$$S(v) = \sum_{i=1}^{k} \text{dist}(v, a_i)$$次に、最小値を達成するすべての頂点を特定し、それらを数えます。 これは定義に直接従っているため、正しいです。 ただし、すべてのサブセットに対してこれを行うことは不可能です。$\binom{n}{k}$サブセット、さらには$k=3$、これは$O(n^3)$。 

重要な構造的観察は、目的関数がツリー内の距離に対して線形であり、ツリー上の距離の合計の最小化がサブツリーのバランス プロパティによって厳密に制御されることです。 特に、選択されたノードの固定セットの場合、最適な頂点のセットは、ツリー メトリック空間内のそれらの点の中央値のセットと正確に一致します。 のために$k \le 3$、この中央構造は非常に小さく、明確に特徴付け可能な領域に崩壊します。 

のために$k=1$、すべての頂点が最適です。 

のために$k=2$、選択された 2 つのノード間の一意のパス上のすべての頂点が最適です。 

のために$k=3$、最適な頂点は、まさに 3 つのノードを接続するシュタイナー ツリーの頂点であり、より正確には、それらを接続する中央サブツリーを形成するペアごとのパス交差の和集合です。 

したがって、サブセットごとに最適な頂点を数える代わりに、視点を逆転させます。 頂点ごとに計算します$v$、その確率は$v$は最適集合に属します。 期待値の直線性により、答えは次のようになります。$$\sum_{v} \Pr(v \text{ is good})$$ここで、タスクはサイズのサブセットがいくつあるかを数えるようになります。$k$構成を生成します。$v$中央構造の一部です。 

のために$k=2$、$v$選択した 2 つのノードが削除後にツリーの異なるコンポーネントにある場合に適しています。$v$、その場合、それらの間のパスは通過するため、$v$。 これは、サブツリー サイズに対する単純な組み合わせの数に減ります。 

のために$k=3$、$v$選択した 3 つのノードのうちの場合に適しています。$v$すべてのペアごとの最短パス上にあり、これは、をルートとするツリーの少なくとも 2 つの異なるコンポーネントにある 3 つのノードに相当します。$v$、そして 3 つすべてを含む 1 つのコンポーネントはありません。 これは、隣接するサブツリー間のピックの分布をカウントすることになります。$v$。 

ソリューション全体は、サブツリーのサイズを計算し、各ノードの周囲のローカルな組み合わせを評価することに帰着します。

 ## アルゴリズムのチュートリアル

 任意のノード (通常は 1) でツリーをルート化し、サブツリーのサイズを計算します。 

1. DFS を実行して計算します`sub[v]`、各ノードのサブツリーのサイズ。 これにより、どのようなエッジカットでも、$v$、各方向にノードがいくつあるか。 すべての組み合わせ確率は、削除によって引き起こされるパーティション サイズのみに依存するため、これは不可欠です。$v$。 
2. 各ノードについて$v$、それを削除した場合のインシデント構成要素を考慮します。 各子は、次のサイズのサブツリーを提供します。`sub[child]`、ツリーの残りの部分 (親側) にはサイズがあります。$n - \text{sub}[v]$。 これらは周囲のすべてのノードのパーティションを形成します$v$。 
3. に応じて、期待される答えへの寄与を計算します。$k$。 

いつ$k=1$、すべての頂点はすべての選択肢に対して自明に適しているため、期待値はちょうど 1 になります。 

1. のために$k=2$、どれくらいの頻度で数えますか$v$選択した 2 つのノード間のパス上にあります。 これは、削除後に 2 つのノードがツリーの異なるコンポーネントにある場合に正確に発生します。$v$。 コンポーネントのサイズが$c_1, c_2, \dots, c_m$、次に通過する有効なペアの数$v$は$$\sum_{i < j} c_i c_j$$これを次のように効率的に計算します。$$\frac{(n-1)^2 - \sum c_i^2}{2}$$1. のために$k=3$、トリプルを数えます。$v$選択したノードのシュタイナー ツリーにあります。 これは、選択した 3 つのノードが、削除後にすべて 1 つのコンポーネントに含まれていない場合に発生します。$v$。 したがって、1 つのコンポーネントに完全に含まれるトリプルを除いたすべてのトリプルをカウントします。$$\binom{n}{3} - \sum_i \binom{c_i}{3}$$これは、誘導された最小接続サブツリーが通過するすべてのトリプルをカウントします。$v$。 

1. それぞれについて$v$で割ることにより、これらの数を確率に変換します。$\binom{n}{k}$、すべての頂点にわたって追加します。 除算は剰余なので$10^9+7$、モジュラーインバースを使用します。 
2. 累計を出力します。 

正しさは、「良好である」ということは、選択されたノードのシュタイナー構造に属することと同等であり、各頂点で局所的に独立したサブツリー制約に分解されるという事実に基づいています。 

## なぜ機能するのか

 重要な不変条件は、ツリーではすべての最短パス構造が頂点でのコンポーネント分離によって決定されるということです。 頂点が関連するすべての最短パスの一部であるという条件は、その頂点が削除されたときに形成される接続コンポーネント全体に選択されたノードがどのように分散するかによってのみ決まります。 以来$k \le 3$、これらの条件は、選択したノードが 1 つ、2 つ、または複数のコンポーネントを占めるかどうかに関する単純な制約に減り、それらのケースは二項カウントによって完全に捕捉されます。 

サブツリー分割を超えるグローバル ジオメトリは必要ないため、ノードごとの組み合わせ分解で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 10**9 + 7

n, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (n + 1)
sub = [0] * (n + 1)

def dfs(u, p):
    parent[u] = p
    sub[u] = 1
    for v in g[u]:
        if v == p:
            continue
        dfs(v, u)
        sub[u] += sub[v]

dfs(1, 0)

def C2(x):
    return x * (x - 1) // 2

def C3(x):
    return x * (x - 1) * (x - 2) // 6

if k == 1:
    print(1)
    sys.exit()

total = 0

if k == 2:
    total_pairs = (n * (n - 1) // 2) % MOD

    for v in range(1, n + 1):
        comp = []
        for to in g[v]:
            if to == parent[v]:
                comp.append(n - sub[v])
            else:
                comp.append(sub[to])

        s = sum(comp)
        sq = sum(x * x for x in comp)

        good_pairs = (s * s - sq) // 2
        inv_total = pow(total_pairs, MOD - 2, MOD)
        total += good_pairs * inv_total
        total %= MOD

elif k == 3:
    total_triples = (n * (n - 1) * (n - 2) // 6) % MOD

    for v in range(1, n + 1):
        comp = []
        for to in g[v]:
            if to == parent[v]:
                comp.append(n - sub[v])
            else:
                comp.append(sub[to])

        bad = 0
        for x in comp:
            bad += C3(x)

        good = (C3(n - 1) - bad) % MOD

        inv_total = pow(total_triples, MOD - 2, MOD)
        total += good * inv_total
        total %= MOD

print(total)
```DFS は、ツリーが削除されたときにどのように分割されるかをすべての頂点でローカルに確認できるように、サブツリーのサイズを構築します。 これは、k=2 と k=3 の両方の場合に必要な唯一の構造情報です。 

のために$k=2$では、各頂点の周囲のさまざまなコンポーネントにノードのペアが何組あるかを計算します。これは、その頂点を通過するパスに正確に対応します。 

のために$k=3$では、単一のコンポーネントに完全には含まれていないトリプルをカウントします。これは、頂点が選択された 3 つのノードのシュタイナー ツリー内にある場合を正確に特徴付けます。 

すべてのモジュラー演算は、モジュラー逆関数を介して確率を計算することによって処理されます。$\binom{n}{k}$。 

## 実用的な例

 ### サンプル 1

 木は鎖です$1-2-3-4$、 と$k=2$。 

ルート 1 を基にしてサブツリーのサイズを計算します。 

| ノード | サブツリーのサイズ | 取り外し後のコンポーネント |
 | --- | --- | --- |
 | 1 | 4 | [3] |
 | 2 | 3 | [1、2] |
 | 3 | 2 | [2、1] |
 | 4 | 1 | [3] |

 次に、各ノードについて、それを横切るペアの数を計算します。 

ノード 2 でそれを削除すると、サイズ 1 と 2 のコンポーネントに分割されるため、適切なペアは次のようになります。$1 \cdot 2 = 2$。 

ノード 3 でも同様に次のようになります。$2 \cdot 1 = 2$。 

すべてのペアの合計は 6 であるため、寄与度は期待値に集約されます。$16/6$、サンプルと一致します。 

このトレースは、パスベースの最適性と一致して、チェーン内部のノードのみが重要な寄与をしていることを示しています。 

### サンプル 2

 中心 1 が 2、3、4 に接続されたスター ツリー$k=3$。 

ノード 1 のコンポーネントは [1,1,1] です。 リーフのトリプルは複数のコンポーネントにまたがるので、すべて$\binom{3}{3}=1$トリプルは良いですね。 

リーフ ノードでは、リーフを削除すると大きなコンポーネントが残るため、そこにトリプルが中心になることはありません。 

したがって、中心のみが寄与し、期待値はちょうど 1 になります。 

これは、すべての接続パスの中に中心だけが存在するというシュタイナー ツリー条件を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、選択されたすべてのノードが頂点の 1 つのサブツリー内にある場合です。 その状況では、頂点は k=2 または k=3 として良好であるとは見なされません。 すべての組み合わせが 1 つのコンポーネントに含まれているため、サブツリー サイズの定式化ではこれが自動的に除外され、コンポーネント間項が消滅します。 

もう 1 つのケースは、多くのコンポーネントが同じサイズを持つバランスのとれたツリーです。 組み合わせ公式は、アイデンティティではなくサイズのみに依存するため、依然として機能し、対称性は正確さに影響を与えません。 

最後に、スキューチェーンでは、構造上の理由から、すべての内部頂点は k=2 では異なる動作をしますが、k=3 では同じ動作をします。 分解では、特別なケースを使用せずに両方のケースを処理します。
