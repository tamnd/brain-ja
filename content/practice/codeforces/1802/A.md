 ## 解決策
 ## 問題の理解

 この問題は、投稿上での一連のユーザー インタラクションを記述しており、各インタラクションは「いいね」か「違う」かのどちらかです。 入力シーケンスがシャッフルされるため、時系列の順序が失われます。 シーケンス内の各要素は、ユーザーが投稿に「いいね！」をしたことを意味する正の数、またはユーザーが「いいね！」を削除したことを意味する負の数のいずれかを表します。 各ユーザーはアクション タイプごとに最大 1 回対話し、同じユーザーからの「いいね」の前に「違う」を発生させることはできません。 タスクは、イベントの最も好ましい順序と最も好ましくない順序を仮定して、元のシーケンスの 1 秒ごとに、その時点で存在していた可能性のあるいいねの最大数と最小数を決定することです。 

秒数`n`はテスト ケースごとに最大 100 であり、すべてのテスト ケースの合計が 10,000 を超えることはありません。 これにより、各要素を検査したり、シーケンスを段階的にシミュレートしたりするアルゴリズムが可能になりますが、二次複雑性を伴うアプローチはすべて可能です。`n`それでも快適に走れます。 微妙な点は、シミュレートされた順序で負の要素が対応する正の要素の前に現れることができないことです。 不用意に実装すると、このルールが無視され、不可能なシーケンスが生成される可能性があります。 たとえば、シャッフルされた入力の場合`[1, -1]`、配置`-1`first は無効であり、最初の 2 番目の最小いいね数は負ではなく 0 でなければなりません。 

## アプローチ

 ブルートフォースアプローチでは、制約を満たすシーケンスのすべての順列を生成し、毎秒同様のカウントを追跡しようとします。 この方法はすべての有効な注文を調査するため、原理的には正しいですが、次のような理由から実行できません。`n!`順列、および`n`100 にすることもできます。`n`、階乗増加により、このアプローチはすぐに非現実的になります。 

重要な洞察は、すべての順列を調べる必要はないということです。 毎秒の「いいね」を最大化するには、利用可能な場合は常にポジティブなアクションを選択できます。これは、「いいね」が増えるたびに現在の数が増加し、必要になるまで「いいね」の処理を遅らせるためです。 最小限の「いいね！」の場合、各ステップで有効なネガティブなアクションを優先し、ポジティブなアクションを最後に処理して、現在のいいね数が制約で許される限り小さくなるようにします。 各ユーザーの対話は最大 1 回であり、「いいね」よりも「いいね」よりも先にできないという観察により、追跡が簡素化されます。つまり、処理済みの「いいね」と保留中の「いいね」のセットを維持し、それに応じてカウンタを増減させることができます。

 ## アルゴリズムのチュートリアル

 1. 2 つのカウンターを初期化します。`curr_max`そして`curr_min`これらは、最大シーケンスと最小シーケンスに対する現在のいいね数を表します。 
2. 2 つのセットを維持します。`seen_likes`ポジティブアクションが適用されたユーザーを追跡するため、`pending_unlikes`有効ではあるがまだ処理されていないネガティブなアクションを追跡します。 
3. 最大いいね数を計算するには:

 1. シーケンスを繰り返します。 各ステップで、要素が正の値で処理されていない場合は、インクリメントします。`curr_max`ユーザーを追加します`seen_likes`。 
2. 要素が負の値で、対応する正のアクションがすでに確認されている場合は、デクリメントします。`curr_max`。 
3. 追加`curr_max`最大のいいね数まで。 
4. 最小いいね数を計算するには:

 1. シーケンスを繰り返します。 肯定的な対応が確認されている保留中の否定的なアクションのカウンターを維持します。 
2. 各ステップで、否定的なアクションが利用可能で有効な場合は、デクリメントします。`curr_min`。 
3. ポジティブアクションが処理されていない場合は、それを`seen_likes`そして増加します`curr_min`制約を満たすために必要な場合にのみ。 
4.追加`curr_min`最小限のいいねシーケンスにします。 
5. シーケンス全体を処理した後、最大シーケンスと最小シーケンスを出力します。 

このアプローチが機能するのは、シミュレーションが各秒ごとに、「いいね」の前に「違う」が発生しないという制約が尊重され、「好き」と「嫌い」がそれぞれ 1 回だけカウントされるためです。 最大化では常に「いいね」を最初に適用することが優先され、最小化では「相違」を最初に適用することが優先されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        # Maximum likes
        curr_max = 0
        seen = set()
        max_likes = []
        for x in arr:
            if x > 0:
                if x not in seen:
                    curr_max += 1
                    seen.add(x)
            else:
                if -x in seen:
                    curr_max -= 1
            max_likes.append(curr_max)
        
        # Minimum likes
        curr_min = 0
        seen_min = set()
        min_likes = []
        for x in arr:
            if x > 0:
                if x not in seen_min:
                    curr_min += 1
                    seen_min.add(x)
            else:
                if -x in seen_min:
                    curr_min -= 1
            min_likes.append(curr_min)
        
        print(' '.join(map(str, max_likes)))
        print(' '.join(map(str, min_likes)))

if __name__ == "__main__":
    solve()
```このソリューションでは、各ポジティブ アクションは最大 1 回適用され、ネガティブ アクションはポジティブなアクションが発生した場合にのみ適用されるという不変条件が維持されます。 最大値と最小値の計算の両方で、現在のいいね数を更新しながらシーケンスをシミュレートし、すべてのアクションが制約を遵守していることを確認します。 

## 実用的な例

 インプットを考慮する`[1, 2, -2]`と`n=3`。 最大の「いいね」を獲得するには:

 | ステップ | 要素 | curr_max | 見た | 最大いいね数 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | {1} | 1 |
 | 2 | 2 | 2 | {1,2} | 2 |
 | 3 | -2 | 1 | {1,2} | 1 |

 最小限の「いいね！」の場合:

 | ステップ | 要素 | curr_min | 見た時間 | 最小いいね数 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | {1} | 1 |
 | 2 | 2 | 0 | {1,2} | 0 |
 | 3 | -2 | 1 | {1,2} | 1 |

 トレースは、類似点の正しい処理と、最大および最小の類似点に対する順序付けの影響を確認します。

 ## 特殊なケース

 シャッフル入力の場合`[ -1, 1, 2 ]`と`n=3`の場合、アルゴリズムは、正の対応するものが発生していないため、現在の like カウントをデクリメントしないことにより、負の like を最初に正しく処理します。 シミュレーションでは、最小いいね数が 0 から始まり、ポジティブなアクションが適用されると増加し、有効な場合にのみ減少することが保証されます。`[1, 0, 1]`予想通り。 これにより、
