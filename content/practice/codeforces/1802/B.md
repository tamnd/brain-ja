 ## 解決策
 ## 問題の理解

 私たちは、時間の経過とともに新しいモルモットが到着し、現在所有しているすべての動物の性別が突然明らかにされる「公開」イベントが発生するタイムラインをシミュレートしています。 難しいのは、公開されるまではどのモルモットも完全に曖昧であるため、最悪の場合、2 匹の動物が同じ性別になるか、異なる性別になる可能性があることです。 

各モルモットは、それぞれ最大 2 頭の動物を収容できる鳥小屋に入れなければなりませんが、重要な制限は、同じ鳥小屋に男女混合のペアを入れてはいけないということです。 性別は公開されるまで不明であるため、その瞬間までに作成したグループは、考えられる両方の性別割り当ての下で安全である必要があります。 

手術は数日続きます。 1 の付いた日には、新しいモルモットが現れ、すぐに鳥小屋に割り当てられなければなりません。 2 の付く日には、既存のすべての動物の性別が明らかになります。これにより、突然完全な情報が得られ、次に到着する動物を考慮する前に最適に再編成することができます。 

出力は、性別がどう判明するかに関係なく、また各公開前に動物をどのように割り当てるかに関係なく、常に有効な配置を維持できることを保証する鳥小屋の最小数です。 

制約は大きく、テスト ケースごとに最大 100,000 の操作があり、すべてのテストで合計 100,000 の操作があります。 これにより、考えられるすべての性別の割り当てをシミュレートしたり、動物ごとに複雑な状態を維持したりするアプローチは即座に除外されます。 各イベントを一定時間で処理するソリューションが必要です。 

2 つの操作が存在しない 1 つの操作の長いシーケンスによって、微妙な問題が発生します。 このようなストレッチ期間中、私たちは動物を盲目的に割り当てることを余儀なくされます。 もう 1 つの注意が必要なケースは、大量の挿入の直後に 2 の操作が発生する場合です。その時点で、現在割り当てられていないすべての動物の最悪の場合の構造を再解釈する必要があります。 

単純なアプローチでは、考えられる性別構成を明示的に追跡したり、貪欲にペアを動的に割り当てたりしようとする場合があります。 これは、敵対者（未知の性別割り当て）が事実上、あらゆる時点で最悪の分割を想定することを強制するため、失敗します。 

## アプローチ

 強引な解釈は、各公開後に可能なすべての性別割り当てをシミュレートし、鳥小屋への可能な限り最良のグループ分けを計算することです。 k 匹のモルモットの場合、これはすべての 2^k の割り当てを検討し、実現可能性をチェックすることを意味しますが、これは指数関数的であり、k が 30 程度であってもすぐには実行不可能です。 

重要な観察は、暴露前には情報がないため、すべてのモルモットが見分けがつかない不確実なアイテムとして動作するということです。 最悪の場合の解釈では、暴露が起こったとき、必要な鳥小屋の数を最大化するために性別が敵対的に配置されると想定せざるを得ません。 

公開の直前の任意の時点で、k 匹のモルモットがいるとします。 啓示の後、考えられる最悪の分裂は、一方の性別が ⌈k/2⌉ 回現れ、もう一方の性別が ⌊k/2⌋ 回現れることです。 ただし、より重要な構造上の制約は、各鳥小屋が同性のペアを最大 1 つしか飼育できず、単一の鳥が残った場合は別のケージを強制されることです。 

より深い単純化は、各鳥小屋が空であるか、既知のペアが 1 つ含まれているか、または 1 匹の不確実なモルモットが含まれているかのいずれかであると見なすことで得られます。 暴露が起こるたびに、システムを最適に圧縮できます。k 頭の動物から、私たちができる最善の方法は、それらを ⌊k/2⌋ ペアに詰め込み、場合によっては 1 つの残りのシングルに詰めることです。 残った構造によって、将来の挿入に使用できる「使用可能なスロット」がいくつあるかが決まります。

正しい貪欲な視点は、それぞれの公開後に、最悪の場合の性別分割に合わせて最小限の数の鳥小屋に再編成するというものです。 これにより、クリーンな状態が生成されます。現在「ペアになっていない」モルモットの数を常に維持し、公開されるたびに、できるだけ多くのモルモットを安定したペアに変換できます。 

したがって、解決策は、最後の公開以降に存在する動物の数を追跡し、各公開後にそれらを小さな残りのセットのみが重要となる圧縮形式に変換することになります。 新たに挿入するたびに、既存の鳥小屋の空きスロットが消費されるか、最悪の場合を想定して新しいスロットの作成が強制されます。

 | --- | --- | --- | --- |
 | 性別割り当てに対する暴力 | O(2^n · n) | O(n) | 遅すぎる |
 | 各公開時の貪欲な圧縮 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在「未解決」のモルモットの数、つまり最後の医師の診察以降に追加されたモルモットの数を表す単一の値を維持しながら、操作を左から右に処理します。 

1. カウンタを初期化する`cur = 0`、最後の公開以降のモルモットの数を表し、`ans = 0`、最悪の状態で必要な鳥小屋を表します。 
2. スケジュール内の毎日を繰り返します。 
3. 操作が次の場合`1`、増分`cur`新しいモルモットが追加され、すぐに不安な状況に置かれなければならないからです。 これは、最悪の場合のペアリング圧力が増大する可能性があることを反映しています。 
4. 操作が次の場合`2`、公開イベントを処理します。 この瞬間、すべてが`cur`モルモットは鳥小屋に最適に再配置できます。 
5. 最悪の場合の要件を計算するには、次の点に注意してください。`cur`動物はせいぜい形成できる`cur // 2`安全なペア。シングルが 1 つ残っている可能性があります。 これらの動物に必要な鳥小屋の数は正確に`cur - (cur // 2)`、これを単純化すると、`(cur + 1) // 2`。 
6. この寄付は次のように蓄積されます。`ans`これらの鳥小屋は、現在のセグメントを安全に収容するために存在する必要があるためです。 
7.リセット`cur = 0`、公開後、概念的にすべてを最適に再編成し、新たに開始するためです。 

重要な点は、リビールで区切られた異なるセグメントにまたがる情報を決してマージしないことです。 医師の診察によりすべての不確実性が解決され、完全な再構成が可能になるため、各セグメントは独立して動作します。 

### なぜ効果があるのか

 不変条件は、任意の 2 つのリビール操作の間では、その間隔内のすべてのモルモットは区別できない不確実な要素であり、解決の瞬間にそれらの最悪のグループ分けを考慮するだけでよいということです。 お披露目では、不確実な動物のマルチセット全体を、最悪の場合の性別割り当ての下で必要な最小限の数の鳥小屋に置き換えます。これはまさに、敵対的なペアリングによって引き起こされる避けられない紛争の最大数です。 完全な暴露と再配置の後はすべてのセグメントが独立しているため、セグメントのコストを合計すると、グローバルに有効な最小値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    b = list(map(int, input().split()))
    
    cur = 0
    ans = 0
    
    for x in b:
        if x == 1:
            cur += 1
        else:
            ans += (cur + 1) // 2
            cur = 0
    
    print(ans)
```実装では、アルゴリズムの状態に直接対応する 2 つの変数のみが保持されます。`cur`現在の未解決のブロック サイズを保存し、`ans`医師の診察によって区切られたすべてのブロックにわたって必要な鳥小屋を蓄積します。 

重要な実装の詳細は次の式です。`(cur + 1) // 2`、これは最悪の場合のペアとシングルへのグループ化をコンパクトに表しています。 リセットする`cur`それぞれの後に`2`医師の診察を受けるたびに不確実性が完全に排除され、最適な再編成が可能になり、以前の構造が引き継がれないため、これは不可欠です。 

## 実用的な例

 セグメントがどのように形成され評価されるかを理解するために、2 つの代表的な入力を追跡します。

```| ステップ | 操作 | カー | 答え |

 最初の 3 回の挿入の後、サイズ 3 のブロックが得られます。公開時には、これには次のことが必要です。`(3+1)//2 = 2`最悪の場合は鳥小屋。 リセット後、新しいモルモットは新しいブロックを開始しますが、まだ何も貢献しません。 

これにより、2 つの操作間の連続する各ブロックが独立して処理され、固定コストに寄与することが確認されます。

これは、完全に閉じられたセグメント (2 で終わる) のみが答えに寄与することを示しています。

            else:
                ans += (cur + 1) // 2
                cur = 0
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは、医師の診察の間に挿入がない場合です。 この状況では、セグメント サイズはゼロであり、何も寄与しません。 たとえば、入力`2 2 2`生成する`cur = 0`毎回なので、更新のたびに追加されます`(0 + 1)//2 = 0`、予想どおりゼロの答えが得られます。 

もう 1 つの重要なケースは、長い中断のない挿入シーケンスとそれに続く 1 回の医師の診察です。 入力用`1 1 1 1 1 2`、私たちは蓄積します`cur = 5`、そして発表の際に私たちは計算します`(5 + 1)//2 = 3`。 これは、最終的に同じ性別になった場合にのみ、最大 2 頭の動物が安全に鳥小屋を共有できるという最悪の場合の要件と一致し、基本的に残った 1 頭とのペアリングを強制されます。 

最後に、次のようなパターンを交互に配置します。`1 2 1 2 1 2`長さ 1 の各セグメントが正確に 1 つの鳥小屋に寄与し、リセットによりキャリーオーバーの相互作用が防止されることを確認します。 各セグメントは独立しており、アルゴリズムのリセットにより、古い状態が今後の計算に影響を与えないようにします。
