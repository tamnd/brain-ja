 ## 問題の理解

 入力は、元の単語のシーケンスを取得し、マーカー文字列を挿入することによって形成された単一の文字列です。`"WUB"`非常に具体的な方法で、それらの周囲とそれらの間で。 すべての元の単語には次のものが含まれないことが保証されています。`"WUB"`その内部では、`"WUB"`最後の文字列は、リミックス中に追加された人工的な構造です。 

タスクは、元の単語のシーケンスを復元することです。 概念的には、治療する必要があります`"WUB"`繰り返し、場合によってはブロック内に現れる可能性のある区切り文字として。 これらの区切り文字を削除した後、残りの文字は単一のスペースで区切られ、順番に元の単語を形成する必要があります。 

文字列の長さは最大 200 であるため、大量の前処理や複雑な解析戦略に関する懸念はすぐに排除されます。 O(n²) の解でも安全ですが、構造は線形スキャンで十分であることを示唆しています。 

正確さのためには、いくつかの特殊なケースが重要です。 初め、`"WUB"`連続して出現すると、次のような長い区切り文字が生成されます。`"WUBWUBWUB"`、複数の空の単語ではなく、単一の区切り文字のように動作する必要があります。 例えば、`"WUBWUBABC"`生産すべき`"ABC"`空のトークンは含まれません。 

2番、`"WUB"`文字列の先頭または末尾に出現する場合がありますが、先頭または末尾にスペースを含めることはできません。 例えば、`"WUBABCWUB"`まだ出力する必要があります`"ABC"`余分な空白なし。 

第三に、文字列には単語が 1 つだけ含まれ、何も含まれない場合があります。`"WUB"`この場合、出力は変更されていない元の文字列になります。 

## アプローチ

 素朴なアプローチは、繰り返し検索することです。`"WUB"`そして何も残らなくなるまで文字列から削除します。 それぞれの削除により文字列がシフトされ、O(n) のコストがかかります。最悪の場合、O(n) 回の削除が発生し、O(n²) の動作が発生する可能性があります。 これは n ≤ 200 の場合はまだ許容されますが、不必要に間接的であり、特に再構成された単語の間にスペースが正しく挿入されることを保証する場合、連続する区切り文字のエッジ処理が困難になります。 

より直接的なアプローチは、処理中に文字列を左から右に 1 回スキャンすることです。`"WUB"`単一の区切りパターンとして。 出会うたびに`"WUB"`、完全にスキップします。 一致しないセグメントが見つかると、それを単語の一部として収集します。 重要な観察は次のとおりです`"WUB"`出力に決して表示されるべきではない区切り記号のように動作し、文字を提供することはありません。 これにより、問題は既知の固定長区切り文字を使用したスト​​リームからのトークン抽出に変わります。 

重要な改善点は、中間文字列の構築や入力の繰り返しの変更を避けることです。 代わりに、文字列内でポインタを 1 回だけ移動し、意味のある文字を抽出し、単語間の移行時にのみスペースを挿入します。

 ## アルゴリズムのチュートリアル

 1. インデックスを初期化する`i = 0`そして空のリスト`words`。 このリストには、再構成された単語が順番に保存されます。 
2. その間`i`が文字列の長さより小さい場合は、次で始まる部分文字列が存在するかどうかを確認します。`i`マッチ`"WUB"`。 

一致したら進みます`i`この区切り文字を完全にスキップするには、3 ずつ入力します。 

これが機能する理由は、`"WUB"`は常に構造的な区切り文字であり、実際の単語の一部ではありません。 
3. もし`"WUB"`位置に見つかりません`i`、単語を集め始めます。 

空のバッファを作成して進み続けます`i`現在の位置が開始していない間、`"WUB"`順序。 

各文字をバッファに追加します。 

これにより、実際の文字の連続したシーケンスを最大限に抽出できるようになります。 
4. 1回に1回`"WUB"`が発生するか、文字列が終了する場合は、バッファを単語に変換して追加します。`words`空でない場合。 

これにより、連続する区切り文字によって空の単語が発生するのを防ぎます。 
5. 文字列全体を処理した後、収集されたすべての単語を単一のスペースを使用して結合し、結果を出力します。 

重要なアイデアは次のとおりです`"WUB"`ハード境界として機能します。 スキップするたびに必ず単語の間または境界に到達するため、文字が蓄積されて完全なオリジナルの単語が形成されます。 

### なぜ効果があるのか

 正しさは、いつでも有効な単語の先頭に立つか、有効な単語の先頭に位置するかという不変条件に基づいています。`"WUB"`ブロック。 以来`"WUB"`実際の単語内には決して出現しないため、スキップしても意味のあるデータは削除できません。 の一部ではないすべてのキャラクター`"WUB"`ブロックは元の 1 つの単語に属し、文字は元の曲とまったく同じ語順を維持しながら順番に追加されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

words = []
i = 0

while i < n:
    if i + 3 <= n and s[i:i+3] == "WUB":
        i += 3
        continue

    buf = []
    while i < n and not (i + 3 <= n and s[i:i+3] == "WUB"):
        buf.append(s[i])
        i += 1

    if buf:
        words.append("".join(buf))

print(" ".join(words))
```実装はスキャン戦略に直接に従います。 外側のループにより、文字列が単一パスで処理されることが保証されます。 内側のループは単語を構築します。`"WUB"`境界線が現れる。 

微妙な点は繰り返しチェック`i + 3 <= n`部分文字列比較の前。 これにより、文字列の終端を超えてスライスされることが回避され、境界でのロジックが安全に保たれます。 もう 1 つの重要な詳細は、`buf`追加する前にガードし、空の単語が連続するのを防ぎます。`"WUB"`シーケンス。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列が複数の文字列で始まる場合です。`"WUB"`ブロックなど`"WUBWUBABC"`。 アルゴリズムがスキップを繰り返す`"WUB"`届くまで`'A'`, したがって、最初に空の単語は作成されません。 

もう一つのケースは、`"ABCWUBWUBDEF"`、単語の間に複数の区切り文字が表示されます。 スキャンでは両方が処理されます`"WUB"`空のバッファを生成せずに、オカレンスを区切り文字として使用し、`"ABC DEF"`。 

最後のケースは、`"WUBWUBWUB"`、入力全体が区切り文字で構成されます。 バッファーが満たされることはないため、単語は追加されず、出力は正しく空の文字列になります。
