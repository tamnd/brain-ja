 ## 解決策
 ## 問題の理解

 小文字の上に文字列が与えられます。 すべての文字とすべての部分文字列について、その文字が部分文字列内に何回出現するかを調べ、その値を二乗し、すべてを合計します。 

より正確には、各部分文字列について、「a」から「z」までの各文字を取得し、その部分文字列に出現する回数を数え、その数を二乗し、結果をすべての部分文字列にわたって累積します。 

したがって、このタスクは部分文字列を個別に扱うのではなく、すべての部分文字列範囲にわたる文字出現のグローバルな寄与を扱う必要があります。 

入力サイズは大きく、テスト ケース全体の文字列の合計長は最大数百万に達します。 すべての部分文字列を明示的に検査するソリューションは、O(n^2) 個の部分文字列があり、それぞれの内部の頻度を数えるだけでも、最悪の場合 O(n^3) 個の動作が発生するため、すぐに遅すぎます。 

このため、部分文字列の統計を再計算するのではなく、個々の文字の出現の寄与という観点から問題を再解釈する必要があります。 

弦が均一な場合、微妙なエッジケースが表示されます。 たとえば、`aaaa`、すべての部分文字列は大きな二乗頻度を持ち、単純な部分文字列の列挙はカウントの繰り返しの再計算によりオーバーカウントします。 もう 1 つの特殊なケースは、次のような文字を交互に使用することです。`ababab`ここで、重複は非常に重要であり、慎重に構造化されていない場合、文字ごとの部分文字列の単純なカウントは二重カウントにつながります。 

主な課題は、「頻度の 2 乗の部分文字列の合計」を、各出現または出現のペアが独立して寄与する構造に変換することです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての部分文字列を列挙し、その中の各文字の頻度を計算し、二乗して答えに加算します。 これは定義に直接従うため、正しいです。 ただし、長さ n の文字列の場合、約 n(n+1)/2 の部分文字列があり、単純に実行するとそれぞれのカウント作業が O(n) 必要となり、複雑さは O(n^3) になります。 プレフィックス頻度配列によって部分文字列ごとの計算が 1 文字あたり O(1) に削減されたとしても、最終的には O(26・n^2) になります。これは、テスト ケース全体で n が 10^5 以上に達すると制限をはるかに超えます。 

重要な洞察は、部分文字列の観点から考えるのをやめ、代わりに出現の寄与の観点から考えることです。 固定文字 c の場合、各部分文字列は、含まれる c の数の 2 乗に寄与します。 四角形を拡大すると、単一出現の寄与と出現間のペアごとの相互作用に分かれる構造が明らかになります。 これにより、問題は、特定の位置に 1 つまたは 2 つの出現が含まれる部分文字列の数を数えるという問題に変換されます。 

このシフトが機能するのは、部分文字列制約がインデックスに対する間隔包含制約になり、位置が判明するとイベントごとに O(1) で組み合わせてカウントできるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(26・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字を個別に処理し、結果を合計します。 

固定文字 c の場合、文字列内での出現位置を p1、p2、...、pk とします。 

1. 問題を文字ごとの出現回数に変換します。 異なる文字からの寄与が正方形内で相互作用しないため、1 つの文字を分離します。 
2. この文字については、任意の部分文字列 [l, r] が cnt(c, l, r) の出現を含むものとして解釈されます。 cnt^2 のすべての部分文字列の合計が必要です。 
3. cnt^2 を cnt + 2・C(cnt, 2) に展開します。 これにより、単一の出現と出現のペアが分離されます。 
4. 単一発生の寄与をカウントします。 位置 pi の各出現箇所は、pi 以降で始まり pi 以降で終了するすべての部分文字列に含まれます。 このような部分文字列の数は pi · (n − pi + 1) であるため、各出現箇所は正確にその量に寄与します。 
5. ペアの寄与をカウントします。 i < j の出現ペア (pi, pj) の場合、開始が最大 pi で終了が少なくとも pj であれば、両方とも部分文字列に含まれます。 これにより、開始には pi 個の選択肢が、終了には (n − pj + 1) 個の選択肢が与えられます。 このような各部分文字列は cnt^2 展開に 2 を寄与するため、ペアの合計寄与は 2 · pi · (n − pj + 1) となります。 
6. サフィックスの累積を使用してペアの寄与を効率的に計算します。 すべてのペアを反復する代わりに、(n − pj + 1) の累計を維持しながら、右から左に位置をスキャンします。 各 pi について、将来の用語の接尾辞の合計に 2 · pi を乗算したものを加算します。 
7. すべての文字にわたる両方の部分を合計します。 

### なぜ効果があるのか

 重要な不変条件は、すべての部分文字列がそれに含まれる出現によって一意に説明され、cnt^2 の代数的拡張により、各出現および出現の各順序ペアが最終合計に 1 回だけ寄与することが保証されることです。 有効な部分文字列境界の組み合わせカウントは、インデックスの包含条件と正確に一致するため、過剰カウントまたは過少カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i + 1)

    ans = 0

    for c in range(26):
        p = pos[c]
        k = len(p)
        if k == 0:
            continue

        suf = [0] * (k + 1)

        for i in range(k - 1, -1, -1):
            suf[i] = suf[i + 1] + (n - p[i] + 1)

        for i in range(k):
            pi = p[i]
            ans += pi * (n - pi + 1)
            ans += 2 * pi * suf[i + 1]

    MOD = 998244353
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```最終的な合計では各文字が独立しているため、実装では最初にインデックスを文字ごとにグループ化します。 サフィックス配列`suf[i]`後続のすべての出現の合計寄与度を、その後で終了できる部分文字列の数に関して格納します。 これにより、ペアを列挙する代わりに、ペアの寄与を位置ごとに O(1) で計算できるようになります。 

重要な点はインデックス付けです。位置は 1 から始まるため、次のような部分文字列をカウントする式が可能になります。`pi * (n - pi + 1)`クリーンな状態を維持し、境界での off-by-one エラーを回避します。 

## 実用的な例

 ### 例 1:`ab`キャラクターごとの貢献度を計算します。 

のために`a`位置 1 では、単一寄与は 1 × (2 − 1 + 1) = 2 です。ペアは存在しません。 

のために`b`位置 2 では、単一寄与は 2 × (2 − 2 + 1) = 2 です。ペアは存在しません。 

合計は4です。 

| ステップ | キャラクター | ポジション | 単一合計 | ペアの合計 | 合計 |
 | --- | --- | --- | --- | --- | --- |
 | | | [1] | 2 | 0 | 2 |
 | b | b | [2] | 2 | 0 | 2 |

 これは、出現の包含によってのみ部分文字列がカウントされていることを確認します。 

### 例 2:`aaa`ポジションは[1、2、3]です。 

単一の貢献:

 1 は 1×3 = 3 に寄与します

 2 は 2×2 = 4 に寄与します

 3 は 3×1 = 3 に貢献します

 ペアの貢献:

 (1,2): 2 × 1 × (3 − 2 + 1) = 4

 (1,3): 2 × 1 × (3 − 3 + 1) = 2

 (2,3): 2 × 2 × (3 − 3 + 1) = 4

 合計は20です。 

これは直接列挙と一致し、単一のカウントだけでは表現できない重複効果をペア項がどのように捉えているかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26・n) | 各文字位置は 1 回処理され、サフィックスの合計は文字ごとに線形です。 
| スペース | O(26・n) | 位置リストとサフィックス配列の保存 |

 このソリューションは、各文字が単純な算術演算のみを使用して線形時間で処理されるため、最大 5x10^6 までの合計入力サイズを快適に処理します。

 ## 特殊なケース

 単一文字の文字列が最も単純な境界です。 入力用`a`、唯一の部分文字列は`[1,1]`、周波数の 2 乗は 1 です。アルゴリズムは、寄与 1 × (1 − 1 + 1) = 1 を持つ 1 つの出現を正しく計算し、ペア項が存在しないため、出力は正しいです。 

次のような完全に均一な文字列`aaaaa`ペアカウントを強調します。 各部分文字列は異なる頻度を持ち、単純な実装では重複する寄与を誤ってカウントすることがよくあります。 ここでは、位置のすべてのペアが部分文字列の包含を介して複数回寄与し、サフィックスの累積により、部分文字列の開始と終了の境界制約を通じて各ペアが正確にカウントされることが保証されます。 

どちらも同じ位置寄与式を特殊化したものであり、k に応じてゼロ ペアまたは最大ペアのいずれかを使用するため、アルゴリズムは両方のケースを自然に処理します。
