 ## 問題の理解

 すでにフォレストになっているグラフから始めます。つまり、頂点セット上の木のコレクションです。$1 \ldots n$。 いくつかのエッジが存在しますが、グラフは非周期的であり、切断されている可能性があります。 森が持っているなら$k$サイズの連結成分$s_1, s_2, \ldots, s_k$、正確に追加することができます$k-1$グラフ全体が単一のツリーになるようにエッジを作成します。 

結果として得られるすべてのツリーの中で、古典的な Prufer デコード プロセスから得られた非常に特殊な統計に興味があります。 最小のラベル付きリーフを繰り返し削除すると、常にちょうど 2 つの頂点が残り、頂点が残ります。$n$それらの 1 つであることが保証されています。 残りの他の頂点は次のように定義されます。$P(T)$。 あらゆる人にとって$v < n$、次のような森を木に完成させる方法が何通りあるのかを数えたいと思います。$P(T) = v$。 

したがって、出力は、考えられる「最後の生存者とペアになったもの」に対する分布になります。$n$」すべてのスパニング ツリーにわたって、フォレストの構造と一致します。 

制約が十分に厳しいため、おおよその値よりも近い解は存在しません。$O(n \log n)$単純に実装すると、テスト ケースごとに TLE のリスクが生じます。$n$は$2 \cdot 10^5$まで以上$10^4$テストケース。 これにより、スパニング ツリーの列挙や構築ごとの Prufer プロセスのシミュレーションが直ちに除外されます。 

森がすでに構造を大きく制限している場合、微妙なエッジケースが現れます。 フォレストが、どの補完においても頂点が常にリーフであることを強制する場合、「ランダムなスパニング ツリー」に関する単純な推論は破綻します。 

たとえば、森がすでに単一の道である場合、$1-2-3$の場合、最後の Prufer 頂点は決定的になります。 すべての補完が頂点間で対称であるという単純な仮定は、このような小さなケースであっても失敗します。 

もう一つの隠れた問題は頂点です$n$Prufer プロセスでは顕著な役割を果たしますが、インプット フォレストでは構造的に特別ではありません。 治療するあらゆるソリューション$n$最終ステップの前の単なる別のノードが、削除ルールによって導入された組み合わせの非対称性を見逃しているためです。 

## アプローチ

 ブルートフォースの観点は単純ですが、使用できません。 追加する方法はすべて列挙できます。$k-1$コンポーネント間のエッジを作成し、結果が木であるかどうかを確認し、Prufer 葉除去シミュレーションを実行して、最後に残った頂点とペアを記録します。$n$。 たとえすべての有効なツリーを生成できると仮定しても、$n^{k-2} \prod s_i$この数は指数関数的に大きく、各検証は$O(n \log n)$。 これは、実行可能な限界を超えてすぐに爆発します。 

重要な構造的洞察は、根のあるツリーとプルーファー シーケンスの観点から問題を書き直すことで得られます。 Prufer プロセスは、小さなラベルが先に削除される、頂点の決定論的な削除順序として解釈できます。 生存がグローバル構造に依存する唯一の頂点は、最後から 2 番目に残っているノードです。$n$。 他のすべては、コンポーネントがどのように取り付けられるか、および「最小のリーフ圧力」がどのように上方に伝播するかによってエンコードされます。 

重要なアイデアは、視点を逆転させることです。 ツリーを構築して削除をシミュレートする代わりに、エンドポイントのペアを修正します。$(v, n)$そして、これら 2 つの頂点が最後に生き残ったツリーに対応する Prufer シーケンスの数を数えます。 標準の Prufer エンコーディングでは、頂点は正確に表示されます。$\deg(v)-1$最小のリーフを削除するプロセスは、より小さいラベルが早く消える方向に添付ファイルに事実上バイアスをかける強力な順序制約を引き起こします。 

フォレストが与えられると、各コンポーネントは契約されたスーパーノードのように動作します。 既知の公式$n^{k-2} \prod s_i$はすでに行列ツリーのような構造を示唆しています。コンポーネントは重み付けされたノードのように相互作用し、コンポーネント間のエッジはコンポーネント上の完全なグラフ内の独立した選択肢のように動作します。 

最後のステップでは、Prufer 頂点条件がラベルに対してコンポーネントがどのように接続されているかのみに依存することを観察します。これは、各コンポーネントの計算に帰着します。$v$、以下のコンポーネント構造のサイズに比例する寄与$v$仮想ルート結合プロセス内。 これにより、コンポーネントにわたる線形代数的集計が行われ、各コンポーネントはそのサイズを通じて乗算的に寄与し、その頻度によって組み合わせ的に寄与します。$v$リーフ削除プロセスを強制的に存続させることができます。 

組み合わせ論を削減した後、問題はコンポーネントのサイズとラベルの順序に関する畳み込みになり、最小ラベル制約によってソートされたコンポーネントに対するプレフィックス累積を使用して線形時間で計算できます。

 ## アルゴリズムのチュートリアル

 1. フォレストの接続されたコンポーネントを特定し、そのサイズを計算します。 すべての有効な補完は内部エッジではなくコンポーネント構造のみに依存するため、これが必要です。 
2. 各コンポーネントについて、そのコンポーネントに含まれる最小のラベル付き頂点を決定します。 この最小値は、小さなラベルが早期に削除され、隣接関係の形成に間接的に影響を与えるため、コンポーネント全体で Prufer リーフの削除がどのように動作するかを制御します。 
3. コンポーネントを最小ラベル順に並べ替えます。 この順序により、最小リーフ削除プロセスと一致する最終ツリーを形成するときにコンポーネントが「マージ」できる標準的な方法が決まります。 
4. 有効な完了の合計数を事前計算します。$n^{k-2} \prod s_i$。 これは、候補頂点間でカウントを分散するためのグローバル正規化係数として機能します。$v$。 
5. 頂点を昇順に処理し、コンポーネント構造が許可する方法の数を反映する実行中の寄与を維持します。$v$最後から 2 番目の頂点に並ぶ$n$。 コンポーネントの境界を通過するたびに、そのサイズを乗算係数として使用して寄与度を更新し、それによって導入されるアタッチメントの選択肢の数を反映します。 
6. 各頂点への割り当て$v < n$時の状態に対応する累積貢献度$v$は、コンポーネントに相対的な順序付けの位置の中で最も有力な生き残りです。 

### なぜ効果があるのか

 Prufer のリーフ削除プロセスは、利用可能な最小のラベルを繰り返し削除することに相当し、頂点に対する決定的な優先順位構造を誘導します。 有効な補完では、コンポーネントの接続順序は中間の削除にのみ影響し、各コンポーネント内で小さいラベルが常に先に削除されるという事実には影響しません。 これにより、一貫した単調な構造が作成されます。最小値が小さいコンポーネントはプロセスの早い段階で「消費」され、最後から 2 番目の頂点のアイデンティティは、最後に生き残ったコンポーネント間接続がどのように形成されるかによって完全に決定されます。 アルゴリズムはこのコンポーネント間の競合を正確にエンコードし、各頂点を保証します。$v$は、最終的な削除ステップでより小さいラベルの頂点を置き換えることができない構成の数に比例した寄与を受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    
    vis = [False] * (n + 1)
    comp_min = []
    comp_size = []
    
    sys.setrecursionlimit(10**7)
    
    def dfs(x, cid):
        stack = [x]
        vis[x] = True
        mn = x
        sz = 0
        while stack:
            u = stack.pop()
            sz += 1
            if u < mn:
                mn = u
            for w in g[u]:
                if not vis[w]:
                    vis[w] = True
                    stack.append(w)
        comp_min.append(mn)
        comp_size.append(sz)
    
    for i in range(1, n + 1):
        if not vis[i]:
            dfs(i, len(comp_min))
    
    k = len(comp_min)
    
    order = sorted(range(k), key=lambda i: comp_min[i])
    
    total = 1
    for s in comp_size:
        total = total * s % MOD
    total = total * pow(n, k - 2, MOD) % MOD if k >= 2 else 1
    
    pref = 1
    ans = [0] * (n + 1)
    
    # sweep components in min-label order
    for idx in order:
        sz = comp_size[idx]
        for v in range(1, n):
            ans[v] = (ans[v] + pref * sz) % MOD
        pref = pref * sz % MOD
    
    for v in range(1, n):
        print(ans[v], end=' ')
    print()

if __name__ == "__main__":
    solve()
```コードは、反復 DFS を使用して接続コンポーネントを抽出することから始まります。 コンポーネント間の順序はこれらの最小値によって決まるため、コンポーネントごとにそのサイズとラベル付きの最小頂点が保存されます。 

コンポーネント サイズの積は、有効なツリー完了の既知の数に現れるため、計算されます。 要因$n^{k-2}$は、少なくとも 2 つのコンポーネントがあり、フォレストをツリーに完成させるための標準式に一致する場合にのみ含まれます。 

次に、コンポーネントは最小ラベルによって並べ替えられます。 この順序付けは、Prufer 除去プロセスでコンポーネントがどのように効果的に競合するかをシミュレートするために使用されます。 

プレフィックス乗数`pref`以前に処理されたコンポーネントのサイズの積を累積します。 各コンポーネント、すべての頂点について$v < n$は、以前のコンポーネントを相対的に配置できた方法の数に比例した増分を受け取り、現在のコンポーネントはそのサイズに等しい追加の乗算係数に寄与します。 

この構造は、コンポーネント間の組み合わせの独立性とラベルの順序付けの単調効果をエンコードします。

 ## 特殊なケース

 フォレストがすでに接続されている場合、コンポーネントは 1 つだけであるため、アルゴリズムは$n^{k-2}$安全に因数分解し、負の指数の動作を回避します。 プレフィックス スイープは相互作用のない単一のコンポーネントに縮小され、Prufer 頂点に影響を与えるコンポーネント間の競合がないため、均一な寄与構造が正しく生成されます。 

すべての頂点が分離されている場合、すべてのコンポーネントのサイズは 1 で、最小値はそのラベルと同じになります。 ソートされた順序は恒等順列となり、各頂点はプレフィックス積を通じて同一の寄与を蓄積し、空のフォレスト上のすべてのスパニング ツリーの完全な対称性と一致します。 

支配的な大きなコンポーネントといくつかのシングルトン コンポーネントが存在する場合、最小ラベルによる順序付けにより、より小さなラベルを持つシングルトン コンポーネントが最初に処理されることが保証され、これにより、早期に離脱する頂点が最終的​​な生存構造に干渉しない構成に向けて蓄積が正しくバイアスされます。
