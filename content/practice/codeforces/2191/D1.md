 ## 解決策
 ## 問題の理解

 括弧の文字列が与えられます`s`これはすでに有効な通常の括弧シーケンスです。 タスクは、空ではない最長のサブシーケンスを見つけることです。`t`の`s`これも有効な通常の括弧シーケンスであり、より「優れた」ものです。`s`。 シーケンス`t`よりも優れています`s`それが同じように始まる場合`s`しかし、ある位置で分岐します。`t`もっている`'('`そして`s`もっている`')'`、 または`s`の接頭辞です`t`しかしそれよりも短い`t`。 そのようなサブシーケンスが存在しない場合は、戻り値が返されます。`-1`。 

入力は最大で可能です`10^4`テスト ケース。それぞれの文字列の長さは最大です。`2 * 10^5`。 すべてのテスト ケースにわたるすべての長さの合計は次のように制限されます。`2 * 10^5`。 これは、各文字列を線形時間で処理するアルゴリズムは許容できるが、すべてのサブシーケンスを生成したり、文字に対してネストされた反復を実行しようとするソリューションは、サブシーケンスの数が指数関数的に増加するため、遅すぎることがわかります。 

元のシーケンスが「完全にバランスが取れている」ため、余分なプレフィックスを挿入しても改善できない場合、微妙なエッジ ケースが発生します。`'('`。 たとえば、`s = "()"`または`s = "(())()"`、空でない部分列は次のいずれかに等しい`s`または、短くて良くないので、出力は次のようにする必要があります。`-1`。 単純に括弧を数える不注意なアプローチでは、誤って括弧を削除すると考える可能性があります。`')'`または追加`'('`可能ですが、サブシーケンスは元の順序を尊重する必要があるため、これは不正確です。 

## アプローチ

 ブルートフォースアプローチは、空でないすべてのサブシーケンスを考慮することです。`s`、各サブシーケンスが通常の括弧シーケンスであるかどうかを確認し、辞書順に比較します。`s`。 このアプローチは原理的には正しいですが、すべてのサブシーケンスを生成するには`O(2^n)`まったく不可能な時間です`n`まで`2 * 10^5`。 

重要な観察は、より良いサブシーケンスを構築するには、分岐の最初の位置に次の要素が含まれるようにする必要があるということです。`'('`で`t`そして`')'`で`s`。 したがって、最初または最後から最小限の文字を削除することのみを考慮する必要があります。`s`more で始まる通常の括弧シーケンスを実現するには`'('`分岐位置にあります。 つまり、最適な`t`は常に次の接頭辞を取得することによって取得されます。`'('`s の先頭といくつかの接尾辞`')'`最後からです。 これは、内部で並べ替えを行うとサブシーケンス条件に違反したり、長さを不必要に短縮したりする可能性があるためです。 の数を数える`'('`と`')'`にいる`s`高速な線形時間ソリューションを提供します。 

これにより問題はコンピューティングに限定されます`min(count_open, count_close)`2 を乗算して、最も長い適切なサブシーケンスの長さを取得します。 この長さが等しい場合`n`、 それから`s`それ自体が唯一の最大部分列であり、答えは次のようになります。`-1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定された文字列の場合`s`の合計数を数えます。`'('`文字 (`count_open`） そして`')'`文字 (`count_close`）。 このステップには、次の長さの線形時間がかかります。`s`。 
2. より良いサブシーケンスの最大長は、最小長の 2 倍です。`count_open`そして`count_close`。 これは、同じ数が必要であるためです。`'('`そして`')'`通常の括弧シーケンスを維持するには、サブシーケンスは次の値よりも短くなければなりません。`s`より良いと考えられるようになります。 
3. この計算された長さが、`s`の場合、これより良いサブシーケンスは存在しません。 出力`-1`この場合。 それ以外の場合は、計算された長さを出力します。 

機能する理由: すべての通常の括弧のサブシーケンスは、一連の開始括弧とそれに続く同数の閉じ括弧によって表現できます。場合によっては、有効性を維持する方法でインターリーブすることもできます。 最初に生じる可能性のある相違点`t`より良い`s`を置き換える位置にある必要があります`')'`で`s`と`'('`で`t`。 数を数えてみると、`'('`そして`')'`、早期に分岐し、「より良い」条件を満たす最長の有効なブラケット サブシーケンスを形成できることを確認します。 このアルゴリズムは、サブシーケンスが規則的であり、より優れているという不変条件を保持します。`s`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        count_open = s.count('(')
        count_close = s.count(')')
        max_len = min(count_open, count_close) * 2
        if max_len == n:
            print(-1)
        else:
            print(max_len)

if __name__ == "__main__":
    solve()
```このソリューションは、まずテスト ケースの数を読み取ります。 テスト ケースごとに、次の数をカウントします。`'('`そして`')'`文字列の中で。 小さい方のカウントを 2 で乗算すると、可能な限り長い、より適切なサブシーケンスの長さが得られます。 小切手`max_len == n`私たちが戻らないことを保証します`s`それ自体は良くありません。

 ## 特殊なケース

 長さ 2 の文字列の場合、`s = "()"`、数えると得られる`count_open = count_close = 1`。 計算された`max_len`は`2`に等しい`n`したがって、出力は次のようになります`-1`これは、より適切なサブシーケンスが存在しないことを正しく示しています。 

次のような完全にネストされた長いシーケンスの場合`s = "((()))"`、`count_open = 3`、`count_close = 3`、`max_len = 6 = n`したがって、出力は`-1`。 

のために`s = "(((())))"`、`count_open = 4`、`count_close = 4`、`max_len = 8`。 1 対の括弧を削除すると、次のようになります。`((()))`、長さ 6 よりも優れています。`s`したがって、出力は次のようになります`6`。 アルゴリズムは比較することでこれを正確に識別します。`max_len`に`n`そして、削除可能なペアを暗黙的に減算します。
