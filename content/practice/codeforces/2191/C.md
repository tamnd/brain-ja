 ## 解決策
 ## 問題の理解

 重み付けされた無向グラフが与えられます。 正確に選択しなければなりません$n-1$エッジ。 

もしそれらが$n-1$エッジはスパニング ツリーを形成するため、選択は禁止されています。 すべての選択肢の中で可能な限り総重量を最小限に抑えたいと考えています。$n-1$**ツリーを形成しない**エッジ。 

A graph on$n$頂点が正確に一致する$n-1$エッジは、接続されている場合にのみツリーになります。 この観察により、問題はすぐに単純化されます。つまり、次の最小重みセットを探しています。$n-1$誘導されたグラフが切断されているエッジ。 

グラフのサイズが大きいです。 すべてのテスト ケースで、頂点の総数とエッジの総数は両方とも最大で$2 \cdot 10^5$。 サブセット、スパニング ツリー、さらにはエッジ セットのすべてのペアを列挙するアルゴリズムは完全に不可能です。 に近いものが必要です$O(m \log m)$テストファイルごとに。 

世界的に最も軽い場合、微妙なエッジケースが現れます。$n-1$エッジはすでに切断されています。 例えば：```
n = 4
edges: 1, 2, 3, 100
```最も明るい 3 つのエッジを選択すると、すでに切り離されたグラフが得られるため、答えは単純です。$1+2+3=6$。 MST の構築から開始して変更を強制するソリューションでは、このケースは見逃されます。 

もう 1 つの重要なケースは、最も軽い場合です。$n-1$エッジがツリーを形成します。 したがって、任意の木の辺を置き換えても必ずしも答えが得られるわけではありません。 置換ではグラフを切断する必要があります。 たとえば、余分なエッジがサイクルを作成する場合、そのサイクルからエッジを削除するとグラフの接続が維持され、ツリーが得られますが、これは禁止されています。 

最後のコーナーケースが発生するのは、$m=n-1$。 グラフには、正確に 1 つのセットが含まれています。$n-1$エッジ。 そのセットがツリーの場合、有効な答えは存在しないため、出力する必要があります。$-1$。 

## アプローチ

 ブルートフォースソリューションでは、次のすべてのサブセットを検査します。$n-1$エッジを作成し、それがツリーを形成しているかどうかを確認し、無効なエッジの中で最小の重みを維持します。 がある$$\binom{m}{n-1}$$このようなサブセットは、エッジが数十個あるグラフであっても天文学的に大きくなります。 

重要な観察は、すべてのエッジを重みでソートすることから得られます。 

させて$r=n-1$。 最初のものを考えてみましょう$r$edges in nondecreasing weight order. このセットを呼び出します$P$。 

すべてのセット$r$エッジには少なくとも次の重量があります$P$、 なぜなら$P$世界最軽量のものが含まれています$r$エッジ。 

もし$P$がすでに切断されている場合は、すぐに最適化されて完了です。 

興味深いケースは次のような場合です。$P$木を形成します。 

エッジを追加するとします$e$外$P$。 以来$P$は木です、追加します$e$正確に 1 つのサイクルを作成します。 そのサイクルからエッジを削除しても、グラフは接続されたままになり、ツリーが残ります。 それは役に立ちません。 

切り離されたグラフを取得するには、によって作成されたサイクル上に**ない**エッジを削除する必要があります。$e$。 

固定外側エッジの場合$e$、1 回のスワップで取得できる最も安価な切断セットは、最も重いエッジを削除することによって達成されます。$P$のエンドポイント間のパス上にないもの$e$。 

驚くべき事実は、あらゆる最適な答えがそのような 1 つのスワップで表現できるということです。 以下とは異なるソリューション$P$数回の追加と削除により、少なくとも有効な単一スワップと同程度の重量増加があります。 

これにより、問題全体が、プレフィックスの外側のすべてのエッジについて、対応するツリー パス上にないプレフィックス ツリーの最大重みエッジを見つけることになります。 

それはツリーデータ構造の問題になります。

 ## アルゴリズムのチュートリアル

 ### 重要なプレフィックスの構築

 1. すべてのエッジを重みで並べ替えます。 
2. しましょう$r=n-1$。 最初を取る$r$エッジを作成し、このセットを呼び出します$P$。 
3. それらの重みの合計を計算します。$S$。 
4. DSU を端に使用します。$P$。 
5. もし$P$切断、出力$S$。 他のセットはありません$r$エッジの重みを小さくすることができます。 
6. もし$m=r$、 それから$P$可能な唯一のセットは$r$エッジ。 木なので有効な答えが存在しないので出力$-1$。 

### プレフィックスがツリーの場合

 1. 治療する$P$木として。 
2. ツリーをルート化し、バイナリリフティングテーブルを構築します。 
3. すべての祖先ジャンプに対して、2 つの値を保存します。 

- そのジャンプの最大エッジウェイト、
 - そのジャンプの 2 番目の最大エッジウェイト。 
4. あらゆるエッジに$e=(u,v,w)$外$P$、からのパスをクエリします$u$に$v$木の中に。 
5. しましょう$M$はツリー全体の最大エッジ重みになります。 
6. しましょう$P_{\max}(u,v)$間のツリー パス上の最大エッジ ウェイトになります。$u$そして$v$。 
7. そのパス上に**ない**最も重い木の端が必要です。 
8. もし$M$がパスに含まれていない場合、答えは単純です。$M$。 
9. もし$M$パス上にある場合は、パスの外側にある最大の木の端が必要です。 これは次の大きい方に等しい:

 - 最大値が一意である場合のツリー全体で 2 番目に大きいエッジの重み、
 - パスの外側の他の場所に出現する場合も同じ最大値。 
10. 保存された最大値と 2 番目の最大値の情報を使用して、最適な取り外し可能なエッジの重みを計算します。$h$。 
11. この外側エッジのコスト増加は、$$w-h.$$1. すべての外側エッジにわたって有効な最小増加量を取得します。 
2. 答えは次のとおりです。$$S + \min(w-h).$$### なぜ効果があるのか

 最初の$n-1$エッジは、そのサイズの最小重みセットです。 他のセットでは、それらの一部をより重いエッジに置き換える必要があります。 

プレフィックスが切断されている場合、それはすでに有効な解決策であり、改善することはできません。 

プレフィックスがツリーの場合、非プレフィックス エッジを 1 つ追加すると、一意のサイクルが作成されます。 そのサイクルの外側のエッジを削除すると、グラフが切断され、有効なセットが得られます。$n-1$エッジ。 

固定追加エッジの場合、許容可能な最も重いツリー エッジを削除すると、可能な限り最小限の増加が得られます。 

いくつかのスワップによってプレフィックスと異なる有効なソリューションには、追加エッジ パスでカバーされない、削除されたツリー エッジが少なくとも 1 つ含まれている必要があります。 削除されたエッジと追加されたエッジの 1 つを比較すると、最良の有効な単一スワップと同等以上のコスト増加が生じます。 したがって、最適なソリューションは常に 1 回のスワップによって達成され、最小限のスワップを実現します。$w-h$外側の端全体に塗るだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 19

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def merge_pair(a, b):
    vals = [a[0], a[1], b[0], b[1]]
    vals.sort(reverse=True)
    return (vals[0], vals[1])

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        edges = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            edges.append((w, u - 1, v - 1))

        edges.sort()

        r = n - 1
        prefix = edges[:r]
        extra = edges[r:]

        prefix_sum = sum(w for w, _, _ in prefix)

        dsu = DSU(n)
        for w, u, v in prefix:
            dsu.union(u, v)

        root = dsu.find(0)
        connected = all(dsu.find(i) == root for i in range(n))

        if not connected:
            out.append(str(prefix_sum))
            continue

        if m == r:
            out.append("-1")
            continue

        tree = [[] for _ in range(n)]
        all_tree_weights = []

        for w, u, v in prefix:
            tree[u].append((v, w))
            tree[v].append((u, w))
            all_tree_weights.append(w)

        max1 = max(all_tree_weights)
        cnt_max1 = all_tree_weights.count(max1)

        if cnt_max1 >= 2:
            max2 = max1
        else:
            max2 = max((x for x in all_tree_weights if x != max1), default=-1)

        depth = [0] * n
        up = [[0] * n for _ in range(LOG)]
        best = [[(-1, -1)] * n for _ in range(LOG)]

        stack = [(0, -1, -1)]
        order = [0]

        parent = [-1] * n
        parent[0] = 0

        while stack:
            v, p, w = stack.pop()

            up[0][v] = p if p != -1 else 0
            best[0][v] = (w, -1)

            for to, wt in tree[v]:
                if to == p:
                    continue
                depth[to] = depth[v] + 1
                parent[to] = v
                stack.append((to, v, wt))

        for k in range(1, LOG):
            uk = up[k - 1]
            uk2 = up[k]
            bk = best[k]
            bk1 = best[k - 1]

            for v in range(n):
                mid = uk[v]
                uk2[v] = uk[mid]
                bk[v] = merge_pair(bk1[v], bk1[mid])

        def path_two_max(a, b):
            res = (-1, -1)

            if depth[a] < depth[b]:
                a, b = b, a

            diff = depth[a] - depth[b]
            bit = 0
            while diff:
                if diff & 1:
                    res = merge_pair(res, best[bit][a])
                    a = up[bit][a]
                diff >>= 1
                bit += 1

            if a == b:
                return res

            for k in range(LOG - 1, -1, -1):
                if up[k][a] != up[k][b]:
                    res = merge_pair(res, best[k][a])
                    res = merge_pair(res, best[k][b])
                    a = up[k][a]
                    b = up[k][b]

            res = merge_pair(res, best[0][a])
            res = merge_pair(res, best[0][b])

            return res

        INF = 10**30
        add = INF

        for w, u, v in extra:
            path_max, path_second = path_two_max(u, v)

            if max1 > path_max:
                removable = max1
            else:
                removable = max(max2, path_second)

            if removable != -1:
                add = min(add, w - removable)

        if add == INF:
            out.append("-1")
        else:
            out.append(str(prefix_sum + add))

    sys.stdout.write("\n".join(out))

solve()
```ソート後、アルゴリズムはまず全体的に最も軽いかどうかをチェックします。$n-1$エッジはすでに切断されています。 そのケースは他にないため、すぐに処理されます$n-1$-edge set can have a smaller sum.

 プレフィックスがツリーを形成すると、残りの作業はそのツリー上で行われます。 バイナリ リフティングを使用すると、任意のツリー パス上の最大および 2 番目に大きいエッジの重みをクエリできます。$O(\log n)$。 これらの値は、パス上にない最も重いエッジ、つまり削除したいエッジを決定するのに十分です。 

この実装では、リフティング セグメントごとに 2 つの最大の重みが保存されます。 2 つのセグメントの結合は、4 つの候補のうち最大の 2 つの値を取ることによって行われます。 これにより、より複雑なデータ構造を回避しながら、パス クエリの効率が維持されます。 

すべての重み計算では Python 整数が使用され、最大の値を安全に処理できます。$10^9$おおよそ合計すると$2 \cdot 10^{14}$。
