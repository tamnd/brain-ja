 ## 解決策
 ## 問題の理解

 2 つの条件が同時に成立するように、2 つの色を使用して、一列に配置された一連の個別の整数に色を付けるように求められます。 まず、元のシーケンス内で隣接する 2 つの数字は異なる色でなければなりません。 次に、数値を昇順に並べ替える場合、新しいシーケンスでは、隣接する数値も異なる色で表示される必要があります。 入力では複数のテスト ケースが提供され、それぞれがカードの数とその整数値を提供します。 各テスト ケースの出力は、有効な色分けが存在する場合は単純に「YES」、そうでない場合は「NO」になります。 

制約は小さく、テスト ケース内のカードの数は最大 100 枚、テスト ケースの数は最大 200 です。 これは、O(n²) ソリューションでも通常は十分に高速に実行できることを意味しますが、すべてのカラーリングを強引にチェックするのではなく、洞察力によって問題を解決できるため、線形または線形演算のアプローチを目指す必要があります。 

微妙な点は、元の配列または並べ替えられた配列の色を個別に交互に変えることはできないということです。 順番を考えてみる`[2, 3, 1]`。 オリジナルの色を交互にすると、`[red, blue, red]`、しかし並べ替えた後`[1, 2, 3]`カラーリングはこうなります`[red, red, blue]`、失敗します。 エッジ ケースは、最小または最大の要素が、ソートされたシーケンス内で繰り返し色を強制する位置に出現する場合に発生します。 これは、元の配列の隣接関係が、ソートされた配列の隣接関係に自明にマッピングされないことを示しています。 

## アプローチ

 ブルートフォース手法では、配列の 2ⁿ 可能な色付けをすべて試して、2 つの条件をチェックします。 これはあらゆる可能性を検討するので正しいですが、2¹⁰⁰ が天文学的に大きいため、n = 100 の場合は明らかに非現実的です。 n が小さい場合でも、問題には隠れた構造があるため不要です。 

重要な観察は、シーケンスがソートされた順序と元の順序に従って「ジグザグに色分けされている」場合、両方の条件を同時に満たすことができるということです。 ソートされたシーケンス内の位置にラベルを付けると、これらの位置を交互に色付けすることで、ソートされた隣接関係が確実に満たされるようになります。 実際には、ソートされた順序でインデックスに基づいて色を割り当てることができます。奇数のインデックスには 1 つの色が割り当てられ、偶数のインデックスにはもう 1 つの色が割り当てられます。 ソートされた順序で色を割り当てた後、元の位置にマップし直します。 その後、元の配列内の隣接する要素の色が異なることを確認するだけで済みます。 存在する場合、有効なカラーリングが存在します。 それ以外の場合は、そうではありません。 これが機能するのは、ソート順に交互にソートすることでソート状態が保証され、n のサイズが小さいため、元の配列の隣接性を効率的にチェックできるためです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、n と配列 a を読み取ります。 各配列を個別に処理する必要があります。 
2. 各要素とその元のインデックスを含むタプルのリストを作成します。 これにより、元の位置を記憶しながら配列を並べ替えることができます。 
3. 配列を値でソートします。 並べ替えた後、並べ替えた配列に沿って交互に色を割り当てます。 たとえば、インデックス 0 (最小値) はカラー 0 を取得し、インデックス 1 はカラー 1 を取得します。 色の割り当てを、元のインデックスにマップされた別の配列に保存します。 
4. 元の配列を反復処理します。 隣接する要素のペアごとに、割り当てられた色が異なるかどうかを確認します。 いずれかのペアが同じ色の場合、このテスト ケースの答えは「いいえ」になります。 
5. 隣接するすべてのペアが異なる色を持っている場合、答えは「YES」です。 結果を出力し、次のテスト ケースに進みます。 

機能する理由: ソートされた順序で色を交互にすることにより、ソートされた隣接性が満たされることが保証されます。 色を元の位置にマッピングし直すことで、元の隣接関係が維持されているかどうかを確認できます。 このアルゴリズムは、2 色の場合、ソート順に沿って交互に代入することで競合が最小限に抑えられ、配列サイズが小さいため競合を簡単に検出できるという事実を利用しています。 競合が存在する場合、他のカラーリングは両方の条件を同時に満たすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        indexed_a = list(enumerate(a))
        indexed_a.sort(key=lambda x: x[1])
        
        color = [0] * n
        for i, (idx, _) in enumerate(indexed_a):
            color[idx] = i % 2  # alternate colors in sorted order
        
        ok = True
        for i in range(n - 1):
            if color[i] == color[i + 1]:
                ok = False
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードは最初に要素を列挙して元の位置を保持し、値で並べ替えます。 次に、並べ替えられた順序に沿って交互に色を割り当て、元の位置にマップし直します。 最後に、元の配列の隣接性をチェックし、結果を出力します。 モジュロを使用すると、色が正しく交互に配置され、チェック ループによって無効な隣接関係が効率的に検出されます。 

## 実用的な例

 **例 1:**`[2, 3, 4, 1]`| 元のインデックス | 値 | ソートされたインデックス | 割り当てられた色 | 元の順序での最終色 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 1 | 1 | 1 |
 | 1 | 3 | 2 | 0 | 0 |
 | 2 | 4 | 3 | 1 | 1 |
 | 3 | 1 | 0 | 0 | 0 |

 元の順序で隣接性を確認します: 1 vs 0、0 vs 1、1 vs 0 → すべて異なります。 はいを出力します。 

**例 2:**`[2, 3, 1]`| 元のインデックス | 値 | ソートされたインデックス | 割り当てられた色 | 元の順序での最終色 |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 1 | 1 | 1 |
 | 1 | 3 | 2 | 0 | 0 |
 | 2 | 1 | 0 | 0 | 0 |

 隣接性の確認: 1 vs 0、0 vs 0 → 競合。 出力NO.

 これらのトレースは、元の配列に隣接関係の競合が発生したとき、アルゴリズムが正しく検出していることを示しています。

 ## 特殊なケース

 のために`[2,3,1]`、ソートされたシーケンス`[1,2,3]`元の順序で色を任意に変更しようとすると競合します。 アルゴリズムは、並べ替えられた位置に基づいて色を割り当てます。`[0,1,2] → colors 0,1,0]`。 元のインデックスにマッピングし直すと、次のようになります。`[1,0,0]`。 元の隣接関係を確認すると、位置 1 と位置 2 の両方が色 0 であり、競合が発生しています。 出力は NO であり、アルゴリズムがこのエッジ ケースを正しく処理していることを確認します。 同様に、サイズ 2 の配列は常に解決可能です。これは、2 つの要素を常に異なる色にでき、並べ替え順序によってこの交互が維持されるためです。
