 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、それを任意に並べ替えることができます。 順序を修正した後、プレフィックスとサフィックスの間で考えられるすべての分割位置を調べます。 分割ごとに、プレフィックスの MEX とサフィックスの MEX を計算します。これらのペアはすべて異なるものにする必要があります。 

重要な要件はグローバルです。単一の順列は、両側に同じ欠落した最小の非負整数がある場合の分割を回避する必要があります。 1 つの分割を選択するわけではありませんが、どの分割でも MEX 値が等しくなることがないようにする必要があります。 

制約は小さく、テスト ケースあたり最大 100 個の要素と 500 個のテスト ケースです。 これは、どのソリューションでもテスト ケースごとに線形または二次推論が可能であるが、順列に対する階乗または指数関数は不要であり、避けるべきであることを直ちに示唆しています。 n が小さい場合でも、n! であるため順列は依然として実行不可能です。 n = 100 でも成長が速すぎます。 

素朴だが自然な試みは、MEX が 0 から始まる小さな整数の存在に大きく依存していると考えることです。これは、相対的な順序ではなく、低い値の分布のみが重要であることをすでに示唆しています。 

配列に明確な小さな数値がほとんどない場合、微妙なエッジ ケースが発生します。 たとえば、すべての要素がゼロの場合、すべてのプレフィックスとサフィックスは MEX = 1 になるため、すべての分割は失敗します。 同様に、0 が完全に欠落している場合は、すべてのセグメントが MEX = 0 になり、再びすべての分割が失敗します。 これらの縮退したケースは、0 と 1 の頻度の全体的な構造が答えを支配していることを示しています。 

## アプローチ

 強引なアイデアは、配列のすべての順列を試し、分割ごとにプレフィックス MEX とサフィックス MEX を計算することです。 これは条件に直接一致するため、正しいです。 ただし、順列の生成は n の階乗であり、すべてのセグメントの MEX を再計算するため、1 つの順列をチェックするだけでも O(n^2) かかります。 これはまったく実現不可能です。 

重要な観察は、数値がセグメント内に完全に存在するしきい値を超えた場合にのみ MEX が変化するということです。 MEX が x を超えて増加するには、0 から x までのすべての数字がそのセグメントに出現する必要があります。 これは、プレフィックスとサフィックスの MEX 値は、実現可能性を超えた正確な順序ではなく、分割全体で 0、1、2 などがどのように分散されるかのみに依存することを意味します。 

決定的な単純化は、0 が最も影響力のある値であるため、0 が出現する回数を追跡することです。 少なくとも 1 つの 0 がある場合、出現を区切ってプレフィックス MEX の動作を制御できます。 0 がない場合、どの分割でもプレフィックスとサフィックスの両方が常に MEX = 0 になるため、条件が満たされることはありません。 

少なくとも 2 つのゼロがあれば、いつでも有効な配置を構築できます。 プレフィックスに 0 が含まれる場合と含まれない場合があるように、いくつかのゼロを先に配置し、いくつかを後に配置して、すべての分割にわたって異なる MEX 値を作成することができます。 MEX は最初に 0 が存在するかどうかに依存するため、残りの構造 (ゼロ以外の数値) ではこの可能性を破壊できません。 

ゼロが 1 つだけあると、状況は厳しくなります。 分割によって同一の MEX 値が生成されないことを確認する必要があります。 これは一部の構成では不可能であることが判明しますが、影響領域を分離するのに十分なゼロ以外の値がある場合には可能です。 決定的な特徴付けは、0 と 1 の出現を数えることに帰着します。少なくとも 2 つの 0 がある場合、または少なくとも 1 つの 0 と少なくとも 1 つの 1 がある場合、有効な順序を構築できます。 そうでないとできません。 

これにより、問題は順列から単純な周波数推論に軽減されます。

 ## アルゴリズムのチュートリアル

1. 0 と 1 の数に注目して、各値が何回出現するかを数えます。 MEX は常に 0 から始まり、小さな整数が存在するかどうかに依存するため、これら 2 つの値は MEX の動作を支配します。 
2. 配列にゼロがない場合は、すぐに答えが「いいえ」であると結論付けます。 これは、すべてのサブ配列が MEX = 0 であるため、すべてのプレフィックスとサフィックスのペアがすべての分割で等しくなるためです。 
3. ゼロが 1 つだけある場合は、プレフィックスとサフィックスの動作を分離できるゼロ以外の要素が少なくとも 1 つあるかどうかを確認します。 実際には、これは、少なくとも 1 つの 1 が存在するかどうかをチェックすることになります。 そうでない場合、分割では両側の MEX 値が強制的に同じになるように単一のゼロが分離されます。 
4. ゼロが 2 つ以上ある場合は、「YES」を出力します。 一部の分割ではプレフィックスにゼロが含まれ、他の分割では含まれないように常に配列を配置することができ、すべてのパーティションで異なる MEX 値が保証されます。 

機能する理由: セグメントの MEX は、最初に 0 が存在するかどうかによって決定され、次に 0 が完全にカバーされている場合に 1 が存在するかどうかによって決定されます。 分割の両側がすべての順列に対して等しい MEX を持つことができる唯一の方法は、0 の構造が制約されすぎて、それらの影響を分離できない場合です。 0 (複数のゼロまたはそれを補う 1) の分布に十分な柔軟性があれば、カットごとにプレフィックスとサフィックスの境界によって MEX の等価性が破られる順序を常に構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    z = a.count(0)
    o = a.count(1)
    
    if z == 0:
        print("NO")
    elif z == 1 and o == 0:
        print("NO")
    else:
        print("YES")
```この実装は、0 と 1 の出現数のカウントに完全に依存しています。完全に縮退した MEX 定数状況に陥っていないことを保証する以上に、残りの値が有効な配置の存在に影響を及ぼさないため、これで十分です。 

重要な点は、順列を明示的に構築しようとしないことです。 この問題は、有効な順序付けが存在するかどうかを問うだけであり、構造条件は単純な周波数チェックに帰着します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        z = a.count(0)
        o = a.count(1)
        if z == 0:
            out.append("NO")
        elif z == 1 and o == 0:
            out.append("NO")
        else:
            out.append("YES")
    return "\n".join(out)

# provided samples
assert run("""3
2
1 0
3
0 3 0
6
1 0 5 0 6 1
""") == """YES
YES
YES"""

# custom cases
assert run("""3
2
0 2
3
2 3 4
4
0 0 0 0
""") == """NO
NO
YES"""
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | [1,0] | はい | 0 と 1 の最小の有効なケース |
 | [2,3,4] | いいえ | 0 がない場合、定数 MEX | が強制されます。 
| [0,0,0,0] | はい | 複数のゼロを使用すると構築が可能になります。 

## 特殊なケース

 配列にゼロがない場合、順序に関係なく、すべてのセグメントは MEX = 0 になります。 たとえば、入力`[2,3,5]`は、分割ごとに常にプレフィックス MEX 0 とサフィックス MEX 0 を生成するため、答えは NO でなければなりません。 

ゼロが 1 つだけあり、1 が存在しない場合、次のようになります。`[0,2,3]`、単一のゼロを使用して、プレフィックスとサフィックス MEX がすべてのパーティションにわたって一貫して異なる分割を作成することはできず、強制的に失敗します。 

次のようにゼロが複数ある場合`[0,0,1,2]`、常にゼロを配置して、すべての分割で少なくとも 1 つの辺が 0 を含むかどうかで異なり、すべての分割で MEX 値が等しくなるのを防ぐことができます。
