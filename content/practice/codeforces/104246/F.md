 ## 解決策
 ## 問題の理解

 コーダーのコレクションが与えられ、それぞれが何らかの初期報酬値から始まります。 時間の経過とともに、一連の更新が到着し、各更新は 1 人のコーダーのみをターゲットにし、そのコーダーの報酬を正または負の整数だけ増加させます。 

更新のたびに、その時点ですべてのプログラマーの間で個別の報酬値がいくつ存在するかを報告するよう求められます。 言い換えれば、最初の k 回の更新を処理した後、概念的にはサイズ n の更新された配列が得られ、その中にある一意の値の数が必要になります。 

入力構造は複数の独立したテスト ケースです。 各テスト ケースは初期配列を与え、次にポイント変更のストリームを与え、更新ステップごとに 1 つの答えを出力する必要があります。 

n と m は両方ともテスト ケースごとに 100,000 まで大きくなり、すべてのテスト ケースの合計は最大 200,000 になるため、制約が重要になります。これにより、各更新後に個別の値の数を最初から再計算するアプローチは即座に除外されます。これは、クエリごとに O(n) のコストがかかり、最悪の場合、およそ 10^10 の操作が発生するためです。 

微妙な問題は、更新後に値が頻繁に繰り返される可能性があることです。 素朴な直感では、値の頻度マップを維持しようとするかもしれませんが、値を共有する要素の数を追跡せずにやみくもに頻度を更新すると、不正確な個別のカウントにつながります。 

別のエッジ ケースは、異なる更新パスの後に複数のコーダーが同じ値に収束する場合に発生します。 たとえば、[1, 2] から始めて、インデックス 1 に +1 を追加し、インデックス 2 に -1 を追加すると、[2, 1] が得られます。これは、個々の値が同一性を変更したとしても、依然として 2 つの異なる値を持ちます。 どのソリューションでも、インデックスごとの履歴だけでなく、グローバルな値の多重度を追跡する必要があります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、更新のたびに個別の値の数が再計算されます。 k 番目の操作を適用した後、配列全体をスキャンし、すべての値をセットに挿入して一意の値をカウントします。 セットでは値の重複が自然に排除されるため、これは正しいです。 

ただし、各スキャンのコストは O(n) で、それを m 回実行するため、テスト ケースごとの複雑さは O(nm) になります。 n と m が最大 100,000 であるため、これは実現可能な限界をはるかに超えています。 

重要な点は、操作ごとに 1 つの要素だけが変更されるということです。 これは、配列全体を再計算する必要がないことを意味します。 単一の古い値と単一の新しい値の寄与を調整するだけで済みます。 

すべてのコーダーにわたって値の周波数マップを維持する場合、各更新は 2 つの周波数にのみ影響します。更新されたコーダーの古い値は 1 回減少し、新しい値は 1 回増加します。 個別の値の数は、正のカウントを持つこの頻度マップ内のキーの数と正確に一致します。 

したがって、セットを再構築する代わりに、カウントを増分的に維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 周波数マップのメンテナンス | O((n + m) log n) または O(n + m) 平均 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各コーダーの現在の値を格納する配列と、各値がグローバルに出現する回数を格納するハッシュマップの 2 つの構造を維持します。 

### ステップ

 1. 配列を初期化する`a`すべてのプログラマーの初期報酬付き。 
2. 周波数マップを構築する`freq`どこ`freq[x]`現在値を持っているコーダーの数です`x`。 
3. 個別の値の初期数をキーの数として計算します。`freq`ゼロ以外の周波数を持つ。 
4. アップデートごとに`(p, r)`、現在の値を確認します`old = a[p]`。 
5. 減少`freq[old]`コーダーだから一人ずつ`p`この値はなくなります。 
6. もし`freq[old]`ゼロになると、マップから削除するか、存在しないものとして扱います。これは、個別の値に寄与しなくなるためです。 
7. 新しい値を計算します`new = old + r`それをコーダーに割り当てます`p`。 
8.増加`freq[new]`必要に応じてエントリを作成します。 
9. 各更新後に、現在のキーの数を出力します。`freq`。 

各ステップは、操作ごとに 1 つの要素のみが変更されるという事実によって駆動されるため、グローバル構造の更新は 2 つのカウンター調整に減ります。 

### なぜ効果があるのか

 重要な不変条件は、各更新を処理した後、周波数マップがすべてのコーダーにわたる現在の報酬値のマルチセットを正確に表すことです。 個別の値はゼロより大きい頻度の値に正確に対応するため、マップ内のアクティブなキーを数えることで正しい答えが得られます。 すべての更新では 1 つの配列位置のみが変更されるため、2 つのカウントを調整すると、完全な再計算を必要とせずにこの不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        distinct = 0

        for x in a:
            if x not in freq:
                freq[x] = 0
            if freq[x] == 0:
                distinct += 1
            freq[x] += 1

        for _ in range(m):
            p, r = map(int, input().split())
            p -= 1

            old = a[p]

            freq[old] -= 1
            if freq[old] == 0:
                distinct -= 1

            new = old + r
            a[p] = new

            if new not in freq:
                freq[new] = 0
            if freq[new] == 0:
                distinct += 1
            freq[new] += 1

            out_lines.append(str(distinct))

    print("\n".join(out_lines))

if __name__ == "__main__":
    solve()
```実装は不変条件を直接反映します。 配列`a`は現在の値を保存するため、更新ごとに O(1) の古い値にアクセスできます。 辞書`freq`多重性を追跡します。 変数`distinct`いずれかの方向にカウントがゼロを横切るときにアクティブなキーの数を増分的に維持することで、アクティブなキーの数の再計算を回避します。 

遷移を扱うときは注意が必要です。 値をデクリメントする場合、個別カウンタはカウントがちょうど 0 になった場合にのみ減少します。 値をインクリメントする場合、個別のカウンタは 0 から 1 に遷移するときにのみ増加します。 これにより、すでに存在する値を二重にカウントすることが回避されます。 

インデックス作成は、から 1 を減算して調整されます。`p`入力では 1 から始まるインデックスが使用されるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, m = map(int, input().split())
            a = list(map(int, input().split()))
            freq = {}
            distinct = 0
            for x in a:
                if freq.get(x, 0) == 0:
                    distinct += 1
                freq[x] = freq.get(x, 0) + 1

            for _ in range(m):
                p, r = map(int, input().split())
                p -= 1
                old = a[p]
                freq[old] -= 1
                if freq[old] == 0:
                    distinct -= 1
                new = old + r
                a[p] = new
                if freq.get(new, 0) == 0:
                    distinct += 1
                freq[new] = freq.get(new, 0) + 1
                out.append(str(distinct))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値が完全に消失する場合です。 現在、1 人を除いてすべてのコーダーが値 5 を持っており、最後のコーダーが更新されて消えたとします。 5 の頻度はゼロに低下するため、個別のカウンターをちょうど 1 つ減らす必要があります。 デクリメント ステップで次のことがチェックされるため、アルゴリズムはこれを処理します。`freq[old] == 0`減算して減少した後`distinct`その瞬間だけ。 

もう 1 つのケースは、すでに存在する値を導入することです。 コーダーが 3 から 7 に変更したが、7 がすでに他の場所に現れている場合、個別カウントを増加させてはなりません。 小切手`if freq[new] == 0`値が以前に存在しなかった場合にのみ、個別にインクリメントするようにします。 

3 番目のケースは、同じインデックスで更新が繰り返される場合です。 配列`a[p]`は常に現在の値を保存するため、各更新では次の状態を適用する前に前の状態が正しく減算されます。 これにより、以前の更新からの古い貢献が蓄積されることが回避されます。
