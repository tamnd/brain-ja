 ## 解決策
 ## 問題の理解

 桁の並べ替え操作によって小さな整数を繰り返し変換しています。 各ステップでは、現在の値を取得し、先頭のゼロを使用して 4 桁の文字列に正規化し、その桁から 2 つの新しい数値を形成します。1 つは昇順にソートされた数値、もう 1 つは降順にソートされた数値です。 次の値は、これら 2 つの数値の差です。 

したがって、各状態は前の状態にのみ依存し、変換は決定的です。 10000 未満の初期値から始めて、このルールを正確に k 回適用し、最終値を報告します。 

k は 10^18 まで非常に大きくなる可能性がありますが、状態空間は小さいです。 すべての数字は、事実上、可能な 10,000 個の 4 桁構成のうちの 1 つです。 これにより、k ステップを直接シミュレートすることは直ちに除外されます。最悪のケースは、テスト ケースごとに 10^18 の演算が行われることになり、これは実現可能な制限をはるかに超えているからです。 10^5 のテスト ケースでさえ、k の線形にはすでに大きすぎます。 

重要な構造上の制約は、関数が有限セットをそれ自体にマップすることです。 これにより、繰り返しの適用が最終的にサイクルに入ることが保証されます。 このサイクル動作がソリューションのバックボーン全体です。 

実際には、いくつかのエッジ動作が重要です。 

よくある間違いは、先頭のゼロを忘れることです。 たとえば、21 は 0021 として扱う必要があります。パディングをスキップすると、桁の並べ替えが完全に変わり、異なる遷移が生成され、正確さが損なわれます。 

もう 1 つの微妙なケースは、7770 や 1000 など、数字が繰り返される数字です。これらは、多くの場合、安定したサイクルまたは固定小数点にすぐに崩壊します。 数字のパディングや並べ替えが正しく実装されていない場合、これらのケースではすぐに問題が露呈する傾向があります。 

最後に、k はゼロにすることができます。 その場合、出力は変更されていない元の数値でなければなりませんが、少なくとも 1 回の反復を想定すると誤って処理されやすくなります。 

## アプローチ

 単純なアプローチは単純なシミュレーションです。 各ステップで、数値を先頭にゼロが付いた 4 文字の文字列に変換し、数字を 2 回並べ替えて p と q を形成し、q から p を引いた値を計算して続行します。 これは正しく、k が小さい単一のテスト ケースの場合は問題ありません。 

問題はkの大きさです。 桁の並べ替えは固定サイズを超えるため、各ステップは O(1) ですが、k は 10^18 まで増加する可能性があります。 たとえ各ステップに数回の操作しかかからなかったとしても、それを k 倍することは不可能です。 

重要な観察は、変換が 10,000 状態の固定された世界に対して作用するということです。 有限集合上の決定論的な関数は、最終的には繰り返さなければなりません。 状態が繰り返されると、シーケンスはサイクルに入ります。 その後、さらなる遷移が定期的に行われます。 

これは、k ステップに達するか、繰り返される状態を検出するまでシミュレーションする必要があるだけであることを意味します。 状態は最大 10000 個あるため、最初に繰り返される状態は 10000 ステップ以内に出現する必要があります。 その後、サイクル長を抽出し、剰余演算を使用して直接ジャンプします。 

これにより、前処理後に天文学的に大きな k が定数時間の計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | テストあたり O(k) | お(1) | 遅すぎる |
 | サイクル検出 + ジャンプ | テストごとに O(10000) | O(10000) | 承認済み |

 ## アルゴリズムのチュートリアル

 変換を、0000 から 9999 までの整数に対して定義された関数 f(x) として扱います。

1. 桁ソート ルールを 1 回適用して、[0, 9999] 内の任意の数値 x の次の状態を事前計算します。 これにより、文字列ソートの繰り返しが回避されるため、シミュレーション中に遷移が O(1) になります。 
2. 各テスト ケースについて、最初の数値から開始し、各値が最初に出現する時間を記録しながら遷移をシミュレートします。 各数値が最初に表示されるステップ インデックスを保存します。 
3. 繰り返しの前に k ステップに到達すると、現在の値を直接返します。 これは、k が小さい場合、またはシーケンスが観測部分内で循環しない場合を処理します。 
4. 以前に確認した値を再度確認すると、サイクルが検出されました。 繰り返される値の最初の出現インデックスをエントリ ポイント t、現在のステップを s とします。 サイクルの長さは s - t です。 
5. k ステップ後の最終状態を計算するために、2 つのフェーズを区別します。 k < t の場合、答えはサイクルが開始する前にあります。 それ以外の場合は、(k - t) modcycle_length を使用してサイクルのどこまで到達するかを計算し、それに応じてサイクルにインデックスを付けます。 
6. 対応する保存値を出力します。 

重要な設計上の選択は、プレサイクル動作とサイクル動作を分離することです。 最初の部分はループへの線形チェーンであり、2 番目の部分は周期的な繰り返しです。 このアルゴリズムはシーケンスを明示的に保存することに依存しているため、後でシーケンスにインデックスを付けることができます。 

### なぜ効果があるのか

 変換は有限セットに対する決定論的な関数を定義するため、すべての無限の軌道は最終的にある状態を繰り返す必要があります。 状態が繰り返されると、決定論により、その状態からの将来の進化全体が同一になるように強制され、サイクルが形成されます。 記録された最初の出現インデックスにより、サイクルのエントリ ポイントが正しく識別されることが保証され、モジュラー演算によりサイクル内の正しい位置に到達することが保証されます。 考えられるすべての状態がプレフィックスまたはサイクルのいずれかで考慮されるため、シミュレーションの外部には目に見えない動作は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def next_state(x: int) -> int:
    s = str(x).zfill(4)
    asc = "".join(sorted(s))
    desc = "".join(sorted(s, reverse=True))
    return int(desc) - int(asc)

def solve():
    t = int(input())
    
    # Precompute transitions for all states
    nxt = [0] * 10000
    for i in range(10000):
        nxt[i] = next_state(i)
    
    for _ in range(t):
        n, k = input().split()
        n = int(n)
        k = int(k)
        
        seen = {}
        seq = []
        
        cur = n
        step = 0
        
        while cur not in seen and step <= k:
            seen[cur] = step
            seq.append(cur)
            if step == k:
                break
            cur = nxt[cur]
            step += 1
        
        if step == k:
            print(cur)
            continue
        
        if cur not in seen:
            print(cur)
            continue
        
        start = seen[cur]
        cycle = step - start
        
        if k < len(seq):
            print(seq[k])
        else:
            idx = (k - start) % cycle
            print(seq[start + idx])

if __name__ == "__main__":
    solve()
```実装ではまず、各ステップが一定時間で計算されるように遷移テーブルを構築します。 これにより、シミュレーション中にソートが繰り返されることが回避されます。 

各テスト ケースについて、最初の出現インデックスに番号をマッピングする辞書内の訪問した状態を追跡します。 シーケンスは、サイクルを検出した後に応答を再構築できるように保存されます。 

停止条件は慎重に 3 つのケースに分けられます。 繰り返しの前に自然にステップ k に到達した場合は、すぐに出力します。 k に到達せず、サイクル検出も行わずに早期終了した場合 (実際にはまれですが、ステップ制限により可能です)、現在の状態を返します。 それ以外の場合は、サイクル演算を適用します。 

主な微妙な点は、次の間で正しいインデックス付けを保証することです。`seen`、`seq`、歩数もカウントされます。 の`start`インデックスはサイクルのエントリポイントをマークし、`(k - start) % cycle`ループ内の正しいオフセットを与えます。 

## 実用的な例

 ### 例 1

 入力: n = 523、k = 2

 まず正規化してトランジションを適用します。 

| ステップ | 現在 | 次の状態 | 理由 |
 | --- | --- | --- | --- |
 | 0 | 0523 | 5085 | 並べ替えられた降順から昇順を引いたもの |
 | 1 | 5085 | 7992 | 変換が適用されました |
 | 2 | 7992 | 6174 | 次の反復 |

 2 ステップ後の値は、アラインメントに応じて、k=1 の場合は 7992、k=2 の場合は 6174 になります。 ここで、k=2 は 6174 になります。 

このトレースは、値がどのくらい早くよく知られている Kaprekar サイクルに移行するかを示しています。 

### 例 2

 入力: n = 1351、k = 1

 | ステップ | 現在 | 次の状態 | 理由 |
 | --- | --- | --- | --- |
 | 0 | 1351 | 2214 | 数字の並べ替え (5311 ～ 1135) |

 1 ステップ実行すると、すぐに 2214 が得られます。 

これは、明らかではない開始値であってもさまざまな中間状態を生成できることを示しており、サイクル圧縮の前に直接シミュレーションが必要な理由が裏付けられています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(10000 + t · L) | すべての遷移を 1 回事前計算し、その後、各テストは、状態の数によって制限される、最大でもプレフィックスとサイクル エントリをシミュレートします。 
| スペース | O(10000) | 遷移テーブルとテストごとの訪問シーケンスのストレージ |

 固定の 4 桁の状態空間により、繰り返し前のステップ数である L が最大 10000 であることが保証されます。t が 10^5 までの場合、各テストは k とは独立して制限された作業を実行するため、解の効率は維持されます。

 ## 特殊なケース

 重要なエッジ ケースは k = 0 です。シミュレーション ループで次のチェックが行われるため、アルゴリズムは初期値を直接返します。`step == k`進む前に。 入力用`n = 1234, k = 0`、シーケンスは決して進められず、出力は次のようになります。`1234`。 

もう 1 つのケースは、7770 のような数字の繰り返しです。変換により、そのような数字はすぐに安定したサイクルに減らされます。 サイクル検出メカニズムは、少数のステップ内の繰り返しを捕捉し、冗長な計算を回避します。 

21 が 0021 になるなど、パディングの後に先頭にゼロがある数値の場合は、`zfill(4)`一貫した数字の並べ替えが保証されます。 これがないと、変換で 21 が 2 桁の数字として誤って扱われ、まったく異なる軌道が生成されてしまいます。
