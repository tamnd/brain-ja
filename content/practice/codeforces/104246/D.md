 ## 解決策
 ## 問題の理解

 ピザは同一のスライスに切り分けられ、各スライスは固定の中心角 θ によって定義される扇形になります。 すべてのスライスは合同であるため、半径 r は分布の問題には無関係です。 重要なのは、360 度の円全体がいくつの等しい角度の部分に分割されるかだけです。 

このステートメントからは、スライスの数が直接与えられることはありません。 代わりに、スライスの数を 360 / θ として暗黙的に定義するスライス角度 θ が伝えられ、これがすべてのテスト ケースで整数であることが保証されます。 

2 人がピザを分割して、両方が整数のスライス全体を受け取り、両方とも同じ数のスライスを受け取りたいと考えています。 スライスは細分化できないため、問題はスライスの総数が偶数であるかどうかを確認することになります。 

入力サイズは小さく、最大 2400 のテスト ケースとケースごとの定数時間演算が可能です。 これは、テスト ケースのソリューションごとに O(1) があれば十分であり、単純な算術チェックやモジュラー チェックでも十分に制限内に収まることを強く示唆しています。 スライスの反復や因数分解を伴うものは不要です。 

θ = 360 など、θ が大きい場合、微妙なエッジ ケースが発生します。その場合、スライスは 1 つしかなく、2 人で均等に分割することは不可能です。 もう 1 つの特殊なケースは θ = 180 で、スライスがちょうど 2 つあり、公平な分割が可能です。 

## アプローチ

 この問題を直接考える方法は、まずスライスの数 n = 360 / θ を計算することです。 n がわかったら、n を 2 つの等しい整数に分割できるかどうか、つまり n が 2 で割り切れるかどうかが問題になります。 

強引な考え方としては、ピザのカットをシミュレートしたり、スライスの数を明示的に数えたりすることになりますが、スライス数は単純な除算で決定されるため、それはすでに不要です。 円周上を反復したり、スライスを明示的に構築したりするアプローチは、ケースごとに一定時間で実行されますが、概念的には過剰です。 

重要な観察は、2 人の間の公平性は、同一のユニットの合計数が偶数であるかどうかを尋ねることと同じであるということです。 ジオメトリと半径は、スライスが一致していることを保証する以上の役割はありません。 スライス数のパリティのみが重要です。 

したがって、問題は (360 / θ) % 2 == 0 かどうかをチェックすることになり、これは 360 / θ が偶数であるかどうかをチェックするように書き直すことができます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの θ を読み取り、スライス数 n を 360 割った θ として計算します。 この問題では割り切れることが保証されているため、丸めの問題は発生しません。 
2. n が 2 で割り切れるかどうかを確認します。これにより、スライスを分割せずにスライスを 2 つの等しいグループに分割できるかどうかが決まります。 
3. nが偶数の場合は「YES」を出力します。 それ以外の場合は「NO」を出力します。 

### なぜ効果があるのか

 各スライスはリソースの分割不可能な単位です。 有効な分散ではスライス全体のみが割り当てられるため、問題は n 個の同一オブジェクトを 2 つの等しいサイズのセットに分割することになります。 このようなパーティションは、n が偶数である場合にのみ存在します。 総数以外の幾何学的特性は実現可能性に影響を及ぼさないため、パリティは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        r, theta = map(int, input().split())
        n = 360 // theta
        if n % 2 == 0:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを個別に読み取り、スライスの数に影響を与えないため、r を無視します。 整数の除算 360 // θ は、この問題により θ が 360 を除算することが保証されているため安全です。パリティ チェックは実現可能性の条件を直接エンコードします。 

よくある実装上の間違いは、360 / θ の浮動小数点除算を試みてからパリティをチェックすることです。これにより、他の問題で精度の問題が発生する可能性があります。 ここでは、整数除算を使用することでそのようなリスクを回避し、スライスの離散構造に合わせます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        r, theta = map(int, input().split())
        n = 360 // theta
        out.append("YES" if n % 2 == 0 else "NO")

    return "\n".join(out)

# provided samples
assert run("3\n10 45\n5 40\n8 60\n") == "YES\nNO\nYES"

# custom cases
assert run("1\n1 360\n") == "NO", "single slice"
assert run("1\n1 180\n") == "YES", "two slices"
assert run("1\n10 90\n") == "YES", "four slices"
assert run("1\n10 120\n") == "NO", "three slices"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 360 | いいえ | 単一のスライスを分割することはできません。 
| 1 180 | はい | 最小有効偶数分割 |
 | 1 90 | はい | 典型的な偶数の場合 |
 | 1 120 | いいえ | スライス数が奇数の場合 |

 ## 特殊なケース

 θ = 360 の場合、ピザは 1 枚のスライスで構成されます。 アルゴリズムは n = 1 を計算し、奇数パリティを検出し、正しく NO を返します。 

θ = 180 の場合、スライスはちょうど 2 つあります。 計算の結果、n = 2、パリティは偶数であるため、YES が生成され、唯一可能な公平な分割と一致します。 

θ = 1 または 360 の小さな約数の場合、アルゴリズムは整数演算とパリティのみに依存するため一貫して動作し、精度やスケーリングの問題は発生しません。
