 ## 解決策
 ## 問題の理解

 1 から N までの番号が付けられた直線上の隠れた区間を扱っています。この直線上のどこかに、A で始まり B で終わる連続したセグメントがあり、私たちの目標は、その長さ (B マイナス A プラス 1) を決定することです。 

A または B に直接アクセスすることはできません。代わりに、「x はセグメントの前、セグメント内、またはセグメントの後にあります」という形式のクエリを行うことができます。 応答は、ラインを 3 つの領域に分割します。つまり、A の左側のすべて、A から B までのすべて、および B の右側のすべてです。各クエリにより、選択した点がどの領域に属しているかが正確にわかります。 

重要な制約は、テストあたりのクエリ数が 55 に制限されているのに対し、N は 10^9 まで大きくできることです。 これにより、全範囲にわたるリニア スキャンまたは高密度プローブ戦略が即座に除外されます。 全範囲にわたる各バイナリ検索には約 30 クエリのコストがかかり、このような検索を単純に複数回実行すると制限を超えてしまうため、対数戦略であっても慎重に予算を立てる必要があります。 

微妙だが重要な保証は、間隔の長さが最大 ​​10^6 であることです。 この追加の境界により、単純な「[1, N] に対して A と B を個別に検索する」アプローチがクエリ バジェットを圧迫するのを防ぐことができます。 これは、1 つのエンドポイントがわかれば、もう 1 つのエンドポイントはより小さな領域で見つかる可能性があることを示唆しています。 

[1, N] に対する完全な二分探索を使用して A と B の両方を個別に見つけようとすると、単純な間違いが発生します。 これには、A に対して約 30 個のクエリ、B に対してさらに 30 個のクエリが必要となり、合計で約 60 個のクエリが必要になります。 これはすでに許可されている 55 を超えています。もう 1 つの間違ったアプローチは、クエリを使用して推測された点から「拡張」しようとすることです。これは、応答では距離が示されず、相対位置しか示されないためです。 

したがって、課題は単にセグメントを見つけるだけではなく、部分的に答えを学習した後に検索スペースを削減せざるを得なくなる厳しいクエリ バジェットを尊重しながらそれを行うことです。 

## アプローチ

 ブルートフォース戦略では、セグメント内にある最初のインデックスとセグメント内にある最後のインデックスが見つかるまで、1 から N までのすべての位置をスキャンし、各ポイントをクエリします。 これが機能するのは、すべてのポイントが明示的に分類されているため、遷移を追跡することで A と B を識別できるためです。 ただし、最悪の場合、N は 10^9 になるため、各クエリが定数時間であっても、このアプローチは完全に実行不可能です。 

より構造化されたアプローチは二分探索です。 正しく解釈すれば、応答関数は便利な意味で単調です。 A の場合、すべての位置 x < A は「<」を返しますが、すべての位置 x >= A は「=」または「>」を返します。 これにより、きれいな単調境界が得られ、「<」ではない最初の位置をバイナリ検索できるようになります。 

同様に、B については、すべての位置 x > B は「>」を返し、すべての位置 x <= B は「<」または「=」を返すことがわかります。 これにより、「>」以外の最後の位置を二分検索できます。 

全範囲 [1, N] にわたって両方のバイナリ検索を実行すると、約 60 個のクエリが使用される危険があります。 これを解決する重要な観察は、セグメントの長さが最大 ​​10^6 であることが保証されていることです。 A を特定したら、B は [A, min(N, A + 10^6)] にある必要があることがわかります。 これにより、2 番目の二分検索ドメインが 10^9 から最大 10^6 に削減され、クエリが大幅に削減されます。 

したがって、タスクを 2 つの段階に分割しました。A の全範囲二分探索と、小さなウィンドウでの B の限定二分探索です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | リニアスキャン | O(N) クエリ | お(1) | 遅すぎる |
 | 全二分探索を 2 回 | O(log N) クエリ | お(1) | クエリが多すぎます |
 | 最適化された分割検索 | O(log N + log L) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

1. 範囲 [1, N] で二分検索を実行して A を見つけます。中点 x については、クエリを実行し、応答を解釈します。 応答が「<」の場合、x は厳密に A の前にあるため、A は右側にある必要があります。 それ以外の場合、x は A の内側または右側にあるため、A は x または左側にあります。 検索は「<」ではない最初の位置に収束します。 
2. A がわかったら、B の縮小検索範囲を [A, min(N, A + 10^6)] として定義します。 この問題ではセグメントの長さが最大 ​​10^6 であることが保証されているため、これは有効であり、B はこの間隔の外に存在することはできません。 
3. 2 回目の二分検索を実行して、「>」ではない最後の位置を見つけます。 中間点 x の場合、応答が「>」の場合、x は厳密に B の後にあるため、左に検索する必要があります。 それ以外の場合、x は B または B より前にあるため、右に移動します。 
4. 両方のエンドポイントが見つかったら、答えを B − A + 1 として計算します。 

### なぜ効果があるのか

 正確性は、クエリ関数の 2 つの単調分割に依存します。 述語「x < A」は x において厳密に単調であり、述語「x > B」も x において厳密に単調です。 これにより、二分探索で境界を正確に特定できるようになります。 最大セグメント長の制約により、A の周囲の検索スペースを縮小しても B を除外できないことが保証されるため、第 2 段階は安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x):
    print(f"? {x}", flush=True)
    return input().strip()

def find_A(n):
    lo, hi = 1, n
    ans = n
    while lo <= hi:
        mid = (lo + hi) // 2
        res = ask(mid)
        if res == '<':
            lo = mid + 1
        else:
            ans = mid
            hi = mid - 1
    return ans

def find_B(n, A):
    lo = A
    hi = min(n, A + 10**6)
    ans = A
    while lo <= hi:
        mid = (lo + hi) // 2
        res = ask(mid)
        if res == '>':
            hi = mid - 1
        else:
            ans = mid
            lo = mid + 1
    return ans

def solve():
    n = int(input())
    A = find_A(n)
    B = find_B(n, A)
    print(f"! {B - A + 1}", flush=True)

if __name__ == "__main__":
    solve()
```このソリューションでは、対話を小さなヘルパー関数に分割します。`ask`、すべてのクエリが即座にフラッシュされるようにします。これは対話型の問題では必須です。 最初の二分探索では、「<」を左側のセグメントの外側にあることを示す厳密な指標として扱うことにより、左側の境界を特定します。 2 番目のバイナリ検索は、可能な最大セグメント長から導出される安全なウィンドウに意図的に制限されており、これがクエリ制限内にとどまる鍵となります。 

一般的な実装の落とし穴は、応答「=」を個別の処理が必要な特殊なケースとして扱うことです。 実際には、「=」はどちらのバイナリ検索でもセグメント内にあるのと同じように動作するため、極端でない場合とグループ化できます。 

## 実用的な例

 ### 例 1

 入力:```
N = 6
A = 2, B = 4
```A の二分探索:

 | ステップ | そうだ | こんにちは | ミッド | 応答 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 6 | 3 | '=' | 左に移動 |
 | 2 | 1 | 2 | 1 | '<' | 右に移動 |
 | 3 | 2 | 2 | 2 | '=' | 見つかった |

 B の二分探索 (範囲 [2, 6]):

 | ステップ | そうだ | こんにちは | ミッド | 応答 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 6 | 4 | '=' | 右に移動 |
 | 2 | 5 | 6 | 5 | '>' | 左に移動 |
 | 3 | 5 | 4 | - | 停止 | B = 4 |

 これにより、A = 2、B = 4 が確認されるため、答えは 3 になります。 

### 例 2

 入力:```
N = 10^9, segment length = 10^6
```最初のバイナリ検索では、A を見つけるのにまだ約 30 クエリが必要です。2 番目のバイナリ検索ではサイズ 10^6 のウィンドウのみを探索するため、約 20 クエリが必要です。 これは、55 クエリ制限内に問題なく収まります。 

このトレースは、最適化が表面的なものではなく、最悪の場合の実現可能性のために必要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 (クエリ) | O(log N + log 10^6) | 全範囲で A を二分探索し、次に有界範囲で B を二分探索します。 
| スペース | お(1) | 少数の整変数のみが維持されます。 

log2(10^9) が約 30、log2(10^6) が約 20 であるため、クエリの複雑さは 55 未満に留まり、安全マージンが得られます。

 ## 特殊なケース

 間隔が 1 で始まると、A の二分検索では「<」が表示されないため、直接 1 に収束します。デフォルトの答えは上限に初期化され、有効な候補が現れた場合にのみ強化されるため、ロジックは引き続き機能します。 

間隔が N で終了すると、2 番目のバイナリ検索では「>」応答がまったく表示されないため、許容範囲全体に拡張され、B = N が正しく返されます。 

間隔の最大許容長が 10^6 の場合、制限された 2 番目の検索範囲は有効な領域と正確に一致します。 これが、2 番目のバイナリ検索がクエリ制限内に収まるほど十分な効率を維持する唯一の理由であり、有効な B が考慮から除外されないことが保証されます。
