 ## 解決策
 ## 問題の理解

 配列が与えられ、少なくとも 2 つの長さのすべての連続したセグメントを調べます。 選択した各セグメントについて、元の順序を無視し、代わりに値を並べ替えます。 並べ替えたら、連続する要素間のギャップを計算します。 このようなすべてのギャップが少なくとも所定のしきい値以上である場合、セグメントは有効であると見なされます。$k$、並べ替え後、2 つの連続する値が次の値よりも近いことを意味します。$k$。 

タスクは、この特性を満たすサブ配列の数を数えることです。 

重要な制約は、すべてのテスト ケースの合計の長さが最大でも$10^5$。 これにより、ソートされた構造を再計算したり、各部分配列を個別にスキャンしたりするアプローチは即座に除外されます。 二次関数の何か$n$テスト ケースごとのサイズは 1 つのテスト ケースでも失敗するため、$10^5$すでに約が必要になります$10^{10}$部分配列の単純な列挙での演算。 

微妙な点は、条件が元の順序に関するものではなく、各部分配列内のソートされたマルチセットに関するものであるということです。 有効性は位置ではなく値のグローバルな順序に依存するため、この切断により単純なスライディング ウィンドウ チェックが難しくなります。 

典型的な失敗例は、元の配列内の隣接する要素をチェックするだけで十分であると想定することに起因します。 たとえば、配列が次の場合、$[1, 100, 2]$と$k = 50$、ソート後は次のようになるため、部分配列は有効です。$[1,2,100]$、ギャップは$1$そして$98$, したがって無効です。 しかし、元の隣接要素のみをチェックすると、隣接しない要素間のこの相互作用を誤って見逃してしまいます。 

もう 1 つの失敗モードは、ソートされた配列を部分配列ごとに個別に再計算することです。 のために$n = 10^5$、 平$O(n^2 \log n)$実現不可能です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての部分配列について、その要素を抽出して並べ替え、隣接するすべての差異が少なくとも以下であるかどうかを確認します。$k$。 これは定義に直接従うため、正しいです。 ただし、$O(n^2)$サブ配列と各チェックのコスト$O(m \log m)$、 どこ$m$は部分配列の長さです。 これはおおよそ次のことにつながります$O(n^3 \log n)$最悪の場合、それは実現可能な限界をはるかに超えています。 

主な改善は、サブ配列ごとにすべてを再計算する必要がないことを認識したことによってもたらされます。 代わりに、スライディング ウィンドウを維持し、現在のウィンドウの並べ替えられた構造を動的に追跡します。 この条件は、ソートされた順序での隣接する差分のみに依存するため、現在のマルチセットをソートされた形式で維持し、最小の隣接ギャップを効率的に追跡できれば、挿入または削除ごとに対数時間で妥当性を更新できます。 

重要なアイデアは、現在のウィンドウをバランスのとれた順序構造として維持することです。 値を挿入するときは常に、その隣接関係のみが変更されるため、ソート順にその直前の先行者と後続者をチェックするだけで済みます。 私たちは、隣接するすべての差異を追跡する別の構造を維持し、これらの差異を最小限に抑えます。 ウィンドウは、この最小値が少なくとも次の場合にのみ有効です。$k$。 

これにより、問題は 2 ポインター ウィンドウの拡張に変わり、各ステップで正確さが維持されます。$O(\log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 引き違い窓を維持しております$[l, r]$ただし、ウィンドウは位置ではなく値に基づいて検証されます。 現在のウィンドウの順序付けされたマルチセットを保持し、隣接する差異を追跡します。 

### ステップ

 1. 2 つのポインタを初期化する$l = 0$、$r = 0$、および値の空の順序構造。 
2. 連続する要素間のすべての隣接する差分を、その最小値とともにソート順に格納する構造を維持します。 
3.右ポインタを伸ばす$r$一度に 1 ステップずつ挿入$c[r]$秩序ある構造に。 
4. 値を挿入するときは、その先行者と後続者をソートされた順序で見つけます。 両方が存在する場合は、それらの間の古いギャップを削除し、挿入された値を含む 2 つの新しいギャップに置き換えます。 近隣が 1 つだけ存在する場合、ギャップは 1 つだけ作成されます。 ソートされた順序で隣接する関係のみが変更されるため、このローカル更新で十分です。 
5. 挿入後、隣接する最小ギャップが少なくとも 1 つ以上あるかどうかを確認します。$k$。 そうでない場合、ウィンドウは無効です。 
6. ウィンドウが無効な間に移動します。$l$前方、削除$c[l]$構造から取得し、同じ先行/後続ロジックを使用して影響を受けるギャップを更新します。 
7. 有効性を復元した後、次で終わるすべてのサブ配列が削除されます。$r$そしてどこからでも始めてください$[l, r]$は有効なので追加します$(r - l)$答えに。 

ステップ 7 が機能する理由は、要素を削除してもソート順のギャップを減らすことができないため、有効なウィンドウの小さいプレフィックスは有効なままであるためです。 制約を取り除くだけです。 

### なぜ効果があるのか

 このアルゴリズムは、現在のウィンドウのマルチセットが常にソートされた順序で完全に表現され、そのソートされた順序内のすべての隣接するギャップが正確に追跡されるという不変条件を維持します。 すべての更新はローカルの隣接関係にのみ影響するため、グローバルな最小ギャップは常に正確です。 妥当性は、隣接するギャップが以下に該当するかどうかのみに依存するため、$k$、ウィンドウの正確さを判断するには、最小ギャップを維持するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class OrderedMultiset:
    def __init__(self):
        self.a = []
        self.count = {}

    def _add_gap(self, x):
        self.count[x] = self.count.get(x, 0) + 1

    def _remove_gap(self, x):
        self.count[x] -= 1
        if self.count[x] == 0:
            del self.count[x]

    def min_gap(self):
        if not self.count:
            return float('inf')
        return min(self.count.keys())

    def __repr__(self):
        return str(self.count)

import bisect

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    sorted_list = []
    gaps = {}

    def add(x):
        nonlocal sorted_list, gaps
        i = bisect.bisect_left(sorted_list, x)

        if i > 0:
            left = sorted_list[i - 1]
            gaps[left, x] = x - left
        if i < len(sorted_list):
            right = sorted_list[i]
            gaps[x, right] = right - x
        if 0 < i < len(sorted_list):
            left = sorted_list[i - 1]
            right = sorted_list[i]
            gaps[left, right] = 0
            del gaps[left, right]

        bisect.insort(sorted_list, x)

    def remove(x):
        nonlocal sorted_list, gaps
        i = bisect.bisect_left(sorted_list, x)

        left = sorted_list[i - 1] if i > 0 else None
        right = sorted_list[i + 1] if i + 1 < len(sorted_list) else None

        if left is not None:
            gaps.pop((left, x), None)
        if right is not None:
            gaps.pop((x, right), None)

        if left is not None and right is not None:
            gaps[left, right] = right - left

        sorted_list.pop(i)

    l = 0
    ans = 0

    for r in range(n):
        add(arr[r])

        while True:
            if len(sorted_list) >= 2:
                min_gap = min(gaps.values()) if gaps else float('inf')
            else:
                min_gap = float('inf')

            if min_gap >= k:
                break
            remove(arr[l])
            l += 1

        ans += r - l

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、現在のウィンドウ値のソートされたリストと、順序付けされたペアをキーとした隣接するギャップの辞書を維持します。 新しい要素を挿入すると、ローカルの先行および後続関係のみが更新されます。 要素を削除する場合も同じ考え方が当てはまります。 

表現`ans += r - l`位置で終わるすべての有効なサブ配列をカウントします`r`正確に存在するため、長さは少なくとも 2 です。`(r - l)`単一要素の場合を除く有効な開始点。 

よくある間違いは、挿入および削除操作中に隣接構造の両側の更新を忘れることです。これにより、最小ギャップ トラッキングが静かに破損します。

 ## 特殊なケース

 重要なエッジケースは、値が繰り返されることです。 2 つの等しい要素が同じウィンドウに入ると、それらの並べ替えられた差分は 0 になり、すぐにすべての要素に違反します。$k \ge 1$。 重複を挿入すると隣接構造にゼロ ギャップ エントリが作成され、これが最小値となり、左ポインタが強制的に移動されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、有効なウィンドウが非常に短い場合です。 たとえば、$[1,100]$大きい$k$、ウィンドウが頻繁に単一の要素に折りたたまれることがあります。 このアルゴリズムは、追加するだけであるため、長さ 1 のウィンドウのカウントを正しく回避します。$r-l$、その状況ではゼロになります。
