 ## 解決策
 ## 問題の理解

 私たちには都市の木が与えられています。 各都市には価値があり、各都市のペアは独自のシンプルなパスで接続されています。 クエリごとに、指定された 2 つのエンドポイント間のパス上にある都市を調べ、値が 1 より大きい公約数を持つ 2 つの異なる都市がそのパス上に存在するかどうかを知りたいと考えています。 

より簡単な言葉で言い換えると、各クエリは、ツリー パス上の値に互いに素でないペアが少なくとも 1 つ含まれているかどうかを尋ねます。 

n ≤ 1000 という制約により、パスが十分に短く、クエリごとに O(n²) 個のアイデアが概念的に可能であることが明らかですが、q ≤ 100000 では、クエリごとにパス情報を個別に再計算するソリューションから遠ざけられます。 クエリごとに頻度マップを再構築するような作業でも、不用意に実行すると速度が非常に遅くなる危険があります。 

隠れた難しさは、条件が単一のノードやグローバル プロパティに関するものではないことです。 それは、動的パスに制限された値の間で繰り返される素因数の存在についてです。 

いくつかの特殊なケースがその構造を強調しています。 

すべてのパス上のすべての値がペアごとに互いに素である場合、すべての答えは NO でなければなりません。 たとえば、値 [2、3、5、7] のチェーンでは、素因数を共有する 2 つの数値がないため、クエリは NO を返す必要があります。 

単一の素数がパス上の 2 つの異なるノードに出現する場合、答えはすぐに「YES」になります。 たとえば、パス上の値 [6, 10, 15] は、6 と 10 が係数 2 を共有するか、6 と 15 が係数 3 を共有するため、すでに YES を保証しています。 

単純な間違いは、パス上の隣接するノードのみをチェックすること、または 1 つの固定ルート パス分解に対してのみチェックすることです。 この条件は、ローカルではなく、パス内のすべてのペアにわたってグローバルです。 

## アプローチ

 最も直接的なアプローチは、x と y の間のパス上のすべてのノードを抽出して各クエリを処理し、次にノードのすべてのペアをチェックして gcd が 1 より大きいペアがあるかどうかを確認することです。これは定義に直接一致するため正しいですが、遅すぎます。 1 つのパスには最大 1000 個のノードを含めることができるため、クエリごとにすべてのペアをチェックするのは O(n²) であり、最悪の場合は約 10⁵ × 10⁶ の操作が必要になりますが、これは現実的ではありません。 

もう少し良いアプローチは、パス上のノードを引き続き列挙しますが、すべてのペアをチェックする代わりに、各値を因数分解し、どの素数がすでに出現しているかを追跡することです。 素数が 2 回出現した瞬間に停止できます。 これにより内部チェックが軽減されますが、最悪の場合、各ノードにはいくつかの素因数があり、それでもクエリごとに最大 1000 ノードを走査し、全体で約 10⁸ の操作が行われますが、これは Python では依然として危険です。 

重要な点は、実際には各パスを個別に再構築する必要がないということです。 各ノードが主要な特徴の小さなセットを提供するツリー内のパスに対するクエリをサポートする必要があるだけです。 これは、ツリーに関する Mo のアルゴリズムの古典的な設定です。オイラー ツアーでツリーを線形化し、LCA 調整でパス クエリを範囲クエリに減らし、頻度カウントを動的に維持できます。 

各ノードはその素因数に寄与し、現在のアクティブ セット内で各素数が何回出現するかというグローバル カウントを維持します。 いずれかの素数が 2 以上に達すると、クエリの答えは YES になります。 

これにより、問題は変化するノードのセットにわたってマルチセットを維持することに変わり、更新は現在の Mo ウィンドウの内外でノードを切り替えることに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース パス + ペア チェック | O(q · n²) | O(n) | 遅すぎる |
 | パストラバーサル + プライムトラッキング | O(q · n · log A) | O(n) | 危険 |
 | 素数カウントを使用したツリー上の Mo | 写真 O((n + q) √n · log A) | O(n + P) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各数値を個別の素因数に前処理します。 値は最大 10⁷ なので、√A までの試算で因数分解は十分に高速です。

次に、ツリーのオイラー ツアーを構築して、各ノードが線形配列に 2 回 (入力時に 1 回、終了時に 1 回) 表示されるようにします。 これにより、サブツリーのメンバーシップを表現できるようになり、パス クエリの LCA 修正もサポートされます。 

次に、各クエリ (x, y) がオイラー ツアーの範囲クエリに変換されます。 x と y が祖先関係にない場合、オイラー範囲だけでは単純なパスを完全には表現できないため、それらの LCA を個別に考慮する必要もあります。 

次に、Mo のアルゴリズムを適用して、ポインタの動きを最小限に抑える順序でこれらの範囲クエリを処理します。 

素数にわたる周波数配列を維持します。 現在のウィンドウに追加された各ノードについて、その素因数を反復処理し、その数を増やします。 削除の場合は、それらの数が減ります。 

また、現在少なくとも 2 の頻度を持つ素数の数を追跡するグローバル カウンタも維持しています。これが、クエリに答えるために必要な唯一の情報です。 

いつでも、このカウンタが正であればクエリの答えは YES、それ以外の場合は NO となります。 

### なぜ効果があるのか

 各ノードは、その素因数セットを正確に提供します。 ノードのペアは、少なくとも 1 つの素因数を共有する場合に限り、1 より大きい gcd を共有します。 したがって、「gcd > 1 のペアが存在する」という条件は、「パス集合内の少なくとも 2 つのノードに出現する素数が存在する」と同等になります。 Mo のアルゴリズムによって維持されるデータ構造は、これらの発生を正確に追跡するため、すべての YES は有効な反復プライムに対応し、すべての NO は反復が完全に存在しないことに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import isqrt

n = int(input())
a = list(map(int, input().split()))

g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

# factorization
def factorize(x):
    res = set()
    d = 2
    while d * d <= x:
        if x % d == 0:
            res.add(d)
            while x % d == 0:
                x //= d
        d += 1
    if x > 1:
        res.add(x)
    return list(res)

pf = [factorize(x) for x in a]

# LCA via binary lifting
LOG = 11
up = [[-1] * n for _ in range(LOG)]
depth = [0] * n

def dfs(u, p):
    up[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(0, -1)

for k in range(1, LOG):
    for i in range(n):
        if up[k - 1][i] != -1:
            up[k][i] = up[k - 1][up[k - 1][i]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff & (1 << k):
            a = up[k][a]
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]
    return up[0][a]

# Euler tour for Mo
euler = []
first = [-1] * n
last = [-1] * n

def dfs2(u, p):
    first[u] = len(euler)
    euler.append(u)
    for v in g[u]:
        if v == p:
            continue
        dfs2(v, u)
    last[u] = len(euler)
    euler.append(u)

dfs2(0, -1)

def get_path_lca(u, v):
    return lca(u, v)

# Mo's algorithm over Euler tour
q = int(input())
queries = []
for i in range(q):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    if first[x] > first[y]:
        x, y = y, x
    w = lca(x, y)
    queries.append((first[x], first[y], i, w))

block = int(len(euler) ** 0.5)

queries.sort(key=lambda x: (x[0] // block, x[1] // block))

cnt = {}
vis = [0] * n
bad_primes = 0

def toggle(u):
    global bad_primes
    if vis[u]:
        vis[u] = 0
        for p in pf[u]:
            cnt[p] -= 1
            if cnt[p] == 1:
                bad_primes -= 1
            elif cnt[p] == 0:
                pass
    else:
        vis[u] = 1
        for p in pf[u]:
            cnt[p] = cnt.get(p, 0) + 1
            if cnt[p] == 2:
                bad_primes += 1

# Mo pointers
cur_l, cur_r = 0, -1
ans = [False] * q

def add(idx):
    toggle(euler[idx])

for l, r, qi, w in queries:
    while cur_l > l:
        cur_l -= 1
        add(cur_l)
    while cur_r < r:
        cur_r += 1
        add(cur_r)
    while cur_l < l:
        add(cur_l)
        cur_l += 1
    while cur_r > r:
        add(cur_r)
        cur_r -= 1

    if w != euler[l] and w != euler[r]:
        toggle(w)
        ans[qi] = bad_primes > 0
        toggle(w)
    else:
        ans[qi] = bad_primes > 0

out = []
for i in range(q):
    out.append("YES" if ans[i] else "NO")
print("\n".join(out))
```この解決策は、すべての都市が素数の小さなリストとして表されるように、各ノード値を因数分解することから始まります。 次に、LCA クエリ用のバイナリ リフティング構造と、ノード範囲全体で Mo のアルゴリズムを有効にするオイラー ツアーの両方を使用してツリーが準備されます。 

各クエリは、オイラー配列と可能な LCA 調整上のセグメントに変換されます。 Mo プロシージャは、アクティブなセグメントを段階的に拡大または縮小し、ノードを内外に切り替えます。 各トグルは素数の頻度を更新し、「反復素数」のグローバル カウンタを調整します。 

クエリに対する答えは、現在のアクティブ セット内で素数の頻度が少なくとも 2 つあるかどうかによって完全に決まります。

 サンプルツリーを考えてみましょう。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) √n · k) | ノードごとに k 素数更新を行うオイラー ツアー上の Mo のアルゴリズム |
 | スペース | O(n + P) | 隣接関係、オイラー配列、素数周波数マップ |

 n ≤ 1000 および q ≤ 100000 の場合、√n は約 32 であるため、状態遷移の総数は数百万以内に収まり、各遷移はノードごとに数個の素数のみを処理するため、時間制限内に十分収まります。

 ## 特殊なケース

 すべての値が 2、4、8、16 のような素数のべき乗である場合、単一の素数が何度も出現するときに反復素数検出が機能するかどうかをテストします。 このアルゴリズムは素数 2 の頻度を正しく累積し、因子 2 を含む 2 つのノードがアクティブになるとすぐに YES をトリガーします。 

重複が存在するが、LCA 処理によって分離されている場合は、オイラー分解の正確性をテストします。 LCA ノードはクエリ評価中に一時的に挿入され、エンドポイントがオイラー区間を直接形成しない場合でもパスが完全に表現されるようにします。 

各ノードに複数の素数がある場合、トグルごとに複数のカウンターを更新しても有効な繰り返しを見逃すことはありません。 すべての素因数が独立して処理されるため、ノード間のオーバーラップは引き続き正しく検出されます。
