 ## 解決策
 ## 問題の理解

 いくつかの独立したクエリが与えられます。 各クエリは目標数値を提供します`x`整数の間隔`[l, r]`。 この間隔内で、3 つの異なる整数を選択できるかどうかを知りたいのです。`a < b < c`、すべて横たわっています`[l, r]`、その積が次と等しくなるように、`x`。 

このようなトリプルが存在する場合、有効な選択肢を 1 つ出力することができます。`(a, b, c)`。 そのようなトリプルが存在しない場合は、次のように出力します。`-1`。 

間隔は非常に特殊な点で小さいですが、`l`そして`r`は最大 1000 まで可能で、その差は最大 100 です。これは、すべてのクエリが最大 101 個の候補値に対して動作することを意味します。 この制限が構造を単純化するための重要な要素です。`x`最大 10^9 の場合、クエリごとの検索スペースは厳密に制限されます。 

単純なアプローチでは、インターバル内のすべてのトリプルを試行します。 利用できる数値は最大 101 個であるため、テスト ケースごとに約 100^3 ≈ 10^6 の組み合わせがあり、最大 100 個のテスト ケースを使用できます。これは限界に達していますが、最適化された Python ではまだ許容されます。 ただし、1 つのループを完全に削除する、より直接的な削減もあります。 

主なエッジケースは厳格な不等式要件から生じます`a < b < c`。 3つの数字を掛け合わせても`x`、次のような繰り返し値を使用します。`a = b`は無効です。 もう一つの微妙なケースは次のような場合です。`x`が小さいか素数である: 区間内で因数分解は存在しませんが、不注意な実装では 3 番目の値を検証せずに誤って部分除数を受け入れる可能性があります。 

素朴な考えによる失敗例:

 入力:`x = 12, l = 1, r = 5`トリプルのような`(1, 2, 6)`正しく乗算しますが、`6`は範囲外であるため、部分的な推論が妥当性を示唆している場合でも、拒否する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのトリプルを反復処理します。`(a, b, c)`間隔内でその積が等しいかどうかを確認します`x`。 これは、すべての可能性を徹底的にチェックし、制約によって間隔が小さいことが保証されるため、これは正しいです。 ただし、そのコストは間隔のサイズに応じて 3 乗的に増加します。 最大 101 個の値を使用すると、クエリごとに約 171,700 の組み合わせが得られ、100 個のクエリ全体でこれは数千万回のチェックに近づく可能性がありますが、オーバーヘッドを含めると Python の制約の下では依然として境界線に達します。 

重要な点は、3 つの値をすべて個別に選択する必要はないということです。 直したら`a`そして`b`、の値`c`として完全に決定されます`c = x / (a * b)`、分割が正確であれば。 これにより、検索が 3 つのネストされたループから 2 つのループと定数時間の検証ステップに減ります。 

したがって、すべてのトリプルを探索する代わりに、すべての順序付きペアを列挙します。`(a, b)`と`a < b`、積を計算します`a * b`、どうかを確認してください。`x`それで割り切れます。 そうであれば、計算します`c`それが区間内にあり、を満たすかどうかを検証します。`b < c`。 

これにより、3 次検索が 2 次検索に変わり、最大間隔サイズを考慮すると快適に高速になります。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`x`、`l`、 そして`r`、区間内の候補となる整数のリストを構築します。`[l, r]`。 

明示的なリストを使用する理由は、間隔が短く、クエリごとに固定されているためです。 
2. 考えられるすべての選択肢を反復します。`a`から`l`に`r`。 

それぞれ`a`はトリプルの最初の要素を表し、昇順を強制すると自然に重複が回避されます。 
3. それぞれについて`a`、すべてを繰り返します`b`そのような`b > a`。 

これにより、追加のチェックを行わずに、厳密な順序条件が常に維持されることが保証されます。 
4. コンピューティング`a * b`。 この値を超えると`x`、大きいため、まだ続行できます`b`生成物がさらに増加するだけですが、制約が小さいため、厳密には剪定は必要ありません。 
5. もし`x % (a * b) == 0`、計算する`c = x / (a * b)`。 

このステップでは、可能な唯一の候補を導​​き出すことで 3 番目のループを完全に置き換えます。`c`。 
6.次のことを確認します。`c`は整数であり、その範囲内にあります`[l, r]`、また満足します`c > b`。 

これにより、トリプルのすべての制約が満たされることが保証されます。 
7. そのような場合は、`c`存在する場合はすぐに出力されます`(a, b, c)`現在のテスト ケースの処理を停止します。 
8. ペアがない場合`(a, b)`有効な結果を生成します`c`、出力`-1`。 

### なぜ効果があるのか

 すべての有効な解は、正確に 1 つの順序ペアに対応します。`(a, b)`と`a < b`。 そのペアの 3 番目の値は、`c`は製品制約によって一意に決定されます。 アルゴリズムは、間隔内のすべての可能な順序ペアをチェックするため、有効なトリプルが存在する場合は、それに対応するペアが見つかります。 どの候補者もそうなので、`c`間隔と順序の制約に照らして検証されるため、無効なトリプルは生成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, l, r = map(int, input().split())

        found = False

        for a in range(l, r + 1):
            for b in range(a + 1, r + 1):
                prod = a * b
                if prod > x:
                    continue
                if x % prod != 0:
                    continue

                c = x // prod
                if c > b and l <= c <= r:
                    print(a, b, c)
                    found = True
                    break
            if found:
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```このソリューションは、ペア固定のアイデアを直接実装しています。 ネストされたループは列挙します`(a, b)`昇順で確実に`a < b`自動的に。 乗算チェックにより、不必要な除算作業が回避されます。`a * b`すでに超えています`x`。 一度有効になると`c`が導出されると、アルゴリズムは印刷前に順序と範囲の制約を即座に検証します。 

早期に終了することが重要です。有効なトリプルが見つかったら、問題はどのような正解も許容するため、検索を続ける必要はありません。

 ## 特殊なケース

 有効な因数分解が存在するが、因数の 1 つが区間の外側にある場合、微妙なケースが発生します。 例えば、`x = 24, l = 2, r = 5`。 因数分解`2 * 3 * 4`完璧に動作し、アルゴリズムによって検出されますが、次のような分解`1 * 3 * 8`範囲制約が無視される場合、精神的には正当であるとみなされる可能性があります。 アルゴリズムは明示的に強制します`l <= c <= r`, したがって、そのようなケースは正しく拒否されます。 

もう 1 つのエッジ ケースは、複数の因数分解が存在する場合です。 アルゴリズムは最初の有効なペアで停止するため、`(a, b)`、問題の要件に一致する有効なトリプルを返す可能性があります。
