 ## 解決策
 ## 問題の理解

 _n_ 個の停留所がある路線に沿って 1 台の路面電車が走行しており、最初の停留所で空車で始まり、最後の停留所で空車で終わります。 各停留所では、新しい乗客が乗車する前に一定数の乗客が降車します。 入力は、各ストップの整数のペア (出発する数と入る数) で構成されます。 私たちの仕事は、車内の乗客数がどの時点でもトラムの定員を超えないようにするために必要なトラムの最小定員を決定することです。 

制約は単純です。停留所は最大 1000 か所あり、どの停留所でも出入りする乗客の数は 1000 人を超えません。入力サイズが小さいため、O(n) 解は完全に受け入れられます。 各停止を順番にシミュレートする単純なアルゴリズムは、ミリ秒未満で動作します。 

多くの乗客が最初または終点の停留所で出入りする場合、明らかではないエッジケースが発生します。 たとえば、最初の停留所の出発者数が 0 人、入場者数が 1000 人の場合、即座の収容力は少なくとも 1000 人でなければなりません。 もう 1 つの微妙なケースは、一時的に残高を出入りするが、後で急上昇する場合です。 たとえば、ストップの場合`0 5`、`3 2`、`2 4`、`6 0`、トラムではさまざまな停留所でピークが発生するため、合計だけでなく実行中の最大値を追跡する必要があります。 

## アプローチ

 この強引なアプローチは実際にはすでに効率的です。路面電車の走行をシミュレートします。 乗客ゼロからスタート。 各停留所で、出発する数を減算し、入る数を加算し、現在の乗客数を記録します。 シミュレーション中に確認された最大値を追跡します。 この最大値は、路面電車が持つ必要のある最小容量です。 これは正しいです。トラムはそのピークを超えることはなく、トラムは少なくともその数の乗客を処理する必要があるからです。 

すべての停止を検査して入口と出口のダイナミクスを確認する必要があるため、この問題に対して漸近的にこれより高速な方法はありません。 重要な洞察は、運行の順序が重要であるということです。乗客は必ず乗車する前に降車します。 不注意に交換すると、誤ったピークが発生する可能性があります。 もう 1 つの微妙な点は、乗客数をゼロに初期化し、最初の停車地が乗客を排除しようとしないことを確認することです。これは入力制約によって保証されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各停留所をシミュレートする | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`current_passengers`ゼロに。 これは現在路面電車に乗っている人の数を表します。 
2.初期化`max_passengers`ゼロに。 これにより、路面電車のピーク時の乗車率が追跡されます。 
3. 最初から最後まで各ストップを繰り返します。 各停留所について、から降車する乗客の数を引きます。`current_passengers`。 これは、エントリの前に終了が発生することを反映しています。 
4. に入場する乗客の数を追加します。`current_passengers`。 
5.アップデート`max_passengers`もし`current_passengers`現在の最大値を超えています。 
6. すべての停止を処理した後、`max_passengers`必要な最小限のトラム容量を保持します。 この値を出力します。 

なぜ機能するのか: 不変条件は次のとおりです`current_passengers`always accurately reflects the number of passengers after each stop. 更新中`max_passengers`旅行全体を通じて最大の乗車率を確保します。 出口は常に入口の前に発生するため、操作の順序は実際の路面電車の動作を正確にモデル化します。 終点までに乗客は全員降車しており、問題の制約と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
current_passengers = 0
max_passengers = 0

for _ in range(n):
    a, b = map(int, input().split())
    current_passengers -= a
    current_passengers += b
    max_passengers = max(max_passengers, current_passengers)

print(max_passengers)
```コードはアルゴリズムに従って段階的に実行されます。 ストップの数を読み取り、カウンターを初期化し、各ストップをループします。 使用する`map(int, input().split())`退出数と入場数を安全に変換します。 加算前の減算では、エントリー前退出ルールが尊重されます。 トラッキング`max_passengers`ピーク負荷を確実に捕捉します。 実行中のカウントと最大値のみが必要なため、追加の配列やリストは必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    current_passengers = 0
    max_passengers = 0
    for _ in range(n):
        a, b = map(int, input().split())
        current_passengers -= a
        current_passengers += b
        max_passengers = max(max_passengers, current_passengers)
    return str(max_passengers)

# provided sample
assert run("4\n0 3\n2 5\n4 2\n4 0\n") == "6", "sample 1"

# custom cases
assert run("2\n0 0\n0 0\n") == "0", "all zero"
assert run("3\n0 5\n5 0\n0 0\n") == "5", "peak at first stop"
assert run("5\n0 1\n1 2\n2 3\n3 4\n4 0\n") == "7", "gradual buildup"
assert run("3\n0 1000\n0 0\n1000 0\n") == "1000", "large numbers"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 ストップ、すべてゼロ | 0 | 最小サイズの入力、乗客なし |
 | 3 ストップ、最初のピーク | 5 | 最初の停留所がピーク占有率を引き起こす |
 | 5 ストップ、徐々に増加 | 7 | ストップ間で段階的に増加 |
 | 3 ストップ、多数 | 1000 | 最大旅客値の処理 |

 ## 特殊なケース

 最初のエッジ ケースは、最初の停止ですでに高いピークが発生している場合です。 入力の場合:```
2
0 1000
1000 0
```最初の停車後、`current_passengers`は 1000 であり、更新されます`max_passengers`最後の停止後、すべて終了し、0 に戻ります。アルゴリズムは、必要な容量として 1000 を正しく報告します。 

もう 1 つのエッジ ケースは、エントリとエグジットが完全に相殺され、初期負荷を超えることがない場合です。 入力：```
3
0 3
3 3
3 0
```占有率は変動します: ストップ 1 → 3、ストップ 2 → 3 (3 を出て 3 に入る)、ストップ 3 → 0。最大値は 3 のままです。シミュレーションは、各ストップ後の実行最大値を追跡するため、これらのキャンセルを正しく処理します。
