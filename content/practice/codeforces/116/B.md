 ## 解決策
 ## 問題の理解

 小さな長方形のグリッドがあり、各セルには空、ブタ、またはオオカミが含まれています。 オオカミは、4 つの方角のいずれかで直接隣接する 1 頭の豚を食べることができます。 豚は一度食べると消滅し、二度と食べることはできません。 

目標は、合計で何頭の豚を食べるかを最大化することです。 

主要な制限は珍しいものであり、非常に重要です。すべての豚は最大でも 1 匹のオオカミに隣接します。 オオカミにはまだ数頭の隣接するブタがいるかもしれませんが、ブタが複数のオオカミによって争われることは決してありません。 

この制限により、問題はマッチングの問題から単純な貪欲なシミュレーションに変わります。 

グリッドの寸法は最大 10 × 10 であるため、ボード全体には最大 100 個のセルが含まれます。 非効率的な解決策でも合格する可能性があります。 それでも、この問題は、重いグラフ アルゴリズムの必要性を排除する構造的特性に気づくかどうかをテストするように設計されています。 

オオカミが豚を食べる間にボードが変化するため、慎重な実装が依然として重要です。 誤って同じ豚を 2 回食べることを許可すると、答えは不正解になります。 

簡単な間違いの 1 つは、豚が食べられた後に取り除くのを忘れることです。 次の入力を考えてみましょう。```
1 3
WPW
```正しい出力は次のとおりです。```
1
```真ん中のブタは両方のオオカミに隣接していますが、各ブタが隣接するオオカミを最大 1 つまで持つことができるため、この構成は実際にはステートメントによって禁止されています。 保証を無視した不注意な実装は、豚を 2 回カウントする可能性があります。 

もう 1 つの微妙なケースは、オオカミに複数の隣接するブタがいる場合です。```
2 2
PW
PP
```正しい出力は次のとおりです。```
1
```たとえ二匹の豚が隣接していても、オオカミは一匹の豚しか食べることができません。 バグのあるソリューションでは、隣接するすべての豚がカウントされる可能性があります。 

境界処理も一般的なエラーの原因です。 例えば：```
1 2
WP
```正しい出力は次のとおりです。```
1
```オオカミにはグリッド内にのみ隣人がいます。 チェックを行わずにボード外の座標にアクセスすると、インデックス エラーが発生します。 

## アプローチ

 最も直接的な強引なアイデアは、すべてのオオカミに対してあらゆる可能な決定を試みることです。 各オオカミは隣接するブタを 1 匹選ぶか、誰も選ばないことができます。 すべての組み合わせを再帰的に探索し、最大の答えを維持することができます。 

基板が小さいのでこれで大丈夫です。 最悪の場合、細胞は約 100 個あり、その多くがオオカミである可能性があります。 各オオカミに最大 4 つの選択肢がある場合、探索スペースは次のようになります。$4^k$、 どこ$k$オオカミの数です。 たった 20 匹のオオカミでも、すでに 1 兆を超える可能性があります。 

この爆発が起こる理由は、通常、オオカミが豚を奪い合うためです。 1 匹のオオカミに豚を選択すると、後で別のオオカミがブロックされる可能性があります。 

重要な観察は、この問題によりほとんどすべての競争が排除されるということです。 すべての豚は最大でも 1 匹のオオカミと隣接します。 つまり、オオカミが豚を見たら、他のオオカミは決してそれを取ることができないということです。 

これに気づくと、問題は簡単になります。 グリッドを反復処理します。 すべてのオオカミについて、その 4 つの隣接するセルをチェックします。 隣人に豚がいる場合、オオカミはすぐにそれを食べ、答えを増やし、その豚をボードから消去します。 

いずれにせよ、将来のオオカミがそのブタを使用することはできないため、この貪欲な選択は常に安全です。

 ## アルゴリズムのチュートリアル

 1. ブタが食べられた後にセルを変更できるように、グリッドを 2D 配列に読み取ります。 
2. 上下左右の 4 つの移動方向を用意します。 
3. グリッド内のすべてのセルを走査します。 
4. 現在のセルにオオカミがいる場合、その隣接する 4 つのセルを調べます。 
5. 各近傍について、まず座標がボード内にあるかどうかを確認します。 これにより、無効な配列アクセスが防止されます。 
6. 隣のセルに豚がいる場合は、すぐにオオカミに食べさせます。 

1. 答えを 1 つ増やします。 
2. そのブタ細胞を次のものに置き換えます。`.`そうすれば、オオカミは二度とそれを食べることができなくなります。 
3. このオオカミの隣人をさらにチェックするのをやめます。 

オオカミが食べる豚は最大でも 1 頭なので、食べた後も継続すると過剰にカウントされてしまいます。 
7. すべてのセルを処理した後、食べた豚の総数を出力します。 

### なぜ効果があるのか

 正しさは、すべての豚が最大でも 1 匹のオオカミに隣接しているという保証から得られます。 オオカミが隣のブタを見つけたとします。 今も後も、他の​​オオカミがその豚を使うことはできません。 すぐに食べたからといって将来の選択肢が減るわけではありません。 

その特性により、成功する貪欲な選択はすべて、他のすべての選択から独立しています。 このアルゴリズムでは、少なくとも 1 匹の隣接する豚を持つオオカミごとに 1 匹の豚を正確にカウントします。食べられた豚はグリッドから削除されるため、豚は 2 回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    ans = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'W':
                for dx, dy in directions:
                    ni = i + dx
                    nj = j + dy

                    if 0 <= ni < n and 0 <= nj < m:
                        if grid[ni][nj] == 'P':
                            ans += 1
                            grid[ni][nj] = '.'
                            break

    print(ans)

solve()
```ブタは食べられると消えるため、このソリューションでは、ボードを文字リストの変更可能なリストとして保存します。 Python では文字列は不変であるため、生の文字列を使用すると更新が面倒になります。 

外側のループはすべてのセルを 1 回スキャンします。 オオカミに遭遇するたびに、方向配列を使用して隣接する 4 つの位置をテストします。 

アクセスする前に境界チェックが行われます`grid[ni][nj]`。 この順序を逆にすると、エッジ セルでインデックス エラーが発生します。 

オオカミが豚を食べた後、コードは豚をただちに置き換えます。`.`。 これにより、二重カウントが防止され、問題ステートメントが正確にモデル化されます。 

の`break`という声明は必須です。 オオカミが食べられるのは豚一頭だけです。 休憩がなければ、1 頭のオオカミが複数の隣接するブタを誤って消費する可能性があります。

import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    ans = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'W':
                for dx, dy in directions:
                    ni = i + dx
                    nj = j + dy

                            ans += 1
                            grid[ni][nj] = '.'
                            break

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue()

 ## 特殊なケース

 オオカミが数頭の豚に触れた場合を考えてみましょう。```
2 2
PW
PP
```アルゴリズムはオオカミの位置をスキャンします`(0,1)`。 隣人を順番にチェックし、豚を見つけます。`(0,0)`。 答えは 1 になり、豚は取り除かれ、ループは直ちに終了します。 残りの豚はそのオオカミに対して無視されます。これは、各オオカミが最大 1 匹の豚を食べるというルールに一致します。 

次に、ボードのエッジケースを考えてみましょう。```
1 2
WP
```オオカミは左上隅に座っています。 一部の隣接する座標はボードの外に表示されます。`(-1,0)`または`(0,-1)`。 境界チェックでは、配列にアクセスする前にこれらの位置が拒否されます。 有効な隣人`(0,1)`にはブタが含まれているので、答えは安全に 1 になります。 

最後に、食べられる可能性がないケースを考えてみましょう。```
2 2
P.
.W
```オオカミ`(1,1)`4方向すべてをチェックします。 すべての有効なネイバーは空であるか、ボードの外側にあります。 答えが増加することはなく、アルゴリズムは正しく 0 を出力します。
