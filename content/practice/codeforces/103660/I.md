 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられており、1 から n までのインデックス範囲をいくつかの連続したセグメントに分割したいと考えています。 各インデックスは正確に 1 つのセグメントに属している必要があり、セグメントはギャップや重複なく配列全体をカバーする必要があります。 

すべてのセグメントについて、最初の配列の値の合計と 2 番目の配列の値の合計を比較します。 セグメントは、そのセグメントの a の合計が同じセグメントの b の合計以上である場合にのみ有効とみなされます。 タスクは、配列をできるだけ多くの有効なセグメントに分割することです。 

出力はそのようなセグメントの最大数、または有効なセグメント化を 1 つも作成できない場合は -1 になります。 

制約は単純な意味で重要です。 すべてのテスト ケースの n の合計は最大 5000 です。これは、テスト ケースごとに O(n²) 個の解が許容されることを意味します。 三次以降のものは、複数のテストにわたって直接実装すると遅すぎます。 これは、動的プログラミングまたはプレフィックスに対する貪欲なスキャンで十分である可能性が高いことも示唆しています。 

配列全体でも条件を満たさない場合、微妙なエッジ ケースが発生します。 a の合計が b の合計よりも小さい場合、すべてのパーティションに分割された配列全体が含まれており、その合計が依然としてグローバルな差分となるため、セグメント化はまったく機能しません。 たとえば、a がすべて 0 で、b がすべて 1 の場合、どのセグメントも不等式を満たすことができないため、答えは -1 でなければなりません。 

もう 1 つの厄介な状況は、有効なセグメントは存在するが、早すぎる貪欲な切断が失敗する場合に発生します。 たとえば、初期のプレフィックスが (a − b) に関してわずかに負であるが、後の要素がそれを補う場合、将来の有効なセグメントの形成を妨げる位置で強制的にカットを行わないようにする必要があります。 

## アプローチ

 自然な出発点は、考えられるすべてのパーティションをチェックすることを検討することです。 配列を k 個のセグメントに分割するそれぞれの方法で、各セグメントが合計条件を満たすかどうかを検証します。 パーティションの数が n とともに指数関数的に増加し、セグメントの合計を繰り返し計算しても 2 次またはそれ以上のオーバーヘッドが発生するため、これはすぐに実行不可能になります。 

より良い方法は、プレフィックスの違いに焦点を当てることです。 c[i] = a[i] − b[i] となる配列 c を定義します。 セグメント [l, r] の条件は、そのセグメントにわたる c の合計が負でないことになります。 したがって、問題は、配列を、それぞれの合計が負でない最大数の連続セグメントに分割することになります。 

この再定式化は、2 つのアレイを個別に追跡する必要がなくなり、すべてが実行残高の管理に減らされるため、強力です。 

重要な観察は、実行合計が以前は負またはゼロであった後、再び負でなくなるとすぐにカットする必要があるということです。 負でない合計でセグメントを終了できる機能を維持しながら、セグメントを可能な限り長く延長すると、セグメントの数が最大になります。 これにより、問題は貪欲スキャンに変わります。つまり、現在の合計を維持し、それが正の値またはゼロの値に達するたびに、安全にセグメントを閉じてリセットできます。 

正確な直観は、カットを遅らせてもセグメント数の増加には決して寄与しないということです。 合計が負でないプレフィックスはすべて有効なセグメント エンドポイントとして機能し、それをさらに拡張しても、潜在的な以前のカットを失う危険があるだけです。

 ## アルゴリズムのチュートリアル

 処理中に暗黙的に配列を単一の差分配列に変換します。 次に、現在どれだけの余剰があるかの実行バランスを維持しながら、左から右にスキャンします。

1. 実行変数 current_sum = 0 およびカウンタ セグメント = 0 を初期化します。実行合計は、現在のセグメント内の合計 (a − b) を追跡します。 
2. 配列をインデックス 1 から n まで繰り返し、a[i] − b[i] を加算して current_sum を更新します。 これにより、現在形成中のセグメントの純バランスが維持されます。 
3. 更新するたびに、current_sum が負でないかどうかを確認します。 そうであれば、このインデックスで現在のセグメントを閉じ、セグメントを 1 つインクリメントすることにします。次に、current_sum を 0 にリセットして、次のインデックスから新しいセグメントを開始します。 
4. すべての要素を処理した後、セグメントをまったく形成しなかった場合、つまりセグメントはゼロのままで、出力は -1 です。 それ以外の場合はセグメントを出力します。 

current_sum が負でなくなったらすぐにカットするという決定は、将来の柔軟性を最大化する貪欲な選択です。 これにより、以前のセグメントが有効なままできるだけ短くなり、追加のセグメントを形成するために使用できる要素がより多く残されます。 

### なぜ効果があるのか

 累計は、特定の時点でセグメントを終了する可能性を表します。 合計が負でなくなると、有効なセグメントが得られます。 このカットを遅らせると、より多くの要素が同じセグメントに蓄積されるだけであり、以前に有効なエンドポイントを形成していた可能性のあるインデックスを消費するため、将来の有効なセグメント境界の数を増やすことはできません。 したがって、貪欲な戦略では、可能なセグメントの数は常に維持または増加され、決して減ることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        current_sum = 0
        segments = 0
        
        for i in range(n):
            current_sum += a[i] - b[i]
            if current_sum >= 0:
                segments += 1
                current_sum = 0
        
        if segments == 0:
            print(-1)
        else:
            print(segments)

if __name__ == "__main__":
    solve()
```コードは貪欲な解釈に直接従います。 差分への変換は a[i] − b[i] としてインラインで実行され、余分なメモリを回避します。 重要な点は、セグメントの形成後に current_sum をリセットすることです。これにより、各セグメントが独立していることが保証されます。 

current_sum >= 0 という条件により、セグメントを閉じることができます。 ゼロサムセグメントも有効であるため、厳密には正になるのを待ちません。 

## 実用的な例

 配列が徐々に正の残高を蓄積していく単純なケースを考えてみましょう。 

入力:

 n = 5

 a = [2, 2, 2, 2, 2]

 b = [1, 1, 1, 1, 1]

 | 私 | a[i]-b[i] | 現在の合計 | セグメント |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 0 | 2 |
 | 3 | 1 | 1 | 3 |
 | 4 | 1 | 0 | 4 |
 | 5 | 1 | 1 | 5 |

 すべてのプレフィックスは負ではないため、すべての要素が独自の要素または最小セグメントの一部となり、最大のカット数が得られます。 

次に、よりバランスの取れたケースを考えてみましょう。 

入力:

 n = 4

 a = [1, 1, 1, 1]

 b = [2, 2, 0, 0]

 | 私 | a[i]-b[i] | 現在の合計 | セグメント |
 | --- | --- | --- | --- |
 | 1 | -1 | -1 | 0 |
 | 2 | -1 | -2 | 0 |
 | 3 | 1 | -1 | 0 |
 | 4 | 1 | 0 | 1 |

 最後にのみプレフィックスが有効になるため、セグメントは 1 つだけしか形成できません。 これは、アルゴリズムが実現可能性が達成されるまで切断を正しく遅らせていることを示しています。

 ## 特殊なケース

 完全に負の配列の差は、故障状態を明確に示します。 

入力:

 n = 3

 a = [1, 1, 1]

 b = [2, 2, 2]

 累計は -1、-2、-3 となり、回復することはありません。 セグメントを閉じることはできないため、セグメントはゼロのままで、-1 を出力します。 このアルゴリズムは、有効な非負の境界に達した場合にのみセグメントをカウントするため、誤ったセグメンテーションの生成を正しく回避します。 

差分がゼロの場合は、最大のセグメンテーションを示します。 

入力:

 n = 3

 a = [5, 5, 5]

 b = [5, 5, 5]

 各ステップでは current_sum がゼロに保たれるため、すべてのインデックスがセグメントを閉じます。 結果は 3 つのセグメントになり、ゼロが有効なものとして扱われ、貪欲なリセットが最適性を失わないことが確認されます。
