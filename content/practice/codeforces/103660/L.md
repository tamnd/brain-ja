 ## 解決策
 ## 問題の理解

 私たちには、下から上に一列に配置されたモンスターの塔が与えられます。 各フロアには一定の強さのモンスターが存在します。 プレイヤーはある程度の初期体力を持ってスタートします$x$。 どの時点でも、プレイヤーは最下層のみを見ることができます。$k$残りのフロアを探索し、その中から現在の強さを超えないモンスターを1体選ぶ。 そのようなモンスターが殺されると、プレイヤーはその力を獲得し、そのフロアは消滅し、すべての上位フロアが 1 つ下に移動します。 

タスクは最小の初期強度を決定することです$x$したがって、プレイヤーはこれらのルールに従って最終的にタワー内のすべてのモンスターを除去できるようになります。 

重要な点は、モンスターを除去するとタワーの構造が変わり、どのモンスターが「最下位」に入るのかということです。$k$」ウィンドウは動的です。プロセスは固定された順序ではなく、どのモンスターを削除するかによって異なります。 

制約により、最大で$2 \times 10^5$テスト ケース全体のモンスターの合計が大きいため、テスト ケースごとの線形計算よりも悪いソリューションは困難になります。 最低値を繰り返しスキャンする二次シミュレーション$k$床を削除するたびに、最大で$O(n^2)$最悪の場合の動作が遅くなります。$n$到達する$2 \times 10^5$。 

素朴な推論による微妙な失敗例は、現在のウィンドウ内で到達可能な最小のモンスターを常に取得する必要があると仮定することです。 これにより、プレイヤーは大きな利益を遅らせることになる可能性があります。 

たとえば、小さな塔を考えてみましょう。```
n = 3, k = 2
a = [5, 1, 10]
```利用可能な最小のモンスターを常に選択する場合、最初に 1 つを取得し、ゆっくりと強さを増加させる可能性がありますが、最適な戦略では、より早く 10 に到達するために、最初に 5 つを取る必要がある可能性があります。 順序制約により、貪欲なローカル選択が自明ではなくなります。 

もう 1 つの隠れた問題は、床を削除した後、到達可能なウィンドウに新しいモンスターが入ってくることを無視していることです。 最初のものを扱う解決策$k$静的セットとしては間違っています。 

## アプローチ

 ブルートフォースアプローチでは、プロセス全体がシミュレートされます。 候補の初期強度を試してみる$x$、現在のモンスターの配列を維持し、最も低いモンスターを繰り返しスキャンします。$k$倒せるモンスターを見つける要素。 削除するたびに、構造を変更して再スキャンする必要があります。$k$要素。 最悪の場合は実施させていただきます$n$撤去、それぞれの費用$O(k)$、につながる$O(nk)$に退化します。$O(n^2)$。 

操作のたびに状態が進化するため、これでは遅すぎますが、唯一の本当の困難は、現在どのモンスターが最も低いモンスターの中で利用可能であるかを追跡することです。$k$そして、現在の強さを考えると殺せる可能性があります。 

重要な点は、実際には動的構造を明示的にシミュレートする必要がないということです。 代わりに、固定の開始強度について、実現可能性の観点から考えることができます。$x$、各ステップで最初の要素の中から任意の要素を選択できるという制約の下で、すべての要素を消費する一連の削除が存在するかどうかを知りたいのです。$k$生き残った要素。 

重要な構造的洞察は、私たちが対話できる候補のセットは、それらの正確なアイデンティティではなく、すでに削除された要素の数によってのみ支配されるということです。 これは、貪欲な実現可能性チェックを示唆しています。つまり、到達可能な最小の未処理要素を常に考慮し、制約を維持しながら可能な限り最適な強度の増加をシミュレートします。 

実現可能性を効率的に決定するために、現在到達可能な要素に対する優先順位構造を使用し、最初の要素のスライディング フロンティアを維持できます。$k$生きているモンスター。 モンスターを取り除くと、新しいモンスターがウィンドウに入ります。 各ステップでは常に、倒せる最小のモンスターを選択します。より小さい有効なオプションが存在する場合、より大きなモンスターを選択しても将来の実現可能性が向上することはないからです。 柔軟性が低下するだけです。 

これにより、問題は単調な実現可能性チェックに変わります。$x$作品、それより大きいもの$x$も機能します。 したがって、二分探索を行うことができます。$x$。 

各チェックが実行されます$O(n \log n)$ヒープを使用する（または$O(n)$慎重な 2 点管理によって償却されます)、完全なソリューションが効率的になります。

 ## アルゴリズムのチュートリアル

 私たちは問題を決定問題として扱います: 初期強度が与えられた場合$x$、塔をクリアできるでしょうか？ 

1. 値を固定する$x$現在の最低値を表す構造体を初期化します$k$入手可能なモンスター。 また、ウィンドウに入ったモンスターの数を追跡するポインターも維持します。 
2.最初のを挿入します$k$モンスターを強さに基づいた最小構造に組み込む。 これは現在到達可能なすべてのモンスターを表します。 
3. モンスターがまだ残っている、または構造物に残っている間に、倒せるモンスターを選択することを繰り返し試みます。 構造内で利用可能な最小のモンスターが現在の強さを超える強さを持っている場合、有効な動きは存在せず、これは$x$失敗します。 
4. そうでない場合は、そのモンスターを除去し、その強さを現在の強さに加えて、削除済みとしてマークします。 1 つのモンスターを削除した後、ウィンドウに常に最下位のモンスターが含まれるように、次の目に見えないモンスターを構造物に押し込みます。$k$生きているモンスター。 
5. すべてのモンスターが除去されるまで続けます。 成功すると、最初の$x$で十分です。 
6. 二分探索を使用します。$x$、実現可能性は単調であるため、初期強度を増加しても利用可能な動きが減少することはありません。 

これが機能する理由は制約の構造にあります。 いつでも、唯一の制限は、最も低いものから選択できることです。$k$残りの要素。 ヒープはまさにそのセットを表します。 その中でも、早めに戦力を上げておくと今後の選択肢が広がるだけなので、倒せるモンスターの中で一番小さいものを選ぶのが無難です。 大型のモンスターを優先して、殺せる小型のモンスターをスキップする戦略は、以前は利用できなかった新しいオプションのロックを解除することはできません。 それは利益を得ることなくより多くの強度を消費するだけであるため、最適な戦略では常に実行可能な最小限の除去が優先されます。 

タワーをクリアする能力は初期強度において単調であるため、二分探索は正当化されます。 ある場合$x$有効な削除の完全なシーケンスを許可し、その後、$x' > x$同じシーケンスをたどることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def can(x, a, k):
    n = len(a)
    cur = x
    i = 0
    heap = []

    # initial window
    while i < n and i < k:
        heapq.heappush(heap, a[i])
        i += 1

    # process
    used = k
    while heap:
        # ensure we can take something
        if heap[0] > cur:
            return False

        val = heapq.heappop(heap)
        cur += val

        if i < n:
            heapq.heappush(heap, a[i])
            i += 1

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0, sum(a)
        ans = hi

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, a, k):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```の`can`関数は、固定開始強度の実現可能性をシミュレートします。 ヒープには常に次のものが含まれます$k$到達可能なモンスターを配列内の出現順に並べます。これは動的「最低位」に一致します。$k$これは、削除された要素が再挿入されることはなく、以前の要素が消えると新しい要素が入るためです。 

二分探索は、次の範囲で制限される回答範囲にわたって実行されます。$0$そして、すべてのモンスターの強さの合計です。これは、成長の可能性のわずかな上限であるためです。 

微妙な点は、スライディング ウィンドウを正しく維持することです。要素が削除された場合にのみ次の目に見えない要素をプッシュし、ヒープ サイズが現在到達可能なセグメントを反映するようにします。

 ## 特殊なケース

 まれなケースが発生するのは、$k = 1$。 この状況では、構造は現在の最上位のモンスターのみが利用可能な厳格なラインに退化します。 ヒープには常に 1 つの要素が含まれており、その要素が現在の強度を超えるとすぐに障害が発生するため、アルゴリズムはこれを自然に処理します。 入力の場合:```
n = 3, k = 1
a = [5, 1, 10], x = 5
```シミュレーションは段階的に進みます。最初に 5 が取得され、強度が 10 になり、次に 1 が取得され、次に 10 が取得されます。 初期値が小さいと、最初の比較ですぐに失敗します。 

もう 1 つのエッジケースは、すべてのモンスターが妥当な初期強度に比べてすでに小さい場合です。 で：```
n = 5, k = 3
a = [1, 1, 1, 1, 1]
```平$x = 1$成功すると、ヒープベースのプロセスは構造を再充填しながら継続的に排出します。 ヒープが常に次のデータを反映するという不変式$k$生きている要素により、モンスターがシフト中にスキップされたり失われたりすることはありません。 

3 番目のケースは、単一の非常に大きなモンスターが深く埋められている場合です。```
n = 4, k = 2
a = [1, 1, 100, 1]
```最初は 100 に到達できなくても、最初の 2 つの小さなモンスターを繰り返し消費すると、最終的にはアクティブ ウィンドウに含められるほど強度が増加します。 スライド挿入メカニズムにより、最終的には正しいタイミングでヒープに挿入されることが保証され、シミュレーションによって時期尚早に破棄されることはありません。
