 ## 解決策
 ## 問題の理解

 チャージされた時間に応じて出力が変わるダメージスキルが与えられています。 ダメージは直線的に増加しますが、充電時間がしきい値を超えると増加率が変化します$k$。 前または時$k$秒、各秒が貢献します$x$ダメージ。 後$k$、追加の秒数が貢献します$y$代わりにダメージを与える。 

各テスト ケースには、敵の健康値のリストも与えられます。 このスキルは一度だけ使用され、すべての敵に同じダメージを与えます。 目標は、最小の整数の充電時間を選択することです$t$すべての敵は同一のダメージを受け、最も弱い制約が最も強い敵となるため、結果として生じるダメージは少なくともすべての敵の最大体力となります。 

入力サイズは小さく、テスト ケースは最大 100 個で、各テストには最大 100 人の敵が含まれます。ヘルス値を除くすべてのパラメーターは 100 で制限され、最大値は 100 になります。$10^9$。 これにより、単純な方法で最大のヘルス値まで可能なすべての充電時間を試行するアプローチは即座に除外されます。 までのリニアスキャン$10^9$テストケースごとに実行すると遅すぎます。 

エッジケースにおける唯一の微妙な点は、損傷の区分的な定義から生じます。 もし$x < y$、その後さらに長く充電します$k$効率が向上するため、最適解がオーバーシュートする可能性があります$k$大幅。 もし$x \ge y$、その後充電します$k$は悪くなるか役に立たないため、最良の戦略は常に、最初のセグメントがターゲットに到達したらすぐに停止するか、せいぜいその時点で停止することです。$k$。 

単純な間違いは、単一の勾配を持つ単調な動作を想定したり、2 番目のセグメントを完全に無視したりすることです。 たとえば、次の場合$k = 2, x = 10, y = 1$、敵の体力は25で、$t = 3$与える$20 + 1 = 21$、ダメージは依然として増加しますが、はるかに遅いため、早期に停止するよりも悪いです。 正解するには、両方のフェーズを明示的に考慮する必要があります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての充電時間を試します。$t$1 から順に、それぞれのダメージ関数を計算します。$t$、すべての敵を倒すのに十分かどうかを確認します。 候補者ごとに$t$、計算ダメージは$O(1)$, したがって、テスト ケースあたりのコストは答えの値に比例します。 

問題は、答えが次のように大きくなる可能性があることです。$10^9$、敵の体力がその範囲までなので、$x, y$最悪のケースでは、テスト ケースごとに数十億のタイム ステップをシミュレートする必要があるかもしれませんが、これは実行不可能です。 

重要な観察は、ダメージ関数が単調であるということです。$t$。 最初は傾きを伴って直線的に増加します$x$、次に勾配を付けます$y$。 単調さのせいで 1 回に 1 回$t$十分な時間ですが、それ以上の時間でも十分です。 これにより、答えの二分探索が可能になります。 

固定の場合$t$、区分的公式を使用して一定時間でダメージを計算し、それを敵の最大体力と比較し、二分探索を使用して有効な最小値を見つけることができます。$t$。

 ## アルゴリズムのチュートリアル

 各テスト ケースを最小値を見つけるために縮小します。$t$ダメージ(t) ≧ 最大体力となるように。 

1.すべての敵の健康値を読み取り、計算します$H = \max a_i$。 すべての敵は同じダメージを受けるため、重要な値はこれだけです。 
2. 関数を定義する$f(t)$ダメージを計算するもの:

 もし$t \le k$、 戻る$t \cdot x$。 

それ以外の場合は戻る$k \cdot x + (t - k) \cdot y$。 

これは区分的課金ルールに直接一致します。 
3. 二分探索境界を設定します。 答えは少なくとも 0 で、最大でも次のような安全な上限です。$10^9$または$H + k$、スロープ 1 であっても、必要な時間は健康スケールを超えることはできないためです。 
4. 二分探索を実行します。$t$。 各中間点について$m$、計算する$f(m)$。 もし$f(m) \ge H$、 それから$m$十分な値なので、より小さい値を試してみます。 そうでなければ、もっと時間が必要です。 
5. 二分探索の後、最小値を出力します$t$条件を満たすものです。 

重要な考え方は、時間を段階的にシミュレーションすることは決してないということです。 閉形式のダメージ関数のみを評価します。 

### なぜ効果があるのか

 機能$f(t)$は減少していない$t$両方のセグメントの傾きが負ではないため$x$そして$y$。 渡ったら$k$、傾きは変化する可能性がありますが、負になることはありません。 これにより、単調な述語が保証されます。$t$すべての敵を倒すのに十分な時間であれば、それ以上の時間でも十分です。 二分探索が有効であるのは、まさにこの単調性が成り立つためであり、各ステップで探索空間を安全に半分にできることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def damage(t, k, x, y):
    if t <= k:
        return t * x
    return k * x + (t - k) * y

def solve():
    T = int(input())
    for _ in range(T):
        n, k, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        H = max(a)

        lo, hi = 0, 10**18

        while lo < hi:
            mid = (lo + hi) // 2
            if damage(mid, k, x, y) >= H:
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```機能`damage`問題で説明されているとおりに区分的線形動作を正確にエンコードします。 二分探索は時間の整数領域で動作し、十分な最小値が見つかるまで範囲を縮小します。 

実装の微妙な詳細は、上限の選択です。 次のような大きな定数を使用する$10^{18}$制約が与えられた場合に考えられる所要時間を余裕で超えるため、安全です。 もう 1 つの重要な点は、そのステップの後にすべての敵を個別に合計したり処理したりせず、最大体力のみを計算することです。
