 ## 解決策
 ## 問題の理解

 長さの 1 次元グリッドが与えられます。`n`、いくつかのセルには壁があり、他のセルは空です。 ハミドは 1 つの空のセルの上に立っていて、毎日 2 つのことが起こります。まずマニが現在ハミッドが占有していない空のセルに壁を置き、次にハミッドが方向 (左または右) を選択してその方向に最も近い壁に向かって移動し、それを破壊してそこで 1 日を終了します。 選択した方向に壁がない場合、ハミッドはすぐに逃げます。 目標は、マニが脱出を遅らせ、ハミッドができるだけ早く脱出するという、両方のプレーヤーが最適に行動した場合に、ハミッドがグリッドから脱出する必要がある最小日数を決定することです。 

入力により複数のテスト ケースが提供され、各テスト ケースにはグリッドのサイズ、Hamid の開始位置、壁と空のセルの初期レイアウトが含まれます。 出力は、各ケースの脱出までの日数である必要があります。 

とすれば`n`最大 200,000 と次の合計`n`すべてのテスト ケースにわたる値も 200,000 で制限されるため、テスト ケースごとにグリッドを線形に反復するソリューションは許容されます。 毎日、可能なすべての壁の配置をシミュレートするアプローチは、空のセルとの組み合わせで可能な移動の数が増加するため、非常に遅くなります。 明らかではないエッジケースは、ハミドがグリッドの端に近いとき、またはマニが脱出を阻止する重要な動きを 1 つしか持っていないときに発生します。 たとえば、グリッドが`.#..`ハミドはポジション 2 からスタートし、マニは片側をブロックできますが、ハミッドはすぐに反対側に逃げ、わずか 1 日かかりました。 不注意なシミュレーションでは、マニが両端を同時にブロックできると想定して、日数を過大にカウントする可能性があります。 

## アプローチ

 強引なアプローチでは、マニが構築できるあらゆる可能な壁と、ハミドが移動できるあらゆる方向をシミュレートすることになります。 私たちはハミッドの位置と壁を追跡し、ハミッドが逃げるまで毎日更新します。 この方法は原理的には正しいですが、マニが潜在的に`O(n)`Hamid には 2 つの移動オプションがあります。 と`n`最大 2·10^5 ですが、これは競技プログラミングの制約では実現不可能です。 

重要な洞察は、Hamid が各方向で最も近い壁のみを考慮しているということです。 マニの最適な戦略は、ハミッドが逃げられる距離を最大限に縮めるような方法で壁を配置することです。 逆に、ハミッドは常に最も近い逃げ道に向かって移動します。 これにより、問題は、Hamid の開始位置から現在空いているグリッドの最も近い端までの距離を計算することになります。 脱出までの日数は、最も近い脱出に到達するための空のセルの最小数に、途中でマニがハミッドに破壊を強制できる壁を加えたものです。 これにより、両方向で最も近い壁を見つけるための線形スキャン後のテスト ケースごとの定数時間計算のソリューションが簡素化されます。 

解決策は次のようになります。Hamid の開始位置を基準にして、左端に最も近い空のセルと右端に最も近い空のセルを見つけます。 逃げる距離は、ハミッドの左端の空きセルまでの距離と右端の空きセルまでの距離の最大値です。 また、ハミドが間違った方向を選択した場合、マニが毎日壁を設置し、実質的に距離が 1 つ増加する可能性があることも考慮する必要があります。 ハミッドにとっての最適な動きは、常に最も近いオープンサイドに向かい、総日数を最小限に抑えることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(n^2) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の処理を容易にするために、Hamid の開始位置を 1 ベースのインデックスから 0 ベースのインデックスに変換します。 
2. グリッド内の左端と右端の空のセルを特定します。 これらは避難境界を表します。 
3. Hamid の開始位置から、左側の最も近い空のセルと右側の最も近い空のセルまでの距離を計算します。 
4. 距離が短い方向を選択して、ハミドが脱出するのに必要な最小日数を決定します。 マニが壁を最適に配置すると、そのパスに複数の空のセルがある場合に限り、距離は 1 増加します。 
5. 各テスト ケースについて計算された日数を返します。 

機能する理由: 不変条件は、Hamid が常に最も近い脱出方向に最適に移動するということです。 マニは 1 日にせいぜい壁 1 枚分遅らせることができますが、ハミドは常に合計日数が最小になるパスを選択します。 両側の最も近い空のセルまでの距離を考慮することで、すべての動きをシミュレートすることなく、マニが強制できる最大の遅延を直接取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def hamid_escape(n, x, s):
    x -= 1  # Convert to 0-based index
    left_dist = right_dist = 0

    # Check distance to the left escape
    for i in range(x, -1, -1):
        if s[i] == '.':
            left_dist = x - i
            break

    # Check distance to the right escape
    for i in range(x, n):
        if s[i] == '.':
            right_dist = i - x
            break

    # The number of days is max distance Hamid must traverse to escape
    return max(left_dist, right_dist)

t = int(input())
results = []
for _ in range(t):
    n, x = map(int, input().split())
    s = input().strip()
    results.append(str(hamid_escape(n, x, s)))

print("\n".join(results))
```このコードは、Hamid の位置を 0 から始まるインデックスに変換します。 Hamid の位置から左右にスキャンして最も近い空のセルを見つけ、各方向の距離を計算します。 最終結果は 2 つの距離の最大値であり、マニの最適なブロックを説明します。

 ## 特殊なケース

 Hamid が左端または右端の空のセルの隣から開始する場合、アルゴリズムは距離 1 を正しく計算します。`.#.`Hamid を中心に、left_dist=1 および right_dist=1、結果は 1 日になります。 マニが片側しかブロックできない場合、アルゴリズムは`max(left_dist, right_dist)`Hamid が引き続き最小パスを選択するようにします。 このコードは、各壁の配置をシミュレートするのではなく、距離を考慮して最適な結果を取得します。これにより、単純なシミュレーションでは過剰になる可能性があるすべての特殊なケースが処理されます。
