 ## 解決策
 ## 問題の理解

 次の接続された無向グラフが与えられます。`n`家と`m`橋。 各橋は、川の北側の家 1 軒と南側の家 1 軒を接続する必要があります。 家は両側の直線に沿って配置する必要があり、直線で描いた場合は橋を渡ってはなりません。 家が別の側にある場合、または側の家の相対的な順序が異なる場合、2 つの配置は異なります。 

より簡単に言うと、問題はグラフを 2 つのグループに分割できるかどうか (各橋が一方のグループから他方のグループに家を接続しているかどうか) をチェックすることに帰着します (2 部チェック)。 グラフが 2 部構成の場合、配置の数は、北側と南側の交換を考慮して 2 を掛けた、各グループ内のハウスの順列の積になります。 

制約は厳しいです:`n`2×10^5 に達する可能性があり、すべての合計は`n`そして`m`テスト ケース全体の値は 2×10^5 によって制限されます。 これにより、テスト ケースごとに O(n + m) を超える複雑さのアルゴリズムが除外されます。 すべてのサイド割り当てを試す単純なアプローチは、次の点で指数関数的です。`n`そして実行不可能です。 

一般的なエッジ ケースは、ハウスの三角形 (3 つのノードが互いに接続されている) です。 このグラフは 2 部グラフではないため、答えはゼロでなければなりません。 接続されているすべてのグラフが分割できると想定する不注意な実装では、誤ってゼロ以外のカウントが与えられてしまいます。 

もう 1 つの微妙なエッジ ケースは、コンポーネントにハウスが 1 つしかない場合です。 どちらの側にも配置できますが、二重カウントを避けるために、両側の家の順列を慎重に計算する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての 2^n 辺の割り当てを列挙し、それぞれの妥当性をチェックします。 有効な各サイドの割り当てについて、非交差制約に注意しながら、各サイドの家の順列をカウントします。 これが機能するのは、有効な配置がグラフの 2 分割に対応し、各線に沿って住宅を順序付けするためです。 複雑さは O(2^n × n log n) であり、`n`20以上。 

重要な洞察は、1 つのグループのすべての家を片側に任意の順序で配置すると、非交差条件が自動的に満たされるということです。 したがって、問題は 2 つのステップに集約されます。まず、グラフが 2 部構成であるかどうかを確認します。 次に、各側の家の順列を数えます。2 つのグループのサイズの階乗を計算し、2 を掛けてどちらのグループが北に行くかを選択します。 

このアプローチはノードとエッジの数が線形であり、最大の入力を効率的に処理できます。 組み合わせ計算は、10^9 + 7 を法として実行する必要があります。最大 2×10^5 までの階乗を事前計算することで、高速な計算が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n × n log n) | O(n) | 遅すぎる |
 | 二部 + 階乗 | テスト ケースあたり O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 10^9 + 7 を法とする階乗を最大値まで事前計算します。`n`すべてのテストケースにわたって。 これにより、順列をカウントするための O(1) 階乗検索が可能になります。 
2. テスト ケースごとに、ブリッジ接続からグラフの隣接リストを作成します。 これにより、近隣への効率的な O(1) アクセスが提供されます。 
3. 各家の側面を格納する配列を初期化します。最初は設定されていません。 未訪問の家から深さ優先検索 (DFS) を開始し、接続された家に交互の側面を割り当てます。 
4. DFS 中に、近隣の家が現在の家と同じ側にすでに割り当てられている場合、グラフは 2 部構成ではありません。 この場合、このテスト ケースの答えを直ちにゼロに設定します。 
5. DFS 中に両側の家の数を数えます。 させて`a`北側の番号になり、`b`南側の番号です。 
6. コンポーネントを完全に訪問したら、配置数を次のように計算します。`2 × factorial(a) × factorial(b) % MOD`。 各側の順列の 2 つの階乗を乗算し、北と南の入れ替えを考慮して 2 を乗算します。 
7. 連結成分ごとにステップ 3 ～ 6 を繰り返し、すべての成分の配置を 10^9 + 7 を法として乗算します。 
8. テスト ケースの最終カウントを出力します。 

不変条件は、DFS の間、割り当てられたすべてのサイドが 2 部制約を尊重するということです。 すべてのエッジは反対側のノードを接続します。 順列カウントでは各辺内のすべての可能な順序が考慮されるため、有効な非交差配置はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

MOD = 10**9 + 7

# Precompute factorials
N = 2 * 10**5 + 5
fact = [1] * N
for i in range(1, N):
    fact[i] = fact[i - 1] * i % MOD

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)
        
        side = [-1] * n
        ans = 1
        valid = True
        
        def dfs(u, color):
            nonlocal a, b, valid
            side[u] = color
            if color == 0:
                a += 1
            else:
                b += 1
            for v in adj[u]:
                if side[v] == -1:
                    dfs(v, 1 - color)
                elif side[v] == color:
                    valid = False
        
        for i in range(n):
            if side[i] == -1:
                a = b = 0
                dfs(i, 0)
                if not valid:
                    ans = 0
                    break
                ans = ans * fact[a] % MOD
                ans = ans * fact[b] % MOD
                ans = ans * 2 % MOD
        
        print(ans)
        
solve()
```コードはまず階乗を計算して、高速な順列カウントを可能にします。 隣接リストは便宜上、0 から始まるインデックスを使用して構築されています。 DFS は、各側の家を数えて、交互の側を割り当てます。 競合が発生した場合、`valid`は False になり、答えはすぐにゼロになります。 最終的なカウントは、順列の場合は階乗を乗算し、サイド スワップの場合は係数 2 を乗算します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | DFS は各ノードとエッジを 1 回走査し、階乗事前計算は O(N) です。 |
 | スペース | O(n + m) | 隣接リストにはエッジが格納され、サイド配列には色が格納されます。 |

 制約が与えられると、すべてのテスト ケースにわたる n と m の合計は ≤ 2×10^5 になります。 DFS は直線的な時間で実行され、ソリューションが 2 秒の制限内に収まるようにします。
