 ## 問題の理解

 システム内の各ショップには、ベースライン需要、価格に対する需要の感度、ユニットあたりの生産コストという 3 つのパラメータがあります。 販売価格を設定する場合$p$、単一の店舗での需要は、価格が上昇するにつれて減少する一次関数になります。 1店舗の利益は、販売価格と原価の差である1個あたりの利益に、販売個数を乗じて求められます。 

単一のショップの場合、価格の関数としての利益は次の二次式で表されます。$p$。 重要な観察は、連続するセグメントにわたって複数の店舗を集計すると、それらの需要とコストが単純に合計されるため、範囲にわたる総利益は依然として次の単一の二次関数であるということです。$p$、集計された係数のみを使用します。 

タスクは、可能な限り最高の均一価格を求める複数のクエリに答えることです。$p$(上キャップ付き$m$) 店舗の特定のセグメントの総利益を最大化します。 

入力サイズは、最大約$10^5$ショップや問い合わせなど。 これにより、クエリごとに答えを最初から再計算することが直ちに除外されます。$10^{10}$最悪の場合の運用。 唯一の実行可能なソリューションは、各クエリが定数時間または対数時間で応答できるようにデータを前処理する必要があります。 

計算された最適価格が許容範囲外にある場合、微妙な問題が発生します。 たとえば、二次方程式がより大きな価格を示唆する場合、$m$、その場合、その値を使用すると、実行不可能な市場条件に対応することになります。 別のエッジケースは、ある範囲内のすべての需要の傾きがゼロである場合に発生します。これは、価格が需要に影響を与えないことを意味します。 その状況では、二次方程式が縮退し、通常の頂点公式が崩れます。 

## アプローチ

 クエリ範囲を固定すると$[l, r]$、プロセスを直接シミュレートできます。多くの候補価格を試してください。$p$、各店舗の需要を計算し、利益を合計し、最大値を取得します。 利益関数は価格ごとに明確に定義されているため、これは正しいです。 ただし、各評価では範囲内のすべてのショップを反復処理する必要があり、複数の価格をサンプリングした場合でも、$O(n)$クエリごとのコストは最小限です。 クエリが多いと、これでは遅くなりすぎます。 

重要な構造的洞察は、固定セグメントにわたる利益関数は常に次の 2 次多項式であるということです。$p$。 関数を繰り返し評価する代わりに、クエリごとに関数の係数を 1 回計算できます。 さらに良いことに、係数は範囲にわたる単なる合計であるため、プレフィックス合計を使用すると定数時間で係数を取得できます。

 ## アルゴリズムのチュートリアル

 セグメント全体の利益表現を書き換えます$[l, r]$標準二次形式に変換$p$。 これは、ショップごとの寄与を拡大し、係数をグループ化することによって行われます。$p^2$、$p$、および定数項。 

任意の範囲にわたって 3 つの集計値を定義します。 

1. コンピューティング$A = \sum_{i=l}^{r} b_i$。 これは、価格に対する需要の総合的な感応度です。 
2. コンピューティング$B = \sum_{i=l}^{r} (a_i + b_i c_i)$。 これにより、すべての線形寄与が収集されます。$p$。 
3. コンピューティング$C = \sum_{i=l}^{r} a_i c_i$。 これにより、一定の損失項が捕捉されます。 

これらにより、合計利益は二次関数になります。$$P(p) = -A p^2 + B p - C$$次に、各クエリを処理します。 

1. プレフィックスの合計を構築します。$a_i$、$b_i$、$a_i c_i$、 そして$b_i c_i$。 

これによりコンピューティングが可能になります$A$、$B$、 そして$C$任意の範囲に対して一定時間で。 
2. お問い合わせの場合$[l, r]$、 抽出する$A$、$B$、 そして$C$プレフィックスの違いを使用します。 

このステップにより、セグメントの完全スキャンが置き換えられます。 
3. もし$A = 0$、二次関数は一次関数に崩壊します。 その場合、価格を上げても凹みは生じないため、実行可能な最適な解決策は常に境界にあります。$p = m$。 
4. それ以外の場合は、放物線の頂点を計算します。$$p^* = \frac{B}{2A}$$これは実数値マキシマイザーです。 
5. 価格は整数でなければならないため、利益を次のように評価します。$\lfloor p^* \rfloor$そして$\lceil p^* \rceil$なぜなら、凹二次方程式の場合、整数の最大値は頂点に最も近い位置になければならないからです。 
6. また、次のように評価します。$p = m$頂点が許可された領域を超える可能性があるためです。 
7. これらの候補の中で最大の利益を返します。 

### なぜ効果があるのか

 固定セグメント上では、利益関数は次の凹二次関数になります。$p$いつでも$A > 0$。 凹二次関数には単一のグローバル最大値があるため、連続最適値がその頂点にあります。 整数に制限すると、検索対象が頂点の周囲で最も近い 2 つの整数に限定されます。 実行可能ドメインがさらに切り詰められるため、$m$、境界もチェックする必要があります。 プレフィックス合計により、二次係数がクエリごとに正確に計算され、すべてのセグメントにわたって正確さが維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q, m = map(int, input().split())
    a = [0] * (n + 1)
    b = [0] * (n + 1)
    ac = [0] * (n + 1)
    bc = [0] * (n + 1)

    for i in range(1, n + 1):
        ai, bi, ci = map(int, input().split())
        a[i] = ai
        b[i] = bi
        ac[i] = ai * ci
        bc[i] = bi * ci

    pa = [0] * (n + 1)
    pb = [0] * (n + 1)
    pac = [0] * (n + 1)
    pbc = [0] * (n + 1)

    for i in range(1, n + 1):
        pa[i] = pa[i - 1] + a[i]
        pb[i] = pb[i - 1] + b[i]
        pac[i] = pac[i - 1] + ac[i]
        pbc[i] = pbc[i - 1] + bc[i]

    def get(l, r):
        A = pb[r] - pb[l - 1]
        B = (pa[r] - pa[l - 1]) + (pbc[r] - pbc[l - 1])
        C = pac[r] - pac[l - 1]
        return A, B, C

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        A, B, C = get(l, r)

        def profit(p):
            return -A * p * p + B * p - C

        if A == 0:
            out.append(str(profit(m)))
            continue

        p_star = B / (2 * A)
        candidates = set()

        for x in [int(p_star), int(p_star) + 1]:
            if 0 <= x <= m:
                candidates.add(x)
        candidates.add(m)

        best = -10**30
        for p in candidates:
            best = max(best, profit(p))

        out.append(str(best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では 4 つのプレフィックス配列が構築されるため、各クエリは一定時間で集計された係数を抽出できます。 機能`get(l, r)`再構築する$A$、$B$、 そして$C$数学モデルで導き出されたとおりです。 

の`profit(p)`関数は二次式を直接評価します。 これにより、ショップごとの寄与の再計算が回避され、すべての演算が整数ベースのままとなるため、数値の安定性が確保されます。 

候補セットには頂点の両側と上限が含まれます$m$。 頂点を整数にキャストし、床と天井の両方をチェックすることで、離散最大値が失われないことが保証されます。 

特別な場合`A == 0`ゼロ除算を回避し、縮退した線形ケースを安全に処理します。 

## 実用的な例

 3 つのショップと 1 つのクエリを持つ小規模なインスタンスを考えてみましょう。 

| 私 | あ_い | b_i | c_i |
 | --- | --- | --- | --- |
 | 1 | 4 | 1 | 2 |
 | 2 | 2 | 2 | 1 |
 | 3 | 3 | 1 | 3 |

 クエリ:$l = 1, r = 3, m = 10$接頭辞から派生した値を計算します。 

| ステップ | A = Σb | B = Σ(a + bc) | C = Σ(ac) |
 | --- | --- | --- | --- |
 | 1-3 | 1+2+1=4 | (4+2)+(2+2)+(3+3)=16 | 4・2+2・1+3・3=17 |

 利益関数は次のようになります。$P(p) = -4p^2 + 16p - 17$頂点は次のとおりです。$p^* = 16 / (2·4) = 2$私たちは以下を評価します:

 | p | 利益 |
 | --- | --- |
 | 1 | -4 + 16 - 17 = -5 |
 | 2 | -16 + 32 - 17 = -1 |
 | 3 | -36 + 48 - 17 = -5 |
 | 10 | -400 + 160 - 17 = -257 |

 最大値は次のとおりです$p = 2$。 

このトレースは、頂点が最適価格を正確に識別していること、および価格が高くなるとすぐに利益が低下するため、境界チェックが必要であることを示しています。 

2 番目のケースは、境界の優位性を示しています。 

しましょう$A = 0$、$B = 5$、$C = 3$、 そして$m = 4$。 

利益は線形になります:$P(p) = 5p - 3$。 

| p | 利益 |
 | --- | --- |
 | 0 | -3 |
 | 4 | 17 |

 アルゴリズムが直接選択します$p = m$、制約の下で正しい最大値と一致します。

 ## 特殊なケース

 いつすべて$b_i = 0$セグメントでは、二次関数は一次関数に崩壊します。 アルゴリズムはこれを次のように検出します。$A = 0$そしてすぐに評価します$p = m$。 たとえば、すべてのショップに価格に関係なく需要がある場合、価格を上げても単位あたりの利益が向上するだけなので、境界は最適になります。
