 ## 解決策
 ## 問題の理解

 私たちにはチケットのコレクションが与えられ、それぞれに数値の価格が付けられています。 これらの価格から、ペアチケットの違いに興味があります。 タスクは、これらの差異をグローバルに推論するだけでなく、それらを 2 つの段階で使用することです。まず、ランク付けされた意味で特定の「ターゲット」差異を特定し、次に、二次ルールの下で最適でありながらこの差異を達成する実際のチケットのペアを構築します。 

重要な考え方は、問題内のすべての意味のある情報は、チケット価格間のペアごとの絶対差から得られるということです。 価格を並べ替えると、注目するすべての差は並べ替えられた配列内の 2 つのインデックス間の距離になり、順序付けされていないペアを明示的に考慮する必要がなくなります。 

制約構造は、チケットの数が十分に大きいため、すべてのペアを列挙することが不可能であることを意味します。 単純なペアの列挙に​​は O(n^2) の演算が必要ですが、約 10^10 の比較が必要になるため、約 10^5 要素ですでに法外な演算が必要になります。 そのため、すぐにソートされた順序と単調性を利用する方法に向かうことになります。 

実際には重要な微妙なエッジケースが 2 つあります。 

1 つ目は、複数のペアが同じ違いを共有する場合です。 たとえば、価格の場合`[1, 2, 3, 4]`、 違い`1`ペアで発生します`(1,2)`、`(2,3)`、 そして`(3,4)`。 k 番目の最小の差を求める問題の場合は、個別の値だけでなく、すべての重複を正しく数えることを確認する必要があります。 

2 つ目は、固定差の下での最適なペアが一意でない場合です。 価格が`[1, 10, 11, 20]`そして、差分制約を修正します`10`。 多くのペアはそれを満たしますが、この問題では、何らかの順序で辞書編集的に最良または最小のペアを選択する必要がある場合があります。 不注意な 2 ポインター スイープは、最適な候補を明示的に追跡しない場合、早期に停止したり、最適ではない有効なペアを選択したりする可能性があります。 

これらの観察は、問題の構造が基本的に、差異に対する単調な制約の下でペアを数えて選択することに関するものであることをすでに示唆しています。 

## アプローチ

 直接的なアプローチではすべてのペアを考慮します`(i, j)`そして計算します`|a[i] - a[j]|`。 これらの値を並べ替えると、k 番目に小さい差を選択し、その後再度スキャンしてその値を達成するペアを見つけることができます。 

この総当りの正確さは、差分の完全なマルチセットを明示的に構築するため、簡単です。 ただし、コストはチケット数の 2 次になります。 n を最大 100,000 とすると、これはおよそ 50 億ペアとなり、実現可能な時間制限をはるかに超えます。 

重要な構造的洞察は、配列をソートした後、述語「差 ≤ d」が非常に強い意味で単調になるということです。 ペアなら`(i, j)`満足する`a[j] - a[i] ≤ d`、その後増加します`j`または減少`i`予測可能な方法で実現可能性を維持します。 これにより、線形時間で 2 ポインター スイープを使用して有効なペアをカウントできるようになります。 

差 ≤ d を持つペアの数を数えることができたら、d を二分探索して、少なくとも k 個のペアが条件を満たす最小値を見つけることができます。 これにより、問題は二次列挙から O(n log V) に変換されます。ここで、V は差の値の範囲です。 

正しい差のしきい値を特定した後、同じ 2 ポインターのアイデアを再利用して実際のペアを抽出します。 数を数える代わりに、二次選択ルールに従って、条件を満たす最良のペアをスキャンして追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log n) または O(n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n log V) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 まず配列を並べ替えて、差異が単純なインデックス ギャップになるようにします。 これにより、問題はインデックスに対する単調関数の処理に変換されます。 

次に関数を定義します`count(d)`を満たすペアの数を返します`a[j] - a[i] ≤ d`。 これは 2 つのポインターを使用して計算されます。`i`、私たちは前進します`j`制約を維持しながら可能な限り。 あらゆるポジション`i`貢献する`j - i - 1`有効なペア。 これは機能します。`a[j] - a[i] > d`、増加しています`j`さらに差が広がるだけです。 

次に二分探索をします`d`。 からの検索範囲を維持します`0`に`max(a) - min(a)`。 各中間点について、次のように計算します。`count(mid)`。 カウントが少なくとも k の場合は、より小さい値を試します。 それ以外の場合は、しきい値を増やします。 最終結果は最小になります`d`少なくとも k 個のペアが存在するようにします。 

この閾値を取得した後`d*`、それに対応する有効なペアを見つける必要があります。 再び 2 ポインター スキャンを使用しますが、今度は候補ペアを収集します。`(i, j)`そのような`a[j] - a[i] ≤ d*`。 必要な順序に応じて、問題のタイブレーク ルールに従って最適なペアを追跡し、通常は 2 番目のインデックスを最小化するか、二次プロパティを最大化します。 

なぜ機能するのかは述語の単調性に由来する`a[j] - a[i] ≤ d`。 固定の場合`i`、 有効`j`ソートされた配列内で連続したプレフィックスを形成します。 これにより、カウントが線形になり、二分探索が確実に行われるようになります。`d`増加しているため有効です`d`有効なペアのセットを増やすだけです。 修正後の選択の正しさ`d*`すべての許容可能なペアは、2 ポインター スキャンが完全に探索する明確に定義された実行可能領域内にあるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(a, d):
    n = len(a)
    j = 0
    total = 0
    for i in range(n):
        if j < i + 1:
            j = i + 1
        while j < n and a[j] - a[i] <= d:
            j += 1
        total += j - i - 1
    return total

def best_pair_with_diff(a, d):
    n = len(a)
    best = None
    for i in range(n):
        j = i + 1
        while j < n and a[j] - a[i] <= d:
            if best is None or (a[i], a[j]) < best:
                best = (a[i], a[j])
            j += 1
    return best

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    lo, hi = 0, a[-1] - a[0]

    while lo < hi:
        mid = (lo + hi) // 2
        if count_pairs(a, mid) >= k:
            hi = mid
        else:
            lo = mid + 1

    d = lo
    ans = best_pair_with_diff(a, d)
    print(ans[0], ans[1])

if __name__ == "__main__":
    solve()
```コードは、すべての有効な違いが方向性を持つように配列を並べ替えることから始まります。 の`count_pairs`関数は 2 ポインター スイープを実装します。`i`、ポインタ`j`前進するだけなので、全体的な複雑さは線形のままです。 

二分探索では、この関数を単調な述語として使用します。 重要な詳細は、`count_pairs(d)`いつでも減らない`d`増加するため、バイナリ検索の正確さが保証されます。 

目標差を修正した上で、`best_pair_with_diff`再度スキャンします。 入れ子になったループは全体として線形のままです。`j`それぞれの中で前進するだけです`i`有効な差異のセグメント。 比較`(a[i], a[j]) < best`辞書編集的に最小の有効なペアが常に選択されるように、決定的なタイブレーク ルールを強制します。 

## 実用的な例

 検討してください`n = 4`、`k = 3`、`a = [1, 2, 3, 4]`。 

二分探索ではカウントが評価されます。 

| ミッド(d) | ペア ≤ d |
 | --- | --- |
 | 0 | 0 |
 | 1 | 3 |
 | 2 | 5 |
 | 3 | 6 |

 に収束します`d = 1`。 

有効なペアは次のようになります。`(1,2)`、`(2,3)`、`(3,4)`。 辞書編集的に最小のものは、`(1,2)`。 

このトレースは、個別の値ではなくすべてのペアがカウントされるため、差異の重複が正しく処理されていることを示しています。 

ここで考えてみましょう`a = [1, 10, 11, 20]`、`k = 2`。 

| d | ペア ≤ d |
 | --- | --- |
 | 0 | 0 |
 | 5 | 1 |
 | 10 | 4 |

 それで`d = 10`。 有効なペアは次のとおりです。`(1,10)`、`(1,11)`、`(10,11)`、`(11,20)`注文に応じて。 スキャンにより、それらの中から辞書編集的に最小のものを確実に選択します。`(1,10)`。 

これは、選択フェーズが二分探索フェーズでペアがどのようにカウントされたかに依存しないことを確認します。

 ## 特殊なケース

 次のような等しい要素の場合`[5, 5, 5, 5]`、すべてのペアの差はゼロです。 二分探索は次のように折りたたまれます。`d = 0`、スキャンでは引き続き正しく識別されます`(5, 5)`最適なペアとして。 2 ポインター構造体はこれを自然に処理します。`a[j] - a[i] <= 0`すべての有効なペアに当てはまります。 

次のような密集したシーケンスの場合`[1, 2, 3, 4]`, 多くのペアが同じ違いを共有します。 このアルゴリズムでは、差異を重複排除するのではなく、それらすべてをカウントするため、k 番目のペアのロジックは正しいままになります。 

次のような間隔の広い値の場合、`[1, 100, 1000]`、有効な領域はまばらです。 カウントがしきい値間で急激に変化するため、バイナリ検索は引き続き正しく収束し、スキャンでは選択した差で実行可能なペアのみが正しく分離されます。
