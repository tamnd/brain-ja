 ## 問題の理解

 無向の単純なグラフが与えられます。 各頂点はネットワーク内のノードを表し、各エッジは 2 つのノード間の相互接続を表します。 タスクは、このグラフ内にいくつの異なる三角形が存在するかを数えることです。ここで、三角形は頂点の 3 つです。$(i, j, k)$3 つのエッジすべてが$(i, j), (j, k), (k, i)$が存在します。 

入力は、頂点とエッジの数とそれに続くエッジ リストによってグラフを記述します。 各エッジには順序がありません。つまり、方向を強制しません。 出力は、三角形の総数を表す単一の整数です。 

重要な制約の意味は、グラフが十分に大きくなり、頂点の数が 3 次のものはすぐに使用できなくなり、密な場合には 2 次隣接性チェックですら遅すぎる可能性があることです。 構造を持たずに近隣リストを繰り返しスキャンするソリューションでは、同じ関係を何度も再検討する危険があります。 

重複排除を行わずに単純な隣接交差を使用すると、微妙な障害が発生するケースが発生します。 たとえば、ノードの隣接するノードのすべてのペアを反復処理して隣接性をチェックすることによって三角形をカウントしようとすると、走査順序に応じて同じ三角形が複数回カウントされる可能性があります。 

4 頂点の完全なグラフのような入力では、この問題がすでに明らかになります。 三角形は 4 つありますが、隣接性に対する単純なトリプル ループでは、慎重に正規化しない限り、各三角形を簡単に 6 回数えることができます。 

もう 1 つのエッジ ケースは、スター グラフに葉の間に追加のエッジがいくつか加えられているなど、歪んだ度数分布です。 単純な「すべての隣接ペアをチェックする」アプローチは、中心ノードが大規模なペアごとの反復を強制するため、ひどく劣化します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。頂点のトリプルをすべて列挙します。$i, j, k$、3 つのエッジがすべて存在するかどうかを確認します。 すべての三角形は 3 つの頂点によって一意に決定されるため、これは正しいです。 ただし、これには次のことが必要です$O(n^3)$各チェックには隣接関係の検索が含まれる場合があるため、中程度のサイズのグラフであっても完全に実行不可能になります。 

もう少し良いアイデアは、頂点を固定することです。$i$次に、すべての近傍を反復処理します。$j$、そしてすべての近隣地域に渡って$k$の$j$かどうかを確認します$k$に接続されています$i$。 これにより、検索スペースが長さ 2 のウォークに縮小されます。 これにより、無関係な頂点のスキャンが回避されますが、特に高次の頂点が存在する場合には、作業が頻繁に繰り返されます。 最悪の場合、こうなります$O(nm)$が鈍くなるにもほどがあります。 

重要な改善点は、各無向エッジが、より低い「ランク」頂点からより高い「ランク」頂点への有向エッジになるように、エッジに方向を課すことです。 自然なランクは程度です。 各エッジを低次のエンドポイントから高次のエンドポイントに導き、インデックスによって任意に結合を切断します。 

この方向により、各ノードが限られた数の発信エッジのみを持つことが保証されます。 ノードに発信エッジが多すぎる場合、より高次のエンドポイントがそれらのエッジを吸収しなければならないという事実と矛盾し、グローバルに持続できない不均衡を強いることになります。 より具体的には、これにより、前方隣接ノードの数が約$O(\sqrt{m})$。 

エッジの方向が決まると、この順序に従ってすべての三角形に一意の「最小」頂点があり、出力エッジを使用してその頂点から始まる三角形のみを列挙します。 これにより、重複したカウントが防止され、冗長な探索が大幅に削減されます。

 ## アルゴリズムのチュートリアル

 次数に基づいて頂点の順序を構築し、すべてのエッジを小さい次数から大きい次数に向けます (頂点インデックスによって結合を解除します)。 その後は、「前方エッジ」のみをトラバースします。 

1. すべての頂点の次数を計算します。 これにより、接続性の観点から各ノードがどの程度「重い」かがわかります。 
2. ルール「頂点」を使用して頂点を暗黙的に並べ替えまたは比較します。$u$よりも小さいです$v$もし$deg(u) < deg(v)$、または度が等しい場合、および$u < v$。 これにより、曖昧さを回避する一貫した順序が定義されます。 
3. 隣接リストを構築しますが、有向エッジのみを保持します。$u$に$v$もし$u < v$この順序の下で。 このステップにより、各無向エッジが 1 つの有向エッジに縮小されます。 
4. 各頂点について$u$、すべての前方隣接要素を反復処理します。$v$。 そういったそれぞれに対して$v$、すべての前方隣接要素を反復処理します。$w$の$v$、どうかを確認してください。$w$の前方隣人でもあります$u$。 もしそうであれば、三角形を見つけたことになります$u \to v \to w$。 
5. ハッシュ セットまたは隣接リストごとのブール マーキングを使用して、メンバーシップをテストします。$O(1)$平均的な時間。 

これが機能する理由は、すべての三角形が次数の順序に従って固有の最小頂点を持っているためです。 その頂点は、その前方エッジを介して三角形を列挙しようとする唯一の頂点になります。 方向によって後方へのトラバースが妨げられるため、他の 2 つの頂点はそれを再列挙できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n)]
    deg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        deg[u] += 1
        deg[v] += 1

    order = list(range(n))
    order.sort(key=lambda x: (deg[x], x))
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    forward = [[] for _ in range(n)]

    for u, v in edges:
        if pos[u] < pos[v]:
            forward[u].append(v)
        else:
            forward[v].append(u)

    # build fast lookup
    mark = [0] * n
    timer = 1

    ans = 0

    for u in range(n):
        for v in forward[u]:
            mark[v] = timer

        for v in forward[u]:
            for w in forward[v]:
                if mark[w] == timer:
                    ans += 1

        for v in forward[u]:
            mark[v] = 0
        timer += 1

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、グローバルな順序を定義するために使用される次数を計算することから始まります。 の`pos`array converts each vertex into its rank, allowing constant-time comparison.

 の`forward`隣接リストは指向性グラフをエンコードします。 各無向エッジは、下位ランクのエンドポイントから上位ランクのエンドポイントへの方向に 1 回だけ保存されるため、三角形の重複列挙が防止されます。 

三角形のカウントでは、セットの代わりにマーキング配列を使用します。 固定ノードの場合$u$、そのすべての前方隣接がマークされます。 次に、各前方隣接者に対して$v$、その前方隣接をスキャンします$w$かどうかをテストします$w$とマークされていました。 これにより、ハッシュ ルックアップが配列インデックス付けに置き換えられ、より高速で安定したものになります。 

一時的な`timer`遅すぎる各ノードの配列全体のクリアを回避します。

 ## 特殊なケース

 完全なグラフは、二重カウントの可能性が最も高いケースです。 方向を指定しない場合、すべての三角形は走査ルートに応じて複数回出現します。 有向構造により、最小ランクの頂点のみが各三角形を列挙することが保証されます。 

葉の間に追加のエッジがあるスター グラフも、単純な隣接ペアのカウントを複数の三角形が存在すると誤解させる可能性があります。 実際には、3 番目のエッジが完了しない限り、長さ 3 の閉じたサイクルはまだ存在しません。 最後のエッジ チェックがなければ 2 ホップの到達可能性だけでは十分ではないため、マーキング アプローチでは、完全に接続されたトリプルのみがカウントされることが保証されます。 

孤立したノードを持つ疎なグラフでは、前方リストが空であり、三角形の列挙に参加しないため、問題は発生しません。
