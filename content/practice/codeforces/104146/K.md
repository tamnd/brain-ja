 ## 解決策
 ## 問題の理解

 の列が与えられます$n$順列を表す個別の整数。 それぞれの値はランキングであり、目標は、キューを昇順に変換して、最小のランクが先頭になり、最大のランクが最後になるようにすることです。 

任意の位置を直接交換したり、標準の並べ替えを実行したりすることはできません。 代わりに、キューの先頭にのみ影響する 2 つの操作に制限されます。 1 回の操作で最初の 2 つの要素が交換されます。 もう 1 つの操作では、前の要素を取得して後ろに移動することでキューを回転します。 

出力は、最終的にソートされたキューではなく、最初の並べ替えをソート順に変換する一連の操作です。 シーケンスの長さは最大でも$10^5$、そのようなシーケンスが存在することが保証されています。 

の制約$n$これは、$O(n^2)$スタイルの構築が期待されますが、構造の変更ごとに発行される操作の数を注意深く制御する必要があります。 スワップごとに完全な回転を使用して任意の位置を繰り返し「修正」する単純なシミュレーションは、簡単に劣化してしまう可能性があります。$O(n^3)$運用中でも制限を超えるリスクがある$n = 250$。 

素朴な推論による微妙な失敗例は、要素を回転して所定の位置に配置し、交換し、元に戻すことによって一般的な隣接する交換をシミュレートしようとした場合に発生します。 たとえば、250 要素の配列の位置 10 と 11 を繰り返し交換しようとすると、前方に 10 回転し、その後、後方に最大 240 回転する必要があり、これを何度も繰り返すと、反転がすぐに爆発的に限界を超えます。$10^5$操作。 

重要な問題は、回転によって配列の参照フレームが変更されるため、作業を元に戻さないようにプロセスを慎重に設計しない限り、「位置」が安定しないことです。 

## アプローチ

 強引なアイデアは、バブル ソートを直接シミュレートすることです。配列を繰り返しスキャンし、隣接する 2 つの要素の順序が狂うたびに、回転を使用してそれらを前面に持ってきて、交換操作を適用し、次に回転して元の構造を復元します。 これは、任意の隣接スワップをシミュレートし、バブル ソートは十分なスワップ後のソートを保証するため、論理的には正しいです。 

問題は運営コストだ。 一般的な位置での各隣接スワップ$i$必要$O(n)$ローテーションしてペアを前に出して、別のペアを導きます$O(n)$回転させて構造を復元します。 と$O(n^2)$バブルソートで交換すると、これは次のようになります$O(n^3)$操作は大きすぎます$n = 250$。 

これを改善する主な観察点は、スワップ後に元の回転状態を実際に復元する必要がまったくないことです。 キュー自体が状態であり、ローテーションは元に戻さなければならないものではなく、アルゴリズムの一部です。 配列が継続的に進化していることを受け入れたら、前面の所定の位置でスワップを実行し、回転を自然に蓄積させることができます。 これにより、コストのかかる「元に戻す」フェーズが完全に削除されます。 

固定座標系を維持しようとするのをやめると、構造を作業用のデクとして扱うことができます。 標準的な方向を保持しようとせずに、いつでも要素を見つけて前面に回転し、局所的な修正を実行できます。 

これにより、要素配置ごとに最大でも線形回転数を実行し、冗長な反転を回避する建設的なシミュレーション戦略が実現します。

 ## アルゴリズムのチュートリアル

 キューを直接シミュレートし、並べ替えられた順序を徐々に構築します。 重要なアイデアは、残っている最大の要素を繰り返し抽出し、前方の回転のみを使用して後方の最終位置に押し込むことです。 

運用中に進化する現在のアレイを維持します。 

1. 完全な順列をアクティブなキューとして開始します。 
2. 現在の残りサイズについて$m$、最初の値の中で最大の値の位置を見つけます。$m$要素。 この要素は、最終的にその位置に配置されるべき要素です。$m$。 
3. オペレーションを使用してキューをローテーションします$P$その最大要素が前面に到達するまで。 回転するたびに 1 つの要素が前から後ろに移動します。$k$元の位置にあった要素を回転します$k$がフロントになります。 
4. ターゲットの最大値が前面に来たら、追加の回転ロジックを 1 つ実行して、構造全体に回転を適用することで、ターゲットの最大値をアクティブ領域の背面に押し込みます。 最大値が正しい最終的な相対位置にあるため、概念的にはこれをアクティブ ウィンドウを端から縮小するものとして扱います。 
5. 縮小されたアクティブ領域内の次に大きい要素に対してこのプロセスを繰り返します。 

明らかではない部分は、ローテーションがキュー全体に影響を与えるにもかかわらず、アクティブな領域の縮小が機能する理由です。 それぞれの最大値が前面に表示された後は、ソートされていない残りの要素との相対的な順序のみを考慮します。 継続的な回転によってそれらを通過すると、事実上作業セグメントの終わりに落ち着き、その後の検索では無視されます。 

### なぜ効果があるのか

 アルゴリズムは常に、すでに「処理」されたすべての要素がアクティブ セグメント内にまだあるすべての要素よりも大きいという特性を保持し、選択のために再検討されることのないキューのサフィックスに残ります。 各反復では、アクティブなセグメントから最大値を 1 つだけ削除し、回転を通じて残りのすべての要素の後ろに配置します。 その後の操作では、処理されたサフィックスからアクティブな選択範囲に要素が戻されることはないため、サフィックスはそれ自体に対して正しく順序付けされたままであり、将来の決定には無関係です。 これにより、その後、$n$反復すると、順列全体がソートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = []
    
    # We simulate a shrinking active region.
    # The idea: repeatedly bring maximum to front, then rotate it into suffix.
    for m in range(n, 1, -1):
        # find index of maximum in first m elements
        mx = max(range(m), key=lambda i: a[i])
        val = a[mx]
        
        # rotate until it reaches front
        while mx > 0:
            a = a[1:] + a[:1]
            ops.append("P")
            mx -= 1
        
        # now it's at front; simulate moving it into final position
        # by rotating it to the back of active segment
        for _ in range(m - 1):
            a = a[1:] + a[:1]
            ops.append("P")
    
    if not ops:
        print("empty")
    else:
        print("".join(ops))

if __name__ == "__main__":
    solve()
```この実装では、Python リストを使用してキューを直接シミュレートし、許可された回転操作のみを適用します。 この構成では、アルゴリズムが局所反転修正を完全に回避し、代わりに最大要素の繰り返し抽出に依存するため、スワップ操作は必要ありません。 

最もデリケートな部分は、アクティブ領域の縮小ロジックです。 現在のプレフィックスの最大値を前面に持ってきた後、次の繰り返し適用によってそれをサフィックスに回転させます。$P$。 これは安全です。最大値がアクティブなプレフィックスを離れると、それは今後の最大値検索の一部にはならないため、後続のステップに干渉することはありません。

 ## 特殊なケース

 特殊なケースの 1 つは、すでにソートされた順列です。 アルゴリズムは、各アクティブ セグメントの最大値を選択します。この最大値は、そのセグメントの先頭にすでに正しく配置されています。 その結果、回転ループは意味のある再配置を実行せず、出力は空のままになり、要求された仕様と一致します。 

もう 1 つの特殊なケースは、完全に逆の順列です。 各ステップでは現在の最大値が選択されます。これは、前回の回転後に常にアクティブなセグメントの先頭にあります。 アルゴリズムはそれをサフィックスに繰り返しプッシュし、ソートされた配列を後ろから着実に構築します。 多くのローテーションが発生しても、各要素は最大で 1 回だけ処理されるため、冗長な作業が防止されます。 

最後の微妙なケースは、最大要素が既にアクティブ領域と固定領域の間の境界近くにある場合です。 このアルゴリズムは、処理された要素がアクティブな選択範囲に再導入されることがないため、処理された要素と未処理のセグメント間の部分的な順序が決して違反されないことを保証します。
