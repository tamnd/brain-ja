 ## 解決策
 ## 問題の理解

 色あせた名札を表す短い文字列が与えられています。 元の名前は、Alice、Bob、または Cindy の 3 つの固定文字列のいずれかであることがわかっています。 ただし、観察された文字列には小文字または大文字が含まれている可能性があり、一部の位置がドットで表示されて判読できない場合があります。 各ドットは、任意の 1 つの英語文字を表すことができます。 

タスクは、すべてのドットを適切な文字に置き換えた後でも、3 つの名前のうちどれが観察されたパターンと一致するかを判断することです。 名前は、大文字と小文字が区別され、ドットが何にでも一致することを許可して、観察された文字列と 1 文字ずつ一致する場合に有効であるとみなされます。 

出力は、3 つの名前のうち互換性のある名前がいくつあるかによって異なります。 正確に 1 つの名前が適合する場合は、その名前が出力されます。 複数の名前が当てはまる場合は、情報が不十分であるため、CAN'T TELL と出力されます。 どの名前も適合しない場合は、「SOMETHING'S WRONG」が出力されます。 

入力サイズは非常に小さく、最大 5 文字です。 これにより、複雑な前処理や最適化の必要性が即座に排除されます。 各候補名と直接比較するだけで十分です。 

入力にドットのみが含まれる場合、微妙なエッジ ケースが発生します。 たとえば、「....」のような入力は、各文字を自由に選択できるため、3 つの名前すべてに一致します。 この場合、正しい出力は名前のいずれかではなく、CAN'T TELL です。 もう 1 つのケースは、「bob」と「Bob」のように、大文字と小文字の不一致が発生する場合です。この場合、完全に等しい必要があります。 大文字と小文字を区別しない単純な比較では、無効な一致が誤って受け入れられてしまいます。 

## アプローチ

 ブルートフォースアプローチはすでに問題の構造と一致しています。 3 つの候補名をそれぞれ試し、それぞれの位置を確認することで入力文字列と一致するかどうかを確認します。 入力内のドットはワイルドカードとして機能するため、常に一致します。 固定文字は正​​確に一致する必要があります。 

候補は 3 つだけで、各文字列の長さは最大 5 であるため、合計の作業量は一定です。 候補セットを拡張しても、構造は単純なパターン マッチングのままになります。 

重要な点は、ドットの考えられるすべての解釈を構築する必要はないということです。 そうなると、ドット数は爆発的に増加します。 代わりに、互換性を直接テストします。入力内の固定文字と競合しない場合、候補は有効です。 これにより、問題は組み合わせ生成から決定論的チェックに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 色あせたネームタグを表す入力文字列を読み取ります。 これを、文字が固定制約であり、ドットがワイルドカードであるパターンとして扱います。 
2. 3 つの候補名、Alice、Bob、Cindy を固定参照文字列として保存します。 
3. 各候補名について、入力文字列と 1 文字ずつ比較します。 
4. 各位置で、入力文字がドットの場合、候補から対応する任意の文字を受け入れます。 ドットでない場合は、候補者の性格と完全に一致する必要があります。 
5. すべてのポジションが候補者と一致する場合、その候補者を有効としてマークします。 
6. 3 つの候補をすべてチェックした後、有効な候補がいくつあるかを数えます。 
7. 候補が 1 つだけ有効な場合は、それを出力します。 複数が有効な場合は、CAN'T TELL が出力されます。 どれも有効でない場合は、「SOMETHING'S WRONG」と出力されます。 

### なぜ効果があるのか

各ドットは自由な選択を表すため、候補文字列に制約は課されません。 ドット以外の文字はすべて、満たさなければならない厳しい制約です。 したがって、妥当性は、候補文字列がすべての固定制約と一致しているかどうかをチェックすることに帰着します。 すべての制約を各候補に対して個別に検証するため、固定文字に違反する名前を誤って受け入れることはできず、少なくとも 1 つの制約と矛盾しない限り、名前を拒否することもできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def matches(pattern, name):
    if len(pattern) != len(name):
        return False
    for pc, nc in zip(pattern, name):
        if pc != '.' and pc != nc:
            return False
    return True

def solve():
    s = input().strip()
    candidates = ["Alice", "Bob", "Cindy"]

    valid = []
    for name in candidates:
        if matches(s, name):
            valid.append(name)

    if len(valid) == 1:
        print(valid[0])
    elif len(valid) > 1:
        print("CAN'T TELL")
    else:
        print("SOMETHING'S WRONG")

if __name__ == "__main__":
    solve()
```マッチング関数は、中心となるアイデアをエンコードします。つまり、ドットは制約として無視されますが、他のすべての文字は正確に一致する必要があります。 メインループは単純に 3 つの候補をフィルタリングします。 

よくある間違いは、特に「bob」と「Bob」のような入力を比較する場合に、大文字と小文字の区別を忘れることです。 条件`pc != nc`厳密な一致を強制します。 もう 1 つの微妙な点は、長さの一貫性です。問題では長さが常に正しいと示されていますが、拡張バリアントでの偶発的な誤用を防ぐためのチェックが含まれています。

 ## 特殊なケース

 「....」のような完全なワイルドカード文字列は、最も重要で明白ではないケースです。 すべてのポジションに制約がないため、すべての候補者に互換性があります。 アルゴリズムは 3 つの名前すべてを評価して有効とマークし、CAN'T TELL を生成します。 

「Zzzzz」のような厳密な不一致の場合は、逆の動作を示します。 各候補は最初の文字比較で失敗するため、有効なリストは空のままになり、出力は「SOMETHING'S WRONG」になります。 

大文字と小文字の区別も重要な条件です。 すべての文字で正確に比較されるため、「bob」のような入力は「Bob」と一致してはなりません。 このアルゴリズムは、正規化せずに等価性をチェックすることでこれを強制し、大文字と小文字が混在する入力の正確性を保証します。
