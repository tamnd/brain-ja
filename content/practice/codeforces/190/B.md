 ## 解決策
 ## 問題の理解

 私たちには、平面上に 2 つの円形の「脅威ゾーン」が与えられています。 それぞれは中心点と半径によって定義されます。 中心は都市であり、半径は敵の環がその都市からどれだけ離れているかを表します。 

飛行機内のどこにでも 1 つのレーダーを設置することが許可されています。 このレーダーは半径の円盤内にあるものをすべて検出します$r$レーダーの位置を中心にします。 攻撃が開始された瞬間に、2 つの敵の円のそれぞれから少なくとも 1 つの点を検出できれば、レーダーは成功したとみなされます。 幾何学的用語では、レーダー ディスクは指定された両方の円と交差する必要があります。 

タスクは、半径を最小限に抑えながら、これを可能にするレーダーの位置とその半径を選択することです。 

入力サイズは一定で、与えられる円は 2 つだけであるため、少量の固定量の幾何学的計算を伴う解決策は容易に十分に高速になります。 漸近的な最適化手法は必要ありませんが、精度と正しいケース処理が重要です。 

素朴だが危険な間違いは、最良のレーダー位置が円の中心や中心の中点などのいくつかの明白な場所の 1 つにあるに違いないと考えることです。 これは、最適な点が平面内のどこにでも、通常は中心間のセグメントに沿って存在する可能性があるが、必ずしも離散的な候補にあるとは限らないため、これは失敗します。 

もう 1 つのよくある落とし穴は、封じ込めケースを無視することです。 一方の円がもう一方の円の内側に完全にある場合、またはそれらが大きく重なり合っている場合、最適な半径は素の場合とは異なる動作をします。 

たとえば、両方の円が一致する場合、答えは単に半径が小さいということになります。レーダーを中心に配置すると、その半径に等しい距離で両方の境界が検出されることがすでに保証されるためです。 中心間の距離のみを考慮するアプローチでは、誤ってゼロが返されます。 

## アプローチ

 点が欲しい$P$両方の円の境界に到達するために必要な最大距離を最小限に抑えます。 

レーダー位置を固定する場合$P$、必要な最小半径は次のとおりです。$$\max(d(P, C_1) - r_1,\; d(P, C_2) - r_2,\; 0)$$どこ$C_i$円の中心です$i$、 そして$r_i$はその半径です。 引き算します$r_i$なぜなら、円の中心に到達する必要はなく、円の境界に触れるだけでよいからです。 

幾何学的に、これは各円が「距離制約」領域を誘発することを意味します。つまり、距離内にいる必要があります。$r + r_i$中心の$C_i$。 したがって、固定の場合$r$、実現可能性は次のようになります: ポイントは存在しますか?$P$両方の円盤の半径内にあるもの$r + r_1$その周り$C_1$と半径$r + r_2$その周り$C_2$。 

これにより、問題は最小のものを見つけることに減ります。$r$2 つの円盤が交差するように。 

重要な観察は単調性です。半径が$r$機能するだけでなく、より大きな半径も機能します。 これにより、バイナリ検索が可能になります$r$。 

特定の条件の実現可能性をテストするには$r$、2 つの円が交差するかどうかを確認します。$$d(C_1, C_2) \le (r + r_1) + (r + r_2)$$これは次のように単純化されます。$$d(C_1, C_2) \le 2r + r_1 + r_2$$それで：$$r \ge \frac{d(C_1, C_2) - r_1 - r_2}{2}$$以来$r \ge 0$、答えは次のとおりです。$$\max\left(0, \frac{d - r_1 - r_2}{2}\right)$$この問題は、中心間のユークリッド距離を計算し、この公式を適用することに要約されます。 

ブルートフォース解釈では、考えられるすべてのレーダー位置を試すことになりますが、連続した空間上では不可能です。 最適な位置はグリッドに制限されないため、平面を離散化しても役に立ちません。 

洞察としては、制約は単一のスカラー値、つまり中心間の距離によって完全に決定されるということです。

 ## アルゴリズムのチュートリアル

 1. それぞれ座標と半径が含まれている 2 つの円の説明を読みます。 これらは問題内の唯一の幾何学的オブジェクトを定義するため、これ以降の推論はすべてそれらの相対的な配置に依存します。 
2. 2 つの中心間のユークリッド距離を計算します。$$d = \sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2}$$この距離は、2 つの脅威ゾーン間の空間関係を完全に捉えています。 
3. 実効オーバーラップ不足を計算します。$$d - (r_1 + r_2)$$これは、円がすでに接触または重なり合っているところからどのくらい離れているかを測定します。 
4. この値が負またはゼロの場合、円はすでに交差しているか、一方が他方を含んでいます。 この場合、交差点エリアに設置されたレーダーは追加半径なしで両方に接触できるため、答えは 0 になります。 
5. それ以外の場合は、超過距離を 2 で割ります。これは、両方の円へのギャップを同時に「埋める」ために、レーダーが外側にどれだけ拡張する必要があるかを表します。 
6. 結果の値を十分な浮動小数点精度で出力します。 

### なぜ効果があるのか

 必要な半径を最小にするレーダー位置は、常に 2 つの中心を結ぶ線分上にあります。 このラインから外れた候補点については、それをセグメント上に投影しても、最大制約が改善されるような方法でどちらの中心までの距離も増加することはありません。 これにより、最適化は 2D の連続検索から 1D の距離バランスの問題に軽減されます。 その構造に制限されると、最小半径は、展開された円間の覆われていないギャップのちょうど半分、またはすでに重なっている場合はゼロになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x1, y1, r1 = map(int, input().split())
x2, y2, r2 = map(int, input().split())

dx = x1 - x2
dy = y1 - y2

d = (dx * dx + dy * dy) ** 0.5

ans = (d - r1 - r2) / 2.0
if ans < 0:
    ans = 0.0

print(ans)
```この実装では、以前に導出された幾何学的な縮小が直接計算されます。 唯一の微妙な点は、浮動小数点の精度が十分であることを確認することです。 制約を考慮すると、Python の倍精度浮動小数点数を使用するのが適切です。 

負の値はゼロにクランプする必要がある重複ケースを表すため、減算ステップは 2 で割る前に実行する必要があります。 このクランプをスキップすると、誤った否定的な回答が得られます。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    x1, y1, r1 = map(int, input().split())
    x2, y2, r2 = map(int, input().split())

    dx = x1 - x2
    dy = y1 - y2
    d = math.sqrt(dx * dx + dy * dy)

    ans = (d - r1 - r2) / 2.0
    if ans < 0:
        ans = 0.0

    return f"{ans:.10f}"

# provided sample
assert abs(float(run("0 0 1\n6 0 3\n")) - 1.0) < 1e-9

# identical circles
assert abs(float(run("0 0 5\n0 0 5\n")) - 0.0) < 1e-9

# one inside another
assert abs(float(run("0 0 10\n1 1 1\n")) - 0.0) < 1e-9

# far apart
assert abs(float(run("0 0 1\n100 0 1\n")) - 49.0) < 1e-9

# tangent case
assert abs(float(run("0 0 1\n2 0 1\n")) - 0.0) < 1e-9
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 同一の円 | 0 | 完全封じ込め |
 | 一つの中にもう一つ | 0 | ネストされた円の処理 |
 | 遠く離れて | 49 | 大きな分離の正確さ |
 | 接円 | 0 | 境界が等しい場合 |

 ## 特殊なケース

 重要なエッジケースは、一方の円がもう一方の円を完全に包含する場合です。 入力の場合:```
0 0 10
1 0 1
```アルゴリズムは計算します$d \approx 1$、 そして$r_1 + r_2 = 11$, したがって、ギャップはマイナスです。 クランプは応答をゼロに強制します。 幾何学的には、大きい円の内側の点はすでに小さい円との交差を保証しているため、追加のレーダー半径は必要ありません。 

もう 1 つの特殊なケースは接線です。```
0 0 1
2 0 1
```ここ$d = 2$、 そして$r_1 + r_2 = 2$、ギャップはゼロになります。 アルゴリズムは正確にゼロを返し、円がすでに接触しているという事実と一致するため、接触点に設置されたレーダーは両方を即座に検出します。 

3 番目の微妙なケースは、半径が小さい場合の大きな分離です。```
0 0 1
100 0 1
```ギャップは 98 なので、答えは 49 です。これは対称性を反映しています。最適なレーダーは円の「膨らんだ境界」の中間に位置し、両側に必要な到達距離のバランスを均等に保っています。
