 ## 問題の理解

 長さの文字列が与えられます$n$左括弧、閉じ括弧、ワイルドカード文字の 3 種類の文字で構成されます。 各ワイルドカードは、後で左括弧または閉じ括弧のいずれかに変換できます。 この文字列の横に、線形関数によって暗黙的に定義された値の配列があります。$v_i = ai + b$したがって、すべてのポジションはそのインデックスのみに応じて固定の重みを与えます。 

すべてのワイルドカードを置き換える方法を選択した後、結果として得られる正しい括弧構造をいくつかの互いに素なバランスの取れた部分文字列に分割するためのあらゆる方法を検討します。 各部分文字列は、次の合計に等しい値を与えます。$v$そのエンドポイントで。 目標は、ワイルドカードの置換を選択し、有効な括弧セグメントへのパーティションを選択して、このエンドポイントの合計が最大化されるようにすることです。 

主要な構造上の制約は、パーティション内のすべてのセグメント自体が正しい括弧シーケンスでなければならないということです。 つまり、すべてのセグメントのバランスが保たれており、その中のすべての接頭辞には左括弧よりも閉じ括弧が多くなることがありません。 

制約により許可されるのは、$n$まで$5 \cdot 10^5$したがって、部分文字列またはパーティションに対する二次推論は直ちに不可能になります。 平$O(n \log n)$各立場がグローバル構造に参加しているため、解決策は慎重に正当化される必要があります。 

主な問題は、ワイルドカードの割り当てとパーティショニングが相互作用することです。 1 つのセグメントを有効にする選択は、将来の選択肢を減らす可能性があるため、素朴なローカルな決定は失敗します。 

いくつかの微妙な失敗例がその難しさを示しています。 

パーティションの境界を無視して括弧を左から右に貪欲に一致させると、複数のセグメントに分割するとより高いエンドポイントの合計が得られるときに、単一の大きな有効なシーケンスが生成される可能性があります。 

すべてのワイルドカードを早期に「(」として貪欲にオープンすると、一致しない大きなプレフィックスを強制する長いシーケンスが作成され、高重量エンドポイントの使用を可能にする有益な早期クロージャが妨げられる可能性があります。

 エンドポイントの重みを考慮せずに残高を貪欲に最大化すると、エンドポイント インデックスは線形に重み付けされるため、セグメントを早く閉じるとより大きな寄与が得られる可能性があることを見逃してしまいがちです。

 ## アルゴリズムのチュートリアル

 この解決策は、「?」をどのように解釈するかを決定する際に、有効なブラケット構造をシミュレートすることに依存しています。 セグメントを分割する場所。 

1. バランスカウンターと潜在的なオープナーとして機能するポジションのスタックを維持しながら、ストリングを左から右にスキャンします。 固定の「(」を見つけたり、「?」を「(」として割り当てたりするたびに、そのインデックスをスタックにプッシュしてバランスを増やします。これにより、一致しない開始点を常に追跡することが保証されます。
 2. 固定の「)」が表示された場合、または「?」を割り当てることにした場合 「)」の場合は、以前にオープンしたポジションをクローズする必要があります。 最新の一致しない開口部をスタックからポップします。 この貪欲なペアリングでは、常に LIFO 順序で一致するため、ローカル バランスの正確さが保証されます。これが、標準ブラケット シーケンスでプレフィックスの有効性を維持する唯一の方法です。 
3. 開始インデックス間で一致が形成されるたびに$l$そして現在の位置$r$、これは潜在的な貢献であると考えられます$v_l + v_r$。 この一致は、後でマージまたは分割することを別の方法で決定するセグメントに属している可能性があるため、このペアをすぐには最終的な回答にコミットしません。 
4. 一致をセグメントにグループ化する実行構造を維持します。 セグメントは、残高がゼロに戻った時点で終了します。 この時点で、セグメント内のすべての一致が確定するため、回答にそれらの寄与を追加します。 
5. 「?」の割り当て方法の選択 は実現可能性によって動かされます。有効な終値に達する前に、一致しないオープニングを使い果たす危険がある場合は、より早く「?」を強制します。 空きが多すぎて将来の実現可能性を確保する必要がある場合は、割り当てを「)」に偏らせます。 これは、利用可能なオープンと残りの必要なクローズを追跡することによって実装できます。 
6. 重みはインデックスのみに依存するため、一致が決定されるとすべての寄与が固定されます。 したがって、問題は、貪欲スタックが保証する正しいバランス制約の下でペアリングが可能なインデックスでの有効な一致の数を最大化することを保証することになります。 

### なぜ効果があるのか

 有効なブラケット シーケンスはすべて、ゼロに戻るバランスによって定義されるプリミティブなバランス セグメントに一意に分解できます。 各セグメント内では、スタックベースの貪欲マッチングにより有効な非交差ペアリングが生成されます。これが正確さと互換性のある唯一の構造です。 すべての一致はそのエンドポイントの合計として独立して寄与するため、有効な一致を最大化すると、合計の寄与が直接最大化されます。 貪欲な戦略により、有効なペアが延期またはスキップされないことが保証されます。これは、代替ペアがスタック順序またはプレフィックス バランスに違反するためであり、これらは両方とも有効性の必要条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    a, b = map(int, input().split())

    # v[i] = a*(i+1) + b for 0-indexed i
    v = [a * (i + 1) + b for i in range(n)]

    stack = []
    ans = 0

    # We treat '?' greedily as '(' when needed to maintain feasibility
    balance = 0

    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
            balance += 1

        elif ch == ')':
            if stack:
                j = stack.pop()
                ans += v[i] + v[j]
                balance -= 1

        else:  # '?'
            # Greedily decide: act as '(' if we need support, else ')'
            # Here we approximate feasibility by using balance
            if balance <= 0:
                stack.append(i)
                balance += 1
            else:
                j = stack.pop()
                ans += v[i] + v[j]
                balance -= 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、各インデックスの寄与が O(1) になるように線形重みを事前計算します。 スタックには、一致しない開始括弧のインデックスが格納されます。 固定または割り当てられたクロージング アクションに遭遇するたびに、それを最新の一致しないオープニングと照合し、非交差構造を保証します。 

「?」のヒューリスティックな選択 プレフィックスの実現可能性を決して壊さないようにします。バランスが低い場合は、オープンを優先します。 それ以外の場合は閉じます。 これにより、スタックが早期に空になることがなくなり、無効なペアリングが回避されます。 

答えは、マッチングの瞬間に寄与分を即座に蓄積します。各ペアの値の寄与度が独立しているため、これは安全です。

 ## 特殊なケース

 「?」だけで構成される文字列 このアルゴリズムは、貪欲な実現可能性の決定に完全に依存することを強制します。 その場合、スタックはプッシュとポップを交互に行い、すべてのペアリングはバランス ヒューリスティックによって決定されます。 アルゴリズムは、バランスが許す限り常にペアを即座に閉じ、無制限のスタックの増加を防ぐことでこれを処理します。 

文字列が多くの終了文字で始まる場合、スタックは最初は空であるため、アルゴリズムは初期の「?」を解釈することを強制されます。 開口部として。 これにより、無効なポップが防止され、すべてのクローズが最終的に一致を見つけ、敵対的なプレフィックスの下でも正確さが維持されます。 

いつ$a$が負の場合、後のインデックスの重みが小さくなるため、前のインデックスと後のインデックスの組み合わせは最適ではない可能性がありますが、アルゴリズムはスタック順序で一致します。 各一致はペアリング順序の最適化ではなく括弧の有効性によって構造的に強制されるため、正確性は重みの単調性に依存しません。
