 ## 解決策
 ## 問題の理解

 整数の長い配列とサブセグメントに対する多くのクエリが与えられます。 配列内の任意の間隔について、そのセグメントに少なくとも 1 つの偶数と少なくとも 1 つの奇数が含まれている場合、それを「良好」と呼びます。 言い換えれば、セグメントが不良であるのは、セグメントが完全に奇数の値で構成されている場合、または完全に偶数の値で構成されている場合のみです。 

各クエリは範囲を指定します`[X, Y]`、サブ配列の数を数えなければなりません`[L, R]`この範囲内に完全に入っていれば問題ありません。 したがって、単一の間隔をチェックするのではなく、クエリ範囲内のすべての有効なサブ間隔をカウントします。 

このタスクを言い換える便利な方法は、次のすべての部分配列をカウントすることです。`[X, Y]`、無効なものを減算します。 サブ配列は、そのすべての要素が同じパリティを持つ場合には無効になります。 したがって、無効なサブ配列とは、正確には、等しいパリティの連続するラン内に完全に含まれるサブ配列です。 

この制約により、私たちは部分配列の列挙から遠ざけられます。 最大 5 × 10^5 要素と 5 × 10^5 クエリでは、クエリ ソリューションごとに O(n) があると 10^11 の演算が発生し、これは実現可能性をはるかに超えています。 クエリあたりのサブ配列の数は長さが 2 次であるため、サブ配列あたりの構築が O(log n) であっても遅すぎます。 

微妙な問題が境界に現れます。 クエリがパリティ実行を途中で実行した場合、その実行の一部のみが無効なサブ配列に影響します。 たとえば、ランニング中`[2, 2, 2, 2]`、クエリ`[2nd position, 3rd position]`より小さなランを生成します`[2, 2]`、無効な部分配列の数は、クリップされたセグメント内でのみ計算されます。 

この境界効果はまさに、単純な前処理では不十分になる原因です。単にグローバル実行の寄与を差し引くことはできません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのクエリを列挙し、その内部のすべてのサブ配列を列挙します。`[X, Y]`、それぞれに両方のパリティが含まれているかどうかを確認します。 O(1) のサブ配列をチェックするためにプレフィックス パリティ情報を事前計算したとしても、最悪の場合、各クエリは依然として O(n^2) 個のサブ配列に影響し、クエリ全体で合計 O(n^3) 回の演算が爆発的に増加します。 

代わりに、ロジックを反転することができます。 正常なサブ配列を直接カウントするのではなく、クエリ範囲内のすべてのサブ配列をカウントし、不良なサブ配列を減算します。 部分配列は、その中のすべての要素が等しいパリティの最大の連続セグメント内にある場合にのみ不良となります。 

この観察により、問題の構造は配列のパリティ実行への分解に帰着します。 各実行は、すべての値が偶数または奇数の最大セグメントです。 不良サブアレイはすべて、これらの実行の 1 つの内部に完全に存在する必要があります。 

したがって、問題は次のようになります。クエリごとに、交差するすべてのパリティ実行の合計寄与度を計算します。`[X, Y]`ただし、クエリ内にある各実行の部分のみをカウントします。 実行はばらばらで順序付けられているため、これは管理可能です。 

すべての実行とその寄与を事前計算し、実行のプレフィックス合計を使用して、境界で最大 2 つの部分的な実行と中央の完全にカバーされた実行を組み合わせて各クエリに答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | お(1) | 遅すぎる |
 | 分解 + プレフィックスの合計を実行する | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず配列を連続したパリティ ブロックに圧縮します。 各ブロックは、その左端点、右端点、およびそれが偶数を表すか奇数を表すかを保存します。 各ブロックについて、無効なサブ配列に対する内部寄与も計算します。これは、ブロック内に完全に含まれるサブ配列の数です。 

次に、これらのブロックの寄与度に基づいてプレフィックスの合計を構築し、完全なブロックの範囲の寄与度を迅速に合計できるようにします。 

クエリごとに、エンドポイントがどのブロックに属しているかを決定します。 左の端点はあるブロックの内側にあり、右の端点はあるブロックの内側にあります。 

次に、答えを 3 つの部分に分割します。左側のブロックからの部分的な寄与、右側のブロックからの部分的な寄与、および厳密にそれらの間のブロックからの完全な寄与です。 

1. ビルド パリティは、左から右にスキャンしてアレイ全体を実行します。 パリティが変更されるたびに、現在の実行を終了し、新しい実行を開始します。 
2. 実行ごとに`[l, r]`、その内部の無効な寄与を次のように計算します。`(len * (len + 1)) / 2`。 
3. ラン寄与に対するプレフィックス合計を構築します。 
4. 各クエリについて`[X, Y]`を含む実行を見つけます。`X`そして、以下を含む実行`Y`。 
5. 両方のエンドポイントが同じ実行内にある場合は、クリップされたセグメントからのみ寄与を計算します。`[X, Y]`。 
6. それ以外の場合は、寄与度を次のように計算します。 

クリップされた左ラン貢献、

 クリップされた右ランの貢献に加えて、

 さらに、その間の完全にカバーされた実行のプレフィックスの合計。 
7. サブ配列の合計を計算します。`[X, Y]`を使用して`(len * (len + 1)) / 2`。 
8. 合計から無効な寄与を引いて、正常なサブアレイの数を取得します。 

重要な不変条件は、すべての無効なサブ配列が完全に 1 つのパリティ実行内にあり、すべての実行が独立して寄与するということです。 プレフィックスの合計により、完全にカバーされた各実行が 1 回だけカウントされることが保証され、クリッピングにより部分的な実行の境界の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

# build parity runs
runs = []
run_id = [0] * n

start = 0
for i in range(1, n + 1):
    if i == n or (a[i] % 2) != (a[i - 1] % 2):
        runs.append((start, i - 1))
        start = i

for idx, (l, r) in enumerate(runs):
    for i in range(l, r + 1):
        run_id[i] = idx

m = len(runs)

run_val = [0] * m
for i, (l, r) in enumerate(runs):
    length = r - l + 1
    run_val[i] = length * (length + 1) // 2

pref = [0] * (m + 1)
for i in range(m):
    pref[i + 1] = pref[i] + run_val[i]

def calc_partial(l, r):
    length = r - l + 1
    return length * (length + 1) // 2

out = []
for _ in range(q):
    L, R = map(int, input().split())
    L -= 1
    R -= 1

    total = (R - L + 1) * (R - L + 2) // 2

    cl = run_id[L]
    cr = run_id[R]

    if cl == cr:
        bad = calc_partial(L, R)
    else:
        l_end = runs[cl][1]
        r_start = runs[cr][0]

        bad = 0
        bad += calc_partial(L, l_end)
        bad += calc_partial(r_start, R)
        if cl + 1 <= cr - 1:
            bad += pref[cr] - pref[cl + 1]

    good = total - bad
    out.append(str(good))

print("\n".join(out))
```実装は、配列をパリティ実行に圧縮することから始まります。 各実行はその境界とともに保存されるため、クエリ内にどれだけの実行が含まれているかをすぐに判断できます。 の`run_id`配列はすべてのインデックスをその実行にマップします。これにより、エンドポイントの分類が一定時間になります。 

プレフィックスの合計`pref`これにより、実行全体の寄与を O(1) に追加できます。 機能`calc_partial`クリップされたセグメント内の部分配列の数を計算します。これは三角数の標準式です。 

各クエリについて、間隔内のサブ配列の合計を計算し、パリティ実行内で形成された不良なサブ配列を減算します。 ロジックは、二重カウントを避けるために、単一実行クエリと複数実行クエリを注意深く区別します。 

## 実用的な例

 小さな配列を考えてみましょう。```
A = [1, 3, 4, 6, 5]
```パリティ実行は次のとおりです。 

[1,3] 奇数、[4,6] 偶数、[5] 奇数。 

クエリ`[1, 5]`(1 のインデックス付き) になります。`[0, 4]`。 

実行を追跡します:

 | ステップ | Ｌ | R | cl | cr | 悪い計算 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 0 | 4 | 0 | 2 | 開始 |
 | 左部分 | - | - | - | - | [0,1] が貢献 |
 | 右部分 | - | - | - | - | [4,4] が貢献 |
 | ミドルラン | - | - | - | - | ラン 1 が完全に含まれています |

 左部分不良 = 2_3/2 = 3

 中走不良＝3_4/2＝6

 右部分不良 = 1*2/2 = 1

 悪い合計 = 10

 サブ配列の合計 = 5*6/2 = 15

 答え = 5

 これは、実行への分解によってすべての無効な部分配列が 1 回だけキャプチャされることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、クエリが単一のパリティ実行内に完全に存在する場合です。 この場合、すべての部分配列が無効になるため、答えはゼロになる必要があります。 アルゴリズムはこれを直接処理します。`cl == cr`クリップされたセグメントに対して三角数を計算することで分岐します。 

もう 1 つのエッジ ケースは、クエリが実行境界で正確に開始または終了する場合です。 分解により、境界インデックスが一貫して実行に割り当てられるため、クリップされた計算はオフバイワン調整なしで正しいままになります。 

最後のケースは、クエリがちょうど 2 回の実行にまたがる場合です。 ここでは、完全にカバーされる中間ランはなく、プレフィックス合計項はスキップされ、存在しないセグメントが誤って二重にカウントされるのを防ぎます。
