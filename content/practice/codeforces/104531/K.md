 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられており、それらを任意に並べ替えることができます。 選択した順序については、各位置 i とそこに配置された値をペアにし、その 2 つのビットごとの XOR をとり、すべての位置でこれらの値を合計することでスコアを計算します。 

形式的には、p が長さ n の順列である場合、スコアは p[i] XOR i のすべての位置 i の合計になります。 タスクは、可能な最大スコアを達成する順列を構築することです。 

入力は複数の独立したテスト ケースで構成され、それぞれが値 n を与えます。 それぞれについて、この XOR 合計を最大化するサイズ n の有効な順列を出力する必要があります。 

最大 10^5 のテスト ケースで n が 10^5 までという制約により、単純に実行した場合、二次関数や、テスト ケースごとの n log n からも遠ざけられます。 すべての順列の直接評価は階乗時間であり、直ちには不可能です。 局所的な改善をシミュレートする貪欲なスワッピング戦略であっても、入力スケールを組み合わせた場合には耐えられません。 

n の値が小さい場合、ビット パターンに関する直観が誤解を招く可能性がある微妙なエッジ ケースが発生します。 n = 1 の場合、順列のみが [1] であるため、答えは自明です。 n = 2 の場合、1 XOR 1 + 2 XOR 2 は 0 に等しく、1 XOR 2 + 2 XOR 1 も 0 に等しいため、両方の置換は同じスコアを与えます。 n が大きくなると、上位ビットが XOR 寄与を支配し、インデックスに対する数値の配置によって上位ビットがアクティブ化される頻度が決まるため、構造が意味を持ちます。 

## アプローチ

 ブルート フォース ソリューションでは、すべての順列を列挙し、それぞれの XOR 合計を計算し、最大値を追跡します。 これが機能するのは、スコアが順列ごとに O(n) で評価できるため、正確性が簡単です。 問題は規模だ。 あるよ！ n = 10 の場合でも、これはすでに大きすぎますが、ここでの n は 10^5 に達するため、ブルート フォースは完全に実行不可能になります。 

重要な点は、関数がビットごとに分離可能であるということです。 各ビットは、そのビットが i と p[i] の間で異なるかどうかに応じて、独立して合計に寄与します。 i と p[i] のビット値が異なる場合、ビットは XOR に 1 を与えます。 したがって、ビットごとに、インデックスと割り当てられた値の間で発生する不一致の数を効果的に最大化しようとしています。 

これにより、問題は、すべてのビット位置にわたるビット単位の不一致を同時に最大化する順列を構築することに変わります。 最適な戦略は、できるだけ多くの上位ビットを反転する方法でインデックスと値をペアにすることになります。これを実現する構造は、範囲内のビット単位の補数ペアです。 

具体的には、n の最上位ビットまでのバイナリの数値を考える場合、固定インデックスで XOR を最大化する最良の方法は、バイナリ空間で可能な限り大きな値を割り当てることです。 これは、i XOR j が局所的に最大化されるように、i と値 j をペアにすることになります。これは、n を含む最小の 2 のべき乗ブロックに制限されたビット単位の補数に各数値をマッピングすることにグローバルに対応します。 

直接的な構造が現れます。2 の最大累乗ブロック内で作業し、各インデックス i を (マスク XOR i) にマップします。マスクは、n から 1 を引いたものと同じビット長を持つ最大の全 1 値です。完全なブロックの外側の値は、固定したままにするか、残りの範囲内で調整することによって処理されます。 

これにより、最初の最上位ビットでビット フリップを最大化する順列が生成され、合計を支配します。

 ## アルゴリズムのチュートリアル

 現在のビット長 n 内でビットごとの補数ロジックを使用して置換を直接構築します。

1. n より大きい 2 の最小のべき乗を計算し、それを m と呼びます。 マスクを m − 1 として定義します。これは、すべてのビットが n に必要な最上位ビットまで設定された 2 進数です。 このマスクは、操作したい完全なビット空間を表します。 
2. 1 から n までの各数値 i について、候補値 j = マスク XOR i を計算します。 この値はマスク幅内の i のビット単位の補数であり、バイナリ表現での最大の分離が保証されます。 ビットが異なる場合に XOR が最大化されるため、このステップが選択されます。 
3. j が有効な範囲 [1, n] 内にあり、まだ割り当てられていない場合は、p[i] = j を割り当てます。 これにより、最大の XOR ペアリングを強制しながら有効な順列を維持できるようになります。 
4. j が無効であるか、すでに使用されている場合は、フォールバックとして p[i] = i を割り当てます。 これにより、制約を破ることなく置換の有効性が維持されます。 
5. 結果の配列を出力します。 

貪欲ペアリングが機能するのは、補数マッピングがインボリューションであるためです。つまり、2 回適用すると元の数値に戻ります。 これは、有効なペアが自然に形成され、各割り当てがペアを完了するか安全にフォールバックすることを意味します。 

### なぜ効果があるのか

 この構築では、最初に可能な限り高いビット位置でビット差を最大化しようとします。 XOR 合計は上位ビットによって支配されるため、アクティブなビット幅内で数値とそのビット単位の補数をペアにすると、ペアごとの寄与が最大化されます。 インボリューション プロパティにより、i とその補数の両方が範囲内にある場合は常に、それらが互いに素なペアを形成し、競合を防ぎ、有効な置換を保証します。 残りの要素は、n が 2 の完全な累乗ブロックではない場合にのみ発生し、これらの要素をペアにして有効性を損なうことなく上位ビットの寄与を改善することはできないため、制約の下では要素を修正することが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        m = 1
        while m <= n:
            m <<= 1
        mask = m - 1

        p = [-1] * (n + 1)
        used = [False] * (n + 1)

        for i in range(1, n + 1):
            if p[i] != -1:
                continue
            j = mask ^ i
            if 1 <= j <= n and p[j] == -1:
                p[i] = j
                p[j] = i
            else:
                p[i] = i

        print(*p[1:])

if __name__ == "__main__":
    solve()
```実装ではまず、n までのすべての値をカバーするバイナリ マスクを決定します。 次に、各位置を反復処理し、そのマスクの下でその補数とペアにしようとします。 小切手`p[j] == -1`各数値が 1 回だけ使用されるようにします。 ペアリングが不可能な場合、エレメントは所定の位置に固定されます。 

微妙な点は、順番に反復し、ペアの両端が未使用の場合にのみ代入する必要があることです。 そうしないと、以前の決定が上書きされ、順列の有効性が損なわれる危険があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        m = 1
        while m <= n:
            m <<= 1
        mask = m - 1

            j = mask ^ i
            if 1 <= j <= n and p[j] == -1:
                p[i] = j
                p[j] = i
            else:
                p[i] = i

        out.append(" ".join(map(str, p[1:])))
    return "\n".join(out)

 ## 特殊なケース

 n = 1 の場合、アルゴリズムはマスクを 1 に設定してペアリングを試行しますが、i = 1 は無効な j = 0 にマップするため、p[1] = 1 となります。代替の置換がないため、出力は正しいです。 

n = 2 の場合、マスクは 3 です。i = 1、j = 2 の場合、p[1] = 2 および p[2] = 1 を割り当てます。これは、範囲が許可する場合、ペアリング メカニズムが完全なスワップを正しく形成することを示しています。 

n = 3 の場合、マスクは 3 です。ペアリングでは (1,2) が与えられ、3 は固定されたままになります。これは、3 の範囲内に有効な補数がないため、最適な構造と一致します。
