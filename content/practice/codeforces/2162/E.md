 ## 解決策
 ## 問題の理解

 1 から n までの整数の配列と整数 k が与えられます。 この配列の末尾に正確に k 個の数値を追加することができます。 目標は、追加後に結果として得られる配列内の回文部分配列の総数が最小になるように、これらの k 個の数値を選択することです。 部分配列が前方と後方で同じように読み取られる場合、その部分配列は回文です。 

n は 2·10^5 まで大きくなり、すべてのテスト ケースにわたる n の合計も 2·10^5 に制限されるため、テスト ケースあたりおよそ O(n) または O(n log n) の時間でソリューションを設計する必要があります。 追加のたびに回文部分配列を明示的にカウントするアプローチは、部分配列の総数が O(n²) であり、最悪の場合 4·10^10 に達するため、非常に遅すぎます。 

重要な観察は、単一の要素が単独で回文部分配列を形成しているということです。 同じ要素の連続する部分シーケンスはそれぞれ回文であるため、繰り返される要素のシーケンスによっても回文部分配列の数が増加します。 配列内で既に多く表されている数値を追加すると、回文部分配列の数が増加する可能性があります。 逆に、既存の対称性を破る数値、または配列内で「まれな」数値を追加すると、新しい回文が最小限に抑えられます。 

エッジケースには、すでにほぼ均一になっている配列が含まれます。たとえば、`[2, 2, 2, 2]`。 追加中`2`この場合、回文部分配列の数が大幅に増加するため、次の値とは異なる任意の数を追加する必要があります。`2`。 もう 1 つのエッジケースは次のような場合です`k`1 または n: 同じ数値を繰り返し追加するのが魅力的に見える場合でも、数値の選択が「正確に k 個の操作」ルールに準拠していることを確認する必要があります。 

## アプローチ

 ブルートフォース手法では、k 個の数値のあらゆる組み合わせを試して追加し、新しい配列をシミュレートし、回文部分配列をカウントします。 各テスト ケースには n^k 個の組み合わせがあり、回文を数えるのは O(n²) であるため、総当たりアプローチは実行不可能です。 n = 2・10^5 および k = 1 の場合、これはすでに受け入れられません。 

効率的な解決策を可能にする洞察は、対称性を強化するのではなく、対称性を破る数字を追加したときに回文の増加が最小限に抑えられるという観察から得られます。 特に、配列に出現しない数値は、既存の要素を使用して新しい複数要素の回文を作成できません。 したがって、配列内にすでに存在する、または最小限の増加を保証する特定の制約を満たす 1 から n までの任意の数値を安全に選択できます。 最も単純な決定論的戦略は、1 から k (または最大 n) までのすべての整数を順番に追加し、k > n の場合はこれを繰り返すことです。 これにより、既存の回文構造との相互作用が最小限に抑えられます。 

これにより、問題は「追加するたびに回文を数える」という問題から、単純な「k 個の異なる数値、または既存の繰り返しシーケンスを形成しない数値を選択する」に変換され、問題は建設的なものに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²・n^k) | O(n) | 遅すぎる |
 | 最適な建設的 | O(k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 
2. 各テスト ケースについて、n、k、および配列 a を読み取ります。 
3. 回文部分配列を最小化するように各要素が選択された長さ k のシーケンスを構築します。 シンプルで安全な選択は、最初の n 個の一意の数値を k 個の数値が得られるまで繰り返し使用することです。 たとえば、n = 5 および k = 3 の場合、[1, 2, 3] を選択します。 
4. 選択した k 個の数値シーケンスを出力します。 

正しさは、配列内にすでに存在する数値を追加したり、1 から n までの数値を系統的に選択したりしても、避けられない単一要素の回文を超える余分な複数要素の回文が発生しないという不変条件に依存します。 数値を 1 から n まで周期的に繰り返すことで、多くの新しい回文が作成される、長く連続する繰り返しシーケンスが形成されないようにすることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    # We simply append numbers 1..n cyclically until we have k numbers
    res = []
    for i in range(k):
        res.append((i % n) + 1)
    print(' '.join(map(str, res)))
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 テスト ケースごとに、1 から n までを循環させて k 個の数値を構築します。 k > n の場合、モジュロ演算を使用してラップアラウンドします。 これにより、常に正確に k 個の数値が生成され、繰り返される数値の大きな連続ブロックが回避されるため、余分な回文の作成が回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        res = [(i % n) + 1 for i in range(k)]

## 特殊なケース

 たとえば配列が一様な場合、`[1, 1, 1]`k=3 の場合、追加`[1, 2, 3]`より長い繰り返しシーケンスを作成しないことで、潜在的な複数要素の回文を解消します。 同様に、k > n の場合、モジュロベースのサイクルにより、繰り返される数値の長いブロックが作成されなくなります。 最小の k=1 の場合、アルゴリズムは常に安全な単一要素である 1 を追加します。これにより、誤って長い回文が作成されることがなくなります。 各シナリオでは、1 要素より長い新しい回文部分配列が回避されるという不変条件が維持されます。
