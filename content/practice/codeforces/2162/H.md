 ## 解決策
 ## 問題の理解

 値が固定された配列が与えられますが、クエリに答える前にそれらを任意に並べ替えることができます。 この配列に加えて、いくつかのインデックス範囲も与えられます。 任意の候補値に対して$x$、各範囲は、配列を並べ替えた後にその範囲内に表示できる値に制約を課します。 

機能$f(a, x, l, r)$部分配列内の最小値と最大値のみに依存します$a[l..r]$。 もし$x$これら 2 つの極値によって形成される間隔の厳密に外側にある場合、つまり最小値より厳密に小さいか、最大値より厳密に大きい場合、関数は 0 を出力します。それ以外の場合は 1 を出力します。したがって、各間隔は本質的にセグメントに値を「カバー」させることになります。$x$弱い意味で：$x$は、その間隔内に配置された値の範囲を完全に外側にあってはなりません。 

私たちはあらゆることについて尋ねられます$x \in [1,n]$、すべての間隔がこの条件を同時に満たすように配列を並べ替えることができるかどうか。 

制約は、区間にわたる 3 次以上の解が不可能であることを直ちに示します。 と$n, m \le 2000$テストごとの合計とテスト全体で制限された二次和の合計、周囲のソリューション$O(n^2)$または$O(n^2 \log n)$が期待されています。 すべての順列を明示的にシミュレートしようとするアプローチは実行不可能です。$n!$は大きすぎるため、大域的な構造制約をエンコードしない限り、順列に対する貪欲な構築も失敗します。 

配列内のすべての値が同一である場合、微妙なエッジ ケースが発生します。 その場合、すべての間隔は自明に min = max を持ち、すべての間隔は min = max になります。$x$は条件を満たしているため、答えは常にすべて 1 になるはずです。 配列内の変動性を仮定する単純なアプローチでは、このような場合に誤って過剰な制約が行われる可能性があります。 

もう 1 つの重要なエッジ状況は、間隔が重なり合う場合です。 ローカルの貪欲な配置は、各間隔を個別に満たす可能性がありますが、単一の値の割り当てが複数の範囲に同時に影響するため、全体的には失敗します。 本当の難しさは、間隔が独立したローカル条件ではなく、値の分布方法に関してグローバルな制約を課すことです。 

## アプローチ

 ブルートフォースのアイデアは、配列のすべての順列を試して、それぞれについてチェックすることです。$x$、すべての間隔が条件を満たすかどうか。 これはすぐには不可能です。$n!$順列、さらに 1 つの順列のチェックにもコストがかかります$O(nm)$、指数関数的な爆発につながります。 

固定順列で条件を単純化できます。 一定の間隔で$[l,r]$、その最小値と最大値を定義します。 間隔は次の範囲で有効です$x$間隔の値の範囲が次の両側と交差する場合に限り、$x$、完全に下ではないことを意味します$x$完全に上ではありません$x$。 同様に、すべての間隔内に少なくとも 1 つの値が存在することを保持する必要があります。$\le x$少なくとも 1 つの値$\ge x$。 

この再定式化は、位置への依存を取り除き、実現可能性に焦点を当てます。すべての間隔に、相対的に「十分に小さい」要素と「十分に大きい」要素の両方が同時に含まれるように値を配置できるでしょうか。$x$?

 ここで視点を切り替えます。 修理$x$。 値を 2 つのグループに分割します。$\le x$そしてそれら$> x$。 並べ替えによってマルチセットの数が変更されないため、配列内のそれらの数は固定されます。 問題は、すべての間隔が各側から少なくとも 1 つの要素を受け取るように、これらの値を位置全体に分散できるかということです。 

これは、「小さい」値のみまたは「大きい」値のみが割り当てられた位置のセットに間隔が完全に含まれないようにすることと同じです。 したがって、どの位置が小さな値を取得するかを選択することを考える場合、すべての間隔は、選択されたセットとその補数の両方と交差する必要があります。 

これは古典的な間隔刺し制約になります。「小さな位置」のセットは、どの間隔も単色にならないようなものでなければなりません。 したがって、固定の場合、$x$のカウントに等しいサイズの位置のサブセットが存在するかどうかを確認する必要があります。$\le x$完全に含まれていない要素、またはどの間隔からも切り離されている要素。 

これは、インターバルにわたる 2-SAT スタイルの実現可能性構造ですが、さらに単純化します。重要なのは、小さな割り当てが多すぎる、または少なすぎる禁止されたインターバル構造が存在するかどうかだけです。 掃討することで$x$、値の数を維持できます。$\le x$そして、問題を両側で間隔が「ヒット」できるかどうかをチェックすることに還元します。これは、最適な割り当ての下で不可能になる間隔の数がゼロであるかどうかをチェックするのと同じです。 

重要な洞察は、それぞれの$x$、実現可能性はカウントのみに依存します。$k = |\{a_i \le x\}|$、および間隔に少なくとも 1 つの小さい値と 1 つの大きい値を割り当てることができるかどうか。 これは、配置が存在するかどうかを確認することになります。$k$間の小さなマーカー$n$すべての間隔に少なくとも 1 つのマーカーと少なくとも 1 つの非マーカーがあるように配置します。これは、どの間隔も同じ側で完全にカバーできないことを保証するのと同じです。 これは、プレフィックス構造と貪欲な配置を使用した、間隔制約上の単純な実現可能性チェックに変換されます。

 ## アルゴリズムのチュートリアル

 1. 配列の周波数情報を事前計算し、プレフィックス カウント配列を構築します。$x$、値がいくつあるかをすぐに知ることができます。$\le x$。 これが必要なのは、置換の自由によって順序付けは削除されますが、多重性は削除されないためです。 
2. それぞれについて$x$、 定義する$k$配列内の要素の数として$\le x$。 これにより、値がサイズが固定された小さなグループと大きなグループに分割されます。 
3. 問題を正確に割り当てていると解釈する$k$「小さい」という位置づけです。 すべての間隔には、少なくとも 1 つの小さなポジションと少なくとも 1 つの大きなポジションが含まれている必要があります。 この再定式化により、値の配置がインデックスに対する 2 値のラベル付け問題に変わります。 
4. 固定割り当ての場合、インターバルが完全に小さいポジションにある場合、または完全に大きいポジションにある場合、インターバルは失敗します。 したがって、有効性を維持するには、区間が単色であることが必要です。 
5. すべての割り当てを試す代わりに、ある程度のサイズが存在するかどうかだけを気にすることに注目してください。$k$単色の間隔を避ける位置のサブセット。 これは、間隔の制約に関する実現可能性の問題になります。 
6. 各間隔を、それに含まれる小さなポジションの数に関する制約に変換します。 各インターバル$[l,r]$0 または$r-l+1$小さなポジション。 したがって、すべての間隔は、選択したサブセットによって「カット」される必要があります。 
7. そのようなサブセットの存在は、選択できるかどうかを確認することに帰着します。$k$インターバルごとに打ちながらポジションを決めます。 これは古典的な間隔ヒットの実現可能性問題に相当し、適切なエンドポイントの貪欲な処理とカバレッジの維持によって解決できます。 
8.スイープ$x$1から$n$、更新中$k$、貪欲なインターバルヒットチェックを効率的に使用して実現可能性を再計算します。 

### なぜ効果があるのか

 核となる不変条件は、順列に関するすべての情報が、値のバイナリ パーティションに折りたたまれるということです。$\le x$そして$> x$、そしてそれらの数だけが重要です。 このパーティションが固定されると、各間隔の条件は、その間隔に両方のパーティションが出現するかどうかのみに依存します。 これにより、問題は、マルチセット値の配置から、間隔ごとに交差する固定サイズの位置のサブセットの選択まで軽減されます。 有効なソリューションはすべての間隔で少なくとも 1 つの小さなポジションを割り当てる必要があり、可能な限り早い位置を選択すると、固定カーディナリティ制約を尊重しながら将来の間隔を満たす能力が保持されるため、貪欲な実現可能性チェックは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(n, intervals, k):
    if k == 0 or k == n:
        return False

    intervals = sorted(intervals, key=lambda x: x[1])
    chosen = 0
    last = -1

    for l, r in intervals:
        if last < l:
            chosen += 1
            last = r
        if chosen > k:
            return False

    return chosen <= k

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        intervals = [tuple(map(int, input().split())) for _ in range(m)]

        freq = [0] * (n + 2)
        for v in a:
            freq[v] += 1

        pref = [0] * (n + 2)
        for i in range(1, n + 1):
            pref[i] = pref[i - 1] + freq[i]

        ans = []
        for x in range(1, n + 1):
            k = pref[x]
            if feasible(n, intervals, k):
                ans.append('1')
            else:
                ans.append('0')

        print("".join(ans))

if __name__ == "__main__":
    solve()
```解決策は、配列を周波数構造に圧縮して、各しきい値が$x$一定時間で評価できる。 プレフィックス配列は、「小さい」カテゴリに分類される値の正確な数を示します。 

実現可能性関数は、貪欲なインターバルヒット戦略をエンコードします。 インターバルは正しいエンドポイントによってソートされ、各インターバルに少なくとも 1 つが含まれることが保証されるように、「代表的な小さなポジション」を配置しようとします。 せいぜい配置できれば$k$このような代表値を使用すると、間隔の制約に違反することなく、一貫して小さな値を割り当てることができます。 

境界例$k=0$そして$k=n$間隔に小さい値と大きい値の両方を同時に含めることが不可能になるため、明示的に拒否されます。

 ## 特殊なケース

 完全に等しい配列は、任意の間隔内の最小値と最大値が一致し、積の状態が常にゼロになるため、最も脆弱なケースです。 値を「小さい」グループと「大きい」グループに分けることに依存するアプローチでは、これらのケースを誤って拒否しないようにする必要があります。 

例えば：```
1
4 2
5 5 5 5
1 3
2 4
```ここでは毎$x$有効である必要があります。 アルゴリズムの周波数ベースの分割により、次のいずれかが生成されます。$k=0$または$k=4$、実現可能性チェックでは、両方のカテゴリが存在することを前提とする間隔カバレッジ ロジックを強制するのではなく、これらを自動的に有効なものとして扱う必要があります。 

2 番目の脆弱なケースは、次のような間隔が連鎖を形成する場合です。$[1,2], [2,3], [3,4]$。 貪欲なインターバルヒットでは、共有エンドポイントが一貫して処理されるようにする必要があります。 そうしないと、配置を再開する素朴な貪欲さがオーバーラップを誤ってカウントし、無効な実現可能性の結果を生成します。
