 ## 問題の理解

 これは 2 つの実行問題です。 

最初の実行時に、プログラムは正の整数を受け取ります$n$。 バイナリ文字列を出力する必要があります$s$その長さは最大でも$\sqrt{2}\cdot \lceil \log_2 n \rceil + 5$。 

2 回目の実行中に、プログラムはバイナリ文字列を受け取ります。$q$。 この文字列は、以前に出力された文字列を取得することによって取得されました。$s$任意のバイナリ接尾辞 (空の場合もあります) を追加します。 タスクは元の番号を回復することです$n$。 

最大の問題は、デコーダが元の文字列がどこで終わるのかを認識できないことです。 有効なソリューションはすべてエンコードする必要があります$n$デコーダがエンコードされた情報と任意の追加ビットの間の境界を決定できるように、自己区切りの方法で。 

以来$n \le 10^{18}$、そのバイナリ表現には最大 60 ビットが含まれます。 

これは、非常に高度な圧縮スキームが必要ないことをすぐに示唆しています。 長さの制限はおよそ$1.414 \cdot k + 5$、 どこ$k$のビット長です$n$。 のために$k \le 60$、バイナリ表現自体は 60 ビットのみを使用しますが、90 ビット近くが許可されます。 表現の長さを記述するメタデータを保存するのに十分なスペースがあります。 

よくある間違いは、次のバイナリ表現を出力することです。$n$直接。 仮定する$n=5$、そのバイナリ形式は次のとおりです`101`。 2 回目の実行では受け取る可能性があります`101011001...`。 元のコードがどこで終わっているのかを知る方法がないため、デコードは不可能になります。 

もう 1 つの間違った考えは、次のような固定区切り文字を追加することです。`0`。 エンコードされたデータ自体にその区切りパターンが含まれている可能性がある場合、デコーダが間違った位置で停止する可能性があります。

## テストケース```
# encoder/decoder helpers for testing

def encode(n):
    nb = bin(n)[2:]
    k = len(nb)

    kb = bin(k)[2:]
    gamma = "0" * (len(kb) - 1) + kb

    return gamma + nb

def decode(q):
    z = 0
    while z < len(q) and q[z] == '0':
        z += 1

    pos = z
    kb = q[pos:pos + z + 1]
    k = int(kb, 2)

    pos += z + 1
    nb = q[pos:pos + k]

    return int(nb, 2)

# minimum value
s = encode(1)
assert decode(s) == 1

# suffix appended
assert decode(s + "101010") == 1

# power of two
s = encode(1024)
assert decode(s) == 1024
assert decode(s + "111111") == 1024

# all ones in binary
s = encode(63)
assert decode(s + "0000") == 63

# maximum constraint
s = encode(10**18)
assert decode(s + "101011001") == 10**18
```| テスト入力 | 期待される出力 | 検証内容 |
