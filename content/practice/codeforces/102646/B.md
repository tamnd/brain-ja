 ## 解決策
 ## 問題の理解

 タスクは、2 つの数値キューを 1 つの配列にマージすることです。 許可される唯一の操作は、どちらかのキューから現在の最初の要素を取得し、それを回答に追加することです。 元の各配列の内部順序は変更できません。 考えられるすべてのマージされた配列の中で、辞書編集的に最小の配列が必要です。 2 つの入力配列には、次のすべての数値が含まれます。`1`に`2n`正確に 1 回、つまりすべての値が一意であることを意味します。 

主な問題は、局所的に小さい最初の要素だけでは必ずしも十分ではないことです。 現在両方の配列が大きな値を公開している場合、正しい選択は両方の配列の残りのサフィックスを比較することによって決まります。 たとえば、`5`以上`6`で始まる配列の場合、必ずしも最適であるとは限りません。`6`はるかに小さい値で継続します。 

各配列の長さは次のとおりです。`100000`したがって、要素の総数は次のようになります。`200000`。 有効なインターリーブの数は指数関数的であるため、可能なすべてのマージを試行するアプローチは不可能です。 毎回サフィックスを 1 文字ずつ比較しても、二次関数の動作が低下する可能性があり、この入力サイズには遅すぎます。 

重要なエッジケースは接尾辞の比較から得られます。 1 つの配列が使い果たされた場合は、選択肢がないため、残りの配列をコピーする必要があります。 例えば：```
1
A = [3]
B = [1]
```答えは次のとおりです。```
1 3
```最初の要素のみをチェックする貪欲なソリューションはここでは機能しますが、より複雑な場合には失敗します。 

もう 1 つのケースは、通常の文字列問題で最初の要素が等しい場合です。 ここでは、順列プロパティにより 2 つの配列間で同じ値が得られなくなりますが、常に 1 つの要素のみを比較できると想定したソリューションは失敗します。```
n = 3
A = [6, 10, 4]
B = [9, 8, 11]
```正解は次から始まります`6`、接尾辞があるため、`[6,10,4]`よりも小さいです`[9,8,11]`。 間違って選択した後、後の要素を見て決定を下すことはできません。 

## アプローチ

 強引なアイデアは、考えられるすべての選択肢のシーケンスを生成することです。 あらゆる瞬間に私たちが得ることができるのは、`A`またはから`B`したがって、可能なマージの数は次のようになります。$$\binom{2n}{n}$$のために`n = 100000`、これは実際的な限界をはるかに超えています。 それらの可能性のほんの一部を保存することさえ不可能です。 

より合理的な貪欲なアイデアは、常に小さい現在のフロント要素を選択することです。 これでは十分ではありません。 残りの配列が次の場所にあるという決定点を考慮してください。```
A = [4, 100]
B = [5, 1]
```取る`4`最初は正しいように見えますが、次の場合は次のようになります。```
A = [4, 100]
B = [4?]
```長い部分を比較する必要があります。 この問題では、等しい値は発生しませんが、同じ原則は変わりません。次の選択は、残りのサフィックス全体に依存します。 

重要な観察は、どの時点においても、辞書編集的に小さい残りの接尾辞を取得することが最適な動きであるということです。 もし`A[i:] < B[j:]`から取って`A`の将来の要素はすべて安全であるため、常に安全です`A`残りの要素の前に留まります`B`別の決定を下すまで。 大きい方の接尾辞から先に取得すると、2 つの接尾辞が異なる最初の位置では、すぐに悪い答えが得られます。 

残りの課題は、サフィックスを効率的に比較することです。 すべての要素よりも小さい区切り値を使用して 2 つの配列を連結し、すべてのサフィックスのランクを構築します。 プレフィックスを 2 倍にすることでこれらのランクが得られます`O(n log n)`時間。 その後、各サフィックス比較は定数時間のランク比較になります。 接頭辞の 2 倍化では、すべての接尾辞が一意のランクを持つまで、ますます長い接頭辞の辞書編集ランクが構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(2n,n)) | O(2n) | 遅すぎる |
 | サフィックスを直接比較する | O(n²) | お(1) | 遅すぎる |
 | サフィックスランク + 貪欲なマージ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 つの結合アレイを構築する`S = A + [0] + B`。 値`0`すべての実数値は正であるため、 は区切り文字として機能します。 この配列はサフィックスを比較するためにのみ使用され、答えを作成するために使用されません。 
2. すべての接尾辞の辞書編集上のランクを計算します。`S`プレフィックスダブリングを使用します。 各ランクは、どの接尾辞が小さいかを示します。 
3. 2 つのポインタを保持します。`i`現在の位置については`A`そして`j`現在の位置については`B`。 
4. 両方の配列にまだ要素がある間に、次から始まるサフィックスのランクを比較します。`i`で`A`そして`j`で`B`。 小さい方の接尾辞の最初の要素を追加し、そのポインタを前方に移動します。 
5. 一方の配列が空の場合は、もう一方の配列の残りの要素を直接追加します。 これ以上決定する必要はありません。 

貪欲な選択が機能する理由は、2 つの候補接尾辞間の最初の異なる位置によって、それらの接尾辞で始まるすべてのマージの辞書編集順序が決定されるためです。 小さい方のサフィックスを選択すると、最初の未決定の位置が可能な限り最適に保持され、1 つの要素を削除した後にこの引数を繰り返すと、選択されたすべての要素が最適なマージの一部であることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_ranks(arr):
    n = len(arr)
    vals = {v: i for i, v in enumerate(sorted(set(arr)))}
    rank = [vals[x] for x in arr]
    k = 1

    while k < n:
        order = list(range(n))
        order.sort(key=lambda x: (rank[x], rank[x + k] if x + k < n else -1))

        new_rank = [0] * n
        for idx in range(1, n):
            a = order[idx - 1]
            b = order[idx]
            if (rank[a], rank[a + k] if a + k < n else -1) != (
                rank[b],
                rank[b + k] if b + k < n else -1,
            ):
                new_rank[b] = new_rank[a] + 1
            else:
                new_rank[b] = new_rank[a]

        rank = new_rank
        k <<= 1

    return rank

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    combined = A + [0] + B
    rank = build_ranks(combined)

    ans = []
    i = 0
    j = n + 1

    while i < n and j < 2 * n + 1:
        if rank[i] < rank[j]:
            ans.append(A[i])
            i += 1
        else:
            ans.append(B[j - n - 1])
            j += 1

    while i < n:
        ans.append(A[i])
        i += 1

    while j < 2 * n + 1:
        ans.append(B[j - n - 1])
        j += 1

    print(*ans)

if __name__ == "__main__":
    solve()
```の`build_ranks`関数はサフィックス比較エンジンです。 最初は、すべてのサフィックスは最初の値によってのみランク付けされます。 各倍加ステップでは、現在のブロックのランクと次のブロックのランクを使用してサフィックスをソートします。 十分な反復の後、ランク配列は接尾辞の順序を完全に表します。 

区切り値`0`はすべての実数より小さいため、2 つの配列を安全に分離できます。 元の配列内のすべての数値は異なるため、`A`の接尾辞の接頭辞にすることはできません`B`, そのため、区切り文字によって誤った比較が行われることはありません。 

マージ ループは 2 つのポインターを維持します。 のポインタ`B`から始まります`n + 1`2 番目の配列は、結合された配列の区切り文字の後に始まるためです。 比較ではスキャン値の代わりに事前に計算されたランクを使用するため、作業の繰り返しが避けられます。 

Python の整数はオーバーフローせず、コードによって指数関数的な数の可能なマージが作成されることはありません。 唯一のデリケートな部分は、区切りインデックスを維持することと、結合された配列インデックスと配列インデックス間の変換を維持することです。`B`インデックスは正しいです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    n = int(sys.stdin.readline())
    A = list(map(int, sys.stdin.readline().split()))
    B = list(map(int, sys.stdin.readline().split()))

    combined = A + [0] + B

    def build_ranks(arr):
        n = len(arr)
        rank = [x for x in arr]
        k = 1
        while k < n:
            order = sorted(range(n), key=lambda x: (rank[x], rank[x+k] if x+k < n else -1))
            nr = [0] * n
            for a, b in zip(order, order[1:]):
                nr[b] = nr[a] + ((rank[a], rank[a+k] if a+k < n else -1) != (rank[b], rank[b+k] if b+k < n else -1))
            rank = nr
            k *= 2
        return rank

    r = build_ranks(combined)
    ans = []
    i, j = 0, n + 1

    while i < n and j < 2*n + 1:
        if r[i] < r[j]:
            ans.append(A[i])
            i += 1
        else:
            ans.append(B[j-n-1])
            j += 1

    ans += A[i:]
    ans += B[j-n-1:]

    sys.stdin = old
    return " ".join(map(str, ans)) + "\n"

 ## 特殊なケース

 1 つの配列が空になると、アルゴリズムは別の比較を試行しません。 のために：```
n = 1
A = [3]
B = [1]
```サフィックスランク比較で選択するのは`B`、生産`1 3`。 その後、`B`は空で残りは`3`が追加されます。 

よくある間違いは、現在の要素のみを比較することです。 ケース:```
A = [6,10,4]
B = [9,8,11]
```から始まる`6 < 9`、 それで`A`が選ばれます。 残りのサフィックスが変更されたため、後で比較が変更されます。 アルゴリズムは、保存されているサフィックス ランクを使用して削除のたびに選択を再計算することでこれを処理します。 

セパレータの位置もエラーが発生する場所です。 結合された配列には次のようにインデックスが付けられます。```
A + [0] + B
```したがって、の最初の要素は`B`インデックスにあります`n + 1`。 実装では、結合されたインデックスを比較用に保持し、変換して元のインデックスに戻します。`B`インデックスは、answer 要素を追加する場合にのみ使用できます。
