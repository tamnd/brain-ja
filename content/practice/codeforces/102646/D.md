 ## 解決策
 ## 問題の理解

 この問題は、バスケットボール チームの選択プロセスをモデル化しています。 がある`n`決まった順番で並んでいるプレイヤーとプレイヤー`i`スキル値がある`a[i]`。 正確に選択しなければなりません`k`プレーヤーは元の順序を維持しながら。 最初に選ばれたプレイヤーがマルチプライヤーを受け取ります`b[1]`、2番目は受け取ります`b[2]`、 等々。 目標は、選択したプレーヤーのスキルと割り当てられた乗数の合計である貢献度の合計を最大化することです。 

入力により、プレイヤーのスキルがラインナップ順に与えられ、`k`チーム内で選択された各ポジションの価値を表す乗数。 出力は、プレーヤーの最適なサブシーケンスを選択した後の最大の合計値です。 

主な制約は、`n <= 1000`。 これは十分に小さいため、二次動的計画法が現実的です。 解決策`O(n^2)`快適ですが、可能な限りすべてのセットを試しています`k`サブシーケンスの数は組み合わせで増加するため、プレーヤーは不可能です。 の値`a[i]`そして`b[i]`到達できる`100000`、したがって、答えは近辺にある可能性があります`10^13`つまり、実装では 64 ビット整数を使用する必要があります。 Python の整数はすでにこの範囲を処理しています。 

微妙な点は、最高のプレーヤーが必ずしも最大のスキル値を持っているわけではないということです。 大きなスキル値を持つプレーヤーは、後でより大きなマルチプライヤーに割り当てられるとより価値が高くなりますが、小さいプレーヤーは以前のポジションに保持される必要がある場合があります。 順序の制約により、単純にプレーヤーを並べ替えることができなくなります。 

例えば：```
Input:
3 2
10 1 10
1 100

Output:
1010
```プレイヤーをスキルごとに分類する不用意な解決策は、スキルのある 2 人のプレイヤーを選択する可能性があります`10`、これはたまたまここでは機能しますが、推論は不完全です。 重要な部分は、最初に選択されたプレーヤーの後に、選択されたプレーヤーに 2 番目の乗数を割り当てることです。 有効な選択肢はサブシーケンスであり、任意のグループではありません。 

乗数が大きく異なる場合には、別の特殊なケースが発生します。```
Input:
3 2
100 50 1
1 100

Output:
5100
```最初の 2 人のプレイヤーを選択すると、`100 * 1 + 50 * 100 = 5100`。 最大のスキルと最大の乗数を組み合わせ、ポジションを無視する貪欲なアプローチでは、1 番目と 3 番目のプレイヤーを使用しようとする可能性があります。`100 * 1 + 1 * 100 = 200`、それはさらに悪いことです。 

可能な限り最小のケースにも注意が必要です。```
Input:
1 1
7
9

Output:
63
```可能な選択肢は 1 つだけです。 少なくとも 1 人のプレイヤーがスキップされることを前提とした DP の初期化は、ここで失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチは、考えられるすべてのグループを列挙することです。`k`プレーヤーは元の順序を維持しながら。 選択したサブシーケンスごとに、最初に選択したスキルに次の値を乗算して貢献度を計算します。`b[1]`、2番目によって`b[2]`、 等々。 すべての有効なチームをチェックするため、これは正しいです。 

問題は可能なチームの数です。 から`n`プレイヤー、選択方法の数`k`は`C(n, k)`。 いつ`n = 1000`、これは天文学的に大きくなる可能性があります。 たとえ 1 つのチームの評価に時間がかかったとしても`k`運用を行っても、総作業量は依然として制限をはるかに超えています。 

重要な点は、プレーヤーを左から右にスキャンする際に重要な情報は、すでに選択されているプレーヤーの数だけであるということです。 ラインナップの一部のプレフィックスを処理して選択した場合`j`プレーヤーの場合、達成された最高の合計値を除いて、選択されたプレーヤーの正確な身元はもはや重要ではありません。 この重複する部分問題構造は、自然に動的プログラミングにつながります。 

ブルートフォースアプローチは、考えられるすべての決定が考慮されるため機能しますが、ほぼ同じ部分的な選択が何度も繰り返されます。 同じ処理されたプレフィックスと同じ数の選択されたプレーヤーを持つ 2 つのチームは、より良いスコアのみを必要とするという観察により、これらすべての可能性を小さな状態に圧縮することができます。 

私たちは定義します`dp[j]`プレーヤーのいくつかのプレフィックスを処理し、正確に選択した後に可能な最大スコアとして`j`選手たち。 新しいプレイヤーを検討するとき、私たちはそれらを無視するか、彼らを`(j+1)`-番目に選択されたプレイヤー。 状態を逆方向に更新すると、配列を 1 つだけ保存できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n,k) * k) | O(k) | 遅すぎる |
 | 最適 | O(nk) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`dp[0] = 0`そして他のすべての状態は不可能であると考えられます。 州`dp[j]`正確に選択した後の最高スコアを表します`j`これまでに処理されたプレーヤーからのプレーヤー。 
2. プレーヤーを左から右に 1 人ずつ処理します。 現在のスキル値を持つプレイヤーの場合`x`、次に選択されるプレイヤーとしてそれらを割り当ててみてください。 
3. 選択数を更新します`k-1`まで`0`。 もし`j`プレーヤーはすでに選択されており、現在のプレーヤーを選択すると、新しい値が与えられます。`dp[j] + x * b[j+1]`。 

現在のプレーヤーは 1 回しか選択できないため、逆の順序が必要です。 小さなことから更新中`j`大きい`j`同じプレイヤーが 1 回の反復で複数回貢献できるようになります。 
4. すべてのプレイヤーが処理されると、答えは次のようになります。`dp[k]`, この状態は、必要な数のプレイヤーを正確に選択していることを表すためです。 

不変条件は、ラインナップのプレフィックスを処理した後、`dp[j]`正確に選択するためのすべての方法の中で可能な限り最良の値が含まれています`j`そのプレフィックスからのプレーヤー。 現在のプレーヤーを無視すると、古い状態はすべて有効なままになります。 現在のプレーヤーを選択すると、すべての有効な状態が次のように拡張されます。`j`選択したプレイヤーを有効な状態にします`j+1`選ばれた選手たち。 可能な決定はこれら 2 つだけであるため、すべての有効なチームが考慮され、最高のスコアが保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    neg = -10**30
    dp = [neg] * (k + 1)
    dp[0] = 0

    for x in a:
        for j in range(k - 1, -1, -1):
            if dp[j] != neg:
                dp[j + 1] = max(dp[j + 1], dp[j] + x * b[j])

    print(dp[k])

if __name__ == "__main__":
    solve()
```配列`dp`選択したプレーヤーの可能な数ごとに現在の最良の値のみを保存します。 あり得ない状態は非常に小さい数から始まるため、有効な最大値になることはありません。 

プレーヤーを処理するとき、ループは次から始まります。`k - 1`そして下に移動します。 すでに選択した後に現在のプレーヤーを選択するための乗数`j`選手たちは`b[j]`Python はゼロベースのインデックスを使用するため、`b[0]`最初に選択されたプレーヤーの乗数です。 

ケースに別途対応する必要はありません`n = k`。 最終状態には正確な値が含まれている必要があるため、DP では当然、すべてのプレーヤーを使用するように回答が強制されます。`k`選択。 

最大寄与率は約に達する可能性があるため、答えは 32 ビット整数の制限を超える可能性があります。`1000 * 100000 * 100000`、つまり`10^13`。 Python の整数はオーバーフローの問題を回避します。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    data = inp.strip().split()
    it = iter(data)
    n = int(next(it))
    k = int(next(it))
    a = [int(next(it)) for _ in range(n)]
    b = [int(next(it)) for _ in range(k)]

    neg = -10**30
    dp = [neg] * (k + 1)
    dp[0] = 0

    for x in a:
        for j in range(k - 1, -1, -1):
            if dp[j] != neg:
                dp[j + 1] = max(dp[j + 1], dp[j] + x * b[j])

    return str(dp[k])

assert run("""3 2
1 2 3
2 1
""") == "7", "sample 1"

assert run("""5 4
5 9 10 3 2
10 10 5 5
""") == "215", "sample 2"

assert run("""1 1
7
9
""") == "63", "single player"

assert run("""3 2
100 50 1
1 100
""") == "5100", "large multiplier ordering"

assert run("""4 3
5 5 5 5
2 2 2
""") == "30", "all equal values"

 ## 特殊なケース

 マルチプライヤーのサイズが大きく異なる場合は、DP がプレイヤーの役割をすぐに決定しないため、処理されます。 のために：```
3 2
100 50 1
1 100
```最初の 2 人のプレイヤーを処理した後の状態には、両方のプレイヤーを獲得する可能性が含まれており、`100 * 1 + 50 * 100 = 5100`。 アルゴリズムは、スキルのみに基づいた貪欲な選択に置き換えるのではなく、この状態を維持します。 

シングルプレイヤーの場合:```
1 1
7
9
```から始まる`dp[0] = 0`。 唯一の移行によって作成されるのは、`dp[1] = 63`、これは必須の答えです。 更新ループが正しく停止するため、無効なアクセスはありません。`k - 1`。 

値が等しい場合:```
4 3
5 5 5 5
2 2 2
```最適なチームがたくさんあります。 DP は、選択された正確なインデックスではなく最良のスコアを保存するため、これを処理します。 どの 3 人のプレイヤーも同じ合計を与えます`30`したがって、最終的な状態は正しいままになります。
