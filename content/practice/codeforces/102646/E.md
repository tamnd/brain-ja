 ## 解決策
 ## 問題の理解

 次のような有向グラフがあります。`n`頂点と`m`エッジ。 元のグラフは強く接続されていることが保証されており、すべての頂点が指定されたエッジを使用して他のすべての頂点に到達できることを意味します。 正確に守らなければなりません`k`これらの端を切り取り、残りを削除します。 目標は、残りのグラフにできるだけ多くの強く接続されたコンポーネントを持たせることです。 出力は、コンポーネントの最大数と ​​1 つの有効なセットです。`k`それを実現するエッジインデックス。 

重要な制限は、`k`よりも小さいです`n`。 すべての頂点はすでに別個の強く接続されたコンポーネントである可能性があるため、絶対最大の答えは次のようになります。`n`。 問題は、私たちが常に選択できるかどうかです`k`誤って有向サイクルを作成することなくエッジを作成できます。 

と`n`まで`100000`そして`m`まで`200000`、エッジの多くのサブセットを試行したり、SCC を繰り返し再計算したりするソリューションは、非常に遅すぎます。 一般的なコンテスト設定では使用できる操作が数百万しかないため、グラフのサイズが線形に近いソリューションが必要です。 

よくある間違いは、任意のエッジを選択することです。 例えば：```
3 3 2
1 2
2 3
3 1
```正しい出力は次のとおりです。```
3
1 2
```エッジがあるので`1 -> 2`そして`2 -> 3`有向チェーンを形成するため、すべての頂点が独自の SCC になります。 不用意なエッジの選択`1`そして`3`サイクルを生み出す`1 -> 2 -> 3 -> 1`エッジのためここでは不可能です`2`がありませんが、3 つのエッジをすべて選択すると、明らかに 1 つの SCC が作成されます。 重要な点は、選択したエッジがサイクルを回避する必要があるということです。 

もう一つのエッジケースは、`k = 0`。```
5 5 0
1 2
2 3
3 4
4 5
5 1
```正しい出力は次のとおりです。```
5
```空のグラフには異なる頂点間にパスがないため、すべての頂点が個別の SCC になります。 常に少なくとも 1 つのエッジを出力しようとする実装は失敗します。 

最後のエッジ ケースは、グラフが密で、すべての頂点に多数の入力エッジと出力エッジがある場合です。 例えば：```
4 6 3
1 2
2 3
3 4
4 1
1 3
2 4
```正解はまだ`4`。 密度は関係ありません。 必要なのは、疎なグラフではなく、エッジの小さな非巡回サブセットだけです。 

## アプローチ

 直接的なアプローチでは、さまざまなセットを試します。`k`エッジを検出し、各選択肢の SCC カウントを計算します。 これは正しいです。考えられるすべてのサブセットをチェックすると、最適なサブセットが確実に見つかるからです。 ただし、選択肢の数は、`C(m, k)`、小さなグラフであっても巨大になります。 すべての選択を行った後で SCC アルゴリズムを実行することは不可能です。 

有益な観察は、元のグラフが強く結びついているという事実から得られます。 DFS は任意の頂点から開始して、他のすべての頂点に到達できます。 DFS ツリーには正確に次の内容が含まれています`n - 1`これらのエッジは常に親から子への有向ツリーを形成します。 ツリーには有向サイクルがないため、そのツリー内のすべての頂点が独自の SCC になります。 

以来`k < n`、どれでもお受けできます`k`この DFS ツリーからのエッジ。 結果のグラフは非循環のままになります。つまり、正確に`n`強く接続されたコンポーネント。 これはすでに理論上の最大値であるため、これ以上複雑な最適化は必要ありません。 

ブルート フォースは、残りのグラフをすべて探索するため機能しますが、検索スペースが巨大であるため失敗します。 DFS ツリーの観察により、すべてのエッジ サブセット間の検索から 1 つの保証された最適なサブセットの構築までの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(m, k) * (n + m)) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の頂点 (頂点など) から DFS を実行します。`1`。 DFS がエッジを介して新しい頂点にアクセスするたびに、そのエッジを DFS ツリーの一部として記録します。 グラフは強く結びついているため、このプロセスはすべての頂点を訪問します。 
2. 最初のものを取る`k`DFS ツリー エッジを記録し、そのインデックスを出力します。 これらは非環状構造に由来するため、必須のエッジです。 
3. もし`k`が 0 の場合、選択されたエッジを 0 として出力します。 空のグラフには、すでに SCC の最大数が示されています。 

なぜ効果があるのか:

 選択されたエッジは DFS ツリーのサブセットです。 このツリー内のすべてのエッジは、親頂点から子頂点を指します。 選択したエッジをたどるとツリーの下方向にしか移動できないため、すでに訪問した頂点に戻ることはできません。 選択したグラフは DAG です。 DAG では、2 つの異なる頂点が相互に到達できないため、すべての頂点が独自の SCC を形成します。 したがって、答えは次のとおりです`n`、これは SCC の最大可能数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    graph = [[] for _ in range(n)]

    for i in range(1, m + 1):
        u, v = map(int, input().split())
        graph[u - 1].append((v - 1, i))

    ans = []
    seen = [False] * n

    sys.setrecursionlimit(300000)

    def dfs(u):
        seen[u] = True
        for v, idx in graph[u]:
            if not seen[v]:
                ans.append(idx)
                if len(ans) == k:
                    return True
                if dfs(v):
                    return True
        return False

    if k > 0:
        dfs(0)

    print(n)
    if k:
        print(*ans)

if __name__ == "__main__":
    solve()
```出力にはエンドポイントではなくエッジ番号が必要であるため、隣接リストには宛先頂点と元のエッジ インデックスの両方が格納されます。 

DFS は、新しい頂点を最初に検出したときにエッジを正確に記録します。 これにより、記録されたエッジがグラフの到達可能な部分のスパニング ツリーになります。 グラフは頂点から強くつながっているので`0`あらゆる頂点に到達します。 

再帰はすぐに停止します`k`エッジが集まっています。 唯一の目標は、ツリー全体ではなく、有効な最適なサブセットを出力することであるため、これは安全です。 条件`k < n`DFS ツリーに常に十分なエッジが含まれていることを保証します。 

構築後のSCC計算は必要ありません。 この証明により、選択したエッジが DAG を形成し、可能な最大の答えが得られることがすでに保証されています。 

## 実用的な例

 最初のサンプルの場合:```
4 5 1
1 2
2 3
1 4
4 3
3 1
```考えられる DFS トラバーサルの 1 つは頂点から始まります`1`。 

| ステップ | 現在の頂点 | 選択されたエッジ | 選択されたエッジ |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 -> 2 | 1 |

 アルゴリズムが停止する理由は、`k = 1`。 

選択したグラフにはエッジのみが含まれています`1 -> 2`。 サイクルが存在しないため、4 つの頂点はすべて個別の SCC になります。 答えは`4`。 

カスタムの例:```
5 5 3
1 2
2 3
3 4
4 5
5 1
```DFS ツリーは、すべての頂点が検出されるまでサイクルに従います。 

| ステップ | 現在の頂点 | 選択されたエッジ | 選択されたエッジ |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 -> 2 | 1 |
 | 2 | 2 | 2 -> 3 | 1 2 |
 | 3 | 3 | 3 -> 4 | 1 2 3 |

 選択したエッジがチェーンを作成します`1 -> 2 -> 3 -> 4`。 頂点`5`この選択されたサブセットからは切断されていますが、それは許可されています。 サイクルがないため、すべての頂点は独立した SCC のままとなり、答えは次のようになります。`5`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(n + m) | 隣接関係リストと DFS 状態配列には、グラフ |

 ## 特殊なケース

 いつ`k = 0`、アルゴリズムは DFS 選択をスキップし、印刷のみを行います。`n`。 これは、空の有向グラフには非自明な SCC がないという事実と一致します。 頂点が 5 つあり、エッジが選択されていない例の場合、答えは次のようになります。`5`。 

いつ`k`に近いです`n`、すべてのスパニング ツリーが正確にエッジを持っているため、DFS ツリーは依然として十分なエッジを提供します。`n - 1`エッジ。 グラフの場合`n = 5`そして`k = 4`の場合、アルゴリズムは 4 つのツリー エッジすべてを出力できますが、選択されたグラフは依然として非巡回です。 

元のグラフに多くのサイクルが含まれている場合、それらのサイクルは無視されます。 たとえば、以下を含むグラフでは、`1 -> 2 -> 3 -> 1`、DFS ツリーはのみを選択できます`1 -> 2`そして`2 -> 3`。 削除されたバック エッジはまさに頂点を 1 つの SCC にマージしたものであるため、それを除外することで最適な結果が得られます。
