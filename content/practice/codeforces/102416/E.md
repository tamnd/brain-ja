 ## 解決策
 ## 問題の理解

 最大 100 個の球状の保護領域があります。 宇宙船 (i) には中心 ((x_i,y_i,z_i)) と半径 (r_i) があります。 元の球体が内部で重ならないように、いくつかの宇宙船を選択する必要があります。 中心間の距離が半径の合計に正確に一致する 2 つの球は互いに素であるとみなされるため、接線は許可されます。 

宇宙船を選択すると、その責任は半径 (r_i) から半径 (3r_i) に拡大します。 展開された球は自由に重なり合うことができます。 それらの結合は、少なくとも 1 つの元の球によってカバーされていたすべてのポイントをカバーする必要があります。 

出力は、宇宙船インデックスの有効なサブセットです。 あ`NO`答えはステートメントで許可されていますが、実際にはジオメトリがすべての入力の構造を提供するため、アルゴリズムが出力する必要はありません。`NO`。 

制約 (n\le100) により、(O(n^2)) 個の解が 1 秒以内に自明になります。 座標と半径は最大 (10^4) であるため、距離の 2 乗は最大でもおおよそ (3\cdot10^8) であり、半径の 2 乗を含む式も、Python 整数および通常の 64 ビット整数の範囲内で安全に使用できます。 比較には整数演算のみが必要であるため、平方根を計算する代わりに距離の二乗を比較する必要があります。 

微妙な部分は、ばらばらであることと適用範囲の間の相互作用です。 コレクションが任意の順序で構築される場合、単に結合していない球の最大コレクションを選択するだけでは十分ではありません。 半径 (1) の小さな球が、半径 (100) のはるかに大きな球と交差しているとします。 小さな球が最初に選択されると、大きな球が選択されなくなる可能性があり、小さな球の 3 倍に拡張された領域は大きな球をカバーできるほど大きくありません。 

たとえば、次のように考えてみましょう```
2
0 0 0 1
100 0 0 100
```2 つの球は接しているため、両方を選択することも、正解に両方を含めることもできます。 危険なケースは、代わりにわずかに重複しています。```
2
0 0 0 1
99 0 0 100
```(99<101) ため、半径 1 の球と半径 100 の球は重なり合います。 最初に小さな球を選択すると、大きな球は破棄されます。 拡張された半径は (3) のみであり、明らかに元の大きな球をカバーできません。 最初に最大の半径を処理することで、この間違いを回避できます。 

接線も境界ケースの 1 つです。 のために```
2
0 0 0 1
2 0 0 1
```中心間の距離は (2=r_1+r_2) であるため、両方の球を選択できます。 を使用した不注意な実装`<=`2 つの球が競合するかどうかを判断するときに、2 番目の球が誤って拒否されてしまいます。 

同一の球体は、別の有用なエッジケースを提供します。```
2
5 5 5 7
5 5 5 7
```それらの距離はゼロであるため、選択できるのは 1 つだけです。 どちらを選択しても、半径 (21) の拡張された球があり、元の球の両方をカバーします。 半径の順序の等価性を間違って扱っても証明は崩れませんが、一致する球を素として扱うと無効な答えが生成されます。 

## アプローチ

 直接的な総当たり戦略は、(n 個の) 宇宙船のすべてのサブセットを列挙し、それが有効な選択であるかどうかをテストすることです。 (2^n) 個のサブセットがあります。 すべての元の球体が、選択した 1 つの宇宙船の 3 倍に拡張された球体に含まれなければならないというより強力な条件を使用したとしても、1 つの候補サブセットをチェックするには (O(n^2)) 時間がかかります。つまり、すべての元の球体と選択したすべての球体を比較できます。 (n=100) では (O(2^{100}n^2)) となり、最悪の場合、およそ (1.3\cdot10^{34}) のペア チェックになります。 それはまったく不可能です。 

この問題は、拡張後のカバレッジを維持しながら、元の球の交差グラフで独立した集合を見つけることを実際に求めているため、強引なアイデアが機能します。 障害は、一般的な最大独立集合問題が指数関数的であることです。 

重要な幾何学的観察は、最大独立集合は必要ないということです。 拡張された球がすべてをカバーする独立したセットのみが必要です。 最大半径から最小半径まで球を処理し、以前に保持されていたすべての球と結合していない球を貪欲に保持します。 

球 (i) が拒否されたとします。 これは、すでに選択されている球 (j) と交差します。 半径の大きい順に処理するので、(r_j\ge r_i)となります。 交差点は、

 [
 d(c_i,c_j)<r_i+r_j。 
]

 球 (i) 内の任意の点 (p) を取得します。 (j) の中心からの距離は最大で

 [
 d(c_j,p)\le d(c_j,c_i)+r_i
 <r_j+2r_i
 \le3r_j.
 ]

 したがって、球 (i) のすべての点は、以前に選択した球 (j) の半径 (3r_j) 球の内側にあります。 

これが半径を小さくして処理する理由のすべてです。 拒否された球体は常に、その拒否を引き起こした球体よりも大きくないため、重複不等式が必要な 3 の因数に変わります。 

ブルート フォース検索では、安全な選択肢を特定する方法がないため、考えられるすべてのサブセットが試行されます。 半径の順序付けは、まさにその情報を提供します。球が拒否されるたびに、以前に選択された球は、その 3 倍の拡張で拒否された球を完全にカバーするのに十分な大きさであることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n n^2)) | (O(n)) | 遅すぎる |
 | 半径を小さくして欲張りに | (O(n^2)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての球を読み取り、元のインデックスを保持します。 半径を小さくして並べ替えます。 証明に必要なのは (r_j\ge r_i) のみであるため、等しい半径は任意の決定論的な順序で処理できます。 
2. 選択した球のリストを維持します。 最初は空です。 球 (i) を検討するときは、その中心をすでに選択されているすべての球 (j) と比較します。 
3. 2 つの球は、それらの中心距離が少なくとも (r_i+r_j) である場合に正確に素になります。 比較して平方根を回避する

 [
 d^2\ge(r_i+r_j)^2。 
]

 これが選択したすべての球体に当てはまる場合は、答えに (i) を追加します。 接球は互いに素であるとみなされるため、等価性が許可されます。 

1. 球 (i) が選択した球と交差する場合、それを拒否します。 選択した球は以前に処理されているため、その交差する球には少なくとも (r_i) の半径があります。 
2. すべての球が処理された後、選択したインデックスを出力します。 構築では常に有効な答えが生成されるため、`NO`決して到達しません。 

### なぜ効果があるのか

 不変条件は、半径でソートされた順序の接頭辞を処理した後、選択されたすべての球がペアごとに素であり、その接頭辞から拒否されたすべての球が、選択された球の 3 倍に拡張された領域で完全にカバーされることです。 

ペアごとの素性は、以前に選択されたすべての球体から素である場合にのみ、球体を受け入れることから直接発生します。 カバレッジについては、拒否された球 (i) を考慮し、それと交差する選択された球を (j) とします。 (j)は先に処理されているので、(r_j\ge r_i)。 (i) 内の任意の点 (p) について、

 [
 d(c_j,p)
 \le d(c_j,c_i)+d(c_i,p)
 < (r_i+r_j)+r_i
 = r_j+2r_i
 \le3r_j.
 ]

 したがって、(i) のすべての点は (j) の拡張された球に属します。 選択した球体は、拡張された半径が元の半径よりも大きいため、それ自体を覆います。 したがって、元の保護ポイントはすべて保護されたままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    spheres = []

    for idx in range(1, n + 1):
        x, y, z, r = map(int, input().split())
        spheres.append((x, y, z, r, idx))

    # Larger spheres must be considered first.
    spheres.sort(key=lambda s: (-s[3], s[4]))

    selected = []

    for x, y, z, r, idx in spheres:
        disjoint = True

        for j in selected:
            x2, y2, z2, r2, _ = j

            dx = x - x2
            dy = y - y2
            dz = z - z2

            dist2 = dx * dx + dy * dy + dz * dz
            limit = r + r2

            # Tangency is allowed, so equality means disjoint.
            if dist2 < limit * limit:
                disjoint = False
                break

        if disjoint:
            selected.append((x, y, z, r, idx))

    print(len(selected))
    print(*[s[4] for s in selected])

if __name__ == "__main__":
    solve()
```入力ループは、座標、半径、および元のインデックスを一緒に保存します。 出力では、ソート後の位置ではなく、入力での位置によって宇宙船が参照されるため、元のインデックスが必要になります。 

並べ替えキーは次を使用します。`-r`したがって、より大きな半径が最初に来ます。 2 番目のコンポーネントである元のインデックスは、等半径処理を決定的にするだけです。 この証明は、等しい半径内のいずれの次数に対しても機能します。 

すべての候補球について、内側のループはすでに選択されている球のみをチェックします。 いずれかの内部が重複している場合、候補は拒否されます。 比較には二乗距離が使用されるため、浮動小数点演算は必要ありません。 

厳密な比較`dist2 < limit * limit`は不可欠です。 いつ`dist2 == limit * limit`、球は接しており、問題は両方を選択することを明示的に許可します。 使用する`<=`接球を誤って拒否してしまう可能性があります。 

Python の整数には任意の精度があるため、オーバーフローの心配はありません。 固定幅の 64 ビット演算であっても、指定された境界により、これらの二乗値は範囲内に快適に収まります。 

ソート順の最初の球には競合するものが何もないため、出力には常に少なくとも 1 つの球が含まれます。 より一般的には、証明は、選択されたセットが常にカバレッジ条件を満たしていることを示しているため、印刷`NO`は不要です。

 サンプル 1 の場合、```

2

 ## 特殊なケース

 別の球に接する球を交点として扱ってはなりません。 のために```
2
0 0 0 1
2 0 0 1
```最初の球が選択されます。 2 番目の中心距離の 2 乗は (4)、半径の 2 乗和も (4) です。 拒否の条件は厳密な不等式であるため、2 番目の球も選択されます。 最終的に拡張された領域は、元の両方の球体をカバーします。 

球体が一致する、または重なっている場合は、別の方法で処理されます。 のために```
2
5 5 5 7
5 5 5 7
```中心距離の二乗は (0)、半径の二乗合計は (196) です。 2 番目の球は拒否されます。 両方の球が同一であるため、最初に選択した球の拡張半径は (21) となり、元の半径 7 の領域を両方カバーします。 

最も重要な順序付けのエッジ ケースは、はるかに大きな球に重なる小さな球です。```
2
0 0 0 1
3 0 0 2
```半径 2 の球が最初に考慮され、選択されます。 半径 1 の球は、中心距離 (3) が (2+1=3) より小さいため拒否されます。 ここでの等価性は、実際には球が接していることを意味するため、これも選択されます。 厳密な重複を示すには、代わりに次を使用します。```
2
0 0 0 1
2 0 0 2
```ここで、中心距離は (2<3) であるため、小さな球は拒否されます。 その小さな球内のどの点でも、大きな球の中心からの距離は最大 (2+1=3) であり、実質的な余裕を持った拡張半径 (3\cdot2=6) となります。 大きな球体の膨張がそれをすっぽり覆う。 

最後に、選択された球が 1 つあるという理由で、他の選択された球が複数存在する場合でも球が拒否されることがあります。 アルゴリズムは、最適なカバー球を特定する必要はありません。 半径の順序付けにより、この球が拒否された球と少なくとも同じ大きさであることが保証されるため、最初に交差する選択した球で十分です。 この 1 つの事実は、係数 3 のカバレッジの証明を提供し、貪欲な構築が後戻りすることなく有効であり続ける理由です。
