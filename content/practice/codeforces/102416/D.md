 ## 解決策
 ## 問題の理解

 公平なサイコロを繰り返して振ります`k`顔。 成功したロールとは、次のことを示しています。`1`、それが見えたらすぐにゲームは終了します`n`連続成功ロール。 すべてのロールのコストは £1 であるため、必要な賞品は、最初のロールが発生するまでの予想ロール数とまったく同じです。`n`連続したもの。 

入力は次のもので構成されます`k`、サイコロの面の数、および`n`、連続するストリークの必要な長さ。 出力は予想されるロール数であり、絶対誤差または相対誤差は最大で`10^-4`。 公式の制約は次のとおりです`3 <= k <= 20`そして`1 <= n <= 5`。 

小さな上限は`n`シミュレーションや状態ベースの動的プログラムを示唆するかもしれませんが、必要な量は正確な期待値であり、特定のランダムな実験ではありません。 シミュレーションには大量のロールが必要になる可能性があり、答えは近似的にしか得られません。 有益な観察は、すべてのロールの成功確率が次のように固定されていることです。`1/k`、そして私たちの将来に影響を与える過去からの唯一の情報は、完全に 1 で構成される現在の接尾辞の長さです。 

誤って処理されやすい境界ケースがいくつかあります。 のために`n = 1`、1つですでにゲームが終了します。 たとえば、入力の場合`3 1`、予想ロール数は`3`、すべてのロールには確率があるため、`1/3`ゲームを終了することについて。 空ではない中間ストリーク状態が常に存在すると仮定した繰り返しでは、ここで誤って間違った値が返される可能性があります。 

もう 1 つのよくある間違いは、勝ちロールを含めずに、その後の出目の数を数えることです。 のために`k = 6, n = 2`、正解は`42`、 ない`41`, なぜなら、ウイニングロール自体のコストは1ポンドだからです。 サンプルはこの値を確認しています。 

3 番目の問題は、ストリークを延長しようとして失敗すると、現在のストリークが完全にリセットされることを忘れていることです。 と`k = 3, n = 2`、次のようなシーケンス`1, 1`2ロール後に終了しますが、`1, 2, 1, 1`4時過ぎには終わります。 その後`2`、早いほど`1`連勝記録更新には貢献できない。 

## アプローチ

 直接的な総当りのアイデアは、サイコロの目の可能なシーケンスを生成し、各シーケンスが最初に次の要素を含むタイミングを決定することです。`n`連続したもの。 これは概念的には正しいです。すべての有限シーケンスには既知の確率があり、すべての可能な結果の停止時間を平均化することで望ましい期待値が得られるからです。 問題は、プロセスの最大長が固定されていないことです。 シーケンスは任意の数のロールでターゲット ストリークを回避できるため、網羅的な列挙には有限の最悪の場合の停止限界がありません。 後は人為的に止めても`L`ロール、あります`k^L`検査するシーケンスがあり、それはすぐに実行不可能になります。 

代わりに、現在のストリークの長さを使用してプロセスを記述することができます。 させて`E_i`現在のサフィックスに正確に含まれる場合に必要となる追加のロールの予想数になります。`i`連続したもの、ここで`0 <= i < n`。 州から`i`、次のロールは 1 ロールかかります。 確率で`1/k`、それは別のものであり、次の状態に移ります。`i + 1`。 確率で`(k - 1)/k`、それは 1 ではなく、ストリークは状態にリセットされます。`0`。 

したがって、`E_i = 1 + (1/k) E_{i+1} + ((k-1)/k) E_0`と`E_n = 0`。 

重要な単純化は、実際にはこれらすべての方程式を数値的に解く必要がないことです。 最後の状態から開始して逆方向に代入すると、等比和が生成されます。 結果は`E_0 = (1 - (1/k)^n) / ((1 - 1/k)(1/k)^n)`。 

分子と分母に次の値を掛ける`k^n`よりきれいな整数表現が得られます`E_0 = (k^(n+1) - k) / (k - 1)`。 

たとえば、`k = 6`そして`n = 2`、これは与えます`(6^3 - 6) / 5 = 210 / 5 = 42`。 

答えは実際には、次のすべての有効な整数値に対する整数です。`k`そして`n`なので、浮動小数点演算は不要です。

 | 最適 |`O(1)`|`O(1)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`k`そして`n`。 1 が出る確率は`1/k`、他のものを転がす確率は`(k-1)/k`。 
2. 現在の連続 1 接尾辞の長さによってプロセスをモデル化します。 現在のサフィックスに長さがある場合`i`、1 つ増加すると、`i+1`、他の値はゼロにリセットされます。 これにより、残りの待ち時間に影響を与える可能性のある過去の情報がすべて取得されます。 
3. しましょう`E_i`状態から予想される残りのロール数を示します`i`。 ターミナルの状態は、`E_n = 0`, 必要なストリークがすでに取得されているためです。 
4. すべての非終端状態について、1 ステップの期待値を書き込みます`E_i = 1 + E_{i+1}/k + (k-1)E_0/k`。 

の`1`私たちがこれから作ろうとしているロールを説明します。 残りの 2 つの項は、考えられる 2 つの次の状態を表します。 
5. 漸化式を逆方向に解きます。 繰り返しの置換により表現されます`E_0`それ自体と等比数列に関して。 結果として得られる方程式は次のように単純化されます。`E_0 = (k^(n+1) - k)/(k-1)`。 
6. 整数演算を使用してその式を計算し、出力します。 許可される最大の答えは最大です`10^9`したがって、Python の整数演算は計算を快適に処理します。 

### なぜ効果があるのか

 州`i`は常に、次のロールの直前に連続する 1 の数を正確に表します。 現在のサフィックスの長さが判明すると、古いロールは将来のロールに影響を及ぼさないため、これで十分です。 各状態から、反復では考えられるすべての次の結果が考慮され、その次のロールに 1 つだけが追加されます。 以来`E_n = 0`、再帰を解くと、初期状態を含むすべての状態からの予想停止時間が得られます。`E_0`。 閉じた形式は単にこれらの期待方程式の正確な解であるため、アルゴリズムはランダムなシミュレーションに基づく推定値ではなく、必要な期待ロール数を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())

    answer = (k ** (n + 1) - k) // (k - 1)
    print(f"{answer:.2f}")

if __name__ == "__main__":
    solve()
```プログラムは 2 つのパラメーターを読み取り、反復から得られた閉じた形式を直接評価します。 反復はすでに代数的に単純化されているため、個々のストリーク状態を構築する必要はありません。 

指数は`n + 1`、 ない`n`。 これは一般的な off-by-one エラーです。 のために`n = 1`、式は次のようになります`(k^2-k)/(k-1) = k`これは、まさに 1 回のロールが成功するまでに予想される待ち時間です。 

引き算も、`k`、与える`k^(n+1) - k`。 のみを使用する`k^(n+1)`値が大きい場合は近いように見えても、不正確な結果が生成されます。 

式は常に整数であるため、整数の除算は安全です。 さらに重要なことは、書式設定の前に浮動小数点の丸めを導入することを回避できることです。 出力では小数点以下 2 桁が使用されており、必要な範囲内に収まります。`10^-4`許容範囲。

## テストケース```python
import sys
import io

def solve():
    k, n = map(int, input().split())
    answer = (k ** (n + 1) - k) // (k - 1)
    print(f"{answer:.2f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("6 2\n") == "42.00", "sample 1"

# Minimum k and minimum n
assert run("3 1\n") == "3.00", "single one on a 3-sided die"

# Maximum k and maximum n
assert run("20 5\n") == "3368420.00", "maximum constraints"

# Two-sided streak with the smallest possible die
assert run("3 2\n") == "6.00", "short streak"

# Boundary case n = 1 with a larger die
assert run("20 1\n") == "20.00", "single one on a 20-sided die"

 ## 特殊なケース

 のために`3 1`、ターゲットは単に 1 に等しい最初のロールです。 式は次のようになります`(3^2 - 3)/(3-1) = 3`したがって、出力は次のようになります`3.00`。 誤って使用してしまう解決策`k^n`の代わりに`k^(n+1)`この場合はすぐに失敗します。 

のために`6 2`、目標は2回連続です。 式は次のようになります`(6^3 - 6)/5 = 42`したがって、出力は次のようになります`42.00`。 このケースでは、期待値には最後のストリークを作成するロールが含まれているため、成功したロールにチャージする前にカウントを停止するという間違いが見つかります。 

のために`3 2`、期待値は`(3^3 - 3)/2 = 12/2 = 6`。 有用な手動トレースは、プロセスが状態 0 で開始し、1 の後に 1 の状態に移動し、次の 1 の後に最終状態に到達し、1 以外の状態の後に 0 に戻ることです。 繰り返しには両方の遷移が含まれるため、ロールの各ペアを独立した試行として扱うのではなく、繰り返し失敗した試行が考慮されます。 

のために`20 5`、答えは`(20^6 - 20)/19 = 3,368,420`。 これは、与えられた制約の最大のコーナーであり、個々のロールをシミュレートすることが期待値を計算する方法として不適切である理由を示しています。 閉じた形式ではすぐに答えに到達しますが、実際のランダムなプロセスでは、目的の縞が現れるまでに数百万回のロールが必要になる場合があります。
