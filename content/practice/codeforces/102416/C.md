 ## 問題の理解

 正確に作る必要がある`d`小銭のドル。 利用可能な硬貨の額面は以下のすべての整数です。`a`ある上限を通過して`b`を含み、どの額面でも何度でも使用できます。 タスクは可能な限り最小のものを見つけることです`b`誰のために`d`これらのコインの合計として表すことができます。 

入力には以下が含まれます`a`そして`d`、 と`1 <= a <= d <= 10^9`。 値は 10 億に達する可能性があるため、可能な値の線形数をチェックするアルゴリズムは、1 秒の制限に対してコストが高すぎます。 候補値を 1 つずつ試すのではなく、問題を定数時間演算に縮小する必要があります。 

最初の境界ケースは、`a = d`。 唯一の作り方は`d`価値のあるコインを使うことです`d`、したがって、答えは次のようになります。`d`。 例えば、`10 10`与える`10`。 少なくとも 2 枚のコインが必要であると想定する不注意なアプローチでは、誤って小さい値が返される可能性があります。 

もう一つの小さなケースは、`a = 1`。 例えば、`1 7`答えがあります`1`、価値のあるコインだから`1`単独であらゆるプラスの金額を生み出すことができます。 から始まる検索`a + 1`これはすぐに見逃してしまうでしょう。 

場合`d`で割り切れます`a`も重要です。 のために`6 18`、価値のあるコイン 3 枚`6`すでに目標を立てているので、`b = 6`。 丸めに基づく解決策`d / floor(d / a)`浮動小数点演算を誤って行うと、大きな値で精度の問題が発生する可能性があるため、整数の上限除算が推奨されます。 

## アプローチ

 直接的なアプローチは、考えられるすべての上位宗派を試してみることです`b`、から始まります`a`。 各候補者について、次のことを判断できます。`d`のコインを使用して形成できます`a`を通して`b`。 これは正しいです。候補を昇順に検査するため、最初の実行可能な候補が必然的に最小値になります。 

問題はそれです`b`と同じ大きさにすることができます`d`、 そして`d`できる`10^9`。 最悪の場合、これは大まかにチェックすることを意味します`10^9`候補者たち。 たとえ各候補を一定時間内にテストできたとしても、それは約 10 億回の操作に相当し、1 秒の制限時間としては決して適切とは言えません。 

有益な観察は、最大額面を固定するのではなく、コインの数を固定することから得られます。 正確に使用するとします`k`コイン。 可能な最小の合計は`ka`、すべてのコインは少なくとも`a`。 可能な最大の合計は`kb`、すべてのコインは最大でも`b`。 

さらに重要なのは、どの宗派も`a`そして`b`存在する、間のすべての整数の合計`ka`そして`kb`達成可能です。 したがって`d`正確に形成できます`k`コインを正確にいつでも`ka <= d <= kb`。 

最初の不等式は次のようになります。`k <= floor(d / a)`。 させて`q = floor(d / a)`。 

せいぜい使えるのであれば`q`コイン、次に選択`q`コインは下限に関して可能な限り最大の柔軟性を提供します。`qa <= d`。 私たちに必要なのは`b`十分に大きい`q`コインは届く`d`、つまり`qb >= d`。 

したがって、可能な限り小さい`b`は`ceil(d / q)`、

どこ`q = floor(d / a)`。 

以下を考慮する理由はありません`q`コイン。 もし`k < q`、 それから`ceil(d / k) >= ceil(d / q)`、そのため、必要なコインの数を減らすと、必要な最大額面が大きくなるか、同等になるだけです。 可能性のある総当たり検索`b`その結果、 は 2 つの整数除算に減らされました。

 ## アルゴリズムのチュートリアル

 1.読む`a`そして`d`。 これらは利用可能なコインの最低値と目標金額です。 
2. コンピューティング`q = d // a`。 これは少なくとも価値のあるコインの最大数です`a`おそらく合計に収まる可能性があります`d`。 
3. 最小額面境界を計算します。`q`コインが届く`d`。 必要です`q * b >= d`したがって、整数の上限除算を使用します。`b = (d + q - 1) // q`。 
4. 印刷`b`。 以来`q`は実現可能な最大のコイン数であり、この値は可能な最小の上限額です。 

### なぜ効果があるのか

 しましょう`q = floor(d / a)`。 以来`qa <= d`を使用して`q`すべてのコインに価値がある場合、コインは目標を超えることはありません`a`。 私たちにはそれらが必要です`q`到達可能なコイン`d`、これには次のことが必要です`qb >= d`。 

利用可能な単位は以下の完全な整数区間を形成するため、`a`に`b`、間のすべての合計`qa`そして`qb`正確に達成可能です`q`コイン。 したがって`b = ceil(d / q)`で十分です。 

コインの枚数が少ない場合`k < q`、到達`d`必要になるだろう`b >= ceil(d / k)`。 以来`k < q`、 我々は持っています`ceil(d / k) >= ceil(d / q)`。 したがって、これ以上小さくはありません`b`少ないコインで作業できます。 計算された値は実現可能かつ最小です。

表現`(d + q - 1) // q`浮動小数点演算を行わずに天井除算を実行します。 入力には次の値まで含めることができるため、これは重要です。`10^9`、整数演算では、丸めを考慮せずに正確な結果が得られます。

import sys

def solve(data: str) -> str:
    a, d = map(int, data.split())

    q = d // a
    b = (d + q - 1) // q

    return str(b)

def run(inp: str) -> str:

 ## 特殊なケース

 のために`a = d`、 考慮する`10 10`。 計算すると、`q = 10 // 10 = 1`、 に続く`b = ceil(10 / 1) = 10`。 ターゲットを作成できる唯一の利用可能な金種は次のとおりであるため、結果は正しいです。`10`自体。 このアルゴリズムは、複数のコインが必要であると誤って想定することはありません。 

のために`a = 1`、 考慮する`1 7`。 取得します`q = 7`、 それで`b = ceil(7 / 7) = 1`。 これは、単一宗派であることを示しています。`1`十分です。 確かに価値のある7枚のコイン`1`ターゲットを正確に設定します。 このケースでは、答えが可能な最小の入力値と等しくなることも確認されています。`a`。 

正確に割り切れるターゲットについては、次のことを考慮します。`6 18`。 ここ`q = 18 // 6 = 3`、 そして`b = ceil(18 / 3) = 6`。 貴重なコイン 3 枚`6`作る`18`, したがって、それ以上の額面は必要ありません。 計算は正確に当てはまります`a`、これは可能な限り最小の答えです。 

分割できないターゲットの場合は、次のことを考慮します。`3 10`。 我々は持っています`q = 10 // 3 = 3`。 コインが 3 枚到達する必要があります`10`、したがって、最大額面は満たす必要があります`3b >= 10`、与える`b = 4`。 The actual formula yields`(10 + 3 - 1) // 3 = 12 // 3 = 4`、 ない`3`。 宗派あり`3`そして`4`、ターゲットは`3 + 3 + 4 = 10`。 これは、通常のフロア分割の誤った使用を暴露する種類の事件です。 

最後に最大目標を検討します`a = 500000000`、`d = 1000000000`。 得ます`q = 2`、 そして`b = ceil(1000000000 / 2) = 500000000`。 貴重なコイン 2 枚`500000000`ターゲットを正確に設定します。 入力スケールが最大であっても、計算は定数時間のままです。
