[CF 269D - 最大のウォーターフォール](https://codeforces.com/problemset/problem/269/D)

 **評価:** 2600
 **タグ:** データ構造、dp、グラフ、並べ替え
 **解決時間:** 2 分 57 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 壁に取り付けられた一連の水平パネルがあります。 高所にある人工の「トップパネル」から水が始まります`t`そして最終的には高さの人工「底部パネル」に到達しなければなりません`0`。 

パネルの水平間隔が重なっていて、それらの間に両方とも重なる中間パネルがない場合、パネルは下のパネルに水を送り込むことができます。 幾何学的に、重なり合う点のいずれかに垂直線を引くと、水は下にある最初のパネルに落ちます。 これにより、上位パネルから下位パネルへの有向非環状構造が作成されます。 

2 つのパネル間の有効な遷移ごとに、その遷移を通過できる水の量は、水平方向の投影の重なり部分の長さに等しくなります。 

上部パネルから下部パネルへの下向きのパスを 1 つだけ選択したいと考えています。 パスの品質は、その最も弱い遷移、つまりパス上のすべてのエッジ間の最小の重なりによって決まります。 タスクは、この最小値を最大化することです。 

最初の課題は、パスの最適化そのものではありません。 難しいのは、有効な遷移のグラフを見つけることです。 まで`10^5`パネルでは、すべてのペアをチェックすることは不可能です。 

制約があるため、私たちは慎重に考える必要があります。 二次アルゴリズムはおおよそのパフォーマンスを発揮します`10^10`ペアチェックは 2 秒ではまったく不可能です。 平`O(n√n)`不快だろう。 対象範囲はこのあたりです`O(n log n)`。 

いくつかの微妙な状況により、単純な構造が不正確になります。 

考慮する：```
t = 10

height 8: [0,10]
height 6: [0,10]
height 4: [0,10]
```上部パネルを下部パネルに直接接続することはできません。 中央のパネルは落下中に最初に遭遇するパネルであるため、それをブロックします。 

別の例:```
height 8: [0,5]
height 6: [5,10]
```これらのパネルは 1 つのエンドポイントで接触しているだけです。 条件が必要であるため、それらのオーバーラップの長さはゼロです。```
max(l1,l2) < min(r1,r2)
```そしてそうではありません`≤`。 接触間隔を重複として扱うと、無効なエッジが作成されます。 

3 番目のトラップは、パネルが複数の高いパネルから水を受け取ると表示されます。 グラフはツリーではありません。 一意の親または一意の入力エッジを前提とするソリューションは失敗します。 

例えば：```
height 10: [0,10]
height 7 : [0,4]
height 7 : [6,10]
height 4 : [0,10]
```下のパネルにはさまざまなルートで到達できるため、最適なボトルネック値はあらゆる可能性を考慮する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、最初にグラフを明示的に構築します。 

パネルのペアごとに、投影が重なっているかどうかを確認します。 それらが存在する場合、それらの間で接続をブロックする別のパネルを検索します。 すべてのエッジを構築した後、最も広いパスの動的プログラミング アルゴリズムを実行します。```
dp[v] = maximum bottleneck value from top to v
```このアプローチは、目的がまさに DAG 上の古典的な最大ボトルネック パス問題であるため、概念的には正しいです。 

問題はグラフの構成です。 がある`O(n²)`パネルのペアを検索し、エッジが存在するかどうかを判断するには、パネル間で別の検索が必要になる場合があります。 最適化を行ったとしても、複雑さは許容範囲をはるかに超えています。 

重要な観察は幾何学的なものです。 

水平線を上から下にスイープすることを想像してください。 任意の x 座標において、下の次のパネルは、その x で現在表示されているパネルとまったく同じです。 スイープ中にパネルが表示されると、その間隔のすべてのポイントで、以前に表示されていたものではなく、そのパネルがすぐに表示され始めます。 

これは、ペアごとのパネル比較ではなく、間隔更新を通じてグラフを構築できることを意味します。 

壁の x 座標セグメントごとに、それを覆うすでに処理済みの最も高いパネルを維持します。 新しいパネルが表示されると、そのパネルによって置き換えられるすべての表示間隔は、前の表示パネルから新しいパネルまでのグラフのエッジに対応します。 置換された間隔の長さは、そのエッジのオーバーラップ長に影響します。 

幾何学的に重要な事実は、結果として得られるグラフには次のものだけが含まれるということです。`O(n)`エッジ。 各パネルは、最大で 2 つの出力エッジを取得できます。1 つはその左側の境界を介して、もう 1 つは右側の境界を介して取得されます。 これは、交差しない水平セグメントによって形成される可視性グラフの標準特性です。 

この DAG を構築すると、最適化が簡単になります。 オーバーラップ長さのあるエッジに沿って`w`、そのエッジを介して伝播されるボトルネック値は次のとおりです。```
min(current_bottleneck, w)
```すべてのエッジは高さ順に下に向かうため、頂点を上から下に処理すると答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n²) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### スイープラインによるグラフ作成

 人工パネルを2枚追加します。 

天板には間隔があります`[-10^9, 10^9]`高所で`t`。 

底板には間隔があります`[-10^9, 10^9]`高所で`0`。 

次に、すべてのパネルを高さの降順に並べ替えます。 

### 座標圧縮

 可視性が変化する可能性がある唯一の X 座標は、間隔のエンドポイントです。 

左右のエンドポイントをすべて収集し、並べ替えて圧縮します。 

2 つの連続する座標の間では、可視性は一定です。 これらの基本間隔は、スイープ構造によって維持される単位になります。 

### スイープ構造

 圧縮された基本間隔にわたってセグメント構造を維持します。 

基本間隔ごとに、現在表示されている最も高い処理済みパネルを保存します。 

最初は、すべての間隔で上部パネルが表示されます。 

### パネルを上から下に処理します

 パネル時`v = [l,r]`が発生しました:

 1. 内部のすべての基本区間をクエリします。`[l,r]`。 
2. 表示される各パネル`u`これらの間隔で見つかったオーバーラップ長は、全長に等しいものとなります。`u`見えた。 
3. 有向エッジを追加する`u → v`そのオーバーラップ長さで。 
4. 可視性を置き換えます`[l,r]`パネルごとに`v`。 

クエリと更新の操作は、区間の割り当てと区間の分解をサポートするセグメント ツリーを使用して実装されます。 

### DAG での動的プログラミング

 グラフが構築されたら、次のようにします。 

1. しましょう`dp[top] = +∞`。 
2. 頂点を高さの降順に処理します。 
3. あらゆるエッジに`u → v`オーバーラップあり`w`、 アップデート```
dp[v] = max(dp[v], min(dp[u], w))
```これは標準の最も幅の広いパス遷移です。 

1. 下部パネルの値が答えです。 

### なぜ効果があるのか

 どのスイープ位置でも、基本間隔で維持される可視パネルは、現在のスイープ高さから下に移動するときに正確に遭遇する最初のパネルです。 新しいパネルが表示されると、そのパネルがカバーするすべての間隔は、その間隔でそのすぐ上の固有のパネルに属していました。 その可視性を置き換えると、ステートメントに必要な幾何学的なエッジが正確に作成されます。 

2 つのパネルが共有するすべての基本間隔から累積された重なりは、それらのパネルの水平方向の重なりの合計に等しくなります。 すべての有効なウォーターフォール パスがこの DAG 内のパスに対応し、すべての DAG パスが有効なウォーターフォール パスに対応するため、最適化問題は最大ボトルネック パス問題になります。 

DP 遷移では、次の不変条件が保持されます。`dp[v]`トップパネルから`v`。 高さの降順で処理すると、すべての先行ファイルがすでに終了していることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, m, top_id):
        self.n = 1
        while self.n < m:
            self.n <<= 1

        self.tag = [-1] * (2 * self.n)
        self.tag[1] = top_id

    def push(self, p):
        if self.tag[p] != -1:
            self.tag[p << 1] = self.tag[p]
            self.tag[p << 1 | 1] = self.tag[p]
            self.tag[p] = -1

    def collect(self, p, l, r, ql, qr, seglen, res):
        if ql >= r or qr <= l:
            return

        if ql <= l and r <= qr and self.tag[p] != -1:
            res.append((self.tag[p], seglen[l:r]))
            return

        if r - l == 1:
            res.append((self.tag[p], seglen[l:r]))
            return

        self.push(p)
        m = (l + r) >> 1
        self.collect(p << 1, l, m, ql, qr, seglen, res)
        self.collect(p << 1 | 1, m, r, ql, qr, seglen, res)

    def assign(self, p, l, r, ql, qr, value):
        if ql >= r or qr <= l:
            return

        if ql <= l and r <= qr:
            self.tag[p] = value
            return

        self.push(p)
        m = (l + r) >> 1
        self.assign(p << 1, l, m, ql, qr, value)
        self.assign(p << 1 | 1, m, r, ql, qr, value)

    def query(self, l, r, seglen):
        res = []
        self.collect(1, 0, self.n, l, r, seglen, res)
        return res

    def update(self, l, r, value):
        self.assign(1, 0, self.n, l, r, value)

def solve():
    n, t = map(int, input().split())

    panels = []

    panels.append((t, -10**9, 10**9))
    for _ in range(n):
        h, l, r = map(int, input().split())
        panels.append((h, l, r))
    panels.append((0, -10**9, 10**9))

    m = n + 2

    coords = []
    for _, l, r in panels:
        coords.append(l)
        coords.append(r)

    coords = sorted(set(coords))
    pos = {x: i for i, x in enumerate(coords)}

    seg_lengths = [0] * max(1, len(coords) - 1)
    for i in range(len(coords) - 1):
        seg_lengths[i] = coords[i + 1] - coords[i]

    order = sorted(
        range(m),
        key=lambda i: -panels[i][0]
    )

    rank = [0] * m
    for idx, v in enumerate(order):
        rank[v] = idx

    edges = [[] for _ in range(m)]

    st = SegmentTree(max(1, len(coords) - 1), 0)

    for v in order[1:]:
        h, l, r = panels[v]

        L = pos[l]
        R = pos[r]

        pieces = st.query(L, R, seg_lengths)

        overlap = {}

        for panel_id, arr in pieces:
            length = sum(arr)
            overlap[panel_id] = overlap.get(panel_id, 0) + length

        for u, w in overlap.items():
            edges[u].append((v, w))

        st.update(L, R, v)

    INF = 10**18
    dp = [0] * m
    dp[0] = INF

    for u in order:
        for v, w in edges[u]:
            cand = min(dp[u], w)
            if cand > dp[v]:
                dp[v] = cand

    print(dp[order[-1]])

if __name__ == "__main__":
    solve()
```このソリューションはスイープ ラインの構築に直接従います。 

圧縮された座標により、壁が基本的な間隔に分割され、可視性が変化することはありません。 セグメント ツリーには、各基本間隔でどのパネルが現在表示されているかが格納されます。 

新しいパネルが到着すると、その間隔をクエリすると、どのパネルがその真上にあるか、およびそれぞれがどれだけオーバーラップしているかを正確に明らかにします。 それがグラフの端になります。 

動的プログラミング フェーズは、高さ順に並べられた DAG 上での最も幅の広いパスの計算です。 人工の上部パネルは無限の容量で始まり、各エッジは重なり合う長さによってボトルネックを制限します。 

微妙な点の 1 つは、重複長は複数の基本間隔にわたって累積する必要があることです。 パネルは、いくつかの切断された圧縮部分で別のパネルと重なることができ、それらはすべて同じ幾何学的オーバーラップに属します。 

もう 1 つの微妙な点は、厳密なオーバーラップです。 基本区間は正の長さであるため、座標圧縮はこれを自然に処理します。 共有エンドポイントは基本間隔を作成せず、重複も生じません。

 ## 特殊なケース

 以下にのみ接触するパネルを検討してください。```
2 10
8 0 5
4 5 10
```圧縮された座標は次のようになります。`{0,5,10}`。 オーバーラップ長がゼロであるため、交差点の内側には基本区間はありません。 スイープでは 2 つのパネル間にエッジは生成されません。 アルゴリズムは正しく出力します`0`。 

完全なネストを検討してください。```
2 10
8 0 10
4 2 8
```下のパネルが表示されると、スイープでは正確な間隔で上のパネルが表示されます。`[2,8]`。 結果として得られるエッジに重みがかかります`6`。 底部に伝播したボトルネック値はそのまま残る`6`、真の最小オーバーラップと一致します。 

ブロックパネルを考えてみましょう。```
3 10
8 0 10
6 0 10
4 0 10
```上部パネルは中央パネルにのみ接続されます。 中央のパネルは下のパネルにのみ接続されます。 スイープは常に新しく挿入されたパネルをそのすぐ上に現在表示されているパネルにリンクするため、直接エッジは表示されているブロッカーをスキップしません。 これは、有効な遷移の幾何学的定義と正確に一致します。
