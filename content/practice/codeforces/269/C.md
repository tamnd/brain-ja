 ## 解決策
 ## 問題の理解

 次のような無向接続グラフが与えられます。`n`頂点と`m`エッジ。各エッジにはフロー値がすでに割り当てられています。 頂点には 1 から 1 までの番号が付けられます。`n`、頂点 1 をソースおよび頂点として使用`n`シンクとして。 私たちのタスクは、結果として得られる有向グラフが有効なフローを表すように、各エッジに方向を割り当てることです。 具体的には、ソースとシンクを除くすべての頂点について、入力フローの合計が出力フローの合計と等しくなければならず、ソースには入力エッジがなく、方向を割り当てた後、グラフは非周期のままでなければなりません。 

入力により各エッジに端点が与えられます`(ai, bi)`そして流れ`ci`。 出力は、入力順序のエッジごとに、フローが次から始まるかどうかを示す必要があります。`ai`に`bi`（出力`0`）またはから`bi`に`ai`（出力`1`）。 複数のソリューションが存在する可能性があります。 

この制約は、最大 200,000 個の頂点と 200,000 個のエッジを持つことができることを意味します。 エッジ方向のすべての順列を試す単純なアプローチは不可能です。 操作はほぼ線形である必要があります`n + m`なぜなら、O(n log n) または O(m log m) を超えるとタイムアウトになる可能性があるからです。 エッジ ケースには、小さなグラフ、複数のエッジがソースに接続されているグラフ、中間の頂点でフローが「キャンセル」される可能性があるグラフが含まれます。 

たとえば、不用意に実装すると、すべてのエッジがソースから離れたところに任意に割り当てられる可能性があります。 これは流れ保存の不変条件を破ることになります。 たとえば、次のことを考えてみましょう。```
3 3
1 2 5
2 3 5
1 3 2
```正しい割り当てでは、5 つのユニットを 1 → 2 → 3 に配線し、2 つのユニットを 1 → 3 に直接配線する必要があります。すべてのエッジを 1 → 2、2 → 3、1 → 3 として割り当てると、ソース/シンクのルールは満たされますが、慎重に行わないと非循環性に違反します。 

## アプローチ

 ブルート フォース ソリューションでは、エッジに対して可能な 2^m 方向すべてを反復処理します。 割り当てごとに、ソースとシンクを除くすべての頂点で流れの保存が成立するかどうかを確認します。 これは正しいですが、2^200000 は天文学的に大きいため実行不可能です。 

重要な洞察は、フロー保存から得られます。ソースとシンクを除き、どの頂点でも、入ってくるフローの合計は出ていくフローの合計と等しくなります。 これは、残りの入力フローが完全に決定されている頂点 (有向フローの葉のように) を繰り返し「処理」すると、貪欲に方向を伝播できることを意味します。 ソースから開始して、すべてのエッジを外側に向けることができます。その後、フローを受け取る各頂点は、未処理のエッジに沿ってフローを押すだけであるため、サイクルを作成せずにエッジに沿ってフローを方向付けることができます。 これにより、問題は流量によって導かれるエッジのトポロジカルな順序付けに帰着します。 

基本的に貪欲な BFS/DFS を実行します。頂点ごとに、未処理のエッジを確認し、頂点の流れの保存が満たされるように方向を割り当ててから、次の頂点に移動します。 解決策が保証されているため、このアプローチは確実に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * n) | O(n + m) | 遅すぎる |
 | トポロジカル伝播を使用した貪欲なフロー割り当て | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成します。 各エッジには、隣接する頂点、そのインデックス、およびフロー値が保存されます。 
2. を初期化します。`remaining_flow`頂点の配列`remaining_flow[v]`頂点がまだ割り当てる必要がある発信フローの合計です。 頂点 1 の場合、これは 1 に接続されているエッジのすべてのフローの合計です。他のすべての頂点の場合、すべてのフローの合計から、すでに割り当てられている入力フローの合計を引いたものになります。 
3. ソース頂点を使用してキューを初期化します。`1`。 
4. キューが空でない間に、頂点をポップします。`v`。 未割り当てのエッジごとに`(v, u, idx)`:

 1. もし`v`ソースであるか、その残りの流れが正である場合は、からの方向を割り当てます。`v`に`u`。 
2.アップデート`remaining_flow[u]`このエッジの流れを差し引くことによって。 
3. もし`remaining_flow[u]`ゼロに達し、押す`u`列に並びます。 
5. すべてのエッジに方向が割り当てられるまで繰り返します。 
6. 入力された順に指示を出力します。 エッジが次から割り当てられた場合`ai`に`bi`、出力0。 それ以外の場合は、出力 1。 

これが機能する理由は、各ステップで、フローのソースに保存を満たすのに十分な未割り当てのフローがあるエッジのみを割り当てるためです。 利用可能なフローの順序で頂点を処理することにより、サイクルを回避し、フローの制約を満たします。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

n, m = map(int, input().split())
adj = [[] for _ in range(n + 1)]
edges = []
deg = [0] * (n + 1)
res = [0] * m

for i in range(m):
    a, b, c = map(int, input().split())
    edges.append((a, b, c))
    adj[a].append((b, i, c))
    adj[b].append((a, i, c))
    deg[a] += c
    deg[b] += c

queue = deque([1])
visited = [False] * (n + 1)
visited[1] = True

while queue:
    v = queue.popleft()
    for u, idx, c in adj[v]:
        if res[idx] != 0 and res[idx] != 1:
            if v == edges[idx][0]:
                res[idx] = 0
            else:
                res[idx] = 1
            deg[u] -= c
            if not visited[u] and u != n:
                queue.append(u)
                visited[u] = True

for r in res:
    print(r)
```この実装では、最初に隣接リストを構築し、エッジ情報を保存します。 未処理のフローを追跡します。`deg`。 BFS は、頂点の着信/発信フローが完全に決定可能なときに頂点が処理されることを保証します。 方向を割り当てると、どのエンドポイントが現在の頂点に一致するかがチェックされ、フローの一貫性が保証されます。
