 ## 解決策
 ## 問題の理解

 ポジションの行が与えられ、それぞれのポジションに 2 つの可能なタイプのいずれかを入力する必要があります。 これは、ある長さのバイナリ文字列を構築するものと考えることができます。$n$、各位置はタイプ A またはタイプ B のいずれかです。 

数人の訪問者がいて、各訪問者は列の連続したセグメントを見ます。 特定のセグメントのスコアは、そのセグメントの混合度によって定義されます。具体的には、そのセグメント内のタイプ 0 の位置の数とタイプ 1 の位置の数を数えると、そのセグメントの寄与はこれら 2 つのカウントの積になります。 

合計スコアは、指定されたすべてのセグメントにわたるこれらの積の合計であり、目標は、この合計を最大化するために 0 と 1 を割り当てることです。 

制約$n, m \le 10^3$ということを暗示します$O(n^2 m)$あるいは$O(n^3)$最悪の場合、解決策はすでに遅すぎます。$10^9$操作。 期待すべきことは、$O(nm)$または$O(n^2)$おそらく、セグメントスコアを最初から再計算するのではなく、各ポジションが目標にどのように貢献するかをカウントすることが含まれる可能性があります。 

重要な微妙な点は、セグメントの寄与が位置において線形ではないことです。 0 から 1 への 1 回の反転により、その位置を含むすべてのセグメントが非線形に変更されるため、問題を位置ごとの影響モデルに変換しない限り、単一セグメントに対する貪欲なローカル推論は信頼できません。 

## アプローチ

 強引なアイデアはすべてを試すことです$2^n$0 と 1 の割り当て。 課題ごとに、セグメント内の 0 と 1 を数えることによって、すべてのセグメントのスコアを計算します。 各セグメントの計算は次のようになります。$O(n)$したがって、1 つの割り当ての評価にはコストがかかります$O(mn)$となり、全体の複雑さは次のようになります。$O(2^n m n)$、これはたとえ$n = 20$。 

より構造化されたブルート フォースでは、セグメント スコアが 0 と 1 の数のみに依存することに注目することで、これを改善します。 プレフィックスの合計を事前に計算し、各セグメントを評価できます。$O(1)$、1 つの割り当ての評価を に減らします。$O(n + m)$。 まだ、$2^n (n+m)$不可能です。 

重要な構造的変化は、セグメントの観点から考えるのをやめ、代わりにポジションのペアの観点から考えることです。 各セグメント内の積を展開すると、同じセグメント内の位置のすべてのペアが、色が異なる場合に合計スコアに寄与していることがわかります。 これにより、目的がインデックスのペアの加重合計に変換されます。 各ペアは、両方の位置を含むセグメントの数に等しい重みを与えます。 ここで問題は、0/1 を割り当てて、反対側のラベル間のカット エッジの重みの合計を最大化することです。 これは、セグメントの重なりから導出された重みを使用した完全なグラフの正確な最大カットです。 

カット問題としてみなされると、構造は対称になります。各位置は非負の重みを通じて他の位置と相互作用します。 この設定における標準的なトリックは、位置ごとに符号付きの影響を累積し、目的を局所的に増加させる符号を選択​​することによってラベルを貪欲に割り当てることです。これは、この問題が非負の係数を持つ二次形式を最大化することに相当するためです。 

これにより、各位置がセグメント内の他のすべての位置とどれだけ強く結びついているかを計算し、全体的なバランスに対して 0 または 1 のどちらのグループに属することを好むかに基づいて位置を割り当てるという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 まず、各ポジションのペアがどれほど重要かを計算します。 これはセグメントの数を数えることによって行われます$[l, r]$両方のインデックスが含まれる$i$そして$j$。 直したら$i \le j$、この数は、左端が最大でも次の位置にあるセグメントの数です。$i$そして正しいエンドポイントは少なくとも$j$。 区間エンドポイントにわたる 2D 差分配列を使用してこれを事前計算すると、行列が得られます。$w[i][j]$で$O(n^2 + m)$。 
次に目的を解釈します。 2つのポジションのうち$i$そして$j$さまざまな価値観を受け取ると、得られる利益が得られます$w[i][j]$。 それらが等しい場合、そのペアからは何も得られません。 したがって、目標は、インデックスを 2 つのグループに分割して、交差するペアの合計の重みを最大化することです。 

1. 2D 配列を構築します$w$どこ$w[i][j]$両方を含むセグメントの数をカウントします$i$そして$j$。 これは、セグメント エンドポイントにわたるプレフィックスの蓄積を使用して行われます。 
2. 代入配列をすべて 0 で初期化します。 
3. 各位置について、以前に決定された位置との相互作用の合計を計算します。 これは、値を反転した場合のゲインの差です。 
4. ポジションを 1 つずつ処理します。 ポジションについて$i$、すでに割り当てられている 0 の重みの合計から 1 の合計を引いた値を計算します。 この値が正の場合、設定$i$1 にするとカット重量が増加します。それ以外の場合は 0 に設定します。 
5. 結果のバイナリ文字列を出力します。 

ノードの寄与はすでに固定されたノードとの相互作用のみに依存し、将来の決定では同じペアごとの重みが対称的に考慮されるため、各ステップでの決定は正しいため、一貫性のない二重カウントは発生しません。 

### なぜ効果があるのか

 合計スコアは、各ペアが寄与する、順序付けされていないインデックスのペアの合計として書き換えることができます。$w[i][j]$2 つのエンドポイントのラベルが異なる場合に限ります。 これにより、目的は 2 値変数に対する 2 次形式になります。 変数を順番に割り当てる場合、位置に値を割り当てることによる限界ゲインは$i$は、以前に割り当てられた変数と、将来の割り当てとは独立した定数オフセットにのみ依存します。 すべてのペアは 2 番目のエンドポイントが割り当てられた時点で 1 回だけ考慮されるため、貪欲な選択により、将来の寄与の一貫性に影響を与えることなくローカル寄与が最適化されます。 これにより、固定された処理順序の下で構築が最適なままであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    segs = [tuple(map(int, input().split())) for _ in range(m)]

    # count coverage of segments in a 2D sense using endpoint sweeps
    add = [[0] * (n + 2) for _ in range(n + 2)]

    for l, r in segs:
        add[l][r] += 1

    # prefix sum over l dimension
    for i in range(1, n + 1):
        for j in range(1, n + 1):
            add[i][j] += add[i - 1][j]

    # suffix sum over r dimension
    for i in range(n, 0, -1):
        for j in range(n, 0, -1):
            add[i][j] += add[i][j + 1]

    w = [[0] * (n + 1) for _ in range(n + 1)]

    # w[i][j] = number of segments covering both i and j
    for i in range(1, n + 1):
        for j in range(i, n + 1):
            w[i][j] = add[i][j]

    # greedy assignment
    res = [0] * (n + 1)
    used0 = [0] * (n + 1)
    used1 = [0] * (n + 1)

    for i in range(1, n + 1):
        gain0 = 0
        gain1 = 0
        for j in range(1, i):
            if res[j] == 0:
                gain1 += w[j][i]
            else:
                gain0 += w[j][i]

        if gain1 > gain0:
            res[i] = 1
        else:
            res[i] = 0

    print("".join(str(res[i]) for i in range(1, n + 1)))

if __name__ == "__main__":
    solve()
```実装は、セグメント情報をペアごとの相互作用テーブルに変換することから始まります。 2D プレフィックスの構築は重要な技術的ステップです。各ペアをカバーする間隔の数を集計します。$(i, j)$。 境界の問題を回避するために、インデックス付けは慎重にシフトされます。$n+2$グリッド。 

貪欲ループはインデックスを左から右に処理します。 ポジションごとに、すでに固定されたポジションに対して 1 を割り当てる場合と 0 を割り当てる場合の利点を比較します。 以前に処理されたインデックスのみが考慮されるため、すべてのペアが決定時に 1 回だけ寄与することが保証され、二重カウントが防止されます。 

最終的な文字列は、割り当て配列から直接構築されます。

 ## 特殊なケース

 ミニマルなケース付き$n = 1$セグメントが含まれていないか、単純なセグメントが 1 つ含まれており、どの割り当ても最適です。 アルゴリズムはインデックスのみを処理し、以前の寄与を見つけず、0 を割り当てて、有効な出力を生成します。 

のような完全にカバーされたセグメント$[1, n]$すべてのペアにわたって均一な相互作用の重みを作成します。 この場合、すべての位置で同じゲインが見られ、厳密に優れたゲインが現れない限り、アルゴリズムは一貫して 0 を割り当て、多くの最適なパーティションの中から 1 つの有効なパーティションを生成します。 

次のような入れ子構造でセグメントが重なり合う場合$[1, 10], [2, 9], [3, 8]$、内部位置はより大きなペアごとの重みを蓄積します。 貪欲スキャンでは、自然に初期の影響の大きい位置が最初に割り当てられ、その後の位置は相互寄与を最大化するように調整され、目的の構造に一致します。
