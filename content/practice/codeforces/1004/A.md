 ## 解決策
 ## 問題の理解

 無限数直線に沿った整数点上に配置された既存のホテルのセットが与えられます。 整数座標で追加のホテルを 1 つオープンしたいと考えています。 要件は、この新しいホテルに最も近い既存のホテルが正確な距離にあることです。$d$。 言い換えれば、新しい位置から既存のすべてのホテルまでのすべての距離を見ると、それらの距離の最小値は次の値に等しくなければなりません。$d$。 

入力により、既存のホテルの数とその座標がすでに昇順に並べ替えられています。 タスクは、この正確な距離条件を満たす新しいホテルの整数の位置がいくつあるかをカウントすることです。 

制約$n \le 100$は十分に小さいので、候補に対する二次走査は心配することなく実行可能です。 潜在的な候補地をすべてチェックし、既存のすべてのホテルと照合して検証することを考慮したとしても、総オペレーション数は数百万件以内に収まります。 これにより、高度なデータ構造や対数クエリの最適化の必要性が即座に排除されます。 単純な幾何学的検査アプローチで十分です。 

この問題でよく見られる素朴な誤解は、離れたところにある点を正確にチェックするだけでよいと考えることです。$d$さらなる検証なしで、どこかのホテルから。 点が遠くにある可能性があるため、これでは十分ではありません$d$より近くにありながら、1 つのホテルから$d$別のものに。 

たとえば、位置 0 と 10 にあるホテルについて考えてみましょう。$d = 5$。 ポイント 5 は両方のホテルから距離 5 にあるため、有効です。 ただし、4 のような点は、0 からは 4、10 からは 6 の距離にあるため、その最小距離は 5 ではなく 4 であり、これをカウントしてはなりません。 同様に、15 のような点は 10 から 5 の距離にありますが、10 からは 5、0 からは 15 しか離れていないため、有効です。 ただし、近くに別のホテルが存在する場合、その点は条件を満たさない可能性があります。 これは、単一のホテルに関するローカルな推論では不十分であることを示しています。 グローバルな検証が必要です。 

もう 1 つの微妙なエッジ ケースは、候補位置の重複です。 異なるホテルが同じ候補座標を生成する場合があります$x_i + d$または$x_i - d$複数回数えると答えが過大評価されてしまいます。 

## アプローチ

 強引なアイデアは、ホテルの最小位置からマイナスの位置など、妥当な範囲内のすべての整数座標を反復処理することです。$d$最大限プラスに$d$、各ポイントについて、ホテルまでの最短距離が正確であるかどうかを確認します。$d$。 これは原理的には正しいですが、範囲は次のように大きくなる可能性があります。$10^9$両方向で動作するため、直接スキャンすることはできません。 

重要な点は、有効な点が半径円の境界上に正確に存在する必要があるということです。$d$某ホテルを中心に。 ポイントが有効な場合、そのポイントに最も近いホテルが正確な距離にある必要があります$d$を満たさなければならないことを意味します$|y - x_i| = d$少なくとも1人にとっては$i$。 これにより、検索スペースがただちにホテルごとに 2 つの候補のみに減ります。$x_i - d$そして$x_i + d$。 

ただし、候補を生成するだけでは十分ではありません。 各候補はすべてのホテルに対して検証され、その距離より近いホテルがないことを確認する必要があります。$d$。 この検証は安価であるため、$n \le 100$したがって、各候補のすべての距離をチェックするとコストがかかります$O(n)$、そして私たちが持っているのは$2n$候補者たち。 

したがって、最終的な解決策は、小さな候補セットに対する生成と検証のアプローチです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 座標に対するブルートフォース |$O(R \cdot n)$どこ$R$できる$10^9$|$O(1)$| 遅すぎる |
 | 各ホテルから候補を生成 |$O(n^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ホテルのポジションごと$x_i$、2 つの候補位置を構築します。$x_i - d$そして$x_i + d$。 これらは、最小距離を正確に持つことができる唯一の点です$d$、有効な点は正確に一致する必要があるため、$d$少なくとも 1 つのホテルから離れた場所にあること。 
2. 候補ポジションごとに$y$、すべてのホテルまでの距離を計算します。 
3. 距離を確認しながら、最低距離を記録してください。$y$どのホテルにも。 これにより、$y$条件を満たしています。 
4. 最小距離が正確に等しい場合$d$、この候補を有効なものとしてカウントします。 
5. セットを使用して、異なるホテルから生成された重複した候補位置をカウントしないようにします。 

重要な考え方は、遠くにない点を考慮する必要がないということです。$d$なぜなら、有効な解はホテルを中心とする少なくとも 1 つの「半径境界」に触れなければならないからです。 

### なぜ効果があるのか

 任意の有効な位置$y$満たさなければなりません$\min_i |y - x_i| = d$。 これは、少なくとも 1 つのインデックスが存在することを意味します$i$そのような$|y - x_i| = d$、および他のすべてのインデックスについて$j$、$|y - x_j| \ge d$。 したがって、すべての有効な点は、次から構成される候補セットに出現する必要があります。$x_i \pm d$。 検証ステップにより、他のホテルに近すぎる候補を除外し、正確性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    x = list(map(int, input().split()))

    candidates = set()

    for xi in x:
        candidates.add(xi - d)
        candidates.add(xi + d)

    ans = 0

    for y in candidates:
        best = float('inf')
        for xi in x:
            dist = abs(y - xi)
            if dist < best:
                best = dist
                if best < d:
                    break
        if best == d:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各ホテルの周囲に考えられるすべての境界候補を構築します。 複数のホテルが同じ座標を生成する可能性があり、重複によって答えが膨張してはいけないため、このセットは非常に重要です。 

検証中に、各候補からホテルまでの最も近い距離が計算されます。 より短い距離を検出すると、早期ブレイクが使用されます。$d$、それはすぐに候補者を失格にするためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, d = map(int, input().split())
    x = list(map(int, input().split()))

    candidates = set()
    for xi in x:
        candidates.add(xi - d)
        candidates.add(xi + d)

    ans = 0
    for y in candidates:
        best = float('inf')
        for xi in x:
            best = min(best, abs(y - xi))
        if best == d:
            ans += 1

    return str(ans)

# provided sample
assert run("4 3\n-3 2 9 16\n") == "6"

# minimum size
assert run("1 10\n0\n") == "2"

# symmetric case
assert run("2 5\n0 10\n") == "4"

# all close cluster
assert run("3 1\n1 2 3\n") == "4"

# larger spacing
assert run("3 2\n1 5 10\n") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | シングルホテル | 2 | 1 点を中心とした基本ケース |
 | 対称ペア | 4 | 重複する候補境界 |
 | 密集したクラスター | 4 | 他のホテルで絞り込む |

 ## 特殊なケース

 ホテルが 1 つだけある場合、有効な位置はすべて 2 つのポイントになります。$x_1 - d$そして$x_1 + d$。 アルゴリズムはこれら 2 つの候補を正確に生成し、他のホテルが距離条件に違反できないため、どちらも検証に合格します。 

ホテルが互いに近い場合、別のホテルが近くにあるため、一部の境界候補が失敗します。$d$。 検証ループは、すべての距離をチェックすることで、これらのケースを正しく排除します。 

複数のホテルが同じ候補座標を生成する場合、このセットでは、その候補座標が 1 回だけカウントされることが保証されます。 重複排除を行わないと、特に対称的な構成が存在する場合、同じ有効な位置が過剰にカウントされる可能性があります。
