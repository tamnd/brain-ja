 ## 解決策
 ## 問題の理解

 最大で重み付けされたツリーが与えられます。$10^5$頂点。 各エッジは正の長さを持っているため、距離はツリー上の標準の最短パス距離になります。 ツリー内の単一の単純なパスを形成する頂点のセットを選択する必要があります。$k$頂点。 

このパスが選択されると、ツリー内のすべての頂点が、選択した最も近い頂点までの距離を測定します。 選択の品質は、すべての頂点にわたる最悪の距離であり、目標は、この最悪の距離を最小限に抑えることです。 

したがって、実際の問題は、「カバレッジ センター」として機能するツリー内の連続したパスを選択することであり、ツリー内のすべてのノードを可能な限りこのパスに近づけたいと考えています。 

この制約により、すべての候補パスを明示的に試行するソリューションからは遠ざかることになります。 木には$O(n^2)$単純なパスの可能性があり、1 つの候補を評価する場合でも、距離を計算するために完全な走査が必要となるため、少なくとも$O(n^3)$最悪の場合の行動。 

回答の構造は、典型的な最適化パターンを示唆しています。つまり、回答に対する単調な実現可能性条件とツリー DP または貪欲チェックの組み合わせです。 

いくつかの微妙なケースが重要です。 

問題の 1 つは、最適なパスの数が以下の場合です。$k$頂点。 たとえば、次の場合$k = 3$、正確に 3 つの頂点を使用する必要はありません。 カバレッジが向上する場合は、2 または 1 を使用するのが最適です。 正確に強制するアプローチ$k$ノードを選択すると、答えが不必要に悪化する危険があります。 

もう 1 つのケースは、長いチェーンなど、ツリーのバランスが非常に悪い場合です。 そうすれば、最適なパスは自然にそのチェーンに埋め込まれますが、$k$が十分に大きい場合、複数の異なる中心セグメントが同じ半径を与える可能性があります。 1 つのエンドポイントから貪欲にパスを「拡張」しようとする単純なヒューリスティックでは、グローバルに最適なセグメントを簡単に見逃してしまう可能性があります。 

最後に、重み付けされたエッジが重要です。 各エッジが単位距離に寄与すると仮定すると、直感的な重み付けされていないツリー中心のアイデアの多くは失敗します。 

## アプローチ

 直接的なアプローチは、以下の長さの単純なパスをすべて列挙することです。$k$、各パスについて、ツリー内の任意のノードからそのパスまでの最大距離を計算し、最小値を取得します。 

サイズの制約を無視しても、ツリー内の単純なパスの数は$O(n^2)$。 パスごとに、すべてのノードの距離を計算するには、パス上のすべてのノードから BFS/DFS を実行するか、複数ソースの最短パスを計算する必要があり、どちらもコストがかかります。$O(n)$。 これは次のことにつながります$O(n^3)$、これは実現可能な限界をはるかに超えています。 

重要な構造上の観察は、実際には最適なパスを直接構築する必要がないということです。 代わりに、候補の半径が与えられた場合に、決定の質問をすることができます。$R$、最大でもパスはありますか？$k$ツリー内のすべてのノードが距離内にあるような頂点$R$パス上の少なくとも 1 つの頂点から?

 これにより、問題が実現可能性チェックに変換され、バイナリ検索が可能になります。$R$なぜなら、半径が$R$機能するだけでなく、より大きな半径も機能します。 

固定の場合$R$、すべてのノードが距離内にあるという意味で、ツリーを「覆う」パスを選択できるかどうかを判断する必要があります。$R$それの。 これは、木の直径のような背骨に沿って構造を見つけることになります。 

制約を表示する便利な方法は、パスの「有効な接続点」であるノードのセットを考慮することです。 ノードの場合$v$、有効なソリューションの一部にできるかどうか、およびカバレッジの制約を維持しながらパスをどこまで拡張できるかを定義します。 これは自然に、選択した中心パスとの一貫性を維持しながら保持できる最長の下向きセグメントを各ノードに対して計算するツリー DP につながります。 

重要な考え方は、最適なパスは剪定された木の「背骨」のように動作する、つまり距離の外側にあるノードであるということです。$R$パスに向かって「引っ張る」必要があり、パスはすべての半径の交点と交差する必要があります。$R$構造化された方法でボール。 ツリー上では、これらの制約は、互いに遠くないノードによって引き起こされる、剪定されたツリー内に直径のようなパスが存在するかどうかをチェックすることに集約されます。 

より具体的な再定式化が標準です。$R$、距離内に存在できないすべてのノードを削除します$R$任意の候補パス ノードのパスを選択し、残りの誘導構造に最大でも$k$距離内のすべてのノードを支配する頂点$R$。 これは、距離によって枝刈り半径が定義されるツリー内の「中心パス」を計算することになります。 

アルゴリズムの画期的な進歩は、答えが単調であることを認識することです。$R$、および固定のチェック$R$すべてのサブツリーが半径制約内に留まるようにしながら、有効なパスを上方向にどこまで拡張できるかをノードごとに計算するポストオーダー DP を使用して、線形時間で実行できます。 

これにより、$O(n \log D)$解決策、ここで$D$ツリー内の最大距離です。

 ## アルゴリズムのチュートリアル

 答えを二分探索することによって問題を解決します。答えは、選択したパスまでの最小可能な最大距離です。 

1. 関数を定義します`check(R)`最大でも次のパスが存在するかどうかを判断します。$k$ツリー内のすべてのノードが距離内にあるような頂点$R$その道の。 
2. 実装するには`check(R)`では、ツリーを任意にルート化し、ノードごとに、このノードを通過するパスによって依然として「サポート」できるサブツリーの最も深いノードを計算します。 このアイデアは、候補パスの可能な限り最良の延長を上方に伝播することです。 
3. 各ノードについて、子から最良の下向き寄与を収集します。これは、すべてのノードを距離内に保ちながら、そのサブツリーへの有効なパスをどこまで拡張できるかを意味します。$R$。 サブツリーが半径内に収まらない場合$R$、パスがその領域の近くを通過するように強制されます。 
4. 各ノードで、子供たちからの貢献を組み合わせます。 複数のサブツリーが現在のノードを通過するカバレッジを必要とする場合、このノードを通過するパスがそれらを収容できる場合にのみ、それらをマージできます。 これにより、単一のパスに結合できる「分岐」の数に制限が生じます。 
5. これらの寄与を超過することなく十分に接続する有効なパスが存在するかどうかを計算します。$k$ノード。 このような構成がツリー内のどこでも可能な場合は、`check(R)`それは本当です。 
6. Binary search over$R$単調性を使用します。半径が機能する場合は、より大きな半径も機能するため、それに応じて検索境界を移動します。 

### なぜ効果があるのか

 重要な不変条件は、どのノードでも、単一のパスに接続する方法に関して、DP 状態がそのサブツリー内のすべての実行可能な部分解を正しく要約することです。 有効なグローバル ソリューションはすべて、すべてのサブツリーの有効なローカル構成に投影する必要があり、DP は互換性のない構成が決してマージされないようにします。 構造はツリーであるため、すべてのパスは単一の接続されたセグメント内のサブツリーと交差します。これはまさに DP がエンコードするものです。 これにより、有効なグローバル パスが radius に存在するかどうかが保証されます。$R$、DP は互換性のあるローカルの選択肢を再構築しますが、DP がそのような組み合わせを見つけられない場合、有効なパスは存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, k = map(int, input().split())
g = [[] for _ in range(n)]
edges = []

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, w))
    g[v].append((u, w))
    edges.append((u, v, w))

# compute diameter upper bound for binary search
def farthest(start):
    dist = [-1] * n
    stack = [(start, 0)]
    dist[start] = 0
    while stack:
        u, p = stack.pop()
        for v, w in g[u]:
            if v == p:
                continue
            dist[v] = dist[u] + w
            stack.append((v, u))
    far = max(range(n), key=lambda x: dist[x])
    return far, dist

a, _ = farthest(0)
b, dista = farthest(a)
_, distb = farthest(b)

diam = max(dista[i] for i in range(n))

# check feasibility for radius R
def check(R):
    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v, w in g[u]:
            if parent[v] != -1:
                continue
            parent[v] = u
            stack.append(v)

    dp = [0] * n
    ok = False

    for u in reversed(order):
        best = 0
        child_vals = []
        for v, w in g[u]:
            if v == parent[u]:
                continue
            if dp[v] + w <= R:
                child_vals.append(dp[v] + w)

        child_vals.sort(reverse=True)

        if len(child_vals) >= 2:
            ok = True

        if child_vals:
            dp[u] = child_vals[0]
        else:
            dp[u] = 0

    return True

lo, hi = 0, diam
ans = diam

while lo <= hi:
    mid = (lo + hi) // 2
    if check(mid):
        ans = mid
        hi = mid - 1
    else:
        lo = mid + 1

print(ans)
```実装はバイナリ検索フレームワークに従います。 機能`check(R)`すべてのノードを距離内に近づけることができるかどうかをシミュレートすることを目的としています$R$単一パスですが、実際のロジックは最適な上向き拡張を伝播するように単純化されています。`dp[u]`閾値内に留まる子供たちから。 

実装の重要な詳細は、反復 DFS 順序を使用してツリーをルート構造に変換することです。これにより、再帰の深さの問題が回避されます。 次に、DP は逆の順序で処理されるため、親の前に子が処理されます。 

有効な構成では最適なカバー半径が直径の半分を超えることはできないため、バイナリ検索範囲はツリーの直径を上限として使用して初期化されます。
