 ## 解決策
 ## 問題の理解

 最大 20 頂点を持つ接続された無向重み付きグラフが与えられます。 スパニング ツリーを選択する必要があります。 その木のコストは 2 つの部分から構成されます。 

最初の部分は標準であり、選択したエッジの重みの合計です。 

2 番目の部分はツリーの構造に依存します。 選択したスパニング ツリーについて、その最大一致サイズを計算します。これは、ツリーから選択できるペアごとの頂点が分離されたエッジの最大数を意味します。 適合サイズがあれば、$k$、追加料金を支払います$k \cdot c$。 

私たちの目標は、総コストを最小限に抑えたスパニング ツリーを見つけることです。 

グラフの頂点が小さいので、$n \le 20$ただし、頂点のすべてのペアにエッジがある可能性があるため、潜在的に密になる可能性があります。 スパニングツリーには、$n-1$しかし、可能なスパニングツリーの数は膨大です。 完全なグラフであっても、ケイリーの公式は次のようになります。$n^{n-2}$木々にまたがる。 のために$n=20$、それはすでにあります$2.6 \times 10^{23}$、列挙することはまったく不可能です。 

の小さな値$n$ソリューションではビットマスクを使用する必要があることを強く示唆しています。 周囲の複雑さ$O(2^n \cdot \text{poly}(n))$現実的なので、$2^{20}\approx 10^6$。 のようなもの$O(2^n n^2)$おおよそです$4\times 10^8$理論上の最悪の数では原始的な操作ですが、非常に小さな定数と慎重な実装により、6 秒の制限内で許容可能になります。 すべてのツリーの列挙や、すべてのツリー内のすべての一致を伴うものはすべて絶望的です。 

問題の危険な部分は、用語の一致です。 素朴なアイデアは、候補スパニング ツリーを生成し、それらの最大一致を計算することです。 マッチングサイズはツリー構造全体に依存するため、MST 構築と合わせて最適化する方法は明らかではありません。 

見逃しやすい状況がいくつかあります。 

4 つの頂点上のパスを考えてみましょう。```
1 - 2 - 3 - 4
```エッジを取得できるため、最大一致サイズは 2 です。$(1,2)$そして$(3,4)$。 

入力：```
4 100
0 1 0 0
1 0 1 0
0 1 0 1
0 0 1 0
```エッジの重みを最小化するだけのソリューションでは、このツリーが選択され、エッジの合計が取得されます。$3$ですが、実際のコストは$3+2\cdot100=203$。 

もう 1 つの微妙なケースはスターです。```
    2
    |
3 - 1 - 4
```すべてのエッジが中心に接しているため、最大一致サイズは 1 のみです。 

入力：```
4 100
0 1 1 1
1 0 0 0
1 0 0 0
1 0 0 0
```ツリーの重みは 3 で、マッチング ペナルティは 1 つだけです。$100$したがって、総コストは 103 です。「頂点の周囲のエッジが多いほどマッチングが大きくなる」と仮定する解決策は完全に間違っています。 

最も重要な構造上の罠は、ツリー内の最大一致サイズがローカル プロパティではないことです。 同じエッジ重み合計を持つ異なるツリーには、異なるマッチング ペナルティが適用される場合があります。 最適化では両方の項を同時に処理する必要があります。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 グラフのすべてのスパニング ツリーを列挙し、エッジの重みの合計を計算し、最大一致サイズを計算して、最小の答えを保持します。 

これが機能するのは、目的がスパニング ツリー上で直接定義されているためです。 すべての木を調べることができれば、正しさはすぐにわかります。 

問題はスパニングツリーの数です。 20 個の頂点を持つ完全なグラフには、次のものがあります。$$20^{18}$$異なるスパニングツリー。 1 秒あたり 100 万本の木をチェックしたとしても、その検索スペースには影響を与えません。 

したがって、一致する用語をより深く理解する必要があります。 

重要な観察は古典的な定理から来ています。 

すべての木は二部構成です。 

二部グラフの場合、$$\text{maximum matching} = \text{minimum vertex cover}.$$これがケーニッヒの定理です。 

マッチングについて考える代わりに、頂点カバーについて考えてください。 

最終的なツリーの最大一致サイズが次であると仮定します。$k$。 次に、ツリーには次のサイズの頂点カバーがあります。$k$。 

その頂点カバーを次のようにします$S$。 

ツリーのすべてのエッジをカバーする必要があるため、すべてのツリーのエッジの内側に少なくとも 1 つの端点が必要です。$S$。 

つまり、ツリーは端点が両方とも外側にないエッジのみを使用します。$S$。 

これにより問題は完全に変わります。 

一部のサブセットを修正$S$。 仮定する$S$は最終的なツリーの頂点カバーになります。 

その場合、許可されるすべてのツリー エッジは次の条件を満たす必要があります。$$u\in S \quad\text{or}\quad v\in S.$$言い換えると、外側の 2 つの頂点間のエッジ$S$は禁止されています。 

このようなエッジのみを使用するすべてのスパニング ツリーの中で、単純に最小重みのものが必要です。 これは、制限されたグラフにおける MST の問題にすぎません。 

その制限されたグラフが切断されている場合、この選択に対応するスパニング ツリーは存在しません。$S$。 

制限付きグラフが接続されている場合、互換性のある最も安価なスパニングツリー$S$まさにそのMSTです。 

その総コストは次のようになります$$\text{MST weight} + |S|\cdot c.$$なぜこれで十分なのでしょうか?

 なぜなら、ツリーに一致する最大サイズがある場合、$k$、サイズの頂点カバーがあります$k$。 そのカバーを列挙すると、対応する制限されたグラフ内でツリーが実行可能になります。 その制限されたグラフの MST は、そのツリーよりも安くなるしかありません。 したがって、すべてのサブセットを考慮すると、$S$最適を決して逃しません。 

ここで問題は次のようになります。 

すべてのサブセットを列挙する$S$、接触するエッジのみを含むグラフを構築します$S$、その MST 重みを計算し、最小化します。$$\text{MST weight}+|S|c.$$以来$n\le 20$、 がある$2^n$サブセット。 サブセットごとに、Prim のアルゴリズムを実行できます。$O(n^2)$。 

それにより得られるのは$O(2^n n^2)$。

 ## アルゴリズムのチュートリアル

 1. グラフを読み取り、欠落しているすべてのエッジを無限値に置き換えます。 
2. すべてのビットマスクを列挙する$mask$から$0$に$2^n-1$。 
3. 設定されたビットを解釈します。$mask$候補頂点カバーとして$S$。 
4. エッジが存在する暗黙的な制限付きグラフを構築します。$(u,v)$少なくとも 1 つのエンドポイントが属する場合にのみ許可されます$S$。 

端点が両方とも外側にあるエッジ$S$で覆われた木には出現できません$S$。 
5. この制限されたグラフで Prim のアルゴリズムを実行します。 

エッジを緩和するとき、2 つの端点が両方とも外側にあるすべてのエッジを無視します。$S$。 
6. Prim がすべての頂点に到達できない場合、制限されたグラフは切断されます。 

その場合、このサブセットは$S$スパニングツリーを生成できないため、破棄します。 
7. それ以外の場合は、MST 重みを取得します。$W$。 
8. コンピューティング$$W + c \cdot \text{popcount}(mask).$$1. すべてのマスクに対する回答を最小限に抑えます。 

### なぜ効果があるのか

 あらゆるスパニングツリーの場合$T$、 させて$k$一致する最大サイズになります。 

すべての木は二部構成であるため、ケーニッヒの定理により頂点カバーが得られます。$S$サイズの$k$。 

あらゆるエッジ$T$に少なくとも 1 つのエンドポイントがあります$S$、 それで$T$によって定義される制限されたグラフ内に完全に含まれます。$S$。 

その制限されたグラフの MST の重みは最大で次の重みになります。$T$、 なぜなら$T$は、同じグラフの 1 つの有効なスパニング ツリーです。 

したがって、この特定のサブセットについては$S$、$$\text{MST}(S)+|S|c \le \text{weight}(T)+kc.$$したがって、最適なツリーのコストは、列挙によって考慮される少なくとも 1 つの値です。 

逆に、すべてのサブセットについて$S$、制限されたグラフのすべてのスパニング ツリーには、すべてのエッジがカバーされます。$S$。 したがって$S$はそのツリーの頂点カバーであるため、一致する最大サイズは最大で$|S|$。 私たちが計算するコストは、$$\text{MST}(S)+|S|c,$$これは MST 自体によって達成可能であり、真の目的を過小評価することはありません。 

2 つの方向を合わせると、すべてのサブセットの最小値がまさに答えであることがわかります。 

マッチングから頂点カバーへの削減が重要な橋渡しとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 18

def prim(mask, n, g):
    dist = [INF] * n
    used = [False] * n
    dist[0] = 0

    total = 0

    for _ in range(n):
        v = -1

        for i in range(n):
            if not used[i] and dist[i] < INF:
                if v == -1 or dist[i] < dist[v]:
                    v = i

        if v == -1:
            return INF

        used[v] = True
        total += dist[v]

        for to in range(n):
            if used[to]:
                continue

            if ((mask >> v) & 1) == 0 and ((mask >> to) & 1) == 0:
                continue

            w = g[v][to]
            if w < dist[to]:
                dist[to] = w

    return total

def solve():
    n, c = map(int, input().split())

    g = [[INF] * n for _ in range(n)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j in range(n):
            if i == j:
                g[i][j] = INF
            elif row[j] != 0:
                g[i][j] = row[j]

    ans = INF

    for mask in range(1 << n):
        mst_cost = prim(mask, n, g)
        if mst_cost == INF:
            continue

        cur = mst_cost + c * mask.bit_count()
        if cur < ans:
            ans = cur

    print(ans)

solve()
```実装はほぼ文字通り証明に従います。 

機能`prim`マスクに対応する制限されたグラフ内の MST 重みを計算します。 すべてのサブセットに対して新しいグラフを明示的に構築するのではなく、緩和中に制限をチェックします。 少なくとも 1 つのエンドポイントがマスクに属している場合、エッジは使用できます。 

戻る`INF`未訪問の到達可能な頂点が存在しない場合が重要です。 このようにして、制限されたグラフが切断されていることを検出します。 

グラフで使用しているのは、`INF`存在しないエッジの場合。 このような値は決して距離を改善しないため、これにより Prim はそれらを自然に無視できます。 

表現```
((mask >> v) & 1) == 0 and ((mask >> to) & 1) == 0
```両方の端点が候補頂点カバーの外側にあるかどうかをチェックします。 このようなエッジは禁止されており、スキップされます。 

パイソンの`bit_count()`はサブセットのサイズを示します。これは頂点カバー ペナルティに正確に対応します。 

微妙な点の 1 つは、空のマスクが許可されていることです。 これは単に頂点が選択されていないことを意味します。 通常、制限されたグラフは切断されますが、非常に小さなグラフでは均一にテストすることが依然として有効です。

import io

def run(inp: str) -> str:
    INF = 10 ** 18

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, c = map(int, input().split())

    g = [[INF] * n for _ in range(n)]

    for i in range(n):
        row = list(map(int, input().split()))
        for j in range(n):
            if i != j and row[j] != 0:
                g[i][j] = row[j]

    def prim(mask):
        dist = [INF] * n
        used = [False] * n
        dist[0] = 0

        total = 0

        for _ in range(n):
            v = -1

            for i in range(n):
                if not used[i] and dist[i] < INF:
                    if v == -1 or dist[i] < dist[v]:
                        v = i

            if v == -1:
                return INF

            total += dist[v]

                if used[to]:

                if ((mask >> v) & 1) == 0 and ((mask >> to) & 1) == 0:
                    continue

                if g[v][to] < dist[to]:

    ans = INF

    for mask in range(1 << n):
        cur = prim(mask)
        if cur != INF:
            ans = min(ans, cur + c * mask.bit_count())

    return str(ans) + "\n"

 ## 特殊なケース

 星形グラフを考えてみましょう。```
4 100
0 1 1 1
1 0 0 0
1 0 0 0
1 0 0 0
```よくある間違いは、マッチングペナルティが中心の度合いとともに大きくなると仮定することです。 実際には、すべてのエッジが同じ頂点を共有するため、一致するエッジに属することができるのは 1 つのエッジだけです。 

アルゴリズムは、頂点カバーの定式化を通じてこれを処理します。 カバーとして中心だけを選択すると、マスク サイズ 1 が与えられます。制限されたグラフにはすでにすべての木のエッジが含まれているため、Prim は重み 3 を返し、答えは次のようになります。$$3 + 1\cdot100 = 103.$$次にパスを考えてみましょう。```
4 100
0 1 0 0
1 0 1 0
0 1 0 1
0 0 1 0
```最大一致サイズは 2 です。最小頂点カバーのサイズも 2、つまり頂点 2 と 3 です。 

アルゴリズムがそのマスクを列挙する場合、すべてのパス エッジが許可されます。 プリムは木の重み 3 を取得し、$$3 + 2\cdot100 = 203.$$サイズ 1 のマスクは 3 つのエッジすべてをカバーできないため、アルゴリズムは、マッチング ペナルティが 100 になる可能性があるという不可能な仮定を正しく拒否します。 

最後に、グラフを切り離すマスクを考えてみましょう。```
4 1
0 1 1 1
1 0 1 1
1 1 0 1
1 1 1 0
```マスクを取る`{1}`。 

頂点間のエッジ`{2,3,4}`どちらのエンドポイントもカバーに属していないため、禁止されています。 制限されたグラフは、頂点 1 を中心とする星形になり、まだ接続されています。 

代わりに空のマスクを使用すると、すべてのエッジが禁止されます。 プリムはすべての頂点に到達できずに戻ります`INF`。 アルゴリズムはそのサブセットを自動的に破棄します。 

この接続チェックは不可欠です。 多くのマスクは有効なスパニング ツリーに対応していないため、マスクを有効なものとして扱うと不正確な応答が生成されます。
