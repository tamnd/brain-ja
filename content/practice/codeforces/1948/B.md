 ## 解決策
 ## 問題の理解

 0 から 99 までの整数の配列が与えられます。私たちの目標は、2 桁の数値を個々の桁に繰り返し「分割」することによって、それを非減少配列に変換できるかどうかを判断することです。 具体的には、少なくとも 10 個の要素については、その要素を順番にその数字に置き換えることができます。 たとえば、12 は [1, 2] になり、45 は [4, 5] になります。 この操作は、適格な要素に対して何度でも実行できます。 このタスクは、配列全体を非降順でソートする一連の操作が存在するかどうかを判断することです。 

この制約により、最大 50 個、最大 1000 個のテスト ケースの長さの配列が得られます。 最大の配列は小さいため、配列の長さが 2 次であるアルゴリズムは実現可能ですが、要素数が指数関数的なものは実用的ではありません。 各要素は最大 99 個であるため、「分割」操作により生成される新しい要素は最大 2 つで、これが変換された配列のサイズを制限します。 

エッジ ケースは、数値がすでに 1 桁である場合、配列に重複が含まれている場合、または順序に合わせるためにより大きな数値を分割する必要がある場合に発生します。 たとえば、入力`[12, 3]`に変換できます`[1, 2, 3]`、並べ替えられます。 分割を考慮せずに元の数値のみをチェックする不注意な実装では、誤って「NO」が報告されてしまいます。 もう 1 つのエッジ ケースは、すべての数値がすでに 0 または 1 桁の数値である場合です。`[0, 0]`; アルゴリズムはそれをすでにソート済みとして認識する必要があります。 

## アプローチ

 ブルートフォースアプローチは、可能なすべての順序で分割を実行して、可能なすべての配列を生成することです。 各配列について、それが減少していないかどうかを確認します。 これは、すべての組み合わせを徹底的に試行するため、原理的には正しいですが、可能性の数は、複数桁の数値の数に応じて指数関数的に増加します。 配列の最大長が 50 であっても、およそ`2^50`最悪の場合の可能性は大きすぎます。 

最適な解決策を可能にする重要な洞察は、数値を分割することは相対的な桁の順序を決して減らすことがないため、並べ替えに厳密に有益であるということです。 それぞれの数字`x`2 桁のうち、1 桁目と 2 桁目にのみ分割でき、これらの桁は常に減少しません (`x//10 <= x%10`）。 したがって、すべての組み合わせを探索する代わりに、貪欲なアプローチを取ることができます。つまり、2 桁の各数値をその構成桁にすぐに変換し、結果の配列がソートされているかどうかを確認します。 早く分割しても配列の並べ替えが容易になるだけなので、分割を遅らせるメリットはありません。 

この洞察を適用することで、問題を、非減少次数を検証するための変換された配列の単純なパスに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲な分割 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`b`これは、変換された配列を保持します。 元の配列を反復処理し、各 2 桁の数値をその桁に置き換えます。 
2. 各要素について`x`配列内で`a`、それが少なくとも 10 であるかどうかを確認します。そうであれば、追加します`x // 10`に続く`x % 10`に`b`。 それ以外の場合は追加します`x`直接。 これにより、数値を桁に分割することがすぐにシミュレートされます。 
3. すべての要素が処理されたら、`b`を反復処理します`b`そして、各要素が前の要素以上であるかどうかを確認します。 いずれかの要素がこの条件に違反する場合、分割を使用して配列を並べ替えることは不可能であると結論付けられ、「NO」が出力されます。 
4. アレイ全体が`b`非減少チェックに合格すると、「YES」が出力されます。 

なぜ機能するのか: あらゆる点で配列`b`には、分割後に可能な最小の表現が含まれており、さらに分割しても最初の桁が減ったり、より小さい数値が作成されたりすることはありません。 したがって、もし`b`が非減少の場合、元の配列をソートする一連の操作があります。 逆に、もし`b`は非減少ではなく、一連の分割によって修正することはできません。すでにすべての数値を分割しており、さらに分割しても要素数が増加するだけで、順序を改善するために桁が減少することはないからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = []
        for x in a:
            if x >= 10:
                b.append(x // 10)
                b.append(x % 10)
            else:
                b.append(x)
        ok = True
        for i in range(1, len(b)):
            if b[i] < b[i - 1]:
                ok = False
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    main()
```ソリューションでは、テスト ケースの数を読み取り、各テスト ケースに対して配列を読み取ります。 変換された配列`b`数値を即座に分割することによって構築されます。 非減少次数のチェックは 1 回のパスで実行されます。 このアプローチにより、不必要な分割が回避され、ソートが可能かどうかを判断するために関連するシーケンスのみを追跡することが保証されます。

 ## 特殊なケース

 のような配列の場合`[12, 3]`、アルゴリズムは 12 を次のように分割します。`[1, 2]`3 を追加して取得します`[1, 2, 3]`。 このチェックでは、配列がソートされていることを確認し、「YES」が生成されます。 のために`[28, 5]`、分割すると生成される`[2, 8, 5]`。 最後の要素 5 は 8 未満であるため、チェックは失敗し、「NO」が生成されます。 これにより、アルゴリズムが、分割が必要だが不十分な配列、およびすでにソートされている配列または簡単にソート可能な配列を処理できることが確認されます。
