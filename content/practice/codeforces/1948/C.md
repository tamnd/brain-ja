 ## 解決策
 ## 問題の理解

 We have a 2-row grid with$n$各セルには左または右を指す矢印が含まれています。 ロボットは左上隅から開始し、毎秒まず最初に隣接するセル (上下左右) に移動し、新しいセルの矢印に従います。 私たちの目標は、ロボットが右下隅に到達できるかどうかを判断することです。 

入力は複数のテスト ケースを与え、それぞれが指定します$n$2 つの矢印の列は 2 つの行を表します。 に達した場合、出力は YES になります。$(2, n)$可能ですが、それ以外の場合は「いいえ」です。 

制約が示すのは、$n$まで行くことができます$2 \cdot 10^5$と合計$n$すべてのテスト ケースにわたって次の制限も受けられます。$2 \cdot 10^5$。 これにより、完全な状態拡張を伴う単純な再帰または BFS スタイルでグリッドを徹底的に探索するアルゴリズムは除外されます。そのようなアプローチには、次のようなアプローチが含まれる可能性があるためです。$O(n^2)$テストケースごとの操作が遅すぎます。 ロボットは隣接するセルにのみ移動し、矢印の方向によって制限されるため、ソリューションではすべてのパスを盲目的に探索するのではなく、この構造を活用する必要があります。 

単純なソリューションが失敗する可能性のあるエッジ ケースには、続行するために行の切り替えが必須となるグリッドが含まれます。 たとえば、最初の行が左矢印で終わり、2 番目の行が右矢印で終わっている場合、上の行に沿って真っすぐ移動するとロボットがトラップされます。 もう 1 つの微妙なケースは、ロボットが最後の列に到達することなく行間を無限に振動する可能性がある場合に発生します。 矢印の制約を無視して単純な動きをシミュレートするだけの場合、これらのシナリオはパスが存在することを誤って示唆する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、BFS または DFS を使用して、考えられるすべての一連の動きをシミュレートします。 各セルで、ロボットは上下左右に移動して、矢印に従ってください。 これは、到達可能なすべての状態を調査するため、原則的には正しいです。 ただし、$n = 2 \cdot 10^5$、各セルは 4 つの可能性に分岐する可能性があり、状態の合計数が大きくなりすぎます。 操作回数は次のとおりです$O(4^n)$最悪の場合、それは不可能です。 

重要な洞察は、水平方向の動きが矢印の方向によって厳しく制限されていることを観察することで得られます。 上の行の左矢印は、行を切り替えずに右に進むことを防ぎます。 行の切り替えは、新しい行の矢印で前方に移動できる場合にのみ役立ちます。 これにより、問題はローカル チェックに帰着します。ロボットは、矢印の方向が一致していれば常に水平に移動でき、現在の行と目的の行の矢印の両方がロボットの位置に対して後方を向いている場合、行を切り替えることができます。 したがって、列に沿った貪欲なトラバーサルを使用してパスを分析し、各列で前進または切り替えが可能かどうかを確認できます。 

この観察により、$O(n)$アプローチ: 列を左から右にスキャンし、各列で最大 1 つの行スイッチを使用して有効なパスが存在するかどうかを確認します。 考えられるすべてのシーケンスをシミュレートする必要はもうありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^n) | O(n) | 遅すぎる |
 | 貪欲な横断 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 一番上の行の列 0 から開始します。 現在の行 (1 または 2) を追跡します。 
2. 各列について、現在の行の矢印を調べます。 右を向いている場合、ロボットは同じ行の次の列に移動できます。 左を向いている場合、列の切り替えが許可されない限り、ロボットは右に移動できなくなります。 
3. 他の行への切り替えが可能かどうかを確認します。 他の行の現在の列の矢印が右 (ゴール方向) を向いている場合、スイッチは有効です。 列を切り替えて移動を続けます。 
4. どの列でも前進も切り替えもできない場合は、終了して NO を返します。 
5. 最後の列に到達するまで続けます。 ロボットが2行目列に到着した場合$n$、YESを返します。 それ以外の場合は NO を返します。 

機能する理由: 各列チェックにより、ロボットが無効な状態に決して移行しないという不変条件が維持され、法的措置が存在する場合にのみロボットが移動することが保証されます。 水平方向の移動には一致する矢印が必要で、垂直方向の切り替えはターゲット行が前方への移動を許可する場合にのみ発生します。 列方向のスキャンにより、指数関数的な探索を回避しながら、潜在的なパスを決して見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_reach(n, top, bottom):
    row = 0  # 0 for top, 1 for bottom
    col = 0
    while col < n:
        if row == 0:
            if top[col] == '>':
                col += 1
            elif bottom[col] == '>':
                row = 1
            else:
                return "NO"
        else:
            if bottom[col] == '>':
                col += 1
            elif top[col] == '>':
                row = 0
            else:
                return "NO"
    return "YES" if row == 1 else "NO"

t = int(input())
for _ in range(t):
    n = int(input())
    top = input().strip()
    bottom = input().strip()
    print(can_reach(n, top, bottom))
```このソリューションでは、貪欲な列方向のスキャンを使用します。 現在の行を追跡し、可能な限り前に進むことを試みます。 前進がブロックされている場合は、列を切り替えることで進行できるかどうかを確認します。 これにより、ロボットが列ごとに移動するため、移動ルールが尊重され、境界のオーバーシュートが防止されます。

    sys.stdin = io.StringIO(inp)

            bottom = input().strip()
