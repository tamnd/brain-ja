 ## 解決策
 ## 問題の理解

 1 から n までのタイムラインと一連の間隔が与えられ、それぞれが特定の時間枠内でのみ使用可能になる「赤い封筒」を表します。 各封筒には値と強制クールダウン効果もあります。ボブが時刻 x で封筒を受け取った場合、彼はすぐにそのコインを受け取りますが、その後は時刻 d_i まで何も受け取ることができなくなり、時刻 d_i + 1 でのみ再開されます。 

複数のエンベロープが同時に利用可能な場合、ボブは決定論的に動作します。 彼は常に最も高い値を持つものを選択し、値が同点の場合は、より大きなクールダウン エンドポイント d_i を持つものを優先します。 これにより、彼の行動は、現在利用可能なエンベロープによって完全に駆動される貪欲なプロセスになります。 

アリスは最大 m 回まで介入できます。 それぞれの介入により、ボブは 1 つの時点で行動することができなくなり、実質的にその瞬間をスキップすることになります。 時間 x をスキップした後、x + 1 から再開しますが、利用可能なエンベロープのセットが変更されているか、同じ選択が再び許可されている可能性があります。 

課題は、アリスがボブの貪欲な行動で最終的に収集するコインの合計ができるだけ少なくなるように、どの瞬間にボブの邪魔をすべきかを選択することです。 

この制約は、すべての時点およびすべての選択肢にわたる直接シミュレーションが実行不可能であることをすでに示唆しています。 タイムラインは最大100000、妨害は最大200ですが、エンベロープの数も多くなります。 時間の経過に伴う単純な動的プログラミングと外乱数は 2e7 状態程度必要になりますが、Python ではすでに限界があり、各遷移にコストがかかる場合は実行不可能です。 

さらに微妙な問題は、ボブのプロセスが「封筒ごとに 1 つの決定」ではなく、時間の経過とともに継続的なプロセスであり、エンベロープが重なって持続する可能性があることです。 特に、1 単位でも遅延すると有効期限切れや最大選択エンベロープの変更が発生する可能性があるため、タイミングの小さな変更によって、次にどのエンベロープが選択されるかが完全に変わる可能性があります。 

見落としやすいエッジ ケースの 1 つは、複数の同一の最良のエンベロープが長時間にわたって重なる場合です。 ある瞬間にアリスが邪魔をすると、ボブは次の瞬間にすぐに同じ封筒を再び取り出す可能性があります。つまり、邪魔は決定を削除するのではなく、変更するだけであることを意味します。 たとえば、エンベロープが時間 1 から 10 まで最適である場合、時間 1 をスキップすると、ボブは代わりに時間 2 でエンベロープを選択するだけになります。 実際にそれを回避するには、アリスは一度中断するだけでなく、許可されたウィンドウを超えてピックを遅らせる必要があります。 

もう 1 つの特殊なケースは、ボブがクールダウン中の場合です。 ボブはすでに非アクティブであるため、クールダウン中に障害が発生しても何も変わりません。 すべての時間ステップに意味があると仮定するソリューションでは、状態が過大にカウントされます。 

## アプローチ

 ブルートフォース戦略では、可能なすべての妨害時間の選択に対してボブの行動を明示的にシミュレートします。 最大 m 時点の各サブセットについて、貪欲なプロセスを再実行し、結果の合計を計算します。 単一の外乱セットを修正したとしても、アクティブ エンベロープの優先順位構造を使用すると、シミュレーションは O(n + k log k) になります。 擾乱セットの数は n^m のオーダーであり、m = 2 の場合でも天文学的に大きくなります。 

より構造化されたブルート フォースでは、時間と妨害回数に応じた動的プログラミングが使用されます。 dp[t][j] が、j 個の外乱が残っている状態で、時間 t 以降の最良の結果を表すものとします。 時間 t で、現在利用可能な最適なエンベロープを決定し、それを採用するかスキップします。 これにより、時間の経過に伴う移行の問題が即座に軽減されます。

重要な観察は、2 つの意味のあるイベントの間のボブの行動が安定しているということです。 何かが変化するのは、エンベロープがアクティブになったとき、有効期限が切れたとき、またはボブがエンベロープを受け取ってクールダウンに入ったときだけです。 このようなイベント間では、「利用可能な最良のエンベロープ」の正体は変わりません。 これにより、タイムラインを、決定が統一されたイベント セグメントに圧縮することができます。 

この構造が明らかになると、問題は時間の経過とともに最短パスのような DP になり、各状態が 1 つのエンベロープを消費する (クールダウンによって前方にジャンプする) か、または外乱を使用して時間を 1 ステップずらすかのいずれかになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 妨害セットに対する総当たり攻撃 | O(n^m · n log n) | O(n) | 遅すぎる |
 | イベント圧縮による時間の経過に伴う DP | O(n · m + k log k) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 毎回 t で 2 つの質問に答えることができるようにプロセスを再定式化します。それは、ボブが行動する場合にどのエンベロープを選択するか、そして 1 単位だけ遅らせるとどうなるかです。 

1. アクティブなエンベロープのセットを時間 t ごとに事前計算し、最大の重みを持つエンベロープを維持し、より大きい d によって関係を解消します。 これはスイープ ラインと優先キューを使用して実行でき、s_i でエンベロープを追加し、t_i の後にエンベロープを削除します。 
2. アリスが j 個の妨害を利用できる場合に、時刻 t から開始してボブが収集できる最大コインを表す動的プログラミング テーブル dp[t][j] を定義します。 
3. 必要なときに将来の状態がすでにわかっているように、時刻 n から 1 までの dp を計算します。 
4. 各時間 t で、利用可能な最良のエンベロープ e(t) を取得します。 使用可能なエンベロープがない場合、この時点では何も起こらないため、dp[t][j] は単に dp[t+1][j] になります。 
5. 封筒が存在する場合、アリスには 2 つの選択肢があります。 彼女は時間 t で妨害することができます (妨害がまだ残っている場合)。これにより妨害が 1 つ消費され、ボブが行動することなくシステムが時間 t+1 に移動します。 これにより dp[t+1][j-1] が得られます。 
6. あるいは、アリスはボブの行動を許可します。 ボブはエンベロープ e(t) を取得し、その値を取得し、時間 d + 1 まで非アクティブになります。したがって、次の状態は dp[d+1][j] にエンベロープの値を加えたものになります。 
7. これらの選択肢のうち最大のものを選択します。 

重要な考え方は、1 単位遅延しても利用可能なエンベロープのセットは変更されず、時間インデックスのみが変更されるということです。 これにより、「スキップ」遷移がローカルで明確に定義されます。 

### なぜ効果があるのか

 DP は、各時刻 t において、意味のある効果が 2 つだけであるという不変式に依存します。それは、ボブの状態を変更せずに時間を 1 つ進めるか、ボブがその瞬間に選択するであろうエンベロープを正確に実行してその回復時間にジャンプするかのどちらかです。 ボブの貪欲なルールにより、ボブの選択は将来の外乱ではなく現在アクティブなエンベロープのみに依存することが保証されるため、最適な戦略はそのようなアトミックなアクションのシーケンスに分解できます。 したがって、アリスの影響は、時間をユニットごとにずらすか、可能な限り早い実行時点でエンベロープを消費することによって完全に捕らえられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, m, k = map(int, input().split())
    
    add = [[] for _ in range(n + 2)]
    remove = [[] for _ in range(n + 2)]
    
    envelopes = []
    for i in range(k):
        s, t, d, w = map(int, input().split())
        envelopes.append((s, t, d, w))
        add[s].append((w, d, s, t))
        if t + 1 <= n:
            remove[t + 1].append((w, d, s, t))
    
    # active set as max-heap by (w, d)
    heap = []
    alive = {}
    
    best = [None] * (n + 2)
    
    for t in range(1, n + 1):
        for item in add[t]:
            w, d, s, te = item
            heapq.heappush(heap, (-w, -d, w, d))
            alive[(w, d, s, te)] = alive.get((w, d, s, te), 0) + 1
        
        for item in remove[t]:
            w, d, s, te = item
            alive[(w, d, s, te)] -= 1
        
        while heap:
            nw, nd, w, d = heap[0]
            key = (w, d)
            # lazy check: ensure exists
            found = False
            for (ws, ds, s, te), cnt in alive.items():
                if cnt > 0 and ws == w and ds == d:
                    found = True
                    break
            if found:
                break
            heapq.heappop(heap)
        
        if heap:
            w, d = heap[0][2], heap[0][3]
            best[t] = (w, d)
        else:
            best[t] = None
    
    INF = 10**18
    
    # dp[t][j]
    dp = [[0] * (m + 1) for _ in range(n + 3)]
    
    for t in range(n, 0, -1):
        for j in range(m + 1):
            # skip
            res = dp[t + 1][j]
            
            if j > 0:
                res = max(res, dp[t + 1][j - 1])
            
            if best[t] is not None:
                w, d = best[t]
                nxt = d + 1 if d + 1 <= n + 1 else n + 1
                res = max(res, w + dp[nxt][j])
            
            dp[t][j] = res
    
    print(dp[1][m])

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に、各時点について、ボブがその時点で行動した場合に取られる最適なエンベロープを構築します。 これは、アクティブな間隔のヒープを持つスイープ ラインを使用して行われます。 

その後、動的計画法は時刻 n から逆方向に動作します。 各ステップで、現在の瞬間をスキップするか (外乱を消費するかどうか)、利用可能な最良のエンベロープを実行してクールダウン エンドポイントにジャンプします。 DP テーブルは将来のすべての結果をエンコードするため、各遷移はローカルであり、プロセス全体を再シミュレートする必要はありません。 

微妙な詳細は、ジャンプ状態のインデックス付けです。 パラメータ d のエンベロープを取得した後、ボブは d + 1 から再開しますが、これは n を超える可能性があります。 これは安全に n + 1 にクランプされるため、タイムラインを超えた dp はゼロとして機能します。

 ## 特殊なケース

 重大なエッジ ケースは、最適なエンベロープが長期間連続して変化しない場合に発生します。 この状況では、ボブがすぐに同じエンベロープを再試行するため、単純な「1 回スキップ」戦略は失敗します。 スキップされたタイム ステップごとに t が 1 つ進み、エンベロープが期限切れになるか最終的に取得されるまで繰り返し決定が強制されるため、DP はこれを正しく処理します。 

もう 1 つの微妙なケースは、エンベロープのクールダウンにより、次の決定がまったく新しいエンベロープが利用可能になる領域に押し込まれる場合です。 t から d+1 への DP ジャンプはこれを正確に捉え、遅延した結果が新しい時間から完全に再評価されることを保証します。 

最後のエッジ ケースは、長いプレフィックスに対してアクティブなエンベロープがない場合です。 DP は dp[t][j] = dp[t+1][j] を正しく伝播し、状態に影響を与えることなくアイドル時間を効果的に圧縮します。
