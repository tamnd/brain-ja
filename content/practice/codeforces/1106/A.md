 ## 解決策
 ## 問題の理解

 2 つの可能な文字で満たされた正方形のグリッドが与えられます。`X`そして`.`。 タスクは、このグリッドの内部セルをすべてスキャンし、それが対角線で形成される「十字」パターンの中心であるかどうかを判断することです。 

ポジション`(i, j)`セル自体とその 4 つの対角線上の隣接セルがすべてクロス センターである場合にのみ、クロス センターとしての資格を持ちます。`X`。 Concretely, the five required cells are`(i, j)`、`(i-1, j-1)`、`(i-1, j+1)`、`(i+1, j-1)`、 そして`(i+1, j+1)`。 

出力は、単純にグリッド内の有効な中心の数です。 

グリッド サイズは最大です`500 × 500`、これは最大 250,000 個のセルを意味します。 一定の作業量で各セルをチェックすることは快適に実行可能ですが、より大きなパターンを繰り返しスキャンしたり、高価な条件を再チェックしたりするソリューションは、より深いループ内で誤って不要な繰り返し作業を導入しない限り、依然として合格します。 

微妙なエッジ ケースは、グリッドが小さすぎて有効な中心を含めることができない場合です。 もし`n < 3`の場合、4 つの斜めの隣接セルすべてを持つセルは存在しないため、答えは常に 0 になります。 次の場合には、別のエッジケースが発生します。`X`クラスターは存在しますが、対角方向に不完全です。たとえば、完全なプラス型の行または列です。`X`対角線だけが重要なので役に立ちません。 

典型的な間違いは、4 方向の隣接性のみをチェックするか、誤って対角線の代わりに直交する隣接線を使用することです。 もう 1 つのエラーは、特に次の場所で境界チェックを忘れることによって発生します。`i = 1`、`i = n`、`j = 1`、`j = n`、斜めのアクセスは範囲外になります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 あらゆる細胞に対して`(i, j)`グリッド内で、4 つの対角線上の近傍とそれ自体をチェックすることによって、それが有効な中心であるかどうかを検証しようとします。 各チェックには一定の時間がかかるため、全体の複雑さは次のようになります。`O(n^2)`。 各検証では 5 つのセルのみを検査するため、このアプローチは漸近的な動作の点ですでに最適です。 

これが効率的に機能する理由は、交差の条件が完全に局所的であるためです。 異なる候補センター間には依存関係がないため、前処理や動的プログラミングは必要ありません。 各セルは独立して評価できます。 

すでに各セルに一度触れているため、さらに最適化を試みても複雑さのクラスは変わりません。 唯一の「最適化」は、境界を慎重に処理し、内部チェック内の冗長な計算を回避することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(n²) | O(1) おまけ | 承認済み |
 | 最適 | O(n²) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド サイズとグリッド自体をメモリに読み取ります。 これを文字列のリストとして保存するため、インデックス付けは O(1) になります。 これにより、解析オーバーヘッドなしで直接文字にアクセスできるようになります。 

2. カウンタをゼロに初期化します。 これにより、有効なクロスセンターの数が累積されます。 

3. すべてのセルを反復処理します。`(i, j)`そのような`1 < i < n - 1`そして`1 < j < n - 1`。 有効な中心には 4 つの対角線上の近傍が必要であるため、境界線はスキップします。 

4. 各候補セルについて、必要な 5 つの位置すべてに以下が含まれているかどうかを確認します。`X`。 そのうちの 1 つでもそうでない場合は、`X`、セルは即座に拒否されます。 この早期拒否により、不一致が見つかった場合の不必要なチェックが回避されます。 

5. すべての条件が満たされると、カウンターがインクリメントされます。 

6. グリッド全体をスキャンした後、カウンターを出力します。 

### なぜ効果があるのか

 すべての有効なクロスは、その中央のセルによって一意に識別されます。 十字の定義は 5 つの位置の固定セットにのみ依存するため、これら 5 つのセルをチェックすることは必要かつ十分です。 他の構成では、これらの正確な対角位置を等しくすることなく、有効なクロスを生成することはできません。`X`。 すべての候補中心が 1 回だけテストされ、有効な構成がスキップされないため、アルゴリズムはすべての交差を 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    grid = [input().strip() for _ in range(n)]

    if n < 3:
        print(0)
        return

    ans = 0

    for i in range(1, n - 1):
        for j in range(1, n - 1):
            if (grid[i][j] == 'X' and
                grid[i - 1][j - 1] == 'X' and
                grid[i - 1][j + 1] == 'X' and
                grid[i + 1][j - 1] == 'X' and
                grid[i + 1][j + 1] == 'X'):
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。有効な内部セルのみを反復処理し、必要な 5 つの位置を明示的にテストします。 初期の`n < 3`チェックにより、不要なループが防止され、境界ロジックもクリーンになります。 

実装でよくある間違いは、混同することです`(i-1, j+1)`と`(i+1, j-1)`または、対角線を 1 つ完全に忘れてしまいます。 もう 1 つの微妙な問題は、誤って次から反復してしまうことです。`0`に`n-1`次に、ループ内に境界チェックを追加します。これにより、煩雑になり、off-by-one エラーのリスクが増加します。

 ## 特殊なケース

 のために`n = 1`または`n = 2`の場合、アルゴリズムはループが実行される前にすぐにゼロを返します。 これは、斜めに隣接する 4 つのセルがないという事実と一致します。 

完全に埋められたグリッドの場合、`X`、すべての内部セルがチェックされますが、隣接する中心の対角線が正しく重なっていないため、ほとんどのセルは失敗します。 たとえば、`3×3`すべてのグリッド`X`、中心は有効ですが、より大きなグリッドでは、境界線に隣接する候補は対角線が欠落しているため失敗します。 

スパースグリッドの場合、`X`縦線または横線が形成されますが、斜めの構造がないため、十字は検出されません。 アルゴリズムはすべての候補を正しく検査しますが、対角一致が欠落しているため候補を拒否します。 

各ケースでは、決定が純粋に局所的なものであり、候補ごとに 5 つのセルのチェックによって完全に捕捉されることが確認されています。
