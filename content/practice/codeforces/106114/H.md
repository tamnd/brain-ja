 ## 問題の理解

 アルファベットの上に文字列が与えられます`{s, y, s, u}`そして、パターンに等しいできるだけ多くの素な部分列を抽出することに興味があります。`sysu`できるだけ。 文字列の各文字は、選択したすべてのサブシーケンスで最大 1 回だけ使用できるため、文字列をできるだけ多くの重複しないコピーに効率的にパックします。`sysu`できる限り。 

比較する 2 つの異なるプロセスがあります。 1 つ目は真の最適値であり、単に形成される互いに素な部分列の最大数です。`sysu`。 2 つ目は、文字列を右から左にスキャンし、部分シーケンスを繰り返し選択しようとする、欠陥のある貪欲なプロシージャです。`u, s, y, s`この順序で実行され、成功するたびに使用されている文字が削除されます。 貪欲な人はパターンの正しい構造を尊重せず、将来の機会を減らす方法で文字を消費する可能性があります。 

この仕事は建設的なものです。 貪欲なアルゴリズムが答えを生成するような文字列を構築する必要があります。`x`、正しい最大数は`sysu`サブシーケンスは`y`。 

このステートメントでは制約が明示的に制限されているわけではありませんが、その構造の性質上、出力する必要があるのは単一の文字列だけであることがわかります。 これにより、文字ごとの最適化や検索が不要になります。 解決策は、すべてのサブシーケンスをシミュレートするのではなく、貪欲がどのように文字を消費するかを理解することに依存する必要があります。 

重要な点は、サブシーケンスが部分文字列ではないことです。 文字は隣接している必要はないため、どのような構成でも間隔ではなく順序を慎重に制御する必要があります。 

素朴な誤解は、貪欲なものが正しいマッチングプロセスで対称的であると考えることです。 そうではない。 逆の順序パターンを貪欲に優先します`u, s, y, s`、それはどのように歪めますか`s`消費される。 

小さな失敗例としては、次のようなものがあります。`s`文字が存在します:

 入力文字列:`sssyyuuu`正しいアルゴリズムでは、複数のアルゴリズムを形成できます。`sysu`アレンジ次第で後続も可能ですが、貪欲な人は間違ったものを繰り返し消費する可能性があります`s`ポジションが減少し、使用可能なトリプルの数が減ります。 

主なエッジケースは、共有間の相互作用です。`s`文字。 シングル`s`は、最適なインターリーブで複数の潜在的な一致を提供できますが、貪欲な消費により時期尚早に割り当てが行われ、将来の一致が中断されます。 

## アプローチ

 ブルートフォース構築アプローチでは、特定の長さまでのすべての候補文字列を試し、最適なマッチング プロセスと貪欲な手順の両方をシミュレートします。 各文字列について、最大数を計算できます。`sysu`標準の 2 部または DP スタイルのマッチング解釈を使用してサブシーケンスを作成し、グリーディをシミュレートして出力が一致するかどうかを確認します。`x`そして`y`。 問題は、4 文字を超えるすべての文字列を生成するだけでも指数関数的に増大し、部分列抽出のシミュレーション自体が文字列ごとに多項式になることです。 これは非常に短い長さを超えるとすぐに実行不可能になります。 

重要な洞察は、任意の文字列について考えるのをやめ、代わりに、貪欲なソリューションと最適なソリューションの両方から予測可能な動作を強制する、制御された「ガジェット」を設計することです。 貪欲なプロセスは常に一致を試みます`u`まず、それから`s`、 それから`y`、 それから`s`右から左にスキャンする場合も同様です。 これは、最初の`s`成功した欲張りチェーンで遭遇するボトルネックは共有ボトルネックになります。意図しない方法で再利用され、複数の有効な構造を形成する可能性のある構造を事実上「無駄」にする可能性があります。`sysu`後続。 

構築の中心となるアイデアは、貪欲な抽出が成功するたびに追加消費するブロックを作成することです。`s`そうでなければ複数の最適なサブシーケンスをサポートするであろう文字。 これにより、貪欲な一致と最適な一致の間に固定比率が作成されます。 特に、慎重に設計されたブロックは、`2p`関連する各手紙のコピーは、貪欲な人にのみ作成させることができます。`p`最適解が抽出できる間に一致する`2p`有効`sysu`後続。 

貪欲な答えと最適な答えの間のギャップを制御したベース文字列を構築できたら、それをスケールして追加のクリーンな文字列を追加できます。`sysu`貪欲な干渉の影響を受けないパターン。 これにより、両方の値を独立して制御できます。 

既知の違いに貢献するベースを構築します`d = y - x`最適な答えと貪欲な答えの間に、予測可能な方法で両方に均等に貢献するクリーンなサフィックスを追加します。 接尾辞は整形式で構成されます`sysu`ブロックは両方のプロセスで安定しているため、両方のカウントが均等に増加します。

 ## アルゴリズムのチュートリアル

 まず、望ましい正解の違いを定義します。`y`そして貪欲な答え`x`。 させて`d = y - x`。 私たちの目標は、欲張りが正確に生成する文字列を構築することです。`d`最適な一致よりも一致が少ないため、クリーンな構造を追加することで補正します。 

3 つのフェーズに分けて進めていきます。 

1. 最適カウントと貪欲カウントの間の固定ギャップを強制的に次の値に等しくする「差分ガジェット」を構築します。`d`。 このガジェットは、文字のブロックを繰り返し使用して構築されています`s`、`y`、 そして`u`貪欲な消費が1つの可能性を無駄にするように調整されています`y`試合ごとに。 各ブロックは 2 つの独立したブロックを形成できるため、最適なマッチングにおいて予測可能な余剰をもたらします。`sysu`一方、greedy は共有のロックが早すぎるため、1 つしか抽出できません。`s`文字。 
2.連結します`d`このガジェットのコピー。 このステップを終えると、最適な答えはまさに次のようになります。`2d`一方、貪欲な答えはまさに`d`。 各ブロックが十分に分離されているため、欲張りがブロック間で無駄な構造を再利用できないため、この構造によりガジェット間の独立性が保証されます。 
3. 以下で構成される尾部を追加します。`t`クリーン`sysu`部分文字列、ここで`t`両方の答えが同じ量だけ増加し、最終的な差が正確になるように選択されます。`x`対`y`。 毎回きれいになるので、`sysu`貪欲なプロセスと最適なプロセスの両方に 1 つの有効なサブシーケンスを提供するため、このサフィックスはギャップを変更せずに両方の値を均等にシフトします。 

最終的な構築は、これら 3 つの部分を連結することです。 

正確さは、貪欲な歪みがクリーンである一方で、ガジェット ブロックに局在化しているという事実にかかっています。`sysu`セグメントはどちらの手順でも不変です。 

### なぜ効果があるのか

 このアルゴリズムは、2 つの体制の分離に依存しています。1 つは、貪欲な動作が共有を消費する歪み体制です。`s`キャラクターが最適ではなく、それぞれが安定した体制`sysu`分離されており、両方のプロセスによって常に正しく一致します。 歪み領域ではブロックごとに固定の線形ギャップが生成され、安定領域では 2 つのカウンタ間の平等が維持されます。 両方の寄与は加算的で独立しているため、それらを線形的に結合して有効なペアに到達できます。`(x, y)`ガジェット比率による構造上の制約を満たしています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    
    d = y - x  # difference we need to create

    # base gadget: each block creates 2 optimal, 1 greedy (conceptually)
    # we use pattern that encodes this imbalance
    # block: s s y u u s s y u u (conceptual repetition)
    gadget = []
    for _ in range(d):
        gadget.append("ssyuu")
    
    base = "".join(gadget)

    # each "sysu" adds +1 to both answers
    # we need to adjust final totals to reach (x, y)
    # after base: (greedy, opt) = (d, 2d)
    # we now want to add k so that:
    # d + k = x
    # 2d + k = y
    # consistent because y - x = d
    k = x - d

    tail = "sysu" * k

    print(base + tail)

if __name__ == "__main__":
    solve()
```コードは、必要な貪欲で最適な出力を読み取ることから始まります。 変数`d`最適な答えが貪欲な答えと比較してどれだけ大きくなければならないかを表します。 次に、繰り返しの歪みブロックからなる基本文字列を構築します。各歪みブロックは、2 つのプロセス間の固定の不均衡に寄与することを目的としています。 これらのブロックを連結すると、貪欲なブロックが最適なブロックと比べて強制的にアンダーカウントされる文字列が生成されます。 

ベースを構築した後、クリーンな数を計算します。`sysu`最終的な貪欲な値が次の値に達するように、サブシーケンスを追加する必要があります。`x`。 それぞれなので`sysu`貪欲カウントと最適カウントの両方に正確に 1 を寄与しますが、ベースによって確立された差を維持して、両方を均等にシフトするだけです。 

注意が必要なのは、`k`負ではありません。 これは、ステートメントに含まれる実現可能性条件によって保証されます。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。`x = y`。 この状況では、`d = 0`, したがって、ガジェットは構築されません。 出力は単純になります`sysu * x`。 貪欲なプロセスと最適なプロセスはどちらも、分離されたプロセスの連結に対して同じように動作します。`sysu`ブロック化されるため、等価条件は直接保持されます。 

もう 1 つのエッジケースは次のような場合です`x = 0`。 その場合、構築では、貪欲な者がいかなるものをも形成しないことを保証する必要があります。`sysu`たとえ最適な形式であっても、その後は`y`。 これは完全にガジェット フェーズによって処理されます。この構造により、貪欲な消費が常に潜在的な一致を破ることが保証され、クリーンなサフィックスは追加されません。`k = 0`。 

最後の微妙なケースは次のような場合です。`k = x - d`ゼロになります。 これは、ターゲットの貪欲値全体がディストーション ガジェットによってすでに達成されている状況に対応します。 その場合、出力はガジェット ブロックのみで構成され、クリーンなブロックがないため、`sysu`が追加されると、バランスは発生しません。 最適な場合でも、ガジェットの貢献度がちょうど 2 倍に達し、必要なガジェットの貢献度に一致します。`y`。
