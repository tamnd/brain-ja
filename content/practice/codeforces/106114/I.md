 ## 問題の理解

## アプローチ

 最も直接的なアプローチは、すべての塩基を試すことです$k$2から$R$、 変換する$n$基地に$k$、桁の合計を計算し、最小値を追跡します。 数値を基数に変換する$k$かかります$O(\log_k n)$部門ごとに分けられるため、すべての拠点にわたってこれはおおよそ次のようになります$$\sum_{k=2}^{R} O(\log n) \approx O(R \log n)$$これでは遅すぎる$R$特に次の場合は大きいです$R$到達できる$10^{12}$。 中程度の場合でも$R$、分割を繰り返すとコストが高くなります。 

重要な構造は、ベースが相対的に大きくなると、$\sqrt{n}$、の表現$n$非常に短くなります。 具体的には、$k > \sqrt{n}$、 それから$n$基地内で$k$最大 2 桁の数字:$$n = a_0 + a_1 k$$と$a_1 \in \{0,1\}$。 実際、いつ$k > n$、一桁の数字があるとき、$\sqrt{n} < k \le n$、2 桁の表現があります。 

これにより、検索空間が縮小されます。すべての大きな塩基を個別に繰り返す代わりに、考えられる数字のペアを列挙できます。$(a_1, a_0)$そしてどの塩基がそれらを生成するかを導き出します。 このようなペアの数は約$\sqrt{n}$、 以来$a_1 k \le n$暗示する$a_1 \le \sqrt{n}$。 

小規模拠点用$k \le \sqrt{n}$、数字抽出の直接シミュレーションを行う余裕があります。 大きな基底の場合、表現ロジックを反転し、分解の候補を列挙します。$n$1 桁または 2 桁に分割します。 

これにより、問題が 2 つの領域に分割されます。1 つは小さな塩基の単純なシミュレーション、もう 1 つは大きな塩基の組み合わせ列挙です。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. 最初に答えを次の桁の合計として設定します。$n$基数 2 は明確に定義された表現を生成し、常に範囲内にあるため、これにより有効な上限が保証されます。 
2. すべての塩基を反復処理します。$k$2から$\min(R, \lfloor \sqrt{n} \rfloor)$。 塩基ごとに分割を繰り返します$n$による$k$そして余りを積み上げます。 これにより、その基数の桁の合計が直接計算されます。 

私たちが立ち止まる理由$\sqrt{n}$この点を超えると、表現は最大でも 2 桁にまで縮小するため、直接構築する場合と比較してシミュレーションは無駄になります。 
3. これらの小さな基数を処理しながら、見つかった最小桁の合計で答えを更新します。 
4. 大きな塩基を処理できるようになりました$k > \sqrt{n}$。 この体制では、$n$は次のようにのみ表現できます。$$n = a_0 + a_1 k$$どこ$a_1 \ge 1$暗示する$k \le n$。 したがって、以下の基数のみを考慮します。$R \cap [\sqrt{n}, n]$。 
5. 繰り返す代わりに$k$、可能な値を反復します。$a_1$。 それぞれについて$a_1$、計算する$a_0 = n \bmod a_1$-style 分解制約ですが、より具体的には次の点に注意してください。$$k = \frac{n - a_0}{a_1}$$どこ$a_0 < k$。 これにより有効な制限が生じます$k$構造化式の約数によって引き起こされる範囲に変換するため、分割の候補を列挙します。$n$固定して2桁にする$a_1$とコンピューティング$k$。 
6. 有効な分解ごとに、桁の合計を計算します。$a_0 + a_1$, and update the answer.
 7. すべてのケースで最小値を取得します。 

### なぜ効果があるのか

 The algorithm relies on a structural invariant: every representation of$n$基地内で$k > \sqrt{n}$は最大 2 桁です。 これは、桁の合計がペアによって完全に決定されることを意味します。$(a_1, a_0)$と$n = a_1 k + a_0$。 基数を検索する代わりに、実行可能な桁分解を検索します。$n$。 すべての有効な基底はそのような分解の 1 つに正確に対応するため、候補が見逃されることはなく、無効な桁の合計が含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum_base(n, k):
    s = 0
    while n:
        s += n % k
        n //= k
    return s

def solve():
    n, R = map(int, input().split())

    # base 2 as initial bound
    ans = digit_sum_base(n, 2)

    lim = int(n ** 0.5)

    # small bases: direct simulation
    for k in range(2, min(R, lim) + 1):
        ans = min(ans, digit_sum_base(n, k))

    # large bases: at most two digits
    # n = a0 + a1 * k
    for a1 in range(1, lim + 1):
        k = n // a1
        if k > R or k < 2:
            continue

        a0 = n - a1 * k
        if 0 <= a0 < k:
            ans = min(ans, a0 + a1)

    print(ans)

if __name__ == "__main__":
    solve()
```機能`digit_sum_base`繰り返し除算を使用して標準の基数変換を実行します。これは、各桁が各ステップの剰余であるため有効です。 

最初のループは、表現に多くの桁が含まれる可能性があるすべての基数をカバーします。 でのカットオフ$\sqrt{n}$これにより、この高価な操作を頻繁に実行することがなくなります。 

2 番目のループでは、考えられる高桁係数を列挙します。$a_1$。 それぞれについて、候補塩基を導き出します。$k$、残りを再構築することで一貫性があるかどうかを検証します。$a_0$。 これにより、すべての大きなベースを明示的に反復することが回避されます。

 ## 特殊なケース

 ### ケース: 基数が n に等しい

 入力:```
n = 100, R = 100
```いつ$k = n$、表現は「1 0」、桁の合計は 1 です。アルゴリズムはこれを大底ロジックで捉えます。$a_1 = 1$、$a_0 = 0$、合計は 1 になります。 

### ケース: R が非常に小さい

 入力:```
n = 50, R = 2
```基数 2 のみが有効です。 小基底ループにより、大基数の列挙を必要とせずに桁の合計が正しく計算されます。 

### ケース: n が平方根しきい値のすぐ下

 入力:```
n = 1000000, R = 1000000
```ここでは両方の体制が重なっています。 小塩基ループは 1000 までのすべての塩基を処理しますが、大塩基列挙では 1000 を超える塩基も 2 桁の分解によって確実にチェックされます。 しきい値を超えるすべての表現は 2 桁でなければならないため、塩基が見逃されることはありません。
