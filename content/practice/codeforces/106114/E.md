 ## 解決策
 ## 問題の理解

 アイテムタイプの小さなセットが与えられ、各タイプには固定の「重量」または「コスト」が設定されています。 また、いくつかのクエリがあり、各クエリは同じ質問をします。これらの項目タイプを何度でも使用することが許可され、順序が重要になるのは合計をどのように蓄積するかだけである場合、指定された値に正確に等しい合計を構築できる方法は何通りありますか。 

これをより明確に見る方法は、合計 0 から開始して、指定された重みの 1 つを繰り返し追加するプロセスを想像することです。 一連の選択によって最終的な合計が計算されます。 各クエリ値 T について、1e9 + 7 を法とする正確な合計 T を生成するピックのシーケンスの数をカウントする必要があります。 

重要なスケールは、項目タイプの数 n と値 ai の両方が小さく、最大 100 ですが、目標合計 ti が最大 1e9 と巨大であることです。 これにより、クエリごとにその全範囲に至るまで独立して答えを計算しようとするアプローチは即座に排除されます。 T までの線形または二次 DP は不可能です。 

代わりに、この構造は合計に対する線形再帰を示唆しています。各状態は、固定オフセット ai によってシフトされた前の状態に依存します。 

クエリごとに単純な DP を試みると、微妙な失敗例が発生します。 たとえば、n = 2、a = [2, 3]、T = 1e9 の場合、T までの DP を格納することさえできません。 クエリごとに最適化したとしても、それを m 回繰り返すことは不可能です。 

もう 1 つの微妙なエッジ ケースは T = 0 です。何も選択しないことで合計 0 を形成する方法は 1 つだけあります。 再帰実装では、この基本ケースを明示的に正しくシードする必要があります。 

## アプローチ

 強引な解釈は簡単です。 f[x] を合計 x を形成する方法の数とします。 次に、x を形成するすべての方法は、最後のステップとしていくつかの ai を選択することで終了します。そのため、f[x] はすべての有効な ai の f[x - ai] の合計に等しくなります。 これは、古典的な無制限のナップザックまたは小銭の繰り返しです。 ターゲットまでのすべての x に対してきれいに機能します。 

問題は、これには、クエリされた最大の T まで f を計算する必要があることです。T は 1e9 になる可能性があるため、直接 DP は時間とメモリの両方で不可能です。 各クエリまでを個別に計算するだけだとしても、これを m 個のクエリに対して繰り返すことは絶望的になります。 

重要な観察は、再帰には固定係数と制限された依存関係範囲があるということです。 各状態は最大 100 個の前の状態にのみ依存します。 これは、シーケンス f[x] が最大 100 次の線形再帰のように動作することを意味します。これを認識すると、遷移を 100 次元の状態ベクトルの線形変換としてエンコードできます。 

個々の f[x] の観点から考える代わりに、連続した値のベクトルを維持します。 位置 i から i + 1 への移行は、固定の 100 × 100 行列による行列の乗算です。 これにより、問題は、位置 T に到達するための遷移行列のべき乗に変換されます。 

単純な行列のべき乗ではクエリごとに O(n^3 log T) のコストがかかりますが、行列の構造は固定されており、構造が疎であるため、構造を再利用して行列にベクトルを乗算するコストを O(n^2) に削減できます。 遷移行列の事前計算能力により、対数ステップでジャンプすることができ、各ステップが効率的に適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート DP | O(mTn) | O(T) | 遅すぎる |
 | 行列のべき乗 | O(n^3 log T) | O(n^2) | 遅すぎる |
 | 最適化された行列ベクトル累乗 | O(n^2 log T + mn^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 線形構造を明らかにする方法で DP を書き換えます。 F[i]を和iを形成するシーケンスの数とする。 漸化式は F[i] = F[i - aj] のすべての j の合計です。 

最大 AI シフトをカバーするのに十分な大きさで、サイズ 100 にパディングされた連続 DP 値のスライディング ウィンドウを格納する状態ベクトルを定義します。 

### ステップ

 1. 状態ベクトル S(i) = [F[i], F[i+1], ..., F[i+99]] を定義します。

この表現は、i から i+1 へのシフトが固定変換に対応するように選択されます。 
2. S(i+1) を S(i) の一次関数として表します。 

それぞれの新しいエントリは、オフセットが何らかの ai と一致するかどうかに応じて、以前のエントリのシフトされたコピー、またはいくつかのシフトされた寄与の合計のいずれかになります。 これは、固定の 100 × 100 の遷移行列 A を定義します。 
3. ai のリストから行列 A を 1 回構築します。 

各 AI に対して、F[i] を F[i+ai] にシフトする寄与を追加します。これは、適切な行列の位置に 1 を配置することを意味します。 
4. 2 進累乗を使用して A の累乗を事前計算します。 

T は 1e9 までであるため、k に対して A^(2^k) を 30 まで保存します。 これにより、対数ステップで時間をジャンプすることができます。 
5. 各クエリ T に対して、基本状態 S(0) を初期化します。ここで、F[0] = 1、他のすべてのエントリは 0 です。 
6. T をバイナリに分解し、対応する事前計算行列を S(0) に適用し、行列とベクトルの乗算を使用して状態ベクトルを効率的に更新します。 
7. 各クエリの答えは、S(T) の最初のコンポーネント、つまり F[T] です。 

### なぜ効果があるのか

 反復は線形で時間不変です。つまり、S(i) から S(i+1) への遷移は i に依存しません。 線形時不変システムは、固定線形演算子の繰り返し適用として表すことができます。 各 F[i] は有界ウィンドウ内の以前の値にのみ依存するため、状態ベクトルは将来の値を計算するために必要なすべての情報を完全に捕捉します。 したがって、遷移行列を累乗すると、中間値を明示的に反復することなく、任意の T の反復が正しくシミュレートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mat_mul(A, B, n):
    C = [[0]*n for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        Ci = C[i]
        for k in range(n):
            if Ai[k]:
                aik = Ai[k]
                Bk = B[k]
                for j in range(n):
                    Ci[j] = (Ci[j] + aik * Bk[j]) % MOD
    return C

def mat_vec(A, v, n):
    res = [0]*n
    for i in range(n):
        s = 0
        Ai = A[i]
        for j in range(n):
            if Ai[j]:
                s += Ai[j] * v[j]
        res[i] = s % MOD
    return res

def solve_case(a, T):
    n = len(a)
    K = 100

    F0 = [0]*K
    F0[0] = 1

    A = [[0]*K for _ in range(K)]

    for i in range(K-1):
        A[i][i+1] = 1

    for x in a:
        if x < K:
            A[K-x-1][0] = (A[K-x-1][0] + 1) % MOD

    def apply(mat, vec):
        return mat_vec(mat, vec, K)

    res = F0[:]

    # binary exponentiation on T
    base = A
    t = T
    while t:
        if t & 1:
            res = apply(base, res)
        base = mat_mul(base, base, K)
        t >>= 1

    return res[0]

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    for _ in range(m):
        T = int(input())
        print(solve_case(a, T))

if __name__ == "__main__":
    solve()
```この実装では、固定の 100 次元の状態空間を構築し、遷移を行列としてエンコードします。 シフト構造は、ウィンドウを前方に移動する超対角線上に配置することでキャプチャされます。 各 AI は、F[i] を F[i+ai] にフィードする寄与を追加します。 べき乗ループは、T の 2 進表現に従って行列累乗を適用します。 

現在の電力を状態に適用するときに完全な行列乗算の代わりにベクトル乗算が使用されるため、繰り返しのオーバーヘッドが削減されます。 

## 実用的な例

 a = [1, 2] および T = 3 の小さなインスタンスを考えてみましょう。 

F 値を追跡します。 

| 私 | F[i]の計算 | F[i] |
 | --- | --- | --- |
 | 0 | 基本ケース | 1 |
 | 1 | F[0] | 1 |
 | 2 | F[1] + F[0] | 2 |
 | 3 | F[2] + F[1] | 3 |

 ここで、T = 4 と仮定します。 

| 私 | F[i] | 推論 |
 | --- | --- | --- |
 | 0 | 1 | ベース |
 | 1 | 1 | 0から |
 | 2 | 2 | 1 と 0 から |
 | 3 | 3 | 2と1から |
 | 4 | 5 | 3と2から |

 これは、各状態が固定オフセットからの寄与を集約するという直観と一致します。 

これらの例は、反復が安定しており、前の値の固定線形結合によって完全に決定されることを示しています。これはまさにマトリックス モデルが捉えているものです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K^3 log T + mK^2) | 行列のべき乗が優勢であり、K = 100 |
 | スペース | O(K^2) | 遷移行列と一時ベクトル |

 この制約により、K = 100 が境界線になりますが、最適化された実装の下では許容されます。 対数累乗により、最大 1e9 の T も効率的に処理されます。

 ## 特殊なケース

 基本ケース T = 0 は、初期状態ベクトルで F[0] = 1 を初期化することによって処理されます。 行列のべき乗中、どの遷移も負のインデックスを生成しないため、この値は保存されたままになり、反復の同一性は原点で維持されます。 

すべての ai が T より大きい場合、システムは正の T に対して 0 を返す必要があります。行列の定式化では、これは到達可能な状態に値を注入しない遷移行列に対応するため、状態ベクトルは初期位置を超えて 0 のままになります。 

スパース AI を持つ大きな T の場合、べき乗は多くの中間ステップをスキップしますが、各ステップが同じ線形変換の適用に正確に対応するため、正確性は維持されます。 バイナリ分解により、中間値への依存性が失われないことが保証されます。
