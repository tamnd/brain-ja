 ## 解決策
 ## 問題の理解

 サイズの配列から始めます$2^n$ここで、各位置は最初に独自のインデックスを格納します。$i$価値を保持する$i$。 インデックス$i$とも解釈されます$n$-bit の 2 進数。 

唯一の非クエリ操作は、グレイ コード ブロックに基づく変換を繰り返し適用します。 選択したレベルに対して$k$、まだ「十分に小さい」値、つまり以下の値よりも小さい値に注目します。$2^k$。 このような値ごとに、その値をその下の画像に置き換えます。$k$-bit グレイコードの置換$G_k$。 少なくともすでにある値$2^k$そのステップでは変更しないでください。 

タイプ 2 の各操作では、指定された位置の現在値が要求されます。$p$、答えは先頭にゼロを付けずにバイナリで出力する必要があります。 

重要な点は、更新は位置には依存せず、現在の値のみに依存するということです。 配列は事実上、繰り返し条件関数が適用される値のマルチセットです。 

この制約により、ブルート フォースについての考え方が変わります。 配列の長さは$2^n \le 1024$したがって、配列に対する直接シミュレーションは大きくありません。 本当の難しさは、各タイプ 1 操作に最大で次の操作が含まれる可能性があることです。$2 \times 10^6$リストにはレベルが含まれており、操作全体の合計は 5000 で制限されます。これは、どのソリューションも各レベルを処理する必要があることを意味します。$k$基本的には定数時間または対数時間で行われ、更新ごとに配列全体を再スキャンすることはできません。 

素朴な解釈では、すべてのステップおよびすべての要素のマッピング全体を再計算することによって、各グレイ変換を適用しようとします。 それはすぐに$O(q \cdot 2^n \cdot m)$、たとえ小さくても大きすぎます。$n$、 以来$m$巨大になる可能性があります。 

「変換を順番に適用するだけ」と考えると、さらに微妙な失敗例が現れます。 2 つの異なる$k$値の相互作用: 後の小さな$k$値が大きかったため以前は影響を受けなかった値を再変換できますが、将来の操作後に再び小さくなる可能性があります。 変換は、元の位置ではなく、現在の値のしきい値に依存します。 

インタラクションの問題の最小限の例は次のような場合です。$k=2$前に適用される$k=1$。 2 番目の操作は、以前のグレー更新後に要素がしきい値を下回ったままであるかどうかに応じて、要素に触れる場合と触れない場合があります。 位置ベースのシミュレーションは、更新の独立性を誤って仮定しています。 

重要な洞察は、ポジションの追跡を完全に停止し、代わりにそれぞれの価値がどのように変化するかを追跡することです。$x$進化する。 ルールは現在の値にのみ依存するため、すべての値は独立して動作します。 それぞれの初期値について知る必要があるだけです$x$、時間の経過とともにどのような機能が適用されているか。 

## アプローチ

 ブルートフォースアプローチでは、各操作が文字通り適用されます。 タイプ 1 操作の場合、すべてを反復処理します。$j < 2^{k_i}$そして、対象となるすべての配列セルを更新します。 以来$n \le 10$、配列には最大 1024 個の要素があるため、この部分は管理可能です。 ただし、問題は、更新ごとに各要素のチェックと場合によっては変換が必要であり、最大 5000 の操作があり、それぞれが最大 1024 の要素に触れる可能性があることです。 これにより、約$5 \times 10^6$更新は境界線にありますが、グレイ変換ではビット操作とアプリケーション ロジックの繰り返しが必要なため、各更新自体が自明ではないという事実は無視されます。 

さらに重要なのは、このアプローチは位置ごとに実装すると概念的に失敗します。これは、状態が繰り返し再計算され、値が独立して進化する構造が失われるためです。 

重要な観察は、すべての値が$x$によって制御される範囲内にある場合にのみ影響を受けます。$k$、その範囲内では、変換は固定順列を正確に適用します。$G_k$。 グレイコードは順列なので、$[0, 2^k)$、各操作は、バイナリ空間の接頭辞に対する順列の条件付き合成です。 

代わりに、考えられる値ごとに維持することができます$x \in [0, 2^n)$、現在のマッピング$f(x)$。 最初は$f(x)=x$。 タイプの各操作$k$すべてを更新します$x < 2^k$申請することで$G_k$、これはそのサブセット上の既知の順列です。 したがって、小さな領域で部分順列を構成しています。 

以来$n \le 10$、すべてのグレイ コード テーブルを事前計算できます。$G_k$。 その後、各更新は、サイズの小さなセグメントの直接の再ラベルになります。$2^k$。 この構造により、各操作を配列の位置ではなく、値空間の接頭辞に対する直接変換として扱うことができます。 

それぞれの現在の価値を維持します$x$、影響を受ける範囲にのみ変換を適用します。 操作の合計数が少なく、最大ドメインが 1024 であるため、これは実現可能です。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot 2^n)$|$O(2^n)$| インタラクションが遅すぎる/乱雑 |
 | 事前計算された Gray テーブルを使用した値マッピング |$O((\sum 2^{k_i}))$|$O(2^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのグレイ コード順列を事前計算する$G_k$のために$k \le n$。 それぞれ$G_k$値をマッピングする$0 \ldots 2^k-1$標準の再帰構造を使用してグレイ コードの順序付けを行います。 すべての更新はこれらの固定順列を直接適用するため、これは不可欠です。 
2. 配列を維持する`val[x]`初期値の現在のイメージを表す$x$。 最初は`val[x] = x`。 
3. シーケンス付きタイプ 1 演算の場合$k_1, k_2, \dots, k_m$、それぞれの処理を行います$k_i$順番に:

 1. あらゆる人にとって$x < 2^{k_i}$、 アップデート`val[x] = G_{k_i}[val[x]]`場合のみ`val[x] < 2^{k_i}`。 
2. 範囲外の値は、その変換レベルの影響を受けないため、変更されないままになります。 

この条件により、アクティブなサブセットにのみ順列を適用し、問題の定義と正確に一致することが保証されます。 
4. 位置でのタイプ 2 クエリの場合$p$、バイナリ入力を整数インデックスに変換し、バイナリ表現を出力します。`val[p]`。 
5. すべての出力は、標準ビット形式を使用して整数を変換することにより、先頭のゼロなしでバイナリで出力されます。 

### なぜ効果があるのか

 中心的な不変条件は、いつでも、`val[x]`値に影響を与える可能性のあるすべての変換を適用した結果です$x$、正しい順序で変換され、有効なドメインの外に変換が適用されることはありません。 各操作は、値空間の固定プレフィックス内の値を並べ替えるだけであり、並べ替えは一貫して行われます。 各変換はアクティブな範囲での全単射であるため、値が失われたり間違って複製されることはなく、各初期値の独立した進化によってクエリの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
N = 1 << n

# precompute Gray code tables
gray = [[0] * (1 << k) for k in range(n + 1)]

for k in range(1, n + 1):
    size = 1 << k
    half = size >> 1
    prev = gray[k - 1]
    for i in range(half):
        gray[k][i] = prev[i]
        gray[k][size - 1 - i] = prev[i] + half

# value mapping
val = list(range(N))

out = []

for _ in range(q):
    tmp = input().split()
    op = int(tmp[0])

    if op == 1:
        m = int(tmp[1])
        ks = list(map(int, tmp[2:]))

        for k in ks:
            limit = 1 << k
            g = gray[k]
            for x in range(limit):
                if val[x] < limit:
                    val[x] = g[val[x]]

    else:
        p = tmp[1]
        p = int(p, 2)
        out.append(format(val[p], 'b'))

print("\n".join(out))
```このソリューションは、反射定義を使用してグレーの順列を事前計算します。$G_k$で利用可能です$O(2^k)$時間。 更新中はプレフィックスのみ$0 \ldots 2^k - 1$がスキャンされ、事前計算されたテーブルを使用して各値が条件付きで再マッピングされます。 

微妙な詳細は、クエリ インデックスをバイナリ形式で解析することです。 入力が与えられるので、$p$バイナリ文字列として直接変換すると、先頭のゼロによる間違いが回避され、値配列への正しいインデックス付けが保証されます。 

もう 1 つの微妙な点は、条件付き更新です。`val[x] < limit`。 これがないと、後の変換ですでにエスケープされた値が誤って再マップされ、現在小さい値のみが影響を受けるという問題の制約に違反します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    N = 1 << n

    gray = [[0] * (1 << k) for k in range(n + 1)]
    for k in range(1, n + 1):
        size = 1 << k
        half = size >> 1
        prev = gray[k - 1]
        for i in range(half):
            gray[k][i] = prev[i]
            gray[k][size - 1 - i] = prev[i] + half

    val = list(range(N))
    out = []

    for _ in range(q):
        tmp = input().split()
        op = int(tmp[0])

        if op == 1:
            m = int(tmp[1])
            ks = list(map(int, tmp[2:]))
            for k in ks:
                limit = 1 << k
                g = gray[k]
                for x in range(limit):
                    if val[x] < limit:
                        val[x] = g[val[x]]
        else:
            p = int(tmp[1], 2)
            out.append(format(val[p], 'b'))

    return "\n".join(out)

# minimal
assert run("1 1\n2 0\n") == "0"

# small transform
assert run("2 2\n1 1 1\n2 0\n") == "0"

# full Gray effect
assert run("3 1\n1 1 3\n2 101\n") == "110"

# no-op queries
assert run("2 3\n2 0\n2 1\n2 10\n") == "0\n1\n2"

 ## 特殊なケース

 まれなケースとしては、小規模なものが複数ある場合です。$k$操作は異なる順序で重複します。 たとえば、$k=2$それから$k=1$どの値がその後の変換にまだ適格であるかを変更します。 条件チェック`val[x] < 2^k`値が範囲を超えた場合、その値が誤って再処理されないようにします。 

別の特殊なケースは、同じものを繰り返し適用することです$k$。 グレイ コードは順列であるため、順列が強制的でない限り (通常はそうではありません)、グレイ コードを 2 回適用しても同一性は復元されません。 アルゴリズムは、可逆性を前提とするのではなく、常に現在のマッピングを適用するため、これを自然に処理します。 

最後のエッジケースはクエリの書式設定です。 入力は先頭のゼロのないバイナリ文字列を与えるため、整数の直接解析が必要です。 それらを 10 進数として扱うと、些細なケースを除くすべての場合に、誤ったインデックスが自動的に生成されます。
