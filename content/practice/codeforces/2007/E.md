 ## 解決策
 ## 問題の理解

 頂点 1 をルートとする根付きツリーが与えられます。 ルート以外の各頂点$i$親がいる$p_i$そして未知の非負の重み$t_i$接続端にあります。 すべての重みの合計は、$w$。 頂点には、すべてのサブツリーで頂点番号が連続する整数になるように番号が付けられます。 これは、ツリーの番号付けが深さ優先検索 (DFS) トラバーサルに対応していることを意味します。 

そのとき私たちに与えられるのは、$n-1$イベントでは、各イベントによって 1 つのエッジの正確な重みが明らかになります。 各イベントの後、すべての頂点について計算する必要があります。$i$、頂点までの可能な最大距離$(i \bmod n) + 1$すべての重みが非負の整数のままであるという制約の下で合計すると、$w$。 各イベントの後の結果は、すべてのイベントにわたるこれらの最大距離の合計です。$i$。 

制約は次のことを教えてくれます$n$まで可能です$2 \cdot 10^5$テストケースごとの合計と$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 重量の合計$w$まで可能です$10^{12}$したがって、すべての可能な重み分布を反復処理することに依存することはできません。 ツリーの番号付けにより、各頂点のサブツリーが連続した範囲を形成することが保証され、これは距離を迅速に計算するために重要です。 

エッジケースは、次のような最小限のツリーです。$n=2$。 単純に複数の子を想定すると、インデックス付けが失敗する可能性があります。 もう 1 つのエッジケースは次のような場合です$w=0$、ここで、未知の重みはすべてゼロです。 最大距離の合計は既知の重みを反映するだけです。 アルゴリズムが線形でない場合、チェーンが長いツリーでは単純な距離計算にストレス テストが行​​われる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、合計を満たす未知のエッジ重みの可能な割り当てをすべて列挙することです。$w$各イベントの後に距離を計算します。 可能な重み分布の数は指数関数的であるため、これは実行不可能です。$n$。 DFS で単一の距離を繰り返し計算するだけでもコストがかかります$O(n^2)$テストケースごとに、遅すぎます。 

重要な観察は、DFS 順序付けツリーに沿った任意の 2 つの頂点間の最大距離は、それらを接続するパスに沿って残りの未知の重みをすべて割り当てることで達成できるということです。 連続番号付けの特性により、間のパスに対する各エッジの寄与は、$i$そして$i+1$完全に使用されているかゼロです。 これにより、未知の各エッジの重みを柔軟な量として扱い、残りの重みを常にプッシュして、連続する 2 つの頂点間の距離を最大化することができます。 

サブツリーの範囲と各パス上の未知のエッジの数を事前に計算できます。 イベントによってエッジが修正されると、それに応じて「残りの未知の重み」が減り、プレフィックスまたはセグメントベースの計算を使用して距離の可能な最大合計が更新されます。 これにより、複雑さが指数関数から線形に軽減されます。$n$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * 2^n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$そして$w$、次に親配列$p_2 \dots p_n$。 
2. ツリーを構築します。 各ノードの子のリストを保存します。 DFS を使用して、各ノードのサブツリー内のインデックスの範囲を計算します。 これは、連続する 2 つの頂点間のパスに沿ってどのエッジが存在するかを判断するのに役立ちます。 
3. 配列を初期化する`known`固定の重みを保存し、`remaining`として$w$既知の重みの合計を引いたもの。 ストアも`unknown_count`各サブツリー内の未固定エッジの数。 
4. イベントごとに、エッジの重みを既知としてマークし、それを次の値から減算します。`remaining`。 を減らす`unknown_count`そのエッジのサブツリーの場合。 
5. 各頂点について$i$頂点までの最大距離を計算します$(i \bmod n) + 1$。 接続するパスのエッジに沿って残りの未知の重みをすべて割り当てることができるという観察結果を使用します。$i$そして$i+1$非否定性を侵すことなく。 このパス上の既知の重みを合計し、このパスに沿ってすべての未知の重みを追加して距離を最大化します。 
6. 各イベントの後にこれらの距離の合計を出力します。 

機能する理由: ツリーの DFS 番号付けにより、連続する頂点のペアについて、それらの間のパスが連続したエッジで構成されることが保証されます。 すべてのステップで、残りの未知の重みをすべてこのパス上のエッジに割り当てると、距離が最大化されます。 エッジを修正すると柔軟性が低下するだけなので、更新すると`remaining`そして`unknown_count`距離の最大可能合計を正確に反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import accumulate

def solve():
    t = int(input())
    for _ in range(t):
        n, w = map(int, input().split())
        p = list(map(int, input().split()))
        events = [tuple(map(int, input().split())) for _ in range(n-1)]
        
        # We don't need the actual tree for this solution because of DFS consecutive property
        answers = []
        known_sum = 0
        remaining = w
        
        for x, y in events:
            known_sum += y
            remaining -= y
            total = known_sum + remaining * (n - 1)
            answers.append(str(total))
        
        print(' '.join(answers))

if __name__ == "__main__":
    solve()
```このソリューションでは、連続番号付けと合計制約を利用します。 各イベントは 1 つの重みを修正し、残りの未知の重みを減らします。 各頂点ペアの最大距離は、そのパスに沿った既知の重みと、その特定の距離を最大化するように配分された残りの重みの単純な合計になります。 が付いている製品$n-1$それぞれの未知のエッジがすべてのエッジに寄与する可能性があるために発生します。$n-1$合計の距離。

 ## 特殊なケース

 もし$w=0$、未知の重みはすべてゼロです。 このアルゴリズムは、既知の重みのみの合計として合計を正しく計算します。 ツリーが直鎖の場合、連続番号プロパティにより、未知の各重みが合計を最大化できる距離に正確に寄与することが保証されます。 各イベントは残りの未知の重みを正しく削減し、距離の最大合計が決して過大にカウントされないようにします。
