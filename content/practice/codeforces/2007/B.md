 ## 解決策
 ## 問題の理解

 配列が与えられていますが、操作によって位置が直接変更されるわけではありません。 代わりに、範囲が表示されるたびに、各操作が値をターゲットにします。$[l, r]$、現在の値がその数値間隔内にあるすべての要素は、ちょうど 1 ずつ増加または減少します。 

このようなグローバル変換のたびに、配列内に現在存在する最大値が求められます。 

したがって、構造は「インデックスを更新する」ではなく、「現在の値に応じてすべての要素を更新する」ということになります。 これにより、配列は小さな塊で連続的に左または右にシフトされる複数の整数セットのように動作します。 

主な難点は、値が時間の経過とともに移動するため、特定の間隔に属する要素のセットが変化することです。$[l, r]$操作のたびに変化します。 操作ごとにすべての要素をスキャンする単純なシミュレーションは遅すぎます。$n$そして$m$まで行く$10^5$、それは次のことにつながります$O(nm)$最悪の場合の行動。 

微妙なエッジ ケースは、すべての要素が常にすべてのクエリのアクティブ範囲内にある場合です。 そのような状況では、すべての操作でアレイ全体がシフトされ、構造を繰り返し再スキャンまたは再構築するソリューションは二次関数的に劣化します。 

もう 1 つのエッジ ケースは、単一の値のみが繰り返し影響を受ける場合です。 それでも、その値は数直線上を「歩く」ことができ、固定インデックスや静的バケットに依存する単純な構造ではその値を追跡できなくなります。 

## アプローチ

 ブルート フォースのアイデアは単純です。操作ごとに、配列全体を反復処理し、値の条件を満たす要素に更新を適用します。 これは定義に直接従うため正しいですが、コストがかかります$O(n)$操作ごとに、$O(nm)$、これは大きすぎます。 

これを改善するために、構造を配列として考えるのをやめ、代わりに値の頻度マップとして扱います。 各操作は連続した範囲の値とのみ対話するため、中心となるタスクはキーのスライスを繰り返し抽出し、それらをシフトすることになります。$\pm 1$、それらをマージして戻します。 

重要な観察は、値が常にクラスター化されているということです。つまり、キーのみがクラスター化されています。$[l, r]$移動すると、それらは均一に移動します。 したがって、個々の要素に触れる代わりに、同じ値のグループ全体を一度に処理します。 これにより、問題は、動的順序構造で範囲の抽出と再挿入が繰り返されることになります。 

主な課題は、キーに対する範囲クエリをサポートしながら、これらのグループを並べ替えられた順序で維持することです。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(n)$| 遅すぎる |
 | 順序付きマップ/グループ化シミュレーション |$O((n+m)\log n)$償却済み |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、個別の値のソートされたリストと、各値が出現する回数を格納する辞書を維持します。 

各操作により、この構造内のキーの範囲が更新されます。 

1. 現在の個別の値のソートされたリストを維持します。 

これにより、内部の値のセグメントをすばやく見つけることができます。$[l, r]$。 
2. 周波数マップを維持する`cnt[value]`各値が何回出現するか。 

これにより、個々の要素に触れることがなくなります。 
3. 各操作について、二分探索を使用して、ソートされた値リスト内の影響を受ける左端と右端の位置を特定します。 

これにより、どの値が更新範囲内にあるかが正確に識別されます。 
4. 影響を受けるすべての値とその数を一時リストに抽出します。 

周波数エントリを削除することで、それらを構造から論理的に削除します。 
5. 演算に応じて、抽出された各値を +1 または -1 シフトして再挿入します。 

シフトされた値がすでに存在する場合は、カウントをマージします。 
6. 新しい値が表示されたとき、または古い値が完全に消えたときに、並べ替えられたリストが更新されていることを確認します。 

これにより、将来のバイナリ検索の正確さが維持されます。 
7. 各操作を処理した後、最大値は単純にソートされたリストの最後の要素になります。 

重要な考え方は、各個別の値はプロセス全体で限られた回数だけ挿入および削除されるため、償却コストは管理可能なままであるということです。 

### なぜ効果があるのか

 すべてのステップで、構造体は現在配列内にある値の複数セットを正確に表します。 各操作では、値が連続した間隔内にある要素のみが移動され、それらの要素は ±1 の固定オフセットによって移動されるため、値によるグループ化は損失がありません。 常に等しい値をマージし、並べ替え順序を維持するため、表現は正確なままであり、対数時間でクエリ可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    cnt = {}
    for x in a:
        cnt[x] = cnt.get(x, 0) + 1

    keys = sorted(cnt)

    def add_key(x):
        if x in cnt:
            return
        # insert into sorted list
        i = bisect_left(keys, x)
        keys.insert(i, x)

    def remove_key(x):
        i = bisect_left(keys, x)
        if i < len(keys) and keys[i] == x:
            keys.pop(i)

    for _ in range(m):
        op, l, r = input().split()
        l = int(l)
        r = int(r)

        # find affected range in keys
        L = bisect_left(keys, l)
        R = bisect_right(keys, r)

        affected = keys[L:R]
        if op == '+':
            delta = 1
        else:
            delta = -1

        # remove old keys
        for x in affected:
            cnt_x = cnt[x]
            del cnt[x]
            remove_key(x)

            nx = x + delta
            cnt[nx] = cnt.get(nx, 0) + cnt_x
            add_key(nx)

        if keys:
            sys.stdout.write(str(keys[-1]) + "\n")
        else:
            sys.stdout.write("0\n")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この実装では、アクティブな値のソートされたリストと頻度辞書が保持されます。 各操作では、二分探索を使用して影響を受ける値の間隔を見つけ、同じ値のグループ全体を 1 つのバッチで移動します。 

微妙な部分は、次の間の一貫性を維持することです。`cnt`そして`keys`。 値が完全に消えるたびに、両方の構造から値を削除する必要があります。 そうしないと、キーが古いと、今後のバイナリ検索が破損する可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
a = [1, 2, 3]
+ 1 2
- 2 3
```鍵の状態を追跡します。 

| ステップ | 操作 | キー | マックス |
 | --- | --- | --- | --- |
 | 0 | 初期化 | [1,2,3] | 3 |
 | 1 | +1..2 | [1,2,3] → [1,2,3] | 3 |
 | 2 | -2..3 | [1,2,3] → [1,2,3] | 3 |

 これは、値が内部でシフトした場合でも、順序付けされたキー構造から常に最大値が取得されることを示しています。 

### 例 2

 入力:```
a = [2,2,5]
- 2 3
```| ステップ | 操作 | キー | マックス |
 | --- | --- | --- | --- |
 | 0 | 初期化 | [2,5] | 5 |
 | 1 | -2..3 | [2,5] → [1,5] | 5 |

 下のセグメントのみが影響を受けるため、最大値は安定したままになります。 

これらの例は、シフトが繰り返された場合でも、値によるグループ化が正確さを維持することを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、すべての値がすべてのクエリ範囲に該当する場合です。 この状況では、すべての操作でマルチセット全体が ±1 だけシフトされ、正確さは構造を繰り返し再構築するのではなく、周波数を適切にマージすることに完全に依存します。 

もう 1 つのエッジ ケースは、デクリメントまたはインクリメントを繰り返した後、多くの値が 1 つの値に集約される場合です。 実装がカウントを正しくマージできない場合、ソートされた構造には重複または古いエントリが含まれ、将来の範囲クエリが中断され、誤った最大値が生成されます。 

すべての変換はグループ化された値のレベルで適用され、並べ替えられたキー リストは常に頻度マップと同期されるため、アルゴリズムは両方のケースを自然に処理します。
