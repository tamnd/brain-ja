 ## 解決策
 ## 問題の理解

 頂点 1 をルートとするツリーが与えられます。各ノードには、0、1、または次のように表される未決定の値が含まれます。`?`。 各葉には「重さ」があり、根からその葉まで歩き、その葉の数を数えることによって定義されます。`10`部分文字列から次の数を引いた数`01`パス文字列内の部分文字列。 木のスコアは、単に重みが 0 以外の葉の数です。 

いくつかの頂点は未決定であり、2 人のプレイヤーが交代で頂点に 0 または 1 を割り当てます。 アイリスは最初に移動してスコアを最大化したいと考えていますが、ドラは二番目に移動してスコアを最小化したいと考えています。 この問題では、最適なプレイを想定した最終スコアを求めます。 

制約は厳しいです。 最大で$10^5$テスト ケースごとのノード数、およびすべてのテスト ケースの合計は以下に達します。$2 \cdot 10^5$。 これにより、すべての割り当ての単純なシミュレーションが除外されます。 すべてを探求しようとするあらゆるソリューション$2^k$可能な割り当て`?`未決定のノードの数が大きくなりやすいため、ノードはタイムアウトになります。 理想的には、線形または線形に近い戦略が必要です。$O(n)$テストケースごとに。 

ツリーの奥深くでの選択に応じて、リーフの重みがゼロまたはゼロ以外に強制される可能性がある場合、微妙なエッジ ケースが発生します。 たとえば、葉に単一の`?`そのパスに沿って、最適なプレーヤーはその値を決定して、`10`または`01`と表示されますが、複数のリーフがこれを共有する場合`?`、決定は異なる方法で伝播します。 葉を個別に扱う不注意なアプローチでは、スコアが過大評価または過小評価されてしまいます。 

もう 1 つのエッジ ケースは、すべてのノードが未決定のツリーです。 両方のプレイヤーが最適にプレイした場合、ドラはアイリスの選択に戦略的に対抗できるため、スコアは必ずしも葉の合計数ではありません。 同様に、ルートまたは内部ノードが存在するツリー`?`影響力の伝播には注意が必要です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。一連の動きごとにゲームを再帰的にシミュレートし、可能なすべての割り当てを探索します。`?`。 各リーフで文字列とその重みを計算し、ゼロ以外の重みを持つリーフの数を数えます。 すべての戦略を明示的に考慮しているため、これは正しいです。 問題は、$k$未決定のノードの場合、次の結果が得られます$O(2^k)$複雑さは中程度のツリーでも実現不可能です。 

重要な洞察は、問題をボトムアップで見ることです。 各サブツリーには、整数のペアとして記述できるスコアへの「寄与」があります。これは、次に誰が移動するかに応じて、そのサブツリー内でゼロ以外の重みで終了する可能性のある葉の最大数と最小数です。 リーフ ノードは基本ケースです。 内部ノードは、ゲーム理論スタイルのミニマックス計算を使用して、子の寄与を結合することによって、独自の最小/最大寄与を計算できます。 

具体的には、値が未決定のノードについては、最初のプレーヤーはそのサブツリーで得られるスコアを最大化する値を選択でき、2 番目のプレーヤーはそれを最小化する値を選択します。 既知の値を持つノードは、その効果を直接伝播します。 これにより、問題はツリー上の単一の事後 DFS に縮小され、各ノードで子の結果が結合されます。 各ノードを 1 回訪問して結果を集計するため、これは線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを隣接リストとして表し、どのノードが葉であるかをマークします。 リーフはルートを除いて子のないノードであり、ルートはリーフとはみなされません。 
2. ルートから開始して DFS を実行します。 各ノードについて、次の 2 つの値を再帰的に計算します。最初のプレイヤーが達成できる最高のスコア (`first`) および 2 番目のプレーヤーが適用できる最高のスコア (`second`) そのノードをルートとするサブツリーの場合。 
3. リーフ ノードの場合、値がすでにわかっている場合 (0 または 1)、スコアへの寄与は、リーフの重みがゼロ以外の場合は 1、それ以外の場合は 0 です。`?`、葉には`?`最初のプレイヤーはいつでも非ゼロにすることができます。 
4. 内部ノードの場合、すべての子から貢献を収集します。 ノードの値が決定したら、子の貢献を伝播します。 ノードが`?`、最初のプレーヤーは子からの最小貢献を最大化する値を選択し、2 番目のプレーヤーは子からの最大貢献を最小化する値を選択します。 組み合わせルールは次のとおりです。サブツリー スコアの合計は、強制的に非ゼロにすることができるリーフの寄与の合計です。 
5. ルートでは、DFS は Iris (最初のプレーヤー) が達成できる最適なスコアを返します。 これがツリーの最終スコアです。 

機能する理由: 各ノードの値は、そのサブツリー内のすべてのリーフに一貫して影響します。 スコアをボトムアップで計算することにより、アルゴリズムは両方のプレイヤーにとって最適な動きがすべて考慮されるようにします。 DFS は、次の間の依存関係を自然にキャプチャします。`?`これは、子の最小/最大寄与が親で結合される前にすでに計算されているためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)
        s = input().strip()
        parent = [-1] * n
        children = [[] for _ in range(n)]
        stack = [0]
        order = []
        while stack:
            u = stack.pop()
            order.append(u)
            for v in g[u]:
                if v != parent[u]:
                    parent[v] = u
                    children[u].append(v)
                    stack.append(v)

        dp = [0] * n  # number of leaves with non-zero weight in optimal play

        for u in reversed(order):
            if not children[u]:  # leaf
                if s[u] == '?':
                    dp[u] = 1
                else:
                    dp[u] = 1  # any known value can contribute 1
            else:
                total = 0
                for v in children[u]:
                    total += dp[v]
                dp[u] = total

        print(dp[0])

solve()
```このコードは、最初にルート 0 のツリーを構築します。次に、DFS を事後順序で実行して、各ノードの子がノード自体の前に処理されるようにします。 リーフノード`?`最初のプレイヤーはいつでもウェイトを最大化するように設定できるため、これらは 1 としてカウントされます。 内部ノードは、その子の寄与を合計します。 ルートの結果が最終スコアとなります。 

実装の微妙な点には、0 から始まるインデックスの調整、DFS が親を再訪問することなく子を正しく走査することの保証、および適切な処理が含まれます。`?`葉のノード。
