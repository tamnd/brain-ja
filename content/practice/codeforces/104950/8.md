 ## 解決策
 ## 問題の理解

 ツリー構造は固定されています。各ノードには最大 2 つの子があり、ノード 1 がルートです。 時間の経過とともに変化するのは、すべてのノードに付けられるラベルです。ラベルは、そのノードがサブツリーの前にアクセスされるか、サブツリーの間、またはサブツリーの後にアクセスされるかを決定する 3 つの値から選択されます。 

これらのラベルが与えられると、ツリーの完全な走査順序はすべてのノードの順列になります。 順序は標準の再帰 DFS によって取得されますが、少し工夫がされています。すべてのノードで、その左右のサブツリーに対するノードの位置は、現在のラベルに依存します。 ラベルが 3 つの値のいずれかに固定されると、最初にノードを訪問するか、途中で訪問するか、最後に訪問するかの一貫したルールが得られます。 

2 つの操作がサポートされています。 1 つの操作で、数値インデックス範囲内のすべてのノードに新しいラベルが割り当てられます。 もう 1 つは、グローバル トラバーサル順序内の特定のノードの現在位置を要求します。 

重要な問題は、単一ノードのラベルを変更すると、そのラベル自体の位置に影響を与えるだけではないことです。 これは、サブツリー全体の走査順序の構造を変更し、祖先がクエリされたノードを含むサブツリーと自分のノードをインターリーブする方法にも影響します。 

この制約により、最大 10 万のノードと 10 万の操作が許可されます。 更新ごとに走査を最初から再計算するソリューションでは、すべてのノードに繰り返しアクセスし、すぐに制限時間を超えてしまいます。 クエリごとにのみ再計算しても、やはり遅すぎます。 

さらに微妙な問題は、ツリー構造は静的ですが、走査順序は動的であり、すべてのノード ラベルに同時に依存することです。 深いリーフの変更は、その影響をすべての祖先まで伝播する可能性があるため、正しい解決策では、局所的な変更ではなく、パスに依存する影響を考慮する必要があります。 

単純なアプローチも、歪んだツリーでは失敗します。 ツリーがチェーンに縮退すると、各クエリですべての祖先を処理する必要が生じ、最悪の場合の複雑さは 2 次になります。 

## アプローチ

 直接的なアプローチは、各更新後に全体の走査順序を再計算し、結果の配列をスキャンして要求されたノードの位置を見つけることでクエリに応答することです。 1 つのトラバーサルの構築はノード数において線形であり、これをすべての操作に対して行うと、最悪の場合、およそ nq 回の操作が発生することになりますが、これは実行可能な制限をはるかに超えています。 

主な観察点は、各更新後に実際には完全な走査順序は必要ないということです。 各クエリは、単一ノードのランクのみを要求します。 そのランクは、ノードの祖先からの寄与と、トラバーサルでノードへのパスの前に配置される祖先パスの兄弟からの寄与に分解できます。 

ツリー構造は非常に単純化します。つまり、固定ノード i の場合、ルートから i までのパス上のノードのみが、自明ではない方法でその位置に影響を与えることができます。 他のすべてのノードは、完全に i の前か完全に i の後にあるサブツリー内に完全に存在するか、またはパスに無関係です。 これにより、依存関係がグローバルからパスローカルに軽減されます。 

各祖先について、ターゲット ノードがその左側のサブツリーにあるか右側のサブツリーにあるかがわかれば、そのラベルの効果は単純になります。 ラベルは、祖先自体がサブツリーの前にカウントされるかどうか、およびパスが継続する前に兄弟サブツリーが寄与するかどうかを決定します。 これらの寄与はサブツリー サイズによって完全に決定され、DFS を使用して事前に計算できます。 

残りの課題は、ラベルがツリー パスに沿ってではなく、ノード インデックスの範囲にわたって変化することです。 これは、セグメント ツリーまたはバイナリ インデックス付き構造でラベル配列を維持しながら、別のツリー構造分解を使用してパスの寄与を効率的にクエリすることを示唆しています。

重光分解により、ルートからノードへのパスを対数のセグメントに分割できます。 各セグメントで、現在のラベルが必要なノードからの寄与を集約します。 各ノードは、そのラベルとクエリ ノードの左または右のどちらの分岐にあるかに応じて、小さな固定式を通じて独立して寄与するため、セグメント ツリーは各ラベル状態の集計合計を格納できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 操作ごとにトラバーサルを再計算する | O(nq) | O(n) | 遅すぎる |
 | パス分解 + セグメントツリー集約 | O(q log² n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーをノード 1 にルートし、すべてのノードの親、深さ、サブツリーのサイズ、および各子が左の子か右の子かを計算します。 これは、後で任意の祖先について、クエリ ノードが左側のサブツリーにあるか右側のサブツリーにあるかを判断できるようにするために必要です。 
2. ルートからノードまでのパスを少数の連続セグメントに分割できるように、ツリーの重光分解を構築します。 これにより、パス クエリが、ツリーの配列表現に対する一連のセグメント クエリに変換されます。 
3. 配列 x を維持します。ここで、x[v] はノード v の現在のラベルです。更新ではノード インデックスの範囲にわたって値が割り当てられるため、この配列を遅延伝播を使用してセグメント ツリーに格納し、セグメント ツリー内の各ノードが均一なラベルまたはプッシュ ダウンできる混合セグメントを表すようにします。 
4. 各ノード v について、その左サブツリーと右サブツリーのサイズを事前計算します。 これにより、パス上で v が見つかったときに、クエリ ノードの前にトラバーサルに追加されるノードの数を計算できます。 
5. 固定クエリ ノード i について、i が v の左右のサブツリーにあるかどうか、現在のラベル x[v]、および v のサブツリー サイズの 3 つの情報に基づいて祖先 v の寄与を定義します。この寄与は、v 自体とその兄弟サブツリーが i の前に現れるかどうかを決定する定数時間式です。 
6. クエリに答えるには、root から i までの重光分解パスをたどります。 各セグメントについて、x に対するセグメント ツリーを使用して、そのセグメント内のすべてのノードの集約された寄与を計算します。この寄与は、ノードがパス構造に対して左方向にあるか右方向にあるかによって重み付けされます。 すべてのセグメントの貢献度を組み合わせて、最終的なランクを取得します。 
7. 更新クエリの場合は、ノード インデックス上のセグメント ツリーに範囲割り当てを適用します。 これにより、x 値が対数時間で更新され、将来のすべてのパス クエリに自動的に影響します。 

### なぜ効果があるのか

 走査順序は、各ノードに適用されるローカル順序付けルールによって完全に決定され、それらのルールはノードがその左右のサブツリーとどのように対話するかにのみ影響します。 固定ターゲット ノード i の場合、ルートから i へのパスの外側にあるすべてのノードは、完全に i の前後に完全なサブツリー ブロックを提供するか、クエリに依存するものをまったく提供しません。 これにより、グローバルな順序付けの問題が、単一のパスに沿った独立した寄与の合計に軽減されます。 ヘビーライト分解により、このパスを効率的に処理できることが保証され、一方、セグメント ツリーにより、構造を再構築することなく動的なラベルの変更がそれらの寄与に反映されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
L = [0] * (n + 1)
R = [0] * (n + 1)

for i in range(1, n + 1):
    l, r = map(int, input().split())
    L[i] = l
    R[i] = r

parent = [0] * (n + 1)
is_left = [0] * (n + 1)

g = [[] for _ in range(n + 1)]
for i in range(1, n + 1):
    if L[i]:
        parent[L[i]] = i
        is_left[L[i]] = 1
        g[i].append(L[i])
    if R[i]:
        parent[R[i]] = i
        is_left[R[i]] = 0
        g[i].append(R[i])

sz = [0] * (n + 1)

def dfs(u):
    sz[u] = 1
    for v in g[u]:
        dfs(v)
        sz[u] += sz[v]

dfs(1)

# heavy-light decomposition
heavy = [0] * (n + 1)
depth = [0] * (n + 1)
head = [0] * (n + 1)
pos = [0] * (n + 1)
cur = 0

def dfs_hld(u):
    global cur
    sz_u = sz[u]
    maxc = 0
    big = 0
    for v in g[u]:
        depth[v] = depth[u] + 1
        dfs_hld(v)
        if sz[v] > maxc:
            maxc = sz[v]
            big = v
    heavy[u] = big

dfs_hld(1)

def decompose(u, h):
    global cur
    head[u] = h
    pos[u] = cur
    cur += 1
    if heavy[u]:
        decompose(heavy[u], h)
        for v in g[u]:
            if v != heavy[u]:
                decompose(v, v)

decompose(1, 1)

x = [-1] * (n + 1)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)
        self.lazy = [None] * (4 * n)

    def apply(self, v, l, r, val):
        self.t[v] = val
        self.lazy[v] = val

    def push(self, v, l, r):
        if self.lazy[v] is None:
            return
        m = (l + r) // 2
        self.apply(v*2, l, m, self.lazy[v])
        self.apply(v*2+1, m+1, r, self.lazy[v])
        self.lazy[v] = None

    def update(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(v, l, r, val)
            return
        self.push(v, l, r)
        m = (l + r) // 2
        if ql <= m:
            self.update(v*2, l, m, ql, qr, val)
        if qr > m:
            self.update(v*2+1, m+1, r, ql, qr, val)

    def get(self, v, l, r, i):
        if l == r:
            return self.t[v]
        self.push(v, l, r)
        m = (l + r) // 2
        if i <= m:
            return self.get(v*2, l, m, i)
        return self.get(v*2+1, m+1, r, i)

seg = SegTree(n)

def contribution(v, target):
    if v == 0:
        return 0
    side = is_left[target]
    if side == 1:
        if seg.get(1, 1, n, v) == -1:
            return 1
        return 0
    else:
        if seg.get(1, 1, n, v) in (0, -1):
            return 1
        return 0

def query(u):
    res = 0
    while u:
        h = head[u]
        v = u
        while v != parent[h]:
            res += contribution(v, u)
            v = parent[v]
        u = parent[h]
    return res + 1

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, l, r, val = tmp
        seg.update(1, 1, n, l, r, val)
    else:
        _, i = tmp
        print(query(i))
```セグメント ツリーは、すべてのノードの現在のラベルを保存し、更新がノード インデックスの連続した間隔に影響を与えるために必要な範囲割り当てをサポートします。 各クエリは、ルートからノードへのパスに沿って祖先のラベルを取得し、それらを最終ランクへの寄与に変換します。 

ヘビーライト構造は、パスを管理可能なセグメントに分割するために使用され、1 回のパスで完全な深さを通過しないようにします。 寄与関数は、現在のラベルに基づいてノードがそれ自体をトラバーサルのプレフィックスに追加するかどうか、およびクエリ ノードがその左側または右側のサブツリーにあるかどうかをエンコードします。 

最終的なランクは、すべての祖先の貢献の合計にノード自体の 1 を加えたものです。 

## 実用的な例

 ノード 1 に 2 つの子 2 と 3 があり、ノード 2 に子 4 と 5 がある小さなツリーを考えます。ラベルが最初はすべて -1 (事前順序走査を意味する) であると仮定します。 

| ステップ | ノード | ラベル | 貢献ロジック | 部分ランク |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | -1 | ノード 2 は 4 のサブツリーの前にあります | 2 |
 | 2 | 1 | -1 | ノード 1 はサブツリーの前にあります | 1 |
 | 3 | 4 | -1 | リーフノード自体を追加します | 3 |

 これは、予想される予約注文構造を裏付けています。 

ここで、ノード 1 を事後順序に変更し、他のノードは事前順序のままにすることを検討してください。 ルートはトラバーサルの最後に移動するため、その下のすべてのノードが先に移動します。 

| ステップ | ノード | ラベル | 注文への影響 | ランク推移 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | ルートは子の後に移動します。 最終位置 1 を増やします |
 | 2 | 2 | -1 | ローカルでは変更なし | 安定した |
 | 3 | 4 | -1 | サブツリー内のまだ葉 | 写真 安定した |

 これは、内部のサブツリー構造に影響を与えることなく、単一の祖先の更新がグローバルな順序付けにどのように影響するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log² n) | 各クエリは、ヘビー-ライト パスをたどって、祖先の寄与を求めるセグメント ツリー クエリを実行します。 
| スペース | O(n) | ツリー、分解配列、およびセグメント ツリーのストレージ |

 各操作は対数的に多くのセグメントのみに触れ、各セグメント操作はラベル上のセグメント ツリーにより対数的であるため、複雑さは制限内に収まります。

 ## 特殊なケース

 歪んだチェーンは、再帰の深さの問題なしに祖先の蓄積が処理されるかどうかをテストします。 各ノードはルートからリーフへのパス上にあるため、すべての更新がすべてのクエリに影響し、誤ったセグメント集計がすぐに目に見えます。 

すべてのノードが事後順序に更新される場合は、祖先がプレフィックスの寄与から正しく除外されているかどうかをテストします。 ルートは常にトラバースの最後に移動する必要があり、ルートでのラベル効果を無視するソリューションでは、体系的にシフトされた答えが生成されます。 

部分的な更新では古いラベルが将来のクエリに漏れてはいけないため、すべてのノードをカバーする範囲更新では、遅延伝播が以前の値を正しく上書きするかどうかをテストします。
