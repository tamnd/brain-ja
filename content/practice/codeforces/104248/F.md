 ## 解決策
 ## 問題の理解

 私たちには小さな番号が与えられています\(n \le 8\)、入力変数の固定リストを表します。\(x_1, x_2, \dots, x_n\)。 これに加えて、ターゲット式が与えられます\(X\)、これらの変数の短い文字列として記述されます。 

タスクは、組み合わせ論理項を構築することです\(P\)、プリミティブ コンビネータのみから構築\(I\)、\(K\)、\(S\)、および括弧は、次のような場合に\(P\)シーケンスに適用されます\(x_1 x_2 \dots x_n\)、基準以下に減少します\(S\)、\(K\)、\(I\)式へのリダクション ルール\(X\)。 

より具体的に言うと、\(P\)の関数のように動作します\(n\)引数。 すべての引数が指定されると、その構造がまさに次の記号の左に関連付けられた適用である項を生成する必要があります。\(X\)。 たとえば、次の場合\(X = abc\)、完全な評価後の結果は \(((a b) c)\) でなければなりません。 

重要な制限は、SKI コンビネータを使用する場合を除き、出力構造で変数を直接使用できないことです。 ラムダ式をシミュレートする組み合わせ項を合成する必要があります。\(\lambda x_1 \dots x_n.\, X\)。 

の小さな値\(n\)は重要な構造上の制約です。 入力が最大 8 つ、出力の長さが最大 ​​8 シンボルであるため、関数の合計の意味論的な複雑さはごくわずかです。 ただし、SKI 形式の構文エンコーディングは最大 400,000 文字まで大きくなる可能性があるため、構築プロセスでの急激な爆発を回避する必要があります。 

単純な間違いは、「変数を選択」のようなものを直接記述できると考えることです。\(x_i\)」または「戻る」\(X\)もう 1 つのよくある失敗は、SKI ではアプリケーション構造を介して明示的にエンコードする必要がある場合に、出力の連結が自由であると誤って想定することです。 

エッジケースは最小限ですが重要です。 もし\(X\)が単一の変数の場合、正解は単にその引数を返す射影コンビネータです。 すべてのシンボルが入っている場合、\(X\)が同一であっても、ソリューションは単一のオカレンスに折りたたむのではなく、完全なアプリケーション構造を保持する必要があります。 

## アプローチ

 ブルートフォース解釈では、コンビネータ式を直接検索しようとします。\(I\)、\(K\)、 そして\(S\)その評価が目的のマッピングと一致する\(n\)への入力\(X\)。 考えられる SKI 式の空間は長さに応じて指数関数的に増大し、各候補をシンボリック入力でシミュレートする必要があるためリダクション チェック自体もコストがかかるため、これはすぐに実行不可能になります。 

重要な観察は、SKI コンビネータが *機能的に完全* であることが知られているということです。つまり、変数を体系的に削除することで、すべてのラムダ式を SKI 形式に変換できます。 これは、検索をしないことを意味します。 代わりに、目的の関数を SKI に *コンパイル*します。 

ターゲット関数は非常に構造化されています。 それは単に「取る」です\(n\)引数を指定して固定式を返す\(X\)これはまさにラムダ項であり、分岐や算術はなく、変数の選択と反復適用だけが行われます。 

したがって、問題は、投影の SKI 表現を構築し、アプリケーションを使用してそれらを構成することに帰着します。 

標準ツールはブラケット抽象化: 変換です。\(\lambda x.t\)に対応する 3 つのルールを使用して変数を再帰的に削除することにより、SKI に変換されます。\(I\)、\(K\)、 そして\(S\)。 これを繰り返すと、\(n\)変数は閉じたコンビネータを生成します\(P\)。

 ## アルゴリズムのチュートリアル

 私たちは建設します\(P\)変数に対してターゲット式を反復的に抽象化することによって\(x_n, x_{n-1}, \dots, x_1\)。 

1. に対応する生の式ツリーから開始します。\(X\)、各文字は変数です\(x_i\)。 これは、自由変数を使用したコンビネータ式として扱われます。 

2. 各変数について\(x_k\)から\(n\)まで\(1\)、現在の式を変換します\(T\)新しい表現に\(\lambda x_k. T\)括弧の抽象化ルールを使用します。 このステップでは、一度に 1 つの変数を削除します。 

3. 抽象化する場合\(x\)、の構造を処理します\(T\)：
もし\(T\)まさに\(x\)に置き換えてください\(I\)。 
もし\(x\)には現れない\(T\)に置き換えてください\(K T\)。 
もし\(T\)アプリケーションです\(A B\)を \(S (\lambda x.A)(\lambda x.B)\) に置き換えます。 

再帰により、変数のすべての出現がコンビネータを適切に通過することが保証されます。 

4. すべての抽象化が適用された後、結果として得られる用語には、\(I\)、\(K\)、 そして\(S\)、変数はありません。 これは必須です\(P\)。 

これが機能する決定的な理由は、各抽象化ステップで意味論的な等価性が維持されるためです。変換された項は、任意の引数に適用された場合、ラムダ抽象化と同じように動作します。 帰納的に、すべての変数を削除した後、元の関数とまったく同じように評価される閉じた項が得られます。\( \lambda x_1 \dots x_n. X \)。 

各抽象化は構造の 1 つの層を制限された数のコンビネータで置き換えるため、構築は最終的な式のサイズにおいて線形です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("t", "l", "r", "v")
    def __init__(self, t, l=None, r=None, v=None):
        self.t = t
        self.l = l
        self.r = r
        self.v = v

def parse(expr):
    # expression is just sequence of variables, left-associated application
    # build as left fold of variables
    nodes = [Node("var", v=c) for c in expr]
    if not nodes:
        return None
    cur = nodes[0]
    for i in range(1, len(nodes)):
        cur = Node("app", cur, nodes[i])
    return cur

def free_of_x(node, x):
    if node.t == "var":
        return node.v != x
    return free_of_x(node.l, x) and free_of_x(node.r, x)

def subst(node, x):
    # bracket abstraction: λx.node
    if node.t == "var":
        if node.v == x:
            return Node("I")
        return Node("K", Node("I"), node)  # placeholder, fixed below
    if node.t == "app":
        A = subst(node.l, x)
        B = subst(node.r, x)
        return Node("app", Node("app", Node("S"), A), B)

def abstract(node, x):
    if node.t == "var":
        if node.v == x:
            return Node("I")
        return Node("app", Node("K"), node)
    if free_of_x(node, x):
        return Node("app", Node("K"), node)
    if node.t == "app":
        A = abstract(node.l, x)
        B = abstract(node.r, x)
        return Node("app", Node("app", Node("S"), A), B)

def to_string(node):
    if node.t == "var":
        return node.v
    if node.t == "I":
        return "I"
    if node.t == "S":
        return "S"
    if node.t == "K":
        return "K"
    return "(" + to_string(node.l) + to_string(node.r) + ")"

def main():
    n = int(input())
    X = input().strip()

    t = parse(X)

    # variables are x1..xn, but only need names; assume a,b,c...
    vars = [chr(ord('a') + i) for i in range(n)]

    for v in reversed(vars):
        t = abstract(t, v)

    print(to_string(t))

if __name__ == "__main__":
    main()
```解析ステップでは、ターゲット式に完全に左側に関連付けられたアプリケーション ツリーを構築します。 SKI の削減は文字列形式ではなくアプリケーション構造に依存するため、これは重要です。 

抽象化関数は、一度に 1 つの変数を削除します。 の`free_of_x`ショートカットは、変数が表示されない場合に不要な再帰を回避し、\(K\)ルール。 それ以外の場合、アプリケーションは\(S\)コンビネーター、構造を保持します。 

文字列への最終変換では、完全に括弧で囲まれたアプリケーションが出力されます。これは、解析時のあいまいさを避けるために必要です。 

## 実用的な例

 検討してください\(n = 2\)、\(X = "ab"\)。 

ツリー \( (a b) \) から始めます。 要約以上\(b\)初め。 

| ステップ | 式 |
 |---|---|
 | 開始 | (a b) |
 | 抽象b | S(Ka)(Ib) |
 | 抽象的な | 最終的な SKI フォーム |

 これは、抽象化を繰り返すことで、両方の引数を順番に返す高階関数を構築する方法を示しています。 

ここで考えてみましょう\(n = 3\)、\(X = "aca"\)。 

| ステップ | 式 |
 |---|---|
 | 開始 | ((a c) a) |
 | 抽象的なc | S(S(Ka)a)(Kc) |
 | 抽象b | 変更されない構造が伝播される |
 | 抽象的な | SKI最終学期 |

 このケースは、変数の繰り返しの出現が、\(S\)明示的なコピーではなく、コンビネーター。 

各トレースは、追加の簿記を導入することなく、変数の再利用が正しく表現されていることを確認します。

 ## 特殊なケース

 いつ\(X\)最初の引数と同一の単一の変数で構成されている場合、抽象化は、\(K\)ルール。 たとえば、入力\(n=3, X=a\)ネストされたチェーンに段階的に削減します。\(K\)最終的には最初の入力を除くすべての入力を無視するコンビネータを生成します。 

いつ\(X\)同じ変数を複数回繰り返します。たとえば、\(aaa\)、アルゴリズムは値を明示的にコピーしようとしません。 代わりに、\(S\)combinator は引数フローを構造的に複製します。 それぞれの出現は抽象化中に独立して処理され、最終項での正しいレプリケーションが保証されます。 

変数が現れない場合\(X\)まったく、抽象化によって用語が崩壊します。\(K T\)、定数関数を生成します。 これは、無関係な入力が破棄される唯一のメカニズムであり、未使用の変数への誤った依存を防ぎます。
