 ## 解決策
 ## 問題の理解

 私たちにはいくつかの石の山が与えられました。 各移動で、プレイヤーは正確に 1 つの山を選択し、そこから正の数の石を取り除きます。 最後の石を取り除いたプレイヤーはゲームに勝つのではなく負けることになるため、これは標準的な引き算ゲームの悲惨なバージョンになります。 

タスクは 2 つあります。 まず、両側からの最適なプレイを前提として、最初のプレイヤーが強制的に勝利するかどうかを判断する必要があります。 第 2 に、勝利戦略が存在する場合は、有効な最初の手を 1 つ出力する必要があります。これは、ポジションが相手にとって負けの状態に移行するように、どの山を選択し、いくつの石を削除するかを意味します。 

制約は非常に小さく、パイルは最大 100 個、各パイルのサイズは最大 100 個です。これにより、状態を越える指数関数的なゲーム ツリー探索が即座に除外されます。 すべての除去にわたる完全なミニマックスは、最大 100 までのサイズの各山で 1 つの手につき最大 100 の選択肢が可能であり、たった 100 の山でも状態空間が天文学的に大きくなるため、大きく分岐します。 

微妙なエッジケースはミゼール規則から生じます。 通常の Nim では、戦略はパイル サイズの XOR のみに依存します。 ここで、すべての山がサイズ 1 またはほぼ空の場合、負け条件が変わります。 たとえば、次のような位置`1 1 1`最後の石を取ることを強制されたプレイヤーは勝つのではなく負けることになるため、標準の Nim とは動作が異なります。 

すべてのパイルが同一の小さな値である場合、別の特殊なケースが発生します。 たとえば、サイズ 1 の山が 1 つしかない場合、最初のプレーヤーはそれを取得しなければならず、すぐに負けます。 ミゼール ルールを調整しない単純な XOR ベースの実装では、これが誤って分類されてしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのゲーム状態をゲーム ツリー内のノードとしてモデル化します。 ある状態から、山を選択し、1 と ai の間の石を削除することによってすべての手を試し、結果の順位が勝ちか負けかを再帰的に判断します。 これはゲーム グラフ全体を調査するため概念的には機能しますが、完全に実行不可能です。 

サイズ 100 の単一の山であっても、これによってすでに 100 の状態のチェーンが作成されます。 100 個の山では、分岐が山全体で増殖し、選択肢が増加し、指数関数的な爆発につながります。 最悪の場合の状態の数は、山全体の石のすべての分割数に相当し、計算の限界をはるかに超えています。 

重要な観察は、このゲームがミゼール ルールを備えた標準的な Nim の亜種であるということです。 通常の Nim では、パイルのグランディ値がそのサイズであり、すべてのパイルの XOR によって勝者が決まります。 唯一の変更は、すべての杭がサイズ 1 の場合、または問題を単一の石杭のみの構成に縮小する場合に発生します。 

少なくとも 1 つのパイルのサイズが 1 より大きい場合、ゲームは通常の Nim とまったく同じように動作するため、すべてのパイル サイズの XOR によって結果が決まります。 XOR がゼロの場合、ポジションは負けています。 それ以外の場合は、XOR をゼロにする手が存在し、山を必要な値まで減らすことで直接構築できます。 

すべての山がちょうど 1 の場合、ゲームは単純なパリティ ゲームになります。 すべての動きで 1 つの山が完全に削除され、最後の山を取ったプレイヤーが負けます。 したがって、山の数が奇数の場合、最初のプレーヤーが負けます。 偶数の場合は、最初のプレイヤーが勝ちます。 

これにより、問題は指数関数的な検索から 1 回の線形スキャンと 1 回の XOR 計算に減ります。

 ## アルゴリズムのチュートリアル

 すべての山がサイズ 1 であるかどうかに応じて、ゲームの扱いが異なります。 

1. すべての山をスキャンし、すべての山に石が 1 つだけあるかどうかを確認します。 

ミゼールルールが通常の Nim から逸脱するのはこの退廃的なケースの場合だけであるため、この区別は重要です。 
2. すべての山が 1 の場合、n が奇数か偶数かを計算します。 

n が奇数の場合、最初のプレイヤーは最終的に最後の山を取って負ける必要があるため、その位置は負けになります。 n が偶数の場合、最初のプレーヤーは常に動きをミラーリングできます。 
3. オール 1 の条件が成立し、n が偶数の場合は、勝ち手を出力します。山全体を 1 つ削除します (任意のインデックス、石を 1 つ削除します)。 

これによりカウントが奇数の 1 に減り、対戦相手に不利な立場が強制さ​​れます。 
4. それ以外の場合は、すべてのパイル サイズの XOR を計算します。 

これは、通常のプレイにおける標準の Nim 不変式です。 
5. XOR が 0 の場合、「Lose」を出力します。 

最適なプレイの仮定の下では、ゼロ XOR ポジションを別のゼロ XOR ポジションに変換する手はありません。 
6. XOR がゼロ以外の場合、勝ち手を構築します。 

減らすと XOR がゼロになる山を見つけます。 山 a[i] の場合、target = a[i] XOR xor_all を計算し、a[i] - ターゲットの石を削除します。 
7. 選択したパイルインデックスと除去カウントを出力します。 

### なぜ効果があるのか

核となる不変条件は、パイル サイズの XOR が通常の Nim での負けポジションを特徴付けるということであり、唯一の例外はミゼール プレイでのオール 1 構成です。 すべての正当な手はちょうど 1 つの山を変更し、XOR はそのような更新の下で予測どおりに動作します。つまり、山を x から y に反転すると、XOR が X から X XOR x XOR y に変更されます。 これがゼロになるように y を選択すると、対戦相手が負け状態になることが保証されます。 すべてのヒープが同一のシングルトンである場合、XOR だけでは最後の移動損失ルールが捕捉されないため、オール 1 のケースは別になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    all_ones = all(x == 1 for x in a)

    if all_ones:
        if n % 2 == 1:
            print("Lose")
        else:
            print("Win")
            # remove one stone from any pile
            print(1, 1)
        return

    xr = 0
    for x in a:
        xr ^= x

    if xr == 0:
        print("Lose")
        return

    print("Win")
    for i, x in enumerate(a):
        target = x ^ xr
        if target < x:
            print(i + 1, x - target)
            return

if __name__ == "__main__":
    solve()
```ミゼールの動作はそこでのみ異なるため、解決策はまず特殊なすべて 1 のケースを分離します。 次に、すべてのパイル サイズの XOR を計算します。 XOR がゼロ以外の場合、新しい値が次と等しくなるように削減できる山を検索します。`x XOR total_xor`これにより、グローバル XOR がゼロになることが保証されます。 減算量は、現在のパイル サイズとこのターゲットの差となります。 

XOR が 0 以外の場合、少なくとも 1 つの有効なパイルが存在する必要があるため、パイル上のループは安全です。

 ## 特殊なケース

 重要なエッジケースの 1 つは、サイズ 1 の単一の山です。 入力`1 / 1`すぐにすべて 1 の分岐をトリガーします。 アルゴリズムは n = 1 (奇数) を識別するため、「Lose」を出力します。 これは、最初のプレイヤーが最後の石を取って負けるというルールと一致します。 

別のケースは、すべての山が 1 であるが、n が偶数である場合です。`1 1`。 アルゴリズムは勝ちを出力し、最初の山から 1 つの石を削除します。 この移動の後、山は 1 つだけ残り、相手は負けることになります。 

3 番目のエッジケースは、次のような混合構成です。`1 1 5`。 XOR はゼロではないため、アルゴリズムはすべて 1 のショートカットを無視し、通常の Nim ロジックを使用します。 山 (5 個) を見つけて、XOR がゼロになるように減らします。 これが機能するのは、1 より大きなパイルが存在すると標準の Nim 構造が復元され、複雑な問題が適用されなくなるからです。
