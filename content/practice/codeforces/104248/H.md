 ## 解決策
 ## 問題の理解

 固定三角形の内側または境界上に描かれた閉じたポリラインの 3 つのセグメントの長さを表す 3 つの数値が与えられます。 ポリラインには正確に 3 つのセグメントがあり、このポリラインのすべての頂点は三角形の辺の 1 つに位置する必要があります。 さらに、三角形の各辺にはこれらの頂点が少なくとも 1 つ含まれている必要があるため、ポリラインは強制的に三角形のすべての辺に「接触」することになります。 

このようなすべての有効なポリラインのうち、最初に 3 つのセグメントすべての合計の長さを最小化します。 複数の構造が同じ最小全長を達成する場合、セグメント長の積を最小にする構造を選択します。 このタスクでは、何かを構築するように求められるわけではありません。 代わりに、結果として得られる最適なポリラインが指定されたトリプル a、b、c と正確に等しいセグメント長を持つ三角形が存在するかどうかのみが尋ねられます。 

入力制約は非常に小さく、各値はマイナス 1,000 から 1,000 の間です。 これは、三角形の形状に対する強引な幾何学的検索が不可能であることを直ちに示していますが、答えは明示的な幾何学ではなく、3 つの数値に関する単純な代数条件によって決定される可能性が高いことも示唆しています。 

重要な点は、入力に負の値が許可されていることです。 ジオメトリ内のセグメントの長さは常に非負であるため、有効な構成では、a、b、c がすべて負でない必要があります。 それだけですでに多くのケースが排除されています。 

もう 1 つの隠れたエッジのケースは、構造をサポートする三角形の縮退です。 元の三角形は非縮退である必要がありますが、ポリライン制約はその側面にある点のみを考慮し、最適化は事実上、三角形の境界上の 3 つの点が最短の閉じたチェーンでどのように接続されるかについての推論に帰着します。 多くの素朴な解釈は任意の幾何学を誤って仮定していますが、実際の答えははるかに単純な条件に崩壊します。 

不注意なアプローチでは、三角形の形状や頂点の配置を列挙しようとする可能性がありますが、最小化ステップの後には意味のある自由度のみが失われるため、これは不必要で誤解を招く可能性があります。 

## アプローチ

 強引なアイデアは、座標を持つ三角形を考慮し、その辺に 3 つの点を配置し、それらをすべての可能な巡回順序で接続し、各辺が少なくとも 1 回接触することを強制しながら、結果として得られるポリラインの長さを計算することです。 それぞれの三角形の形状と配置について、最適な構成によってセグメントの長さが a、b、c になるかどうかをテストします。 

このアプローチは理論的には正しいですが、三角形の空間は連続しているため、すぐに失敗します。 座標を離散化しても、構成の数は組み合わせ的に増加します。 3 辺の 3 点のそれぞれの配置にはすでに連続的な自由度があり、そのような配置すべてを最小化すると、数え切れないほどの検索スペースが生じます。 

重要な観察は、全長を最小化した後、最適なポリラインは常に、展開された境界表現で各辺が直線セグメントとして「使用」される回数のみに依存する構成に縮退するということです。 実際、幾何学的制約により、ポリラインは三角形の辺で形成された木のような構造上で最短の閉じたチェーンのように動作するように強制されます。 これにより、問題は純粋に代数的な条件に帰着します。つまり、3 つのセグメントの長さは、適切な順序付けの後、不等式の意味で有効な三角形を形成できなければならず、それらはすべて非負でなければなりません。

直感的には、最小化ステップにより、実際の三角形の形状への依存が除去されます。 残っているのは、凸状境界上の 3 点を最短周期順序で接続するのと同等の構成であり、これは常に平らな境界に沿ったユークリッド距離のように動作する直線セグメントによって実現されます。 これは、ソート後にトリプルが三角形不等式を満たさなければならないという古典的な条件につながります。 

したがって、幾何学的なセットアップ全体は、すべてが正でなければならないという追加の制約とともに、a、b、c が非縮退三角形の辺の長さとして解釈できるかどうかをチェックすることに集約されます。

 ## アルゴリズムのチュートリアル

 a、b、c と正確に等しいセグメント長を生成する構成が存在するかどうかを判断したいと考えています。 これらは長さを表すため、最初の制約は非負です。 

2 番目の制約は、最小の閉じた 3 セグメント サイクルの構造に由来します。そのようなサイクルは、最適化後にユークリッド空間で三角形のように動作する必要があるため、セグメントの長さは有効な三角形を形成できなければなりません。 

### ステップ

 1. 3 つの整数 a、b、c を読み取ります。 これらはポリラインの候補セグメント長です。 
2. a、b、c のいずれかが負かどうかを確認します。 少なくとも 1 つが否定的な場合は、構成は不可能であると直ちに結論付けます。 負の長さは幾何学的セグメントを表すことはできません。 
3. x ≤ y ≤ z になるように値を並べ替えます。 並べ替えを使用すると、順列をチェックする代わりに、必要なすべての条件を 1 つの不等式で表現できます。 
4. x + y ≥ z が成立するかどうかを検証します。 これは、「中断」または不可能なジオメトリを強制することなく、3 つのセグメントがループに近づくことができることを保証する三角形不等式条件です。 
5. 非負かつ三角不等式が成立する場合は「Yes」を出力します。 それ以外の場合は「いいえ」を出力します。 

### なぜ効果があるのか

 元の構築における最適化により、ポリラインは凸形状の 3 つの境界点を接続する最短の閉じたパスのように動作するように強制されます。 このようなパスは、三角形不等式の違反によって正確に捉えられる、閉鎖を妨げる「欠損角」を持つことはできません。 最大のセグメントが他の 2 つのセグメントの合計よりも長い場合、最適性を超えて全長を増加させずにループを閉じる幾何学的実現はできず、最小性と矛盾します。 逆に、三角形不等式が成り立つときは常に、セグメントが有効な三角形境界構成を形成していると解釈でき、これらの正確なセグメント長を達成する縮退埋め込みがいくつかの三角形に存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c = map(int, input().split())

# all lengths must be nonnegative
if a < 0 or b < 0 or c < 0:
    print("No")
    sys.exit()

x, y, z = sorted([a, b, c])

# triangle inequality
if x + y >= z:
    print("Yes")
else:
    print("No")
```ジオメトリでは負のセグメント長が禁止されているため、ソリューションではまず無効な負の入力をフィルターします。 次に、条件を 1 つの並べ替えられた不等号チェックに縮小します。 並べ替えにより、すべての順列ではなく、三角不等式の 1 つのケースのみをテストするだけで済みます。 

重要な実装の詳細は次のとおりです。`>=`それよりも`>`。 縮退三角形は問題の最小化ルールに基づく有効な制限構成に依然として対応するため、等価性が許可されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    a, b, c = map(int, input().split())

    if a < 0 or b < 0 or c < 0:
        return "No"

    x, y, z = sorted([a, b, c])

    if x + y >= z:
        return "Yes"
    return "No"

# provided sample
assert run("2 3 4\n") == "Yes"
assert run("-1 -1 -1\n") == "No"

# custom cases
assert run("0 0 0\n") == "Yes", "degenerate zero triangle"
assert run("1 2 3\n") == "Yes", "degenerate equality case"
assert run("1 2 4\n") == "No", "violates triangle inequality"
assert run("10 1 1\n") == "No", "large imbalance case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0 0 0 | はい | 有効な境界ケースを縮退する |
 | 1 2 3 | はい | 等価性は許可されます |
 | 1 2 4 | いいえ | 三角不等式違反 |
 | 10 1 1 | いいえ | 極端な不均衡の除去 |

 ## 特殊なケース

 次のような負の入力の場合`-1 5 5`、アルゴリズムは並べ替えの前にそれらを即座に拒否します。 これにより、注文後に幾何学的な長さとして誤って解釈されるのを防ぎます。 

次のような退化したケースの場合`0 0 0`、ソートにより生成される`(0, 0, 0)`そして不平等`0 + 0 ≥ 0`が成り立つので、出力は正しく「Yes」になります。 これは、折りたたまれた三角形が依然として最小長条件を満たしているという解釈と一致します。 

境界等価性の場合、次のような`1 2 3`、ソートすると、`(1, 2, 3)`そして不等式は正確に成り立ちます。 これは、閉包条件で等価性が許容されることを確認し、縮退三角形の実現と一致します。 

のような強いアンバランス入力の場合`10 1 1`、ソートすると、`(1, 1, 10)`そして不等式は成り立ちません。 これは、他の 2 つのセグメントの合計よりも長い 1 つのセグメントでループを閉じることができない構成が存在しないことを正しく反映しており、その場合、想定される最適な構造を超えて全長が増加することになります。
