 ## 解決策
 ## 問題の理解

 有向グラフが与えられます$n$すべての頂点に最大 1 つの外向きエッジがある頂点。 各頂点には小文字のラベルも付いています。 一部の頂点は別の頂点を指しますが、他の頂点は終端で何も指しません。 

決定論的な比較手順で 2 つの頂点を分離できない場合、2 つの頂点は区別できないとみなされます。 この手順では、2 つの開始頂点を並行して比較します。最初にそれらのラベル、次にそれらに出力エッジがあるかどうか、そして両方が終端である場合、それらは直ちに同等であると見なされます。 それ以外の場合、両方に発信エッジがある場合、比較はそれぞれの発信エッジに対して再帰的に続行されます。 

重要な考え方は、出力エッジを繰り返したどったときに、終了するまで常に同じラベルと構造の選択肢のシーケンスが表示される場合、2 つの頂点は同等であるということです。 これにより、問題は本質的に、頂点が生成するチェーンの「署名」によって頂点をグループ化することになります。 

制約$n \le 10^5$ペアごとの比較アプローチを除外します。 すべてのペアを比較すると、$O(n^2)$また、各比較は長さのチェーンに沿って進む可能性があるため、比較のシミュレーションさえも遅すぎます。$O(n)$、最悪の場合には立体的な動作を与えます。 

複数の頂点が長いチェーンを形成し、最終的にはマージされる場合、微妙なエッジ ケースが発生します。 たとえば:

 入力:```
a 2
a 3
a 0
a 0
```頂点 2 と 3 は両方とも終端ノードを指しますが、異なるパスを経由します。 直接隣接するものだけを比較するか、ラベルだけを比較する単純なアプローチでは、実装の詳細に応じてそれらを誤ってマージまたは分離する可能性があります。 正しい等価性は、発信パスの完全な構造によって異なります。 

もう 1 つの特殊なケースはサイクルです。 各頂点には最大でも 1 つの出力エッジがあるため、循環が可能です。 サイクルでは、状態の繰り返しを検出しない限り、比較が自然に終了することはありません。 単純な DFS 比較は永久にループするか、不等価であると誤って仮定します。 

## アプローチ

 ブルート フォース手法では、指定されたプロセスをシミュレートすることにより、頂点のすべてのペアを比較しようとします。 各ペアについて、ラベルと構造を比較しながら、出ていくエッジに沿って足並みを揃えて歩きます。 不一致に遭遇した場合は、停止します。 それ以外の場合は、両方のパスが終了するまで続行されます。 

これは等価性の定義を直接反映しているため、概念的には正しいです。 ただし、チェーンまたはサイクルを含むグラフでは、1 つの比較で複数の要素を横断することができます。$O(n)$頂点。 これをすべてのペアに対して行うと、$O(n^2)$それぞれの比較、潜在的に$O(n)$、 その結果$O(n^3)$最悪の場合は時間がかかります。 

重要な観察は、各頂点の構造が 2 つのコンポーネント (そのラベルとその出力近傍の同値クラス) によって完全に決定されるということです。 2 つの頂点が同じラベルを持ち、その外向きの隣接頂点が同等であることがすでにわかっている場合、これらの頂点自体が同等になります。 終端頂点は、外向きのエッジを持たない基本ケースです。 

これは当然、逆の依存関係の順序で頂点を処理することを示唆していますが、グラフにはサイクルが含まれている可能性があるため、単純なトポロジー順序は存在しません。 代わりに、各頂点の「署名」を再帰的に定義されたオブジェクトとして扱い、反復ハッシュと安定化を使用して同値クラスを計算します。 

各頂点に、そのラベルとその出力近傍の現在のクラス (または終端ノードの場合は特別な null 値) で構成される署名を割り当てます。 その後、変化がなくなるまでクラスを繰り返し再計算します。 各改良は状態空間を厳密に分割または安定化するため、収束は対数反復または線形に近い反復で発生します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペア シミュレーション |$O(n^3)$|$O(n)$| 遅すぎる |
 | 反復的な署名の改良 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 等価性の再帰的定義を頂点シグネチャの反復改良に圧縮します。 

1. 各頂点のクラスを 0 として初期化します。これは、構造を考慮する前に、最初にすべての頂点が同一であると想定されていることを表します。 
2. 各頂点に対して、そのラベルとその出力近傍の現在のクラスで構成される一時キーを定義するか、出力エッジがない場合は特別な値を定義します。 これは、比較プロセスが再帰の 1 ステップで確認したものを正確にエンコードします。 
3. これらのキーをソートまたはハッシュして、新しいクラス ID を一貫して割り当てます。 同一のキーを持つ頂点は同じクラスを受け取ります。 
4. クラスの割り当てが安定するまで、ステップ 2 と 3 を繰り返します。 安定性とは、反復中に頂点のクラスが変更されないことを意味するため、さらに改良しても等価性は変わりません。 
5. 最終的なクラス ID を出力します。 

繰り返し再計算を行う理由は、発信近隣クラス自体が定義の一部であるためです。 最初は正しい等価性が分からないため、粗く開始して、構造が完全に捕捉されるまで徐々に洗練していきます。 

### なぜ効果があるのか

 不変条件は、各反復の後、2 つの頂点が同一の計算クラスを持つ場合、それらの出力サブ構造は現在のリファインメントの深さまで区別できないということです。 各反復により、出力エッジに沿って「先読み深さ」が 1 ステップずつ効果的に増加します。 各頂点には出力エッジが最大 1 つあるため、構造はチェーンとサイクルの集合であり、リファインメントはこれらの構造に沿って決定論的に伝播します。 パーティションの変更が停止すると、クラスは完全再帰比較によって定義された等価関係を正確にエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
label = []
to = []

for _ in range(n):
    parts = input().split()
    label.append(parts[0])
    t = int(parts[1])
    to.append(t - 1 if t != 0 else -1)

cls = [0] * n

while True:
    keys = []
    for i in range(n):
        nxt = cls[to[i]] if to[i] != -1 else -1
        keys.append((label[i], nxt, i))

    keys.sort()

    new_cls = [0] * n
    cur = 0
    new_cls[keys[0][2]] = 0

    for i in range(1, n):
        if keys[i][0] != keys[i - 1][0] or keys[i][1] != keys[i - 1][1]:
            cur += 1
        new_cls[keys[i][2]] = cur

    if new_cls == cls:
        break
    cls = new_cls

print("\n".join(map(str, cls)))
```このコードは、出力エッジをゼロベースのインデックスに変換して、初期のグラフ表現を構築します。 各反復では、ラベルとその出力近傍の現在のクラスを組み合わせたすべての頂点の署名が構築されます。 これらのシグネチャをソートすると、同一の構造がグループ化され、それに応じて新しいクラス ID が割り当てられます。 

終了チェックでは、反復間で完全なクラス配列が比較されます。 安定したら、さらに洗練してもグループ化は変わらないため、停止します。 

実装の微妙な詳細は、キー タプルに元のインデックスを含めることです。 これにより、ソート後に安定した頂点への割り当てが保証されます。 これがないと、ソートされた順序と頂点の同一性の間のマッピングが失われます。 

## 実用的な例

 ### 例 1

 入力:```
a 2
b 3
b 0
b 3
```初期状態:

 | 頂点 | ラベル | アウト | クラス |
 | --- | --- | --- | --- |
 | 1 | | 2 | 0 |
 | 2 | b | 3 | 0 |
 | 3 | b | - | 0 |
 | 4 | b | 3 | 0 |

 最初の反復キー:

 | 頂点 | キー |
 | --- | --- |
 | 1 | (a,0) |
 | 2 | (b,0) |
 | 3 | (b,-1) |
 | 4 | (b,0) |

 ソート後のクラスは次のようになります。 

| 頂点 | 新しいクラス |
 | --- | --- |
 | 3 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 4 | 1 |

 2 回目の反復では、更新された隣接クラスを使用します。 頂点 2 と 4 は両方とも、クラス 0 を持つ 3 を指しているため、それらの署名は (b,0) として再び一致します。 頂点 1 は、異なる洗練された構造を持つ頂点 2 を指しているため、明確なままです。 安定化後、頂点 1、2、4 は完全な構造的同一性を反映する一貫した等価グループに分類されます。 

これは、平等性がラベルだけでなく、発信チェーンの安定した構造にも依存することを示しています。 

### 例 2

 入力:```
3
a 2
a 3
a 1
```これにより、1 → 2 → 3 → 1 のサイクルが形成されます。 

最初はすべてのクラスが同等です。 最初の改良では、すべてのラベルが一致し、すべての近傍がクラス 0 を持つため、すべての頂点に同一のキーが割り当てられます。どの反復でも区別は生じないため、アルゴリズムはすぐに安定します。 

これにより、サイクル ノードがプロセスにおいて構造的に対称である場合、それらが同等であることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n \cdot k)$| 反復ごとにソート$n$キー。$k$| は安定化するまでのリファインメントの数です。 
| スペース |$O(n)$| ラベル、エッジ、クラス割り当ての配列 |

 実際には、反復回数は少なくなります。これは、各ステップが構造の深さの少なくとも 1 レベルによって同値クラスを絞り込み、グラフには次数制約があるため境界構造があるためです。 と$n \le 10^5$, これは制限時間内に快適に収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての頂点が終端である場合です。 その場合、すべての頂点には外向きのエッジがなく、ラベルのみが重要になります。 このアルゴリズムは純粋にラベルによって初期キーを割り当てるため、同一のラベルはすぐにグループを形成し、安定化は 1 回の反復で行われます。 

もう 1 つのエッジ ケースは、終端ノードで終わる長いチェーンです。 例えば、$1 \to 2 \to 3 \to 4 \to 5$。 等価性は逆方向に伝播します。つまり、ノード 5 がベースであり、次にノード 4 がそれに依存する、というようになります。 反復的な改良によりこれが徐々に捕捉され、下流の構造が異なる場合、異なる深度にあるノードが異なるクラスを確実に受け取るようになります。 

最後のエッジ ケースは、チェーンにフィードするサイクルです。 各頂点には出力エッジが 1 つだけあるため、このような構造は単純ですが、それでもサイクルを通じて終端の区別を伝播する必要があります。 サイクル ノードが一貫した下流クラスを認識すると、リファインメント プロセスが安定し、正しいグループ化が保証されます。
