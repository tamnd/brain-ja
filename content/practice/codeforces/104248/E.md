 ## 解決策
 ## 問題の理解

 私たちは飛行機に配置されたバンパーの小さなコレクションを与えられました。 各バンパーには固定位置、半径、およびボールが衝突するたびに獲得されるスコアがあります。 ボールは、ジオメトリによって決定される特定の「最初の」バンパーに当たることから始まります。最も高い Y 座標を持つすべてのバンパーの中で、最も大きな X 座標を持つバンパーを開始点として選択します。 

最初のヒットの後、ボールはバンパーからバンパーへと移動します。 あるバンパーから別のバンパーへの移動は、その中心間の直線セグメントが他のバンパーと交差または接触していない場合にのみ許可されます。 各移動には、中心間のユークリッド距離から 2 つの半径を引いて切り上げたものに等しい時間がかかります。 ボールがバンパーに到達するたびに、そのバンパーの値だけスコアが増加します。 

次のバンパーを選択すると、動きは決定的になりますが、重要な制限があります。すぐに前のバンパーに戻ることは禁止されています。 これは、システムの状態が現在のバンパーだけでなく、どこから来たのかにも依存することを意味します。 

2 種類の質問に答えるように求められます。 1 つ目は、最初のバンパーから開始して、指定された時間 T までの任意の瞬間に取得できる最大スコアを求めます。 2 番目の質問は、時間 T でボールが現在特定のバンパー X にあると仮定して、その瞬間までに達成できた最大スコアはいくらか、またはそのような状況が発生しない場合は不可能であると報告することを尋ねます。 

制約はバンパーの数という点で非常に少なく、最大でも 7 です。これは、解の構造が n にわたる漸近最適化に関するものではなく、実行可能なすべての動作パターンを列挙または徹底的に探索するものであることをすぐに示唆しています。 大きな制約はクエリの数と時間制限値 (最大 1e9) であるため、時間を移行に伴う継続的な累積コストとして扱う必要があります。 

パスを考慮する場合、微妙なエッジケースが現れます。バンパーの再訪問は直前のノードによってのみ制限されるため、より長いサイクルが許可されます。 これは、ボールが複数のバンパーをループして通過する可能性があり、ポジティブなサイクルが存在する場合は任意の大きなスコアを蓄積する可能性があることを意味します。そのため、正しい解決策では、経路が単純であると仮定するのではなく、繰り返される横断パターンを慎重に考慮する必要があります。 

## アプローチ

 直接シミュレーションのアプローチでは、時間の経過に伴うバンパー衝突の考えられるすべてのシーケンスをモデル化しようとします。 どの状態からでも、次の有効なバンパーを選択し、移動時間を蓄積して続行します。 これにより、ノードがバンパーであり、可視性が満たされる場合に有向エッジが存在するグラフが自然に形成されます。重みは移動時間を表し、ノードの重みはスコアの増加を表します。 

すぐに複雑になるのは、状態が単なるノードではなく、現在のバンパーと前のバンパーで構成されるペアであることです。これは、前のバンパーに直接戻ることが禁止されているためです。 これを無視すると、違法な遷移が過大にカウントされてしまいます。 

ブルート フォース ソリューションでは、考えられるすべてのヒット シーケンスを列挙し、現在の時間とスコアを追跡し、到達可能なすべての状態を保存します。 n は最大 7 であるため、単純なシーケンスの数は制限されていますが、依然として指数関数的であり、各バンパーを最大 1 回訪問することに制限すると、おおよそ 7 階乗のオーダーになります。 再訪を許可すると、状態空間はサイクルによって無限になりますが、時間は移動するたびに増加するため、固定された時間範囲については、累積時間がその制限を超えないシーケンスのみを考慮する必要があります。

重要な観察は、すべての有効な進化が、各状態がペア (以前、現在の) である拡張された状態グラフ内のパスとして表現できるということです。 n は最大 7 であるため、最大 42 の状態が得られます。 各状態から、固定の移動コストで、前のバンパーを除く次のバンパーに移行します。 これにより、各ノードがすでに制約をエンコードしている小さな重み付き有向グラフの探索に問題が軽減されます。 

スコアは訪問ノードごとに蓄積され、時間はエッジで加算されるため、すべての完全なパスは明確に定義されたペア (時間、スコア) に対応します。 各クエリについて、基本的に、時間制約 (場合によっては特定の状態で終了することに制限) を満たすすべてのパスの中で最高のスコアを求めます。 

これを最短パスまたは DP で時間の経過とともに解決しようとするのではなく (1e9 限界があるため実行不可能です)、小さな状態空間を活用し、最初のバンパーから開始して、深さ優先検索によって到達可能なすべての状態を明示的に列挙します。 n は小さいため、すべての単純なパスを探索するだけでも十分安価です。 すぐに後戻りするサイクルを避けるために訪問した情報を維持し、同じパス内の状態を再訪問することを禁止することで無限再帰を自然に防ぎます。 

探索された各パスから、特定の状態 (以前、現在) の時間とスコアの具体的なペアが得られます。 これらの結果は保存されます。 クエリへの応答は、事前に計算されたリストをスキャンし、制約の下で最良のスコアを選択することになります。

 | 単純なパス上の完全な状態の列挙 | お(ん!) | お(ん!) | n ≤ 7 であるため受け入れられます |

 ## アルゴリズムのチュートリアル

 まず、バンパーのすべてのペア間の可視性グラフを作成します。 各ペアについて、中心間の直線セグメントが他のバンパーと交差するかどうかを確認します。 そうなった場合、その移行は禁止されます。 それ以外の場合は、幾何学的公式から計算された移動時間を持つ有向エッジになります。 

次に、すべての点をスキャンし、最大の Y 座標を持つ点を選択し、最大の X 座標との関係を破ることによって、開始バンパーを決定します。 これにより初期状態が得られます。 

次に、現在のバンパーと前のバンパーの両方をエンコードする状態に対して深さ優先検索を実行します。 初期状態は、以前の有効な移動を持たない開始バンパーから始まります。これは、previous を start 自体と等しく設定することによって表されます。 

各ステップで、現在の累積時間とスコアを記録します。 状態 (prev、cur) に到達するたびに、このペアを到達可能な構成として保存します。 現在の状態から、前のバンパーを除くすべての次のバンパーを試し、動きが有効で、時間が大きな安全限界を超えない場合は再帰します。 

この探索の後、到達可能なすべての状態とその時間およびスコア値のコレクションが得られます。 

最初のタイプのクエリごとに、記録されたすべての状態を反復処理し、時間が T 以下のものだけを考慮します。その中で最大スコアを取得します。 ゲームがすぐに停止する可能性があるため、初期状態も記載しています。 

2 番目のタイプのクエリごとに、現在のバンパーが指定された xj に一致する状態に注目を限定し、時間 T までに到達可能なスコアの中から最良のスコアを再度選択します。 

正確さは、すべての有効なプレイが展開された状態グラフ内のパスに正確に対応するという事実に依存します。 このようなパスを漏れなく列挙し、時間制約のもとで直接評価するため、解候補を取りこぼすことはありません。 

DFS 中に維持される不変条件は、記録されたすべての状態が、すべての幾何学的制約と直後の制約を満たす有効な一連の動きに対応するということです。 すべての拡張ステップはこれらの制約を尊重するため、無効な構成が結果セットに導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
b = []
for _ in range(n):
    x, y, r, s = map(int, input().split())
    b.append((x, y, r, s))

# check visibility
def visible(i, j):
    x1, y1, r1, _ = b[i]
    x2, y2, r2, _ = b[j]
    for k in range(n):
        if k == i or k == j:
            continue
        x3, y3, r3, _ = b[k]

        # distance from point k center to segment ij
        # compute projection
        dx, dy = x2 - x1, y2 - y1
        if dx == 0 and dy == 0:
            continue
        t = ((x3 - x1) * dx + (y3 - y1) * dy) / (dx * dx + dy * dy)
        t = max(0.0, min(1.0, t))
        px = x1 + t * dx
        py = y1 + t * dy
        dist2 = (px - x3) ** 2 + (py - y3) ** 2
        if dist2 <= r3 * r3:
            return False
    return True

def cost(i, j):
    x1, y1, r1, _ = b[i]
    x2, y2, r2, _ = b[j]
    dist = ((x1 - x2) ** 2 + (y1 - y2) ** 2) ** 0.5
    return max(0, int((dist - r1 - r2 + 0.999999)))

# start
start = 0
for i in range(n):
    if b[i][1] > b[start][1] or (b[i][1] == b[start][1] and b[i][0] > b[start][0]):
        start = i

adj = [[False] * n for _ in range(n)]
for i in range(n):
    for j in range(n):
        if i != j and visible(i, j):
            adj[i][j] = True

states = []

def dfs(cur, prev, t, score, visited_edges):
    states.append((cur, prev, t, score))
    for nxt in range(n):
        if nxt == prev:
            continue
        if not adj[cur][nxt]:
            continue
        nt = t + cost(cur, nxt)
        ns = score + b[nxt][3]
        if nt > 10**18:
            continue
        dfs(nxt, cur, nt, ns, visited_edges + ((cur, nxt),))

# initial
dfs(start, start, 0, b[start][3], ())

q = int(input())
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        T = tmp[1]
        ans = 0
        for cur, prev, t, s in states:
            if t <= T:
                ans = max(ans, s)
        print(ans)
    else:
        T, x = tmp[1], tmp[2]
        x -= 1
        ans = -10**18
        ok = False
        for cur, prev, t, s in states:
            if cur == x and t <= T:
                ans = max(ans, s)
                ok = True
        if not ok:
            print("#")
        else:
            print(ans)
```このソリューションは、バンパーのすべてのペア間の可視性マトリックスを構築することから始まります。 これは、遷移が正当​​であるかどうかを決定するために必要な唯一の幾何学的な前処理です。 コスト関数は、上限効果を伴う指定された式を使用して移動時間を計算します。 

DFS は、システムの到達可能なすべての構成を列挙します。 各状態には、現在のバンパー、前のバンパー、合計経過時間、および累積スコアが保存されます。 再帰では、前のバンパーにすぐに戻ることはできないというルールが尊重されます。 

クエリは、事前に計算された状態のリストをスキャンすることによって回答されます。 これはクエリごとに線形ですが、n ≤ 7 であるため、状態セットは非常に小さいため、依然として効率的です。 

## 実用的な例

 それぞれが他の 2 つを見えるように配置された 3 つのバンパーの小さな構成を考えてみましょう。 DFS は、最上部のバンパーから開始して、0 から 1、次に 1 から 2 などの状態を生成し、時間とスコアの両方を蓄積します。 各遷移により、新しい記録された状態が生成されます。 

| ステップ | 現在 | 前へ | 時間 | スコア |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 | s0 |
 | 2 | 1 | 0 | t01 | s0 + s1 |
 | 3 | 2 | 1 | t01 + t12 | s0 + s1 + s2 |

 このトレースは、到着時のみスコアが蓄積され、移行時のみ時間が増加する様子を示しています。 どのクエリでも、時間制約の下でこのテーブルの最適なプレフィックスを選択するだけです。 

次に、3 つのバンパーの間にサイクルが存在する 2 番目のケースを考えてみましょう。 DFS は、線形パスと、異なる以前の状態のノードを再訪することによって形成される循環状構造の両方を調査します。 

| ステップ | 現在 | 前へ | 時間 | スコア |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 | s0 |
 | 2 | 1 | 0 | t01 | s0 + s1 |
 | 3 | 0 | 1 | t01 + t10 | s0 + s1 + s0 |

 これは、前のノードの制約が重要である理由を示しています。 状態 (0,1) は (0,0) とは異なるため、ノードを再訪問することは制約に違反することと同等ではなく、別個の状態として扱う必要があります。

n の限界が小さいため、指数列挙も引き続き実行可能です。 実際には状態の数は少ないままであり、各クエリは事前に計算されたリストをスキャンすることによって回答されます。

 ## 特殊なケース

 重要なケースの 1 つは、開始バンパーからの動きが不可能な場合です。 その状況では、それ以上の状態に到達できないため、タイプ 1 のすべてのクエリは開始ノードのスコアのみを返す必要があります。 DFS は、遷移を試みる前に初期状態を記録するため、これを自然に処理します。 

もう 1 つのケースは、タイプ 2 のクエリが、指定された時刻以前に到達できないバンパーを要求する場合です。 この場合、その現在のバンパーを持つ状態は時間制約を満たさないため、答えは「#」でなければなりません。 これは、スキャン中に有効な状態が見つかったかどうかを追跡することによって処理されます。 

最後の微妙なケースは、直後の制限から生じます。 (a, b) と (b, a) のような状態は両方とも有効ですが、異なる履歴を表します。 DFS はそれらを明示的に分離し、違法な即時反転が決して導入されないようにしながら、中間ノードを経由するより長いサイクルを許可します。
