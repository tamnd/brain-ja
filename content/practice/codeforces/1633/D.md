 ## 問題の理解

 サイズの配列から始めるように求められます$n$ここで、すべての要素は最初は 1 です。各要素について$a_i$、フォームの操作を実行できます$a_i = a_i + \lfloor a_i / x \rfloor$、選択する$x > 0$私たちの好きなように。 各要素には目標値があります$b_i$そしてご褒美$c_i$。 私たちの目標は、いくつかの要素をターゲットとまったく同じにすることで、獲得できるコインの合計を最大化することです。$k$すべての要素にわたる合計操作。 

入力には複数のテスト ケースが含まれています。 各テスト ケースは配列サイズを指定します$n$、操作限界$k$、ターゲット配列$b$、コイン配列$c$。 各テストケースで取得できる最大コインを出力する必要があります。 

制約を見てみると、$n$まで可能です$10^3$と合計$n$すべてのテスト ケースで最大でも$10^3$、これは合計の要素数が少ないことを意味します。 しかし、$k$と同じ大きさにすることができます$10^6$したがって、単純に操作をシミュレートするアルゴリズムは遅すぎます。 各操作はそれ自体の関数によって要素を増加させます。$b_i \le 10^3$、任意の値に到達するまでの操作の数$b_i$境界があり、比較的小さいです。 これは、考えられる各ターゲットに到達するための最小操作数を 1 から事前計算できることを示唆しています。 

明らかではないエッジケースが発生するのは次の場合です。$k = 0$。 その場合、要素を増やすことはできないため、コインを提供する要素は対象の要素のみとなります。$b_i = 1$。 不用意に実装すると、チェックせずに操作を実行しようとする可能性があります。$k = 0$そしてゼロ以外の答えを返します。 もう 1 つのエッジケースは次のような場合です$b_i = 1$; 1 に到達するには操作がゼロであることを認識する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択肢をシミュレートします。$x$ターゲットに到達するまですべての要素に対して操作をカウントします。 単一の要素の場合$a_i$に到達するまでに必要な操作の数$b_i$までの可能性があります$b_i - 1$、各操作が増加するため、$a_i$少なくとも 1 まで。$n$要素を使用すると、最大で次のような問題が発生する可能性があります。$n \cdot 10^3$テスト ケースごとにシミュレートされた操作に、範囲を乗算したもの$x$, あっという間に制限時間を超えてしまいます。 

重要な観察は、1 から任意の値に到達するために必要な最小限の操作数が比較的少なく、依存関係がないことです。$k$。 のために$1 \le a_i \le 10^3$、配列を事前計算できます`ops_needed[val]`そのような`ops_needed[val]`到達するための最小操作数です`val`これは、BFS のようなアプローチで構築でき、1 から探索し、現在の値ごとに可能なすべての操作を適用します。$a_i + \lfloor a_i / x \rfloor$これにより、1000 までのすべての値に対する最小限の操作の表が得られます。 

各ターゲットの最小限の操作がわかったら$b_i$、問題は古典的な境界のあるナップザックの問題に帰着します。 各要素は次の重みを持つアイテムです。`ops_needed[b_i]`と等しい値`c_i`。 容量たっぷりのナップザックがあります$k$そしてコインの合計を最大化したいと考えています。 動的プログラミングの使用`k`効率的であるため、`k`まで可能です$10^6$ただし、すべての項目にわたる最小限の操作の合計ははるかに小さくなります。 具体的には、すべての合計`ops_needed[b_i]`テストケース全体では最大でも$n \cdot 12$1000 に達するまでに約 12 を超える操作を必要とする要素はないため、DP はオーバーします。`k`決して超えることのない最適化により、`k`うまくいきます。

 ## アルゴリズムのチュートリアル

 1. 1 から最大 1000 までの各値に到達するための最小操作数を事前計算します。操作が 0 で 1 を含むキューから開始します。 キュー内の値ごとに反復します`x`1 から現在の値まで。 次の値を次のように計算します。`next_val = cur + cur // x`。 もし`next_val`以前に到達したことがない場合は、その操作数を次のようにマークします`cur_ops + 1`そしてそれをキューに追加します。 1000 までの値がすべて入力されたら停止します。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、`b`、 そして`c`。 問題をナップザックに変換します。要素ごとに、`weight = ops_needed[b_i]`そして`value = c_i`。 
3. DP 配列を初期化する`dp[0..k]`から 0、ここで`dp[j]`最大で達成可能な最大コインを表します`j`操作。 
4. 要素ごとに繰り返します`j`から`k`まで`weight`。 アップデート`dp[j] = max(dp[j], dp[j - weight] + value)`。 逆方向に反復すると、各要素が最大 1 回使用されるようになります。 
5. すべての要素を処理した後、`dp[k]`最大で達成可能な最大のコインが含まれます`k`操作。 この値を出力します。 

機能する理由: 最小限の操作を事前に計算することで、各ターゲットに到達するための最小コストの方法が確実にわかります。 DP は、組み合わせた操作が予算内に収まる要素のサブセットを選択することを保証します。`k`コインを最大化しながら。 逆方向に反復すると、要素の二重カウントが防止され、0 ～ 1 のナップザック プロパティが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

# Precompute minimal operations to reach values from 1 to 1000
MAX_VAL = 1000
ops_needed = [float('inf')] * (MAX_VAL + 1)
ops_needed[1] = 0
queue = deque([1])
while queue:
    cur = queue.popleft()
    cur_ops = ops_needed[cur]
    for x in range(1, cur + 1):
        nxt = cur + cur // x
        if nxt <= MAX_VAL and ops_needed[nxt] > cur_ops + 1:
            ops_needed[nxt] = cur_ops + 1
            queue.append(nxt)

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))
    
    # Map b[i] to ops_needed, cap at k+1 (we cannot use more than k)
    weights = [min(ops_needed[val], k + 1) for val in b]
    
    dp = [0] * (k + 1)
    for w, v in zip(weights, c):
        if w > k:
            continue
        for j in range(k, w - 1, -1):
            dp[j] = max(dp[j], dp[j - w] + v)
    
    print(dp[k])
```事前計算セクションでは、各ターゲット値の演算数が最小限であることが保証されます。 BFS を使用すると、冗長な再計算が防止され、無限ループが回避されます。 重みをマッピングする`min(ops_needed[val], k + 1)`内部で到達できない要素を確実にスキップします。`k`操作。 ナップザック DP はサブセットの選択を処理します。 反復`j`逆方向では 0 ～ 1 の選択が保証されます。
