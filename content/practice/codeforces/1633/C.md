 ## 解決策
 ## 問題の理解

 問題は、Monocarp のキャラクターとモンスターの間のターンベースの戦闘シミュレーションです。 それぞれに初期体力と攻撃力があります。 各ターンでは、キャラクターが最初に攻撃し、現在の攻撃値だけモンスターの健康を減らし、その後モンスターが報復して、モンスターの攻撃によってキャラクターの健康を減らします。 これは、いずれかのヘルスがゼロまたはマイナスになるまで交互に繰り返されます。 目標は、Monocarp がキャラクターの攻撃や体力をアップグレードするために一定数のコインを費やして勝利を保証できるかどうかを判断することです。 

入力ではテスト ケースの数を指定します。 各テスト ケースについて、キャラクターの健康状態と攻撃力、モンスターの健康状態と攻撃力、利用可能なコインの数、および健康状態と攻撃のアップグレードに対するコインあたりの利益が与えられます。 出力は、勝利が達成可能かどうかを示す単純な YES または NO です。 

制約により、非常に大きな数が許可されます。キャラクターとモンスターの健康状態は最大で$10^{15}$、コインまで$2 \cdot 10^5$、および大規模なアップグレード$10^{10}$。 テストケースの数は次のとおりです。$5 \cdot 10^4$、ソリューションは、大まかに言って、各テスト ケースを効率的に処理する必要があります。$O(k)$あるいは、各ターンの単純なシミュレーションでは制限時間を超えてしまう可能性があるためです。 

明らかではないエッジケースには、キャラクターがアップグレードなしですでに勝っている状況、すべてのコインが最適に攻撃または体力に向かう必要がある状況、およびコインの数がゼロである状況が含まれます。 たとえば、次の場合$h_C = 1$、$d_C = 1$、$h_M = 1$、$d_M = 10$、 そして$k = 0$, Monocarp は 1 回の攻撃でも生き残ることができないため、正しい出力は NO です。 現在の統計を考慮せずに常にアップグレードを試行する単純なアプローチでは、誤って「YES」と報告される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、健康と攻撃のアップグレードの間でコインを分配するあらゆる方法を試みることです。 分布ごとに、一方が死ぬまでターンを繰り返すことで戦闘をシミュレートします。 これが機能するのは、アップグレードの各組み合わせが有効であり、シミュレーションがルールを正確に反映しているためです。 ただし、最悪のケースとしては、$k+1$試してみるディストリビューションと、最大での戦いのシミュレーション$10^{15}$健康は無理です。 単純にターン数を計算しても遅すぎます。 したがって、ブルートフォースは非現実的です。 

重要な洞察は、各攻撃をシミュレートすることなく、各側が生き残るターン数を数学的に計算できることです。 キャラクターがモンスターを倒す$\lceil h_M / d_C' \rceil$曲がる、どこで$d_C' = d_C + w \cdot x$そして$x$攻撃に費やしたコインの数です。 モンスターがキャラクターを殺す$\lceil h_C' / d_M \rceil$曲がる、どこで$h_C' = h_C + a \cdot (k - x)$健康のために費やしたコインのために。 キャラクターのターン数がモンスターのターン数以下の場合、Monocarp が勝ちます。 これにより、問題はチェックに減ります$k+1$テストケースごとの簡単な計算。 

したがって、攻撃と体力の間で考えられるすべてのコインの分割を反復し、整数演算を使用して各側を倒すまでのターン数を計算し、勝利を保証する分割が少なくとも 1 つあるかどうかを確認できます。 以来$k$せいぜい$2 \cdot 10^5$と合計$k$すべてのテストケースで次を超えない$2 \cdot 10^5$、このアプローチは効率的です。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k * max(h_M, h_C)) | お(1) | 遅すぎる |
 | 最適な数学 | テスト ケースごとの O(k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、キャラクターとモンスターの初期ステータス、コインの数とその利点を読み取ります。 
2. コイン 0 から攻撃まで、攻撃と体力の間でコインを分配するすべての可能な方法をループします。$k$。 
3. 各分割について、新しい攻撃を計算します。$d_C' = d_C + w \cdot x$そして新しい健康$h_C' = h_C + a \cdot (k - x)$。 
4. キャラクターがモンスターを倒すのに必要なターン数を次のように計算します。$\text{turns}_C = \lceil h_M / d_C' \rceil$。 
5. モンスターがキャラクターを倒すのに必要なターン数を次のように計算します。$\text{turns}_M = \lceil h_C' / d_M \rceil$。 
6. もし$\text{turns}_C \le \text{turns}_M$どの分割についても、このテスト ケースでは直ちに YES と結論付けます。 それ以外の場合は、すべての分割を確認した後、「いいえ」と結論付けます。 
7. 各テスト ケースに対して YES または NO を出力します。 

機能する理由: 可能なすべてのコインの分布を反復処理し、生存時間を数学的に計算することで、すべての最適なアップグレードが考慮されることを保証します。 戦闘ターンは決定的で厳密に減少するため、ターン数の比較によって結果が正しく決まります。 ループオーバー$k+1$あらゆる最適な組み合わせを捕捉するには十分な可能性があるため、有効な勝ちの分配が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

t = int(input())
for _ in range(t):
    hC, dC = map(int, input().split())
    hM, dM = map(int, input().split())
    k, w, a = map(int, input().split())
    
    possible = False
    for coins_attack in range(k + 1):
        coins_health = k - coins_attack
        new_attack = dC + coins_attack * w
        new_health = hC + coins_health * a
        
        turns_to_kill_monster = (hM + new_attack - 1) // new_attack
        turns_to_survive = (new_health + dM - 1) // dM
        
        if turns_to_kill_monster <= turns_to_survive:
            possible = True
            break
    
    print("YES" if possible else "NO")
```このソリューションはまず、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 テスト ケースごとに、すべてのコインの分布を反復し、結果として得られる攻撃力と体力を計算し、整数演算による天井除算を使用してターン数を計算します。 不必要な計算を避けるために、勝ちの分布が見つかるとループは直ちに中断されます。 アップグレードなしを含むすべてのディストリビューションがテストされるため、コインがゼロ、アップグレード値がゼロ、またはすでに十分な統計情報などのエッジ ケースは自然に処理されます。
