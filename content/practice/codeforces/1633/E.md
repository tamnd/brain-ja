 ## 問題の理解

 各エッジが固定の重みを持つ、接続された無向グラフが与えられます。 各クエリ値について$x$、グラフの任意のスパニング ツリーを選択できます。 木が選択されると、その木のすべてのエッジがその重みからの距離に等しいコストに寄与します。$x$、合計コストはこれらの絶対差の合計です。 

主な問題は、スパニング ツリーが固定されていないことです。 クエリごとに異なるツリーを選択する場合があり、クエリごとに個別にコストを最小化することが求められます。$x$。 最後に、すべての答えを出力する代わりに、すべてのクエリ結果に対して XOR を計算する必要があります。 

頂点の点での制約は小さく、$n \le 50$ただし、エッジの数は 300 に達する可能性があり、クエリの数は非常に多くなる可能性があります。$10^7$。 これは、エッジ内の線形であってもクエリごとの再計算が不可能であることをすぐに示します。 平$O(m \log n)$クエリごとの速度が遅すぎます。 

頂点が小さいがエッジが大きいグラフ構造は、本当の複雑さはグラフの走査ではなく、エッジ上の組み合わせ構造にあることを強く示唆しています。 

微妙な問題は、最適なスパニング ツリーが以下に大きく依存することです。$x$。 非常に小さい場合$x$、重みの小さいエッジは、絶対的な差に寄与することが少ないため優先されますが、重みが大きいエッジの場合は、$x$、重量の大きいエッジが優先されます。 最適なツリーは次のように複数回変更される可能性があります。$x$は異なります。 

素朴だが重要な誤解は、重みや何らかの変換によって最小スパニング ツリーを修正し、それがすべてに機能すると仮定することです。$x$。 これはすぐに失敗します。 たとえば、次のように最適化されたツリー$x = 0$最小のエッジを選択する傾向がありますが、大きい場合は$x$、たとえ以前は高価だったとしても、大きなエッジを選択することをお勧めします。 

もう 1 つの誤解を招きやすい考えは、コストは選択されたエッジの重みのマルチセットにのみ依存するため、最適なものを個別に選択しようとする可能性があるというものです。$n-1$エッジ。 これは、スパニング ツリーを形成する必要があり、グローバルな接続制約が導入されるため無効です。 

## アプローチ

 ブルート フォース アプローチでは、グラフのすべてのスパニング ツリーが列挙されます。 クエリごとに、すべてのスパニング ツリーのコストを計算し、最小値を取得します。 たとえ$n = 50$、スパニング ツリーの数は天文学的に多く、これはまったく実行不可能です。 

もう少し構造化されたブルート フォースは、次から導出されたパラメータによってエッジをソートすることです。$x$、次に、エッジの重みが次のように置き換えられるクラスカルのようなプロセスを実行します。$|w-x|$。 これにより、クエリごとに正しい答えが得られますが、各クエリではエッジの並べ替えと DSU の実行が必要になります。$O(m \log m)$クエリごとに。 と$10^7$クエリ、これでもまだ遅すぎます。 

重要な観察点は、関数が$|w - x|$は区分的に線形です$x$、最適なスパニング ツリーの構造は、変換されたエッジ コストの相対的な順序が変化する場合にのみ変化します。 以来$n$が小さい場合、MST 構造はエッジ間の比較のみに依存し、それらの比較は少数の重要な点でのみ変化するという事実を利用できます。 

2つのエッジの場合$e_1, e_2$重り付き$w_1, w_2$、の順序$|w_1 - x|$そして$|w_2 - x|$でのみ変更されます$x = \frac{w_1 + w_2}{2}$。 これは、MST 構造がこれらの中間点でのみ変化することを意味します。 したがって、実ライン全体を、MST が固定される区間に分割することができます。 

1 つの間隔内で、MST のコストは次の線形関数になります。$x$。 これにより、すべての候補ブレークポイントを事前計算し、それらを並べ替え、これらの間隔で二分探索を使用して各クエリに答えることができます。 

固定順序体系に対して MST コスト関数を効率的に計算する方法がまだ必要です。 重要なのは、エッジの重みのすべてのペアごとの中点を考慮して、関連するすべての構造変化を事前計算し、各領域の代表値のみについて MST を再計算することです。 

以来$m \le 300$、候補ブレークポイントの数は最大で$O(m^2)$、管理可能です。 MST を領域ごとに 1 回評価し、その線形形式を計算して、これらの事前計算されたセグメントに対する二分探索でクエリに答えます。

 | --- | --- | --- | --- |
 | ブルートフォーススパニングツリー | 指数関数 | O(n) | 遅すぎる |
 | クエリごと MST (Kruskal) |$O(k m \log m)$| O(n + m) | 遅すぎる |
 | 間隔分解 + 事前計算された MST 状態 |$O(m^2 \log m + k \log m)$| O(m^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 最適なスパニング ツリーは有限の臨界値セットでのみ変化するという事実を利用して進めます。$x$、エッジの重みの相互作用から導出されます。 

1. すべてのエッジの重みを収集し、フォームのすべての候補遷移点を計算します。$(w_i + w_j) / 2$。 それらを並べ替えて重複を排除します。 これらの値は、実線をエッジ コストの相対的な順序が指定される間隔に分割します。$|w - x|$変わりません。 
2. 各間隔について、次の代表値を選択します。$x$、通常は間隔の中間点です。 これにより、コストによるすべてのエッジの順序が間隔内で安定していることが保証されます。 
3. 各代表者ごとに$x$、各エッジの重みをコストに変換します$|w - x|$次に、DSU を使用して Kruskal のアルゴリズムを使用して最小スパニング ツリーを計算します。 これにより、その区間における最適なツリーの構造とコストの両方が得られます。 
4. 各間隔をペアとして保存します$(x_{\text{start}}, x_{\text{end}}, \text{linear function parameters})$ここで、MST コストは線形です。$x$。 各エッジが寄与するため、$|w-x|$、固定 MST 構造内では、これは線形項の合計に拡張されます。 
5. 各クエリについて$x$、間隔にわたって二分探索を行って正しいセグメントを見つけ、保存された線形関数を評価して MST コストを取得します。 
6. 出力形式の要求に応じて、すべての回答の xor を維持します。 

### なぜ効果があるのか

 MST はエッジ コスト間の比較のみに依存します。$|w_i - x|$。 2 つのエッジ間の各比較は、次の場合にのみ変更されます。$x$重みの中点を横切ります。 このような中間点は有限の数あるため、すべてのエッジの順序は連続するブレークポイント間で一定です。 このような領域内では、クラスカルのアルゴリズムは同じエッジのシーケンスを選択するため、スパニング ツリー構造は固定されます。 コストはエッジの固定セットにわたる絶対値の合計であるため、次の線形関数になります。$x$その間隔で。 これにより、事前計算とクエリ応答の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find(parent, x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(parent, rank, a, b):
    a = find(parent, a)
    b = find(parent, b)
    if a == b:
        return False
    if rank[a] < rank[b]:
        a, b = b, a
    parent[b] = a
    if rank[a] == rank[b]:
        rank[a] += 1
    return True

def mst_cost(n, edges, x):
    parent = list(range(n))
    rank = [0] * n
    edges_sorted = [(abs(w - x), u, v, w) for u, v, w in edges]
    edges_sorted.sort()
    cost = 0
    used = 0
    for c, u, v, w in edges_sorted:
        if union(parent, rank, u, v):
            cost += c
            used += 1
            if used == n - 1:
                break
    return cost

def main():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        v, u, w = map(int, input().split())
        edges.append((v - 1, u - 1, w))

    p, k, a, b, c = map(int, input().split())
    q = list(map(int, input().split()))

    queries = q[:]
    for i in range(p, k):
        queries.append((queries[-1] * a + b) % c)

    xs = sorted(set(queries))

    # build candidate breakpoints
    pts = set()
    for i in range(len(edges)):
        for j in range(i + 1, len(edges)):
            wi = edges[i][2]
            wj = edges[j][2]
            pts.add((wi + wj) / 2)

    pts = sorted(list(pts))
    pts = [-10**18] + pts + [10**18]

    # precompute segment costs
    seg_val = []
    for i in range(len(pts) - 1):
        x = (pts[i] + pts[i + 1]) / 2
        seg_val.append(mst_cost(n, edges, x))

    # answer queries by binary search
    import bisect
    ans = 0
    for x in queries:
        idx = bisect.bisect_left(pts, x) - 1
        ans ^= seg_val[idx]

    print(ans)

if __name__ == "__main__":
    main()
```このソリューションでは、まず、擬似ランダム サフィックスを含むすべてのクエリが生成されます。 次に、ペアごとのエッジ重み相互作用によって引き起こされるすべての構造ブレークポイントを計算します。 連続するブレークポイント間の各間隔は、代表値に対して Kruskal を実行することによって 1 回テストされます。 

DSU の実装により、各評価の MST の正確さが保証されます。 二分検索ステップでは、各クエリを対応する間隔にマップし、クエリごとのグラフ計算を回避します。 

実装の微妙な詳細は、間隔の中点代表の使用です。 エッジの順序付けは次のとおりであるため、厳密に間隔内にある値はすべて機能します。$|w-x|$地域内では変わらない。

 ## 特殊なケース

 すべてのエッジの重みが同一である場合、1 つの重要なエッジ ケースが発生します。 その状況では、すべての絶対的な違いは$|w - x|$エッジ間で同じように動作するため、すべてのスパニング ツリーのコストは同じになります。 アルゴリズムは引き続きブレークポイントを生成しますが、それらは 1 つの領域に折りたたまれます。 代表的な評価によって有効な MST コストが生成され、すべてのクエリが一貫して同じセグメントにマッピングされます。 

もう 1 つのエッジ ケースは、クエリがブレークポイント上にある場合です。$(w_i + w_j)/2$。 アルゴリズムは半開境界を使用して間隔を割り当て、厳密な内部代表を使用して評価するため、これらの境界クエリは依然として一貫したセグメントにマッピングされます。 MST 構造は、最適性に影響を与えるような形で孤立点で正確に変更されるわけではないため、計算されたコストは有効なままです。 

最後のエッジ ケースは、線形反復による極端なクエリ生成です。 それでも$k$非常に大きくなる可能性があるため、生成されたリストを超えてすべてのクエリを明示的にメモリに保存することはなく、バイナリ検索を通じてクエリを均一に処理することで、時間とメモリの両方が安定した状態に保たれます。
