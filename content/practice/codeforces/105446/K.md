 ## 解決策
 ## 問題の理解

 ニットスカーフを表す部分的に構築されたシーケンスが与えられます。 各位置は色であり、スカーフのいくつかの接頭辞はすでに固定されています。 私たちのタスクは、このプレフィックスを完全な長さのシーケンスに拡張することです。`n`～の色を使用して`1`に`k`、間隔の制約を尊重しながら: ある色がどこかの位置に現れた場合、その色は次の位置で再び現れてはなりません。`p - 1`ポジション。 

同時に、すべての有効な補完の中で、単一色の最大頻度を可能な限り小さく保ちたいと考えています。 言い換えれば、最近の繰り返しを防ぐ厳しい制約の下で、可能な限り均等に色の使用のバランスをとっているということです。 

入力によりターゲットの長さが与えられます`n`、色の数`k`、間隔要件`p`、すでに構築されたプレフィックス長`m`、そして最初に固定`m`色。 このプレフィックスを完全な有効なシーケンスに拡張するか、補完が存在しないことを報告する必要があります。 

制約により許可されるのは、`n, k, p`最大 100000 で、二次構築やシーケンスの完全な再スキャンの繰り返しが除外されます。 逆スキャンして各配置の有効性をチェックしようとするアプローチ`p`単純に位置を指定すると、最悪の場合、O(n・p) に劣化するため、速度が非常に遅くなります。 位置ごとに定数または対数の仕事が必要です。 

いくつかのエッジケースは、単純な貪欲な試みを打ち破ります。 

もし`p = 1`、制限がないため、どの補完も有効であり、周波数のバランス調整は純粋に配布に関するものになります。 

もし`k = 1`そして`p > 1`の場合、唯一の色がすぐに間隔に違反するため、1 より長いシーケンスは不可能になります。 例：`n = 5, k = 1, p = 2`とプレフィックス`[1]`距離 1 内での繰り返しを強制するため、出力は不可能です。 

プレフィックスが既に内部的に制約に違反している場合は、直ちにそれを拒否する必要があります。 例：`p = 3`、プレフィックス`[1, 2, 1]`はすでに無効です。 

最後に、貪欲な拡張機能がローカルで有効な色を選択したものの、後でスペースの制約によりすべてのオプションがブロックされる場合、微妙な失敗ケースが発生します。 これは、各色の将来の配置の可用性を考慮していない場合に発生します。 

## アプローチ

 強引なアイデアは、シーケンスを位置ごとに構築することです。 各ステップですべての色を試します`1..k`、前のファイルをスキャンして、間隔の制約に違反しているかどうかを確認します。`p-1`位置を決めて仮割り当てします。 これは制約を直接適用するため正しいですが、位置ごとに O(k・p) のコストがかかるため、O(n・k・p) となり、100,000 スケールの入力には大きすぎます。 

各チェックが O(1) になるように、最後に表示された配列を使用して有効性チェックを最適化したとしても、各ステップでどの有効な色を選択するかを決定する戦略が必要です。 現在の周波数が最小の色を選択する単純な貪欲なアプローチは、色を割り当てるのが早すぎて、間隔のギャップにより後で使用できなくなる可能性があるため、失敗する可能性があります。 

重要な観察は、間隔制約がローカルであり、最後の制約にのみ依存するということです。`p - 1`一方、バランシングの目標はグローバル カウントのみに依存します。 この分離により、2 つの構造を維持することができます。1 つは最近の使用状況を追跡する (実現可能性を強化するため)、もう 1 つは頻度を追跡する (配布のバランスを取るため) ことです。 各ステップで、現在許可されており、許可された候補の中で頻度が最も少ない色を選択する必要があります。 

これをサポートする効率的な方法は、色ごとにその最後の出現インデックスを維持し、頻度配列を維持することです。 また、現在有効な色の中から頻度が最も少ない色を素早く検索できる構造も保持しています。 以来`k`大きくなる可能性があるため、次の順序で候補を格納する優先キューを使用してこれをシミュレートします。`(frequency, color)`、無効なエントリがスペースに違反する場合は、遅延して破棄します。 

これにより、各色が制限された回数プッシュおよびポップされるため、各配置が償却 O(log k) に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・k・p) | O(n) | 遅すぎる |
 | 最適 | O(n log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 常にプレフィックスを尊重して、シーケンスの構築を左から右へのストリーミング プロセスとして扱います。 

1. 配列を初期化する`last[c] = -inf`それぞれの色ごとに`c`、周波数を設定します`freq[c] = 0`。 また、指定されたプレフィックスを最初に処理し、両方の配列を更新し、スペース違反がすでに存在しないことを確認します。 違反が見つかった場合は直ちに停止させていただきます。 
2. すべての色を含む優先キューを構築します。 各エントリーストア`(freq[c], c)`。 ヒープは常に最も使用されていない色を提案します。 
3. 位置から反復する`m+1`に`n`、それぞれの位置で、有効な色を選択する必要があります。 
4. 色が見つかるまで繰り返しヒープから取り出します`c`そのような`i - last[c] >= p`。 この条件により、その色は最後に使用されなくなります。`p - 1`ポジション。 そのような色が存在しない場合、構築は不可能であると判断されます。 
5. 有効な色が見つかったら、それを位置に割り当てます。`i`、 アップデート`last[c] = i`、増分`freq[c]`、更新されたペアをヒープにプッシュして戻します。 
6. すべてのポジションが埋まるまで続けます。 

重要な考え方は、ヒープが常に周波数のバランスを保とうとする一方で、フィルタリング ステップが実現可能性を強制するということです。 

### なぜ効果があるのか

 どの段階でも`i`、間隔制約によって許可されるすべての色の中で、常に最小の頻度を持つ色が選択されます。 それ以外の選択をすると、最大周波数を変更しないままにするか、必要よりも早く増加させることになり、後のバランス調整が難しくなるだけです。 間隔制約は適格性を制限するだけであり、適格な色間の順序を制限するものではないため、有効な候補間で頻度によって並べ替えることで正確さが保たれます。 

不変条件は、位置を配置する前の条件です。`i`、部分シーケンスは間隔制約を満たしており、ヒープには正しい頻度を持つすべての色が含まれています。 すべての割り当てでは両方のプロパティが保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, k, p = map(int, input().split())
    m = int(input())
    s = list(map(int, input().split()))

    last = [-10**18] * (k + 1)
    freq = [0] * (k + 1)

    # validate prefix
    for i, c in enumerate(s, start=1):
        if i - last[c] < p:
            print("impossible")
            return
        last[c] = i
        freq[c] += 1

    heap = []
    for c in range(1, k + 1):
        heapq.heappush(heap, (freq[c], c))

    def push(c):
        heapq.heappush(heap, (freq[c], c))

    for i in range(m + 1, n + 1):
        while heap:
            f, c = heapq.heappop(heap)
            if f != freq[c]:
                continue
            if i - last[c] >= p:
                break
        else:
            print("impossible")
            return

        s.append(c)
        last[c] = i
        freq[c] += 1
        push(c)

    print(*s)

if __name__ == "__main__":
    solve()
```この解決策は、指定されたプレフィックスを検証することから始まります。 初期に無効なスペースがあると、将来の選択に関係なく全体を完了することが不可能になるため、このステップは不可欠です。 

ヒープには、現在の頻度に従って順序付けされたすべての色が保存されます。 遅延削除を使用します。古いエントリはヒープ内に残りますが、ポップされると無視されます。 これにより、コストのかかる減少キー操作が回避されます。 

構築中に、最も頻度の低い色を繰り返し抽出し、それが間隔制約を遵守しているかどうかをチェックします。`last[c]`。 そうでない場合は、この反復ではそれを破棄して続行します。 

微妙な点の 1 つは、周波数が変化してもヒープを使用することが正しいかどうかです。 の`(f, c)`ペアが古くなってしまう可能性があります。 これが比較する理由です`f != freq[c]`使用する前に。

 ## 特殊なケース

 すでにスペースに違反しているプレフィックスはすぐに拒否されます。 たとえば、`p = 3`、入力`[1, 2, 1]`2番目の理由で失敗します`1`最初に比べて発生が早すぎます。 アルゴリズムは、次の場合にプレフィックスの前処理中にこれを検出します。`i - last[c] < p`。 

単色システム`p > 1`長さ 1 を超えると不可能になります。その色のすべてのポップが間隔チェックに失敗し、代替が存在しないため、アルゴリズムは最終的にヒープを使い果たします。 

いつ`p = 1`、すべての色が常に有効です。 ヒープは周波数のバランスを取るだけであり、間隔チェックでは候補をブロックしないため、アルゴリズムは純粋な負荷分散に退化します。
