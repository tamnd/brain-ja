 ## 解決策
 ## 問題の理解

 英語の小文字で構成される 2 つの文字列が与えられており、文字の多重度の点で両方を「カバーする」3 番目の文字列を構築したいと考えています。 具体的には、文字が最初の単語に 5 回、2 番目の単語に 2 回出現する場合、同じ複数の文字セットを使用して両方の単語を同時に表現できなければならないため、結果の文字列にはその文字が少なくとも 5 回出現する必要があります。 

目標は、そのような文字列を可能な限り短い長さで作成することです。 文字の順序は正確性とは無関係であるため、結果として得られるマルチセットの順列は許容されます。 

入力サイズは文字列あたり 100 万文字に達する可能性があるため、文字列の繰り返しの連結、完全な展開での並べ替えベースのマージ、または一方の文字列をもう一方の文字ごとに 1 回スキャンするアプローチなどの二次的な動作は直ちに排除されます。 唯一実行可能な方向は、アルファベットを直線的にカウントすることです。 

マルチセットではなくシーケンスのマージという観点から考えると、微妙な問題が生じます。 たとえば、2 つの単語がまったく文字を共有していない可能性があり、それらを「インターリーブ」しようとする単純なアプローチでは、文字ごとの最大頻度のみを考慮することを認識せず、誤って構造を保持しようとします。 

2 番目のエッジ ケースは、両方の単語が同一である場合です。 この場合、答えはまったく同じ単語となり、両方の入力を盲目的に連結するアルゴリズムでは長さが不必要に 2 倍になります。 

最後に、順序は関係ありませんが、正確さは文字ごとの頻度の比較に完全に依存するため、処理中にカウント情報が失われるアプローチは失敗します。 

## アプローチ

 総当りの解釈では、結合されたマルチセットのすべての順列を生成し、両方の単語をサブマルチセットとして含む条件をどれが満たすかを確認し、最も短い有効なものを選択します。 順列を避け、代わりに段階的に候補を構築することを考えたとしても、配列を介した検索は文字数の要因で増加し、たとえ小さな入力であっても完全に実行不可能になります。 

もう少し構造化された総当り攻撃のアイデアは、文字を繰り返し追加し、現在のマルチセットが両方の入力マルチセットを支配しているかどうかを確認することによって結果を構築してみることです。 問題は、すべての有効性チェックに頻度テーブルのスキャンが必要であり、候補拡張ごとに実行すると、総コストが生成された候補の数と 26 回の比較に比例することです。 最終的な長さ N に制限したとしても、このような増分構築では、順序付けの選択肢に対する指数関数的な検索空間が依然として隠蔽されますが、順序付けは実現可能性に影響を与えないため、これは不必要です。 

重要な観察は、問題は文字の配置に関するものではなく、26 次元の周波数空間における座標に関する最大制約を満たすことに関するものであるということです。 各単語はアルファベット上のカウントのベクトルを定義し、有効な最小アマルグラムは単にこれら 2 つのベクトルの点ごとの最大値です。 これが分かると、問題は文字列ごとに 1 回文字をカウントし、各文字の必要な数を出力することになります。

 ## アルゴリズムのチュートリアル

 各文字列を 26 個の小文字の頻度マップとして扱います。 

1. アレイを構築する`fa`サイズは 26 で、最初の文字列内の各文字の出現をカウントします。 これにより、最初の単語で各文字が何回必要になるかが正確に捕捉されます。 
2. 2 番目のアレイを構築する`fb`2番目の文字列についても同様に行います。 これにより、2 番目の単語の要件が独立して分離されます。 
3. 結果の頻度配列を構築する`fc`各文字のインデックスはどこにありますか`i`、設定しました`fc[i] = max(fa[i], fb[i])`。 このステップでは、各文字がいずれかの単語に少なくとも必要な頻度で出現するため、結果として得られるマルチセットから両方の単語を形成できるという要件が強制されます。 
4. 26 文字すべてを繰り返し、各文字を追加します`i`繰り返された`fc[i]`出力文字列に倍します。 多重度のみが正確であるかどうかがチェックされるため、発行の順序は重要ではありません。 
5. 結果の文字列を出力します。 

唯一の微妙な点は、入力の順序を決して保持しようとしないことです。 この問題はサブシーケンスや埋め込みを必要とせず、マルチセットの包含のみを必要とするため、最終的なマルチセットの順列はすべて有効です。 

### なぜ効果があるのか

 各入力単語は制約を定義します。すべての文字に対して、結果には少なくともその数のコピーが必要です。 これらの制約は文字間で独立しているため、実行可能なセットは 26 個の単純な下限の交差になります。 すべての制約を満たす最小の文字列は、各境界をできるだけ厳密に取得することによって実現されます。これは、正確に 2 つの周波数ベクトルの座標上の最大値です。 選択したカウントを減らすと、2 つの単語のうちの少なくとも 1 つに違反するため、構築は最小限で済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = input().strip()
    b = input().strip()

    fa = [0] * 26
    fb = [0] * 26

    for ch in a:
        fa[ord(ch) - 97] += 1
    for ch in b:
        fb[ord(ch) - 97] += 1

    res = []
    for i in range(26):
        cnt = fa[i] if fa[i] > fb[i] else fb[i]
        if cnt:
            res.append(chr(i + 97) * cnt)

    sys.stdout.write("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、入力の解析とカウントが分離され、各文字列が正確に 1 回スキャンされるようになります。 固定サイズの配列を使用すると、ディクショナリのオーバーヘッドが回避され、入力サイズにおいて演算が厳密に線形に保たれます。 

構築フェーズは 26 文字を超えて反復されますが、これは入力の長さに比べれば無視できるものであり、文字列の再構築が繰り返されるのを避けるために連結は最後に 1 回行われます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の文字列が同一である場合です。 のような入力の場合`aaaaa`そして`aaaaa`、両方の周波数配列が同一であるため、最大演算では同じカウントが保存され、出力は 2 倍ではなく、まったく同じマルチセットになります。 このアルゴリズムはカウントを合計することはなく、比較のみを行うため、自然に重複を回避します。 

もう 1 つのケースは、次のような完全にバラバラなアルファベットです。`abc`そして`xyz`。 周波数配列は決してオーバーラップしないため、最大値は単に独立した寄与を連結するだけです。 出力には 6 文字すべてが 1 回含まれますが、これは削減できないため最小限です。 

3 番目のケースには、次のような歪んだ周波数分布が含まれます。`aaaaab`そして`abbbb`。 ここでは、最大値は 5 つが正しく保存されます。`a`キャラクターと4人`b`周波数ベクトル内の各位置が独立して処理されるため、文字の過少カウントと不必要な繰り返しの両方が回避されます。
