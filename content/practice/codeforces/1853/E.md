 ## 問題の理解

 の行が与えられています`n`タコ、それぞれの健康値は次のとおりです。`1`そして`k`。 目標はすべてのタコを健康にすることです`k`。 私たちは、隣接する範囲のタコの健康を減らす岩を投げることができます。`1`。 ただし、タコの体力が低下すると、`0`、すぐに再生されます`k`。 課題は、必要な岩の数を最小限に抑えることです。 

データの観点から見ると、入力は配列です`a`長さの`n`、各ボルダーは、連続する部分配列を次のように削減することに対応します。`1`。 出力はテスト ケースごとに 1 つの整数であり、必要なボルダーの最小数を表します。 

制約は厳しいです:`n`到達できる`2 × 10^5`すべてのテストケースにわたって、`k`と同じ大きさにすることができます`10^9`。 これにより、各ボルダー アプリケーションの強引なシミュレーションが除外されます。これは、単純に実行すると数十億の操作が必要になる可能性があるためです。 この問題では、段階的なシミュレーションではなく、全体的な健康状態の減少について推論する必要があります。 

考慮すべきエッジケースには、一部のタコがすでに健康状態にあるシーケンスが含まれます`k`(岩は必要ありません) または健康なタコが出現するシーケンス`1`交互の位置に出現し、複数の小さな岩を強制する可能性があります。 

不用意にアプローチすると、可能な限り最大の範囲に繰り返し岩を投げようとする可能性がありますが、体力がリセットされるため、`k`打つとき`0`、これは冗長なスローにつながる可能性があります。 たとえば、`n = 3, k = 3, a = [1,2,1]`単純に 3 つのタコすべての上に 1 つの岩を投げても、最初の投げで体力が減少するため、最適化は達成されません。`[3,1,3]`、まださらなるアクションが必要です。 

## アプローチ

 ブルート フォース ソリューションは、各ボルダー アプリケーションを明示的にシミュレートします。 体力が以下のタコを少なくとも 1 匹含む範囲を繰り返し選択することができます。`k`その範囲内のすべての値を減らします。 投げるたびに、アルゴリズムはゼロに達したタコをチェックし、その健康状態を次のようにリセットします。`k`。 これは正しいですが、遅すぎます。 それぞれの投げが影響する場合`n`タコと、最大で必要になるかもしれません`k`タコごとのスロー数、複雑さは到達する可能性があります`O(n * k)`、これは大規模な場合には不可能です`k`。 

最適な解決策を明らかにする重要な観察は、_reduction distances の剰余のみが存在することです。`k`_ 案件。 タコに健康があると仮定します。`a_i`。 必要です`(k - a_i)`到達するまでの減少数`k`（回り込みを考慮して）。 岩を左から右に投げる場合、以前の投げの効果は蓄積された「オフセット」として追跡できます。 最適な戦略は貪欲です。まだ到達していない左端のタコに岩を投げます。`k`、ヘルスをリセットするタコにぶつからないように、岩をできるだけ右に伸ばします。 左から右にスキャンし、必要なときに常にスローを適用することで、最小限のスローが保証されます。

 | 最適な貪欲さ | O(n) | テスト ケースごとに O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`throws = 0`そして変数`current_offset = 0`これは、現在の位置に影響を与える岩を投げた回数を追跡します。 
2. タコを左から右に繰り返します。 
3. 位置にある各タコについて`i`、前のスロー後の有効なヘルスを計算します。`effective = (a[i] + current_offset) % k`。 もし`effective == k`、次のタコに移動します。 
4. もし`effective < k`、新しい岩が必要です。 インクリメント`throws`による`1`。 
5. 値を大きくしてボルダー効果を適用します。`current_offset`による`(k - effective)`。 これにより、現在のタコが確実に到達します`k`。 
6. 次のタコに進みます。`current_offset`。 
7. 反復の後、`throws`必要な最小限の岩の数です。 

機能する理由: 貪欲なアプローチは、各岩の後に現在の位置のタコが到達するという不変条件に依存しています。`k`すぐに、そしてそれ以上の岩がその体力を低下させることはありません`k`。 ボルダーを可能な限り延長する (オフセットを運ぶ) ことで、冗長なスローを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        throws = 0
        current_offset = 0
        
        for health in a:
            effective = (health + current_offset) % k
            if effective == 0:
                continue
            needed = k - effective
            throws += 1
            current_offset += needed
        
        print(throws)

if __name__ == "__main__":
    solve()
```このループは、前の岩を通過した後の各タコの有効な健康状態を計算します。 タコがすでにいる場合`k`前のスローを考慮した後、それをスキップします。 それ以外の場合は、それを達成するためにさらに何回削減する必要があるかを計算します。`k`、スロー数をインクリメントし、オフセットを累積します。 これにより、再計算の繰り返しが回避され、ヘルスリセットによるラップアラウンドが正しく処理されます。

 最小限の健康状態と最大の健康状態を交互に切り替える場合は、次のようになります。`[1, k, 1, k]`、アルゴリズムは最初に岩を投げます。`1`次の場所に届くまでそれを運びます`k`、その後、新しいボルダーを開始します。 これにより、スローが最小限に抑えられます。 オフセットの蓄積により、タコがすでに`k`不要な追加の岩を避けてスキップされます。 このメソッドは、oct をスキップして単一要素配列を処理します。
