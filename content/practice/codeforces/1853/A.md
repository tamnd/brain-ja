 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、非常に構造化された方法で、選択した分割点の右側から左側に値をシフトする操作を繰り返し適用できます。 各操作ではインデックスが選択され、左側のすべての要素が 1 ずつ増加し、右側のすべての要素が 1 ずつ減少します。 

目的は、配列をソートすることではありません。 代わりに、ソートされた配列またはソートされていない配列から開始し、配列が非減少ではなくなる状態に到達するために必要なそのような操作の最小数を知りたいと考えます。 

したがって、タスクは基本的に、「非常に具体的なグローバル変換を使用して、ソートをいかに早く解除できるか」ということになります。 

合計に関する制約$n \le 500$テストケース全体にわたって、余裕があることを意味します$O(n^2)$快適に解決します。 立体的またはそれ以下のものは不要ですが、それでも技術的にはギリギリ安全です。 ただし、構造は、テスト ケースごとに線形またはほぼ線形のソリューションが期待されることを示唆しています。 

重要な点は、配列が最初からすでにソートされていない可能性があることです。その場合、操作は必要ありません。 もう 1 つの重要なケースは、配列が最初はソートされているものの「かろうじて」ソートされている場合です。つまり、どこかで反転を強制できるかどうかによって、1 回の操作で十分かどうかが異なる場合があります。 

素朴な誤解は、違反が現れるまで操作をシミュレーションする必要があると考えることです。 これは、各操作がすべての要素にグローバルに影響を及ぼし、単純なシミュレーションの仮定をすぐに破壊するため、失敗します。 もう 1 つの間違いは、答えが局所的な隣接差のみに依存すると仮定することです。 実際には、この操作はすべての接頭辞と接尾辞の関係に同時に影響します。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての分割シーケンスで操作を適用することをシミュレートします。 各操作はインデックスによって定義されるため、$n-1$動きごとの選択肢。 長さのすべてのシーケンスを試す$k$につながる$(n-1)^k$飛躍的に広がる可能性。 段階的にシミュレートし、各操作の後に並べ替えをチェックしようとしても、すべての可能性に対して繰り返し実行すると、依然としてコストがかかります。 

しかし、重要な観察によってすべてが単純化されます。私たちは任意の状態に到達しようとしているのではなく、単調性を打破しようとしているだけです。 つまり、何かが存在する最初の瞬間だけを気にするのです。$i$そのような$a_i > a_{i+1}$。 

各操作はカット全体で右から左に質量をシフトし、プレフィックスとサフィックスに対する相対的な効果は線形で均一です。 これは、配列内のどこかにどれだけ早く降下を作成できるかが重要であることを意味します。 

すべての操作をシミュレートする代わりに、隣接する要素間の違いがどのように変化するかを推論できます。 位置での各操作$i$すべてのプレフィックス要素を増やし、すべてのサフィックス要素を減らすため、分割がペアの前、後、または内側のいずれであるかに応じて、隣接するすべてのペアが予測可能な方法で影響を受けます。 

重要な単純化は、違反を強制できる最も早い場所が答えを決定するということです。 何らかの反転を表示するために必要な操作の数だけを考慮する必要があり、これは隣接する要素間の最小ギャップに対する可能な限り最良の分割効果を分析することに帰着します。 

最適な解決策は、隣接するペアの順序を減らすために必要な最小操作数に依存します。

 ## アルゴリズムのチュートリアル

 1. まず、配列がまだソートされていないことを確認します。 インデックスが存在する場合$i$そのような$a_i > a_{i+1}$の場合、操作は必要なく、答えは 0 になります。これは、ターゲット条件の直接の解釈です。 
2. 配列がソートされている場合は、次のように定義される、隣接する要素間の最小ギャップを計算します。$a_{i+1} - a_i$みんなのために$i$。 これは、配列がソートされていない状態にどれだけ「近づいているか」を測定します。 
3. 反転を強制する操作を適用する最適な場所を特定します。 各操作は、選択した分割の左右のすべての要素に影響を与えるため、違反を作成する最も効果的な方法は、最小のギャップを横切って 1 つのプレフィックスを上にプッシュし、サフィックスを下にプッシュすることを繰り返すことです。 
4. スプリット時の 1 つの操作の効果$i$増やすことです$a_i$に対して$a_{i+1}$ちょうど 2 単位ずつ ($a_i$がプレフィックスに含まれており、$a_{i+1}$はサフィックスにあります）。 したがって、その後$k$同じスプリットで操作を行うと、ギャップは次のように減少します。$2k$。 
5. 逆変換を行うには、次のものが必要です。$a_i + k > a_{i+1} - k$、これは以下と同等です$a_{i+1} - a_i < 2k$。 したがって、最低限の$k$ペアの場合は$\left\lfloor \frac{(a_{i+1} - a_i)}{2} \right\rfloor + 1$。 
6. すべての隣接するペアについてこの値を計算し、すべてのペアの最小値を取得します。 これにより、必要な操作の全体的な最小数が得られます。 

### なぜ効果があるのか

 各操作は分割ポイントによって完全に特徴付けられ、一方のすべての要素に均一な +1 シフトを適用し、もう一方の要素には -1 を適用します。 これは、境界を越えた要素間の相対的な差のみが変化し、他のすべての比較は変更されないか、同じ方向に移動することを意味します。 したがって、最初の反転は何らかの隣接するペアで現れる必要があり、最適な戦略は常に、必要なステップ数を最小限に抑える分割にすべての操作を集中させます。 混合戦略は最初の反転を加速することなく複数の境界を越えて効果を分散させるため、異なる分割のシーケンスが最も弱い隣接するギャップを繰り返し攻撃することよりも優れたパフォーマンスを発揮することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # already unsorted
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                print(0)
                break
        else:
            ans = float('inf')
            for i in range(n - 1):
                diff = a[i + 1] - a[i]
                ans = min(ans, diff // 2 + 1)
            print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず即時反転をスキャンします。 これが必要なのは、この問題ではゼロ操作が許可されており、このケースをチェックしないと誤って肯定的な答えが強制されてしまうためです。 

配列がソートされている場合は、隣接するペアを分割するために必要な最小操作数を計算します。 表現`diff // 2 + 1`各演算の ±1 対称更新効果の下で、非負のギャップを負のギャップに反転するために必要な最小数の演算を直接エンコードします。 

ループ構造により、反転はグローバルに伝播する前にまずローカルに現れる必要があるため、隣接するペアのみを考慮することが保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列が開始時にすでにソートされていない場合です。`[3, 1, 2]`。 アルゴリズムは最初のスキャン中にこれを即座に捕捉するため、ギャップを計算せずに 0 を出力します。 これにより、回答の不正確なインフレが防止されます。 

もう 1 つのエッジ ケースは、すべての要素が等しい場合です。たとえば、`[5, 5, 5]`。 最小の隣接差はゼロであり、次の式は`diff // 2 + 1`これは、一方を上にシフトし、もう一方を下にシフトするため、単一の操作でどこかに厳密な反転が作成されるという事実と一致します。 

最後のエッジケースは、配列が大きなギャップを伴って厳密に増加している場合です。`[1, 100]`。 差は 99 で、答えは 50 になります。50 回の演算の後、左側の要素は 50 増加し、右側の要素は 50 減少し、次のようになります。`[51, 50]`、これは最初に考えられる反転です。
