 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`それぞれの頂点には、最初はそのラベルに等しい一意の整数の優先順位が付けられます。 特定の順序でツリーを燃やすことを想像できます。頂点がなくなるまで、最も優先順位の低い葉を繰り返し削除します。 タスクは、この書き込みプロセスに関する質問に答えることです。 クエリ タイプには 3 つあります。頂点の優先順位を他の頂点よりも高くする、頂点がいつ燃焼するかを尋ねる、2 つの頂点のうちどちらが最初に燃焼するかを比較する。 

入力はツリーのエッジと一連のクエリで構成されます。 「when」クエリの出力は頂点が燃焼するステップ番号であり、「compare」クエリの出力は最初に燃焼する頂点です。 

制約は大きくなります。`n`そして`q`それぞれ最大 200,000 まで可能です。 これにより、葉の除去を順番に明示的にシミュレートするアプローチは除外されます。`n`クエリごとの削除は次のようになります`O(nq)`この操作は 4 × 10^10 に達する可能性があり、実行可能な限界をはるかに超えています。 

エッジ ケースには、優先度が繰り返し増加するチェーン、スター、頂点などのツリーが含まれます。 たとえば、中心 1、葉 2 ～ 5 の 5 つのノードを持つスター ツリーを考えてみましょう。 葉2を繰り返し上げると葉の中で最後に燃えることになり、燃える順番が変わります。 単純なシミュレーションでは、これらの相互作用が見逃され、不正確な「いつ」の値が生成される可能性があります。 

## アプローチ

 ブルートフォース手法では、ツリーを明示的に追跡し、リーフを 1 つずつ削除し、各ステップで最小のリーフ優先度を再計算します。 正しいのですが、これにはツリー全体を繰り返しスキャンする必要があり、`O(n^2 + q n)`、これは 2 × 10^5 までの n には実行不可能です。 

重要な観察は、木の燃焼順序が **葉の除去ランキング** (**木のプルーファー順序逆順序**とも呼ばれる) を計算するのと同等であるということです。 ツリーでは、すべての子が燃えた後、葉以外のすべての頂点が葉になります。 これは、優先順位が静的な場合に各頂点の書き込み **時間**を事前計算するという戦略を示唆しています。 その後、優先度順に並べられた **セグメント ツリーまたは平衡二分探索ツリー**を使用して、優先度の更新を効率的に処理できます。 

明示的にリーフを削除する代わりに、現在のリーフを優先度に従って最小ヒープに保存できます。 「up」クエリごとに優先度が上がり、ヒープから頂点が削除されたり、新しいキーで頂点が再挿入されたりする可能性があります。 「いつ」クエリは単純な検索になり、「比較」クエリは事前に計算された書き込みステップの比較に減ります。 

複雑さは次のように低下​​します`O((n+q) log n)`ヒープ上の各操作 (挿入、削除、更新) にコストがかかるため、`O(log n)`そして、各頂点は更新ごとに 1 回だけヒープに入ります。 これは制約内にうまく収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² + nq) | O(n) | 遅すぎる |
 | ヒープベースの書き込み順序 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. **入力を読み取り、ツリーを構築します**: リーフと近隣を効率的に見つける必要があるため、隣接リストを使用してグラフを表します。 
2. **頂点の優先順位を初期化**: 以下から開始します`p[v] = v`すべての頂点に対して。 
3. **最初のリーフを特定します**: 次数 1 の頂点。優先度によってキー設定された最小ヒープにそれらをプッシュします。 
4. **仮想の火傷をシミュレートして、火傷ステップを割り当てます**:

 1.初期化`step = 1`。 
2. ヒープが空でない間に、最小限の優先順位でリーフをポップします。 
3.割り当て`burn_step[leaf] = step`。 
4. リーフの隣については、その次数を減らします。 リーフになった場合は、ヒープにプッシュします。 
5. インクリメント`step`。 
5. **クエリの処理**:

 -`"up v"`： 増加`p[v]`現在のすべての優先事項よりも大きくなるようにします。 v が現在ヒープ内のリーフである場合は、そのキーを更新します。 
-`"when v"`: 出力`burn_step[v]`。 
-`"compare v u"`： 比較する`burn_step[v]`そして`burn_step[u]`、より小さいステップで頂点を出力します。 
6. **不変条件を維持**:

 - ヒープに挿入された各リーフには、正しい現在の優先順位が設定されます。 
- 各頂点は、リーフ間の優先順位の昇順で 1 回だけ燃えます。 
- 更新では常に個別の優先順位が保持されます。 

**機能する理由**: ヒープにより、各ステップでツリーを明示的に変更することなく、書き込み順序を正確にシミュレートし、常に最小の現在の優先順位でリーフが削除されることが保証されます。 ツリー構造は固定されており、優先順位のみが変更されるため、ヒープは優先順位の更新を効率的に動的に処理できます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n, q = map(int, input().split())
adj = [[] for _ in range(n + 1)]
degree = [0] * (n + 1)
for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)
    degree[u] += 1
    degree[v] += 1

p = [0] + list(range(1, n + 1))
burn_step = [0] * (n + 1)
max_priority = n

# Min-heap of (priority, vertex)
heap = []
for v in range(1, n + 1):
    if degree[v] == 1:
        heapq.heappush(heap, (p[v], v))

current_step = 1
deg = degree[:]
while heap:
    prio, v = heapq.heappop(heap)
    if burn_step[v]:
        continue
    burn_step[v] = current_step
    current_step += 1
    for u in adj[v]:
        deg[u] -= 1
        if deg[u] == 1 and burn_step[u] == 0:
            heapq.heappush(heap, (p[u], u))

for _ in range(q):
    query = input().split()
    if query[0] == 'up':
        v = int(query[1])
        max_priority += 1
        p[v] = max_priority
    elif query[0] == 'when':
        v = int(query[1])
        print(burn_step[v])
    else:
        v, u = int(query[1]), int(query[2])
        if burn_step[v] < burn_step[u]:
            print(v)
        else:
            print(u)
```このソリューションは、ヒープを使用して書き込みステップを事前計算し、リーフの削除をシミュレートします。`"up"`書き込み順序は元のトポロジに依存するため、クエリは優先順位のみを変更し、書き込み順序は変更しません。`"when"`そして`"compare"`クエリは事前計算を使用します`burn_step`。 

## 実用的な例

 **サンプル 1**

 | ステップ | ヒープ (最小プリオ リーフ) | 焼けた | バーンステップ |
 | --- | --- | --- | --- |
 | 1 | [2,4,5] | 2 | バーンステップ[2]=1 |
 | 2 | [4,5] | 4 | バーンステップ[4]=2 |
 | 3 | [3,5] | 3 | バーン_ステップ[3]=3 |
 | 4 | [1,5] | 1 | バーン_ステップ[1]=4 |
 | 5 | [5] | 5 | バーンステップ[5]=5 |

 「2 3 を比較」: burn_step[2]=1 < burn_step[3]=3 → 出力 2。 

「3 4 を比較」: burn_step[3]=3 > burn_step[4]=2 → 出力 4。 

**カスタム チェーン ツリー**

 入力: 1-2-3-4-5、優先順位は最初は 1 ～ 5。 書き込み順序: 葉 1 と葉 5 が最初に競合します。 最小リーフ優先度は 1 → 最初に書き込みます。 次に 5、最後に 2、4、3 と続きます。 エンドポイントがチェーンで最初に焼き付けられることを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | ヒープ内の各リーフの挿入/削除には log n のコストがかかります。 n 頂点、q 個のクエリ。 |
 | スペース | O(n) | 隣接性、次数、優先順位、書き込みステップを保存します。 |
