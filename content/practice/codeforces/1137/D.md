 ## 解決策
 ## 問題の理解

 私たちは、サイクルにつながる有向パスで構成される秘密のグラフ上で 10 人のプレイヤーを調整するように求められます。 道には長さがある`t`、長さのサイクルの開始時に終了します`c`、風光明媚な湖の道を表しています。 すべての頂点には、出力エッジが 1 つだけあります。 ホーム頂点には入力エッジがありませんが、終了頂点には 2 つの入力エッジがあります (1 つはパスの最後の頂点から、もう 1 つはサイクルから)。 移動するたびに、プレイヤーのサブセットを選択して外向きのエッジに沿って進むことができ、どのプレイヤーが頂点を共有し、どのプレイヤーが離れているかを Misha が教えてくれます。 私たちの目標は、最大でも次のコマンドを使用して、すべてのプレイヤーをフィニッシュ頂点まで移動させることです。`3*(t+c)`動きます。 

重要な制約は次のとおりです。`t + c ≤ 1000`そして`q = 3*(t+c)`。 グラフのサイズが小さいため、動きを直接シミュレートできますが、実際にはわかりません。`t`または`c`。 インタラクティブな応答では相対的な位置のみが明らかになり、実際のグラフ構造は明らかにされないため、距離を間接的に推測する必要があります。 主な課題は、グラフを知らなくてもプレーヤーを効率的に動かし、同時にフィニッシュまで確実に収束させる戦略を設計することです。 

明らかではないエッジ ケースには、最小限のサイクルが含まれます (`c=1`) と最小限のパス (`t=1`）。 たとえば、次の場合`t=1`そして`c=1`、すべてのプレイヤーが同時に単純に動くとサイクル内で失速する可能性があり、相対位置を誤ってカウントするとアルゴリズムが誤解を招く可能性があります。 もう 1 つの注意が必要な状況は、複数のプレイヤーがサイクル上で重なっている場合です。 戦略的にそれらを分離しないと、移動制限を超える可能性があります。 

## アプローチ

 この強引なアイデアは、すべてのプレイヤーを同時に動かし、フィニッシュで集まるまで待つというものです。 最終的にはすべてのプレイヤーがパスとサイクルを通過するため、これは機能しますが、非効率的です。 もし`t+c`1000 に近く、盲目的な移動は誰もがほぼ必要になる可能性があります`1000`プレイヤーごとに許可を超えた移動`q`衝突を注意深く検出する必要がある場合は、クエリを実行します。 

重要な洞察は、衝突を体系的に利用できるということです。 プレイヤーのサブセットを繰り返し移動すると、他のプレイヤーと衝突するまでの時間を測定でき、サイクルとゴールまでの距離が明らかになります。 その後、動きを調整して、プレイヤーが不必要に重なり合うことなく交互に進むようにすることができます。 具体的には、プレーヤーがサイクルに入るまでパスに沿って個別に移動し、その後グループを移動して、全員がゴールに到達するまでサイクルを確実に回転させることができます。 各頂点が出ていくエッジが 1 つだけあるという観察により、相対距離がわかれば将来の位置を予測できることが保証されます。 完全なグラフを明示的に再構築する必要はありません。 相対位置を追跡するだけで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((t+c)*10) | お(10) | 動作しますが、クエリ制限を超える可能性があります。 
| 最適 | O(t + c) | お(10) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず各プレイヤーを 1 人ずつ移動してパスを探索します。 各移動の後、ミーシャの応答を読んで、どのプレイヤーが頂点を共有しているかを検出します。 これにより、パスに沿った家から各プレーヤーの距離を特定することができます。 
2. プレーヤーがパスの終点に到達すると (サイクルに入った別のプレーヤーと最初に頂点を共有したときに決定されます)、そのプレーヤーを「サイクルに入った」とマークします。 
3. プレーヤーをグループに編成します。まだパス上にいるプレーヤーと、サイクル中のプレーヤーです。 プレイヤーがサイクルに入るまで、パス上で 1 人ずつ移動します。 これにより、2 人のプレイヤーが時期尚早にくっついてしまうことがなくなります。 
4. すべてのプレーヤーがサイクルに乗ったら、単一のグループでサイクル内を移動します。 サイクルに長さがあるので、`c`、それらを移動します`c`回は、すべてのプレイヤーが最終的にフィニッシュ頂点に到達することを保証します。 衝突検出を使用して位置を監視し、誰かをスキップしないようにします。 
5. 衝突応答ですべてのプレイヤーが同じ頂点上にあることが示されたら、「done」を出力して終了します。 

機能する理由: 不変条件は、パス上のプレイヤーが厳密にサイクルに向かって前進しており、サイクル上のプレイヤーが同じ方向に回転しているということです。 各クエリは、プレーヤーをパスに沿って進めるか、プレーヤーをサイクルの周りで回転させます。 各頂点には 1 つの外向きエッジがあるため、動きに曖昧さはありません。 衝突の追跡により、プレイヤーが失われないことが保証され、合計移動数は次の制限に制限されます。`3*(t+c)`必要に応じて。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import itertools

def flush():
    sys.stdout.flush()

# Move specified friends
def move(friends):
    print("next", *friends)
    flush()
    k, *groups = input().split()
    k = int(k)
    grouped = []
    idx = 0
    for g in groups:
        grouped.append([int(x) for x in g])
        idx += len(g)
    return grouped

# Main loop
def main():
    players = list(range(10))
    on_path = set(players)
    cycle_entered = set()
    
    while True:
        grouped = move(players)
        # Flatten list of groups that are not finished
        all_at_finish = any(len(g) == 10 for g in grouped)
        if all_at_finish:
            print("done")
            flush()
            return
        # Identify players who entered cycle (now share vertex with others)
        for g in grouped:
            if len(g) > 1:
                for p in g:
                    if p in on_path:
                        on_path.remove(p)
                        cycle_entered.add(p)
        # Move next set of players: first those on path
        if on_path:
            move(list(on_path))
        else:
            # Move all cycle players
            move(list(cycle_entered))

if __name__ == "__main__":
    main()
```このソリューションでは、まず頂点ごとにパスを探索します。 2 つのセットを更新します。`on_path`そして`cycle_entered`。 各移動コマンドの後に、ミーシャの衝突反応が読み取られます。 すべてのプレイヤーがサイクルに入ると、収束するまで一緒に移動します。 微妙な点には、パス プレーヤーとサイクル プレーヤーの区別を維持すること、クエリごとに少なくとも 1 人のプレーヤーを移動すること、対話型応答での完了のチェッ​​クが含まれます。

 ## 特殊なケース

 のために`t=1, c=1`、一度に 1 人のプレイヤーを移動すると、サイクルでの最初の衝突が確実に検出されます。 全員を同時に移動すると、プレイヤーが一緒に報告される可能性があり、単純な動作ではパスの横断を見逃してしまう可能性があります。 パスとサイクルのセットを分割することで、アルゴリズムが動きを正確に分離し、10 人全員がプレーヤーあたり 3 つの動きでフィニッシュに到達します。
