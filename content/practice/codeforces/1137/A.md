 ## 解決策
 ## 問題の理解

 私たちは、一定のサイズのグリッドとして配置された都市を与えられています。$n \times m$ここで、各セルは特定の高さの超高層ビルを含む交差点を表します。 行の各交差点について$i$そしてコラム$j$、私たちは超高層ビルの 2 つのラインに焦点を当てます。$i$- 列目 (東の通り) およびフル$j$- 列目 (南の通り)。 Dora は、行と列の両方で高さの相対的な順序をそのまま維持し、1 から整数までの数値を使用して、これらの高層ビルに整数の高さを再割り当てしたいと考えています。$x$。 目標は最大数を最小限に抑えることです$x$使用済み。 

入力は次のもので構成されます$n$そして$m$、続いて$n \times m$初期の高さを表す整数のグリッド。 出力は同じサイズのグリッドである必要があり、各セルには最小限の最大高さが含まれます。$x$その交差点では達成可能です。 

制約により許可されるのは、$n, m \le 1000$、グリッドは最大まで可能です$10^6$細胞。 行と列を個別にソートすることで各交差を個別に解決する素朴なソリューションには、$O(n m (n + m) \log(n + m))$動作が遅すぎます。 これは、行と列の情報を一度前処理し、交差ごとに効率的に使用するソリューションが必要であることを意味します。 

行または列の高さが重複している場合、微妙なエッジ ケースが発生します。 たとえば、行が`[1, 1, 2]`そしてコラムは`[1, 2, 2]`、交差の高さは行と列の両方のランキングに影響を与える可能性があります。 行と列で独立してランクを割り当てる不注意なアプローチは、いずれかの行の相対順序に違反する可能性があります。 

最小限の入力で別のエッジケースが発生します。$n = m = 1$。 ここで、唯一の交差の答えは自明のことですが 1 ですが、アルゴリズムはインデックス付けエラーなしで単一要素の行と列を正しく処理する必要があります。 

## アプローチ

 強引なアプローチでは、各交差点を個別に検討することになります。 その交差を含む行と列について、割り当てられた最大数を追跡しながら、最小の高さの 1 から始まるランクを並べ替えて割り当てます。 次に、交差部分での重複を考慮して、両方のシーケンスにわたる最大数を計算します。 これは正しく機能しますが、各行と列をソートするため非効率的です。$nm$時間はおよそにつながります$O(n m (n + m) \log(n + m))$操作。 

重要な点は、各行および各列内の高さの相対的なランクを事前に計算できることです。 各行について、並べ替えられた行内での位置を表す「行ランク」を各セルに割り当てることができます。 同様に、各列に「列ランク」を割り当てることができます。 の交差点については、$(i, j)$の場合、答えは、行ランクと列ランクの最大値に、一方のランクが他方のランクよりも優っている場合の調整を加えたものになります。これは、両方のシーケンスで交差の位置を揃えるために数値を拡張する必要があるためです。 これにより、前処理後にセルごとに一定時間で答えを計算できるようになり、複雑さが大幅に軽減されます。$O(n m)$後$O(n m \log m + n m \log n)$行と列の並べ替えの前処理。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n m (n + m) log(n + m)) | O(n + m) | 遅すぎる |
 | 最適 | O(n m log m + n m log n) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各行について、すべての高さを抽出し、その行内の各セルのランクを計算します。 ランクは、身長が最も低い場合は 1、次に低い場合は 2、というようになります。 これにより、最小の整数に再マップされたときに、行内の相対的な順序が維持されることが保証されます。 
2. 各列に対して同じプロセスを繰り返し、各セルに列ランクを割り当てます。 この段階では、ランクの 2 つの行列があります。`row_rank[i][j]`そして`col_rank[i][j]`。 
3. 各セルについて$(i, j)$、行と列の順序の両方を保持するために必要な最大数を計算します。 させて`r = row_rank[i][j]`そして`c = col_rank[i][j]`。 させて`row_len`行内の一意の値の数になります`i`そして`col_len`列内の固有の値の数になります`j`。 交差の最小最大値は次のとおりです。`max(r, c) + max(row_len - r, col_len - c)`。 この式により、両方のシーケンスを確実にマッピングできるようになります。`[1, x]`秩序を乱さずに。 
4. 結果として得られる最小最大値の行列を出力します。 

なぜ効果があるのか​​:`row_rank`そして`col_rank`各行の最小限の相対順序をエンコードします。 交差点では、2 つの間の最大ランクによってそのセルの開始番号が決まります。 行の右側または列の下にある残りの位置は、残りの一意のランクの数だけ最大値を拡張し、相対順序の違反がないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = [list(map(int, input().split())) for _ in range(n)]

row_rank = [[0]*m for _ in range(n)]
col_rank = [[0]*m for _ in range(n)]

# Compute ranks for rows
for i in range(n):
    vals = sorted(set(a[i]))
    val_to_rank = {v: idx+1 for idx, v in enumerate(vals)}
    for j in range(m):
        row_rank[i][j] = val_to_rank[a[i][j]]

# Compute ranks for columns
for j in range(m):
    col_vals = sorted({a[i][j] for i in range(n)})
    val_to_rank = {v: idx+1 for idx, v in enumerate(col_vals)}
    for i in range(n):
        col_rank[i][j] = val_to_rank[a[i][j]]

# Compute final answers
res = [[0]*m for _ in range(n)]
for i in range(n):
    for j in range(m):
        r = row_rank[i][j]
        c = col_rank[i][j]
        row_len = len(set(a[i]))
        col_len = len({a[k][j] for k in range(n)})
        res[i][j] = max(r, c) + max(row_len - r, col_len - c)

for row in res:
    print(*row)
```最初の 2 つのセクションでは、ソートされたセットを使用して行と列のランクを効率的に計算します。 セットを使用すると、重複した高さがランクに干渉するのを回避できます。 最後のネストされたループは、上で説明した式を使用して各交差の最小最大値を計算します。 慎重に使用しなければなりません`len(set(...))`固有の高さをカウントするには、重複した値が不正確な結果をもたらす可能性があります。
