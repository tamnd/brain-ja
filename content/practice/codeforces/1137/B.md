 ## 解決策
 ## 問題の理解

 2 つのバイナリ文字列が与えられます。 

最初の文字列`s`は直接出力する必要があるスケジュールではありません。 代わりに、文字のマルチセットとして機能します。 シンボルを任意の順序で並べ替えることができますが、シンボルの合計数は`'0'`キャラクターと`'1'`文字はまったく同じままでなければなりません。 

2番目の文字列`t`がターゲットパターンです。 あらゆる可能な再配置の中で、`s`、回数を最大化するものが欲しいです。`t`部分文字列として表示されます。 

出力は、次のものを再配置したものです。`s`この最大値を達成します。 

重要な制限は、順序のみを変更できることです。 もし`s`100 個のゼロと 200 個の 1 が含まれている場合、答えにもちょうど 100 個のゼロと 200 個の 1 が含まれている必要があります。 

両方の文字列の長さは 500,000 に達する場合があります。 この規模では、二次アルゴリズムは完全に不可能です。 たとえ$O(n^2)$スキャンには約必要になります$2.5 \times 10^{11}$最悪の場合の運用。 合計入力サイズが本質的に線形であるソリューションが必要です。 

主な難点は、部分文字列の出現を最大化することと、貪欲にコピーを配置することは同じではないことです。`t`独立して。 異なる出来事が重複する場合があります。 実際、オーバーラップによって、より多くの文字を一定量の文字に収めることができます。 

考慮する：```
t = 10101
```接尾辞があるため、前の出現が完全に終了する前に次の出現が始まる可能性があります。`"101"`も接頭語です。 重複を無視すると文字が無駄になり、出現回数が減ります。 

もう 1 つの簡単な間違いは、コピーを 1 つ作成した後で停止することです。`t`。 

例：```
s = 11110000
t = 1100
```単純な解決策では、コピーを 1 つ配置する可能性があります。```
1100 + remaining
```ただし、リソースが許せば、可能な限り重複するコピーを追加し続ける必要があります。 

3 番目のエッジ ケースは、次のコピーを 1 つも構築できない場合に発生します。`t`。 

例：```
s = 1111
t = 000
```使用可能なゼロがないため、すべての配置にはゼロの出現が含まれます。 正解は、次のすべての文字を使用した任意の文字列です。`s`、 のような：```
1111
```の部分コピーを強制しようとしています`t`文字数違反になります。 

## アプローチ

 ブルートフォースビューとは、次の文字のあらゆる順列を考慮することです。`s`、何回数えますか`t`と表示されるので、最適なものを選択します。 

すべての有効なスケジュールを検査するため、これは明らかに正しいです。 残念ながら、もし`|s| = 500000`、順列の数は天文学的であり、まったく実行不可能です。 

より現実的な強引なアイデアは、次の完全なコピーを繰り返し追加することです。`t`十分な 0 と 1 が残っているときはいつでも。 これにより、重複しないオカレンスの数が最大化されます。 

欠点は、オカレンスの重複が許可されていることです。 仮定する：```
t = 10101
```接尾語`"101"`接頭辞に等しい`"101"`。 

1 つのオカレンスを書き込んだ後:```
10101
```追加するだけで済みます`"01"`別のオカレンスを作成するには:```
1010101
```オーバーラップにより 3 文字が節約されます。 0 と 1 の供給には限りがあるため、文字を保存するということは、より多くの文字を適合させることを意味します。 

この観察は、接頭辞関数または KMP の考え方を直接示しています。 の最長の適切なプレフィックスがわかっている場合`t`これもサフィックスであるため、1 つのオカレンスを書き込んだ後、最初からやり直す必要はありません。 重複しない末尾のみを追加できます。 

させて```
k = longest border length of t
```それから：```
tail = t[k:]
```最初のコピーの後`t`を追加することですべての追加オカレンスを作成できます。`tail`。 

末尾を追加するたびに、必要な文字数が最小限に抑えられながら、新しいオカレンスが 1 つだけ作成されるため、末尾を繰り返し追加することが常に最適です。 

アルゴリズムは次のようになります。 

1. 利用可能な 0 と 1 を数えます。`s`。 
2. コピーが 1 つあるかどうかを確認します。`t`形成することができる。 
3. そうでない場合は、すべての文字を任意に出力します。 
4. それ以外の場合は、`t`。 
5. の最長境界線を計算します。`t`KMPを使用します。 
6. 文字数が許す限り、重複しない末尾を繰り返し追加します。 
7. 残りの未使用文字をすべて追加します。 

KMP は境界線を計算するため、すべてが線形です。$O(|t|)$時間。

 ## アルゴリズムのチュートリアル

 1. で利用可能な 0 と 1 の数を数えます。`s`。 
2. 1 つの完全なコピーに必要な 0 と 1 の数を数えます。`t`。 
3. もし`s`のコピーを 1 つ作成するのに十分な 0 または 1 が含まれていません`t`、いかなる出来事も存在することはできません。 残りの文字をすべて任意の順序で出力して停止します。 
4. KMP 接頭関数を計算します。`t`。 
5. しましょう`k = pi[-1]`。 これは、最も長い適切なプレフィックスの長さです。`t`それも接尾辞です。 
6. の完全なコピーを 1 つ追加します。`t`答えを入力し、利用可能な供給量からその文字数を差し引きます。 
7. 以下を定義します。```
tail = t[k:]
```これはまさに、オーバーラップを再利用しながらもう 1 つオカレンスを作成するために追加する必要がある部分です。 
8. に含まれる 0 と 1 を数えます。`tail`。 
9. 十分な文字数が残っているうちに、次のコピーを書きます。`tail`、それを追加し、そのカウントを減算します。 
10. 末尾を追加できなくなったら、残りのゼロをすべて追加し、次に残りのすべての 1 を追加します。 

### なぜ効果があるのか

 最初に発生した後、`t`と書かれているように、将来の出来事はすべて、可能な限り以前の出来事と重なる必要があります。 2 つの連続するコピー間の法的重複の最大値は、正確に、`t`。 

オーバーラップが小さいと、同じ数の出現を作成しながら、より多くの文字が消費されます。 0 と 1 の供給は固定されているため、追加出現ごとに消費する文字数が減ることはこれ以上に悪いことはありません。 

KMP 境界は可能な限り最大の重なりを与えます。 したがって、それぞれが追加されました`tail`最小限の文字コストで 1 つの新しいオカレンスを作成します。 これを貪欲に繰り返すことで、利用可能な数に収まる出現数が最大化されます。 もう一度`tail`すべての出現には少なくとも末尾と同じ数の新しい文字が必要となるため、追加の出現を作成する代替構造は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
t = input().strip()

cnt0 = s.count('0')
cnt1 = len(s) - cnt0

need0 = t.count('0')
need1 = len(t) - need0

if cnt0 < need0 or cnt1 < need1:
    print('0' * cnt0 + '1' * cnt1)
    sys.exit()

m = len(t)

pi = [0] * m
for i in range(1, m):
    j = pi[i - 1]
    while j > 0 and t[i] != t[j]:
        j = pi[j - 1]
    if t[i] == t[j]:
        j += 1
    pi[i] = j

k = pi[-1]
tail = t[k:]

tail0 = tail.count('0')
tail1 = len(tail) - tail0

ans = [t]

cnt0 -= need0
cnt1 -= need1

while cnt0 >= tail0 and cnt1 >= tail1:
    ans.append(tail)
    cnt0 -= tail0
    cnt1 -= tail1

ans.append('0' * cnt0)
ans.append('1' * cnt1)

print(''.join(ans))
```最初のセクションでは、利用可能なリソースをカウントし、次のコピーが 1 つでもあるかどうかを確認します。`t`可能です。 そうでない場合は、すべての配置で出現がゼロになるため、有効な再配置が最適です。 

プレフィックス関数の計算は標準の KMP です。 値`pi[-1]`文字列全体の最長の境界線を返します。 

微妙なアイデアは次のような構造です。`tail = t[k:]`。 境界線の長さが`k`、次に最初の`k`次に出現する文字は、前の出現の接尾辞としてすでに存在します。 残りのサフィックスのみを追加する必要があります。 

ループはできるだけ多くの末尾を追加します。 各反復では、可能な限り最小限の文字数を使用しながら、新しいオカレンスを 1 つだけ作成します。 

最後に、残った 0 と 1 が追加されます。 その時点で、別のテールの手頃な価格テストにすでに不合格になったため、それ以上のオカレンスを作成することはできません。

# helper: run solution on input string, return output string
import sys, io

def solve():
    s = input().strip()
    t = input().strip()

    cnt0 = s.count('0')
    cnt1 = len(s) - cnt0

    need0 = t.count('0')
    need1 = len(t) - need0

    if cnt0 < need0 or cnt1 < need1:
        print('0' * cnt0 + '1' * cnt1)
        return

    pi = [0] * len(t)
    for i in range(1, len(t)):
        j = pi[i - 1]
        while j and t[i] != t[j]:
            j = pi[j - 1]
        if t[i] == t[j]:
            j += 1
        pi[i] = j

    k = pi[-1]
    tail = t[k:]

    ans = [t]

    cnt0 -= need0
    cnt1 -= need1

    tail0 = tail.count('0')
    tail1 = len(tail) - tail0

    while cnt0 >= tail0 and cnt1 >= tail1:
        ans.append(tail)
        cnt0 -= tail0
        cnt1 -= tail1

    ans.append('0' * cnt0)
    ans.append('1' * cnt1)

    print(''.join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    global input
    input = sys.stdin.readline

    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old
    return out.getvalue().strip()

# perfect overlap chain
assert run("11110000\n1010\n") == "10101010"

# minimum size
assert run("0\n0\n") == "0"
