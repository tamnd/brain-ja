 ## 解決策
 ## 問題の理解

 直線上に配置された一連の整数が与えられ、位置のペア間の接続性のクエリに答えたいと考えていますが、接続性は隣接性に基づいていません。 代わりに、値のビットごとの AND が少なくとも 1 つの設定ビットを共有する場合、あるインデックスから後のインデックスにジャンプすることができます。 開始位置から$x$、チェーン内のすべての連続するペアがゼロ以外のビット単位の AND を持っている限り、インデックスのチェーンを先に進めることができます。 タスクは、多くのクエリに対して、目標位置に到達できるかどうかを判断することです$y$から始まる$x$。 

これは基本的に、ノードがインデックスであり、からのエッジがある有向グラフ上の到達可能性の問題です。$i$に$j$のために$i < j$もし$a_i \& a_j > 0$。 課題は、すべてのエッジを明示的に構築することが不可能であることです。$O(n^2)$最悪の場合は動作します。 

制約は大きく、最大 300,000 個の要素と 300,000 個のクエリがあります。 ペアを直接検査するアプローチはすべてタイムアウトになります。 BFS または DFS はクエリごとに線形に低下する可能性があるため、クエリごとのグラフ トラバーサルでさえ遅すぎます。 これにより、迅速な到達可能性チェックを可能にする構造の前処理が進められます。 

微妙なエッジ ケースは、ゼロの存在です。 値 0 のインデックスには、発信または着信の有用なエッジがありません。$0 \& x = 0$みんなのために$x$。 このような位置は、通過する必要のない単純なクエリの分離されたエンドポイントとして使用される場合を除き、有効なパスに参加することはできません。 たとえば、次の場合$a = [1, 0, 2]$の場合、位置 2 は、たとえ中央に位置していても、1 と 3 を接続することができません。 

もう 1 つの明白ではない問題は、到達可能性が対称的ではなく、インデックスの増加によって制限されることです。 これにより、構造が順方向のみのグラフに近づき、ソリューション内の順序付けを活用できるようになります。 

## アプローチ

 直接的なアプローチでは、グラフを明示的に構築し、クエリごとに BFS を実行します。 インデックスごとに$i$、すべてチェックします$j > i$エッジを追加する場合$a_i \& a_j > 0$。 これにはすでに費用がかかります$O(n^2)$、これは 300,000 要素には大きすぎます。 

明示的な構築をスキップしてクエリごとに BFS を試したとしても、各走査は依然として配列の大部分に影響を与える可能性があります。 クエリが 300,000 件になると、最悪の場合の複雑さは完全に不可能になります。 

重要な点は、ビット単位の AND 接続が共有セット ビットのみに依存するということです。 各数値は最大 18 ビットのサブセットとして表示できます (値は最大 300,000 であるため)。 ビットの観点から考えると、各位置は複数のビット グループに属しており、共有ビット メンバーシップを通じてのみ移動が可能です。 

これは、各ビットについて、左から右へのスキャン中に確認された最新の位置を維持することを示唆しています。 インデックスにいるとき$i$、どの以前のインデックスがそのインデックスと少なくとも 1 ビットを共有しているかがわかり、接続情報を前方に「マージ」できます。 

ただし、ビットごとの完全な推移的な接続を維持することは依然として複雑です。 重要な単純化は、すべてのペア間の完全な到達可能性は必要ないということです。 このフォワード グラフで 2 つのインデックスが同じ連結成分に属しているかどうかを知る必要があるだけです。 エッジは前方にのみ進むため、ビットの出現に基づいて、インデックス上の結合のような構造を使用してコンポーネントを段階的に構築できます。 

素セット共用体 (DSU) を維持しながら、インデックスを左から右に処理します。 各ビットについて、そのビットが出現した最後のインデックスを記憶します。 インデックスにいるとき$i$、設定されたビットごとに$a_i$、私たちは組合します$i$そのビットの最後に確認されたインデックスを使用して、最後に確認されたインデックスを次のように更新します。$i$。 これにより、重複するビットのチェーンによって引き起こされる接続が正確に構築されます。 

DSU が構築されると、各クエリは次のことを確認することになります。$x$そして$y$同じコンポーネントに属しており、$x < y$(入力によりすでに保証されています)。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS |$O(qn)$|$O(n^2)$| 遅すぎる |
 | ビット伝播上の DSU |$O(n \alpha(n) \cdot B + q \alpha(n))$|$O(n + B)$| 承認済み |

 ここ$B$値の範囲内のビット数です (最大 18)。 

## アルゴリズムのチュートリアル

 1. インデックスを使用して DSU 構造を初期化します。$1 \dots n$。 各インデックスは独自のコンポーネントで始まります。 これは、最初は接続性が不明であることを表します。 
2. 配列を維持する`last[bit]`、各エントリには、値にそのビットが含まれる最新のインデックスが格納されます。 最初はすべて未設定です。 
3. インデックスを左から右に繰り返します。 インデックス時$i$に設定されているすべてのビットを検査します。$a_i$。 各ビットは、接続が伝播する「チャネル」を表します。 
4. 各ビットについて$b$セットする$a_i$、 もし`last[b]`存在する、結合する$i$と`last[b]`。 これにより、現在の位置が同じビットの前の出現位置に接続され、その出現位置にすでに接続されているすべてのものに間接的に接続されます。 
5. すべてのビットの共用体を処理した後、$a_i$、 アップデート`last[b] = i`あらゆるビットに対して$b$セットする$a_i$。 これにより、将来のインデックスが各ビット グループの最新の代表に確実に接続されます。 
6. 前処理後、クエリごとに$(x, y)$、DSU 検索操作が同じルートを返すかどうかを確認します。 ある場合は「Shi」を出力し、そうでない場合は「Fou」を出力します。 

### なぜ効果があるのか

 DSU の不変条件は、連続する要素が少なくとも 1 つの共通ビットを共有する左から右へのインデックスのシーケンスが存在する場合に限り、2 つのインデックスが同じセット内にあることです。 すべての結合演算は、共有ビットによって引き起こされるグラフ内に有効なエッジを導入することに正確に対応します。 考えられるすべてのエッジがノードを少なくとも 1 つの共有ビットの最新の以前の出現に接続するため、元の到達可能性定義内のすべてのパスがこれらの結合を通じて表現可能です。 DSU の推移性により、マルチステップ チェーンが確実にキャプチャされるため、DSU の接続クエリは元のグラフの到達可能性と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    dsu = DSU(n)
    last = [-1] * 20

    for i in range(n):
        x = a[i]
        for b in range(20):
            if x & (1 << b):
                if last[b] != -1:
                    dsu.union(i, last[b])
                last[b] = i

    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        if dsu.find(x) == dsu.find(y):
            out.append("Shi")
        else:
            out.append("Fou")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU は、左から右にスキャンしながら接続をコンポーネントに圧縮するために使用されます。 重要な実装の詳細は次のとおりです。`last`これにより、各新しいインデックスが各ビットの最新のインデックスにのみ接続され、二次比較が回避されます。 以前の接続はすでに推移的にキャプチャされているため、ユニオン操作で十分です。 

値は最大 300,000 であり、19 ビット内に収まるため、ビット反復は 20 で制限されます。

 ## 特殊なケース

 重要なエッジケースは、有効な値の間にゼロが現れる場合です。 入力用`[1, 0, 2]`, インデックス 2 はどの結合にも参加しません。 アルゴリズムは、ビットが設定されていないため、正しく分離されたままになります。`last`更新されることはなく、結合も発生しません。 

もう 1 つのケースは、同じビット パターンを持つ値が繰り返される場合です。 のために`[7, 7, 7]`、各インデックスはすべての共有ビットを介して前のインデックスと結合し、DSU はそれらを 1 つのコンポーネントにマージします。 重複した結合は DSU によって無視されるため、アルゴリズムは二重にカウントしたり、冗長な構造を作成したりしません。 

さらにエッジ ケースには、接続に直接のオーバーラップではなく中間インデックスを介したチェーンが必要な、まばらなビット分散が含まれます。 の`last`配列では、すべての新しい出現がそのビットの既存のコンポーネントにリンクされ、接続が前方に伝播されるため、そのような連鎖が確実に保持されます。
