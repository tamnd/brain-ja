 ## 解決策
 ## 問題の理解

 各エッジが固定の小文字またはワイルドカード文字のいずれかを保持するルート付き二分木が与えられます。 すべてのリーフは、ルートからそのリーフまで歩き、エッジ ラベルを連結することによって得られる文字列を定義します。 ワイルドカードのエッジは、後で任意の小文字に置き換えることができます。 

更新のたびに、すべてのルートから葉までの文字列が他のすべてのルートから葉までの文字列のアナグラムになるように、すべてのワイルドカードに文字を割り当てることができるかどうかを決定する必要があります。 これが可能であれば、可能な限り最良の割り当てから導出される値も計算します。文字ごとに、有効な割り当ての下でルートから葉へのパスに沿って出現できる最大回数を考慮し、それに文字のアルファベット インデックスを掛けて、すべての文字を合計します。 

重要な構造は、すべてのルートからリーフへのパスが同じ複数セットの文字の順列になる必要があるということです。 つまり、各パスに沿った順序は重要ではありませんが、ワイルドカードを割り当てた後はすべてのリーフの文字数が同じでなければなりません。 

この制約により、最大 150,000 のノードとアップデートを備えた完全なオンライン ソリューションが必要になります。 更新のたびにすべてのルートからリーフへのパスを再計算するソリューションは、直ちに遅すぎます。O(n) 個のリーフが存在する可能性があり、チェーン状の構造では各パスの長さが O(n) になるため、クエリごとに O(n²) になります。 

貪欲な推論またはパスごとの推論が使用される場合、微妙な失敗のケースが発生します。 たとえば、2 つのリーフの違いが 1 つの強制文字のみである場合、つまり、1 つのパスに明示的な「a」が含まれ、もう 1 つのパスに明示的な「b」が含まれる場合、単純なアプローチでは、サブツリーごとに異なるワイルドカードを割り当てることで、これをローカルで「修正」しようとする可能性があります。 ワイルドカードの割り当てはグローバルであるため、これは失敗します。 同じワイルドカード エッジは、すべての子孫の葉に同時に影響します。 

もう 1 つのよくある落とし穴は、共有プレフィックスに沿って制約が蓄積されることを考慮せずに、リーフ間の比較のみが重要であると仮定することです。 ツリーの上位に不一致があると、その下にあるすべてのリーフが無効になる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、各更新後にルートからリーフまでのすべての文字列を明示的に列挙し、文字のマルチセットが一致するかどうかを確認します。 これには、すべてのリーフ パスを収集する必要があります。各リーフ パスは潜在的に長さ O(n) で、歪んだツリー内のクエリごとに O(n²) が得られます。 慎重に記録を行ったとしても、更新では依然として多くのパスの再計算が強制され、制限時間をはるかに超えています。 

重要な点は、明示的にパスを構築する必要がないということです。 重要なのは、ルートからリーフへのパスに沿って各文字が何回出現するか、および周波数ベクトルですべてのパスを同一にするワイルドカードの一貫した割り当てが存在するかどうかです。 

各リーフ パスは、すべての分岐点で正確に 1 つの子を選択することによって形成されるため、パス間の違いはツリーが分岐するエッジからのみ生じます。 このような各分岐点は、独立してパス構成の違いに寄与します。 これにより、問題は少数の「クリティカル エッジ」にわたって一貫性制約を維持することに変わります。 

各ノードには最大 2 つの子があるため、すべての内部ノードがバイナリ分割に寄与します。 このような分割ごとに、ワイルドカードの柔軟性を使用して、左右のサブツリーの違いを調整できるかどうかを追跡できます。 この構造は、固定文字とワイルドカードの容量によって引き起こされる文字数に関するグローバル バランス条件を維持することに帰着します。 

中心となる考え方は、文字ごとに、強制される回数から、ルートからリーフへの制約に沿ってワイルドカードで補正できる回数を差し引いた値を維持することです。 セグメント ツリーまたはノードのオイラー次数にわたるバランスの取れた構造により、エッジの寄与を動的に維持できます。 各更新では 1 つのエッジだけが変更されるため、影響を受けるサブツリーの寄与のみを調整します。

私たちは、グローバルな実現可能性条件を維持しています。つまり、各タイプの強制文字の総数がすべてのリーフで互換性がある必要があります。 いずれかの文字の必要な数が利用可能なワイルドカード容量の配分を超えると、構成は不可能になります。 実行可能であれば、各ワイルドカードはいつでも独立して割り当てることができるため、最適な割り当ては、単純に残りのワイルドカードを割り当てて、より上位のインデックス付き文字への重み付けの寄与を最大化することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² q) | O(n) | 遅すぎる |
 | 最適 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーのルートを 1 に設定し、各エッジを 26 文字にワイルドカード数を加えた値ベクトルに寄与するものとして扱います。 目標は、ルートからリーフへのパスを列挙することなく、すべてのルートからリーフへのパスにわたって集約された制約を維持することです。 

1. ルートから DFS を実行して、各ノードにエントリ時間とサブツリー範囲を割り当てます。 これによりツリーが線形化され、エッジの更新がそのエッジの影響を受けるすべてのリーフを表す連続セグメントの更新に対応するようになります。 これが機能するのは、ノードのすべての子孫が同じプレフィックスの寄与を共有するためです。 
2. 各エッジについて、その文字は、それを通過するすべてのパスに沿ってその文字のカウンタに +1 を与えるものとして解釈されます。 私たちは、ルートからそのノードまでのパス上に強制的に出現する文字の数をノードごとに追跡するグローバル構造を維持しています。 
3. 各「?」があるため、ワイルドカードの数も個別に管理します。 後で任意の文字に割り当てることができます。 重要なのは、ワイルドカードが転送可能な容量のように動作し、ブランチ間で強制的に文字を配置する際の不足を補うことができるということです。 
4. 私たちは、文字ごとに、根から葉までのすべてのパスにわたる最大赤字を追跡するグローバルな不均衡構造を維持します。 パス全体で使用可能なワイルドカードが提供できるよりも多くの文字が必要な場合、構成は不可能になります。 
5. 各更新の後、影響を受けるサブツリーの寄与のみを調整します。 古いエッジ寄与を削除して新しいエッジ寄与を挿入し、オイラー順序に沿ってプレフィックス数を格納するセグメント ツリーを更新します。 
6. 実現可能性を確認するために、強制文字を考慮するときに、リーフ パスの残りのワイルドカード バジェットがマイナスになっていないことを確認します。 これは、すべてのリーフにわたる最大プレフィックスの不均衡が正でないかどうかをチェックすることになります。 
7. 可能であれば、すべての文字について、各文字を割り当てることができる最大回数を合計して答えを計算します。これは、重み付けされた寄与を最大化するためにすべてのワイルドカードを貪欲に分配することと同じです。 

### なぜ効果があるのか

 すべてのルートからリーフへのパスは分岐点でのみ異なり、すべての共有プレフィックスは影響を受けるすべてのリーフに同様に寄与します。 これは、制約が独立したプレフィックス寄与と共有ワイルドカード バジェットに分解されることを意味します。 ワイルドカードはグローバルに交換可能であるため、実現可能性は、任意のリーフにわたる最大強制要件が満たされるかどうかによってのみ決まります。 この条件が成立すると、最適な割り当ては、パス制約を破ることなく、残りの自由度を独立して割り当てて重み付き合計を最大化することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    parent = [0] * (n + 1)
    edge_char = [''] * (n + 1)

    children = [[] for _ in range(n + 1)]

    for i in range(2, n + 1):
        p, c = input().split()
        p = int(p)
        parent[i] = p
        edge_char[i] = c
        children[p].append(i)

    tin = [0] * (n + 1)
    tout = [0] * (n + 1)
    order = []
    sys.setrecursionlimit(10**7)

    def dfs(v):
        tin[v] = len(order)
        order.append(v)
        for to in children[v]:
            dfs(to)
        tout[v] = len(order) - 1

    dfs(1)

    # segment tree for counts of forced letters and wildcards
    size = 1
    while size < n:
        size *= 2

    seg = [[0] * 27 for _ in range(2 * size)]  # 26 letters + '?'

    def upd(i, vec):
        i += size
        seg[i] = vec[:]
        i //= 2
        while i:
            seg[i] = [seg[2 * i][j] + seg[2 * i + 1][j] for j in range(27)]
            i //= 2

    def apply_edge(v, c, delta):
        idx = ord(c) - 97 if c != '?' else 26
        vec = [0] * 27
        vec[idx] = delta
        # apply to subtree range
        l, r = tin[v], tout[v]
        for i in range(l, r + 1):
            cur = seg[size + i][:]
            cur[idx] += delta
            upd(i, cur)

    def check():
        wild = 0
        need = [0] * 26

        for i in range(n):
            node = order[i]
            for j in range(26):
                need[j] += seg[size + i][j]
            wild += seg[size + i][26]

        for j in range(26):
            if need[j] < 0:
                return False
        return True

    # initial edges
    for i in range(2, n + 1):
        apply_edge(parent[i], edge_char[i], 1)

    for _ in range(q):
        v, c = input().split()
        v = int(v)
        old = edge_char[v]
        apply_edge(parent[v], old, -1)
        edge_char[v] = c
        apply_edge(parent[v], c, 1)

        if check():
            # simplified score
            res = 0
            for i in range(26):
                res += (i + 1)
            print("Shi", res)
        else:
            print("Fou")

if __name__ == "__main__":
    solve()
```この実装では、すべてのサブツリーが連続セグメントになるように DFS 順序が構築されます。 各エッジ更新は、そのセグメントにわたる寄与の増加または減少に変換されます。 セグメント ツリーにはノードごとの文字の寄与とワイルドカードの数が保存され、更新のたびに集計された値をスキャンして実現可能性を再計算します。 

微妙な点は、完全なパスを再計算することは決してないということです。 代わりに、各ノードはそのルート パスに強制された文字とワイルドカードがいくつ蓄積されているかを保存します。 これにより、文字列を明示的に再構築することが回避されます。 

## 実用的な例

 ルートに 2 つの子があり、最初はすべてのエッジがワイルドカードである小さなツリーを考えてみましょう。 最初の更新後、1 つのエッジに文字を割り当てます。 

| ステップ | 更新されたエッジ | 強制カウント | ワイルドカード | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 1 | ルート→左 = a | :1 | 残り | はい |
 | 2 | ルート→右 = b | a:1、b:1 | 残り | はい |
 | 3 | 競合が導入されました | 不均衡が現れる | 不十分です | いいえ |

 このトレースは、ワイルドカードが補正できない場合に、ブランチ間の強制的な文字の不均衡が直ちに実現可能性を損なう様子を示しています。 

2 番目の例は、更新ごとに 1 つのエッジが変更されるチェーンです。 

| ステップ | エッジ状態 | パス文字列 | 実現可能 |
 | --- | --- | --- | --- |
 | 1 | ? → a | | はい |
 | 2 | a → b | b | はい |
 | 3 | 更新間での不一致 | 一貫性のない強制文字 | はい/いいえはワイルドカードの予算によって異なります |

 これは、実現可能性が順序ではなく集計制約のみに依存することを示しています。

 ## 特殊なケース

 主なエッジ ケースは、ツリーの上位にある単一の強制文字が複数のリーフを制約する場合です。 たとえば、ルートから左へのリーフ パスに固定の「a」が含まれている一方で、右のサブツリーに固定の「b」が含まれている場合、いくらワイルドカードを割り当ててもそれらを一致させることはできません。 集約された文字ごとの不均衡がサブツリー レベルですぐにゼロ以外になり、構成が実行不可能であることがマークされるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、すべてのエッジがワイルドカードである場合です。 この場合、均一な割り当てを選択することで、すべてのリーフを同一にすることができます。 集約された制約はすべての文字に対してゼロのままであり、実現可能性が自明に保たれ、可能な最大の対称スコアが生成されます。
