 ## 問題の理解

 マルチセットのような長さの配列が与えられます。$2^k$、すべての値はサイズの順列のインデックスと同じ範囲にあります。$2^k$。 課題は、この配列を次のように「説明」できるかどうかを判断することです。以下の数の完全な順列が 2 つ存在します。$0$に$2^k-1$、彼らに電話してください$p$そして$q$、それぞれの位置が$i$満足する$a_i = p_i \oplus q_i$。 

したがって、直接構築する代わりに$a$、XOR が観測値を与える 2 つの隠れた順列ラベルに分解しようとしています。 すべてのインデックスは 1 つのペアにのみ参加します$(p_i, q_i)$、各整数は各順列で 1 回だけ出現します。 

これにより、問題はハイパーキューブ上の構造化されたペアリングの問題に変わります。$[0, 2^k-1]$、各位置は、XOR が次のように固定されるラベルのペアを選択します。$a_i$。 

制約$k \le 12$せいぜい意味する$4096$要素。 これは順列に対する指数関数的な検索には大きすぎますが、許容できるほど小さいです。$O(n^2)$または$O(n \log n)$慎重にグループ化したスタイルの構造。 全ビット空間にわたる XOR の構造は、直接代入ではなくバイナリ マスクとインボリューションを使用することを強く示唆しています。 

素朴な間違いは、貪欲に考えて、未使用の値を選択することです。$p_i$、その後強制的に$q_i = p_i \oplus a_i$、続けます。 これは失敗します。なぜなら、初期の選択では、たとえグローバルな解決策が存在しても、残りの値を一貫してペアにすることができない状況が生じる可能性があるからです。 たとえば、2 つの異なる位置で、同じ XOR パートナーを使用する互換性のないペアリングが必要な場合、ローカルの貪欲さが順列の有効性を壊します。 

それぞれの値を仮定すると、別の微妙な失敗が発生します$x$と独立して一致させることができます$x \oplus a_i$すべてのインデックスの使用を調整する必要はありません。 この制約はグローバルです。各数値は両方の順列で 1 回だけ出現する必要があります。

 ## アルゴリズムのチュートリアル

 問題を各インデックスに割り当てるものとして再解釈します$i$注文されたペア$(p_i, q_i)$2 つの異なる未使用の数値を消費し、その XOR が等しい$a_i$。 課題は、すべての数値が確実に 1 回だけ使用されるようにすることです。 

1. の各値の頻度を数えます。$a$。 これらの頻度は、特定の XOR 値で実現する必要があるエッジの数を表します。 これらの要求を満たすために要素を一貫してペアにすることができない場合、構築は失敗します。 
2. 未使用の番号の構造を維持します。$0$に$2^k - 1$。 最初は、両方の番号ですべての番号が使用可能です$p$そして$q$。 
3. 制御された順序で値を処理します。通常はすべての数値を反復処理します。$x$そしてそれをとして割り当てようとしています$p$-価値。 選ばれた人のために$x$、未使用のインデックスを見つける必要があります$i$いくつかの$a_i$そのような$y = x \oplus a_i$こちらも未使用です。 これにより、有効なペアを形成できることが保証されます。 
4. このようなインデックスを選択したら$i$、修正します$p_i = x$そして$q_i = y$、両方にマークを付けます$x$そして$y$使用済みとして。 また、次の頻度も減らします。$a_i$。 
5. いずれかの時点で、選択した未使用の番号に対して有効なペアが存在しない場合、その番号は順列一貫性のある割り当てに出現できないため、構築は失敗します。 
6. すべての数字が消費されるまで続けます。 すべてのインデックスが割り当てられ、すべての数値が 1 回だけ使用される場合は、構築された順列を出力します。 

隠されたメカニズムは、割り当てが成功するたびに、実現可能性を維持しながら問題のサイズを永続的に縮小することです。ペアが固定されると、どちらのエンドポイントも再利用できなくなり、置換制約が反映されます。 

### なぜ効果があるのか

 核となる不変条件は、すべての代入で 2 つの未使用の数値と 1 つの未使用の XOR 要件が削除され、グローバル ソリューションが存在する場合、すべての削除で残りを完了できる可能性が保持されるということです。 XOR 構造により、有効なグローバル ペアが存在する場合、常に選択できることが保証されます。$x$そして$i$そのような$x \oplus a_i$も使用されません。そうしないと、一部の値がすべての可能なペアから分離され、間の完全な全単射の存在と矛盾するからです。$p$そして$q$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    n = 1 << k
    a = list(map(int, input().split()))
    
    freq = {}
    for i, v in enumerate(a):
        freq[v] = freq.get(v, 0) + 1

    used_p = [False] * n
    used_q = [False] * n
    used_num = [False] * n

    p = [-1] * n
    q = [-1] * n

    # map value -> list of indices with that value
    pos = {}
    for i, v in enumerate(a):
        pos.setdefault(v, []).append(i)

    # we will greedily build pairs
    # iterate over all numbers as potential p-values
    for x in range(n):
        if used_num[x]:
            continue
        # try to pair x
        found = False
        for v in range(n):
            if v not in pos or not pos[v]:
                continue
            y = x ^ v
            if y >= n or used_num[y]:
                continue

            i = pos[v].pop()
            if i is None:
                continue

            p[i] = x
            q[i] = y
            used_num[x] = True
            used_num[y] = True
            found = True
            break

        if not found:
            print("Fou")
            return

    print("Shi")
    print(*p)
    print(*q)

if __name__ == "__main__":
    solve()
```このコードは、未使用の番号を候補として繰り返し選択することで答えを構築します。$p$-側で、互換性のある未使用のパートナーとペアリングします。$q$-側。 辞書`pos`各 XOR 値の残りのインデックスを保存し、各 XOR 値が確実に$a_i$は 1 回だけ使用されます。 

重要な点は、数値が使用済みとしてマークされると、その後のペアリングに参加できなくなり、ローカルではなくグローバルに置換制約が適用されることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列内のすべての値が 0 である場合です。 その状況では、すべてのペアが満足する必要があります$p_i = q_i$これは、両方が異なる値の順列であるという要件に真っ向から矛盾します。 2 つの異なる未使用の数値は再利用せずに XOR ゼロのペアを満たすことができないため、アルゴリズムはこれを検出します。 

もう 1 つのエッジ ケースは、XOR 値に大きな偏りがあり、一部の値クラスが早期に枯渇し、ペアにできない孤立した数値が残る場合です。 このような分離が発生すると、貪欲な構築は正確に失敗し、入力が正しく拒否されます。
