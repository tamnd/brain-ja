 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、考えられるすべての連続する部分文字列を調べます。 各部分文字列について、3 つの文字がすべて同一である 3 つの等間隔の位置のパターンが含まれているかどうかを知りたいと考えます。 具体的には、部分文字列内でインデックスを検索します。$x < x+k < x+2k$これらの位置の文字が同じになるようにします。 

タスクは、そのようなパターンがいくつ存在するかを数えることではなく、部分文字列の中に少なくとも 1 つの有効なパターンが含まれる部分文字列の数を数えるということです。 

これを言い換えると、長さ 3 の有効な等差数列はすべて、それを「カバーする」部分文字列のセットを定義するということになります。 部分文字列にそのようなトリプルの最初と最後の位置が含まれる場合、その部分文字列には自動的にトリプル全体が含まれます。 

文字列の長さは最大 300,000 になる可能性があるため、すべての部分文字列またはすべてのトリプルを 2 次または 3 次の方法で明示的にチェックするソリューションは失敗します。 部分文字列の単純な列挙はすでに$O(n^2)$それぞれの内部のパターンをチェックすると、次のようにプッシュされます。$O(n^3)$、それは不可能です。 ポジションのすべてのペアを列挙するだけでも、最悪の場合には大きすぎます。 

微妙なエッジ ケースとしては、すべて同じ文字が含まれる文字列があります。 その場合、インデックスのすべての等差数列は有効なトリプルを形成し、少なくとも 1 つのトリプルを含む部分文字列の数は急速に増加します。 すべてのトリプルを明示的に生成しようとするソリューションでは、誤って 2 次の動作に移行しないように注意する必要があります。 

もう 1 つの注意が必要なケースは、次のような文字列を交互に使用することです。`010101`。 ここでは、有効なトリプルは存在しますが、まばらであり、正しい解決策としては、単に繰り返される文字を含むだけで適切な等差数列を含まない部分文字列を過剰にカウントすることを回避する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての部分文字列について$[l,r]$、その中にあるすべての可能なトリプルをスキャンし、$(x, x+k, x+2k)$等価条件を満たします。 これは正しいですが、非常に遅いです。$O(n^2)$部分文字列と各スキャンには時間がかかる場合があります$O(n)$、につながる$O(n^3)$時間。 

重要な観察は、すべての有効なトリプルがその端点と中間点によって完全に決定されるということです。 真ん中のインデックスを修正すると$j$の場合、2 つのエンドポイントはそれを中心に対称である必要があります。$i = j - k$そして$k = j + k$、次のように書き換えることができます$i = 2j - r$正しいエンドポイントを修正するとき$r$。 この対称性により、問題を「部分文字列のチェック」から「固定された右端点に対して部分文字列がどこまで左から開始できるかをカウントする」という問題に変換できます。 

部分文字列について直接考える代わりに、視点を逆転させます。 右端ごとに$r$、最小のインデックスを計算します$L(r)$すべての部分文字列が$[l,r]$と$l \leq L(r)$少なくとも 1 つの有効なトリプルエンドがその前に含まれています$r$。 一度$L(r)$知られているので、正確に貢献します$L(r)$で終わる有効な部分文字列$r$。 

私たちは計算します$L(r)$考えられるすべての中間位置をスキャンすることにより$j < r$と同じ性格を持つ$s[r]$。 そういったそれぞれに対して$j$、対応する左端点は次のとおりです。$i = 2j - r$。 これなら$i$有効な場合、トリプルを形成します$(i, j, r)$。 すべての候補者の中で、最小限のものを採用します$i$トリプルが早く始まるほど、より多くの部分文字列がカバーされるためです。 

問題の構造により、各位置が中間インデックスとして限られた数の意味のある遷移のみに関与することが保証され、文字ごとの出現に対して償却された線形スキャンが可能になります。

 ## アルゴリズムのチュートリアル

 各文字の位置のリストを維持しながら、文字列を左から右に処理します。 

1. インデックスを文字に基づいて 2 つのリストに分割します。`0`そして1つは`1`。 これにより、等しい文字を持つトリプルのみを考慮できるようになります。 
2. 各右端点について$r$、インデックスのみを検査します$j < r$～と同じ性格を共有するもの$s[r]$。 これらは、で終わる有効な対称トリプルを形成できる唯一の候補です。$r$。 
3. 各中間ポジション候補について$j$、暗黙の左端点を計算します。$i = 2j - r$。 これは、等差数列で等間隔を強制することから直接得られます。 
4. 有効な最小値を追跡します。$i$すべての候補者にわたって。 有効でない場合$i$存在する場合、トリプルエンドは存在しません$r$。 
5. 最小限の場合$i$存在する場合、それ以前で始まるすべての部分文字列を意味します$i$そして終わる$r$少なくとも 1 つの有効なトリプルが含まれているため、次のように追加します。$i$答えに。 
6. 次へ進む$r$アクティブな候補セットを更新します$j$それに応じて位置を決めます。 

核となる不変条件は、それぞれの$r$、で終了する有効なトリプルの可能な限り最も早い開始点を正確に識別します。$r$。 すべての有効なトリプルは 1 つのペアに正確に対応します$(j, r)$このようなすべてのトリプルには一意の中間インデックスがあるため、それを見逃すことはありません。 逆に、計算されたすべての候補トリプルは、等間隔と等しい文字を強制するため、構築上は有効です。 この 1 対 1 の対応により、右端点ごとに最小の左端点を数えることで、重複や省略のない有効な部分文字列の数が正確に数えられるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos = {'0': [], '1': []}
    for i, c in enumerate(s, 1):
        pos[c].append(i)

    ans = 0

    for r in range(1, n + 1):
        c = s[r - 1]
        best_i = n + 1

        # iterate over positions j of same character
        lst = pos[c]

        # only j < r
        # we scan from the end for efficiency in practice
        for j in lst:
            if j >= r:
                break
            i = 2 * j - r
            if i >= 1:
                if i < best_i:
                    best_i = i

        if best_i != n + 1:
            ans += best_i

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、エンドポイントごとに関連する中間の位置のみを検査するように 2 つの位置リストが構築されます。 計算$i = 2j - r$等差数列条件を直接エンコードします。 

ループが一度切れる$j$到達する$r$、位置は昇順に保存されるためです。 計算された最小値$i$が最有力候補として残されています。 候補が存在しない場合、正しいエンドポイントは何も寄与しません。 

よくある落とし穴は、それを忘れることです$i$少なくとも 1 のままでなければなりません。そうでない場合、トリプルは無効になります。 もう 1 つは、等しい文字のすべてのペアが有効なトリプルを生成すると仮定することですが、これは間隔条件が成立しない限り正しくありません。

 ## 特殊なケース

 単一文字の文字列には可能なトリプルが含まれていないため、完全な等差数列を生成するための有効な中間インデックスがないため、アルゴリズムは自然にゼロを生成します。 

繰り返される文字を含まない文字列。例:`0101`、有効な結果が生成されることはありません$i = 2j - r$これは文字列内にあるため、すべての候補が破棄され、答えはゼロのままになります。 

次のような完全に均一な文字列`111111`は多くの候補ペアを生成しますが、最小左エンドポイント ロジックにより、各右エンドポイントは可能な限り早いトリプルごとに 1 回のみ寄与することが保証され、有効な進行の密な構造にもかかわらず、過剰カウントが防止されます。
