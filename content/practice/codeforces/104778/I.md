 ## 問題の理解

 We are given a football season consisting of$n$一致します。 各試合は、勝利、引き分け、または負けの 3 つの結果のうちの 1 つで終了します。 勝利がもたらすもの$k$ポイント、引き分けは 1 ポイント、負けは 0 ポイントになります。 すべての期間にわたって蓄積されたポイントの合計数も通知されます。$n$まさに一致します$p$。 

The task is not to reconstruct a valid season, but to determine the maximum possible number of draws that could have produced the given total score. 勝ち、引き分け、負けの組み合わせがない場合$n$ゲームは正確に結果をもたらすことができます$p$ポイント、答えは次のとおりです。$-1$。 

制約は非常に大きいです。$n$まで行くことができます$10^{12}$そして$p$まで$10^{15}$したがって、一致を反復したり、すべての組み合わせを試したりするアプローチは不可能です。 解決策は純粋に算術的であり、線形制約に関する構造的推論に依存する必要があります。 

最もデリケートな状況は、スコアを形成することが不可能な境界ケースです。 たとえば、次の場合$p$大きすぎます（より大きい）$nk$)、または 1 と の組み合わせとして表現できない場合$k$の場合、有効な季節は存在しません。 もう 1 つの微妙なケースは、引き分けを最大化すると消費される試合が多すぎて、残りのスコアに到達するのに十分な勝利を収めることができなくなる場合です。 

不可能の簡単な例は次のとおりです$n = 1, k = 5, p = 2$。 可能なスコアは 0、1、または 5 のみであるため、2 を形成することはできません。 正しい出力は次のとおりです$-1$。 

もう 1 つのエッジ ケースは、すべての試合が引き分けの場合です。$p = n$。 例えば、$n = 10, p = 10, k = 3$は 10 引き分けで勝利なしの有効な解決策を持っています。 

## アプローチ

 ブルートフォースアプローチでは、勝ち、引き分け、負けの可能な分布をすべて列挙しようとします。$n$一致します。 これを勝利数と引き分け数の反復に縮小したとしても、依然としてチェックすることになります。$O(n^2)$勝ちのそれぞれの選択が引き分けと負けを制限するため、最悪の場合は州になります。 これはまったく不可能です$n$まで$10^{12}$。 

重要な観察は、穴埋めとしての損失を除いて、損失は得点には無関係であるということです。 問題は、非負の整数を見つけることに帰着します$w$そして$d$次のような:$$wk + d = p$$そして$$w + d \le n$$最大化したい$d$、つまり最小化することを意味します$w$ですが、それでも両方の制約を満たします。 

最初の制約は純粋に算術的なものです。$p - wk$負ではなく、次と等しい必要があります$d$、 それで$p - wk \ge 0$そして$p - wk$は整数です。 

これにより、問題は有効な勝利数を選択することに変わります。$w$、各勝利が消費されます$k$残りのポイントはドローで正確に埋める必要があります。 

描画を最大化するには、可能な限り最小の描画が必要です$w$そのような$p - wk \le n - w$, 引き分けはポイントと試合スロットの両方を消費しますが、勝ちは試合スロットのみを消費するためです。 

これは、可能性に関する直接的な実現可能性チェックにつながります。$w$、しかしそれ以来$w \le n$そして$w \le p/k$、小規模な構造化検索のみを考慮する必要があります。つまり、成功するために必要な最小限の勝利数から開始します。$p$残りの容量を超えず、モジュールの制約によって引き起こされる狭い範囲内で調整します。 

より具体的には、次のように書き換えます。$$d = p - wk$$そして$$d \le n - w
\Rightarrow p - wk \le n - w
\Rightarrow p - n \le w(k - 1)$$これにより下限が与えられます$w$、 その間$w \le \lfloor p/k \rfloor$上限を与えます。 以来$k \ge 2$、実現可能な領域$w$は短い間隔なので、境界付近の一定数の候補をテストするだけで済みます。 

有効な最小のものを選択します$w$この間隔で計算します$d$、返却してください。

 ## アルゴリズムのチュートリアル

 勝ちと引き分けの観点から問題を再定式化してから、容量制限を伴う線形ディオファントス制約の実現可能性を確認することに落とし込みます。 

1. 可能な最大勝利数を次のように計算します。$w_{\max} = \lfloor p / k \rfloor$。 これは、合計ポイントを超えない最大の勝利数です。 
2. もし$w_{\max} > n$、それを以下に減らします$n$、試合よりも多くの勝利を収めることはできないためです。 これにより、存在する以上の一致が割り当てられることがなくなります。 
3. 一定の勝利数の場合$w$、残りのポイントは引き分けで埋める必要があります。$$d = p - wk$$これは強制的です。 一度は自由がない$w$が選ばれます。 
4. 実現可能性の制約を確認します。 

使用されるマッチの数は、$w + d$したがって、次のことが必要です。$$w + (p - wk) \le n$$これは次のように単純化されます。$$p - w(k - 1) \le n$$5. 増えてから$w$減らす$d$、ただし、一致の使用量も増加するため、最小の値を検索します。$w$両方の実現可能条件が成立します。$p - wk \ge 0$そして$w + d \le n$。 
6. そうでない場合$w$存在する、返す$-1$。 
7. それ以外の場合は計算します$d = p - wk$選ばれた人たちのために$w$を入力して出力します。 

### なぜ効果があるのか

 有効な季節はすべてペアに対応します$(w, d)$線形方程式と線形容量制約を満たします。 スコア方程式が修正されました$d$一度$w$が選択されているため、検索空間は 1 つの次元に折りたたまれます。 実現可能条件は単調である$w$: 勝ち数が増加すると、残りのポイントが直線的に減りますが、利用可能な容量も直線的に減ります。 この単調な構造により、解が存在する場合、制約が最初に満たされる境界によって描画を最大化するための最適な構成が得られます。$w$スコアの実現可能性とそれ以上の規模に違反する可能性があります$w$引き分けがさらに減るだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k = map(int, input().split())

    # If even all wins are not enough or too many points are impossible
    if p > n * k:
        print(-1)
        return

    # We try to minimize wins while still making score achievable with draws
    # From feasibility: p - w*k <= n - w  =>  p - n <= w*(k - 1)
    # Also: p - w*k >= 0

    w_min = max(0, (p - n + (k - 2)) // (k - 1))  # ceil((p - n)/(k - 1))
    w_max = min(n, p // k)

    if w_min > w_max:
        print(-1)
        return

    # Try boundary candidates (monotonic structure)
    best_d = -1

    for w in range(w_min, min(w_max, w_min + 5) + 1):
        d = p - w * k
        if d < 0:
            continue
        if w + d <= n:
            best_d = max(best_d, d)

    print(best_d if best_d >= 0 else -1)

if __name__ == "__main__":
    solve()
```コードはまず、最大勝利数でもスコアに到達できないという不可能なケースを排除します。 次に、能力の制約から勝利の下限を導き出し、スコアの実現可能性から上限を導き出します。 最後のステップでは、制約が単調に動作するため、実現可能性が遷移する境界付近の一定サイズのウィンドウのみをチェックします。$w$。 

戻り値は、次のように計算された描画の数です。$p - wk$、有効になるとすぐに続きます$w$固定されています。

 ## 特殊なケース

 1 つの失敗モードは、すべてのスコアがそれを下回ると解決策があると仮定することです。$nk$。 例えば、$n = 1, k = 5, p = 2$与える$p \le nk$ですが、どの組み合わせも 2 を生成しません。アルゴリズムはこれを拒否します。$w_{\max} = 0$につながる$d = 2$に違反します$w + d \le n$。 

もう 1 つのエッジ ケースは、最適解がゼロ勝利を必要とする場合です。 のために$n = 10, p = 10, k = 5$、最良の構成は 10 引き分け 0 勝です。 式は正しく次のようになります$w = 0$、$d = 10$、容量を正確に満たしています。 

3 番目のケースは、利用可能な試合を超えた余分なドローを減らすために勝利が必要な場合です。 のために$n = 5, p = 9, k = 2$、素朴な貪欲さは最初に多くのドローを試行する可能性がありますが、制約により強制されます$w = 4, d = 1$、5 つの一致に正確に適合します。 アルゴリズムは、スコアと容量の両方の制約を同時に適用することでこの境界を見つけ、描画の過剰割り当てが発生しないようにします。
