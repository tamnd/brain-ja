 ## 解決策
 ## 問題の理解

 3 つの剛体セグメントの長さを表す 3 つの正の整数が与えられます。 1 回の移動で、任意の 1 つのセグメントを選択し、変更後にセグメントが正の値を維持している限り、その長さを 1 単位だけ変更して増加または減少させることができます。 

目標は、これら 3 つの長さを、非縮退三角形を形成できるトリプルに変換することです。 つまり、結果として得られる 3 つの長さはすべての三角形不等式を厳密に満たす必要があるため、各辺は他の 2 つの辺の合計よりも厳密に小さくなければなりません。 このような単位変更の必要最小限の数が求められます。 

各操作は 1 つのセグメントに ±1 だけ影響を与えるため、支払うコストは、元のトリプルと最後に選択されたトリプルの間の L1 距離の合計となります。 

制約は値ごとに最大 10^6 であるため、考えられるすべての最終トリプルを探索したり、変更を段階的にシミュレートしようとするソリューションは直ちに実行不可能になります。 状態に対する単純な BFS や、可能な最終的な長さの強引な列挙には、座標ごとに数百万のオーダーの検索スペースが必要になり、少なくとも 10^18 の組み合わせになりますが、これはまったく不可能です。 

いくつかの危険な状況は、早めに切り分ける価値があります。 

3 つのセグメントがすでに三角不等式を厳密に満たしている場合 (たとえば 3、4、5)、答えはゼロになります。 「とにかく調整」しようとする不用意な解決策は、不必要な変更を誤って導入することになります。 

2 つの辺の合計がすでに 3 番目の辺と正確に一致している場合 (1、2、3 など)、形状は縮退しています。 厳密に等価性を破らなければなりません。つまり、少なくとも 1 つの単位の変更が必要です。 非厳密な不等式のみをチェックするソリューションでは、このケースが誤って有効であると認識されてしまいます。 

もう 1 つの微妙なケースは、1、1、100 など、一方の辺が他の 2 つの合計よりもはるかに大きい場合です。これを最適に修正するには、両方の小さな辺を増やすか、大きな辺を減らすことができることを理解する必要があり、構造がなければ最適な戦略は明らかではありません。 

## アプローチ

 強引な解釈では、正の整数の最後のトリプルをすべて考慮し、有効な三角形を形成するかどうかを確認しながら、元のトリプルをそれに変換するコストを計算します。 各候補トリプルのコストは |a − a'| です。 + |b − b'| + |c − c'|。 到達可能なすべてのターゲットを直接評価するため、これは原理的には正しいです。 

問題は規模だ。 各辺は 1 からおおよそ max(a, b, c) まで、極端な場合には不均衡をプラスまたはマイナスして移動することができ、すでに座標ごとに約 10^6 の可能性が得られます。 全体の空間は立方体になり、たとえ妥当なウィンドウに制限したとしても、候補者の数は時間内に列挙できる数をはるかに超えたままになります。 

重要な観察は、三角形条件が順序付けを通して見ると非常に単純であるということです。 最終的な辺を x ≤ y ≤ z として並べ替えると、条件は x + y > z になります。 この不等式は便利な点で単調です。トリプルがこれに違反する場合、唯一の修正は x または y を増やすか、z を減らすことです。単位ステップでそうすることは、z − (x + y) の「ギャップを埋める」必要がある量に対してコストが線形に動作することを意味します。 

これは、すべてのトリプルを検索すべきではないことを示唆しています。 代わりに、1 つの構造を修正しようとします。つまり、2 つの数値が変更されないか最小限に調整され、3 つ目の数値が不等式を満たすのに十分なだけ調整される構成で終了します。 コストは移動量に対して線形であるため、最適解は常にシステムを境界 x + y = z + 1 (厳密な不等式を満たす最小の整数) まで押し込むことに対応します。これ以上調整してもコストが不必要に増加するだけであるためです。

したがって、問題は、ソート後に最大の辺が他の 2 つの合計より厳密に小さいことを確認するために各辺をどの程度調整する必要があるかを確認し、最も安価な方向に調整することになります。

 ## アルゴリズムのチュートリアル

 ### 1. 3 つの長さを並べ替えます

 a ≤ b ≤ c になるように値を並べ替えます。 これにより、c が a および b と比較して大きすぎるかどうかという、唯一の意味のある制約が分離されます。 ソートにより、複数の三角形不等式の順列を個別に考慮する必要がなくなります。 

### 2. すでに有効かどうかを確認します

 a + b > c の場合、トリプルはすでに厳密な三角形を形成しています。 操作は必要ないので、答えはゼロです。 このステップは、これ以上変更を加えてもコストが増加するだけであるという事実を捉えています。 

### 3. 赤字を計算する

 a + b ≤ c の場合、三角形条件は失敗します。 失敗量は、c が許容最大値をどれだけ超えているかを正確に表します。 ギャップ値を定義します。 

ギャップ = c − (a + b) + 1

 これは、厳密な不等式が成り立つために、どれだけ c を減らすか、a + b を増やす必要があるかを表します。 

+1 が表示されるのは、a + b が c よりも厳密に大きい必要があり、等しくないためです。 

### 4. ギャップを運用に変換する

 各操作は片側を 1 ずつ変更するため、a + b − c のすべての改善単位は正確に 1 つの動きに対応します。 a または b を増やすと合計が増加し、c を減らすとしきい値が減少し、どちらも単位のコストが等しくなります。 したがって、最小操作数はまさにギャップです。 

### 5. 結果の出力

 三角形の条件がすでに成立しているかどうかに応じて、0 またはギャップのいずれかを返します。 

### なぜ効果があるのか

 ソート後、三角形の実現可能性は 1 つの線形不等式のみに依存します。 一連の操作では、式 a + b − c が移動ごとに最大 1 だけ変更され、有効な最終状態ではこの式が少なくとも 1 である必要があります。したがって、最小移動数は、この式を初期値から 1 まで押し上げるための最小コストであり、正確には max(0, c − a − b + 1) になります。 あらゆる移動が、不平等を満たすために正確に 1 単位の改善に寄与するため、他の調整方法によってコストを改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c = map(int, input().split())
a, b, c = sorted([a, b, c])

if a + b > c:
    print(0)
else:
    print(c - a - b + 1)
```この解決策は、3 つのセグメントの長さを読み取り、最大値が分離されるようにそれらを並べ替えることから始まります。 これにより、三角形の条件を 1 つのチェックに減らすことができます。 

条件文は、厳密な不等式がすでに成立しているかどうかを直接テストします。 存在する場合は、変更する必要はありません。 

それ以外の場合は、差 c - (a + b) + 1 が計算されます。 この式は、システムを三角形が有効になる境界に到達させるために必要な単位調整の正確な数です。 各操作は、不等式を満たすために正確に 1 単位の改善に寄与するため、ループやシミュレーションは必要ありません。 

## 実用的な例

 ### 例 1: 3 2 6

 並べ替えると、a = 2、b = 3、c = 6 になります。 

| ステップ | | b | c | a + b | 状態 | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 2 | 3 | 6 | 5 | 5 ≤ 6 | 無効です |
 | コンピューティング | - | - | - | - | ギャップ = 6 − 5 + 1 = 2 | 答え |

 ギャップは 2 で、2 つのユニットの改善が必要であることを意味します。 考えられる変換の 1 つは、6 から 5 に減少し、2 から 3 に増加して、三角形の条件を満たす 3、3、5 に達することです。 

このトレースは、どちらの側を変更するかを考える必要がないことを示しています。 重要なのは純不均衡だけです。 

### 例 2: 13 111 57

 並べ替えると、a = 13、b = 57、c = 111 が得られます。 

| ステップ | | b | c | a + b | 状態 | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 13 | 57 | 111 | 70 | 70 ≤ 111 | 無効です |
 | コンピューティング | - | - | - | - | ギャップ = 111 − 70 + 1 = 42 | 答え |

 アルゴリズムは、大きな不均衡が支配的であることを示しており、答えは最大の辺が他の 2 つの合計をどれだけ超えるかによってのみ決まります。 

これらの例は、演算の特定の分布ではなく、ソートされた不等式のみが重要であることを確認しています。

## テストケース```python
import sys, io

def solve():
    import sys
    a, b, c = map(int, sys.stdin.readline().split())
    a, b, c = sorted([a, b, c])
    if a + b > c:
        print(0)
    else:
        print(c - a - b + 1)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided samples
assert run("3 2 6") == "2"
assert run("250 100 200") == "0"
assert run("13 111 57") == "42"

# custom cases
assert run("1 1 2") == "1"
assert run("1 1 3") == "2"
assert run("5 5 5") == "0"
assert run("1 2 1000000") == "999998"

 ## 特殊なケース

 入力 1 1 2 の場合、並べ替えにより 1、1、2 が得られます。小さい方の 2 つの合計が最大であるため、ギャップは 2 − 2 + 1 = 1 となります。アルゴリズムは、2 を 1 に減らす、または 1 の 1 つを 2 に増やすなど、単一単位の変更に対応して 1 を出力します。 

1 1 3 の場合、並べ替えにより 1、1、3 が得られます。ギャップは 3 − 2 + 1 = 2 になります。アルゴリズムは、1 回の移動では厳密な不平等を復元できないため、2 回の調整が必要であることを正確に識別します。 

5 5 5 の場合、5 + 5 > 5 であるため、不等式は直ちに成り立ち、アルゴリズムはギャップ計算分岐に入らずに 0 を返します。 これにより、三角形がすでに存在する場合に不必要な調整が導入されないことが確認されます。
