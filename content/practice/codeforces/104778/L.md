 ## 解決策
 ## 問題の理解

 隣接行列で表される、最大 2000 個の頂点を持つ単純な無向グラフが与えられます。 このグラフから、正確に k 個の異なる頂点を選択する必要があります。 それらの頂点を選択した後、これらの頂点を削除し、単一の新しい頂点 V に置き換えます。 V の隣接関係は交差によって定義されます。V は、選択されたすべての頂点が元々 x に接続されていた場合にのみ、残りの頂点 x に接続されます。 

言い換えれば、V は選択されたすべての頂点に共通するエッジのみを保持します。 タスクは、このマージされた頂点 V が削除されなかったすべての頂点に接続されるように k 個の頂点を選択できるかどうかを決定することです。 そのような選択が存在する場合は、k 個の頂点の有効なセットを出力する必要があり、そうでない場合は -1 を出力します。 

重要な制約は n ≤ 2000 で、これによりおおよそ O(n^2) または O(n^2 log n) の解が許容されますが、定数に応じて O(n^3) 以上のアプローチが境界線になります。 入力自体は n 行 n 列の行列であるため、その読み取りにはすでに O(n^2) のコストがかかります。そのため、ソリューションは理想的にはそのスケールに近い値で動作するはずです。 

微妙な失敗のケースは、選択したセットの外側にある頂点が、選択した 1 つの頂点にさえエッジを欠いている場合に発生します。 その 1 つの欠落エッジにより、最終的な隣接関係にあるその頂点を含むすべての候補セットが削除されます。 たとえば、近傍がわずかに異なる頂点を選択すると、各頂点が個別に高度に接続されている場合でも、それらの交差は急速に縮小し、普遍的ではなくなる可能性があります。 

もう 1 つの特殊なケースは、k が大きい場合、特に n に近い場合です。 k = n − 1 の場合、基本的に、他のすべての頂点との近傍交差が完了している単一の頂点が存在するかどうかを尋ねることになります。これは非常に制限的であり、ローカル ヒューリスティックではなく、慎重なグローバル推論を強いられます。 

## アプローチ

 直接的な総当たり戦略は、k 個の頂点のすべてのサブセットを試し、それらの共通の近傍に残りのすべての頂点が含まれているかどうかを確認することです。 各サブセットについて、隣接セットを交差させることになりますが、これには頂点ごとに O(n) のコストがかかるため、1 回のチェックは O(k・n) となります。 サブセットの数は二項 n から k を選択しますが、最悪の場合は指数関数的となり、n = 50 の場合でも直ちに実行不可能になります。 

重要な観察は、条件がグローバルであるが、選択されたセットの外側の頂点ごとにローカルに書き換えることができるということです。 選択されていない頂点 u を固定します。 V が u に接続するには、選択されたすべての頂点が u に接続されている必要があります。 これは、選択されたセットが u に隣接する頂点のセット内に完全に含まれていなければならないことを意味します。 したがって、各外部頂点には制約が課せられます。つまり、選択されたすべての頂点がその隣接セット内に存在する必要があります。 

したがって、すべての頂点 u は、圧縮後に u が接続されたままである場合に許可される候補のセット S(u) を定義します。 選択されていないすべての u について、すべての S(u) 内にあるサイズ k のセットが必要です。 これは、あまりにも多くの制約に違反しないように k 個の頂点を選択することに相当します。または、より直接的には、補数形式で再解釈できます。 

許可されたセットに基づいて推論する代わりに、視点を反転します。 頂点 v は、選択したセットの外側のすべての頂点に接続されている場合にのみ、選択したセットに含めることができます。 これを直接テストするのは困難ですが、対称性を利用することはできます。頂点 v がいくつかの u に接続されていない場合、v が選択された場合、u は最後に残ったセットに含めることができません。 これにより、相互排他構造が形成されます。 

より生産的な再定式化は、補数グラフを確認することです。 補数グラフでは、エッジは禁止されたペアを表します。 「選択されたすべての頂点が残りのすべての頂点に接続されなければならない」という条件は、選択されたセットが残りの頂点と「悪い相互作用」を持たないことを意味し、最終的には、増大する制約セットに関して相互に一貫性のある頂点から候補セットを貪欲に構築することでチェックできる実現可能性条件に帰着します。

これを解決する標準的な方法は、ソリューションの一部である可能性のある頂点の候補セットを維持することです。 セット外の頂点によって引き起こされる制約を繰り返し適用し、非互換性が検出されるたびに候補プールを縮小します。 最後に残りの一貫したプールから k 個の頂点を抽出できれば、答えは存在します。 

これが機能するのは、すべての制約が隣接行列エントリのレベルでバイナリであるためです。そのため、サブセットを列挙するのではなく、すべての頂点に関する一貫性を同時に維持することで実現可能性を検証できます。

 ## アルゴリズムのチュートリアル

 私たちは、依然として選択の候補となる頂点のセットを維持できるような方法で条件を解釈します。 

1. すべての頂点を潜在的な候補として開始します。 サイズ k の有効な解に参加できない頂点を徐々に削除していきます。 
2. すべての頂点 u について、その隣接ビットマスクまたは隣接セットを計算します。 これにより、他の頂点との互換性条件をすばやくテストできます。 
3. 各頂点 u について、u に隣接しない頂点の数を確認します。 非近傍が多すぎる場合、最終的に残ったセットからそれらすべての非近傍を除外することが許可されない限り、u は有効な解に属することができません。 n − k 個の頂点を選択したセットの外側に保持する必要があるため、これには制約が課せられます。頂点 u を安全に含めることができるのは、互換性のある構成のグラフ内に最大でも n − k 個の非近傍がある場合のみです。 
4. すべての頂点として初期化された候補セット C を維持します。 各頂点 u について、C 内の u に接続されていない頂点の数を計算します。 この数が n − k を超える場合、u は有効な選択の一部になることができず、C から削除されます。これは、競合が多すぎると、選択したセットの外側に多すぎる頂点が強制され、必要な構造のための十分な余地が残らないためです。 
5. すべての頂点を処理した後、候補セット C の頂点の数が k 未満の場合、解は存在せず、-1 を出力します。 
6. それ以外の場合は、C から任意の k 個の頂点を選択し、出力します。 

重要な点は、最終的な補集合を明示的に構築する必要がないことです。 選択されたすべての頂点が、残りの頂点の十分に大きな一貫した構造と共存できることを確認するだけです。 これにより、指数関数的なサブセットの列挙が完全に回避されます。 

### なぜ効果があるのか

 不変条件は、C から削除されたすべての頂点が、有効なサイズ k の選択の一部であることと互換性がないことが証明されていることです。 削除条件により、そのような頂点を含めると、残りのグラフから n − k 個を超える頂点が強制的に除外されます。これは、完全に互換性のある構造を残しながら正確に k 個の頂点を削除するという要件に矛盾します。 したがって、C には常にすべての潜在的に有効な頂点が含まれており、C の任意の k サブセットは、マージされた頂点 V が残りのすべての頂点に接続するために必要なすべての隣接制約を尊重します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    # C = all candidates
    cand = list(range(n))

    # Precompute non-neighbors for each vertex
    non_adj = []
    for i in range(n):
        bad = []
        for j in range(n):
            if i != j and g[i][j] == 0:
                bad.append(j)
        non_adj.append(bad)

    allowed = [True] * n

    for u in range(n):
        cnt = 0
        for v in range(n):
            if allowed[v] and g[u][v] == 0:
                cnt += 1

        # if too many conflicts, u cannot be in solution
        if cnt > n - k:
            allowed[u] = False

    cand = [i + 1 for i in range(n) if allowed[i]]

    if len(cand) < k:
        print(-1)
    else:
        print(*cand[:k])

if __name__ == "__main__":
    solve()
```コードは最初に隣接行列を読み取り、ブール互換性フィルターを構築します。 近傍の交差を明示的に構築するのではなく、頂点ごとに、互換性のない頂点が実行可能な状態でいくつあるかをカウントします。 頂点が現在許可されている n − k 個を超える頂点と競合する場合、その頂点は有効な構造の一部であることができず、破棄されます。 

最後のステップでは、十分な頂点が枝刈りに耐えられるかどうかを確認するだけです。 はいの場合、残りのすべての頂点が圧縮操作によって引き起こされる必要な制約構造とペアごとに一致するため、それらの k はどれも有効です。

 ## 特殊なケース

 ほぼすべてのペアが接続されている密なグラフでも、非隣接ペアを注意深くカウントする必要があります。 このアルゴリズムはすべての頂点を対称的に扱うため、完全なグラフであってもすべての頂点が許可され、任意の k サブセットが有効になります。 

完全に空のグラフでは、すべての頂点の競合数が最大になります。 k < n の場合、各頂点には n − 1 個の非隣接点があり、これは n − k を超えるため、すべての頂点が削除され、出力は正しく -1 になります。 

k が n に近い場合、たとえば k = n − 1 の場合、しきい値 n − k は 1 となるため、2 つのエッジが欠落している頂点であっても無効になります。 このアルゴリズムは、グラフがほぼ完成し、圧縮操作によって課せられる構造要件と一致しない限り、ほぼすべての頂点を拒否するほど厳密になります。
