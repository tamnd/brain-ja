 ## 問題の理解

 長さの順列を構築するように求められます$n$、からの数字の配列を意味します。$1$に$n$繰り返しはなく、まさにそのとおりです$k$要素は少なくとも 1 つの反転に関与します。 

反転は位置のペアです$i < j$ここでの値は$i$の値よりも大きいです$j$。 要素は、左側の大きい要素または右側の小さい要素のいずれかとして、少なくとも 1 つのそのようなペアに表示される場合、「アクティブ」であるとみなされます。 

したがって、タスクは反転の数を制御することではなく、少なくとも 1 つの反転関係に関与する個別の要素の数を制御することです。 

制約$n \le 100$そして$k \le n$厳しい最適化を強制されないことをすぐに示唆してください。 線形または二次式の構築$n$それは受け入れられますが、本当の難しさは純粋に構造的なものです。どの値を「反転なし」にできるか、またそれらの値を残りの値から分離する方法を決定することです。 

重要なエッジ ケースは、どの要素も反転に参加すべきではない場合に発生します。 これは、順列が完全に増加している場合にのみ発生します。これは、偏差があると少なくとも 1 つの反転ペアが発生するためです。 それで$k = 0$順列を強制的に$1, 2, \dots, n$。 

もう一つの微妙な状況は次のような場合です。$k = n$つまり、すべての要素が反転に参加する必要があります。 これは可能ですが、反転ペアに決して出現しない、グローバルに「クリーンな」要素の作成を回避する場合に限ります。 すべての要素は右側のものよりも大きいか、左側のものよりも小さいため、減少順列はすでにこれを満たしています。 

したがって、中心的な課題は、正確にどこで置換を構築するかを決定することです。$n-k$要素には反転がまったくありませんが、残りの要素には反転がありません。$k$要素は強制的に参加することになります。 

## アプローチ

 ブルートフォースアプローチでは、サイズのすべての順列を列挙します。$n$、要素ごとに反転に関与しているかどうかを計算し、その要素がいくつあるかを数えて、次と等しいかどうかを確認します。$k$。 これは正しいですが、すぐには実行不可能です。$n!$順列、さらに順列ごとの反転参加コストの計算も可能$O(n^2)$、中程度の場合でも爆発を引き起こす$n$。 

構造上の洞察は、要素が「完全なピボット」のように動作する場合にのみ反転が発生しないということです。要素の左側にあるものはすべて小さく、右側にあるものはすべて大きくなります。 このような要素は非常に制限されており、複数の要素が必要な場合は、非常に制御された方法で配置する必要があります。 

すべての要素を同時に構築しようとする代わりに、順列を 2 つの部分に分けます。 私たちは明示的に選択します$n-k$要素を反転なしにし、残りの要素を強制します$k$要素が反転に完全に絡み合います。 

反転のない要素を保証する最もクリーンな方法は、最大値を使用して要素を昇順で順列の最後に配置することです。 これにより、右側の小さな要素に遭遇することがなくなり、左側のすべてが構造上より小さくなります。 

残りの最小値は前に配置されます。 これらを降順に並べると、このプレフィックス内のすべての要素は少なくとも 1 つの反転に関与します。これは、各要素がプレフィックス構造内で右側に小さい要素、または左側に大きい要素を持つためです。 

この分離により、必要なカウントが確実に適用されます。

 ## アルゴリズムのチュートリアル

 すべての反転参加を担当するプレフィックスとクリーンであることが保証されたサフィックスの 2 つのセグメントで順列を構築します。 

1. もし$k = 0$、恒等順列を出力します。$1$に$n$。 これは反転がまったくない唯一の配置なので、すべての要素が自動的にクリーンになります。 
2. それ以外の場合は、定義します$m = n - k$。 これら$m$要素はすべての反転を避けなければならない要素になります。 
3. 値を割り当てます$m+1$を通して$n$クリーンサフィックスに。 これらは最大の数値であるため、右側のどの要素よりも小さくなることはありません。 
4. これらのサフィックス値を昇順で順列の最後に配置します。 これにより、シーケンスがソートされるため、サフィックス自体内で反転が導入されなくなります。 
5. プレフィックスに値を入力します$1$を通して$m$降順で。 これにより、このプレフィックス内のすべての要素がプレフィックス内の少なくとも 1 つの反転に関与することが保証されます。 

プレフィックスを反転する理由は、各要素が左側に大きい要素、または右側に小さい要素の両方を持つことを強制し、反転ペアに確実に参加できるようにするためです。 

### なぜ効果があるのか

 この構造では、厳密な役割分担が強制されます。 すべての suffix 要素はすべての prefix 要素より大きいため、suffix 要素は prefix 要素と反転を形成できません。 サフィックス内では順序が増加しているため、反転も存在せず、これらの要素は完全にクリーンになります。 

プレフィックス内では、降順により、すべての要素の右側に小さい要素が存在し、その要素を含む反転ペアが少なくとも 1 つ生成されることが保証されます。 したがって、すべての接頭辞要素がアクティブになります。 

これは正確に与えます$m = n-k$クリーンな要素と$k$アクティブな要素を使用し、2 つのグループ間の相互干渉はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

if k == 0:
    print(*range(1, n + 1))
else:
    m = n - k
    # prefix: 1..m in decreasing order
    prefix = list(range(m, 0, -1))
    # suffix: m+1..n in increasing order
    suffix = list(range(m + 1, n + 1))
    print(*(prefix + suffix))
```実装は構築を直接反映します。 縮退の場合のみ分岐が発生します。$k = 0$ここで、反転は要件に違反し、ソートされた順列が強制されます。 

接頭辞の反転は不可欠です。 代わりに増加していた場合、プレフィックス要素は必ずしも反転に関与せず、必要なカウントを壊すことになります。 サフィックスは、反転動作から完全に分離されるようにソートされたままになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())

    if k == 0:
        return " ".join(map(str, range(1, n + 1)))
    m = n - k
    prefix = list(range(m, 0, -1))
    suffix = list(range(m + 1, n + 1))
    return " ".join(map(str, prefix + suffix))

 ## 特殊なケース

 ケース$k = 0$反転が禁止される唯一の状況です。 アルゴリズムは完全に増加する順列を出力することでこれを個別に処理し、すべての要素が厳密な非反転条件を確実に満たすようにします。 

のために$k = n$の場合、この構造は接尾辞のない完全に減少する接頭辞を生成します。これにより、すべての要素が少なくとも 1 つの反転ペアに現れることが保証されます。 各要素の左側には大きな要素があるため、どれもきれいではありません。 

いつ$n - k = 1$の場合、プレフィックスには 1 つの要素があり、サフィックスにはグローバル構造の右側に大きな要素が含まれているため、反転に引き続き関与し、少なくとも 1 つの反転ペアが存在することが保証されます。 

いつ$n - k = 0$、サフィックスが配列全体となり、昇順により反転がないことが保証され、要件に正確に一致します。
