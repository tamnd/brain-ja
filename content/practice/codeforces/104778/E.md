 ## 解決策
 ## 問題の理解

 私たちは 1 から n までのページ番号が付いている非常に大きな本を与えられました。 開始ページ x を選択し、x から n までのすべてのページを読み取ります。 各ページには番号があり、その番号の最後の桁だけを気にします。 

ページの最後の桁が a または b に等しい場合、そのページは「特別」であるとみなされます。 選択した開始ページ x について、サフィックス間隔 [x, n] に存在する特殊ページの数を数えます。 タスクは、このカウントが正確に k になるような開始ページ x を見つけることであり、すべての有効な選択肢の中から可能な最大の x を出力する必要があります。 そのような x が存在しない場合は、-1 を出力します。 

重要な問題は、n が 10^12 までという制約にあります。 これにより、すべてのページを反復したり、ページを明示的に保存したりするアプローチは即座に除外されます。 どのソリューションも、個々のページの ID ではなく、最後の桁のパターンの構造に依存する必要があります。 

貪欲にスタート地点を移動させようと思うと微妙な問題が出てきます。 [x, n] の特殊ページの数は x において単調ですが、最後の桁のみが重要であり、これらの桁は 10 桁ごとに循環的に繰り返されるため、厳密には線形ではありません。 この周期性は不可欠です。 

素朴な考えを打ち破るエッジケースには、k が本全体の特別ページの総数よりも大きい状況が含まれます。 たとえば、n = 20、a = 4、b = 7 の場合、特殊ページは 4、7、14、17 になります。k = 5 の場合、解は存在しません。 「カウントが k と一致するまで x をシフトする」という単純な試みは、最終的にページ 1 を超えてしまい、x = 1 が有効であると誤って想定してしまいます。 

もう 1 つの注意が必要なケースは、a = 0 または b = 0 の場合です。0 で終わるページは 10 桁ごとに表示されますが、10、20、30 などの境界付近の動作は一貫して処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、1 から n までの可能なすべての開始ページ x を試します。 各 x について、[x, n] 内で数字 a または b で終わるページが何ページあるかを数えます。 このような各チェックには O(n) がかかるため、総コストは O(n^2) になります。これは、10^12 までの n では不可能です。 

固定 x のカウントを改善しても、依然としてすべての x にわたる外側のループが残りますが、これは根本的に大きすぎます。 失敗のポイントはカウントではなく、候補スタートの数にあります。 

重要な観察は、条件が 10 桁ごとに繰り返される最後の桁にのみ依存するということです。 個々のページを扱う代わりに、10 個の連続する数字のブロックという観点から考えることができます。 各フル ブロックは、0 ～ 9 の中に a または b が出現するかどうかによってのみ決定される固定数のスペシャル ページに貢献します。 

[x, n] に完全なサイクルが何回あるかがわかったら、算術を使用して O(1) のカウントを計算できます。 これにより、候補 x をすぐに確認できるようになります。 

ここでのタスクは次のようになります。サフィックス [x, n] にちょうど k 個の特殊な数字が含まれるような最大の x を見つけます。 「[x, n] 内の特殊ページの数 ≥ k」という述語は x において単調減少するため、カウントが k に低下する境界を二分探索して等しいことを検証できます。 

すべての位置をスキャンするという問題を、O(log n) チェック (各 O(1) 個) で x を対象に 1 回の二分探索に減らすことにしました。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 [x, n] 内の最後の桁が a または b であるページ数を返すヘルパー関数 f(x) を定義します。

1. 0 ～ 9 のどの数字が「特別」であるかを事前に計算します。 これは、d が a または b に等しい場合に数字 d が特別になる固定マスクです。 これにより、一定時間のチェックが可能になります。 
2. [1, t] に存在するスペシャル ページの数を返す関数 count_upto(t) を定義します。 これは、10 の完全なブロックと残りのセグメントを使用して計算されます。 完全なブロックごとに、0 から 9 までの特殊な数字の数を追加します。その後、残ったプレフィックスを直接処理します。 
3. プレフィックス数を使用してサフィックス数を表現します: f(x) = count_upto(n) − count_upto(x − 1)。 これにより、問題は高速プレフィックス関数の評価に変換されます。 
4. f(1) を計算して実現可能性を確認します。 f(1) < k の場合、サフィックスに k 個の特殊ページを含めることはできないため、-1 を出力します。 
5. それ以外の場合は、f(x) ≤ k が厳密に成り立たないような最小の x を二分探索するか、同等に f(x) = k の場合に最大の x を見つけます。 x が増加すると f(x) は減少するため、f(x) < k となる最初の x を検索してから、元に戻ることができます。 
6. 二分探索の後、等価条件が境界で崩れる可能性があるため、候補 x を検証します。 

二分探索の正しさは f(x) の単調性に依存します。つまり、x が増加すると区間 [x, n] が縮小するため、特別なページの数は増加できません。 

### なぜ効果があるのか

 開始点を右に移動するとカウントされる間隔からページが削除され、新しいページが追加されないため、関数 f(x) は x に対して増加しません。 この単調な構造により、有効な x 値のセットが整数の接尾辞セグメントを形成することが保証されます。 二分探索によりこのセグメントの境界が正確に識別され、境界をチェックすることで有効な最大の x が確実に選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, a, b = map(int, input().split())

    special = [0] * 10
    special[a] = 1
    special[b] = 1

    def count_upto(x):
        if x <= 0:
            return 0
        full = x // 10
        rem = x % 10
        base = sum(special) * full
        extra = 0
        for d in range(rem + 1):
            extra += special[d]
        return base + extra

    total = count_upto(n)

    def f(x):
        return total - count_upto(x - 1)

    if f(1) < k:
        print(-1)
        return

    lo, hi = 1, n
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if f(mid) >= k:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、サフィックス クエリをプレフィックス カウントに変換することに依存しているため、候補 x ごとに何かを再計算する必要がありません。 関数 count_upto は、数直線を 10 のブロックと剰余セグメントに分割することにより、最後の桁の周期構造を処理します。 

二分探索は、f(x) ≥ k の条件下で x を最大化するように設計されていますが、f は減少しているため、正確に k 個の特殊ページを持つ最大の有効な開始点を直接特定します。 

よくある微妙な点は、x - 1 が 0 になる x = 1 の処理です。prefix 関数は、不正な算術演算を避けるために、非正の入力を明示的に保護します。 

## 実用的な例

 ### 例 1

 入力: n = 29、k = 3、a = 8、b = 0

 まず特殊な数字 0 と 8 を識別します。次に、サフィックスの数を評価します。 

| × | f(x) 計算のアイデア | f(x) |
 | --- | --- | --- |
 | 29 | 29 ページのみ → 特別ではない | 0 |
 | 28 | 28、29→28ページは特別です | 1 |
 | 20 | ページ 20..29 → 20,28 | 2 |
 | 18 | ページ 18..29 → 18、20、28 | 3 |
 | 17 | ページ 17..29 → 17、18、20、28 | 3 |

 二分探索では、f(x) = 3 の最大の x、つまり 18 が見つかります。これは、サフィックス内の 3 ページが 0 または 8 で終わるという要件に一致します。 

### 例 2

 入力: n = 20、k = 5、a = 4、b = 7

 特別ページは 4、7、14、17 です。合計数は 4 で、すでに k 未満です。 

したがって、f(1) < k となり、アルゴリズムはすぐに -1 を出力します。 これにより、検索が必要になる前に実現可能性のチェックが行われることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(log n) | x に対する二分探索。各ステップでは O(1) 桁の算術演算を使用します。 
| スペース | お(1) | 定数配列と変数のみが使用されます。 

n が 10^12 までの場合でも、対数が小さく、各評価が定数時間であるため、解は制約内に簡単に収まります。

 ## 特殊なケース

 n = 10、k = 1、a = 0、b = 9 のような場合、特殊ページは正確に 9 と 10 です。サフィックス [9, 10] には両方の特殊ページが含まれており、[10, 10] には 1 つしか含まれていませんが、9 が条件を満たしているため最大の有効な開始ではないため、正解は x = 9 です。 アルゴリズムは f(9) = 2 および f(10) = 1 を評価し、二分探索では f(x) = 1 の最大の x として 10 が正しく返されます。 

k が特殊ページの総数に等しい場合、唯一の有効な答えは x = 1 です。アルゴリズムは f(1) = k を検出し、二分探索は自然に左端の境界まで拡張されます。 

4と5のようにaとbが近い場合、特殊ページの密度は高くなりますが、単調な構造は変わりません。 10 個の各ブロックは正確に 2 つの特別な位置を提供し、接尾辞のカウントはバイナリ検索の前提を壊すような不連続性もなくスムーズに動作します。
