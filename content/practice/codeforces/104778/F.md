 ## 問題の理解

 の行から始めます`n`初期の箱の山。 各スタック`i`含まれています`a_i`箱。 初期スタックの隣接するすべてのペアの間に、新しい空のスタックを挿入します。そのため、レイアウトは、元のスタックと新しいスタックが交互に並ぶシーケンス (元のスタック、新しいスタック、元のスタック、新しいスタック) になります。 これにより、`2n − 1`合計でスタックします。 

移動には重要な制限があり、ボックスは元のスタックから隣接する新しいスタックの 1 つにのみ移動できます。 元のスタック間での直接転送は許可されず、新しいスタックはボックスのみを受け取ります。 

タスクは、許可された一連の動きの後で、すべての動きを実行できるかどうかを判断することです。`2n − 1`スタックにはまったく同じ数のボックスが含まれます。 

ボックスの総数は固定されているため、解が存在する場合、各スタックは同じ値になる必要があります。`S = (sum of a_i) / (2n − 1)`。 これは、合計が次で割り切れる必要があることを直ちに意味します。`2n − 1`、そうでなければ答えは不可能です。 

制約`n ≤ 200000`これは、どのソリューションもほぼ直線的な時間で実行する必要があることを意味します。 二次関数または偶数関数`O(n log n)`スタックを繰り返し調整する貪欲なシミュレーションは、最悪の場合、遅すぎます。 プレフィックス推論またはローカルの実現可能性条件に基づいた解決策を期待する必要があります。 

平均が整数である場合、微妙なエッジケースが現れますが、フローの制限により再分配は依然として不可能です。 たとえば、合計が一致したとしても、スタックの一部のプレフィックスでは、2 つの元のスタック間の禁止された境界を「通過」してボックスを移動する必要がある場合がありますが、これは許可されていません。 これが主な構造上の困難です。 

## アプローチ

 素朴なアプローチは、プロセスを直接シミュレートすることです。 私たちは、`2n − 1`構造を変更するには、まだ余分なボックスがある元のスタックを繰り返し選択し、すべてが等しくなるまで隣接する新しいスタックにそれらを押し込みます。 これは、流れまたはバランスのシミュレーションに似ています。 ただし、各ボックスの動きは局所的であり、最悪の場合、単一のボックスが何度も調整される可能性があります。 まで`2n − 1`スタックと潜在的に`O(n)`スタックごとの調整、これは次のように縮退します。`O(n^2)`行動。 

重要な観察は、新しいスタックが元のスタック間のバッファーとして機能し、移動を分離することです。 元の各スタックは、そのすぐ左および右のバッファとのみ対話します。 これにより、問題はローカルな実現可能性の制約に変わります。元の各スタックは、グローバルな調整を必要とせずに、その余剰または不足を 2 つの隣接するバッファ位置に「分割」できなければなりません。 

プロセスを次のように再定式化します。 各オリジナル スタックはその値を 2 つの隣接するギャップに提供し、各ギャップは正確に 2 つの隣接するオリジナル スタックからの提供を受け取ります。 最終的な構成は均一であるため、すべてのギャップも同じ目標値で一貫して安定する必要があります。 これにより、問題は、元のノードがエッジにプッシュされるパス グラフ上にフローの一貫した割り当てが存在するかどうかを確認することに変換されます。 

シミュレートする代わりに、左から右に制約を導き出します。各境界を通過しなければならない量は、プレフィックスの不均衡によって一意に決定されます。 いずれかの時点で必要な転送が不可能になった場合、答えは否定的です。

 ## アルゴリズムのチュートリアル

 目標値を計算します`S = sum(a) / (2n − 1)`。 整数でない場合は、すぐに NO を返します。 

次に、システムを不均衡の線形伝播として解釈します。 させて`balance`現在の元のスタックから次の領域に渡す必要がある追加のボックスの数を表します。 元のスタック上で左から右にスイープし、境界を通過する余剰または不足の量を維持します。 

1. 合計を計算し、割り切れるかどうかを確認します。`2n − 1`。 失敗すると構成を均等に分散できないため、すぐに停止します。 
2. スタックごとのターゲットを設定する`S`。 
3. 変数を初期化する`carry = 0`、前のセグメントから現在のセグメントに渡す必要があるボックスの数を表します。 
4. 元の各スタックを反復処理します。`i`左から右へ。 
5.アップデート`carry`追加することで`a_i - S`。 これはスタックの量を表します`i`流入フローを考慮すると、目標から逸脱します。 
6. いつでも`carry`が負になると、欠損を左方向に押す必要があることが検出されますが、移動は隣接する新しいスタックを介して一貫した 1 つの方向にのみ伝播するため、これは不可能です。 
7. 最後まで伝播を続けます。 
8. すべてのスタックを処理した後、システムに一貫性がある場合は、YES を返します。 

重要な考え方は、`carry`各中間バッファを通過する必要があるネット転送をエンコードします。 新しいスタックはそれぞれ単に導管として機能します。 フローの連続性を強制する以上の独立した制約は保存されません。 

### なぜ効果があるのか

 不変条件は、スタックの処理後です。`i`、の値`carry`スタック間の境界を通過して輸送する必要がある箱の正味の数に等しい`i`そして`i+1`均一性を達成するために。 もし`carry`がマイナスになることはありません。これは、許可された転送の構造に違反する方向にボックスを移動する必要があることを意味します。これは、禁止されているオリジナルからオリジナルへの移行を経由せずに、以前の赤字を将来の黒字で修正することができないためです。 

各境界には厳密に 1 つの自由度があり、サイクルが存在しないため、このプレフィックスの一貫性条件は実現可能性にとって必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    m = 2 * n - 1
    
    if total % m != 0:
        print("NO")
        return
    
    target = total // m
    
    carry = 0
    for x in a:
        carry += x - target
        if carry < 0:
            print("NO")
            return
    
    if carry == 0:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```実装はプレフィックス伝播モデルに直接に従います。 キーラインは`carry += x - target`、プレフィックスが望ましい均一な設定からどれだけ逸脱しているかを累積します。 ネガティブな状況での早期撤退`carry`不可能な状態に継続することを防ぎます。 最終チェックでは、すべての余剰が最後までに完全に吸収されること、つまり不均衡が残らないことが保証されます。 

よくある間違いは、最終条件を無視することです`carry == 0`。 負のプレフィックスがない場合でも、残りの正のフローは、ボックスがシステムから出る必要があることを意味しますが、これは許可されていません。 

## 実用的な例

 有効な再配布が存在する最初のサンプルを考えてみましょう。 

私たちは計算します`S`そして追跡する`carry`:

 | 私 | a[i] | a[i] - S | キャリー |
 | --- | --- | --- | --- |
 | 1 | 7 | +2 | 2 |
 | 2 | 13 | +8 | 10 |
 | 3 | 5 | 0 | 10 |

 このトレースでは、キャリーがマイナスになることはなく、システムは挿入されたスタックを通じて分配できる一貫した余剰を維持します。 最終的な実現可能性は、この余剰が構造によって完全に吸収されることに対応します。 

ここで、不均衡を解決できないというあり得ないケースを考えてみましょう。 

| 私 | a[i] | a[i] - S | キャリー |
 | --- | --- | --- | --- |
 | 1 | 3 | -2 | -2 |

 ここで、キャリーはすぐにマイナスになります。これは、最初のスタックが、左側から供給できない受信ボックスをすでに必要としていることを意味します。 以前の構造は存在しないため、この違反は不可能であることを証明します。 

これらの例は、実現可能性がグローバルな再配置ではなく、純粋にプレフィックスの動作によって決定されることを示しています。

 ## 特殊なケース

 合計が次の値で割り切れる場合、重大なエッジケースが発生します。`2n − 1`しかし、プレフィックス条件はすぐに失敗します。 たとえば、最初のスタックがすでにターゲットを下回っている場合、不足分を供給するための以前のバッファーがないため、アルゴリズムは最初のステップで正しく拒否されます。 

もう一つの微妙なケースは次のような場合です。`carry`ポジティブになり、最後までポジティブであり続けます。 これは、最後の境界を越えて輸出するメカニズムがないために吸収できない余剰に相当します。 最終チェック`carry == 0`中間違反が発生しない場合でも、この状況は確実に拒否されます。 

これら 2 つのケースを合わせると、プレフィックスの実現可能性とグローバルな保存の両方が独立して必要な条件であることがわかります。
