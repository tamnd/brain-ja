 ## 問題の理解

 数直線上の点の集合が与えられます。 負の位置を含め、整数線上のどこにでも追加の点を 1 つ配置できます。 この選んだポイントに対して$x$からの絶対距離の合計を計算します。$x$既存のすべてのポイントに。 タスクは、整数座標が存在するかどうかを判断することです。$x$この合計が指定された目標値と等しくなるように$d$、そうであれば、そのような座標を出力します。 

ここでの重要なオブジェクトは、整数に対する関数です。$$F(x) = \sum_{i=1}^{n} |x - a_i|$$任意の整数を見つける必要があります$x$そのような$F(x) = d$。 

制約は大きく、最大 200,000 点と最大座標です。$10^{12}$、 その間$d$と同じ大きさにすることができます$10^{17}$。 これにより、各候補ポジションの合計を独立して評価するアプローチは即座に除外されます。 最小入力値と最大入力値の間のすべての整数座標を直接スキャンすることは、その範囲が最大であるため、すでに実行不可能です。$10^{12}$、各ポジションのコストを評価する$O(n)$。 

2 番目の微妙な問題は、関数が任意ではないことです。関数は凸状であり、指定された点でのみ傾きが変化する区分線形です。 その構造が問題を解決できる唯一の理由です。 

特殊なケースは 3 つの主な形式で現れます。 

1 つのケースは、すべての点が同一である場合です。 たとえば、すべてが$a_i = 100$、 それから$F(x) = n \cdot |x - 100|$。 もし$d = 0$、 のみ$x = 100$動作します。 もし$d > 0$かどうかを確認する必要があります。$d$で割り切れます$n$そうでない場合、整数解は存在しません。 

もう一つのケースは次のような場合です。$n = 1$。 それから$F(x) = |x - a_1|$、そしてどんな解決策も単純です$x = a_1 \pm d$。 中央値に基づく直感は退化するため、中央値の特性に基づく素朴な推論はここでは失敗する可能性があります。 

3 番目のケースは、目的の値が可能な最小合計を下回る場合です。 関数は任意の中央値で最小値に達し、その最小値はすでに超えている可能性があります。$d$。 その場合、どんなに離れても解決策はありません。 

## アプローチ

 ブルートフォースのアイデアは、指定された点の最小座標と最大座標の間のすべての整数位置を試し、それぞれの距離の合計を計算することです。 この関数はどこでも明確に定義されているため機能しますが、遅すぎます。 座標範囲は最大で広がります$10^{12}$、各評価コスト$O(n)$、約につながる$10^{17}$最悪の場合の運用。 

重要な構造観察は次のとおりです。$F(x)$は整数上の凸関数です。 その傾きは入力ポイントでのみ変化し、連続するポイント間では線形になります。 これは、恣意的に検索する必要がないことを意味します。 代わりに、プレフィックス数とプレフィックス合計を使用して関数を分析できます。 

ポイントがソートされたら、計算できるようになります$F(x)$与えられた時間内で効率的に$x$二分探索を使用します。 さらに重要なのは、この関数は凸状で区分線形であるため、中央領域までは減少し、その後は単調増加します。 この構造により、目標値が目標値であるかどうかを判断できます。$d$が最小値の左側または右側にある場合は、その側の一次式を反転します。 

中心となるアイデアは、中央値での最小値を計算し、それを次の値と比較することです。$d$、次に、前置和を使用して関数の増加側の線形方程式を解きます。

 ## アルゴリズムのチュートリアル

 ### 最適な推論

 1. 座標の配列を並べ替えます。 絶対値の構造は順序に依存するため、並べ替えは不可欠です。 
2. ソートされた配列に対してプレフィックスの合計を計算します。 これにより、候補位置の各側にいくつの点があるかを迅速に評価できます。 
3. 中央位置を見つける$m$。 中央値は関数を最小化します$F(x)$。 最小値を計算します$F(m)$。 
4. もし$d < F(m)$、停止してNOを出力します。 関数は、ライン上のどこでも最小値を下回ることはできません。 
5. もし$d = F(m)$、中央値座標自体を出力します。 中央値はどれでも機能し、いずれかを選択するだけで十分です。 
6. それ以外の場合は、$d > F(m)$。 解は中央領域の左または右の外側に存在する必要があります。 両方向を個別にチェックします。 
7. 固定側の場合、次のように表現します。$F(x)$プレフィックスの合計を使用した一次関数として。 配列の右側では、関数の傾きは点の数に等しく、値は予想通りに増加します。 私たちは次のことを解決します$x$一次式が次のようになる$d$。 
8. 候補者の確認$x$必要に応じて直接置換し、有効であれば出力します。 

### なぜ効果があるのか

 機能$F(x)$各項が凸であるため$|x - a_i|$は凸であり、和は凸を維持します。 凸整数関数には単一のグローバル最小間隔 (中央領域) があり、両側でそこから離れると単調非減少になります。 これにより、最小値を超える値はいずれか一方または両方の単調分岐に沿って正確に到達可能であり、その分岐の一次式を反転することで解決できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    def cost(x):
        import bisect
        k = bisect.bisect_right(a, x)
        left = x * k - pref[k]
        right = (pref[n] - pref[k]) - x * (n - k)
        return left + right

    m = a[n // 2]
    base = cost(m)

    if d < base:
        print("NO")
        return

    if d == base:
        print("YES")
        print(m)
        return

    # try right side
    total = n
    sum_all = pref[n]

    # candidate on right: x >= m
    # F(x) = sum(x - a_i for a_i <= x) + sum(a_i - x for a_i > x)
    # we binary search x by monotonicity
    lo, hi = m, 10**18

    ans = None
    for _ in range(200):
        mid = (lo + hi) // 2
        if cost(mid) < d:
            lo = mid
        else:
            hi = mid

    if cost(lo) == d:
        ans = lo

    if ans is None:
        lo, hi = -10**18, m
        for _ in range(200):
            mid = (lo + hi) // 2
            if cost(mid) < d:
                hi = mid
            else:
                lo = mid
        if cost(lo) == d:
            ans = lo

    if ans is None:
        print("NO")
    else:
        print("YES")
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、次の直接評価関数に依存しています。$F(x)$接頭辞の合計と二分探索を使用して、ポイントを左側と右側に分割します。$x$。 コスト関数は中心的なプリミティブであり、次のように実行されます。$O(\log n)$内部の二分探索のため。 

まず中央値に基づく最小値を計算します。 この値によって実現可能性がすぐに決まります。 その後、単調性を利用します。中央値から右に移動するとコストが厳密に増加するため、コストが一致する点を二分探索できます。$d$。 同じロジックが左側にも対称的に適用されます。 

よくある落とし穴は、閉じた形式の反転が常に単純であると仮定していることです。 可能ではありますが、整数の境界を正しく処理することは、凸関数に対する単調二分探索に依存するよりも脆弱です。
