 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられます。 文字列は、各ブロックが同一の文字で構成される、最大の連続ブロックのシーケンスとして考えることができます。 たとえば、`aabbbbccc`、ブロックは`aa`、`bbbb`、 そして`ccc`。 

1 つの操作は次のように機能します。まず、現在のすべてのブロックの中で最も長いブロックを特定します。 複数のブロックが同じ最大長を共有する場合、それらの中で一番左のブロックが選択されます。 そのブロックを選択した後、ブロック内の文字を 1 文字だけ削除します。そのため、ブロックは 1 文字ずつ縮小しますが、長さがゼロになるまで消えません。その場合、ブロックは隣接する構造に自然にマージされます。 

この操作を正確に繰り返します`k`回、削除のたびにブロックを常に再計算します。 タスクは、最終的な文字列を決定することです。 

制約により許可されるのは、`n`最大 200000 なので、それぞれの後にブロックを最初から再計算するソリューション`k`操作が遅すぎます。 単純なシミュレーションでは文字列全体を繰り返しスキャンすることになる可能性があり、最悪の場合は約`O(nk)`、両方が大きい場合は大きすぎます。 

微妙なエッジケースは、ブロックの長さの関係から生じます。 常に左端の最大ブロックを選択するため、2 つの同一の大きなブロックは、その位置に応じて大きく異なる動作をします。 たとえば、`aaabbb`、どちらのブロックも長さ 3 なので、常に次から削除します。`aaa`最初は最大値でなくなるまで。 左端のルールを厳密に適用しない不用意な実装は、すぐに分岐してしまいます。 

もう 1 つのエッジ ケースは、ブロックから削除すると、後で変更する決定が分割またはマージされる場合です。 たとえば、ブロックを縮小した後、それまで最大ではなかったブロックが最大になる可能性があり、次の操作でフォーカスが完全に切り替わる可能性があります。 

## アプローチ

 ブルートフォースアプローチは文字通りプロセスをシミュレートします。 文字列全体を繰り返しスキャンしてブロックに圧縮し、左端のタイブレークで最大長のブロックを見つけ、そこから 1 文字を削除して、構造を再構築します。 各スキャンにかかる費用`O(n)`、そして私たちはそれをします`k`回、与える`O(nk)`全体。 と`n`そして`k`両方とも大きくなる可能性があるため、これでは遅くなりすぎます。 

重要な観察は、文字列の進化は完全にブロック構造によって駆動され、各操作は長さを 1 つ減らすことによって 1 つのブロックのみを変更するということです。 ブロックの相対的な順序は、ブロックが隣接するブロックと一致するように縮小する場合、またはタイブレーク シフトの場合にのみ局所的に変更されます。 これは、ブロックを毎回再構築するのではなく、動的に維持する必要があることを示唆しています。 

文字列を二重にリンクされたブロックのリストとして表現でき、各ブロックには文字と長さが格納されます。 現在の最大長のブロックを左端の優先順位ですばやく見つけるために、長さによってグループ化されたブロックを追跡する構造を維持し、各長さのバケット内でブロックを左から右の順序で保持します。 長さに対する優先順位の構造により、常に最大長を選択でき、その中でそのバケット内の最初のブロックを取得します。 

それぞれの操作は、最大長のブロックのうち左端のブロックを抽出し、その長さをデクリメントし、ゼロになった場合は削除し、隣接する等しい文字ブロックをマージします。 マージはローカルの近隣にのみ影響するため、更新は一定時間で償却されたままになります。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nk) | O(n) | 遅すぎる |
 | ブロック + 順序付けされたバケット | O(n + k log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、入力文字列を最大のブロックに圧縮します。 各ブロックは、その文字、現在の長さ、および隣接するブロックへのポインタを二重リンク構造で格納します。 すべての操作は個々の文字ではなくブロックに関して定義されるため、この手順が必要です。 

次に、現在存在する最大ブロック長を取得できるデータ構造を維持します。 長さごとに、ブロックのキューを左から右の順序で維持します。 また、最大値を迅速に取得できるように、アクティブな長さのソートされたコンテナーも維持します。 

その後、パフォーマンスを行います`k`それぞれの操作は次のように進行します。 

1. アクティブな長さのセットから現在の最大ブロック長を特定します。 これは、次の操作ターゲットを含めることができる唯一の候補の長さです。 
2. この長さに対応するキューから、まだ有効な一番左のブロックを取り出します。 すでに削除されているか長さが変更されている場合は、有効なものが見つかるまでスキップしてください。 
3. ブロックの長さを 1 つ減らします。 これは、そのブロックから文字を削除することを表します。 
4. ブロックがまだ正の長さである場合は、同じ長さのバケットにブロックを再挿入または更新します。 長さが変わるとバケット間を移動します。 
5. ブロックが空になった場合は、リンクされた構造からブロックを削除します。 左右の隣接文字が同じ文字を持つ場合、それらを 1 つのブロックにマージし、長さとポインターを更新します。 

重要な点は、マージはローカルでのみ行われるため、構造全体を再スキャンする必要がないことです。 各削除は、最大 2 つの隣接するブロックにのみ影響します。 

すべての操作が完了したら、ブロック リストを左から右に走査し、各ブロックを展開することによって、最終的な文字列を再構築します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは文字列の正確な表現を最大ブロックのシーケンスとして維持します。 長さに対する優先順位の構造により、選択されたブロックが常に真のグローバル最大長ブロックであることが保証され、各長さのバケット内での左から右の順序により正しいタイブレークが強制されます。 すべての変更は 1 ブロックを 1 文字ずつ減らすか、2 つの隣接するブロックをマージするだけなので、隠されたグローバル プロパティが侵害されることはありません。 各操作の後でも表現の一貫性は保たれるため、最終的な再構築は元の文字列に対して段階的にプロセスを実行することと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Block:
    __slots__ = ("ch", "len", "prev", "next")
    def __init__(self, ch, length):
        self.ch = ch
        self.len = length
        self.prev = None
        self.next = None

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    # build blocks
    blocks = []
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        blocks.append(Block(s[i], j - i))
        i = j

    # link blocks
    for i in range(len(blocks)):
        if i > 0:
            blocks[i].prev = blocks[i - 1]
        if i + 1 < len(blocks):
            blocks[i].next = blocks[i + 1]

    # buckets by length
    from collections import defaultdict, deque
    buckets = defaultdict(deque)
    active_lengths = set()

    for b in blocks:
        buckets[b.len].append(b)
        active_lengths.add(b.len)

    def clean_top():
        while active_lengths:
            mx = max(active_lengths)
            dq = buckets[mx]
            while dq and dq[0].len != mx:
                dq.popleft()
            if dq:
                return mx
            active_lengths.discard(mx)
        return None

    for _ in range(k):
        mx = clean_top()
        dq = buckets[mx]

        # get valid leftmost block
        b = dq.popleft()

        b.len -= 1
        if b.len > 0:
            buckets[b.len].append(b)
            active_lengths.add(b.len)
        else:
            # remove block and possibly merge
            left = b.prev
            right = b.next

            if left:
                left.next = right
            if right:
                right.prev = left

            if left and right and left.ch == right.ch:
                # merge right into left
                left.len += right.len
                left.next = right.next
                if right.next:
                    right.next.prev = left

                buckets[left.len].append(left)
                active_lengths.add(left.len)

    # reconstruct
    # find head
    head = blocks[0]
    while head.prev:
        head = head.prev

    res = []
    cur = head
    while cur:
        res.append(cur.ch * cur.len)
        cur = cur.next

    print("".join(res))

if __name__ == "__main__":
    solve()
```この実装では、ブロックを二重リンク リストとして保持するため、削除やマージの際に文字列全体を移動したり再スキャンしたりする必要がありません。 バケット構造は、現在の長さによってブロックをグループ化します。`active_lengths`現在の最大長を取得できます。 ヘルパーさん`clean_top`キューに入れられてからブロックの長さが変更された場合に、古いエントリを確実にスキップします。 

マージ ステップはローカルです。隣接するブロックのみがチェックされ、同じ文字の隣接ブロックのみが結合されます。 これにより、再計算のカスケードが回避されます。

 ## 特殊なケース

 主なエッジケースは、複数のブロックが同じ最大長で始まり、タイブレークが繰り返し問題になるような方法でインターリーブされている場合です。 例えば、`aaabbb`と`k = 2`常に左を選択します`aaa`まず、前に 2 回縮小します`bbb`アルゴリズムは対称的な方法で等しい長さのタイを再評価することはないため、常に左端が優先されます。 

もう 1 つのエッジ ケースは、ブロックが消滅して隣接するブロックをマージするときに発生します。 例えば、`aabbaa`真ん中を十分に取り除いた後`bb`原因となる可能性があります`aa`マージするブロックを変更し、グローバル スキャンを行わずに利用可能な最大ブロックのセットを変更します。 リンク構造により、次のことが保証されます。`bb`が空になると、隣接ポインタがすぐに再接続され、一定時間内にマージが行われるため、文字列を再スキャンすることなく正確さが保たれます。
