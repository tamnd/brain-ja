 ## 解決策
 ## 問題の理解

 同じ長さの整数の 2 つの配列が与えられます。 各位置 i は「制約間隔」を定義しますが、間隔は順序付けされていません。インデックス i における候補整数 x の有効範囲は、どちらが大きいかに関係なく、単純に ai と bi の間のセグメントです。 したがって、各ペアは数直線上の閉区間に寄与します。 

タスクは、すべての制約を同時に満たす整数 x の数を数えることです。これは、x がこれらの n 個の区間のすべての内側に存在する必要があることを意味します。 言い換えれば、(ai, bi) で定義されるすべてのセグメントの交点にある整数点の数を探します。 

制約は大きく、n は最大 200000、値は最大 1e9 です。 これにより、考えられるすべての x を試したり、範囲を明示的に構築したりするアプローチは除外されます。 範囲サイズが大きすぎるため、値ドメインのフルスキャンは不可能です。 唯一実行可能な方向は、問題を間隔ごとに一定量の情報に圧縮することです。 

単純な間違いは、各間隔を 1 つずつチェックして候補をフィルタリングすることによって、有効な x 値のグローバル セットを構築しようとすることです。 範囲が大きい場合、多数の大きな整数間隔の交差を個々の点のセットとして明示的に表すことができないため、単一の間隔から開始して繰り返し交差するセットであっても爆発する可能性があります。 

2 番目の微妙な落とし穴は、各ペアが方向を定義していないため、(ai, bi) と (bi, ai) は同一の制約であることを忘れていることです。 それらを有向区間として扱うと、交差境界が不正確になる可能性があります。 

## アプローチ

 強引に試す場合は、1 から 1e9 までのすべての整数 x を反復処理し、それが n 個の間隔をすべて満たしているかどうかを確認することを想像できます。 各チェックのコストは O(n) であるため、最悪のケースは O(1e9 * n) となり、これは完全に実行不可能です。 

重要な観察は、各制約が標準の閉じた区間であるということです。 すべての有効な x のセットは、これらの間隔の正確な交点です。 直線上の複数の区間の交点も単一の区間であり、空である可能性があります。 つまり、多くの候補者を追跡する必要はなく、グローバルな重複のみが必要です。 

各間隔 [min(ai, bi), max(ai, bi)] は下限と上限に寄与します。 すべての間隔の交差は、すべての下限の最大値とすべての上限の最小値を取ることによって取得されます。 結果の左端点が右端点よりも大きい場合、交差点は空になります。 それ以外の場合、それらの間のすべての整数が有効となり、それらを直接カウントします。 

これにより、問題は n 個の間隔の管理から 2 つの実行値の維持に軽減されます。

 ## アルゴリズムのチュートリアル

 入力を 1 回スキャンする間、すべての間隔の交差を維持します。

1. 各ペア (ai, bi) について、それを適切な間隔 [l, r] に変換します。ここで、l = min(ai, bi) および r = max(ai, bi)。 エンドポイントは順序付けされていないため、この正規化手順が必要です。 
2. グローバル交差をすべての整数を含む区間として初期化します。左境界は非常に小さく、右境界は非常に大きくなります。 これにより、最初の間隔が初期制限を完全に定義することが保証されます。 
3. 区間 [l, r] ごとに、新しい左境界を max(current_left, l) に設定して交差を更新します。 これにより、これまでに確認されたすべての間隔で有効な値のみが保持されます。 
4. 同様に、右境界を min(current_right, r) に更新します。 これにより、制約を超える値が確実に破棄されます。 
5. すべての間隔を処理した後、結果の左境界が右境界より大きいかどうかを確認します。 その場合、すべての制約を満たす整数は存在しません。 
6. それ以外の場合、この閉区間内のすべての整数が有効であるため、答えは right − left + 1 になります。 

### なぜ効果があるのか

 各間隔は、許可される整数のセットを定義します。 直線上の間隔によって定義される集合の交点自体が間隔です。 すべてのステップで、維持される範囲は、それまでに処理されたすべての間隔の交差部分に正確に等しくなります。 新しい間隔の外側にある整数は少なくとも 1 つの制約に違反する必要がある一方、以前の交差と新しい間隔の両方の内側にある整数はこれまでに確認されたすべての制約を満たすため、更新ではこのプロパティが保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    left = -10**18
    right = 10**18
    
    for i in range(n):
        l = min(a[i], b[i])
        r = max(a[i], b[i])
        left = max(left, l)
        right = min(right, r)
    
    if left > right:
        print(0)
    else:
        print(right - left + 1)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを直接反映しています。 唯一の微妙な設計上の選択は、最初の交差境界に十分大きなセンチネルを使用することです。 入力値は最大 1e9 であるため、±1e18 を使用すると、最初の更新前の偶発的なクリッピングを安全に回避できます。 ロジックの残りの部分は、単純なローリング交差点です。

### 例 2

 入力:

 間隔は[3,6]、[7,8]、[10,12]です。 これらは重複しません。 

| ステップ | 間隔 | 左 | 右 |

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての間隔が同一の単一点である場合です。 (ai, bi) = (5, 5) が繰り返される入力 n = 3 の場合、アルゴリズムは最初の反復後に left = 5 および right = 5 を設定し、変更されません。 出力は 1 になり、x = 5 のみがすべての制約を満たすことが正しくカウントされます。 

もう 1 つのエッジ ケースは、最初の数ステップの直後に間隔が崩れる場合です。 たとえば:

 入力:

 n = 2

 a = [1, 100]

 b = [2, 90]

 正規化後、[1,2] と [90,100] が得られます。 最初の間隔を処理した後、left = 1、right = 2 となります。2 番目の間隔の後、left は 90 になり、right は 2 になり、left > right となり、出力 0 が生成されます。アルゴリズムは、その後の更新が一貫して継続する場合でも、交差点が空になるとすぐに不可能を正しく検出します。
