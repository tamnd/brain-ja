 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられます。 正確に k 個の位置を削除する必要がありますが、元の文字列内で削除された 2 つの位置が隣接してはいけないという厳密なルールがあります。 これらの文字を削除した後、残りの文字は順序どおりに残り、文字列は残りの文字の最大の連続したチャンクに分割されます。 

要件は、そのようなすべてのチャンクが文字列として同一である必要があるということです。 チャンクが 1 つしかない場合は、比較するものが存在しないため、条件は自明に満たされます。 

出力は、結果として得られるすべてのチャンクを等しくする k 個の隣接しない削除の選択肢が存在するかどうかという、単純な実現可能性チェックです。 

n が 200000 までの制約は、部分文字列に対する 2 次の動作や徹底的な削除シミュレーションを伴ういかなる解法も不可能であることを直ちに示唆しています。 線形または線形演算に近いものが必要で、構造的制約を伴う貪欲な構築やプレフィックス マッチングが含まれる可能性があります。 

隠れた重要な問題は、削除が任意の区切り文字ではないことです。削除は隣接してはなりません。 これにより、セグメンテーション構造がパス グラフ内の独立したセット選択の組み合わせと結合されます。 もう 1 つの微妙な点は、結果として得られるチャンクは長さが同じであるだけでなく、文字列としてすべて正確に等しい必要があることです。 

いくつかのエッジケースは、素朴な推論が失敗する場所を明らかにします。 

k が 0 に等しい場合、文字列全体が単一のチャンクとなり、答えは常に YES になります。 

k が大きくても、非隣接制約の下で有効な場合、残りの文字の構造により、多数の小さなチャンクが強制される可能性があります。 たとえば、周期的な文字列内で交互に削除すると、多数の単一文字セグメントが生成される可能性がありますが、残りの文字がすべて等しい場合に限り、これらのセグメントは自明に同一になります。 

素朴な考え方による典型的な失敗例は、残りのセグメントの長さが等しいことを確認するだけでよいと仮定することです。 たとえば、次のように考えてみましょう`s = "abacaba"`。 慎重に選択した 1 文字を削除すると、2 つの同一のセグメントが作成される可能性があります`"aba"`ただし、等長セグメンテーションだけではコンテンツの平等性は保証されません。 

もう 1 つの微妙な失敗は、削除位置がグローバルに一貫していて隣接していない必要があることを考慮せずに、貪欲に周期性を強制できると仮定していることです。 

## アプローチ

 ブルートフォース解釈では、k 個の隣接しないインデックスを選択し、結果の文字列をシミュレートし、それをチャンクに分割し、すべてのチャンクが等しいかどうかを確認します。 長さ n の文字列内の隣接しない k 個の位置を選択する方法の数は、パス グラフでサイズ k の独立したセットを選択するのと同等であるため、最悪の場合でも k においてすでに指数関数的になります。 候補を効率的に生成したとしても、各候補について文字列を再構築してセグメントを比較する必要があり、チェックあたり少なくとも O(n) になります。 これはすぐに実行不可能になります。 

重要な点は、削除が修正されると、残りの文字列は、削除された位置で区切られた単一ブロックの繰り返しコピーで構成されている必要があるということです。 つまり、残りの文字は繰り返しパターンを定義し、削除は同一のコピー間の区切りとしてのみ機能します。 

削除という観点から考える代わりに、視点を逆転させます。結果の文字列が t 個の同一のブロックで構成され、各ブロックが文字列 p であると仮定します。 次に、これらのブロック内に k 個の削除をインターリーブすることによって、元の文字列が形成されます。 削除を隣接させることはできないため、文字列を残りの文字の等しい連続セグメントに分割する方法で区切り文字を効果的に配布しています。 

重要な再定式化は、削除後に得られる文字列を、t 個の等しい連続セグメントに分割できるサブシーケンスとして考慮することです。 最終的な文字列の長さを m = n − k とします。 この場合、m は t で割り切れる必要があり、各セグメントの長さは m / t になります。 各セグメントは正確に一致する必要があります。これは、サブシーケンスが周期 m / t の周期構造を持っていることを意味します。 

ここで問題は、k 個の隣接しない文字を削除して得られる長さ m の部分列を、ある程度の周期長で周期的になるように選択できるかということです。 

非隣接制約は、残りの文字間の k 個のギャップを選択するものとして再解釈できます。これは、連続する 2 つの元の位置を削除できないため、削除は少なくとも 1 つの保持文字で区切る必要があることを意味します。 これは、最終的な文字列では、元のインデックスの任意の 2 つの削除位置の間に、少なくとも 1 つの保持された文字が存在することを意味し、削除の密度が制限されます。 

解決策は、最終的には、考えられるセグメント数を建設的にチェックすることになります。 m のすべての約数 t (または同等のすべての可能なブロック長) を試します。 各候補について、隣接制約を尊重しながら残りの文字列がブロック サイズ m / t で周期的になるように k 個の削除を選択できるかどうかをテストします。 このチェックは、繰り返しをまたがって整列する必要がある位置での文字の一貫性を検証することと、隣接性を侵害せずに位置を削除することで不一致を「修正」できるかどうかを検証することに要約できます。 

これにより、問題は、各候補期間の線形スキャンにわたる構造化された貪欲な実行可能性チェックに帰着します。

 ## アルゴリズムのチュートリアル

 まず最終的な長さ m = n − k を修正します。 m が正でない場合は、自明な場合に限りすぐに YES を返しますが、k ≤ (n+1)/2 という制約の下では m が有効であることが保証されます。 

次に、m % t == 0 となるように、考えられるすべての数の等しいブロック t に対して反復処理を行います。各 t について、ブロック長は L = m / t です。 

正確に k 個の文字を削除し、隣接する元のインデックスを決して削除せずに、長さ L の文字列を正確に t 回繰り返した長さ m のサブシーケンスを形成できるかどうかを検証しようとします。

元の文字列に対する貪欲なマッチング プロセスをシミュレートします。 長さ L のターゲット周期パターンへのポインターを維持します。元の文字列の文字ごとに、それをサブシーケンスの一部として保持するか削除するかを決定します。 

各位置 i で、s[i] をパターン位置 (構築されたサブシーケンス アラインメント内の i mod L) 内の予期される文字と比較します。 一致する場合は、それを保持し、パターン ポインタを進めます。 一致しない場合は削除を検討しますが、隣接制約を考慮して、前の元の位置が削除されていない場合に限ります。 

使用された削除の数を追跡します。 どこかの時点で k を超えた場合、この候補を停止します。 文字列全体が正常に処理され、正確に k 個の削除で終了し、パターンが完全に満たされている場合は、受け入れられます。 

すべての有効な t に対してこれを繰り返します。 

### なぜ効果があるのか

 有効な解は最終サブシーケンスに周期構造を誘導するため、アルゴリズムは正しいです。 ブロック数 t を固定すると、保持される各位置が何に整列する必要があるかの構造が完全に決定されます。 残された唯一の自由は、どの不一致文字を削除するかです。 削除はグローバルな相互作用ではなく隣接関係によってのみ制約されるため、実現可能性はローカルの貪欲な決定プロセスに帰着します。つまり、不一致が発生するたびに、隣接関係に違反しない限り、それを削除することが最適です。隣接関係に違反する場合、その候補期間は不可能です。 これにより、指定された t に対して有効な構成が存在する場合、貪欲シミュレーションがそれを見つけることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    m = n - k
    if m <= 0:
        print("YES")
        return

    # try all possible number of blocks t
    for t in range(1, m + 1):
        if m % t != 0:
            continue
        L = m // t

        deletions = 0
        last_deleted = False
        j = 0  # pointer in subsequence pattern

        ok = True

        for i in range(n):
            if j < m and s[i] == s[j % L]:
                j += 1
                last_deleted = False
            else:
                if last_deleted:
                    ok = False
                    break
                deletions += 1
                last_deleted = True
                if deletions > k:
                    ok = False
                    break

        if ok and j == m and deletions == k:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```実装では、候補となる周期構造を修正し、各文字が最終的なサブシーケンスに寄与するか、それとも削除する必要があるかを貪欲に決定します。 変数`j`サブシーケンスに受け入れられた文字の数を追跡します。`j % L`候補ブロックの繰り返しを強制します。 の`last_deleted`flag は、2 つの連続した削除を防止することで隣接性制約を強制します。 

最終チェックでは、正確に m 個の保持文字を構築し、正確に k 個の削除を使用したことを確認します。

 ## 特殊なケース

 重大なエッジ ケースは、最適なソリューションで 1 文字しか残らない場合です。 のために`n = 3, k = 2`、任意の文字列は単一文字の結果になるため、アルゴリズムは単一ブロックの周期性を有効なものとして扱う必要があります。 L が 1 になり、すべての文字がパターンに一致するため、貪欲シミュレーションはこれを自然に処理します。 

もう 1 つのケースは、隣接関係の制約により削除が強制的に分離される場合です。 たとえば、次のような文字列では、`abcdef`、隣接する不一致を削除しようとすると失敗します。`last_deleted`チェックして、文字の頻度が実現可能性を示唆している場合でも、不可能な期間の選択を正しく拒否します。 

さらに、周期長が m に近い長い場合には、エッジ ケースが発生します。 このような場合、パターンはほぼ完全なサブシーケンスに縮退し、不一致を修正するために使用できる欠失はわずか数個だけになります。 隣接関係の制限により連続エラーを削除できないため、クラスターが不一致の場合、このアルゴリズムは正しく失敗します。
