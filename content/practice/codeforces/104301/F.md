 ## 問題の理解

 整数の順序付きペアを数えています$(a, b)$どこ$0 \le a \le b$, ただし、すべてのペアが有効であるわけではありません。 この制限はビット単位の条件から生じます。つまり、次のビット単位の OR を取るときです。$a$そして$b$を超えてはなりません。$n$。 言い換えれば、いずれかの数値に含まれるすべてのビットは、それより大きな値を作成しない場合にのみ許可されます。$n$。 

これについて考えるのに役立つ方法は、$a$そして$b$設定されたビットを「マージ」します。マージされた数値は、依然として許容される範囲内にある必要があります。$n$。 両方の数値がそれぞれ小さい場合でも、それらの OR により上位ビットが導入され、値がそれを超える可能性があります。$n$。 

各テスト ケースでは異なる値が得られます。$n$そして、そのために存在する有効なペアがいくつあるかを計算する必要があります。$n$。 まであり得るので、$10^5$テストケースとそれぞれの$n$と同じ大きさにすることができます$10^9$が必要です。$O(1)$または$O(\log n)$試験溶液ごとに。 ペアを直接列挙するものはすぐに遅すぎます。$n$、潜在的にあります$O(n^2)$ペア。 

微妙なエッジケースが発生する場合$n = 0$。 この場合、唯一の有効なペアは$(0, 0)$。 もう 1 つの重要なケースは次のような場合です。$n = 1$、ペアが好きな場所$(0,1)$、$(1,1)$、 そして$(0,0)$OR 制約に対してすべてを慎重にチェックする必要があり、単純な推論では、OR が sum や max のように動作しないことを見逃してしまうことがよくあります。 

主な問題点は、OR 制約が数値ごとに分離できないことです。 独自に有効なものをカウントすることはできません$a$そして$b$ビット間の相互作用が重要であるためです。 

## アプローチ

 ブルートフォースソリューションでは、すべてのペアに対して反復処理が行われます。$(a, b)$と$0 \le a \le b \le n$、計算する$a \mid b$であるかどうかを確認します。$\le n$。 これは正しいですが、すぐには実行できません。 ペア数は約$n(n+1)/2$、おおよそ次のようになります$5 \times 10^{17}$操作時の操作$n = 10^9$。 

重要な観察は、次のバイナリ表現を見ることで得られます。$n$。 条件$a \mid b \le n$OR 結果が次の値を超えるビット パターンを導入してはいけないことを意味します。$n$。 唯一の問題となる状況は、OR が境界ビットを越える数値を生成する場合です。$n$ゼロがありますが、からのビットを組み合わせることで上位ビットがアクティブになります。$a$そして$b$。 

ペアに関して直接考える代わりに、視点を切り替えます。ビットのプレフィックスごとに、範囲内に留まるというプレフィックス制約に違反しない有効なペアがいくつ存在するかを数えます。$n$。 これはビットをめぐる桁動的計画法の問題になり、すでに厳密に下回っているかどうかを追跡します。$n$またはまだそのプレフィックスと一致しています。 

最上位ビットから下方向にビットを処理します。 各ビットで、ビットのすべての組み合わせを考慮します。$a$そして$b$その位置では、$a \le b$そしてOR制約。 OR 制約は、現在のプレフィックスが次の場合にのみ制限的になります。$a \mid b$の対応するプレフィックスを超える可能性があります$n$。 これにより、密接性に基づいて小さな状態空間を備えた DP を構築できます。$n$と間の順序制約$a$そして$b$。 

順序付けの制約$a \le b$ビット単位でも処理されます。 ビットをスキャンしている間、次のことを維持します。$a$すでに厳密に以下より小さいです$b$、またはプレフィックスが依然として等しい。 これは、バイナリ表現における標準の辞書編集 DP です。 

最終結果は、すべてのプレフィックスにわたるすべての有効なビット割り当ての合計です。

 ## アルゴリズムのチュートリアル

 のバイナリ表現に対してビットごとの動的プログラミングを使用して、各テスト ケースを独立して解決します。$n$。 

### ステップ

 1.変換$n$31 ビットのバイナリ形式に変換します ($n \le 10^9$）。 制約はプレフィックスベースであるため、最上位ビットから最下位ビットまで処理します。 これにより、以下を超える値が構築されることがなくなります。$n$すぐに検出せずに。 
2. 4 つの情報を追跡する DP 状態を定義します: 現在のビット位置、これまでの OR がまだプレフィックスと等しいかどうか$n$、そして$a$まだ等しい$b$プレフィックス用語か、すでに小さいものです。 OR の厳密性が必要なのは、ゼロビットを超えるためです。$n$構成はただちに無効になります。 
3. 各ビット位置で、ビットの 4 つの組み合わせをすべて試します。$(a_i, b_i)$で$\{0,1\} \times \{0,1\}$ただし、次の場合は割り当てを破棄します。$a_i > b_i$まだ等接プレフィックス状態にある場合$a \le b$。 これにより、プレフィックス全体で順序付けの制約が一貫して保持されます。 
4. ビットの候補ペアごとに、OR ビットを計算します。$o_i = a_i \mid b_i$。 まだ厳しい場合は$n$、このビットの設定が の対応するビットを超えないようにしてください。$n$。 もし$n_i = 0$そして$o_i = 1$の場合、この分岐はすでにグローバル制約に違反しているため無効です。 
5. 次のビット位置に移行し、OR 制約と順序制約の両方のタイトネス状態を更新します。 OR に小さいビットを配置すると、$n$、すべての下位ビットの制約から解放されます。 
6. ビット範囲の終わりに達したら、すべての有効なウェイを合計します。 この数にはすべての有効なペアが含まれます$(a, b)$両方の条件を満たしていること。 

### なぜ効果があるのか

 すべてのペア$(a, b)$ビット選択のシーケンスに一意に対応します。 DP はそのようなシーケンスをすべて列挙しますが、必然的に超過するシーケンスのみを削除します。$n$最初の違反箇所で。 順序付け状態により、無効な置換が決してカウントされないことが保証されます。$a > b$。 どちらの制約もプレフィックスごとに適用されるため、有効なペアが除外されることはなく、無効なペアが含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    bits = [(n >> i) & 1 for i in range(30, -1, -1)]
    L = len(bits)

    from functools import lru_cache

    @lru_cache(None)
    def dp(i, tight, eq):
        if i == L:
            return 1

        res = 0
        nb = bits[i]

        for a in (0, 1):
            for b in (0, 1):
                if a > b:
                    continue

                o = a | b

                if tight and o > nb:
                    continue

                ntight = tight and (o == nb)

                # ordering tightness update:
                # eq = 1 means a == b so far
                # if a < b, we become strictly smaller forever
                neq = eq and (a == b)

                res += dp(i + 1, ntight, neq)

        return res

    return dp(0, True, True)

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(solve_case(n))

if __name__ == "__main__":
    main()
```このコードは、ビットに対して再帰的な数字 DP を構築します。 機能`dp(i, tight, eq)`ビットからの有効な割り当てをカウントします`i`これからも。 の`tight`フラグは、これまでに構築された OR が接頭辞を超えないことを強制します。`n`。 の`eq`フラグは、次の間の順序制約を強制します。`a`そして`b`プレフィックスの意味で、以下と一致する遷移のみを許可するようにします。$a \le b$。 

各ステップで、4 つのビット ペアすべてが試行されます。 無効なトランジションは早期に削除されます: 違反するトランジション$a \le b$、またはORを超えるもの$n$。 再帰により、有効な完了が蓄積されます。 

各状態は何度も再利用されるため、メモ化は不可欠です。 これがないと、再帰はビット位置にわたって指数関数的に拡大します。

 ## 特殊なケース

 のために$n = 0$の場合、DP には有効な割り当てが 1 つだけあります。両方の数値がすべてのビット位置で 0 でなければなりません。 OR 制約はビットの設定を即座に禁止し、順序制約は簡単に満たされます。 基本ケースでは単一の空の構造がカウントされるため、アルゴリズムは正しく 1 を返します。 

次のような 2 の小さな累乗の場合、$n = 2$、最上位ビットには厳しい制限が導入されます。 3 以上の OR を生成するペアは、最初の違反ビットで拒否されます。 DP はこれをローカルで強制するため、無効なサフィックスが構築されることはありません。 結果には、両方の数値が許可されたビット パターン内に収まる組み合わせのみが含まれます。 

次のような値の場合$n = 7$、すべての下位ビットが 1 である場合、厳密な制約がアクティブになることはほとんどありません。 DP はほとんどの組み合わせを効果的に探索し、正当性は無効な組み合わせの二重カウントを防ぐために順序付け状態に依存します。$a > b$ケース。
