 ## 解決策
 ## 問題の理解

 複数の独立したシナリオが与えられます。 各シナリオでは、読者は数日間にわたる一連の読書量と本の長さのリストを持っています。 毎日、本を順番に読み進めるために使用できる一定のページ数が提供されます。 本を完全に覆うのに十分なページが蓄積されると、その本は永久に完成したものとみなされます。 

毎日、その日の読書の進捗状況を処理した後、完全に読み終えた本の数を報告する必要があります。 

重要な点は、本は順番に消費され、部分的な進捗は日をまたいで引き継がれるということです。 毎日の後の答えは独立したものではなく、それまでのすべての日に依存します。 

制約は厳しいです。 すべてのテスト ケースの合計日数と本の数は最大です。$2 \cdot 10^5$。 これにより、毎日の進捗状況を最初から再計算したり、本のリストを繰り返しスキャンしたりするソリューションは即座に除外されます。 1 日にすべての書籍をチェックする単純なシミュレーションでは、次のように劣化します。$O(nm)$最悪の場合、それは許容範囲をはるかに超えています。 

いくつかの微妙な特殊なケースが重要です。 1 つは、1 日に複数の本を一度に読み終えるのに十分なページ数がある場合です。 もう 1 つは、本が非常に小さいために急速に消費される場合、または非常に大きいために何日も進歩がない場合です。 完成した複数の本を正しくループせずに、現在の本から減算するだけの単純な解決策は、次のような場合に失敗します。 

入力:```
1
3 3
10 10 10
5 5 20
```正しい動作:

 1日目は1冊、2日目は2冊、3日目は3冊完了します。 

バグのあるアプローチでは、1 日に 1 冊の本を読み終えた後に停止し、連鎖した完了が失われる可能性があります。 

## アプローチ

 強引なアイデアは簡単です。現在の本と必要な残りのページへのポインタを維持します。 毎日、その日のページを追加し、可能な限り本のサイズを繰り返し減算します。 これは正しいですが、実装には注意が必要です。 最悪のケースは、毎日 1 冊の本だけを読み終えて、日をまたがって多くのエントリに繰り返し触れる場合です。ただし、その場合でも、各本は 1 回削除されるため、合計の作業量は$O(n + m)$。 ただし、毎回最初からスキャンを再開したり、次の未完の本を繰り返し検索したりする単純なネストされたアプローチでは、二次関数になってしまいます。 

重要な点は、各本は一度だけ読み終えるだけであり、一度読み終えたら、再度読む必要がないということです。 これは、書籍リストへの単一のポインタと蓄積されたページの実行カウンタを維持できることを意味します。 各ブックはテスト ケース全体で最大 1 回処理されるため、償却された複雑さは線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 再スキャンによるブルート フォース シミュレーション |$O(nm)$|$O(1)$| 遅すぎる |
 | 2 点累積シミュレーション |$O(n + m)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 書籍配列へのポインターと、これまでに収集されたページの累計という 2 つの変数を維持します。 

1. ポインタを初期化する`i = 0`最初の本と変数を指す`cur = 0`蓄積されたページを保存します。 
2. 順番に毎日、その日の読書量を`cur`。 これは、繰り越される未読ページの合計を表します。 
3. その間`cur`現在の本を完全に覆うのに十分な大きさです (`cur >= b[i]`) そしてまだ本が残っているので、から本のサイズを引きます。`cur`そして移動します`i`フォワード。 それぞれの減算が 1 冊の本を読み終えることに相当します。 
4. その日の可能な完了をすべて処理した後、出力します。`i`, これは、これまでに完全に完了した本の数です。 

重要なアイデアは、ポインターは前方にのみ移動するということです。 一度ページが削除されると、その本は永久に完成するため、私たちは決してその本を読み返すことはありません。 

### なぜ効果があるのか

 いつでも、`cur`未完了の作業にまだ割り当てられていない残りのページを表します。 本を読み終えるたびに、そのページ数を正確に削除し、`cur`次の未完成の本に向けて残っている部分的な進行状況を常に反映します。 ブックは順番に処理され、再アクセスされることはないため、ポインタ`i`単調増加です。 これにより正確性が保証され、二重カウントやスキップが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    i = 0
    cur = 0
    res = []
    
    for x in a:
        cur += x
        
        while i < m and cur >= b[i]:
            cur -= b[i]
            i += 1
        
        res.append(str(i))
    
    print(" ".join(res))
```コードはアルゴリズムに直接に従います。 変数`cur`数日間にわたってページが蓄積されます。 ポインタ`i`完全に完了した本の数を追跡します。 内側のループは、現在蓄積されているページで完了できるすべての書籍を削除し、連鎖完了が正しく処理されるようにします。 

実装によくある落とし穴は、`while`ループし、それを単一のループに置き換えます`if`、これでは誤って 1 日に 1 冊しか完了できなくなります。

 | 測定 | 複雑さ | 説明 |

テスト ケース全体の入力サイズの合計は次のとおりです。$2 \cdot 10^5$したがって、テスト ケースの集計ごとの線形時間処理は容易に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out_lines = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        i = 0
        cur = 0
        res = []
        for x in a:
            cur += x
            while i < m and cur >= b[i]:
                cur -= b[i]
                i += 1
            res.append(str(i))
        out_lines.append(" ".join(res))
    
    return "\n".join(out_lines)

""") == """1 1 2 2

 | --- | --- | --- |
 | 最小サイズ | 0 | 完了した本はありません |
 | チェーンの完成 | 1 2 3 | 複数の書籍を 1 つのフローで |
 | 進歩なし | 0秒 | 大きな本が進歩を妨げる |
 | 大きな一日 | 3 | ワンステップで完全消費 |

 ## 特殊なケース

 主なエッジケースは、1 日に複数の本を読み終える場合です。 アルゴリズムはこれを次のように処理します。`while`蓄積されたページが十分である限り、本を消費し続けるループ。 たとえば:

 入力:```
1
1 3
100
10 20 30
```実行は次から始まります`cur = 100`。 ループは 10、次に 20、次に 30 を削除し、3 冊すべての本を 1 ステップで終了して終了します。`cur = 40`。 ポインタが最後に到達したため、出力は次のようになります。`3`。 

もう 1 つの特殊なケースは、本が大きすぎて 1 日では読みきれない場合です。 ポインタが動かず、`cur`単純に溜まっていく。 これにより、実現可能性が得られるまで減算が行われないため、不必要な操作を行わずに正確性が保証されます。
