 ## 問題の理解

 多くの独立したクエリが与えられます。 各クエリは負ではない整数を提供します$n$、整数がいくつあるかを数えなければなりません$x$からの範囲で$0$に$n$は 2 つの整数の平方和として書くことができます。つまり、$x = a^2 + b^2$いくつかの整数の場合$a$そして$b$。 両方$a$そして$b$は負でも正でも構いませんが、二乗すると符号が削除されるため、表現は絶対値のみに依存します。 

各クエリの出力は表現の数ではなく、個別の値の数です。$x \le n$少なくとも 1 つのそのような表現を認めます。 

制約により、前処理が必要になります。 まで$10^5$クエリと$n \le 10^7$、クエリごとに答えを再計算することは不可能です。 線形であってもクエリごとのメソッド$n$届くだろう$10^{12}$限界をはるかに超えた最悪の場合の操作。 これは、グローバル構造を最大値まで一度計算する必要があることを直ちに示唆しています。$n$、その後、一定時間内に各クエリに応答します。 

微妙なエッジケースは、$x = 0$。 それは有効です。$0 = 0^2 + 0^2$、を含める必要があります。 間違いが起こりやすいもう 1 つの点は、重複してカウントすることです。 例えば、$5 = 1^2 + 2^2$そしてまた$5 = 2^2 + 1^2$, ただし、カウントされるのは 1 回だけです。 出力は、多重性ではなく、存在に関するものです。 

素朴なアプローチでは、多くの場合、それぞれをテストしようとします。$x$すべてのペアをスキャンすることにより$(a, b)$ただし、この二重ループは最大で 1 つのクエリでもすぐに大きくなりすぎます。$n$までのすべてのペアを反復処理する必要があるため、$\sqrt{n}$、 だいたい$10^4$次元ごと、または$10^8$クエリごとにチェックします。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリと各数値について$x \le n$、すべての整数のペアを試します$(a, b)$そのような$a^2 + b^2 = x$。 それぞれの候補者数は$x$に比例する$\sqrt{x}$ので、すべてチェックしてください$x \le n$おおよそにつながります$\sum_{x=1}^{n} \sqrt{x}$のオーダーで成長します。$n^{3/2}$。 と$n = 10^7$、これはまったく不可能です。 

重要な点は、クエリごとに構造を再計算する必要がないことです。 「2 つの平方和として記述できる」という性質は、次の値にのみ依存します。$x$、クエリ自体ではありません。 これにより、最大値までのすべての有効な値を事前計算できます。$n$一度。 

それぞれの数値を個別にテストするのではなく、視点を反転します。 可能な正方形を列挙します$a^2$そして$b^2$、それらの合計を直接マークします。 以来$a^2 \le 10^7$、必要なのは$a \le 3162$。 これにより、すべてのペアを反復処理する問題が軽減されます。$(a, b)$と$a^2 + b^2 \le \text{maxN}$。 各ペアは 1 つの到達可能な合計を提供し、これをブール配列でマークします。 

到達可能なすべての合計をマークした後、各クエリに次の形式で回答できるようにプレフィックス合計配列を構築します。$O(1)$時間。

 ## アルゴリズムのチュートリアル

 この問題は、可能な最大のクエリまですべての値を事前計算し、プレフィックスの合計を使用して各クエリに答えることで解決します。 

1. まず、最大のものを決定します$n$すべてのテストケースにわたって。 これが必要なのは、クエリごとに再計算するのではなく、単一のグローバル計算を必要とするためです。 これがなければ、同じ作業を繰り返して時間を無駄にすることになります。 
2. ブール配列を作成する`ok`サイズの`max_n + 1`、最初はすべて false です。 この配列には、数値が 2 つの平方和として表現できるかどうかが格納されます。 
3. すべての整数を反復処理します。$a$そのような$a^2 \le max_n$。 それぞれについて$a$、計算する$a^2$一度使用して再利用します。 これにより、正方形を繰り返し再計算することが回避され、効率が確保されます。 
4. 固定ごとに$a$、すべての整数を反復処理します。$b$そのような$a^2 + b^2 \le max_n$。 各ペアにマークを付けます`ok[a^2 + b^2] = True`。 有効なペアのみを列挙するため、ループ条件を超えて境界チェックは必要ありません。 
5. すべてのペアが処理された後、プレフィックス合計配列を構築します`pref`どこ`pref[i]`値の数を数えます$x \le i$満足する`ok[x]`。 これにより、問題は集合メンバーシップ クエリから範囲カウント クエリに変換されます。 
6. 各テストケースについて$n$、出力`pref[n]`。 

### なぜ効果があるのか

 すべての有効な表現$x = a^2 + b^2$ちょうど 1 つの非負の整数のペアに対応します$(a, b)$と$a \le b$または$b \le a$, しかし、ペアレベルでの一意性は必要ありません。 到達可能な各合計が少なくとも 1 回マークされていることを確認するだけで済みます。 すべてのペアを体系的に列挙するため、表現可能なすべての番号がマークされます。 接頭辞の合計は、少なくとも 1 つの有効な表現を持つ整数を正確にカウントするため、答えは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    ok = [False] * (max_n + 1)

    a = 0
    while a * a <= max_n:
        a2 = a * a
        b = 0
        while a2 + b * b <= max_n:
            ok[a2 + b * b] = True
            b += 1
        a += 1

    pref = [0] * (max_n + 1)
    cnt = 0
    for i in range(max_n + 1):
        if ok[i]:
            cnt += 1
        pref[i] = cnt

    out = []
    for n in ns:
        out.append(str(pref[n]))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装における中心的なアイデアは、二重ループです。$a$そして$b$、平方和が範囲内にある間のみ実行されます。 これにより、最大値を超えて不要なペアを探索することがなくなります。$n$。 ブール配列により、異なるペアからの同じ値が二重にカウントされるのを防ぎます。 

プレフィックス合計の構築は、事前に計算されたメンバーシップ配列をクエリ応答構造に変換するため、不可欠です。 これがないと、各クエリで次のスキャンが必要になります。$n$が鈍くなるにもほどがあります。

 ## 特殊なケース

 ### ケース:$n = 0$入力：```
1
0
```アルゴリズムが初期化されます`ok[0] = True`なぜなら$0 = 0^2 + 0^2$。 プレフィックス配列は次で始まります`pref[0] = 1`したがって、出力は 1 です。二重ループはこのケースを決して見逃すことはありません。$a = 0, b = 0$明示的に含まれています。 

### ケース: 少数の合計しか存在しない小さな境界

 入力:```

```列挙のマークは次のとおりです。$0 = 0^2 + 0^2$、$1 = 0^2 + 1^2$、$2 = 1^2 + 1^2$。

```マークされた値には、0、1、2、4、5、および 8 が含まれます。プレフィックス カウントには、これら 6 つの値が正しく累積されます。 ネストされたループにより、境界までのすべての有効なペアが探索されることが保証されるため、たとえ連続していなくても、表現可能な数値が見逃されることはありません。
