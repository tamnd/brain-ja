 ## 解決策
 ## 問題の理解

 私たちは、ヤロスラフとアンドレイという 2 人のプレイヤー間のターンベースのゲームを分析するように求められています。各プレイヤーは長さ 2·n のバイナリ文字列を持っています。 これらは、結合されたインデックス セット {1, 2, …, 2·n} から交互に位置を選択します。 各ターンで、選択された位置により、そのインデックスの文字列からキャラクターがプレイヤーに与えられます。 ゲームの終了時に、各プレイヤーは集めたキャラクターを並べ替えて、可能な限り最大の 2 進数を形成し、より大きな数字を持ったプレイヤーが勝ちます。 

入力では n が与えられ、これによって各文字列と文字列自体の長さが決まります。 出力は単純に、両方が最適にプレイした場合にどちらが勝つかを示します。ヤロスラフが「先手」、アンドレイが「後手」、数字が等しい場合は「引き分け」です。 

n が 10^6 に達する可能性があるとすると、(2・n) 個あるため、すべての一連の動きの総当りシミュレーションは実行不可能です。 考慮すべき順列。 これにより、明示的なシミュレーションを試みるソリューションは除外されます。 正しい解は、n に関して線形または線形算術時間で機能する必要があります。 

主なエッジケースは、文字列の 0 と 1 の分布が非常に偏っている場合です。 たとえば、一方のプレイヤーがすべて 1 を持ち、もう一方のプレイヤーがほとんど 0 を持っている場合、手の選択は単純になりますが、両方のプレイヤーが同じ数の 1 を持っているにもかかわらず、配置が不均一である場合、単純に 1 だけを数えることは誤解を招く可能性があります。 両方のプレイヤーの 1 と 0 の数が等しい場合、別の微妙な問題が発生します。この場合、ターン順序により、最初のプレイヤーにゲームを決定する可能性のある小さなアドバンテージが与えられます。 

## アプローチ

 ブルートフォースアプローチでは、両方のプレイヤーが行う可能性のあるすべての選択をシミュレートする必要があります。 各ターンで、現在のプレイヤーはポジションを選択し、対応するキャラクターを記録し、すべてのポジションが使い果たされるまでゲームが再帰的に続きます。 最後に、集めたキャラクターを並べ替えて、各プレイヤーの最大数を計算します。 このアプローチは原理的には正しいですが、その時間計算量は 2・n の階乗であり、10^6 までの n には大きすぎます。 

最適なアプローチは、1 は常に上位の位置に配置されるべきであるため、最終的な数字の値は各プレーヤーが確保できる 1 の数によってのみ決まるという観察から生まれます。 したがって、プレイヤーは 1 をめぐって競争するだけで済みます。各プレイヤーは、可能であれば 1 のポジションを取ることを目指すか、相手に 0 を強制することで 1 を拒否する必要があります。 

両方のプレイヤーが 1 を持つポジションの数、ヤロスラフだけが 1 を持つポジション、そしてアンドレイだけが 1 を持つポジションの数を数えることができます。ゲームは、プレイヤーが交互に残りの最大値 (可能であれば 1、そうでない場合は 0) を選択し、各ターンでカウントを調整するシーケンスとして見ることができます。 これにより、すべての手を明示的にシミュレートするのではなく、単純な算術といくつかの条件付きルールに問題が軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O((2n)!) | O(2n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 両方の文字列が 1 を持つ位置 (common_ones)、Yaroslav のみが 1 を持つ位置 (s_only)、Andrey のみが 1 を持つ位置 (t_only) の数を数えます。 両方のプレイヤーにとって 0 のポジションは、それらを獲得しても数値的アドバンテージが増加も減少もしないため、無関係です。 
2. 各プレーヤーが集めた 1 の数に応じてカウンターを初期化します (first_score = 0、second_score = 0)。 
3. ターンをシミュレートします。ヤロスラフから交互に始まる 2·n ターンがあります。 ヤロスラフのターンでは、彼に最も高い価値をもたらすポジションを選択する必要があります。 common_ones > 0 の場合、それらの 1 つを取得します (first_score をインクリメントし、common_ones をデクリメントします)。 それ以外の場合、s_only > 0 の場合は、それらのいずれかを採用します (first_score をインクリメントし、s_only をデクリメントします)。 それ以外の場合は、スコアを増加させることなく、残りの低い値の位置 (t_only または両方のゼロ) を削除します。 
4. Andrey の番では、同じロジックを使用します。common_ones を優先し、次に t_only を優先し、次に残りの 0 または s_only を優先します。 
5. すべてのターンの後、first_score と Second_score を比較します。 first_score > Second_score の場合、ヤロスラフが勝ちます。 Second_score > first_score の場合、アンドレイが勝ちます。 それ以外の場合は引き分けです。 

機能する理由: 常に残りの最も高い 1 を獲得するか、対戦相手に 1 を拒否することで、各プレイヤーは潜在的なスコアを最大化します。 この戦略は正確な位置ではなく、カウントに依存します。これは、最後の再配置によって最大の数を形成できるためです。 この不変式により、明示的な検索を行わずに最適なプレイが確実にシミュレートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()
t = input().strip()

both_ones = 0
s_only = 0
t_only = 0

for i in range(2*n):
    if s[i] == '1' and t[i] == '1':
        both_ones += 1
    elif s[i] == '1':
        s_only += 1
    elif t[i] == '1':
        t_only += 1

first_score = 0
second_score = 0

turns = 2*n
for turn in range(turns):
    if turn % 2 == 0:  # Yaroslav's turn
        if both_ones > 0:
            both_ones -= 1
            first_score += 1
        elif s_only > 0:
            s_only -= 1
            first_score += 1
        elif t_only > 0:
            t_only -= 1
        else:
            pass
    else:  # Andrey's turn
        if both_ones > 0:
            both_ones -= 1
            second_score += 1
        elif t_only > 0:
            t_only -= 1
            second_score += 1
        elif s_only > 0:
            s_only -= 1
        else:
            pass

if first_score > second_score:
    print("First")
elif first_score < second_score:
    print("Second")
else:
    print("Draw")
```コードはまず、文字列内の位置の種類をカウントします。 次に、カウントのみを使用してゲームをシミュレートします。 ターン ロジックでは、各プレイヤーの潜在的なスコアを最大化するために、慎重にポジションに優先順位が付けられます。 微妙な点は、both_one が存在する場合、最初のプレイヤーが先に 1 つを取ることでアドバンテージを得るということです。 最初にデクリメントするカウンタを混同すると、off-by-one エラーが発生する可能性があります。
