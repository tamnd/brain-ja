 ## 解決策
 ## 問題の理解

 3 サイクルと呼ばれる操作のみを使用して整数の配列をソートできるかどうかを判断するように求められます。 3 サイクルは 3 つの異なるインデックスを選択し、それらの間で要素を回転させます。 たとえば、配列が`[a, b, c, d]`そしてインデックスを選択します`1, 2, 3`、3 サイクル後の配列は次のようになります。`[c, a, b, d]`。 タスクは配列を明示的にソートすることではなく、この方法で配列をソートできるかどうかを判断することだけです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列と配列自体のサイズが示されます。 配列内の各整数は 1 ～ n の間です。 n は最大 500,000 であり、すべてのテスト ケースの合計も 500,000 であるため、線形または線形に近いアプローチが必要です。 可能な 3 サイクルのシーケンスをすべてシミュレートするソリューションは組み合わせによるものであり、これらの制約内では不可能です。 

微妙なエッジケースは、置換のパリティから現れます。 3 サイクルは、置換理論の意味では奇数の置換です。偶数の隣接するスワップに分解できます。 これは、すべての順列を 3 サイクルだけでソートできるわけではないことを意味します。 例えば、`[2, 1]`2 つの要素の交換には 2 サイクルが必要であり、これを 1 つの 3 サイクルでは表現できないため、これは不可能です。 要素が繰り返される配列。`[2, 2]`、同じ数値を交換しても効果がなく、配列はすでにソートされているため、自明にソート可能です。 

## アプローチ

 ブルートフォースアプローチは、3 サイクルのすべてのシーケンスを試すことです。 サイズが n の配列の場合、3 サイクルの数は n3 のオーダーであり、シーケンスの数は指数関数的に増加します。 これは、n が 500,000 までの場合は明らかに実行不可能です。 3 サイクルを使用して各要素をソートされた位置に貪欲に移動しようとしても面倒になります。3 サイクルでは 3 つの要素しか回転できず、一部の構成はどの組み合わせでも解決できないためです。 

重要な洞察は、ソートによって引き起こされるインデックスの順列に注目することです。 ポジションに番号を付けると`1..n`そして、ソートされた配列を実現するために各要素がどこに行く必要があるかを考慮すると、位置の順列が得られます。 次に、問題は順列理論からの質問に帰着します。この順列は 3 サイクルの積として表現できるか? これは、順列が偶数順列であるかどうかを尋ねることと同じです。 個別の要素を持つ配列の場合、単純な 2 要素の交換を除いて、あらゆる順列は 3 サイクルの積として表現できます。 同一の要素を交換すると奇数パリティが効果的にキャンセルされ、重複するすべての配列を並べ替えることができるため、要素を繰り返すと作業が容易になります。 

したがって、最適なアプローチは次のとおりです。 

1. 重複を数えます。 少なくとも 1 つの重複がある場合、答えは常に「YES」です。 
2. それ以外の場合は、ソートによって引き起こされる置換のパリティを計算します。 順列が偶数の場合、3 サイクルとして表すことができます。 奇数であれば、それはできません。 偶数の場合は YES、奇数の場合は NO を返します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n³) | O(n) | 遅すぎる |
 | 順列パリティ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 各テスト ケースについて、n と配列 a を読み取ります。 
2. a の値が複数回出現するかどうかを確認します。 「はい」の場合は、すぐに「YES」を出力します。 繰り返し要素を使用すると、重複を交換することで奇数の順列を修正できます。 
3. すべての要素が異なる場合は、配列の並べ替えに必要な順列を計算します。 これは、各要素をそのインデックスとペアにし、値でペアを並べ替え、元のインデックスの新しい位置を記録することによって行われます。 
4. この順列のパリティを計算します。 サイズ n の訪問済み配列を初期化して、どの位置が処理されたかをマークします。 未訪問の位置ごとに、開始位置に戻るまでその位置が形成するサイクルに従います。 各サイクルの長さを数えます。 長さ k のサイクルは k-1 回の転置に寄与します。 すべてのサイクルを合計して、転置の総数を決定します。 
5. 移調の総数が偶数の場合は、YES を出力します。 それ以外の場合は NO を出力します。 

機能する理由: このアルゴリズムは、あらゆる順列をサイクルに分解できるという事実を利用しています。 順列のパリティ (偶数または奇数の転置) によって、それが 3 サイクルの積として表現できるかどうかが決まります。 要素を繰り返すことでパリティを調整できるため、重複するすべての配列がソート可能になります。 サイクルと転置を明示的にカウントすることで、ソートが可能かどうかを判断します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if len(set(a)) < n:
            print("YES")
            continue
        
        # Compute permutation
        b = sorted((val, i) for i, val in enumerate(a))
        p = [0] * n
        for idx, (_, original_idx) in enumerate(b):
            p[original_idx] = idx
        
        # Count transpositions to compute parity
        visited = [False] * n
        transpositions = 0
        for i in range(n):
            if not visited[i]:
                cycle_len = 0
                j = i
                while not visited[j]:
                    visited[j] = True
                    j = p[j]
                    cycle_len += 1
                transpositions += cycle_len - 1
        
        print("YES" if transpositions % 2 == 0 else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは最初に重複を処理し、すぐに並べ替え可能性を保証します。 個別の要素の場合、置換配列は現在のインデックスをソートされた位置にマップします。 この順列の各サイクルを訪問することで、必要な転置の数を計算します。 長さ k の各サイクルには、k-1 回の転置が必要です。 これらの転置の合計により、置換パリティが得られます。 

## 実用的な例

 **例 1:**`[3, 1, 2]`| ステップ | 私 | 訪問しました | j | サイクルレン | 移調 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | [F、F、F] | 0->2->1->0 | 3 | 2 |

 合計移調 = 2 → 偶数 → はい。 

**例 2:**`[2, 1]`| ステップ | 私 | 訪問しました | j | サイクルレン | 移調 |

 | 1 | 0 | [F、F] | 0->1->0 | 2 | 1 |

 合計転置 = 1 → 奇数 → NO。 

これらの例は、循環棚卸方法によってソート可能性が正しく判断されることを示しています。

 ## 特殊なケース

 のために`[2, 1]`、すべての要素は個別であり、順列は`(2 1)`は単一の転置、奇数パリティです。 アルゴリズムは Visited[0] をマークし、サイクルを 1 までたどって 0 に戻り、転置 = 1 を計算し、NO を出力します。 のために`[2, 2]`、重複が存在するため、アルゴリズムはパリティを計算せずにすぐに YES を出力します。 これは、最小サイズの配列と重複するエッジ ケースの両方の処理を示しています。
