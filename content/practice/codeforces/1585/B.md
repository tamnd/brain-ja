 ## 解決策
 ## 問題の理解

 一連の数値が与えられ、現在のシーケンスの最後の要素のみに依存する変換を繰り返し適用します。 各変換は、配列を 2 つのサブシーケンスに分割します。各グループ内の元の相対順序は維持しながら、最後の要素以下の要素は前に移動し、厳密にそれより大きい要素は後ろに移動します。 その後、配列はこの連結によって置き換えられます。 

配列の変更が停止するまで、この操作を何回適用する必要があるかを尋ねられます。 変換を適用しても配列が変更されなくなると、その後のアプリケーションでは配列が変更されないままになり、この安定化が起こった最初の瞬間を出力します。 

この制約により、テスト ケース全体で最大 2 · 10^5 の合計要素が許可され、最悪のケースで 2 次のシミュレーションが即座に除外されます。 配列を繰り返し再構築し、操作ごとに完全なシーケンスをスキャンする単純なアプローチでは、配列の展開が遅い場合に O(n^2) に低下する可能性があり、制限を下回ると遅すぎます。 

配列がすでに固定小数点にある場合、微妙なエッジ ケースが発生します。 たとえば、すべての要素が等しい場合、たとえば [7, 7, 7, 7] の場合、最後の要素はすべてを左側に分割し、右側には何も移動しないため、配列は変更されません。 正解は 0 です。不注意なシミュレーションでも 1 回完全な反復を実行し、それを意味のある変更として誤ってカウントする可能性があります。 

もう 1 つの重要なケースは、配列が厳密に増加している場合です。 [1, 2, 3, 4] の場合、最後の要素は常に最大値であるため、やはり何も動かず、答えは 0 になります。これは、プロセスが必ずしも「並べ替え」を行うわけではなく、より大きな要素がピボットの前に現れた場合にのみ再編成されることを示しています。 

## アプローチ

 直接シミュレーションは簡単です。各ステップで最後の要素を取得し、配列をスキャンし、要素がこのピボット以下であるか > であるかに応じて 2 つのリストに分割し、それらを連結します。 各ステップのコストは O(n) です。 問題は、各操作で順序付けが部分的にしか改善されないため、最悪の場合、最大 O(n) ステップのシミュレーションが必要になる可能性があることです。 これにより、O(n^2) が得られますが、これは合計要素数 2・10^5 に対して大きすぎます。 

重要な観察は、プロセスが現在のピボットよりも大きい要素の位置によって駆動されるということです。 各操作は、最終的にソートされた構造に対してすでに正しく配置されている要素間の境界を効果的に「前に押し出します」。 変更をシミュレートする代わりに、将来のすべての操作において安定したサフィックス内にすでに要素がいくつあるかを推論できます。 

端からスキャンすると、これまでの最大値を維持できます。 この実行最大値よりも大きい要素に遭遇した場合、それは、この要素が正しい領域に落ち着く前に、最終的に少なくとももう 1 回の自明でない反転を強制することを意味します。 このような「サフィックス優位性の破壊」はそれぞれ、1 つの必要な操作に対応します。 

具体的には、最後の最大要素自体を除いて、右から左にトラバースするときに新しい最大値が表示された回数を数えます。 このカウントは、安定化前の有効な変更の数に直接対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 最大トラッキングによる逆スキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列の最後の要素から開始し、それを現在の最大値として扱います。 この要素は、いかなる操作においてもそれ自体を通過することはないため、初期の安定したサフィックスを形成します。 
2. 配列を右から左にトラバースし、この方向でこれまでに確認された最大値を維持します。 この最大値は、以前の要素がすでに最終的な順序と「互換性」があるかどうかを定義するしきい値を表します。 
3. 現在の最大値より厳密に大きい要素に遭遇するたびに、最大値を更新し、カウンターをインクリメントします。 このイベントは、少なくとも 1 つの変換手順がなければ解決できないサフィックス順序の構造違反を表します。 
4. トラバースの終了後、カウンタは、固定点に到達するまでに配列の構造を何回修正する必要があるかを表します。 
5. このカウンタを答えとして返します。 

### なぜ効果があるのか

 各バージョンは最後の要素をピボットとして使用し、その値に基づいて要素を分割します。 最終的な安定した構成は、右から見て、最大接尾辞要素を超える前の要素がない状況に対応します。 右からのスキャン中に新しい最大値が現れるたびに、配列が安定する前に、最終的に何らかの操作のピボットになる必要がある点をマークします。 これらの最大値は、外転によって解決される方法とは逆の順序で発生するため、それらをカウントすると、それ以上の再配置が不可能になるまで必要な操作の数が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = 0
        ans = 0
        
        for i in range(n - 1, -1, -1):
            if a[i] > mx:
                mx = a[i]
                ans += 1
        
        out.append(str(max(0, ans - 1)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを独立して処理します。 逆スキャンでは実行最大値が維持されます。 新しい最大値が現れるたびに、カウンターが増加します。 最後に確認された最大値はすでに安定したサフィックスに対応しており、演算を必要としないため、最終的な答えは 1 を減算することによって調整されます。 この微妙な減算は、正確性を保証する主な実装の詳細です。これがないと、完全にソートされた配列は、0 ではなく、誤って 1 を返します。 

## 実用的な例

 ### 例 1: [2、4、1、5、3]

 接尾辞の最大値を右から左に追跡します。 

| インデックス（右→左） | 値 | 現在の最大値 | 新しいマックス？ | カウンター |
 | --- | --- | --- | --- | --- |
 | 4 | 3 | 3 | はい | 1 |
 | 3 | 5 | 5 | はい | 2 |
 | 2 | 1 | 5 | いいえ | 2 |
 | 1 | 4 | 5 | いいえ | 2 |
 | 0 | 2 | 5 | いいえ | 2 |

 counter = 2 が得られ、1 を減算すると 1 が得られます。これは、意味のある 1 回の変換の後、配列が安定するという事実と一致します。 

### 例 2: [5, 3, 2, 4, 1]

 | インデックス（右→左） | 値 | 現在の最大値 | 新しいマックス? | カウンター |
 | --- | --- | --- | --- | --- |
 | 4 | 1 | 1 | はい | 1 |
 | 3 | 4 | 4 | はい | 2 |
 | 2 | 2 | 4 | いいえ | 2 |
 | 1 | 3 | 4 | いいえ | 2 |
 | 0 | 5 | 5 | はい | 3 |

 カウンタ = 3、最終的な答え = 2。これは、ステートメントに示されている 2 段階の安定化プロセスと一致します。 

これらのトレースは、より大きな要素が現在の接尾辞の最大値の左側に現れるたびに、それが一連​​の反転で必要な構造修正に対応していることを示しています。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = 0
        ans = 0
        for i in range(n - 1, -1, -1):
            if a[i] > mx:
                mx = a[i]
                ans += 1
        
        out.append(str(max(0, ans - 1)))
    
    print("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# provided samples
assert run("3\n5\n2 4 1 5 3\n5\n5 3 2 4 1\n4\n1 1 1 1\n") == "1\n2\n0"

# all equal
assert run("1\n4\n7 7 7 7\n") == "0"

# increasing
assert run("1\n5\n1 2 3 4 5\n") == "0"

# decreasing
assert run("1\n5\n5 4 3 2 1\n") == "4"

# single element
assert run("1\n1\n42\n") == "0"

 | すべて等しい配列 | 0 | 即時安定化 |
 | 配列を増加する | 0 | すでに安定した接尾辞構造 |
 | 配列を減少させる | 4 | 最悪の場合の調整回数 |
 | 単一要素 | 0 | 境界条件 |
