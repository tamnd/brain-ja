 ## 解決策
 ## 問題の理解

 各セルが小さな迷路の地形タイプのように動作するグリッドが与えられています。 旅行者は、マークされた 1 つのセルから開始します。`S`マークされた固有の出口セルに到達する必要があります。`E`。 移動は 4 つの基本的な方向に許可されており、各移動には 1 単位の時間がかかります。 

ほとんどのセルは空であるか、ブロックされているか、または特殊です。 空のセルは自由に移動できます。 マークされたセル`P`永久の壁です。 マークされたセル`C`は収集品であり、踏むと入手可能なキャンディコーンの数が 1 つずつ増えます。 マークされたセル`J`ロックされたゲートのように機能します。少なくとも 1 つのキャンディ コーンが現在保持されている場合にのみ入ることができ、ゲートを踏むと 1 つのキャンディ コーンを消費します。 

重要な問題は、通過する能力があることです。`J`セルの数によって異なります`C`セルはパスに沿って収集されており、キャンディーは合計で最大 8 個であるため、状態空間は境界のあるままになります。 

タスクは、から移動するのに必要な最小時間を計算することです。`S`に`E`、または有効なパスが存在しないことを報告します。 

グリッド サイズは最大 100 x 100 なので、最大 10,000 個のセルが存在します。 キャンディーの状態を無視する素朴な最短経路検索は失敗します。`J`セルが間違っています。 同時に、どのソリューションでもキャンディーの収集によって引き起こされる状態の変化を処理する必要があるため、位置だけでは十分ではありません。 

正しい状態には、位置と現在のキャンディー数の両方が含まれている必要があります。 キャンディーの数は最大 8 個であるため、完全な状態空間は最大 100 × 100 × 9 であり、BFS には十分小さいです。 

異なるキャンディー数で同じセルを再度訪問すると、微妙なエッジケースが現れます。 たとえば、ある場所に到着すると、`J`キャンディー 0 個のセルは不可能ですが、キャンディー 1 個で後で到着する場合は有効になる可能性があります。 位置だけをキーとする単純な訪問先配列では、有効なパスが誤って破棄されてしまいます。 

別のエッジケースは、キャンディーが通過する必要があるときに発生します。`J`しかし、最適なパスでは、最初にセルを収集するために迂回する必要があります。 将来の制約を無視した貪欲な最短経路はここで失敗します。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのパスを列挙しようとします。`S`に`E`、各パスに沿ってキャンディーのコレクションを追跡します。 各ステップは最大 4 つの方向に分岐するため、可能なパスの数はパスの長さに応じて指数関数的に増加します。 100 x 100 のグリッドであっても、単純なパスの数だけでも天文学的に膨大になるため、これは完全に不可能になります。 

これが不要な理由は、問題に最適な下部構造があるためです。同じ数のキャンディーで同じセルに到達することは、そこに到達する方法に関係なく同等です。 状態が位置とキャンディーの数によって完全に記述されることが認識されると、問題は重み付けされていないグラフの最短経路になります。 

これは、拡張された状態空間に対する幅優先探索を直接示唆しています。 各ノードはトリプルです`(i, j, k)`どこ`k`現在保有しているキャンディーの数です。 トランジションは隣接するセルへの移動と更新に対応します。`k`細胞の種類によって異なります。 各移動には正確に 1 ユニットのコストがかかるため、BFS は最短パスを保証します。

 | --- | --- | --- | --- |

 | 展開された状態グラフの BFS | O(n · m · 9) | O(n · m · 9) | 承認済み |

 ## アルゴリズムのチュートリアル

 到達可能な各構成をグラフ内の状態として扱い、開始状態から BFS を実行します。 

1. 開始セルを見つけます`S`BFS キューを状態で初期化します`(S_row, S_col, 0, 0)`、最後の値は実行されたステップ数です。 まだキャンディーが収集されていないため、キャンディーの数は 0 から始まります。 
2. によってインデックス付けされた訪問済み構造を作成します。`(row, col, candy_count)`。 これにより、異なる数のキャンディーを持つセルを再訪問するステートが誤って破棄されることがなくなります。 
3. キューが空でない間に、先頭の状態を抽出します`(r, c, k, dist)`。 
4. 現在のセルが出口の場合`E`、すぐに戻ります`dist`、BFS はこれが可能な最短のパスであることを保証するためです。 
5. 4 つの可能な移動方向のそれぞれについて、次のセルを計算します。`(nr, nc)`。 範囲外またはカボチャの場合はスキップしてください`P`。 
6. ターゲット セルに基づいて、移動が有効かどうかを判断します。 

そうであれば`J`、 確保する`k > 0`、次に減分します`k`キャンディーが消費されるので1つずつ。 

そうであれば`C`、増分`k`踏み込んでから1つずつ。 

空いている場合は、`S`、 または`E`、すでに処理されていない限り、キャンディーの数は変わりません。 
7. 結果の状態が`(nr, nc, nk)`訪問されていない場合は、訪問済みとしてマークし、距離を指定してキューに追加します`dist + 1`。 
8. 到達せずにキューが使い果たされた場合`E`、 戻る`"SPOOKED!"`。 

### なぜ効果があるのか

 BFS はすべての状態を深度で処理するため、アルゴリズムは距離の増加順に状態を探索します。`d`深いところでは`d+1`。 各状態は、将来の意思決定に必要なすべての情報 (位置とキャンディーの在庫) を完全にエンコードします。 これにより、キャンディー数が異なる同じセルへの 2 回の訪問はまったく異なる状況となるため、誤った枝刈りが防止されます。 したがって、最初に出口に遭遇したとき、より短い有効なパスは存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    
    sr = sc = er = ec = -1
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                sr, sc = i, j
            elif grid[i][j] == 'E':
                er, ec = i, j
    
    # visited[r][c][k]
    visited = [[[False] * 9 for _ in range(m)] for _ in range(n)]
    
    q = deque()
    q.append((sr, sc, 0, 0))
    visited[sr][sc][0] = True
    
    directions = [(1,0), (-1,0), (0,1), (0,-1)]
    
    while q:
        r, c, k, dist = q.popleft()
        
        if grid[r][c] == 'E':
            print(dist)
            return
        
        for dr, dc in directions:
            nr, nc = r + dr, c + dc
            if not (0 <= nr < n and 0 <= nc < m):
                continue
            if grid[nr][nc] == 'P':
                continue
            
            nk = k
            cell = grid[nr][nc]
            
            if cell == 'C':
                nk += 1
            elif cell == 'J':
                if nk == 0:
                    continue
                nk -= 1
            
            if not visited[nr][nc][nk]:
                visited[nr][nc][nk] = True
                q.append((nr, nc, nk, dist + 1))
    
    print("SPOOKED!")

if __name__ == "__main__":
    solve()
```実装は状態定義を直接反映します。 BFS キューには位置とキャンディー数の両方が保存されます。これは正確性のために不可欠です。 訪問された配列は 3 次元であるため、同じ状態が再び訪れることはありません。 セルの効果を処理する順序が重要です。残されたセルではなく、入力されたセルに基づいて次のキャンディーの数を計算します。 

よくある間違いは、キャンディーの数を考慮せずにセルを訪問済みとしてマークすることです。これは、より多くのキャンディーで同じ位置に到達すると、将来のロックが解除される可能性があるため、正しくありません。`J`細胞。 

もう 1 つの微妙な点は、`E`プッシュ時ではなくキューからポップするとき、これにより返される距離が有効な最短パスに対応することが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、異なるキャンディ数でセルが再訪された場合です。 への最短の幾何学的パスが存在する状況を考えてみましょう。`J`セルでは十分なキャンディーが提供されませんが、少し遠回りすると十分なキャンディーが提供されます。 アルゴリズムは次のように処理してこれを処理します。`(r, c, k1)`そして`(r, c, k2)`別々の状態として認識されるため、どちらのパスも他方のパスを誤って排除することはありません。 

終了時に別のエッジケースが発生します。`E`すべてのキャンディーを使い果たした後にのみ到達できます。 BFS は、パスに沿ってキャンディーを消費し、到達することを正しく許可します。`E`と`k = 0`消費の順序が合法である限り有効です。 

最後の微妙なケースは、キャンディーに遭遇する前に複数のキャンディーが収集されている場合です。`J`。 BFS は、キャンディー数が多い状態が少ない状態と並行して探索されることを保証するため、アルゴリズムは貪欲な収集戦略を強制するのではなく、実現可能性を最大化する構成を自然に見つけます。
