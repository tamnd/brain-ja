 ## 解決策
 ## 問題の理解

 次のもののみからなる文字列が与えられています。`0`、`1`、 そして`2`。 このシーケンスの連続セグメントを、そのセグメント内で次の数が含まれるように選択したいと考えています。`2`文字数は指定された制限を超えません`k`。 このような有効なセグメントすべての中で、可能な限り最大の長さが必要です。 

言い換えれば、文字列上でウィンドウをスライドさせ、数字のカウントが含まれる最長の部分を探します。`2`許容予算内に収まります。 

入力サイズは最大です$10^5$これにより、すべての部分文字列を明示的に試行するソリューションは即座に除外されます。 ブルートフォースアプローチでは次のことが考えられます。$O(n^2)$部分文字列、さらにはその数を数えることもできます。`2`それぞれの内側にあるものは、それを向かって押します$O(n^3)$または$O(n^2)$、1秒の制限には遅すぎます。 したがって、線形または線形に近いメソッド、通常は文字列を 1 パスで処理するメソッドが必要です。 

素朴な推論による主な微妙な失敗例は、最適なセグメントには有効なウィンドウの複数のストレッチが含まれる可能性があり、間違った側から縮小すると最適な答えが失われる可能性があることを忘れていることです。 たとえば、次の場合`k = 1`そして文字列は`220202`、単純なアプローチでは、あまりにも多くの位置を貪欲にスキップし、早期に削除した後に開始されるより長い有効なウィンドウを見逃す可能性があります。`2`s.

 ## アプローチ

 ブルートフォース戦略は簡単です。考えられるすべての部分文字列を列挙し、その数を数えます。`2`s が含まれており、カウントが最大であるものの中で最大長を追跡します。`k`。 開始インデックスごとに、終了ポインターを拡張し、カウンターを維持します。 これはおおよそ次のことにつながります$n$開始位置ごとに、最大でスキャンできます。$n$文字、結果として$O(n^2)$時間。 この時点ではすでに大きすぎます$n = 10^5$、次の順序で必要になるため、$10^{10}$操作。 

問題の構造は、強制する条件が単調であるため、より効率的なアプローチを示唆しています。つまり、セグメントが超過して無効になると、`k`の発生`2`、さらに延長すると事態は悪化するだけです。 これはまさにスライディング ウィンドウが適切に機能する設定です。 すべての部分文字列のカウントを再計算する代わりに、単一のウィンドウを維持します。`[l, r]`そしてその数を追跡します`2`がその中にあります。 拡大します`r`ウィンドウが制約に違反するたびに、段階的に移動します。`l`再度有効になるまで転送します。 

これにより、問題は、各文字がウィンドウに入ったりウィンドウから出たりするのは 1 回だけという単一の線形スキャンに変わります。

 ## アルゴリズムのチュートリアル

 窓口を整備しております`[l, r]`ストリングとカウンターを越えて`cnt2`何個保存するか`2`は現在ウィンドウ内にあります。 

1.初期化`l = 0`、`cnt2 = 0`、 そして`best = 0`。 空のウィンドウから始めて、徐々に有効なセグメントを構築します。 
2. 反復する`r`から`0`に`n - 1`。 含めるたびに、`s[r]`現在のウィンドウに。 
3. もし`s[r] == '2'`、増分`cnt2`。 これは、限られた予算の一部を消費しているかどうかを追跡します。 
4. もし`cnt2 > k`、ウィンドウは無効です。 再び有効になるまで、左側から縮小する必要があります。 私たちは移動することでこれを行います`l`前進と減算`cnt2`を削除するたびに、`2`。 
5. 有効性を復元した後、現在のウィンドウが`[l, r]`制約を満たしているので更新します`best = max(best, r - l + 1)`。 
6. まで続けます`r`文字列の終わりに達します。 答えは`best`。 

重要なアイデアは、`l`前進のみで後退はしないため、直線的な動作が保証されます。 

### なぜ効果があるのか

 あらゆるポジションで`r`、アルゴリズムはウィンドウが`[l, r]`多くても含まれる`k`の発生`2`、そしてそれ`l`これが現在のものに対して当てはまる最小のインデックスです。`r`。 で終わる大きなウィンドウは`r`の数を増やすか維持するだけです`2`s、無効な拡張子は移動して修正する必要があります。`l`右。 これにより、次で終わる有効な候補ウィンドウが存在しないことが保証されます。`r`より小さい有効なプレフィックスはすべて暗黙的にみなされるため、無視されます。`l`進歩します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    l = 0
    cnt2 = 0
    best = 0

    for r in range(n):
        if s[r] == '2':
            cnt2 += 1

        while cnt2 > k:
            if s[l] == '2':
                cnt2 -= 1
            l += 1

        best = max(best, r - l + 1)

    print(best)

if __name__ == "__main__":
    solve()
```この実装は、スライディング ウィンドウ ロジックを直接反映しています。 重要な唯一の詳細は、回答を更新する前に縮小ループが有効性を完全に復元する必要があるということです。そうしないと、無効なセグメントがカウントされる可能性があります。 ポインタ`l`は決してリセットされないため、線形の複雑さが維持されます。

## 特殊なケース

 主なエッジケースは次のような場合です`k = 0`、いいえの意味`2`全然許される。 のような入力の場合`10202`、アルゴリズムは常に縮小し続けます。`2`に遭遇します。 で`r = 2`、最初にヒットしました`2`、強制的に`l`に移動する`2`、ウィンドウがリセットされます。 これは、アルゴリズムが無効な状態を蓄積しないことを示しています。`cnt2`すぐに修正されます。 

もう 1 つのケースは、文字列に以下が含まれる場合です。`k`の発生`2`合計で、例えば`s = 1112011`と`k = 2`。 この状況では、`cnt2`決して超えない`k`、 それで`l`決して動かない。 アルゴリズムは効果的に次の値を返します。`n`文字列全体が有効であるためです。
