 ## 解決策
 ## 問題の理解

 部屋がノード、ドアがエッジである無向グラフとしてモデル化された建物が与えられます。 ハリーは特定の部屋から開始し、いくつかある出口の部屋のいずれかに到達したいと考えています。 同時に、固定の部屋に複数の幽霊が配置されます。 

ハリーとすべてのゴーストは同じ速度で、1 秒あたり 1 つのエッジで動き、全員が同時に動き始めます。 ハリーが出口で安全であるとみなされるのは、ハリーの出発点から出口までの道が存在し、幽霊と同じタイムステップで部屋を共有することなくその道を通過できる場合のみです。 

重要な点は、幽霊も移動するため、最初から幽霊がいる部屋は単純に「悪い」というわけではないということです。 幽霊がハリーと同じ時間、またはハリーより早く部屋に到着する可能性がある場合、その部屋はハリーにとって安全ではなくなります。 

グラフのサイズは最大 200,000 のノードとエッジであるため、ソリューションは線形または線形に近いものでなければなりません。 すべての出口から BFS を実行したり、ゴーストごとにすべてのパスをシミュレートしたりすると、遅すぎます。 唯一の実現可能なアプローチは、グラフ内の最短距離を計算し、それをグローバルに推論することです。 

よくある失敗例は、タイミングを無視したことに起因します。 

例:

 入力:```
3 2 1 1 1
1 2
2 3
3
2
```ここで、ハリーは 1 から開始し、ゴーストは 2 から開始し、出口は 3 です。ハリーは 2 ステップで 3 に到達します。 ゴーストは1ステップで3に到達します。 たとえ出口に到達できるとしても、ハリーは安全に出口を使用することができません。 

ハリーからの到達可能性のみをチェックする単純なアプローチでは、この出口が誤って有効であるとカウントされてしまいます。 

もう 1 つの失敗例は、ゴーストが開始部屋のみをブロックし、ゴーストがハリーの進路に入るたびにブロックされると想定していることです。 

## アプローチ

 この強引なアイデアは、ハリーとすべての幽霊の両方を同時にシミュレートすることです。 (ノード、時間、占有者) などの状態を追跡するマルチソース BFS を試みたり、ハリーからの可能なパスをすべて探索してゴースト パスと交差するものを拒否したりすることもできます。 すべてのパスを複数の移動エージェントに対してチェックする必要があり、インタラクションの数が n と m の両方で増加するため、これは実際にはすぐに指数関数的になります。 

核となる単純化は、動きが均一であることを観察することから生まれます。 ハリーもゴーストも 1 秒ごとに 1 つのエッジを移動するため、重要なのは、それぞれがどの部屋にどれだけ早く到着できるかだけです。 幽霊が時間 t に部屋に到着した場合、安全に部屋を通過するには、ハリーは厳密に t より早く到着する必要があります。 そうでなければ、ハリーと幽霊はある時点で一致することになります。 

これにより、問題は重み付けされていないグラフ上の 2 つの最短経路計算に変換されます。 BFS を使用して、ハリーの開始部屋からの最短距離を計算します。 また、ゴーストからの最短距離も計算します。これは、すべてのゴーストの位置を単一の BFS 内の同時ソースとして扱うことで実行できます。 

両方の距離配列が判明すると、その部屋までの距離がゴースト距離よりも厳密に短い場合、その部屋はハリーにとって安全です。 最後に、この条件を満たす出口の部屋の数を数えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | 高 | 遅すぎる |
 | 2 つの BFS の距離の比較 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. グラフを作成する

 都市を隣接リストとして保存します。 各部屋は、接続された部屋のリストを保持します。 

この構造が必要なのは、両方の BFS トラバーサルで近隣ノードを効率的に探索する必要があるためです。 

### 2. ハリーのスタートルームからの BFS

 s から始まる標準 BFS を実行し、ハリーが各部屋 v に到達するのに必要な最小時間 distH[v] を計算します。 

すべてのエッジの重みは 1 に等しいため、BFS は最短パスを保証します。 

### 3. すべてのゴースト位置からのマルチソース BFS

 距離 0 にあるすべてのゴースト ルームでキューを初期化し、ゴーストが各部屋 v に到達できる最も早い時間である distG[v] を計算します。 

ゴーストは同時に移動するため、このステップは非常に重要です。 それらを複数の BFS ソースとして扱うと、すべてのゴーストの中で可能な限り最も早い到着が正しくモデル化されます。 

### 4. 出口の到着時間を比較する

 各出口部屋 e について、distH[e] < distG[e] かどうかを確認します。 それが本当なら、ハリーは幽霊よりも先に出口にたどり着くことができる。 

この条件を満たす出口の数を数えます。 

### 5. カウントを出力する

 最終的な答えは安全な出口の数です。 

### なぜ効果があるのか

 BFS 距離は、均一なエッジ コストの下での正確な最も早い到着時間を表します。 ハリーとゴーストは両方とも最適かつ同時に移動するため、遭遇はこれらの最も早い到着時間によってのみ決定されます。 ゴーストが時刻 t にノードに到着する可能性がある場合、ハリーが時刻 t 以降に到着するパスは、時刻 t 以前にそのノードで衝突を引き起こします。 したがって、最短到着時間を比較すると、考えられるすべてのインタラクションが完全に把握され、代替パス構造はこの制約を回避できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start_nodes, n, adj):
    INF = 10**18
    dist = [INF] * (n + 1)
    q = deque()

    if isinstance(start_nodes, list):
        for s in start_nodes:
            dist[s] = 0
            q.append(s)
    else:
        dist[start_nodes] = 0
        q.append(start_nodes)

    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == INF:
                dist[v] = dist[u] + 1
                q.append(v)

    return dist

def solve():
    n, m, s, k, g = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    exits = list(map(int, input().split()))
    ghosts = list(map(int, input().split()))

    distH = bfs(s, n, adj)
    distG = bfs(ghosts, n, adj)

    ans = 0
    for e in exits:
        if distH[e] < distG[e]:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、2 つの距離の計算がきれいに分離されます。 BFS ヘルパーは、単一の整数または開始ノードのリストを受け入れることにより、単一ソースと複数ソースの両方のケースをサポートします。 ゴースト BFS はマルチソースであり、正確性を保つために不可欠です。 

微妙な点は、距離を大きな INF 値で初期化し、ノードごとに 1 回だけ更新することです。 これにより、各ノードが最小距離で 1 回だけ処理されることが保証され、BFS の正確性が維持されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 隣接リスト上の 2 つの BFS トラバーサル |
 | スペース | O(n + m) | グラフストレージと距離配列 |

 ## 特殊なケース

 主なエッジケースは、幽霊がハリーの隣の部屋から出発し、ハリーの進路が短いにもかかわらず、より早く出口に到達する場合です。 アルゴリズムはこれを処理します。これは、ゴーストからの BFS がその最も早い到着時間を外側に正しく伝播し、ハリーが厳密に速くない限り、近くの地域が即座に危険になるためです。 

もう 1 つのケースは、複数のゴーストが存在し、そのうちの最小の到着のみが問題となる場合です。 すべてのゴーストが時刻 0 でキューに入り、各ノードへの最初の到着がすべてのソースにわたって自動的に最小になるため、マルチソース BFS はこれを自然にエンコードします。 

最後のケースは、幽霊が出口に到達できない場合です。 ゴーストの距離は無限のままであり、distH[e] < distG[e] の比較は、パスの長さに関係なくそのような出口を正しく受け入れ、ゴーストが決して干渉できないという事実と一致します。
