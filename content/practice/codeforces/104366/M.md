 ## 問題の理解

 多くの独立したクエリが与えられます。 各クエリは数値を提供します$n$、その値については、最初に次からのすべての整数を想像します。$2$まで$n$。 各整数について$i$、値を定義します$f(i)$、 どこ$f(i)$合計が正確に等しい素数の最小数です$i$。 これらの最適なカウントを計算した後、$i$、累積合計を返すように求められます$f(2) + f(3) + \dots + f(n)$クエリごとに。 

ここでの重要なオブジェクトは、$f(i)$。 数値を乗算的に因数分解する代わりに、数値を加法的に素数に分解し、使用される素数の数を最小限に抑えたいと考えています。 これにより、問題は、すべての素数がコインであり、最小数のコインが合計を形成する必要がある、古典的な「無制限のコインでコインを交換する」状況に変わります。 

制約は非常に大きく、最大 100 万のクエリと値$n$1000万まで。 これにより、再計算するアプローチは即座に除外されます。$f(i)$クエリごとに個別に実行するか、クエリごとに動的プログラミングを使用します。 クエリごとのリニア スキャンですら、総作業量が約$10^{13}$最悪の場合の運用。 実行可能なソリューションでは、すべてを閉じた形式の式か、全範囲にわたる単一の事前計算に 1 回だけ削減する必要があります。 

誤った推論を引き起こす可能性がある微妙な点は、より大きな数には多くの素数が必要であると想定していることです。 たとえば、次のように計算してみます。$f(6) = 3 + 3 = 2$、$f(7) = 2 + 2 + 3 = 3$、

 次に、素数に対する一般的な DP を試みます。 これは不要であり、タイムアウトになります。 もう一つの落とし穴はそれを忘れることです$2$は素数であり、繰り返し使用できるため、最適な分解の構造が強く制限されます。 

## アプローチ

 ブルートフォース解釈では、これを最短経路またはナップザック問題として扱います。 各整数について$i$、すべての素数を試します$p \le i$そして計算する$f(i) = \min(f(i - p) + 1)$。 これは、分解において可能な最後の素数をすべて探索し、ボトムアップでソリューションを構築するため、正しいです。 

ただし、コストは、次の値までのすべての値の素数を反復することによって支配されます。$n$。 ふるいで素数を事前計算したとしても、DP 遷移には依然として大まかに次のものが必要です。$O(n \cdot \pi(n))$操作。 と$n = 10^7$、これは実現可能な限界をはるかに超えています。 

重要な観察は、素数集合に以下が含まれるため、最適分解の構造がほぼ完全に崩壊しているということです。$2$。 任意の整数は次のいずれかを使用して表現できます。$2$s、ただし、単一のパリティ制約を除く。$3$余分な合計よりも効率的に奇数の合計を修正するのに役立ちます$2$s. これは驚くべき単純化につながります。必要な素数の最適な数は、数値の詳細な素数構造には依存せず、パリティのみに依存します。 

偶数の場合$n$、のみを使用して$2$が与えます$n/2$すべての素数は少なくとも$2$、したがって、各項は最大でも寄与します$2$合計効率の観点からコインあたり。 奇数の場合$n \ge 3$、私たちは1つを使用します$3$そして残りは$2$s、与える$(n-3)/2 + 1 = (n-1)/2$素数。 どちらの場合も次のようにきれいに統合されます$f(n) = \lfloor n/2 \rfloor$。 

この削減が見られると、元のタスクは純粋に算術的になります。必要なのは、次の接頭辞の合計だけです。$\lfloor i/2 \rfloor$。

 ## アルゴリズムのチュートリアル

 クローズドフォームを使用しております$f(i) = \lfloor i/2 \rfloor$、次にクエリをプレフィックス合計の問題に変換します。 

1. 何も事前計算しないか、オプションで最大まで答えを事前計算します。$n$プレフィックス配列を使用する場合は、クエリに表示されます。 重要なアイデアは、素数情報や動的計画法はもはや必要ないということです。 
2. 各クエリ値について$n$、 定義する$m = \lfloor n/2 \rfloor$。 この値は、範囲内に収まる整数の完全なペアがいくつあるかを表し、合計全体の制御パラメーターになります。 
3. 導出された閉じた形式を使用して答えを計算します。 もし$n = 2m$、合計$\sum_{i=2}^{n} \lfloor i/2 \rfloor$等しい$m^2$。 もし$n = 2m+1$、合計は次と等しい$m(m+1)$。 これは、連続する整数をペアにしてそれらの寄与を合計することから直接得られます。 
4. 計算された値をクエリごとにすぐに出力します。 

なぜそれが機能するのかは、その方法に根ざしています$\lfloor i/2 \rfloor$ペアで行動します。 すべてのペア$(2k-1, 2k)$貢献する$(k-1) + k = 2k-1$、きれいな算術構造を形成します。 これらの寄与を合計すると、パリティに応じて完全二乗または三角数のような式が得られます。 以来$f(i)$はまさにこのフロア式なので、他の素数分解で結果を変更することはできません。 

不変条件は、すべての整数が素数の最小数として切り捨てられた値のちょうど半分に寄与し、この寄与は異なる整数間の相互作用とは無関係であるということです。 これにより、状態間の結合がすべて取り除かれ、問題が直接合計の恒等式に変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        m = n // 2
        if n % 2 == 0:
            print(m * m)
        else:
            print(m * (m + 1))

if __name__ == "__main__":
    solve()
```この実装は派生した閉じた形式に完全に依存しているため、前処理や配列の割り当てはありません。 唯一の微妙な点は、整数の除算とパリティを正しく処理することです。 使用する$m = n // 2$プライム ロジックや DP 状態で分岐することなく、偶数と奇数の両方のケースが均一に処理されるようにします。 

偶数の場合が返されます$m^2$、これは対称的にペアを合計することに対応します。 奇妙なケースが戻ってくる$m(m+1)$、これは追加の不対項の寄与を説明します。$m$。
