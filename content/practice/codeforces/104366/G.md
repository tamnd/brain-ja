 ## 解決策
 ## 問題の理解

 長い 10 進数文字列が与えられ、左から右に配置された一連の数字として解釈されます。 隣接するすべての数字のペアの間に、プラス記号を挿入するかどうかを個別に決定します。 各ポジション$i$ランダムなイベントに寄与する: 確率的に$p_i/100$、数字の間にプラスが挿入されます$i$と数字$i+1$、そうでない場合、数字は接着されたままになります。 

すべての決定が完了すると、数字列はいくつかの連続したブロックに分割されます。 各ブロックは単一の整数 (基数 10) として解釈され、これらすべての整数を合計します。 タスクは、すべてのランダムな選択に対するこの最終合計の期待値をモジュロで計算することです。$998244353$。 

重要な問題は、ブロックの値が一連の「プラスなし」の決定に依存するため、単純な評価ではすべてを列挙する必要があることです。$2^{n-1}$構成は不可能です$n$まで$2 \cdot 10^6$。 これにより、指数関数または二次関数のシミュレーションさえも即座に除外されます。 

この制約は、あらゆる解が線形または線形に近いものでなければならないことも示唆しています。$O(n \log n)$は厳しいですが許容できる可能性がありますが、桁のスパンを繰り返し再利用するものは遅すぎます。 

微妙なエッジ ケースとして、入力数値の先頭のゼロが許可されますが、連続する部分文字列のみが整数として解釈されるため、算術の正確さには影響しません。 もう 1 つの特殊なケースは、すべての確率が 0 または 100 の場合です。この場合、問題は決定論的なセグメント化または 1 つの完全な数値に分解されますが、解は特別なケースなしで一貫して動作する必要があります。 

## アプローチ

 ブルートフォース戦略は、$n-1$可能なカット位置。 サブセットごとに、結果のブロックを再構築し、その数値を計算し、その正確なカット パターンの確率で重み付けされた累計に加算します。 各構成に必要なものは、$O(n)$数値に解析する時間がかかるため、合計作業量は次のようになります。$O(n 2^{n})$、でもそれは不可能です$n = 30$。 

完全なセグメンテーションの観点から考えるのをやめ、代わりに各桁の位置の寄与を独立して考慮すると、問題の構造が変わります。 重要な観察は、すべての桁が非常に制御された方法で最終合計に寄与しているということです。その寄与は、プラス記号に到達する前に左にどれだけ「拡張」できるかによってのみ決まります。 

位置に数字を固定すると$i$、任意の形式の数値の値は、次で終わる連続したサフィックスの長さに依存します。$i$。 左に移動するたびに、同じブロックを続けるか、確率でブロックを壊します。$p_{i-1}/100$。 これにより、幾何学的生存構造が作成されます: 位置の数字$i$乗算確率で左に拡張するブロックに寄与します。 

セグメントを列挙する代わりに、桁ごとに期待される寄与度を計算します。 現在のプレフィックスの予想される寄与をローリング値として維持しながら、数字を左から右に処理します。 新しい各桁は、小数点以下 1 桁シフト (10 倍) することですべての既存のコントリビューションに追加され、その前に分割が発生するかどうかに応じて新しいコントリビューションが開始されます。 分割確率によって、以前の構造がどの程度「リセット」されるかが決まります。 

これにより、問題はプレフィックス寄与に対する線形再帰に変わり、各位置がモジュラー算術と事前計算された確率を使用して期待値を更新します。

 ## アルゴリズムのチュートリアル

 確率を次のように書き換えます$q_i = 1 - p_i/100$の間にプラスが挿入されない確率を表します。$i$そして$i+1$。 すべての計算はモジュロで実行されます$998244353$, そのため、逆モジュラーを使用して割り算を変換します。 

ローリングバリューを維持します$dp$、これまでに処理されたプレフィックスとヘルパー変数によって形成された式の期待値を表します。$pref$これは、まだ拡張できる現在の接尾辞構造の寄与を捉えています。 

1. 文字列を左から右にスキャンしながら、各数字の文字を整数値に変換します。 これにより、大きな部分文字列を保存したり、数値を再計算したりすることがなくなります。 
2.初期化$dp = 0$そして$pref = 0$。 開始時には、何の数字も貢献していないため、両方の数量はゼロです。 
3. ポジションごとに$i$、数字を組み込む$d_i$まず既存の貢献を拡張することによって。 以前に形成された数値はすべて小数点以下 1 桁左にシフトするため、既存の寄与に 10 を掛けます。これは、数字を追加することですべてのアクティブなセグメントの桁の値がどのように変更されるかを反映しています。 
4. 位置で新しいセグメントを開始する寄与を追加します。$i$。 これは直前にプラスが挿入された場合に発生します$i$、確率で発生します$p_{i-1}/100$。 その場合は数字$i$新しい数値を開始し、次のように直接貢献します。$d_i$。 この新しいスタートを分割確率で重み付けします。 
5. を使用して継続効果と再開効果を組み合わせる$q_{i-1}$。 前のセグメントを拡張することで期待される寄与は、次のようにスケールされます。$q_{i-1}$、再開部分は次のように拡大縮小されます。$p_{i-1}/100$。 これにより、次のようなフォームの線形更新が生成されます。$$pref = pref \cdot (10 \cdot q_{i-1}) + d_i$$その後$dp$寄付金を適切に積み立てます。 
6. 蓄積する$dp$すべてのプレフィックスがグローバルな期待合計に寄与するため、各ステップでの現在のプレフィックス寄与度を計算します。 

微妙な点は、セグメントの境界を明示的に追跡することは決してないということです。 代わりに、確率で重み付けされた期待値の線形性により、すべてのセグメンテーション状態を 1 つの進化する状態にマージすることができます。 

### なぜ効果があるのか

 各桁の寄与は、その左側で連続して「ノーカット」イベントが何回発生したかによってのみ決まります。 これらのイベントは独立したベルヌーイ連鎖を形成するため、予想される寄与は生存確率が乗算される位置の合計として表すことができます。 このアルゴリズムは、ローリング係数システムでこの生存プロセスをエンコードし、考えられるすべてのセグメンテーションが正しい確率の重みで暗黙的に 1 回だけ考慮されるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n = int(input())
    s = input().strip()
    p = list(map(int, input().split()))

    # precompute probabilities
    q = [(100 - x) * modinv(100) % MOD for x in p]

    dp = 0
    pref = 0

    for i in range(n):
        d = ord(s[i]) - 48

        if i == 0:
            pref = d
            dp = d
        else:
            pref = (pref * 10 % MOD * q[i - 1] + d) % MOD
            dp = (dp + pref) % MOD

    print(dp % MOD)

if __name__ == "__main__":
    solve()
```コードは単一パスで数字を処理します。 配列$q$プラスが挿入されない確率を格納し、100 の逆数を使用してモジュラー形式に変換します。変数$pref$構築中の現在アクティブなサフィックス番号の期待値を追跡します。 新しい数字は既存のすべての数字を小数点以下 1 桁左にシフトしてからスケールするため、各ステップで 10 が乗算されます。$q[i-1]$セグメントが継続する確率を反映します。 追加$d$新しいポジションで貢献を開始するためのアカウントです。 

変数$dp$すべてのプレフィックスの寄与を累積します。これは、すべてのセグメントの期待値を暗黙的に合計することに相当します。 

実装でよくある落とし穴は、確率を剰余分数に変換する必要があることを忘れていることです。 もう 1 つは、確率スケーリングを適用する前に 10 の乗算を適用することです。これにより、桁位置が誤って重み付けされます。 

## 実用的な例

 次の入力を考えてみましょう。```

s = "123"
p = [100, 0]
```ここでは常に最初のカットが発生するため、常に 1 と 2 の間で分割されますが、2 と 3 の間に分割されることはありません。

 | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | - | 0 | 1 | 1 |
 | 1 | 2 | 0 | 1 | 2 | 3 |
 | 2 | 3 | 1 | 2 | 23 | 26 |

 最終的に予想される合計は 26 で、セグメント「1」+「23」に対応します。 

ここで次のことを考えてみましょう。```

```カットは決して起こらないため、すべてが 1 つの数字を形成します。 

| 私 | 数字 | q[i-1] | 前の都道府県 | 後の優先順位 | DP |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての確率が 0 である場合、つまり数値が分割されない場合です。 アルゴリズムはこれを処理します。$q_i = 1$したがって、反復は確率的なスケーリングを行わない純粋な桁シフトに帰着します。 入力用`s = "1203"`そして`p = [0,0,0]`、計算が構築されます`1 → 12 → 120 → 1203`、最終的な答えは完全な整数値と一致します。 

もう 1 つのエッジ ケースは、すべての確率が 100 の場合です。これは、すべての隣接するペアが常に分割されることを意味します。 のために`s = "456"`と`p = [100,100]`、 全て$q_i = 0$、したがって、漸化式は各桁で再開するように崩壊します。 アルゴリズムが生成するのは、`4 + 5 + 6 = 15`、予想される完全にセグメント化された合計と一致します。 

3 番目のエッジ ケースは、単一の長いゼロ文字列です。 のために`s = "0000"`確率に関係なく、すべてのプレフィックスの寄与はゼロのままであるため、実行状態は決して変化しません。 アルゴリズムは両方を正しく維持します`pref`そして`dp`全体を通してゼロに設定し、隠れた除算やオーバーフローの問題を回避します。
