 ## 問題の理解

 このタスクは基本的に、テキスト トークンのストリームを処理し、それらから非常に具体的な文字統計を抽出することです。 構造解析や変換を実行する代わりに、すべての入力文字列を読み取り、ハイフン文字の出現のみに焦点を当てます。`-`。 このキャラクターがトークンに出現するたびに、最終的な答えに 1 ユニット貢献します。 

入力は、場合によっては複数行にまたがる空白で区切られた一連の文字列と考えることができ、出力は、それらを組み合わせたすべてに表示されるハイフンの数を表す 1 つの整数です。 文字検査以外には、文字列のグループ化、順序付け、解釈は重要ではありません。 

公式の説明は最小限ですが、暗黙の制約は Codeforces の文字列処理タスクの標準です。 入力サイズは合計で数十万文字または数百万文字に簡単に達する可能性があります。 これにより、繰り返しの再スキャンや非効率な連結戦略が即座に排除されます。 ソリューションは入力を単一パスで処理し、各文字を 1 回だけ検査する必要があります。 

微妙なエッジケースは、入力がどのように終了され、構造化されるかによって発生します。 通常、読み取りはトークンベースの入力または EOF までの完全なストリーム読み取りを介して行われるため、固定数の文字列または行を想定する実装は、入力の長さが変化すると通知なく失敗する可能性があります。 もう 1 つのエッジ ケースは、ハイフンがまったく存在しない場合です。この場合、正しい出力は単にゼロであり、実装では、一致する文字が見つからない場合でも出力を生成するようにする必要があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべての文字列をメモリに読み取り、文字列ごとにすべての文字を反復処理し、文字列に遭遇するたびにカウンターをインクリメントします。`-`。 これはタスクの定義を直接反映しているため、これは正しいです。 このアプローチのコストは、すべての文字列の合計文字数に比例します。 その全長を N とすると、実行時間は O(N) となり、漸近複雑さの観点からはすでに最適になっています。 

すべての文字を少なくとも 1 回検査してハイフンかどうかを判断する必要があるため、これ以上の意味のあるアルゴリズムの最適化はありません。 文字のスキャンやバッチ処理をスキップしようとしても、暗黙的に各文字に影響するため、理論的な下限は線形のままです。 

唯一の実際的な改良点は、入力の読み取り方法です。 Python の標準入力メソッドを効率的に使用すると、繰り返しの関数呼び出しや文字列の連結によるオーバーヘッドが発生しなくなります。 したがって、最適なソリューションとは、複雑さを軽減することではなく、可能な限り最も直接的かつ効率的な方法でリニア スキャンを実装することです。

 ## アルゴリズムのチュートリアル

 1. 標準入力からの入力を、空白で区切られたトークンの連続ストリームとして読み取ります。 これにより、書式設定を前提にすることなく、改行とスペースの混在を正しく処理できるようになります。 
2. カウンタをゼロに初期化します。 このカウンターは、すべてのトークンで発生したハイフンの合計数を累積します。 
3. 入力から取得した各トークンを反復処理します。 各トークンは独立して処理されますが、同様に処理されます。 
4. 各トークンについて、すべての文字を反復処理し、それが等しいかどうかを確認します。`-`。 存在する場合は、カウンターを 1 つインクリメントします。 この直接的な文字チェックにより、不必要な前処理や変換が回避されます。 
5. すべてのトークンが処理された後、カウンターの最終値を出力します。 

重要な考え方は、問題は完全にストリーミング入力での文字カウントに帰着するため、正確性は文字がスキップされず、文字が二重にカウントされないことを保証することだけに依存するということです。 

### なぜ効果があるのか

 このアルゴリズムは単純な不変条件を維持します。つまり、k 個のトークンを処理した後、カウンターはそれらの k トークンに現れるハイフンの数に等しくなります。 各トークンは 1 回完全にスキャンされ、すべての文字が 1 回だけ評価されます。 入力は素のトークンに分割され、すべてのトークンがカバーされるため、最終的なカウンターは必然的に入力全体のハイフンの合計数と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

data = sys.stdin.read().split()

ans = 0
for token in data:
    for ch in token:
        if ch == '-':
            ans += 1

print(ans)
```このソリューションは、次を使用して入力全体を一度に読み取ります。`sys.stdin.read()`これにより、行ごとの読み取りによるオーバーヘッドが回避されます。 トークンに分割すると、空白で区切られたすべての文字列が均一に処理されます。 

ネストされたループ構造は意図的かつ最小限のものです。 外側のループはトークンを反復し、内側のループは各文字を検査します。 条件`ch == '-'`必要なロジックはこれだけであり、カウンタは補助記憶装置なしで結果を蓄積します。 

ここでよくある実装上の間違いは、繰り返し使用することです。`input()`ループ内で呼び出しを行うと、速度が遅くなり、EOF 条件が失われる危険性があります。 もう 1 つの微妙な問題は、文字列メソッドを誤って使用して最適化しようとすると、トークン内のすべての文字の処理を忘れることです。 提示されたソリューションは、直接反復に固執することで両方の落とし穴を回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    ans = 0
    for token in data:
        for ch in token:
            if ch == '-':
                ans += 1
    return str(ans)

# constructed cases

# case 1: mixed hyphens
assert run("a-b c--d e-f") == "4", "mixed hyphens"

# case 2: no hyphens
assert run("abc def ghi") == "0", "no hyphens"

# case 3: all hyphens
assert run("--- --") == "5", "all hyphens"

# case 4: single character
assert run("-") == "1", "single hyphen"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | a-b c--d e-f | 4 | トークン間の混合配布 |
 | ABCデフギ | 0 | 対象キャラクターが存在しない |
 | --- -- | 5 | 密な連続ハイフン |
 | - | 1 | 最小入力の場合 |

 ## 特殊なケース

 主なエッジケースは、入力にトークンがまったく含まれていない場合です。 そのような状況では、`sys.stdin.read().split()`空のリストを返し、ループは実行されません。 カウンタは初期値の 0 のままですが、文字がなく、したがってハイフンもないため、これは正しいことです。 

もう 1 つのケースは、空白のない非常に大きな連続文字列です。 アルゴリズムは各文字を独立して処理するため、正しく動作します。 たとえば、次のように入力します`a---b---c`は単一のトークンとして扱われ、スキャンではすべてのハイフンが直接カウントされ、正しい合計が生成されます。 

最後のエッジ ケースは、トークン間の複数のスペースや改行など、不規則な空白です。 分割するとすべての空白が均一に折りたたまれるため、トークンのグループ化はカウントの正確さとは無関係です。
