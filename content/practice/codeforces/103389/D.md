 ## 解決策
 ## 問題の理解

 一連の整数が与えられます。各位置はライン内のノードとして解釈でき、各位置の値はそのノードに関連付けられた重みまたは高さを表します。 タスクは、これらの値から導出される特定の構築ルールの下で、このラインを最適に「接続」するコストに対応する値を計算することです。 

このステートメントに組み込まれている重要な考え方は、接続が極大値を越えるか、極大値で区切られた領域内に留まるかによって、接続の動作が異なるということです。 シーケンス全体で最大の値を持つ位置を選択すると、その位置は自然な区切り文字として機能します。その位置を横切る接続にはその最大値によって決定されるコストがかかりますが、一方の側に完全にある接続はその側内の値によってのみ制御されます。 

最終出力は、これらの制約の下で必要なすべての接続を構築するために可能な最小コストを集計した単一の整数です。 

複雑さの観点から見ると、入力サイズは暗黙的に少なくとも線形または線形に近い処理を必要とするのに十分な大きさです。 ペア間のすべての接続を明示的にシミュレートしたり、完全な接続状態を維持しようとする 2 次アプローチは、シーケンスの長さが 200,000 以上などの一般的な競技プログラミングの制限に達すると、遅すぎます。 これは、解決策が問題を隣接する要素間の局所的な関係または単一パスの計算に帰着させる必要があることを直ちに示唆しています。 

単純な推論による一般的な失敗例は、最大値ごとの分割を明示的にシミュレートし、各セグメント内の接続を再計算しようとすることです。 たとえば、次のような配列を考えてみましょう。`[1, 100, 2, 3]`。 単純な戦略では、左右のパーティションを再計算する可能性があります。`100`サブセグメントを再帰的に処理しますが、これにより二重にカウントされたり、境界を越えた寄与が欠落したりする危険があります。 正しい動作は、再帰的分解ではなく、ローカル比較のみに依存します。 

もう 1 つの微妙な問題は、等しい値の誤った処理です。 例えば`[5, 5, 5]`「厳密に大きい」条件に対して人為的な追加の分割や特別な処理を作成すべきではありません。 間違った場所での厳密な不等式に依存する解決策は、等しい近傍を誤って分類し、不正確なエッジ寄与を生成します。 

## アプローチ

 強引な解釈では、構造によって引き起こされるあらゆる潜在的な接続について明示的に推論します。 大域的な最大値を選択し、配列を左右の部分に分割し、各辺を再帰的に解き、最大値を介して両方の辺を接続することを想像する人もいるかもしれません。 この考え方は概念的には正しいですが、再帰のあらゆるレベルで同じ構造の再計算が繰り返されることになります。 配列が厳密に増加または減少するなどの最悪の場合、これは縮小セグメントの繰り返しスキャンに変質し、二次的な動作につながります。 

重要な観察は、グローバル構造が不要であるということです。 完全なセグメントについて推論する代わりに、隣接する要素間で局所的に何が起こっているかを調べることができます。 隣接する各ペアは最終的な答えに 1 回だけ寄与し、その寄与は 2 つの値の大きい方によって決まります。 これは、ローカル領域の支配的な値が接続コストを決定する区切りとして機能するという事実から直接得られます。 

これが認識されると、問題全体は隣接するペアの単純な合計を計算することに集約されます。

 ## アルゴリズムのチュートリアル

 1. シーケンスを表す値の配列を読み取ります。 これは、グローバルではなくローカルに分析する構造です。 
2. アキュムレータを初期化する`ans = 0`寄付金の最終合計を保存します。 
3. すべての隣接するペアを反復処理します。`(a[i], a[i+1])`左から右へ。 各ペアは境界を表しており、隣接する 2 つの位置間の優位性によって、その境界を横切る最小限必要な接続コストが決まります。 
4. ペアごとに、次の値を追加します。`max(a[i], a[i+1])`に`ans`。 その理由は、より大きなエンドポイントが、最適な構築においてこのローカル境界を効果的に「横断」または「橋渡し」する接続を支配するためです。 
5. すべての隣接するペアを処理した後、出力します。`ans`最終結果として。 

### なぜ効果があるのか

 重要な不変条件は、概念構造内のすべてのエッジが元のシーケンス内の 1 つの隣接境界に正確に対応し、そのコストがその境界の大きい端点によってのみ決定されることです。 ステートメント内のグローバル最大値引数により、ピークを越える構造は少なくともそのピークの値を支払わなければならないことが保証され、この効果は近隣間の独立した寄与にきれいに分解されます。 各隣接関係は 1 回だけ考慮され、最終的な定式化では隣接関係を越えて相互作用が及ぶことはないため、極大値を超える合計により、重複や省略なしに全体的な最適コストが完全に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
a = list(map(int, input().split()))

ans = 0
for i in range(n - 1):
    ans += max(a[i], a[i + 1])

print(ans)
```このソリューションは、まず線形時間で配列を読み取り、次に隣接するペアに対してシングル パスを実行します。 アキュムレータ`ans`定数時間を使用して各境界から寄与を収集します`max`手術。 

微妙な点は、グローバル最大値やセグメント化に対して特別な処理が必要ないことです。 このステートメントが最大限のピボットを介してアイデアを動機付けているとしても、その構造は証明装置にすぎません。 最終的な式は、すべての位置の寄与をローカルに完全にエンコードしています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    a = list(map(int, input().split()))

    ans = 0
    for i in range(n - 1):
        ans += max(a[i], a[i + 1])

    return str(ans)

# provided sample-like cases
assert run("4\n1 3 2 4\n") == "10"
assert run("5\n5 5 1 7 2\n") == "24"

# custom cases
assert run("1\n10\n") == "0", "single element"
assert run("2\n1 100\n") == "100", "two elements boundary"
assert run("3\n3 3 3\n") == "6", "all equal values"
assert run("6\n6 5 4 3 2 1\n") == "20", "strictly decreasing"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次のような単一要素配列の場合`[10]`、隣接するペアがないため、ループは実行されず、答えは残ります。`0`、これは接続が存在しないという考えと一致します。 

のような配列の場合`[1, 100]`、アルゴリズムは正確に 1 つのステップを実行します。`max(1, 100) = 100`。 これは、唯一の境界がより大きなエンドポイントによって支配されているという解釈と一致します。 

次のような均一配列の場合`[5, 5, 5]`、すべての隣接関係が同じ値を提供します`5`、結果は次のようになります`10`。 このアルゴリズムは、等価性を表す特殊なケースを正しく回避します。 

次のような厳密に減少する配列の場合`[6, 5, 4, 3]`、各ステップは左側の要素に寄与し、セグメンテーション ロジックを必要とせずに合計が正しく累積され、ローカルの優位性がグローバル構造を完全に捉えていることが確認されます。
