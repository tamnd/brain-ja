 ## 問題の理解

 固定文字列が与えられています`s`長さの`n`、および複数のクエリ。 各クエリはセグメントを与えます`[l, r]`内部`s`。 セグメントごとに、新しい文字列を構築するように求められます。`t`それは可能な限り短く、それでも次のシーケンスとして表示されないようにします。`s[l..r]`。 

サブシーケンスのチェックは、標準的な貪欲な方法で行われます。位置から開始します。`l`、右にスキャンして、最初の出現を見つけます。`t1`、そこからスキャンを続けて見つけます`t2`、 等々。 過去に移動せずにすべての文字を正常に一致させた場合`r`、 それから`t`はサブシーケンスです。 そうでなければ、それを超えなければならない場合は、`r`、 そうではない。 

したがって、各クエリは、この貪欲な一致プロセスをセグメント内で「使い果たす」ことを強制する最短の文字列を要求します。 

文字列のアルファベットは小さくて固定されており、文字間の遷移を事前に計算できるため、これは重要です。 

この制約は、各クエリおよび各候補文字列に対して独立して部分列一致をシミュレートできないことを意味します。 強引に構築しようとした場合`t`そしてそれをテストしてください`[l, r]`、各テストにはすでにセグメント内で直線的な時間がかかり、使用可能な文字列の数は長さに応じて指数関数的に増加します。 貪欲に伸ばしてみても`t`チェックすると次のように劣化します`O(n * q)`試行ごとに、両方の場合は遅すぎます。`n`そして`q`大きいです。 

すべての文字が`s[l..r]`は同一です。 その場合は、いずれか`t`異なる文字を含む場合は 1 つのステップですぐに失敗しますが、同じ文字が繰り返される場合はより長く存続する可能性があります。 最も頻繁に出現する文字を常にローカルに追加する単純な戦略では、最善の動きがセグメント内の頻度ではなく、グローバルな次の出現に依存することを見落としてしまいます。

## アプローチ

 強引なアイデアは、最短の文字列を直接構築することです。`t`各クエリ内の部分シーケンスの一致プロセスをシミュレートすることによって。 ポジションから始める`l`、考えられるすべての次の文字を試し、ポインタがどこまで移動するかをシミュレートし、強制的に失敗するまで文字列を再帰的に拡張します。`r`。 これは、文字通りサブシーケンス チェックの定義に従っているため、概念的には機能します。 

問題は、各拡張子が次の出現箇所を見つけるために文字列内を前方にスキャンする必要があることと、可能な拡張子の数がアルファベット サイズごとに分岐することです。 貪欲に 1 つのブランチを選択したとしても、内部でスキャンを繰り返す必要があります。`[l, r]`これにより、最悪の場合、クエリごとに二次的な動作が発生します。 クエリが多くなると、これは不可能になります。 

重要な観察は、ポジションを固定すると、`x`部分シーケンス一致ポインタが現在位置する場所、次の文字に可能な最良の選択`t`に依存していない`[l, r]`。 のみに依存します`x`。 キャラクターごとに`c`、次の出現位置を計算できます。`c`後`x`。 最良の選択は、この次の位置をできるだけ右に移動するキャラクターです。これにより、サブシーケンスの存続期間が最大化されます。 

これはそれぞれのポジションを意味します`x`決定的な遷移が 1 つだけある`nxt[x]`、これは、最適なキャラクターを選択した後に到達可能な最も遠くの次の位置です。 これが構築されると、最も一致するのが難しい文字列を構築するプロセスは純粋なウォークになります。`l`を使用して繰り返しジャンプします。`nxt`通り過ぎるまで`r`。 

各クエリは、より大きな位置に到達するために必要なジャンプの数を見つけることに帰着します。`r`。 これは、各ノードが出力エッジを 1 つだけ持つ関数グラフ上の古典的なバイナリ リフティング問題です。

 ## アルゴリズムのチュートリアル

 まず、次に出現する各文字を前処理します。 あらゆるポジションについて`x`、現在いる場合に各キャラクターがどこに行くかを計算します。`x`部分シーケンスのマッチング中。 

次に、これを単一の最適なトランジションに変換します。`nxt[x]`、これは、ビルドの 1 つのステップで一致するポインターを押し込むことができる最も遠くの距離を表します。`t`。 

その後治療を行っております`nxt`関数グラフとして作成し、バイナリリフティングテーブルを構築することで、一度に複数のステップをジャンプできます。 

クエリごとに`[l, r]`からのジャンプをシミュレートします。`l`超えるまで`r`、リフティングテーブルを使用して、必要なジャンプの回数を数えます。 

### ステップ

 1. 事前計算`next_pos[x][c]`次に出現する文字として`c`ポジションの後`x`。 これは、各文字の最後に表示された位置を維持しながら、右から左にスキャンすることによって行われます。 
2. ポジションごとに`x`、計算する`nxt[x]`すべての中から最大値をとることで`next_pos[x][c]`。 文字が存在しない場合、その次の位置は次のように扱われます。`n + 1`。 このステップでは、最適な貪欲拡張を定義します。 
3. バイナリリフティングテーブルを構築する`up[k][x]`どこ`up[0][x] = nxt[x]`より高いレベルは 2 倍のジャンプで構成されます。 
4. 各クエリについて`[l, r]`から何度もジャンプしようとします。`l`範囲内に留まりながら 2 のべき乗で上向き`r`、何回ジャンプできるかを数えます。 
5. ポインタが初めて次の位置に移動したとき`r`、ジャンプした回数が答えです。 

### なぜ効果があるのか

 どの位置でも`x`、延長のプロセス`t`サブシーケンス一致ポインタが次にどこに到達するかによってのみ異なります。 この次の位置を最大化するキャラクターを常に選択するため、失敗を遅らせるためにすべてのステップが局所的に最適になります。 後続のプロセスは位置が単調であるため、一度ジャンプが定義されると、停止条件を除いて以前の選択やクエリ間隔には依存しません。`r`。 これにより、問題全体が、バイナリ リフティングによって正確に処理される決定論的関数の繰り返し適用に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    s = input().strip()
    
    ALPHA = 26
    nxt_pos = [[n] * ALPHA for _ in range(n + 2)]
    
    last = [n] * ALPHA
    
    for i in range(n, 0, -1):
        last[ord(s[i - 1]) - 97] = i
        for c in range(ALPHA):
            nxt_pos[i][c] = last[c]
    
    nxt = [0] * (n + 2)
    for i in range(1, n + 1):
        best = 0
        for c in range(ALPHA):
            best = max(best, nxt_pos[i][c])
        nxt[i] = best
    
    nxt[n + 1] = n + 1
    
    LOG = 20
    up = [[n + 1] * (n + 2) for _ in range(LOG)]
    
    for i in range(1, n + 2):
        up[0][i] = nxt[i]
    
    for k in range(1, LOG):
        for i in range(1, n + 2):
            up[k][i] = up[k - 1][up[k - 1][i]]
    
    out = []
    
    for _ in range(q):
        l, r = map(int, input().split())
        pos = l
        steps = 0
        
        for k in reversed(range(LOG)):
            np = up[k][pos]
            if np <= r:
                pos = np
                steps += 1 << k
        
        out.append(str(steps + 1))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はビルドから始まります`nxt_pos`、すべての位置のすべての文字の次の出現を保存します。 これにより、後で一定時間の遷移クエリが可能になります。 

それから`nxt[i]`サブシーケンス ポインタを最も遠くに移動する文字を選択することによって計算されます。 これは、文字の分岐選択から単一の決定的な遷移への重要な削減です。 

バイナリリフティングテーブル`up`この関数の上に構築されています。 各エントリー`up[k][i]`トランジションの適用を表します`2^k`から始まる回`i`。 

各クエリに対して、次の値を超えない範囲で可能な限り最大のジャンプを貪欲に適用します。`r`。 成功したジャンプの数に 1 を加えたものが、構築される文字列の長さになります。

 ## 特殊なケース

 セグメントが単一の繰り返し文字で構成されている場合、トランジションは常に 1 ステップ前に進みます。 アルゴリズムは次のようにしてこれを処理します。`nxt[x] = x+1`したがって、リフティングを繰り返すと、それまでにどれだけの位置が残っているかが正確にカウントされます。`r + 1`。 

ある位置の後に文字が再び出現しない場合、その次の出現は次のように扱われます。`n + 1`で最大候補となる。`nxt[x]`。 これは、部分シーケンスのマッチングにおける即時の失敗を正確にモデル化します。 

いつ`l == r`、ポインタはセグメントを超える前にごく少数の遷移しか行うことができず、バイナリ リフティングでは文字ごとの動きをシミュレートするのではなく、これを対数ステップで正しくカウントします。
