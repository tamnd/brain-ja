 ## 解決策
 ## 問題の理解

 単一の小文字の単語が与えられ、それが特定の音声規則に従っているかどうかを確認するように求められます。 このルールは、子音と母音がどのように順番に現れるかを制限します。 

すべての子音の直後には母音が続く必要がありますが、唯一の例外は子音です。`'n'`の後に任意の文字または文字列の末尾を続けることができます。 母音は次のように固定されます`'a'`、`'e'`、`'i'`、`'o'`、 そして`'u'`。 それ以外の文字は子音として扱われます。 

タスクは、文字列全体が適用されるすべての場所でこの制約を尊重するかどうかを判断するだけです。 

入力長は最大 100 です。これは、文字列を直接スキャンすれば十分であることを意味します。 たとえ$O(n^2)$ここでのアプローチは簡単ですが、構造は単一の左から右への検証で十分であることを示唆しています。 

ルールについて非公式に考えると、いくつかの特殊なケースが見落とされがちです。 1 つ目は文字列の最後に現れる子音です。 例えば、`"abc"`で終わる`'c'`、これは子音なので、後続の母音がないため、すぐにルールに違反します。 

もう 1 つのケースは、子音が連続する場合です。 例えば、`"king"`失敗する理由`'k'`続いて`'i'`それはいいのですが、`'n'`続いて`'g'`、 そして`'g'`ではない子音です`'n'`, したがって、その後に母音が必要ですが、何も保証されません。 

ついに、`'n'`それ自体は特別ですが、ローカルのみです。 のような文字列`"nbo"`は有効です。`'n'`の後に子音を続けることはできますが、それが非子音の場合、次の文字に安全性は与えられません。`n`子音。 

## アプローチ

 ブルートフォース解釈では、すべての子音の位置をチェックし、次の文字が見つかるまで前方にスキャンして、それが母音であるか、子音が母音であるかを確認します。`'n'`。 これは正しく機能しますが、最悪の場合、サフィックスの再スキャンが繰り返し行われ、二次的な動作が発生します。 

ここでは文字列が短いため、これでも問題ありませんが、条件の構造はより明確な不変条件を示唆しています。つまり、各位置の有効性は現在の文字と次の文字にのみ依存します。 長期的な依存関係がないため、任意に先を見据える必要はありません。 

これにより、問題は単一の直線パスに縮小されます。 各位置で、現在の文字がルールに違反する子音であるかどうかを確認するだけで済みます。 母音の場合は何もチェックする必要はありません。 もしそうなら`'n'`、常に安全です。 それ以外の場合は、次の文字が存在し、母音である必要があります。 

この観察により、冗長なチェックがすべて廃止され、検証が純粋にローカルになります。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、各文字が母音かどうかに基づいて検証します。`'n'`、または別の子音。 

1. 母音のセットを定義する`{a, e, i, o, u}`したがって、メンバーシップチェックは一定時間行われます。 これにより、文字列の比較を繰り返すことがなくなります。 
2. 各インデックスを反復処理します。`i`文字列の。 
3. 現在の文字が母音の場合、母音は後続の文字に制約を課さないため、制限なしで続行します。 
4. 現在のキャラクターが`'n'`、また続けます。`'n'`は「その後に母音を続けなければならない」ルールから除外されます。 
5. 現在の文字が他の子音である場合、次の文字があることを確認する必要があります。 もし`i + 1`範囲外の場合、文字列は直ちに無効になります。 
6. 次の文字が存在する場合は、それが母音であることを確認します。 そうでない場合はルール違反となり、早期に終了する場合があります。 

### なぜ効果があるのか

 重要な不変条件は、すべての無効な構成が、不正な構成が存在する正確な位置で検出可能であるということです。`n`子音が現れます。 このような子音には、その直後の後続子音に関する厳しいローカル要件があります。 この要件に違反した場合、ルールはグローバル構造ではなく隣接性に関するものであるため、後で修正することはできません。 したがって、正確性を保証するには、次の文字のみをチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    vowels = set("aeiou")
    
    n = len(s)
    for i, c in enumerate(s):
        if c in vowels:
            continue
        if c == 'n':
            continue
        
        # consonant that must be followed by vowel
        if i + 1 >= n or s[i + 1] not in vowels:
            print("NO")
            return
    
    print("YES")

if __name__ == "__main__":
    solve()
```コードはアルゴリズムを直接反映しています。 母音セットはメンバーシップの高速チェックに使用され、文字ごとに一定時間の検証が保証されます。 失敗時の早期終了により、違反の検出後の不必要なスキャンが回避されます。 

微妙な点は境界確認です`i + 1 >= n`。 それなしでアクセスすると、`s[i + 1]`文字列の末尾に子音が現れるとエラーが発生します。 これはまさに次のような単語を無効にするケースです。`"king"`。

 ## 特殊なケース

 次のような単一文字列`"n"`は有効です。`'n'`は、後続の母音の必要性を明示的に免除されます。 ループはそれを 1 回処理し、特殊なケースとして分類し、制限の問題なくそれを受け入れます。 

非で終わる文字列`n`などの子音`"abc"`最後の文字で失敗します。 いつ`i`最終インデックス、条件に達する`i + 1 >= n`すぐに拒否を引き起こします。 これは、特殊でないすべての子音の後には別の文字が続き、その文字は母音でなければならないという中心的なルールを捉えています。 

次のような子音の連続`"bcd"`最初の文字ですでに失敗しています。`'b'`続いて`'c'`、これは母音ではなく、また免除されません。 アルゴリズムは早期に終了し、完全な走査を必要とせずに可能な限り早い位置で違反が検出されることを示しています。
