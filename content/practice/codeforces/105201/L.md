 ## 解決策
 ## 問題の理解

 都市は木です。すべての交差点は 1 本の小道を介して他のすべての交差点に接続されています。 交差点`1`には常に元のガソリン スタンドが含まれますが、他の交差点には一時的にレプリカが含まれる場合があります。 数日の間にレプリカが追加および削除され、特定の交差点から現在最も近い既存のガソリン スタンドまでの距離を尋ねる日もあります。 

タスクはツリー自体を保守することではありません。 道は決して変わりません。 課題は、マークされた頂点のセットを維持することです。マークされた頂点は、そこにガソリン スタンドが存在することを意味し、同時に最短距離のクエリに迅速に答えます。 

制約により、動的データ構造が強制されます。 まで`2 * 10^5`交差点と`2 * 10^5`運用では、クエリごとにすべてのガソリン スタンドをスキャンするのはコストがかかりすぎます。 最悪の場合、すべての操作がクエリであり、ステーションが多数ある場合は、直接検索に時間がかかる可能性があります。`O(nq)`、それは約です`4 * 10^10`操作。 すべてのクエリ頂点から幅優先検索を実行することさえ不可能です。 操作ごとに対数またはそれに近い仕事量が必要です。 

単純な実装を壊すエッジケースがいくつかあります。 1 つ目は、元のステーションが頂点にあることです。`1`決して消えません。 例えば：```
3 3
1 2
2 3
3 3
1 2
3 3
3 1
```出力は次のとおりです。```
0
0
```にステーションを追加した後、`2`、クエリ`3`距離を与える`1`、 ない`0`ただし、重要なケースは、頂点をクエリすることです。`1`必ず戻らなければなりません`0`。 レプリカのみを削除しても、頂点を誤って削除してはなりません`1`。 

もう 1 つのよくある間違いは、最も近い駅が常に最近追加された頂点の中にあると仮定することです。 例えば：```
4 3
1 2
2 3
3 4
1 4
3 2
2 4
```出力は次のとおりです。```
0
```の駅`1`は利用可能なままなので、レプリカを削除した後、`4`、頂点`2`まだ距離がある`1`頂点へ`1`。 追加だけを記憶し、古いアクティブなステーションを忘れる構造は失敗します。 

最後のエッジケースは、答えがゼロの場合です。 最寄りの駅はそれ自体であるため、駅を含む交差点でのクエリはすぐに 0 を返す必要があります。 

## アプローチ

 簡単な解決策は、現在のガソリン スタンドのセットを保持し、クエリごとにクエリの交差点からガソリン スタンドに到達するまでグラフ検索を実行することです。 幅優先探索で見つかった最初の測点は最小距離にあるため、これは正しいです。 ただし、1 つのクエリですでにすべての頂点にアクセスでき、これを繰り返すことができます。`2 * 10^5`クエリにより、許容できない最悪のケースが発生します。 

もう 1 つの直接的なアプローチは、すべてのステーションを保存し、クエリ頂点からすべてのステーションまでの距離を計算することです。 ツリー距離クエリは、最小共通祖先の前処理を使用して高速に実行できますが、ステーションが多数ある場合は、依然として作業量が多すぎます。 ブルート フォース ソリューションは、単一のクエリを適切に処理するため成功しますが、クエリと更新の数が多いため失敗します。 

重要な観察は、ツリーが静的であるということです。 マークされた頂点のセットのみが変更されます。 これにより、重心分解が適切になります。 重心はツリーをより小さなコンポーネントに分割し、すべての頂点は次のコンポーネントのみに属します。`O(log n)`重心レベル。 ツリー全体を検索するのではなく、すべての重心付近のアクティブなステーションに関する情報を保存します。 

すべての重心について`c`、私たちはからの距離を保ちます`c`を通る重心分解パスに属するすべてのアクティブなステーションに送信されます。`c`。 クエリが頂点について尋ねる場合`x`のすべての重心の祖先を調べます。`x`。 からの任意のパス`x`任意のステーションへの送信は、あるレベルでこれらの重心の 1 つを通過する必要があるため、最良の答えは次の最小値です。```
distance(x, centroid) + closest station distance stored at centroid
```ステーションを追加および削除すると、に保存されている値のみが変更されます。`O(log n)`分解パス上の重心。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n) | O(n) | 遅すぎる |
 | 最適 | 更新/クエリごとに O(log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの重心分解を構築します。 分解中、元の頂点ごとにペアのリストが保存されます。`(centroid, distance)`重心ツリー内の祖先とそれぞれの祖先までの距離を記述します。 

このリストは、通常のツリーの頂点と、それに関する情報を要約できる重心との間の橋渡しとなります。 
2. すべての重心について、現在アクティブなステーションまでの距離を含むヒープを維持します。 ステーションは削除できるため、遅延削除する必要がある距離を含む 2 番目のヒープも維持します。 

遅延削除により、ヒープの途中からのコストのかかる削除が回避されます。 両方のヒープに最小値が出現すると、両方のコピーが破棄されます。 
3. 最初に頂点をアクティブ化します`1`、元のガソリンスタンドが常に存在するためです。 アクティブ化とは、パス上のすべての重心ヒープにその距離を挿入することを意味します。 
4. 頂点にレプリカを構築する場合`x`、 活性化`x`。 あらゆる人にとって`(centroid, distance)`に所属するペア`x`、 入れる`distance`その重心のヒープに。 
5. レプリカが頂点で破壊された場合`x`、無効化します。 対応する距離をすべての重心の削除ヒープに挿入します。`x`さんの道。 
6. 頂点でのクエリの場合`x`、すべてを検査します`(centroid, distance)`に所属するペア`x`。 まず遅延削除ヒープをクリーンアップしてから、次の距離を結合します。`x`その重心に保存されている最も近いアクティブなステーションの距離を使用して、重心まで移動します。 

すべての重心の祖先の最小値を取ると、最も近い駅が得られます。 

なぜ効果があるのか:

 ツリー内の頂点の各ペアには一意のパスがあります。 重心分解では、どの頂点ペアについても、両方の頂点の分解パス上に重心が存在し、その重心を介した接続が考慮されます。 その重心に保存された値は、重心からアクティブなステーションまでの最短ルートを表します。 クエリ頂点から同じ重心までの距離を加算すると、そのステーションへの候補パスが再構築されます。 考えられるすべてのステーションが重心祖先を通じて考慮されるため、最小の候補は正確に真の最も近い距離になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

size = [0] * (n + 1)
dead = [False] * (n + 1)
paths = [[] for _ in range(n + 1)]

def calc_size(v, p):
    size[v] = 1
    for u in g[v]:
        if u != p and not dead[u]:
            size[v] += calc_size(u, v)
    return size[v]

def find_centroid(v, p, total):
    for u in g[v]:
        if u != p and not dead[u] and size[u] * 2 > total:
            return find_centroid(u, v, total)
    return v

def collect(v, p, d, c):
    paths[v].append((c, d))
    for u in g[v]:
        if u != p and not dead[u]:
            collect(u, v, d + 1, c)

def decompose(v):
    total = calc_size(v, 0)
    c = find_centroid(v, 0, total)
    dead[c] = True
    collect(c, 0, 0, c)
    for u in g[c]:
        if not dead[u]:
            decompose(u)

decompose(1)

add_heap = [[] for _ in range(n + 1)]
del_heap = [[] for _ in range(n + 1)]
active = [False] * (n + 1)

def activate(v):
    if active[v]:
        return
    active[v] = True
    for c, d in paths[v]:
        heapq.heappush(add_heap[c], d)

def deactivate(v):
    if not active[v]:
        return
    active[v] = False
    for c, d in paths[v]:
        heapq.heappush(del_heap[c], d)

def clean(c):
    while add_heap[c] and del_heap[c] and add_heap[c][0] == del_heap[c][0]:
        heapq.heappop(add_heap[c])
        heapq.heappop(del_heap[c])

def query(v):
    ans = 10 ** 9
    for c, d in paths[v]:
        clean(c)
        if add_heap[c]:
            ans = min(ans, d + add_heap[c][0])
    return ans

activate(1)

out = []
for _ in range(q):
    data = list(map(int, input().split()))
    if data[0] == 1:
        activate(data[1])
    elif data[0] == 2:
        deactivate(data[1])
    else:
        out.append(str(query(data[1])))

sys.stdout.write("\n".join(out))
```重心分解部分は静的構造を構築します。`paths[v]`は重要な配列です。更新またはクエリの際に頂点が使用できる重心が正確に格納されます。 

各重心の 2 つのヒープは、遅延削除を備えたマルチセットを実装します。 Python ヒープは最小限の要素の効率的な削除のみをサポートしているため、破壊されたステーションは個別に記録され、先頭に到達したときに削除されます。 これにより、すべてのヒープ操作が対数的に維持されます。 

頂点の活性化`1`元のステーションは初期状態の一部であるため、クエリを処理する前に発生します。 この問題により、削除操作のターゲットがレプリカのみであることが保証されるため、初期アクティブ化を維持する以外に追加の保護は必要ありません。 

すべての距離は Python の整数に快適に適合します。 元のツリーがチェーンになる可能性があるため、再帰制限が増加し、最初の深さ優先検索が Python のデフォルトの再帰制限よりもはるかに深くなります。

 ## 特殊なケース

 永久ステーションの場合、アルゴリズムは頂点をアクティブ化します。`1`イベントを読む前に。 クエリが頂点で行われた場合`1`、その重心パスには保存された距離が含まれています`0`そのアクティブなステーションからの応答なので、答えはすぐにゼロになります。 

ステーションが追加され、後で削除されると、アクティベーションによってその距離が関連するすべての重心ヒープに挿入されます。 削除ではヒープのスキャンや再構築は行われません。 一致する値が削除ヒープに挿入され、それらの重心に対する次のクエリでは、最小値が使用される前に古い値が破棄されます。 これにより、削除されたステーションが応答に影響を与えることがなくなります。 

それ自体にステーションを含む頂点でのクエリの場合、更新フェーズでは、その頂点のパス上のすべての重心構造に距離 0 がすでに挿入されています。 クエリ中に、その頂点を含む重心はゼロの候補に寄与するため、返される最小値は正確です。
