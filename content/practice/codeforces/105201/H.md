 ## 解決策
 ## 問題の理解

 私たちは次のラインを持っています`n * k`入口からの距離に応じて番号が付けられた位置。 各ポジションには最初に 1 つの靴が含まれており、各人が正確に所有しています`k`靴。 配列`a`現在各位置に置かれている靴の所有者を示します。 

1 日は 2 つのランダムなイベントで構成されます。 誰もが一様に自分の靴を一足選び、それを持ち去ります。 その後、人々はランダムな順序で戻ってきます。 取り外された靴は、到着順に空の位置に配置され、最も近い空の位置が最初に埋められます。 

クエリごとに、特定の日数後の特定の人が所有するすべての靴の予想平均位置が必要です。 答えは、正確な有理値のモジュール表現です。 

ポジションの合計数は最大で`500000`、ただしクエリの数も`500000`、日数は次のように大きくなります。`10^18`。 たとえ 1 つのクエリに何日もかかる場合でも、あまりにも多くの遷移が必要となるため、シミュレーションは機能しません。 50 万件のクエリでは、前処理後のクエリごとにほぼ一定の時間が必要ですが、クエリごとの日数や靴の合計数によっては除外されます。 

主なエッジケースは遷移公式から得られます。 いつ`k = 1`, 誰もが靴を 1 つだけ所有しているため、毎日すべての靴を脱いでランダムに置き直します。 漸化式の乗数はゼロになるため、通常のモジュラー除算のように扱うと失敗します。 例えば：```
Input:
2 1
1 2
2
1 0
1 1
```人物 1 の初期の平均順位は次のとおりです。`1`。 1 日後には靴が 2 つになり、その所有者がランダムに位置を割り当てられます。`1`そして`2`したがって、人物 1 の予想平均順位は次のようになります。`3/2`。 次のべき乗を計算する不注意な実装`(k-1)/k`扱わずに`k = 1`ゼロを反転しようとします。 

もう一つのエッジケースは、`d = 0`。 ランダムな操作は発生しないため、答えは初期平均値になる必要があります。 例えば：```
Input:
2 2
1 1 2 2
1
1 0
```答えは`3/2`人 1 の 2 つの靴はすでに位置 1 と 2 にあるためです。チェックせずに長期公式を直接適用します。`d = 0`誤って初期状態を定常値に置き換える可能性があります。 

最後の微妙なケースは、ポジションのインデックスが 1 つであることです。 のために：```
Input:
2 2
1 2 1 2
1
1 0
```person 1 はポジション 1 と 3 を所有しているため、平均は次のようになります。`2`。 最初のスロットを距離ゼロとして扱うと、間違った結果が生成されます。 

## アプローチ

 直接的なアプローチは、靴の全体的な配置を保持し、毎日シミュレーションすることです。 毎日、各人の靴をランダムに 1 つ選び、空いている位置を特定し、脱いだ靴をシャッフルして元に戻します。 シミュレーションを毎日行った後、リクエストされた人物の平均位置を計算できました。 これは、説明されているプロセスに正確に従っているため、正しいです。 

問題は、日数に制限がないことです。 1 つのクエリで次のことが尋ねられる場合があります`10^18`日なので、1 日を処理するシミュレーションでも`O(nk)`時間は無理です。 最悪の場合、約`10^18 * 5 * 10^5`操作。 

有益な観察は、個々の靴の位置を知る必要がないということです。 各個人に属するポジションの予想合計が必要なだけです。 

ある人が靴の位置の合計を期待していると仮定します。`S`。 彼らのそれぞれの`k`靴には確率がある`1/k`脱げなくなるため、残った靴は予想される合計額に貢献します。`(k-1)/k * S`。 

取り外された靴には、空の位置の 1 つが割り当てられます。 すべての人において、空いている位置は、まさに脱いだ靴の位置です。 どの靴にも確率があるから`1/k`削除される場合、空のポジションの予想合計は、ポジションの合計を で割ったものになります。`k`。 ポジションの合計は次のとおりです。$$\frac{nk(nk+1)}{2}$$したがって、空のポジションの予想合計は次のようになります。$$\frac{n(nk+1)}{2}$$がある`n`削除された靴はすべて、同じように空のポジションを取得する可能性があります。 したがって、ある人の脱いだ靴の予想される新しい位置への寄与は次のようになります。$$\frac{nk+1}{2}$$これにより、線形回帰が得られます。$$S_{t+1}=\frac{k-1}{k}S_t+\frac{nk+1}{2}$$この繰り返しの不動点は、無限日数後の平均位置です。$$\frac{nk+1}{2}$$合計ではなく平均の場合、同じ式は次のようになります。$$A_d=C+\left(\frac{k-1}{k}\right)^d(A_0-C)$$どこ`A0`は初期の平均位置であり、`C`は`(nk+1)/2`。 

全体の問題は、各人の初期平均を保存し、クエリごとに 1 つのべき乗剰余を計算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(日 * n * k) | O(nk) | 遅すぎる |
 | 最適 | O(nk + q log d) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期配置における各人物の役職の合計を数えます。 それぞれの合計を次の値で割ります`k`初期平均位置を取得するには`A0`それぞれの人の。 
2. 再帰で使用されるモジュール定数を事前計算します。 定常値は次のとおりです。$$C=\frac{nk+1}{2}$$乗数は次のとおりです。$$r=\frac{k-1}{k}$$すべての除算は、逆モジュラーによる乗算として実行されます。 

1. クエリごとに`(x, d)`、保存されている人の初期平均を取得します。`x`。 
2. もし`d`がゼロの場合、遷移が発生していないため、最初の平均がすぐに出力されます。 
3. それ以外の場合は、次のように計算します。$$r^d$$2進累乗を使用します。 いつ`k = 1`、`r`はゼロであるため、すべての正の日数は定常値に直接到達します。 

1. 以下を使用して値を結合します。$$C+r^d(A_0-C)$$結果のモジュロを出力します`10^9+7`。 

これが機能する理由は、各人の予想される平均順位が単一の値で完全に記述されるためです。 毎日のランダムな選択は、靴が留まるか動くかにのみ影響し、期待値の直線性は、すべての靴の期待される寄与を独立して合計できることを意味します。 反復は以前の期待平均値のみに依存するため、この値を 1 人あたり 1 つ保存すれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    sums = [0] * (n + 1)
    for i, x in enumerate(a, 1):
        sums[x] += i

    inv_k = pow(k, MOD - 2, MOD) if k != 1 else 0
    inv_2 = (MOD + 1) // 2

    if k == 1:
        c = (n + 1) * inv_2 % MOD
        initial = [0] * (n + 1)
        for i in range(1, n + 1):
            initial[i] = sums[i] % MOD
    else:
        c = (n * k + 1) % MOD * inv_2 % MOD
        initial = [0] * (n + 1)
        for i in range(1, n + 1):
            initial[i] = sums[i] % MOD * inv_k % MOD

    if k == 1:
        multiplier = 0
    else:
        multiplier = (k - 1) % MOD * inv_k % MOD

    q = int(input())
    ans = []

    for _ in range(q):
        x, d = input().split()
        x = int(x)
        d = int(d)

        if d == 0:
            ans.append(str(initial[x]))
        elif k == 1:
            ans.append(str(c))
        else:
            power = pow(multiplier, int(d), MOD)
            value = (c + power * (initial[x] - c)) % MOD
            ans.append(str(value))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードの最初の部分では、各所有者のポジションの初期合計が保存されます。 それぞれの所有者が正確に持っているため、`k`靴、で割る`k`初期平均が得られます。 

反復定数は 1 回計算されます。 モジュラーの逆`k`の場合にのみ有効です`k`は 1 つではないため、特殊なケースは個別に処理されます。 いつ`k = 1`、最初の配置に関するすべての情報を失うには 1 日で十分であり、答えはすべての正の定常値と等しくなります。`d`。 

通常の場合、`pow(multiplier, d, MOD)`対数時間で高速累乗を実行します。 Python の整数はオーバーフローしませんが、すべての演算モジュロを削減します。`MOD`値を小さく保ち、必要なモジュラー演算に一致します。

```定常平均は次のとおりです。$$C=\frac{4+1}{2}=\frac52$$人物 1 の状態は次のように発展します。 

| 日 | 初期平均 A0 | 乗算器の電力 | 現在の平均 |

 初日は、期待平均が初期値から定常値に向かって半分移動します。 これは、回帰が平衡状態に直接ジャンプしないことを確認します。

 ## 特殊なケース

 いつ`k = 1`、アルゴリズムは決して反転しようとしません`k`または無効な反復乗数の累乗を計算します。 のために：```
2 1
1 2
2
1 0
1 1
```最初のクエリは初期位置を返します`1`。 2 番目のクエリは次を返します。$$\frac{2+1}{2}=\frac32$$それは`500000005`モジュロ`10^9+7`。 

いつ`d = 0`の場合、アルゴリズムは繰り返しを完全にスキップします。 のために：```
2 2
1 1 2 2
1
1 0
```保存された合計は`3`で割って、`k = 2`与える`3/2`。 日数が経過しないため、答えは元の配置のままになります。 

1 つのインデックス付きポジションの場合、コードは次を使用して合計を計算します。`enumerate(a, 1)`。 で：```
2 2
1 2 1 2
1
1 0
```人物 1 はポジション 1 と 3 を所有しており、平均すると`(1+3)/2 = 2`。 この実装は、位置を 1 つもシフトしないため、物理的距離の定義と一致します。
