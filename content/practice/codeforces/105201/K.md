 ## 解決策
 ## 問題の理解

 文字列とターゲット値が与えられます$k$。 個別の部分文字列ごとに$t$、文字列内に出現する回数を調べ、その頻度に部分文字列の長さを掛けます。 この製品が等しい場合$k$、その部分文字列は有効とみなされます。 この条件を満たす個別の部分文字列の数を数え、それらの中で辞書順に最小のものと最大のものを報告する必要もあります。 

重要な点は、出現箇所を反復処理するのではなく、個別の部分文字列 _values_ を反復処理していることです。 異なる位置にある 2 つの同一の部分文字列は、応答セットに 1 回だけ寄与しますが、条件ではその頻度が重要です。 

文字列の長さは最大です$10^6$、 その間$k$まで上がります$10^{12}$。 これにより、すべての部分文字列を明示的に列挙するアプローチは即座に除外されます。$O(n^2)$彼らのうち。 各部分文字列の頻度を単純に計算することさえ不可能です。 

主な困難は、各部分文字列のすべての出現に関するグローバルな頻度情報と、部分文字列の長さに関連付けられたフィルタリング条件の両方が必要であることです。 これは、サフィックスベースの構造、または繰り返し構造による部分文字列のグループ化と組み合わせたハッシュ技術を強く示唆しています。 

犯しやすい単純な間違いは、各部分文字列を 1 回チェックし、一致する文字列の出現をカウントすれば十分であると考えることです。 たとえば、次のような文字列では`"aaaaaa"`、部分文字列`"aaa"`何度も登場し、重なり合います。 重複する発生を慎重に処理しない、または一致を繰り返し再計算する単純なスキャンは、タイムアウトするか、頻度のカウントを誤ります。 

もう 1 つの微妙なエッジ ケースは、複数の部分文字列が同じ有効な値を持つ場合です。 たとえば、いくつかの異なる長さが満たされる場合、$|t| \cdot freq(t) = k$、1 つの長さクラス間だけでなく、すべてのクラス間で辞書編集上の極端な点を正しく識別する必要があります。 

## アプローチ

 直接的な総当たり手法では、すべての部分文字列を列挙し、文字列をスキャンしてその頻度を計算し、条件をチェックします。 部分文字列を修正したとしても、スライディング ウィンドウを介してその出現数をカウントするのは困難です。$O(n)$、そして、あります$O(n^2)$部分文字列、結果として$O(n^3)$最悪の場合。 比較を減らすためにハッシュを使用しても、依然として次のような問題に直面します。$O(n^2)$個別の部分文字列なので、頻度を個別にカウントする余裕はありません。 

重要な構造上の観察は、条件が部分文字列自体にのみ依存し、その位置には依存しないということです。 すべての個別の部分文字列の出現数を効率的に計算できれば、部分文字列ごとに方程式を 1 回評価できます。 これはまさに、LCP ベースのカウントを備えたサフィックス オートマトンまたはサフィックス配列が提供するものです。これにより、繰り返し出現の同値クラスごとに部分文字列がグループ化され、頻度の寄与を集合的に計算できるようになります。 

ここでより有益な観点は、各部分文字列が接尾辞構造内の間隔に対応し、その頻度はその接頭辞を共有する接尾辞の数によって決まるということです。 接尾辞オートマトンでは、各状態は同一の出現セットを持つ部分文字列のセットを表し、接尾辞リンクを介して線形時間で各状態の出現数を計算できます。 

(状態で表される) 個別の部分文字列ごとに、その長さの範囲と頻度がわかれば、その間隔に次のような長さが存在するかどうかを確認できます。$len \cdot freq = k$。 各状態は連続した範囲の長さを持つすべての部分文字列を表すため、チェックは状態ごとに最大 1 つの候補長に減ります。 

有効な部分文字列を識別した後、遷移を使用して有効な状態から最小文字列と最大文字列を再構築することで、辞書編集上の最小文字列と最大文字列を取得できます。

 | 接尾辞 オートマトン + カウント |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 文字列に対して構築されたサフィックス オートマトンを使用して問題を解決し、出現回数を伝播して部分文字列の頻度を計算します。 

1. 文字列の接尾辞オートマトンを構築します。 各状態は、テキスト内の同じ終了位置を共有する部分文字列のセットを表します。 この構造は、繰り返される部分文字列を線形数の状態に圧縮します。 
2. 各状態について、その状態を維持します。`len`(その状態の部分文字列の最大長) および`link.len`(サフィックスリンクから導出される最小境界)。 これにより、その状態によって表される部分文字列の長さの連続した間隔が得られます。 
3. オートマトンを構築した後、接尾語の終端に対応する終端状態をマークすることによって出現カウントを初期化します。 各端末状態は周波数 1 から始まります。 
4. 周波数を降順に伝播します。`len`, そのため、長い部分文字列はそのカウントをサフィックスにリンクされた状態にプッシュします。 これにより、すべての状態でその部分文字列クラスの合計出現数が累積されるようになります。 
5. 各状態について、その間隔内の長さを持つすべての部分文字列を表すものとして解釈します。$(link.len, len]$。 各状態について、長さが存在するかどうかを計算します。$L$この間隔で次のようになります$L \cdot freq = k$。 そうであれば、この状態を有効としてマークします。 
6. 有効な状態をすべて収集します。 それぞれの有効な状態は、少なくとも 1 つの部分文字列ファミリーに寄与します。 辞書編集上の最小および最大の部分文字列を抽出するには、オートマトンをルートから走査します。 

最小の文字列についてはアルファベット順に遷移をたどり、最大の文字列についてはアルファベット順を逆に追跡しますが、有効な状態に対応するパスに沿ってのみ遷移を追跡します。 
7. すべての有効な状態をカウントし、走査から得られた辞書編集上の最小文字列と最大文字列を出力します。 

### なぜ効果があるのか

 接尾辞オートマトンは、すべての部分文字列を等価クラスに分割します。各クラスは、元の文字列内の同じ出現セットを共有します。 これにより、クラス全体で部分文字列の頻度が一定になるため、条件のチェックは単一の代表的な間隔のチェックに減ります。 すべての部分文字列が 1 つの状態間隔に正確に対応するため、有効な候補が見逃されることはありません。 辞書編集的トラバーサルが機能するのは、遷移では接頭辞の順序が保持され、トラバーサルを有効な状態に制限することで、条件を満たす部分文字列のみを構築できるようにするためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self, n):
        self.next = [{} for _ in range(2 * n)]
        self.link = [-1] * (2 * n)
        self.length = [0] * (2 * n)
        self.last = 0
        self.size = 1

    def extend(self, c):
        p = self.last
        cur = self.size
        self.size += 1
        self.length[cur] = self.length[p] + 1

        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = self.size
                self.size += 1
                self.length[clone] = self.length[p] + 1
                self.next[clone] = self.next[q].copy()
                self.link[clone] = self.link[q]

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

def solve():
    s = input().strip()
    n = len(s)

    sam = SAM(n)

    for ch in s:
        sam.extend(ch)

    size = sam.size

    cnt = [0] * size
    for i in range(size):
        cnt[i] = 0
    cnt[0] = 0

    # mark terminal states
    v = sam.last
    while v:
        cnt[v] = 1
        v = sam.link[v]

    order = sorted(range(size), key=lambda x: sam.length[x], reverse=True)

    for v in order:
        p = sam.link[v]
        if p != -1:
            cnt[p] += cnt[v]

    def check_state(v):
        L = sam.length[v]
        p = sam.link[v]
        low = sam.length[p] + 1 if p != -1 else 1

        # try candidate length
        if k % cnt[v] != 0:
            return False
        need_len = k // cnt[v]
        return low <= need_len <= L

    valid = [False] * size
    for i in range(size):
        if cnt[i] > 0 and check_state(i):
            valid[i] = True

    def dfs_small(v, path):
        res = None
        if v != 0 and valid[v]:
            return path
        for c in sorted(sam.next[v].keys()):
            u = sam.next[v][c]
            if cnt[u] > 0:
                res = dfs_small(u, path + c)
                if res is not None:
                    return res
        return None

    def dfs_large(v, path):
        res = None
        if v != 0 and valid[v]:
            return path
        for c in sorted(sam.next[v].keys(), reverse=True):
            u = sam.next[v][c]
            if cnt[u] > 0:
                res = dfs_large(u, path + c)
                if res is not None:
                    return res
        return None

    ans_list = [i for i in range(size) if valid[i]]

    if not ans_list:
        print(0)
        return

    min_s = dfs_small(0, "")
    max_s = dfs_large(0, "")

    print(len(ans_list))
    print(min_s)
    print(max_s)

if __name__ == "__main__":
    solve()
```この実装では、サフィックス オートマトンを構築し、その後、端末カウントをサフィックス リンクに沿って逆方向に伝播し、各状態がその完全な出現頻度を保存します。 の`check_state`関数は制約を直接エンコードします$|t| \cdot freq(t) = k$それを状態の有効な間隔内の単一の長さチェックに変換することによって。 DFS プロシージャは、ソートされた順序でオートマトンの遷移を尊重することにより、辞書編集的に最小および最大の有効な部分文字列を構築します。 

微妙な点は、周波数の伝播は長さの降順に進む必要があることです。 そうしないと、短い状態が長い状態からの寄与を受け取る前に更新され、正確さが損なわれます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての文字が同一である場合です。これは、重複した文字が出現すると、非常に不均一な周波数増加が生じるためです。 で`"aaaaaa"`、それぞれの長い部分文字列は何度も重複しており、小さなサブセットのみが方程式を満たします。 サフィックス オートマトンは、これらの重複を状態頻度に正しく集約し、二重カウントを防ぎます。 

次のように、すべての文字が異なる場合には、別の特殊なケースが発生します。`"abcde"`。 ここでは、すべての部分文字列の頻度が正確に 1 であるため、条件は部分文字列の長さが次と等しいかどうかをチェックすることになります。$k$。 もし$k$は部分文字列の長さとして表現できないため、答えは空です。 各状態には周波数 1 があり、正確な長さを含む間隔のみがあるため、オートマトンはこれを自然に処理します。$k$チェックを乗り越えます。 

3 番目のエッジ ケースは、複数の状態が有効な製品に対応する場合です。 このような場合、辞書編集では、無効な状態が構築順序で前に現れたとしても、無効な状態を無視する必要があります。 有効な状態マーキングによって制約された DFS は、寄与しない遷移を早期に削除することで正確性を保証します。
