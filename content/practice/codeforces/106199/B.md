 ## 問題の理解

 私たちには次のようなシステムが与えられています$n$コンポーネント。それぞれに負でない整数値を割り当てる必要があります。$d_i$。 これらの値は独立していません。 コンポーネントのペア間には有向制約があります。 各制約の形式は次のとおりです。$u \to v$パラメータ付き$a, b$、そしてそれは下限を強制します$d_u$に関しては$d_v$: の値$u$少なくとも$a \cdot d_v + b$。 

これらの依存関係ルールに加えて、グローバル予算、つまり選択されたすべての値の合計があります。$d_i$を超えてはなりません$X$。 依存関係制約と合計制約の両方を満たすすべての代入の中で、すべての代入の最小値を最大化したいと考えます。$d_i$。 有効な割り当てが存在しない場合は、不可能であることを報告する必要があります。 

したがって、この構造は、総和にグローバルな上限を持つ線形下限不等式のシステムです。 目的は、合計や個々の値を最大化することではなく、実行可能性を維持しながら最小の変数を可能な限り高くすることです。 

制約により、最大で$2 \cdot 10^5$テストごとの変数と依存関係、最大$10^4$テスト。 これにより、テストごとに二次関数や三次関数さえも即座に除外されます。 どのソリューションも、総入力サイズにおいて本質的に線形またはほぼ線形である必要があります。$O((n + m) \log X)$またはそれ以上です。 

素朴な解釈では、貪欲に値を割り当てたり、制約を一度だけ伝播させたりしようとします。 これは、制約が係数を介して値を乗算的に増幅するチェーンやサイクルを形成する可能性があるため、失敗します。$a_i$。 小さなサイクルであっても、大規模な固定小数点動作が強制される可能性があります。 

いくつかの失敗シナリオがその微妙さを示しています。 

相互制約のある 2 つの変数を考えてみましょう。$1 \to 2: d_1 \ge d_2$、$2 \to 1: d_2 \ge d_1 + 1$。 これは不可能です。$d_1 \ge d_1 + 1$。 

より微妙なケース:$1 \to 2: d_1 \ge 2 d_2$、$2 \to 1: d_2 \ge 2 d_1$。 これにより、両方向に指数関数的な増加が強制され、すべての値がゼロでない限り不可能ですが、定数によってはゼロが制約に違反する可能性があります。 

もう 1 つのエッジ ケースは、制約がチェーンを形成し、小さな増加が逆方向に伝播し、1 つのノードがシステム全体を支配する場合です。 1 つのノードを変更すると以前の仮定が無効になるため、ローカルの貪欲な割り当ては失敗します。 

## アプローチ

 ブルートフォース手法では、ターゲット値を推測しようとします。$T$、強制する$d_i \ge T$すべてのノードに対して制約を繰り返し、固定点に到達するまで制約を伝播し、合計制約が満たされているかどうかを確認します。 各伝播がすべてのエッジを複数回横断する可能性があり、多くの値を試す必要があるため、これはすでにコストがかかります。$T$。 最悪の場合こうなります$O(nm)$チェックごとに、大きな値に対する二分探索による乗算は実行不可能になります。 

重要な観察は、問題が目標の最小値において単調であるということです。 候補を固定したら$T$、実現可能性を確認できます。$d_i \ge T$、その後繰り返し制約を適用します$d_u = \max(d_u, a d_v + b)$安定するまで。 このプロセスが予算を超える場合$X$、または矛盾が生じる場合、候補は無効です。 

これにより、問題は最大線形不等式系の実現可能性チェックに変換されます。 各制約は下限を前方に伝播し、更新ごとに値が増加するだけであり、値は実現可能性またはオーバーフローの検出によって制限されるため、システムは収束します。 

次に、実現可能な最小値の最大値を二分探索します。$T$。 チェックごとに、次の条件を満たす最小の実行可能な割り当てを計算します。$d_i \ge T$と依存関係の制約を調べて、合計を確認します。 

これは、増加するため機能します。$T$全部増やすだけ$d_i$結果として得られるクロージャーでは、それらが減少することはないため、実現可能性は単調です。

## アルゴリズムのチュートリアル

 この問題を、固定の下限制約の下で「実行可能な最小の割り当て」を繰り返し解くものとして扱います。$T$。 

1. 候補値を確定する$T$。 ごとに初期化します$d_i = T$。 これにより、最小値は少なくとも次のとおりであるという要件が強制されます。$T$。 
2. すべてのノードをキューに入れます。 BFS のようなプロセスを使用して制約緩和を伝播します。 
3. キューが空でない間にノードを取得します。$v$そして、それに影響を与えるすべての受信制約を緩和しようとします。 各エッジについて$u \to v$パラメータ付き$a, b$かどうかを確認します。$d_u$満足するには増やす必要があります$d_u \ge a \cdot d_v + b$。 その場合はアップデートしてください$d_u$そして押します$u$列に並びます。 

この方法で更新を処理する理由は、各ノードの値がそれを上向きに強制するすべての制約の最大値であるため、緩和を繰り返すと最小の固定点に収束するためです。 

1. 伝播中に、いずれかの値が安全限界を超えた場合 (たとえば、$X$）、早期に停止してこれを宣言できます$T$実現不可能。 Any further increases only worsen feasibility.
 2. After stabilization, compute the sum of all$d_i$。 超えた場合$X$、 これ$T$実現不可能です。 それ以外の場合は実現可能です。 
3. 二分探索$T$から$0$十分に大きな上限まで (通常は$10^{18}$）。 実現可能な最適な割り当てを追跡します。 
4. 最終的な最適値を得るために伝播を再実行します。$T$実際のものを再構築する$d_i$価値観。 

なぜ効果があるのか:

 重要な不変条件は、各緩和ステップの後に、フォームのすべての制約が解除されることです。$d_u \ge a d_v + b$は、更新されたノードを含むすべての処理されたエッジに対して満たされ、値は必要な場合にのみ増加します。 これにより、キューが空になると、以前の値の最小性を侵害することなく、制約によって変数をさらに増やすことができなくなります。 結果として得られるベクトルは、上記の最小固定点です。$T$。 制約も目的も単調なので、$T$、二分探索では、実現可能な最小値の最大値が正しく検出されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def check(n, edges, X, T):
    d = [T] * n
    q = deque(range(n))
    inq = [True] * n

    while q:
        v = q.popleft()
        inq[v] = False
        dv = d[v]

        for u, a, b in edges[v]:
            # constraint: d_u >= a * d_v + b
            nd = a * dv + b
            if nd > d[u]:
                d[u] = nd
                if d[u] > X:
                    return None
                if not inq[u]:
                    q.append(u)
                    inq[u] = True

    total = sum(d)
    if total > X:
        return None
    return d

def solve():
    t = int(input())
    for _ in range(t):
        n, m, X = map(int, input().split())
        edges = [[] for _ in range(n)]

        for _ in range(m):
            u, v, a, b = map(int, input().split())
            u -= 1
            v -= 1
            edges[v].append((u, a, b))

        lo, hi = 0, 10**18
        best = None

        while lo <= hi:
            mid = (lo + hi) // 2
            res = check(n, edges, X, mid)
            if res is not None:
                best = res
                lo = mid + 1
            else:
                hi = mid - 1

        if best is None:
            print(-1)
        else:
            print(*best)

if __name__ == "__main__":
    solve()
```この実装では、逆隣接形式で制約をエンコードするため、各ノードは値が変更されたときに入ってくる影響のみを検査する必要があります。 BFS キューにより、増加が安定するまで確実に伝播されます。 

機能`check`固定最小しきい値に対する最小実現可能ベクトルを計算します。 値を超えた場合の早期停止条件$X$不要な伝播を防ぎます。 次に、二分探索により、可能な最大の最小値が確実に見つかります。 

微妙な点は、常に更新されたノードからのみ伝播することです。 なしで`inq`ガードしないと、キューが過度に増大し、変更されていないノードが繰り返し再処理される可能性があり、パフォーマンスが大幅に低下する可能性があります。 

## 実用的な例

 3 つのノードと単純な線形依存関係を持つ小規模システムを考えてみましょう。 

入力：```
3 2 100
1 2 1 0
2 3 1 0
```制約を次のように解釈します。$d_1 \ge d_2$、$d_2 \ge d_3$, 総額制限あり。 

二分探索をします$T$。 

のために$T = 10$:

 | ステップ | キュー | 更新されたノード | 値 (d1,d2,d3) |
 | --- | --- | --- | --- |
 | 初期化 | 0、1、2 | なし | (10,10,10) |

 | リラックス1→2 | 1 | d1=10≧10 | (10,10,10) |

 合計は 30 です。実現可能です。 

のために$T = 40$:

 | ステップ | キュー | 更新されたノード | 値 (d1,d2,d3) |
 | --- | --- | --- | --- |
 | 初期化 | 0、1、2 | なし | (40,40,40) |

 合計は 120 > 100 であり、実行不可能です。 

これは、二分探索が全体和に基づいて実現可能性を正しく区別していることを示しています。 

トレースは、しきい値が固定されると、伝播によって相対的な構造は変化せず、絶対的なスケーリングのみが変化することを確認します。
