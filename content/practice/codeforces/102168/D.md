 ## 解決策
 ## 問題の理解

 文字列があります`s`長さの`n`。 あらゆるポジションについて`i`, Vasya は、位置の文字を正確に削除して得られた文字列を書き込みます。`i`。 結果として得られるすべての文字列には長さがあります`n - 1`、そしてタスクはこれらが何個あるかを数えることです`n`実際は文字列が違います。 

入力には 1 つのラテン語の小文字文字列が含まれています。 その長さは 2 ～ 200,000 であるため、アルゴリズムは次の値に比例して作業を実行します。`n^2`あまりにも高価すぎる。 位置が 200,000 ある場合、単純な 2 次ループでも最悪の場合約 400 億回の反復が必要となり、2 秒の制限には収まりません。 線形または線形に近い解決策が必要です。 

微妙な点は、2 つの異なる削除位置によってまったく同じ文字列が生成される可能性があることです。 たとえば、`aaa`、3 つの文字のいずれかを削除すると、`aa`したがって、答えは 3 ではなく 1 です。単に削除位置を数える不用意な解決策は、このケースでは失敗します。 

もう一つの境界ケースは、`ab`。 最初の文字を削除すると、`b`、2番目の与えるものを削除しながら、`a`したがって、答えは 2 です。誤って隣接する位置のすべてのペアを同等のものとして扱う実装では、誤って 1 が返されます。 

より長い例は次のとおりです`aabb`。 最初の文字からいずれかの文字を削除する`aa`与える`abb`、最終的な文字からいずれかの文字を削除します。`bb`与える`aab`。 答えは 2 です。文字の同等性は、2 つのエンドポイントだけでなく、2 つの削除位置の間の間隔全体にわたって重要です。 

## アプローチ

 直接的なアプローチは、削除された可能性のあるすべての位置に対して結果の文字列を構築し、結果の文字列をすべてセットに入れることです。 これは正しいです。生成されたすべての文字列が Vasya の 1 日を正確に表し、セットによって重複が削除されるからです。 ただし、1 つの結果を構築するにはコストがかかります`O(n)`、そして、あります`n`削除の可能性、与える`O(n^2)`時間。 のために`n = 200000`これは、文字列とセットのオーバーヘッドを考慮する前の、およそ 400 億文字の操作に相当します。 

有益な観察は、実際にはこれらの文字列を構築する必要がないということです。 2 つの削除位置を検討します`i < j`。 ポジション前`i`、結果として得られる両方の文字列には、まったく同じプレフィックスが含まれています。 ポジション後`j`、両方にまったく同じサフィックスが含まれています。 唯一異なる可能性がある部分は、からの間隔です。`i`を通して`j`。 

削除中`i`葉```
s[i+1] s[i+2] ... s[j]
```その間隔から削除しながら`j`葉```
s[i] s[i+1] ... s[j-1]
```これら 2 つの文字列が等しいためには、間隔内のすべての文字が`s[i..j]`同じでなければなりません。 1 文字でも異なる場合は、結果として得られる 2 つの文字列の対応する位置が異なります。 

これにより、ポジションの削除という非常に単純な等価性ルールが得られます。`i`そして`j`間のすべての文字が等しい場合、まったく同じ文字列が生成されます。 言い換えれば、等しい文字の 1 つの最大ランに属するすべての位置は、そのランから 1 つの文字が削除されると同じ結果を生成します。 

のために`aabb`、ランは`aa`そして`bb`したがって、結果として 2 つの異なる文字列が得られます。 のために`abca`、すべての文字が独自の実行を形成するため、4 つの異なる結果が得られます。 のために`zzz`、実行は 1 回だけであるため、削除するたびに同じ文字列が生成されます。 

したがって、答えは単に同じ文字の最大連続実行数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | 最悪の場合は O(n²) | 遅すぎる |
 | 等しい文字の実行をカウントする | O(n) | O(1) 補助スペース | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります`s`答えは 1 から始めてください。`n >= 2`、少なくとも 1 つの削除結果が存在し、最初の文字が最初の実行を開始します。 
2. 文字列を 2 文字目から最後までスキャンします。 いつでも`s[i]`とは異なります`s[i - 1]`、新しい最大値の実行が始まるので、答えを増やします。 
3. 次の位置を無視します。`s[i] == s[i - 1]`。 これらは同じ実行に属しており、その実行から任意の 1 文字を削除すると、同じ結果の文字列が得られます。 
4. 実行回数を出力します。 

### なぜ効果があるのか

 文字列を等しい文字の最大のランに分割します。 2 つの削除位置が同じランに属しているとします。 それらの間のすべての文字は同一であるため、削除をある位置から別の位置に移動しても、結果の文字列は何も変わりません。 したがって、1 つの実行内のすべての位置は 1 つの異なる結果に対応します。 

ここで、2 つのポジションが異なるランに属していると仮定します。 それらの間には、連続する 2 つの文字が異なる境界があります。 一方の結果は境界の一方の側で文字をシフトし、もう一方の結果はシフトしないため、2 つの削除結果はその境界で異なります。 したがって、異なる実行の位置から同じ文字列を生成することはできません。 

したがって、最大の等しい文字の実行ごとに異なる結果の文字列が 1 つだけ存在し、それらの実行をカウントすることで必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_string(s: str) -> int:
    answer = 1

    for i in range(1, len(s)):
        if s[i] != s[i - 1]:
            answer += 1

    return answer

def main() -> None:
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```の`solve_string`関数は実行カウント アルゴリズムを直接実装します。 初期値`answer = 1`入力の長さが少なくとも 2 であるため、文字列には常に少なくとも 1 つの実行があるため、これは有効です。 

インデックス 0 には比較する前に文字がないため、ループはインデックス 1 から始まります。 からのすべての変更`s[i - 1]`に`s[i]`新しい実行を開始し、新しい個別の削除結果を 1 つだけ提供します。 

削除後に取得した文字列を構築する必要はなく、セットも必要ありません。 Python の整数は、最大でも次の値であるため、この答えには十分です。`n`、わずか 200,000 です。 

の`strip()`call は、標準入力によって提供される改行を削除します。 文字列には小文字のラテン文字のみが含まれているため、誤って削除される可能性のある意味のあるスペースはありません。

 ## 特殊なケース

 のために`aa`、アルゴリズムは次から始まります`answer = 1`。 インデックス 1 では、現在の文字も`a`したがって、答えは 1 のままです。考えられる 2 つの削除は両方とも次のようになります。`a`これは、最小サイズの等しい文字の場合の処理​​を確認します。 

のために`ab`、最初の答えは 1 で、インデックス 1 での比較により次のことがわかります。`b != a`、答えは 2 に増えます。2 つの削除結果は次のとおりです。`b`そして`a`、したがって、それらは純粋に異なります。 

のために`aaaa`、スキャンでは、前の文字と異なる文字が検出されることはありません。 答えは 1 のままで、4 つの位置のいずれかを削除すると次の結果が得られるという事実と一致します。`aaa`。 

のために`aabbbaa`、スキャンでトランジションが確認されます。`a -> b`そして`b -> a`。 1 から開始すると、これら 2 つの遷移により、答えは 3 になります。実行は次のとおりです。`aa`、`bbb`、 そして`aa`であり、各実行は正確に 1 つの異なる文字列に対応します。 

最大長の代替文字列の場合`abab...ab`、すべての隣接するペアは異なります。 答えは最初の位置以降のすべての位置で増分され、200,000 が生成されます。 これにより、答えの上限と、ループ内にオフバイワンエラーがないかの両方がチェックされます。 

ソリューション全体の背後にある重要なエッジ ケースは、同じ等しい文字列内の削除位置のペアです。 のために`aabb`、最初の文字からいずれかの文字を削除します`aa`生成する`abb`。 アルゴリズムは、その実行全体を 1 回だけカウントします。 1 回目から 2 回目に移行すると、キャラクターが から変わります。`a`に`b`, したがって、答えは 2 に増加し、結果として得られる 2 つの異なる文字列と正確に一致します。
