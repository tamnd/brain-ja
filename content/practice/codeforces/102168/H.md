 ## 問題の理解

 私たちは持っています`n`人と2種類のベッド。 がある`a`誰でも一人で寝られるシングルベッドと、`b`ダブルベッド、2人でベッドを共有できます。 各人物はバイナリ値で記述されます。 価値のある人`1`価値のある人がダブルベッドを他の人と共有することに同意する`0`共有することを拒否し、一人でしか寝られません。 

割り当てが存在する場合は、それを構築する必要があります。 各ベッドには 1 名様または`0`、各ダブルベッドには 0 名、1 名、または 2 名が宿泊できます。 人物は 1 回だけ出現する必要があり、`0`ダブルベッドに他の人と一緒に寝てはいけません。 

制約により、最大で`200000`人々とそれまで`200000`ベッド合計。 したがって、ソリューションは線形または線形に近いものになる必要があります。 二次関数の何か`n`すでに必要になる可能性があります`4 * 10^10`2 秒の制限をはるかに超える上限での操作。 また、互換性ルールには 2 つのカテゴリしかなく、すべての意欲的な人は他のすべての意欲的な人と互換性があるため、ここで複雑なグラフ アルゴリズムを使用する理由もありません。 

いくつかの境界ケースは誤って処理されやすいものです。 考慮する```
1 0 1
0
```答えは`YES`、ダブルベッドが備わっています。`0 0`, なぜなら、一人では共有できず、シングルベッドがないため、実際にはこのケースは`NO`。 ダブルベッドを 2 つの独立した場所があるものとして扱う不用意な実装は、誤って人をそこに一人で置く可能性があります。 

ここで考えてみましょう```
2 1 0
00
```答えは`NO`、両方ともシングルベッドが必要ですが、存在するのは 1 つだけであるためです。 物理的な寝姿勢の合計が少なくとも次のとおりであることを確認するだけです。`n`ダブルベッドの位置を個別にカウントすると不十分になります。 

別の境界ケースは次のとおりです。```
3 1 1
011
```これは実現可能です。 人`1`シングルベッドを使用しなければなりません。`2`そして`3`ダブルベッドを共有できます。 意欲のある人を最初にシングルベッドに貪欲に配置する実装では、有効な割り当てが存在する場合でも、意欲のない人が場所を失ってしまう可能性があります。 

最後に考えてみましょう```
3 0 2
111
```これは実現可能です。 ダブルベッド 1 台には 2 人が宿泊でき、もう 1 台には 1 人が宿泊できます。 ダブルベッドは完全に埋まる必要はないため、すべてのダブルベッドにちょうど 2 人を収容することを要求することは、有効な取り決めを拒否することになります。 

## アプローチ

 ブルートフォースソリューションでは、ベッドへの人々の可能な割り当てを試し、すべての割り当てが共有ルールを遵守しているかどうかをチェックできます。 検索を大幅に簡素化し、シングルベッドを占有している人だけを選択したとしても、すでに`2^n`可能なサブセット。 のために`n = 200000`、つまりおおよそ`2^200000`それは数え切れないほどの可能性です。 完全なペアを列挙しようとするとさらに悪いことになります。 

なぜ総当たりが不要なのかというと、相性関係が極めて単純だからである。 持っている人`0`制限は 1 つだけあります。それは、ダブルベッドを共有できないことです。 持っている人`1`ダブルベッドの上に置く場合には制限はありません。 したがって、すべての`0`シングルベッドを予約する必要があります。 このような人々が全員配置されると、残りの全員が喜んで共有するため、残りの容量を貪欲に埋めることができます。 

これにより、直ちに 2 つの実現可能条件が得られます。 まず、やる気のない人の数はこれを超えることはできません`a`なぜなら、それぞれに個別のシングルベッドが必要だからです。 第二に、人の総数は、睡眠場所の総数を超えることはできません。`a + 2b`。 これらの条件も十分です。 乗り気でない人全員をシングルベッドに入れ、次に残りのシングルベッドを乗り気のある人に使用し、最後に残りの乗り気な人全員を一度に 2 台のダブルベッドに分配します。 

重要な観察は、異なる意欲的な人々の間には相互作用が存在しないということです。 希望しない人全員がシングルベッドで保護されたら、残りの 2 人は互換性があるため、以前の選択を再検討する必要はありません。

 | ブルートフォース | O(2^n) 以上 | O(n) | 遅すぎる |
 | 貪欲な建設 | O(n + a + b) | O(n + a + b) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`a`、`b`そして文字列に従って人々を 2 つのグループに分けます。 構築が各カテゴリを直接処理できるように、不本意な人々と意欲的な人々のインデックスを保存します。 
2. 不本意な方が多い場合`a`、印刷`NO`。 望まない人は皆、自分専用のシングルベッドを必要とするため、この要件を回避することはできません。 
3. もし`n > a + 2b`、印刷`NO`。 あるのは`a + 2b`実際の睡眠場所、そして誰もがそれらのいずれかを必要とします。 
4. の出力を作成します。`a`シングルベッド。 まず、乗り気でない人全員をシングルベッドに寝かせます。 その後、残ったシングルベッドは希望者に使用していただきます。 
5. まだ割り当てられていない意欲のある人々を採用し、彼らを`b`ダブルベッドは一度に2台。 最後のベッドに希望者が 1 人だけ残っている場合は、その人を 1 つの位置に配置し、`0`もう一方では。 
6. 未使用のシングルベッドポジションごとに、`0`、ダブルベッドの未使用のすべての位置も受け取ります`0`。 印刷する`YES`次に、構築された割り当てが続きます。 

### なぜ効果があるのか

 不変条件は、シングル ベッドを共有する必要がないため、既にシングル ベッドに割り当てられているすべての人が永続的に安全であるということです。 さらに重要なことは、望ましくない人がすべて割り当てられた後、割り当てられていないすべての人が喜んで共有することです。 したがって、ダブルベッド用に選択されたどのペアも有効です。 

シングルベッドよりもベッドを希望しない人の方が多いという理由でアルゴリズムが拒否した場合、それらの人々全員が個別のベッドを必要とするため、解決策は存在しません。 拒否された場合、次の理由で`n > a + 2b`、相性に関係なく物理的に寝る場所が足りません。 逆に、両方の条件が当てはまる場合、希望しない人は全員シングルベッドに収まり、残りの人は全員希望するため、残りのシングルとダブルの定員は全員を配置するのに十分です。 したがって、解が存在する場合にのみ構築が成功します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    s = input().strip()

    unwilling = []
    willing = []

    for i, c in enumerate(s, 1):
        if c == '0':
            unwilling.append(i)
        else:
            willing.append(i)

    if len(unwilling) > a or n > a + 2 * b:
        print("NO")
        return

    single = [0] * a
    double = [[0, 0] for _ in range(b)]

    pos = 0

    # Unwilling people must use single beds.
    for person in unwilling:
        single[pos] = person
        pos += 1

    # Use remaining single beds for willing people.
    wi = 0
    while pos < a and wi < len(willing):
        single[pos] = willing[wi]
        pos += 1
        wi += 1

    # Put the remaining willing people into double beds.
    di = 0
    while wi < len(willing):
        double[di][0] = willing[wi]
        wi += 1

        if wi < len(willing):
            double[di][1] = willing[wi]
            wi += 1

        di += 1

    print("YES")

    for person in single:
        print(person)

    for x, y in double:
        print(x, y)

if __name__ == "__main__":
    solve()
```2 つの配列`unwilling`そして`willing`には、必要な出力番号付けと一致する 1 から始まる人物インデックスが含まれています。 最初の実現可能性チェックは、ダブルベッドを使用できない唯一のタイプの人を保護します。 2 番目のチェックでは、ダブルベッドごとに 2 つの物理的な睡眠場所がカウントされます。 

意図的に加工を施したシングルベッド構造`unwilling`初め。 この順序は本質的な貪欲な選択です。 乗り気でない人が全員宿泊できれば、乗り気な人のためにシングルベッドを使っても問題はありません。その人はダブルベッドを使うこともできたはずですから。 

ダブルベッドのループには 1 人か 2 人の意欲的な人が参加します。 2 番目の位置は、他の人が残っている場合にのみ埋まるため、部分的に占有されている最後のダブルベッドが正しく表現されます。 すべての配列はゼロで初期化され、未使用のベッドに必要な表現が自動的に与えられます。 

Python には整数オーバーフローの問題はなく、固定幅の整数を使用する言語でも、関連する最大の式が存在します。`a + 2b`、周りだけです。`600000`。 インデックス作成には、`enumerate(s, 1)`個人番号が正確に必要なものになるように`1`を通して`n`。

## テストケース

 有効なソリューションの出力は一意ではないため、テスト ハーネスは、生成された割り当てを 1 つの固定文字列と比較するのではなく、検証する必要があります。 次のテストでは、同じ構築ロジックを使用して、出力のセマンティック要件を検証します。```python
import sys
import io

def solve_data(inp: str) -> str:
    data = inp.split()
    it = iter(data)

    n = int(next(it))
    a = int(next(it))
    b = int(next(it))
    s = next(it)

    unwilling = []
    willing = []

    for i, c in enumerate(s, 1):
        if c == '0':
            unwilling.append(i)
        else:
            willing.append(i)

    if len(unwilling) > a or n > a + 2 * b:
        return "NO\n"

    single = [0] * a
    double = [[0, 0] for _ in range(b)]

    pos = 0
    for person in unwilling:
        single[pos] = person
        pos += 1

    wi = 0
    while pos < a and wi < len(willing):
        single[pos] = willing[wi]
        pos += 1
        wi += 1

    di = 0
    while wi < len(willing):
        double[di][0] = willing[wi]
        wi += 1

        if wi < len(willing):
            double[di][1] = willing[wi]
            wi += 1

        di += 1

    out = ["YES"]
    out.extend(map(str, single))
    out.extend(f"{x} {y}" for x, y in double)
    return "\n".join(out) + "\n"

def run(inp: str) -> str:
    return solve_data(inp)

def validate(inp: str, out: str) -> bool:
    data = inp.split()
    n, a, b = map(int, data[:3])
    s = data[3]

    lines = out.strip().splitlines()

    if not lines:
        return False

    if lines[0] == "NO":
        zeros = s.count('0')
        return zeros > a or n > a + 2 * b

    if lines[0] != "YES":
        return False

    if len(lines) != 1 + a + b:
        return False

    used = []

    for i in range(1, 1 + a):
        x = int(lines[i])
        if x != 0:
            if not (1 <= x <= n):
                return False
            used.append(x)

    for i in range(1 + a, 1 + a + b):
        x, y = map(int, lines[i].split())

        if x != 0:
            if not (1 <= x <= n):
                return False
            if s[x - 1] == '0' and y != 0:
                return False
            used.append(x)

        if y != 0:
            if not (1 <= y <= n):
                return False
            if s[y - 1] == '0' and x != 0:
                return False
            used.append(y)

    return sorted(used) == list(range(1, n + 1))

# All unwilling people exactly fit into single beds.

# Physical capacity is enough, but there are too many unwilling people.

assert not validate(case4, run(case4)), "too many unwilling people"

# Maximum-size style test with all willing people.
n = 200000
case5 = f"{n} 0 {n // 2}\n" + "1" * n + "\n"
assert validate(case5, run(case5)), "large input"

 ## 特殊なケース

 最初のエッジケースは、シングルベッドがないときに共有することを拒否する人です。 のために```
1 0 1
0
```望まない人の数は`1`、 その間`a = 0`。 アルゴリズムは最初の実現可能性チェックに失敗し、出力されます。`NO`。 ダブルベッドは、誰かと一緒にそこに置くと制限に違反するため、この人を救うことはできませんが、問題のあるダブルベッドの位置が使用されておらず、その人が占有していない場合にのみ、単独で置くことが許可されます。 したがって、その人には合法的なベッドがありません。 

2 番目のエッジ ケースは、総物理容量は十分であるにもかかわらず、シングル ベッドの容量が不十分です。 のために```
2 1 0
00
```乗り気でない人が 2 人いて、シングルベッドが 1 台しかありません。 小切手`len(unwilling) > a`と評価される`2 > 1`、アルゴリズムは次のように出力します`NO`。 ベッドの位置の合計だけを数えると、次のようになります。`1`したがって、このケースでは、互換性の制限を忘れたソリューションが捕捉されます。 

3 番目のエッジケースは、意欲的な人がダブルベッドに一人で放置されるケースです。 のために```
3 1 1
011
```人`1`唯一のシングルベッドを占有します。 人`2`そして`3`二人とも喜んでダブルベッドの 2 つの位置を占めています。 代わりに、ダブルベッド 2 台を希望する人が 4 人いた場合、アルゴリズムは両方のベッドを完全に満たします。 参加希望者が 3 人で、ダブルベッドが 2 台ある場合、最後のベッドには 1 人が 1 人、ゼロが 1 人になります。 残りの人が喜んで共有するので、これは合法です。 

4 番目のエッジ ケースは、正確な総容量です。 のために```
4 1 2
0001
```合計の物理的容量は`1 + 2 * 2 = 5`、4人には十分ですが、乗り気でない人が3人いて、シングルベッドが1つしかありません。 最初のチェックでは、構築前にインスタンスが拒否されます。 これは、総容量だけでは十分な実現可能性条件ではない理由を示しています。 

最後のエッジケースは、ベッド在庫の空の部分または未使用の部分です。 のために```
