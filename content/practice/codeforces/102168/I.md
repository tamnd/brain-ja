 ## 解決策
 ## 問題の理解

 あります`n`時系列に並べられたコンテスト。 コンテスト用`i`、`a[i]`参加することで得られる評価上昇です。 コンテスト参加後`i`、キリルは次をスキップする必要があります`b[i]`コンテストのため、彼が参加できる最も早いコンテストは、`i`は`i + b[i] + 1`。 

課題は、回復間隔が重ならない一連のコンテストを選択し、その合計を最大化することです。`a[i]`価値観。 以来`a[i]`否定的な場合もあり、空の選択肢も関係します。キリルは単にコンテストに参加せず、利益を得ることができます。`0`。 

と`n <= 200000`、`O(n^2)`解決策は遅すぎます。 最悪の場合、約`200000^2 / 2 = 20,000,000,000`状態遷移は 2 秒の制限に収まりません。 線形時間に近いアルゴリズムが必要です。 

の値`a[i]`到達できる`10^9`どちらの方向でも、回答には多くのコンテストからの投稿を含めることができます。 32 ビット整数では十分ではありません。答えは次のとおりです。`2 * 10^14`規模的には。 Python の整数はこれを自動的に処理しますが、C++ などの言語はこれを行う必要があります。`long long`。 

直接的な実装が間違っている可能性がある境界ケースがいくつかあります。 コンテストが 1 つしかない場合、たとえば```
1-10 0
```答えは`0`、 ない`-10`, なぜなら参加は任意だからです。 もし`b[i] = 0`、次のコンテストがすぐに利用可能になります。 例えば、```
25 07 0
```答えがあります`12`、だから治療します`b[i]`あたかもコンテストが含まれているかのように`i + 1`誤って 2 回目のコンテストを禁止することになります。 

もう 1 つの境界は、回復期間が残りのシーケンス全体を超えて延長される場合です。 のために```
210 5100 0
```答えは`100`。 コンテスト 1 の後には使用可能なコンテストは残りませんが、だからといってコンテスト 1 が必須になったり、コンテスト 2 よりも優先されるわけではありません。 

最後に、否定的なコンテストに対して、それを強制的に受け入れるべきではありません。 のために```
3-5 0-2 0-7 0
```答えは`0`。 コンテストを受けられない可能性を明示的に示さずに負の無限大に初期化された DP は、暗黙のうちに否定的な答えを生成する可能性があります。 

## アプローチ

 簡単な解決策は、考えられるすべての最後のコンテストを考慮します。 私たちがそのコンテストを決めたとします`i`これが私たちが参加する最後のコンテストです。その後、以前に選択したすべてのコンテストがその前に終了する必要があります。`i`、その前にすべての有効なサブセットを再帰的に列挙できます。 すべての有効なスケジュールには明確に定義された最後のコンテストがあるため、これは正しいですが、サブセットの数は指数関数的であるため、このアプローチは、`n = 200000`。 

動的プログラミングを使用すると、総当たりのアイデアをより構造化できます。 させて`dp[i]`最初ののみを使用して得られる最大の評価増加になります。`i`コンテスト。 コンテスト処理時`i`、可能性は正確に 2 つあります。 私たちはそれをスキップして去ります`dp[i - 1]`。 または、私たちはそれに参加します。その場合、以前に選択したコンテストが最大でも嘘でなければなりません`b[i] + 1`前の位置`i`。 最初の場合`i`コンテストには次からの番号が付けられます`1`、回復期間の前に利用できる最後のコンテストは次のとおりです。`i - b[i] - 1`。 

したがって、コンテストを受けることで得られる価値は`i`は`a[i] + dp[i - b[i] - 1]`。 

重要な観察は、`dp`考えられるすべてのプレフィックスに対する最適な答えがすでに含まれています。 以前のスケジュールを個別に確認する必要はありません。 禁止された間隔の前の履歴全体は 1 つの数字で要約できます。 

これにより再発が得られます`dp[i] = max(dp[i - 1], a[i] + dp[max(0, i - b[i] - 1)])`。 

の`max(0, ...)`コンテストのケースを扱う`i`配列の先頭より前に移動するように強制されます。 繰り返しでは各コンテストを 1 回検査するため、合計の作業は直線的になります。

 ## アルゴリズムのチュートリアル

 1.作成`dp`どこ`dp[i]`最初から得られる最高の評価増加を表します`i`コンテスト。 セット`dp[0] = 0`なぜなら、コンテストを考慮する前は利益がゼロだからです。 
2. コンテストを左から右に処理します。 コンテスト用`i`、まずスキップすることを検討してください。 その場合の最良の結果はまさに`dp[i - 1]`。 
3. コンテストに参加する場合`i`、次はスキップしなければなりません`b[i]`コンテスト。 禁断のインターバル直前の勝負は`i - b[i] - 1`。 したがって、最も互換性のある以前の結果は次のとおりです。`dp[max(0, i - b[i] - 1)]`。 
4.追加`a[i]`その互換性のあるプレフィックス結果に。 これにより、選択したコンテストに含まれる最適なスケジュールが得られます。`i`。 
5. スキップ ケースと参加ケースの大きい方を次の場所に保存します。`dp[i]`。 すべてのコンテストを処理した後、`dp[n]`可能な最大の評価増加です。 

### なぜ効果があるのか

 最初のスケジュールの中から最適なスケジュールを検討します。`i`コンテスト。 コンテストが含まれていない場合`i`、その値は最大でも`dp[i - 1]`、 そして`dp[i - 1]`はそのような最適なスケジュールを表します。 コンテストが含まれている場合`i`、選択された他のすべてのコンテストは最初のコンテストに属している必要があります`i - b[i] - 1`コンテスト。 の定義によれば、`dp`、最も互換性のある早いスケジュールには価値があります`dp[max(0, i - b[i] - 1)]`。 追加`a[i]`可能な限り最善のスケジュールを提供します。`i`。 これら 2 つのケースはすべての有効なスケジュールをカバーするため、それらの最大値を取得すると、すべてのプレフィックスに対する真の最適値が得られます。 誘導により、`i`、`dp[n]`が最適です。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())
    dp = [0] * (n + 1)
    for i in range(1, n + 1):        a, b = map(int, input().split())
        previous = i - b - 1        if previous < 0:            previous = 0
        take = a + dp[previous]        skip = dp[i - 1]
        dp[i] = max(skip, take)
    print(dp[n])

if __name__ == "__main__":    solve()
```配列`dp`余分な位置を 1 つ使用するため、`dp[0]`は当然空のプレフィックスを表します。 コンテストにて`i`、`previous = i - b - 1`コンテストと一緒に使用できる最大のプレフィックスです`i`。 

1 を引くことが主要なインデックス作成の詳細です。 もし`b = 0`、コンテスト`i - 1`は許可されるため、プレフィックスは次で終わる必要があります`i - 1`。 式は正確に与えます`i - 0 - 1 = i - 1`。 もし`b = 1`、コンテスト`i - 1`はスキップする必要があるため、使用可能なプレフィックスは次で終わります。`i - 2`。 

いつ`previous`はネガティブです。単に先行できるコンテストがありません`i`、 そして`dp[0] = 0`その状況を表しています。 Python の任意精度の整数は、おおよその合計も安全に処理できます。`200000 * 10^9`。 

入力は次のように処理されます`sys.stdin.readline`これにより、入力全体をトークンの大きなリストに繰り返し分割するオーバーヘッドが回避されます。

 ## 特殊なケース

 ### 単一のネガティブなコンテスト

 のために```
1-10 0
```初期状態は`dp[0] = 0`。 唯一のコンテストに参加すると得られるもの`-10`、スキップしながら、それは与えます`0`、 それで`dp[1] = 0`。 アルゴリズムは、少なくとも 1 つのコンテストを選択する必要があるとは決して想定しません。 

### 回復期間なし

 のために```
25 07 0
```コンテスト 1 には`previous = 0`、与える`dp[1] = 5`。 コンテスト 2 では、`previous = 1`、 なぜなら`2 - 0 - 1 = 1`。 そのテイク値は`7 + dp[1] = 12`、したがって、答えは次のとおりです`12`。 これはまさに、次の場合に必要な境界動作です。`b[i] = 0`。 

### 最初からの回復

 のために```
210 5100 0
```コンテスト 1 には`previous = -5`に固定されています。`0`。 それを取ると得られる`10`。 コンテスト 2 では、`previous = 1`、与える`100 + dp[1] = 110`自身の回復値がゼロだからだ。 したがって、答えは実際には`110`、コンテスト 2 はコンテスト 1 の後に受講できるため、`b[1]`コンテスト 1 に続くものにのみ影響し、コンテスト 2 に先行するものには影響しません。この区別こそが、DP が検討中のコンテストから遡って検討する理由です。 

### すべての値が負です

 のために```
3-5 0-2 0-7 0
```毎`take`値が負の場合、`skip`残る`0`。 したがって、DP はアレイ全体でゼロのままになります。 これは、評価の増加がオプションであるという事実を処理します。 

### 非常に大きな正の値

 多くの互換性のあるコンテストが`a[i] = 10^9`。 と`200000`コンテスト、合計が到達可能`2 * 10^14`。 このスケールでは反復自体は変わりませんが、32 ビット整数を使用した実装ではオーバーフローが発生します。 Python の整数型ではこの問題が回避されるため、同じ繰り返しが入力範囲全体に対して引き続き有効になります。
