 ## 問題の理解

 空ではない小文字の文字列が 2 つあります。`s`そして`t`。 1 回の操作で、任意の 2 つの位置を選択できます。`s`そしてそれらの間の部分文字列全体を反転します。 操作は 0 回を含め、何度でも実行できます。 タスクは、次のことを判断することです。`s`正確に変換できます`t`。 

重要な問題は、どの個別の反転を実行するかではなく、繰り返しの反転によってどのような文字の再配置が可能になるかということです。 どちらの文字列にも最大 200,000 文字が含まれるため、多くの可能性のある反転シーケンスを検査するアルゴリズムは機能しません。 2 秒の制限があるため、目的のソリューションでは文字列の長さが本質的に線形である必要があります。 二次アルゴリズムではすでに最大サイズで約 400 億回の基本反復が必要ですが、これは実用的なレベルをはるかに超えています。 

最初のエッジケースは長さが異なります。 例えば、`s = "abcd"`そして`t = "abc"`生産しなければならない`NO`。 反転によって文字数が変更されることはありません。そのため、最初に長さを考慮せずに文字の頻度のみを比較するアプローチでは、これを明示的に処理する必要があります。 

2 番目の特殊なケースは、文字が繰り返される場合です。 のために`s = "xxx"`そして`t = "yyy"`、答えは`NO`両方の文字列の長さが同じであっても。 長さだけをチェックするような不注意な解決策では、受け入れられてしまいます。 文字の多重度が重要です。 

3 番目のエッジ ケースは、文字列が等しい必要がない、または 1 回の反転で取得できる必要がないことです。 のために`s = "abac"`そして`t = "acba"`、答えは`YES`。 変換は数回の逆転によって達成できるため、次のことをテストします。`t`ちょうど 1 つだけ反転した部分文字列から離れています`s`では不十分です。 

4 番目のエッジ ケースは、すでにターゲットと等しい文字列です。 例えば、`s = "abc"`そして`t = "abc"`生産しなければならない`YES`ゼロ操作の実行が許可されているためです。 少なくとも 1 回の反転が必要であると想定する実装では、この有効なケースが拒否される可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、文字のあらゆる配置が到達可能な状態の候補として扱われます。 それぞれの状態について、可能な限りの逆転を試み、次のいずれかになるまで探索を続けることができます。`t`が見つかるか、到達可能な取り決めがすべて使い尽くされてしまいます。 すべての合法的な操作が明示的に表現されているため、これは正しいのですが、すぐに使用できなくなります。 と`n`明確な文字が存在する可能性があります`n!`さまざまな順列、さらには 1 つの順列を照合することもできます。`t`費用`O(n)`。 したがって、完全な順列ベースの検索には少なくとも次のものが必要です。`O(n · n!)`追加で作業します`O(n^2)`すべての状態がすべての可能な反転間隔を明示的に検査する場合の係数。 

有益な観察は、可能な限り最小の反転を考慮することから得られます。 長さ 2 の部分文字列を反転すると、次の位置に配置されます。`i`そして`i + 1`キャラクターを交換するだけです。 つまり、許可される操作には隣接スワップが含まれます。 

文字列のあらゆる順列を生成するには、隣接するスワップで十分です。 目的の文字を一度に 1 つずつ移動して、目標位置に到達するまで移動し、位置ごとにこのプロセスを繰り返します。 したがって、部分文字列の反転を繰り返すと、文字列が再配置される可能性があります。`s`完全に恣意的な方法で。 

任意の並べ替えが可能になると、元の文字の正確な順序は重要ではなくなります。 唯一不変なのは、各文字が何回出現するかです。 からの変革`s`に`t`は、2 つの文字列の長さが同じで、すべての小文字の頻度が同じ場合に存在します。 

アルファベットには小文字が 26 文字しか含まれていないため、汎用の辞書も必要ありません。 26 個のカウンターの 2 つの配列を保持し、それらを比較できます。 これにより、単純な線形時間の解決策が得られます。

 ## アルゴリズムのチュートリアル

 1.読む`s`そして`t`そしてその長さを比べてみます。 長さが異なる場合は印刷してください`NO`反転によってポジション数が変わることはないため、すぐに実行されます。 
2. 26 個のカウンターの配列を作成します。`s`および 26 個のカウンターの別の配列`t`。 インデックス`0`を表します`'a'`、 索引`1`を表します`'b'`、 等々。 
3.スキャン`s`各文字に対応するカウンタをインクリメントします。 に対しても同じことを行います`t`。 これにより、各文字列にどの文字のマルチセットが含まれるかを正確に記録します。 
4. 2 つの周波数配列を比較します。 すべてのカウントが等しい場合、出力します`YES`; それ以外の場合は印刷します`NO`。 

この周波数テストで十分な理由は、長さ 2 の反転によって隣接スワップが得られるためです。 任意の隣接スワップによってあらゆる順列が生成されるため、同じ文字マルチセットを使用した任意の順序付けに到達できます。 

### なぜ効果があるのか

 すべての操作で文字のマルチセットが保持されるため、異なる周波数を相互に変換することはできません。 逆に仮定すると、`s`そして`t`同一の文字頻度を持ちます。 隣接した交換が許可されているため、並べ替えることができます`s`その文字の任意の順列に変換します。 構築できます`t`隣接するスワップを使用して、必要な文字の出現を各ターゲット位置に移動することにより、左から右に移動します。 部分文字列の反転を繰り返すと、これらの交換が実行される可能性があるため、`t`到達可能です。 したがって、周波数条件は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    if len(s) != len(t):
        print("NO")
        return

    cnt_s = [0] * 26
    cnt_t = [0] * 26

    for ch in s:
        cnt_s[ord(ch) - ord('a')] += 1

    for ch in t:
        cnt_t[ord(ch) - ord('a')] += 1

    print("YES" if cnt_s == cnt_t else "NO")

if __name__ == "__main__":
    solve()
```最初のチェックでは、文字処理の前に長さの境界が処理されます。 これは論理的に必要であると同時に、不可能な入力の場合には若干コストが安くなります。 

入力アルファベットは英小文字に制限されているため、2 つの配列にはちょうど 26 個のエントリがあります。 表現`ord(ch) - ord('a')`各文字を 0 ～ 25 の整数にマップします。 

比較`cnt_s == cnt_t`すべての文字の多重度を同時にチェックします。 反転により順序が任意に変更されるため、位置を比較する必要はありません。 

Python では整数のオーバーフローは発生せず、最大のカウンターはわずか 200,000 です。 弦自体もメモリに快適にフィットします。

    old_stdout = sys.stdout

        sys.stdin = io.StringIO(inp)

        return sys.stdout.getvalue()
    finally:

 ## 特殊なケース

 さまざまな長さについては、次のことを考慮してください。`s = "abcd"`そして`t = "abc"`。 アルゴリズムは比較します`4`そして`3`、すぐに印刷します`NO`、そしてそれらの文字の頻度を比較しようとすることは決してありません。 すべての反転で長さが正確に保持されるため、これは正しいです。 

異なる多重度を持つ文字が繰り返される場合は、次の点を考慮してください。`s = "aabb"`そして`t = "abac"`。 どちらの文字列も長さは 4 なので、長さテストは合格します。 の頻度`a`両方の文字列で 2 ですが、`s`2つ含まれています`b`文字の間`t`1つ含まれています`b`そして1つ`c`。 配列はそれらの位置で異なるため、結果は次のようになります。`NO`。 

複数の反転が必要な変換については、次のことを考慮してください。`s = "abcabc"`そして`t = "ccbbaa"`。 の頻度`a`、`b`、 そして`c`両方の文字列で 2 です。 アルゴリズムは戻ります`YES`特定の反転シーケンスを見つけようとすることなく。 隣接するスワップは任意の順列を実現できるため、上記の証明はそのようなシーケンスが存在することを保証します。 

すでに等しい文字列については、次のことを考慮してください。`s = "abc"`そして`t = "abc"`。 長さが一致し、3 つの文字数がすべて一致するため、結果は次のようになります。`YES`。 これは、許可されるゼロ操作の使用に相当します。 

可能な限り小さい文字列の場合、`s = "a"`そして`t = "b"`意味のある反転を実行するための異なるポジションのペアが存在しないため、まったく変更できません。 それらの周波数は異なるため、アルゴリズムは次の値を返します。`NO`。 のために`s = "a"`そして`t = "a"`、周波数が一致し、アルゴリズムが戻ります。`YES`。 

最大サイズのケースには 200,000 文字が含まれます。 このアルゴリズムは依然として各文字列に対して 1 回のパスを実行し、52 個のカウンターのみを保持するため、リソースの使用量は可能な順列の数に依存しません。 これはまさに、与えられた制約の下でソリューションを実用化するために必要なプロパティです。
