 ## 解決策
 ## 問題の理解

 固定順序で操作を処理しながら、非負の整数のマルチセットを維持します。 追加操作では値が 1 つ挿入されますが、削除操作では現在存在する値が 1 つだけ削除されます。 重複する値は許可されるため、1 つのコピーを削除しても、コピーが 1 つしかない場合を除き、すべてのコピーを削除することはできません。 

すべての操作の後に、現在保存されているすべての値の算術平均が必要になります。 マルチセットが空になった場合、必要な答えはゼロになります。 

直接的な数学的定義は次のとおりです。 

[
 \text{平均}=\frac{\text{すべての要素の合計}}{\text{要素数}}。 
]

 主な難点は、最大 200,000 の操作が存在する可能性があることです。 2 秒の制限がある場合、各操作の後にマルチセット全体をスキャンするアルゴリズムは、(n^2) 個の作業量で実行されます。 (n=200,000) の場合、これは約 400 億の要素訪問に達する可能性があり、これは現実的な数字をはるかに超えています。 各操作は定数または対数の作業のみを必要とする必要があります。 

値 (x) は (10^9) まで大きくなり、同時に 200,000 個の要素が存在する可能性があります。 したがって、それらの合計は (2\cdot10^{14}) に達する可能性があります。 Python の整数はこの範囲を正確に処理し、倍精度浮動小数点数でも (2\cdot10^{14}) より大きい (2^{53}) までのすべての整数を表すことができます。 最後の除算は、(10^{-9}) の必要な相対誤差または絶対誤差に対しても安全です。 

最初のエッジケースは空のマルチセットです。 例えば、```
1
+ 0
```生成する```
0.0
```唯一の要素がゼロだからです。 より一般的には、唯一の要素を追加して削除した後、```
2
+ 5
- 5
```答えは```
5.0
0.0
```ゼロをチェックせずに常に現在のサイズで除算する不注意な実装では、2 番目の演算の後にゼロによる除算が試行されます。 

2 番目のエッジ ケースは、重複した値を含むマルチセットです。 考慮する```
3
+ 2
+ 2
- 2
```正しい出力は次のとおりです```
2.0
2.0
2.0
```削除では 1 つのオカレンスのみが削除されるため、1 つの`2`残っています。 構造体を通常のセットとして扱う実装では、値が完全に削除され、誤ってゼロが報告される可能性があります。 

3 番目のエッジ ケースは大きな値です。 例えば、```
2
+ 1000000000
+ 1000000000
```答えがある```
1000000000.0
1000000000.0
```不必要に狭い整数型を使用した解は、合計の計算中にオーバーフローする可能性があります。 Python の任意精度の整数を使用すると、この問題が回避されます。 

## アプローチ

 ブルート フォース アプローチは、文字通り算術平均の定義に従います。 現在の要素を保持し、要求された挿入または削除を実行してから、残りのすべての要素を反復して合計を計算し、要素の数で除算します。 これは、操作のたびに要求された量を正確に再構築するため、正しいです。 

問題はスキャンの繰り返しです。 マルチセットに、ほとんどの (n) 操作に対しておよそ (n/2) 個の要素が含まれている場合、作業量の合計は 2 次になります。 最悪の場合、訪問される要素の数は次のようになります。 

[
 1+2+\dots+(n-1)=\frac{n(n-1)}2.
 ]

 (n=200000) の場合、この単純なサイズ増加シナリオでも、これは約 200 億の訪問になります。 マルチセットを全体的に大きく保つ構造でも、同じ二次次数を生成できます。 このような解決策では制限時間内に収まりません。 

より高速な解決策を明らかにする観察は、挿入または削除によって 1 か所のみの要素の合計と合計数が変更されるということです。 両方の量に対する他の要素の寄与は変化しないため、他の要素を検査する必要はありません。 

現在の合計が (S)、現在のサイズが (C) であるとします。 (x) を追加すると、(S+x) と (C+1) に変わります。 (x) を 1 つ削除すると、(S-x) と (C-1) に変わります。 答えは (S/C) としてすぐに計算できます。 

実際には、この問題のためにマルチセット全体を保存する必要はありません。 このステートメントは、すべての削除が有効であることを保証するため、(x) が存在するかどうかを検証するためのデータ構造は必要ありません。 必要なのは、合計と要素の数だけです。 重複値も、出現するたびに合計とカウントに独立して寄与するため、特別な処理は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(1)) 補助スペース | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`total = 0`そして`count = 0`。 これらの変数は、現在存在するすべての発生の合計とその合計数を表します。 
2. 次の操作とその値を読み取ります`x`。 操作が`+`、 追加`x`に`total`そして増加します`count`1つずつ。 これは、1 つの新しいオカレンスの挿入を正確に反映しています。 
3. 操作が次の場合`-`、減算`x`から`total`そして減少します`count`1つずつ。 入力により、この発生を削除できることが保証されるため、メンバーシップ チェックや頻度マップは必要ありません。 
4. 操作適用後の確認`count`。 ゼロの場合は出力`0.0`空のマルチセットの算術平均はゼロになるように定義されているためです。 それ以外の場合は出力`total / count`。 
5. すべて (n) の操作に対してこのプロセスを繰り返します。 各演算では一定数の算術演算のみが使用されるため、完全な処理は線形です。 

### なぜ効果があるのか

 不変条件は、処理されたすべての操作の後に、`total`現在マルチセット内にあるすべての出現の合計に等しくなりますが、`count`それらの出現数に等しくなります。 最初は、空のマルチセットでは両方の値が正しいです。 挿入により、合計にちょうど (x) が追加され、カウントにちょうど 1 回の出現が追加されます。 削除により、合計からちょうど (x) が削除され、カウントからちょうど 1 つの出現が削除されます。 したがって、不変式はすべての操作の後でも真のままです。 マルチセットが空ではない場合、`total / count`はまさにその算術平均であり、`count`がゼロの場合、アルゴリズムは別途定義された値ゼロを出力します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    total = 0
    count = 0
    output = []

    for _ in range(n):
        op, x = input().split()
        x = int(x)

        if op == '+':
            total += x
            count += 1
        else:
            total -= x
            count -= 1

        if count == 0:
            output.append("0.0")
        else:
            output.append(str(total / count))

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```2 つの状態変数は、ウォークスルーからの不変条件を直接実装します。`total`要求された平均は現在の操作の前ではなく後のマルチセットに対するものであるため、答えを計算する前に更新されます。 

削除ブランチは使用します`total -= x`そして`count -= 1`。 削除が常に既存の出現を参照することが入力によって明示的に保証されるため、頻度辞書はありません。 不必要な周波数を維持すると、答えに貢献せずにメモリ使用量が増加します。 

の`count == 0`チェックは除算の前に行う必要があります。 この問題では、空のマルチセットの平均がゼロとして明示的に定義されているため、このケースは通常の除算では処理できません。 

Python の整数演算は次のようになります。`total`(2\cdot10^{14}) に達しても正確です。 除算により浮動小数点値が生成されます。 Its relative precision is comfortably within the required (10^{-9}) tolerance for the range of possible answers.

 で答えを集める`output`また、それらを一度書き込むと、ラインごとに個別のシステムレベルの出力操作を実行する必要がなくなります。 これは、回答が 200,000 件ある場合に役立ちます。

 ## 特殊なケース

 空のマルチセットは明示的に処理されます。 入力用```
2
+ 5
- 5
```最初の操作で得られるのは`total = 5`そして`count = 1`、したがって、答えは次のとおりです`5.0`。 2 番目の操作により、状態が次のように変更されます。`total = 0`そして`count = 0`。 除算はスキップされ、アルゴリズムは次のように出力します。`0.0`、空のマルチセットの特別な定義と一致します。 

重複する値は自動的に表されます。`count`個別の数値ではなく、出現回数をカウントします。 のために```
3
+ 2
+ 2
- 2
```州は`(2, 1)`、`(4, 2)`、 そして`(2, 1)`のために`(total, count)`。 あらゆる答えは`2.0`。 等しい値は同じ寄与を持つため、どの物理的な出来事が削除されたかを区別する必要はありません。 

ゼロ値には特別な算術処理は必要ありません。 のために```
2
+ 5
+ 0
```状態はから変わります`(5, 1)`に`(5, 2)`、生産`5.0`そして`2.5`。 ゼロを指定すると、集計表現が予測したとおりに、合計を変更せずに要素の数が増加します。 

Python では、最大値によってオーバーフローが発生することもありません。 と```
2
+ 1000000000
+ 1000000000
```合計は`2000000000`、カウントは次のようになります`2`、与える`1000000000.0`。 このような挿入を 200,000 回行うと、合計は`200000000000000`、Python はこれを正確に表します。 

操作の最大数には、より大きなアルゴリズム構造は必要ありません。 200,000 個の追加があっても、すべての操作は依然として 1 回の更新で構成されます。`total`、への 1 つの更新`count`、そして1つの部門。 合計作業量は直線的に増加します。これが、ソリューションを入力制限に適したものにする特性です。
