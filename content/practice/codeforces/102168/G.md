 ## 問題の理解

 を取り揃えております。`n`表示される値。 最初はボタン`i`ショー`a[i]`、そしてそれを見せたいのです`b[i]`。 ボタンを押す`i`自身の値を変更する`-1`、他のすべての値は によって変化します`+1`。 各ボタンを何回押すかを決定する必要があります。 出力は配列です`c`、 どこ`c[i]`ボタンを押した回数です`i`、 または`-1`有効なシーケンスが存在しない場合。 

決定的な難点は、一度押すとすべてのボタンに影響するため、ボタンが独立していないことです。 直接シミュレーションでは、潜在的に数十億の操作を実行する必要があります。 以来`n`と同じくらい大きいです`200000`、たとえ支出を伴うアルゴリズムであっても`O(n)`印刷機ごとの作業が遅すぎます。 すべてのプレスを代数的に記述し、配列全体を線形時間で処理する必要があります。 

不注意な解決策では見逃される可能性のあるエッジケースがいくつかあります。 1つ目は`n = 1`。 例えば、```
1
3
1
```唯一のボタンは押すたびに減るので正解は`2`。 で割る式`n - 2`導出が不用意に実装された場合にのみ、このケースを別個に扱う必要があります。`-1`、ゼロではありません。

## アプローチ

 簡単なアプローチは、プレスをシミュレートすることです。 現在の値がまだ正しくないボタンを繰り返し選択して押し、すべてを更新することができます。`n`表示される値。 このようなシミュレーションは、ステートメントの操作を正確に再現するため、有効な解決策に従って選択が行われていれば正しいものになります。 問題は操作回数です。 ボタンが 3 つしかない場合でも、合計押下回数は数十億回にも達し、押すたびに 3 つの値がすべて変更されます。 と`n = 3`たとえば、初期値の合計が目標合計と数十億異なる場合があり、同じ次数で必要なプレスの合計数が求められます。 したがって、直接シミュレーションでは次のことが必要になる場合があります。`Θ(nS)`操作、どこで`S`合計プレス数です。 

個々のプレスには単純な決定論的な効果があるため、ブルート フォースは機能しますが、実際にはプレスの順序を知る必要がないため失敗します。 最終的な状態は、各ボタンが押された回数によってのみ異なります。 

させて`S`はプレスの合計数なので、`S = c[1] + c[2] + ... + c[n]`。 

特定のボタンを 1 つ考えてみましょう`i`。 押されている`c[i]`何度も、そしてそれ以外の毎回`S - c[i]`プレスはそれにプラスの影響を与えます。 したがって、その最終値は次のようになります。`b[i] = a[i] - c[i] + (S - c[i])`。 

並べ替えた後、`b[i] = a[i] + S - 2c[i]`、

それで`c[i] = (a[i] + S - b[i]) / 2`。 

これが重要な削減です。 単一の値がわかったら`S`、それぞれの個別のプレス回数が決定されます。 

入手できます`S`すべてのボタンについての方程式を合計します。 左側はこうなります`sum(b)`、右側は次のようになります。`sum(a) + nS - 2S = sum(a) + (n - 2)S`。 

のために`n != 2`、これは与えます`S = (sum(b) - sum(a)) / (n - 2)`。 

次に、すべてを計算します`c[i]`そしてそれが負でない整数であることを確認してください。 

いつ`n = 2`、の係数`S`消えます。 唯一の不変条件は`sum(b) = sum(a)`。 

その条件が満たされない場合、目標は不可能です。 それが保持されている場合は、`d = b[0] - a[0]`。 

必要です`c[1] - c[0] = d`。 常に最小の非負の解を選択できます。`d >= 0`、 取る`c[0] = 0`そして`c[1] = d`; それ以外の場合は取る`c[0] = -d`そして`c[1] = 0`。 

ケース`n = 1`は一般式にも適用されます。`n - 2 = -1`。 それは与える`S = a[0] - b[0]`、これは、唯一のボタンを押す必要がある正確な回数です。 その値が負の場合にのみ拒否する必要があります。

 | --- | --- | --- | --- |
 | ブルートフォース |`O(nS)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、初期配列`a`、およびターゲット配列`b`。 必要なのはそれらの合計と個々の差だけであるため、線形時間ソリューションには両方の配列を保存するだけで十分です。 
2. もし`n = 2`、まず比較してください`sum(a)`そして`sum(b)`。 押すたびに値が 1 つずつ変化します`-1`そしてもう一つは`+1`なので、合計は不変です。 合計が異なる場合は出力`-1`。 
3. のために`n = 2`等しい合計で計算します`d = b[0] - a[0]`。 もし`d >= 0`、出力`(0, d)`。 それ以外の場合は出力`(-d, 0)`。 どちらの場合も、2 つのプレス回数の差がまさに必要なものとなります。 
4. のために`n != 2`、計算する`S = (sum(b) - sum(a)) / (n - 2)`。 

使用する前に、分割が正確であることを確認してください。 分子が割り切れない場合`n - 2`、整数の合計プレス数は存在できません。 
5. あらゆる人にとって`i`、計算します`c[i] = (a[i] + S - b[i]) / 2`。 

分子は偶数である必要があります。`c[i]`整数でなければなりません。 も必要です`c[i] >= 0`負の回数だけボタンを押すことはできないためです。 
6. 全て出力する`c[i]`すべてのチェックが成功した場合。 値`S`は合計された方程式から導出され、それぞれ`c[i]`ボタンの正確な方程式から導出されました`i`したがって、これらのカウントはターゲットの状態を再現します。 

### なぜ効果があるのか

 しましょう`S`合計プレス数になります。 すべてのボタンについて`i`、 その通り`c[i]`そのうちの 1 回押すと減少し、もう 1 回押すと減少します。`S - c[i]`押すと増加します。 したがって、有効な解決策はすべて次の条件を満たす必要があります。`b[i] = a[i] + S - 2c[i]`。 のために`n != 2`、これらの方程式を合計すると、一意に決定されます。`S`したがって、アルゴリズムは可能な唯一の合計押下数をチェックし、すべての押下を一意に決定します。`c[i]`。 のために`n = 2`、合計された方程式には次の情報が含まれていません。`S`ただし、唯一の不変条件は 2 つの合計が等しいことです。構築されたカウントのペアによって必要な差が実現されます。 その結果、受け入れられた出力はすべてターゲット方程式を満たしますが、拒否されたケースはすべて必要条件に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    sum_a = sum(a)
    sum_b = sum(b)

    if n == 2:
        if sum_a != sum_b:
            print(-1)
            return

        d = b[0] - a[0]

        if d >= 0:
            print(0, d)
        else:
            print(-d, 0)
        return

    numerator = sum_b - sum_a
    denominator = n - 2

    if numerator % denominator != 0:
        print(-1)
        return

    total = numerator // denominator

    if total < 0:
        print(-1)
        return

    ans = []

    for x, y in zip(a, b):
        value = x + total - y

        if value % 2 != 0:
            print(-1)
            return

        c = value // 2

        if c < 0:
            print(-1)
            return

        ans.append(c)

    print(*ans)

if __name__ == "__main__":
    solve()
```最初の部分では、初期配列とターゲット配列の合計を計算します。 これらの合計は、プレスの合計数を決定するのに十分です。`n != 2`。 

の`n == 2`ブランチは分母がゼロになるため、一般式の前に置かれます。 2 つのボタンの場合、押された回数の違いのみが問題になります。 最初の目標値が より大きい場合`d`、2番目のボタンが押されたはずです`d`最初よりも回数が増えました。 1 つのカウントをゼロにすると、有効な最小解が得られます。 

のために`n != 2`、`numerator`は`sum_b - sum_a`そして`denominator`は`n - 2`。 パイソンの`%`演算子を使用すると、使用する前に割り算が正確かどうかをテストできます。`//`。 このチェックが必要なのは、プレスの合計数の小数部を切り捨てると意味のないカウントが生成されるためです。 

表現`x + total - y`まさに`2c[i]`。 除算する前にパリティをチェックすることで、奇数の値が暗黙的に切り捨てられることを防ぎます。 非否定性チェックは、プレス数の物理的な意味を強制します。 

Python の整数には任意の精度があるため、中間合計がそれよりはるかに大きい場合でもオーバーフローのリスクはありません。`10^9`。
