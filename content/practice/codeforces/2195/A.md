 ## 解決策
 ## 問題の理解

 非常に小さな整数のコレクションがいくつか与えられ、各コレクションには最大 5 つの数値が含まれており、その積がちょうど 67 である空ではないサブセットを選択できるかどうかを尋ねられます。 

各テスト ケースは独立しています。 テスト ケース内では、少なくとも 1 つの要素を選択する限り、指定された数値の任意のサブセットを選択することができ、選択したすべての値を掛け合わせます。 問題は、積が正確に 67 に等しいようなサブセットが存在するかどうかです。 

各テスト ケースの数値が最大 5 つであるという制約により、問題の性質が完全に変わります。 サイズ 5 のセットには、$2^5 - 1 = 31$空ではないサブセットなので、すべてのサブセットを強引に列挙することも簡単です。$10^4$テストケース。 これにより、高度な数理論や最適化トリックの必要性が即座に排除されます。 

ターゲット値 67 が素数であるという事実から、微妙な問題が発生します。 これは、有効な選択は正確に 67 まで乗算する必要があることを意味します。そのため、成功する唯一の方法は、積に余分な素因数が含まれず、67 と正確に一致する数値を選択することです。すべての入力値は 1 から 67 までの範囲にあるため、意味のある値に寄与できる数値は 1 と 67 だけです。これは、他のすべての整数には 67 と互換性のない素因数が含まれるためです。 

7 と 9 や 3 と 23 のような組み合わせが何らかの形で 67 になると考えるのは単純な間違いです。67 には 1 より大きい整数に対する非自明な因数分解がないため、これは不可能です。 

もう 1 つの潜在的な落とし穴は、要素を選択しないことが禁止されていることを忘れていることです。 たとえば、67 に等しい要素がなく、すべての要素が 1 である場合、不注意な実装では、空の積を 1 として扱い、「スケールアップ」することで誤って成功と結論付ける可能性がありますが、それは許可されていません。 

エッジケースには次のようなものがあります。 

配列に 67 に等しい 1 つの要素が含まれている場合、答えは明らかに YES です。 

入力：```
1
1
67
```出力：```
YES
```配列に 1 と 2、3、5、7 などの小さな合成数のみが含まれている場合、どの組み合わせも 67 を形成できません。 

入力:```
1
5
1 2 3 4 5
```出力：```
NO
```これは、1 以外の選択では 67 に関係のない要素が導入されるためです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 指定された数値の空でないすべてのサブセットを試し、その積を計算し、それが 67 に等しいかどうかを確認します。$n \le 5$、サブセットは最大 31 個あるため、テスト ケースごとに最大 31 回の乗算になります。 横切って$10^4$テストケース、これはおおよそです$3.1 \times 10^5$制限内で快適に操作できます。 

重要な観察は、完全な積を計算する必要さえないということです。 ターゲットは素数である固定数 67 です。 1 または 67 以外の係数があると、すぐに 67 に達することは不可能になります。これは、単一の 67 を選択できるか、または 1 と 67 のみを組み合わせることができるかどうかを確認するだけでよいことを意味します。1 を乗算しても何も起こらないため、唯一の意味のある要件は、配列内に少なくとも 1 つの 67 が存在することです。 67 が存在する場合、他のすべての数字を無視して、その要素だけを選択できます。 

したがって、問題はサブセットの列挙から単純な存在チェックに縮小されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、番号のリストを読みます。 有効なサブセットには 67 が含まれている必要があり、67 以外の 1 より大きい数値を含めることはできないため、67 が少なくとも 1 回出現するかどうかを判断するだけで済みます。 
2. 配列をスキャンして、67 に等しい要素があるかどうかを確認します。それが見つかった瞬間に、その要素のみを選択することで有効なサブセットが存在することがわかります。 
3. 67 が見つからずにスキャンを終了した場合は、他のすべての数値が 1 であるか、67 を形成できない既約因数が導入されているため、どのサブセットも 67 を生成できないと結論付けます。 

### なぜ効果があるのか

 正しさは 67 の構造から得られます。67 は素数であるため、67 に等しい積は、67 に等しい 1 つの因数と、1 に等しい他のすべての因数で構成されなければなりません。67 自体以外の 1 より大きい整数の組み合わせは、余分な素因数の導入を避けることはできません。 したがって、配列内に数値 67 が存在することは、答えが YES になるために必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    
    ok = False
    for x in arr:
        if x == 67:
            ok = True
            break
    
    print("YES" if ok else "NO")
```このソリューションは各テスト ケースを個別に処理し、最大 5 つの数値に対して線形スキャンを実行します。 早めの休憩により、67 が早く現れた場合でも最小限の作業が保証されます。 

重要な実装の詳細は、積の計算をまったく試みないことです。 これにより、不必要な整数の増加に関する懸念が回避され、ロジックがターゲット値の数学的構造に合わせて維持されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        ok = any(x == 67 for x in arr)
        out.append("YES" if ok else "NO")
    return "\n".join(out)

 ## 特殊なケース

 67 を含む単一要素配列は、最も直接的な成功例です。 アルゴリズムは単一の値を読み取り、直ちに等しいことを検出し、それ以上の作業を行わずに YES を返します。 

1 だけの配列は、掛け算の直感が誤解を招く可能性があるケースです。 たとえサブセット積が 1 であっても、サブセットは 67 に到達できないため、スキャンは 67 を見つけることなく完了し、NO を返します。 

複数の 67 がある場合、たとえば`[67, 67, 1, 1]`、アルゴリズムはカウントを考慮しないため、依然として正しく動作します。 最初の出現により YES がトリガーされ、残りは無関係です。
