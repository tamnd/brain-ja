 ## 解決策
 ## 問題の理解

 それぞれが係数によって定義される二次関数のセットが与えられます。$a_i$、$b_i$、 そして$c_i$。 2 つの関数が交差しない場合、独立していると呼ばれます。これは代数的に、それらの差がゼロにならないことを意味します。 二次関数の場合、$f_i(x) = a_i x^2 + b_i x + c_i$そして$f_j(x) = a_j x^2 + b_j x + c_j$、どちらかの場合に独立が発生します。$a_i \neq a_j$または$a_i = a_j$しかし$b_i = b_j$そして$c_i \neq c_j$。 実際のところ、独立するには次のことが必要です$f_i - f_j = 0$本当の解決策はありません。 

目標は、関数ごとに見つけることです。$f_i$、以下を含む関数の最大サブセットのサイズ$f_i$そして、すべての関数がペアごとに独立しています。 各テスト ケースには関数のリストと次の合計が示されます。$n^2$すべてのテスト ケースでは最大 900 万件です。 これは、余裕があることを意味します$O(n^2)$アルゴリズムはテストケースごとに異なりますが、$O(n^3)$遅すぎるでしょう。 

単純なアプローチでは、すべてのサブセットを試して独立性をチェックする可能性がありますが、これは組み合わせによるものであり、$n$もう 1 つの潜在的な落とし穴は、係数が非常に似ているものの、完全に同じではない関数を混乱させることです。 例えば、$f(x) = x^2 + 2x + 1$そして$g(x) = x^2 + 2x + 2$同じ線形項を共有しているにもかかわらず、どこにも交差しないため、独立しています。 この区別を怠ると、不正確な回答につながる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、以下を含む関数のすべてのサブセットを反復処理します。$f_i$そして、そのサブセットのペアごとの独立性を確認します。 これには生成が必要です$2^{n-1}$サブセットとチェックアップ$\binom{n}{2}$サブセットごとのペア。 たとえ$n=20$、これは不可能になります。 このアプローチは正しいですが、計算的には実行不可能です。 

重要な洞察は、問題を、交差することなく同じ「傾きパターン」を共有する関数の最大数を数えることに減らすことです。 二次関数の場合、2 つの関数の交差はそれらの差の根で発生します。 2 つの関数が依存している (どこかで交差している) のは、それらの関数が同じである場合に限ります。$a$そして判別式$\Delta = (b_i - b_j)^2 - 4(a_i - a_j)(c_i - c_j)$は非負です。 だって全部$a_i \neq 0$主な課題は、実際の違いを生み出すことなく、共存できる機能の数を効率的に数えることです。 

関数をその順に並べ替える$a$係数を計算し、係数の違いによって引き起こされる矛盾を考慮します。$b$そして$c$これを、各関数がノードであり、エッジが 2 つの依存関数を接続するグラフとしてモデル化できます。 次に、問題は、特定のノードを含むこのグラフ内の最大の独立セットのサイズを見つけることに帰着します。 グラフは構造化されているため (二次交差により各連結成分が比較的小さい)、貪欲または動的プログラミングのアプローチを使用して、これを効率的に計算できます。$O(n^2)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、関数の数を読み取ります。$n$とその係数$(a_i, b_i, c_i)$。 
2. を初期化します。$n \times n$ブール行列`conflict[i][j]`かどうかを追跡する$f_i$そして$f_j$交差する。 
3. ペアごとに$i < j$、の判別式を計算します。$f_i - f_j$。 させて$da = a_i - a_j$、$db = b_i - b_j$、$dc = c_i - c_j$。 もし$da = 0$そして$db = 0$、次の場合に関数が交差します。$dc = 0$、これは区別性のために起こり得ません。 それ以外の場合は計算します$\Delta = db^2 - 4*da*dc$。 もし$\Delta \ge 0$、 マーク`conflict[i][j] = conflict[j][i] = True`。 
4. 機能ごとに$f_i$を含む最大のサブセットを計算します。$f_i$衝突はありません。 グラフは比較的まばらであるため、貪欲な動的アプローチを使用します。つまり、競合しないすべての関数をカウントします。$f_i$そして、競合しない近傍を再帰的に含めます。 実際には、これは次のようになります。`count_i = 1 + sum(1 for j if not conflict[i][j])`重複を正しく考慮した後。 
5. テスト ケース内のすべての関数のカウントを出力します。 

機能する理由: 競合グラフは依存関係を正確にエンコードします。 定義上、組織化されたサブセットは、このグラフの独立したセットに対応します。 各関数について、それを含め、競合しない関数をすべて選択すると、競合する関数を追加すると独立性に違反するため、その関数を含む最大の組織化されたサブセットが得られます。 の$O(n^2)$ループは、すべてのペアごとの競合が正しくマークされていることを確認し、正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        funcs = [tuple(map(int, input().split())) for _ in range(n)]
        conflict = [[False]*n for _ in range(n)]
        
        for i in range(n):
            a1, b1, c1 = funcs[i]
            for j in range(i+1, n):
                a2, b2, c2 = funcs[j]
                da, db, dc = a1 - a2, b1 - b2, c1 - c2
                if da == 0 and db == 0:
                    conflict[i][j] = conflict[j][i] = False
                else:
                    delta = db*db - 4*da*dc
                    if delta >= 0:
                        conflict[i][j] = conflict[j][i] = True
        
        res = []
        for i in range(n):
            count = 0
            for j in range(n):
                if i == j or not conflict[i][j]:
                    count += 1
            res.append(str(count))
        print(" ".join(res))

if __name__ == "__main__":
    main()
```このソリューションは、テスト ケースを読み取り、すべての関数をタプルとして保存することから始まります。 競合マトリックスにより、どのペアが交差するかを確実に把握できます。 精度エラーを避けるために、各判別計算は整数演算で行われます。 最終的なカウントは行列上で反復され、関数自体が含まれます。 これにより、off-by-one エラーが回避され、ネストされたループは安全です。$n^2$合計で最大900万です。
