 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられ、特定のタイプのスワップを実行できます。1 から n/2 までの任意のインデックス i について、位置 i の要素を位置 2i の要素と交換できます。 タスクは、このようなスワップを任意の回数実行することによって、配列を昇順にソートできるかどうかを判断することです。 

入力は複数のテスト ケースを表します。 各テスト ケースでは、順列の長さである単一の整数 n が与えられ、その後に 1 から n までの n 個の異なる整数が任意の順序で続きます。 各テスト ケースの出力は、許可された操作を使用して配列を並べ替えることができる場合は「YES」、そうでない場合は「NO」になります。 

制約は重要です。n は最大 200,000 まで、テスト ケースは最大 10,000 まで可能ですが、すべてのテスト ケースにわたる n の合計は 200,000 に制限されます。 これは、テスト ケースごとに n で線形または線形に近い解が必要であることを意味します。 考えられるすべてのスワップをシミュレートする単純なアプローチでは、n が指数関数的となり、完全に実行不可能になります。 

エッジケースは、2i スワップ構造によりターゲット位置に到達できない要素を除いて、配列がほぼソートされている場合に発生します。 たとえば、n=5 の場合、順列が [1,4,2,3,5] の場合、インデックス 2 の要素 4 をインデックス 4 の要素 2 と交換でき、並べ替えが可能になるため、答えは YES です。 しかし、配列が [1,4,2,3,5] の場合、スワップによって到達可能な位置では要素 4 をインデックス 4 の正しい位置に移動させることができないため、答えは NO です。 スワップ グラフ構造を無視する単純なアルゴリズムは、誤って「YES」と判断する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、許可されたスワップのあらゆる可能なシーケンスをシミュレートし、配列がソートできるかどうかを確認することです。 各スワップは位置のペア (i、2i) にのみ影響しますが、スワップのシーケンスは多数考えられます。 n=200,000 の場合、シーケンスの数は天文学的に多くなります。 すべての組み合わせで各スワップを実行することさえ、操作数が指数関数的に増加するため、現実的ではありません。 

重要な洞察は、許可されるスワップを有向グラフとしてモデル化することです。スワップは可逆であるため、インデックス i がインデックス 2i に到達することも、その逆も可能です。 これにより、i=2j として記述できないインデックス (通常は最後のインデックス) をルートとするツリーのフォレストが形成されます。 重要な点は、要素はこれらのスワップによって定義されたインデックスの連結コンポーネント内でのみ移動できるということです。 接続されたコンポーネントがわかったら、ソートされた配列内の位置を占める要素が各コンポーネントに正確に含まれているかどうかを確認できます。 並べ替えは、各コンポーネントにそれらの位置に対するターゲット値の正しいマルチセットが含まれている場合にのみ可能です。 

したがって、最適なアプローチは、スワップ関係に基づいてインデックスの接続されたコンポーネントを特定し、各コンポーネント内の要素のセットをそれらが占めるソートされた位置のセットと比較することです。 このアプローチは、各インデックスが 1 回アクセスされ、コンポーネントのメンバーシップ チェックが線形であるため、n に関して線形時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、n と順列配列 a を読み取ります。 
2. どのインデックスが処理されたかを追跡するために、長さ n のブール値の訪問済み配列を初期化します。 
3. 1 から n までの各インデックス i について、まだアクセスされていない場合は、新しいコンポーネントを開始します。 2 つの空のリストを初期化します。1 つはこのコンポーネントのインデックス用で、もう 1 つはこれらのインデックスの要素用です。 
4. 深さ優先検索または反復走査を使用して、スワップを介して i から到達可能なすべてのインデックスを収集します。 訪問したインデックス j ごとに、訪問済みとしてマークし、j をインデックス リストに追加し、a[j] を要素リストに追加します。 インデックスが範囲内にある限り、インデックスごとに j → 2j 接続と 2j → j 接続を考慮します。 
5. コンポーネントを収集した後、インデックスのリストと要素のリストの両方を並べ替えます。 2 つのリストを要素ごとに比較します。 インデックス リストは特定の数値を含む必要がある位置を表し、要素リストはそれらの位置に実際にある数値を表します。 異なる場合はソートできません。 
6. すべてのコンポーネントが予想される要素と一致する場合は、YES を出力します。 それ以外の場合は、NO を出力します。 

機能する理由: スワップ操作は、要素間で要素を自由に交換できるインデックスの接続コンポーネントを定義します。 各コンポーネントは独立しているため、異なるコンポーネント内の要素の相対的な順序を変更することはできません。 配列のソートは、各コンポーネントに、最終的にソートされた配列内の位置に必要な要素が正確に含まれている場合にのみ可能です。 アルゴリズムはこの不変条件を直接チェックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def can_sort_heapify(n, a):
    visited = [False] * n

    def dfs(idx, indices):
        visited[idx] = True
        indices.append(idx)
        for nxt in [2*(idx+1)-1, (idx+1)//2-1]:
            if 0 <= nxt < n and not visited[nxt]:
                dfs(nxt, indices)

    for i in range(n):
        if not visited[i]:
            indices = []
            dfs(i, indices)
            component_values = [a[j] for j in indices]
            if sorted(indices) != sorted([v-1 for v in component_values]):
                return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(can_sort_heapify(n, a))
```この解決策では、最初に、大きな n に対するスタック オーバーフローを回避するのに十分な高い再帰制限を設定します。 DFS は、許可されたスワップを介して到達可能なすべてのインデックスを調査し、接続されたコンポーネントを形成します。 各コンポーネントについて、現在の要素とそれらの位置のターゲットの並べ替え値を抽出します。 両方のリストを並べ替えて比較すると、並べ替えられた配列と一致するようにコンポーネント内の要素を再配置できるようになります。 0 から始まるインデックスを使用すると、DFS と配列の処理が簡素化されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | DFS では各インデックスが 1 回だけアクセスされます。 各コンポーネントのソートは O(k log k) ですが、すべてのコンポーネントにわたる k の合計は n なので、最悪の場合は O(n log n) |
 | スペース | O(n) | 訪問したアレイと DFS スタック |

 n ≤ 2⋅10^5 および t ≤ 10^4 で、テスト全体の合計 n ≤ 2⋅10^5 の場合、解は時間とメモリの制限内に簡単に収まります。
