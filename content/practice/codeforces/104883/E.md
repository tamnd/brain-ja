 ## 解決策
 ## 問題の理解

 それぞれに整数レベルを持つ一連の宝石が与えられています。 許可される唯一の操作は、少なくとも 2 つの同一レベルの連続したブロックを取得し、それをレベルが 1 つ増加する単一の宝石に結合することです。 このプロセスはシーケンス内のどこでも繰り返すことができ、マージによってさらなるマージのための新たな機会が生まれる可能性があります。 

問題は、このような一連の結合の後、配列全体を 1 つの宝石に縮小することが可能かどうかです。 

主な難点は、マージはローカルであり、隣接関係に依存しますが、その効果は値が上方に伝播することです。 マージでは複数の要素が削除され、上位レベルの要素に置き換えられます。これにより、十分な数の同一のコピーが隣接する場合、その要素は将来のマージに参加できるようになります。 

制約は大きく、テスト ケースあたり最大 10^5 要素、すべてのテストで合計最大 5 × 10^5 です。 これにより、単純な方法で配列のスキャンとマージを繰り返すシミュレーションは即座に排除されます。 テスト ケースごとに n で 2 次的なアプローチは失敗します。 

マージによって、遠く離れたセグメントが崩壊した後でのみマージ可能になる高レベルの gem が作成される場合、微妙なエッジ ケースが発生します。 たとえば、異なるマージ順序が成功した場合でも、貪欲な左から右へのマージは失敗する可能性があります。 

もう 1 つのエッジ ケースは、シーケンスがほぼ均一であるが、単一の異なる要素によって分離されている場合です。 たとえば、[1, 1, 2, 1, 1] のようなシーケンスは、1 がたくさんあるため単純化できるように見えますが、2 はマージの単一チェーンの形成を妨げる形で相互作用をブロックします。 

## アプローチ

 ブルートフォースアプローチでは、マージプロセスを明示的にシミュレートします。 配列を繰り返しスキャンし、長さが少なくとも 2 で同じ値の最大セグメントを見つけ、それを値 +1 の単一の要素に置き換え、移動が不可能になるまで繰り返すことができます。 各スキャンは O(n) であり、最悪の場合は O(n) のマージが実行され、テスト ケースごとに O(n^2) になる可能性があります。 要素が 10^5 の場合、これは遅すぎます。 

重要な観察は、プロセスが連続する実行のみに依存しており、マージによって常に実行が削減され、そのレベルが増加するということです。 個々の要素を追跡する代わりに、配列を同じ値の連続に圧縮できます。 各実行は、ペア (値、カウント) によって特徴付けられます。 操作は次のようになります。ランのカウントが 2 以上の場合、2 つ以上のコピーを 1 つのより高いレベルのアイテムに置き換えることによってカウントを減らすことができ、その後、同じ新しいレベルの隣接するランとマージできます。 

これは、間隔の縮小と同様のスタックベースの削減を示唆しています。 ランを左から右に処理し、マージの機会があれば即座に解決しようとする構造を維持します。 マージ後に 2 つの隣接するグループが等しくなるたびに、それらはさらに結合されます。 これは本質的に、値によってインデックス付けされた一連のカウントに対するカスケード キャリー プロセスです。 

要素をシミュレートする代わりに、値ごとのカウントのマップまたは配列を維持し、「キャリード マージ」を上方に伝播します。 同じ値の少なくとも 2 つのアイテムを蓄積するたびに、それらは値 +1 の 1 つのアイテムに折りたたまれます。 

これは、基数が 2 である点と、「桁」がレベルに対応し、値が上に伝播する点を除いて、2 進加算に似ています。 

最後の疑問は、すべてのキャリーが伝播した後、あるレベルですべての質量を単一の項目に減らすことができるかどうかということになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 圧縮 + キャリー伝播の実行 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力シーケンスを等しい値の連続ランに圧縮し、そのカウントのみを保存します。 これにより、同一ブロック内の無関係な内部構造が削除されます。 
2. 各値をそのレベルで現在利用可能な「項目」の数にマップする辞書 (または配列) を作成します。 実行カウントを使用して初期化します。各実行はその値の 1 つの項目を提供しますが、ランの長さが少なくとも 2 の場合は、複数の単一項目ではなく 1 レベル上のマージされた項目を直ちに提供します。 
3. キャリーのような伝播を維持しながら、値を昇順に処理します。 各レベル v で、現在利用可能なアイテムの数を取得します。 
4. レベル v のカウントが少なくとも 2 である間、ペアを繰り返しレベル v + 1 にマージします。マージするたびに、v のカウントが 2 ずつ減り、v + 1 のカウントが 1 ずつ増えます。これは、v に残る項目が 2 つ未満になるまで続けられます。 
5. 次のレベルに上に移動し、以前のキャリーから新しく作成されたアイテムを含め、同じプロセスを繰り返します。 
6. 構造内に表示されるすべてのレベル (キャリーによって作成されたレベルを含む) を処理した後、どこかに 1 つの項目が残っているかどうかを確認します。 全体的に 1 つの項目だけが残っている場合、答えは「はい」、そうでない場合は「いいえ」です。 

重要な考え方は、マージはレベルごとのカウントのパリティのような動作にのみ依存するということです。 あるレベルの偶数カウントは完全に上方に伝播しますが、奇数カウントは、より高いレベルにさらなる構造が存在しない限り除去できない剰余を残します。 

### なぜ効果があるのか

 どのレベル v でも、同一のアイテムのペアのみをマージでき、各マージによって厳密にレベルが上がります。 レベルを下げる操作はないため、レベル間の相互作用は一方向の上向きの流れになります。 これは、システムがマルチレベルのキャリー プロセスのように動作し、各レベルが独立して 0 または 1 つの残りアイテムに解決され、さらに次のレベルにキャリーされることを意味します。 キャリーは決定的で順序に依存しないため、最終的な構成は一意になります。 完全に伝播した後にアイテムが 1 つだけ残った場合、それは構造が完全に崩壊して 1 つの宝石になったことに相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    from collections import Counter
    
    cnt = Counter()
    for x in a:
        cnt[x] += 1
    
    # we may need to propagate upward dynamically
    keys = sorted(cnt.keys())
    max_key = max(keys) if keys else 0
    
    # use dict for dynamic levels
    while True:
        changed = False
        new_cnt = Counter()
        
        for v in sorted(cnt.keys()):
            c = cnt[v]
            if c >= 2:
                carry = c // 2
                rem = c % 2
                if rem:
                    new_cnt[v] += rem
                new_cnt[v + 1] += carry
                changed = True
            else:
                new_cnt[v] += c
        
        cnt = new_cnt
        
        if not changed:
            break
    
    total = sum(cnt.values())
    print("Yes" if total == 1 else "No")

if __name__ == "__main__":
    solve()

t = int(input())
for _ in range(t):
    solve()
```この実装では、レベル全体にわたる周波数マップが維持されます。 各反復では、上向き伝播の 1 ラウンドが実行され、利用可能なすべてのペアが折りたたまれます。 このループは、少なくとも 2 つの項目を持つレベルがなくなるまで続きます。つまり、それ以上のマージは不可能になります。 

重要な実装上の選択は、シーケンスをシミュレートするのではなく、値に対してカウンターを使用することです。 これにより、隣接性への依存が回避されます。これは、圧縮と抽象化の後、隣接性は最初の同一グループを形成する場合にのみ重要となるためです。 

微妙な問題は終了です。カウント ≥ 2 のレベルがない場合、それ以上のマージが存在しないため、システムは安定します。 その時点で、残りのすべての項目は、それ以上結合できないという意味で分離されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(n) | 値と中間キャリーの周波数マップ |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        from collections import Counter
        
        cnt = Counter(a)
        
        while True:
            changed = False
            new = Counter()
            for v in sorted(cnt.keys()):
                c = cnt[v]
                if c >= 2:
                    new[v] += c % 2
                    new[v + 1] += c // 2
                    if c >= 2:
                        changed = True
                else:
                    new[v] += c
            cnt = new
            if not changed:
                break
        
        output.append("Yes" if sum(cnt.values()) == 1 else "No")
    
    t = int(input())
    for _ in range(t):
        solve()
    
    return "\n".join(output)

 ## 特殊なケース

 [k] のような単一要素の配列は、すでに完成した構成です。 アルゴリズムはカウンターを 1 つの項目で初期化し、すぐにマージが不可能であることを確認します。 合計数は 1 なので、正しく Yes が出力されます。 

[1, 2] のような厳密に交互の小さな構成では、マージはまったく生成されません。 各値はそれぞれのレベルで分離されたままであるため、最終的なカウントは 2 で、答えは「いいえ」になります。カウント ≥ 2 のレベルがないため、伝播ループは何も変更しません。 

[1, 1, 1, 1, 1, 1] のような完全に均一な配列は、最大限のカスケードを示します。 レベル 1 では、最終アイテムが 1 つだけ残るまで、3 ラウンドのペアリングによって上位レベルのキャリーが生成されます。 このアルゴリズムは整数の 2 による除算を繰り返し適用し、上向き伝播の正確さを保証します。
