 ## 解決策
 ## 問題の理解

 各アカウントには一定量の「秘術ダスト」が付属しており、カードデッキの固定リストがあり、完全に作成するにはそれぞれ特定のダストコストが必要です。 すべてのアカウントについて、任意のデッキのサブセットを選択した場合に作成できる完全なデッキの最大数を知りたいと考えています。ただし、選択した各デッキは必要なダストをすべて消費し、選択したすべてのコストの合計がアカウントのダストバジェット内に収まる必要があります。 

より具体的に言うと、配列が与えられます。`A`サイズの`n`、 どこ`A[i]`アカウントに利用できるダストは何ですか`i`。 配列も与えられます`B`サイズの`m`、ここでそれぞれ`B[j]`デッキの作成にかかるコストです`j`。 それぞれについて`A[i]`のサブセットを選択する必要があります。`B`選択した要素の数をその合計が超えないように最大化する`A[i]`。 

制約`n, m ≤ 10^5`アカウントごとにナップザックを再計算しようとするソリューションは直ちに除外します。 単純なアカウントごとの動的プログラミングのアプローチでは、`O(n * m)`時間は次のとおりです`10^10`最悪の場合、1 秒の制限をはるかに超えて操作が行われる可能性があります。 

重要な微妙な点は、値を最大化したり、アカウントごとにさまざまな組み合わせを計算したりすることは求められず、アイテムの数だけを求められることです。 これにより、ソート後の構造が貪欲になります。 

よくある失敗例は、デッキコストを分類していないことに起因します。 最初に高価なデッキを選択すると、人為的にデッキ数を減らすことができます。 たとえば、次の場合`A = 10`そして`B = [8, 7, 3, 2]`、最初に 8 を選択すると 1 つのデッキのみが得られますが、最適なのは`[2, 3, 7]`または`[2, 3]`予算によっては、任意の順序で貪欲に表示するのは間違いです。 

もう一つのエッジケースはゼロコストデッキです。 もし`B = [0, 0, 5]`そして`A = 1`, 予算が許せば、最初に両方のゼロコストのデッキを採用し、その後でも潜在的に 5 コストのデッキを採用することができます。 ゼロを無視したり、厳密な正の値を想定したりする方法では、カウントを誤る可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 アカウントごとに、デッキのすべてのサブセットを試し、合計コストを計算し、予算内に収まる最大サブセット サイズを追跡します。 これは制約定義を直接強制するため正しいですが、列挙する必要があります。`2^m`アカウントごとにサブセットを作成することは、たとえ小規模であっても不可能です`m`。 

より構造化されたブルート フォースは、サブセットをサイズで並べ替えるか、アカウントごとにナップザック DP を試すことです。 それは擬似多項式解につながります`O(n * m * max(A))`精神的にはそうだが、それでも実現不可能であるため、`A[i]`と同じ大きさにすることができます`10^9`。 

重要な観察は、どのデッキも同じ「価値」（1 つの作成されたデッキ）に貢献するため、常に安価なデッキを最初に優先する必要があるということです。 並べ替えたら`B`減少しない順に、固定予算に対する最適な戦略は、予算を超えるまでできるだけ多くの最小コストを取ることです。 これにより、各クエリがプレフィックス合計の問題に変わり、その後に二分探索が行われます。 

ソートされたものを事前計算します`B`とそのプレフィックスの合計。 それからそれぞれについて`A[i]`、プレフィックスの合計が ≤ となるような最大のプレフィックス インデックスを見つけます。`A[i]`。 その指標が答えです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^m) | お(1) | 遅すぎる |
 | 最適 (ソート + プレフィックス + 二分検索) | O(m log m + n log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を、「予算内に収まる最小の要素の数」という複数のクエリに答えることに変換します。 

1. 配列をソートする`B`昇順で。 これにより、常に安価なデッキを最初に考慮することが保証されます。これは、各デッキがカウントに均等に寄与するため必要です。 
2. プレフィックス合計配列を構築する`P`、 どこ`P[k]`最初のクラフトに必要なダストの合計を表します`k`最安デッキ。 これにより、サブセットの合計が単調シーケンスに変換されます。 
3. アカウントごとの予算`A[i]`、二分探索を実行します。`P`最大のインデックスを見つけるには`k`そのような`P[k] ≤ A[i]`。 そのアカウントの答えは、`k`。 
4. すべての回答を順番に出力します。 

プレフィックス合計配列が厳密に減少しないため、二分探索は機能します。`P[k] ≤ A[i]`) は単調です`k`。 

### なぜ効果があるのか

 デッキがコストで分類されると、より高価なデッキを使用し、より安価なデッキをスキップする最適な選択は、選択したデッキの数を減らさずに、総コストを減らすか維持するだけでデッキを交換することで改善できます。 この交換議論を繰り返すと、すべての最適解は、選択されたデックが常にソートされたリストのプレフィックスとなる構造に強制的に組み込まれます。 これにより、解空間は 1 次元になり、プレフィックス合計によって完全にキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    A = list(map(int, input().split()))
    m = int(input())
    B = list(map(int, input().split()))

    B.sort()

    P = [0] * (m + 1)
    for i in range(1, m + 1):
        P[i] = P[i - 1] + B[i - 1]

    def upper_bound(x):
        lo, hi = 0, m
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if P[mid] <= x:
                lo = mid
            else:
                hi = mid - 1
        return lo

    res = []
    for a in A:
        res.append(str(upper_bound(a)))

    print(" ".join(res))

if __name__ == "__main__":
    main()
```ソートのステップにより、常に可能な限り安価なデッキを最初に消費することが保証されます。 プレフィックス配列は、繰り返される合計チェックを単一の単調な構造に変換します。 二分探索により、実現可能な最大プレフィックス長が効率的に見つかります。 

微妙な点は、バイナリ検索ではなく上限スタイルのバイナリ検索を使用していることです。`bisect_right`直接的には同じですが、どちらも同等です。 重要な条件は、生の値ではなく、プレフィックスの合計に基づいて検索することです。 

ゼロコストデッキはプレフィックス合計への寄与がゼロであるため、自然に処理され、予算を消費せずにプレフィックスインデックスを増加させることができます。 

## 実用的な例

 検討してください`B = [0, 2, 5, 9]`とアカウント`A = [0, 5, 10]`。 

まず並べ替えます`B`(すでにソート済み) プレフィックスの合計を計算します。 

| k | B[k] | P[k] |
 | --- | --- | --- |
 | 0 | - | 0 |
 | 1 | 0 | 0 |
 | 2 | 2 | 2 |
 | 3 | 5 | 7 |
 | 4 | 9 | 16 |

 各アカウントについて:

 | あ | 実現可能なプレフィックス k | 理由 |
 | --- | --- | --- |
 | 0 | 1 | ゼロコストデッキのみが適合します |
 | 5 | 3 | 0 + 2 + 5 = 7 は大きすぎるため、0 + 2 | が最適です。 
| 10 | 3 | 0 + 2 + 5 = 7 は適合し、4 番目は | を超えます。 

のために`A = 5`、バイナリ検索により、最大のプレフィックス合計 ≤ 5 が見つかります。これは、`k = 2`、2つのデッキに対応。 これは、私たちが常に最初にコストが小さいことを好むことを裏付けています。 

ここで、不均衡が大きい場合を考えてみましょう。`B = [100, 1, 1]`、`A = 2`。 

並べ替え済み`B = [1, 1, 100]`、プレフィックスの合計`[0, 1, 2, 102]`。 

| あ | k |
 | --- | --- |
 | 2 | 2 |

 私たちは両方の安価なデッキを正しく採用し、高価なデッキを完全に無視します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    A = list(map(int, input().split()))
    m = int(input())
    B = list(map(int, input().split()))

    B.sort()
    P = [0]
    for x in B:
        P.append(P[-1] + x)

    def upper_bound(x):
        lo, hi = 0, m
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if P[mid] <= x:
                lo = mid
            else:
                hi = mid - 1
        return lo

    return " ".join(str(upper_bound(a)) for a in A)

# sample-like test
assert run("3\n5 10 15\n4\n2 2 3 4") == "2 4 4", "basic case"

# minimum case
assert run("1\n0\n1\n0") == "1", "single zero case"

# all expensive
assert run("2\n1 10\n3\n100 200 300") == "0 0", "no budget case"

# all zeros
assert run("2\n0 5\n3\n0 0 0") == "3 3", "zero cost stacking"

# mixed case
assert run("3\n3 6 10\n4\n1 2 5 7") == "3 4 4", "prefix growth case"

 ## 特殊なケース

 すべてのデッキコストがゼロの場合、すべてのプレフィックスのプレフィックス合計はゼロのままです。 アルゴリズムは戻ります`m`すべてのプレフィックスが実行可能であるため、すべてのアカウントに適用されます。 のような入力の場合`A = [0, 100]`そして`B = [0, 0, 0]`、二分検索では常に 3 が返され、予算に関係なくすべてのデッキを使用できるという事実と一致します。 

どのデッキも高すぎる場合、`B = [5, 6, 7]`そして`A = [0, 4]`、プレフィックスの合計は 0 から始まり、すぐに予算を超えます。 最も安価なデッキでも購入できるわけではないため、アルゴリズムはすべてのアカウントに対して 0 を正しく返します。 

予算が非常に大きい場合、二分検索では常に次の結果が返されます。`m`完全なプレフィックスの合計が適合するためです。 これにより、クエリごとのオーバーフローや反復的な蓄積が回避され、前処理が行われる理由がわかります。
