 ## 解決策
 ## 問題の理解

 1 から n までのすべての整数を実行するループが与えられています。 ループ内には、m 個の条件を持つ連鎖された if-else 構造があり、m+1 個の可能な分岐が生成されます。 ループの反復ごとに 1 つのブランチが選択され、そのブランチによって配列 A 内の対応するカウンターがインクリメントされます。 

問題は、条件で使用されるしきい値が固定されていないことです。 各 xj は、整数 1 ～ n から均一にランダムに独立して選択されます。 演算子は固定されており、等価、より小さい、またはより大きいことが可能です。 

i の固定値の場合、各条件は xj に応じて i を受け入れるか拒否します。 その後、成功した最初の条件に従って実行が行われます。 どれも成功しない場合は、最後の分岐が選択されます。 n 回の繰り返し全体で、各分岐が実行されると予想される回数が必要です。 

出力は、998244353 を法として与えられた、このランダム性の下での各 Ai の期待値です。 

重要な構造は、唯一のランダム性が x 配列から得られ、x の値が固定されると i の各反復が独立して動作するということです。 したがって、期待値は、i が各分岐に到達する確率の i にわたる合計になります。 

素朴な解釈では、i のすべての n 値と、考えられるすべてのランダムな x 構成をシミュレートしますが、n は 10^9 にもなる可能性があるため、計算上はすぐに無意味になってしまいます。 固定 i の場合でも、ランダム性を列挙することは不可能です。 代わりに、正確な確率を計算する必要があります。 

微妙な失敗のケースは、条件を i 全体で独立したものとして扱うことから発生します。 たとえば、演算子「<」を含む固定 j の場合、イベント i < xj は i に大きく依存します。 小さいと通過する可能性が高く、大きいと通過する可能性が低くなります。 この依存関係を無視すると、不正確な一様近似が行われることになります。 

もう 1 つのよくある間違いは、if-else チェーンのプレフィックス構造を忘れることです。 j 番目の分岐は、単に「条件 j が true」ではなく、「前のすべての条件が false で、条件 j が true」です。 

## アプローチ

 すべての x 値を固定すると、各 i は決定論的に 1 つのブランチにマップされるため、問題は [1, n] のパーティションの各領域にいくつの i が入るかを数えることになります。 しかし、x はランダムであるため、これらの境界自体はランダムに移動し、整数直線の幾何学的分割を直接推論するのは面倒になります。 

ブルートフォースアプローチでは、考えられるすべての x 構成を明示的に列挙します。 各 xj には n 個の選択肢があるため、n^m 個の構成があり、それぞれについて i にわたるループをシミュレートします。 シミュレーションコストを無視しても、これは天文学的な金額です。 

より合理的な総当り攻撃は、単一の i を固定し、すべての x 構成を合計することによって各分岐に到達する確率を計算することです。 各 i について、m 個を超える独立変数を区分的条件で積分する必要があり、直接処理すると m 単位で指数関数的に拡大します。 

重要な観察は、固定 i の場合、各条件が i の単純な線形確率に寄与するということです。 演算子「=」、「<」、または「>」の場合、成功確率と失敗確率は両方とも [1, n] に対する i の線形関数です。 i が分岐 j に到達する確率は、このような線形項の j の積になります。 これにより、問題は i に関する多項式の加算に変わります。 

期待値が m 次までの i の多項式の合計として書き込まれると、問題は m 次までの i のべき乗の合計を計算することになり、これはスターリング数と二項恒等式を使用して処理できます。 

確率的分岐プロセスから多項式代数への移行が中心的な単純化です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての x 構成を列挙する | O(n^m) | お(1) | 遅すぎる |
 | i あたりの確率総当たり | O(nm) 以上 | お(1) | 遅すぎる |
 | スターリング和による多項式展開 | O(m^2) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

### 1. 各条件を成功確率と失敗確率に変換します。 

固定の i と単一のランダムな xj の場合、各演算子は確率になります。 

opが「=」の場合、成功確率は1/n、失敗確率は(n−1)/nとなります。 

op が「<」の場合、成功は P(i < xj) = (n−i)/n、失敗は i/n です。 

op が「>」の場合、成功は P(i > xj) = (i−1)/n、失敗は (n−i+1)/n です。 

これらはそれぞれ、i を n で割った一次関数です。 

### 2. 分岐 j に到達する確率を表現する

 分岐 j の場合、i は前の条件をすべて失敗し、j で成功する必要があります。 

したがって、確率は j 項の積であり、各項は位置に応じて失敗確率または成功確率のいずれかになります。 

これにより、確率は、n^{-j} でスケールされた i 内の j 個の線形多項式の積になります。 

### 3. 各分岐確率を i の多項式に展開します。 

各分岐 j の確率は次のように書くことができます。 

Pj(i) = (1 / n^j) × i の次数が最大 j−1 の多項式。 

この多項式を段階的に拡張します。 新しい線形係数を乗算するたびに次数が最大 1 ずつ増加するため、次数 m までの係数配列を維持します。 

### 4. 期待値をべき乗項の和に変換する

 Aj の期待値は、Pj(i) の i にわたる合計です。 展開後、これは 0 から m-1 までの k の i^k の合計の線形結合になります。 

したがって、タスクは、指定された素数を法とする S_k = sum_{i=1..n} i^k を計算することになります。 

### 5. スターリング数を使用して S_k を計算する

 第 2 種スターリング数を使用して累乗を書き直します。 

i^k = S2(k, t) × t の t の合計! ×C(i,t)。 

i を合計すると二項項が変換されます。 

sum_{i=1..n} C(i, t) = C(n+1, t+1)。 

したがって、S_k は、階乗、スターリング数、および n の二項係数のみを含む t にわたる合計になります。 

これにより、 i の反復処理が完全に回避されます。 

### 6. 最終的な答えを得るためにすべてを組み合わせます

 各ブランチ j について、その多項式係数を事前に計算された S_k 値と組み合わせ、n^j の逆剰余を乗算します。 

結果は Aj の期待値です。 

### なぜ効果があるのか

 核となる不変条件は、k 個の条件を処理した後、if チェーンの部分的なプレフィックスに到達する確率が、常に n^{-k} でスケールされた i の多項式として表現できるということです。 成功確率と失敗確率の両方が i のアフィン関数であるため、新しい条件はそれぞれこの構造を維持します。 乗算におけるこの閉包により、非多項式項が決して出現しないことが保証され、ケースベースの確率列挙ではなく、期待値全体を有限次数代数に還元することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_stirling(n):
    # S2[k][t]
    S2 = [[0] * (n + 1) for _ in range(n + 1)]
    S2[0][0] = 1
    for i in range(1, n + 1):
        for j in range(1, i + 1):
            S2[i][j] = (S2[i - 1][j - 1] + j * S2[i - 1][j]) % MOD
    return S2

def solve():
    n, m = map(int, input().split())
    ops = input().split()

    inv_n = modinv(n)

    # polynomial for each branch
    # dp[j][k] = coefficient of i^k before final 1/n^j scaling
    dp = [[0] * (m + 1) for _ in range(m + 2)]
    dp[1][0] = 1  # first branch starts empty product

    for j in range(1, m + 1):
        op = ops[j - 1]

        if op == '=':
            succ = (1, 0)
            fail = (MOD - 1, 1)
            fail_const = 1
        elif op == '<':
            succ = (MOD - 1, n)
            fail = (1, 0)
        else:  # '>'
            succ = (1, MOD - 1)
            fail = (MOD - 1, 1)

        new_dp = [[0] * (m + 1) for _ in range(m + 2)]

        for b in range(1, j + 1):
            for k in range(m + 1):
                if dp[b][k] == 0:
                    continue
                for coeff, power in [succ, fail]:
                    nb = b + (1 if coeff != 0 else 0)
                    if nb > m + 1:
                        continue
                    # multiply polynomial by (coeff * i + const)
                    for t in range(m, -1, -1):
                        if dp[b][t] == 0:
                            continue
                        new_dp[nb][t + power] = (new_dp[nb][t + power] +
                                                dp[b][t] * coeff) % MOD

        dp = new_dp

    # compute S_k
    S2 = build_stirling(m)

    fact = [1] * (m + 2)
    for i in range(1, m + 2):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (m + 2)
    invfact[m + 1] = modinv(fact[m + 1])
    for i in range(m + 1, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n_, k):
        if k < 0 or k > n_:
            return 0
        return fact[n_] * invfact[k] % MOD * invfact[n_ - k] % MOD

    S = [0] * (m + 1)
    for k in range(m + 1):
        val = 0
        for t in range(k + 1):
            val += S2[k][t] * fact[t] % MOD * C(n + 1, t + 1)
        S[k] = val % MOD

    inv_pows = [1] * (m + 2)
    for i in range(1, m + 2):
        inv_pows[i] = inv_pows[i - 1] * inv_n % MOD

    ans = [0] * (m + 2)

    for j in range(1, m + 2):
        for k in range(m + 1):
            ans[j] = (ans[j] + dp[j][k] * S[k]) % MOD
        ans[j] = ans[j] * inv_pows[j] % MOD

    print(*ans[1:m + 2])

if __name__ == "__main__":
    solve()
```この実装では、各分岐の確率寄与の多項式表現が構築されます。 dp 構造体には分岐の深さごとに i^k の係数が格納され、各条件は i の線形係数に寄与するかどうかに応じてこれらの係数を更新します。 展開後、コードはスターリング数を使用してべき乗和を閉じた形式に変換し、n^j スケーリングに逆モジュラーを適用します。 

最もデリケートな部分は、各条件が i の定数項または線形項にどのように寄与するかを追跡することです。 そこに間違いがあると、多項式構造が崩壊し、誤った期待が生じます。 

## 実用的な例

 n = 3、単一条件 m = 1、たとえば「<」の最小ケースを考えてみましょう。 

すべての i は、i < x1 の場合はブランチ 1 に寄与し、それ以外の場合はブランチ 2 に寄与します。 

| 私 | P(i < x1) | P(ブランチ1) |
 | --- | --- | --- |
 | 1 | 2/3 | 2/3 |
 | 2 | 1/3 | 1/3 |
 | 3 | 0 | 0 |

 合計すると E[A1] = 1、E[A2] = 2 となります。これは、i が小さいほど「<」を満たすことが多いという考えと一致します。 

次に、演算子「=」、「>」を使用して m = 2 を考えます。 

分岐 1 は、i が x1 に等しい場合にのみ発生します。 

分岐 2 は、i ≠ x1 および i > x2 の場合に発生します。 

| 私 | P(B1) | P(B2) |
 | --- | --- | --- |
 | 1 | 1/3 | 0 |
 | 2 | 1/3 | 1/3 |
 | 3 | 1/3 | 2/3 |

 i を合計すると、i に多項式に依存する寄与が得られ、直接カウントするのではなくべき乗和処理が必要な理由がわかります。

 ## 特殊なケース

 n = 1 の場合、すべての比較は縮退確率に陥ります。 「<」と「>」の場合、すべての成功確率はゼロになり、等しい場合のみゼロ以外の質量が生成されます。 i = 1 に置き換えるとすべての線形式が正しく減少するため、アルゴリズムはこれを処理します。 

すべての演算子が「=」の場合、各分岐は相互に独立した等価イベントに依存します。 多項式展開は定数項のみに縮小され、高次の係数は DP 全体でゼロのままになります。 

m が大きく n が小さい場合でも、t ≥ n の場合 C(n+1, t+1) がゼロになり、特別な場合を必要とせずに寄与が自然に切り捨てられるため、スターリングベースの電力和は依然として正しく動作します。 

これらの動作は代数定式化から直接続くため、ブランチ固有の処理は必要ありません。
