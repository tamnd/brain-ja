 ## 解決策
 ## 問題の理解

 与えられた音楽プレイリストは、`n`初期の順序で並べられたユニークな曲`a`。 アプリは曲を循環的に再生します。最後の曲が終わると、最初の曲からやり直します。 別途、希望のリスニングシーケンスがあります`b`同じもの`n`歌。 どの日でも、プレイリストの先頭から開始します`a`スキップボタンを押すと次の曲にジャンプします。 目標は、曲を聴くために必要なスキップの最小数を決定することです。`b`どの曲もスキップせずに順番に`b`自体。 

数日間の更新によりさらに複雑さが増します。 毎日 (最終日を除く)、次のいずれかを変更するスワップ操作が与えられます。`a`または`b`永久に。 各更新の後、新しいものから始めて最小スキップ数を再計算する必要があります。`a_1`。 

この制約は、プレイリストの単純なシミュレーションが遅すぎることを意味します。 と`n`そして`d`200,000 までの場合、O(n²) または O(n・d) の解はおよそ 4 × 10¹⁰ の演算を実行することになり、2 秒で許容できる演算をはるかに超えます。 これは、O(n + d・log n) または O(n + d) のアプローチが必要であることを示唆しています。 エッジケースには次のような場合が含まれます。`a`そして`b`1 つの曲が最初にある場合は、ほぼ同じです。`a`しかし後半に`b`、および交換により最初または最後の要素の位置が変更される場合。 直線的にスキャンする不用意な実装`a`の各曲ごとに`b`大きいと失敗する`n`。 

## アプローチ

 ブルートフォースアプローチは簡単です。 から開始`a_1`、および各曲について`b`、スキャン`a`スキップした曲を数えながら、その曲に出会うまで順番に。 終わりに達した後、`a`、必要に応じて先頭に戻ります。 これはプロセスを正確にシミュレートしているため、これは正しいです。 ただし、`n = 200,000`、これは最悪の場合、O(n²) 回の操作につながり、遅すぎます。 

最適化するための重要な観察事項は次のとおりです。`a`は順列であるため、各曲には一意のインデックスがあります。 各曲の位置を事前に計算すると、`a`、1 つの曲からスキップする回数を計算できます。`b`スキャンの代わりにモジュラー演算を使用して次のステップに進みます。 具体的に言うと、曲であれば、`b[i]`位置にあります`pos[b[i]]`で`a`そして前の曲`b[i-1]`にいた`prev_pos`、スキップ数は`(pos[b[i]] - prev_pos - 1) % n + n * (pos[b[i]] < prev_pos)`。 基本的に、次の曲がプレイリスト内の現在の曲より前に表示される場合、ラップアラウンドが考慮されます。 これにより、1 日の計算量が O(n) に削減されます。 

更新を効率的に処理することが次の課題です。 2 つの要素を入れ替える`a`位置マップ (O(1)) を更新する必要があります。 要素を入れ替える`b`シーケンス内の順序を変更する必要がありますが、これも配列表現の場合は O(1) です。 これらの観察により、毎日の最小スキップ数は O(n) で計算でき、更新ごとに O(1) 以上の作業が追加されることはありません。 したがって、合計の複雑さは O(d・n) であり、これは許容範囲内です。`n`最大200,000および小規模`d`。 最大の入力については、セグメント ツリーを使用してさらに最適化する可能性があります。`d`に近かった`n`ただし、ここでは 1 日あたり O(n) アプローチで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (プレイリストをシミュレート) | O(n²) | O(n) | 遅すぎる |
 | 最適 (位置マッピング + モジュラー スキップ) | O(d・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`d`そして初期配列`a`そして`b`。 を構築する`pos`各曲番号を辞書でマッピング`a`O(1) ルックアップのインデックスに追加します。 これにより、直線的にスキャンするのではなく、曲の位置に直接ジャンプできるようになります。 
2. 初日は初期化`prev_pos = -1`。 曲ごとに`b[i]`順番に、その位置を計算します`curr_pos = pos[b[i]]`。 スキップ数は`(curr_pos - prev_pos - 1) % n`もし`curr_pos > prev_pos`、 または`(curr_pos + n - prev_pos - 1)`ラッピングが必要な場合。 これらのスキップを蓄積して更新します`prev_pos = curr_pos`。 
3. その日の合計スキップ数を出力します。 
4. 残りのそれぞれについて`d-1`更新情報を読んでください`(c, x, y)`。 もし`c = 1`、交換`a[x-1]`そして`a[y-1]`、更新します`pos[a[x-1]]`そして`pos[a[y-1]]`それに応じて。 もし`c = 2`、交換`b[x-1]`そして`b[y-1]`。 これらのスワップは一定時間の操作です。 
5. 更新後の新しいアレイに対して手順 2 ～ 3 を繰り返します。 結果を出力に追加します。 

機能する理由: 毎日、アルゴリズムは次の不変条件を維持します。`pos`各曲の現在位置を正確に反映します。`a`。 モジュラー演算を使用すると、ラップアラウンド境界を越えるスキップが正しく考慮されることが保証されます。 それぞれの曲に入っているので、`b`は 1 回だけ表示されるため、スキップの数を間違えることはなく、累積合計が必要な最小限のスキップ数を表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

# position map for quick lookup
pos = [0] * (n + 1)
for i, song in enumerate(a):
    pos[song] = i

def compute_skips():
    skips = 0
    prev = -1
    for song in b:
        curr = pos[song]
        if curr > prev:
            skips += curr - prev - 1
        else:
            skips += curr + n - prev - 1
        prev = curr
    return skips

print(compute_skips())

for _ in range(d - 1):
    c, x, y = map(int, input().split())
    x -= 1
    y -= 1
    if c == 1:
        a[x], a[y] = a[y], a[x]
        pos[a[x]] = x
        pos[a[y]] = y
    else:
        b[x], b[y] = b[y], b[x]
    print(compute_skips())
```解決策は、各曲を次のようにマッピングすることから始まります。`a`そのインデックスに。 これにより、スキップを計算するときに位置の O(1) ルックアップが可能になります。 の`compute_skips`関数が反復処理される`b`順番に、循環プレイリストの動作を処理するためにモジュラー演算でスキップを計算します。 更新はインプレースで処理されます。`pos`スワップイン後すぐに更新される`a`。 スワップイン`b`反復順序にのみ影響します。 スワップを読み取るときは、ゼロベースのインデックス付けに細心の注意が払われます。
