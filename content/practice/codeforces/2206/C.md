 ## 解決策
 ## 問題の理解

 次のような接続された無向グラフが与えられます。$n$頂点と$m$エッジ。各エッジは 2 つの頂点を接続しますが、その重みは不明です。 あなたの兄弟は、頂点から始まるダイクストラのアルゴリズムのバリアントを実行しました$1$ただし、重大な間違いがあります。常にヒープから最小距離をポップする代わりに、最初に最大距離をポップします。 彼らは、頂点が最初に配列にポップされる順序を記録しました。$S$。 私たちのタスクは、この「逆ダイクストラ」が正確なシーケンスを生成するように、正の整数エッジの重みを再構築することです。$S$。 それが不可能な場合は、その旨を報告しなければなりません。 

重要な制約は次のとおりです。$n$まで可能です$10^5$そして$m$まで$2 \cdot 10^5$、つまり、どのソリューションも大まかに次のようにする必要があります。$O(n + m)$または$O((n + m) \log n)$。 考えられるすべてのエッジの重みを総当りで検索することは不可能です。 エッジの重みは、以下の正の整数でなければなりません。$10^9$したがって、有効な重みの範囲は広いですが、制限されています。 

明らかではないエッジケースには、次のようなグラフが含まれます。$S$1 ではない頂点、または距離の割り当てに対応できないシーケンスで始まる。 たとえば、頂点を持つ三角グラフ$1, 2, 3$そして$S = [1, 3, 2]$適切な重さであれば満足できますが、$S = [2, 1, 3]$最初にポップされた頂点は常に開始点から最大の初期距離で到達可能でなければならないため、これは不可能です。 

もう 1 つの微妙な点は、複数のエッジが同じ 2 つの「レベル」の頂点を接続できることです。 一様な重みを不用意に割り当てると、順序付けの制約に違反する可能性があります。$S$ヒープが頂点を異なる順序でポップする可能性があるためです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての正の整数の重みを試し、逆ダイクストラをシミュレートして、結果のシーケンスが一致するかどうかを確認します。$S$。 単一のエッジの重みでも最大で$10^9$可能性はあります$2 \cdot 10^5$エッジにより、天文学的に大きな検索スペースが得られます。 

重要な洞察は、正確な重みは必要なく、頂点間の相対的な差だけが必要であるということです。 各頂点の位置に応じて「レベル」または「距離」を割り当てると、$S$、逆さまのヒープが正しい順序で頂点をポップすることを保証できます。 具体的には、距離を割り当てます$d[v]$そのような$d[S_1] > d[S_2] > \dots > d[S_n]$、連続する頂点間で 1 ずつ減少します。 次に各エッジについて$u \text{--} v$、重さを設定します$w = |d[u] - d[v]|$これにより、エッジに沿った移動が最大ヒープの順序に違反しないことが保証されます。 

これが機能するのは、逆さまのダイクストラが基本的に頂点を距離の短い順にポップするためです。 シーケンスと一致する距離を割り当てることにより、$S$重みが各エッジに沿った距離の差に等しい場合、すべての頂点が最初に割り当てられた順序で正確にポップされることが保証されます。$S$。 順序を満たすためにエッジにゼロまたは負の重みが必要な場合、割り当ては不可能です。

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`pos`各頂点をそのインデックスにマッピングする$S$。 これにより、シーケンス内の頂点の順序をすばやく検索できます。 
2.「擬似距離」を割り当てる$d[v]$各頂点に次のように$n - \text{pos}[v]$。 頂点$S_1$取得します$n$、$S_2$取得します$n-1$、 等々。 これにより保証されます$d[S_i] > d[S_{i+1}]$。 
3. 各エッジについて$u_j \text{--} v_j$、その重みを次のように計算します。$w_j = |d[u_j] - d[v_j]|$。 もし$w_j = 0$、エッジは順序付けをサポートできないため、出力できません。 
4. それ以外の場合は、割り当てます$w_j = |d[u_j] - d[v_j]|$。 これにより、エッジに沿ってある頂点から別の頂点に移動しても、許容値よりも長い距離の頂点が生成されることがなくなります。$S$。 
5. すべての重みを出力します。 上記のルールを満たす一貫した割り当てはすべて有効です。 

これが機能する理由: ヒープは常に最大距離の頂点をポップします。 に沿って厳密に減少する距離を割り当てることにより、$S$重みを差として設定すると、各頂点の順番が来たときに利用可能な最大距離が得られます。 重みがゼロのエッジは、2 つの頂点が同じ距離にあることを意味し、次の厳密な順序に違反します。$S$, だからこそ、不可能性をチェックするのです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
edges = [tuple(map(int, input().split())) for _ in range(m)]
S = list(map(int, input().split()))

pos = [0] * (n + 1)
for idx, v in enumerate(S):
    pos[v] = idx

# assign distances decreasing from n
d = [0] * (n + 1)
for v in range(1, n + 1):
    d[v] = n - pos[v]

weights = []
possible = True
for u, v in edges:
    w = abs(d[u] - d[v])
    if w == 0:
        possible = False
        break
    weights.append(w)

if not possible:
    print("impossible")
else:
    print(" ".join(map(str, weights)))
```このソリューションでは、まず位置マッピングを構築し、減少する擬似距離を割り当てます。 次に、各エッジの重みは距離の絶対差になります。 ウェイトがゼロの場合は、2 つの頂点が同時にポップされ、次の順序に違反するため、不可能であることを示します。$S$。 からの距離を減少させるという選択$n$すべての重みが正の整数であることを保証します。 絶対差により、エッジの両方向の有効な重みが生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(m)]
    S = list(map(int, input().split()))
    pos = [0] * (n + 1)
    for idx, v in enumerate(S):
        pos[v] = idx
    d = [0] * (n + 1)
    for v in range(1, n + 1):
        d[v] = n - pos[v]
    weights = []
    possible = True
    for u, v in edges:
        w = abs(d[u] - d[v])
        if w == 0:
            possible = False
            break
        weights.append(w)
    return "impossible" if not possible else " ".join(map(str, weights))
