 ## 解決策
 ## 問題の理解

 括弧文字列が与えられます$S$、括弧の前と最後にいくつかの括弧を追加することができます。 目標は、結果の文字列が非常に特殊な方法で動作するようにすることです。$X$左側と$Y$右側は完全な文字列$X + S + Y$「変形天秤」と呼ばれる特別な中間オブジェクトへの分割を認めなければなりません。 

この定義は再帰的で少し珍しいように見えますが、非常に具体的な組み合わせの意味を持っています。変形された文字列とは、単一の閉じ括弧 ")" から構築され、それを追加の外側括弧で囲むか、特定の非対称型のバランスの取れた「ブレーク ポイント」を挿入することを繰り返し行う文字列です。 重要な制約は、このような変形された文字列に追加の閉じ括弧が 1 つ追加されると、結果が標準のバランスの取れた括弧文字列になるということです。 

したがって、タスクは構造を明示的に構築することではなく、最小限追加する必要がある文字数を決定することだけです。$S$これにより、単一の閉じ括弧を追加するとバランスがとれた変形文字列にそれを「埋め込む」ことができます。 

制約は非常に大きく、最大で$10^6$すべてのテスト ケースの合計の長さ、最大$10^4$テスト。 部分文字列に対する変換または DP をシミュレートしようとするソリューションは、すぐに遅すぎます。 これにより、テスト ケースごとの線形スキャン、または一定数のスキャンが行われるようになります。 

単純なアプローチでは、考えられるすべての配置をチェックしようとします。$X$そして$Y$、または「完了」するためのすべての可能な方法$S$有効な構造に変換します。 修正の有効性をチェックする場合も$X, Y$スタック シミュレーションが必要であり、すべての選択肢を最適化すると、少なくとも 2 次の動作が得られます。 それは実行不可能です。 

微妙なエッジ ケースは、すでに「ほぼ有効」であるにもかかわらず、プレフィックスまたはサフィックスの調整が非常にわずかしか必要ない文字列から発生します。 たとえば、「()」のような文字列はすでにバランスが取れていますが、必ずしも必要な意味で変形されているわけではありません。 逆に、「)(」のような文字列は、プレフィックスとサフィックスのバランスが取れている状態では、両方向で不一致の構造が作成されるため、適切に動作しません。このようなケースでは、グローバル不変条件を持たない貪欲な推論は失敗する傾向があります。

 ## アプローチ

 重要な問題は、変形された文字列の定義が標準的なバランスではなく、本質的に不均衡の方向をエンコードする再帰的な構造であることです。これにより、ネストされた開口部の成長と、中央のシード ")" の周囲に完全に変形したブロックの対称的な挿入が可能になります。 最後に右括弧を 1 つ追加すると、構造全体が完全にバランスの取れたシーケンスに崩れる必要があります。 

これは、有用な再解釈を示唆しています。構築ルールの観点から考える代わりに、文字列を「1 つの余分な ')' の後でバランスを修正できる」ようにするプロパティに注目します。 この条件は、接頭辞合計の考え方を強く示唆しています。 バランスの取れた文字列は、プレフィックスの合計が負ではなく、ゼロで終わります。 ')' を 1 つ追加するとバランスが取れる文字列は、最後の文字が追加される前に、合計バランス +1 で終了する必要があります。 

ここで問題は、埋め込みたいということです。$S$プレフィックス/サフィックスのパディングが存在し、そのプレフィックス バランス プロファイルが、最後の下向きステップで有効な Dyck パスにシフトできる構造と互換性を持つようにするため、より大きな文字列に変換されます。 

強引なアイデアは、考えられるすべての分割点とすべてのパディング長を試し、プレフィックスのバランスをシミュレートし、結果の構造を有効な変形構造に拡張できるかどうかを確認することです。 これは少なくとも$O(n^2)$パディングを選択するたびに文字列全体をスキャンする必要があるため、テスト ケースごとに実行されます。 

重要な観察は、変形した構造が最終的には、プレフィックスの合計がどれだけ低くなり、どれだけ早くマイナスになるかという極端な不均衡な動作のみを制限するということです。 変換ルールにより次のことを考えることができます。$X$初期バランスを上方に押し上げ、$Y$残った余分なものを吸収するように。 最終的に、最適な答えは、プレフィックスの合計がゼロよりどの程度下回るか、および変形された実現可能性条件に決して違反しない形式にシーケンスを「持ち上げる」ことができることを保証するためにどのくらいの余剰が必要かを追跡する単一パスによって決定されます。 

これにより、問題は、実行バランスを許容範囲内に維持するために必要な最小調整を計算するという問題に軽減されます。最小調整は、プレフィックス最小値とサフィックス補償から導き出すことができます。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、文字列がバランス値のウォークとしてどのように動作するかを追跡し、有効な変形された埋め込みと互換性を持たせるためにどの程度の「リフティング」が必要かを計算することです。 

1. のプレフィックスバランスを計算します。$S$ここで、「(」は +1 に寄与し、「)」は -1 に寄与します。 これにより、マイナスになる可能性のあるパスが得られます。 最小のプレフィックス値を記録します。 この最小値は、無効な領域を避けるために構造全体をどれだけ上にシフトする必要があるかを示します。 
2. しましょう$minPref$最小のプレフィックス合計になります。 もし$minPref \ge 0$、文字列がゼロを下回ることがないため、無効な初期構造を防ぐためにプレフィックスをパディングする必要はありません。 ただし、変形された定義によって暗示される最終的な「+1 クロージャ」条件との互換性を確保する必要があります。 
3. もし$minPref < 0$、それでは少なくとも$-minPref$構造が必要な実現可能境界を侵害しないように、開き括弧を先頭に追加する必要があります。 
4. ここで、サフィックスの動作を計算します。余剰残高を閉じる逆のプロセスを考えてみましょう。 比類のないオープニング構造が最後にどれだけ残っているかを追跡します。 これにより、最終的な構成を 1 つの余分な ')' の後にバランスがとれた変形した形式に拡張できるように、右括弧をいくつ追加する必要があるかが決まります。 
5. 最終的な答えは、必要なプレフィックス リフトとサフィックス吸収の合計であり、これは最小プレフィックス合計と文字列の最終バランスの関数になります。 

### なぜ効果があるのか

 有効な変形埋め込みでは、構造全体が、いったんシフトされると、ちょうど 1 回の追加の終了ステップで Dyck パスに完了できるウォークのように動作する必要があります。 プレフィックスの最小値は、ウォークがベースラインからどの程度下降するかを決定します。これは、必要なプレフィックス修正に直接対応します。 最終的なバランスは、一致しない構造が最後にどれだけ残るかを決定します。これは接尾語の修正に対応します。 変形された文法はこれらの制約を超える新しいネットバランスを導入しないため、これら 2 つの値は実現可能性を完全に特徴付け、貪欲な修正を最適化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        bal = 0
        min_pref = 0

        for c in s:
            if c == '(':
                bal += 1
            else:
                bal -= 1
            if bal < min_pref:
                min_pref = bal

        # minimal prefix needed to avoid going negative
        need_prefix = -min_pref if min_pref < 0 else 0

        # final balance after adding S
        # we need to neutralize surplus using suffix
        need_suffix = bal

        if need_suffix < 0:
            need_suffix = 0

        print(need_prefix + need_suffix)

if __name__ == "__main__":
    solve()
```この実装では、単一のスキャンを実行して、最終残高と最小プレフィックス値の両方を計算します。 プレフィックス補正は、累計がゼロを下回る範囲から直接導出されます。 接尾辞の修正では、右側に追加された文字で閉じる必要がある一致しない開き括弧に対応する残りの余剰残高が使用されます。 

プレフィックス調整は最初に実現可能性を修正するのに対し、サフィックス調整は最後に完全性を修正するため、2 つの貢献は独立しています。 

空のプレフィックスはバランスがゼロであり、人為的に修正をトリガーすべきではないため、最小プレフィックスの初期化には注意が必要です。

 残高がマイナスになることはないため、プレフィックス補正は 0 です。 最終的な残高は 1 なので、余剰を修正するには閉じ括弧が 1 つ必要で、答えは 1 になります。ただし、構造は変形したフォームに埋め込むことができる必要があるため、接尾語吸収ルールによって追加の調整が 1 つ必要であり、この場合は固有の妥当性により 0 になります。 

このトレースは、パスがゼロを下回らない場合、唯一の懸念は最終余剰であり、構造がすでに変形されたオブジェクトの有効なプレフィックスのように動作していることを示しています。

これは、単一の閉じ括弧によって構造が完全に上方にシフトされるという重要なエッジ ケースを示しています。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        bal = 0
        min_pref = 0
        for c in s:
            bal += 1 if c == '(' else -1
            min_pref = min(min_pref, bal)

        need_prefix = -min_pref
        need_suffix = bal if bal > 0 else 0

        out.append(str(need_prefix + need_suffix))

    return "\n".join(out)

 ## 特殊なケース

 "))))" のような右括弧のみで構成される文字列は、すべてのステップで接頭辞の合計を直ちに負の値にします。 最小のプレフィックスは -4 になるため、アルゴリズムでは先頭に 4 つの左括弧が正しく必要になります。 サフィックスのバランスはすでに正ではないため、追加の修正は必要ありません。 これにより、純粋な赤字のケースは完全にプレフィックス リフティングによって処理されることが確認されます。 

"(((" のような文字列は負になることはありません。そのため、接頭辞の修正はゼロですが、余剰残高 3 で終了します。アルゴリズムは 3 つの閉じ括弧を接尾辞に割り当て、残りの開始部分を最後に解決する必要があるという要件に一致します。
