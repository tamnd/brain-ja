 ## 解決策
 ## 問題の理解

 単純な一次関数モジュロを使用して構築された、2 次元平面上の点の大きなセットが与えられます。$n$。 具体的には、各点には座標があります$(x, y)$どこ$x$からの範囲$0$に$n-1$、 そして$y = (a \cdot x + b) \bmod n$。 これにより、正方形のグリッドを囲む点の離散的な「格子」が生成されます。$[0, n-1] \times [0, n-1]$。 

この問題では、現在の点セットの凸包を繰り返し計算し、その境界上にあるすべての点を削除し、削除する前に 2 倍になった包の面積を報告することが求められます。 この操作が適用されるのは、$k$回。 出力は次のシーケンスです。$k$整数。それぞれはそのステップでの 2 倍の領域を表します。 

制約は極端です。$n$到達できる$10^9$そのため、すべてのポイントを明示的に保存することができなくなります。$k$は比較的小さく、最大 300 です。モジュロ演算により、点は特定の繰り返しで格子パターンを形成します。この構造は、すべてを列挙することなく凸包領域を効率的に計算するための鍵となります。$n$ポイント。 

明らかではないエッジケースには、次のような状況が含まれます。$a = 0$、すべての点が水平線上に配置されます。 もう一つは$a = 1$そして$b = 0$小さいもので$n$、グリッドの対角線に沿って点を生成します。 どちらの場合も、凸包は単純な線または正方形ですが、すべてを生成しようとする単純なアルゴリズムです。$n$ポイントがメモリと時間の制限を超える可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、明示的にすべてが生成されます。$n$ポイントを作成し、グラハム スキャンやアンドリューのモノトーン チェーンなどの標準の凸包アルゴリズムを使用します。 各船体の計算は次のとおりです。$O(N \log N)$どこ$N$残りのポイント数です。 後$k$操作を実行すると、合計ランタイムがそれに近づく可能性があります$O(k \cdot n \log n)$。 と$n = 10^9$、これはまったく不可能です。 

重要な観察は、モジュラー算術では点が直線上にあるということです。関数$y = (a x + b) \bmod n$回り込みますが、秩序は維持されます。 最小値と最大値の観点から凸包を視覚化できます。$y$それぞれの値$x$、船体の「角」は常に、線が正方形の境界と交差する点に対応します。$0$そして$n-1$。 本質的に、このモジュロ格子セットの凸包は、頂点の数が予測可能で、数が少ない多角形を形成します。$n$。 

この洞察により、すべてを列挙するのではなく、極値のみを使用して式によって凸包面積を計算できるようになります。$n$ポイント。 これらのハル ポイントを削除すると、残りのセットは元のセットの縮小バージョンになるため、このプロセスを繰り返すことができます。$k$分析的には何回も。 したがって、複雑さは次のとおりです$O(k)$、独立して$n$、制限内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * n log n) | O(n) | 遅すぎる |
 | 最適 | O(k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての点を生成せずに、セットの極点を計算します。 させて$x_{\min} = 0$、$x_{\max} = n-1$、そして計算します$y_{\min} = b \bmod n$、$y_{\max} = (a (n-1) + b) \bmod n$。 これらの点は、最初の凸包の角を形成します。 
2. これらのコーナーの靴紐公式を使用して、凸包の 2 倍の面積を計算します。 モジュールラップにより船体は事実上、平行四辺形または台形になるため、算術演算の数が少なくなります。 
3. 概念的にハル ポイントを削除します。 削除後、残りの点のセットは格子の高さが小さくなります。これは、垂直方向の境界を 1 縮小することで表すことができます。 
4. 上記を繰り返します$k$繰り返し、各ステップで境界を更新します。 いずれかの反復で境界が崩れる (セットが空になる) 場合は、後続の領域に 0 を出力します。 

機能する理由: モジュロに基づいたポイントの構造により、凸包の頂点が予測可能かつ制限されます。 各ステップで境界を削除すると、セットの有効な「高さ」が減少し、後続のハルに対して同じパターンが維持されます。 すべてを列挙することは決してないので、$n$ポイント、この方法は非常に大規模な場合でも拡張可能$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def doubled_area(n, a, b, k):
    results = []
    h_min = 0
    h_max = n - 1
    for _ in range(k):
        if h_min > h_max:
            results.append(0)
            continue
        # the convex hull forms a rectangle in modulo grid
        width = h_max - h_min
        height = (a * width) % n
        area2 = width * height * 2
        results.append(area2)
        # remove hull, shrink bounds
        h_min += 1
        h_max -= 1
    return results

def main():
    n, a, b, k = map(int, input().split())
    for area2 in doubled_area(n, a, b, k):
        print(area2)

if __name__ == "__main__":
    main()
```このアルゴリズムは、垂直方向の境界を介してセットの最小限の表現を使用します。`h_min`そして`h_max`ポイントを含む有効な行を追跡します。 2 倍の面積の計算には、これらの境界のみが使用されます。 増加と減少`h_min`そして`h_max`それぞれの外皮を除去した後、巨大な配列を作成せずに剥離をシミュレートします。 このアプローチにより、境界計算における off-by-one エラーが回避され、整数領域が保証されます。

## 複雑さの分析

 | --- | --- | --- |

## 特殊なケース

 のために`n = 1, a = 0, b = 0, k = 2`、初期セットには 1 つのポイントがあります。 最初の凸包の面積は 0 で、削除後はセットが空になるため、2 番目の凸包の面積も 0 になります。アルゴリズムは、次のことを確認することでこれを正しく処理します。`h_min > h_max`そして0を返します。 

のために`a = 0`、すべての点は水平線上にあります。 凸包はエリア 0 の線です。アルゴリズムは `h を追跡します。
