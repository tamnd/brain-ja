 ## 解決策
 ## 問題の理解

 値ゼロが特別な役割を果たす整数の配列が与えられます。 可能な限り多くの素なインデックスのトリプルを抽出したいと考えており、各トリプルは非常に厳密な構造を持つ必要があります。つまり、ゼロ、次にゼロ以外の値、次に別のゼロのように見える必要があります。 形式的には、選択された各トリプルは位置を使用します$i < j < k$両端が 0 で、中央の要素が 0 以外になるようにします。 

異なるトリプルを結合する 2 つのグローバル制約があります。 まず、選択されたすべての中間要素は値が異なる必要があるため、2 つの異なるトリプルで同じ非ゼロの数値を再利用することはできません。 第 2 に、すべてのトリプルで使用されるすべてのインデックスは素である必要があるため、あるポジションが 1 つのトリプルで使用されると、そのポジションは永久に使用できなくなります。 

課題は、そのようなトリプルをどれだけ多く構築できるかを最大化することです。 

制約は大きく、すべてのテスト ケースの合計長は最大 500,000 です。 これにより、値ごとにすべてのトリプル、さらにはすべてのゼロのペアを試行するアプローチは即座に除外されます。 二次関数の何か$n$失敗するだろうし、さらには$O(n \log n)$実際には慎重に線形にする必要があります。 

グローバル インデックスの消費を考慮せずに貪欲なペアリングが実行されると、微妙な障害モードが発生します。 たとえば、ゼロが豊富にあるものの分散しており、値が貪欲に再利用されている場合、ローカルで有効なトリプルが形成され、より適切なグローバル割り当てがブロックされる可能性があります。 もう 1 つの問題は、各値が独立して寄与すると仮定することです。$\min(\#zeros, 1)$、値間のゼロの競合を無視します。 

小さな例として、次のことを考えてみましょう。 

入力:```
1
6
0 1 0 2 0 0
```単純な値ごとの貪欲なアプローチでは、1 と 2 の両方に周囲のゼロを割り当てようとしますが、同じゼロは再利用できないため、トリプルは 1 つだけ可能です。 

共有リソース (ゼロ) と排他的な中間値の間のこの相互作用が重要な問題です。 

## アプローチ

 ブルートフォース戦略では、有効なトリプルをすべて列挙しようとします。$(i, j, k)$あらゆるミドルポジションに対応$j$、次に、個別の中間値を持つ素のトリプルの最大セットを選択してみます。 これは当然、最大マッチングまたはセットパッキングの問題になります。 ゼロを再利用可能なエンドポイントとしてモデル化し、ゼロ以外の各位置を潜在的な中心としてモデル化し、次に左右のゼロの割り当てを検索することができます。 ただし、トリプル候補の数は$O(n^2)$最悪の場合、各非ゼロは両側で多くのゼロとペアになる可能性があるためです。 すべての候補を構築するだけでもすでに大きすぎます。 

重要な観察は、どの特定のゼロが組み合わせ的に末尾で使用されるかを考慮する必要がないということです。 ゼロは同一のリソースです。 カウントだけが重要です。 全体的に重要なのは、選択した中間位置の左右に使用可能なゼロがいくつ存在するかです。 

中間値を固定すると$x$、他のトリプルによってすでに消費されているゼロを考慮した後、その前に少なくとも 1 つのゼロが存在し、その後に少なくとも 1 つのゼロが存在するかどうかを知る必要があるだけです。 これは、選択された中央のそれぞれにちょうど 2 つのゼロを割り当てる方法で、値を貪欲に処理することを示唆しています。 

ポジションの幾何学的な観点から考える代わりに、リソース割り当ての観点に移ります。 スキャン中に配列内で利用可能なゼロを維持し、選択された各中央が正確に 2 つのゼロを消費するようにトリプルを割り当てようとします。 難しいのは、左右のゼロが異なる側から来ることを強制することであり、これは順序の問題を意味します。 

これを解決する標準的な方法は、ゼロをプールとして扱いますが、配列をスイープすることで順序を尊重することです。 中間の候補を検討するとき、左側の 1 つの未使用のゼロと右側の 1 つの未使用のゼロとの一致を試みます。 右側のゼロは重要な制約です。 将来の構造を時期尚早に消費しないようにする必要があります。 

これは貪欲な戦略につながります。利用可能なゼロをスキャンして維持し、可能な限りトリプルを形成しようとしますが、各中間が最大 1 回使用され、各トリプルが 2 つのゼロを消費するようにします。 最適性は、ゼロが交換可能であり、それらの合計の可用性のみが答えを制限するという事実から来ています。

 | トリプルのブルートフォース列挙 + 選択 |$O(n^2)$それより悪い |$O(n^2)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 この問題を、選択された各中間位置に 2 つの異なるゼロ位置 (その前後に 1 つずつ) を割り当てることができ、ゼロが再利用されないように、できるだけ多くの中間位置を選択するという問題を再定式化します。 

1. 配列をゼロの位置と非ゼロの位置に分割します。 ゼロ以外の位置のみをトリプルの中央の候補として考慮します。 ゼロは消耗リソースであり、左右の割り当てに分割する必要があります。 
2. これまでに確認された未使用のゼロの数を維持しながら、配列を左から右にスキャンします。 この値は、現在使用可能な左側のエンドポイントの数を表します。 
3. 右側にゼロが何個残っているかも維持します。 これは、接尾語のゼロのカウントとして事前に計算できます。 
4. ポジションごとに$j$と$a_j \neq 0$、左側に少なくとも 1 つの未使用のゼロが存在し、右側に少なくとも 1 つのまだ使用可能なゼロが存在する場合にのみ、それを中間の候補とみなします。 これにより、その周りに有効なトリプルを形成できることが保証されます。 
5. 真ん中を選択した場合$j$、左側のプールから 1 つのゼロをすぐに消費し、右側のプールから 1 つのゼロを暗黙的に予約します。 次に、重複が選択されないように、この中間の値を使用済みとしてマークします。 
6. 可能であれば常に有効な中間を貪欲に選択しながら、スキャンを続けます。 選択されたミドルの数が答えです。 

重要な設計上の選択は、位置を明示的に選択するのではなく、右側のゼロを減少する予算として扱うことです。 これにより二重カウントが回避され、実現可能性が保証されます。 

なぜそれが機能するのかは、グローバル交換の議論と結びついています。 最適解が中間のセットを選択すると仮定します。 割り当てを並べ替えて、各中央が可能な限り最も早い利用可能な左ゼロと最も遅い利用可能な右ゼロを使用することができます。 この正規化によって実現可能性が低下することはありません。 この正規化の下では、両方のリソースが利用可能な場合に常に中間を選択する貪欲なスキャンは、将来のより良いソリューションをブロックすることはありません。これは、左側のゼロを早期に消費することは将来の柔軟性を高めるだけであり、右側のゼロはアイデンティティではなく合計カウントによってのみ制約されるためです。 

したがって、このアルゴリズムは、可能な限り多くの中間頂点を限られたゼロのバジェットに効果的にパックし、それぞれの頂点がシーケンス全体でそのバジェットの 2 ユニットを分割する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        total_zeros = sum(1 for x in a if x == 0)

        left_zeros = 0
        used_middle = set()
        ans = 0

        # remaining zeros to the right
        right_zeros = total_zeros

        for x in a:
            if x == 0:
                left_zeros += 1
                right_zeros -= 1
            else:
                if x in used_middle:
                    continue
                # try to form a triple centered at x
                # need at least 1 zero on each side
                if left_zeros > 0 and right_zeros > 0:
                    used_middle.add(x)
                    ans += 1
                    left_zeros -= 1
                    right_zeros -= 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、単一の左から右へのスイープに依存します。 変数`left_zeros`現在の位置の左側に利用可能なゼロが何個あるかをカウントします。 変数`right_zeros`はゼロの合計数として初期化され、先に進むにつれて減分されるため、右側に残っているゼロの数が常に反映されます。 

ゼロ以外の値が見つかった場合、その値の使用は 1 回だけ試行されます。`used_middle`設定し、中間値の区別を強制します。 両方の側に少なくとも 1 つの使用可能なゼロがある場合、貪欲にトリプルを形成し、各側の予算から 1 つのゼロを消費します。 

微妙な点は、どのゼロ インデックスを使用するかを明示的に選択していないことです。 正しさは、カウントだけが重要であるという事実に依存します。これは、左右の分割によってすでに捕捉されている順序制約を除いて、ゼロは区別できないためです。

 ## 特殊なケース

 重要なエッジ ケースは、ゼロが存在するが、潜在的な中間要素の片側に集中しすぎている場合です。 考慮する：```
0 0 1 0 0
```アルゴリズムは左側のゼロを徐々に割り当てます。 中央の値 1 に達すると、左右のゼロ プールは両方とも空ではないため、正確に 1 つのトリプルを形成します。 消費後は、それ以上のトリプルは不可能であり、異なる非ゼロが 1 つだけ存在するため、最適解と一致します。 

もう 1 つのエッジ ケースは、複数のゼロ以外の値が表示されるが、対称配置をサポートするにはゼロが不十分である場合です。```
0 1 2 3 0
```ここでは、中央の値の 1 つだけを使用できます。これは、1 つを選択した後、残りの構造が別の値の両側ゼロ割り当てをサポートできないためです。 貪欲なアプローチにより、ゼロが部分的に消費されると、後の候補の実現可能性が正しく低下します。 

最後に、ゼロが豊富だが中間が繰り返される場合:```
0 1 0 1 0 1 0
```各値の最初の出現のみが使用可能です。 の`used_middle`制約を使用すると、たとえローカル ゼロの可用性があればそれが可能であっても、同一の値を誤って二重にカウントすることがなくなります。
