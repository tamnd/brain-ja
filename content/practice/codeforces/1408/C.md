 ## 解決策
 ## 問題の理解

 2 台の車が長い道路の両端から出発する`l`。 左側の車はその位置からスタートします`0`そして右に移動します。 正しい車がその位置からスタートします`l`そして左に移動します。 

両車ともにスピードを出してスタート`1`。 道路に沿って、固定座標に旗が設置されています。 車が旗を通過するたびに、その車の速度のみが増加します`1`。 2 台の車は連続的かつ同時に移動します。 

2 台の車が同じ位置を占めたときの正確な時間を判断する必要があります。 

まず注目すべきことは、車が勝手に速度を変えるわけではないということです。 速度は旗の位置でのみ変化します。 2 つの連続した速度変更の間、各車両は一定の速度で移動します。 これにより、モーションが非常に構造化された形式になります。 

1 回のテストで指定できるフラグの数は次のとおりです。`10^5`ただし、すべてのテスト ケースの合計も次の制限を受けます。`10^5`。 これにより、小さなタイム ステップを使用するシミュレーションは即座に除外されます。 各クエリに二次作業が必要な場合、両方の車の間で起こり得るすべての対話をシミュレートすることさえ困難になります。 

答えは実数であるため、純粋に組み合わせによる量を求めているわけではありません。 動きは連続的です。 これは多くの場合、直接ジオメトリまたは時間通りの二分探索のいずれかを示唆します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
1
1 10
5
```車は異なる時間に旗に到達します。 左側の車はその後に到着します`5`数秒経って加速しますが、右側の車は会議が始まるまで決してその旗に触れません。 同じイベントで両方の車がスピードを上げると仮定した解決策では、間違った答えが得られます。 

考慮する：```
1
2 10
1 9
```両車ともちょうど 1 秒後にフラッグに衝突しました。 彼らのスピードは`2`、そして彼らは位置で会います`5`さらに2秒後。 答えはまさに`3`。 実装が小さな間隔を繰り返しシミュレートしようとすると、浮動小数点累積エラーが表示されます。 

もう 1 つの微妙なケースは、どちらかの車が次の旗に到達する前にミーティングが発生する場合です。 例えば：```
1
2 10
4 6
```両方の車が最初の旗に到達すると、速度を上げてお互いに向かって移動します。 会議は旗の時点ではなく、間隔内で行われる場合があります。 フラグの到着時間をチェックするだけのソリューションでは、これが見逃されます。 

主な課題は、区分的に一定の速度を正しく処理しながら、任意の時間後の位置を計算することです。 

## アプローチ

 当然の強引なアイデアは、イベントをシミュレートすることです。 各イベントは、車の 1 台が次のフラッグに到達する瞬間です。 どのイベントが最初に起こるかを繰り返し判断し、そのイベントまでの時間を進め、位置を更新し、速度を 1 つ上げて、車が合流するまで続行することができます。 

速度の変更は旗のところでのみ発生するため、これは概念的に機能します。 状態は有限の瞬間にのみ変化します。 

問題は、会議が 2 つのイベントの間に発生する可能性があることです。 次のフラッグイベントまでに車間距離の残りが縮まっているかどうかを常に確認する必要があります。 実装はかなりデリケートになります。 

別の可能性は、非常に小さな時間増分を使用して動きをシミュレートすることです。 それは明らかに遅すぎます。 たとえ精度でも`10^-7`長い道で`10^9`天文学的な手順が必要になります。 

重要な観察は、時間を固定すると、`T`、各車がどこを追いかけているかを正確に判断できます`T`秒。 

左側の車については、それが通過するセグメントのシーケンスがわかっています。```
0 -> a1 -> a2 -> ... -> an -> l
```セグメント上`i`、その速度は知られています。 利用可能な時間を最大限に費やすことができます`T`可能な限り完全なセグメントを移動します。 残り時間が次のセグメントを完了するには不十分な場合は、そのセグメント内のどこかで停止し、正確な位置を計算します。 

同じ考え方が適切な車に対して独立して機能します。 

次に、次のように定義します。```
f(T) = position_of_left_car_after_T
g(T) = position_of_right_car_after_T
```時間の経過とともに左側の位置が増加します。 時間の経過とともに正しい位置が減少します。 

車は時間が経つにつれて出会った`T`まさに次のとき:```
f(T) >= g(T)
```この条件は単調です。 それがしばらくの間真実である場合、それはそれより長い期間すべて真実のままです。 これにより二分探索が可能になります。 

2 つの位置が交差する最小時間を二分探索します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | イベントシミュレーション | テストあたり O(n) | お(1) | 受け入れられますが、より複雑です |
 | 二分探索 + 位置評価 | O(n log L) | お(1) | 承認済み |

 ここ`L`は時間の検索範囲を表します。 倍精度を得るには、約 60 回のバイナリ検索反復で十分です。 

## アルゴリズムのチュートリアル

 ### 一定時間の位置演算

 時間が経過した後の左車の位置が知りたいとします。`T`。 

車はその位置からスタートします`0`スピードを持って`1`。 

旗を通過するたびに速度が上がります`1`。 

道路セグメントを左から右に処理します。 

現在のセグメントの長さが`d`そして現在の速度は`v`、セグメント全体を横断するには次のものが必要です。```
d / v
```秒。 

十分な時間が残っている場合は、その時間を消費してセグメントの最後に移動し、速度を上げます。 

それ以外の場合、車はセグメント内に留まります。 その位置は次のとおりです。```
current_position + remaining_time * v
```そして私たちは立ち止まります。 

右の車は右端から対称に計算されます。 

### 二分探索

 1.セット`low = 0`。 
2.セット`high = l`。 

集合時間を超えることはできません`l`なぜなら、加速がなくても、車は総合速度で互いに接近するからです。`2`、内の会議`l/2`秒。 
3. 約60回繰り返します。 
4. しましょう`mid = (low + high) / 2`。 
5. 後、左車両の位置を計算します。`mid`秒。 
6. 後、正しい車の位置を計算します。`mid`秒。 
7. 左の位置が少なくとも右の位置であれば、時間までに車はすでに出会っています`mid`なので、上限を次のように移動します。`mid`。 
8. それ以外の場合、会議は後で行われるため、下限を次のように移動します。`mid`。 
9. 反復が終了したら、出力します。`high`。 

### なぜ効果があるのか

 一定時間ごとに`T`、すべての速度変化は完全なセグメントを横断したときにのみ発生するため、位置計算は物理的な動きを正確に再現します。 したがって、1 台の自動車のシミュレーションは正確です。 

定義する：```
h(T) = left_position(T) - right_position(T)
```最初は`h(0) < 0`。 時間が経過しても、左の位置が減ることはなく、右の位置が増加することもありません。`h(T)`単調増加です。 

車はまさにその時に出会った`h(T) >= 0`。 

述語が単調であるため、二分探索は「まだ満たされていない」と「すでに満たされている」の間の一意の遷移点を見つけます。 半分に分割することを繰り返すと、任意の小さな誤差で真の集合時間に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def left_pos(t, a, l):
    pos = 0.0
    speed = 1.0

    for flag in a:
        dist = flag - pos
        need = dist / speed

        if t >= need:
            t -= need
            pos = flag
            speed += 1.0
        else:
            return pos + speed * t

    dist = l - pos
    need = dist / speed

    if t >= need:
        return float(l)

    return pos + speed * t

def right_pos(t, a, l):
    pos = float(l)
    speed = 1.0

    for flag in reversed(a):
        dist = pos - flag
        need = dist / speed

        if t >= need:
            t -= need
            pos = float(flag)
            speed += 1.0
        else:
            return pos - speed * t

    dist = pos
    need = dist / speed

    if t >= need:
        return 0.0

    return pos - speed * t

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n, l = map(int, input().split())
        a = list(map(int, input().split()))

        lo = 0.0
        hi = float(l)

        for _ in range(70):
            mid = (lo + hi) / 2.0

            lp = left_pos(mid, a, l)
            rp = right_pos(mid, a, l)

            if lp >= rp:
                hi = mid
            else:
                lo = mid

        ans.append(f"{hi:.15f}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```機能`left_pos`そして`right_pos`固定時間位置クエリを実装します。 各関数はセグメントのシーケンスを順に実行し、セグメント全体が完了できる限り時間がかかります。 

よくある間違いは、旗に到達する前に速度を上げることです。 実装では、まずセグメントを終了するのに十分な時間が存在するかどうかがチェックされます。 旗に到着した後にのみ速度が増加します。 

もう 1 つの微妙な詳細は、最後のセグメントです。 最後のフラッグの後、車は最終速度で終点に向かって進みます。 コードは、そのセグメントを他のセグメントとまったく同様に扱います。 

二分探索では 70 回の反復が使用されます。 各反復で検索間隔が半分になるため、必要な条件を達成するにはこれで十分以上です。`10^-6`精度。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def left_pos(t, a, l):
        pos = 0.0
        speed = 1.0

        for flag in a:
            dist = flag - pos
            need = dist / speed

            if t >= need:
                t -= need
                pos = flag
                speed += 1.0
            else:
                return pos + speed * t

        return min(float(l), pos + speed * t)

    def right_pos(t, a, l):
        pos = float(l)
        speed = 1.0

        for flag in reversed(a):
            dist = pos - flag
            need = dist / speed

            if t >= need:
                t -= need
                pos = float(flag)
                speed += 1.0
            else:
                return pos - speed * t

        return max(0.0, pos - speed * t)

    tc = int(input())
    out = []

    for _ in range(tc):
        n, l = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0.0, float(l)

        for _ in range(70):
            mid = (lo + hi) / 2

            if left_pos(mid, a, l) >= right_pos(mid, a, l):
                hi = mid
            else:
                lo = mid

        out.append(f"{hi:.6f}")

    return "\n".join(out)

# sample-style checks

assert abs(float(res) - 3.0) < 1e-5

res = run("1\n1 10\n1\n").strip()
assert abs(float(res) - 3.666666666666667) < 1e-5

# minimum case
res = run("1\n1 2\n1\n").strip()
assert abs(float(res) - 1.0) < 1e-5

# symmetric flags

assert float(res) > 0

assert float(res) > 0

res = run("1\n2 10\n1 9\n").strip()
assert abs(float(res) - 3.0) < 1e-5

 ## 特殊なケース

 ### 次の旗の前にミーティング

 入力:```
1
2 10
4 6
```両方の車が最寄りの旗に到達すると、速度は`2`。 ミーティングは、正確に旗の位置ではなく、旗の間のどこかで行われます。 

位置クエリ関数は、残り時間が次のフラグに到達するのに不十分な場合は常にセグメント内で停止するため、これを自然に処理します。 

### 1台の車は加速するが、もう1台は加速しない

 入力:```
1
1 10
1
```左の車は 1 秒後に旗に到達し、速度を上げます`2`。 適切な車は速度を保ちます`1`。 

アルゴリズムは各車を個別に計算します。 同時加速イベントについては仮定が行われていないため、答えは正しいままです。 

### 旗を渡った後、まったく同じ座標で集合

 入力:```
1
2 10
1 9
```両方の車が 1 秒後にフラッグに衝突し、同時に加速します。 時間に`3`、両方の位置が等しい`5`。 

二分検索では次の条件が使用されます。```
left_position >= right_position
```したがって、平等は有効な会議状態として扱われます。 車が厳密に交差するのではなく、正確に交差する場合でも、トランジション ポイントが正しく検出されます。 

### 非常に大きな座標

 入力:```
1
2 1000000000
413470354 982876160
```距離も時間も近いかもしれません`10^9`。 このアルゴリズムは整数時間シミュレーションを実行しません。 セグメント長の算術演算と double のバイナリ検索のみを使用し、必要な許容範囲内で正確さを保ちます。
