 ## 問題の理解

 それぞれが少なくとも指定された整数と同じ大きさの、負ではない個別の整数の配列が与えられます。$k$、そして私たちは実行します$k$配列上のランダムなデクリメント。 毎秒、次のいずれかが$n$要素は均一にランダムに選択され、1 ずつ減らされます。すべての減分の後、すべての要素のビットごとの XOR が 0 から 0 までの各可能な値と等しい確率が必要になります。$2^c-1$。 確率は、以下を表すモジュラー整数として返されます。$p \cdot q^{-1} \bmod 998244353$分数の場合$p/q$。 

入力制約は次のことを意味します。$n$せいぜい$2^c - k$、$k \le 16$、 そして$c \le 16$。 以来$k$が小さい場合、デクリメントの数を考慮して動的計画法を検討することが可能です。 可能な XOR 結果の数は次のとおりです。$2^c$可能なすべての減分シーケンスを明示的に追跡する単純なアプローチでは、指数関数的に増加します。$k$そして実行不可能$k=16$より大きな配列を使用します。 小さいもの$k$bound は、組み合わせまたは変換ベースのソリューションが実行可能であることを示唆しています。 

明らかではないエッジケースが発生するのは次の場合です。$k = 1$または$n = 1$。 たとえば、次の場合$n = 1$、$a_1 = k = 1$、 そして$c = 2$の場合、単一のデクリメントによって唯一の要素が 1 ずつ減らされるため、XOR は決定的になります。 減分ごとに複数のオプションを想定する不注意な DP は、不可能なイベントの平均を誤って算出する可能性があります。 もう 1 つのエッジ ケースは、すべての要素が等しい場合、またはデクリメント後に一部の要素がすでに 0 である場合です。 XOR 確率はまばらになり、モジュラー演算の正確な処理が必要になります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのシーケンスを列挙します。$k$減少します。 毎秒、すべてを試します$n$選択肢を選択し、結果の XOR を再帰的に計算します。 これにより、$n^k$可能なシーケンス。 最悪の場合に備えて$n = 2^c - k = 65520$そして$k = 16$、これはまったく不可能です。 小さい方でも$n$、各シーケンスの可能な各 XOR の確率を保存すると、すぐにメモリと時間の制約を超えます。 

重要な洞察は、各要素が組み合わせの意味で独立してデクリメントされ、モジュロ 2 加算では XOR が線形であることを認識することで得られます。 これは、**XOR 値とデクリメント数を組み合わせた動的プログラミング アプローチ**を使用することを示唆しています。 各要素は、デクリメントされる回数の多項分布に寄与します。 小型用$k$では、各要素の確率を個別に計算し、XOR 畳み込みを要素ごとの乗算に変換する **ウォルシュ アダマール変換 (WHT)** を使用してそれらを効率的に組み合わせることができます。 WHT は XOR の線形性を利用し、確率分布を次のように組み合わせることを可能にします。$O(2^c \cdot c)$の代わりに$O((2^c)^n)$。 

ブルートフォースアプローチは概念的には単純ですが、指数関数的です。$k$そして$n$。 WHT を使用すると、XOR の線形性を利用して、各要素の確率分布を表す関数を生成します。 これにより、すべての XOR 結果のモジュロに対する正確な確率分布が生成されます。$998244353$。

 ## アルゴリズムのチュートリアル

 1. まず、モジュラー逆関数を事前計算します。$n$モジュロ$998244353$各減少は全体に均一に分散されるため、$n$要素。 これにより、各ステップで任意の要素が選択される確率を表すことができます。 
2. 要素の確率分布を次のように表します。$k$減少します。 各要素$a_i$0からデクリメントできます$k$回。 正確に減少する確率$d$時間は多項係数で与えられます$\binom{k}{d} \cdot (1/n)^d \cdot ((n-1)/n)^{k-d}$。 
3. 配列を構築する`dp`長さの$2^c$各 XOR 値の確率を表します。 初期化する`dp[a_1] = 1`最初の要素の場合、他のエントリはゼロです。 確率はモジュロで保存されます$998244353$分数に対して逆モジュラーを使用します。 
4. 後続の各要素に対して、**ウォルシュ-アダマール変換**を適用します。`dp`要素の分布配列。 変換された配列を要素ごとに乗算し、逆変換を実行します。 この畳み込みは、XOR に基づいて独立した確率を効果的に組み合わせます。 
5. すべての要素が処理された後、`dp[x]`XOR = の最終確率が含まれます。$x$。 各確率に合計シーケンスの逆モジュラーを乗算します。$(n^k)$正常化すること。 
6. 出力`dp[x]`モジュロ$998244353$みんなのために$x \in [0, 2^c - 1]$。 

これが機能する理由は、WHT が元の領域では点単位ではない XOR 畳み込みを点単位の乗算に変換するためです。 変換、乗算、逆変換を行うことで、要素のデクリメント XOR をすべての方法で指定した値まで正確に合計を計算します。 すべてのデクリメント数を組み合わせて考慮するため、シーケンスが省略されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def walsh_hadamard(a, invert):
    n = len(a)
    h = 1
    while h < n:
        for i in range(0, n, h * 2):
            for j in range(i, i + h):
                x = a[j]
                y = a[j + h]
                a[j] = (x + y) % MOD
                a[j + h] = (x - y + MOD) % MOD
        h *= 2
    if invert:
        inv_n = modinv(n)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def solve():
    n, k, c = map(int, input().split())
    a = list(map(int, input().split()))
    size = 1 << c
    dp = [0] * size
    dp[a[0]] = 1
    inv_n = modinv(n)
    
    # Precompute probability distribution for one element
    from math import comb
    elem_prob = [0] * (k + 1)
    for d in range(k + 1):
        elem_prob[d] = comb(k, d) * pow(inv_n, d, MOD) * pow((n - 1) * inv_n % MOD, k - d, MOD) % MOD
    
    for i in range(1, n):
        # Construct array of length 2^c for this element's XOR probabilities
        f = [0] * size
        for d in range(k + 1):
            f[a[i] - d] = elem_prob[d] if (a[i] - d) >= 0 else 0
        # Transform both dp and f
        walsh_hadamard(dp, False)
        walsh_hadamard(f, False)
        for j in range(size):
            dp[j] = dp[j] * f[j] % MOD
        walsh_hadamard(dp, True)
    
    print(" ".join(map(str, dp)))

if __name__ == "__main__":
    solve()
```このコードは、最初の要素の確率分布を初期化し、要素の減分ごとに組み合わせ確率を事前計算し、WHT を適用して分布を効率的に組み合わせます。 逆モジュラは、モジュロ演算で分数を正しく処理します。 要素の減分がその値を超える場合、負のインデックスが発生しないように注意が必要です。
