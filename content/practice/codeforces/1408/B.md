 ## 解決策
 ## 問題の理解

 非減少配列が与えられています`a`ここで、各エントリは負ではない整数です。 この配列を次の合計に分割したいと考えています。`m`配列`b₁, b₂, ..., bₘ`それぞれが`bᵢ`また、減少することはなく、強い構造上の制限があります。つまり、最大でも次の値を使用します。`k`明確な価値観。 

それぞれのポジションで`j`、すべての配列の値を正確に合計する必要があります。`a[j]`。 したがって、各インデックスの「高さ」を複数のモノトーン シーケンスに分散させますが、異なる値が多すぎることができないという意味で、各シーケンス自体は単純でなければなりません。 

タスクは、そのようなシーケンスの最小数を見つけるか、それが不可能であると判断することです。 

制約は小さいです。`n ≤ 100`、`a[j] ≤ 100`、最大 100 個のテスト ケース。 これは、およそ次のような解決策が考えられることを示唆しています。`O(n^3)`あるいは慎重にさえ`O(n^2 * k)`許容されます。 ただし、可能な配列の数は指数関数的に増加するため、任意の分解をブルートフォースで構築することは不可能です。`n`。 

主要な構造上の制約は、それぞれの`bᵢ`減っていない。 これは、あるインデックスで値が一度増加すると、その後は減少することはないことを意味します。 「せいぜい」と組み合わせると、`k`それぞれの「異なる価値観」`bᵢ`本質的には最大で次のもので構成されます`k`平坦なセグメント。 

次の場合、微妙なエッジケースが発生します。`a`わずかなギャップを伴いながら厳密に増加しています。 単純に貪欲に分割すると、必要な「価値レイヤー」の数が過小評価される可能性があります。 もう 1 つのエッジケースは次のような場合です`k = 1`： 毎`bᵢ`は一定でなければならないため、実現可能性が大幅に制限されます。 

## アプローチ

 自然な最初の試みは、それぞれについて考えることです。`bᵢ`繰り返し剥がしていく「層」として`a`。 すべての配列は非減少であるため、各層も非減少でなければなりません。 ブルートフォース戦略では、レイヤーを 1 つずつ構築しようとします。有効なレイヤーを繰り返し見つけます。`bᵢ`からそれを引きます`a`、続けます。 

1 つのレイヤーを選択すると、それ以降のすべてのレイヤーが制約されるため、これはすぐに困難になります。 各ステップには多くの有効な分解が考えられ、それらを探索すると指数関数的な分岐につながります。 

重要な観察は、視点を反転することです。 レイヤーを構築する代わりに、配列内の「ジャンプ」を表現するために必要なレイヤーの数を推論します。 値が増加するたびに、`a`、その増加は、個別の値の変更に対応できる十分な層でサポートされている必要があります。 

より具体的には、スキャンを想像してください`a`左から右へ。 値が増加するたびに、`a[j-1]`に`a[j]`、単調性と限界を維持しながら、この成長をサポートするのに十分な容量を層に導入する必要があります。`k`レイヤーごとに異なる値。 各レイヤーは限られた回数だけ「動作を変更」できます（最大でも`k-1`増加します）。 これにより、問題は、単調な「増加イベント」の数をレイヤー全体に分散する必要があるかどうかを数えるという問題に変わります。 

貪欲な構築は次のようになります。レイヤ全体に増分を分散するシミュレーションを行い、個別の値の制限に達するまで既存のレイヤを常に埋め、必要な場合にのみ新しいレイヤを開きます。 

これは、最小限の階層構造の解釈につながります。つまり、各層が吸収できるのは最大でも次のとおりです。`k-1`配列に沿って値が増加します。 したがって、増加分を容量のバケットに貪欲にグループ化します。`k-1`、バケットの数が答えです。

 ## アルゴリズムのチュートリアル

 配列を処理し、次の位置のみに焦点を当てます。`a[j] > a[j-1]`平らなセグメントは構造的な変更を強制しないためです。 

1. すべてのプラスの増加を計算します`d[j] = a[j] - a[j-1]`のために`j ≥ 2`。 このような各位置は、レイヤーによってサポートされなければならない必須の「増加イベント」を表します。 
2. 各ユニットの増加をレイヤーへの割り当てが必要なものとして扱いますが、各レイヤーが最大でも収容できることに注意してください。`k-1`このようなイベントは、許可された制限を超えて新しい個別の値を導入する必要が生じる前に増加します。 
3. 現在のレイヤー数を維持する`m`現在のレイヤー バッチに割り当てられた増加数を追跡するカウンター。 
4. 配列を反復処理し、増加分を現在のバッチに蓄積します。 次に必要な増加量を追加すると容量を超える場合`k-1`、新しいレイヤーを開始し、カウンターをリセットします。 
5. もし`k = 1`、すぐに実現可能性を確認してください。 この場合、すべての`bᵢ`は定数である必要があるため、可能な配列の合計は定数配列の積み重ねからのみ得られます。 これは次の場合にのみ可能です`a`は定数、それ以外の場合の答えは`-1`。 
6. 作成されたレイヤーの総数を出力します。 

### なぜ効果があるのか

 各層は、最大でも次の非減少シーケンスに対応します。`k`個別の値。つまり、最大でも 1 つの値から別の値にのみ遷移できます。`k-1`回。 厳密に増加するたびに、`a`少なくとも 1 つのそのような遷移がレイヤー間のどこかでサポートされるように強制します。 

すべてのレイヤーが追加的かつ独立して寄与するため、容量制限のあるバケットに増加イベントを貪欲に分散することで、必要なレイヤーの数が最小限に抑えられます。 層の数を減らそうとすると、ある層がそれ以上の量を吸収する必要があります。`k-1`増加し、個別値制約に違反します。 逆に、貪欲なパッキングは常に制限を尊重し、容量を無駄にすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        if k == 1:
            ok = all(x == a[0] for x in a)
            print(1 if ok else -1)
            continue

        increases = 0
        layers = 1
        used = 0

        for i in range(1, n):
            if a[i] > a[i - 1]:
                inc = a[i] - a[i - 1]
                used += inc
                if used > k - 1:
                    layers += 1
                    used = inc

        print(layers)

if __name__ == "__main__":
    solve()
```ソリューションは、次の実現可能性を直接チェックすることから始まります。`k = 1`。 その場合、すべての配列は定数である必要があるため、配列の変動は無視されます。`a`すぐに分解できなくなります。 

のために`k ≥ 2`、コードは、現在のレイヤー グループに割り当てられている「増加ユニット」の数を追跡します。 これを超えるたびに`k-1`、新しいレイヤーが作成されます。 値`k-1`が表示されるのは、非減少配列が最大で`k`個別の値は最大で増加する可能性があります`k-1`回。 

微妙な点は、差異が蓄積されるということです`a[i] - a[i-1]`、ポジションをカウントするだけではありません。 これにより、ジャンプが大きくなると、階層化された分解で複数のユニットの増加が必要となるため、それに比例してより多くの容量が消費されます。

 ## 特殊なケース

 いつ`k = 1`の場合、アルゴリズムはすべての要素が等しいかどうかを直ちにチェックします。 入力用`a = [5, 5, 5]`、それは戻ります`1`単一の定数配列で十分だからです。 入力用`a = [0, 0, 1]`、それは戻ります`-1`一定の分解では厳密な増加を生み出すことはできないためです。 

配列に要素が 1 つだけある場合、次のようになります。`n = 1`、 どれでも`k ≥ 1`機能します、そして答えは常にです`1`。 増加が発生しないため、アルゴリズムはこれを自然に処理します。`layers`残る`1`。 

増加量が大きい場合など`a = [0, 0, 10]`と`k = 3`、アルゴリズムはジャンプを次のように正しくカウントします。`10`容量の単位。 各レイヤーで扱えるのは`2`増加し、それが生み出す`5`これは、大きなジャンプを単一のイベントとして扱うのではなく、複数のシーケンスに分散する必要があることを反映しています。
