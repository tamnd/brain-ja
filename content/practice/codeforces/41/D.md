 ## 解決策
 ## 問題の理解

 数字のグリッドがあります。 ポーンは下の行のどこかから開始し、一度に 1 行ずつ上に移動します。 各ステップで、斜め左または斜め右に進む場合があります。 訪問したすべてのセルは、収集されたエンドウ豆の合計にその数字を与えます。 

目標は単に合計を最大化することではありません。 最終的な合計も次の値で割り切れる必要があります。`k + 1`。 すべての有効なパスの中で、合計が最大のパスが必要です。 最大合計自体に加えて、開始列と正確な移動順序を再構築する必要があります。 

ボードには最大でも`100 × 100 = 10,000`細胞。 各セルには次の数字が含まれます。`0`に`9`、したがって、可能な最大のパス合計は最大で`100 × 9 = 900`。 割り算条件は剰余モジュロのみに依存します`k + 1`、 そして`k ≤ 10`, したがって、最大でも`11`明確な残り。 これは、位置と剰余に対する動的プログラミングが快適に適合するという強力なヒントです。 

単純な DFS では、行ごとに 2 回分岐します。 ポーンが正確に上に移動するので、`n - 1`回、パスの数はおよそ`m × 2^(n-1)`。 と`n = 100`、これはまったく不可能です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

すべての有効なパスの合計が次の値で割り切れないと仮定します。`k + 1`。```
2 2 1
11
11
```あらゆるパスが集まります`2`で割り切れます。`2`, したがって、これは有効です。 しかし、ボードを変更すると、次のようになります。```
2 2 2
11
11
```あらゆるパスが集まります`2`で割り切れない`3`。 正しい出力は次のとおりです`-1`。 不注意に実装すると、依然として最大額が出力される可能性があります。 

もう 1 つの微妙なケースは、再構成の方向です。 出力内の移動は下から上に記述されていますが、多くの DP ソリューションは行を上から下に処理します。 再構築が間違った方向で行われた場合、生成されたパスは動きと一致しません。 

例：```
3 3 1
123
456
789
```有効な最適パスは次のとおりです。`8 -> 5 -> 3`これは移動に対応します`R L`下から上に見た場合。 解釈を逆にすると、間違ったパスが生成されます。 

境界列も重要です。 左端の列からは、ポーンは左上に移動できません。 右端の列からは右上に移動できません。 これらのチェックを忘れると、範囲外の遷移が発生します。 

例えば：```
3 2 1
11
11
11
```コラムから`1`、上向きの動きは 1 つだけ合法です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 最下行のすべての開始列を選択し、各ステップで上向きの両方向を再帰的に試行し、収集された合計を計算し、合計が次で割り切れる最適なパスを維持します。`k + 1`。 

これが機能するのは、すべての可能なパスが 1 回だけ探索されるためです。 問題はパスの数です。 それぞれの動きには最大 2 つの選択肢があり、`n - 1`移動するため、単一の開始列で約`2^(n-1)`パス。 と`n = 100`、これは天文学的な大きさです。 

問題の構造からすると、より良い選択肢が得られます。 未来は次の 3 つのことだけで決まります。 

1. 現在の行。 
2. 現在の列。 
3. 現在の合計モジュロ`k + 1`。 

正確な合計自体は割り算には関係なく、その余りだけが問題になります。 これは、動的プログラミングを可能にするキー圧縮です。 

特定の剰余を含む特定のセルに到達したときに達成可能な最大合計を表す DP 状態を定義します。 せいぜいあるので`100 × 100 × 11 = 110,000`状態をすべて効率的に処理できます。 

移行は簡単です。 DP 構築中にセルから 1 行下に移動し、次の数字を追加した後に残りを更新します。 各状態には最大 2 つの発信遷移があります。 

パスを再構築するために、最良の値を取得するために使用された以前の状態を保存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · 2^n) | O(n) | 遅すぎる |
 | 最適なDP | O(n・m・k) | O(n・m・k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`mod = k + 1`。 
2. 定義する`dp[row][col][rem]`セルに到達したときに取得できる最大の合計として`(row, col)`合計残りあり`rem`モジュロ`mod`。 
3. すべての状態を次のように初期化します。`-1`、到達不可能を意味します。 
4. 一番上の行から始めます。 列ごとに`c`、 セット：```
dp[0][c][grid[0][c] % mod] = grid[0][c]
```一番上の行には、パスにセルが 1 つだけ含まれています。 

1. 行を上から下に処理します。 

到達可能なすべての状態について`(row, col, rem)`:

 - に移動してみてください`(row + 1, col - 1)`それが存在する場合。 
- に移動してみてください`(row + 1, col + 1)`それが存在する場合。 

計算:```
new_sum = current_sum + next_digit
new_rem = new_sum % mod
```現在保存されている値よりも大きな合計が得られる場合は、DP テーブルを更新し、親の状態を記録します。 

1. すべての行を処理した後、一番下の行を検査します。 

すべての列の中で`c`、状態を見つけます。```
dp[n-1][c][0]
```最大の合計額で。 

残り`0`で割り切れることを意味します`k + 1`。 

1. そのような状態が存在しない場合は、印刷します。`-1`。 
2. それ以外の場合は、保存されている親ポインタを使用してパスを再構築します。 

再構築中は、下から上に逆方向に移動します。 前の列が現在の列より小さい場合、前方への移動は次のようになります。`R`。 そうでなければそうでした`L`。 

1. 再構築は逆方向に進むため、収集された移動シーケンスを逆にします。 
2. 印刷:

 1. 最大合計。 
2. 1 から始まるインデックスを使用する、最下行の開始列。 
3. 移動文字列。 

### なぜ効果があるのか

 DP の不変条件は次のとおりです。`dp[row][col][rem]`常に、先頭行から次の行までのすべてのパスの中で可能な最大の合計を格納します。`(row, col)`残りの合計は`rem`。 

一番上の行から始まるパスにはセルが 1 つだけ含まれているため、基本ケースは正しいです。 

正当な移動は斜め下方向への移動のみであり、桁を追加した後の新しい余りは古い余りと新しい桁によって一意に決定されるため、すべての遷移は正確さを維持します。 

複数のパスが同じ状態に達する場合は、最大の合計のみを保持することが安全です。 将来の継続は位置と余りにのみ依存するため、合計が小さいほどより良い最終的な答えが得られることはありません。 

すべての有効なパスは最後の行で終わり、剰余があるため、最終的な答えは最適です。`0`は DP テーブルで表され、それらの中から最大値を明示的に選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = -1

n, m, k = map(int, input().split())
mod = k + 1

grid = [list(map(int, input().strip())) for _ in range(n)]

# dp[row][col][rem] = maximum sum
dp = [[[INF] * mod for _ in range(m)] for _ in range(n)]

# parent[row][col][rem] = (prev_col, prev_rem)
parent = [[[None] * mod for _ in range(m)] for _ in range(n)]

# initialize top row
for c in range(m):
    val = grid[0][c]
    r = val % mod
    dp[0][c][r] = val

# transitions
for row in range(n - 1):
    for col in range(m):
        for rem in range(mod):
            cur = dp[row][col][rem]

            if cur == INF:
                continue

            for nc in (col - 1, col + 1):
                if 0 <= nc < m:
                    val = grid[row + 1][nc]
                    new_sum = cur + val
                    new_rem = new_sum % mod

                    if new_sum > dp[row + 1][nc][new_rem]:
                        dp[row + 1][nc][new_rem] = new_sum
                        parent[row + 1][nc][new_rem] = (col, rem)

# find best answer in bottom row
best_sum = INF
best_col = -1

for col in range(m):
    if dp[n - 1][col][0] > best_sum:
        best_sum = dp[n - 1][col][0]
        best_col = col

if best_sum == INF:
    print(-1)
    sys.exit()

# reconstruct path
moves = []

row = n - 1
col = best_col
rem = 0

while row > 0:
    prev_col, prev_rem = parent[row][col][rem]

    if prev_col < col:
        moves.append('R')
    else:
        moves.append('L')

    col = prev_col
    rem = prev_rem
    row -= 1

moves.reverse()

print(best_sum)
print(best_col + 1)
print(''.join(moves))
```DP テーブルには、各状態の最適な合計のみが保存されます。 到達しなかった状態が残る`-1`。 

再構成が容易になるため、この実装ではグリッドを上から下に処理します。 すべてのトランジションは、1 つの法的なポーンの動きに正確に対応します。 

親テーブルには、前の列と前の剰余のみが保存されます。 前の行は常に`row - 1`なので、別途保管する必要はありません。 

微妙な点は、再構築中の動きの解釈です。 下から上に逆方向に移動します。 前の列が現在の列より小さいとします。 これは、前進が左から右に行われたことを意味するため、正しい記号は次のとおりです。`R`。 

もう 1 つの簡単な間違いは、間違った列を印刷することです。 必要な出力は、一番下の行の開始列です。 選択した下段の状態から再構築が始まるため、`best_col + 1`まさに必要な答えです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n · m · (k + 1)) | 各状態は最大 2 つの遷移を試行します。

    parent = [[[None] * mod for _ in range(m)] for _ in range(n)]

    best = INF
    best_col = -1

        else:
            moves.append('L')

        col = pc
        rem = pr
        row -= 1

    moves.reverse()

    return f"{best}\n{best_col + 1}\n{''.join(moves)}"

 ## 特殊なケース

 不可能なケースを考えてみましょう。```
2 2 2
11
11
```ここ`mod = 3`。 すべてのパスは正確に 2 つのセルを経由するため、すべての合計は次と等しくなります。`2`。 以来`2 % 3 != 0`、有効な答えは存在しません。 

DP は状態を残りで満たします`2`、ただし、一番下の行には剰余のある状態が含まれていません。`0`。 アルゴリズムは正しく印刷します`-1`。 

ここでエッジと列の移動を考えてみましょう。```
3 2 1
11
11
11
```コラムから`0`、ポーンは左上に移動できません。 コラムから`1`、右上に移動できません。 

移行中の条件は次のとおりです。```
if 0 <= nc < m:
```無効な動きをフィルタリングします。 範囲外のアクセスは発生しません。 

もう 1 つの注意が必要なケースは、パス再構築の方向です。```
3 3 1
123
456
789
```再構築された先行チェーンは次のとおりです。```
(2,1) <- (1,2) <- (0,1)
```後ろ向きに歩きながら：

 - 前のコラム`2`現在の列へ`1`前進を意味します`L`- 前のコラム`1`現在の列へ`2`前進を意味します`R`移動は次のように後方に収集されます。`LR`、次に反転します`RL`。 

逆にしないと、生成されたパスは実際の走査順序と一致しません。
