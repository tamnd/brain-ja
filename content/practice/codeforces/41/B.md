 ## 解決策
 ## 問題の理解

 Vasya が所定のブール額で開始し、その後火星ドルを売買できる場合に、_n_ 日の終わりに所有できる金額を最大化するように求められます。 毎日ドルの価格があり、Vasya が実行できる売買操作は 1 回のみで、整数のドルを購入し、翌日に完全な整数の価格で販売します。 

入力により、日数、ブール単位の最初の金額、および毎日のドル価格のリストが得られます。 出力は、おそらく一度売買した後にヴァシャが持つことのできるブールの最大量です。 

制約は小さく、日数も初期金額も最大 2000 です。2000 平方の操作はわずか約 400 万回であり、2 秒の制限時間に十分収まるため、二次的にスケールするアルゴリズムが可能になります。 主な課題は効率ではなく、整数の売買動作を正しくモデル化することです。 

いくつかの特殊なケースは明らかではありません。 たとえば、ドル価格が決して上昇しない場合、最適な戦略は決して買わないことであるため、最大金額は初期金額になります。 最初の金額がすべてのドル価格よりも小さい場合、Vasya はドルを購入できず、やはり最大金額は変わりません。 いつも初日に買うという軽率な解決策は、ここで間違った答えを生み出すことになります。 

## アプローチ

 最も単純なアプローチはブルートフォースです。 毎日、その日にドルを買うことを検討してください。 潜在的な購入日ごとに、その後の毎日の売却をシミュレートします。 Vasya が購入できるドル数を計算し (現在のブールを価格で整数除算)、販売価格を掛け、残りのブールを追加して最終合計を計算します。 すべての売買ペアの最大値を追跡します。 

この方法は、考えられるすべての売買決定を列挙しているため、正しいです。 操作回数はおおよそ$O(n^2)$なぜなら、購入を検討する可能性のある n 日ごとに、その後のすべての日を潜在的な売り日としてチェックするからです。 n ≤ 2000 の場合、これは最大 400 万回の操作であり、許容範囲内です。 

少し単純化するための重要な洞察は、特定の日以降の最大販売価格が重要であるということです。 各購入日のその後のすべての日をチェックする代わりに、_i_ 日以降の最大価格を事前に計算できます。 したがって、_i_ 日に購入した場合の利益は単純に次のようになります。`(max_price_after_i - price[i]) * dollars_can_buy`。 これにより、冗長な比較が減り推論が簡素化されますが、ドルと残りのブールの計算には 1 日あたりの整数演算が含まれるため、漸近的には O(n²) のままです。

 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適化された最大トラッキング | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 日数を読み取る`n`そして初期資金`b`、その後、日次価格の配列を読み取ります`a`。 
2. 変数を初期化する`max_money`これは、Vasya がドルを購入しないシナリオを表しています。 
3. 毎日繰り返す`i`買いの可能性のある日として。 Vasya が購入できるドル数を計算します。`b // a[i]`。 ドルを購入できない場合は、次の日にスキップします。 
4. 購入日ごとに`i`、後日毎日繰り返します`j > i`潜在的な売り日として。 Vasyaが当日に売れた場合の最終的な金額を計算する`j`として`dollars_bought * a[j] + leftover_bourles`。 アップデート`max_money`この合計が大きい場合。 
5. 考えられるすべての買い/売りペアを確認した後、印刷します。`max_money`。 

機能する理由: 各反復で、実行可能なすべての売買日を考慮し、計算では整数ドルの購入と残りのブールが考慮されます。 すべての有効なシナリオが列挙されるため、すべての反復にわたる最大値が真の最大値であることが保証されます。 ドルを購入できない日をスキップすると、初期資金が少なすぎるエッジケースの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, b = map(int, input().split())
a = list(map(int, input().split()))

max_money = b

for i in range(n):
    dollars = b // a[i]
    leftover = b % a[i]
    if dollars == 0:
        continue
    for j in range(i + 1, n):
        total = dollars * a[j] + leftover
        if total > max_money:
            max_money = total

print(max_money)
```このソリューションはまず、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 保守します`max_money`まったく買わない可能性を考慮して。 潜在的な購入日ごとに、整数除算により Vasya が購入できるドル数が得られ、モジュロ演算により残りのブールが得られます。 ドルを購入できない場合は反復をスキップします。 ネストされたループでは、考えられるすべての販売日が考慮され、表示される最大金額が更新されます。 整数演算を慎重に使用することで、浮動小数点エラーが発生しないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, b = map(int, input().split())
    a = list(map(int, input().split()))
    max_money = b
    for i in range(n):
        dollars = b // a[i]
        leftover = b % a[i]
        if dollars == 0:
            continue
        for j in range(i + 1, n):
            total = dollars * a[j] + leftover
            if total > max_money:
                max_money = total
    return str(max_money)

# provided sample
assert run("2 4\n3 7\n") == "8", "sample 1"

# minimum-size input
assert run("1 1\n1\n") == "1", "min input"

# prices decreasing
assert run("3 5\n5 4 3\n") == "5", "no profit"

# all-equal prices
assert run("4 10\n2 2 2 2\n") == "10", "no profit all same"

# buy on first day, sell on last
assert run("3 10\n2 5 6\n") == "30", "first to last"

# initial money too small
assert run("3 1\n2 3 4\n") == "1", "cannot buy"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 \n 1 | 1 | 最小入力 |
 | 3 5 \n 5 4 3 | 5 | 価格下落、購入不可 |
 | 4 10 \n 2 2 2 2 | 10 | すべての価格は同じなので、購入する必要はありません |
 | 3 10 \n 2 5 6 | 30 | 初日に買って、最終日に売ると利益が最大化 |
 | 3 1 \n 2 3 4 | 1 | 初期資金が少なすぎて買えない |

 ## 特殊なケース

 初期資金がすべての価格よりも小さい場合、Vasya はドルを購入できません。 例えば、`b = 1`そして価格`[2,3,4]`。 アルゴリズムは計算します`dollars = b // a[i]`毎日を 0 として、すべての反復をスキップして終了します`max_money = b = 1`。 

価格が単調に減少する場合、早期に購入すると当初よりも資金が少なくなるため、購入をスキップすると最大の利益が得られます。 トレースは、アルゴリズムが合計金額を正しく比較していることを確認します。`max_money`各ステップで、より悪い選択肢を選択することはありません。
