 ## 解決策
 ## 問題の理解

 無向グラフを構築する必要があります`n`三角形が存在しないような都市。 三角形は、すべてのペアが直接接続されている 3 つの異なる都市を意味します。 3 サイクルを含まないすべてのグラフの中で、可能な限り最大数の道路を含むグラフが必要であり、また 1 つの有効な構造を出力する必要があります。 

入力には都市の数のみが含まれます。 出力では、最初に道路の最大数を出力し、次にすべての道路をリストする必要があります。 

バウンド`n ≤ 100`は十分に小さいため、ほとんどすべての多項式時間構築が快適に機能します。 たとえ`O(n^3)`検証ステップは問題ありません。`100^3 = 1,000,000`操作。 本当の課題はパフォーマンスではなく、三角形を回避しながらエッジの数を最大化する極値のグラフ構造を発見することです。 

よくある間違いは、三角形が表示されるかどうかを確認しながら、貪欲にエッジを追加しようとすることです。 このアプローチでは、グローバルに最適ではない、ローカルに最適な構成に行き詰まる可能性があります。 

たとえば、次のように仮定します。`n = 4`。 

不用意に貪欲に構築すると、次のようなものが構築される可能性があります。```
1-2
2-3
3-4
```このグラフにはエッジが 3 つしかありません。 しかし、最適な答えは 4 つのエッジです。```
1-3
1-4
2-3
2-4
```これはパーティションを含む完全な 2 部グラフです`{1,2}`そして`{3,4}`。 

もう一つの微妙なケースは奇妙だ`n`。 

のために`n = 5`、均等に半分に分割することは不可能です。 サイズのパーティションを選択した場合`2`そして`3`、エッジの数は次のようになります。`2 × 3 = 6`。 

バグのある実装により、パーティションが誤って試行される可能性があります`1`そして`4`、4つのエッジのみが生成されます。 最適なパーティション サイズは、可能な限りバランスがとれている必要があります。 

最小のケースも重要です。 

のために`n = 1`、グラフにはエッジがありません。 

のために`n = 2`、ちょうど 1 つのエッジが可能です。 

2 つのパーティションにわたるすべてのペアを盲目的に接続する構造でも、空のパーティションを正しく処理する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 エッジのすべての可能なサブセットを考慮します。`n(n-1)/2`候補エッジを選択し、グラフに三角形が含まれているかどうかをテストし、最大の有効なグラフを保持します。 

これが機能するのは、定義が明示的であるためです。必要なのは、3 サイクルを含むグラフを拒否することだけです。 三角形の検出自体は、`O(n^3)`頂点のトリプルをすべてチェックすることによって。 

問題はグラフの数です。 がある`2^(n(n-1)/2)`無向グラフの可能性。 たとえ`n = 20`、これは天文学的な規模になります。 網羅的な検索は全く不可能です。 

より合理的で欲張りなアイデアは、三角形を避けながらエッジを 1 つずつ追加することです。 ローカルな決定によって将来のエッジがブロックされる可能性があるため、それでも最適性は保証されません。 

重要な観察は、古典的な極値グラフの結果です。つまり、エッジの最大数を持つ三角形のないグラフは、常に 2 つの部分が可能な限りバランスされた完全な 2 部グラフになります。 

なぜここで二者構成が重要なのでしょうか? どの三角形でも、すべてのペアが接続される 3 つの頂点が必要です。 2 部グラフでは、頂点は 2 つのグループに分割され、エッジはグループのみを横断します。 三角形には同じグループの 2 つの頂点が必要ですが、同じグループのエッジは存在しません。 したがって、2 部グラフには自動的に三角形が含まれなくなります。 

2 部グラフのうち、1 つのパーティションにサイズがある場合`a`そしてもう1つはサイズがあります`b`、すると、すべてのクロスペアを接続でき、次のようになります。`a × b`エッジ。 

以来`a + b = n`、製品`a × b`2 つの値が可能な限り近い場合に最大になります。 したがって、最適なパーティション サイズは次のとおりです。```
⌊n/2⌋ and ⌈n/2⌉
```次に、最初の部分のすべての頂点を 2 番目の部分のすべての頂点に接続するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n²) · n³) | O(n²) | 遅すぎる |
 | 最適 | O(n²) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`n`。 
2. 頂点をできるだけ均等に 2 つのグループに分割します。 

させて：```
left = n // 2
right = n - left
```最初のグループには頂点が含まれます`1...left`、2 番目のグループには頂点が含まれます。`left+1...n`。 
3. エッジの空のリストを作成します。 
4. 頂点ごとに`i`最初のグループでは、すべての頂点に接続します`j`2番目のグループで。 

これにより、完全な 2 部グラフが作成されます。 
5. エッジの数を出力します。 
6. 保存されているすべてのエッジを印刷します。 

### なぜ効果があるのか

 グラフは 2 部構成であるため、同じパーティション内の頂点間にエッジは存在しません。 どの三角形にも少なくとも 1 つのそのようなエッジが必要ですが、これは不可能です。 したがって、構築には常に三角形が含まれません。 

次にエッジ数を考えてみましょう。 パーティションのサイズが`a`そして`b`、グラフには次のものが含まれます`a × b`エッジ。 以来`a + b = n`、この積は、2 つの数値が可能な限りバランスがとれたときに最大になります。 私たちの構築ではこれらのパーティション サイズを正確に使用するため、三角形のないグラフにはそれ以上のエッジを含めることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

left = n // 2

edges = []

for i in range(1, left + 1):
    for j in range(left + 1, n + 1):
        edges.append((i, j))

print(len(edges))

for u, v in edges:
    print(u, v)
```コードは建設的な証明を直接実装します。 

変数`left`最初のパーティションのサイズを格納します。 2 番目のパーティションには、残りの頂点が自動的に含まれます。 

ネストされたループにより、2 つのパーティション間のすべてのクロスエッジが生成されます。 各ペアは 1 回だけ追加されるため、重複したエッジは表示されません。 

頂点範囲は、1 つずつ違う間違いを避けるために慎重に選択されます。 最初のパーティションは次のとおりです。```
1 ... left
```2 番目のパーティションは次のとおりです。```
left + 1 ... n
```これは偶数と奇数の両方で正しく機能します`n`。 

たとえば、次のようなとき`n = 5`:```
left = 2
first group  = {1, 2}
second group = {3, 4, 5}
```6 つのクロスエッジすべてが追加されます。 

メモリ使用量はわずかです。`2500`エッジが存在する場合`n = 100`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())

    left = n // 2

    edges = []

    for i in range(1, left + 1):
        for j in range(left + 1, n + 1):
            edges.append((i, j))

    print(len(edges))

    for u, v in edges:
        print(u, v)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3\n") == (
    "2\n"
    "1 2\n"
    "1 3\n"
), "sample 1"

# minimum size
assert run("1\n") == "0\n", "single vertex"

# two vertices
assert run("2\n") == (
    "1\n"
    "1 2\n"
), "single edge"

# odd n
assert run("5\n") == (
    "6\n"
    "1 3\n"
    "1 4\n"
    "1 5\n"
    "2 3\n"
    "2 4\n"
    "2 5\n"
), "balanced odd partition"

# even n
assert run("4\n") == (
    "4\n"
    "1 3\n"
    "1 4\n"
    "2 3\n"
    "2 4\n"
), "balanced even partition"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`0`エッジ | 空のグラフを正しく処理します。 
|`2`| 片端 | 最小の自明ではないグラフ |
 |`4`| 4 エッジ | 偶数 n | の正しいバランスのとれた 2 部構成
 |`5`| 6 エッジ | 奇数 n に対する正しいバランスの取れた 2 部構成 |

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
```アルゴリズムは以下を計算します。```
left = 0
```したがって、最初のパーティションは空で、2 番目のパーティションには頂点が含まれます。`1`。 ネストされたループは実行されず、エッジがゼロになります。```
0
```道路は存在できないので、これは正しいです。 

次に、次のことを考えてみましょう。```
2
```パーティションは次のようになります。```
{1}
{2}
```このアルゴリズムはエッジを 1 つだけ追加します。```
1 2
```頂点が 2 つだけの三角形は存在できません。 

奇数サイズの場合はさらに微妙です。```
5
```パーティションはサイズになります`2`そして`3`。 アルゴリズムが生成するのは、`2 × 3 = 6`エッジ。 

パーティションを使用したバグのある実装`1`そして`4`4 つのエッジのみが生成されます。```
1-2
1-3
1-4
1-5
```このグラフには三角形はありませんが、最大ではありません。 製品を最大化するにはバランスのとれた分割が必要です。 

最後に、次のことを考慮してください。```
6
```パーティションは完全にバランスが取れています。```
{1,2,3}
{4,5,6}
```グラフには次の内容が含まれます`3 × 3 = 9`エッジ。 いずれかのパーティション内にエッジを追加しようとすると、すぐに三角形が作成されます。 

たとえば、エッジを追加する`(1,2)`作成します:```
1-2-4-1
```なぜなら両方とも`1`そして`2`すでに接続されています`4`。 これは、完全な二部構造が最大である理由を裏付けています。
