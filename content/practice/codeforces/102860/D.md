 ## 解決策
 # 問題の理解

 家は直交多角形です。壁は水平または垂直で、角は整数の座標を持ちます。 フェンス上のすべての点が少なくともマンハッタンの距離に留まりながら、家全体を含む最短の閉じたフェンスを構築する必要があります。`l`家のあらゆる場所から。 入力は家の境界頂点を順番に与え、出力はそのようなフェンスの可能な最小周囲長です。 

制約は十分に大きいため、処理されるポイントの数は線形または線形に近い値を維持する必要があります。 家には最大で次のものを置くことができます`100000`したがって、頂点のすべてのペアを比較したり、多くの幾何学的操作を使用して展開された形状全体を明示的にシミュレートしたりするアルゴリズムは適合しません。 解決策`O(n log n)`生成された点の線形数の並べ替えが主要な操作であるため、これは適切です。 

重要な幾何学的観察は、必要なフェンスがマンハッタン半径によるミンコフスキー拡張住宅の境界であるということです。`l`形。 その境界のすべての点を構築する代わりに、候補となる極点の小さなセットのみが必要です。 元の頂点ごとに`(x, y)`、4つのポイント`(x+l, y)`、`(x-l, y)`、`(x, y+l)`、 そして`(x, y-l)`十分です。 これらすべての生成された点の凸包により、最も短い囲いフェンスが得られます。 

一部の特殊なケースは見落とされやすいものです。 もし`l = 0`、答えは元の多角形の周囲にすぎず、生成された点には多くの重複が含まれています。 例えば：```
Input:
4 0
0 0
0 2
2 2
2 0

Output:
8
```実装を不注意にすると、繰り返しポイントを含むハルが作成され、長さ 0 のエッジが誤って計算されたり、同一のポイントの並べ替えに失敗したりする可能性があります。 

もう 1 つの注意が必要なケースは、凹型の家です。 最短の囲み曲線が凹面のコーナーを横切る可能性があるため、最適なフェンスは、すべてのエッジで独立してシフトされた元の形状ではありません。 例えば：```
Input:
9 0
0 0
4 0
4 1
2 1
2 3
1 3
1 1
0 1
0 0
```正しいフェンスは外側の境界に従いますが、正の距離を適用すると、凹型のノッチが消えます。 すべての壁を独立して外側に移動するだけの方法では、不要な内側の角が残り、周囲が長くなってしまう可能性があります。 

## アプローチ

 直接的なアプローチでは、家のすべての壁を処理してオフセット ポリゴンを構築しようとします。 各水平壁を垂直方向に移動し、各垂直壁を水平方向に移動して、すべての交差を計算できます。 家自体は軸に沿ったセグメントのみで構成されているため、これは自然に見えます。 

難しいのは、マンハッタンの距離によって水平方向と垂直方向の境界だけが作成されるわけではないことです。 角の周りでは、最も近い点が対角線のセグメントを形成します。 すべてのコーナーケースを手動で処理するには、特に凹角の周囲で隣接する壁がどのように相互作用するかを追跡する必要があります。 単純な幾何学構造では、作成されるセグメントが多すぎる可能性があるため、慎重に結合する必要があります。 

より良い視点は、距離の定義について考えることです。 ある点からマンハッタンまでの距離にあるすべての点のセット`(x, y)`せいぜい`l`ダイヤモンドです。 これらのダイヤモンドによって家全体を拡張すると、まさに禁止領域の境界が作成されます。 最小の有効なフェンスが、この拡張の外側の境界になります。 

直交多角形の場合、この拡張の極点は、元のすべての頂点を 4 つの基本方向に移動することによって生成されます。`l`。 これらの点が収集されると、残りの作業はすべて標準の凸包問題になります。 船体は不要な凹部分を自動的に削除し、最短の囲いフェンスに現れる点だけを残します。 

ブルートフォース構築では、すべてのセグメントの相互作用について推論するのに労力がかかります。 包囲アプローチは、これらすべてのケースを単一の幾何学的不変式に置き換えます。生成された点の凸包は、まさに拡張された形状の境界になります。

 ## アルゴリズムのチュートリアル

 1. 家のすべての頂点を読み取り、頂点ごとに 4 つのシフトされた点を生成します。 これらの点は、マンハッタン拡張の考えられる極端な位置を表しています。 展開された形状のすべてのエッジは端点の極値によって決定されるため、エッジに沿ってポイントを生成する必要はありません。 
2. 重複して生成されたポイントを削除し、残りのポイントを辞書順に並べ替えます。 ソートにより、単調チェーンハルアルゴリズムがポイントを順番に処理できるようになります。 
3. 凸包の下部と上部を構築します。 新しいポイントを追加する際、ターンが反時計回りでない場合は必ず前のポイントを削除します。 これにより、外側の境界点のみが保持されます。 
4. 最終ハルを順番にトラバースし、最後の頂点から最初の頂点までを含む、連続する頂点の各ペア間のユークリッド距離を加算します。 これによりフェンスの長さが決まります。 

なぜ効果があるのか:

 集合のマンハッタン展開は、その集合と半径のダイヤモンドのミンコフスキー和です。`l`。 直交多角形の場合、この拡張された形状のすべての極点は、元の角を 4 つの基本方向の 1 つだけシフトすることで得られる必要があります。 生成された点セットには、そのような極端な点がすべて含まれます。 凸包を取得すると、最小の囲いフェンスに必要な外側の境界が正確に維持されますが、周囲に寄与できない点は削除されます。 フェンスには拡張領域が含まれている必要があり、そこに入ることはできないため、これより短い有効なフェンスは存在できません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def cross(a, b, c):
    return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])

def convex_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def solve():
    n, l = map(int, input().split())
    points = []

    for _ in range(n):
        x, y = map(int, input().split())
        points.append((x + l, y))
        points.append((x - l, y))
        points.append((x, y + l))
        points.append((x, y - l))

    hull = convex_hull(points)

    ans = 0.0
    m = len(hull)
    for i in range(m):
        x1, y1 = hull[i]
        x2, y2 = hull[(i + 1) % m]
        ans += math.hypot(x1 - x2, y1 - y2)

    print("{:.10f}".format(ans))

if __name__ == "__main__":
    solve()
```入力処理では、ポリゴンの頂点を直接読み取り、アルゴリズムのステップ 1 と一致する 4 つの可能なシフト ポイントを即座に作成します。 座標はおよそ最大になる可能性があります`2 * 10^8`、これは依然として Python 整数によって安全に処理されます。 

ハルの実装では単調連鎖法を使用します。 の`cross`関数は 3 点の方向を決定します。 これらのポイントは現在の境界内にあり、最短のフェンス上には表示できないため、左折以外のポイントを削除する必要があります。 

重複削除による`set`重要なとき`l = 0`または、生成された複数の点が一致する場合。 これがないと、ハル ループに繰り返しの頂点が含まれ、不正確な周囲計算が作成される可能性があります。 

周長の計算には次のものを使用します。`math.hypot`これにより、平方根を手動で計算する必要がなく、浮動小数点出力を直接処理できます。 Python の整数は、外積計算中のオーバーフローを回避します。

 ## 特殊なケース

 いつ`l = 0`、生成されたすべての点は、元の頂点と 4 回同一になります。 アルゴリズムは最初にこれらの重複を削除し、次に通常の凸包を計算します。 前の例の正方形の場合、船体は元の正方形であり、答えは次のようになります。`8`。 

凹型ポリゴンの場合、アルゴリズムは元のインデントを保存しようとしません。 2 番目のサンプルについて考えてみましょう。 生成された点には内側のノッチの周囲の候補が含まれていますが、凸包は外側の境界に現れないものを破棄します。 結果として得られる船体は、まさに最短のフェンス形状になります。 

非常に大きな座標の場合、シフトされた点が近づく可能性があります。`2 * 10^8`規模的には。 Python の整数演算では、すべての外積計算が正確に保たれ、最後の周囲長変換のみが浮動小数点値を使用します。 これにより、船体建造時の精度の問題が防止されます。
