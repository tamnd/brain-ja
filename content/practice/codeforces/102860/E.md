 ## 解決策
 # 問題の理解

 旗はから作られています`n`星が横一列に並んでいます。 行にまったく同じ数の星が含まれている必要はありませんが、各行のサイズは他の行のサイズと最大 1 つだけ異なっていなければなりません。 2 つの異なる行サイズを使用する場合、同じサイズの行は互いに接触できないため、2 つのサイズを交互に配置する必要があります。 すべての可能な配置の中で、行の数と任意の行の星の最大数の間の可能な限り最小の差を見つける必要があります。 

入力には単一の整数が含まれています`n`、利用可能な星の数。 出力は、そのようなフラグの高さと幅の間の可能な最小の絶対差です。 

の値`n`と同じ大きさにすることができます`10^12`したがって、可能なすべての行数を反復処理することは不可能です。 線形ソリューションには、最大で次のことが必要になります。`10^12`利用可能な時間を大幅に超えています。 可能な行数の数学的構造を活用する必要があります。 の異なる値の数`floor(n / x)`ほんの約です`2 * sqrt(n)`、これはこの制限に対して十分小さいです。 

星の数を同じ行に分割できない場合には、注意が必要なケースが発生します。 たとえば、`n = 5`、2 行を使用するとサイズが得られます`3`そして`2`、ただし、これらの行は 2 つしかないため許可されます。 不用意に実装すると、2 つの行サイズが異なるために拒否される可能性があります。 正しい答えは、`1`。```
5
```出力：```
1
```もう 1 つの特殊なケースは、すべての行が同じ長さである場合です。 のために`n = 16`, 4 つの星が 4 列有効です。 答えは`0`。```
16
```出力：```
0
```交互の行のみをチェックするソリューションでは、交互する 2 つの異なる行サイズがないため、このケースを見逃す可能性があります。 

## アプローチ

 直接的なアプローチは、可能な限りすべての行数を試すことです。`r`。 各選択肢の最大行長は次のとおりです。`ceil(n / r)`。 残りの星がサイズの行に分散できるかどうかを確認できます`ceil(n / r)`そして`floor(n / r)`。 これは正しいです。有効なフラグはすべて、これら 2 つの可能な行サイズを正確に持たなければならないからです。 ただし、すべて試してみると、`r`から`1`に`n`実行します`O(n)`小切手。 と`n`まで`10^12`、これは不可能です。 

重要な点は、有効な行数が商を使用して記述できることです。`q = floor(n / r)`。 いつ`q`修正されています、可能性はすべてあります`r`値は 1 つの間隔を形成します。 くらいしかありません`2 * sqrt(n)`異なる商材。 

フラグがあるとします。`r`行と`q = floor(n / r)`。 させて`rem = n mod r`。 

もし`rem = 0`、各行にはサイズがあります`q`、 それで`r`でなければなりません`n / q`。 

それ以外の場合は、`rem`サイズの行`q + 1`そして`r - rem`サイズの行`q`。 これら 2 つの行サイズは交互に配置する必要があるため、行数の違いは最大 1 つまで許容されます。```
abs(rem - (r - rem)) <= 1
```これにより、考えられる 3 つの方程式が得られます。```
rem = r / 2
rem = (r - 1) / 2
rem = (r + 1) / 2
```置き換える`n = q * r + rem`～の直接の候補者を3人挙げる`r`:```
r = 2n / (2q + 1)
r = (2n + 1) / (2q + 1)
r = (2n - 1) / (2q + 1)
```すべての商区間について、これらの少数の候補をテストするだけで済みます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 遅すぎる |
 | 最適 | O(sqrt(n)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 等しい値のすべての区間を反復します。`floor(n / r)`。 開始行数の場合`l`、計算する`q = n // l`最大行数`r`同じ商です。 これにより、不可能な多くの行数が一度にスキップされます。 
2. 現在の商について`q`、候補者をテストします`n / q`。 これは、すべての行のサイズが等しい場合に可能な唯一の行数です。 
3. 交互の行数から導出された 3 つの式をテストします。```
2n / (2q + 1)
(2n + 1) / (2q + 1)
(2n - 1) / (2q + 1)
```現在の商区間内の候補のみが実際にこの値を持つことができます。`q`。 
4. すべての候補行数について、行分布が有効であることを確認し、次の最小値を更新します。`abs(rows - maximum_row_size)`。 

これが機能する理由: 考えられるすべてのフラグには行数が含まれています`r`。 アルゴリズムは、これを含む一意の商区間を訪問します。`r`。 その間隔内で、上記の方程式は、2 つの行サイズが交互になる可能性のあるすべての方法をカバーしています。 同じサイズの行は個別に処理されます。 すべての有効な配置がチェックされるため、記録された最小の差が最適なものとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    ans = n
    def check(r):
        nonlocal ans
        if r <= 0:
            return
        q = n // r
        rem = n % r
        if rem != 0 and abs(rem - (r - rem)) > 1:
            return
        ans = min(ans, abs(r - ((n + r - 1) // r)))

    l = 1
    while l <= n:
        q = n // l
        r = n // q

        if n % q == 0:
            check(n // q)

        d = 2 * q + 1
        for x in (2 * n, 2 * n + 1, 2 * n - 1):
            if x > 0 and x % d == 0:
                cand = x // d
                if l <= cand <= r:
                    check(cand)

        l = r + 1

    return ans

def main():
    n = int(input())
    print(solve_case(n))

if __name__ == "__main__":
    main()
```メイン ループは、行数を 1 つずつ増やすのではなく、商区間間をジャンプします。 間隔`[l, r]`同じものを生成するすべての行数が含まれます`floor(n / rows)`価値。 

すべての行が同じサイズになる可能性があるため、割り算の場合は個別にチェックされます。 残りのケースでは、生成された 3 つの候補は、行数の増加と減少が交互に起こる状況とまったく同じです。 

検証関数は剰余を再計算し、交互の条件をチェックします。 これにより、代数のみに依存することがなくなり、整数の除算によって生じる無効な候補が防止されます。 Python の整数は大きな値を安全に処理するため、オーバーフロー処理は必要ありません。

## テストケース```python
import sys, io

def solve_case(n):
    ans = n

    def check(r):
        nonlocal ans
        if r <= 0:
            return
        q = n // r
        rem = n % r
        if rem != 0 and abs(rem - (r - rem)) > 1:
            return
        ans = min(ans, abs(r - ((n + r - 1) // r)))

    l = 1
    while l <= n:
        q = n // l
        r = n // q

        if n % q == 0:
            check(n // q)

        d = 2 * q + 1
        for x in (2 * n, 2 * n + 1, 2 * n - 1):
            if x > 0 and x % d == 0:
                cand = x // d
                if l <= cand <= r:
                    check(cand)

        l = r + 1

    return ans

def run(inp: str) -> str:
    return str(solve_case(int(inp.strip()))) + "\n"

assert run("16") == "0\n", "equal rows"
assert run("5") == "1\n", "two alternating rows"
assert run("1") == "0\n", "single star"
assert run("1000000000000") == "0\n", "perfect square boundary"
assert run("50") == "3\n", "non-square large case"

 ## 特殊なケース

 のために`n = 5`、アルゴリズムは次の商区間に達します。`q = 2`。 候補者`r = 2`交互式から生成されます。 残りは`1`、行のサイズが調整されます`3`そして`2`。 それらのカウントは 1 異なります。これはフラグが有効であることを意味し、答えは次のようになります。`1`。 

のために`n = 16`、候補者`r = 4`これは等しい行の場合に由来します。`16`で割り切れます`4`。 余りはゼロなので、各行には 4 つの星が含まれます。 高さと幅は両方とも 4 で答えが得られます`0`。 

次のような大きな値の場合、`n = 10^12`、アルゴリズムは 1 兆行カウントを試行することはありません。 商区間のみを対象とし、大きな整数に対しても同じ算術が機能します。 これが、実現可能な解決策と総当たり検索の違いです。
