 # 問題の理解

 ゲームは独立したラウンドで構成されます。 各ラウンドの開始時のスコアは次のようになります。`n`。 各ジェネレータ値は 1 つの手を表します。Petya は現在のスコアからその値を減算しようとしますが、成功した減算のみが適用されます。 スコアが正確に 0 に達すると、現在のラウンドが完了し、次の手が存在する場合は、新しいスコアから開始されます。`n`。 

入力により、手の数、ラウンドの初期スコア、およびジェネレーター出力のシーケンス全体が得られます。 タスクは、これらの手を再生し、完全に完了したラウンドの数と、最後に記録された手の後に残ったスコアを判断することです。 最後の手がラウンドを終了した場合、その後新しいラウンドは開始されないため、最終スコアは 0 になります。 

制限は直接シミュレーションするには十分小さいです。 多くてもあります`100000`したがって、各動きを 1 回処理するアルゴリズムはわずか約`100000`操作。 可能なすべてのラウンド分割を構築しようとしたり、シーケンスを繰り返しスキャンしたりするアプローチでは、不必要な作業が追加されますが、線形時間は容易に制限内に収まります。 

主なエッジケースは、失敗した減算を正しく処理することと、ラウンドが終了する正確な瞬間に発生します。 たとえば、入力の場合```
1 5
7
```出力は```
0
5
```なぜなら`7`から引くことはできません`5`, そのため、スコアは変わりません。 ジェネレーターの値を常に減算するような不注意なソリューションを使用すると、無効な負のスコアが生成されます。 

もう一つのケースは、```
1 5
5
```出力付き```
1
0
```唯一の動きでラウンドが完了するからです。 よくある間違いは、スコアを次のようにリセットすることです。`5`ゼロに到達した直後に、最終スコアが新しいラウンドの開始スコアとして誤って報告されてしまいます。 

3 番目の境界ケースは、```
3 5
2 2 2
```出力付き```
0
1
```動きによってスコアは次のように変わります。`5 -> 3 -> 1 -> 1`, 最後の引き算が不可能だからです。 完了したラウンドに向けて進行するたびにすべてのジェネレータ値をカウントするソリューションでは、オーバーカウントになります。 

## アプローチ

 最も直接的な解決策は、ゲームを正確にシミュレートすることです。 現在のスコアと完了したラウンド数を保持します。 すべてのジェネレータ値について、それを減算することでスコアが負にならないかどうかを確認します。 そうであれば、減算を適用します。 スコアが0になると1ラウンドが終了したことになるので、答えを増やして次の手のスコアを準備します。 

ここでの総当たり解釈は、実際には最適な方法と同じです。 ゲームの状態は各手ごとにのみ変化し、手の数は限られているため、より高速な数学的ショートカットの必要性は隠れていません。 シーケンスの考えられるすべてのラウンドへの分割を試みる仮説的なアプローチでは、膨大な数の可能性が検討されますが、シミュレーションでは、唯一の有効なイベント順序に従うことで、それを完全に回避します。 

解決策を明らかにする観察は、ジェネレーター シーケンスがすでにゲームの完全な歴史であるということです。 選択の余地はありません。 次の状態は現在のスコアと次のジェネレーターの値にのみ依存するため、シーケンスを 1 回通過するだけで十分です。

 ## アルゴリズムのチュートリアル

 1. 現在のスコアを次のように初期化します。`n`そして完了したラウンドカウンターはゼロになります。 スコアは、最初に記録された手を処理する前の Petya の状態を表します。 
2. 各ジェネレーターの値を、出現する順序で処理します。 値が現在のスコアより大きくない場合は、スコアからその値を減算します。 それ以外の場合は、スコアがマイナスになることはルールで許可されていないため、無視してください。 
3. 減算が成功するたびに、スコアがゼロになったかどうかを確認します。 そうなった場合は、完了ラウンドカウンターを増やし、スコアを元に戻します。`n`今後の動きのために。 復元は次のラウンドの開始を表しますが、現在の手が最後の手だった場合、その状況で必要な最終スコアはゼロであるため、最終的な解答には影響しません。 
4. すべての手が処理された後、完了したラウンド数と現在のスコアを出力します。 最後の手がラウンドを終了した場合、最後の手の後に復元ステップは行われないため、最終スコアは 0 のままになります。 

実装には、最後のステップで小さな調整が 1 つ必要です。 ループ後はゲームが停止した瞬間のスコアのみが必要なため、ラウンドが終了するとすぐにスコアを復元できます。 その情報を保存するために、コードはリセットする前に現在の手が最後の手であるかどうかをチェックします。 

機能する理由: シミュレーション中、保存されるスコアは常に、すべての処理された移動後の Petya の正確なスコアです。 ゲーム ルールで許可されている場合にのみ移動が適用され、スコアが 0 になった時点で完了したラウンドがカウントされます。 記録されたすべての手が元の順序で一度処理されるため、最終的に保存された状態は実際のゲーム状態と一致します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())
    a = list(map(int, input().split()))

    score = n
    rounds = 0

    for i, x in enumerate(a):
        if x <= score:
            score -= x

        if score == 0:
            rounds += 1
            if i != k - 1:
                score = n

    print(rounds)
    print(score)

if __name__ == "__main__":
    solve()
```変数`score`そして`rounds`出力で要求された 2 つの量を直接表します。 ループは、ゲームの順序に合わせて、ジェネレーターの履歴を左から右にたどります。 

減算条件には、`x <= score`Python の整数では負の値が許可されますが、ゲーム自体では許可されないため、減算後にチェックするのではなく。 これにより、無効な中間状態が防止されます。 

リセット条件は、現在の手が最後の手であるかどうかをチェックします。 ラウンドが早く終了した場合、次に記録された手は新しいラウンドに属し、次から開始する必要があります。`n`。 最後の手がラウンドを終了すると、新しいラウンドは開始されないため、答えはスコアを 0 に保つ必要があります。 

インデックス作成のトリックや大きな整数の問題はありません。 値は Python の整数型に簡単に適合し、アルゴリズムは入力シーケンスといくつかの変数のみを保存します。

## テストケース```python
import sys
import io

def solve(data):
    input = io.StringIO(data).readline
    k, n = map(int, input().split())
    a = list(map(int, input().split()))

    score = n
    rounds = 0

    for i, x in enumerate(a):
        if x <= score:
            score -= x
        if score == 0:
            rounds += 1
            if i != k - 1:
                score = n

    return f"{rounds}\n{score}\n"

assert solve("4 3\n1 2 4 1\n") == "1\n2\n", "sample 1"
assert solve("1 5\n5\n") == "1\n0\n", "single completed round"
assert solve("1 5\n7\n") == "0\n5\n", "failed subtraction"
assert solve("3 5\n2 2 2\n") == "0\n1\n", "ignored final move"
assert solve("5 4\n3 1 5 4 2\n") == "2\n2\n", "multiple rounds"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`4 3 / 1 2 4 1`|`1 / 2`| 提供されたサンプル動作 |
 |`1 5 / 5`|`1 / 0`| 最後の動きでラウンドを終了する |
 |`1 5 / 7`|`0 / 5`| 無効な減算は無視されます。 
|`3 5 / 2 2 2`|`0 / 1`| 減算が失敗した後の境界 |

 ## 特殊なケース

 場合について```
1 5
7
```アルゴリズムはスコア 5 から始まります。 唯一のジェネレータ値がスコアより大きいため、減算は行われません。 スコアがゼロになることはなく、ラウンドカウンターはゼロのままで、最終スコアは 5 です。 

場合について```
1 5
5
```減算は成功し、スコアが 5 から 0 に変わります。 アルゴリズムは完了したラウンドを 1 回カウントします。 これは最後の手であるため、スコアはリセットされず、必要な最終スコアはゼロのままになります。 

場合について```
3 5
2 2 2
```最初の動きでスコアが 3 に変更され、2 番目の動きでスコアが 1 に変更されます。 2 が 1 より大きいため、3 番目の手を適用することはできません。そのため、スコアは 1 のままです。 ゼロに到達することがないため、アルゴリズムはラウンドをカウントしません。 

場合について```
5 4
3 1 5 4 2
```最初の 2 つの動きでラウンドが完了します。 3 番目の手はスコア 4 から始まり、失敗し、スコアは変わりません。 4 番目の動きで第 2 ラウンドが完了します。 最終手は4から始まり2が残ります。 このアルゴリズムは、中間のリセットと最終的な非ゼロ スコアの両方を正しく処理します。
