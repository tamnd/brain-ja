 ## 問題の理解

 無向公園グラフがあります。 入り口は頂点です`1`そして、Vasya は、に直接接続されている頂点でのみ終了することができます。`1`。 有効なウォークは次から始まります`1`、正確に 3 つの異なるエッジを順番に使用し、それらの隣接する頂点の 1 つで終了します。 タスクは、これらのルールを満たすさまざまな 3 エッジ ウォークがいくつあるかを数えることです。 

ウォークでは同じ頂点を複数回訪問できますが、ウォーク中に使用される 3 つのエッジは区別されている必要があります。 たとえば、シーケンス`1 -> 2 -> 1 -> 3`最初の 2 つの移動は同じエッジを反対方向に使用するため、無効です。 

グラフには最大で`100000`頂点と`200000`エッジ。 考えられるすべての 3 エッジ シーケンスを試す解決策は不可能です。なぜなら、ウォーク数はおよそ 2 乗の和にまで増加する可能性があり、これは 1 秒の制限をはるかに超えているからです。 線形時間に近いグラフを処理する必要があります。 

難しいのは、長さ 3 の四球を見つけられないことです。 それらを直接数えるのは簡単です。 難しいのは、3 つのエッジのうち 1 つが再利用されているウォークを削除することです。 

いくつかの特殊なケースでは、不用意なソリューションが壊れてしまいます。 

エッジが 1 つだけあるグラフの場合:```
2 1
1 2
```答えは`0`。 唯一考えられる動きは、`1 -> 2`、3 つの異なるエッジを選択することはできません。 

三角形の場合:```
3 3
1 2
2 3
3 1
```答えは`0`。 頂点の隣で終了する 3 エッジ ウォークが多数あります`1`, しかし、それらのどれもがエッジを繰り返します。 

スターの場合:```
4 3
1 2
1 3
1 4
```答えは`0`。 すべての道路が入口に接触しているため、3 つのエッジの移動は、すでに使用されているエッジを通って直ちに戻らなければなりません。 

よくある間違いは、隣の地点で終わる長さ 3 の歩行をすべて数えることです。`1`そして、同じエッジが 2 回現れる可能性があることを忘れています。 

## アプローチ

 直接的なアプローチはあらゆる可能性を生み出すでしょう`1 -> a -> b -> c`、どうかを確認してください`c`の隣人です`1`、そして 3 つのエッジが異なることを確認します。 最初の移行では、`deg(1)`2 番目には多くの選択肢があり、3 番目にも分岐が可能です。 グラフの密集した部分では、これが大きくなりすぎます。 高次の頂点を含むグラフでは、数十億の候補ウォークが作成される可能性があります。 

有益な観察は、制限されていない歩行を数えるのは簡単で、無効なケースのみが非常に特殊な構造を持っているということです。 

まず、隣接する頂点をすべてマークします。`1`。 このセットをこうしましょう`S`。 

頂点ごとに`v`、隣接するものの数を計算します。`v`に属する`S`。 この値を呼び出します`inside[v]`。 

今度は散歩を考えてみましょう`1 -> a -> b -> c`。 最初の頂点`a`入っている必要があります`S`。 から引っ越してから`a`に`b`、可能な最終頂点の数は正確に`inside[b]`、最後の頂点は隣接する頂点でなければならないため、`1`。 すべての頂点を残したまま、すべてのエッジにわたってこれを合計します。`S`正しく終了した長さ 3 のウォークをすべてカウントしますが、エッジウォークの繰り返しも含まれます。 

エッジを繰り返す方法は 2 つだけです。 

最初の 2 つのエッジは同じであってもかまいません。 これにより、次の形式のウォークが得られます`1 -> a -> 1 -> c`。 がある`deg(1)`～の選択肢`a`そして`deg(1)`～の選択肢`c`、あります。`deg(1)^2`そんな散歩。 

2 番目と 3 番目のエッジは同じであってもかまいません。 これらの散歩には次のような形式があります。`1 -> a -> b -> a`。 すべての隣人のために`a`の`1`、 がある`deg(a)`～の選択肢`b`したがって、カウントは、次数のすべての近傍の次数の合計になります。`1`。 

3 つの移動すべてが同じエッジを使用する場合、2 つのケースは重複します。`1 -> a -> 1 -> a`。 まさにあります`deg(1)`このような散歩なので、それらを一度追加し直します。 

最終的な答えは次のとおりです。```
all_length_three_walks
- deg(1)^2
- sum_of_neighbor_degrees
+ deg(1)

 ## アルゴリズムのチュートリアル

 1. グラフを読み取り、隣接リストを保存します。 グラフはまばらであるため、隣接リストを使用してすべてのエッジを線形時間で検査できます。 
2. 頂点に直接接続されているすべての頂点を検索します。`1`そしてそれらにマークを付けます。 これらは唯一可能な終了頂点であり、唯一可能な最初の頂点でもあります。 
3. すべての頂点について、その隣接頂点がマークされている数を数えます。 この値は、その頂点に到達した後の最終ステップに有効な選択肢がいくつ存在するかを示します。 
4. 無制限の散歩をすべてカウントします。 マークされた頂点ごとに`u`、すべてのエッジを検査します`u -> v`。 追加`inside[v]`それぞれの隣接するマークが付いているため、`v`考えられる終了点を 1 つ作成します。 
5. 最初のエッジが再利用されるウォークを減算します。 彼らの構造は、`1 -> u -> 1 -> v`、与える`degree(1) * degree(1)`ケース。 
6. 2 番目のエッジが再利用されるウォークを減算します。 彼らの構造は、`1 -> u -> v -> u`のすべての近傍の次数の合計を与えます。`1`。 
7. 両方の無効グループでカウントされたバック四球を追加します。 これらはまさに`1 -> u -> 1 -> u`、隣人ごとに 1 つ`1`。 

なぜ効果があるのか:

 無制限のカウントには、入口の隣で終わるすべての可能な 3 エッジ ウォークが含まれます。 このようなウォークが無効である唯一の理由は、その 3 つのエッジのうちの 1 つが 2 回出現することです。 単純な無向グラフでは、最初と 2 番目のエッジは、ウォークがすぐに頂点に戻る場合にのみ一致します。`1`、2 番目と 3 番目のエッジは、ウォークが前の頂点に戻った場合にのみ一致します。 最後の頂点は入口ではないため、最初と 3 番目のエッジを等しくすることはできません。 2 つの無効なグループは別々にカウントされ、それらの交差は 1 つのエッジを 3 回使用するウォークとまったく同じであるため、包含/除外によってすべての無効なウォークが 1 回だけ削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

g = [[] for _ in range(n)]

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

mark = [False] * n
for v in g[0]:
    mark[v] = True

inside = [0] * n
for v in range(n):
    cnt = 0
    for u in g[v]:
        if mark[u]:
            cnt += 1
    inside[v] = cnt

total = 0
for u in g[0]:
    for v in g[u]:
        total += inside[v]

deg1 = len(g[0])

bad_first_two = deg1 * deg1

bad_second_three = 0
for u in g[0]:
    bad_second_three += len(g[u])

answer = total - bad_first_two - bad_second_three + deg1

print(answer)
```配列`mark`は、可能な終了頂点を表します。 の`inside`配列は、ウォークをカウントする際に頂点の近隣を繰り返しスキャンすることを回避します。 

変数`total`アルゴリズムで説明されている無制限の歩行カウントに従います。 エッジの繰り返しは単純な式であり、後で減算する方が安価であるため、意図的にエッジの繰り返しを無視します。 

補正項は整数演算のみを使用します。 Python の整数はオーバーフローしません。これは、ウォークの数がエッジの数よりはるかに大きくなる可能性があるため便利です。 

グラフは内部的にゼロインデックスが付けられているため、入口頂点がインデックスとして保存されます。`0`。 隣接リストには当然既存の頂点のみが含まれるため、特別な境界処理は必要ありません。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    mark = [False] * n
    for v in g[0]:
        mark[v] = True

    inside = [0] * n
    for v in range(n):
        for u in g[v]:
            if mark[u]:
                inside[v] += 1

    total = 0
    for u in g[0]:
        for v in g[u]:
            total += inside[v]

    d = len(g[0])
    bad = d * d
    for u in g[0]:
        bad += len(g[u])

    return str(total - bad + d)

1 2
""") == "0"

assert solve("""3 3

2 3
3 1
""") == "0"

assert solve("""4 3
1 2
1 3
1 4
""") == "0"

assert solve("""5 6
1 2
2 3
3 4
4 5
5 1
2 5
""") == "2"
