 ## 解決策
 # 問題の理解

 円周上にいくつかのマークされた点が与えられます。 円には円周があります`L`、すべての点は、選択した開始点からの時計回りの距離で表されます。 円の中心が厳密に三角形の内側に含まれるか、正確にその辺の 1 つに含まれる三角形を形成する 3 つのマークされた点の異なる選択肢が何個あるかを数える必要があります。 

重要な幾何学的事実は、円に内接する三角形の 3 つの頂点が中心を含まないのは、3 つの頂点すべてが開いた半円の内側に収まる場合のみであるということです。 点が円の半分以上に広がっている場合、中心は三角形の内側になければなりません。 2 つの点が正反対にある場合、中心は三角形の境界上にあるため、それらの三角形もカウントする必要があります。 

入力は次のようになります。`300000`ポイント。 そのサイズでは、すべてのトリプルをチェックすることは不可能です。`n^3 / 6`可能な三角形。 平`O(n^2)`操作が大きすぎる場合`n`限界に近いです。 ソリューションでは、ソートされた順序でポイントを処理し、線形または線形に近いスキャンを使用する必要があります。 

トリッキーなケースは、開いた半円と閉じた半円の違いから生じます。 頂点が正確に半円離れた三角形は、中心が境界線上にあるため有効です。 を使用するソリューション`<= L / 2`無効な三角形を検索すると、これらのケースが誤って削除されます。 

例えば：```
3 10
0 5 6
```答えは次のとおりです。```
1
```のポイント`0`そして`5`直径の両端です。 三角形はその 2 点を結ぶ辺に中心があります。 距離を扱う`5`不正な半円の一部があると、この三角形が誤って無効としてカウントされるためです。 

もう 1 つのエッジ ケースは、すべての点が小さな円弧の内側に集中している場合です。```
4 20
0 1 2 3
```答えは次のとおりです。```
0
```考えられるすべての三角形は開いた半円の中に収まるので、中心を含むものはありません。 隣接する点だけをチェックするか、円の周囲の一方向だけをチェックする不注意な実装では、これらのケースを見逃す可能性があります。 

# アプローチ

 直接的なアプローチは、考えられるすべてのトリプル ポイントを調べることです。 各トリプルについて、ジオメトリを使用して中心が三角形の内側にあるかどうかを計算したり、点が半円に収まるかどうかを同等にチェックしたりできます。 考えられるすべての三角形が考慮されるため、これは正しいですが、`C(n,3)`トリプル。 と`n = 300000`、それはおおよそです`4.5 * 10^15`これは実際的な制限をはるかに超えています。 

重要な観察は、中心を直接含む三角形を数えるのは、反対側のグループを数えるよりも難しいということです。 すべての頂点が 1 つの開いた半円の内側にある場合、三角形は無効になります。 円の周りの点を並べ替えた後、無効な三角形を効率的に数えることができます。 

このような半円の最初の点を修正します。 私たちが点に立っていると仮定してください`i`そして時計回りに見てください。 あれば`k`後のポイントは厳密に以下です`L / 2`離れてから、それらの間のすべてのペア`k`ポイントはポイントを含む無効な三角形を作成します`i`。 これにより、`k * (k - 1) / 2`から始まる無効な三角形`i`。 

残る唯一の問題は、同じ無効な三角形が複数回カウントされるかどうかです。 開いた半円内の三角形の場合、その半円の最初の点は一意です。 3つのポイントであれば、`a < b < c`循環的な順序で、`c - a < L / 2`、から始まります`b`円を囲む必要があり、その囲む距離は`L / 2`。 したがって、無効な三角形はすべて 1 回だけカウントされます。 

答えは、三角形の総数から無効な三角形を引いたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. すべての点の座標を時計回りの順序で並べ替えます。 すべての座標にプラスを追加して、ソートされた配列を複製します。`L`。 複製部分は、円をさらに 1 周することを表しており、これにより、ラップアラウンドのケースを手動で処理する代わりに、通常の 2 ポインターの移動を使用できるようになります。 
2. 原点ごとに`i`からの距離まで右ポインタを移動します。`i`少なくとも到達する`L / 2`。 間の点`i + 1`そして`right - 1`まさに参加できるポイントです`i`開いた半円の内側。 
3. ある場合`k`そのような点を追加します`k * (k - 1) / 2`無効な三角形数に。 これらはすべて、以下を組み合わせる点のペアです。`i`中心を含めることができない三角形を作成します。 
4. 可能な三角形の総数を計算します。`n * (n - 1) * (n - 2) / 6`、無効なカウントを減算します。 

2 ポインタ スキャンの背後にある不変条件は、すべての開始点について次のとおりです。`i`の場合、右ポインタは常に、許可された開いた半円の外側にある最初の位置をマークします。 どちらのポインターも前方にのみ移動するため、ポイントの各ペアはソートされた順序で 1 回だけ考慮されます。 カウント引数は、すべての無効な三角形には 1 つの一意の開始頂点があることが証明されているため、減算によって不要な三角形が正確に削除されます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    x = list(map(int, input().split()))
    x.sort()

    a = x + [v + L for v in x]

    bad = 0
    r = 0

    for i in range(n):
        if r < i + 1:
            r = i + 1
        while r < i + n and a[r] - a[i] < L / 2:
            r += 1
        cnt = r - i - 1
        bad += cnt * (cnt - 1) // 2

    total = n * (n - 1) * (n - 2) // 6
    print(total - bad)

if __name__ == "__main__":
    solve()
```半円テストに必要な情報は循環順序だけであるため、入力が最初に並べ替えられます。 配列を複製すると、すべての検索を単純な増加間隔として書き込むことができます。 

ポインタ`r`決して後退することはありません。 各開始位置について、厳密には半円の内側にない最初の点が検索されます。 正確にポイントするため、厳密な比較が必要です。`L / 2`離れて、境界線を中心とする有効な三角形を作成します。 

値`cnt`は後の選択肢の数です`i`同じ開いた半円に収まる可能性があります。 そのうちの 2 つを選択すると、無効な三角形が 1 つ与えられるため、貢献度は次のようになります。`cnt * (cnt - 1) // 2`。 

Python の整数はオーバーフローしないため、多数の可能な三角形を直接計算しても安全です。

 # エッジケース

 2 つの頂点が向かい合う場合、三角形を数えなければなりません。 入力の場合:```
3 10
0 5 6
```ポインタ検索から`0`前に止まります`5`距離がちょうどいいから`L / 2`。 三角形は無効としてマークされず、合計数は残ります。`1`。 

すべての点が近接して配置されている場合、すべての三角形は無効になります。 のために：```
4 20
0 1 2 3
```から始まる`0`距離内にある他の 3 点を見つけます`10`、無効な三角形が 3 つ生成されます。 必要に応じて他の開始点でも同じことが起こり、すべての可能な三角形が 1 回だけ削除されます。 

最も一般的な実装上の間違いは、`<= L / 2`の代わりに`< L / 2`。 閉じた半円には、中心が三角形の境界上にあり、カウントする必要がある直径のケースが含まれるため、アルゴリズムは開いた半円に依存します。
