 ## 解決策
 ## 問題の理解

 複数の文字セットが与えられ、各文字はアルファベットでの位置に等しい固有コストを持つロケットステージを表します。 このマルチセットから正確に k 個の異なるステージを選択し、厳密な互換性ルールを尊重する順序で配置する必要があります。文字 x のステージの後に文字 y のステージが続く場合、文字 y はアルファベットで x より少なくとも 2 位置後でなければなりません。 つまり、x が i 番目の文字の場合、y は少なくとも i+2 以上でなければなりません。 

タスクは、指定された文字列から k 個の文字を選択し、選択した文字のアルファベットの合計を最小限に抑えながら、この制約がすべての隣接するペアに適用されるように順序付けすることです。 順序制約を満たす k 個の文字を選択できない場合、答えは -1 になります。 

n ≤ 50 という制約により、原理的にはサブセットに対する総当り攻撃が可能になります。 サブセットは最大 2^50 で、これはすでに大きすぎますが、追加の順序制約により、ほとんどのサブセットが無効になります。 ただし、サブセットのフィルタリングでも、単純に行うとコストがかかりすぎます。 さらに重要な観察は、制約の構造が選択された文字のソート順序のみに依存するため、問題は任意の順列ではなく有効なサブシーケンスの選択に帰着するということです。 

重要なエッジケースは、選択されたすべての文字がアルファベット内で近い場合です。 たとえば、「b」と「c」のような文字を選択する必要がある場合、それらは 1 つの位置しか異なっていないため、条件は失敗します。 もう 1 つのエッジ ケースは、入力に小さな文字が多く含まれているが、k が大きいため、十分な文字が存在するにもかかわらずスペース ルールを維持できない場合です。 

## アプローチ

 直接的なアプローチは、サイズ k のすべてのサブセットを試して並べ替え、間隔ルールを満たしているかどうかを確認することです。 これは正しいです。有効な解はいずれも一部のサブセットに対応し、制約を尊重するそのサブセットの順序も厳密にアルファベット順に増加する必要があるためです。 ただし、サブセットの数は C(n, k) であり、最悪の場合は約 2^50 となり、実現可能な限界をはるかに超えています。 

重要な観察は、選択した文字を並べ替えると、その順序が固定されるということです。 次に、制約はローカルになります。隣接して選択された文字については、その数値が少なくとも 2 異なっていなければなりません。これにより、問題は、合計を最小限に抑えながら、連続して選択された要素が十分な間隔になるように、並べ替えられた配列から k 個の要素を選択することになります。 

この構造は、ソートされた文字に対する貪欲な戦略を示唆しています。つまり、可能な限り小さい文字を選択する必要がありますが、間隔の制約も尊重する必要があります。 将来の選択を妨げない限り、より小さい文字を選択しても実現可能性が損なわれることはないため、ソートされた順序で文字を処理し、長さ k の有効なシーケンスを拡張できるかどうかに応じて、各文字を取得するかスキップするかを貪欲に決定できます。

 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n・k) | O(k) | 遅すぎる |
 | 仕分けされた手紙を貪欲にスキャン | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 最適化はこれらの値のみに依存するため、各文字を 1 ～ 26 の数値重みに変換します。 
2. 重みの配列を昇順に並べ替えます。 これは、制約に違反することなく、最適な解を並べ替えて並べ替えることができ、制約は順序に関して単調であるため、正当化されます。 
3. 異なる長さのシーケンスに対して最後に選択された最小値を追跡する動的プログラミング状態を維持します。 具体的には、dp[j] は、j 個の要素を選択したときに最後に選択された値の最小値を表します。 
4. dp[0] = -infinity および他のすべての dp 値を無限大として初期化します。 基本ケースは、まだ何も選択していないことに対応します。 
5. ソートされた重みを 1 つずつ繰り返します。 各重み x について、dp 配列を k から 1 まで逆方向に更新します。各 j について、x が長さ j-1 の有効なシーケンスを拡張できるかどうかを確認します。つまり、x は少なくとも dp[j-1] + 2 でなければなりません。拡張できる場合は、dp[j] を現在の値と x の間の最小値として更新します。 
6. すべての要素を処理した後、dp[k] がまだ無限大である場合、有効な選択は存在しません。 それ以外の場合、dp[k] は最後の要素の可能な最小値ですが、実際に必要なのは選択した要素の合計です。 合計を正しく追跡するために、dp を最後の値ではなく最小合計として維持します。 
7. したがって、dp[j] を j 個の有効な要素を使用して達成可能な最小合計として再定義し、それに応じて更新します。x が dp[j-1] を拡張できる場合は、dp[j] = min(dp[j], dp[j-1] + x) を設定します。 

### なぜ効果があるのか

 DP の不変条件は、dp[j] がこれまでに処理された j 要素の有効な選択の最小可能合計を格納することです。ここで、有効性には、最後に選択された要素に対する間隔制約が含まれます。 要素を昇順に処理するため、x で終わる有効なシーケンスは、以前の候補または等しい候補によってのみ改善できます。 この遷移では、有効な (j-1) 長のシーケンスに x を追加するすべての方法が考慮され、最小値をとることで最適性が維持されます。 すべての有効なソリューションはソート順に段階的に構築できるため、最適なソリューションが除外されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    a = sorted(ord(c) - ord('a') + 1 for c in s)

    INF = 10**18
    dp = [INF] * (k + 1)
    dp[0] = 0

    for x in a:
        for j in range(k, 0, -1):
            if dp[j - 1] != INF:
                # enforce spacing constraint
                if j == 1 or True:
                    # for j > 1 we still need to ensure gap constraint
                    # but since we are not tracking last value, we must encode differently
                    pass
        # corrected DP below
        pass

    # correct solution: need state with last value tracking
    dp = [[INF] * 27 for _ in range(k + 1)]
    for i in range(27):
        dp[0][i] = 0

    for x in a:
        for j in range(k, 0, -1):
            for last in range(27):
                if dp[j - 1][last] != INF:
                    if j == 1 or x >= last + 2:
                        dp[j][x] = min(dp[j][x], dp[j - 1][last] + x)

    ans = min(dp[k])
    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この実装では 2 次元 DP が使用され、2 番目の次元では最後に選択された文字値が追跡されます。 これが必要なのは、間隔の制約が選択サイズだけではなく隣接性に依存するためです。 各 dp[j][last] は、最後に選択された値が last に等しい、選択された j 要素の最小合計を表します。 新しい文字 x を処理するときは、x が少なくとも last + 2 である場合にのみ、新しいシーケンスを開始するか、既存のシーケンスを拡張します。 

遷移は前の層 dp[j-1] のみに依存するため、最終バージョンでは j に対する逆反復は必要ありません。 この構造により、実行可能性の制約を維持しながら、シーケンスの長さの増加が自然に強制されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · k · 26) | k 状態にわたる DP および最大 26 の最後の値次元
 | スペース | O(k・26) | すべての長さと最後の値の DP テーブルを保存する |

 n ≤ 50 および k ≤ 50 の場合、合計操作は最大でも数万回であるため、これは制限内で快適に実行されます。

def run(inp: str) -> str:

    from collections import deque

    s = sys.stdin.readline().strip()

 ## 特殊なケース

 k=2 の「ab」のような密集したアルファベット セグメントは、直ちに間隔ルールに違反します。 b < a + 2 であるため、DP は 'a' から 'b' へのあらゆる遷移を正しく拒否し、dp[2] が有限になることはありません。 

k=2 の「aaaaaz」など、多数の小さな文字と 1 つの大きな文字がある場合でも、最適な選択は (a, z) であるため、機能します。 DP は dp[1] の a で始まり、z ≥ a + 2 が成り立つため、その後 z でそれを拡張できます。 

すべての文字が同一の場合、2 番目のピックは少なくとも 2 異なることができないため、1 より大きい長さのシーケンスを形成しようとする試みはすべて制約に失敗します。DP は dp[1] のみを有効に保ち、より上位の状態を無限のままにし、必要に応じて -1 を生成します。
