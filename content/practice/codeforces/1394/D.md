 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`山々がつながっている`n-1`すべての山に他の山から到達できるように道路を整備します。 それぞれの山には高さがある`h_i`そして疲労感`t_i`。 ボボニウ氏は、道路を「課題」に分けて整理したいと考えています。課題とは、山の高さが減少しない道を指します。 すべての道路は 1 つのチャレンジに属している必要がありますが、山は複数のチャレンジに表示される場合があります。 チャレンジの疲労度は、そのチャレンジに含まれるすべての山の疲労値の合計です。私たちの目標は、合計の疲労度を最小限に抑えるために道路をチャレンジに分割することです。 

課題は、道路を 1 つの経路にグループ化する方法を制限する、減少しない高さの要件から生じます。 なぜなら`n`まで可能です`2 * 10^5`、考えられるすべてのパスを反復する解決策は実行不可能です。 ほぼ線形のアルゴリズムが必要です`n`。 

単純なアプローチでは、非減少特性を満たすすべてのパスをリストし、すべてのエッジをカバーするパーティションを選択しようとする可能性があります。 これは 2 つの理由で失敗します。 まず、ツリー内のパスの数は指数関数的です。 第二に、たとえ列挙を無視したとしても、すべてのサブセットに対する単純な DP には時間がかかります。`O(2^n)`時間。 エッジ ケースには、同じ高さの山、リーフ ノード、および山が複数の増加シーケンスを接続するジャンクションとして機能するため、複数回カウントする必要があるパスが含まれます。 たとえば、ルートの高さが低く、すべての子の高さが高い場合、ルートはその子から始まるすべてのチャレンジに含める必要があります。 

## アプローチ

 ブルートフォースアプローチでは、ツリーの非減少パスへのあらゆる可能な分解を試み、それぞれの疲労度を計算し、最小値を取得します。 すべてのパーティションが考慮されるため正確性が保証されますが、パーティションの数はより速く増加します。`O(2^n)`。 小さくても`n`、これは実現不可能です。 

重要な洞察は、ツリー構造と単調性制約を活用することです。 それぞれの山とその子供たちについて考えてみましょう。 子供の身長が親よりも高い場合は、親から始まる同じ課題に参加することができます。 それが低い場合は、その子に新たな挑戦を始めなければなりません。 この観察は、ツリー上の動的プログラミング ソリューションを示唆しています。各ノードについて、2 つのケースの下でサブツリー内のすべてのエッジをカバーするために必要な最小限の疲労度を追跡します。 ケース 1 は、ノードがその親チャレンジの開始点である場合です。 ケース 2 は、独自の挑戦を開始する場合です。 ポストオーダートラバーサルを使用して、子からの結果を組み合わせて、現在のノードの最小疲労度を計算します。`t_i`ノードが複数のチャレンジに参加する場合。 この問題は、各ノードを 1 回処理し、その子からの結果をマージする DP に帰着します。`O(n)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ツリー上の最適な DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを任意に、たとえばノード 1 にルートします。これにより、親子関係が簡素化され、単一の走査順序が確保されます。 
2. 各ノードの DP を定義します。`u`。 保守します`dp[u]`をルートとするサブツリーのすべてのエッジをカバーする最小疲労合計として`u`。 便宜上、次の 2 つの値を追跡します。`dp[u].up`からのパスの場合`u`親に続き、`dp[u].alone`もし`u`子どもたちのために新たな挑戦が始まります。 
3. ツリーを事後順序で走査します。 ノードごとにすべての子を処理します`v`。 もし`h[v] > h[u]`、子供は次の課題を拡張できます。`u`。 次に、への貢献`dp[u].up`は`dp[v].up`。 そうでない場合は、次の時点で新たな挑戦を開始する必要があります。`v`、追加`dp[v].alone`プラス`t[u]`に`dp[u].alone`。 
4. すべての子供を処理した後、子供たちの最小疲労度を決定します。`u`最小限の繰り返しカウントですべてのエッジをカバーする値の組み合わせを選択します。 含む`t[u]`パスを延長できない子供のため、毎回 1 回ずつ複数のチャレンジでカウントする必要があります。 
5. 戻る`dp[root].up`、すべての道路をカバーする最小の合計疲労を表します。 

これはどのノードでも不変条件であるため機能します。`dp[u]`は、親チャレンジを継続するか新たに開始するかを考慮して、サブツリーに必要な最小限の疲労を正確に捕捉します。 事後トラバーサルにより、すべての子サブツリーが親よりも前に処理されるため、組み合わせは正しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n = int(input())
t = list(map(int, input().split()))
h = list(map(int, input().split()))
edges = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    edges[u].append(v)
    edges[v].append(u)

def dfs(u, parent):
    max_gain = []
    total = 0
    for v in edges[u]:
        if v == parent:
            continue
        child = dfs(v, u)
        if h[v] > h[u]:
            total += child
        else:
            total += child
            max_gain.append(t[v])
    if not max_gain:
        return total + t[u]
    max_gain.sort(reverse=True)
    return total + t[u] + max_gain[0]

ans = dfs(0, -1)
print(ans)
```再帰を使用してポストオーダートラバーサルを実装します。 各子は親の身長と比較してチェックされ、チャレンジを続行できるかどうかが決定されます。`max_gain`マージできない子マウンテンのオプションの追加をキャプチャします。 並べ替えにより、必要に応じて最大の寄与が最初に追加されるようになります。 による再帰`sys.setrecursionlimit`深い木を処理できることが保証されます。
