 ## 解決策
 ## 問題の理解

 私たちには、Du のメッセージが毎日どれほど面白いかを表す一連の「楽しい値」が与えられます。 プロセスが開始される前に、これらの値を任意の順序で並べ替えることができます。 順序を決定すると、左から右に日が進みます。 

毎日、Du が現在ミュートになっていない場合は、シーケンスから次の値を取得し、それを合計の楽しみに追加します。 その値が指定されたしきい値より大きい場合`m`、ボボニウは怒り、ドゥに次の発言をやめるよう強制します。`d`日々。 静かな日の間は、価値も消費されず、楽しみも得られず、プロセスは単に時間をスキップして進みます。 

目標は、蓄積された楽しみの合計が最大化されるように配列を並べ替えることです。 

主な問題点は、値が大きいと強制的な沈黙が引き起こされ、今後のポジションが無駄になるため危険であるということです。 値が小さい場合は、ペナルティが発生することはなく、常にアクティブな発言日を効率的に埋めることができるため、安全です。 

制約は次のとおりです`n = 100000`これにより、階乗または二次順列検索が即座に除外されます。 平`O(n^2)`すべての並べ替えにわたる貪欲なシミュレーションは不可能です。 各要素を制御された構造内に 1 回だけ配置する戦略が必要です。理想的には、`O(n log n)`または`O(n)`時間。 

降順でソートし、利用可能な最大の値を常に選択する単純な貪欲型は、失敗する可能性があります。これは、大きな値をあまりにも早く配置すると、長いミュート間隔により将来の位置が多すぎる可能性があるためです。 逆に、大きな値を常に延期することも、小さな値が無駄になる時間を「ブロック」するために使用する必要がある場合には、最適ではない可能性があります。 

すべての値が より大きい場合、微妙なエッジ ケースが発生します。`m`。 次に、選択されたすべての要素がミュートをトリガーします。 例えば、`n = 5, d = 2, m = 0, a = [1,2,3,4,5]`。 どの順序付けでも頻繁にブロックが発生するため、戦略では、大きな値に最適な位置のみを使用し、無駄な配置を最小限に抑える必要があります。 

別の特殊なケースが発生するのは、`d = 1`。 この場合、大きな値はすべて翌日のみブロックされるため、間隔は最小限になり、問題は単純な最適な位置の選択にはるかに近づきます。 過度に複雑なスケジューリングは不要ですが、それでも正しい結果を生成する必要があります。 

## アプローチ

 ブルートフォース手法では、配列のすべての順列を列挙し、各順列のプロセスをシミュレートし、結果として得られる fun を計算します。 順列ごとに、ポインタとクールダウン カウンターを維持しながら、左から右にスキャンします。 より大きい値に遭遇するたびに、`m`、次はスキップします`d`ポジション。 このシミュレーションの費用は`O(n)`順列ごとに、`n!`順列が変化し、実行不可能な結果が生じる`O(n! * n)`複雑。 

主な構造上の観察は、以下の値のみが存在するということです。`m`ブロッキングのダイナミクスに影響を与えます。 価値観`<= m`は「安全」です。ミュートをトリガーすることはありません。したがって、それらを配置するために利用できるアクティブな日数を除いて、常に順序とは独立して貢献します。 問題は、利用可能な発言スロットのタイムラインのどこに大きな値を配置するかを決定することに帰着します。 

配列を 2 つのグループに分けることができます: 安全な値 (`<= m`) と危険な値 (`> m`）。 安全な値は、将来の可用性を低下させることがないため、講演可能な日があるときは常に貪欲に採用する必要があります。 課題は、貢献を収集しながらブロック効果を最小限に抑えるために、危険な値をどのように配置するかになります。 

重要な洞察は、危険な値を降順で処理し、貪欲なスケジューリング構造を使用してタイムラインへの配置をシミュレートすることです。 それぞれの危険な値は 1 つのアクティブな日を消費し、次のアクティブな日をブロックします。`d`数日かかるため、事実上タイムラインに「ギャップ」が生じます。 一方、安全な値は、ブロックされていない残りのポジションをすべて埋めるだけです。 

これにより、残りのアクティブなスロットの数と、ギャップを埋めるために使用できる安全な値の数を維持する貪欲なプロセスが発生します。 同じブロックコストが発生しても、より高い報酬が得られるため、私たちは常に、より大きな危険な値を最初に配置することを優先します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 分割 + 貪欲なスケジューリング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を 2 つのソートされたグループに変換し、利用可能な日の間で危険な値の最適なスケジュールをシミュレートします。 

1. 配列を 2 つのリストに分割します。1 つは、以下の値をすべて含むリストです。`m`もう 1 つは以下の値をすべて含むものです。`m`。 より大きなグループのみがブロック動作を引き起こすため、この分離が必要です。 
2. 両方のリストを降順に並べ替えます。 最大値は、同じブロッキング コストでより高い即時ゲインを提供するため、使用可能なスロットの中で前に配置する必要があります。 
3. これまでに使用できる「有効なポジション」がいくつあるかを計算します。 それぞれの危険な値は 1 日を占め、次の値が削除されます。`d`利用可能になってから数日かかるため、各プレースメントはサイズのブロックを消費します`d + 1`。 
4. 危険な値を降順に貪欲に反復し、有効なスロットに関して利用可能な容量がある限り、各値を配置します。 各配置はその値を答えに寄与し、残りの容量を減らします。 
5. 考えられるすべての危険な値を設定した後、残りの使用可能な日数をすべて安全な値で埋めます。 安全な値はブロックをトリガーしないため、できるだけ多くの値を取得し、それらをすべて回答に追加します。 
6. 残りのスロットよりも安全な値がある場合でも、安全な値は相互に干渉したり、スケジュールに干渉したりしないため、すべてを採用します。 

### なぜ効果があるのか

 重要な不変条件は、すべての危険な値がちょうど 1 つの「アクティブ化スロット」を消費し、決定的に削除されるということです。`d`配置場所に関係なく、将来使用できるスロット。 これにより、すべての危険な価値はコストの点で交換可能になり、利点のみが異なります。 したがって、それらを降順に並べ替えて貪欲に選択すると、固定された可能なアクティベーション数の下で合計ゲインが最大化されます。 安全な値は将来のアクティベーションの可用性に影響を与えないため、危険なスケジュールが修正されたら、いつでも独立して追加できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    big = []
    small = []
    
    for x in a:
        if x > m:
            big.append(x)
        else:
            small.append(x)
    
    big.sort(reverse=True)
    small.sort(reverse=True)
    
    # maximum number of big elements we can place
    # each big consumes (d + 1) effective positions
    max_big = (n + d) // (d + 1)
    
    take_big = min(len(big), max_big)
    
    ans = sum(big[:take_big])
    
    # remaining positions after placing big elements
    remaining_slots = n - take_big * (d + 1)
    
    # we can place all small elements in remaining slots
    ans += sum(small[:remaining_slots])
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、値が次の値を超えるかどうかに基づいて、危険なグループと安全なグループに分割することから始まります。`m`。 両方のグループを降順に並べ替えることで、常に最も価値のある要素を最初に考慮することができます。 

表現`(n + d) // (d + 1)`各危険値は 1 日を占有し、次の日を無効にするため、最良の場合に「ブロック イベント」をトリガーできる回数を計算します。`d`日々。 これにより、スケジュールできる大きな要素の数に上限が与えられます。 

取得する大きな要素の数を選択した後、小さな要素に実際に使用できる残りの日数を計算します。 これらには、利用可能な最良の安全な値が単に入力されます。 

重要な点は、日ごとの変化を明示的にシミュレートしないことです。 代わりに、各大きな値が消費する有効なスロットの数をカウントするようにプロセスを圧縮します。

 ## 特殊なケース

 すべての値が以下の場合`m`、アルゴリズムはすべてを小さなグループに配置し、残りのスロットを次のように計算します。`n`。 ブロッキングは発生しないため、答えはすべての値の合計になります。 例えば、`n = 4, m = 10, a = [1,2,3,4]`その結果、4 つの要素すべてが選択されます。 

すべての値が超過した場合`m`、アルゴリズムは完全に容量公式に依存します。`(n + d) // (d + 1)`。 選択された各要素はブロック全体を消費し、最大数の要素のみが選択されます。 のために`n = 5, d = 2, a = [5,4,3,2,1]`、最大 2 つの要素が選択され、次のようになります。`5 + 4 = 9`。 

いつ`d`に比べて大きい`n`、使用できる大きな要素は 1 つまたは 2 つだけです。 残りのスロットは、小さな値が存在する場合は、その値で完全に埋められます。 このケースでは、順序に関係なく、容量計算が危険な値の影響を正しく制限していることが確認されています。
