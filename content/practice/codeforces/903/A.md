 ## 解決策
 ## 問題の理解

 このタスクでは、Ivan が 3 つの塊の小さな部分と 7 つの塊の大きな部分だけを使用して、正確に _x_ 個の鶏肉の塊を購入できるかどうかを尋ねます。 各テスト ケースではターゲットのチャンク数を指定し、その正確な数が小さい部分と大きい部分の負でない組み合わせとして取得できるかどうかを出力で示す必要があります。 

入力は、テスト ケースが最大 100 個で、各テスト ケースの目標チャンク数が 100 を超えないように制限されます。これは、テスト ケースあたり数千回の演算のオーダーで複雑なアルゴリズムを許容できることを意味します。 たとえば、小さな部分と大きな部分のすべての組み合わせを試行する単純なネストされたループは、制限時間内でも快適に実行されます。 

ターゲットが大きな部分のサイズより小さい場合、微妙なエッジケースが発生します。 たとえば、Ivan が 5 つのチャンクを望んでいる場合、唯一の選択肢は 1 つまたは 2 つの小さな部分ですが、どちらの合計も 5 にはなりません。ターゲットが 3 または 7 で割り切れるかどうかだけをチェックする単純な実装では、一部の数値に対して誤って YES と答えてしまうため、単一の倍数ではなく部分の組み合わせを考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、小さな部分の可能なすべてのカウントを繰り返し、大きな部分でカバーする必要がある残りのチャンクを計算し、その余りが 7 で割り切れるかどうかをチェックします。形式的には、ターゲット _x_ に対して、_a = 0_ から _a_max = x // 3_ を試行し、各 _a_ について _b = (x - 3_a) / を計算します。 7*。 _b_ が負ではない整数の場合、答えは YES です。 これは、すべての有効な組み合わせを徹底的にテストするため、正しいです。 最大の _x_ が 100 の場合、テスト ケースごとに最大 34 回の反復があり、テスト ケースが最大 100 の場合、合計操作数は約 3400 であり、これは許容範囲内です。 

より高速なアプローチは、貪欲な観察に依存しています。つまり、任意の数値 _x >= 12_ は、常に 3 と 7 の組み合わせとして表すことができます。 12 未満の数値は事前に計算できます。 これが機能するのは、3 の倍数と 1 つ以上の 7 を組み合わせるのに十分なチャンクがあれば、後続のすべての数字は 3 を追加することで形成できるためです。 この観察により、各クエリが単純なチェックに減らされます。_x >= 12_ または _x_ が、事前に計算された 12 未満の表現可能な数値の小さなセットに含まれています。これにより、前処理後のテスト ケースごとの解は O(1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(x_max * n) = O(100 * 100) | お(1) | 承認済み |
 | 事前計算 / 貪欲 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース _n_ の数を読み取ります。 
2. 各テスト ケースについて、ターゲットのチャンク数 _x_ を読み取ります。 
3. _x_ が 12 以上の場合は、すぐに YES を出力します。 これは、12 以上の数値は 3 と 7 の合計に分解できるという特性に基づいています。 
4. _x < 12_ の場合は、3 と 7 の合計として表現できるかどうかを明示的にチェックします。 この範囲で表現できる数値は 3、6、7、9、10 です。 
5. _x_ が表現可能な場合は YES を出力し、それ以外の場合は NO を出力します。 

機能する理由: 不変条件は、すでに 7 を含む数値に 3 を繰り返し加算することで、後続のすべての数値が確実にカバーされるため、12 以降の数値には常に到達可能であるということです。 12 未満の数値については、完全な列挙により、どの値を表現できるかが確認されます。 これにより、アルゴリズムが不可能な数値が達成可能であると誤って主張しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_buy_chunks(x):
    if x >= 12:
        return True
    return x in {3, 6, 7, 9, 10}

n = int(input())
for _ in range(n):
    x = int(input())
    print("YES" if can_buy_chunks(x) else "NO")
```機能`can_buy_chunks`コアロジックをカプセル化します。 チェック中`x >= 12`多数の貪欲な洞察を捕捉します。 数値が小さい場合は、セットを使用すると O(1) メンバーシップ テストが確実に行われます。 高速 I/O が使用される理由は、`input()`各行を効率的に読み取ります。 _x = 1_ や _x = 2_ などのエッジ ケースは表現できないため、正しく NO を返します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各テスト ケースは、セット チェックまたは貪欲ルールのいずれかによって O(1) で処理されます。 
| スペース | お(1) | 事前に計算された小さな数値のセットは一定です。 追加の動的メモリは必要ありません。 

n ≤ 100 とすると、これは 1 秒および 256 MB 以内に十分収まります。

 ## 特殊なケース

 可能な最小のターゲット _x = 1_ または _x = 2_ の場合、アルゴリズムは正しく NO を返します。 _x = 3_ または _x = 7_ の場合、アルゴリズムは、それぞれ小さい部分と大きい部分から到達可能であると識別します。 12 以上のようなターゲットの場合、アルゴリズムは、7 を含む基本の組み合わせに十分な 3 の倍数を加算することで任意の組み合わせを形成できるという特性に基づいて、即座に YES を出力します。これにより、1 ～ 100 の入力範囲全体にわたって正確さが保証されます。
