 ## 解決策
 ## 問題の理解

 最大 200,000 個の整数の配列が与えられます。 ポジションのペアごとに$(i,j)$と$i\le j$、特別な関数を評価します$d(a_i,a_j)$、すべてのペアの合計が必要です。 

関数は通常の差分とは異なる動作をします。 2 つの数値の差が最大 1 の場合、それらの寄与はゼロになります。 それ以外の場合、寄与分は通常の差額に等しい$a_j-a_i$。 正の値と負の値の両方が可能です。 

ペアの順序はインデックスを通じてのみ重要であるため、配列を左から右に処理すると想像できます。 ポジションに到着したら$j$、以前のすべての要素$a_i$で終わる 1 つのペアを形成します$j$。 問題は、以前のすべての数値が現在の値にどの程度寄与しているかということです。 

限界$n\le 2\cdot10^5$二次アルゴリズムを除外します。 単純な二重ループは大まかに検査します$$\frac{200000\cdot199999}{2}\approx2\cdot10^{10}$$これは 2 秒をはるかに超えています。 解決策$O(n\log n)$または$O(n)$が必要です。 

微妙なケースの 1 つは、ちょうど 1 だけ異なる数値から生じます。 このようなペアの寄与はゼロではなく、$\pm1$。 

入力：```
2
5 6
```唯一のペアに違いがあります$1$、したがって、答えは次のとおりです```
0
```通常の減算を使用した不用意な実装では、$1$。 

もう 1 つの罠はマイナスの貢献です。 

入力：```
2
10 1
```ペアは貢献します$1-10=-9$の絶対値が 1 を超えているため、正解は次のようになります。```
-9
```関数を絶対差として扱うと、次のようになります。$9$、これは間違いです。 

繰り返される値も特別です。 

入力：```
3
7 7 7
```すべてのペアはゼロずつ異なるため、すべての寄与がなくなり、答えは次のようになります。```
0
```禁止された差分を削除せずに、プレフィックスの合計のみに基づいた式$0,\pm1$これらのペアを間違ってカウントしてしまいます。 

## アプローチ

 最も直接的なアプローチでは、すべてのペアをチェックします。$(i,j)$。 各ペアについて、通常の差を計算します。$a_j-a_i$。 その絶対値が 1 以下の場合は、0 に置き換えます。 このような寄与をすべて合計すると、定義に文字通り従うため、明らかに正しいです。 

問題はペアの数です。 と$n=200000$、約200億ペアあります。 非常に低コストの操作であっても、制限時間内にそれほど多くのペアを処理することはできません。 

作業をスピードアップするには、1 つのポジションを検討してください$j$。 以前のすべての要素がすでにわかっていると仮定します。 特別なルールをしばらく無視すると、以前の数値の寄与度の合計は次の値に等しくなります。$$\sum_{i<j}(a_j-a_i) =(j-1)\cdot a_j-\text{prefixSum}.$$以前のすべての要素の合計を維持する場合、この式は一定時間で更新できます。 

唯一の問題は、値の違いが最大 1 であるペアは、通常の差ではなくゼロに寄与する必要があることです。 これらのペアは上記の式内にすでに含まれているため、それらの寄与を差し引く必要があります。 

現在の値の場合$x$、以前に発生したもののみ$x-1$、$x$、 そして$x+1$修正が必要です。 彼らの数は十分です。 あれば

 -$cnt[x-1]$以前の値は次と等しい$x-1$、
 -$cnt[x]$以前の値は次と等しい$x$、
 -$cnt[x+1]$以前の値は以下に等しい$x+1$、

 次に、通常の式が追加されます$$1\cdot cnt[x-1]+0\cdot cnt[x]-1\cdot cnt[x+1]$$禁断のペアのために。 彼らの貢献はゼロであるはずなので、正確にこの金額を差し引きます。 

ハッシュ テーブルにより、これらのカウントを期待どおりに利用できるようになります$O(1)$時間をかけ、線形の解を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各値がこれまでに出現した回数を格納するハッシュ マップを初期化します。 また、前の要素の合計と実行中の答えも維持します。 
2. 配列を左から右に処理します。 現在値が$x$、まず、以前のすべての要素の通常の寄与を計算します。$$(j-1)\cdot x-\text{prefixSum}$$これは次の合計に等しい$x-a_i$以前のすべてのインデックスに対して。 

1. 等しい以前の値がいくつあるかを見つける$x-1$、$x$、 そして$x+1$。 

これらはまさに、ペアごとの差が存在する値です。$x$絶対値は最大でも 1 です。 

1. 通常の公式には、これらのペアからの寄与がすでに含まれています。 式内での彼らの貢献度の合計は次のとおりです。$$cnt[x-1]-cnt[x+1].$$等しい値を持つペアは、補正前であっても寄与がゼロになります。 

1. 現在の貢献度からこの量を減算します。 

この調整の後、すべての禁止されたペアの寄与は事実上ゼロになります。 

1. 修正した投稿を回答に追加します。 
2. 現在の値を周波数マップに挿入し、プレフィックスの合計を更新します。 
3. すべての要素が処理されるまで続行します。 

### なぜ効果があるのか

 すべてのステップで、接頭辞合計式は、現在の要素とそれ以前のすべての要素の間の通常の差の合計を計算します。 問題定義に違反する唯一のペアは、相違点のあるペアです。$-1$、$0$、 または$1$。 このようなペアには値のみを含めることができます$x-1$、$x$、 そして$x+1$、通常の合計内の彼らの合計貢献度は正確に$cnt[x-1]-cnt[x+1]$。 その量を取り除くと、通常の差の合計が必要な関数に変換されます。 すべてのペアは、その右のエンドポイントが処理されるときに 1 回だけ現れるため、最終的な答えは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = {}
    prefix_sum = 0
    ans = 0

    for i, x in enumerate(a):
        cur = i * x - prefix_sum

        cur -= freq.get(x - 1, 0)
        cur += freq.get(x + 1, 0)

        ans += cur

        freq[x] = freq.get(x, 0) + 1
        prefix_sum += x

    print(ans)

solve()
```変数`prefix_sum`以前に処理されたすべての数値の合計を保存します。 インデックスの要素の場合`i`、式`i * x - prefix_sum`以前のすべての値との通常の差の合計を計算します。 

次の 2 行で修正を実行します。 これまでに発生したすべての`x-1`貢献した`+1`通常の金額の範囲内であるため、これらの拠出金は消滅する必要があります。 これまでに発生したすべての`x+1`貢献した`-1`、負の量を引くと加算になります。 

順序が重要です。 現在の値は、その寄与が計算される前に周波数マップに挿入してはなりません。 そうすると、要素とそれ自体で構成されるペアが誤ってカウントされます。 

Python の整数は、任意のサイズに自動的に拡張されます。これは、言語によっては、答えが 64 ビットの制限を超える可能性があるため、必要です。
