 ## 解決策
 ## 問題の理解

 私たちには数枚の銀行カードが渡され、それぞれに 4 桁の PIN コードが関連付けられています。 タスクは、1 桁の変更をできるだけ少なくしながら、2 枚のカードが同じ最終コードを共有しないようにこれらの PIN を変更することです。 1 回の操作で 1 つの PIN の 1 つの位置が他の桁に変更されるため、どの桁が選択されたかに関係なく、各変更には単価がかかります。 

出力では、そのような桁編集の最小数を示すだけでなく、この最小コストを達成するすべての PIN の最終的な有効な構成を 1 つ示す必要があります。 

重要な問題は、「文字列全体を無料で再割り当て」することができないことです。 2 つの同一の PIN が存在する場合、桁を変更してその等価性を積極的に破る必要があり、それぞれの変更にコストがかかります。 各 PIN の長さは 4 で、n は最大 10 であるため、合計の検索スペースは十分に小さいため、強力な最適化構造に依存するのではなく、競合を直接推論できます。 

制約は非常に厳しく、テスト ケースあたり最大 10 PIN、テスト ケース 100 個です。 これにより、非常に小さな定数を超える n の指数関数は即座に除外されますが、4 桁の文字列の限られた状態空間に対するブルート フォース スタイルの競合解決が可能になります。 

多くの PIN が同一である場合、微妙なエッジ ケースが発生します。 たとえば、10 枚のカードすべてに「1111」が含まれている場合、桁の変更を最小限に抑えながら、10 個の異なるコードを慎重に割り当てる必要があります。 「一意になるまでインクリメントする」という単純な考えは、異なる位置を変更することでコストが削減される可能性があることを無視しているため、失敗する可能性があります。 

別の失敗例は、複数の重複が存在するが部分的に重複する可能性がある場合に発生します。 たとえば、「0000, 0000, 0000, 0001」は、新しい任意のコードをやみくもに生成するのではなく、既存の文字列の構造を再利用することで安価に解決できます。 

## アプローチ

 ブルートフォース手法では、10,000 通りの可能性がある空間全体から一意の 4 桁の文字列を各 PIN に割り当て、元のリストに対するハミング距離の合計を最小限に抑えようとします。 これは概念的には正しいです。各割り当てコストは、元のコードと選択したコード間の異なる桁数にすぎず、最小コストの注入マッピングが必要です。 

ただし、総当たり検索の領域は天文学的に大きいです。 カードあたりの候補を 10,000 個のみに制限したとしても、すべての単射写像を試すには、一度に 10 個ずつ取得される最大 10,000 個のサイズの順列が必要になり、これは完全に実行不可能です。 

重要な単純化は、n が小さく、競合が局所的であることに気づくことから始まります。 10,000 個のコードすべてをグローバルに考えるのではなく、貪欲に答えを構築し、一度に 1 つの PIN ごとに衝突を解決します。 各 PIN はすでに一意であるか、わずかに変更する必要があります。 変更はローカル (4 つの位置のみ) であるため、各 PIN を、小さな状態空間内の未使用のスロットに「プッシュ」するノードとして扱うことができます。 

これが機能する理由は、衝突が発生するたびに、ハミング距離の観点から最も近い未使用のコードを見つけるだけでよいということです。 検索スペースが小さいため、コストの降順で近くの代替案を列挙したり、数字の置換に対して制限付き DFS を実行したりすることができます。 n は最大 10 であるため、競合する PIN ごとにすべての変更を試みても、一定のスケールのままになります。 

したがって、グローバル割り当ての代わりに、使用されている PIN のセットを維持し、競合する各エントリを一意になるまで最小限に変更することで、重複を段階的に修正します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース グローバル割り当て | O(10000^n) | O(n) | 遅すぎる |
 | 貪欲な現地修理 | O(n * 10^4) 個の最悪の場合の小さな定数 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すでに使用されている最終コードのセットを維持しながら、PIN を 1 つずつ処理します。

1. 出力順序は入力順序と一致する必要があるため、テスト ケースのすべての PIN を読み取り、順番に保管します。 

目標は、作業を進めながら重複を排除した最終的なリストを作成することです。 
2. セットを維持する`used`最終回答ですでに割り当てられている PIN が含まれています。 

これにより、候補コードが利用可能かどうかを定期的にチェックできます。 
3. 各 PIN について、まずそれがすでに使用されていないかを確認します。 

入っていない場合`used`を変更せずにセットに挿入します。 いかなる変更も不必要にコストを増加させるだけであるため、これは最適です。 
4. PIN がすでに使用されている場合は、それを変更する必要があります。 一度に 1 桁ずつ変更して新しい候補を生成しようとします。 

0 から 3 までのすべての位置と 0 から 9 までのすべての数字を試し、候補文字列を計算します。 
5. すべての有効な候補者の中で、`used`、元の PIN までのハミング距離が最小のものを選択します。 

各候補は正確に 1 つの位置で異なるため、このコストは 1 となり、競合解決ステップとして可能な最小値となります。 
6. PIN を選択した候補に置き換えて、`used`。 
7. 実行された変更の数を累積します。 これは、桁変更の合計数です。 

重要な点は、競合が最初に 1 桁の変更で貪欲に解決されることです。 n が非常に小さく、各 PIN の位置が 4 つだけであるため、この局所的な最適性で十分です。先に進む前に、1 つの PIN に必要以上の変更を加える必要はありません。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、処理されたすべての PIN が一意であるという不変条件を維持します。 新しい PIN が追加されるときに、それが競合する場合は、ハミング距離で最も近い未使用の文字列に置き換えます。 有効な解決策では衝突を解消するために少なくとも 1 桁の変更も必要となるため、そのステップでは常に 1 桁の変更を選択することが最適です。 状態空間の有界構造により、有効な候補がなくて行き詰ることがありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        pins = [input().strip() for _ in range(n)]
        
        used = set()
        ans = []
        changes = 0
        
        for s in pins:
            if s not in used:
                used.add(s)
                ans.append(s)
                continue
            
            # must modify
            best = None
            best_cost = 10
            
            for i in range(4):
                for d in '0123456789':
                    if d == s[i]:
                        continue
                    cand = s[:i] + d + s[i+1:]
                    if cand not in used:
                        best = cand
                        best_cost = 1
                        break
                if best:
                    break
            
            ans.append(best)
            used.add(best)
            changes += 1
        
        print(changes)
        for x in ans:
            print(x)

if __name__ == "__main__":
    solve()
```実装は段階的な構築を反映しています。 の`used`set は一意性を強制しますが、ネストされたループは衝突が検出されるたびに最小限の 1 桁の修正を試みます。 検索は 4 つの位置と 10 桁に制限されているため、実際には候補の生成は定数時間で行われます。 

微妙な実装の詳細は、有効な代替が見つかった場合の早期終了です。 この貪欲なステップには単一変更の有効な候補が最適であるため、検索を続ける必要はありません。

 ## 特殊なケース

 「0000」のような完全に複製された入力を 10 回繰り返すと、貪欲な修復ロジックが最も強く実行されます。 アルゴリズムは、最初に出現したものを変更せずに処理し、必要に応じて「1000」、「2000」などを割り当てます。 ハミング距離 1 で未使用の数値があれば十分であり、衝突が密になるまで小さな桁スペースが可用性を保証するため、各ステップでは 1 桁の変更のみが必要です。 

もう 1 つの特殊なケースは、「1234」と「1235」のように、2 つのコードが最後の桁のみが異なる場合です。 3 番目の同一の「1234」が出現した場合は、より大きな変更を検討する前に変更され、最小限のコストが維持されます。 このような状況では、アルゴリズムは決して複数桁の編集を試行しません。これは、この制約された状態空間での最適なローカル修復と一致します。
