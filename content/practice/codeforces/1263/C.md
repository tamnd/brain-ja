 ## 問題の理解

 私たちには一定量の評価ポイントが与えられます。$n$。 引き分けの場合、これらのポイントは均等に分割されます。$k$ただし、ユニット全体のみが配布されるため、各参加者が受け取ります$\lfloor n / k \rfloor$ポイント。 残ったポイントは破棄されます。 

タスクは、単一の引き分けをシミュレートすることではなく、参加者ごとの利益として現れる可能性のあるすべての個別の値を列挙することです。$k$すべての正の整数にわたって変化します。 つまり、次の関数を考えます。$f(k) = \lfloor n/k \rfloor$そして、この関数が取り得るすべての値のセットが必要です。 

出力に関する重要な観察点は、次のさまざまな値が存在することです。$k$同じ商を生み出します。 たとえば、かつて$k > n$、値はゼロになり、永久にゼロのままになります。 これはすでに、すべてを反復処理することを示唆しています。$k \le n$は不要です。 

制約$n \le 10^9$すべてをループするアプローチを除外します$k$直接。 リニア スキャンにはテスト ケースごとに最大 10 億回の反復が必要ですが、これは 1 秒で許容される回数をはるかに超えています。 広い範囲をスキップする方法が必要です$k$同じ商を生み出すもの。 

微妙なエッジケースが、小さい値と大きい値の間の境界に現れます。$k$。 たとえば、次のようなとき$n = 1$、出力はのみです$1$そして$0$。 ナイーブなアプローチは、次の場合に早期に停止します。$\lfloor n/k \rfloor$ゼロになると、ゼロがまだ有効な値であり、含める必要があるという事実を見逃してしまう可能性があります。 

もう 1 つのよくある間違いは、値を誤って重複排除することです。 違うので$k$間隔を指定しても同じ結果が得られるため、注意してグループ化せずに値を収集するだけでは、エントリが繰り返されたり、値が欠落したりする可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、あらゆることを試します。$k$から$1$に$n$、計算する$\lfloor n/k \rfloor$、結果をセットに挿入します。 考えられるすべての参加者数が考慮されるため、これは正しいです。 ただし、そのコストは、$O(n)$テスト ケースごとに分割することは不可能になります。$n = 10^9$。 

重要な構造特性は次のとおりです。$\lfloor n/k \rfloor$は、次の間隔にわたって一定に留まる非増加関数です。$k$。 値を固定すると$v = \lfloor n/k \rfloor$、それからすべて$k$連続した範囲内では、これと同じ商が満たされます。 すべてを繰り返すのではなく、$k$を使用すると、商が変化する各区間の終わりに直接ジャンプできます。 

重要な洞察は、固定された$k$、 もし$v = n // k$、次に最大の$k$それでも価値を与えるもの$v$は$k = n // v$。 これにより、ブロック全体をスキップできます$k$一気にステップ数を大幅に削減$O(\sqrt{n})$、どちらかですから$k$または$v$相手が小さいときは大きく成長しなければなりません。 

この場合、問題は両側のスイープになります。つまり、増加を繰り返すか、$k$、または同等の個別の値の減少$v$、商が変化するブレークポイント間をジャンプします。

 ## アルゴリズムのチュートリアル

 すべての個別の値を収集したいと考えています。$\lfloor n/k \rfloor$全部列挙せずに$k$。 

1. から始める$k = 1$。 これにより最大値が得られます$n$、 以来$\lfloor n/1 \rfloor = n$。 
2. コンピューティング$v = \lfloor n/k \rfloor$。 これは、含める必要がある 1 つの異なる出力値です。 
3. に移動する代わりに$k + 1$、同じ値が存在する最後の位置に直接ジャンプします。$v$が成立する。 その立場は、$k_{\text{end}} = n // v$。 これが機能するのは、すべてが$k$範囲内で$[k, k_{\text{end}}]$同じ商を生み出す$v$。 
4. に移動します$k = k_{\text{end}} + 1$、商は厳密に減少します。 プロセスを繰り返します。 
5. まで続けます$k > n$。 その時点で商はゼロになるので、一度ゼロが含まれるようにする必要があります。 

なぜジャンプが有効であるかは、除算の単調性に依存します。$k$増加し、$n/k$が減少し、整数の下限は商が少なくとも 1 下がる特定のブレークポイントでのみ変更されます。 解決中$\lfloor n/k \rfloor = v$正確に範囲を返します$k \in [\lfloor n/(v+1) \rfloor + 1, \lfloor n/v \rfloor]$、だからジャンプして$n//v$現在のプラトーの境界に達します。 

維持される不変条件は、すべての整数が$k$現在のポインタよりも小さい値は、すでに正確に 1 つのセグメントで考慮されており、各セグメントは正確に 1 つの別個の商値に寄与します。 関数はブレークポイントを通過する場合にのみ変更されるため、値がスキップされたり、重複が追加されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    res = []
    k = 1

    while k <= n:
        v = n // k
        res.append(v)
        k = n // v + 1

    res.append(0)
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    ans = solve_case(n)
    print(len(ans))
    print(*ans)
```この実装は、関数の定数セグメント間をジャンプするという考えに従っています。$\lfloor n/k \rfloor$。 ループは現在の商を計算し、商が変化する次のインデックスに直接ジャンプします。$k = n // v + 1$。 

微妙な点は、最後にゼロが明示的に追加されていることです。 ループは次の値のみを処理します。$k \le n$したがって、当然のことながらすべての正の商をカバーしますが、最後のゼロ領域を明示的に生成する前に停止します。 以来$k > n$結果がゼロになる場合は、最後に 1 回追加します。 

注文はすでに減少しています。$k$増加し、$n // k$決して増えません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        n = int(input())
        res = []
        k = 1
        while k <= n:
            v = n // k
            res.append(v)
            k = n // v + 1
        res.append(0)
        return res

    t = int(input())
    out = []
    for _ in range(t):
        ans = solve()
        out.append(str(len(ans)))
        out.append(" ".join(map(str, ans)))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 いつ$n = 1$、ループは次から始まります$k = 1$、生成します$v = 1$、にジャンプします$k = 2$、すでに超えています$n$。 この時点では、アルゴリズムはまだゼロを追加します。 結果はまさに$[1, 0]$、これは可能な下限値の完全なセットと一致します。 

いつ$n$大きいですが$k$すぐに飛び越える$n$、 例えば$n = 10^9$、最初のいくつかの値は大きく、その後急速に崩壊します。 ジャンプのルール$k = n // v + 1$一度それを保証します$v = 1$、次のジャンプは次の位置に着地します。$k = n + 1$、残りすべてに対する不必要な反復を防止します。$k$すべてゼロを生成する値。 

いつ$n$完全な正方形であるか、繰り返しの約数があり、複数の$k$間隔は同じ商サイズの遷移にマップされます。 このアルゴリズムは、$n$の単調構造のみ$\lfloor n/k \rfloor$。
