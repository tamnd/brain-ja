 ## 解決策

 ## 問題の理解

 文字列のコレクションが与えられます。各文字列はパスワードを表します。 システムは、これらのパスワードを完全に独立したものとして扱いません。 代わりに、パスワード間の「等価性」の概念を定義します。つまり、2 つのパスワードが少なくとも 1 つの共通の文字を共有する場合、または隣接する各ペアが 1 つの文字を共有する他のパスワードのチェーンを通じて接続できる場合、2 つのパスワードは同等です。 

これにより、問題は当然接続性に関する推論に変わります。 各パスワードは、グラフ内のノードとして考えることができます。 対応する文字列が少なくとも 1 つの文字を共有する場合、2 つのノード間にエッジが存在します。 したがって、等価性とは、2 つのノードがこのグラフの同じ接続コンポーネント内にあるというステートメントとまったく同じです。 

実際に正しい管理者パスワードは 1 つのパスワードだけですが、どれが正しいかは不明です。 試行するパスワードのセットを選択した場合、それらはすべて同じアクセス結果につながるため、任意のパスワードを試行すると、その等価クラス内のすべてのパスワードが自動的にカバーされます。 このタスクは、どの接続コンポーネントに管理者パスワードが含まれているかに関係なく、選択したパスワードの少なくとも 1 つがそのコンポーネント内に存在するように、最小数のパスワードを選択することです。 

より具体的に言い換えると、文字を共有するパスワードをリンクすることによって形成されるすべての接続コンポーネントから少なくとも 1 つの代表者を選択する必要があります。 

制約は大きく、文字列数は最大 200,000、全長は最大 1,000,000 です。 これにより、ペアごとの比較アプローチが即座に除外されます。 すべての文字列のペアをチェックする単純なグラフ構築では、パスワードの数が 2 次になり、非常に遅すぎます。 すべての文字列を相互に比較するだけでも制限時間を超えてしまいます。 

アルファベットは小文字 26 文字のみですが、これが構造上の重要な制限です。 各パスワードは、これら 26 個の可能な「ポート」を介してのみ接続できます。これは、文字または文字によって引き起こされる接続コンポーネントの結合構造を強く示唆しています。 

重複が存在する場合、微妙な特殊なケースが発生します。 同一の文字列は自明に等価ですが、別個のコンポーネントとして扱うべきではありません。 もう 1 つのエッジ ケースは、パスワードに複数の異なる文字が含まれている場合です。これは、複数の文字グループを一度に接続し、別個のコンポーネントを結合する可能性があるためです。 

## アプローチ

 ブルートフォースアプローチでは、パスワード間のグラフを明示的に構築します。 文字列のすべてのペアを比較し、それらが文字を共有しているかどうかを確認します。 それらがあれば、それらを結合または接続します。 ペアをチェックするには、最大 50 文字の比較が必要です。$n^2$ペア、これはおおよそ次のようになります$10^{10}$最悪の場合の運用。 これは実現可能な限界をはるかに超えています。 

重要な点は、パスワード間の直接の比較が不要であるということです。 2 つのパスワードが関連付けられる唯一の理由は、共有文字の存在です。 これは、文字が接続性を完全に捉える中間表現として機能することを意味します。 

文字列間のエッジを考える代わりに、グラフ構造を反転します。 各文字をノードとして扱い、そこに含まれるすべての文字にパスワードを接続します。 この場合、2 つのパスワードは、それらの文字セットがこれらの文字ノードを通じて重複する場合に正確に等価になります。 これにより、26 文字にわたって素集合結合 (DSU) 構造を使用できるようになります。 

各パスワードは、そのすべての文字を 1 つの接続された構造に効果的に「結合」します。 すべてのパスワードを処理した後、文字はいくつかの接続されたコンポーネントを形成します。 コンポーネントの文字を少なくとも 1 つ含むパスワードは、そのコンポーネントに属します。 したがって、パスワードが関与する個別の文字コンポーネントの数は、接続されているパスワード グループの数に対応します。 

最後に、各グループには少なくとも 1 つの代表的なパスワードが必要であるため、答えは、少なくとも 1 つのパスワードに出現する文字によって引き起こされる個別の連結成分の数になります。

 ## アルゴリズムのチュートリアル

 当社では、小文字ごとに 1 つずつ、26 ノードにわたって DSU を維持しています。 

1. 各文字がそれ自体の親となる DSU を初期化します。 これは、最初は文字がつながっていないことを表します。 
2. 各パスワードについて、そのパスワードに含まれる一連の個別の文字を抽出します。 文字が繰り返されても接続性は変わらないため、文字列内の一意性のみを考慮します。 
3. 各パスワードについて、その最初の文字を参照として取得し、それを同じパスワード内の他のすべての文字と結合します。 この手順では、パスワード内のすべての文字が 1 つの接続コンポーネントにマージされ、このパスワードがそれらをリンクしていることが反映されます。 
4. すべてのパスワードに対してこれを繰り返し、接続が増えるにつれて徐々に文字グループをマージします。 
5. すべてのパスワードを処理した後、少なくとも 1 つのパスワードに含まれるすべての文字をスキャンし、各文字の代表的な親を収集します。 
6. それぞれの文字がパスワード間の等価性の関連要素を表すため、これらの文字の中の個別の代表の数が答えになります。 

### なぜ効果があるのか

 各パスワードは、そのすべての文字が単一の等価クラスに属することを強制します。 文字上の DSU は、これらの制約の推移的閉包を維持します。 2 つのパスワードが 1 つの文字を共有する場合、両方ともその文字をそれぞれのセットに結合し、DSU 構造内で文字セットが確実に交差するようにします。 この交差により、共有文字を介して接続されたすべてのパスワードが同じ DSU コンポーネントに組み込まれることが保証されます。 したがって、各 DSU コンポーネントはパスワードの 1 つの等価クラスに正確に対応し、コンポーネントごとに 1 つの代表を選択するだけで十分かつ最小限で済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.r[ra] < self.r[rb]:
            ra, rb = rb, ra
        self.p[rb] = ra
        if self.r[ra] == self.r[rb]:
            self.r[ra] += 1

def solve():
    n = int(input())
    dsu = DSU(26)

    used = set()

    for _ in range(n):
        s = input().strip()
        letters = list(set(s))

        for ch in letters:
            used.add(ord(ch) - 97)

        base = ord(letters[0]) - 97
        for ch in letters[1:]:
            dsu.union(base, ord(ch) - 97)

    comps = set()
    for c in used:
        comps.add(dsu.find(c))

    print(len(comps))

if __name__ == "__main__":
    solve()
```DSU は、固定アルファベット サイズ 26 に基づいて構築されています。各文字列はその文字間の結合に寄与し、共起するすべての文字が確実に接続されます。 の`used`未使用の文字は答えに寄与しないはずなので、set は入力に実際に出現する文字を追跡します。 

微妙な点は、結合演算の前に各文字列内の文字の重複を除去することです。 これがないと、文字を繰り返すと冗長結合が発生する可能性がありますが、正確性の問題は発生しません。 それでも、重複排除により推論が簡素化され、操作が最小限に抑えられます。 

最後に、使用されている文字についてのみ個別の DSU ルートをカウントすることで、実際のパスワードに関連するコンポーネントのみをカウントすることが保証されます。

            self.r = [0] * n
        def find(self, x):

                x = self.p[x]

 ## 特殊なケース

 すべてのパスワードが次のような同一の単一文字列である場合`"a", "a", "a"`、アルゴリズムはそれらを 1 つの文字コンポーネントとして正しく処理します。 DSU は単一ノードを超えて新しい構造を導入することはないため、結果は 1 のままです。 

パスワードが次のような連鎖を形成する場合`"ab", "bc", "cd"`、最初のマージ`a-b`、2番目のマージ`b-c`、そして 3 番目のマージ`c-d`。 DSU は、すべての文字が 1 つの代表に集約され、1 つの等価クラスが生成されることを保証します。 

パスワードがどの文字も共有していない場合:`"a", "b", "c"`、結合は実行されないため、各文字は独自のコンポーネントのままになります。 異なるルートを数えると 3 つになり、どのパスワード間にも同等性が存在しないという事実と一致します。
