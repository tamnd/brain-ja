 ## 解決策
 ## 問題の理解

 私たちは、成長する線に沿ってカーソルを左右に移動する操作と、現在のカーソル位置の文字を上書きする操作の 3 種類の操作をサポートするテキスト エディターを保守しています。 この線は概念的には右側に境界がなく、カーソルは常に最初のセルから開始して特定のセルを指します。 

すべての操作の後、現在の文字列全体を調べて、2 つのことを決定する必要があります。 まず、その中の括弧のシーケンスが有効な括弧構造を形成しているかどうかです。 有効性を考慮して、括弧以外の文字はすべて無視されます。 次に、それが有効な場合は、ネストされたペアが常に異なる色になるように、ブラケット ペアのカラー マッチングに必要な最小色の数を計算します。 

2 番目の要件は、ネストの各レベルで個別の色が強制されるため、正しいブラケット シーケンスの最大ネスト深さを計算することと同等です。 

主な困難は、最大 100 万回の一連の操作で更新が行われるたびに、これに答える必要があることです。 更新のたびに 1 つの文字が変更されたり、カーソルが移動したりする可能性があり、有効性と深さを最初から再計算するのは非常に遅すぎます。 

この制約は、すべての解が線形時間に近いか、最悪の場合でも非常に小さな定数で線形演算的でなければならないことを意味します。 クエリごとに文字列全体を再スキャンするようなことは、直ちに実行不可能になります。 

文字を上書きすると、微妙なエッジ ケースが発生します。位置が文字から括弧に、またはその逆に変更される可能性があります。 これは、シーケンスの有効性が単調ではないことを意味し、増分構造は括弧効果の挿入と削除の両方をサポートする必要があります。 

もう 1 つの注意が必要な状況は、文字列 ")(" や "(()))" など、一致しない閉じ括弧によりシーケンスが一時的に無効になる場合です。 このような場合、将来の構造に関係なく、すぐに -1 を出力する必要があります。 

最後に、カーソルの移動は有効性とは無関係です。 カーソルは初期化されていない位置に移動することができ、上書きは常に現在の位置にのみ影響します。 

## アプローチ

 直接的なアプローチは、文字列全体を維持し、各操作の後にそれをスキャンして括弧の正しさをチェックし、最大の深さを計算することです。 有効性をチェックするにはプレフィックス バランス スキャンが必要で、ネストの深さを計算するには最大プレフィックス合計を追跡する必要があります。 各クエリのコストは O(n) となり、最悪の場合、合計操作数は O(n^2) になります。これは、最大 10^6 の n の制限をはるかに超えています。 

重要な点は、各更新後に実際には完全な構造は必要ないということです。 ブラケット シーケンスに必要なグローバル プロパティは 2 つだけです。合計残高がマイナスになるかゼロで終わるかどうか、もう 1 つはすべての有効なプレフィックス間の最大プレフィックス バランスです。 ポイント更新と範囲クエリをサポートする構造にプレフィックス情報を保存すると、両方を動的に維持できます。 

これにより、「(」が +1 に寄与し、「)」が -1 に寄与し、他の文字が 0 に寄与する一連の値を維持するという問題が軽減されます。ポイントの更新をサポートし、範囲全体の合計と最小プレフィックス合計 (または同等の最小プレフィックス バランス) の 2 つのことをクエリする必要があります。 セグメント ツリーはこのための自然な構造であり、セグメントごとの合計と最小プレフィックス合計の両方を保存します。 

カーソル操作はどの位置が更新されるかのみに影響するため、各書き込みはセグメント ツリー内のポイントの更新に変換されます。 各演算の後、ルートをチェックします。合計がゼロでない場合、または最小プレフィックス合計が負の場合、シーケンスは無効です。 それ以外の場合、答えは最大プレフィックス合計であり、これも各ノードの集約情報の一部としてセグメント ツリーに保存できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | セグメントツリー | O(n log n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 エディタ行を配列としてモデル化し、各セルに寄与を格納します。 '(' の場合は +1、 ')' の場合は -1、その他すべての場合は 0 です。 

各ノードが 3 つの値 (セグメントの合計、セグメント内の最小プレフィックス合計、セグメント内の最大プレフィックス合計) を格納するセグメント ツリーを維持します。 これらにより、セグメントをスキャンせずにマージできます。 

### ステップ

 1. 最大 n のサイズの配列をすべて 0 で初期化し（または動的に拡張し）、その上に空のセグメント ツリーを構築します。 カーソルは位置 0 から始まります。 
2. コマンドごとに、カーソルを更新するか、現在のセルを変更します。 

文字を書くときに、それを数値効果に変換し、カーソル位置でセグメント ツリー内のポイント更新を実行します。 これが必要なのは、この位置のみが変更され、影響を受けるすべてのプレフィックス情報を効率的に更新したいためです。 
3. カーソル移動コマンドの場合は、可能であれば左に移動し、そうでない場合は右に移動します。 基礎となる文字列は変更されないため、構造の更新は必要ありません。 
4. 各コマンドの後で、セグメント ツリーのルートをクエリします。 ルートは現在の文字列全体を表します。 
5. ルートの総和がゼロでない場合、またはプレフィックスの最小和が負の場合、括弧の構造が無効であるため、-1 を出力します。 
6. それ以外の場合は、ルートに格納されている最大プレフィックス合計を出力します。 これは最大ネスト深さに相当し、まさに必要な最小色の数となります。 

### なぜ効果があるのか

 セグメント ツリーは、すべてのセグメントの正しい集計情報を維持します。 合計により、すべての開始括弧が終了括弧と一致することが保証されます。 最小プレフィックス合計により、バランスに違反するプレフィックスがないことが保証されます。つまり、その前に対応する開始括弧がなければ閉じ括弧は表示されません。 両方の条件が当てはまる場合、文字列は正しい括弧シーケンスです。 有効なプレフィックス間の最大のプレフィックス合計は、最も深いネスト レベル、つまり必要な色の最小数に等しくなります。 

すべての更新は 1 つの位置にのみ影響するため、各操作の後でもセグメント ツリーの一貫性が維持され、プレフィックスから導出されたすべての値の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.sum = [0] * (4 * n)
        self.pref = [0] * (4 * n)
        self.suff = [0] * (4 * n)
        self.mx = [0] * (4 * n)

    def merge(self, idx):
        l = idx * 2
        r = idx * 2 + 1

        self.sum[idx] = self.sum[l] + self.sum[r]

        self.pref[idx] = max(
            self.pref[l],
            self.sum[l] + self.pref[r]
        )

        self.suff[idx] = max(
            self.suff[r],
            self.sum[r] + self.suff[l]
        )

        self.mx[idx] = max(
            self.mx[l],
            self.mx[r],
            self.suff[l] + self.pref[r]
        )

    def update(self, idx, l, r, pos, val):
        if l == r:
            self.sum[idx] = val
            self.pref[idx] = max(0, val)
            self.suff[idx] = max(0, val)
            self.mx[idx] = max(0, val)
            return

        mid = (l + r) // 2
        if pos <= mid:
            self.update(idx * 2, l, mid, pos, val)
        else:
            self.update(idx * 2 + 1, mid + 1, r, pos, val)

        self.merge(idx)

def solve():
    n = int(input())
    s = input().strip()

    N = n + 5
    st = SegTree(N)

    arr = [0] * N
    cur = 0

    def apply(ch):
        if ch == '(':
            return 1
        if ch == ')':
            return -1
        return 0

    res = []

    for c in s:
        if c == 'L':
            cur = max(0, cur - 1)
        elif c == 'R':
            cur += 1
        else:
            v = apply(c)
            arr[cur] = v
            st.update(1, 0, N - 1, cur, v)

        total = st.sum[1]
        min_pref = 0
        bal = 0
        ok = True

        # reconstruct prefix validity from segment tree info:
        # we use mx/suff/pref structure: invalid if any prefix goes negative
        if total != 0:
            ok = False
        else:
            # check via stored prefix/suffix
            if st.pref[1] < 0 or st.suff[1] < 0:
                ok = False

        if not ok:
            res.append("-1")
        else:
            res.append(str(st.mx[1]))

    print(" ".join(res))

    solve()
```セグメント ツリーには各ノードの貢献度が保存されるため、O(log n) 個のノードのみが更新されます。 の`update`関数は単一の位置を上書きし、文字を +1、-1、または 0 に変換します。 

マージ関数は、合計だけでなく、ネストの深さを計算するために必要なプレフィックスとサフィックスの寄与も維持するように設計されています。 

毎回の手術後に根を検査します。 合計がゼロ以外の場合、シーケンスのバランスをとることはできません。 プレフィックス制約が負のプレフィックスを示している場合、それは無効です。 それ以外の場合、格納されている最大ネスト深さは、`mx[1]`が返されます。

 ## 特殊なケース

 重大なエッジケースは、閉じ括弧を文字で上書きすることです。 たとえば、「)」から始めて「a」に変更すると、即座に無効なプレフィックスが削除されます。 ポイント更新により値がゼロにリセットされ、すべての集計から負の寄与が削除されるため、セグメント ツリーがこれを処理します。 

もう 1 つの特殊なケースは、長いプレフィックス「(」の後に単一の「)」が続く場合です。 プレフィックスの合計はゼロになりますが、最大ネストの深さは、クロージャ前の最も深いオープン スタックを反映する必要があります。 保存されたプレフィックスとサフィックスの値により、バランスをとった後でも中間の深さが確実に保持されます。 

最後のケースは、カーソルが最初の領域を超えて移動することを繰り返すことです。 ツリーはゼロで初期化されるため、事前に割り当てられた境界を超える動的なサイズ変更ロジックを必要とせずに、新しい位置への書き込みは正しく動作します。
