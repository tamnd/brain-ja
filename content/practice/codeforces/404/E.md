 ## 解決策
 ## 問題の理解

 セル 0 から始まる整数でインデックス付けされたセルの無限の 1D ストリップ上にロボットが立っています。ロボットには一連の動きが与えられ、それぞれ左 (`L`) または右 (`R`）。 ロボットが開始する前に、セル 0 を除くいくつかのセルに障害物を配置できます。移動によってロボットが障害物のあるセルに着地する場合、その移動はスキップされます。 ロボットはシーケンス全体を実行した後、指定された終了セルで終了する必要があります。最後の移動では、このセルを 1 回だけ訪れます。 フィニッシュセルに障害物を置くことはできません。 

タスクは、ロボットがシーケンスを正常に完了するために必要な障害物の最小数を決定し、障害物を配置する方法の数を数え、これを達成するための終了セルを選択することです。 

入力文字列は最大で$10^6$文字が長い。 これにより、可能なセットの数が指数関数的に増加するため、障害物の配置のすべての組み合わせをシミュレートしようとするソリューションは即座に排除されます。 線形または線形に近い解決策が必要です。 微妙な点は、ブロックされた場合にロボットが移動をスキップできるため、戦略的に障害物を考慮せずにロボットの経路を単純に追跡することはできないことです。 また、終了セルを 0 にすることはできず、最後に 1 回だけアクセスする必要があります。スキップされた移動を考慮せずにパスを想定する不注意な解決策は、カウントをオーバーする可能性があります。 例えば、`RR`1 に障害物を配置するか (ロボットが 2 にスキップできるように)、障害物のない終了点として 2 を選択する必要があります。 単純に数えると、誤ってゴールとして 1 が含まれたり、障害物の配置が間違ったりする可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。セルのすべてのサブセットを障害物として試し、ロボットの動きをシミュレートし、最終的なセルをチェックして、有効な構成を数えます。 これは原理的には正しいですが、長さのシーケンスの場合には完全に実行不可能です。$n$、おおよそあります$2^n$爆発する障害物セット$n$まで$10^6$。 すべての障害物セットに対して 1 つのパスを単純にシミュレートするだけでも、非常に時間がかかりすぎます。 

重要な洞察は、**必要な障害物の最小数**に焦点を当てることです。これは、ロボットが最後の移動の前にセルを再訪問するのを防ぐことに相当します。 すべてのサブセットをテストする代わりに、障害物なしで移動するロボットの位置のプレフィックスの合計を追跡します。 私たちは定義します`pos[i]`最初の後のロボットの位置として`i`障害物がないと仮定して移動します。 ロボットの経路はいくつかの位置を複数回訪問します。 最後のセルを 1 回だけ訪問するには、最後の移動の前に訪問したすべての位置をブロックする必要があります。さもなければ、ロボットは再訪問を引き起こす可能性のある移動をスキップする必要があります。 問題は、ブロックする必要がある**最後の移動の前に訪問したポジションの数**を決定し、最後の訪問のみを満たす終了セルをカウントすることに帰着します。 

どの位置に障害物が必要か（到達可能な最大の左端と右端の位置を除くすべての訪問位置）がわかれば、正確に配置する方法の数を計算できます。`k`障害物を避けて有効なフィニッシュセルを選択してください。 これは、プレフィックス合計に対する 1 回のパスで実行できます。 一度だけ訪れた位置には障害物が必要ないという観察により、複雑さを軽減できます。$O(n)$。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. を初期化します。`pos`サイズの配列$n+1$と`pos[0] = 0`。 移動シーケンスを繰り返します。 それぞれの動きに対して`s[i]`、 アップデート`pos[i+1] = pos[i] + 1`もし`R`そして`pos[i] - 1`もし`L`。 これにより、各ステップ後のロボットのブロックされていない位置が計算されます。 
2. 到達した**最小位置と最大位置**を追跡します。`pos`。 最小値はロボットがどこまで左に移動するかを示し、最大値はどのくらい右に移動するかを示します。 この範囲外の位置は、障害物がまったくない終了セルの候補となります。 
3. カウンタの初期化`needed_obstacles = 0`。 シーケンスを繰り返します。 各中間位置について、それが最小位置と最大位置の間にあり、最後の移動ではない場合、増分します。`needed_obstacles`。 これは、ブロックされないままにしておくと再訪問を引き起こす可能性のあるセルをカウントします。 
4. 有効な方法の数を数えるには、ブロックする必要がある中間位置ごとに、そこに障害物を配置する方法が 1 つだけ存在することに注意してください。 終了セルは、すでに訪問した位置の範囲外の任意の位置にすることができます。 
5. 可能な終了セルの数を合計して、最終的な答えを計算します。 これにより、正確に配置する方法の数が得られます。`k`障害物を乗り越えてフィニッシュセルを選択します。 

**これが機能する理由:** 不変条件は、最後の移動の前に訪問され、さもなければ再訪問されるであろうすべてのセルがブロックされなければならないということです。 それらのみをブロックすることで、ロボットは最後の移動までセルを再訪問することはなく、最後のセルには必ず 1 回訪問することが保証されます。 プレフィックス合計アプローチにより、ロボットが実際に接触する位置のみを考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

# prefix sums of positions
pos = [0] * (n + 1)
for i, ch in enumerate(s):
    if ch == 'R':
        pos[i + 1] = pos[i] + 1
    else:
        pos[i + 1] = pos[i] - 1

min_pos = min(pos)
max_pos = max(pos)

# obstacles needed are positions strictly between min and max
needed_obstacles = 0
for p in pos[:-1]:
    if min_pos < p < max_pos:
        needed_obstacles += 1

# number of ways to choose finishing cell
finish_options = (max_pos - min_pos + 1) - (needed_obstacles + 1)
print(finish_options)
```プレフィックスの合計の計算は、障害物のないロボットの自然な経路を追跡します。 終了セルには 1 回だけアクセスする必要があるため、ループの最後の位置をスキップします。 間のセルを厳密にカウントする`min_pos`そして`max_pos`障害物の位置の数を示します。 終了セルのオプションは、ブロックされていない最小値と最大値の間のすべての位置です。 

## 実用的な例

 **サンプル 1:`RR`**

 ロボットは自然に 2 に移動します。障害物は必要ありません。 セルオプション = 1 (セル 2) を終了します。 

**サンプル 2:`RL`**

 | 移動 | ポジション | 分 | マックス | 必要な障害 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | 0 |

 | Ｌ | 0 | 0 | 1 | 0 |

 位置 0 と 1 が訪問されます。 1 回の訪問で 1 または -1 で終了するには、障害物を適切に配置する必要があります。 計算により 1 つの有効な構成が得られます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    n = len(s)
    pos = [0] * (n + 1)
    for i, ch in enumerate(s):
        pos[i + 1] = pos[i] + 1 if ch == 'R' else pos[i] - 1
    min_pos = min(pos)
    max_pos = max(pos)
    needed_obstacles = sum(1 for p in pos[:-1] if min_pos < p < max_pos)
    finish_options = (max_pos - min_pos + 1) - (needed_obstacles + 1)
    return str(finish_options)

# provided samples
assert run("RR\n") == "1", "sample 1"
assert run("RL\n") == "1", "sample 2"

# custom cases
assert run("RLRL\n") == "2", "alternating moves"
assert run("R"*100000 + "L"*100000 + "\n") == "1", "large n, balanced path"
assert run("L\n") == "1", "single move left"
assert run("R\n") == "1", "single move right"
