 ## 解決策
 ## 問題の理解

 奇数サイズの正方形の文字グリッドが与えられます。 各セルには英小文字が含まれています。 タスクは、文字が完全な「X」パターンを形成しているかどうかを確認することです。 「X」パターンには 2 つのプロパティがあります。2 つの対角線には同じ文字が含まれている必要があり、対角線の外側の他のすべてのセルには 1 つの異なる文字が含まれている必要があります。 

入力サイズが小さい場合:$3 \le n < 300$したがって、各セルを個別に検査する単純なアプローチでも実現可能です。 なぜなら$n$が常に奇数である場合、両方の対角線に属する一意の中央セルがあるため、二重にカウントしないように注意する必要があります。 

斜めの文字と非斜めの文字が偶然同じになった場合、微妙なエッジケースが発生します。 たとえば、3×3 グリッドの場合:```
aaa
aaa
aaa
```対角線のみをチェックする単純なアプローチでは、これが「X」であると誤って主張する可能性がありますが、対角文字と非対角文字が異なる必要があるという条件を満たしません。 同様に、アルゴリズムは最小の奇数サイズを処理する必要があります。$n = 3$そして最大の$n = 299$。 

## アプローチ

 最も単純な方法は総当たり法です。グリッド内のすべてのセルを反復処理します。 各セルについて、それが対角線上にあるかどうかを判断します。 一致する場合は、選択した斜線文字と一致することを確認してください。 そうでない場合は、非斜線文字と一致することを確認してください。 いずれかのチェックが失敗した場合は、すぐに「NO」を返します。 

これはグリッドが小さいため機能しますが、$n^2 < 90,000$最悪の場合、すべてのセルをチェックしても問題ありません。 より「洞察力に富んだ」観察は、前もって 2 つの文字を識別できるということです。左上隅は常に対角線上にあり、上中央 (または対角以外の) セルは非対角文字を示します。 この後は、グリッドを 1 回通過するだけで十分です。 これにより、ループ内の意思決定が軽減され、動的に文字を選択するためにネストされた条件が必要なくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 承認済み |
 | 最適化されたシングルパス | O(n²) | O(n²) | 承認済み |

 入力サイズが適度であるため、この問題にはどちらのアプローチも受け入れられます。 

## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$そして$n \times n$グリッド。 高速 I/O を使用して、大規模な場合の遅延を回避します$n$。 
2. 斜めの文字が左上のセルであることを確認します。 斜めになっていない文字が、最初の行の左上のセルのすぐ隣のセルであることを確認します。 これら 2 つの文字が同じ場合は、すぐに「NO」を出力します。 
3. 各セルを反復処理します。$(i, j)$グリッド内で。 
4. もし$i = j$または$i + j = n-1$、セルは対角線上にあります。 斜めの文字と一致するかどうかを確認します。 そうでない場合は、「NO」を出力して終了します。 
5. セルが対角線上にない場合は、対角線上にない文字と一致するかどうかを確認します。 そうでない場合は、「NO」を出力して終了します。 
6. すべてのチェックに合格した場合は、「YES」と出力します。 

機能する理由: このアルゴリズムは、2 つの対角線が均一であること、および他のすべてのセルが異なる文字で均一であることを保証します。 逸脱は直ちに検出されます。 対角線はインデックスによって一意に定義されるため、対角線と非対角線の区別は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [input().strip() for _ in range(n)]

diag_char = grid[0][0]
off_diag_char = grid[0][1]

if diag_char == off_diag_char:
    print("NO")
    sys.exit()

for i in range(n):
    for j in range(n):
        if i == j or i + j == n - 1:
            if grid[i][j] != diag_char:
                print("NO")
                sys.exit()
        else:
            if grid[i][j] != off_diag_char:
                print("NO")
                sys.exit()

print("YES")
```最初の 2 行は入力を効率的に読み取ります。 すぐに 2 つの重要な文字を選択し、それらが同一であるエッジケースをチェックします。 ネストされたループは、インデックス演算を使用して各セルを 1 回だけ調べて、セルを対角かどうかを分類します。 チェックの順序により、最初の違反で確実に終了するため、シンプルかつ効率的です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        n = int(input())
        grid = [input().strip() for _ in range(n)]

        diag_char = grid[0][0]
        off_diag_char = grid[0][1]

        if diag_char == off_diag_char:
            print("NO")
            return out.getvalue().strip()

        for i in range(n):
            for j in range(n):
                if i == j or i + j == n - 1:
                    if grid[i][j] != diag_char:
                        print("NO")
                        return out.getvalue().strip()
                else:
                    if grid[i][j] != off_diag_char:
                        print("NO")
                        return out.getvalue().strip()

        print("YES")
    return out.getvalue().strip()

# provided sample
assert run("5\nxooox\noxoxo\nsoxoo\noxoxo\nxooox\n") == "NO", "sample 1"

# minimal case, valid X
assert run("3\naxa\nxax\naxa\n") == "YES", "3x3 valid"

# minimal case, invalid X (all same)
assert run("3\naaa\naaa\naaa\n") == "NO", "3x3 all same"

# 5x5 valid X
assert run("5\naxaxa\nxaxax\naxaxa\nxaxax\naxaxa\n") == "YES", "5x5 valid"

# off-diagonal same as diagonal
assert run("3\naaa\aba\aaa\n") == "NO", "3x3 diagonal/off-diagonal clash"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3x3 最小有効 X | はい | 小さな X を正しく識別する |
 | 3x3 はすべて同じ | いいえ | 対角/非対角の等価性を検出 |
 | 5x5 有効 | はい | より大きなグリッドが機能する |
 | 3x3 クラッシュ | いいえ | 斜めでない文字は斜めと同じで失敗を引き起こします。 

## 特殊なケース

 のために$n=3$すべて同じ文字で:```
aaa
aaa
aaa
```アルゴリズムセット`diag_char='a'`そして`off_diag_char='a'`。 等しいことが検出され、「NO」が出力されます。 

最大の場合$n=299$、アルゴリズムは引き続き実行されます$299^2$= 89,401 回の反復 (10^8 を大きく下回っており、速度と正確性の両方が保証されています)。 

インデックス条件が同じであるため、中央の対角線上のセルは正しくオーバーラップします。`(i == j or i + j == n-1)`中央のセルを自然に処理できるため、二重カウントは発生しません。 

このアプローチは、特別なケースを使用せずにすべての微妙な条件を捉え、ソリューションを簡潔かつ信頼性の高いものに保ちます。
