 ## 解決策
 ## 問題の理解

 ヴァレラは四角いスタジアムの周囲を走り回ります。 正方形には辺の長さがあります`a`、ルートは反時計回りの順序で境界に従います。 

開始点は左下隅です`(0, 0)`。 走った後`a`彼が届くメートル`(a, 0)`、次々と`a`彼が届くメートル`(a, a)`、 等々。 周囲の合計は`4a`、つまり、1 周するたびに彼は次の状態に戻ります。`(0, 0)`そして同じ道を繰り返し続ける。 

コーチは毎日ヴァレラに飲み物を与える`d`メートル。 ヴァレラが走った後、ヴァレラの座標を出力する必要があります。`d`、`2d`、`3d`、...、`nd`メートル。 

重要な観察は、現在のラップに沿った位置のみが重要であるということです。 ヴァレラが総距離を走った場合`s`、その後、彼の位置は次のように決定されます。`s mod (4a)`なぜなら、すべての完全な境界が彼をまったく同じ場所に戻すからです。 

制約が十分大きいため、最大で次の値を生成する必要があります。`10^5`と答える。 メートル単位で動きをシミュレートするようなソリューションは不可能です。 距離が実数で表される場合でも、極小ステップのシミュレーションでは、最悪の場合、数十億回の操作が必要になります。 それぞれの答えを一定時間で計算する直接的な式が必要です。 

いくつかの特殊なケースでは、誤った答えが簡単に発生する可能性があります。 

考慮する：```
a = 2
d = 2
n = 1
```正確に実行した後`2`メートル、ヴァレラはここにいます`(2, 0)`、最初のコーナー。 厳密な不等式を使用した不用意な実装では、代わりに次の境界線に置かれる可能性があります。 

別の例:```
a = 3
d = 12
n = 1
```以来`12 = 4a`、彼はちょうど 1 周を完了し、に戻ります。`(0, 0)`。 モジュロを取るのを忘れた場合`4a`、境界を越えて彼を誤って見つけようとする可能性があります。 

より微妙なケースは次のとおりです。```
a = 2
d = 5
n = 1
```外周は`8`、 それで`5 mod 8 = 5`。 距離`5`上端にあります。 正しい位置は、`(1, 2)`。 1 つのラップのみを想定したり、エッジ遷移を誤って計算したりするソリューションは、ここで失敗します。 

## アプローチ

 最も直接的なアイデアは、実行をシミュレートすることです。 すべてのドリンクイベントを開始できるのは、`(0,0)`必要な距離をカバーするまで、エッジに沿って繰り返し移動します。 これはパスを正確にたどるので、これは正しいです。 

問題は規模だ。 距離は次のように大きくすることができます`10^5`、まであります`10^5`クエリ。 動きを段階的にシミュレートするには、非常に多くの操作が必要になります。 辺の長さを繰り返し減算して各クエリを処理することさえ不要な作業です。 

パスの構造により、はるかに単純な解決策が得られます。 スタジアムの境界は長さのサイクルです`4a`。 1周するごとにランナーは同じ位置に戻ります。 のために`i`- 杯目、総移動距離は$$s=i\cdot d$$のみ$$r=s\bmod (4a)$$重要です。 

これで、周囲が 4 つの長さのセグメントに分割されました。`a`。 

もし`r`は最初のセグメントに属し、Valera は下端にあります。 

もし`r`彼は 2 番目のセグメントに属しており、右端にいます。 

もし`r`3番目のセグメントに属しており、彼はトップエッジにいます。 

もし`r`4 番目のセグメントに属し、彼は左端にいます。 

それぞれのケースでは、単純な式を通じて座標が得られます。 すべてのクエリは一定時間内に独立して処理されるため、ソリューション全体が 1 回で実行されます。`O(n)`。

 ## アルゴリズムのチュートリアル

 1. 周囲の長さを計算します`p = 4 * a`。 
2. 飲み物を飲むたびに総走行距離を維持してください。 再計算する代わりに`i * d`、現在の値を保持できます。`cur = (cur + d) mod p`。 

その後`i`- 回目の反復、`cur`等しい`(i*d) mod p`。 
3. 正方形のどちら側かを決定します`cur`嘘。 

もし`0 <= cur <= a`、ランナーは下端にあります。 

もし`a < cur <= 2a`、ランナーは右端にいます。 

もし`2a < cur <= 3a`、ランナーは上端にあります。 

それ以外の場合、彼は左端にいます。 
4. そのエッジに沿った距離を座標に変換します。 

下端の場合:$$(x,y)=(cur,0)$$右端の場合:$$(x,y)=(a,cur-a)$$上端の場合:$$(x,y)=(a-(cur-2a),a)$$左端の場合:$$(x,y)=(0,a-(cur-3a))$$5. 座標を出力します。 

### なぜ効果があるのか

 いかなる瞬間においても、ランナーの位置は現在のラップでどれだけ進んだかによってのみ決まります。 モジュロを取る`4a`周上の正確な位置を維持しながら、完了したラップをすべて削除します。 

の区間分解`[0,4a)`正方形の 4 つの辺と一致します。 各間隔内では、単一の直線エッジに沿って単位速度で移動が発生するため、座標式は、周囲に沿った開始点からの距離が次の値に等しい固有の点を表します。`cur`。 可能なすべての値なので、`cur`正確に 1 つのエッジに属している場合、アルゴリズムは常に正しい位置を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, d = map(float, input().split())
n = int(input())

perimeter = 4.0 * a
cur = 0.0

out = []

for _ in range(n):
    cur = (cur + d) % perimeter

    if cur <= a:
        x = cur
        y = 0.0
    elif cur <= 2.0 * a:
        x = a
        y = cur - a
    elif cur <= 3.0 * a:
        x = 3.0 * a - cur
        y = a
    else:
        x = 0.0
        y = 4.0 * a - cur

    out.append(f"{x:.10f} {y:.10f}")

sys.stdout.write("\n".join(out))
```最初の部分では、正方形の辺の長さとドリンクの間隔を読み取ります。 境界線はクエリごとに再利用されるため、一度計算されます。 

変数`cur`完了したラップを削除した後、周囲に沿った現在の距離を保存します。 で更新します```
cur = (cur + d) % perimeter
```繰り返しの計算を避ける`i * d`値を数値的に小さく保ちます。 

4 つの条件分岐は、正方形の 4 つの辺に直接対応します。 式は、ランナーが現在のエッジに沿ってどれだけ進んだかから導出されます。 

微妙な点の 1 つは、コーナー位置の処理です。 使用する`<=`と正確に等しい距離を保ちます`a`、`2a`、 または`3a`明確に定義された単一の側面にあります。 どちらの隣接する側が選択されたかに関係なく、座標は同一であるため、曖昧さが回避されます。 

出力音量は大きく、最大`10^5`線。 回答をリストに集めて 1 回印刷するほうが、1 行ずつ書くよりもはるかに高速です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    a, d = map(float, input().split())
    n = int(input())

    perimeter = 4.0 * a
    cur = 0.0

    out = []

    for _ in range(n):
        cur = (cur + d) % perimeter

        if cur <= a:
            x, y = cur, 0.0
        elif cur <= 2.0 * a:
            x, y = a, cur - a
        elif cur <= 3.0 * a:
            x, y = 3.0 * a - cur, a
        else:
            x, y = 0.0, 4.0 * a - cur

        out.append(f"{x:.10f} {y:.10f}")

    return "\n".join(out)

# provided sample
assert run("2 5\n2\n") == (
    "1.0000000000 2.0000000000\n"
    "2.0000000000 0.0000000000"
)

# minimum-size input

# exactly one full lap

 ## 特殊なケース

 ### コーナーに正確に着地する

 入力:```
2 2
1
```外周の位置は、`2`、辺の長さに等しい。 アルゴリズムは最初の分岐に入ります (`cur <= a`) と出力:```
2.0000000000 0.0000000000
```ここが正しいコーナーです。 隣接するエッジを解釈すると同じ座標が生成されるため、結果は明確になります。 

### 全周に等しい距離

 入力:```
3 12
1
```外周は`12`。 

アルゴリズムは以下を計算します。```
cur = 12 mod 12 = 0
```以来`cur = 0`、座標は次のようになります。```
0.0000000000 0.0000000000
```ランナーは 1 周を完了し、スタート地点に戻りました。 

### 何周にもわたる長い距離

 入力:```
2 21
1
```外周は`8`。 

アルゴリズムは以下を計算します。```
cur = 21 mod 8 = 5
```以来`5`間にあります`4`そして`6`、ランナーは上端にあります。 

座標:```
x = 6 - 5 = 1
y = 2
```出力：```
1.0000000000 2.0000000000
```残りだけが重要です。 周回完了までの 20 メートルは最終的な順位には影響しません。
