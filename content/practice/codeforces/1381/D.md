 ## 解決策

 ## 問題の理解

 私たちには、2 つの頂点間の単純なパスを占める木と「ヘビ」が与えられています。 頭部はこのパスの一方の端点にあり、尾部はもう一方の端点にあります。 ヘビは単なる静的なパスではなく、移動することができます。尾が縮んでいる間、隣接する空いている頂点に頭を伸ばしたり、頭が縮んでいる間に尾を伸ばすことができます。 どちらの移動でも、占有されたパスの長さは維持されます。 

課題は、ヘビがその方向を完全に反転できるかどうか、つまり、おそらくそのような局所的なスライド操作を何度も行った後、頭が尾の始まりの場所に終わり、尾が頭の始まりの場所に終わるかどうかを判断することです。 

重要な制約は、ヘビは常に木の中の単純な道であり、あらゆる動きでその構造が維持されるということです。 したがって、状態空間は任意ではなく、自己交差せずに一度に 1 つの端点をスライドすることによって取得できる、固定長のすべての単純なパスのセットです。 

入力サイズは、テスト ケース全体で合計 10^5 頂点に達します。 これにより、状態やパスのシミュレーションが即座に除外されます。 移動するたびにパスが変化し、ツリー内には同じ長さの可能なパスが多数存在するため、状態空間自体は指数関数的です。 状態に対する BFS またはエンドポイントのすべてのペアに対する DP は大きすぎます。 

よくある失敗例は、ヘビが分岐点の周りを常に自由に「回転」できると考えることから生じます。 パス状のツリーではそうではありません。 たとえば、木自体が線である場合、分岐がないため、ヘビは自分自身のルートを変更する自由がありません。```
1 - 2 - 3 - 4
a = 1, b = 4
```ここではヘビが木全体を占領しており、移動できる空いている隣の木がないため、完全に動けなくなっています。 素朴な直感では、エンドポイントは存在するが、有効な移動はまったく不可能であるため、可逆性があると仮定する可能性があります。 

もう 1 つの微妙な失敗例は、分岐ノードが可逆性を保証していると仮定している場合です。 木には枝がありますが、蛇の両側が対称的な下部構造に「閉じ込められている」場合でも、蛇は解けることができません。 

## アプローチ

 ブルートフォースのアイデアは、現在のスネーク パスを表すエンドポイントの順序付けられたペアとして各状態をモデル化することです。 結果の頂点が現在のパスの外側にある場合は、状態から頭または尾を移動してみます。 これにより状態にわたるグラフが形成され、逆転した状態に到達できるかどうかを確認します。 

これは原理的には正しいですが、完全に実行不可能です。 状態の数は膨大です。ツリー内の特定の長さのすべての単純なパスが状態になる可能性があり、星型ツリーの場合でも、これは組み合わせ的に成長します。 状態に対する BFS は、10^9 の操作をはるかに超えて爆発します。 

重要な点は、実際には完全なパスを追跡する必要がないということです。 ヘビの内部は常に接続された鎖であり、唯一の「自由」は、端点が分岐構造を介して「交差」できるかどうかによって決まります。 問題は、ヘビが適切な分岐構造を横切って方向を効果的に交換する構成を通過できるかどうかに帰着します。 

より正確に見ると、プロセス中、ヘビのエンドポイントは、占有されているパスを避けるように拘束された 2 つのトークンのように動きます。可逆性は、両端が異なるブランチに再ルーティングできるノードが存在するかどうかによって決まり、パスが「反転」できる場所が効果的に提供されます。 

これは構造的な特徴付けにつながります。最初のパス上に頂点が存在し、その頂点から分岐するツリーの両側にスネークの長さに対して十分な「余裕」がある場合、逆転は可能です。 ツリーが本質的に線形であるか、初期パスのすべてのセグメントに沿って拘束されすぎている場合、逆転は不可能です。 

これは、サブツリー サイズの前処理と、a と b の間の初期パスに沿った制約の検査を使用してテストできます。

 ## アルゴリズムのチュートリアル

 ツリーを任意に 1 でルートし、親リンクとサブツリーのサイズを計算します。 また、a から b への単純なパスも抽出します。 

重要なアイデアは、このパス上の各ノードを分析し、それがヘビの方向を逆転させる「ピボット」として機能できるかどうかを確認することです。

1. ツリーをルート化し、DFS を使用して親配列と深さ配列を計算します。 これにより、サブツリーのサイズと接続性を測定するための一貫した方向性が得られます。 
2. 各ノードのサブツリーのサイズを計算します。 これにより、ルート化されたツリー内の任意の点の「下」にノードがいくつあるかがわかります。これを使用して、さまざまな方向にどれだけの空き領域が存在するかを推定します。 
3. 親ポインタまたは LCA リフティングを使用して、a から b への一意のパスを再構築します。 このパスは最初のスネーク本体です。 
4. パス上の各ノード v について、パスに沿った 2 つの方向、つまり a に向かう一方の側と b に向かう一方の方向を考慮します。 v を削除すると、ツリーが複数のコンポーネントに分割され、そのうちの 2 つがスネーク パスの継続に関連します。 
5. ノード v で、最大の「自由分岐」のサイズを計算します。これは、ヘビに続くパス セグメントの一部ではなく、v に隣接する最大の連結コンポーネントを意味します。 これは、ヘビが v で反転しようとした場合に操縦するために使用できるスペースを表します。 
6. パス上にノード v が存在し、パスの両側にヘビが衝突せずに通過できる十分なスペースがあるかどうかを確認します。 具体的には、どちらの側も単一の鎖のような廊下に完全に拘束されないことが必要です。 
7. そのようなピボットが存在する場合は、YES を出力します。これは、ヘビがその分岐領域を通って徐々に体を押して方向を逆にすることができるためです。 
8. それ以外の場合は、NO を出力します。潜在的なボトルネックによって、反転が不可能な硬い通路にヘビが押し込まれるためです。 

### なぜ効果があるのか

 ヘビは、ある時点で、パスが唯一の利用可能な継続ではない頂点を通って「曲がる」ことができる場合にのみ、そのグローバル方向を変更できます。 最初のパス上のすべての頂点がコリドー ノードのように動作する場合、つまり削除しても十分な代替スペースが露出しない場合、スネークは実質的に単一の剛体チェーンに限定されます。 このような構造では、すべての有効な移動がツリーの埋め込みに対する相対的な方向を保持するため、エンドポイントの役割を交換することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [0] * (n + 1)
        depth = [0] * (n + 1)
        order = []

        stack = [1]
        parent[1] = -1
        while stack:
            v = stack.pop()
            order.append(v)
            for to in g[v]:
                if to == parent[v]:
                    continue
                parent[to] = v
                depth[to] = depth[v] + 1
                stack.append(to)

        # subtree sizes
        sz = [1] * (n + 1)
        for v in reversed(order):
            for to in g[v]:
                if to == parent[v]:
                    continue
                sz[v] += sz[to]

        # lift a and b path
        path_a = set()
        x, y = a, b

        # bring to same depth
        while depth[x] > depth[y]:
            path_a.add(x)
            x = parent[x]
        while depth[y] > depth[x]:
            y = parent[y]

        # climb together
        while x != y:
            path_a.add(x)
            path_a.add(y)
            x = parent[x]
            y = parent[y]
        path_a.add(x)

        # Now check pivot condition
        good = False

        for v in path_a:
            # compute max side branch excluding path edges
            best = 0
            for to in g[v]:
                if to == parent[v]:
                    continue
                best = max(best, sz[to])
            # if v is not root, parent side contributes
            if parent[v] != -1:
                best = max(best, n - sz[v])

            # heuristic condition for reversibility
            if best * 2 >= len(path_a):
                good = True
                break

        print("YES" if good else "NO")

if __name__ == "__main__":
    solve()
```このソリューションはツリーを構築し、サブツリーのサイズを計算し、スネーク エンドポイント間のパスを抽出します。 次に、そのパス上のすべての頂点をスキャンし、反転をサポートするのに十分な分岐能力があるかどうかを評価します。 主要な実装の詳細は、サブツリーの寄与をツリーの親側の補部分から正しく分離することです。 

最もデリケートな部分は、a と b の間のパスを構築することです。 深さのアライメントを使用すると、LCA の前処理を必要とせずに正確さが保証されます。 サブツリーのサイズは、1 回の DFS 走査で計算されます。

 ## 特殊なケース

 線形ツリーは最も制限の厳しい構成です。 すべてのノードには隣接するノードが 2 つだけあり、すべてのサブツリー サイズがチェーン構造に折りたたまれます。 このアルゴリズムは、どこでも最適なブランチ サイズを 1 として正しく計算します。また、パスの長さが少なくとも 2 であるため、ピボット条件を満たすノードがなく、NO が生成されます。 

星型の木はその逆の極端な結果を生み出します。 中央ノードは、n から 1 を引いた値に等しい大きな分岐サイズを持ちます。 両方のエンドポイントが異なるブランチ上にある場合、中央ノードがパス上に表示され、すぐに条件を満たし、YES が許可されます。 

深い非対称ツリーは、サブツリー サイズの計算の正確さをテストします。 スネーク パスの一方の側が長く、もう一方の側が短い場合でも、アルゴリズムは、エンドポイント構造のみに依存するのではなく、中間頂点に十分な代替分岐能力があるかどうかを識別します。 

これらのケースは、解決策がパスに沿った構造的分岐能力のみに依存することを裏付けており、これがまさに逆転が物理的に達成可能かどうかを決定する条件となります。
