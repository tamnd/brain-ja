 ## 問題の理解

 2 つのバイナリ文字列が与えられています。`a`そして`b`、同じ長さの`n`。 課題は変革することです`a`の中へ`b`一連のプレフィックス反転操作を使用します。 長さのプレフィックス反転`k`最初のものを逆にする`k`の登場人物`a`そして同時にそのプレフィックス内のすべてのビットを反転します。 出力には、これを実現する一連のプレフィックス長がリストされている必要があり、操作の数は次の値を超えてはなりません。`2n`。 

制約が示すのは、`n`まで到達できます`10^5`テストケースごと、すべての合計`n`テストケース全体にわたって`10^5`。 これは、ソリューションが次の点で線形である必要があることを意味します。`n`テストケースごとに。 考えられるすべてのプレフィックス反転を素朴な方法でシミュレートする二次アルゴリズムでは、あまりにも遅すぎます。 

文字列がすでに同一である場合、微妙な特殊なケースが発生します。 このシナリオでは、最適なシーケンスは空です。 サイズの接頭辞を常に反転する不注意なアプローチ`n`まず不必要な操作を実行する可能性があります。 最初と最後のビットが異なる場合、別の厄介な状況が発生します。 間違ったプレフィックスを選択すると、必要以上の操作が強制される可能性があります。 

小さな例でこれらの点を説明します。 もし`a = "01"`そして`b = "10"`、単純なアプローチでは、最初に文字列全体を反転して、`"10"`、偶然にも 1 回の操作で問題が解決されますが、操作の順序によっては、正確性を確保するために中間状態を慎重に処理する必要がある場合があります。 

## アプローチ

 ブルートフォースアプローチでは、直接一致を試みます。`a`に`b`不一致が発生するたびに左から右にスキャンしてプレフィックスを反転します。 それぞれの不一致について、プレフィックスを反転して最初の誤ったビットを修正することもできますが、各反転のシミュレーションには O(n) 回かかるため、最悪の場合でも O(n^2) 回の操作が必要になります。 これは原理的には正しいですが、各フリップを明示的にシミュレートすると遅すぎます。`n = 10^5`。 

重要な洞察は、逆向きに推論することです。 私たちは、各ビットの最終的な構成のみを考慮します。`a`マッチング`b`。 最後のビットから最初のビットまで作業することで、実際にすべてのステップをシミュレートすることなく、どのプレフィックス反転が必要であるかを決定できます。 ポジションごとに`i`から`n-1`まで`0`、 もし`a[i]`(以前の反転をすべて適用した後) が一致しません`b[i]`、長さのプレフィックス全体を反転できます`i+1`。 その時点の最初のビットも一致しない場合は、最初に長さ 1 のプレフィックスを反転して、効果的に反転してから、より大きなプレフィックスを反転します。 

このアプローチでは、文字列全体の反転を毎回シミュレートする必要がなくなります。 代わりに、文字列の現在の論理「先頭」と「末尾」を表す 2 つのポインターと、現在のセグメントが反転されているかどうかを判断する反転状態を維持します。 各操作は O(1) となり、文字列ごとに最大 2n 回の操作が実行され、問題の制約が満たされます。

 ## アルゴリズムのチュートリアル

 1. ポインタの初期化`l = 0`そして`r = n-1`現在のセグメントを追跡するには`a`検討中です。 維持する`flip`セグメントが論理的に反転されているかどうかを追跡するフラグ。 
2. 最後の文字から最初の文字まで繰り返します (インデックス`i = n-1`まで`0`）。 各ステップで、以下を考慮して現在の「テール」での有効ビットを決定します。`flip`州。 
3. 現在の有効ビットが一致する場合`b[i]`、何もせずにポインタを内側に移動します。 一致しない場合は、最初のビット (現在の「ヘッド」) のみを反転すると、一致するかどうかを確認します。`b[i]`。 そうであれば、長さ 1 のフリップを操作リストに追加します。 
4. 長さの反転を追加する`i+1`最後のビットを揃えるには`b[i]`。 スワップ`l`そして`r`そして反転させます`flip`プレフィックスの反転によって引き起こされる反転と反転を説明するためのフラグ。 
5. すべての位置が処理されるまで続行します。 結果として得られる操作のリスト (最大 2n) は次のように変換されます。`a`の中へ`b`。 

機能する理由: 各操作により、既に修正されたビットを妨げることなく、右端の未処理のビットが確実に修正されます。 不変条件は、現在のポインタの右側のすべてのビットが一致することです。`b`、セグメント ポインタとフリップ フラグにより​​、論理状態が正確に追跡されます。`a`。 プレフィックスを逆の順序で反転すると、修正されたビットが誤って変更されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(input().strip())
        b = list(input().strip())
        ops = []

        l, r = 0, n - 1
        flip = 0

        for i in reversed(range(n)):
            current = a[l] if flip == 0 else ('1' if a[l] == '0' else '0')
            if (r-l)%2 == 1:
                current = a[r] if flip == 0 else ('1' if a[r] == '0' else '0')

            if current != b[i]:
                first_bit = a[l] if flip == 0 else ('1' if a[l] == '0' else '0')
                if first_bit != b[i]:
                    ops.append(1)
                ops.append(i+1)
                flip ^= 1
                l, r = r, l

            if l < r:
                r -= 1
            else:
                l += 1

        print(len(ops), *ops)

if __name__ == "__main__":
    solve()
```このソリューションは入力を読み取り、各テスト ケースを処理し、現在の先頭と末尾への論理ポインターを維持します。 の`flip`flag を使用すると、コストがかかる配列の物理的な反転や反転を回避できます。 最初のビットのチェックにより、完全なプレフィックス フリップの前に最初のビットを位置合わせする必要があるケースが、長さ 1 の追加のフリップによって確実に修正されます。
