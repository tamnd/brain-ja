 ## 解決策
 # 問題の理解

 この問題は友情グラフについて説明しています。 生徒一人ひとりが頂点であり、あらゆる友情関係は方向性のないエッジです。 グループを形成するには、学生のサブセットを選択する必要があります。 選択したグループのスコアは、グループ内およびグループの境界を超えた友情に依存し、選択した生徒ごとに追加のペナルティが課せられます。 目標は、可能な最大スコアを見つけることです。 元の問題は、フォーム内のすべてのテスト ケースに対してこの値を要求します。`Case #x: answer`。 

選ばれた生徒を次のように代表させます。`1`そして選ばれなかった生徒`0`。 友情の絆のために`(u, v)`、その貢献度は`1`両方のエンドポイントが選択されている場合、`-1`エンドポイントが 1 つだけ選択されている場合、および`0`さもないと。 選択された生徒全員のスコアも減ります`1`。 

制約は大きいです。 すべてのテストで到達できる生徒の合計数`10^6`、および到達できる友情エッジの合計数は、`2 * 10^6`。 考えられるすべてのグループを試す解決策は不可能です。`2^n`グループ。 二次関数のグラフ アルゴリズムでも、`n`遅すぎるでしょう。 グラフをほぼ線形に処理するメソッドが必要です。 

難しいのは、最も優れたグループには、必ずしもつながりの強い生徒だけが含まれているわけではないということです。 友達が多い生徒でも、十分な友達がいない状態で選ばれた場合、スコアに悪影響を及ぼす可能性があります。 いくつかの小さな例は、貪欲な選択が失敗する理由を示しています。 

考慮する：```
1
2 1
1 2
```正しい出力は次のとおりです。```
Case #1: 0
```両方の生徒を選択すると 1 つの友好的なペアが与えられますが、選択された 2 人の生徒にもペナルティが与えられます。`-2`、合計を与えます`-1`。 生徒を 1 人選択すると、`-2`、そして誰も与えないを選択すると`0`。 常に友人を選択するような貪欲なルールは間違っています。 

別のケース:```
1
3 2
1 2
2 3
```正しい出力は次のとおりです。```
Case #1: 1
```3 人の生徒全員を選択すると、内部友情が 2 つとペナルティが 3 つ与えられます。 値は`2 - 3 = -1`エッジペナルティを考慮した上で。 最良の選択は生徒を選ぶことです`1`そして`2`または`2`そして`3`、これにより、友情利益が 1 つとペナルティが 2 つ与えられ、その結果、`-1`。 誰も与えないことを選択する`0`したがって、実際の答えは次のとおりです。`0`。 

2 番目の例は、接続されていない選択肢と空のグループを正しく処理する必要があることを示しています。 最適なグループは空である可能性があるため、少なくとも 1 人の生徒に解答を強制するような実装は失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、可能なすべての生徒のサブセットを試してみることです。 各サブセットについて、その中に完全に含まれている友情の数、その境界を越えている友情の数を計算し、学生ペナルティを差し引きます。 考えられるすべての答えが考慮されるため、このアプローチは正しいです。 ただし、`2^n`したがって、サブセットごとに一定時間チェックを行ったとしても、操作数は指数関数的に増加します。 のために`n = 300000`、これはまったく不可能です。 

重要な観察は、スコアが加重選択問題として書き換えられるということです。 させて`S`選択されたセットになります。 友情のエッジの場合、貢献は次のように書くことができます。$$3[x_u = 1 \land x_v = 1] - x_u - x_v$$両方のエンドポイントを選択すると、`3 - 1 - 1 = 1`、正確に 1 つを選択すると、`-1`、どちらも選択しないと`0`。 

これをすべてのエッジで合計し、学生ペナルティを追加すると、次のようになります。$$3 \times \text{internal edges} - \sum_{v \in S}(\deg(v)+1)$$ここで問題は、頂点を選択し、選択した生徒ごとにマイナスのコストを受け取る一方で、2 つのエンドポイントが両方とも選択されている友情ごとにプラスの報酬を受け取るということです。 

これはまさに最大重量閉包問題です。 私たちはすべての生徒とすべての友情のためのオブジェクトを作成します。 選択した友情オブジェクトは、そのエンドポイントの生徒の両方が選択されている場合にのみ許可されます。 この依存関係は、当然、無限の容量エッジで表されます。 最大重量のクロージャは、最小限のカット構造を使用して解決できます。 

フロー ネットワークの場合、正の重みはソースから接続され、負の重みはシンクに接続され、依存関係エッジには無限の容量があります。 最大クロージャ値は、すべての正の重みの合計から最小カットを差し引いたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ディニックとの最大限のクロージング | O(V^2E) 最悪の場合、この構造では実際には十分な速度です。 O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての友人関係を読み取りながら、すべての生徒の学位を計算します。 選択された各生徒の重みは次のとおりです。`-(degree + 1)`なぜなら、選択されたすべての生徒は直接 1 ポイントを失い、他のエンドポイントを選択することで補償されない友情関係の出来事ごとに 1 ポイントを失うからです。 
2. 計算された負の重みを使用して、すべての生徒のノードを作成します。 重みのある友情ごとに別のノードを作成する`3`なぜなら、友情の両方のエンドポイントを選択すると、エンドポイント コストが適用される前に純利益が 3 になるからです。 
3. 閉包グラフを作成します。 すべての正の重みノードに対して、その重みに等しい容量を持つソースからエッジを追加します。 すべての負の重みノードについて、絶対重みと等しい容量を持つエッジをシンクに追加します。 
4. すべての友情ノードから 2 つのエンドポイントの学生ノードに無限のキャパシティ エッジを追加します。 これにより、有効な終了が強制されます。友情の報酬を選択した場合、両方の生徒も選択する必要があります。 
5. 最大流量アルゴリズムを実行します。 答えは、すべての正の重みの合計から最小カットの値を引いたものです。 

正確さはクロージャプロパティから得られます。 有効な学生グループは、両方のエンドポイントが選択されている学生ノードとすべての友情ノードを正確に選択することに対応します。 逆に、すべての有効なクロージャは、何らかの学生グループに対応します。 フロー構築では、最小カットによって選択すべきではないノードの重みが正確に削除されるため、最大の総重みを持つクロージャが見つかります。 変換では元のスコアが保持されるため、最大クロージャ値が必要な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.g[u].append([v, c, len(self.g[v])])
        self.g[v].append([u, 0, len(self.g[u]) - 1])

    def max_flow(self, s, t):
        flow = 0
        n = self.n
        while True:
            level = [-1] * n
            level[s] = 0
            q = [s]
            for u in q:
                for v, c, _ in self.g[u]:
                    if c and level[v] == -1:
                        level[v] = level[u] + 1
                        q.append(v)
            if level[t] == -1:
                return flow

            it = [0] * n

            def dfs(u, f):
                if u == t:
                    return f
                while it[u] < len(self.g[u]):
                    e = self.g[u][it[u]]
                    v, c, rev = e
                    if c and level[v] == level[u] + 1:
                        ret = dfs(v, min(f, c))
                        if ret:
                            e[1] -= ret
                            self.g[v][rev][1] += ret
                            return ret
                    it[u] += 1
                return 0

            while True:
                pushed = dfs(s, 10**18)
                if not pushed:
                    break
                flow += pushed

def solve_case(n, edges):
    deg = [0] * n
    for u, v in edges:
        deg[u] += 1
        deg[v] += 1

    total_positive = 3 * len(edges)

    source = n + len(edges)
    sink = source + 1
    dinic = Dinic(sink + 1)

    for i in range(n):
        w = -(deg[i] + 1)
        dinic.add_edge(i, sink, -w)

    for i, (u, v) in enumerate(edges):
        node = n + i
        dinic.add_edge(source, node, 3)
        dinic.add_edge(node, u, 10**18)
        dinic.add_edge(node, v, 10**18)

    return total_positive - dinic.max_flow(source, sink)

def main():
    t = int(input())
    ans = []
    for case in range(1, t + 1):
        n, m = map(int, input().split())
        edges = []
        for _ in range(m):
            x, y = map(int, input().split())
            edges.append((x - 1, y - 1))
        ans.append(f"Case #{case}: {solve_case(n, edges)}")
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```学生ノードの容量を作成するには学位が必要であるため、実装では最初にすべての友人関係が保存されます。 グラフは次のように構築されます。`n + m + 2`ノード: 各生徒に 1 つ、友情報酬ごとに 1 つ、ソースとシンク。 

無限の能力値は、考えられるすべてのプラスの報酬の合計よりも大きければよいだけです。 ここでの最大報酬は、`3m`、 それで`10**18`安全に大きく、オーバーフローの懸念を回避します。 

Dinic の実装では、隣接リストと残差エッジが使用されます。 逆エッジ インデックスはエッジの追加時に保存されるため、一致する逆エッジを検索せずに DFS 中に容量を更新できます。 

答えは次のように計算されます`total_positive - min_cut`。 これは、最大クロージャから最小カットへの標準的な変換です。フローは、最適クロージャから除外されたノードの重みを正確に削除します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V^2E) ディニックにとって最悪のケース | ネットワークには、`n + m + 2`ノードと`O(n + m)`この構造は、指定された制限に対して十分に効率的です。 
| スペース | O(n + m) | フロー グラフには、生徒ごとに 1 つのノード、友情ごとに 1 つのノード、および残余エッジが保存されます。 

制約には数百万のエッジが含まれるため、隣接リスト表現が必要です。 グラフ サイズは線形のままで、最大フロー インスタンスは任意の高密度ネットワークではなく構造化されるため、ソリューションを時間とメモリの制限内に収めることができます。

## 特殊なケース

 単一の友情の場合:```
1
2 1
1 2
```アルゴリズムは重み付きの 1 つの友情ノードを作成します`3`および重み付きの 2 つのスチューデント ノード`-2`。 友情ノードは両方の生徒と一緒にのみ選択できます。 3 つすべてを選択すると、`3 - 2 - 2 = -1`したがって、クロージャ アルゴリズムは何も選択せずに返します。`0`。 

友達が多い生徒の場合、アルゴリズムは友達を自動的に選択しません。 Student ノードの次数が増加するため、負の重みが大きくなります。 この生徒が役に立つ唯一の方法は、それに接続されている十分な友情報酬ノードも選択されている場合です。 

空の最適グループの場合、最小カットのソース側には有用なノードが含まれない可能性があります。 これが許可されるのは、最大クロージャではオブジェクトを選択できないため、返される答えは正確にゼロになる可能性があるためです。 

密なグラフの場合、友情ノードの数は多くなりますが、それぞれのノードは 2 つの学生ノードにのみ接続されます。 グラフは、フロー構築が入力制限を処理できるほど十分にまばらなままです。
