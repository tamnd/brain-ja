 ## 解決策
 # 問題の理解

 ジュエリーは一連の宝石であり、各文字は 1 種類の宝石を表します。 選択した幅に対して`d`、文字列は左から右にいくつかの長さの完全な部分に切断されます。`d`。 不完全なサフィックスが存在する場合、それは破棄されます。 完成した部分は行列の行になり、行は任意の順序で並べ替えることができます。 タスクは、可能なすべての幅にわたって生成できる異なる行列の数を数えることです。 

1 つの固定幅の場合、元の部分の順序は重要ではなくなります。 行文字列のマルチセットのみが重要です。 あれば`m`行を選択すると、特定の行が表示されます`c`倍、異なる行配置の数は多項値になります。$$\frac{m!}{\prod c!}$$最終的な答えは、可能なすべての幅にわたるこの値の合計です。 

文字列の長さは次のとおりです`300000`、すべてのテスト ケースの合計の長さは次のようになります。`1000000`。 二次解法は、1 つのテスト ケースでも約`9 * 10^10`操作。 に近い解決策が必要です`O(n log n)`大規模なテストケースごとに。 調和系列の観察が鍵となります。各幅について考慮される完全なブロックの合計数は次のとおりです。$$\sum_{d=1}^{n}\left\lfloor\frac nd\right\rfloor = O(n\log n)$$したがって、各ブロックを幅ごとに 1 回処理することが可能です。 

よくある間違いは、等しい行を間違って扱うことです。 たとえば、入力文字列の場合`aaaa`、選択する`d = 1`4 つの同一の行を作成します。```
a
a
a
a
```この幅の答えは、`1`、 ない`4!`なぜなら、すべての行の順序が同じに見えるからです。 

もう 1 つの特殊なケースは、幅が文字列の長さの半分より大きい場合です。 のために`abcde`そして`d = 3`、完全な行は 1 つだけあります。```
abc
```その幅で可能な行列の数は正確に次のとおりです。`1`。 少なくとも 2 行が存在することを前提としたソリューションは、ここで失敗する可能性があります。 

3 番目のケースは、残ったサフィックスが無視される場合です。 のために`aab`そして`d = 2`、行は次のみです。```
aa
```最後`b`行は作成されません。 貢献度は、`1`、文字列の完全な長さに基づいたものではありません。 

## アプローチ

 直接的なアプローチは、あらゆる幅を試すことです`d`、文字列を行に分割し、各行が何回出現するかを数え、多項係数を計算します。 これは正しいです。分割後の唯一の自由は、等しい行と異なる行を並べ替えることだけだからです。 

問題は式ではありません。 問題は頻度表を構築することです。 すべての行のペアを文字列として比較すると、コストが大きくなりすぎる可能性があります。 近い幅の場合`1`、 がある`n`それらの行を文字ごとに比較すると、`O(n^2)`。 

有益な観察は、行は常に元の文字列の連続した部分であるということです。 構築する必要はありません。 部分文字列ハッシュを使用すると、一定時間内に行を識別できます。 幅ごとに`d`を検査します。`floor(n/d)`行を抽出し、そのハッシュを頻度マップに入力し、その頻度を使用して多項値を計算します。 

すべての幅にわたる行の合計数はわずかであるため、`O(n log n)`、これにより、一見高価な幅の列挙が実用的なソリューションに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗を最大で事前計算します。`n`。 幅の答えには次のような値が必要です`m!`そして`c!`したがって、これらのテーブルを使用すると、あらゆる多項計算を迅速に実行できます。 
2. 文字列のローリング ハッシュを構築します。 2 つの独立したハッシュ モジュールが使用されるため、2 つの異なる部分文字列が同じ識別子を受け取る可能性は非常に低くなります。 
3. 可能なすべての幅にわたって反復します。`d`から`1`に`n`。 
4. 完全な行の数を計算します。$$m = \left\lfloor\frac nd\right\rfloor$$もし`m`がゼロの場合、この幅は発生しませんが、指定された幅の範囲では決して発生しません。 

1. 行インデックスごとに`i`から`0`に`m-1`、で始まる部分文字列のハッシュを取得します。`i*d`長さのある`d`。 各ハッシュが何回出現するかを保存します。 
2. 周波数マップにカウントを含めます`c1, c2, ...`。 追加$$m! \times invfact[c1] \times invfact[c2] \times ...$$グローバルな答えへ。 これは、まさに行マルチセットのさまざまな順列の数です。 

1. 累積された答えのモジュロを出力します。`998244353`。 

なぜ効果があるのか:

 固定幅の場合、すべての有効な行列には、元の文字列を分割して作成されたのとまったく同じ行が含まれている必要があります。 考えられる唯一の違いは、これらの行の順序です。 同一の行が交換された場合、行列は変化しないため、各重複カウントの階乗で除算します。 ローリング ハッシュは、すべての行の ID を維持しながら、高価な部分文字列比較を定数時間の等価性チェックに置き換えるだけです。 すべての幅の正しい寄与を合計すると、可能な行列の完全なセットが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MOD1 = 1000000007
MOD2 = 1000000009
BASE = 911382323

def solve_case(s):
    n = len(s)

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    p1 = [1] * (n + 1)
    p2 = [1] * (n + 1)
    h1 = [0] * (n + 1)
    h2 = [0] * (n + 1)

    for i, c in enumerate(s):
        x = ord(c) - 96
        p1[i + 1] = p1[i] * BASE % MOD1
        p2[i + 1] = p2[i] * BASE % MOD2
        h1[i + 1] = (h1[i] * BASE + x) % MOD1
        h2[i + 1] = (h2[i] * BASE + x) % MOD2

    def get_hash(l, r):
        a = (h1[r] - h1[l] * p1[r - l]) % MOD1
        b = (h2[r] - h2[l] * p2[r - l]) % MOD2
        return (a, b)

    ans = 0

    for d in range(1, n + 1):
        rows = n // d
        cnt = {}
        for i in range(rows):
            key = get_hash(i * d, i * d + d)
            cnt[key] = cnt.get(key, 0) + 1

        cur = fact[rows]
        for c in cnt.values():
            cur = cur * invfact[c] % MOD

        ans += cur
        if ans >= MOD:
            ans -= MOD

    return ans % MOD

def main():
    t = int(input())
    out = []
    for case in range(1, t + 1):
        s = input().strip()
        out.append(f"Case #{case}: {solve_case(s)}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```必要な最大値は行数であり、文字列全体の長さになる可能性があるため、階乗配列はテスト ケースごとに 1 回構築されます。 剰余が素数であるため、フェルマーの定理を使用して逆剰余が得られます。 

ローリング ハッシュ配列には、すべてのプレフィックスのハッシュが保存されます。 部分文字列ハッシュは、その前のプレフィックスの寄与を削除することで復元されます。 ハッシュのペアは辞書キーとして使用されるため、行文字列自体を保存せずに繰り返し行をカウントできます。 

幅ごとに、コードは行ハッシュに対する頻度辞書を作成します。 値`fact[rows]`すべての行の並べ替えをカウントし、逆階乗を乗算することで、等しい行によって生じる過剰カウントが削除されます。 これらの乗算の順序は、寄与を追加する前にすべての重複グループを含める必要があるという意味でのみ重要です。

## 特殊なケース

 のために`aaaa`、 幅`1`行を作成します`a,a,a,a`。 周波数マップには、カウントを含む 1 つのエントリが含まれています`4`、つまり貢献度は`4! / 4! = 1`。 重複補正は逆階乗を通じて適用されるため、アルゴリズムはこれを処理します。 

のために`abcde`、幅`3`、`4`、 そして`5`それぞれが完全な行を 1 つだけ作成します。 たとえば、幅`4`のみを作成します`abcd`、 その間`e`無視されます。 アルゴリズムは行数を次のように設定します。`1`、正確に貢献する`1`。 

のために`aab`、 幅`2`行のみを作成します`aa`。 残り`b`行として検査されることはありません。 周波数マップには以下が含まれます`aa:1`、つまり貢献度は`1`。 実装は完全な行の定義に従い、破棄されたサフィックスは決して含まれません。
