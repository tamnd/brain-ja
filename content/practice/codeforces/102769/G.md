 ## アプローチ

 直接的な解法では、すべての整数を反復処理します。`x`1から`n`。 数値ごとに、次のように計算します。`a = floor(x^(1/k))`かどうかをテストします`x % a == 0`。 これは定義に正確に従っているため、正しいです。 ただし、そのとき`n`到達する`10^9`、これには 1 つのテスト ケースに対して約 10 億のチェックが必要ですが、これは利用可能な時間をはるかに超えています。 

有益な観察は、多くの連続した値が存在することです。`x`同じ値を持っています`floor(x^(1/k))`。 もし`m = floor(x^(1/k))`の場合、そのような数値はすべてその区間内にあります。`m^k <= x < (m + 1)^k`。 

すべての数値を調べる代わりに、考えられるすべてのルート値を調べることができます。`m`。 1 つの間隔内で、次の倍数を数えるだけで済みます。`m`。 可能な数`m`価値観は`floor(n^(1/k))`、最も遅いケースは次のとおりであるため、最大でも約 31623 です。`k = 2`。 

固定の場合`m`、間隔は次のとおりです。`[m^k, min(n, (m+1)^k - 1)]`。 

の倍数の数`m`この間隔では次のようになります。`floor(high / m) - floor((m^k - 1) / m)`。 

のために`m >= 1`、これは直接計算できます。 下限式は次のように単純化されます。`m^(k-1) - 1`、したがって、貢献度は次のようになります。`floor(high / m) - m^(k-1) + 1`。 

すべての数値が個別に検査されるため、総当たり攻撃は機能しますが、次の理由により失敗します。`n`大きすぎます。 間隔観測では、同じルートを共有するすべての数値が 1 つの計算に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 | O(n^(1/k) * log k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. もし`k = 1`、 戻る`n`すぐに。 すべての正の整数はそれ自体を下限根として持つため、すべての数値が適切です。 
2. 探す`r = floor(n^(1/k))`二分探索を使用します。 べき乗に近い値は誤って丸められる可能性があるため、浮動小数点演算は使用できません。 
3. 考えられるすべてのルート値を反復処理します。`m`1から`r`。 それぞれ`m`数字の完全な 1 つのブロックを表します。`k`-th root に等しい`m`。 
4. ブロックの右端点を次のように計算します。`min(n, (m+1)^k - 1)`。 左側の終点は、`m^k`、およびすべての倍数`m`この範囲内では、1 つの適切な数値が得られます。 
5. の倍数を加算します。`m`この区間内では整数除算を使用します。 考えられるすべてのルートに対してこれを繰り返すと、すべての適切な数値が 1 回だけカウントされます。 

この分割が正しい理由は、すべての正の整数が 1 つの値を持つためです。`floor(x^(1/k))`。 間隔は重複しないため、数値を 2 回数えることはできず、すべての有効な数値はそのルートに属する間隔に表示されます。 

機能する理由: アルゴリズムは、次の値までのすべてのルート値を処理した後、不変条件を維持します。`m`、答えには、フロアが一致するすべての適切な数値が正確に含まれています。`k`-th ルートは最大でも`m`。 次の間隔にはルートを持つ数字のみが含まれます`m+1`、そして複数の数え方の公式は適切な数の定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def power_limit(a, b, limit):
    result = 1
    while b:
        if b & 1:
            result *= a
            if result > limit:
                return limit + 1
        b >>= 1
        if b:
            a *= a
            if a > limit:
                a = limit + 1
    return result

def kth_root(n, k):
    if k == 1:
        return n
    lo, hi = 1, n
    ans = 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if power_limit(mid, k, n) <= n:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans

def solve_case(n, k):
    if k == 1:
        return n

    r = kth_root(n, k)
    ans = 0

    for m in range(1, r + 1):
        high = min(n, power_limit(m + 1, k, n) - 1)
        lower_power = power_limit(m, k, n)
        ans += high // m - (lower_power - 1) // m

    return ans

def main():
    t = int(input())
    out = []
    for case in range(1, t + 1):
        n, k = map(int, input().split())
        out.append(f"Case #{case}: {solve_case(n, k)}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```の`power_limit`アルゴリズムはべき乗が次を超えるかどうかだけを知る必要があるため、Python の通常のべき乗の代わりにこの関数が使用されます。`n`。 早期に停止すると、二分探索中に不必要に大きな整数が作成されることが回避されます。 

の`kth_root`関数は、考えられるルート値に対して二分検索を実行します。 単調特性は次の事実から来ます。`x^k`として増加します`x`増加するため、値が大きすぎると、それ以上の値も大きすぎます。 

内部`solve_case`、各反復は 1 つのルート間隔を処理します。 表現`high // m - (lower_power - 1) // m`～の倍数を数える`m`間隔を反復せずに。 減算では、`lower_power - 1`間隔は次から始まりますので、`m^k`、そしてその時点の前に厳密に倍数のカウントが必要です。 

Python の整数はオーバーフローしませんが、初期のカットオフが発生します。`power_limit`などの値があるため、パフォーマンスには依然として必要です。`2^1000000000`決して建設してはなりません。

 ## 特殊なケース

 いつ`k = 1`、すべての数値には独自のルートがあるため、ルート間隔のアイデアは崩壊します。 アルゴリズムはループを回避して戻ります。`n`、これは定義と直接一致します。 入力用`233 1`、それは出力します`233`。 

根が 1 の場合、次のべき乗以前のすべての数値は最初の区間に属します。 入力用`5 2`、間隔は`[1, 3]`、3 つの値すべてがカウントされます。 アルゴリズムは反復を開始します`m = 1`, したがって、これらの値が含まれます。 

いつ`n`間隔の途中で終了する場合は、間隔を短くする必要があります。 入力用`16 2`、ルート 4 の間隔は通常次のようになります。`[16, 24]`、しかし、ただ`16`許容範囲内です。 アルゴリズムが使用するのは、`min(n, (m+1)^k - 1)`, したがって、有効な部分のみがカウントされます。 

いつ`k`は非常に大きいため、ルート値は通常 1 です。入力の場合`1,000,000,000 1000000000`、アルゴリズムの二分探索では、1 より大きい根は制限内でその検出力を持つことができないことがすぐにわかり、最初の間隔のみが処理されます。
