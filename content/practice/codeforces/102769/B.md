 ## 問題の理解

 セルの長方形のマップがあります。 乾電池を表すと、`#`湿電池は次のように表されます。`.`。 境界壁は長方形の境界線ですが、問題はその覆われた長方形の領域を求めます。 長方形は完全に乾電池で構成されており、クエリで指定されたセルが含まれている必要があります。 いくつかのクエリの後、個々のセルがドライとウェットの間で切り替わるため、要求されたセルの可能な最大面積を答える必要があります。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、初期グリッドとそれに続く操作が提供されます。 更新により 1 つのセルが変更されます。 クエリでは、特定の位置を含む最大の完全に乾いた長方形が求められます。 

制約は 1 つの次元では小さいですが、1 つのテスト ケースで最大 1000 行、1000 列、および 1000 の操作が可能です。 1000 x 1000 のグリッドにはすでに約$10^{12}$可能な長方形。 完全な動的プログラミング テーブルを使用してすべてのクエリの答えを再計算しても、時間がかかりすぎます。 各クエリがグリッドを 1 回だけスキャンする方法が必要です。 

有益な観察は、1000 列がマシンサイズのビット演算に自然に適合するということです。 行全体は 1 つの整数として表すことができます。ここで、ビットは`1`乾燥したという意味です。 交差する行は 1 つの整数 AND 演算になります。 これにより、候補四角形のすべての列を非常に迅速に調べることができます。 

不注意な解決策を打ち破る特殊なケースがいくつかあります。 クエリされたセル自体がウェットの場合、すべての有効な四角形にはそのセルが含まれている必要があるため、答えはゼロになります。

## アプローチ

 直接的なアプローチは、クエリされたセルを含む可能なすべての四角形を列挙し、そのすべてのセルが乾燥しているかどうかをテストすることです。 すべての有効な答えが考慮されるため、これは正しいですが、1000 x 1000 グリッド内の四角形の数はおよそ$10^{12}$。 プレフィックス合計を使用しても、クエリごとにすべての四角形をチェックすることは制限をはるかに超えています。 

より良いアイデアは、長方形の 1 つの次元を固定し、可能な限り最適な他の次元を計算することです。 クエリ セルの場合、すべての四角形にクエリ対象の行が含まれている必要があります。 その行から上に拡張すると、これまでに含まれていたすべての行の交差を維持できます。 残りの設定ビットは、現在の高さ間隔のすべての行が乾燥している列です。 

その高さ間隔の最大の長方形は、クエリされた列を含むこれらの有効な列の最長の連続セグメントです。 下に伸ばしながらも同じことができます。 2 回のスキャンは、長方形の上部と下部の境界をすべてカバーします。 

これが効率的に機能する理由は、グリッドの次元が 1000 しかないためです。実際の作業は最適化された大きな整数演算によって処理されるため、各行を Python 整数として表すと、アルゴリズムの観点からはすべての行の交差が一定時間内に発生します。

 ## アルゴリズムのチュートリアル

 1. グリッドのすべての行を整数ビットマスクとして保存します。 少し`j`列のときに設定されます`j`その列は乾いています。 セルの更新は、対応するビットに対する単一の XOR 演算になります。 
2. お問い合わせの場合は、`(r, c)`、利用可能なすべての列から開始し、行から上に向かって拡張します。`r`。 各行を追加した後、現在のマスクをその行と交差させます。 残りのビットは、現在の四角形の高さの各行でドライになっている列を表します。 
3. クエリされた列がマスクから消えた場合は、その方向への拡張を停止します。 より大きな長方形にはそのウェット セルも含まれるため、それ以上の行では有効な答えを作成できません。 
4. 有効な高さ間隔ごとに、柱を含む連続した乾燥セグメントの長さを計算します。`c`。 その幅に現在の高さを掛けて、答えを更新します。 
5. 列から下に伸ばしながら同じプロセスを繰り返します`r + 1`。 両方向を組み合わせると、クエリ セルを含む四角形の考えられるすべての上下の境界線が考慮されます。 

なぜ効果があるのか:

 上向きスキャン中に、からの行を処理した後、`top`に`r`、ビット マスクには、行のすべてのセルが乾燥している列が正確に含まれています。 を含む最長連続セグメント`c`は、その正確な行セットに対して可能な最大幅の長方形です。 すべての有効な四角形には上部の行があり、その上部の行がスキャンに表示されます。 同じ議論が下向きスキャンにも当てはまります。 あらゆる垂直範囲が考慮され、それぞれに最適な幅が選択されるため、最大面積が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def trailing_ones(x):
    return ((~x) & (x + 1)).bit_length() - 1

def width_at(mask, col):
    right = trailing_ones(mask >> col)
    left_mask = mask & ((1 << col) - 1)
    left = trailing_ones(left_mask)
    return left + right + 1

def solve_case(n, m, q, grid, queries):
    rows = []
    for s in grid:
        x = 0
        for i, ch in enumerate(s):
            if ch == '#':
                x |= 1 << i
        rows.append(x)

    all_bits = (1 << m) - 1
    ans = []

    for t, x, y in queries:
        x -= 1
        y -= 1

        if t == 1:
            rows[x] ^= 1 << y
        else:
            if ((rows[x] >> y) & 1) == 0:
                ans.append("0")
                continue

            best = 1

            mask = all_bits
            height = 0
            for i in range(x, -1, -1):
                mask &= rows[i]
                if ((mask >> y) & 1) == 0:
                    break
                height += 1
                best = max(best, height * width_at(mask, y))

            mask = all_bits
            height = 0
            for i in range(x + 1, n):
                mask &= rows[i]
                if ((mask >> y) & 1) == 0:
                    break
                height += 1
                best = max(best, height * width_at(mask, y))

            ans.append(str(best))

    return ans

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m, q = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        queries = [tuple(map(int, input().split())) for _ in range(q)]

        out.append(f"Case #{case}:")
        out.extend(solve_case(n, m, q, grid, queries))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```グリッド表現は主な実装の詳細です。 各行は整数に変換されるため、セルを更新するときに文字列を変更したり、配列を再構築したりする必要はありません。 この操作は 1 ビットのみを反転するため、XOR が機能します。 

クエリの場合は、`mask`すべての列が有効な状態で開始されます。 すべての AND 演算では、現在の垂直範囲内に少なくとも 1 つのウェット セルを含む列が削除されます。 クエリ列が削除されると、四角形には要求されたセルを含めることができなくなるため、スキャンはすぐに終了します。 

機能`width_at`指定された列を含む一連のセット ビットを検索します。 右側は、クエリされたビットを最下位位置にシフトした後、後続のビットをカウントすることによって取得されます。 左側は、クエリされた列の前のビットに対する同じ操作です。 

Python の整数には任意の精度があるため、1 行に 1000 ビットを含めることができる場合でも、オーバーフローの心配はありません。

 ## 特殊なケース

 クエリされたセルがウェットの場合、アルゴリズムはスキャン前にビットをチェックします。 のみを含むグリッドの場合`.`クエリされた位置では、考えられるすべての長方形にそのウェット セルが含まれるため、答えはすぐにゼロになります。 

最適な長方形が境界線に接触すると、上向きまたは下向きのスキャンは自然に行配列の端に到達します。 スキャンは最後の有効な行の後で停止するだけであるため、特別な境界処理はありません。 

1 行または 1 列のみが使用可能な場合でも、同じ交差ロジックが適用されます。 幅の計算では 1 を返すことができ、面積式では細い長方形を正しく処理できます。 最小の高さまたは幅に関する仮定はアルゴリズムに組み込まれていません。
