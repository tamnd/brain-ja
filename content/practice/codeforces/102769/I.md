 ## 解決策
 ## 問題の理解

 この問題は、無限グリッドの原点から始まる宇宙船をモデル化します。 ゲーム中には、新しいジャンプスキルが追加されます。 スキル`(a, b)`そのベクトルを何度でも加算または減算することで宇宙船を移動させることができるため、到達可能な位置のセットは、取得されたすべてのベクトルによって生成された整数格子とまったく同じになります。 

報酬イベントの場合、座標にミッションが出現します`(x, y)`価値のあるもの`w`。 ミッションは次の場合にのみ完了できます`(x, y)`現在到達可能です。 宇宙船は到達可能なすべての報酬を個別に収集でき、スキルは蓄積されるだけであるため、答えは現在生成されているラティスに属するミッションからのすべての報酬値の合計になります。 

到達できるイベント数は、`10^5`テストケースごとに合計が達成可能`10^6`。 すべてのクエリに対して以前のすべてのスキルをチェックするソリューションには、最大で`10^11`制限時間内に収まらない操作。 ソリューションでは、対数時間に近い各イベントを処理する必要があります。 

主な問題は、到達可能なセットが座標の最大公約数だけではないことです。 例えばスキルを持っているとか、`(2,0)`そして`(0,2)`両方の座標が偶数である点のみを許可します。 ポイント`(2,2)`到達可能ですが、`(2,1)`そうではありません。 単一の gcd 値では、この情報が失われます。 

一部の特殊なケースは見落とされやすいものです。 

スキルがなければ、あらゆるミッションは不可能です。```
4
2 1 1 10
1 2 0
2 4 0 5
2 1 0 7
```正しい答えは、`5`、なぜなら、`(4,0)`スキル後に到達可能になる`(2,0)`取得されます。 原点またはすべての点が到達可能であると仮定するソリューションでは、過剰にカウントされてしまいます。 

1 つのスキルで、完全な平面ではなく 1 次元の線が作成されます。```
3
1 2 4
2 1 2 10
2 2 4 5
```正しい答えは、`5`。 最初のミッションは無理だから`(1,2)`の倍数ではありません`(2,4)`。 2番目のものは到達可能です。 1 つのベクトルを完全な 2 次元の基底として扱うと、間違った答えが得られます。 

座標がゼロのベクトルも正しく機能する必要があります。```
3
1 0 3
2 0 6 8
2 1 3 10
```正しい答えは、`8`。 最初のスキルは垂直方向の移動のみを許可します。 ポイント`(1,3)`到達できません。 

## アプローチ

 直接的なアプローチでは、獲得したすべてのスキルを保存し、ミッションごとに、ターゲットの座標が保存されているすべてのベクトルの整数の組み合わせとして表現できるかどうかを解決します。 以前のすべてのベクトルに対するガウス消去法では、同じ情報が繰り返し再構築されるため、総コストが非常に大きくなります。 

重要な観察は、生成されたセットが常に 2 次元の整数格子であるということです。 すべてのベクトルが必要なわけではありません。 現在の格子を記述するコンパクトな基底だけが必要です。 

2 次元では、格子はエルミート標準形式で保存できます。```
(a, 0)
(c, d)
```ここで、到達可能なすべてのポイントは次の形式になります。```
(a * p + c * q, d * q)
```整数の場合`p`そして`q`。 

この表現により、定数時間のメンバーシップ テストが行​​われます。 ポイント`(x, y)`正確にいつ到達できるか`y`で割り切れます`d`、そして 2 番目の基底ベクトルの寄与を除去した後、残りの x 座標は次の式で割り切れます。`a`。 

新しいベクトルが到着すると、基底を再構築するのではなく更新します。 ベクトルを追加すると行列式の gcd を通じて格子のインデックスが変更されるため、更新では gcd 操作が使用されます。 行列式は格子ベクトルによって形成される平行四辺形の面積を記述し、それらの面積の gcd が新しい格子インデックスを与えます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(Q²) | O(Q) | 遅すぎる |
 | Hermite 標準形式のメンテナンス | O(QログC) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在の格子を 3 つの状態のいずれかに維持します。 空、1 つのプリミティブ方向によって生成された単一の線、または次のように保存された完全な 2 次元格子にすることができます。`(a, c, d)`。 
2. 新しいスキルを追加するときは、まず格子が空かどうかを確認します。 存在する場合、スキルは最初のジェネレータになります。 
3. 現在の格子が一方向である場合、新しいベクトルがそれに平行であるかどうかを確認します。 並列の場合は、gcd を使用してステップ サイズを更新します。 平行でない場合は、独立したベクトルが 2 つ存在することになるので、これを 2 次元のエルミート形式に変換します。 
4. 格子がすでに 2 次元である場合は、エルミート基底を更新します。 新しい垂直期間は次のようになります。`gcd(d, y)`。 新しい格子インデックスは、古いインデックスの gcd と新しいベクトルによって作成された行列式から見つかります。 
5. 報酬クエリの場合、現在のラティスのメンバーシップをテストします。 ポイントがそのポイントに属している場合は、その報酬値を答えに追加します。 

なぜ効果があるのか:

 維持された基礎により、獲得したすべてのスキルとまったく同じ一連のポイントが常に生成されます。 スキルを追加すると格子が拡大されるだけで、gcd と行列式の公式は古い基底と新しいベクトルの両方を含む最小の格子を計算します。 すべてのクエリはこの正確な格子表現に対して直接応答されるため、受け入れられたすべての報酬は到達可能ですが、拒否されたすべての報酬は到達できません。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return abs(a), 1 if a >= 0 else -1, 0
    g, x, y = egcd(b, a % b)
    return g, y, x - (a // b) * y

class Lattice:
    def __init__(self):
        self.typ = 0
        self.u = self.v = 0
        self.a = self.c = self.d = 0

    def add(self, x, y):
        if x == 0 and y == 0:
            return

        if self.typ == 0:
            g = gcd(abs(x), abs(y))
            self.typ = 1
            self.u, self.v = x // g, y // g
            self.step = g
            return

        if self.typ == 1:
            if self.u * y == self.v * x:
                if self.u != 0:
                    k = x // self.u
                else:
                    k = y // self.v
                self.step = gcd(self.step, abs(k))
                return

            x1, y1 = self.u * self.step, self.v * self.step
            self.typ = 2
            self.a, self.c, self.d = self.to_hnf(x1, y1, x, y)
            return

        a, c, d = self.a, self.c, self.d
        nd = gcd(d, y)
        idx = gcd(a * d, a * y, c * y - d * x)
        na = idx // nd

        _, p, q = egcd(d, y)
        nc = (p * c + q * x) % na if na else 0

        self.a, self.c, self.d = na, nc, nd

    def to_hnf(self, x1, y1, x2, y2):
        if y1 == 0:
            x1, y1, x2, y2 = x2, y2, x1, y1
        idx = abs(x1 * y2 - x2 * y1)
        d = gcd(abs(y1), abs(y2))
        a = idx // d
        _, p, q = egcd(y1, y2)
        c = (p * x1 + q * x2) % a if a else 0
        return a, c, d

    def reachable(self, x, y):
        if self.typ == 0:
            return x == 0 and y == 0

        if self.typ == 1:
            if self.u == 0:
                return x == 0 and y % (self.v * self.step) == 0
            if self.v == 0:
                return y == 0 and x % (self.u * self.step) == 0
            return x * self.v == y * self.u and x % self.u == 0 and (x // self.u) % self.step == 0

        if y % self.d:
            return False
        q = y // self.d
        return (x - self.c * q) % self.a == 0

def solve():
    t = int(input())
    out = []
    for case in range(1, t + 1):
        q = int(input())
        lattice = Lattice()
        ans = 0
        for _ in range(q):
            data = list(map(int, input().split()))
            if data[0] == 1:
                lattice.add(data[1], data[2])
            else:
                if lattice.reachable(data[1], data[2]):
                    ans += data[3]
        out.append(f"Case #{case}: {ans}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では現在の格子記述のみが保持されるため、メモリ使用量は一定に保たれます。 の`add`この方法は、ウォークスルーで説明されている 3 つの格子状態に従います。 2 次元の更新は最もデリケートな部分です。`idx`新しい格子インデックスを保存し、`egcd(d, y)`y 座標が新しい垂直周期となる組み合わせを構築します。 

生成されたすべてのベクトルの y 座標は次の倍数であるため、完全な格子のメンバーシップ テストでは、最初に y 座標がチェックされます。`d`。 2 番目の基底ベクトルの係数を固定した後、残りの x 座標は水平サブグループに属さなければなりません。 

1 次元のケースは、単一のベクトルが一意のエルミート基底を定義しないため分離されます。 このケースを忘れると、間違った答えが生まれる可能性が高くなります。

 ## 特殊なケース

 空の格子の場合、アルゴリズムは次のようになります。`typ = 0`。 ミッションは以下でのみ受け付けます`(0,0)`、これはスキルを取得する前に到達できる唯一のポイントです。 

次のような単一ベクトルの場合`(2,4)`、アルゴリズムは飛行機全体が到達可能であるかのように見せかけません。 プリミティブ方向を格納します`(1,2)`そしてステップサイズ`2`、だからそれだけ`(2k,4k)`ポジションはメンバーシップチェックに合格します。 

ゼロ座標ベクトルの場合も、同じ表現が機能します。 スキル`(0,3)`垂直線が作成され、クエリ ロジックは無効な除算を実行する代わりに、欠落している座標を明示的にチェックします。 

2 次元格子の場合、エルミート形式は隠れたパリティの間違いを防ぎます。 たとえば、スキル`(2,0)`そして`(0,2)`偶数グリッドを正確に記述する基底を生成します。`(1,1)`一方で拒否される`(4,2)`受け入れられます。
