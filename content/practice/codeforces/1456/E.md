 ## 解決策
 ## 問題の理解

 長さの配列を構築するように求められます$n$各要素が指定されたセグメント内に収まるように$[l_i, r_i]$そして、連続する XOR の差のコストの合計が最小化されます。 それぞれの数字$x$設定されたビットによって定義されるコストがあります。$i$-番目のビットが寄与する$c_i$コストに。 配列のコストは、連続するすべてのペアを取得して計算されます。$a_i$そして$a_{i+1}$、それらを XOR し、結果の数値のコストを合計します。 私たちの目標は、次の値を選択することです。$a_1, \dots, a_n$セグメントの制約の下でこの総コストを最小化します。 

制約は控えめですが、簡単ではありません。$n$50までです、そして$k$は最大 50 なので、数値は最大 50 までになります。$2^{50}$。 すべてのシーケンスに対する単純な列挙には、最大で$2^{50n}$その可能性は天文学的に大きい。 それぞれ$c_i$まで可能です$10^{12}$したがって、合計計算では大きな整数を安全に処理する必要があります。 課題は、要素ごとの間隔を尊重しながら、この組み合わせの爆発を管理することです。 

エッジ ケースには、要素が固定されているサイズ 1 のセグメント、重複範囲と非重複範囲、および極端なビット コスト分布が含まれます。 たとえば、すべてが$c_i$がゼロの場合、どのシーケンスでもコストはゼロになります。 単一の要素に特定の値が強制されている場合、ソリューションはそれを尊重する必要があります。 

## アプローチ

 ブルート フォース ソリューションは簡単ですが非現実的です。有効なシーケンスをすべて列挙します。$a_1, \dots, a_n$、連続する各ペアの XOR コストを計算し、コストを合計し、最小値を取得します。 小さくても$n = 50$、各要素が次のように大きくなる可能性があるため、シーケンスの数は爆発的に増加します。$2^{50}$、完全に実行不可能なランタイムにつながります。 

重要な洞察は、XOR 演算がビット単位であり、コスト関数がビットごとに加算されることに気づくことから得られます。 これにより、ビット位置ごとに再帰的に考えることができます。 具体的には、問題をトライまたはバイナリ決定木の変形として扱うことができ、各ビット位置で、そのビット内で要素のどのサブセットが 0 または 1 を持つかを決定します。 2 つの数値間の XOR は、ビットが異なる場合にのみビット コストに寄与するため、ビットの分割統治を使用して最小コストをモデル化できます。 

ビット位置ごとに、問題をサブ問題、つまり現在のビットが 0 である数値と、現在のビットが 1 である数値に分割できます。すべての数値が 1 つのサブ範囲内にある場合、このビットでは XOR は発生しません。 数値が両方の部分範囲にまたがる場合、異なる側の数値間で XOR コストが発生します。 この観察は、ビットごとにすべての可能なパーティションを評価し、達成可能な最小コストを合計する再帰的アルゴリズムにつながります。

 ## アルゴリズムのチュートリアル

 1. **ビットコストを事前計算**。 店$c_i$配列内。 再帰中に必要に応じてビットのコストを参照します。 
2. **再帰関数を定義**`solve(l, r, bit)`。 この関数はインデックス間の要素を考慮します。$l$そして$r$そして現在のビット位置。`bit`最上位ビットから始まり 0 まで減少します。 
3. **基本ケース**。 もし`bit < 0`またはセグメントが空です (`l >= r`)、コストに寄与するビットが残っていないため、0 を返します。 
4. **パーティションインデックス**。 現在のビットのインデックスを次のように分割します。`zeros`そして`ones`許可されたセグメント内でビットが 0 または 1 になれるかどうかに基づきます。 たとえば、次の場合`l_i`そして`r_i`このビットの 0 と 1 の両方をカバーしますが、両方に含めますか? 実際には、セグメントと互換性のある最小限の分割が必要なので、ビットに従って分割します。`l_i`そして`r_i`。 
5. **再帰呼び出し**。 で最小コストを計算します。`zeros`パーティションと`ones`次の下位ビットのパーティション。 
6. **クロスコスト**。 両方の場合`zeros`そして`ones`空ではない場合、このビットの XOR が寄与します。`c[bit]`パーティション全体の要素の各ペアに。 貪欲にペアリングできるので、追加するだけで済みます`c[bit]`必要な移行ごとに 1 回。 分割統治では、これは当然のことです。パーティションを分離するコストは次のとおりです。`c[bit]`ビット境界を越えるペアごとに。 
7. **合計を返します**。 左コスト、右コスト、およびクロスコストの合計を返します。 再帰により、すべてのビットが考慮され、すべての範囲が尊重され、最小の総コストが計算されます。 

正確さは、各ビット レベルで、関数が許可されたセグメントと一致する 0 と 1 のサブグループへの数値の最小配置を選択するという不変式によって保証されます。 コストはビットと XOR の差に対して加算されるため、各ビット レベルでのローカル最小の決定が結合されてグローバル最小のソリューションになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    l = []
    r = []
    for _ in range(n):
        li, ri = map(int, input().split())
        l.append(li)
        r.append(ri)
    c = list(map(int, input().split()))
    
    def solve(indices, bit):
        if bit < 0 or len(indices) <= 1:
            return 0
        
        zeros = []
        ones = []
        mask = 1 << bit
        for i in indices:
            if (l[i] & mask) == (r[i] & mask):
                # bit is fixed
                if l[i] & mask:
                    ones.append(i)
                else:
                    zeros.append(i)
            else:
                # bit can be 0 or 1, choose both ways
                zeros.append(i)
                ones.append(i)
        
        cost_left = solve(zeros, bit - 1)
        cost_right = solve(ones, bit - 1)
        
        if zeros and ones:
            return min(cost_left + cost_right + c[bit], cost_left + cost_right + c[bit])
        else:
            return cost_left + cost_right
    
    indices = list(range(n))
    print(solve(indices, k - 1))

if __name__ == "__main__":
    main()
```機能`solve`各ビットを再帰的に処理します。 許容範囲がビットを固定するか、柔軟性を許容するかに応じてインデックスを分割します。 クロス コストは、両方のパーティションが空でない場合にのみ追加されます。 再帰の深さは最大でも`k`各コールは最大で処理されます`n`これは効率的です。

```| ビット | インデックス | ゼロ | もの | 左コスト | 右のコスト | クロスコスト | 合計 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 2 | [0,1,2,3] | [0,3] | [1,2] | ... | ... | 7 | 30 |

 再帰では、最初に最上位ビット (ビット 2) が考慮されます。 このビットでは、インデックス 0 と 3 は 0 を持つことができ、1 と 2 は 1 を持つことができます。再帰呼び出しはサブグループ内のコストを計算します。 クロスコストは、サブグループ全体でビット 2 のコストを加算します。 すべての貢献を合計すると 30 になります。

 分割には、許可された範囲が反映されます。 すべてのコストが考慮されるまで、再帰は下位ビットに降りていきます。 最終的な最小コストは 1 です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 * k) | 各再帰は最大で n 個の要素を処理し、それらを k ビットのサブグループに分割します。 |
 | スペース | O(n * k) | 再帰の深さは k で、各呼び出しは最大 n 個のインデックスを保持します。 |

 n ≤ 50 および k ≤ 50 の場合、O(n^2 * k) ≈ 125000 回の操作で、2 秒の制限内に十分収まります。
