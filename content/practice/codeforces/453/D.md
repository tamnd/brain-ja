 ## 解決策
 ## 問題の理解

 長さのすべてのビットマスクによってインデックス付けされたエネルギーのベクトルがあります。`m`。 以来`n = 2^m`、すべての頂点は`m`-ビット番号。 

1 つの変換ステップは線形です。 頂点のペアごとに`u`そして`v`からの寄稿`v`に`u`ビット表現間のハミング距離のみに依存します。$$A_{u,v} = b[\text{popcount}(u \oplus v)]$$もし`e_i`は時間のエネルギーベクトルです`i`、 それから$$e_{i+1} = A e_i.$$タスクは計算することです$$e_t = A^t e_0$$モジュロ`p`、 どこ`t`と同じ大きさにすることができます`10^{18}`。 

この制約により、通常の行列のべき乗が即座に除外されます。 マトリックスのサイズは`n × n`、 そして`n = 2^m`と`m ≤ 20`、 それで`n`到達できる`1,048,576`。 密な行列には、以下のものが含まれます。`10^{12}`エントリを保存することは完全に不可能です。 

単純に一度変換を適用するだけでもコストがかかります`O(n²)`。 おおよその最大サイズについては、`10^{12}`べき乗を考慮する前に、単一ステップの演算を実行します。 

マトリックスの構造が問題全体です。 すべてのエントリは以下にのみ依存します`u xor v`。 このような行列は XOR 畳み込み代数を形成し、ウォルシュ アダマール変換によって対角化されます。 

微妙なエッジケースは、`t = 0`。 この場合、変換は適用されず、答えは単純です。`e0 mod p`。 

例えば：```
m = 1
t = 0
p = 100
e0 = [5, 7]
b = [3, 4]
```出力：```
5
7
```ゼロ指数を処理せずに固有値を盲目的に累乗するソリューションは数学的には機能しますが、実装ではこの特殊なケースが忘れられることがよくあります。 

もう 1 つの簡単な間違いは、2 による除算を使用してウォルシュ アダマール変換を実行することです。 弾性率`p`は必ずしも素数であるとは限らず、偶数である場合もあるため、逆剰余は一般に存在しません。 

例えば：```
p = 100
```の逆`2`モジュロ`100`存在しません。 正規化されたアダマール行列に基づく解はすぐに失敗します。 正しいアプローチでは、非正規化変換を使用します。反転は、次の値で割ることによって実現されます。`n = 2^m`モジュロを取る前に整数を上書きする`p`。 

3 番目の落とし穴は、固定幅演算を使用する言語での整数オーバーフローです。 固有値は、値の加算と減算を繰り返して構築されます。`10^9`、次にパワーアップします。`10^{18}`モジュロ`p`。 Python はこれを自然に処理しますが、C++ ソリューションではモジュロを削減する必要があります。`p`気をつけて。 

## アプローチ

 まず変換を行列の乗算として見てみましょう`A`。 

ブルートフォースソリューションは次のように構成します。$$A_{u,v}=b[\text{popcount}(u\oplus v)]$$そして計算します$$A^t e_0.$$各ステップは正確に行列とベクトルの乗算であるため、この定義は正しいです。 残念ながら、行列には​​サイズがあります`n × n`と`n = 2^m`。 最大制約では、これは 1 兆を超えるエントリになります。 たった一度の掛け算にもコストがかかる`O(n²)`。 

重要な観察は、行列は次のもののみに依存するということです。`u xor v`。 

定義する$$g[x] = b[\text{popcount}(x)].$$それから$$(Af)[u] = \sum_v g[u\oplus v] f[v].$$これはまさにカーネルとの XOR 畳み込みです`g`。 

Walsh-Hadamard 変換は、XOR 畳み込みに対して、FFT が通常の畳み込みに対して果たすのと同じ役割を果たします。 もし`H`はアダマール変換を表し、$$H(g *_{\text{xor}} f) = (Hg)\cdot(Hf).$$その結果、行列はアダマール基底で対角になります。 

対角要素は単に次の Walsh-Hadamard 変換です。`g`。 それらを次のように表すと、`λ[x]`、 それから$$A = H^{-1} D H,$$どこ`D`エントリが斜めになっている`λ[x]`。 

これで、べき乗が簡単になります。$$A^t = H^{-1} D^t H.$$巨大な行列を累乗する代わりに、累乗のみを行います。`n`スカラー固有値。 

残りの課題は、固有値を効率的に計算することです。 カーネル$$g[x] = b[\text{popcount}(x)]$$ハミング重みのみに依存します`x`。 このような関数はブール立方体上で対称です。 彼らの Walsh 変換はまさに Krawtchouk 変換です。 

もし`k = popcount(mask)`、次にウェイトのすべてのマスク`k`同じ固有値を持ちます。 させて$$\lambda_k$$その値を表します。 

クラウチョークの再発により、すべてが可能になります`m+1`計算される固有値`O(m²)`時間。 以来`m ≤ 20`、このコストは無視できます。 

固有値を取得した後:

 1. 変身`e0`FWTで。 
2. マスクごとに次の乗算を行います。`λ_{popcount(mask)}^t`。 
3. 逆 FWT を適用します。 
4. で割る`n`。 
5.モジュロを削減します`p`。 

高価な部分は、サイズの 2 つの Walsh-Hadamard 変換です。`n`、複雑さを与える`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log t) 以上 | O(n²) | 遅すぎる |
 | 最適 | O(n log n + m²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1

 Krawtchouk 変換テーブルを構築します。 

させて$$K_k(i)$$重みに対応するクラウチョーク多項式の値`k`そして議論`i`。 

再発というのは、$$K_k(i) = K_k(i-1)-K_{k-1}(i)-K_{k-1}(i-1),$$と$$K_0(i)=1.$$以来`m ≤ 20`、`(m+1) × (m+1)`テーブルが小さいです。 

### ステップ 2

 すべての個別の固有値を計算します。 

体重ごとに`k`:$$\lambda_k = \sum_{i=0}^{m} b[i]\;K_k(i).$$ポップカウントが等しいすべてのマスク`k`この固有値を共有します。 

### ステップ 3

 Walsh-Hadamard 変換を初期エネルギー ベクトルに適用します。 

標準の反復変換は次のことを実行します。$$(a,b)\rightarrow(a+b,\ a-b)$$すべてのブロックに。 

すべての算術はモジュロで実行されます`p`。 

### ステップ 4

 マスクに対応する変換された係数ごとに`x`、 させて$$k=\text{popcount}(x).$$係数を掛ける$$\lambda_k^t \pmod p.$$これはまさに対角行列の作用です`D^t`。 

### ステップ 5

 Walsh-Hadamard 変換を再度適用します。 

正規化されていないアダマール行列の場合、$$H^2 = nI.$$変換を 2 回適用すると、次の係数が得られます。`n`。 

### ステップ 6

 すべての係数を次の値で割ります。`n`。 

なぜなら`n=2^m`、この除算は整数アダマール代数では正確です。 最終的な答えのモジュロを減らす前にそれを実行します`p`。 

### なぜ効果があるのか

 変換行列は次の条件を満たします。$$A_{u,v}=g[u\oplus v].$$この形式の行列は、ウォルシュ アダマール基底によって対角化されます。 マスクに関連付けられた固有値は、そのハミング重みのみに依存し、次のウォルシュ変換と等しくなります。`g`。 

初期ベクトルを変換した後、各アダマール座標は独立して進化します。 マトリックスを次のように引き上げると、`t`の乗は、各固有値の になります。`t`-乗。 逆変換により、元の座標系が再構築されます。 

すべてのステップはまさに次の代数的再定式化であるため、$$e_t=A^t e_0,$$結果のベクトルは正確に次のエネルギー分布になります。`t`変化。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def fwht(a, mod):
    n = len(a)
    step = 1
    while step < n:
        jump = step << 1
        for i in range(0, n, jump):
            for j in range(step):
                x = a[i + j]
                y = a[i + j + step]
                a[i + j] = (x + y) % mod
                a[i + j + step] = (x - y) % mod
        step <<= 1

def solve():
    m, t, p = map(int, input().split())
    n = 1 << m

    e = [x % p for x in map(int, input().split())]
    b = list(map(int, input().split()))

    # Krawtchouk table
    K = [[0] * (m + 1) for _ in range(m + 1)]

    for i in range(m + 1):
        K[0][i] = 1

    for k in range(1, m + 1):
        K[k][0] = K[k - 1][0]

    for k in range(1, m + 1):
        for i in range(1, m + 1):
            K[k][i] = (
                K[k][i - 1]
                - K[k - 1][i]
                - K[k - 1][i - 1]
            )

    eig = [0] * (m + 1)
    for k in range(m + 1):
        s = 0
        for i in range(m + 1):
            s += b[i] * K[k][i]
        eig[k] = s % p

    fwht(e, p)

    popcnt = [0] * n
    for i in range(1, n):
        popcnt[i] = popcnt[i >> 1] + (i & 1)

    powers = [pow(eig[k], t, p) for k in range(m + 1)]

    for mask in range(n):
        e[mask] = e[mask] * powers[popcnt[mask]] % p

    fwht(e, p)

    inv_factor = pow(n, -1, p)

    out = [(x * inv_factor) % p for x in e]
    sys.stdout.write("\n".join(map(str, out)))

solve()
```Krawtchouk テーブルは、重み対称関数のすべてのウォルシュ変換値を計算します。 カーネルはハミング重みのみに依存するため、完全な行列を構築する必要はありません。 

最初の Walsh-Hadamard 変換は、ベクトルを固有基底に移動します。 の乗算`powers[popcount(mask)]`対角行列を適用します`D^t`。 

2 番目の変換は元の基底に戻ります。 ここで使用されるウォルシュ アダマール行列は正規化されていないため、逆行列を次で割る必要があります。`n`。 

最もデリケートな部分は固有値の計算です。 同じポップカウントを持つすべてのマスクは同じ固有値を共有するため、次の問題が軽減されます。`2^m`固有の固有値のみを指定する`m+1`。
