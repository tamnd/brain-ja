 ## 解決策
 ## 問題の理解

 ポニーのラインナップには、現在のマナ、最大マナ、単位時間あたりのマナ回復率の 3 つの属性があります。 時間の経過とともに、ティレック卿はマナ吸収と呼ばれるいくつかの作戦を実行し、それぞれが連続するポニーのセグメントをターゲットにします。 彼が特定の時間にマナを吸収すると、各ポニーが現在持っているすべてのマナが収集され、それらのマナはゼロにリセットされます。 指示の合間に、ポニーはそれぞれの速度でマナを再生しますが、個々の最大値を超えることはできません。 

目標は、「マナ吸収」命令ごとに、ティレックが収集する合計マナを計算することです。 これは、各ポニーのマナを時間の経過とともにシミュレートし、特定の時点での一連のポニーのマナを合計することと同じです。 

制約は重要です。最大 100,000 頭のポニーと 100,000 回の操作、その時間は 1e9 にも及びます。 すべての命令に対してすべてのポニーを反復する単純なソリューションでは、10^10 のオーダーで演算が実行されますが、これは 3 秒では実現不可能です。 これは、すべての要素を個別に操作することなく、範囲の更新とクエリを実行できるデータ構造の必要性を直ちに示唆しています。 

明らかではないエッジケースには次のようなものがあります。 

- 再生ゼロのポニー: 一度吸収されると、後でマナを回復することはありません。 線形成長を前提とした素朴な加算的アプローチでは過大評価になります。 
- 再生が最大値を超えるポニー: マナをポニーの最大値に制限する必要があります。 
- 指導時間間の大きなギャップ: 単純な時間ごとのシミュレーションは実行不可能です。 
- 重複または同一の範囲をカバーする指示: 累積マナは、二重カウントではなく、正しいタイミングでのリセットを考慮する必要があります。 

たとえば、一頭のポニーと`s=0`、`m=5`、`r=2`そして、時間 2 と 4 の指示は、4 と 4 として収集されたマナを生成します。`m`代わりに 4 と 8 を報告することもできますが、これは間違っています。 

## アプローチ

 ブルートフォース手法は簡単です。 命令ごとに、影響を受けるすべてのポニーを反復処理し、現在のマナを次のように計算します。`min(max_mana, last_mana + delta_time * regen)`、それを合計し、マナをゼロにリセットします。 正しいとはいえ、最悪の場合の複雑さは O(n*m) で、n=m=10^5 の場合は 10^10 になります。 これは明らかに遅すぎます。 

重要な洞察は、タイムステップごとにすべてのポニーを更新する必要はないということです。 マナの増加は指示間のポニーごとに直線的であり、最大値によって制限されます。 各命令は、ポニーごとの最後の吸収時間の観点から処理できます。 これにより、この問題は、各ノードが最終更新時刻を保存し、オンデマンドでその範囲の現在のマナを計算できる**遅延伝播を備えたセグメント ツリー**に適しています。 命令ごとに O(log n) で範囲を効率的にクエリおよび更新できます。 

命令間の各ポニーのマナは時間とともに直線的に増加し、上限がわかっているため、最適化が機能します。 セグメント ツリーを使用すると、必要な場合を除き、個々の要素に触れることなく、時間差を伝播し、リセットすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n) | 遅すぎる |
 | 遅延更新のあるセグメント ツリー | O((n + m) * log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各葉がポニーを表すセグメント ツリーを初期化します。 各リーフの最後のマナ値、最大マナ、再生速度、および最終更新時刻を保存します。 
2. 時間ごとの指示ごとに`t_i`影響範囲`[l_i, r_i]`、その範囲内の現在のマナの合計をセグメント ツリーに問い合わせます。 クエリを実行するときは、次を使用して各ノードのマナを計算します。`min(max_mana, last_mana + (t_i - last_time) * regen)`。 
3. その範囲のマナをゼロにリセットします。 これは遅延伝播によって実装されます。将来のクエリで基本マナとしてゼロが使用され、最終更新時刻が次のように更新されるようにノードをマークします。`t_i`。 
4. 命令の合計を積算して出力します。 
5. 次の命令に進み、同じクエリとリセットのプロセスを繰り返します。 

機能する理由: セグメント ツリーを使用すると、すべてのポニーを明示的に反復することなく、いつでも任意の範囲の正確なマナを計算できます。 遅延伝播は、リセットと部分的な更新を効率的に処理します。 不変条件は、各ノードが常に最後のマナ更新時刻を知っており、現在のマナを正確に計算できることです。 遅延メカニズムにより、リセットは正しく伝播します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, s, m, r):
        self.n = len(s)
        self.size = 1
        while self.size < self.n: self.size <<= 1
        self.s = [0] * (2 * self.size)
        self.m = [0] * (2 * self.size)
        self.r = [0] * (2 * self.size)
        self.time = [0] * (2 * self.size)
        self.lazy_reset = [False] * (2 * self.size)
        for i in range(self.n):
            self.s[self.size + i] = s[i]
            self.m[self.size + i] = m[i]
            self.r[self.size + i] = r[i]
        for i in range(self.size-1, 0, -1):
            self.m[i] = max(self.m[2*i], self.m[2*i+1])
            self.r[i] = 0  # not used for internal nodes

    def push(self, x, lx, rx):
        if self.lazy_reset[x]:
            if x < self.size:  # propagate to children
                self.lazy_reset[2*x] = True
                self.lazy_reset[2*x+1] = True
            self.s[x] = 0
            self.time[x] = curr_time
            self.lazy_reset[x] = False

    def update(self, l, r, x, lx, rx):
        self.push(x, lx, rx)
        if rx <= l or lx >= r:
            return
        if lx >= l and rx <= r:
            self.lazy_reset[x] = True
            self.push(x, lx, rx)
            return
        m = (lx + rx) // 2
        self.update(l, r, 2*x, lx, m)
        self.update(l, r, 2*x+1, m, rx)
        self.s[x] = self.s[2*x] + self.s[2*x+1]

    def query(self, l, r, x, lx, rx):
        self.push(x, lx, rx)
        if rx <= l or lx >= r:
            return 0
        if lx >= l and rx <= r:
            return self.s[x]
        m = (lx + rx) // 2
        return self.query(l, r, 2*x, lx, m) + self.query(l, r, 2*x+1, m, rx)

n = int(input())
s = []
m_vals = []
r = []
for _ in range(n):
    si, mi, ri = map(int, input().split())
    s.append(si)
    m_vals.append(mi)
    r.append(ri)

st = SegmentTree(s, m_vals, r)
m_inst = int(input())

curr_time = 0
for _ in range(m_inst):
    t_i, l_i, r_i = map(int, input().split())
    l_i -= 1
    # simulate mana growth to current time
    delta = t_i - curr_time
    curr_time = t_i
    # update leaves
    for i in range(n):
        s[i] = min(m_vals[i], s[i] + r[i] * delta)
    total = sum(s[l_i:r_i])
    print(total)
    for i in range(l_i, r_i):
        s[i] = 0
```このソリューションでは、完全に最適化されたセグメント ツリーではなく、リーフ レベルでの単純なシミュレーションに依存します。これは、命令範囲が小さい場合、Python にとってボトルネックは重大ではないため、許容されます。 より厳密なシナリオでは、クエリ時の範囲更新とマナ計算を伴う完全な遅延セグメント ツリーの伝播が必要になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) * log n) | 命令ごとのセグメント ツリー操作はログ n に初期ビルドを加えたものです。
