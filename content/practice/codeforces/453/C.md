[CF 453C - リトルポニーと夏の太陽のお祝い](https://codeforces.com/problemset/problem/453/C)

 **評価:** 2200

 **解決時間:** 2 分 13 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 無向グラフと、頂点ごとに、ウォーク中にその頂点が何回出現する必要があるかのパリティが与えられます。 

ウォークは一連の頂点によって表されます。 シーケンス内の連続する頂点はエッジで接続する必要があります。 頂点とエッジは何度も再検討される可能性があります。 散歩はどこで始まり、どこで終わることもでき、さらには誰もいない場合もあります。 

頂点ごとに`v`、最後のウォークで偶数回出現する必要があるか、奇数回出現する必要があるかがわかります。 私たちのタスクは、訪問カウントが必要なすべてのパリティと一致する有効なウォークを構築することです。 そのようなウォークが存在しない場合は、次のように出力します。`-1`。 

グラフには以下が含まれます`10^5`頂点と`10^5`エッジ。 可能な歩行を探索しようとする解決策は、直ちに不可能になります。 すべての候補状態を保存するだけでも、組み合わせが爆発的に増加します。 この制約は、線形または線形に近いグラフの横断を強く示唆しています。 

最も重要な観察は、パリティのみが重要であるということです。 頂点が 1 回訪問されるか 17 回訪問されるかは関係なく、カウントが奇数であるか偶数であるかのみを考慮します。 2 つの訪問を追加するとモジュロ 2 が打ち消されるため、パリティに関する問題は多くの場合非常に単純になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

切り離されたグラフを考えてみましょう。```
4 1
1 2
1 0 1 0
```頂点 3 と 4 は、頂点 1 を含むコンポーネントから分離されています。頂点 3 には奇数パリティが必要です。 他のコンポーネントからは到達できないため、答えは不可能です。 

もう 1 つの微妙なケースは、すべてのパリティがゼロの場合です。```
3 2
1 2
2 3
0 0 0
```空の散歩は有効です。 常にどこかで DFS を開始するソリューションでは、不必要にアクセスが発生し、パリティ要件が破られてしまいます。 

3 番目の厄介な状況は、必要な奇数頂点の合計数が奇数である場合に発生します。```
2 1
1 2
1 0
```これは実際に解決可能です。 散歩`[1]`頂点 1 を 1 回訪問し、頂点 2 を 0 回訪問します。 

多くのグラフ パリティ問題では偶数の奇数頂点が必要ですが、その規則はオイラー パスのエッジ次数に適用されます。 ここでは頂点の出現数をカウントしているため、条件が異なります。 

## アプローチ

 ブルートフォース手法では、ウォークを構築し、すべての頂点のパリティ ベクトルを追跡しようとします。 各状態は、現在の頂点と、これまでに訪問したすべての頂点のパリティで構成されます。 

頂点が 30 しかないグラフであっても、`2^30`可能なパリティマスク。 と`10^5`頂点を含めると、状態空間は想像を絶するほど大きくなります。 この方向性は絶望的だ。 

重要な点は、ウォークを検索する必要がないということです。 DFS ツリーを使用して直接構築できます。 

ルートを選択して DFS を実行するとします。 DFS が子サブツリーの処理を終了して親に戻ると、そのサブツリーがすべてのパリティ要件をすでに満たしているかどうかがわかります。 

現在、頂点のパリティが間違っている場合は、その頂点への追加の訪問を 1 回記録することで、ローカルで修正できます。 そうすることで、その頂点のパリティのみが反転されます。 親に戻ると、DFS ウォークが再び親を訪問するため、親のパリティも変更されます。 

これは、頂点を葉から上に向かって処理することを示唆しています。 すべてのサブツリーは、制御がその親に戻る前に正しくすることができます。 パリティを自由に調整できない唯一の頂点は DFS ルートです。これは、その上に親がないためです。 

これにより、問題は接続されたコンポーネント上の建設的な DFS に変換されます。 パリティを修正しながら、実際のウォークを生成します。 

グラフが切れている可能性があります。 奇数パリティを必要とする頂点は、選択した DFS コンポーネントに属している必要があります。そうでない場合は、その頂点にアクセスすることはできません。 これは、必要なパリティ 1 を持つ頂点の中からルートを選択することで処理します。そのような頂点が存在しない場合、空のウォークはすでに有効です。

 ## アルゴリズムのチュートリアル

 1. グラフと必要なパリティ配列を読み取ります。 
2. 奇数パリティが必要な頂点の数を数えます。 
3. このカウントがゼロの場合、空のウォークを出力します。 すべての頂点は訪問回数が 0 回であるため、すでに偶数パリティを持っています。 
4. 必要なパリティが 1 である頂点を DFS ルートとして選択します。 
5. このルートから DFS を実行します。 
6. DFS が最初に頂点に入ったとき`v`、追加`v`応答シーケンスに追加し、現在のパリティ状態を反転します。`v`。 
7. 訪れたことのないすべての隣人のために`to`、その子を再帰的に処理します。 
8.子供から帰ったら追記`v`もう一度パリティ状態を反転します`v`。 

これは、DFS ツリーの端に沿って歩いて戻ることに相当します。 
9. すべての子が処理された後、現在のパリティを比較します。`v`必要なパリティを備えています。 
10. それらが異なる場合と`v`はルートではないので追加します`v`もう一度そのパリティを反転します。 次に、その親を追加し、親のパリティを反転します。 

これは、木の端をさらに 1 回横断することを表します。 修正します`v`パリティの不一致を親に押し上げながら永続的に実行します。 
11. それらが異なる場合、および`v`がルートであるため、ルートは不一致をどこにも押し付けることはできません。 建設は失敗します。 
12. DFS が終了したら、パリティ 1 を必要とするすべての頂点が訪問されたかどうかを確認します。 そうでない場合は、必要な頂点の一部が別の接続されたコンポーネント内にあるため、出力します。`-1`。 
13. それ以外の場合は、構築されたシーケンスを出力します。 

### なぜ効果があるのか

 DFS は、非ルート頂点の処理が完了すると、その頂点のパリティがその要件と正確に一致し、二度と変更されないという不変条件を維持します。 

葉が最初に処理されます。 リーフのパリティが正しくない場合は、さらに 1 回リーフを訪問し、その親に戻ると、リーフと親のみが反転されます。 葉は永続的に正しくなります。 

帰納的に、内部頂点を処理するとき、すべての子サブツリーはすでに固定されています。 現在の頂点に残っている不一致は、親エッジを通るトラバースを 1 つ追加することで、まったく同じ方法で修正できます。 

すべてのパリティの不一致は、DFS ツリーを通じて上に押し上げられます。 結局のところ、すべての矛盾は根本に蓄積されます。 ルートのパリティもその要件と一致する場合、すべての頂点は正しいことになります。 そうでない場合、最終的な不一致を吸収するルートの上に親がないため、その接続コンポーネント内には有効なウォークは存在しません。 

記録された頂点の連続するすべてのペアがグラフ エッジの横断に対応するため、結果として得られるシーケンスは常に有効なウォークになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    need = list(map(int, input().split()))

    root = -1
    for i in range(n):
        if need[i]:
            root = i
            break

    if root == -1:
        print(0)
        print()
        return

    visited = [False] * n
    cur = [0] * n
    ans = []

    sys.setrecursionlimit(300000)

    def dfs(v, parent):
        visited[v] = True

        ans.append(v + 1)
        cur[v] ^= 1

        for to in g[v]:
            if to == parent:
                continue
            if visited[to]:
                continue

            dfs(to, v)

            ans.append(v + 1)
            cur[v] ^= 1

        if cur[v] != need[v]:
            if parent == -1:
                return False

            ans.append(parent + 1)
            cur[parent] ^= 1

        return True

    ok = dfs(root, -1)

    if not ok:
        print(-1)
        return

    for i in range(n):
        if need[i] and not visited[i]:
            print(-1)
            return

    print(len(ans))
    print(*ans)

solve()
```配列`cur`構築されたウォークによって現在達成されているパリティを格納します。 頂点が応答シーケンスに追加されるたびに、そのパリティが反転します。 

頂点を入力すると 1 回の訪問が行われるため、すぐに頂点を追加して切り替えます。`cur[v]`。 

子から戻った後、ウォークは物理的に親に戻るため、親を再度追加します。 これは実際の走査と一致し、パリティを正しく更新します。 

最もデリケートな部分はミスマッチの修正です。 非ルート頂点が間違ったパリティで終了する場合、その親を追加します。 現在の頂点はすでにシーケンス内の最後の頂点であったため、親に移動すると、そのツリー エッジの追加の走査が 1 回実行されます。 これにより、子は固定されたまま、親のパリティが反転されます。 

根が特殊なんです。 他のすべての頂点はパリティの不一致を上方に押し上げる可能性がありますが、ルートにはそれを送信する場所がありません。 ルートが間違ったままの場合、解決策は存在しません。 

最終的な接続チェックは不可欠です。 必要な奇数頂点を含む切断されたコンポーネントには、選択したルートからは到達できません。 このチェックがないと、アルゴリズムは部分的な解を誤って出力します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | すべての頂点とエッジは一定の回数だけ処理されます。 
| スペース | O(n + m) | 隣接リスト、DFS 状態、および応答シーケンス |

 グラフに含まれるのは最大でも`10^5`頂点と`10^5`エッジ。 直線的な移動は制限時間内に簡単に収まります。 回答の長さは最大で次のように制限されます。`4n`、元のソリューションで使用された保証と一致します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    need = list(map(int, input().split()))

    root = next((i for i, x in enumerate(need) if x), -1)

    if root == -1:
        return "0\n\n"

    vis = [False] * n
    cur = [0] * n
    ans = []

    sys.setrecursionlimit(1000000)

    def dfs(v, p):
        vis[v] = True
        ans.append(v + 1)
        cur[v] ^= 1

        for to in g[v]:
            if to != p and not vis[to]:
                if not dfs(to, v):
                    return False
                ans.append(v + 1)
                cur[v] ^= 1

        if cur[v] != need[v]:
            if p == -1:
                return False
            ans.append(p + 1)
            cur[p] ^= 1

        return True

    if not dfs(root, -1):
        return "-1\n"

    for i in range(n):
        if need[i] and not vis[i]:
            return "-1\n"

    return str(len(ans)) + "\n" + " ".join(map(str, ans)) + "\n"

 ## 特殊なケース

 切り離されたグラフを考えてみましょう。```
4 1
1 2
1 0 1 0
```アルゴリズムは頂点 1 をルートとして選択し、頂点 1 と 2 のみを探索します。頂点 3 は依然として奇数パリティを必要としますが、未訪問のままです。 最終検証ではこれを検出し、出力します。`-1`。 

すべてのパリティがゼロに等しいとみなします。```
3 2
1 2
2 3
0 0 0
```必要なパリティ 1 を持つルートが存在しません。 アルゴリズムはすぐに空のウォークを出力します。 すべての頂点が出現する回数は 0 回であり、これは偶数です。 

孤立した奇数頂点を考えてみましょう。```
1 0
1
```DFS は唯一の頂点から開始し、それを 1 回記録して終了します。 そのパリティはすでに正しいです。 出力は単純に次のようになります。```
1
1
```このケースでは、ルート自体がエッジを横断することなく要件全体を満たしている可能性があることが確認されています。 

接続されていない 2 つの奇数頂点を考えてみましょう。```
2 0
1 1
```どちらの奇数の頂点がルートとして選択されても、もう一方の頂点には到達できません。 最終的な接続チェックが失敗し、アルゴリズムが出力します。`-1`。 これは、単一のウォークが 2 つの切断されたコンポーネントの頂点を訪問できないという事実を正しく捉えています。
