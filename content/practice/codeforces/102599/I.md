 ## 解決策
 ## 問題の理解

 可能な辺の長さを 3 つの範囲に分割する 4 つの順序付けられた境界があります。 最初の面`x`から選択する必要があります`[A, B]`、2番目の面`y`から`[B, C]`、そして3番目の面`z`から`[C, D]`。 範囲の順序により、選択されたすべてのトリプルはすでに次の条件を満たします。`x <= y <= z`。 有効な三角形に必要な残りの唯一の要件は、非縮退三角形不等式です。これは次のようになります。`x + y > z`。 

課題はトリプルの数を数える事です`(x, y, z)`これらの条件を満たしていること。 

境界の最大値は次のとおりです。`500000`。 すべてのトリプルを直接列挙すると、最大で次のようになります。`500000^3`1秒の制限時間内に収まる可能性をはるかに超えています。 すべてのペアを反復しても`(x, y)`は高すぎる`2.5 * 10^11`そんなペアたち。 間隔の長さの積に依存することを避ける必要があります。 

重要なエッジ ケースは、有効な三角形と無効な三角形の間の境界から発生します。 不注意な実装では、厳密な不等式を誤って処理したり、可能なすべてのトリプルが三角形であると想定したりすることがよくあります。 

たとえば、次の入力を使用します。```
1 1 1 3
```可能なトリプルは次のとおりです`(1,1,1)`、`(1,1,2)`、 そして`(1,1,3)`。 最初のもののみが有効です。`1 + 1 > 1`それは本当ですが、`1 + 1 > 2`そして`1 + 1 > 3`は誤りです。 答えは`1`。 使用する`>=`の代わりに`>`変性症例を誤ってカウントしてしまう可能性があります。 

もう 1 つの境界ケースは、すべての間隔に 1 つの値が含まれる場合です。```
500000 500000 500000 500000
```唯一可能な三角形は、`(500000,500000,500000)`、したがって、答えは次のとおりです`1`。 複数の値を持つ範囲に依存したり、間隔の長さで誤って除算したりするソリューションは、ここで失敗する可能性があります。 

最後のよくある間違いは、`z`に達します。 のために：```
1 2 3 4
```ペア`(2,3)`許可します`z = 3`そして`z = 4`ですが、これより大きな値は存在しません。 すべてを考慮するあらゆる式`z < x+y`でクリッピングせずに`D`数えすぎてしまうだろう。 

## アプローチ

 簡単な解決策は、可能な限りすべてのことを試してみることです`x`、可能な限り`y`、そして可能性のあるものを数えます`z`三角不等式を満たす値。 固定用`x`そして`y`、有効な`z`値はからのものです`C`に`min(D, x+y-1)`。 このアプローチは、三角形の定義を直接適用するため、正しいです。 

問題はペアの数です。 最初の 2 つの範囲には両方とも約を含めることができます。`500000`価値観、周囲の生成`250000000000`ペア。 各ペアを一定時間で処理しても終わりません。 

重要な点は、すべてのペアを個別に知る必要はないということです。 固定値の場合`z`、唯一の問題は何ペアかです`(x,y)`持っている`x+y > z`。 これにより、問題は、考えられる長方形内の合計を数えるという問題に変わります。`(x,y)`価値観。 

反対の量、つまり次の値とのペアの数を数えることができます。`x+y <= z`、ペアの合計数からそれを減算します。 両方の範囲をゼロから開始するようにシフトすると、これは点を数えるという古典的な問題になります。`(a,b)`長方形の中に`a+b`せいぜい何らかの値です。 包含-排他により、このカウントが定数時間で得られるため、可能なすべての処理を繰り返すことができます。`z`。 多くても`500000`このような値は管理が容易です。

 ## アルゴリズムのチュートリアル

 1. しましょう`n = B - A + 1`そして`m = C - B + 1`最初の 2 つの辺の範囲のサイズになります。 可能な総数は、`(x,y)`ペアは`n * m`。 
2. 最初の 2 つの辺の長さを 0 から始まる座標に変換します。 定義する`a = x - A`、 それで`0 <= a < n`、 そして`b = y - B`、 それで`0 <= b < m`。 

条件`x + y <= z`は次のようになります:```
a + b <= z - A - B
```この変換により、元の大きな値が削除され、標準的な境界グリッド数の問題が残ります。 
3. ヘルパー関数を作成する`triangle_count(k)`ペアの数を返します`(a,b)`満足する`a >= 0`、`b >= 0`、`a < n`、`b < m`、 そして`a+b <= k`。 

上限なし`a`そして`b`、非負のペアの数は次のとおりです。```
(k+1)(k+2)/2
```もし`a`到達する`n`、 シフト`a`までに`n`そして無効な領域を減算します。 同じことが当てはまります`b`、両方の制限に違反するペアは包含-除外によって追加されます。 
4. 可能な限りすべてのことを`z`から`C`に`D`、何個かを計算します`(x,y)`ペアを満たす`x+y <= z`。 ペアの合計数からこれを減算して、これで終わる有効な三角形の数を取得します。`z`。 
5. これらのカウントをすべて加算して、最終的な答えを求めます。 

なぜ効果があるのか:

 固定ごとに`z`、すべてのペア`(x,y)`次の 2 つのグループのうちの 1 つに正確に当てはまります。`x+y <= z`、非縮退三角形を形成できない、または`x+y > z`、そうなります。 ヘルパー関数は、四角形の境界に対する包含/除外を使用して、最初のグループを正確にカウントします。 合計ペア数から減算すると、そのペアに対する有効な選択肢が正確に残ります。`z`。 考えられるすべてを合計すると`z`各三角形には正確に 3 分の 1 の辺があるため、有効な三角形をすべて 1 回カウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B, C, D = map(int, input().split())

    n = B - A + 1
    m = C - B + 1

    def count_leq(k):
        def calc(t):
            if t < 0:
                return 0
            return (t + 1) * (t + 2) // 2

        return calc(k) - calc(k - n) - calc(k - m) + calc(k - n - m)

    total_pairs = n * m
    ans = 0

    for z in range(C, D + 1):
        not_triangles = count_leq(z - A - B)
        ans += total_pairs - not_triangles

    print(ans)

if __name__ == "__main__":
    solve()
```変数`n`そして`m`最初の 2 つの側面で考えられる選択肢を説明します。 配列を格納するのではなく長さとして保持することで、ソリューションで定数メモリを使用できるようになります。 

機能`calc(t)`は、無制限のグリッドの三角数公式です。 合計が以下の非負の値のペアをすべてカウントします。`t`。 負の場合はゼロを返す`t`どのペアに対しても制限が小さすぎる場合に対処します。 

の 4 つの用語`count_leq`包含除外補正です。 最初の項は、すべての非負のペアをカウントします。 2 番目と 3 番目はペアを削除します。`a`または`b`許容範囲を超えています。 4 番目は、2 回削除されたペアを元に戻します。 

ループオーバー`z`しかないという事実を利用します`D-C+1`最大辺の可能な値。 Python の整数はオーバーフローの問題を回避します。これは、答えが 32 ビット整数よりもはるかに大きくなる可能性があるため重要です。 

## 実用的な例

 最初のサンプルの場合:```
1 2 3 4
```シフトされた長方形には次のものがあります。`n = 2`、`m = 2`、合計ペア = 4。 

| z | k = z-A-B | x+y <= z | のペア 有効なペア |
 | --- | --- | --- | --- |
 | 3 | 0 | 1 | 3 |
 | 4 | 1 | 3 | 1 |

 合計は`3 + 1 = 4`、サンプル出力と一致します。 トレースは、最大側の各値がどのように個別に処理されるかを示します。 

2 番目のサンプルの場合:```
1 2 2 5
```ここ：`n = 2`、`m = 1`、合計ペア = 2。 

| z | k = z-A-B | x+y <= z | のペア 有効なペア |
 | --- | --- | --- | --- |
 | 2 | -1 | 0 | 2 |
 | 3 | 0 | 1 | 1 |
 | 4 | 1 | 2 | 0 |
 | 5 | 2 | 2 | 0 |

 答えは`2 + 1 = 3`。 この例は、より大きな`z`2 つの小さい辺の合計がその値を超えることができない場合、値は最終的に不可能になります。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    A, B, C, D = map(int, input().split())

    n = B - A + 1
    m = C - B + 1

    def count_leq(k):
        def calc(t):
            if t < 0:
                return 0
            return (t + 1) * (t + 2) // 2

        return calc(k) - calc(k - n) - calc(k - m) + calc(k - n - m)

    total = n * m
    ans = 0

    for z in range(C, D + 1):
        ans += total - count_leq(z - A - B)

    return str(ans) + "\n"

assert solution("1 2 3 4\n") == "4\n", "sample 1"
assert solution("1 2 2 5\n") == "3\n", "sample 2"
assert solution("500000 500000 500000 500000\n") == "1\n", "sample 3"

assert solution("1 1 1 3\n") == "1\n", "degenerate triangles must not count"
assert solution("1 1 2 2\n") == "1\n", "single valid combination"
assert solution("5 5 5 6\n") == "2\n", "equal sides and upper bound handling"
assert solution("1 500000 500000 500000\n") == "0\n", "largest side too large for most pairs"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 1 3`|`1`| 厳密な三角形不等式と退化の場合 |
 |`1 1 2 2`|`1`| 最小範囲と正確な境界 |
 |`5 5 5 6`|`2`| 等間隔、複数の扱い`z`値 |
 |`1 500000 500000 500000`|`0`| 広い範囲と不可能な三角形 |

 ## 特殊なケース

 縮退三角形の場合:```
1 1 1 3
```アルゴリズムは次のように反復します。`z = 1, 2, 3`。 のために`z = 1`、とのペアの数`x+y <= 1`はゼロなので、唯一のペア`(1,1)`カウントされます。 のために`z = 2`そして`z = 3`、小さい辺の合計が以下であるため、ペアは無効として分類されます。`z`。 最終的な答えは、`1`。 

単一値の最大値の場合:```
500000 500000 500000 500000
```シフトされた範囲は両方とも長さ 1 です。 唯一可能なことについては`z`、ヘルパー関数は無効なペアをカウントしません。`500000 + 500000 > 500000`。 合計のペア数は 1 なので、答えは 1 です。 

上限クリッピングの場合:```
1 2 3 4
```ペア`(2,3)`合計があります`5`, したがって、それは許可します`z`までの値`4`、指定された間隔を超えてはなりません。 アルゴリズムは決して`z`外`[C,D]`, したがって、上限は当然尊重されます。 最終的なカウントが残っている`4`。
