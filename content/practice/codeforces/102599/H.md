 ## 問題の理解

 円形の湖の周りに均等に家が配置されています。 がある`N`家と隣の家は距離があります`D`。 一つの家がスタート地点です。 ミハイルは順番を自分で決めて、すべての家を一度だけ訪問しなければなりません。 連続する 2 つの家の間を移動する場合は、円を周回する短いルートが使用されます。 目標は、合計歩行距離を最大化することです。 

入力には以下が含まれます`N`、家の数、および`D`、隣り合う家との間の距離。 出力は可能な最大の歩行距離です。 

主な問題は、可能な訪問注文の数が膨大であることです。 と`N`最大 100 万個の場合、すべての順列をチェックするアルゴリズムでさえ不可能です。 階乗探索は即座に除外され、二次解でも最大の場合で約 1 兆の演算を実行するため大きすぎます。 目的のソリューションは数学的パターンを導き出し、一定時間で実行する必要があります。 

いくつかのエッジケースでは、パターンを推測するだけの実装が壊れる可能性があります。 家が 3 軒あり、隣家との距離が 5 の場合、答えは次のようになります。`10`。 パスは 2 回移動する必要があり、すべての家のペアが三角形上で隣接しているため、両方の長さは 5 にすることができます。 最大ジャンプが常に次であると仮定する解決策は、`floor(N/2)`ここで移動数を掛けると正しい結果が得られますが、そのアイデアは偶数の場合には失敗します。`N`。 

たとえば、次の入力を使用します。```
6 10
```可能な単一ジャンプの最大値は`3 * 10`、しかし、反対側の家を繰り返し取った後、残りのポジションがより短い移動を強制するため、そのようなジャンプを5回行うことはできません。 正しい答えは、`130`、 ない`150`。 欠けている洞察は、`N`最適なルートの構造を変更します。 

もう 1 つの境界ケースは次のような場合です。`N`奇数です。 入力の場合:```
5 1
```答えは`8`。 不用意に実装すると、偶数ケースの式を使用して、より小さい値を取得しようとする可能性があります。 奇数の大きさの円上で、最大距離を繰り返しジャンプしてすべての家を訪問することができます。 

## アプローチ

 直接的なアプローチは、可能なすべての訪問順序を試すことです。 の順列ごとに、`N - 1`友人の家では、歩行をシミュレートし、連続する家間の最短の円形距離を追加します。 考えられるすべてのルートがチェックされるため、これは正しいです。 ただし、置換の数は、`(N - 1)!`の値が小さい場合でも不可能になります。`N`。 100 万戸の住宅の場合、このアプローチは実現不可能です。 

円の構造により、より強力な観察が可能になります。 重要なのは、それぞれのジャンプがどれだけ遠くまで飛べるかということだけです。 奇数の家の場合、次のようにします。`N = 2k + 1`。 正確にジャンプする`k`円の周りの家は常に新しい家に移動し、追加を繰り返します`k`モジュロ`N`どの家にも訪問するので、`k`そして`2k + 1`は互いに素である。 したがって、それぞれの`N - 1`動きには長さがある場合があります`k`。 

偶数の家の場合、`N = 2k`。 可能な最大ジャンプは、`k`、向かいの家に到着。 このようなジャンプを使用した後、次の便利なジャンプ パターンが長さを交互に切り替えます。`k`そして長さ`k - 1`。 順序のあるルート```
0, k, 1, k+1, 2, k+2, ...
```各家を訪問します。 含まれています`k`長さのあるジャンプ`k`そして`k - 1`長さのあるジャンプ`k - 1`, これにより、可能な最大の合計が得られます。 

これが最適である理由は、すべての移動が円上の可能な最大距離によって制限されるためです。 奇妙なケースでは、すべての移動で上限に達します。 偶数の場合、逆方向のジャンプを多用すると家を再訪問することになるため、残りのジャンプでは少なくとも 1 単位の距離を失う必要があります。 交互構造では、まさに避けられないユニットが失われます。

 ## アルゴリズムのチュートリアル

 1.読む`N`そして`D`。 まず、隣接するギャップの単位で最大距離を計算し、次に次の値を掛けます。`D`最後に。 
2. かどうかを確認します。`N`奇数です。 もし`N = 2k + 1`、すべての動きには長さがある可能性があります`k`、そして、あります`2k`動く。 の単位での答え`D`は`2k * k`。 
3. もし`N`は偶数なので、次のように書きます`N = 2k`。 最適なルートは、`k`長さの動き`k`そして`k - 1`長さの動き`k - 1`。 の単位での答え`D`は`k * k + (k - 1) * (k - 1)`。 
4. 結果を乗算します。`D`そしてそれを印刷します。 Python の整数は任意の精度であるため、可能な最大値には特別な処理は必要ありません。 

機能する理由: 2 つの家間の移動は円の半分に制限されます。 奇数の場合`N`、最大ジャンプ長は`k`、および追加するモジュラー シーケンス`k`毎回すべての頂点に到達するため、すべての移動で上限が達成されます。 偶数の場合`N`、最大ジャンプ長は`k`、ただし、反対側の頂点はペアを形成します。 反対側のジャンプを行った後、次のジャンプは競合を生じずに別の未使用の反対側の頂点に再度到達することはできません。 交互の構造では、ロングジャンプの可能な最大数に達し、残りのすべての動きを利用可能な最大のショートジャンプで埋めます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())

    if n % 2 == 1:
        k = n // 2
        ans = 2 * k * k
    else:
        k = n // 2
        ans = k * k + (k - 1) * (k - 1)

    print(ans * d)

if __name__ == "__main__":
    solve()
```変数`k`隣接する家の間の隙間で測定された、ジャンプ可能な最大長さを表します。 奇数の場合`N`、まさにあります`2k`移動すると、すべての移動がその距離に到達します。 偶数の場合`N`, この式では、長いジャンプと、円形の配置によって強制されたわずかに短いジャンプが別々にカウントされます。 

の乗算`D`問題の組み合わせ部分は交差するギャップの数にのみ依存するため、問題は最後まで延期されます。 これにより、式の検証も容易になります。 配列インデックスやシミュレーションがないため、実際のルートの構築による境界エラーは発生しません。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, d = map(int, sys.stdin.readline().split())

    if n % 2:
        k = n // 2
        ans = 2 * k * k
    else:
        k = n // 2
        ans = k * k + (k - 1) * (k - 1)

    sys.stdin = old_stdin
    return str(ans * d)

assert solve("4 1\n") == "5"
