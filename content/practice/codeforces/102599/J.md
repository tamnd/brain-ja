 ## 解決策
 ## 問題の理解

 柱の高さを豊富に取り揃えております。 目標は、最終的な高さを 1 つ選択することです`x`すべての柱を変形して、その高さが正確になるようにします`x`。 柱コストの増加`A`追加したレンガごとに、レンガを削除するコストがかかります`R`取り外されたレンガごとに、レンガをある柱から別の柱に移動するコストがかかります`M`。 

出力は、最終的な高さのすべての選択肢の中で可能な最小の総コストです。 

到達できる柱の数`100000`したがって、レンガの最大数まで可能な限りあらゆる高さを試すのは現実的ではありません。 高さは次のように大きくすることができます`10^9`これにより、高さの数値範囲に応じたアプローチが除外されます。 に近いアルゴリズムが必要です`O(N log N)`または`O(N)`候補の高さが多すぎると反復処理が実行可能な操作を超えてしまうため、ソート後に実行されます。 

よくある間違いは、最終的な身長が平均値または中央値である必要があると仮定することです。 運用コストによって答えは変わります。 たとえば、レンガの追加が非常に安価な場合は、レンガの除去に費用がかかるため、最適な高さは平均を超える可能性があります。 

別のエッジケースは、レンガを移動する方が、個別に削除して追加するよりも安価である場合に発生します。 考慮する：```
3 100 100 1
1 3 8
```正しい答えは、`4`。 レンガの総数は`12`なので、すべての柱の高さを作る`4`レンガを高さの柱から移動するだけで済みます`8`高さの柱まで`1`。 独立した追加と削除のみを比較するソリューションでは、この低コストの転送を見逃してしまいます。 

2 番目のエッジ ケースは、1 つの操作方向が自由な場合です。 例えば：```
2 0 100 100
0 5
```正しい答えは、`0`。 空柱を高く上げる`5`費用はかからないので、目標の高さは`5`無料です。 一部のレンガを移動または削除する必要があると常に想定する不用意な実装は、プラスのコストを生み出すことになります。 

3 番目のエッジ ケースは、すべての柱がすでに同じ高さである場合です。```
3 10 20 5
7 7 7
```正しい答えは、`0`。 アルゴリズムは現在の高さを候補として考慮し、不必要な操作の実行を回避する必要があります。 

## アプローチ

 簡単な解決策は、可能な限り最終的な高さを試してみることです。 候補者の身長ごとに`x`、追加する必要があるレンガの数と削除する必要があるレンガの数を数えます。 次に、差異を修正するコストを計算します。 考えられるすべての答えがチェックされるため、これは正解です。 

ただし、最大高さは次のとおりです。`10^9`、可能な限りすべてをスキャンします`x`値には最大で`10^9`評価。 評価は1つでもかかります`O(N)`、結果として約`10^14`限界をはるかに超えた最悪の場合の操作。 

重要な観察は、コスト関数が凸であるということです。 目標の高さを 1 つ増やすと、追加または削除する必要があるレンガの数が徐々に変化します。 総コストは最適値に達するまで減少し、その後増加します。 整数範囲にわたる凸関数は、傾きの二分探索を使用して最小化できます。 

固定ターゲット高さの場合`x`、以下の高さのすべての柱`x`必要な追加と上記のすべての柱に貢献します`x`削除に貢献します。 これら 2 つの量を効率的に計算できれば、あらゆるもののコストを評価できます。`x`素早く。 

高さをソートすると、二分探索を使用して、候補の高さより下にある柱の数を見つけることができます。 プレフィックス合計を使用すると、毎回すべての柱を反復処理することなく、不足しているレンガまたは余分なレンガの合計数を計算できます。 次に、答えの高さを二分探索します。 

ブルートフォース手法は、考えられるすべてのターゲットをチェックするため機能しますが、範囲が大きすぎるため失敗します。 コスト曲線が凸であるという観察により、数十億の候補からの検索が約 31 チェックに減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NH)、H は最大高さ | お(1) | 遅すぎる |
 | 最適 | O(N log N + log(H) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 柱の高さをソートし、プレフィックス合計配列を構築します。 プレフィックスの合計により、柱のプレフィックスの合計高さを即座に見つけることができるため、柱の数に関係なくコスト計算が可能になります。 
2. 選択した目標高さのコストを計算する関数を定義します。`x`。 ソートされた配列に対して二分検索を使用して、少なくとも高さの最初の柱を見つけます。`x`。 この位置より前の柱にはレンガを追加する必要があり、残りの柱には取り除くか移動する必要がある余分なレンガがあります。 
3. 下側の不足しているレンガの数と上側の過剰なレンガの数を計算します。 これら 2 つの値は、高さに到達するために必要な作業量を表します。`x`。 
4. 可能な限り動くレンガを使用してください。 レンガを 1 つの柱から取り外して別の柱に追加すると、両方の操作を同時に満たすことができます。 このような移動の数は、不足しているレンガ数と過剰なレンガ数の最小値です。 
5. 移動コストを固定する`min(M, A + R)`。 レンガを移動する方が、レンガを削除して新しいレンガを追加するよりも費用がかかる場合、レンガを移動する理由はありません。 
6. 目標高さを二分探索します。 コストを比較してください`mid`そして`mid + 1`。 コストが減少している場合は、検索範囲を上に移動します。 それ以外の場合は、下に移動します。 最小のコストは、傾きが変化する点の近くで見つかります。 

これが機能する理由: ターゲットの高さを選択するコストは凸型になります。 ターゲットの高さを左から右に移動すると、予測可能な方向にコストが変化します。最適化の前では、ターゲットを増加すると、追加が増加するよりもコストのかかる除去が減少し、最適化後はその逆が起こります。 二分探索により遷移点が見つかります。 固定ターゲットの場合、考えられるすべてのブリック転送が有益な場合に最初に使用され、残りの差分が追加または削除によって処理されるため、コスト計算は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, R, M = map(int, input().split())
    h = list(map(int, input().split()))

    h.sort()
    pref = [0]
    for x in h:
        pref.append(pref[-1] + x)

    M = min(M, A + R)

    def cost(x):
        import bisect

        idx = bisect.bisect_left(h, x)

        need = x * idx - pref[idx]
        extra = (pref[n] - pref[idx]) - x * (n - idx)

        move = min(need, extra)
        need -= move
        extra -= move

        return move * M + need * A + extra * R

    left = h[0]
    right = h[-1]

    while left < right:
        mid = (left + right) // 2
        if cost(mid) <= cost(mid + 1):
            right = mid
        else:
            left = mid + 1

    print(cost(left))

if __name__ == "__main__":
    solve()
```ソートされた配列とプレフィックス合計配列は、アルゴリズムの最初のステップに対応します。 ソート後、候補の高さごとに柱が下位グループと上位グループに分割されるため、ソートされた位置に対する二分探索が可能です。 

の`cost`関数はまず次のようにして分割点を見つけます。`bisect_left`。 表現`x * idx - pref[idx]`目標の下に不足しているレンガの数を計算します。 表現`(pref[n] - pref[idx]) - x * (n - idx)`ターゲット上の余分なレンガを計算します。 

転送計算は追加と削除の前に処理されます。 余分なレンガを 1 つ移動すると、同時に不足しているレンガが 1 つ修正されるため、この順序は重要です。 有効な手の数は小さい側によって制限されるため、`min(need, extra)`が正しい量です。 

移動コストは次のように置き換えられます。`min(M, A + R)`なぜなら、レンガを個別に作成して削除するよりもコストがかかる移動は決して役に立たないからです。 

Python の整数はオーバーフローしません。これは、総コストが約 100 ドルに達する可能性があるため、必要です。`10^18`。 二分探索では、`h[0]`そして`h[-1]`この間隔の外側にあるターゲットは、最も近い境界よりも優れていることはありえないため、境界として使用します。

## テストケース```python
import sys
import io
import bisect

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, A, R, M = map(int, input().split())
    h = list(map(int, input().split()))

    h.sort()
    pref = [0]
    for x in h:
        pref.append(pref[-1] + x)

    M = min(M, A + R)

    def cost(x):
        idx = bisect.bisect_left(h, x)
        need = x * idx - pref[idx]
        extra = pref[n] - pref[idx] - x * (n - idx)
        move = min(need, extra)
        return move * M + (need - move) * A + (extra - move) * R

    l, r = h[0], h[-1]
    while l < r:
        m = (l + r) // 2
        if cost(m) <= cost(m + 1):
            r = m
        else:
            l = m + 1

    return str(cost(l))

""") == "12"

 ## 特殊なケース

 安価なムーブメントの場合:```
3 100 100 1
1 3 8
```このアルゴリズムは、最適な高さの周囲の候補の高さを評価します。 高所で`4`、不足しているレンガが 3 つと余分なレンガが 4 つあります。 3 回移動すると、レンガが最も高い柱から最も低い柱に移動され、取り除かなければならないレンガが 1 つ残ります。 費用は`3 * 1 + 1 * 100 = 103`その高さの場合、しかし高さ`3`より良いです: 2 回の移動で最初の柱が固定され、5 つのレンガを取り除く必要が残ります。`2 + 5 = 7`。 二分探索は正しい最小値に達します`4`凸コスト関数を介して。 

無料追加の場合:```
2 0 100 100
0 5
```目標の高さ`5`空の柱が 1 つあり、レンガが 5 つ必要ですが、余分なレンガは必要ありません。 追加コストはゼロなので、総コストはゼロです。 欠落カウントと追加カウントの不均衡が許容されるため、コスト関数がこのケースを処理します。 

等しい柱の場合:```
3 10 20 5
7 7 7
```高さで可能なすべての修正をカウントします`7`はゼロです。 関数はゼロを返し、バイナリ検索は、この既存の高さに達するまで、答えを有効範囲内に保持します。 このソリューションは不必要な操作を強制しません。
