 ## 解決策
 ## 問題の理解

 私たちはエクスプローラーのコレクションを持っており、各エクスプローラーには値があります。`e`その探索者を含むグループに必要な最小人数を記述します。 グループは、すべてのメンバーの要件が最終的なグループ サイズによって満たされる場合にのみ有効です。 タスクは、いくつかのエクスプローラーを選択し、それらを可能な最大数の有効なグループに分割することです。 一部の探索者は、有効なグループに配置できない場合、無視される場合があります。 

入力には、いくつかの独立したテスト ケースが含まれています。 各テスト ケースについて、配列はすべてのエクスプローラーの経験不足の値を表します。 出力は、その配列から作成できるグループの最大数です。 

すべてのテスト ケースにわたるエクスプローラーの合計数は最大で`3 * 10^5`。 これは、ソリューションが各エクスプローラーを少数回だけ処理する必要があることを意味します。 可能なパーティションの数が指数関数的に増加するため、多くの異なるグループの組み合わせを試みるアプローチはすぐに不可能になります。 たとえ`O(N^2)`単一のテスト ケースが到達すると、ソリューションは遅すぎます。`200000`エクスプローラーであるため、目的のソリューションは次のものに近い必要があります。`O(N log N)`または`O(N)`。 

いくつかのケースでは、簡単に誤って処理されてしまいます。 すべての探索者に要件がある場合`1`、各エクスプローラーは単独で実行でき、答えは配列のフルサイズになります。 

例えば：```
1
4
1 1 1 1
```正しい出力は次のとおりです。```
4
```常に可能な限り最大のグループを最初に構築しようとする不用意な解決策では、サイズ 4 の 1 つのグループが作成され、4 つのグループを作成する機会が失われる可能性があります。 

もう 1 つの注意が必要なケースは、大きな要件が小さな要件と一緒に現れる場合です。 

例：```
1
5
2 3 1 2 2
```正しい出力は次のとおりです。```
2
```大きな要件を持つエクスプローラーをすぐに破棄する貪欲な方法では、要件を持つ 1 つのエクスプローラーが存在するという事実を見逃す可能性があります。`3`他の 2 人のエクスプローラーと一緒に使用して、有効なグループを形成できます。 

最後のエッジケースは、要件が残りの使用可能なエクスプローラーの数より大きい場合です。 

例：```
1
3
1 1 5
```正しい出力は次のとおりです。```
2
```5 人のグループを必要とする探索者を含めることはできませんが、他の 2 人の探索者はサイズ 1 の 2 つのグループを形成できます。 

## アプローチ

 直接的な総当たりソリューションでは、エクスプローラーをグループに割り当てるさまざまな方法を試し、最良の結果を維持します。 これは概念的に機能します。考えられるすべての有効な配置が考慮され、最適な配置が見つかる必要があるためです。 問題は、可能な割り当ての数が非常に急速に増加することです。 と`N`エクスプローラーでは、可能なパーティションの数が確認できる数をはるかに超えています。 検索を多くの考えられるグループ境界に限定したとしても、非常に多くの操作が必要となり、おおよその範囲に達します。`O(N^2)`現実的な実装ではさらに悪いことになります。 

有用な観察は、何がグループを有効にするのかを見ることから得られます。 グループにサイズがある場合`s`、その中のすべての探索者は必ず持っている必要があります`e <= s`。 これは、要件が小さい探索者は配置が容易である一方、要件が大きい探索者は周囲により多くのメンバーが必要であることを意味します。 

要件を並べ替えることで、難易度の高い順に探索者を処理できるようになります。 分類した後、最小の要件から順にグループを構築できます。 現在のグループに収集された探索者の数を数え続けます。 この数が現在のエクスプローラーの要件に達すると、グループを閉じて 1 つの有効なグループとしてカウントできます。 

この貪欲な選択が機能する理由は、小さな要件では、より大きなグループを待ってもメリットが得られないためです。 グループに現在のエクスプローラーに十分な人数がすでに含まれている場合、グループを作成すると、それらのエクスプローラーが完成したグループとしてすぐに保存され、後のエクスプローラーは将来のグループを形成するために残されます。 より大きな要件は、より多くの潜在的なグループ メンバーが利用可能になった後に検討されます。 

ブルート フォースはすべての有効なパーティションを探索するため機能しますが、可能性が多すぎるため失敗します。 ソートされた順序によって、グループが有効になる正確な瞬間が明らかになるという観察により、パーティション検索を 1 回の貪欲スキャンに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | 検索戦略によっては指数関数的または悪化する | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(1) 並べ替え以外の追加 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 探索者の要件を降順に並べ替えます。 有効なグループ メンバーになるために必要な人数が少ないため、小規模な要件を最初に処理する必要があります。 

2. ソートされた配列を維持しながら走査します。`current`、可能性のあるグループに対して現在収集されている探索者の数。 

3. 現在のエクスプローラーを`current`。 もし`current`この探索者の要求以上になると、グループを形成して答えを増やしていきます。 

4.リセット`current`これらのエクスプローラーはすでに使用されており、別のグループに貢献できないため、グループの形成後にゼロに設定されます。 

重要な決定は、グループが有効になったらすぐにグループを閉じることです。 現在のエクスプローラーに要件があるとします。`x`そして私たちはすでに持っています`x`グループ内の探索者。 このグループに追加のエクスプローラーを保持すると、さらにグループを作成できなくなりますが、ここで終了すると、残りのエクスプローラーに別の有効なグループを作成する最良の機会が与えられます。 

なぜ効果があるのか:

 ソートされた配列の接頭辞を処理した後、アルゴリズムはその接頭辞のみを使用して、可能な最大数のグループを作成します。 完成したグループは、そのサイズが少なくともその内部のすべての処理されたエクスプローラーの要件である場合にのみ作成されたため、有効です。 アルゴリズムがグループを閉じるとき、将来のグループでこれらのエクスプローラーのいずれかを使用すると、グループの数を増やすことなく、後のエクスプローラーから利用可能なユーザーが削除されるだけなので、グループをすぐに終了することが常に最適です。 エクスプローラーをソートされた順序で処理すると、チェックされたすべての要件が現在のグループ内で最大の要件であることが保証され、妥当性を証明するには十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        e = list(map(int, input().split()))

        e.sort()

        groups = 0
        current = 0

        for value in e:
            current += 1
            if current >= value:
                groups += 1
                current = 0

        ans.append(str(groups))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```このソリューションでは、スキャンが貪欲証明で使用される順序に従うように、まず要件を並べ替えます。 変数`current`未完了のグループに対して収集された探索者の数を保存します。 各探索者はこのカウントを 1 つずつ増やします。 

比較`current >= value`は、グループを閉じるための正確な条件です。 配列はソートされているため、`value`は現在のグループ内で発生する最大の要件であるため、満たされるということは、そのグループ内のすべての探索者が満たされることを意味します。 

リセットする`current`ゼロにすることが不可欠です。 これを忘れると、同じ探索者が複数のグループに貢献し、不可能な答えを導き出す可能性があります。 

この問題では Python の整数はオーバーフローせず、合計入力サイズは制限内ですべてのテスト ケースを並べ替えるのに十分な大きさです。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.readline
    t = int(data())
    out = []

    for _ in range(t):
        n = int(data())
        arr = list(map(int, data().split()))
        arr.sort()

        groups = 0
        current = 0

        for x in arr:
            current += 1
            if current >= x:
                groups += 1
                current = 0

        out.append(str(groups))

    sys.stdin = old_stdin
    return "\n".join(out)

""") == """3

 ## 特殊なケース

 すべての探索者が要件 1 を持っている場合:```
1
4
1 1 1 1
```ソートされた配列は変わりません。 エクスプローラーごとにカウンターが 1 に達するため、アルゴリズムはグループを 4 回閉じて 4 を返します。 可能な限り最大のグループを優先する戦略では、誤ってグループが返されます。 

混合要件の場合:```
1
5
2 3 1 2 2
```並べ替えると次のようになります。```
1 2 2 2 3
```最初の探索者は単独でグループを作成します。 次の 2 人の探索者は、サイズ 2 のグループを作成します。 残りの 2 人の探索者は要件 3 を満たすことができないため、無視されます。 答えは 2 で、グループの最大数に一致します。 

不可能な大規模な要件の場合:```
1
3
1 1 5
```ソートされた配列は次のとおりです。```
1 1 5
```最初の 2 人の探索者は、それぞれサイズ 1 のグループを作成します。 最後の探索者はカウンターを 1 に増やしますが、要件は 5 であるため、グループは作成されません。 アルゴリズムは 2 を返します。3 番目のエクスプローラーは有効なグループに所属できないため、これが最適です。
