 ## 問題の理解

 これは出力のみの構築問題です。 読み取る入力ファイルがありません。 このタスクは、小さなスタックベースの言語で書かれたプログラムを印刷することです。 生成されたプログラムは、後で隠れた初期スタック上でジャッジによって実行されます。 

初期スタックには整数カウントが含まれます`N`一番下、そしてそれから`N`その上の負でない整数。 印刷されたスタック プログラムの目標は、それらの合計を残すことです。`N`実行後のスタックの一番上の値。 他の値は答えの下に残る可能性があるため、プログラムは先頭の要素が正しいことを保証するだけで済みます。 

マシンは意図的に制限されています。 メモリ内の任意の位置にはアクセスできず、上位のいくつかのスタック要素にのみアクセスできます。 使用可能な命令により、現在のスタック状態に基づいて、算術演算、複製、スワッピング、およびループが可能になります。 重要な制約は実行制限です。プログラムは次の時間内に終了する必要があります。`(N + 22)^2`すべての命令に対して実行された`0 <= N <= 100`。 これにより、すべての値についてスタック全体を繰り返しスキャンするソリューションが除外されます。 およそ 2 次の動作を持つ構造は許容されますが、3 次の増加を伴うものは制限を超えます。 

主な困難は次のような事実から来ています。`N`がゼロになる可能性があり、その値がゼロになる可能性があります。 カウントを保持せずに先頭の値をループ条件として使用するソリューションでは、データ値と残りの要素数が混同される可能性があります。 たとえば、スタックが次で始まる場合、`0`ただ、正しい結果は`0`ただし、先頭がゼロ以外かどうかをチェックするループは決して実行されず、答えとして値を残さない可能性があります。 もう 1 つの注意が必要なケースは、単一の要素です。 スタックに次の内容が含まれている場合`1, 5`、答えは次のようになります。`5`、および上に常に 2 つの数値があると想定する実装`N`無効なスワップまたは追加が実行される可能性があります。 3 番目のエッジ ケースは、値がすべてゼロです。 のために`3, 0, 0, 0`、ループではなく値によって制御されます。`N`すぐに停止して誤って戻ってしまう`0`目的の構造を消費する前に。 

## アプローチ

 この問題を直接考える方法は、繰り返しスタックから数値を削除し、その合計を累積することです。 マシンにランダム アクセスがある場合、これは簡単です。答えを含む変数を保持し、すべての要素を追加します。 難しいのはカウンターを維持することです`N`値を移動しながら。 

最初の試みは、下部のカウンタを使用し、上部の値をアキュムレータに繰り返し移動することです。 マシンはこれを行うことができますが、カウンタが使用可能な状態を維持できるように、反復のたびにスタックを再配置する必要があります。 値は 100 個存在する可能性があるため、スタック移動の数は制限されますが、アプローチの設計が不十分だと、データの前後の移動に多くの命令が費やされる可能性があります。 約コストがかかるネストされた走査`N`それぞれの操作`N`要素は約に達します`10000`ここではまだ許容できる操作ですが、不必要なオーバーヘッドが大きくなると二次境界に違反する危険があります。 

重要な観察は、スタックに残りの値の数がすでに格納されていることです。 カウンタの隣にアキュムレータを維持し、ループ反復ごとに 1 つの入力数値を正確に消費できます。 スタックを正しく配置した後、すべてのループ条件でカウンタの位置がチェックされるため、カウンタが値と混同されることはありません。 

施工にはちょっとした工夫がされています。 まずゼロ アキュムレータを作成します。 次に、カウンタが正の間、現在の最高値をアキュムレータに加算し、カウンタをデクリメントします。 このループの後は、アキュムレータと消費されたカウンタのみが残るため、最後のステップで不要な値が削除され、残っているスタック値が必要な最上位の結果に結合されます。

 | 最適 | O(N²) | O(N) スタックの深さ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. スタックにゼロを置き、先頭の要素を再配置して、ゼロが累計値になるようにします。`N`アクセス可能な状態を保ちます。 合計演算には中立値が必要であるため、アキュムレータはゼロから開始する必要があります。 
2. カウンタがゼロでない間、繰り返します。 必要なスタック要素をコピーして交換し、カウンターを失わずに現在の数値を追加できるようにします。 値を加算した後、カウンタを 1 つデクリメントします。 各反復では、入力値が 1 つだけ消費されます。 
3. すべての値が処理されたら、残ったカウンター情報を削除し、必要な合計だけが上部に表示されるまで残りのスタック値をマージします。 
4. アキュムレータを最上位のスタック要素のままにします。 裁判官はこの最終的な特性のみをチェックするため、暫定的な帳簿上の値は、答えを下回っている限り問題になりません。 

これが機能する理由: メイン ループ中の不変条件は、アキュムレータには既に削除されたすべての値の合計が含まれているのに対し、カウンタは未処理の元の値の数を表すことです。 最初はアキュムレータはゼロで、カウンタは`N`。 各反復では、正確に 1 つの値が削除され、それがアキュムレータに追加され、不変条件が維持されたままカウンタが減少します。 カウンタがゼロに達すると、元の値はすべて 1 回だけ加算されるため、アキュムレータは必要な合計と等しくなります。 

## Python ソリューション

 以下の Python プログラム自体が、必要な回答ジェネレーターです。 スタック マシン用の有効なプログラムを出力します。```python
import sys
input = sys.stdin.readline

program = """PUSHZ
SWAP2
WHILE NOT EZ DO
BEGIN
COPY
SWAP3
ADD
SWAP2
DEC
END
POP
"""

sys.stdout.write(program)
```生成されたプログラムは、アキュムレータの作成から始まります。`SWAP2`アキュムレータを元のカウントに対して正しい位置に配置します。 ループ条件は、カウントがゼロに達したかどうかをチェックします。 ループ内では、`COPY`、`SWAP3`、 そして`ADD`次の値が累計に含まれるように、上位の要素を再配置します。`DEC`残りのカウントを更新します。 

決勝戦`POP`ループの終了後に古いカウンターを削除します。 アキュムレータは反復ごとに保持されるため、答えはスタックに残ります。 

ターゲット マシンは任意のサイズの整数をサポートしているため、ジェネレーターには整数のオーバーフロー処理はありません。 また、これは出力のみの問題であるため、Python コードは入力を処理しません。

 | --- | --- | --- | --- |
 | イニシャル | 3 | なし | 4、7、2 |

 アキュムレータは、各反復で削除された値だけ増加します。 最終的な値は`13`、すべての元の要素の合計です。

 | 最終回 | 削除されました | 0 | なし |

 ループは安全にスキップされ、プログラムは有効なゼロ結果を残します。

 ## 特殊なケース

 のために`N = 0`、プログラムはすぐにゼロカウンターを認識します。 ループ条件は失敗するため、無効なポップまたは算術演算は発生しません。 最後のクリーンアップでは、初期化されたゼロ アキュムレータが答えとして残ります。 

のために`N = 1`価値のあるもの`5`、最初で唯一の反復では単一の値が消費され、それがアキュムレータに追加され、カウンターが 1 から 0 に減ります。 プログラムは、欠落している 2 番目の値にアクセスしようとすることはありません。 

のために`N = 3`価値観を持って`0, 0, 0`、ループは合計される値ではなくカウンターによって制御されます。 すべての値がゼロであっても、ループは 3 回実行され、停止する前にすべての要素が消費されます。 

## よくある間違い

 よくある間違いは、追加されている現在値をループ条件として使用することです。 これは、入力値がゼロであることが許可されているため、有効な要素が終了状態と同一に見える可能性があるため、失敗します。 

もう 1 つの間違いは、値を移動しているときにカウンターを破壊することです。 マシンには残りの要素の数を回復する方法がないため、ループが早期に停止するか、実行時エラーが発生するまで継続する可能性があります。 

3番目の間違いはそれを忘れることです`N`それ自体は初期スタックの一部です。 最終的な答えは一番上にあれば十分ですが、プログラムは処理中にカウントとデータ値を区別するのに十分な構造を保持する必要があります。
