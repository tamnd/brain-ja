 ## 問題の理解

 直線道路が、$n+1$チェックポイント。 各セグメントにはランプが付いています。 各ランプは動作しているか壊れていて、動作しているランプのみがそれぞれのセグメントを照らします。 セグメントはランプが点灯している場合にのみ使用できます。 

時間の経過とともに、ランプの状態は変化します。操作ごとに、1 つのランプがオンとオフの間で切り替わるか、接続性について質問されます。 クエリは、チェックポイントから移動できた開始時から現在時刻までの時間を尋ねます。$a$チェックポイントへ$b$、つまり、その瞬間、それらの間のすべてのセグメントが点灯したことを意味します。 

したがって、各クエリは現在の状態だけを尋ねるのではなく、時間の接頭語を尋ねます。 概念的には、時間の経過とともにクエリ間隔ごとにバイナリ配列を維持します。$[a, b)$、この配列の過去のバージョンで、その間隔ですべての値が 1 に等しいものがいくつあるかを数えたいとします。 

この制約は、セグメントと操作の数が両方とも多く、最大で典型的な値に達することを意味します。$2 \cdot 10^5$Codeforces ではこのタイプの問題をスケールします。 これにより、クエリごとに接続を最初から再計算する必要が直ちに排除されます。 すべてのクエリに対して範囲全体をスキャンしたり、クエリごとに過去のすべての状態を再シミュレートしたりするアプローチは、遅すぎます。$O(nq)$またはより悪い行動。 

微妙なエッジ ケースは、クエリが最終状態だけでなく時間プレフィックスを参照することです。 たとえば、セグメントのオンとオフが何度も切り替わる場合、セグメントがオンのままである各間隔は、さまざまなクエリに対して複数の有効な時刻に寄与します。 現在の状態をチェックするだけの単純なアプローチでは、履歴の有効性をカウントする代わりに、クエリごとに 0 または 1 が誤って出力されます。 

もう 1 つの失敗例は、クエリがセグメント間隔にわたることを忘れていることです。 たとえば、内部セグメントが 1 つだけオフの場合、リンクが 1 つ壊れただけでも、そのタイム ステップでは間隔全体が無効になります。 したがって、正確さは、スナップショットごとに範囲が完全に 1 であるかどうかを検出することに依存します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 時間を段階的にシミュレーションします。 各切り替えの後、ランプの現在の配列が維持されます。 お問い合わせの場合$(a, b)$、0 から現在時刻まですべての時間ステップをスキャンし、すべてのセグメントが$[a, b-1]$点灯しています。 各小切手にかかる費用$O(b-a)$したがって、クエリは次のようになります$O(n)$、すべての時間ステップにわたって、これは次のようになります$O(nq)$最悪の場合。 

すべてのクエリですべての履歴状態の範囲をスキャンする必要があるため、これは失敗します。 と$10^5$オペレーション、これはすでに$10^{10}$制限をはるかに超えています。 

重要な点は、クエリはセグメント間隔が特定の時点で完全にアクティブであるかどうかのみに依存するということです。 時間を主要な次元として考える代わりに、視点を反転します。各セグメントについて、それがオンになっている時間間隔を追跡します。 各セグメントは切り替えられるため、そのアクティブ期間は時間の経過とともにばらばらになります。 

今度はクエリです$(a, b)$範囲内のすべてのセグメントにわたるこれらのアクティブ化間隔の交差を求めます。 言い換えれば、すべてのセグメントが一致する瞬間が必要です。$[a, b-1]$同時にアクティブになります。 これは、その間隔における最小の「オフ状態」が 0 である時点、または最小値が 1 である時点を見つけることと同等です。 

したがって、問題は時間の経過とともに動的範囲最小クエリになりますが、完全にアクティブなセグメント範囲を持つ時間のプレフィックスの数を数えています。 これは、セグメント間隔ごとに、最後に切り替えられた時点を維持し、セグメント ツリーまたはバイナリ インデックス構造を使用して、範囲全体にわたって最小の「ネクストオフ制約」を維持することによって自然に処理されます。 各クエリは、各時間プレフィックスで最小値がまだ満たされているかどうかを確認し、この条件が時間の経過とともに保持された回数をカウントすることに帰着します。これは、オフライン処理で増分的に維持できます。 

より明確な再定式化は、時間を順番に処理し、セグメントがオンの場合は各葉が 1、そうでない場合は 0 になるセグメント ツリーを維持することです。 クエリ間隔の場合、各タイム ステップで範囲の最小値が 1 であるかどうかを知る必要があります。 再計算する代わりに、範囲が完全にアクティブになるたびに増加するカウンターをクエリごとに維持します。これは、範囲の最小値とポイントの更新をサポートするセグメント ツリーを維持することで追跡できます。

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`state[i]`各ランプが現在点灯しているかどうかを表します。 最初は入力によって与えられます。 これは現在の道路のスナップショットです。 
2. セグメントツリーを構築します。`state`各セグメントの最小値を格納します。 最小値が 1 の場合は、セグメント全体が完全に点灯することを意味します。 
3. 時系列に操作を処理します。 各位置でトグル`i`反転する`state[i]`そしてその位置のセグメントツリーを更新します。 これにより、今後のすべてのクエリで正しい構成が参照されるようになります。 
4. お問い合わせの場合$(a, b)$、区間にわたるセグメントツリーの最小値を確認します。$[a, b-1]$。 これが 1 に等しい場合、このタイム ステップでは道路が完全に照明されているため、この時間がクエリの答えに寄与します。 
5. クエリごとに応答カウンタを維持し、現在のタイム ステップでクエリ間隔が完全に点灯するたびに応答カウンタをインクリメントします。 
6. すべてのイベントを処理した後、各クエリの累積値を出力します。 

重要なアイデアは、各タイム ステップが独立して寄与し、セグメント ツリーによって各クエリ条件を対数時間で評価できるということです。 

### なぜ効果があるのか

 セグメント ツリーは、範囲クエリが現時点でその間隔内のランプの最小値を返すという不変条件を維持します。 クエリ間隔は、この最小値が 1 に等しい場合に限り、特定の時点で有効になります。これにより、すべてのセグメントが点灯することが保証されます。 時間を順番に処理し、切り替えるたびに構造を更新するため、システムのすべての状態が 1 回だけチェックされ、各クエリはそのプレフィックスに有効な時間ステップの数を正確に蓄積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = min(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, l, r, i, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i, val)
        else:
            self.update(v * 2 + 1, m + 1, r, i, val)
        self.t[v] = min(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        if r < ql or l > qr:
            return 1
        m = (l + r) // 2
        return min(
            self.query(v * 2, l, m, ql, qr),
            self.query(v * 2 + 1, m + 1, r, ql, qr)
        )

n, q = map(int, input().split())
state = list(map(int, input().split()))

seg = SegTree(state)
queries = []
ans = [0] * q

for idx in range(q):
    tmp = input().split()
    if tmp[0] == "toggle":
        i = int(tmp[1]) - 1
        state[i] ^= 1
        seg.update(1, 0, n - 1, i, state[i])
    else:
        a = int(tmp[1]) - 1
        b = int(tmp[2]) - 1
        if seg.query(1, 0, n - 1, a, b - 1) == 1:
            ans[idx] = 1

sys.stdout.write("\n".join(map(str, [x for x in ans if x != 0])))
```セグメント ツリーは、ポイントの更新時に範囲の最小値を維持するためにのみ使用されます。 各トグルは 1 つのリーフを反転し、各クエリは間隔全体が現在アクティブかどうかを検査します。 

微妙な点の 1 つはインデックス付けです。セグメントはストップ間のエッジに対応するため、$a$に$b$セグメント範囲に変換されます$[a-1, b-2]$。 このシフトを間違えると、小規模なテストは合格することが多いため、検出が困難なオフバイワン エラーが発生します。

 ## 特殊なケース

 重大なエッジ ケースは、クエリが単一のセグメントにまたがる場合です。 この場合、セグメント ツリー クエリは 1 つのリーフに縮小されます。 単一要素の最小値は要素自体であるため、アルゴリズムはこれを正しく処理します。そのため、トグルを押すとクエリ結果が即座に反転されます。 

別のエッジ ケースは、同じセグメントの繰り返しトグルです。 反転するたびに、そのセグメントを含むすべてのクエリの有効性が変更されます。 セグメント ツリーの更新により、影響を受けるすべての範囲に対してこの伝播が再計算なしで即座に行われるようになります。 

最後のエッジケースは、すべてのセグメントが最初にオフになっている場合です。 このシナリオでは、すべてのクエリはすぐに無効と評価され、切り替え後にのみ有効な間隔が表示されます。 すべての時間ステップは更新を通じて独立して評価されるため、アルゴリズムは引き続きすべての状態を均一に処理します。
