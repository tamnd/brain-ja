 ## 問題の理解

 高さの完全なバイナリ ツリーとして配置されたタスクをスケジュールするように求められます。$h$。 高さの完全なバイナリ ツリー$h$もっている$2^h - 1$ノード。 最初は、ルート タスクのみが準備されています。 それぞれの離散的な瞬間において、最大で$p$プロセスは準備完了のタスクを同時に実行できます。 タスクが実行されると、その子は次の瞬間に準備が整います。 目標は、ツリー内のすべてのタスクを実行するために必要な最小時間数を決定することです。 

入力は複数のテスト ケースを提供します。 各テスト ケースが提供するのは、$h$そして$p$、ツリーの高さとプロセスの数を表します。 各テスト ケースの出力は単一の整数、つまりすべてのタスクを完了するために必要な最小時間数です。 

制約は非常に重要です。 まであります$5 \cdot 10^5$テストケース。 ハイツ$h$最大でも 50 です。つまり、最大のツリーは$2^{50} - 1$ノード。 プロセス数$p$までです$10^4$。 これらの制約は、大規模なタスクに対して各タスクを個別にシミュレートできないことを示しています。$h$- すべてのノードを明示的に走査することは不可能です。 代わりに、ツリーの構造と各深さの予測可能なノード数を活用する戦略が必要です。 

明らかではないエッジケースには、適度に大きなツリーを持つプロセスが 1 つだけあることが含まれます。 例えば、$h = 3$、$p = 1$その結果、タスクが順次実行されます。タスクは 1 つずつ実行する必要があるため、時間は 7 になります。 並列処理が常にすべてのプロセスを完全に利用できると仮定する不用意な貪欲なアプローチは、そのような場合に必要な時間を過小評価する可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。プロセスをシミュレートします。 準備が整ったタスクのキューを保持し、各瞬間に最大で次のタスクを割り当てます$p$プロセスを作成し、タスクを完了としてマークし、その子を準備完了キューにプッシュします。 これは正しく動作しますが、$h = 50$、 がある$2^{50} - 1$タスク。 各タスクのシミュレーションには次の時間がかかります$10^{15}$合理的な制限時間をはるかに超えた作戦。 

最適なアプローチは、バイナリ ツリー構造を利用します。 深さで$d$、 がある$2^{d-1}$タスク。 ある深さのタスクは、前のレベルが終了した後でのみ準備可能になります。 同じレベルのすべてのタスクが同時に準備完了になるため、準備完了タスクの数を計算し、最大サイズのバッチで処理できます。$p$。 これにより、問題はレベル全体の合計となり、プロセス制限によるタスクの上限分割が実行されます。$p$。 計算は、各ノードを個別に繰り返すのではなく、深さごとのタスクのカウントに依存します。 

重要な洞察は、前のレベルからの未完了のタスクの累積バックログを考慮して、問題を最後のレベルを完了するまでに必要な時間を数えることに帰着できることを認識することです。 残りのタスクのソートされたリストを維持し、常に利用可能な最大のバッチを最初に処理することで、合計時間を最小限に抑えます。

 ## アルゴリズムのチュートリアル

 1. ツリーの各深さでのタスクの数を計算します。 深さについて$d$1から$h$、 がある$2^{d-1}$タスク。 これらをリストに保存します`tasks`。 
2. リストを逆にして、最も深いレベルから処理を開始します。 これにより、最大のバッチを優先することができ、合計時間を最小限に抑えるために重要です。 
3.初期化`ready`1 は、時点 1 で準備が完了したルート タスクを表します。`time`0として。 
4. 実行すべきタスクがまだ残っていますが、次のとおりです。 

4.1. 現在の深さのタスクの数を`ready`。 

4.2. この時点で実行できるタスクの数を決定します。`done = min(ready, p)`。 

4.3. 減算`done`から`ready`。 

4.4. インクリメント`time`1までに。 
5. すべてのレベルがなくなるまで繰り返します。`ready`0になる。戻る`time`最小の瞬間数として。 

なぜ機能するのか: 不変条件は次のとおりです`ready`現時点で実行できるタスクの数を常に正確に表します。 までを常に実行することで、`p`瞬間ごとのタスクを処理し、より大きなバッチを最初に処理するため、プロセスが使用可能な場合はアイドル時間が発生しないようにします。 この戦略により、合計時間が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def minimal_time(h, p):
    tasks = [(1 << i) for i in range(h)]
    tasks.reverse()
    ready = 0
    time = 0
    for t in tasks:
        ready += t
        done = min(ready, p)
        ready -= done
        time += 1
    while ready > 0:
        done = min(ready, p)
        ready -= done
        time += 1
    return time

t = int(input())
for _ in range(t):
    h, p = map(int, input().split())
    print(minimal_time(h, p))
```最初のループは、深さごとのタスクの数を逆に構築するので、最大のバッチを最初に処理します。 変数`ready`実行可能なタスクを追跡します。 まで繰り返し実行します`p`瞬間ごとのタスク。 最後の while ループは、前の深さからの残りのタスクを処理します。 これにより、未処理のタスクがなくなることが保証されます。
