 ## 解決策
 ## 問題の理解

 整数の角を持つすべての単位正方形は、4 つの無限のドラゴン曲線のいずれかの 1 つのセグメントと正確に交差します。 対角を持つクエリ正方形の場合$(x,y)$そして$(x+1,y+1)$、2つのことを決定する必要があります。 

1 つ目は、4 つの曲線のどれにその正方形と交差するセグメントが含まれるかです。 

2 番目は曲線に沿ったセグメントのインデックスです。各曲線の最初のセグメントにはインデックスが付いています。$1$。 

座標の大きさは次のとおりです$10^9$、まであります$2 \cdot 10^5$クエリ。 曲線を明示的に生成するアプローチは絶望的です。 その大きさの座標に到達するのに十分な大きさの有限のドラゴン カーブを生成する場合でも、指数関数的に多くのセグメントが必要になります。 クエリごとに対数解が必要です。 

難しいのは、ドラゴンの曲線が自己相似であることです。 原点から非常に遠い正方形でも、再帰的に小さなドラゴンの曲線のように見える構造に属しています。 意図したソリューションでは、原点に到達するまで、クエリ正方形をフラクタルの 1 つのスケールから次の小さなスケールに繰り返しマッピングします。 各ステップで座標がおよそ 2 で除算されるため、最大の座標に必要な反復は約 31 回だけです。$10^9$。 

よくある間違いは、スケールダウン後もセグメントの順序が維持されると想定することです。 そうである場合もありますが、対応する大き​​なセグメント内の順序が逆になる場合もあります。 たとえば、同じ大規模セグメントに属する 2 つの隣接する正方形が、1 回の再帰的縮小後に逆の順序で表示される場合があります。 ソリューションでは、これらの反転を明示的に追跡する必要があります。 

もう 1 つの微妙なケースは、負の座標の処理です。 再帰的座標変換は、算術シフトと慎重に選択された式に依存します。 単純な除算で置き換えると、負の象限内の正方形のマッピングが壊れる可能性があります。 

## アプローチ

 ブルートフォース手法では、ターゲットの正方形に到達するまでセグメントごとにドラゴン カーブが生成されます。 すべてのセグメントが正確に 1 つの正方形と交差するため、これは概念的には簡単です。 残念ながら、セグメントの数は曲線の次数とともに指数関数的に増加します。 近くの座標$10^9$これは再帰の深さ約 30 に相当し、これはすでに数十億のセグメントを意味します。 そのアプローチは完全に不可能です。 

重要な観察は自己相似性です。 

ドラゴン曲線の 2 つのバージョンを考えてみましょう。 元の 1 つの注文を呼び出す$n+1$、もう 1 つはそれを回転させて得られます。$45^\circ$反時計回りにスケーリング$1/\sqrt2$、 注文$n$。 小さい方の曲線の各セグメントは、大きい方の曲線の正確に 2 つのセグメントに拡張されます。 これにより、平面内の正方形と次に小さいスケールの正方形の間に直接的な再帰的関係が得られます。 

平面は次のように分割できます。$2 \times 2$ブロック。 パリティに応じて、そのようなブロックは「垂直」または「水平」のいずれかになります。 ブロック タイプから、現在の正方形を小さい方のドラゴン カーブ内の対応する正方形にマッピングする決定論的変換を導き出すことができます。 この操作を繰り返すと座標が縮小していきます。 

縮小中、再帰的に拡張されたセグメント内のセグメントの位置も維持されます。 縮小するたびに、表現されるセグメントの長さが 2 倍になります。 ローカルの順序が逆になる場合があるため、置き換えます$$pos \leftarrow (2^k-1)-pos.$$最終的に原点に隣接する 4 つの正方形の 1 つになると、曲線の番号がすぐにわかり、累積された位置が答えになります。

 ## アルゴリズムのチュートリアル

 1. クエリされた正方形座標から開始します$(x,y)$。 
2. 2 つの値を維持します。`bit`、現在の再帰セグメントによって表される元のセグメントの数。`pos`、そのセグメント内の位置、最初はゼロです。 
3. その正方形が原点に隣接する 4 つの正方形のいずれでもない間に、再帰的リダクションを 1 回実行します。 
4. ダブル`bit`小さい曲線の 1 つのセグメントが、大きい曲線の 2 つのセグメントに対応するためです。 後$k$リダクションの場合、表現されるセグメントの長さは次のようになります。$2^k$。 
5. この削減によってローカルの順序が逆になるかどうかを確認します。 必要な条件は、```
(x ^ y ^ ((x ^ y) >> 1)) & 1
```それが本当なら交換してください```
pos = bit - 1 - pos
```これは、現在のセグメント内の位置を反映します。 
6. 現在の状態かどうかを確認します。$2 \times 2$ブロックは水平または垂直です。 

もし```
((x ^ y) >> 1) & 1
```が true の場合は、水平方向の変換を使用します。```
x, y =
    (x >> 1) + ((y + 1) >> 1),
    ((y + 1) >> 1) - (x >> 1) - 1
```それ以外の場合は、垂直方向の変換を使用します。```
x, y =
    ((x + 1) >> 1) + (y >> 1),
    (y >> 1) - ((x + 1) >> 1)
```これらの数式は、正方形を次に小さいドラゴン カーブ内の対応する正方形にマッピングします。 
7. まで続けます$(x,y)$に属します$2 \times 2$原点の近傍、つまり```
-1 <= x <= 0 and -1 <= y <= 0
```8. 最終的な座標からカーブ番号を決定します。```
curve = (x & 1 ^ y & 3) + 1
```9. セグメントインデックスは次のとおりです。`pos + 1`出力は 1 ベースであるためです。 

### なぜ効果があるのか

 各縮小は、クエリされた正方形をドラゴン曲線の 1 つのスケールから次の小さなスケールにマッピングします。 ドラゴン曲線の幾何学的構造により、すべての正方形が縮小表示内の 1 つの正方形に正確に対応することが保証されます。 座標変換ではその対応関係が保持されます。 同時に、`bit`現在の再帰セグメントにマージされた元のセグメントの数を記録します。`pos`それらのセグメントのどれにクエリが含まれているかを記録します。 再帰的な構築で方向が逆転するたびに、ミラー変換が更新されます。`pos`それに応じて。 十分な削減の後、クエリは原点に隣接する 4 つの基本セグメントの 1 つに到達します。 その時点で、曲線の同一性と正確なセグメント位置の両方が一意に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dragon_curve(x, y):
    bit = 1
    pos = 0

    while not (-1 <= x <= 0 and -1 <= y <= 0):
        bit <<= 1

        if (x ^ y ^ ((x ^ y) >> 1)) & 1:
            pos = bit - 1 - pos

        if ((x ^ y) >> 1) & 1:
            x, y = (
                (x >> 1) + ((y + 1) >> 1),
                ((y + 1) >> 1) - (x >> 1) - 1
            )
        else:
            x, y = (
                ((x + 1) >> 1) + (y >> 1),
                (y >> 1) - ((x + 1) >> 1)
            )

    curve = ((x & 1) ^ (y & 3)) + 1
    return curve, pos + 1

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x, y = map(int, input().split())
        c, p = dragon_curve(x, y)
        ans.append(f"{c} {p}")

    sys.stdout.write("\n".join(ans))

solve()
```実装は文字通り再帰的リダクションに従います。 

ループはソリューションの核心です。 各反復で座標はおよそ 2 分の 1 に縮小されるため、最大の座標であっても約 30 回の反復のみが必要になります。 

変数`bit`元のセグメントで測定された現在の再帰セグメントの長さと常に等しくなります。 このため、電流削減を処理する前に 2 倍になります。 

反転更新は間違いやすいです。 この式では、次の新しい値が使用されます。`bit`、古いものではありません。 ある長さのセグメント内で順序が反転した場合$L$、 位置$p$になる$L-1-p$。 

座標変換では、示されているとおりに算術右シフトを使用する必要があります。 Python のシフトは負の整数に対して正しく機能し、意図した動作と一致します。

 ## 特殊なケース

 の広場を考えてみましょう`(0,0)`。 

正方形はすでにベース近傍に属しているため、ループ条件はすぐに失敗します。 再帰的な削減は必要ありません。 アルゴリズムは曲線を直接計算します`1`そして位置`1`。 常に少なくとも 1 つの削減を実行するソリューションは、誤って基本構成から離れてしまいます。 

の広場を考えてみましょう`(-2,0)`。 

最初の削減は2倍になります`bit`から`1`に`2`。 パリティ テストでは、ローカルの順序が逆になっていることが示されているため、`pos`からの変更`0`に`1`。 座標変換後の正方形は次のようになります。`(-1,-1)`、これは基本正方形です。 最終的な答えは、`2 2`。 反転を無視する実装では、位置が返されます。`1`、それは間違いです。 

次のような大きな負の座標を考えてみましょう。`(-10^9,-10^9)`。 

再帰式は、負の値に算術シフトを繰り返し適用します。 Python は右シフト中に符号を保持し、意図した幾何学的縮小に一致します。 交換中`>> 1`通常の除算とゼロへの切り捨てでは、異なる中間座標が生成され、最終的には間違った曲線が生成されます。 このアルゴリズムは、フラクタル構造から派生した正確な変換を使用することで、この問題を回避します。
