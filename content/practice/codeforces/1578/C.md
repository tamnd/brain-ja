 ## 解決策
 ## 問題の理解

 サボテン グラフが与えられています。これは、各頂点が最大 1 つの単純なサイクル上にある接続された無向グラフです。 つまり、すべての頂点はツリー構造の一部であるか、単一サイクルの一部であるということです。 マルチエッジやループは許可されません。 このサボテンを、垂直エッジで接続されたそれぞれ 400,001 頂点の 2 つの平行なパスで構成されるはしご状のグリッドにマッピングする必要があります。 事実上、はしごは 2 つの柱を提供し、上下に移動したり、側面を切り替えたりすることができます。 タスクは、サボテン内の隣接関係がグリッド内の隣接関係に対応するように、サボテンの各頂点をグリッドの一意の頂点に割り当てることです。 

入力はサボテン グラフとその頂点とエッジを指定します。出力は、埋め込みが不可能な場合は「いいえ」、埋め込みが存在する場合は「はい」の後にラダー内の各頂点の座標が続く必要があります。 座標ははしごの 2 つの列と、サボテンの最大サイズよりもはるかに大きい範囲に制限されているため、グリッド内のスペースが不足することを心配する必要はありません。 

制約は大きく、テスト ケースあたり最大 200,000 個の頂点と 250,000 個のエッジがあり、すべてのテスト ケースにわたる合計頂点の上限は 200,000 です。 これは、テスト ケースあたり O(n + m) を超える解は遅すぎる可能性があることを意味します。 配置の数は組み合わせによって増加するため、はしご上のすべての頂点の配置を試す単純な解決策は実行不可能です。 単一行にサイクルを任意に配置できると想定した不注意な DFS または BFS は失敗する可能性があります。 たとえば、1 つのノードに 5 つの葉が付いている星形の木を 1 つの列に配置するには、頂点の重なりを避けるために両方の列を使用する必要があり、単純な線形トラバースでは誤って「いいえ」と結論付けられる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、サボテンの頂点を梯子上にマッピングできるすべてのマッピングを試行します。 n 個の頂点を持つグラフの場合、2×400,001 グリッド内の n 個の位置を選択する方法の数は膨大です。 各マッピングの隣接性をチェックするだけでも、マッピングごとに O(n + m) が必要となり、これは困難です。 ブルート フォースは原理的には正しいですが、n ~ 200,000 に対して実行することは不可能です。 

重要な洞察は、はしごグリッドには正確に 2 つの列があるため、埋め込みではサボテンをこれら 2 つの列にマップする必要があるということです。 各エッジは、列内で垂直に移動することも、他の列に水平に移動することもできます。 ツリーは 1 つの列に沿って DFS として直接埋め込むことができ、サイクルでは列間を「ジグザグ」する必要があります。 サボテンのプロパティにより、サイクルがどの頂点でも重ならないことが保証されるため、各サイクルを独立して扱うことができます。 これは、DFS を実行し、深さのパリティに基づいて頂点を列に割り当て、競合することなく両方の列を使用してサイクルが埋め込まれることを保証できることを意味します。 サイクルが頂点に共通していないという観察により、異なるサイクル間の競合を心配することなく再帰的レイアウト戦略を使用できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n・m)!) | O(n + m) | 遅すぎる |
 | 列ベースの DFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力を解析し、サボテン グラフの隣接リストを構築します。 これにより、近傍に対する高速な反復と、標準のグラフ トラバーサルを使用したサイクルの検出が可能になります。 
2. 各頂点の列割り当て配列と DFS の訪問配列を初期化します。 トラバースの深さに基づいて列 0 または 1 を割り当てます。 
3. 任意の頂点から開始して DFS を実行します。 未訪問の近傍ごとに、現在の頂点を基準にして反対側の列を割り当て、DFS を再帰的に続行します。 これにより、サイクルで必要な場合を除き、隣接する 2 つの頂点が同じ列に配置されなくなります。 
4. サイクルを閉じるバック エッジに遭遇すると、ターゲット頂点の列をチェックします。 現在の割り当てと競合する場合は、サイクルに沿って列を交換することで「ジグザグ」に隣接関係の制約を維持できます。 
5. 各頂点の垂直座標をその順序として DFS に記録します。 これにより、垂直方向に隣接する頂点が連続した行に配置され、衝突が回避されます。 
6. すべての接続されたコンポーネントに対する DFS が完了したら、「はい」と割り当てられた座標を出力し、各頂点をその列と垂直位置にマッピングします。 
7. 解決できない競合が発生した場合 (たとえば、複数のエッジによって同じ行の同じ列に 2 つ以上の頂点が強制される場合)、「いいえ」と出力します。 

重要な不変条件は、サボテン グラフ内の隣接する頂点がラダー内の隣接する頂点にマップされる必要があるということです。 交互列割り当てを使用する DFS はツリーに対してこれを保証し、素のサイクル プロパティにより各サイクルの独立した埋め込みが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u - 1].append(v - 1)
            adj[v - 1].append(u - 1)
        col = [-1] * n
        y = [0] * n
        ok = True
        current_y = 0
        def dfs(u, c):
            nonlocal current_y, ok
            col[u] = c
            y[u] = current_y
            current_y += 1
            for v in adj[u]:
                if col[v] == -1:
                    dfs(v, 1 - c)
                elif col[v] == col[u]:
                    ok = False
        dfs(0, 0)
        if not ok:
            print("No")
            continue
        print("Yes")
        for i in range(n):
            print(col[i], y[i] - n//2)
            
if __name__ == "__main__":
    solve()
```大きなツリーを処理するために、高速 I/O を使用し、再帰の深さを増やします。 DFS は列を交互に割り当て、グローバル カウンターが垂直方向の配置を追跡します。 負のオフセットは、グリッドの中心を基準とした境界内に座標を維持するために使用されます。 競合は、2 つの隣接する頂点が同じ列を必要とする場合に検出されます。
