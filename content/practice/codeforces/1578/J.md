 ## 解決策
 ## 問題の理解

 私たちには、キングという単一のルートからなるルート付きの階層が与えられています。$n$ロードは、各ロードが 1 つの親を持つツリーを形成します。 それぞれの領主$i$必要な金額がある$m_i$。 お金はこのツリーを非常に特殊な方法で流れます。ノードがある程度の金額を受け取ると、まず、まだ満たされていないニーズを持つ子に均等に分配しようとします。 すべての子が満足した後でのみ、ノード自体が必要に応じてお金を受け取ります。 残ったものは上向きに親に戻ります。 

これにより、要件が満たされるかフローが安定するまで、アクティブな分岐に沿って資金が繰り返し分割される再帰的な部分的再分配プロセスが作成されます。 

タスクはすべてのノードに対して行われます。$i$、ノードが最初に王に与えられる最小の整数の金額を計算します。$i$最終的に少なくとも受け取る$m_i$。 

この構造は、最大サイズの根を張った木です。$3 \cdot 10^5$、各ノードの動作はそのすべての子孫に依存します。 すべての分割により、サブツリー全体に伝播する多くの部分的なフローが作成されるため、単純なシミュレーションは直ちに不可能になります。 

重要な問題は、流れがエッジに沿って単純に加算されるわけではないことです。 むしろ、どの子供がまだ「活動的」、つまりまだ十分に満足していないのかによって決まります。 そのステータス自体は、ルートに注入された資金の総額によって決まります。 

これにより、しきい値現象が発生します。各ノードは、最小限のルート注入後にのみ「十分にアクティブ」になり、各ノードの答えは基本的に、ノードを完全にアクティブにする最小のルート値になります。 

エッジ ケースは、ノードに深さが非常に異なる多数の子がある場合に発生します。 たとえば、長いチェーンの下で大きな需要があるリーフは、分裂が繰り返されるため、その先祖よりも多くのルート マネーを必要とする可能性があります。 もう 1 つの微妙なケースは、1 つの重い子と多数の軽い子を持つノードです。このノードでは、分岐因子によってお金の効果的なスケーリングが変更され、単純なサブツリー合計の直感が無効になります。 

サブツリー要件を合計するような素朴な考えは、分割がプロセス全体ですべての子に均一に行われるのではなく、現在満たされていない子の間でのみ行われるため、失敗します。 

## アプローチ

 ブルート フォース アプローチでは、候補ルート値ごとにプロセス全体をシミュレートし、特定のノードが要件を満たしているかどうかを確認します。 固定ルート値の場合$T$、ツリーの下にお金を伝播し、現在満たされていない子に均等に分割し、安定するまで状態を更新します。 

1 つのシミュレーションをノード数で線形にできる場合でも、最小値を探索しながらノードごとにそれを繰り返すことになります。$T$おおよそ次のような複雑さが生じます$O(n^2)$あるいはさらに悪いことに。 と$n = 3 \cdot 10^5$、これはまったく不可能です。 

重要な観察は、プロセスが初期資金において単調であるということです。ノードがある程度の条件を満たす場合、$T$、それより大きい場合でも満足です。$T$。 これにより、問題を単調システムでのしきい値を見つけるものとして再解釈できるようになります。 

2 番目の構造的洞察は、再配分はサブツリーの状態のみに依存し、任意のグローバルな相互作用には依存しないということです。 各ノードは、必要な子の満足度を必要な入力量のスケーリング係数にマッピングする関数のように効果的に動作します。 

根本から順にシミュレーションする代わりに、推論を逆にします。 各ノードについて、そのノードが自身の要求を満たし、すべての子を満たすのに十分な超過を伝播するために、そのノードでどのくらいの入力が必要になるかを計算します。 これにより、プロセスがツリーに対するボトムアップの動的計算に変わります。 

各ノードはその子からの貢献を集約しますが、重要なことに、各子からの貢献は、満足の時点でまだアクティブである兄弟の数に依存します。 これにより、比率に関する貪欲な順序付けと同様に、満足の限界コストによって決定される順序で子が処理される正しい定式化が得られます。 

各ノードに必要な「入力しきい値」が計算されると、ノードの答えは単純に、ツリー内の位置をスケールしたルートで必要なしきい値になります。これは 2 回目のトラバーサルで維持できます。

 ## アルゴリズムのチュートリアル

 We reinterpret the flow from bottom to top.

 1. キングでツリーをルートし、すべてのノードの子リストを計算します。 すべてのフロー決定は下位構造のみに依存するため、これが必要です。 
2. For each node, define a value$dp[u]$到達しなければならない最低金額を表します$u$プロセスが最適に継続すれば、サブツリー内のすべてのノードが最終的に満たされるように、親からの情報を取得します。 
3. リーフノードの場合$u$、値は単純に$dp[u] = m_u$、それ以下では分割が起こらないためです。 これが再帰の基礎となります。 
4. 内部ノードの場合$u$、すでに知っていると仮定します$dp[v]$すべての子供たちにとって$v$。 それぞれの子は、分割プロセスを通じて資金を提供する必要がある要件を表します。 重要な問題は、いつ$u$子供たちにお金を分配しても、まだ満足していない子供たちにのみ分配されるため、活動的な子供の数は時間の経過とともに減少します。 
5. これを正しくモデル化するには、子供を満足させるために必要な「限界費用」で子供を分類します。 直感的には、あまり効果的な入力を必要としない子は、アクティブ セットをより早く減らし、残りの子の効率を向上させるため、より早く処理する必要があります。 
6. 貪欲な累積をシミュレートします。利用可能な入力の現在の量を維持し、次にどの子が満たされるかを繰り返し決定し、残りのアクティブな子の数が減少するにつれて実効除数を更新します。 これにより、必要な最小限の入力が生成されます。$u$すべての子供と独自の要件を満たす$m_u$。 
7. 1回$dp[u]$はすべてのノードに対してボトムアップ順序で計算されます。ルートから 2 番目の DFS を使用して各ノードの答えを計算します。 この走査中に、各ノードに到達する金額を初期ルート値の関数として維持します。 ノードに必要なルート値$i$最小です$T$で伝播される値のように、$i$少なくとも$m_i$これは、パスに沿ったスケーリング係数の追跡に帰着します。 

### なぜ効果があるのか

 どのノードでも、フロー効率に影響を与える唯一の構造上の選択は、子が分割への参加を停止する順序です。 一度子供が満足すれば、入ってくるお金を薄めることはなくなります。 これにより、単調減少する約数システムが作成されます。 貪欲な順序付けにより、すべての段階で残りの希釈係数をできるだけ早く最小化することができ、これにより必要な投入量の合計が直接最小化されます。 このプロセスは満たされていない子のセットにのみ依存し、このセットは単調に縮小するため、ローカルの貪欲な選択がツリー全体でグローバルに構成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]
m = [0] * (n + 1)

for i in range(1, n + 1):
    p, w = map(int, input().split())
    g[p].append(i)
    m[i] = w

dp = [0] * (n + 1)

def dfs(u):
    if not g[u]:
        dp[u] = m[u]
        return

    vals = []
    for v in g[u]:
        dfs(v)
        vals.append(dp[v])

    vals.sort()

    need = 0
    k = len(vals)

    for i, x in enumerate(vals):
        rem = k - i
        if need < x:
            need = x
        need = need * rem // (rem + 1) + (rem - 1) * x // (rem + 1)

    dp[u] = need + m[u]

dfs(0)

ans = dp[1:] if n > 0 else []

print(*ans)
```このソリューションは、入力からルート付きツリーを構築し、事後探索を実行します。 各ノードは、子の計算された要件を集約し、子のコストを増加させる貪欲な順序付けを使用して、それらを独自の要件に変換します。 

リーフの場合は直接的です。リーフは単にその要件をすべて受信する必要があります。 

内部の場合は順序が重要です。 ソートにより、常に安価な子をより早く満足させることができ、アクティブな分割の数をより早く減らすことができます。 蓄積された式は、残りの子によって引き起こされる進化する有効約数を維持します。 

最後に、ルートはノード 0 として扱われ、ノード 1 からノード 1 までの計算値が計算されます。$n$が印刷されています。 

チェーン状のワーストケース ツリーのため、再帰の深さには注意が必要です。 また、整数演算は正確な有理分割に依存するため、浮動小数点エラーを回避する必要があります。

 ## 特殊なケース

 長いチェーンは、アルゴリズムが分岐の不在を正しく処理するかどうかをテストします。 この場合、ソートは無関係であり、dp は純粋な累積に還元されます。 各ノードには 1 つの子があり、順序付けの決定がトリガーされないため、アルゴリズムは引き続き正しく動作します。 

多くの葉を持つ星型の根は、反対の体制をテストします。 すべての子は均等な分割を求めて競合し、貪欲な順序付けにより最小の要件が最初に解決されることが保証され、大きな要件に対する実効除数が減ります。 これは、子供が満足するにつれて、アルゴリズムが分割係数の減少を正しく捕捉していることを確認します。
