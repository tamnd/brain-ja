 ## 解決策
 ## 問題の理解

 迷宮は、部屋がノード、通路が容量のある無向エッジである、接続された重み付きグラフとして見ることができます。 各部屋には 1 回限りの「成長値」もあり、ルーシーがその部屋のキャンディーを食べることを選択すると幅が増加します。 ルーシーは、ある程度の初期幅を持つ部屋 1 から開始し、現在の幅がエッジの幅を超えない場合にのみエッジを横切ることができます。 

重要な制約は、幅は時間の経過とともに増加するだけで減少することはなく、キャンディーを食べるたびにサイズが永続的に増加することです。 課題は、グラフ内の到達可能性だけではなく、ノードが訪問される順序に応じて単調増加する制約下での到達可能性です。 

このタスクは、エッジ制約下ですべての動きが有効になるように、部屋 1 から始まるすべての部屋への訪問を順序付けし、キャンディーを消費するタイミングを選択する方法が存在するかどうかを判断することです。 可能であれば、初期幅を最大化する必要があります。 

この制約では、最大 100,000 のルームと 100,000 のエッジが許可されるため、ノードの順列を考慮したり、考えられるすべての状態を動的にシミュレートしたりするアプローチは、直ちに実行不可能になります。 保存状態でも`(node, subset of eaten candies)`指数関数的であり不可能です。 

ソリューションでは、明示的なサブセットの追跡を回避し、代わりに順序付け制約を、理想的には演算ごとに線形または対数に近い効率的にチェックできる構造に圧縮する必要があります。 

貪欲なトラバーサルが将来の幅の増加を無視する場合、微妙な失敗のケースが発生します。 たとえば、最初はアクセス可能なパスが、後で広いエッジを通過するためにキャンディーが必要となる部屋へのアクセスをブロックする可能性があります。 あまりにも早くすべてのキャンディーを貪欲に摂取すると、たとえ別の順序で機能しても、途中で失敗する可能性があります。 

もう 1 つのエッジ ケースは、たとえ部屋に到達できる場合でも、ルーシーが狭い橋を渡る前にキャンディーを食べることを意図的に避けなければならない場合です。 これにより、「訪問時には必ず食べる」という単純な BFS や DFS は正しくなくなります。 

## アプローチ

 強引なアイデアは、キャンディーを食べるすべての可能な順序を試してみることです。 部屋の順列ごとに、ルーシーが部屋 1 から始めてその順序に従い、幅を更新し、各ステップでエッジ制約を確認できるかどうかをシミュレートします。 これは、すべての有効な一連の決定を明示的に試行するため、正しいです。 

ただし、順列の数は n! であり、100,000 どころか、n = 20 であっても天文学的な数になります。 単一のシーケンスをシミュレートするだけでも O(n + m) かかるため、これはまったく実行不可能です。 

重要な観察は、問題は恣意的な順序に関するものではなく、単調しきい値の下での実現可能性に関するものであるということです。 開始幅 X を固定すると、問題は次のようになります。合計の増加を累積しながら、エッジ制約を決して超えないトラバースを設計できるか? これは、すべてのステップで、現在の幅と将来の可能な増分が依然として利用可能なエッジを尊重するような順序付けが存在するかどうかをチェックすることに変換されます。 

この構造は、初期幅にわたる二分探索と組み合わせた貪欲な実現可能性チェックを示唆しています。 固定 X の場合、到達可能な状態をシミュレートしますが、すべての順列を追跡するのではなく、接続の制約を破ることなくキャンディーを安全に摂取できる訪問部屋を常に優先します。 

重要な再定式化は、幅制約の下で現在到達可能かどうかによって利用可能なノードを並べ替えたり動的に維持したりすると、エッジ制約に決して違反しないようにしながら、到達可能なコンポーネントを貪欲に拡張できるということです。 正確かどうかは、特定の幅のしきい値を下回ってノードが到達不能になると、消費の次数を増やしてもボトルネック エッジを超えずにノードを回復できないという事実にかかっています。 

しきい値設定の下で効率的な動的接続をサポートするために、エッジを並べ替えて昇順に処理し、素セット和集合 (DSU) 構造を使用して、現在の幅の推測に対する実現可能性の制約を維持しながら接続を段階的に構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | お(ん!) | O(n + m) | 遅すぎる |
 | 最適 (二分探索 + DSU 実現可能性チェック) | O((n + m) log W) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を意思決定チェックに落とし込みます。固定開始幅 X に対して、ルーシーがトラバース中にエッジ制限を超えることなくすべてのキャンディーを消費できるかどうかを判断します。 

1. 幅を大きくしてすべてのエッジを並べ替えます。 これにより、幅が増加するにつれて接続を段階的にアクティブ化できるようになります。 
2. 候補開始幅 X を固定し、現在の幅を X として初期化します。 
3. 部屋全体に DSU を維持します。 最初は部屋 1 のみがアクティブです。 
4. 「利用可能なキャンディー」のマルチセットまたは優先順位構造を維持します。これは、現在の DSU 状態で到達可能だがまだ消費されていない部屋を意味します。 
5. 繰り返し：

1. 現在到達可能なコンポーネントからのトラバースに対する現在の幅しきい値要件以上の幅を持つすべてのエッジを DSU に追加します。 
2. 新たに到達可能なすべてのノードを、食事の候補としてマークします。 
3. 未訪問の到達可能な部屋が存在しない場合は失敗します。 
4. それ以外の場合は、到達可能な部屋を選択し、そのキャンディーを消費し、その値だけ現在の幅を増やします。 
6. すべての部屋が正常に消費された場合、X は実現可能です。 

重要な設計上の選択は、DSU が最短パスではなく、徐々に進化する制約の下で接続を維持するために使用されることです。 幅が大きくなると使用できるエッジが少なくなるため、実質的に単調な構造になります。 

### なぜ効果があるのか

 正確さは単調な実現可能性の特性に依存します。つまり、開始幅 X が十分な場合、より小さな制約セット (つまり、より制限的なエッジ) では実現可能性を向上させることはできません。 DSU はエッジを昇順に処理するため、各段階で、現在の幅のしきい値の下でどの領域が相互に到達可能であるかを正確に知ることができます。 

キャンディーを消費すると幅が増えるだけであり、将来の到達可能性が高まるだけであるため、到達可能なノードを貪欲に消費することは有効です。 したがって、現在の制約の下で今すぐに使用しても安全な場合、到達可能なノードの消費を遅らせることは役に立ちません。 

X に対する二分探索が機能するのは、実現可能性が単調であるためです。X から開始できる場合、開始幅を小さくしても機能しない可能性もありますが、開始幅を大きくすると、実現可能性の制約が維持または改善されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def can(start_w, n, edges, c):
    dsu = DSU(n)
    active = [False] * n
    active[0] = True
    cur_w = start_w

    i = 0
    m = len(edges)

    while True:
        # activate edges that are usable at current width
        while i < m and edges[i][0] <= cur_w:
            _, u, v = edges[i]
            dsu.union(u, v)
            i += 1

        # gather reachable unvisited nodes
        progress = False
        root0 = dsu.find(0)

        for v in range(n):
            if not active[v] and dsu.find(v) == root0:
                active[v] = True
                cur_w += c[v]
                progress = True

        if all(active):
            return True

        if not progress:
            return False

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    edges = []
    for _ in range(m):
        a, b, w = map(int, input().split())
        edges.append((w, a - 1, b - 1))

    edges.sort()

    # feasibility check for very large initial widths
    lo, hi = 0, sum(c)

    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, edges, c):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、部屋全体に DSU を構築し、幅の大きい順にエッジを処理します。 各実現可能性チェックでは、到達可能なコンポーネントを繰り返し拡張し、新たに到達可能なキャンディーを食べることによって、指定された開始幅で完全に消費できるかどうかをシミュレートします。 

二分検索ではこのチェックがラップされて開始幅が最大化されます。 上限はキャンディーの合計です。これより大きい開始幅は、すべてのノードの遅延を許可する以上に意味のある追加の実現可能性を追加しないからです。 

微妙な点は、DSU 接続を使用して部屋 1 からの到達可能性を常に再計算することです。これにより、明示的なパス シミュレーションが回避されます。

 ## 特殊なケース

 重要なエッジ ケースは、残りのノードに到達するために必要なボトルネック エッジを超えて幅が増加するため、ルーシーがキャンディーをあまり早く食べないようにする必要がある場合に発生します。 このような場合、単純な「可能な限り食べる」戦略は失敗します。 

もう 1 つのエッジ ケースは、初期幅がすでにすべての小さなエッジを超えている場合で、ロックを解除するのに十分なキャンディーが他の場所で収集されるまで、グラフの一部を即座に除外することになります。これにより、DSU ベースの到達可能性が拡張後に正しく再計算されるかどうかがテストされます。 

到達可能性は常に現在の幅制約に基づいて再計算され、ノードは部屋 1 の現在接続されているコンポーネント内にある場合にのみ消費されるため、アルゴリズムは両方のケースを処理します。
