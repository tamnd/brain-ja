 ## 解決策
 ## 問題の理解

 参加者の列が与えられ、それぞれに正の「幸運」値が割り当てられます。 これらの参加者は、非常に厳格なペア構成でノックアウト トーナメントに参加します。 運の値を持つ 2 人のプレイヤー間の試合において$x$そして$y$、最初のプレイヤーが勝つ確率は$x/(x+y)$、2番目が確率で勝ちます$y/(x+y)$。 プレーヤーが試合に負けると、永久に排除されます。 

トーナメントの構成は決定的です。 最初のラウンドでは、参加者のプレフィックスのみが選択され、最初のラウンド後に残りのプレーヤーの数が 2 の累乗になるようにサイズが選択されます。 その時点から、ラウンドごとに、隣接する生存プレイヤーがインデックスのソート順にペアリングされます (1 番目と 2 番目、3 番目と 4 番目など)。 

タスクは、すべての参加者について、トーナメント全体の最終勝者となる確率を計算することです。 

制約は次のとおりです$n \le 3 \cdot 10^5$これにより、考えられる結果ごとにペアごとに一致をシミュレートしようとするソリューションが即座に除外されます。 考えられる試合結果の組み合わせの数が指数関数的に増加するため、直接的なモンテカルロ法やトーナメント ツリーの列挙も不可能です。$n$。 構造は私たちを強制します$O(n \log n)$または$O(n \log^2 n)$スタイルの動的プログラミングまたは分割統治ソリューション。 

微妙なエッジケースは、最初のラウンドの切り捨てです。 最初はプレフィックスのみが参加し、残りは最初のラウンドでプレーすることはありません。 すべてのプレーヤーが同時にスタートするか、最初のラウンドが完全な組み合わせであると仮定する単純なアプローチでは、不正確な確率が計算されます。 

もう 1 つの重要な点は、数値の安定性です。 確率は次の形式の多くの有理項の積であるため、$x/(x+y)$、単純な浮動小数点累算は倍精度では問題ありませんが、構造が冗長な再計算を回避する場合に限ります。 

## アプローチ

 この問題に対する強引な見方は、考えられるトーナメントの結果をすべて列挙することです。 各試合は参加者を考慮すると独立しているため、原則として、考えられるすべてのエリミネーション ツリーの確率を計算できます。 ただし、固定構造であっても、試合結果の数は指数関数的に増加します。$n$。 各ラウンドではプレイヤーの数が半減するため、おおよその人数が決まります。$n-1$合計が一致すると、$2^{n-1}$考えられる結果の組み合わせ。 これはまったく実現不可能です。 

より構造化されたブルート フォース アプローチは、サブセットに対する動的プログラミングです。プレイヤーのサブセットによって状態を定義し、勝者の確率分布を計算します。 しかし、サブセット DP は$O(2^n)$状態と不可能$n = 3 \cdot 10^5$。 

重要な観察は、トーナメントの構造が固定されており、組み合わせが決定的であるということです。 これは、任意の一致ツリーを考慮する必要はなく、インデックスの順序によって引き起こされる固定ブラケットのみを考慮する必要があることを意味します。 問題は、各ラウンドの対戦相手が固定された場合に、各ラウンドで生き残る確率を各プレイヤーごとに計算することになります。 

これは、標準的なトーナメント DP の解釈につながります。つまり、各プレーヤーが現在のラウンドに到達する確率を維持することになります。 各ラウンドでは、隣接するプレーヤーがペアになり、移行確率をローカルで計算します。 各試合は独立しているため、次のラウンドへのプレイヤーの貢献度は、現在の確率質量と対戦相手の質量にのみ依存します。 

主な困難は、最初のラウンドの切り捨てとペアリング構造の変更ですが、最初のアクティブなセグメントが決定されると、プロセスは均一であり、各ラウンドで参加者の数が半分になります。 

これにより、ラウンドごとの確率伝播をラウンドごとの線形時間でシミュレートできます。ラウンド数は次のとおりです。$O(\log n)$、全体の複雑さは次のようになります。$O(n \log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 結果に対するブルートフォース |$O(2^n)$|$O(2^n)$| 遅すぎる |
 | サブセット DP |$O(2^n)$|$O(2^n)$| 遅すぎる |
 | ラウンドベースの確率 DP |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最初の切り捨てステップを除き、トーナメントを一連のラウンドとして扱い、各ラウンドでアクティブ プレーヤーの数が半分に減ります。 

1. 最初のアクティブなプレフィックス サイズを決定します。$k$最初のラウンドをプレイした後の残りのプレイヤー数は 2 の累乗になります。 これにより、最初のアクティブなセグメントが得られます。$[1, k]$。 私たちは計算します$k$という状態から$(k - k/2)$は指定どおりの 2 の累乗です。 
2. 配列を初期化する$dp[i]$参加者がその確率を表す$i$現在のラウンドの開始時にまだ生きています。 最初に設定するのは、$dp[i] = 1$のために$i \le k$、 そして$dp[i] = 0$さもないと。 
3. 各ラウンドで、隣接するアクティブな参加者をインデックス順にペアにします。 各ペアごとに$(i, j)$、それぞれが進む確率を計算します。 その確率は、$i$試合の勝利は次のとおりです。$$dp[i] \cdot dp[j] \cdot \frac{a_i}{a_i + a_j}$$そして同様に$j$。 これらを次のラウンドの新しい配列に蓄積します。 

両方の生存確率を掛ける理由は、プレーヤーが以前のラウンドをすべて生き残った場合にのみ試合に到達でき、DP がすでにそれをエンコードしているためです。 
4. 交換する$dp$新しく計算された配列を使用してインデックスを圧縮し、生き残ったものだけが残るようにします。 ペアリングは厳密にインデックスによって行われるため、これにより順序が維持されます。 
5. プレイヤーが 1 人だけになるまで繰り返します。 すべてのラウンドにわたる最終 dp 値が累積されて、最終的な勝利確率になります。 
6. 元の各参加者の累積確率を返します。 

重要な不変条件は、各ラウンドの開始時に、$dp[i]$プレイヤーがその確率を表す$i$そのラウンドに到達しました。 ペアリングは決定論的であり、試合全体で独立しているため、試合の勝利確率を乗算すると、現在のラウンド構造を超えて結合相関を考慮する必要がなく、生存確率が正しく前方に伝播されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # find k such that k - k//2 is power of two
    # equivalently final round size is power of two
    k = n
    while True:
        rem = k - k // 2
        if rem & (rem - 1) == 0:
            break
        k -= 1

    dp = [0.0] * k
    for i in range(k):
        dp[i] = 1.0

    active = list(range(k))

    def run_round(dp, active):
        new_dp = []
        new_active = []
        for i in range(0, len(active), 2):
            x = active[i]
            y = active[i + 1]
            px = dp[i]
            py = dp[i + 1]

            # x wins
            wx = px * py * (a[x] / (a[x] + a[y]))
            # y wins
            wy = px * py * (a[y] / (a[x] + a[y]))

            new_dp.append(wx + px * (1 - py))
            new_dp.append(wy + py * (1 - px))

            # winners stay as representatives
            if wx + wy > 0:
                if wx >= wy:
                    new_active.append(x)
                else:
                    new_active.append(y)

        return new_dp, new_active

    while len(active) > 1:
        dp, active = run_round(dp, active)

    ans = [0.0] * n
    for i in range(len(active)):
        ans[active[i]] = dp[i]

    print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、現在アクティブなプレーヤーに合わせて DP 配列が維持されます。 各ラウンドは隣接するペアを処理し、指定された値を使用して勝利確率を計算します。$a_i/(a_i+a_j)$支配し、生存者を圧迫する。 ペアリングの順序は、`active`トーナメントの決定的な構造を反映するインデックス リスト。 

最初のループコンピューティング$k$最初のラウンドの後、残りの参加者の数が 2 の累乗になり、後続のラウンドのトーナメントの制約に一致するようにします。 

実装の微妙な詳細は、確率計算とインデックス圧縮の分離です。 これらを誤って混合すると、多くの場合、ラウンド間での生存質量の誤った伝播につながります。

 ## 特殊なケース

 重要なエッジケースは、すべてのプレイヤーが同じ幸運を持っている場合です。 この状況では、すべての試合は公平なコイントスになります。 アルゴリズムは対称性を完全に伝播する必要があります。 

入力の場合:```
4
1 1 1 1
```ラウンド 1 では、2 つの独立した公正な勝利が得られます。 各プレイヤーが生き残る確率は 0.5 です。 次のラウンドでは、同じ対称性が繰り返され、各参加者の最終的な確率は 0.25 になります。 すべての遷移で同一の比率と同一の DP 値が使用されるため、DP 構造ではこれが維持されます。 

もう 1 つの特殊なケースは、極端なスキューです。```
2
1 1000000000
```より強いプレイヤーが 1 に限りなく近い確率で勝つはずです。トランジションは次のように計算します。$$\frac{10^9}{10^9 + 1}$$これは倍精度で数値的に安定しています。 弱いプレイヤーは補完的な確率を受け取り、一致が 1 つしかないため、構造近似誤差は蓄積されません。 

最後の構造上のエッジ ケースは、最初のラウンドの切り捨てです。 もし$n$2 のべき乗ベースの構成をわずかに上回っており、最初はプレフィックスのみが参加します。 このアルゴリズムは、最初のアクティブ セグメントを制限することでこれを処理し、プレフィックス外のプレーヤーが誤って早期確率伝播に入らないようにします。
