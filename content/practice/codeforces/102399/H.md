 ## 解決策
 ## 問題の理解

 (n) 個の異なる正の整数 (a_1,\ldots,a_n) があります。 カードには正の整数 (x) が含まれています。 このカードを使用すると、配列要素の 1 つに対して 1 つの演算を実行できます。(x) で乗算するか、除算が正確な場合は (x) で除算します。 その後カードは消滅するため、同じ値（x）を再度使用することはできません。 

目標は、できるだけ少ないカードを使用しながら、すべての配列要素を等しくすることです。 入力では、要素の数と個別の配列値が昇順で与えられます。 出力は、消費する必要があるカードの最小数です。 

元のコンテストのステートメントには、1 秒の時間制限と 512 MB のメモリ制限があります。 (n) が (200,000) までの場合、(O(n^2)) のソリューションは、最悪の場合、約 (4\cdot10^{10}) 個のペア チェックを実行します。これは、1 秒のコンテスト制限に収まる範囲をはるかに超えています。 本質的に線形または線形に近いアルゴリズムが必要です。 

見落としがちな詳細がいくつかあります。 まず、カードは世界的に一意です。 2 つの要素の両方がカード (2) を必要とする場合、そのカードで両方の操作を実行することはできません。 例えば、```
5
2 3 6 12 18
```答えは(4)ではなく(5)です。 すべての要素が (6) と同等であるため、最終値 (6) を選択することは有望に見えます。必要なカード値は (3,2,2,3) です。 (2) と (3) の繰り返しにより、その計画は不可能になります。 割り算だけをチェックして要素ごとに 1 つの操作をカウントする不注意な解決策では、誤って (4) が返されてしまいます。 

第 2 に、元の配列に存在しない最終値は (n-1) 個の解を与えることができません。 (n-1) 個の操作では、すべての操作が 1 つの要素にのみ影響するため、少なくとも 1 つの要素は操作を受けません。 変更されていない要素は元の値と同じままであるため、共通の最終値は元の配列要素の 1 つである必要があります。 例えば、```
3
6 10 15
```2枚のカードでは解決できません。 値 (30) では、カード (5、3、2) を使用して、すべての要素が 1 枚のカードでターゲットに到達しますが、(30) は配列にないため、3 つの要素すべてを変更する必要があります。 正解は(3)です。 

3 番目に、単一の要素がすでにそれ自体と等しいため、(n=1) はカードを必要としません。 例えば、```
1
42
```答えは(0)です。 これは、入力によって配列要素が異なることが保証されるため、「すべての要素が等しい」場合をテストする唯一の意味のある方法でもあります。 

最後に、(10^{18}) を含む算術演算は、固定幅の整数を使用する言語では注意が必要です。 Python の整数自体はオーバーフローしませんが、中間の LCM であっても (10^{18}) よりもはるかに大きくなる可能性があります。 LCM が (10^{18}) を超えると、配列要素を分割することができないため、この実装では依然として LCM に上限が設けられています。 

## アプローチ

 直接的な解決策は、最終的な答えが驚くほど制限されていることを観察することから始まります。 

(k) 枚のカードを使用してすべての要素を同等にしたいとします。 すべてのカードは 1 つの要素のみを変更するため、(k<n-1) の場合、少なくとも 2 つの配列要素には触れません。 それらは最初は区別され、その後も区別されるため、平等は不可能です。 したがって、すべてのソリューションには少なくとも (n-1) 枚のカードが必要です。 

(n) 枚のカード ソリューションが常に存在します。 (g) をすべての配列要素の GCD とします。 すべての (a_i) を (a_i/g) で除算し、すべての要素を (g) に送信します。 元の (a_i) が異なるため、必要なカード値はすべて異なります。 したがって、常に (n) 枚のカードで十分です。 

したがって、答えは (n-1) または (n) になります。 

次に、(n-1) 枚のカードがいつ可能になるかを考えてみましょう。 配列要素のうち 1 つだけをそのままにすることができます。 その値を (y) とします。 最終値は (y) であるため、他のすべての要素 (a_i) は 1 回の操作で (y) に到達する必要があります。 

1 つの操作で (a_i) を (y) に変更できるのは、2 つの状況のうちの 1 つの場合のみです。 (a_i<y) の場合、(a_i) は (y) を除算する必要があり、必要なカードは (y/a_i) です。 (a_i>y) の場合、(y) は (a_i) を除算する必要があり、必要なカードは (a_i/y) です。 

必要なカードは(a_i)と(y)によって完全に決まります。 カードは再利用できないため、これらの比率はすべて異なる必要があります。 

したがって、要素 (y=a_i) は、割り算の下で他のすべての配列要素が (y) と比較可能であり、結果として得られるすべての比率が異なる場合に、正確に有効な (n-1) ターゲットになります。 

残りの問題は、配列のすべての位置についてすべて (n) 個の要素をチェックせずに、考えられるすべての候補を見つけることです。 

候補 (a_i) の場合、より小さな要素ごとに (a_i) を分割する必要があります。 同様に、(i) より前のすべての要素の最小公倍数は、(a_i) を除算する必要があります。 アレイをスキャンしている間、このプレフィックス LCM を維持できます。 すべての配列要素は最大で (10^{18}) であるため、LCM の上限は (10^{18}+1) に設定できます。そのため、LCM が大きくなっても候補を分割することはできません。 

同様に、より大きな要素はすべて (a_i) で割り切れる必要があります。 同様に、(a_i) は (i) の後のすべての要素の GCD を除算する必要があります。 接尾辞 GCD 配列は、この条件を一定時間で与えます。 

候補者はたくさんいるはずがない。 (i<j) である (a_i) と (a_j) が両方とも候補である場合、(a_i) の条件は (a_i\mid a_j) となります。 値が異なるため、(a_j\ge 2a_i)。 正の値から始まり (10^{18}) を超えることはありませんが、これは最大約 60 回発生する可能性があります。 これにより、配列全体に対してすべての候補を検査できるようになります。 

候補ごとに、配列をスキャンし、他の要素ごとに必要なカード比率を計算し、その比率をセットに挿入します。 要素がどちらの方向にも候補で割り切れない場合、候補は失敗します。 比率が 2 回表示される場合、同じカードが 2 回必要になるため、候補も不合格になります。 

ブルート フォース手法では、考えられるすべて (n) のターゲットをチェックし、それぞれの要素についてすべて (n) の要素をスキャンします。 最悪のケースは (O(n^2)) で、(n=200,000) のターゲット要素チェックは約 (4\cdot10^{10}) 回です。 最適な方法では、まずプレフィックス LCM とサフィックス GCD を使用して候補をフィルターします。候補は (O(\log 10^{18})) 個だけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log 10^{18})) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ソートされた配列を読み取り、サフィックス GCD 配列を構築します。 この配列は、すべての位置 (i) について、厳密に (i) の右側にあるすべての値の GCD を格納します。 最後の位置のサフィックス GCD は (0) です。これは、すべての正の整数が (0) で除算されるため便利です。 
2. 現在の位置より前のすべての値の LCM を厳密に維持しながら、配列を左から右にスキャンします。 この最小公倍数が (10^{18}) を超える場合は、(10^{18}) より大きい特別な値に置き換えます。 このような LCM は、候補となる配列要素を分割することはできません。 
3. プレフィックス LCM が (a_i) を分割し、(a_i) がサフィックス GCD を分割する場合にのみ、(a_i) をターゲット候補としてマークします。 最初の条件は、すべての小さな要素が 1 回の操作で (a_i) に到達できることを示しています。 2 つ目は、より大きな要素はすべて 1 回の操作で (a_i) に到達できることを示しています。 
4. 考えられるすべてのターゲット (y) について、(y) 以外のすべての配列要素をスキャンします。 (x<y) の場合、必要なカードを (y/x) として計算します。 (x>y) の場合は、(x/y) として計算します。 候補者はこれらの割り算が正確であることを保証するため、ここでは追加の割り算テストは必要ありません。 
5. 必要なすべての比率をセットに挿入します。 同じ比率が 2 回出現した場合、対応するカードはテーブル上に 1 回しか存在しないため、このターゲットは拒否されます。 すべての比率が異なる場合、ターゲットは有効な (n-1) 枚のカード構造を与えるため、すぐに (n-1) を出力します。 
6. 候補が見つからない場合は、(n) を出力します。 前に説明した GCD 構造では、(n) 枚のカードが常に十分であることが保証されます。 

### なぜ効果があるのか

 下限 (n-1) が続きます。これは、操作が少ないと、少なくとも 2 つの異なる元の要素がそのまま残されるためです。 (n-1) 演算の解は 1 つを除くすべての要素に触れなければならないため、その最終値は触れられていない要素と等しくなければなりません。 変更されたすべての要素は、正確に 1 回の操作でそのターゲットに変換可能である必要があります。これは、2 つの値がいずれかの方法で割り切れる場合に正確に可能です。 必要なカードは商であるため、すべての商は区別される必要があります。 

プレフィックス LCM 条件は、より小さな配列要素ごとに候補を分割するということとまったく同じです。 接尾辞 GCD 条件は、候補がより大きな要素ごとに分割されると言うのとまったく同じです。 これらの条件が成立すると、比率スキャンによって残りの唯一の制限、つまりカードの値が 2 回必要でないことがチェックされます。 したがって、アルゴリズムは、(n-1) 個の解が存在する場合、正確にそれを見つけます。 何も見つからなかった場合は、下限によってすべての小さな答えが除外され、GCD 構築により (n) カードの解が提供されるため、(n) が最適になります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

LIMIT = 10**18
INF = LIMIT + 1

def solve_case(a):
    n = len(a)

    # suffix_gcd[i] = gcd(a[i], ..., a[n-1])
    # We need the gcd strictly after i, so suffix_gcd[i + 1].
    suffix_gcd = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_gcd[i] = math.gcd(a[i], suffix_gcd[i + 1])

    candidates = []

    # pref_lcm is the LCM of elements strictly before i.
    pref_lcm = 1

    for i, x in enumerate(a):
        if pref_lcm <= LIMIT and x % pref_lcm == 0:
            if suffix_gcd[i + 1] % x == 0:
                candidates.append(i)

        if pref_lcm <= LIMIT:
            g = math.gcd(pref_lcm, x)
            multiplier = x // g

            if pref_lcm > LIMIT // multiplier:
                pref_lcm = INF
            else:
                pref_lcm *= multiplier

    # Try every possible untouched element.
    for idx in candidates:
        target = a[idx]
        used = set()

        for x in a:
            if x == target:
                continue

            if x < target:
                card = target // x
            else:
                card = x // target

            if card in used:
                break

            used.add(card)
        else:
            return n - 1

    return n

def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(a))

if __name__ == "__main__":
    main()
```サフィックス GCD 配列は右から左に構築されます。`suffix_gcd[i + 1]`位置以降の要素が正確に含まれます`i`ので、確認してください`suffix_gcd[i + 1] % x == 0`候補の右側を処理します。 

候補自体がプレフィックスの一部であってはいけないため、プレフィックス LCM は現在の要素をテストした後にのみ更新されます。 LCM は (L/\gcd(L,x)\cdot x) として計算され、共通因数による不必要な乗算が回避されます。 

(10^{18}+1) の上限は、パフォーマンスと明瞭さの尺度です。 接頭辞 LCM が (10^{18}) より大きくなると、すべての配列値が最大 (10^{18}) になるため、将来の配列値はこれで割り切れなくなります。 より大きな最小公倍数を正確に知る必要はありません。 

候補の検証中に、可算条件はすでに確立されています。 これにより、コードは要素ごとに別のモジュロ演算を実行する代わりに、整数の除算を直接使用できるようになります。 

セットには、変換された配列値ではなく、カード値が含まれます。 2 つの要素は、異なる値から始まっている場合でも同じ商を必要とする場合があります。これはまさに、候補が拒否されなければならない状況です。 

Python には任意精度の整数があるため、LCM を計算するときにオーバーフローが発生することはありません。 明示的な上限により、LCM が不必要に大きくなるのを防ぎ、操作を制限したままにします。

    suffix_gcd = [0] * (n + 1)

    return str(n)

 ## 特殊なケース

 単一の要素の場合、```
1
42
```候補は (42)、プレフィックス LCM は (1)、サフィックス GCD は (0) です。 候補は有効で、比率セットは空で、アルゴリズムは (1-1=0) を返します。 操作は必要ありません。 

繰り返しカードが必要な場合は、```
5
2 3 6 12 18
```候補 (6) は可算条件を満たします。 必要な比率は (3,2,2,3) です。 このセットは (2) の 2 回目の出現を即座に検出するため、(6) は (n-1) 個の解を提供できません。 他の候補は可分性条件を満たさないため、正解 (5) が得られます。 

配列外のターゲットについては、次のことを考慮してください。```
3
6 10 15
```値 (30) は 3 つの要素すべてで割り切れ、比率 (5、3、2) は異なります。 これにより、有効な 3 枚のカードの構造が得られますが、元の要素がどれも (30) ではないため、2 枚のカードの構造は得られません。 2 つの操作では、1 つの要素は変更されず、最終値が (6,10,15) のいずれかになることが強制されます。 アルゴリズムは正しく (3) を返します。 

上限に近い値の場合、```
2
999999999999999999 1000000000000000000
```どちらの数も他方を割ることはありません。 元の値を 1 枚のカードの対象にすることはできないため、答えは (1) にはなりません。 それぞれの数字を単独で割って(1)に達するとカードは2枚で足りるので、答えは(2)になります。 また、実装は (10^{18}) を超える値を生成する乗算に依存しません。 

大きなプレフィックス LCM の場合、キャップが重要になります。 プレフィックスに、LCM がすでに (10^{18}) を超える値が含まれているとします。 すべての将来の値は最大 (10^{18}) であるため、将来の配列値はその接頭辞 LCM で割り切れません。 この実装では LCM が (10^{18}+1) に置き換えられるため、後続の候補はすべて巨大な整数を構築することなく拒否されます。 

最大入力サイズの場合、配列```
1 2 3 ... 200000
```(200,000) の個別の値があります。 ターゲット (1) にはカード (2,3,\ldots,200000) が必要ですが、すべて異なるため、答えは (199999) になります。 候補はプレフィックス LCM 条件によって即座に検出され、比率スキャンによって必要なカードがすべて一意であることが確認されます。
