## アプローチ

 直接的な解決策は、すべてのクエリ部分文字列を明示的に処理することです。 かっこを次のように変換します。`+1`そして`-1`、すべてのプレフィックスの合計を計算し、その最小値を見つけて、その最小値が何回発生するかを数えます。 合計がゼロの場合、完全なプレフィックスはカウントされた最小値に属しますが、開始位置を表さないため、そのカウントから 1 を減算します。 すべての有効な回転は最小プレフィックス位置に正確に対応するため、これは正しいです。 

問題は仕事量です。 長さ m の部分文字列に対するクエリには O(m) がかかり、長さが 300000 に近いクエリが 300000 件あると、最悪のケースではおよそ 9⋅10 10 回の操作に達します。 ポイントの更新により、今後のクエリでも変更された値が強制的に表示されるため、これを修正する便利な 1 回限りの前処理はありません。 

この問題を処理可能にする観察結果は、連結シーケンスに必要な情報が 3 つの値のみで要約できることです。その合計、プレフィックスの最小合計、その最小値に達するプレフィックスの数です。 シーケンスが次のように分割されたとします。`A + B`。 に属するすべてのプレフィックス`A`元の合計を保持し、空でないプレフィックスはすべて入力されます。`B`によってシフトされます`sum(A)`。 その結果、

 min(A+B)=min(min(A), sum(A)+min(B))。 

最小プレフィックスの数は、対応する側から、または 2 つの値が等しい場合は両方の側から取得されます。 したがって、これら 3 つの値は、構成可能なセグメント ツリー ノードを形成します。 

ブルート フォース手法は、これらのプレフィックスの合計を明示的に正確に計算するため機能しますが、クエリごとに最初から再計算します。 セグメント ツリーは間隔ごとに同じ情報を保存し、クエリに対して O(logn) ノードのみを結合します。 文字の反転により 1 つのリーフが変更されるため、O(logn) 個の祖先のみを再構築する必要があります。

 1. 毎に変換する`(`に`+1`そしてすべての`)`に`-1`。 セグメント ツリー ノードごとに、`sum`、その間隔の合計値、`mn`、空のプレフィックスを含む最小プレフィックス合計、および`cnt`、到達するプレフィックスの数`mn`。

3. 左側のノードに参加する場合`A`そして右のノード`B`の合計は となります`A.sum + B.sum`。 に含まれるプレフィックス`A`に到達するプレフィックスは古い値を持ちますが、`B`価値がある`A.sum + prefix_of_B`。 したがって、新しい最小値は次のようになります。

2 つの候補が等しい場合、それらのカウントが加算されます。 それ以外の場合は、より小さい値を達成した側のみが寄与します。 

1. 初期文字列からセグメント ツリーを構築します。 ツリーは、美しさのクエリに答えるために必要な情報を正確に使用して、すべての間隔を表すようになりました。 
2. 位置の更新の場合`x`、そのリーフに格納されている値を無効にします。 同じマージ ルールを使用してその祖先を再計算します。 ルートからリーフへのパスが 1 つだけ変更されるため、更新のコストは O(logn) です。 
3. お問い合わせの場合`[l,r]`、その区間をカバーするセグメント ツリー ノードを元の左から右の順序で結合します。 クエリが多くのツリー ノードにまたがる場合でも、結果のノードは完全な部分文字列を記述します。 
4. 結果が`sum`ゼロではない、返す`0`。 正しい括弧シーケンスには、同じ数の開始括弧と閉じ括弧が含まれている必要があり、循環回転によって合計を変更することはできません。 
5. 合計がゼロの場合は、return`cnt - 1`。 ノードは、空のプレフィックスから完全な部分文字列までのプレフィックスの最小値をカウントします。 合計がゼロであるため、完全なプレフィックスも最小値となり、ローテーションの開始点となる可能性のない余分なオカレンスが 1 つだけ発生します。 

不変条件は、すべてのセグメント ツリー ノードがその区間のプレフィックスサム構造を正確に記述することです。 特に、`mn`は、その区間の先頭を基準としたその区間の最小のプレフィックス合計です。`cnt`は、それに到達するプレフィックスの数です。 マージ操作では、右側の子からのプレフィックスが左側の子全体の前にある場合に導入される定数オフセットが考慮されます。 ゼロサム間隔の場合、最小プレフィックスの後に開始すると非負のプレフィックス合計が生成され、すべての有効なローテーションはそのような最小値の後に開始する必要があります。 したがって、`cnt - 1`は、有効な循環回転の正確な数です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    q = int(input())

    size = 1
    while size < n:
        size <<= 1

    total = [0] * (2 * size)
    mn = [0] * (2 * size)
    cnt = [0] * (2 * size)

    def set_leaf(pos, value):
        p = size + pos
        total[p] = value
        if value < 0:
            mn[p] = value
            cnt[p] = 1
        else:
            mn[p] = 0
            cnt[p] = 1

    for i, ch in enumerate(s):
        set_leaf(i, 1 if ch == '(' else -1)

    # Empty leaves represent an empty sequence.
    for i in range(size + n, 2 * size):
        total[i] = 0
        mn[i] = 0
        cnt[i] = 1

    for p in range(size - 1, 0, -1):
        left = p << 1
        right = left | 1

        total[p] = total[left] + total[right]

        right_mn = total[left] + mn[right]

        if mn[left] < right_mn:
            mn[p] = mn[left]
            cnt[p] = cnt[left]
        elif mn[left] > right_mn:
            mn[p] = right_mn
            cnt[p] = cnt[right]
        else:
            mn[p] = mn[left]
            cnt[p] = cnt[left] + cnt[right]

    def update(pos):
        p = size + pos
        value = -total[p]
        total[p] = value

        if value < 0:
            mn[p] = value
        else:
            mn[p] = 0
        cnt[p] = 1

        p >>= 1
        while p:
            left = p << 1
            right = left | 1

            total[p] = total[left] + total[right]

            right_mn = total[left] + mn[right]

            if mn[left] < right_mn:
                mn[p] = mn[left]
                cnt[p] = cnt[left]
            elif mn[left] > right_mn:
                mn[p] = right_mn
                cnt[p] = cnt[right]
            else:
                mn[p] = mn[left]
                cnt[p] = cnt[left] + cnt[right]

            p >>= 1

    def query(l, r):
        # Query [l, r), maintaining separate accumulators
        # because concatenation is ordered.
        l += size
        r += size

        l_sum = 0
        l_mn = 0
        l_cnt = 1

        r_sum = 0
        r_mn = 0
        r_cnt = 1

        while l < r:
            if l & 1:
                node_sum = total[l]
                node_mn = mn[l]
                node_cnt = cnt[l]

                candidate = l_sum + node_mn

                if l_mn < candidate:
                    pass
                elif l_mn > candidate:
                    l_mn = candidate
                    l_cnt = node_cnt
                else:
                    l_cnt += node_cnt

                l_sum += node_sum
                l += 1

            if r & 1:
                r -= 1

                node_sum = total[r]
                node_mn = mn[r]
                node_cnt = cnt[r]

                candidate = node_sum + r_mn

                if node_mn < candidate:
                    r_mn = node_mn
                    r_cnt = node_cnt
                elif node_mn > candidate:
                    r_mn = candidate
                    r_cnt = r_cnt
                else:
                    r_mn = node_mn
                    r_cnt = node_cnt + r_cnt

                r_sum = node_sum + r_sum

            l >>= 1
            r >>= 1

        # Merge the accumulated left and right parts.
        candidate = l_sum + r_mn

        if l_mn < candidate:
            final_mn = l_mn
            final_cnt = l_cnt
        elif l_mn > candidate:
            final_mn = candidate
            final_cnt = r_cnt
        else:
            final_mn = l_mn
            final_cnt = l_cnt + r_cnt

        final_sum = l_sum + r_sum
        return final_sum, final_mn, final_cnt

    out = []

    for _ in range(q):
        parts = input().split()

        if parts[0] == '1':
            x = int(parts[1]) - 1
            update(x)
        else:
            l = int(parts[1]) - 1
            r = int(parts[2])

            segment_sum, segment_mn, segment_cnt = query(l, r)

            if segment_sum != 0:
                out.append("0")
            else:
                out.append(str(segment_cnt - 1))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

 上記で説明した修正されたクエリ条件は、以下のテスト ハーネスとソリューション関数に反映されます。```python
import sys
import io

def solve_data(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()
    q = int(input())

    size = 1
    while size < n:
        size <<= 1

    total = [0] * (2 * size)
    mn = [0] * (2 * size)
    cnt = [0] * (2 * size)

    for i, ch in enumerate(s):
        p = size + i
        v = 1 if ch == '(' else -1
        total[p] = v
        mn[p] = min(0, v)
        cnt[p] = 1

    for i in range(n, size):
        p = size + i
        total[p] = 0
        mn[p] = 0
        cnt[p] = 1

    for p in range(size - 1, 0, -1):
        a = p << 1
        b = a | 1
        total[p] = total[a] + total[b]
        x = total[a] + mn[b]

        if mn[a] < x:
            mn[p], cnt[p] = mn[a], cnt[a]
        elif mn[a] > x:
            mn[p], cnt[p] = x, cnt[b]
        else:
            mn[p], cnt[p] = mn[a], cnt[a] + cnt[b]

    def pull(p):
        a = p << 1
        b = a | 1
        total[p] = total[a] + total[b]
        x = total[a] + mn[b]

        if mn[a] < x:
            mn[p], cnt[p] = mn[a], cnt[a]
        elif mn[a] > x:
            mn[p], cnt[p] = x, cnt[b]
        else:
            mn[p], cnt[p] = mn[a], cnt[a] + cnt[b]

    def update(pos):
        p = size + pos
        total[p] = -total[p]
        mn[p] = min(0, total[p])
        cnt[p] = 1

        p >>= 1
        while p:
            pull(p)
            p >>= 1

    def merge(a_sum, a_mn, a_cnt, b_sum, b_mn, b_cnt):
        x = a_sum + b_mn

        if a_mn < x:
            return a_sum + b_sum, a_mn, a_cnt
        if a_mn > x:
            return a_sum + b_sum, x, b_cnt
        return a_sum + b_sum, a_mn, a_cnt + b_cnt

    def query(l, r):
        l += size
        r += size

        ls, lm, lc = 0, 0, 1
        rs, rm, rc = 0, 0, 1

        while l < r:
            if l & 1:
                ls, lm, lc = merge(
                    ls, lm, lc,
                    total[l], mn[l], cnt[l]
                )
                l += 1

            if r & 1:
                r -= 1
                rs, rm, rc = merge(
                    total[r], mn[r], cnt[r],
                    rs, rm, rc
                )

            l >>= 1
            r >>= 1

        return merge(ls, lm, lc, rs, rm, rc)

    ans = []

    for _ in range(q):
        t, *v = map(int, input().split())

        if t == 1:
            update(v[0] - 1)
        else:
            l, r = v
            sm, minimum, count = query(l - 1, r)

            if sm != 0:
                ans.append("0")
            elif minimum == 0:
                ans.append(str(count - 1))
            else:
                ans.append(str(count))

    return "\n".join(ans)

def run(inp: str) -> str:
    return solve_data(inp)

 ## 特殊なケース

 単一の文字の場合`(`、セグメント ツリーの葉には`sum = 1`そして`mn = 0`。 クエリではゼロ以外の合計が検出され、ゼロが返されます。 これにより、空のプレフィックスを文字自体が正しい括弧シーケンスを形成できる証拠として扱うことがなくなります。 

のために`()`、プレフィックスの合計は次のとおりです。`0,1,0`。 最小値はゼロで、最初に 1 回、最後に 1 回の計 2 回発生します。 最後のプレフィックスは新しい回転開始位置に対応していないため、アルゴリズムは次の値を返します。`cnt - 1 = 1`。 これは、生の最小カウントを常に返す実装をキャッチする場合です。 

のために`)(`、プレフィックスの合計は次のとおりです。`0,-1,0`。 最小値は`-1`、最初の文字の境界でのみ発生します。 最後のプレフィックスは最小値ではないため、減算は実行されません。 答えは、`1`、回転に対応`()`。 

最小プレフィックスが負であるバランスの取れた文字列の場合、次のようになります。`())(`の場合でも、元のシーケンスが正しい括弧シーケンスである必要がなくても、アルゴリズムは引き続き機能します。 その合計はゼロであり、有効な回転は完全に最小プレフィックス位置によって決定されます。 最小値の絶対値は重要ではなく、どのプレフィックスがその値に達するかだけが重要です。 

最後に、ポイント更新により合計金額が正確に変更されます。`2`または`-2`。 ツリーは影響を受けるパスを即座に再計算するため、更新後のクエリでは、文字列全体を再構築することなく、新しい残高と新しいプレフィックス最小構造が確認されます。
