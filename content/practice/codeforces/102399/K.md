 ## 解決策
 ## 問題の理解

 正確に (2n) 枚のレタスの葉を含む (2\times n) グリッドがあります。 各葉には負ではないエネルギー値があり、Kolya はタートルが開始する前にすべての葉を自由に並べ替えることができます。 

左上のセルから右下のセルへのパスは、しばらく右に移動し、下に 1 回だけ移動することで構成されます。 列 (k) で下向きの移動が発生した場合、タートルは上の行の最初の (k) セルと下の行の最後の (n-k+1) セルを食べます。 タートルは総エネルギーが最大になるパスを選択するため、配置の値はそのようなパスすべて (n) の最大値になります。 この最大値ができるだけ小さくなるように、指定された (2n) 個の値のマルチセットを配置する必要があります。 

入力では、最初の行に元の (n) 個の値が表示され、続いて下の行に (n) 個の値が表示されます。 Kolya はすべての (2n) 個の葉を収集し、それらを任意に再分配できるため、元の位置は重要ではありません。 出力は、任意の最適な (2\times n) 配置です。 

境界 (n\le25) が主な手がかりです。 葉の数はせいぜい (50) なので、(n) の指数関数アルゴリズムはまだ大きすぎますが、総エネルギーに対するサブセット合計スタイルの動的プログラムは実用的です。 すべての値は最大 (50000) であるため、すべての葉の合計エネルギーは最大 (2\cdot25\cdot50000=2.5\cdot10^6) になります。 これにより、到達可能な合計のビットセット表現が可能になります。 公式問題では、5 秒の時間制限と 512 MB のメモリ制限も与えられており、これはビットセット動的プログラミング ソリューションと一致しています。 

不注意な構築によって誤って処理される可能性があるいくつかのエッジケースがあります。 まず、2 つのエンドポイントがすべての可能なパス上に存在します。 例えば、```
2
1 4
2 3
```値は (1、2、3、4) です。 2 つの最大値をエンドポイントに配置すると、1 つの最適な配置は次のようになります。```
1 3
4 2
```考えられる 2 つのパスの合計は (7) と (6) であるため、カメは (7) を食べます。 中央に大きな値を隠そうとする構造は、いくつかの 2 つの値が 2 つの避けられないエンドポイントを占有する必要があるという事実に勝つことはできません。 

第 2 に、等しい値は個別のオブジェクトとしてではなく、通常のマルチセットとして扱われなければなりません。 例えば、```
3
0 0 0
0 0 0
```にはゼロしかないので、すべての配置は値 (0) を持ちます。 サブセットの再構築では、値の繰り返しを許可する必要があり、一意のインデックスに依存してはなりません。 

第三に、残りの値の最適な分割は、総エネルギーのちょうど半分である必要はありません。 のために```
3
0 100 200
300 400 500
```2 つの最小値 (0) と (100) はエンドポイントに属します。 残りの値は (200,300,400,500) で、合計は (1400) になります。 一番上の行の内部セルに (300+400=700) を選択すると、2 つの極端なパスの合計が等しくなります。 個人の価値観のみに基づいて貪欲に選択すると、このようなバランスの取れたサブセットを見逃す可能性があります。 

## アプローチ

 直接的な総当たりの解決策では、(2n) 個の葉のすべての順列が列挙されます。 各順列について、可能なすべて (n) の下向き列を評価し、最小の最大パス合計を維持できます。 あらゆる可能な再配置が考慮されているため、これは正しいです。 ただし、((2n)!) 個のラベル付き順列があり、すべてのパスを評価すると、別の係数 (n) が追加され、(O((2n)!,n)) 個の演算が行われます。 (n=25) では、これは (50!\cdot25)、およそ (7.6\cdot10^{65}) 個のパス評価になります。 重複する値を無視しても、これは絶望的です。 

任意の順列について考えるのをやめ、最適な配置とはどのようなものかを考えると、有用な構造が現れます。 上の行は減少していないと仮定でき、下の行は増加していないと仮定できます。 これは交換引数です。2 つの上の行の位置 (i<j) に (x>y) が含まれている場合、それらを交換しても最大パス合計を増やすことはできません。 同様の議論は、一番下の行に対して反対方向に機能します。 この単調性の観察は、この問題の重要な特性の 1 つです。 

ここで、一番上の行が次のようになっているとします。 

[
 t_1\le t_2\le\cdots\le t_n
 ]

 そして一番下の行は

 [
 b_1\ge b_2\ge\cdots\ge b_n。 
]

 (F_k) を列 (k) で下に移動するパスの合計とします。 それから

 [
 F_k=t_1+\cdots+t_k+b_k+\cdots+b_n。 
]

 連続したパスの場合、

 [
 F_{k+1}-F_k=t_{k+1}-b_k。 
]

 (t_{k+1}) は減少せず、(b_k) は増加しないため、差 (F_{k+1}-F_k) は減少しません。 したがって、シーケンス (F_k) は離散凸です。 凸シーケンスはエンドポイントでのみ最大値に達することができるため、タートルの最大パスは 2 つの極端なパスの 1 つになります。 

これにより問題は劇的に崩壊します。 最初の極端なパスには、下の行全体と最初の上部セルのみが含まれます。 2 番目には、上の行全体と最後の下のセルのみが含まれます。 

避けられない 2 つのセルには、2 つの最小値が含まれている必要があります。 最小の値を左上のセルに入力し、2 番目に小さい値を右下のセルに入力します。 交換引数は、どちらかのエンドポイントに小さい値を移動しても、2 つの極端なパスの合計のうち大きい方を増やすことはできないことを示しています。 これは、標準ソリューションで使用される構造でもあります。 

これら 2 つのエンドポイントを修正すると、正確に (2n-2) 個の値が残ります。 それらの合計が (S) であるとします。 一番上の行の内部セルとして正確に (n-1) 個を選択し、それらの合計を (X) とします。 残りの (n-1) 値は、一番下の行の内部セルに格納されます。 

2 つの極端なパスの合計には、2 つのエンドポイントからの共通の寄与があります。 それらの可変部分は単純に

 [
 ×
 ]

 そして

 [
 S-X。 
]

 したがって、最小限に抑える必要があります

 [
 \max(X,S-X)。 
]

 つまり、合計が (S/2) にできるだけ近い、正確に (n-1) 個の残りの値のサブセットが必要です。 (X>S/2) を取得することは、(S-X<S/2) で置き換えることよりも優れていることは決してないため、到達可能な最大値 (X\le S/2) を見つけるだけで十分です。 

これは、カーディナリティに制約のあるサブセット合計の問題です。 標準の (O(nS)) ブール DP は概念的にすでに単純ですが、(S) は (2.4\cdot10^6) 程度になる可能性があり、最大 (25) 個の異なるカーディナリティを追跡する必要があります。 ビットセットは、マシンワード係数によって合計次元を削減します。 Python では、整数自体がビットセットであるため、最適化された C コードでは 1 つのシフトで全体の遷移が実行されます。 

構造観察と DP との関係が中心的なアイデアです。 ブルートフォースソリューションは、すべての順列を無関係なものとして扱うため、失敗します。 単調性はすべての最適な配置を 2 つのソートされた行に縮小し、凸性引数はすべての可能なパスを 2 つの極端なパスに縮小し、これら 2 つのパスにより最適化が 2 つのサブセット和のバランスに縮小されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((2n)!,n)) | (O(n)) | 遅すぎる |
 | 通常の部分集合和 DP | (O(n^2S)) | (O(nS)) | 最悪の場合は遅すぎる |
 | ビットセット DP | (O(n^2S/w)) | (O(n^2S/w)) | 承認済み |

 ここで、(S\le2.4\cdot10^6) は (2n-2) 個の非エンドポイント値の合計であり、(w) はマシンワードのサイズです。 Python の任意精度の整数は、このビットセット操作を効率的に実装します。 

## アルゴリズムのチュートリアル

 1. すべて (2n) の値を読み取り、それらを並べ替えます。 最小の値を左上のセルに入力し、2 番目に小さい値を右下のセルに入力します。 これらのセルは考えられるすべてのパスに属しているため、そこに 2 つの最小値を割り当てることが最適です。 
2. 残りの (2n-2) 個の値を (v_1,\ldots,v_{2n-2}) とし、その合計を (S) とします。 一番上の行の内部セルとして、正確に (n-1) 個を選択する必要があります。 それらの合計が (X) の場合、残りの値の合計は (S-X) になります。 
3. 到達可能なサブセットの合計をビットセットで表現します。 させて`dp[j]`処理された値のサブセットに (j) 個の要素が含まれており、合計が (x) である場合に、そのビット (x) が正確に設定される整数である必要があります。 最初は空のサブセットのみが存在するため、`dp[0] = 1`。 
4. 残りの値をすべて処理します (v)。 次を使用してカーディナリティの状態を降順に更新します。```
dp[j] |= dp[j-1] << v
```左シフトは、到達可能なすべての合計 (x) を (x+v) に移動しますが、ビットごとの OR は、(v) を使用しないサブセットを保持します。 降順`j`1 つの遷移中に同じ値を複数回使用してはいけないため、これが必要です。 

1. すべての値が処理された後、正確に (n-1) 個の選択された値がないかビットセットを検査します。 (S//2) から開始して、到達可能な最大の合計 (X) を見つけます。 目的は (\max(X,S-X)) であり、(X) が下から (S/2) に近づくにつれて減少するため、これは最適です。 
2. どの値が最上位の内部グループを形成するかを再構築します。 処理された値を逆方向に見ていきます。 以前の DP 状態が 1 つ少ない選択値を使用して (X-v) を形成できる場合、(v) を最上位グループに取り込み、(X) を (X-v) で置き換えます。 それ以外の場合は、(v) を一番下のグループに入れます。 保存された DP 状態は、これらの選択肢の少なくとも 1 つが到達可能なターゲットを再現することを保証します。 
3. 選択した上位値を徐々に並べ替えて、最小のエンドポイントの後に配置します。 下の値を降順に並べ替えて、2 番目に小さいエンドポイントの前に置きます。 結果として得られる行は、構造上の引数で必要とされる方向に正確に単調になります。 

これが機能する理由は、1 つの不変式によって把握されます。行を並べ替えると、連続する差分が非減少シーケンスを形成するため、考えられるすべてのパス合計は 2 つの極端なパス合計の間に収まります。 2 つの極端なパスには同じ 2 つのエンドポイント寄与があり、残りの寄与は (X) と (S-X) です。 DP は、最大値を最小化するサブセット (X) を見つけます。 すべての最適解は値を増やすことなくこの単調形式に変換でき、DP はすべての可能なカーディナリティ ((n-1)) サブセットを考慮するため、構築された配置は大域最適に達します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    values = list(map(int, input().split()))
    values += list(map(int, input().split()))

    values.sort()

    # The two unavoidable endpoints get the two smallest values.
    top_left = values[0]
    bottom_right = values[1]

    remaining = values[2:]
    m = len(remaining)
    need = n - 1

    total = sum(remaining)
    half = total // 2

    # dp[j] is a bitset:
    # bit s is 1 iff we can choose j processed values with sum s.
    dp = [0] * (need + 1)
    dp[0] = 1

    # Keep every layer for reconstruction.
    history = [dp[:]]

    mask = (1 << (half + 1)) - 1

    for v in remaining:
        upper = min(need, len(history[-1]))
        for j in range(need, 0, -1):
            dp[j] |= (dp[j - 1] << v) & mask
        history.append(dp[:])

    bits = dp[need]
    target = bits.bit_length() - 1

    # target is the largest reachable sum <= half.
    top_internal = []
    bottom_internal = []

    j = need
    current = target

    for i in range(m, 0, -1):
        v = remaining[i - 1]

        if j > 0 and current >= v:
            previous = history[i - 1][j - 1]
            if (previous >> (current - v)) & 1:
                top_internal.append(v)
                current -= v
                j -= 1
                continue

        bottom_internal.append(v)

    top_internal.sort()
    bottom_internal.sort(reverse=True)

    top = [top_left] + top_internal
    bottom = bottom_internal + [bottom_right]

    print(*top)
    print(*bottom)

if __name__ == "__main__":
    solve()
```最初の部分では、すべてのリーフをソートし、すべてのパスが訪問する必要がある 2 つのセルで 2 つの最小値を固定します。 これは、プルーフからエンドポイント プロパティを直接実装します。 

ビットセット DP は、合計が到達可能かどうかを表すバイナリ ビットを含む整数を使用します。 たとえば、次の場合`dp[2]`ビット (3) と (7) が含まれている場合、2 つの処理された値のサブセットは合計 (3) と (7) を持つことができます。 この整数を (v) だけシフトすると、到達可能な合計は (3+v) と (7+v) に変わります。 

DP は、大きなカーディナリティから小さなカーディナリティに向かって更新されます。 小さい値から大きい値に更新されると、現在の値が同じ反復で繰り返し挿入される可能性があり、0/1 サブセットの合計が無制限のナップザックに変わってしまいます。 

の`mask`(S/2) より大きいすべての合計を削除します。 すべての値が負ではないため、このような合計は後で役立つことはありません。そのため、値を追加した後に破棄された合計が有用な範囲に戻ることはありません。 これにより、メモリ トラフィックが削減されるだけでなく、Python の整数が小さく保たれます。 

の`history`配列には、値が処理されるたびに DP 状態が格納されます。 再構築の場合にのみ必要です。 目標合計がわかったら、以前の状態を調べて、現在の値が選択されているかどうかを判断します。 表現```
(previous >> (current - v)) & 1
```以前の状態が必要な残りの合計に達するかどうかを正確にチェックします。 

Python では整数オーバーフローは発生しません。 C++ では、パスには最大 (n+1\le26) 個の値が含まれ、それぞれ最大 (50000) 個の値が含まれるため、パスの合計には 64 ビット型でも十分ですが、Python の整数ではその懸念が完全に解消されます。 

最終的な並べ替えは表面的なものではありません。 DP は、どの値が各行の内部セルに属するかを決定するだけです。 単調性の証明では、上の行が増加し、下の行が減少する必要があるため、印刷する前にこれら 2 つのグループを並べ替える必要があります。

## 複雑さの分析

 (S) を、エンドポイントに配置されていない (2n-2) 個の値の合計とします。 (S\le48\cdot50000=2.4\cdot10^6) があります。 

| 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n^2S/w)) | (O(n^2)) 個のビットセット遷移があり、それぞれが (O(S/w)) 個のマシンワード上で動作します。 |
 | スペース | (O(n^2S/w)) | 再構築のために (O(n^2)) DP ビットセットを保存します。 |

 (n\le25) では、カーディナリティ状態の数はごくわずかですが、(S/2) を超える合計は破棄されるため、最大のビットセットには約 (1.2\cdot10^6) 個の有用なビットしか含まれません。 パイソンの`int`操作では、最適化されたネイティブ コードで大きなビットセット シフトが実行されるため、Python で可能なすべての合計を反復処理するよりも大幅に高速になります。 

メモリ制限も、指定された 512 MB 制限に対して安全です。 問題が小さい (n) ため、再構成レイヤーの保存が実用的になります。 

## テストケース

 構成的問題の出力は一意である必要はないため、最も堅牢なテストでは、出力が入力の置換であること、およびその最大パス和が最適値に等しいことが検証されます。 小規模な場合には、すべての順列を列挙することで最適値を計算できます。 以下のテストには、実装に固有の自然な結果がある場合の決定論的な正確な出力チェックも含まれています。```python
# The solution function is the same algorithm as above.
import sys
import io
from itertools import permutations

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        n = int(sys.stdin.readline())
        values = list(map(int, sys.stdin.readline().split()))
        values += list(map(int, sys.stdin.readline().split()))

        values.sort()

        top_left = values[0]
        bottom_right = values[1]

        remaining = values[2:]
        m = len(remaining)
        need = n - 1

        total = sum(remaining)
        half = total // 2

        dp = [0] * (need + 1)
        dp[0] = 1

        history = [dp[:]]
        mask = (1 << (half + 1)) - 1

        for v in remaining:
            for j in range(need, 0, -1):
                dp[j] |= (dp[j - 1] << v) & mask
            history.append(dp[:])

        target = dp[need].bit_length() - 1

        top_internal = []
        bottom_internal = []

        j = need
        current = target

        for i in range(m, 0, -1):
            v = remaining[i - 1]

            if j > 0 and current >= v:
                previous = history[i - 1][j - 1]
                if (previous >> (current - v)) & 1:
                    top_internal.append(v)
                    current -= v
                    j -= 1
                    continue

            bottom_internal.append(v)

        top_internal.sort()
        bottom_internal.sort(reverse=True)

        top = [top_left] + top_internal
        bottom = bottom_internal + [bottom_right]

        print(*top)
        print(*bottom)

        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def max_path_sum(grid):
    top, bottom = grid
    n = len(top)

    best = 0
    for k in range(n):
        cur = sum(top[:k + 1]) + sum(bottom[k:])
        best = max(best, cur)

    return best

def parse_grid(out, n):
    lines = out.strip().splitlines()
    assert len(lines) == 2

    top = list(map(int, lines[0].split()))
    bottom = list(map(int, lines[1].split()))

    assert len(top) == n
    assert len(bottom) == n

    return [top, bottom]

def brute_optimum(values, n):
    best = 10**30

    # For these tests the values are small enough that exhaustive
    # permutation is practical.
    for p in set(permutations(values)):
        grid = [list(p[:n]), list(p[n:])]
        best = min(best, max_path_sum(grid))

    return best

def assert_optimal(inp):
    lines = inp.strip().splitlines()
    n = int(lines[0])
    original = list(map(int, lines[1].split()))
    original += list(map(int, lines[2].split()))

    out = solution(inp)
    grid = parse_grid(out, n)

    produced = grid[0] + grid[1]

    assert sorted(produced) == sorted(original), "output is not a permutation"

    expected = brute_optimum(original, n)
    actual = max_path_sum(grid)

    assert actual == expected, (
        f"not optimal: expected {expected}, got {actual}\n{out}"
    )

 ## 特殊なケース

 最初のエッジ ケースは (n=2) です。 可能なパスは 2 つだけであるため、内部グループにはそれぞれ 1 つの値が含まれます。 のために```
2
0 1
2 3
```ソートされた値は (0,1,2,3) です。 エンドポイントは (0) と (1) を受け取り、(2,3) を残します。 DP は値を 1 つ選択する必要があり、最良の選択は (2) です。 結果として得られるグリッドは、```
0 2
3 1
```2 つのパスの合計は (4) と (3) なので、答えは (4) になります。 よくある off-by-one の間違いは、(n-1) ではなく、(n) 個の残りの値を選択することです。これにより、間違った数のセルが行に残ることになります。 

2 番目のエッジ ケースは、すべての値が等しい場合です。 のために```
4
5 5 5 5
5 5 5 5
```エンドポイントは両方とも (5) であり、残りのすべてのサブセットは固定カーディナリティに対して同じ合計を持ちます。 DP は、残りの 6 つの値のいずれか 3 つを使用してターゲット (15) に到達します。 並べ替えると 4 つの行が 2 つ生成されます`5`s. 考えられるすべてのパスの合計は同じになるため、構築は最適になります。 

3 番目のエッジ ケースは、最適なサブセットの合計が残りの合計のちょうど半分である場合です。 のために```
3
0 100 200
300 400 500
```2 つのエンドポイント値は (0) と (100) です。 残りの合計は (1400) であるため、理想的な内部最高額は (700) です。 DP は (300+400=700) を求めます。 残りの値は (500) と (200) で、降順に配置されます。 結果として得られるグリッドは、```
0 300 400
500 200 100
```2 つの極端なパスは両方とも合計 (800) を持ち、凸性により中間パスより大きいパスはないことが保証されます。 これにより、厳密に半分を下回るサブセット合計のみを検索する実装が捕捉されます。 

4 番目のエッジ ケースは最大入力サイズです。 (n=25) の場合、(50) 枚の葉があり、最大の総エネルギーは (2.5\cdot10^6) です。 2 つの最小のエンドポイントを修正した後、DP は最大 (48) の値を処理し、その合計の半分までの合計のみが必要になります。 ビットセット表現により、Python ですべての状態について何百万もの合計を反復することなく、これが実現可能になります。 

最後の微妙なケースは、値が繰り返される場合です。 再構成は、個別の数値 ID ではなく、ソートされたリスト内の位置を使用して機能します。 複数のリーフが同じ値を持つ場合、出現箇所を選択すると同じ配置値が得られ、DP の後方再構成では一意の識別子を必要とせずにそれらの重複が自然に処理されます。
