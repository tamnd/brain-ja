 ## 問題の理解

 都市の有向加重グラフがあります。 市`1`それは首都であり、すべての指示された道路です`u -> v`容量がある`w`、最大でも重量の貨物を意味します`w`その道を横切ることができます。 

固定都市の場合`s`からのルート`s`首都までは複数の道路を利用できます。 同じ貨物がルート上のすべての道路に耐えられる必要があるため、その特定のルートでサポートされる最大貨物重量は、そのルートに沿った最小エッジ容量となります。 可能な限り最善のルートが必要なので、`s`からのすべてのルートにおける最大値です。`s`に`1`、そのルート上の最小エッジ キャパシティ。 首都へのルートがない場合、答えは次のとおりです。`-1`。 

公式の制限は次のとおりです`n <= 10^5`そして`m <= 10^6`、2 秒の時間制限と 512 MB のメモリ制限があります。 道路の数が十分に多いため、アルゴリズムは次のようなことを行うことができます。`O(nm)`は問題外です。 平`O(n^2)`大きすぎるとき`n`到達する`10^5`。 グラフをほぼ線形に処理する必要があるか、`m log n`時間。 エッジ容量は最大でも`10^9`したがって、Python 整数はオーバーフローを心配することなく直接それらを処理します。 

道路の方向によって、最初の共通の罠が発生します。 都市で終わる小道について質問しています`1`、そこから始まるパスではありません。 例えば：```
2 1
2 1 5
```答えは、`5`。 誤って都市から通常の検索を実行した場合`1`元のグラフ、都市の上に`2`に向かう唯一の道があるため、到達できません`1`。 

2 番目のトラップは、ルート上の最小エッジではなく最大エッジを取得しています。 考慮する：```
3 2
3 2 10
2 1 3
```答えは次のとおりです。```
3
```能力の道`10`能力を超えて役に立たない`3`道。 ルートのキャパシティがボトルネックになります。 

3 番目のトラップは、最初に見つかったパスを受け入れます。 考慮する：```
4 4
2 1 2
2 3 8
3 4 7
4 1 7
```都市の答え`2`は：```
7
7
-1
```すぐに取得する DFS`2 -> 1`記録するだろう`2`、 それでも`2 -> 3 -> 4 -> 1`体重を支える`7`。 この問題では、単に到達可能なパスではなく、最適なパスが求められます。 

最後に、到達できない都市は残らなければなりません`-1`。 例えば：```
3 1
2 1 4
```出力は次のとおりです。```
4
-1
```次のような不用意な初期化`answer[v] = 0`要求される答えが明確であるにもかかわらず、到達不可能な都市をあたかも重量ゼロの輸送が可能であるかのように見せることができます。`-1`。 

## アプローチ

 直接的な総当たりの解決策は、すべての都市から首都までの経路を列挙することです。 各パスについて、最小エッジ容量を取得してボトルネックを計算し、その開始都市で見られる最大のボトルネックを保持します。 考えられるすべてのルートが検査されるため、これは正しいです。 

問題はパスの数です。 完全な有向グラフでは、1 つのソースからの単純なパスを列挙する DFS が次のような問題に遭遇する可能性があります。`P(n-1,1) + P(n-1,2) + ... + P(n-1,n-1)`さまざまなパス、どこで`P(a,b) = a! / (a-b)!`。 すべての開始都市全体で、これは次の順序です。`n!`、処理できる範囲をはるかに超えています`n = 10^5`。 訪問状態の処理が追加されない限り、サイクルにより不注意なパス列挙がさらに悪化します。 

ブルート フォースはパスの最小エッジ キャパシティによって答えが定義されるため機能しますが、考えられるすべてのパスを個別に処理するため失敗します。 有益な観察は、パスの値がボトルネックである 1 つの数値で要約できることです。 都市から首都までの到達可能な最大のボトルネックがわかったら、もう 1 本の道路でパスを延長しても、最小限の操作でその値を変更するだけです。 

方向性の問題もあります。 すべての答えが都市へのルートを説明しているため、`1`、すべての道を逆向きにします。 本来の道`u -> v`容量の`w`逆エッジになる`v -> u`同じ容量で。 首都からへのルートになりました`u`反転したグラフでは、からのルートに正確に対応します。`u`元のグラフの首都に。 

これにより、問題は都市から始まる最大ボトルネック パス問題に変換されます。`1`。 ダイクストラスタイルの貪欲アルゴリズムでそれを解決できます。 暫定的な最小距離を選択する代わりに、現在知られている最大のボトルネックを持つ未処理の都市を繰り返し選択します。 今の街に価値があるなら`best[v]`そして逆エッジ`v -> u`容量がある`w`、そして到達`u`を通して`v`サポートします`min(best[v], w)`。 

その数値が改善されれば`best[u]`、新しい値を最大ヒープにプッシュします。 すべての拡張が適用されるため、ダイクストラを機能させるのと同じ貪欲な順序付けがここでも有効です。`min`、すでに既知のパスの値を増やすことはできません。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的、`O(n!)`密なグラフで |`O(n + m)`プラス再帰/パス状態 | 遅すぎる |
 | 最適 |`O((n + m) log n)`|`O(n + m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 反転グラフを作成します。 あらゆる本来の道に対して`u -> v`容量あり`w`、エッジを保存します`v -> u`同じ容量で。 これにより都市から遠ざかることになる`1`新しいグラフでは都市に向かって移動することに相当します`1`元のグラフでは。 
2.作成`best[v]`、都市に到達するために現在知られている最大のボトルネック容量`v`市内から`1`反転したグラフで。 セット`best[1]`道路がまだ使用されていないため、無限大に設定し、他のすべての値を に設定します。`-1`それらの都市には到達していないからです。 
3.置く`(infinity, 1)`最大優先度のキューに入れられます。 パイソンの`heapq`は最小ヒープであるため、容量を負の値として保存して使用します`(-capacity, vertex)`。 
4. 既知の最大のボトルネックがある都市をヒープから削除します。 ヒープ エントリが古い場合は、`best[v]`大きくなったので破棄します。 これは、ダイクストラのアルゴリズムで一般的に使用されるのと同じ遅延削除手法です。 
5. 反転エッジごとに`v -> u`容量あり`w`に到達することで得られるボトルネックを計算します。`v`そしてこの境界を越えます:```
candidate = min(best[v], w)
```もし`candidate > best[u]`、 アップデート`best[u]`新しい値をヒープにプッシュします。 貨物はすでに通過した部分と新しい道路の両方を満たさなければならないため、最小限が必要です。 

1. ヒープが空になるまで続行します。 その時点で、反転グラフの首都から到達可能なすべての都市には、考えられる最大のボトルネックがあります。 すべての都市は依然として同等です`-1`元のグラフでは資本に到達できません。 
2. 出力`best[2]`、`best[3]`、...、`best[n]`。 市`1`それ自体は要求されていません。 

### なぜ効果があるのか

 不変条件は、都市がいつでも`v`は現在の最大のボトルネックで抽出され、その値はすでに最適化されています。 もっと良い道があったと仮定してください`v`。 より良いパス上のまだ抽出されていない最初の頂点を考えてみましょう。 首都が最初に抽出され、パスは反転したグラフの外側に向かって進むため、同じパス上のその先行するパスはすでに抽出されているはずです。 その先行パスが処理されると、アルゴリズムは、より良いパスのプレフィックスのボトルネックに等しい次の頂点の候補を挿入します。 その候補者は少なくとも主張されているボトルネックである`v`。 キューは常に最大の候補を最初に抽出するため、`v`これより小さい値では抽出できませんでした。 したがって、最終的な値はすべて最適になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # rev[v] contains (u, w) for every original edge u -> v with weight w.
    rev = [[] for _ in range(n)]

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        rev[v].append((u, w))

    best = [-1] * n
    best[0] = 10**18

    # Python has a min-heap, so store negative bottlenecks.
    pq = [(-best[0], 0)]

    while pq:
        neg_value, v = heapq.heappop(pq)
        value = -neg_value

        # Ignore an outdated heap entry.
        if value != best[v]:
            continue

        for u, w in rev[v]:
            candidate = min(value, w)

            if candidate > best[u]:
                best[u] = candidate
                heapq.heappush(pq, (-candidate, u))

    sys.stdout.write("\n".join(map(str, best[1:])))

if __name__ == "__main__":
    solve()
```入力ループは、各道路を逆隣接エントリに変換します。 本来の道なら`u -> v`、到達`v`反転したグラフで次のことに移ります。`u`に保存します。`rev[v]`まさに必要な変換です。`best[0]`に初期化されます`10**18`これは、考えられるすべてのエッジ容量よりも安全に大きくなります。 記号的な無限大に初期化することもできますが、整数を使用するとボトルネックの計算が単純になります。 最初の遷移は次のようになります。`min(10**18, w) = w`。 

プライオリティ キューには負の値が含まれています。`heapq`最小ヒープを実装します。 したがって、実際のボトルネックが最大の頂点は、格納されている負の数が最小となり、最初に抽出されます。 

頂点はヒープに複数回入ることがあります。 たとえば、最初に容量に到達する可能性があります。`3`そして後に改善されました`7`。 このコードでは、ヒープを検索して古いエントリを削除するのではなく、古いエントリをそこに残します。 古いとき`(3, v)`エントリがポップされ、`value != best[v]`, したがって無視されます。 これにより、実装がシンプルになり、期待される内容が維持されます。`O((n+m) log n)`縛られた。 

比較は`candidate > best[u]`、 ない`>=`。 値が同じでは何も改善されません。同じ容量の道路が多数あるグラフでは、同じヒープ エントリの重複を避けることが役立ちます。 

グラフ アルゴリズム内には 1 ベースのインデックス操作はありません。 都市は次から変換されます`1..n`に`0..n-1`すぐに、だから街`1`頂点です`0`。 最後のスライス`best[1:]`出力から大文字を正確に削除します。 

Python の整数はオーバーフローせず、すべての容量は正で最大でも`10^9`。 余分な`10**18`Sentinel は首都にのみ使用され、出力には表示されません。
