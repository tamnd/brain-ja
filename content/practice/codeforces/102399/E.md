 ## 解決策
 ## 問題の理解

 (n) 人の乗客が左から右に番号が付けられた座席に座っています。 乗客 (i) は時刻 (t_i) にお腹が空いた。 温水タンクは全員の左側にあり、一度に使用できるのは乗客 1 人だけです。 乗客がタンクを使用し始めると、ちょうど (p) 分後に乗客はお湯を持って座席に戻ります。 

興味深いのは、席を立つときのルールです。 乗客 (i) がお腹が空くと、左側のすべての座席に目を向けます。 乗客が現在席を離れているために、それらの座席の 1 つでも空席がある場合、乗客 (i) は離れることを拒否し、座席で待ち続けます。 左側の座席がすべて埋まった最初の瞬間、乗客 (i) は出発します。 複数の乗客が同時に出発できる場合は、座席番号が最も小さい乗客が最初に出発します。 タスクは、すべての乗客の戻り時間を決定することです。 この解釈は、元​​の完全な声明および提供されたサンプルと一致します。 

制約が十分に大きいため、シミュレーションはイベントベースでなければなりません。 (n=100000) の場合、(O(n^2)) シミュレーションは約 (10^{10}) 回のチェックを実行できますが、これは 1 秒の制限をはるかに超えています。 (t_i) と (p) の値は (10^9) に達する可能性があるため、毎分シミュレーションするとさらに悪化します。 たとえば、時刻 0 および (p=10^9) に全員がお腹が空いた場合、最後の乗客は時刻 (10^{14}) 頃に戻ります。 時計自体を分刻みでシミュレートすることはできません。 

不注意な実装を簡単に破ってしまういくつかのエッジケースがあります。 1つ目は同時に起こる飢餓です。 例えば、```
3 2
0 0 0
```与える```
2 4 6
```乗客 1 が先に出発します。 乗客 2 と 3 は、左側に空席が見えるため、着席したままになります。 乗客 1 が戻ったら、乗客 2 は出発できますが、乗客 2 は外出しているため、乗客 3 は再び待たなければなりません。 

もう 1 つのエッジ ケースは、右側の乗客よりも空腹時間が大幅に遅い乗客です。 例えば、```
2 3
10 0
```与える```
13 3
```座席 1 が占有されているため、乗客 2 は時刻 0 に出発することができます。 乗客 1 は時刻 10 になって初めてお腹が空くので、答えは 13 になります。乗客が常に座席順に出発すると仮定した解決策では、これら 2 つが誤って逆転してしまいます。 

3 番目のエッジ ケースは、乗客がちょうど別の乗客が戻ってきたときにお腹が空いた場合です。 例えば、```
3 5
0 5 5
```与える```
5 10 15
```時刻 5 では、乗客 1 が戻ってきたのとちょうど同じタイミングで、乗客 2 はお腹が空いています。 乗客 2 はその時点で出発できます。 乗客 2 が出発したばかりで座席が空になっているため、乗客 3 は同時に出発することはできません。 イベントを不注意な順序で処理すると、誤って両方の乗客が同時に降車してしまう可能性があります。 

## アプローチ

 最も直接的なアプローチは、列車の状態をシミュレートすることです。 あらゆる瞬間に乗客を検査し、誰が降車できるかを判断します。 乗客はお腹が空いたときにちょうど出発でき、座席番号が小さい乗客は欠席することがありません。 すべてのイベントの後にすべて (n 人) の乗客を単純にスキャンする場合、すべての決定は実際の現在の状態に基づいて行われるため、シミュレーションは正確です。 

問題はコストです。 (O(n)) 個の重要なイベントが発生する可能性がありますが、各イベントの後にすべての (n) 人の乗客をスキャンすると、(O(n^2)) 個の作業が必要になります。 (n=100000) では、およそ (10^{10}) 枚の乗客小切手に相当します。 分ごとのシミュレーションは、答えが (10^{14}) まで大きくなる可能性があるため、さらに実用的ではありません。 

重要な観察は、乗客が必要とするのは、現在外出している人々に関する 1 つの特定の情報、つまりその中で最も小さい座席番号だけであるということです。 最小の欠席を(x)とする。 そうすれば、乗客 (i) はちょうど (x>i) のとき、または誰もいないときに出発できます。 1 から (i-1) までのすべての座席を検査する必要はありません。 

2 番目の有益な観察があります。 お腹が空いているが現時点で出発できない乗客は、座席の昇順に保管できます。 誰かが席に戻ると、待っている最も小さい乗客だけが席を立つことができる可能性があります。 その乗客が出発すると、新しく空いた座席が再び右側の乗客をブロックする可能性があります。 したがって、各戻り後にアクティブになる待機乗客は最大でも 1 人です。 

その結果、システム全体を一連のイベントとして処理できるようになります。 飢餓時間は初期のイベントです。 出発するすべての乗客は、タンクの使用終了時に将来の完了イベントを作成します。 Python では 2 つのミニヒープで十分です。1 つのヒープは時系列イベントを保存し、もう 1 つは待機中の乗客のインデックスを保存し、もう 1 つは遅延削除で現在不在の最小の乗客を追跡します。 

タンク自体には明示的なキューは必要ありません。 維持する`free_time`、すでに出発した乗客全員がタンクを使い終わる時刻です。 新しい乗客が時刻 (x) に出発した場合、その戻り時刻は次のとおりです。 

[
 \max(x,\text{自由時間})+p.
 】

 更新中`free_time`このようにして、タンクで待っている乗客を自動的に考慮します。 

ブルートフォース手法は、すべての状態を明示的に再構築するため機能しますが、(n) が大きくなると失敗します。 最小の欠席席のみが資格を制御するという観察により、フル スキャンをヒープ操作に置き換えることができ、シミュレーションを (O(n\log n)) に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適なイベントシミュレーション | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての乗客の空腹時間を読み取り、イベントを配置します`(t_i, 0, i)`イベントヒープに入れます。 タイプ`0`飢餓の出来事を表します。 乗客インデックスを最終的な順序キーとして使用すると、飢餓イベントが左から右に同時に発生します。 
2. メンテナンス`away`、席を離れた乗客の最小の山。 メンテナンスも行います`is_away[i]`これにより、ヒープ エントリがまだアクティブであるかどうかがわかります。 このヒープ内の最小のアクティブな値は、まさに最小の空シートです。 
3. メンテナンス`waiting`、お腹は空いたものの、左隣の人が不在のためまだ出発できない乗客を乗せたミニヒープ。 すべての乗客がこのヒープに入るのは最大 1 回で、ヒープから出るのは最大 1 回であるため、ここでは遅延削除は必要ありません。 
4. メンテナンス`free_time`。 乗客が定時に出発するとき`x`、計算します`finish = max(x, free_time) + p`。 彼らはすぐに出発するか、すでに戦車の列に入っている全員の後ろで待機するため、これが彼らの帰還時間です。 
5. 乗客の空腹事態が発生した場合`i`が発生した場合は、まず非アクティブなエントリを削除します`away`。 もし`away`空であるか、その最小のアクティブな乗客のインデックスがより大きいです`i`、すべての座席の左側`i`占領されている。 乗客`i`すぐに出発できるので、に追加してください`away`そして完成イベントをスケジュールします。 
6. それ以外の場合は乗客`i`まだ出発できません。 彼らのインデックスを`waiting`。 退出条件は現在外出している人が戻った場合にのみ成立するため、空腹時間自体を再度処理する必要はありません。 
7.乗客の完走イベント時`i`が発生した場合、乗客への応答としてそのイベント時間を記録します`i`そしてその乗客をもう離れていないというマークを付けます。 上部の掃除`away`heap は遅延して次に小さい空席を利用可能にします。 
8. 乗客が戻ってきたら、待っている最小の乗客を検査します。 それらのインデックスが残っている最小の欠席乗客よりも小さい場合、または欠席乗客がいない場合、待機している乗客は降車することが許可されます。 それらを次の場所に移動します`away`そして、タンクキューで完了をスケジュールします。 
9. イベント ヒープが空になるまでイベントを処理します。 すべての乗客には飢餓イベントが 1 つと完了イベントが 1 つだけ存在するため、シミュレーションでは (O(n)) 個のヒープ挿入と削除のみが実行されます。 

### なぜ効果があるのか

 不変条件とは、`away`には、現在空席の乗客が正確に含まれており、その最小のアクティブ要素は左端の空席です。 したがって、乗客 (i) は、ちょうどそのタイミングで出発することが許可されます。`away`が空であるか、その最小要素が (i) より大きいです。 の`waiting`ヒープには、以前にこのテストに失敗した空腹の乗客が正確に含まれています。 返却は空席を解消できる唯一のイベントであり、待機中の乗客に資格を与えることができる唯一のイベントです。 新たに対象となるすべての乗客のうち、最小のインデックスが最初に出発する必要があります。これはまさに最小要素です。`waiting`。 ついに、`free_time`では、すべてのタンクの使用状況が出発順にシリアル化されているため、記録されたすべての完了時間が、その乗客がお湯を受け取る実際の時間となります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    t = list(map(int, input().split()))

    # Event:
    # (time, type, passenger)
    # type 0 = hunger, type 1 = return.
    # Hunger events at the same time are processed before returns.
    events = [(t[i], 0, i) for i in range(n)]
    heapq.heapify(events)

    # Passengers currently away from their seats.
    away = []
    is_away = [False] * n

    # Hungry passengers who are still sitting because
    # somebody to their left is away.
    waiting = []

    answer = [0] * n

    # End time of the tank queue.
    free_time = 0

    while events:
        current_time, event_type, i = heapq.heappop(events)

        if event_type == 0:
            # Remove passengers who have already returned.
            while away and not is_away[away[0]]:
                heapq.heappop(away)

            if not away or away[0] > i:
                # Every seat to the left of i is occupied.
                is_away[i] = True
                heapq.heappush(away, i)

                start = max(current_time, free_time)
                finish = start + p
                free_time = finish

                heapq.heappush(events, (finish, 1, i))
            else:
                # Some smaller-indexed seat is empty.
                heapq.heappush(waiting, i)

        else:
            # Passenger i returns to their seat.
            answer[i] = current_time
            is_away[i] = False

            while away and not is_away[away[0]]:
                heapq.heappop(away)

            # At most one waiting passenger can leave now.
            if waiting:
                candidate = waiting[0]

                if not away or away[0] > candidate:
                    heapq.heappop(waiting)

                    is_away[candidate] = True
                    heapq.heappush(away, candidate)

                    start = max(current_time, free_time)
                    finish = start + p
                    free_time = finish

                    heapq.heappush(events, (finish, 1, candidate))

    print(*answer)

if __name__ == "__main__":
    solve()
```イベント ヒープには両方の種類のイベントが含まれているため、無関係な瞬間のシミュレーションが回避されます。 空腹イベントは、同じタイムスタンプで返品イベントの前に命令されます。 これが必要なのは、乗客はその時点で空腹を判断する一方、すでに外出していた乗客は、帰国イベントが処理されるまでは依然として不在とみなされているためです。 

の`away`heap は通常のセットとは少し異なります。 Python には組み込みの順序付きセットが提供されていないため、実装では遅延削除が使用されます。 乗客が戻ってきたら、`is_away[i]`false になりますが、古いヒープ エントリは一時的に残ります。 最小限が必要な場合は常に、非アクティブなエントリが先頭から削除されます。 

条件`away[0] > i`オリジナルのシートルールをコンパクトにしたものです。 最も小さい空席が乗客の右側にある場合`i`の場合、座席 (1) ～ (i-1) の間に空席は存在しません。 

の`waiting`ヒープは乗客インデックス順に並べられます。これは、返品によって誰かが適格になると、左端の適格な乗客が優先されるためです。 最小限の要素のみを検査する必要があります。 出発するとすぐに席が空いてしまうため、待っている大人数の乗客も同時に出発することはできません。`free_time`完了イベントが挿入される前に更新されます。 現在タンクがアイドル状態の場合、乗客は出発時刻に出発します。 誰かがすでにタンクを使用しているか、タンクを待っている場合、乗客は次から開始します。`free_time`。 Python の整数は、オーバーフローすることなく、(10^{14}) 程度の最大の答えを処理します。

 ## 特殊なケース

 1人乗りのケースにはまったく詰まりがありません。 のために```
1 7
0
```乗客 1 は時刻 0 に直ちに出発し、時刻 7 までタンクを使用します。答えは次のとおりです。`7`。 アルゴリズムは空のものを認識します`away`飢餓イベントを処理するときにヒープが生成されるため、乗客はすぐに入場できます。 

全員が同時にお腹が空いたら、一番左の乗客が先に出発し、他の乗客は待たなければなりません。 のために```
3 2
0 0 0
```乗客 1 は 0 時に出発し、2 時に戻ります。乗客 2 と 3 は に配置されます。`waiting`。 時刻 2 で、乗客 1 が乗客から降ろされます。`away`、乗客 2 は資格を得て出発し、乗客 3 は乗客 2 によってブロックされたままになります。したがって、乗客の戻り時間は 2、4、6 になります。 

右端の乗客は、左端の乗客より前に合法的に水を受け取ることができます。 のために```
2 3
10 0
```乗客 2 は時刻 0 でお腹が空いており、座席 1 は占有されているため、乗客 2 はすぐに出発し、3 時に戻ります。乗客 1 は時刻 10 でお腹が空くだけで、13 時に戻ります。アルゴリズムでは、座席番号が出発順序を決定することは想定されていません。 

ラージ (p) の場合は、アルゴリズムがクロック シミュレーションではなくイベント時間を使用する必要がある理由を示しています。 と```
3 1000000000
0 0 0
```3 人の乗客は (10^9)、(2\cdot10^9)、および (3\cdot10^9) で戻ります。 このプログラムは、シミュレートされた膨大な時間間隔にもかかわらず、乗客ごとに一定数のヒープ操作のみを実行します。 

最も微妙な境界は、別の乗客が戻ってきたときに正確に飢餓イベントが発生することです。 この実装により、イベント キューに決定的な順序が与えられ、適格性テストに使用される状態は適切なイベントでのみ更新されます。 これにより、小さい空席がまだ存在する間に乗客が誤って降車することが防止され、また、複数の乗客が同時に適格になった場合でも、左から右への優先順位が維持されます。 いくつかの空腹イベントと返品イベントがサービス期間ごとに正確に区切られているため、サンプル自体はこの相互作用の優れたストレス テストになります (p=314)。
