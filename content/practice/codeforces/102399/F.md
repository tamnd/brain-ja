 ## 問題の理解

 最初は空である、個別の整数の動的なセット (A) を維持します。 挿入または削除のたびに、(0 \le x \le k) を使用して XOR マスク (x) を選択した後に MEX がどの程度小さくなるかを決定する必要があります。 

固定マスク (x) の場合、送信されたセットは、すべての (a\in A) を (a\oplus x) に置き換えることによって取得されます。 その MEX は、(y\notin{a\oplus x\in A}) に対する最小の非負の整数 (y) です。 許可されるすべての (x) に対してこの MEX の最小値が必要です。 

すべての値は 20 ビットに収まるため、(A) で発生する可能性のある値は (2^{20}=1,048,576) のみです。 更新の数はさらに多く、最大 (200,000) です。 このため、更新のたびに値ドメイン全体をスキャンするソリューションは不可能になります。 (O(2^{20}q)) でさえ約 (2.1\cdot10^{11}) の演算であり、2 秒のコンテスト ソリューションで実現できる範囲をはるかに超えています。 固定 (20) ビット ユニバースに依存する前処理が必要ですが、各更新のコストは最大対数時間でなければなりません。 

誤って処理されやすい境界ケースがいくつかあります。 空集合もその 1 つです。 例えば、```
1 0
1 5
```出力があります```
0
```なぜなら、変換されたセットはまだ空であり、その MEX は (0) であるからです。 何らかの変換された値が存在することを前提としたソリューションでは、この問題が発生します。 

もう 1 つの重要なケースは、(0) から (k) までのすべての値がすでに (A) にある場合です。 例えば、```
3 2
1 0
1 1
1 2
```出力があります```
0
0
1
```3 回目の更新後、許可される XOR マスクはすべて (0,1,2) になるため、どれもすぐに (0) を消すことはできません。 答えは(1)になります。 (0) 自体が (A) に存在しないかどうかだけをチェックする不注意な実装では、XOR 演算の効果が失われます。 

XOR 範囲の上限も重要です。 (k=2^{20}-1) の場合、可能なすべての 20 ビット値がマスクとして許可されます。 (2^{20}) 個の可能な値が存在する一方で、最大で (200,000) 個の値が存在するため、一部の値 (z) が欠落しており、(x=z) を選択できます。 すると (z\oplus x=0) となるので、答えは常に (0) になります。 (x=k) が許可されていることを忘れると、ここで off-by-one エラーが発生します。 

最後に、(A) の値はゼロに近い必要はありません。 例えば、```
1 2
1 7
```出力があります```
0
```(0) が欠落しており、(x=0) を選択するとすでに MEX (0) が得られるためです。 現在保存されている値のみを検索するソリューションは不必要であり、不正確になる可能性があります。 

## アプローチ

 直接的なアプローチは、許可されているすべてのマスク (x) を試すことです。 それぞれの (x) について、変換されたセットを構築または概念的に検査し、その MEX を見つけることができます。 (|A|=n) の場合、その MEX は最大でも (n) であるため、単純な実装で (0,1,\ldots,n) のメンバーシップをテストできます。 最悪の場合、更新ごとに (O((k+1)n)) のコストがかかります。 (q=200,000)、(k) が (2^{20}) に近く、(n) が (200,000) に近い場合、最悪のケースはおおよそ次のようになります。 

[
 200,000\cdot1,048,576\cdot200,000
 \約 4.2\cdot10^{16}
 ]

 会員チェック。 MEX 計算をより高速なデータ構造に置き換えても、更新のたびにすべての (2^{20}) マスクを試すのはすでにコストが高すぎるため、アプローチは節約されません。 

重要な観察は、MEX をマスクごとに個別に計算する必要があるものとして考えるのをやめるということです。 

マスク (x) を修正します。 その MEX は最小の (y) であるため、(y) は変換されたセットに属しません。 条件 (y\notin{a\oplus x\in A}) は次と同等です。 

[
 A に y\oplus x\not を加えます。 
]

 しましょう

 [
 z=y\oplus x。 
]

 この場合、(z) は単に (A) から欠落している値であり、

 [
 y=x\oplus z。 
]

 その結果、

 \min_{z\notin A}(x\oplus z)。 
]

 許容される最良の値 (x) を取得すると、

 \min_{z\notin A}\min_{0\le x\le k}(x\oplus z)。 
】

 これにより問題は完全に変わります。 考えられるすべての値 (z) に対して、静的関数を定義します。 

[
 g(z)=\min_{0\le x\le k}(x\oplus z)。 
]

 そうすると、答えは単純です

 [
 \boxed{\min_{z\notin A}g(z)}。 
]

 集合 (A) は動的ですが、(g) は (k) にのみ依存します。 値 (g(z)) を前処理し、現在欠落している値 (g) のそれぞれの値がいくつあるかを数え、空ではない最小のバケットを維持できます。 

もう 1 つ便利な境界があります。 (A) に現在 (n) 個の値が含まれている場合、変換されたすべてのセットにも (n) 個の値が含まれるため、その MEX は最大でも (n) です。 したがって、最終的な答えは最大でも (n\le q) になります。 (g(z)>q) でバケットを維持する必要はありません。 

残りのタスクは、(g(z)) をすばやく計算することです。 これは、(z) と (k) のバイナリ表現を使用して定数時間で実行できます。

 ## アルゴリズムのチュートリアル

 1. 希望する答えを次のように書き換えます。 

[
 \min_{z\notin A}g(z),
 \qquad
 g(z)=\min_{0\le x\le k}(z\oplus x)。 
】

 これは、固定 (x) の場合、(A) のすべての欠損値 (z) が (A\oplus x) の欠損値 (y=z\oplus x) に全単射的に対応するため機能します。 
2. 単純に (x=z) を選択できるため、(z\le k) の場合は常に (g(z)=0) であることを観察します。 

したがって、すべての値 (0,1,\ldots,k) は同じバケット (g=0) に属します。 
3. (z>k) の場合、(z) と (k) を最上位ビットから比較します。 (z>k) であるため、最も高い異なるビットでは、(z) は (1) を持ち、(k) は (0) を持ちます。 

許可された (x) はそのビットを (z) と等しく保つことができないため、XOR にはそのビットが含まれている必要があります。 修正すると下位ビットは(z)と(k)の下位部分と同じ問題になります。 
4. しましょう

 [
 d=z\oplus k.
 】

 (z) と (k) が異なり、(k) に (1) が含まれるビットは、正確に次の設定ビットです。 

[
 d\mathbin{&}k.
 】

 そのような最上位のビットが (r) である場合、貪欲なプロセスはそこで停止します。そのビットでは (z) が (0) で、(k) が (1) なので、選択された (x) はすでに厳密に (k) より小さくなります。 すべての下位ビットを自由に一致させることができます。 

したがって、もし`bad = d & k`、その後

 [
 g(z)=(d\mathbin{&}\neg k)
 \数学ビン{&}
 \left(-2^{\オペレーター名{ビット長}(悪い)}\right)。 
]

もし`bad`がゼロの場合、そのような停止ビットは存在しないため、

 [
 g(z)=d\mathbin{&}\neg k.
 】
 5. それぞれの (g(z)\le q) に含まれる値 (z\in[0,2^{20})) の数を事前計算します。 答えが (q) を超えることはないため、(g(z)) より大きい値は無視できます。 

最初はすべての値 (z) が (A) から欠落しているため、これらのカウントは完全な欠落セットを表します。 
6. (0) から (q) までのすべての可能なバケット値を含む最小ヒープを維持します。 それと並行してメンテナンスも行います`cnt[v]`、現在欠落している (z) の数 (g(z)=v)。 

(A) に値が挿入されると、そのバケットは欠損値を 1 つ失います。 (A) から削除されると、そのバケットには欠損値が 1 つ追加されます。 
7. 更新のたびに、バケット数が 0 のヒープ エントリを削除します。 残りの最小ヒープ値は正確に

 [
 \min_{z\notin A}g(z),
 】

 これは必要最小限の可能な MEX です。 

不変条件とは、`cnt[v]`は常に (A) に現在存在しない値の数に等しく、許可されたマスクとの最良の XOR は正確に (v) になります。 ヒープは候補バケット インデックスを表しますが、カウントがゼロのバケットは遅延して破棄されます。 したがって、ヒープの最小値は常に、すべての欠落している (z) の中で最小の (g(z)) となり、上記の変換により、元の問題に対する正確な答えになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

LIMIT = 1 << 20

def solve():
    q, k = map(int, input().split())

    cnt = [0] * (q + 1)

    # Every z in [0, k] has g(z) = 0.
    cnt[0] = k + 1

    not_k = ~k

    # For z > k, compute g(z) in O(1).
    for z in range(k + 1, LIMIT):
        d = z ^ k
        bad = d & k

        g = d & not_k

        if bad:
            # Keep only bits strictly above the highest bit of bad.
            g &= -(1 << bad.bit_length())

        if g <= q:
            cnt[g] += 1

    # Initially every bucket is a candidate.
    heap = list(range(q + 1))
    heapq.heapify(heap)

    # True means that this bucket currently has an entry in the heap.
    in_heap = [True] * (q + 1)

    def get_g(z):
        if z <= k:
            return 0

        d = z ^ k
        bad = d & k

        g = d & not_k

        if bad:
            g &= -(1 << bad.bit_length())

        return g

    ans = []

    for _ in range(q):
        typ, z = map(int, input().split())
        g = get_g(z)

        if g <= q:
            if typ == 1:
                # z becomes present, so it is no longer missing.
                cnt[g] -= 1
            else:
                # z becomes missing again.
                if cnt[g] == 0 and not in_heap[g]:
                    heapq.heappush(heap, g)
                    in_heap[g] = True
                cnt[g] += 1

        while cnt[heap[0]] == 0:
            v = heapq.heappop(heap)
            in_heap[v] = False

        ans.append(str(heap[0]))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```前処理は次から始まります`cnt[0] = k + 1`(0) から (k) までのすべての値は、許可された間隔からの XOR 距離が 0 であるためです。 (k) より大きい値のみがビット単位の式を必要とします。 

このような値の場合、`d = z ^ k`2 つの数値が異なる位置を正確に記録します。 表現`d & ~k`(k) がゼロを持つ異なる位置を保持します。これらの位置は、必ず最小の XOR に寄与する位置です。 もし`bad = d & k`がゼロ以外の場合、その最上位の設定ビットは、(z) が 0、(k) が 1 である最初の下位位置を識別します。 表現`-(1 << bad.bit_length())`その位置より下のすべてのビットをクリアします。 

更新自体には (g(z)) の計算が 1 回だけ必要です。 値が欠落しなくなるため、挿入によりバケットが減ります。 削除すると、値が再び欠落するため、バケットが増加します。 

ヒープは怠惰です。 バケットは、カウントがゼロになってもすぐには削除されません。 代わりに、クリーンアップ ループは、カウントがゼロのバケットが先頭に達した場合にのみ削除します。 の`in_heap`配列は、バケットが再び空でなくなったときに、不要な重複ヒープ エントリを防ぎます。 

すべての算術演算は整数のみです。 ここでは、Python 整数にはオーバーフローの問題はなく、関連する値はすべて 20 ビット ドメイン内に快適に収まります。

1 0
1 0
```許可される唯一のマスクは (x=0)、変換されたセットは ({0}) であるため、答えは (1) です。 アルゴリズムはバケット内の 1 つの欠損値 (g=0) から始まり、(0) を挿入するとそのバケットが空になります。 次の欠損値には (g=1) があるため、ヒープは (1) を報告します。 

のために```
3 2
1 0
1 1
1 2
```最初のゼロバケットには (0,1,2) が含まれます。 挿入するたびに、欠落しているセットからこれらの値の 1 つが削除されます。 3 回目の挿入の後、そのカウントは 0 に達します。 残っている最小のバケットは (g(3)=1) であるため、出力は (1) になります。 

最大マスク境界については、```
2 1048575
1 0
1 1048575
```許可されるマスクは 20 ビット ユニバース全体をカバーします。 まだ多くの欠損値があり、欠損値 (z) 自体は許可されたマスクです。 (x=z) を選択すると (z\oplus z=0) となるため、(g(z)=0) になります。 したがって、バケット (0) は空ではないままとなり、答えは (0) のままになります。 

(x\le k) と (x<k) の間の 1 つずつの区別は、条件によって処理されます。`z <= k`。 (z=k) の場合、(x=k) を選択すると XOR (0) が得られるため、(g(k)=0) になります。 (k) を除外すると、この値が誤って正のバケットに移動されます。 

(z>k) の式は、最初の強制 XOR ビットが唯一の寄与ビットではない場合も処理します。 (k=2) と (z=7) の場合、バイナリ表現は (010) と (111) になります。 最小値は (4) ではなく (7\oplus2=5) です。 ここ`d = 5`、`bad = 0`したがって、式は両方の寄与ビットを保持し、(g(7)=5) を取得します。 (z=5) では、次のようになります。`d = 7`そして`bad = 2`、その最上位ビットがストップビットです。 より低い寄与がクリアされ、(g(5)=4) が得られます。 これらのケースはまさに、最上位の異なるビットのみを使用することが正しくない理由です。
