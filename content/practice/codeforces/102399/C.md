 ## 解決策
 ## 問題の理解

 (n \times m) 個の長方形グリッドがあり、そのセルは 2 色で着色されています。 2 つのセルが 1 面を共有している場合、隣接セルとなります。 すべてのセルに同じ色の隣接セルが最大 1 つある場合、その色付けは有効です。 

タスクは、グリッドの有効な色をすべてカウントし、結果のモジュロ (10^9+7) を出力することです。 グリッドの次元はそれぞれ (100,000) に達する可能性があるため、セルの数は (10^{10}) に達する可能性があります。 考えられるすべての色付けを明示的に処理するメソッドは絶望的であり、状態がより小さい次元に指数関数的に依存するメソッドであっても、(10^5 \times 10^5) グリッドを処理することはできません。 問題を次元ごとに一定の作業量に削減する必要があります。 

推論の間違いを明らかにする小さな事件が 2 つあります。 (1\times1) グリッドの場合、両方の色が有効であるため、答えは (2) になります。 すべてのセルに 4 つの隣接セルがあると仮定する方法、または (n=2) から開始する反復を盲目的に適用する方法では、これが誤られる可能性があります。 (1\times3) グリッドの場合、有効な文字列はすべてバイナリ文字列であり、3 つの等しい連続セルがないため、(6) 色が与えられます。 隣接する等しいセルのみを禁止する不用意なアプローチでは、2 つの交互の文字列のみがカウントされ、(001) などの色付けが見逃されます。 

(2\times2) グリッドの場合、答えは (6) です。 4 つのセルをすべて同じ色にすることはできません。また、多数色のセルの 1 つが 2 つの等しい隣接セルを取得するため、一方の色と他方の色の 3 つのセルによる配色も無効です。 これは、多くても 1 つの等しい隣接する実際の条件と、すべての隣接する色が反対の色でなければならないというより強力で誤った条件を区別するため、便利なチェックです。 

## アプローチ

 直接的なアプローチは、(2^{nm}) 個の色をすべて列挙することです。 それぞれの色について、すべてのセルを検査し、同じ色の隣のセルを数えることができます。 これは正しいことです。考えられるすべてのカラーリングが考慮され、必要な条件に正確に照らしてチェックされるからです。 最悪の場合の仕事量は (O(nm,2^{nm})) です。 (n=m=100,000) の場合、(10^{10}) 個のセルと (2^{10^{10}}) 個の可能な色が存在するため、検索空間を書き留めることさえ不可能です。 

有益な観察は、色について直接考えるのをやめ、代わりに同じ色を持つ隣接するセルのすべてのペアにマークを付けることです。 セルには同色の隣接セルが最大 1 つしか存在しないため、これらのマークされたエッジは一致を形成します。つまり、2 つのマークされたエッジがセルを共有することはできません。 

ここで、そのようなエッジの向きを考えてみましょう。 水平方向に隣接する 2 つのセルが同じ色であるとします。 各エンドポイントは、唯一許可されている同じ色の隣接セルをすでに使用しているため、そのすぐ上のセルが存在する場合、そのセルは反対の色を持つ必要があります。 同じ引数により、水平方向の同色のペアがすべての行に伝播されます。 したがって、単一の水平方向の同色のエッジにより、カラーリング全体が水平方向の同色のエッジのみを持つように強制されます。 垂直エッジは垂直方向に伝播し、最終的には強制された水平構造と衝突するため、このようなカラーリングでは垂直の同じ色のエッジはどこにも発生しません。 同じ議論は、水平と垂直を入れ替えても機能します。 この構造観察がソリューション全体の鍵となります。 

したがって、有効なカラーリングはすべて 2 つのファミリーの少なくとも 1 つに属します。 最初のファミリーには垂直方向の同じ色のエッジがないため、すべての列が垂直方向に交互になります。 2 番目のファミリーには水平方向の同じ色のエッジがないため、すべての行が水平方向に交互になります。 両方のファミリーに属する唯一のカラーリングは、2 つのチェッカーボード カラーリングです。

最初の家族について考えてみましょう。 すべての列が垂直方向に交互に配置されるため、グリッド全体は最初の行によって決まります。 最初の行には、連続する 3 つのセルが決して等しくないバイナリ文字列を指定できます。 最初の行が選択されると、残りの行はすべて垂直方向の交互に強制的に選択されます。 最初のセルの色が固定されている場合、(f_k) を長さ (k) の有効な文字列の数とします。 最初の 2 つの値は (f_1=1) と (f_2=2) です。 (k\ge3) の場合、最初のセルを修正した後、最後のブロックは前の文字列を 1 つのセルまたは 2 つの等しいセルだけ拡張できます。 

[
 f_k=f_{k-1}+f_{k-2}。 
】

 最初のセル自体には 2 つの可能な色があるため、このファミリーには (2f_m) 個のグリッドが含まれます。 

対称性により、水平方向の同色のエッジがないファミリーには (2f_n) 個のグリッドが含まれます。 それらの交差点は、まさに 2 つのチェッカーボードで構成されます。 包含排除により、

 2(f_n+f_m-1)。 
】

 これは、この問題に使用される標準的な特徴付けです。

 ## アルゴリズムのチュートリアル

 1. (n) と (m) を読み取り、(L=\max(n,m)) とします。 より大きな次元までのフィボナッチのような値のみが必要です。 
2. (f_1=1) と (f_2=2) を定義します。 (3) から (L) までのすべての (i) について、計算します。 
[
 f_i=f_{i-1}+f_{i-2}\pmod{10^9+7}。 
】
 これは、最初の色が固定され、同じ色が 3 つ連続しない、長さ (i) のバイナリ文字列をカウントします。 
3. 縦方向に同色のエッジがないカラーリングを (2f_m) でカウントします。 係数 (2) は最初のセルの色を選択し、その後、垂直方向の交互に各列の残りの部分が決定されます。 
4. 引数を (90^\circ) だけ回転させると、水平方向の同色のエッジがない色が (2f_n) だけカウントされます。 
5. 2 つのファミリーは、正確に 2 つの市松模様の色で重なり合っています。 これら 2 つの重複した色を 1 回減算すると、
 [
 2f_n+2f_m-2。 
】
 6. 印刷
 [
 2(f_n+f_m-1)\pmod{10^9+7}。 
】

 カウントの背後にある不変条件は、同じ色の隣接するペアを持つ有効なカラーリングはすべて、そのようなペアに対して可能な方向が 1 つだけであるということです。 その方向が選択されると、垂直方向が交互になる必要があり、残りの自由は、連続する 3 つの同じ色がないまさに 1 次元のバイナリ文字列になります。 2 つの可能な方向は 2 つのチェッカーボードを除いて互いに素であるため、包含/除外式ではすべての有効な色が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    limit = max(n, m)

    if limit == 1:
        f1 = 1
    else:
        f1, f2 = 1, 2

        for _ in range(3, limit + 1):
            f1, f2 = f2, (f1 + f2) % MOD

    if n == 1:
        fn = 1
    elif n == 2:
        fn = 2
    else:
        a, b = 1, 2
        for _ in range(3, n + 1):
            a, b = b, (a + b) % MOD
        fn = b

    if m == 1:
        fm = 1
    elif m == 2:
        fm = 2
    else:
        a, b = 1, 2
        for _ in range(3, m + 1):
            a, b = b, (a + b) % MOD
        fm = b

    print((2 * (fn + fm - 1)) % MOD)

if __name__ == "__main__":
    solve()
```再帰計算は (\max(n,m)) まで 1 回だけ計算できます。これはより簡単で、2 つの別々のループを実行する必要がありません。 上記の実装では境界ケースが明示的に保たれていますが、コンパクトな配列ベースの実装も可能です。 

値 (f_1=1) と (f_2=2) は、通常のフィボナッチ初期化 (1,1) ではありません。 ここではそれらは直接的な組み合わせの意味を持ちます。 最初の色が固定されている場合、長さ 1 の文字列が 1 つあり、長さ 2 の文字列が 2 つあります。2 番目のセルはどちらの色でも構いません。 

Python の整数はオーバーフローしませんが、いずれにしても、すべての反復値はモジュロ (10^9+7) で減算されます。 (1) の減算は最後の乗算の前に行われ、最後の乗算が行われるため、Python では法を加算する必要はありません。`% MOD`負の中間値を正しく処理します。 

より効率的な実装では、すべての値を配列に格納し、(f_n) と (f_m) を直接読み取ることができます。 ローリング バージョンは定数補助メモリのみを使用し、2 つの次元が個別に処理される場合には十分です。 

## 実用的な例

 提供されたサンプル (n=2、m=3) の場合、漸化式により (f_1=1)、(f_2=2)、および (f_3=3) が得られます。

2 番目の例として、(n=1,m=3) を取り上げます。 繰り返し値は再び (f_1=1、f_2=2、f_3=3) になります。 

| ステップ | 寸法 | (f_{i-2}) | (f_{i-1}) | (f_i) |

 | イニシャル | 2 | 1 | 2 | |

 式は次のようになります

 [
 2(f_1+f_3-1)=2(1+3-1)=6。 
】

 これら 6 つの文字列は、(000) と (111) を除いた長さ 3 のバイナリ文字列です。 これにより、2 次元の引数が縮退した 1 行グリッドも正しく処理できることが確認されます。

import io

MOD = 10**9 + 7

def solve_data(data: str) -> str:
    n, m = map(int, data.split())

    limit = max(n, m)
    f = [0] * (limit + 1)

    f[1] = 1
    if limit >= 2:
        f[2] = 2

    for i in range(3, limit + 1):
        f[i] = (f[i - 1] + f[i - 2]) % MOD

 ## 特殊なケース

 のために`1 1`、再発には (f_1=1) のみが含まれます。 式は次のようになります

 [
 2(1+1-1)=2。 
】

 セルは 1 つだけなので、2 つの色のいずれかが有効な色を生成します。 隣接するものの不在は、公式によって自然に処理されます。 

のために`1 3`、グリッドは単なるバイナリ文字列です。 中央のセルには 2 つの等しい隣接セルがあるため、有効な文字列には 3 つの等しい連続セルを含めることはできません。 6 つの有効な文字列は、(2f_3=6) によってカウントされた文字列とまったく同じです。 数式は同じ結果を返します。 

[
 2(f_1+f_3-1)=2(1+3-1)=6。 
]

のために`2 2`, (f_2=2) なので、

 [
 2(f_2+f_2-1)=2(2+2-1)=6。 
】

 6 つの有効なカラーリングには、2 つのチェッカーボードと、1 組の等しい隣接セルを持つ 4 つのカラーリングが含まれます。 このケースでは、2 つの方向ファミリーが単純に追加されるのではなく、正確に 2 つのカラーリングによってオーバーラップする必要があることが確認されています。 

のために`2 3`、漸化式では (f_2=2) と (f_3=3) が得られます。 水平エッジ ファミリが寄与し (2f_2=4)、垂直エッジ ファミリが寄与し (2f_3=6)、2 つのチェッカーボードが両方のファミリで発生します。 最終的なカウントは (4+6-2=8) で、サンプルと一致します。 

のために`100000 100000`特別な数学的ケースは必要ありません。 反復は各ステップで法 (10^9+7) で評価されるため、値は小さいままであり、答えは 2 つの同一の値 (f_{100000}) から得られます。 実行時間は、グリッドの (10^{10}) セルではなく、(100,000) で線形のままです。
