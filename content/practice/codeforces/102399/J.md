 ## 解決策
 ## 問題の理解

 (n) 人の住民と (n) 匹の猫がいます。 居住者 (i) は猫 (i) を飼っています。 それぞれの知人関係は、住人(a)から猫(b)への有向辺で表現され、住人(a)が猫(b)のことを知っていることを意味します。 すべての居住者が自分の猫を知っているため、すべての頂点に自己ループがあります。 

(n) 個のインデックスを 2 つの空でないセットに分割する必要があります。 最初のセットが陪審員となり、これらの指標が住民としてみなされることを意味します。 2 番目のセットは参加者になります。これは、これらのインデックスが猫として取得されることを意味します。 サイズの合計は (n) になる必要があるため、すべてのインデックスは 2 つのセットのいずれかに正確に属している必要があります。 陪審員は、参加する猫の知り合いであってはなりません。 

最後の条件には、グラフの解釈に役立つものがあります。 インデックス (a) が陪審員に割り当てられ、エッジ (a \to b) があると仮定します。 すると猫(b)は参加者にはなれないので、猫(b)も審査員に所属しなければなりません。 したがって、頂点がジュリーに入れられるときは常に、1 つの出力エッジによって到達可能なすべての頂点もそこに入れられる必要があります。 陪審は、出力エッジの下で閉じられた空ではない適切なサブセットです。 

この制約は、線形グラフ アルゴリズムを強く示唆しています。 すべてのテストにわたって、最大 (10^6) 個の頂点と (10^6) 個の知り合いエッジが存在する可能性があります。 (O(n^2)) ですら大きすぎますが、(O(n+m)) が適切です。 また、テスト ケースの数が多いということは、実装では各エッジを一定の回数だけ処理し、再帰的 DFS ではなく反復グラフ トラバーサルを使用する必要があることも意味します。これは、(10^6) 個の頂点を持つグラフは Python の再帰制限を簡単に超えて、過剰な呼び出しスタックのオーバーヘッドが発生する可能性があるためです。 

不注意な建設を欺いてしまう可能性のあるいくつかの特殊なケースがあります。 

(n=1) の場合、可能な唯一の分割には陪審員がいないか、参加者がいないことになります。 必要な出力は次のとおりです`No`。```
1
1 1
1 1
```到達可能なセットまたは到達不可能なセットを盲目的に選択する構造では、誤って空のサイドが生成される可能性があります。 

強く接続されていないグラフの場合、エッジが多くても答えは存在します。 例えば、```
2
2 3
1 1
2 2
1 2
```答えは陪審員 ({2}) と参加者の猫 ({1}) です。 住人 2 は猫 2 しか知らないので、交差条件は満たされます。 ゼロ度の頂点を見つけることに固執する不用意なアプローチでは、両方の頂点に外向きのエッジがあるため、これを見逃してしまいます。 

グラフの方向も重要です。 考慮する```
3
3 4
1 1
2 2
3 3
2 1
```ここでは、居住者 1 は猫 1 しか知らないため、陪審 ({1}) が機能します。頂点 1 に到達できない頂点のセットは ({2,3}) であり、これも有効な陪審を形成します。 知人を無向関係として扱う実装では、たとえその条件が陪審員の居住者から参加者の猫へのエッジのみを禁止しているにもかかわらず、頂点 1 と 2 が同じ側になければならないと誤って結論付けることになります。 

最後に、すべての頂点が他のすべての頂点に到達できる場合、解決策は存在しません。 例えば、```
2
2 4
1 1
1 2
2 1
2 2
```どちらかの頂点をジュリーに入れると、到達可能性によってもう一方の頂点も強制的にジュリーに入れられます。 したがって、空でないすべての閉集合はグラフ全体となり、参加者は残りません。 

## アプローチ

 直接的な総当たりアプローチでは、可能なすべての陪審のサブセットを列挙することになります。 (2^n) 個の部分集合があり、空集合と完全集合は無効であり、(2^n-2) 個の候補が残ります。 すべての候補者について、すべて (m) 個の知人エッジをスキャンし、何らかのエッジが陪審員内で始まり、陪審員外で終了する場合、そのエッジを拒否することができます。 これは、考えられるすべてのパーティションが検査されるため正しいですが、最悪の場合の作業量は ((2^n-2)m) であり、(n=10^6) はおろか (n=30) にとってもすでに巨大です。 

実際に選択できるのはどのインデックスが陪審員に属するかだけであるため、総当り攻撃が機能します。 重要なのは、選択したサブセットが有効になる理由を理解することです。 (a) が陪審員にいて、優位性がある場合 (a\to b)、(b) も陪審員に入れなければなりません。 この議論を繰り返すと、ジュリー頂点から到達可能なすべての頂点がジュリーに含まれなければならないことがわかります。 グラフの用語では、外向きのエッジの下で閉じられた空ではない適切なセットが必要です。 

これにより、問題はすぐに到達可能性に結びつきます。 頂点 1 から開始します。頂点 1 から到達できない頂点がある場合は、そのような到達できない頂点をすべて審査の対象とします。 このセットは出力エッジの下で閉じられます。到達不可能な頂点に到達可能な頂点へのエッジがあった場合、その頂点自体は到達可能になります。 

すべての頂点が 1 から到達可能である場合はどうなるでしょうか? 次に、同じアイデアを反転したグラフで実行します。 反転したグラフで 1 から到達できない頂点がある場合、元のグラフでは対応する頂点が 1 に到達できないことを意味します。 そのような頂点すべてを陪審員として受け入れてください。 このセットは、出力エッジの下で再び閉じられます。 反転したグラフでもすべての頂点が 1 から到達可能である場合、すべての頂点は 1 に到達でき、1 はすべての頂点に到達できるため、グラフは強く結合されます。 強接続グラフでは、空ではないすべての出力閉集合にすべての頂点が含まれている必要があり、有効な分割は不可能になります。 

したがって、2 つの走査は、必要な 2 つのケースを正確に区別します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n m)) | (O(n+m)) | 遅すぎる |
 | 最適 | (O(n+m)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのインデックス (1,\ldots,n) をグラフの頂点として扱います。 すべての知人ペア ((a,b)) に対して、有向エッジ (a\to b) を追加します。 この方向はまさに禁止された状況を表しています。つまり、陪審頂点 (a) は参加者頂点 (b) へ向かうエッジを持つことができません。 
2. 元のグラフの頂点 (1) から DFS または BFS を実行し、到達可能なすべての頂点をマークします。 いくつかの頂点が未訪問のまま残っている場合は、それらの頂点を正確に審査員に入れ、他のすべての頂点を参加者セットに入れます。 エッジは到達不可能なセットから出て到達可能なセットに入ることができないため、これは最初の有用なケースです。 
3. すべての頂点に到達した場合は、反転グラフを構築し、そこで頂点 (1) からの走査を実行します。 反転したグラフで (v) に到達するということは、(v) が元のグラフで (1) に到達できると言うのと同じです。 
4. 反転したグラフ内で到達できない頂点が残っている場合は、それらの頂点を審査員に入れ、他のすべての頂点を参加者セットに入れます。 このセットは、元の出力エッジの下で閉じられています。 (v) がその中にあり、(v\to u) であるとします。 (u) が (1) に到達できれば、(v) は (u) に到達し、その後 (1) に到達できます。これは、反転したグラフでは (1) からは (v) に到達できないことと矛盾します。 
5. 2 番目の走査もすべての頂点に到達した場合、出力`No`。 この時点で、頂点 1 はすべての頂点に到達でき、すべての頂点は頂点 1 に到達できます。その結果、頂点のすべてのペアが相互に到達できるため、グラフは強く接続されます。 
6. 成功したケースの場合、選択した閉セット内の頂点を陪審員の居住者として出力し、その補数を参加者の猫として出力します。 2 つのセットはすべて (n) 個のインデックスを分割するため、それらのサイズの合計は自動的に (n) になります。 トラバースが成功すると、選択したセットの外側に少なくとも 1 つの頂点が残るため、両側は空ではありません。 

### なぜ効果があるのか

 中心的な不変条件は、出力エッジの下で陪審が閉じられなければならないということです。 最初のトラバーサルは、1 から到達できない頂点からそのようなセットを構築します。 2 番目のトラバーサルは、1 に到達できない頂点からそのようなセットを構築します。 いずれの場合も、選択されたセットから出ていくエッジはその補数に入ることができないため、参加している猫を知っている陪審員はいません。 

両方の走査がすべての頂点に到達すると、グラフは強く結合されます。 空ではない陪審セットを選択し、その中の頂点 (v) を 1 つ選択します。 グラフは強く接続されているため、(v) からすべての頂点に到達できます。 出力エッジの下でのクロージャは、結果的にすべての頂点を審査に強制します。 この場合、陪審員にはすべて (n) 個の頂点が含まれ、参加者は存在しませんが、これは禁止されています。 したがって`No`強接続の場合は正確に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def traverse(graph, start):
    n = len(graph)
    seen = bytearray(n)
    seen[start] = 1
    stack = [start]

    while stack:
        v = stack.pop()
        for u in graph[v]:
            if not seen[u]:
                seen[u] = 1
                stack.append(u)

    return seen

def solve():
    t = int(input())
    answer = []

    for _ in range(t):
        line = input()
        while not line.strip():
            line = input()

        n, m = map(int, line.split())

        graph = [[] for _ in range(n)]
        rev = [[] for _ in range(n)]

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            graph[a].append(b)
            rev[b].append(a)

        reachable = traverse(graph, 0)

        if not all(reachable):
            jury = [i + 1 for i in range(n) if not reachable[i]]
            participants = [i + 1 for i in range(n) if reachable[i]]

            answer.append("Yes")
            answer.append(f"{len(jury)} {len(participants)}")
            answer.append(" ".join(map(str, jury)))
            answer.append(" ".join(map(str, participants)))
            continue

        can_reach_one = traverse(rev, 0)

        if not all(can_reach_one):
            jury = [i + 1 for i in range(n) if not can_reach_one[i]]
            participants = [i + 1 for i in range(n) if can_reach_one[i]]

            answer.append("Yes")
            answer.append(f"{len(jury)} {len(participants)}")
            answer.append(" ".join(map(str, jury)))
            answer.append(" ".join(map(str, participants)))
        else:
            answer.append("No")

    sys.stdout.write("\n".join(answer))

if __name__ == "__main__":
    solve()
```隣接リスト`graph`住人と猫の知り合いの縁を表します。 逆リスト`rev`にはちょうど反対側のエッジが含まれているため、2 番目のトラバースで「どの頂点が頂点 1 に到達できるか?」という質問に答えることができます。 すべての頂点から個別の検索を実行する必要はありません。 

トラバースでは、`bytearray`Python のブール値リストの代わりに。 最大 (10^6) 個の頂点を使用すると、メモリ消費量が大幅に削減されます。 スタックは反復的でもあり、長いチェーンでの再帰の深さの問題を回避します。 

最初の検索では、すべての頂点が頂点 1 から到達可能かどうかがチェックされます。一部の頂点が到達不能な場合、コードは到達不能な頂点を判断材料として正確に選択します。 条件`if not reachable[i]`は重要な境界の選択です。この場合、頂点 1 自体は補体に属しますが、到達できない頂点はすべてジュリーに属します。 

2 番目の検索では、`rev`。 頂点は、元のグラフの頂点 1 に到達できる時点で正確にマークされます。 その結果、選択するのは、`not can_reach_one[i]`2 番目の可能な閉集合を与えます。 

Python の整数は任意の精度であり、すべてのインデックスは実装内でのみゼロベースの形式に変換されるため、整数がオーバーフローすることはありません。 入力により、知人ペアが一意であることが保証されるため、重複したエッジを削除する必要はありません。 

テスト ケースを区切る空行は、(n) と (m) を読み取る前に空行をスキップすることで処理されます。 出力は蓄積されて 1 回書き込まれるため、繰り返し呼び出すよりも大幅に高速になります。`print`潜在的に数百万のインデックスに対応します。 

## 実用的な例

 サンプルの最初のテスト ケースを考えてみましょう。```
3 4
1 1
2 2
3 3
1 3
```有向エッジは (1\to1)、(2\to2)、(3\to3)、および (1\to3) です。 

| ステップ | 開始頂点 | 到達可能な頂点 | 到達不可能な頂点 | アクション |
 | --- | --- | --- | --- | --- |
 | オリジナルのDFS | 1 | ({1,3}) | ({2}) | 陪審員 = ({2}) |
 | 出力 | | 陪審員 ({2}) | 参加者 ({1,3}) |`Yes`|

 セット ({2}) は、出ていくエッジが (2\to2) だけであるため、閉じられています。 参加猫は1匹と3匹ですが、住人2はどちらも知りません。 これにより、サイズ (1+2=3) の有効なパーティションが得られます。 

次に、2 番目のサンプル テストについて考えてみましょう。```
3 7
1 1
1 2
1 3
2 2
3 1
3 2
3 3
```グラフには 1 からすべての頂点まで、3 からすべての頂点までのエッジがあります。ただし、3 自体も存在し、頂点 2 には自己ループのみがあります。 

| ステップ | 開始頂点 | 到達可能な頂点 | 到達不可能な頂点 | アクション |
 | --- | --- | --- | --- | --- |
 | オリジナルのDFS | 1 | ({1,2,3}) | (\varnothing) | 続ける |
 | リバースDFS | 1 | ({1,3}) | ({2}) | 陪審員 = ({2}) |
 | 出力 | | 陪審員 ({2}) | 参加者 ({1,3}) |`Yes`|

 元のグラフでは、すべての頂点は 1 から到達可能であるため、最初の構築では空でない陪審を与えることはできません。 反転したグラフでは、頂点 2 は 1 から到達できません。これは、元のグラフでは頂点 2 が 1 に到達できないことを意味します。 頂点 2 を陪審として選択すると、その唯一の出向きエッジが自己ループ (2\to2) であるため、機能します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n+m)) | 各グラフのエッジは、2 つの走査のそれぞれで最大 1 回検査されます。 |
 | スペース | (O(n+m)) | 元の隣接リストと逆の隣接リストには、(2m) の有向エントリとトラバーサル状態が格納されます。 |

 すべてのテスト ケースにわたって、(n) と (m) の合計は最大でも (10^6) です。 したがって、グラフ操作の合計数は、おおよそ (2\cdot10^6) 個の頂点と (2\cdot10^6) 個のエッジ エントリで線形となり、指定された制限に適しています。 反復トラバーサルにより、Python の再帰オーバーヘッドと再帰の深さのエラーも回避されます。 

## テストケース

 この問題では有効なパーティションを受け入れるため、正確な出力文字列は適切なアサーションではありません。 代わりに、以下のテスト ハーネスは実際の出力を検証します。サイズをチェックし、両方のセットがパーティションを形成していることを確認し、陪審員セットと参加者セットに対してすべての知人エッジをチェックします。```python

    sys.stdout = out

def validate(inp: str, out: str) -> bool:

    pos = 0
    t = int(data[pos])
    pos += 1

    cases = []

    for _ in range(t):
        n = int(data[pos])
        m = int(data[pos + 1])
        pos += 2

        edges = []
        for _ in range(m):
            a = int(data[pos])
            b = int(data[pos + 1])
            pos += 2
            edges.append((a, b))

        cases.append((n, edges))

    tokens = out.split()
    pos = 0

        pos += 1

        if verdict == "No":
            continue

        if verdict != "Yes" or pos + 2 > len(tokens):
            return False

        j = int(tokens[pos])
        p = int(tokens[pos + 1])
        pos += 2

        if j <= 0 or p <= 0 or j + p != n:
            return False

        if pos + j + p > len(tokens):
            return False

        jury = list(map(int, tokens[pos:pos + j]))
        pos += j

        participants = list(map(int, tokens[pos:pos + p]))
        pos += p

        if len(set(jury)) != j or len(set(participants)) != p:
            return False

        if any(x < 1 or x > n for x in jury + participants):
            return False

        jury_set = set(jury)
        participant_set = set(participants)

        if jury_set & participant_set:
            return False

        if len(jury_set | participant_set) != n:
            return False

        for a, b in edges:
            if a in jury_set and b in participant_set:
                return False

    return pos == len(tokens)

 ## 特殊なケース

 最小のケースとしては、```
1
1 1
1 1
```最初のトラバースは頂点 1 に到達するため、到達できない頂点はありません。 逆のトラバーサルも頂点 1 に到達します。グラフは強く接続されています。これは、アルゴリズムが次のように出力することを意味します。`No`。 これにより、要素が 1 つの陪審員または参加者セットを印刷し、反対側を空のままにするというよくある間違いを回避できます。 

自己ループのみで構成されるグラフの場合、```
1
4 4
1 1
2 2
3 3
4 4
```頂点 1 からの最初のトラバースは頂点 1 のみに到達します。頂点 2、3、および 4 には到達できないため、アルゴリズムは ({2,3,4}) を審査員として選択し、({1}) を参加者セットとして選択します。 すべての陪審頂点は、陪審インデックスでもある自分の猫のみを知っているため、陪審と参加者の間に禁じられた優位性はありません。 

有向チェーンの場合、```
1
4 7
1 1
2 2
3 3
4 4
1 2
2 3
3 4
```1 からの最初のトラバースは 4 つの頂点すべてに到達するため、閉じた到達不能セットを直接提供することはできません。 逆グラフでは、元のチェーンが 1 ではなく 4 に向かうため、すべての頂点から頂点 1 に到達できます。したがって、逆走査は頂点 1 にのみ到達し、({2,3,4}) が判断材料として残ります。 (2\to3) と (3\to4) がその内側に留まるため、このセットは元のエッジの下で閉じられます。 

強く接続された場合、```
1
3 6
1 1
2 2
3 3
1 2
2 3
3 1
```1 からの元の走査はすべての頂点に到達します。 元のサイクルではすべての頂点が 1 に到達できるため、反転したグラフでも 1 がすべての頂点に到達します。アルゴリズムは次のように出力します。`No`。 空でない陪審は、サイクル全体を陪審員に強制し、参加者の猫を残さないことになります。 

2 つの頂点の境界の場合、```
1
2 3
1 1
2 2
1 2
```最初のトラバースは両方の頂点に到達します。 反転したグラフでは、元の辺 (1\to2) が (2\to1) になるため、頂点 1 はそれ自体にのみ到達します。 したがって、アルゴリズムは頂点 2 を陪審員として選択し、頂点 1 を参加者として選択します。 居住者 2 は猫 2 しか知らないので、この構築は有効です。 このケースは、1 から始まる入力ラベルと 0 から始まる Python 配列の間の変換における off-by-one エラーを捕捉するのに特に役立ちます。
