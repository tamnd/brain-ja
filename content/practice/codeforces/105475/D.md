 ## 解決策
 ## 問題の理解

 状況を有向グラフとしてモデル化できます。$N$ノード、1 人につき 1 ノード。 人それぞれ$i$1 つの鍵を自分の部屋に保管し、2 つ目の鍵をその人の部屋に預ける$c_i$。 有向エッジ$i \to c_i$にアクセスするというアイデアを捉えています。$c_i$の部屋は、の鍵を取得する機能のロックを解除します$i$。 誰かが自分の部屋に入ると、そこに保存されているすべてのキーをすぐに収集し、グラフを通じてアクセスを前方に伝播し続けることができます。 

これにより、アクセスが有向エッジに沿って広がる到達可能性システムが作成されますが、宛先ノードが到達可能になって初めてア​​クティブになります。 このプロセスは単調です。ある人に到達できると、その人はさらなる鍵のロックを解除することで、外部への影響力を永続的に提供します。 

人それぞれに$i$、最初のキーが削除される人の最小数を計算したいと思います。$i$残りのロックされていないセットからは到達できなくなります。 同様に、削除によって最終的に到達する可能性のあるすべてのパスが破壊される開始ノードの最小数を求めています。$i$。 

制約により許可されるのは、$N$まで$10^5$これにより、除去セットをシミュレートしたり、ノードごとにグラフ検索を実行したりするアプローチは直ちに除外されます。 それぞれの到達可能性をゼロから再計算する単純なソリューション$i$さまざまな除去には費用がかかります$O(N^2)$さらに悪いことに、10 秒で実行できる速度をはるかに超えています。 すべてのノードにほぼ線形な時間で応答できるようにするグラフの構造分解が必要です。 

グラフに長い依存関係のチェーンまたはサイクルが含まれる場合、微妙なエッジ ケースが発生します。 たとえば、次のような単純なサイクルでは、$1 \to 2 \to 3 \to 1$, removing a single key anywhere breaks global propagation. それに対して、連鎖的には$1 \to 2 \to 3 \to 4$、ノード 4 は長いカスケードに依存しており、分離するのが非常に困難です。 正しい解決策は、局所次数だけでなく、分岐構造と環状構造を区別する必要があります。 

## アプローチ

 強引なアイデアは各人をテストすることです$i$独立して。 固定の場合$i$、さまざまな人々のセットを削除してみて、次のことをシミュレートします。$i$ロックされていない部屋の初期セットからはまだ到達可能です。 これにより、削除を伴う有向グラフ上で到達可能性プロセスを繰り返し実行することになり、最悪の場合、探索が行われます。$O(N)$シミュレーションあたりのノード数と必要なもの$O(N)$削除される人の数を段階的に増やそうとすると、ノードごとのシミュレーションが増加します。 これにより、少なくとも$O(N^3)$最悪の場合の行動。 

重要な観察点は、グラフが恣意的ではないということです。 各ノードには出力エッジが 1 つだけあるため、構造は関数グラフになります。接続されたすべてのコンポーネントは、それにフィードするツリーを含む有向サイクルで構成されます。 このように考えると、到達可能性はサイクル構造とサイクルにつながるノードの深さによって完全に支配されます。 

重要な変化は、任意の除去セットの観点から考えるのをやめ、代わりに、到達できるサブグラフに独立したエントリ ポイントがいくつ存在するかという観点から考えることです。$i$。 各ノードには 1 つの発信エッジがあるため、どのパスも最終的にサイクルに分類され、すべての影響がそのサイクルを通過します。 ノードは、その到達可能なコンポーネントへの可能なエントリ ルートがすべてブロックされた場合にのみ到達不能になります。これは、機能グラフ構造の上位に「独立したアクセス ソース」がいくつ存在するかを数えることに帰着します。 これらのソースは、逆グラフの強く接続された構造ルートに対応し、問題は、この関数依存システムにおける優位性の計算に帰着します。 

これにより、逆エッジを使用した線形時間分解が可能になり、SCC 短縮から得られるトポロジー的に意味のある順序でノードを処理できます。 コンポーネントの DAG に凝縮されると、各ノードの答えは、共通の依存関係ルートを共有せずにノードに到達できるコンポーネントの数によって決まります。 これは、凝縮グラフによって引き起こされるツリー状構造上の計数問題になります。

 ## アルゴリズムのチュートリアル

 有向グラフを、強く接続された各コンポーネントが単一のノードである構造に変換し、DAG を生成します。 

1. エッジによって形成されるグラフの強接続成分を計算します。$i \to c_i$。 各ノードの出次数 1 があるため、これは標準の DFS または反復スタックベースの SCC 分解を使用して線形時間で実行できます。 SCC が重要な理由は、サイクル内ではすべてのノードが相互に到達可能であるため、アクセス性を確保するために単一のユニットとして動作するためです。 
2. 各 SCC を単一のスーパーノードに縮小します。 あらゆるエッジに$i \to c_i$、エンドポイントが異なるコンポーネントに属している場合は、それらのコンポーネント間に有向エッジを作成します。 結果として得られるグラフは、各コンポーネントが最大 1 つの出力エッジを持つ森林のような DAG になります。 
3. コンポーネント グラフを反転して、エッジが「ロック解除に使用できる」ことを表す構造を取得します。 各コンポーネントは、最終的にキーを提供できるすべてのコンポーネントを集約します。 
4. 各コンポーネントについて、この逆 DAG で到達できる独立したルート コンポーネントの数を計算します。 これは、トポロジ順に DAG 上の DP を介して行われます。 ルート コンポーネントは、元のコンポーネント グラフに入力エッジがないコンポーネントです。 このような各ルートは、キーの独立した開始ソースを表します。 
5. 任意のノードの答えは、反転コンポーネント グラフでその SCC に到達できるルート コンポーネントの数です。 これは、最終的にそのノードのロックを解除するためにアクセスを開始できる独立した方法の数です。 ノードを到達不能にするには、これらのソースをすべて削除する必要があるため、削除の最小数はこの数と等しくなります。 

### なぜ効果があるのか

 SCC 縮小後、システムは DAG になり、すべてのノードが相互に到達可能な人々の最大セットを表します。 外部からのアクセス パスはルート コンポーネントから始まり、有向エッジに沿って下に流れる必要があります。 各ルート コンポーネントは、互いに素な「アクセスの起点」を表します。グラフは関数グラフであるため、これらの起点は、コンポーネントの到達可能性を超えて新しい独立したパスを作成するような形でマージされません。 

したがって、少なくとも 1 つのルート コンポーネントにそのノードへのパスがある場合にのみ、ノードに到達できます。 到達可能性を完全にブロックするには、そのようなルートをすべて無効にする必要があります。 キーを削除する必要がある人の最小数は、ノードの SCC に到達できる個別のルート コンポーネントの数と正確に一致します。これは、各ルートが、別のルートで置き換えることができないロック解除可能性の独立したチェーンに寄与するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, gr):
    sys.setrecursionlimit(10**7)
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n

    def dfs2(v, c):
        comp[v] = c
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to, c)

    cid = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, cid)
            cid += 1

    return comp, cid

def solve():
    it = iter(sys.stdin.read().strip().split())
    out = []

    while True:
        try:
            n = int(next(it))
        except StopIteration:
            break

        c = []
        for _ in range(n):
            c.append(int(next(it)))

        g = [[] for _ in range(n)]
        gr = [[] for _ in range(n)]

        for i in range(n):
            g[i].append(c[i])
            gr[c[i]].append(i)

        comp, k = kosaraju(n, g, gr)

        indeg = [0] * k
        cg = [[] for _ in range(k)]

        for i in range(n):
            for j in g[i]:
                if comp[i] != comp[j]:
                    cg[comp[i]].append(comp[j])
                    indeg[comp[j]] += 1

        from collections import deque
        q = deque([i for i in range(k) if indeg[i] == 0])

        reach = [0] * k
        for i in q:
            reach[i] = 1

        topo = []
        while q:
            v = q.popleft()
            topo.append(v)
            for to in cg[v]:
                indeg[to] -= 1
                if indeg[to] == 0:
                    q.append(to)

        for v in topo:
            for to in cg[v]:
                reach[to] += reach[v]

        ans = [0] * n
        for i in range(n):
            ans[i] = reach[comp[i]]

        out.append(" ".join(map(str, ans)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず関数グラフを構築し、Kosaraju のアルゴリズムを使用してそれを強く接続されたコンポーネントに圧縮します。 このステップが必要なのは、サイクルが相互の到達可能性を表し、サイクルを単一のユニットとして扱うことで依存関係の伝播における曖昧さがなくなるためです。 

縮小後、コンポーネント グラフは非循環になるため、位相順序に従って処理できます。 度数ベースのキューは、有効な順序付けを構築します。 それぞれがアクセスの独立した開始点を表すため、各ソース コンポーネントを到達可能性カウント 1 で初期化します。 

伝播ステップでは、各コンポーネントに到達できるソース コンポーネントの数が累積されます。 これは、そのコンポーネント内のすべてのノードの答えになります。

 ## 特殊なケース

 といったタイトなサイクル`1 2 0`強く結びついた 1 つのコンポーネントに崩壊します。 この場合、すべてのノードが同一の到達可能性を共有するため、アルゴリズムは SCC 縮小後にすべてのノードに同じ値を割り当てます。 伝播ステップでは単一のユニット到達カウントを割り当て、それをノードにマッピングし直すと均一な出力が得られます。 

のような混合構造`0 -> 1 -> 2`自己ループが 2 の場合、サイクル SCC にフィードするツリーが形成されます。 SCC ステップはサイクルのみをマージし、チェーンが指す DAG を残します。 ルート数の伝播により、チェーン内のすべてのノードが依存するサイクルと同じ数のソースを確実に継承します。 これにより、上流ノードの到達可能性はサイクル エントリ ポイントによって支配されるため、上流ノードの過小カウントが防止されます。
