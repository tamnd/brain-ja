 ## 解決策
 ## 問題の理解

 数直線上に一連の点が与えられ、各点には最初に 1 羽のニワトリが含まれています。 一連のジャンプを使用してある位置から別の位置に移動できる場合、2 羽のニワトリはつながっているとみなされます。各ジャンプは選択した値よりも厳密に短くなければなりません。$k$。 つまり、2 つの位置が距離内にある場合、$k$、それらを直接接続されているものとして扱うことができ、接続性は中間位置を介して推移的です。 

これにより、一連の位置が、距離が より短い点のペアの間にエッジが存在するグラフに変わります。$k$。 として$k$成長し、より多くのエッジが表示され、コンポーネントが結合され、コンポーネント内の到達可能なペアの数が増加します。 

各テスト ケースについて、次の最小値を見つけるように求められます。$k$これらの接続されたコンポーネント内で互いに到達できるニワトリのペアの総数は少なくとも$a$。 

制約は私たちを$O(n \log n)$または$O(n \log \text{range})$テストケースごとのアプローチ。 と$n$まで$10^5$、すべてのペアに対する二次推論や接続性の繰り返しの再計算は、最大で次の時間が必要となるため、遅すぎます。$10^{10}$最悪の場合の距離チェック。 

微妙な点は、接続性は直接的な距離だけで決まるわけではないということです。 2 つの点が遠く離れていても、中間点の連鎖があれば、それらは同じコンポーネントに属する可能性があります。 単純な間違いは、直線距離が 未満であるペアのみを数えることです。$k$、これは到達可能なペアを過小評価します。 

すべての点が非常に近い場合、別の特殊なケースが発生します。 たとえば、ポジションが$[1,2,3,4]$そして$k=3$、その後、セット全体が 1 つのコンポーネントとなり、すべてのコンポーネントが生成されます。$\binom{4}{2}=6$ただし、すべてのペアの距離が直接 3 未満であるわけではありません。 どのソリューションも推移閉包を正しく考慮する必要があります。 

## アプローチ

 重要な観察は、1 次元では、位置のソートによって接続構造が完全に決定されるということです。 並べ替え後、コンポーネントが「壊れる」可能性がある唯一の場所は、連続するポイント間のギャップです。 

値を固定すると$k$、次に、距離が より短い任意の 2 つの連続した点$k$同じコンポーネントチェーンに属しており、少なくともサイズのギャップがある場合$k$行を別々のコンポーネントに分割します。 これにより、問題は、任意のグラフの接続性から、隣接する差分をしきい値処理することによるグループ化に軽減されます。 

コンポーネントが形成されると、各コンポーネント内の到達可能なペアをカウントするのは簡単になります。サイズのコンポーネント$s$貢献する$\frac{s(s-1)}{2}$ペア。 

したがって、固定の場合$k$、ソート後に線形時間で有効なペアの数を計算できます。 残りのタスクは最小値を見つけることです$k$この値が少なくとも$a$。 増えてからは$k$コンポーネントをマージし、ペアの数を単調に増加させるだけです。二分探索は$k$有効です。 

強引なアイデアはあらゆる可能性を試すだろう$k$0 から 0 までの値$10^9$、各値について、コンポーネントとペアの数を再計算します。$O(n)$。 これは次のことにつながります$O(n \cdot 10^9)$、それは不可能です。 二分探索により評価の数が約 30 に減り、効率的な解決策が得られます。

 ## アルゴリズムのチュートリアル

 1. 隣接性がラインに沿った距離の増加に対応するように、位置の配列を並べ替えます。 これにより、有効なパスは必ず連続したインデックスを通過する必要があります。 
2. 関数を定義する`count_pairs(k)`最大許容ジャンプが次の場合に、フレンドのペアが何組存在するかを計算します。$k$。 この関数は、ソートされた配列を処理し、連続する点間のギャップが少なくとも$k$。 コンポーネントが終了するたびに、その貢献度が次のように追加されます。$s(s-1)/2$、 どこ$s$コンポーネントのサイズです。 
3. 二分探索を使用します$k$、検索スペースは 0 からエンドポイント間の最大距離までです。 各中間点について$k$、計算する`count_pairs(k)`。 
4. もし`count_pairs(k)`少なくとも$a$、有効な最小しきい値が必要なため、より小さい値を試します。 それ以外の場合は増加します$k$さらに多くのコンポーネントをマージします。 
5. 二分探索が完了すると、左側の境界が最小になります。$k$条件を満たすものです。 

ステップ 2 が正しい重要な理由は、ソートされた配列では接続チェーンが隣接する点を通過する必要があるため、コンポーネントは隣接するギャップが以下のまさに最大のセグメントになるためです。$k$。 

### なぜ効果があるのか

 ソートされた構造により、問題はパス グラフのエッジのしきい値処理に変わります。 固定の場合$k$、エッジは、ギャップが 未満である連続したポイント間にのみ存在します。$k$、これによって接続が完全に決まります。 非連続的な接続は、そのようなエッジのシーケンスによってすでに暗示されている必要があるため、追加のエッジが隣接する比較を超えてコンポーネントの構造を変更することはありません。 コンポーネントのサイズによって到達可能なペアの数が一意に決まり、この数は次のように単調増加します。$k$、二分探索では、実行可能な最小しきい値が正しく分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_pairs(x, k):
    n = len(x)
    total = 0
    size = 1

    for i in range(1, n):
        if x[i] - x[i - 1] < k:
            size += 1
        else:
            total += size * (size - 1) // 2
            size = 1

    total += size * (size - 1) // 2
    return total

def solve_case(n, a, x):
    x.sort()

    lo, hi = 0, x[-1] - x[0] + 1

    while lo < hi:
        mid = (lo + hi) // 2
        if count_pairs(x, mid) >= a:
            hi = mid
        else:
            lo = mid + 1

    return lo

def main():
    t = int(input())
    for _ in range(t):
        n, a = map(int, input().split())
        x = list(map(int, input().split()))
        print(solve_case(n, a, x))

if __name__ == "__main__":
    main()
```ソートされていない入力では、無関係な点がライン構造内で隣接しているものとして誤って扱われるため、解決策はまずソートに依存します。 の`count_pairs`関数はコンポーネントのサイズを注意深く累積し、十分に大きなギャップが現れたときに各セグメントをフラッシュします。 

よくある実装上の間違いは、ループの後に最後のコンポーネントを追加するのを忘れることです。これにより、ペアが過小評価されてしまいます。 もう 1 つの微妙な問題は、`<= k`の代わりに`< k`接続状態。 この問題は厳密な不等式を定義しているため、しきい値チェックは正確に一致する必要があります。 

二分探索境界は次のように選択されます。`hi`すべての点が接続される上限として常に有効です。 使用する`x[-1] - x[0] + 1`可能な限り最大のギャップ条件も安全に含まれることを保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def count_pairs(x, k):
        n = len(x)
        total = 0
        size = 1
        for i in range(1, n):
            if x[i] - x[i - 1] < k:
                size += 1
            else:
                total += size * (size - 1) // 2
                size = 1
        total += size * (size - 1) // 2
        return total

    def solve_case(n, a, x):
        x.sort()
        lo, hi = 0, x[-1] - x[0] + 1
        while lo < hi:
            mid = (lo + hi) // 2
            if count_pairs(x, mid) >= a:
                hi = mid
            else:
                lo = mid + 1
        return lo

    def main():
        t = int(input())
        out = []
        for _ in range(t):
            n, a = map(int, input().split())
            x = list(map(int, input().split()))
            out.append(str(solve_case(n, a, x)))
        return "\n".join(out)

    return main()

 ## 特殊なケース

 次のようなジャンプが許可されない構成の場合、`x = [5, 20, 100]`と$k = 0$、すべての点が独自のコンポーネントを形成します。 アルゴリズムは各ギャップを処理し、すべての差異がそれを超えるか等しいことを確認します。$k$、シングルトンコンポーネントをフラッシュし、ゼロペアを生成しますが、これは正しいです。 

のような完全に接続されたケースの場合`x = [1, 2, 3, 4]`十分な大きさの$k$、ループは分割をトリガーしないため、最後のフラッシュはサイズ 4 の単一コンポーネントを生成し、6 つのペアを返します。 これは、最後のコンポーネントの処理が不可欠であることを確認します。 

緊密にクラスタ化されているが完全には接続されていない場合など`x = [1, 3, 6, 10]`、正しさは、隣接する各差分が以下であるかどうかに完全に依存します。$k$。 このアルゴリズムは、ギャップがしきい値を超えるとすぐにコンポーネントを正しく分離し、接続性が過大評価されることがないようにします。
