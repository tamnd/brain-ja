 ## 問題の理解

 2 つのシーケンスが与えられ、1 つは長さです。`n`そしてもう一つの長さ`m`。 これらのシーケンス内の正確なシンボルは不明ですが、古典的な編集距離の定義の下でそれらのプレフィックスがどの程度類似しているかについては十分な情報が与えられています。 

プレフィックス間の編集距離`a[1..i]`そして`b[1..j]`標準の動的プログラミング規則に従います。最後の要素が一致する場合、コストは斜め前の状態から取得されます。 それ以外の場合は、削除、挿入、置換のいずれかを足したものになります。 

珍しいのは、単純な方法で完全な数値 DP テーブルを直接操作しないことです。 代わりに、問題の構造により、これらの DP 値のパリティ情報のみを利用して、2 つのシーケンスの要素間の一貫性条件を再構築する必要があります。 これらのパリティ駆動の遷移から、最終的には「この位置のペアは同じ値を含まなければならない」または「これら 2 つの位置は異なっていなければならない」という形式の制約を導き出すことになります。タスクは、そのような制約をすべて同時に満たすことができるかどうかを確認し、可能であれば 1 つの有効な代入を構築することになります。 

DP テーブルは概念的には次のようになりますが、`n * m`エントリの主な問題点は、各エントリが独立して選択されないことです。 それぞれが隣接するセルに依存するため、各セルを個別に扱う単純な試みは、すぐに不一致になったり、分岐が指数関数的に増加したりする可能性があります。 

考えられるすべての編集距離値を再構築しようとする単純な実装では、すでに`O(nm)`これは一般的な制約では問題ありませんが、パリティを慎重に利用しない場合、値の選択の分岐に隠れた複雑さが潜んでいます。 さらに悪いことに、実際のシーケンスを直接推測しようとすると、各不一致または一致の決定が多くの DP 遷移に伝播するため、指数関数的な可能性が生じます。 

2 つの異なる遷移が両方とも同じ DP パリティを説明できる場合、微妙なエッジ ケースが発生します。 たとえば、すべての文字が異なると想定される場合、複数の DP パスがパリティ制約に一致する可能性はありますが、すべての制約を介して伝播されるときにグローバルに一貫性があるのはそのうちの 1 つだけです。 1 つのセルで貪欲なローカル決定を行うと、後の制約と簡単に矛盾する可能性があります。 

正しい解決策は、早期に値をコミットすることを回避します。 代わりに、すべての制約が抽出されるまで解釈を延期します。 

## アプローチ

 ブルートフォースパースペクティブでは、DP テーブル全体を再構築し、シーケンスを推測しようとします。 これは、両方のシーケンスの文字に任意の値を仮定し、編集距離を再計算し、ターゲット DP 構造との一貫性をチェックすることから始まります。 可能な割り当ての数は、次のように指数関数的に増加します。`n + m`なぜなら、各位置は多くの可能な値を取ることができ、すべての割り当ては完全な DP テーブルに影響を与えるからです。 

たとえサイズが固定されたアルファベットに限定されたとしても`k`、ブルートフォースでは依然として必要になります`k^(n+m)`可能性があり、各チェックには少なくとも`O(nm)`DP を再計算する時間が長くなり、実行不可能な複雑さが生じます。 

重要な構造的観察は、3 つの候補遷移のうちどれが最小値を生成したかがわかれば、編集距離の反復がほぼ決定的であるということです。 唯一のあいまいさは、最小値が直接取得されたのか、それとも 1 ずつ増加されたのかということです。 この曖昧さこそがパリティによって捉えられるものです。`e[i][j]`、隣接するもののパリティがわかっている場合、2 つの可能性のうち 1 つだけが一致します。 

各 DP 遷移が一致のような動作に対応するか不一致のような動作に対応するかを解決すると、各セルは`(i, j)`間の制約を引き起こします`a[i]`そして`b[j]`。 一致状態では平等が強制され、不一致状態では不平等が強制されます。 これにより、問題は位置の 2 部グラフ上の制約充足問題に変換されます。 

最後のステップは、等式制約が不等式制約と矛盾を引き起こすかどうかを確認することです。 等価制約は、同じ値を共有する必要がある変数の連結コンポーネントを形成します。 単一コンポーネント内に不等式制約が存在する場合、システムは一貫性がありません。 それ以外の場合は、各連結成分に任意の個別の値を割り当てることができます。

 ## アルゴリズムのチュートリアル

 与えられた情報をパリティ制約のある DP グリッドとして扱い、構造制約を段階的に抽出します。 

1. DP テーブルの初期化`e[i][j]`ただし、基本条件を使用してその同等性と実現可能性を追跡するだけです`e[0][j] = j`そして`e[i][0] = i`。 

これらの境界により、曖昧さなく最初の行と最初の列のパリティが固定され、伝播全体が固定されます。 
2. 各セルについて`(i, j)`、斜め、上、左の 3 つの遷移からの候補値を計算します。 

各候補は以前に計算された状態から導出されるため、それらのパリティはすでにわかっています。 
3. 次のことを決定します。`a[i] == b[j]`または`a[i] != b[j]`の指定されたパリティとの一貫性をチェックすることによって保持される必要があります。`e[i][j]`。 

対角線の遷移を一致させることでパリティの一貫性が維持される場合は、それを一致制約として扱います。 それ以外の場合は、不一致制約である必要があります。 
4. 間の制約を記録します。`a[i]`そして`b[j]`この決定に基づいて。 

一致制約は 2 つの変数が同じ同値クラスに属しなければならないことを意味し、不一致制約はそれらが同じクラスになってはいけないことを意味します。 
5. 全体にわたって Union-Find 構造を構築する`n + m`変数、マージ`a[i]`と`b[j]`一致制約が現れるたびに。 
6. すべての等価制約を処理した後、すべての不一致制約を検証します。 

各不等式エッジについて、その端点が同じ Union-find コンポーネントに属しているかどうかを確認します。 そうした場合、システムに一貫性がなくなります。 
7. 各連結成分に個別の値を割り当て、結果のシーケンスを出力します。 

### なぜ効果があるのか

 DP の繰り返しにより各セルが制限されます`(i, j)`根本的に異なる 2 つの方法のみで動作します。1 つは最適なトランジションで文字を揃える (`a[i] = b[j]`)、または不一致を強制します (`a[i] != b[j]`）。 パリティ情報により、これらのケースのどれが各状態で一貫しているかについてのあいまいさがなくなります。 すべてのローカル決定が修正されると、等価制約はインデックスに対する等価クラスを定義し、不等式制約はクラス間の禁止エッジとして機能します。 等価性は推移的であるため、union-find はすべての強制された識別を正しく取得します。 矛盾はすべて、単一の同値クラス内の不等式として現れる必要があり、最終チェックで検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, m = map(int, input().split())
    # p[i][j] = parity of edit distance e[i][j]
    p = [list(map(int, input().split())) for _ in range(n + 1)]

    dsu = DSU(n + m)

    def id_a(i): return i - 1
    def id_b(j): return n + j - 1

    bad = []

    for i in range(1, n + 1):
        for j in range(1, m + 1):
            # inferred condition from DP parity structure
            # if consistent with match, enforce equality, else inequality
            if p[i][j] == (p[i - 1][j - 1] ^ 0):
                dsu.union(id_a(i), id_b(j))
            else:
                bad.append((id_a(i), id_b(j)))

    for u, v in bad:
        if dsu.find(u) == dsu.find(v):
            print("NO")
            return

    comp_val = {}
    cur = 1

    ans_a = [0] * n
    ans_b = [0] * m

    for i in range(1, n + 1):
        r = dsu.find(id_a(i))
        if r not in comp_val:
            comp_val[r] = cur
            cur += 1
        ans_a[i - 1] = comp_val[r]

    for j in range(1, m + 1):
        r = dsu.find(id_b(j))
        if r not in comp_val:
            comp_val[r] = cur
            cur += 1
        ans_b[j - 1] = comp_val[r]

    print("YES")
    print(*ans_a)
    print(*ans_b)

if __name__ == "__main__":
    solve()
```DSU は、インデックスを等価制約によって引き起こされる等価クラスに分割します。 マッピング`a[i] -> i-1`そして`b[j] -> n+j-1`両方のシーケンスが同じ構造内に存在することを保証します。 不等式制約は個別に保存されるため、すべての結合が完了した後でのみ検証できるため、マージ中の早期の矛盾が回避されます。 

最後の割り当てステップでは、コンポーネントごとに新しい整数を使用します。 制約は実際のシンボル値ではなく、等号と不等号のみを考慮するため、どのようなラベル付けも機能します。

 ## 特殊なケース

 特殊なケースは、等価制約が不一致制約を含むサイクルを間接的に強制する場合に発生します。 たとえば、次の場合`a[i]`は等価エッジを介して接続されています`b[j]`、その後、それらの間に不一致制約が追加されると、DSU は不等式がチェックされる前にそれらを同じコンポーネントに配置します。 両方のエンドポイントが同じ代表を共有するため、最終検証中にこの不一致が検出されます。 

もう 1 つの微妙なケースは、等価制約が存在しない場合です。 この状況では、すべてのノードが独自のコンポーネントとなり、すべての不等式制約が自明に満たされます。 このアルゴリズムは、不必要なマージを試行することなく個別の値を正しく割り当て、構造の欠如も一貫して処理されることを示しています。
