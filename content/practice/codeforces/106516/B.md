 ## 解決策
 ## 問題の理解

 長さが次のような長いシーケンスが与えられます。$N^2$、およびからのすべての値$1$に$N$正確に表示されます$N$回。 このシーケンスは、以下を含むアクションのタイムラインとして解釈されることを意図しています。$N$循環構造に配置されたラベル付きトークン。 値の出現ごとに、そのトークンに関連付けられた移動または相互作用が記述されます。 

中心的な問題は、このシーケンスが隠された構造ルールの下で一貫した方法で実現できるかどうかです。つまり、動きは次のように分解可能でなければなりません。$N$循環サブシーケンス。それぞれがラベルの「ローテーション スケジュール」のように動作します。 言い換えれば、シーケンスを次のように分割できるかどうかを判断しようとしています。$N$有効なチェーン、各チェーンが循環する$1 \to 2 \to \dots \to N \to 1$外観の制約を尊重しながら、順番に。 

制約が十分に大きいため、分解を明示的に検索したり、要素のチェーンへのすべての割り当てをシミュレートしようとすると、組み合わせが爆発的に増加します。 単純な割り当てプロセスでは、各出現がどのサブシーケンスに属するかに基づいて効果的に分岐するため、指数関数的な可能性がもたらされます。$N^2$。 これにより、バックトラッキングやブルートフォースパーティショニングが即座に排除されます。 

局所的な周波数条件は満たされるが、全体的な構造が不可能な場合、微妙な失敗のケースが発生します。 たとえば、値が次のようなプレフィックスを構築することができます。$y$～に比べて早すぎるようです$y-1$、「リンクされていない」発生が多すぎる状況を生み出します。$y$存在する。 貪欲な割り当ては、ローカルでは引き続き成功する可能性がありますが、サブシーケンスに有効な先行タスクがなくなるため、後で拡張できなくなります。 

重要な問題は、実現可能性は総数ではなく、隣接する値の出現がすべてのプレフィックスにわたってどのようにインターリーブされるかによって決まることです。 

## アプローチ

 直接的なアプローチでは、分解を明示的に構築しようとします。$N$循環サブシーケンス。 配列をスキャンし、各要素を、それを合法的に受け入れることができるサブシーケンスの 1 つに割り当てます。これは、要素が既に配置されているサイクル内の以前の値を持っていることを意味します。 これは、制約のあるスケジュールの問題のように動作します。$N$リソースと$N^2$イベント。 

この貪欲な構築は概念的には正しいですが、考えられるすべてのサブシーケンスを維持し、各ステップで有効な配置をチェックすると、コストのかかる状態の爆発が発生します。 最悪の場合、各要素は多くのサブシーケンスをスキャンする必要があり、更新がカスケードされるため、次のような複雑さが生じます。$O(N^3)$実装によっては、それ以上の場合もあります。 

構造的な洞察は、連続する値間のプレフィックスの不均衡によって実現可能性が完全に把握されるということです。 すべてのプレフィックスとすべての値について$y$、の出現数$y$これまでに確認されたのは、次の発生回数を超えることはできません。$y-1$これまでに複数の人に見られました。 各「チェーン」は最大でも 1 つの一致しないものを提供できるため、この条件は必要かつ十分です。$y$いつでも、そして追加のたびに$y$先行するものによってサポートされている必要があります$y-1$ある連鎖の中で。 

これにより、問題全体がプレフィックス数の維持と、すべての値にわたる単純な不等式のチェックに集約されます。

 ## アルゴリズムのチュートリアル

 この問題をシーケンス全体にわたるプレフィックスカウント条件に変換します。 

### ステップ

 1. 頻度テーブルを初期化する`cnt[y]`価値観について$1 \ldots N$、すべてゼロから始まります。 これは、各値がこれまでにプレフィックスに出現した回数を追跡します。 
2. シーケンスを左から右にスキャンします。 ポジションごとに$i$、増分`cnt[x[i]]`。 これにより、すべてのステップで正しいプレフィックス周波数が維持されます。 
3. ポジションの更新後$i$、すべての値の条件を確認します。$y \ge 2$：

確保する`cnt[y] <= cnt[y-1] + 1`。 

これによりその値が強制されます$y$決して前任者を「上回る」ことはありません$y-1$複数回発生することによって。 
4. 違反が見つかった場合は、直ちにシーケンスが無効であると結論付けます。 
5. スキャンが違反なく完了した場合、シーケンスは有効です。 

### なぜ効果があるのか

 重要な不変条件は、どの接頭辞であっても、それぞれの値が$y$対応するサービスでまだサポートされていない「一致しない」オカレンスは最大 1 つだけです。$y-1$。 有効な各チェーンは、次から先に進むための単一の保留スロットに貢献します。$y-1$に$y$。 もし$y$を超える$y-1$複数の、何らかの発生によって$y$順序を壊すことなくチェーンに配置することはできないため、分解は不可能です。 逆に、不等式が常に成り立つ場合は、次の各出現を常に割り当てることができます。$y$既存のチェーンを延長するか、単一の許容される新しい一致しないチェーン位置を開始して、構築可能性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    cnt = [0] * (n + 1)

    for v in a:
        cnt[v] += 1

        for y in range(2, n + 1):
            if cnt[y] > cnt[y - 1] + 1:
                print("No")
                return

    print("Yes")

if __name__ == "__main__":
    solve()
```実装では、プレフィックス数が維持され、各更新の直後に隣接制約がチェックされます。 内側のループオーバー$y$隣接する差異のみが問題となるため、これで十分です。 どのような値の違反も、それが現れた瞬間にローカルに検出されます。 

微妙な点は、プロパティがプレフィックスに依存しているため、フル スキャンの後ではなく、各増分後にチェックが行われる必要があることです。 検証を遅らせると、将来の発生によって「マスク」される中間の無効な状態を見逃す可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

assert run("1\n1") == "Yes"

# small valid structured case

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、上位のラベルがその先行ラベルの出現が十分に存在する前に早すぎる場合です。 たとえば、次のように入力します。```
3
1 3 3 ...
```2 が十分な量で確立されていない間に 3 の 2 番目の出現が発生するため、2 番目の 3 はすぐに失敗します。 アルゴリズムはこれを正確なプレフィックスで検出します。`cnt[3] > cnt[2] + 1`、無効な補完が受け入れられないようにします。 

もう 1 つのケースは、値が完全にバランスが取れているものの、最も高いラベルが繰り返し出現することから始まるなど、値がシフトしている場合です。 合計カウントが最後に一致しても、プレフィックス チェックは早期に失敗しますが、アルゴリズムが最終状態まで検証を遅らせることがないため、これは正しく処理されます。
