 ## 解決策
 ## 問題の理解

 非常に構造化された組み合わせ構造から得られる平面グラフが与えられます。 各頂点は、2 つの方法のいずれかで動作するように制約されます。 頂点の 1 つのタイプは、「1 入力」ノードのように動作します。つまり、すべての入射エッジのうち、正確に 1 つのエッジが内側に向けられている必要があります。 もう 1 つのタイプは、固定の「k イコライザー」ノードのように動作します。このノードでは、すべての入射エッジが一方向に配向されるか、すべてが逆方向に配向され、次数が定数 k (この問題では k は 6) に固定されます。 

タスクは、単一の有効な方向を見つけることではなく、すべての頂点の制約を同時に満たすエッジの方向がいくつあるかをカウントすることです。 各エッジには方向があり、実現可能性は頂点での局所的な制約によって完全に決まります。 

これはグローバルな計数問題のように見えますが、その構造は非常に厳格です。 グラフは平面であり、制約された意味で 2 部構成であり、片側に高次の頂点が含まれています。 主な問題は、制約がサイクル間で相互作用するため、単純なローカル推論はグローバルに伝播するとすぐに一貫性がなくなることです。 

複雑さの観点から見ると、グラフのサイズが十分に大きいため、向きを指数関数的に列挙することは不可能です。 構造が標準のマッチングまたはフロー インスタンスではないため、サブセットまたはフローに対する動的プログラミングでさえ、最悪の場合は非常に遅くなります。 有効な解決策は、平面性と次数制約によって引き起こされる強制的なローカル構造を利用する必要があります。 

低次数の「1-in」頂点が出現すると、微妙なエッジ ケースが発生します。 たとえば、1 インチ頂点の次数が 1 の場合、その入射エッジは直ちに強制されます。 次数 2 の場合、2 つのエッジのうちの 1 つを内側に選択する必要があり、これにより二者択一が導入されますが、隣接するエッジ間に強い結合も作成されます。 このような構造をすぐに縮小しない単純なソルバーは、システム内に不必要な自由度を保持し、過剰にカウントしたり、後で削減した後に一貫性がなくなったりします。 

## アプローチ

 ブルート フォース アプローチでは、すべてのエッジに方向を割り当ててから、各頂点の制約をチェックしようとします。 M 個のエッジを使用すると、2^M 通りの可能性が得られます。これは、M が 10^5 程度になる一般的な制約はもちろんのこと、M が約 40 の場合でも直ちに実行不可能です。 制約がサイクルを通じて伝播し、初期の選択を独立して検証できないため、局所的妥当性による枝刈りさえも失敗します。 

重要な観察は、これが一般的な方向の問題ではなく、正しく単純化されると 2 要素フィールド上で線形システムのように動作する、高度に構造化された制約システムであるということです。 この制約は、解空間が空であるか、GF(2) 上のアフィン空間であることを強制します。つまり、すべての有効な構成は、基本解と特定の構造コンポーネントに沿った独立したバイナリ 反転から導出できることになります。 

平面性と固定された高次の k が重要です。 これらは、局所的な還元可能なパターン、つまり 1-in 側の次数 1 または 2 の頂点、および制御された方法でマージまたは削除できる剛体 k イコライザー頂点の存在を強制します。 これらの削減により、アフィン変換までの解空間を維持しながら、グラフが徐々に簡素化されます。 

このアルゴリズムは、解セットの等価性を維持しながら、強制エッジを縮小したり、制約をマージしたり、頂点を削除したりするローカル変換を繰り返し適用します。 各操作は、頂点の数を減らすか、ローカル構造を同等だがより単純な制約システムに置き換えます。 最終的には、平面性により、自明でない構造が存続できないことが保証され、一貫性がある場合にはインスタンスが完全に崩壊することになります。

 ## アルゴリズムのチュートリアル

 このアルゴリズムは、方向制約の等価性を維持しながらグラフを継続的に単純化することによって動作します。 

1. まず、各頂点制約をエッジの方向に関するローカル ルールとして解釈します。 1-in 頂点には 1 つの入力エッジが必要ですが、k イコライザー頂点にはすべてのエッジが一貫して位置合わせされる必要があります。 この再定式化により、問題はエッジ方向に関する制約満足システムに変換されます。 
2. 次数によってリダクション ルールが即座にトリガーされるすべての頂点を含む、処理構造 (通常はキュー) を初期化します。 これにより、強制的な単純化が利用可能になるとすぐに常に適用されるようになります。 
3. 次数 1 の 1 インチ頂点に遭遇すると、その唯一の入射エッジが直ちに内側に強制されます。 このエッジを縮小し、制約をその隣接エッジにマージします。 1-in 条件を満たす代替の向きがないため、これは正しいです。 
4. 1-in 頂点の次数が 2 の場合、それを削除し、その 2 つの近傍を 1 つのコンストレイント ノードにマージします。 その理由は、その 2 つのエッジのうちの 1 つが内側を向いている必要があり、これにより、隣接する 2 つの構造間に二項関係が強制されるからです。 縮小すると、グラフ サイズを削減しながら、この依存関係が維持されます。 
5. 隣接する 1-in 頂点は、その制約を単一のより高次の 1-in 頂点に結合することによってマージできます。 このステップでは、マージされた各構造で 1 つの入力エッジを選択する必要があるという不変条件を維持しながら、隣接構造を簡素化します。 
6. 2 つの k イコライザー頂点が接続されている場合、残りの隣接頂点を巡回順序でペアにして再接続することによって、これらの頂点を一緒に削除します。 これにより、ローカル埋め込みを通じて厳格な「全か無か」制約を変換しながら、平面性が維持されます。 重要なアイデアは、エッジを共有することで方向間の一貫性が強制され、両方の頂点を削除してその構造を外側に伝播できるようにするということです。 
7. 各修正の後、自己ループを削除し、平行エッジをマージします。これは、これらのエッジが制約の下で方向に関する独立した情報を持たないためです。 
8. これ以上のルールが適用されなくなるまで、これらの削減を繰り返します。 その時点で、グラフが空でない限り、残りのすべての頂点は補題 E.1 に違反する必要があります。 したがって、リダクションがきれいに終了すれば、解空間は完全に考慮されたことになります。 

### なぜ効果があるのか

 プロセス全体では、解空間のアフィン構造が維持されます。 すべてのリダクションは、変数を固定するか、2 つの変数を等しいか反対であると識別するか、非線形性を導入することなく依存制約を除去します。 各演算は GF(2) に対する線形変換に対応するため、解の数は全体を通じて 0 または 2 の累乗のままになります。 平面性により、低次数のマージ可能なパターンがすべて使い果たされた後、既約構成が残らないことが保証され、グラフが完全に削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
        edges.append((u, v))

    deg = [len(g[i]) for i in range(n)]
    active = [True] * n

    from collections import deque
    q = deque(i for i in range(n) if deg[i] <= 2)

    dsu = DSU(n)

    while q:
        u = q.popleft()
        if not active[u]:
            continue
        if deg[u] == 0:
            active[u] = False
            continue

        if deg[u] == 1:
            v = g[u][0]
            if not active[v]:
                continue
            dsu.union(u, v)
            active[u] = False
            deg[v] -= 1
            if deg[v] <= 2:
                q.append(v)

        elif deg[u] == 2:
            a, b = g[u]
            if not active[a] or not active[b]:
                continue
            dsu.union(a, b)
            active[u] = False
            deg[a] -= 1
            deg[b] -= 1
            if deg[a] <= 2:
                q.append(a)
            if deg[b] <= 2:
                q.append(b)

    comp = set()
    for i in range(n):
        if active[i]:
            comp.add(dsu.find(i))

    print(1 if len(comp) == 0 else 0)

if __name__ == "__main__":
    solve()
```この実装では、隣接リストが維持され、頂点が削除されると次数が動的に追跡されます。 キューにより、次数が削減可能な状態に低下するすべての頂点が迅速に処理されることが保証されます。 DSU は、制約によって 2 つのコンポーネントが同じ動作を強制される場合に常に頂点をマージするために使用されます。これは、方向制約のアフィン解釈に基づく縮小に相当します。 

重要な点は、度が静的ではないということです。 収縮するたびに隣接する次数が変更されるため、更新のたびに影響を受ける頂点を再度キューに入れる必要があります。 これを行わないと、強制的な削減が行われないことになり、正確性が損なわれます。

 ## 特殊なケース

 キー エッジ ケースは、次数 2 の頂点の長いチェーンです。 このような場合、すべての内部ノードは縮小後に近隣ノードを繰り返しエンキューし、マージされた 1 つのコンポーネントが残るか、すべてが消滅するまで構造が徐々に崩壊します。 次数の更新後に近隣ノードを再エンキューできない単純な実装では、早期に停止し、未解決の制約が誤って残されてしまいます。 

もう 1 つのエッジ ケースは、初期の収縮により次数が 3 から 2 に低下する頂点です。 これは、以前にスキップされた場合でも、再度処理する必要があります。 キューベースのアプローチにより、そのような遷移が見逃されることがなくなり、動的な次数の変化の下でも正確さが維持されます。
