 ## 問題の理解

 順列が与えられ、長さの部分列を抽出できるかどうかを判断するように求められます。$K$強い構造上の制限があります。選択されたサブシーケンス内で、要素は少数の厳密に減少するシーケンスに分解可能でなければなりません。 古典的な等価性により、これは、選択されたサブシーケンス内の最も長く増加するサブシーケンスが特定のしきい値によって制限されることを要求するのと同じです。 

グローバル順列には、それ自体の最長の増加するサブシーケンスがあり、その長さを呼び出します。$L$。 この値は、構造全体がどの程度「非減少」であるかを特徴づけるとともに、配列全体をカバーするために必要な減少サブシーケンスの最小数も決定するため、非常に重要です。 

タスクは、任意の部分列を構築することではなく、次のサイズの部分列が存在するかどうかを判断することです。$K$その内部順序は、上記の意味で十分に「単純」です。 

制約の観点から見ると、すべては LIS 関連の構造を効率的に計算することを中心に展開します。 すべてのサブシーケンスを試す解決策は不可能です。$\binom{N}{K}$候補者たち。 平$O(N^2)$メソッドが境界線にある場合$N$大きいです。 これにより私たちは標準に向かうことになります$O(N \log N)$LIS 機構と、サブシーケンスが完全な配列から構造を継承する方法についての慎重な組み合わせ推論。 

素朴な考え方による典型的な失敗例は、局所的に増加または減少する要素を貪欲に選択することで適切なサブシーケンスが常に見つかると仮定した場合に現れます。 たとえば、次のような順列では、$[3,1,4,2,5]$構造化されたサブシーケンスを貪欲に抽出すると、グローバル LIS 制約によってすでに特定の機能が妨げられていることを見逃してしまう可能性があります。$K$- ローカルな選択が可能であるように見えても、既存のサブシーケンス。 

重要な問題は、プロパティが選択された要素だけでなく、それらが順列全体のグローバルな LIS 分解とどのように相互作用するかにも依存することです。 

## アプローチ

 ブルートフォース手法では、サイズのすべての部分列を列挙しようとします。$K$、LIS を計算し、それが必要な境界を満たしているかどうかを確認します。 各 LIS 計算は次のようになります。$O(K \log K)$、そして、あります$\binom{N}{K}$これにより、中程度の人でもこれは完全に実行不可能になります。$N$。 

構造的なブレークスルーは 2 つの古典的な事実から来ています。 まず、シーケンスの LIS の長さは、シーケンスを分割するために必要な減少するサブシーケンスの最小数と等しくなります。 第 2 に、完全な順列を減少するサブシーケンスに最適に分解すると、すべてのサブシーケンスが尊重する必要があるグローバルな制約が得られます。 

させて$L$配列全体の LIS 長になります。 順列を正確に分解できます。$L$標準的な忍耐ソート構造を使用してサブシーケンスを減少させます。 電話してください$D_1, D_2, \dots, D_L$、サイズが小さい順に並べられます。

重要な洞察は、構築されたサブシーケンスの最悪のケースは、ある部分から部分的に取らざるを得なくなったときに起こるということです。$D_m$。 取得する完全なブロックの数と、元の配列で未使用のまま残される要素の数との間のバランスは、以下の不等式に直接つながります。$L, N,$そして$K$。 

小さく減少するサブシーケンスを多く取りすぎると、選択したセットが「断片化」しすぎて、選択したサブセットの LIS が、鳩の巣引数によって許容される制限を超えて拡大する必要があります。 分解がより大きなブロックに向かって十分に偏っている場合は、パックすることができます。$K$効果的な増加制約の数を少なく保ちながら、要素を増やすことができます。

 ## アルゴリズムのチュートリアル

 この解決策は、順列全体の減少する部分列分解を構築し、収集するためにそれらのブロックの数が必要かどうかを推論することを中心に展開します。$K$要素。 

### ステップ

 1. 貪欲な「忍耐ソート」スタイルのプロセスを使用して、完全な順列の最小数の減少サブシーケンスへの LIS 分解を計算します。 

このような数列の数は$L$、これは配列の LIS 長でもあります。 
2. 減少する各サブシーケンスのサイズを記録します。$D_1, D_2, \dots, D_L$、次に、これらのサイズを昇順でない順に並べ替えます。 

断片化を最小限に抑えるために、最初に大きな構造ブロックを消費する必要があるため、この順序は重要です。 
3. サブシーケンス全体を貪欲に取得する$D_1, D_2, \dots$収集された要素の合計数が少なくとも$K$。 

させて$m$累積合計がそれに達するか超える最初のインデックスである$K$。 
4. この選択を解釈します: 構築されたサブシーケンス$b$多くてもから作られています$m$ブロックを減らしていく。 

もし$m$小さいです、それでは$b$は、少数の減少シーケンスで覆われているため、強力な構造を持っています。 
5. 世界的な不平等が存在するかどうかを確認する$$2(L + K - N) \le K + 1$$が成立する。 

これが失敗すると、LIS 構造と強制オーバーラップの間の鳩のような議論により、構築が存在できなくなります。 
6. これが成立する場合、分解による貪欲な構築により、選択されたサブシーケンスの LIS が十分に小さいことが保証され、したがって必要な条件が満たされます。 

### なぜ効果があるのか

 への分解$L$サブシーケンスを減らすことは、置換の表現で使用するシーケンスの数を減らすことができないという意味で最適です。 これは、抽出したサブシーケンスが交差するブロックの数に基づいて、その LIS の下限を継承することを意味します。 

構築するとき$b$サイズの小さい順にブロック全体を消費することで、潜在的な LIS インフレの唯一の原因である部分的に使用される構造の数を最小限に抑えます。 この不等式は、部分ブロックが許容制限を超えて LIS を強制できないしきい値を正確に捉えています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lis_decreasing_partition(arr):
    # patience sorting style: maintain piles by last element
    piles = []
    for x in arr:
        # place into first pile whose last element > x
        lo, hi = 0, len(piles)
        while lo < hi:
            mid = (lo + hi) // 2
            if piles[mid][-1] > x:
                hi = mid
            else:
                lo = mid + 1
        if lo == len(piles):
            piles.append([])
        piles[lo].append(x)
    return piles

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    piles = lis_decreasing_partition(a)
    L = len(piles)

    sizes = sorted((len(p) for p in piles), reverse=True)

    need = k
    m = 0
    total = 0
    for s in sizes:
        if total >= need:
            break
        total += s
        m += 1

    lhs = 2 * (L + k - n)
    rhs = k + 1

    if lhs <= rhs:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```機能`lis_decreasing_partition`順列の標準的な最適な分割を減少するサブシーケンスに構築します。 各パイルはそのようなサブシーケンスの 1 つを表し、パイルの数は配列の LIS 長と正確に一致します。 

次に、杭のサイズを抽出します。これは、構築の議論は、これらの減少するブロックの内部順序ではなく、これらの減少するブロックの大きさのみに依存するためです。 貪欲な累積ステップ モデルは、到達するまでブロック全体を取得します。$K$要素。 

最後に、そのようなパッキングによって増加する制約が多すぎることを回避できるかどうかを捉える不等式を評価します。

 ## 特殊なケース

 1 つの特殊なケースは、順列がすでに厳密に減少しているときに発生します。 この状況では、LIS は 1 で、分解には 1 つのブロックがあります。 貪欲な構造では、このブロックから要素がすぐに収集されるため、$m=1$、条件は常に次の場合に合格します。$K$に比べて大きすぎない$N$。 アルゴリズムは、断片化が存在しないことを正しく認識します。 

もう 1 つの特殊なケースは、完全に増加する順列です。 ここでは、すべての要素が独自の減少する部分列を形成するため、分解は次のようになります。$L=N$。 貪欲なプロセスは多くのシングルトンを消費するため、$m$不平等が極度の断片化を許さない場合、大規模かつ失敗を引き起こす可能性があります。 アルゴリズムは、$K$-subset は、グローバル構造から高度な LIS の複雑さを継承します。 

次のような混合順列$[2,1,4,3,6,5]$は、ペアが自然減少ブロックを形成する中間領域を示しています。 分解によりバランスの取れた山が生成され、答えが「YES」であるかどうかは、意図した特性評価と一致する局所的な構造ではなく、不等式に完全に依存します。
