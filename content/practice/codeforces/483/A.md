 ## 解決策
 ## 問題の理解

 共素関係の非常に特殊なパターンを形成するように、指定された間隔内で 3 つの整数を構築するように求められます。 3 つの異なる数字が必要です$a < b < c$、すべての間にあります$l$そして$r$、ここで、隣接するペア$(a,b)$そして$(b,c)$1 以外の公約数は共有しませんが、外側のペアは共有します$(a,c)$1 より大きい約数を共有します。 

より具体的に言えば、共素性の「壊れた推移性」の例を探しています。つまり、中央の数は両端と互いに素ですが、両端は互いに素ではありません。 タスクは、そのようなトリプルを構築するか、そのようなトリプルが区間内に存在しないことを判断することです。 

制約$r - l \le 50$重要な構造上のヒントです。 それでも$r$それ自体は次のように大きくできます$10^{18}$、間隔が非常に小さいです。 これは、範囲内のすべての値を検査する、またはそこから候補を構築するアプローチが実行可能であることを意味します。 間隔内のすべてのトリプルのブルート フォース スキャンは、最大でも$\binom{51}{3}$、小さいです。 

主な微妙なエッジ ケースは、間隔が小さすぎて 3 つの異なる数値を含めることができない場合です。 もし$r - l < 2$の場合、使用できる整数は 3 つ未満であり、答えは直ちに不可能になります。 因子構造の観点から区間がまばらな場合、別のエッジ ケースが発生しますが、連続する整数がすでに有用な共素性パターンを提供していることが多いため、失敗はまれで構造化されています。 

単純な間違いは、ランダムなトリプルが常に存在すると仮定したり、次のような固定パターンを試したりすることです。$(x, x+1, x+2)$可分性条件を検証せずに。 間隔が小さい場合、またはローカル算術構造がエンドポイント間に共有除数を生成しない場合、これは失敗します。 

## アプローチ

 ブルートフォースソリューションでは、すべてのトリプルに対して反復処理が行われます。$a < b < c$内部$[l,r]$、どうかを確認してください$\gcd(a,b)=1$、$\gcd(b,c)=1$、 そして$\gcd(a,c)\neq 1$。 間隔サイズは最大 51 であるため、これには最大約 22,000 のトリプルが含まれ、各チェックでは$O(\log r)$gcdの計算。 これはすでに十分に高速ですが、問題のより深い構造が隠蔽されています。 

重要な点は、恣意的に検索する必要がないということです。 単純な構成パターンは、ほとんどの場合、連続した整数で機能します。$x, x+1, x+2$。 連続する数字は互いに素であることがわかっているので、$\gcd(x,x+1)=1$そして$\gcd(x+1,x+2)=1$。 私たちが強制しなければならない唯一の条件は、$\gcd(x,x+2) \ne 1$。 これは、両端が共通の要素を共有している場合に発生します。これを保証する最も簡単な方法は、$x$偶数として$x$そして$x+2$どちらも 2 で割り切れます。 

したがって、問題は偶数を見つけることになります。$x$そのような$x, x+1, x+2$すべては間隔の中にあります。 そのようなトリプルが存在しない場合は、総当たり攻撃に戻るか、不可能であると結論付けます。 

ドメインが小さいため、総当たりアプローチが機能します。 建設的なアプローチは、パリティを利用して共有約数を強制するため機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3 \log r)$、$n \le 51$|$O(1)$| 承認済み |
 | 建設的 (パリティベース) |$O(r-l)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず間隔を変換します$[l,r]$整数の小さな明示的なリストに変換します。 範囲サイズは最大 51 であるため、これは安全かつ高速です。 

1. アレイを構築する$vals = [l, l+1, \dots, r]$。 これにより、算術推論を繰り返すことなく、すべての候補に直接アクセスできるようになります。 
2. このリストの長さが 3 未満の場合は、すぐに -1 を返します。 トリプルを形成するのに十分な個別の数字がありません。 
3. インデックスのすべてのペアを反復処理します。$i < j < k$。 トリプルごとに$(vals[i], vals[j], vals[k])$、次を計算します。 

-$\gcd(vals[i], vals[j])$-$\gcd(vals[j], vals[k])$-$\gcd(vals[i], vals[k])$最初の 2 つの gcd が 1 で、最後の gcd が 1 より大きいパターンを検索しています。 
4. このようなトリプルが見つかるとすぐに、それを昇順で返します。 

このステップバイステップの検索が許容される理由は、候補の数が非常に少ないため、より深い数理論のショートカットに依存するのではなく、区間の完全な構造チェックを効果的に実行できるためです。 

### なぜ効果があるのか

 すべての有効な解は指定された間隔内から得られる必要があり、すべてのトリプルは必要な共素性条件について明示的にテストされます。 考えられるすべてのトリプルをソート順に列挙するため、有効な構成を見逃すことはありません。 何も存在しない場合は、その区間内で有効な反例を形成することができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

l, r = map(int, input().split())

vals = list(range(l, r + 1))

n = len(vals)
if n < 3:
    print(-1)
    sys.exit(0)

for i in range(n):
    for j in range(i + 1, n):
        for k in range(j + 1, n):
            a, b, c = vals[i], vals[j], vals[k]
            if gcd(a, b) == 1 and gcd(b, c) == 1 and gcd(a, c) != 1:
                print(a, b, c)
                sys.exit(0)

print(-1)
```このソリューションは、範囲内のすべての可能なトリプルを直接列挙し、3 つの必要な gcd 条件をチェックします。 の使用`sys.exit(0)`有効な反例が見つかったらすぐに停止し、不必要な計算を回避します。 

唯一微妙な点は、Python の組み込み機能に依存していることです。`gcd`、呼び出されるのは最大でも数千のペアであるため、この制約には十分な速度です。 

## 実用的な例

 ### 例 1:`l = 2, r = 4`リストはあります`[2, 3, 4]`。 

| 私 | j | k | | b | c | gcd(a,b) | gcd(b,c) | gcd(a,c) | 有効 |
 | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 2 | 3 | 4 | 1 | 1 | 2 | はい |

 アルゴリズムはトリプルを即座に見つけます。 これは意図した構造を裏付けています。3 は 2 と 4 の間の互いに素なブリッジとして機能し、2 と 4 は約数 2 を共有します。 

### 例 2:`l = 1, r = 2`我々は持っています`[1, 2]`, したがって、トリプルはありません。 

アルゴリズムは最初に長さをチェックし、それが 3 未満であることを確認し、すぐに -1 を返します。 これは、最小間隔の正しい処理を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((r-l)^3 \log r)$| 値は最大 51 なので、gcd チェックでは約 22,000 個のトリプルになります。 
| スペース |$O(1)$| 間隔リストのみを保存します |

 制約$r-l \le 50$は、三次列挙であっても実際には時間制限内で簡単であることを保証します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    l, r = map(int, input().split())
    vals = list(range(l, r + 1))

    if len(vals) < 3:
        return "-1"

    n = len(vals)
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                a, b, c = vals[i], vals[j], vals[k]
                if gcd(a, b) == 1 and gcd(b, c) == 1 and gcd(a, c) != 1:
                    return f"{a} {b} {c}"

    return "-1"

# provided samples
assert run("2 4\n") == "2 3 4", "sample 1"
assert run("1 2\n") == "-1", "sample 2"

# custom cases
assert run("3 5\n") == "-1", "no valid triple in small odd range"
assert run("10 14\n") == "10 11 12" or run("10 11 12\n") == "10 11 12", "consecutive construction exists"
assert run("6 8\n") == "6 7 8", "simple valid consecutive case"
assert run("7 9\n") == "-1", "insufficient parity structure"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 5 | -1 | 有効な共部性パターンのない狭い範囲 |
 | 10 14 | 10 11 12 | 連続的な建設的な解決策の存在 |
 | 6 8 | 6 7 8 | 最小の有効なトリプル |
 | 7 9 | -1 | gcd 構造が失敗するエッジケース |

 ## 特殊なケース

 インターバルに関しては`[1,2]`の場合、数値が 3 つ未満であるため、アルゴリズムはすぐに -1 を返します。 これにより、縮退した入力サイズが正しく処理されることが確認されます。 

みたいな間隔で`[6,8]`、列挙は単一のトリプルをチェックします。`(6,7,8)`。 gcd 値は次のとおりです。`gcd(6,7)=1`、`gcd(7,8)=1`、 そして`gcd(6,8)=2`、したがって、要求どおりに正確に成功します。 範囲が狭いため、ブルート フォース ループは一定時間でこれに到達します。 

数値がすべてペアごとに互いに素であるか、エンドポイント間で共有される約数がない区間の場合、すべての候補が gcd 制約に対して明示的に検証されるため、アルゴリズムはすべてのトリプルを使い果たし、不可能であると正しく結論付けます。
