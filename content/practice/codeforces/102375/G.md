 ## 問題の理解

 先行ゼロのない、空ではない 10 進数文字列が 1 つ与えられます。 文字列は必ずしも基数 10 で解釈されるわけではありません。文字列に現れるすべての数字がその基数で有効な数字であれば、基数 (B) を選択することもできます。 基数 (B) の同じ数字のシーケンスを解釈すると、整数 (D) が生成されます。 

私たちのタスクは、(B) と (1 < X < D) で (B) と (X) の両方が最大 (10^9) になるように (D) の適切な約数 (X) を選択することです。 そのようなペアが存在しない場合は、(-1) が出力されます。 

長さは (3\cdot10^6) に達する可能性があるため、入力自体はすでに数百万文字の長さになります。 文字列全体を繰り返しスキャンしたり、多数の基底を試行したり、結果として得られる膨大な数に対して整数因数分解を実行したりするソリューションは、適切ではありません。 基本的に、数字を 1 回の線形パスで通過する必要があります。 有益な事実は、すべての桁の合計が最大 (9\cdot3\cdot10^6=27\cdot10^6) であり、(10^9) をはるかに下回るということです。 これにより、基数と除数の両方について十分に小さい候補が得られます。 

メインの構築を盲目的に適用すると失敗する小さなケースがいくつかあります。 入力用`1`、基数に関係なく、表現される値は常に (1) であるため、適切な約数は存在せず、正しい答えは次のとおりです。`-1`。 入力用`4`の場合、桁の合計は (4) ですが、その合計を除数として選択すると (X=D=4) となり、これは適切な約数ではありません。 正しい答えは次のとおりです`10 2`。 入力用`10`の場合、桁の和は (1) であるため、桁の和に基づく構成では (X=1) を使用できません。 それにもかかわらず、基数 (10) は (D=10) を与え、(X=2) は機能します。 これらのケースは、最終的なアルゴリズムが長さ 1 の文字列を分離する理由と、桁の合計が 1 の場合を説明します。 

## アプローチ

 直接的なアプローチでは、基数 (B) を試し、対応する数値 (D) を構築し、約数 (X) を検索します。 すべての (10^9) 個の可能な塩基の中からのみを選択するだけでも、少なくとも (10^9) 個の候補がすでに得られます。 長さ (n) の文字列から 1 つの塩基を評価するには、その桁を処理する必要があるため、考えられるすべての塩基を調べるだけでも、少なくとも (10^9n) 桁の演算が必要になります。 最大長では、因数分解を行う前に少なくとも (3\cdot10^{15}) の演算が行われます。 因数分解 (D) は、(D) に数百万桁の 10 進数が含まれる可能性があるため、さらに悪化します。 

候補の基底と約数のテストは簡単であるため、ブルート フォースは機能しますが、可能な基底の空間と表現される数が膨大であるため、失敗します。 重要な観察は、(D) を明示的に知る必要がまったくないということです。 

基数 (B) で書かれた数値の場合、(B-1) を法として減算すると、(B\equiv1\pmod{B-1}) となるため、(B) のすべての累乗が (1) に置き換えられます。 したがって、数字が (a_0,a_1,\ldots,a_{n-1}) の場合、

 [
 D=\sum a_iB^i\equiv\sum a_i\pmod{B-1}。 
】

 桁の合計を (S) とします。 私たちが選ぶなら

 [
 B=S+1、
 】

 そうすると (B-1=S)、つまり (D\equiv S\equiv0\pmod S) になります。 したがって、(X=S) は自動的に (D) の約数になります。 

こちらは中央工事です。 (S) は少なくとも個々の数字であるため、(B=S+1) は有効な基数です。 (S\le27\cdot10^6) なので、(B) と (X) はどちらも (10^9) よりも快適に下回ります。 

長さが少なくとも 2 で (S\ge2) の文字列の場合、(X=S) も (D) よりも厳密に小さくなります。 先頭の数字は少なくとも 1 であるため、(D\ge B=S+1>S=X) となります。 

少なくとも 2 桁の残りの状況は (S=1) だけです。 最初の数字はゼロ以外なので、文字列は次のようにする必要があります。`100...0`。 (B=10) を選択すると (D=10^{n-1}) が得られ、(X=2) が適切な約数になります。 最後に、1 桁の文字列は、基数とは関係なく、その桁を正確に表します。 このような数値が適切な約数を持つのは、その数字自体が複合数字である場合 (許可された数字の中で (4,6,8,9) を意味する場合のみ) です。

 ## アルゴリズムのチュートリアル

 1. 数字列を読み取り、その長さと数字の合計 (S) を計算します。 本体の建設には合計だけが必要なので、潜在的に膨大な数 (D) を建設する理由はありません。 
2. 文字列が 1 桁の場合は、個別に扱います。 1 桁の表現は、基数に関係なく、常にその桁と等しい値を持ちます。 数字が (4,6,) または (8) の場合は、(B=10) と (X=2) を選択します。 桁が (9) の場合は、(B=10) と (X=3) を選択します。 (1,2,3,5,7) の場合、数値は素数なので、(-1) を出力します。 
3. 文字列に少なくとも 2 桁の数字があり、(S=1) の場合、文字列は必ず`100...0`。 (B=10) と (X=2) を選択します。 表される値は (10^{n-1}) であり、(2) で割り切れ、(2) より大きくなります。 
4. それ以外の場合は (n\ge2) および (S\ge2)。 (X=S)と(B=S+1)を設定します。 すべての桁が最大 (S) であるため、基数は有効であり、厳密には (B) より小さいです。 
5. (B) と (X) を出力します。 (S\le27\cdot10^6) なので、両方の値は (10^9) の制限を満たします。 また、(D\ge B=S+1) であるため、(D>X) になります。 

### なぜ効果があるのか

 主な構造の背後にある不変式は (B\equiv1\pmod{B-1}) です。 (B=S+1) の場合、これは (B\equiv1\pmod S) になります。 したがって、すべての位置パワー (B^k) は (1) モジュロ (S) に一致するため、表現された数全体は (D\equiv S\equiv0\pmod S) を満たします。 したがって、(X=S) は常に (D) を除算します。 

構造もあらゆる限界を満たしています。 桁の合計は最大 (27\cdot10^6) なので、(B=S+1\le27,000,001) と (X=S\le27,000,000) になります。 (S) は少なくとも最大桁であるため、基数 (B) ではすべての桁が有効です。 長さが少なくとも 2 の文字列の場合 (D\ge B>X)、除数は適切です。 特殊なケースは、(S) が有効な固有約数として機能できない状況を正確にカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(s: str) -> str:
    n = len(s)
    digit_sum = sum(ord(c) - 48 for c in s)

    if n == 1:
        d = ord(s[0]) - 48

        if d in (4, 6, 8):
            return "10 2"
        if d == 9:
            return "10 3"
        return "-1"

    if digit_sum == 1:
        return "10 2"

    return f"{digit_sum + 1} {digit_sum}"

s = input().strip()
print(solve(s))
```最初のパスでは、文字列全体を整数に変換せずに桁の合計を計算します。 最大 300 万桁の文字列を整数に変換する必要はなく、多くの Python 環境では追加の変換制限が適用されます。 

1 桁のみの場合は位置ベースは効果がないため、1 桁の分岐は別になります。 例えば、`4`はすべての有効な基数で (4) を表すため、(4) 自体に適切な約数があるかどうかを実際に尋ねる必要があります。 

桁の合計が 1 である複数桁の文字列の場合、最初の桁は 1 であり、他の桁はすべて 0 である必要があります。 表現される数値が 10 の正の累乗であるため、固定構造 (B=10、X=2) が機能します。 

一般部門では、`digit_sum + 1`がベースであり、`digit_sum`は除数です。 コードは (D) を決して計算しません。これが実装の主な利点です。 したがって、Python の整数は、入力の長さに関係なく、(27\cdot10^6+1) で囲まれた小さな値にのみ使用されます。 

Python ではオーバーフローの懸念はなく、固定幅の整数を使用する言語でも、構築された (B) と (X) は簡単に 32 ビットの符号付き整数の範囲内に収まります。 文字列は 1 回スキャンされるため、実装では隠れた二次関数の動作も回避されます。

 [

 】

 ## 特殊なケース

 入力用`1`、アルゴリズムはすぐに 1 桁の分岐に入ります。 その値はすべての可能な基数で (1) であるため、(X<D) を伴う (X>1) は存在しません。 出力は正しく行われています`-1`。 

入力用`4`の場合、1 桁ブランチは (4) を複合として認識し、(X=2) を選択します。 基数 (10) は、数字 (4) が (10) より小さいため有効であり、表現された値は (4) のままです。 したがって`10 2`(2<4) および (2\mid4) を満たします。 

入力用`9`の場合、(3\mid9) であるため、アルゴリズムは (2) の代わりに (X=3) を使用します。 出力`10 3`は (D=9) を表すため、除数は適切です。 

入力用`10`の場合、桁の合計は (1) となり、(X=1) が必要となるため、主要な構築は不可能になります。 特別なブランチは (B=10) を選択し、(D=10) を与え、(X=2) が適切な約数になります。 同じ推論がフォームのすべての入力に対して機能します。`100...0`少なくとも 2 桁の数字。 

次のような入力の場合`2222`の場合、桁の合計は (8) であるため、アルゴリズムは (B=9) と (X=8) を選択します。 表現される値は、

 [
 2\cdot9^3+2\cdot9^2+2\cdot9+2=1622、
 】

 (1622) は (8) で割り切れます。 合同引数は (D) を構築することなくこれを与えます。 

最大サイズの入力の場合:`1`(2,999,999) 個のゼロが続いても、桁の合計は (1) のままです。 したがって、このアルゴリズムは、表現された膨大な数を処理しようとはしません。 戻ります`10 2`線形数字合計パスの直後であり、表される値は (10^{2,999,999}) であり、これは確実に (2) で割り切れ、(2) より大きくなります。
