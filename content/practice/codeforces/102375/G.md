 ## 問題の理解

 先行ゼロのない空ではない 10 進数文字列が与えられます。 この数字は、必ずしも関心のある数値を 10 進数で表現したものであるとは限りません。 代わりに、基数 (B) を選択し、基数 (B) でまったく同じ数字シーケンスを解釈することもできます。 数字が (a_0,a_1,\ldots,a_{n-1}) の場合、結果の値は次のようになります。 

[
 D=a_0B^{n-1}+a_1B^{n-2}+\cdots+a_{n-1}。 
】

 基数は、文字列に出現するすべての数字より少なくとも 1 つ多くなければなりません。 (2\le X<D) および (X\le10^9) を使用して、底 (2\le B\le10^9) と適切な約数 (X) を見つける必要があります。 そのようなペアが存在しない場合は、(-1) が出力されます。 元のコンテスト ステートメントでは、(n\le3\cdot10^6)、2 秒の制限、および 512 MiB のメモリが与えられています。 

長さが重要な制約です。 最大 300 万桁では、長さが 2 次のものは不可能であり、文字列全体を何度も繰り返し操作するアルゴリズムさえも望ましくありません。 一定数の線形パスが必要です。理想的には、数字のいくつかのプロパティを収集するために 1 回のパスのみが必要です。 数値 (D) 自体は数百万桁になる可能性があるため、それを整数として構築することはまったく不要であり、通常の固定幅の算術演算では不可能です。 

魅力的な構築が失敗する小さなケースがいくつかあります。 入力用`1`、表される数は基数に関係なく常に (1) であるため、適切な約数はなく、答えは正しくなります。`-1`。 入力用`2`の場合、値は常に (2) であるため、(X<D) が必要であるため、(X=2) の選択は無効です。 1桁の素数でも同じ問題が発生します`3`、`5`、 そして`7`。 それに対して、入力は`4`すでに複合されているため、`10 2`表現された値が (4) であり、その適切な除数 (2) が有効であるため、この関数は機能します。 

もう一つの境界ケースは、`10`。 その桁の合計は (1) であるため、桁の合計に直接基づく構成では (X=1) を使用できません。 有効な答えは、`4 2`: 文字列`10`基数 (4) は (2) で割り切れる (4) を表します。 フォームのすべての文字列に対して同じ特殊な構造が機能します。`100...0`少なくとも 2 桁の数字を持っていること。

 ## アルゴリズムのチュートリアル

 1. 数字列を読み取り、その数字の合計 (S) を計算します。 (1) モジュロ (S) に一致する基底を選択すると、位置表現全体がその桁の和をモジュロ (S) に変換するため、和だけが必要になります。 
2. 文字列の長さが 1 の場合、値を直接処理します。 のために`1`、有効な約数はありません。 のために`2`、`3`、`5`、 そして`7`、その数は素数です。 のために`4`、`6`、`8`、 そして`9`、底 (10) とその数字の適切な約数を選択します。 
3. 文字列に少なくとも 2 桁の数字があり、(S=1) の場合、文字列は必ず`100...0`。 (B=4) と (X=2) を選択します。 表現された値は (4^{n-1}) であるため、(2) で割り切れます。また、(n\ge2) であるため、その値は少なくとも (4) です。 
4. 文字列に少なくとも 2 桁の数字と (S\ge2) がある場合は、(X=S) と (B=S+1) を選択します。 すべての桁は最大 (S) であるため、基数 (B) ではすべての桁が有効です。 
5. 前のステップでの選択により、(B\equiv1\pmod X) が得られます。 したがって、すべての (k) に対して (B^k\equiv1\pmod X) となり、表現された数は次の条件を満たします。 
[
 D\equiv S\equiv0\pmod X.
 】
 最初の桁が正で、少なくとも 2 桁あるため (D\ge B=S+1>X)、(X) が適切な約数になります。 
6. 構築されたペアを印刷します。 (S\le9\cdot3\cdot10^6=27\cdot10^6) なので、(S) と (S+1) は両方とも (10^9) 境界を満たします。 

構築の背後にある不変式は合同式 (B\equiv1\pmod X) です。 これが成立すると、位置表現は (B) モジュロ (X) のべき乗への依存をすべて失い、その桁の正確な合計が残ります。 その合計に等しい (X) を選択すると、表現された数値が (X) で割り切れるようになります。 この除数が (1) となる唯一の状況は (S=1) であり、その場合は個別に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    if n == 1:
        d = ord(s[0]) - ord('0')

        if d < 4:
            print(-1)
            return

        for x in range(2, int(d ** 0.5) + 1):
            if d % x == 0:
                print(10, x)
                return

        print(-1)
        return

    digit_sum = sum(ord(c) - ord('0') for c in s)

    if digit_sum == 1:
        print(4, 2)
        return

    x = digit_sum
    b = x + 1

    print(b, x)

if __name__ == "__main__":
    solve()
```最初のブランチは、基数が数値を変更できないため、1 桁の文字列を処理します。 1 桁の数 (d) の場合、有効な約数は (d) が合成されたときに存在します。 (\sqrt d) までの約数のみをテストするだけで十分ですが、値が非常に小さいため、ハードコードされたチェックでも機能します。 

長い文字列の場合、コードは 1 回のパスで桁の合計を計算します。 Python の整数は、最大値が (27\cdot10^6) のみであるため、この合計を快適に格納できます。 

合計が (1) の場合、負でない数字と最初の数字がすでに (1) であることから、他にゼロ以外の数字が存在しないことがわかります。 基数 (4)、除数 (2) の構築は、(D) を構築することなく機能します。 

少なくとも (2) の合計の場合、コード セットは次のようになります。`x = digit_sum`そして`b = x + 1`。 文字列で表される巨大な数値を評価する必要はありません。 可分性証明は完全にモジュロ (x) で動作します。 

Python ではオーバーフローの問題もありません。 さらに重要なのは、実装では (B^{n-1}) や (D) が決して作成されないことです。(D) には数百万の桁が含まれる可能性があるため、これは任意精度の整数を使用する言語であっても間違った実装戦略となります。

## 特殊なケース

 入力用`1`の場合、アルゴリズムはすぐに 1 桁の分岐に入ります。 その値は (1) なので、除数を探すループも必要ありません。答えは次のようになります。`-1`。 これにより、(X>1) をチェックせずに数字自体と等しい (X) を選択するという最も基本的な間違いが見つかります。 

入力用`2`、同じ 1 桁のブランチは、数値が合成ではないことを認識し、出力します。`-1`。 選択する`B=3, X=2`表面的には魅力的に見えますが、表現される数は依然として (2) なので (X=D) となり、厳密な不等式に違反します。 

入力用`4`、アルゴリズムは (2) を除数として見つけて出力します。`10 2`。 表現された値は (4) のままなので、結果は (2<D) を満たします。 これは、数字の合計構造を機械的に適用するのではなく、1 桁の入力を個別に処理する必要がある理由を示しています。 

入力用`10`の場合、桁の合計は (1) ですが、約数は少なくとも (2) でなければならないため、これを約数として使用することはできません。 文字列には 2 桁の合計 (1) があるため、正確に次のようにする必要があります。`10`。 特別な分岐は (B=4) を選択し、(D=4) と (X=2) を与えます。 ここでは (2\mid4) および (2<4) であるため、この構造は有効です。 

入力用`1000`、同じ推論により (B=4)、(X=2) が得られます。 表現される数は (4^3=64) であり、(2) で割り切れます。 桁の合計が常に少なくとも (2) であると仮定する不注意な実装では、代わりに (X=1) を出力しようとしますが、これは禁止されています。 

次のような入力の場合`11`の場合、桁の合計は (2) であるため、アルゴリズムは (B=3) と (X=2) を選択します。 表される値は (1\cdot3+1=4) および (4\equiv0\pmod2) です。 厳密な不等式 (X<D) も成り立ちます。 これは、一般的な構造の最小の重要な例です。
