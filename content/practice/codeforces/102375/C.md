 ## 解決策
 ## 問題の理解

 (1) から (N) までの番号が付けられた正確に (N) 個のルームがあり、正確に (N) 人の参加者がいます。 参加者 (i) はパスポート番号 (a_i) を持っています。 参加者の部屋への 1 対 1 の割り当てを選択することができ、参加者のパスポート番号が受け取った部屋の番号と等しい場合に、参加者は一致を作成します。 

タスクは、一致の数を最大化することです。 (N) より大きいパスポート番号は、その番号を入力する余地がないため、一致することはありません。 (1 \le x \le N) を持つパスポート番号 (x) の場合、部屋 (x) に入れることができる参加者は 1 人だけであるため、(x) の重複によって複数の一致を作成することはできません。 

重要な結果は、区間 ([1,N]) 内のすべての個別のパスポート番号が、正確に 1 つの一致の候補となることです。 配列内でその間隔の異なる値がいくつ発生するかを数えるだけで済みます。 

限界 (N \le 10^5) は線形アルゴリズムまたは (O(N\log N)) アルゴリズムには十分小さいですが、一般的な競合プログラミングの時間制限の下では (O(N^2)) アプローチは除外されます。 (N=10^5) では、二次スキャンは約 (10^{10}) 件の比較を実行できますが、これは実用的なレベルをはるかに超えています。 パスポート番号は (10^9) に達する可能性があるため、パスポート番号によってインデックス付けされた配列を割り当てると、膨大なメモリが浪費されます。 ハッシュ セットは、実際に発生する値のみを保存するため、自然に適合します。 

いくつかのケースでは、不注意な実装により間違った答えが生成される可能性があります。 まず、重複は 1 回としてカウントされる必要があります。 入力用```
5
1
3
5
7
5
```答えは (4) ではなく (3) です。部屋 (1)、(3)、および (5) は一致する可能性がありますが、パスポート (5) を持つ 2 人の参加者が同じ部屋を争うからです。 

次に、部屋の範囲外の値は無視する必要があります。 のために```
4
1000000000
1000000000
1000000000
1000000000
```番号 (10^9) を持つ部屋はないので、答えは (0) です。 

3 番目に、境界値 (N) は有効であり、含める必要があります。 のために```
3
1
2
3
```答えは(3)です。 をチェックする実装`a[i] < N`の代わりに`a[i] <= N`誤って (2) を返します。 

最後に、最小の部屋範囲が正しく機能する必要があります。 のために```
1
1
```答えは (1) ですが、```
1
2
```答えは (0) です。 これらのケースでは、有効な間隔の終点付近での間違いが明らかになります。 

## アプローチ

 直接的なアプローチは、すべての部屋を検討し、その部屋番号と同じパスポートを持つ人をすべての参加者から検索することです。 各部屋 (r) について、(N) 個のパスポート番号をスキャンし、参加者の中にパスポート (r) があるかどうかを確認します。 そのような参加者がいる場合は、1 試合としてカウントします。 これは正しいです。各ルームには 1 人の参加者だけをホストできるため、ルーム (r) が 1 つの試合に貢献するには、パスポート (r) を持つ少なくとも 1 人の参加者が存在すれば十分です。 

問題は仕事量です。 (N) 個の部屋があり、各部屋では (N^2) 個の比較を行う (N) 人の参加者をチェックする必要がある場合があります。 (N=10^5) では、最悪の場合 (10^{10}) 個の比較となり、遅すぎます。 

問題を変える観察は、パスポート番号が発生するかどうかがわかれば、参加者の身元は問題ではなくなるということです。 (1) から (N) までの部屋番号 (r) ごとに、(r) がパスポート番号の中に少なくとも 1 回出現するとき、答えは 1 を獲得します。 ルーム (r) には参加者が 1 人しか含まれないため、同じ (r) が複数出現しても役に立ちません。 

出現したすべてのパスポート番号をセットで表すことができます。 入力を読み取るときに、(1 \le a_i \le N) を満たす値のみを挿入します。 最終的に、セットのサイズは、一致する参加者が存在する部屋の数と正確に一致します。 

2 つのアプローチは次のように要約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(1)) | 遅すぎる |
 | 最適 | (O(N)) 期待される | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (N) を読み取り、という空のセットを作成します。`seen`。 このセットには、部屋に対応する各パスポート番号が含まれており、重複したものは自動的に削除されます。 
2. (N) 個のパスポート番号をそれぞれ読み取ります。 値 (a_i) が (1 \le a_i \le N) を満たす場合、それを`seen`。 (N) より大きい値はどの部屋にも一致しないため、保存する必要はありません。 
3. すべての参加者が処理された後、出力します。`len(seen)`。 セット内の各値は、そのパスポート番号を持つ参加者を対応する部屋に割り当てることで照合できる 1 つの個別の部屋番号に対応します。 

なぜこれらすべての一致が同時に達成できるのでしょうか? このセットに (k) 個の個別の有効なパスポート番号が含まれていると仮定します。 それぞれが異なる部屋番号に対応しているため、個別のパスポート値ごとに 1 人の参加者を選択し、その参加者を対応する部屋に入れることができます。 1 人の参加者が持つパスポート番号は 1 つだけであり、異なるパスポート番号が同じ参加者に属することはできないため、これらの参加者は異なります。 残りの参加者は、残りのルームに任意に割り当てることができます。 

### なぜ効果があるのか

 参加者のプレフィックスを処理した後の不変条件は次のとおりです。`seen`には、部屋の範囲 (1) から (N) にあるプレフィックスとは異なるパスポート番号が正確に含まれます。 最後に、すべての部屋 (r) について、少なくとも 1 人の参加者がパスポート (r) を持っている場合に、セットには正確に (r) が含まれます。 (r) が存在する場合、そのような参加者の 1 人をルーム (r) に割り当てることができ、一致が生成されます。 (r) が存在しない場合、どの割り当ても room (r) を一致させることはできません。 価値観が違うので、`seen`さまざまな部屋に対応しているため、これらの可能な一致をすべて一度に実現できます。 したがって、セットのサイズは正確に、可能な最大一致数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    seen = set()

    for _ in range(n):
        passport = int(input())
        if passport <= n:
            seen.add(passport)

    print(len(seen))

if __name__ == "__main__":
    solve()
```最初の行には、ルームと参加者の数が表示されます。 このセットは最初は空で、パスポート番号が処理される前の状態と一致します。 

すべての参加者に対してコードがチェックされます`passport <= n`。 パスポート番号は少なくとも (1) であることが保証されているため、下限を明示的にテストする必要はありません。 (n) に等しいパスポートは受け入れられる必要があるため、比較は次のようになります。`<=`それよりも`<`。 

電話をかける`seen.add(passport)`重複を自動的に処理します。 5 人の参加者がパスポート (5) を持っている場合でも、セットには (5) のコピーが 1 つだけ含まれており、部屋 (5) を占有できるのはそのうちの 1 人だけであるという事実と正確に一致します。 

Python では整数オーバーフローの懸念はなく、最大のパスポート値 (10^9) は整数型によって直接処理されます。 さらに重要なのは、サイズ (10^9) の配列を割り当てようとしないため、パスポートの範囲が大きくてもメモリ使用量に悪影響が及ばないことです。 

決勝戦`len(seen)`が答えです。保存されているすべての値が、達成可能な 1 つの異なる部屋の一致に対応しているからです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N)) 期待される | 各パスポートは 1 回読み取られ、予想される一定時間内にハッシュ セットに挿入されます。 |
 | スペース | (O(N)) | 最大 (N) 個の異なるパスポート番号を保存できます。 |

## テストケース```python
import sys
import io
from contextlib import redirect_stdout

def solve():
    n = int(input())
    seen = set()

    for _ in range(n):
        passport = int(input())
        if passport <= n:
            seen.add(passport)

    print(len(seen))

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    output = io.StringIO()

    try:
        with redirect_stdout(output):
            solve()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = sys.stdin.readline

    return output.getvalue().strip()

assert run("4\n1000000000\n1000000000\n1000000000\n1000000000\n") == "0", "sample 2"

assert run("1\n2\n") == "0", "minimum size, passport outside room range"

# All values are equal, so duplicates must count only once
assert run("6\n4\n4\n4\n4\n4\n4\n") == "1", "duplicate passports"

# Boundary condition: both 1 and N are valid
assert run("3\n1\n2\n3\n") == "3", "upper boundary N must be included"

# Mixed valid and invalid values
assert run("6\n1\n6\n7\n2\n2\n1000000000\n") == "3", "valid range and duplicates"

 ## 特殊なケース

 最初のエッジケースは、パスポート番号が重複している場合です。 考慮する```
5
1
3
5
7
5
```アルゴリズムは (1)、(3)、および (5) をセットに挿入します。 パスポート (7) は、部屋 (7) がないため破棄され、2 番目のパスポート (5) は、(5) がすでに存在しているため、セットを変更しないままにします。 結果は(3)です。 重要な特性は、セットがマッチング可能な参加者ではなく、マッチング可能なルームを表すということです。 

2 番目のエッジ ケースは、部屋の範囲外のパスポート番号です。 と```
4
1000000000
1000000000
1000000000
1000000000
```すべての値は失敗します`passport <= n`チェック。 セットは空のままであるため、結果は (0) になります。 これにより、不正確な一致と無関係な値の不必要な保存の両方が回避されます。 

3 番目のエッジ ケースは上限です。 のために```
3
1
2
3

有効な一致が得られる最小のケースは次のとおりです。```
1
1
```ここでは (N=1)、パスポート (1) が範囲チェックに合格します。 セットはこうなります`{1}`ですので、答えは(1)となります。 密接に関連する入力については```

最大サイズのケースには、同一のパスポート番号 (100,000) を含めることができます。 アルゴリズムは入力に対して正確に 1 回のパスを実行しますが、セットには依然として 1 つの値のみが保存されます。 これは、参加者の数が最大値に達した場合でも、解が線形のままである理由を示しています。
