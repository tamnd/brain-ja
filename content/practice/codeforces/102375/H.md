 ## 解決策
 ## 問題の理解

 与えられた最大単語長 (N) に対して、辞書には、長さが (1) から (N) までのすべての小文字の英語文字列が含まれます。 同じ長さの単語は辞書順に表示され、短い単語がすべて最初に表示されます。 辞書全体を連結すると、1 つの巨大な文字列が生成されます。 4 文字の部分文字列の出現回数が必要です。`icpc`その連結では、モジュロ (10^9+7) になります。 

難しいのは、(N) が (10^9) まで大きくなる可能性があることです。 辞書にはすでに長さ (N) の (26^N) 個の単語が含まれているため、最後の層を表現することさえ不可能です。 元の問題には 2 秒の制限と 512 MiB のメモリ制限があり、生成される単語または文字の数に比例するものは除外されます。 解は、長さを 1 つずつ列挙するのではなく、累乗剰余を使用して、(N) に対数的に依存する必要があります。 

カウントする出現には 2 種類あります。 出現箇所は、辞書の 1 つの単語内に完全に収まることも、連続する 2 つの単語間の境界を越えることもできます。 連結によって単語間の境界が削除されるため、2 番目の種類を無視すると微妙なエラーになります。 

たとえば、(N=3) の場合、個々の単語は、次の単語を含めるのに十分な長さはありません。`icpc`、そして境界もそれを作成することはできません。 正しい答えは、`0`。 (N<4) を処理せずに (26^{N-4}) を含む式を盲目的に適用するソリューションでは、誤って負の指数が解釈される可能性があります。 

(N=4) の場合、答えは次のようになります。`4`、 ない`1`。 言葉`icpc`それ自体が 1 つの内部発生に寄与します。 連続する 4 文字の単語間の境界を越えて、追加の 3 つの出現が作成されます。`cpci`、`pcic`、 そして`cicp`。 個々の単語内の出現のみをカウントするソリューションでは、これら 3 つが欠落します。 

ある長さの最後の単語と次の長さの最初の単語の間の境界も誤って処理されやすいです。 たとえば、次の境界線は、`zzz`そして`aaaa`完全にから成る`z`文字の後に続く`a`キャラクターなので作成できません`icpc`。 すべての辞書境界を同等のものとして扱うと、そのような遷移が過大にカウントされてしまいます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべての単語を辞書順に生成し、それらを連結してスキャンします。`icpc`。 これは正しいです。最終的な文字列内のすべての出現箇所が 1 回だけ検査されるためです。 ただし、

 [
 26+26^2+\cdots+26^N
 ]

 単語、合計文字数は

 [
 \sum_{L=1}^{N} L26^L=\シータ(N26^N)。 
]

 (N=10^9) の場合、(26^N) ですら表現できないため、総当たり攻撃は時間制限が関係するはるか前に天文学的に失敗します。 

有益な観察は、パターンの長さが 4 で固定されていることです。 長さ (L) のワードの場合、ワードを構築せずに内部出現を位置ごとにカウントできます。 各固定位置には 4 つの指定文字が必要で、(L-3) 個の空き位置が残るため、その長さのすべての単語にわたって (26^{L-4}(L-3)) 個の出現が存在します。 

残る唯一の問題は、連結境界です。 境界を越える 4 文字の出現は、左側の単語から (1)、(2)、または (3) 文字を取得する必要があります。 なぜならそのパターンは、`icpc`、必要な左サフィックスと右プレフィックスはそれぞれ次のとおりです。 

[
 (i,\ cpc),\qquad
 (ic,\ pc),\qquad
 (icp,\c)。 
]

 同じ長さの連続したワードの場合、右のワードは、基数 (26) で左のワードをインクリメントすることによって取得されます。 必須の左サフィックスはすべて、次の文字で終わります。`z`, したがって、キャリーはプレフィックスに到達しません。 (L\ge4) の場合、3 つの境界タイプはそれぞれ 4 つの文字位置を固定し、(L-4) 個の任意の位置を残します。 したがって、各タイプは (26^{L-4}) 回発生し、(3\cdot26^{L-4}) 回の交差が発生します。 

からの移行`z...z`に`a...a`境界文字には`z`そして`a`。 (L<4) の場合、3 つの境界パターンはその長さの単語に一貫して収まらないため、同じ長さの交差は発生しません。 

固定 (L\ge4) の内部オカレンスと交差オカレンスを組み合わせると、次のようになります。 

[
 (L-3)26^{L-4}+3\cdot26^{L-4}
 =L26^{L-4}。 
]

 したがって、問題全体は評価になります

 [
 \sum_{L=4}^{N}L26^{L-4}
 ]

 モジュロ (10^9+7)。 

これは加重等比数列です。 これは、幾何和と加重幾何和の標準公式を使用して評価でき、必要な剰余べき乗は 1 つだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N26^N)) | (O(N26^N)) | 遅すぎる |
 | 最適 | (O(\log N)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (N<4) の場合は、戻り値を返します。`0`。 4 文字を含む単語はなく、短い単語の境界は形成できません`icpc`。 
2. 考えられるすべての単語長 (L\ge4) について、完全に単語内の出現をカウントします。 (L-3) 個の可能な開始位置ごとに残りの文字には (26^{L-4}) 個の選択肢があり、((L-3)26^{L-4}) となります。 
3. 同じ長さの連続する単語間の境界をまたぐ出現数をカウントします。 分割`icpc`最初、2 番目、または 3 番目の文字の後には、3 つの可能な境界形状が与えられます。 各形状について、4 つの文字位置は固定されており、他の (L-4) 位置は任意であるため、各形状は (26^{L-4}) に寄与します。 したがって、境界寄与は (3\cdot26^{L-4}) になります。 
4. 2 つの寄与を追加します。 長さの合計（L）は、

 [
 (L-3+3)26^{L-4}=L26^{L-4}。 
]

 1. (k=L-4) および (t=N-3) とします。 この場合、(k) の範囲は (0) から (t-1) となり、答えは次のようになります。 

[
 \sum_{k=0}^{t-1}(k+4)26^k。 
]

 これを次のように分けます

 [
 \sum_{k=0}^{t-1}k26^k
 +
 4\sum_{k=0}^{t-1}26^k。 
]

 1. 等比級数公式を使用する

 [
 \sum_{k=0}^{t-1}r^k=\frac{r^t-1}{r-1}
 ]

 (r=26) で。 

1. 加重等比級数公式を使用する

 \frac{r-tr^t+(t-1)r^{t+1}}{(r-1)^2}。 
]

 すべての除算はモジュロ (10^9+7) で実行されます。 (r-1=25) は素数法を法として非ゼロであるため、その逆法が存在します。 

1. 2 進累乗を使用して (26^t\bmod(10^9+7)) を計算します。 これは (N) に対数的に依存する唯一の操作であるため、完全なアルゴリズムには (O(\log N)) 時間がかかります。 

### なぜ効果があるのか

 すべての長さ (L) について、すべての出現は 1 つの単語内、または連続する単語間の 1 つの境界をまたいで一意に属します。 内部カウントでは、考えられるすべての開始位置と残りの文字のすべての割り当てが考慮されます。 境界オカレンスの場合、分割ポイントは 3 つの内部カットの 1 つである必要があります。`icpc`、および辞書編集の後続構造は、(L\ge4) の場合、各カットに対して正確に (26^{L-4}) の有効な境界を与えます。 異なる語長間の遷移は何も寄与しません。 したがって、すべての長さの正確な寄与は (L26^{L-4}) となり、最終的な等比級数の計算ではこれらの寄与の合計が正確に評価されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
R = 26
INV25 = 280000002

def solve():
    n = int(input())

    if n < 4:
        print(0)
        return

    # We need:
    # sum_{k=0}^{t-1} (k + 4) * 26^k
    t = n - 3

    p = pow(R, t, MOD)

    # sum_{k=0}^{t-1} r^k
    geometric = (p - 1) % MOD
    geometric = geometric * INV25 % MOD

    # sum_{k=0}^{t-1} k * r^k
    weighted_num = (
        R
        - (t % MOD) * p
        + ((t - 1) % MOD) * p % MOD * R
    ) % MOD

    weighted = weighted_num * INV25 % MOD * INV25 % MOD

    answer = (weighted + 4 * geometric) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```早期リターンは (N<4) 範囲全体を処理し、負の指数や無効な境界の仮定を回避します。 

変数`t = n - 3`は置換後の項の数です (k=L-4)。 (N=4) の場合、`t`は 1 であるため、合計には、必要に応じて項 (4\cdot26^0=4) のみが含まれます。 

値`p`答えのモジュロを (26^t) 法で格納します。 Pythonの組み込み`pow(base, exponent, modulus)`べき乗剰余演算を効率的に実行し、巨大な整数 (26^t) を構築することはありません。 

(25) の逆数は次のようになります。`280000002`、なぜなら

 [
 25\cdot280000002\equiv1\pmod{10^9+7}。 
]

 加重級数の分子は剰余で減算されます`MOD`乗算の前に。 Python の整数はオーバーフローしませんが、中間値を減らすと演算が小さく保たれ、モジュール構造が明示的になります。 

元の被加数 (k+4) は加重等比級数と通常の等比級数の 4 つのコピーに自然に分割されるため、2 つの成分は別々に計算されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(\log N)) | 1 つのべき乗剰余演算は (26^{N-3}) | を計算します。 
| スペース | (O(1)) | 一定数のモジュラー整数のみが格納されます。 

可能な最大の (N) は (10^9) であるため、すべての長さを反復処理するとすでに遅すぎます。 2 進累乗では、そのような指数に対して約 30 の二乗ステップのみが必要であり、この解は規定の制限に快適に適合します。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

MOD = 10**9 + 7
INV25 = 280000002

def solution():
    input = sys.stdin.readline
    n = int(input())

    if n < 4:
        print(0)
        return

    t = n - 3
    p = pow(26, t, MOD)

    geometric = (p - 1) % MOD
    geometric = geometric * INV25 % MOD

    weighted_num = (
        26
        - (t % MOD) * p
        + ((t - 1) % MOD) * p % MOD * 26
    ) % MOD

    weighted = weighted_num * INV25 % MOD * INV25 % MOD

    print((weighted + 4 * geometric) % MOD)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solution()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def brute(n: int) -> int:
    # Independent reference for small n.
    words = []

    for length in range(1, n + 1):
        total = 26 ** length
        for x in range(total):
            chars = []
            y = x
            for _ in range(length):
                chars.append(chr(ord('a') + y % 26))
                y //= 26
            words.append(''.join(reversed(chars)))

    s = ''.join(words)
    return sum(s[i:i + 4] == 'icpc' for i in range(len(s) - 3))

def fast_reference(n: int) -> int:
    if n < 4:
        return 0

    ans = 0
    power = 1

    for length in range(4, n + 1):
        ans = (ans + length * power) % MOD
        power = power * 26 % MOD

    return ans

# Provided samples
assert run("3\n") == "0", "sample 1"
assert run("5\n") == "134", "sample 2"

# Minimum size
assert run("1\n") == "0", "minimum N"

# Boundary where the first occurrences appear
assert run("4\n") == "4", "first non-zero case"

# Small case with an independent brute-force reference
assert run("6\n") == str(brute(6)), "small brute-force cross-check"

# Uniform boundary words such as zzz...z -> aaa...a must contribute nothing
assert run("3\n") == "0", "uniform word boundary"

# Maximum allowed N, checked against a direct O(N) modular reference.
# This reference is used only by the test harness, not by the submitted solution.
assert run("1000000000\n") == str(fast_reference(1000000000)), "maximum N"
