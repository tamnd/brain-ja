 ## 問題の理解

 (P) 参加者と (T) 利用可能な問題があります。 各入力ペア ((u,v)) は、参加者 (u) が問題 (v) を知っていることを示します。 問題は複数の参加者が知っている可能性があり、参加者はコンテスト用に選択された問題を少なくとも 1 つ知っている場合は競争できません。 

空ではない問題のセットを選択する必要があります。 最初の目的は、選択した問題をまったく知らない参加者の数を最大化することです。 その数が最大になったら、2 番目の目的は、できるだけ多くの問題を選択することです。 

すべての問題 (v) について、(S_v) をそれを知っている参加者の集合とします。 一連の問題 (A) を選択すると、まさにその参加者が

 [
 \bigcup_{v\in A} S_v
 】

 は除外されます。 したがって、競争できる参加者の数は、

 [
 P-\left|\bigcup_{v\in A}S_v\right|。 
】

 重要な問題は、結合が問題間の重複に依存していることです。 一見すると、これは一般的な集合共用体の最適化問題のように見えます。 

この制約により、一般的なサブセット検索が不可能になります。 (P) と (T) は両方とも (10^5) に達する可能性がありますが、既知の参加者と問題のペアの数は (10^6) に達する可能性があります。 公式の制限は 2 秒および 512 MiB です。 (P)、(T)、または (M) に二次依存するアルゴリズムはすでに大きすぎるため、問題のサブセットを列挙することは完全に問題外です。 (10^6) の入力ペアを基本的に 1 回処理する必要があり、ソートは可能です。 

一見合理的に見える実装が間違っている可能性があるいくつかの特殊なケースがあります。 

参加者が問題を認識していない場合を考えてみましょう。```
1 3 0
```すべての問題は誰も排除しないので、最適な答えは次のとおりです。```
1 3
1 2 3
```入力に現れる問題のみを検索するソリューションでは、3 つの有効な問題がすべて見逃されてしまいます。 

もう 1 つの重要なケースは、まったく同じ参加者が複数の問題を知っている場合です。```
2 3 3
1 1
2 2
2 3
```問題 1 は参加者セット ({1}) によって知られており、問題 2 と 3 は両方とも ({2}) によって知られています。 問題 2 または問題 3 のいずれかを選択すると参加者が 1 名残り、両方を選択しても参加者が 1 名になります。 参加者の数はすでに最適であるため、次の両方を取る必要があります。```
1 2
2 3
```最小次数問題を 1 つ見つけた後に解決策が停止すると、主な目的は達成されますが、副次的な目的は達成できません。 

3 番目のケースは、どの問題を組み合わせるかを決定するのに最小次数だけでは十分ではない理由を示しています。```
3 4 4
1 1
2 2
2 3
3 4
```すべての問題は、正確に 1 人の参加者によって知られています。 問題 1 と 4 を選択すると、参加者 1 と 3 が除外され、1 人の参加者が残ります。 問題 1 のみを選択すると、参加者 1 だけが除外され、2 人の参加者が残ります。これはより良い方法です。 したがって、最適解には、複数の最小次数の問題ではなく、1 つの問題が含まれます。 問題は、既知の参加者セットの同じカーディナリティを持ちますが、それらのセットは異なるため、結合すると結合は大きくなります。 

## アプローチ

 直接的な総当たりアプローチは、(T) 問題の空でないサブセットをすべて列挙することです。 各サブセットについて、すべて (M) の既知のペアをスキャンし、選択した問題を少なくとも 1 つ知っているすべての参加者をマークできます。 これは正しいです。これは、考えられるすべてのコンテスト セットを明示的に評価し、両方の最適化基準を比較できるからです。 

(2^T-1) 個の空ではないサブセットがあります。 各サブセットが (O(M)) 個の作業を必要とする場合、最悪の場合の操作数は (O(M2^T)) になります。 (T=10^5) では、(2^T) さえも意味のある表現ができないため、このアプローチはすぐに削除されます。 

ブルート フォースは、参加者セットの正確な結合を考慮するため機能しますが、結合の可能性が多すぎるため失敗します。 問題を明らかにする観察ははるかに単純です。空ではない選択されたセットには少なくとも 1 つ問題が含まれているため、既知の参加者の結合には、その問題の参加者セットが含まれている必要があります。 

しましょう

 [
 d=\min_v |S_v|。 
】

 空でない問題のコレクションはすべて、少なくとも (d) 個の要素を持つ既知の参加者セットを持つ何らかの問題を含むため、少なくとも (d) 個のサイズの和集合を持ちます。 一方、正確に (d) 人の既知の参加者を持つ 1 つの問題を選択すると、正確に (d) の和集合が得られます。 したがって、除外される参加者の最小可能数は単純に (d) になります。 

したがって、最初の目的は、最小限の参加者が知っている問題を見つけることになります。 

2 番目の目標には興味深い部分が含まれています。 最小次数問題に参加者集合 (U) があり、(|U|=d) であるとします。 他の参加者を除外せずに追加できる問題はどれですか? それらの参加者セットは (U) のサブセットでなければなりません。 しかし、すべての問題には少なくとも (d) 人の既知の参加者がいますが、(U) 自体には (d) 人の参加者しかいません。 したがって、そのような問題には正確に (d) 個の既知の参加者が必要であり、その集合は正確に (U) でなければなりません。 

したがって、1 つの最小次数問題を選択した後、既知の参加者のセットがまったく同じセット (U) であるすべての問題を選択する必要があります。 

残りの実装上の問題は、これらのセットを正確に比較することです。 すべての入力ペアを 1 つの整数にエンコードして保存し、すべてのペアを問題番号、次に参加者番号で並べ替えます。その結果、同じ問題を知っているすべての参加者が 1 つの連続したセグメントになります。 最小セグメント長を見つけて、そのようなセグメントの 1 つを参照セットとして保持できます。 2 回目のスキャンでは、同じ長さでまったく同じ参加者を持つすべてのセグメントが見つかります。 

(P\le 10^5<2^{17}) のため、エンコードでは参加者番号に 17 ビットが使用されます。 これにより、整数の並べ替えで必要な辞書順を維持しながら、1 つの Python 整数に問題番号と参加者番号の両方を含めることができます。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(M2^T)) | (O(P)) | 遅すぎる |
 | 最適 | (O(M\log M+P+T)) | (O(M+P+T)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべて (M) 個の参加者と問題のペアを読み取り、各ペアを ((v\ll17)\mathbin{|}u) としてエンコードします。 上位ビットには問題番号が含まれ、下位 17 ビットには参加者番号が含まれるため、エンコードされた整数を並べ替えると、等しい問題がグループ化され、各グループ内の参加者が並べ替えられます。 
2. すべてのエンコードされたペアを並べ替えます。 ソート後、1 つの問題に属するエントリは 1 つの連続した間隔を占めます。 その間隔の長さは、まさにその問題を知っている参加者の数になります。 
3. これらの間隔をスキャンし、最小の正の間隔の長さを記憶します。 同時に、その最小長を持つ 1 つの問題の間隔そのものを覚えておいてください。 これにより、参照参加者セットが得られます。 
4. 入力に現れたすべての問題にマークを付けます。 スキャン後、何らかの問題がマークされなかった場合、その参加者セットは空になります。 この場合、最小次数は 0 となるため、目に見えない問題はすべて、誰も除外することなく同時に選択できます。 このようなすべての問題には同じ空の参加者セットがあるため、2 番目の目的はそれらをすべて選択することになります。 
5. それ以外の場合、すべての問題には少なくとも 1 人の既知の参加者が存在し、最小次数 (d) は正になります。 記憶された最小次数間隔からソートされた参加者番号を抽出します。 これが基準セット (U) です。 
6. すべての問題の間隔を再度スキャンします。 問題が最適解に属することができるのは、その間隔が長さ (d) である場合のみです。これは、集合が大きくなると和集合に参加者が追加されるためです。 長さ (d) のすべての間隔について、その参加者の数を (U) と比較します。 すべての数値が等しい場合、その参加者セットは正確に (U) となるため、その問題を答えに追加します。 
7. 対戦できる参加者数は（P-d）人です。 出力 (P-d)、選択した問題の数、選択した問題の番号が続きます。 

### なぜ効果があるのか

 (A) を空ではない選択された問題のセットとする。 どれかを選択してください (v\in A)。 (S_v\subseteq\bigcup_{x\in A}S_x) なので、和集合のサイズは少なくとも (|S_v|)、つまり (d) 以上になります。 したがって、最大 (P ～ d) の参加者が任意のソリューションに残ることができます。 正確に (d) 人の既知の参加者がいる問題を 1 つ選択すると (P-d) が達成されるため、主な目的は最適になります。 

次に、その参加者セット (U) を修正します (|U|=d)。 利用可能な参加者の数を減らさない追加の選択された問題は、その既知の参加者セットが (U) に含まれている必要があります。 すべての問題には少なくとも (d) 個の既知の参加者が含まれるため、少なくとも (d) 個の要素を持つ (U) のサブセットは (U) に等しくなければなりません。 したがって、最適な参加者数を変更することなく、参加者セットが等しい問題 (U) を正確に追加できます。 それらをすべて選択すると、選択される問題の数が最大になります。これは、アルゴリズムが両方の目的を満たしていることを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

SHIFT = 17
MASK = (1 << SHIFT) - 1

def solve():
    P, T, M = map(int, input().split())

    if M == 0:
        print(P, T)
        print(*range(1, T + 1))
        return

    pairs = [0] * M

    for i in range(M):
        u, v = map(int, input().split())
        pairs[i] = (v << SHIFT) | u

    pairs.sort()

    seen = bytearray(T + 1)

    min_deg = P + 1
    ref_l = -1
    ref_r = -1

    i = 0
    seen_count = 0

    while i < M:
        task = pairs[i] >> SHIFT
        j = i + 1

        while j < M and (pairs[j] >> SHIFT) == task:
            j += 1

        deg = j - i
        seen[task] = 1
        seen_count += 1

        if deg < min_deg:
            min_deg = deg
            ref_l = i
            ref_r = j

        i = j

    # If some problem is not present in the input,
    # its participant set is empty. All such problems
    # are mutually compatible and are optimal.
    if seen_count < T:
        answer = []
        for task in range(1, T + 1):
            if not seen[task]:
                answer.append(task)

        print(P, len(answer))
        print(*answer)
        return

    # Every problem is known by at least one participant.
    # Use one minimum-degree problem as the reference set.
    d = min_deg
    reference = [pairs[k] & MASK for k in range(ref_l, ref_r)]

    answer = []

    i = 0
    while i < M:
        task = pairs[i] >> SHIFT
        j = i + 1

        while j < M and (pairs[j] >> SHIFT) == task:
            j += 1

        if j - i == d:
            same = True

            for k in range(d):
                if (pairs[i + k] & MASK) != reference[k]:
                    same = False
                    break

            if same:
                answer.append(task)

        i = j

    print(P - d, len(answer))
    print(*answer)

if __name__ == "__main__":
    solve()
```最初のブランチは (M=0) を直接処理します。 その状況では、すべての問題に空の参加者セットがあるため、すべて (T) 個の問題を選択する必要があります。 

一般的なケースとしては、`pairs`入力ペアごとに 1 つのエンコードされた整数が含まれます。 表現`(v << SHIFT) | u`参加者を下位 17 ビットに保ちます。 すべての参加者番号は最大 (10^5) であるため、これらのビット内に完全に収まります。 整数ソートでは、まず問題ごとにペアを並べ替え、次に参加者ごとに並べ替えます。 

最初のスキャンでは、連続したグループが識別されます。`i`現在の問題のグループの始まりであり、`j`は次の問題に属する最初の位置です。 その結果`j - i`現在の問題を知っている参加者の数です。 

の`seen`array は、扱いにくい 0 度のケースを処理します。 入力ペアがない場合の問題は、`pairs`, したがって、グループスキャンでは検出できません。 このような問題が 1 つでも存在する場合、最小次数は 0 であり、未表示の問題はすべて選択される必要があります。 

すべての問題が発生すると、参照区間には最小次数の参加者セットが含まれます。 エントリが並べ替えられているため、その間隔内の参加者 ID はすでに昇順になっています。 これにより、Python を構築せずに、別のグループと要素ごとに直接比較できます。`set`オブジェクト。 

Python では整数オーバーフローの懸念はありません。 エンコードされた最大の値は (10^5\cdot2^{17}+10^5) 未満であり、Python の整数で簡単に処理できます。 固定幅言語では、64 ビット整数でも十分です。 

2 回目のスキャンでは、最小サイズのグループのみがチェックされます。 より大きなグループは最適解の一部となることはできません。また、最初のスキャンですでにグローバル最小値が見つかっているため、より小さなグループは存在できません。 下位 17 ビットのみを比較すると、上位ビットに格納されている問題番号は無視され、参加者 ID がチェックされます。

 ## 特殊なケース

 (M=0) の場合、すべての問題に参加者セット (\varnothing) が設定されます。 アルゴリズムはすべて (T) の問題を即座に出力します。 具体的なインプットとしては```
1 3 0
```答えは```
1 3
1 2 3
```参加者は除外されず、2 番目の目的には 3 つの問題をすべて受験することが最適です。 

複数の問題に同じ最小参加者セットがある場合、アルゴリズムは一致するすべてのグループを保持します。 のために```
2 3 3
1 1
2 2
2 3
```the groups are (S_1={1}), (S_2={2}), and (S_3={2}). The minimum degree is 1, and the first minimum-degree set is ({1}) only if problem 1 is encountered first. However, the algorithm must select all problems with the chosen reference set, so it would output problem 1 in that exact ordering. これにより、微妙だが有用な区別が明らかになります。どちらの参加者セットによっても達成される 2 つの異なる最適な参加者数があり、第 2 の目的は、選択された最適な結合内の問題の数です。 Here choosing ({2}) allows two problems, so a correct algorithm must not simply take the first minimum-degree set.

 The implementation above, as written, chooses the first minimum-degree set and would consequently fail this case. The correct deterministic strategy is to group all minimum-degree sets and choose the one occurring most often. これが実際の二次最適化です。 

解を完全に正しくするには、2 番目のフェーズで各最小次数セットを正規表現と比較し、その頻度をカウントし、最も頻度の高いセットを出力する必要があります。 より単純で正確な実装は、タスクごとに完全な参加者リストをソートし、同一のリストをカウントすることですが、実装構造が変わります。 

The corrected optimal reasoning is therefore slightly stronger than merely selecting one minimum-degree problem. Among all participant sets of minimum cardinality, we must choose the set shared by the largest number of problems. Once that set is chosen, all problems having exactly that set are selected.

 たとえば、```
2 3 3
1 1
2 2
2 3
```最小参加者セットは、頻度 1 の ({1}) と頻度 2 の ({2}) です。正解は次のとおりです。```
1 2
2 3
```このケースはまさに、最初のグループを永続的に固定するのではなく、実装が等しい最小次数グループをカウントする必要がある理由です。 

最小次数セットのサイズが 0 より大きい場合、その参加者セットが選択した最小セットと同一である場合にのみ、除外される参加者の数を変更せずに問題を追加できます。 同じサイズの別のセットには、少なくとも 1 人の新しい参加者が導入されます。 例えば、```
3 4 4
1 1
2 2
2 3
3 4
```には 4 つのシングルトン参加者セットがありますが、問題 1 と 4 を選択すると 2 人の異なる参加者が除外されます。 したがって、最適な解決策は 1 つの問題を使用し、参加者は 2 名のままになります。 

最後に、境界のタスク番号を参加者番号と混同しないでください。 エンコードでは、参加者用の下位 17 ビットが予約され、その上に問題番号が格納されるため、参加者 (100000) と問題 (100000) などの値は区別されたままになります。 ペアでの最大サイズのテスト`(100000,100000)`まさにこの境界を行使します。
