 ## 問題の理解

 (N) 個の頂点を持つ正多角形があり、選択した頂点自体を別の正多角形の頂点にする一方で、それらの頂点をできるだけ少なくしたいと考えています。 

(k) 個の頂点を選択するとします。 すべての元の頂点は同じ円上にあり、(2\pi/N) の角度で等間隔に配置されているため、(N/k) 番目の元の頂点をすべて取得できる場合、選択した頂点は正確に正角形 (k) を形成します。 それはまさに (k) が (N) を割るときに可能になります。 

したがって、問題は、少なくとも (3) である (N) の最小の約数を見つけることになります。 (N) が素数の場合、少なくとも (3) には適切な約数は存在しないため、答えは (N) そのものになります。 

(N) の値は (10^{12}) に達することがあります。 (N) までのすべての可能なポリゴン サイズをスキャンするアルゴリズムは、ほぼ (10^{12}) 回の反復を実行できますが、これは実用的なレベルをはるかに超えています。 考えられるすべての数値を調べるのではなく、(N) の約数構造を活用する必要があります。 

間違いが露呈しやすい小さなケースが 2 つあります。 (N=5) の場合、(5) は素数であり、その頂点間に三角形やその他の小さな正多角形が存在しないため、答えは (5) になります。 (N=8) の場合、2 番目の頂点ごとに正方形が形成されるため、答えは (8) ではなく (4) になります。 奇数の約数のみを検索する不注意な解決策では、(4) を見逃してしまいます。 もう 1 つの有用な例は (N=10) で、答えは (5) です。 約数 (2) は多角形を表すには小さすぎるため、最初に使用できる約数は (5) です。 

## アプローチ

 直接的なアプローチは、(3) から始めて、選択された頂点のすべての可能な数 (k) を試し、(k) が (N) を割るかどうかをテストすることです。 正則 (k) 角形は (N) の約数 (k) に対して正確に形成できるため、最初に成功した値が正確に答えになります。 最悪の場合、(N) が素数の場合、(3) から (N) までのすべての値をテストします。これは、(N-2) 個の割り算チェックです。 (N=10^{12}-11) の場合、これは基本的に 1 兆回の反復となるため、このアプローチは使用できません。 

重要な観察は、すべての合成数 (N) の約数が (\sqrt N) を超えないという標準的な約数の特性です。 使用可能な最小の約数 (d\ge3) が (\sqrt N) より大きいとします。 その場合、その補数 (N/d) は (\sqrt N) より小さくなります。 (d) は (3) 以上であるため、補数も (N) の約数であり、(3) 以上であれば、さらに小さな使用可能な答えになります。 (3) の下で可能な相補約数は (1) または (2) のみであり、これらの場合は、関連する係数 (d) が (N) または (N/2) であることを意味します。 どちらの状況でも、(\sqrt N) までのすべての約数をチェックしても、各候補約数の直接テストと組み合わせると、答えが得られます。 

実際、(3) から (\lfloor\sqrt N\rfloor) までのすべての整数 (d) を単純にテストできます。 最初に見つかった約数が答えです。 そのような約数が存在しない場合、最小の約数が (2) である可能性を除いて、(N) は素数になります。 ただし、(2)自体は答えにはならないので、使える約数を探し続ける必要があります。 すべての整数をループすることで、これを自然に処理できます。 (N=2p) のような偶数の素数の場合、ループは (p\le\sqrt N) と仮定して最終的に (p) に到達します。(p>\sqrt N) の場合、(N) は実際にはその唯一の適切な約数が (2) であると認識することによって処理されるため、答えは (p=N/2) になります。 したがって、最もクリーンな実装では、係数 (2) を明示的に処理し、奇数の約数を検索します。

最適な検索を定式化するもう少し明確な方法は、少なくとも (3) である (N) の最小の約数を見つけることです。 まず候補 (4) までの (2) の累乗を処理し、次に奇数の約数を検索します。 ただし、さらに単純な実装もあります。(d=3,4,5,\ldots) を (\sqrt N) までテストし、(N) を割り切れない場合は、係数 (2) から残りのケースを決定します。 以下の実装では、この直接定式化が使用されます。 

## アルゴリズムのチュートリアル

 1. (N) を読み取ります。 少なくとも (3) である、(N) の最小の約数を探します。 
2. (N) が (4) で割り切れる場合は、すぐに (4) を返します。 正方形は三角形に次ぐ最小の多角形であり、(4) で割り切れるということは、(N/4) 番目の頂点ごとに 1 つが形成されることを意味します。 
3. (d=3) から開始して、(d^2\le N) の間、すべての整数 (d) をテストします。 (d\mid N) の場合、(d) を返します。 昇順に検索すると、最初に見つかった約数が最小の答えであることが保証されます。 
4. (3) ～ (\sqrt N) の約数が存在しない場合は、残りの場合を区別します。 (N) が偶数の場合、(\sqrt N) より小さくできる唯一の適切な約数は (2) です。したがって、奇数の素数 (p) に対しては (N=2p) となり、使用可能な最小の約数は (p=N/2) になります。 (N) が奇数の場合、(\sqrt N) までの約数がないことは (N) が素数であることを意味するため、答えは (N) になります。 

検索が (\sqrt N) に到達するだけでよい理由は、約数が (d) と (N/d) のペアで存在するためです。 合成数の約数が (\sqrt N) より大きい場合、その対の約数は (\sqrt N) より小さくなります。 したがって、以下の除数 (\sqrt N) が欠けていると、残りの因数分解がどのようなものになるかを正確に知ることができます。 

### なぜ効果があるのか

 (k) を選択された頂点の数とする。 選択した頂点は、元の多角形の周りの位置が等間隔である場合に正(k)角形を形成します。 間隔は (N/k) 個の元のエッジである必要があるため、(N/k) は整数でなければなりません。 したがって、有効なポリゴン サイズは、正確に (N) の約数 (3) 以上になります。 

アルゴリズムは、これらの考えられる約数を (\sqrt N) まで昇順に調べます。 見つかった場合、それより小さい有効な除数はスキップされません。 何も見つからない場合、(\sqrt N) より小さいすべての適切な約数は (1) または (2) のいずれかになります。 奇数 (N) の場合、それは (N) が素数であることを意味します。 偶数 (N) の場合、適切な約数は (2) だけであることを意味するため、(N=2p)、および (p=N/2) が多角形を表すことができる最小の約数になります。 したがって、戻り値は常に頂点の有効な最小数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    if n % 4 == 0:
        print(4)
        return

    d = 3
    while d * d <= n:
        if n % d == 0:
            print(d)
            return
        d += 2

    if n % 2 == 0:
        print(n // 2)
    else:
        print(n)

solve()
```(4) による割り算の最初のチェックでは、可能な限り最小の偶数ポリゴン サイズが処理されます。 (4\mid N) の場合、(3\nmid N) であるため、(4) より小さい答えは存在し得ないため、(4) が直ちに最適になります。 

その後、ループは (3) から始まる奇数の候補のみをチェックします。 (4)以外の候補でも最小の答えにはなり得ません。 たとえば、(8\mid N) の場合、(4) がすでに返されています。 (N) が (4) より大きい偶数で割り切れる場合、(4) でも割り切れるため、そのケースはすでに処理されています。 

条件`d * d <= n`は (d\le\sqrt N) の整数形式です。 Python の整数には任意の精度があるため、(N=10^{12}) の場合でもオーバーフローの心配はありません。 

ループが終了すると、(3) と (\sqrt N) の間に (N) の奇数の約数はありません。 奇数 (N) の場合、これは (N) が素数であることを意味し、答えは (N) になります。 偶数 (N) の場合、小さい係数は係数 (2) のみであるため、(N=2p)、有効な最小の約数は (p=N/2) になります。 

すべての偶数候補がすでに特殊な (4) ケースでカバーされているため、ループは (2) ずつ増加します。 これにより、ロジックを変更せずに反復回数がおよそ半分になります。 

## 実用的な例

 (N=5) の場合、実行は短時間です。

(N=21) の場合、次のトレースが得られます。

 最初の候補 (3) はすでに (21) を分割しています。 7 つおきの頂点を選択すると、3 つの等間隔の頂点が得られるため、答えは (3) になります。 

有用な追加トレースは (N=10) です。 

| (N) | (d) | (d^2\le N) | (10\bmod d) | アクション |
 | --- | --- | --- | --- | --- |
 | 10 | 3 | はい | 1 | 続ける |

 ここで (2) は (10) を分割しますが、2 つの頂点は多角形を形成しません。 次の有効な約数は (5) で、最後の偶数分岐は正確にその値を回復します。

## テストケース```python
import sys
import io

def solve_value(n: int) -> int:
    if n % 4 == 0:
        return 4

    d = 3
    while d * d <= n:
        if n % d == 0:
            return d
        d += 2

    if n % 2 == 0:
        return n // 2

    return n

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        n = int(sys.stdin.readline())
        return str(solve_value(n))
    finally:
        sys.stdin = old_stdin

# Provided samples
assert run("5\n") == "5", "sample 1"
assert run("21\n") == "3", "sample 2"

# Minimum-size input
assert run("3\n") == "3", "minimum N"

# Smallest composite case
assert run("4\n") == "4", "square"

# Even number with no divisor 3 or 4
assert run("10\n") == "5", "2 * prime"

# Maximum-size boundary
assert run("1000000000000\n") == "4", "maximum N"

# Large odd prime
assert run("999999999989\n") == "999999999989", "large prime"

 ## 特殊なケース

 (N=3) の場合、ループは (d=3) から開始されますが、条件 (3^2\le3) はすでに false です。 (N) が奇数であるため、アルゴリズムは (N=3) を返します。 三角形はすでに最小の正多角形であるため、これは正しいです。 

(N=5) の場合、同じ推論で (5) が返されます。 すべての正多角形の頂点に三角形が含まれると想定する不注意な実装では、誤って (3) が返されますが、正五角形の 3 つの頂点は等間隔ではありません。 

(N=8) の場合、最初の (N\bmod4=0) チェックは (4) を返します。 2 つおきの頂点を取得して得られる 4 つの頂点は正方形を形成します。 奇数の約数のみをチェックするソリューションでは、(8) が答えであると誤って結論付ける可能性があります。 

(N=10) の場合、(4) は (N) を除算せず、ループは除数ではない (3) をチェックします。 (5^2>10) のため、ループは停止します。 (N) は偶数なので、残りの因数は (10/2=5) となり、これが正解です。 これは、(2) を答えの可能性として扱うというよくある間違いを捉えています。 

(N=21) の場合、最初の候補 (d=3) は (21) を除算するため、アルゴリズムはすぐに (3) を返します。 選択した 3 つの頂点は、(21/3=7) 個の元のエッジによって分離され、等しい角度ギャップが与えられます。 

最大入力 (N=10^{12}) の場合、数値は (4) で割り切れるため、アルゴリズムは除数ループに入らずにすぐに (4) を返します。 より一般的には、最大サイズの値が素数になるように選択された場合でも、ループは (10^6) までの奇数のみをテストする必要があり、これは依然として意図された複雑さの範囲内です。
