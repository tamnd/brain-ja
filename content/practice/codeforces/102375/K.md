 ## 問題の理解

 私たちは既知の単語の辞書を持っています。 すべてのクエリに対して、1 つの辞書エントリが秘密の単語 (S) として選択され、整数 (K) によって、2 番目のプレーヤーが別の文字 (S) が公開されるまでに何回推測が失敗するかが決まります。 

プレイヤーはいつでも (S) という接頭辞を知っています。 彼らは、その接頭辞を持つ、以前に使用されていなかった辞書の単語に名前を付けることができます。 秘密の単語自体も辞書に含まれており、同じスペルであっても辞書の項目は異なるため、出現するたびに個別にカウントする必要があります。 

ヴァレラはゲームをできるだけ長く続けたいと考えています。 クエリ ((w,K)) の場合、必要な答えは、プレーヤーが最終的に秘密の単語を推測した場合の成功した推測を含む、可能な最大の推測数です。 

すべての辞書単語の合計の長さは最大 (2\cdot10^5) であり、(2\cdot10^5) 個のクエリが存在する可能性があります。 これにより、すべてのクエリに対してディクショナリ全体に比例した作業を実行することが排除されます。 プレフィックス数を前処理し、その後クエリごとに秘密の単語全体をたどるソリューションでも、多くのクエリが長い単語を参照する場合、約 (2\cdot10^{10}) 個の演算に到達する可能性があります。 ソリューションでは、前処理を合計入力サイズに対して本質的に線形にし、各クエリを対数またはそれに近い値に保つ必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 まず、秘密の単語は最初の文字を持つ唯一の単語である可能性があります。 例えば、```
1
a
1
1 1
```答えがあります`1`。 間違った推測は存在しないため、プレイヤーはすぐに秘密の単語を指定します。 失敗した推測のみをカウントする数式は、誤ってゼロを返します。 

次に、辞書エントリの重複が問題になります。 考慮する```

aa
ab
ab
2
2 2
```答えは`3`。 (K=2) の場合、プレイヤーはファーストネームを指定できます。`aa`そしてもう一つの出来事は`ab`、その後、最初のプレイヤーが単語全体が次であることを明らかにします。`ab`。 辞書をセットとして扱うと、利用可能な推測が 1 つ失われ、間違った結果が生成されます。 

第三に、以前に名前を付けた単語は再利用できません。 例えば、```
4
abc
abd
abe
abf
2

```答えがあります`4`。 最初のラウンドでは、次の 2 つが`abd`、`abe`、`abf`名前を付けなければなりません。 接頭辞が次のようになると、間違った単語が 1 つだけ残ります。`ab`したがって、2 番目のラウンドは、間違った推測とその後に続く成功した推測で構成されます。`abc`。 すべての接頭語の下にある単語の数を個別にカウントすると、同じ単語が再度使用できると誤って想定されてしまいます。 

## アプローチ

 最も直接的なアプローチは、ゲームをシミュレートすることです。 各クエリについて、現在知られているプレフィックスに一致する辞書の単語をすべて検査し、適切な間違った単語を選択し、それらを考慮から削除し、(K) 個の推測の後の次の文字を明らかにして、続行することができます。 これは正しいです。唯一の戦略的な選択は、どの未使用の一致する単語を誤った推測として費やすかであるからです。 

すべてのプレフィックスですべて (N) 個の辞書単語をスキャンするリテラル実装では、1 つのクエリに対してコスト (O(N|S|)) がかかります。 指定された境界の下では、これは、多くのクエリと長い秘密語を含む構造内のすべてのクエリに対するおおよそ (2\cdot10^{15}) 個の基本チェックに達する可能性があるため、使用できません。 

自然な改善は、トライを構築し、各プレフィックスを通過する辞書エントリの数を保存することです。 この場合、クエリは秘密の単語のプレフィックスのみを検査できます。 これにより、1 つのクエリが (O(|S|)) に減りますが、(2\cdot10^5) クエリでは依然として (O(Q\cdot |S|)) の作業が必要になる可能性があり、これは大きすぎます。 

重要な観察は、個々の単語について考えるのをやめ、代わりに間違った辞書の単語すべてに期限を割り当てることです。 間違った単語 (T) の場合、(T) と秘密の単語 (S) の最長の共通プレフィックスの長さを (d) とします。 この単語はラウンド (1,\ldots,d) 中に推測できますが、(d) 番目の文字が明らかになると、その単語は有効な推測ではなくなります。 

ゲームを続行するには、すべてのラウンドでちょうど (K) 回の間違った推測が必要です。 したがって、問題はスケジュールの問題になります。各間違った単語は期限 (d) のあるジョブであり、各ラウンドには (K) 個のスロットがあります。 プレイヤーは期限が早い単語を最初に使用する必要があります。これらの単語はすぐに消えてしまうためです。 

(C_d) を、(S) との最も長い共通プレフィックスの長さが少なくとも (d) である間違った辞書エントリの数とする。 専門用語で言えば、これは単に (S) の最初の (d) 文字を持つ辞書エントリの数から秘密のエントリ自体を引いたものです。 

(r) ラウンドを完了したいとします。 (d) から (r) までの最後の (r-d+1) ラウンドを考えてみましょう。 そこに配置されるすべての推測は、期限が少なくとも (d) である単語を使用する必要があり、(K(r-d+1)) 個の必須推測が存在します。 したがって、必要なのは

 [
 C_d \ge K(r-d+1)
 】

 すべて (d\le r) ごとに。 

この条件でも十分です。 少なくとも (d) の期限を持つ単語のセットはネストされているため、通常の貪欲なスケジューリング引数が適用されます。つまり、期限が最小の利用可能な単語を常に使用します。 接尾辞の不等式は、まさにその貪欲なスケジュールに必要な容量条件です。 

不等式を整理すると、

 [
 r \le d-1+\left\lfloor\frac{C_d}{K}\right\rfloor。 
】

 したがって、完全なラウンドの最大数は次のようになります。 

[
 r=\min_d\left(d-1+\left\lfloor\frac{C_d}{K}\right\rfloor\right)。 
】

 最小値内の式は、特に便利な形式になっています。 

\左\lf床\frac{C_d+K(d-1)}{K}\右\r床。 
】

 したがって、固定された秘密の単語の場合、すべての深さ (d) がラインに寄与します。 

[
 f_d(x)=C_d+(d-1)x、
 】

 そしてクエリは、(x=K) におけるこれらの行の最小値を求めます。 これはまさに下凸包のトリック問題です。 辞書の単語ごとにハルを 1 回構築し、そのハルに対する二分探索で各クエリに答えます。 

(r) 回のラウンドが完了した後、(r) が秘密の長さより小さい場合、次のラウンドに (K) 個の間違った推測が含まれることはできません。 (W=N-1) を間違った辞書エントリの総数とします。 その時点でまだ使える間違った単語の数は

 [
 R=\min(C_{r+1}, W-rK)。 
】

 プレイヤーはそれらの (R) 単語に名前を付け、次に秘密の単語に名前を付けることに成功します。したがって、最終的な答えは次のようになります。 

[
 rK+R+1。 
】

 (r) が秘密の長さに等しい場合、すべてのラウンドが完了し、最初のプレーヤーが単語全体を明らかにするため、答えは単純に (rK) になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | リテラルシミュレーション | (O(QN | S | )) 最悪の場合 | (O(N)) | 遅すぎる |
 | トライプラスシミュレーション | (O(\sum | S | +Q | S | )) | (O(\sum | S | )) | 遅すぎる |
 | トライプラス凸包 | (O(L+Q\log L))、ここで (L) は合計の語長 | (O(L)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての辞書単語を含むトライを構築します。 各 try ノードには、通過する辞書エントリの数が格納されます。 等しい単語は個別に挿入されるため、単語の多重度は自動的に保持されます。 
2. すべての辞書単語 (S) について、トライ内のそのパスをたどります。 すべてのプレフィックス長 (d) について、

 [
 C_d=\text{カウント(長さ }d のプレフィックス)-1。 
】

 減算により、秘密の単語として選択された特定の辞書エントリが削除されます。 他の同一のエントリはカウントされたままになりますが、これはまさにゲームで必要なことです。 

1. すべての間違った単語を、(S) を含む最大の共通プレフィックス長が期限であるジョブとして解釈します。 期限 (d) を持つ単語は、最初の (d) ラウンドのいずれかで推測できます。 値 (C_d) は正確に、期限が少なくとも (d) であるジョブの数です。 
2. プレフィックス長 (d) ごとに、次の行を作成します。 

[
 y=C_d+(d-1)x。 
】

 クエリ値 (K) の場合、最小ライン値を (K) で割ると、完全なラウンドの最大数が求められます。 

[
 r=\min\left(|S|,\left\lfloor\frac{\min_d(C_d+K(d-1))}{K}\right\rfloor\right)。 
】

 凸包は最適化できるラインのみを保存するため、対数時間で最小値を見つけることができます。 

1. (r=|S|) の場合、ゲームはすべてのラウンドで生き残ります。 最終回で(K)が予想した結果、すべての文字が明らかになったので、答えは(rK)となります。 
2. それ以外の場合、次の既知のプレフィックスの長さは (r+1) になります。 そのプレフィックスの下には (C_{r+1}) 個の間違った辞書エントリがありますが、(rK) 個の以前の推測の一部はこの同じサブツリーから来たものである可能性があります。 使用可能な間違った単語の残りの最小可能数は次のとおりです。 

[
 R=\min(C_{r+1},N-1-rK)。 
】

 プレイヤーはそれらすべて (R) に名前を付けることができ、その後秘密の単語に名前を付ける必要があるため、答えは (rK+R+1) になります。 

1. 要求されたすべてのペア ((w,K)) に対してハル クエリを繰り返します。 単語の前処理は他の単語から独立しているため、重複するクエリのペアには追加の作業は必要ありません。 

なぜ効果があるのか

 中心的な不変条件は、すべての間違った単語は、その単語がまだ命名できる最後のラウンド、つまり秘密の単語との共通の最長プレフィックス長によってのみ特徴付けられるということです。 (r) ラウンドを完了するには、最後の (r-d+1) ラウンドには、少なくとも (d) の期限を持つ (K(r-d+1)) ワードが必要です。 不等式 (C_d\ge K(r-d+1)) は必要であり、適格なセットがネストされているため、常に最も早い締め切りの利用可能な単語を最初に使用する貪欲な戦略には十分です。 凸包は、これらすべての不等式を満たす最大の (r) を計算します。 十分な数のラウンドが完了すると、(R) の公式は使用可能な間違った単語が何個残るかを正確に数えます。その後、ゲームがまだ終了していない場合は、秘密の単語が必ず次の推測となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hull(values):
    hull = []

    for slope, intercept in enumerate(values):
        while len(hull) >= 2:
            m1, b1 = hull[-2]
            m2, b2 = hull[-1]
            m3, b3 = slope, intercept

            # l2 is redundant if the intersection of l1,l2
            # is not to the right of the intersection of l2,l3.
            if (b1 - b2) * (m3 - m2) <= (b2 - b3) * (m2 - m1):
                hull.pop()
            else:
                break

        hull.append((slope, intercept))

    return hull

def query_hull(hull, x):
    lo = 0
    hi = len(hull) - 1

    while lo < hi:
        mid = (lo + hi) // 2

        m1, b1 = hull[mid]
        m2, b2 = hull[mid + 1]

        if m1 * x + b1 <= m2 * x + b2:
            hi = mid
        else:
            lo = mid + 1

    m, b = hull[lo]
    return m * x + b

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    children = [{}]
    count = [0]

    # Build the trie and count how many dictionary entries
    # pass through every node.
    for word in words:
        node = 0
        for ch in word:
            nxt = children[node].get(ch)
            if nxt is None:
                nxt = len(children)
                children[node][ch] = nxt
                children.append({})
                count.append(0)

            node = nxt
            count[node] += 1

    hulls = [None] * n
    prefix_counts = [None] * n

    # For every possible secret word, prepare C_d and its
    # lower hull of lines C_d + (d-1) * x.
    for idx, word in enumerate(words):
        node = 0
        values = []

        for ch in word:
            node = children[node][ch]
            values.append(count[node] - 1)

        prefix_counts[idx] = values
        hulls[idx] = build_hull(values)

    q = int(input())
    total_wrong = n - 1
    out = []

    for _ in range(q):
        w, k = map(int, input().split())
        w -= 1

        values = prefix_counts[w]
        length = len(values)
        hull = hulls[w]

        minimum = query_hull(hull, k)
        rounds = minimum // k

        if rounds > length:
            rounds = length

        completed = rounds * k

        if rounds == length:
            out.append(str(completed))
            continue

        remaining = min(values[rounds], total_wrong - completed)
        answer = completed + remaining + 1
        out.append(str(answer))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```trie の構築はウォークスルーの最初の部分に続きます。 単語が出現するたびに、その完全なプレフィックス パス上のカウンタがインクリメントされるため、2 つの同一のスペルは 2 つの別個のエントリに寄与します。 

それぞれの言葉に対して、`values[d]`ストア (C_{d+1})。 単語自体は次のように 1 回だけ減算されます。`count[node] - 1`、同じスペルの他の辞書エントリはそのまま残ります。`build_hull`傾きが (0,1,2,\ldots) のラインを受け取ります。 外積比較では、浮動小数点の交差座標が回避されます。 すべての値は整数であり、おおよそ (K|S|) までの大きさになる可能性があるため、当然、整数演算も十分です。 Python の整数にはオーバーフローの問題はありません。`query_hull`2 つの隣接する船体のラインを比較します。 下部ハルにより、行の値が最小値付近で順序付けされるため、二分探索では (O(\log |S|)) で最適な行が見つかります。 

ハルによって返される式は次のとおりです。 

[
 M=\min_d(C_d+K(d-1))。 
】

 整数除算を使用してこれを (K) で割ると、完全なラウンドの最大数が得られます。 の`rounds > length`ガードは、最小の式が文字数を超える理論的なケースを処理します。 

最終的な計算では次を使用します。`values[rounds]`、 なぜなら`rounds`完全なラウンドは、次の既知のプレフィックスが長さを持っていることを意味します`rounds + 1`、ゼロから始まるインデックスに対応`rounds`。 の`+1`最終的な答えは、すべての文字が明らかになる前にゲームが停止したときの秘密の単語の推測の成功です。 

## 実用的な例

 ### サンプル 1

 辞書の最初の単語を考えてみましょう`asassin`。 秘密のパスに沿った関連する間違った単語の数は次のとおりです。 

[
 C_1=5、\qquad C_2=2、\qquad C_3=0。 
】

 後のプレフィックス数もゼロであるため、ハルの最小値を改善することはできません。 

(K=1) の場合、関連する 3 つの行は (5)、(2+x)、および (2x) です。 (x=1) での最小値は (2) であるため、2 つの完全なラウンドが可能です。 次のプレフィックスには間違った単語がないため、3 回目の試行で秘密の単語自体が推測されます。 

| プレフィックス長 (d) | (C_d) | 直線 (C_d+(d-1)K)、(K=1) |
 | --- | --- | --- |
 | 1 | 5 | 5 |
 | 2 | 2 | 3 |
 | 3 | 0 | 2 |

 したがって (r=2)、答えは (2\cdot1+0+1=3) となります。 

(K=2) の場合、ライン値は (5,4,4) です。 最小値は (4) で、(r=2) となります。 3 番目の接頭辞の下にも間違った単語は残っていないため、答えは (4+1=5) になります。 

(K=3) の場合、ライン値は (5,5,6) です。 最小値は (5) で、(r=1) となります。 最初のラウンドで 3 回推測した後、2 番目の接頭辞の下に使用可能な間違った単語が 2 つ残ります。 プレイヤーはそれら 2 つの名前を指定し、秘密の単語を推測します。 

| (K) | 船体の最小値 | ラウンドを完了する (r) | 残りの間違った推測 | 最終的な答え |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | 0 | 3 |
 | 2 | 4 | 2 | 0 | 5 |
 | 3 | 5 | 1 | 2 | 6 |

 このトレースは、以前に使用された単語がプレフィックスごとに個別にカウントされるのではなく、スケジュールされたジョブとして扱われなければならない理由を示しています。 (K=3) の場合、最初のラウンドでは、より深い接頭辞に属するいくつかの単語が消費されます。 

### サンプル 2

 辞書エントリ 2 を取り上げます。`ab`、合言葉として。 prefix の下には他に 2 つの辞書エントリがあります`a`:`aa`そして2回目の発生`ab`。 したがって、(C_1=2)。 完全なプレフィックスの下`ab`、その他の発生のみ`ab`残っているので(C_2=1)。 

(K=1) の場合、行の値は (2) および (2) になります。 2 つの完全なラウンドが可能です。 

| プレフィックス長 (d) | (C_d) | 直線 (C_d+(d-1)K)、(K=1) |
 | --- | --- | --- |
 | 1 | 2 | 2 |
 | 2 | 1 | 2 |

 プレイヤーのファーストネーム`aa`、その後、最初のプレイヤーが明らかにします`b`。 プレイヤーは次に相手の名前を指定します`ab`、最初のプレイヤーは単語全体が明らかになったのでゲームを終了します。 答えは`2`。 

(K=2) の場合、ライン値は (2) と (3) であるため、完全なラウンドは 1 つだけ可能です。 そのラウンドでの 2 つの推測の後、間違いはありませんでした`ab`エントリが残り、秘密の単語の推測に成功します。 

| (K) | 船体の最小値 | ラウンドを完了する (r) | 残りの間違った推測 | 最終的な答え |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | 0 | 2 |
 | 2 | 2 | 1 | 0 | 3 |

 2 番目のクエリは、重複するスペルが別の辞書エントリのままでなければならない理由を示しています。 2番目`ab`スペルが秘密の単語と同じであっても、これは正当な間違った推測です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(L+Q\log L)) | トライ構築とすべてのハル構築には (O(L)) がかかります。ここで (L) はすべてのワードの合計長です。 各クエリは 1 つのハル バイナリ検索を実行します。 |
 | スペース | (O(L)) | トライ、接頭辞カウント配列、凸包、および格納された単語には、合計 (O(L)) 個の情報が含まれます。 |

 ここでは (L\le2\cdot10^5) と (Q\le2\cdot10^5) です。 前処理は実際の入力サイズにおいて線形ですが、各クエリは要求された単語に属するハルのみに触れます。 最大の包はその単語の長さによって制限されるため、対数クエリ制限は小さいままです。 

## テストケース```python
import sys
import io

def build_hull(values):
    hull = []

    for slope, intercept in enumerate(values):
        while len(hull) >= 2:
            m1, b1 = hull[-2]
            m2, b2 = hull[-1]
            m3, b3 = slope, intercept

            if (b1 - b2) * (m3 - m2) <= (b2 - b3) * (m2 - m1):
                hull.pop()
            else:
                break

        hull.append((slope, intercept))

    return hull

def query_hull(hull, x):
    lo = 0
    hi = len(hull) - 1

    while lo < hi:
        mid = (lo + hi) // 2

        m1, b1 = hull[mid]
        m2, b2 = hull[mid + 1]

        if m1 * x + b1 <= m2 * x + b2:
            hi = mid
        else:
            lo = mid + 1

    m, b = hull[lo]
    return m * x + b

def solve_stream(stream):
    input = stream.readline

    n = int(input())
    words = [input().strip() for _ in range(n)]

    children = [{}]
    count = [0]

    for word in words:
        node = 0

        for ch in word:
            nxt = children[node].get(ch)

            if nxt is None:
                nxt = len(children)
                children[node][ch] = nxt
                children.append({})
                count.append(0)

            node = nxt
            count[node] += 1

    hulls = [None] * n
    prefix_counts = [None] * n

    for idx, word in enumerate(words):
        node = 0
        values = []

        for ch in word:
            node = children[node][ch]
            values.append(count[node] - 1)

        prefix_counts[idx] = values
        hulls[idx] = build_hull(values)

    q = int(input())
    total_wrong = n - 1
    answer = []

    for _ in range(q):
        w, k = map(int, input().split())
        w -= 1

        values = prefix_counts[w]
        length = len(values)

        rounds = query_hull(hulls[w], k) // k
        rounds = min(rounds, length)

        completed = rounds * k

        if rounds == length:
            answer.append(str(completed))
        else:
            remaining = min(values[rounds], total_wrong - completed)
            answer.append(str(completed + remaining + 1))

    return "\n".join(answer)

def run(inp: str) -> str:
    return solve_stream(io.StringIO(inp)).strip()
