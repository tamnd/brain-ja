 ## 解決策
 ## 問題の理解

 文字列として表された 2 つの T シャツのサイズを比較するように求められます。 各文字列は 3 つの文字のいずれかで終わります。S は小、M は中、L は大です。 さらに、S または L の前に、特小または特大を示す一連の X がある場合があります。 Medium には X がないため、M は固定です。 入力では複数のサイズのペアが指定され、各ペアについて、最初のサイズが 2 番目のサイズより小さいか、大きいか、または等しいかを出力する必要があります。 

重要なのは順序を理解することです。 小は中または大よりも小さく、大は中または小よりも大きくなります。 小さいサイズの場合、X が多いほどシャツは小さくなります (例: XXXS < XS)。 大きいサイズでは、X の数が多いほどサイズが大きくなります (例: XXXL > XL)。 中は常にすべての小型とすべての大型の間にあります。 

制約により、テスト ケースは最大 10,000 個まで存在でき、各サイズ文字列は最大 50 文字であることがわかります。 文字列文字に対するネストされたループを含む単純なアプローチでも、50 × 10,000 = 500,000 の操作が可能であり、1 秒の制限では許容できるため、機能する可能性があります。 ただし、さまざまな数の X と最後の文字を処理するには、慎重な文字列解析が必要です。 

極端なサイズや珍しい組み合わせを比較する場合、エッジケースが発生します。 たとえば、XXXXXS 対 M は返されます。`<`、長さに関係なく、小は中よりも小さいためです。 同様に、L 対 XXXL は返されるはずです。`<`XXXL はラージであり、L はシングル ラージであるため、XXXL > L です。単純な辞書編集上の文字列比較は、サイズが小さいにもかかわらず、文字列として "XXXXXS" > "M" であるため、ここでは失敗します。 

## アプローチ

 ブルートフォース手法では、各 T シャツのサイズを絶対ランクを表す整数としてエンコードし、これらの整数を比較します。 小さい場合は、X の数に応じて減少する負の数を割り当てることができます。 中程度の場合はゼロ。 大きい場合は、X の数に応じて増加する正の数。 これが機能するのは、すべてのサイズが線形順序に分類され、それらをエンコードすることで単純な数値比較が可能になるためです。 このアプローチは正しいですが、一度に 2 つの文字列のみを比較する必要がある場合は、不必要な簿記が発生します。 

最適なアプローチは、順序付けルールが単純で局所的であるという事実を利用します。つまり、最後の文字によってカテゴリ (S、M、L) が決まり、その前にある X の数によって S と L 内の相対的な順序付けが決まります。最初に最後の文字を確認できます。 それらが異なる場合、すぐに比較が行われます: S < M < L。最後の文字が等しい場合は、X の数を比較します。S の場合、X が多いほど小さいことを意味します。 L の場合、X が多いほど大きいことを意味します。 これには、文字列ごとに最大でも文字数をカウントする必要があり、文字列の長さは線形です。長さ ≤ 50 なので O(1) です。追加のデータ構造は必要なく、すべてのテスト ケースを効率的に処理できます。

 | ブルート フォース (ランク エンコーディング) | O(t * n) | お(1) | 受け入れられますが、少し複雑になります |
 | 最適 (文字ベースの比較) | O(t * n) | お(1) | 受け入れられ、よりシンプル |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、2 つの T シャツ サイズ文字列を読み取ります。`a`そして`b`。 
3. 各文字列の最後の文字を抽出して、そのタイプ (小、中、または大) を決定します。 
4. タイプが異なる場合は、S < M < L の順序で直接比較します。 印刷`<`もし`a`より小さく、`>`大きい場合は、等しい場合は続行します。 
5. 型が同じ場合は、各文字列内の X の数を数えます。 小さい場合は、X が多いほどサイズが小さいことを意味します。 大きい場合は、X の数が多いほどサイズが大きいことを意味します。 媒体には X がなく、常に別の媒体と同等です。 
6. 種類に応じてカウントを比較し、出力します。`<`、`>`、 または`=`必要に応じて。 

機能する理由: このアルゴリズムは 2 つのプロパティに依存しています。 まず、最後の文字はメイン カテゴリをエンコードしており、すでにすべてのサイズが部分的に順序付けされています。 次に、X の数によって、S または L カテゴリ内の順序が微調整されます。 これら 2 つのケースを明示的に処理することにより、アルゴリズムはすべての有効なサイズ文字列の正しい比較を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b = input().split()
    type_a, type_b = a[-1], b[-1]
    
    if type_a != type_b:
        if type_a == 'S':
            print('<')
        elif type_a == 'M':
            if type_b == 'S':
                print('>')
            else:
                print('<')
        else:  # type_a == 'L'
            print('>' if type_b != 'L' else '=')
    else:
        count_a, count_b = a.count('X'), b.count('X')
        if type_a == 'S':
            print('<' if count_a > count_b else '>' if count_a < count_b else '=')
        elif type_a == 'L':
            print('>' if count_a > count_b else '<' if count_a < count_b else '=')
        else:
            print('=')
```コードはまずテスト ケースの数を読み取り、それらをループします。 最後の文字はメインの型を決定するため、型が異なる場合に比較を省略できます。 型が一致する場合は、X を数え、それが S か L かに応じて比較を調整します。S については、X が多いほど小さくなるため、順序が逆になります。 Medium は単純な等価として扱われます。
