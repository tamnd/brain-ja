 ## 解決策
 ## 問題の理解

 指定されたシーケンスかどうかを確認するように求められます$b$何らかの元のシーケンスからネットワーク経由で送信された可能性があります$a$特定のエンコード手順による。 エンコードには順序が必要です$a$、連続するセグメントに分割し、セグメントごとにセグメントの長さを先頭または末尾に追加します。 送信されたシーケンス$b$セグメントの長さと元の値をインターリーブします。 

入力は複数のテスト ケースで構成され、それぞれがシーケンスを提供します。$b$。 出力は、元のシーケンスが存在するかどうかに応じて、単純な YES または NO です。$a$それは生成した可能性があります$b$説明されているエンコーディングの下で​​。 

制約は重要です。 各シーケンスには最大で次のものを含めることができます$2 \cdot 10^5$すべてのテスト ケースの合計は同じ値によって制限されます。 これにより、線形演算よりも悪いアルゴリズムが排除されます。$O(n \log n)$テストケースごとまたは二次式ごと$O(n^2)$合計で。 唯一実現可能なアプローチは、線形スキャンまたは単純な貪欲アルゴリズムです。 

明らかではないエッジ ケースには、長さが 1 のシーケンス、複数の繰り返し数字が表示されるシーケンス、セグメントの長さ自体が要素値と混同される可能性があるシーケンスが含まれます。 たとえば、次のようなシーケンス$b = [1, 1]$は有効で、長さ 1 の単一要素セグメントを表します。$b = [2, 1]$セグメント長 2 の後に値 1 が続くものとして解釈される可能性があり、有効な元のシーケンスと一致しない可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのパーティションを試行しようとします。$b$各セグメントの前後に長さが割り当てられたセグメントに分割されます。 サイズのシーケンスの場合$n$、指数関数的な数のパーティションと順列が存在します。 このアプローチはすべての組み合わせを試行するため、原理的には正しいですが、組み合わせ爆発のため計算的には実行不可能です。 数百または数千の長さのシーケンスの場合、これは妥当な制限時間をすぐに超えてしまいます。 

線形ソリューションを解くための重要な洞察は、数値がセグメント長として使用されると、同じ処理ウィンドウ内の後のセグメントの一部として再度使用することはできないことに気づくことです。 さらに、アルゴリズムはシーケンスの後ろから動作し、セグメントに番号を貪欲に割り当てることができます。 まだ配置されていない最大の要素を常に削除しようとすると、$a$それをその値のセグメントの最後の要素として解釈すると、そのようなセグメントを使用してシーケンス全体をカバーできるかどうかを確認することに問題を減らすことができます。 

これにより、問題はマルチセットまたは数値の周波数マップを使用したシミュレーションに帰着します。 残りの最大の数値を繰り返し削除し、それをセグメントの終わりとして扱い、セグメントの長さを減算して、負の数や欠落した数値がないことを確認します。 この貪欲なアプローチは、残りの最大の数値を常に選択する場合、セグメントの長さがその最大の要素に明確に関連付けられるため、機能します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 周波数マップで貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、シーケンスを読み取ります。$b$各数値の頻度をカウンターに保存します。 
2. 常に残っている最大の番号を選択するように、降順でソートされたリストまたはマルチセットを初期化します。 
3. 数字が残っているうちに最大の数字を選択します$x$残り。 長さが次のセグメントの最後の要素として扱います。$x$。 
4. 削除を試みる$x$セグメントに対応するマルチセットの要素。 これは、セグメント サイズが満たされるまで、残っている最大の要素を繰り返し削除することで実行できます。 
5. いずれかのステップで必要な数がマルチセット内にない場合、シーケンスは形成できません。 NO を出力し、次のテスト ケースに進みます。 
6. すべてのセグメントが正常に処理された後でマルチセットが空になった場合は、YES と出力します。 

機能する理由: 各ステップで、残りの最大数によって、それを最後の要素として含める必要がある最小セグメントが決まります。 貪欲な割り当てにより、考慮されない要素がなくなり、セグメントの長さが満たされることが保証されます。 このアルゴリズムは、セグメントの終わりとして使用されるすべての要素が、仮説上の元のシーケンス内の有効なセグメントに対応するという不変条件を維持します。$a$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        counter = Counter(b)
        heap = [-x for x in b]
        heapq.heapify(heap)
        possible = True
        
        while heap:
            x = -heapq.heappop(heap)
            if counter[x] == 0:
                continue
            counter[x] -= 1
            segment_sum = x
            segment = []
            while segment_sum > 0:
                if not heap:
                    possible = False
                    break
                y = -heapq.heappop(heap)
                if counter[y] == 0:
                    continue
                counter[y] -= 1
                segment_sum -= y
                segment.append(y)
                if segment_sum < 0:
                    possible = False
                    break
            if segment_sum != 0:
                possible = False
                break
        print("YES" if possible else "NO")

solve()
```このソリューションでは、まずテスト ケースの数を読み取ります。 テスト ケースごとに、シーケンスの否定された値を使用して最大ヒープを構築し、頻度のカウンターを維持します。 残りの最大の数値を貪欲に選択し、数値を削除してその長さのセグメントを形成しようとし、矛盾がないかチェックします。 マイナスのカウントや合計が残っていると、その可能性が失われます。
