 ## 解決策
 ## 問題の理解

 すべての人が頂点 1 から開始する、無向接続グラフが与えられています。各友人には、最終的に到達する必要がある目的地の頂点があります。 これらの友人の中で、最大でも 6 歳の一部のグループは、車を持っていないという意味で「特別」です。 他の人はみんな車を持っているかもしれません。 

車を持っている友人は、車を持っていない友人を何人でも迎えに行くことができますが、その条件は厳格です。車の所有者は頂点 1 から自分の目的地までの最短経路に沿って運転し、車を持っていない友人はすべて、互換性のある方法でその正確な最短経路ルート上に位置していなければなりません。 言い換えれば、自動車は 1 から目的地までの単一の最短ルートを定義し、すべての乗客はそのルート上で自動車が通過する頂点に沿って位置する必要があります。 

課題は、車を持たずに一人で歩かなければならない友人の数を最小限に抑えることです。 同様に、各車の所有者の最短経路が割り当てられたすべての乗客を「カバー」できるように、k 人の特別な友人のうち何人を車の所有者に割り当てることができるかを最大化したいと考えています。 

k が最大 6 であるため、問題の構造は緊密になります。これは、2^6 が 64 にすぎないため、特別なフレンドのサブセットに対する指数関数的な解法が実行可能であることを直ちに意味します。ただし、グラフ自体とフレンドの数 f は、テスト ケースごとに最大 10^4 と大きくなる可能性があるため、どのような解法でもグラフ情報を大幅に圧縮し、ペアごとの最短パスの再計算を回避する必要があります。 

車を持たない友人を最も近い車の所有者に貪欲に割り当てようとすると、素朴な失敗例が現れます。 この問題は、車を持たない 2 人の友人が個別に異なる車と互換性があるものの、最短経路の分岐により一緒にサービスを提供できない場合に問題が発生します。 たとえば、必要な 2 つの頂点が、特定の車の目的地までのすべての最短経路の異なる分岐上にある場合、貪欲な割り当てでは、両方が一緒に乗車できると誤って想定される可能性があります。 

もう 1 つの微妙な問題は、「1 から h_i への最短経路上にある」ということが、単純な距離の比較だけと同等であると仮定していることです。 2 つの頂点は独立して距離制約を満たす可能性がありますが、単一の最短パス ツリー ルート上に一緒に存在しないため、グループ化が無効になります。 

## アプローチ

 強引な視点は、k 人の特別な友人だけに焦点を当てることから始まります。 特別な友人ごとに、車を持っている友人に割り当てるようにします。 固定車の所有者の場合、特別な友人のどのサブセットを乗せることができるかを決定する必要があります。 これは、選択されたすべての特別な頂点が 1 からその車の目的地までの単一の最短経路上にあるかどうかによって決まります。 

関連するすべての自動車の目的地からの最短距離を事前に計算すると、標準条件を使用して、頂点がその目的地までの最短経路上にあるかどうかを確認できます。つまり、dist1[v] + dist[v][h] が dist1[h] に等しい場合に限り、頂点 v は 1 から h までの最短経路上にあります。 ただし、グラフが大きいため、すべてのペアについて dist[v][h] を計算することは不可能です。 

重要な観察は、k が非常に小さいため、視点を逆転できるということです。 大規模な状態空間で乗客のサブセットに対して各車両を個別にチェックするのではなく、潜在的な各車両の目的地に関する k 個の特別な頂点間のすべてのペア関係を事前計算します。 

すべての友人 (潜在的な車の所有者) について、目的地からすべての頂点までの最短距離を事前に計算します。 次に、特別な頂点ごとに、1 回の比較を使用して、その頂点が 1 からその目的地までの最短パス上にあるかどうかをテストできます。 これにより、問題が互換性マスクに変換されます。車の所有者ごとに、どの特別な友人を乗せることができるかを記述する k ビット マスクを計算します。

ここで、問題は、すべての特別な友人が少なくとも 1 つの選択されたマスクで覆われ、覆われていない要素が最小限になるように、車の所有者のサブセットを選択することになります。 This is a classic DP over subsets of size k.

 dp[mask] を、特別な友人のサブセット マスクを正確にカバーするために必要な車の所有者の最小数として定義します。 各車両はマスクを提供し、最大 2^k の状態にわたってサブセット DP を実行します。 

この強引なアイデアでは、マスクの前処理を行わずに車両ごとにサブセットを直接割り当てようとするため、グラフ チェックが繰り返されることになります。 これでは、およそ O(f * 2^k * (n + m)) となり、遅すぎます。 最適化されたバージョンでは、BFS によってグラフ作業が O(f * (n + m)) に削減され、選択内容が O(f * 2^k) に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パスを繰り返しチェックするサブセットごとのブルート フォース | O(f · 2^k · (n + m)) | O(n + m) | 遅すぎる |
 | BFS + bitmask DP over cars | O(f · (n + m) + f · 2^k) | O(n + m + 2^k) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、k 個の特別な友達を固定し、それらをインデックス 0 から k-1 として扱います。 

1. 頂点 1 から BFS を実行して、すべての頂点の dist1[v] を計算します。 これにより、開始点からすべてのノードまでの最短距離が得られます。 
2. 入力リスト内の各友人 i について、h_i からすべての頂点までの最短距離が必要です。 すべての f に対してこれを個別に実行して完全な配列を保存する代わりに、必要に応じて BFS を使用して各フレンドを処理します。 
3. 各友人 i に対して、k 個の特別な友人に対するビットマスクを決定します。 頂点 x_j に位置する各特別な友人 p_j について、次のことを検証することによって、x_j が 1 から h_i への最短経路上にあるかどうかを確認します。 

dist1[x_j] + dist_i[x_j] == dist1[h_i].

 If true, we set bit j in the mask of friend i.
 4. 私たちが気にするのは、車を持っている友人のマスクだけです。 車を持たない友人の場合、他人に奉仕することができないため、その貢献は無関係です。 
5. 次に、最小数のマスクを使用してすべての k ビットをカバーするサブセット DP を解決します。 dp[0] = 0 およびその他すべての状態を無限大として初期化します。 
6. 車の所有者マスク m ごとに、逆のサブセット順序で dp を更新します。すべての状態 s に対して、dp[s | を設定します。 m] = min(dp[s | m], dp[s] + 1).
 7. 答えは dp[(1 << k) - 1] で、車を持たない友人全員を完全にカバーしていることを表します。 

これが機能する主な構造的理由は、すべての車が k 個の特別な頂点にわたる単一の固定カバレッジ パターンに対応しているためです。 これらのパターンが分かると、グラフは消え、問題は最大でも 6 のサイズのユニバースに対する純粋なセットカバーの最適化になります。 

## なぜ機能するのか

 最短パス構造により、距離加法性を使用して目的地までの有効なルート上の頂点のメンバーシップを独立してテストできることが保証されます。 これにより、各車両が利用可能な乗客の決定的なサブセットに変換されます。 k が小さいため、特別な友人間のすべての対話はサブセット マスクによって完全にキャプチャされ、DP は対話パターンを見逃さずにこれらの独立したカバーを組み合わせるあらゆる方法を探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, g, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        v = q.popleft()
        for to in g[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        f = int(input())
        h = list(map(int, input().split()))
        k = int(input())
        p = list(map(int, input().split()))
        special_idx = [x - 1 for x in p]
        special_vertices = [h[i] for i in special_idx]

        dist1 = bfs(1, g, n)

        masks = []

        for i in range(f):
            dist_i = bfs(h[i], g, n)
            mask = 0
            for j in range(k):
                v = special_vertices[j]
                if dist1[v] + dist_i[v] == dist1[h[i]]:
                    mask |= (1 << j)
            masks.append(mask)

        dp = [10**9] * (1 << k)
        dp[0] = 0

        for mask in masks:
            if mask == 0:
                continue
            for s in range((1 << k) - 1, -1, -1):
                if dp[s] == 10**9:
                    continue
                ns = s | mask
                if dp[ns] > dp[s] + 1:
                    dp[ns] = dp[s] + 1

        print(dp[(1 << k) - 1])

if __name__ == "__main__":
    solve()
```すべての最短パスの有効性チェックは dist1 に依存するため、頂点 1 からの BFS はテスト ケースごとに 1 回計算されます。 各フレンドは宛先から別の BFS をトリガーしてカバレッジ マスクを構築します。合計 f と n が全体で 10^4 に制限されるため、これは許容されます。 

DP ループは 2^k 個の状態を反復し、k は最大 6 であるため、これは定数因数の作業です。 唯一の微妙な実装の詳細は、単一の遷移ステップでマスクが複数回再利用されることを避けるために、DP 状態を逆方向に反復することです。 

## 実用的な例

 k = 3 人の特別な友達が頂点 A、B、C に対応する小さな概念的なケースを考えてみましょう。 

### 例 1

 3 人の車の所有者がマスクを生産しているとします。 

| 車 | マスク |
 | --- | --- |
 | 1 | 110 |
 | 2 | 011 |

 dp[000] = 0 に初期化します。 

車 1 を処理した後、dp は 110 をカバーするように更新されます。車 2 を処理した後、トランジションを結合すると、2 台の車を使用して 111 のカバレッジが得られます。 

これは、マスクを組み合わせることがなぜ必要なのかを示しています。1 台の車ですべてをカバーできるわけではありませんが、それらの車を組み合わせることですべてをカバーできるのです。 

### 例 2

 すべての車のマスクが同一である場合、たとえばすべて 100 である場合、複数の車を冗長的に使用しない限り、dp は完全なカバレッジに達することはできません。これは、重複が役に立たず、DP が不必要な選択を正しく回避することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m + f・(n + m)) + f・2^k) | 1 からの BFS に友人ごとの BFS、さらに最大 64 州にわたるサブセット DP |
 | スペース | O(n + m + 2^k) | 隣接リスト、距離配列、DP テーブル |

 この制約により、すべてのテスト ケースにわたる n と m の合計が最大 10^4 であることが保証されるため、BFS の繰り返しは引き続き実行可能です。 指数部分は k ≤ 6 によって制限され、サブセット DP は無視できます。

 ## 特殊なケース

 重要なエッジ ケースは、複数のフレンドが同じ宛先頂点を共有する場合です。 BFS ベースのマスク構造では、当然のことながら同一のマスクが割り当てられ、DP はそれらを交換可能として扱い、過剰カウントを回避します。 

もう 1 つのエッジ ケースは、自動車の最短経路に特別な頂点が含まれているものの、別の特別な頂点と一貫性がない場合です。 距離の等価性チェックは、互換性のないグループ化を正しく拒否し、マスクがカバレッジを誇張しないようにします。 

最後に、特別な友人がどの車でもカバーできない場合は、状態遷移がゼロの場合を除いて dp は無限のままとなり、それらの友人は歩かなければならないことが正しく得られます。
