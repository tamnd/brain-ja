 ## 問題の理解

 私たちに与えられた一行は、$n$串は左から右に並べられています。 各スキュワーには 2 値の状態があります。つまり、まだ初期状態にあるか、反転されているかのいずれかです。 

位置を選択するだけで単一の操作が実行されます$i$。 その操作は串をひっくり返します$i$距離内のすべての串もひっくり返します$k$それらの立場が存在する限り、そこから。 したがって、1 つの操作は、次の点を中心とする連続セグメントに影響を与えます。$i$、具体的には以下のすべてのインデックス$i-k$に$i+k$。 

複数の操作の効果はパリティとともに累積されます。串が奇数回ひっくり返されるとひっくり返されてしまい、偶数回ひっくり返されると元の状態に戻ります。 目標は、最終的な意味ですべての串が少なくとも 1 回裏返されることを保証することです。つまり、各位置を少なくとも 1 つの選択された操作でカバーする必要があります。 

出力には、最小限の操作数だけでなく、これらの反転を実行した正確な位置も含まれます。 

制約$n \le 1000$そして$k \le 1000$すぐに提案する$O(n^2)$あるいは$O(nk)$操作とチェックの最大数が少ないため、このアプローチで十分です。 これは直線上の古典的な貪欲なカバーリング問題であるため、最適解は線形であることが期待されます。 

微妙な点が生じるのは、$k = 0$。 その場合、各操作は 1 つの串にのみ影響します。つまり、すべての串を個別に選択する必要があります。 貪欲な間隔ロジックでは、このケースを明示的に処理する必要があります。 

もう 1 つのエッジケースは次のような場合です$2k + 1 \ge n$。 次に、適切に選択された中心での 1 回の操作で配列全体がカバーされるため、答えは 1 回の移動に集約されます。 

単純な間違いは、反転オーバーラップを動的に回避または追跡する必要があると考えることです。 これはフリップのシミュレーションとカバーされていないポジションの再計算につながりますが、これは不必要であり、不正確なパリティ推論の危険性があります。 この問題では、最終状態のパリティを明示的に管理する必要はなく、完全なカバレッジを確保するだけで済みます。 

## アプローチ

 この強引なアイデアは、考えられるすべての操作シーケンスをシミュレートし、カバレッジを追跡することです。 各ステップで、次のフリップとして考えられるすべての位置を試し、結果としてカバーされる範囲をシミュレートし、すべての位置がカバーされるまで再帰的に実行できます。 各状態が最大で分岐するため、これは急速に指数関数的になります。$n$最悪の場合、カバレッジによる枝刈りさえも保存されません。 

重要な観察は、各操作が固定長の連続した間隔をカバーすることです。$2k+1$。 問題をセグメントをカバーするものとして再解釈すると、$[1, n]$間隔の数を最小限にすると、構造は純粋に貪欲になります。 カバレッジを除いて、間隔間に依存関係はありません。 最良の戦略は、常に、その点から可能な限り右に広がる間隔を使用して、カバーされていない左端の位置をカバーすることです。これは、操作を最適に中心に置くことによって実現されます。 

したがって、選択肢を検討する代わりに、繰り返し「ジャンプ」します。$2k+1$現在カバーされていないポイントをカバーしながら、各中心をできるだけ左に配置します。

 ## アルゴリズムのチュートリアル

 1. 左端の串の位置 1 から開始します。これは、最初にカバーする必要がある位置です。 

これを最初の未発見のポイントとして扱います。 
2. もし$k = 0$、1 から 1 までのすべての位置を出力します。$n$。 

これが必要なのは、各操作で 1 つの串を反転するだけであり、一度に複数の位置をカバーする方法がないためです。 
3. それ以外の場合は、現在の左端のカバーされていない位置について$l$、位置にオペレーションを配置します$l + k$。 

この選択は、右側のカバー範囲を最大化しながらカバーできるため、最適です。$l$、カバレッジを作成する$[l, l + 2k]$。 
4. オペレーションを配置した後、次のカバーされていない位置を次のように更新します。$l + 2k + 1$。 

これまでのすべてが続くため、$l + 2k$現在の操作でカバーされています。 
5. まで繰り返します。$l > n$。 

その時点で、すべてのポジションがカバーされます。 

### なぜ効果があるのか

 このアルゴリズムは、すべての位置が厳密に以下であるという不変条件を維持します。$l$すでにカバーされています。 各ステップで、対象となる操作を選択します。$l$可能な限り右端までカバー範囲を拡大します。 をカバーする代替選択肢$l$中心を中に配置する必要があります$[l, l+2k]$、そしてそれらの選択肢のいずれも、範囲を超えて拡張することはできません$l+2k$。 したがって、選択すると、$l+k$有効なソリューションと比較して操作の数が増加することはなく、貪欲な進行によりセグメント全体の最小サイズのカバーが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    if k == 0:
        print(n)
        print(*range(1, n + 1))
        return

    res = []
    i = 1

    while i <= n:
        pos = i + k
        if pos > n:
            pos = n
        res.append(pos)
        i += 2 * k + 1

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```実装は貪欲構造に直接従います。 特別な場合$k = 0$一般式は誤ってステップバイしようとするため、最初に処理されます。$1$冗長センターを配置したままです。 

変数`i`は、左端のカバーされていない位置を表します。 それぞれが選んだ`pos`はそのセグメントの最適な中心です。 各選択の後、正確にジャンプします$2k + 1$これは操作の全カバレッジ幅であるためです。 

クランピング`pos`に`n`すべての定式化を正確にするために厳密に必要というわけではありませんが、有効な範囲外の位置を参照しないことが保証されます。$l + k > n$。

 ## 特殊なケース

 いつ$k = 0$、各操作は 1 つの位置にのみ影響します。 このアルゴリズムは、貪欲な間隔ロジックを明示的にバイパスし、すべてのインデックスを直接出力することで、位置をスキップする誤ったステップを回避します。 

いつ$2k + 1 \ge n$、最初に選ばれたセンター$l + k$配列の末尾に達するか、それを超えます。 この場合、最初の操作はすでにすべての位置をカバーしており、ループは 1 回の反復の直後に終了します。 

いつ$n = 1$、ループは 1 回実行され、位置 1 を選択します。これは、条件に関係なく完全なカバレッジを自明に満たします。$k$。
