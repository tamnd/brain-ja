 ## 解決策
 ## 問題の理解

 正の整数の配列から始めます。 すべての要素について、最大でそれを減らすことができます`k`、値は正のままである必要があります。 これらの減少をすべての位置で個別に実行した後、結果として得られる配列の最大公約数をできるだけ大きくする必要があります。 

このタスクを別の言い方で表現すると、次のようになります。最大の整数を見つける`g`すべての元の値が`a[i]`の正の倍数に下方調整できます。`g`、最大でそれを変更しながら`k`。 

固定候補 gcd の場合`g`, 質問は非常に具体的になります。 すべての数字ができる`a[i]`の倍数に達する`g`間隔の中で`[a[i] - k, a[i]]`? 「はい」の場合、`g`達成可能です。 1 つの要素でもそのような倍数に到達できない場合は、`g`不可能です。 

制約があるため、私たちは複雑さについて注意深く考える必要があります。 配列の長さは最大で`3 * 10^5`、値は次のようになります。`10^6`。 すべてのペアを比較したり、すべての要素に対してすべての約数を直接テストしたりするアルゴリズムは、非常に遅すぎます。 たとえ`O(n * maxA)`アプローチはおおよそ届くだろう`3 * 10^11`最悪の場合の運用。 値の範囲は`10^6`、意図したソリューションは、配列自体を大量に反復するのではなく、値ドメインにわたって数論的構造をほぼ確実に利用します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

仮定する`k = 0`。```
3 0
6 10 14
```答えは`2`、何も変えることができないからです。 すべての数値が常に近くの倍数に移動できると想定する不用意な実装は、より大きな gcd 値を誤って受け入れる可能性があります。 

もう 1 つの微妙なケースは、値が候補 gcd よりも既に小さい場合に発生します。```
2 3
2 100
```試しています`g = 5`最初の数値は次の正の倍数になることができないため、すぐに失敗します。`5`。 最も近い下限倍数は、`0`ただし、値は正のままでなければなりません。 

間隔も重要です。 考慮する：```
2 2
7 13
```のために`g = 5`、最初の数字は次のようになります。`5`、ただし 2 番目の数字は次の値にはなりません。`10`なぜなら、それは によって減少する必要があるからです`3`。 正しい答えは、`1`。 チェックだけを行う間違った実装`a[i] % g <= k`到達可能な複数のロジックを正確に処理しないと、無効なケースを黙って受け入れることができます。 

最も重要な観察は、数値に関して次のことです。`x`、の倍数`g`に存在します`[x-k, x]`まさに次のとき:```
floor(x / g) > floor((x-k-1) / g)
```この間隔の解釈が効率的なソリューションの中核です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 可能なすべての gcd を試します`g`から`1`まで`max(a)`、各配列要素について、次の倍数かどうかを確認します。`g`中にある`[a[i]-k, a[i]]`。 

数字の場合`x`、到達可能な最大の倍数`g`は：```
(x // g) * g
```この倍数が正で、少なくとも`x-k`、 それから`x`GCD に貢献できる`g`。 

結果として得られる値は最終的な gcd の倍数でなければならないため、このロジックは正しいです。 すべての要素が独立して次の倍数に到達できる場合、`g`とすると、gcd が次の値で割り切れる配列全体を構築できます。`g`。 

問題は実行時間です。 まであります`10^6`候補 gcd 値および最大`3 * 10^5`配列要素。 直接実装すると、おおよそのパフォーマンスが得られます`3 * 10^11`チェックしますが、これは完全に不可能です。 

重要な洞察は、実際にはすべての gcd 候補についてすべての配列要素を検査する必要はないということです。 重要なのは、値がどこで発生するかではなく、どの値が存在するかです。 すべての値が最大であるため、`10^6`を使用すると、値ドメイン上に周波数配列を構築し、範囲クエリに効率的に答えることができます。 

候補 gcd の場合`g`、連続する倍数間のすべての間隔を考慮します。```
[t*g, (t+1)*g - 1]
```このような間隔内のすべての数値は、倍数までしか移動できません。`t*g`。 その調整は、数値が最大でも次の場合にのみ可能です。`k`より大きい`t*g`。 

したがって、間隔内の有効な数値は次のとおりです。```
[t*g, t*g + k]
```それより大きい数値はすべて gcd で失敗します`g`。 

これにより、問題は値軸上の間隔範囲に変換されます。 周波数に対するプレフィックスの合計を使用すると、各ブロックの無効な領域内にある数値の数をすぐに数えることができます。 無効な数値が存在する場合、gcd 候補は失敗します。 

全体の複雑さは調和的になります。```
maxA/1 + maxA/2 + maxA/3 + ...
```これはおよそ`maxA * log(maxA)`そして簡単に十分な速さで`10^6`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n * maxA)`|`O(1)`| 遅すぎる |
 | 最適 |`O(maxA log maxA)`|`O(maxA)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、計算します。`MAX = max(a)`。 
2. 周波数配列を構築する`freq`どこ`freq[x]`何倍の値を保存するか`x`が表示されます。 
3. 周波数にわたるプレフィックス合計配列を構築します。 

これにより、任意の値の範囲内に配列要素の数を数えることができます。`[L, R]`一定時間内に。 
4. 考えられるすべての gcd 候補を反復処理します。`g`から`MAX`まで`1`。 

最初の有効な gcd が自動的に最大の答えとなるため、下方向に反復します。 
5. 複数のブロックごとに`[m, m+g-1]`、どの番号が無効であるかを判断します。 

からの数字`m`に`m+k`まで減少する可能性があります`m`。 

からの数字`m+k+1`に`m+g-1`の倍数には到達できません`g`。 
6. プレフィックス合計を使用して、各無効領域内にある配列値の数をカウントします。 

そこに値が 1 つでもある場合、gcd`g`不可能です。 
7. すべてのブロックに無効な数値が含まれていない場合は、次のように出力します。`g`そして終了します。 

### なぜ効果があるのか

 固定 gcd の場合`g`、すべての数値は次の倍数でなければなりません。`g`最大で減少した後`k`。 

間隔の中で`[m, m+g-1]`、数値以下の到達可能な倍数は次のとおりです。`m`。 値`x`このブロックで到達できるのは`m`まさに次のとき:```
x - m <= k
```したがって、有効な領域は次のとおりです`[m, m+k]`、それより上のすべては無効です。 

このアルゴリズムは、値ドメイン全体にわたってそのような無効な領域をすべてチェックします。 配列要素が無効な間隔に該当しない場合、すべての数値が次の倍数に達する可能性があります。`g`、 それで`g`達成可能です。 値が無効な間隔に該当する場合、その要素には法的な調整が存在しないため、`g`不可能。 

gcd の候補を最大から最小の順にテストするため、最初の有効な候補が最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    MAX = max(a)

    freq = [0] * (MAX + 1)

    for x in a:
        freq[x] += 1

    pref = [0] * (MAX + 1)
    pref[0] = freq[0]

    for i in range(1, MAX + 1):
        pref[i] = pref[i - 1] + freq[i]

    def range_count(l, r):
        if l > r or l > MAX:
            return 0

        r = min(r, MAX)

        if l == 0:
            return pref[r]

        return pref[r] - pref[l - 1]

    for g in range(MAX, 0, -1):
        ok = True

        m = 0

        while m <= MAX:
            bad_l = m + k + 1
            bad_r = m + g - 1

            if range_count(bad_l, bad_r) > 0:
                ok = False
                break

            m += g

        if ok:
            print(g)
            return

solve()
```実装は数学的構造に直接に従います。 

周波数配列は、入力全体を値カウントに圧縮します。 すべての数値が最大なので、`10^6`、値ドメインの反復処理は十分効率的です。 

プレフィックス合計配列が主な最適化です。 これがないと、無効な間隔に要素が含まれているかどうかを確認するには、毎回間隔全体をスキャンする必要があります。 プレフィックス合計により、それが定数時間に短縮されます。 

ループオーバー`g`最大から最小の順に実行されるため、有効な gcd が見つかったらすぐに停止できます。 

内側のループは次のサイズのブロックを処理します。`g`。 で始まるブロックの場合`m`、無効な領域は次のとおりです。```
[m + k + 1, m + g - 1]
```そこにある値は、最も近い下限の倍数を大きく上回っています。 

微妙な詳細の 1 つは、間隔をクリップすることです。`MAX`。 一部の間隔は配列の最大値を超えており、プレフィックス配列の外側でクエリを実行するとエラーが発生します。 

もう 1 つの重要な詳細は、取り扱いです。`m = 0`。 ブロック`[0, g-1]`より小さい数値を表します`g`。 結果の値は正の値を維持する必要があるため、`(k, g-1]`まで減らす必要があるため、無効です。`0`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(MAX log MAX)`| すべての gcd 候補にわたる高調波系列 |
 | スペース |`O(MAX)`| 周波数とプレフィックス配列 |

 ここ`MAX`配列の最大値です。`10^6`。 

高調波の複雑さは、複数の反復処理から生じます。```
MAX/1 + MAX/2 + MAX/3 + ...
```次のように動作します`MAX log MAX`。 

これは簡単に制限内に収まります`MAX = 10^6`。

 ## 特殊なケース

 変更が許可されない場合を考えてみましょう。```
3 0
6 10 14
```アルゴリズムは gcd 候補を下方にチェックします。 のために`g = 3`、ブロック`[9,11]`無効な間隔があります`[10,11]`、および値`10`そこに存在するので、`3`失敗します。 のために`g = 2`、すべての数値はすでに次の倍数の上にあります。`2`したがって、無効な間隔はすべて空になります。 アルゴリズムは正しく返します`2`。 

次に、候補 gcd よりも小さい値を検討します。```
2 3
2 100
```試しています`g = 5`、最初のブロックは`[0,4]`。 有効な数字は次のとおりです`[0,3]`。 価値`2`は概念的にのみゼロになる可能性があるため問題ありませんが、正の倍数が重要です。 後のブロックは最終的に失敗します。`100`距離内で正しく位置合わせできません`3`。 アルゴリズムは、から始まるブロックを通じてこれらの小さな値の領域を自然に処理します。`0`。 

最後に、古典的なオフバイワントラップを調べてみましょう。```
2 2
7 13
```のために`g = 5`、ブロック`[10,14]`有効な番号があります`[10,12]`および無効な番号`[13,14]`。 以来`13`無効な領域にある場合、アルゴリズムは拒否します`5`。 

これはまさに正しいです。`13`の中へ`10`を減らす必要があります`3`を超える`k = 2`。
