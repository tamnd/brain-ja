 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$小文字のグリッド。 有効な文字列は、常に次から開始して、左上のセルから右または下にのみ移動して到達可能なセルまで歩くことによって形成されます。$(1,1)$。 移動するたびに新しいセルの文字が追加されるため、有効な各文字列はグリッド内の 1 つの単調パスに正確に対応します。 

このような道筋を段階的に構築していくことでゲームを進めていきます。 最初の動きは強制されます: のみ$(1,1)$有効なプレフィックスとして存在します。 その後、各プレーヤーは現在のパスを右または下に 1 ステップずつ拡張しますが、これは結果のプレフィックスがまだ有効なパスである場合に限ります。 まさにその後$2n-1$移動すると、左上から右下までの完全なパスが形成されます。 

フルパスが決まったら、その数を数えます。`'a'`そして`'b'`含まれる文字。 勝者は最終的な差のみに依存します: 詳細`'a'`つまり、最初のプレイヤーが勝ち、さらに`'b'`は 2 番目のプレイヤーが勝つことを意味し、平等は引き分けを意味します。 どちらのプレイヤーも最適です。 

重要な構造的観察は、一連の動きは自由なストリングゲームではないということです。 単調なパスを巡る制約のあるゲームで、手数は固定されています。 以来$n \le 20$、グリッドは十分に小さいため、位置またはフロンティアにわたる完全な状態空間の探索は妥当ですが、パスの数が指数関数的に増加するものは妥当ではありません。 

単純なアプローチでは、有効なパスをすべて列挙しようとします。 で$20 \times 20$グリッド、単調パスの数は$\binom{38}{19}$、すでに存在しています$10^{11}$, したがって、直接列挙することは不可能です。 

より微妙な失敗例は、貪欲な推論から生じます。 たとえば、各ステップで現在のプレーヤーに利益をもたらす文字を選択することは、局所的には失敗します。これは、将来の強制移動がグリッド構造に大きく依存するためです。 この決定はローカルなものではありません。移動によって到達可能なフロンティアが移動し、後で利用できる文字が変わる可能性があります。 

本当の課題は、どちらのプレイヤーもどのセルが最終パスの一部になるかを効果的に制御しているものの、選択の順序が単調性によって制限されていることです。 

## アプローチ

 この強引なアイデアは、ゲームをすべての有効なプレフィックスに対する完全なミニマックスとして扱うことです。 各状態は現在位置によって定義されます$(r,c)$そして誰の番だ。 各州から分岐して、$(r+1,c)$または$(r,c+1)$、累積カウント`'a'`そして`'b'`到着するまでの途中$(n,n)$。 これはゲームを正しくシミュレートしますが、状態の数は単調パスの数に比例し、これは指数関数的です。$n$。 メモ化しても、個別のプレフィックスの数は依然として$O(n^2)$しかし、最適なプレイは残りの手のパリティとグローバルパリティ制約に依存するため、ゲーム構造は単純な DP オーバーポジションだけではなく、単純な DP は敵対的な構造を失います。 

重要な観察は、ゲームの長さが固定されており、次の値に等しいということです。$2n-1$したがって、すべての再生は、からの 1 つの完全な単調パスに正確に対応します。$(1,1)$に$(n,n)$。 プレイヤーは任意の文字を選択するのではなく、一連の右/下の動きを効果的に決定しますが、ターンの交互によって制約されます。 

個々のパスの観点から考えるのではなく、ゲームをレイヤーごとにパスを構築するプロセスとして再解釈します。 各ステップで現在位置がわかり、プレーヤーは右に進むか下に進むか (両方が利用可能な場合) を選択します。 重要な洞察は、唯一の不確実性は各ステップでどのフロンティア セルに到達できるかにあり、これは初期の選択が与えられると決定論的に進化するということです。 

これは、対角線のレイヤー上の DP に換算できます。 どの段階でも$k$、位置は対角線上にある必要があります$r+c=k+1$。 私たちは、最適なプレイの下で各対角線上のどの位置に到達できるかを維持します。 このゲームは、各プレーヤーが最終的な不均衡を最大化または最小化する方向に舵を切ろうとする、階層化された到達可能性ゲームになります。`'a'`そして`'b'`。 

各セルの結果をゲーム値、つまり最適なプレイの下でそのセル以降に達成できるカウントの差としてエンコードします。 次に、各セルはその右と下の隣接セルのみに依存するため、遷移は右下から後方に伝播します。 

これにより、問題は、各状態が で終わる完全なパスに基づいたターミナル ペイオフを持つ 2 人プレイ ゲームの結果を格納するグリッド上の古典的な DP に縮小されます。$(n,n)$。

 ## アルゴリズムのチュートリアル

 DP 状態を定義します$dp[r][c]$最終的なスコア差を表す（`'a'`マイナスの数`'b'`) セルから達成可能$(r,c)$両方のプレーヤーがそのポジションから最適にプレーし、最後まで継続すると仮定します。 

1.行列を初期化する$dp$サイズの$n \times n$、各エントリには、そのセルからの最高の達成可能なスコアの差が保存されます。$(n,n)$。 各細胞が貢献します$+1$含まれている場合`'a'`、$-1$含まれている場合`'b'`、 そして$0$さもないと。 
2. 右下のセルにベースケースを設定します$dp[n-1][n-1]$そのセルの値と等しくなります。 これがパスの唯一の終点であるため、それ以上の決定は行われません。 
3. 最後の行を右から左に入力します。 最後の行のどのセルからでも可能な手は右のみであるため、$dp[r][c]$現在のセルにプラスした値です$dp[r][c+1]$。 これは強制的な伝播であり、プレイヤーの決定がその方向に残っていないことを反映しています。 
4. 最後の列も同様に下から上に入力します。ここでは下方向への移動のみが可能です。 繰り返しますが、各状態は強制され、線形に蓄積されます。 
5. 残りのグリッドを距離の逆順に塗りつぶします。$(n,n)$, 右下から左上に向かって処理します。 細胞ごとに$(r,c)$、境界上にない限り、両方の動きを使用できます。 
6. 各内部セルで、次の 2 つのオプション間の最適なプレイを想定します。 

右に移動すると、$dp[r][c+1]$、下に移動すると、$dp[r+1][c]$。 そのステップのプレイヤーは、ターンパリティに応じて最終結果を最大化または最小化する手を選択します。 残りの手数は固定されているため、この交互は 1 つの最小値にまとめられ、貢献度の同等性を考慮した上で 2 つのサブゲームのうちより良い方を一貫して選択することでエンコードできます。 
7. 計算後$dp[0][0]$、結果を解釈します: ポジティブはより多くを意味します`'a'`、否定はより多くを意味します`'b'`, ゼロはドローを意味します。 

### なぜ効果があるのか

 それぞれ$dp[r][c]$は、両方のプレーヤーが最適なプレーでそのポジションから開始したサブゲームの結果を表します。 重要な不変条件は、パスのすべての接尾辞が残りの接尾辞グリッドの最適な選択によって完全に決定され、グリッドが移動方向に非循環であるため、ゲームがきれいに分解されるということです。 すべての状態は厳密に後の位置 (右または下) にのみ依存するため、DP 順序により、状態を計算する前に必要な部分問題がすべて解決されることが保証されます。 これにより、パス空間全体にわたるミニマックス評価の一貫性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]
    
    val = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if g[i][j] == 'a':
                val[i][j] = 1
            elif g[i][j] == 'b':
                val[i][j] = -1
    
    dp = [[0] * n for _ in range(n)]
    
    dp[n-1][n-1] = val[n-1][n-1]
    
    for j in range(n-2, -1, -1):
        dp[n-1][j] = val[n-1][j] + dp[n-1][j+1]
    
    for i in range(n-2, -1, -1):
        dp[i][n-1] = val[i][n-1] + dp[i+1][n-1]
    
    for i in range(n-2, -1, -1):
        for j in range(n-2, -1, -1):
            right = dp[i][j+1]
            down = dp[i+1][j]
            dp[i][j] = val[i][j] + max(right, down)
    
    if dp[0][0] > 0:
        print("FIRST")
    elif dp[0][0] < 0:
        print("SECOND")
    else:
        print("DRAW")

if __name__ == "__main__":
    solve()
```DP はボトムアップで構築されるため、すべての州がその右および下の隣接州の計算結果をすでに持っています。 最終行と最終列は遷移が 1 つしかないため、別々に処理されます。 内部再帰は、セルの寄与と 2 つの利用可能な継続のうちの最良のものを組み合わせます。 

最終的な比較は、$(0,0)$スコア差は残りのすべての動きに対する最適なプレイをすでに反映しているため、ゲームの結果を直接エンコードします。

 ## 特殊なケース

 のために$n=1$、ゲームには可能な移動シーケンスが 1 つだけあり、決定はありません。 DP は単一セルの値を正確に返すため、`'a'`すぐにFIRSTが生成され、`'b'`は SECOND を意味し、その他の文字は DRAW を意味します。 

ほとんどのセルで一方向のみが効果的に使用できるグリッドの場合、DP は強制パスの累積に減少します。 遷移の 1 つが無関係になり、最大値は単に有効な継続だけを選択するだけなので、繰り返しは引き続き適用されます。
