 ## 解決策
 ## 問題の理解

 私たちは、細胞が列状に並んだ三角錐構造を与えられています。 最初の行には 1 つのセルがあり、2 番目の行には 2 つのセルがあり、以下同様に最大 _n_ 行になります。 各セルには値を保持できます。 ピラミッドを変更できる操作は 2 種類あります。1 つは単一のセルを変更する方法、もう 1 つは特定のセルをルートとするサブピラミッド全体を変更する方法です。この場合、サブピラミッドにはルート セルの直下のすべてのセルが最後の行まで含まれ、より小さい三角形の形状が形成されます。 

Vasya はすでにピラミッド内のいくつかのセルを変更しており、私たちは Petya が Vasya のすべての変更を複製できるようにする一連の操作を生成する任務を負っています。 目標は、操作の説明で使用される数値の合計数を最小限に抑えることです。これは、すべての操作パラメーターのカウントの合計を最小限に抑えることと同じです (各操作には、タイプ、ルート セル、および影響を受けるセルの値があります)。 

入力により、ピラミッドのサイズ _n_、変更されたセルの数 _k_、および変更された各セルの行インデックスと列インデックスが得られます。 出力は、変更されたすべてのセルをカバーする一連の操作を記述するために必要な数値の最小合計数を表す単一の整数です。 

この制約は、_n_ と _k_ の両方が 10^5 に達する可能性があることを暗示しているため、サブピラミッド内のすべてのセルを明示的にシミュレートしたり、変更されたセルのすべてのサブセットをテストしたりするアルゴリズムは遅すぎます。 これは、私たちのソリューションが _n_ または _k_ での 2 次演算を回避し、理想的には O(k log k) または O(k) 時間で動作する必要があることを意味します。 注意すべきエッジケースには、下部の行に集中した変更や、大きなサブピラミッドの効率的な形成を妨げる広く分離されたセルが含まれます。 

## アプローチ

 ブルートフォース手法では、変更された各セルに個別に操作を割り当てようとします。 これはカバレッジを保証するため正しいですが、使用される数値の合計数は _k_ に比例して増加します。サブピラミッドが複数のセルをカバーできる場合、これは最小値ではありません。 _k_ が大きい場合、このアプローチでは長すぎるシーケンスが生成され、明らかに最適ではありません。 

重要な洞察は、変更された複数のセルが連続した三角形を形成している場合、1 つのサブピラミッド操作でそれらすべてをカバーできるため、説明内の数値の数が減るということです。 次に問題は、変化したセルの最大のサブピラミッドを見つけることに帰着します。ここで、各サブピラミッドは、その三角形構造を完全に満たしている一連の変化したセルをカバーします。 これにより、貪欲な戦略が可能になります。ピラミッドを下の行から上に向かって処理し、サブピラミッドの一部であるセルにマークを付け、サブピラミッドを可能な限り拡張します。 次に、サブピラミッドの各ルートが操作を生成し、その下のすべての変更をカバーします。 

この観察により、問題は動的計画法または行にわたる貪欲な問題に帰着します。セルごとに、下の行のカウントを使用して、そのセルで終わるサブピラミッドの最大高さを決定します。 このボトムアップを行うことで、各演算が最大限に行われるようになり、出力内の数値の数が最小限に抑えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) | O(k) | 正しいが最小限ではない |
 | ボトムアップサブピラミッド DP | O(k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 辞書または配列を初期化して、どのセルが変更されたかをマークします。 セルを行と列の座標で表します。 
2. ピラミッドを下段から上に向かって加工します。 行ごとに、その行内の変更された各セルを調べます。 
3. 変更されたセルごとに、下の行からサブピラミッドを拡張できるかどうかを確認します。 真下と右斜め下の両方のセルがサブピラミッド自体のルートである場合、サブピラミッドは上に伸びることができます。 このプロパティを使用して、変更された各セルで終わるサブピラミッドの最大サイズを計算します。 
4. 最大サイズが計算されたら、サブピラミッドの根細胞を特定します。 ルートは、サブピラミッドをさらに上に拡張できない (またはピラミッドの頂点にある) セルです。 これらのルートを操作生成用にマークします。 
5. 各ルート サブピラミッドの操作を生成します。 この操作には、タイプ (2)、ピラミッドの線形番号付けのルート セル インデックス、およびサブピラミッドでカバーされるすべてのセルの値が含まれます。 
6. 各操作のタイプとルート セル インデックス、および対象となるセルの数を含む、操作内のすべての数値のカウントを合計します。 この合計は、シーケンスを記述する数値の最小合計数です。 

このアルゴリズムが機能するのは、下から上に処理し、可能なサブピラミッドが可能な限り大きくなるようにするためです。 サブピラミッドを拡張できない場所にのみルートをマークすることで、変更された各セルが 1 回の操作でカバーされることが保証され、より小さなサブピラミッドではより多くのセルをカバーできないことが保証されます。 これにより、数値の合計数が最小になるシーケンスが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    changed = [[] for _ in range(n + 2)]
    idx = lambda r, c: r * (r - 1) // 2 + c

    # Store changed cells by row
    for _ in range(k):
        r, c = map(int, input().split())
        changed[r].append(c)

    # dp[r][c] = max height of subpyramid with bottom at cell (r, c)
    dp = [{} for _ in range(n + 2)]

    for r in range(n, 0, -1):
        for c in changed[r]:
            # Height is 1 if no row below
            dp[r][c] = 1
            if r < n:
                if c in dp[r + 1] and c + 1 in dp[r + 1]:
                    dp[r][c] = 1 + min(dp[r + 1][c], dp[r + 1][c + 1])

    # mark roots
    total_numbers = 0
    used = set()
    for r in range(1, n + 1):
        for c in changed[r]:
            h = dp[r][c]
            # cell is root if it's not inside a bigger subpyramid
            if (r == 1) or ((r - 1 not in dp) or (c - 1 not in dp[r - 1]) or dp[r - 1][c - 1] <= h):
                total_numbers += 2 + h * (h + 1) // 2

    print(total_numbers)

if __name__ == "__main__":
    main()
```このソリューションでは、まず変更されたセルを行ごとに整理し、次に変更された各セルの最大サブピラミッド サイズを下から順に計算します。 次に、セルがその上の大きなサブピラミッドの一部ではないことを確認することで、ルートを識別します。 最後に、すべての操作の数値のカウントを合計し、合計数値が最小限になるようにします。 境界チェックは最上行とピラミッドのエッジを処理し、重要なエラーを防ぎます。 カウントを超えて演算の生成が必要な場合、ラムダ関数は行と列の座標を線形番号付けにマップします。
