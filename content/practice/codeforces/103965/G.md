 ## 解決策
 ## 問題の理解

 私たちは与えられています$n$スタック (ステートメントではロケットと呼ばれています) と、追加の空のスタックが 1 つあります。 それぞれの$n$type はすべてのスタックにわたって正確に 2 回出現し、各スタックには最初、ちょうど 2 つの要素が上下に重なって含まれています。 

目標は、すべてのスタックに 2 つの同一のタイプが含まれるように構成を変更することです。これは、各ロケットが「純粋」になることを意味します。 要素のマルチセット全体は決して変更されないため、これは本質的に、固定された要素のコレクションに対する再配置の問題です。$2n$に配布されるアイテム$n+1$スタックします。 

唯一許可される操作は、空ではないスタックから最上位の要素を取得することです$i$そしてそれを別のスタックにプッシュします$j$、 提供された$j$現在、要素は 2 つ未満です。 これは、各スタックの容量が常に最大 2 つであることを意味します。 

制約$n \le 10^5$そして最大でも$2n$この動きは、どのような解も時間的に線形または線形に近いものでなければならないこと、また、各動きの後に繰り返しスキャンやグローバルな再計算を行うことを構築に含めることはできないことを強く示唆しています。 各要素は一定の回数だけ「処理」できます。 

微妙な点は、スタックの最下位要素と最上位要素の両方が最初は固定されていますが、移動後はスタックが動的な LIFO 構造になることです。 これは、最上位の要素のみを注意深く追跡する必要があり、任意の位置へのアクセスを想定できないことを意味します。 

単純な考えは、不一致のスタックを繰り返し選択し、それを貪欲に修正しようとすることです。 間違った要素を 1 つ移動すると、以前に固定されていたスタックが壊れる可能性があり、構造化されたターゲット組織がなければ、プロセスが循環したり、必要以上のものを必要としたりする可能性があるため、これはすぐに問題になります。$2n$動く。 

重要なエッジ ケースは、スタックに 2 つの異なる型が含まれており、単純なスワップによって依存関係のチェーンが作成されるような方法で、それらの型の両方のコピーが異なるスタックに埋め込まれている場合です。 グローバルな方向を指定せずに要素が複数回移動されるため、貪欲なローカル修正は線形移動を簡単に超える可能性があります。 

## アプローチ

 ブルートフォース戦略では、均一ではないスタックを繰り返し検索し、その要素の 1 つと一致するパートナーを見つけて、補助スタックを介して要素を交換することで解決しようとします。 これは、競合を繰り返し修正することに似ています。 

問題は、修正ごとに、すべてのスタックの中から一致する要素をスキャンし、それを解放するために要素のチェーンを移動する可能性があることです。 最悪の場合、それぞれの$2n$要素が移動される可能性があります$O(n)$連鎖的な修復により時間がかかり、$O(n^2)$操作。 これでは遅すぎます。 

重要な観察点は、この問題にはペア構造が隠されていることです。各値が正確に 2 回出現するため、すべての値が位置のペアを自然に定義します。 スタックをノードとして、要素をそれら 2 つの出現間の有向リンクとして解釈すると、システムを不一致の配置によって形成されたサイクルの集合として考えることができます。 

空のスタックは、必要な構造を上書きせずに要素を「ルーティング」できるバッファーとして機能するため、非常に重要です。 スタックを 1 つずつ修正する代わりに、グローバル不変式を適用できます。つまり、値を処理するたびに要素を処理し、ブロックを避けるために空のスタックを一時ストレージとして使用し、両方のコピーをできるだけ早く同じスタックに配置します。 

建設的なアイデアは、ペアリングのプロセスをシミュレートすることです。補助構造で一致するパートナーがすでに「待機」している要素を見つけると、すぐにペアを完了します。 それ以外の場合は、一時的にバッファ スタックに移動します。 これにより、各要素が一定の回数だけ移動されることが保証されます。 

これが機能するより深い理由は、すべての操作がペアを解決するか、未解決の要素を複数回移動できない構造に移動するためです。 これにより、シャッフルが繰り返されるのを防ぎます。

 ## アルゴリズムのチュートリアル

 スタックを変更可能なリストとして扱い、最上位のみを操作します。 補助スタックを維持します$0$、最初は空であり、作業メモリとして使用されます。 

1. スタックを 1 から 1 まで繰り返します。$n$、各スタックについて、その最上位要素を繰り返し検査します。 スタック内の両方の要素がすでにペア (同じ値が 2 回) を形成している場合は、それをスキップします。 
2. スタックに 2 つの異なる値が含まれている場合、次のようにします。$a$そして$b$、一番上の要素を選択します$x$。 他の出来事をすでに見たかどうかを調べます。$x$何らかの一時的な構造物で。 
3. 値からスタックへのマッピングを維持します。スタックには、最初に検出された値が現在保持状態で保存されています。 もし$x$がまだ表示されていない場合は、それを補助スタックに移動し、その位置をマークします。 
4. もし$x$すでにいくつかのスタックで見られています$j$、そしてそのパートナーを見つけました。 移動します$x$現在のスタックから$j$、ペアが完成します。 今スタックします$j$均一で安定した状態になります。 
5. スタックが 2 つの同一の値でいっぱいになると、スタックへのタッチを完全に停止します。 
6. すべてのスタックが処理されるまで続行します。 各値は最大 2 回の一時ストレージへの移動と 1 回の最終配置に関与するため、操作の総数は次の制限を受けます。$2n$。 

重要な考え方は、すべてのスタックをスキャンしてパートナーを「検索」しないということです。 パートナーがすでに記録されている場合にのみ反応し、各値が常に一定の動作でトリガーされるようにします。 

### なぜ効果があるのか

 不変条件は、すべての値がすでに完成したスタックに正しく配置されているか、「そのペアを待っている」ことを表す 1 つの一時的な位置にのみ格納されているかのいずれかです。 値が一時状態に入ると、それが何度も複製されたり、任意に移動されたりすることはありません。 そこで待機するか、すぐにパートナーとマッチングされます。 各値は最大でも一定数の状態を遷移するため、合計移動数は線形であり、これを超えることはできません。$2n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    stacks = [[] for _ in range(n + 2)]
    
    for i in range(1, n + 1):
        a, b = map(int, input().split())
        stacks[i].append(a)
        stacks[i].append(b)
    
    res = []
    pos = {}  # value -> stack index where it is waiting
    
    def move(i, j):
        x = stacks[i].pop()
        stacks[j].append(x)
        res.append((i, j))
    
    for i in range(1, n + 2):
        while stacks[i]:
            x = stacks[i][-1]
            
            if x in pos:
                j = pos[x]
                move(i, j)
                # now x completes pair in j, mark j as done
                pos.pop(x, None)
            else:
                move(i, 0)
                pos[x] = 0
    
    print(len(res))
    for i, j in res:
        print(i, j)

if __name__ == "__main__":
    solve()
```この実装では、バッファリングのアイデアの直接シミュレーションを使用します。 補助スタックのインデックスは 0 です。初めて値に遭遇するたびに、それをバッファーにプッシュし、その位置を記憶します。 再びそれを見つけたら、すぐに一致するスタックに移動します。 

重要な点は、常にスタックの最上位で動作し、内部要素にはアクセスしようとしないことです。これは問題の制約と一致します。 もう 1 つの重要な点は、すべての動きが出力リストに即座に記録され、最終的なシーケンスの正確さが保証されることです。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのスタックがすでに正しい場合です。 この場合、要素はまったく移動されず、出力はまったく操作が 0 である必要があります。 すべての最上位要素がスタック内で有効なペアを即座に形成するため、アルゴリズムは当然すべての処理をスキップし、バッファリングはトリガーされません。 

別のエッジケースは次のようなフルサイクルです$1,2$、$2,3$、$3,1$。 ここでは、最初から純粋なスタックはなく、すべての動きは別のスタックに依存します。 バッファーは不可欠なものになります。バッファーは、一致するパートナーが現れるまで要素を一時的に保管し、グローバル検索を必要とせずにサイクルを断ち切ります。 各要素は一度バッファに入り、その後正確に 1 回一致するため、シーケンスは線形のままです。 

3 番目のエッジ ケースは、値の両方の要素が最初は同じスタック内にあるものの、順序が逆である場合です。 それらがすでに有効なペアを形成している場合でも、アルゴリズムは処理順序に応じてそれらを最初にバッファに移動する場合があります。 ただし、2 番目のコピーが見つかると、バッファリングされたコピーで即座に解決され、最終的にスタックが重複や損失なく復元されることが保証されます。
