 ## 解決策
 ## 問題の理解

 一連の葉の山のサイズが与えられていますが、これらの葉の山は 1 から c までの番号が付けられた位置の長い線上に配置されています。 これらの位置のうち実際に非ゼロの山が含まれるのは n だけです。具体的には、位置 1 から n には値 a1 から an が格納されますが、n 以降 c までのすべての位置は事実上空です。 

[1, c] の範囲内のどこにでも、固定長 k の位置の連続したセグメントを選択できます。 このようなセグメントごとに、その中にあるすべての山の値の合計を計算します。 1..n の外側の位置は空であるため、何も寄与しません。 

タスクは、この合計を最小にする長さ k のセグメントを見つけることです。 

重要な制約は、c が 10^9 まで大きくなり得るため、これを完全な配列に対する通常のスライディング ウィンドウとして扱うことが不可能になるということです。 実際の非ゼロ要素の数は n から 10^5 までのみであるため、正しい解決策は座標範囲全体にわたる反復を避け、代わりにウィンドウが小さなアクティブ領域とどのように相互作用するかを考慮する必要があります。 

素朴なアイデアは、サイズ c の配列を構築し、長さ k のウィンドウをスライドすることです。 c を反復処理することさえ不可能であるため、これはすぐに失敗します。 

2 番目の単純なアイデアは、完全に 1..n 内にあるウィンドウのみを考慮することです。 これにより、ウィンドウが n を超えて空の領域に拡張されると、有効な最適な答えが失われ、合計が大幅に減少する可能性があります。 

k が十分に大きく、ウィンドウが空の領域に完全に収まる場合、微妙なケースが 1 つ発生します。 たとえば、n = 5、c = 10、k = 4 の場合、[6, 9] を選択すると、a の値には触れませんが、合計 0 が得られ、これが最適です。 空の領域を無視するアプローチはここで失敗します。 

k が n より大きい場合には、別の注意が必要なケースが発生します。 その場合、空でない要素に触れるすべての有効なウィンドウには配列のサフィックスが含まれている必要があり、純粋に a の固定長部分配列の観点から推論するのは不正確になります。 

## アプローチ

 ブルートフォース手法では、サイズ c の配列 b (i ≤ n の場合は b[i] = a[i]、それ以外の場合は b[i] = 0) を明示的に構築し、長さ k のすべてのセグメントを評価します。 各ウィンドウの合計は O(k) で計算され、全体の複雑さは O(c · k) になりますが、c は 10^9 であるため、これは実現可能な限界をはるかに超えています。 

問題の構造により、より強力な単純化が可能になります。 ゼロ以外の寄与は、位置 1 から n までに限定されます。
