 ## 解決策
 ## 問題の理解

 私たちには曲のコレクションが与えられており、各曲には基本的な楽しみの価値があります。 次に再生する曲を繰り返し選択することで、長さ k のプレイリストを構築します。 問題は、同じ曲を連続して繰り返し再生すると、その楽しさが減じることです。基本値 a の曲が連続して複数回再生されると、1 回目は a、2 回目は a-1、3 回目は a-2 というようになりますが、0 を下回ることはありません。 別の曲に切り替えるとすぐに、前の曲の減衰がリセットされます。 

あらゆるステップで、プレイリストは貪欲に構築されます。 すべての曲の現在の「次回プレイ バリュー」を確認し、その中で最大のものを選択し、その曲を選択します。 同点の場合は、前回と異なる曲を選んでも構いません。 そのような代替案が存在しない場合にのみ、前の曲を続行します。 

目標は、このルールの下で k 回プレイした後に得られる合計の楽しみを計算することです。 

この制約により、直接シミュレーションが不可能になります。 k が 10^9 までの場合、O(k) の仕事でも大きすぎます。 曲の数 n は最大 2×10^5 です。これは、ソートやヒープを伴うものであれば何でも問題ないことを示唆していますが、それは個別に k ステップを反復しない場合に限ります。 重要な問題は、貪欲なプロセスによって曲を繰り返す長い連続部分が作成されるため、それらの連続部分をブロックに圧縮する必要があることです。 

単純なシミュレーションでは、すべての曲を繰り返しスキャンして、次に最適なピックを見つけます。 それだけでは O(nk) のコストがかかり、すぐに遅すぎます。 

2 番目の素朴なアプローチは、現在の値の優先キューを維持することですが、同じ曲を選択するたびに値が変わります。 それでもまだ k 回の更新に直面しており、依然として大きすぎます。 

最高の曲が前の曲でもあるが、別の曲が同じ現在の値を持つ場合、微妙なエッジケースが発生します。 その場合、前の曲を続けることが最適であっても、タイブレーク ルールにより強制的に切り替えが行われます。 これは、これを純粋な「常に最大値を取る」プロセスとして扱うことはできないことを意味します。 前の選択が私たちを拘束します。 

## アプローチ

 ブルートフォースシミュレーションは簡単です。 k ステップのそれぞれで、すべての曲の現在の実効値を計算し、ルールに従って最良の曲を選択し、その連続カウンターを更新し、必要に応じて他の曲をリセットします。 これが機能するのは、状態が単純であるためです。最後に選択した曲だけが値が減少し、他の曲はすべて基本値のままです。 ただし、それでもステップごとに O(n) のコストがかかるため、O(nk) になり、k が 10^9 に達すると、これは実行可能な限界をはるかに超えます。 

重要な観察は、システムには、現在リピートされている 1 つの「アクティブな」曲を除いて、進化する構造がほとんどないということです。 他のすべての曲は基本値で一定のままです。 これは、競合が常に 2 つの量の間で行われることを意味します。現在の曲の減少する値と、他のすべての曲の中で最も良い固定値です。 

これにより、問題は、現在の曲が厳密に最良の代替曲よりも良くなくなるまでに、どのくらいの期間連続記録を継続できるかについての推論に帰着します。 それが起こったら切り替えなければならず、このプロセスが繰り返されます。 各ストリークは、等差数列の合計を使用して 1 回のジャンプで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nk) | O(n) | 遅すぎる |
 | ストリーク圧縮 | O(n log n) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、基本享受値のリストを前処理し、最大の値と 2 番目に大きい値を特定します。 また、最大値を持つ曲が何曲あるかも追跡します。これは、前の曲が固有の最大値である場合にタイブレークに影響するためです。 

次に、プレイリストをシミュレートしますが、一度に 1 曲ずつステップ実行するのではなく、同じ曲の連続するブロック全体を処理します。

1. 最初に選択した曲を最大のベース値を持つ曲として初期化します。 最初のプレイで最大限の価値が得られ、連続連続記録を 1 に設定します。 
2. 現在の曲、その基本値、連続して何回再生されたかをいつでも知ることができます。 これにより、現在の寄与、つまりベースからストリーク オフセットを差し引いた値が決まります。 
3. 最良の代替値を計算します。これは、グローバル最大値、または現在の曲が固有の最大値である場合は 2 番目の最大値のいずれかになります。 
4. 現在の曲の次の値が最良の代替曲よりも厳密に大きい場合、連続記録を継続します。 減少する値が代替値以下になるまでに安全に続行できる回数を計算します。 これにより、算術合計を使用して一度に追加できる完全なセグメントが得られます。 
5. 現在の曲が続行できない場合は、最適な代替曲に切り替え、その連続数を 1 にリセットし、このプロセスを繰り返します。 

ストリーク内の重要な計算は、実行できるステップ数を決定することです。 セグメントの開始時の現在の値が cur で、最良の代替値が best_other である場合、cur、cur−1、cur−2 などが厳密に best_other より大きいままである間続行します。 これにより、セグメントの長さの明確な境界が生成されます。 

### なぜ効果があるのか

 いかなる時点においても、重要な候補は 2 種類のみです。1 つは現在繰り返されている曲であり、その値は直線的に減少します。もう 1 つは他のすべての曲の中で最も優れた曲であり、これは一定です。 貪欲なルールにより、これら 2 つのうちの最大値が常に選択されます。 時間の経過とともに変化するのはそのうちの 1 つだけであるため、決定境界を越えることができるのはストリークごとに 1 回だけです。 これにより、各曲がブロック内でのみアクティブになることが保証され、すべてのブロックは単純な不等式によって完全に決定されるため、プロセスが正確かつロスレスになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    mx = a[-1]
    smx = a[-2] if n > 1 else 0
    
    # frequency of maximum value
    cnt_mx = a.count(mx)
    
    def best_other(prev_is_unique_max):
        if prev_is_unique_max:
            return smx
        return mx
    
    # start with max element
    cur_val = mx
    streak = 1
    k -= 1
    ans = mx
    
    prev_is_unique_max = (cnt_mx == 1)
    
    while k > 0:
        bo = smx if (cur_val == mx and prev_is_unique_max) else mx
        
        # try to continue current song
        if cur_val > bo:
            # max steps we can take
            t = cur_val - bo
            t = min(t, k)
            
            # sum of decreasing sequence: cur_val + (cur_val-1) + ...
            ans += t * cur_val - t * (t - 1) // 2
            
            cur_val -= t
            k -= t
            streak += t
            
            if k == 0:
                break
        
        # switch song
        # choose best alternative value
        if cur_val == mx and prev_is_unique_max:
            new_val = smx
        else:
            new_val = mx
        
        if new_val == 0:
            break
        
        ans += new_val
        cur_val = new_val
        streak = 1
        k -= 1
        
        # after switching, previous is no longer unique max situation
        prev_is_unique_max = False
    
    print(ans)

if __name__ == "__main__":
    solve()
```決定プロセス全体はそれらにのみ依存するため、実装では最初に 2 つの最大の基本値を特定します。 メイン ループ内では、閉じた形式の合計を使用して現在のストリークを延長するか、利用可能な最適な代替に切り替えます。 

等差数列の公式は重要です。減少する値を 1 つずつ加算する代わりに、ブロックの完全な寄与を一定時間で計算します。 整数の除算を使用し、ストリークの長さが正の場合にのみ式を適用するように注意する必要があります。 

微妙な点は、前の曲がユニーク最大値である場合の処理​​です。 その状況では、代替は 2 番目の最大値であり、それ以外の場合はグローバル最大値です。

 ## 特殊なケース

 主なエッジケースは、最大値が 1 回だけ現れる場合です。 その状況では、別の曲が減衰後の現在の値と等しい場合、最大の曲に留まることが許可されない場合があります。 その場合、アルゴリズムは明示的に 2 番目の最大値に切り替え、タイ ルールが確実に尊重されるようにします。 

k が非常に大きい場合、別のエッジ ケースが発生します。 単純なシミュレーションは決して完了しませんが、ブロックベースのアプローチでは k を大きなチャンクで消費するため、個々のステップの反復が妨げられます。 

最後に、すべての値が等しい場合、すべての切り替えがタイ ルールによって強制され、プロセスは繰り返しの交代に退化します。 最良の代替案と電流減衰が即座に一致するため、アルゴリズムはこれを正しく処理します。
