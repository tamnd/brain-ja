 ## 解決策
 ## 問題の理解

 一連の整数が与えられます。 これらは、ゼロから始まる継続的な値への毎日の「変化」と考えてください。 左から右に進むにつれて、累計が維持されます。 各要素は、この累計を増加または減少させます。 

タスクは、配列を左から右に処理する際に、この累計がこれまでに到達した最高値を決定することです。 

したがって、配列がスコアの増分と減分として解釈される場合は、プレフィックス境界で達成される最大スコアはいくらかという質問が生じます。 

出力は単一の整数、つまり配列全体の最大プレフィックス合計です。 

この問題の制約は、単一の線形スキャン以上のものを必要とするほど大きくありません。 これにより、プレフィックスの合計を繰り返し再計算しようとしたり、入れ子になったループを使用したりするソリューションはすでに除外されています。これらは 2 次の動作に変わり不必要だからです。 

すべての値が負の場合、微妙なエッジ ケースが発生します。 この場合、累計はゼロから始まり、決して改善されないため、答えはゼロのままになるはずです。 少なくとも 1 つの正のプレフィックスの増加を前提としたソリューションは、ここでは失敗します。 たとえば、入力`[-3, -2, -5]`生産しなければならない`0`、 ない`-3`。 

もう 1 つのエッジ ケースは、最大のプレフィックス合計が最初の要素で発生する場合です。 例えば`[5, -10, 1]`返すべきです`5`。 完全な蓄積後にのみチェックするか、中間プレフィックスを考慮することを忘れる単純な実装では、これを見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのプレフィックスの合計を個別に計算し、最大値を取得します。 各インデックス i について、0 から i までの合計を計算します。 これは、プレフィックス合計の定義に直接従うため、正しく機能します。 ただし、各プレフィックスの合計を再計算すると、合計でおよそ n + (n-1) + ... + 1 回の操作、つまり O(n²) が必要になります。 一般的な制約が 10^5 までの場合、これは非常に遅くなります。 

重要な観察は、プレフィックスの合計が増加しているということです。 最初から再計算する代わりに、配列を 1 回スキャンしながら実行中の合計を維持できます。 新しい要素ごとに現在の合計が更新され、それをこれまでに確認された最良の値とすぐに比較します。 これにより、繰り返しの再計算の問題が 1 回のパスの累積に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースプレフィックス再計算 | O(n²) | お(1) | 遅すぎる |
 | 単一パスの累計 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの変数から始めます。`current_sum = 0`そして`best = 0`。 要素が適用される前の開始状態を考慮できるため、初期の最適値はゼロです。 
2. 配列を左から右に繰り返します。 各位置で、現在の要素を`current_sum`。 これは、次の「気分の変化」または「増分」の適用をシミュレートします。 
3. アップデート後`current_sum`と比較してください`best`。 もし`current_sum`大きいので交換してください`best`それと一緒に。 この手順により、これまでに検出された最高のプレフィックス値を常に記憶できるようになります。 
4. 配列の最後まで続けます。 最終的な値は、`best`が答えです。 

### なぜ効果があるのか

 位置 i の累計は、正確に最初の i 要素の接頭辞の合計です。 考えられるすべてのプレフィックス合計は、スキャン中に 1 回だけ評価されます。 セットの最大値は増分比較で保存されるため、これまでに確認された最大値を追跡することで、候補プレフィックスが見逃されないことが保証されます。 累積合計を超える非隣接プレフィックス間の依存関係はないため、追加の構造は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

current_sum = 0
best = 0

for x in a:
    current_sum += x
    if current_sum > best:
        best = current_sum

print(best)
```この実装は、上記のスキャンを直接変換したものです。 唯一の微妙な決定は初期化です`best`負の無限大ではなくゼロにします。 これは、要素が取得される前に累計が開始されるため、空のプレフィックスが有効であることを反映しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各要素は一定時間の更新で 1 回処理されます。 
| スペース | お(1) | 維持される実行変数は 2 つだけです。 

すべての要素を少なくとも 1 回読み取る必要があり、追加の構造が必要ないため、リニア スキャンが最適です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    current_sum = 0
    best = 0
    for x in a:
        current_sum += x
        best = max(best, current_sum)
    return str(best)

# provided samples (illustrative)
assert run("3\n1 -2 3\n") == "2"

# all negative
assert run("3\n-1 -2 -3\n") == "0"

# all positive
assert run("4\n1 2 3 4\n") == "10"

# alternating
assert run("5\n1 -1 1 -1 1\n") == "1"

# single element
assert run("1\n5\n") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて否定的 | 0 | 空のプレフィックスの処理 |
 | すべて肯定的 | 合計 | 完全な累積の正確性 |
 | 交互 | 1 | 正しい中間最大値 |
 | 単一要素 | 価値そのもの | 境界条件 |

 ## 特殊なケース

 完全に負の数で構成される入力の場合、累計は継続的に減少します。 このアルゴリズムは常にゼロ初期化ベストと比較するため、正しくゼロを返します。 例えば`[-4, -2, -7]`生成する`0`空のプレフィックスを超えるプレフィックスがないためです。 

単一要素の配列の場合、最初の更新では、現在の値と最良の値が正の場合はすぐにその値に設定され、負の場合は最良の値がゼロに維持されます。 これは、要素を処理する前に常に開始状態と比較するという考えと一致します。
