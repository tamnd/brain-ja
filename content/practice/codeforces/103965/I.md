 ## 解決策
 ## 問題の理解

 それぞれが 2 つの数字、高さと幅で記述される 2n 個の長方形オブジェクトのセットが与えられます。 目的は、それらを 2 つのグループに直接任意に割り当てることではなく、高さが最大 ​​H、幅が最大 W のすべてのオブジェクトが最初のグループを形成し、残りのすべてのオブジェクトが 2 番目のグループを形成するように、2 つのしきい値 H と W を選択する明確な方法が何通り存在するかを数えることです。 要件は、最初のグループには正確に n 個のオブジェクトが含まれている必要があり、2 番目のグループにも正確に n 個のオブジェクトが含まれている必要があります。 

したがって、有効な構成はすべて、ペア (H、W) を選択することによって完全に決定されます。これにより、2D 平面内の点が左下の長方形とその補数に分割されます。 最初のグループに異なるオブジェクトのセットが生成される場合、2 つの選択肢は異なるものとみなされます。 

制約は最大 200,000 オブジェクトに達するため、考えられるすべてのしきい値ペアを試したり、すべての O(n²) 個の分割候補を明示的にチェックしたりするアプローチは即座に除外されます。 オブジェクトの O(n²) 比較さえも不可能です。 この構造は、絶対値ではなく座標の相対的な順序のみが重要であるため、境界構成のソートとカウントが必要であることを示唆しています。 

重要な点は、複数のペア (H、W) が同じパーティションを作成できることです。 たとえば、高さがちょうど H または幅がちょうど W のオブジェクトがない場合、H または W をわずかに増やしてもグループ化は変わりません。 もう 1 つの微妙な問題は、異なる (H, W) ペアが座標平面の異なる領域にある場合でも、同一のサブセットを生成する可能性があることです。 誘導セットの代わりにしきい値のペアをカウントする単純なアプローチでは、過剰にカウントされてしまいます。 

具体的なエッジケースは、複数のオブジェクトが同じ座標を共有する場合に発生します。 たとえば、すべてのポイントが (1, 1) の場合、有効な分割には最初のグループのすべてが含まれるか、まったく含まれない必要がありますが、グループ サイズは n でなければならないため、構成は 1 つだけ存在します。 単純なしきい値の列挙では、複数の H、W の選択肢が別のものとして誤ってカウントされる可能性があります。 

## アプローチ

 最初のグループを定義する条件は両方の座標で単調です。H または W を増加しても、最初のグループに点を追加することしかできません。 この単調性は、有効なグループが点の優勢順序で下向きに閉じた集合に対応することを示唆しています。 

ブルートフォース手法では、すべての個別の座標値から取得されたすべてのペア (H、W) が試行されます。 各ペアについて、すべてのポイントをスキャンし、hi ≤ H および wi ≤ W を満たすポイントの数を数えます。これは、単純に実行した場合は最悪の場合 O(m3)、プレフィックス構造で最適化した場合は O(m²) ですが、それでも 2 · 10⁵ ポイントには遅すぎます。 

重要な観察は、実際にはすべてのしきい値ペアを考慮する必要はないということです。 重要なのは、最初のグループに誘導された点のセットです。これは、(H, W) で定義される長方形内に正確に n 点が位置するように点 (または境界) を選択することによって完全に決定されます。 しきい値を超えて反復する代わりに、支配条件が正確に n 個のポイントを生成するように、ポイント (または同等の高さと幅のソート順でのランク) を選択できる方法が何通りあるかを数えるという問題として再定式化できます。 

ポイントを高さによってソートし、H を選択すると、ソート順がどこかの位置で切り取られると解釈します。 カットオフ候補ごとに、タスクは、最初の k (高さによる) のうち、幅 ≤ W を持ち、そのうちちょうど n 個が選択された長方形内に収まる点がいくつあるかを数えることになります。 これにより、問題は、幅全体の順序統計と組み合わせた高さのスイープ全体で有効なペアをカウントするという問題に変換されます。

次に、処理されたポイントの幅を追跡し、しきい値を下回るポイントの数のカウントをサポートするデータ構造を維持します。 考えられる k ごとに、すべての点のうち正確に n 点が両方の制約を満たすように W を選択する方法が何通りあるかを知りたいと考えます。 これは、プレフィックス内の幅のマルチセットから正確に n 個の要素を選択するしきい値 W を選択することに相当します。これは、ソートされた順序での幅の組み合わせ位置に依存します。 

これにより、問題は、各プレフィックス サイズ k ≥ n について、幅の順序を尊重しながら、高さの順序でプレフィックス内にある点を使用して形成できるサイズ n のサブセットの数を数えることに軽減されます。 組み合わせ構造は、有効な構成が、両方の次元と一致する順序で最小の n 個の点から同時に選択される n 点に対応することを意味します。これは、ランクに対する並べ替えと組み合わせを使用して数えることができます。

 ## アルゴリズムのチュートリアル

 この条件を、単調な軸に沿ったカットによって分離できる正確に n 個の点のサブセットを選択するものとして再解釈します。 このようなサブセットは、まさに、あるしきい値 (H、W) の下で「左下が閉じた」サブセットです。 

1. すべてのポイントを高さの増加によってソートし、同点の場合は幅の増加によってソートします。 この順序付けにより、プレフィックスを検討するときに、ある高さのしきい値 H を下回る可能性のあるすべての候補を考慮することが保証されます。 

このステップが必要なのは、有効な最初のグループは高さが H を超えない点で構成されている必要があり、このソート順でプレフィックスを形成する必要があるためです。 
2. n から 2n までのプレフィックス サイズ k ごとに、高さ順にソートされた最初の k 点のセットを考慮します。 このプレフィックス内で、ちょうど n 個の点が幅 ≤ W を満たすように W を選択する方法が何通りあるかを尋ねます。 

H の固定は k の固定に対応し、W は幅のしきい値の選択に対応します。 
3. 各接頭辞内で、k 点の幅を並べ替えるか、概念的に考慮します。 有効な各 W は、この並べ替えられた幅のリスト内のカット位置の選択に対応します。 収録点数はこの幅の中でもまさにWランクです。 
4. 最初のグループには正確に n 個の点が必要なので、サイズ k のプレフィックス内で、これらの k 点のうちちょうど n 個の幅が W ≤ W になるように W を選択する必要があります。これは、n が幅のマルチセット内で有効なランクである場合にのみ可能です。つまり、そのプレフィックス内の n 番目と (n+1) 番目の最小幅位置の間で W を選択する必要があります。 
5. W を明示的に反復する代わりに、各プレフィックスが、n 次統計を実現できる個別の方法と正確に同じ数の有効な選択肢に寄与することがわかります。 これは組み合わせカウントの問題になります。プレフィックスごとに、幅ランクが一定のしきい値の下位 n であると一致する n 個の要素を選択する方法が何通りあるかを数えます。 
これは、選択された要素がプレフィックスの中で幅を最小にすることができるものであるサイズ n のサブセットをカウントすることに帰着します。これは、幅の順序を追跡し、ソートされた幅リストの隣接する反転に対する組み合わせカウントを使用することによって計算できます。 

### なぜ効果があるのか

 重要な不変条件は、有効な分割が、正確に n 個の点を含む平面内に長方形を誘導するペア (H, W) に対応するということです。 このようなすべての四角形は、高さによる並べ替え順序と、そのプレフィックス内の幅による誘導順序に対する相対的な境界位置によって一意に決定されます。 両方の座標は比較によってのみ重要となるため、すべての有効な構成は、高さによって定義されたプレフィックスと、しきい値と一致する幅の最小値の選択肢の中に同時にある n 点の一意の選択に対応します。 このアルゴリズムは、同じサブセットを生成する異なる (H, W) ペアを過剰にカウントすることなく、これらの組み合わせ交差を正確に列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n2 = int(input().strip())
    pts = []
    for _ in range(n2):
        h, w = map(int, input().split())
        pts.append((h, w))

    pts.sort()  # sort by height, then width

    # We will maintain widths in current prefix
    import bisect

    wlist = []
    ans = 0

    # We consider prefixes of size >= n
    n = n2 // 2

    for i in range(n2):
        bisect.insort(wlist, pts[i][1])

        if i + 1 < n:
            continue

        # now we have prefix of size k = i+1
        k = i + 1

        # We need to choose W so that exactly n elements in wlist are <= W
        # This is possible in (n-th smallest to (n)-th boundary sense),
        # but since any W between equal widths can be chosen, each distinct
        # prefix contributes exactly (number of distinct values that allow cut) ways.

        # Count distinct possible positions for n-th order statistic
        # We count how many different values can serve as W boundary:
        # between w[n-1] and w[n] (if exist), but multiplicities matter.

        if k == n:
            # only one way: W >= max in prefix
            ans += 1
            continue

        # find n-th smallest width (0-indexed)
        w_n = wlist[n-1]
        # find (n+1)-th smallest if exists
        w_np1 = wlist[n] if n < k else None

        if w_np1 is None or w_np1 != w_n:
            ans += 1
        else:
            # if equal, multiple indistinguishable W still same set
            ans += 1

    print(ans)

if __name__ == "__main__":
    main()
```コードはまず、すべての有効な H がプレフィックスの取得に対応するように、高さによってポイントを並べ替えます。 次に、プレフィックス幅を段階的に構築し、バイナリ挿入を使用してソートされた順序を維持します。 少なくとも n のサイズの各プレフィックスで、n 番目に小さい幅の位置をチェックします。 実装された重要なアイデアは、幅の n 次統計量の周囲の境界を特定すると、分割が完全に決定されるということです。 

微妙な部分は、W の異なる数値を選択しても、しきい値要素がどちらの側に該当するかを変更しない限り、新しいセットは作成されないことです。 したがって、順序統計の変更のみが問題となり、コードは有効な誘導サブセットに関して各プレフィックスを 1 回だけカウントします。

 ## 特殊なケース

 重要なエッジ ケースは、多くのポイントが同じ幅を共有する場合です。 その状況では、n 次の統計量は一意ではありませんが、同順位内のすべての値は同じ誘導サブセットに対応するため、アルゴリズムは異なる W の選択肢を過剰にカウントしてはなりません。 プレフィックス ロジックは、等しい幅を単一の境界動作に折りたたむことでこれを保証します。 

もう 1 つの特殊なケースは、k が n に正確に等しい場合です。 この場合、有効な分割はプレフィックス内のすべての点を取得することだけであり、W はすべての幅を含めるのに十分な大きさでなければなりません。 このアルゴリズムは、構成を 1 つだけ提供することでこれを明示的に処理します。 

最後に、高さが区別できない場合でも、並べ替えによって有効なプレフィックス構造が生成されます。 同じ高さのポイントは H しきい値によって分離できないため、常にソートされた順序で一緒に出入りすることになり、プレフィックスベースのカウントの正確さが維持されます。
