 ## 問題の理解

 円形のキーボードが与えられました。$n$固定された巡回順序で配置されたキー。 各キーには小文字のラテン文字が含まれており、複数の位置が同じ文字を共有する場合があります。 ポインタは選択した任意のキーから始まり、ターゲット文字列を生成したいと考えています。$s$。 

2 種類の移動が許可されています。 まず、円に沿って 1 歩前進して、すぐにそのキーに文字を入力します。 この移動により、位置が変更され、文字が追加されます。 次に、テレポート中に何も入力しなくても、現在のキーと同じ文字を含む他のキーに即座にテレポートできます。 

タスクは、文字列を生成する有効な動きのシーケンスが存在するかどうかを判断することです。$s$その通り。 

制約により両方が許可されます$n$そして$|s|$まで$2 \cdot 10^5$これにより、位置を超えて分岐したり、考えられるすべてのポインター状態を試行したりするシミュレーションが除外されます。 考えられるすべての現在のキーを明示的に追跡するソリューションは、次の方向に劣化します。$O(n|s|)$、大きすぎます。 

微妙な難しさは、テレポーテーションによって到達可能性の点で同じ文字が出現するすべてが同等になりますが、円運動は依然として隣接性に依存するという事実から生じます。 単純な間違いは、キーボード文字列内の文字数または文字の隣接性をチェックするだけでよいと考えることです。 動きの方向が重要であるため、これは失敗します。 

小さな失敗例: キーボードが壊れている場合`abca`そして文字列は`aaa`、素朴な考えでは、次の繰り返しを考えるかもしれません。`a`で十分です。 ただし、動きの構造により、出現の間に互換性のない文字を通過する必要がある場合は、有効なステップを十分に連鎖させることができない可能性があります。 

本当の課題は、テレポーテーションを使用して同一の文字内の位置をリセットしながら、文字の制約を伴う有向サイクル上の歩行を調整できるかどうかを判断することです。

重要な観察は、テレポーテーションは同じ文字を持つすべての位置を単一の等価クラスに折りたたむということです。 文字が出現すると、同じ文字が出現する別の文字を次の移動の新しい開始点として即座に選択できます。 これは、唯一の本当の制約は、連続する文字間で各遷移が行われるかどうかであることを意味します。$s$これは、順序に違反することなく、前の文字のある出現から次の文字のある出現まで円に沿って前進することによって実現できます。

円構造は、ある位置から$p$、次の動きは常に次の動きに進みます。$p+1 \mod n$。 したがって、キャラクターの開始位置を固定すると、再度テレポートするまでのパスは完全に決定されます。 これは、各文字の開始位置のシーケンスを選択できるかどうかを効果的にチェックしていることを意味します。$s$各ステップが正しく進むように。

 ## アルゴリズムのチュートリアル

 文字が出現するたびに、サイクル上の点として扱います。 各文字について、円上のすべての位置を昇順に保存します。 

文字列の各プレフィックスを処理した後に到達できる、現在到達可能な位置の間隔を維持します。 動きは常にサイクルに沿って前進するため、到達可能な位置は常に円上で連続した円弧を形成します。 

1. 最初の文字を選択して初期化します$s[0]$。 任意の出現箇所から開始できるため、最初に到達可能なセットは、その文字を含む位置の完全なセットになります。 これが最初の間隔です。 
2. 次の各文字について$s[i]$、到達可能な間隔を更新しようとします。 現在の間隔内のあらゆる位置から、円に沿って前進することができます。 次に発生するのは、$s[i]$到達できるかは、現在の円弧の後にその文字の次の位置がどこにあるかによって決まります。 
3. 発生するたびに、$s[i]$、現在の間隔内にあるか、または現在の間隔から前に進むことで到達できるかどうかを確認します。 動きは決定論的であるため、少なくとも 1 回発生するかどうかを確認するだけで済みます。$s[i]$現在の円弧境界から到達可能です。 
4. 問題が発生しない場合$s[i]$現在の間隔から到達できる場合、プロセスはすぐに失敗します。 
5. それ以外の場合は、間隔を更新して、$s[i]$1 回前進した後に到達可能な場所に到達したら、続行します。 

これにより、円上で円弧が繰り返し交差したり移動したりするという問題が発生します。 

### なぜ効果があるのか

 重要な不変条件は、処理後の$i$文字の場合、可能なポインター位置のセットは常にサイクル上の単一の連続する円弧になります。 これは、移動が厳密に前方に行われ、テレポートでは同一の文字内でのジャンプのみが許可されるためです。文字の出現はすべて対称的に扱われるため、連続性が損なわれることはありません。 

到達可能な状態空間が複数の切断されたアークに分割されることはないため、複数の間隔を追跡する必要はありません。 いずれかのステップで有効な遷移が存在しない場合、テレポーテーションは前進移動によって課せられる順序制約を変更できないため、一連のテレポーテーションと前進移動は回復できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    k = input().strip()
    s = input().strip()

    pos = {}
    for i, c in enumerate(k):
        pos.setdefault(c, []).append(i)

    if s[0] not in pos:
        print("NO")
        return

    # current reachable set is represented as a set of positions
    # we store it explicitly since n is large but transitions are constrained
    cur = set(pos[s[0]])

    for i in range(1, len(s)):
        c = s[i]
        if c not in pos:
            print("NO")
            return

        nxt = set()
        for p in cur:
            # move forward from p until we either find c or loop
            # since this is O(n^2) worst, we optimize by direct jump logic
            pass

        # Instead of brute force, we simulate using next occurrence pointer
        for p in cur:
            # binary search next occurrence after p
            arr = pos[c]
            # find smallest index in arr with value > p
            l, r = 0, len(arr)
            while l < r:
                m = (l + r) // 2
                if arr[m] > p:
                    r = m
                else:
                    l = m + 1
            if l < len(arr):
                nxt.add(arr[l])
            else:
                nxt.add(arr[0])  # wrap around cycle

        if not nxt:
            print("NO")
            return
        cur = nxt

    print("YES")

if __name__ == "__main__":
    solve()
```この実装では、各文字のすべての出現箇所が、ソートされたインデックスのリストに圧縮されます。 文字列内の遷移ごとに、現在到達可能なすべての位置を、必要な文字の次の有効な出現位置に循環順序でマッピングしようとします。 二分検索では、現在位置より厳密に後の最初の出現箇所が検索され、必要に応じてラップアラウンドされます。 

重要な点は、すべてのポインター パスを明示的にシミュレートすることはなく、各候補状態から次に必要な文字への可能な限り最良の前方ジャンプのみをシミュレートすることです。
