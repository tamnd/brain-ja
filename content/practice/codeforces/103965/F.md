 ## 解決策
 ## 問題の理解

 一般乗客が満席で出発する 1 両の電車をシミュレートしています。 その後、特権的な乗客が次々と到着し、できるだけ早く座席に座ろうとしますが、一般の乗客が立ち上がることを決定した場合にのみ座席が空くことができます。 

一般の乗客はそれぞれ定期的に行動します。 乗客 i は、ai 分ごとに、ai の倍数の時間で状況を確認します。 少なくとも 1 人の特権乗客が現在立って座席を待っていることを確認すると、すぐに席を永久に譲ります。 一般の乗客が立ち上がると、その座席は永久に空席となり、二度と取り戻すことはできません。 

特権乗客は、一定の減少しない到着瞬間の順序で時間の経過とともに到着します。 特権的な乗客は到着すると、まずすでに空いている座席を占有しようとします。 空席がない場合はお待ちいただくことになります。 重要なのは、後で空いた座席は、先に待っていた特権的な乗客がすぐに座ることができるということです。 

時間は分単位で変化し、各分内での行動の順序は固定されます。特権的な乗客が最初に到着し、次に待っている乗客が現在空いている席に座ろうとし、その後になって初めて、「時間を確認」する一般の乗客が立ち上がって席を解放する可能性があります。 

出力では、各特権乗客に、座ることができた正確な瞬間を尋ねます。 

n、m が 100000 までという制約は、分ごとにシミュレーションするソリューションは不可能であることを意味します。 最大 100,000 人まですべての時間を繰り返し、毎回すべての乗客をチェックするとしても、遅すぎます。 この構造は、一般の乗客はそれぞれ、一度立ち上がると二度と交流することがないため、意味のあるイベントに貢献するのはせいぜい 1 つであることを強く示唆しています。 これにより、一般の乗客ごとに 1 回の起動時間を計算できるようになります。 

わずか 1 分以内の注文では、微妙なケースが発生します。 一般の乗客が立ち上がるのと全く同じタイミングで特権乗客が到着した場合、特権乗客は新たな座席の解放が行われる前に、すでに空いている座席に最初にアクセスできます。 これにより、誰かがすぐに着席するか、後のリリースを待つ必要があるかが変わる可能性があります。 

## アプローチ

 直接シミュレーションでは、毎分処理して n 人全員の一般乗客の状態を更新し、立ち上がるべきかどうかを確認しようとします。 これには、最悪の場合、100,000 までステップアップするたびにすべての乗客をチェックする必要があり、約 10¹⁰ の運行が必要となり、これでは遅すぎます。 

重要な観察は、一般の乗客が状態を変更するのは 1 回だけであるということです。 システムが「アクティブ」になった瞬間、つまり少なくとも 1 人の特権乗客が座席なしで待機しているか存在していることを意味しますが、一般乗客は全員、この状態に初めて気づいた時点で最終的に立ち上がることになります。これは、最初の特権到着時またはその後の最初のチェック時に発生します。 

したがって、プロセス全体は、最初の特権的到着である b1 に等しい単一のグローバルしきい値時間 t0 に短縮されます。 その瞬間から、すべての特権乗客が着席するまで、すべての一般乗客の行動は、t0 の後に次の ai の倍数が発生するかどうかによってのみ決定されます。 各乗客は、少なくとも t0 である最初のチェック時間に、正確に 1 つの座席解放の可能性を提供します。 

したがって、一般乗客 i ごとに、t0 より前の ai の最初の倍数である 1 回の時刻 ti を事前に計算できます。 各 ti は、空席になる座席を表します。

これらの座席解放時間をすべて把握したら、残りの問題はスケジュール設定プロセスになります。 座席解放イベントと特権到着イベントという 2 つのソートされたシーケンスをマージします。 到着時に空席がある場合は、すぐに着席します。 それ以外の場合、乗客は次の座席が解放されるまで待ちます。 座席の解放が発生すると、その座席は最初に待っていた乗客によってすぐに消費されるか、空席のプールに追加されます。

 ## アルゴリズムのチュートリアル

 このプロセスをイベントに変換します。各一般乗客は時間 ti に 1 つの「座席解放イベント」を生成し、各特権乗客は時間 bi に 1 つの「到着イベント」を生成します。 

1. t0 を b1、つまり最も早い特権到着時刻として計算します。 この時点からシステムがアクティブになり、一般の乗客が永久に出発し始める可能性があります。 
2. 各一般乗客 i について、t0 以降の最初のチェック時間を計算します。 これは ti = ceil(t0 / ai) * ai です。 これは、座席が空いた瞬間を表します。 
3. すべての ti 値を収集し、昇順に並べ替えます。 これらは、将来の空席状況を表します。 
4. 特権乗客を到着順に処理しながら、座席解放も時系列順に処理します。 ソートされた ti リスト上のポインタと、到着したがすぐに座ることができずに待機している特権乗客の列とともに、現在存在する空席の数を示すカウンターを維持します。 
5. 時刻 t での到着を処理する場合、最初に時刻 t よりも厳密に短いすべての座席解放を空き座席のプールに挿入します。 次に、空席がある場合は、到着した乗客をすぐに座らせるようにしてください。 そうでない場合は、待機キューに追加します。 
6. 時刻 t におけるすべての到着を処理した後、時刻 t に正確に発生するすべての座席解放を処理します。 座席が解放されるたびに、最も早く待っている特権乗客にすぐに座席を割り当てるか、待っている人がいない場合は空席数を増やします。 
7. 特権乗客に座席が割り当てられたら、その回答として現在時刻を記録します。 

各時間ステップ内の順序付けが重要です。 時刻 t に空いた座席は、その瞬間より前にすでに座席が存在していなければ、時刻 t に到着した乗客は使用できないため、到着は常にリリース前に同時に処理されなければなりません。 

### なぜ効果があるのか

 このプロセスにより、時間 b1 でシステムがアクティブになると、全員が着席するまで常に少なくとも 1 人の特権乗客が待機することが保証されます。 これにより、すべての一般乗客が最終的に「誰かが立っている」という条件が成立する最初のチェック時間に到達することが保証されるため、各乗客は正確に 1 つの決定的な解放時間 ti に寄与します。 この削減後、システムは標準的な 2 ストリーム スケジューリングの問題になり、早い到着が常に遅い到着よりも優先され、座席は区別できないため、時間順に貪欲に割り当てることが最適になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    t0 = b[0]

    releases = []
    for ai in a:
        # first multiple of ai >= t0
        t = ((t0 + ai - 1) // ai) * ai
        releases.append(t)

    releases.sort()

    ans = [-1] * m
    free_seats = 0
    wait = deque()

    i = 0
    j = 0  # pointer over releases

    # We process in time order of events from both lists
    # We'll iterate over arrivals and also inject releases as needed
    for i in range(m):
        t = b[i]

        # process all releases strictly before t
        while j < n and releases[j] < t:
            if wait:
                idx = wait.popleft()
                ans[idx] = releases[j]
            else:
                free_seats += 1
            j += 1

        # arrival at time t
        if free_seats > 0:
            free_seats -= 1
            ans[i] = t
        else:
            wait.append(i)

        # process releases at exactly time t
        while j < n and releases[j] == t:
            if wait:
                idx = wait.popleft()
                ans[idx] = t
            else:
                free_seats += 1
            j += 1

    # remaining releases after last arrival
    while j < n:
        if wait:
            idx = wait.popleft()
            ans[idx] = releases[j]
        else:
            free_seats += 1
        j += 1

    print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、まず各一般乗客を 1 つのリリース タイムスタンプにまとめます。 次に、2 つのポインターを使用して、これらのタイムスタンプを到着シーケンスとマージします。 すぐに座ることができない到着者は順番を守る必要があるため、行列が必要です。 自由席カウンターは、待っている乗客が存在する前に解放が行われた場合に対応します。 

よくある落とし穴は、等しいタイムスタンプを誤って処理することです。 このコードは、リリース前の到着を同時に明示的に処理し、時刻 t に空いた座席が、それ以前にすでに存在していた場合を除き、時刻 t に到着する誰かによって使用されないようにします。

 ## 特殊なケース

 重要なエッジケースは、座席の解放が行われたまさにそのときに特権的な乗客が到着する場合です。 たとえば、時刻 10 に座席が空になり、乗客も時刻 10 に到着した場合、到着者は、同時に解放が処理される前に、既存の空席を確認する必要があります。 これにより、事前に利用可能であるはずの座席を誤ってスキップすることがなくなります。 

もう 1 つの微妙なケースは、複数の一般乗客が同じ解放時間を持っている場合です。 その場合、複数の座席が同時に空席になるため、到着順に待っている乗客に座席を分配する必要があります。 キューにより、一度に複数の座席が現れた場合でも、早く待っている乗客が最初に割り当てられます。 

3 番目のケースは、座席が空いた瞬間に特権乗客が待っていない場合に発生します。 座席は無料プールに蓄積され、失われるのではなく、次の到着までに消費される必要があります。
