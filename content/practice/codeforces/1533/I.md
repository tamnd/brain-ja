 ## 解決策
 ## 問題の理解

 この状況は、2 つの 2 つのノード セット間の 2 層の指向性ルーティング プロセスとして見ることができます。 1 つのセットはサラトフの観光スポットに対応し、もう 1 つのセットはエンゲルスの観光スポットに対応します。 各バス路線は双方向で利用できるという意味で双方向ですが、決定プロセスは方向性があり段階的です。 

すべての観光客はサラトフの光景から始まります。 朝、サラトフの各サイトはエンゲルスのサイトへ向かう橋を 1 つだけ選択し、そのサイトにいる観光客全員がその選択された橋に沿って移動します。 この後、すべての観光客はエンゲルスの観光スポットに分散されます。 夕方になると、エンゲルスの各光景は独立してサラトフに戻る出発橋を 1 つだけ選択し、再びその光景を見るすべての観光客がその選択された橋に沿って一緒に移動します。 

これは、プロセス全体が Saratov ノードから Saratov ノードへの関数を定義することを意味します。各 Saratov ノードは Engels ノードにマップされ、各 Engels ノードは Saratov ノードにマップされます。 これら 2 つの選択肢の構成によって、各観光客が丸 1 日の後にどこに到着するかが決まります。 作成されたマッピングによって開始ノードが自分自身に送り返される場合、旅行者は家に帰ります。 

両方のパーティション内のすべてのノードに対して、どの発信エッジを使用するかを自由に選択できます。 目的は、各観光地から出発した観光客の数で加重して、最終的に元のサラトフの観光地に戻る観光客の数を最小限に抑えることです。 

制約は十分に小さいため、3 次または中程度の 2 次グラフの構築も実行可能です。 各サイドに最大 100 個のノードと最大 10,000 個のエッジがある場合、本当の課題はサイズではなく構造です。 これは、シミュレーションやブルートフォース関数割り当てではなく、マッチング モデルやフロー モデルへの削減を強く示唆しています。 

貪欲なローカル割り当てを試みると、微妙な問題が発生します。エンゲルス ノードがどのように元に戻るかを考慮せずに、単一のサラトフ ノードに最適な発信エッジを選択すると、収益を最小化するのではなく最大化するサイクルを簡単にトラップしてしまう可能性があります。 もう 1 つの障害モードは、2 つの層間の独立性を前提としていますが、実際には 2 番目の層は最初の層によって引き起こされる分布に直接依存します。 

カップリングを示す最小限の例:

 入力:```
2 2 2
5 5
1 1
2 2
```貪欲に 1→1 と 2→2 を両方向にマッピングすると、観光客はすべて戻ってきます。 しかし、慎重にクロスマップすると、構造によってはアイデンティティサイクルを断ち切る可能性があります。 これは、問題がエッジを個別に選択するだけではなく、合成された関数内のサイクルの制御に関するものであることを示しています。 

## アプローチ

 単純なアプローチでは、サラトフ ノードごとにエンゲルスへのブリッジを割り当て、エンゲルス ノードごとにブリッジ バックを割り当てて、合成後にサラトフ ノードが自分自身にマップされる数を計算します。 各ノードには複数の選択肢があるため、割り当てに対する指数関数的な検索になります。 ノードごとの決定的な選択肢に限定したとしても、最大で$n_2^{n_1}$最初の層の可能性と$n_1^{n_2}$2 番目の層については、完全に実行不可能です。 

重要な観察は、Saratov の各ノードが効果的に 1 つの入射エッジを選択し、各 Engels ノードも 1 つの入射エッジを選択し、これらの選択が元の Saratov セット上の有向グラフを定義することです。 観光客は、サラトフからエンゲルスへ、そしてその逆に戻る選択されたエッジの構成がこの誘導マッピングで自己ループを形成する場合に限り、元の場所に戻ります。 

これはマッチング問題に似てきます。できるだけ多くの恒等サイクルの形成を避けるようにエッジのペアを選択したいと考えています。 この構造は、直接の往復ペアリングを「切断」しようとする二部マッチング定式化に変換できます。 

より具体的には、Saratov ノードのペアリングを検討してください。$u$エンゲルスノードを使用した場合$v$。 エッジを選んだ場合$u \to v$最初のフェーズと$v \to u$第 2 段階では、すべての観光客が から始まります。$u$この構成を通過した人は家に帰ります。 したがって、そのような一貫したペアはそれぞれ、コストに寄与する「悪いサイクル」に対応します。$k_u$。 目標は、そのような固定小数点サイクルに参加するノードの重みを最小限に抑える一貫した選択システムを選択することになります。 

さらに再構成すると、あらゆる可能な組み合わせを扱うことができます。$(u, v)$相互マッピングにならないようにする「安全な方向」を形成するための候補として。 最適な構造は、「非帰還構造」を一致可能な構成として解釈する派生グラフで最大の二部一致を見つけることと同等であることが判明し、答えは観光客の総数から帰還サイクルから「保護」できる観光客の最大数を引いたものになります。 

この変換により、サラトフ ノードとエンゲルス ノード間のグラフ上で最大二部マッチング問題が発生します。エッジは安全な転送の可能性を表します。 一致した各エッジは、そのサラトフ ノードに関連付けられたすべての観光客が直接戻ることを効果的に防ぎます。 

したがって、問題は、2 部グラフでの最大一致を計算し、保護されている観光客の数を減算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | 指数 | O(n) | 遅すぎる |
 | 二部マッチングの削減 | O(n₁・n₂・√n) | O(n₁・n₂) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左側のノードがサラトフのサイトを表し、右側のノードがエンゲルスのサイトを表す 2 部グラフを構築します。 間にエッジを追加します$u$そして$v$間にバス路線がある場合。 このグラフは、観光客が 2 つの都市間を移動できるすべての可能な方法をエンコードしています。 
2. このグラフで最大の 2 部マッチングを計算します。 一致した各エッジはペアを表します$(u, v)$ここでは、この接続が折り返しのない構造で使用されるように、観光客を一貫してルーティングできます。 
3. 一致した各サラトフ ノードを、観光客が元の場所に戻ることから「救われる」ノードとして解釈します。 各サラトフノードは最初は貢献するため、$k_u$観光客のために、アイデンティティサイクルを回避する構造に参加するこれらのノードの数を最大化したいと考えています。 
4. 最終的な答えは、観光客の総数から、最適なマッチング構造でマッチングできるサラトフ ノードの数を引いたものです。 

### なぜ効果があるのか

 重要な不変条件は、両側での決定論的な選択の構成が、サラトフ ノード上で互いに素な機能サイクルの集合を引き起こすということです。 長さ 1 の各サイクルは、出発点に戻る観光客に正確に対応します。 このようなサイクルを断ち切るには、対応する二部相互作用の少なくとも 1 つのエンドポイントが相互マッピングで使用されないことが必要です。 最大のマッチングにより、非自明な接続に参加するノードの数が最大化されます。これは、合成関数内の強制セルフマップを最小限に抑えることに対応します。 この構造は、一致するすべてのエッジが潜在的なアイデンティティ固定寄与を 1 つだけ除去することを保証し、最適性はマッチングの最大値から導き出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class HopcroftKarp:
    def __init__(self, n, m):
        self.n = n
        self.m = m
        self.g = [[] for _ in range(n)]
        self.pu = [-1] * n
        self.pv = [-1] * m
        self.dist = [0] * n

    def add_edge(self, u, v):
        self.g[u].append(v)

    def bfs(self):
        q = deque()
        for u in range(self.n):
            if self.pu[u] == -1:
                self.dist[u] = 0
                q.append(u)
            else:
                self.dist[u] = float('inf')

        found = False
        for u in q:
            pass

        while q:
            u = q.popleft()
            for v in self.g[u]:
                if self.pv[v] == -1:
                    found = True
                else:
                    if self.dist[self.pv[v]] == float('inf'):
                        self.dist[self.pv[v]] = self.dist[u] + 1
                        q.append(self.pv[v])

        return found

    def dfs(self, u):
        for v in self.g[u]:
            if self.pv[v] == -1 or (self.dist[self.pv[v]] == self.dist[u] + 1 and self.dfs(self.pv[v])):
                self.pu[u] = v
                self.pv[v] = u
                return True
        self.dist[u] = float('inf')
        return False

    def max_matching(self):
        match = 0
        while self.bfs():
            for u in range(self.n):
                if self.pu[u] == -1:
                    if self.dfs(u):
                        match += 1
        return match

def solve():
    n1, n2, m = map(int, input().split())
    k = list(map(int, input().split()))

    hk = HopcroftKarp(n1, n2)

    for _ in range(m):
        x, y = map(int, input().split())
        hk.add_edge(x - 1, y - 1)

    match = hk.max_matching()

    # unmatched Saratov nodes contribute returns
    print(sum(k) - match)

if __name__ == "__main__":
    solve()
```グラフは 1 辺あたり最大 100 個の頂点を持つ 2 部構成であるため、この実装では Hopcroft-Karp が使用されます。$O(E \sqrt{V})$ソリューションは簡単かつ堅牢です。 各サラトフ ノードは、バス ルート経由で到達可能なすべてのエンゲルス ノードに接続されており、可能な最大のペアリング構造を計算します。 

よくある落とし穴は、インデックスをゼロベースの形式にシフトする必要があることを忘れていることです。 これを怠ると、黙って隣接リストが破損し、一見もっともらしいが不正確な一致が生成されます。 

もう 1 つの微妙な点は、Hopcroft-Karp は正当性に影響を与えることなく隣接リスト内の重複を自然に無視するため、同じノードのペア間の複数のエッジには特別な処理が必要ないことです。

 ## 特殊なケース

 重要なエッジ ケースは、すべての Saratov ノードが 1 つの Engels ノードにのみ接続する場合です。 この状況では、ルートの決定に関係なく、すべての観光客がエンゲルスの 1 つのノードに集約され、帰りのマッピングで激しい競合が発生します。 Hopcroft-Karp はその Engels ノードに 1 つのエッジしか照合できないため、アルゴリズムはこれを処理します。そのため、他のすべてのノードは照合されず、最終的なカウントに寄与します。 

もう 1 つのエッジ ケースは、グラフが同じサイズのパーティション間で完全に 2 部構成になっている場合に発生します。 ここでは、マッチングがすべてのノードを飽和させ、戻ってくる観光客がゼロになります。 このアルゴリズムは、すべてのノードに個別のパートナーがあり、合成された関数内で強制的な自己マッピング サイクルが形成されるのを防ぐため、これを実現します。
