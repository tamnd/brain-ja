 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます。 固定値の場合$k$、2 つの文字数のうち少なくとも 1 つが小さい場合、部分文字列は有効であると見なされます。$k$ゼロまたは最大$k$もの。 

タスクは、元の文字列を最小数の連続する有効な部分に分割することです。 すべての場合にその最小値を計算する必要があります$k$から$1$に$n$、 どこ$n$文字列の長さです。 

届く長さは$2 \cdot 10^5$。 すべてを処理するあらゆるソリューション$k$独立して$O(n)$時間はすでにかかっています$O(n^2)$、それは限界をはるかに超えています。 総作業量は次の値に近づく必要があります。$O(n \log n)$。 

微妙な点は、有効性は長さに基づいていないことです。 1 つの文字が十分にまれである場合は、長いセグメントでも有効である可能性があります。 たとえば、$k=1$、セグメント`0000001`は 1 つだけ含まれているため有効です`1`。 

もう 1 つの簡単な間違いは、1 カウントを超えたらすぐにカットしてしまうことです。$k$。 セグメントは両方のカウントが超過した場合にのみ無効になります。$k$。 のために$k=2$、文字列`00011`は 2 つしかないため、まだ有効です。 

3 番目のトラップは、最大有効拡張子を計算するときに表示されます。 仮定する$k=1$現在のセグメントは先頭から始まります`00100010`。 最長の有効なプレフィックスは、制限を超える最初のシンボルによって決まりません。 1 つの文字タイプがすでに超過している可能性があります$k$、一方、もう一方は依然として制限内に留まり、セグメントの続行が可能になります。 

## アプローチ

 ブルートフォースソリューションでは、次の値が固定されます。$k$、すべての有効なセグメント境界を計算し、動的プログラミングまたは貪欲なパーティショニングを実行します。 これをなんとかしたとしても$O(n)$一人の時間$k$、それを全員に繰り返します$n$値が与える$O(n^2)$、 だいたい$4 \cdot 10^{10}$最悪の場合の運用。 

重要な観察点は、開始位置が固定されている場合です。$i$、最長の有効なセグメントは、0 と 1 の出現位置を使用して記述することができます。 

させて：

-$p_0$の立場になる$(k+1)$-st 以降に発生するゼロ$i$。 
-$p_1$の立場になる$(k+1)$-st 以降に発生するもの$i$。 

セグメントは、少なくとも 1 つのカウントが最大でもまだ有効である限り有効です。$k$。 

その前に止めたら$p_0$の場合、セグメントには最大でも以下が含まれます$k$ゼロ。 

その前に止めたら$p_1$の場合、セグメントには最大でも以下が含まれます$k$もの。 

したがって、最も長い有効なセグメントは、両方の条件が失敗する直前に終了します。 次の開始位置は$$\text{next}(i)=\max(p_0,p_1).$$このジャンプ関数がわかれば、最適なパーティションは貪欲になります。常に最長の有効なセグメントを取得します。 最初のセグメントが短いと、将来のオプションが減るだけです。 

残りの課題は、すべての答えを計算することです$k$。 

小型用$k$、くらいしかありません。$\sqrt n$異なる価値観。 すべての位置に対してジャンプ関数を明示的に構築し、動的プログラミングで答えを計算できます。 

大型用$k$、各セグメントは長いため、回答に含まれるセグメントはほとんどありません。 貪欲なプロセスを直接シミュレートできます。 大規模なすべての費用の合計$k$は調和系列になります。

 ## アルゴリズムのチュートリアル

 1. すべて 0 とすべて 1 の位置を保存します。 
2. インデックスごとに$i$、次を計算します。 

- 前にゼロが何個現れるか$i$、
 - 前に何個表示されますか$i$。 

これらのランクにより、次の項目に直接ジャンプできます。$(k+1)$-st 以降のいずれかの文字の出現$i$。 
3. しきい値を選択します$B \approx \sqrt n$。 
4. あらゆる人にとって$k \le B$:

 コンピューティング$$\text{next}[i] = \max( \text{pos0}[r_0(i)+k], \text{pos1}[r_1(i)+k] ),$$存在しない出現は位置として扱われます$n+1$。 
5. 同じように$k$、計算する$$dp[i]=1+dp[\text{next}[i]]$$右から左へ。 

ここ$dp[i]$で始まるサフィックスをカバーするために必要なセグメントの最小数です。$i$。 
6.ストア$dp[1]$これに対する答えとして$k$。 
7. あらゆる人にとって$k>B$、貪欲パーティションを直接シミュレートします。 

位置から開始$1$。 

繰り返しジャンプする$$\max( \text{pos0}[r_0(i)+k], \text{pos1}[r_1(i)+k] )$$ポジションが決まるまで$n+1$。 
8. ジャンプが何回行われたかを数えます。 その数がこれの答えです$k$。 

### なぜ効果があるのか

 で始まるセグメントの場合$i$、無効になる唯一の方法は、それ以上のものが含まれている場合です。$k$ゼロ以上$k$同時に。 

ゼロカウントを超えた最初の瞬間$k$です$(k+1)$-st ゼロ以降$i$。 ワンカウントを超えた最初の瞬間$k$です$(k+1)$-次から 1 つ後$i$。 

両方の位置に到達する前に、少なくとも 1 つの文字数がまだ制限内にあります。 2 つの位置のうち大きい方に到達した後は、両方の制限を超えています。 これにより、最長有効セグメントが一意に決定されます。 

すべての有効なパーティションはこの時点までに最初のセグメントを終了する必要があるため、最も長い有効なセグメントを貪欲に取得することが最適です。 最初のセグメントを可能な限り延長しても、以降の部分の数は決して増加しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pos0 = [0]
    pos1 = [0]

    for i, c in enumerate(s, 1):
        if c == '0':
            pos0.append(i)
        else:
            pos1.append(i)

    zcnt = len(pos0) - 1
    ocnt = len(pos1) - 1

    pos0.extend([n + 1] * (n + 2))
    pos1.extend([n + 1] * (n + 2))

    r0 = [0] * (n + 2)
    r1 = [0] * (n + 2)

    z = o = 0
    for i in range(1, n + 1):
        r0[i] = z
        r1[i] = o
        if s[i - 1] == '0':
            z += 1
        else:
            o += 1

    r0[n + 1] = z
    r1[n + 1] = o

    B = int(n ** 0.5) + 1
    ans = [0] * (n + 1)

    nxt = [0] * (n + 2)
    dp = [0] * (n + 2)

    for k in range(1, min(B, n) + 1):
        for i in range(1, n + 1):
            p0 = pos0[r0[i] + k + 1]
            p1 = pos1[r1[i] + k + 1]
            nxt[i] = max(p0, p1)

        dp[n + 1] = 0
        for i in range(n, 0, -1):
            dp[i] = 1 + dp[nxt[i]]

        ans[k] = dp[1]

    for k in range(B + 1, n + 1):
        cur = 1
        cnt = 0

        while cur <= n:
            p0 = pos0[r0[cur] + k + 1]
            p1 = pos1[r1[cur] + k + 1]
            cur = max(p0, p1)
            cnt += 1

        ans[k] = cnt

    print(*ans[1:])

solve()
```配列`r0`そして`r1`店舗出現ランク。 位置の場合`i`がセグメントの始まりである場合、`r0[i] + k + 1`ゼロカウントを超える最初のゼロを指します`k`。 同じ考え方が 1 にも当てはまります。 

小さい値の場合`k`では、ジャンプ グラフを明示的に構築し、1 次元 DP を使用してセグメントの最小数を計算します。 すべてのジャンプは厳密に右に移動するため、DP は右から左に評価されます。 

大きな値の場合、`k`、答えは小さいです。 貪欲なジャンプをシミュレートすると、完全な DP テーブルを構築するよりもコストが安くなります。 

最も一般的な 1 つ違いの間違いは、オカレンスの検索です。 私たちに必要なのは、$(k+1)$-st 開始位置の後に出現します。これは、以下に対応します。`rank + k + 1`。
