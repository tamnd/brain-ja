 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれのテスト ケースは個別の整数のソートされた配列で構成されます。 これらの数値を数直線上の不動点として考えてください。 質問点$y$が選択され、関数は配列内の最も近い点を返します。$y$絶対距離に基づいて。 

一意の最近接点がある場合、関数は通常どおりに動作します。 It fails only when$y$は 2 つの異なる配列値から正確に等距離にあります。これは、有効な答えが 2 つあり、結合が定義されていないためです。 

したがって、タスクはクエリをシミュレートすることではありません。 代わりに、整数が存在するかどうかを判断する必要があります。$y$これは、2 つの配列要素間の「タイ位置」に正確に配置されます。 

入力サイズが大きい: すべてのテスト ケースの要素の合計数が次の値に達します。$2 \cdot 10^5$、テスト ケースごとに二次関数を除外します。 すべての候補クエリ ポイントを試したり、値の間のすべての整数の位置をチェックしたりするソリューションは、数値間のギャップが最大で$10^9$、列挙が不可能になります。 

よくある間違いは、関係に隣接しない要素が含まれる可能性があると想定することです。 たとえば、ある点が次の点に等しく近い可能性があると考えるかもしれません。$x_i$そして$x_j$たとえその間に値があるとしても。 中間点は常に内部値の 1 つに近いため、このようなことは起こり得ません。 もう一つの微妙な間違いは、それを忘れていることです$y$整数でなければなりません。 整数ではない中点は、たとえ幾何学的に中心にあったとしても、有効なクラッシュを生成しません。 

## アプローチ

 ブルートフォースのアイデアは、配列要素の最小値と最大値の間のすべての整数値を反復処理し、それぞれの要素に対して$y$、最も近い配列点を計算します。 2 点が同点の場合は成功と宣言します。 これは論理的には正しいですが、まったく実行不可能です。 到達できる値の範囲は、$10^9$そのため、1 つのテスト ケースでも数十億のチェックが必要になる可能性があります。 

重要な観察は、引き分けは非常に構造化された状況でのみ起こり得るということです。 任意の 2 つの隣接する要素について$x_i$そして$x_{i+1}$に近い点のセット$x_i$は中間点の左側にあり、セットはそれに近い$x_{i+1}$右側にあります。 同点はちょうど中間点で起こります。 

整数のみを考慮しているため、$y$、この中間点は整数でなければなりません。これは次の場合にのみ発生します。$x_i + x_{i+1}$は均等です。 これにより、問題全体が、隣接するペアに均等な差があるかどうかを確認することに集約されます。 

これにより、幾何学的検索のように見えたものが、隣接する差異に対する単純なスキャンに変換されます。

 ## アルゴリズムのチュートリアル

 問題を、ソートされた配列内の隣接するペアをチェックすることに集約します。 

1. すでにソートされており重複を含まない点の配列を読み取ります。 この順序により、隣接する候補間で同順位が必ず発生することが保証されます。 
2. 隣接するペアごとに$(x_i, x_{i+1})$、差を計算します$d = x_{i+1} - x_i$。 
3. もし$d$が偶数であれば、整数の中点が存在することがすぐにわかります。$y = \frac{x_i + x_{i+1}}{2}$。 この値では、両方のエンドポイントが同じ距離にあるため、クラッシュが保証されます。 
4. 偶数の差を持つ隣接ペアがない場合は、配列内のどこにも整数の中点が存在しないため、同点になる可能性はないと結論付けます。 
5. すべてのテスト ケースに対してこのプロセスを個別に繰り返します。 

重要な決定点はステップ 3 です。これは、算術構造を数直線上の幾何学的対称性に直接結び付けるためです。 

### なぜ効果があるのか

 任意の点$y$は、連続する要素間の垂直二等分線で囲まれた数直線の連続領域に最も近いです。 これらの境界は、隣接するペアの中点に正確に発生します。 配列はソートされているため、曖昧な領域はすべて近傍によってのみ定義され、中間点によって支配されずにそれ以上のペアは競合できません。 したがって、有効なクラッシュ ポイントの存在は、隣接するペア間の整数の中点の存在と同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    x = list(map(int, input().split()))
    
    ok = False
    for i in range(n - 1):
        if (x[i + 1] - x[i]) % 2 == 0:
            ok = True
            break
    
    print("YES" if ok else "NO")
```この実装は、隣接する差異のみが重要であるという観察に直接従っています。 有効なペアが見つかると、ループは早期に停止します。これは、大きな配列に初期の均等なギャップが含まれる場合、効率にとって重要です。 

微妙な点は、合計ではなく差を計算することです。 どちらもパリティとしては同等ですが、Python が大きな整数を安全に処理する場合でも、減算により大きな中間値に関する懸念が回避されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = stdin.readline

            if (x[i + 1] - x[i]) % 2 == 0:
                ok = True
                break
        out.append("YES" if ok else "NO")
    return "\n".join(out)

 ## 特殊なケース

 サイズ 2 の配列の場合、決定全体は単一のパリティ チェックに集約されます。 2 つの値が奇数だけ異なる場合、ちょうど中間に位置する整数はないため、クラッシュの可能性はありません。 差が偶数の場合、中点は整数となり、常にあいまいさが生じます。 

大規模な疎配列の場合も、中間点が隣接ベースのボロノイ境界に影響を与えないため、同じロジックが依然として当てはまります。 値が大きく離れている場合でも、重要なのは距離の同等性のみであり、大きさは関係ありません。 

等差数列のような均一な間隔を持つシーケンスの場合、答えはステップ サイズに完全に依存します。 ステップが偶数の場合、隣接するすべてのペアが有効な中間点を生成し、クラッシュが発生します。 ステップが奇数の場合、中間点は整数ではないため、関数は全体を通じて安全なままになります。
