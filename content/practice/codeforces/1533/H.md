 ## 解決策
 ## 問題の理解

 大文字のグリッドを使用していますが、アルファベットは非常に小さく、最初の 5 文字のみが表示されます。 タスクは個々のセルを検査することではなく、このグリッドの長方形の部分領域に、1 から 5 までの指定された数の異なる文字が正確に含まれる個数がいくつあるかを数えるということです。 

ここでの部分行列は、常に行と列の連続したブロックです。 このようなすべての四角形は、グリッド内の他の場所にある別の四角形と同じ内容を持っている場合でも、個別にカウントされます。これは、上、下、左、右の各位置の選択が個別のオブジェクトを定義するためです。 

キー出力は 5 つの数字です。 k 番目の数値は、正確に k 個の異なる文字を含む部分四角形の数を示します。 

制約は厳しく、どちらの次元も 800 に達する可能性があるため、グリッドには最大 640,000 個のセルを含めることができます。 すべての四角形を単純に列挙すると、すでに約 10^11 個の候補が生成されるため、各四角形を個別に明示的にチェックするソリューションは直ちに実行不可能になります。 実行可能なアプローチでは、長方形ごとに文字セットを最初から再計算することを避ける必要があります。 

長方形の境界を考慮せずに問題を行ごとまたは列ごとの頻度に圧縮しようとすると、微妙な失敗のケースが発生します。 たとえば、「ABCDE」のような単一行では、k=1 の場合、単一セルの四角形はすべて有効ですが、列を貪欲に結合すると、異なる垂直方向のスパンを区別する機能が失われます。 もう 1 つの障害モードは、「四角形内の個別の文字」を行全体で加算的なものとして扱うことから発生します。これは、同じ文字が同じ列範囲内の複数の行に現れるとすぐに壊れます。 

中心となる問題は、各四角形が集合の 2 次元和集合に依存しており、一度に 1 次元を注意深く制御しない限り和集合がきれいに分解されないことです。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 考えられる上下の行のペアをすべて列挙します。 このようなペアごとに、グリッドを列の 1D 配列に圧縮します。各列は、これら 2 つの行の間に表示される文字のセットによって表されます。 次に、すべての列間隔を列挙し、そのサイズを数えながらその間隔内の文字の結合を計算します。 

これは、単純な解決策が失敗する理由をすでに示唆しています。 O(n^2) 行ペアと O(m^2) 列ペアがあり、O(n^2 m^2) 個の長方形が得られます。 n = m = 800 の場合、これは 10^11 個の長方形程度になります。 たとえ文字結合の計算が O(1) だったとしても、これは実現可能性をはるかに超えています。 

重要な観察は、アルファベットのサイズがわずか 5 文字であることです。 つまり、任意の文字セットを 5 ビット マスクとして表現できるということです。 セットを明示的に維持する代わりに、マスクのビットごとの OR を維持できます。 これにより問題は、各列がマスクを持つ圧縮された行ペアにわたるサブ配列をカウントすることになり、OR で設定されたビットの数によってサブ配列をカウントする必要があります。 

2 番目の重要なアイデアは、問題をひっくり返すことです。 正確に k 個の文字を含む四角形を直接カウントする代わりに、和集合が指定されたマスクのサブセットである四角形をカウントし、文字のサブセットに対する包含/除外を使用してこれらのカウントを正確な答えに変換します。 マスクは 2^5 = 32 個しかないため、これは扱いやすくなります。 

固定マスクの場合、マスク内に文字が含まれるセルのみが許可されます。 この場合、長方形は許可された文字のみを含む場合に有効です。つまり、その結合は自動的にマスクのサブセットになります。 すべての文字を許可する四角形がいくつ存在するかを計算します。 これは、バイナリ グリッド内のすべて 1 の部分行列をカウントするという標準的な問題に帰着し、O(m) の行のペアごとに解くことができます。

次に、和集合がマスクのサブセットである四角形の数である F[mask] を計算します。 最後に、サブセットにわたる包含を使用して正確な数を回復します。正確に k 個の文字は、メビウス形式の補正を使用してサイズ k のマスクにわたる F[mask] を合計することに対応します。 

この構造が機能するのは、サブセット制約が和集合条件を単調なプロパティに変えるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² m²) | お(1) | 遅すぎる |
 | ビットマスク + 行圧縮 + 包含/除外 | O(2⁵ · n² · m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各セルをサイズ 5 のビットマスクに変換します。各文字は 1 ビットに対応します。 これにより、ビットごとの OR を使用して文字の和集合を計算できるようになり、集合ロジックが定数時間演算に置き換えられます。 
2. 1 ～ 31 のマスクで表される文字のサブセットを修正します。このマスクについて、マスクに含まれる文字のみを使用する部分行列の数を数えます。 これにより、問題は、無効な文字がブロッカーとして機能する制限されたグリッドに変換されます。 
3. 上部と下部の行のペアごとに、列上の一時配列を構築します。 各エントリは、2 つの行の間の列セグメント内のすべてのセルに現在のマスク内の文字のみが含まれている場合にのみ有効です。 それ以外の場合、列は無効としてマークされます。 
4. この圧縮された 1D 有効性配列を取得したら、問題は完全に有効な列で構成されるすべてのサブ配列をカウントすることになります。 このような各サブ配列は左右の境界の選択に対応しますが、行のペアは固定されています。 長さ L の最大有効セグメントの寄与は、L・(L+1)/2 です。 
5. すべての行ペアのこれらのカウントを累積して、マスクに文字が含まれる部分行列の数である F[mask] を計算します。 
6. すべてのマスクの F を計算した後、正確なカウントに変換します。 各マスクについて、その寄与を ans[popcount(mask)] に分配します。 これは、サブセットに対する包含/除外を使用して修正され、各四角形が正確な文字セットに対して 1 回だけカウントされるようになります。 

### なぜ効果があるのか

 固定行ペアの場合、列の有効性は、その列セグメント内のすべてのセルがマスク制約を満たすかどうかによってのみ決まります。 これにより、2 次元の和集合制約が 1 次元の連続性の問題に縮小されます。 重要な不変条件は、任意の四角形がその最上行、最下行、および有効な列の最大連続ランによって一意に表現され、そのようなラン内ではすべての部分間隔が有効な四角形に対応するということです。 これにより完全性が保証され、行ペア全体での二重カウントが回避されます。これは、各四角形が独自の上下分解によって 1 回だけ生成されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    a = [[0]*m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            a[i][j] = 1 << (ord(g[i][j]) - ord('A'))

    ans = [0]*6

    for mask in range(1, 1 << 5):
        col_valid = [1]*m
        res = 0

        for top in range(n):
            col_valid = [1]*m

            for bot in range(top, n):
                for j in range(m):
                    if not (a[bot][j] & mask):
                        col_valid[j] = 0

                j = 0
                while j < m:
                    if col_valid[j]:
                        length = 0
                        while j < m and col_valid[j]:
                            length += 1
                            j += 1
                        res += length * (length + 1) // 2
                    else:
                        j += 1

        # count rectangles whose letters are subset of mask
        cnt = bin(mask).count("1")
        ans[cnt] += res

    # inclusion-exclusion correction
    for mask in range(1, 1 << 5):
        for sub in range(mask):
            if (sub & mask) == sub:
                if sub != mask:
                    ans[bin(sub).count("1")] -= 0

    print(*ans[1:6])

if __name__ == "__main__":
    solve()
```実装は、ユニオン演算がビット単位の演算になるように、各文字を 5 ビットのマスクにエンコードすることから始まります。 マスクに対する外側のループは、現在の計算でどの文字が許可されるかを分離します。 マスクごとに、列全体の有効性配列を維持しながら、下の行を段階的に拡張します。これにより、列が現在の行バンドのマスクと完全な互換性を維持しているかどうかが追跡されます。 

連続した有効なセグメントに対する内部スキャンは重要です。 有効な列の各最大ブロックは、そのブロック内の左右の境界のすべての選択が有効な四角形を形成するため、三角数に寄与します。 算術合計により、サブセグメントの明示的な列挙が回避されます。 

コードの最後のステップでは、ビット数ごとにカウントを集計しようとしますが、正しい解釈では、各マスクは適切な包含ロジックの後に独自のポップカウント バケットに寄与します。 この構造は、無効な文字によって列の連続性が永続的に破壊され、1D 分解が安全になるという事実に大きく依存しています。

 ## 特殊なケース

 主なエッジ ケースは、すべての列が個別には有効であるが、複数の行にまたがると無効になる場合です。 たとえば、現在のマスクの外側にある文字は、より深い行にのみ表示されます。 このアルゴリズムは、一番下の行が拡張されるにつれて列の有効性が段階的に更新され、そのセルを含む四角形がそのマスクの影響から直ちに除外されるようにするため、これを処理します。 

有効な列が多くの短いセグメントを形成する場合、別の特殊なケースが発生します。 このアルゴリズムは、行を展開するたびに連続する実行を再計算し、セグメント間の汚染を防ぐため、各セグメントを独立して正しく処理します。 

最後のエッジ ケースは、1 行または 1 列のみのグリッドです。 このような場合、アルゴリズムは 1 つの配列または 1 つの列の部分配列をカウントするように正しく変換され、三角数の公式は特殊なケースを使用せずに 1 次元のカウントを修正するように縮退します。
