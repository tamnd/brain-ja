 ## 解決策
 ## 問題の理解

 私たちには、バイオームの「タイプ」の小さなグリッドが与えられます。各タイプは、固定されたパラメータからのパラメータのペアによって識別されます。$n \times m$テーブル。 これらのペアの一部は存在し、一意の整数識別子が割り当てられていますが、その他のペアは使用できません。 私たちのタスクは、これらの識別子で構成される長方形のマップを構築することです。 

マップは任意ではありません。 存在するすべての識別子は、出力グリッドに少なくとも 1 回出現する必要があります。 2 つのセルが 1 つの側面を共有する場合、それらのバイオームの対応するパラメーター ペアは、マンハッタン距離だけ異なる必要があります。$(temperature, humidity)$飛行機。 言い換えれば、最終的なグリッド内の隣接するバイオームは、グリッド内の隣接するセルに対応する必要があります。$n \times m$パラメータグリッド。 

出力形状にも制約があります。構築されたマップの高さと幅の両方が、利用可能なバイオームの数を超えてはなりません。$k$。 以来$n, m \le 10$、利用可能なバイオームの総数は少なく、問題の構造は、本質的にグラフをグリッドに埋め込んでいることを示唆しています。 

主な困難は、任意の値を割り当てるように求められるのではなく、すべてのノードが少なくとも 1 回は使用されるようにしながら、隣接関係の制約を正確に保持するように求められることです。 

利用可能なバイオームが切断されたグラフを形成する場合、微妙な失敗のケースが発生します。 たとえば、2 つのバイオームが存在するがパラメーター グリッド内で隣接していない場合、出力での隣接性にはパラメーター空間での隣接性が必要であるため、有効なマップ内でそれらを隣り合わせに配置する方法はありません。 欠落したノードは使用できないため、欠落したノードでそれらを「ブリッジ」しようとしても不可能です。 

別の失敗ケースは、グラフが接続されているが、必要な次元のグリッド埋め込みとの 2 部互換性がない場合に発生します。 狭いグリッドに折りたたもうとすると、サイクルまたは隣接の不一致が強制される可能性があります。 両方の次元が最大であるという制約$k$ハミルトニアンのような走査が存在する場合、それをルーティングするための十分な余地があることを保証します。 

実際のタスクは、利用可能なセルの誘導グラフが、隣接制約を尊重しながらすべての頂点を訪問するパス状の走査をサポートしているかどうかを判断し、そのような走査をグリッド内に構築することになります。 

## アプローチ

 強引なアイデアは、すべてを配置しようとすることです。$k$バイオームを最大でも一定のサイズのグリッドに分割する$k \times k$、各セルにバイオームを割り当て、隣接制約を確認します。 グリッド構成の数が指数関数的に増加するため、これはすぐに手に負えなくなります。$k^{k^2}$、隣接制約による枝刈りでも、巨大な検索スペースが残ります。 難しいのは配置だけではなく、誘導された隣接関係が元のグラフと正確に一致するように強制することです。 

重要な観察は、グリッド自体は幾何学的には重要ではないということです。 重要なのは、元のノードで連続する要素が隣接するようにすべてのノードのシーケンスを作成することです。$n \times m$グリッド。 このようなシーケンスを取得したら、それを行ごとに、寸法が範囲内のグリッドに配置するだけです。 

これにより、問題は、4 方向に隣接する有効なセルの間にエッジが存在する、使用可能なセルによって形成されたグラフ内のハミルトニアン パスを見つけるという問題に軽減されます。 以来$n, m \le 10$、グラフはバックトラッキングを使用して DFS ベースの構築を試みるのに十分小さいですが、意図した解決策はより単純です。制約によって接続されたパスカバー可能な構造が強制されるため、有効な答えが存在する場合、単純な DFS 順序付けが機能することが構造によって保証されます。 

有効なバイオームから開始して DFS トラバーサルを構築し、未訪問の隣接するバイオームに常に移動するように試みます。 これにより、スパニング ツリーの走査順序が生成されます。 次に、すべてのノードが正確に 1 回アクセスされたかどうかを検証します。 そうでない場合は、有効な埋め込みが存在しません。 

ご注文をいただいたら、両方の寸法が以下のグリッドに再形成できるかどうかを確認します。$k$。 以来$k$はノードの数です。いつでも選択できます$h=1, w=k$必要に応じて、一方向の隣接関係は自明に満たされます。 

したがって、問題は接続の確認と DFS 順序の作成に帰着します。

 ## アルゴリズムのチュートリアル

 利用可能な各バイオームセルをモデル化します$(i, j)$グラフ内のノードとして$a_{i,j} \neq 0$、4 方向に隣接する有効セルへのエッジを持ちます。 

1. すべての有効なノードを識別し、その識別子と座標を保存します。 これにより、グラフの頂点のセットが得られます。 
2. エッジを明示的に保存するのではなく、グリッドの近隣を使用して暗黙的に隣接関係を構築します。 これにより、不必要なオーバーヘッドが回避されます。 
3. 任意の有効なノードから DFS を開始します。 DFS 中に、ノードを訪問済みとしてマークし、その識別子を順序付けリストに追加します。 私たちは常に、まだ訪れていない隣人を最初に探索します。 
4. DFS が完了したら、訪問したノードの数が次と等しいかどうかを確認します。$k$。 そうでない場合、グラフは切断されており、有効な構造は存在しません。 
5. 有効な場合は、次のサイズの単一行グリッドを出力します。$1 \times k$DFS注文を使用します。 

常に 1 つの行を出力できる理由は、出力の隣接性には水平方向の隣接行の正確性のみが必要であるためです。 DFS では、順序付けされた連続する要素が元のグラフで隣接していることが保証されるため、要素を線形に配置すると、必要な隣接制約がすべて保持されます。 

### なぜ効果があるのか

 DFS オーダーは、すべてのステップが有効な隣接エッジに沿って移動するトラバーサルを形成します。 各ノードは 1 回だけ訪問されるため、シーケンス内の連続する要素がマンハッタン距離条件を満たすことが保証されます。 このシーケンスを 1 つの行にマッピングすると、必要に応じて隣接関係が正確に保持され、出力グリッドの垂直方向の隣接関係によって新たな競合が発生しないため、追加の制約に違反することはありません。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = []
    nodes = []
    pos = {}

    for i in range(n):
        row = list(map(int, input().split()))
        grid.append(row)
        for j, v in enumerate(row):
            if v != 0:
                nodes.append((i, j, v))
                pos[(i, j)] = v

    k = len(nodes)
    if k < 2:
        print(-1)
        return

    visited = set()
    order = []

    dirs = [(1,0),(-1,0),(0,1),(0,-1)]

    def dfs(x, y):
        visited.add((x, y))
        order.append(grid[x][y])
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if (nx, ny) in pos and (nx, ny) not in visited:
                dfs(nx, ny)

    sx, sy, _ = nodes[0]
    dfs(sx, sy)

    if len(order) != k:
        print(-1)
        return

    print(1, k)
    print(*order)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この解決策は、すべての有効なバイオーム セルを抽出し、それらをグラフ ノードとして割り当てることから始まります。 次に、グリッド隣接上で DFS を実行し、有効なバイオーム位置のみを通過するようにします。 

訪問済みセットはノードを再訪問しないことを保証し、順序リストは走査シーケンスを記録します。 正確かどうかは、DFS が到達可能なすべてのノードを訪問するかどうかにかかっています。 そうでない場合、グラフは切断され、有効な線形埋め込みを形成できません。 

最後に、走査を単一行グリッドとして出力します。 これにより、隣接関係の制約を尊重しながら、複雑な 2D 埋め込みロジックの必要性が回避されます。 

微妙な点は、複数行のグリッドを構築しようとしていないことです。 この問題ではそれが可能ですが、隣接条件はグローバル ジオメトリではなく隣接するセルのみを制約するため、有効なソリューションはすべて 1 次元にフラット化できます。

 ## 特殊なケース

 重要なエッジケースは、有効なバイオームが存在するが 4 接続されていない場合に発生します。 このような状況では、DFS は 1 つのコンポーネントのみを探索し、順序の長さの最終チェックは失敗します。 たとえば、斜めに配置されたバイオームが 2 つだけ存在する場合、許可された移動によってそれらを接続することはできないため、トラバースは存在せず、出力は正しく -1 になります。 

もう 1 つのエッジ ケースは、グリッドにちょうど 2 つの隣接するノードがある場合です。 DFS は両方を訪問し、長さ 2 の次数を生成し、アルゴリズムは 1×2 グリッドを出力します。 両方の要素が唯一の行で連続しているため、これは隣接要件を満たします。 

最後のエッジケースは、グリッドが完全に接続されている場合に発生します。 DFS はすべてのノードを訪問し、順序付けは自然にセット全体に及びます。 すべての隣接エッジがシーケンスの少なくとも 1 つの方向で保存されるため、平坦化は引き続き有効です。
