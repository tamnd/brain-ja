 ## 解決策
 ## 問題の理解

 ヴィカは決まった日にバータウンに到着します$k$。 彼女には何人かの友人がおり、各友人は、連続して 1 日の間、自宅に泊めてもらえると申し出てくれます。 制約は、彼女が選択できる友人は最大 1 人であり、一度選択すると、その友人が許可した間隔内にのみ留まることができるということです。 ただし、彼女は必ずしもその間隔の開始時に到着するとは限らないため、実際の滞在は 1 日より早く開始する必要があります。$k$。 

選択した友人に対して間隔をあけて$[l_i, r_i]$、ヴィカは日中からしか滞在できません$k$今日まで$r_i$、ただし、$k$その隙間の中にあります。 つまり、彼女の有効滞在日数は$r_i - k + 1$ただし、次の場合に限ります。$l_i \le k \le r_i$。 間隔が含まれていない場合は、$k$、彼女はまったく滞在できません。 

このタスクは、次の内容を含むすべての間隔をチェックすることになります。$k$そして一番右に伸びているものを見つけます。 

制約は小さいです。$t \le 500$、$n \le 100$これにより、複雑な前処理や高度なデータ構造の必要性が即座に排除されます。 テスト ケースごとに単純なリニア スキャンで十分です。 

間隔が含まれない場合、微妙なエッジ ケースが表示されます。$k$。 たとえば、次の場合$k = 4$そしてすべての間隔は次のようになります$[1,2]$、$[5,6]$、その場合、どの友人も開始が早すぎるか、遅すぎるかのどちらかです。 その場合、ヴィカは 1 日でも滞在できないため、答えは正確に 0 でなければなりません。 

もう 1 つのエッジ ケースは、複数の間隔に次のものが含まれる場合です。$k$。 例えば、$k = 3$、および間隔$[1,4]$、$[2,6]$、 そして$[3,3]$。 不用意にアプローチすると、最も近い開始間隔が選択される可能性があります。$k$、しかしそれは関係ありません。 正しい選択は、右端点が最大になる間隔です。 

## アプローチ

 強引な解釈では、Vika の選択を明示的にシミュレートします。友人ごとに、$k$は彼らの間隔にあり、彼女がその友人を選択した場合に滞在できる日数を計算し、最大値を取得します。 これはすでに実行されています$O(n)$各間隔が 1 回チェックされるため、テスト ケースごとに実行されます。 

決定は間隔間の重複に依存しないため、ここにはより深い組み合わせ構造はありません。 友達はそれぞれ独立しています。その日に Vika をホストすることができます。$k$あるいはできない。 有効な間隔をフィルタリングすると、最適な選択は最大の正しいエンドポイントによってのみ決定されます。 

より複雑な「最適化」では、ソートやスイープが試行される可能性がありますが、複雑さは改善されずに不必要なオーバーヘッドが追加されます。 重要な観察は、重要な唯一の制約は、$k$にある$[l_i, r_i]$、それらの間隔のうち、最大化$r_i$滞在期間を直接最大化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての間隔をチェック) |$O(n)$テストケースごと |$O(1)$| 承認済み |
 | 最適 (同じ考え方、ダイレクトスキャン) |$O(n)$テストケースごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$、友達の数とヴィカの到着日を定義します。 目標は、この固定基準点に対してすべての間隔を評価することです。$k$。 
2. 回答変数を 0 として初期化します。これは、Vika がこれまで滞在できる最適な日数を表します。 0 から開始すると、有効な間隔が存在しない場合も当然処理されます。 
3. 各友達の間隔で繰り返します$[l_i, r_i]$。 各間隔について、まず日が含まれているかどうかを確認します$k$、 意味$l_i \le k \le r_i$。 この条件により、Vika は到着日から実際に滞在を開始できるようになります。 
4. 間隔が有効な場合、潜在的な滞在期間を次のように計算します。$r_i - k + 1$。 これは日中からの滞在を反映しています$k$その間隔内の利用可能な最後の日まで。 
5. 現在の値の最大値と計算された滞在長で回答を更新します。 これにより、すべての有効な友人の中から常に最良の選択を維持できるようになります。 
6. すべての間隔を処理した後、保存されている最大値を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、Vika が選択した友人の間隔を早くも遅くも離れることがないという事実に基づいています。 彼女の滞​​在は、開始日以降の間隔の正しい境界によって完全に決定されます$k$固定されています。 すべての有効な間隔が独立した候補の回答に寄与します$r_i - k + 1$、無効な間隔は何も寄与しません。 決定空間は独立した値に対する単純な最大値であるため、すべての間隔をスキャンすると、隠れた相互作用を見逃すことなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    n, k = map(int, input().split())
    best = 0

    for _ in range(n):
        l, r = map(int, input().split())
        if l <= k <= r:
            best = max(best, r - k + 1)

    out.append(str(best))

print("\n".join(out))
```このソリューションは、テスト ケースごとに単一の実行最大値を維持します。 条件`l <= k <= r`使用可能な間隔のみをフィルタリングして、無効な滞在を決して計算しないようにします。 表現`r - k + 1`到着から出発までの日数も含めて正しくカウントされます。 

出力はバッファリングされ、テスト ケース間で繰り返される I/O オーバーヘッドを回避します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, k = map(int, input().split())
        best = 0
        for _ in range(n):
            l, r = map(int, input().split())
            if l <= k <= r:
                best = max(best, r - k + 1)
        out.append(str(best))

    return "\n".join(out)

 ## 特殊なケース

 区間を含まない場合$k$の場合、スキャンでは最初の応答 0 が更新されることはありません。たとえば、次のようになります。$k = 7$、間隔$[1,3]$そして$[8,10]$どちらも満たさないため、両方とも無効です$l \le k \le r$。 アルゴリズムは正しく答えを 0 のままにし、それを直接出力します。 

複数の間隔が含まれる場合$k$、正しいエンドポイントのみが重要です。 たとえば、$k = 3$、間隔$[1,4]$、$[2,6]$、 そして$[3,3]$、アルゴリズムは候補値を評価します$2$、$4$、 そして$1$。 最大値は 4 です。$[2,6]$。 選択プロセスは、間隔がどこまで左から始まるかには依存せず、間隔がどこまで右に広がるかのみに依存します。$k$。
