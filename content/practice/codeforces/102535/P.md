 ## 解決策
 ## 問題の理解

 タスクは、数字かどうかを判断することです。`k`基地と特別な関係がある`b`。 値を書くことを想像してください`0*k, 1*k, 2*k, ..., (b-1)*k`基地内で`b`、1 桁だけが残るまで、繰り返し桁の合計を減らします。 結果として得られる`b`数字には可能なすべての基数が含まれている必要があります。`b`ペアが有効であるとみなされるためには、正確に 1 回数字を入力します。 

入力には最大で次のものが含まれます`100000`独立したペア。 両方の値`k`そして`b`到達できる`10^15`なので、次の倍数ごとにプロセスをシミュレートします。`0`に`b-1`不可能です。 1 つのテスト ケースでも、`10^15`一方、時間制限により、入力全体でおよそ数百万回の単純な操作しか許可されません。 ソリューションはサイズに応じて回避する必要があります`b`そして問題を少量の算術に縮小します。 

よくある間違いは、デジタル ルートを直接生成しようとすることです。 もう一つの間違いは、数字を忘れることです。`0`他の数字とは動作が異なります。 たとえば、入力```
1
3 4
```ベースがある`4`、したがって、必要なシーケンスは次のようになります。`0, 3, 6, 9`。 4 進数のデジタル ルートは次のとおりです。`0, 3, 2, 1`、これは次の順列です。`0,1,2,3`、したがって、答えは次のとおりです`COOL`。 デジタルルートを単純に扱うソリューション`x mod (b-1)`間違って回転してしまう`3`の中へ`0`なぜなら`3 mod 3 = 0`。 

もう 1 つのエッジケースは次のような場合です`k`～と因子を共有する`b-1`。 例えば：```
1
2 7
```ここ`b-1 = 6`。 を乗算して生成される剰余`2`モジュロ`6`は`2,4,0,2,4,0`したがって、いくつかのデジタルルートが繰り返され、一部の数字は表示されません。 正しい答えは、`NOT COOL`。 

可能な限り小さなベースにも注意が必要です。 と：```
1
1 2
```唯一の値は`0`そして`1`、そしてそれらはデジタルルートを生成します`0`そして`1`。 答えは`COOL`。 一般式で処理する必要があります`b-1 = 1`正しく。 

## アプローチ

 直接的なアプローチは、すべての値のデジタル ルートを計算することです。`i*k`のために`0 <= i < b`、表示された数字を保存し、すべての数字が 1 回出現するかどうかを確認します。 クールなペアの定義はまさにこれらのペアに関するものであるため、これは正しいです。`b`生成された値。 ただし、最悪の場合、これは実行されます`b`各テストケースの反復。 以来`b`できる`10^15`そしてそれがあるかもしれません`10^5`テストケース、操作数が到達可能`10^20`、それは限界をはるかに超えています。 

重要な観察は、デジタル ルートの数学的形式から得られます。 基地内`b`、桁の合計はモジュロ値を保持します。`b-1`、 なぜなら`b`に等しい`1`モジュロ`b-1`。 数字の合計を繰り返すと、同じ剰余が維持されます。 唯一の特殊なケースは、剰余が 0 の正の数がデジタル根を持つことです。`b-1`の代わりに`0`。 

させて`m = b-1`。 私たちが重視する値は次のとおりです。`0*k, 1*k, ..., m*k`。 

最初の値は常にデジタルルートを与えます`0`。 残りの値については、次の値を掛けるかどうかが問題になります。`k`モジュロ`m`可能なすべての残余を正確に 1 回生成します。 乗算`k`剰余の剰余の置換です`m`まさにいつ`k`そして`m`は互いに素である。 

もし`gcd(k, b-1) = 1`、すべての剰余モジュロ`b-1`の倍数のうち 1 回出現する`k`。 残留物`0`複数から来ます`(b-1)k`、デジタルルートを生成します`b-1`, 一方、他の残基は残りの数字を生成します。 gcd が 1 より大きい場合、いくつかの残基が衝突するため、配列は順列になることはできません。

 ## アルゴリズムのチュートリアル

 1. コンピューティング`m = b - 1`。 デジタル ルート全体の動作は、この数値を法とする値にのみ依存します。 
2. コンピューティング`gcd(k, m)`。 どちらの数値も非常に大きくなる可能性がありますが、含まれるビット数は約 50 ビットのみであるため、ユークリッド アルゴリズムで十分です。 
3. gcd が`1`、出力`COOL`。 それ以外の場合は出力`NOT COOL`。 

この 1 つの gcd チェックで十分である理由は、`k`モジュロ`m`すべての残基を 1 回だけ訪問するか、以前の残基を繰り返します。 中間ケースはありません。 

なぜ効果があるのか:

 数字を考慮してください`k, 2k, ..., (b-1)k`モジュロ`b-1`。 もし`k`逆モジュロを持っています`b-1`、その逆数を乗算すると、生成されたすべての剰余が一意の乗数に戻されるため、すべての剰余が 1 回だけ表示されます。 これはまさに gcd が次の場合に発生します。`1`。 

gcd がそうでない場合`1`、によって共有される自明ではない約数が存在します。`k`そして`b-1`。 乗算`k`次に、異なる乗算器が同じ剰余モジュロを生成するように強制します。`b-1`したがって、デジタルルートにはすべての数字を一度だけ含めることはできません。 gcd 条件は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        k, b = map(int, input().split())
        if math.gcd(k, b - 1) == 1:
            ans.append("COOL")
        else:
            ans.append("NOT COOL")
    print("\n".join(ans))

import math
solve()
```このソリューションでは、2 つの入力値と現在の gcd 結果のみが保持されます。 値`b - 1`係数はすべてのデジタル ルートを制御するため、一度計算されます。 

Python の整数はオーバーフローしませんが、重要な実装の詳細は依然として乗算を完全に回避することです。 ブルートフォースのアイデアには次のような値が必要です`i*k`、これらは不必要であり、ランタイムを不可能にします。 ユークリッド アルゴリズムは、元の数値に直接作用します。 

特別な場合`b = 2`自動的に処理されます。 その場合`b - 1`等しい`1`、すべての整数は互いに素です`1`なので、ベースとのすべてのペア`2`正しく分類されるのは`COOL`。

 ## 特殊なケース

 この場合の場合:```
1
3 4
```アルゴリズムが計算します`b-1 = 3`その後`gcd(3,3) = 3`、これは示唆するでしょう`NOT COOL`gcd ルールに基づいて。 ただし、この例は、倍数が`0,3,6,9`、ベースのデジタルルーツ`4`は`0,3,2,1`、これは順列です。 最初の乗数の範囲を注意深くチェックする必要があるため、前のショートカットは失敗します。乗数は次のとおりです。`0`を通して`b-1`、ゼロ以外の部分には以下が含まれます`b-1`価値観。 のために`b=4`、必要な条件はまだです`gcd(k,b-1)=1`場合のみ`k`モジュロとみなされます`b-1`、しかしここでは`k=3`与える`gcd(3,3) != 1`。 矛盾は、配列に反復残基があるという事実から生じます。`0`ゼロ以外の乗数の間で、その剰余は次のようにマッピングされます。`b-1`他の値は残りの桁をカバーします。 これは、証明に特別な剰余処理を含める必要がある理由を示しています。 

実際の正しい条件は次のとおりです。 

のために`m = b-1`、乗算器からの値`1`を通して`m`デジタルルートを生成する必要がある`1`を通して`m`。 残留物`0`は 1 回だけ出現する必要があり、非ゼロ残基も 1 回だけ出現する必要があります。 これはまさに次のようなときに起こります。`gcd(k,m)=1`そうでない場合は、非ゼロ残基をすべて区別することができないためです。 ケース`k=3, b=4`もっている`m=3`, なので条件によってはカッコ良くありません。 実際のデジタル ルートは次のとおりです。 

| 乗数 | 値 | 残りのmod 3 | デジタルルート |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 3 | 0 | 3 |
 | 2 | 6 | 0 | 3 |
 | 3 | 9 | 0 | 3 |

 正しい出力は次のとおりです。```
NOT COOL
```このケースは、小さな例を手動で計算する実装を捕捉しますが、剰余ゼロを持つすべての正の倍数が同じ桁にマッピングされることを忘れています。`b-1`。 

のために：```
1
1 2
```アルゴリズムが計算します`b-1 = 1`。 gcd は`gcd(1,1)=1`、したがって、それは返されます`COOL`。 生成される唯一のデジタル ルートは、`0`そして`1`、これは基数で考えられるすべての数字です`2`。 

のために：```
1
2 7
```アルゴリズムが計算します`b-1 = 6`そして`gcd(2,6)=2`。 gcd は 1 より大きいため、次の値を掛けます。`2`モジュロ`6`すべての残基を作成することはできません。 出力は`NOT COOL`、繰り返される残基パターンと一致します。

```このアルゴリズムは、膨大な倍数のシーケンスを構築することはありません。 2 つの大きな整数に対して Euclid のアルゴリズムのみを実行し、それらが互いに素であることを検出して、次の値を返します。`COOL`。 これにより、解が基数の大きさではなく算術サイズに依存することが検証されます。
