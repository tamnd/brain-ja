 ## 解決策
 ## 問題の理解

 対戦相手の列はバイナリ文字列として見ることができます。`O`現在活動中のムックを意味し、`E`敗北したミークを意味します。 キムがアクティブなムックに到達するたびに 1 分が経過し、その位置は`E`、および反転する前のすべての位置`O`。 Reversinator を使用すると、戦闘が始まる前に最初の行の連続する部分を 1 つだけ反転できます。 ラインをクリアするのに必要な合計分数ができるだけ少なくなるように、反転を選択する必要があります。 

重要な観察は、戦闘プロセスが恣意的なシミュレーションではないということです。 一番左のキャラクターの重みを 1、次のキャラクターの重みを 2、その次のキャラクターの重みを 4 というように割り当てると、1 回の戦闘操作はこの 2 進数から 1 を減算することとまったく同じになります。 一番左の`O`最下位設定ビットのように機能します。これは 0 になり、より小さいビットはすべて 1 になります。 戦闘の合計数は、この 2 進数の値になります。 

入力には最大 35,000 個の文字列が含まれますが、その合計の長さはわずか 500,000 です。部分文字列には約 n² 個の選択肢がある可能性があるため、これにより、考えられるすべての反転の試行が除外されます。 文字列で表される数値は指数関数的に大きくなる可能性があるため、選択肢ごとに戦闘プロセスをシミュレートするソリューションですら不可能です。 各テストケースに対して線形または線形に近いアプローチが必要です。 

よくある間違いは、文字列を元の左から右の順序で最適化することです。 重みは右に向かって大きくなるため、元の文字列の右側が最も大きな影響を受けます。 もう 1 つの間違いは、反転を 1 回使用する必要があることを忘れていることです。 長さ 1 のセグメントが許可されます。これは、文字列を変更しないことを意味します。 

たとえば、入力の場合`E`、ムックはないので答えは です。`0`。 有益な逆転を常に探す方法は、変化があるに違いないと仮定することで失敗する可能性があります。 入力用`O`、答えは`1`、1回の戦いが必要であり、逆転することはできないためです。 入力用`EOOE`、元の値は`6`ですが、最良のセグメントを逆にすると、`EEOO`、その値は`3`。 元の順序を最も重要な側として扱う方法では、誤った選択が発生します。 

## アプローチ

 直接的なアプローチは、可能なすべての間隔を試し、それを逆にして、結果のバイナリ値を計算し、最小値を維持することです。 O(n²) 個の間隔があります。 たとえ区間の反転と評価が O(1) に最適化されたとしても、候補の数は n = 500000 に対してすでに多すぎます。総当たりは、Reversinator のあらゆる可能な使用をチェックするため正しいですが、検索スペースが問題です。 

便利な変換は、2 進数を通常の表記で見ることです。 元の文字列を反転します。 この逆の表現では、最初の文字が最上位ビットになります。 元の文字列のセグメントを反転しても、この新しい文字列のセグメントを反転するだけです。 タスクは、1 つの部分文字列反転によって取得できる辞書編集上最小のバイナリ文字列を見つけることになります。 

バイナリ文字列の場合、可能な限り最良の反転を特徴付けるのは簡単です。 最初の文字列の後にゼロがない場合、文字列はすでに可能な限り小さくなっています。 それ以外の場合は、最初の位置に次の値が含まれます。`1`を受け取る必要があります`0`、そこでゼロを移動する唯一の方法は、最後のゼロまで反転することです。 終了が小さい場合は、最初に変更された順位が悪化し、開始が早まると、先頭は変わらないままになります。`1`。 

この反転の後は、結果として得られる 2 進数のモジュロを評価するだけで済みます。`10^9`。

 ## アルゴリズムのチュートリアル

 1. 入力文字列を反転します。 これにより、通常の辞書編集上の比較が戦闘数の数値比較と一致するように表現が変更されます。 
2. 最初に出現するものを見つけます。`1`逆文字列で。 これは、おそらく数を減らすことができる最初の場所です。 
3. 最後に出現したものを検索します。`0`逆文字列で。 これは、最も早い有用な位置に移動できる最も遠いゼロです。 
4. 最初の場合`1`最後の前に登場する`0`、その間隔を逆にします。 これにより、改善できる最初の重要な位置にゼロが配置されます。 
5. 結果のバイナリ文字列を数値の剰余に変換します。`10^9`左から右にスキャンして、現在の値を繰り返し 2 倍にします。 

機能する理由: 反転された文字列は通常のバイナリ表現であるため、辞書順に小さくすることは、戦闘カウントを小さくすることとまったく同じです。 最初の異なるビットが結果を決定します。 反転では、1 つ以上の 0 を横切って 0 を左に移動することによってのみ文字列を改善できます。 最も早いものとそれに続く最新のゼロは、最初の異なるポジションで最大限の改善をもたらし、その後の反転により残りの順序が自動的に修正されます。 そのようなペアが存在しない場合は、可能なすべての反転によって最初の有効ビットが変更されないまま維持されるか、ビットが大きくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9

def solve_case(s):
    s = s[::-1]

    first_one = -1
    last_zero = -1

    for i, c in enumerate(s):
        if c == '1' and first_one == -1:
            first_one = i
        if c == '0':
            last_zero = i

    if first_one != -1 and last_zero > first_one:
        s = s[:first_one] + s[first_one:last_zero + 1][::-1] + s[last_zero + 1:]

    ans = 0
    for c in s:
        ans = (ans * 2 + (c == '1')) % MOD
    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(str(solve_case(s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```最初の変身は、`s[::-1]`、中心的な単純化です。 それは、異常な戦闘プロセスを通常の二項演算に変えます。 

の検索`first_one`そして`last_zero`1回のスキャンで完了します。 もし`first_one`以前ではありません`last_zero`、より重要な位置へのゼロの有用な移動がないため、文字列は変更されないままになります。 

スライス反転は一度だけ適用されるので安全です。 最後のループでは、バイナリ文字列で表される巨大な整数が構築されることはありません。 剰余モジュロのみを保持します`10^9`、これはオーバーフローを回避し、最大長に対して機能します。 

## 実用的な例

 のために`EOOE`、反転した表現は次のように始まります。`EOOE`。 

| 文字列の状態 | 初め`1`| 最後`0`| アクション | 値 |
 | --- | --- | --- | --- | --- |
 | えおえ | 1 | 3 | 位置 1 ～ 3 を反転 | えええ |
 | えええ | - | - | バイナリ値を変換する | 3 |

 反転すると、最後のゼロが最も重要な位置に移動します。 これは、文字列の元の方向が誤解を招く理由を示しています。 

のために`OOE`、反転した表現は次のようになります。`EOO`。 

| 文字列の状態 | 初め`1`| 最後`0`| アクション | 値 |
 | --- | --- | --- | --- | --- |
 | えお | 1 | 2 | 位置 1 ～ 2 を反転 | えお |
 | えお | - | - | バイナリ値を変換する | 3 |

 ここでは、影響を受ける 2 つのビットが両方ともすでに最良の順序になっているため、反転しても値は改善されません。 このアルゴリズムでは、強制的な逆転が目に見える影響を及ぼさないように正しく許可されています。

 ## 特殊なケース

 のために`E`、反転された文字列には何も含まれていません`1`、 それで`first_one`未設定のままです。 アルゴリズムは反転をスキップしてゼロ値を評価し、`0`。 

のために`O`、があります。`1`でもいいえ`0`, したがって、より小さなビットを前に移動する方法はありません。 アルゴリズムは文字列を変更せずに値を返します。`1`。 

のために`EOOE`、元々の戦闘数は最小限ではありません。 文字列を反転した後、`EOOE`、アルゴリズムは最初の`1`インデックス 1 と最後`0`インデックス 3 でその部分を反転し、次を取得します。`EEOO`。 バイナリ値は次のようになります`3`、最適な結果と一致します。 

のみを含む入力の場合`O`キャラクターなど`OOOOOOOOOO`、可能なすべての反転で同じ文字列が生成されます。 このアルゴリズムはゼロの欠如を検出し、不必要な操作を行わずにバイナリ値を直接計算します。
