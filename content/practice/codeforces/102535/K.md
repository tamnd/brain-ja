 ## 解決策
 ## 問題の理解

 敵の列は長さの配列として見ることができます`n`。 各ポジションはアクティブな敵であり、次のように記述されます。`MOOK`、または非アクティブな敵、と書かれます。`MEEK`。 キムは常に左端から開始し、最初のアクティブな敵に到達するまで歩きます。 その敵を倒すには 1 分かかり、その後その陣地は非アクティブになり、再びアクティブになるまでにすべての非アクティブな陣地が無効になります。 

タスクは、すべてのポジションが次のポジションになるまでの合計分数を計算することです。`MEEK`。 

という点では制約は小さい`n`、 と`n`最大でも 50 ですが、最大 10,000 までの多くのテスト ケースが存在する可能性があります。 操作の数は指数関数的に増加する可能性があるため、操作の数に比例して時間がかかるシミュレーションでも危険が伴う可能性があります。`n`。 50 桁のラインは、およその値を表すことができます。`2^50`、したがって、文字通りすべての戦いを実行するアプローチは完了できません。 解決策は、戦闘をシミュレートするのではなく、数学的パターンを見つける必要があります。 

厄介なケースは、戦列が戦闘のたびに単純に敵を 1 人失うわけではないという事実から生じます。 たとえば、すでに非アクティブなポジションが再びアクティブになる可能性があります。 

考慮する：```
1
MOOK
```答えは`1`。 初期数のみをカウントするソリューション`MOOK`ここでは位置は機能しますが、敵が戻ってくる可能性があるため、より大きな場合には失敗します。 

別の例は次のとおりです。```
3
MOOK
MEEK
MEEK
```答えもまた、`1`。 最初の陣地を倒した後は、アクティブな敵は残りません。 あらゆるオリジナルを期待する無頓着なシミュレーション`MEEK`何らかの作業が必要な場合は過大評価になります。 

より明らかな例は次のとおりです。```
3
MEEK
MOOK
MEEK
```答えは`2`。 最初の戦いでは行が次のように変更されます。```
MOOK
MEEK
MEEK
```2戦目で終わります。 中央の敵が前面の敵を再出現させました。これが問題の中心的な動作です。 

## アプローチ

 直接的な解決策は、現在の配列を保持し、最初の配列を見つけます。`MOOK`に変更します。`MEEK`、前のすべてを回す`MEEK`に位置する`MOOK`、配列にのみが含まれるまで繰り返します。`MEEK`。 これはまさにプロセスに従っているので、正しいです。 

問題は繰り返しの回数です。 このプロセスは実際には 2 進数でカウントダウンされるため、戦闘の数は次のように大きくなる可能性があります。`2^n - 1`。 と`n = 50`、最悪の場合、1,000 兆回を超える操作が必要になります。 非常に効率的なシミュレーションでもこれを処理することはできません。 

有益な観察は、各位置が 2 進数とまったく同じように動作するということです。 させて`MOOK`代表する`1`そして`MEEK`代表する`0`。 最初の位置は最下位ビットです。 キムが最初の試合を破ったとき`MOOK`、彼女は最初のものを見つけます`1`をビットして、次のように変更します。`0`、すべて以前のものですが`0`ビットになる`1`。 これは、まさに 2 進数から 1 を引く仕組みです。 

たとえば、州```
MOOK
MEEK
MOOK
```2進数を表します`101`左側を最下位ビットとして読み取った場合。 その値は次のとおりです。```
1 * 2^0 + 0 * 2^1 + 1 * 2^2 = 5
```このプロセスでは、ゼロに達するまでに 5 回の戦闘が実行されます。 

全体の問題は、最初の配置を左端の位置に重みがある 2 進数に変換することに帰着します。`2^0`、その値を出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 行を左から右に読み、すべての行を処理します。`MOOK`2進数として`1`そしてすべての`MEEK`2進数として`0`。 

一番左の敵は、キムが最初に倒すことができる位置であるため、最下位ビットです。 
2. ラインをスキャンしている間、現在のバイナリ値を維持します。 インデックスの位置の場合`i`、 追加`2^i`が含まれている場合`MOOK`。 

アクティブな各敵は、バイナリの重みで表される戦闘数に正確に貢献します。 
3. 累積値を出力します。 

到達できる値は`2^50 - 1`、これは Python の整数型内に快適に収まります。 

なぜ効果があるのか:

 不変条件は、現在の敵陣がプロセスが終了するまでにまだ必要な戦闘数を表すということです。 1 回の戦闘では、バイナリ表現から 1 を減算する正確な変換が実行されます。ここで、左端の位置が最下位ビットになります。 2 進数がゼロに達するとプロセスが停止するため、開始時の 2 進数は正確に必要な戦闘数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        value = 0

        for i in range(n):
            s = input().strip()
            if s == "MOOK":
                value += 1 << i

        ans.append(str(value))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```プログラムは各テスト ケースを独立して処理します。 変数`value`線で表される 2 進数を格納します。 

シフト操作は`1 << i`ポジションの重みが生まれます。 最初の入力行にはインデックスがあるので、`0`コードでは、最初の敵が貢献します`2^0`、最初の敵がキムが到達できる最初の敵であるプロセスと一致します。 

このソリューションは戦闘を決してシミュレートしないため、指数関数的な状態変化を回避します。 Python の整数は、可能な最大値が以下であるため、オーバーフローの問題も回避します。`2^50`。

 ## 特殊なケース

 入力の場合:```
1
MOOK
```アルゴリズムは唯一の位置に次の重みを割り当てます。`2^0`、与える`1`。 これは必要な単一の戦いに一致します。 

入力の場合:```
3
MOOK
MEEK
MEEK
```アルゴリズムは非アクティブな位置を無視して戻ります。`1`。 上位 2 進ビットが設定されていないため、プロセスは最初の敗北の直後に終了します。 

入力の場合:```
3
MEEK
MOOK
MEEK
```2位が貢献する`2^1`、与える`2`。 最初の戦いで最初のポジションが有効になり、2 番目の戦いでそれが削除されます。 これにより、最初は非アクティブな位置が単なる空のスペースではなく、値がゼロの 2 進数であることが確認されます。 

最大で 50 個の位置がすべて揃っている場合`MOOK`、答えは次のとおりです。```
1 + 2 + 4 + ... + 2^49 = 2^50 - 1
```アルゴリズムは、個々の戦闘を実行せずにこれを直接処理します。
