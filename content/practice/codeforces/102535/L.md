 ## 解決策
 # 問題の理解

 対戦相手の列はバイナリ配列として見ることができます。 ムックというのは、`1`なぜなら、それでも戦いが必要であり、MEEKは`0`キムは無料でそこを通過するからです。 戦闘が始まる前に、2 つの位置を正確に交換することができます`k`回。 目標は、すべての MOOK をクリアするのに必要な分数ができるだけ少なくなるようにラインを配置することです。 

戦闘プロセスには、隠されたバイナリ カウンタ構造があります。 ポジションを付けるとしたら`i`値`2^(i-1)`すべての MOOK ポジションの値を合計すると、1 回の戦いでは常にこの合計が 1 だけ減少します。 最初のMOOKはから変わります`1`に`0`、前のゼロはすべて 1 になります。これはまさに 2 進数のデクリメントです。 このため、最終的な答えは、スワップ後のバイナリ配列で表される数値になります。 

入力により、ラインの長さ、正確なスワップ数、および各ポジションの現在の状態が得られます。 出力は、これらのスワップを実行した後の可能な最小のバイナリ値です。`10^9`。 

制約`n <= 100000`が主な難点です。 戦闘プロセスのシミュレーションには最大で 3 分かかります。`2^n`minutes, which is impossible. 考えられるすべてのスワップの選択肢を試しても、可能なペアの数は 2 次であり、スワップのシーケンスは指数関数的に増加するため、2 秒の制限が許容するものをはるかに超えています。 ソリューションでは、一定の回数だけ行を検査する必要があるため、`O(n)`アプローチ。 

単純なソリューションを壊すいくつかのエッジケースがあります。 MOOK がない場合、答えは常にゼロです。 例えば：```
2 5
MEEK
MEEK
```正しい出力は次のとおりです`0`。 常に MOOK を移動させようとする方法では、少なくとも 1 つの戦闘が存在すると誤って想定する可能性があります。 

2 番目のトラップは、スワップを正確に使用する必要があるという要件です。`k`回。 例えば：```
2 1
MOOK
MEEK
```唯一のスワップによって状態は次のように変化します。`MEEK, MOOK`、価値を与える`2`。 完全に最適化された配置に到達しようとするだけのソリューションでは、誤った出力が発生します。`1`。 

最後の特殊なケースは、タイプの異なる 2 人の対戦相手です。 無意味な追加操作として交換できる同等の要素はありません。 例えば：```
2 2
MEEK
MOOK
```2 回のスワップの後、配列は初期状態に戻るので、答えは次のようになります。`2`、ソートされた値ではありません`1`。 

## アプローチ

 直接的なアプローチでは、スワップのあらゆる選択肢をシミュレートします。 スワップのシーケンスごとに、結果として得られるバイナリ値を計算し、最小値を保持することができます。 これは、あらゆる法的な最終取り決めを考慮しているため、正しいです。 ただし、1 つのスワップでも、`O(n^2)`を選択し、これを最大まで繰り返します`n`スワップは不可能な検索空間を与えます。 

より良い出発点は、スワップによって何が改善されるかを理解することです。 同じ数の MOOK を持つ最小のバイナリ値は、すべての MOOK を行の先頭に置くことによって取得されます。これは、前の位置ほど 2 の累乗が小さくなるためです。 例えば、MOOKが3冊ある場合、理想的な形は、`111000...`。 

MEEK を含む最初のブロック内のすべての位置は間違いです。 右の MOOK と交換すると、まさにそのような間違いが 1 つ修正されます。 改善を最大限に高めるには、ブロックの外側の左端の間違った位置と右端の MOOK を使用する必要があります。 

残る難点は「まさに」という言葉です。 ミスの数よりも少ないスワップが必要な場合は、すべてのスワップが役立つはずです。 ソートされた取り決めに達するのに十分なスワップがある場合、唯一の問題は、残りのスワップを無駄にできるかどうかです。 1 つの MOOK と 1 つの MEEK を含む長さ 2 の行を除くすべての場合において、同等の対戦相手間で、または以前のスワップを取り消すことによって、追加のスワップを行うことができます。 可能な操作は 2 つの位置を繰り返し交換することだけであるため、例外的なケースは個別に処理できます。

 ## アルゴリズムのチュートリアル

 1. 行を MOOK が存在するバイナリ配列に変換します。`1`そしてMEEKは`0`。 MOOKの数を数えて、それを呼び出します`m`。 可能な限り最良の最終配置では、ポジションに配置されます`1`を通して`m`。 
2. 特殊なケースに対処する`n = 2`ちょうど 1 つの MOOK と 1 つの MEEK が含まれます。 すべてのスワップでは 2 つの要素が交換されるため、パリティのみが得られます。`k`重要です。 偶数回の交換では元の状態が復元され、奇数回では 2 つの位置が交換されます。 
3. 最初の内部の間違ったゼロ位置をすべて見つけます。`m`位置と最初の後のすべての 1 つの位置`m`ポジション。 これらは、有用なスワップによって価値が向上する可能性があるポジションです。 
4. 以下の場合`k`間違いが存在する場合は、すべての間違いを修正するスワップを使用してください。 残りのスワップは、配置に影響を与えることなく無駄にできるため、最終的なバイナリ値を変更する必要はありません。 
5. もし`k`間違いの数より小さいので、正確に実行してください`k`便利な交換品。 最小の不正確な位置と、ターゲット プレフィックス外の最大の MOOK 位置を組み合わせます。 これにより、バイナリ値が最大限に削減されます。 
6. を追加して、結果のバイナリ値を計算します。`2^i`残りのMOOKポジションごとに。 答えはモジュロで計算されます`10^9`。 

なぜ効果があるのか:

 バイナリ値の解釈は、戦闘プロセスを単純な数値問題に変換します。 戦闘時間を最小化することは、スワップ後のバイナリ値を最小化することと同じです。 有用なスワップはすべて、`1`前の位置に移動し、`0`後の位置へ。 最も古い利用可能なゼロと最も新しい利用可能なゼロを組み合わせると、そのスワップの最大の減少が生じます。 考えられるすべての間違いが修正されると、その配置はすでに可能な最小の配置となり、別個に処理される 2 つの要素の混合ケースを除いて、残りの交換は無効化できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9

def solve_case(n, k, arr):
    ones = sum(arr)

    if ones == 0:
        return 0

    if n == 2 and ones == 1:
        if k % 2 == 1:
            return (2 if arr[0] == 1 else 1)
        return (1 if arr[0] == 1 else 2)

    bad = []
    extra = []

    for i in range(ones):
        if arr[i] == 0:
            bad.append(i)

    for i in range(ones, n):
        if arr[i] == 1:
            extra.append(i)

    use = min(k, len(bad))

    extra.sort(reverse=True)

    for i in range(use):
        a = bad[i]
        b = extra[i]
        arr[a], arr[b] = arr[b], arr[a]

    ans = 0
    power = 1
    for x in arr:
        if x == 1:
            ans += power
            if ans >= MOD:
                ans -= MOD
        power = (power * 2) % MOD

    return ans % MOD

def main():
    n, k = map(int, input().split())
    arr = []
    for _ in range(n):
        arr.append(1 if input().strip() == "MOOK" else 0)

    print(solve_case(n, k, arr))

if __name__ == "__main__":
    main()
```このコードは、ターゲットのプレフィックス長を決定するため、最初に MOOK の数をカウントします。 変更が必要な位置を直接見つけることができるため、ターゲット配置は個別に保存されません。 

の`bad`配列には、最適なプレフィックスに MOOK を含める必要がある MEEK 位置が格納されます。 の`extra`配列には、現在そのプレフィックスの外にある MOOK が格納されます。 これら 2 つのグループを交換すると、考えられる最も価値のある変更が最初に実行されます。 

特殊な 2 要素のケースは、グリーディ スワップの前に処理されます。 これにより、余分なスワップは常に無視できると想定するという間違いを避けることができます。 より大きな配列の場合、最終的なバイナリ値を変更せずに、余分なスワップを吸収できます。 

最後のループでは、2 のべき乗を使用して 2 進数を評価します。`10^9`。 Python の整数はオーバーフローしませんが、累算中にモジュラスを取得すると、計算が小さく保たれ、必要な出力が反映されます。

 ## 特殊なケース

 MOOK の数が 0 であるため、all-MEEK のケースが処理されます。そのため、バイナリ値は 0 であり、スワップによって MOOK を作成することはできません。 

正確なスワップ条件は、2 要素の混合ケースによって処理されます。 のために：```
2 2
MEEK
MOOK
```最初のスワップによって作成される`MOOK, MEEK`、そして 2 番目のスワップは に戻ります。`MEEK, MOOK`。 このアルゴリズムは偶数のスワップを検出し、元の値を返します。 

有用なスワップが 1 つだけ利用可能なサンプルの場合:```
3 1
MEEK
MOOK
MEEK
```最初の位置はターゲット MOOK プレフィックス内にあり、現在間違っています。 アルゴリズムはそれをプレフィックスの外側にある唯一の MOOK と交換し、`MOOK, MEEK, MEEK`、その値は`1`。 

以下の場合については、`k`が間違いの数より大きい場合、最適な配置に達すると、アルゴリズムは値を変更するスワップを停止します。 すでに処理されている 2 要素混合ラインを除いて、同等の対戦相手のペアが少なくとも 1 組存在するため、残りの交換は無害に行うことができます。
