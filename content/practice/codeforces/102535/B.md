 ## 解決策
 ## 問題の理解

 キー番号のコレクションとロック番号のコレクションがあります。 キーは 2 つの数字が隣接している場合にのみロックを開きます。つまり、絶対的な差がちょうど 1 であることを意味します。 このタスクは、指定されたロックのうち、使用可能なキーが少なくとも 1 つあるロックの数を数えるというものです。 

入力は、ペリーが所有するキーとアクティブな日に表示されるロックを説明します。 最初の部分は個別のキー番号を示し、2 番目の部分は個別のロック番号を示します。 出力は、使用可能なキーで開けることができるロックの数です。 

値は 104 に制限されていますが、キーとロックの量はそれぞれ 104 に達する可能性があります。これは、すべてのキーをすべてのロックに対してチェックするソリューションでは、最悪の場合、最大 10^8 の比較が実行されることを意味します。 これは一部の言語では許容される値の限界に近いですが、数値の範囲が小さく、キーとロックの関係が非常に単純な構造であるため、ここでは必要ありません。 直線的なアプローチは簡単に十分に高速です。 

主なエッジ ケースは、番号範囲の端にあることや、ロックには一致するキーが 1 つだけ必要であることを忘れていることが原因で発生します。 たとえば、次の入力を使用すると、```
1
1
1
1
```答えは`0`。 差が 1 ではなく 0 であるため、番号 1 のキーはロック 1 を開けることができません。 

別の境界ケースは次のとおりです。```
1
1
1
2
```答えは`1`。 唯一のキーはロックからちょうど 1 つ離れたところにあるので、機能します。 ロックの前の番号をチェックするだけの実装は、ここで失敗します。 

同様の上限のケースは次のとおりです。```
1
104
1
103
```答えは`1`。 キー 104 はロック 103 を開くことができるため、範囲内の最後の値は他のすべての値と同じように動作します。 

## アプローチ

 直接的な解決策は、すべてのロックを調べて、すべてのキーと比較することです。 特定のロックについて、いずれかのキーの差がちょうど 1 であれば、そのロックは答えに 1 を与えます。 このメソッドは有効なキーの定義に直接従うため、正しいです。 ただし、10^4 キーと 10^4 ロックを使用すると、約 10^8 チェックを実行できるため、必要以上に手間がかかります。 

問題の構造から、より簡単な観察が得られます。 番号 x のロックは、キー x - 1 および x + 1 によってのみ開くことができます。すべてのキーを検索する必要はありません。 代わりに、使用可能なキーをセットに保存し、2 つの定数時間メンバーシップ クエリを実行することで各ロックをチェックできます。 

ブルートフォース手法は、考えられるすべてのキーとロックのペアを探索するため機能しますが、それらのペアのほとんどすべてが無関係であるため失敗します。 各ロックには有効なキーが 2 つしかないという観察により、問題は一連の単純な検索に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(kL) | お(1) | 最大の入力に対して遅すぎる |
 | 最適 | O(k + L) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのキー番号を読み取り、セットに保存します。 このセットを使用すると、コレクション全体をスキャンせずに、特定のキーが存在するかどうかを問い合わせることができます。 
2. すべてのロック番号 x について、キー セットに x - 1 が存在するか、またはキー セットに x + 1 が存在するかを確認します。 このロックを開けることができる鍵はこれら 2 つだけです。 
3. これら 2 つの考えられるキーのうち少なくとも 1 つが存在する場合は常に、答えを増やします。 
4. 成功したロックの最終的な数を出力します。 

これが機能する理由は、開閉ルールがキー番号とロック番号の間の距離のみに依存するためです。 どのロック x についても、x - 1 と x + 1 以外のすべてのキーの距離は 1 とは異なるため、これら 2 つの値をチェックすることで、考えられるすべての成功ケースがカバーされます。 

なぜ効果があるのか:

 ロックの処理中に維持される不変条件は、答えが、セット内に少なくとも 1 つの隣接するキーを持つ、すでに処理されたロックの数に等しいということです。 新しいロック x が検査されるとき、アルゴリズムは、それを開ける可能性のあるキーの完全なセットを正確にチェックします。 存在する場合はカウントが増加し、存在しない場合はカウントは変化しません。 したがって、すべてのロックは、カウントされるべきときに正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().split()
    if not data:
        return

    idx = 0

    k = int(data[idx])
    idx += 1

    keys = set()
    for _ in range(k):
        keys.add(int(data[idx]))
        idx += 1

    L = int(data[idx])
    idx += 1

    answer = 0
    for _ in range(L):
        lock = int(data[idx])
        idx += 1
        if lock - 1 in keys or lock + 1 in keys:
            answer += 1

    print(answer)

if __name__ == "__main__":
    solve()
```メンバーシップのチェックが中心的な操作であるため、ソリューションではまずキーからセットを作成します。 Python セットでは平均 O(1) ルックアップ時間が得られ、各ロック チェックが継続的な作業に変わります。 

ループ オーバー ロックはアルゴリズムに直接に従います。 ロック値の場合`lock`、式`lock - 1`そして`lock + 1`可能なキー番号のみを表します。 有効なキー範囲外の値を検索してもセットから false が返されるだけなので、境界には特別な処理は必要ありません。 

入力サイズが小さいため、実装ではすべての入力トークンを一度に読み取り、ジャッジが余分な空白や行のフォーマットを提供するかどうかに依存することを回避します。 Python では整数オーバーフローの懸念はなく、チェックされる最大値は 105 のみです。

 ## 特殊なケース

 次のように、キーとロックが同じ番号を持つ場合:```
1
1
1
1
```アルゴリズムは、キー 0 と 2 を探してロック 1 をチェックします。どちらも存在しないため、答えは 0 のままです。 これにより、等しいものを有効な一致として扱うというよくある間違いを回避できます。 

大きい方の鍵で開けられるロックの場合、次のようになります。```
1
1
1
2
```アルゴリズムは、ロック 2 についてキー 1 と 3 をチェックします。キー 1 が存在するため、答えは 1 になります。 これにより、差分ルールの両方向が処理されることが確認されます。 

最終的な境界値の場合:```
1
104
1
103
```アルゴリズムは、ロック 103 のキー 102 と 104 をチェックします。キー 104 が存在するため、ロックは正常にカウントされます。 許容範囲外の値は単にセットに存在しないため、問題は発生しません。
