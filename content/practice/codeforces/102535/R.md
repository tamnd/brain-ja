 ## 解決策
 ## 問題の理解

 数値のペアをカウントする必要があります`(k, b)`どこ`k`は乗数であり、`b`ベースです。 乗算時にペアは有効とみなされます`k`からのすべての桁位置ごとに`0`に`b-1`その基数のすべての可能な桁を含むデジタル ルートを 1 回だけ生成します。 

入力により、許容される最大の乗数が得られます`k'`および最大許容塩基`b'`。 答えは、次の有効なペアの数です。`1 <= k <= k'`そして`2 <= b <= b'`、剰余を取得`10^6`。 

この制限は、すべてのペアの反復を許可する制限をはるかに超えています。 まであります`5 * 10^9`両方の変数の可能な値があるため、すべての基数とすべての乗数をチェックするには、約`2.5 * 10^19`操作。 解決策では、問題を約数の算術に落とし込み、フロア分割値が少数しか変化しないという事実を利用する必要があります。 

最初の隠れエッジケースが基本です`2`。 デジタルルートには数字のみが含まれます`0`そして`1`、すべての正の数はデジタルルートを持ちます`1`基地内で`2`。 の係数を仮定する式`b-1`ここで壊れる以上のものです。 たとえば、入力`1 2`答えがあります`1`、唯一のペアなので、`(1,2)`有効です。 

もう 1 つのエッジケースは次のような場合です`k`そして`b-1`は互いに素ではありません。 A direct simulation may accidentally pass small examples because only a few products are checked. たとえば、入力`2 3`答えがあります`3`。 ベース用`3`の値が必要です。`0, k, 2k`なる`0,1,2`。 と`k=2`、値は順列ではありません。`2*2`と同じデジタルルートを持っています`1*2`。 

最後のエッジケースは大きな境界です。 入力`5000000000 5000000000`このサイズの配列を格納したり、すべての塩基をループしたりすることではアプローチできません。 このアルゴリズムは、ほぼ平方根サイズの値のグループでのみ機能する必要があります。 

## アプローチ

 簡単なアプローチは、すべての塩基を反復処理することです。`b`、その後は毎回`k`、のデジタル ルートをシミュレートします。`0, k, 2k, ..., (b-1)k`。 シミュレーションは定義を直接チェックするため、正確です。 ただし、使用できません。ペアの数だけでは到達できます。`25 * 10^18`。 

重要な観察は、デジタル ルート公式から得られます。 正の整数の場合`x`基地内で`b`:`f_b(x) = 1 + ((x - 1) mod (b - 1))`。 

させて`m = b - 1`。 の値`k, 2k, ..., mk`の順列になる`1, 2, ..., m`正確に乗算するとき`k`すべての剰余を剰余で並べ替えます`m`。 それはまさに次のときに起こります`gcd(k, m) = 1`。 

元の問題は現在、約数の計算の問題です。 必要なものは次のとおりです。`sum over m = 1 to b'-1 of count of k <= k' with gcd(k,m)=1`。 

メビウス関数の使用:`count(k <= K, gcd(k,m)=1) = sum over d|m of mu(d) * floor(K/d)`。 

合計を交換すると次のようになります。`answer = sum over d <= min(K, B-1) of mu(d) * floor(K/d) * floor((B-1)/d)`。 

残りの課題は、これを迅速に評価することです。 下限値は間隔ごとに一定に保たれます。 これらの間隔の間をジャンプすることができ、必要なのはメビウス関数の接頭辞の合計だけです。 Möbius 関数の大きなプレフィックス値は、Du Jiao スタイルの再帰で取得されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k' * b' * b') | お(1) | 遅すぎる |
 | 最適 | 約 O(N^(2/3)) | O(N^(1/2)) | 承認済み |

 ここ`N = min(k', b'-1)`。 

## アルゴリズムのチュートリアル

 1. しましょう`n = b' - 1`。 答えをメビウスの和に変換します。`sum(mu(d) * floor(k'/d) * floor(n/d))`。 

この変換により、個々のペアをテストする必要がなくなりました。 
2. メルテンス関数を計算する`M(x) = mu(1) + ... + mu(x)`フロア分割に必要な値。 

小さな値は線形ふるいを使用して事前に計算されます。 より大きな値は、以下を使用して再帰的に計算されます。`M(x) = 1 - sum(M(x / i))`すべての範囲に対して、`x / i`は一定です。 
3. 除数変数を反復処理します。`d`ブロックで。 現在の場合`d`、最大値を計算します`r`次のような:`k'/d`そして`n/d`のすべての値は変更されません。`[d, r]`。 

ブロック全体の貢献度は次のとおりです。`(M(r) - M(d-1)) * floor(k'/d) * floor(n/d)`。 
4. すべてのブロック寄与モジュロを加算します。`10^6`。 

アルゴリズムの背後にある不変条件は、すべての約数が`d`まさに貢献する`mu(d) * floor(k'/d) * floor(n/d)`。 等しいフロア分割をグループ化すると、加算の順序のみが変更され、値は変更されません。 Mertens 関数はブロック内のすべてのメビウス値の合計を与えるため、すべての約数が 1 回だけ含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**6
LIM = 2000000

mu = [1] * (LIM + 1)
prime = []
vis = [False] * (LIM + 1)
mu[0] = 0

for i in range(2, LIM + 1):
    if not vis[i]:
        prime.append(i)
        mu[i] = -1
    for p in prime:
        if i * p > LIM:
            break
        vis[i * p] = True
        if i % p == 0:
            mu[i * p] = 0
            break
        mu[i * p] = -mu[i]

pref = [0] * (LIM + 1)
for i in range(1, LIM + 1):
    pref[i] = pref[i - 1] + mu[i]

cache = {}

def mertens(n):
    if n <= LIM:
        return pref[n]
    if n in cache:
        return cache[n]
    res = 1
    i = 2
    while i <= n:
        q = n // i
        j = n // q
        res -= (j - i + 1) * mertens(q)
        i = j + 1
    cache[n] = res
    return res

def solve():
    k, b = map(int, input().split())
    n = b - 1
    limit = min(k, n)

    ans = 0
    d = 1
    while d <= limit:
        qk = k // d
        qn = n // d
        r = min(k // qk, n // qn)
        mob = mertens(r) - mertens(d - 1)
        ans = (ans + mob * qk * qn) % MOD
        d = r + 1

    print(ans % MOD)

solve()
```ふるいはメビウス値を最大で計算します。`LIM`より大きなリクエストはすべて再帰的 Mertens 関数を通じて処理されるためです。 再帰では、繰り返されたフロア分割引数の結果が保存されるため、高速に動作します。 

メイン ループは、範囲全体にわたって一度に 1 つの除数を進めることはありません。 いつ`k//d`または`(b-1)//d`が定数の場合、その区間内のすべての約数は同じ乗数を持つため、区間全体がまとめて処理されます。 

Python の整数はオーバーフローを回避しますが、答えは縮小剰余になります`10^6`各ブロックの貢献後。 の使用`min(k, b-1)`また、除数が大きくても何も寄与しないため、不必要な作業が回避されます。 

## 実用的な例

 入力の場合:```
3 5
```我々は持っています`k'=3`そして`b'-1=4`。 

| d範囲 | M(r)-M(d-1) | 床(3/d) | 床(4/d) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 3 | 4 | 12 |
 | 2 | -1 | 1 | 2 | -2 |
 | 3 | -1 | 1 | 1 | -1 |
 | 4 | 0 | 0 | 1 | 0 |

 合計は`9`、サンプルと一致します。 

入力の場合:```
2 3
```私たちには基地があります`2`そして`3`。 

| d | μ(d) | フロア(2/d) | フロア(2/d) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 2 | 4 |
 | 2 | -1 | 1 | 1 | -1 |

 答えは、`3`。 この事例は、すべての乗算器がすべての塩基に対して機能するわけではないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | およそ O(N^(2/3)) | ふるいは小さな値を処理し、フロア分割グループ化は再帰的な状態を制限します。

 ## 特殊なケース

 のために`1 2`、アルゴリズムセット`n = 1`。 合計には次の内容のみが含まれます`d = 1`、 と`mu(1)=1`、`floor(1/1)=1`、 そして`floor(1/1)=1`、答えを生み出す`1`。 

のために`2 3`、アルゴリズムは次のように考慮します。`n = 2`。 メビウス展開では次のことが得られます。`floor(2/1)*floor(2/1) - floor(2/2)*floor(2/2) = 4 - 1 = 3`。 

これは有効なペアをカウントします`(1,2)`、`(2,2)`、 そして`(1,3)`拒否しながら`(2,3)`。 

最大値の場合、除数ループが数十億回の反復に達することはありません。 両方のフロア分割が等しい範囲間をジャンプし、大規模な Mertens クエリはメモ化によって再利用されます。 これにより、入力値の生のサイズに依存せずに実行が維持されます。
