 ## 解決策
 ## 問題の理解

 暗号化された各メッセージにはマーカー値が含まれています。 すべてのマーカーについて、可算性に基づいて 3 つのエージェントのうちのどれがそれを受け取るべきかを決定する必要があります。 エージェント 003 はマーカーが 3 で割り切れるメッセージを受信し、エージェント 005 はマーカーが 5 で割り切れるメッセージを受信し、エージェント 007 はマーカーが 7 で割り切れるメッセージを受信します。単一のマーカーが複数のエージェントに属する場合があるため、出力には固定順序で複数のエージェント名が含まれる可能性があります。 各マーカーを処理した後、出力には区切り線が含まれている必要があります。 

入力には最大 100,000 個のマーカーを含めることができ、各マーカーは (10^{18}) までの大きさにすることができます。 テスト ケースの数は、アルゴリズムの選択を決定する部分です。 すべてのマーカーに対して多くの操作を試行するソリューションでは、すぐに使用可能な時間を超えてしまいます。 (10^5) の場合、目的の解決策はマーカーごとにほぼ一定の作業を必要とするため、数値のサイズに依存するアプローチは不可能になります。 幸いなことに、3 つの固定の小さな整数による割り算のチェックは定数時間の操作です。 

主なエッジケースは、複数の条件が同時に当てはまる可能性があるという事実から生じます。 最初の割り切れる数値を見つけた後にソリューションが停止すると、有効な受信者を見逃してしまいます。 例えば：```
1
420
```正しい出力は次のとおりです。```
AGENT 003
AGENT 005
AGENT 007
---
```数値 420 は 3 つの値すべてで割り切れます。 を使用する不注意な実装`if`、`elif`、`else`最初に一致したエージェントのみを出力します。 

もう 1 つのエッジ ケースは、誰にも一致しないマーカーです。```
1
11
```正しい出力は次のとおりです。```
NONE
---
```すべてのマーカーに少なくとも 1 人の受信者がいると想定しているプログラムでは、何も印刷されないか、不完全な区切り構造が生成される可能性があります。 

最後のケースは非常に大きなマーカーです。```
1
1000000000000000000
```正しい出力は次のとおりです。```
AGENT 003
AGENT 005
AGENT 007
---
```この値は 32 ビット整数の制限をはるかに超えています。 このアルゴリズムは、Python が自然に処理する大きな整数を処理する必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての受信者の条件を個別にテストすることです。 各マーカーについて、3 で割り切れるかどうか、5 で割り切れるか、7 で割り切れるかどうかを確認します。実際、これは問題に必要な完全なロジックなので、正しいです。 合計作業量はテスト ケースごとに 3 つのモジュロ演算であり、最大の入力に対しておよそ (3 \times 10^5) の演算が行われます。 

もし誰かが各マーカーの約数を検索して問題を一般化しようとすると、コストははるかに大きくなるでしょう。 (10^{18}) に近いマーカーの場合、その平方根までのすべての可能な約数をチェックするには、1 つのケースに対して約 (10^9) 回の反復が必要になりますが、これはまったく不要です。 重要な約数は、既知の 3 人の受信者だけです。 

重要な観察は、問題は約数を発見することを求めているわけではないということです。 可能性のある受信者はすでにわかっています。 3 つの固定された可分性チェックを評価するだけで済みます。 これにより、タスクがマーカーごとの定数時間演算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース除数検索 | テスト ケースあたり O(sqrt(m)) | お(1) | 遅すぎる |
 | 3、5、7 で割り切れるかどうかを確認する | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、各マーカーを個別に処理します。 各マーカーは他のマーカーと相互作用しないため、ケース間で状態を保持する必要はありません。 
2. 現在のマーカーの受信者の空のリストを作成します。 最終的な順序が明示的に制御されるように、名前をすぐに出力するのではなく保存します。 
3. マーカーが 3 で割り切れるかどうかを確認します。割り切れる場合は、追加します。`AGENT 003`。 このチェックは、最初の受信者の完全な状態を表します。 
4. マーカーが 5 で割り切れるかどうかを確認します。割り切れる場合は、追加します。`AGENT 005`。 
5. マーカーが 7 で割り切れるかどうかを確認します。割り切れる場合は、追加します。`AGENT 007`。 
6. 受信者が追加されていない場合は、追加します。`NONE`。 それ以外の場合は、収集されたすべての受信者をチェックされた順序で印刷します。 
7. 各テスト ケースの後に区切り線を印刷します。 

なぜ効果があるのか:

 アルゴリズムは、考えられる受信者ごとに、その受信者がメッセージを受信するかどうかを定義する数学的条件を正確に実行します。 3 つのチェックはすべて独立して実行されるため、複数の値で割り切れるマーカーは正しく処理されます。 3 つの条件のいずれも当てはまらない場合、受信者リストは空のままになります。これは、まさに次の状況です。`NONE`。 チェックは常に必要な順序で実行されるため、最終的な出力順序が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        m = int(input())
        agents = []

        if m % 3 == 0:
            agents.append("AGENT 003")
        if m % 5 == 0:
            agents.append("AGENT 005")
        if m % 7 == 0:
            agents.append("AGENT 007")

        if not agents:
            ans.append("NONE")
        else:
            ans.extend(agents)

        ans.append("---")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```入力は次を使用して読み取られます`sys.stdin.readline`テストケースがたくさんある可能性があるからです。 このソリューションでは、出力行をリストに保存し、最後に一度書き込みます。これにより、繰り返しの印刷オーバーヘッドが回避されます。 

の`agents`リストはマーカーごとに再構築されます。 各可算性テストは独立しているため、別々に実行します。`if`ステートメントは必須です。 それらを次のように置き換えると、`elif`マーカーは複数のエージェントに属することができるため、バグが発生します。 

Python の整数には任意の精度があるため、(10^{18}) までの値は特別な処理を必要としません。 モジュロ演算は、オーバーフローを心配することなく、入力値に直接作用します。

 ## 特殊なケース

 最初のエッジ ケースは、重複した可分性です。 入力の場合:```
1

```アルゴリズムが評価する`420 % 3`、`420 % 5`、 そして`420 % 7`。 3 つの結果はすべて 0 なので、リストは次のようになります。```
AGENT 003
AGENT 005

```3 つのモジュロ演算により、ゼロ以外の剰余が生成されます。 リストは空のままであるため、アルゴリズムは次のように挿入します。`NONE`セパレータを印刷する前に。
