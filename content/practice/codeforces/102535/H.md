 ## 解決策
 ## 問題の理解

 タスクは、タグによって記録された音のみを使用して、タグ付きの各生き物を分類することです。 クリーチャーが発するすべてのサウンドが 2 つの有効なバップ サウンドの特別なセットに属している場合、そのクリーチャーはバップです。`BEEP`そして`BOOP`。 それ以外の音は、その生き物がバップではないことをすぐに証明します。 

入力には複数の生き物が含まれています。 生き物ごとに、録音された音の数を受け取り、その後にそれらの音の文字列が続きます。 各クリーチャーの出力は、録音されたサウンドがすべて有効なバップサウンドであるかどうかに応じて固定メッセージになります。 

制限は十分に小さいため、すべてのサウンドを直接検査できます。 クリーチャーは最大 350 個存在でき、各クリーチャーには最大 350 個のサウンドがあるため、サウンド チェックの合計数は最大 122,500 になります。 すべてのサウンドを単純にリニアスキャンするだけでも、簡単に制限時間内に収まります。 これらの制約により、複雑なデータ構造や前処理の必要性が排除されます。 主な要件は、分類条件の間違いを避けることです。 

よくある間違いは、`BEEP`または`BOOP`すべてのサウンドがそれらの 1 つであることを確認するのではなく。 例えば：```
1
3
BEEP
BOOP
QUACK
```正しい出力は次のとおりです。```
IT'S NOT A BOP!
```少なくとも 1 つの有効なバップ サウンドが表示されるかどうかのみをチェックする不注意な実装では、このクリーチャーが誤って受け入れられてしまいます。 

もう 1 つのエッジ ケースは、同じ有効な音を何度も繰り返す生き物です。```
1
4
BOOP
BOOP
BOOP
BOOP
```正しい出力は次のとおりです。```
IT'S A BOP!
```出現回数は関係ありません。 条件は、録音されたすべてのサウンドが許可されたセットに属しているかどうかによってのみ決まります。 

3 番目のケースは、1 つの音を持つ生き物です。```
1
1
BEEP
```正しい出力は次のとおりです。```
IT'S A BOP!
```チェック変数を誤って誤って初期化する実装や、複数のサウンドを読み取った後にのみテストする実装は、この最小の入力で失敗する可能性があります。 

## アプローチ

 簡単なアプローチは、あらゆる生き物のあらゆる音を調べることです。 それぞれの生き物について、まずそれがバップであると仮定し、次に録音された各音を検査します。 それ以外の音の場合`BEEP`または`BOOP`、クリーチャーを無効としてマークします。 これが機能するのは、バップの定義が、録音されたすべてのサウンドがその 2 つの要素セットに含まれていなければならないということであるためです。 

入力自体に必要な情報がすべて含まれているため、ブルート フォース アプローチはすでに線形です。 最悪の場合、考えられるすべてのサウンドがチェックされ、350 × 350 = 122,500 回の比較が行われます。 これはパフォーマンスの問題ではないため、同じ考え方が最適な解決策でもあります。 

重要な観察は、異なる生き物の間には関係がなく、音を互いに比較する必要がないということです。 それぞれの生き物は、独自の音のリストを検証することで個別に分類できます。 この条件が単純なメンバーシップ チェックであるという観察により、問題を入力の 1 回のパスに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C × N) | お(1) | 承認済み |
 | 最適 | O(C × N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 生き物の数を読み取ります。 ある生き物の音は他の生き物に影響を与えないため、各生き物は独立して処理されます。 
2. 各クリーチャーについて、音の数を読み取り、そのクリーチャーが現在バップであるとみなされることを示すフラグを設定します。 生き物は禁止された音を見つけた後にのみ無効になるため、最初の仮定は有効です。 
3. それぞれの音を読み、正確であるかどうかを確認します`BEEP`または`BOOP`。 どちらでもない場合は、フラグを変更して、そのクリーチャーがバップではないことを示します。 
4. 現在のクリーチャーのすべてのサウンドが処理された後、フラグに基づいて結果を出力します。 後から音が出ると、前に有効に見えたクリーチャーが無効になる可能性があるため、最後まで待ちます。 

機能する理由: 生き物の音のスキャン中、不変条件は、これまでに確認されたすべての音が有効なバップ サウンドである場合にフラグが true のままであることです。 有効なサウンドではこのプロパティは変更されませんが、無効なサウンドではこのプロパティが永久に破壊されます。 最終サウンドが処理された後、フラグは、録音されたすべてのサウンドがバップ ルールを満たしているかどうかを示します。これはまさに必要な条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    c = int(input())
    ans = []

    for _ in range(c):
        n = int(input())
        is_bop = True

        for _ in range(n):
            sound = input().strip()
            if sound != "BEEP" and sound != "BOOP":
                is_bop = False

        if is_bop:
            ans.append("IT'S A BOP!")
        else:
            ans.append("IT'S NOT A BOP!")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`is_bop`生物の現在の分類を表します。 それは次のように始まります`True`なぜなら、バップのルールに反するサウンドはまだ存在しないからです。 すべてのサウンドは読み取られた直後にチェックされるため、追加のストレージは必要ありません。 

比較では、2 つの完全な文字列のみが含まれるため、文字列の正確な等価性が使用されます。`BEEP`そして`BOOP`受け入れられます。 プレフィックス チェックまたはサブストリング チェックでは、次のような値が誤って受け入れられます。`BEEPS`または`XBOOP`。 

コードはサウンドを到着時に処理し、最終的な出力メッセージのみを保存します。 入力制限が小さいため、通常の整数処理で十分であり、オーバーフローの心配はありません。

 許可されたセット外のサウンドが出現した場合にのみフラグが変化するため、有効なサウンドと無効なサウンドの両方が含まれるケースが処理されます。 入力の場合:```
1
3
BEEP
BOOP
QUACK
```最初の2つの音は残ります`is_bop`として`True`、 それから`QUACK`に変更します`False`、生産:```

```アルゴリズムが音をカウントしたり、多様性を要求したりしないため、繰り返し音のケースが機能します。 のために：```

BOOP
BOOP
```各比較は成功するため、フラグは true のままとなり、出力は次のようになります。```
