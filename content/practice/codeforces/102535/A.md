 ## 解決策
 ## 問題の理解

 私たちは 5 つの鍵と 5 つのロックの小さなコレクションを持っています。 入力により、ペリーが所有する鍵の番号とドアの錠の番号がわかります。 タスクは、その特定のキーがその特定のロックを開けることができるかどうかを判断することです。 キーが機能する場合は成功メッセージが出力され、そうでない場合は失敗メッセージが出力されます。 

キーとロックの関係は固定されています。 キー 1 はロック 2 でのみ機能し、キー 2 はロック 1 と 3 で機能し、キー 3 はロック 2 と 4 で機能し、キー 4 はロック 3 と 5 で機能し、キー 5 はロック 4 でのみ機能します。使用可能なキーとロックは 5 つしかないため、決定空間全体には 25 個の組み合わせしか含まれません。 制約には高度なデータ構造や最適化は必要ありません。 一定量の作業を実行するソリューションは、簡単に十分に高速です。 

主なエッジ ケースは、キー シーケンスの終端と、近くの番号が常に同じ方向に機能すると仮定することから生じます。 たとえば、入力```
1
4
```生成する必要があります:```
CURSE YOU
```キー 1 はロック 2 のみを開くため、ある距離内にあるすべてのロックを開けることができるかのようにキーを扱うと、誤った結果が得られます。 

もう 1 つの境界ケースは最後のキーです。```
5
4
```正しい出力は次のとおりです。```
GOOD LUCK AGENT P
```キー 5 には有効なロックが 1 つだけあり、そのロックは 4 です。隣接するロックをチェックしている間に存在しないロック 6 にアクセスしようとする実装は失敗する可能性があります。 

3 番目のケースは、キーとロックが同じ番号を持つ場合です。```
3
3
```正しい出力は次のとおりです。```
CURSE YOU
```番号はさまざまなオブジェクトを識別します。 キー番号がロック番号と一致することは、互換性を意味するものではありません。 

## アプローチ

 簡単なアプローチは、各キーの可能なロックを保存し、指定されたロックがそのリストに表示されるかどうかを確認することです。 これは事実上、ロック システムの直接のシミュレーションです。 すべての有効なキーとロックのペアが正確なルールに照らしてチェックされるため、これは正しいです。 この問題では、最悪の場合でも 1 つのキーに対して考えられるロックを 2 つだけチェックする必要があるため、実行される操作はせいぜい数回です。 

より一般的なブルート フォースの解釈は、指定されたペアが見つかるまで、考えられるすべてのキーとロックの関係を試行することです。 5 つのキーと 5 つのロックがある場合、最大 25 ペアをチェックすることになります。 これもここでは簡単に受け入れられますが、入力がすでに関心のある唯一のペアを識別しているという事実を無視しています。 

重要な点は、ロック システムが静的であることです。 答えは計算や検索には依存しません。 それは、ペアが事前に定義された有効なペアの小さなセットに属しているかどうかのみに依存します。 これらのペアを直接表現すると、問題は定数時間のメンバーシップ チェックに変わります。 

総当たりアプローチは入力サイズが小さいため機能しますが、問題の実際の構造を表現するものではありません。 有効な関係が固定されているという観察により、解決策を 1 回の検索に減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 入力からキー番号とロック番号を読み取ります。 これら 2 つの値は、評価する必要がある状況を完全に表しています。 
2. 有効なキーとロックのペアの表現を作成します。 この表現は、ロック システムの規則に一致して、各キーを開くことができるロックにマップします。 
3. 指定されたキーで使用可能なロックの中に指定されたロックが存在するかどうかを確認します。 検索が成功すると、その鍵でドアを開けることができます。 
4. 印刷`"GOOD LUCK AGENT P"`有効なペアの場合と`"CURSE YOU"`さもないと。 

なぜ効果があるのか:

 保存されたマッピングには、許可されているすべてのキーロック関係が正確に含まれています。 どの入力に対しても、アルゴリズムは問題の定義と同じ条件、つまり指定されたロックが指定されたキーによって開かれたロックのセットに属しているかどうかをチェックします。 有効なペアが欠落しておらず、無効なペアも含まれていないため、検索によって生成される答えは常に正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    L = int(input())

    can_open = {
        1: {2},
        2: {1, 3},
        3: {2, 4},
        4: {3, 5},
        5: {4}
    }

    if L in can_open[k]:
        print("GOOD LUCK AGENT P")
    else:
        print("CURSE YOU")

if __name__ == "__main__":
    solve()
```辞書には完全なロック システムが保存されています。 各キー番号は、それが開くことができるロック番号を正確に含むセットを指します。 

メンバーシップ チェックでは、指定されたキーを使用して可能なロックを取得し、入力ロックがそのセット内にあるかどうかをチェックします。 入力値は 1 ～ 5 であることが保証されているため、追加の検証や境界処理は必要ありません。 

インデックス計算がないため、オフバイワンのリスクはありません。 また、このソリューションでは、キーとロック番号の間の関係についての算術仮定も回避します。これは、最初と最後のキーが中間のキーとは異なる動作をするため、重要です。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    k = int(sys.stdin.readline())
    L = int(sys.stdin.readline())

    can_open = {
        1: {2},
        2: {1, 3},
        3: {2, 4},
        4: {3, 5},
        5: {4}
    }

    if L in can_open[k]:
        print("GOOD LUCK AGENT P")
    else:
        print("CURSE YOU")

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

assert solution("1\n4\n") == "CURSE YOU\n", "sample 1"
assert solution("2\n3\n") == "GOOD LUCK AGENT P\n", "sample 2"
assert solution("3\n1\n") == "CURSE YOU\n", "sample 3"

assert solution("1\n2\n") == "GOOD LUCK AGENT P\n", "minimum key boundary"
assert solution("5\n4\n") == "GOOD LUCK AGENT P\n", "maximum key boundary"

 ## 特殊なケース

 最初の境界ケースの場合:```
1
4
```アルゴリズムはセットを取得します`{2}`キー 1 の場合。メンバーシップ チェックでは、そのセットに 4 が存在するかどうかが尋ねられますが、これは false であるため、次のように出力されます。`CURSE YOU`。 これは、キーに可能なロックが 1 つだけある場合を処理し、無関係なロックの受け入れを回避します。 

最後のキーの場合:```
5
4
```アルゴリズムは取得します`{4}`キー 5 の場合。値 4 はすぐに見つかるため、出力は次のようになります。`GOOD LUCK AGENT P`。 固定マッピングにより、使用可能なキー範囲を超えて検索しようとする試みが防止されます。 

番号を一致させる場合:```
3
3
```アルゴリズムは取得します`{2, 4}`キー 3 の場合。3 が存在しないため、出力されます。`CURSE YOU`。 これは、ソリューションが 2 つの入力数値を直接比較するのではなく、実際の互換性をチェックしていることを確認します。
