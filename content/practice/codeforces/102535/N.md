 ## 解決策
 ## 問題の理解

 建物は、各フロアに 1 つある独立した 2D マップの集合です。 すべてのマップは、歩行可能なセル、壁、階段のセルを含むグリッドです。 異なる階にある同じ文字の階段は、それらの位置間の接続を表します。 目標は、ドアに変換する必要がある壁セルの数を最小限に抑えながら、1 階の開始セルを選択し、最後の階の任意のセルに到達することです。 

重要な点は、移動自体が自由であるということです。 すでに開いているセルを通過したり、階段を通過したり、すでに切断された壁を通過したりする場合は、切断後はすべて費用がかかりません。 最小化される唯一のリソースは、ルートの一部として入力される個別の壁セルの数です。これは、各セルに 1 回のレーザー カットが必要なためです。 

入力サイズの合計は 100 フロアで制限され、各フロアには最大でも 100 × 100 のグリッドが含まれます。 これにより、建物全体で最大 100 万個のセルが使用されます。 状態空間が指数関数的に増大するため、多くの可能なパスを試行したり、壁のすべてのサブセットにわたって検索を実行したりする解決策は不可能です。 線形または線形に近いグラフの走査が必要です。 100 万ノードは大きいですが、各ノードとエッジを一定の回数処理するアルゴリズムでは管理可能です。 

いくつかの詳細が、他の点では合理的な解決策を壊す可能性があります。 特定の空のセルから強制的に検索を開始すると、より大きな答えが得られる可能性があるため、1 階のどこからでも開始することが重要です。 いくつかの階段が存在する場合でも、フロアに最上階への経路がない場合もあるため、到達不能な状態は明示的に処理する必要があります。

## アプローチ

 直接的なアプローチは、建物内を通過する可能性のある移動をシミュレーションすることです。 考えられるすべてのプレイヤーの位置を状態として扱い、動きを繰り返し探索して、カット数が最も少ないパスを見つけようとします。 すべての法的行為が代表されるため、これは正しいです。 ただし、すべての移動を同等に扱う通常の最短パス アルゴリズムを使用すると、壁に入る場合と空のセルに入る場合の重要な違いが無視されます。 切断壁の可能な組み合わせをすべて検討するのはさらに困難です。 最悪の場合、セルが約 100 万個になる可能性があり、多くの代替サブセットやパスを保存するアプローチは不可能になります。 

有益な観察は、これはすでに最短経路問題であるが、エッジには考えられるコストが 2 つしかないということです。 空き部屋、階段、またはすでに利用可能な場所への移動には費用はかかりません。 壁セルへの移動はレーザーカットを 1 つ消費するため、コストが 1 つかかります。 したがって、グラフにはバイナリのエッジ重みがあり、0 ～ 1 BFS が最短パスを効率的に見つけることができることを意味します。 

グラフを明示的に構築する必要はありません。 すべてのグリッド セルがノードです。 4 つの隣接するセルは移動エッジを作成し、階段セルは他のフロアの同じ文字に追加のゼロコスト エッジを作成します。 開始位置は 1 階のどこでもよいため、その階のすべてのセルは距離 0 から始まります。 

ブルートフォース手法は、すべての合法的な動きを調査するため機能しますが、可能な状態とパスの数が多すぎるために失敗します。 すべての遷移のコストが 0 または 1 であるという観察により、高価な一般的な最短パス探索を deque ベースの走査に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 可能なカットの数は指数関数的に増加します。 指数 | 遅すぎる |
 | 最適 | O(V + E) | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのフロアを読み取り、グリッドを保存します。 読みながら、すべての階段文字の座標を収集します。 一致する階段を通過する移動はコストがゼロの遷移であるため、これらの座標は後で必要になります。 
2. すべてのセルの距離配列を作成し、1 階のすべてのセルを距離 0 で初期化します。 他のすべてのセルは到達不能として開始されます。 これは、開始位置が最適に選択されるという事実をモデル化します。 
3. デキューを使用して 0-1 BFS を実行します。 セルを処理するときは、隣接する 4 つのセルすべてを試してください。 壁に入ると距離に 1 が追加され、他のセルに入ると 0 が追加されます。 新しい距離によって既知の距離が改善される場合は、それを更新し、コスト 0 の移動の場合はセルをデキューの前に、コスト 1 の移動の場合は後ろにセルを配置します。 
4. 階段セルを処理する場合、コスト 0 で、異なるフロアにある同じ階段文字が出現するすべての場所に移動します。 これらの遷移は、階段を上ることを表します。 
5. 検索が終了したら、最上階のすべてのセルを検査します。 その中で最も短い距離が答えになります。 最上階のすべてのセルに到達できない場合は、建物を横断できないことを報告してください。 

なぜ効果があるのか:

 0-1 BFS は、ダイクストラのアルゴリズムと同じ最短パスの順序を維持しますが、重みが 0 または 1 のみであるという事実を利用して、優先キューを回避します。 あらゆる瞬間に、両端キューには、現在の既知の最短距離に従って順序付けされたセルが格納されます。 セルは、より安価な可能性をすべて考慮した後でのみ最終決定されます。 考えられるすべての動きは正確なカット コストを備えたエッジによって表されるため、ターゲット フロアで見つかった最初の最短距離が、必要なドアの最小数になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    f = int(input())
    floors = []
    stairs = {}

    for floor in range(f):
        r, c = map(int, input().split())
        grid = []
        for i in range(r):
            row = list(input().strip())
            grid.append(row)
            for j, ch in enumerate(row):
                if ch.isalpha():
                    stairs.setdefault(ch, []).append((floor, i, j))
        floors.append((r, c, grid))

    ids = []
    index = 0
    for floor, (r, c, _) in enumerate(floors):
        cur = []
        for i in range(r):
            row = []
            for j in range(c):
                row.append(index)
                index += 1
            cur.append(row)
        ids.append(cur)

    n = index
    dist = [10**9] * n
    q = deque()

    for i in range(floors[0][0]):
        for j in range(floors[0][1]):
            idx = ids[0][i][j]
            dist[idx] = 0
            q.append(idx)

    rev = [None] * n
    for f_id, (r, c, _) in enumerate(floors):
        for i in range(r):
            for j in range(c):
                rev[ids[f_id][i][j]] = (f_id, i, j)

    used_stairs = set()

    while q:
        cur = q.popleft()
        floor, r, c = rev[cur]

        current_distance = dist[cur]

        grid = floors[floor][2]
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < floors[floor][0] and 0 <= nc < floors[floor][1]:
                nxt = ids[floor][nr][nc]
                weight = 1 if grid[nr][nc] == '#' else 0
                nd = current_distance + weight
                if nd < dist[nxt]:
                    dist[nxt] = nd
                    if weight == 0:
                        q.appendleft(nxt)
                    else:
                        q.append(nxt)

        ch = grid[r][c]
        if ch.isalpha() and ch not in used_stairs:
            used_stairs.add(ch)
            for nf, nr, nc in stairs[ch]:
                nxt = ids[nf][nr][nc]
                if current_distance < dist[nxt]:
                    dist[nxt] = current_distance
                    q.appendleft(nxt)

    ans = 10**9
    top = f - 1
    for i in range(floors[top][0]):
        for j in range(floors[top][1]):
            ans = min(ans, dist[ids[top][i][j]])

    if ans == 10**9:
        print("DAMN, THE ABSCONDER ABSCONDS AGAIN!")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```入力解析フェーズでは、各フロアを保存し、階段の位置を記録します。 階段辞書を使用すると、すべてのフロアを繰り返しスキャンしなくても、階段の移行を見つけることができます。 

の`ids`配列は三次元位置を変換します`(floor, row, column)`単一のインデックスにまとめられます。 これにより、距離配列がコンパクトになり、deque がタプルの代わりに整数を格納できるようになります。 逆マッピングでは、状態が処理されるたびに座標が回復されます。 

BFS の初期化により、最下階のすべてのセルが距離 0 の両端キューに配置されます。 これは開始場所の選択を処理する部分です。 最初のキューを 1 つのセルに制限すると、別の問題が解決されます。 

隣接緩和は目的地が壁の場合のみコスト１を使用する。 このアルゴリズムは壁セルをブロックしません。これは、壁セルに入るとドアが切断され、その位置が使用可能になることを意味するためです。 

階段の最適化`used_stairs`はパフォーマンスの詳細です。 階段文字のすべてのセルが緩和されると、同じ階段を再度処理しても結果は改善されません。 この最適化がないと、何度も出現する階段に、同じゼロコストの遷移が繰り返し追加される可能性があります。 

Python の整数には制限がないため、オーバーフローは心配ありません。 必要な境界チェックは、可能な 4 つのグリッドの移動だけです。
