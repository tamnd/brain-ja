 ## 解決策
 ## 問題の理解

 このタスクは、非常に大規模な電子充填プロセスをシミュレートすることですが、重要なのは最終的に充填されたサブシェルのみです。 原子番号を持つ原子`a`まさに`a`電子。 電子は値順にサブシェルに配置されます。`n + l`、関係はより小さいものによって解決されます。`n`。 インデックス付きのサブシェル`l`保持できる`4l + 2`電子。 

クエリごとに、電子構成全体を出力するのではなく、電子を受け取る最後のサブシェルのみが必要になります。 答えにはシェル番号が含まれている必要があります`n`、サブシェルのラベル、および実際にそこに配置されている電子の数。 

の限界`a`と同じくらい大きい`10^15`電子を 1 つずつシミュレートすることは直ちに除外されます。 すべてのテスト ケースについて、すべての満たされたサブシェルを反復処理するだけでも、関連する位置が数百万存在する可能性があるため、遅すぎます。`10^5`クエリ。 このソリューションでは、サブシェルの大規模なグループを数学的に飛び越えて、対数的な数の候補のみを検査する必要があります。 

最初の注意が必要なケースは、順序が単純にシェル数を増やすことではないということです。 たとえば、入力`19`生成する`4s1`、 なぜなら`4s`小さい`n+l`よりも`3d`。 シェルを順番にスキャンするソリューションでは、間違った結果が得られます。 

もう 1 つのエッジ ケースは、クエリがサブシェルの境界で正確に終了することです。 入力用`2`、答えは`1s2`。 答えを含む最初のグループではなく次のグループを見つける不注意な二分探索は、誤って次のグループに移動する可能性があります。`2s`。 

最後の微妙なケースは、拡張されたサブシェルの名前付けです。 たとえば、最大のサンプルでは 1 文字より長いラベルが使用されています。 仮定した解決策`l`常に 1 文字の場合は、1 文字のラベルが使い果たされると失敗します。 

## アプローチ

 直接的なアプローチでは、サブシェルの順序を生成し、残りの電子数から各サブシェルの容量を減算し、残りの値が現在のサブシェルに収まったときに停止します。 これは、Aufbau の順序に正確に従っているため、正しいです。 ただし、`10^15`電子の場合、サブシェルの数が多すぎて、クエリごとに個別に生成できません。 

有益な観察は、サブシェルが値によって自然に対角線を形成するということです。`k = n + l`。 すべての対角線は全体としてスキップできます。 固定の場合`k`、可能なすべてのペアが満たされます`n + l = k`、その対角線内の電子の総数は式で計算できます。 累積容量が指定された原子番号に達する最初の対角線を二分探索できます。 

対角線を見つけた後、その中には約半分のサブシェルしかありません。 容量は等差数列を形成するため、それらをたどる代わりに、別の二分探索を使用します。 これにより、問題全体が数回の対数検索に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとの O(サブシェルの数) | お(1) | 遅すぎる |
 | 最適 | クエリあたり O(log K) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのサブシェルに含まれる電子の総数を返す関数を定義します。`n + l <= K`。 

固定サブシェルインデックスの場合`l`、有効なシェルは次の条件を満たします。`l + 1 <= n <= K - l`。 そのような砲弾の数は`K - 2l`、そして誰もが貢献します`4l + 2`電子。 この算術式を合計すると閉じた式が得られ、対角線全体をスキップできます。 
2. 最小の二分探索`K`対角線までの電子の合計が`K`少なくとも指定された原子番号です。 

前の対角線は完全に満たされているため、それらの合計を差し引くと、対角線の内側に配置する必要がある電子の数が残ります。`K`。 
3. 対角線の内側で正確なサブシェルを見つけます`K`。 

この対角線では、貝殻が増加していきます。`n`。 対応する`l`値が減少します。 それらの容量は算術数列であるため、別の二分探索により、累積容量が残りの電子数に達する最初のサブシェルが見つかります。 
4. そのサブシェル内の残りの電子を計算し、その電子を変換します。`l`値を必要なラベル形式に変換します。 

以降の最初の 20 個のサブシェル インデックス`s`そして`p`単一文字のラベルが付いています。 その後、ラベルは辞書順に並べられた文字の組み合わせになります。 

機能する理由: このアルゴリズムは、元のシーケンスの連続した部分のみをグループ化することによって、Aufbau ルールと同じ順序を保持します。 最初の二分探索では、答えを含む正確な対角線が特定され、2 番目の二分探索では、その対角線内の正確なサブシェルが特定されます。 スキップされたすべての部分は正確な容量公式によってカウントされるため、電子の位置をスキップしたり 2 回カウントしたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def prefix(k):
    if k <= 0:
        return 0
    m = (k - 1) // 2
    return 2 * k * (m + 1) * (m + 1) - (2 * m * (m + 1) * (4 * m + 5)) // 3

def inside_sum(largest_l, count):
    return count * (4 * largest_l + 2) - 2 * count * (count - 1)

def label(idx):
    if idx == 0:
        return "s"
    if idx == 1:
        return "p"

    singles = "dfghijklmnoqrtuvwxyz"
    idx -= 2

    if idx < len(singles):
        return singles[idx]

    idx -= len(singles)
    length = 2
    while True:
        block = 26 ** length
        if idx < block:
            chars = []
            for _ in range(length):
                chars.append(chr(ord('a') + idx % 26))
                idx //= 26
            return ''.join(reversed(chars))
        idx -= block
        length += 1

def solve_one(a):
    lo, hi = 1, 100000
    while lo < hi:
        mid = (lo + hi) // 2
        if prefix(mid) >= a:
            hi = mid
        else:
            lo = mid + 1

    k = lo
    rem = a - prefix(k - 1)

    start_n = k // 2 + 1
    max_l = k - start_n

    lo, hi = 0, max_l
    while lo < hi:
        mid = (lo + hi) // 2
        if inside_sum(max_l, mid + 1) >= rem:
            hi = mid
        else:
            lo = mid + 1

    skipped = lo
    l = max_l - skipped
    before = inside_sum(max_l, skipped)
    e = rem - before
    n = k - l

    return str(n) + label(l) + str(e)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_one(int(input())))
    print('\n'.join(ans))

main()
```の`prefix`関数は最適化の中核です。 個々のサブシェルではなく、完全な対角線をカウントします。 変数`m`可能な限り最大です`l`対角線の値`k`であり、式はその対角線内のすべての容量を合計することで得られます。 

二人目の助っ人は、`inside_sum`、最初の容量を与えます。`count`対角線の内側のサブシェル。 これらの容量は毎回ちょうど 4 ずつ減少するため、合計は等差数列になります。 

最初の二分探索では、すべての可能な入力に対して十分な大きさの範囲が使用されます。 必要な値は、`10^15`電子はそれよりもはるかに小さい`100000`したがって、この境界は安全な上限にすぎません。 Python の整数は、大規模な乗算時のオーバーフローを回避します。 

ラベル変換は数学から分離されています。 これにより、異常な命名規則と電子計数ロジックが混在することが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log K) | 対角位置とサブシェル位置に対する 2 つの二分探索 |

 ## 特殊なケース

 原子番号について`2`、アルゴリズムは次のことを見つけます。`k = 1`最初の対角線にはすでに十分な電子が含まれているためです。 残りのカウントは`2`、対角線の最初のサブシェルには容量があります`2`したがって、出力は次のようになります`1s2`。 二分検索は最初の有効なプレフィックスを検索するため、次の対角線には移動しません。 

原子番号について`19`、アルゴリズムはまずすべての対角線をスキップしてから`k = 5`。 その対角線内で、次の順序で容量を比較します。`3d`、`4s`。 最初のサブシェルには残りの電子を含めることができないため、答えは次のようになります。`4s1`。 

次のような非常に大きな値の場合、`1000000000000000`、アルゴリズムが完全な構成を構築することはありません。 完全な対角線の式を評価し、対数検索を実行するだけで、計算されたサブシェル インデックスから最終的な複数文字のラベルが生成されます。 これは、ラベルの長さに関する固定の上限を仮定せずに、拡張命名規則を処理します。
