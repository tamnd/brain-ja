 ## 解決策
 ## 問題の理解

 配列で表される爆発物の列があります`E`。 所定の位置に爆発物`i`少なくとも 1 つの爆発物がその前のどこかにあり、少なくとも 1 つの爆発物がその後ろのどこかにある場合にのみ起動できます。 タスクは、この条件を満たす正確に爆発物の評価を追加することです。 

入力により、爆発物の数とその評価が左から右に表示されます。 出力は、戦線の両端ではなく、他の爆発物に囲まれているすべての陣地による合計評価です。 

制約`n <= 100`とても小さいです。 直接のシミュレーションや繰り返しのチェックはすでに十分に高速です。`O(n^2)`ソリューションでは約 1 万回の操作しか実行されません。 ただし、この問題の興味深い部分は、条件を過度に複雑にするのではなく認識していることです。 境界が小さいということは、高度なデータ構造や最適化が必要ないことも意味します。 

評価は 1000 まで大きくなるため、最終的な合計は約 100000 に達する可能性があります。Python の整数はこれを簡単に処理できるため、特別なオーバーフロー処理は必要ありません。 

よくある間違いは、最初と最後の爆発物は片側が欠けているため決して爆発できないことを忘れていることです。 例えば：```
Input:
3
5 8 2
```正しい出力は次のとおりです。```
8
```中央の爆発物には両側に隣接する爆発物がありますが、両端には隣接しません。 配列に複数の要素があるかどうかだけをチェックする不注意な実装では、エンドポイントが誤って含まれる可能性があります。 

もう 1 つのエッジ ケースは、爆発物が 3 つ未満のラインです。```
Input:
2
5 10
```正しい出力は次のとおりです。```
0
```どちらの爆発物にも左側と右側の両方はありません。 配列全体を誤ってループし、存在しない隣接要素にアクセスする実装は、失敗したり、誤ってエンドポイントをカウントしたりする可能性があります。 

## アプローチ

 簡単なアプローチは、すべての爆発物を検査し、両側に何かがあるかどうかを尋ねることです。 各位置について、その前後の要素をスキャンできます。 両方のスキャンで少なくとも 1 つの爆発物が見つかった場合、その評価が回答に追加されます。 これは正しいです。爆発の条件は、まさに配列内のどこかに左右に隣接するものが存在することだからです。 

この方法の問題は、作業が繰り返されることです。 多くの位置を確認すると、左右で同じ情報が何度も再発見されます。 最悪の場合、すべての位置でほぼアレイ全体のスキャンが実行され、おおよその結果が得られます。`n * n`操作。 

重要な観察は、この状態が他の爆発物の値にまったく依存していないことです。 それは立場によってのみ異なります。 最初と最後の位置を除くすべての位置には、左側に少なくとも 1 つの要素が、右側に少なくとも 1 つの要素が自動的に配置されます。 これにより、問題は条件を繰り返しチェックすることから、単に配列の中間セクションを合計することに変わります。 

この総当たり法は、爆発物ごとにルールを直接テストするため機能しますが、同じ位置情報を再発見するのに時間がかかるため失敗します。 エンドポイントのみが無効であることが観察されると、問題は有効範囲を通過する 1 回のパスに限定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | これらの制約は受け入れられますが、不要です |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 爆発物の数とその定格を読みます。 条件は爆発物の位置に依存するため、配列の順序は重要です。 
2. 答えをゼロに初期化します。 各爆発物は独立して考慮されるため、必要となるのは累計だけです。 
3. インデックスから位置を反復処理します。`1`インデックスを付ける`n - 2`。 これらは、正確に、その前に少なくとも 1 つの要素があり、後に少なくとも 1 つの要素がある位置です。 
4. 訪問した各位置の評価を回答に追加します。 訪問したすべての位置は、その位置だけで爆発条件を満たします。 
5. 累積合計を出力します。 

なぜ効果があるのか:

 要件を満たさない唯一の位置は、アレイの両端です。 最初の位置の左側には爆発物がなく、最後の位置の右側には爆発物がありません。 他のすべての位置には、少なくとも 1 つの小さいインデックスと少なくとも 1 つの大きいインデックスがあるため、すべての中間要素がその評価に寄与する必要があります。 このアルゴリズムはこれらの中間要素を正確に合計し、無効なエンドポイントを正確に除外するため、結果が正しいことが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    e = list(map(int, input().split()))

    ans = 0
    for i in range(1, n - 1):
        ans += e[i]

    print(ans)

if __name__ == "__main__":
    solve()
```位置に直接アクセスする必要があるため、入力はリストに保存されます。 ループは次から始まります`1`の代わりに`0`最初の爆発物は爆発できないからです。 その前で止まる`n - 1`最後の爆発物も爆発できないからです。 

いつ`n`は`1`または`2`、範囲`range(1, n - 1)`は空です。 これにより、別の境界条件を必要とせずに、自然にゼロの答えが得られます。 

このコードは、入力配列と 1 つの整数アキュムレータのみを保存します。 合計演算の順序によって、Python ではオーバーフローの問題が発生しません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各中間爆発物は 1 回ずつ訪問されます。 
| スペース | O(1) 入力ストレージを除く | 処理中には応答変数のみが使用されます。 

と`n <= 100`、線形解は簡単に制限時間内にあります。 効率の低い二次手法でも合格しますが、線形アプローチは条件の構造を直接反映し、不必要なチェックを回避します。 

## テストケース```python
import sys
import io

def solve(data):
    lines = data.strip().split()
    if not lines:
        return ""
    n = int(lines[0])
    e = list(map(int, lines[1:]))

    ans = 0
    for i in range(1, n - 1):
        ans += e[i]
    return str(ans)

def run(inp: str) -> str:
    return solve(inp)

assert run("6\n1 3 5 2 3 10\n") == "13", "sample 1"
assert run("2\n5 10\n") == "0", "sample 2"

assert run("1\n7\n") == "0", "single explosive has no sides"
assert run("3\n4 9 6\n") == "9", "only middle explosive counts"
assert run("5\n1 1 1 1 1\n") == "3", "all equal values"
assert run("100\n" + " ".join(["1000"] * 100) + "\n") == "98000", "maximum size input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`爆発物 |`0`| 最小サイズと空の反復範囲 |
 |`3`爆発物 | 中間値 | 有効な位置は 1 つだけ存在します |
 | 5 つの同等の評価 | 3 つの中間値の合計 | エンドポイントの除外を確認します |
