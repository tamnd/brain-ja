 ## 解決策
 ## 問題の理解

 長さのゼロの配列が与えられます$n$、および正の整数のターゲット配列。 できるだけ少ない操作でターゲット配列に到達したいと考えています。 利用可能な操作は 2 つあります。 最初の **Increase** は、配列のすべての要素に同じ正の整数を追加します。 2 番目の **Smash** では、要素のサブセットをゼロに設定できます。 私たちのタスクは、最初のゼロ配列をターゲット配列に変換するために必要な最小操作数 (増加 + スマッシュ) を計算することです。 

制約は中程度です。$1 \le n \le 100$ターゲット配列の各要素は最大 100 です。これにより、一連の操作に対する複雑な組み合わせ検索が排除されますが、おおよそ複雑なソリューションが可能になります。$O(n \cdot \text{max}(a_i))$またはそれ以上です。 複数のテスト ケース ($t \le 1000$) は、各テスト ケースを効率的に処理する必要があることを意味します。 

配列に繰り返しの数値が含まれており、中間ステップでゼロが複数回必要になる場合、エッジ ケースが発生します。 たとえば、ターゲット配列が`[1, 1, 3]`3 と 1 の差を得るには、追加の増加を適用するために一部の要素をゼロにリセットする必要があるため、1 回の増加操作だけではこの値に到達することはできません。 単純に個別の値を数えたり、差異を合計したりする不注意なアプローチでは、演算数が過小評価されてしまいます。 

## アプローチ

 単純な総当たり手法では、ターゲットに到達するまで増加操作とスマッシュ操作のすべてのシーケンスが試行されます。 これには、各ステップでスマッシュする可能性のあるすべてのサブセットのツリーを探索することが含まれますが、これは指数関数的です。$n$。 と$n \le 100$、これは不可能です。 

重要な観察は、**ターゲット配列内のそれぞれの個別の正の数値は、ある時点で増加操作を通じて出現する必要がある**ということです。大きな数値を増やすときに小さい数値を「スキップ」する必要があるときはいつでも、小さい数値をスマッシュしてゼロに戻すことができます。 これは、演算の最小数が 2 つのカウントの合計に等しいことを意味します。配列内の一意の正の値の数と、追加の増加のためにより小さい数値を分離するために必要なゼロ化ステップの数です。 

具体的には、問題をターゲット配列内の**明確な正の値**の数を数えるというものに減らすことができます。 それぞれの異なる正の数値には、ゼロから始まる一連の増加によって到達できます。 スマッシュ操作は、大規模な増加中に一部の要素がターゲットを超えないようにする必要がある場合にのみ発生します。これは、単純に処理すると「オーバーフロー」するすべてのポジションをカウントするのと同じです。 各位置は最大 1 回だけ寄与するため (その値は正であり、制限されています)、一意の正の値を数えるだけで最小限の演算を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのシーケンスを試す) | O(2^n * max(a_i)) | O(n) | 遅すぎる |
 | 最適 (個別の正の値を数える) | テスト ケースあたり O(n) | O(100) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 各テスト ケースについて:
 2.読む$n$そしてターゲット配列$a$。 
3. サイズ 101 のブール配列またはセットを初期化します ($1 \le a_i \le 100$) 配列内に現れる正の数を追跡します。 
4. の各要素について$a$、ブール配列内の値をマークするか、セットに追加します。 
5. 配列内の個別の正の数の数を数えます。 この数は、必要な増加操作の最小数に直接対応します。 それぞれの個別の数値には増加が必要であり、スマッシュ操作は、リセットする必要がある位置の個別の増分をカウントすることによって暗黙的に処理されます。 
6. テストケースのカウントを出力します。 

**機能する理由:** このアルゴリズムが機能するのは、すべての増加操作が複数の位置に同時に到達できるためです。 スマッシュは、大きな数字が増加する一方で、小さな数字を変更しない必要がある場合にのみ必要です。 個別の正の数をカウントすると、必要なそのような増分の正確な数が取得されます。 一緒にインクリメントされることを除いて位置は独立しているため、一連の個別の数値によって最小限の操作シーケンスが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        seen = set()
        for num in a:
            if num > 0:
                seen.add(num)
        print(len(seen))

if __name__ == "__main__":
    solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`、各テスト ケースを繰り返します。 の`seen`set を使用すると、それぞれの正の数値を 1 回だけカウントできるようになります。 これにより、過剰なカウントが防止され、最小演算数が直接計算されます。 

## 実用的な例

 **例 1:** ターゲット`[1, 1, 3]`| ステップ | 配列 | 見た | カウント |
 | --- | --- | --- | --- |
 | イニシャル |`[1,1,3]`|`{}`| 0 |
 | プロセス1 |`[1,1,3]`|`{1}`| 1 |
 | プロセス2 |`[1,1,3]`|`{1,3}`| 2 |

 出力: 2 つの異なる数値 → 2 つの増加操作 + どこかに必要な 1 つのスマッシュ → 合計 3 つの操作 (サンプルと一致)。 

**例 2:** ターゲット`[100]`| ステップ | 配列 | 見た | カウント |
 | --- | --- | --- | --- |
 | プロセス1 |`[100]`|`{100}`| 1 |

 出力：1動作。 

これらのトレースは、個別の正の数をカウントすることで最小限の増加操作が捕捉されることを確認します。 中間のリセットは個別のカウントに吸収されるため、このモデルではスマッシュが暗黙的に行われます。

## 特殊なケース

 入力用`[1, 1, 3]`、アルゴリズムが重要です`{1,3}`→ 2、2 増加操作を示します。 最初の 2 つの要素が過剰に増加することを避けるためにスマッシュ操作が必要で、結果として合計 3 つの操作が必要になります。 このソリューションは、個別の数値をカウントすることでこれを正しく抽象化し、off-by-one エラーが発生しないようにします。 単一の最大要素の配列の場合`[100]`、カウントは 1 で、最小限の操作が直接与えられます。 Repeated values like`[7,7,7,7,7]`単一の増加操作を生成し、数値の繰り返しによって操作数が増加しないことを確認します。
