 ## 解決策
 ## 問題の理解

 重み付けされたエッジを持つ木が与えられ、特定の「勝利の色」が少なくとも一定の値以上の最小コストを持つように、頂点に非負の重みを割り当てるように求められます。`l`、頂点の重みの合計を可能な限り小さく保ちます。 勝利するカラーリングは、少なくとも 1 つの頂点が赤であるカラーリングであり、カラーリングのコストは、赤い頂点の重みの合計と、異なる色の頂点を接続するエッジの重みの合計となります。 

各クエリはしきい値を提供します`l`そして、最適な勝利カラーリングのコストが少なくとも`l`。 

課題は高い制約にあります。頂点とクエリの数はそれぞれ最大 250,000 まで可能であり、すべてのテスト ケースの合計も 250,000 に制限されます。 これは、考えられるすべての色付けを反復しようとする単純なアプローチは実行不可能であることを意味します。 ツリーごとにほぼ線形の時間とクエリごとの対数または定数時間で機能するアプローチが必要です。 

難しいのは、コスト関数にはカラーリングに応じて頂点の重みとエッジの寄与の両方が含まれることです。 単純な実装では、頂点の重みを任意に割り当てたり、各クエリのカラーリングをシミュレートしようとしたりする可能性があり、大きな入力ではすぐに失敗します。 もう 1 つの微妙な問題は、重みの大きいエッジがコストを支配する可能性があり、最適な頂点の割り当てがツリー内の最大のエッジに依存する可能性があることです。 

たとえば、重み 10 と 1 のエッジで線形に接続された 3 つのノードからなる小さなツリーと、クエリ`l = 15`には、最小コストが少なくとも 15 になるように頂点の重みを分散する必要があります。すべての頂点の重みを 0 に割り当てると失敗します。異なる色の頂点間のエッジが最適なカラーリングに寄与する 11 は 15 未満であるためです。このようなエッジが優勢なケースを正しく処理することが重要です。 

## アプローチ

 ブルート フォース アプローチでは、すべての可能なカラーリングを試し、特定の頂点ウェイトのセットに対する最小コストを計算し、そのコストに達するまで頂点のウェイトを繰り返し増加させます。`l`。 これは理論上は機能しますが、ツリーごとに O(2^n) であり、n が 250,000 までの場合は明らかに不可能です。 

線形の解決策を明らかにする観察は、問題が **ツリーとそのエッジの構造に基づく頂点の重みの貪欲な分布**に帰着するということです。 与えられた頂点の重みの合計に対する最小勝利カラーリング コストを最大化する最適な方法は、隣接するエッジの重みの合計に比例する重みを頂点に割り当て、クエリのしきい値を満たすように均等に重みを増やすことです。 

より具体的には、2 つの端点の色が異なるときに各エッジを最小コストに寄与するものとして扱うと、ツリーをパスの観点から考えることができます。 最小の勝利カラーリングコストは、最大エッジ重みの関数として表すことができます。 これにより、累積的なエッジ寄与のソートされた配列を事前計算し、最小コストを上回るために必要な頂点の重みの最小合計を見つけて各クエリに答えることができます。`l`。 したがって、問題は **エッジの重みの並べ替えられたリストのプレフィックスの合計** に帰着します。これは、ツリーあたり O(n log n) とクエリあたり O(log n) で効率的に実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 (貪欲なエッジベース) | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次のツリーを読み取ります。`n`ノードと`n-1`エッジ。 
2. すべてのエッジの重みをリストに収集し、降順に並べ替えます。 最大のエッジが最小の勝利色コストを支配します。 
3. ソートされたエッジの重みのプレフィックスの合計を計算します。 これにより、最大の k 個のエッジをカバーするように頂点の重みを割り当てると、合計のエッジ寄与を迅速に決定できます。 
4. 各クエリについて`l`、勝利の最小着色コストが少なくとも以下であることを確認する必要があります。`l`。 これは、k 個の最大のエッジ寄与の合計と最小の赤色の頂点の重みが一致または超えるような、頂点の重みの最小合計を見つけることになります。`l`。 
5. プレフィックス合計配列で二分検索を使用して、クエリを満たすために頂点の重みで「カバー」する必要がある上端の数を見つけます。 到達するために必要な追加の頂点重み寄与を追加します。`l`プレフィックスの合計だけでは不十分な場合。 
6. 各クエリの頂点の重みの合計を出力します。 

機能する理由: このアルゴリズムが機能するのは、どのような優れたカラーリングでも、最小コストが赤い頂点の重みまたは色の境界を横切るエッジによって決まるためです。 エッジをソートし、プレフィックスの合計を考慮することで、どの色付けにも最大のエッジからの寄与が含まれる必要があることが保証され、最小コスト要件が確実に満たされます。 最初に最大のエッジをカバーするという貪欲な選択により、必要な頂点の重みの合計が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_left

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        edges = []
        for _ in range(n - 1):
            u, v, w = map(int, input().split())
            edges.append(w)
        edges.sort(reverse=True)
        prefix = [0]
        for w in edges:
            prefix.append(prefix[-1] + w)
        q = int(input())
        queries = [int(input()) for _ in range(q)]
        for l in queries:
            # binary search the minimal number of edges to cover
            if prefix[-1] >= l:
                idx = bisect_left(prefix, l)
                print(prefix[idx])
            else:
                # need to add extra weight to vertices
                print(l)
                
if __name__ == "__main__":
    solve()
```コードはすべての入力を効率的に読み取ります。`sys.stdin.readline`そしてエッジの重みを収集します。 エッジを降順に並べ替えると、プレフィックスの合計の計算が可能になり、二分検索によるクエリに答えるのに役立ちます。 微妙な部分は、合計のエッジの重みが不十分な場合のクエリの処理です。 頂点に追加の重みを割り当てるだけです。 これにより、勝利したカラーリングのコストが最小値に達することが保証されます。`l`。

## 特殊なケース

 ツリーがエッジ [1,1,1] でクエリ l=5 のラインである場合、プレフィックスの合計は 3 にしか達しないため、5 に達するには追加の頂点の重みを追加する必要があります。アルゴリズムは 5 を正しく出力し、エッジの重みだけでは不十分な場合を処理できることを確認します。 

ツリーに重み 10 の単一エッジがあり、クエリが l=15 の場合、出力は 15 となり、必要に応じて頂点の重みが追加されることが再びわかります。 これは、前に説明したエッジ優位のケースに対処します。
