 ## 解決策
 ## 問題の理解

 ヴァーニャは自分のトランプのサブセットを見つけました。各カードには以下の整数がラベル付けされています。$-x$そして$x$。 彼はすべてのカードの合計がゼロになることを望んでいます。 そのゼロ和を達成するために彼が見つけるべき追加のカードの最小数を決定する必要があります。 

入力により 2 つの数値が得られます。$n$そして$x$、彼が見つけたカードの数と、カードに許可される最大絶対値を表します。 次に、のリスト$n$整数は、見つかったカードの値を表します。 出力は単一の整数、つまり合計をゼロにするために必要な新しいカードの最小数です。 

制約は小さいです。$n \le 1000$そして$x \le 1000$。 これにより、アルゴリズムを線形時間で実行できるようになります。$n$。 見つかったカードからヴァーニャが得られる絶対値の最大値は次のとおりです。$1000 \times 1000 = 10^6$、標準の整数型で安全に処理されます。 

微妙なケースとしては、見つかったカードの合計がすでに以下で割り切れる場合があります。$x$またはそれより小さい$x$。 たとえば、Vanya が値 7 のカードを 1 枚見つけた場合、$x = 3$, 彼は 1 枚のカードではバランスを取ることができないため、複数のカードを使用する必要があります。 不注意な解決策では、合計がゼロ以外の場合、最小値が常に 1 であると想定される可能性がありますが、これは正しくありません。 

## アプローチ

 素朴なアプローチは、次の間の追加カードのすべての組み合わせを試してみることです。$-x$そして$x$合計がゼロになるまで。 これは原理的には正しいです。なぜなら、いつでも金額を補うのに十分なカードを選択できるからです。しかし、現実的ではありません。 たとえば、合計が 1000 の場合、$x = 1$、最大 1000 枚のカードのシーケンスを探索する必要がありますが、これは組み合わせ的に爆発的です。 

重要な洞察は、重要なのは見つかったカードの絶対合計だけであることに注意することです。 あらゆる価値のカードが無限にあります。$-x$に$x$したがって、問題は次のようになります: 目標合計が与えられた場合$S$、絶対値を持つカードは最大何枚まで$x$到達するために必要な$S$? カードの最小枚数は単純に上限です。$|S| / x$。 これが機能するのは、許可された最大のカードを常に合計とは反対の方向に、ゼロに達するまで繰り返し選択できるためです。 

これにより、問題が組み合わせ検索から単純な算術計算に変換され、$O(n)$入力と$O(1)$必要なカードの枚数を計算します。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$そして$x$。 これらは見つかったカードの数とカードの最大値を表します。 必要になります$x$単一カードで行うことができる最大の調整を決定します。 
2. の配列を読み取ります。$n$見つかったカードを表す整数。 それらの合計を計算すると、$S$。 ここでの目標は、この合計をゼロに減らすことです。 
3. の絶対値を取得します。$S$、調整の方向は無関係であるためです。 の符号に応じて、プラスまたはマイナスのカードを追加できます。$S$。 
4. 分割$|S|$による$x$整数の除算を使用して、必要なフルサイズのカードの枚数を数えます。 もし$|S|$で割り切れない$x$, 残りをカバーするには追加のカードが 1 枚必要です。 
5. 計算されたカードの総数を出力します。 

これが機能する理由: 最大許容絶対値のカードを繰り返し取得することで、必要なカードの数を最小限に抑えます。 不変条件は、カードが追加されるたびに、修正する残りの合計が最大で減少することです。$x$。 天井分割を使用すると、残りの部分が次の値よりも小さくなります。$x$追加のカード1枚としてカウントされます。 これにより、最小数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
cards = list(map(int, input().split()))

total = sum(cards)
needed_cards = (abs(total) + x - 1) // x  # ceiling division
print(needed_cards)
```まず入力を読み取り、見つかったカードの合計を計算します。 表現`(abs(total) + x - 1) // x`の上限を計算します`abs(total) / x`浮動小数点演算を行わずに効率的に実行できます。 これにより、合計が正確に割り切れない場合に単純な整数の除算で発生する 1 による誤差が回避されます。$x$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, x = map(int, input().split())
    cards = list(map(int, input().split()))
    total = sum(cards)
    return str((abs(total) + x - 1) // x)

# provided samples
assert run("3 2\n-1 1 2\n") == "1", "sample 1"
assert run("3 3\n1 1 1\n") == "1", "sample 2"

# custom cases
assert run("1 1\n7\n") == "7", "single card, large sum"
assert run("4 5\n5 5 5 5\n") == "4", "sum divisible by x"
assert run("2 10\n-3 4\n") == "1", "sum small, single card covers"
assert run("5 1\n1 -1 1 -1 1\n") == "1", "alternating sum"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1\n7 | 7 | カードは 0 枚ではなく、複数枚必要です |
 | 4 5\n5 5 5 5 | 4 | 最大カードで割り切れる合計 |
 | 2 10\n-3 4 | 1 | x が剰余より大きい小さい合計 |
 | 5 1\n1 -1 1 -1 1 | 1 | 代替値、剰余処理 |

 ## 特殊なケース

 カードの合計がゼロの場合、新しいカードは必要ないため、アルゴリズムはすぐに 0 を返します。 たとえば、入力`2 5\n3 -3`与える`total = 0`、 それで`(abs(0) + 5 - 1) // 5 = 0`。 

If the absolute sum is smaller than`x`の場合、アルゴリズムは正しく 1 を出力し、1 枚のカードで十分なシナリオをカバーします。 入力用`1 5\n3`、`abs(3)/5`は 1 未満であるため、天井分割により 1 が生成されます。 

他のすべてのケースでは、天井分割により、必要な合計を超えずに常に必要な最小数のカードが選択されることが保証されます。 

このアプローチは直接的で、すべてのエッジ ケースを処理し、入力制限に合わせて簡単に拡張できます。
