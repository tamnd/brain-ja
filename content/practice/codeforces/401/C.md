 ## 解決策
 ## 問題の理解

 ゼロと 1 のマークが付いているカードのセットを、2 つのゼロが隣接せず、3 つのカードが連続しないように一列に配置するように求められます。 各タイプのカードの枚数は事前にわかっています。`n`ゼロと`m`もの。 出力は、これらの条件を満たす 0 と 1 のシーケンス、または`-1`そのような取り決めが存在しない場合。 

制約は大きく、両方とも`n`そして`m`最大 10^6 まで可能です。 これは、すべての順列を試すような解決策は実行不可能であることを意味します。 O(n + m) の解は許容されますが、二次関数はタイムアウトになります。 

エッジケースは極端な不均衡から発生します。 たとえば、0 の数が 1 よりもはるかに多い場合、すべての 0 を分離することは不可能です。これは、各 0 には、エッジを除いて両側に少なくとも 1 つの 1 が必要であるためです。 同様に、1 の数が 0 よりはるかに多い場合、どのようにインターリーブしても 3 つの連続した 1 が発生する危険があります。 たとえば、`n = 1`そして`m = 4`、単一のゼロを持つ 1 のシーケンスは 1 の 3 倍を防ぐことができないため、正しい出力は次のようになります。`-1`。 

少数のカウントも考慮する必要があります。 のために`n = 1`そして`m = 2`、唯一の有効な取り決めは、`101`または`110`。 しかし`011`ゼロ隣接ルールに違反するため、不注意な構築はたとえ小さな入力でも失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、次のすべてのシーケンスを生成しようとします。`n`ゼロと`m`それぞれを有効かどうか確認します。 順列の数は n + m で指数関数的であり、n、m の 1 秒の時間制限をはるかに超えて 10^6 までであるため、これは明らかに実行不可能です。 

重要な洞察は、シーケンスを貪欲に処理することです。 この制約では、連続する 1 は最大 2 つ、ゼロは連続して 1 つまで許可されます。 これは、残りのカウントとシーケンスの最後の要素に基づいて 1 または 0 を繰り返し追加できることを意味します。 ゼロが互いに接触しようとしている場合は、1 を挿入する必要があります。 1 が 3 つ発生するリスクがある場合は、0 を挿入する必要があります。 これにより、問題は残りのカウントに基づいて局所的な最適な選択を繰り返し行うことになり、O(n + m) で実行できます。 

シーケンスを構築する前に、実現可能性を確認する必要もあります。 ゼロの場合、それぞれは最大 2 つのゼロを区切ることができます。 1 の場合、各 0 は最大 1 組の 1 を区切ることができます。 これにより限界が与えられます。`n > m + 1`、 または`m > 2*(n + 1)`、解決策は存在しません。 これらの不等式により、そもそも不可能なシーケンスを構築することができなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+m)!) | O(n+m) | 遅すぎる |
 | 貪欲 | O(n+m) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.次のことを確認します`n > m + 1`または`m > 2*(n + 1)`。 どちらかが true の場合、出力します`-1`。 これらは、隣接制約から導出される実現可能範囲です。 
2. 空のリストを初期化する`result`シーケンスを段階的に構築します。 
3. まだ 0 または 1 が残っている間に、1 つまたは 2 つの 1 を配置するか、または 1 つのゼロを配置するかを決定します。 常に、残りの数が大きい要素を優先して配置しますが、隣接性の制約は尊重します。 具体的には、ゼロを次のゼロに続けて配置したり、3 番目に連続してゼロを配置したりしないでください。 
4. それぞれのカウントから追加された要素の数を減算します。 両方のカウントがゼロになるまで繰り返します。 
5. を変換します。`result`リストを文字列に変換して出力します。 

機能する理由: ローカル隣接ルールに違反することなく、常に大きい数の要素を配置することで、ゼロが接触したり、1 がトリプルを形成したりすることがなくなります。 実現可能性チェックにより、この貪欲なアプローチが避けられないブロックに遭遇しないことが保証されます。 各ステップでカードの総数が減少するため、アルゴリズムは O(n + m) ステップで終了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

if n > m + 1 or m > 2*(n + 1):
    print(-1)
    sys.exit()

result = []

while n > 0 or m > 0:
    if m > n:
        if m >= 2:
            result.append('11')
            m -= 2
        else:
            result.append('1')
            m -= 1
        if n > 0:
            result.append('0')
            n -= 1
    elif n >= m:
        if n > 0:
            result.append('0')
            n -= 1
        if m > 0:
            if m >= 2 and n < m - 1:
                result.append('11')
                m -= 2
            else:
                result.append('1')
                m -= 1

print(''.join(result))
```コードは最初に実現可能性チェックを実行します。 次に、貪欲ループを使用して、可能な限り最良のセグメントを常に追加します。 2 つの要素の追加`'11'`は 3 つ連続しない場合にのみ使用されます。 これにより、隣接関係の制約が全体にわたって確実に維持されます。

 ## 特殊なケース

 のために`n = 1`、`m = 4`、アルゴリズムは最初に実現可能性をチェックします。`m = 4 > 2*(n + 1) = 4`境界にあります。 実際には、4 つの 1 を 1 つのゼロだけで区切って配置することは不可能です。 アルゴリズムは出力します`-1`すぐに。 

のために`n = 5`、`m = 2`、`n > m + 1 = 3`したがって、アルゴリズムは次のように出力します。`-1`。 ゼロ隣接ルールに違反するシーケンスを構築する試みは行われません。 

等しいカウントの場合は次のようになります`n = 3`、`m = 3`、アルゴリズムは要素を交互に配置し、隣接する 0 や 3 つの 1 を維持しません。 貪欲な配置はこれらの境界シナリオを正しく処理し、堅牢性を確認します。
