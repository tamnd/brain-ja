 ## 解決策
 ## 問題の理解

 コンテストのプラットフォームには、ラウンドごとに開始時間ごとに連続した番号が付けられます。 ラウンドは、スタンドアロンの Div2 ラウンド、または Div2 が識別子を取得する同時ラウンドのペアのいずれかになります。`i`そして Div1 は識別子を取得します`i + 1`。 

セレハは Div2 ラウンドのみに参加します。 現在彼はラウンドに参加中です`x`、そしてこの前に彼は正確に参加しました`k`初期の Div2 ラウンド。 以前の参加のそれぞれについて、彼は次のいずれかを覚えています。 

- 識別子付きのスタンドアロン Div2 ラウンド`a`- または同時ペア`(a, a + 1)`どこ`a`Div2識別子です

 記憶されているすべての識別子は次の値より小さいです`x`。 

欠けている情報は、彼がスキップしたラウンドに関するすべてです。 一部の未使用の識別子はスタンドアロンの Div2 ラウンドに対応する場合があり、一部は同時ペアに属する場合があります。 以下を計算する必要があります。 

- セレジャが逃した可能性のある Div2 ラウンドの最小数
 - セレジャが逃した可能性のある Div2 ラウンドの最大数

 制約はわずかです。 すべての識別子は 4000 未満であるため、`O(x^2)`解決策は快適に通過するでしょう。 つまり、課題はパフォーマンスではなく、番号付けルールを正しくモデル化することです。 

危険なのは、識別子の意味を理解することです。 スタンドアロンの Div2 ラウンドは 1 つの識別子を消費します。 同時ペアは 2 つの連続する識別子を消費します。小さい方が Div2 ラウンド、大きい方が Div1 ラウンドです。 

不注意な実装では、未使用の識別子がすべて独立して扱われることがよくありますが、連続する 2 つの識別子が実際には 1 つの同時ペアに属している可能性があるため、これは誤りです。 

次の例を考えてみましょう。```
x = 8
known rounds:
2 2
2 5
```使用される識別子は次のとおりです。`{2, 5}`。 未使用の識別子は次のとおりです。`{1, 3, 4, 6, 7}`。 

逃した Div2 ラウンドを最大化すると、すべての未使用の識別子をスタンドアロンの Div2 ラウンドにして、5 つの逃したラウンドを与えることができます。 

Div2 ラウンドの逃しを最小限に抑えるには、可能な限り識別子を同時ペアに結合する必要があります。 

-`(3,4)`同時に 1 つのペアにすることができます
 -`(6,7)`別の同時ペアにすることもできます
 -`1`スタンドアロンのままでなければなりません

 つまり、Div2 ラウンドを逃したのは 3 回だけです。 

もう 1 つの微妙なケースは、記憶された同時ペアが隣接する識別子をブロックする場合です。```
x = 6
known:
1 2 3
```識別子`2`そして`3`はすでに同時ペアによって占有されています。 追加ペアリングはできません`(1,2)`または`(3,4)`識別子が 2 つの異なるラウンドに属することはできないためです。 

正しく処理するには、どの識別子がすでに使用されているかを追跡する必要があります。 

## アプローチ

 強引なアイデアは、記憶されているラウンドと一致するすべての有効なコンテスト スケジュールを再構築し、各再構築でセレジャがスキップした Div2 ラウンドの数をカウントすることです。 未使用の識別子はすべて次のいずれかになる可能性があるため、

 - スタンドアロンの Div2 ラウンド
 - 同時ペアの一部
 - または同時ペア内の Div1 のみの識別子

 可能性の数は指数関数的に増加します。 

たとえば、未使用の識別子が 2000 個ある場合、すべての割り当てを試みるのは絶望的です。 

重要な点は、完全なスケジュールは決して必要ないということです。 未使用の識別子の中に Div2 ラウンドがいくつ存在するかだけを考慮します。 

すべての識別子に次の値より小さいマークを付けるとします。`x`すでに入力に表示されています。 残りの識別子はすべて無料です。 

最大の答えを得るには、戦略は明らかです。 すべての無料の識別子は、スタンドアロンの Div2 ラウンドになる可能性があります。 このような選択はそれぞれ、Div2 ラウンドを 1 回逃す原因となり、この構築を妨げるものは何もありません。 したがって、最大値は空き識別子の数と同じになります。 

貪欲なアイデアが現れる場所に最小限の答えがあります。 

同時ペアは 2 つの連続する識別子を消費しますが、寄与するのは 1 つの Div2 ラウンドのみです。 したがって、Div2 ラウンドの逃しを最小限に抑えるには、自由な識別子間でできるだけ多くの同時ペアを作成する必要があります。 

これは単純な区間ペアリングの問題になります。 

- 識別子を左から右にスキャンします
 - 2 つの連続する識別子が両方とも空いている場合は常に、それらをペアにします
 - それ以外の場合は、現在の識別子をスタンドアロンの Div2 ラウンドとして残します。 

この貪欲さが機能するのは、2 つの空き連続 ID をペアにすることで常に Div2 ラウンド数が 1 つだけ減り、後で ID を使用してもより良い機会を生み出すことができないためです。

 ## アルゴリズムのチュートリアル

 1. ブール配列を作成する`used`からの識別子の場合`1`に`x - 1`。 
2. 覚えているラウンドの説明をすべて読みます。 
3. 説明がスタンドアロン Div2 ラウンドの場合`2 a`、マーク識別子`a`使用済みとして。 
4. 記述が同時ペアの場合`1 a b`、両方にマークを付けます`a`そして`b`使用済みとして。 
5. からの識別子の数を数えます。`1`に`x - 1`未使用です。 このカウントは、失敗した Div2 ラウンドの最大可能数です。 

すべての未使用の識別子は、独立してスタンドアロンの Div2 ラウンドになることができます。 
6. 最小の答えを計算するには、次の識別子をスキャンします。`1`に`x - 1`。 
7. 現在の識別子がすでに使用されている場合は、スキップします。 
8. それ以外の場合は、次の識別子が存在し、未使用であるかどうかを確認します。 

両方が空いている場合は、それらから同時に 1 つのペアを作成します。 答えを 1 つ増やし、両方の識別子をスキップします。 
9. ペアリングが不可能な場合、現在の識別子はスタンドアロンの Div2 ラウンドになる必要があります。 答えを 1 増やして 1 つ先に進みます。 

### なぜ効果があるのか

 すべての未使用の識別子がスタンドアロンの Div2 ラウンドを表す可能性があるため、最大の構成は簡単です。 

最小限の構造では、不変条件は、2 つの連続する空き識別子に遭遇するたびに、それらのペアを常に最適にするということです。 ペアは 2 つの識別子を消費しますが、失敗した Div2 ラウンドは 1 つだけです。 どちらかの識別子をペアにしないままにしても、合計をさらに減らすことはできません。 

貪欲スキャンでは、常に可能な最大数の素の連続ペアが作成されます。 すべてのペアにより、失敗した Div2 ラウンドの数が 1 ずつ減るため、これにより最終的な答えも最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, k = map(int, input().split())

    used = [False] * (x + 2)

    for _ in range(k):
        parts = list(map(int, input().split()))

        if parts[0] == 1:
            _, a, b = parts
            used[a] = True
            used[b] = True
        else:
            _, a = parts
            used[a] = True

    # maximum answer
    mx = 0
    for i in range(1, x):
        if not used[i]:
            mx += 1

    # minimum answer
    mn = 0
    i = 1

    while i < x:
        if used[i]:
            i += 1
            continue

        if i + 1 < x and not used[i + 1]:
            mn += 1
            i += 2
        else:
            mn += 1
            i += 1

    print(mn, mx)

solve()
```の`used`配列には、記憶されたラウンドに既に属しているすべての識別子が記録されます。 同時ラウンドの場合、どちらの識別子も後で再利用できないため、両方の識別子をマークします。 

最大の答えは、未使用の識別子の数だけです。 それらのそれぞれは、スタンドアロンの Div2 ラウンドを表すことができます。 

最小の答えは貪欲スキャンを使用します。 微妙な部分は境界条件です`i + 1 < x`。 識別子`x`それ自体は現在のラウンドに属しており、再利用できないため、厳密に次の値よりも小さい識別子のみが使用されます。`x`案件。 

もう 1 つの簡単な間違いは、ペアを形成した後に両方の識別子をスキップするのを忘れることです。 ペアリングしたら`(i, i + 1)`、両方の識別子が消費されるため、再度参加することはできません。

## 特殊なケース

 最小の有効な入力を考えてみましょう。```
1 0
```より小さい識別子はありません`1`, したがって、スキャン範囲は空です。 アルゴリズムは次のものを正しく生成します。```
0 0
```よくあるオフバイワンのバグに誤って識別子が含まれている`x`それ自体とリターン`1 1`。 

ここで次のことを考えてみましょう。```
6 1
1 2 3
```識別子`2`そして`3`は、記憶された同時ペアによってすでに占有されています。 

無料の識別子は、`{1, 4, 5}`。 

貪欲スキャンは次のように動作します。 

-`1`とペアリングできません`2`、つまりスタンドアロンになります
 -`4`とペアにする`5`合計最小値は`2`。 

最大値は`3`すべての無料の識別子がスタンドアロンになる可能性があるためです。 

正しい出力:```
2 3
```記憶されているペアから Div2 識別子のみをマークするバグのある実装では、識別子が誤って認識されてしまいます。`3`は無料であり、無効なペアリングが生成されます。 

最後に、次のことを考慮してください。```
8 3
2 1
2 3
2 5
```無料の識別子は、`{2, 4, 6, 7}`。 

貪欲なプロセス:

 -`2`とペアリングできません`3`-`4`とペアリングできません`5`-`6`とペアにする`7`最小値は`3`、 ない`2`。 

これにより、連続しない空き識別子をペアにしようとする実装が捕捉されます。
