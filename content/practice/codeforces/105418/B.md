 ## 解決策
 ## 問題の理解

 文字列が与えられ、その文字を任意に並べ替えることができます。 再配置後、結果の文字列を複数の連続したブロックに分割したいと考えます。 すべてのブロックは回文でなければならず、すべてのブロックは同じ長さでなければなりません。 文字列のすべての文字を使用する必要があるため、ブロックは順列の完全なパーティションを形成します。 

この要件には 2 つの構造上の制約が隠されています。 まず、各回文に長さがある場合$m$、次に全長$n$で割り切れる必要があります$m$。 第 2 に、そのような回文が少なくとも 2 つ必要であるため、ブロックの数は次のようになります。$k = n / m$満たさなければなりません$k \ge 2$。 各ブロック内では、ブロックが前方と後方で同じように読み取られるように文字を配置する必要があり、これによりブロックごとに頻度の制約が課せられます。 

入力サイズはテスト ケース全体で大きく、全長は最大で$2 \cdot 10^5$。 これにより、考えられるすべてのパーティションを試行したり、テストごとに多くの順列を明示的に構築したりするアプローチは直ちに除外されます。 テストごとに線形または線形に近い値を超えるものは困難になります。 

ここでの単純な間違いは、いつでも選択できると仮定することです$m = 1$、単一の文字は自明の回文であるためです。 少なくとも 2 つの回文が必要なので、これは失敗します。`"a"`または`"aa"`実現可能性を慎重にチェックする必要があります。 もう 1 つのよくある間違いは、文字列全体を回文に並べ替えることができれば、答えは常に有効であると仮定することです。$k=1$、これは明示的に禁止されています。 

文字の周波数が大きく偏っている場合、より微妙なエッジケースが現れます。 例えば、`"aaaaabc"`柔軟に見えますが、約数によって異なります。$n$、奇数頻度の文字を複数の回文ブロックに均等に分散することは不可能な場合があります。 

## アプローチ

 最も直接的な観点から始めます。考えられるすべてのブロック サイズを試します。$m$。 それぞれについて$m$かどうかを確認します$n \bmod m = 0$、次に構築を試みます$k = n/m$長さの回文$m$。 修正を検証するには$m$にキャラクターを分配します。$k$それぞれの文字列を回文に配置できるかどうかを確認します。 これには、ブロックごとに奇数の頻度で出現できる文字の数を推論する必要があります。 

この強引なアプローチは、約数の数が増えるためコストが高くなります。$n$最悪の場合、候補者ごとに大きくなる可能性があります$m$、文字列全体の分布をシミュレートし、少なくとも$O(n \cdot d(n))$テストごとの動作は、全体的な制約の下では遅すぎます。 

重要な点は、実際にはすべての約数を試す必要はないということです。 代わりに、パリティの分布とグループ化能力の観点から実現可能性を理解するだけで済みます。 それぞれの長さの回文$m$中央に残り数が奇数の文字を最大 1 つ含めることができます。 したがって、全体にわたって、$k$回文、最大でも対応できます$k$半構造を構築するときに奇妙な貢献をするキャラクター。 

これにより、問題は組み合わせ構築から頻度カウントに移ります。 ブロック数の候補を試してみる$k$、導出$m = n/k$、文字頻度を使用して実現可能性をテストします。 

以来$k \ge 2$の約数を考慮するだけで済みます。$n$まで$n/2$そして実際には、可能な限りすべてのことを試すことができます$k$から$2$に$n$どこ$n \bmod k = 0$。 それぞれについて、実現可能性を確認します。$O(26)$周波数カウントを使用した時間。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 文字列内の各文字の頻度を数えます。 これが必要なのは、有効な構文は順序ではなく、各文字の数にのみ依存するためです。 
2. 可能な数のブロックを反復処理します。$k$から始まる$2$まで$n$ただし、次の値のみを考慮します。$n \bmod k = 0$。 そういったものごとに$k$、 定義する$m = n / k$。 私たちは事実上、どれだけの回文を構築するかを推測しています。 
3.固定の場合$k$、すべての回文の「奇数の中心位置」に必要な文字数を計算します。 奇数長の各回文は 1 つの中心に寄与しますが、偶数長の回文は中心に寄与しません。 したがって、奇数長ブロックの数はパリティによって決まります。$m$。 
4. 頻度カウントを使用して実現可能性を確認します。 各文字について、対称の位置を埋めるためにできるだけ多くの完全なペアを使用し、残った文字が中心の候補となります。 必要なセンターの総数は、奇数の残存容量を持つキャラクターの数を超えてはなりません。 
5. 有効な場合$k$が見つかったら、貪欲に回文を構築します。 利用可能な文字ペアから各回文の半分を埋め、必要に応じて中心を割り当て、半分をミラーリングします。 

重要な実装の詳細は、各回文を最初から個別に構築しようとするのではなく、最初にグローバルなペアのマルチセットを構築し、次にそれらをブロック全体に均等に分散する方が構築が最も簡単であるということです。 

### なぜ効果があるのか

 各回文は、その前半とおそらく中心人物によって完全に決定されます。 すべての回文の前半は、中央を除く合計文字のちょうど半分を使用します。 キャラクターをペアの貢献と残りのシングルに分離することで、ペアを均等に分散するという問題を軽減します。$k$残りのシングルが回文の数を超えないようにしながら、構造を作成します。 有効な解決策はすべて、このバランス条件を正確に満たさなければなりません。$k$周波数実現可能性チェックに合格すると、構築は常に存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(k, s):
    n = len(s)
    m = n // k
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    pairs = [[] for _ in range(k)]
    idx = 0

    # build half strings
    half = [[] for _ in range(k)]

    # distribute pairs
    for c in range(26):
        while cnt[c] >= 2:
            cnt[c] -= 2
            half[idx].append(chr(c + 97))
            idx = (idx + 1) % k

    # build full strings
    res = [""] * k
    for i in range(k):
        left = "".join(half[i])
        right = left[::-1]
        res[i] = left + right

    return res

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        freq = [0] * 26
        for ch in s:
            freq[ord(ch) - 97] += 1

        ok = False
        ans_k = -1
        for k in range(2, n + 1):
            if n % k != 0:
                continue

            cnt_odd = sum(f % 2 for f in freq)
            if cnt_odd > k:
                continue

            ok = True
            ans_k = k
            break

        if not ok:
            print(-1)
            continue

        # construct
        m = n // ans_k
        cnt = freq[:]

        pairs = []
        for i in range(26):
            pairs.extend([chr(i + 97)] * (cnt[i] // 2))

        res = [[] for _ in range(ans_k)]
        i = 0

        for ch in pairs:
            res[i].append(ch)
            i = (i + 1) % ans_k

        blocks = []
        for i in range(ans_k):
            left = "".join(res[i])
            if m % 2 == 1:
                # assign center later
                blocks.append(left)
            else:
                blocks.append(left + left[::-1])

        # assign centers if needed
        centers = []
        for i in range(26):
            if cnt[i] % 2:
                centers.append(chr(i + 97))

        if m % 2 == 1:
            for i in range(ans_k):
                c = centers.pop() if centers else 'a'
                blocks[i] = blocks[i] + c + blocks[i][::-1]

        print(m)
        print("".join(blocks))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、文字列の長さの割り切りをチェックし、奇数頻度の文字の数が回文の数を超えていないことを確認することで、有効なブロック数を特定します。 有効な構成が選択されると、文字ペアをブロック全体に均等に分散して回文を構築し、ブロック長が奇数の場合はオプションで中央の文字を割り当てます。 

微妙な点は、構築が最初に文字をペアにすることに大きく依存していることです。 これにより、構築時に個々の回文の妥当性について検討する必要がなく、対称性が保証されます。 最後のミラーリング ステップでは、検証ではなく構造的に回文プロパティを強制します。

 ## 特殊なケース

 特殊なケースの 1 つは、文字列の長さが素数の場合です。 その状況で唯一有効なのは、$k$は 1 であり、これは許可されておらず、強制的に`-1`。 アルゴリズムは次のことのみを考慮するため、これを処理します。$k \ge 2$分割する$n$、プライムの場合$n$、そんなことはない$k$存在します。 

別の特殊なケースは、ちょうど 1 つの文字が大きな奇数頻度を持つ場合に発生します。 のような文字列の場合`"aaaaab"`、奇数の数は 2 ですが、$k=2$、回文ごとに奇数の中心を 1 つ配置するのに十分な容量がまだあります。 この構造では、残りの文字が中心として割り当てられ、構造の残りの部分の対称性が維持されます。 

3 番目のエッジ ケースは、すべての文字が異なる場合です。 この場合、すべての周波数は 1 になるため、奇数のカウントは次のようになります。$n$。 以来$k$少なくとも 2 である必要があります。実現可能性には次のことが必要です$n \le k$、そうでない限り不可能です$n \le 2$。 アルゴリズムはそのようなケースのほとんどを正しく拒否し、ペアリングが可能な些細な小さな文字列のみを許可します。
