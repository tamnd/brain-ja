 ## 解決策
 ## 問題の理解

 道路で接続された都市の有向ネットワークが与えられており、各道路には、フェニックスがそれに沿って移動する場合にどれだけのモンスターと戦わなければならないかを表す非負のコストが設定されています。 フェニックスは都市 1 から出発し、一連の指示された道路を使用して都市 n に到達する必要があります。 これは、パス コストがエッジの重みの合計となる標準的な最短パス設定です。 

面白いのは、フェニックスにはモンスターの数を減らすことができる特別な操作が 1 つあるということです。 彼は、旅行全体を通じて次のオプションの 1 つを正確に選択できます。道路を 1 つ選択し、その重み w を Floor(w / 2) に置き換えるか、選択したパスに沿って連続する 2 つの道路を選択し、両方の重みを Floor(w / 2) に置き換えます。 この操作を 1 回適用した後も、通常のパスに沿って移動し、変更されたエッジの重みを蓄積します。 

目標は、単一の半減能力のパスと使用量の両方を最適に選択した後、都市 1 から都市 n までの総コストを最小限に抑えることです。 

制約は、すべてのパスに対する単純な列挙が不可能であることを直ちに示します。 最大 10^5 の都市と 2×10^5 の道路がある場合、すべてのパスの探索やエッジのすべてのサブセットの試行に依存するアプローチは、組み合わせ的に爆発的に発生します。 単一のダイクストラ実行でも実行可能ですが、複雑なのは、変更されたエッジの数とそれらが連続しているかどうかに対する状態依存性を導入する追加の「1 回限りの変更」です。 

能力の最適な使用が元のグラフの最短パス上にない場合、微妙なエッジ ケースが発生します。 たとえば、わずかに長いパスは、2 つの大きな隣接エッジを半分にすると安くなる可能性があるため、状態追跡を行わない貪欲な最短パスは失敗します。 

もう 1 つの障害モードは、半分化がエッジごとに独立していると仮定した場合です。 最大のエッジを貪欲に半分にすると、2 つの中程度のエッジを連続して半分にする方が、単一の大きなエッジを半分にするよりも全体の削減が大きくなるケースを見逃してしまいます。 

## アプローチ

 ブルートフォースのアイデアは、1 から n までのすべての可能なパスを考慮し、各パスについて 3 つのバリエーション (操作なし、1 つのエッジを半分にする、または連続する 2 つのエッジを半分にする) をシミュレートすることです。 長さ k の固定パスの場合、そのようなすべての選択肢を評価するのは O(k) です。 ただし、有向グラフ内のパスの数は n で指数関数的に増加する可能性があるため、このアプローチはすぐには実行不可能になります。 最適なパス構造は半分化が適用される場所によって異なるため、最短パスに制限しても役に立ちません。 

重要な観察は、操作の構造により、少量の固定量の追加の状態が導入されるということです。 エッジを順番にトラバースするとき、どの時点でも、その能力をまだ使用していないのか、現在「両エッジの半分化」の途中にいるのか、それとも能力がすでに使用されて完了しているのかだけを気にします。 これにより、問題はノードごとの少数の状態にわたる階層化された最短経路問題に変わります。 

展開されたグラフ上で最短パス アルゴリズムを効果的に実行します。このグラフでは、各ノードが特別な操作を使用してどの程度の距離にあるかを表す状態に分割されます。 各状態からの遷移は、通常どおりエッジを取得するか、現在のエッジで半分化を開始するか、該当する場合は次のエッジで半分化を完了するかをシミュレートします。 これは、ローカル隣接関係に関係するパス制約がグラフ状態にエンコードされる標準的な手法です。 

各都市は最大 3 つの意味のある構成になる可能性があるため、結果は最大 3n 州にわたるダイクストラのようなプロセスになります。 これにより、正確な正確性を維持しながら、複雑さを管理しやすくすることができます。

 ## アルゴリズムのチュートリアル

各都市を 3 つの状態でモデル化します。状態 0 はまだ操作が使用されていないことを意味し、状態 1 は操作を「選択された最初のエッジ」として使用し、オプションで次のエッジと組み合わせるのを待機していることを意味します。状態 2 は操作が完全に消費されたことを意味します。 

次に、これらの状態に対して最短パス アルゴリズムを実行します。 

1. 距離テーブル dist[node][state] を無限大で初期化し、dist[1][0] = 0 に設定します。これは、変更を使用せずに都市 1 から開始することを反映しています。 
2. 現在の距離によって順序付けされた優先キューを使用します。 各エントリは (現在のコスト、ノード、状態) を表します。 私たちは常に既知の最小コストを最初に拡張し、最終コストの昇順で状態を処理するようにします。 
3. 状態 (u, 0) から、3 つの異なる概念的な方法で出力エッジ (u → v, w) をトラバースできます。 普通に考えて、コスト +w で v で状態 0 に留まることもできます。 このエッジで半減操作を開始し、下限 (w/2) を支払い、v で状態 1 に移動します。これは、部分的に適用された操作を前に進めることを意味します。 
4. 状態 (u, 1) から、2 エッジ操作の最初のエッジがすでに選択されています。 エッジ (u → v、w) をトラバースするとき、この 2 番目のエッジにも半分化を適用して操作を完了します。 その遷移は、コストフロア(w/2)が追加されて、v の状態 2 に移行します。 状態 1 では次のエッジが同じパス セグメントの一部になることが強制されるため、これにより連続性が強制されます。 
5. 状態 (u, 0) から、コスト w を取ることにより、操作をまったく使用せずに v の状態 2 に単純に移動することもできます。 これは、このパスでは特別な能力を使用しない場合を表します。 
6. 状態 (u, 2) から、すべての遷移は標準的な最短パス遷移です。操作はすでに完全に使用されているため、w を追加するだけで状態 2 に留まります。 
7. 到達可能な状態がすべて処理されるまでダイクストラを続けます。 答えは、dist[n][0]、dist[n][1]、dist[n][2] の最小値です。 

主要な構造上の制限は、状態 1 が無期限に存続できないことです。 これにより、後続の 1 つのエッジに操作の解決が強制され、「2 つの連続するエッジ」の変更が 1 回だけ適用されることが保証されます。 

### なぜ効果があるのか

 有効なソリューションのどの時点でも、関連する履歴は、その操作を使用したかどうか、およびその操作の 2 エッジ バージョンを適用している最中かどうかだけです。 操作は最大でも 2 つの連続するエッジとのみ対話するため、以前のエッジに関するメモリは無関係です。 これにより、プロセスは拡張された状態空間上でマルコフ行列になります。 

ダイクストラのアルゴリズムは、すべての遷移が負でないエッジ コストを保持し、すべての有効な変更されたパスがこの拡張されたグラフ内の 1 つのパスに正確に対応するため、正確性を保証します。 逆に、展開されたグラフ内のすべてのパスは、元の問題での演算の有効な使用に対応するため、無効な構成は導入されません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline
INF = 10**30

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        g[u].append((v, w))

    dist = [[INF] * 3 for _ in range(n + 1)]
    dist[1][0] = 0
    pq = [(0, 1, 0)]

    while pq:
        d, u, st = heapq.heappop(pq)
        if d != dist[u][st]:
            continue

        if st == 0:
            for v, w in g[u]:
                nd = d + w
                if nd < dist[v][0]:
                    dist[v][0] = nd
                    heapq.heappush(pq, (nd, v, 0))

                nd2 = d + (w // 2)
                if nd2 < dist[v][1]:
                    dist[v][1] = nd2
                    heapq.heappush(pq, (nd2, v, 1))

                nd3 = d + w
                if nd3 < dist[v][2]:
                    dist[v][2] = nd3
                    heapq.heappush(pq, (nd3, v, 2))

        elif st == 1:
            for v, w in g[u]:
                nd = d + (w // 2)
                if nd < dist[v][2]:
                    dist[v][2] = nd
                    heapq.heappush(pq, (nd, v, 2))

        else:
            for v, w in g[u]:
                nd = d + w
                if nd < dist[v][2]:
                    dist[v][2] = nd
                    heapq.heappush(pq, (nd, v, 2))

    print(min(dist[n]))

if __name__ == "__main__":
    solve()
```この実装では、3 つの状態にわたる完全な距離テーブルが維持され、標準のダイクストラ ループが実行されます。 重要な点は、状態 1 では 2 エッジ操作を完了する遷移のみが許可され、無効な再利用や非連続的な適用が防止されることです。 

実装上の微妙な懸念は、状態 0 からの遷移の重複です。通常のトラバーサル、半分の開始、または操作を既に使用済みとして早期にマークするという 3 つのオプションを明示的に許可します。 この最後の遷移が必要なのは、操作がまったく使用されないか、後で使用される可能性があり、状態 2 が特別な処理が残らない「完了」状態として機能するためです。

 ### サンプル 2 トレース

 グラフには重み 5 の単一エッジ 1 → 2 があります。 

| ステップ | ノード | 状態 | コスト | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 開始 |
 | 2 | 2 | 0 | 5 | 普通にエッジを取る |
 | 3 | 2 | 1 | 2 | 端から半分に切り始める |
 | 4 | 2 | 2 | 5 | マーク操作の未使用パス |

 アルゴリズムはすべての解釈を評価し、dist[2][0]、dist[2][1]、dist[2][2] の中から最小値を選択し、2 を与えます。 

このトレースは、単一のエッジでも未変更または半分として扱うことができ、状態システムが早期にコミットすることなく両方の可能性を同時に維持する方法を示しています。 

### サンプル 1 スケッチ

 最適なパスは 3 つのエッジを順番に使用します。 このアルゴリズムは、通常のパスと、ルートの中央にある 2 つの連続するエッジにわたって操作が適用されるバリアントの両方を調査します。 状態遷移により、隣接するエッジ全体に正確に半分化が適用されるようになり、ダイクストラにより、より安価な組み合わせ構成が選択されることが保証されます。 

トレースは、アルゴリズムが事前に固定パスを想定していないことを確認します。 緩和中に操作のさまざまな配置を動的に評価します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各ノードと状態のペアは最大 1 回処理され、各エッジは一定数の緩和を誘発します。 
| スペース | O(n + m) | 隣接リストと 3 状態の距離テーブル |

 グラフのサイズは大きいですが、まばらであり、3n 状態の拡張により定数係数は小さく保たれます。 2×10^5 エッジを使用すると、これは優先キュー ダイクストラ実装の一般的な制限内に快適に収まります。

 ## 特殊なケース

 シングルエッジ グラフは、アルゴリズムによって半分化演算の即時適用が正しく許可されているかどうかをテストします。 入力あり`1 2 1`、状態 0 からの唯一の遷移にはコスト 0 の状態 1 への移動が含まれており、アルゴリズムはノード 2 で距離 0 で正しく終了します。 

のような両刃チェーン`1 → 2 → 3`重り付き`100, 100`状態 1 遷移が正しく使用されるようにします。 アルゴリズムは最初のエッジの後に状態 1 に移行し、2 番目のエッジに操作を強制的に完了させ、コストが発生します。`50 + 50 = 100`。 

競合するパスの例は、アルゴリズムが固定ルートを想定していないことを示しています。 長くても高度に削減可能なパスと、短くても高価なパスがある場合、両方がダイクストラによって並行して探索され、状態テーブルにより、元の最短パスに偏ることなく最適な組み合わせが選択されることが保証されます。
