 ## 問題の理解

 非常に構造化されたパターンに従う一連のコインの額面が与えられています。各コインは数字の 1 だけで構成されており、長さは特別な方法で増加します。 したがって、11、111、1111、11111 などの値が無限に続きます。 各テストケースには目標量が与えられます`n`を表現できるかどうかを判断する必要があります。`n`これらのコインの合計として、各コインの種類を無制限に使用できます。 

これを再構成すると、次のことを確認しています。`n`非負の整数係数を使用した、11、111、1111 などの数値の線形結合として表すことができます。 この構造は、古典的な無制限のコイン変更の実現可能性の問題を示唆していますが、重要な問題は、コインの価値が恣意的ではなく、高度に相関していることです。 

制約`n ≤ 10^9`重要なガイドです。 すべての値に対して動的プログラミングを実行しようとするソリューション`n`時間とメモリの両方ですぐに大きすぎます。 テスト ケースごとのリニア スキャンでさえ、次の場合には遅すぎます。`t = 10^4`。 

これらのコインのすべての組み合わせを列挙しようとする単純なアプローチは、方法の数が組み合わせ的に増加するため、すぐに失敗します。 コインシステムが正規ではない場合、貪欲な選択は失敗する可能性があるため、貪欲な構築に限定することさえ安全ではありません。 

微妙な特殊なケースは、多くの小さな値が形成されるべきように見えても形成できないことです。 たとえば、最小のコインは 11 で、次は 111 であるため、12 を形成することはできません。これは、11 と少量組み合わせるとすでにオーバーシュートします。 別の例は 23 で、これは 11 + 11 + 1 のような分解を試みる可能性がありますが、1 はコインとして入手できないため、そのような推論は破綻します。 

## アプローチ

 強引なアイデアは、これを標準的な無制限のコイン変更の実現可能性問題として扱うことです。 まず、次の値までのすべてのコインの価値を生成します。`n`シーケンスが急速に成長するため、これは実現可能です。 次に、古典的な動的プログラミング アプローチを実行します。`dp[x]`合計かどうかを示します`x`形成することができる。 コインごとに、到達可能な状態をすべて緩和します。`n`。 

このアプローチは、すべての組み合わせを体系的に調査するため、正しいです。 ただし、その実行時間は次の値に比例します。`O(n * number_of_coins)`、最悪の場合は`10^9 * 30`、実現可能な限界をはるかに超えています。 ビットセットの最適化にまで削減しても、依然として困難です。`10^4`テストケース。 

重要な観察は、すべてのコインが数字の 1 のみで構成されており、これにより強力な加法構造が得られるということです。 それぞれの長さのコイン`k`として見ることができます`111...1 = (10^k - 1) / 9`。 この構造は、より大きなコインは、桁の値がシフトされた小さなコインのほぼ線形結合であることを意味します。 これは、すべてのコインが独立した制約に寄与するわけではないことを示唆しています。 

より有用な視点は、最小限の少数のコインのみを使用してモジュール構造と構築可能性を考慮することです。 11 と 111 を含めると、桁シフトを伴うこれら 2 つの組み合わせによってより大きなコインを表すことができ、指定された制約までの実現可能性をチェックするためにより大きなコインが冗長になります。 

したがって、問題は次のことを確認することになります。`n`は、11 と 111 の 2 つのコイン タイプだけを使用して表すことができます。そこから、問題は、非負の整数での単純な線形ディオファントスの実現可能性チェックになります。 

大きい方のコイン (111) の可能なすべてのカウントを試し、余りが 11 で割り切れるかどうかを確認します。`n ≤ 10^9`、反復回数は最悪の場合でも最大約 10^7 ですが、ループを次のように制限することでさらに減らすことができます。`n / 111`。

 ## アルゴリズムのチュートリアル

 1. 2 つの重要なコイン値、11 と 111 を事前計算または修正します。制約までの値の到達可能性を失うことなく、これら 2 つの組み合わせで置き換えることができるため、大きなコインは必要ありません。 
2. 各テスト ケースに対して、値を取得します。`n`そして、使用する 111 コインの数を繰り返します。 範囲は 0 から`n // 111`。 各選択肢は、意味のある最大額面を使用して合計の一部を固定することを表します。 
3. 固定数の 111 コインについて、残りの値を計算します。`r = n - 111 * x`。 このステップでは、11 枚のコインのみを使用して残りを形成できるかどうかを分離します。 
4. かどうかを確認します。`r`は 11 で割り切れます。そうであれば、11 コインを使用して余りを正確に埋めることができます。これは、表現が有効であることを意味します。 
5. 選択肢がある場合`x`有効な剰余が得られると、すぐに次のように結論付けられます。`n`達成可能であり、YES と出力されます。 そのような分割が機能しない場合は、NO を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての 111 個のコインが最初にグループ化され、残りの値は完全に 11 によって生成される半グループに収まるように、有効な表現を再配置できるという事実に依存しています。11 は最小単位であるため、11 で割り切れない残りは、合計をそれ以上増やさない限り、より大きなコインを使用して修復することはできません。`n`。 これにより、111 コインにわたる検索が完全かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ok = False

        max_x = n // 111
        for x in range(max_x + 1):
            rem = n - 111 * x
            if rem % 11 == 0:
                ok = True
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、111 枚のコインの可能なカウントをループし、余りが 11 で割り切れるかどうかをチェックします。有効な分解が見つかったら、早期に終了することで、不要な組み合わせを探索することがなくなります。 

実装の微妙な詳細は、ループを境界付けるときに整数除算が使用されるようにすることです。 浮動小数点または不正な境界を使用すると、有効なケースが失われるか、パフォーマンスの問題が発生する可能性があります。

import sys, io

def run(inp: str) -> str:

 のために`n = 11`、ループはすぐに見つけます`x = 0`、余りは 11 で割り切れるので、答えは YES です。 これにより、基本単位の動作が直接チェックされます。
