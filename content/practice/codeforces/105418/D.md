 ## 解決策
 ## 問題の理解

 この問題は、非常に構造化された方法で成長する利益のプロセスを説明しています。 初日、ハーシュは何も稼げませんでしたが、翌日になると、彼の 1 日あたりの利益は、前回の増加よりも正確に 1 単位ずつ増加します。 したがって、毎日の利益の順序は累積的です。1 日目は 0、2 日目は 1、3 日目は 3、4 日目は 6 というようになります。 

私たちが実際に尋ねることは次のとおりです: 日数が与えられた場合$d$、この着実に増加する毎日の増分ルールに基づいて、その日までに累計された利益の合計を計算します。 

制約から得られる重要な観察点は次のとおりです。$d$と同じ大きさにすることができます$10^9$までありますが、$10^4$テストケース。 日々の蓄積をシミュレートするソリューションは不可能です。最大でも 1 つのテスト ケースですら$d$10億ステップを繰り返す必要があります。 

これにより、直ちに閉じた形式の公式または直接的な算術解釈が強制されます。 

微妙なエッジケースは最小の入力です。 いつ$d = 1$、利益は 0 でなければなりません。$d = 2$、利益は 1 です。最初の項を誤って 0 ではなく 1 として扱うと、単純なオフバイワンの間違いがよく発生し、数列全体が上にシフトされ、間違った基数から始まる三角数が生成されます。 

もう 1 つの潜在的な問題は、日次増分と累積利益の混同です。 このステートメントは直接的な式ではなくプロセスを定義するため、インデックスを調整せずに「最初の d 整数の合計」などの部分的なロジックのみを実装すると、小さい値に対して誤った結果が得られます。 

## アプローチ

 文字通りプロセスをシミュレーションすると、継続利益と毎日 1 ずつ増加する日次増分が維持されます。 1 日目には 0 を追加し、2 日目には 1 を追加し、3 日目には 2 を追加します。 後$d$数日かかると、合計を計算することになります。$$0 + 1 + 2 + \dots + (d-1)$$これは標準的な等差数列です。 ブルートフォース手法では、1 から 2 までループします。$d$そして毎回の増分利益を蓄積します。 これは概念的には機能しますが、実行時間は次のとおりです。$O(d)$テストケースごとに。 と$d$まで$10^9$、これは単一のクエリであっても完全に実行不可能になります。 

シーケンスの構造により、問題が単純になります。 シミュレーションする代わりに、総利益は最初の利益の合計であると認識します。$d-1$整数。 この合計は閉じた形式になります。$$\frac{(d-1)d}{2}$$これにより、反復への依存がすべて取り除かれ、各クエリが定数時間の演算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(d)$テストごと |$O(1)$| 遅すぎる |
 | 最適 |$O(1)$テストごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. Read the number of test cases$t$。 各テスト ケースは独立しており、特定の日に直接式を計算する必要があります。 
2. 入力日ごとに$d$、プロセスを 0 から始まる毎日の増分の累積和として解釈します。これにより、問題はシーケンスの合計に変換されます。$0, 1, 2, \dots, d-1$。 
3. 等差級数の公式を使用して合計を計算します。$\frac{(d-1)d}{2}$。 このステップでは反復が完全に回避され、最終結果が直接評価されます。 
4. 各テスト ケースの計算値をすぐに出力します。 

### なぜ効果があるのか

 このプロセスでは、毎日の利益を 0 から始まり毎日 1 ずつ増加する厳密な増加シーケンスとして定義します。 つまりその日には$i$、追加される増分は$i-1$。 後の合計利益$d$days は、これらすべての増分を正確に合計したものです。 これは線形等差数列を形成するため、その和は初項、終項、項数によって一意に決まります。 代替の累積順序は存在しないため、閉じた形式は有効なシミュレーションと一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        d = int(input())
        print((d - 1) * d // 2)

if __name__ == "__main__":
    solve()
```実装の中核は直接算術式です。 初日は利益がゼロであるため、1 を引くことが重要です。これは、一連の貢献が次の時点で終了することを意味します。$d-1$、 ない$d$。 整数除算を使用すると、浮動小数点の精度の問題が発生せずに正確さが保証されます。 

テスト ケースのループは簡単で、各クエリは一定時間で処理されます。

 ## 特殊なケース

 のために$d = 1$、増加のシーケンスは、単一の 0 寄与を除いて空です。 式は次のようになります$(1-1)\cdot1/2 = 0$、期待される結果と正確に一致します。 

のために$d = 2$、増分は 0 と 1 で、合計は 1 になります。式は次のようになります。$(2-1)\cdot2/2 = 1$、自明ではない最小のケースで正しさを確認します。 

非常に大きい場合$d$、 のような$10^9$、任意精度の整数のため、Python では乗算は安全です。 固定幅言語では、これには 64 ビットのストレージが必要ですが、中間ステップが 64 ビットを超えることはありません。$10^{18}$なので、オーバーフローセーフタイプで十分です。
