 ## 解決策
 ## 問題の理解

 私たちは、各牛が正確に 1 つのコインを受け取り、割り当てられたすべてのコインの合計値が目標金額に等しくなるように、6 頭の異なる牛にコインを割り当てようとしています。$n$。 利用可能なコインは額面によって制限されています。1 から 5 までの各値に対して、ファーマー ジョンには固定の数があります。$a_x$価値のあるコインの$x$。 課題は、実現可能性だけを判断することではなく、異なる割り当てがいくつ存在するかを数えることであり、少なくとも 1 頭の牛が異なる価値のコインを受け取った場合、2 つの割り当ては異なります。 

この構造は本質的に制約のある配布の問題です。牛は別個であるため、順序が重要であり、限られたリソースのマルチセットからちょうど 6 枚のコインを選択しています。 2 つの割り当てで同じ複数セットのコイン値が使用されている場合でも、どの牛がどのコインを取得するかを交換すると、異なる有効な構成が作成されます。 

制約は小さいです。$n \le 30$、そしてそれぞれ$a_x \le 6$。 これは、牛の数もコインの数も少ないため、すべての割り当てに対する強引な攻撃が妥当であることを直ちに示します。 境界分岐のある 6 つの位置にわたる割り当てを列挙するアプローチは、すぐに終了します。 指数関数的な組み合わせまたは小さな状態空間にわたる動的計画法を含む解決策が期待されています。 

いくつかの微妙なエッジの状況が重要です。 

コインの合計が少なすぎる場合は、値を無視しても、6 つのコインを割り当てることはできません。 たとえば、すべてが$a_x = 0$の場合、次の条件に関係なく割り当ては存在しません。$n$、答えはゼロでなければなりません。 

コインが十分にあるにもかかわらず、その値が小さすぎるか大きすぎる場合でも、合計制約は失敗する可能性があります。 たとえば、すべてのコインの価値が 1 の場合、達成できる合計は 6 だけなので、$n \ne 6$結果はゼロです。 

最後に、多重度の制約が重要です。 たとえ合計が次になるような 6 つの値の有効なマルチセットが存在するとしても、$n$、利用可能なコイン数を超えてカウントしないようにする必要があります。 限られた供給を無視した単純な組み合わせのカウントは正しくありません。 

## アプローチ

 最も直接的なアイデアは、各牛に 1 頭ずつコインを割り当てることです。 牛ごとに、利用可能なコインの種類を選択し、その利用可能性を減らし、再帰的に続行します。 これは、合計制約と制限された供給制約の両方を尊重するため、問題を正確にモデル化します。 結果は単に、合計が次の値に等しい有効なリーフ割り当ての数になります。$n$。 

ただし、分岐要素は牛 1 頭あたり最大 5 つまでで、牛は 6 頭います。 最悪の場合、これは次のような事態につながります$5^6 = 15625$割り当てはすでに小さいですが、コインの入手可能性に応じた枝刈りも考慮する必要があります。 枝刈りを無視したとしても、これは計算上は簡単です。 

この問題は 6 つのラベル付きスロットに値を入力することと同等であることに気づくことで、構造をよりクリーンにすることができます。$[1,5]$、各値を使用できる回数と合計条件に関するグローバル制約が適用されます。 これは当然ながら、非常に小さな状態空間にわたる限定された深さの検索です。 

もう少し構造化されたビューは、残りのコイン数を追跡しながら、牛と残りの合計に対する動的プログラミングです。 でも、それぞれから$a_x \le 6$、メモ化を使用するか、メモ化を使用しない直接 DFS でも十分です。 

重要な洞察は、決定が 6 つしかなく、決定ごとに 5 つの選択肢があるため、状態空間が小さいため、妥当性チェックを伴うブルート フォースがすでに最適であるということです。

 | --- | --- | --- | --- |
 | 6頭の牛に対するブルートフォースDFS |$O(5^6)$|$O(1)$または$O(6)$再帰 | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは牛を 1 頭ずつ処理し、各価値のコインがまだ何枚あるか、到達する必要がある残りの金額を管理します。 

1. すべてのコインのカウントから開始します$a_1 \ldots a_5$、および目標金額$n$、牛インデックス 0 にいます。残りの合計は最初は$n$。 これは検索の初期状態を定義します。 
2. 現在の牛について、その値のコインがまだ 1 つ以上利用できる場合に限り、各コインの値を 1 から 5 まで割り当ててみます。 このステップでは、供給制約をローカルに適用します。 
3. 価値のあるコインを割り当てる場合$v$、デクリメントします$a_v$残りの合計を減らす$v$、次の牛に戻ります。 これにより、部分的な割り当てが常に実際の残りのリソースを反映するようになります。 
4. どこかの時点で残りの合計がマイナスになった場合、その分岐の探索は直ちに停止されます。 残りのコインはすべてプラスであるため、回復する方法はありません。 
5. 6 頭目の牛に到達したら、残りの合計がちょうど 0 であるかどうかを確認します。 そうであれば、これを 1 つの有効な割り当てとしてカウントします。 

正確さは、牛へのコインのすべての割り当てがこの検索ツリー内の 1 つのパスに正確に対応するという事実に依存します。 各レベルでは 1 つの牛のコインを選択し、各選択はコインの価値と入手可能性の両方によって一意に決定されます。 したがって、有効な割り当てを見逃すことも、同一の状態展開下で同じ割り当てを二重にカウントすることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    cows = 6
    values = [1, 2, 3, 4, 5]
    
    sys.setrecursionlimit(10000)
    
    from functools import lru_cache
    
    @lru_cache(None)
    def dfs(i, c1, c2, c3, c4, c5, rem):
        if rem < 0:
            return 0
        if i == cows:
            return 1 if rem == 0 else 0
        
        res = 0
        counts = [c1, c2, c3, c4, c5]
        
        for v in range(5):
            if counts[v] > 0:
                nxt = counts[:]
                nxt[v] -= 1
                res += dfs(i + 1, nxt[0], nxt[1], nxt[2], nxt[3], nxt[4], rem - (v + 1))
        
        return res
    
    print(dfs(0, a[0], a[1], a[2], a[3], a[4], n))

if __name__ == "__main__":
    solve()
```この実装は、前述の再帰的構築を直接反映しています。 コインの入手可能性は将来の選択に影響を与えるため、状態には牛のインデックスと残りのコイン数の両方が含まれます。 残りの合計は、ターゲット制約を早期に強制するためのパラメータとして保持されます。 

メモ化により、異なる選択シーケンスが同じ残りのマルチセットとカウインデックスにつながる場合に発生する可能性のある繰り返し状態が再計算されなくなります。 これにより、生の再帰がすでに小さい場合でも、実行が高速に保たれます。 

よくある落とし穴は、牛が別個であることを忘れることです。これにより、階乗で除算したり、組み合わせカウントを誤って使用したりする可能性があります。 ここでは、各牛の位置を注文どおりに明示的に扱うため、正規化は必要ありません。

 ## 特殊なケース

 エッジケースの 1 つは、コインの総数が不十分な場合です。 入力用`n = 6, a = (0,0,0,0,0)`の場合、DFS は牛 0 では移動が不可能であることをすぐに検出するため、再帰は 0 を返します。これにより、リソースが存在しないとすべてのパスが正しくブロックされることが確認されます。 

もう 1 つのケースは、コインは存在するが、必要な金額と一致しない場合です。 例えば、`n = 7, a = (6,0,0,0,0)`すべての牛に値 1 のコインを強制的に取得させ、リーフ レベルで合計 6 を生成しますが、7 には到達しません。アルゴリズムは、残りの合計 1 で深さ 6 に到達し、すべてのパスを拒否します。 

最後の微妙なケースは、多くの組み合わせが存在する過剰なコインです。 各割り当ては牛全体にわたる個別の順序付けされたシーケンスとして扱われるため、DFS は追加の組み合わせ補正を行わずに各順列を自然にカウントし、意図した個別性の定義と一致します。
