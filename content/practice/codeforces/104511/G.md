 ## 問題の理解

 私たちは、人が時計をチェックする一連の瞬間を追跡しています。 各チェックは、最初の遅延から始まり、前のチェック時間とステップ番号の小さな周期関数に基づいて展開される繰り返しによって決定された時間に行われます。 

各チェック時間では、完全なタイムスタンプは気にしません。 私たちが気にするのは、時計が示す内容、つまり現在時刻のモジュロだけです。$m$。 その表示値が最大でも$x$、「休憩」としてカウントします。 まさにその後$n$このようなチェックを行うとプロセスが停止し、中断が発生した回数を報告する必要があります。 

重要な問題は、次のチェック時間が前回の時間全体に依存するのに、決定は時間の剰余にのみ依存することです。$m$。 これは、生の時間は際限なく増加し、非常に大きな値に達する可能性があるため、絶対値ではなくモジュラー演算ですべてを追跡するように努めるべきであることを直ちに示唆しています。 

制約により、すべての総当たりシミュレーションが行われます。$n$不可能な手順の場合$n$が大きいため、再発の構造には強い繰り返しまたは周期性が含まれている必要があります。 もう 1 つの微妙な点は、更新ルールが次のものに依存することです。$i \bmod c$、モジュロと相互作用する小さな繰り返しパターンを導入します。$m$州。 

単純なシミュレーションでは、次回は前回から直接計算されます。 これは論理的には正しいですが、次の場合には失敗します。$n$最大で必要になるため、サイズは大きくなります。$10^9$トランジション。 

不注意な最適化でよくある失敗例は、モジュロのみを使用して繰り返しを減らそうとすることです。$m$フルタイムがモジュロとどのように相互作用するかを理解していません。 漸化式では乗算が混合されます。$m-1$小さな追加摂動があり、符号反転効果が欠けていると、不正確な遷移が発生します。 

たとえば、次のように誤って仮定した場合、$z_i \bmod m$が必要であり、次のように更新しようとします$(m-1)z_i \bmod m = z_i \bmod m$、それらはモジュロの本質的な否定動作を失います。$m$、シーケンスが完全に変わります。 

## アプローチ

 直接シミュレーションによりフルタイムを維持$z_i$。 各ステップが適用されます$$z_{i+1} = (m-1)z_i + a(i \bmod c)^2.$$これは明らかに小規模な場合に機能します$n$、しかし、の値は$z_i$成長が非常に早く、保管することさえ不要になります。$z_i \bmod m$休憩を数えることが重要です。 

重要な観察は、モジュロの下で遷移が大幅に簡素化されることです。$m$。 以来$m-1 \equiv -1 \pmod m$、次のようになります。$$z_{i+1} \bmod m = (-z_i + a(i \bmod c)^2) \bmod m.$$したがって、定義すると$t_i = z_i \bmod m$の場合、プロセスは純粋に剰余に対する再帰になります。$$t_{i+1} = (a(i \bmod c)^2 - t_i) \bmod m.$$これは、周期的な外部期間によって駆動される、符号が交互になる線形反復です。$c$。 符号の反転は重要な構造です。これは、状態が「反転と小さな値の追加」を交互に繰り返すことを意味します。 

交互の符号を削除するには、シーケンスを偶数インデックスと奇数インデックスに分割します。 繰り返しを 2 回適用すると、符号はキャンセルされます。$$t_{i+2} = t_i + (f_{i+1} - f_i) \bmod m,$$どこ$f_i = a(i \bmod c)^2$。 

これで、各パリティ クラスは純粋な加算プロセスになります。 増分は以下にのみ依存します$i \bmod c$、つまり、毎回繰り返されます$c$ステップ。 これにより、シーケンスは最大でも周期で周期的になります。$2c$。 以来$c \le 1000$、1 つの完全な期間の長さを明示的に計算できます。$2c$を繰り返してすべてをカバーします$n$ステップ。 

1 つの期間の値がわかったら、区切りを数えるということは、それらの値がいくつあるかを数えるということになります。$\le x$に完全な期間が何個収まるかを乗算します。$n$、残りを加えます。

 ## アルゴリズムのチュートリアル

 私たちは完全に残基を扱います$t_i = z_i \bmod m$。 

1. から始める$t_1 = b \bmod m$。 初めての時計観測です。 
2. コンピューティング$t_{i+1} = (a(i \bmod c)^2 - t_i) \bmod m$のために$i = 1$まで$2c$。 

に止まります$2c$この長さは、システムの繰り返し動作を完全に捉えるのに十分であるためです。 
3. すべての値を保存する$t_1, t_2, \dots, t_{2c}$そして何個あるか数えてください$\le x$。 この値を呼び出します`cnt_period`。 
4. 完全な期間の長さを計算します。$2c$に適合する$n$。 させて`full = n // (2c)`。 
5. 乗算: それぞれの完全な期間は同じ数の休憩に寄与するため、加算します。`full * cnt_period`。 
6. 残りの部分をシミュレートします$n \bmod (2c)$ステップを実行し、それぞれの貢献を個別に追加します。 

なぜそれが機能するのかというと、2 つの事実があります。 第 1 に、剰余の反復は現在の剰余とステップ インデックスの決定論的周期関数にのみ依存します。 第 2 に、2 つのステップの後、符号効果がキャンセルされ、進化が有界の周期的増加シーケンスを持つ純粋な加算システムに変わります。 これにより、システム全体が毎回繰り返すことになります。$2c$したがって、状態シーケンスは周期的であり、ブレークのカウントも周期的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, a, b, x, c = map(int, input().split())

        def f(i):
            r = i % c
            return (a * r * r) % m

        max_len = min(n, 2 * c)

        tvals = [0] * (max_len + 1)
        tvals[1] = b % m

        for i in range(1, max_len):
            tvals[i + 1] = (f(i) - tvals[i]) % m

        cnt = 0
        for i in range(1, max_len + 1):
            if tvals[i] <= x:
                cnt += 1

        if n <= max_len:
            print(cnt)
            continue

        full = n // max_len
        rem = n % max_len

        ans = full * cnt
        for i in range(1, rem + 1):
            if tvals[i] <= x:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、最大でも 1 つの完全なサイクルの長さの剰余シーケンスのみが保存されます。$2c$。 遷移ではモジュラー形式を直接使用するため、大きな整数の処理が回避されます。 

繰り返し定義と完全に一致するように、インデックス付けは 1 から始まるように維持されます。 機能$f(i)$定期的な寄与を計算します$a(i \bmod c)^2$、常に剰余を減算$m$。 

最終的な答えは、プロセスを完全なサイクルと残りのプレフィックスに分割することによって組み立てられ、それ以上のステップがないことが保証されます。$O(c)$シミュレーションが必要です。

 ## 特殊なケース

 いつ$c = 1$、 用語$i \bmod c$は常にゼロであるため、再帰は次のように単純化されます。$t_{i+1} = -t_i$。 シーケンスは 2 つの値の間で決定論的に切り替わり、アルゴリズムはこれを計算された値内で正確にキャプチャします。$2c = 2$期間。 

いつ$b \ge m$、初期値は剰余として減算されます$m$。 実装は明示的に適用されます$b \bmod m$、開始時間がモジュラスを超えた場合でも状態が有効であることを保証します。 

いつ$x = m-1$、すべての残余はブレークとしてカウントされます。 定期的なカウント方法では、例外なく各サイクルのすべての位置がカウントされるため、正しい合計が生成されます。
