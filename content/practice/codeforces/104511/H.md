 ## 解決策
 ## 問題の理解

 いくつかのセルには木があり、他のセルには何もない地面があるグリッドが与えられています。 目標は、すべてのツリーが最終的に削除されるように、すべてのツリー セルに「日番号」を割り当てることであり、スケジュールでは重要な制約が尊重されます。つまり、ツリーを削除できるのは、現在グリッドの境界から空のセルを通って到達可能な日にのみです。 

一日あたりの作業員の数は限られているため、たとえ多くの木が伐採対象となったとしても、$k$そのうちの1つは同日にカットすることができます。 木は数日かけて削除され、木が削除されると空になり、他の木に到達できるようになります。 

出力は、すべての樹木セルに伐採日のラベルが付けられ、到達可能条件と 1 日あたりの作業員制限の両方を尊重しながらすべての樹木を除去する有効なスケジュールを形成します。 有効なスケジュールを自由に選択できますが、日数は最小限に抑えたいと考えています。 

主要な構造上の制約は、「除去可能である」ということは、空きスペースを通した境界への接続に依存しており、樹木が除去されると動的に変化するということです。 そのため、アクセシビリティがどのように進化するかを明示的にモデル化しない限り、単純な貪欲戦略は信頼性が低くなります。 

制約は大きく、多くのテスト ケースにわたってグリッドは最大 500 x 500 になります。 つまり、1 日ごとまたはツリーごとに到達可能性を最初から再計算することはできません。 ステップごとにフラッド フィルまたは BFS を繰り返し実行するソリューションは、非常に遅すぎます。 

木が他の木に囲まれていても、複数回削除しないと到達できない場合、微妙なエッジ ケースが発生します。 到達可能性は静的ではないため、最初の到達可能性に基づいて早期に割り当てるという単純な戦略は失敗します。 

## アプローチ

 ブルートフォース戦略では、プロセスを毎日シミュレートします。 毎日、すべてのツリーをスキャンし、境界から空のセルまで BFS を実行し、現在到達可能なすべてのツリーにマークを付けて、最大 2 つのツリーを割り当てます。$k$そのうちの今日に至るまで。 次に、それらを削除して繰り返します。 

これはルールに直接従うため、正しいです。 ただし、各 BFS は$O(n^2)$まで繰り返します。$O(n^2 / k)$最悪の場合は 2 倍以上の複雑さになる可能性があります。 

重要な洞察は、視点を逆転させることです。 「木がいつ到達可能になるか」という観点から考えるのではなく、障害物の中にどれだけ深くネストされているかに基づいて各木に優先順位を割り当てます。 到達しにくい木は後でスケジュールする必要があります。 これは、境界からの距離のような値を計算することを示唆していますが、グラフでは木がすでに削除されていない限り、木の間を移動することはできません。 

これをグリッド上の最短経路問題としてモデル化できます。空のセルは距離 0 で、木のセルは最適なエスケープ パスに基づいて距離を継承します。 境界から空のセルまでのマルチソース BFS により、基本的な「エスケープ距離」が得られ、距離を増やすことでツリーを階層化できます。 

すべてのツリーに距離が設定されたら、この値に基づいてツリーをソートまたはバケット化します。 距離が短い木は常に、少なくとも深い木と同じくらい適格です。 次に、距離の短い順に貪欲に日を割り当てます。$k$一日あたりの木。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 日々のシミュレーション |$O(n^4)$最悪の場合 |$O(n^2)$| 遅すぎる |
 | マルチソース BFS + スケジューリング |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドをグラフに変換し、境界からの到達可能性が各ツリーの深さの概念を定義します。 

1. すべての境界セルが空である BFS キューを初期化します。 これらはすでに外部と接続されているため、出発点となります。 
2. 空のセルに対してのみ BFS を実行し、すべてのセルについて空のスペースを通る境界までの最小距離を計算します。 この距離は、そのセルがアクセスの作成にどれだけ容易に参加できるかを表します。 
3. すべてのツリー セルについて、その「アクティブ化レベル」を、それに到達できる最も近い空のセルまでの距離として定義します。 これは、周囲の木々が消滅するにつれて、どれだけ早く露出するかを直感的に測定します。 
4. すべてのツリーセルをこのアクティブ化レベルごとに分類します。 
5. アクティブ化レベルの昇順にバケットを処理します。 各バケット内で、最大で 1 つまでの日付番号を順番に割り当てます。$k$一日あたりの木。 
6. 一日がいっぱいになると$k$割り当てが完了したら、日カウンターをインクリメントして続行します。 

重要な考え方は、より小さいアクティブ化レベルのツリーは、より大きなレベルのツリーよりも早く適格になることが保証されているため、この値による順序付けが到達可能性の制約に違反することは決してないということです。 

不変条件は、ツリーを特定の日に割り当てるたびに、厳密に小さいアクティブ化レベルを持つすべてのツリーがすでにスケジュールされているということです。これは、必要な空きスペースの接続条件がすべてすでに確立されていることを意味します。 したがって、割り当てられたすべてのツリーは、スケジュールされた日またはその前に到達可能になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        grid = [list(input().strip()) for _ in range(n)]

        dist = [[-1] * n for _ in range(n)]
        q = deque()

        # start BFS from boundary empty cells
        for i in range(n):
            for j in range(n):
                if (i == 0 or j == 0 or i == n-1 or j == n-1) and grid[i][j] == '.':
                    dist[i][j] = 0
                    q.append((i, j))

        dirs = [(1,0), (-1,0), (0,1), (0,-1)]

        while q:
            x, y = q.popleft()
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < n:
                    if grid[nx][ny] == '.' and dist[nx][ny] == -1:
                        dist[nx][ny] = dist[x][y] + 1
                        q.append((nx, ny))

        trees = []
        maxd = 0
        for i in range(n):
            for j in range(n):
                if grid[i][j] == 'T':
                    d = 0
                    for dx, dy in dirs:
                        ni, nj = i + dx, j + dy
                        if 0 <= ni < n and 0 <= nj < n and dist[ni][nj] != -1:
                            d = max(d, dist[ni][nj])
                    trees.append((d, i, j))
                    maxd = max(maxd, d)

        trees.sort()

        ans = [['.'] * n for _ in range(n)]
        day = 1
        cnt = 0

        for d, i, j in trees:
            ans[i][j] = str(day)
            cnt += 1
            if cnt == k:
                cnt = 0
                day += 1

        for i in range(n):
            print(' '.join(ans[i]))

if __name__ == "__main__":
    solve()
```BFS セクションは、有効なエスケープ ルートのみを伝播するように、空のセルに制限された境界からアクセシビリティ ランドスケープを計算します。 次に、各ツリーには、隣接するアクセス可能なセルから導出された値が割り当てられ、より深いツリーがより大きな値を受け取ることが保証されます。 

スケジューリング セクションは純粋に貪欲です。ツリーが難易度によって順序付けされると、それらをサイズのバッチに割り当てます。$k$、ワーカーの制約が尊重されることを保証します。 

微妙な点は、除去を明示的にシミュレートする必要がないということです。 順序付けにより、正しい依存関係構造がすでにエンコードされています。 

## 実用的な例

 いくつかの木がすでに境界上にある小さなグリッドを考えてみましょう。 これらはすぐに距離 0 を取得するため、最初にスケジュールされます。 

| 木 | 隣接距離 | 割り当てられた日 |
 | --- | --- | --- |
 | A(エッジ) | 0 | 1 |
 | B（内側） | 1 | 1 |
 | C（内側） | 2 | 2 |

 これは、明示的なシミュレーションを行わずに、内部ツリーがどのように自然に後の日に移行するかを示しています。 

次に、完全に囲まれた木のクラスターを考えてみましょう。 最初はどれにも到達できないため、それらの距離は内側に伝播し、後のバケットに強制的に入れられます。 

これにより、BFS が各ツリーが「どのようにトラップされているか」を正しくエンコードしていることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、空の境界セルがない場合です。 その場合、BFS は空で開始され、すべてのツリーには初期アクセスがありません。 それらの距離は未定義のままであり、デフォルトでワーストケースの階層化が設定されているため、アルゴリズムはそれらを後で正しく割り当て、到達可能なツリーの後で処理されるようにします。
