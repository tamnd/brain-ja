 ## 解決策
 ## 問題の理解

 各学期に 1 つずつ、合計 2 つのスコア集が与えられます。 各学期の成績は単純にそのスコアの算術平均であり、最終成績は 2 学期の平均値の平均です。 

出演させていただくのはせいぜい`k`移動。移動すると、ある学期から 1 つのスコアが取得され、それが別の学期に転送されます。 すべての移動後、両方の学期が空になっていないことが必要です。 目標は、最終的な平均評点を最大化することです。 

したがって、この構造はシーケンス内での再配置に関するものではなく、サイズを制御しながら 2 つのバケット間で値を再分配し、サイズの逆数を含む非線形目標を最適化するものです。 

主な難しさは、1 つの要素を移動すると、両方の学期の分子と分母の両方が同時に変更されるため、移動数の影響が線形ではないという事実にあります。 

制約は大きく、最大で`2 * 10^5`すべてのテスト ケースにわたる合計要素、および最大`10^4`テスト。 これにより、可能なすべての移動回数を試行したり、操作を繰り返しシミュレートしたりするアプローチは除外されます。 テストごとに二次関数を実行すると、すぐに遅すぎます。 テストごとに線形または線形演算に近いものが必要です。 

微妙な問題は、単純に貪欲に「常に最小または最大の要素を移動する」と失敗する可能性があることです。これは、移動の限界利益が、移動される値だけではなく、現在の平均とサイズに依存するためです。 もう 1 つの落とし穴は、実際にはすべての動きが結合しているにもかかわらず、2 つの学期を独立して扱っていることです。 

## アプローチ

 ブルートフォース解釈では、最大でもすべてのシーケンスが試行されます。`k`移動し、各転送をシミュレートし、両方の平均を再計算します。 A から B へ、および B から A へ移動する移動の数だけを選択した場合でも、特定の要素が移動する組み合わせ爆発に直面します。 それはすぐに構造が指数関数的になるか、少なくとも次数が高すぎて通過できない多項式になります。 

各学期内で重要なのはその合計とその規模だけであることに気づくことで、ビューを単純化できます。 要素の同一性は、要素が移動されるかどうかによってのみ重要になります。 これは、「移動する最適な候補」が極端な値を持つ要素になるように要素を並べ替えることを示唆しています。 

方向を固定する場合、たとえば要素を A から B に移動する場合、B の平均を最大化するには、最小の要素を A から移動する必要があります。これは、小さな値を削除すると A の平均が増加し、B への低抵抗の注入も回避されるためです。 対称的に、B から A に移動するときは、B の最大の要素を移動します。 

これは重要な洞察につながります。いつでも、最適な手は常にソートされた順序の一方の端から取られるということです。 これにより、プレフィックスまたはサフィックス構造からどれだけの要素を取得するかを選択するための意思決定スペースが減ります。 

次に、両方の配列を事前にソートし、接頭辞の合計を使用して、取得後に新しい合計を迅速に計算します。`x`最小または最大の要素。 最後のタスクは、次の制限に従って、2 つの学期間の実行可能なすべての移動の分割を試みることになります。`k`、どちらの側も空にならないようにしながら。 

各構成は O(1) で評価できるため、実装に応じて O(n + m + k) または O((n + m) log(n + m)) で可能な移動数をスキャンできます。

 ## アルゴリズムのチュートリアル

 1. 両方の配列をソートして、最小要素と最大要素を効率的に推論できるようにします。 これが必要なのは、最適な転送には常に極端な点が含まれており、並べ替えによってそれらが明らかになるためです。 
2. 両方の配列のプレフィックスの合計を計算します。 これにより、構成を迅速に評価するために必要な「最初の x 要素を取得」の合計を定数時間で計算できます。 
3. 両方の学期の合計とサイズを事前計算します。 これらは平均の開始状態を定義します。 
4. 決定を検討します。いくつかの要素を A から B に移動し、いくつかの要素を B から A に移動します。総移動量は最大でも次のとおりです。`k`。 
5. 固定数の場合`x`A から B に移動された要素のうち、最適なものを決定する`y`B から A まで`x + y ≤ k`そして結果として得られる両方のセットは空ではないままになります。 最良の選択は、A から最小値を取得し、B から最大値を取得することに対応します。 
6. それぞれの実現可能性について`(x, y)`ペア、計算:

 - A の新しいサイズ:`n - x + y`- A の新しい合計:`sumA - sum_of_x_smallest_A + sum_of_y_largest_B`- B の新しいサイズ:`m - y + x`- B の新しい合計:`sumB - sum_of_y_largest_B + sum_of_x_smallest_A`7. 目標を次のように計算します。`(avgA + avgB) / 2`すべての有効な構成の最大値を追跡します。 
8. 見つかった最良の値を返します。 

### なぜ効果があるのか

 重要な特性は、各学期内では、複数の価値観のみが重要であり、その順序ではないということです。 最適な動きのシーケンスは、A→B の動きは常に A の最小の残りの要素を取り、B→A の動きは常に B の最大の残りの要素を取るものに変換できます。極端でない要素が代わりに移動された場合、それをより極端な候補と交換すると、交換中の平均変化の単調性により、両方の学期の平均が厳密に改善または保存されます。 この交換議論により、注意を極端なものに限定しても最適な解決策が破棄されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        a.sort()
        b.sort()

        preA = [0]
        for x in a:
            preA.append(preA[-1] + x)

        preB = [0]
        for x in b:
            preB.append(preB[-1] + x)

        sumA, sumB = preA[n], preB[m]

        def sum_small_A(x):
            return preA[x]

        def sum_large_B(x):
            return preB[m] - preB[m - x]

        ans = float('-inf')

        max_x = min(k, n - 1 + m)  # rough safe bound

        for x in range(min(k, n) + 1):
            for y in range(min(k - x, m) + 1):

                na = n - x + y
                nb = m - y + x

                if na <= 0 or nb <= 0:
                    continue

                newA = sumA - sum_small_A(x) + sum_large_B(y)
                newB = sumB - sum_large_B(y) + sum_small_A(x)

                avgA = newA / na
                avgB = newB / nb

                ans = max(ans, (avgA + avgB) / 2)

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、最初に両方の学期をソートし、接頭語の合計を構築して、任意の候補転送セットを定数時間で評価できるようにします。 ネストされたループは、制約の下で各方向に移動される要素の数を列挙します。`x + y ≤ k`。 各状態は、プレフィックス情報から直接新しい合計とサイズを再計算します。 

ゼロ除算は無効であり、問​​題の制約にも違反するため、どちらの学期も空にならないように注意する必要があります。 これはチェックすることで処理されます`na > 0`そして`nb > 0`。 

浮動小数点除算は、最後の平均化ステップでのみ使用されます。 すべての中間値は正確な整数です。

 ## 特殊なケース

 両方の配列のサイズが 1 の場合、移動はできません。 アルゴリズムはのみを評価します`(x, y) = (0, 0)`、元の平均を保持し、無効な空学期状態を回避します。 

いつ`k`に比べて大きいです`n`または`m`、アルゴリズムは結果のサイズの実現可能性チェックを使用して移動を自然に制限します。 たとえ多くの移動が許可されていても、学期を空にすることは、`na > 0`そして`nb > 0`制約。 

すべての値が等しい場合、どの構成でも同じ結果が得られます。 プレフィックス合計ロジックは依然として一貫した合計を生成し、アルゴリズムは転送に関係なく不変の平均を正確に返します。
