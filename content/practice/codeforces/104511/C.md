 ## 解決策
 ## 問題の理解

 一度に 1 ノードずつツリーを成長させています。 最初は頂点が 1 つあります。 各クエリは既存のノードに新しいノードを接続します。$i$クエリにはルート構造があります$i+1$ツリー内で接続された頂点。 

挿入のたびに、特別なマージ ルールに基づいて現在のツリーが「良好」であるかどうかを判断する必要があります。 すべての頂点は値 0 から始まります。移動により、端点の値が等しいエッジを選択し、そのエッジを削除し、2 つの頂点を 1 つにマージして、値を 1 増やします。両方の端点の近傍は、マージされたノードの近傍になります。 これを繰り返して、ツリー全体を単一の頂点に折りたたもうとします。 問題は、木の現在の形状を考慮すると、これが常に可能かどうかです。 

制約は非常に大きく、最大で$3 \cdot 10^5$すべてのテスト ケースにわたる操作。 これにより、マージをシミュレートしたり、クエリごとに構造プロパティを最初から再計算したりするソリューションは除外されます。 どのアプローチも全体として線形に近くなければならず、通常は償却されます。$O(n)$または$O(n \log n)$。 

重要な微妙な点は、答えが実際のマージのシミュレーションではなく、進化するツリーの構造特性のみに依存することです。 単純なアプローチではマージ プロセスをシミュレートしようとする可能性がありますが、単一のクエリでも大きなサブツリーを繰り返し折りたたむ必要があり、非常に遅くなる可能性があります。 

もう 1 つの落とし穴は、次数やパリティなどの局所的なプロパティだけで答えが決まると想定していることです。 ツリーは同一の次数分布を持つ可能性がありますが、より深い構造に応じて異なる折り畳み可能性を持つため、グローバル追跡のない貪欲なローカルルールは失敗します。 

## アプローチ

 ブルートフォースのアイデアは、マージプロセスを明示的にシミュレートすることです。等しい値を接続するエッジを繰り返し見つけ、ノードをマージし、隣接関係を更新し、移動がなくなるまで継続します。 これはルールを直接反映しているため、原則として正しいです。 ただし、マージごとに隣接関係の更新に直線的な時間がかかる可能性があり、$O(n)$クエリごとにマージします。 すべてのクエリにわたって、これはすぐに 2 次またはさらに悪化し、これは実行不可能です。$3 \cdot 10^5$ノード。 

重要な観察点は、結合プロセスが非常に構造化されているということです。 各マージは同じ値のコンポーネント間でのみ発生し、コンポーネントが大きくなるにつれて値は単調に増加します。 これにより階層が作成されます。ノードはレイヤーにグループ化されているかのように動作し、このプロセスは、すべてのコンポーネントが一貫したボトムアップ方式でペアリングできるかどうかを確認するのと同じです。 

重要な再定式化は、マージをシミュレートする代わりに、ツリー上の有効なペアリング構造の存在と同等の動的条件を維持することです。 これは、サブツリーの寄与に対するバランス状態を維持することになり、ノードが追加されるたびに段階的に追跡できます。 新しいノードはそれぞれ単一のエッジにのみ影響するため、クエリごとに状態変数の小さなセットを更新できます。 

これにより、グローバルな再構築の繰り返しによる問題が、現在の構成が必要なパリティと一貫性の制約を満たしているかどうかを維持する、ルート化された動的ツリー上のローカルな更新の問題に軽減されます。

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、挿入を順番に処理します。 

各ノードはパリティ要件に影響します。最終的に完全に折りたたむには、すべてのサブツリーがマージ ルールの下で内部的にペア可能である必要があります。マージ ルールは、「未解決」ノードが上方に伝播する方法について均等性制約を維持するように動作します。 

各ノードについて、そのサブツリーに現在上方に渡さなければならない未解決のユニットがあるかどうかを表す値を維持します。 これは単純な DFS のような伝播構造で追跡できますが、ノードは動的に挿入されるため、親ポインターを維持し、挿入パスに沿ってのみ更新します。 

重要な考え方は、新しいノードが作成されるとき、$u$に付いています$x_i$、新しいリーフ制約が導入されます。 の状態を更新します$x_i$そして、安定性が回復するまで、不均衡が上方に伝播します。 

### ステップ

 1. 単一の頂点は簡単に折りたたむことができるため、有効としてマークされた単一のノードから開始します。 
2. ブール値またはパリティ状態を維持する$dp[v]$各ノードについて、そのサブツリーに現在未解決のマージ要件があるかどうかを示します。 
3. 新規ノードを追加する場合$u$に付いている$p = x_i$、初期化します$dp[u] = 1$、それは 1 つの新しいユニットに貢献するためです。 
4. から上に移動します。$p$、更新中$dp[p]$その子に基づいて。 複数の子が貢献する場合、マージは等しい状態間でのみ発生するため、ペアでキャンセルされます。 
5. ノードの累積値が均等になると、完全に解決でき、上方への伝播が停止します。 
6. 変化が起こらないノードに到達するか、ルートに到達するまで伝播を続けます。 
7. 各挿入後、ルートに未解決の寄与がない場合に限り、ツリーは「良好」になります。 

### なぜ効果があるのか

 マージ操作は常に 2 つの等しい状態をより高いレベルの状態に縮小し、同一の寄与をペアにするように動作します。 これにより、重要なのは貢献をあらゆるレベルで完全に組み合わせることができるかどうかだけであることが強制されます。 伝播不変式により、すべてのサブツリーが完全に削減できるかどうかが正しく要約されることが保証されます。 ルートに不均衡が残っていない場合は、完全なマージ シーケンスが存在します。 それ以外の場合、一部の構造は本質的にペアリングできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        q = int(input())
        x = list(map(int, input().split()))

        n = q + 1
        parent = [0] * (n + 1)
        dp = [0] * (n + 1)
        children = [[] for _ in range(n + 1)]

        parent[1] = 0
        dp[1] = 0

        good = True

        for i in range(1, q + 1):
            u = i + 1
            p = x[i - 1]

            parent[u] = p
            children[p].append(u)

            cur = u
            dp[cur] = 1

            while cur != 0:
                total = dp[cur]

                for v in children[cur]:
                    if v == parent[cur]:
                        continue
                    total += dp[v]

                dp[cur] = total % 2

                if dp[cur] == 0:
                    break

                cur = parent[cur]

            print("YES" if dp[1] == 0 else "NO")

if __name__ == "__main__":
    solve()
```この実装では、各サブツリー内の未解決のノードのパリティ形式の要約を維持しようとします。 各挿入により、新しいノードが 1 ユニットに寄与するように設定され、上方に伝播し、各祖先でパリティが再計算されます。 ルートでのチェックにより、すべてのコントリビューションがキャンセルされるかどうかが決定されます。 

微妙な部分は、ノードが安定するとすぐに伝播を停止することで、不必要な再計算を防ぐことです。 ツリー構造は、親ポインターと隣接リストを使用して段階的に構築されます。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードがルートに直接接続されている場合です。 この場合、挿入するたびにルートのパリティ状態が反転します。 アルゴリズムはこれを処理します。これは、すべての新しい子がルートの累積された未解決の値を即座にインクリメントし、YES/NO 出力を交互に強制するためです。 

もう 1 つのエッジケースは長いチェーンです。 ここで、更新はすべての祖先に伝播しますが、中間ノードでパリティがキャンセルされると安定化はすぐに起こり、完全な再計算を行わなくてもルートがグローバルな実現可能性を正しく反映することが保証されます。 

3 番目のエッジ ケースは、ルートに到達する前にサブツリーが内部でキャンセルされるバランスの取れた分岐です。 伝播ルールにより、キャンセルがローカルで発生することが保証され、より高いレベルでの誤った蓄積が防止されます。
