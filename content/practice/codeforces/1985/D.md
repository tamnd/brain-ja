 ## 解決策
 ## 問題の理解

 ドットとハッシュで構成されるグリッドが与えられます。 このグリッドのどこかに、隠れた中心までのマンハッタン距離が厳密に半径未満であるすべてのセルによって形成される形状があります。 これにより、グリッド軸に沿ったダイヤモンド型の領域が作成されます。 この領域内のすべてのセルは でマークされています。`#`そして外にあるものはすべて`.`。 タスクは、このダイヤモンドの中心の整数座標を回復することです。 

マンハッタンの円は非常に厳格な構造を持っています。 中心から移動すると、境界は対角の 4 方向に均等に広がり、対称的なひし形を形成します。 この対称性は、半径を知らなくてもグリッドから再構築できる重要な特性です。 

この制約により、すべてのテスト ケースで合計セル数が最大 200,000 個まで許可されるため、各セルを一定の回数検査するあらゆるソリューションが許容されます。 グリッドが大きい場合、単一のテスト ケース内の二次関数はどれも遅すぎます。 

単純な間違いは、考えられるすべての中心と半径をテストして円をシミュレートまたは適合させようとすることです。 各候補センターについて、すべてを確認する必要があります。`#`セルはマンハッタン条件を満たしているため、最悪の場合、複雑さはおよそ O(n²m²) になります。 もう 1 つの間違ったアプローチは、中心がすべての幾何学的中点であると仮定することです。`#`正当な理由のない細胞。 形状が座標空間内で完全に対称ではなくても、マンハッタン ボールとしては有効である場合、これは失敗する可能性があります。 

具体的な落とし穴は、中心が境界ボックスの中心であると想定していることです。`#`。 これはここでは機能しますが、それはマンハッタン ボールが常に 4 つの極値方向すべてを均等に飽和させる理由を理解している場合に限ります。 

## アプローチ

 ブルートフォース戦略は、各セルを潜在的な中心として扱うことです。 候補者ごとに`(i, j)`、任意の場所までのマンハッタンの最大距離を計算します。`#`セルを開き、すべてかどうかを確認します`#`一定の半径内にあります。 これには、候補ごとにグリッド全体をスキャンする必要があり、最悪の場合は O((nm)²) の動作が発生します。これは、中程度のグリッドであっても遅すぎます。 

重要な観察は、マンハッタンボールの中心が`(h, k)`非常に特殊な境界形状を持っています。 一番上の`#`細胞はちょうど離れたところにある`r-1`中央の上に、下に同じ距離にある最下位、そして左端と右端についても同様です。 これは、中心を純粋に座標の極値から回復できることを意味します。`#`細胞。 

させて`min_row`、`max_row`、`min_col`、`max_col`すべての境界ボックスになる`#`細胞。 マンハッタン ボールは完全に対称であるため、中心は上端と下端のちょうど中間、および左端と右端のちょうど中間に位置する必要があります。 ダイヤモンドの構造によりパリティの調整が保証されるため、その中間点は整数であることが保証されます。 

これにより、問題はグリッド上の 1 回のパスに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 4 つの変数を初期化する`min_row`、`max_row`、`min_col`、`max_col`すべての極端な位置を追跡する`#`細胞。 有効なセルがそれらを正しく更新できるように、それらを反対の極端な位置から開始します。 
2. グリッド内のすべてのセルを行ごとにスキャンします。 遭遇したとき`#`、その座標を使用して 4 つの境界すべてを更新します。 
3. グリッドを処理した後、中央の行を次のように計算します。`(min_row + max_row) // 2`。 これが機能するのは、ダイヤモンドが上下対称であるため、中心が最高と最低のちょうど中間にあるためです。`#`。 
4. 中央の列を次のように計算します。`(min_col + max_col) // 2`同じ対称引数を使用します。 
5. 結果を出力します`(center_row, center_col)`。 

### なぜ効果があるのか

 マンハッタン円は、中心までのマンハッタン距離が固定半径よりも厳密に小さいすべての点によって定義されます。 これにより、水平方向と垂直方向のすべての極値が中心によって一意に決定される凸状のダイヤモンドが作成されます。 一番上の`#`まさに`r-1`中央から少し上にあり、一番下は`r-1`以下の手順に従い、左右についても同様に行います。 形状は完全に塗りつぶされているため、`#`はこれらの極端な外側にあり、少なくとも 1 つは各境界上にあります。 したがって、境界ボックスの中心は正確に次のとおりです。`(h, k)`、極値の中点が真の中心と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        
        min_r = n
        max_r = 1
        min_c = m
        max_c = 1
        
        for i in range(1, n + 1):
            row = input().strip()
            for j, ch in enumerate(row, start=1):
                if ch == '#':
                    if i < min_r:
                        min_r = i
                    if i > max_r:
                        max_r = i
                    if j < min_c:
                        min_c = j
                    if j > max_c:
                        max_c = j
        
        center_r = (min_r + max_r) // 2
        center_c = (min_c + max_c) // 2
        
        print(center_r, center_c)

if __name__ == "__main__":
    solve()
```この実装では 4 つの境界変数が維持され、単一のパスでそれらが更新されます。 1 から始まるインデックスを使用すると、問題のステートメントと直接一致し、off-by-one 変換が回避されます。 マンハッタン円は対称性を保証しており、極値の合計は常に偶数であるため、整数の 2 による除算は安全です。 

微妙な点は、半径を明示的に再構築しようとしていないことです。 半径は、境界ボックスが中心からどれだけ離れているかを暗黙的にエンコードされますが、出力には不要です。

 ## 特殊なケース

 単一の要素を含む最小限のグリッド`#`最小座標と最大座標の両方がすぐに崩壊するため、これは重要です。 アルゴリズムはすべての境界をその位置に設定し、中点は変更されず、正しい中心が生成されます。 

塗りつぶされた長方形のブロックはマンハッタン ダイヤモンドとは形状が異なりますが、保証の範囲内では依然として有効です。 この場合、境界ボックスは正確であり、中点は依然として対称の真の中心に位置します。 

薄いひし形は、形状が数行または数列のみにまたがる場合に、整数の除算が正しく動作するかどうかをテストします。 マンハッタン円には常に対称な極値距離があるため、最小座標と最大座標の合計は均等なままとなり、丸めの問題が回避されます。
