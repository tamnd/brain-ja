 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$ここで、各セルは空 (「.」) または塗りつぶし (「#」) のいずれかです。 「#」の連結コンポーネントは、上下左右に移動することで相互に到達できるセルのセットです。 Alex は、行と列を選択し、その行と列のすべてのセルに「#」を入力するという 1 つの操作を実行できます。 タスクは、この操作を 1 回実行した後で、接続された '#' コンポーネントの可能な最大サイズを決定することです。 

グリッドの大きさは次のとおりです。$10^6$すべてのテスト ケースの合計セル数。これは、どのソリューションもセル数に対してほぼ直線的な時間で実行される必要があることを意味します。 あらゆる可能な操作を素朴に探索するアルゴリズム (すべてを試すなど)$n \cdot m$各再計算にはグリッドの完全な DFS または BFS が含まれる可能性があるため、行と列のペアとコンポーネントを毎回再計算すると、時間がかかりすぎます。 

選択した行と列に既に多くの「#」セルが含まれている場合、明らかではないエッジ ケースが発生します。 たとえば、2x2 グリッドを考えてみましょう。```
# .
. #
```最初の行と最初の列を選択すると、塗りつぶされたセルは次のようになります。```
# #
# #
```サイズ 3 ではなく 4 の連結コンポーネントを作成します。オーバーラップ (交差セル) を修正せずに行と列に存在する '#' を単純にカウントすると、誤って 5 としてカウントされます。オーバーラップを正しく処理することが不可欠です。 

もう 1 つの微妙なシナリオは、グリッドが空であるか、すでにいっぱいである場合です。 すべてのセルが「.」の場合、最適な操作により次のサイズのコンポーネントが生成されます。$n + m - 1$交差セルは 1 回だけカウントされるためです。 すべてのセルがすでに「#」である場合、どの操作でもコンポーネントのサイズを増やすことはできませんが、アルゴリズムは依然として正しい合計を生成する必要があります。 

## アプローチ

 ブルートフォース手法では、すべての行が考慮されます。$r$そしてコラム$c$、それらを一時的に「#」セルで埋め、DFS または BFS を使用して最大の連結成分を再計算します。 正しいとはいえ、このアプローチには次のことが必要です$O(n \cdot m \cdot (n \cdot m))$最悪の場合の動作が制限されますが、制約を考慮すると遅すぎます。 各グリッドには最大で次のものを含めることができます$10^6$セルがあり、最大で$10^4$テストケース。 明らかに、すべての可能性を反復してコンポーネントを再計算することは不可能です。 

最適化するための重要な洞察は、操作によって選択された行と列に沿ってセルが接続されますが、グリッド全体の接続コンポーネントを毎回再計算する必要がないということです。 代わりに、行ごとに「#」セルの数を計算し、列ごとに「#」セルの数を計算できます。 結果として得られるコンポーネントの最大サイズは、選択した行と列の「#」に、操作によって追加された新しいセルを加えたものから、交差セルの 1 を引いたものになります。 数式形式で、行に対して$r$そしてコラム$c$:```
potential_size = row_count[r] + col_count[c]
if grid[r][c] == '.':
    potential_size += 1
```すべての行と列を反復処理して、最大値を追跡できます。 各行と列のペアの計算は$O(1)$事前に計算されたカウントを使用すると、全体的な複雑さは次のようになります。$O(n \cdot m)$テストケースごとに、制限内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n*m)^2) | O(n*m) | 遅すぎる |
 | 最適 | O(n*m) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 指定されたグリッドについて、計算します。`row_count[r]`各行の「#」セルの数として、`col_count[c]`各列の「#」セルの数として。 これにはグリッドを 1 回通過する必要があります。 
2. 変数を初期化する`max_component`ゼロに。 
3. すべてのセルを反復処理します。`(r, c)`グリッド内で。 各セルについて、行に対して操作を実行した場合のコンポーネントの潜在的なサイズを計算します。`r`そしてコラム`c`。 式は`row_count[r] + col_count[c]`。 交差セルの場合`grid[r][c]`は「.」です。セルは「#」になりますが、以前は空だったので、1 ずつ増加します。 
4.アップデート`max_component`計算されたサイズが現在の最大値より大きい場合。 
5. すべての行と列のペアを確認した後、出力します。`max_component`。 

Why it works: By precomputing counts, we capture all existing '#' cells along each row and column. Adding one for empty intersection cells ensures we do not double-count. Any single operation can only extend a component along a row and a column; there is no benefit to choosing a cell outside the densest row or column combination, so this approach always finds the global maximum.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [list(input().strip()) for _ in range(n)]
        
        row_count = [0] * n
        col_count = [0] * m
        
        for r in range(n):
            for c in range(m):
                if grid[r][c] == '#':
                    row_count[r] += 1
                    col_count[c] += 1
        
        max_component = 0
        for r in range(n):
            for c in range(m):
                # Base count: '#' in row + '#' in column
                size = row_count[r] + col_count[c]
                if grid[r][c] == '.':
                    size += 1  # Add intersection cell if empty
                max_component = max(max_component, size)
        
        print(max_component)

if __name__ == "__main__":
    solve()
```解決策は、テスト ケースの数を読み取ることから始まります。 テスト ケースごとに、グリッドを読み取り、行および列ごとに '#' をカウントする配列を構築します。 ネストされたループは、各演算を考慮して達成可能な最大成分を計算し、過剰カウントを避けるために交差セルが最初に空の場合にのみ慎重に成分を追加します。
