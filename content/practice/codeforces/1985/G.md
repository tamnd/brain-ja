 ## 解決策
 ## 問題の理解

 この問題では数字を数えるように求められます$n$与えられた範囲内で乗算する$n$整数で$k$桁の合計を正確にスケーリングします$k$。 正式に言うと、$D(n)$の桁の合計です$n$、すべてが欲しいです$n$で$[10^l, 10^r)$満足のいく$D(k \cdot n) = k \cdot D(n)$。 入力は複数のテスト ケースで構成され、それぞれが指定します$l$、$r$、 そして$k$、出力はカウントモジュロです$10^9+7$。 

の範囲$n$非常に大きくなる可能性があります:$10^l$に$10^r$と$r$まで$10^9$。 すべての数値をチェックする単純なアプローチは、単一のテスト ケースであっても不可能です。$10^9$現実的な制限時間を超えてしまう可能性があります。 同様に、$k$また、非常に大きくなる可能性があるため、複数の反復に依存するアルゴリズムは実行できません。 

範囲に 0 または 1 桁の数字が含まれる場合、エッジ ケースが発生します。 たとえば、次の場合$l = 0$そして$r = 1$、有効な数値は 0 と 1 だけです。もう 1 つの微妙なシナリオは次のような場合です。$k = 1$, ここで、すべての数値が条件を自明に満たします。 不用意に実装すると、非常に大きな数値を直接乗算しようとする可能性があり、オーバーフローが発生したり、桁の合計の計算が非常に遅くなったりする危険があります。 

## アプローチ

 ブルートフォースアプローチはすべてを反復することになる$n$範囲内で計算します$D(n)$、 それから$D(k \cdot n)$、等しいかどうかを確認します。 これは小さい数値では正しく機能しますが、次のような範囲では機能します。$10^0$に$10^9$、これには最大で$10^9$テスト ケースごとの操作数は、2 秒の制限時間をはるかに超えています。 桁合計の計算は桁数が線形であるため、合計の演算量は次のとおりです。$10^{10}$、それは不可能です。 

重要な洞察は、9 を法とする問題を考察することです。 桁の合計関数$D(n)$に一致します$n \bmod 9$。 つまり、$D(n) \equiv n \pmod 9$。 問題の状態から$D(k \cdot n) = k \cdot D(n)$、両辺を法 9 で計算すると、次のようになります。$k \cdot n \equiv k \cdot D(n) \pmod 9$。 もし$k$は 9 と互いに素なので、9 を法にしてキャンセルできます。$n \equiv D(n) \pmod 9$。 

この観察により、候補番号の数が大幅に減少します。 数字のみ$n \bmod 9$9 を法とした数字の合計に等しいことを考慮する必要があります。 これは、「10 進数のレプユニット」に何らかの整数を乗算した場合にのみ発生することがわかります。 ダイナミック プログラミングを使用して数字を 1 桁ずつ系統的に生成し、9 を法とする合計を追跡することで、範囲内のすべての数字を反復処理することなく、有効な数字をすべてカウントできます。

 ## アルゴリズムのチュートリアル

 1. 次のことに注意してください。$D(n) \equiv n \pmod 9$。 満足のいく数字の場合$D(k \cdot n) = k \cdot D(n)$、モジュロ 9 を使用します。$k \cdot n \equiv k \cdot D(n) \pmod 9$。 もし$k$は 3 で割り切れないので、キャンセルして取得できます$n \equiv D(n) \pmod 9$。 
2. すべての数字$n$満足のいく$n \equiv D(n) \pmod 9$モジュロ 9 プロパティを維持する数字を選択することで再帰的に生成できます。 考えられる最初の各桁 (ゼロ以外の数値の場合は 1 ～ 9) から開始し、0 ～ 9 の数字を追加して数値を拡張します。9 を法とする現在の桁の合計を追跡します。 
3. 各候補番号について、それが範囲内にあるかどうかを確認します。$[10^l, 10^r)$。 条件を正確に満たす数値のみをカウントします。 
4. 大きな範囲を処理するには、次の桁数までの数値のみを生成します。$10^r - 1$。 メモ化を使用して、残りの桁、現在の合計のモジュロ 9、および厳密な境界に基づいて中間カウントを保存します。 
5. カウントモジュロを返します$10^9+7$。 

なぜ機能するのか: モジュロ 9 プロパティは、満足しない数値が存在することを保証します。$n \equiv D(n) \pmod 9$満足できない$D(k \cdot n) = k \cdot D(n)$。 再帰的生成により、不可能な候補を繰り返すことなく、すべての有効な数値を列挙できます。 メモ化により、冗長な計算が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def sum_of_digits_mod9(n):
    return sum(int(c) for c in str(n)) % 9

def count_valid(n_str, k):
    from functools import lru_cache
    
    digits = [int(c) for c in n_str]
    
    @lru_cache(None)
    def dfs(pos, sum_mod9, tight, started):
        if pos == len(digits):
            return int(started and (k * sum_mod9) % 9 == (k * sum_mod9) % 9)
        
        limit = digits[pos] if tight else 9
        total = 0
        for d in range(0, limit+1):
            total += dfs(pos+1, (sum_mod9 + d) % 9, tight and d == limit, started or d > 0)
        return total % MOD
    
    return dfs(0, 0, True, False)

def solve():
    t = int(input())
    for _ in range(t):
        l, r, k = map(int, input().split())
        l_val = 10**l
        r_val = 10**r - 1
        ans = (count_valid(str(r_val), k) - count_valid(str(l_val-1), k)) % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```説明: 関数`count_valid`モジュロ 9 プロパティを満たす、指定された制限までのすべての数値をカウントします。 再計算を避けるためにメモ化を使用して、数値を桁ごとに再帰的に構築します。 の引き算`count_valid(l_val-1)`包括的な下限を処理します。
