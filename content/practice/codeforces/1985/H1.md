 ## 解決策
 ## 問題の理解

 以下で構成されるグリッドが与えられます。`n`行と`m`列。各セルは空 (「.」) または塗りつぶし (「#」) のいずれかです。 塗りつぶされたセルの接続されたコンポーネントは、'#' タイルのセットであり、辺を共有する隣接するタイルに沿って移動するだけで、任意の 2 つのタイル間を移動できます。 この問題では 1 つの操作が可能です。任意の行または列を選択し、その行または列のすべてのセルに「#」を入力できます。 私たちの目標は、最大 1 回のそのような操作で達成できる接続コンポーネントの最大サイズを決定することです。 

入力には複数のテスト ケースが含まれており、その合計は`n * m`10^6 で区切られたすべてのケースにわたって。 これは、各グリッド上の線形パスは可能ですが、グリッド全体にわたる二次またはネストされた走査は遅すぎる可能性があることを意味します。 行または列の操作は 1 つしか実行できないため、最大のクラスターを最大化するにはどの単一操作がコンポーネントをマージまたは拡張するかを検討する必要があります。 

エッジ ケースには、小さなグリッド、すでに完全に塗りつぶされているグリッド、またはすべての塗りつぶされたセルが分離されているグリッドが含まれます。 たとえば、「.」が付いた 1x1 グリッドです。 唯一の行または列を埋めた後は 1 を返す必要があり、すべての行と列に少なくとも 1 つの「#」がすでに含まれているグリッドは、散在するタイルを接続するだけで最大化される可能性があります。 考えられるすべての行または列に対する単純なフラッドフィルは、小さなグリッドでは実現可能ですが、総セル数の制限が 10^6 に近づくと遅すぎます。 

## アプローチ

 ブルート フォース アプローチでは、すべての行と列を反復処理し、「#」で埋めるシミュレーションを行った後、シミュレーションごとに DFS または BFS を使用して最大の連結成分のサイズを計算します。 あらゆる可能性を徹底的にチェックしているのでこれは正しいのですが、遅すぎます。 一定のサイズのグリッドの場合`n*m`、各シミュレーションには DFS に O(n_m) がかかり、`n+m`シミュレーションの結果、テスト ケースごとに O((n+m)_n_m) になります。 n_m ~ 10^6 および n+m ~ 2000 の最悪のシナリオでは、テスト ケースごとにおよそ 2*10^9 の操作が必要になりますが、これは実行不可能です。 

重要な点は、行または列を埋めるとセルが行に追加されるだけであるということです。 したがって、演算後の最大の連結成分は、選択した行または列のセルと、同じ行または列にある既存の '#' セルの合計が最大になります。 各行と列の「#」の数を事前計算できます。 次に、潜在的な各演算について、結果の連結成分のサイズは、その行と列の「#」の合計に、交差セルが空の場合は 1 を加えたものになります (二重カウントを避けるため)。 これにより、問題は、達成可能な最大の合計を見つけるためにすべての行と列にわたる線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+m) * n * m) | O(n*m) | 遅すぎる |
 | 最適 | O(n*m + n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各グリッドについて、各行と各列の塗りつぶされたセルの数を計算します。 させて`row_count[i]`行内の「#」の数になります`i`そして`col_count[j]`列内の「#」の数`j`。 これには、グリッド全体にわたる 1 回のパス、O(n*m) が必要です。 
2. 潜在的な最大サイズを計算するために、空のセルまたは埋め込まれているセルを特定します。 各操作は行全体または列全体に影響するため、次の 2 種類の操作を個別に検討してください。 行の塗りつぶし`i`または記入欄`j`。 
3. 行の塗りつぶしをシミュレートする場合`i`、結果として得られる最大の成分は、その行のセルの数と、この行と交差する列のセルの数を加算したものになりますが、二重カウントを調整する必要があります。 最大連結成分は次のようになります。`row_count[i] + max_col_count`、 どこ`max_col_count`列数の最大値であり、(i,j) で交差するセルが空だった場合は +1 で調整されます。 
4. 同様に充填カラムをシミュレーションする場合`j`、計算する`col_count[j] + max_row_count`空いている交差点でも同じ調整を行います。 
5. 答えは、行と列に対するすべての操作の最大値です。 
6. エッジケース: グリッドが完全に埋められている場合、どの操作を行ってもサイズは増加しません。 グリッドに 1 行または 1 列しかない場合、グリッドを埋めるのは簡単です。 

不変条件は、1 つの行または列を塗りつぶしても、その線に沿った連結成分のみが作成され、最大のマージは、多く塗りつぶされた行と多く塗りつぶされた列の交点で発生するということです。 行数と列数を事前に計算することで、すべての DFS をシミュレートすることなく、最適なマージを確実にキャプチャできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        
        row_count = [0]*n
        col_count = [0]*m
        
        for i in range(n):
            for j in range(m):
                if grid[i][j] == '#':
                    row_count[i] += 1
                    col_count[j] += 1
        
        max_row = max(row_count)
        max_col = max(col_count)
        
        # find if there exists an empty cell at intersection
        found_empty = False
        for i in range(n):
            if row_count[i] == max_row:
                for j in range(m):
                    if col_count[j] == max_col and grid[i][j] == '.':
                        found_empty = True
                        break
                if found_empty:
                    break
        
        ans = max_row + max_col
        if found_empty:
            ans += 1
        
        print(ans)

solve()
```The first part reads the input and counts '#' cells per row and column. We then compute the maximum row and column counts. 難しい部分は、最大カウントを持つ行と列の交差部分が空かどうかをチェックすることです。これにより、合計にセルを 1 つ追加して二重カウントを回避できます。 最後に、答えを出力します。
