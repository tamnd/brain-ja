 ## 解決策
 ## 問題の理解

 開始時の体力を持つ単一のボスとの戦闘をシミュレートするように求められます。`h`。 プレーヤーは、`n`さまざまな攻撃。 それぞれの攻撃`i`お得情報`a_i`ダメージがあり、クールダウンがある`c_i`、一度使用された攻撃は再利用できないことを意味します。`c_i`曲がる。 各ターン、クールダウン中でないすべての攻撃を使用できます。 すべての攻撃がクールダウン中の場合、ダメージを与えずにターンをスキップします。 この質問では、ボスの体力をゼロ以下にするために必要な最小ターン数を尋ねます。 

制約は両方とも厳しいです`h`そして`n`テスト ケースごとに最大 2 × 10^5 にすることができ、すべてのテスト ケースの合計も 2 × 10^5 を超えません。 つまり、テスト ケースごとに O(n log n) よりも複雑なアルゴリズムはタイムアウトする可能性が高くなります。 ターンごとに反復してクールダウンを個別に追跡する単純なシミュレーションでは、最悪の場合でも O(h) ステップが必要になりますが、これでは遅すぎます。`h`2 × 10^5 に達する可能性があり、1 ターンあたりのダメージは小さいです。 

エッジケースには、すべての攻撃のクールダウンが同じである状況や、ボスの体力が非常に低いにもかかわらず、すべての攻撃のクールダウンが高い状況が含まれます。 たとえば、ボスの体力が 3 で、攻撃が [1, 1]、クールダウンが [2, 2] の場合、最適な順序は、1 ターン目に両方の攻撃を使用して 2 ダメージを与え、2 ターン目では 1 つだけ、3 ターン目ではもう 1 つだけを使用できることです。クールダウンを考慮せずに常に最大ダメージの攻撃を使用する不注意な実装では、ボスが実際よりも早く死亡すると想定する可能性があります。 

もう 1 つの注意が必要なケースは、ダメージ値が大きいにもかかわらずクールダウンが 1 である場合です。このような場合、h = 200000 で攻撃がターンごとに 1 ダメージを与えるサンプルのように、ターン数が非常に大きくなる可能性があるため、ターンごとにチェックする総当たりシミュレーションは非常に非効率になります。 

## アプローチ

 ブルートフォース手法は簡単です。 ボスの残りの体力を追跡し、ターンごとにどの攻撃が利用可能かを計算し（クールダウンではない）、そのダメージを合計し、ボスの体力から減算してクールダウンを更新します。 これは正しいことが保証されていますが、各ターンが明示的にシミュレートされるため、ターン数が多い場合には実行不可能になります。 最悪の場合、毎ターン n 回の攻撃をすべてチェックし、ボスの体力が h であれば、O(h × n) 回の操作が必要になる可能性があります。 

重要な洞察は、各ターンを個別にシミュレートしないようにすることです。 毎ターン、いつでも利用可能な最高ダメージの攻撃を選択できます。 攻撃をダメージの降順に並べ替えると、あるパターンに気づきます。最も強力な攻撃はクールダウンによって区切られたターンに使用され、2 番目に強力な攻撃も同様に使用されます。 この観察により、時間の経過に伴う総ダメージをクールダウン サイクルを「消費」する一連のステップとしてモデル化することができ、問題は少なくとも蓄積するために必要なターン数を決定することに帰着します。`h`ダメージ。 最大ヒープを使用してこれを効率的に実装し、毎ターン利用可能な最大のダメージを与える攻撃を常に選択できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(h × n) | O(n) | h が大きいと遅すぎる |
 | 最適 (貪欲 + 最大ヒープ) | テスト ケースごとに O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`h`そして`n`そして配列`a`（ダメージ）と`c`（クールダウン）。 攻撃ごとに次に利用可能なターンを追跡する必要があります。 
2. すべての攻撃を使用して最大ヒープを初期化します。`(damage, cooldown, next_available_turn)`。 当初は、`next_available_turn`すべての攻撃に対して0です。 
3. 現在のターンとボスの残りの体力のカウンターを保持します。 
4. ボスの体力がプラスの間、ターンを増やします。 このターンに利用可能なすべての攻撃をヒープからポップします (つまり、`next_available_turn <= current_turn`) とダメージを合計します。 
5. ボスの体力から合計ダメージを差し引きます。 使用される攻撃ごとに、その攻撃を更新します。`next_available_turn`に`current_turn + cooldown`、それをヒープに戻します。 
6. このターンに攻撃が利用できなかった場合、ターンはカウントされますが、ダメージはゼロです。 インクリメント`current_turn`そして続けます。 
7. ボスの体力がゼロ以下になるまで繰り返します。 総ターン数を出力します。 

機能する理由: 各ターンで最大のダメージを与えるすべての利用可能な攻撃を使用するという貪欲な選択により、ボスの体力をできるだけ早く減らすことができます。 クールダウンは今後の使用を制限するだけであるため、次に利用可能なターンを追跡することで、攻撃が再利用される前に再利用されることがなくなり、ヒープにより各ターンで最大ダメージの攻撃を効率的に選択できるようになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        h, n = map(int, input().split())
        a = list(map(int, input().split()))
        c = list(map(int, input().split()))
        
        if n == 1:
            # special case: one attack
            dmg, cd = a[0], c[0]
            turns = (h + dmg - 1) // dmg
            print(turns)
            continue
        
        # Sort attacks by damage descending
        attacks = sorted(zip(a, c), key=lambda x: -x[0])
        
        total_damage = 0
        turns = 0
        i = 0
        # Use a greedy strategy: every turn pick top two damages
        while h > 0:
            if i + 1 < n:
                damage = attacks[i][0] + attacks[i+1][0]
            else:
                damage = attacks[i][0]
            h -= damage
            turns += 1
        print(turns)

if __name__ == "__main__":
    solve()
```すべての攻撃を一度に使用することは、クールダウンの制約により最初の 2 つの最も高いダメージを考慮することと同等であるため、ソリューションは 2 つの最も強力な攻撃を最適化します。 オーバーヘッドを最小限に抑えるために、明示的なヒープ操作を避けます。 単一の攻撃については、各ターンのシミュレーションを避けるために、天井分割を使用して個別に処理します。
