 ## 解決策
 ## 問題の理解

 私たちに与えられた家族は、$N$現在、各人は右の靴と左の靴の 2 つの靴を持っています。 ただし、この靴は混ざっています。 あらゆる人にとって$i$、彼らが現在持っている正しい靴は誰かのものです$a_i$、そして彼らが現在持っている左の靴は誰かのものです$b_i$。 

目標は、その人が靴を並べ替えることです。$i$結局両方とも自分の靴になります。 唯一許可される操作は 2 人の間での交換ですが、同じ側でのみです。右の靴は右の靴とのみ、左の靴は左の靴とのみ交換できます。 スワップでは、2 人の間でその側の靴を交換します。 

すべての人の正しいペアを復元するために必要なスワップの最小数を計算する必要があります。 

制約から得られる重要な観察点は次のとおりです。$N$と同じ大きさにすることができます$10^6$。 これにより、二次関数または二次関数に近い解は即座に除外されます。 スワップを直接シミュレートしようとするアプローチや、置き忘れられたシューズを繰り返し検索しようとするアプローチはタイムアウトになります。 解決策は本質的に線形である必要があります。$N$、または最悪の場合$O(N \log N)$ただし、このスケールでは対数因子は危険です。 

この問題の微妙な点は、右の靴と左の靴が別々に動くことです。 スワップ中にサイド間に相互作用はありません。 これは、この 2 つの側面を時期尚早に混合する解決策は、不正確である可能性が高いことを意味します。 

エッジ ケースは、サイクルが重なっている場合、または両方の配列がすでに正しいにもかかわらず、両側で位置がずれている場合に発生します。 たとえば、右の靴がすべてすでに正しいが、左の靴が大きなサイクルを形成している場合でも、答えは左側の順列構造によって完全に決定されます。 スワップはローカルではなくグローバルに構造を修正するため、単純な「カウントの不一致と貪欲なスワップ」アプローチは失敗します。 

もう 1 つのエッジ ケースは、両方の配列が同一であるが、アイデンティティ マッピングと等しくない場合です。 たとえば、次のような純粋な順列サイクル$a = [2,3,1]$。 すべての位置が「間違っている」場合でも、要素ごとに 2 つの独立した補正を必要とするのではなく、サイクル分解能が必要です。 

## アプローチ

 このプロセスを直接シミュレートしようとすると、間違った靴を持っている人を繰り返し探し、正しい所有者と交換することになります。 各スワップでは、ターゲットを特定し、位置を更新し、左側と右側の両方の一貫性を維持する必要があります。 ハッシュを使用したとしても、繰り返される更新によりプロセスが形成され、次のような状態に劣化する可能性があります。$O(N^2)$敵対的なケースでは、それぞれの修正がさらに多くの不一致を引き起こす可能性があるためです。 

重要な洞察は、サイド内のスワップが、任意のスワップを使用して順列をソートするのとまったく同じように動作するということです。 各辺はサイズの順列を独立して定義します$N$: 右の靴は現在の位置から所有者へのマッピングを定義し、左の靴についても同様です。 

問題は、2 つの独立した順列を修正することに帰着します。 あらゆる順列について、同一性を復元するために必要なスワップの最小数はよく知られており、次のようになります。$N -$(順列のサイクル数)。 各サイクルの長さ$k$正確に必要です$k-1$スワップごとに 1 つの要素を正しい位置に配置し、サイクル サイズを 1 つ減らすことができるためです。 

左と右の演算は独立しているため、合計の答えは両方の置換に必要なスワップの合計になります。 

したがって、両方の配列のサイクル分解を計算し、結果を合計します。

 ## アルゴリズムのチュートリアル

 右靴のマッピングと左靴のマッピングを個別に処理し、それぞれを順列として扱います。$N$要素。 

1. どの位置が処理されたかを追跡するために、false に初期化された訪問済み配列を構築します。 これにより、各要素が正確に 1 つのサイクルに割り当てられるようになります。 
2. 右の靴の配列について、1 から 2 までの各位置を繰り返します。$N$。 ある位置が訪問されていない場合は、マッピングに従って繰り返し追跡することによってそのサイクルのトラバースを開始します。$i \rightarrow a_i$原点に戻るまで。 この走査で新しいノードを訪問するたびに、そのノードに訪問済みのマークが付けられ、サイクル サイズがカウントされます。 
3. サイズのサイクルごとに$k$、追加します$k-1$答えに。 これは、そのサイクルを個別に修正するために必要なスワップの数に対応します。 
4. 正しい配列のすべてのサイクルが終了したら、訪問した構造をリセットします。 
5. 左側の配列に対して同じサイクル分解プロセスを繰り返します。$b$、再度合計します$k-1$発見されたサイクルごとに。 
6. 両辺の合計を出力します。 

重要な点は、実際にはスワップを実行しないということです。 各順列を最適に解決する場合に必要なスワップの数のみを計算します。 

### なぜ効果があるのか

 各辺は順列を定義します$N$アイテム。 順列は互いに素なサイクルに一意に分解され、各サイクル内で要素が位置間で回転します。 1 回のスワップで、サイクル内の 1 つの要素を正しい位置に配置することで修正でき、残りの要素の構造を維持しながらサイクル サイズを効果的に 1 つ削減できます。 これにより、サイクルの長さが保証されます。$k$常に正確に要求する$k-1$各スワップは、すでに達成されている正確さを妨げることなく、そのサイクル内で最大 1 つの誤って配置された要素を修正できるためです。 

左右の操作は独立しており干渉しないため、スワップの最小合計数は、各置換の最適コストを個別に合計したものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_swaps(p):
    n = len(p) - 1
    vis = [False] * (n + 1)
    res = 0

    for i in range(1, n + 1):
        if not vis[i]:
            cur = i
            cycle_size = 0
            while not vis[cur]:
                vis[cur] = True
                cycle_size += 1
                cur = p[cur]
            res += cycle_size - 1

    return res

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    print(count_swaps(a) + count_swaps(b))

if __name__ == "__main__":
    solve()
```この実装では、位置が人のラベルと直接一致するように、便宜上、インデックスが 1 の配列を構築します。 の`count_swaps`関数は、標準的なサイクル分解ロジックを分離します。 未訪問の各ノードは、ループを閉じるまで順列に従う走査を開始し、途中でサイクル サイズが蓄積されます。 

ここでよくある落とし穴は、両方の配列を独立して処理する必要があることを忘れていることです。 もう 1 つの微妙な問題は、入力を読み取る際のインデックス付けが正しくないことです。 1 から始まるインデックスを使用すると、順列をたどる際の 1 つずつの間違いを回避できます。

 ## 特殊なケース

 最小限のエッジケースは次のような場合です$N = 1$。 どちらの配列にも 1 のみが含まれている必要があります。アルゴリズムは単一ノードをサイズ 1 のサイクルとしてマークし、各サイドのスワップがゼロとなり、正しい出力 0 が生成されます。 

もう 1 つのケースは、両方のアレイが大きなサイクルを形成する場合です。 例えば、$a = [2,3,4,5,1]$。 トラバーサルはすべてのノードを 1 回訪問し、サイズ 5 のサイクルを生成し、4 つのスワップを提供します。 2 番目の配列が異なるサイクル構造を持つ場合、同じロジックが独立して 2 番目の配列に適用されます。 訪問済みの状態はパス間でリセットされるため、アルゴリズムはそれらを正しく分離します。 

より微妙なケースは、両方の順列が同一であるが自明ではない場合です。 構造が一致していても、それぞれの側で独立した固定が必要です。 スワップはサイド間で共有できないため、アルゴリズムは両方の寄与をキャンセルしようとするのではなく、正しくカウントします。
