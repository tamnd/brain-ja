 ## 問題の理解

 有向非巡回グラフを構築するように求められます。$N$ラベル付き頂点、ここで頂点$i$プログラマーを表します。 エッジ$i \to j$手段$i$直接命令できる$j$そして、これらのエッジから、通常の推移的な意味で到達可能性を定義します。$i$は、それ自体を含む、有向エッジに沿ってそこから到達可能なすべての頂点に対する権限を持ちます。 

各プログラマーにとって$i$、必要な値が与えられています$a_i$。 タスクは、次の頂点数が得られるような有向非巡回グラフを構築することです。$i$まさに$a_i$。 同様に、到達可能なセットのサイズは、$i$、 含む$i$、目標値と一致する必要があります。 

グラフは非巡回のままでなければならないため、到達可能性により半順序構造が誘発されます。 これは、到達可能なセットがエッジに沿って単調に動作する必要があることを直ちに示唆しています。$u \to v$、その後、から到達可能なすべてのもの$v$からもアクセス可能です$u$、 それで$a_u \ge a_v$。 

制約が強いですね。$N$まで可能です$10^5$、ただしすべての合計$a_i$せいぜい$10^6$これは、必要な到達可能質量の合計に関して、どのような構造でもほぼ直線的な仕事しか提供できない可能性があることを示唆しています。 二次関数の何か$N$それはすぐには不可能ですし、$O(N \log N)$ソリューションは注意深く構成する必要があります。 

値が DAG 構造と一致しない場合、微妙な失敗のケースが発生します。 ある頂点が別の頂点よりも必要な値が小さいにもかかわらず、順序付けの制約によりその頂点を支配せざるを得なくなった場合、矛盾が発生します。 たとえば、2 つの頂点が同一の大きなリーチを必要とするが、DAG の順序付けにおいて一方が他方より厳密に上位になければならない場合、到達可能なセットの複製は不可能になります。 

もう 1 つの明白ではない問題は、単純な貪欲な構造では到達可能性が過大評価される可能性があることです。 たとえば、各頂点を次の頂点に単純に接続すると、$a_i-1$頂点を超えると、誤って推移的なリーチが導入される可能性があります。$a_i$パスが重なっているためです。 

中心的な難しさは、単にエッジを構築するだけではなく、到達可能性のサイズが少なくとも、あるいは最大でも正確であることを保証することです。

 ## アルゴリズムのチュートリアル

 DAG を構築するには、各ノードにグローバル構造内の「制御された位置」のブロックを割り当て、各ノードの到達可能なセット サイズが正確に必要な値であることを確認します。 

1. すべての頂点を昇順でない順に並べ替えます。$a_i$。 これにより、必要な到達範囲がより大きい頂点が最初に処理されるようになり、より大きな到達可能性構造のソースとして機能できるようになります。 この順序により、後の頂点がすでに固定された構造をオーバーライドする必要がなくなります。 
2. 増加するアクセス可能なエンドポイントの構造を表すアクティブ ノードの動的なリストを維持します。 最初、このリストは空です。 
3. ソートされた順序で頂点を 1 つずつ処理します。 頂点を扱う場合$v$要件付き$a_v$、正確に到達できることを確認したいと考えています$a_v$それ自体を含むノード。 それ自体は 1 としてカウントされるため、到達する必要があります$a_v - 1$他のノード。 
4. 最後は私たちが取る$a_v - 1$アクティブリストからノードを選択して接続します$v$それぞれに。 これらのノードが選択されるのは、最近作成された到達可能性エンドポイントを表し、制御された境界を超えて意図しない拡張が行われないようにするためです。 
5.加工後$v$、追加します$v$アクティブリストに追加します。 これにより、以前のノードの到達可能なエンドポイントとして利用できるようになります。 
6. いずれかの時点で、アクティブなリストに含まれる内容が次の値よりも少ない場合$a_v - 1$ノードが存在する場合、到達要件を満たすのに十分な個別のノードがないため、構築は不可能です。 
7. すべてのエッジが構築されたら、出力します。 

### なぜ効果があるのか

 この構築では、重要な不変条件が維持されます。アクティブ リストは常に、到達可能なセットがネストされたノードのチェーンを表し、新しく追加された各ノードは、制御されたプレフィックスのような方法で到達可能性を拡張するだけです。 常に最新のノードに頂点をアタッチするため、意図しない方法で推移閉包を通じて到達可能性を増大させるクロスリンクの導入を回避します。 

各ノードの到達可能なセットは、まさにそのノードが直接接続しているノードとそれ自体です。 構築順序には後方エッジが存在しないため、余分なパスが現れることはありません。 要件によるソート処理により、ノードの出力エッジが固定されると、その後の操作で到達可能なセットを増やすことができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    nodes = list(range(n))
    nodes.sort(key=lambda i: -a[i])

    active = []
    edges = []

    for v in nodes:
        need = a[v] - 1

        if need > len(active):
            print(-1)
            return

        # connect to last 'need' active nodes
        for u in active[-need:]:
            edges.append((v + 1, u + 1))

        active.append(v)

    print(len(edges))
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```コードはまず配列を読み取り、必要な範囲が大きい頂点が最初に処理されるようにインデックスを並べ替えます。 の`active`list は、後の頂点が接続できるノードの進化するプールです。 各頂点について、必要なリーチからそれ自体を差し引いた値を満たすのに十分な以前のノードが存在することを確認することで、実現可能性をチェックします。 次に、すべてのエッジがソート順で前に処理された頂点から後の頂点に移動するため、非循環性を維持しながら、正確にその数の最近のノードに接続します。 最後に、すべてのエッジを保存して出力します。 

実装の微妙な詳細は、インデックスが出力時にのみ 1 ベースに変換されることです。 もう 1 つの重要な点は、常に次の接尾辞から取得することです。`active`、任意の要素ではなく、意図しない推移的拡張を防ぐ構造的不変条件が維持されます。

 ## 特殊なケース

 重大なエッジケースは、最大規模の場合です。$a_i$表示が早すぎますが、要件を満たすのに十分なノードが残っていません。 例えば、$N=4$、$a = [4,1,1,1]$。 アルゴリズムは最初に 4 つを処理し、3 つのアクティブなノードを必要としますが、どれも存在しないため、正しく不可能を返します。 

もう 1 つの特殊なケースは、すべての場合と同様に均一な小さな値です。$a_i = 1$。 この場合、エッジは必要なく、アクティブなリストは接続を生成することなく成長し、すべてのノードがそれ自体にのみ到達するため、正確性が維持されます。 

3 番目のエッジ ケースは、多くのノードが大きなリーチを必要とする場合です。$a_i = N$みんなのために$i$。 これは不可能です。到達可能な最大セット サイズは DAG の順序に従って厳密に減少する必要があるため、アルゴリズムはアクティブな容量が不足していることを即座に検出し、一貫して -1 を返します。
