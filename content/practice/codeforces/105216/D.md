 ## 解決策
 ## 問題の理解

 注文された 2 つのペアの数を数えるように求められます。$N$-桁数は、一連の厳密な桁レベルの制約を満たします。 それぞれの数字は正確に$N$どちらの数字もゼロから始めることはできず、位置ごとに比較する場合、その数字は常に異なる必要があります。 同時に、最初の数値のすべての桁と 2 番目の数値のすべての桁を合計すると、これら 2 つの合計は等しくなければなりません。 

したがって、点単位の不等式制約と桁の合計に対するグローバルな等価制約を使用して、同じ長さの 2 つの数値文字列をペアにします。 各クエリの出力は、そのようなペアの数を法でとったものです。$10^9 + 7$。 

制約は大きく、最大 800 クエリと$N$これにより、数値またはペアを直接列挙しようとするソリューションは即座に除外されます。 単一の数字でも、$9 \cdot 10^{N-1}$可能性があり、それらをペアにすることは完全に不可能です。 ソリューションでは、構造を大幅に圧縮し、クエリ間で計算を再利用する必要があります。 

微妙な特殊ケースは、先頭の桁の制限にあります。 位置間の対称性が崩れるため、どの数字 DP も最初の位置を異なる方法で処理する必要があります。 もう 1 つの問題は、「合計が等しい」という条件によって 2 つの数値がグローバルに結合されるため、累積残高を追跡せずに各位置を個別に決定できないことです。 

## アプローチ

 ブルートフォースアプローチでは、有効なものをすべて列挙することになります。$N$-アリスの場合は数字を、ボブの場合はすべて数字を入力し、両方の条件を確認します。 各ペアについて、すべての桁を比較し、桁の合計を計算します。 それはおおよそ次のことにつながります$(9 \cdot 10^{N-1})^2$ペア、それぞれに必要なもの$O(N)$小切手は、$N=2$。 ボトルネックは、指数関数状態空間上の二次ペアリングです。 

重要な観察は、この問題は桁の位置全体で対称であり、各位置で桁が異なるかどうか、および桁の合計がどのように累積されるかという 2 つの集約されたプロパティのみに依存するということです。 これは、合計桁の合計の差を追跡しながら、位置ごとに両方の数値を同時に構築する桁動的計画法を示唆しています。 

各位置で、アリスの数字とボブの数字を選択します。 制約により、それらは強制的に異なるものになります。 最終条件への影響は、累計の差によってのみ発生します。 両方の合計を追跡する代わりに、それらの差を追跡しますが、その差はゼロで終わる必要があります。 

これは問題を有効な長さのカウントに変換します。$N$数字のペアのシーケンス。各ペアは 2 つの異なる数字で構成され、最初の数字の位置制限と合計のバランスに関するグローバルな制限があります。 これは、合計の差分を DP に圧縮できる古典的な畳み込み構造です。 

単一の位置の遷移を事前計算します。つまり、考えられる各差分状態について、2 つの異なる桁を選択して別の差分状態に移動する方法が何通りあるかを計算します。 次に、この遷移を累乗します$N$先頭のゼロがない制約により、最初の桁の遷移が変更されています。 

この構造は、可能な合計の差を表す状態にわたる線形 DP になります。 各桁の大きさは最大 9 であるため、差の範囲は次のように制限されます。$9N$、管理可能です。

 ## アルゴリズムのチュートリアル

 問題を構築として再定式化します$N$順序付けられた数字のペア$(a_i, b_i)$、 どこ$a_i \neq b_i$。 地位の貢献$i$最終的な制約は$a_i - b_i$、そしてこれらの貢献の合計がゼロになることを要求します。 

1. 位置のプレフィックスを処理した後、桁の合計間の特定の累積差を達成できる方法の数を状態が表す DP を定義します。 違いは以下の範囲に及びます$-9N$に$9N$, そこで、それを非負のインデックス空間にシフトします。 
2. 位置ごとに、順序付けられたすべての数字のペアを列挙することによって、異なる状態間の遷移を計算します。$(a, b)$そのような$a \neq b$。 各ペアはデルタに寄与します$a - b$。 これは、最初の桁の制約を除き、位置に依存しない固定遷移カーネルを定義します。 
3. 最初の位置では、どちらの数字もゼロで始まらないように桁を制限します。 これはつまり$a, b \in [1,9]$、まだ一緒です$a \neq b$。 一度適用されたこれらの遷移のみを使用して DP を初期化します。 
4. 残りについて$N-1$位置では、数字が 0 から 9 までの完全な遷移カーネルを繰り返し適用します。$a \neq b$。 
5. 差分軸上の畳み込みとして DP を維持します。 各ステップでは、有効な数字ペアからの寄与を蓄積することによって、到達可能なすべての差を更新します。 
6. すべての位置を処理した後、等しい桁の合計は合計の差がゼロであることを意味するため、答えは差がゼロで終了する方法の数になります。 

これが機能する理由は、アリスとボブの間の唯一のグローバル結合が合計制約であり、その制約が位置にわたって加算的に分解されるためです。 すべての有効な構造は、異なる状態にわたる DP 内のパスに一意に対応します。 各遷移は、ある位置でのすべての有効な数字ペアの選択肢を正確にエンコードするため、DP は状態を失ったり複製したりしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

# Precompute all (a, b) pairs grouped by delta = a - b
full_trans = {}
first_trans = {}

for a in range(10):
    for b in range(10):
        if a == b:
            continue
        full_trans.setdefault(a - b, 0)
        full_trans[a - b] += 1

for a in range(1, 10):
    for b in range(1, 10):
        if a == b:
            continue
        first_trans.setdefault(a - b, 0)
        first_trans[a - b] += 1

# Determine possible range of differences
MAXD = 9 * 800
OFF = MAXD

def build_dp(trans):
    dp = [0] * (2 * MAXD + 1)
    dp[OFF] = 1  # zero difference
    new = [0] * (2 * MAXD + 1)

    for _ in range(N):
        for i in range(2 * MAXD + 1):
            if dp[i] == 0:
                continue
            val = dp[i]
            for d, cnt in trans.items():
                ni = i + d
                if 0 <= ni <= 2 * MAXD:
                    new[ni] = (new[ni] + val * cnt) % MOD
        dp, new = new, [0] * (2 * MAXD + 1)

    return dp

Q = int(input())
queries = [int(input()) for _ in range(Q)]
maxN = max(queries)

# Precompute DP for all N up to maxN using convolution DP
# dp_full[n] = distribution after n full positions
dp = [0] * (2 * MAXD + 1)
dp[OFF] = 1

full_dp = [None] * (maxN + 1)
full_dp[0] = dp[:]

for i in range(1, maxN + 1):
    new = [0] * (2 * MAXD + 1)
    for j in range(2 * MAXD + 1):
        if dp[j] == 0:
            continue
        val = dp[j]
        for d, cnt in full_trans.items():
            ni = j + d
            if 0 <= ni <= 2 * MAXD:
                new[ni] = (new[ni] + val * cnt) % MOD
    dp = new
    full_dp[i] = dp[:]

ans = {}
for n in queries:
    # first digit layer applied separately
    base = full_dp[n - 1]
    res = 0
    for d, cnt in first_trans.items():
        # shift index by delta
        if -d + OFF < 0 or -d + OFF >= len(base):
            continue
        res = (res + base[-d + OFF] * cnt) % MOD
    ans[n] = res

for n in queries:
    print(ans[n])
```この実装では、桁の合計間の考えられる差に基づいて DP が構築されます。 配列インデックスは、負の値を安全に格納できるように、定数オフセットによってシフトされた現在の合計の差を表します。 最初の桁は、先頭のゼロが許可されていないため、制限された遷移テーブルを使用して個別に処理されます。 

最初の桁を除くすべての位置に対して完全な遷移 DP を事前計算し、これらの結果をすべてのクエリに再利用します。 最後のステップでは次のように畳み込みます。$N-1$-length 最初の桁の遷移を含む結果。 

実装の微妙な詳細は、負の差を処理す​​るために固定オフセットを使用することです。 この変更がなければ、インデックス作成は煩雑になり、エラーが発生しやすくなります。 もう 1 つの重要な詳細は、最初の桁の遷移を分離することです。 そうしないと、ゼロで始まる数値が誤って含まれてしまいます。 

## 実用的な例

 概念的な小さなケースを考えてみましょう。$N = 2$。 最初の桁が 1 つと 2 番目の桁が 1 つあります。 DP は最初に 2 桁目 (等号を除く 0 ～ 9 の桁) のすべての有効な寄与を構築し、次に制限された最初の桁のペアと結合します。 

単一のテストの場合$N = 2$、プロセスは次のように要約できます。 

| ステップ | 状態（差分分布） | アクション |
 | --- | --- | --- |
 | 初期化 | たった0の差 | 開始 |
 | 位置 2 の後 | a-b全体にわたる分布 | 完全なトランジションが適用されました |
 | 最終 | 0 に至る有効な最初の桁の遷移の合計 | 組み合わせる |

 これは、サフィックス構造を事前計算した後に最初の桁が事実上どのように畳み込み境界条件として適用されるかを示しています。 

のために$N = 3$、同じ構造が繰り返されますが、最初の数字と結合する前に 2 つの完全なトランジション レイヤーが適用されます。 

| ステップ | 状態 | 意味 |
 | --- | --- | --- |
 | 初期化 | 0 | 空のプレフィックス |
 | 2層を完全に重ねた後 | 到達可能なすべての違い | 接尾辞の構造 |
 | 最初の桁の畳み込み後 | diff 0 のみが抽出されました | 有効なペア |

 これらのトレースは、DP が均一な内部位置から先頭桁の寄与をきれいに分離していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 のために$N = 1$、1 ～ 9 の 1 桁の数字のみが有効です。 この条件は、合計が等しい個別の数字の順序付きペアをカウントすることに帰着します。これは、すべてのペアをカウントするのと同じです。$a \neq b$、与える$9 \cdot 8 = 72$。 最初の桁の遷移のみが使用され、セットを変更するゼロ先行の制限がないため、DP は正しく初期化されます。 

大型の場合$N$の場合、ゼロ先行制約は最初のステップにのみ影響します。 アルゴリズムはこの層を正しく分離するため、無効な数値が DP 状態に導入されることはありません。 

いつ$N$が最大 (800) である場合、差の範囲が最も広くなります。 オフセットベースのインデックス付けにより、負のインデックス付けが発生しないことが保証され、位置ごとに 9 という制限された桁の寄与により、すべての有効な状態が配列境界内に留まります。
