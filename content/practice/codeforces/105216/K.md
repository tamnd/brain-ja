このプロセスは無限に続き、家の中の 2 台のコンピューターが初めて同じ名前を共有するまでの予想週数を計算するように求められます。 そのイベントは失敗とみなされ、失敗が発生するとすぐにカウントが停止されます。

微妙なエッジケースは次のような場合です$k$を超える$N$。 その場合、以上のものを持っているとすぐに重複が避けられなくなります。$N$ウィンドウ内の項目は表示されますが、ウィンドウのサイズには上限があるため、$k$、プロセスは実質的に異なる動作をします。 もし$k > N$、イベントは最終的に保証されますが、予想される時間は、スライディング ウィンドウがどれだけ早く埋まり、力が重なるかによって異なります。 ウィンドウは静的ではないため、単純な「k 個の項目に関する誕生日のパラドックス」アプローチは間違っています。

 ## アルゴリズムのチュートリアル

 最初の重複が次のサイズのスライディング ウィンドウに表示されるまでの予想時間を計算します。$k$、均一なランダム抽選の下で$1$に$N$。 

1. 各プレフィックス長の生存確率をモデル化します。$i$重複がまだ発生していないと仮定します。 まず最初に$k$ステップでは、以前に表示された値はすべて異なるため、ステップでは$i$、まさにあります$i-1$禁止された値。 これにより、生存確率係数は次のようになります。$\frac{N-(i-1)}{N}$。 
2. この推論をステップに拡張します。$k+1$、ウィンドウがいっぱいになりました。 サバイバルの下では、ウィンドウには次の内容が含まれます$k$個別の値なので、次の値が安全である確率は次のようになります。$\frac{N-k}{N}$。 この値は、後続のすべてのステップで安定したままになります。 
3. 生存確率を繰り返し計算します。 させて$S_i$ステップまでに衝突が発生しなかった確率$i$。 初期化する$S_0 = 1$、上で導出された段階的な生存係数を使用して更新します。 
4. 予想停止時間はアイデンティティを使用して計算されます。$E[T] = \sum_{i \ge 0} S_i$これは、停止イベントを直接列挙するのではなく、停止時間を生存確率の合計に変換します。 
5. 合計を 2 つの部分に分割します。$i \le k$、生存確率は、利用可能な選択肢が減少するにつれて乗算的に減少し、 から始まる無限の尾部が発生します。$k+1$、比を持つ等比級数になります$\frac{N-k}{N}$。 
6. 次の実行積を使用して有限プレフィックスを計算します。$\frac{N-i}{N}$、次に、から始まる閉じた形状の幾何学的尾部を追加します。$S_k$。 
7. すべての計算はモジュロで実行されます$10^9+7$、除算には逆モジュラーを使用します。$N$。 

### なぜ効果があるのか

 重要な不変条件は、衝突が発生しない限り、アクティブなウィンドウは常に個別の要素で構成されるということです。 これにより、次の描画の禁止値の数が、正確な履歴ではなく、現在のウィンドウ サイズのみに依存するようになります。 ウィンドウがサイズに達したら$k$、禁止値の数は正確に安定します。$k$、その時点からプロセスはメモリレスになります。 これにより、問題が、変化する確率の接頭辞と、それに続く静止した幾何学的な尾部に変換され、期待値が一意に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    N, k = map(int, input().split())
    
    # If k >= N, collision happens quickly in expectation,
    # but formula still works if handled carefully.
    
    invN = modinv(N % MOD)
    
    # S = survival probability up to current step
    S = 1
    
    # expected value
    ans = 0
    
    # prefix up to k steps
    for i in range(1, k + 1):
        ans = (ans + S) % MOD
        S = S * (N - (i - 1)) % MOD * invN % MOD
    
    # tail geometric part: from step k+1 onward
    # survival ratio becomes (N-k)/N
    if N > k:
        ratio = (N - k) % MOD * invN % MOD
        
        # expected remaining contribution = S / (1 - ratio)
        # = S * N / k
        inv_one_minus = modinv((k % MOD))
        tail = S * N % MOD * inv_one_minus % MOD
        ans = (ans + tail) % MOD
    else:
        # if k >= N, collision guaranteed soon; treat tail carefully
        ans = ans % MOD
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは実行中の生存確率を維持します`S`これは、「これまでのところすべて異なる」という仮定の下で、現在のプレフィックス長まで重複が発生しない確率を表します。 各反復が更新されます`S`利用可能な新しい選択肢の数を使用します。 プレフィックスの寄与により、予想される生存質量が蓄積されます。 

サイズに達したら`k`、プロセスは定常状態に入り、新しい描画が行われるたびに確率との衝突が回避されます。`(N-k)/N`。 これにより幾何学的なテールが作成され、モジュラー逆関数を使用して閉じた形式で合計されます。`k`。 

実装の微妙な点は、モジュール分割をきれいに処理することです。 表現`S * N / k`モジュラー算術では、逆モジュラーを使用して記述する必要があり、オーバーフローを回避して正確性を維持するには、乗算の順序が重要です。

 ## 特殊なケース

 いつ$N = 1$、すべてのコンピュータには同じ名前が付いています。 最初の挿入は常に安全ですが、2 回目の挿入ではすぐに衝突が発生します。 最初のステップの後に生存確率がゼロに低下し、期待値が小さな定数に崩壊するため、アルゴリズムはこれを処理します。 

いつ$k = 1$、ウィンドウに複数のコンピューターが配置されることはありません。 新しいコンピューターはそれぞれ、以前のコンピューターとのみ比較されます。 これは、2 つの連続した描画が一致したときに衝突が発生する単純な幾何学的プロセスに退化します。 プレフィックスの計算は自然にシングルステップの生存モデルに縮小され、テールの式はステップ 1 の直後に正確になります。 

いつ$k \ge N$、初期に衝突が発生しなかった場合、ウィンドウは最終的にすべての可能な名前を含むのに十分な大きさです。 プレフィックスの計算は、システムが新しい値が存在しない領域に移行し、幾何学的なテールが強制的に消滅するまで、縮小する可用性を正確に捕捉します。
