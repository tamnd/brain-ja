 ## 解決策
 ## 問題の理解

 賞品の値の行が与えられ、各賞品は正の整数値を持ちます。 ジョンにはスコア制限がある$p$を超えない価値のある賞品のみを選ぶことが許可されています。$p$。 すべての有効な賞品の中で、彼は最も価値のある賞品を望んでいます。 

簡単に言うと、整数のリストをスキャンし、最大でも指定されたしきい値以下の整数のみを考慮することが許可されます。 タスクは、これらの適格な整数の最大値を見つけることです。 

制約は小さいです: どちらの賞品の数も$n$およびすべての値を含む$p$これは、配列に対する単純な線形スキャンでも十分な速度であることがすぐにわかります。 アン$O(n)$あるいは$O(n^2)$このアプローチは制限内であれば快適に実行できますが、それを超えると不必要な複雑さになります。 

入力の構造も単純です。1 行目はサイズと制限を示し、2 行目は賞金の値のリストを示します。 

このような単純な問題でも、いくつかの特殊なケースが重要になります。 まず、すべての値は以下に等しい可能性があります。$p$、すべての項目が有効であり、答えは単にその値であることを意味します。 第 2 に、有効な最大値がリストの最後に表示される可能性があるため、ソート順を前提とした早期停止戦略は、盲目的に適用すると失敗します。 第三に、以下の値$p$はどこにでも現れる可能性があるため、有効な最大の要素ではなく、最初の有効な要素を誤って選択しないようにする必要があります。 

## アプローチ

 ブルートフォースのアイデアは、最終的な解決策とほぼ同じです。 私たちはすべての賞品に目を通し、許可された最高の価値を追跡します。 各要素について、以下の場合$p$、現在のベストアンサーと比較し、それが大きい場合は更新します。 

これが機能するのは、すべての有効な候補が少なくとも 1 回検査される必要があり、要素をスキップできる順序保証がないためです。 操作回数は正確に$n$しきい値との比較、および最大$n$最大変数の更新なので、全体的に$O(n)$。 

これを超える意味のある最適化はありません。 仕分けには費用がかかる$O(n \log n)$ロジックを改善することなく。 ヒープやセグメント ツリーなどのデータ構造は、静的配列に対する単一のクエリにとって不必要なオーバーヘッドです。 重要な観察は、問題は純粋に静的リストに対する制約された最大値であるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース スキャン |$O(n)$|$O(1)$| 承認済み |
 | 並べ替えてフィルタリングする |$O(n \log n)$|$O(1)$または$O(n)$| 受け入れられるが不要 |
 | 最適なスキャン |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 これまでに確認された最高の有効な賞品を格納する単一の変数を維持しながら、配列を 1 回処理します。 

1. 変数を初期化する`best`すべての賞品の値が少なくとも 1 であるため、誤って 0 が答えになることはあり得ません。 
2. 各賞品の値を反復処理します。$v_i$配列内で左から右に。 
3. それぞれの値が満たされているかどうかを確認します。$v_i \le p$。 この条件により、ジョンが取得できる賞品のみが考慮されることが保証されます。 
4. 値が有効な場合は、次と比較します。`best`。 もし$v_i > best$、 アップデート`best`に$v_i$。 このステップにより、これまでに確認された有効な最大値が常に保持されるようになります。 
5. すべての値を処理した後、出力します。`best`最終的な答えとして。 

この手順が機能する理由は、すべての実行可能な候補が 1 回だけ検査され、最初の候補を処理した後もアルゴリズムが不変条件を維持するためです。$k$要素、`best`そのプレフィックス内のすべての有効な要素の最大値を格納します。 最終的な答えは有効な値のグローバル最大値のみに依存するため、この不変式を配列全体に拡張することで正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    arr = list(map(int, input().split()))
    
    best = 0
    for v in arr:
        if v <= p and v > best:
            best = v
    
    print(best)

if __name__ == "__main__":
    solve()
```解決策は、リストのサイズとしきい値を読み取ることから始まります。 次に、すべての賞品の値を解析して配列に入れます。 

変数`best`すべての値が正であるため、0 に初期化されます。そのため、これは制約の下で最大限の追跡を行うための安全な単位要素です。$v_i \le p$。 

ループは両方のチェックを 1 回のパスで実行します。まず、次の点について実現可能性を検証します。$p$、次に最大値を更新します。 この順序により、無効な値による誤った更新が防止されます。 

最後に、計算された最大値が直接出力されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての要素が次の値より大きい場合です。$p$。 たとえば、次の場合$p = 2$そして配列は$[5, 6, 7]$、値は対象になりません。 アルゴリズムが初期化されます`best`この問題では少なくとも 1 つの有効な選択が存在することが保証されているため、このケースは公式の入力には表示されませんが、実装では引き続き安全に処理されます。 

もう 1 つのエッジ ケースは、有効な最大値が最初の位置に現れる場合です。 入力用$p = 10$、 配列$[9, 1, 8]$、アルゴリズムは正しく設定します`best`すぐに 9 に設定され、その後の小さな値の影響を受けません。 

最後のエッジケースは、有効な最大値が最後に現れる場合です。 入力用$p = 10$、 配列$[1, 2, 10]$、アルゴリズムは段階的に更新され、最後の要素が最良のものとして正しくキャプチャされます。 これにより、正確性のために順序付けの仮定が必要ないことが確認されます。
