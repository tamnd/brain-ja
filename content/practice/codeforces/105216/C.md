 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには、$N$各時計には独自の固定された周期的な動作があります。 クロック$i$時々音を出す$1, 1+i, 1+2i, 1+3i,\dots$。 すべての時計は、最初の音が所定の時刻に発生するように初期調整されています。$1$、そしてそれぞれの期間で繰り返し続けます。 

私たちは次のように尋ねられます：特定の時間に$T$、これらの時計のうち、正確にその瞬間に音を発する時計は何個ありますか。 

したがって、固定時計の場合$i$かどうかを確認する必要があります。$T$から始まる等差数列に属します$1$ステップ付き$i$。 これは、$T-1$で割り切れます$i$。 したがって、各テスト ケースの答えは整数の数になります。$i$範囲内で$[1, N]$そのような$i \mid (T-1)$。 

制約は次のとおりです$N, T \le 10^9$最大 100 のテスト ケース。 これにより、テスト ケースごとにすべてのクロックを反復するアプローチは即座に除外されます。$O(NQ)$、最悪の場合は、$10^{11}$操作。 

次の場合、微妙なエッジケースが発生します。$T = 1$。 この場合、すべての進行は 1 から始まるため、すべての時計が時刻 1 に鳴ります。$T-1 = 0$すべてを意味します$i$0 を割るので、答えは次のようになります。$N$。 この特別な構造を忘れた実装では、誤って 0 を返したり、除算チェックを誤って処理したりする可能性があります。 

もう一つ注意すべきケースは大きい$T$どこ$T-1 > N$。 約数は常に小さいと仮定する素朴な約数の計算アプローチ$N$約数を数えているだけであるという事実を見落とす可能性があります。$N$のすべての約数ではありません$T-1$。 

## アプローチ

 直接シミュレーションのアプローチは簡単です。 各時計ごとに$i$1から$N$かどうかを確認します。$T-1$で割り切れます$i$。 これは、時計の観察から正しく導き出されます。$i$時間ごとに鳴る$1 + k i$したがって、メンバーシップをテストするだけで済みます。$T$その順番で。 ボトルネックは明らかです。テスト ケースごとに最大でスキャンが必要になる場合があります。$10^9$この値は実現可能な限界をはるかに超えています。 

重要な構造的洞察は、問題は実際にはすべてのクロックに個別に関係しているのではなく、単一の数の約数に関係しているということです。$T-1$。 各有効なクロック インデックスは正確に次の約数です。$T-1$を超えない約数のみを考慮します。$N$。 これにより、問題は有界除数カウント問題に変わります。 

可能な限りすべてを繰り返すのではなく、$i$、約数を列挙します$T-1$までスキャンすることで効率的に$\sqrt{T-1}$。 各約数について$d$、両方を考慮します$d$そして$(T-1)/d$以内にある場合はカウントします。$[1, N]$。 これにより、各テスト ケースが次のように縮小されます。$O(\sqrt{T})$これは十分に高速です。$\sqrt{10^9} \approx 31623$。

 ## アルゴリズムのチュートリアル

 クロックと除数を直結する形で条件を書き換えます。 時計$i$時間ごとに鳴る$T$もし、そしてその場合に限り$T = 1 + k i$ある整数に対して$k$、これは以下と同等です$T-1$で割り切れる$i$。 

と表します。$x = T - 1$。 タスクは整数の数を数えるようになります$i$満足する$1 \le i \le N$そして$i \mid x$。 

### ステップ

 1. コンピューティング$x = T - 1$。 これにより、等差数列条件がきれいな割り算条件に変換されます。 問題の構造は完全に把握されています$x$。 
2. 応答カウンターをゼロに初期化します。 これにより、有効な約数が累積されます。$x$上限も尊重します$N$。 
3. 反復する$i$1から$\lfloor \sqrt{x} \rfloor$。 それぞれについて$i$、どうかを確認してください$i$分割する$x$。 これは、約数が平方根を中心に対称的なペアになるため効率的です。 
4.いつでも$i \mid x$、両方を考慮してください$i$そして$x / i$潜在的なクロックインデックスとして。 それぞれが有効な約数のペアを表します。 
5. 各候補約数について、最大でも次の場合にのみ答えに追加します。$N$。 これにより、システム内に存在するクロックのみをカウントすることが保証されます。 
6. もし$i = x / i$, 完全な正方形の場合なので、二重に数えることは避けてください。 

### なぜ効果があるのか

 すべての有効なクロック インデックスは正確に次の約数です。$x = T-1$、およびそのすべての約数$x$時を刻む時計に相当する$T$。 列挙が終わりました$\sqrt{x}$より大きい約数があるため、すべての約数のペアが漏れなく見つかることが保証されます。$\sqrt{x}$小さいものと組み合わせています。 によるフィルタリング$N$存在するクロックのみをカウントすることを保証するため、アルゴリズムは、次の約数間の交差を正確に計算します。$x$そして範囲$[1, N]$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, t = map(int, input().split())
        x = t - 1
        
        ans = 0
        
        i = 1
        while i * i <= x:
            if x % i == 0:
                if i <= n:
                    ans += 1
                j = x // i
                if j != i and j <= n:
                    ans += 1
            i += 1
        
        print(ans)

if __name__ == "__main__":
    solve()

ここでよくある間違いは、両方のことを忘れることです。$i$そして$x//i$に対してテストする必要があります$N$独立して。 もう 1 つは、ループを 0 から開始するか、ケースの処理を誤っていることです。$x = 0$、ここで、以下のすべての整数$N$有効です。
