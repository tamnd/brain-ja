 ## 解決策
 ## 問題の理解

 私たちには、各セルが陸地、水、または溶岩のいずれかである大きなグリッドが与えられています。 溶岩は禁止されていますが、陸と水は通行可能です。 移動は 4 方向で、移動のコストは水が関係するかどうかによってのみ決まります。土地から土地への移動にはスタミナが 0 かかりますが、何らかの形で水に触れた移動には 1 スタミナがかかります。 

グリッド全体に点在するのは、宝石を含む最大 15 個の特別なセルです。 また、溶岩ではなく、宝石が含まれていないことが保証されている開始セルもあります。 このタスクは、マディがグリッド上を移動し、少なくとも k 個の個別のジェム セルを訪問するために必要な最小合計スタミナを計算することです。 

重要な点は、宝石を訪れること自体はスタミナを消費せず、移動のみが消費されるということです。 宝石セルに到達すると、それは収集されたとみなされ、再訪問しても新しいものは何も追加されません。 

グリッドは 2000 × 2000 までの大きさになる可能性があり、どの宝石が収集されているかとともに、すべてのセルのすべての状態を明示的にモデル化しようとするソリューションは即座に除外されます。 サイズ n * m * 2^C の状態空間にわたる単純な最短パスは、1 つのテスト ケースでもすでに数億の状態を超えており、複数のテスト ケースがある可能性があるため、大きすぎます。 

重要な構造上の制約は、C が最大でも 15 であることです。これは唯一の小さなパラメーターであり、すべてのグリッド セルについて直接推論するのではなく、問題をこれらのいくつかの特別な点間の相互作用にまで圧縮する必要があることを示唆しています。 

素朴なアプローチを打ち破る危険な状況がいくつかあります。 

1 つは、すべての移動のコストが 1 であると仮定し、BFS を直接使用する方法です。 陸地間の移動は自由であるため、最短経路の重み付けが解除されないため、これは失敗します。 

もう 1 つは、すべての gem から個別に最短パスを実行しようとし、グリッド距離を再利用せずに繰り返し再計算することです。 それは大きな定数係数の爆発につながります。 

より微妙なケースは、最適なルートが水のセルを通過する必要がある場合です。水のセルには宝石が含まれているためではなく、水のセルが陸地間の唯一の橋であるためです。 陸上接続コンポーネントを介して宝石を接続するだけのソリューションは、接続のために水が避けられない入力では失敗します。 

最後に、宝石を集めるということは、単に最も近い k に個別に到達することだけではありません。 場合によっては、最適なルートが中間の宝石を迂回し、総水への露出を減らすため、最も近い距離による貪欲な選択は機能しません。 

## アプローチ

 直接的なアプローチでは、各状態が現在のグリッド セルと収集されたジェムのセットで構成されるペアである拡張状態空間上の最短経路問題としてプロセス全体をシミュレートします。 各移動は隣接するセルに移行し、場合によっては収集されたセットを更新します。 移行コストは地形に応じて 0 または 1 です。 これは原理的には正しいですが、状態の数は n * m * 2^C になります。 n と m は最大 2000、C は最大 15 なので、これは実現可能な限界をはるかに超えています。 

重要な観察は、グリッド構造は、重要なノードの小さなセット、つまり開始位置と宝石の位置の間の最短経路距離を計算する場合にのみ重要であるということです。 重要なノードから他のノードに移動するために必要な最小スタミナがわかれば、グリッド自体を考慮する必要はなくなります。 

これにより、問題は最大 16 個のノード上の完全な重み付きグラフに縮小され、エッジの重みは元のグリッドの最短パス コストを表します。 残りのタスクは、最小の総コストで少なくとも k 個の gem ノードを訪問するウォークを選択することになります。

この縮小された問題の総当りバージョンでは、C では階乗である、訪問する gem のすべての順列が試行されます。ただし、C は最大 15 であるため、サブセットに対するビットマスク動的プログラミングが可能になります。 重要なノードのすべてのペア間の最短パスを計算し、DP を実行します。ここで、状態はどの gem が収集され、どの gem が現在いるかを表します。 

ペアごとの距離を効率的に計算するために、エッジの重みが 0 または 1 のみであるという事実を利用します。これにより、セル数の線形時間でグリッド上の各重要なノードから 0 ～ 1 の BFS を使用できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な状態の BFS オーバー (セル、サブセット) | O(nm · 2^C) | O(nm · 2^C) | 遅すぎる |
 | ペアワイズ 0-1 BFS + ビットマスク DP | O(C・nm + 2^C・C^2) | O(nm + 2^C · C) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、重要な位置、つまり開始セルとすべての gem セルを分離します。 これらを小さいグラフ内のノードとして扱い、0 から C までインデックスが付けられます。0 は開始点、1 から C は宝石です。 

次に、0 ～ 1 の移動コスト ルールに従って、これらのノードのすべてのペア間のグリッド内の最短パス距離を計算します。 

1. 重要なノードごとに、グリッド全体で 0 ～ 1 BFS を実行します。 BFS は、そのノードから到達可能なすべてのセルに最小のスタミナ コストを割り当てます。陸上セル間の遷移のコストは 0、水を伴う移動のコストは 1 です。BFS は、コスト 0 のエッジがコスト 1 のエッジよりも前に処理されるように、両端キューを使用します。 
2. 特定のソース ノードから BFS を実行した後、他の重要なノードの位置でのみ距離を抽出します。 これにより、重要なノード間の完全な距離行列の 1 行が得られます。 
3. すべての C+1 個の重要なノードに対してこれを繰り返し、完全なペアワイズ距離行列 dist[i][j] を構築します。 
4. 次に、問題を宝石上のサブセット DP に縮小します。 dp[mask][i] を、初期位置から開始し、マスク内の gem のセットを正確に訪問し、gem i で終了するために必要な最小スタミナとして定義します。 
5. 開始ノードから各 gem i に直接遷移し、dp[1 << (i-1)][i] を dist[start][i] に設定して、dp を初期化します。 
6. 遷移の場合、状態 dp[mask][i] から、dp[mask | i] を更新しながら、未訪問の gem j への移動を試みます。 (1 << (j-1))][j] dp[mask][i] + dist[i][j] を使用します。 
7. DP を満たした後、マスクに少なくとも k 個の宝石が含まれているすべての状態を調べ、それらの中で最小の dp 値を取得します。 

正確かどうかは、関連するすべてのノード間の最短パス コストが判明すると、内部グリッド構造はもはや重要ではなくなるという事実にかかっています。 次に、DP は宝石を訪問するすべての可能な順序を調査し、最適なルートが宝石訪問の順列として表現できることを確認します。 DP はすべてのサブセットとすべての終点を考慮するため、考えられるすべてのルート構造が含まれます。 

不変条件は、dp[mask][i] が常に、マスク内の gem を正確に収集し gem i で終わるすべてのパスの最適コストを表すということです。 すべての遷移では、事前に計算された最短パス距離が使用され、グリッド内の 2 つのエンドポイント間を移動するための最善の方法がすでにエンコードされているため、最適性が維持されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline
INF = 10**18

def zero_one_bfs(start_i, start_j, grid, n, m):
    dist = [[INF] * m for _ in range(n)]
    dq = deque()
    dist[start_i][start_j] = 0
    dq.append((start_i, start_j))

    while dq:
        x, y = dq.popleft()
        cur = dist[x][y]

        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x + dx, y + dy
            if nx < 0 or nx >= n or ny < 0 or ny >= m:
                continue
            if grid[nx][ny] == 2:
                continue

            w = 0 if (grid[x][y] == 0 and grid[nx][ny] == 0) else 1
            nd = cur + w

            if nd < dist[nx][ny]:
                dist[nx][ny] = nd
                if w == 0:
                    dq.appendleft((nx, ny))
                else:
                    dq.append((nx, ny))

    return dist

def solve():
    t = int(input())
    for _ in range(t):
        n, m, C, k = map(int, input().split())
        sx, sy = map(int, input().split())
        sx -= 1
        sy -= 1

        grid = []
        for _ in range(n):
            grid.append(list(map(int, list(input().strip()))))

        gems = []
        for _ in range(C):
            x, y = map(int, input().split())
            gems.append((x - 1, y - 1))

        nodes = [(sx, sy)] + gems
        sz = len(nodes)

        dist = [[INF] * sz for _ in range(sz)]

        for i in range(sz):
            si, sj = nodes[i]
            d = zero_one_bfs(si, sj, grid, n, m)
            for j in range(sz):
                ti, tj = nodes[j]
                dist[i][j] = d[ti][tj]

        dp = [[INF] * sz for _ in range(1 << C)]

        for i in range(1, sz):
            mask = 1 << (i - 1)
            dp[mask][i] = dist[0][i]

        for mask in range(1 << C):
            for i in range(1, sz):
                if dp[mask][i] == INF:
                    continue
                for j in range(1, sz):
                    if mask & (1 << (j - 1)):
                        continue
                    nmask = mask | (1 << (j - 1))
                    nd = dp[mask][i] + dist[i][j]
                    if nd < dp[nmask][j]:
                        dp[nmask][j] = nd

        ans = INF
        for mask in range(1 << C):
            if bin(mask).count("1") >= k:
                for i in range(1, sz):
                    ans = min(ans, dp[mask][i])

        print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```コードは、各重要なノードから 0 ～ 1 BFS を実行し、グリッド上の完全な距離行列を計算することから始まります。 重要な詳細はコスト ルールです。移動は両方のエンドポイントが着地の場合にのみ無料で、それ以外の場合は 1 コストかかり、これはエッジ緩和に直接エンコードされます。 

距離が計算された後は、グリッドが再度使用されることはありません。 動的プログラミング ステージでは、事前に計算された最短パスをエッジの重みとして使用して、各 gem を完全なグラフ内のノードとして扱います。 

よくある実装の落とし穴は、dp 遷移ではマンハッタン距離やローカル グリッド ステップではなく、事前に計算された最短パスを使用する必要があることを忘れていることです。 もう 1 つは、ビットマスク内の gem 0 がノード配列内のノード 1 に対応するため、gem ビットのインデックスが間違っていることです。 

## 実用的な例

 一部のパスで水を通過する必要がある、スタート地点と 3 つの宝石がある小さなシナリオを考えてみましょう。 目標は、最も近い宝石を貪欲に選択するのではなく、DP がどのようにサブセットを構築するかを説明することです。 

dp の状態を (マスク、終了ノード、コスト) として追跡します。 

| ステップ | マスク | エンドノード | コスト |
 | --- | --- | --- | --- |
 | 初期化 | 001 | G1 | dist(S, G1) |
 | 初期化 | 010 | G2 | dist(S, G2) |
 | 移行 | 011 | G2 | dp[001][1] + dist(G1, G2) |
 | 移行 | 011 | G1 | dp[010][2] + dist(G2, G1) |

 これは、異なる注文を介して同じサブセットにどのように到達できるかを示しており、DP は最も安い注文を維持します。 

次に、幾何学的順序で宝石を収集することが、余分な水を通過する必要があるため最適ではない 2 番目の例を考えてみましょう。 DP は依然としてすべての順列を探索するため、空間的に直感的ではない場合でも、高コストの順序付けを自然に回避し、より安価な順序を選択します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(C · n · m + 2^C · C^2) | 各重要なノードはグリッド上で 0 ～ 1 BFS を実行し、次にサブセット上の DP がすべての gem 状態を接続します。 
| スペース | O(n · m + 2^C · C) | グリッド距離ストレージとサブセットおよびエンドポイント上の DP テーブル |

 グリッド サイズは大きくなりますが、すべてのテスト ケースにわたる n · m の合計には制限があるため、BFS 部分は管理可能に保たれます。 サブセット DP はグリッド サイズには依存せず、小さい C にのみ依存します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、水を使用しない限り、スタート地点と宝石が完全に切り離された陸地領域にある場合です。 その状況では、陸上のみの BFS を介した接続を前提とするソリューションでは、到達不能と誤って報告されます。 0-1 BFS はコスト 1 で水を介して正しくルーティングされるため、DP は引き続きその宝石を考慮できます。 

もう 1 つのエッジ ケースは、k が C に等しい場合です。DP は完全なマスクのみを考慮する必要があり、ビット数をチェックせずに誤ってすべての状態の最小値を取得する可能性があります。 正しい処理では、答えを取得する前にポップカウントによってマスクを明示的にフィルタリングします。 

最後のエッジケースは、複数の宝石がそれらの間で同一の最短経路距離を共有する場合です。 DP はパスの一意性に依存せず、最小限のペアごとのコストのみに依存するため、引き続き正しく機能します。そのため、等コスト遷移は正確性や最適性に影響を与えません。
