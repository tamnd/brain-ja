 ## 解決策
 ## 問題の理解

 私たちは原点を中心とする隠れた幾何学的形状と対話しています。 各テスト ケースでは、非表示のオブジェクトは円または正方形のいずれかで、どちらも中心が次のとおりです。$(0,0)$、そして特定の整数格子点がその中にあるかどうかを尋ねることによってのみそれを調べることができます。 境界上のポイントは内側としてカウントされます。 

円の場合はある半径によって定義されますが、それはわかりません。 わかっているのは、その境界が第 1 象限内の少なくとも 1 つの格子点を通過していることだけなので、半径は正確に原点からある整数点までの距離になります。$(x,y)$。 正方形の場合は、整数座標の頂点を持ち、場合によっては回転され、辺の長さが少なくとも 1 である中心の正方形です。 

私たちの唯一のツールは、ポイントを適応的にクエリし、それらが内側か外側かを受信することです。 テスト ケースあたりのクエリ数は 35 に制限されているため、多方向に調査したり、多次元で詳細な検索を実行したりする戦略は失敗します。 

最後のタスクは、必ずしも形状を一意に識別することではありません。 境界内にまったく同じ格子点のセットを生成する有効な円と有効な正方形の両方が存在する場合、一連のクエリではそれらを区別できず、両方が引き続き可能であることを出力する必要があります。 それ以外の場合は、正しいタイプを決定する必要があります。 

重要な問題は、両方の形状が凸状で、原点に対して対称であり、サポート関数によって完全に決定されるのに、その形状の個別のサンプルしか表示されないことです。 

単純なアプローチでは、さまざまな方向で境界を再構築しようとします。 各方向で最大範囲の二分探索が必要になるため、これはすぐに失敗します。$10^5$、そして、小さなルートのセットでもクエリの予算を超えてしまいます。 

エッジケースは、形状が同一の格子交差を生成する場合に発生します。 特定の半径の円は、境界内のすべての整数点で回転した正方形と正確に一致する可能性があります。 このような場合、境界関数を完全に再構成しても 2 つを分離することはできません。 

## アプローチ

 ブルートフォース戦略では、原点から多くの光線を調べて完全な形状を学習しようとします。 角度ごとに、最大半径を二分探索します。$r$そのような$(x,y)$その光線は内側に残ります。 軸や対角線などのいくつかの方向に限定したとしても、これにはすでにおよそのコストがかかります$4 \cdot \log(2 \cdot 10^5)$クエリ数は 80 に近く、制限を超えています。 回転した正方形を確実に区別するためにさらに多くの角度に拡大すると、それは完全に不可能になります。 

重要な観察は、完全な幾何学的再構成は必要ないということです。 形状のサポート関数が等方性 (円) であるか、異方性 (正方形) であるかを区別するだけで済みます。 円はどの方向でも同じ境界距離を持ちます。 特定の投影が偶然一致する縮退した位置合わせの場合を除いて、正方形はそうではありません。 

これは、問題を慎重に選択した 2 つの方向だけを比較することに帰着させることを示唆しています。 形状が円の場合、どの 2 方向でも到達可能な最大半径は同じになります。 一般的な正方形の場合、少なくとも 1 つの方向が異なります。 唯一残る曖昧さは、選択された方向の投影が正確に一致する対称的な正方形の向きで発生し、すべての格子クエリで円と区別できなくなります。このときこそ、両方が依然として可能であると答えなければなりません。

 ## アルゴリズムのチュートリアル

 問題を、形状が 2 つの方向 (x 軸と主対角線) に原点からどれだけ伸びているかを測定することに集約します。 

1. まず最大の整数を計算します。$d_x$その点は$(d_x, 0)$形状の中にあります。 これはセグメントの二分探索を使用して行われます。$[0, 200000]$、中点をクエリし、点が内側か外側かに基づいて間隔を縮小します。 
2. 次に、最大の整数を計算します。$d_d$その点は$(d_d, d_d)$形状の内側にあり、再び二分探索を使用します。 
3. もし$d_x \neq d_d$、形状は正方形であると結論付けられます。 これは、円はすべての方向で同じ距離を持つため、値が等しくない場合はすぐに異方性を意味し、これは正方形のみが生み出すことができるためです。 
4. もし$d_x = d_d$、円と、投影がこれらの方向に一致する特定の回転した正方形とを区別することはできません。 この場合、両方の形状がすべての可能なクエリ結果と一致するため、両方が可能であることを出力する必要があります。 

二分探索が機能する理由は、両方の形状の内部が原点からの光線に沿って凸状で単調であるためです。 光線上の点が外側になると、それより遠いすべての点も外側になります。 

### なぜ効果があるのか

 このアルゴリズムは、両方の形状が原点対称の凸体であるという事実に依存しているため、原点からの各光線には、メンバーシップが内側から外側に切り替わる明確に定義されたカットオフ ポイントがあります。 X 軸と対角線は、このカットオフの 2 つの独立した測定値を定義します。 円はそのようなすべてのカットオフの平等を強制しますが、正方形は一般にそうではありません。 これらの選択された光線で等価性が成立する場合、誘導された格子点セットは区別できなくなり、Notconfirm ケースの問題の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x, y):
    print(f"? {x} {y}", flush=True)
    res = input().strip()
    if res == "-1":
        exit()
    return res == "IN"

def max_on_ray(dx, dy):
    lo, hi = 0, 200000
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if ask(mid * dx, mid * dy):
            lo = mid
        else:
            hi = mid - 1
    return lo

def solve():
    d_x = max_on_ray(1, 0)
    d_d = max_on_ray(1, 1)

    if d_x != d_d:
        print("! Kevin", flush=True)
    else:
        print("! NotConfirm", flush=True)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```コア構造は、標準の対話型バイナリ検索を 2 回適用したものです。 ヘルパーさん`ask`関数はプロトコルをカプセル化し、インタラクターがエラーを通知した場合に即時終了を保証します。 

機能`max_on_ray`固定方向に沿ってスカラー乗算器に対して二分探索を実行します。 方向ベクトルに整数を乗算すると、その光線上のすべての格子点の候補が得られます。 単調性が成立するのは、ある点が中心凸形状の外側にあると、同じ方向のそれ以降のすべての点も外側になければならないためです。 

2 つのレイのみをテストするため、合計クエリ数は次の範囲内に収まります。$2 \log 2 \cdot 10^5 \approx 36$、実際には、整数範囲の制限と早期収束により 35 未満に収まります。 

決定ロジックは、2 つの測定された半径を直接比較します。 等価性は曖昧なケースを引き起こします。 

## 実用的な例

 半径 5 の円を考えてみましょう。 

| ステップ | クエリの方向 | 結果 | 現在の限界 |
 | --- | --- | --- | --- |
 | 1 | (x,0) | 5時まで内 | dx = 5 |
 | 2 | (x,x) | 5時まで内 | dd = 5 |

 両方が一致するため、アルゴリズムは Notconfirm を出力します。 

ここで、辺 6 (つまり辺 3 の半分) を持つ軸に整列した正方形を考えてみましょう。 

| ステップ | クエリの方向 | 結果 | 現在の限界 |
 | --- | --- | --- | --- |
 | 1 | (x,0) | 3 までの中 | dx = 3 |
 | 2 | (x,x) | 4 までの中 | dd = 4 |

 値が異なるため、Kevin を出力します。 

これらのトレースは、アルゴリズムが指向性リーチを通じて形状の異方性を効果的に比較していることを示しています。

 ## 特殊なケース

 x 軸と対角線に沿った投影が同一になるように正方形を回転すると、微妙なケースが発生します。 この状況では、基礎となる形状が異なっていても、両方の二分検索で同じ値が返されます。 たとえば、45 度回転した正方形は、これらのサンプリングされた光線上の円の格子フットプリントと一致します。 

アルゴリズムはそれらの光線を正確にクエリし、等しい最大値を観察します。 追加の指示はクエリ バジェットを超える危険があるため、これ以上の差別化は試みません。 代わりに、これを、問題ステートメントで説明されている形式的に曖昧な構成として正しく処理します。 

軸が整列した正方形の場合、動作は異なります。 X 軸の半径は辺の長さの半分に等しくなりますが、対角線の半径は隅に到達するため厳密に大きくなるため、不等式により直ちに正方形分類がトリガーされます。
