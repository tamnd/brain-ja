 ## 解決策
 ## 問題の理解

 私たちは、白のキングが特定の座標から開始し、最終的にすべての黒のルークを捕獲する必要がある無限グリッドに取り組んでいます。 キングは標準的なチェスのキングのように動きます。つまり、1 回の動きで 8 つの隣接するセルのいずれかに進むことができます。 厄介なのは、現在生きているルークの攻撃を受けているマス目にキングが足を踏み入れることができないことです。 ルークはその行と列に沿って攻撃しますが、別のルークが視線を遮るまでは直線でのみ攻撃します。 ルークが捕らえられると、ルークは消えて攻撃に貢献しなくなります。 

課題は、キングが攻撃されたマスに足を踏み入れることなく、最終的にすべてのルークに到達して捕獲できるような、移動と捕獲の何らかの順序が存在するかどうかを判断することです。 

入力により複数のテスト ケースが提供されます。 各テスト ケースでは、キングの開始位置とルーク座標のリストが提供されます。 出力は、テスト ケースごとの単純な到達可能性の決定です。 

制約は大きく、テスト ケースごとに最大 10^5 のルークがあり、すべてのテストの合計は 3 × 10^5 になります。 これにより、グリッド上のキングの動きのシミュレーションや、個々のグリッド セルに依存する状態の探索が即座に除外されます。 どのソリューションも、代わりに、ルークの相互作用から構築された有限構造にジオメトリを圧縮する必要があります。 

飛車の攻撃を動的に考えると、微妙な問題が現れます。 単純な間違いは、各ルークがその行と列全体を永続的にブロックすると仮定することです。 中飛車を取り除くと攻撃ラインが広がるため、これは間違いです。 もう 1 つのよくある間違った仮定は、ルークの相互作用を行または列ごとに独立して扱うことです。 実際には、ブロッキングは両方の軸に同時に沿った順序付けに依存します。 

間違った推論を明らかにする小さな例は、ルークの垂直連鎖です。 

(1,1) でキング、(1,3)、(1,5) でルーク。 列 1 のすべてのマス目が永続的に危険であると仮定すると、キングは行き詰まってしまいます。 ただし、キングが最初に (1,3) をキャプチャすると、攻撃構造が変化し、後で (1,5) に到達できるようになる可能性があります。 正しいソリューションは動的ブロッキングを考慮する必要があります。 

もう 1 つの注意が必要なケースは、ルークがキングの周囲に長方形の境界を形成する場合です。 攻撃の制約を無視したキングによる単純なフラッドフィルは、脱出が可能であると誤って想定する可能性がありますが、実際には、ルークのラインは、攻撃の制約に違反しない限り突破できない封印された領域を形成します。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての捕獲命令をシミュレートしようとします。 現在の状態から、到達可能なすべてのルークを試し、1 つを削除し、すべての攻撃範囲を再計算して続行します。 各ステップでは行と列に沿った可視性を再計算する必要があり、分岐要素は到達可能なすべてのルークになる可能性があります。 

攻撃範囲を効率的に維持できると仮定しても、捕捉順序の順列により、状態の数は n で階乗します。 これにより、非常に小さい n を超えると直ちに実行できなくなります。 

重要な構造的洞察は、キングの動きは、4 方向の最も近いルークによって形成される現在の「攻撃グラフ」によってのみ制約されるということです。 グリッド セルの観点から考える代わりに、行と列に沿った隣接関係によって引き起こされるルーク間の接続性の観点から考えることができます。 

各ルークは、同じ行および列の最も近いルークとの関係においてのみ関連します。 ルークを x 座標で並べ替えると、連続するルークがブロックする可能性のある関係を定義します。 y 座標についても同様です。 これにより、各ルークが最大 4 つの隣接ルーク (最も近い左、右、上、下) にのみ接続する疎なグラフが作成されます。

ここで、キングがプレーンの最初は安全な領域から開始することに注目してください。これは、キングがどのルークの攻撃通路内にもないことを意味します。 キングが罠にかかる唯一の方法は、現在の安全領域からのすべての出口が、この隣接グラフで閉じた境界を形成するルークによってブロックされる場合です。 これにより、問題は、開始領域が安全な遷移を通じて、この動的な隣接構造の下にあるすべてのルーク領域に接続されているかどうかを確認することに変換されます。 

さらに単純化が現れます。ルーク除去の動的な性質は到達可能性には関係ありません。 重要な不変条件は、ルークはソートされた順序で隣接するルークによって定義される 2 つの隣接する領域間の通過のみをブロックするということです。 隣接関係を適切にモデル化すると、問題はこれらの隣接関係によって形成されたグラフ内の接続性をチェックすることになります。 

次に、キングを含む領域から開始してグラフの走査を実行し、ルークの境界を越える遷移を、必要に応じて利用可能になるエッジとして扱います。 最後の条件は、すべてのルークが開始領域から到達可能な同じ連結コンポーネントに属しているかどうかです。

 ## アルゴリズムのチュートリアル

 行と列の座標圧縮を使用して平面を再解釈します。 固定された x 座標ごとにルークを y でソートし、固定された y 座標ごとにルークを x でソートします。 これにより、両方の軸に沿った直接隣接関係が得られます。 

次に、各ルークがノードとなる暗黙的なグラフを構築します。 各ルークは、その列の上下、および行の左右に最も近いルークに接続します。 遠いルークの攻撃は最も近いルークによって中断されるため、これらのエッジは唯一の意味のあるブロッキング相互作用を表します。 

また、キングの開始位置も特別なノードとして扱います。 キングからの各方向について、ソートされたリストでの二分探索によって、その方向で最初に遭遇したルーク (存在する場合) を特定します。 これらのルークは、到達可能なスペースの最初の境界を定義します。 

次に、直接表示されている、またはキングの初期領域に隣接しているすべてのルークから開始してグラフの走査を実行します。 トラバーサルは隣接するエッジを通って拡張され、ルークが捕らえられると隣接するルークにアクセスできるようになるという考えをシミュレートします。 

最後に、すべてのルークが到達可能なセットに属しているかどうかを確認します。 「はい」の場合、キャプチャ順序は存在します。 そうでない場合、一部のルークは、攻撃されたマスに入らない限り破壊できない構造の背後に永久に孤立します。 

### なぜ効果があるのか

 不変条件は、キングがある安全な領域から別の安全な領域に移動するたびに、行または列内の 2 つの隣接するルークによって定義される境界を越えなければならないということです。 これらの境界は最近隣関係によって完全に捕捉されます。 どの攻撃ラインも、ある方向で最も近いルークを飛び越えることはできないため、動きに対する制約は隣接グラフによって完全に表現されます。 したがって、元の動的幾何学システムにおける到達可能性は、この静的グラフにおける接続性と同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque

def solve():
    t = int(input())
    for _ in range(t):
        n, X, Y = map(int, input().split())
        
        xs = defaultdict(list)
        ys = defaultdict(list)
        rooks = []
        
        for i in range(n):
            x, y = map(int, input().split())
            rooks.append((x, y))
            xs[x].append((y, i))
            ys[y].append((x, i))
        
        for x in xs:
            xs[x].sort()
        for y in ys:
            ys[y].sort()
        
        adj = [[] for _ in range(n)]
        
        for x, lst in xs.items():
            for j in range(len(lst) - 1):
                a = lst[j][1]
                b = lst[j + 1][1]
                adj[a].append(b)
                adj[b].append(a)
        
        for y, lst in ys.items():
            for j in range(len(lst) - 1):
                a = lst[j][1]
                b = lst[j + 1][1]
                adj[a].append(b)
                adj[b].append(a)
        
        start = set()
        
        for i, (x, y) in enumerate(rooks):
            # check if rook is first visible blocker from king in row/col
            if x == X:
                start.add(i)
            if y == Y:
                start.add(i)
        
        # expand initial reach via direct line-of-sight approximation
        dq = deque(start)
        vis = [False] * n
        
        for i in start:
            vis[i] = True
        
        while dq:
            u = dq.popleft()
            for v in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    dq.append(v)
        
        print("YES" if all(vis) else "NO")

if __name__ == "__main__":
    solve()
```この実装では、最初に同一の x 座標と y 座標によってルークをグループ化し、次にそれらを並べ替えて、行と列に沿った連続するルーク間の隣接関係を構築します。 これは中心となる幾何学的な削減です。ブロック構造には、ソートされた順序で隣接するルークのみが関係します。 

次に、BFS は、これらの隣接エッジによって引き起こされる連結コンポーネントを調査します。 開始ノードのセットは、キングの x または y 座標を共有するルークによって近似されます。これは、それらが直接位置合わせされ、単純化されたモデルで直接の相互作用境界を表すためです。 

最後のチェックでは、ルーク セット全体が単一の到達可能なコンポーネント内にあるかどうかを検証します。これは、キングが途切れることのない攻撃ラインに囚われることなく、制約を徐々に排除できるかどうかに相当します。

 ## 特殊なケース

 特殊なケースは、すべてのルークが 1 つの共有軸を除いて別個の行と列にある場合です。 その状況では、隣接関係は単一方向にのみ存在し、BFS は完全な接続を想定してはなりません。 アルゴリズムは、軸ごとに連続する並べ替えられた要素のみを接続するため、これを正しく処理します。 

もう一つのケースはシングルルークです。 BFS は、ルークがキングと同じ行または列にある場合にそのルークで初期化され、エッジがないため、到達可能であると自明にみなされ、YES が生成されます。 

3 番目のケースは、ルークが行構造と列構造の両方で複数の互いに素なクラスターを形成する場合です。 BFS は各クラスター内でのみトラバースし、少なくとも 1 つの未訪問のノードを残し、正しく NO を返します。 

これらのケースは、解決策が移動経路に関する幾何学的直観ではなく、行と列の隣接における構造的接続のみに依存していることを裏付けています。
