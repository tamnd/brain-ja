 ## 解決策
 ## 問題の理解

 固定文字列を使用していますが、`ECUST`、そしてタスクは、基礎となる文字を変更せずに、各文字の大文字と小文字を個別に選択することによって形成できるすべての文字列を生成することです。 各文字はその位置に残りますが、大文字または小文字のいずれかにすることができ、そのような組み合わせはすべて有効な出力とみなされます。 

出力は任意ではありません。 生成されたすべての文字列は、標準の ASCII 辞書順を使用して並べ替える必要があります。 この順序付けでは、文字列を 1 文字ずつ比較し、最初に異なる位置で、小さい方の ASCII 値を持つ文字列が最初に来ます。 大文字の ASCII コードは小文字よりも小さいため、同じ位置で比較すると、同じ文字の大文字バージョンは常に小文字バージョンより前に来ます。 

入力形式は技術的には線を提供しますが、回答に影響を与える情報は含まれません。 問題全体は決定的であり、文字列のみに依存します。`ECUST`。 

暗黙の制約は、文字列の長さが 5 に固定されるため、生成される文字列の総数も 5 に固定されることです。$2^5 = 32$。 これにより、パフォーマンスやメモリ使用量に関する懸念が即座に排除されます。 単純な列挙であっても、かなり高速です。 

主な微妙な点は順序にあります。 単純なアプローチでは、すべての大文字と小文字の組み合わせを生成し、汎用の文字列ソートを使用してそれらをソートする可能性があります。 これは安全ですが、正しい順序で直接生成できる構造特性が隠蔽されます。 

典型的な間違いは、ASCII ルールをチェックせずに、大文字と小文字の組み合わせに対する辞書編集順が 2 進数のように動作すると仮定することです。 たとえば、小文字を「小さい」ものとして扱うと、正しい順序が逆転し、誤った出力が生成されます。 

もう 1 つの微妙な問題は、各キャラクターが独立して変化することを忘れていることです。 誰かが誤って大文字と小文字をグローバルに切り替えたり、文字を交換したりすると、大文字と小文字を保持する有効なバリアントが生成されません。 

## アプローチ

 ブルートフォース手法は、位置のすべてのサブセットを小文字に生成することです。 5 つの文字それぞれについて、大文字のままか小文字になるかを決定し、32 個の文字列を生成します。 それらを生成した後、通常の文字列比較を使用してリストを並べ替えます。 

これが機能するのは、検索スペースが非常に小さいためです。 基本的にコストは 32 個の文字列の生成とそれらの並べ替えにあり、無視できる程度です。 ただし、ASCII 順序が大文字小文字の変更と相互作用する方法を利用する場合、実際には並べ替えは必要ないため、不必要な作業が実行されます。 

重要な観察は、辞書編集上の比較において各位置が独立して動作するということです。 各文字では、同じ文字でも大文字は小文字よりも常に小さくなります。 これは、大文字を 0 として解釈し、小文字を 1 として解釈すると、文字列全体の辞書編集上の順序が 5 ビット バイナリ マスクの自然な昇順と一致することを意味します。 

したがって、生成して並べ替える代わりに、マスクを 0 から 31 まで列挙し、対応する文字列を直接構築できます。 これにより、正しい順序が自動的に生成されます。

 ## アルゴリズムのチュートリアル

 それぞれのキャラクターを扱います`ECUST`大文字と小文字の 2 つの状態があるものとして解釈し、選択を二者択一の決定として解釈します。 

1. 0 から 31 までのすべての整数を考慮します。各数値は、大文字と小文字の選択の一意の組み合わせを表します。 各ビットは文字列内の 1 つの位置に対応します。 これが機能するのは、5 つの文字が正確に 5 つの二項決定を行うためです。 
2. 各数値について、最上位ビット (位置 0) から最下位ビット (位置 4) までのバイナリ表現を調べます。 ビット値 0 は大文字を維持することを意味し、ビット値 1 は小文字に変換することを意味します。 
3. 結果の文字列を 1 文字ずつ構築します。 各位置で、ステップ 2 のルールを適用して、キャラクターを下げるか維持するかを決定します。 
4. 構築された各文字列をすぐに出力します。 マスクは昇順に処理されるため、出力はすでに正しい辞書順になっています。 

重要な点は、0 から上に向かって反復することで、前のビットが前の文字に対応し、大文字は常に小文字よりも辞書編集的に小さいため、辞書編集上の正確さが保証されることです。 

### なぜ効果があるのか

 このアルゴリズムは、マスクのバイナリ順序付けと文字列の ASCII 辞書編集順序という 2 つのシステム間の一貫した順序調整に依存しています。 生成された 2 つの文字列間の最初の異なる位置では、その位置はマスク内の最も重要な異なるビットに正確に対応します。 0 を大文字に、1 を小文字にマップし、大文字の方が ASCII 値が小さいため、マスクの順序は辞書編集上の順序と直接一致します。 この不変式により、事後の並べ替えが不要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = "ECUST"
n = len(s)

for mask in range(1 << n):
    res = []
    for i in range(n):
        c = s[i]
        if mask & (1 << (n - 1 - i)):
            res.append(c.lower())
        else:
            res.append(c)
    print("".join(res))
```プログラムはまずベース文字列を修正し、大文字と小文字の選択を表すすべての可能なビットマスクを反復処理します。 ビット テストは、最上位ビットが最初の文字に対応するように調整され、辞書編集上の正確性が保証されます。 

文字列の構築はマスクごとに 1 回のパスで行われるため、実装が単純になり、並べ替えロジックや補助データ構造が不要になります。 

## 実用的な例

 より小さな類似した文字列でプロセスを説明できます。`AB`、構造的には同一のままで、ロジックが見やすくなります。 

のために`AB`、マスクを 0 から 3 まで列挙します。 

| マスク | バイナリ | 選択肢 | Bの選択 | 出力 |
 | --- | --- | --- | --- | --- |
 | 0 | 00 | あ | B | AB |
 | 1 | 01 | あ | b | アブ |
 | 2 | 10 | | B | aB |
 | 3 | 11 | | b | アブ |

 このトレースは、最初の異なる文字では大文字が常に小文字に先行するため、マスク順序の増加が辞書編集順序と一致することを示しています。 

同じ理屈を当てはめると、`ECUST`このパターンを 5 つの位置に拡張するだけで、32 個の順序付けされた出力が生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = "ECUST"
    n = len(s)
    out = []
    for mask in range(1 << n):
        res = []
        for i in range(n):
            c = s[i]
            if mask & (1 << (n - 1 - i)):
                res.append(c.lower())
            else:
                res.append(c)
        out.append("".join(res))
    return "\n".join(out)

 ## 特殊なケース

 唯一の意味のあるエッジ動作は、境界での順序付け、つまり完全に大文字の文字列と完全に小文字の文字列です。 

入力用`ECUST`、マスク`00000`生成する`ECUST`すべての文字が大文字であるため、これが最小の文字列になります。 マスク`11111`生成する`ecust`すべての文字が小文字であるため、これが最大になります。 

最初のケースについて説明すると、各ビットはゼロであるため、文字は変換されず、出力はそのまま残ります。`ECUST`。 他の文字列では最初の異なる位置にこれより小さな文字を含めることはできないため、辞書編集順で最初に出現する必要があります。 

最後のケースでは、すべてのビットが 1 であるため、すべての文字は小文字になります。 他の文字列は、大文字が出現する前またはある位置で異なり、大文字の方が小さいため、そのような文字列はすべてその前に置かれます。`ecust`最終的な出力。
