 ## 解決策
 ## 問題の理解

 開始点によって定義される小さな整数の範囲が与えられます。`l`。 隠された番号`a`からの区間のどこかにあることが保証されています`l`まで`l + 5`, したがって、最大で 6 つの連続する整数が候補として考えられます。 

この範囲の制約に加えて、`a`2 つのモジュール条件を同時に満たさなければなりません。 2で割った余りは次のように固定されます。`m2`、3で割った余りは に固定されます。`m3`。 タスクは、両方の剰余条件に一致する許容範囲内の整数を特定するか、そのような整数が存在しないことを報告することです。 

制約は非常に小さいです。`l`は最大 100 で、検索間隔の長さは 6 に固定されています。これにより、高度な数理論や最適化の必要性が即座に排除されます。 間隔を直接スキャンした場合でも、最大 6 回のチェックが実行されますが、これは一定時間です。 

唯一の微妙な点は自然数の定義にあります。 0 が明示的に許可されているため、モジュロ動作がまだ明確に定義されている場合、区間には 0 または小さな値を含めることができるため、隠れた除外はありません。 

このタイプの問題における典型的な間違いは、中国剰余定理機構を使用して合同式を直接解こうとすることです。 ここでは、検索スペースが非常に小さいため、ブルート フォースがすでに最適化されているため、これは不必要であり、エラーが発生しやすくなります。 

## アプローチ

 最も簡単なアイデアは、すべての整数を試してみることです`a`範囲内で`[l, l + 5]`両方の条件を満たすかどうかを確認します`a % 2 == m2`そして`a % 3 == m3`。 候補は最大 6 つあり、それぞれが一定時間のチェックを必要とするため、これは自明のことながら高速です。 

これは、制約がスケールしないため機能します。 ただし、間隔が大きい場合 (たとえば 10^9 まで)、この直接列挙は不可能になります。 その場合、モジュロ 2 とモジュロ 3 の条件が結合してモジュロ 6 の構造になるため、モジュロ 6 の剰余の周期性を使用してモジュラー制約を交差する必要があります。重要な観察は、すべての整数がモジュロ 6 の剰余によって一意に決定され、両方の制約が一緒になって単一の剰余クラスをモジュロ 6 で指定することです。 

この問題では、より深い構造は必要ありませんが、ブルート フォースがすでに本質的に最適である理由が説明されています。探索空間は 1 つの完全なモジュラス サイクルよりも小さいからです。

 ## アルゴリズムのチュートリアル

 1.読む`l`、`m2`、 そして`m3`入力から。 これらは候補範囲と必要な残りを定義します。 
2. すべての整数を反復処理します。`a`から`l`に`l + 5`包括的な。 これは、考えられるすべての有効な候補をカバーします。 
3. 各候補者について`a`、計算する`a % 2`それが等しいかどうかを確認してください`m2`。 一致しない場合は破棄します`a`すぐに。 
4. 最初の条件が成立する場合、計算します。`a % 3`それが等しいかどうかを確認してください`m3`。 それも一致する場合、有効な解決策が見つかったので、出力できます。`a`。 
5. 有効な候補が見つからずにループが終了した場合、出力`-1`。 

チェックの順序は正確性にとって重要ではありませんが、モジュロ 2 を最初にチェックすると、候補の半分がすぐにフィルタリングされるため、若干効率的になります。 

### なぜ効果があるのか

 考えられるすべての値`a`最大 6 つの連続する整数のセットに含まれます。 アルゴリズムは、このセット全体の各要素を明示的に評価します。 候補がスキップされず、すべての候補が正確な定義制約に対してテストされるため、反復中に有効な解決策が見つかる必要があります。 逆に、値を受け入れる前に両方のモジュール条件がチェックされるため、有効な候補のみが返されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l, m2, m3 = map(int, input().split())

for a in range(l, l + 6):
    if a % 2 == m2 and a % 3 == m3:
        print(a)
        sys.exit()

print(-1)
```実装は、隠れた最適化を行わずにアルゴリズムに直接に従います。 正確に 6 つの値にわたるループにより、制限された実行時間が保証されます。 早期出口経由`sys.exit()`有効な候補者が見つかったらすぐに停止しますが、それがなくてもコストは無視できます。 

一般的な実装の落とし穴は、範囲を誤って次のように設定することです。`range(l, l+5)`の代わりに`l+6`。 間隔は両端を含むため、正確に 6 つの数値を含める必要があります。 

もう 1 つの微妙な点は、有効な数値が存在しない場合の処理​​です。 弊社は印刷のみを行っております`-1`すべての候補者を出し尽くした後。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    l, m2, m3 = map(int, input().split())

    for a in range(l, l + 6):
        if a % 2 == m2 and a % 3 == m3:
            return str(a)

    return "-1"

# provided samples
assert run("0 1 2") == "5"
assert run("63 1 1") == "67"

# minimum range, solution at boundary
assert run("0 0 0") in {"0", "6"}  # depending on valid range overlap

# no solution exists
assert run("1 0 0") in {"-1", "-1"}  # small contrived case

# solution at left boundary
assert run("10 0 1") == run("10 0 1")

# all candidates invalid
assert run("2 1 0") == "-1"

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`l`は 0 です。ループは次から始まるため、アルゴリズムには有効な候補として 0 が正しく含まれています。`l`自体。 たとえば、入力の場合`0 0 0`、最初のチェック`a = 0`両方の条件をすぐに満たします。`0 % 2 = 0`そして`0 % 3 = 0`、アルゴリズムはそれ以上反復せずに 0 を返します。 

もう 1 つのエッジ ケースは、有効な解が上限にある場合です。`l + 5`。 たとえば、次の場合`l = 2`、候補者`7`間隔内の唯一の有効な数値である可能性があります。 ループには明示的に次のものが含まれます`l + 5`、 それで`a = 7`テストされ、正しく受け入れられます。 

最後のエッジケースは、区間内に両方のモジュラー制約を満たす数値がない場合です。 その場合、すべての反復で少なくとも 1 つの条件が失敗し、ループが完全に完了します。 アルゴリズムは次のように出力します。`-1`、不可能であることを正しく知らせます。
