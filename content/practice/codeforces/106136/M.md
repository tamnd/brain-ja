 ## 解決策
 ## 問題の理解

 厳密に増加する長さのシーケンスを構築するように求められます$n$、すべての要素は以下の負でない整数です。$2^{30}$。 問題は単調性ではなく、すべての隣接するペア、つまり連続するペアごとに制約があることです。$(a_i, a_{i+1})$の場合、ペアは 2 つの数値の XOR が AND よりも厳密に小さいというビット単位の条件を満たす必要があります。 

入力は複数のテスト ケースで構成され、それぞれが必要な長さを指定します。$n$。 それぞれのケースについて、有効なシーケンスを 1 つ出力するか、構築が不可能であることを報告します。 

制約は合計すると大きくなります。$n$すべてのテストケースにわたって、$10^6$。 これは、どのようなソリューションでも、テスト ケースごとに線形時間で各シーケンスを構築する必要があり、理想的には検索やバックトラックを行わずに非常に単純な決定論的なパターンで構築する必要があることを直ちに示唆しています。 テストケースごとに二次関数を実行することは不可能です。$O(n \log n)$定数が大きい場合は境界線になります。 

この条件の微妙な点は、XOR と AND の両方が同時に関与することです。 XOR はビットの不一致を測定し、AND は共有ビットを測定します。 不等式 XOR < AND は、隣接する数値がその差に比べて十分多くの高重みビットを共有する必要があることを意味します。これはすでに疑わしいです。なぜなら、ほとんどの順序付きペアでは、上位ビットに強い重複がない限り、XOR が優勢になる傾向があるからです。 

エッジケースは小さい場合にすぐに現れます$n$。 のために$n = 2$、単一の有効なペアが必要ですが、そのようなペアが存在するかどうかは明らかではありません。 単純な仮定では、連続した整数を選択すると機能するかもしれませんが、$a$そして$a+1$XOR は常に次と等しい$2^{k+1}-1$AND がゼロであるため、条件は不可能になります。 これは、すべての増加シーケンスが制約を満たすことができるわけではなく、構造を注意深く設計する必要があり、そうでない場合は答えが不可能である可能性があることを示唆しています。$n$。 

もう 1 つの潜在的な落とし穴は、条件が対称であるか、値が増加するにつれて単調に動作すると仮定することです。 XOR と AND は大きさではなくバイナリの重複に完全に依存するため、どちらでもありません。 

## アプローチ

 ブルートフォース手法では、シーケンスを段階的に構築しようとし、各位置で、前の値よりも大きいすべての可能な値を試し、ビットごとの条件をチェックします。 これには、最悪の場合、次までのスキャンが必要になります。$2^{30}$ポジションごとに候補者が存在するため、完全に実行不可能になります。 合理的なサブセットに制限したとしても、総作業量は依然として与えられた制限をはるかに超えることになります。$n$まで$10^6$。 

重要な洞察は、ビット構造の観点から条件を書き直すことで得られます。 2つの数字の場合$a < b$、私たちは必要とします$$a \oplus b < a \& b.$$この不等式は、AND が XOR によって打ち消されない上位ビットに寄与する場合にのみ成立します。 ただし、XOR には常に 2 つの数値が異なる場合にのみビットが含まれ、AND には両方の数値が 1 である場合にのみビットが含まれます。これは構造的な緊張を直ちに暗示します。XOR は差異を強調表示し、AND は重複を強調表示します。数値の差を支配するには重複が必要です。 

重要な観察は、2 つの数値が上位ビットを共有する場合、そのビットは AND にはプラスに寄与しますが、XOR には何も寄与しないということです。 一方、XOR はビットの違いによって完全に決まります。 AND を XOR よりも大きくするには、少なくとも 1 つの上位ビットを共有しながら、下位ビットのみが異なる隣接する数値が必要であり、その共有ビットがすべての異なるビットの数値を支配する必要があります。 

これは、最上位ビットを固定し、制御された方法で下位ビットのみを変更するチェーンを構築し、AND には常にその固定ビットが含まれるようにし、XOR は下位ビットに限定されるようにすることを示唆しています。 ただし、厳密な単調性は単純な構築を複雑にします。 

確実に前進する方法は、完全な組み合わせ構造ではなく、厳密に増加するシーケンスのみが必要であることを理解することです。 これにより、すべての要素にわたって単一の優勢な上位ビットを強制し、XOR を小さく保つ方法で制御された下位ビットのセットのみを変更することができます。 

最も簡単な実用的な構造は、次の形式の数値を選択することです。$$a_i = 2^{k} + i$$十分に小さいため$i$, しかし、連続する数値間の AND が小さすぎるため、これは失敗します。 代わりに、視点を反転します。固定の上位ビットを共有するペアを構築し、慎重に選択されたブロック内で遷移が確実に発生するようにします。これにより、隣接するすべてのペアに大きな共有ビット セットがあり、相違点はわずかになります。 

最後の建設的なアイデアは、すべての数値が固定の最上位ビットを持つことを保証しながら昇順でシーケンスを構築することであり、その制約内で、隣接関係がサブセット内の制御された増分のように動作することを保証します。この場合、AND は、どの XOR 寄与よりも高い優勢ビットを常に保持します。 これにより、本質的に AND 優位性を保証する高ビット マスク内でインデックスをエンコードするパターンが生まれます。 

制約を単純化した後の核となる結論は、すべての制約に対して有効なシーケンスが存在するということです。$n \ge 2$であり、XOR を下位ビットの増分によって制限したままにしながら、シーケンス全体にわたって共有の最上位ビットを保証する固定ビット パターンを使用して線形に構築できます。

 ## アルゴリズムのチュートリアル

 この構築は、単一の上位ビットを固定し、残りのビットで単調増加シーケンスをエンコードすることに依存しており、隣接関係が常にその上位ビットを保持することを保証します。 

1. 固定ビット位置 (ビット 29 など) を選択し、シーケンス内のすべての数値にこのビットが設定されていることを確認します。 これにより、すべての隣接するペアに、少なくとも次の値を含む非ゼロ AND が含まれることが保証されます。$2^{29}$、違いが下位ビットに限定されている場合、XOR に対する比較が優先されます。 
2. 整数を列挙してシーケンスを構築します$0, 1, 2, \dots, n-1$各値を次のように設定します$a_i = (1 << 29) | i$。 これにより、下位ビットは通常どおり増加するため、厳密な単調性が維持されます。 
3. 隣接構造を暗黙的に検証します。連続する値の場合、上位ビットはキャンセルされ、AND には常に上位ビットが含まれるため、XOR は下位ビットにのみ影響します。 これにより、XOR が次のように厳密に制限されるようになります。$2^{29}$、一方、AND は少なくとも$2^{29}$、すべてのペアに対して不等式が成り立ちます。 
4. シーケンスを直接出力します。 

この構築は決定論的であり、テスト ケースの構造から独立しています。 

### なぜ効果があるのか

 すべての要素には固定の最高設定ビットが含まれているため、隣接するペアについては AND 演算によってこのビットが保持され、大きなベースライン値が保証されます。 一方、XOR は下位 29 ビットの差のみを反映し、共有上位ビットの寄与よりも常に厳密に小さくなります。 これにより、隣接するペアごとに XOR と AND の間の大きさが厳密に分離され、低ビット カウンタによる厳密な順序を維持しながら、不等式が常に保持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    HIGH = 1 << 29
    
    for _ in range(T):
        n = int(input())
        if n < 2:
            print(-1)
            continue
        
        # construct sequence
        res = []
        for i in range(n):
            res.append(str(HIGH | i))
        
        print(" ".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは、まずテスト ケースの数を読み取り、次にそれぞれを個別に処理します。 一定の上位ビット$2^{29}$すべての要素が共通のドミナント ビットを共有することを保証するために使用され、すべての隣接するペアにわたる AND 演算が安定します。 

各値は、この上位ビットと単純な増加カウンタの OR 演算によって形成されます。 これにより、下位 29 ビットは通常どおり増加し、順序付けに干渉しないため、厳密な単調性が保証されます。 

よくある間違いは、出力を次の範囲内に留めておく必要があることを忘れることです。$[0, 2^{30})$。 選択された構造は、ビット 29 と最大値までの値のみを使用するため、この境界を尊重します。$10^6$、十分範囲内です。

これらの例は、その構築がローカル調整には依存せず、共有された上位ビットがすべてのペアを支配するという不変条件のみに依存することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    T = int(input())
    HIGH = 1 << 29
    out = []

    for _ in range(T):
        n = int(input())
        if n < 2:
            out.append("-1")
            continue
        arr = [(HIGH | i) for i in range(n)]
        out.append(" ".join(map(str, arr)))

    return "\n".join(out)

# minimal size
assert run("1\n2\n") != "-1"

# multiple test cases
assert run("2\n2\n3\n") != ""

# larger sequence sanity
assert len(run("1\n5\n").split()) == 5

# all equal n=2 edge behavior
assert run("1\n2\n").count("-1") == 0
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 のために$n = 2$、シーケンスは次のようになります$[2^{29}, 2^{29}+1]$。 AND は$2^{29}$両方の数値が最上位ビットを共有しており、XOR は 1 であるためです。不等式はきれいに成立し、厳密な順序付けが維持されます。 

のために$n = 10^6$、下位ビットのみが変化するため、この構造は依然として機能します。 カウンターが大きくなっても下にとどまる$2^{20}$、固定上位ビットよりもはるかに低いため、オーバーフローやビット干渉は発生しません。
