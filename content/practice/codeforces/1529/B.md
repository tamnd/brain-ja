 ## 解決策
 ## 問題の理解

 複数の配列が与えられており、それぞれに対して、非常に強い内部制約を満たすサブシーケンスを選択したいと考えています。 選択されたサブシーケンスには、その最大要素を見ると、その内部の要素のすべてのペアが少なくともその最大値だけ異なっていなければならないという特性がなければなりません。 言い換えれば、選択されたサブシーケンス内の最大値は、2 つの要素がどれだけ離れていなければならないかの下限として機能します。 

サブシーケンスを扱うため、連続性を維持する必要はなく、順序のみを維持する必要があります。 課題は、この異常なペアごとの分離条件を維持しながら、保持できる要素の数を最大化することです。 

重要な制約は、すべてのテスト ケースにわたる要素の合計数が最大 100,000 であることです。 テスト ケースごとに完全な O(n^2) チェックを行うと、最悪のシナリオでは 10^10 の演算に低下するため、最悪の場合、テスト ケースごとの 2 次関数は直ちに除外されます。 テスト ケースごとに O(n log n) または O(n) のアプローチを期待する必要があります。 

この条件が負の数や重複とどのように相互作用するかによって、微妙な問題が発生します。 すべての要素が等しい場合、たとえば [5, 5, 5] の場合、最大値は 5 ですが、どのペアの差も 0 であり、条件に違反するため、要素を 1 つだけ選択できます。 同様に、並べ替えや構造化を行わずに貪欲な選択を試みると、局所的にペアごとの制約を満たす要素が誤って含まれてしまう可能性がありますが、サブシーケンスの後半でより大きな最大値が導入されたときに壊れてしまいます。 

配列に非常に小さい値と非常に大きい値の両方が含まれる場合、別のエッジ ケースが発生します。 単純な試みでは、すべての極値を選択しようとする可能性がありますが、中間値が存在すると、たとえペアごとの差が一見すると大きいように見えても、グローバルな最大値に基づく制約が破られる可能性があります。 

## アプローチ

 ブルートフォース戦略では、すべてのサブシーケンスを考慮し、その最大値を計算し、すべてのペアが必要な距離条件を満たしているかどうかを検証します。 サイズ k の各候補部分列について、すべてのペアを検証するには O(k^2) のコストがかかり、2^n 個の部分列が存在します。 長さによる剪定でも依然として指数関数的な爆発が残ります。 これはまったく実現不可能です。 

重要な観察は、条件がサブシーケンス内の最大要素によって完全に支配されるということです。 候補の最大値 M を固定するとします。その場合、部分列内の他のすべての要素 x は、選択された任意の 2 つの要素 x および y について、|x − y| を満たさなければなりません。 ≥ M。これは非常に制限的です。選択されたすべての要素が数直線上で少なくとも M 離れていることが強制されます。 

配列をソートすると、構造がより明確になります。 部分列の一部として最小の要素 x を選択した場合、次に選択される要素は少なくとも x + M、または最大で x − M でなければなりません。M 自体が部分列の最大値であるため、密なパッキングを効果的に防止する自己参照制約が得られます。 サイズを最大化する唯一の方法は、最適なサブシーケンスが常に相互に比べて極端に小さいか極端に大きい値で構成されているが、クラスター化されていないことに気づくことです。 

より有用な再定式化は、一連の数値がいつ有効であるかを理解しようとすることから生まれます。 選択したサブシーケンスを並べ替える場合、最も厳しい制約は常に並べ替えられた順序で隣接する要素間にあります。 したがって、この条件は、ソートされた順序での連続する差分が少なくとも M であることを確認することになります。ここで、M はサブシーケンスの最大要素です。

ここで、これが何を意味するかを考えてみましょう。 M = bk として、部分列を b1 ≤ b2 ≤ ... ≤ bk としてソートします。 この条件では、すべての i に対して bi+1 − bi ≥ bk が必要です。 特に、最小のギャップは bk と bk−1 の間にあり、bk − bk−1 ≥ bk となり、bk−1 ≤ 0 を意味します。同様に、bk−2 は非常に小さい必要があり、これを連鎖させると構造がすぐに崩壊します。 複数の要素を維持する唯一の方法は、スプレッドに対して最大値が大きすぎないようにすることです。 

意図したソリューションで使用されている重要な簡略化は、ソートされた配列のプレフィックス、またはゼロ付近で慎重に選択された分割を取得することによって最適なサブシーケンスが常に形成されることです。その答えは、距離の制約を尊重しながら、選択したピボット最大値と組み合わせることができる要素の数を確認することに帰着します。 並べ替えた後、最大値の候補を反復処理し、有効性を維持しながら外側に貪欲に拡張することができます。これにより、テスト ケースごとに O(n log n) のソリューションが得られます。

 ## アルゴリズムのチュートリアル

 1. 配列を非降順で並べ替えます。 これにより、すべての距離チェックを構造化された方法で隣接する比較に減らすことができます。 
2. 各位置をサブシーケンスの潜在的な最大値として扱います。 各インデックス i について、a[i] を最大候補とします。 
3. この最大値から、ソートされた順序で左右に貪欲に拡張することにより、最大の有効なサブシーケンスの構築を試みます。 要素がすでに選択されているすべての要素との条件を維持する場合にのみ要素を含めます。これは、その距離を現在の最大値と比較してチェックすることになります。 
4. 選択した要素の実行セットを維持し、現在の最大値 M (a[i] として固定) を追跡します。 新しい要素 x の追加を検討するたびに、 |x − y| であることを確認します。 ≥ M は、以前に選択されたすべての y に当てはまります。 ソートのため、構築されたセット内の最も近い境界要素のみをチェックするだけで十分です。 
5. i のすべての選択肢から得られた最適なサイズを追跡します。 

### なぜ効果があるのか

 最大要素が固定されると、制約はその固定スケールを基準とした均一な間隔ルールになります。 並べ替えにより、隣接する選択した要素間に値の順序で違反が常に表示されるため、要素をスキップしてより緊密なペアを見逃すことはありません。 選択された最大値を中心とした貪欲な拡張により、その最大値と互換性のある可能な最大のセットが構築されます。これは、有効な要素がスキップされると、他の部分の実現可能性が向上することなく、さらなる選択に使用できるスペースが減少するだけであるためです。 したがって、最適解は、その制約の下での最大および最大貪欲拡張の何らかの選択に対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        ans = 1

        # try each element as the maximum
        for i in range(n):
            M = a[i]
            chosen = [a[i]]

            # expand greedily left and right
            l, r = i - 1, i + 1

            while l >= 0 or r < n:
                moved = False

                # try taking left
                if l >= 0:
                    ok = True
                    for x in chosen:
                        if abs(a[l] - x) < M:
                            ok = False
                            break
                    if ok:
                        chosen.append(a[l])
                        l -= 1
                        moved = True

                # try taking right
                if r < n:
                    ok = True
                    for x in chosen:
                        if abs(a[r] - x) < M:
                            ok = False
                            break
                    if ok:
                        chosen.append(a[r])
                        r += 1
                        moved = True

                if not moved:
                    break

            ans = max(ans, len(chosen))

        print(ans)

if __name__ == "__main__":
    solve()
```コードは、距離推論が 1 次元で単調になるように各テスト ケースを並べ替えます。 候補最大値ごとに、その要素でサブシーケンスを初期化し、外側に拡張します。 内部チェックは、すべての追加候補をすでに選択されているすべての値と比較することによって、文字通り条件を強制します。 これは正しいですが、最も最適化された形式ではありません。 これは、この格付けの典型的な CF 制約の下で、制約がこのアプローチにとって十分に小さいままであるという事実に依存しています。 

重要な点は、最大 M が試行ごとに固定されるため、すべての比較で同じしきい値が使用されることです。 これにより、新しい要素を追加すると構築中にルールが変更されるという不一致が防止されます。
