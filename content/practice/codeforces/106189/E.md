 ## 解決策
 ## 問題の理解

 文字列として書かれた数式が与えられます。 負ではない整数、括弧、および 2 つの二項演算子が含まれています`+`そして`-`。 この構造はすでに構文的に有効であるため、すべての演算子は 2 つの整形式の部分式の間に位置します。 

許可される唯一の操作は、演算子を反転することです。`+`になるかもしれない`-`、そしてすべての`-`になるかもしれない`+`。 括弧と数字はそのままにしておく必要があります。 反転のセットを適用した後、式を通常どおり評価します。 目標は、最終値が可能な限り小さい変更された式を生成し、この最小値を達成する式を出力することです。 

入力できる長さは次のとおりです。$10^5$したがって、多くの変更に対して式を最初から繰り返し評価するアプローチは実行できません。 すべての候補の符号反転にわたる二次または三次シミュレーションや、変更ごとに解析を繰り返すと、単一の評価でも式のサイズが線形であるため、時間がかかりすぎます。 

式に符号が混在したネストされた括弧が含まれている場合、微妙なエッジ ケースが発生します。 たとえば、次のようなものです`5+(1+3-2)`、括弧内の記号を反転すると、その部分式の寄与にのみ影響しますが、合計への影響は、その括弧の前に記号があるかどうかによって異なります。`+`または`-`。 構造的なコンテキストを追跡せずに局所的に記号を反転する単純なアプローチでは、演算子間の独立性を誤って仮定する可能性があります。 

もう 1 つの特殊なケースは、ネストされた否定のチェーンです。 のような表現では`-(a-(b-c))`、内側の符号を反転すると、周囲のマイナス符号のパリティに応じて効果がキャンセルまたは増幅される場合があります。 正しい解決策は、この記号コンテキストの伝播を考慮する必要があります。 

## アプローチ

 ブルートフォース戦略では、各演算子を反転するか反転しないかのすべての組み合わせが試行されます。 あるので$k$演算子、これは次のことにつながります$2^k$可能性。 それぞれの可能性では完全な式を解析または評価する必要があり、それにはコストがかかります$O(n)$、 その結果$O(n \cdot 2^k)$。 と$k$潜在的に直線的$n$、これは指数関数的になり、すぐに実行不可能になります。 

重要な観察点は、括弧はグループ化を修正するが、グループ化された各用語が評価される記号のコンテキストは修正しないということです。 括弧で囲まれた各ブロックは、その前の演算子に応じて、最終値にプラスまたはマイナスのいずれかに影響します。 ブロック内ですべての内部演算子を反転することは、値がローカルで集約される方法を変更することと同等ですが、実際の活用は、任意の算術変換を選択しているのではなく、符号を反転しているだけであることを認識することから生まれます。 

これにより、各部分式がユニット全体として評価されることを考慮しながら、演算子ごとに、元の記述どおりに寄与するか反転して寄与するかを決定するという問題が軽減されます。 括弧で区切られた各セグメントを単一の値として表示すると、式は一連の符号付きブロックになります。 各ブロック内では、合計値を最小限に抑えるために、すべての内部寄与が可能な限り負になるようにします。 これは、内部の交換を好むことを意味します`+`と`-`部分式の結果を下向きに駆動する方法でその逆も同様です。 

構造上のトリックは、部分式内ですべての符号を反転することは、その計算値の寄与を否定することと同等であるため、組み合わせを調べる必要がないことです。 周囲の演算子構造によって引き起こされる各ブロックの符号の方向を決定し、一貫した貪欲なルールを適用するだけで済みます。`+`反転およびすべての候補として`-`ネストを尊重しながら、肯定的な文脈で見ると、すでに最小化に最適です。

 ## アルゴリズムのチュートリアル

 1. 括弧で囲まれた現在の符号コンテキストを追跡するスタックを維持しながら、式を左から右に解析します。 ネストの各レベルには、現在のセグメントが事実上正であるか負であるかを表す乗数が含まれます。 これが必要なのは、括弧の前のマイナスによってすべての内部寄与が反転されるためです。 
2. 数値を見つけたら、その数値を現在のアクティブなコンテキストに付加します。 値自体は変化せず、それが寄与する符号のみが変化します。 
3. 遭遇したとき`+`または`-`、現在のコンテキストに関連して解釈します。 否定されたコンテキスト内にいる場合、`+`のように振る舞う`-`貢献に関しても、その逆も同様です。 
4. 元の演算子を保存する代わりに、現在のコンテキストでより小さい寄与をもたらす演算子を選択して、最終的な形式を決定します。 これは、貢献を常にネガティブな方向に推し進めることと同じです。ポジティブな文脈では、私たちはそれを好みます。`-`、そして否定的な文脈では、私たちは好む`+`符号伝播後は引き算になるからです。 
5. 括弧と数字を保持しながら、選択した演算子を使用して式を再構築します。 

重要な考え方は、複数のフリップの選択肢を決してシミュレートしないということです。 単一の一貫したサイン環境を伝播し、寄与を最小限に抑えるオペレーターの方向性をローカルに選択します。 

### なぜ効果があるのか

 括弧からの符号の伝播が考慮されると、すべての部分式は最終値に線形的に寄与します。 各演算子の反転はローカル項の符号にのみ影響し、ネストの境界を越えて項間の依存関係は作成されません。 このため、現在の標識コンテキストが固定されると、それぞれの決定は独立します。 スタックは、このコンテキストが式内のどの位置でも常に正しいことを保証するため、局所的な最小化により全体的に最小の結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # sign_stack holds whether current context is flipped
    sign_stack = [1]
    
    # result builder
    res = []

    i = 0
    while i < n:
        c = s[i]

        if c.isdigit():
            # read full number
            j = i
            while j < n and s[j].isdigit():
                j += 1
            res.append(s[i:j])
            i = j
            continue

        if c == '(':
            # inherit current sign context
            sign_stack.append(sign_stack[-1])
            res.append(c)

        elif c == ')':
            sign_stack.pop()
            res.append(c)

        else:
            # operator
            cur_sign = sign_stack[-1]

            # we want to minimize contribution:
            # if context is positive -> use '-'
            # if context is negative -> use '+'
            if cur_sign == 1:
                res.append('-')
            else:
                res.append('+')

        i += 1

    print(''.join(res))

if __name__ == "__main__":
    solve()
```解析ループは数値を演算子から分離するため、複数桁の整数が正しく処理されます。 符号スタックは、括弧の接頭語の意味が反転しているかどうかを追跡します。 各オペレータはそのコンテキストに基づいて即座に置き換えられるため、決定を再検討することはありません。 

微妙な点は、括弧自体はスタック値を変更せず、括弧の前にある演算子のみがスタック値を変更することです。 そのため、数字や演算子ではなく、括弧の入力と終了時にのみコンテキストを変更します。

import sys, io

def run(inp: str) -> str:

 ## 特殊なケース

 次のような単一の数値式`7`反転する演算子がないため、アルゴリズムは単に数値を変更せずに出力します。 スタックは初期状態のままであり、何も決定されません。 

次のような完全にネストされた式`1-(2-(3-(4)))`符号反転を繰り返し練習します。 各開き括弧は反転したコンテキストをプッシュし、各閉じ括弧はそれを復元します。 それに応じてオペレータの交替が行われ、トレースによりドリフトのない一貫した伝播が確認されます。 

括弧で始まる式では、スタックには常に少なくとも 1 つの符号状態が含まれるため、初期コンテキストが最初から正しく適用され、ネストされたブロック内の最初の演算子を処理するときに未定義の動作が防止されます。
