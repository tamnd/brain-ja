 ## 解決策
 ## 問題の理解

 このタスクは、IPv6 アドレス表現の正規化に関するものです。 入力は、コロンで区切られた 16 進数のグループで構成される単一の文字列です。 有効な拡張 IPv6 形式では、常に正確に 8 つのグループが存在し、各グループは最大 4 桁の 16 進数で記述された 16 ビット値を表します。 ただし、入力では、1 つまたは複数の連続するグループが省略され、二重コロンまたは隣接する区切り文字によるセグメントの欠落によって表される圧縮形式が使用される場合があります。 

目標は、完全な標準形式を再構築することです。 つまり、区切り文字を解釈し、欠落しているグループをゼロで復元し、最終的な表現に正確に 8 つのコンポーネントが含まれるようにする必要があります。 各コンポーネントは、必要に応じて先頭にゼロを埋め込んだ 4 文字の 16 進文字列として記述する必要があります。 

ステートメントでは入力サイズの制約が明示的に大きくありませんが、このタイプの問題は常に線形解析用に設計されています。 配列の分割、挿入、シフトを非効率的に繰り返すソリューションは問題なく合格しますが、不必要な二次関数の動作は回避できます。 

アドレスが圧縮で始まるか圧縮で終わる場合、微妙なエッジ ケースが発生します。たとえば、`"::1"`または`"2001::"`。 もう 1 つの特殊なケースは、複数の連続する欠落セクションであり、複数のグループがゼロであることが暗示されます。 すべての空の部分文字列が正確に 1 つのグループに対応すると仮定する単純な分割ベースのアプローチは、圧縮で複数の欠落セグメントが表される場合には失敗します。 

例えば、`"1::1"`単一のゼロ グループではなく、2 つのゼロ グループの間に 7 つのゼロ グループになる必要があります。 

## アプローチ

 直接解釈するアプローチは、文字列をコロン文字で分割し、結果として得られる各セグメントをグループとして扱うことです。 問題は、IPv6 圧縮によってこの前提が崩れることです。 2 つのコロンが連続して出現すると、分割によって空の文字列が生成されますが、その空の文字列は 1 つのゼロ グループを表すのではなく、欠落しているグループのブロック全体を表します。そのサイズは、アドレス内の他の場所にすでに存在するセグメントの数によって異なります。 

正しい推論は、アドレスを合計 8 つの固定セグメントを持つものとして扱うことです。 分割後、空ではないグループがいくつ存在するかを数えます。 8 とこの数の差は、空のセグメントが表示される位置に挿入する必要があるゼロ グループの数です。 

構造が復元されると、各セグメントは個別に正規化されます。 すべてのグループを 16 進数から整数に変換し、先頭のゼロを保持して正確に 4 桁で出力する必要があります。 

重要な点は、圧縮は有効な IPv6 アドレスで最大 1 回しか発生しないため、拡張が必要な​​領域は最大 1 つだけであるということです。 これにより、ゼロブロックに対して単一の挿入ポイントが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 圧縮を処理せずに直接分割 | O(n) | O(n) | 間違っています |
 | ゼロ拡張による分割 + リビルド | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列をコロン文字で生のセグメントに分割します。 これにより、圧縮ポイントに対応する空の文字列が保持されます。 分割配列の構造は、欠落ブロックが発生する場所をエンコードします。 
2. 空ではないセグメントの数を数えます。 これにより、アドレスにすでに指定されている明示的なグループの数がわかります。 
3. 8 から明示的なグループの数を引いて、欠落しているグループの数を決定します。 この値は、挿入する必要があるゼロ グループの数です。 
4. 分割されたセグメントをスキャンして最終リストを作成します。 空のセグメントが見つかると、それが圧縮ポイントを表します。 その位置を必要な数に置き換えます。`"0000"`グループ。 
5. 空でないすべてのセグメントについて、長さが 4 文字になるまで左にゼロを埋め込んで正規化します。 これにより、各 16 ビット ブロックの均一な表現が保証されます。 
6. 再構築後、結果に正確に 8 つのグループが含まれていることを確認します。 コロンを使用してそれらを結合し、最終的な IPv6 アドレスを形成します。 

重要な構造上の考え方は、圧縮形式ではゼロ グループの単一の連続ブロックのみが削除されるため、欠落している情報はすべて局所的に特定され、決定論的に復元できるということです。 

### なぜ効果があるのか

 IPv6 圧縮ルールでは、連続するゼロ グループの最大 1 つのシーケンスが二重コロンで置き換えられることが保証されます。 これは、分割表現には、拡張が必要な​​場所が 1 か所だけ含まれていることを意味します。 グループの総数は 8 に固定されているため、欠落長は一意に決まります。 すべての有効な再構成では、明示的なグループを順番に保存する必要があり、圧縮領域のみが柔軟であるため、計算された数のゼロで埋めると、一意の標準形式が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize(group: str) -> str:
    return group.zfill(4)

s = input().strip()
parts = s.split(':')

# count explicit groups
explicit = sum(1 for x in parts if x != '')

missing = 8 - explicit

res = []
i = 0
n = len(parts)

while i < n:
    if parts[i] == '':
        if missing > 0:
            res.extend(['0000'] * missing)
            missing = 0
        i += 1
    else:
        res.append(normalize(parts[i]))
        i += 1

print(':'.join(res))
```この解決策は、最初にセパレータの構造を解析し、次に欠落しているゼロ ブロックを圧縮ポイントに 1 回だけ挿入することによって機能します。 正規化ステップにより、各グループが 4 つの 16 進数であることが保証されます。 微妙な点は、空のセグメントを 1 回だけ使用する必要があるということです。 圧縮の配置方法に応じて複数の空のエントリが表示されることがありますが、展開サイトを表すのはそのうちの 1 つだけです。 

## 実用的な例

 インプットを考慮する`"2001:db8::1"`。 

に分かれます`["2001", "db8", "", "1"]`。 明示的なグループが 3 つあるため、5 つが欠落しています。 空のエントリは 5 つの挿入をトリガーします`"0000"`グループ。 最終的なシーケンスは次のようになります。 

| ステップ | アクション | 結果 |
 | --- | --- | --- |
 | 1 | 2001年を読む | [2001] |
 | 2 | db8を読む | [2001, 0db8] |
 | 3 | 空のブロックは展開します | [2001, 0db8, 0000, 0000, 0000, 0000, 0000] |
 | 4 | 1 を読む | [2001, 0db8, 0000, 0000, 0000, 0000, 0001] |

 最終的な出力は次のとおりです`"2001:0db8:0000:0000:0000:0000:0000:0001"`。 

ここで考えてみましょう`"::1"`。 

分割すると得られる`["", "", "1"]`。 明示的なグループが 1 つあるため、7 つが欠落しています。 空の領域は 7 つのゼロ ブロックに拡張され、最後に`"1"`正規化されています。 

| ステップ | アクション | 結果 |
 | --- | --- | --- |
 | 1 | 空の展開 | 7 0000 ブロック |
 | 2 | 1 を読む | 0001を追加 |

 結果は次のようになります`"0000:0000:0000:0000:0000:0000:0000:0001"`。 

これらのトレースは、空のセグメントが圧縮領域全体のプレースホルダーとして一貫して機能することを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    s = input().strip()
    parts = s.split(':')

    explicit = sum(1 for x in parts if x != '')
    missing = 8 - explicit

    res = []
    i = 0
    while i < len(parts):
        if parts[i] == '':
            if missing > 0:
                res.extend(['0000'] * missing)
                missing = 0
            i += 1
        else:
            res.append(parts[i].zfill(4))
            i += 1

    return ':'.join(res)

# basic
assert run("1::1\n") == "0001:0000:0000:0000:0000:0000:0000:0001"
# already full
assert run("abcd:0:0:0:0:0:0:1\n") == "abcd:0000:0000:0000:0000:0000:0000:0001"
# leading compression
assert run("::\n") == "0000:0000:0000:0000:0000:0000:0000:0000"
# trailing compression
assert run("2001:db8::\n") == "2001:0db8:0000:0000:0000:0000:0000:0000"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1::1`| 拡張されたミドルブロック | 集中圧縮処理 |
 | 完全な住所 | パディングされたグループ | 正規化の正確性 |
 |`::`| すべてゼロ | フル圧縮の場合 |
 | 後続`::`| サフィックス展開 | エッジ配置の処理 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列の先頭に圧縮が発生し、分割後に最初に空のセグメントが生成される場合です。 この場合、アルゴリズムは、実際のグループが処理される前に展開が確実に行われるようにする必要があります。 最初の空のセグメントが不足しているゼロ ブロックの即時挿入をトリガーするため、構築ロジックはこれを処理します。 

もう 1 つのケースは、圧縮を行わずに入力にすでに 8 つの明示的なグループが含まれている場合です。 ここでは空のセグメントが存在しないため、欠落カウントはゼロになり、拡張は行われません。 このアルゴリズムは各グループを個別に正規化するだけで、変更を加えることなく正確さを維持します。
