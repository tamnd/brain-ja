 ## 解決策
 ## 問題の理解

 テトリスプレイヤーのスコアログが与えられました。 各ログ エントリから、プレイヤーが文字列で表される 1、2、3、または 4 行を同時にクリアしたことがわかります。`single`、`double`、`triple`、 そして`tetris`。 

プレイヤーはレベル 18 から開始します。クリアで与えられるスコアは現在のレベルによって異なります。 

レベル 18 の場合:

 - シングル = 760 ポイント
 - ダブル = 1900 ポイント
 - トリプル = 5700 ポイント
 - テトリス = 22800 ポイント

 クリアされたラインの総数が特定のしきい値に達すると、レベルが上がります。 

最初のトランジションは特別です。 合計クリアラインが少なくとも 130 個蓄積されるまで、プレイヤーはレベル 18 のままです。 合計が 130 以上に達すると、プレイヤーはレベル 19 に移行します。 

その後、さらに 10 ラインクリアするごとにレベルが 1 つずつ上がります。 140 行に達するとレベル 20 になり、150 行に達するとレベル 21 になります。 

18 を超える各レベルでは、スコア値が次のように増加します。 

- シングルの場合 +40
 - ダブルの場合 +100
 - トリプルの場合 +300
 - テトリスの場合 +1200

 タスクは、ログを処理し、最終スコアを計算し、スコアと最終レベルの両方を出力することです。 

アクションの数は次のように大きくなります。$10^5$。 これにより、アクションごとに行数やレベル範囲を繰り返し繰り返すシミュレーションが即座に除外されます。 作業がログ エントリの数に比例するソリューションが必要です。 アン$O(N)$スキャンは簡単に十分に高速です。 

微妙な点は、アクションのスコアリングに使用されるレベルが、そのアクションから新しくクリアされたラインが追加される前のレベルであることです。 手がしきい値を超えるのに十分なラインをクリアした場合でも、その手は以前のレベルを使用してスコアを獲得し、今後の動きのみがより高いレベルを使用します。 

次の例を考えてみましょう。```
129 cleared lines so far
next action = single
```シングルはレベル 18 シングルとしてスコア化する必要があります。 アクション後、合計は 130 になり、プレイヤーはレベル 19 に進みます。 

よくある間違いは、最初に行数を更新し、新しいレベルを計算してから、アクションをスコアリングすることです。 これにより、実際に移行をトリガーした動きに対してレベル 19 ポイントが誤って付与されてしまいます。 

もう 1 つのエッジ ケースは、一度に複数のしきい値を大きく超える場合です。```
128 lines
next action = tetris
```プレイヤーは合計 128 行から 132 行にジャンプします。 アクションのスコアは依然としてレベル 18 です。その後初めてレベルが 19 になります。 

## アプローチ

 単純なシミュレーションでは、アクションを 1 つずつ処理します。 

すべてのアクションについて、既にクリアされた行数から現在のレベルを決定し、そのレベルでのそのアクションのスコアを検索し、対応するクリアされた行数を追加して続行します。 

ブルートフォースバージョンでもすでに効率的です。$10^5$アクション。 唯一の潜在的な非効率性は、しきい値を反復処理してレベルを繰り返し再計算することです。 毎回しきい値をスキャンすると、コストが不必要に増大します。 

重要な点は、レベルが現在のアクションの前にクリアされた行数のみに依存するということです。 直接的な公式があります。 

クリアしたラインが 130 ライン未満の場合、レベルは 18 です。 

それ以外の場合:$$\text{level} = 19 + \left\lfloor \frac{\text{lines}-130}{10} \right\rfloor$$現在のレベルを一定時間で計算できるようになると、すべてのアクションも一定時間で処理されます。 

得点するには、$$d = \text{level} - 18$$この場合、スコア値は次のようになります。$$760 + 40d$$シングルの場合、$$1900 + 100d$$ダブルの場合、$$5700 + 300d$$トリプルの場合、$$22800 + 1200d$$テトリスの場合。 

問題全体は、ログを 1 回通過するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースしきい値シミュレーション | O(N) | お(1) | 承認済み |
 | 最適な直接レベル計算 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`lines = 0`そして`score = 0`。 
2. 各スコアリングアクションについて、すでにクリアされたライン数から現在のレベルを決定します。 

もし`lines < 130`、レベルは 18 です。それ以外の場合は、次を使用します。$$19 + (lines - 130) // 10$$3. コンピューティング`d = level - 18`。 

これにより、開始レベルから何回レベルが上昇したかがわかります。 
4. 現在のレベルを使用して、現在のアクションに対してポイントを与えます。 

アクションは、新しくクリアされた行を追加する前にスコア付けする必要があります。 
5. 対応する数のクリアされた行を追加します。`single -> 1`

`double -> 2`

`triple -> 3`

`tetris -> 4`6. すべてのログ エントリが処理されるまで続行します。 
7. ログ全体を処理した後、同じ式を使用して、最終的にクリアされた行の総数から最終レベルを計算します。 
8. 最終スコアと最終レベルを出力します。 

### なぜ効果があるのか

 あらゆる瞬間において、ゲームのレベルは現在のアクションの前にクリアされたライン数のみによって決まります。 スコアリングのルールは、アクション後の行数ではなく、そのレベルによって決まります。 

アルゴリズムはこの不変条件を正確に維持します。 各ログエントリを処理する前に、`lines`以前にクリアされた行の数を保存します。 現在のレベルはその値から計算され、それに応じてアクションがスコアリングされ、その後初めて新しくクリアされた行が追加されます。 

すべてのアクションは実際のゲームで使用されるのと同じレベルを使用してスコア付けされ、レベル遷移は公式のしきい値から直接計算されるため、累積スコアと最終レベルは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_level(lines):
    if lines < 130:
        return 18
    return 19 + (lines - 130) // 10

def solve():
    n = int(input())

    score = 0
    lines = 0

    for _ in range(n):
        action = input().strip()

        level = get_level(lines)
        d = level - 18

        if action == "single":
            score += 760 + 40 * d
            lines += 1
        elif action == "double":
            score += 1900 + 100 * d
            lines += 2
        elif action == "triple":
            score += 5700 + 300 * d
            lines += 3
        else:  # tetris
            score += 22800 + 1200 * d
            lines += 4

    final_level = get_level(lines)
    print(score, final_level)

solve()
```機能`get_level`レベル遷移ルール​​を直接エンコードします。 このロジックを 1 か所に保持すると、スコアリングと最終レベルの計算の間の不一致が回避されます。 

実装の詳細の重要な点は、操作の順序です。 現在のレベルは、行数を更新する前に計算されます。 これは、動きがしきい値を超えたときのゲームの動作と一致します。 

スコア値は、レベル 18 の基本値にレベル依存の増分を加えたもので表されます。 これにより、大きなテーブルの保存が回避され、ステートメントで説明されているルールが反映されます。 

Python の整数は大きな値を自動的に処理するため、すべてのアクションがテトリスであってもオーバーフローの心配はありません。
