 ## 解決策
 ## 問題の理解

 整数シーケンスが与えられるので、残りの要素の順序を維持したまま任意の要素を削除できます。 

目標は、結果として得られるサブシーケンスですべての内部要素が厳密な山または厳密な谷になるように、できるだけ多くの要素を保持することです。 サブシーケンス内のすべての位置について、その値は両方の隣接点よりも大きいか、両方の隣接点よりも小さい必要があります。 言い換えれば、連続する要素間の差異は符号が交互になる必要があります。 

出力はサブシーケンスそのものではありません。 元の配列で選択した要素のインデックスを出力する必要があります。 少なくとも 3 の長さの振動サブシーケンスが存在しない場合は、次のように出力します。`0`。 

配列の長さは 50,000 に達する場合があります。 二次動的計画法ソリューションでは、最悪の場合、約 25 億回の比較が必要になりますが、これは利用可能な時間をはるかに超えています。 周りのものすべて`O(n²)`すぐに除外されます。 線形または`O(n log n)`解決策が必要です。 

トリッキーなケースは、等しい値と長い単調な実行から発生します。 

考慮する：```
3
1 1 2
```正しい答えは、`0`。 増加と減少のみをチェックする不注意な実装では、最初の 2 つの値が有効な方向の変化として誤って扱われる可能性があります。 

考慮する：```
5
1 2 3 4 5
```すべてのサブシーケンスは単調です。 少なくとも 3 長さの振動は存在しないので、答えは次のようになります。`0`。 

考慮する：```
5
1 5 3 4 2
```シーケンス全体がすでに交互になっています。```
1 < 5 > 3 < 4 > 2
```答えには 5 つのインデックスがすべて含まれています。 

考慮する：```
6
1 4 7 5 2 6
```価値観`4`そして`5`両方とも必要ではありません。 最も長い振動サブシーケンスは、転換点のみを保持します。```
1 < 7 > 2 < 6
```値のすべての変化を維持する単純な戦略では、有効な振動は生成されません。 

## アプローチ

 その強引なアイデアが動的プログラミングです。 

すべての位置とすべての以前の位置について、最後のステップが増加しているか減少しているかを思い出しながら、サブシーケンスの拡張を試みることができます。 これにより、最長の振動サブシーケンスが正しく検出されますが、インデックスのすべてのペアを調べる必要があります。 と`n = 50,000`最悪の場合の作業は次のとおりです。`50,000²`、それは完全に不可能です。 

重要な観察は、厳密に増加する実行の内部では、最後の要素のみが重要であるということです。 現在次のものがあるとします。```
... < 3 < 5 < 8
```将来的に減少させたい場合は、`8`常に少なくとも維持するのと同じくらい良い`5`または`3`、 なぜなら`8`次の下降ステップの自由度が高まります。 

同じ理由が実行数の減少にも当てはまります。 内部```
... > 10 > 7 > 4
```最小のエンドポイントのみが役に立ちます。 

これは、すべてのモノトーン セグメントをそのエンドポイントまで圧縮できることを意味します。 生き残る要素はまさに転換点、山と谷です。 貪欲なアルゴリズムにより、これをオンラインで維持できます。 

回答インデックスを左から右に構築します。 

考慮される最後の 3 つの値が単調な場合は常に次のようになります。```
x ≤ y ≤ z
```または```
x ≥ y ≥ z
```中間の値`y`最適な振動サブシーケンスでは決して山や谷になることはできません。 それを削除し、より極端なエンドポイントを保持します。 

配列全体を処理した後、残りのインデックスは最大長の振動サブシーケンスを形成します。 これは、古典的なウィグル部分列問題で使用されるのと同じ貪欲な原理です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n²) | O(n²) または O(n) | 遅すぎる |
 | 貪欲な転換点 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 回答リストの先頭にインデックスを付ける`0`。 
2. インデックスを左から右に処理します。 
3. 現在のインデックスの場合`i`、最後に選択した 2 つのインデックスを確認し、`i`。 
4. 値を次のようにします。`x`、`y`、 そして`z`。 
5. もし`x ≤ y ≤ z`、 それから`y`非減少セグメント内にあります。 取り除く`y`それを次のように置き換えます`i`。 
6. もし`x ≥ y ≥ z`、 それから`y`非増加セグメント内にあります。 取り除く`y`それを次のように置き換えます`i`。 
7. それ以外の場合、方向は次のように変わります。`y`そして`z`。 ポイント`y`山か谷になるので追加`i`。 
8. すべてのインデックスが処理された後、保存されたインデックスは最長の振動サブシーケンスを記述します。 
9. 残っているインデックスが 3 つ未満の場合は、次のように出力します。`0`。 それ以外の場合は、長さとインデックスを出力します。 

### なぜ効果があるのか

 不変条件は、配列の任意のプレフィックスを処理した後、格納されたインデックスがそのプレフィックス内で終わる可能な限り長い振動サブシーケンスを形成することです。 

連続する 3 つの候補値が満たされるたびに、```
x ≤ y ≤ z
```中間の値は決して役に立ちません。 後に続く可能性のある将来の要素`y`フォローすることもできます`z`、 そして`z`少なくとも同じくらい極端です。 交換中`y`と`z`達成可能な最大振動長を短縮することはできません。 

同じ議論が当てはまります```
x ≥ y ≥ z
```ここで、最新の値は少なくとも中央の値と同じくらい役に立ちます。 

その結果、削除されたすべての要素は明らかに冗長です。 保持されているすべての内部要素は真の方向の変化に対応し、山または谷になります。 冗長な点のみが破棄されるため、結果として得られるサブシーケンスは可能な最大長になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = [0]

for i in range(1, n):
    while len(ans) >= 2:
        x = a[ans[-2]]
        y = a[ans[-1]]
        z = a[i]

        if (x <= y <= z) or (x >= y >= z):
            ans.pop()
        else:
            break

    ans.append(i)

if len(ans) < 3:
    print(0)
else:
    print(len(ans))
    print(*ans)
```リスト`ans`この問題では元のシーケンス内の位置が求められるため、値ではなくインデックスが保存されます。 

の`while`ループは貪欲な戦略の核心です。 最新の値が現在の単調傾向を継続する場合、以前のエンドポイントは役に立たなくなり、削除されます。 

を使用して`while`単一の代わりに`if`重要です。 1 つのインデックスを削除すると、新しいトリプルが形成され、単調になる場合もあります。 このプロセスは、最後に選択したポイントが真の転換点になるか、前のポイントが 1 つだけ残るまで続きます。 

等しい値は条件によって自然に処理されます```
x <= y <= z
x >= y >= z
```これにより、平らなセグメントが偽の振動を生成するのを防ぎます。 

すべてのインデックスは 1 回挿入され、多くても 1 回削除されるため、合計実行時間は線形のままです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべてのインデックスは 1 回プッシュされ、最大 1 回ポップされます。 
| スペース | O(n) | 回答インデックスは次のように保存されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    ans = [0]

    for i in range(1, n):
        while len(ans) >= 2:
            x = a[ans[-2]]
            y = a[ans[-1]]
            z = a[i]

            if (x <= y <= z) or (x >= y >= z):
                ans.pop()
            else:
                break

        ans.append(i)

    out = []

    if len(ans) < 3:
        out.append("0")
    else:
        out.append(str(len(ans)))
        out.append(" ".join(map(str, ans)))

    return "\n".join(out)

# sample-like cases
assert run("3\n1 3 2\n") == "3\n0 1 2"
assert run("3\n1 2 3\n") == "0"

# minimum size
assert run("1\n5\n") == "0"

# all equal
assert run("5\n7 7 7 7 7\n") == "0"

# already oscillating
assert run("5\n1 5 2 6 3\n") == "5\n0 1 2 3 4"

# long monotone run compressed to endpoints
assert run("6\n1 4 7 5 2 6\n") == "4\n0 2 4 5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 5`|`0`| 最小サイズ |
 |`7 7 7 7 7`|`0`| 値が等しいと振動は発生しません。 
|`1 5 2 6 3`| すべてのインデックス | すでに最適なシーケンス |
 |`1 4 7 5 2 6`| ターニングポイントのみ | モノトーンセグメントの圧縮 |

 ## 特殊なケース

 次のことを考慮してください。```
3
1 1 2
```処理`2`パターンを作成します:```
1 ≤ 1 ≤ 2
```真ん中のインデックスが削除されます。 最終的なインデックス セットは次のようになります。```
[0, 2]
```その長さは 2 だけなので、アルゴリズムは次のように出力します。`0`。 値が等しい場合でも、偽の山や谷が生成されることはありません。 

考慮する：```
3
1 2 3
```パターンは常に増加しています:```
1 ≤ 2 ≤ 3
```中間点は破棄され、端点のみが残ります。 ここでも最終的な長さは 2 なので、答えは次のようになります。`0`。 

考慮する：```
6
5 4 3 2 1 0
```すべての新しい値は同じ減少傾向を続けます。 このアルゴリズムは、以前のエンドポイントを繰り返し削除し、最新のエンドポイントを保持します。 最後のサブシーケンスには最初と最後のインデックスのみが含まれています。少なくとも 3 の長さの振動は存在しないため、これは正しいです。 

考慮する：```
5
1 3 2 4 1
```すべての内部要素はすでに厳密な山または谷になっています。```
1 < 3 > 2 < 4 > 1
```どの単調性条件もトリガーされず、すべてのインデックスが残り、アルゴリズムは完全なシーケンスを返します。
