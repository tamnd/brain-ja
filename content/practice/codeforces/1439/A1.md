 ## 解決策
 ## 問題の理解

 グリッドにはセルごとに可能な状態が 2 つだけ含まれており、目標は、非常に特殊なローカル操作を適用してすべての状態を除去することです。 各操作は単一の 2 x 2 ブロックを調べ、その 4 つのセルのうちちょうど 3 つを反転します。 反転とは 0 から 1、および 1 から 0 を切り替えることを意味するため、各移動により、制御された方法でその小さな正方形内のパリティが変更されます。 

重要な視点は、「セルを独立して編集している」わけではないということです。 すべての移動は、固定された 2 x 2 領域内の 3 つの位置を結合するため、セルを修正する唯一の方法は、隣接する正方形の調整された変更を介することです。 これは、ボトムアップ戦略をすぐに示唆します。セルが処理領域内に入ると、以前の作業を中断せずに再びそれに触れるのは難しいためです。 

制約は十分小さいため、グリッド上の線形スイープで十分です。 すべてのテスト ケースにわたるセルの合計数は最大 20,000 であるため、セルごとに制限された数の演算を割り当てる定数要素を多用した構造であっても安全です。 操作空間は組み合わせであるため、グローバル検索や状態探索のアプローチは除外されます。 

2 x 2 ブロックに 3 つまたは 4 つのブロックが含まれる場合、微妙なエッジ ケースが発生します。 体系的な削減を強制せずに任意のトリプルを反転する単純な貪欲なアプローチでは、ブロックが別の高密度構成のままになり、発振または不完全なクリアが発生する可能性があります。 たとえば、完全に埋められた 2 x 2 ブロックでは、任意のトリプルを反転すると、ゼロが 1 つだけ含まれる別の構成が生成されます。これは慎重に処理する必要があり、そうしないと、進行せずにループする危険があります。 

## アプローチ

 ブルートフォース解釈では、これを、考えられるすべての操作シーケンスにわたる状態探索問題として扱います。 各演算はローカル正方形内の 3 ビットを変更するため、分岐係数は大きく、必要な深さは 1 の数に比例します。 100 x 100 のグリッドであっても、構成の数は天文学的に多く、遷移を調査することは不可能です。 

重要な構造的観察は、各操作が 2 x 2 の正方形に限定されていることです。これは、グリッドをセルごとに処理し、問題を右下隅に寄せる方法で常に 1 つを削除できることを示唆しています。 任意のパターンを「修正」しようとする代わりに、2 x 2 ブロックごとに単純な状態に縮小し、残りのブロックを下方向と右方向に伝播します。 

標準的な建設的なアイデアは、最後の行と列を除くすべてのセルを反復処理することです。 1 が表示されるたびに、そのセルに固定されている 2 x 2 の正方形に対して操作を強制し、そのセルの寄与を排除し、制御された方法で処理済みのセルまたは将来のセルにのみ影響を与えます。 これにより、右下の 2 x 2 ブロックに到達するまでに、残りのブロックはすべてそこに閉じ込められ、固定された一連の操作を使用して直接クリアできるようになります。

 ## アルゴリズムのチュートリアル

 グリッドを左上から右下に処理しますが、最大 n-1 行、m-1 列までしか処理しません。これは、すべての操作が選択した左上隅から始まる 2 x 2 ブロックをターゲットにするためです。

1. 最後の行または最後の列を除く各セル (i, j) を繰り返します。 この段階では、(i, j) の 1 はすぐに削除する必要があります。これは、後でここに固定された 2 x 2 ブロックを安全に使用する機会が二度とないためです。 
2. Grid[i][j] がすでに 0 の場合は、何もせずに次に進みます。 変更しないままにすると、不必要な反転が発生しなくなります。 
3. Grid[i][j] が 1 の場合、(i, j)、(i, j+1)、(i+1, j)、(i+1, j+1) によって形成される 2 × 2 の正方形を調べます。 これら 4 つのセルのうち 3 つを反転する操作を構築し、常に左上のセルが 0 になることを保証するパターンを選択します。 

便利な決定論的な選択は、反転されたセットに (i, j) が含まれることを常に保証することです。 他の 3 つのセルのうち 2 つ未満が 1 である場合は、ちょうど 3 つのセルが切り替わるように適切なセルを選択して操作を完了します。 これにより、隣接する位置に一時的に 1 が導入される可能性がありますが、それらの位置はすでに処理されているか、後で処理されます。 

1. 最後の行と列を除くすべてを処理した後、右下の残りの 2 x 2 ブロックに注目します。 このような各ブロックは個別に縮小できます。 ブロック内に残っている 1 の数に応じて、すべて 0 になるまで固定パターンを繰り返し適用します。 各演算は制御された方法でそのブロック内の 1 の数を減らすため、ブロックごとに最大でも一定数の演算が必要となります。 

これが機能する理由は、すべての操作がローカル メジャー (通常は検討中の現在または最終ブロック内の 1 の数) を厳密に削減するためです。 スイープ順序により、以前の修正が後で取り消されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add(ans, cells):
    ans.append([cells[0][0], cells[0][1],
                cells[1][0], cells[1][1],
                cells[2][0], cells[2][1]])

def solve():
    n, m = map(int, input().split())
    g = [list(map(int, list(input().strip()))) for _ in range(n)]
    ans = []

    for i in range(n - 1):
        for j in range(m - 1):
            if g[i][j] == 1:
                cells = [(i, j), (i, j + 1), (i + 1, j), (i + 1, j + 1)]
                ones = [(x, y) for x, y in cells if g[x][y] == 1]
                zeros = [(x, y) for x, y in cells if g[x][y] == 0]

                if len(ones) == 4:
                    op = [ones[0], ones[1], ones[2]]
                elif len(ones) == 3:
                    op = ones
                elif len(ones) == 2:
                    op = [ones[0], ones[1], zeros[0]]
                else:
                    op = [ones[0], zeros[0], zeros[1]]

                add(ans, [(x + 1, y + 1) for x, y in op])
                for x, y in op:
                    g[x][y] ^= 1

    for i in range(n - 1):
        for j in range(m - 1):
            if g[i][j] == 1 or g[i][j + 1] == 1 or g[i + 1][j] == 1 or g[i + 1][j + 1] == 1:
                cells = [(i, j), (i, j + 1), (i + 1, j), (i + 1, j + 1)]
                ones = [(x, y) for x, y in cells if g[x][y] == 1]

                if len(ones) == 4:
                    op = [ones[0], ones[1], ones[2]]
                elif len(ones) == 3:
                    op = ones
                elif len(ones) == 2:
                    op = [ones[0], ones[1], cells[0] if cells[0] not in ones else cells[1]]
                else:
                    continue

                add(ans, [(x + 1, y + 1) for x, y in op])
                for x, y in op:
                    g[x][y] ^= 1

    print(len(ans))
    for op in ans:
        print(*op)

if __name__ == "__main__":
    solve()
```この構造では、実行中の操作リストが維持され、その影響がグリッド上で即座にシミュレートされます。 主要な実装の詳細は、2 x 2 ブロック内の現在のパリティ構成に基づいて各操作が選択されることです。 これにより、グローバルな推論が必要なくなります。 

ダブルパス構造は意図的です。 最初のパスでは、すべての不規則性が右下の領域に向かって押し出されます。 2 番目のパスでは、そのプロセス中に作成された可能性のある残りのパターンがクリーンアップされます。 1 ベースのインデックスへの座標変換は操作を記録する場合にのみ適用されるため、シミュレーション中の 1 つ違いのミスが回避されます。 

## 実用的な例

 小さなグリッドを考えてみましょう。```
1 1
1 0
```単一の 2 x 2 ブロックを追跡します。 

| ステップ | ブロック状態 | 見つかったもの | 選択された操作 | 結果のブロック |
 | --- | --- | --- | --- | --- |
 | 1 | 1 1 / 1 0 | 3 | 3 つすべてを反転します | 0 0 / 0 1 |
 | 2 | 0 0 / 0 1 | 1 | パターン | を使用して最後のものを修正します。 0 0 / 0 0 |

 最初の操作では密集領域がクリアされますが、残りの領域が作成される可能性があります。 2 番目のステップで解決します。 

ここで次のことを考えてみましょう。```
1 0 1
0 1 0
1 0 1
```左上の 2 x 2 ブロックを処理すると、局所的な密度が減少し、残りの密度が下または右のブロックに押し込まれます。 各操作はアクティブ ブロック内の 1 の数を厳密に減らすため、ブロックごとの制限された数の操作の後、グリッド全体が 0 になります。 

トレースは、影響を受けるすべてのセルが現在の処理フロンティア内またはその下にあるため、既に処理された領域に複雑さを再導入する操作がないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各セルは、最大でも 2 x 2 の定数の修正に参加します。 
| スペース | O(nm) | グリッドストレージと運用リスト |

 すべてのテスト ケースにわたるセルの合計数は 20000 で制限されているため、nm 操作の定数倍であっても安全に制限内に収まります。 この構造では、問題の制約に合わせて、セルごとに最大 3 つの操作が保証されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    out = []

    def solve():
        n, m = map(int, input().split())
        g = [list(map(int, list(input().strip()))) for _ in range(n)]
        ops = []

        def add(cells):
            ops.append(cells)

        for i in range(n - 1):
            for j in range(m - 1):
                if g[i][j] == 1:
                    cells = [(i, j), (i, j + 1), (i + 1, j), (i + 1, j + 1)]
                    ones = [c for c in cells if g[c[0]][c[1]] == 1]
                    zeros = [c for c in cells if g[c[0]][c[0]] == 0]

                    if len(ones) >= 3:
                        op = ones[:3]
                    else:
                        op = ones + zeros[:3-len(ones)]

                    for x, y in op:
                        g[x][y] ^= 1

        out.append(str(len(ops)))

    solve()
    return "\n".join(out)

 ## 特殊なケース

 重大な状況は、2 x 2 ブロックに 1 つだけがある場合です。 単純な戦略では、常に 3 つを反転しようとする可能性がありますが、ここではそれは不可能であり、無効な操作が発生したり、間違った選択を強制されたりする可能性があります。 代わりに、アルゴリズムはこのケースを 1 つの 1 と 2 つのゼロのペアにすることで処理し、操作が有効なままであり、1 を削除する方向に進むことを保証します。 

別のエッジケースは、右下の領域が以前のステップからの残りの領域を蓄積するときに発生します。 スイープ順序が厳密に左上から右下ではない場合、以前の修正は後の操作によって元に戻される可能性があります。 固定された走査順序により、ブロックが処理されると、その後の操作がその左上のアンカーに触れないことが保証され、正確さが維持されます。
