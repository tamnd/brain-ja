 ## 解決策
 ## 問題の理解

 私たちは次のラインを持っています$n$コンピューターと$m$参加者にはそれぞれ優先コンピューターと入力方向があります。 各参加者は特定のコンピューターに座りたいと考えていますが、それが占有されている場合は、空いているコンピューターが見つかるまで入力した方向に進み続けます。 参加者の「狂気」とは、参加者が望んでいたコンピューターと実際に座っているコンピューターとの間の距離です。 私たちは、参加者が動揺しないように、参加者の好みと参加方向の考えられるすべてのシーケンスを考慮し、すべての有効なシーケンスの総狂気を素数を法として合計したいと考えています。$p$。 

制約$1 \le m \le n \le 500$それを暗示します$m$そして$n$を許容できるほど小さい$O(n^2 \cdot m)$動的プログラミングのアプローチですが、すべてを単純に列挙します$n^m \cdot 2^m$可能な構成は不可能です。 これにより、強引な解決策が排除されます。 

複数の参加者が同じターゲット コンピューターを使用している場合、明らかではないエッジ ケースが発生します。 たとえば、$n=3$そして$m=2$、両方の参加者がコンピューターをターゲットにします$2$、一方が左から、もう一方が右から入った場合、お互いをブロックする可能性があります。 すべての方向を無視したり、参加者を個別に扱ったりする不用意なシミュレーションは、一部のシーケンスが参加者の動揺につながるため、カウントすべきではないため、不正確な完全な狂気を生み出すことになります。 

## アプローチ

 ブルートフォースアプローチは、すべてを列挙することです。$n^m$配列$a$そして$2^m$配列$b$、各参加者の座席をシミュレートし、狂気の合計を計算し、参加者が動揺していない構成のみを含めます。 これは正しいですが、計算上実行不可能です。$500^{500} \cdot 2^{500}$天文学的です。 

重要な洞察は、この問題には、我々が利用できる組み合わせ構造があるということです。 参加者の各シーケンスは、参加者に割り当てられたコンピュータの順列をカウントすることに相当し、各順列は、参加者が希望する座席からどれだけ移動する必要があるかによって重み付けされます。 各参加者の動きは、左または右のコンピューターをターゲットにする他の参加者の数にのみ依存するため、多項式を使用して問題をモデル化できます。$x^k$多項式では、合計の狂気が次のように参加者を割り当てる方法の数をエンコードします。$k$。 

これらの多項式の畳み込みを高速フーリエ変換 (FFT) またはより簡単に動的プログラミングで使用することにより、すべての有効なシーケンスにわたる狂気の合計を効率的に計算できます。 左右から入ってくる参加者からの寄与を表す 2 つの多項式を構築します。 それらを乗算すると、有効なすべてのシーケンスの狂気の値を合計した係数を持つ多項式が得られます。 モジュロ$p$操作により、値がオーバーフローしないことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^m * 2^m * m) | O(m) | 遅すぎる |
 | 多項式 DP / FFT | O(n * m^2) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化する`fL[i]`そして`fR[i]`のために$i=0\ldots n$、座席の配置方法の数を表します$i$参加者は左右から入場し、狂気の累計が係数としてエンコードされます。 当初は、`fL[0] = fR[0] = 1`参加者がゼロなので狂気も生まれません。 
2. 左から参加する参加者ごとに、利用可能なすべてのポジションを左から右に繰り返します。 目標位置に向けて$a_i$、参加者は所定の位置に座ることができます$a_i, a_i+1, \ldots, n$空いているもの。 それぞれの選択が貢献します`distance = position - a_i`狂気へ。 アップデート`fL`これらの寄与を多項式シフトとして追加することにより、既存の狂気係数に対して`k`、係数を増加します`k + distance`参加者をその位置に配置する方法の数によって決まります。 
3. 左右対称に、右側から入場する参加者を処理します。 右から左にターゲット位置を反復します。$a_i$、位置 $a_i、a_i-1、\ldots、1 を考慮します。`. The madness contribution is `距離 = a_i - 位置`. Update `fR`も同様に。 
4. すべての参加者が処理されると、畳み込みによって合計多項式が取得されます。`fL`そして`fR`。 各係数`c_k`結果では、参加者を完全に狂わせて座らせる方法の数がカウントされます`k`。 各係数を乗算します。`k`合計して $p` を法とする最終的な答えを取得します。 
5. 合計を返します。 整数のオーバーフローを避けるために、すべてのステップでモジュラー演算が使用されます。 

これが機能するのは、各ステップで次の不変条件が維持されるためです。`fL[i][k]`そして`fR[i][k]`すべての座席への配置方法を正しくエンコードする`i`完全に狂気の参加者`k`それぞれの側から入ります。 それらを組み合わせると、二重にカウントすることなくすべての有効なシーケンスがカウントされ、畳み込みは合計狂気を正しく蓄積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def solve():
    n, m, p = map(int, input().split())
    global MOD
    MOD = p

    # Initialize DP arrays for participants entering from left and right
    fL = [0] * (m * n + 1)
    fR = [0] * (m * n + 1)
    fL[0] = fR[0] = 1

    # Compute sum of madness for left and right separately
    for side in ('L', 'R'):
        dp = [0] * (m * n + 1)
        dp[0] = 1
        for k in range(1, m + 1):
            ndp = [0] * (m * n + 1)
            for i in range(len(dp)):
                if dp[i] == 0:
                    continue
                for move in range(n):
                    ndp[i + move] = (ndp[i + move] + dp[i]) % MOD
            dp = ndp
        if side == 'L':
            fL = dp
        else:
            fR = dp

    # Sum over convolution to get total madness
    ans = 0
    for i in range(len(fL)):
        ans = (ans + i * fL[i] * fR[i]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に DP 配列を準備します`fL`そして`fR`すべての座席シーケンスを左と右からエンコードします。 各配列インデックスは合計狂気値に対応します。 参加者と可能な距離を反復して DP 配列を更新し、係数ごとの乗算によって左右の寄与を結合して、すべての有効なシーケンスを考慮します。 モジュラー演算によりオーバーフローが防止されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m^2 * n) | 各 DP 更新は、m 人の参加者と最大 n 個の可能な距離にわたって反復されます。 
| スペース | O(m * n) | DP 配列には、考えられる狂気の合計値が格納されます。 

このアプローチは制約内に快適に適合します。$m,n \le 500$、について与える$500^2 * 500 = 125,000,000$3 秒の制限時間内で実行可能です。
