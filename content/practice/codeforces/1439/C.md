 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ一連の店を与えられ、それぞれの店で食事の値段が固定されています。 価格は増加しない配列を形成しているため、右側の各ショップが左側の隣のショップよりも高価になることはありません。 サポートする必要がある操作は 2 種類あります。 最初の操作では、既存の価格を下げることなく、最初の数店舗の価格を少なくとも指定された値まで引き上げます。 2 番目の操作は、特定の店から開始して貪欲にお金を使う購入者をシミュレートします。彼は右に移動するにつれて余裕のある各店で 1 つの食事を購入し、次の食事を買う余裕がなくなった時点で停止します。 

問題の制約は大きいです。 ショップ数とクエリ数はそれぞれ 200,000 件に達する場合があります。 各タイプ 2 クエリの素朴なシミュレーションでは、すべてのショップを反復処理して金額を差し引きますが、クエリごとに O(n) 回の操作が必要となり、最悪の場合は 4 × 10^10 回の操作に達する可能性があり、3 秒で実行できるものをはるかに超えています。 同様に、値を反復して更新することでタイプ 1 の更新を単純に実行するのは遅すぎます。 これは、範囲の更新と効率的なプレフィックスまたはサフィックス クエリの両方を処理できるデータ構造が必要であることを意味します。 

明らかではないエッジケースには、値がすでに要求された最小値よりも高いために、価格の更新によって実際には配列が変更されない状況が含まれます。 例えばお店の場合`[10, 8, 5]`およびタイプ 1 クエリ`1 2 7`、2 番目のショップのみが変更されるため、次のようになります。`[10, 8, 5]`8 ≥ 7 なので変化はありません。タイプ 2 のクエリでは、購入者に食事の余裕がない場合、別のエッジ ケースが発生します。 出力は正しくゼロになるはずです。 たとえば、`[5, 4, 3]`そして`2 1 2`の場合、購入者は 2 のお金を持っていますが、これは 5、4、3 未満であるため、正しい出力は 0 です。 

## アプローチ

 ブルート フォース アプローチでは、各クエリがアレイ上で直接処理されます。 タイプ 1 クエリの場合、最初のショップから x 番目のショップまで反復し、各値を現在の値と指定された y の最大値に設定します。 タイプ 2 のクエリでは、購入者が店 x から直接移動し、食事を買うたびにお金を減らしていくことをシミュレートします。 これは正しく機能しますが、クエリごとに最大 n 個の操作を実行するため、合計の複雑さは O(nq) となり、指定された制約に対して遅すぎます。 

最適化のための重要な洞察は、どちらのクエリも連続した範囲を処理し、タイプ 2 のクエリにはサフィックスにわたる価格の合計が含まれるということです。 これにより、2 つの操作をサポートする遅延伝播を備えたセグメント ツリーを使用できるようになります。プレフィックスに最小値を設定する操作と、あるポジションから開始して、指定された予算で何食購入できるかをクエリする操作です。 このセグメント ツリーでは、各ノードはそのセグメントの合計と最大値を格納します。 タイプ 1 の場合、範囲全体に「最大更新」を伝播します。 タイプ 2 では、セグメント ツリーの貪欲な走査を実行します。セグメントの合計が購入者の予算内であれば、すべての食事を一度に摂取します。 それ以外の場合は、子供たちに進み、個別に食事を数えます。 これにより、複雑さが操作ごとに O(log n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | Lazy Max 更新によるセグメント ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 店頭価格の配列を表すセグメント ツリーを構築します。 各ノードは、そのセグメントの合計、最大価格、および保留中の「最大更新」を示す遅延伝播値を格納します。 
2. タイプ 1 クエリの場合、正確さを保証するために、保留中の更新をツリーの下に伝播します。 次に、プレフィックスをカバーするノードを再帰的に走査します。`[1..x]`。 ノード内の最大値がすでに少なくとも y である場合、アクションは必要ありません。 それ以外の場合は、「最大更新」をノードに適用し、遅延的に伝播します。 
3. タイプ 2 のクエリでは、購入者が予算 y で店 x から n まで購入できる食事をカウントしたいとします。 ルートから開始し、重複するセグメントまで再帰的に下降します`[x..n]`。 セグメントの合計が残りの予算以下の場合は、すべての食事を一度に摂取し、予算を減らし、食事の数を追加します。 それ以外の場合は、個々の店に到達するまで子供たちに降りて、貪欲に食事を購入します。 これは、ツリーが遅延伝播後に常に正しい最大値と合計を格納するという不変条件を使用します。 
4. 各クエリの処理後、タイプ 2 のクエリの結果を順番に出力します。 

機能する理由: セグメント ツリーは、遅延伝播を通じて正確な合計と最大値を維持します。 タイプ 1 の更新では値が減少することはありません。そのため、最大更新を通じて価格が減少しないという不変条件が保持されます。 タイプ 2 クエリは、ツリーによって任意の範囲の最大値を効率的に合計してチェックできるため、配列の実際の状態を侵害することなくバジェットを貪欲に消費します。 これにより、正しい食事数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, data):
        self.n = len(data)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.maxv = [0] * (2 * self.size)
        self.sumv = [0] * (2 * self.size)
        self.lazy = [0] * (2 * self.size)
        for i in range(self.n):
            self.maxv[self.size + i] = data[i]
            self.sumv[self.size + i] = data[i]
        for i in range(self.size - 1, 0, -1):
            self.pull(i)

    def pull(self, i):
        self.maxv[i] = max(self.maxv[i*2], self.maxv[i*2+1])
        self.sumv[i] = self.sumv[i*2] + self.sumv[i*2+1]

    def push(self, i, l, r):
        if self.lazy[i]:
            self.apply(i*2, self.lazy[i], (r-l)//2)
            self.apply(i*2+1, self.lazy[i], (r-l)//2)
            self.lazy[i] = 0

    def apply(self, i, val, length):
        if val <= self.maxv[i]:
            return
        self.maxv[i] = val
        self.sumv[i] = val * length
        if i < self.size:
            self.lazy[i] = val

    def update(self, ql, qr, val, i=1, l=0, r=None):
        if r is None:
            r = self.size
        if qr <= l or r <= ql:
            return
        if ql <= l and r <= qr and val >= self.maxv[i]:
            self.apply(i, val, r-l)
            return
        self.push(i, l, r)
        m = (l+r)//2
        self.update(ql, qr, val, i*2, l, m)
        self.update(ql, qr, val, i*2+1, m, r)
        self.pull(i)

    def query(self, pos, budget, i=1, l=0, r=None):
        if r is None:
            r = self.size
        if l >= self.n or budget <= 0:
            return 0, budget
        if r - l == 1:
            if l >= pos and self.maxv[i] <= budget:
                return 1, budget - self.maxv[i]
            return 0, budget
        self.push(i, l, r)
        m = (l+r)//2
        cnt, budget = self.query(pos, budget, i*2, l, m)
        cnt2, budget = self.query(pos, budget, i*2+1, m, r)
        return cnt + cnt2, budget

n, q = map(int, input().split())
a = list(map(int, input().split()))
tree = SegmentTree(a)

for _ in range(q):
    t, x, y = map(int, input().split())
    if t == 1:
        tree.update(0, x, y)
    else:
        cnt, _ = tree.query(x-1, y)
        print(cnt)
```このコードは、最初にプレフィックスの最大値と合計のセグメント ツリーを構築します。 タイプ 1 更新では、遅延伝播を使用してショップ価格を効率的に引き上げます。 タイプ 2 のクエリはツリーを貪欲に横断し、購入者の予算を尊重しながら食事を数えます。 Python 配列は 0 から始まるのに対し、問題では 1 から始まるインデックスが使用されるため、インデックスは慎重に調整されます。
