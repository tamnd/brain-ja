 ## 解決策
 ## 問題の理解

 値のペアが与えられています$(a, b)$素数を法とする有限体上で$p$。 各クエリは、開始ペアを変換するために必要な最小限の操作数を要求します。$(a_i, b_i)$ターゲットペアに$(c_i, d_i)$ここで、各操作は 2 つの決定論的な変換のうちの 1 つを適用します。 

各変換では、2 つの座標をモジュロで線形に混合します。$p$。 1 つの操作は 1 つの座標を 2 倍にし、減算を使用してもう 1 つの座標を調整し、もう 1 つの操作は 2 番目の座標に対して対称的なアクションを実行します。 重要なのは、これらの変換は交換できないため、操作の順序が重要であるということです。 

入力サイズが大きい: 最大$10^5$クエリと$p$と同じ大きさにすることができます$10^9+7$。 これにより、すべてのクエリごとのグラフの走査が即座に排除されます。$p^2$州。 グラフにはサイズがあるため、状態空間にわたる単一の BFS さえ不可能です$p^2$、これは計算の限界をはるかに超えています。 

したがって、重要な要件は、状態空間を 1 次元または代数的に構造化されたものに圧縮して、各クエリが対数時間または定数時間で応答できるようにすることです。 

微妙な制約としては、$a+b \not\equiv 0 \pmod p$すべての入力に対して。 この条件は主要な構造上のヒントであることが判明します。これにより、ダイナミクスがあいまいになる特殊な不変部分空間への退化が防止されます。 

単純なアプローチでは、次からのすべての可能な変換をシミュレートします。$(a,b)$BFS が到達しようと試みます$(c,d)$。 これはすぐに失敗します: 探索しても$10^6$クエリごとの状態数は制限をはるかに超えており、$10^5$クエリ。 

2 番目の素朴なアイデアは、変換が線形であることを観察し、行列をべき乗してみるというものです。 ただし、同じ演算を繰り返し適用するわけではないため、行列のべき乗は直接役に立ちません。 各ステップで 2 つの異なる線形マップから選択することになり、考えられる構成の数が指数関数的に増加します。 

注意すべき重要なエッジ ケースは、どちらの操作も 2 次元のように見えますが、問題を解決する非常に強力な不変条件を保持していることです。 

たとえば、小さな値を試してみると、次のようになります。$(a,b) = (1,2)$、どちらの操作でも保存されます$a+b = 3$。 これは偶然ではなく、重要な構造の簡素化です。 

## アプローチ

 ブルートフォースソリューションは各状態を処理します$(a,b)$2 つの出力エッジを持つ有向グラフのノードとして。 各クエリの開始状態から BFS を実行すると、最短パスが得られます。 これは正しいですが、各 BFS は次の範囲まで探索するため、不可能です。$p^2$州があり、そこにあります$10^5$クエリ。 

重要な観察は、両方の操作で合計が保持されることです。$$(a+b) \to (2a + (b-a)) = a+b$$そして$$(a+b) \to ((a-b) + 2b) = a+b.$$したがって、到達可能なすべての状態は同じアフィン ライン上になければなりません$a+b = S$、 どこ$S$クエリごとに固定されます。 

これにより、2D 問題が 1D 問題に分解されます。$a$知られていますが、$b$として決定されます$b = S - a$。 現在、私たちは進化を追跡するだけです$a$。 

各操作は次の関数になります。$a$:

 - 最初の操作:$a \to 2a$- 2 番目の操作:$a \to 2a - S$ここで問題は次のようになります。$a$、 到着$c$これら 2 つのアフィン関数の最小数の適用を使用します。 

これらの操作の構造は重要です。 どちらの演算も同じ線形部分 (2 の乗算) を共有し、定数シフトのみが異なります。 これは、一連の操作によって次の形式の変換が生成されることを意味します。$$a \mapsto 2^k a - S \cdot T$$どこ$T$2 番目の演算がシーケンス内のどこで使用されたかによって決定される、2 の個別のべき乗の合計です。 

これにより、問題は表現の問題になります。スケーリング制約の下で、バイナリ加重サブセット合計を使用して値を表現できるかどうかを判断する必要があります。 

この構造から、解決策は小さなエラーが存在するかどうかをチェックすることに帰着します。$k$次のような:$$\frac{2^k a - c}{S}$$範囲内の整数です$[0, 2^k - 1]$。 そういった最小限の$k$が答えです。

 ## アルゴリズムのチュートリアル

 不変条件とアフィン削減を使用して、各クエリを独立して解決します。 

1. 不変合計を計算する$S = a + b \bmod p$。 ターゲットペアが満たさない場合$c + d \equiv S \pmod p$、すぐに戻ります$-1$。 

これは、両方の操作が保存されるという事実からわかります。$a+b$、そのため不一致により変換は不可能になります。 
2. 次のように処理して、問題を単一の変数に還元します。$b$依存関係として:$b = S - a$。 ターゲットに対しても同じことを行うので、変換するだけで済みます。$a \to c$。 
3. 2 つの操作を定義します。$a$:$$f(a) = 2a, \quad g(a) = 2a - S.$$このステップでは、2D システムを単一の座標上のアフィン システムに変換します。 
4. その後の様子を観察します。$k$操作を行うと、どのシーケンスでも次の結果が生成されます。$$a_k = 2^k a - S \cdot T,$$どこ$T$は、次の異なる 2 のべき乗の部分集合和です。$k$ビット。 
5. ターゲットの方程式を並べ替えます。$$S \cdot T = 2^k a - c.$$計算:$$T = (2^k a - c) \cdot S^{-1} \bmod p.$$6.次のことを確認します。$T$は有効なバイナリ サブセットの合計です。 

それは満たさなければなりません$0 \le T < 2^k$。 もしそうなら、$k$実現可能です。 
7. 増加を繰り返す$k$(以来約60まで)$2^k$を超える$p$すぐに)、有効な最小値を返します$k$。 

### なぜ効果があるのか

 不変和は、システムを、同一の線形部分を持つ 2 つのマップによって生成される 1 次元のアフィン半群に還元します。 すべての操作シーケンスは、どのステップで変換を適用するかを選択することに一意に対応します。$-S$各アプリケーションは後続の 2 倍化によってスケーリングされるため、これらの変換はバイナリの重みで累積されます。 これにより、係数にバイナリ構造が強制されます。$T$、到達可能性は、2 の累乗にわたる制限されたサブセットの合計と等価になります。 表現は有効なそれぞれに対して一意であるため、$k$、存在のチェックは、状態空間の検索ではなく、単純な算術条件の検証に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p, q = map(int, input().split())
    inv = lambda x: pow(x, p - 2, p)

    for _ in range(q):
        a, b, c, d = map(int, input().split())

        S = (a + b) % p
        if (c + d) % p != S:
            print(-1)
            continue

        if S == 0:
            # impossible under constraints (given input guarantees S != 0)
            print(0 if (a, b) == (c, d) else -1)
            continue

        invS = pow(S, p - 2, p)

        pow2 = 1
        ans = -1

        for k in range(0, 70):
            if k > 0:
                pow2 = (pow2 * 2) % p

            val = (pow2 * a - c) % p
            t = (val * invS) % p

            if t < pow2:
                # additional consistency check in integer sense
                # lift to canonical integer representative already in [0, p)
                ans = k
                break

        print(ans)

if __name__ == "__main__":
    solve()
```実装ではまず不変式を強制します。$a+b$。 次に、各クエリをアフィン モデルでの実現可能性のチェックに削減します。 ループオーバー$k$2 のべき乗をモジュロで計算します$p$、それぞれについて$k$必要な変換係数を計算します$T$。 重要なチェックは、この係数がバイナリ範囲内に収まるかどうかです。$[0, 2^k)$、これは、2 番目の操作の有効なシーケンスから発生する可能性があるかどうかをエンコードします。 

モジュラー演算には注意が必要です。すべての中間計算はモジュロで実行されます。$p$ただし、最終的な実現可能性チェックは、次の代表値の自然な整数順序に依存します。$[0,p)$。

 ## 特殊なケース

 エッジ ケースの 1 つは、不変式が変換を即座にブロックする場合です。 もし$a+b \neq c+d$、アルゴリズムは戻ります$-1$これは、状態空間が互いに素な不変線に分割されることを反映しており、さらなる計算は必要ありません。 

もう 1 つのエッジ ケースは、変換が自明な場合です ($k=0$）。 アルゴリズムは正しくチェックします$T=0$で$k=0$、操作が適用されないことに対応します。 

3 番目のエッジケースは次の場合に発生します。$S$モジュロが小さいかゼロに近い$p$。 以来$S \neq 0$が保証され、モジュラー反転が常に有効であるため、アフィン リダクションでの除算の問題が防止されます。
