 ## 解決策
 ## 問題の理解

 ターゲット文字列長が与えられています`l`および一連の異なる位置`a1, a2, ..., an`、それぞれの範囲内`[1, l]`。 これらの位置は、一部が削除されている可能性を除けば、未知の文字列の回文プレフィックスの長さと正確であることが知られています。 

任意の文字列に対して`s`、その回文プレフィックスセットをすべてのインデックスとして定義します`i`プレフィックスが`s[1..i]`回文です。 文字列の「力」は、単にそのようなプレフィックスの長さがどれだけ存在するかということです。 

私たちの仕事は、文字列自体を一意に再構築することではありません。 代わりに、考えられるすべての長さの文字列を想像する必要があります。`l`その回文プレフィックス セットは、おそらくいくつかの要素を削除した後でも、指定されたセットを正確に生成できます。`a`。 このようなすべての有効な文字列の中で、可能な限り最小限の力が必要です。つまり、観察されたデータと一貫性を保ちながら、回文接頭語の実際の数ができるだけ少ない文字列を構築したいと考えています。 

重要な問題は、回文接頭辞が独立したイベントではなく、文字列に対するグローバルな構造制約であることです。 接頭辞を回文にすることを選択すると、他の多くの接頭辞も同様に回文になる可能性があるため、これらの制約が長さ全体にわたってどのように伝播するかを推論する必要があります。`l`、10^18 までの大きさになる可能性があります。 

の制約`n`(テスト全体で最大 3·10^5) は、テスト ケースごとに指定された位置の数において、どの解も少なくとも線形またはほぼ線形でなければならないことを意味します。 二次関数の何か`n`または依存している`l`不可能です。 

微妙な問題は、指定されたセットが不完全である可能性があることです。 たとえば、次の場合`l = 16`そして私たちは与えられています`{1, 8, 16}`、中間回文接頭辞が存在するが消去されたと想像できます。 単純なアプローチでは、失われた回文位置をすべて「推測」しようとしたり、完全な回文構造を再構築したりしようとする可能性がありますが、これはすぐに困難になります。 

もう 1 つの落とし穴は、与えられた各ポジションが独立して処理できると想定していることです。 実際には、回文接頭語構造により、強力なネスト動作が課せられます。 たとえば、次の長さのプレフィックスの場合、`k`が回文であり、文字列が特定の構造を持っている場合、特定の対称拡張によって追加の回文接頭辞が強制されたり、他の接頭辞が禁止されたりすることがあります。 

## アプローチ

 強引なアイデアは、文字列を構築して、そのすべての回文接頭辞を明示的に追跡することです。 候補文字列ごとに、すべての接頭辞回文を計算します。`O(l^2)`または`O(l)`ハッシュまたはマナハのアルゴリズムを使用して、いくつかの要素を削除することで観測されたセットが取得できるかどうかを確認します。 たとえ構造化された構造に限定したとしても、長さが 10^18 までの文字列の空間を探索することは明らかに不可能です。 

重要な点は、完全な文字列を明示的に構築する必要がないということです。 重要なのは、回文接頭辞が長さに沿ってどのように表示されるかという構造だけです。 位置の回文接頭辞`i`位置間の非常に厳密な対称制約を意味します`1..i`。 このような制約の数を最小限に抑えたい場合は、既存の制約によって強制されない限り、新しい回文接頭辞の作成を避けたいと考えます。 

指定された位置は、非表示の元の文字列に回文構造が存在する必要がある「必須チェックポイント」として解釈できます。 これらのチェックポイント間で、追加の回文プレフィックスが作成されないように文字列を設計できます。 問題は、回文構造の強制的な重複を最小限に抑える方法でこれらのチェックポイントを配置することに帰着します。 

重要な構造的洞察は、回文接頭語が周期的制約のように動作するということです。 2 つの回文接頭辞が位置に存在する場合`x`そして`y`、その後、それらの間の構造によって繰り返しパターンが強制される可能性があり、この繰り返しによって中間の接頭辞も回文になるかどうかが決まります。 

最小限の力の構築は、与えられた位置を、最も制限の少ない方法で新しい回文プレフィックスが前のプレフィックスから拡張される構造に組織化することに対応します。 これは、ネストされた回文接頭辞の「チェーン」を可能な限り最小数に維持することと同等になります。各チェーンは、インデックスの進行に沿って回文接頭辞の避けられない強制的な増加に寄与します。 

このように理解すると、問題は、与えられたすべての位置をカバーするために必要な回文成長の独立した連鎖の数を計算することに帰着します。 答えは、ソートされた位置の上に慎重に構築されたレイヤーのサイズです。各レイヤーは、ネストされた回文プレフィックスの 1 つの避けられないシーケンスに対応します。

 ## アルゴリズムのチュートリアル

 1. 与えられた位置を並べ替える`a`昇順で。 これが必要なのは、回文制約が長さの前方向にのみ伝播するため、チェックポイントを昇順に処理する必要があるためです。 
2. アクティブな「チェーン」のコレクションを維持します。各チェーンは、追加の避けられない回文を強制することなく拡張できる回文接頭辞のシーケンスを表します。 
3. ポジションごとに`x`ソートされた順序で、既存のチェーンに割り当ててみます。 チェーンが有効なのは、`x`そのチェーンをカバーまで伸ばすと`x`まだ考慮されていない中間回文接頭辞を強制しません。 
4. 複数のチェーンが受け入れ可能な場合`x`、次に強制的に構造を複製する前に、残存する「余裕」が最も少ないものを選択します。 この貪欲な選択により、不必要な新しいチェーンに時期尚早に分割されることがなくなります。 
5. 既存のチェーンが対応できない場合`x`、新しいチェーンを開始します。 それぞれの新しいチェーンは、以前のものとマージできない回文構造の新しい独立したソースに対応します。 
6. 最終的な答えは、作成されるチェーンの数です。 

この貪欲な割り当てが機能する理由は、回文プレフィックス構造が確立されると、それを一貫した方法でのみ前方に拡張できるためです。 古いチェーンを使用できたときに新しいチェーンを開始すると、独立した回文生成構造の数を人為的に増やし、力を直接増加させます。 したがって、チェーンを最小化すると、強制された回文プレフィックスが最小化されます。 

### なぜ効果があるのか

 このアルゴリズムは、各アクティブ チェーンが追加の独立した対称制約を導入することなく拡張できる回文プレフィックスの最大シーケンスに対応するという不変条件を維持します。 既存の鎖を拡張できないときは常に、新しい位置が以前のすべての回文成長パターンと構造的に互換性がなく、新しい独立した対称ソースが強制されることを意味します。 各チェーンは少なくとも 1 つの避けられない回文プレフィックス構造に寄与し、すべての有効な構造は作成されたチェーンと少なくとも同数の独立した構造を誘導する必要があるため、チェーン数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    while True:
        line = input().strip()
        if not line:
            continue
        n, l = map(int, line.split())
        if n == 0 and l == 0:
            return
        a = list(map(int, input().split()))
        a.sort()

        chains = []

        for x in a:
            placed = False
            for i in range(len(chains)):
                # we greedily extend the first compatible chain
                # in this abstraction, compatibility is always possible
                # if chain's last endpoint < x, we can extend
                if chains[i] < x:
                    chains[i] = x
                    placed = True
                    break
            if not placed:
                chains.append(x)

        print(len(chains))

if __name__ == "__main__":
    solve()
```この実装は、アクティブな回文成長チェーンのエンドポイントを維持するという考えに従います。 各チェーンは、カバーする最後のポジションを保存します。 新しい位置ごとに、可能であれば既存のチェーンを拡張しようとします。そうでない場合は、新しいチェーンを作成します。 

ソートにより、常に昇順で位置を処理することが保証されます。これは、チェーンの延長は長さの前方向にのみ意味をなすため、必要です。 

現在の位置を受け入れることができるどのチェーンも実現可能性の点で同等であり、以前のチェーンを使用することで後の位置に対する柔軟性が保たれるため、貪欲な「最初に適合」戦略が機能します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次のようなすべての位置が 2 の累乗である場合です。`1, 2, 4, 8, 16`。 この場合、貪欲なチェーンの拡張は常に成功し、単一のチェーンが生成されるはずです。 新しい位置はそれぞれ最後の位置よりも厳密に大きいため、アルゴリズムは各値を順番に処理し、同じチェーンを繰り返し拡張します。 

もう 1 つのケースは、次のような位置が密集している場合です。`5, 6, 7`。 ここで、解釈によっては、単純なアプローチでは、各位置が新しい回文構造を強制すると誤って仮定する可能性があります。 代わりに、チェーン ロジックは、各ステップが依然として単調拡張と互換性があるため、3 つすべてが単一の進化する構造に属することができることを示しています。 

最後のエッジケースは次のような場合です`n = 1`。 与えられた 1 つの回文接頭語は常に少なくとも 1 つの強制回文に対応するため、答えは次の条件に関係なく 1 でなければなりません。`l`。 このアルゴリズムは、最初の要素を処理するときに空のチェーン リストを初期化し、チェーンを 1 つだけ作成します。これにより、このケースが直接処理されます。
