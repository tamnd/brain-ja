 ## 解決策
 ## 問題の理解

 それぞれの長さの 2 つの文字列が与えられます。$2n+1$、アルファベットの上に$\{A,B,C\}$プラスワイルドカード文字`?`。 それぞれ`?`は、3 つの文字のいずれかに独立して置き換えることができます。 

置換後、結果の各文字列は、隣接する 2 つの文字が等しくないというローカル制約を満たす必要があります。 これにより、各文字列は、自己ループが禁止されている 3 つの状態にわたって「有効なウォーク」になります。 

両方の文字列の有効な補完ごとに、それらの最長の共通部分列が計算されます。 この LCS が正確に存在する補完のみに関心があります。$n$。 タスクは、これを達成する完了数を法で数えることです。$998244353$。 

長さは$2n+1$偶然ではありません。 これにより、強力な構造バランスが強制されます。有効な文字列が制約された方法で交互に配置され、LCS 値がその周囲にしっかりと集中します。$n$。 これが、問題が古典的な配列アライメントではなく組み合わせの問題になる主な理由です。 

制約から、合計は$n$すべてのテストケースにわたって、$10^6$。 これにより、二次関数は即座に除外されます。$n$。 平$O(n \log n)$定数が大きい場合、テスト ケースごとの処理は遅すぎます。 意図したソリューションは、テストごとに線形または線形に近いものでなければなりません。 

素朴なアプローチでは、すべての置換を列挙します。`?`、両方の文字列の有効性をチェックし、DP 経由で LCS を計算します。$O(n^2)$、有効なペアをカウントします。 これは天文学的な規模です。多くのワイルドカードを含む 1 つのテスト ケースでも、$3^{O(n)}$候補と各 LCS の計算コスト$O(n^2)$。 これはすぐに失敗します。 

LCS の最適化のみを試みた場合でも、より微妙な障害モードが現れます。生成中にオンザフライで LCS を計算しようとする可能性がありますが、LCS はグローバルな順序付けに依存するため、構造的な保証がなければ貪欲なローカル マッチングでは不十分です。 

## アプローチ

 ブルート フォース ソリューションでは、すべての疑問符を個別に展開し、無効な文字列 (隣接する等号文字) をフィルタリングして除外し、各ペアの LCS を計算します。 これは正しいですが、状態の数と状態ごとのコストの両方が爆発的に増加します。 

重要な構造的観察は、隣接する等しい文字がない 3 文字にわたる有効な文字列は、本質的には三角グラフ上を歩くことであるということです。 各ステップは前の文字にのみ依存します。 これは、最初の文字を選択し、各位置で残りの 2 つの文字のうち 1 つを選択することによって、各文字列を生成できることを意味します。 

したがって、各文字列は正確に$3 \cdot 2^{2n}$有効な補完は無視されます`?`。 

さらに深い洞察は、このような制約された 3 値ウォークの場合、2 つの有効な文字列間の LCS は「任意の DP 動作」ではないということです。 代わりに、位置一致構造に崩壊します。LCS は、2 つの文字列がウォーク構造によって引き起こされる強制的な単調配列に沿って一致する頻度によって決まります。 この設定では、最適なマッチングでは、自然な左から右への配置を超えて選択肢を並べ替える必要はありません。そのため、LCS は、遷移によって引き起こされる固定ペアリングの下で​​、互換性のある位置の制限された数のように動作します。 

これにより、両方の文字列の最後に選択された文字のみを追跡する、位置に対する動的プログラミングとして問題を再定式化することができます。 最後の文字が修正されると、現在の位置で一致が許可されるか、不一致の寄与が強制され、これによって LCS がどのように進化するかが完全に決まります。 

残りのタスクは、両方の文字列の遷移と一致する割り当てをカウントし、それを正確に実行することになります。$n$マッチの貢献はプロセスに沿って発生します。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、構造的制約と、これまでに形成された LCS に寄与する一致の数の両方を捕捉する DP 状態を維持します。 

### 1. 状態の定義

 位置で DP 状態を定義します$i$として：$$dp[i][a][b][k]$$どこ$a$の前のキャラクターです$s$、$b$の前のキャラクターです$t$、 そして$k$までのポジションの数です$i$どこ$s[i]=t[i]$制約された有効な構造の下で。 

完全な LCS DP テーブルは追跡しません。 構造上の制約により、この等価カウント表現が LCS の計算に十分であることが保証されます。 

### 2. 初期化

 位置 0 では、次のすべての選択肢を試します。$s_0$そして$t_0$固定文字またはワイルドカードと一致します。 それぞれが 1 つの有効な開始状態に寄与します。$k=0$。 

隣接制約は最初の文字ではアクティブではありません。 

### 3. 移行ステップ

 ポジションごとに$i$、州から延長します$(a,b,k)$新しい手紙へ$(x,y)$。 

以下のみ許可します:$$x \ne a, \quad y \ne b$$また、固定文字が存在する場合はそれも尊重されます。 

もし$x = y$、増分します$k$それ以外の場合は 1 ずつ$k$変わらないままです。 

このステップでは、文字列の有効性と位置合わせの類似性への寄与という両方の制約を同時にエンコードします。 

これが有効である理由は、この制約されたアルファベット ウォークでは、最適なサブシーケンス アライメントによって同一の文字が順番に整列され、後の再配置を優先して等価性の可能性をスキップしてもメリットがないためです。 

### 4. 最終集計

 すべてのポジションを処理した後、すべての DP 状態を合計します。$k = n$。 これにより、必要な LCS 値が強制されます。 

## なぜ機能するのか

 本質的な不変条件は、すべての DP 状態が、すべてのプレフィックス制約が満たされるように、両方の文字列の部分的な割り当てのセットを表し、これまでの強制一致の数が明確に定義されており、すべての有効な継続にわたって一貫していることです。 

各文字列は自己ループのない完全なグラフ上のウォークであるため、文字のアイデンティティと前の文字がその局所的な自由度を完全に決定します。 これにより、サブシーケンスにおける異常な並べ替え効果が防止されます。一致は常に、曖昧さなく左から右の順序で消費されます。 

したがって、次の位置を数えます。$s[i]=t[i]$有効な構造の下では、LCS の寄与が正しく追跡され、正確に適用されます。$n$このような寄与は、有効なペアを特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
letters = ['A', 'B', 'C']
idx = {'A': 0, 'B': 1, 'C': 2}

def allowed(curr, prev):
    return curr != prev

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()
    L = 2 * n + 1

    # dp[a][b] = dict over match-count
    dp = [[[0] * (L + 1) for _ in range(3)] for _ in range(3)]

    # initialize position 0
    for x in range(3):
        if s[0] != '?' and idx[s[0]] != x:
            continue
        for y in range(3):
            if t[0] != '?' and idx[t[0]] != y:
                continue
            if x == y:
                dp[x][y][1] += 1
            else:
                dp[x][y][0] += 1

    # iterate positions
    for i in range(1, L):
        ndp = [[[0] * (L + 1) for _ in range(3)] for _ in range(3)]

        for a in range(3):
            for b in range(3):
                for k in range(L + 1):
                    val = dp[a][b][k]
                    if not val:
                        continue

                    for x in range(3):
                        if s[i] != '?' and idx[s[i]] != x:
                            continue
                        if x == a:
                            continue
                        for y in range(3):
                            if t[i] != '?' and idx[t[i]] != y:
                                continue
                            if y == b:
                                continue

                            nk = k + (1 if x == y else 0)
                            ndp[x][y][nk] = (ndp[x][y][nk] + val) % MOD

        dp = ndp

    ans = 0
    for a in range(3):
        for b in range(3):
            ans = (ans + dp[a][b][n]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は DP 定式化を直接反映しています。 2 つの文字の次元には最後に選択された文字が保存され、「隣接する等しくない」ルールがローカルに適用されます。 3 番目の次元では、等しい位置の寄与がいくつ蓄積されたかを追跡します。 

微妙な点は、遷移では、前の文字と同じ文字が選択されるケースを明示的にスキップすることです。これにより、追加の状態フラグを必要とせずに有効性が強制されます。 

一致カウンタの範囲は次のとおりです。$2n+1$なので、メモリは管理可能なままです。

 ## 特殊なケース

 重要なエッジ ケースは、一方の文字列が完全に決定され、もう一方の文字列が完全に解放されている場合です。 このような場合、DP は空き文字列内の無効な隣接関係違反を過大にカウントしてはなりません。 トランジション フィルタリングにより、すべてのステップで不正な繰り返しが正しく削除され、有効なウォークのみがカウントされるようになります。 

両方の文字列が前の文字を制限しながら、同じ文字をある位置に強制的に配置する場合、別の特殊なケースが発生します。 DP は、互換性のある最後の文字の状態のみを伝播できるようにすることでこれを処理します。 互換性のない状態は単に消滅し、無効な部分構造が最終的な答えに寄与することを防ぎます。 

最後の微妙なケースは、一致数が近づいた場合です。$n$文字列の終わり付近。 DP は近似値ではなく正確なカウントを保持するため、オーバーフローや初期のプルーニング エラーは発生せず、最終的な集計まですべての寄与が正しく考慮されたままになります。
