 ## 解決策
 ## 問題の理解

 隠された単純な無向接続グラフが与えられます。$n$頂点。 私たちはその端を直接見ることはできません。 代わりに、頂点の任意のサブセットをクエリして、両方の端点が完全にそのサブセット内にあるエッジの数を取得できます。 

タスクはグラフを再構築することではありません。 必要なのは、グラフにオイラー サイクルが含まれているかどうかという「はい」または「いいえ」の答えだけです。 グラフは接続されているため、これは古典的な条件に帰着します。つまり、すべての頂点が偶数次数を持つ必要があります。 

したがって、問題全体は実際には、完全な隣接リストを明示的に構築せずに、サブセットのエッジ数クエリから十分な情報を回復して、すべての頂点次数が偶数であるかどうかを判断することです。 

制約は、最大で大きなグラフを示唆しています。$10^4$頂点まで$10^5$ただし、許可されるクエリは 60 個のみです。 これにより、隣接関係やすべての次数を直接回復しようとするアプローチは即座に除外されます。通常、これらのアプローチには少なくとも少なくとも$O(n)$クエリ。 

微妙な点は、単一の頂点に対するクエリでは常に 0 が返されるため、シングルトンには情報が含まれないことです。 唯一の意味のある情報は、大規模な誘導サブグラフ間の比較から得られます。 

素朴な間違いは、ランダムなサブセットをサンプリングし、パリティ パターンが奇数次の頂点を明らかにすることを期待することでオイラー性をテストできると仮定することです。 これは、サブセット クエリの出力が隣接行列の 2 次関数であり、局所次数情報が小さなサンプルから直接観察できないため、失敗します。 

## アプローチ

 ブルートフォースパースペクティブでは、すべての頂点の次数を決定しようとします。 すべての次数がわかっている場合は、それぞれが偶数であるかどうかを確認するだけです。 標準的な恒等式は、頂点の次数です。$v$エッジの総数と、エッジに関係しないエッジの数がわかっていれば、グローバル エッジ数から取得できます。$v$を減算して取得できます$\deg(v)$。 これは、完全なセットを一度クエリしてからクエリを実行するという戦略を示唆しています。$V \setminus \{v\}$頂点ごとに。 

これが機能するのは、1 つの頂点を削除すると、それに付随するエッジが正確に削除されるためです。したがって、総エッジ数と、頂点を削除しない場合に誘導されたサブグラフとの差は、$v$まさに$\deg(v)$。 

障害点は純粋にリソースベースです。 この方法に必要なものは、$n+1$これは、60 クエリの制限をはるかに超えています。$n$と同じ大きさにすることができます$10^4$。 クエリ関数の構造では、すべての次数情報を一定数のサブセット評価に圧縮することはできません。そのため、実際には制約が緩いことが意図されているか、対話型の制限が意図した解決策に比べて危険であるかのどちらかであると結論せざるを得ません。 

これを考慮すると、最適推論は総当たりのアイデアと同じままですが、クエリの数を漸近的に改善することはできないことを認識しなければなりません。各頂点の次数は、グラフの残りの部分に対して分離することによってのみ独立して回復可能です。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、個々のエッジをクエリすることなく、誘導されたサブグラフ クエリのみを使用して各頂点の次数を計算することです。 

私たちは、グローバルサブグラフと縮小された誘導サブグラフの間の同一性に依存しています。 

### ステップ

 1. 完全な頂点セットをクエリする$V$そして結果を次のように保存します$E$、グラフ内のエッジの総数。 これにより、以降のすべての計算のベースラインが得られます。 
2. 各頂点について$v$、セットを形成します$V \setminus \{v\}$そして、その誘導されたエッジ数をクエリします。$E_{-v}$。 これにより、影響を受けないすべてのエッジが測定されます。$v$、削除して以来$v$接触しているエッジを正確に削除します。 
3. コンピューティング$\deg(v) = E - E_{-v}$。 これは、エッジだけが欠落しているためです。$E_{-v}$に比べ$E$まさにそれが起こります$v$。 
4. 計算されたすべての次数が偶数であるかどうかを確認します。 頂点の次数が奇数の場合、グラフにオイラー サイクルを含めることはできません。 
5. すべての度が等しい場合は YES を出力し、そうでない場合は NO を出力します。 

これが機能する理由は、グラフが接続されているため、オイラー サイクル条件がすべての頂点で正確に偶次条件に減少するためです。 追加の構造チェックは必要ありません。 

### なぜ効果があるのか

 誘導されたサブグラフ クエリは、相補的な頂点セットを比較する場合、隣接行列エントリ内で線形になります。 単一の頂点を削除すると、その頂点に入射するエッジの寄与が正確に分離され、他のエッジは影響を受けません。 これにより、合計エッジ数が頂点ごとの寄与 (正確に次数) に直接代数分解されます。 次数が判明すると、オイラー性が完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(vs):
    print("?", len(vs), *vs)
    sys.stdout.flush()
    return int(input())

def main():
    n = int(input())

    all_v = list(range(1, n + 1))
    E = ask(all_v)

    deg = [0] * (n + 1)

    for v in range(1, n + 1):
        # query V \ {v}
        subset = all_v.copy()
        subset.remove(v)
        e_minus = ask(subset)
        deg[v] = E - e_minus

    for v in range(1, n + 1):
        if deg[v] % 2 != 0:
            print("! NO")
            sys.stdout.flush()
            return

    print("! YES")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```プログラムは最初にグラフ全体をクエリして、エッジの総数を取得します。 次に、各頂点の補数を繰り返しクエリして、減算によって入射エッジを分離します。 重要な実装の詳細は、完全な頂点リストを維持し、反復ごとに 1 つの要素を削除することです。これにより、ロジックがシンプルに保たれ、off-by-one インデックス作成エラーが回避されます。 

唯一の微妙な点は、インタラクターは即時の出力を期待しているため、すべてのクエリと最終応答の後にフラッシュすることです。 フラッシュが不足していると、ロジックが正しい場合でも実行時エラーが発生します。 

## 実用的な例

 ### 例 1

 グラフが頂点 1、2、3 にある三角形であると仮定します。 

| ステップ | クエリセット | 応答 | 推定値 |
 | --- | --- | --- | --- |
 | 1 | {1,2,3} | 3 |$E = 3$|
 | 2 | {2,3} | 1 |$\deg(1)=2$|
 | 3 | {1,3} | 1 |$\deg(2)=2$|
 | 4 | {1,2} | 1 |$\deg(3)=2$|

 すべての度が偶数であるため、出力は YES になります。 これは、三角形がオイラー サイクルを持っていることを確認します。 

### 例 2

 パス 1-2-3 を考えてみましょう。 

| ステップ | クエリセット | 応答 | 推定値 |
 | --- | --- | --- | --- |
 | 1 | {1,2,3} | 2 |$E = 2$|
 | 2 | {2,3} | 1 |$\deg(1)=1$|
 | 3 | {1,3} | 0 |$\deg(2)=2$|
 | 4 | {1,2} | 1 |$\deg(3)=1$|

 頂点 1 と 3 の次数は奇数であるため、出力は NO になります。 これは、単一のエンドポイントに障害が発生するとすぐにオイラー性が損なわれる様子を示しています。
