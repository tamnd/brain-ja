 ## 解決策
 ## 問題の理解

 正の整数の円形配列が与えられ、円内の隣接するペアごとに、それらの数値が等しいかどうかがわかります。 入力はこの情報を文字列として提供します`s`文字の`E`そして`N`、 どこ`E`2 つの隣接する値が等しい必要があることを示し、`N`は、それらが異なる必要があることを示します。 課題は、これらすべての等式と不等式を満たす実際の数値を配列に割り当てることが可能かどうかを判断することです。 配列を構築する必要はなく、テスト ケースごとに YES または NO で答えるだけで済みます。 

制約は小さく、配列の長さです。`n`範囲は 2 ～ 50、テスト ケースは最大 1000 個まであります。 以来`n`が小さい場合は、すべてのペアを検査するか、テスト ケースごとに複数の線形パスを実行するアルゴリズムが許容されます。 最も難しいのは、循環構造における等価性の連鎖について推論することです。`E`制約は複数の要素に伝播し、`N`制約がこれらのチェーンと矛盾する場合、制約は競合を引き起こします。 

すべての関係が次の場合に重要なエッジケースが発生します。`N`。 たとえば、`n = 3`そして`s = NNN`、各要素は隣接する要素とは異なっていなければなりません。 これは不可能です。なぜなら、円は閉じており、最後の要素を満たすためには、ある要素が別の要素と等しくなる必要があるからです。`N`。 不用意に実装すると、循環クロージャが無視され、誤って YES が出力される可能性があります。 1 つしかない場合には、別の微妙なケースが発生します。`N`に囲まれて`E`s:`E`チェーンは要素を吸収できますが、単一のチェーンでは`N`境界で避けられない紛争が発生する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、ある大きな限界 (10^9 など) までの可能な数値の割り当てをすべて試行することです。 割り当てごとに、`E`マッチとすべて`N`異なります。 これは正しいですが、非現実的です。`n = 50`、要素ごとに 2 つの値を試す場合でも、2^50 の代入が必要となり、実行可能な計算をはるかに超えています。 

最適なアプローチでは、問題を 2 つの可能な値の建設的な割り当てとして扱います。 各要素にラベルを割り当てて、円に沿って等価制約を伝播できます。 2 つの要素が次のように接続されている場合`E`、同じラベルを共有する必要があります。 で接続した場合`N`、それらは異なるはずです。 重要な洞察は、必要なラベルは 2 つだけであるということです。`N`制約では、2 つのエンドポイントが異なることのみが必要です。 文字列の場合`s`完全にから成る`E`s、すべての要素に同じ値を割り当てることができます。 それ以外の場合は、どのような取り決めでも、`N`少なくとも 1 つ存在する限り、解決できます。`N`そしてその時点から連鎖が始まる可能性があります。 唯一不可能なケースは次のような場合です`n = 3`3 つの制約はすべて次のとおりです。`N`または、サイズ 3 の円内のすべての要素が隣接するすべての要素と異なっていなければならないその他のパターン。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 建設的な 2 つのラベル | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`各テスト ケースを繰り返します。 各テスト ケースは文字列を提供します`s`長さの`n`。 
2. もし`s`のみが含まれます`E`s、すぐに YES を出力します。 円内のすべての要素に同じ番号を割り当てることができるため、これは有効です。 
3. 他の文字列については、次の場合に特殊な不可能なケースがないかどうかを確認します。`n = 3`そしてすべてのキャラクターは`N`。 この状況では、各要素は隣接する要素と異なる必要がありますが、長さ 3 の円ではこれは不可能です。 
4. 他のすべての場合は、2 つの異なる数値を最初の番号から交互に割り当てることで、有効な割り当てを構築できます。`N`制約。 隣接するものが等しい必要がある場合は、同じラベルを伝播します。 隣接するものが異なる必要がある場合は、ラベルを切り替えます。 
5. 実現可能性を判断するだけでよく、配列を明示的に構築する必要はないため、不可能な 3 要素の全 N ケースが回避されれば、YES と結論付けることができます。 
6. 不可能な場合には NO を出力し、それ以外の場合には YES を出力します。 

機能する理由: 等式を連結成分として扱い、差を成分間の制約として扱うことにより、少なくとも 1 つの等価または差を持つ 3 より大きい長さの文字列は、2 つの異なる数値で満たされることがわかります。 等式の伝播により、`E`は一貫しており、2 つのラベルを反転することで差異を埋めることができます。 このアルゴリズムは、3 要素の循環オール N 競合を明示的に処理するため、偽の YES を生成することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)
        if s.count('E') == n:
            print("YES")
        elif n == 3 and s == "NNN":
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```最初のセクションでは入力を読み取り、テスト ケースを繰り返します。 チェック中`s.count('E') == n`は、すべてが等しい場合を効率的に処理します。 特別なチェック`n == 3 and s == "NNN"`は、すべての近傍が異なる必要がある最小円の唯一不可能な配置を示しています。 他のすべての調整は自動的に実行可能であるため、YES と出力します。 文字列の長さが入力から直接使用されるため、境界処理は自動的に行われます。また、円の閉包は、明示的にチェックする不可能なパターンにのみ関連します。

 ## 特殊なケース

 入力用`NNN`、アルゴリズムがチェックします`n == 3 and s == "NNN"`そして NO を出力し、不可能なケースを正しく処理します。 長さ 50 の文字列の場合、すべて`E`つまり、カウントチェックがトリガーされ、YES が出力されます。 交互用`N`そして`E`の場合、50 要素の円は交互に割り当てられた 2 つの数値で満足できるため、アルゴリズムは YES を出力し、伝播不変条件が成り立つことが確認されます。 すべての境界ケース`n = 2`の任意の構成と同様に簡単に処理されます。`E`または`N`実現可能です。
