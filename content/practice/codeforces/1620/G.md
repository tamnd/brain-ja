 ## 解決策
 ## 問題の理解

 最大 23 個の文字列が与えられます。 各文字列は文字ごとにグループ化されているという意味ですでに「ソート」されているため、ランレングスエンコーディングのように見えます。`'a'..'z'`、 例えば`"aaabccczzz"`。 

次に、これらの文字列のサブセットを考えてみましょう。 そのサブセットについては、選択した各文字列の考えられるすべてのサブシーケンスを調べ、サブセット内のすべての文字列の和集合を取得します。 これにより、サブセット内の少なくとも 1 つの文字列のサブシーケンスとして形成できる一連の個別の文字列 (空の文字列を含む) が得られます。 この共用体のサイズは関数です$f$。 

評価しなければなりません$f$入力文字列のサブセットごとに。 まであります$2^{23} \approx 8 \cdot 10^6$サブセットなので、サブセットを反復しても問題ありません。 難しいのは計算です$f$各文字列の長さは最大で次のとおりであるため、サブセットごとにすばやく処理できます。$2 \cdot 10^4$、そして単純に部分列を数えると長さは指数関数的になります。 

最後に、すべての値を出力する代わりに、各サブセットは重み付けされた値を提供します。$f$サブセットのサイズとサブセット内のインデックスの合計によって計算し、すべての結果を XOR します。 

主要な構造は、各文字列の文字が単調であることです。これにより、サブシーケンスが大きく制約されます。 

主なエッジケースは、何が結合されているかの誤解から生じます。 よくある間違いは、文字列の結合ではなく、連結された文字列のサブシーケンスを扱うことです。 もう 1 つは、各文字列内の順序制約を考慮せずに、文字間の独立性を仮定することです。 

微妙な失敗例としては、2 つの文字列がサブシーケンスで重なっている場合が挙げられます。二重カウントが正しくありません。 

たとえば、1 つの文字列が`"ab"`そしてもう一つは`"aab"`、2 番目の部分列のセットには最初の部分列のセットが厳密に含まれるため、単純な合計は過大評価になります。 

本当の課題は、サブセット全体のサブシーケンス セットの和集合のサイズをカウントしていることです。これは、文字列に対する包含-除外またはビットマスク DP を示唆しています。 

## アプローチ

 直接解釈すると、文字列のサブセットごとに、各文字列のすべてのサブシーケンスを明示的に列挙し、それらをマージします。 単一の長さの文字列$L$すでに持っています$2^L$サブシーケンスなので、1 つの文字列であってもこれは不可能です。 

各文字列を文字数で圧縮したとしても、サブシーケンスの数は実行数の組み合わせに依存します。 

重要な観察点は、各文字列が文字ごとにソートされているため、すべてのサブシーケンスは各文字から取得した文字数によって完全に決定され、文字ごとの順序が維持されるということです。 これは、各文字列が単調言語を定義することを意味します。つまり、文字数が接頭辞の一貫性の制約を超えないすべての文字列です。 

サブシーケンスという観点から明示的に考える代わりに、視点を逆転させます。つまり、考えられるすべてのサブシーケンス文字列です。$x$「それを生成できるサブセット内の最初の文字列」があります。 したがって、固定サブセットの場合、$f$共用体のサイズです。すべての文字列を合計することで計算できます。$x$少なくとも 1 つであるかどうか$s_i$含まれています$x$続編として。 

そこで、量指定子を切り替えます。文字列のサブセットを反復してサブシーケンスを数える代わりに、候補サブシーケンスを反復して、それらが出現するサブセットの数をカウントします。 これは古典的な「オブジェクトを合計し、それらをカバーするサブセットを数える」です。 

さて、重要な構造は次のとおりです。$n \le 23$、文字列に対してサブセット DP を実行できますが、文字列のすべてのサブシーケンスに対して反復処理を行うことは避ける必要があります。 代わりに、各文字列に対する「貪欲な一致プロファイル」によってサブシーケンスを特徴付けます。 

各文字列はソートされているため、サブシーケンスは各文字の文字数の選択によって完全に決定されますが、さらに重要なのは、ターゲットのサブシーケンスを修正する場合、それが文字列内に存在するかどうかを確認するのは線形スキャンであることです。 これは、役割を再び反転することを示唆しています。サブシーケンスをまったく列挙すべきではありません。 

この問題の標準的なトリックは、文字列のサブセットに対する包含-除外を使用して、文字列のマルチセット結合に存在する個別のサブシーケンスの数をカウントする 26 文字にわたる DP をサブセットごとに計算することです。 ただし、23 品目以上の包含・除外は可能です。 

固定サブセットの定義$S$、補数アプローチ: 部分列の和集合は、少なくとも 1 つの部分列であるすべての文字列と等しくなります。$s_i$。 補数は、いずれの部分列でもない文字列です。 直接カウントする代わりに、文字列サブセットに対する Möbius を介してサブセットごとの寄与を計算します。 

文字列のすべてのサブセットについて、そのサブセット内のすべての文字列に共通のサブシーケンス (つまり、サブシーケンス セットの共通部分) の数を表す DP を事前計算します。 次に、文字列に対する包含と除外によって、共用体サイズを回復できます。 

させて$g(T)$すべての文字列の部分列である文字列の数になります。$T$。 次に、固定サブセットの場合$S$、結合サイズは次のとおりです。$$f(S) = \sum_{T \subseteq S, T \neq \emptyset} (-1)^{|T|+1} g(T)$$だから必要なのです$g(T)$みんなのために$T \subseteq [n]$。 これはコンピューティングであれば実現可能です$g(T)$速いです。 

今、$g(T)$内のすべての文字列の部分列である文字列の数です。$T$、それらの交差オートマトンのサブシーケンスと同等です。 文字列はソートされているため、それぞれについて事前計算できます。$T$文字に対する制約のマージされた構造。文字列全体の最小可用性と等しい容量を持つ 26 文字以上の DP に削減されます。

 ## アルゴリズムのチュートリアル

 1. 各文字列を 26 次元の圧縮形式に前処理し、文字ごとのカウントのみを保持します。 文字列はソートされているため、この表現はサブシーケンスの実現可能性に関連するすべての制約を捕捉します。 
2. 文字列のサブセットを指定して、サブセット内のすべての文字列にわたってどのサブシーケンスが有効であるかの交差構造を計算する関数を定義します。 これは、文字の利用可能性を座標的に最小にすることによって行われます。 
3. サブセットごとに$T$、交差制約の下で形成できる個別のサブシーケンスの数をカウントする、アルファベット状態に対する DP を計算します。 これにより、$g(T)$、内のすべての文字列の部分列である文字列の数$T$。 
4.変換$g(T)$の中へ$f(S)$すべてのサブセットに対して$S$サブマスクに対する包含/除外の使用。 サブセットごとに$S$、すべてのサブマスクを反復処理します。$T \subseteq S$、パリティに応じて符号が交互に変化します。$|T|$の貢献を蓄積し、$g(T)$。 
5. サブセットごとに$S$、その重みを次のように計算します。$|S| \cdot \sum i$と乗算します$f(S)$。 結果を XOR して最終的な答えにします。 

### なぜ効果があるのか

 中心的な不変条件は、部分列が文字列間の交差の下で閉じた集合系を形成するということです。文字列は、各文字列に対して独立して有効である場合にのみ、部分集合に対して有効です。 これにより、文字列に対する結合が、その有効性述語に対する包含/除外に変換されます。 有効性はソートされた文字列のアルファベット制約に基づいて分解されるため、文字に関する DP は各交差状態で実行可能なすべてのサブシーケンスを正確にカウントします。 次に、包含/除外ステップにより、サブシーケンスごとに 1 回だけユニオン カーディナリティが再構築され、重複する文字列にわたって過剰カウントが発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def popcount(x):
    return x.bit_count()

def solve():
    n = int(input())
    s = [input().strip() for _ in range(n)]

    # Precompute letter counts per string (compressed structure)
    cnt = [[0]*26 for _ in range(n)]
    for i in range(n):
        for c in s[i]:
            cnt[i][ord(c)-97] += 1

    size = 1 << n

    # intersection constraints per subset
    min_cnt = [None] * size
    min_cnt[0] = [10**18]*26

    for mask in range(1, size):
        b = (mask & -mask).bit_length() - 1
        prev = mask ^ (1 << b)
        if prev == 0:
            min_cnt[mask] = cnt[b][:]
        else:
            arr = [0]*26
            for c in range(26):
                arr[c] = min(min_cnt[prev][c], cnt[b][c])
            min_cnt[mask] = arr

    # DP over subsets: compute g[mask]
    # number of subsequences common to all strings in mask
    g = [0] * size
    g[0] = 1

    for mask in range(1, size):
        arr = min_cnt[mask]

        dp = 1
        for c in range(26):
            dp = dp * (arr[c] + 1) % MOD

        g[mask] = dp

    # compute f via inclusion-exclusion over subsets
    f = [0] * size
    for mask in range(1, size):
        sub = mask
        res = 0
        while sub:
            sign = 1 if (popcount(sub) % 2 == 1) else -1
            res = (res + sign * g[sub]) % MOD
            sub = (sub - 1) & mask
        f[mask] = res % MOD

    ans = 0
    for mask in range(1, size):
        k = popcount(mask)
        idx_sum = 0
        for i in range(n):
            if mask & (1 << i):
                idx_sum += i + 1
        w = k * idx_sum

        ans ^= (f[mask] * w) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この問題構造では各文字列内の順序はサブシーケンスの実現可能性に無関係であるため、実装ではまず各文字列を文字の頻度に圧縮します。 次に、交差制約を表すサブセット最小値を構築します。 値$g(mask)$制約が固定されると各文字が独立して寄与するため、文字に対する単純な積 DP として計算されます。 

サブマスクに対する包含/除外ループは、和集合と交差の間の標準的な同一性に依存して、和集合サイズを正確に再構築します。 最後に、重み付き XOR 累積がステートメントから直接続きます。 

最もデリケートな部分は、符号ミスがあると XOR 集合体が直接破損するため、サブセットの反復が正しいパリティ処理で行われるようにすることです。

 ## 特殊なケース

 重要なエッジケースは、次のように、ある文字列がサブシーケンス内で別の文字列を完全に支配する場合です。`"a"`そして`"aa"`。 素朴なアプローチでは、両方が存在する場合、サブシーケンスを二重にカウントします。 このソリューションでは、交差最小値により共有サブシーケンス空間が重複しないことが保証され、包含-除外により過剰カウントが排除されます。 

もう 1 つの特殊なケースは、多数の同一の文字列です。 サブセットが異なっていても、交差構造は同一のままであるため、すべて$g(mask)$適当に潰す。 包含/除外ステップでは、文字列の ID ではなくセットの ID に基づいて動作するため、サブセットごとに正しい共用体サイズが得られます。 

最後に、シングルトン サブセットは常に正確性アンカーとして機能します。単一の文字列に対して、$f$サブシーケンスの数に空の文字列を加えたものと等しくなければなりません。これは、文字の容量を超える積 DP によって正確に適用されます。
