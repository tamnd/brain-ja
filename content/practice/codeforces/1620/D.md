 ## 解決策
 ## 問題の理解

 店でチップスのどの袋を選んでも、金種 1、2、および 3 のコインだけを使用して正確な価格を支払うことができるように、事前にコインを準備するように求められます。各テスト ケースの入力により、フレーバーの数と各フレーバーのコストが得られます。 出力は、これらの価格をカバーするために持ち運ぶ必要があるコインの最小総数を表す単一の数値である必要があります。 

コストは非常に高額になる可能性があり、$10^9$、テスト ケースごとに最大 100 個のフレーバーを使用でき、テスト ケースは 1000 個あります。 これにより、考えられる価格ごとにコインのすべての組み合わせを列挙しようとするアプローチは除外されます。 実際の合計を抽象化し、コインの額面を法とした剰余に焦点を当てる戦略が必要です。 

すべての価格が 3 を法として一致する場合、重要なエッジ ケースが発生します。たとえば、すべての価格が 3 で割り切れる場合、1 または 2 のコインを持ち運ぶ必要はありません。 逆に、ある価格が余り 1 を残し、別の価格が 3 を法として 2 余りを残す場合、両方の余りを満たすためにコインを運ぶ必要があります。 もう 1 つの微妙なエッジ ケースは、価格が 1 または 2 など小さい場合で、貪欲なアプローチにより必要なコインの数が過大評価される可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての価格に対して 1、2、および 3 コインの可能なすべての組み合わせを試し、最小の合計を選択します。 原理的には最小ベクトルを見つけることができるので、これは機能します。$(c_1, c_2, c_3)$各価格を満たすコインの数。 ただし、最も大きなコストがかかるのは、$10^9$したがって、考えられる合計額ごとにコインを列挙することは不可能です。 フレーバーごとにコインを 100 枚に制限する場合でも、$O(100 \cdot 10^9)$明らかに不可能な操作です。 

洞察は、問題を法 3 で調べることで得られます。任意の数値は次のように表すことができます。$3 \cdot x + r$、 どこ$r$は 0、1、または 2 です。最大商がわかっている場合$x$3 の倍数が必要で、価格にどの剰余が現れるかがわかっているので、3 価値コインの最大数と残りをカバーするコインを加算することで、必要な最小限のコインを決定できます。 コインの種類は 3 つだけで、必要なだけ持ち運べるので、問題は残りの組み合わせの少数のセットのみをチェックするだけで済みます。 複雑さは、価格自体のサイズではなく、価格の数において線形になります。

 ## アルゴリズムのチュートリアル

 1. 必要な各金種のコインの最大数に応じてカウンターを初期化します。`max3`、`max2`、`max1`。 
2. 各価格について、貪欲に取得できる価値 3 のコインの数を計算します。`c3 = price // 3`。 剰余を計算する`r = price % 3`。 
3. すべての価格にわたって、r=1 および r=2 で観察された最大剰余を追跡します。 させて`max1 = 1`いずれかの価格が 1 残っている場合、`max2 = 1`価格が残っている場合 2.
 4. 3 の倍数の最大商を追跡します。`max3 = max(price // 3 for all prices)`。 
5. 残りのコインの組み合わせを検討します: 追加`max1`1のコインと`max2`2からのコイン`max3 * 3`すべての価格をカバーします。 ただし、価格によってはこれを調整する必要がある場合があります。たとえば、2 の価格は 2 の 0 コインでは支払うことができないため、少なくとも少なくとも 2 コインを運ぶようにしてください。`max2`コイン2。残り1についても同様です。 
6.最後に戻ります`max3 + max1 + max2`必要な最小コインの合計として。 これが機能するのは、3 の倍数を最大にすることで各価格の最大部分を確実にカバーでき、残りのコインで最後の 1 または 2 ユニットをカバーできるからです。 

なぜ機能するのか: 不変条件は、どんな価格も次のように表すことができるということです。`3*c3 + c2*2 + c1*1`いくつかの整数の場合`c3, c2, c1`。 最大限を取ることで`c3`すべての価格のうち、3 つの値の部分が常に十分であることを保証します。 3 を法とする剰余は 0、1、または 2 のみであるため、どの剰余が現れるかを追跡することで、1 および/または 2 の最大 1 枚のコインを追加するだけですべてのケースがカバーされることが保証されます。 どの価格も、最小性が保証される最大 3 の倍数を超えて、1 または 2 のコインを複数必要とすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_coins_needed(prices):
    # track maximum quotient by 3 and remainder presence
    max_quotient = 0
    need1 = 0
    need2 = 0
    for price in prices:
        q, r = divmod(price, 3)
        max_quotient = max(max_quotient, q)
        if r == 1:
            need1 = 1
        elif r == 2:
            need2 = 1
    return max_quotient + need1 + need2

t = int(input())
for _ in range(t):
    n = int(input())
    prices = list(map(int, input().split()))
    print(min_coins_needed(prices))
```機能`min_coins_needed`アルゴリズムをキャプチャします。 各価格を反復処理し、3 の倍数と残りに分割します。 剰余 1 または 2 が発生するかどうかを追跡し、最大商を維持します。 最後に、最大商と剰余 1 と 2 のインジケーターの合計により、必要な最小限のコインが得られます。 使用する`divmod`手動による除算と剰余の計算を回避します。 価格が 1 または 2 に等しいなどのエッジケースは、設定に従って自然に処理されます。`need1`または`need2`1に。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        prices = list(map(int, input().split()))
        out.append(str(min_coins_needed(prices)))
    return "\n".join(out)
