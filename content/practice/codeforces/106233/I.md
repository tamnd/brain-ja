 ## 解決策
 ## 問題の理解

 平面上に一連のマジック マークが配置されています。 の`i`- 番目のマークには座標があります`(xi, yi)`。 トリックでは、連続するマークのセグメントを選択し、そのセグメント内のすべてのマークを、指定された点を中心に時計回りに 90 度、180 度、または 270 度回転させます。 すべてのトリックの後、すべてのマークを含む軸に沿った最小の長方形の領域が必要になります。 

課題は、操作が点のセット全体ではなく、配列内の位置に対して行われることです。 マークは何度も移動する可能性があり、将来の操作のセグメント エンドポイントは元のインデックス付けに依存します。 更新のたびにすべてのマークの座標を保持し、グローバルな最小値と最大値の x 値と y 値をすばやく見つける必要があります。 

制約により、最大で`2 * 10^5`マークと`2 * 10^5`回転。 選択した間隔ですべてのマークを移動する直接シミュレーションには、最大で`O(nq)`周囲に影響を与える可能性のある操作`4 * 10^10`座標が変化し、数秒の許容範囲をはるかに超えています。 この解決策では、各演算を対数に近づける必要があります。 

難しいケースは、回転自体ではなく、時間の経過とともに変換を正しく維持することです。 セグメントは何度も回転でき、さまざまな中心を中心にして回転できます。 たとえば、単一の点が 2 回回転される場合、2 回目の回転では、その点のすでに変更されている位置を使用する必要があります。 

入力の場合:```
1 1
5 7
1 1 0 0 90
```要点`(5,7)`になる`(-7,5)`, したがって、外接する四角形の面積はゼロになります。 幅と高さのみを保存する不用意な実装は、絶対位置を失い、失敗します。 

別のケースは次のとおりです。```
2 1
0 0
10 1
1 2 5 5 180
```両方の点が回転します`(5,5)`そしてなる`(10,10)`そして`(0,9)`。 答えは`90`。 セグメントの中心のみを回転するか、平行移動を処理せずに座標のみを交換するソリューションでは、間違った四角形が生成されます。 

## アプローチ

 簡単な解決策は、すべてのポイントを明示的に保存することです。 クエリごとに、以下を繰り返します。`l`に`r`、すべての点を回転し、グローバル最小値と最大値の座標を更新します。 すべての点が常に実際の現在の位置に保たれるため、これは正しいです。 この問題は間隔が大きい場合に発生します。 最悪の場合、すべてのクエリがすべてのクエリに影響を及ぼします。`n`ポイントがあるため、複雑さは次のようになります`O(nq)`。 

有益な観察は、長方形はその内部のすべての点を知る必要がないということです。 点のセットの場合、その境界ボックスは、最小 x、最大 x、最小 y、および最大 y の 4 つの値によって完全に決定されます。 セグメント全体のこれら 4 つの値を一度に更新できれば、問題ははるかに小さくなります。 

点の周りの回転はアフィン変換です。 次の形式の式を使用して座標を変更します。```
x' = a*x + b*y + c
y' = d*x + e*y + f
```ここで使用される 4 つの可能な回転は、符号と座標を交換するだけです。 このような変換を境界ボックスに適用する場合、アフィン変換は軸に沿った長方形の極値の点を極値の候補にマッピングするため、ボックスの 4 隅をチェックするだけで済みます。 

これは自然にセグメント ツリーにつながります。 各ノードは、その間隔の境界ボックスと、子に渡されるのを待っている遅延アフィン変換を保存します。 ノード全体がクエリによってカバーされる場合、すべてのポイントを訪問するのではなく、格納されている四角形を変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 遅延変換を使用したセグメント ツリー | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のマークの順序に基づいてセグメント ツリーを構築します。 すべてのノードについて、この間隔内のすべてのポイントの x 値と y 値の最小値と最大値を保存します。 最初は、すべての遅延変換は恒等変換です。 
2. すべての回転をアフィン変換として表します。 時計回りに90度回転させる場合`(x0, y0)`、式は次のとおりです。```
x' = y0 - y + x0
y' = x - x0 + y0
```180 度の場合と 270 度の場合は同じ表現で処理されます。 

1. 更新がセグメント ツリー ノードを完全にカバーする場合、回転をノードの境界ボックスに直接適用します。 四隅を変形し、新しい最小値と最大値の座標を見つけて保存します。 
2. 新しい変換をノードの既存の遅延変換と組み合わせます。 新しい変換は最新の変更を表すため、以前の保留中の変換の後に適用する必要があります。 
3. 部分的にカバーされたノードにアクセスすると、その遅延変換を両方の子にプッシュします。 これにより、再帰を続行する前に子情報の同期が維持されます。 
4. 各更新の後、ルートにはすべてのマークの境界ボックスが含まれるため、その幅と高さによって答えが得られます。```
(max_x - min_x) * (max_y - min_y)
```これが機能する理由: セグメント ツリーの不変条件は、すべてのノードがその区間内のすべてのポイントの現在位置の正確な境界ボックスを、子に伝播する必要がある変換とともに格納することです。 区間内のすべての点が同じアフィン変換を受けるため、区間全体に回転を適用するのは安全です。 変換された長方形の角には変換された極値が含まれるため、更新された境界ボックスは正確になります。 遅延変換を組み合わせると、将来の操作でも同じ意味が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compose(t2, t1):
    a2, b2, c2, d2, e2, f2 = t2
    a1, b1, c1, d1, e1, f1 = t1
    return (
        a2 * a1 + b2 * d1,
        a2 * b1 + b2 * e1,
        a2 * c1 + b2 * f1 + c2,
        d2 * a1 + e2 * d1,
        d2 * b1 + e2 * e1,
        d2 * c1 + e2 * f1 + f2,
    )

def apply_transform(node, t):
    a, b, c, d, e, f = t
    mnx, mxx, mny, mxy = node[:4]

    xs = []
    ys = []
    for x, y in ((mnx, mny), (mnx, mxy), (mxx, mny), (mxx, mxy)):
        xs.append(a * x + b * y + c)
        ys.append(d * x + e * y + f)

    node[0] = min(xs)
    node[1] = max(xs)
    node[2] = min(ys)
    node[3] = max(ys)

    node[4] = compose(t, node[4])

def build(v, l, r, pts, tree):
    if l == r:
        x, y = pts[l]
        tree[v] = [x, x, y, y, (1, 0, 0, 0, 1, 0)]
        return
    m = (l + r) // 2
    build(v * 2, l, m, pts, tree)
    build(v * 2 + 1, m + 1, r, pts, tree)
    pull(v, tree)

def pull(v, tree):
    left = tree[v * 2]
    right = tree[v * 2 + 1]
    tree[v][0] = min(left[0], right[0])
    tree[v][1] = max(left[1], right[1])
    tree[v][2] = min(left[2], right[2])
    tree[v][3] = max(left[3], right[3])

def push(v, tree):
    t = tree[v][4]
    if t != (1, 0, 0, 0, 1, 0):
        apply_transform(tree[v * 2], t)
        apply_transform(tree[v * 2 + 1], t)
        tree[v][4] = (1, 0, 0, 0, 1, 0)

def update(v, l, r, ql, qr, t, tree):
    if ql <= l and r <= qr:
        apply_transform(tree[v], t)
        return
    push(v, tree)
    m = (l + r) // 2
    if ql <= m:
        update(v * 2, l, m, ql, qr, t, tree)
    if qr > m:
        update(v * 2 + 1, m + 1, r, ql, qr, t, tree)
    pull(v, tree)

def rotation(x, y, a):
    if a == 90:
        return (0, -1, x + y, 1, 0, y - x)
    if a == 180:
        return (-1, 0, 2 * x, 0, -1, 2 * y)
    return (0, 1, x - y, -1, 0, x + y)

def solve():
    n, q = map(int, input().split())
    pts = [None] + [tuple(map(int, input().split())) for _ in range(n)]

    tree = [[0, 0, 0, 0, (1, 0, 0, 0, 1, 0)] for _ in range(4 * n + 5)]
    build(1, 1, n, pts, tree)

    ans = []
    for _ in range(q):
        l, r, x, y, a = map(int, input().split())
        update(1, 1, n, l, r, rotation(x, y, a), tree)
        ans.append(str((tree[1][1] - tree[1][0]) * (tree[1][3] - tree[1][2])))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ツリーには 4 つの座標と 1 つの保留中の変換が保存されます。 の`apply_transform`機能はソリューションの中核です。 4 つの角すべてを変換して外接する四角形を更新し、その後の伝播のために構成された変換を保存します。 

作曲順は最も間違いやすい場所です。 ノードがすでに変換されている場合`old`、そして新しいローテーション`new`到着すると、結果として生じる変換は次のようになります。`new(old(point))`、したがって、次の乗算順序は`compose`その方向に従います。 

再帰では、通常のセグメント ツリー間隔ロジックが使用されます。 完全なカバレッジでは変換がすぐに適用されますが、部分的なカバレッジでは子を訪問する前に保留中の操作がプッシュされます。 ここでは Python 整数はオーバーフローしません。回転中に座標が増加する可能性があるため、これは便利です。

 ## 特殊なケース

 単一点の場合:```
1 1
5 7
1 1 0 0 90
```セグメント ツリーの葉には正確な点が保存されます。 回転変換により、保存された最小座標と最大座標が新しい点の位置に変更されます。 ルートの x 値と y 値は等しいため、面積はゼロになります。 

任意の中心を中心とした回転の場合:```
2 1
0 0
10 1
1 2 5 5 180
```ルート長方形は直接変換されます。 古い長方形の 4 つの角が新しい長方形の角の候補になります。 アルゴリズムは x 範囲を取得します`[0,10]`と y 範囲`[9,10]`、エリアを与える`90`。 

変換を繰り返す場合:```
3 2
1 1
2 2
3 3
1 2 0 0 180
2 3 10 10 270
```最初の更新では、最初の 2 つの位置で保留中の 180 度の回転が保存されます。 2 回目の更新中に、ツリーは下降する前にこの変換をプッシュするため、2 回目の回転はすでに回転された座標に適用されます。 これにより、すべてのマークの実際の現在の状態が保存されます。
