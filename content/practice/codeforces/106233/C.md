 ## 解決策
 ## 問題の理解

 限られた量の生地と数種類の具材を用意したパン屋があります。 特定の餡のパンは、ある程度の量の生地とその餡をある程度消費し、一定の利益をもたらします。 パン屋は生地だけを消費するプレーンなパンを作ることもできます。 タスクは、合計利益ができるだけ大きくなるように、各種類のパンを何個焼くかを選択することです。 

入力には、利用可能な生地、餡の種類の数、プレーン パンのコストと利益、および各餡の種類ごとに、利用可能な餡の量、バンズごとに必要なフィリングの量、バンズごとに必要な生地、および利益が記述されます。 アウトプットは、獲得できる最大の金額です。 

生地の制限は最大 1000 であり、これによって問題についての考え方が変わります。 生地の残量を指標とした状態は、維持できるほど少ない状態です。 充填タイプの数も最大 10 個と少ないため、各タイプを個別に処理することが可能です。 すべてのフィリングの種類に対して可能な限りの数のバンズを試すソリューションでは、組み合わせが増えるため急速に大きくなりすぎますが、O(m * n * 小さい値) に近いソリューションは快適です。 

よくある間違いは、生地 1 グラムあたりの利益が最も高いフィリングだけを選択することです。 詰め物も限られたリソースであるため、これは失敗します。 たとえば、次のことを考えてみましょう。```
10 2 2 1
7 3 2 100
12 3 1 10
```一番良い選択は、最初の詰め物だけを使い切らないことです。 正しい答えは、`241`、最初のタイプのバンズを 2 つ、2 つ目のタイプのバンズを 4 つ、プレーンのバンズを 1 つ使用します。 欲張って比率を選択すると、貴重な生地が未使用のままになる可能性があります。 

もう 1 つのエッジケースは、餡が存在するものの、プレーンなバンズと比べて使用する価値がない場合です。 例えば：```
100 1 25 50
15 5 20 10
```正しい出力は次のとおりです。```
200
```不注意な解決策では、入手可能なフィリングに生地を費やしてしまう可能性がありますが、プレーンなバンズを 4 つ使用した方がより多くの利益が得られます。 

3 番目のエッジケースは、餡の量がパン 1 個に必要な量で割り切れない場合です。 例えば：```
5 1 3 10
4 3 2 100
```リソースが限られているため、中身の入ったパンは 1 つしか作ることができません。 残った詰め物は使用できません。 正しい出力は次のとおりです`110`、中身の入ったパンが 1 つとプレーンのパンが 1 つです。 生地の制限をチェックするだけのループでは、答えが過大評価される可能性があります。 

## アプローチ

 直接的な強引なアイデアは、各フィリングの種類ごとにいくつのバンズを作るかを決定することです。 タイプごとに、ゼロから詰め物と生地で許可される数まで、考えられるすべてのカウントを試します。 すべてのフィリングの選択を決定した後、残りの生地はプレーンバンズに変換されます。 考えられるあらゆるベーキング計画が考慮されているため、これは正しいです。 

問題は組み合わせの数です。 それぞれの充填タイプだけでは選択肢の数は限られていますが、10 種類を組み合わせると大きな検索スペースが生まれます。 すべてのタイプで約 100 個の選択肢が許可されている場合、ブルート フォースは次の選択肢を探索することになります。`100^10`組み合わせ、それは不可能です。 

有益な観察は、すべての種類のパンで共有される唯一のリソースは生地であるということです。 充填リソースは、現在の充填タイプにのみ影響します。 生地の制限が小さいため、使用済み生地のあらゆる量に対して達成可能な最大の利益を保管することができます。 

1 つの充填タイプの場合、パンの作成を境界のあるナップサック アイテムとして扱うことができます。 その種類のバンズの最大数はわかっており、各バンズの生地コストと利益は固定です。 動的プログラミング配列を更新します。`dp[x]`正確に使用した後の最大利益を意味します`x`生地のグラム数。 すべてのフィリングタイプを処理した後、残りの生地にプレーンバンズを最適に詰めます。 

このブルート フォースは有効なプランをすべて列挙するため機能しますが、多くのプランが同じ量の使用済み生地を共有していることを無視するため失敗します。 動的プログラミングのアプローチでは、そのようなすべての計画を 1 つの状態にマージします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(すべての選択肢の積) | お(1) | 遅すぎる |
 | 最適 | O(m * n * maxBunsPerType) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 利用可能な生地とすべてのパンの種類を確認します。 プレーン バンの情報は、すべての充填バンが考慮された後に適用されるため、個別に保存します。 
2.次のサイズの動的プログラミング配列を作成します。`n + 1`。 位置の値`i`正確に支出した後の最大利益を表します`i`生地のグラム数。 最初は、生地をゼロに費やしても利益はゼロです。 
3. すべての充填タイプを 1 つずつ処理します。 このタイプの場合、利用可能なフィリングから可能なバンズの最大数を計算します。 実際の数は、充填量と生地の制限の両方によって制限されます。 
4. 現在の充填タイプのバンズを可能な限りすべて試してみます。 以前に生地を使用した可能性があるすべてについて、選択した数のバンズを追加して新しい状態を更新します。 これは、現在の詰め物が生地を除いて他の詰め物から独立しているため機能します。 
5. すべての具材を処理した後、すでに使用されている可能な量の生地をすべて繰り返します。 残った生地でプレーンバンズを作った利益を加えて、最大の答えを維持します。 

これが正しい理由は、いくつかのフィリング タイプを処理した後、動的プログラミングの状態には、費やされる生地の量ごとに可能な限り最高の利益が含まれるためです。 新しい充填タイプを追加するときは、そのタイプの考えられるすべての寄与が考慮されるため、不変式は true のままです。 すべての具材を処理した後、残るのは残った生地をどう使うかだけであり、プレーンバンズにはそれ以外の制限はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())

    types = []
    for _ in range(m):
        a, b, c, d = map(int, input().split())
        types.append((a, b, c, d))

    dp = [0] * (n + 1)

    for a, b, c, d in types:
        limit = min(a // b, n // c)
        ndp = dp[:]

        for dough_used in range(n + 1):
            if dp[dough_used] < 0:
                continue
            for cnt in range(1, limit + 1):
                new_dough = dough_used + cnt * c
                if new_dough > n:
                    break
                value = dp[dough_used] + cnt * d
                if value > ndp[new_dough]:
                    ndp[new_dough] = value

        dp = ndp

    ans = 0
    for used in range(n + 1):
        plain = (n - used) // c0 * d0
        if dp[used] + plain > ans:
            ans = dp[used] + plain

    print(ans)

if __name__ == "__main__":
    solve()
```配列`dp`すでにコミットされている生地の可能な量ごとに最良の結果を保存します。 利用可能な空のベーキング プランのみから始まります。 

充填ごとに、変数`limit`不可能な移行を防ぎます。 パンは、十分な餡と十分な生地がなければ作ることができません。 コピーされた配列`ndp`現在の充填に対するすべての新しい選択は、同じ反復で既に同じ充填を使用した決定ではなく、以前の充填セットに基づく必要があるため、 が使用されます。 

最後のループはプレーンなパンを処理します。 州はすでにすべての充填バンズを計上しているため、残りの生地はプレーンバンズにのみ費やすことができます。 Python の整数では、最大の答えが依然として小さいため、オーバーフローの問題が回避されますが、整数演算を使用すると、すべての中間値が自然に処理されます。 

## 実用的な例

 最初のサンプルの場合:```
10 2 2 1
7 3 2 100
12 3 1 10
```充填物を処理した後の重要な状態は、次のように追跡できます。 

| ステップ | 加工済み詰め物 | 使用した生地 | 最高の利益 |
 | --- | --- | --- | --- |
 | イニシャル | なし | 0 | 0 |
 | 充填後 1 | タイプ1 | 2 | 100 |
 | 充填後 1 | タイプ1 | 4 | 200 |
 | 充填後 2 | タイプ2 | 6 | 240 |

 最高の状態では、充填されたバンズに 6 グラムの生地が使用されます。 残り 4 グラムなので、プレーンのパンを 2 つ作ることができ、さらに 1 つの利益が追加されます。 最終的な答えは、`241`。 

2 番目のサンプルの場合:```
100 1 25 50
15 5 20 10
```詰め物による利益はほとんどないため、詰め物を使用しないのが最適な状態です。 

| ステップ | 加工済み詰め物 | 使用した生地 | 最高の利益 |
 | --- | --- | --- | --- |
 | イニシャル | なし | 0 | 0 |
 | 充填後 1 | タイプ1 | 0 | 0 |
 | 最終回 | プレーンバン | 100 | 200 |

 トレースは、動的プログラミング段階では、利用可能なすべてのリソースを使用する必要がないことを示しています。 残りの生地は、最良の利益が得られる場合にのみ使用されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m * n * 平均的なパンの可能性) | フィリングごとに、すべての生地の状態と可能な数を試します。 
| スペース | O(n) | 現在の生地の状態のみが保存されます。 

生地の最大量はわずか 1000 個で、フィリングの数は最大 10 個であるため、遷移の数は簡単に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    n, m, c0, d0 = map(int, data().split())
    types = []
    for _ in range(m):
        a, b, c, d = map(int, data().split())
        types.append((a, b, c, d))

    dp = [0] * (n + 1)

    for a, b, c, d in types:
        limit = min(a // b, n // c)
        ndp = dp[:]
        for i in range(n + 1):
            for cnt in range(1, limit + 1):
                if i + cnt * c > n:
                    break
                ndp[i + cnt * c] = max(ndp[i + cnt * c], dp[i] + cnt * d)
        dp = ndp

    ans = 0
    for i in range(n + 1):
        ans = max(ans, dp[i] + (n - i) // c0 * d0)

    sys.stdin = old
    return str(ans) + "\n"

 ## 特殊なケース

 限定充填ケースの場合:```
5 1 3 10
4 3 2 100
```アルゴリズムは、充填されたパンを最大 1 つ製造できると計算します。`4 // 3 = 1`。 遷移により、生地が 2 グラム使用され、利益が 100 の状態が作成されます。 残りの 3 グラムで 1 つのプレーンなパンが生成され、最終的な結果が得られます。`110`。 

プレーンなパンの方が良い場合:```
100 1 25 50
15 5 20 10
```フィリングの移行では、フィリング入りバンズを 1 つだけ作成できますが、そのような選択肢はどれも、プレーン バンズに生地を使用する場合と比較してあまり価値がありません。 最終スキャンでは、プレーン パンの利益が追加されたすべての状態を比較するため、空の充填状態が勝ちます。`200`。 

混合リソースの場合:```
10 2 2 1
7 3 2 100
12 3 1 10
```動的プログラミング状態は、以前のタイプからどれだけの充填が残っているかを覚えておく必要なく、2 つの充填タイプを組み合わせます。 各充填は独自の制限に従って 1 回処理されるため、最終状態はすべての有効な組み合わせを表します。
