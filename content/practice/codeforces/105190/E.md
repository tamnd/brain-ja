 ## 解決策
 ## 問題の理解

 入力には単一の整数が含まれています`n`。 この値は、必要な出力には影響しません。 タスクは、標準入力から整数を正常に読み取り、文字列を出力するだけです。`AC`。 

制約`1 ≤ n ≤ 1000`この値は決して使用されないため、アルゴリズムには無関係です。 1 つの整数の読み取りと 1 つの固定文字列の出力は、どちらも一定の時間と一定のメモリを必要とします。 

唯一の微妙な間違いは、印刷する前に入力を読み取るのを忘れたことです。 このような単純な問題では、多くの審査員が未読の入力を無視しますが、競技プログラミング ソリューションでは、提供された入力を消費することが期待されます。 

たとえば、入力の場合```
1
```正しい出力は```
AC
```もう 1 つの考えられる間違いは、正確な大文字以外の文字列を出力することです。 

たとえば、入力の場合```
1000
```印刷```
ac
```または```
Accepted
```この問題では正確な出力が明示的に必要とされるため、これは不正解です。`AC`。 

## アプローチ

 簡単な解決策は、整数を読み取って出力します。`AC`。 入力値が 1 つだけであり、それに依存する計算がないため、これで問題全体がすでに解決されています。 正確に 1 つの整数が読み取られ、1 つの文字列が出力されるため、実行時間は一定です。 

入力は意図的に無意味であるため、これ以上洗練されたアルゴリズムはありません。 このチャレンジは、出場者が基本的な入力と出力を正しく実行できることを確認するためにのみ存在します。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`標準入力から。 必要な出力には影響しないため、値自体は無視されます。 
2. 文字列を出力します`AC`まさに指定どおりです。 

### なぜ効果があるのか

 この問題は任意の入力値を受け入れますが、常に同じ出力を必要とします。 アルゴリズムは常に出力するため、`AC`入力を消費した後、すべての有効なテスト ケースの仕様と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

input()
print("AC")
```プログラムは最初に 1 つの入力行を読み取ります。 この値は不要なため破棄されます。 その後、必要な文字列を正確に出力します。 解析や追加の計算は必要ないため、境界条件、オーバーフロー、またはオフバイワンエラーに関する心配はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    input()
    print("AC")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# sample-style case
assert run("1\n") == "AC\n", "sample"

# custom cases
assert run("1000\n") == "AC\n", "maximum input"
assert run("500\n") == "AC\n", "middle value"
assert run("999\n") == "AC\n", "large value"
assert run("42\n") == "AC\n", "arbitrary value"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1000`|`AC`| 許可される最大の入力。 |
 |`500`|`AC`| 一般的な有効な値。 |
 |`999`|`AC`| 別の大きな有効な値。 |
