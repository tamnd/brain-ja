 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするツリーが与えられています。各エッジには正の重みがあります。 すべてのクエリでアブドラは開始都市に配置されます`u`そして目標金額を与える`p`。 

から`u`、アブドラは、根を張ったツリー内で下方向にのみ移動できます。つまり、すべての有効な目的地を意味します。`v`のサブツリー内に存在する必要があります`u`。 同様に、ルートから`v`通過しなければならない`u`、 それで`u`の先祖です`v`。 

彼が目的地を選ぶなら`v`、彼の利益は、からのパスに沿ったエッジの重みの合計です。`u`に`v`時間単位のコストは、単にそのパス上のエッジの数です。 クエリごとに、クエリの子孫に到達するために必要なエッジの最小数を見つける必要があります。`u`収集された重量の合計が少なくとも`p`。 そのような子孫が存在しない場合、答えは次のようになります。`-1`。 

主な問題点は、各クエリが独立しており、開始ノードとしきい値の両方が異なることです。 素朴な戦略では、クエリごとにすべての子孫を探索しますが、ツリーに最大 100,000 個のノードがあり、最大 100,000 個のクエリがある場合、これでは遅すぎます。 

この制約は、対数クエリ処理による線形または線形に近い前処理に近いソリューションが必要であることを意味します。 クエリごとにサブツリー情報を再計算したり、クエリごとに DFS を実行したりすると、すぐに失敗します。 

開始ノードがリーフである場合、微妙なエッジ ケースが発生します。 この場合、有効な移動は存在しないため、リーフからのすべてのクエリは返される必要があります。`-1`かかわらず`p`。 もう 1 つのエッジ ケースは、重みが大きくてもパスの長さが短い場合に発生します。つまり、深いパスだけが十分な合計を蓄積できる可能性があり、すべての子孫ブランチをグローバルに考慮しない場合、貪欲なローカル選択は失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、開始ノードから DFS を実行して各クエリを個別に処理することです。`u`、現在の深さと累積された重みを維持し、サブツリー内の到達可能なすべてのノードをチェックします。 これは、有効なパスをすべて列挙するため、正しいです。 ただし、各クエリは次の場所にアクセスする可能性があります。`O(n)`ノード、最悪のケースを与える`O(nq)`、それは周りにあります`10^10`操作は不可能であり、明らかに実行不可能です。 

構造的な観察は、すべての有効な動きは、次から始まる下向きのパスを選択することに対応しているということです。`u`そして、その経路に沿ってどれだけ早く体重を蓄積できるかだけを気にします。 一定のステップ数の場合`k`、私たちが集めることができる最高のお金`u`子遷移の局所的に最適な選択を常に行うことによって決定されます。 これは関数を定義することを示唆しています`f_u(k)`から得られる最大合計を表します。`u`正確に使用して`k`下向きのエッジ。 

計算できるようになると`f_u(k)`、各クエリは最小値の検索になります。`k`そのような`f_u(k) >= p`。 なぜなら`f_u(k)`は減少していない`k`、評価できれば、これは二分探索で答えることができます。`f_u(k)`効率的に。 

課題は、すべてのノードに対してこれらすべての関数を計算することになります。 遷移は当然ツリー DP: ノードからです`u`、子供を選ぶ`v`与える`f_u(k) = w(u,v) + f_v(k-1)`その子に対しては、すべての子に対して最大値を採用します。 

難しいのは、それぞれ`f_u`完全な関数です`k`深さまで`n`したがって、それをノードごとに明示的に保存することは二次的になります。 節約のアイデアは、各関数を、ある子パスが別の子パスよりも優れたキー ブレークポイントのセットとして圧縮形式で保存できることです。 これらの関数は単調であり、ツリー上で小規模から大規模への手法を使用してマージでき、非支配状態のみを保持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | 圧縮された関数をマージしたツリー DP | O(n log n) 償却 | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノードごとに定義します`u`達成可能な最良のペアを表す状態のセット`(k, value)`どこ`value`～から得られる最大の合計です。`u`まさに`k`下にステップします。 各状態は、最適なパス長の候補を表します。 

1. ノード 1 でツリーをルートし、DFS を実行して、親の前に子を処理します。 これにより、情報を計算するときに、`u`、 全て`f_v`子供向け`v`はすでに知られています。 
2. 各ノードについて`u`に留まることを表す初期状態から始めます。`u`と`(k = 0, value = 0)`。 
3. すべての子どもたちに`v`の`u`、すでに計算された構造を採用します。`v`すべての状態を 1 ステップと重みでシフトします`w(u,v)`。 これにより、次の形式の候補状態が生成されます。`(k+1, f_v(k) + w(u,v))`。 これらは通過するパスを表します`v`最初のステップとして。 
4. すべての子コントリビューションを 1 つの構造にマージします。`u`。 マージ中、2 つの状態が存在するときは常に`(k1, x1)`そして`(k2, x2)`存在し、一方は両方の次元で悪くなっています。つまり、より多くのステップが使用されますが、より良い値が得られないため、それを破棄します。 これにより、達成可能な最良の値の上限エンベロープのみが維持されます。 
5. すべての子を処理した後、次のコンパクトなモノトーン構造が得られます。`u`二分検索を介してクエリに答えることができます。`p`、最小のものを見つけます`k`格納された値が少なくとも`p`。 
6. 各クエリについて`(u, p)`、保存されているものをバイナリ検索します。`(k, value)`ノードのリスト`u`有効な最小値を見つけるには`k`。 値が到達しない場合`p`、戻ります`-1`。 

なぜそれが機能するかというと、`u`どの子孫に対しても、正確に 1 つの子を選択することから始める必要があり、その後、問題はその子のサブツリー内の同じ構造に帰着します。 DP はこれらの選択肢のすべての最適な組み合わせを構築し、優勢枝刈りによって潜在的に最適な答えが削除されないようにします。 破棄された状態は、ステップと累積値の両方において、他の状態よりも厳密に悪いため、しきい値クエリに対して最適になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    g[u].append((v, w))
    g[v].append((u, w))

# we root the tree at 1
parent = [0] * (n + 1)

order = []
stack = [1]
parent[1] = -1

# build parent + order
while stack:
    u = stack.pop()
    order.append(u)
    for v, w in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

children = [[] for _ in range(n + 1)]
for u in range(2, n + 1):
    p = parent[u]
    for v, w in g[p]:
        if v == u:
            children[p].append((u, w))

# DP structures: for each node store list of (k, best_sum)
dp = [[] for _ in range(n + 1)]

# leaves start with (0,0)
for u in range(n, 0, -1):
    if not children[u]:
        dp[u] = [(0, 0)]
        continue

    cur = [(0, 0)]

    for v, w in children[u]:
        child = dp[v]
        shifted = [(k + 1, val + w) for k, val in child]

        # merge cur and shifted
        merged = []
        i = j = 0
        tmp = sorted(cur + shifted)

        for k, val in tmp:
            if merged and merged[-1][0] == k:
                merged[-1] = (k, max(merged[-1][1], val))
            else:
                merged.append((k, val))

        # prune dominated
        pruned = []
        best = -1
        for k, val in merged:
            if val > best:
                pruned.append((k, val))
                best = val

        cur = pruned

    dp[u] = cur

q = int(input())
for _ in range(q):
    u, p = map(int, input().split())
    arr = dp[u]

    ans = -1
    for k, val in arr:
        if val >= p:
            ans = k
            break
    print(ans)
```実装の中核は、ルート付きツリー上のボトムアップ DP です。 各ノードは、達成可能な圧縮リストを蓄積します。`(steps, sum)`ペア。 子を処理するときは、その値を 1 ステップシフトしてエッジの重みを追加し、それを現在の候補リストにマージします。 

枝刈りステップは不可欠です。ステップごとに分類すると、以前の値よりも小さいか等しい値を持つ状態は役に立ちません。これは、より少ないステップでより高いしきい値に到達するのに決して役立つことがないためです。 

クエリは、事前に計算されたリストをスキャンして、しきい値を満たす最初の状態を見つけることによって回答されます。 

## 実用的な例

 ノード 1 が重み 3 で 2 に接続し、重み 5 で 3 に接続し、ノード 2 が重み 4 で 4 に接続する小さなツリーを考えてみましょう。 

ノード 2 の場合、DP テーブルは次のように展開されます。 

| ステップ | 処理されたノード | DP 状態 |
 | --- | --- | --- |
 | 1 | 4 | (0,0)、(1,4) |
 | 2 | 2 | (0,0)、(1,3)、(2,7) |

 ノード 2 で始まるクエリの場合、`p = 6`、DP テーブルをスキャンして、次の場所を見つけます。`k = 2`値は`7`、したがって、答えは次のとおりです`2`。 

これは、DP が複数の子パスを結合する方法と、より深い構造を探索した後でのみ長いパスが十分な重みを蓄積できる方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) 償却 | 各ノードは子 DP リストを優先枝刈りでマージし、各状態は制限されたマージでも存続します。 
| スペース | O(n log n) | 各ノードには、非支配的な圧縮フロンティアが格納されます。`(k, sum)`ペア |

 枝刈り後の各ノードは少数の意味のある状態のみを提供し、すべての状態はツリー構造に沿って限られた回数だけマージされるため、複雑さは制約内に収まります。

 ## 特殊なケース

 リーフ ノードは、単純なアプローチの最も直接的な失敗ケースです。 子孫がないため、可能な唯一の状態は次のとおりです。`(0,0)`。 プラスのお金を必要とするクエリはすぐに返されます`-1`、DP は空または最小の状態セットによって正しく表されます。 

開始ノードの直下に非常に大きな重みエッジが存在する場合、別のエッジ ケースが発生します。 最適な答えは次のようになります`1`たとえより深いパスが存在し、DP は浅い高重みエッジがより深い低重み累積によって覆い隠されないようにする必要があります。 優位性枝刈りでは、値が小さいほど値が大きくなるため、そのような状態が保存されます。`k`剪定しても必ず生き残ります。 

最後の微妙なケースは、複数の子が同様の歩数を生成するが合計が異なる場合に発生します。 マージ ステップにより、各ステップ カウントの最適な合計のみが保持されるようになり、有効な最適な遷移の誤った枝刈りが防止されます。
