 ## 解決策
 ## 問題の理解

 整数の配列を操作しており、サブシーケンスを選択することができますが、連続して選択されたインデックスの間隔には制限があります。 サブシーケンスが固定されたら、サブシーケンス内のすべての隣接するペアを取得し、2 つの値の gcd を計算し、それらの gcd を合計することでスコアを割り当てます。 

タスクは、このスコアを最大化するサブシーケンスを選択することです。 

重要な制約は算術的ではなく構造的なものです。位置 i を選択してから位置 j を選択した場合、i の後に j が最大 k ステップ存在する必要があります。 したがって、サブシーケンスはサイズ k のスライディング ウィンドウ内でローカルに接続されたままでなければなりません。 

出力は各テスト ケースの可能な最大スコアのみであり、サブシーケンス自体ではありません。 

制約が十分に大きいため、ウィンドウ内のすべてのペアにわたる二次比較は失敗します。 合計 n が 2 · 10^5 までの場合、すべての位置について k にわたる線形スキャンでも、最悪の場合、約 4 · 10^10 回の演算にまで低下します。 これにより、各位置がほぼ対数または償却定数時間で処理され、遷移が明示的に列挙されるのではなく集計されるソリューションが直ちに必要になります。 

貪欲に推論しようとすると微妙な難しさが現れる。 gcd 相互作用は非線形であるため、位置ごとに局所的に最適な前の要素を選択することは機能しません。 あるステップでは最適でない値でも、将来の要素との互換性により、後で最適になる可能性があります。 

2 番目の問題は、最適な先行処理が値と距離 k 内にあるかどうかの両方に依存することです。 これにより、問題はスライディング ウィンドウ全体にわたって本質的に動的になります。 

## アプローチ

 答えを計算する直接的な方法は、配列に対して動的プログラミングを使用することです。 dp[i] を、位置 i で終了する有効なサブシーケンスの最高スコアとする。 すべての i について、[i − k, i − 1] の範囲内のすべての前の位置 j を試し、サブシーケンスを j から i に拡張します。 遷移により、gcd(a[j], a[i]) が dp[j] に追加されます。 

この強引なアイデアは、i への有効な最後のステップをすべて試行するため正しいですが、コストが大きすぎます。 各位置は最大 k 個前の位置を遡ることができ、O(nk) 個の遷移が発生します。 n が 2 · 10^5 までの場合、これは実行不可能になります。 

重要な観察は、遷移は j 自体には依存せず、j の値のみに依存するということです。 固定 i の場合、同じ値 a[j] を持つすべての候補は、dp[j] を除いて同じ方法で寄与します。 これにより、値ごとに状態を集計できるようになります。 

すべての j をスキャンする代わりに、可能な配列値 x ごとに現在のウィンドウ内のすべてのインデックスの中で最良の dp 値を維持します。 その後、遷移は位置 j ではなく値 x の検索になります。 固定 x の場合、dp[i] への寄与は best_dp[x] + gcd(x, a[i]) です。 

ここで問題は、ウィンドウ内のすべての値 x の中から、best_dp[x] + gcd(x, a[i]) の最大値をすばやく見つけることになります。 

これは、除数を使用して値をグループ化することで処理します。 固定の a[i] の場合、任意の値 x は、a[i] の約数 d に等しい gcd に寄与します。 すべての x に対して gcd を明示的に計算する代わりに、a[i] の各約数 d を考慮し、値が d で割り切れるすべての x の中で最良の dp[x] を求めます。 これにより、これらの値に対する候補スコア d + max dp[x] が得られます。 

これを効率的にサポートするために、すべての約数 d に対して、値が d で割り切れるすべてのアクティブな要素の dp 値のマルチセットを維持します。 値がスライディング ウィンドウに入るとき、またはスライディング ウィンドウから出るときに、そのすべての約数が更新されます。 これにより、少数の a[i] の約数のみをチェックすることで各クエリに答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ポジションに対するブルートフォース DP | O(nk) | O(n) | 遅すぎる |
 | スライディング ウィンドウを使用した値 + 除数の集計 | O(n √A log A) | O(A √A) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

1. dp[i] をインデックス i で終わる有効なサブシーケンスの最良のスコアとして定義します。 すべての遷移が以前に計算された状態から進むように、i の昇順で dp を計算します。 
2. 遷移が許可されるインデックスのスライディング ウィンドウ、つまり i − k ≤ j < i となるすべてのインデックス j を維持します。 これにより、距離の制約が確実に遵守されます。 
3. すべての値 v について、a[j] = v であるすべてのアクティブなインデックス j の dp[j] を格納するデータ構造を維持します。目標は、各値に対して現在利用可能な最適な dp 値を迅速に知ることです。 
4. 各約数 d について、値が d で割り切れるすべてのアクティブなインデックスの dp 値を含むマルチセットを維持します。 この構造により、a[i] で d の gcd 倍数を形成できる最適な先行演算子を照会できます。 
5. 新しいインデックス i を処理するときは、dp[i] を計算した後、最初にその寄与をすべての除数構造に挿入します。 古いインデックスがウィンドウを離れると、関連するすべての構造からそのインデックスの寄与が削除されます。 これにより、すべての構造がスライディング ウィンドウと一貫性を保ちます。 
6. dp[i] を計算するには、a[i] のすべての約数 d を繰り返します。 各 d について、d で割り切れるすべての数値の中で保存されている最大 dp 値を取得し、候補スコア d + best_dp_in_that_set を計算します。 すべての約数の最大値は dp[i] になります。 
7. サブシーケンスは任意の位置で開始できるため、dp[i] をすべての i に対してゼロとして初期化します。 すべての dp 値を計算した後の最終的な答えは、最大 dp[i] になります。 

### なぜ効果があるのか

 j から i への有効な遷移はすべて、値 gcd(a[j], a[i]) = g を生成します。 値 a[j] は g で割り切れるため、j は除数 g に対応する構造に含まれます。 したがって、a[i] の除数 g を処理する際には、寄与 dp[j] + g が考慮されます。 j が複数の約数セットに含まれる場合でも、約数ごとに最大値を独立して取得するため、正確性が向上するだけです。 これにより、すべての有効なペアの遷移が少なくとも 1 か所で評価され、無効な遷移が決して導入されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 400000

# precompute divisors for all values up to MAXV
divs = [[] for _ in range(MAXV + 1)]
for i in range(1, MAXV + 1):
    for j in range(i, MAXV + 1, i):
        divs[j].append(i)

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # multiset via dict frequency + current maximum tracking is complex,
    # so we store lists and recompute max lazily per divisor
    active = [0] * (n + 1)
    dp = [0] * n

    # for each divisor d, we keep a multiset as dict value->count
    from collections import defaultdict

    cnt = [defaultdict(int) for _ in range(MAXV + 1)]
    cur_max = [0] * (MAXV + 1)

    def add_value(v, val):
        for d in divs[v]:
            cnt[d][val] += 1
            if val > cur_max[d]:
                cur_max[d] = val

    def remove_value(v, val):
        for d in divs[v]:
            cnt[d][val] -= 1
            if cnt[d][val] == 0:
                del cnt[d][val]
            if val == cur_max[d] and val not in cnt[d]:
                # recompute
                cur_max[d] = max(cnt[d].keys()) if cnt[d] else 0

    left = 0

    for i in range(n):
        if i > k:
            remove_value(a[left], dp[left])
            left += 1

        best = 0
        for d in divs[a[i]]:
            best = max(best, cur_max[d] + d)

        dp[i] = best

        add_value(a[i], dp[i])

    print(max(dp))

t = int(input())
for _ in range(t):
    solve()
```実装は、可能な最大要素サイズまでのすべての値の約数を事前計算することから始まります。 これにより、メインループ中に除数リストを繰り返し再計算することが回避されます。 

ソリューションの中核はスライディング ウィンドウです。 配列内を移動するとき、距離 k 内のインデックスのみを維持します。 ウィンドウに出入りする値ごとに、すべての除数ベースの集計を更新して、各除数が現在アクティブな要素の中で割り切れる最適な dp 値を認識できるようにします。 

次に、位置 i の dp 計算は、a[i] の除数をスキャンし、各除数 d をその除数で利用可能な最良の dp 値と組み合わせることに帰着します。 

最もデリケートな部分は、構造からの削除です。 複数のインデックスが同じ dp 値を共有する可能性があるため、周波数を追跡します。 値が完全に消えると、正確さを維持するためにその除数の最大値が再計算されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 エッジ ケースの 1 つは、ウィンドウ内のすべての値が 2 の累乗などの大きな gcd 構造を共有する場合です。 その状況では、多くの約数が均等に寄与し、アルゴリズムは値ごとではなく約数ごとに正しい最大値を維持することに依存します。 

もう 1 つのケースは、割り算パターンを共有しているときに、値が頻繁にウィンドウに出入りする場合です。 除去ロジックが重要になるのは、古い最大値が dp 遷移を過大評価してしまうためです。 周波数ベースの再計算により、最大の寄与が消失した場合の正確性が保証されます。 

最後のケースは、k が小さい場合です。 この場合、問題となるのはローカル遷移だけであり、解決策は隣接する要素に対するほぼ線形のスキャンに縮退しますが、常に少数のインデックスのみがアクティブなままであるため、除数法は依然として正しく処理されます。
