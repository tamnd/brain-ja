 ## 解決策
 ## 問題の理解

 文字列と、選択された 2 つの部分文字列に対するスコアリング関数を定義する 3 つの大きな係数が与えられます。 文字列内の重複しない 2 つのセグメントを選択する必要があります。 最初のセグメントは文字列の接頭辞と一致する必要があり、2 番目のセグメントは文字列の接尾辞と一致する必要があります。 セグメントは厳密に順序付けされ、互いに素である必要があり、スコアへの寄与はセグメントの長さにセグメント間のギャップを加えたものによって決まります。 

タスクは、両方のセグメントの長さに報酬を与え、さらに 3 番目の係数によってそれらの間の距離に報酬を与えたりペナルティを与えたりする線形式を最大化することです。 重要な制約は、2 つの部分文字列が任意ではないということです。最初の部分文字列は文字列全体の接頭辞と等しくなければならず、2 番目の部分文字列は文字列全体の接尾辞と等しくなければなりません。 

この制約により、文字列の長さは最大 100 万まで許可され、二次関数や偶数関数は即座に除外されます。$O(n \log n)$部分文字列の境界を越える二重ループ。 どのソリューションも基本的に、文字列を線形または線形に近い時間で処理する必要があります。 選択した両方の部分文字列が接頭辞と接尾辞のパターンに一致する必要があるため、問題は基本的に、接頭辞の一致が各位置からどこまで続くか、および接尾辞の一致が文字列内でどの程度まで遡るかを事前に計算することです。 

単純なアプローチでは、すべての 4 回転を試すことになります。$(l_1, r_1, l_2, r_2)$直接比較してプレフィックスとサフィックスの条件を検証します。 エンドポイントを制限しても、これは部分文字列の一致により三次またはさらに悪化し、明らかに失敗します。$n = 10^6$。 

より微妙な障害モードは、プレフィックス一致とサフィックス一致を別々に誤って処理することによって発生します。 たとえば、部分文字列はプレフィックスと一致するが、サフィックス候補と無効に重複する場合や、その逆の場合があります。 もう 1 つのよくある間違いは、プレフィックス一致の長さがわかったら、境界制約を検証せずにどの開始位置でもそれを再利用できると想定することです。 

## アプローチ

 強引な解釈により、2 つのセグメントを選択するという考えが修正されます。 最初のセグメントのすべての有効な選択肢を反復処理し、それが文字列の接頭辞と一致することを確認してから、接尾辞と一致するすべての有効な 2 番目のセグメントを反復して、式を直接計算します。 ハッシュによって部分文字列の等価性が最適化されたとしても、依然として次のような問題に直面します。$O(n^2)$候補ペアは不可能になります。$10^6$。 

重要な観察点は、有効なセグメントの構造が非常に制限されていることです。 接頭辞と等しい部分文字列は、その終了位置によって完全に決定されます。 同様に、接尾辞に等しい部分文字列は、その開始位置によって完全に決定されます。 これにより、問題は 4 つの自由変数から 2 つの意味のある境界、つまりプレフィックス一致セグメントの終わりとサフィックス一致セグメントの始まりに減ります。 

これら 2 つのインデックスの観点からすべてを表現すると、目的はそれらの位置と事前計算可能なプレフィックスとサフィックスの一致長の関数になります。 残りの課題は、順序制約を尊重しながら、それらの間の最適な分割点を効率的に評価することです。$r_1 < l_2$。 これにより、当然のことながら、すべての位置のプレフィックス一致長とすべての位置のサフィックス一致長が事前計算され、達成可能な最良のプレフィックス寄与とサフィックス寄与を維持しながら、考えられる分割ポイントがスキャンされます。 

この場合、問題はセグメント境界を越える組み合わせ検索ではなく、プレフィックスを最大限に維持する線形スイープになります。

 ## アルゴリズムのチュートリアル

 まず、各位置が文字列の接頭辞とどの程度一致するかを計算します。 配列を定義します`pref[i]`位置から始まる最長のプレフィックスの長さとして`i`。 これは、Z 関数または KMP スタイルの前処理を使用して線形時間で計算できます。 

同様に計算します`suff[i]`、位置で終わる最長の接尾辞一致`i`、再び逆文字列処理を使用します。 

次に、選択した 2 つの部分文字列を再解釈します。 最初のセグメントはある位置で終了します`r1`、可能な限り最良の開始は、プレフィックスとどの程度一致するかによって制限されます。 2 番目のセグメントはある位置から始まります`l2`、そしてその最良の結果は接尾辞の一致によって制約されます。 

次に、2 つのセグメント間のすべての有効な分割境界を反復処理し、左側からの達成可能な最良の寄与を維持し、それらを右側からの寄与と組み合わせます。 

最初のセグメントに依存する項がその終了位置のみに依存し、2 番目のセグメントに依存する項がその開始位置のみに依存し、さらにそれらの間のギャップに対する線形ペナルティまたは報酬が追加されるように、式を再編成できます。 

スイープ中に、可能な最初のセグメント値の現在の最大値を維持します。`r1`左から右へ。 それぞれの可能性について`l2`、過去の最高のものと組み合わせます`r1`順序付け制約を満たします。 

### なぜ効果があるのか

 すべての有効なソリューションはエンドポイントによって一意に決定されます$r_1$そして$l_2$。 これらが修正されると、最も有効な$l_1$そして$r_2$プレフィックスとサフィックスのマッチング制約によって強制されるため、独立した最適化は必要ありません。 スイープにより、候補分割を評価するときに、すべての有効な左側セグメントがすでに考慮されていることが保証され、最大値が維持されているため、より適切なプレフィックス調整された構成を決して見逃すことがなくなります。 これにより、実行可能なすべての構成が正規表現で 1 回だけ考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i <= r:
            z[i] = min(r - i + 1, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] - 1 > r:
            l, r = i, i + z[i] - 1
    return z

def solve():
    n, x, y, zc = map(int, input().split())
    s = input().strip()

    # prefix matches
    z = z_function(s)
    pref = [0] * n
    pref[0] = n
    for i in range(1, n):
        pref[i] = min(z[i], n - i)

    rs = s[::-1]
    zr = z_function(rs)
    suff = [0] * n
    suff[n - 1] = n
    for i in range(n - 1):
        suff[i] = min(zr[n - 1 - i], i + 1)

    NEG = -10**30

    best = NEG
    best_left = NEG

    for r1 in range(n):
        if pref[r1] > 0:
            val_left = (r1) * x + pref[r1] * x
            best_left = max(best_left, val_left)

        l2 = r1 + 1
        if l2 < n and suff[l2] > 0:
            val_right = (n - l2 - 1) * y + suff[l2] * y
            best = max(best, best_left + val_right + (l2 - r1) * zc + x + y - zc)

    if best == NEG:
        print(0)
    else:
        print(best)

if __name__ == "__main__":
    solve()
```この解決策は、文字列の各サフィックスがプレフィックスとどの程度一致するかを測定する Z 関数の計算から始まります。 これにより、部分文字列の比較を行わずに、接頭辞の等価性制約に直接アクセスできるようになります。 

次に、反転した文字列に対してミラー Z 関数を計算して、元の文字列内のすべての位置のサフィックス一致の長さを取得します。 この対称性により、サフィックス オートマトンやハッシュ ベースのチェックの構築が回避されます。 

一掃`r1`またはそれ以前に終了する有効な最初のセグメントからの可能な限り最高の寄与を維持します。`r1`。 先に進むたびに、そのエンドポイントでのプレフィックス一致長を使用して、この最適な値を更新します。 

潜在的な分割ごとに、分割の直後から始まる最も有効な 2 番目のセグメントを評価します。`r1`。 この組み合わせでは、事前計算された寄与と線形ギャップ項が使用されます。 すべての分割の最大値が最終的な答えになります。 

境界処理は重要です。プレフィックスまたはサフィックスの一致長がゼロである位置は寄与してはならず、有効なペアが存在しない場合はゼロを返さなければなりません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、完全な文字列以外の位置でプレフィックスと一致する部分文字列がない場合です。 そのような場合には、`best_left`有効になることはなく、組み合わせを形成できないため、アルゴリズムは正しくゼロを返します。 

もう 1 つの特殊なケースは、すべて同一の文字を含む文字列です。 ここでは、すべての位置が前方一致と後方一致の両方に有効です。 スイープでは依然として順序を尊重する必要があり、ギャップ タームが支配的になります。 すべての位置が左右両方の寄与を更新するため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは、最適な分割によって両方のセグメントが隣接する場合に発生します。 ギャップ項がゼロになり、事前に計算された最適な左右の値が隣接制約と一致するため、この式は引き続き適用されます。
