 ## 解決策
 ## 問題の理解

 各位置が確率変数の上限を表す整数の配列が与えられます。 インデックスごとに$i$、値$b_i$整数間隔から独立して均一に選択されます$[1, a_i]$。 これらのランダムな選択の後、次の部分配列を調べます。$b$そして、その部分配列内の最大値が指定されたしきい値を超えない確率を求めます。$x$。 

同様に、クエリの場合$(l, r, x)$、すべての確率が必要です。$b_i$範囲内で$[l, r]$せいぜい$x$、最大値は最大なので、$x$まさにすべての要素がそうなったとき。 

入力により、配列上のポイントの更新も可能になります$a$、対応する分布を変更します。$b_i$その位置からは。 各クエリは、現在の状態を使用して回答する必要があります。$a$。 

この制約により、各演算が対数時間に近づくような解決策が求められます。 まで$10^5$更新とクエリの合計を考慮すると、クエリごとに範囲を線形にスキャンするアプローチは遅すぎます。$O(nq)$最悪の場合。 

確率式について推論するときに、微妙な問題が発生します。 素朴な解釈では、ランダムな値をシミュレートしたり、分布を直接維持しようとしたりする可能性がありますが、どちらも不必要で誤解を招きます。 ランダム性は完全に独立しており、確率は決定論的な積に崩壊します。 

よくある間違いは、イベント「最大値 ≤ x」を、確率変数にわたる最大値の分布を追跡する必要があるものとして扱うことです。 それは不必要な複雑さにつながります。 もう 1 つの落とし穴は、更新によって値だけでなく分布が変更されるため、セグメントごとに事前に計算された確率は、注意深く維持しない限り無効になることを忘れていることです。 

## アプローチ

 定義を直接展開すると、インデックスごとに$i$我々は持っています：$$P(b_i \le x) = \frac{\min(a_i, x)}{a_i}.$$だって全部$b_i$は独立しており、最大値が超過する確率$[l, r]$せいぜい$x$製品になります:$$\prod_{i=l}^{r} \frac{\min(a_i, x)}{a_i}.$$ブルート フォース ソリューションでは、範囲を反復処理することにより、クエリごとにこの積を計算します。 各クエリのコスト$O(n)$最悪の場合、$O(nq)$全体。 と$10^5$動作が非常に遅くなります。 

重要な構造的観察は、各クエリは範囲積であるが、各用語は次の値間のしきい値比較に依存しているということです。$a_i$そして$x$。 つまり、各要素の寄与は区分的に次のようになります。 

いつ$a_i \le x$、貢献度は$1$、そしていつ$a_i > x$、になります。$x / a_i$。 

これにより、問題が動的配列上の 2 つの範囲統計に分割されます。要素の数がどのくらいかを知る必要があります。$x$範囲内にあり、それらの要素の積も必要です。 各ノードでソートされた値を格納するセグメント ツリーを使用すると、「より大きい値はいくつあるか」を答えることができます。$x$各ノード内の二分探索により、「その製品は何ですか」という情報を得ることができます。 

各クエリは次の組み合わせになります。$O(\log n)$セグメント ツリー ノード、および各ノードが貢献します。$O(\log n)$ソートされた配列に対する二分探索による時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n)$クエリごと |$O(1)$| 遅すぎる |
 | ソートされたノードを含むセグメント ツリー |$O(\log^2 n)$操作ごと |$O(n \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、各ノードがセグメント内の値のマルチセットをソートされた順序で保存するセグメント ツリーを、高速に集約するためのプレフィックス積とともに維持します。 

1. 配列上にセグメント ツリーを構築します。$a$、各ノードで、そのセグメント内のソートされた値のリストとプレフィックス積配列モジュロを格納します。$10^9+7$。 これにより、しきい値ベースのクエリに対数時間でローカルに応答できるようになります。 
2. お問い合わせの場合$(l, r, x)$、範囲を次のように分解します。$O(\log n)$セグメントツリーノード。 各ノードは独立して、応答の一部を提供します。 
3. ノード内で、次より大きい最初の値を見つけます。$x$ソートされたリストに対して二分探索を使用します。 この時点より前のすべてが寄与します$1$、その時点からのすべてが貢献します$x / a_i$。 
4. 各ノードについて、次の 2 つの値を計算します。$x$、およびそれらの要素の積です。 プレフィックス積配列を使用すると、二分探索後に一定時間内にサフィックスの積を抽出できます。 
5. すべてのノードからの貢献を結合します。 もし$k$より大きい要素の総数です$x$、 そして$P$はそのようなすべての要素の積であるため、最終的な答えは次のようになります。$$x^k \cdot P^{-1} \pmod{10^9+7}.$$6. アップデートについて$(p, v)$では、リーフ ノードを更新し、ルートへのパスに沿って並べ替えられたリストとプレフィックス製品を再構築します。 

正確さは、各セグメント ツリー ノードが範囲の正確な分割を提供し、各ノード内でしきい値分割が正確に処理されるという事実に依存します。 

### なぜ効果があるのか

 確率変数は独立しているため、確率式はインデックス全体で完全に因数分解されます。 各要素は、それが超過するかどうかのみに基づいて独立して寄与します。$x$。 セグメント ツリーにより、クエリ範囲内のすべての要素が 1 回だけカウントされ、しきい値に基づく分割がすべてのノードにわたって一貫して処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [[] for _ in range(4 * self.n)]
        self.pref = [[] for _ in range(4 * self.n)]
        self.a = arr[:]
        self.build(1, 0, self.n - 1)

    def build(self, v, tl, tr):
        if tl == tr:
            self.tree[v] = [self.a[tl]]
            self.pref[v] = [self.a[tl] % MOD]
            return
        tm = (tl + tr) // 2
        self.build(v * 2, tl, tm)
        self.build(v * 2 + 1, tm + 1, tr)

        merged = self.tree[v * 2] + self.tree[v * 2 + 1]
        merged.sort()
        self.tree[v] = merged

        pref = []
        cur = 1
        for x in merged:
            cur = (cur * x) % MOD
            pref.append(cur)
        self.pref[v] = pref

    def update(self, v, tl, tr, pos, val):
        if tl == tr:
            self.tree[v] = [val]
            self.pref[v] = [val % MOD]
            return
        tm = (tl + tr) // 2
        if pos <= tm:
            self.update(v * 2, tl, tm, pos, val)
        else:
            self.update(v * 2 + 1, tm + 1, tr, pos, val)

        merged = self.tree[v * 2] + self.tree[v * 2 + 1]
        merged.sort()
        self.tree[v] = merged

        pref = []
        cur = 1
        for x in merged:
            cur = (cur * x) % MOD
            pref.append(cur)
        self.pref[v] = pref

    def query_node(self, v, x):
        arr = self.tree[v]
        if not arr:
            return 0, 1
        import bisect
        idx = bisect.bisect_right(arr, x)
        k = len(arr) - idx

        if k == 0:
            return 0, 1

        total_prod = self.pref[v][-1]
        left_prod = self.pref[v][idx - 1] if idx > 0 else 1
        prod_gt = (total_prod * modinv(left_prod)) % MOD

        return k, prod_gt

    def query(self, v, tl, tr, l, r, x):
        if l > r:
            return 0, 1
        if l == tl and r == tr:
            return self.query_node(v, x)
        tm = (tl + tr) // 2
        k1, p1 = self.query(v * 2, tl, tm, l, min(r, tm), x)
        k2, p2 = self.query(v * 2 + 1, tm + 1, tr, max(l, tm + 1), r, x)

        k = k1 + k2
        p = (p1 * p2) % MOD
        return k, p

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    st = SegTree(a)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            p = int(tmp[1]) - 1
            v = int(tmp[2])
            st.update(1, 0, n - 1, p, v)
        else:
            l = int(tmp[1]) - 1
            r = int(tmp[2]) - 1
            x = int(tmp[3])

            k, prod = st.query(1, 0, n - 1, l, r, x)
            ans = pow(x, k, MOD) * modinv(prod) % MOD
            print(ans)

if __name__ == "__main__":
    solve()
```セグメント ツリーは各ノードで完全にソートされた配列を格納します。そのため、構築と更新の両方でマージされた配列が再構築されます。 プレフィックス積配列を使用すると、二分探索分割点の後にサフィックス積を抽出でき、再計算を回避できます。 

クエリ ロジックはカウントと乗算集計を分離しており、変換された確率式と直接一致します。 

## 実用的な例

 小さな配列を考えてみましょう。$a = [2, 5, 3]$そして私たちはクエリします$(1, 3, 3)$。 

各ポジションを評価します。$a_1 = 2$貢献する$1$、$a_2 = 5$貢献する$3/5$、 そして$a_3 = 3$貢献する$1$。 最終的な確率は次のようになります$3 / 5$。 

| ノード | 値 | x=3 で分割 | k (>\x) | 製品(>x) |
 | --- | --- | --- | --- | --- |
 | ルート | [2,5,3] | [2,3] | 1 | 5 |

 セグメント ツリーは配列をノードに分割しますが、各ノードはしきい値を超える要素を個別に識別します。 ノードを結合すると、カウントと積の両方の一貫性が維持され、直接計算と一致します。 

次に、アップデートの変更を検討してください$a_2$から$5$に$1$、その後に同じクエリが続きます。 配列は次のようになります$[2,1,3]$を超える要素はなくなりました。$3$、したがって、答えは次のようになります$1$。 この更新により、影響を受けるセグメント ツリー ノードが強制的に再構築され、今後のすべてのクエリに変更された配布が確実に反映されます。

 ## 特殊なケース

 特殊なケースは、範囲内のすべての値が以下の場合に発生します。$x$。 その状況では、あらゆる要因が$1$、セグメント ツリーは正しく返される必要があります。$k = 0$そして製品$1$。 このケースを保護せずにモジュラー逆行列を盲目的に適用する実装は、空の積で除算する危険があります。 

もう 1 つのエッジ ケースは、すべての値が超過する場合です。$x$。 そうすれば、すべての要素が貢献します$x / a_i$、したがって、答えは次のようになります$x^{r-l+1} / \prod a_i$。 アルゴリズムは、すべてのノードでバイナリ検索インデックスをゼロにすることでこれを処理します。そのため、プレフィックス積は空になり、完全なセグメントは完全に「より大きい」グループに寄与します。 

単一の位置を更新すると、複数のセグメント ツリー ノードに影響します。 内部ノードでプレフィックス プロダクトを再構築せずにリーフ ストレージを更新するだけの単純な実装では、ソートされた順序とプレフィックスの累積が実際の配列と矛盾するため、後のクエリで不正なプロダクトが暗黙的に生成されます。
