 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times N$単位セルのグリッド。すべて美しさの値 0 から始まります。 システムは、時間の経過とともに適用される 3 種類の操作によって進化します。 まず、グリッド全体に水平または垂直のカット ラインを導入します。 これらの線は、グリッドを互いに素な長方形領域に分割します。 これらの領域は入力で明示的に列挙されませんが、平面の動的な分解を暗黙的に定義します。すべてのセルは常に 1 つの領域に正確に属し、より多くの行が追加されると領域がさらに分割される可能性があります。 

2 番目に、単一のセルを選択して更新を適用できます。 この操作はそのセルに影響を与えるだけでなく、操作の瞬間にそのセルを含む領域全体内のすべてのセルの美しさを向上させます。 領域は以前に描画されたすべてのカットラインによって定義されるため、これは、更新が軸に沿った固定の長方形だけでなく、動的に変化する長方形のようなコンポーネント全体に伝播することを意味します。 

3 番目に、グリッドの静的な部分四角形に対するクエリが要求されます。 特定の長方形について、その時点でその内部のすべてのセルの最大の美しさの値を報告する必要があります。 

主な問題は、パーティション構造と値の両方が時間の経過とともに変化するため、クエリは完全に更新された状態を反映する必要があることです。 

制約は大きいです:$N \le 10^5$、$Q \le 3 \cdot 10^5$、まであります$2.5 \cdot 10^4$これにより、セルごとの値を明示的に維持したり、単純に四角形を再計算したりするソリューションは即座に排除されます。 一枚でも$O(N^2)$構造は不可能であり、四角形には次のものが含まれる可能性があるため、四角形のクエリごとのスキャンでさえ遅すぎます。$O(N^2)$細胞。 

動的パーティショニングでは微妙な問題が発生します。 素朴なアプローチでは、カットが追加されると変化する領域 ID を持つ 2D グリッドを維持しようとしますが、カットはストリップ全体を分割するため、潜在的に再ラベル付けが必要になります。$O(N^2)$制約の下では不可能です。 

もう 1 つの失敗例は、更新が個々のセルだけでなく領域全体に適用されることを無視したために発生します。 たとえば、セルを更新し、後でその領域を分割する場合、古い更新は、更新時にその領域に残っている部分にのみ正しく適用される必要があります。 単純なセルごとの累積では、この依存関係が完全に失われます。 

## アプローチ

 ブルートフォース解釈では、グリッドが明示的に維持されます。 タイプ 2 の各操作は、セルを含む領域全体をフラッドフィルまたは反復して追加します。$X$すべての細胞に。 タイプ 3 の各クエリは、長方形全体をスキャンして最大値を計算します。 

これはルールに直接従うため、原則として正しいです。 ただし、1 回のアップデートで次の点に影響を与える可能性があります。$O(N^2)$セル、およびクエリでも検査できます$O(N^2)$細胞。 まで$3 \cdot 10^5$操作、これは不可能につながります$O(N^2 Q)$最悪の場合。 

構造的な洞察は、水平および垂直のカットが軸に沿ったブロックへの動的なパーティションを定義し、時間の経過とともに小さくなるということです。 カットが追加されると消えることはありません。そのため、各セルの「領域履歴」は、その行または列を横切る一連のカットによって決まります。 これは、グリッドが増加する垂直境界と水平境界によって効果的に分割されていることを示唆しています。 

個々のセルを追跡する代わりに、カットされていない最大の水平ストリップと垂直ストリップをそれぞれ独立したコンポーネントとして扱うことができます。 どの領域も、現在のカット セットで定義されている 1 つの水平セグメントと 1 つの垂直セグメントのデカルト積です。 したがって、タイプ 2 の更新は、そのようなブロック 1 つだけに影響し、タイプ 3 のクエリは、長方形と交差するブロックの和集合の最大値を要求します。 

この構造により、行と列の間隔にわたって動的な 2D 構造を維持するという問題が軽減され、各操作はカット位置によって定義された連続セグメントと相互作用します。 カット ラインの座標圧縮と両軸にわたるセグメント ツリーの慎重な使用により、更新は 2D パーティションにわたる範囲更新になり、クエリは範囲最大クエリになります。 

中心的なアイデアは、グリッドを x 間隔と y 間隔の構造に分割し、次に 1 つの次元でセグメント ツリーを維持し、各ノードが他の次元で別のセグメント ツリーを維持し、展開するパーティションにわたって動的 2D セグメント ツリーを効果的に構築することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグリッドシミュレーション |$O(N^2 Q)$|$O(N^2)$| 遅すぎる |
 | 動的 2D セグメント化構造 |$O(Q \log^2 N)$|$O(N \log N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての垂直および水平のカット位置のセットをソートされた構造として維持します。 カットが挿入されるたびに、既存の間隔が 2 つの小さな間隔に分割されます。 これにより、グリッドはいつでも、隣接するカット座標によって定義される互いに素なブロックに分割されることが保証されます。 
2. すべての潜在的なカット座標とクエリ境界を圧縮して、関連するすべての行と列のインデックスが離散座標系に属するようにします。 これは、構造が変化する境界のみを考慮するために必要です。 
3. X 軸 (行) 上にセグメント ツリーを構築します。 このツリー内の各ノードは、連続する行範囲に対応します。 
4. X セグメント ツリーの各ノード内で、Y 軸 (列) 上に別のセグメント ツリーを維持します。 この入れ子構造により、任意の長方形を以下の組み合わせとして表すことができます。$O(\log N)$X ノードと$O(\log N)$y 範囲。 
5. タイプ 1 操作の場合、アクティブな切断境界を記録する構造を更新します。 これにより、将来のタイプ 2 操作で点を領域にマッピングする方法が事実上変更されます。 任意のセルを含む現在のブロックを迅速に判断できるように、区間分割構造を更新します。 
6. タイプ 2 の操作の場合、セルを含む現在のブロックを見つけます。$(a, b)$カット境界間の二分探索によって。 特定したら、2D セグメント構造内のそのブロックに範囲加算を適用します。 これが機能するのは、ブロック内のすべてのセルが同じ更新スコープを共有しているためです。 
7. タイプ 3 の操作の場合、クエリ四角形を次のように分解します。$O(\log^2 N)$セグメントツリー上の部分問題。 各部分問題は完全に含まれるブロック全体の最大値を返し、その最大値を取得して結果を結合します。 

### なぜ効果があるのか

 不変条件は、グリッド内のすべての点が常に、現在のカット構造によって定義された正確に 1 つのアクティブなセル ブロックに属し、各更新がそのようなブロック全体に正確に 1 つ影響するということです。 ネストされたセグメント ツリー構造はこのパーティションを正確に反映するため、すべての更新は両方の次元で明確に定義された連続領域に適用されます。 クエリは正規セグメント ツリー ノードに分解されるため、クエリ四角形内のすべてのセルが重複や省略なく 1 回だけカバーされ、最大集計の正確性が保証されます。

import sys
input = sys.stdin.readline

NEG_INF = -10**30

class SegTree2D:
    def __init__(self, xs, ys):
        self.nx = len(xs)
        self.ny = len(ys)
        self.xs = xs
        self.ys = ys
        self.t = [[NEG_INF] * (4 * self.ny) for _ in range(4 * self.nx)]
        self.lazy = [[0] * (4 * self.ny) for _ in range(4 * self.nx)]

    def _push_y(self, vx, vy):
        if self.lazy[vx][vy] != 0:
            val = self.lazy[vx][vy]
            self.t[vx][vy] += val
            if vy < 2 * self.ny:
                self.lazy[vx][vy*2] += val
                self.lazy[vx][vy*2+1] += val
            self.lazy[vx][vy] = 0

    def _push_x(self, vx, vy, vx2):
        if self.lazy[vx][vy] != 0:
            self.lazy[vx2][vy] += self.lazy[vx][vy]

    def update_y(self, vx, vy, ly, ry, ql, qr, val):
        self._push_y(vx, vy)
        if qr < ly or ry < ql:
            return
        if ql <= ly and ry <= qr:
            self.lazy[vx][vy] += val
            self._push_y(vx, vy)
            return
        mid = (ly + ry) // 2
        self.update_y(vx, vy*2, ly, mid, ql, qr, val)
        self.update_y(vx, vy*2+1, mid+1, ry, ql, qr, val)
        self.t[vx][vy] = max(self.t[vx][vy*2], self.t[vx][vy*2+1])

    def query_y(self, vx, vy, ly, ry, ql, qr):
        self._push_y(vx, vy)
        if qr < ly or ry < ql:
            return NEG_INF
        if ql <= ly and ry <= qr:
            return self.t[vx][vy]
        mid = (ly + ry) // 2
        return max(
            self.query_y(vx, vy*2, ly, mid, ql, qr),
            self.query_y(vx, vy*2+1, mid+1, ry, ql, qr)
        )

カットはセル上ではなくセル間にあるため、オフバイワン境界には注意が必要です。 これは、インターバルが包括的または半開として扱われるかどうかに影響し、一貫性のない処理はリージョン構造のサイレント破損につながります。

 ## 特殊なケース

 主なエッジケースは、更新が行われる前に複数のカットが単一の行または列を分離する場合です。 その状況では、単純な実装では更新をストリップ全体に伝播する可能性がありますが、正しい動作では、伝播は結果として生じる最小領域に厳密に制限されます。 セグメントベースの表現により、カットが挿入されると、その後の更新では元のグリッドではなく、調整された間隔のみが考慮されることが保証されます。 

1 または N に近い境界にカットが追加される場合、別のエッジ ケースが発生します。間隔のエンドポイントが半開セグメントとして処理されない場合、境界付近の更新が誤って隣接する領域に飛び出す可能性があります。 座標圧縮と厳密な間隔処理により、次のような極端な場合でも、各セルが正確に 1 つのセグメントにマッピングされることが保証されます。$x = 1$または$x = N-1$、オフバイワン伝播エラーを防ぎます。
