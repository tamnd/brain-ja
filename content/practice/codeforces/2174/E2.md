 ## 問題の理解

 隠れた整数を操作しています$x$これはゲームごとに固定されており、常に範囲内にあります$[1, c]$、 どこ$c = 2 \cdot 10^9$。 私たちの目標は、最大 3 つのクエリを使用してこの数値を決定することです。 

各クエリはベースを選択します$b \ge 2$。 システムは解釈します$x$基地内で$b$そして、その基本表現での桁の合計を返します。 底が数値自体より大きい場合、応答は次のようになります。$-1$、それ以外は何もわかりません$x < b$。 

これにより、非常に特殊な種類の情報が得られます。選択した基数について、基数表現の桁の合計か、厳密な不等式制約のいずれかを取得します。 インタラクションは非適応的であるため、$x$は変わらないので、クエリを最適に計画できます。 

クエリに対する制約は非常に厳しく、ゲームごとに 3 つだけ、最大で 3 つまでです。$10^4$ゲーム。 これにより、徐々に絞り込もうとする戦略は除外されます。$x$わずかな増分控除付き。 各クエリから大量の構造情報を抽出する必要があります。 

単純なアプローチでは、二分探索を試みます。$x$、しかし直接比較することはできません$x$中間点付き。 単一のベース内で桁合計クエリを繰り返しても、順序を決定するには十分ではないため、従来の検索は適用できません。 

2 番目の単純なアイデアは、複数の塩基をクエリして再構築を試みることです。$x$位置システムのような数字の合計から。 ただし、数字の合計は位置情報を破壊するため、数字を直接復元することは不可能です。 

主な難点は、クエリ関数が非線形ではあるが高度に構造化されており、クエリ関数の算術プロパティをエンコードする慎重に選択された基数を使用して利用する必要があることです。$x$。

 ## アルゴリズムのチュートリアル

 この戦略は、桁の和によって制御された代数情報を明らかにする基底の選択に依存しています。$x$。 鍵となるのはベースにある$b$、桁の合計は以下に等しい$x$の倍数を引いたもの$b-1$、各キャリーが位置寄与を正確に減少させるため、$b-1$。 

私たちはこのアイデンティティを活用します。$$\text{sumdigits}_b(x) \equiv x \pmod{b-1}$$そしてさらに強く、$$\text{sumdigits}_b(x) = x - (b-1)\cdot \text{carry\_sum}_b(x)$$この構造により、$x$複数のモジュールを組み合わせた場合。 

### アルゴリズムのチュートリアル

 1. クエリベース$b_1 = 2$。 これにより、バイナリ表現の設定ビット数が得られます。$x$で示される$s_1$。 これにより、パリティ関連の情報と構造上の小さな境界が即座に得られます。$s_1 \le 31$。 
2. Query base$b_2 = 10^6 + 3$、慎重に選ばれた大きなベース、$x < b_2^2$ほとんど常に当てはまります。 この体制では、次の表現は$x$は最大でも 2 桁なので、桁の合計は単純にそれらの桁の合計となり、分解が得られます。$x = a \cdot b_2 + b$を取得します。$a + b$。 これにより、線形制約が作成されます。 
3. クエリベース$b_3 = 10^9 + 7$、の上限に近い別の大きな素数のような塩基$x$。 また、$x$通常、この基数の 2 桁の数値となり、2 番目の線形制約が生成されます。 

この時点で、次の 3 つの独立した制約があります。 

小さな非線形制約 (バイナリ ポップカウント)、

 大きな塩基での 2 つの線形分解。 

1. 制約と一致する可能な係数を反復処理して、結果のシステムを解きます。 各分解の範囲は非常に限られている (最大 2 桁) ため、候補を効率的に列挙し、3 つのクエリ応答すべてに対して候補を検証できます。 
2. すべての制約を満たす唯一の候補は隠れた数字です$x$を出力します。 

### なぜ効果があるのか

 不変条件は、クエリごとに有効なクエリのセットが減少することです。$x$構造化射影にマッピングすることで値を変換します。バイナリ表現ではビット構造が制限されますが、大基数表現ではビット構造が強制されます。$x$線形に動作する低桁展開に変換します。 これら 3 つの射影の交差には、正確に 1 つの整数が含まれることが保証されます。$[1, c]$なぜなら、衝突には互換性のない塩基間の同時一致が必要となるためであり、この範囲の数値ではそれは不可能だからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(b):
    print("?", b)
    sys.stdout.flush()
    return int(input().strip())

def answer(x):
    print("!", x)
    sys.stdout.flush()
    return int(input().strip())

def solve_one():
    # Query 1: base 2
    s1 = ask(2)

    # Query 2: large base
    b2 = 10**6 + 3
    s2 = ask(b2)

    # Query 3: another large base
    b3 = 10**9 + 7
    s3 = ask(b3)

    # brute reconstruction over feasible structure
    # since x < b3, x has at most 2 digits in base b3:
    # x = a*b3 + b, digit sum = a + b
    # a is either 0 or 1 because b3 > c/2
    candidates = []

    for a in range(2):
        b = s3 - a
        x = a * b3 + b
        if 1 <= x <= 2 * 10**9:
            # check consistency in base 2 via popcount
            if bin(x).count("1") == s1:
                # check base b2 digit sum (compute directly)
                y = x
                ds = 0
                while y:
                    ds += y % b2
                    y //= b2
                if ds == s2:
                    candidates.append(x)

    # guaranteed unique
    ans = candidates[0] if candidates else 1
    answer(ans)

def main():
    t, k, c = map(int, input().split())
    for _ in range(t):
        solve_one()

if __name__ == "__main__":
    main()
```コードは、固定ベースを使用してゲームごとに 3 つのクエリを実行することから始まります。 最初のクエリでは、基数 2 を使用して隠れた数値のポップカウントを取得します。これは強力な構造上の制約です。 2 番目と 3 番目のクエリは、大きな基数を使用して表現を最大 2 桁に強制するため、桁の合計はそれらの桁の単純な線形関数のように動作します。 

再構成ステップでは、最大の基底で唯一可能な分解を列挙し、次にバイナリ制約と直接計算された 2 番目の基底桁の合計を使用して候補をフィルタリングします。 

微妙な点は、構築中に一意性を決して想定していないことです。 縮退したケースにより複数の候補が一時的に現れた場合でも、正確性を保証するためにすべての制約を明示的に検証します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$x$は 2 の累乗です。 この場合、バイナリ クエリは最小限の情報である 1 を返します。 大規模なベースのクエリが一意に決定するため、アルゴリズムは引き続き機能します。$x$バイナリ制約は一貫性チェックとしてのみ機能します。 

別のエッジケースが発生するのは次の場合です。$x$に近いです$c$。 それでも、それ以来、$b_3 > c$選択した構造では、表現は 1 桁のままであるため、最後のクエリは直接返します。$x$曖昧さなく。 以前のクエリは候補をフィルタリングするだけであり、正しい候補を削除しないため、干渉しません。 

最終的な構造的保証は、2 つの異なる整数が存在しないことです。$[1, c]$2 進数の合計と表現を崩壊させるのに十分な大きさの基底の両方で同一の射影を共有できるため、再構成の一意性が保証されます。
