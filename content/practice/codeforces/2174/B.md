 ## 問題の理解

 一連の数字を構築しています$b_1, b_2, \ldots, b_n$各友達が与える願い事カードの数を表しますが、各友達には上限があります$a_i$、そしてすべて$b_i$合計予算を超えることはできません$k$。 それぞれ$b_i$内に留まらなければなりません$0 \le b_i \le a_i$。 

それぞれの友人の後に$j$終わって、Aちゃんはこれまでのすべての贈り物を見て、見た中で最大の価値だけを覚えています。$\max(b_1, \ldots, b_j)$。 Her happiness after step$j$まさにその最大値です。 最終的なスコアは、これらの接頭辞の最大値の合計です。$j$。 

構造は重要です。一度大きな値が出現すると、それはその後のすべてのプレフィックスに寄与し続けます。 価値を置くなら$x$位置にある$i$、貢献します$x$で始まるすべての接尾辞に$i$ただし、後でこれより大きな値が表示されない場合に限ります。 

制約$k \le 360$がキー信号です。 それでも$n$到達できる$10^5$、私たちが配布する「リソース」の合計はわずかです。 依存するソリューション$k$状態はもっともらしいですが、二次関数はすべて$n$そうではありません。 

単純な試みでは、次のすべての割り当てを試みることになります。$b_i$ただし、値を個別に選択しても、すでにおおよその結果が得られます$(k+1)^n$可能性はありますが、それは完全に不可能です。 早い段階で大きな値を設定すると多くのプレフィックスが改善されますが、後で使用したほうがよい予算が消費されるため、貪欲な選択でも失敗します。 

初期の大規模な場合、微妙なエッジケースが発生します。$a_i$私たちに大きな割り当てをするよう誘惑する$b_i$すぐに。 たとえば、次の場合$a = [100, 1, 1]$そして$k=2$、選択する$b_1=2$局所的には最適に見えますが、それぞれの大きな値はプレフィックスの合計に長期的な乗算効果をもたらすため、後の位置に応じて異なる方法で分散することが最善の戦略である可能性があります。 

もう 1 つの特殊なケースは、$a_i = 0$。 これらのポジションは、最大値を直接増やすことはできませんが、選択した最大値が寄与し続ける時間を延長するため、順序付けにおいて依然として重要です。 

## アプローチ

 重要な観察は、最終的なスコアは、新しいプレフィックスの最大値となる値と、それらが導入される位置にのみ依存するということです。 新しい最大値が得られたら$x$の位置に表示されます$i$、後のすべてのプレフィックスは少なくとも貢献します$x$より大きな値が表示されるまで続けます。 

したがって、問題は次のとおりです。時間の経過とともに最大値となるいくつかの「ジャンプ」を選択します。各ジャンプにはコスト (値自体が総予算に寄与します) とメリット (時間セグメント全体に寄与します) があります。 

これは、使用されたカードの数と処理されたポジションの数に対する動的プログラミングを示唆しています。 ただし、実際には完全なシーケンス次元は必要ありません。 私たちが知る必要があるのは、これまでに使用したカードの数と、プレフィックスの処理中に蓄積できる貢献量だけです。

重要な構造は、現在の最大値を$x$に$x + d$位置にある$i$費用$d$カードを削除し、残りのすべてのサフィックス プレフィックスの寄与を増加させます。 なぜなら$k$が小さい場合、DP 状態を「使用したカードの数」と「現在の最大レベルでのこれまでの最高の合計貢献度」として扱うことができます。 

ポジションを反復処理し、ポジションごとに、現在の最大値を変更しないままにするか、最大値まで増やす遷移を許可します。$a_i$、費用の差額を支払います。 増加するたびに将来のすべての寄与が線形に変化するため、正確に使用した場合、各州が達成可能な最高の合計を追跡する DP を維持できます。$c$これまでのカードと現在の最大枚数は$x$。

 ## アルゴリズムのチュートリアル

 DP 配列を定義します。`dp[c]`は、友人の接頭語を処理した後に得られる最大の合計幸福度を表します。`c`カードの合計。 

また、選択した値を拡張することが将来のプレフィックスに寄与するという考えも維持しています。 プレフィックス最大値を明示的に追跡する代わりに、値を割り当てると、`v`位置にある`i`、貢献します`v`で始まるすべての接尾辞の貢献`i`。 

1.初期化`dp[0] = 0`他のすべての状態は非常に負の数になります。 これは、最初はカードを使用しておらず、貢献もないことを表します。 
2. 友達を左から右に処理します。 友達のところ`i`、このフレンドにカードを割り当てるかどうかに基づいて DP の更新を検討します。 
3. 考えられる各電流の合計使用量`c`、値を割り当てることを検討します。`x`位置を決める`i`、 どこ$0 \le x \le a_i$そして$c + x \le k$。 割り当ての貢献`x`位置にある`i`は:

 現在のプレフィックス寄与プラス`x * (n - i + 1)`なぜなら、一度新たな最大値が`x`が導入されると、残りのすべての接尾辞プレフィックスに対して存続します。 

この視点は、問題をポジションごとの重み付けされたナップザックの選択に変えるものです。 
4. 新しい DP アレイを更新します`ndp`からのすべての有効な遷移を試みることにより、`dp[c]`に`ndp[c + x]`。 
5. すべての値を処理した後、`x`それぞれに`i`、交換します`dp`と`ndp`。 
6. 最後に、答えはすべての最大値です`dp[c]`のために`c <= k`。 

重要なのは、各カードが最大値を維持する時間に応じて直線的に貢献し、DP により各ポジションに各ユニットを最適に割り当てることが保証されるということです。 

### なぜ効果があるのか

 不変条件は、最初の処理後の`i`ポジション、`dp[c]`正確に使用して、達成可能な最高の合計幸福度を保存します`c`カード、インデックスまでの友人のみを考慮`i`。 友人ごとのキャパシティやグローバル予算を超えることがないため、すべての移行で実現可能性が保たれます。 

正しさは、すべての有効な構造が次のとおりであるという事実から得られます。$b$は独立したポジションごとの寄与に分解でき、DP はそのような分布をすべて重複なく列挙します。 プレフィックスの最大動作は、割り当てられた各値の線形永続性によって捕捉されるため、将来の決定によって以前の貢献が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        NEG = -10**18
        dp = [NEG] * (k + 1)
        dp[0] = 0

        for i in range(n):
            ndp = [NEG] * (k + 1)

            for c in range(k + 1):
                if dp[c] < 0:
                    continue
                # option: assign x cards to friend i
                max_x = min(a[i], k - c)
                for x in range(max_x + 1):
                    nc = c + x
                    # contribution: x persists from position i onward
                    gain = dp[c] + x * (n - i)
                    if gain > ndp[nc]:
                        ndp[nc] = gain

            dp = ndp

        print(max(dp))

if __name__ == "__main__":
    solve()
```この実装では、使用されたカードの合計に対してナップザック スタイルの DP が維持されます。 内側のループでは、友達ごとの制限と残りの予算の両方を考慮して、現在の友達に渡すカードの枚数を列挙します。 

表現`x * (n - i)`寄与を現在の位置から累積すると解釈した場合に、影響を受けるサフィックス接頭辞の数を取得します。 DP の更新は、同じフレンドが複数回再利用されることを避けるために、新しい配列に対して行われます。 

微妙な詳細は、到​​達不可能な状態を大きな負の値で初期化することです。 これにより、無効な遷移が有効に見える結果に伝播するのを防ぎます。 また、繰り返し`c`ここでは別のを使用するため、上向きか下向きかは関係ありません。`ndp`。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。$a_i = 0$。 DP は 0 カードから決して移行しないため、答えはずっと 0 のままです。 少なくとも 1 つのプラスの割り当てを前提とした貪欲な試みは、誤って貢献を過大評価することになります。 

もう一つのケースは、大規模な場合です。$a_i$最後に登場します。 このアルゴリズムは、持続性を最大化するため、最終ポジションまで予算の支出を正しく遅らせます。 素朴な左から右への貪欲な割り当てでは、早期に誤って支出し、長期的な貢献を失うことになります。 

3 番目のケースは次の場合です。$k$個人に比べて大きい$a_i$でも全体的に小さい。 DP は複数のポジションにわたる部分的な割り当てを保証し、単一のステップで容量の完全な使用を強制することはなく、最適な分割動作を維持します。
