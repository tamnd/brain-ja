 ## 解決策
 ## 問題の理解

 一連の操作を使用してバイナリ シーケンスを段階的に構築するように求められます。 空のシーケンスから始めます`b`そして、それぞれの`n`演算では、どこかにゼロを挿入します。`b`そして、その位置より前のすべての要素を反転します。 正式に、ポジションを選択すると`p`、 最初`p`の要素`b`反転され (0 が 1、1 が 0 になります)、その後にゼロが挿入されます。 結局`n`オペレーション、私たちは望んでいます`b`指定されたターゲット配列と正確に一致する`a`。 

入力は複数のテスト ケースを与え、それぞれにシーケンスが含まれます。`a`までの長さ`10^5`、すべてのシーケンスの長さの合計は次のように制限されます。`10^5`。 これは、解が次の点で線形である必要があることを意味します。`n`各テスト ケースでは、演算の二次シミュレーションまたは単純なシミュレーションは最大で実行されるため、`n^2`動作し、2 秒の制限時間を超えます。 

明白ではないエッジケースは、次の最初の要素が存在する場合に発生します。`a`は`1`。 最初の操作では常にゼロが挿入され、その前に何も反転されないため、次の最初の要素は`b`最初の操作の後は常にゼロになります。 これにより、次で始まるシーケンスが作成されます。`1`建設不可能。 別の微妙なケースは、次のような交互パターンが存在する場合に発生します。`[0,1,0]`。 不注意な実装では、反転を考慮せずにゼロを順番に挿入しようとして、調整不可能なシーケンスに達する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、次のことをシミュレートします。`b`直接。 操作ごとに、可能なすべての挿入ポイントを試します`p`から`0`に`i-1`そして最初のものを反転します`p`要素。 これは正しいでしょうが、複雑さは次のとおりです。`O(n^2)`各反転が接触するため、テスト ケースごとに`p`要素と`n`操作では、これは実行不可能になります`n = 10^5`。 

重要な観察は、反転がトグルとして機能するということです。 配列全体を追跡するのではなく`b`現在のパリティ (反転したかどうか) を知り、最後からの効果をシミュレートするだけで済みます。`a`後ろ向きに。 最後の操作により、ある位置にゼロが挿入されていることがわかります。 このゼロは、次の図の右端のゼロに対応します。`b`手術前。 逆方向に反復することで`a`そして選択する`p`現在の反転状態に基づいて、シーケンス全体をシミュレートせずに各操作を決定できます。 具体的には、フラグを維持します。`flip`そして操作のリスト。 現在のビットがフリップ状態で予想されるゼロと一致する場合、最後に挿入できます (`p = i-1`）。 それ以外の場合は、挿入する前に最初の要素を反転する必要がある場合があります。 これにより、複雑さが軽減されます。`O(n)`テストケースごとに。 

ブルートフォースは操作定義に直接従うため機能しますが、大規模な処理には遅すぎます。`n`。 逆方向の作業とフリップの追跡に関する洞察は、`O(n^2)`シミュレーションを線形に変換する`O(n)`インバージョンの累積的な性質を利用した構築。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | フリップトラッキング (最適) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の最後の要素から開始します。`a`そして後ろに進みます。 フリップフラグを初期化して、`0`(反転はまだ適用されていません) および空のリスト`operations`。 
2. インデックスごとに`i`から`n-1`まで`0`、反転状態で現在のビットを確認します。 フリップフラグが設定されている場合は、次の点を考慮してください。`1`として`0`そして`0`として`1`。 
3. 現在のビットが次の場合`0`フリップの下に追加します`i`立場として`p`手術のために。 これにより、最初のゼロがこの位置に正しく配置されます。`i`必要に応じて要素を反転します。 
4. 現在のビットが次の場合`1`反転の下では、の最初の要素を反転する必要があります。`b`最初（に対応）`p = 0`) に挿入します。`i`。 追加`0`に続く`i`を操作リストに追加し、反転フラグを切り替えます。 
5. 逆方向に作成したため、最後に操作のリストを逆にします。 
6. の最初の要素が`a`は`1`、それは不可能なので「NO」を返します。 それ以外の場合は、「YES」と操作リストを返します。 

機能する理由: 各ステップで、累積反転の下で最後のゼロを正しく配置します。 逆方向に反復することで、達成すべき将来の状態が常にわかり、フリップ フラグは以前のすべての反転を追跡します。 これにより、挿入された各ゼロがすべての操作後に正しい位置に配置されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if a[0] == 1:
            print("NO")
            continue
        ops = []
        flip = 0
        for i in reversed(range(n)):
            cur = a[i] ^ flip
            if cur == 0:
                ops.append(i)
            else:
                ops.append(0)
                ops.append(i)
                flip ^= 1
        print("YES")
        print(" ".join(map(str, ops[::-1])))

if __name__ == "__main__":
    solve()
```コードは複数のテスト ケースを効率的に読み取ります。 各シーケンスについて、最初に次のような自明な不可能ケースをチェックします。`1`。 次に、`flip`変数を使用して、配列を変更せずに反転をシミュレートします。 操作を逆の順序で追加し、最後に逆にすると、操作リストが順方向のシーケンスに対応することが保証されます。
