 ## 解決策
 ## 問題の理解

 ランプのコレクションが与えられ、それぞれに 2 つのプロパティがあります。`a_i`そして`b_i`。 最初はすべてのランプが消灯しています。 消灯しているランプを点灯させると獲得できます`b_i`ポイント。 ただし、各操作の後、しきい値が以下のランプは`a_i`現在点灯しているランプの数以下になると壊れます。 壊れたランプを再びオンにすることはできず、壊れたランプは今後の動作の「オン カウント」に寄与しなくなります。 私たちの目標は、獲得できる合計ポイントを最大化することです。 

制約が教えてくれるのは`n`最大 200,000、および合計`n`テスト ケース全体の数も 200,000 に制限されます。 これにより、二次関数であるアルゴリズムが即座に除外されます。`n`, なぜなら、O(n²) は最悪の場合、4 × 10¹⁰ の演算に達するからです。 テスト ケースごとに O(n log n) または O(n) に近いアルゴリズムが必要です。 

ランプの出力が非常に低い場合、明白ではないエッジケースが発生します。`a_i`そして高い`b_i`。 点灯するのが早すぎると、他の価値の高いランプが壊れる可能性があるため、欲張りな戦略ではしきい値間の相互作用を考慮する必要があります。`a_i`そして報酬`b_i`。 たとえば、2 つのランプの場合:`(a=1, b=100)`そして`(a=2, b=1)`、最初のランプをオンにするとすぐに 100 ポイントを獲得できますが、2 番目のランプを安全にオンにすることはできません。 正しいアプローチは、高価値のランプを壊さないように、最初に低報酬のランプをオンにすることかもしれません。 

## アプローチ

 ブルートフォースアプローチは、ランプを点灯するすべての順列を試し、各ステップの後にどのランプが壊れたかを追跡し、合計ポイントを計算することです。 これはすべての可能性を検討するため、原理的には正しいですが、その複雑さは要因によって異なります。`n`(O(n!))、これはたとえ`n = 20`。 

問題をより注意深く観察すると、ランプの破損状態は現在点灯しているランプの数にのみ依存していることがわかります。 これは並べ替えのヒントです`a_i`、より高いランプ以来`a_i`壊れる前に、より多くのランプが点灯していることに耐えることができます。 指定されたオンカウントの間存続するランプの中で、最も高いランプを選択する必要があります。`b_i`まず、報酬が高いほど合計スコアへの寄与が大きくなるからです。 

重要な洞察は、考えられるすべての注文をシミュレーションする必要はないということです。 正確にオンにしたいことがわかっていれば、次のように推論できます。`k`破壊しきい値に達する前にランプを点灯するのが最善です`k`選択するランプは最高のものです`b_i`価値観。 これにより、問題は考えられるすべての数値をテストする問題に変換されます。`k`点灯させるランプの一番上を選択してください`k`報酬を確認し、次の条件を考慮してその構成を安全に達成できるかどうかを確認します。`a_i`しきい値。 

これにより、テスト ケースごとに O(n log n) のソリューションが得られます。ランプを次の順序で並べ替えます。`b_i`上位の報酬にすばやくアクセスし、可能な数を繰り返し、十分なランプが存在することを確認します。`a_i >= k`許可する`k`操作。

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、ランプの数を読み取ります。`n`そして彼らの`(a_i, b_i)`価値観。 
2. ランプを降順に並べ替えます。`b_i`。 これにより、点灯するランプを選択するときに、常に最高の報酬を最初に考慮することが保証されます。 
3. 最大ヒープまたはソートを初期化する`a_i`値を使用して、指定されたオンカウントでどれだけのランプが存続できるかを効率的にカウントします。 
4. 可能な数の操作を繰り返す`k`1から`n`。 それぞれについて`k`、ランプが何個あるか数えてください`a_i >= k`。 この数が少なくとも`k`そうすると、安全に電源をオンにすることができます`k`戦略を壊すことなくランプを使用できます。 
5. 有効なすべての中で`k`、上位の合計が最大になるものを選択します。`k` `b_i`価値観。 
6. 最大合計点を出力します。 

なぜ機能するのか: 不変条件は、選択したランプの数に関係なく、`k`を選択できます。`k`最大の報酬を持つランプであり、そのしきい値により生き残ることができます。 より低い報酬を選択しても合計を向上させることはできず、不十分なランプを選択するため、これより良い組み合わせは存在しません。`a_i`早期破損の原因となり、安全性を損ないます。 この推論により、アルゴリズムが最適な合計ポイントを見つけることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        lamps = []
        for _ in range(n):
            a, b = map(int, input().split())
            lamps.append((a, b))
        
        # Sort lamps by b_i descending
        lamps.sort(key=lambda x: -x[1])
        
        # Precompute b_i prefix sums for efficiency
        b_prefix = [0]
        for a, b in lamps:
            b_prefix.append(b_prefix[-1] + b)
        
        # Sort a_i ascending
        a_sorted = sorted(a for a, b in lamps)
        
        max_points = 0
        for k in range(1, n + 1):
            # Count how many lamps have a_i >= k
            count = n - (lower_bound(a_sorted, k))
            if count >= k:
                max_points = max(max_points, b_prefix[k])
        
        print(max_points)

def lower_bound(arr, target):
    """Returns first index where arr[index] >= target"""
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

if __name__ == "__main__":
    solve()
```このソリューションでは、まず報酬別にランプを並べ替えて、価値の高いランプに焦点を当てます。 次に、上位の報酬を効率的に合計するためにプレフィックス合計配列を使用します。 の`lower_bound`各候補に対して十分な閾値を備えたランプを効率的にカウントする機能`k`、完全な線形スキャンを回避し、複雑さを O(n log n) に保ちます。 

微妙な選択には、プレフィックスの合計を正しく計算することが含まれます (`b_prefix[0] = 0`)、比較の処理`a_i >= k`二分探索を使用して O(n²) カウントを回避します。
