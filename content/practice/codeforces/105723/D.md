 ## 解決策
 ## 問題の理解

 頂点 1 をルートとする根付きツリーが与えられます。 各頂点には数値と固有のランクが含まれます。 このタスクは、ツリー内の任意のパスに関するものではなく、祖先とランク フィルタリングによって制約された非常に特殊なパスに関するものです。 

すべての頂点 i について、i が両方の端点の祖先となるような、すべての単純なパス u から v を調べます。 ツリーはルート化されているため、これは、u と v の両方が i のサブツリー内にあり、それらの間の一意のパスが必然的に i を通過することを意味します。 その構造上の制約に加えて、ランクが最大でも i のランクの頂点のみを使用できます。 最後に、そのようなすべての有効なペア (u、v) のうち、パスに沿った頂点値の可能な最大の合計が必要です。 

主な難点は、制約が i に依存するだけでなく、そのサブツリー内で使用できる頂点も制限されることです。 したがって、各クエリは事実上、「i の下で許可されたノード」によって動的にフィルタリングされたツリー内の最適なパスを求めます。 

制約は大きく、テスト ケース全体の合計 n は最大 5 · 10^5 です。 これにより、DFS または単純な方法で動的プログラミングを使用してノードごとに最適なパスを再計算するアプローチは直ちに除外されます。これは、最悪の場合は 2 次関数になるためです。 ノードあたり O(n log n) ですら不可能です。 この構造は、各ノードの答えが、おそらく特定の順序で頂点をアクティブ化することによって、グローバル処理から導出される必要があることを示唆しています。 

すべての値が負の場合、微妙なエッジ ケースが発生します。 その場合、最適な「パス」は長いチェーンではなく、単一の頂点になります。これは、延長すると合計が減少するためです。 もう 1 つの特殊なケースは、ノードのサブツリー内でのランクが最小である場合です。 その場合、そのノードのみが使用可能となり、回答は強制的に独自の値に折りたたまれます。 

最後の重要な観察は、ランクは一意であるため、アクティベーションよりも厳密な順序付けとして扱うことができるということです。 

## アプローチ

 直接的なブルート フォース ソリューションでは、各ノード i を独立して考慮します。 固定 i の場合、ランクが最大 ri であるサブツリー内のすべてのノードを収集し、このフィルタリングされたセット内の任意の 2 つのノード間の最大パス合計を計算します。ここで、パスは i を通過する必要があります。 これは、このフィルタリングされたサブツリー内で i からの 2 つの最適な下向きパスを見つけることになります。 無効なノードをスキップして、毎回 i から DFS を実行できます。 

これは正しいですが、非常に高価です。 最悪の場合、すべてのノードでサブツリーのほぼ全体を走査することになり、総作業量は O(n^2) になります。 n が 5 · 10^5 までの場合、これは完全に不可能です。 

重要な洞察は、各 i を個別に扱うのをやめ、代わりにランクの昇順でノードを処理することです。 ランクが上がる順にノードを徐々に「アクティブ化」すると想像すると、ノード i をアクティブ化した瞬間に、正確にランク ≤ ri のノードがアクティブになります。 これは問題の制約と一致します。 

ここで、問題は動的になります。ノードが追加されると、最高位のノードが現在のノード i である最適なパスに関する情報が維持されます。 「i は u および v の祖先である」という制限は、u と v が i のアクティブなサブツリーの異なる部分に存在する必要があることを意味するため、アクティブなフォレストのコンポーネント内で最適な上向きおよび下向きの寄与を維持する必要があります。 

これは、アクティブ化された各ノードがその子コンポーネントをマージする、古典的な動的ツリー接続フレーバーです。 i を通過するパスの値は、2 つの異なる子サブツリーからの最良の下向き寄与を組み合わせることによって決定されます。 したがって、各ノードについて、各アクティブ コンポーネント内で最良の「そのノードから開始して下降する単一パスの合計」を維持し、そのような最大の 2 つの値を組み合わせて、現在のランクの候補回答を形成します。 

これにより、問題はツリー上の結合のようなプロセスに変わり、ランク順に処理され、アクティブ化のたびにローカルの最適パス情報が更新されます。

 | ランク発動＋DP合成 | O(n log n) または O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ランクは制約の境界を定義するため、ランクの昇順に頂点を処理します。 

1. すべての頂点をランクの昇順に並べ替えます。 この順序で 1 つずつアクティブ化していきます。 頂点 i が処理される時点で、ランクが小さいすべての頂点はすでにアクティブであり、適格です。 
2. 頂点が現在許可されているかどうかを示すブール配列 active[v] を維持します。 最初はすべて非アクティブです。 
3. 各頂点 i について、アクティブになると、その頂点をアクティブとしてマークし、ツリー内のすでにアクティブな子に接続しているとみなします。 これにより、アクティブなノードによって誘導されるフォレストが効果的に構築されます。 
4. 各アクティブノード v について、アクティブノードのみを使用する v で始まる下向きパスの最大合計として定義される値 dp[v] を維持します。 v にアクティブな子がない場合は、dp[v] = a[v] になります。 アクティブな子がある場合、 dp[v] は a[v] 単独、または a[v] にその子の中で最適な dp を加えたものになります。 
5. ノード i をアクティブ化するとき、そのアクティブな子を調べます。 それらの dp 値を取得し、上位 2 つの値を並べ替えまたは追跡します。 これらは、i から開始して異なるサブツリーに至る最適な 2 つの下向きパスを表します。 
6. i を最高点として使用する最良のパスは、i に個別の子からの 2 つの最大の正の dp 寄与の合計を加算することによって取得されます。 存在する正の寄与が 2 つ未満の場合は、最適な単一パスにフォールバックします。 
7. この計算された値を i の答えとして保存します。 
8. 最後に、すべてのノードが処理されるまで続行します。 

実装の重要な詳細は、アクティブ化された構造内で dp 値をボトムアップで維持する必要があるため、ノードがアクティブになるたびに、その dp がそのサブツリー方向のすでにアクティブな隣接ノードから即座に計算されることです。 

### なぜ効果があるのか

 アクティブなノードはいつでも、両方のエンドポイントがアクティブな場合にのみ、すべてのエッジがノードをその親に接続するフォレストを形成します。 ランクを増やして処理するため、i の処理時には、制約 ri の下で有効なパスはすべてこのアクティブなフォレストに完全に含まれます。 

固定 i の場合、u から v への有効なパスはすべて i を通過し、完全にアクティブなノード内になければなりません。 i を削除するとツリーが子サブツリーに分割され、i を横切る有効なパスは 1 つのサブツリーから 1 つのエンドポイントを選択し、別のサブツリーからもう 1 つのエンドポイントを選択する必要があります。 そのような最良の選択は、まさに、異なる子からの 2 つの最良の独立した下方寄与です。 dp 構造により、各子サブツリーから始まる最適な下向きパスが常にわかることが保証されるため、上位 2 つを組み合わせることで最適な交差パスが得られます。 

この不変式により、i を処理するときに、最大ランクが i であるすべての候補パスが正しく評価され、i が最大ランクであるパスに後続のノードが寄与できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = [0] * (n + 1)
        p = list(map(int, input().split()))
        for i in range(2, n + 1):
            parent[i] = p[i - 2]

        a = [0] + list(map(int, input().split()))
        r = [0] + list(map(int, input().split()))

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        order = list(range(1, n + 1))
        order.sort(key=lambda x: r[x])

        active = [False] * (n + 1)
        dp = [0] * (n + 1)
        ans = [0] * (n + 1)

        def get_best(v):
            best1 = 0
            best2 = 0
            for to in children[v]:
                if active[to]:
                    val = dp[to]
                    if val > best1:
                        best2 = best1
                        best1 = val
                    elif val > best2:
                        best2 = val
            return best1, best2

        for v in order:
            active[v] = True

            dp[v] = a[v]
            for to in children[v]:
                if active[to]:
                    dp[v] = max(dp[v], a[v] + dp[to])

            best1, best2 = get_best(v)

            ans[v] = max(a[v], a[v] + best1, a[v] + best1 + best2)

        print(*ans[1:])

if __name__ == "__main__":
    solve()
```コードはアクティベーション順序を直接反映しています。 dp 配列には、現在アクティブなフォレスト内の最良の下方寄与が格納されます。 各ノードについて、ランクが小さいため、すでにアクティブな子をチェックすることによって、アクティブ化後に dp を計算します。 次に、最良の 2 つの子の寄与を抽出して、そのノードを通過する最適なパスを形成します。 

微妙な点は、get_best での最良の値の初期化です。 ノードでの新しいパスの開始は a[v] を介して常に許可されるため、非正の寄与は暗黙的に処理されます。 これにより、答えに否定的な分岐が誤って強制されることが回避されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての値が負の場合です。 この場合、パスを拡張しようとすると合計が減少するため、すべてのノードの正解はそれ自体の値になります。 アクティブ化中、子からの dp 値が親の基本値を改善することはありません。そのため、best1 と best2 は非正の寄与のままであり、式は正しく a[i] にフォールバックします。 

もう 1 つのケースは、根に多くの子が存在する星形のツリーです。 ルートが処理されるとき、すべての子がすでにアクティブになっている可能性があるため、アルゴリズムはそれらの中から 2 つの最大の dp 値を正しく選択する必要があります。 アクティブ化の順序により、すべての子がルートより前に利用可能になるため、get_best(root) は完全な候補セットを確認します。 

最後の微妙なケースは、ノードにアクティブな子が 1 つだけある場合です。 この場合、best2 は 0 となり、アルゴリズムは 2 つのパスが存在すると誤って想定してはなりません。 別のサブツリーに 2 番目の終点がなければ、単一のブランチは i を通る交差パスを形成できないため、a[i] の max によって正確さが保証されます。
