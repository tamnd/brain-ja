 ## 解決策
 ## 問題の理解

 文字だけからなる文字列が与えられます`a`、`b`、 そして`c`。 文字列には、2 つの等しい文字が隣り合わないことが保証されており、3 つの文字すべてが文字列内のどこかに少なくとも 1 回は出現します。 

タスクは、少なくとも 1 つを含む、この文字列の最も短い連続セグメントを見つけることです。`a`、少なくとも 1 つ`b`、少なくとも 1 つ`c`。 言い換えれば、すべての部分文字列の中で、3 つのシンボルすべてを「カバーする」ウィンドウの最小長が必要です。 

入力サイズは最大 100,000 文字まで可能です。 すべての部分文字列の列挙は最悪の場合でも 2 次であり、約 10^10 の演算が必要になるため、すべての部分文字列を明示的に調べようとするものは即座に除外されます。 有効なウィンドウをネストしたループでも遅すぎます。 

隣接する 2 つの文字が等しくないという隣接制約は、構造的には重要ですが、正確さのために厳密に必要というわけではありません。 これは主に、同じキャラクターの長期実行などの病的なケースを防ぎます。 ただし、それがなくても、中心的な問題は同じままです。つまり、3 つの異なるシンボルを含む最小限のウィンドウが必要です。 

いくつかの危険な状況については注意する価値があります。 

文字列がすでに次のようなものである場合`abc`の場合、文字列全体が可能な限り最小の有効な部分文字列であるため、答えは 3 です。 ウィンドウを誤って積極的にリセットする単純なアプローチでは、これを見逃してしまう可能性があります。 

たとえば文字が広がっている場合`abacbc`場合、最適な部分文字列は、最後の欠落文字が表示される場所で終了する可能性があります。 再起動が早すぎる単純な貪欲スキャンでは、以前の有効なセグメント内で開始される短いウィンドウを見逃す可能性があります。 

もう 1 つの微妙なケースは、複数の有効な部分文字列が重なり合う場合です。 例えば`abcbac`、いくつかのウィンドウには 3 文字すべてが含まれており、最小文字は必ずしも明確な境界に揃っているとは限りません。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての部分文字列をチェックし、各部分文字列のカウントをチェックします。`a`、`b`、 そして`c`全部登場する。 O(n^2) 個の部分文字列があり、各チェックのコストは直接実行した場合は O(n)、事前に計算された度数表を使用した場合は O(1) ですが、全体では依然として O(n^2) です。 n が最大 100000 であるため、これは実現可能な限界をはるかに超えています。 

すべての部分文字列を個別に考慮する必要がないことに気づくことで、これを改善できます。 代わりに、特定の位置で終了するウィンドウのみを考慮します。 右のエンドポイントを修正した場合、最適な左のエンドポイントは、各文字が表示される最新の位置によって決まります。 

どのインデックスでも`i`、最後に確認された位置がわかっているとします。`a`、`b`、 そして`c`まで`i`。 3 つすべてが少なくとも 1 回出現した場合、次で終わる有効な部分文字列はすべて`i`遅くとも、最後に確認されたポジションのうちの最小のポジ​​ションより前に開始する必要があります。 それより早く開始すると不要な文字が含まれ、後で開始すると必要な文字の 1 つが削除されます。 これにより、O(1) の各位置で終了する最適なウィンドウ、つまり O(n) の完全な答えを計算する直接的な方法が得られます。 

これにより、問題は部分文字列の列挙から 3 つのポインターの維持に変わります。

 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字が出現した最新のインデックスを維持しながら、文字列を左から右に処理します。 

1. 3 つの変数を初期化する`last_a`、`last_b`、 そして`last_c`to indicate that none of the characters have been seen yet. 変数も保持します`ans`非常に大きな数値に初期化されます。 これは、これまでに見つかった最良の答えを表しています。 
2. インデックス付きの文字列を反復処理します。`i`。 各ステップで、次のいずれかに応じて、対応する最後に表示された位置を更新します。`s[i]`は`a`、`b`、 または`c`。 これにより、いつでも、その位置までの各文字の最新の出現が保証されます。`i`。 
3. 更新後、最後に表示された 3 つの位置がすべて有効かどうかを確認します。 それらのいずれかがまだ初期化されていない場合、次で終わる有効な部分文字列を形成できません。`i`, そのため、このステップの残りの部分は省略します。 
4. 3 つの文字がすべて表示されている場合は、最後に表示された 3 つの位置のうち最も早い位置を計算します。 この位置は、次で終わる最小の有効な部分文字列の左境界になります。`i`これにはまだ 3 つの文字がすべて含まれています。 
5. この部分文字列の長さを次のように計算します。`i - min(last_a, last_b, last_c) + 1`、更新します`ans`この長さが現在のベストよりも短い場合。 
6. 文字列の終わりまで続けます。 最終的な答えは、記録された最小値です。 

なぜこれが正しい左境界なのかが重要なポイントです。 で終わる任意の部分文字列`i`各文字が少なくとも 1 回含まれる必要があります。 以前またはその時点での各文字の最新の出現`i`は、不必要に拡張せずに含めることを保証する唯一の候補です。 最小の有効なウィンドウは、これらの必要な最後の出現の最も早い時点で強制的に開始されます。 

### なぜ効果があるのか

 すべてのインデックスで`i`の場合、アルゴリズムは、次で終わる可能な限り最良の部分文字列を暗黙的に考慮します。`i`。 不変条件というのは、`last_a`、`last_b`、 そして`last_c`常にそれぞれのキャラクターの最新の位置を表します。`i`。 次で終わる任意の有効な部分文字列`i`各文字が少なくとも 1 回出現する必要があるため、これらの最後の出現時またはその前に開始する必要があります。 可能な限りタイトなスタートは、それらの最小値です。 これにより、次で終わる有効な部分文字列が存在しないことが保証されます。`i`構築されたものよりも短くなる可能性があるため、すべての最小値を取得します。`i`大域的最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    last = {'a': -1, 'b': -1, 'c': -1}
    ans = 10**18
    
    for i, ch in enumerate(s):
        last[ch] = i
        
        if last['a'] != -1 and last['b'] != -1 and last['c'] != -1:
            start = min(last['a'], last['b'], last['c'])
            ans = min(ans, i - start + 1)
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、最後に見た位置を追跡するというアイデアを直接実装しています。 辞書`last`各文字のインデックスを格納します。 先に進むたびに 1 つのエントリを更新し、3 つの文字がすべて表示されたかどうかをすぐに確認します。 

重要な詳細は、最後の出現の最小値を計算することです。 このステップは、ウィンドウには各文字の最新の必要な外観が含まれなければならないという事実をエンコードします。 

オフバイワンハンドリングは、`+1`両方の端点が含まれるため、長さの式に含めます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    last = {'a': -1, 'b': -1, 'c': -1}
    ans = 10**18
    
    s = input().strip()
    for i, ch in enumerate(s):
        last[ch] = i
        if last['a'] != -1 and last['b'] != -1 and last['c'] != -1:
            start = min(last['a'], last['b'], last['c'])
            ans = min(ans, i - start + 1)
    
    return str(ans)

# provided sample
assert run("abac\n") == "3"

# minimum length case
assert run("abc\n") == "3"

# symmetric shuffle
assert run("cab\n") == "3"

# longer mixed case
assert run("abcbac\n") == "3"

# alternating spread
assert run("acbabc\n") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`abc`| 3 | 最小有効ウィンドウ |
 |`cab`| 3 | 順列順序 |
 |`abcbac`| 3 | 最適なウィンドウをオーバーラップ |
 |`acbabc`| 3 | リセットと再利用の繰り返し |

 ## 特殊なケース

 次のような非常に短い入力の場合`abc`の場合、アルゴリズムはすべての最後の位置を即座に更新し、最後のインデックスで有効なウィンドウを生成します。 最後に出現したものの最小値は 0 になるため、答えは 3 になります。 

次のような高度にインターリーブされた文字列の場合、`abcbac`、複数の有効なウィンドウが表示されます。 このアルゴリズムは、単一の「最初の」ウィンドウを選択しようとはしません。 すべてのエンドポイントを個別に評価し、後のウィンドウが以前のより優れたウィンドウを隠すことができないようにします。 

キャラクターの登場が遅い場合など`aaabbbccc`隣接関係の制限が削除された場合でも、このメソッドは最後の出現を正しく追跡し、すべての文字が検出された場合にのみ有効なウィンドウを形成します。その後は、新しい出現のたびに終了するより厳密なウィンドウを使用して応答を継続的に更新します。
