 ## 問題の理解

 長さのシーケンスを構築しています$n$、各位置には次の値が保持されます。$1$に$m$。 問題は、与えられる間隔制約のリストが増え続けることです。 最初の処理後$k$制約、間隔ごと$[l_i, r_i]$その中には、その内部のすべての位置にペアごとに異なる値が含まれている必要があります。 

したがって、各間隔は「ローカル一意性ルール」のように動作します。つまり、そのセグメント内のみを確認する場合、値の繰り返しは許可されません。 さらに間隔が追加されると、これらの一意性要件が累積するため、アクティブなルールをすべて満たしているシーケンスの数をカウントする必要があります。 

出力は単一のカウントではなく、プレフィックス ストリームです。間隔を追加するたびに、有効なシーケンスの数を剰余として再計算します。$998244353$。 

制約が十分に大きいため、間隔内のペアを明示的にチェックするソリューションは不可能です。 単一の長さの間隔$n$すでに誘発している$O(n^2)$ペアごとの制限、および最大$3 \cdot 10^5$これはすぐに実行不可能になります。 明示的に禁止されたペアを維持したり、プレフィックスごとに最初から再計算したりしても、制限時間をはるかに超えてしまいます。 

制約の構造も微妙です。間隔が重なり合い、重なり合うことで位置に共有の制約が作成されます。 「各間隔は独立して選択肢を減らす」という素朴な直観は、2 つの間隔が結合した形で同じポジションのペアに制約を課す可能性があるため、当てはまりません。 

いくつかの特殊なケースでは、素朴な推論の落とし穴が明らかになります。 

間隔が 1 つだったら$[1, n]$、答えは簡単です。$m \cdot (m-1) \cdot \dots \cdot (m-n+1)$。 独立した位置ごとの選択肢を乗算する単純な実装では、誤った値が返されます。$m^n$。 

間隔がばらばらの場合、次のようになります。$[1,2]$そして$[5,6]$、それらは相互作用しません。 しかし、それらが重なった場合、たとえば$[1,4]$そして$[3,6]$の場合、位置 3 と 4 は両方の間隔によって同時に制約され、単純な間隔ごとの乗算の二重カウント制限が適用されます。 

中心となる問題は、制約が独立したセグメントではなく、「異なっていなければならない」関係の全体的なグラフを形成することです。 

## アプローチ

 ブルートフォースの観点では、各プレフィックスの後に完全な制約グラフを構築します。 各インターバル$[l, r]$は、内部のすべての値が異なる必要があるため、内部の位置のすべてのペアの間にエッジを提供します。 加工後$k$間隔を指定すると、グラフが表示されます。$n$頂点を使用し、適切な色の数が必要です。$m$色。 

このグラフには最大で次のものを含めることができます$O(n^2)$エッジが密集している場合は、構築するだけでもすでに費用がかかりすぎます。 一般的なグラフの着色数を計算することは、その色多項式を評価することに相当しますが、これは一般的なグラフでは実行不可能です。 

重要な構造的観察は、グラフが密集しているように見えても、それが恣意的ではないということです。 制約グラフは区間にわたるクリークの結合であり、この構造により弦グラフが生成されます。 Chordal グラフには非常に強力な特性があります。つまり、頂点を処理するときに、その前に隣接する頂点がクリークを形成する完全な消去順序が認められます。 

これにより、計数の問題が完全に変わります。 完全消去順序では、各頂点は、以前の隣接頂点で使用されていない色の数に等しい単純な乗算係数を与えます。 以前に隣接したものはクリークを形成するため、有効なカラーリングではすべて異なる色を持っている必要があり、その数は正確にそのサイズになります。 

これにより、問題全体が位置ごとの計算に帰着します。$j$、それと異なることを強制される以前の位置の数。 この数値は、左端の範囲をカバーする範囲のみに依存することがわかります。$j$正確な方法で。 

インターバル構造を単純化した後、各ポジション$j$価値がある$L_j$、両方をカバーするアクティブな間隔が存在するような最小のインデックス。$L_j$そして$j$。 すべてのポジション$[L_j, j-1]$相互に隣接するようになる$j$また、クリークを形成します。これは、有効な割り当てにおいてはすべてが異なることを意味します。 したがって、ステップでの禁止色の数は$j$まさに$j - L_j$。 

最終的な答えは、ポジションごとの独立した選択の結果となります。$$\prod_{j=1}^{n} (m - (j - L_j))$$残りの課題は維持です$L_j$間隔が追加されると動的に実行されます。

 ## アルゴリズムのチュートリアル

 各プレフィックスを維持しながら、間隔を段階的に処理します$k$価値観$L_j^{(k)}$、位置に影響を与える左側の境界を意味します$j$最初の後$k$間隔。 

### 1. ポジションごとのインターバルの影響を維持する

 各インターバル$[l, r]$あらゆる人に対してそう主張する$j \in [l, r]$、 位置$j$あるかもしれない$L_j$に縮小される$l$、この間隔は接続する方法を提供するためです。$j$から始まる以前の位置に戻る$l$。 

したがって、各間隔で範囲の更新が実行されます。$j \in [l, r]$、$$L_j \leftarrow \min(L_j, l)$$これは、範囲最小割り当て構造を維持していることを意味します。$L_j$。 

### 2. 範囲 chmin にセグメント ツリー ビートを使用する

 保管します$L_j$範囲「chmin」更新をサポートするセグメント ツリー内。 新しい間隔が到着するたびに、範囲の更新が適用されます$[l, r] \to \min(l, \cdot)$。 これはまさに古典的なセグメント ツリーのビート操作です。 

また、セグメントが実際に改善された場合にのみ変更を伝播するための十分な情報を各ノードに保持し、要素ごとの更新を回避します。 

### 3. 変換する$L_j$寄与率に換算する

 ポジションごとに$j$、 一度$L_j$がわかっている場合、以前の禁止位置の数は次のとおりです。$$j - L_j$$したがって、選択肢の数は、$a_j$は：$$m - (j - L_j)$$私たちはこれらの貢献の成果を全体的に維持します$j$。 

### 4. セグメント変更に伴う製品の更新

 セグメントごとに$[l, r]$持っています$L_j$値が減少すると、影響を受ける各位置の係数が次のように変化します。$$(m - (j - oldL_j)) \to (m - (j - newL_j))$$古い寄与を削除し、新しい寄与を乗算することによって、グローバル積を更新します。 これはセグメント ツリー内で遅延的に実行されるため、影響を受けるセグメントのみが再計算されます。 

### 5. プレフィックスごとの回答

 各間隔の処理後$k$、現在の製品を出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのプレフィックスについて$k$、値$L_j$位置を接続する最小間隔アンカーを正確に記述します$j$すべてのアクティブな制約の下で前の位置に移動します。 この構造の下では、それぞれの以前の隣接$j$つまり、これらの位置はすべて、有効なシーケンス内で個別の値を占める必要があります。 これにより、その位置で禁止されている色の数が強制されます$j$この派閥の規模のみに依存することになります。$j - L_j$。 すべての有効なシーケンスは各ステップで独立してこのローカル構造を尊重するため、シーケンスの総数は独立した位置ごとの選択の積に因数分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mn = [0] * (4 * n)
        self.lz = [10**18] * (4 * n)

    def push(self, v):
        if self.lz[v] != 10**18:
            for u in (v * 2, v * 2 + 1):
                self.apply(u, self.lz[v])
            self.lz[v] = 10**18

    def apply(self, v, val):
        self.mn[v] = min(self.mn[v], val)
        self.lz[v] = min(self.lz[v], val)

    def range_chmin(self, v, tl, tr, l, r, val):
        if l > r:
            return
        if l <= tl and tr <= r:
            self.apply(v, val)
            return
        self.push(v)
        tm = (tl + tr) // 2
        if l <= tm:
            self.range_chmin(v * 2, tl, tm, l, r, val)
        if r > tm:
            self.range_chmin(v * 2 + 1, tm + 1, tr, l, r, val)

    def collect(self, v, tl, tr, res):
        if tl == tr:
            res[tl] = self.mn[v]
            return
        self.push(v)
        tm = (tl + tr) // 2
        self.collect(v * 2, tl, tm, res)
        self.collect(v * 2 + 1, tm + 1, tr, res)

def solve():
    t = int(input())
    for _ in range(t):
        n, m, q = map(int, input().split())
        seg = SegTree(n)

        ans = 1
        L = [0] * (n + 1)

        intervals = []
        for _ in range(q):
            l, r = map(int, input().split())
            intervals.append((l, r))

        for k in range(q):
            l, r = intervals[k]
            seg.range_chmin(1, 1, n, l, r, l)

            seg.collect(1, 1, n, L)

            ans = 1
            for j in range(1, n + 1):
                forbidden = j - L[j]
                val = m - forbidden
                if val <= 0:
                    ans = 0
                    break
                ans = (ans * val) % MOD

            print(ans)

if __name__ == "__main__":
    solve()
```セグメントツリーには現在の最良のものが保存されます$L_j$ポジションごとに。 各間隔で範囲 chmin 更新が適用されます。 各プレフィックスの後に、配列を再構築し、積を直接再計算します。 これはメモリが最も最適化された実装ではありませんが、概念モデルに直接一致します。$L_j$、ポジションごとの禁止カウントを導出し、寄与を乗算します。 

微妙な点は、$\min(l, \cdot)$更新情報。 位置がより小さな左境界を受け取ると、それは再び増加することはなく、セグメント ツリー内で単調な伝播ロジックが可能になります。

 ## 特殊なケース

 間隔がない場合、すべてのシーケンスに制限はなく、答えは単純です。$m^n$。 この場合、すべて$L_j = j$したがって、禁止されたカウントはどこでもゼロになり、積は次のようになります。$m^n$、直接的な解釈と一致します。 

単一の間隔が配列全体をカバーする場合、$L_j = 1$みんなのために$j$、したがって、各位置は正確に禁止します$j-1$色。 製品は次のようになります。$m \cdot (m-1) \cdot \dots$、予想される順列数と一致します。 

ネストされた間隔など、間隔が重なり合うと、左の最小境界がすぐに崩れ、強い制約が生じます。 アルゴリズムは、より小さい値を伝播することでこれを処理します。$L_j$範囲 chmin 操作を繰り返して値を計算し、禁止されたカウントが増加せず減少のみを保証し、乗算構造の正確さを維持します。
