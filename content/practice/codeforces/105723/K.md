 ## 解決策
 ## 問題の理解

 マルチタイプの括弧システムと同様に、適切に入れ子になった構造のように動作する一連の符号付き整数が与えられます。 各値は、その正と負の出現が一致するペアを形成するという意味で、正確に 2 回出現します。また、ネスト構造により、これらのペアが互いに素であるか、適切にネストされ、任意に交差することがないことが保証されます。 

このシーケンスから、すべてのクエリは、同じネスト ルールの下でバランスが保たれていることが保証された連続セグメントを提供します。 このようなセグメントごとに、各サブシーケンスが「プライマリ」になるように、最小数のサブシーケンスに分割する必要があります。 主部分列は非常に厳密な形状をしています。すべての正の数が最初に来て、その後にすべての負の数が続きます。また、元の列によって引き起こされたペア構造を尊重する必要があります。 

主な難点は、セグメント内の要素の順序を変更することはできず、サブシーケンスを形成する場合にのみ要素を削除することができ、各要素は 1 つのサブシーケンスに属さなければならないことです。 

この制約により、オフラインのクエリごとの構造、または少なくとも対数クエリ処理が強制されます。 テストごとに最大 10^5 の要素と全体で 10^5 のクエリを使用する場合、パーティションを明示的にシミュレートしたり、セグメントを繰り返しスキャンしようとするアプローチは時間制限を超えます。 クエリごとのソリューションが O (セグメントの長さ) であっても、最悪の場合は 10^10 の演算が必要になりますが、これは実行不可能です。 

微妙なエッジ条件は、すべてのクエリ セグメントのバランスがすでに保証されているということです。 これにより、セグメント内の構造の正確性を検証する必要がなくなりましたが、内部のペアリングの依存関係は単純化されません。 

単純な間違いは、セグメントのバランスが取れているため、答えは常に 1 であると想定することです。たとえば、[1, 2, -2, -1, 3, -3] のようなセグメントについて考えてみましょう。 これはバランスが取れていますが、入れ子構造により複数の独立したチェーンが強制されるため、単一の基本サブシーケンスを形成することはできません。 

もう 1 つの失敗モードは、左から右にスキャンし、初期にネガティブが現れるたびに新しいサブシーケンスを開始することで、貪欲にサブシーケンスを構築しようとすることです。 構造が線形ではなく階層的であるため、これは問題になります。 

## アプローチ

 ブルート フォース ビューでは、定義を直接シミュレートします。 各クエリ セグメントについて、基本的な有効性を維持しながら要素を貪欲に挿入しながら、サブシーケンスを 1 つずつ構築しようとします。 挿入ごとに、正または負の追加によって「すべての正が次にすべての負」の制約が維持されるかどうかを確認する必要があります。 これにより、サブシーケンスごとに繰り返しスキャンと簿記が行われることになり、最悪の場合、ほぼすべての要素を複数回再検討することになる可能性があります。 クエリが多くなると、これは二次関数またはさらに悪い動作に悪化します。 

構造上のブレークスルーは、シーケンスをネストによって引き起こされるツリーとして解釈することによってもたらされます。 すべての値は、その正の発生と負の発生の間の間隔に対応します。 シーケンスのバランスが取れているため、これらの間隔は適切な入れ子構造を形成し、線の中に根を張った森と同等になります。 

この表現内では、各位置はネストされた間隔の 1 つのチェーンに正確に属します。 プライマリ サブシーケンスは、順番に読み取られたときに、選択されたすべてのノードが祖先の順序を尊重し、インターリーブなしで「オープン フェーズ、次にクローズ フェーズ」に分割できるように、ノードのセットを選択することに対応します。 この制限は、有効なサブシーケンス内では、ノードを閉じ始めると、ネスト ツリーの 2 つの独立したブランチ間を切り替えることができないことを意味します。

これにより、強力な単純化が強制されます。各主サブシーケンスは、ネスト階層内の単一のチェーンに従うものとして解釈できます。 したがって、セグメントを最小数の主部分列に分解することは、最小数の根から葉へのチェーンを使用してそのセグメントの誘導フォレストをカバーすることと同じです。 

ツリーでは、すべてのノードをカバーするために必要なルートからリーフへのチェーンの最小数は、セグメントに制限されている場合に新しい切断されたコンポーネントを開始するノードの数に等しくなります。これは、親がセグメント外にあるノード、または誘導されたフォレストのルートであるノードの数を数えることによって計算できます。 

これにより、各クエリがネスト ツリー内の親関係に関する境界ノードをカウントするようになります。

 ## アルゴリズムのチュートリアル

 ### 1. 入れ子構造を構築する

 スタックを使用してシーケンスを 1 回処理します。 正の値が見つかるたびに、それを開始ノードとしてプッシュします。 対応する負の値が見つかったら、それをポップし、現在のスタックの最上位の子としてリンクします。 これにより、ネストされた間隔の暗黙的なツリーが再構築されます。 

これが機能する理由は、バランスの取れた構造により、どの時点でもスタックにアクティブなオープン インターバルがネスト順に正確に含まれることが保証されるためです。 

### 2. 親子関係を記録する

 各ノード (絶対値) について、その親をツリーに保存します。 スタックの最上位に別のノードがあるときにノードが開かれると、その最上位がその親になります。 

これにより、シーケンスが、各ノードが最大 1 つの親を持つルート付きフォレストに変換されます。 

### 3. ツリー構造の隣接性を事前計算する

 各ノードに対してその親と、場合によってはその深さを保存しますが、最終クエリには深さは厳密には必要ありません。 

### 4. クエリセグメントを処理する

 クエリ範囲 [l, r] の場合、両方の出現がセグメント内に完全に収まるすべてのノードが考慮されます (問題の条件によって保証されます)。 これらのノードについて、セグメントの外側にある親を持つノード、または親がないノードの数を数えます。 

このような各ノードは、有効な基本分解における新しいチェーンの開始に対応します。 

### 5. カウントを出力する

 答えはまさにこれらの「境界ルート」ノードの数です。 

### なぜ効果があるのか

 有効なセグメント内では、入れ子構造はフォレストのように動作します。 プライマル サブシーケンスは、その定義に違反する方法で正位相と負位相のインターリーブを強制するため、降順後に 2 つのブランチ間で切り替えることはできません。 この制限により、すべてのサブシーケンスは、誘導されたフォレスト内の単一の根から葉へのチェーン内に留まることになります。 したがって、セグメント内でノードがその親から切断されるたびに、新しいチェーンを開始する必要があり、この数よりも少ないチェーンを使用する分解はできません。 逆に、そのような各ノードでチェーンを開始し、下方向にたどると、常に有効な主サブシーケンス カバーが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}
    for i, x in enumerate(a):
        pos[x] = i

    parent = [-1] * (n + 1)
    stack = []

    for x in a:
        v = abs(x)
        if x > 0:
            if stack:
                parent[v] = abs(stack[-1])
            stack.append(v)
        else:
            stack.pop()

    # for each node, store interval [L[v], R[v]]
    L = [0] * (n + 1)
    R = [0] * (n + 1)

    for i, x in enumerate(a):
        v = abs(x)
        if x > 0:
            L[v] = i
        else:
            R[v] = i

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        ans = 0
        for v in range(1, n + 1):
            if L[v] >= l and R[v] <= r:
                p = parent[v]
                if p == -1 or not (L[p] >= l and R[p] <= r):
                    ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、署名されたシーケンスに対するスタックを使用して、ネストされたフォレストを再構築します。 各値の最初の出現はそのエントリ位置を示し、2 番目の出現はその出口位置を示し、ツリー ノードの区間表現を形成します。 

クエリごとに、どのノードがセグメントに完全に含まれているかを確認し、その親がセグメントの外側にあるかどうかをテストします。 このような各ノードは、新しいプライマリ サブシーケンスを開始するものとしてカウントされます。 

この実装は、各クエリ セグメントのバランスが取れているという保証に大きく依存しており、これにより、一貫した方法で間隔が完全に含まれるか完全に除外されることが保証されます。 

## 実用的な例

 ### 例 1

 順番を考えてみる`[1, 2, -2, -1, 3, -3]`そしてクエリ`[1, 6]`。 

| ステップ | ノード | 間隔 | 親 | セグメント内 | 新しいチェーン |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | [0,3] | - | はい | はい |
 | 2 | 2 | [1,2] | 1 | はい | いいえ |
 | 3 | 3 | [4,5] | - | はい | はい |

 ノード 1 と 3 が独立したコンポーネントを開始するため、答えは 2 です。 

これは、シーケンス全体のバランスが取れているとしても、独立したトップレベルの間隔には別個の主サブシーケンスが必要であることを確認します。 

### 例 2

 シーケンス`[1, 2, 3, -3, -2, -1]`、クエリ`[1, 6]`。 

| ステップ | ノード | 親 | セグメント内 | 新しいチェーン |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | - | はい | はい |
 | 2 | 2 | 1 | はい | いいえ |
 | 3 | 3 | 2 | はい | いいえ |

 構造が完全にネストされているため、必要なチェーンは 1 つだけです。 

これは完全にネストされたチェーンでの動作を示しており、セグメント全体が 1 つの基本サブシーケンスに折りたたまれます。

 ## 特殊なケース

 重要なエッジ ケースは、単一のクエリ内に複数の独立したルート インターバルが出現する場合です。 で`[1,2,-2,1,-1,3,-3]`、構造は複数のコンポーネントに分割されます。 このアルゴリズムは、親がセグメントの外側にある各ルートを正確にカウントします。 

もう 1 つのエッジ ケースは、完全にネストされた構造です。 で`[1,2,3,-3,-2,-1]`、すべてのノードの親がセグメント内にあるため、最初のチェーンの後に新しいチェーンが開始されることはなく、一貫して答え 1 が生成されます。 

最後の微妙なケースは、次のような単一のペアを含む最小限のセグメントです。`[x,-x]`。 ここで、ノードには内部の親がなく、常にカウントされ、答え 1 が生成されます。これは、単一のペアが常にそれ自体で主であるという事実と一致します。
