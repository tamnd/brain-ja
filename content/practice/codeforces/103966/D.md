 ## 解決策
 ## 問題の理解

 一列に配置された一連の位置が与えられ、各位置には特定の重みが与えられます。 次に、独立したクエリのコレクションが与えられます。 各クエリは、指定されたインデックスから開始され、固定ステップ サイズで繰り返し前方にジャンプするプロセスを記述します。 このプロセスでは、配列の境界を出るまで、訪問したすべての位置の値が収集され、クエリごとに収集された合計を出力する必要があります。 

したがって、各クエリは、配列内のインデックスの等差数列を定義します。位置 a から始まり、次に a + b、次に a + 2b というようになります。 タスクは、そのようなすべての位置の配列値の合計を計算することです。 

この制約により、最大数十万の要素とクエリが許可されます。 単純なクエリごとのシミュレーションでは、クエリごとに最大 n 個の要素をステップ実行する必要がある場合があり、最悪の場合、およそ n × q の操作 (10^10 のオーダー) が発生します。 これは、通常の制限時間内で実行できる範囲をはるかに超えています。 

主な問題は、クエリごとにステップ サイズが異なる可能性があり、同じ配列が再利用されるため、これらの等差数列がどのように動作するか構造を利用する必要があることです。 

ステップ サイズが 1 の場合、微妙なエッジ ケースが発生します。その場合、クエリは a から n までの完全なサフィックスの合計に縮退します。 2 番目のエッジ ケースは、ステップ サイズが n に近い大きい場合で、各クエリは 1 つまたは 2 つの要素のみに触れます。 1 つのレジームのみを効率的に処理する単純な均一最適化は、もう一方のレジームでは失敗します。 

もう 1 つの明白ではない問題は、戦略の混合が間違っていることです。n までのすべてのステップ サイズを事前計算しようとすると、メモリまたは前処理が大きくなりすぎます。 小さいステップ サイズのみを最適化した場合、間違って処理された場合、大きいステップ サイズでも依然として合計で TLE になります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。クエリごとに a から開始し、現在のインデックスに値を繰り返し加算し、n を超えるまで b ずつジャンプします。 これはプロセス定義を正確にシミュレートするため、これは正しいです。 ただし、そのコストはクエリごとに訪問される要素の数に比例します。 最悪の場合、b = 1 の場合、1 つのクエリで O(n) 個の要素がスキャンされ、q 個のクエリでは O(nq) となり、大きすぎます。 

この改善は、ジャンプが等差数列を形成し、配列が b を法とする剰余クラスを通じて表示できることに気づいたことから来ています。 b を固定すると、インデックスが独立したチェーンに分割されます。a mod b 形式のすべてのインデックスはチェーンを形成し、各ステップはそのチェーン内で 1 つの位置だけ前に進みます。 これらの残基チェーンに沿ってプレフィックス合計を事前計算すると、各クエリはその事前計算された構造内の定数時間差分クエリになります。 

問題は、b 自体が大きくなる可能性があり、n までの考えられるすべての b のチェーンを事前計算すると O(n^2) のコストがかかることです。 標準的なトレードオフは、ステップ サイズを小さい領域と大きい領域に分けることです。 小さい b については、すべての剰余クラスにわたって DP テーブルを事前計算します。 b が大きい場合、クエリごとにアクセスされる要素の数は少ないため、直接シミュレーションはすでに十分に効率的です。 

これにより、問題が 2 つの領域に分割され、すべてのクエリが効率的にカバーされます。

 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 残差 DP + 閾値分割 | O(n√n + q√n) | O(n√n) | 承認済み |

 ## アルゴリズムのチュートリアル

 √n 付近のしきい値 B を選択します。

1. 1 から B までのすべてのステップ サイズ b の答えを前処理します。各 b について、サイズ n の配列を構築し、サイズ b のジャンプに沿った累積和を計算します。 これは、各位置がチェーン内の次の位置の値を再利用できるように、インデックスを右から左に処理することを意味します。 これは正しいです。i + b から始まる合計がわかったら、a[i] を追加することでそれを i まで拡張できるからです。 
2. 前処理後、b ≤ B の各クエリは、ステップ サイズ b のインデックス a で事前計算された値を直接返すことによって、O(1) で答えることができます。 これが機能するのは、DP がそのインデックスから始まる正確なジャンプ チェーンに沿った合計をすでに表しているためです。 
3. b > B のクエリについては、直接シミュレーションを実行します。 各ステップは少なくとも B 位置にジャンプするため、訪問される要素の数は最大でも n / B であり、少ないです。 
4. 各クエリの合計を個別に蓄積し、出力します。 

重要な決定点は B での分割です。これにより、ステップ数と前処理表現の両方にコストがかかるクエリが存在しないことが保証されます。 

### なぜ効果があるのか

 ステップ サイズが小さい場合、等差数列の構造は剰余クラスと完全に一致するため、各インデックスは同じクラス内の 1 つの将来のインデックスのみに依存します。 これにより、すべての値が一度計算されて再利用されるクリーンな繰り返しが作成されます。 ステップ サイズが大きい場合、進行は十分に短く、直接列挙しても制限を超えるほどの総作業量が蓄積されることはありません。 すべてのインデックスは、事前計算されたチェーン ロジックによって処理されるか、すべてのクエリにわたって少数回のみアクセスされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = list(map(int, input().split()))
    q = int(input())

    B = int(n ** 0.5) + 1

    # dp[b][i] will store sum starting at i with step b, only for b <= B
    dp = [[0] * n for _ in range(B + 1)]

    for b in range(1, B + 1):
        for i in range(n - 1, -1, -1):
            nxt = i + b
            if nxt < n:
                dp[b][i] = w[i] + dp[b][nxt]
            else:
                dp[b][i] = w[i]

    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1

        if b <= B:
            out.append(str(dp[b][a]))
        else:
            s = 0
            i = a
            while i < n:
                s += w[i]
                i += b
            out.append(str(s))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DP テーブル`dp[b][i]`から始まる等差数列の合計をエンコードします。`i`ステップ付き`b`したがって、スモールステップ方式でのクエリは直接検索に減ります。 各状態は以下に依存するため、逆ループは不可欠です。`i + b`、これはすでに計算されている必要があります。 

大きなステップの場合、インデックスが急速に増加し、クエリごとの反復回数が少ないことが保証されるため、while ループは効率的です。 

## 実用的な例

 小さな配列を考えてみましょう`w = [2, 3, 5, 7]`。 

クエリ`(1, 3)`インデックス 0 から始まり 0、3 を訪問し、合計は 2 + 7 = 9 となります。 

| ステップ | 私 | 訪問した値 | 累計額 |
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 2 |
 | 2 | 3 | 7 | 9 |

 これにより、疎な等差数列が正しく走査されたことが確認されます。 

ここで考えてみましょう`(2, 2)`インデックス 1 から始まります。シーケンスは 1, 3 で、3 + 7 = 10 となります。 

| ステップ | 私 | 訪問した値 | 累計額 |
 | --- | --- | --- | --- |
 | 1 | 1 | 3 | 3 |
 | 2 | 3 | 7 | 10 |

 これは、b が小さい場合の DP レジームを示しており、サフィックス構造の繰り返しの再利用がキャプチャされます。

 ## 特殊なケース

 ステップ サイズ 1 の場合、すべてのクエリは接尾辞の合計になります。 DP は値を逆方向に正しく伝播する必要があります。 そうしないと、フォワード DP が初期化されていない状態を誤って再利用することになります。 入力`[1,2,3,4]`クエリ付き`(2,1)`生産しなければならない`2+3+4=9`、後方再帰は最後から構築することでこれを保証します。 

非常に大きなステップ サイズの場合、`b ≥ n/2`、各クエリは最大 2 つの要素を訪問します。 シミュレーション ブランチはこれを安全に処理し、ループはすぐに終了します。`i`すぐに境界線の外に飛び出します。
