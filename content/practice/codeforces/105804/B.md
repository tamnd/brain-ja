 ## 解決策
 ## 問題の理解

 双方向の道路で結ばれた町を表す無向接続グラフが与えられます。 各道路は 2 つの異なる町を接続しており、ネットワーク全体が最初は接続されているため、どのペアの町の間でも移動が可能です。 

課題は、このシステムを有向システムに置き換えることです。 既存のすべての道路には方向を割り当てる必要があり、必要に応じて新しい方向付き道路を追加することもできます。 これを実行した後、結果として得られる有向グラフは強い接続を維持する必要があります。つまり、すべての町から有向エッジに従って他のすべての町に到達できなければなりません。 

目標は、追加する新しい道路の数を最小限に抑えながら、既存の道路の向きを自由に変更できるようにすることです。 複数のテスト ケースが与えられているため、グラフごとにこの最小値を個別に計算する必要があります。 

このソリューションを推進する重要な制約は、すべてのテスト ケースにわたるエッジの総数が最大 200,000 であることです。 これにより、接続性を再計算したり、エッジごとに二次時間で重いグラフ アルゴリズムを実行したりするソリューションは除外されます。 テスト ケースあたり O(n + m) 程度であれば安全ですが、O(m log m) 回繰り返しても許容されます。 方向のシミュレーションや到達可能性の再計算を繰り返し試行すると、タイムアウトになります。 

微妙なケースは、すでに「ほぼツリー」になっているグラフから生じます。 グラフがツリーの場合、エッジをどのように配向しても、すべてのノードをカバーする有向サイクルを取得することはできません。 単純なアプローチでは、エッジを恣意的に方向付けようとし、強力な接続が局所的に修正できると想定する可能性がありますが、ツリーには基本的にサイクルがないため、余分なエッジは避けられません。 

別の失敗ケースは、グラフがすでに 2 辺接続されているが 2 頂点接続されていない場合に発生します。 ローカル次数やスパニング ツリーの方向に依存する一部の単純な戦略では、アーティキュレーション ポイントを見逃してしまうため、追加のエッジを追加しない限り、強力な接続が切断されます。 

## アプローチ

 強引な解釈では、指定された無向エッジのすべての可能な方向を試し、結果の有向グラフが強く接続されているかどうかを確認します。 有効な方向ごとに、接続ギャップを修正するために必要な追加のエッジの数を計算します。 m 個のエッジにはそれぞれ 2 つの選択肢があり、2^m 個の構成になるため、これはすぐに実行不可能になります。 m = 20 の場合でも、これはすでに爆発しており、ここで m は 200,000 に達します。 

重要な観察は、私たちは恣意的な意味で実際には自由ではないということです。 有向グラフの強い接続性は構造的に特徴付けることができます。すべての有向グラフは強く接続されたコンポーネントに圧縮でき、凝縮グラフは有向非巡回グラフです。 グラフ全体を強く接続するには、この DAG 構造内のソースとシンクを削除する必要があります。 

重要な単純化は、エッジを最適な方向に向けることができるということです。 これは、配向後の SCC ソースとシンクの数を最小限に抑える配向を選択できることを意味します。 古典的な結果は、接続された任意の無向グラフにおいて、結果として得られる有向グラフが、外部接続を必要とするコンポーネントの数が関節構造とブリッジの関数に減少する構造を持つようにエッジを方向付けることができるということです。 実際、最適な向きを設定した後、グラフを強く接続するために必要なエッジの最小数は、DFS ツリー分解で現れる「不均衡な」コンポーネントの数によって決まります。 

重要な洞察は、DFS ツリーをルート化し、バック エッジを慎重に処理しながら、すべてのツリー エッジを下向きに配置することです。 これにより、SCC 凝縮が元のグラフのブリッジに密接に対応する有向構造が生成されます。 各ブリッジは、グラフを両方向で相互に到達できない部分に効果的に分割します。 このような「一方向のボトルネック」ごとに、双方向の到達可能性を回復するために有向エッジを 1 つ追加する必要があります。

したがって、方向を検索する代わりに、DFS を使用して橋の構造を計算します。 ブリッジが特定されたら、概念的にグラフをブリッジ ツリーに圧縮します。 k 個の葉を持つツリーは、強く接続するために正確に ceil(leaf_count / 2) 個の追加エッジを必要とします。これは、追加された各エッジが 2 つの葉をペアにし、凝縮ツリーの 2 つの次数 1 要件を排除できるためです。 

全体の問題は次のようになります。すべてのブリッジを見つけ、ブリッジ ツリーを構築し、そのツリー内の次数 1 を持つノードの数を数え、それらをペアにするために必要なエッジの数を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースの方向性 | O(2^m) | O(n + m) | 遅すぎる |
 | DFS + ブリッジ分解 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エッジ インデックスを追跡しながら、グラフの隣接リストを構築して、平行移動方向を区別できるようにします。 これは、DFS を使用してブリッジを識別する必要があるため必要です。 
2. DFS を実行して、検出時間と低リンク値を計算します。 走査中、ツリーのエッジごとに、子から親に低リンク情報を伝播します。 ブリッジは、子からの到達可能な最下位の祖先が親の検出時刻より厳密に大きい場合に識別されます。 この条件は、エッジを削除するとグラフが切断されるという事実を捉えています。 
3. すべてのブリッジが見つかったら、元のグラフを「圧縮構造」として扱います。この構造では、ブリッジ以外のすべてのエッジがその端点を同じコンポーネント内に保持し、ブリッジがコンポーネント間の接続を定義します。 
4. ブリッジのみに関するノードの次数を数えることによって、概念的なブリッジ ツリーを構築します。 ブリッジの各エンドポイントは、このツリー内で 1 度に寄与します。 
5. このブリッジ ツリー内の次数 1 を持つノードの数を数えます。これらは、構造の「端」であるコンポーネントに対応し、他の部分に対称的に到達できません。 
6. 答えは、そのような葉の数の半分を切り上げたものです。 追加された各有向エッジは 2 つのリーフを接続し、両方を同時に固定できます。 

### なぜ効果があるのか

 DFS ベースのブリッジ分解では、あらゆる方向で一方向のトラバーサル制約を強制するエッジを正確に識別します。 このようなエッジは、2 つの最大 2 エッジ接続コンポーネント間にボトルネックを作成します。 これらのコンポーネントを縮小すると、残りの構造はツリーになります。 有向ツリー状構造では、強力な接続を実現するには、すべてのノードが着信および発信の両方の到達可能パスを持つ必要があり、これは凝縮ツリー内のリーフを削除することになります。 追加された各エッジは、葉の間にサイクルを作成することで 2 つの葉を削除できるため、最適な戦略は葉をペアにすることであり、式 ceil(L / 2) が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    edges = []
    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))
    
    tin = [-1] * n
    low = [0] * n
    timer = 0
    is_bridge = [False] * m

    def dfs(v, pe):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1
        
        for to, ei in g[v]:
            if ei == pe:
                continue
            if tin[to] == -1:
                dfs(to, ei)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[ei] = True
            else:
                low[v] = min(low[v], tin[to])

    dfs(0, -1)

    comp_deg = [0] * n

    for i, (u, v) in enumerate(edges):
        if is_bridge[i]:
            comp_deg[u] += 1
            comp_deg[v] += 1

    leaves = 0
    for i in range(n):
        if comp_deg[i] == 1:
            leaves += 1

    if m == 0:
        print(0)
    else:
        print((leaves + 1) // 2)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```DFS は標準的なローリンク計算です。 唯一の微妙な部分は、エッジが親エッジへのバックトラックと混同されないようにすることです。これは、単なる親ノードではなくエッジ インデックスを使用して処理されます。 ブリッジを特定した後、非ブリッジ エッジは完全に無視します。これは、非ブリッジ エッジは、最適な配向後の強く接続されたコンポーネント内に存在するためです。 

リーフをカウントするステップでは、すべてのブリッジ エンドポイントがブリッジ ツリーの次数に寄与していると仮定します。 ノードが 1 つのブリッジにのみ関与する場合、そのノードは縮小された構造内の葉のように動作します。 

最終的な式`(leaves + 1) // 2`pairs endpoints optimally.

 ## 実用的な例

 すべてのノードが他のすべてのノードに接続されている単純な三角グラフを考えてみましょう。 橋となるエッジはありません。 

| ステップ | 橋 | 度数 (ブリッジツリー) | 葉 |
 | --- | --- | --- | --- |
 | イニシャル | なし | すべて0 | 0 |

 葉がないため、答えは 0 になります。三角形を周期的に方向付けることができ、すでに強い接続性が得られているため、これは直感と一致します。 

Now consider a line graph 1-2-3-4.

 | ステップ | 橋 | 学位 | 葉 |
 | --- | --- | --- | --- |
 | エッジ 1-2 | はい | 1,1 | 2 |
 | エッジ 2-3 | はい | 2,2 | |
 | エッジ 3-4 | はい | 1,1 | 2 |

 ここではすべてのエッジがブリッジであるため、ブリッジ ツリー内のすべての内部ノードの次数は 2 ですが、エンドポイント 1 と 4 の次数は 1 です。葉 = 2 なので、答えは (2+1)//2 = 1 となります。 

これは、チェーンの端点を接続する単一の有向エッジを追加し、配向後に構造をサイクルに変えることに対応します。

 | --- | --- | --- |
 | 時間 | O(n + m) | DFS for low-link plus single pass over edges |

 この制約により、全体で最大 2×10^5 のエッジが許可されるため、テスト ケースごとの線形時間 DFS で十分です。 Memory usage remains linear in the graph size.

 ## 特殊なケース

 すでにサイクルになっているグラフにはブリッジがありません。 In that situation the DFS marks no edge as critical, so every degree in the bridge structure is zero. The leaf count becomes zero and the algorithm outputs zero, which matches the fact that we can orient the cycle consistently.

 A pure tree is the most sensitive case because every edge is a bridge. The DFS marks all edges, and the bridge tree is identical to the original tree. 葉は木の葉に正確に対応します。 ペアリングの式により、リーフ間のサイクルを閉じるのに十分なエッジが確実に追加されます。また、サイクルが導入されると、子を経由する入力パスと出力パスの両方があるため、すべての内部頂点はすでに問題ありません。 

スター グラフは、n − 1 に等しい多数のリーフを生成します。アルゴリズムは、それらを 2 つのグループに貪欲に組み合わせて、おおよそ (n − 1)/2 個の追加エッジを生成します。 This matches the intuition that each added edge can only fix two endpoints of one-way separations at a time.
