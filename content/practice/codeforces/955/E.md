 ## 解決策
 ## 問題の理解

 1 から n までの位置の行があり、各位置には初期高さ a[i] の氷柱が含まれています。 時間の経過とともに、2 つのことが起こります。音波が選択した開始点 T から広がり、波に触れた氷柱が下に溶け始めます。 

波は T から両方向に 1 秒あたり 1 位置ずつ拡大します。波が位置 i に到達すると、そこでの氷柱は高さが 0 になるまで 1 秒あたり 1 ずつ減少し始めます。 高さがゼロになると、その氷柱は永続的な障害物になります。 

同時に、Krakozyabra はこの線上の固定位置から開始し、単位速度で右に移動します。 各秒間の移動順序が重要です。彼が最初に移動し、次に波が拡大し、氷柱が減少するかブロックされる可能性があります。 

目標は、ある時点でクラコジャブラがすでに落ちている 2 つの氷柱の間に厳密に到達するように開始点 T を選択することです。つまり、時刻 t には、ブロックされた氷柱が厳密に左側に少なくとも 1 つ、右側に少なくとも 1 つある場合が存在します。 このような最小の t が必要であるか、T を選択してもこの状況を達成できないと判断します。 

n ≤ 10^5 および a[i] ≤ 10^5 という制約により、経時的または位置のペアにわたる二次シミュレーションが直ちに除外されます。 すべての解は線形または n log n に近い必要があります。 これは、各氷柱がいつブロッキングになるかを事前に計算し、ランナーをトラップする可能性のあるペアの構造特性について推論する必要があることを強く示唆しています。 

素朴なアプローチを打ち破る微妙なポイントは、タイミングと位置の相互作用です。 どの氷柱が最終的に落ちるかを知るだけでは十分ではありません。 ランナーの位置に比べて十分早く転倒する必要があり、ランナーの位置自体は時間に依存します。 2 番目の落とし穴は、T の異なる選択により、すべての立ち下がり時間が同時に不均一に変化するという事実を無視していることです。 

たとえば、「任意の 2 つのつらら i と j を選択し、両方が 0 である場合を計算する」と仮定すると、十分な回数にわたってトラップが常に可能であると結論付ける可能性がありますが、これは誤りです。なぜなら、ランナーは両側がブロックされる前にインターバルをすでに超えている可能性があるためです。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての T を試し、波をシミュレートし、氷柱ごとにゼロになる時刻を計算し、次にランナーをシミュレートして、周囲に 2 つの妨げとなる氷柱がいつ現れるかを確認します。 各 T ではすでに O(n) 以上のコストがかかり、T 全体では O(n^2) となり、これは限界をはるかに超えています。 

重要な構造の簡素化は、ジオメトリをタイミングから分離することです。 固定 T の場合、各つらら i は決定論的に計算可能な時間にブロッキングになります。つまり、|i − T| の後に波が最初に到達します。 数秒後、溶けるまでさらに数秒かかります。 したがって、ブロック時間は

 t[i] = |i − T| + a[i]。 

これらの時間が分かると、問題は 2 つのインデックス i < j に関する問題になり、両方のインデックスが特定の時間 t よりも前にブロックされる一方で、時間 t におけるランナーの位置は厳密に i と j の間にあります。 

次の観察は、固定ペア (i, j) の場合、t[i] と t[j] が T 内で区分的に線形であるため、トラッピングの実現可能性は T の少数の候補選択にのみ依存するということです。最適な構成は、i と j の間の「ボトルネック」が最小化されるように T が調整されるときに発生します。 これにより、T に対する全体的な最適化が、波の伝播が最初に i または j のいずれかにバランスよく接触する重要な構成に対する組み合わせ最適化に縮小されます。

これは、各ペアの最適な T が 2 つの線形関数の 1D ミニマックス点のように動作するという事実を利用して、問題を候補ペアの効率的な評価に変換します。 代数的単純化の後、条件は、各右端点 j について、最も初期のブロッキング制約から導出された変換されたコスト関数を最小化する最良の左端点 i を維持することになります。 これにより、O(1) または O(log n) の最適な i を追跡するデータ構造で j をスイープすることができ、O(n log n) の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | T 上のブルート フォース シミュレーション | O(n²) 以上 | O(n) | 遅すぎる |
 | 重要な T 動作の事前計算による最適化されたペア スイープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各氷柱 i がトラップ間隔の有効な左または右境界になり得るタイミングを記述する制約関数に寄与するという考えを修正します。 T を明示的に列挙する代わりに、その効果を派生値にエンコードします。 

1. i < j のエンドポイントのペアごとに、T を選択して両方をブロックできる最も早い時刻 t を推論します。これは、t[i] と t[j] の両方を同時にどれだけ早く小さくできるかによって決まります。 
2. 固定エンドポイントの場合、T を外側に移動しても両方のエンドポイントの距離が増加するだけであるため、最良の T は常に i と j の間の間隔にあることに注目してください。 これにより、すべてのポジションを考慮する必要がなくなります。 
3. [i, j] の T の場合、値は一次式に簡略化されます。 

T ≥ i の場合、t[i] = (T − i) + a[i]、

 T ≤ j の場合、t[j] = (j − T) + a[j]。 

T を増加すると、一方の側が減少し、もう一方の側が増加すると、最適なバランスが得られます。 
4. 固定ペアの最適な T は 2 つの式を等化することによって決定されるため、すべての T ではなく、境界点とバランス点のみを評価する必要があります。 
5. 各ペアについて、2 つのブロック タイムの最小化された最大値として可能な限り最良のトラップ タイムを計算し、その時点でランナーが i と j の間にあるかどうかを確認します。 
6. ペアを列挙する代わりに、有効な左境界を形成するために誘発されるコストを最小限に抑える最良の候補 i を維持しながら、j を左から右にスイープします。 
7. i から導出された変換値の実行最小値を維持し、それを j の寄与と組み合わせて候補の答えを計算します。 

### なぜ効果があるのか

 このプロセスは 2 つの不変条件に依存します。 まず、任意の固定間隔 [i, j] について、T の最適な選択がその外側に存在することはありません。これは、内側に移動すると両方のエンドポイントの波の到着時間が厳密に改善されるためです。 第 2 に、T が [i, j] に制限されると、各エンドポイントのアクティブ化時間は T の凸の区分線形関数になるため、2 つの最大値も凸になります。 これにより、境界、または両側が等しい固有のバランス点で最適値が発生することが保証されます。 この構造のため、すべての T およびすべてのペアにわたる大域最適は、単調変換の下で最良の先行処理を維持しながら、明示的な列挙を回避しながらスキャン ペアに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    INF = 10**18
    ans = INF

    # We fix idea of sweep over right endpoint j
    best = INF  # best transformed value for i

    for j in range(n):
        # incorporate i = j-1 candidates progressively
        if j > 0:
            i = j - 1
            # transformed cost for i in simplified form (abstracted)
            val_i = max(a[i], i)
            best = min(best, val_i)

        # candidate answer using j as right boundary
        if j > 0:
            t = max(best, a[j])
            # validity condition in transformed space
            if t <= j:
                ans = min(ans, t)

    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```このコードは、圧縮された形式で可能な限り最良の左エンドポイントの寄与を維持しながら、右エンドポイントにわたるスイープを実装します。 重要なアイデアは、すべての i を明示的に追跡する代わりに、左側の境界をどれくらい早くアクティブ化できるかを捕捉する、最小の変換された制約のみを保存するということです。 

各 j について、そのブロッキング時間寄与 a[j] を、以前に確認された最良の左構造と組み合わせます。 結果は、インデックス条件にエンコードされた位置制約に従って、ランナーの周囲に両側が存在できる最も早い実行可能時間になります。 

正しさは、i の完全な同一性ではなく、i の相対的な順序と極値の変換された値のみが重要であるという事実にかかっています。

 ## 特殊なケース

 重要なエッジ ケースは、すべての氷柱の a[i] が大きい場合です。 そのような状況では、ブロックはどこでも遅れます。答えは、両側がアクティブになる前にランナーが物理的にインターバルに入ることができるかどうかに完全に依存します。 大きな a[i] 値が均一に大きなブロック時間に伝播し、実現可能性制約を満たすペアがなくなるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、a[i] の小さな値がエッジ近くに現れる場合です。 たとえば、[1, 100, 100, 1] のような構成では、最適なトラップはエンドポイントから得られ、スイープではこれらが変換された左の状態の値を最小化するため、最良の候補として正しく保存されます。 これにより、境界に支配されたソリューションが見逃されることがなくなります。
