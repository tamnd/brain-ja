 ## アルゴリズムのチュートリアル

 私たちは次のような症状を治療します。`t`で`s`削除後に表示されるものの候補アンカーとして。

3. 有効なオカレンスごとに`[i, i+m-1]`、生き残らなければならないセグメントと考えてください。 次に、長さの 2 つの互いに素な区間を選択する必要があります。`k`文字列の残りの部分、つまり`[1, i-1]`そして`[i+m, n]`、スペースが許せば片側から両方を受け入れることができる柔軟性があります。

### なぜ効果があるのか

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hash(s, base=91138233, mod=10**9+7):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)
    for i, c in enumerate(s):
        h[i+1] = (h[i] * base + (ord(c) - 96)) % mod
        p[i+1] = (p[i] * base) % mod
    return h, p

def get_hash(h, p, l, r, mod=10**9+7):
    return (h[r] - h[l] * p[r-l]) % mod

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()
    t = input().strip()

    hs, ps = build_hash(s)
    ht, pt = build_hash(t)

    target = get_hash(ht, pt, 0, m)

    occ = []
    for i in range(n - m + 1):
        if get_hash(hs, ps, i, i + m) == target:
            occ.append(i)

    # possible starting positions for k-segments
    def check(i):
        left_len = i
        right_len = n - (i + m)

        left_cnt = max(0, left_len - k + 1)
        right_cnt = max(0, right_len - k + 1)

        if left_cnt + right_cnt < 2:
            return None

        res = []
        if left_cnt >= 2:
            res.append((1, 2))
        elif left_cnt >= 1 and right_cnt >= 1:
            res.append((1, i + m + 1))
        elif right_cnt >= 2:
            res.append((i + m + 1, i + m + 2))
        else:
            return None
        return res[0]

    for i in occ:
        ans = check(i)
        if ans:
            print("Yes")
            print(ans[0], ans[1])
            return

    print("No")

if __name__ == "__main__":
    solve()
```この実装はローリング ハッシュに依存して、発生したものを列挙します。`t`で`s`線形時間で。 発生が修正されると、`check`関数は、長さの有効な開始位置の数についてのみ理由付けします。`k`欠失はその出現箇所の左側と右側に存在します。 

インデックス付けには注意が必要です。出力には 1 から始まるインデックスが必要なので、0 から始まる配列で計算されるすべての開始位置は +1 シフトされます。 実現可能性チェックでは、結果の文字列全体の構築が回避されます。これは、パフォーマンスにとって不可欠です。`n = 5 * 10^5`。
