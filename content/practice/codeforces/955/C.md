 ## 解決策

 ## 問題の理解

 この課題は、完全累乗として表現できる数を数えるというものです。 クエリごとに、整数のセグメントが与えられます。$[L, R]$そして、このセグメント内の整数を次の形式で書き込むことができる数をカウントする必要があります。$x = a^p$、 どこ$a$は正の整数であり、指数です$p$は厳密に 1 より大きくなります。 

言い換えれば、完全二乗、完全立方体、完全 4 乗などの範囲内のすべての数値を数えることになります。 同じ数字は、複数の表現がある場合でも、1 回だけ数えるべきです (64 など)。$2^6$、$4^3$、 そして$8^2$。 

入力サイズから、間隔をスキャンして各クエリを処理できないことが明らかです。 範囲のエンドポイントは次のとおりです$10^{18}$これにより、数値ごとの反復が即座に除外されます。 単一のクエリでも列挙するには大きすぎます。 

より微妙な制約は、クエリの数です。$10^5$。 これにより、事前計算戦略が推進されます。つまり、関連するすべての数値のグローバル構造を一度構築し、その後、高速範囲カウントを通じてクエリに答える必要があります。 

エッジケースは、権力間の重複から発生します。 単純なアプローチでは、指数ごとに累乗を個別にカウントする可能性があります。たとえば、すべての平方、すべての立方体、すべての 4 乗を個別にカウントして合計します。 これにより、64 や 729 などの数値が複数回オーバーカウントされます。 もう 1 つの落とし穴は、浮動小数点のルート計算です。これにより、次のような境界付近で精度エラーが発生する可能性があります。$10^{18}$、丸めにより、次のような値が誤って含まれたり除外されたりする可能性があります。$999999999999999999$。 

## アプローチ

 ブルートフォースのアイデアでは、すべての整数を反復処理することで各クエリを処理します。$[L, R]$各数値が完全累乗であるかどうかを確認します。 数値をチェックするには、すべての指数を試す必要があります$p \ge 2$、整数の根を計算し、べき乗によって検証します。 これは概念的には機能しますが、範囲は次のように大きくなる可能性があります。$10^{18}$そのため、単一のクエリでも実行不可能な作業に変質してしまいます。 

重要な観察は、すべての完璧なセットが次のようにパワーアップするということです。$10^{18}$実際には小さいです。 固定指数の場合$p$、最大の拠点$a$満足のいく$a^p \le 10^{18}$のように急速に減少します$p$成長します。 のために$p = 2$、私たちは約$10^9$候補者ですが、$p = 3$ちょうど約$10^6$、その後は急激に下がります。 一度$p > 60$、 平$2^p$制限を超えているため、個別の完全なパワーの総数は最大でも数百万程度であり、重複排除後ははるかに少なくなります。 

これは、前処理戦略を示唆しています。つまり、以下のすべての完全な累乗を生成します。$10^{18}$それらを並べ替えたリストに保存し、重複を削除してから、二分検索で各クエリに答えて、該当するものがいくつあるかを数えます。$[L, R]$。 

ブルート フォースから最適なソリューションへの移行は、コストのかかる作業がクエリに依存しないことを認識することから始まります。 すべての有効な値が事前計算されると、各クエリは 2 つの二分検索に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ここ$N$は、最大の個別の完全累乗の数です。$10^{18}$。 

## アルゴリズムのチュートリアル

 1. までのすべての完璧なパワーを生成します。$10^{18}$指数を反復処理することによって$p$2から始まります。 For each exponent, compute all valid bases$a$そのような$a^p \le 10^{18}$。 の上限$a$は整数です$\lfloor (10^{18})^{1/p} \rfloor$。 
2. 拠点ごとに$a$、計算する$a^p$整数乗算または高速累乗を使用します。 結果がそれを超えた場合$10^{18}$、増加を停止します$a$値は増加するだけなので、その指数の場合。 
3. 64 や 729 などの数値は複数の指数と塩基のペアによって生成される可能性があるため、重複を避けるためにすべての計算値をセットに挿入します。 
4. 生成が完了したら、セットをソートされた配列に変換します。 
5. 各クエリについて$[L, R]$、二分探索を使用して有効な完全累乗の数を計算します。要素の数を数えます。$\le R$マイナス何個ですか$< L$。 

ここで二分探索が有効である理由は、事前に計算されたリストが厳密にソートされているため、プレフィックスのカウントが効率的かつ信頼できるものになるためです。 

### なぜ効果があるのか

 次のように書けるすべての数字$a^p$のために$p > 1$重複排除後に生成されたセットに 1 回だけ表示されます。 生成プロセスは、範囲内のすべての有効な指数とすべての有効な基数をカバーするため、有効な数値が失われることはありません。 並べ替えにより順序が維持され、二分検索によりセグメントが正しく分離されます。$[L, R]$、静的な順序セットに対する純粋な計数問題として各クエリが確実に回答されるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def generate():
    vals = set()

    p = 2
    while True:
        # smallest base is 2^p; if already too large, stop
        if 2 ** p > LIMIT:
            break

        a = 2
        while True:
            v = pow(a, p)
            if v > LIMIT:
                break
            vals.add(v)
            a += 1

        p += 1

    vals.add(1)  # 1 = 1^p for any p > 1
    return sorted(vals)

vals = generate()

def count_le(x):
    lo, hi = 0, len(vals)
    while lo < hi:
        mid = (lo + hi) // 2
        if vals[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

q = int(input())
out = []

for _ in range(q):
    L, R = map(int, input().split())
    out.append(str(count_le(R) - count_le(L - 1)))

print("\n".join(out))
```コードは最初に、以下に至るまでの完全な累乗の完全な宇宙を構築します。$10^{18}$。 指数と基数にわたるネストされたループは制限チェックによって制御され、理論的な検索スペースが大きい場合でも確実に終了します。 

1 を含めることは特殊な場合であるため明示的です。これは有効です。$a^p$誰にとっても$p > 1$、ただし、そうしないと、2 から始まる基本反復では見逃されてしまいます。 

の`count_le`関数は、標準の二分検索を実行してプレフィックス要素をカウントします。 これにより、ライブラリ関数への依存が回避され、境界処理、特に次のような境界処理が明示的に行われます。$\le R$そして$< L$。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、1 が含まれていることです。1 は次と等しいため、$1^p$有効な指数ごとに、明示的に追加するか、個別に処理する必要があります。 そうしないと、次のようなクエリが実行されます。$[1, 1]$誤ってゼロを返します。 

もう 1 つの微妙なケースは、64 などのオーバーラップ表現です。生成中に、次のように表示されることがあります。$2^6$、$4^3$、 そして$8^2$。 セットを使用して重複を排除しない場合、重複によって頻度が人為的に膨らむため、バイナリ検索の結果が過剰にカウントされます。 

最後に上限$10^{18}$浮動小数点精度の限界に近づいています。 を使用したあらゆるアプローチ`math.pow`または、浮動小数点ルート抽出では、次のような境界値を誤って分類するリスクがあります。$10^{18}$または$999999999999999999$。 整数ベースの生成では、正確な整数の乗算のみを使用し、オーバーフロー時に停止することで、これを完全に回避します。
