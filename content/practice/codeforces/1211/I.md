 ## 解決策
 ## 問題の理解

 最大 500 個の頂点を持つ無向グラフが与えられます。 このグラフは、非常に特殊な隠れラベル付けプロセスから作成されたことが知られています。各頂点には元々 0 から 15 までの数値があり、ラベルが 2 進数 1 ビットだけ異なる場合に限り、2 つの頂点の間にエッジが存在します。 言い換えれば、2 つの頂点の値が XOR 形式で 2 のべき乗だけ異なる場合、2 つの頂点は隣接していることになります。 

このタスクは、同じ XOR ルールを使用してグラフを再構築すると、指定された入力グラフが正確に復元されるように、すべての頂点に対する 0 から 15 の範囲の数値の有効な割り当てを再構築することです。 

重要な制約は、値が 4 ビットの数値のみであることです。 これは、説明しようとしているグラフが 4 次元の超立方体構造内に存在することを意味しますが、どの頂点がどの立方体の頂点に対応するかは知らされません。 隣接構造のみが表示されます。 

入力サイズは十分小さいため、エッジや頂点に対する二次推論は可能ですが、16^n 個の代入をすべて試すようなことはできません。 グローバルな一貫性を強制せずに頂点ごとにラベルを個別に扱うソリューションは失敗します。エッジが強い結合制約を課すためです。1 つの頂点が固定されると、その隣接頂点が部分的に制約され、これらの制約が伝播します。 

素朴なアプローチの微妙な失敗例は、次数に基づいて各頂点を独立して処理することです。 たとえば、可能なビット 反転の中で各頂点が正しい数の近傍を持つようにラベルを貪欲に割り当てようとする場合があります。 これは、複数の頂点が同時に共有エッジに一致する必要があり、ローカル次数情報が 4 ビット値を一意に決定しないため、失敗します。 

## アプローチ

 重要な観察は、グラフがまさに 4 次元超立方体のサブグラフであるが、任意にラベル付けされているということです。 各ラベルは 4 ビット ベクトルで、各エッジはちょうど 1 ビットの反転に対応します。 

これは、グラフが各ビット位置に 1 つずつ、合計 4 つの完全一致の和集合でなければならないことを意味します。 各頂点は、ビット反転ごとに 1 つずつ、最大 4 つの隣接頂点に接続します。 したがって、グラフは 4 正規以下であり、すべてのエッジはどのビットが異なるかによって「色付け」されます。 

強引なアイデアは、各頂点に 0 ～ 15 の値を割り当て、一貫性をチェックすることです。 これにより、16^n 個の可能性が得られますが、完全に実行不可能です。 

より構造化されたブルート フォースでは、1 つの頂点を 0 として固定し、制約を伝播します。各近傍は正確に 1 ビット異なる必要があるため、4 つの候補の 1 つでなければなりません。 これは、小さな状態空間上の制約伝播問題になります。 主な問題点は、複数の割り当てがローカルで引き続き可能であるにもかかわらず、サイクル間の一貫性により固有の構造が強制されることです。 

重要な洞察は、絶対的なラベルを推測する必要がないということです。 代わりに、BFS を使用してラベルを段階的に再構築し、エッジ制約を変換として扱うことができます。 1 つの頂点に値を割り当てると、すべてのエッジがその隣接頂点に、未知の k に対する XOR 2^k の値を強制します。 k は最初は不明であるため、隣接構造と一致するすべての可能性を試し、グローバルに一貫性を維持します。 

これを、より単純な構造に注目することで解決します。ラベルは 0 から 15 であるため、各頂点を 4 ビット ベクトルとして扱い、エッジに沿った一貫性を強制することでビット表現を直接割り当てようとします。 すべてのエッジ (u, v) に沿って、a[u] と a[v] の間の XOR は 2 の累乗でなければならない、つまり 1 ビットだけ異なることを意味します。 

これは、バイナリ ベクトルに対する制約システムになります。 グラフは解決可能であることが保証されているため、ローカル一貫性を強制すれば、任意の開始からの一貫した伝播は成功します。

任意の頂点を選択し、それに 0 を割り当てます。その後、BFS を実行します。 各エッジについて、すでに割り当てられている制約と一致するビットを 1 つだけ反転することによって、隣接エッジを割り当てようとします。 各頂点の次数は小さいため、すでに割り当てられているすべての近傍によって課される制約を交差することによって、その値を一意に決定できます。 

これにより、すべての頂点が修正されるまで、各頂点の候補ラベルを繰り返し調整することになります。

 | 4 ビット状態での制約の伝播 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各頂点について、その可能な値を完全なセット {0, 1, ..., 15} として初期化します。 これは、制約を考慮する前に取得できる可能性のあるすべての 4 ビット ラベルを表します。 
2. すべてのエッジ (u, v) に対して、a[u] XOR a[v] が正確に 1 ビット セットでなければならないという制約を強制します。 これは、u のドメイン内のすべての値 x に対して、v は x XOR y が 2 のべき乗となるような値 y を持たなければならないことを意味します。 それに応じてドメインを制限します。 このステップでは、構造ルールを直接エンコードします。 
3. キューを使用して制約を繰り返し伝播します。 頂点のドメインが縮小するたびに、許容値も縮小する可能性があるため、隣接するすべての頂点を再チェックします。 制約は独立していないため、これが必要になります。 1 つの頂点に対する制限により、隣接する頂点における複数の可能性が無効になる可能性があります。 
4. 頂点のドメインが単一の値になった場合、それを固定として扱います。 この固定値はさらに、すべての近傍を、正確に 1 ビット異なる値のみに制限します。 これにより、制約充足問題と同様の連鎖的な効果が生じます。 
5. ドメインの変更が発生しなくなるまで伝播を続けます。 グラフは解決可能であることが保証されているため、このプロセスはすべての頂点が少なくとも 1 つの有効な値 (実際には 1 つだけ) を持った状態で終了する必要があります。 
6. 各頂点に最終的に割り当てられた値を出力します。 

これが機能する理由は、各エッジが 2 つの 4 ビット変数間に厳格な代数制約を強制するためです。 拘束システムはグローバルに一貫しており、対称性まで完全に決定されます。 エッジ制約に違反する値を割り当てることは決してなく、すべての制約は有効な可能性からのみ導出されるため、有効なグローバル ソリューションをすべて削除することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def is_pow2(x):
    return x and (x & (x - 1)) == 0

def ok(x, y):
    return is_pow2(x ^ y)

n, m = map(int, input().split())
g = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

all_vals = (1 << 16) - 1

cand = [all_vals] * n
dq = deque()

# initialize
for i in range(n):
    dq.append(i)

while dq:
    u = dq.popleft()
    new_mask = 0

    for val in range(16):
        if not (cand[u] >> val) & 1:
            continue

        valid = True
        for v in g[u]:
            ok_v = False
            for nv in range(16):
                if (cand[v] >> nv) & 1 and ok(val, nv):
                    ok_v = True
                    break
            if not ok_v:
                valid = False
                break

        if valid:
            new_mask |= (1 << val)

    if new_mask != cand[u]:
        cand[u] = new_mask
        for v in g[u]:
            dq.append(v)

ans = [0] * n
for i in range(n):
    ans[i] = (cand[i] & -cand[i]).bit_length() - 1

print(*ans)
```このソリューションは、各頂点の可能な値のビットマスクを維持します。 各更新ステップでは、XOR 1 ビット ルールに基づいて互換性のある近隣の値と一致しない値が除外されます。 BFS キューにより、頂点の可能性が縮小するたびに、その隣接頂点が再検討され、制約の伝播が安定します。 

最終的な割り当てでは、各頂点の残りの有効な最小値が選択されます。 この問題では有効なラベル付けの存在が保証されるため、各マスクは最終的に空ではなくなり、一貫性により残りの選択肢が機能することが保証されます。 

微妙な点は、内部検証ループです。頂点の候補値ごとに、すべての近傍が少なくとも 1 つの互換性のある値を持っているかどうかを確認する必要があります。 これにより、ローカルな実現可能性だけではなく、グローバルな一貫性が強化されます。

 ## 特殊なケース

 重要なエッジ ケースは、次数の高い頂点であり、その値は近傍によってほぼ完全に決定されます。 スター グラフでは、中心にすべてのリーフと互換性のあるラベルが同時になければなりません。 アルゴリズムは、互換性のある値のみが残るまで、許可されたマスクを繰り返し交差させることでこれを処理します。 

もう 1 つの特殊なケースは、コンポーネントが切断されていることです。 伝播はすべての頂点にわたってグローバルであるため、各コンポーネントは独立して進化します。 すべての頂点を使用したキューの初期化により、すべてのコンポーネントが確実に処理されます。 

最後の微妙なケースは、複数の割り当てが有効な対称ソリューションです。 アルゴリズムはそれらを区別しようとしません。 実現可能性を維持するだけです。 残りの選択肢は、問題ステートメントによって保証されている少なくとも 1 つの有効なグローバル ソリューションに属しているため、最後に残っている最下位ビットを選択するのは安全です。
