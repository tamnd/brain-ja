 ## 解決策
 ## 問題の理解

 私たちには一連の日が与えられており、それぞれの日にアイスクリーム 1 個分を買うための価格が設定されています。 毎日、ターニャがその日に食べられる量を記述する制約もあります。 夏の間ずっと、彼女は正確に食べなければなりません$k$毎日の最小および最大消費量制限を尊重しながら、合計量を摂取してください。 

重要な決定は、$k$各ポーションは食べるその日に購入する必要があり、費用はその日の価格によって異なるため、数日に分けて購入する必要があります。 安い日もあるので、そこに多くの部分を割り当てたいのですが、上限を超えたり、下限に違反したりすることはできません。 

出力は、購入にかかる最小の総コストです。$k$1 日あたりの制限をすべて尊重しながら、部分的に摂取する、または$-1$有効なディストリビューションが存在しない場合。 

この制約により、貪欲なアプローチまたは並べ替えベースのアプローチが推進されます。 と$n$まで$2 \cdot 10^5$そして$k$まで$10^9$、ユニットごとに部分を動的に分配しようとしたり、部分ごとのシミュレーションを使用したりするソリューションは不可能です。 たとえ$O(nk)$戦略はすぐには実行不可能です。 

エッジケースは、実現可能性自体が失敗した場合に発生します。 すべての最小要件の合計が超過した場合$k$、またはすべての最大容量の合計が以下です$k$、解決策は存在しません。 もう 1 つの微妙なケースは、貪欲な割り当てが必須の最小値を無視する場合です。単純な「常に最も安い日を選択する」戦略では、一部の部分を受け取る必要がある高価な日の下限に違反する可能性があるため、実現可能性が損なわれます。 

## アプローチ

 ブルートフォースアプローチでは、境界を尊重しながら毎日に割り当てる部分の数を決定し、コストを計算しようとします。 これは、すべての整数ベクトルを列挙することと同じです。$(d_1, \dots, d_n)$そのような$a_i \le d_i \le b_i$そしてその合計は$k$、次に総コストを評価します。 このような分布の数は組み合わせ的に増加し、大まかな境界でさえ指数関数的であることがわかります。$n$、毎日が可能な値の範囲に寄与するためです。 これは非常に小さいものを超えるとすぐに実行不可能になります$n$。 

重要な観察点は、コスト構造が 1 日あたり線形であることです。つまり、1 日あたりすべての部分が決まります。$i$同じ費用がかかります$c_i$。 これは、1 日以内の注文にはこだわらず、毎日どれだけの量を注文するかだけを気にすることを意味します。 問題は配布になる$k$同一のユニットを下限と上限のあるビンに分割します。ビン内の各ユニットは同じコストになります。 

制約を最適化から分離すると、自然な貪欲なアイデアが生まれます。 まず、最小要件をすべて満たさなければなりません。 これにより、ベースラインの割り当てが得られます。 その後、残りの部分を分配する必要があります。 この時点で、毎日の残り容量があり、追加の各部分はその日に追加されます。$i$費用がかかる$c_i$。 したがって、追加部分は常に最初に利用可能な最も安い日に割り当てる必要があります。 

これにより、問題はコストに基づいて日数を分類し、上限を尊重しながら残りの容量を貪欲に埋めることに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | O(n) | 遅すぎる |
 | 貪欲に並べ替え |$O(n \log n)$| O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてを合計して、部分の最小必要合計を計算します。$a_i$。 これを超えると$k$、解決策は存在しません。 これにより、下限の実現可能性が強制されます。 
2. すべてを合計して最大可能合計を計算します。$b_i$。 これが以下の場合$k$、解決策は存在しません。 これにより、上限の実現可能性が強制されます。 
3. 毎日最小値を割り当てます$a_i$部分。 これは、すべての有効なソリューションに含める必要がある強制ベースラインです。 
4. 残りの部分を次のように計算します。$k - \sum a_i$。 これらは、残りの容量内のどこにでも割り当てることができる柔軟なユニットです。 
5. 日ごとに、残りの容量を次のように計算します。$b_i - a_i$。 これらは、その日に割り当てることができる追加の部分の数を表します。 
6. すべての日をコストの増加順に並べ替えます$c_i$。 これにより、柔軟な部分を割り当てるときに、常に安い日を最初に考慮することが保証されます。 
7. ソートされた順序で日数を繰り返します。 毎日、残りの容量と残りのグローバル要件の範囲内で、できるだけ多くの残りの部分を割り当てます。 
8. 総コストをベースラインコストとして累計する$\sum a_i \cdot c_i$追加の割り当て部分による増分コストを加えます。 
9. 残りの部分がすべて割り当てられたら停止します。 

### なぜ効果があるのか

 必須の最小割り当てを修正した後、残りの部分はすべて独立しており、特定の日に配置するコストを除いて同一になります。 毎日、同じコストで限られた数の同じ「スロット」が提供されます。 これにより、クォータがいっぱいになるまで、利用可能な最も安価なスロットを選択するという問題が軽減されます。 コストによるソートからの逸脱は、より高価な割り当てられたスロットをより安価な未使用スロットと交換することで改善できるため、交換引数による貪欲な選択が最適です。 最小制約はベースラインにのみ影響します。 オプションの割り当ての順序には影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    days = []
    
    min_sum = 0
    max_sum = 0
    
    for _ in range(n):
        a, b, c = map(int, input().split())
        min_sum += a
        max_sum += b
        days.append((c, a, b))
    
    if k < min_sum or k > max_sum:
        print(-1)
        return
    
    remaining = k - min_sum
    
    total_cost = 0
    
    for c, a, b in days:
        total_cost += a * c
    
    days.sort()
    
    for c, a, b in days:
        if remaining == 0:
            break
        capacity = b - a
        take = min(capacity, remaining)
        total_cost += take * c
        remaining -= take
    
    print(total_cost)

if __name__ == "__main__":
    solve()
```実装は、合計の最小値と最大値を使用して実現可能性をチェックすることから始まります。 これにより、不可能な構成での無駄な作業が防止されます。 ベースライン コストは必須の割り当てから即座に計算されるため、強制的な決定と任意の決定を明確に分離できます。 

コストによる並べ替えは重要なステップです。日数が注文されると、残りの容量をその順序で貪欲に消費します。 の`remaining`変数は、まだ割り当てられていない柔軟な部分の数を追跡します。 各反復では、現在の最も安い日から可能な限り消費されます。 

よくある実装上の間違いは、並べ替えの前にベースライン コストを含める必要があることを忘れることです。 並べ替えは必須の割り当てには影響せず、柔軟な割り当てにのみ影響します。 もう 1 つの微妙な問題は、他の言語における整数のオーバーフローですが、Python は大きな整数を安全に処理します。

 ## 特殊なケース

 主なエッジケースは、最小要件をすでに超えている場合です$k$。 その場合、コストを考える前に答えを出さなければなりません。$-1$。 アルゴリズムは、次の合計を介してこれを即座に検出します。$a_i$不必要な並べ替えや割り当てが発生しないようにします。 

もう 1 つのケースは、最大容量が不十分な場合です。 コストが良くても流通が届かない$k$、早期の実現可能性チェックにより、誤った部分割り当てが防止されます。 

最後の微妙なケースは、すべての柔軟なキャパシティがより高価な日に属し、より安価な日がその最小値ですでに飽和している場合です。 このアルゴリズムは、必須の割り当てとオプションの割り当てを分離し、実行不可能な再割り当てを強制するのではなく、貪欲な選択が実際に利用可能な柔軟性にのみ適用されるようにするため、引き続き正しく動作します。
