 ## 解決策
 ## 問題の理解

 問題の難易度のリストが与えられます。各問題にはインデックスと複雑さの数値が含まれています。 タスクは 3 つの異なるインデックスを選択することです$a$、$b$、 そして$c$対応する値が厳密に増加するチェーンを形成するようにします。$r_a < r_b < r_c$。 

出力は値そのものではなく、有効なトリプルのインデックスです。 そのようなトリプルが存在しない場合は、次のように出力する必要があります。`-1 -1 -1`。 

制約により、最大で$n = 3000$。 このサイズは十分小さいので、$O(n^2)$あるいは注意深く管理されていても$O(n^3)$一部の言語ではアプローチが通る可能性がありますが、Python では、アプローチはすべて合格します。$O(n^3)$タイムアウトになる危険性があります。 二次スキャンは許容されますが、最悪のケースごとに 2,700 万回以上の演算を超える三次スキャンは、定数によってはすでに境界線に達しています。 

重要な問題は計算上のものではなく、構造上のものです。 数値関数を最適化したりトリプルをカウントしたりすることは求められていませんが、インデックスが保存された長さ 3 の増加する部分列の存在を見つけることが求められています。 

単純な落とし穴は、値が繰り返されたり、並べ替えられていない場合に発生します。 たとえば、次のような配列では、`[5, 1, 5, 1, 5]`不注意な試みにより、数列を形成していると考えて等しい値を選択する可能性があります。 厳密な不平等が要求されるため、これは失敗します。 もう 1 つの微妙な問題は、値が順序を満たしている限り、インデックスは任意であり得るため、インデックスの正しい順序で値を選択することは無関係であることです。 

ブルートフォース手法では、有効なトリプルが分散していて隣接していない可能性があることを見逃す可能性があるため、貪欲なローカル チェックが近隣のみを検査する場合は失敗する可能性があります。 

## アプローチ

 最も直接的なアイデアは、インデックスのトリプルをすべて試してみることです。 私たちが選ぶ$i < j < k$かどうかを確認してください$r_i < r_j < r_k$。 これは条件を明示的にテストするため、正しいです。 ただし、これを調べると、$\binom{n}{3}$3 倍になり、最悪の場合は約 45 億小切手になります。$n = 3000$。 Python では遅すぎます。 

有効な中間要素を効率的に検出する機能を維持しながら、すべてのトリプルを列挙することを回避する必要があります。 

重要な観察は、固定されたミドルポジションの場合、$j$可能なすべてのペアを検索する必要はありません$(i, k)$独立して。 代わりに、以下より小さい値が存在するかどうかだけを知る必要があります。$r_j$その左側とそれより大きい値$r_j$その右側にあります。 両方が存在する場合、$j$有効なトリプルの中間として機能します。 

これにより、問題は 2 つのヘルパー構造の維持に変換されます。1 つはこれまでに確認された最小の要素 (またはそのインデックス) を追跡するプレフィックス スキャン、もう 1 つは各要素よりも大きい可能な最小の候補を追跡するか、右側にあるより大きな要素の存在を単純にチェックするサフィックス スキャンです。 値は任意であるため、位置ごとに、大きい値が右側に存在するかどうか、同様に小さい値が左側に存在するかどうかを事前計算できます。 

これらの配列が計算されると、有効な中間インデックスのスキャンが簡単になります。 どれについても$j$、存在する場合$i < j$と$r_i < r_j$そして$k > j$と$r_k > r_j$、すぐにそのトリプルを出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | プレフィックス/サフィックスの事前計算 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、すべての有効なトリプルには明確な中間要素があるという考えに基づいてソリューションを構築します。 

1. 配列を事前計算する`left_min_index`あらゆる位置に保存されます$j$、プレフィックスに含まれる最小値のインデックス$1..j$。 これで候補が得られます$i$そのような$r_i < r_j$値を比較することで迅速にテストできます。 
2. 配列を事前計算する`right_max_index`あらゆる位置に保存されます$j$、サフィックス内で見られる最大値のインデックス$j..n$。 これで候補が得られます$k$そのような$r_k > r_j$。 
3. 各インデックスを反復処理します。$j$それを潜在的な中間要素として扱います。 
4. それぞれについて$j$、最適なプレフィックス候補が実際に満たすかどうかを確認します。$r_{left[j]} < r_j$。 そうでない場合、この要素には有効な左要素がありません。$j$。 
5. 同様に、最適なサフィックス候補が次の条件を満たすかどうかを確認します。$r_{right[j]} > r_j$。 そうでない場合、これに有効な正しい要素はありません。$j$。 
6. 両方の条件が当てはまる場合は、インデックスのトリプルをただちに出力します。 

### なぜ効果があるのか

 すべての有効なソリューションには中間要素があります$b$。 このようなトリプルが存在する場合、左側のすべての要素のうち、$b$、少なくとも 1 つは小さく、すべての要素の右側にあります。$b$、少なくとも 1 つは大きいです。 プレフィックスとサフィックスの事前計算により、これらの候補を見逃さないことが保証されます。 考えられるすべての中間位置をテストするため、正しい位置を見つける必要があります。$b$、その時点で、必要なコンパニオンは両方とも事前計算された配列内にすでにエンコードされています。 すべての候補中間インデックスが明示的に検査されるため、有効な構成をスキップすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
r = list(map(int, input().split()))

left_min_index = [0] * n
min_idx = 0
for i in range(n):
    if r[i] < r[min_idx]:
        min_idx = i
    left_min_index[i] = min_idx

right_max_index = [0] * n
max_idx = n - 1
for i in range(n - 1, -1, -1):
    if r[i] > r[max_idx]:
        max_idx = i
    right_max_index[i] = max_idx

for j in range(n):
    i = left_min_index[j]
    k = right_max_index[j]
    if r[i] < r[j] and r[k] > r[j]:
        print(i + 1, j + 1, k + 1)
        sys.exit()

print(-1, -1, -1)
```プレフィックス スキャンは、左側の最小値の実行中の最良の候補を構築し、各位置に対して、より小さい要素の可能な限り強力な選択肢が得られるようにします。 

サフィックス スキャンは、より大きな要素に対しては逆に同じことを行います。 有効な中間要素には、少なくとも 1 つの小さい値と 1 つの大きい値が存在するだけでよいため、完全なリストではなく極値を使用するだけで十分です。 

最後のループでは、各インデックスを潜在的な中間点として単純にテストし、両方が満たされているかどうかを検証します。

 ## 特殊なケース

 厄介なシナリオは、最小の有効な左要素が中央の候補に隣接していない場合です。 考慮する`3 1 4 1 5 9`。 インデックス 2 (値 4) では、正しい左候補はインデックス 0 や 3 ではなく、インデックス 1 (値 1) です。プレフィックス最小配列により、位置に関係なく利用可能な最良の左値をグローバルに追跡するため、インデックス 1 が確実に選択されます。 

もう 1 つの特殊なケースは、値が繰り返されることです。 で`2 2 2 3 3`、単純なスキャンでは両側に等しい値が選択される可能性がありますが、厳密な不等号によりそれが妨げられます。 サフィックスの最大値とプレフィックスの最小値は、位置の仮定に依存するのではなく、常に実際の値の比較を検証するため、正確性が保証されます。 

最後のケースは、有効なトリプルが遠く離れている場合です。`1 100 2 3 4`。 中間の要素は、必ずしも局所的な増加傾向に含まれるわけではありません。 このアルゴリズムは、潜在的な中間としてすべてのインデックスをチェックし、隣接関係には依存せず、グローバルなプレフィックスとサフィックスの存在のみに依存するため、引き続き機能します。
