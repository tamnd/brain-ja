 ## 解決策
 ## 問題の理解

 都市の固定された循環ルートに沿って旅行する観光客に対して、最小限の訪問回数を計画することが求められます。 都市には 1 から n までの番号が付けられ、周期的に配置されており、旅行者は常に前方に移動します。つまり、都市 i から i+1、都​​市 n から都市 1 に戻ります。各都市 i には、自撮り写真の目標数があります。$a_i$これは必ず撮影する必要があり、旅行者が自撮りできるのは 1 回の訪問につき 1 枚だけです。 彼は都市 1 から開始し、都市をスキップすることはできません。 目標は、すべてのセルフィー要件を満たすために必要な都市訪問の合計数を見つけることです。 

入力は都市の数で構成されます$n$そして配列$a$長さの$n$。 それぞれ$a_i$まで可能です$10^9$そして$n$まで可能です$2 \cdot 10^5$。 これは、訪問の総数が非常に多くなる可能性があるため、都市を 1 つずつ訪問する総当りシミュレーションでは時間がかかりすぎることを意味します。 代わりに、次の点で線形時間で機能するアプローチが必要です。$n$。 

単純な解決策では、観光客がすべてのカウントが満たされるまでセルフィーを撮り、都市ごとに移動し、サイクルを一周するシミュレーションを試みる可能性があります。 たとえば、入力の場合`3 1 0 0`、シミュレーションは 1 回の訪問後に停止しますが、これは問題ありません。 しかし、`3 3 1 2`、単純なシミュレーションでは不必要なループが繰り返され、最小訪問数を効率的に見つけることができない可能性があります。 課題は、サイクルによって各都市を複数回訪問することができ、サイクルの数が事前に固定されていないことです。 

明らかではないエッジ ケースには、セルフィーを必要としない都市、他と比べてセルフィー数が非常に多い都市、要件が前の都市よりも低い都市などがあります。 たとえば、入力`3 0 100 0`返すべきです`101`なぜなら、最初の都市は訪問に貢献しませんが、2 番目の都市は 100 の訪問を必要とし、これがサイクル全体に広がるからです。 循環依存関係の累積的な影響を無視した不注意なアプローチでは、訪問数が過小評価される可能性があります。 

## アプローチ

 強引な解決策は簡単です。都市 1 から開始して、各都市が必要な数に達するまで自撮り写真を撮り、都市ごとに移動してサイクルを循環させます。 訪問ごとに、現在の都市の残りの自撮り写真を減らします。 これは論理的には正しいですが、潜在的に次のように合計する必要があります。$10^9$単一都市のステップですが、これは不可能です。 

重要な観察は、各都市 i (最初の都市以降) について、前の都市から引き継がれた「過剰なセルフィー」という観点から考えることができるということです。 観光客は周期的に移動するため、都市 i の最小訪問回数は、前の都市の自撮り回数とその要件との差に影響されます。 より正式には、各都市 i について、都市 i に必要な訪問回数は少なくとも$\max(0, a_i - a_{i-1})$。 最初の都市は常に全額を寄付します$a_1$訪問数に。 次に、この段階的な方法ですべての都市の貢献度を合計すると、最小合計訪問者数が得られます。 これが機能するのは、ある都市で過剰になると、次の都市に必要な追加の訪問回数が減るだけだからです。 

最適な解決策は、リングが周期的でセルフィーをスキップできないという特性を利用します。つまり、各都市に必要な最小限の追加訪問は、前の都市とのマイナスでない差分になります。 これらの調整された差分を合計し、最初の都市の自撮り写真を追加することで、O(n) ソリューションが達成されます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(合計(a_i)) | O(n) | 大きな a_i には遅すぎる |
 | 差に基づく最小値 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市の数を読み取る$n$そして配列$a$各都市で必要とされるセルフィーを表現します。 
2. 合計訪問数を次のように初期化します。$total = a_1$なぜなら、旅は都市 1 から始まり、そこにあるすべての自撮り写真を撮らなければならないからです。 
3. 都市を 2 から n まで繰り返します。 都市ごとに計算します$extra = \max(0, a_i - a_{i-1})$。 これは、前の都市を訪問することですでに「カバーされた」内容を超えて、都市 i に必要な追加の訪問を表します。 
4.追加$extra$に$total$。 
5. 最終版を印刷する$total$。 

機能する理由: 差分ベースのアプローチは、循環順序付けのために避けられない追加の訪問数を正確に取得します。 どの都市でも、前の都市の必要なセルフィー数がそれ以上である場合、現在の都市は追加のサイクルなしで同じ訪問を使用できます。 現在の都市の要件が以前の要件を超えている場合にのみ、追加の訪問が強制されます。$\max(0, a_i - a_{i-1})$式をキャプチャします。 最初の都市が完全にカウントされ、過少カウントが発生しないようにするため、サイクル クロージャ (都市 n から 1) が暗黙的に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = a[0]
for i in range(1, n):
    total += max(0, a[i] - a[i-1])

print(total)
```コードは都市の数と必要な自撮り写真を読み取ります。 初期化します`total`最初の街のセルフィーと一緒に。 後続の都市ごとに、前の都市との負でない差分が加算されます。 これにより、必要最小限の訪問のみがカウントされるようになります。 2 番目の都市から反復を開始し、最初の都市を個別に処理するため、off-by-one エラーは発生しません。 Python の整数は、オーバーフローすることなく非常に大きなカウントを処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    total = a[0]
    for i in range(1, n):
        total += max(0, a[i] - a[i-1])
    return str(total)

# provided samples
assert run("3\n1 0 0\n") == "1", "sample 1"
assert run("4\n3 1 2 2\n") == "4", "sample 2"

# custom cases
assert run("3\n0 100 0\n") == "100", "high middle requirement"
assert run("5\n5 5 5 5 5\n") == "5", "all equal"
assert run("3\n1 0 2\n") == "3", "requires extra at end"
assert run("6\n0 0 0 1 0 0\n") == "1", "single non-zero late"
assert run("3\n1000000000 1000000000 1000000000\n") == "1000000000", "large numbers"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3\n0 100 0 | 100 | ミドルでの大きなジャンプの対応 |
 | 5\n5 5 5 5 5 | 5 | すべての値が等しい場合、訪問数が不必要に増加することはありません。 
| 3\n1 0 2 | 3 | エンドシティでは追加の訪問が必要 |
 | 6\n0 0 0 1 0 0 | 1 | 疎な非ゼロ要件が正しく処理されました。
