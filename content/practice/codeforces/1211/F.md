 ## 問題の理解

 文字列フラグメントのコレクションが与えられます。 もともと、それらはすべて、単語からなる長い文字列を切断することから来ました。`"kotlin"`何度か繰り返した。 

切断後、断片をシャッフルした。 私たちの仕事は、フラグメントの連結が次のようになるよう、フラグメントの順序を復元することです。`kotlin`または`kotlinkotlin`または`kotlinkotlinkotlin`等々。 このステートメントは、有効な順序付けが少なくとも 1 つ存在することを保証します。 

最も重要な観察は、すべてのフラグメントが任意の文字列ではないということです。 すべてのフラグメントのすべての文字は、無限の周期文字列から来ています`kotlinkotlinkotlinkotlin...`到達できるフラグメントの数$10^5$、すべての文字列の合計の長さは最大でも$3 \cdot 10^5$。 フラグメントをペアごとに比較したり、隣接する可能性のあるすべてのフラグメントを照合して最終的な順序を再構築しようとしたりするアプローチは、コストがかかりすぎます。 合計入力サイズが線形に近い値が必要です。 

いくつかの特殊なケースは見落とされがちです。

## アプローチ

 ブルートフォースソリューションでは、フラグメントのすべての順列を試し、それらの連結が繰り返しコピーを形成するかどうかを確認します。`"kotlin"`。 

これは明らかに正しいです。 有効な順序が存在する場合、最終的には 1 つの順列によってその順序が生成されます。 

残念ながら、$n$できる$10^5$。 たとえ$n=15$、すべてをチェック$15!$順列は絶望的です。 探索空間は即座に爆発します。 

重要な観察は、ソース文字列が周期 6 で周期的であることです。 

しましょう```
w = "kotlin"
```すべてのフラグメントは、無限循環文字列の連続セグメントに対応する必要があります。```
...kotlinkotlinkotlin...
```フラグメントが次の位置で始まると仮定します。$p$の 1 回の出現の中で`"kotlin"`。 

その長さが$L$、フラグメントを読んだ後、位置に到着します$$(p + L) \bmod 6$$次の循環コピー内。 

これはグラフの解釈を示唆しています。 

サイクル内の各位置に 1 つずつ、合計 6 つの頂点を作成します。`"kotlin"`。 

すべてのフラグメントについて:

 1. サイクル内で開始する位置を決定します。 
2. 長さを消費した後、どこで終わるかを計算します。 
3. これら 2 つの頂点の間に有向エッジを追加します。 
4. フラグメントインデックスをそのエッジに保存します。 

ここで、有効な連結が何を意味するかを考えてみましょう。 

1 つのフラグメントの後に別のフラグメントが続く場合、最初のフラグメントの終了位置は 2 番目のフラグメントの開始位置と等しくなければなりません。 グラフ用語では、連続するフラグメントは連続するエッジに対応します。 

すべてのフラグメントを 1 回だけ使用するということは、すべてのエッジを 1 回だけ使用することを意味します。 

それはまさにオイラー軌跡の問題です。 

元の文字列全体が整数だったため、`"kotlin"`コピーすると、全長は 6 の倍数になるため、全体の歩行は同じサイクル位置に戻ります。 有効な順序付けの存在が保証されているということは、構築されたグラフがオイラー型であることを意味します。 

オイラー回路を見つけて、そのエッジ インデックスを出力するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適（オイラー回路） |$O(S + n)$|$O(n)$| 承認済み |

 ここ$S$すべての文字列の合計の長さを示します。 

## アルゴリズムのチュートリアル

 1. しましょう`w = "kotlin"`。 
2. すべてのフラグメントについて、一意の位置を決定します`start`フラグメントが開始できるサイクル内。 

の6文字すべてなので、`"kotlin"`異なる場合は、最初の文字が開始位置を直ちに決定します。 次に、フラグメントの残りの部分を循環パターンと照合して検証します。 
3. しましょう`L`フラグメントの長さになります。 

コンピューティング```
end = (start + L) mod 6
```4. 有向エッジを追加する`start -> end`フラグメントインデックスを保持します。 
5. すべてのフラグメントを処理した後、6 つの頂点のグラフに対して Hierholzer のアルゴリズムを実行します。 
6. DFS 中に、エッジが完全に処理されるたびに、そのフラグメント インデックスが応答リストに追加されます。 
7. 収集したリストを反転します。 

これは、Hierholzer のアルゴリズムの標準的な出力順序です。 
8. 結果として得られるフラグメント インデックスを出力します。 

### なぜ効果があるのか

 各頂点は、繰り返しサイクル内の位置を表します。`"kotlin"`。 

位置から始まるフラグメント`u`そしてその位置で終わる`v`自然に有向エッジになる`u -> v`。 

最後の連結で 2 つのフラグメントが隣接する場合、最初のフラグメントの終了サイクル位置は 2 番目のフラグメントの開始サイクル位置と等しくなければなりません。 したがって、有効な連結は、エッジを連続的にたどるウォークに正確に対応します。 

すべてのフラグメントを 1 回だけ使用するということは、すべてのエッジを 1 回だけ走査することを意味します。 それがオイラー軌跡の定義です。 

入力は、繰り返される有効なカットから得られることが保証されています。`"kotlin"`文字列なのでオイラー回路が存在します。 Hierholzer のアルゴリズムはそのような回路を返し、通過したエッジのシーケンスによってフラグメントの有効な順序が与えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = "kotlin"

    pos = {c: i for i, c in enumerate(w)}

    g = [[] for _ in range(6)]

    for idx in range(1, n + 1):
        s = input().strip()

        start = pos[s[0]]

        for j, ch in enumerate(s):
            if ch != w[(start + j) % 6]:
                return

        end = (start + len(s)) % 6
        g[start].append((end, idx))

    ptr = [0] * 6
    ans = []

    start_vertex = 0
    for v in range(6):
        if g[v]:
            start_vertex = v
            break

    stack = [(start_vertex, -1)]

    while stack:
        v, edge_id = stack[-1]

        if ptr[v] < len(g[v]):
            to, eid = g[v][ptr[v]]
            ptr[v] += 1
            stack.append((to, eid))
        else:
            stack.pop()
            if edge_id != -1:
                ans.append(edge_id)

    ans.reverse()
    print(*ans)

solve()

検証ループは、フラグメントが循環パターンに本当に一致するかどうかをチェックします。 この問題では有効な入力が保証されますが、これにより構築が論理的に正しい状態が保たれます。

```グラフには頂点が 6 つしかありませんが、最大$10^5$エッジ。 

2 番目の部分は、Hierholzer のアルゴリズムの反復実装です。 明示的なスタックを使用すると、再帰の深さの問題が回避されます。 すべてのエッジは 1 回だけ処理されます。 頂点で未使用の発信エッジがなくなると、そこに到達したエッジをバックトラックして追加します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    input_data = io.StringIO(inp)

    n = int(input_data.readline())
    w = "kotlin"
    pos = {c: i for i, c in enumerate(w)}

    g = [[] for _ in range(6)]

    for idx in range(1, n + 1):
        s = input_data.readline().strip()
        start = pos[s[0]]
        end = (start + len(s)) % 6
        g[start].append((end, idx))

    ptr = [0] * 6
    ans = []

    start_vertex = 0
    for v in range(6):
        if g[v]:
            start_vertex = v
            break

    stack = [(start_vertex, -1)]

    while stack:
        v, eid = stack[-1]
        if ptr[v] < len(g[v]):
            to, ne = g[v][ptr[v]]
            ptr[v] += 1
            stack.append((to, ne))
        else:
            stack.pop()
            if eid != -1:
                ans.append(eid)

    ans.reverse()
    return " ".join(map(str, ans))
