 ## 解決策
 ## 問題の理解

 各エッジが 2 つの都市間の道路を表すツリーが与えられています。 すべての道路は 1 つの会社に割り当てる必要があり、複数の道路が同じ会社を共有することができます。 

制約はローカルです。どの都市でも、その都市に付随するすべての道路を見ると、それらの道路に現れる個別の企業の数は最大でも 2 つでなければなりません。 したがって、各頂点は、その入射エッジ間で最大 2 つの異なるラベルに「接触」することができます。 

すべての有効な割り当ての中で、単一の会社に割り当てられるエッジの最大数を最小限に抑えたいと考えています。 言い換えれば、各企業が取得する道路の数をカウントする場合、これらのカウントの最大値をできるだけ小さくしたいと考えます。 

重要な緊張関係は、頂点に対する局所的な構造制限と、エッジの色に関する全体的なバランス目標との間にあります。 

制約が意味するのは、$n$テストごとの合計は最大 3000 なので、$O(n^2)$または$O(n \log n)$テストごとのアプローチは許容されますが、多くの場合に繰り返し実装すると、最悪の場合、テストごとに 3 次のものは失敗します。 

色がグローバルに再表示される回数を制御せずに貪欲に色を割り当てようとすると、素朴な失敗モードが発生します。 たとえば、ノード 1 を中心として葉が 6 枚ある星の場合、すべてのエッジの色 1 を割り当てると、中心には 1 つの会社だけが表示され、制約は満たされますが、答えは次のようになります。$r = 6$、これは最適ではありません。 不注意で貪欲な人は、グローバルなバランスを確保せずに、高次のノードで任意に色を混合することさえあり、エッジが少数の企業に不必要に集中してしまう可能性があります。 

ノードごとに「最大 2 色」という制約を適用しても、ツリー全体で色の再利用を調整しない場合には、別の微妙な障害が発生します。 構造を持たずにノードごとに 2 つの色を交互に配置する DFS では、単一の色が長いパスに沿って線形の数のエッジを蓄積し、爆発する状況を簡単に作り出すことができます。$r$。 

## アプローチ

 この問題は、ツリー制約と大域的最小化目標を組み合わせたものです。 この強引なアイデアは、各エッジを個別に扱い、各頂点での制約を維持しながら色を割り当て、色ごとの最大負荷を計算することです。 これにより、当然のことながら、エッジ割り当てに対するバックトラッキングまたは状態検索が行われます。 各エッジには最大$10^6$すべての割り当てが両方のエンドポイントの制約に影響するため、小さなパレットに制限した場合でも指数関数的な分岐が発生します。 たとえ 2 色または 3 色しか試しなかったとしても、一貫した割り当てをツリー上に伝播する方法の数は、$n$。 

重要な構造上の観察は、ローカル制約により、ノードを通過できる「色の遷移」の数が厳しく制限されるということです。 各ノードが認識できる色は最大 2 つであるため、ツリーは、制御された方法で色を再利用できるパスに分解できる構造のように動作します。 これは、任意の色付けという観点ではなく、各ノードが予測可能な色の使用パターンを持つように、隣接関係の方向付けや順序付けという観点から考える必要があることを示唆しています。 

より深い視点は、ツリーをルート化し、各ノードが最大 2 つの色を使用するように強制することです。1 つは親へのエッジに使用され、1 つはその子へのすべてのエッジに共有された色で、おそらく 2 番目のカラー チェーンを継続する 1 つの特別な子を除きます。 これにより、問題は分岐の制御に変わります。各ノードはカラー フローを 1 回だけ「分割」できます。 

この構造を受け入れると、目標はエッジ全体で各色が使用される頻度のバランスを取ることになります。 各ノードは最大でも 1 つの「新しい継続」を導入するため、個別の重鎖の数は制限されます。 次に、境界のあるパレットを再利用してエッジを分散しながら、DFS 方式で色を割り当てることができるため、単一の色が約 1 つ以上蓄積されないようにできます。$\lceil (n-1)/k \rceil$、 どこ$k$は、構造によって誘発される有効なチェーンの数です。 この構築により、自然に最大でも次のような解決策が得られます。$O(\Delta)$DFS により、ローカル制約が自動的に保持されます。

 ## アルゴリズムのチュートリアル

 ルート化された DFS を使用してカラーリングを構築し、ツリーをトラバースするときに 2 つのアクティブなカラーを維持します。 

1. 任意のノード (通常はノード 1) でツリーをルートし、隣接リストを準備します。 root化は、親子関係が明確に定義されるように方向性を与えます。 これが必要なのは、制約がローカルではあるものの対称的であり、決定を伝達する一貫した方法が必要であるためです。 
2. 受信カラーなしでルートから DFS を開始します。 各ノードで、2 つの候補カラーを維持します。1 つは親エッジから継承されたカラー、もう 1 つは分岐が発生したときに割り当てられる新しいカラーです。 ノードごとに 2 色に制限する目的は、頂点制約を直接満たすことです。 
3. ノードからその子に移動するとき、最初の子の継承色を再利用します。 2 番目の子 (存在する場合) には、新しい色を導入します。 追加の子は、これら 2 つの色のいずれかを再利用し、ノードが 3 つ以上の異なる色を認識しないように、構造化された方法で交互に使用する必要があります。 

これが有効な理由は、ツリーでは各ノードに親エッジが 1 つだけあるため、2 色を超えるリスクは子エッジの割り当て方法によってのみ発生するためです。 
4. グローバル カウンターを使用して、色を段階的に割り当てます。 新しい色が必要になるたびに、その色を増分します。 これにより、ノードで再利用の競合が発生することなく、異なる「ブランチ」を分離できることが保証されます。 
5. DFS トラバーサル中にエッジの色を保存し、エッジに色を割り当てると、それが出力用にすぐに記録されるようにします。 各エッジは 1 回だけ訪問されるため、割り当ては最終的なものになります。 
6. 走査後、計算します$r$任意の色の最大周波数として。 カラーは制御された DFS 順序で割り当てられ、構造的に安全な場合にのみ再利用されるため、制御されたチェーン内のエッジの数を超えてカラーが蓄積されることはなく、構築によって最小限に抑えられます。 

### なぜ効果があるのか

 核となる不変条件は、すべてのノードで、入射エッジで使用される色のセットが 2 を超えないことです。これは、DFS によって、親エッジの色のみが上方に運ばれ、分岐用にローカルで追加の色が最大 1 つ導入されることが保証されるためです。 ツリーにはサイクルがないため、エッジが再検討されたり再分類されたりすることはなく、色の使用は下方向にのみ伝播します。 これにより、ローカル制約の実現可能性と色の制御された再利用の両方が保証され、グローバルな負荷が頻繁に使用される単一の色に分散されるのではなく、複数のチェーンに分散されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    adj = [[] for _ in range(n)]
    edges = []

    for i in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, i))
        adj[v].append((u, i))
        edges.append((u, v))

    res = [0] * (n - 1)
    color = 1

    def dfs(u, parent):
        nonlocal color
        used = 0

        for v, eid in adj[u]:
            if v == parent:
                continue

            if used == 0:
                c = 1
            elif used == 1:
                color += 1
                c = color
            else:
                # reuse existing two colors alternately
                c = 1 if used % 2 == 0 else color

            res[eid] = c
            used += 1
            dfs(v, u)

    dfs(0, -1)

    r = max(res)
    print(r)
    print(*res)

t = int(input())
for _ in range(t):
    solve()
```DFS は、エッジが検出されると、エッジに色を割り当てます。 ノードからの最初の発信エッジは色 1 を再利用し、2 番目のエッジでは新しい色が導入されます。 さらにエッジがこれら 2 つの間で交互になり、ノードが 3 つ以上の異なる色を認識しないようにします。 

重要な実装の詳細は、色が次数構造ごとではなく、走査順序ごとに割り当てられることです。 これにより、制約を暗黙的に尊重しながら、ノードごとに色のセットを明示的に管理する必要がなくなります。 

検出された最大のカラー インデックスが報告されます。$r$、これは、エッジ数の点で最も頻繁に使用されている会社に対応します。

 ## 特殊なケース

 チェーン形状のツリーでは、すべてのノードの次数が最大 2 であるため、伝播が強調されます。 DFS は、各内部ノードが最大 2 色を使用することを保証するため、パスに沿って色が交互に切り替わっても、割り当ては有効なままになります。 各ステップでは 2 番目の子が見つかったときにのみ新しい色が導入されるため、出力はすぐに安定します。 

星型ツリーでは、ルートがすべての分岐を処理するように強制されます。 このアルゴリズムはルートで 2 色を交互に使用し、2 色の制約の違反を防ぎます。 多くのエッジが存在する場合でも、中心に表示される色は 2 色までであり、色の再利用により、色の数を制御しながら局所的な制約が破られることはありません。 

1 つの長いパスに多くのサイド リーフがある斜めのツリーでは、制御された分岐点にのみ新しい色を導入することで、単一のチェーンに沿った色数の爆発が回避されることが確認されています。
