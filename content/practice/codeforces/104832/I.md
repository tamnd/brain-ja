 ## 解決策
 ## 問題の理解

 ソースコンテナのコレクションが与えられ、各コンテナには 2 つの液体 A と B が一定の割合で混合されたものが含まれています。 各コンテナから、その内容物の任意の部分を取り出すことが許可されており、その部分は常にそのコンテナ内で A と B の元の比率を保持します。 任意の容器から抽出されたすべての部分は、新しい容器に自由に混合できます。 

一方、一連のターゲット機関があり、それぞれ指定された量の A と B が入った最終コンテナを必要とします。すべてのソースにわたる A の合計量は、すべてのターゲットにわたって必要な A の合計に等しく、同じことが B にも当てはまります。 

問題は、分配を明示的に構築することではなく、すべての研究機関が必要な量のペアを正確に受け取ることができるように、ソースコンテナを分割および混合する方法が存在するかどうかを判断することです。 

重要な制約は、ボトル内で A と B を分離できないことです。 すべての操作では、ボトルの選択された部分のローカル比率が保存されるため、移動するすべての部分は固定 2D ベクトルのスカラー倍になります。 

計算上の観点から見ると、最大 500 のソース ボトルと 500 のターゲット機関があります。 これにより、個々の無限小分割間のフローに対する 3 次または高次 2 次の構築が即座に除外されます。 すべてのペアごとの転送に関する単純な線形計画法でさえ、直接実装すると大きすぎます。これは、250,000 個の変数を含む n × m の 2 部フローが自然に示唆されるためです。 

重要な問題は、同じ割り当て構造を使用して 2 つの線形制約 (A と B) を同時に照合することです。 総量だけを気にするのであれば、これは標準的な輸送問題になります。 複雑なのは、同じフローが A と B の両方を同時に満たさなければならないため、すべての割り当てにわたって比率の一貫性が強制されることです。 

単純な推論が微妙に失敗するケースは、合計金額は一致するが、集計において比率に互換性がない場合に発生します。 

2 つのソース ボトルの A 対 B 比率が大きく異なるが、対象となる機関がこれらの比率を「インターリーブ」する混合物を要求している場合を考えてみましょう。 比率の順序を無視して任意のボリュームを一致させる貪欲な戦略では、たとえ合計が一致していても、A は完全に一致するが B は一致しないという状況が簡単に発生する可能性があります。 

もう 1 つの失敗例は、A と B を 2 つの別個の輸送問題として独立して解決できると仮定した場合です。 このアプローチでは、両方が同じ分割行列によって満たされる必要があることが無視されます。 

## アプローチ

 問題を直接拡張すると、変数が導入されます。$x_{ij}$、ソースボトルの量を表します$i$研究所に送られる$j$。 各ソースは固定比率に寄与するため、送信$x_{ij}$ボトルからmL$i$貢献する$x_{ij} a_i$Aと$x_{ij} b_i$制約は線形になります。 

各情報源について、送信される合計割合は 1 であり、各機関について、A と B の合計が目標と一致する必要があります。 

これは、高度に構造化された制約行列を使用した線形実現可能性問題です。 ブルート フォース ソルバーは、これを一般的な線形プログラム、または追加の結合制約を備えた大規模な最大フローとして扱います。 n、m が 500 までになると、それはすぐに不可能になります。 

重要な構造的洞察は、流れの各単位が一定の比率を持っているということです。$a_i / b_i$。 これは、各ソースが単なるスカラー電源ではなく、2D 空間の線上の点であることを意味します。 あらゆる混合物は、これらの点の凸状の組み合わせです。 各ターゲットも同じ空間内の点です。 

したがって、問題は、正しい総質量保存を用いてターゲット点をソース点の凸状の組み合わせに分解できるかということになります。 

重要な観察は、ソースとターゲットをその比率で並べ替えると、$a_i / b_i$そして$c_j / d_j$の場合、最適なマッチングではこの順序が尊重される必要があります。 直感的には、高比率のソースと低比率のターゲットを早い段階で混合すると、比率の混合を「元に戻す」方法がないため、後から修正が強制され、実現可能性が損なわれます。 

これにより、問題は貪欲なスイープに変換され、比率の最小側と比率の最小側を一致させ、常に一方の側が使い果たされるまで流れを押し出し、その後前進します。

 ## アルゴリズムのチュートリアル

 各ボトルと各研究所を 2D 空間上の一定の比率を持つセグメントとして解釈します。 各セグメントの総質量も次のとおりです。$a_i + b_i$または$c_j + d_j$。 アルゴリズムは、比率が増加する順にこれらのセグメントを照合します。 

1. 各ソースボトルの総質量を計算します。$s_i = a_i + b_i$とその比率$r_i = a_i / (a_i + b_i)$。 各機関に対して同じことを行い、次の情報を取得します。$t_j = c_j + d_j$そして$q_j = c_j / (c_j + d_j)$。 比率は、フロー単位内で A と B がどのように分割されるかを決定する唯一の情報です。 
2. ソースボトルを比率で分類する$r_i$昇順で。 研究機関を比率で並べ替える$q_j$昇順で。 これにより、最も「B-heavy」の混合物が最初に処理され、最も「A-heavy」の混合物が最後に一貫した順序で処理されます。 
3. 2 つのポインター (ソース上と研究所上に 1 つ) を維持し、現在のソースと現在の研究所の残りの質量を追跡します。 
4. 電流源と研究所の間でできるだけ多くの質量を移動させることにより、電流源と研究所を繰り返し一致させます。 移動量を残りの質量の最小値とする。 転送後、両方の残りの値をそれに応じて減らします。 
5. ソースが使い果たされたら、次のソースに移動します。 インスティテュートが満足したら、次のインスティテュートに移動します。 片面が終わるまで続けます。 
6. 最後に両側が完全に消費された場合は、Yes を出力します。 それ以外の場合は No を出力します。 

この手順が意味のある理由は、すべてのステップで、単調な順序で最も近い利用可能な比率を照合し、後で一貫性のない凸の組み合わせを強制する割り当ての「交差」を防ぐためです。 

### なぜ効果があるのか

 不変条件は、スイープのどの時点でも、すでに処理されたすべての情報源の比率が現在の情報源より大きくなく、すでに処理されたすべての機関の比率が現在の機関より大きくないことです。 実現可能な解決策はすべてこの順序を尊重する必要があります。そうしないと、より高い比率のソースがより低い比率の研究所に部分的に割り当てられる一方で、より低い比率のソースがより高い比率の研究所に割り当てられるため、結果として得られる混合物の凸分解に矛盾が生じます。 貪欲なマッチングでは、そのような交差が起こらないよう強制し、すべての転送で A と B の両方の比率が局所的に保存されるため、全体的な実現可能性は、この単調な結合の下で総質量が完全に一致できるかどうかにかかっています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))
    d = list(map(int, input().split()))

    src = []
    dst = []

    for i in range(n):
        s = a[i] + b[i]
        src.append((a[i] / s, s))

    for j in range(m):
        t = c[j] + d[j]
        dst.append((c[j] / t, t))

    src.sort()
    dst.sort()

    i = j = 0
    rem_s = src[0][1] if n else 0
    rem_d = dst[0][1] if m else 0

    while i < n and j < m:
        r_i, _ = src[i]
        r_j, _ = dst[j]

        take = min(rem_s, rem_d)
        rem_s -= take
        rem_d -= take

        if rem_s == 0:
            i += 1
            if i < n:
                rem_s = src[i][1]

        if rem_d == 0:
            j += 1
            if j < m:
                rem_d = dst[j][1]

    print("Yes" if i == n and j == m else "No")

if __name__ == "__main__":
    solve()
```この実装では、各コンテナを比率で重み付けされたセグメントに縮小し、2 ポインター スイープを実行します。 唯一の微妙な点は、セグメントを切り替えるときに残りの容量を正しく維持することです。 比率の一貫性は並べ替えによって構造的に強制されるため、アルゴリズムは A と B を個別に明示的に追跡する必要はありません。 

## 実用的な例

 ### サンプル 1

 ソートされたソースと宛先を比率で追跡し、マッチングをシミュレートします。 

| ステップ | ソース比率 | ソースが残っています | 宛先比率 | 残りの目的地 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0.25 | 4 | 0.5 | 4 | マッチ 4 |
 | 2 | 次へ | 0 | 0.5 | 0 | 両方を移動する |

 このプロセスはきれいに終了します。つまり、不均衡が残ることなくすべての質量が一致します。 

これは、完璧なモノトーンのペアリングを可能にする方法で比率が揃っているケースを裏付けています。 

### サンプル 2

 | ステップ | ソース比率 | ソースが残っています | 宛先比率 | 残りの目的地 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0.5 | 4 | 0.25 | 4 | 不一致が始まります |
 | 2 | マッチングを試みます | 部分的 | 部分的 | 失敗は伝播する | クリーンな完了がありません |

 ここでは、順序の不一致により片側に質量が残り、合計は全体的に一致しているが、比率構造には互換性がないことが示されています。 

これは、合計 A と B が等しいだけでは実現可能性としては十分ではないことを示しています。

 ## 特殊なケース

 すべてのソースの比率が同じ場合、重大なエッジケースが発生します。 この場合、すべての転送で同じ A 対 B の比率が維持されるため、ソートは無関係になり、問題は単純な一括マッチングに帰着します。 スイープでは不整合が決して発生しないため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、一方の側が他方よりも厳密に大きい比率範囲を持つ場合です。 たとえば、すべてのソースが低比率であるが、1 つの研究機関が非常に高比率の混合物を要求している場合、ソートにより、アルゴリズムが高比率の需要に到達する前に低比率の供給をすべて使い果たすことが保証され、一致しない要件が残され、正しく No. が返されます。 

最後のエッジケースは、情報源または機関が 1 つしかない場合です。 このような状況では、解決策は総質量の等しいことを確認することになり、スイープによって中間のあいまいさなしに即座にそれが検証されます。
