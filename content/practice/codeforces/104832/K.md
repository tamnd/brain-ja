 ## 解決策
 ## 問題の理解

 私たちは隠れた幾何学オブジェクト、つまり非常に大きな正方形のグリッド内のどこかに配置された円を操作しています。 正方形は両方の軸で 0 ～ 100000 の座標にまたがり、円は整数の中心座標と整数の半径を持ちます。 半径は少なくとも 100 であることが保証され、円は正方形の内側に完全に含まれます。つまり、境界を越えることはありません。 

情報を取得する唯一の方法は、2 つの整数点の間に線分を描画し、その線分が円の中にどれだけ含まれるかを取得することです。 言い換えれば、任意のセグメントについて、裁判官はそのセグメントの円板と交差する部分の全長を計算します。 

タスクは、最大 1024 個のこのようなクエリを使用して、正確な中心座標と半径を決定することです。 

制約構造は、ソリューションを強力に形成します。 中心の検索空間は 10^5 x 10^5 ですが、座標を 1 つずつ絞り込むグリッド検索やランダム サンプリングのアプローチには大きすぎます。 各クエリは概念的に比較的高価であるため、各プローブからできるだけ多くの幾何学的情報を抽出する必要があります。 重要な観察は、固定された水平線または垂直線に関する各クエリが単にブール値の答えを与えるのではなく、円の弦の長さに等しい連続値を与えるということです。 これにより、問題は離散的な探索から連続的なジオメトリに変換されます。 

プローブの線が円とまったく交差しない場合、微妙なエッジ ケースが発生します。 その場合、答えはまさにゼロです。 すべてのクエリが有用な幾何学的制約を返すと仮定する単純な戦略は、円から遠く離れた線を選択すると、暗黙のうちに失敗する可能性があります。 たとえば、円の中心が y = 90000 付近で半径 100 の場合に y = 0 をクエリすると、常に 0 が返され、使用可能な情報が得られません。 このソリューションでは、任意の固定プローブに依存することを避け、代わりに交差が存在する領域を積極的に特定する必要があります。 

## アプローチ

 ブルートフォース戦略では、グリッド上の多くの線を調査し、円が存在する場所を徐々に狭めようとします。 たとえば、すべての水平線 y = 0、1、2、… を試し、各線が円と交差するかどうかを検出し、すべてのコードのセットから円を再構成します。 各コードが中心と半径に制約を与えるため、これは理論的には妥当ですが、コストが法外に高くなります。 100,000 行を超える 1 回のスキャンでもすでに大きすぎるため、エンドポイントを正確に絞り込みたい場合は、各行に複数のプローブが必要になる場合があります。 

重要な構造的洞察は、円の水平スライスが非常に予測可能な方法で動作するということです。 水平線 y = Y を固定すると、円との交点 (存在する場合) は、長さが次のセグメントになります。 

2 * sqrt(r^2 − (Y − cy)^2)。 

この関数は中心までの垂直距離のみに依存します。 それは cy を中心に対称であり、弦の長さが 2r になる y = cy で正確に最大値に達します。 これは、多くの点から円を再構成する代わりに、この関数が最大化される場所を見つけることで cy を回復できることを意味します。 cy がわかれば、最大弦長から r が直接わかります。 

同じ考え方が、垂直線 x = X を使用して x 方向に対称的に適用され、cx の回復が可能になります。 

したがって、問題は、整数領域にわたる単峰関数のピークを見つけて、そのピークでの値を評価することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 全行網羅スキャン | O(10^5) クエリ | お(1) | 遅すぎる |
 | 弦の長さを使用した単峰性検索 | O(log 10^5) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

水平プローブを関数 f(Y) として扱います。ここで、f(Y) は、円と高さ Y の水平線との交点の長さを返します。この関数は、円の垂直範囲の外側では 0 で、中心まで増加し、その後対称的に減少します。 

この構造を 2 段階の検索で使用します。 

1. query 0 Y 100000 Y の形式のクエリを使用して、全範囲 [0, 100000] の Y に対して三値形式の離散検索を実行することにより、cy の値を検索します。各クエリは f(Y) を返します。 2 つの候補の高さの値を比較し、値が小さい側を破棄します。 これは、f(Y) が cy に単一の最大値を持つ単峰性であるため機能します。 
2. 検索が収束すると、最適な Y が cy として特定されます。 次に、y = cy で最後の水平クエリを 1 つ発行します。 直線は円の中心を通過するため、戻り値はちょうど 2r になります。 これから r を計算します。 
3. 同じ手順を x 方向に繰り返します。 g(X) を、(X, 0) から (X, 100000) までの x = X における垂直セグメントの交差長として定義します。 この関数も単峰性であり、最大値は cx です。 同じ検索戦略を使用して cx を特定し、それをマキシマイザーとして復元します。 
4. cx、cy、rを取得したら、答えを出力します。 

これが機能する理由は、円と軸に沿った固定線との交点が中心からの垂直距離によって完全に決定されるためです。 その距離は平方根の内側に凸の二次関係を形成し、対称的な単峰曲線を生成します。 検索手順は関数値の比較のみに依存するため、許容されるクエリ許容値を超える数値精度は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(x1, y1, x2, y2):
    print(f"query {x1} {y1} {x2} {y2}", flush=True)
    return float(input().strip())

def find_peak_horizontal():
    lo, hi = 0, 100000
    while hi - lo > 3:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        f1 = query(0, m1, 100000, m1)
        f2 = query(0, m2, 100000, m2)
        if f1 < f2:
            lo = m1
        else:
            hi = m2
    best_y = lo
    best_val = -1
    for y in range(lo, hi + 1):
        val = query(0, y, 100000, y)
        if val > best_val:
            best_val = val
            best_y = y
    return best_y, best_val

def find_peak_vertical():
    lo, hi = 0, 100000
    while hi - lo > 3:
        m1 = lo + (hi - lo) // 3
        m2 = hi - (hi - lo) // 3
        f1 = query(m1, 0, m1, 100000)
        f2 = query(m2, 0, m2, 100000)
        if f1 < f2:
            lo = m1
        else:
            hi = m2
    best_x = lo
    best_val = -1
    for x in range(lo, hi + 1):
        val = query(x, 0, x, 100000)
        if val > best_val:
            best_val = val
            best_x = x
    return best_x, best_val

def main():
    cy, max_h = find_peak_horizontal()
    r = int(round(max_h / 2))

    cx, _ = find_peak_vertical()

    print(f"answer {cx} {cy} {r}", flush=True)

if __name__ == "__main__":
    main()
```水平検索機能と垂直検索機能は構造的に同一であり、どの座標が固定されるかだけが異なります。 各クエリは軸に沿った全長セグメントを使用するため、戻り値が円の 1 つの弦に正確に対応することが保証されます。 

理想モデルでは返される最大弦長が数学的に正確に 2r であり、この問題では小さい数値誤差範囲で整数の半径が保証されるため、半径の丸めステップは安全です。

 これはインタラクティブであるため、実際の裁判官の相互作用ではなく、基礎となる動作をシミュレートします。 

隠れた円の中心 (60000、40000) と半径 30000 があると仮定します。 

まず水平検索を実行します。 

| ステップ | そうだ | こんにちは | m1 | 平方メートル | f(m1) | f(m2) | アクション |

 | 1 | 0 | 100000 | 33333 | 66666 | 小さい | 大 | 移動します |

 検索は、弦の長さが最大になる y = 40000 付近に徐々に集中します。

次に、垂直方向に繰り返し、cx = 60000 を回復します。 

これにより、弦長のピークが各次元の中心座標を独立して識別することが確認されます。

 ## 特殊なケース

 重大なケースの 1 つは、円がグリッドの境界に近い場合です。 たとえば、中心が (100, 50000) で半径が 100 の場合、水平関数は依然として単峰的に動作しますが、ほとんどの範囲で非常に非対称になります。 有効な間隔外ではほとんどのクエリがゼロを返しても、単峰性が維持されるため、アルゴリズムは引き続き機能します。 

もう 1 つのケースは、整数サンプリングにより最大値が 1 つの点上で平坦である場合です。 2 つの隣接する y 値がほぼ同じ弦長を生成する場合でも、三分探索は真の中心を含む小さな区間に収束し、その区間にわたる最後のブルート スキャンにより正しい整数座標が選択されます。 

最後の微妙なケースは、半径計算の数値精度です。 戻り値には 10^-6 までの小さな誤差が含まれる可能性があるため、四捨五入が必要です。 r は少なくとも 100 の整数であることが保証されているため、復元された 2r 値を最も近い整数に丸めることにより、曖昧さのない正確な半径が安全に復元されます。
