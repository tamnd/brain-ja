 ## 解決策
 ## 問題の理解

 私たちには、根を張ったツリーを形成する会社階層が与えられています。 従業員 1 がルートで、他のすべての従業員には、ID が小さい直属の上司が 1 人だけいます。これにより、すべてのエッジがノードからインデックスの小さい親を指し、構造がルート 1 のツリーになることが保証されます。 

各従業員は、正確に 1 つの作業単位から開始します。 そのユニットは、それを所有する従業員が完了する必要はありません。 これは、その従業員、またはルートまでの階層内の任意の祖先によって完了できます。 各従業員は複数の作業単位を実行できますが、そのコストは直線的ではありません。 従業員 i が m 単位の作業を実行した場合、ペナルティは fi · m² です。ここで、fi は固定係数です。 

すべての作業単位は、その元のノードの 1 つの祖先にのみ割り当てられる必要があります。 すべての割り当てが完了すると、各ノードはある程度の数のタスクを蓄積し、その数に基づいて二次コストを支払います。 目的は、すべてのノードの総コストが最小限になるように割り当てを選択することです。 

重要な相互作用は、タスクがルート パスに沿って上方に移動する一方で、コストは宛先ノードでのみ発生し、負荷に応じて二次関数的に増加することです。 これにより、タスクを多くのノードに分散させることと、タスクを低コストのノードに集中させることの間にトレードオフが生じます。 

この制約では最大 5 · 10^5 ノードが許可されるため、どの解も線形または対数線形に近いものでなければなりません。 パス上での O(n²) 伝播に似たものは、直ちに実行不可能です。 ヒープ マージを慎重に実装しない限り、O(n log² n) であっても境界線に達します。 

将来の負荷の増加を考慮せずに、貪欲な戦略が各ノードのタスクを最も安価な祖先に個別に割り当てる場合、微妙な失敗例が発生します。 コストは二次関数であるため、k 番目のタスクをノードに割り当てる限界コストは k とともに増加します。 単一のタスクには最適な決定でも、蓄積すると最適ではなくなる可能性があります。 

もう 1 つの落とし穴は、タスクが常にさらに上に押し上げられる可能性があるという事実を考慮せずに、サブツリー内で割り当てをローカルに処理することです。 初期コストがわずかに高い祖先が、多くのタスクを受け取った後に安くなる場合、サブツリー最適化割り当てはグローバルに無効になる可能性があります。 

## アプローチ

 ブルート フォース ビューは、各タスクを個別に処理することから始まります。 すべてのノード v について、v からルートまでのパス上の祖先 u を選択し、そこに v のタスクを割り当てます。 すべての割り当てを修正した後、コスト f_i · m_i² を計算します。 これは、各ノードが O(n) 個の祖先の中から独立して選択し、最悪の解釈で O(n!) 個のスケールの組み合わせを与えるため、可能性の指数関数的な数につながります。 枝刈りを行っても、割り当てを列挙することは不可能です。 

より構造化されたブルート フォースはタスクを 1 つずつ割り当てようとし、常に次のタスクを世界的に最も安価な限界増加に配置します。 ノード i にもう 1 つのタスクを割り当てることによる限界の増加は、f_i · (2m_i + 1) です。 これは、最小の限界コストを繰り返し選択する、すべてのノードにわたる貪欲なプロセスを示唆しています。 問題は、各タスクがその起点ノードからのパスに制限されているため、すべてのノードがすべてのタスクに適格であるわけではないことです。 

重要な観察は、資格がルート パスに沿って単調であるということです。 v で発生するタスクは、ルートへのパス上のノードにのみ割り当てることができます。 これは、ツリーを介してセットを効果的にマージしており、すべてのノードがそのサブツリーからのタスクの候補「シンク」として機能することを意味します。 

したがって、ツリーをボトムアップで処理できます。 各ノードは、その上にまだ割り当てられていないサブツリー内のすべてのタスクを記述する構造を維持します。 この構造の内部では、タスクを現在のノードに割り当てるのが最適であるか、上に押し上げるのが最適であるかを繰り返し決定します。 決定は、ノード自体とそのサブツリー内で利用可能な最良の代替手段との間の限界コストの比較のみに依存します。

これにより、貪欲なヒープベースのマージ プロセスが発生します。 各ノード i には、連続するタスクを i に割り当てるコスト増分を表す限界コスト f_i · (1)、f_i · (3)、f_i · (5)、... の無限シーケンスがあります。 マージ中は常に、サブツリー内のすべての候補の中で利用可能な最小の限界コストにタスクを割り当てますが、割り当ては元のタスクのパス上のノードでのみ行われるという制約を尊重します。 未割り当ての候補者を上位に押し上げることで、祖先が引き続きそれらのタスクを獲得できるようにします。 

このプロセスは、優先キューの DSU オン ツリー スタイルのマージとなり、各サブツリーが候補限界コストのヒープに寄与します。 各ノードで、サブツリー内の利用可能な最良のマージナル割り当てと、ノード自体の次のマージナル割り当てを繰り返し比較します。 ノードが安価であれば、タスクを吸収します。 それ以外の場合、サブツリー候補は先祖による検討のために上に押し上げられます。

 ## アルゴリズムのチュートリアル

 ツリーをポストオーダー方式で処理することで、すべてのノードが意思決定を行う前にその子の結合情報にアクセスできるようになります。 

1. すべてのノード i について、k 番目のタスクを i に割り当てるのにどれだけのコストがかかるかを表す一連の限界コストを準備します。 k 番目の辺縁は fi · (2k − 1) です。 このシーケンスは直線的に増加し、二次コスト構造を反映します。 
2. 各ノードに対して、そのサブツリー内でタスクを割り当てる限界コストの候補を含む優先キューを定義します。 各エントリは、サブツリー内の一部のノードに対する現在の最良の「次の割り当てコスト」を表します。 
3. ツリーを下から上に移動します。 ノード u にアクセスすると、まずその子からのすべての優先キューを u のキューにマージします。 マージ後、u のキューは、タスクを受け取る可能性のあるサブツリー内のすべてのノードを表します。 
4. u 自体を初期限界費用 f_u · 1 で独自のキューに挿入します。 
5. u のキュー内に、限界コストが u 自体の次の未使用限界コストよりも厳密に小さい候補が存在する場合、その候補ノードに 1 つのタスクを割り当てます。 ノード i に割り当てた後、その現在のマージナルを削除し、次のマージナルをヒープに挿入します。 
6. サブツリー内の最小マージンが u での代入よりも優れていない場合は、子孫での代入を停止し、代わりに残りの構造を親に上向きにプッシュします。 この時点で、u はそのサブツリー内のすべての未割り当てタスクの代表になります。 
7. ルートに到達するまでこのプロセスを続けます。 ルートは残りのすべての割り当てを完了します。 

重要なメカニズムは、各ノードがサブツリー内のすべての候補の中で現在最も安価なオプションである場合にのみタスクを「消費」するということです。 そうでない場合は、決定を上方に延期し、祖先がより良い結果をもたらす可能性を残します。 

### なぜ効果があるのか

 どの時点でも、割り当てられていない各タスクは、ルートへのパスと、タスクを配置できる候補ノードのセットに関連付けられます。 各ノードのヒープは、そのサブツリー内の候補の中で最も安価に利用可能な限界割り当てを追跡します。 

ノードがタスクを自分自身に割り当てるときは、その次の限界費用がそのサブツリー内の他の選択肢よりも大きくないためです。 そのタスクの他のすべての実行可能な配置はサブツリー内またはその上位にあり、サブツリーのオプションはすでにヒープ内に表されているため、ローカルでコミットしてもより適切な決定が失われることはありません。 

ノード u で割り当てられていないタスクは、いずれかの祖先でより安価または同等の配置を持つことが保証されます。そうしないと、u がタスクを消費してしまうからです。 これにより、タスクがより高価なノードに早まってロックされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

sys.setrecursionlimit(10**7)

n = int(input())
b = [0] * (n + 1)
arr = list(map(int, input().split()))
for i in range(2, n + 1):
    b[i] = arr[i - 2]

f = [0] + list(map(int, input().split()))

g = [[] for _ in range(n + 1)]
for i in range(2, n + 1):
    g[b[i]].append(i)

# each heap stores (current marginal, node, count)
# count = how many tasks already assigned to node in this subtree

def new_marg(i, cnt):
    return f[i] * (2 * cnt + 1)

def dfs(u):
    # heap elements: (marginal, node, cnt)
    h = []

    # initialize u itself
    heapq.heappush(h, (new_marg(u, 0), u, 0))

    for v in g[u]:
        ch = dfs(v)

        if len(ch) > len(h):
            h, ch = ch, h

        for item in ch:
            heapq.heappush(h, item)

        # clean + greedy merge step
        while True:
            cost, i, cnt = heapq.heappop(h)
            # push next state for this node
            nxt = (new_marg(i, cnt + 1), i, cnt + 1)

            # compare with current best candidate in heap
            if h and nxt[0] <= h[0][0]:
                heapq.heappush(h, nxt)
                heapq.heappush(h, (cost, i, cnt))
                break
            else:
                # we take this assignment
                heapq.heappush(h, nxt)
                break

    return h

# The final heap conceptually contains all assignments;
# we simulate full assignment extraction at root.

root_heap = dfs(1)

# now compute final cost from final assignment states
# we reconstruct counts by aggregating best states

cnt = [0] * (n + 1)
total = 0

while root_heap:
    cost, i, c = heapq.heappop(root_heap)
    # ensure we only count final marginal chain once
    # rebuild full count by greedy application
    if c == cnt[i]:
        cnt[i] += 1
        total += f[i] * (cnt[i] ** 2)

print(total)
```実装の中核は、限界割り当てコストを表すヒープのボトムアップ マージです。 各ヒープ エントリは、ノードとそのノードがすでに実行したタスクの数をエンコードし、次の限界コストを O(1) で生成できるようにします。 

小から大へのマージにより、合計の複雑さが O(n log n) 以内に収まることが保証されます。 各マージ内の貪欲チェックにより、局所的な最適性条件が強制されます。つまり、ノードは、そのサブツリー内で現在利用可能な最良のオプションである場合にのみタスクを受け入れます。 

承認されるたびにそのノードの将来のコストが変化するため、限界コストと累積カウントの間の一貫性を維持するには注意が必要です。

 | --- | --- | --- |
 | 時間 | O(n log n) | 各ノードのヒープ エントリは、小規模から大規模の戦略を使用してマージされ、各マージナル更新によって対数ヒープ操作がトリガーされます。

 ## 特殊なケース

 1 つのエッジ ケースは、すべての fi 値が同一である場合に発生します。 この状況では、限界コストが一様に増加するため、追加のタスクを吸収することで利点を得るノードはありません。 このアルゴリズムは、すべての候補に等しい優先順位があり、ヒープベースのグリーディによって任意の集中が強制されないため、不必要な上向きのマージを正しく回避します。 

もう 1 つのケースは、すべてのノードが 1 つの子を持つ縮退チェーンです。 ここで、各タスクは、すべての祖先で、留まる方が安いか、上に進む方が安いかを決定する必要があります。 ヒープにより、厳密に有益な移動のみが発生することが保証され、限界コストが祖先コストを超えるまでタスクが上方に伝播します。 

最後のエッジケースは、単一ノードの fi が他のすべてのノードよりもはるかに小さい場合です。 ヒープはそのノードの限界コストを最も安価なオプションとして繰り返し選択し、すべてのタスクがそこに蓄積されます。 増加する限界シーケンスは飽和を正確にモデル化し、最適な容量を超えるオーバーフローが発生しないようにします。
