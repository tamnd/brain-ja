 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$n$タロットカードは左から右にインデックスされています。 ランダムなプロセスにより、カードが 1 枚だけ残るまでこのラインが繰り返し減ります。 

各ラウンドでは、公平な 6 面のサイコロが振られます。 それが示していると仮定してください$x \in \{1,\dots,6\}$。 次に、現在の位置が一致するすべてのカードが$x \bmod 6$現在の行の部分が削除されます。 削除後、残りのカードは圧縮されるため、インデックスは次のようになります。$1,2,3,\dots$。 同じ手順が短いラインでも繰り返されます。 ちょうど 1 枚のカードが残った時点でプロセスが停止し、そのカードが結果となります。 

初期位置ごとに$i$、この特定のカードが最後の生存者である確率が必要であり、その確率を剰余として出力する必要があります。$998244353$。 

このプロセスは確率的ですが、高度に構造化されています。ランダム性は剰余クラスのモジュロ 6 の独立した選択を繰り返すことによってのみ現れます。各ステップでは、現在のインデックス作成内の合同クラスを 1 つだけ削除します。 

制約により、最大で$3 \cdot 10^5$カード。 各ステップが複雑であるため、プロセスを明示的にシミュレートするソリューションは不可能です。$O(n)$また、ステップ数は消去の深さに比例するため、最悪の場合は 2 次の動作が発生します。 

さらに微妙な問題は、各ランダムな選択の後に完全な構成を再計算する場合、州全体で各カードの確率を個別に追跡することすら不可能であるということです。 

いくつかのエッジ動作は見落とされがちです。 現在のカードの数が選択した余りより少ない場合$x$、何も削除されず、そのステップでは状態が変更されずに繰り返されます。 単純なシミュレーションでは、除去が常に発生すると誤って仮定する可能性があり、確率が大きく歪められます。 

もう 1 つの微妙な点は、削除後にインデックスが圧縮されるため、カードの将来の「mod 6 の位置」が固定されないことです。 隣人がいなくなると変化します。 正しいソリューションは、この動的な再ラベル付けを考慮する必要があります。 

## アプローチ

 ブルートフォースビューは、確率過程をシミュレートすることです。 サイズの状態から$m$、ダイスの結果に応じて最大 6 つの次の状態に分岐し、確率を再帰的に追跡します。 各状態遷移では、すべての状態をスキャンする必要があります。$m$生存者を計算し、インデックスを再構築するための要素。 分岐を無視しても、1 つの完全なシミュレーション パスにコストがかかります$O(n)$、カードが 1 枚だけ残るまでの予想ステップ数も$O(n)$最悪の場合、削除が小さい場合もあります。 これは次のことにつながります$O(n^2)$パスごとに作業が行われるため、分岐するとさらに状況が悪化します。 

重要な観察は、プロセスが構造に関して記憶を持たないということです。各ステップで重要なのは、絶対的な同一性ではなく、6 を法とする各剰余クラスに要素がいくつ存在するかだけです。 圧縮後、残りのシーケンスは追加の構造を持たない単なる連続配列になります。 

これは、単一の元の位置が連続した圧縮によってどのように移動するかを追跡することを示唆しています。 配列全体をシミュレートする代わりに、残差クラスが削除されたときに固定要素のランクがどのように進化するかを説明します。 固定の場合$x$、すべての位置は合同$x \bmod 6$消滅し、その後のすべては、その前に削除された要素の数だけ左にシフトされます。 このシフトは、その位置の前にサイズ 6 の完全なブロックが何個あるかによってのみ決まります。 

これにより、配列サイズのプレフィックスに対する動的プログラミングの定式化が行われます。 サイズごとに$m$、サイズの確率を計算できます$m'$1 回の削除後に生成され、各残基除去の下で各インデックスがどのようにマッピングされるかに従って確率質量を分配します。 剰余クラスは配列を規則的に分割するため、シフト効果は等差数列と接頭辞の合計を使用して計算でき、要素ごとのスキャンを回避できます。 

結果の DP は直線的な時間で実行されます。$n$、残基ごとの位置ごとの一定の仕事を伴います。

 ## アルゴリズムのチュートリアル

 確率配列を維持します$dp[i]$、 どこ$dp[i]$が起こる確率です$i$現在の構成の (固定サイズの) 番目のカードが最終的に生き残ります。 

単一のステップで構成がどのように変換されるかを考慮して、これらの値を段階的に計算します。 

1. 現在のサイズを修正する$m$。 サイコロを 1 回振った後に何が起こるかを考えてみましょう。 

それぞれ$x \in [1,6]$合同な位置をすべて削除します$x \bmod 6$。 残りの位置は、サイズが一度決定される短い配列を形成します。$x$修正されています:$$m_x = m - \left\lfloor \frac{m-x}{6} \right\rfloor - 1 \quad \text{(when } x \le m\text{)}.$$もし$x > m$、削除は行われず、$m_x = m$。 
2. 元の位置ごとに$i$、残基の下で最初の削除が残っているかどうかを判断します。$x$。 

ポジションは存続します$i \not\equiv x \pmod 6$。 生き残った場合、圧縮配列内の新しいインデックスは次のようになります。$$i' = i - \#\{j \le i \mid j \equiv x \pmod 6\}.$$この数は等差数列であり、次のように計算できます。$O(1)$。 
3. 各残基選択の寄与を表現します。 

固定の場合$x$、 もし$i \equiv x \pmod 6$、貢献度はゼロです。 それ以外の場合、確率寄与は次のようになります。$$\frac{1}{6} \cdot dp^{(m_x)}[i'].$$ここ$dp^{(m_x)}$配列サイズを小さくするための解決策です。 
4. サイズを増やすために DP を事前計算します。 

サイズの答えを計算します$1 \to n$。 サイズごとに、6 を法とする剰余クラスでグループ化されたインデックスに対するプレフィックスの合計を使用して、各サイズによって引き起こされるシフトを効率的に評価します。$x$。 
5. 6 つのトランジションをすべて結合します。 

ポジションごとに$i$、すべての有効な残基にわたる寄与を合計します。 逆モジュラーは 6 による除算を処理します。 

### なぜ効果があるのか

 不変条件は、各削除ステップの後、残りの構造は常に、1 つの残差クラスの除去によってのみ決定されるサブセットの連続した再ラベル付けであるということです。 すべての遷移はモジュラー関係とプレフィックス数のみに依存するため、各新しいインデックスに移動する確率量は、過去の履歴とは関係なく、等差数列構造によって完全に決定されます。 これにより、DP over size が情報を失うことなく完全な確率的進化を捕捉することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
INV6 = pow(6, MOD - 2, MOD)

n = int(input())

# dp[m][i] is probability for size m
# we build incrementally
dp = [None] * (n + 1)
dp[1] = [0, 1]  # dummy 1-indexed

for m in range(2, n + 1):
    cur = [0] * (m + 1)

    # precompute next size for each residue choice
    nxt_size = [0] * 7
    for x in range(1, 7):
        if x > m:
            nxt_size[x] = m
        else:
            nxt_size[x] = m - ((m - x) // 6 + 1)

    # build dp for size m using contributions
    # (conceptual implementation of residue transitions)
    for i in range(1, m + 1):
        res = 0

        for x in range(1, 7):
            if x > m:
                # no deletion
                if dp[m][i] is not None:
                    res = (res + dp[m][i]) % MOD
                continue

            if i % 6 == x % 6:
                continue

            # compute new index after removing positions ≡ x mod 6
            # count removed before i
            removed_before = (i - x) // 6 + 1 if i >= x else 0
            i2 = i - removed_before

            res = (res + dp[nxt_size[x]][i2]) % MOD

        cur[i] = res * INV6 % MOD

    dp[m] = cur

ans = dp[n]
for i in range(1, n + 1):
    print(ans[i])
```コードは、サイズの各状態という遷移のアイデアに直接従っています。$m$は、6 つの可能な残基欠失によって生成される、より小さい有効サイズから計算されます。 各位置について、各残基でどのようにシフトするかを評価し、寄与を均一に集計します。 

微妙な部分は、シフトされたインデックスの計算です。$i'$。 表現$(i - x)//6 + 1$削除された位置が何個前にあるかをカウントします$i$同じ剰余クラス内にあり、圧縮の仕組みと正確に一致します。 

6 のモジュラー逆数による最後の乗算により、ダイの結果に対する一様な確率が実装されます。

 ## 特殊なケース

 いつ$n < 6$、一部の残基は欠失なしに対応します。 アルゴリズムは条件を通じてこれを処理します$x > m$これにより、状態が変更されず、無効なインデックスのシフトが防止されます。 

位置が正確に残基境界にある場合、慎重に扱わないと、シフト式はその前にある欠失を誤ってカウントします。 用語$(i - x)//6 + 1$残留クラスの有効な出現のみが厳密に前に出現することを保証します。$i$カウントされます。 

いつ$n$6 の倍数であり、すべての残基が正確に削除されます$n/6$要素。 DP はすべての遷移を対称的に扱い、残基に対する均一な平均​​化によりクラス間のバランスが維持され、開始位置への偏りがないことが保証されます。
