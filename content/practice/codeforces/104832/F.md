 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$固定の市松模様パターンで始まるグリッド。 細胞$(i, j)$の場合は最初は黒です$i + j$それ以外の場合は奇数で白です。 次に、行全体または列全体を反転する操作を繰り返し適用します。 反転とは、その行のすべてのセルの色が変わることを意味します。 

各操作の後、接続が共有エッジを介して行われるグリッド内に、одинаков 色のセルの接続されたコンポーネントがいくつ存在するかを報告する必要があります。 

重要な問題はスケールです。 両方$n$そして操作の数$q$到達できる$5 \times 10^5$, したがって、セルに明示的に触れるものは何も不可能です。 各操作が影響を与える可能性があるため、グリッドを明示的に維持することすら不可能です。$O(n)$細胞、につながる$O(nq)$行動。 

出力はグローバル構造の影響を受けます。単一行の反転により、すべての列の隣接関係が変更され、その逆も同様です。 各操作の後にコンポーネントを再計算する単純なアプローチでは、BFS または DSU が繰り返し実行されます。$n^2$ノードは完全に範囲外です。 

繰り返しのフリップが打ち消されると、微妙なエッジケースが現れます。 たとえば、同じ行を 2 回反転すると元の状態が復元されますが、パリティなしで「反転したかどうか」だけを追跡する中間推論方法では、構造の変更が永続的なものとして誤って扱われる可能性があります。 

もう 1 つの問題は、接続性が色だけでなく、元のチェッカーボードのパリティとの位置合わせにも依存することです。 一般的な障害モードは、反転がローカル領域にのみ影響するものと想定していますが、実際には行または列全体に沿ってパリティ関係をグローバルに切り替えます。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 グリッドを明示的に維持し、各操作の後に切り替えて行または列全体を反転します。$n$細胞。 次に、すべてに対してフラッド フィルまたは DSU を実行します。$n^2$セルを使用して、同じ色の接続されたコンポーネントをカウントします。 

これは問題の定義に直接従うため、正しいです。 ただし、それぞれの操作に費用がかかります$O(n)$申請して、$O(n^2)$接続性を再計算し、その結果、$O(qn^2)$、両方の次元が大きい場合、これは実現可能性をはるかに超えています。 

重要な観察は、グリッドは決して恣意的に変更されないということです。 最初は完全なチェッカーボードであり、すべての操作は行全体または列全体に適用されるパリティ フリップです。 これは、各セルの最終的な色が、その行と列に適用される反転のパリティの観点から純粋に表現できることを意味します。 

グリッドを追跡する代わりに、各行が奇数回反転されたかどうか、および各列が奇数回反転されたかどうかという 2 つのブール配列を追跡します。 セルの最終的な色$(i, j)$これら 2 つの値と元のパリティの決定論的な関数になります$i + j$。 

これにより、行と列のパリティ状態のみに基づいて、グリッドが接続された単色領域にどのように分割されるかを理解するという問題が軽減されます。 セル間の隣接性は隣接するセルの色が異なるかどうかに依存し、行/列パリティの違いによって完全に表現できるため、構造はさらに簡素化されます。 

最終的な洞察は、グリッドは、対応する行または列の反転が一致しないかどうかにのみ応じて、隣接するセル間のエッジが「同じ色」または「異なる色」のいずれかになる二部構造として見なせるということです。 各操作は 1 つの行または列の状態を切り替えるだけなので、接続されたコンポーネントの数を更新する小さな動的構造を維持できます。$O(1)$または$O(\log n)$操作ごとに。 

結果として得られるソリューションは、アクティブな行反転と列反転の数を追跡し、行と列に沿って存在する一貫したパリティ領域間の遷移の数をカウントします。 各更新では 1 行のみが変更されるため、コンポーネント数に対するローカルな寄与のみが変更されます。

 ## アルゴリズムのチュートリアル

 パリティ状態の観点からグリッドを再構成します。 させて$R[i]$行かどうかを示します$i$奇数回反転され、$C[j]$列についても同様です。 セルの実際の色$(i, j)$と組み合わせた初期チェッカーボード パリティによって決定されます。$R[i] \oplus C[j]$。 

接続されたコンポーネントの構造は、隣接するセルが同じ最終色を共有するかどうかによって異なります。 間の水平隣接の場合$(i, j)$そして$(i, j+1)$、違いは次のいずれかによってのみ異なります。$C[j] \neq C[j+1]$。 垂直方向の隣接性の場合、それは次のいずれかにのみ依存します。$R[i] \neq R[i+1]$。 

この観察により、グリッドが独立した水平方向と垂直方向の一貫した構造に分離されます。 

### アルゴリズムのステップ

 1. 2 つのブール配列を維持する$R$そして$C$、最初はすべて false です。 それぞれの操作で 1 つのエントリが切り替わります。 パリティのみが重要であるため、生のカウントではなく、フリップのパリティを表します。 
2. 2 つのカウンターを維持します。$rowDiff$インデックスの数と等しい$i$そのような$R[i] \neq R[i+1]$、 そして$colDiff$列についても同様に定義されます。 これらは、色の一貫性が水平または垂直に崩れる境界を表します。 
3. 行を反転する場合$i$、以下を含む比較のみ$R[i]$そしてその隣人も変わります。 これは、最大 2 つの隣接ペアに影響します。$(i-1, i)$そして$(i, i+1)$。 更新します$rowDiff$トグルの前後を確認することで一定時間で実行されます。 
4. 同様に列を反転する場合$j$、更新します$colDiff$近隣のみを使用する$j-1$そして$j+1$。 
5. 独立した行と列のカット構造を持つ市松模様のグリッド内の接続されたコンポーネントの数は、これらのカットによって引き起こされる長方形のブロックを数えることから導出される公式によって与えられます。 水平ブレークと垂直ブレークはそれぞれ、グリッドを領域に分割し、その交差部分がコンポーネントを定義します。 
6. 各操作の後、維持されている水平および垂直パーティションの数を使用してコンポーネントの数を計算します。$(rowDiff + 1) \times (colDiff + 1)$、チェッカーボード反転パリティによって調整されます。 

### なぜ効果があるのか

 すべての色の変更は行と列のパリティ効果に分離できるため、グリッドの接続は軸に沿ったパーティションに分解されます。 隣接する 2 つのセルのインデックス間の行または列のパリティが一致しない場合、そのセルの色は正確に異なります。 したがって、接続性は、これらのパリティ配列に境界が存在するかどうかのみに依存します。 各操作は 1 ビットを反転するため、ローカル境界カウントにのみ影響し、すべての更新を通じてグローバル パーティション表現の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    R = [0] * (n + 2)
    C = [0] * (n + 2)

    row_diff = 0
    col_diff = 0

    def flip_row(i):
        nonlocal row_diff
        for j in [i - 1, i]:
            if 1 <= j < n:
                row_diff -= (R[j] != R[j + 1])
        R[i] ^= 1
        for j in [i - 1, i]:
            if 1 <= j < n:
                row_diff += (R[j] != R[j + 1])

    def flip_col(j):
        nonlocal col_diff
        for i in [j - 1, j]:
            if 1 <= i < n:
                col_diff -= (C[i] != C[i + 1])
        C[j] ^= 1
        for i in [j - 1, j]:
            if 1 <= i < n:
                col_diff += (C[i] != C[i + 1])

    for _ in range(q):
        parts = input().split()
        if parts[0] == "ROW":
            flip_row(int(parts[1]))
        else:
            flip_col(int(parts[1]))

        print((row_diff + 1) * (col_diff + 1))

if __name__ == "__main__":
    solve()
```この実装では、行と列のパリティ配列のみが保持されます。 各フリップは最大 2 つの隣接関係を更新し、構造変更の定常的なメンテナンスを保証します。 最後の式では、パリティの変更によって引き起こされる水平セグメントと垂直セグメントの数を乗算し、各演算後のコンポーネント数を生成します。 

反転すると 2 つの隣接するインデックスが一致するかどうかが変化するため、行または列を切り替える前に隣接関係の寄与を更新するように注意する必要があります。 この順序が欠けていると、境界カウントで 1 つずつずれたエラーが発生します。

 ## 特殊なケース

 1 つのエッジ ケースは、同じ行または列の反転が繰り返されることです。 状態はパリティとして保存されるため、2 回反転すると以前の隣接構造が復元されます。 各フリップでは同じ境界の寄与が削除され、再度追加されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、1 または$n$。 存在する隣接ペアは 1 つだけであるため、更新ロジックは 2 つではなく 1 つの隣接ペアのみに正しくアクセスします。 条件付き境界により、正しい構造寄与を更新しながら、無効なインデックス アクセスが発生しないことが保証されます。 

最後のエッジケースは次のような場合です$n = 1$。 隣接ペアがないため、両方のカウンタはゼロのままで、コンポーネントの数は操作に関係なく 1 で一定の​​ままです。 式$(row\_diff + 1)(col\_diff + 1)$この場合、正しく 1 と評価されます。
