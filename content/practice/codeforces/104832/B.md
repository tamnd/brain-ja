 ## 解決策
 ## 問題の理解

 1 人のプレイヤーに対して一連のクイズ結果が与えられ、各結果は正解か不正解のいずれかになります。 プレイヤーはランク 0 から開始し、ランクは上がるだけです。 

ランクを上げるためのルールは、履歴の最新部分を遡ることに基づいています。 各クイズの後、プレーヤーがその開始位置の前にすでに現在のランクにいて、セグメントが十分に長く、そのセグメント内の精度が十分に高いなど、より早い開始位置を見つけようとします。 そのようなセグメントが存在する場合、ランクはすぐに上がります。 

これをより操作的な方法で言い換えると、e 番目のクイズを処理した後、十分に遅く開始され (しかし遅すぎない)、長さが少なくとも c で、正解率が少なくとも p/q である、e で終わる有効なウィンドウが存在するかどうかを知りたいと考えます。 そのようなウィンドウが存在する場合、プレーヤーのランクは 1 つ増加し、同じ時点のポジションでさらなる昇格を確認し続けます。 

入力サイズでは、最大 500,000 個のクイズが可能です。 パラメータ c は最大でも 200 ですが、これは、位置ごとにすべての可能なウィンドウをスキャンすることに依存する解決策は遅すぎるという強力なヒントです。 すべての終了位置に対してすべての開始点を試す 2 次アプローチでは、最悪の場合でも約 10¹¹ のチェックが必要になりますが、これは現実的ではありません。 

したがって、正しいソリューションでは、履歴全体を再スキャンせずに、エンドポイントごとに条件を満たすウィンドウが存在するかどうかを回答できる情報を維持する必要があります。 

整数の精度が原因で比率条件がほとんど失敗しない、またはほとんど成功しない場合、微妙なエッジ ケースが発生します。 たとえば、p/q が 1/2 の場合、正解が 2 つある長さ 3 のセグメントは合格しますが、正解が 1 つある長さ 2 のセグメントも正確に境界上にあり、合格します。 浮動小数点除算を使用するソリューションでは、精度エラーや大きな入力に対する誤ったプロモーションが発生する危険があります。 

もう 1 つのエッジ ケースは、開始位置 s が現在のランクを尊重しなければならないという制約です。昇格後は、プレーヤーがそれらのポイントよりも前にそのランクをすでに離れていると見なされるため、早期の有効な開始は無関係になります。 

## アプローチ

 直接的なアプローチは、すべての終了インデックスに対して、考えられるすべての開始インデックスをシミュレートすることです。 各 e について、1 から e までのすべての を試し、ランク制約をチェックし、長さ制約をチェックして、セグメント全体の比率を計算します。 プレフィックスの合計を事前に計算したとしても、最悪の場合は O(n²) チェックにまで縮退し、5×10⁵ までの n に対しては遅すぎます。 

重要な観察は、比率条件を線形不等式に変換できるということです。 正解を 1 に、不正解を 0 にマッピングすると、s から e までのセグメントは、q・sum ≥ p・(e − s + 1) の場合に限り、sum / length ≥ p / q を満たします。 並べ替えると、プレフィックスの合計に関する条件が与えられます。 

q・(prefix[e] − prefix[s−1]) − p・(e − s + 1) ≥ 0。 

これは、接頭辞の比較として書き直すことができます。 

(スケーリングされた prefix[e]) マイナス (スケーリングされた prefix[s−1]) ≥ 0。ここで、各位置は正解に対する q と長さの各ステップに対する −p に寄与します。 これにより、問題は、各 e について、変換された接頭辞の差が負でないような制限された範囲内にインデックス j = s−1 が存在するかどうかを確認することに変わります。 

長さの制約により s ≤ e − c + 1 が強制され、これは j ≤ e − c になります。 ランク制約により、s が少なくとも現在のランクの開始点に制限されるため、j も以下に制限されます。 したがって、各 e について、プレフィックス値が prefix[e] ≥ prefix[j] を満たすのに十分な最小となるようなインデックス j がスライド間隔に存在するかどうかを知る必要があります。

この構造は、プレフィックス合計に対する移動ウィンドウ最小クエリになりました。 e は増加するだけであり、各ランクの左境界も増加するだけであるため、各ランクの候補プレフィックス インデックスの単調デキューを維持できます。 これにより、償却された O(1) 内の新しいインデックスの挿入と古いインデックスの削除の両方が可能になり、常に有効な範囲内の最小プレフィックスをクエリすることができます。

 ## アルゴリズムのチュートリアル

 変換されたシーケンスにわたるプレフィックス配列と、現在のランクの有効な範囲内の最小プレフィックス値を常にクエリできるスライディング構造を維持します。 

1. 入力文字列を、各正解が 1 を寄与し、各不正解が 0 を寄与する配列に変換し、それに対してプレフィックスの合計を構築します。 
2. 現在のランクについて、プレーヤーがセグメントを開始できる最も早いインデックスを表す左境界 L を維持します。 この境界はランクが上がるたびに前に進みます。 
3. 終了位置 e ごとに、s ≥ L および s ≤ e − c + 1 となるような有効な開始位置 s が存在するかどうかを計算します。これは、範囲 [L−1, e−c] 内のインデックス j = s−1 をチェックすることと同等です。 
4. プレフィックス値がデキューに沿って増加するように、プレフィックス配列全体にわたってインデックス j のデキューを維持します。 これにより、両端キューの先頭が常に現在のウィンドウの最小プレフィックス値を保持することが保証されます。 
5. e が増加するにつれて、適格になったときに新しいインデックス e-c を両端キューに挿入し、最小長の制約を満たす開始のみを考慮するようにします。 
6. インデックスが L-1 より前にある場合は、ランク制限により無効になっているため、両端キューの先頭からインデックスを削除します。 
7. 各 e について、prefix[e] を両端キューの先頭に格納されている最小プレフィックス値と比較します。 prefix[e] がそれ以上の場合、有効なセグメントが存在し、プロモーションが発生します。 
8. 昇進が発生したら、ランクを上げ、L を e+1 に移動します。 以前の開始は新しいランクでは無効になるため、デキュー状態を再初期化するか調整してください。 

### なぜ効果があるのか

 任意の固定エンドポイント e およびランクにおいて、e で終わるすべての有効なセグメントは、制限された区間内の j = s−1 の選択に正確に対応します。 成功の条件は、prefix[e] と prefix[j] の比較のみに依存するため、その間隔内の最小の prefix[j] のみが必要です。 単調デキューは、間隔の両端が時間の経過とともに前進する間、この最小値を効率的に維持し、履歴を再スキャンすることなく正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c, p, q = map(int, input().split())
    s = input().strip()

    # prefix sums of correct answers
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if s[i - 1] == 'Y' else 0)

    rank = 0
    L = 1  # 1-based index of first quiz in current rank
    from collections import deque
    dq = deque()

    # we will maintain candidates j = s-1, so j in [0..n]
    # condition: pref[e] >= pref[j] + threshold transformation handled below

    # transform inequality:
    # q*(pref[e]-pref[s-1]) >= p*(e-s+1)
    # => q*pref[e] - p*e >= q*pref[s-1] - p*(s-1)
    # so we compare transformed prefix values

    trans = [0] * (n + 1)
    for i in range(0, n + 1):
        trans[i] = q * pref[i] - p * i

    # dq maintains indices with increasing trans value
    add_ptr = 0

    for e in range(1, n + 1):
        # add new candidate start index j = e-c
        j = e - c
        if j >= 0:
            while dq and trans[dq[-1]] >= trans[j]:
                dq.pop()
            dq.append(j)

        # remove out of range for rank
        while dq and dq[0] < L - 1:
            dq.popleft()

        # check promotion
        while dq and trans[e] >= trans[dq[0]]:
            rank += 1
            L = e + 1
            dq.clear()
            break

    print(rank)

if __name__ == "__main__":
    solve()
```この実装では、まず問題をプレフィックスの合計に圧縮し、次に、変換されたプレフィックス式を使用して比率条件を線形比較に変換します。 これにより、浮動小数点演算が完全に回避されます。 

デキューは、変換されたプレフィックス値によってインデックス付けされた候補開始点を格納し、常に最良の候補を先頭に保ちます。 有効な開始のスライディングの性質は、現在のランクの許可された境界より前にあるインデックスを破棄することによって処理されます。 昇格が発生すると、システムは許可された開始境界をリセットします。これにより、以前に保存されたすべての候補も無効になるため、両端キューがクリアされます。 

ここでよくある間違いは、条件がセグメントの長さに依存することを忘れていることです。そのため、変換に項 -p・i が含まれています。 これがなければ、不等式を単純なプレフィックス最小クエリに縮小することはできません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, c, p, q = map(int, input().split())
    s = input().strip()

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (1 if s[i - 1] == 'Y' else 0)

    trans = [q * pref[i] - p * i for i in range(n + 1)]

    rank = 0
    L = 1
    dq = deque()

    for e in range(1, n + 1):
        j = e - c
        if j >= 0:
            while dq and trans[dq[-1]] >= trans[j]:
                dq.pop()
            dq.append(j)

        while dq and dq[0] < L - 1:
            dq.popleft()

        while dq and trans[e] >= trans[dq[0]]:
            rank += 1
            L = e + 1
            dq.clear()
            break

    return str(rank)

 ## 特殊なケース

 1 つのエッジ ケースは、最初に考えられる有効なセグメントが正確に長さ c に現れるときに発生します。 アルゴリズムは、候補開始インデックスが有効になった後にのみ候補開始インデックスを挿入することでこれを処理し、時期尚早な評価が発生しないようにします。 

もう 1 つのエッジケースは、理論的には同じエンドポイントで複数のプロモーションが発生する可能性がある場合です。 この実装では、昇格するたびに両端キューをクリアし、左の境界をシフトして、以降のチェックで古い開始点が再利用されないようにします。 

3 番目のエッジ ケースは、厳密にパフォーマンスが低下するパターンであり、比率条件を満たすセグメントがありません。 この状況では、デキューは引き続き候補を蓄積する可能性がありますが、プレフィックス比較は通過しないため、ランクは 0 のままで、無効なプロモーションはトリガーされません。
