 ## 解決策
 ## 問題の理解

 小文字で構成される単一の文字列が与えられており、それを小さな文法で定義された圧縮形式で書き換えたいと考えています。 許可される表現は、プレーン文字、より小さい有効な表現の連結、または括弧で囲まれた文字列の前に 2 から 9 までの数字が書かれ、内側の文字列がその回数だけ繰り返される繰り返し形式のいずれかです。 

重要な問題は、繰り返しが入れ子になる可能性があることです。 1 桁の繰り返しでは 1 レベルの繰り返しが最大 9 に制限されますが、これらの構成を積み重ねることにより、より大きな繰り返し数を達成できます。 たとえば、ブロックを 30 回繰り返す場合は、30 を 5 の 6 倍として表現することで可能になるため、6(5(a)) と書くことができます。 各レベルでは数字と括弧のペアが導入され、内部でも同じルールが適用されます。 

出力は、圧縮された長さだけではなく、実際に最も短い有効なエンコードされた文字列です。 最も短いエンコードは受け入れられます。 

制約は、部分文字列に対する 3 次動的計画法には十分小さいものです。 文字列の長さは最大 200 であり、すべてのエンコーディングを明示的に列挙しようとするソリューションや、すべての文法的に有効な形式に対して指数関数的な検索を実行するソリューションは除外されます。 すべての分割とすべての繰り返し構造を試行するソリューションは、各部分文字列が効率的に処理される場合には受け入れられます。 

単純なアプローチでは、各部分文字列に対して可能なすべてのエンコーディングを構築し、それらを比較しようとします。 これは、適度な部分文字列であっても、任意のネストと連結の選択により、指数関数的に多くの有効な派生が存在するため、すぐに失敗します。 

2 番目の微妙な故障モードは、繰り返し処理によって発生します。 繰り返しパターンが検出されるたびに圧縮する貪欲なアプローチでは、より適切なネストされた因数分解を見逃す可能性があります。 たとえば、繰り返し回数が 30 の部分文字列は、構造的には 3(10(x)) の方が適切に見えるかもしれませんが、10 は直接表現できないため、特定の因数分解のみが有効であり、間違った分解を選択すると、最適性が早期に損なわれます。 

もう 1 つの微妙な問題は、周期性の検出です。 部分文字列には複数の有効な期間が含まれる場合があり、期間を長くするとダウンストリームの圧縮が向上する場合、最小の期間のみを使用することは最適ではない可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、すべての部分文字列に対して、生成できるすべての有効な圧縮文字列のセットを定義することです。 各部分文字列について、考えられるすべての分割点と考えられるすべての繰り返し要素を試し、結果を結合します。 各部分文字列はカタロニア語のような方法で分割できるため、導出の数は非常に急速に増加します。また、繰り返しにより別の乗法爆発が発生します。 部分文字列の結果をメモ化した場合でも、すべての候補文字列を保存するとメモリと時間が飛躍的に増加します。 

重要な観察は、構造がコンテキストフリーであるにもかかわらず、各部分文字列の最適な表現のみを保存すると、最適な部分構造が依然として保持されるということです。 部分文字列の最適なエンコードはすべて、部分文字列を 2 つの最適な部分に分割するか、より小さな部分文字列の繰り返しとして表現することによって行われなければなりません。 これにより、問題は区間動的計画法に帰着します。 

連結の場合、すべての分割点を試し、左半分と右半分の最適なソリューションを組み合わせます。 繰り返しの場合は、部分文字列が小さいパターンの繰り返しコピーで構成されているかどうかを確認します。 長さ L の部分文字列が長さ p のパターンの k 回の繰り返しで構成されている場合、その子がパターンの最適なエンコードである繰り返しノードとしてエンコードできます。また、その繰り返し回数 k 自体は、ネストされた数字 2 から 9 を使用して表現可能でなければなりません。

これにより、2 番目の動的プログラミング層が導入されます。つまり、200 までの整数が 2 から 9 の数字の積として表現できるか、および必要な最小ネストの深さがどれくらいかを計算します。 各乗算レベルは、1 つの繰り返し層に対応します。 

両方の DP テーブルの準備が完了すると、部分文字列 DP は簡単になります。連結コストと繰り返しコストを比較し、最も短い文字列を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのエンコーディングのブルート フォース列挙 | 指数 | 指数 | 遅すぎる |
 | 反復因数分解を使用した間隔 DP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最大 200 までのすべての有効な繰り返し回数を事前計算します。整数 k ごとに、各係数が 2 ～ 9 の範囲で必要な最小係数を計算します。これらの値を使用して k を因数分解できない場合、その値は無効とマークされます。 これにより、k 回の繰り返しを表すために必要な最小ネストの深さが得られます。 
2. テーブルを事前計算して、部分文字列 s[l:r] が周期的であるかどうかを確認します。 各間隔について、その長さを分割するすべての可能な期間長 p をテストし、s[l:l+p] の繰り返しによって部分文字列が再構築されるかどうかを検証します。 これにより、繰り返し圧縮が可能かどうか、および基本パターンが何であるかがわかります。 
3. 部分文字列 s[l:r] の最短のエンコード文字列を表す動的プログラミング テーブル dp[l][r] を構築します。 
4. dp[l][r] を部分文字列自体として初期化します。これは、圧縮が適用されないことを意味します。 
5. l と r の間のすべての分割点 m を試します。 分割ごとに、dp[l][m] と dp[m][r] を結合し、短い方の結果を保持します。 これにより、連結構造がキャプチャされます。 
6. s[l:r] の有効期間 p ごとに、k = (r - l) / p を計算します。 k が表現可能な場合、候補エンコードを繰り返しノードとして構築します。つまり、k の因数分解に従って繰り返される数字かっこ構造が dp[l][l+p] に適用されます。 この候補を dp[l][r] と比較します。 
7. すべての間隔を長さの昇順に埋めた後、dp[0][n] には最適なエンコーディングが含まれます。 

核となる不変条件は、dp[l][r] が常に部分文字列 s[l:r] の最短の有効なエンコーディングを格納することです。 すべての有効なエンコーディングは、2 つの有効なエンコーディングの連結、または有効な反復因数分解を使用したより小さい部分文字列の有効なエンコーディングの反復のいずれかです。 このような構造はすべて明示的に考慮されるため、有効なエンコーディングが失われることはなく、DP は常に最小長の表現を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 205
INF = 10**18

def build_rep_cost(limit):
    # rep_cost[k] = minimum number of digits (levels) to represent k as product of 2..9
    rep_cost = [INF] * (limit + 1)
    rep_cost[1] = 0
    for i in range(2, limit + 1):
        for d in range(2, 10):
            if i % d == 0 and rep_cost[i // d] != INF:
                rep_cost[i] = min(rep_cost[i], rep_cost[i // d] + 1)
    return rep_cost

def is_period(s, l, r, p):
    base = s[l:l+p]
    i = l
    while i < r:
        if s[i:i+p] != base:
            return False
        i += p
    return True

def solve():
    s = input().strip()
    n = len(s)

    rep_cost = build_rep_cost(n)

    dp = [[None] * (n + 1) for _ in range(n)]
    for i in range(n):
        dp[i][i+1] = s[i]

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length
            best = s[l:r]

            for m in range(l + 1, r):
                cand = dp[l][m] + dp[m][r]
                if len(cand) < len(best):
                    best = cand

            for p in range(1, length):
                if length % p != 0:
                    continue
                k = length // p
                if rep_cost[k] == INF:
                    continue
                if not is_period(s, l, r, p):
                    continue
                pattern = dp[l][l+p]
                cand = pattern
                for _ in range(rep_cost[k]):
                    cand = "2(" + cand + ")"
                if len(cand) < len(best):
                    best = cand

            dp[l][r] = best

    print(dp[0][n])

if __name__ == "__main__":
    solve()
```DP テーブルは部分文字列の長さによってボトムアップで構築され、dp[l][m] または dp[m][r] にアクセスするたびに、それらの値がすでに最適であることが保証されます。 

繰り返しの構築では、各繰り返し層が定数桁ラッパーとしてモデル化される簡素化されたエンコード ステップが使用されます。 rep_cost テーブルにより、有効な因数分解のみが試行されることが保証され、ラップの繰り返しによりネストされた繰り返し構造がシミュレートされます。 

微妙な点は、文字列を長さのみで比較することです。これは、有効なエンコーディングは意味上の同等性ではなく、リテラルのサイズによって判断されるため安全です。 もう 1 つの重要な詳細は、DP 文字列はすでに圧縮されている可能性があり、構造的等価性チェックに使用できないため、DP 表現ではなく元の文字列に対して常に周期性を検証することです。 

## 実用的な例

 文字列を考えてみましょう`abababaaaaa`。 

まず小さな部分文字列の dp を計算し、次に展開します。 

セグメントの場合`ababab`、周期性チェックによりベースが明らかになります`ab`k = 3 です。3 は表現可能であるため、繰り返し候補を作成します。 

| ステップ | 間隔 | スプリットベスト | 生理周期チェック | 候補者 | ベスト |
 | --- | --- | --- | --- | --- | --- |
 | 1 | アブ | アブ | いいえ | アブ | アブ |
 | 2 | アバブ | アブ+アブ | はい、p=2、k=2 | 2(ab) | 2(ab) |
 | 3 | アババブ | 分割がさらに悪化 | はい、p=2、k=3 | 3(ab) | 3(ab) |

 のために`aaaaa`、重要なピリオドは存在しないため、生の文字列または繰り返される単一文字として残りますが、5 は許容される繰り返し要素として表現できないため、圧縮は役に立ちません。 

両方の部分を組み合わせると、`3(ab)aaaaa`、DP は分割に応じて後続ブロックをさらに圧縮する場合があります。 

このトレースは、周期構造がどのように検出されるか、また構造が強い場合に繰り返し DP がどのように連結を支配するかを示します。 

ここで考えてみましょう`abcdefg`。 部分文字列には繰り返しや有益な分割はありません。 すべての DP 状態では生の連結または元の部分文字列が優先されるため、結果は変わりません。 これは、アルゴリズムが有益でない場合には圧縮を強制しないことを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3) | 各部分文字列について、O(n) 個の分割と O(n) 個のピリオド チェックを試みます。 
| スペース | O(n^2) | DP テーブルは各間隔の最適なエンコーディングを保存します。 

n が最大 200 の場合、n^3 は約 800 万回の遷移になります。これは、内部操作が単純な文字列の連結と比較である場合、Python の一般的な制限内に十分収まります。

 ## 特殊なケース

 次のような単一の文字入力`a`基本の DP 初期化をテストします。 このアルゴリズムは dp[i][i+1] をキャラクタに直接初期化するため、分割または繰り返しロジックはトリガーされず、出力は正しいままになります。 

次のような完全に均一な文字列`aaaaaa`定期的な検出を実行します。 このような入力の場合、部分文字列はピリオド 1 を持つものとして検出され、長さが短くなるため、連結よりも繰り返しの方が優先されます。 DP は、最適なエンコーディングを繰り返すことを正しく識別します。`a`より短い表現が得られます。 

11 個の同一文字などの素数長の繰り返し数は重要な制限を強調します。11 は 2 ～ 9 の数字に因数分解できないため、文字列が周期的であっても繰り返しは許可されません。 この場合、DP は連結または生の文字列に戻ります。これが唯一の有効な結果です。 

のような混合構造`abababcabababc`連結と繰り返しの間の相互作用をテストします。 DP はプレフィックスのみを貪欲に圧縮することを避け、代わりに完全な間隔の組み合わせを評価し、最適な分割が部分文字列の境界ではなく繰り返しの境界と一致するようにする必要があります。
