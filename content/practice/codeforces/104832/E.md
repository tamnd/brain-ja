 ## 解決策
 ## 問題の理解

 直線に沿って配置されたラベル付きの茶屋のセットが与えられます。 正確な順序は不明なので、これらの茶屋の左から右への完全な並べ替えが、歴史的観察のリストと一致する数を数えたいと考えています。 

それぞれの観察には 3 つの異なる茶屋が含まれます$a, b, c$と断言します。$b$の間のどこかにありました$a$そして$c$道路沿いにあります。 「間」は幾何学的です。最終的な順序を見ると、$b$厳密に次の位置の間になければなりません$a$そして$c$。 の相対的な順序$a$そして$c$は固定ではないのでどちらのパターンも$a < b < c$そして$c < b < a$は許可されますが、次のような構成は$b$両方の同じ側にあることは禁止されています。 

タスクは、次の順列が何回あるかを数えることです。$1 \ldots n$このようなすべての制約をモジュロで同時に満たす$998244353$。 

制約$n \le 24$is the central signal. 階乗探索空間はすでに大きすぎますが、$24$サブセットに対するビットマスク動的プログラミングを強く提案します。 ただし、3 項制約の存在は、単純な半順序を扱っていないことを意味します。 各制約は、ペアごとの比較だけでなく、3 つの要素の相対的な配置に依存します。 That is the main difficulty.

 素朴な解釈では、すべての制約に対して各順列をチェックしようとしますが、順列の生成さえも困難です。$24!$, which is infeasible. どのソリューションでも、順列の構築中に妥当性を段階的に検証できるように、制約チェックを圧縮する必要があります。 

微妙なエッジ ケースは、単純な順序付けの意味で制約が推移的または一貫性を持たないことです。 たとえば、次のような制約がある場合、$(1,2,3)$そして$(2,3,1)$、局所的には合理的に見えるかもしれませんが、全体的には完全な配置を考慮した場合にのみ現れる矛盾を強制します。 もう 1 つの問題は、制約に隣接性は必要なく、相対的な順序のみが必要なため、連続した構造を前提とするメソッドはすぐに失敗することです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての順列を列挙し、すべてのトリプル制約が満たされているかどうかを確認します。 それぞれの順列について、$a, b, c$かどうかを確認します$b$他の 2 つの間にあります。 1 つの順列コストを確認する$O(m)$したがって、全体の複雑さは次のようになります。$O(n! \cdot m)$、これは実現可能性をはるかに超えています。$n = 24$。 

重要な構造上の観察は、制約は距離や隣接性ではなく、相対的な順序についてのみ説明するということです。 これは、左から右への順列を構築し、新しい要素を配置するたびに、その要素に関係するすべての制約が、すでに配置されている要素のみを使用して検証できることを保証することを示唆しています。 

これにより、ビットマスク上のサブセット DP が生成され、マスクがすでに配置されている要素のセットとして解釈されます。 移行では、現在のプレフィックスの末尾に新しい要素を 1 つ追加します。 

難しいのは、それぞれの制約が$(a, b, c)$となった瞬間の条件となる$b$配置されます: その瞬間、ちょうど次のうちの 1 つが配置されます。$a$そして$c$すでにプレフィックスに含まれている必要があります。$b$最終的な順序付けではそれらの間にある必要があります。 これにより、すべての制約がサブセットのみに依存する条件に変換され、段階的にチェックできるようになります。 

残りの課題は、遷移ごとの制約を直接スキャンするのは遅すぎるため、すべてのサブセットにわたってこれらの条件を効率的にチェックすることです。 このソリューションは要素ごとに事前計算に依存します。$b$、すべての制約によって引き起こされる構造。$b$は中央の要素であり、事前計算されたビット演算を使用してその構造に対してサブセットのメンバーシップを検証します。

 ## アルゴリズムのチュートリアル

 頂点のサブセットにわたる DP を定義します。`dp[mask]`要素を正確に配置する有効な部分オーダーの数をカウントします。`mask`最終的な順列の接頭辞として。 

要素ごとに$b$、すべての制約を前処理します。$b$真ん中の要素です。 それぞれの制約$(a, b, c)$有効なプレフィックスに要件を課します$S$含まれている$b$： の間で$a$そして$c$、まさに人はそこに横たわなければなりません$S \setminus \{b\}$。 両方がインまたは両方がアウトの場合、その時点で制約に違反します。$b$が挿入されます。 

次に、マスクを反復処理し、新しい要素を追加して DP を構築します。$x$。 配置の有効性チェック$x$制約のみに依存します。$x$真ん中の要素です。 

### ステップ

 1. それぞれについて事前計算$b$、ペアのリスト$(a, c)$そのような$b$の間になければなりません$a$そして$c$。 これは入力制約を再グループ化したものにすぎません。 
2. 次のコマンドで DP を初期化します。`dp[0] = 1`、空のプレフィックスを表します。 
3. すべてのマスクを小さいものから大きいものまで繰り返します。 マスクごとに、新しい要素の追加を検討してください。$x$マスクの中ではありません。 
4. かどうかを確認するには$x$を追加できる場合は、それに関連するすべての制約を調べてください。$x$。 各ペアごとに$(a, c)$、次のいずれかが必要です。$a$そして$c$すでに入っています`mask`。 
5. このような制約がすべて満たされている場合は、更新します。`dp[mask | (1 << x)] += dp[mask]`。 
6. 最終的な答えは次のとおりです。`dp[(1 << n) - 1]`。 

### なぜ効果があるのか

 DP は、部分順列ごとに「プレフィックスの有効性」の一貫した解釈を強制します。 要素を配置するとき$b$、関連するすべての制約$b$その正しさは次のことによってのみ決まるため、完全にチェック可能になります。$a$そして$c$はすでに相対的に配置されています$b$の挿入の瞬間。 一度$b$が挿入された場合、今後の操作では、$b$間にあります$a$そして$c$, したがって、制約はそのステップで固定されます。 これにより、クリーンな不変条件が作成されます。すべての部分状態は、完全に有効な順列に拡張できる、配置された要素のセットを表します。また、すべての遷移は、新しく完了したすべての制約を、決定可能になったときに正確に強制することで、このプロパティを保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    
    between = [[] for _ in range(n)]
    
    for _ in range(m):
        a, b, c = map(int, input().split())
        a -= 1
        b -= 1
        c -= 1
        between[b].append((a, c))
    
    N = 1 << n
    dp = [0] * N
    dp[0] = 1
    
    for mask in range(N):
        if dp[mask] == 0:
            continue
        
        for x in range(n):
            if mask & (1 << x):
                continue
            
            ok = True
            
            for a, c in between[x]:
                in_a = (mask >> a) & 1
                in_c = (mask >> c) & 1
                if in_a == in_c:
                    ok = False
                    break
            
            if ok:
                dp[mask | (1 << x)] = (dp[mask | (1 << x)] + dp[mask]) % MOD
    
    print(dp[N - 1])

if __name__ == "__main__":
    solve()
```コードは DP を直接ミラーリングします。 配列`between[b]`すべての制約を保存します。$b$他の 2 つの要素の間になければなりません。 移行中は、次の場合に関連する制約のみを検証します。$b$が挿入されます。 

重要な実装の詳細は、制約チェックで現在のマスクのビット テストのみが使用されるため、位置の再計算や明示的な順序の維持が回避されることです。 DP 状態は、どの要素がすでに配置されているかなど、必要な情報を正確にエンコードします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot 2^n + m \cdot 2^n)$| 遷移中の制約チェックによるサブセット上の DP |
 | スペース |$O(2^n + m)$| DP テーブルとグループ化された制約 |

 と$n \le 24$、DP サイズは約$16$百万の州。 制約の数は約$2000$そのため、最適化された C++ と慎重なビット操作の下では、構造は管理可能なままになります。 この定式化により、各制約が関連する場合にのみチェックされるようになり、フル スキャンの繰り返しが回避されます。 

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n, m = map(int, input().split())
    between = [[] for _ in range(n)]
    
    for _ in range(m):
        a, b, c = map(int, input().split())
        a -= 1; b -= 1; c -= 1
        between[b].append((a, c))
    
    N = 1 << n
    dp = [0] * N
    dp[0] = 1
    
    for mask in range(N):
        if dp[mask] == 0:
            continue
        for x in range(n):
            if mask & (1 << x):
                continue
            ok = True
            for a, c in between[x]:
                if ((mask >> a) & 1) == ((mask >> c) & 1):
                    ok = False
                    break
            if ok:
                dp[mask | (1 << x)] = (dp[mask | (1 << x)] + dp[mask]) % MOD
    
    return str(dp[N - 1])

 ## 特殊なケース

 重要なエッジケースは、制約が部分的な構築後にのみ現れる矛盾を形成する場合です。 たとえば、2 つの制約が異なる中間を介して同じエンドポイント間に互換性のないパリティを強制する場合、DP はすべての完了を拒否します。これは、2 番目のエンドポイントが制約を完全に監視可能にするプレフィックスに挿入されたときに違反が正確に検出されるためです。 

もう 1 つのエッジ ケースは、制約が存在しない場合です。 この場合、すべてのサブセット遷移が有効であり、DP はすべての順列を効果的にカウントし、次の結果を生成します。$n!$。 実装ではこれを自然に処理します。`between[x]`すべての人にとって空です$x$したがって、すべての遷移は制限なく通過します。 

最後の微妙なケースは、要素が多くの制約の中間として現れるときに発生します。 その場合でも、各制約は挿入時に独立してチェックされ、決定は現在のマスクのビット メンバーシップのみに依存するため、DP 状態内で順序の曖昧さは発生しません。
