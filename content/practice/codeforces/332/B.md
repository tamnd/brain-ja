 ## 解決策
 ## 問題の理解

 線上に配置された数字のリストが与えられます。各位置は法則を表し、その値はそれがどれほど「有用」または「価値がある」かを表します。 固定長の連続する 2 つのブロックを正確に選択する必要があります`k`。 これら 2 つのブロックは重複できません。両方のブロック内のすべての値の合計ができるだけ大きくなるようにします。 

これを確認する別の方法は、次のサイズのウィンドウをスライドさせているということです。`k`配列全体にわたって、すべての有効な開始位置でその合計を計算します。 これらのウィンドウの合計から、インデックスが重ならず、合計が最大になるように 2 つのウィンドウを選択する必要があります。 出力は値ではなく、これら 2 つのウィンドウの開始インデックスであり、小さい開始インデックスが優先されるタイブレーク ルールが適用されます。 

制約は大きく、最大 200,000 個の要素があります。 すべてのウィンドウのペアを試すソリューションでは、大まかにチェックする必要があります。$O(n^2)$組み合わせでは遅すぎます。 平$O(nk)$ウィンドウ合計を繰り返し再計算するソリューションも、最悪の場合には失敗します。 これにより、通常は線形または線形に近い解決策が求められます。$O(n)$または$O(n \log n)$。 

いくつかの特殊なケースは見落とされがちです。 すべての値が同一の場合、有効なセグメントの任意のペアが最適ですが、タイブレーク ルールにより、可能な限り早い最初のセグメントを選択し、次に最も早い互換性のある 2 番目のセグメントを選択することが強制されます。 もう 1 つの微妙なケースは、最適な 2 つのセグメントが隣接している場合とわずかに離れている場合に発生します。 単純に貪欲な選択をすると、ローカルで最適な 2 番目のセグメントが選択され、グローバルに優れたペアリングがブロックされる可能性があります。 

たとえば、次のことを考えてみましょう。```
n = 5, k = 2
values = [5, 1, 5, 1, 5]
```最良の選択は 1 と 3 (または 3 と 5) で始まるセグメントですが、最初に最適な単一セグメントを貪欲に選択すると、最適なペアがブロックされる可能性があります。 

重要な問題は、最適な 2 番目のセグメントが最初のセグメントの終了場所に依存することです。そのため、最適なプレフィックスの選択とサフィックス スキャンを効率的に組み合わせることができる構造が必要です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。長さのすべての部分配列の合計を計算します。`k`、それらを保存してから、重複しない部分配列のすべてのペアを試します。 くらいあれば`n`考えられる部分配列の場合、すべてのペアをチェックするのは$O(n^2)$、各チェックは$O(1)$したがって、全体の複雑さは次のようになります。$O(n^2)$、これは 200,000 には大きすぎます。 

サイズの各ウィンドウの合計がわかったら、これを観察することでこれを改善できます。`k`、問題は 2 つのインデックスの選択に帰着します。`i < j - k + 1`最大化する`sum[i] + sum[j]`。 すべてのペアを試す代わりに、すべての位置に対して可能な限り最良の最初のセグメントを事前計算できます。`j`2 番目のセグメントが始まる場所。 

ポジションごとに`j`、私たちは最高のものを知りたいです`i`その左側にあります。 これは当然、ウィンドウ合計に対してプレフィックスの最大値を維持することを示唆しています。 それからそれぞれについて`j`、それを最良の有効なものと組み合わせます`i`その前に答えを計算します。 

これにより、二次ペアリングの問題が、事前に計算されたウィンドウの合計とプレフィックスの最適な位置を使用した単一パスに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | プレフィックスの最適化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、配列をウィンドウ合計の配列に変換します。ここで、各インデックスは長さの部分配列の合計を表します。`k`。 

1. 任意のウィンドウ合計を一定時間で計算できるように、入力配列のプレフィックス合計を計算します。 これにより、合計を繰り返し再計算することがなくなり、全体的に線形を維持できるようになります。 
2. アレイを構築する`w`、 どこ`w[i]`で始まるセグメントの合計です。`i`(1 インデックス付き)。 各値は、その位置でセグメントを選択する「スコア」を表します。 
3. 配列を作成する`best_left`、 どこ`best_left[i]`から始まるすべてのウィンドウの中で最適なウィンドウのインデックスを格納します。`1`に`i`。 「最良」とは最大の金額を意味します。 等しい場合は、小さい方のインデックスを維持します。 このプレフィックス構造により、任意の 2 番目のセグメント位置に最適な最初のセグメントを即座に知ることができます。 
4. 2 番目のセグメントのすべての有効な開始位置を繰り返します。 で始まる 2 番目のセグメントの場合`i`、最初のセグメントは開始する前に終了する必要があるため、最後の有効な開始は次のとおりです。`i - k`。 
5. 有効なそれぞれについて`i`、合計値を次のように計算します。`w[i] + w[best_left[i - k]]`そして最大値を追跡します。 小さい最初のインデックスを優先し、次に小さい 2 番目のインデックスを優先してタイブレークを適用します。 
6. 保存された 2 つの開始位置を出力します。 

重要なアイデアは、2 番目のセグメントを修正するときに、プレフィックス最大値によって最適な最初のセグメントが定数時間内にすでにわかっているということです。 

なぜ効果があるのか​​: あらゆるポジションで`i`、`best_left[i]`すべての有効な候補の中から最適な最初のセグメントを保存します。 最適なペアはその最初のセグメントがその範囲内にある必要があり、それを固定の 2 番目のセグメントと組み合わせても、その内部の最適性に影響はありません。 これにより、グローバルな最適化の問題が、プレフィックスとサフィックスの分割に関する独立したローカルな決定に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

# prefix sums
pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

# window sums
w = [0] * (n - k + 1)
for i in range(n - k + 1):
    w[i] = pref[i + k] - pref[i]

# best position to the left
best_left = [0] * len(w)
best_left[0] = 0

for i in range(1, len(w)):
    if w[i] > w[best_left[i - 1]]:
        best_left[i] = i
    else:
        best_left[i] = best_left[i - 1]

best_i = 0
best_j = k
best_val = -1

for j in range(k, len(w)):
    i = best_left[j - k]
    val = w[i] + w[j]
    if val > best_val:
        best_val = val
        best_i = i
        best_j = j
    elif val == best_val and (i < best_i or (i == best_i and j < best_j)):
        best_i = i
        best_j = j

print(best_i + 1, best_j + 1)
```プレフィックス配列は標準であり、各ウィンドウの合計が一定時間で計算されるようにします。 配列`w`問題を 2 つのセグメントではなく 2 つの要素を選択するように圧縮します。 

の`best_left`配列は重要な構造です。これにより、考えられるすべての 2 番目のセグメントについて、スキャンせずに最も有効な最初のセグメントを即座に取得できるようになります。 

タイブレークは、合計の一致後にインデックスを比較することによって、最終ループで明示的に処理されます。 

## 実用的な例

 ### 例 1

 入力:```
5 2
3 6 1 1 6
```ウィンドウの合計:

 | 私 | ウィンドウ | 合計 |
 | --- | --- | --- |
 | 0 | [3,6] | 9 |
 | 1 | [6,1] | 7 |
 | 2 | [1,1] | 2 |
 | 3 | [1,6] | 7 |

 今すぐビルドしてください`best_left`:

 | 私 | w[i] | ベスト左[i] |
 | --- | --- | --- |
 | 0 | 9 | 0 |
 | 1 | 7 | 0 |
 | 2 | 2 | 0 |
 | 3 | 7 | 0 |

 2 番目のセグメントごとに次のようにします。 

- j = 2: [0..0] の最良の i → i=0、合計 = 9 + 2 = 11
 - j = 3: [0..1] の最良の i → i=0、合計 = 9 + 7 = 16

 最適なペアは、0 から始まるインデックス形式の (0, 3) → (1, 4) です。 

これは、プレフィックス選択により、後の位置を評価するときに、グローバルに最適な最初のセグメントを決して見逃さないようにする方法を示しています。 

### 例 2

 入力:```
6 2
1 2 3 1 2 3
```ウィンドウの合計:```
[3, 5, 4, 3, 5]
```比較します:

 - 最適なペアは、ウィンドウ 1 と 4 (0 からインデックス付けされた 1 と 4) で発生し、5 + 5 = 10 となります。 

| j | 最高です | ペアの合計 |
 | --- | --- | --- |
 | 2 | 0 | 8 |
 | 3 | 1 | 8 |
 | 4 | 1 | 10 |

 これは、前のセグメントが有望に見える場合でも、アルゴリズムがどのようにしてより適切な 2 番目のセグメントを待つかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    w = [0] * (n - k + 1)
    for i in range(n - k + 1):
        w[i] = pref[i + k] - pref[i]

    best_left = [0] * len(w)
    for i in range(1, len(w)):
        if w[i] > w[best_left[i - 1]]:
            best_left[i] = i
        else:
            best_left[i] = best_left[i - 1]

    best_i = best_j = 0
    best_val = -1

    for j in range(k, len(w)):
        i = best_left[j - k]
        val = w[i] + w[j]
        if val > best_val or (val == best_val and (i < best_i or (i == best_i and j < best_j))):
            best_val = val
            best_i, best_j = i, j

    return f"{best_i + 1} {best_j + 1}"

# provided sample
assert run("5 2\n3 6 1 1 6\n") == "1 4"

# minimum case
assert run("2 1\n5 6\n") == "1 2"

# all equal
assert run("6 2\n1 1 1 1 1 1\n") == "1 3"

# clear separated peaks
assert run("6 2\n1 100 1 1 100 1\n") == "1 4"

# adjacent best vs later best
assert run("7 2\n5 1 5 1 5 1 5\n") == "1 3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`5 2 ...`|`1 4`| サンプルの正確性 |
 |`2 1 ...`|`1 2`| 最小サイズの動作 |
 | すべて等しい |`1 3`| タイブレークの安定性 |
 | 二つのピーク |`1 4`| 重複しない最適なペアリング |
 | 交互のピーク |`1 3`| 貪欲ではなく正しいグローバル ペアリング |

 ## 特殊なケース

 すべての値が同一の場合、すべてのウィンドウのスコアは同じになります。 プレフィックス最大配列は常に最も古いインデックスを保持するため、最初のセグメントはできるだけ早く固定され、2 番目のセグメントはその後の最も古い有効な位置になります。 これはタイブレーク要件に正確に一致します。 

最適な 2 つのウィンドウが隣接している場合でも、わずかに離れている場合でも、隣接関係は優先順位ではなくインデックスの分離によってのみ強制されるため、アルゴリズムは依然として正しく動作します。 たとえ後のウィンドウがローカルに最適であっても、構築時にグローバルに最適な以前のプレフィックスを置き換えることはありません。`best_left`。 

次のような小さな入力の場合`n = 2k`の場合、有効なセグメントのペアが 1 つだけ存在し、アルゴリズムは曖昧さなくそのペアを正確に選択します。
