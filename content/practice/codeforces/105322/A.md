 ## 解決策
 ## 問題の理解

 私たちは、エリックという 1 人の参加者を追跡しています。彼は、次のような固定位置から開始します。$n$人々をランク順に並べたもの。 各ラウンドでは、参加者がバラバラの試合に参加します。 各試合では、2 人のプレイヤーのうちの 1 人がコイン投げで勝ちますが、順位を交換することで実際に順位を向上させることができるのは、もともと対戦相手よりもランクが低かった勝者だけです。 上位プレイヤーが勝っても何も変わりません。 

エリックの順位は、自分より上のランクの相手と対戦し、その対戦に勝利した場合にのみ変更できます。その場合、その対戦相手と順位が入れ替わります。 それ以外の場合、彼のポジションはそのラウンドでは同じままです。 このプロセスを繰り返した後、$k$ラウンドでは、エリックのランクモジュロの期待値を求められます。$998244353$。 

制約は非常に大きく、両方とも$n$そして$k$まで可能です$10^{18}$。 これにより、ラウンドにわたるシミュレーションや、時間でインデックス付けされたステートにわたる DP が即座に除外されます。 位置によってインデックス付けされた状態を格納することさえ、一般的なマルコフ連鎖として単純に扱うと実行不可能です。 実行可能な解決策は、プロセスを閉じた形式の反復または非常に低次元の変換に削減する必要があります。 

微妙なエッジケースが現れるのは、$n=2$。 この場合、エリックはラウンドごとに 1 回のコイン投げに応じて、その場に留まるか、唯一の他のプレイヤーと入れ替わります。 による除算を前提としたソリューション$n-1$数式を一般化するときにモジュラー反転の問題を回避するには、このケースを慎重に処理する必要があります。 

もう 1 つの重要な構造的観察は、エリックのランクが時間の経過とともに単調に増加しないことです。 彼がより良いランク (より小さい数値) に移動すると、モデル内のいかなる操作によっても押し下げられることはありません。 これにより、双方向の動きによるマルコフ連鎖の多くの典型的な複雑さが解消されます。 

## アプローチ

 直接シミュレーションでは、各ラウンドを独立して処理します。 あるラウンドで、エリックはある対戦相手と一律に対戦します。$n-1$人々。 その対戦相手がエリックよりも上位にランクされている場合、確率で$1/2$エリックは上向きに交換します。 そうでなければ何も変わりません。 これにより、正しい確率過程の記述が得られます。 

ただし、一歩でも踏み越えるシミュレーションを行うと、$n$状態は実行不可能なので、これを繰り返す$k$ステップは完全に問題外です。 

重要な簡素化は、分布追跡を放棄し、代わりに期待値に直接焦点を当てることです。 このプロセスは確率論的ですが、エリックのランクの予想される変化は、完全な分布履歴ではなく、彼の現在のランクにのみ依存します。 

エリックが現在ランクにあると仮定します$i$。 対戦相手は一律に選ばれます$n-1$選手たち。 相手のランクが以上の場合$i$、コインに関係なく何も起こりません。 相手のランクが以下の場合$i$、その後、確率で$1/2$, エリックはその対戦相手と入れ替わり、そのランクにジャンプします。 

これにより、次の予想位置を純粋に計算することができます。$i$、閉じた繰り返しが生成されます。$$E[i_{t+1}] = i - \frac{i(i-1)}{4(n-1)}.$$したがって、問題全体は、単一の値の二次変換を繰り返すことになります。$i$。 非常に大規模な環境下では、困難は確率から関数の反復に移行します。$k$。 

ブルートフォースアプローチでは、この繰り返しが適用されます。$k$時間、原価計算$O(k)$、次の場合は不可能です$k \le 10^{18}$。 

さらに加速するために、これが有限体の単一スカラーでの決定論的な反復であることを観察します。 このようなシステムは通常、更新を合成をサポートする形式に変換するか、反復を線形化する不変変換を見つけることによって処理されます。 この場合、漸化式は有理 2 次マップであり、変換の 2 次元リフト表現での関数合成による高速累乗が可能になります。 

これにより、次の問題が軽減されます。$k$順次評価$O(\log k)$繰り返しの作曲ステップ。

 ## アルゴリズムのチュートリアル

 1. エリックの初期ランクからスタート$x$。 再発は完全な分布で​​はなく現在の期待値のみに依存するため、これが追跡する唯一の状態です。 
2. 現在のランクから予想される次のランクを導出する$i$。 対戦相手は一律に選ばれるため、それぞれの$n-1$考えられる対戦相手には確率がある$1/(n-1)$。 
3. 対戦相手のランクに基づいてケースを分割します。 相手のランクが下位の場合$i$、状態は変わりません。 対戦相手の方がランクが高い場合、確率的には$1/2$, エリックはスワップしてその相手の位置に直接移動します。 
4. よりランクの高いすべての対戦相手の期待される貢献度を計算します。 一様にランダムでランクの高い対戦相手を選択した場合の平均向上は、対戦相手との平均距離に比例します。$i$、次のように評価されます$i/2$。 確率を組み合わせると、予想される減少が得られます。$$\frac{i(i-1)}{4(n-1)}.$$5. これにより、決定論的な反復が得られます。$$f(i) = i - \frac{i(i-1)}{4(n-1)}.$$6. この変換を適用します$k$関数合成で高速累乗を使用して倍数を計算します。 各構成ステップでは、適用されるラウンド数が 2 倍になります。 
7. 結果の値を剰余として返します。$998244353$。 

### なぜ効果があるのか

 このプロセスは対戦相手を超えて交換可能であり、期待値が線形であるため、期待される次の状態は現在の期待ランクにのみ依存します。 これにより、確率システムは単一変数の決定論的反復に崩壊します。 各ステップが 1 つの完全なラウンドの予想される遷移を正確に表し、遷移の構成は複数のラウンドを連続して実行することに正確に対応するため、関数の合成では正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def compose(a1, b1, a2, b2):
    # (a2 x^2 + b2 x) plugged into (a1 x^2 + b1 x)
    # returns coefficients of resulting quadratic in x
    A = a1
    B = b1
    C = a2
    D = b2

    # f(g(x)) = A*(Cx^2 + Dx)^2 + B*(Cx^2 + Dx)
    # expand carefully
    return (
        A * C * C % MOD,
        (2 * A * C * D + B * C) % MOD,
        (A * D * D + B * D) % MOD
    )

def solve():
    n, x, k = map(int, input().split())
    n %= MOD
    x %= MOD

    if n == 1:
        print(x)
        return

    inv = modinv(4 * (n - 1) % MOD)

    # f(i) = i - i(i-1)/(4(n-1))
    #     = (-inv) * i^2 + (1 + inv) * i
    a = (-inv) % MOD
    b = (1 + inv) % MOD

    # identity function: x
    ra, rb = 0, 1

    e = k
    while e:
        if e & 1:
            ra, rb = compose(ra, rb, a, b)
        a, b = compose(a, b, a, b)
        e >>= 1

    # apply resulting function to x
    ans = (ra * x % MOD * x + rb * x) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、予想される遷移を次の 2 次多項式に変換します。$i$。 次に、関数合成に対してバイナリ リフティングを実行し、各関数を 2 乗または乗算できる変換として扱います。$O(1)$。 最後のステップでは、合成された関数を初期ランクで評価します。 

主要な実装の詳細は、漸化式を 2 次多項式として表現し、それをモジュラー演算の下で慎重に構成することです。 2 進累乗構造により、次のことのみが実行されます。$O(\log k)$組成物。

 ## 特殊なケース

 いつ$n=1$、一致は発生せず、エリックのランクは固定されたままになります。 それ以外の場合、再帰では次のような除算が試行されます。$n-1=0$, したがって、このケースは直接処理する必要があります。

いつ$k=0$、合成は適用されず、出力は単に初期ランクになります。$x$。 これは合成フレームワークの恒等関数に対応し、二進累乗中に中立要素として保存する必要があります。
