 ## 解決策
 ## 問題の理解

 各セルがフリーまたはブロックされている長方形のグリッドが与えられます。 タスクは、自由なセルにできるだけ多くのテトロミノを配置することです。 各テトロミノは正確に 4 つの単位セルを占め、回転することができ、障害物や他のテトロミノと重なったりすることなく、グリッド内に完全に収まる必要があります。 

グリッド サイズは最大 100 x 100 であるため、セルの総数は最大 10,000 です。 これは、配置のすべてのサブセットを列挙しようとするアプローチが不可能であることをすでに示唆しています。配置の数が適度な数であっても、指数関数的な爆発につながるからです。 

構造上の重要な問題は、テトロミノの配置が単一のエッジまたはセルのペアに局所的ではないことです。 各配置は同時に 4 つのセルを消費するため、これはそのままの形式でのマッチングの問題ではなく、パッキングの問題になります。 

典型的な単純な試みは、考えられるすべての配置を試し、すでに選択されている配置と競合しない場合は貪欲にそれを採用することです。 これは、初期の貪欲な選択が、たとえ異なる初期の選択によってより大きな解決策が可能であっても、後の多くの配置をブロックする可能性があるため、すぐに失敗します。 たとえば、4 × 4 の小さな空のグリッドでは、中央に 1 つの T 字型のテトロミノを配置すると、一緒にするとより高いカウントが得られる 2 つの L 字型の配置がブロックされる可能性があります。 ローカルな決定は世界的な影響を与えるため、貪欲な選択は信頼できません。 

グリッドに狭い廊下が交互にある場合、別の失敗例が発生します。 貪欲な戦略では、最初に到達可能な廊下を完全に埋めて、埋めることができない断片的なスペースを他の場所に残す傾向がありますが、別の配置では、より多くのグリッドをタイル化することができます。 

したがって、正しいソリューションでは、段階的な実現可能性ではなく、配置のグローバルな一貫性を考慮する必要があります。 

## アプローチ

 強引な定式化では、すべての有効なテトロミノ配置を生成し、次に 2 つが重ならないように配置の最大のサブセットを選択します。 P 個の配置がある場合、これは、各ノードが配置でエッジが重複する配置を接続する競合グラフ上の最大独立集合問題になります。 最悪の場合、P は 10,000 に比例し、各配置が他の多くの配置と重なり、グラフが密になります。 このグラフに対してサブセットを検索したり、一般的な指数最適化を実行しようとするアプローチは、非常に遅すぎます。 

重要な観察点は、問題は 4 セルの形状に関して定義されているにもかかわらず、すべての有効な配置は共有セルを介してのみ相互作用するということです。 これは、実際の制約は「配置と配置の競合」ではなく、「各セルは最大 1 回使用できる」ことを意味します。 これにより、配置をめぐる競合グラフから、グリッド セルをめぐる容量制約へと構造が移行します。 

このように再定式化すると、問題はアイテム (配置) の選択となり、それぞれがリソース (セル) を消費し、各リソースの容量は 1 になります。 これは、ユニット容量を備えた古典的な正確なカバー スタイルの配合です。 

このような構造を解決する標準的な方法は、セルが最大 1 回使用されるように強制し、その 4 つのセルすべてを同時に予約できる場合にのみ配置を選択できるようにするフロー ネットワークを構築することです。 この構造では、配置ごとに選択変数が導入され、必要な 4 つのセルを介してフローがルーティングされ、セルの容量制約による一貫性が強制されます。 

これにより、問題は、配置とセルの両方がノードであり、エッジの数が有効な配置の発生数に比例する疎グラフ上の最大フローまたは最小コスト フローに変換されます。 各テトロミノは正確に 4 つのセルをカバーするため、結果として得られるネットワークは O(P) エッジ付近で管理可能なままになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | プレースメントのサブセットを列挙する | 指数 | 高 | 遅すぎる |
 | 配置競合グラフの検索 | 指数 | O(P^2) | 遅すぎる |
 | フローベースの正確なカバー配合 | O(E √V) または同様の最大フロー境界 | お(え) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのグリッド位置と許可された形状のすべての回転を試して、有効なテトロミノの配置をすべて列挙します。 各配置は 4 つのセルのリストとして保存されます。 図形の数は一定で、グリッドは 100 x 100 のみであるため、このステップは実行可能です。 
2. グリッド内の各セルが容量 1 のノードとなるフロー ネットワークを構築し、最大 1 つの選択されたテトロミノに所属できるようにします。 これは、配置間の明示的な重複チェックに代わるコア制約です。 
3. 配置ごとに、「このテトロミノの選択」を表す選択ノードを導入します。 このノードは、その 4 つの構成セルにフローを送信する責任を負います。 
4. グローバル ソースを容量 1 の各配置ノードに接続します。 これにより、各配置はまったく使用されないか、選択の 1 単位にのみ寄与することになります。 
5. 各配置ノードから、それぞれの容量が 1 である 4 つのセルにエッジを接続します。 配置の有効な選択は、必要な 4 つのセルすべてを介してフローを正常にルーティングすることに対応します。 
6. 各セル ノードを容量 1 のシンクに接続します。 これにより、選択した複数の配置でセルを使用できなくなります。 
7. ソースからシンクまで最大のフローを実行します。 結果として得られるフロー値は、完全に満たされた配置の数に対応します。これは、4 つのセルすべてにフローを正常に押し込む配置のみが有意義に寄与するためです。 

### なぜ効果があるのか

 不変条件は、配置ノードから出るフローのユニットは 4 つの異なるセル容量を占有することができなければならず、それらの各容量はグローバルに最大 1 回しか使用できないということです。 これにより、実行可能なフローがセル内で重複しない一連の配置に対応するように強制されます。 

逆に、k テトロミノの有効なタイリングは、ソースから 1 つのユニットを選択した各配置に送信し、その 4 つのセルに分配することによって、値 k のフローに変換できます。 構築によりすべての制約が満たされるため、フローは実行可能です。 これにより、有効な解と積分フローの間に 1 対 1 の対応関係が確立されるため、フローを最大化すると最適な数のテトロミノが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]
    
    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])
    
    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0
        while q:
            u = q.popleft()
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] < 0:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] >= 0
    
    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                pushed = self.dfs(v, t, min(f, c))
                if pushed:
                    self.adj[u][i][1] -= pushed
                    self.adj[v][rev][1] += pushed
                    return pushed
        return 0
    
    def max_flow(self, s, t):
        flow = 0
        INF = 10**9
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF)
                if not pushed:
                    break
                flow += pushed
        return flow

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # node mapping:
    # placements + cells + source + sink
    cells = [[-1] * m for _ in range(n)]
    cid = 0
    for i in range(n):
        for j in range(m):
            if grid[i][j] == '0':
                cells[i][j] = cid
                cid += 1

    S = cid
    T = cid + 1
    dinic = Dinic(cid + 2)

    # cell capacity edges
    for i in range(n):
        for j in range(m):
            if cells[i][j] != -1:
                dinic.add_edge(cells[i][j], T, 1)

    # tetromino shapes (abstract canonical set)
    # represented as lists of 4 relative coordinates
    shapes = [
        [(0,0),(1,0),(2,0),(3,0)],
        [(0,0),(0,1),(0,2),(0,3)],
        [(0,0),(1,0),(0,1),(0,2)],
        [(0,0),(0,1),(1,1),(2,1)],
        [(0,0),(1,0),(1,1),(1,2)],
        [(0,1),(1,1),(2,1),(2,0)],
    ]

    def inside(x, y):
        return 0 <= x < n and 0 <= y < m

    # placements connect source to cells
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '0':
                continue
            for shape in shapes:
                pts = []
                ok = True
                for dx, dy in shape:
                    x, y = i + dx, j + dy
                    if not inside(x, y) or grid[x][y] != '0':
                        ok = False
                        break
                    pts.append((x, y))
                if not ok:
                    continue

                # create a placement node
                pid = dinic.n
                dinic.adj.append([])
                dinic.adj.append([])
                # expand graph size dynamically (simplified)
                while len(dinic.adj) < pid + 2:
                    dinic.adj.append([])

                dinic.add_edge(S, pid, 1)
                for x, y in pts:
                    dinic.add_edge(pid, cells[x][y], 1)

    print(dinic.max_flow(S, T))

if __name__ == "__main__":
    solve()
```この実装では、配置ノードがグローバル ソースと個々のグリッド セルの間の仲介者として機能する 2 部構成のフロー構造が構築されます。 各配置にはソースからの容量が 1 つあるため、選択できるのは 1 回だけです。 選択された各配置は、必要な 4 つのセルにフローを送信しようとします。各セルは、シンクに向かって飽和する前に最大 1 単位のフローを受け入れることができます。 

微妙な点は、配置ノードが動的に作成されるということです。運用ソリューションでは、隣接リストのサイズ変更のオーバーヘッドを避けるために、配置ノードに事前にインデックスを付ける必要があります。 正確さは順序付けには依存せず、容量制約を維持することにのみ依存します。 

## 実用的な例

 ### 例 1

 4 × 4 の空のグリッドを考えてみましょう。 最適な解決策の 1 つは、4 つのテトロミノを重ならないように配置することです。 

プレースメントがどのように選択されるかを追跡します。 

| ステップ | 選択された配置 | 消費された細胞 | 流量値 |
 | --- | --- | --- | --- |
 | 1 | 最初の有効な配置 | 4 個のセルに使用済みのマークが付いています。 1 |
 | 2 | 2 番目の重複しない配置 | 4 個の新しいセルを使用 | 2 |
 | 3 | 3位 | 4 個の新しいセルを使用 | 3 |
 | 4 | 4位 | 4 個の新しいセルを使用 | 4 |

 このトレースは、セルが 1 つの配置で消費されると、別の配置に参加できないため、フローが自然に非結合性を強制することを示しています。 

### 例 2

 障害物によって狭い廊下に配置が強制されるグリッドを考えてみましょう。 一部の配置は重なり合っていますが、共存できるのはサブセットのみです。 

| ステップ | 選択された配置 | 紛争解決 | 流量値 |
 | --- | --- | --- | --- |
 | 1 | コリドーに沿った配置 | ブロックが重複する代替案 | 1 |
 | 2 | 代替ブランチ配置 | 異なるコリドー セグメントを使用します | 2 |

 これは、アルゴリズムが空間順序で貪欲にコミットしないことを示しています。 グローバル容量制約により一貫したセットが許可される場合にのみコミットされます。

 ## 特殊なケース

 完全にブロックされたグリッドは、列挙中に実行可能性チェックに合格する配置がないため、簡単に処理されます。そのため、ソースから配置ノードにエッジは追加されず、フローはゼロのままです。 

4 つの接続されたフリー セルなしではテトロミノを形成できないため、孤立した単一セルを含むグリッドも自然に処理されます。そのため、これらのセルは配置リストに表示されず、未使用のままになります。 

高度に制約されたコリドーは、容量 1 のセル エッジによって処理されます。 多くの配置が幾何学的に重なっている場合でも、フローはセル容量を考慮したサブセットのみをアクティブにすることができるため、過剰カウントが防止され、グローバルな一貫性が確保されます。
