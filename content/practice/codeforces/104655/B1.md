 ## 問題の理解

 文字列のコレクションが与えられ、各文字列は 5 つの異なるシンボルの固定セットの完全な順序を表します。 有効な順序付けはすべて、これら 5 つの記号の順列であるため、各文字列は各記号を 1 回だけ使用します。 

これら 5 つのシンボルの考えられるすべての並べ替えにおいて、ちょうど 1 つの順序が入力から欠落しています。 私たちの仕事は、指定されたリストにどの順列が含まれないかを判断することです。 

入力サイズは小さいです。5 つの異なる要素の順列の完全なセットのサイズが 120 であるため、存在する順列は最大 119 個です。これは、総検索空間が一定で小さいため、すべての順列を列挙したり、すべての可能性と比較したりする解法であっても、妥当な時間制限内で実行可能であることがすぐにわかります。 

素朴だが重要な観察は、各文字列の長さはわずか 5 であるため、すべての文字列のすべての文字を個別に処理するアプローチでは、合計で数百文字の操作が行われることになります。 これは、競技プログラミングの用語では事実上一定時間です。 

主なエッジケースは、計算上のものではなく概念的なものです。 すべてのシンボルは有効な順列ごとに 1 回だけ出現するため、位置ごとの頻度またはグローバル頻度に依存するメソッドはその構造を尊重する必要があります。 ソートされた入力を仮定したり、欠落している順列が 1 つの位置のみで異なると仮定した不注意なアプローチは失敗する可能性があります。 

たとえば、記号が A、B、C、D、E で、欠落しているとします。`ABCDE`。 誰かが位置ごとに最も一般的な文字を取得して再構築しようとすると、複数の置換が複数の位置で一致する可能性があるため、既存の置換をすでに形成している文字を誤って選択してしまう可能性があります。 正しい答えは、注意深く正当化されない限り、位置的に単独で決定されることはありません。 

## アプローチ

 この強引なアイデアは、5 つのシンボルの考えられるすべての順列を生成し、どれが入力セットに現れないかをチェックすることです。 ちょうど5つあるので！ = 120 の順列、この列挙は簡単です。 指定されたすべての文字列をセットに保存し、120 個の候補を反復処理して、存在しないものを返します。 

これが機能するのは、検索スペースが完全に制限されており、入力サイズに依存しないためです。 一般的な順列問題のボトルネックは階乗増加ですが、ここでは階乗は一定の小さな値に固定されています。 したがって、総当たりアプローチは、現実的な制約に関してすでに一定時間で動作します。 

もう少し直接的な推論アプローチでは、すべての文字列が同じアルファベットの順列であるという事実を利用します。 アルファベットを明示的に修正すると、各入力文字列を順列オブジェクトとして扱い、事前に計算されたすべての順列のリストと比較できます。 これにより、問題は集合メンバーシップのチェックに限定されます。 

これ以上に意味のある漸近的な改善は必要ありませんが、概念的な洞察として、問題の構造により検索や貪欲な再構築の必要性が排除されます。 私たちは順列を段階的に構築しているのではなく、完全な有限集合の中で欠落している要素を特定しているのです。

 ## アルゴリズムのチュートリアル

 問題の定義はすべての順列にわたって一貫したアルファベットを意味するため、5 つの記号が既知で固定されていると仮定します。 

1. すべての入力文字列を読み取り、O(1) 平均メンバーシップ チェック用のハッシュ セットに保存します。 これにより、候補の順列が入力に存在するかどうかを迅速にテストできます。 
2. 5 つのシンボルのすべての順列を辞書順または任意の固定順序で生成します。 このような順列はちょうど 120 個あります。 
3. 生成された順列ごとに、それを文字列に変換します。 
4. この文字列が入力セットに存在するかどうかを確認します。 
5. セット内で見つからない最初の順列は欠落しているものであるため、すぐに出力します。 

重要な設計上の選択は、部分的な情報から構造を再構築しようとするのではなく、入力を完全な有限宇宙にわたるメンバーシップの神託として扱うことです。 

### なぜ効果があるのか

 すべての有効な出力のセットは、指定されたアルファベットのすべての順列の完全な列挙を形成します。 入力には 1 つを除くすべての要素が含まれるため、完全な置換ユニバース内の入力セットの補数には 1 つの要素が含まれます。 ユニバースを明示的に列挙するため、メンバーシップをチェックすることで欠落している要素を一意に分離します。 

2 つの異なる順列を同じ文字列にマッピングすることはできず、有効な順列はすべて入力に存在するか存在しません。 これにより、直接除外検索の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    
    # All input strings are permutations of 5 characters
    arr = data
    sset = set(arr)
    
    # Determine alphabet from input (any string is fine)
    alphabet = sorted(arr[0])
    
    for p in permutations(alphabet):
        cand = ''.join(p)
        if cand not in sset:
            print(cand)
            return

if __name__ == "__main__":
    solve()
```このソリューションは、メンバーシップのチェックが平均して一定時間になるように、すべての順列をセットに読み取ります。 すべての文字列は同じ 5 つの記号の順列であるため、アルファベットは任意の入力文字列から抽出されます。 どの順序でも機能しますが、決定的な生成順序を確保するためだけに並べ替えています。 

次に、120 個の順列すべてを反復処理し、セットに欠けている順列を返します。 早期リターンにより、答えが見つかったらすぐに終了することが保証されます。 

実装の微妙な詳細は、入力全体を一度に読み取ることです。 行数が少ないため、繰り返しの I/O オーバーヘッドが回避され、コードが単純になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、欠落している順列が辞書編集上最初または最後にある場合です。 最初のケースでは、最初に生成された候補がすでにセットに存在しないため、アルゴリズムはすぐに終了します。 2 番目のケースでは、アルゴリズムは欠落している順列を見つける前に 120 個の順列すべてを実行しますが、依然として固定数のチェックのみを実行します。 

もう 1 つのエッジ ケースは、入力順序が完全にシャッフルされる場合です。 メンバーシップのセットに依存しているため、順序は正確さに影響しません。 アルゴリズムは常に、同じ候補のユニバースと比較します。 

最後の微妙なケースは、すべての入力文字列に同じアルファベットが含まれていると仮定する場合です。 これに違反すると、最初の文字列からアルファベットを抽出することは安全でなくなります。 問題の構造は均一性を保証しているため、単一の文字列からのアルファベットの再構築は有効であり、すべての入力にわたって安定しています。
