 ## 解決策
 ## 問題の理解

 私たちは、Web サイトにアクセスしたときに各写真が表示される可能性を制御する重みをもつ写真システムを使用しています。 いつでも、絵が見れる確率は$i$は、その重量をすべての画像の合計重量で割ったものです。 各訪問後、表示された写真の重みだけをすぐに変更します。気に入った場合はその重みを 1 つ増やし、そうでない場合は 1 つ減らします。 

このプロセスを繰り返します$m$独立した訪問。各訪問の分布は現在の重みに依存し、重み自体は以前の結果に基づいて変化します。 タスクは、すべての訪問後の各ピクチャの予想される最終的な重みを、実数としてではなく、大きな素数の下の剰余分数として計算することです。 

重要な問題は、分布が適応的であることです。 すべてのステップは将来のすべてのステップの確率を変えるため、独立したサンプリングではなく自己強化確率過程を扱っています。 

制約は小さく、$n \le 50$そして$m \le 50$。 これは、構造を注意深く活用した場合に限り、すべての画像を含む状態にわたる分布を同時に追跡できることを強く示唆しています。 状態空間はステップ数に応じて指数関数的に増大するため、すべてのランダム性分岐の単純なシミュレーションは不可能です。 

単純な期待の試みでは、訪問された画像のすべての可能なシーケンスの確率をシミュレートまたは再帰的に計算しようとします。 後$m$ステップがあります$n^m$シーケンスは、$m=50$。 

より微妙な失敗例は、相関関係を無視して、画像ごとに期待される重みだけを個別に追跡しようとした場合に発生します。 確率は重みの合計に依存し、それ自体が個々の重みと相関する確率変数であるため、このアプローチはすぐに破綻します。 たとえば、1 回の訪問後の増分は、どのインデックスが選択されたかによって異なり、それが将来のすべての確率に影響します。 

したがって、最大の障害は、期待が写真間で分離できないことです。 

## アプローチ

 ブルートフォースの観点は、システムの完全な状態を、各ステップ後の重みの正確なベクトルとその確率として定義することです。 各ステップは次のように分岐します。$n$可能性は各画像に 1 つあります。 状態から、確率質量を次のように分配します。$n$選択した画像に応じて新しい状態が表示されます。 これはプロセス定義に直接従うため、概念的に機能します。 

ただし、その後$m$ステップごとに状態の数は次のようになります$n^m$、各状態は$n$-次元ベクトル。 たとえ$n=2, m=50$、これは天文学的な規模になります。 

重要な観察は、重みベクトル全体にわたる完全な分散は必要ないということです。 必要なのは予想される最終的な重みだけです。 これは視点を逆転することを示唆しています。つまり、完全な状態を前方に追跡する代わりに、各ピクチャの重み変化への寄与に対して確率質量がどのように再配分されるかを追跡します。 

重要な再定式化は、プロセス中に各画像が選択されると予想される回数に焦点を当てることです。 期待される数がわかっている場合$E[c_i]$何回目の写真$i$が表示されたら、画像の予想される最終的な重みが表示されます。$i$単純に$$w_i + (\mathbf{1}_{a_i=1} - \mathbf{1}_{a_i=0}) \cdot E[c_i].$$したがって、問題全体は、自己修正確率プロセスを通じて予想される選択数を計算することに帰着します。 

ここで、時間ステップにわたる動的計画法と期待空間における暗黙的な重みの進化を導入します。 重要なコツは、重みはランダムですが、その期待される寄与は線形に変化し、分母の構造により、累積的な選択を表す DP 状態の期待される正規化された確率の観点から遷移を表現できることに注意することです。 

特定の数の選択後に構成に到達する確率を追跡する DP を定義しますが、各ピクチャが選択された回数のみを追跡することで状態を圧縮します。 以来$m \le 50$、状態をカウントのタプルとして表すことができます。$(c_1, \dots, c_n)$合計付き$\le m$ただし、すべてを明示的に列挙するわけではありません。$n^m$シーケンス; 代わりに、ステップ遷移を増分的に計算し、確率の計算方法で対称性を再利用します。 

各ステップで絵を選択する確率$i$現在の重みのみに依存します。$$w_i + \Delta_i(c_i)$$総重量で割ったもの$$W + \sum_j \Delta_j(c_j).$$各ステップでは 1 つの座標のみが変更されるため、$\pm 1$、カウント状態間の遷移はまばらで構造化されています。 

DP を層ごとに計算します。各層はステップに対応します。$t$、および状態は、その後に到達可能なカウントベクトルです。$t$更新情報。 各遷移は正確に 1 つの座標を更新し、それに応じて確率質量を蓄積します。 

最後に、期待されるカウントは DP 分布から導出されます。

 ## アルゴリズムのチュートリアル

 各画像が何回選択されたかを追跡しながら、時間ステップとともに変化する確率 DP に基づいてソリューションを構築します。 

1. すべての選択カウントが 0、確率質量が 1 である初期状態から開始します。この時点で、重みは指定された初期重みとまったく同じになります。 
2. 1 ～ の各ステップについて$m$では、現在の DP レイヤーから次のレイヤーへの遷移を計算します。 各状態はカウントのベクトルを表します$(c_1, \dots, c_n)$、この状態から任意の画像を選択することを検討します$i$。 
3. 状態について$c$、現在の重みを次のように計算します。$w_i + (2a_i - 1)c_i$、気に入った写真は重みを増やし、嫌いな写真は重みを減らします。 これにより、その状態における各ピクチャの正確な決定論的な重みが得られます。 
4.総重量を計算します$S = \sum_i w_i + \sum_i (2a_i - 1)c_i$。 これは確率の正規化係数です。 
5.州から$c$、画像を選択して遷移します$i$新しい状態につながる$c'$どこだけ$c_i$1 ずつ増加します。この遷移の確率は、現在の重みです。$i$で割る$S$。 
6. DP 確率質量を次の層状態に蓄積します$c'$。 これにより、明示的に列挙しなくても、考えられるすべてのシーケンスが確実に考慮されます。 
7.完了後$m$ステップでは、すべての状態を合計することによって期待されるカウントを計算します。各状態は、その確率とそのカウント ベクトルの積に寄与します。 
8. 最後に、カウントの変化と重みの更新の間の線形関係を使用して、期待されるカウントを期待される重みに変換し、モジュラー逆算を使用したモジュロ演算で結果を出力します。 

### なぜ効果があるのか

 DP は、ピクチャ選択のすべての可能なシーケンスの確率空間全体を、カウント ベクトルによってインデックス付けされた素のセットに分割します。 すべてのシーケンスは正確に 1 つのカウント ベクトルにつながり、すべての遷移はプロセス定義に従って正確な確率質量を保存します。 カウントが固定されると重みの進化は決定論的になるため、期待値を正確に計算するには DP 状態を条件付けするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def inv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    w = list(map(int, input().split()))
    
    # dp[state] = probability of reaching this count vector
    # state is tuple of counts
    from collections import defaultdict
    
    dp = {tuple([0]*n): 1}
    
    for _ in range(m):
        ndp = defaultdict(int)
        
        for state, prob in dp.items():
            # compute current weights
            weights = []
            total = 0
            
            for i in range(n):
                delta = 1 if a[i] == 1 else -1
                wi = w[i] + delta * state[i]
                weights.append(wi)
                total += wi
            
            if total == 0:
                continue
            
            total_inv = inv(total)
            
            for i in range(n):
                if weights[i] <= 0:
                    continue
                p = prob * weights[i] % MOD * total_inv % MOD
                new_state = list(state)
                new_state[i] += 1
                ndp[tuple(new_state)] = (ndp[tuple(new_state)] + p) % MOD
        
        dp = ndp
    
    exp_counts = [0] * n
    
    for state, prob in dp.items():
        for i in range(n):
            exp_counts[i] = (exp_counts[i] + state[i] * prob) % MOD
    
    res = []
    for i in range(n):
        delta = 1 if a[i] == 1 else -1
        val = (w[i] + delta * exp_counts[i]) % MOD
        res.append(str(val))
    
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```DP ディクショナリには、到達可能なカウント ベクトルにわたる確率質量が格納されます。 各反復では状態を 1 回の訪問だけ拡張し、遷移ごとに 1 つの座標を正確に更新します。 

確率は初期値だけでなく、変化する重みに依存するため、各状態内の重みの計算は非常に重要です。 逆モジュラは、確率計算における除算を処理するために使用されます。 

微妙な点の 1 つは、重みが 0 または負の状態は遷移でスキップされることです。 これは、そのような画像は正の確率で選択できないという解釈と一致します。

 ## 特殊なケース

 1 つの特殊なケースは、1 つの写真だけが「いいね！」された場合に発生します。 その場合、重みの進化に関係なく、すべての確率質量が常にそのピクチャを選択するため、プロセスは決定論的になります。 すべての状態には有効な遷移が 1 つだけ存在するため、DP はこれを正しく処理します。 

もう 1 つのエッジ ケースは、嫌いな写真の重みがゼロになる場合です。 これらの状態から、確率への寄与がゼロになるため、それらのピクチャを通過する遷移は完全にスキップされます。 これにより、無効な負の重みのサンプリング パスが DP に影響を与えることがなくなり、確率質量が有効な構成のみを通過することが保証されます。 

最後の微妙なケースは、複数のピクチャが同じウェイトとタイプで始まる場合の対称性です。 DP は依然としてそれらを別々に扱いますが、それらの分布は同様に進化し、対称遷移確率により期待値は等しいままです。
