 ## 解決策
 ## 問題の理解

 整数の静的配列とパラメータが与えられます。$p$。 隠された実装内で使用される独特の加算ルーチンがあります。これは数値を左から右に加算しますが、加算のたびに条件付きの修正を実行します。 ランニング値が少なくとも$p$、減算します$p$一度。 この補正は、操作ごとに 1 回だけ即時に適用され、モジュロ値を完全に削減しようとするものではありません。$p$。 そのため、中間値は依然として意図したモジュラー範囲を超える可能性があり、最終結果は単なる合計ではなく演算の順序に依存します。 

各クエリは、サブ配列上でこの欠陥のある累積プロセスを実行した結果を要求します。 タスクは、標準範囲の合計や通常のモジュラー合計を計算することではなく、この壊れた加算手順の正確な動作を効率的にシミュレートすることです。 

制約が十分に大きいため、クエリごとにプロセスをシミュレートするアプローチは失敗します。 配列サイズが次の値に達しました$10^6$クエリ数が次の値に達すると、$2 \cdot 10^5$。 単一のクエリに触れる$O(n)$要素はすでに遅すぎるため、要素ごとの対数アプローチさえも除外されます。 ソリューションでは、配列を前処理して、各クエリに対数時間またはほぼ一定の時間で応答できる構造にする必要があります。 

主な微妙な点は、操作が通常の意味で直線的ではないという事実から来ています。 中間のリダクションはプレフィックスの動作に依存するため、これを標準のモジュロ演算として扱う単純な解釈は失敗します。 

最初の誘惑的な間違いは、範囲の合計を計算してから 1 回のモジュロ調整を行うことです。 これは、中間プレフィックスの合計が次の倍数を超える場合に直ちに中断されます。$p$複数回。 

たとえば、次の場合$p = 10$そしてセグメントは$[9, 9]$正しいプロセスは次のようになります。0 から開始し、9 を加算すると 9 が得られ、減算は行わず、さらに 9 を加算すると 18 が得られ、10 を 1 回減算して 8 を取得します。単純な合計では 18 が得られ、実装によっては誤って 8 または 18 に減らされる可能性がありますが、実際のプロセスは 10 を超える中間ステップに依存します。 

値が負の場合、別の故障モードが表示されます。 負の値によって減算がトリガーされることはありませんが、以前に蓄積された値が減少し、後の加算がしきい値を超えるかどうかに影響を与える可能性があります。 合計を追跡するだけのソリューションでは、この順序付けの効果が失われます。 

## アプローチ

 ブルート フォース手法は定義に直接に従います。 各クエリについて、セグメントを反復処理して実行値をシミュレートし、しきい値を超えるたびに条件付き減算を適用します。 これはプロセスを正確に反映しているため、これは正しいです。 ただし、各クエリにはコストがかかります$O(n)$最悪の場合、$O(nm)$、これは実現可能な限界をはるかに超えています。$10^6 \times 2 \cdot 10^5$。 

重要な観察は、このプロセスがセグメントの 2 つの集合プロパティ (セグメントの総和と、左から右にスキャンする場合の最大プレフィックス合計) のみに依存していることです。 その理由は、減算をトリガーする唯一のイベントは、実行中のプレフィックスの合計が次の倍数を超えたときであるためです。$p$。 別の倍数と交差するたびに、ちょうど 1 回の減算が発生します。 したがって、減算の数は、最大プレフィックス合計が相対的にどれだけ大きくなるかによって決まります。$p$。 

これにより、高速マージをサポートするセグメント データを維持するという問題が軽減されます。 セグメント ツリーは、セグメントごとに、その合計と最大プレフィックス合計を保存できます。 連結のプレフィックスの動作は、最適なプレフィックスが完全に左側のセグメントに存在するか、右側のセグメントにまで及ぶかによってのみ決まるため、セグメントを結合するにはこれら 2 つの値で十分です。

 ## アルゴリズムのチュートリアル

 各セグメントに対して維持する構造は、合計と最大プレフィックス合計からなるペアです。 

1. 各リーフが単一の配列要素の値を格納するセグメント ツリーを構築します。 合計は要素そのものであり、プレフィックスが 1 つしかないため、最大プレフィックス合計も要素になります。 
2. 隣接する 2 つのセグメントを結合する場合は、結合された合計を両方のセグメントの合計として計算します。 最終的な実行値は範囲全体の合計に依存するため、これが必要になります。 
3. 2 つの候補を比較して、マージされたセグメントの最大プレフィックス合計を計算します。 最初の候補は、左側のセグメントの最大プレフィックス合計です。 2 番目の候補は、左側のセグメント全体と右側のセグメントの最大プレフィックス合計の合計です。 これは、最適なプレフィックスが左側のセグメント内で停止することも、右側のセグメントに拡張することもできるという事実を捉えています。 
4. お問い合わせの場合$[l, r]$、セグメント ツリーを使用してマージされたセグメント情報を取得します。 
5. しましょう$S$セグメントの合計と$P_{max}$プレフィックスの合計の最大値になります。 バグのある加算が減算された回数$p$等しい$\left\lfloor \frac{P_{max}}{p} \right\rfloor$ただし、次の場合に限ります。$P_{max} > 0$。 もし$P_{max} \le 0$、減算は決して発生しません。 
6. 最終的な答えは次のとおりです。$S - p \cdot k$、 どこ$k$は上記で決定された減算の数です。 

重要な考え方は、すべての減算は次の倍数を超えることに対応するということです。$p$プレフィックスの蓄積中に、最大プレフィックス合計がそれらの交差がどこまで到達できるかを完全に捕捉します。 

### なぜ効果があるのか

 実行中のプロセスは、時折正確に下向きにジャンプしながらプレフィックス合計として展開する値を定義します。$p$。 各ジャンプは、プレフィックスの合計が次の形式の新しいしきい値に達したときに正確に発生します。$k \cdot p$。 厳密に増加するプレフィックス プロセスでは各しきい値を 1 回だけ超えることができるため、ジャンプの合計数は最大の整数に等しくなります。$k$プレフィックスの合計が少なくとも$k \cdot p$。 この条件は、最大プレフィックス合計を で割ることと同じです。$p$。 セグメント連結ではマージ ルールを通じてプレフィックスの最大値が保持されるため、セグメント ツリーはこの動作を再構築するために必要な情報を正確に保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "pref")
    def __init__(self, s=0, p=0):
        self.sum = s
        self.pref = p

def merge(left, right):
    res = Node()
    res.sum = left.sum + right.sum
    res.pref = max(left.pref, left.sum + right.pref)
    return res

n, m, p = map(int, input().split())
a = list(map(int, input().split()))

size = 1
while size < n:
    size <<= 1

seg = [Node() for _ in range(2 * size)]

for i in range(n):
    seg[size + i] = Node(a[i], a[i])

for i in range(size - 1, 0, -1):
    seg[i] = merge(seg[2 * i], seg[2 * i + 1])

def query(l, r):
    l += size
    r += size
    left_res = Node(0, float("-inf"))
    right_res = Node(0, float("-inf"))

    while l <= r:
        if l & 1:
            if left_res.pref == float("-inf"):
                left_res = seg[l]
            else:
                left_res = merge(left_res, seg[l])
            l += 1
        if not (r & 1):
            if right_res.pref == float("-inf"):
                right_res = seg[r]
            else:
                right_res = merge(seg[r], right_res)
            r -= 1
        l >>= 1
        r >>= 1

    if left_res.pref == float("-inf"):
        return right_res
    if right_res.pref == float("-inf"):
        return left_res
    return merge(left_res, right_res)

out = []
for _ in range(m):
    l, r = map(int, input().split())
    l -= 1
    r -= 1
    node = query(l, r)

    s = node.sum
    pref = node.pref

    if pref <= 0:
        out.append(str(s))
    else:
        k = pref // p
        out.append(str(s - k * p))

print("\n".join(out))
```セグメント ツリーには、バグのあるプロセスを再構築するために必要な 2 つの量が正確に保存されます。 マージ操作は、連結下でプレフィックス maxima がどのように動作するかをエンコードします。 クエリは対数時間でセグメントを結合することによって応答され、プレフィックスの最大値から減算回数への最終的な変換により、欠陥のあるモジュラー加算の影響が捕捉されます。 

実装上の微妙な点は、空のセグメント内の最大プレフィックスの ID は、反復クエリのマージ中に慎重に動作する必要があることです。 負の無限大を持つセンチネルを使用すると、空のセグメントが結果に誤って影響を与えることを回避できます。

def run(inp: str) -> str:

    import sys
    input = sys.stdin.readline

    class Node:
        def __init__(self, s=0, p=0):
            self.sum = s
            self.pref = p

    def merge(a, b):
        res = Node()
        res.sum = a.sum + b.sum
        res.pref = max(a.pref, a.sum + b.pref)
        return res

    n, m, p = map(int, input().split())
    arr = list(map(int, input().split()))

    size = 1
    while size < n:
        size <<= 1

    seg = [Node() for _ in range(2 * size)]

    for i in range(n):
        seg[size + i] = Node(arr[i], arr[i])

    for i in range(size - 1, 0, -1):
        seg[i] = merge(seg[2 * i], seg[2 * i + 1])

    def query(l, r):
        l += size
        r += size
        left = None
        right = None

        while l <= r:
            if l & 1:
                left = seg[l] if left is None else merge(left, seg[l])
                l += 1
            if not (r & 1):
                right = seg[r] if right is None else merge(seg[r], right)
                r -= 1
            l >>= 1
            r >>= 1

        if left is None:
            node = right
        elif right is None:
            node = left
        else:
            node = merge(left, right)

        s = node.sum
        pref = node.pref
        if pref <= 0:
            return s
        return s - (pref // p) * p

    out = []
    for _ in range(m):
        l, r = map(int, input().split())
        out.append(str(run_case := query(l - 1, r - 1)))

    return "\n".join(out)

 ## 特殊なケース

 まれなケースは、セグメント内のすべての値が負の場合に発生します。 その状況では、ランニングバリューは決して到達しません$p$, したがって、減算は行われません。 セグメント ツリーは、負のプレフィックス合計の最小値である正しい最大プレフィックスを保持する必要があります。そうしないと、後のマージでしきい値を超えると誤って想定される可能性があります。 

もう 1 つのケースは、プレフィックスの合計が の倍数にまたがる大きな正の値を持つセグメントです。$p$。 構造がしきい値の単調累積を保証しているため、正確性は、個々の交差をカウントするのではなく、最大プレフィックス合計のフロア除算を使用することに依存します。 

最後の微妙なケースは、左セグメントの合計が大きな負であり、右セグメントに大きな正のプレフィックスがある場合です。 マージでは、右のプレフィックスが左の合計によって正しくオフセットされていることを確認する必要があります。そうしないと、プレフィックスの最大値が実際の累積から切り離されてしまいます。
