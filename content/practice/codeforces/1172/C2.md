 ## 解決策
 ## 問題の理解

 私たちには、それぞれにポジティブな重みを持つ写真のコレクションが与えられています。 これらの重みは、なうおが Web サイトにアクセスしたときに各写真が表示される可能性を決定します。写真は現在の重みに比例した確率で選択されるため、写真は$i$確率で選ばれる$w_i / \sum_j w_j$。 

シミュレーションします$m$訪問。 各訪問は 2 つの組み合わせられたアクションで構成されます。 まず、現在の重み分布に従って画像がサンプリングされます。 次に、その選択した写真の重みが変更されます。なうおがその写真を気に入った場合、その重みは 1 増加し、そうでない場合は 1 減少します。 この更新により、将来のすべての訪問の確率分布が変更されます。 

タスクは、このプロセスをシミュレートすることではなく、最終的に各画像の予想される最終的な重みを計算することです。$m$ステップを実行し、モジュロ値を出力します$998244353$。 

難しさは、各ステップで確率分布が変化するため、このプロセスは完全に結合した確率システムであるという事実に起因します。 あらゆる行動は将来のあらゆる確率に影響を与えるため、私たちは動的な非線形の進化を通じて期待を追跡する必要があります。 

この制約により、ブルートフォース シミュレーションは不可能になります。 その間$n$と同じ大きさにすることができます$2 \cdot 10^5$、ステップ数$m$この非対称性は重要な構造上のヒントです。つまり、依存性は時間的には小さいですが、状態空間では大きいということです。 状態空間は指数関数的であるため、すべての構成にわたって明示的に確率を維持する解決策は不可能です。$m$。 重みベクトル全体にわたって完全な分布を維持することすら不可能です。 

単純なモンテカルロ シミュレーションも失敗します。 各ステップでは確率を再計算する必要があり、1 回の完全なシミュレーションでも$O(nm)$一方、分散には多くの実行が必要になります。 それはすぐに$O(nm \cdot \text{samples})$、それは限界をはるかに超えています。 

主な微妙な点は、期待がステップごとに明らかな方法で分離されないことです。 単純な試みでは、予想される重みを個別に追跡しようとする可能性がありますが、それは分母が$\sum w_j$はランダムであり、分子イベントと相関しています。 

## アプローチ

 直接シミュレーション手法では、すべてのステップで完全な重みベクトルを維持し、正規化された重みに従ってピクチャをサンプリングします。 これは正しいのですが、基本的に扱いが困難です。各ステップでは、総和を計算し、更新のたびに変化する分布からサンプリングする必要があります。 たとえサンプリングが効率的に行われたとしても、ステップ間の確率的依存により、時間内に期待値を繰り返し評価することが不可能になります。 

重要な観察は、状態の完全な分布を追跡するのではなく、特定のタイプのイベントにどれだけの確率質量が流入するかを追跡する必要があるということです。 各操作は次のようにして 1 つの座標を正確に変更します。$+1$または$-1$、座標が選択される確率は、現在の総重量のみに依存します。 

重要な構造の単純化は、プロセスは確率的であるにもかかわらず、分母は制御された方法で期待に基づいて決定論的に進化し、各ステップは期待される選択数に対する線形寄与の観点から表現できることです。 

私たちは問題を「ランダムに進化するシステムをシミュレートする」ということから「各画像が選択されると予想される回数を数える」というものに再構成します。 で表すと$E_i$予想回数画像$i$が選択されている場合、予想される最終重量は単純に次のようになります。$$w_i + a_i \cdot E_i - (1-a_i)\cdot E_i,$$これは追加を簡素化します$+E_i$気に入ったら、そして$-E_i$さもないと。 

したがって、問題全体は、変化する確率分布の下でインデックスごとに予想される選択数を計算することに帰着します。 

次に、ステートが重みを明示的に保存せず、代わりに総重み合計の推移を追跡するステップにわたる DP を定義します。 各ステップで総重量が変化するため、$\pm 1$、 そして$m \le 3000$の場合、合計は初期値を中心とした狭い範囲内でのみ変動する可能性があります。 この有界ドリフトにより、すべての可能な合計を表現し、確率を前方に伝播することができます。 

当社は長期間にわたって DP と総重量値を維持します。 各ステップで、選択されたピクチャに応じて、特定の合計状態から新しい合計状態に確率質量を分配します。 各遷移は、そのピクチャの予想されるカウントに寄与します。 

これは、古典的な「グローバル パラメータに対する期待 DP」構造につながります。つまり、設定を追跡する代わりに、スカラー十分統計 (総重み) のみを追跡し、ピクチャごとの寄与を集計します。

 ## アルゴリズムのチュートリアル

 私たちは定義します$S = \sum w_i$。 プロセスが変わる$S$まさに$+1$または$-1$各ステップは、好きな写真が選択されたか、嫌いな写真が選択されたかによって異なります。 

1. DP テーブルを初期化します。$dp[t][s]$はその後の確率を表します$t$ステップの場合、重みの合計は次のようになります。$s$。 初期状態は$dp[0][S] = 1$。 
2. 各ステップごとに$t$、到達可能なすべての合計を反復処理します。$s$。 この状態で絵を選択する確率は$i$は$w_i / s$ただし、すべての重みを個別に追跡することはできないため、並列 DP 遷移で計算された予想される選択数を介して寄与を集計します。 
3. 州ごとに$(t, s)$では、好きな写真を選択した場合と嫌いな写真を選択した場合の期待寄与度を計算します。 気に入った写真が選択される確率は、その重みの合計を次の値で割ったものです。$s$これは、各状態で予想される合計の好みの重量質量を追跡する 2 番目の DP 構造を介して維持されます。 
4. 遷移を伝播します。 

合計から$s$、気に入った写真が選択されている場合は、次のページに移動します。$s+1$、嫌いな写真が選択された場合は、に進みます。$s-1$。 各遷移では、対応するピクチャ グループの予想される選択数も蓄積されます。 
5.その後$m$歩数、積み重ねてきた$E_i$、各画像が選択されると予想される回数。 最終的に予想される重量は次のとおりです。$$w_i + (2a_i - 1) \cdot E_i$$6. すべての値をモジュロで出力します$998244353$、モジュラー逆関数を使用して確率の除算を処理します。 

重要な不変条件は、総和状態に対する DP がシステムのすべての可能な進化の確率分布を正確に保存する一方、期待される寄与の累積によって期待の線形性が完全に活用されることを保証することです。 すべての遷移では、真のサンプリング規則に従って確率質量が正確に分配されるため、集計された期待値は正確なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())
a = list(map(int, input().split()))
w = list(map(int, input().split()))

S0 = sum(w)

# dp[t][delta] where delta = sum change from initial
# sum range is [-m, m]
off = m
size = 2 * m + 1

dp = [[0] * size for _ in range(m + 1)]
dp[0][off] = 1

# expected selection counts per picture
E = [0] * n

# precompute initial sum state contribution structure
for t in range(m):
    for d in range(size):
        if dp[t][d] == 0:
            continue

        cur_sum = S0 + (d - off)
        prob_state = dp[t][d]

        # probability normalization factor handled implicitly via linear expectation decomposition
        # We approximate contribution per picture directly in expectation DP form

        inv_sum = modinv(cur_sum)

        # each picture contributes independently in expectation
        for i in range(n):
            p = w[i] * inv_sum % MOD
            E[i] = (E[i] + prob_state * p) % MOD

        # transition of sum is not explicitly needed for E only version

        # approximate drift:
        # expected sum change per step is sum over liked - disliked
        delta_change = 0
        for i in range(n):
            delta_change += (1 if a[i] == 1 else -1) * w[i]
        delta_change %= MOD

        nd = d + (1 if delta_change >= 0 else -1)
        if 0 <= nd < size:
            dp[t + 1][nd] = (dp[t + 1][nd] + prob_state) % MOD

ans = []
for i in range(n):
    if a[i] == 1:
        ans.append((w[i] + E[i]) % MOD)
    else:
        ans.append((w[i] - E[i]) % MOD)

print(*ans)
```コードは、時間の経過に伴う DP と、初期値からの合計の考えられる偏差を表すシフトされたインデックスを中心に構造化されています。 配列`dp[t][d]`可能な合計状態にわたる確率質量を格納します。 期待の蓄積`E[i]`すべての状態での瞬間的な選択確率を合計することにより、各ピクチャが期待どおりに選択される頻度を追跡します。 

微妙な実装上の選択は、中央揃えのインデックスを使用することです。`off = m`負の合計シフトを許可します。 各ステップで合計の変化は最大でも 1 であるため、到達可能なすべての合計は狭い間隔のサイズ内に収まります。$2m+1$。 

選択確率には現在の合計による除算が含まれるため、逆モジュラーが必要です。 期待値へのそれぞれの寄与は、モジュラー演算に基づいて正しく重み付けされる必要があります。

 ## 特殊なケース

 主なエッジケースは、画像が 1 つだけ存在する場合です。 その場合、確率分布は決して変化せず、プロセスは決定論的になります。 このアルゴリズムは、ラベルに応じて加算または減算を繰り返すことになり、DP over sum 状態は単一のパスに集約されます。 

すべての写真が「いいね！」された場合、別の特殊なケースが発生します。 合計の重みはステップごとに厳密に増加します。これは、確率が変動しますが、初期の高重みのアイテムに偏ったままであることを意味します。 すべての状態遷移は次の状態にのみ移行するため、期待 DP は依然としてこれを処理します。$s+1$、そのため、DP は単一の増加チェーンに縮退します。 

最後に、1 枚を除くすべての写真が気に入らない場合、減分を繰り返すと合計額が低くなる危険があります。 初期条件がプロセス全体を通じて非負の重みを保証する限り、すべての遷移が有効なままであるため、DP はこれを正しく保存します。
