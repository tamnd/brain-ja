 ## 解決策
 ## 問題の理解

 私たちにはアスリートの集合が与えられ、それぞれが強さと持久力という 2 つの属性によって説明されます。 これらのアスリートの中からちょうど k 人を選ばなければなりません。 

重要な条件は、選考そのものではなく、選ばれたグループが決勝トーナメントでどのような「勝者不確実性」を生み出すかである。 2 人のアスリートが厳密な支配関係を持つのは、どちらかが筋力と持久力の両方において厳密に優れている場合に限られます。 そのような優位性が維持されない場合、両者の試合ではどちらの結果になる可能性があります。 

トーナメントの構造は、1 人の勝者が残るまでランダムにペアを排除します。 試合結果は優勢の場合を除いて固定されていないため、組み合わせや結果の順序が異なると、最終的な勝者も異なる可能性があります。 タスクは、最終チャンピオンが一意に決定されない状況を生み出すサイズ k のサブセットがいくつあるかを数えることです。これは、異なるチャンピオンで終わるトーナメントの有効な展開が少なくとも 2 つ存在することを意味します。 

したがって、本当の問題は組み合わせの問題です。すべての k サイズのサブセットの中で、両方の次元での厳密な順序付けによって定義される支配関係の下で、最終的な勝者に関して「非決定的」であるサブセットを検出する必要があります。 

この制約により、最大 5,000 人のアスリートが許可されます。 すべての k サブセットに対する単純なアプローチでは、k が約 2500 であっても実行不可能な組み合わせ爆発が生じるため、天文学的な規模になります。 サブセットを列挙したり、サブセットごとにトーナメントをシミュレートしたりするソリューションは、直ちに除外されます。 

微妙なエッジケースは、優位性が極値点とどのように相互作用するかによって生じます。 

選択されたサブセット内のすべてのアスリートが、他のすべてのアスリートよりも両方の次元で厳密に優れているアスリートが存在するという意味で同等である場合、そのアスリートはあらゆる可能な進化においてチャンピオンになることを余儀なくされます。 たとえば、アスリート (1,1)、(2,2)、(3,3) を選択した場合、最後のアスリートが厳密に優勢で常に勝つため、サブセットは無効になります。 

少なくとも 2 人のアスリートがいて、どちらも他方を支配していない場合、トーナメントの結果が異なる可能性があります。 たとえば、(1,3) と (3,1) には優劣関係がなく、ペアリングの順序と試合結果に応じてどちらかが勝つ可能性があり、サブセットが有効になります。 

最も難しいのは、サブセットに固有の「グローバル ドミネーター」がある場合を特定し、その構造を回避するすべてのサブセットをカウントすることです。 

## アプローチ

 直接的な総当たりアプローチでは、k サイズのすべてのサブセットを列挙し、サブセットごとに、すべてのトーナメントの結果をシミュレートまたは推論します。 単一のサブセットをチェックするだけでも、固有の支配的なアスリートが存在するかどうかを判断する必要がありますが、サブセットの生成だけでもすでに C(n, k) のオーダーに達しており、これは n で指数関数的です。 n が 5000 までの場合、これは完全に不可能です。 

重要な構造的洞察は、支配を幾何学的に再解釈することです。 各アスリートは 2D 平面内の点です。 両方の座標において他のアスリートよりも厳密に優れているアスリートが右側に横たわっています。 アスリートを強さで分類すると、優位性は持久力の順序を確認することになります。 

重要な観察は、サブセットに決定的な勝者が存在するのは、サブセット内の他のすべてを支配するこの半順序の「最大要素」が含まれている場合のみであるということです。 2D では、そのような点は、サブセット内の両方の次元で同時に最大になることに対応します。 

これにより、問題は、単一の点が他のすべてを支配する厳密なパレート最大値にならないサブセットをカウントすることに帰着します。 同様に、選択されたアスリートが他のすべての選択されたアスリートを支配するものを除いた、すべての k サブセットをカウントします。

固定のアスリート i について、i が他の選択されたアスリートすべてを圧倒するサイズ k のサブセットがいくつ存在するかを数えます。 つまり、他のすべての K-1 アスリートは、筋力と持久力の両方で厳密に i を下回る必要があります。 並べ替えて圧縮すると、2D 優位性に対するプレフィックス構造を使用して、そのようなサブセットをカウントできます。 標準的な方法は、強さによって並べ替え、耐久性に関するフェンウィック ツリーを維持して、各 i の有効な候補をカウントすることです。 

各アスリートは、強制チャンピオンとして機能する無効な構成に貢献します。 すべての i を合計すると、「不良」サブセットの総数が得られます。 答えは、合計 C(n, k) からこの値を引いたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース + シミュレーション | O(C(n,k) · k²) | O(k) | 遅すぎる |
 | ソート + Fenwick を使用したドミナンス カウンティング | O(n log n + n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアスリートを強さ順に並べ替えます。必要に応じて、二次キーとして持久力順に並べ替えます。 これにより、アスリートを処理するときに、そのアスリートが強さで優位に立つ可能性のあるすべての候補者がすでに構造化された順序になっていることが保証されます。 
2. 持久力の値を調整圧縮して、以前に持久力の低いアスリートが何人いるかを効率的にクエリできるようにします。 耐久性の値は大きいが、相対的な順序のみが重要であるため、これが必要です。 
3. これまでに処理したアスリートの数を保存する持久力インデックスに対するフェンウィック ツリーを維持します。 
4. アスリートを強さの順に繰り返します。 各アスリート i について、以前に処理された持久力が厳密に s[i] 未満のアスリートが何人いるかをクエリします。 これにより、両方の次元で優勢な候補の数が得られます。 
5. 各アスリート i について、それが支配するアスリートのセットからサイズ k-1 のサブセットがいくつ形成できるかを計算します。 この値を、i が強制勝者となる無効なサブセットの総数に加算します。 
6. すべてのアスリートを処理した後、組み合わせ論 C(n, k) を使用して k サブセットの合計数を計算し、無効なサブセットを減算し、結果のモジュロ 998244353 を出力します。 

これが機能する理由は、各無効なサブセットが両方の次元で一意の「右上」点を持つと見なすことにあります。 サブセットに決定的な勝者がある場合、その勝者は他のすべてのメンバーよりも優勢である必要があり、したがって、そのサブセット内の両方の座標の最大値でなければなりません。 そのようなすべての構成は、その支配的なアスリートを固定し、その支配地域から他のすべての K-1 メンバーを選択するときに、正確に 1 回カウントされます。 他のアスリートが両方の次元で同時にそれを支配できないため、これによりオーバーカウントが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    s = list(map(int, input().split()))

    athletes = list(zip(p, s))
    athletes.sort()

    ys = sorted(set(s))
    comp = {v:i+1 for i, v in enumerate(ys)}
    m = len(ys)

    bit = [0] * (m + 2)

    def add(i, v):
        while i <= m:
            bit[i] += v
            i += i & -i

    def query(i):
        res = 0
        while i > 0:
            res += bit[i]
            i -= i & -i
        return res

    def comb(n, r):
        if r < 0 or r > n:
            return 0
        r = min(r, n - r)
        num = 1
        den = 1
        for i in range(r):
            num = num * (n - i) % MOD
            den = den * (i + 1) % MOD
        return num * pow(den, MOD - 2, MOD) % MOD

    total = comb(n, k)
    bad = 0

    for i, (x, y) in enumerate(athletes):
        yi = comp[y]
        cnt = query(yi - 1)
        if k - 1 <= cnt:
            bad = (bad + comb(cnt, k - 1)) % MOD
        add(yi, 1)

    print((total - bad) % MOD)

if __name__ == "__main__":
    solve()
```コードは強さによるソートに依存しているため、アスリートを処理するときに、フェンウィック ツリーには強さより小さいか同等の強さを持つ選手が正確に含まれます。 次に、フェンウィック ツリーは、耐久性がより低いそれらの数を分離します。 

n が呼び出しごとに O(k) の計算を合計で許容できる程度に十分小さいため、組み合わせ関数は直接実装されます。 

実装の微妙な詳細は、支配領域内に収まるサイズ k-1 のサブセットのみをカウントするようにすることです。 cnt が k-1 より小さい場合、そのアスリートは強制勝利サブセットを形成できず、貢献度はゼロになります。 

## 実用的な例

 ### 例 1

 入力:

 n = 4、k = 2

 p = [1, 1, 3, 3]

 s = [1, 3, 1, 3]

 強さで並べ替えると、ペアのリストは次のようになります。 

(1,1)、(1,3)、(3,1)、(3,3)

 私たちは各アスリートを治療し、持久力を超えたフェンウィックの木を維持します。 

| アスリート | 耐久指数 | クエリを小さくする | 寄与率 C(cnt, k-1) | | の後のビット
 | --- | --- | --- | --- | --- |
 | (1,1) | 1 | 0 | 0 | {1} |
 | (1,3) | 2 | 1 | 1 | {1,2} |
 | (3,1) | 1 | 0 | 0 | {1,2,1} |
 | (3,3) | 2 | 3 | 3 | {1,2,1,2} |

 サブセットの合計 C(4,2) = 6。不良サブセット = 4、したがって、答え = 2。 

これは、1 人のアスリートが両方の次元を支配するサブセットのみがどのように変動から除外されるかを示しています。 

### 例 2

 入力:

 n = 5、k = 3

 p = [2,2,4,4,5]

 s = [1,1,4,5,4]

 ソートされたペア:

 (2,1)、(2,1)、(4,4)、(4,5)、(5,4)

 この表は、混合ペアがばらつきに寄与する一方で、より高い (p, s) を持つアスリートがどのように支配的なカウントを蓄積し、強制的なサブセットを生成するかを示しています。 

計算により、どのアスリートがサイズ k-1 サブセットの厳密な支配者として機能できるかが分離され、それらの構成のみが合計から削除されることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + n log C(n,k)) | アスリートごとの並べ替え、フェンウィック操作、および組み合わせ論 |
 | スペース | O(n) | 圧縮された座標とフェンウィック ツリーのストレージ |

 ソートとフェンウィック更新の両方が対数的であり、組み合わせ計算は最悪でも k で線形ですが、n で償却されるため、この解は n の制限内で最大 5000 まで問題なく収まります。

 ## 特殊なケース

 すべてのアスリートが筋力と持久力の両方において厳密な連鎖を形成すると、すべてのサブセットには明確な支配的な要素が存在します。 すべての k サブセットには常に勝つ 1 人の支配的なアスリートが含まれるため、アルゴリズムはすべてのサブセットを無効として正しくカウントします。 

他のアスリートを圧倒するアスリートがいない場合、トーナメントの結果が異なる可能性があるため、すべてのサブセットが有効になります。 支配的なカウントは常に小さく、減算がゼロになるため、アルゴリズムはこれを処理します。 

複数のアスリートが同じ筋力や持久力を共有している場合、優位性が崩れ、厳密な比較は不可能になります。 フェンウィック ベースのカウントでは、厳格な不平等チェックにより、当然のことながら、等しい値は非優勢なものとして扱われ、そのような同点が誤って強制的な勝者に寄与しないことが保証されます。
