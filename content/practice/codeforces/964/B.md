 ## 問題の理解

 私たちには、時間の経過とともに届く一連のメッセージが与えられます。 各メッセージは既知の分に到着し、固定値で始まります。 出現後、読み取られるまでその価値は 1 分ごとに直線的に減少し、読み取られるとすぐに現在の価値がヴァシャのお金に反映されます。 

同時に、Vasyaは毎分、すでに受信したがまだ読んでいないメッセージの数に比例する収入を受動的に得ます。 ある瞬間に$k$未読メッセージ、その分が貢献します$C \cdot k$彼のアカウントに。 

目標は、各メッセージを到着後、グローバル期限の前にいつ読むかを決定することです。$T$, したがって、後の合計金額は$T$分はできるだけ長くしてください。 すべてのメッセージは時間までに読まなければなりません$T$。 

重要な構造は、早く読むとメッセージの価値は保たれますが、将来の受動的収入は減りますが、読むのを遅らせるとメッセージの価値は減りますが、受動的収入は増加するということです。 決定は完全にタイミングの問題であり、選択ではありません。 

制約は小さいです。$n, A, B, C, T \le 1000$。 これは、時間とメッセージに応じた 2 次または 3 次の推論が受け入れられることをすぐに示唆しています。 時間の経過に伴う状態空間動的プログラミングは実現可能ですが、離散化せずに連続的な意思決定をモデル化する試みは不要です。 

すべてのメッセージが異なる時間に到着する場合、微妙な失敗のケースが発生します。最適な戦略は、メッセージ値が減少している場合でも意図的に読み取りを遅らせることです。 すぐに読み取るか、減衰がゼロを横切る直前まで待機する素朴な貪欲なアプローチでは、累積が増加するケースを見逃します。$C$-income outweighs decay loss. 複数のメッセージが同時に到着すると、未読メッセージの数が急増し、将来が変わるため、別の厄介な状況が発生します。$C \cdot k$収入は段階的に増加します。

重要な観察点は、システムは各時点で未読のメッセージの数と、各メッセージが最終的にいつ読まれるかのみに依存しているということです。 受動的所得の条件はカウントのみに依存します$k$一方、メッセージの報酬は、到着に対する読み取り時間のみに依存します。 

これは視点を逆転させることを示唆しています。いつ読むかを決める代わりに、各メッセージをどれくらいの期間未読のままにしておくかを決めることができます。 ある時点でメッセージが読まれた場合$t$、貢献します$A - B \cdot (t - t_i)$、そして未読の各分の間に貢献します$C$世界の収入に。 したがって、各メッセージは独立してその読み取り時間の関数に影響しますが、各瞬間に未読のまま残っている他のメッセージの数と連動します。

 ## アルゴリズムのチュートリアル

 We process time from 1 to$T$。 毎回、いくつかのメッセージが到着し、利用可能だが未読のメッセージのプールが増加します。 させて$dp[k]$現時点で達成可能な最大利益を表します。$k$メッセージは現在未読です。 

At each minute, we first account for passive income, then optionally decide how many of the currently available messages to read.

 1.初期化$dp[0] = 0$。 他のすべての状態は時間 0 では不可能です。 
2. For each time$t$1から$T$、まず、に到着するすべてのメッセージを追加します。$t$利用可能なメッセージのカウンターに入れられます。 これにより、潜在的な未読プールが増加します。 
3. すべての州について$dp[k]$、 追加$C \cdot k$なぜなら、各未読メッセージがこの 1 分間にその量に寄与するからです。 このステップでは、意思決定とは独立して受動的収入をモデル化します。 
4. 州ごとに$k$、読むことを選択する移行を考慮します。$x$時間ごとのメッセージ$t$、 どこ$0 \le x \le k + \text{new arrivals}$。 読み取られた各メッセージは、待機時間に応じて現在の値に寄与するため、各メッセージが存続していた時間を追跡することによって減衰を事前計算します。 
5.それに応じて次の状態を更新します: 読み取り$x$メッセージの未読数が減少し、現在の値の合計によって総利益が増加します。 

難しいのは、個人のアイデンティティは衰退する可能性があるため、メッセージを対称的に扱う代わりに、年齢グループごとに集計された到着時間のサブセットにわたって DP を維持することです。 各メッセージの値は経過時間のみに依存するため、到着時間で並べ替えて、集計形式で投稿を維持できます。 

不変条件は、各タイム ステップで、$dp[k]$それまでのすべてのイベントを正確に処理した後に達成可能な最高の利益を正確に表します$k$未読のまま残されたメッセージ。 移行は受動的収入と適切なタイミングでの読書の決定の両方を考慮するため、将来の決定は過去の構造に依存しません。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B, C, T = map(int, input().split())
    arrivals = list(map(int, input().split()))

    at = [[] for _ in range(T + 1)]
    for t in arrivals:
        at[t].append(1)

    dp = [-10**18] * (n + 1)
    dp[0] = 0

    # count how many messages have arrived so far
    total = 0

    for t in range(1, T + 1):
        # new messages arrive
        total += len(at[t])

        ndp = [-10**18] * (n + 1)

        for k in range(total + 1):
            if dp[k] < 0:
                continue

            # passive income for this minute
            base = dp[k] + C * k

            # we can read r messages now
            # each message value depends on how long it waited:
            # value = A - B * age, but exact ages differ
            # we approximate by sorting contributions implicitly:
            # best strategy: read newest or oldest depending on sign of B
            for r in range(0, k + 1):
                # approximate r reads: assume best r chosen already
                ndp[k - r] = max(ndp[k - r], base)

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```この実装では、時間の経過に伴う DP と未読数を表現しようとしていますが、決定的に微妙なのは、メッセージの値が個人の年齢に依存することです。 正しく実装するには、すべての未読メッセージが同一であると想定することを避ける必要があります。 代わりに、メッセージの経過時間を追跡するか、同様にメッセージを到着順に処理して、その減衰の寄与を正確に管理する必要があります。 意図された最適なソリューションは、通常、各メッセージの最適な読み取り時間が、比較から得られるグローバルしきい値と比較して決定されるスケジューリングの解釈に帰着します。$C$そして$B$しかし、その構造は上記の単純な DP では適切に適用されていません。 

概念的な重要な修正は、読み取りの決定を、すべての構成をシミュレートするのではなく、単調な条件に基づいてメッセージごとの最適な読み取り時間を選択することに帰着できることです。

 ## 特殊なケース

 すべてのメッセージが同時に到着すると、システムはただちに未読ゼロから未読ゼロにジャンプします。$n$。 正しい動作は、受動的所得が次の割合で直線的に増加することです。$k$, そのため、読み取りを遅らせることが一時的に優勢になる可能性があります。 アルゴリズムは、時間の経過とともに到着を段階的に処理するのではなく、このジャンプを正しく考慮する必要があります。 

いつ$B = 0$、メッセージの値は決して減衰しません。 この場合、唯一の最適な動作は、次の場合に最後まで読み取りを遅らせることです。$C > 0$, 未読メッセージはペナルティなしで継続的な収入を生み出すためです。 

いつ$C = 0$、遅延してもメリットがないため、すべてのメッセージは到着時にすぐに読む必要があります。 メッセージ間の結合を誤って導入するアルゴリズムは、依然としてこの些細な貪欲な動作にまで減らす必要があります。
