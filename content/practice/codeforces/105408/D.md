 ## 解決策
 ## 問題の理解

 フェレットが円状に配置された位置でどのように移動するかを説明する順列が与えられています。 いつでも、円上の各位置は 1 匹のフェレットによって占有されており、順列を適用すると、すべてのフェレットが同時に次の位置に進みます。 この操作を繰り返すと、すべてのフェレットが順列のサイクルに沿って独立して移動する離散時間動的システムが形成されます。 

各クエリについて、あるラウンドの開始時に 2 匹の特定のフェレットが円上で隣接するかどうかが尋ねられます。 「ラウンドの開始」とは順列を何回か適用した後を意味するため、問題は時間ステップが存在するかどうかです。$k \ge 0$順列を適用した後、$k$選択した 2 つのフェレットの位置が円上の隣接するインデックスを占める場合があります。 

重要な点は、隣接関係がラベルの固定円上で定義されていることです。$1$を通して$n$、一方、動きは順列によって定義されます。 置換のサイクルに沿って距離を追跡しているのではなく、置換の同じ累乗に基づく画像が 2 つの連続するラベルを法的に表したことがあるかどうかを尋ねます。$n$。 

制約により、テスト ケースごとにほぼ線形の解決策が求められます。 の合計$n$そして$q$すべてのテスト ケースで最大でも$5 \cdot 10^5$、つまり、次式の解はすべて$n$あるいは$q \log n$クエリごとに失敗します。 テスト ケースごとに 1 回順列を前処理し、一定時間またはほぼ一定時間で各クエリに応答する構築を期待する必要があります。 

単純なシミュレーションはすぐに失敗します。 各フェレットは順列のサイクル内にあり、サイクルの長さは次のようになります。$n$, までシミュレートします$2024!^{2024!}$ステップは不可能です。 問題をサイクルの周期性に還元しても、2 つのフェレットを直接同期させようとすると、潜在的に巨大な最小公倍数が残る可能性があります。 

2 番目の単純なアイデアは、各クエリの置換の全サイクルをシミュレートし、すべての隣接イベントを記録することです。 それには費用がかかります$O(n^2)$最悪の場合、テスト ケースごとに制限され、制約を乗り越えられなくなる可能性があります。 

## アプローチ

 重要な観察は、順列が独立したサイクルに分解されていることです。 各フェレットは、ステップごとに固定オフセットでサイクルに沿って移動します。 開始時間を固定する場合$k$、フェレットの位置は完全にその周期内のインデックスと、$k$サイクル長のモジュロ。 

これにより、問題は 2 つの巡回ウォーク間の同期の問題に変わります。 フェレット用$a$そして$b$、それらが周期的に横たわっていると仮定します。$A$そして$B$長さの$L_A$そして$L_B$。 時間に$k$、サイクル内での位置は次のようにシフトします。$k \bmod L_A$そして$k \bmod L_B$。 時間が存在するかどうか知りたい$k$実際のラベルが固定円のエッジを形成するようにします。 

時間の観点から考えるのではなく、視点を逆転させます。 円上の固定エッジ、たとえば位置間の固定エッジを考えてみましょう。$u$そして$v$。 のために$u$そして$v$同時に占領される$a$そして$b$時に$k$、オフセットは 2 つのモジュラー方程式を満たす必要があります。 これにより、以下の合同システムが作成されます。$k$これは、特定の剰余条件がサイクル長の最大公約数を法として保持する場合にのみ解くことができます。 

これにより、問題は、円に隣接するペアが少なくとも 1 つ存在するかどうかを確認することになります。$(u, v)$それらのサイクル オフセットの差が、$a$そして$b$、モジュロ$\gcd(L_A, L_B)$。 

ブルート フォース アプローチでは、すべてのクエリに対してすべての円のエッジが試行されます。 が遅いですからね。$O(n)$エッジと$O(q)$クエリ。 

重要な構造的洞察は、各円エッジが 2 つの順列サイクルを接続し、そのようなサイクルの各ペアについて、それらの接続エッジ間に現れるオフセット差の剰余クラスを保存するだけでよいということです。 円の元の各エッジはそのようなペアに 1 回だけ寄与するため、保存されるレコードの総数は次のように線形になります。$n$。 

これにより、すべてのエッジをサイクルのペアによってインデックス付けされたマップに前処理し、各ペアに対して、対応する gcd を法とする実行可能な剰余のセットを格納できます。 その後、各クエリはその構造内の 1 つのルックアップに減ります。

 ## アルゴリズムのチュートリアル

 1. 順列をサイクルに分解し、各ノードにサイクル識別子とそのサイクル内の位置を割り当てます。 

これが必要なのは、順列の繰り返し適用下での動作がサイクル内の単なるモジュラー演算であるためです。 
2. 円のすべての隣接エッジ (間のエッジを含む) を繰り返します。$n$そして$1$。 

各エッジは 2 つのノードを接続します$u$そして$v$、いくつかのサイクルに属します$C_u$そして$C_v$。 
3. このようなエッジごとに、gcd を計算します。$g = \gcd(|C_u|, |C_v|)$。 

この値は、2 つの独立した循環シフトがいつ整列できるかを決定します。これは、両方のサイクルが異なる周期で繰り返される可能性があるためです。 
4.剰余値を計算する$$r = (pos[u] - pos[v]) \bmod g$$そしてそれをペアによってインデックス付けされた構造に保存します$(C_u, C_v)$。 

これは、この特定のエッジが両方のサイクルと一致する時間調整で達成可能であることをエンコードします。 
5. 各クエリについて$(a, b)$、周期を特定する$C_a$そして$C_b$、計算する$g = \gcd(|C_a|, |C_b|)$、そして計算します$$\delta = (pos[a] - pos[b]) \bmod g.$$6. 次のことを確認して質問に答えます。$\delta$ペアの保存された残基の中に出現します$(C_a, C_b)$。 存在する場合は 1 を出力し、存在しない場合は 0 を出力します。 

### なぜ効果があるのか

 各サイクルはモジュラークロックのように動作し、ステップごとに位置が 1 つ進みます。 2 匹のフェレットは、1 回の場合にのみ、固定された円の位置のペアに整列します。$k$2 つのモジュール制約を同時に満たします。 このようなシステムでは、制約がサイクル長の gcd を法として一致する場合に正確に解が得られます。 

すべての円の隣接エッジは、そのような制約の 1 つをエンコードします。 サイクル ペアごとにすべての制約を保存すると、達成可能なアライメントのセットが正確に保存され、置換サイクルは独立して展開されるため、他の相互作用は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find_cycles(p):
    n = len(p) - 1
    vis = [False] * (n + 1)
    cid = [0] * (n + 1)
    pos = [0] * (n + 1)
    cycles = []

    for i in range(1, n + 1):
        if vis[i]:
            continue
        cur = []
        v = i
        while not vis[v]:
            vis[v] = True
            cid[v] = len(cycles)
            pos[v] = len(cur)
            cur.append(v)
            v = p[v]
        cycles.append(cur)

    return cid, pos, cycles

def solve():
    T = int(input())
    out_lines = []

    for _ in range(T):
        n, q = map(int, input().split())
        p = [0] + list(map(int, input().split()))

        cid, pos, cycles = find_cycles(p)
        cyc_len = [len(c) for c in cycles]

        store = {}

        def add_edge(a, b):
            ca, cb = cid[a], cid[b]
            if ca == cb:
                return
            if ca > cb:
                ca, cb = cb, ca
                a, b = b, a

            g = gcd(cyc_len[ca], cyc_len[cb])
            key = (ca, cb)
            if key not in store:
                store[key] = set()
            store[key].add((pos[a] - pos[b]) % g)

        from math import gcd

        for i in range(1, n + 1):
            j = i + 1 if i < n else 1
            add_edge(i, j)

        res = []
        for _ in range(q):
            a, b = map(int, input().split())
            ca, cb = cid[a], cid[b]

            if ca == cb:
                res.append('1')
                continue

            if ca > cb:
                ca, cb = cb, ca
                a, b = b, a

            g = gcd(cyc_len[ca], cyc_len[cb])
            key = (ca, cb)

            if key in store:
                delta = (pos[a] - pos[b]) % g
                res.append('1' if delta in store[key] else '0')
            else:
                res.append('0')

        out_lines.append(''.join(res))

    print('\n'.join(out_lines))

if __name__ == "__main__":
    solve()
```コードは、順列をサイクルに分解し、各ノードにサイクル ID とそのサイクル内のインデックスを割り当てることから始まります。 この表現により、時間発展をモジュラー演算に還元することができます。 

の`add_edge`関数は、元の円上の各隣接関係を処理します。 各サイクル ペアが単一の正規キーを持つようにサイクル順序を正規化し、サイクル長の gcd を計算し、観測された剰余を保存します。 これは隣接情報が記録される唯一の場所です。 

クエリ中に、両方のノードが同じサイクル内にある場合、単一サイクルが時間の経過とともにすべての状態を均一にカバーするため、隣接関係は簡単に達成できます。 それ以外の場合は、必要な剰余を計算し、事前計算されたセットのメンバーシップをチェックします。 

## 実用的な例

 順列が円のエッジを通じて相互作用する 2 つのサイクルに分割される小さなケースを考えてみましょう。 エッジがどのように剰余制約を引き起こすかを追跡します。 

| ステップ | エッジ (u,v) | サイクル (Cu,Cv) | g | 残基を追加 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,2) | (A、B) | 計算された | r1 |
 | 2 | (2,3) | (B、C) | 計算された | r2 |
 | 3 | クエリ (a,b) | (A、C) | ぐ | デルタ |

 この表は、各エッジがサイクル ペア制約にどのように独立して寄与するかを示しており、クエリは単にそれらの制約間に必要な位置合わせが存在するかどうかをテストします。 

これは、隣接関係がグローバル シミュレーションには依存せず、エッジによって引き起こされるローカルな制約にのみ依存することを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、クエリされた両方のフェレットが同じ順列サイクル内にある場合です。 その状況では、それらはそのサイクルの周囲を同期して移動し、サイクルのすべての状態に到達できるため、隣接性はサイクルがそれらを隣接する円の位置に配置するかどうかによってのみ決まります。 このアルゴリズムは、サイクル識別子が一致する場合に直ちに true を返すことでこれを処理し、不必要な gcd 計算を回避します。 

2 つのサイクルを接続する円のエッジがない場合、別の微妙なケースが発生します。 これは、それらの間に隣接関係の制約が存在しないことを意味するため、同期は不可能です。 アルゴリズムは、マップ内にサイクル ペア キーが存在しないことを確認することで、これを正しく処理します。 

最後のエッジ ケースは、次のようなラップアラウンド隣接関係です。$n$そして$1$。 円を線形として扱うと、この接続が完全に失われますが、アルゴリズムにはこのエッジが明示的に含まれており、制約構造が完全であることが保証されます。
