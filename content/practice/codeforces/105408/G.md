 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、非常に具体的な構造特性を検証するように求められます。リスト内のすべての数値のペアは、まったく同じ最大公約数を共有する必要があります。 言い換えれば、配列内の任意の 2 つの位置を選択し、それらの gcd を計算する場合、その値は選択したペアに依存してはなりません。 

直接の意味は、配列が高度に制約されていることです。 1 つのペアでも別のペアとは異なる gcd 値を生成する場合、構造は壊れるため、それを拒否する必要があります。 

入力サイズは 10 万要素に達する可能性があり、各値は 1,000 万に達する可能性があります。 これにより、すべてのペアを明示的に検査しようとするアプローチから遠ざけられます。$10^{10}$最悪の場合の gcd 計算は、許容される 1 秒の制限をはるかに超えています。 許容できる解決策では、問題を線形に近い値、または配列のサイズが線形に近い値にまで削減する必要があります。 

微妙な特殊なケースは、小さな値や繰り返しの要因から発生します。 たとえば、次のような配列$[2, 4, 8]$～とは異なる動作をする$[2, 3, 4]$、両方とも小さい gcd を持っていますが。 もう 1 つの注意が必要な状況は、すべての数値が共通の因数を共有しているものの、その因数が残りの素数とどのように相互作用するかが異なり、ペアごとの gcd の一貫性に影響を与える可能性がある場合です。 

たとえば、次のように考えてみましょう$[6, 10, 15]$。 3 つすべての gcd は次のとおりです。$1$ですが、ペアごとの gcd は異なります。$\gcd(6,10)=2$、$\gcd(6,15)=3$、$\gcd(10,15)=5$。 「グローバル gcd が 1 であれば十分である」という素朴な仮定はすぐに失敗します。 

もう 1 つの失敗例は、ソート後に隣接する要素をチェックすれば十分だと考えていることです。 のために$[6, 10, 15]$、ソートすると、$[6,10,15]$、隣接する gcd は$2$そして$5$、すでに異なりますが、たとえ細工されたケースによっては隣接する gcd が一致したとしても、隣接しないペアは依然として条件に違反する可能性があります。 

## アプローチ

 直接解釈すると、すべてのペアの gcd を計算し、同等性をチェックすることが示唆されます。 これは正しいですが、非常に高価です。 と$N$まで$10^5$、大まかに計算します$N(N-1)/2$gcd 操作。 各 gcd は対数であるため、これでも制限時間内では破綻します。 

重要な観察は、すべてのペアごとの gcd が同一である場合、単一の値が存在するということです。$g$要素のすべてのペアがまったく同じ gcd を共有するようにします。$g$。 これにより、強力な構造が強制されます。すべての数値は次の倍数でなければなりません。$g$、各要素を次のように分割した後、$g$、結果として得られる数値のペアは、gcd が次と等しい必要があります。$1$。 2 つの換算された数が素因数を共有する場合、それらの gcd は次の値を超えます。$1$、要件に矛盾します。 

これにより、問題は、正規化後に複数の数値に素因数が出現するかどうかを検出するように変換されます。 

まず、配列全体のグローバル gcd を計算します。 条件が true の場合、この値は共通のペアごとの gcd と等しくなければなりません。 次に、すべての要素をこの gcd で除算します。 ここで、問題は純粋に縮小された配列に関するものになります。つまり、2 つの異なる要素間で素因数が共有されないようにする必要があります。 

これは、最小の素因数のふるいによる素因数分解を使用して効率的にチェックできます。 各数値は 1 回因数分解され、どの素数がすでに出現しているかを追跡します。 複数の要素に素数が見られる場合、条件に違反します。

 ## アルゴリズムのチュートリアル

 1. 配列全体の gcd を計算し、次のように保存します。$g$。 すべてのペアごとの gcd はすべての要素を分割する必要があるため、この値は、共通のペアごとの gcd の可能な唯一の候補を表します。 
2. すべての要素を置き換える$a_i$と$a_i / g$。 これにより、強制的な共通因数が削除されるため、追加の共有構造のみに焦点を当てることができます。 
3. ふるいを使用して、配列内の最大値までの最小素因数テーブルを作成します。 これにより、各数値を高速に因数分解できます。 
4. それぞれの縮小された数値について、その個別の素因数を抽出します。 gcd が 1 より大きいかどうかは累乗を繰り返しても変化しないため、素数の多重度ではなく、素数が出現するかどうかのみを考慮します。 
5. どの素数が以前の数値ですでに使用されているかをマークするセットまたはブール配列を維持します。 
6. 素因数が複数の異なる数値に出現する場合は、すべてのペアワイズ gcd が等しいわけではないと直ちに結論付け、NO を返します。 
7. すべての数値が競合せずに処理された場合は、YES を返します。 

中心的な考え方は、等しいペアごとの gcd が正規化後に素数サポートの素性を強制するということです。 2 つの異なる要素間で素因数が重複すると、gcd が共有ベースラインを超えるペアが直接作成され、条件が破られます。 

## なぜ機能するのか

 グローバル gcd で割った後$g$、すべての数値は、意図したターゲット構造に関して互いに素になります。 2 つの約数が素因数を共有する場合$p$、その場合、その gcd は少なくとも$p$より大きい$1$。 これは、元のペアごとの gcd が超過していることを意味します。$g$、すべてのペアごとの gcd が等しいという仮定に矛盾します。 逆に、複数の換算数に素因数が現れない場合、すべてのペアはまったく同じ gcd を共有します。$g$グローバル要素を超える追加の共通構造は存在しないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10_000_000

# smallest prime factor sieve
spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

n = int(input())
a = list(map(int, input().split()))

import math

g = 0
for v in a:
    g = math.gcd(g, v)

used = set()

for v in a:
    v //= g
    if v == 1:
        continue
    factors = factorize(v)
    for p in set(factors):
        if p in used:
            print("NO")
            sys.exit()
        used.add(p)

print("YES")
```最初のステージでは、すべての要素に対してグローバル gcd を計算します。 これにより、条件が成立する場合に存在する必要がある最小限の共通構造が固定されます。 

ふるいは素早い因数分解を準備します。これは不可欠です。なぜなら、試行除算を繰り返すと 10 万の数値に対して遅すぎるからです。 

各数値はグローバル gcd によって減算され、その後、その主要なサポートが抽出されます。 数値ごとに素数のセットを使用すると、累乗を繰り返すことで誤って競合が引き起こされなくなります。 

グローバルな`used`set は、各素数が最大でも 1 つの縮小された数に現れることを保証し、有効な配列を特徴付ける素数条件を強制します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXV = 10_000_000
    spf = list(range(MAXV + 1))
    for i in range(2, int(MAXV ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXV + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factorize(x):
        res = []
        while x > 1:
            p = spf[x]
            res.append(p)
            while x % p == 0:
                x //= p
        return res

    import math

    n = int(input())
    a = list(map(int, input().split()))

    g = 0
    for v in a:
        g = math.gcd(g, v)

    for v in a:
        v //= g
        if v == 1:
            continue
        for p in set(factorize(v)):
            if p in used:
                return "NO"
            used.add(p)

    return "YES"

 ## 特殊なケース

 すべての要素が同一である配列の場合、グローバル gcd は要素自体に等しく、リダクション後はすべての値が 1 になります。素数が残っていないため、競合は発生せず、アルゴリズムは正しく YES を返します。 

のような配列の場合$[6, 10, 15]$、グローバル gcd は 1 であるため、削減は行われません。 素数セットは異なるペアを通じて間接的に重複しますが、実際には、最初に検出された反復素数はすぐに一意性条件に違反し、正しく NO が生成されます。 

多くの 1 を含む配列の場合、これらはリダクション後に素因数に寄与しません。 それらは追跡構造に干渉せず、配列の大部分が gcd 構造に関して中立である場合でも正確性を保証します。
