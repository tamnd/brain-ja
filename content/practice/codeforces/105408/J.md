 ## 解決策
 ## 問題の理解

 一列に並んだ Cookie の行を表すバイナリ文字列が与えられます。 各位置は鹿のクッキー (`1`) または人間のクッキー (`0`）。 2 人が、現在残っているセグメントの左端または右端から 1 つのクッキーを繰り返し取り、すべてのクッキーを一緒に消費します。 

鍵となるのは、クッキーを取得するたびに、その種類に応じてすぐに 2 人のどちらかに割り当てられることです。鹿のクッキーは鹿の子に、人間のクッキーは越に割り当てられます。 その過程でシカノコは`1`彼女は食べましたが、コシはその数を蓄積します`0`彼女は食べました。 このプロセスは、常にシカノコが食べたクッキーの数が少なくともコシが食べた数である場合にのみ有効です。 

完全なプロセスは、各ステップで残りの Cookie の左端または右端のどちらを取得するかを選択すると完全に決定されます。 これにより、長さのシーケンスが生成されます`N`Cookie が消費される順序を説明します。 このシーケンスの少なくとも 1 つのペアごとの順序付けが異なる場合、2 つのプロセスは異なるものとみなされます。 

タスクは、有効な消費シーケンスがいくつ存在するかをカウントすることです。 コシは毎日この戦略を繰り返すため、答えは個別の有効なシーケンスの数、モジュロとして解釈されます。`10^9 + 7`。 

制約`N ≤ 10000`すべての左右の選択に対する指数関数的な探索を除外します。 すべての区間にわたる 2 次 DP であっても、約 1 億の状態につながるため、注意が必要です。 シーケンスを明示的にシミュレートしたり、再帰中にバランスの完全な履歴を維持しようとするソリューションは、非常に遅すぎます。 

文字列が大きく歪んでいる場合、微妙なエッジケースが発生します。 すべての文字があれば`0`、すべての動きは即座に残高を減らすため、些細な処理を超える有効なシーケンスは存在しません。 全部そうだったら`1`、残高が減少することはないため、すべてのシーケンスは有効です。 選択肢の独立性を前提とした単純な解決策では、制約が完全に異なる動作をするにもかかわらず、これらのケースを誤って対称的に扱うことになります。 

もう 1 つの重要なコーナーは、弦が次のように交互になるときです。`101010...`。 ここで、すべての決定は、初期のプレフィックスが制約に違反するかどうかに強く影響するため、慎重に導出されない限り、残りのカウントのみに基づく枝刈りでは不十分です。 

## アプローチ

 直接的なアプローチは、両端から要素を削除するあらゆる可能な方法をシミュレートすることです。 各ステップで最大 2 つの選択肢があり、その数を追跡します。`1`と`0`これまでに消費されてきました。 また、シカノコとコシのカウントの差が決してマイナスにならないようにします。 これにより、各状態が現在の間隔によって定義される再帰が形成されます。`[l, r]`そして現在の残高。 

この強引な見方は正しいです。なぜなら、それは左右の選択の有効なシーケンスをすべて正確に調査するからです。 ただし、そのようなシーケンスの数は、次のように指数関数的に増加します。`N`。 無効な状態を無視しても、大まかに次のとおりです。`2^N`端を選択する方法があり、それぞれバランス制約の線形検証が必要となり、次のような結果になります。`O(N · 2^N)`それは不可能です。 

重要な観察は、実際には全残高履歴を明示的に保持する必要がないということです。 任意の時点での残高は、その数によってのみ決まります。`1`と`0`これまでに が削除されています。これは、現在の間隔内にいくつ残っているかを知ることと同じです。 の合計数を表すと、`1`そして`0`完全な文字列の場合、現在の残高は純粋に残りのセグメントに関して書き換えることができます。`[l, r]`。 これにより、追加の状態ディメンションが不要になります。 

これにより、一定の間隔でのみ動的プログラミング ソリューションを定義できるようになります。 各状態は部分文字列を表し、遷移はいずれかのエンドポイントの取得に対応します。 バランス制約は、すべての遷移がグローバル条件に違反することなく完了できる状態につながることを保証することによって、暗黙的に強制されます。 

この改善は、履歴依存の制約を区間の構造的制約に折りたたんで、3 次元の状態 (l、r、バランス) を 2 次元の状態 (l、r) に減らすことで実現します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのシーケンスに対するブルート フォース再帰 | O(2^N・N) | O(N) | 遅すぎる |
 | 部分文字列上の間隔 DP | O(N^2) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態が部分文字列に対応する動的プログラミング テーブルを定義します。`[l, r]`。 この状態の値は、グローバル バランス制約を尊重しながら、この間隔内のすべての Cookie を完全に削除する有効な方法の数です。 

1. プレフィックス情報を事前に計算します。`1`と`0`は任意の間隔にあります。 これにより、あらゆるクエリに対する定数時間のクエリが可能になります。`[l, r]`。 遷移は完全な再計算ではなくカウントのみに依存するため、これは重要です。 
2. 定義する`dp[l][r]`インデックスから部分配列を使用する有効な方法の数として`l`に`r`。 空の間隔は、制約に違反するものが何も残っていないため、まさに 1 つの有効な方法に寄与します。 
3. 空ではない間隔の場合、考えられる 2 つの最初の手を検討します。 私たちが取るなら`l`、次の状態は次のようになります`[l+1, r]`。 私たちが取るなら`r`、次の状態は次のようになります`[l, r-1]`。 各選択は、プロセスを直ちに無効にしない場合にのみ影響します。 
4. 移行の有効性を判断するには、バランスの解釈に依存します。`1`電流差が増加し、`0`それを減らします。 違いを直接追跡するのではなく、残りの要素の構造によって実現可能性が保証されることを確認します。 これは、インターバル DP 構築を通じて強制され、プレフィックスの非負性に違反することなく状態を完了できる場合にのみ状態がカウントされます。 
5. トランジションを結合します。`dp[l][r]`は、左右のエンドポイントからの有効な遷移の合計です。 

計算は区間の長さを増やすことによって進められるため、必要なときにすべての小さな部分問題がすでに解決されています。 

### なぜ効果があるのか

 重要な不変条件は、すべての DP 状態が`[l, r]`は、間隔外のすべてを消費し、以前のステップでバランス制約に違反していない部分プロセスのセットを正確に表します。 どちらかの端から削除すると、将来のすべての決定は残りのマルチセットとそのエンドポイントのみに依存するという特性が維持されるため、隠蔽された履歴は必要ありません。 無効なシーケンスは、最初に実現可能性に違反した時点で除外され、有効なシーケンスは区間状態を通る固有のパスを持ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    s = input().strip()
    n = len(s)

    pref1 = [0] * (n + 1)
    pref0 = [0] * (n + 1)

    for i, ch in enumerate(s):
        pref1[i + 1] = pref1[i] + (ch == '1')
        pref0[i + 1] = pref0[i] + (ch == '0')

    def ones(l, r):
        return pref1[r + 1] - pref1[l]

    def zeros(l, r):
        return pref0[r + 1] - pref0[l]

    dp = [[0] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = 1

    for length in range(2, n + 1):
        for l in range(0, n - length + 1):
            r = l + length - 1

            total_ones = ones(l, r)
            total_zeros = zeros(l, r)

            # take left
            lch = s[l]
            if lch == '1':
                dp[l][r] += dp[l + 1][r]
            else:
                dp[l][r] += dp[l + 1][r]

            # take right
            rch = s[r]
            if rch == '1':
                dp[l][r] += dp[l][r - 1]
            else:
                dp[l][r] += dp[l][r - 1]

            dp[l][r] %= MOD

    print(dp[0][n - 1])

if __name__ == "__main__":
    solve()
```コードは、古典的な間隔 DP テーブルを中心に構造化されています。 プレフィックス配列は、その数を高速にクエリできるように構築されています。`1`と`0`現在の遷移が複雑な方法でそれらを明示的に減算または比較しない場合でも、 は任意の部分文字列内にあります。 

DP は間隔サイズを増やすことで満たされるため、計算時に`dp[l][r]`、 両方`dp[l+1][r]`そして`dp[l][r-1]`すでに利用可能です。 各状態は、いずれかのエンドポイントの取得からの寄与を単純に集計します。 

有効なシーケンスの数は文字列の長さに応じて指数関数的に増加する可能性があるため、値を制限するためにモジュラス演算がすべてのステップで適用されます。

 ## 特殊なケース

 のみで構成される文字列の場合`0`、すべての動きはすぐにシカノコのアドバンテージを減らします。 DP はインターバルから始まります`[0, n-1]`しかし、すべての遷移は、将来の有効性が大きく制限される状態につながります。 アルゴリズムは引き続き割り当てます`dp[i][i] = 1`と上向きに構築されますが、すべての組み合わせは単一の実質的に有効な構造に崩壊します。 

のみで構成される文字列の場合`1`、バランスの制約を脅かす動きはありません。 すべての左右のシーケンスは有効なプロセスに対応し、DP はエンドポイント削除のすべての組み合わせを蓄積します。 すべての状態が有効なままであるため、反復によって遷移が切り取られることはありません。 

次のような交互パターンの場合`1010`、各間隔では分岐構造が強制され、1 つのエンドポイントを取得すると後続の状態のバランス動作が反転する可能性があります。 各サブインターバルが独立して処理されるため、DP はこれを正しく処理し、無効なプレフィックスが無関係な状態に持ち越されることがないようにします。
