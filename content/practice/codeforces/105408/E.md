 ## 解決策
 ## 問題の理解

 重み付けされた無向の接続された都市のグラフが与えられます。 Jorge は都市 0 に住んでいます。各エッジは正の長さの道路を表し、最短パスは 2 つの都市間の距離を定義します。 

ホルヘには k 人の友人がいて、各友人は独立して別の都市を占有しています。 彼らがどの都市を占領しているのかは明かされていない。 代わりに、残りの n − 1 都市から k 個の異なる都市の考えられるすべての選択肢を、すべて同じ確率で考慮します。 このような選択ごとに、最短経路を使用して都市 0 から選択した各都市までの距離を計算し、それらの k 個の距離の最小値を取得します。 タスクは、この最小距離の期待値を計算することです。 

主な困難は、独立した距離を合計するのではなく、非線形統計、つまりランダムなサブセットの最小値を平均していることです。 

この制約により、ほぼ線形なグラフの解決策が求められます。 n が最大 100000、m が最大 1e6 であるため、選択肢ごとに最短パスを再計算するアプローチは不可能です。 すべてのペアごとの距離を保存することすら不可能です。 ソース 0 からのすべての距離を一度計算してから、並べ替えられた値を組み合わせて推論する必要があります。 

複数の都市が 0 からの同じ最短距離を共有する場合、微妙なエッジ ケースが発生します。たとえば、複数の都市が距離 5 にある場合、最小値の確率構造は段階的に変化し、等しい距離を適切にグループ化しないと、個々の都市の単純な平均化は失敗します。 もう 1 つのエッジ ケースは、k が n − 1 に非常に近い場合です。その領域では、最小値はほぼすべてのノード間の最小距離であることがほぼ確実で、特に最小値に影響を与えない最も遠いノードについては、組み合わせ確率が引き続き正しく動作する必要があります。 

## アプローチ

 ブルートフォース解釈では、n − 1 の中の k 都市のすべてのサブセットを列挙し、各サブセットの最小距離を計算し、結果を平均します。 最短経路の計算を無視しても、サブセットの数は$\binom{n-1}{k}$、これは中程度の n の場合でも天文学的に大きくなります。 これにより、直接の列挙が即座に除外されます。 

まず、グラフ コンポーネントを組み合わせコンポーネントから分離します。 都市 0 から他のすべての都市までの距離は、ダイクストラのアルゴリズムを使用して計算できます。$O(m \log n)$。 その後、問題は純粋に確率論的になります。n − 1 個の距離の配列が与えられた場合、置換せずに k 個の要素を均一に選択し、期待される最小値を求めます。 

重要な観察は、生存確率の観点から期待を再構成することです。 最小値が何かを直接尋ねる代わりに、最小値が少なくともしきい値 d である確率を考慮します。 これは、選択された k 個の都市すべてが距離 ≥ d の都市に含まれる場合に正確に発生します。 すべての距離を並べ替えると、距離 ≤ d を持つ都市の数のプレフィックス数を計算でき、そこから距離 ≥ d を持つ都市の数を導き出すことができます。 

これにより、期待値がソートされた一意の距離の合計に変換され、最小値がその値に等しい確率に従って各値が寄与します。 この確率は組み合わせを使用して表現されます。しきい値よりも近いノードのセットの外側にある k 個の都市をすべて選択する方法の数を数え、同様に次のしきい値を減算します。 全体の構造は、ソートされた距離にわたる接頭辞の組み合わせに帰着します。

 ## アルゴリズムのチュートリアル

 ソリューションをグラフ前処理フェーズと組み合わせ予想フェーズに分割します。 

1. 都市 0 からダイクストラを実行して、すべての都市までの最短距離を計算します。 

これが必要なのは、その後のすべての計算がこれらの距離のみに依存し、最短距離を超えるパス構造は、それらが計算されると無関係になるためです。 
2. 都市 0 は送信元であり、フレンド都市として選択できないため、検討から削除します。 
3. すべての距離を配列に保存し、降順でない順に並べ替えます。 

ランダムなサブセットの最小値は、最小値から最大値までのしきい値の観点から推論するのが最も簡単であるため、並べ替えが必要です。 
4. 1e9+7 を法とする二項係数について最大 n までの階乗および逆階乗を事前計算します。 

高速な計算が必要です$\binom{a}{b}$なぜなら、確率はサブセットの数え方に依存するからです。 
5. b > a の場合は 0 を返し、そうでない場合は計算する関数 C(a, b) を定義します。$\frac{a!}{b!(a-b)!}$。 

この関数は確率式で繰り返し使用されます。 
6. ソートされた距離配列内の各インデックス i を反復処理し、dist[i] を最小値が最初に現れる候補値として扱います。 

固定 i の場合、最小値が dist[i] と正確に等しいサイズ k のサブセットがいくつあるかを計算します。 
7. i+1 を距離 ≤ dist[i] の都市の数とする。 厳密にこのしきい値以下の都市の数によって、dist[i] を最小値として無効にする選択肢の数が決まります。 
8. インデックス i..n-1 (距離 ≥ dist[i] を持つすべての都市) から k 都市を選択する方法の数を計算します。 

これは C(n-1 - i, k) です。 
9. インデックス i+1..n-1 から k 都市を選択する方法の数を減算します。これは、最小値が厳密に dist[i] より大きいサブセットに対応します。 

これにより、dist[i] が正確に最小値となるサブセットの数が得られます。 
10. この確率の重みに dist[i] を乗算し、累積して最終的な答えを求めます。 

### なぜ効果があるのか

 このアルゴリズムは、都市 0 からの最小距離に従って、都市のすべての k サブセットを分割します。すべてのサブセットには、ソート順に最小要素が 1 つだけあり、組み合わせの差分 C(n-1 - i, k) − C(n-1 - i-1, k) は、ソート順で最初に選択された要素が位置 i であるサブセットを正確にカウントします。 これにより、各サブセットが 1 つの距離バケットに 1 回だけ寄与することが保証されるため、加重合計は最小距離の期待値と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def dijkstra(n, adj):
    import heapq
    dist = [10**30] * n
    dist[0] = 0
    pq = [(0, 0)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def modinv(x):
    return pow(x, MOD - 2, MOD)

def nCk(n, k, fact, invfact):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

def solve():
    n, m, k = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(m):
        a, b, w = map(int, input().split())
        adj[a].append((b, w))
        adj[b].append((a, w))

    dist = dijkstra(n, adj)
    arr = dist[1:]
    arr.sort()

    maxn = n + 5
    fact = [1] * maxn
    invfact = [1] * maxn
    for i in range(1, maxn):
        fact[i] = fact[i - 1] * i % MOD
    invfact[maxn - 1] = modinv(fact[maxn - 1])
    for i in range(maxn - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    total = nCk(n - 1, k, fact, invfact)

    ans = 0
    n1 = n - 1

    for i, x in enumerate(arr):
        if n1 - i < k:
            continue
        # subsets where minimum >= x
        ge = nCk(n1 - i, k, fact, invfact)
        # subsets where minimum > x
        if i + 1 <= n1:
            gt = nCk(n1 - (i + 1), k, fact, invfact)
        else:
            gt = 0
        cnt = (ge - gt) % MOD
        ans = (ans + cnt * x) % MOD

    inv_total = modinv(total)
    print(ans * inv_total % MOD)

if __name__ == "__main__":
    solve()
```実装は、隣接リストを構築し、ダイクストラとヒープを使用して単一ソースの最短パスを計算することから始まります。 これにより、確率段階に必要なすべての距離が生成されます。 

二項係数が繰り返し必要になるため、階乗配列と逆階乗配列は一度だけ事前計算されます。 逆モジュラーはフェルマーの定理を使用して計算されます。モジュラスが素数であるため安全です。 

配列`arr`ノード 0 から他のすべてのノードまでの距離が含まれており、しきい値を推論できるようにソートされています。 ポジションごとに`i`、最小値が次と正確に等しい k サブセットがいくつあるかを計算します。`arr[i]`2 つの二項カウントの差を使用します。 これにより、サブセットを明示的に追跡することが回避されます。 

最後に、逆モジュラーを使用して、累積された加重合計を k サブセットの総数で除算し、期待値を生成します。 

よくある実装上の落とし穴は、都市 0 が選択プールから除外されていることを忘れることです。 もう 1 つは、グループ化せずに等距離を誤って扱っていることです。 組み合わせの差の定式化により、この問題は自動的に回避されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、k = n − 1 の場合です。その状況では、すべてのノードが選択されるため、最小値は常に最小距離になります。 C(n − 1 − i, k) が最初のインデックスを除くすべての i についてゼロになり、寄与する最小距離のみが残るため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、距離が繰り返される場合です。 複数のノードが同一の最短パス値を持っていると仮定します。 各ノードを独立して扱う単純なアプローチでは、確率質量が 2 倍にカウントされますが、減算式 C(n − 1 − i, k) − C(n − 1 − i − 1, k) は、等しい値を自動的に正しい周波数重み付け寄与にまとめます。 

最後のエッジ ケースは k = 1 です。その場合、答えは単純にすべての最短パス距離の平均になります。 各ノードが等しい確率で選択され、組み合わせの差がすべての距離にわたって均一な重み付けに減少するため、アルゴリズムは正しく縮退します。
