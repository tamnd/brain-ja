 ## 解決策
 ## 問題の理解

 私たちは本のコレクションを与えられました。 各本には 3 つの属性があります。それは、ページ数、コナーにとってどれだけ楽しいか、読み終えた場合にどれだけの名声が得られるかです。 本を読むには、ページ数に比例して一定の時間がかかります。具体的には 1 ページあたり 3 分です。 

コナーは 1 日以内に本を読むことしかできません。最終的に重要なのは、利用可能な時間枠内に本を読み終えることができるかどうかです。 彼はすべての本から、完全に完成した本の一部を選択し、2 つの目的を独立して扱いながら、総合的な楽しみか総合的な名声のいずれかを最大化したいと考えています。 両方の可能な限り最高の合計を計算した後、それらを比較し、楽しみと名声のどちらの動機が優勢であるかを決定します。 

声明では借用のルールと時間枠について言及していますが、本質的な制約は 1 日の合計読書制限に減ります。 各ページにかかる時間は同じであり、本は完全に完成した場合にのみ役に立ちます。この問題は、ページに等しい重みと、喜びまたは名声に等しい価値を持つアイテムの選択問題になります。 

この制約の主な意味は、それぞれ最大 1000 ページの書籍を最大 1000 冊処理する必要があるということです。 サブセットを直接列挙するには、最大 2^1000 の組み合わせをチェックする必要がありますが、これは不可能です。 時間制限によって引き起こされる容量は多項式解を可能にするのに十分小さいため、総ページにわたる動的プログラミング ソリューションは自然な方向です。 

すべての書籍が制限内に収まる場合と、少数のサブセットのみが制限内に収まる場合には、微妙なエッジ ケースが発生します。 もう 1 つは、最適な選択において快楽と名声の合計が等しい場合であり、これは同点として明示的に報告する必要があります。 最後に、各本を完全に読むか、まったく読まないことが重要です。部分的に読むことは許可されません。そのため、これは連続問題ではなく、古典的な 0/1 選択問題になります。 

## アプローチ

 ブルートフォース手法では、書籍のすべてのサブセットを試し、合計ページを計算し、合計時間が 1 日の制限内に収まる場合は、対応する享楽または名声の合計を計算します。 これは、すべての有効な組み合わせを直接評価するため正しいですが、すべてのサブセットに拡張され、2^N 通りの可能性が生じます。 N が 1000 までの場合、2^30 でもすでに大きすぎるため、このアプローチは完全に実行不可能です。 

より迅速なソリューションを実現する構造は、各書籍が独立して貢献し、選択肢間の唯一の関係は合計読書時間であるということです。 これはまさにナップザック問題の特徴です。各本には重み (ページ) と価値 (喜びまたは名声) があり、容量の制約の下で価値を最大化したいと考えます。 容量は、利用可能な読み取り時間の合計から算出され、同等のページ単位に変換されます。 

これにより、dp[c] が合計ページ数または最大 c までの達成可能な最大値を格納する 1 次元動的プログラミング配列を使用できるようになります。 各書籍は 1 回処理され、同じ書籍が複数回再利用されるのを避けるために配列が逆方向に更新されます。 

これを 2 回計算します。1 回目は快楽値を使用し、もう 1 回目は名声値を使用します。 最終的な比較は簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N・N) | O(N) | 遅すぎる |
 | 0/1 ナップザック DP | O(N・C) | O(C) | 承認済み |

 ここで C は、その日の有効ページ容量です。 

## アルゴリズムのチュートリアル

1. 利用可能な合計分をページごとの読書時間で割ることにより、制限時間をページ容量に変換します。 これにより、スケジューリングの問題が純粋な重み制約の問題に変わります。 
2. 喜びのための動的プログラミング配列を構築します。ここで、dp[p] は、総ページ数が p を超えない書籍を使用して達成できる最大の合計喜びを表します。 これにより、サブセット空間が容量によってインデックス付けされた線形構造に圧縮されます。 
3. 各ブックを 1 つずつ処理し、ブックご​​とに dp 配列を高容量から低容量に更新します。 この逆の順序により、どの組み合わせでも各ブックが 1 回だけ使用されることが保証されます。 
4. 同じプロセスを名声に対して個別に繰り返し、2 番目の dp 配列を生成します。 
5. それぞれの dp 配列から最大の達成可能な喜びと最大の達成可能な名声を取得します。 
6. 2 つの結果を比較し、対応するラベル (楽しみが優勢、名声が優勢、またはそれらが等しい) を出力します。 

### なぜ効果があるのか

 dp 状態は常に、固定リソース予算に対して達成可能な最良の値を表します。 すべての遷移では 1 つのブックが追加されるだけであり、同じ反復内でそれが再利用されることはないため、すべてのサブセットは 1 回だけ表されます。 dp はすべての組み合わせを暗黙的に探索するため、並べ替えや順序付けは無関係です。 この正しさは、書籍の有効な選択が dp テーブル内の遷移の 1 つのパスに正確に対応し、その中で最も優れた書籍が各容量レベルで保存されるという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def knapsack(values, pages, capacity):
    dp = [0] * (capacity + 1)
    n = len(values)
    for i in range(n):
        w = pages[i]
        v = values[i]
        for c in range(capacity, w - 1, -1):
            if dp[c - w] + v > dp[c]:
                dp[c] = dp[c - w] + v
    return max(dp)

def main():
    n = int(input().strip())
    pages = list(map(int, input().split()))
    pleasure = list(map(int, input().split()))
    fame = list(map(int, input().split()))

    capacity = 260

    best_pleasure = knapsack(pleasure, pages, capacity)
    best_fame = knapsack(fame, pages, capacity)

    if best_pleasure > best_fame:
        print("PLEASURE")
    elif best_fame > best_pleasure:
        print("FAME")
    else:
        print("EITHER")

if __name__ == "__main__":
    main()
```このソリューションでは、値配列によってパラメーター化された標準の 0/1 ナップザック ルーチンを定義します。 同じ構造が両方の目的で再利用されるため、ロジックの重複が回避され、制約の一貫した処理が保証されます。 

容量に対する逆の反復が不可欠です。 前方に反復すると、同じ反復内で 1 冊の本が複数回カウントされ、問題が境界のないナップザックになってしまう可能性があります。 

容量は、1 日の閲覧制限をページ単位に換算して 260 ページに固定されます。 これにより、スケジューリングの側面全体が 1 つの制約に簡素化されます。

 入力:```

Pleasure DP は、価値の密度に応じて 200 ページの本または 100 ページの本を選択しますが、容量制限により、選択されるのは 1 つだけです。 

| ケース | 選択した本 | 楽しみ | 名声 |

この例は、実現可能なセットが同一であっても、最適なソリューションが 2 つの目的間で完全に異なる可能性があることを強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N・C) | 各ブックは、容量を超えて DP 配列を 1 回更新します。 
| スペース | O(C) | サイズ容量の 1 つの DP アレイのみが維持されます。 

N が最大 1000、C が約 260 であれば、ソリューションは制限内で快適に実行されます。 メモリ使用量は最小限であり、DP 配列を超える入力サイズに関して一定です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    pages = list(map(int, input().split()))
    pleasure = list(map(int, input().split()))
    fame = list(map(int, input().split()))

    def knapsack(values, pages, capacity):
        dp = [0] * (capacity + 1)
        for i in range(n):
            for c in range(capacity, pages[i] - 1, -1):
                dp[c] = max(dp[c], dp[c - pages[i]] + values[i])
        return max(dp)

    cap = 260
    p1 = knapsack(pleasure, pages, cap)
    p2 = knapsack(fame, pages, cap)

    if p1 > p2:
        return "PLEASURE"
    elif p2 > p1:
        return "FAME"
    else:
        return "EITHER"

# provided sample (formatted minimally consistent)
assert run("""3
50 60 40
10 20 15
8 25 10
""") == "PLEASURE"

# minimum case
assert run("""1
10
5
7
""") == "FAME"

# equal case
assert run("""2
10 10
5 5
5 5
""") == "EITHER"

# skewed values
assert run("""3
100 100 100
1 100 1
100 1 1
""") == "PLEASURE"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単行本 | 名声 | 最小限の境界動作 |
 | 同等の評価 | どちらか | タイの取り扱いの正しさ |
 | 混合支配 | 楽しみ | DP 集計の正確性 |
 | 対称ケース | 楽しみ | 複数の項目にわたる好みの集約 |

 ## 特殊なケース

 本が 1 冊しかない場合、DP 配列はその本を含めるか除外することしかできないため、アルゴリズムはその本の喜びと名声を直接比較することになります。 遷移によって基本状態 0 が単一の達成可能な値に更新されるため、ナップザックはこれを自然に処理します。 

すべての本のページ数が同じ場合、複数のサブセットが可能ですが、容量は均一に動作します。 DP は依然として、純粋に値の蓄積によってソリューションを区別し、構造によるバイアスがないことを保証します。 

喜びと名声が同じ最適な合計を生成する場合、両方の DP 実行は同じ最大達成可能なサブセット値に収束します。 最後の比較により、正しくトリガーされます。`EITHER`差が正確にゼロに収まり、等価性を超えるタイブレーク ロジックが必要ないため、出力されます。
