 ## 解決策
 ## 問題の理解

 ジョージは、タスクのリストから、それぞれに所定の利益が与えられる作業セグメントを選択することで、収益を最大化したいと考えています。 タスクは配列内に順番に配置されます`p`長さの`n`。 彼は正確に選択しなければなりません`k`重複しないセグメント、それぞれの長さ`m`。 セグメントは開始インデックスと終了インデックスによって定義されます。`[l, r]`、2 つのセグメントが重なることはできません。 The goal is to maximize the sum of profits over all selected segments.

 入力により得られるのは、`n`、`m`、 そして`k`続いて利益の数々。 出力は単一の数値です。つまり、以下から達成可能な最大の合計です。`k`重複しない長さのセグメント`m`。 

この制約は、ブルートフォースアプローチが実行不可能であることを示唆しています。 以来`n`最大5000まで上げることができ、`k*m`まで可能です`n`、すべての組み合わせを試してみます`k`セグメントには次のような操作が含まれます。`O(n^k)`、これは 1 秒の制限時間としては許容範囲をはるかに超えています。 動的プログラミングのアプローチが必要です。 エッジ ケースには、配列の最初または最後にあるセグメント、すべての利益がゼロ、またはすべての利益が等しいなどが含まれます。 たとえば、次の場合`n=5, m=2, k=1`そして`p=[1,1,1,1,1]`の場合、どのセグメントでも合計 2 が得られるため、アルゴリズムはより高い分散を仮定せずに 1 つを正しく選択する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての組み合わせが考慮されます。`k`重複しないセグメント。 これは正しいですが、計算上実行不可能です。 具体的には、最初のセグメントについて考えられるすべての開始インデックスを列挙し、次に選択肢ごとに残りのセグメントの有効な選択肢を再帰的に列挙します。`k-1`セグメント。 それぞれの選択には大まかに関係があります`n`オプションを使用すると、複雑さは O(n^k) になります。 のために`n=5000`そしてさらに`k=3`、これにより数十億の操作が発生し、遅すぎます。 

重要な洞察は、セグメントの長さが固定であるということです。`m`重複してはなりません。 長さの連続する各部分配列の合計を事前に計算できます。`m`次に、動的プログラミングを使用して、最初の投資で達成可能な最大利益を追跡します。`i`選択する配列の要素`j`セグメント。 させて`dp[i][j]`最初から最大の利益になる`i`正確に選択する場合の要素`j`セグメント。 状態遷移はポジションごとに単純です。`i`、それをスキップすることもできます（継承`dp[i-1][j]`) またはで終わるセグメントを取得します`i`（もし`i >= m`) にその合計を加算します`dp[i-m][j-1]`。 これにより、複雑さが O(n*k) に軽減され、制約の下で実現可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | お(1) | 遅すぎる |
 | 動的プログラミング | O(n*k) | O(n*k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のプレフィックスの合計を事前計算します。`p`O(1) 内の任意の部分配列の合計をすばやく計算します。 させて`prefix[i]`最初の合計を保存します`i`要素。 
2. 2D DP テーブルを初期化する`dp`サイズの`(n+1) x (k+1)`、 どこ`dp[i][j]`最初のパラメータを使用して達成可能な最大合計です。`i`要素と正確な選択`j`セグメント。 すべてのエントリを 0 に設定します。 
3. インデックスごとに`i`1から`n`で終わるセグメントの合計を計算します。`i`長さの`m`、つまり`segment_sum = prefix[i] - prefix[i-m]`もし`i >= m`。 
4. それぞれについて`j`1から`k`、 アップデート`dp[i][j]`最大 2 つの選択肢として、現在の要素をスキップする (`dp[i-1][j]`) またはで終わるセグメントを取得します`i`(`dp[i-m][j-1] + segment_sum`） もし`i >= m`。 
5. 表を埋めると、答えは次のようになります。`dp[n][k]`。 

機能する理由: DP テーブルは、配列の各プレフィックスとセグメント数で達成可能な最大利益を正確に表します。 トランジションにより、セグメントが重ならないことが保証されます。`i`、からの利益に追加するだけです。`dp[i-m][j-1]`、これはこのセグメントより前の要素に厳密に対応します。 プレフィックス合計により、一定時間のセグメント合計の計算が可能になります。 このアルゴリズムは、すべての有効なセグメント選択の最大合計を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    p = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix[i] = prefix[i-1] + p[i-1]

    dp = [[0]*(k+1) for _ in range(n+1)]

    for i in range(1, n + 1):
        for j in range(0, k+1):
            dp[i][j] = dp[i-1][j]
            if j > 0 and i >= m:
                dp[i][j] = max(dp[i][j], dp[i-m][j-1] + prefix[i] - prefix[i-m])

    print(dp[n][k])

solve()
```プレフィックス合計の計算では、セグメント合計クエリが O(m) から O(1) に変換されます。 DP テーブルは、考えられるすべてのセグメント選択が確実に考慮されるように順次更新され、インデックス付けによって重複しない制約が維持されます。`dp[i-m][j-1]`。 テーブルをゼロに初期化すると、セグメントが選択されていない場合に対処できます。

import sys, io
