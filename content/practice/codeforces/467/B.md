 ## 解決策
 ## 問題の理解

 私たちは数人のプレイヤーとゲームをすることになり、各プレイヤーはさまざまな種類の兵士で構成される軍隊を制御します。 各軍隊は非負の整数として表され、バイナリ表現は兵士タイプの存在をエンコードします。ビットが 1 に設定されている場合は、軍隊にそのタイプが含まれていることを意味します。 ヒョードルが最後のプレイヤーであり、最大で _k_ 種類の兵士の点で彼と異なる軍隊を持っている他のプレイヤーが何人いるかを判断するように求められます。 言い換えれば、ヒョードルの軍と他のプレイヤーの軍の間のハミング距離は最大でも _k_ でなければなりません。 

入力は、兵士タイプの総数である _n_、他のプレイヤーの数である _m_、およびさまざまな兵士タイプに関する友情のしきい値である _k_ で構成されます。 各軍は番号としてリストされ、最後にはヒョードルの軍も含まれます。 出力は単一の整数で、ヒョードルの潜在的な友人をカウントします。 

制約により、_n_ は最大 20、_m_ は最大 1000、_k_ は最大 _n_ になります。 _n_ ≤ 20 の場合、すべての軍隊を 20 ビットの数値として表すことができるため、個々のビットの演算が高速になります。 _m_ の上限は、他の各プレーヤーを個別に検査できることを意味します。 ビット単位の演算を使用して各選手をヒョードルと比較する素朴なアプローチでは、最大 20 × 1000 = 20,000 のビット チェックが実行されますが、これは制限時間内に十分収まります。 エッジケースには、ヒョードルの数と同じ軍隊のみが含まれる _k_ = 0 の場合と、違いに関係なくすべてのプレーヤーが友達である _k_ = _n_ の場合が含まれます。 

不注意な実装では、バイナリ表現ではなく 10 進数を直接比較しようとしたり、文字列ベースのバイナリ比較を使用したりする可能性があります。 たとえば、ヒョードルの軍隊が 15 (2 進数で 1111) で、別のプレーヤーが 14 (2 進数で 1110) である場合、単純な 10 進数の比較では、ちょうど 1 つのタイプが異なることを見逃してしまいますが、これは _k_ ≥ 1 の場合に許可されます。 

## アプローチ

 最も簡単な解決策は総当たりです。最初の _m_ 人の各プレーヤーについて、自分の軍隊とヒョードルの軍隊の間で異なるビットの数を計算します。 これは、2 つの数値のビット単位の XOR を計算し、結果内の 1 の数をカウントすることと同じです。 各 1 は軍隊が異なる兵士の種類に対応します。 カウントが最大 _k_ の場合、友情カウンターをインクリメントします。 

この総当り攻撃が機能するのは、最大ビット長 _n_ が小さいため、プレーヤーごとに異なるビットをカウントするのが低コストであるためです。 事前計算や組み合わせ最適化などのより高度なテクニックは必要ありません。 実装を簡素化する重要な洞察は、XOR 演算を使用することです。これにより、さまざまな兵士の種類を数える問題が、単一の整数の 1 を数える問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m × n) | お(1) | 承認済み |
 | 最適 | O(m × n) | お(1) | 承認済み |

 ここでの「最適」は基本的にブルートフォースと同じですが、XOR 演算とビットカウントをクリーンで効率的な実装方法として認識していることが洞察です。 

## アルゴリズムのチュートリアル

 1. 入力から整数 _n_、_m_、および _k_ を読み取ります。 これらは、兵士のタイプの数、他のプレイヤーの数、および友情の最大許容差を定義します。 
2. 次の _m + 1_ 行を軍隊を表す整数の配列に読み取ります。 この配列の最後のエントリはヒョードル軍です。 
3. カウンタの初期化`friends = 0`潜在的な友達を追跡するため。 
4. 最初の _m_ 軍のそれぞれについて、ヒョードルの軍とのビットごとの XOR を計算します。 これにより、1 に設定された各ビットが両軍間で異なる兵士のタイプを表す整数が生成されます。 
5. XOR 結果内の 1 の数を数えます。 これは、組み込みの`bin(x ^ y).count('1')`Pythonで。 このカウントが _k_ 以下の場合、`friends`カウンタ。 
6. 他のすべてのプレーヤーを繰り返し処理した後、`friends`カウンタ。 

機能する理由: XOR は、軍隊が異なる兵士のタイプを正確に分離します。 XOR 結果の 1 をカウントすると、ハミング距離が得られます。 友情は最大 _k_ 個の違いがあることによって定義されるため、この数を _k_ と比較することで、潜在的な友達を正確に識別できます。 すべてのプレイヤーは独立して考慮され、近似は含まれないため、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
armies = [int(input()) for _ in range(m + 1)]
fedor = armies[-1]

friends = 0
for i in range(m):
    diff = bin(armies[i] ^ fedor).count('1')
    if diff <= k:
        friends += 1

print(friends)
```このソリューションはまず、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`より大きな _m_ を処理するため。 軍隊の値は簡単にアクセスできるようにリストに保存されており、ヒョードルの軍隊は最後の要素としてアクセスされます。 このループは最初の _m_ 人の選手に対してのみ反復され、ヒョードルと彼自身を比較しないようにします。 XOR 演算は、差分をキャプチャし、次の方法でビットをカウントするための簡潔な方法を提供します。`bin(...).count('1')`Python の組み込みバイナリ表現を利用します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m × n) | m 選手のそれぞれが XOR を使用して n ビットまでカウントしてヒョードルと比較されます。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, k = map(int, input().split())
    armies = [int(input()) for _ in range(m + 1)]
    fedor = armies[-1]
    friends = 0
    for i in range(m):
        if bin(armies[i] ^ fedor).count('1') <= k:
            friends += 1
    return str(friends)

# provided sample
assert run("7 3 1\n8\n5\n111\n17\n") == "0", "sample 1"

# minimum input
assert run("1 1 1\n1\n1\n") == "1", "minimum input"

# all equal armies
assert run("5 3 5\n31\n31\n31\n31\n") == "3", "all equal"

# maximum difference allowed
assert run("4 2 4\n1\n2\n15\n") == "2", "maximum difference"

# no friends
assert run("3 2 0\n1\n2\n3\n") == "0", "no friends"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 7 3 1 … | 0 | 提供されたサンプル |
 | 1 1 1 … | 1 | 最小入力サイズ |
 | 5 3 5 … | 3 | すべての軍隊は同一です、k = n |
 | 4 2 4 … | 2 | k | によって許容される最大差
 | 3 2 0 … | 0 | k = 0、同一の軍隊のみがカウントされます |
