 ## 解決策
 ## 問題の理解

 整数の長いシーケンスが与えられ、そこから部分シーケンスを選択することができます。 目標は、サブシーケンスの長さを最大化することだけではなく、選択した要素がどのように繰り返されるかについて非常に具体的な構造的制約を課すことです。 

構築されたシーケンスの長さは 4 で割り切れる必要があります。 連続する 4 つの要素のブロックにグループ化する場合、各ブロックには、最初と 3 番目の要素が等しく、2 番目と 4 番目の要素が等しいパターンがなければなりません。 したがって、すべてのブロックは次のようになります`x, y, x, y`、元の配列からすべての要素を順番に選択することを除いて、異なるブロックは互いに独立しています。 

この形式の可能な限り長いシーケンスをサブシーケンスとして必要とします。 

入力サイズは最大 500,000 要素になるため、ペアを列挙したり、二次形式で明示的にサブシーケンスを構築しようとするソリューションはすぐに失敗します。 この構造は、繰り返しの値を選択し、それらを制約されたパターンで組み合わせていることを示唆しているため、重要な問題は、有効な値の数を数えることです。`x, y`順序を尊重しながら繰り返しを形成できます。 

微妙な失敗例は、再利用を適切に追跡しない貪欲なペアリングによって発生します。 たとえば、`1 2 1 2 1 2`、貪欲に形を作りたくなる。`(1,2,1,2)`ただし、ペアの使用方法によっては、単純なアプローチではオカレンスを過剰に使用するか、ブロック全体で最適なペアを再利用できない可能性があります。 

もう 1 つのエッジ ケースは、値が何度も出現するが、ペアの選択が競合する場合に発生します。 たとえば、`1 1 1 1 1 1`不注意なペアリング戦略は、最適なソリューションが繰り返し形成されるだけであっても、初期のペアリングを交互に実行し、その後のより良い組み合わせをブロックする可能性があります。`(1,1,1,1)`ブロック。 

## アプローチ

 強引な解釈では、部分シーケンスを段階的に構築しようとし、位置のペアごとにそれらを一致させるかどうかを決定します。`(x, y, x, y)`要素をブロックまたはスキップします。 各要素が複数の潜在的な組み合わせに参加する可能性があり、早期に決定することが後のすべての可能性に影響を与えるため、これはすぐに指数関数的になります。 

もう少し良い単純なアイデアは、2 つの値を固定することです。`x`そして`y`、配列を貪欲にスキャンして、できるだけ多くの抽出を行います。`x, y, x, y`可能な限りのパターン。 すべての値のペアに対してこれを実行すると、最大で`O(n)`異なる価値観と潜在的に`O(n^2)`ペア。 

重要な観察は、答えの構造は値そのものではなく、値のペアの出現のみに依存するということです。 各ブロックは次の 2 つのオカレンスを消費します。`x`そして、次の 2 つの発生`y`。 したがって、固定ペアについては`(x, y)`、ブロックの最大数は、出現を順番に一致させることができる回数によって異なります。 これにより、問題はシーケンス内のペアリングの発生に限定されます。 

すべてのペアを明示的にテストする代わりに、すべての有効なブロックが 2 つの値の選択に対応するという事実を利用できます。`x`そして`y`そしてそれらの出現を順番に貪欲に組み合わせます。 標準的な方法は、値ごとに位置のリストを維持し、2 つのリストをどのくらいの頻度でインターリーブできるかを検討することです。 

より深い洞察は、最適な構築は有効なペアを繰り返し抽出することに帰着するということです。`(x, y)`次の 2 つの出現を見つけることができるように、`x`そしてそのうちの2つ`y`インデックスの順序を昇順にして、それらの出現を将来の考慮事項から削除します。 この構造は、素の一致するインデックスのペアを繰り返し形成し、それらのペアを再度ペアにすることと同じです。 

これにより、利用可能な未使用の位置を維持し、同じ値のペアを順番に繰り返し構築し、ペアをブロックに結合する、オカレンスに対する貪欲なプロセスが発生します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各値のすべてのインデックスを昇順にグループ化します。 各値は、それが表示される位置のリストに貢献します。 これにより、ペアを形成するときに各値を独立して扱うことができます。 
2. すべての値について、その出現を一度に 2 つずつ繰り返し取得し、候補ペアを形成します。 このような各ペアは、最終構築における潜在的なエンドポイントを表します。 
3. このようなペアをすべてグローバルに収集し、最初の出現インデックスでソートします。 これらのペアは、サブシーケンスの順序を維持する使用可能な「エッジ」を表します。 
4. 次に、各ペアをトークンとして扱います。 2 つのトークンのシーケンスを形成したい`(x, y)`2 つのトークンを見つけることができるように、`x`そして2つのトークン`y`、順序制約を尊重します。 
5. これらのペア トークンを順番にスキャンし、長さ 2 のチェーンを形成しようとする貪欲な構造を維持し、使用状況をマークします。 
6. 2 つのペアのマッチングに成功するたびに、`x`そして2組の`y`順番にブロックを出力します`x, y, x, y`。 
7. 有効な組み合わせがなくなるまで続けます。 

重要な推論ステップは、元のシーケンスを再利用可能なペア単位に圧縮し、それらをインデックスの昇順で貪欲にマッチングしていることです。 これにより、実現可能性の制約を維持しながら、グローバルな組み合わせ検索が回避されます。 

### なぜ効果があるのか

 各有効なブロックには、2 つの等しい値のペアを形成する 4 つの出現が必要です。 等価制約により同一の値の再利用が強制されるため、あらゆる解は等しい値の素のペアに分解できます。 出現が最適な順序でペアになったら、残る唯一の自由は、これらのペアをどのようにグループ化するかです。`(x, y)`ブロック。 貪欲な構造により、互換性のある 2 つのペアが順番に存在する場合は常に、それ以降のブロックはすべて、シーケンスの後の残りの未使用の出現にのみ依存するため、それらを使用しても将来のより優れたソリューションをブロックすることができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = {}
    for i, v in enumerate(a):
        pos.setdefault(v, []).append(i)

    pairs = []
    for v, lst in pos.items():
        for i in range(0, len(lst) - 1, 2):
            pairs.append((lst[i], lst[i+1], v))

    pairs.sort()

    used = [False] * len(pairs)

    res = []

    j = 0
    m = len(pairs)

    while j < m:
        if used[j]:
            j += 1
            continue

        i1, i2, v1 = pairs[j]
        used[j] = True

        k = j + 1
        while k < m and used[k]:
            k += 1

        if k == m:
            break

        j1, j2, v2 = pairs[k]
        used[k] = True

        res.extend([v1, v2, v1, v2])

        j = k + 1

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```コードはまず、各値を互いに素な隣接するインデックスのペアに圧縮します。 これにより、同じオカレンスを 2 回再利用することがなくなります。 最初のインデックスによる並べ替えでは、サブシーケンスの順序制約が保持されます。 

次に、貪欲ループは、最も古い利用可能なペアを繰り返し選択し、それを次に利用可能なペアと照合します。 一致が成功するたびに、有効な 1 つだけが生成されます`x, y, x, y`ブロック。 の`used`配列により、各出現ペアが最大 1 回使用されることが保証されます。 

微妙な点は、次の候補を検索するときにすでに使用されているペアをスキップすることです。 これがないと、アルゴリズムが誤ってペアを 2 回再利用したり、順序の一貫性が崩れたりする可能性があります。

 ## 特殊なケース

 1 つの故障モードは、値が奇数回出現することに起因します。 例えば、`1 1 1`複数の使用可能なペアを提供することはできず、残ったペアは無視する必要があります。 位置を 2 つずつグループ化するペアリング ステップでは、余分なオカレンスが自動的に破棄され、無効な再利用が確実に行われません。 

もう 1 つのケースは、ペアは存在するが、インデックス順に適切にインターリーブされていない場合です。 例えば、`1 2 1 3 2 3`値全体にわたる順序制約を尊重する必要があります。 最初の出現順にペアを並べ替えると、連続して使用可能なペアを選択するときに、サブシーケンスの順序に違反しないことが保証されます。 

最後のエッジケースは、ペアが 1 つだけ存在する場合です。 この場合、一致する 2 番目のペアは存在せず、使用可能なパートナー ペアがなくなるとループが終了するため、アルゴリズムは長さ 0 を正しく出力します。
