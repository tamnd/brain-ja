 ## 解決策
 ## 問題の理解

 もともといくつかの順列を連結したものであるシャッフルされた配列が与えられています。 各順列のサイズは異なる場合があります。 連結後、すべての数値が混在したため、元のグループ分けが消えてしまいました。 

私たちのタスクは、各グループが有効な順列を形成するように、すべての配列要素を何らかの順列に割り当てることです。 有効なサイズの並べ替え`k`～からのすべての整数が含まれます`1`に`k`まさに一度。 

たとえば、グループに次のものが含まれている場合、`{1,2,3,4}`、順列です。 含まれている場合`{1,2,4}`、そうではありません。`3`が欠けています。 含まれている場合`{1,1,2}`、重複のため無効です。 

入力ではシャッフルされた数字のみが得られます。 有効なグループを再構築するか、そのような分解が存在しないことを報告する必要があります。 

制約`n ≤ 10^5`二次関数はすぐに除外されます。 すべての既存のグループを繰り返しスキャンしてすべての番号を取得するソリューションは、次のようなパフォーマンスを発揮します。`10^10`制限時間を大幅に超えた最悪の場合の作戦。 線形に近いものが必要です。`O(n log n)`。 

難しいのは、どのような条件が分解を可能にするのかを理解することです。 

値を仮定します`x`表示されます`cnt[x]`回。 を含むすべての順列`x`次のすべての数字も含める必要があります`1`に`x-1`。 つまり:

 - を含む順列の数`x`等しい`cnt[x]`。 
- それらの同じ順列には以下も含まれている必要があります`1,2,...,x-1`。 

したがって、カウントは次の条件を満たす必要があります。```
cnt[1] ≥ cnt[2] ≥ cnt[3] ≥ ...
```この単調性がどこかで崩れると、再構成は不可能になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
3
2 2 1
```のコピーが 2 つあります`2`, したがって、以下を含む 2 つの順列が必要になります。`2`。 しかし、以下を含むすべての順列は、`2`も含まれている必要があります`1`。 一つしかないので`1`、答えは不可能です。 

もう一つの危険なケースは次のとおりです。```
5
1 3 1 2 2
```カウントは次のとおりです。```
cnt[1] = 2
cnt[2] = 2
cnt[3] = 1
```これは有効です。 考えられる分解の 1 つは次のとおりです。```
(1,2,3)
(1,2)
```数値を恣意的に配置する不注意で貪欲な戦略は、有効な解決策が存在する場合でも、グループ内に重複した値を作成して失敗する可能性があります。 

最小のケースも重要です。```
1
1
```これはすでに有効なサイズの並べ替えです`1`。 

しかし：```
1
2
```を含む順列は存在しないため、不可能です`2`も含まずに`1`。 

## アプローチ

 ブルートフォースアプローチでは、順列を 1 つずつ明示的に構築しようとします。 配列内のすべての数値について、既存のグループをすべてスキャンして、その値がまだ含まれていないグループに配置することができ、後で有効な順列になる可能性があります。 

唯一の要件は各順列内の一意性と、より小さい値の存在であるため、これは概念的に機能します。 しかし、実装にはすぐに費用がかかります。 まであれば`10^5`グループ化して要素ごとに多数をスキャンすると、複雑さが増します。`O(n^2)`。 

順列の構造により、より強力な特性が得られます。 

順列に次のものが含まれる場合`x`の場合、すべての小さな正の整数が含まれている必要があります。 これは、以下を含む順列のセットを意味します。`x+1`は常に、以下を含むセットのサブセットです。`x`。 

これにより、問題はカウント条件に変わります。 

値を仮定する`x`表示されます`k`回。 それではまさに`k`順列には次のものが含まれている必要があります`x`。 すべての順列には次のものが含まれるため、`x+1`も含まれています`x`、次のものが必要です。```
cnt[x] ≥ cnt[x+1]
```この条件がすべての値に当てはまれば、構築は簡単になります。 

正確に作成できます`cnt[1]`順列。 次に、すべての値について`x`、その出現を最初のものに分配します。`cnt[x]`順列。 カウントは増加しないため、どのような並べ替えでも受信できます。`x`より小さい値はすべて以前にすでに受信しています。 

この貪欲な割り当ては、有効性を保証するのに十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、すべての値の頻度を数えます。 

させて`cnt[x]`value の出現数になります`x`。 
2. 周波数が増加していないかどうかを確認します。 

あらゆる人にとって`x > 1`、 確認する：```
cnt[x] ≤ cnt[x-1]
```これが失敗した場合は、印刷してください`-1`。 

その理由は構造的なものです。 を含むすべての順列`x`も含まれている必要があります`x-1`、したがって、これ以上コピーすることはできません`x`のコピーよりも`x-1`。 
3. 作成する`cnt[1]`順列。 

すべての有効な置換には次のものが含まれている必要があります。`1`, したがって、順列の数は強制的に 1 の数と等しくなります。 
4. オカレンスを貪欲に割り当てます。 

それぞれの値について`x`、その出現を順列間で分散します。`1`を通して`cnt[x]`。 

具体的に言うと、`x`3 回出現すると、それらを順列に割り当てます`1`、`2`、 そして`3`。 
5. 元の配列順序に対する答えを生成します。 

配列がシャッフルされたため、出現ごとに個別に代入する必要があります。 すべての値の順列 ID のキューを保存します。 元の配列を走査するときに、対応するキューから 1 つの ID をポップします。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです。```
If permutation p receives value x, then it has already received every value from 1 to x-1.
```値は昇順に処理されるため、これは当てはまります。`x`最初のものにのみ割り当てられます`cnt[x]`順列。 以来：```
cnt[x] ≤ cnt[x-1]
```それらの順列はすでに受け取られています`x-1`。 

各順列は最終的に正確に次のものを含みます。```
1,2,...,k
```一部の人にとっては`k`、これはまさに有効な順列です。 

## Python ソリューション```python
import sys
from collections import defaultdict, deque

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    freq = defaultdict(int)

    for x in a:
        freq[x] += 1

    mx = max(a)

    for x in range(2, mx + 1):
        if freq[x] > freq[x - 1]:
            print(-1)
            return

    groups = freq[1]

    assign = defaultdict(deque)

    for x in range(1, mx + 1):
        for group_id in range(1, freq[x] + 1):
            assign[x].append(group_id)

    ans = []

    for x in a:
        ans.append(assign[x].popleft())

    print(groups)
    print(*ans)

solve()
```最初のセクションでは周波数をカウントします。 使用する`defaultdict(int)`手動による存在チェックを回避し、コードをクリーンに保ちます。 

単調性チェックは実現可能性テスト全体です。 ある値が前の値よりも多く出現する場合、大きい値のすべてのコピーには、同じ順列内の小さい値の個別のコピーが必要となるため、再構築は不可能です。 

順列の数は次のように固定されます。`freq[1]`。 すべての有効な置換には次のものが含まれている必要があります。`1`したがって、1 より多くの順列は存在できず、すべてが異なる順列に属します。 

割り当て構造は微妙です。 あらゆる価値観に対して`x`、どの順列 ID がそれを受け取るべきかを事前に計算します。```
1, 2, ..., freq[x]
```後で、元の配列の順序を調べながら、次を使用してこれらの ID を 1 つずつ消費します。`popleft()`。 

これにより、同じ値が配列全体に散在している場合でも、正確さが保たれます。 

よくある間違いは、最初の走査中にオカレンスを分離せずに直接割り当てようとすることです。 これにより、同じ順列内に重複した値が作成されることがよくあります。 

## 実用的な例

 ### 例 1

 入力:```
9

```周波数:```
cnt[1] = 3
cnt[2] = 3
cnt[3] = 1
cnt[4] = 1
cnt[5] = 1
```カウントは増えていないので構築は可能です。 

準備された課題:```
1 -> [1,2,3]
2 -> [1,2,3]
3 -> [1]
4 -> [1]
5 -> [1]
```元の配列の処理:

 | --- | --- | --- | --- |
 | 1 | 1 | 1 | [2,3] |
 | 2 | 2 | 1 | [2,3] |
 | 3 | 3 | 1 | [] |
 | 4 | 1 | 2 | [3] |
 | 5 | 2 | 2 | [3] |
 | 6 | 1 | 3 | [] |
 | 7 | 4 | 1 | [] |

 最終出力:```
3

```このトレースは中心不変式を示しています。 より大きな数を受け取るすべての順列は、より小さな数をすべてすでに受け取っています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての要素はカウントされ、一度割り当てられます。

 ## 特殊なケース

 次のことを考慮してください。```
3
2 2 1
```周波数は次のようになります。```
cnt[1] = 1
cnt[2] = 2
```検証中に、アルゴリズムは以下をチェックします。```
2 > 1
```そして即座に入力を拒否します。 

これは正しいです。なぜなら、すべての順列には以下が含まれるからです。`2`も含まれている必要があります`1`。 の 2 部`2`のコピーが 2 つ必要になります`1`。 

次に、次のことを考えてみましょう。```
5
1 3 1 2 2
```周波数:```
cnt[1] = 2
cnt[2] = 2
cnt[3] = 1
```課題:```
1 -> [1,2]
2 -> [1,2]
3 -> [1]
```処理順序:

 | 値 | 割り当てられた順列 |
 | --- | --- |
 | 1 | 1 |
 | 3 | 1 |
 | 1 | 2 |
 | 2 | 1 |
 | 2 | 2 |

 順列 1 は次のようになります。```
(1,2,3)
```順列 2 は次のようになります。```
(1,2)
```配列の順序がシャッフルされても、割り当ては頻度のみに依存するため、構築は引き続き成功します。 

最後に、以下を調べます。```
1
2
```得られるものは次のとおりです。```
cnt[1] = 0
cnt[2] = 1
```単調性条件はすぐに失敗します。```
1 > 0
```順列を開始することはできません`2`、アルゴリズムは正しく出力します`-1`。
