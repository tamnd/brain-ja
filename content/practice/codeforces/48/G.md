 ## 解決策
 ## 問題の理解

 正確に、無向重み付きグラフが与えられます。`n`頂点と`n`エッジ。 接続されたグラフなので、`n`頂点と`n`エッジにはちょうど 1 つのサイクルが含まれており、グラフは単循環グラフ、つまり 1 つの余分なエッジを持つツリーです。 

あらゆる惑星のために`u`、大統領が他のすべての惑星に 1 つずつ電話をかけるのに必要な合計時間を計算する必要があります。 個々の通話では 2 つの惑星間の最短経路が使用され、通話時間は経路の長さそのものに等しくなります。 

したがって、すべての頂点について`u`、必要な答えは次のとおりです。$ans(u)=\sum_{v=1}^{n} dist(u,v)$グラフはまばらですが、サイズは大きいです。 と`n ≤ 200000`に近い任意のアルゴリズム`O(n²)`すぐには無理です。 すべてのペアごとの距離を保存する場合でも、約`4 × 10^10`価値観。 ほぼ直線的なものが必要です。または、`O(n log n)`。 

重要な構造特性は、グラフに正確に 1 つのサイクルが含まれていることです。 グラフはほぼツリーであるため、すべてのソースに対する一般的な最短パス アルゴリズムは無駄になります。 ソリューション全体は、その特別な構造を活用することで生まれます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

純粋な三角形を考えてみましょう。```
3
1 2 3
2 3 2
1 3 1
```間の最短経路`1`そして`3`は重みの直接の端です`1`を通る道ではなく、`2`体重の`5`。 サイクルを一時的に中断し、代替ルートを復元せずにグラフをツリーとして扱うソリューションでは、不正確な距離が生成されます。 

サイクルに接続されている木が大きい場合には、別の厄介な状況が発生します。```
5
1 2 1
2 3 1
3 1 1
3 4 10
4 5 10
```ノードから`5`への最短ルート`1`サイクルノードを通過します`3`。 接続されたツリー間の距離は、任意の移動順序ではなく、サイクルの周囲の最短ルートに依存します。 これを忘れると、二重にカウントしたり、間違ったサイクル方向を選択したりすることになります。 

サイクル長が等しいことも危険です。```
4
1 2 1
2 3 1
3 4 1
4 1 1
```反対側の頂点には、同じ長さの 2 つの最短ルートがあります。 アルゴリズムは依然として距離を 1 回だけカウントする必要があります。 不注意な 2 ポインターの実装により、誤って両方向が含まれる可能性があります。 

最後に、再帰の深さは実際的な問題です。 グラフは長さのパスに縮退する可能性があります`200000`1 つのサイクル ノードに接続されます。 Python の再帰 DFS は、再帰制限を増やすか、反復トラバーサルを慎重に使用しない限り、クラッシュします。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのノードに対してダイクストラを実行し、すべての最短距離を合計します。 グラフには、`n`エッジなので、ダイクストラは 1 つかかります`O(n log n)`。 すべての頂点に対してこれを繰り返すと、次のようになります。$O(n^2\log n)$と`n = 200000`、これはまったく不可能です。 

グラフの構造は、より強力な何かを示唆しています。 グラフには正確に 1 つのサイクルがあるため、サイクル エッジを削除すると、グラフがいくつかのツリーに分割され、それぞれが正確に 1 つのサイクル頂点に接続されます。 

ツリー内では、距離の合計は古典的なリルート DP です。 唯一の複雑な点は、サイクルを通じて異なるツリー間の相互作用です。 

アタッチされたすべてのツリーを、そのサイクル頂点をルートとするコンポーネントに圧縮するとします。 この場合、2 つの頂点間のすべての最短パスは次のように動作します。 

1. 最初の頂点からそのサイクル ルートまで移動します。 
2. 短い方向を使用してサイクルに沿って移動します。 
3. 2 番目のツリー内を下に移動します。 

その分解が中心的な洞察です。 サイクル動作を分離すると、残りは通常のツリー DP になります。 

難しいのは、サイクルに沿った最短距離を効率的に合計することです。 素朴な方法では、サイクル頂点のすべてのペアを比較しますが、サイクル自体にサイズがある場合、これも二次になります。`O(n)`。 

サイクルは円形であるため、そのサイクルに沿った最短距離は、重複したプレフィックス合計の 2 ポインタ スライディング ウィンドウで処理できます。 これにより、すべてのサイクル寄与計算が線形時間に変換されます。 

最終的なアルゴリズムには、次の 3 つの主要な部分があります。 

1. 固有のサイクルを検出します。 
2. 接続されているすべてのツリーでツリー DP を独立して実行します。 
3. プレフィックス合計と 2 つのポインターを使用したプロセス サイクルの対話。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 葉の削除を使用して固有のサイクルを見つけます。 

次数を持つすべてのノード`1`サイクルに属することはできません。 すべての葉をキューに押し込み、繰り返し削除します。 次数が次になる任意のノード`1`後もサイクルの外です。 

このプロセスの後、残りのノードはまさに一意のサイクルを形成します。 
2. すべての非サイクル ノードをそのサイクル ルートに割り当てます。 

すべてのサイクル頂点について、他のサイクル ノードを避けながら、その接続されたツリーに対して DFS を実行します。 

この走査中に次のことを計算します。 

-`sz[u]`、サブツリーのサイズ
 -`down[u]`、からの距離の合計`u`サブツリー内のノードに
 3. 再ルートされたツリーの答えを計算します。 

標準ツリー DP は、同じコンポーネント内のすべての距離の合計を示します。 

もし：$down(u)=\sum_{v\in subtree(u)}dist(u,v)$次に、再ルートすると、完全なコンポーネントの合計が得られます。$all(v)=all(u)+w\cdot(compSize-2\cdot sz(v))$どこ`w`間のエッジの重みです`u`そして`v`。 
4. サイクル頂点ごとに、コンポーネント情報を収集します。 

させて：

-`compSize[i]`サイクル頂点にアタッチされた頂点の数になります`i`-`compSum[i]`サイクル頂点からの距離の合計になります`i`コンポーネント内のすべてのノードに
 5. サイクルを線形化します。 

サイクルエッジの長さを順番に保存し、プレフィックスの合計を構築します。 

サイクル配列を複製すると、モジュラー演算の煩わしさを感じることなく区間処理が可能になります。 
6. 2 つのポインターを使用して最短方向を決定します。 

サイクル頂点ごとに`i`、最大値を維持します`j`から時計回りに距離がかかるように、`i`に`j`最大でもサイクル長の半分です。 

次に、その間隔内のすべての頂点は、からの時計回りの最短パスを使用します。`i`、残りは反時計回りのパスを使用します。 
7. サイクル貢献度を蓄積します。 

コンポーネントからの貢献が必要だとします`j`コンポーネント内のノードへ`i`。 

すべてのペアが以下に貢献します。$dist(x,y)=dist(x,root_i)+cycleDist(i,j)+dist(root_j,y)$すべてのペアを合計すると、コンポーネントの集合体にきれいに分離されます。 

コンポーネント サイズのプレフィックス合計とコンポーネント距離合計により、各サイクル頂点が他のすべてのコンポーネントを償却定数時間で処理できるようになります。 
8. 外部コントリビューションをすべてのノードに追加します。 

ノードの場合`u`内部コンポーネント`i`:

 - 内部距離はツリー DP からすでにわかっています
 - すべての外部ノードは以下を追加します。`dist(u, root_i)`事前に計算されたサイクル ルートの外部寄与を加えたもの

 これにより最終的な答えが得られます。 

### なぜ効果があるのか

 単循環グラフ内のすべての最短パスは、ツリー セグメントとサイクルに沿った 1 つのセグメントに一意に分解されます。 サイクルを削除すると、グラフが独立したルート付きツリーに切断されるため、すべての非サイクル距離は標準の再ルート DP によって処理されます。 

さまざまなコンポーネントの頂点の場合、唯一の自由は、サイクルのどの方向が短いかを選択することです。 サイクル自体は 1 次元であるため、2 つのポインターは頂点を時計回りの最適範囲と反時計回りの最適範囲に正しく分割します。 

このアルゴリズムは、真の最短サイクル方向を使用してすべてのペアを正確に 1 回カウントし、ツリーの寄与は独立して追加されます。 すべての分解は正確であるため、生成される合計は最短経路距離の合計と等しくなります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n = int(input())

g = [[] for _ in range(n)]

edges = []

for _ in range(n):
    a, b, w = map(int, input().split())
    a -= 1
    b -= 1

    g[a].append((b, w))
    g[b].append((a, w))

    edges.append((a, b, w))

deg = [len(g[i]) for i in range(n)]
removed = [False] * n

q = deque()

for i in range(n):
    if deg[i] == 1:
        q.append(i)

while q:
    u = q.popleft()
    removed[u] = True

    for v, _ in g[u]:
        if not removed[v]:
            deg[v] -= 1
            if deg[v] == 1:
                q.append(v)

in_cycle = [not removed[i] for i in range(n)]

cycle = []

start = next(i for i in range(n) if in_cycle[i])

prev = -1
cur = start

while True:
    cycle.append(cur)

    nxt = -1

    for v, _ in g[cur]:
        if in_cycle[v] and v != prev:
            nxt = v
            break

    prev, cur = cur, nxt

    if cur == start:
        break

m = len(cycle)

pos = [-1] * n
for i, x in enumerate(cycle):
    pos[x] = i

cycle_w = []

for i in range(m):
    u = cycle[i]
    v = cycle[(i + 1) % m]

    for to, w in g[u]:
        if to == v:
            cycle_w.append(w)
            break

comp_root = [-1] * n
depth = [0] * n

sz = [0] * n
dp = [0] * n
ans = [0] * n

comp_size = [0] * m
comp_sum = [0] * m

def dfs1(u, p, root):
    comp_root[u] = root
    sz[u] = 1

    for v, w in g[u]:
        if v == p or in_cycle[v]:
            continue

        depth[v] = depth[u] + w

        dfs1(v, u, root)

        sz[u] += sz[v]
        dp[u] += dp[v] + sz[v] * w

def dfs2(u, p, total):
    ans[u] = total

    for v, w in g[u]:
        if v == p or in_cycle[v]:
            continue

        nxt = total + (comp_size[comp_root[u]] - 2 * sz[v]) * w
        dfs2(v, u, nxt)

for idx, root in enumerate(cycle):
    depth[root] = 0

    dfs1(root, -1, idx)

    comp_size[idx] = sz[root]
    comp_sum[idx] = dp[root]

    dfs2(root, -1, dp[root])

pref = [0]

for w in cycle_w * 2:
    pref.append(pref[-1] + w)

total_cycle = pref[m]

comp_size2 = comp_size * 2
comp_sum2 = comp_sum * 2

pref_size = [0]
pref_sum = [0]

for x in comp_size2:
    pref_size.append(pref_size[-1] + x)

for x in comp_sum2:
    pref_sum.append(pref_sum[-1] + x)

extra = [0] * m

j = 0

for i in range(m):
    if j < i:
        j = i

    while j + 1 < i + m:
        d = pref[j + 1] - pref[i]
        if d * 2 <= total_cycle:
            j += 1
        else:
            break

    left_size = pref_size[j + 1] - pref_size[i + 1]
    left_sum = pref_sum[j + 1] - pref_sum[i + 1]

    left_dist = 0

    for k in range(i + 1, j + 1):
        d = pref[k] - pref[i]
        left_dist += d * comp_size2[k] + comp_sum2[k]

    right_size = pref_size[i + m] - pref_size[j + 1]
    right_sum = pref_sum[i + m] - pref_sum[j + 1]

    right_dist = 0

    for k in range(j + 1, i + m):
        d = total_cycle - (pref[k] - pref[i])
        right_dist += d * comp_size2[k] + comp_sum2[k]

    extra[i] = left_dist + right_dist

final = [0] * n

for u in range(n):
    r = comp_root[u]

    base = ans[u]

    add = extra[r]
    add += (n - comp_size[r]) * depth[u]

    final[u] = base + add

print(*final)
```最初のセクションでは葉を削除してサイクルを分離します。 これが機能するのは、外側の層を繰り返し剥がした後、すべての非サイクル頂点が最終的​​にリーフになるためです。 

サイクルが判明すると、各サイクル頂点がツリー コンポーネントのルートになります。`dfs1`サブツリーのサイズとサブツリーの距離の合計を計算します。`dfs2`再ルートを実行して、すべての頂点がそのコンポーネント内のすべてのノードまでの距離の合計を取得します。 

サイクル処理はソリューションの中心です。 プレフィックス合計には、サイクルに沿った時計回りの距離が格納されます。 配列を複製すると、サイクルをスライドしながらモジュラー演算を回避できます。 

2 ポインター ウィンドウは、どのサイクル頂点が反時計回りよりも時計回りに近いかを識別します。 すべてのサイクル ルートについて、正しい最短サイクル方向を使用して他のすべてのコンポーネントからの寄与を合計します。 

微妙な点の 1 つは、次の式です。```
total + (comp_size[root] - 2 * sz[v]) * w
```親から子に再ルートすると、子サブツリー内のすべてのノードが次の距離に近づきます。`w`、他のすべてのノードは によってさらに遠くなります。`w`。 

もう 1 つの微妙な点は、DFS 中にサイクル頂点へのトラバースを回避することです。 サイクルが特定されると、接続されたすべての構造がツリーのように動作する必要があります。
