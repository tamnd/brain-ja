 ## 解決策
 ## 問題の理解

 ゲームの状態は、ドラゴンが現在持っている頭の数と尾の数という 2 つの数字で完全に記述されます。 州から`(h, t)`イワンは 2 つの移動タイプのうち 1 つを選択できます。 

彼がカットしたら`i`頭、どこ`1 ≤ i ≤ n`そして`i ≤ h`、その後ドラゴンは成長します`headGrow[i]`頭と`tailGrow[i]`尾。 新しい状態は次のようになります。`(h - i + headGrow[i], t + tailGrow[i])`彼がカットしたら`i`尾、どこで`1 ≤ i ≤ m`そして`i ≤ t`、新しい状態は次のようになります。`(h + headGrowTail[i], t - i + tailGrowTail[i])`戦いは 3 つの方法のいずれかですぐに終了します。 

州がこうなったらイワンが勝ちます`(0, 0)`再生後。 

移動後のパーツの合計数が を超えた場合、ドラゴンの勝ちです。`R`。 

イワンが永遠に負けるのを避けることができても、決して強制的に勝つことができない場合、ゲームは引き分けです。 

難しいのは、イワンが 3 つのレベルの目標の下で常に最適なプレーをすることです。 まず、彼は最小限の手数で勝つことを好みます。 勝つことが不可能であれば、彼は永遠に生き残ることを好みます。 それも無理なら、出来るだけ敗北を遅らせたい。 

境界はすべての有効なものを扱うのに十分小さい`(h, t)`ペアをグラフノードとして使用します。 以来`h + t ≤ R ≤ 200`、到達可能な法的状態の総数は最大で約`201 × 201`、ただし、次の状態のみ`h + t ≤ R`案件。 それは大まかに与えます`O(R²)`州では最悪の場合約4万人に達する。 各州には最大でも`n + m ≤ 400`発信トランジション。 すべての状態にわたるグラフ アルゴリズムは完全に実現可能です。 

メモ化を行わない単純な再帰シミュレーションは、ゲーム グラフにサイクルが含まれるため失敗します。 たとえば、1 つの頭を切断すると、ちょうど 1 つの頭が再生されるとします。 その後、状態は変化せず、再帰は永久にループします。 

イワンが永遠に生き残ることができるが、到達できない場合、微妙なエッジケースが表示されます。`(0,0)`。 

例：```
1 0 5
1
1 0
1
0 0
```から`(1,0)`、頭を1つカットすると、元に戻ります`(1,0)`。 合計が超えることはないので、イワンは決して負けません。`R`、しかし彼も決して勝つことはありません。 正しい出力は次のとおりです。```
Draw
```を探すだけの最短経路検索`(0,0)`イワンが負けたという誤った結論を下してしまうだろう。 

もう 1 つの重要なエッジ ケースは、あらゆる可能な動きがすぐに次の値を超える場合です。`R`。 

例：```

1

1

```1 つのヘッドを切断すると、`(2,0)`を合計が超える`R`。 イワンは即座に負けます。```
Zmey

```不注意な実装では、超過していることを忘れてしまうことがあります。`R`これは即時の終端損失であり、それらの状態を誤ってグラフに挿入してしまいます。 

もう 1 つの微妙なケースは、イワンが最終的な敗北を避けることができないが、選択によって遅延の量が異なる場合です。

```印刷された数字は、Ivan が避けられない損失を被るまでに生き残ることができる最大手数です。 

## アプローチ

 最も直接的なアイデアは、各状態を表示することです`(h,t)`ノードとしてすべての可能な動きを再帰的に探索します。 移動が到達した場合`(0,0)`, イワンが勝ちます。 すべての動きが最終的に超えた場合`R`、ドラゴンが勝ちます。 何らかのサイクルが存在する場合、ゲームは永遠に続く可能性があります。 

ゲームは法的領域内で有限であるため、この再帰的アプローチは論理的に正しいです。`h + t ≤ R`。 問題は、再帰だけでは有用な再訪と無限ループを区別できないことです。 同じ状態を繰り返し繰り返す DFS は、終了しない可能性があります。 ゲームは単純な勝ち負けゲームではなく、最適化基準を備えた 3 つの結果があるため、メモ化を行ってもサイクルを正しく処理するのは複雑になります。 

重要な観察は、法的国家が最大約 40,000 ノードからなる有向グラフを形成しているということです。 グラフの観点から考えると、問題は自然に 3 つの別々のグラフ問題に分割されます。 

まず、イワンが到達できるかどうかを判断します`(0,0)`法的地域を離れる前に。 すべての移動には 1 ステップのコストがかかるため、これは重み付けされていないグラフの最短パスにすぎません。 

勝つことが不可能な場合は、イワンが永遠に生き残ることができるかどうかを判断してください。 これは、完全に合法な領域内に留まりながら、開始状態から何らかのサイクルに到達できるときにまさに発生します。 

勝利も無限生存も不可能な場合、最初から到達可能なグラフは負けた出口で終了する DAG になります。 その状況では、Ivan は可能な限り長い生存時間を望んでおり、これが DAG 内の最長のパスになります。 

状態グラフの構造は、この分解を機能させるものです。 ドラゴンがすぐに勝たない限り、すべての合法的な動きは、境界のある状態空間内に留まります。 この境界により、標準のグラフ アルゴリズムがゲームを完全に特徴付けることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | 指数 | 指数再帰ツリー | 遅すぎる |
 | 最適なグラフ + BFS + サイクル検出 + DP | O(R²(n+m)) | O(R²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. あらゆる法的国家を生成する`(h,t)`そのような`h + t ≤ R`。 

これらの州は戦闘を継続できる唯一の州です。 合計が大きくなるような動きは、即時の敗北を意味します。 
2. 法的状態間の指示された移行を構築します。 

すべての状態について、考えられるすべてのヘッドカットとテールカットを試してください。 結果の状態がまだ満足する場合`h + t ≤ R`、それにエッジを追加します。 それ以外の場合、その手は即時負けの出口として扱われます。 
3. 初期状態から BFS を実行して最短距離を計算します。 

すべての移動には正確に 1 回の打撃が必要となるため、BFS では到達可能なすべての状態に最小移動数が与えられます。 
4. もし`(0,0)`到達可能です、印刷します`"Ivan"`そしてBFS距離。 

BFS は、これが可能な限り最小の打撃数であることを保証します。 
5. それ以外の場合は、到達可能なサブグラフにサイクルが含まれているかどうかを確認します。 

3 色で DFS を実行します。`0 = unvisited`

`1 = currently in recursion stack`

`2 = fully processed`色の付いたノードへのエッジに遭遇`1`到達可能なサイクルが存在することを意味します。 
6. 到達可能なサイクルが存在する場合は、出力します。`"Draw"`。 

イワンはそのサイクルの中に永遠に留まり、無限に敗北を避けることができます。 
7. それ以外の場合、到達可能なグラフは非循環になります。 

すべてのパスは最終的に次の値を超える移動で終了する必要があります。`R`。 
8. DAG 上の DP を使用して最長生存時間を計算します。 

定義する`dp[state]`その状態から始まる敗北までの最大手数として。 

法的な動きのない州では、`dp = 1`次の一手がすぐに負けるからです。 

さもないと：`dp[state] = 1 + max(dp[next_state])`9. 印刷`"Zmey"`そして`dp[start]`。 

これは、敗北が避けられない場合にイワンが生き残ることができる最大手数です。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべてのゲームを正確に 3 つのカテゴリに分類します。 

もし`(0,0)`が到達可能な場合、すべてのエッジのコストが等しいため、BFS は最短の勝利シーケンスを見つけます。 

もし`(0,0)`は到達できませんが、到達可能なサイクルが存在する場合、イワンはそのサイクルをループすることで合法的な状態に永久に留まることができます。 超えてこそ敗北なので`R`、そのようなサイクルは無限の生存を保証します。 

どちらの条件も当てはまらない場合、到達可能なグラフは有限 DAG になります。 すべてのプレイは最終的に行き止まりに到達し、すべての手が即座に負けます。 DAG 上の動的プログラミングは、各州がすべての合法的な動きの中から最適な継続を選択するため、可能な最大生存期間を計算します。 

これら 3 つのケースは相互に排他的であり、考えられるあらゆるゲームの進化をカバーします。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

INF = 10**18

def solve():
    H, T, R = map(int, input().split())

    n = int(input())
    head = [(0, 0)] * (n + 1)
    for i in range(1, n + 1):
        head[i] = tuple(map(int, input().split()))

    m = int(input())
    tail = [(0, 0)] * (m + 1)
    for i in range(1, m + 1):
        tail[i] = tuple(map(int, input().split()))

    states = []
    for h in range(R + 1):
        for t in range(R + 1 - h):
            states.append((h, t))

    graph = {}
    for h, t in states:
        nxt = []

        for i in range(1, min(n, h) + 1):
            nh = h - i + head[i][0]
            nt = t + head[i][1]

            if nh + nt <= R:
                nxt.append((nh, nt))

        for i in range(1, min(m, t) + 1):
            nh = h + tail[i][0]
            nt = t - i + tail[i][1]

            if nh + nt <= R:
                nxt.append((nh, nt))

        graph[(h, t)] = nxt

    start = (H, T)
    target = (0, 0)

    dist = {start: 0}
    q = deque([start])

    while q:
        v = q.popleft()

        for to in graph[v]:
            if to not in dist:
                dist[to] = dist[v] + 1
                q.append(to)

    if target in dist:
        print("Ivan")
        print(dist[target])
        return

    color = {}
    has_cycle = False

    def dfs(v):
        nonlocal has_cycle

        color[v] = 1

        for to in graph[v]:
            if to not in dist:
                continue

            if color.get(to, 0) == 0:
                dfs(to)
            elif color[to] == 1:
                has_cycle = True

        color[v] = 2

    dfs(start)

    if has_cycle:
        print("Draw")
        return

    dp = {}

    def longest(v):
        if v in dp:
            return dp[v]

        if not graph[v]:
            dp[v] = 1
            return 1

        best = 0
        for to in graph[v]:
            best = max(best, longest(to))

        dp[v] = best + 1
        return dp[v]

    print("Zmey")
    print(longest(start))

Ivan は常に引き分けや敗北を遅らせるよりも勝つことを好むため、BFS セクションは最初に勝ったケースを解決します。 最小限の攻撃回数で解決できるため、DFS の代わりに BFS を使用することが重要です。 

サイクル検出 DFS は、最初から到達可能な状態のみを横断します。 グラフ内の他の場所にあるサイクルは、Ivan がそれに入ることができない場合は意味がありません。 3 色 DFS は、有向サイクルを検出する標準的な方法です。 再帰スタック内にすでにノードがあるということは、バックエッジが見つかったことを意味し、したがって無限ループが見つかったことを意味します。 

最長パス DP が機能するのは、描画ケースが除外された後、グラフが非循環であることが保証されるためです。 このプロパティがなければ、再帰は永久にループすることになります。 法的優位性を失った国家が戻ってくる`1`なぜなら、イワンはすぐに負ける前に、まだ最後の動きをすることができるからです。 

微妙な点の 1 つは、チェックの順序です。 到達可能性をテストする必要があります`(0,0)`サイクルを確認する前に。 イワンは常に勝つことを好むため、イワンがすでに勝利戦略を持っているかどうかは、到達可能なサイクルには関係ありません。
