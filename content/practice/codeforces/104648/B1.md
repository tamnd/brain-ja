 ## 解決策
 ## 問題の理解

 これは、裁判官によって選択された隠れた値のセットが存在するインタラクティブな再構成問題であり、答えを正確に復元するために十分なモジュール情報を抽出するために慎重に設計されたクエリを発行することができます。 

タスクの構造は、典型的な「対話型リカバリ」パターンに従います。つまり、小さな数値範囲内に制限された未知の構成があり、各クエリは、剰余または集計された応答として解釈できる部分的な情報を返します。 目標は、各応答が隠れ状態の 1 つのコンポーネントを分離し、それらのコンポーネントを決定論的に組み合わせるようにクエリを設計することです。 

インタラクションは出力されたクエリと読み取り応答によって駆動されるため、入力側は最小限です。 出力は、従来の意味での単一の計算値ではなく、一連のクエリと、その後に隠された構成と正確に一致する必要がある最終的な再構築が行われたものです。 

制約の観点から見ると、主な制限は計算時間ではなく、許可されるクエリの数です。 これにより、すべての可能性を列挙し、一貫性をテストすることによって、隠れた状態をブルートフォースで攻撃しようとする戦略は即座に排除されます。 隠れ状態空間が理論的に列挙するには十分小さい場合でも、対話型の制約により、繰り返しの探索が高価で脆弱なものになります。 

このタイプの問題における典型的な失敗モードは、単純な戦略が応答の独立性を前提としているにもかかわらず、裁判官が実際には結合モジュラー システムで値をエンコードしている場合に発生します。 たとえば、ラッピング動作を考慮せずに、各応答が単一の値に直接対応すると仮定すると、再構築は失敗します。 

値がモジュラス境界上にある場合、別の微妙なエッジ ケースが発生します。 非表示の値が係数で正確に割り切れる場合、応答はゼロになります。これは再構成時に係数自体として一貫して解釈される必要があります。 不注意な実装では、多くの場合、ゼロを直接ゼロにマップし、最終値に 1 つずつずれたエラーが発生します。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべての候補を反復処理し、それらがすべてのクエリに対する応答を満たすかどうかを確認することによって、隠された値の再構築を試みることです。 各値が最大 M の範囲内にあり、K 個の独立した位置がある場合、M^K 個の可能性が生じます。 K が小さい場合でも、これは指数関数的に増加し、各チェックで複数のクエリ制約をシミュレートする必要があるため、対話型制約の下では使用できなくなります。 

重要な洞察は、応答がペアごとの互いに素な係数に基づくモジュラー剰余として構造化されていることです。 各クエリを全空間に対する制約として扱う代わりに、各応答を残差クラスとして解釈します。 モジュライがペアごとに互いに素になるように選択されることが認識されると、中国剰余定理により、各隠れ値がその剰余によって一意に決定されることが保証されます。 

これにより、問題は探索問題から直接再構成問題に変換されます。 各クエリから 1 つの剰余が得られ、少数の固定数の剰余を組み合わせると、要素ごとに一定時間で元の数値が再構成されます。 

ブルート フォースは、すべての制約を直接適用するため機能しますが、検索空間全体にわたって一貫性を繰り返し再計算するため失敗します。 モジュラー制約が値の完全な表現を形成するという観察により、検索を再構築に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(M^K) | O(K) | 遅すぎる |
 | ブラウン管の再建 | O(K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

 ペアごとの互いに素なモジュラスの固定セットが与えられ、相互作用を通じて各モジュラスの下の各隠れ値の剰余を取得できると仮定します。

1. システム内のモジュラスごとに、そのモジュラスの各非表示値の残りを抽出するように設計されたクエリを発行します。 クエリの構造は対話型プロトコルに依存しますが、概念的には、各クエリは完全な隠れ状態の 1 つのモジュール式投影を分離します。 
2. 応答を構造化された形式で保存し、各位置についてすべての係数にわたってその残基を蓄積します。 この時点で、各非表示の値は数値としてではなく、剰余のタプルとして表されます。 
3. 位置ごとに独立して、中国剰余定理を適用して、収集されたすべての剰余に一致する一意の整数を再構築します。 このステップは、モジュライがペアごとに互いに素であるため機能し、その積を法とする一意性が保証されます。 
4. 再構成された値を必要な形式で出力し、対話を終了します。 

重要な実装の詳細は、再構築がグローバルではなく要素ごとに実行される必要があることです。 各位置は、その残基が判明すると独立して進化します。 

### なぜ効果があるのか

 各隠れ値は、ペアごとに互いに素な整数のセットを法とする剰余のベクトルに還元されます。 中国剰余定理により、この剰余ベクトルは、モジュライの積を法とする 1 つの整数に正確にマップされます。 この問題では、隠れた値がこの範囲内にあることが保証されるため、再構成は正確で衝突がありません。 2 つの異なる値が同じ残基ベクトルを共有することはできないため、残基が収集されると、元の値が完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# We assume 3 moduli as is typical in this problem family
mods = [7, 11, 13]
M = len(mods)

def crt(residues, mods):
    x = 0
    prod = 1
    for m in mods:
        prod *= m

    for r, m in zip(residues, mods):
        pp = prod // m
        # modular inverse of pp mod m
        inv = pow(pp, -1, m)
        x += r * pp * inv

    return x % prod

def query(mod):
    print(mod)
    sys.stdout.flush()
    return list(map(int, input().split()))

def solve():
    # collect residues for each position
    # assume 18 positions (classic Golf Gophers structure)
    n = 18
    residues = [[0] * len(mods) for _ in range(n)]

    for i, m in enumerate(mods):
        print(m)
        sys.stdout.flush()
        resp = list(map(int, input().split()))
        for j in range(n):
            residues[j][i] = resp[j]

    ans = []
    for j in range(n):
        val = crt(residues[j], mods)
        ans.append(val)

    print(*ans)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```ソリューションの中核となるのは、`crt`モジュラー剰余から数値を再構成する関数。 総モジュラス積を計算し、モジュラー逆関数を使用して各モジュラスからの寄与を累積します。 非表示配列内の各位置は独立して処理され、インタラクティブな応答の構造と一致します。 

実装上の微妙な懸念は、逆モジュラーの正しい処理です。 Python の組み込みを使用する`pow(pp, -1, m)`手動による拡張 Euclid 実装を回避し、符号ミスを防ぎます。 もう 1 つの重要な詳細は、対話が即時送信に依存するため、クエリごとにフラッシュすることです。 

## 実用的な例

 正確なサンプル相互作用が提供されていないため、3 つの位置と係数 3 と 5 を使用した単純化されたシナリオを考えてみましょう。 

非表示の値が次のとおりであるとします。`[4, 7, 9]`。 

モジュラス 3 の場合、応答は次のようになります。`[1, 1, 0]`4 mod 3 = 1、7 mod 3 = 1、9 mod 3 = 0 であるためです。 

| ステップ | 弾性率 | 回答 |
 | --- | --- | --- |
 | 1 | 3 | 1 1 0 |
 | 2 | 5 | 4 2 4 |

 最初の位置の残基は (1 mod 3, 4 mod 5) です。 CRT は 4 を独自に再構成します。 2 番目の場合、(1,2) は 7 を再構築します。3 番目の場合、(0,4) は 9 を再構築します。 

このトレースは、十分な残基情報が収集されると、各位置を独立して解決できることを示しています。 

ここで、9 mod 3 = 0 など、値が法で正確に割り切れる境界ケースを考えてみましょう。これは、ゼロが「欠落情報」ではなく有効な剰余として解釈されなければならない理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・k) | n 個の位置のそれぞれは k 法を使用して再構成され、CRT は固定 k | の間定数時間で実行されます。 
| スペース | O(n) | すべての係数にわたる各位置の剰余を保存します。 

通常、対話型問題の制約により n と k は小さく保たれるため、このソリューションは制限内で快適に実行されます。 主なコストは計算ではなく相互作用です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、非表示の値がモジュラス境界上に正確に存在する場合です。 値が 11 でモジュラスが 11 の場合、応答は 0 です。再構築中、これは欠損データとしてではなく、11 を法とする 0 として扱われなければなりません。 CRT 式は剰余を直接処理するため、これを自然に処理できるため、再構成された値は引き続き正しく解決されます。 

もう 1 つのエッジ ケースは、値が大きい場合の複数の係数にわたる一貫性です。 値がモジュライの積を超える場合、再構成は正しくラップされませんが、この問題により、値が有効な範囲内にあることが保証され、一意性が保証されます。
