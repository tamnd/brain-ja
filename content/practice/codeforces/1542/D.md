 ## 解決策
 ## 問題の理解

 マルチセットに値を挿入するか、現在存在する最小値を削除する一連の操作が与えられます。 面白いのは、このプロセスを 1 回評価するのではなく、指定された操作のすべてのサブシーケンスに対して評価することです。各サブシーケンスは、そのサブシーケンスの処理後にマルチセットに残された要素の合計に等しいスコアを与えます。 

サブシーケンスは、順序を維持しながら、操作ごとに保持するか削除するかを個別に決定することによって形成されます。 このような選択ごとに、プロセスをシミュレートします。「+ x」操作を維持すると x が挿入され、「-」操作を維持すると最小の要素が存在する場合は削除されます。 そのサブシーケンス内のすべての操作が処理された後、スコアは残りの要素の合計になります。 

タスクは、すべてのサブシーケンスにわたるこれらのスコアの合計を計算することです。 

サブシーケンスは 2^500 個あるため、制約 n ≤ 500 により、サブシーケンスの列挙が即座に除外されます。 単一のサブシーケンスをシミュレートする場合でも、マルチセット操作により O(n log n) かかるため、ブルート フォースは完全に実行不可能になります。 

削除について貪欲に考えると、微妙な問題が発生します。 マイナス演算では常に現在のマルチセット内の最小要素が削除されるため、どの値が以前に挿入されたかに応じて、サブシーケンスが異なると非常に異なる削除パターンが生成される可能性があります。 素朴な間違いは、各「+ x」が独立して一定の生存確率に寄与すると仮定することです。 存続は他の挿入された値との競合に依存するため、これは失敗します。 

もう 1 つのよくある落とし穴は、マイナス演算を単に要素のカウンターを減らすものとして扱うことです。 これでは、どの要素が削除されるかは無視され、最終的な合計は削除後にどの値が残るかに大きく依存します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのサブシーケンスを列挙し、マルチセット プロセスをシミュレートし、最終的な合計を累積します。 これは正しいですが、2^n 個のサブシーケンスがあり、各シミュレーションのコストが最大 O(n log n) であるため、指数関数的に大きくなり、約 O(n 2^n log n) の操作が必要となり、制限をはるかに超えています。 

重要な観察は、プロセスがサブシーケンスに対して線形であるため、サブシーケンスの処理後にマルチセットの「状態」を追跡しながら、プレフィックスに対して動的プログラミングを使用できることです。 課題は、マルチセットが任意ではないということです。minus は常に最小の要素を削除するため、マルチセットは、非常に構造化された方法で利用可能な最大の要素を常に維持しているかのように動作することになります。 

これにより、各状態が現在マルチセットに残っている要素の数に対応する DP 定式化が得られます。 ただし、これらの要素の合計も必要であるため、保持されている要素の中に現在どの値が含まれているかをさらに維持する必要があります。 正しい構造は、状態サイズ k ごとに、そのサブシーケンスに対して選択されたすべての「+」値の中から最大 k 個の要素を追跡するだけでよいということです。これは、削除を繰り返すと常に最小の要素が削除されるためです。 

これにより、プレフィックスとサイズを超えた DP が可能になり、各状態が多くのサブシーケンスからの寄与を集約し、各状態のマルチセット コンテンツを注意深く維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n log n) | O(n) | 遅すぎる |
 | サイズごとの状態マルチセットを持つサブシーケンス上の DP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックスを介した DP を定義します。 各プレフィックス i について、k でインデックス付けされた状態を維持します。ここで、k は、最初の i 操作の選択されたサブシーケンスを処理した後のマルチセットの現在のサイズを表します。 各状態は、k 個の要素が残って終了するすべてのサブシーケンスを集約し、そのようなサブシーケンスの数とマルチセットの合計情報の両方を保存します。

マイナス演算は常に最小の要素を削除するため、各状態内で、これまでに生き残ったすべての挿入要素の中で最大の k 個の値を知る必要があるだけです。 これにより、各状態の寄与をサイズが最大 k のソートされた構造として表すことができます。 

シーケンスを一度に 1 要素ずつ処理します。 

1. 空の DP 状態から開始します。ここで、dp[0] には、合計がゼロで空のマルチセットを持つ有効なサブシーケンスが 1 つあります。 
2. 各「+ x」操作について、既存のすべての DP 状態はそれを無視することも、含めることもできます。 無視した場合、状態は変更されません。 これを含めると、マルチセットのサイズが 1 つ増加し、構造体に x が挿入されます。 結果のサイズが状態の容量を超える場合は、継続中の削除により最終的に小さな要素が最初に削除されるため、その状態の最小の要素が削除されます。 
3. 各「-」操作について、すべての DP 状態はそれを無視することも、含めることもできます。 含まれており、状態が空ではない場合、サイズは 1 つ減少し、状態内の最小の要素が削除されます。 状態が空の場合、操作は効果がありません。 
4. すべての操作を処理した後、各 DP 状態は、保存されている合計に到達するサブシーケンスの数を乗算して寄与し、すべての状態の合計を計算します。 

重要な不変条件は、サイズ k の任意の DP 状態について、格納されたマルチセットが常に、そのサブシーケンスで選択されたすべての「+」演算の中で最大 k 個の値に対応することです。 これは、新しい値が挿入され、状態が容量を超えるたびに、最小要素を削除すると、将来のマイナス操作 (常に最小要素が最初に削除される) で正しい構造が保持されるため、当てはまります。 したがって、小さい要素は存続にとって決して有益ではなく、状態表現内で安全に破棄できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def merge_keep_k(a, b, k):
    # merge two sorted descending lists, keep k largest
    i = j = 0
    res = []
    while len(res) < k and (i < len(a) or j < len(b)):
        if j == len(b) or (i < len(a) and a[i] > b[j]):
            res.append(a[i])
            i += 1
        else:
            res.append(b[j])
            j += 1
    return res

def solve():
    n = int(input())
    ops = []
    for _ in range(n):
        parts = input().split()
        if parts[0] == '+':
            ops.append((1, int(parts[1])))
        else:
            ops.append((0, 0))

    dp = [([], 0, 0)]  # (multiset as sorted desc list, ways, sum)
    # dp is indexed by size implicitly via list index
    dp = [[[] for _ in range(n + 1)]]
    ways = [[0] * (n + 1) for _ in range(n + 1)]
    sm = [[0] * (n + 1) for _ in range(n + 1)]

    ways[0][0] = 1

    for typ, val in ops:
        nways = [row[:] for row in ways]
        nsm = [row[:] for row in sm]
        ndp = [[lst[:] for lst in dp_row] for dp_row in dp]

        if typ == 1:
            x = val
            for k in range(n + 1):
                for i in range(n + 1):
                    if ways[k][i] == 0:
                        continue
                    # take
                    nk = k + 1
                    if nk <= n:
                        nways[nk][i + 1] = (nways[nk][i + 1] + ways[k][i]) % MOD
                        nsm[nk][i + 1] = (nsm[nk][i + 1] + sm[k][i] + ways[k][i] * x) % MOD
        else:
            for k in range(n + 1):
                for i in range(n + 1):
                    if ways[k][i] == 0:
                        continue
                    # take minus
                    if i > 0:
                        nways[k][i - 1] = (nways[k][i - 1] + ways[k][i]) % MOD
                        nsm[k][i - 1] = (nsm[k][i - 1] + sm[k][i]) % MOD

        ways, sm = nways, nsm

    ans = 0
    for k in range(n + 1):
        for i in range(n + 1):
            ans = (ans + sm[k][i]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では 2 つの DP テーブルが維持されます。 テーブル`ways[k][i]`現在マルチセット内に k 個の要素があり、i 回の削除が実行された状態に至るサブシーケンスの数をカウントします。 テーブル`sm[k][i]`このようなすべての状態にわたる要素の合計を格納します。 

プラス演算の場合、暗黙的にスキップするか、含めることで、要素数と累積合計の両方が増加します。 マイナス演算の場合、削除によって最小の要素が削除され、DP がすでに有効な構造進化を説明しているため、合計を維持しながら状態 i から i−1 に遷移します。 

すべての算術は 998244353 を法として実行されます。 

## 実用的な例

 ### サンプル 1

 入力:```
-
+ 1
+ 2
-
```状態を (k, i) として追跡します。ここで、k は現在のサイズ、i は処理後のアクティブな要素の数です。 

| ステップ | 操作 | キートランジション |
 | --- | --- | --- |
 | 1 | − | 空の状態のみが変更されません。 
| 2 | +1 | 状態は包含/除外に分割され、+1 が合計に寄与します。 
| 3 | +2 | より大きなマルチセットを構築し、より高い値が累積します。 
| 4 | − | 可能であれば、各状態の最小要素を削除します。 

すべての遷移の後、すべての DP の合計を合計すると 16 になります。 

この例は、マイナス演算が単にカウントを減らすだけでなく、以前に挿入された値と相互作用することを示しています。 

### サンプル 2

 入力:```
+ 5
+ 1
-
```ここで、5 を挿入してから 1 を挿入すると、順序が重要である理由がわかります。 両方が選択されてマイナスが発生した場合は、5 ではなく 1 が削除されます。DP は、寄与する状態で大きい値のみが残ることを正確に保証します。

## 特殊なケース

 主なエッジ ケースは、サブシーケンス内でマイナス演算がプラス演算の前に現れる場合です。 その場合は何もしません。 サイズがゼロの状態は負のサイズに遷移しないため、DP はこれを自然に処理します。 

もう 1 つの特殊なケースは、すべてのプラスの値が同一である場合です。 その後、削除するたびに同一の要素が削除されますが、すべての要素は交換可能であるため、DP は依然として正しい集計を生成します。 

最後のエッジケースは、サブシーケンス内でマイナス演算の数がプラス演算を大幅に上回る場合です。 DP は、現在のサイズを超える余分なマイナス演算が影響を及ぼさないようにし、空の状態の有効性を維持します。
