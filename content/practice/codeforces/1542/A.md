 ## 解決策
 ## 問題の理解

 偶数サイズの数値のコレクション、具体的にはテスト ケースごとに 2n 個の整数が与えられます。 タスクは、すべてのペアが合計が奇数である 2 つの数字で構成されるように、これらの数値を n 個の互いに素なペアに分割できるかどうかを判断することです。 

ペアの一方の数値が偶数で、もう一方の数値が奇数の場合、合計は奇数になります。 したがって、有効な組み合わせはすべて、偶数と奇数が一致する必要があります。 どのペアにも 2 つの偶数または 2 つの奇数を含めることはできません。 

制約から、n は最大 100 で値が小さいため、各テスト ケースの数値は最大 200 個になります。 これにより、テスト ケースごとに最大 O(n²) までのアプローチは十分に高速であることがすぐに分かります。 複雑な最適化を強制されることはありませんが、ペアリングの不必要なシミュレーションは避けるべきです。 

問題の重要な構造は配置ではなく、パリティの数え方にあります。 重要なのは、偶数と奇数がいくつ存在するかということだけです。 

ここでの単純な間違いは、実現可能性をグローバルにチェックせずに、実際に貪欲にペアを構築しようとすることです。 たとえば、最初の奇数と最初の偶数の組み合わせは、別の組み合わせ順序が機能したとしても、後で失敗する可能性があります。 もう 1 つの間違いは、少なくとも 1 つの奇数と 1 つの偶数があれば十分だと考えることです。 カウントが不均衡な場合、これは失敗します。 

素朴な考えによる具体的な失敗例は次のとおりです。 

入力:```
n = 2
array = [1, 3, 2, 4]
```奇数が 2 つと偶数が 2 つあります。 これは機能します。 しかし、少し変更すると、次のようになります。```
n = 2
array = [1, 3, 5, 2]
```これで、オッズが 3 つと偶数が 1 つになりました。 貪欲な試みでもペア (1,2) になる可能性はありますが、オッズが一致しないため、失敗します。 正解はカウントのみに依存します。 

## アプローチ

 ブルートフォースアプローチでは、2n 個の要素のすべてのペアを列挙しようとします。 2n 個の要素をペアに分割する方法の数は (2n) です! / (2^n n!) であり、n = 10 の場合でも非常に速く増加します。各パーティションではパリティのためにすべてのペアの検証が必要になるため、これは完全に不可能になります。 

重要な点は、各有効なペアには偶数と奇数が 1 つずつ含まれている必要があるということです。 つまり、すべての偶数は奇数との組み合わせを 1 つだけ提供し、その逆も同様です。 したがって、偶数の数は奇数の数と等しくなければなりません。 要素の合計は 2n であるため、この条件はちょうど n 個の偶数と n 個の奇数を持つことと同じです。 

これにより、問題は組み合わせによるペアリングから単純な周波数チェックに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペア列挙 | O((2n)! ) | O(2n) | 遅すぎる |
 | カウントパリティ | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 パリティ数を分析することで、各テスト ケースを個別に解決します。 

1. n と 2n の整数のリストを読み取ります。 
2. 偶数の数と奇数の数を数えます。 

数値のパリティは、%2 をチェックすることによって決定されます。 
3. 偶数要素の数が奇数要素の数と等しいかどうかを確認します。 

この条件が必要なのは、すべての有効なペアが偶数と奇数を 1 つずつ消費するためです。 
4. それらが等しい場合は、「Yes」と出力します。 それ以外の場合は、「いいえ」を出力します。 

### なぜ効果があるのか

 有効な各ペアには偶数と奇数が 1 つずつ含まれている必要があるため、各ペアでは各パリティ クラスの要素が 1 つだけ消費されます。 カウントが異なる場合、少なくとも 1 つの要素が反対パリティの有効なパートナーなしで残されます。 逆に、カウントが等しい場合は、パリティを超える値に対する追加の制約がないため、常に偶数を個別の奇数と任意に組み合わせることができます。 これにより、等しいパリティ数の必要性と十分性の両方が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    
    even = 0
    odd = 0
    
    for x in arr:
        if x % 2 == 0:
            even += 1
        else:
            odd += 1
    
    print("Yes" if even == odd else "No")
```ソリューションは、各テスト ケースを個別に反復します。 重要な実装の詳細は、明示的にペアを構築しようとしないことです。 パリティ数のみを追跡することで、不必要な複雑さが回避され、順序の問題が排除されます。 

比較`even == odd`合計サイズは 2n に固定されているため、等しいことは自動的に両方が正確に n であることを意味するため、これで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        even = sum(1 for x in arr if x % 2 == 0)
        odd = 2 * n - even
        
        output.append("Yes" if even == odd else "No")
    
    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての数値が同じパリティを持つ場合です。 

入力の場合:```
n = 2
array = [2, 4, 6, 8]
```アルゴリズムは偶数 = 4、奇数 = 0 をカウントします。これらは等しくないため、「No」を出力します。 有効なペアを形成する奇数の要素が存在しないため、これは推論と一致します。 

もう 1 つのケースは完璧なバランスです。```
n = 3
array = [1, 2, 3, 4, 5, 6]
```ここでは偶数 = 3、奇数 = 3 です。アルゴリズムは「Yes」を出力し、(1,2)、(3,4)、(5,6) などの有効なペアが存在します。 これにより、パリティ条件が十分であることが確認されます。
