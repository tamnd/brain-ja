 ## 解決策
 ## 問題の理解

 私たちには多くの問い合わせが寄せられます。 各クエリは非常に大きな整数を提供します$n$、そしてすべての整数を考慮します$i$1から$n$。 それぞれについて$i$、関数を定義します$f(i)$割り切れない最小の正の整数として$i$。 この値を計算した後、$i$、すべての結果を合計します。 

タスクは、次の場合でもこの合計を効率的に計算することです。$n$と同じくらい大きいです$10^{16}$、最大で$10^4$クエリ。 

重要な難点は、$f(i)$約数の構造に依存します$i$、そして大きい場合$i$約数を直接因数分解したり列挙したりすることはできません。 

制約$n \le 10^{16}$までのすべての値を反復するアルゴリズムは直ちに除外されます。$n$。 平$O(\sqrt{n})$テストごとには不可能です$10^4$テスト。 個々の整数ではなく、関数内の少数の「構造変化」に依存する解決策が必要です。 

微妙なエッジケースは誤解です$f(i)$。 これは欠落している最小の約数ではありません$i$素因数分解という意味ですが、除数セットに含まれない最小の整数です。 たとえば、次の場合$i = 12$、その約数には以下が含まれます$1,2,3,4,6,12$、 それで$f(12) = 5$。 単純な実装では、これが素因数のみに依存すると誤って認識し、複合ギャップを見逃してしまう可能性があります。 

別の失敗例は計算しようとしている場合です$f(i)$それぞれ独立して$i$。 たとえ除数の列挙が最適化されたとしても、これをすべてに対して実行すると、$i \le n$遅すぎます。 

## アプローチ

 まず直接的なアプローチを考えます。 それぞれについて$i$、割り切れない整数が見つかるまで、1 から始めて整数をチェックしてみます。$i$。 これが機能するのは、割り算のチェックが簡単で正確さが保証されるためです。 ただし、それぞれの数字は、$i$には小さな約数が多数ある可能性があり、最悪の場合 (高度に合成された数の場合)、最初に不足している約数を見つける前に多くの候補をチェックする可能性があります。 全員のためにこれを行う$i \le n$おおよそにつながります$O(n \sqrt{n})$実装によっては動作が悪化することもありますが、これは不可能です$10^{16}$。 

重要な洞察は、視点を逆転させることです。 コンピューティングの代わりに$f(i)$直接、各候補値を尋ねます$x$: 数字はいくつ$i \le n$すべての整数を持っています$1,2,\dots,x-1$分割する$i$、 しかし$x$分けない$i$? これにより、問題は最小公倍数の倍数を数える問題に変わります。 

もし$i$からのすべての整数で割り切れます$1$に$x-1$、 それから$i$で割り切れる必要があります$\mathrm{lcm}(1,2,\dots,x-1)$。 以下を定義しましょう:$$L_x = \mathrm{lcm}(1,2,\dots,x)$$次に:

 - 数字$f(i) > x$まさに次の倍数です$L_x$、
 - 数字$f(i) = x$の倍数です$L_{x-1}$しかしそうではありません$L_x$。 

したがって、貢献度を次の値ごとにグループ化できます。$x$を繰り返す代わりに、$i$を繰り返します$x$。 重要な観察は、$L_x$非常に早く成長します。 実際には、次の場合にのみ増加します。$x$新しいプライムパワーを導入します。 これは、次の値のみを考慮する必要があることを意味します。$x$いずれも最大約50$n \le 10^{16}$。 

それぞれの寄与間隔を計算します。$x$として：$$\text{count}(x) = \left\lfloor \frac{n}{L_{x-1}} \right\rfloor - \left\lfloor \frac{n}{L_x} \right\rfloor$$そしてそのような各グループが貢献します$x \cdot \text{count}(x)$答えに。

 ## アルゴリズムのチュートリアル

 1. の値を事前計算します。$L_x = \mathrm{lcm}(1,2,\dots,x)$から始まる$x = 1$。 一度止めてください$L_x > 10^{16}$。 この点を超えると、すべてのクエリの寄与がゼロになるため、これは機能します。 
2. 値を持つクエリごとに$n$、答えを0として初期化します。 
3. 事前に計算されたすべての結果を反復処理します。$x$から始まる値$x = 2$。 それぞれについて$x$、数値がいくつあるかを計算します$i \le n$満足する$f(i) = x$。 これは、連続する LCM しきい値の倍数間の差によって決定されます。 
4.追加$x \cdot (\lfloor n / L_{x-1} \rfloor - \lfloor n / L_x \rfloor)$答えに。 この式は、欠落している約数の最小値が次の数値である数値を正確に分離します。$x$。 
5. まで続けます$L_{x-1} > n$, この時点を超えると、すべての貢献はゼロになるためです。 
6. 累積和モジュロを出力します。$10^9 + 7$。 

安全に早めに停止できる理由は、$L_{x-1} > n$、番号なし$i \le n$以下のすべての整数で割り切れます$x-1$、 それで$f(i) < x$残りのすべてのケースについて。 

### なぜ効果があるのか

 整数を分割するアルゴリズム$i \le n$分割できない最小の整数に基づいて素グループに分割します。 条件$f(i) = x$と言うのと同じです$i$すべての整数で割り切れます$1$を通して$x-1$、ただし割り切れない$x$。 これらの条件は、次のような割り算に直接変換されます。$L_{x-1}$と割り切れないこと$L_x$。 これらのセットは互いに素であり、すべての整数をカバーするため、すべての整数の合計は$x$はまさに必要な合計です$f(i)$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

MOD = 10**9 + 7

# Precompute lcms of prefix [1..x]
lcm_vals = [1]

def lcm(a, b):
    return a // math.gcd(a, b) * b

x = 1
while True:
    nxt = lcm(lcm_vals[-1], x)
    if nxt > 10**16:
        break
    lcm_vals.append(nxt)
    x += 1

# lcm_vals[k] = lcm(1..k)
# we start from k = 0 meaning 1..0 is 1

def solve(n):
    ans = 0
    # f(i) = x contributes using L_{x-1}, L_x
    for x in range(2, len(lcm_vals)):
        L_prev = lcm_vals[x-2]
        L_curr = lcm_vals[x-1]
        if L_prev > n:
            break
        cnt = n // L_prev - n // L_curr
        if cnt > 0:
            ans = (ans + x * cnt) % MOD
    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve(n))
```コードは、プレフィックス LCM のシーケンスを構築することから始まります。LCM は新しいプライム パワーが導入された場合にのみ増加するため、すぐに安定します。 各クエリは、この事前に計算された小さなリストをスキャンすることによって処理されます。 

実装の微妙な詳細はインデックス作成です。`lcm_vals[k]`を表します$L_k$。 これによりインデックスがシフトされ、価値への貢献が$x$使用$L_{x-1}$そして$L_x$。 この 1 つずつのずれは間違いの最も一般的な原因です。 

掛け算$x \cdot cnt$剰余が取られます$10^9+7$ただし、除算ロジックは整数で行われます。$n$到達できる$10^{16}$。

 ## 特殊なケース

 エッジケースの 1 つは、$n = 1$。 唯一の数字は、$i = 1$、その約数は 1 のみであるため、欠落している正の整数の最小値は 2 です。アルゴリズムはこれを処理します。$L_1 = 1$、 そして$L_2 = 2$すでに超えています$n$、したがって、$x = 2$term が寄与し、正確に 1 つのカウントが得られます。 

もう一つのケースは次のような場合です。$n$は非常に大きいですが、それでも LCM のジャンプよりは小さいです。 例えば$n = 10^{16}$。 このアルゴリズムは依然として、少数の固定数の LCM 値を反復するだけです。 各反復では広い範囲の倍数が正しく計算され、減算により二重カウントが回避されます。 

3 番目のケースは、次の場合に早期終了する場合です。$L_{x-1} > n$。 そんな方のために$x$、両方のフロア項がゼロであり、ループが正しく中断され、到達可能な可分性構造を超える不必要な計算が行われないことが保証されます。
