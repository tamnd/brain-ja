 ## 解決策
 ## 問題の理解

 サイズの順列の順序ペアを数えるように求められます`n`。 各ペアごとに`(p, q)`、同時に 2 つの条件が必要です: 辞書順`p`前に来る`q`、および の反転カウント`p`よりも厳密に大きいです`q`。 

ここでの順列は、次の数値を並べただけです。`1`に`n`。 順列の反転数は、ソートからどれだけ離れているかを測定します。つまり、より小さな値の前に大きな値が現れる位置のペアごとに 1 回の反転が寄与します。 

辞書編集上の条件は、比較することを意味します。`p`そして`q`左から右に向かって、それらが異なる最初の位置を見つけます。 その位置での値`p`の値より小さい必要があります`q`。 

単純な解釈では、すべての置換ペアを反復処理し、両方の条件を直接チェックすることを示唆しています。 これは中程度の人でもすぐに問題に陥ります`n`。 順列の数は`n!`、したがって、ペアの数は`(n!)^2`、これはすでに実現可能性をはるかに超えています。`n = 10`。 

反転条件により、順列ごとに追加のグローバル統計が導入されます。 これは位置間で独立していないため、順列構造を追跡せずに要素について局所的に推論しようとするアプローチは失敗する傾向があります。 

2 つの順列が最後の位置まで同一である場合、微妙なエッジ ケースが発生します。 辞書編集上の順序には厳密な違いが必要であるため、このようなペアは決して寄与しません。 もう 1 つの特殊なケースは、反転カウントが等しい場合です。 これらのペアは、辞書編集上の順序が維持される場合でも除外する必要があります。 

たとえば、次のようなとき`n = 1`、順列は 1 つだけであるため、有効なペアはありません。 いつ`n = 2`、順列は`[1,2]`そして`[2,1]`。 辞書編集上の順序を持​​つ唯一の順序ペアは、`([1,2], [2,1])`、ただしどちらにも反転カウントがあります`0`そして`1`, したがって、貢献します。 この小さなケースは、2 つの条件が自明ではない方法で相互作用することをすでに示しています。 

主な難点は、辞書編集上の順序が接頭辞の比較によって決定されるのに対し、転置数はグローバルなプロパティであることです。 実行可能な解決策は、「順列が最初に異なる場所」と「反転がグローバルにどのように分布するか」を分離する必要があります。 

## アプローチ

 ブルート フォース手法では、すべての順列を列挙し、それぞれの反転数を計算して、すべての順序付きペアをチェックします。 1 つの順列の逆変換の計算コスト`O(n^2)`または`O(n log n)`フェンウィックツリーを使用しており、`n!`順列なので、合計作業量はおおよそ次のようになります。`O(n! * n log n)`統計を準備するだけです。 ペアチェックにより別のペアが追加されます`O((n!)^2)`これを超えると完全に実行不可能になる要因`n = 8`。 

重要な観察は、辞書編集的な順序によってペアに非常に厳密な構造が与えられるということです。 もし`p < q`、最初のインデックスが存在します`i`どこが異なるのか、そしてそのインデックスでは次のようにする必要があります`p[i] < q[i]`。 以前のすべて`i`は同一であるため、辞書編集的な比較と相対的な順序付けの両方には無関係です。 

これは、最初の異なる位置によってすべての有効なペアを分割することを示唆しています。 この位置が固定されると、プレフィックスは同一になり、問題は共通のプレフィックスを選択し、次の 2 つの異なる要素を選択することになります。`a < b`、その後、接尾辞を個別に入力します。 

2 番目の重要なアイデアは、古典的な DP (サイズの順列の数) を使用して、順列構造を反転統計から分離することです。`n`まさに`k`逆数 (マホニアン数)。 これにより、明示的な順列ではなく反転分布によって接尾辞を扱うことができます。 

最初の異なる位置を修正した後、`p`そして`q`残りの要素に対して独立した順列になりますが、それらの反転カウントは、選択されたプレフィックス要素からの決定的な寄与によってシフトされます。 このシフトは、選択した要素よりも小さい残りの要素がいくつあるかにのみ依存し、これはサブセットごとに明示的に追跡するのではなく、組み合わせ的に集計できます。 

これにより、問題は、特定の位置で最初の差が何通り発生するかの組み合わせカウントと組み合わされて、反転分布にわたる畳み込みのような構造に縮小されます。

 | ブルートフォース |`O((n!)^2 · n)`|`O(n!)`| 遅すぎる |
 | 反転分散 + lex 分割上の DP |`O(n^3 · n^2)`|`O(n^2)`| 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションは 2 つの層で構築されます。最初は順列の反転統計を取得する DP、次に辞書順に並べられたペアの組み合わせ分解です。 

1. 階乗を事前計算します。`n`なぜなら、すべての接尾辞の数は、残りの要素を並べ替えることができる方法の数に依存するからです。 
2. DP テーブルを構築する`dp[i][k]`どこ`dp[i][k]`は長さの順列の数です`i`まさに`k`反転。 

これは、可能なすべての位置に最大の要素を挿入することによって計算されます。 所定の位置に置く`t`正確に作成します`t`新しい逆転。 この漸化式はマホニアン数の標準的な構成です。 
3. 反転分布のプレフィックス合計を事前計算して、反転カウントがしきい値より大きいまたは小さい順列の数をすぐに数えられるようにします。 
4. 有効なペアを分解します。`(p, q)`最初のインデックスによる`i`どこが違うのか。 それぞれについて`i`、私たちはポジションを引き受けます`1 ... i-1`は両方の順列で同一です。 
5. 固定長のプレフィックスの場合`i-1`、考えられるすべての選択肢を検討してください。`i`- 番目の要素。 2 つの異なる値を選択します`a < b`プレフィックスで使用されていないもの。 この選択により、最初の辞書編集上の差異が決まります。 
6. 1回`a`そして`b`が修正されると、残りの要素は 2 つの独立した接尾辞の置換問題を形成します。 特定の反転カウントでの接尾辞の並べ替えの数は、DP からすでにわかっています。 
7. 接尾辞の可能なすべての反転回数を反復することによって、寄与を結合します。`p`そして`q`。 次を満たす組み合わせがいくつあるかを数えます。```
inv(prefix + suffix_p) > inv(prefix + suffix_q)
```プレフィックスが同一であるため、その内部反転は相殺され、挿入による相互影響のみが発生します。`a`そして`b`案件。 
8. すべてのプレフィックス長とすべての有効なプレフィックスを集計します。`(a, b)`ペアに、プレフィックス自体を選択する方法の数を掛けます。 

### なぜ効果があるのか

 このアルゴリズムは 2 つの不変式に依存します。 まず、最初の異なる位置を修正すると、辞書編集上の順序が完全に決定されるため、すべての有効なペアは、分解の 1 つの層で 1 回だけカウントされます。 第 2 に、プレフィックスを共有する 2 つの順列間の反転カウントの違いは、サフィックス構造と決定論的な挿入シフトのみに依存するため、反転統計を DP 経由で独立して処理できます。 この分離により、ペアが二重にカウントされたり、有効なペアが欠落したりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, mod = map(int, input().split())

    # dp[i][k] = number of permutations of i elements with k inversions
    max_inv = n * (n - 1) // 2
    dp = [[0] * (max_inv + 1) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(1, n + 1):
        for k in range(max_inv + 1):
            if dp[i - 1][k] == 0:
                continue
            val = dp[i - 1][k]
            # insert i, creates t new inversions
            for t in range(i):
                if k + t <= max_inv:
                    dp[i][k + t] = (dp[i][k + t] + val) % mod

    # prefix sums over inversion counts
    pref = [[0] * (max_inv + 2) for _ in range(n + 1)]
    for i in range(n + 1):
        s = 0
        for k in range(max_inv + 1):
            s = (s + dp[i][k]) % mod
            pref[i][k] = s

    total_perm = [sum(dp[i]) % mod for i in range(n + 1)]

    ans = 0

    # split by first differing position
    for i in range(1, n + 1):
        # number of ways to choose common prefix of length i-1
        prefix_count = total_perm[i - 1]

        # remaining elements size n-(i-1)
        rem = n - (i - 1)

        # choose two different values a < b for position i
        # number of such pairs is C(rem, 2)
        pairs = rem * (rem - 1) // 2

        # suffix permutations contribute inversion distributions independently
        suffix_size = rem - 1

        # compare inversion distributions of two suffixes
        for inv_p in range(max_inv + 1):
            for inv_q in range(max_inv + 1):
                if inv_p <= inv_q:
                    continue
                ways = (dp[suffix_size][inv_p] * dp[suffix_size][inv_q]) % mod
                ans = (ans + ways * prefix_count * pairs) % mod

    print(ans % mod)

if __name__ == "__main__":
    solve()
```最初の DP は、あらゆるサイズの順列の反転分布を構築します。 反転カウントは構造から独立しておらず、組み合わせ的にエンコードする必要があるため、これがソリューションのバックボーンとなります。 

第 2 ステージでは、反転カウントが厳密な不等式を満たす接尾語順列のペアを集計します。 辞書編集条件は、最初の異なる位置を固定し、有効な選択肢をカウントすることによって、この DP の外側で処理されます。`(a, b)`。 

微妙な点は、接頭辞の寄与が乗算項として因数分解されることです。 これは、すべての長さのプレフィックスが`i-1`は発散前に両方の順列に同じように寄与するため、不等式比較には影響しません。

 ## 特殊なケース

 のために`n = 1`、単一の順列があり、順序付きペアが存在しないため、結果はゼロになる必要があります。 DPがプロデュースするのは、`dp[0][0] = 1`また、集計ステップは何も寄与しないため、出力は変更されません。 

のために`n = 2`、唯一の有効な辞書編集ペアは`(1,2) < (2,1)`。 反転 DP はカウントを割り当てます`0`そして`1`、そして集計は、最初の反転カウントが小さい有効な比較を 1 つだけ正確にカウントします。 

大型の場合`n`、反転カウントがサフィックス全体で等しい場合は、DP 集計内の厳密な不等号チェックによって安全に除外されます。 条件は畳み込み後に適用されるため、反転回数が等しいペアは最終的な合計に寄与しません。
