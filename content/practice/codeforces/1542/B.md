 ## 問題の理解

 数字から始めます$1$。 すでにセットに含まれている任意の数値から、次の 2 つの演算のいずれかを実行できます。$a$、または追加$b$。 これらの操作を任意の順序で何度でも適用すると、到達可能な値の無限のセットが得られます。 

テストケースごとに、次のものが与えられます。$n$、$a$、 そして$b$。 タスクは、次のことを判断することです。$n$から開始して生成できます$1$。 

制約は、力任せが機能しないことを示す最初の手がかりです。 まであります$10^5$テスト ケース、および各パラメーターは次のように大きくできます。$10^9$。 到達可能な状態を直接探索するアプローチは、すぐに爆発してしまいます。セットは無限であり、最大の値に制限されるためです。$n$何十億もの数字を調べる必要があるかもしれません。 

ソリューションは、各テスト ケースをほぼ対数時間で処理する必要があります。 以来$a \le 10^9$、乗算を繰り返す$a$を超える$10^9$せいぜい30歩くらいの段階で$a \ge 2$。 これは、次の力に焦点を当てるべきであることを示唆しています。$a$、生成されたセット全体ではありません。 

いくつかの特殊なケースは見落とされがちです。 

考慮する$a=1$。 乗算は何もしないので、唯一有用な演算は加算を繰り返すことです。$b$。 例えば：```
n=13, a=1, b=4
```到達可能な数値は、$1,5,9,13,\dots$, したがって、答えは「はい」です。 盲目的に次の力を生成するソリューション$a$永遠にループしてしまうので、$1,1,1,\dots$決して変わりません。 

もう 1 つの注意が必要なケースは次のような場合です。$n$それ自体が力です$a$。```

```単純に4倍することができます。 追加は必要ありません。 答えは「はい」です。$$81 = 3^4 + 0\cdot 5.$$少なくとも 1 つの加算を使用することを要求するソリューションは失敗します。 

3 番目のケースは、乗算の前に加算を行う必要がある場合です。```
n=24, a=3, b=5
```有効な構造の 1 つは、$$1 \to 6 \to 8 \to 24.$$この順序は、「すべての乗算、次にすべての加算」だけではありません。 操作順序の直接シミュレーションは複雑に見えますが、数学的構造により、順序は最終テストには無関係であることがわかります。

 ## アルゴリズムのチュートリアル

 1.読む$n$、$a$、 そして$b$。 
2. もし$a=1$、乗算によって現在の値が変更されることはありません。 

到達可能な唯一の番号は、$$1,\ 1+b,\ 1+2b,\dots$$かどうかを確認してください$$(n-1)\bmod b = 0.$$「はい」の場合、印刷します`"Yes"`、それ以外の場合は印刷します`"No"`。 
3. もし$a>1$、現在の電力が次の値に等しい状態から開始します。$1$。 
4. 現在の電力が最大である間、$n$かどうかをテストします。$$(n-\text{power})\bmod b = 0.$$これが当てはまるなら、$$n=\text{power}+mb$$負でない整数の場合$m$、 それで$n$到達可能です。 印刷する`"Yes"`このテスト ケースの処理を停止します。 
5. それ以外の場合は、現在の電力を次のように乗算します。$a$そして続けます。 
6. のすべてのべき乗の場合$a$まで$n$チェックされましたが、何も機能しません。印刷します`"No"`。 

### なぜ効果があるのか

 到達可能なすべての数値は次の累乗として見ることができます。$a$さらにいくつかのサイズの追加$b$。 乗算の最終カウントを次のように修正します。$k$。 乗算部分が寄与します$a^k$、加算は次で割り切れる量を寄与します。$b$。 したがって、到達可能なすべての数値は次の条件を満たします。$$n=a^k+mb.$$逆に、一部の人にとっては、$k$我々は持っています$$n=a^k+mb$$と$m\ge 0$、から始まります$1$、出演$k$乗算は与えます$a^k$、そしてパフォーマンス$m$追加は与える$n$。 したがって、アルゴリズムは到達可能性の必要十分条件を正確にチェックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, a, b = map(int, input().split())

    if a == 1:
        print("Yes" if (n - 1) % b == 0 else "No")
        continue

    cur = 1
    ok = False

    while cur <= n:
        if (n - cur) % b == 0:
            ok = True
            break
        cur *= a

    print("Yes" if ok else "No")
```最初のブランチのハンドル$a=1$。 これがなければ、べき乗のループは決して終了しません。$1$現在の値を変更しないままにします。 

変数`cur`の連続的な力を保存します$a$:$$1,\ a,\ a^2,\dots$$各べき乗について、残りの差が次の値になるかどうかをテストします。$n$で割り切れます$b$。 割り算チェックが成功した場合は、残りの量をすべて加算演算によって供給できることを意味します。 

Python の整数は任意のサイズに自動的に拡張されるため、オーバーフローの心配はありません。 ループは一旦停止します`cur > n`なぜなら、より大きな権力は代表に参加できないからです。$$n=a^k+mb$$と$m\ge 0$。
