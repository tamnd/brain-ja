 ## 解決策
 ## 問題の理解

 整数の行が与えられ、2 人のプレイヤーが順番に何も残らないまで要素を削除します。 ウィリアムが最初に動き、自分の番で配列内の任意の場所からまだ利用可能な要素を選択できます。 ロボットは戦略的に選択することはまったくありません。各ステップで常に左端に残っている要素を削除します。 

ウィリアムの目標は、収集した価値の合計を最大化することです。 ロボットの決定論的な動作は、ウィリアムの選択が決まれば、残りの配列の進化が完全に予測可能であることを意味します。したがって、問題は敵対ゲーム理論に関するものではなく、ロボットが左からの構造を消費する前にウィリアムがどの位置を「主張する」かを制御することです。 

重要な問題は、ウィリアムの選択が将来の可用性に間接的に影響することです。 左側の貴重な要素を選択するのが遅れると、ロボットがそれを先に消費してしまう可能性があります。 一方で、何かを早く選択しすぎると、ロボットが低価値の要素を取得することを強制されるプレフィックスの「ターンバジェット」を無駄にする可能性があります。 

n が 100000 までという制約は、すべての解が線形または n log n に近い必要があることを意味します。 可能なすべての選択シーケンスをシミュレートしたり、要素のサブセットを明示的に考慮したりするアプローチは、大まかなサブセット探索でさえ指数関数的に増大するため、不可能です。 これにより、要素を順番に処理し、William が効果的に保持できる内容のコンパクトな表現のみを保持する、貪欲な方法またはデータ構造ベースの方法が求められます。 

ロボットの左端のルールから、微妙なエッジケースが発生します。 たとえば、10 1 100 1 のような配列について考えてみましょう。単純な考えでは、William は常に利用可能な最大の要素を取得する必要がありますが、ロボットが左から繰り返し消費した後、プレフィックス クォータ内で取得しないと一部の「大きな」値にアクセスできなくなる可能性があることを無視しています。 もう 1 つの失敗ケースは、大きな値が早期にクラスタリングされる場合です。これは、ロボットがすでにそれらのプレフィックス要素の半分を取得しているという事実に違反することなく、William が初期のプレフィックスで大量の値を取得することができないためです。 

したがって、実際の制約は、元のゲーム シーケンスの隣接性に関するものではなく、プレフィックスの容量に関するものです。ロボットは常にそのプレフィックスの残りを左からロックステップで消費するため、最初の k 要素内で、William は最終的に約 k/2 要素以上を取得することはできません。 

## アプローチ

 ロボットの決定論的な動作を無視する場合、強引なアイデアは、ゲームの状態をシミュレートすることになります。各ステップで、ウィリアムの可能なすべての選択肢を試し、ロボットの強制的な動きをシミュレートして続行します。 これにより、残りの要素の数と深さ n に等しい分岐係数が生成され、階乗または指数関数的な複雑さが生じます。 メモ化でさえも失敗するのは、どの要素が残っているかだけでなく、左の削除を繰り返した後の状態がその順序にも影響するためであり、それでも個別の構成が多すぎるためです。 

重要な点は、「削除後の残りの配列」という観点から考えるのをやめ、代わりにプレフィックス制約という観点から考えることです。 最初の k 個の位置を処理した後、合計で正確に k 個の要素が削除され、それらはウィリアムとロボットの間で分割されます。 ロボットは常に左端の利用可能な要素を消費するため、長さ k のすべてのプレフィックスにおいて、ウィリアムがカウントを独占できないことが事実上保証されます。 これにより、ウィリアムは最初の k 位置のうち選択された要素を最大 k/2 までしか「保持」できないという制約が生じます。

その解釈を受け入れると、問題は次のようになります。配列を左から右に処理し、偶数のインデックス k ごとに、最初の k 要素内で最大で k/2 の選択が保持されるように、ウィリアムが選択した要素のセットを維持します。 ウィリアムは最大の合計を求めているため、初期に選択した小さな要素が多すぎる場合は常に、その中の最小の要素を破棄する必要があります。 これは当然、サイズ制約の下で最大の利益の選択を維持することを示唆していますが、最も役に立たない選択された要素を破棄しているため、実際には、William の現在の選択の中から最小の候補を削除できる構造を維持したいと考えています。 

最小ヒープはまさにこの要件に適合します。暫定的にすべての要素を William のセットの候補として含め、選択された要素の数が現在のプレフィックスに許可されている割り当てを超える場合は常に、最小値を削除します。 これにより、William は常に実現可能性と一致する最良の選択のマルチセットを保持することが保証されます。

 ## アルゴリズムのチュートリアル

 配列を左から右にスキャンし、あたかもウィリアムがそれを取得しようとしているかのように各位置を扱います。 

1. William が暫定的に選択したセットを表す最小ヒープに現在の値を挿入します。 これは、ウィリアムが最初にすべてを実行することを検討していることを前提としており、後で弱い選択肢を削除することで実行不可能性を修正します。 
2. インデックス k を処理した後、ウィリアムがプレフィックス 1 から k までに保持できる要素の数を計算します。 ロボットは常に左端の使用可能な要素を取得するため、どのプレフィックスでも、William はそれらの位置に k/2 を超える要素を含めることができないため、k が偶数の場合にのみその制約を適用します。 
3. k が偶数で、ヒープ サイズが k/2 を超える場合は、制約が満たされるまでヒープから最小の要素を繰り返し削除します。 最小のものを削除する理由は、より大きな要素を保持すると、実現可能性を考慮しながら常に最終的な合計が向上するためです。 
4. 配列の最後まで続けます。 ヒープに残っている要素の合計が、William の達成可能な最大スコアになります。 

重要な点は、ロボットの動きを明示的にシミュレートすることは決してないということです。 ヒープは、重要な唯一の構造的制約を強制します。つまり、ウィリアムの選択は、合計で各プレフィックスのちょうど半分を消費するロボットとの互換性を維持する必要があります。 

### なぜ効果があるのか

 不変条件は、プレフィックス k を処理した後、ヒープにはロボットの強制左端除去ルールに基づいて有効なゲーム結果に拡張できるプレフィックスからの要素の最大合計サブセットが含まれるということです。 ロボットの動作により、残りの容量は左から消費されるため、長さ k の任意のプレフィックス内で、正確に k/2 個の要素が最大でも William に対して効果的に「予約」されることが保証されます。 制約に違反した場合に選択された最小の要素を常に破棄することで、k とともに増加するマトロイドのようなカーディナリティ制約の下で可能な限り最良の値のサブセットを維持します。 これにより、将来の決定において、より大きな要素ではなくより小さな要素を以前に保持しておくことによるメリットが得られないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    heap = []
    total = 0
    
    for i, x in enumerate(a, start=1):
        heapq.heappush(heap, x)
        
        if i % 2 == 0:
            limit = i // 2
            while len(heap) > limit:
                heapq.heappop(heap)
    
    print(sum(heap))

if __name__ == "__main__":
    solve()
```このソリューションは、William が現在選択している値の最小ヒープを維持します。 すべての要素がすぐに追加され、その後、偶数の位置でプレフィックスの実現可能性制約が適用されます。 ヒープ ポップ操作では常に、選択された最小値が削除されます。これは、合計の損失を最小限に抑えるため、唯一の安全な破棄です。 

よくある実装上の間違いは、制約が最後だけでなくプレフィックスごとに適用されることを忘れていることです。 もう 1 つは、最大ヒープを使用する方法です。これは、最も価値のある要素ではなく、選択した最も価値の低い要素を破棄する必要があるため、ロジックが壊れます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各要素はヒープから 1 回プッシュされ、場合によっては 1 回ポップされます。 
| スペース | O(n) | ヒープには最大で n/2 個の要素が格納されます。 

ヒープ操作は標準の制限内で十分な速度を維持できるため、n ～ 100000 の制約は O(n log n) 内に快適に収まります。

 ## 特殊なケース

 重大なエッジケースは、大きな値が早期に出現する場合です。たとえば、`100 1 99 1`。 単純な貪欲戦略では、100 と 99 がすぐに取得されますが、ロボットが介在する要素を消費し、将来の柔軟性が低下するため、プレフィックスの実現可能性に違反する可能性があります。 このアルゴリズムはすべての値を挿入しますが、すぐにプレフィックス制約を適用します。これにより、容量を超えた場合に最小の初期ピックが強制的に削除され、後のプレフィックスのために高い値が保持されます。 

もう 1 つのエッジ ケースは、次のような高値と低値が交互に現れることです。`1 100 2 99 3 98`。 ここではヒープが急速に増大するため、定期的なプルーニングを行わないと、選択内容が許容プレフィックス数を超えてしまいます。 このアルゴリズムは、偶数の各インデックスで最も弱い選択肢を一貫してトリミングし、利用可能な最大値を維持しながら、ウィリアムの選択が決して実行不可能にならないようにします。
