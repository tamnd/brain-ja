 ## 問題の理解

 私たちには循環構造が与えられています。`n`それぞれの位置に値が含まれます。 プロセスは「ステップ サイズ」を選択することで定義されます。`d`を追加して、円の周りを繰り返しジャンプします。`d`モジュロ`n`。 これにより、あるインデックスから開始する決定論的な軌道が作成されます。`s`、訪問します`s, s + d, s + 2d, ...`モジュロ`n`。 

このような各軌道は、円を、次の要素によって完全に決定される互いに素なサイクルに分割します。`d`。 この移動プロセスに伴い、最大で次のことを行うことが許可されています。`m`アクション (「ショット」) であり、各ショットはこれらの軌道の 1 つに沿った連続セグメントの選択に対応します。 目標は、収集される合計値が最大化されるように、考えられるすべてのステップ サイズと軌道にショットを分散する方法を選択することです。 

重要な微妙な点は、変化することです。`d`円の分解を独立した周期軌道に完全に変更し、各軌道内で制約付きサブアレイ選択問題を解決します。 

出力は、ステップ サイズのすべての可能な選択に対して達成可能な単一の最大合計です。`d`最大で`m`ショット。 

ソリューション構造によって暗示される制約から、`n`二次関数が動作するほど十分に大きい`n`不可能です。 すべてのステップ サイズとすべての部分配列を単純に列挙すると、少なくとも次のように爆発します。`O(n^2)`あるいはさらに悪いことに。 これはすぐに次のような構造を示唆しています。`gcd(n, d)`が中心となるのは、それが軌道サイズと繰り返し構造を決定するためです。 

不注意なアプローチは通常、次の 3 つの点で失敗します。 まずはそれぞれの治療を`d`独立して配列を再構築すると、繰り返しが発生します`O(n)`あたりの作業`d`、TLEの原因となります。 

第 2 に、軌道の周期的な性質を無視すると、部分配列の処理が不正確になります。 たとえば、次の場合`n = 6`そして`d = 2`、から始まる軌道`0`は`0,2,4,0,2,4`ただし、線形配列としてこれを誤って平坦化すると、次のようなラップアラウンド部分配列が失われます。`[4,0,2]`。 

第三に、巡回 DP で複数のラップアラウンド サブ配列を許可すると、オーバーカウントが発生します。 たとえば、円が`[1,1,1,1]`2 つのラップ セグメントを分離せずに許可すると、同じ循環寄与が事実上 2 重にカウントされます。 

## アプローチ

 ブルートフォースの観点は、あらゆるステップサイズを試すことです`d`、すべての軌道を構築し、各軌道内であらゆる方法でピックアップを試みます。`m`合計を最大化するために互いに素なセグメント。 これは、定義を直接反映しているため、正しいです。各構成は一度独立しています。`d`は固定されており、セグメントはその構造内で最適に選択されます。 

ただし、固定の場合は、`d`、軌道分解によりすでに配列が次のように分割されています。`g = gcd(n, d)`それぞれの長さの独立したサイクル`n / g`。 1 つの軌道内のすべての部分配列を反復するだけでも、`O((n/g)^2)`、最大でDPを実行します`m`セグメントがそれを実現します`O((n/g) * m^2)`軌道ごとに。 全体を合計すると`d`、代数的再利用なしで素朴に実行すると、これは大きすぎます。 

重要な観察は、軌道が任意の順列ではないということです。 これらはモジュラー演算によって引き起こされる構造化されたサイクルです。 すべての軌道は円形配列のように動作し、次のステップを実行します。`d`これは、圧縮表現で連続するインデックスを移動することと同等です。 これが認識されると、各軌道は古典的な問題に帰着します。つまり、以下を選択するというものです。`m`巡回配列の和を最大化する部分配列。 

2 番目の重要なアイデアは、巡回サブ配列の最適化を線形 DP と補数トリックの組み合わせに変えることです。 ラップアラウンドを直接処理する代わりに、ラップ セグメントが存在しないか、ラップ セグメントが 1 つだけ存在するものとして問題を扱います。これは、合計から最小のサブ配列選択を差し引いたものを使用して処理できます。 

最後に、軌道を横切るナップザックは、独立した軌道への貢献を地球規模の予算配分問題に結び付けます。`m`ショット。

 ## アルゴリズムのチュートリアル

 ステップサイズを修正します`d`繰り返し添加することによって誘導される構造を分析します。`d mod n`。 

まず、計算します`g = gcd(n, d)`。 これにより、独立したサイクルがいくつ存在するかが決まります。 各サイクルは 1 つの剰余クラス モジュロに対応します`g`、各クラス内では、軌道はサイズの順列になります。`n / g`。 

2 番目に、インデックスをウォーキングすることによって各軌道を明示的に構築します`r, r + d, r + 2d, ...`モジュロ`n`帰るまで。 これにより、その軌道の巡回配列表現が生成されます。 

第三に、各軌道を独立して扱います。 単一の軌道について、最大でどのくらいの値を抽出できるかを知りたいと考えています。`m`各ショットは、巡回配列上の連続セグメントの選択に対応します。 

4 番目に、周期的な処理を線形 DP に変換します。 線形化された軌道上で 2 つの古典的な DP テーブルを計算します。 正確に取得するための最適な合計を追跡します`j`位置で終わるサブ配列`i`、そして別のトラックを最もよく要約すると、`i`。 これにより、最大で最適なセグメンテーションが可能になります。`m`線形配列内の互いに素な間隔。 

5 番目に、これを周期的な動作に拡張します。 循環最適解は、完全に線形ケースに含まれる (ラップ セグメントなし) か、終了と開始を接続するラップ セグメントを使用します。 これを明示的にモデル化する代わりに、軌道の合計を計算し、同じ DP の最小合計バージョンを差し引きます。これにより、ラップを使用して最適な構成が効果的に取得されます。 

6 番目に、各軌道に対して関数ができました。`orbit_dp[t]`、これは正確に使用して達成可能な最大合計を与えます。`t`その軌道上でのショット。 

7番目に、ナップザックを使用して軌道を結合します。 私たちはグローバルな DP 予算をオーバーショットで維持しています。 軌道ごとに、`t`それに応じてグローバル状態を更新します。 

8 番目に、有効なすべてを反復処理します。`d`まで`n/2`、軌道構造と寄与を再計算し、最大の結果を取得します。 

### なぜ効果があるのか

 固定する`d`インデックスのグラフを素のサイクルに分割し、繰り返しの反射の下での動きはこの分割にのみ依存します。 すべての有効なショットは、その単一軌道構造内に完全に存在します。`d`, したがって、軌道は独立した部分問題です。 DP は、値を失うことなく、最適な選択を互いに素な間隔に並べ替えることができるため、各軌道内の最適なセグメンテーションを正確に計算します。 補数による循環リダクションにより、ラップアラウンドのケースが二重にカウントされなくなります。 最後に、ナップザックの正確性は軌道間の独立性から導き出されます。つまり、ショット割り当てが軌道間で重複しないため、最適な下部構造を組み合わせることで全体的な最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        ans = 0

        for d in range(1, n // 2 + 1):
            g = gcd(n, d)

            orbits = [[0] * (n // g) for _ in range(g)]
            for r in range(g):
                for k in range(n // g):
                    orbits[r][k] = a[(r + k * d) % n]

            overall = [-10**18] * (m + 1)
            overall[0] = 0

            for r in range(g):
                orbit = orbits[r]
                L = len(orbit)

                total = sum(orbit)

                dp_local_max = [[-10**18] * (m + 1) for _ in range(L + 1)]
                dp_global_max = [[-10**18] * (m + 1) for _ in range(L + 1)]
                dp_local_min = [[10**18] * (m + 1) for _ in range(L + 1)]
                dp_global_min = [[10**18] * (m + 1) for _ in range(L + 1)]

                dp_global_max[0][0] = 0
                dp_global_min[0][0] = 0

                for i in range(1, L + 1):
                    val = orbit[i - 1]
                    for j in range(m + 1):
                        if j > 0:
                            if dp_global_max[i - 1][j - 1] != -10**18:
                                dp_local_max[i][j] = max(dp_local_max[i][j],
                                                         dp_global_max[i - 1][j - 1] + val)
                            if dp_global_min[i - 1][j - 1] != 10**18:
                                dp_local_min[i][j] = min(dp_local_min[i][j],
                                                         dp_global_min[i - 1][j - 1] + val)

                        if dp_local_max[i - 1][j] != -10**18:
                            dp_local_max[i][j] = max(dp_local_max[i][j],
                                                     dp_local_max[i - 1][j] + val)

                        if dp_local_min[i - 1][j] != 10**18:
                            dp_local_min[i][j] = min(dp_local_min[i][j],
                                                     dp_local_min[i - 1][j] + val)

                        dp_global_max[i][j] = max(dp_global_max[i - 1][j],
                                                  dp_local_max[i][j])
                        dp_global_min[i][j] = min(dp_global_min[i - 1][j],
                                                  dp_local_min[i][j])

                orbit_dp = [-10**18] * (m + 1)
                for j in range(m + 1):
                    orbit_dp[j] = dp_global_max[L][j]
                    if j > 0 and dp_global_min[L][j] != 10**18:
                        orbit_dp[j] = max(orbit_dp[j], total - dp_global_min[L][j])

                for cap in range(m, -1, -1):
                    if overall[cap] == -10**18:
                        continue
                    for take in range(1, m - cap + 1):
                        if orbit_dp[take] == -10**18:
                            continue
                        overall[cap + take] = max(overall[cap + take],
                                                 overall[cap] + orbit_dp[take])

            ans = max(ans, max(overall))

        print(ans)

if __name__ == "__main__":
    solve()
```DP は 3 つの層で構成されています。 最初の層は固定ステップ サイズで軌道を構築し、周期的な動きを正しく表現できるようにします。 2 番目の層は、最大セグメント DP と最小セグメント DP の両方を使用して、軌道ごとに、可能なショット数ごとに達成可能な最良の値を計算します。これは、周期的なラップアラウンドの場合を正しく処理するために必要です。 3 番目の層はナップザックを使用して軌道寄与をマージし、すべての軌道にわたるショットの合計数が次を超えないようにします。`m`。 

微妙な点は、最大 DP テーブルと最小 DP テーブルの両方を使用していることです。 最大 DP は標準的な間隔の選択をキャプチャしますが、最小 DP は循環解が境界をラップするケースを処理するために必要であり、合計から最悪の場合の除外セグメントを効果的に減算します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての値が負の場合です。 この状況では、サブアレイを選択すると合計が減少するため、最適な戦略はショットをゼロにすることです。 DP はこれを正しく処理します。`orbit_dp[0] = 0`そして他のすべての状態は否定的または無効のままであるため、ナップサックは全体的な答えを改善することはありません。 

別の特殊なケースが発生するのは、`d`それはそのようなものです`g = n`、各軌道のサイズが 1 であることを意味します。各軌道は独立した単一要素配列になります。 DP は、すべての軌道にわたって最大のポジティブ要素を選択することになり、ナップザックは周期的な複雑さを生じることなくショットを正しく分配します。 

3 番目のエッジケースは次のような場合です。`n`プライムです。 それから`gcd(n, d) = 1`みんなのために`d`したがって、すべての軌道は配列全体に広がります。 アルゴリズムは、同じ構造上で繰り返される完全周期 DP に縮退しますが、依然として正しいままです。`d`は独立して評価され、ナップサック集計は引き続き有効です。
