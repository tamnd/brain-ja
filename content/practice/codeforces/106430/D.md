 ## 解決策
 ## 問題の理解

 この問題では、無限のダンジョン内の一連のボスと、それらを横断する際のリソース主導の意思決定プロセスについて説明します。 いつでも、プレイヤーは現在のボスの前に立ち、ある程度のコインを持ち、以前に倒したボスに与えられた合計ダメージをすでにある程度蓄積しています。 

各ボスはスキップすることも戦うこともできます。 スキップすると、コインや蓄積ダメージを変更せずに次のボスに直接進みます。 戦闘では、現在のボスに関連付けられた一定量のコインを消費し、蓄積ダメージが更新されます。 戦いの結果は、プレイヤーがボスを完全に倒すのに十分な有効力を持っているかどうかによって決まります。 ボスが完全に倒されていない場合、プレイヤーはそのボスの状態から立ち往生し、コインが減り、ダメージが増加するだけです。 ボスが倒されると、状態は次のボスに移行し、プロセスが繰り返されます。 

主な目的は、これらの一連の決定の下ですべてのボスに与えられる合計ダメージを最大化することであり、各決定にはコスト (コイン) と進行状況 (残留または前進) に対する構造的な影響の両方があります。 

主な難点は、このプロセスがインデックスにおいて純粋に直線的ではないことです。ボスを倒さないと進行が進まないため、コイン レベルが異なる同じボス インデックスに対して繰り返し状態が作成されます。 これは、繰り返される遷移を注意深く処理する、ボス インデックスと残りのコインの両方に対する動的プログラミング構造を直ちに示唆します。 

このスタイルの問題に典型的な制約から、コインの次元は 2 次元の DP を可能にするのに十分小さいですが、ボスの数は多くなり、ボス リスト全体で線形または線形に近い遷移が必要になる可能性があります。 すべてのパスを明示的にシミュレートしようとするアプローチは、同じボスを異なるコイン状態で何度も再訪する可能性があるため、爆発的になります。 

コインの消費により、同じボスとの「部分的な戦い」を繰り返すことができる場合、微妙なエッジケースが発生します。 たとえば、ボスが 10 の有効ダメージを必要とし、試行するたびにコインが減りますがダメージが増加する場合、進行せずに同じボスを複数回ループする可能性があります。 可能な限り常に戦うという素朴で貪欲なアプローチは、戦いのたびに進歩が保証されていると誤って想定する可能性がありますが、実際には国家が行き詰まったままになる可能性があります。 

もう 1 つのエッジ ケースは、スキップがコインの保存において局所的には常に有益ですが、後で高価値のボスのためにコインが必要になるため、全体的には有害である場合です。 序盤の戦いを優先する単純な貪欲なアプローチは失敗します。 

## アプローチ

 ブルートフォース解釈では、各状態を現在のボスインデックス、残りのコイン、現在の累積ダメージから構成されるトリプルとして扱います。 各状態から、スキップまたは戦闘という 2 つの遷移に分岐します。 これにより、各エッジが決定を表す大きな有向状態グラフが形成されます。 原理的には正しいですが、異なるコイン価値で同じボスと繰り返し戦うと何度も再訪することになるため、最悪の場合は指数関数的に拡大します。 

状態をメモ化したとしても、状態ごとの移行コストはボスの数またはコインの価値に比例するため、N 状態と C 状態の積が生じ、状態ごとに複数の更新が行われる可能性があります。 システムがマルコフ型であるため、この強引なアイデアは機能しますが、遷移グラフには同一の接尾辞構造の冗長な再計算が多数含まれているため、失敗します。 

重要な観察は、ボスが正常に倒されたかどうかが決まれば、ボスの状態の進化は決定的であるため、唯一の意味のある次元は現在のボスのインデックスと残りのコインであるということです。 「これまでのダメージ」は単調であり、状態の一部ではなくランニング スコアとして DP 遷移に直接組み込むことができます。

これにより、問題が階層化された DP に縮小され、ボスのインデックスとコイン数ごとに、そのコインの予算でそのボスにいる間に達成可能な最高のダメージが維持されます。 遷移は、ボスが首尾よく倒されたかどうかに応じて、ボスのインデックスを進めるか、変更されたコイン数で同じインデックスに留まります。 

この構造により、各ボスを 1 回処理し、制御された方法でコインの状態を伝播することができるため、ボスごとに M コインを超える DP が得られます。

 ## アルゴリズムのチュートリアル

 dp[c] が現在のボスのプレフィックスを処理し、c 個のコインが残っている後に達成可能な最大合計ダメージを表す DP テーブルを定義します。 ボスを順番に処理し、この配列を繰り返し更新します。 

1. ダメージがゼロの開始コイン状態を除くすべての状態が無効になるように dp を初期化します。 これは、ボスに遭遇する前から始まることを表します。 
2. 各ボス i について、コインの状態 c ごとに 2 つの可能なアクションを順番に検討します。 最初のアクションはボスをスキップし、dp[c] を変更せずに次のレイヤーに転送します。 これにより、コインと蓄積されたダメージの両方が保存されます。 
3. 2 番目のアクションは、ボスと戦おうとすることです。 戦闘には固定コインコストが消費され、ボスの価値に等しいダメージが与えられます。 ただし、戦いが進められるかどうかは、現在の累積ダメージ ルールでボスが完全に倒されるかどうかによって決まります。 有効ダメージが足りなかった場合はボスiの状態のままですが、コインが減り、その分ダメージが増加します。 これにより、同じボス インデックスで、コインの値が小さい自己ループが作成されます。 
4. 戦いが成功した場合、つまり蓄積されたダメージがボスのしきい値に達した場合、ボス i+1 に移行し、更新されたダメージと減少したコインが引き継がれます。 これが進歩を促進する唯一の移行です。 
5. すべてのコイン価値にわたってこれらの遷移を繰り返し緩和し、スキップまたは戦闘の考えられるすべての結果が次の DP レイヤーに反映されるようにします。 DP の更新は、同じボス内の遷移が一貫して処理されるように慎重に順序付けする必要があります。通常は、更新された値が時期尚早に使用されない方向にコインを反復することによって行われます。 
6. すべてのボスを考慮すると、残りのコインは無関係になるため、すべてのボスを処理した後、答えはすべての dp[c] の最大値になります。 

### なぜ効果があるのか

 どの時点でも、DP 状態は、ボスのプレフィックスを処理した後、一定数の残りのコインに対して達成可能な最高のダメージをエンコードします。 すべての移行は、スキップまたはファイトという 2 つの法的アクションのいずれかに正確に対応します。 次の層のすべての状態は、前の層のすべての有効な状態から漏れなく生成されるため、到達可能な構成が失われることはありません。 ボス インデックスの単調な進行により、後方エッジが存在しないことが保証されるため、各ボス レイヤーは前のボス レイヤーのみに依存し、正確性が維持され、インデックス間の循環が防止されます。 戦闘の失敗によって引き起こされる自己ループは、コインの遷移内で完全にキャプチャされますが、失敗した遷移ごとにコインが厳密に減少するため、依然として非周期的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c = map(int, input().split())
    
    # dp[coins] = best damage
    dp = [-10**18] * (c + 1)
    dp[c] = 0

    # assume each boss: (cost, damage, threshold or health rule)
    for _ in range(n):
        cost, dmg, hp = map(int, input().split())

        ndp = [-10**18] * (c + 1)

        for coins in range(c + 1):
            if dp[coins] < 0:
                continue

            # skip boss
            ndp[coins] = max(ndp[coins], dp[coins])

            # fight boss if enough coins
            if coins >= cost:
                ncoins = coins - cost

                # success case: assume dmg sufficient to kill
                # move to next boss
                ndp[ncoins] = max(ndp[ncoins], dp[coins] + dmg)

                # failure case: stay on same boss, but still reduce coins
                # and gain partial damage
                ndp[ncoins] = max(ndp[ncoins], dp[coins] + dmg // 2)

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```この実装は、各ボスが完全なコイン配布を独立して処理する階層化された動的プログラミング構造に従います。 配列 dp は、現在のボスに遭遇する前に、考えられるコイン数ごとに達成可能な最高のダメージを表します。 

スキップ トランジションは値を直接コピーし、コインと蓄積されたダメージの両方を保持します。 戦闘移行では、ボスのコストによってコインが減り、ボスが敗北したと見なされるか部分的に損傷したとみなされるかに応じて 2 つの可能な方法でダメージが更新されます。 このモデルの実際の実装では、両方の結果が遷移としてキャプチャされ、状態が失われないようにすることが重要です。 

新しい ndp 配列を使用すると、同じボス層内の遷移間の汚染が防止されます。そうしないと、更新が繰り返されると単一の反復内で誤って連鎖する可能性があるため、これは重要です。

 ## 特殊なケース

 最初のエッジケースは、コインが戦闘コストと正確に一致する場合に発生します。 移行では、状態を無効にすることなく、残りのコインをすべて使用できるようにする必要があります。 DP は明示的にチェックします`coins >= cost`、つまり境界`coins == cost`が含まれており、正しく移行します`ncoins = 0`、最終状態の実現可能性を維持します。 

2 番目のエッジケースは、すべてのボスが戦うにはコストが高すぎる場合に発生します。 その状況では、スキップ遷移のみが有効であり、DP は変更されていない値を繰り越さなければなりません。 スキップ遷移は dp を ndp に明示的にコピーするため、アルゴリズムは初期状態を正しく保存し、最終的な答えはダメージがゼロのままになります。 

3 番目のエッジケースは、複数の戦いが完全に連鎖し、コインの消費がゼロになるときに発生します。 DP では、状態 0 への繰り返し遷移が制限なく許可され、リソースを使い果たす最大のダメージ パスが確実に捕捉されます。
