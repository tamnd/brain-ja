 ## 解決策
 ## 問題の理解

 私たちは、時間の経過とともに変化する整数の配列として表されるセキュリティ コードを維持しています。 変更するたびに、「お気に入りの番号」の固定リストに基づいて条件を評価する必要があります。$d_1, d_2, \dots, d_D$、 どこ$D \le 30$。 

配列のどのバージョンでも、配列内のすべての要素をこれらのお気に入りの数値のどれが分割するかを気にします。 タスクはそれらをリストすることではなく、そのようなすべての合計を計算することです。$d_i$。 

したがって、各クエリは、配列の前のバージョンに何らかの更新を適用した後、現在の配列を考慮し、すべての要素を分割するお気に入りの値をすべて見つけて、それらの合計を出力することを求めます。 

条件を直接考える方法は次のとおりです。$d_i$配列全体の gcd を分割する場合、すべての要素を分割します。 ただし、各更新は前のバージョンに適用され、必ずしも最新のバージョンであるとは限らないため、多くの永続バージョンにわたって gcd を維持するのは面倒です。 

この制約は、クエリごとに配列全体を再計算することが不可能なほど大きい配列サイズと操作数を意味します。 クエリごとに 1 回の再計算にコストがかかります$O(n)$、につながる$O(nq)$、両方が大きい場合は遅すぎます。 

アップデートが以前のバージョンから分岐する場合、微妙なエッジケースが発生します。 たとえば、バージョン 3 がバージョン 1 のインデックス 5 を変更する場合、バージョン 3 はバージョン 2 にまったく依存してはなりません。 「最新の配列」を保存するだけのソリューションや、更新を破壊的に適用するソリューションは、ここで失敗します。 

もう 1 つの落とし穴は、gcd 追跡だけで十分であると想定していることです。 gcd が維持されている場合でも、バージョン履歴が分岐しているため、最初から再計算せずに効率的に更新するのは簡単ではありません。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリの後に完全な配列が再計算され、各お気に入りの数値が gcd に対して、または直接各要素に対してチェックされます。 バージョンごとに、配列全体をスキャンして gcd を計算するか、割り算を検証します。 これは定義を直接適用するため正しいですが、クエリごとにコストがかかります。$O(n)$、更新は最大で$10^5$、最悪の場合、総作業量は 2 次になります。 

重要な観察は、お気に入りの約数の数が非常に少なく、最大 30 であることです。gcd 値の観点から考える代わりに、割り算情報を配列要素ごとのビットマスクとして直接エンコードできます。 各要素には 30 ビットのマスクが格納されます。$i$かどうかを示します$d_i$その要素を分割します。 

すべての要素がマスクとして表現されると、条件「$d_i$すべての要素を除算する」は配列全体のビット単位の AND になります。すべての要素マスクの AND を計算し、生き残ったビットは有効な除数に正確に対応します。 

残りの課題は、以前のバージョンの更新を効率的にサポートすることです。 更新のたびに古いバージョンから派生した新しいバージョンが作成されるため、履歴を保存しながらポイントの変更を可能にする構造が必要です。 永続的なセグメント ツリーはまさにこれを行います。各バージョンは、以前のバージョンと変更されていない構造を共有します。$O(\log n)$ノードは更新ごとにコピーされます。 

各セグメント ツリー ノードには、そのセグメントのビット単位の AND が格納されます。 したがって、各バージョンのルートは、配列全体の AND を直ちに表します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 永続セグメント ツリー + ビットマスク | O((n + q) log n + qD) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各好きな数字を変換する$d_i$を固定インデックスに変換し、それをマスク内の 1 つのビットに関連付けます。 これにより、すべての割り算チェックを整数にコンパクトに保存できます。 
2. 配列要素ごとに、すべての要素に対して割り算をチェックしてマスクを計算します。$d_i$。 もし$d_i \mid a[j]$、セットビット$i$。 これにより、各値が 30 ビット表現に前処理されます。 
3. これらのマスク上にセグメント ツリーを構築します。各リーフには 1 つの要素マスクが格納されます。 内部ノードには子のビット単位の AND が格納されます。これは、値がセグメント内のすべての要素を両方の半分に分割するときに正確に分割されるためです。 
4. 更新パスに沿ってノードのみをコピーすることで永続性を維持します。 インデックス更新時$idx$では、以前のバージョンから変更されていないサブツリーを再利用しながら、ルートからリーフへのパスに沿って新しいノードを作成します。 
5. 各クエリについて、要求されたバージョンのルートへのポインタをたどります。 ルート マスクは、そのバージョンのすべての要素の AND を表すようになりました。 
6. ルート マスクのすべてのビットを反復して答えを計算します。 噛まれたら$i$設定されている場合は追加します$d_i$結果に。 

### なぜ効果があるのか

 各セグメント ツリー ノードには、そのセグメント内のすべてのマスクのビット単位の AND が格納されます。 ビット単位の AND は結合性と可換性があるため、セグメントを任意の順序でマージすると、配列全体を計算した場合と同じ結果が得られます。 永続性により、各バージョンのルートがその配列状態に正確に対応することが保証されるため、ルート マスクは常に正しいグローバル AND になります。 ビットは、配列内のすべての要素にそのビットが設定されている場合に限り、設定されたままになります。これは、すべての要素が対応する要素で割り切れることと同等です。$d_i$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("l", "r", "mask")
    def __init__(self, l=None, r=None, mask=0):
        self.l = l
        self.r = r
        self.mask = mask

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        self.root = self.build(0, self.n - 1)

    def build(self, l, r):
        if l == r:
            return Node(None, None, self.arr[l])
        m = (l + r) // 2
        left = self.build(l, m)
        right = self.build(m + 1, r)
        return Node(left, right, left.mask & right.mask)

    def update(self, node, l, r, idx, val):
        if l == r:
            return Node(None, None, val)
        m = (l + r) // 2
        if idx <= m:
            new_left = self.update(node.l, l, m, idx, val)
            return Node(new_left, node.r, new_left.mask & node.r.mask)
        else:
            new_right = self.update(node.r, m + 1, r, idx, val)
            return Node(node.l, new_right, node.l.mask & new_right.mask)

def main():
    n, q, d = map(int, input().split())
    divisors = list(map(int, input().split()))
    idx = {v: i for i, v in enumerate(divisors)}

    def to_mask(x):
        m = 0
        for i, v in enumerate(divisors):
            if x % v == 0:
                m |= (1 << i)
        return m

    arr = list(map(int, input().split()))
    arr = [to_mask(x) for x in arr]

    st = SegTree(arr)
    versions = [st.root]

    out = []
    for _ in range(q):
        line = input().split()
        prev, pos, val = int(line[0]), int(line[1]) - 1, int(line[2])
        new_mask = to_mask(val)
        new_root = st.update(versions[prev], 0, n - 1, pos, new_mask)
        versions.append(new_root)

        root_mask = new_root.mask
        ans = 0
        for i, v in enumerate(divisors):
            if root_mask & (1 << i):
                ans += v
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```セグメント ツリーには生の値ではなくマスクが保存されるため、すべてのマージはビット単位の AND にすぎません。 永続層は、各更新が既存のノードを変更せずに新しいルートを返すという事実に暗黙的に含まれています。 クエリは常に最新の状態を拡張するのではなく、以前のバージョンを明示的に参照するため、バージョン配列は非常に重要です。 

唯一の微妙な部分は、更新では最後に構築されたバージョンではなく、以前のバージョンのルートが使用されることを覚えていることです。 

## 実用的な例

 約数を考慮する$[2, 3, 5]$そして初期配列$[6, 10]$。 

### 例 1

 私たちはマスクを作ります:

 - 6 → 110 (2と3で割る)
 - 10 → 101 (2と5で割る)

 ルート AND は 100 なので、2 つだけが残り、答えは 2 になります。 

| ステップ | 配列マスク | AND の結果 | アクティブ除数 |
 | --- | --- | --- | --- |
 | ビルド | [110、101] | 100 | {2} |

 ここで、インデックス 1 を値 15 に更新するとします。 

- 15 → 010

 新しい配列は[6, 15]、マスクは[110, 010]、ANDは010、答えは3です。 

| ステップ | 配列マスク | AND の結果 | アクティブ除数 |
 | --- | --- | --- | --- |
 | 更新 | [110、010] | 010 | {3} |

 これは、1 つの更新でどの約数が生き残るかを完全に変えることができることを示しています。 

### 例 2

 約数$[4, 6]$、 配列$[12, 18, 24]$。 

マスク:

 - 12 → 11
 - 18 → 10
 - 24 → 11

 ANDは10なので、答えは6です。 

次に、インデックス 2 を 8 に更新します。 

- 8→01

 配列は[12, 18, 8]、マスクは[11, 10, 01]、ANDは00、答えは0になります。 

これは、ほとんどの要素が除数をサポートしている場合でも、互換性のない 1 つの更新により除数が完全に削除されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、更新プログラムが最新バージョンではなく非常に古いバージョンを参照する場合です。 各バージョンのルートが独立しているため、永続的な構造により正確さが保証されます。 バージョン 0 に配列 [6, 10] があり、バージョン 1 がインデックス 0 から 15 を変更する場合、バージョン 2 は依然としてバージョン 0 から分岐する可能性があります。更新関数は常に提供されたルートを使用するため、以前の構造は干渉することなく保持されます。 

もう 1 つの特殊なケースは、値がどの数値でも割り切れない場合です。 そのマスクは 0 で、それを含むセグメントの AND は 0 になります。これにより、そのバージョンのすべての答えが即座に 0 になります。これは正しいことです。$d_i$1 つの要素がすべてのチェックに失敗した場合、すべての要素を分割できます。
