 ## 問題の理解

 番号はあります`X`それを別の数字に変えたい`Y`。 1 回の操作で正の整数が選択されます`M`そしてラウンド`X`最も近い倍数に`M`。 2 つの倍数が同等に近い場合は、大きい方が選択されます。 タスクは、変換に必要な最小限の操作数を見つけることです。`X`の中へ`Y`。 

重要な問題は、丸め操作では任意の量を移動できないことです。 の選択`M`可能な次の値を制御するため、解決策は 1 つの操作から可能な最大の進行状況を理解することに依存します。 

この制約により、非常に大きな値が許可されます。`X`そして`Y`したがって、多くの小さな変更をシミュレートすることは現実的ではありません。 値が 10 億以上になる可能性がある場合は、繰り返し 1 ずつ減らすか、可能な限りすべてのことを試みるアプローチが必要です。`M`値を指定すると、非常に多くの操作が必要になります。 有用な演算ごとに数値の大きさを大幅に変更する必要があるため、対数観測が必要です。 

主なエッジ ケースは、小さな値付近の動作と丸めのタイ ルールに由来します。 

開始値がすでにターゲットである場合、操作は必要ありません。```
Input:
5 5
```正しい出力は次のとおりです。```
0
```常に最初に増加または減少ロジックに入るソリューションでは、不必要な演算が誤ってカウントされる可能性があります。 

もう 1 つの特殊なケースは、数値をこれ以上減らすことができない場合です。 例えば：```
Input:
3 1
```番号`3`切り捨てることはできません`1`。 選択する`M = 2`作る`3`同様に近い`2`そして`4`、そしてタイは上向きになり、`4`。 より小さい値を選択する`M`も生産できません`1`。 正しい出力は次のとおりです。```
-1
```小さな値をチェックせずに最大減少式を繰り返し適用する貪欲な実装では、永久にループしたり、無効な答えが生成されたりする可能性があります。 

最後の境界ケースは、現在の値がターゲットの 2 倍未満の場合に表示されます。```
Input:
10 6
```選択する`M = 6`ラウンド`10`に`6`、 なぜなら`10`に近いです`6`するよりも`12`。 答えは次のとおりです。```
1
```2 のべき乗の成長または縮小のみを考慮するソリューションでは、これらの最後の 1 ステップの移行が見逃されてしまいます。 

## アプローチ

 直接的な総当りのソリューションでは、考えられるすべての値を試します。`M`各ステップで丸め操作をシミュレートし、次からの最短パスを検索します。`X`に`Y`。 すべての法的措置が調査されるため、これは正しいです。 ただし、膨大な数の選択肢があるため、これは使用できません。`M`、および間の状態の数`X`そして`Y`非常に大きくなる場合もあります。 およその値の場合`10^18`、状態を探索したり、すべての選択肢を試したりすることは不可能です。 

有益な観察は、増加と減少を別々に観察することで得られます。 

いつ`X < Y`、1 回の操作で値が最大 2 倍増加する可能性があります。 選択する`M = 2X`ラウンド`X`上向きに`2X`、最も近い 2 つの倍数は次のとおりであるため、`0`そして`2X`。 これは、ターゲットが十分に近づくまで繰り返し倍増させてから、`M = Y`最後のステップのために。 演算の数は、必要な 2 倍化の数と正確に一致します。`ceil(log2(Y / X))`。 

減少する場合はより微妙です。 減らすには`X`を選択する必要があります。`M < X`。 もし`X`間にあります`M`そして`2M`、四捨五入された値は次のようになります。`M`いつ`X`に近いです`M`するよりも`2M`。 

減少の境界は次のとおりです。```
X - M < 2M - X
```これは次のようになります:```
M > 2X / 3
```有効な最小値`M`最大の減少が生じるため、最善の策は次のとおりです。```
M = floor(2X / 3) + 1
```この操作を繰り返すと、値はおよそ 1 分の 1 に縮小されます。`2/3`。 現在値が2倍以下になったら`Y`、最後の操作が 1 つあります`M = Y`目標に到達します。 

ブルート フォースは、考えられるすべての丸めの選択肢を探索するため機能しますが、検索スペースが巨大であるため失敗します。 すべての最適な動きは最大の有用な増加または減少に置き換えることができるという観察により、問題は短い貪欲なプロセスに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(状態の数 × 可能な M 値) | O(状態の数) | 遅すぎる |
 | 最適 | O(log(max(X, Y))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. もし`X`すでに等しい`Y`、 戻る`0`操作が必要ないからです。 
2. もし`X < Y`、繰り返し倍増`X`倍増しても目標を達成できません。 各倍増は選択することによって達成されます`M = 2X`したがって、これは常に有効な操作です。 
3. 倍加フェーズの後、次の最後の操作を実行します。`M = Y`。 現在の値が を超えているため、`Y / 2`、最も近い倍数に丸めます。`Y`正確に生成します`Y`。 
4. もし`X > Y`、まず現在の値が既に以下かどうかを確認します。`2Y`。 そうであれば、1 回の操作で`M = Y`答えに辿り着く。 
5.そうでない場合は、繰り返し交換してください`X`と`floor(2X / 3) + 1`。 これは可能な限り最速の減少であり、それでも結果をプラスに保ちます。 
6. 現在の値が以下になるまで、これらの減少をカウントします。`2Y`に直接丸める最後の演算を 1 つ追加します。`Y`。 
7. 値を減らすことができず、依然として値が大きい場合`Y`、変換が不可能であると報告します。 

機能する理由: すべての便利な操作には、値を変更できる量に制限があります。 四捨五入では数値をそのサイズを超えて増やすことができないため、増加する場合は 2 倍が可能な最大のジャンプとなります。 減少する場合、到達可能な最小の正の四捨五入値は次のとおりです。`floor(2X/3)+1`、その他の選択肢を選択しても、数値は少なくとも同じ大きさのままになります。 各貪欲な動きは可能な限り最大限の進歩をもたらすため、他のシーケンスはより少ない操作でターゲットに到達することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(x, y):
    if x == y:
        return 0

    ans = 0

    if x < y:
        while x * 2 <= y:
            x *= 2
            ans += 1
        return ans + 1

    if x <= 3:
        return -1

    while x >= 2 * y:
        x = (2 * x) // 3 + 1
        ans += 1
        if x <= 3 and x > y:
            return -1

    return ans + 1

def main():
    data = list(map(int, sys.stdin.read().split()))
    if not data:
        return

    t = data[0]
    idx = 1
    out = []

    for _ in range(t):
        x = data[idx]
        y = data[idx + 1]
        idx += 2
        out.append(str(solve_case(x, y)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```機能`solve_case`増加と減少では最適な動きが異なるため、2 つの方向を分離します。 

増加するブランチでは、対数計算ではなく 2 の乗算が使用されます。 これにより、浮動小数点精度の問題が回避され、実行された操作が直接カウントされます。 

減少するブランチでは整数演算が使用されます。`floor(2X/3)+1`。 ここでは操作の順序が重要です。 コンピューティング`2 * x // 3 + 1`はフロアの動作を正確に保ちますが、浮動小数点計算は入力が大きい場合には精度が失われる可能性があります。 

条件`x >= 2 * y`最終的な直接丸めが可能かどうかを決定します。 これが誤りであると、`M = Y`機能するので`X`に近いです`Y`するよりも`2Y`。

 ## 特殊なケース

 のために`X = Y`の場合、状態はすでに正しいため、アルゴリズムはすぐにゼロを返します。 これにより、貪欲な分岐に入ることが回避され、不必要な操作がカウントされるのが防止されます。 

のために`X = 3`そして`Y = 1`、アルゴリズムはそれを検出します`X`有効な減少を実行するには小さすぎます。 可能な丸めの選択肢では作成できません`1`、それで戻ります`-1`は正しいです。 

のために`X = 10`そして`Y = 6`、アルゴリズムはそれを認識します`10 < 2 * 6`なので、削減フェーズはスキップされます。 選択する`M = 6`ラウンド`10`に`6`、最終ステップの条件を確認します。 

非常に大きな値の場合、次のようになります。`X = 10^12`そして`Y = 1`、アルゴリズムは個々の数値を反復処理することはありません。 幾何学的縮小のみを実行し、演算カウントを対数に保ちます。
