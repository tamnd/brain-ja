 ## 解決策
 ## 問題の理解

 私たちは、キャラクターが進行するにつれて変化するいくつかのキーを持って、一連の部屋を順番に移動するプロセスを与えられます。 初期数のキーから始まり、各部屋に固定数のキーが追加されます。 ただし、部屋 i から部屋 i + 1 に移動するには、部屋 i を処理した後に現在所有しているキーの数が、次の部屋に関連付けられた要件を満たすのに十分な大きさでなければなりません。 

より具体的には、最初の i 部屋以降、キーの合計は初期量にこれまでの累積ゲインをすべて加えたものになります。 次の部屋に入る前に、この累計は少なくともその次の部屋で必要なしきい値以上でなければなりません。 そうでない場合は、初期のキーの数がもっと大きかったはずです。 

このタスクは、連続する部屋間のすべての遷移が有効になるように、キーの最小可能初期数を計算することです。 

この構造によって暗示される制約は、10^5 や 2⋅10^5 などの大きな値までのサイズの配列に対する線形スキャンの問題によく見られます。 これにより、位置のすべてのペアに対する二次チェックや、各候補初期値に対するプレフィックス合計の最初からの再計算が即座に排除されます。 これより遅いと標準制限内でタイムアウトする危険性があるため、解は線形または線形に近いもの (おそらく O(n)) である必要があります。 

調整を繰り返して、推測された初期値を最初からシミュレートしようとすると、微妙な失敗のケースが発生します。 たとえば、障害が発生した場合にのみ初期キーを貪欲に増加させようとすると、部屋 i での違反は修正される可能性がありますが、正しいグローバル境界を維持していない場合は、誤って以前の仮定を破ってしまう可能性があります。 もう 1 つのよくある間違いは、パス全体にわたる最悪の制約を集計せずに、最終的な部屋要件だけをチェックするか、ローカル遷移だけをチェックすることです。 たとえば、部屋の要件が途中で急激に増加し、その後減少する場合、最終的な要件のみに焦点を当てると、必要な初期値が過小評価されてしまいます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。初期キー k を 0 から増やしていき、毎回行程全体をシミュレートしてみてください。 各 k について、キーの累計を計算し、すべての遷移条件が満たされているかどうかを確認します。 これは問題ステートメントを直接反映しているので正しいですが、各シミュレーションは O(n) であり、最悪の場合、合計の欠陥に比例する大きな値まで k をテストする必要がある可能性があります。 これにより、最悪の場合の複雑さは O(nK) となり、非常に遅すぎます。 

重要な観察は、各遷移によって課される制約が同じ変数 k に対する独立した下限であるということです。 部屋 i まで処理した後、k ≥ ai+1 − prefix_sum(i) の形式の条件を導出します。 各位置は k に対する潜在的な制約に寄与し、答えは単純にこれらすべての制約の最大値になります。 これが認識されると、問題は、プレフィックスの合計を維持し、スキャン中に必要な最大 k を追跡することになります。 

これにより、反復的な推測問題が単一パスの累積問題に変換される可能性があります。

 ## アルゴリズムのチュートリアル

 この問題を、各部屋の遷移によって引き起こされるキーの初期数の最も厳しい下限を計算することに変換します。

1. 変数 prefix_sum を初期化して、b 配列からこれまでに取得したキーの総数を格納します。 また、応答を 0 に初期化すると、必要な初期キーの最大数が追跡されます。 
2. 0 から n − 1 までの各インデックス i を反復処理し、b[i] を追加して prefix_sum を更新します。 これは、ベッシーが部屋 i までで取得したであろう鍵の数を表します。 
3. 部屋 i + 1 に入るという制約が存在する各位置 i について、必要な初期キーを ai+1 − prefix_sum として計算します。 この値は、i までゲインした後でも要件を満たすために、開始時に必要な追加のキーの数を表します。 
4. 計算されたすべての要件の最大値として答えを更新します。 その理由は、最初のキーはすべての制約を同時に満たす必要があるため、最も厳しい制約が優先されるということです。 
5. すべてのポジションを処理した後、回答を出力します。 すべての制約が負またはゼロの場合、答えは 0 のままです。これは、追加の初期キーが必要ないことを意味します。 

### なぜ効果があるのか

 任意の点 i において、有効性の条件は、k + prefix_sum(i) が少なくとも ai+1 であることです。 並べ替えると、 k ≥ ai+1 − prefix_sum(i) が得られます。 各 i は独立して k に下限を課し、真の k はそれらすべてを一度に満たさなければなりません。 これらすべての半線制約の交差部分は、正確にその下限の最大値になります。 prefix_sum(i) は増分的に計算され、再検討されることはないため、制約が見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    prefix = 0
    ans = 0

    for i in range(n):
        prefix += b[i]
        if i + 1 < n:
            need = a[i + 1] - prefix
            if need > ans:
                ans = need

    if ans < 0:
        ans = 0

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、累積的なキーのゲインを表す b 配列の実行中のプレフィックス合計が保持されます。 各ステップで、次の部屋のしきい値を満たすために必要な不足額を計算します。 回答変数は、すべてのポジションにわたる最悪の赤字を追跡します。 

よくある落とし穴は、要件が部屋 i に滞在するのではなく、部屋 i + 1 に入る場合に適用されることを忘れることです。これにより、インデックス付けが 1 つシフトされます。 もう 1 つの微妙な問題は、ans が負になることを許可することです。 この場合、追加の初期キーは必要ないため、正解はゼロになります。 

## 実用的な例

 ### 例 1

 しきい値が徐々に上昇し、ゲインが控えめな小さなケースを考えてみましょう。 

| 私 | プレフィックス合計 | a[i+1] | 必須 k = a[i+1] − プレフィックス | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 5 | 3 | 3 |
 | 1 | 4 | 6 | 2 | 3 |
 | 2 | 7 | 8 | 1 | 3 |

 最終的な答えは 3 です。これは、最初の移行が最も要求が厳しいことから来ています。 プレフィックスの合計にはすでに十分なキーが蓄積されているため、後の移行は簡単になります。 

このトレースは、単一のエンドポイント要件ではなく、最悪のプレフィックス不足によって答えがどのように支配されるかを示しています。 

### 例 2

 次に、ゲインが十分に大きいため、追加の初期キーが必要ない場合を考えてみましょう。 

| 私 | プレフィックス合計 | a[i+1] | 必須 k | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 3 | -2 | 0 |
 | 1 | 10 | 6 | -4 | 0 |
 | 2 | 15 | 10 | -5 | 0 |

 すべての制約は負の値です。つまり、キーがゼロから開始するだけでも十分です。 アルゴリズムは、答えを正しくゼロにクランプします。 

これは、システムが蓄積されたゲインによって圧倒されたときの動作を示しています。

リニア スキャンは、インデックスごとに一定の作業のみを実行するため、時間制限内で最大 2⋅10^5 要素の一般的な制約に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    prefix = 0
    ans = 0
    for i in range(n):
        prefix += b[i]
        if i + 1 < n:
            ans = max(ans, a[i + 1] - prefix)

    if ans < 0:
        ans = 0
    return str(ans)

 ## 特殊なケース

 特殊なケースの 1 つは、部屋が 1 つしかない場合です。 この場合、遷移は存在しないため、任意の初期値が機能し、答えはゼロでなければなりません。 ループは制約を評価せず、ans はゼロのままであるため、アルゴリズムはこれを自然に処理します。 

すべてのプレフィックスの合計が将来のすべての要件をすぐに超える場合、別のエッジ ケースが発生します。 たとえば、b が大きくて正の場合、計算されたすべての要件は負になりますが、それらの最大値も負のままです。 最後のクランプステップにより、答えがゼロになることが保証されます。 

最後のエッジケースは、最初の遷移で最悪の制約が発生する場合です。 このような場合、prefix_sum はまだ小さく、必要な k は a0 と a1 によって占められます。 アルゴリズムはこれを i = 0 で即座に捕捉し、その後のプレフィックスの蓄積によって不足が隠蔽される前に ans を更新します。
