 ## 解決策
 ## 問題の理解

 指数のソートされた配列が与えられます。 イワンは指数そのものの代わりに、対応する 2 の累乗を紙に書きます。$$2^{a_1}, 2^{a_2}, \dots, 2^{a_n}$$さらに数値を加算することもできますが、加算されるすべての数値も 2 の累乗でなければなりません。 目標は、合計をフォームの数値と等しくすることです。$$2^v - 1$$負でない整数の場合$v$。 必要な 2 の追加累乗の最小数を計算する必要があります。 

のような数字$2^v - 1$は、バイナリ表現に 1 だけが含まれるため、特別です。 例えば：$$1 = 1_2,\quad 3 = 11_2,\quad 7 = 111_2,\quad 15 = 1111_2$$入力サイズが到達しました$10^5$、指数は次のように大きくなります。$2 \cdot 10^9$。 これにより、巨大なバイナリ配列を明示的に構築したり、ビット位置を最大指数までシミュレートしたりするアルゴリズムは即座に除外されます。 線形時間に近いものが必要です。 

重要な観察は、2 のべき乗の実際の値は膨大ですが、2 進数のキャリーは局所的であるということです。 すべての数値は 2 の累乗であるため、プロセス全体は 2 進加算とまったく同じように動作します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

現在の合計がすでに次の形式になっていると仮定します。$2^v - 1$。 

入力：```
4
0 1 1 1
```数字は$1,2,2,2$、その合計は$7$。 以来$7 = 2^3 - 1$、答えは$0$。 キャリーをチェックせずに常に「欠落ビットを補完」しようとする不注意な実装では、誤って余分な電力が追加される可能性があります。 

もう 1 つの注意が必要なケースは、多くの同等のパワーがキャリーによって崩れる場合です。 

入力：```
3
0 0 0
```合計は$3$、すでに等しい$2^2 - 1$。 個別の指数だけを数えると、ビット 1 が欠落していると考えられ、間違った答えが返されるでしょう。$1$。 

大きなキャリーチェーンも重要です。 

入力：```
5
0 0 0 0 0
```合計は$5$、バイナリ$101$。 フォームの番号に到達するには$111$を追加するだけです。$2$、与える$7$。 答えは$1$、 ない$2$。 ここでは、個々のビットに対する貪欲な推論は簡単に失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、現在の合計を明示的に計算します。$$S = \sum 2^{a_i}$$次に、フォームのすべてのターゲットを試すことができます$2^v - 1$以上$S$。 ターゲットごとに差を計算します。$$D = (2^v - 1) - S$$すべての加算される数値は 2 のべき乗である必要があるため、加算される項の最小数は、設定されたビットの数に等しくなります。$D$。 可能な限りその値を最小化することができます$v$。 

この考えは数学的には正しいです。$D$2 の累乗として独立して追加できます。 

問題は数値の大きさです。 指数到達$2 \cdot 10^9$したがって、概念的には合計自体に数十億ビットが含まれる可能性があります。 直接的な大きな整数の操作は、単純に実装すると実用的ではなくなります。 Python の整数は任意の精度ですが、膨大な数を構築することは無駄であり、不必要です。 

重要な洞察は、完全な数値自体は決して必要ないということです。 すべてのキャリーが処理された後に残るビット数のみを考慮します。 

バイナリ加算を列ごとに考えてみましょう。 指数が出現するたびに$x$ビット位置に 1 単位を寄与します$x$。 同じ位置にある 2 つのユニットが次の位置で 1 つのキャリーに結合されます。 

すべてのキャリーが伝播された後、すべてのビット位置には 0 または 1 が含まれます。合計の最終的なバイナリ表現は次のようになります。$$b_k b_{k-1} \dots b_0$$この数値を次のような形式に変換するには、$111\dots111$、最も高い設定ビットの下のすべての 0 ビットを 1 に変えるだけで済みます。 欠落しているものはそれぞれ、2 の累乗を正確に 1 つ加算する必要があります。 

したがって、答えは単純に、最終合計の最上位設定ビットの下にあるゼロ ビットの数です。 

これは、巨大な整数を明示的に構築しなくても計算できます。 占有ポジション間のキャリーのみをシミュレートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(B²) | O(B) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ここ、$B$キャリー伝播後の関連ビット位置の数を表します。 

## アルゴリズムのチュートリアル

 1. ソートされた指数を読み取ります。 
2. 各指数が何回出現するかを数えます。 

各出現は、そのバイナリ位置に 1 単位を与えます。 
3. 位置を昇順に処理し、キャリーを上に伝播します。 

位置の場合$x$含まれています$c$単位:

 -$c \bmod 2$位置の最後のビットになります$x$-$c // 2$所定の位置に運ばれます$x+1$これは通常の 2 進加算とまったく同じです。 
4. 1 に等しいビットで終わる最高位を追跡します。 

ターゲット形式は次のとおりであるため、この位置より上のビットは重要ではありません。$$111\dots111$$最上位の設定ビットまでのみ。 
5. キャリー伝播後、最上位の設定ビットの下に 0 が含まれる位置がいくつあるかを数えます。 

このような各位置には、2 のべき乗を 1 つ加算する必要があります。 
6. そのカウントを出力します。 

### なぜ効果があるのか

 キャリー伝播の後、現在の合計の真のバイナリ表現が得られます。 フォームは何個でも$2^v - 1$最上位ビット以下のすべてのビットが 1 に等しい。 

加算できるのは 2 のべき乗のみです。つまり、各演算では、下位ビットに影響を与えることなく、選択した 1 つのビットだけを 0 から 1 に変えることができます。 より高いターゲットは先頭に余分なターゲットを追加するだけであるため、最適なターゲットは常に現在の合計を上回る最小のオール 1 の数値になります。 

つまり、最上位の設定ビットの下のすべてのゼロ ビットは 1 回だけ修正する必要があり、追加の追加は必要ありません。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = defaultdict(int)

    for x in a:
        cnt[x] += 1

    bits = {}
    positions = sorted(cnt.keys())

    i = 0
    while i < len(positions):
        pos = positions[i]

        cur = cnt[pos]

        bits[pos] = cur & 1

        carry = cur >> 1
        if carry:
            cnt[pos + 1] += carry
            if pos + 1 not in bits and (i + 1 == len(positions) or positions[i + 1] != pos + 1):
                positions.append(pos + 1)

        i += 1

    positions.sort()

    highest = -1

    for pos in positions:
        if bits.get(pos, 0):
            highest = pos

    ans = 0

    for pos in range(highest):
        if bits.get(pos, 0) == 0:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```辞書`cnt`現在存在する各指数のコピー数を格納します。 ポジションを処理するとき、そのカウントを最終ビットとキャリーに分割します。 

表現:```
bits[pos] = cur & 1
```カウントのパリティを保持し、その位置の最終バイナリ ビットになります。 

表現:```
carry = cur >> 1
```上に移動するペアの数を計算します。 

微妙な点の 1 つは、キャリーによって、元の入力には存在しなかったまったく新しい位置が作成される可能性があることです。 これらの位置を動的に追加し、最終スキャンの前に再度並べ替えます。 

もう 1 つの重要な詳細はループです。```
for pos in range(highest):
```その前に止まります`highest`これは、定義上、設定された最上位ビットがすでに 1 であるためです。 厳密にその下のポジションのみを埋める必要がある場合があります。 

巨大な累乗を直接構築することはないため、ここでは Python 整数は安全です。 操作するのはカウントと位置だけです。

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin

 ## 特殊なケース

 キャリーが繰り返されることを考慮してください。 

入力：```
4
3 3 3 3
```4 つのコピーから始めます$2^3 = 8$。 

バイナリ加算は次のように行われます。 

- ビット 3 の 4 つのユニットはそこでゼロを生成し、2 つのユニットを上に繰り上げます。 
- ビット 4 の 2 つのユニットはそこでゼロを生成し、1 つのユニットを上に繰り上げます。 
- ビット 5 が 1 になります。 

最終的な数値は次のとおりです。$$100000_2$$下位 5 ビットはすべて 0 ですが、最も高い設定ビットより下のみを考慮します。 次の 5 つの追加が必要です。$$111111_2$$アルゴリズムは、キャリー伝播を繰り返すことでこれを自動的に処理します。 

ここで、疎な構成を考えてみましょう。 

入力：```
2
0 3
```合計は次のとおりです。$$1 + 8 = 9 = 1001_2$$ビット 1 と 2 が欠落しています。 アルゴリズムは、設定された最高ビットの下に正確に 2 つのゼロ ビットを検出し、応答します。$2$。 

最後に、キャリーによって形成されたすでに完全な数について考えてみましょう。 

入力：```
3
0 0 0
```3 つの合計は次のようになります。$$11_2$$キャリー伝播により次のものが生成されます。 

- ビット0 = 1
 - ビット 1 にキャリー
 - ビット 1 = 1

 隙間は残らない、だから答えは$0$。 これにより、アルゴリズムが欠落ビットをカウントする前にキャリーを正しく処理していることが確認されます。
