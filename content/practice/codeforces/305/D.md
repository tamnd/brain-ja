 ## 解決策
 ## 問題の理解

 1 から _n_ までの番号が付けられた頂点を持つ有向非巡回グラフが与えられます。すべてのエッジは、小さい番号の頂点から大きい番号の頂点へと進みます。 いくつかのエッジはすでに存在しており、特定の制約の下でさらにエッジを追加することができます。 主な制約により、各頂点 _i_ がより大きな番号を持つすべての頂点に到達できること、重複エッジがないこと、最短パス距離が非常に特殊なパターンに従うことが保証されます。_i_ と _j_ の間の距離が最大 _k_ の場合、最短パスは _j_ - _i_ に正確に等しくなければなりません。 距離が _k_ より大きい場合は、_j_ - _i_ または _j_ - _i_ - _k_ のいずれかになります。 

入力リストには、頂点の数である _n_、既存のエッジの数である _m_、および距離における許容される「ショートカット」を制御するパラメーターである _k_ がリストされます。 次の _m_ 行のそれぞれに、既存のエッジがリストされます。 出力は、すべての制約を満たす新しいエッジを追加する方法の合計数 (モジュロ 10^9 + 7) です。 

グラフは非常に大きくなり、_n_ は最大 10^6、_m_ は最大 10^5 になります。 これにより、すべての頂点ペア間のすべての可能なグラフまたはパスを明示的に列挙するアルゴリズムは除外されます。これは、メモリ内で O(2^(n^2)) または O(n^2) となり、実行不可能です。 _k_ の値が大きい (最大 10^6) と、各潜在的なエッジに対する総当たり距離チェックも防止されます。 

微妙なエッジ ケースは、_k_ ≥ _n_ の場合です。これは、ショートカットがグラフ全体に及ぶ可能性があり、有効なエッジ構成の数が変化するためです。 もう 1 つは、最初にエッジが存在しない場合 (_m_ = 0) です。 すべての頂点が次の _k_ 個の頂点に接続する必要があると単純に仮定すると、一部のエッジがすでに存在する可能性があり、冗長なエッジの追加が禁止されているため、構成が過剰にカウントされる可能性があります。 

## アプローチ

 素朴なアプローチは、_i_ < _j_ である頂点 _i_ と _j_ の間に考えられるすべてのエッジを追加し、すべての最短パス条件が満たされているかどうかを確認することです。 このようなエッジは O(n^2) 個あり、すべてのペア間の最短パスを検証するには、Floyd-Warshall を使用すると O(n^3) かかりますが、10^6 までの _n_ にとってはまったく遅すぎます。 各頂点からの BFS でさえ O(n^2) ですが、これは依然として過剰です。 

重要な観察点は、グラフが頂点インデックスによってトポロジー的に並べ替えられており、距離制約が構造化されていることです。_k_ までの距離は正確である必要があり、_k_ より大きい距離では、長さ _k_ の単一のショートカットが許可されます。 これにより、左から右へ貪欲かつ直線的に作業できるようになります。 各頂点 _i_ について、_k_ ステップ以内で到達可能な最も遠い頂点にエッジを追加することのみを考慮する必要があります。これにより、最短パス制約を満たす「クリティカル エッジ」が作成されます。 すべてのペアをチェックする必要はありません。 許容されるショートカットの構造により、選択が異なる開始点に対して独立していることが保証され、モジュラー演算を使用して構成をカウントできます。 

問題を距離を維持するエッジの有効範囲をカウントすることに変換することで、複雑さを O(n^2) から O(n + m) に軽減します。 既存のエッジは頂点ごとのオプションの数を減らすために使用され、モジュラー演算により境界を超えないことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) から O(n^3) | O(n^2) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力から _n_、_m_、および _k_ を読み取り、配列を初期化します`max_edge[i]`指定されたエッジを使用して、頂点 _i_ から到達可能な最も遠い頂点を追跡します。 当初は、`max_edge[i]`= すべての _i_ に対して 0。 
2. 既存のエッジ _u_ → _v_ ごとに、更新します`max_edge[u]`= 最大(`max_edge[u]`、_v_)。 これは、各ノードが最初に到達できる最も遠い頂点を追跡します。 
3.ローリングを維持する`reach`最短パス制約の下でこれまでに到達可能な最も遠い頂点を表す変数。 頂点を 1 から _n_ まで繰り返します。 頂点 _i_ については、`reach`少なくとも _i_ + 1 をカバーします。そうでない場合は、_i_ から間の頂点にエッジを追加する必要があることを意味します。`reach + 1`そして`i + k`正確な距離要件を満たすために。 
4. このエッジの選択肢の数は (`i + k`) − 最大(`reach`、`max_edge[i]`) 正の場合、それ以外の場合は 1. 現在の合計を乗算します。`ans`10^9 + 7を法とする選択肢の数で割ります。`reach`= 最大(`reach`、`i + k`）。 
5. 頂点 _n_ − 1 まで反復を続けます。変数`ans`有効なエッジ構成の総数が含まれるようになりました。 

機能する理由: 不変条件は、頂点 _i_ を処理した後、1 から _i_ までのすべての頂点が最大の頂点に到達できるということです。`reach`距離の制約を尊重しながら。 _k_ までの長さのショートカットは以前の決定を妨げないため、頂点 _i_ での各決定は後の頂点から独立しています。 剰余乗算では、組み合わせカウントが正しく累積されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    n, m, k = map(int, input().split())
    max_edge = [0] * (n + 2)
    for _ in range(m):
        u, v = map(int, input().split())
        max_edge[u] = max(max_edge[u], v)
    
    reach = 0
    ans = 1
    for i in range(1, n):
        left = max(reach, max_edge[i])
        right = min(i + k, n)
        options = right - left
        if options <= 0:
            continue
        ans = ans * options % MOD
        reach = max(reach, i + k)
    
    print(ans)

if __name__ == "__main__":
    solve()
```最初のセクションは入力を読み取り、初期化します。`max_edge`既存のエッジによって課される制約を追跡します。 頂点にわたるループは、距離不変を維持する各頂点の新しいエッジの有効範囲を計算します。 私たちが使用するのは`max(reach, max_edge[i])`最短パスの要件を破るエッジの追加を避けるため。 の`ans`変数は、10^9 + 7 を法とする有効な構成の合計数を累積します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | すべての頂点を 1 回反復し、すべての既存のエッジを 1 回処理します。 |
 | スペース | O(n) | 配列`max_edge`各頂点の最も遠いエッジを保存します。 |

 これは、n が 10^6 まで、m が 10^5 までの場合、2 秒以内に収まります。
