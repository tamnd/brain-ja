 ## 解決策
 ## 問題の理解

 正規の分数として書かれた有理数が与えられます。`p / q`、および有限の連分数として書かれた別の数。 

連分数の形式は次のとおりです。$$a_1 + \frac{1}{a_2 + \frac{1}{a_3 + \dots}}$$両方の表現が同じ有理数を表すかどうかを判断する必要があります。 

連分数の長さは最大でも 90 と小さいです。 値自体は次のように大きくできます。$10^{18}$, したがって、算術は慎重に行う必要があります。 Python は任意の大きな整数を自然に処理するため、固定幅の整数言語よりも実装がはるかに安全になります。 

ここでは、浮動小数点の直接比較はまったく信頼できません。 連分数は巨大な分子と分母を表す可能性があり、浮動小数点の丸めにより等価性チェックが静かに破損する可能性があります。 

最も危険なエッジケースは中間部分から発生します。 

次の入力を考えてみましょう。```
3 2
2
1 2
```連分数は次のようになります。$$1 + \frac{1}{2} = \frac{3}{2}$$正しい答えは、`YES`。 

浮動小数点を使用した不用意な実装では、次のような計算が行われる可能性があります。`1.4999999999999998`そして平等性を誤って拒否します。 

もう 1 つの微妙なケースは、連分数の長さが 1 である場合に発生します。```
5 1
1
5
```連分数は単純に`5`。 ネストされた分母はまったくありません。 少なくとも 2 つの項を盲目的に仮定するコードはクラッシュするか、間違った結果を生成します。 

もう 1 つのトリッキーなシナリオは、分数の削減が遅すぎる場合に発生します。```
1000000000000000000 1
2
999999999999999999 1
```連分数は次のようになります。$$999999999999999999 + \frac{1}{1} = 1000000000000000000$$中間値は非常に大きくなります。 64 ビット オーバーフローのある言語は、単純化する前に実装が増えると失敗します。 Python はオーバーフローを回避しますが、アルゴリズムは依然として数学的にクリーンなままでなければなりません。 

## アプローチ

 強引なアイデアは簡単です。連分数を分子と分母に明示的に評価し、それを次と比較します。`p / q`。 

端数を後ろから再構築できます。 サフィックスの値が次のようにすでにわかっていると仮定します。`x / y`。 次に前の項を追加します`a[i]`それを次のように変換します。$$a_i + \frac{y}{x} = \frac{a_i x + y}{x}$$これが機能するのは、すべての有限の連分数が有理数を表すためです。 

ブルート フォース バージョンでは、任意精度の算術演算を使用して分数を繰り返し構築します。 以来`n ≤ 90`、巨大な整数であっても管理可能です。 このアルゴリズムは、線形多算演算のみを実行します。 

重要な観察は、実際には 10 進数値を計算したり、除算をシミュレートしたりする必要がまったくないということです。 連分数はユークリッド アルゴリズムと密接に関係しています。 

仮定する：$$\frac{p}{q} = a_1 + \frac{r}{q}$$それから：$$a_1 = \left\lfloor \frac{p}{q} \right\rfloor$$そして、剰余は継続分数の残りを再帰的に定義します。 

これは、与えられたシーケンスを次のユークリッド分解と直接比較できることを意味します。`p / q`。 

各ステップで:

 1. 次の連分数係数は次と等しくなければなりません`p // q`。 
2. 次に交換します`(p, q)`と`(q, p % q)`。 

これはまさにユークリッド アルゴリズムです。 

強引な構築はすでに快適に通過しています。`n`はわずか 90 ですが、ユークリッド解釈はより明確で単純であり、巨大な中間分子を明示的に構築することを避けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再構築 | O(n) | お(1) | 承認済み |
 | ユークリッド比較 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`p`そして`q`。 
2. 連分数列を読み取る`a`。 
3. 各値について`x`シーケンス内:

 かどうかを確認してください`p // q`等しい`x`。 

異なる場合、表現を等しくすることはできないため、次のように出力します。`NO`。 
4. 交換する`(p, q)`と`(q, p % q)`。 

これは連分数の再帰構造を反映しています。 整数部分を削除すると、残りの小数部分は次のようになります。$$\frac{q}{p \bmod q}$$5. すべての係数を処理した後、ユークリッド処理が正確に終了したことを確認します。 

残りの分母はゼロでなければなりません。 そうでない場合は、継続した端数が早く終了しすぎたことになります。 
6. 印刷`YES`すべてのチェックが成功した場合、そうでない場合は出力します`NO`。 

### なぜ効果があるのか

 有限連分数は、まさに次のユークリッド アルゴリズムによって生成される商のシーケンスです。`(p, q)`。 

すべての反復で:$$p = q \cdot \left\lfloor \frac{p}{q} \right\rfloor + (p \bmod q)$$整数商が次の連分数係数になります。 剰余は次の再帰分数を定義します。 

ユークリッド アルゴリズムは有理数を連分数係数に一意に分解するため、すべての商を一致させることで等価性が保証されます。 不一致がある場合は、表現された数値が異なることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p, q = map(int, input().split())

    n = int(input())
    a = list(map(int, input().split()))

    for x in a:
        if q == 0:
            print("NO")
            return

        if p // q != x:
            print("NO")
            return

        p, q = q, p % q

    if q == 0:
        print("YES")
    else:
        print("NO")

solve()
```実装はユークリッド アルゴリズムに直接に従います。 

ループは、各連分数係数を現在の整数商と比較します。`p // q`。 一度でも違うと平等はあり得ません。 

1 つの係数を消費した後、次を使用して次の残りの状態に移動します。```
p, q = q, p % q
```この変換は連分数再帰の核心です。 

最終チェックは微妙で見落としがちです。 ユークリッド アルゴリズムが終了したときに正確に分数展開が終了することを確認する必要があります。 もし`q != 0`すべての係数を処理した後、シーケンスが短すぎました。 

警備員:```
if q == 0:
```ループ内では、連分数がユークリッド分解よりも長いという不正な状況でのゼロ除算が防止されます。 

Python の整数は自動的に任意のサイズに拡張されるため、値が大幅に大きくなってもオーバーフローを心配する必要はありません。$10^{18}$。 

## 実用的な例

 ### 例 1

 入力:```
9 4
2
2 4
```トレース:

 | ステップ | p | q | p // q | 期待される係数 | 新しい (p, q) |
 | --- | --- | --- | --- | --- | --- |
 | 開始 | 9 | 4 | 2 | 2 | (4,1) |
 | 次へ | 4 | 1 | 4 | 4 | (1, 0) |

 すべての係数が処理された後、`q = 0`、したがって、答えは次のとおりです`YES`。 

このトレースは、連分数と Euclid のアルゴリズムの間の正確な関係を示しています。 商はすべてのステップで完全に一致します。 

### 例 2

 入力:```
3 2
2
1 3
```トレース:

 | ステップ | p | q | p // q | 期待される係数 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 開始 | 3 | 2 | 1 | 1 | 続ける |
 | 次へ | 2 | 1 | 2 | 3 | 不一致 |

 2 番目のステップでは、ユークリッド商は次のようになります。`2`、しかし連分数は期待します`3`。 表現が違うので答えは`NO`。 

これは、係数が 1 つも一致しない場合でも、すぐに不平等であることが証明されることを示しています。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    p, q = map(int, input().split())

    n = int(input())
    a = list(map(int, input().split()))

    for x in a:
        if q == 0:
            print("NO")
            return

        if p // q != x:
            print("NO")
            return

        p, q = q, p % q

    if q == 0:
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("9 4\n2\n2 4\n") == "YES\n", "sample 1"

# minimum size
assert run("5 1\n1\n5\n") == "YES\n", "single coefficient"

# mismatch in middle
assert run("3 2\n2\n1 3\n") == "NO\n", "wrong coefficient"

# exact large-value reconstruction
assert run(
    "1000000000000000000 1\n2\n999999999999999999 1\n"
) == "YES\n", "large integers"

# continued fraction too short
assert run("8 3\n1\n2\n") == "NO\n", "sequence ended early"

# continued fraction too long
assert run("2 1\n3\n2 1 1\n") == "NO\n", "sequence too long"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`5/1`と`[5]`|`YES`| 長さ 1 の連分数 |
 |`3/2`と`[1,3]`|`NO`| 商の不一致検出 |
 | 近くの巨大な値$10^{18}$|`YES`| 任意精度演算 |

 ## 特殊なケース

 単一要素の連分数を考えてみましょう。```
5 1
1
5
```アルゴリズムは次から始まります`p = 5`、`q = 1`。 

商は次のとおりです。$$5 // 1 = 5$$これは唯一の係数と一致します。 それから：$$(p, q) = (1, 0)$$ループが終了し、`q == 0`、したがって、答えは次のとおりです`YES`。 

このケースでは、実装が再帰部分のない連分数を正しく処理していることが確認されます。 

ここで、終了が早すぎるシーケンスを考えてみましょう。```
8 3
1
2
```最初の商は次のとおりです。$$8 // 3 = 2$$それは一致します。 状態は次のようになります。$$(p, q) = (3, 2)$$シーケンスはもう終わりましたが、`q != 0`。 ユークリッド過程にはまだ項が残っているため、答えは次のようになります。`NO`。 

これにより、最終的な終了チェックが検証されます。 

最後に、長すぎるシーケンスについて考えてみましょう。```
2 1
3
2 1 1
```加工後係数`2`、状態は次のようになります。$$(p, q) = (1, 0)$$アルゴリズムにはさらに多くの係数を読み取る必要があります。 以来`q == 0`、割り算は不可能で、答えはすぐに出ます。`NO`。 

これにより、無効な追加条項が誤って受け入れられることを防ぎます。
