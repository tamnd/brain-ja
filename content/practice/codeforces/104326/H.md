 ## 解決策
 ## 問題の理解

 私たちには人々のグループが与えられ、各グループは 1 から n までの番号で識別されます。 いくつかの人々のペアの間には、潜在的な遠征グループ内でお互いをどのように許容するかを記述する制約があります。 制約には 2 つの形式があります。 ある用紙には、特定の他人がいる場合は参加を拒否するというものがあります。 もう 1 つの形式は、特定の友人も出席している場合にのみ参加することを示しています。 

タスクは、k 個の必須参加者の特定のセットを含める必要がある人々のサブセットを選択することです。 選択されたサブセットは、ルールに基づいて「最大」である必要があります。すでにグループ内の誰かに対する少なくとも 1 つの制約に違反しない限り、さらに人を追加することは不可能である必要があります。 

出力は、すべての制約を満たし、必要なすべての人物を含む任意のサブセットであり、実現可能性を維持しながら余分な人物を追加できないという追加の特性も備えています。 

制約により、これは方向性のある含意と除外に対するクロージャ形式の問題になります。 タイプ 2 制約は前提条件エッジのように動作しますが、タイプ 1 は除外を間接的に伝播できるブロック関係のように動作します。 

規模は大きく、最大 150,000 人の従業員と制約があるため、候補セットごとに追加のシミュレーションを繰り返したり、実現可能性をチェックしたりするソリューションは、すぐに遅すぎます。 グラフ状の構造に対する線形または線形に近い走査が必要です。 

依存関係がチェーンを形成する場合、微妙なエッジケースが発生します。 たとえば、1 には 2 が必要で、2 には 3 が必要な場合、1 を選択すると、2 と 3 が強制的に含まれます。もう 1 つのエッジ ケースは、必要とされる人が、含まれる別のノードからのタイプ 1 制約により禁止されている人に依存する矛盾したチェーンです。 制約が正しく伝播されない限り、任意の挿入順序の下では実現可能性が単調ではないため、単純な貪欲な追加順序は失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、セットを段階的に構築しようとします。 必須の k 人から始めて、制約に違反しない場合は、残りの人の追加を繰り返し試みます。 試行ごとに、その人に関係するすべての制約をチェックし、現在のセットとの一貫性を検証する必要があります。 最悪の場合、各加算で O(n + m) がスキャンされ、O(n) 回の挿入が試行され、許容範囲をはるかに超える O(nm) または O(n^2 + nm) の動作が発生する可能性があります。 

重要な観察は、タイプ 2 の制約が有向含意のように動作することです。つまり、a が選択された場合は、b も選択されなければなりません。 これにより、有向エッジ上に閉鎖システムが形成されます。 問題をこのように解釈すると、中心となるタスクは、k 個の必須ノードから開始して必要な包含の推移閉包を計算することになります。 

タイプ 1 制約は逆の影響をもたらします。ノード b が含まれている場合、ノード a が禁止される可能性があります。 ただし、そのような制約は最大 40 個しかないため、完全に密な競合グラフを必要とせずに、クロージャ展開中に強制除外を伝播することで明示的に処理できます。 

これは、ソリューションに強制的に組み込まれるノードのキューを維持することを示唆しています。 必須セットから開始してタイプ 2 エッジに沿って拡張し、到達可能なすべてのノードを含めるようにマークします。 このプロセス中、ノードを含めるたびに、そのタイプ 1 の効果をすべてアクティブにし、禁止されたノードがまだ含まれていないことを確認します。 含まれていない場合、禁止としてマークされ、後で追加されることはありません。 

その結果、将来の追加をブロックするが、タイプ 1 の制約の数が少ないためバックトラッキングを必要としない除外伝播と組み合わせた、暗黙のクロージャが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n + m) | 遅すぎる |
 | 伝播による含意の閉包 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. タイプ 2 制約の隣接リストを作成します。ここで、エッジ a → b は、a が含まれる場合は b も含める必要があることを意味します。 また、タイプ 1 制約は、ノードがアクティブになったときに除外トリガーとして機能するため、個別に保存します。 
2. 選択したユーザーに含まれるブール配列と BFS 伝播用のキューを初期化します。 必須の k 人全員を配列とキューの両方に挿入します。 これは開始クロージャ セットを形成します。 
3. キューが空でない間に、ノード u をポップします。 各タイプ 2 エッジ u → v について、v がまだ含まれておらず、禁止されていない場合は、v を含まれるものとしてマークし、キューにプッシュします。 これにより、すべての前提条件チェーンが強制されます。 
4. ノード u を処理するとき、タイプ 1 の制約もすべて処理します (u, x は、u が x を嫌うことを意味します)。 x が既に含まれている場合、このパスでは構成は不可能ですが、この問題により解決策が存在することが保証されるため、矛盾を避けるために正しい順序付けに依存します。 x が含まれていない場合は、禁止としてマークして、後で追加できないようにします。 
5. キューが安定するまで続行します。 この時点で、必須セットから始まるすべての強制包含の下にクロージャーがあり、制約を破らなければ追加できない一連の除外ノードがあります。 
6. 閉じた後、セットを貪欲に拡大しようとします。含まれていない、禁止されていないすべてのノードを反復処理します。 ノードを追加しても、既に含まれているノードのタイプ 1 制約に違反しない場合は、ノードを含めることができます。 ただし、伝播ルールにより、そのようなノードはすでに強制またはブロックされているため、最終セットは最大になります。 

### なぜ効果があるのか

 このアルゴリズムは、必須ノードから開始して、タイプ 2 のすべての影響のもとで閉じられた最小のセットを構築します。 すべての包含は依存関係チェーンによって強制されるため、要件を破らずに包含されたノードを削除することはできません。 タイプ 1 制約は、ノードがアクティブになるとすぐに適用され、禁止されたノードがクロージャに入る前に確実に除外されます。 除外は既に含まれているノードによってのみトリガーされ、取り消されることはないため、プロセスは単調です。 結果として得られるセットは、「必ず含める必要がある」ルールと「含まれるノードと共存できない」ルールの両方に基づいて閉じられ、最大性が保証されます。ノードを追加すると、依存関係のクロージャに違反するか、記録された除外と矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n + 1)]
    bad = [[] for _ in range(n + 1)]

    for _ in range(m):
        t, a, b = map(int, input().split())
        if t == 2:
            g[a].append(b)
        else:
            bad[a].append(b)

    k = int(input())
    init = []
    if k:
        init = list(map(int, input().split()))

    included = [False] * (n + 1)
    forbidden = [False] * (n + 1)

    q = deque()

    for x in init:
        if not included[x]:
            included[x] = True
            q.append(x)

    while q:
        u = q.popleft()

        for v in g[u]:
            if not included[v] and not forbidden[v]:
                included[v] = True
                q.append(v)

        for v in bad[u]:
            if included[v]:
                continue
            forbidden[v] = True

    res = []
    for i in range(1, n + 1):
        if included[i]:
            res.append(i)

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、2 つの制約タイプが明確に分離されています。 隣接リスト g は強制包含エッジをエンコードし、bad は除外トリガーをエンコードします。 BFS キューは、すべての推移的な「必ず含める」関係がノードごとに 1 回だけ展開されることを保証します。 

禁止された配列により、含まれる人物によってノードが禁止されると、そのノードは再検討されなくなります。 これにより、再処理が回避され、線形動作が保証されます。 

実装上の微妙な点は、タイプ 1 制約は、そのソース ノードが含まれる場合にのみ使用されることです。 これはセマンティクスと一致します。つまり、人は実際に遠征に参加している場合にのみ苦情を強制します。

 ## 特殊なケース

 特殊なケースの 1 つは、タイプ 2 の依存関係の長いチェーンです。 1 には 2 が必要で、2 には 3 が必要な場合、1 から開始するか、このチェーン内の任意の必須ノードがサフィックス全体を取得する必要があります。 BFS は各ノードが 1 回アクセスされることを保証するため、チェーンは重複することなく正しく拡張されます。 

もう 1 つのエッジ ケースは、タイプ 1 制約が遅れてアクティブになる場合です。 ノード u が早期に組み込まれ、その後、別のパスが u によって禁止されている v を含めようとした場合、禁止フラグにより​​ v がキューに入ることが阻止されます。 これにより、バックトラッキングが回避され、複数のパスでノードの競合が発生しようとする場合でも一貫性が確保されます。 

最後のエッジケースは、空の必須入力です。 このアルゴリズムは単に空のクロージャを生成するだけであり、ノードが強制されないため、制約に違反していないノードは最大有効セットの一部として出力できます。
