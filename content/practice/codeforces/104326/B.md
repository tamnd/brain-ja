 ## 解決策
 ## 問題の理解

 私たちは回覧板を分割して取り組んでいます。$k$ラベル付きセクターを時計回りに配置します。 からの各番号$1$に$n$は別個のセクターに配置する必要があり、最終的な構成は厳密な読み取り順序を尊重する必要があります。$1$そして時計回りに歩くと必ず遭遇するはずです$2, 3, \dots, n$その正確な順序で、そして元に戻ります$1$。 

それぞれの数字$i$配置できるセクターのセットが制限されています。 著名な分野がある$x_i$、そのセクターから反時計回りに上まで移動できます。$a_i$ステップまたは時計回りに最大$b_i$ステップ。 それでそれぞれ$i$事実上、許容位置の円間隔があり、おそらく周囲が非対称です$x_i$。 

タスクは、1 つの有効な配置を構築することではなく、配置制約と時計回りの順序制約の両方が満たされるように、すべての数値に位置を割り当てる別個の方法が何通りあるかを数えることです。 

制約は小さいです。$n \le 15$、$k \le 60$。 これは直ちに、次のような指数関数的な挙動を示唆しています。$n$指数関数的なものは許容されますが、$k$不必要または無駄です。 小さいもの$n$これは、数値をシーケンスとして扱い、円を直接扱うのではなく、その順序に対して動的計画法を使用する必要があることを強く示唆しています。 

微妙な問題は、構造の円形の性質です。 順序付け条件は循環的です。これは、構成がローテーションまで定義されることを意味します。 シーケンスの開始位置を修正するのは無料ではありませんが、円を線形化するためには便利なテクニックになります。 

順序のラップアラウンドの性質を無視すると、単純な間違いが発生します。 たとえば、次の場合$k=5$有効な位置は次のように選択されます。$1$セクター4にあり、$2$セクター 1 では、4 からの時計回りの順序が正しくラップアラウンドしているにもかかわらず、線形解釈はこれを誤って拒否します。 

もう 1 つのよくある失敗は、グローバルな順序付けを強制せずに各数値を独立して処理することによって発生します。 すべての数値が許可された間隔内に配置されている場合でも、配置がリングの周囲で誤ってインターリーブされる可能性があるため、循環順序の制約に違反する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、すべての割り当てが試行されます。$n$間の異なるセクター$k$, 次に、各数値が許可された領域内にあるかどうか、および時計回りの順序の条件が満たされているかどうかを確認します。 ポジションを選択する方法は次のとおりです。$\binom{k}{n} \cdot n!$そして、割り当てごとに検証パスが必要になります。 これはすでに大きくなっているとき$k=60, n=15$、 以来$\binom{60}{15}$巨大です。 

重要な構造上の観察は、数値の相対的な時計回りの順序が事前に固定されていることです。$1$が選択されると、$2,3,\dots,n$円周上で時計回りに厳密に増加する順序で従う必要があります。 これにより、置換の自由が完全に失われます。 選択したセクターに任意に番号を割り当てることはなくなり、代わりに増加するシーケンスを選択します。$n$円上の位置。 

残りの難関は円形境界です。 シーケンスの開始位置を選択したら、その点で円を「カット」し、線として扱うことができます。 このカットの後、すべての有効な構成は、長さの線上で厳密に増加する位置のシーケンスに対応します。$k$ただし、各番号には依然として独自の許可セットがあり、それがカットを囲む可能性があります。 これにより、番号の可能な開始位置をすべて試してみるようになります。$1$、その選択の円を線形化し、増加するシーケンスに対して単純な DP を実行します。 

これにより、問題はせいぜい小規模な動的プログラミングに縮小されます。$k$開始点。それぞれの開始点には最大でもシーケンス構築 DP が含まれます$n \le 15$ステップと$k \le 60$ポジション。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て |$O(\binom{k}{n} \cdot n!)$|$O(n)$| 遅すぎる |
 | 増加シーケンスにわたる開始点 + DP |$O(k^2 \cdot n)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず周期対称性を修正してから、線形解を数えます。 

1. ホストするセクター番号を選択します$1$。 このセクターが時計回りの横断の起点になります。 すべての有効な円形配置は、位置を固定することによって正確に 1 回カウントされます。$1$有効な構成を回転しても相対的な順序は変わりませんが、開始点の選択が異なるためです。 
2. 選択したセクターから始まる円を直線セグメントに展開します。 カットの前の時計回りのセクターは、インデックスが 1 つ増加したものとして扱われます。$k$なので、さまざまな長さで作業します$k$ただし、いくつかの位置を次のように表すことができます。$x + k$彼らが包み込むとき。 
3. 数字ごとに$i$、許容される円間隔を展開されたラインに変換します。 間隔がカットを横切るかどうかに応じて、これは 1 つの連続したセグメントまたは 2 つのセグメントのいずれかになりますが、間隔の長さは厳密に より短いため、2 つを超えることはありません。$k$。 
4. から順に番号を処理します。$1$に$n$、最後に選択したポジションに対する DP を維持します。 DP 状態は、これまでに数字を配置した方法が何通りあるかを表します。$i$、展開されたライン上の特定の座標で終了します。 
5. 数字ごとに$i$、番号に遷移します$i+1$許可された位置を選択することにより、$i+1$それは厳密に現在の最後の位置の後にあります。 これにより、線形化された表現で時計回りの順序が直接強制されます。 
6. 数値を配置した後、すべての DP 状態を合計します。$n$。 これにより、選択された開始位置のすべての有効な配置がカウントされます。$1$。 
7. 可能なすべての開始セクターに対してプロセス全体を繰り返します。$1$、結果を蓄積します。 

この正しさは、すべての有効な円形構成が独自の回転を​​持っているという事実から来ています。$1$がカットとして選ばれます。 このカットの後、展開されたラインでは時計回りの順序が厳密に増加するシーケンスになり、すべての遷移では区別性と許可される配置制約の両方が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = []
    a = []
    b = []
    for _ in range(n):
        xi, ai, bi = map(int, input().split())
        x.append(xi - 1)
        a.append(ai)
        b.append(bi)

    ans = 0

    for start in range(k):
        # build allowed positions in unrolled line [start, start+k)
        allowed = [[] for _ in range(n)]

        for i in range(n):
            cx = x[i]

            for d in range(-a[i], b[i] + 1):
                pos = (cx + d) % k
                # map into unrolled coordinates
                if pos >= start:
                    u = pos
                else:
                    u = pos + k
                allowed[i].append(u)

            allowed[i] = sorted(set(allowed[i]))

        # dp over last position
        dp = [0] * (2 * k)
        for p in allowed[0]:
            if p >= start:
                dp[p] = 1
            else:
                dp[p + k] = 1

        for i in range(1, n):
            ndp = [0] * (2 * k)
            for last in range(2 * k):
                if dp[last] == 0:
                    continue
                for p in allowed[i]:
                    if p > last:
                        ndp[p] += dp[last]
            dp = ndp

        ans += sum(dp)

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、number の開始セクターを列挙します。$1$、次に、許可されたすべての円位置を一貫した線形座標系に変換します。 DP 配列には、厳密に増加位置を維持しながら、現在のインデックスまで数値を配置できる方法が何通りあるかが格納されます。 

重要な実装の詳細は座標リフティングです。カットの前の位置は次のようにシフトされます。$+k$。 これにより、時計回りの順序が整数の単純な増加順序になります。 条件`p > last`セクターの厳密な順序付けと独自性の両方を強制します。 

もう 1 つの微妙な点は、許可されたセット内の重複排除です。 それなし`set`、同じ位置が異なるラップアラウンド表現から複数回生成され、人為的にカウントが膨らむ可能性があります。

 ## 特殊なケース

 主なエッジケースは、数値の許容間隔が切り取り位置の周囲をラップする場合です。 この状況では、正規化前は同じ物理セクターが 2 つの異なる表現として表示されます。 内部の重複排除ステップ`allowed[i]`これらの重複によってパスが誤って複製されないようにします。 これがないと、2 つのモジュラー ルートを介して到達可能なセクターは、すべての継続パスを 2 倍にカウントし、最終的な答えが膨らむことになります。 

別の特殊なケースは、数値の有効な配置がすべてカットの完全に前にある場合に発生します。 展開ステップでは、それらすべてが次のようにシフトされます。$+k$、それらが以前のポジションよりも大きいままであり、順序を誤って壊さないようにします。 これにより、カットがどこに配置されるかに関係なく、すべての有効な時計回りのシーケンスがライン上で厳密に増加するという不変条件が維持されます。
