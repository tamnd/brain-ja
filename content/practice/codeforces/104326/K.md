 ## 解決策
 ## 問題の理解

 私たちには、数直線上の整数座標を占める人々の列が与えられています。 各人には 1 から n までのラベルが付けられ、立場が変わってもプロセス全体を通じてラベルが付けられたままになります。 

リープフロッグムーブと呼ばれる操作を実行することが許可されています。 1 回の移動で、X と Y という 2 人の人物を選択します。X は Y を飛び越えますが、ジオメトリは制限されています。ジャンプ後、両者は同じ線上に留まり、両者の間の距離は移動前とまったく同じままです。 実際、この操作により、ラベル付き点を任意にテレポートすることなく、線上のラベル付き点を制御して再配置することができます。 

目標は、初期の位置のマルチセットをターゲットのマルチセットに変換できるかどうかを判断し、可能であれば、それを達成する有効なリープフロッグ操作のシーケンスを出力することです。 

重要な点は、どの人物がどこで終了するかではなく、最終的なポジションの複数セットのみが重要であるということです。 ただし、この構築では、ターゲット構成の何らかの並べ替えを実現するために、ラベル付けされた個人を明示的に移動する必要があります。 

n ≤ 100 という制約は、二次推論や三次構造さえも許容できるほど十分に小さいように見えます。 ただし、操作の数は最大 5 × 10^5 と大きくなる可能性があるため、動きをシミュレートし、不必要なスワップを回避する方法に注意する必要があることがわかります。 

微妙なエッジ ケースは、初期マルチセットとターゲット マルチセットが異なる場合です。 たとえば、初期値が [1, 2] でターゲットが [1, 3] の場合、マルチセットを変更するときに許可される動きの不変構造を保持する方法はないため、答えは「いいえ」となります。 

もう 1 つの微妙なケースは、マルチセットは一致するが、順序が大幅に異なる場合です。 たとえば、[1, 100, 200] から [100, 200, 1] は可能ですが、直接の並べ替えステップではなく、一連の制御されたスワップが必要です。 「あらゆる順列が到達可能である」という素朴な考えは、建設的な方法を示さない限り安全ではありません。 

主な困難は、順列の実現可能性ではなく、制限されたリープフロッグ操作の下で順列を構築することです。 

## アプローチ

 ブルート フォース ビューでは、各状態がライン上のラベル付きトークンの順列として扱われます。 どのような状態からでも、可能なリープフロッグの動きをすべて試し、BFS または DFS を実行して目標の配置に到達します。 各状態は n 個の位置をエンコードする必要があり、各遷移は O(n^2) 個の動きを探索します。 積極的な枝刈りを行っても、状態空間は n! 最悪の場合、遷移が密になります。 これは、n = 10 の場合でも完全に実行不可能になります。 

重要な観察は、この操作が、隣接する要素を間接的に並べ替えるために使用できる構造化スワップのように動作することです。 座標は固定スロットに制限されず、行上の相対的な順序のみを考慮するため、並べ替えのようなプロセスをシミュレートできます。 制御されたジャンプを使用して要素を所定の位置に「バブル」できることがわかれば、問題は、座標の自由を尊重しながら、ある順列を別の順列に並べ替える一連の交換を構築することになります。 

これにより、問題は建設的な置換変換問題に変換されます。マルチセットが一致する場合、最初のソート順序をターゲットのソート順序にマッピングし、リープフロッグによってシミュレートされた隣接する転置を介して置換を実現できます。 

したがって、状態を調査する代わりに、ターゲットの割り当てを修正し、ローカル交換を使用して各人を正しい位置に移動する決定論的な方法を実装します。

 ## アルゴリズムのチュートリアル

 まず、初期位置の複数セットがターゲット位置の複数セットと等しいかどうかを確認することで問題を正規化します。 そうでない場合、一連の操作は成功しません。

それらが一致すると仮定して、ターゲットの割り当てを作成します。インデックスを現在の位置とターゲットの位置で並べ替え、それらをペアにして、各人がどこで終了する必要があるかを認識します。 

次に、スワップのようなリープフロッグを使用して、各人物を所定の位置に移動するシミュレーションを行います。 

1. 人々を現在の位置で並べ替え、配列 current_order を生成します。 

これにより、ラインに沿って安定した参照順序付けが行われます。 
2. ターゲットのポジションごとに人々を並べ替えて、target_order を生成します。 

これにより、ライン内の各ランクが最終的にどこに行くべきかがわかります。 
3. current_order[i] が target_order[i] の位置に移動するようにマッピングを構築します。 

これにより、問題はある順列を別の順列に変換するというものに縮小されます。 
4. 列に沿った人の現在の順序を表す配列を維持します。 
5. 左から右の各ポジション i について、正しい人が i に配置されていることを確認します。 

適切な担当者がすでに存在する場合は、続行します。 
6. そうでない場合は、対象人物を j > i のいずれかの位置に配置し、i に到達するまで左方向に段階的に移動するリープフロッグ操作を繰り返します。 

各リープフロッグは、有効性を維持しながら、隣接する参加者との相対的な順序を効果的に交換します。 
7. スワップのような動きを実行するたびに各操作 (X、Y) を記録し、X が正しい方向に Y を飛び越えることを確認します。 
8. 全体の順序が target_order と一致するまで続行します。 

重要な考え方は、current_order と target_order の間のすべての反転は、ローカルなリープフロッグ操作の制限されたシーケンスを使用して解決でき、各反転は単調に削除されるということです。 

### なぜ効果があるのか

 位置 i を固定した後、位置 < i にあるすべての要素がすでにターゲットの順序と一致しており、再度移動する必要がないという不変条件を維持します。 各操作により、現在の順序とターゲットの順序の間の逆転の数が減ります。 反転は有限であり、スワップのようなリープフロッグごとに厳密に減少するため、プロセスは終了する必要があります。 すべてのスワップは有効なリープフロッグに対応するため、許可された設定のセットから離れることはありません。また、左から右へのみ固定するため、以前に固定された位置を壊すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    if sorted(a) != sorted(b):
        print("No")
        return

    # pair people by sorted order
    cur = sorted(range(n), key=lambda i: a[i])
    tgt = sorted(range(n), key=lambda i: b[i])

    # target position for each person
    target_pos = [0] * n
    for i in range(n):
        target_pos[cur[i]] = b[tgt[i]]

    # current order of indices
    order = cur[:]

    pos = [0] * n
    for i in range(n):
        pos[order[i]] = i

    ops = []

    def swap_adj(i):
        x = order[i]
        y = order[i + 1]
        # x jumps over y
        ops.append((x + 1, y + 1))
        order[i], order[i + 1] = order[i + 1], order[i]
        pos[x], pos[y] = pos[y], pos[x]

    for i in range(n):
        want = tgt[i]
        want_person = cur[i]

        j = pos[want_person]
        while j > i:
            swap_adj(j - 1)
            j -= 1

    print("Yes")
    for x, y in ops:
        print(x, y)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずマルチセットの等価性を通じて実現可能性をチェックします。 これがなければ、一連の動きで異なる位置セットを調整することはできません。 

ソートされたペアリングのステップは重要な削減です。最初は ID を無視してランクを一致させます。 これにより、問題はインデックスの 1 つの順列を別の順列に変換することに変換されます。 

の`order`配列は現在の行の順序を表します。 の`swap_adj`関数は私たちがシミュレートする唯一の原始的な操作であり、この縮小されたモデルで隣接する要素を交換するものとして解釈されるリープフロッグ移動に直接対応します。 

内側のループは、必要な各人物を正しい位置に到達するまで左に移動します。 各移動は操作を記録し、順列状態を一貫して更新します。

 ## 特殊なケース

 エッジケースの 1 つは、すべての位置が同一である場合です。 この状況では、すべての順列は自明に有効であり、並べ替えられた順序がターゲットのペアとすでに一致しているため、アルゴリズムは交換を実行しません。 どちらの順序付けにも反転が存在しないため、不変式が成り立ちます。 

もう 1 つの特殊なケースは、完全に逆の順序です。 アルゴリズムは、順序が修正されるまで、隣接するスワップを繰り返し適用します。 各スワップは反転カウントをちょうど 1 つ減らし、n(n−1)/2 操作以内に終了することを保証します。 

最後のエッジ ケースは、n = 1 の場合です。操作は存在せず、単一の位置が一致する限り、答えは常に Yes になります。 両方の並べ替えられたリストが同一であり、ループ本体が実行されないため、アルゴリズムがこれを処理します。
