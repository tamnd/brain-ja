 ## 解決策
 ## 問題の理解

 ここでは、パーティション ステップが非常に特殊な方法で記述され、ランダム ジェネレーターの繰り返し呼び出しによって生成される、事前に選択されたピボット インデックスのシーケンスに依存する、クイックソートの決定論的バリアントが与えられます。 配列は 1 から n までの数値を並べたものですが、実際の値は不明です。 わかっているのは、実行中にピボットとして使用されるインデックスの正確なシーケンス (消費される順序) です。 

パーティション プロシージャは標準の 2 ポインター パーティションのように動作しますが、重要な工夫が施されています。ピボットは値ではなくインデックスによって選択され、スワップ中にピボットの位置が移動する可能性があります。 分割後、ピボットは最終位置に復元され、最初に左側のサブ配列、次に右側のサブ配列で再帰が続行されます。 

この関数は、実行中に実行された比較とスワップの数に比例した値を返します。 すべてのパーティションは、現在のセグメントのサイズに等しいコストに再帰的な寄与を加えたコストをもたらします。 私たちの目標は、ピボット インデックスのこの正確なシーケンスが使用されたときに返される値の合計が最大化されるように、1 から n の順列を構築することです。 

制約は小さく、n ≤ 50 です。これは、サブセットにわたる指数関数または DP が許容されることを直ちに示唆しています。 すべての可能な配列を直接シミュレートしようとする解決策は、n! 個あるため実行不可能です。 しかし、ピボット シーケンスの構造は再帰ツリーに大きな制約を与えます。 

微妙な失敗のケースは、コード内のアサーションに起因します。ピボット インデックスは常に現在のセグメント内に存在する必要があります。 スワップによる要素の移動方法により、ピボットが予想される再帰範囲外になるような配列を構築した場合、プロセスは無効になります。 ローカル パーティション コストを最大化するだけの単純な貪欲な構造は、この構造に簡単に違反する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、1 から n までのすべての順列を列挙し、指定されたピボット シーケンスを使用してそれぞれの順列の分割プロセスをシミュレートします。 縮小するセグメント上で分割が繰り返されるため、最悪の場合、各シミュレーションのコストは O(n^2) であり、n! 個あります。 これは、n = 15 の場合でも大きすぎます。 

重要な観察は、アルゴリズムの動作が各セグメントのピボットに対して値がどのように分散されるかによって完全に決定されるということです。 各ピボットにより、現在の間隔が左右の部分問題に分割されます。 パーティションのコストはセグメント サイズによって決まりますが、再帰の正確さは、選択したピボット値がパーティション化後に一貫した位置になるかどうかによって決まります。 

これにより、問題はインデックス 1 から n にわたるバイナリ再帰構造の構築に変換されます。各ノードはセグメントに対応し、指定されたシーケンスからピボットを割り当てる必要があります。 ピボット シーケンスは、この再帰ツリーのノードが「開かれる」順序を定義します。これは、構造を事前にシミュレートし、サブツリー サイズを考慮した方法で値を割り当てることができることを意味します。 

最適な戦略は、ピボット シーケンスによって引き起こされる再帰ツリーを再構築し、より大きなセグメントへのより高い値の寄与を最大化する方法で値を昇順にノードに割り当てることです。 スワップ ディスプレイスメントを最大化するには、より大きな値が再帰でより上位に表示される必要があるため、代入を走査順序の制約に合わせます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n^2) | O(n) | 遅すぎる |
 | ツリー再構成 + 代入 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ピボット シーケンスが有効な場合にクイックソートがどのようにセグメントを分割するかをシミュレートしますが、値を処理する代わりに、セグメント構造を処理します。

1. 最初の呼び出しをセグメント [1, n] を表すルート ノードとして扱います。 ピボット シーケンスは、ノードが最初に処理されるたびに順番に消費されます。 これにより、各ノードが左右の子に分割されるバイナリ再帰ツリーが定義されます。 
2. セグメント [L, R] については、次の未使用のピボット インデックス p を取得します。 このピボット インデックスは元の実行の現在のセグメントに属しているため、このノードのルートとして割り当てます。 セグメントは [L, p-1] と [p+1, R] に分割され、左右の子を形成します。 
3. 最初に左側のセグメントを再帰し、順番にピボットを消費してから、右側のセグメントを再帰します。 これにより、元の関数の正確な実行順序が保存され、左再帰が右再帰の前に発生します。 
4. いずれかの時点で次のピボット インデックスが現在のセグメント内にない場合、元のコードはピボットがアクティブな間隔内になければならないというアサーションを保証しているため、構築は失敗します。 その場合、有効な配列は存在しません。 
5. ツリー構造が固定されたら、ツリーの順序走査を使用して、1 から n までの値を昇順に割り当てます。 各ノードは一意の値を受け取り、結果が有効な順列であることを保証します。 
6. 結果の配列は、割り当てられた各値を対応するピボット位置に配置することによって形成されます。 

### なぜ効果があるのか

 すべてのピボットがそのセグメントと一致している限り、ピボット シーケンスによって再帰ツリーの形状が完全に決定されます。 各ノードは一意のセグメント パーティションに対応し、ピボット ID で重複する 2 つのノードはありません。 構造が固定されたら、自由になるのはノードに値を割り当てることだけです。 コストは特定の値の比較ではなく、セグメント サイズと再帰構造によって決まるため、ツリーと一致する有効な順列があれば十分です。 走査順序で値を割り当てると、一貫性が確保され、パーティション制約への違反が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    pivots = list(map(int, input().split()))
    
    idx = 0
    tree = {}
    pos = [0] * (n + 1)
    
    def build(l, r):
        nonlocal idx
        if l > r:
            return None
        if idx >= n:
            return None
        
        p = pivots[idx]
        if p < l or p > r:
            return None
        
        idx += 1
        tree[p] = [None, None]
        
        left = build(l, p - 1)
        right = build(p + 1, r)
        
        tree[p][0] = left
        tree[p][1] = right
        return p
    
    root = build(1, n)
    
    if idx != n or root is None:
        print("No solution")
        return
    
    val = 1
    
    def assign(u):
        nonlocal val
        if u is None:
            return
        assign(tree[u][0])
        pos[u] = val
        val += 1
        assign(tree[u][1])
    
    assign(root)
    
    print("Solution exists")
    print(*pos[1:])

if __name__ == "__main__":
    solve()
```この解決策は、まず、ピボット シーケンスによって引き起こされる暗黙的な再帰ツリーを再構築します。 各ピボット インデックスは現在のセグメントに対して検証され、パーティショニング プロセスとの一貫性が確保されます。 いずれかのピボットがセグメント制約に違反すると、構築はただちに停止します。 

ツリーを構築した後、各位置が 1 から n までの一意の値を受け取るように、順序トラバーサルを使用して値を割り当てます。 最終的な配列は、各ピボット位置を割り当てられた値にマッピングすることによって構築されます。 

微妙な点は、再帰の優先順位 (親、左のサブツリーの前、右のサブツリーの前) でピボットを厳密に消費する必要があることです。 逸脱があると、元の実行順序との整合性が崩れます。

 ## 特殊なケース

 サイズ 1 の最小入力は、有効な単一ピボットを超えるセグメント制約がないため、常に成功します。 

反転または非単調ピボット シーケンスは、再帰的なセグメント境界を尊重する場合にのみ有効です。 たとえば、`2 1 4 3`、最初のピボットは範囲を 2 つの有効な独立したセグメントに分割し、後続のピボットは再帰中にそれらのセグメントに正しく一致します。 この構築では、各ピボットが自然に正しいサブツリーに配置されるため、割り当ては引き続き成功します。 

のようなケース`1 7 1 7 1 7 1`分割後、再帰ではピボットが徐々に小さいセグメント内に残ることが期待されますが、シーケンスはアクティブな間隔に属さなくなったインデックスを繰り返し参照するため、失敗します。 ピボットが失敗すると、アルゴリズムはこれを即座に検出します。`[L, R]`工事中にチェック。
