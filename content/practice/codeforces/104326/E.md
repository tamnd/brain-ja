 ## 解決策
 ## 問題の理解

 各家がノードであり、既存の各線路が一方通行のエッジである有向グラフが与えられます。 プーさんは、指定された方向のエッジに沿ってのみ移動できます。 目標は、有向エッジに沿って移動することで、すべての家から他のすべての家に確実に到達できるようにすることです。 これを達成するために、新しい有向エッジを追加することができますが、追加するエッジはできるだけ少なくしたいと考えています。 

出力は、必要なエッジの最小数だけでなく、追加するエッジの明示的なリストでもあります。 すべての最適解の中で、まず開始点でエッジを比較し、次に終点でエッジを比較し、シーケンスを要素ごとに比較して、追加されたエッジの辞書編集上最小のシーケンスを出力する必要があります。 

n ≤ 500 および m ≤ 800 という制約は、O(n^3) または O(nm) のアプローチは許容されるが、n の指数関数は許容されないことを示しています。 エッジのサブセットを試したり、追加するたびに到達可能性を再計算したりする単純なアプローチでは遅すぎます。 

重要な微妙な点は、グラフには有向性があり、任意の方法で強く接続することが求められるのではなく、最終的な有向グラフが強く接続されるようにエッジを追加することが求められることです。 これはまさに、強力な接続性を実現するための最小限のエッジ拡張問題です。 

いくつかの特殊なケースが重要です。 

グラフがすでに強く結びついている場合、答えは空です。 単純なソリューションでは、弱い到達可能性に基づいて接続性を誤って想定した場合、エッジを追加しようとする可能性があります。 

グラフが完全に切断されている場合、つまりエッジがまったくない場合、到達可能性の点ですべてのノードが独自のコンポーネントとなり、それらを最適に接続する必要があります。 

もう 1 つの微妙なケースは、強く結合したコンポーネントへの凝縮が連鎖を形成する場合です。 この場合、コンポーネント間に必要なエッジは 1 つだけですが、コンポーネントのすべてのペアを接続する単純なアプローチでは過剰にカウントされてしまいます。 

## アプローチ

 強引なアイデアは、これを最短の拡張問題として扱うことです。グラフが強く接続されているかどうかを繰り返しチェックし、そうでない場合は、考えられるすべてのエッジを追加して、結果を再帰的に調べます。 各接続性チェックには BFS または Floyd-Warshall 経由で O(n(n + m)) がかかり、分岐係数は O(n^2) で、非常に小さな入力を超えるとすぐに爆発します。 

重要な観察は、強力な接続性は強接続コンポーネント (SCC) の構造のみに依存するということです。 各 SCC 内では、すべてのノードがすでに相互に到達しているため、各 SCC を単一のノードに圧縮できます。 結果として得られるグラフは、凝縮グラフと呼ばれる有向非巡回グラフ (DAG) です。 

この DAG では、問題はエッジを追加することで DAG を強く接続することに帰着します。 古典的な結果では、必要なエッジの最小数は max(ソース コンポーネントの数, シンク コンポーネントの数) になります。ここで、ソースは凝縮 DAG で入次数 0 を持ち、シンクは出力次数 0 を持ちます。 

その理由は構造的なもので、すべてのソース SCC は少なくとも 1 つの入力エッジを受信する必要があり、すべてのシンク SCC は少なくとも 1 つの出力エッジを持たなければなりません。 1 つのエッジが両方の役割を満たすことができるのは、シンクとソースを周期的にペアリングする場合のみです。 

辞書編集上の要件により、SCC から代表的なノードを慎重に選択し、エンドポイントのソート順にエッジを追加する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数 | 高い | 遅すぎる |
 | 最適 (SCC + ペアリング) | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 当社は、SCC の凝縮とコンポーネントの慎重な組み合わせを通じてソリューションを構築します。

1. Kosaraju または Tarjan を使用して有向グラフの SCC を計算します。 各ノードはコンポーネント ID を受け取ります。 コンポーネント間にエッジを追加すると、SCC の内部構造が到達可能性に影響を及ぼさないため、このステップは不可欠です。 
2. 各 SCC がノードとなる要約グラフを構築します。 comp[u] ≠ comp[v] であるすべての元のエッジ u → v に対して、コンポーネント間に有向エッジを追加します。 各 SCC の入次数と出次数も計算します。 
3. 入次数が 0 のすべての SCC をソースと呼ばれるリストに収集し、出次数が 0 のすべての SCC をシンクに収集します。 これらは、グローバルな到達可能性をブロックするコンポーネントです。 
4. SCC が 1 つだけの場合、グラフはすでに強く接続されており、ゼロ エッジを出力します。 
5. それ以外の場合は、各 SCC の代表頂点を準備します。 辞書編集的な最小化は可能な限り最小のエンドポイントを選択することに依存するため、各コンポーネント内の最小のインデックス付き頂点を選択します。 
6. シンクとソースを周期的に照合します。 s 個のシンクと t 個のソースがある場合、i 番目のシンクと (i+1) 番目のソースを t を法にしてそれらをペアにしますが、エッジの数は両方のセットをカバーするのに必要な数だけです。 これにより、エッジの最小数が max(s, t) に等しくなることが保証されます。 
7. 各ペア (sink_component、source_component) について、シンクの代表ノードからソースの代表ノードにエッジを追加します。 
8. 最後に、結果のエッジを (a, b) で辞書順に並べ替えて出力します。 

辞書編集上の最小要件は、SCC ごとに最小の代表を常に選択し、コンポーネント ID の昇順でペアリングし、最終的なリストをソートすることによって満たされます。 

### なぜ効果があるのか

 凝縮グラフは DAG であり、強く接続された拡張はすべて、すべてのソースが受信到達可能性を獲得し、すべてのシンクが送信到達可能性を獲得することを保証する必要があります。 したがって、有効なソリューションには少なくとも max(#sources, #sinks) エッジが含まれている必要があります。 この構造では、シンクとソースをペアにすることでこの境界を明示的に達成するため、すべての欠陥のあるコンポーネントが修正され、SCC の最小代表によって、代替の選択肢が最初の異なる位置で辞書編集的に小さいエッジを生成できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, adj, radj):
    visited = [False] * (n + 1)
    order = []

    def dfs1(u):
        visited[u] = True
        for v in adj[u]:
            if not visited[v]:
                dfs1(v)
        order.append(u)

    def dfs2(u, comp_id):
        comp[u] = comp_id
        for v in radj[u]:
            if comp[v] == -1:
                dfs2(v, comp_id)

    for i in range(1, n + 1):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * (n + 1)
    cid = 0

    for u in reversed(order):
        if comp[u] == -1:
            dfs2(u, cid)
            cid += 1

    return comp, cid

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    radj = [[] for _ in range(n + 1)]

    edges = []
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        radj[b].append(a)
        edges.append((a, b))

    comp, c = kosaraju(n, adj, radj)

    if c == 1:
        print(0)
        return

    indeg = [0] * c
    outdeg = [0] * c
    rep = [10**9] * c

    for i in range(1, n + 1):
        rep[comp[i]] = min(rep[comp[i]], i)

    for u, v in edges:
        cu, cv = comp[u], comp[v]
        if cu != cv:
            outdeg[cu] += 1
            indeg[cv] += 1

    sources = []
    sinks = []

    for i in range(c):
        if indeg[i] == 0:
            sources.append(i)
        if outdeg[i] == 0:
            sinks.append(i)

    k = max(len(sources), len(sinks))
    res = []

    for i in range(k):
        s = sinks[i % len(sinks)]
        t = sources[i % len(sources)]
        res.append((rep[s], rep[t]))

    res.sort()
    print(len(res))
    for a, b in res:
        print(a, b)

if __name__ == "__main__":
    solve()
```この実装では、最初にグラフを SCC に圧縮し、次に凝縮グラフの入次数と出次数を計算します。 代表は各コンポーネントの最小の元のノードとして選択され、辞書編集的な最小化を直接サポートします。 

ペアリングのステップでは、モジュール式インデックスを使用して、片側の要素が少ない場合に循環的に再利用されるようにします。これは、最大(ソース、シンク) 境界を達成する標準的な構造です。 

最後にソートすると、ペアリングによってエッジが任意の順序で生成された場合でも、最終出力は辞書編集順に従うことが保証されます。

トレースは、1 つのソースが再利用せずに複数のシンクに供給できないことを示しているため、ソース リストを循環させます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフがすでに強く接続されている場合です。 その場合、SCC 圧縮により単一のコンポーネントが生成され、アルゴリズムはすぐにゼロを返します。 ソースとシンクを接続しようとする単純なアプローチでは、入次数リストと出力次数リストが空であってもエッジが誤って追加されてしまいます。 

もう 1 つの特殊なケースは、ソースよりもシンクの方が多い場合です。 そのような状況では、循環ペアリングによりソース コンポーネントが確実に再利用されます。 たとえば、シンクが [A、B、C] でソースが [D] の場合、エッジ C→D、A→D、B→D を何らかの順序で追加し、辞書順に並べ替えた後もカウントを最小限に抑えながら正確性を満たします。 

最後の微妙なケースは、SCC 内の複数の頂点が代表として機能する可能性がある場合です。 任意のノードを選択すると、辞書編集上の最小性が損なわれる可能性があります。 SCC ごとに最小のインデックス付き頂点を常に選択することで、すべてのエッジが最初の座標でできるだけ小さくなり、ソートによって 2 番目の座標での結合が解決されます。
