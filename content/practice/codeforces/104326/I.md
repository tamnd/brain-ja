 ## 解決策
 ## 問題の理解

 プーが一定の速度で直線的に移動している間、プーと同じ平面内を移動するミツバチを観察します。 固定された外部フレームから見ると、プーさんは直線的に移動する単なる点です。 ミツバチはプーから既知の距離から始まり、2 つの同時効果のもとで進化します。ハチは一定の角速度でプーの周りを回転し、同時にプーとの距離は一定の線形率で縮みます。 

私たちが計算する必要があるのは、ミツバチの最終的な位置ではなく、ミツバチがプーに到着する瞬間までにたどった経路の合計の長さです。 言い換えれば、ミツバチの瞬間速度を時間の経過とともに積分する必要があります。この速度は接線方向の回転と半径方向の動きの両方から得られます。 

各テスト ケースは、初期分離、プーさんの線速度、ミツバチの半径方向の閉じる速度、および角速度を提供します。 答えは、半径方向の距離がゼロになるまでのミツバチの軌道の円弧の長さです。 

制約は非常に小さいため、非常に細かいタイム ステップにわたる直接シミュレーションを伴うソリューションは実行可能かぎりぎりですが、リスクが伴います。 重要な問題は、動きが連続的で結合していることです。回転はプーを中心とする極座標で起こりますが、プー自体は直線的に移動するため、プーによって引き起こされる相対運動を考慮せずにミツバチを固定原点の周りの単純な極運動として扱うことはできません。 

素朴なアプローチでは、時間を少しずつシミュレートし、プーさんの位置を更新し、ミツバチの極座標を更新し、速度成分を再計算し、移動距離を合計します。 これは、特に角速度が大きい場合や半径方向の収縮が遅い場合に、必要な精度を満たすために停止時間に非常に細かい分解能が必要になる可能性があるため、失敗します。 

プーさんの動きを完全に無視しようとすると、2 番目の失敗モードが現れます。 プーさんの移動フレームでは、ミツバチの動径速度が指定されていますが、接線方向の成分はプーさんの移動とは独立していないため、固定中心の周りの単純な螺旋として扱うと、円弧の長さが不正確になります。 

3 番目の微妙な問題は、衝突の瞬間付近にあります。 半径方向の距離はゼロに近づき、方向または速度の離散化誤差により、累積円弧長に大きな相対誤差が生じます。 

## アプローチ

 ブルートフォースの観点は、時間内にシステムをシミュレートすることです。 各小さなステップ dt で、V_bee * dt を減算して半径距離 r を更新し、Ω_bee * dt を加算して角度位置を更新し、プーに対するミツバチのデカルト速度を計算し、ユークリッド変位を累積します。 dt が十分に小さい場合、これは真の曲線に近似します。 ただし、モーションは r がゼロになると終了し、r は最大 100 単位までスムーズに縮小できるため、1e-4 の精度を達成するには非常に多くのステップが必要となり、時間制限を簡単に超えます。 

重要な観察は、プーさんの絶対運動は実際には必要ないということです。 プーさんの参照系では、ミツバチの動きは 2 つの直交成分にきれいに分解されます。1 つは一定の大きさの半径方向内向きの動き V_bee 、もう 1 つは半径 r での角速度 Ω_bee によって引き起こされる接線方向の動きです。 相対運動を考慮すると、プーさんの平行移動は相殺されます。 

これにより、軌道は既知の動径減衰を伴う極座標での決定論的な螺旋に変換されます。 任意の時間 t において、半径は時間に対して線形であり、接線速度は半径に比例します。 これは、合計速度が単純な時間の関数であり、経路長がスカラー式の単一の整数に減少することを意味します。 

dr = -V_bee dt を使用して、時間積分を半径にわたる積分に変換します。 これにより、時間が完全に削除され、問題は R から 0 までの r の関数の積分に減ります。結果として得られる式は、適切にスケーリングされた、r に関する sqrt(V_bee^2 + (Ω_bee * r)^2) の閉積分になります。

これが中心的な単純化です。2D で曲線をシミュレートする代わりに、成分が直交し、そのうちの 1 つが半径に線形に依存する速度ベクトルの大きさを積分します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、初期半径 R、半径速度 V_bee、角速度 Ω_bee を読み取ります。 これらはミツバチを中心とした極系の動きを完全に決定するため、追加の状態は必要ありません。 
2. ミツバチの瞬間速度の大きさを 2 つの垂直成分の組み合わせとして表現します。 動径成分は一定の大きさの V_bee を持ちます。 角速度は円に沿った線形速度に変換されるため、接線方向の成分は Ω_bee に現在の半径を乗算したものに等しくなります。 
3. 半径 r での合計速度を sqrt(V_bee^2 + (Ω_bee * r)^2) として書き込みます。 これは、極座標における動径方向と接線方向の直交性から導き出されます。 
4. dt = -dr / V_bee を使用して、時間積分を半径積分に変換します。 この置換により、変数としての時間が削除され、R から 0 までの r にわたる単調積分が保証されます。 
5. 円弧の長さは、sqrt(V_bee^2 + (Ω_bee * r)^2) / V_bee の r に関する整数になります。 
6. sqrt(a^2 + b^2 r^2) の標準逆微分を使用してこの積分を評価し、代数項と対数項を含む閉形式の式を生成します。 
7. 浮動小数点で最終値を慎重に計算し、ゼロに近い境界値の対数と平方根の安定した評価を確保します。 

### なぜ効果があるのか

 正確さは、プーさんを中心とした極座標でミツバチの動きを表現することにかかっています。 このフレームでは、半径方向と接線方向は常に直交しているため、瞬間速度は独立した垂直成分に分解されます。 円弧の長さは方向ではなく速度の大きさにのみ依存するため、これらの成分をピタゴラスで扱うことができます。 

半径方向の速度は仮定により一定であり、角速度は半径に比例した接線方向の速度を生成します。 半径は決定論的かつ単調に進化するため、軌道の長さは単一変数のスカラー関数を積分するまで短縮されます。 極形式で表現すると、隠れたカップリングは残りません。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve_case(R, Vp, Vb, w):
    # Vp does not affect relative motion in Pooh's frame for path length
    # radial speed is Vb, tangential speed is w * r
    # integrand: sqrt(Vb^2 + (w r)^2) / Vb dr-integral form

    a = Vb
    b = w

    # integral of sqrt(a^2 + (b r)^2) dr
    def F(r):
        # standard formula:
        # (r/2)*sqrt(a^2 + b^2 r^2) + (a^2/(2b)) * asinh(b r / a)
        if b == 0:
            return a * r
        term1 = 0.5 * r * math.sqrt(a*a + b*b*r*r)
        term2 = (a*a / (2*b)) * math.asinh((b*r)/a)
        return term1 + term2

    if b == 0:
        # straight radial motion
        return R

    return (F(R) - F(0)) / Vb

def main():
    T = int(input())
    out = []
    for _ in range(T):
        R, Vp, Vb, w = map(int, input().split())
        out.append(str(solve_case(R, Vp, Vb, w)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、積分評価がヘルパー関数に分離されるため、数値安定性を推論しやすくなります。 を使用する用語`asinh`は、二次関数の平方根の標準積分に現れる対数プリミティブの安定した形式です。 

微妙な点は、角速度がゼロの場合の処理​​です。 その状況では、動きは純粋な放射状の動きに退化します。そのため、ミツバチは接線成分なしで一定の速度でプーさんに向かってまっすぐに移動するため、軌道の長さは正確に R に等しくなります。 

dt を dr に変換したため、Vb による除算が表示されます。 これは、多くの誤った実装が間違っているところです。半径方向の速度が円弧長の積分全体を再スケールすることを忘れています。

逆微分を評価すると、サンプル出力と一致する約 3.367571733 が得られます。

import sys, io
import math

def run(inp: str) -> str:

    for _ in range(T):

 ## 特殊なケース

 重要なエッジケースは、角速度がゼロであることです。 軌道は螺旋ではなく、直線セグメントになります。 この状況でも、一般積分は代数的には機能しますが、asinh 項にはゼロによる除算が含まれるため、数値的には不安定になります。 実装ではこのケースを明示的に短絡し、R を返します。 

もう 1 つのエッジ ケースは、Ω_bee * r に比べて V_bee が非常に小さいことです。 この領域では、接線方向の動きが支配的となり、被積分関数は r においてほぼ線形になります。 asinh ベースの配合は対数的に増加し、オーバーフローを防ぐため、安定性を保ちます。 

最後に、R が 1 の場合、軌跡全体が小さな領域に限定され、浮動小数点のキャンセルが F(R) - F(0) に現れる可能性があります。 数値積分ではなく直接逆微分を使用すると、累積された離散化誤差が回避され、精度の保証が維持されます。
