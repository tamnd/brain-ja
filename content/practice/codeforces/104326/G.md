 ## 解決策
 ## 問題の理解

 オブジェクトのコレクションが与えられます。各オブジェクトには数値と、他のオブジェクトへの参照の固定順序リストが含まれます。 参照は有向構造を形成し、この構造にはサイクルが含まれる場合があります。 このタスクは、すべてのオブジェクトを等価クラスに分割することです。このクラスでは、2 つのオブジェクトの「完全に展開された構造」が同一である場合、つまり、それらのスカラー値が等しく、それらの参照リストが同じ順序で等価であるオブジェクトを指している場合に、2 つのオブジェクトが同じクラスに属します。 

より具体的に言えば、各オブジェクトはラベルと子オブジェクトのシーケンスによって定義され、子の順序が保持されたルート付き有向グラフが部分構造の等価性の下で同型である場合、2 つのオブジェクトは同一です。 

この難しさは、参照が循環を形成する可能性があるという事実から生じます。 これは、構造がツリーではないことを意味するため、依存関係のサイクルを何らかの方法で断ち切らない限り、サブツリーの単純な再帰比較は終了しません。 

入力サイズは最大 100,000 オブジェクトで、各オブジェクトには最大 10 個の参照があります。 これにより、オブジェクトのすべてのペアを構造的に比較するアプローチは即座に除外されます。 ペアごとの比較アプローチは O(n²) ですが、これは最悪の場合でも約 10¹⁰ の比較となり、実現可能な限界をはるかに超えています。 部分構造ハッシュを繰り返し再計算するオブジェクトごとの単純な再帰ハッシュであっても、共有サブグラフの走査が繰り返されるため、爆発する可能性があります。 

サイクルが存在する場合、微妙なエッジケースが発生します。 たとえば、オブジェクト A が B を参照し、B が A を参照する場合があります。単純な DFS ハッシュ計算は無限に再帰するか、グローバルな調整なしでは正しく設計するのが難しいアドホックなメモ化を必要とします。 

もう 1 つの特殊なケースは、異なるインデックスで現れる複数の同一の部分構造です。 構造的に同一であっても、同じクラスを受け取る必要があり、この等価性は、異なる走査順序で発見された場合でも一貫していなければなりません。 

## アプローチ

 強引なアイデアは、各オブジェクトの再帰的な「シリアル化」を定義することです。つまり、オブジェクトをそのスカラー値とシリアル化された子のリストで構成されるタプルとして表し、これらのタプルが等しいかどうかを比較します。 これをボトムアップで計算すると、各構造をハッシュしてから、同一のハッシュをグループ化できます。 

ただし、このアプローチはサイクルが存在すると失敗します。 依存関係によって DAG が形成されることが保証されていないため、自然なボトムアップ順序は存在しません。 ハッシュを再帰的に計算しようとすると、無限再帰または再計算の繰り返しが発生します。 メモ化を導入したとしても、A のハッシュが B に依存し、その逆も同様であり、どちらも独立して確定できないという循環依存性の問題に依然として直面します。 

重要な観察は、実際には構造評価中にサイクルを解決する必要がないということです。 すべてのノードにわたる一貫した等価関係のみが必要です。 これはまさにグラフ分割改良問題です。スカラー値と隣接する識別子の構造によって順序付けされたマルチセットが一致する場合に限り、2 つのノードが同じ識別子を共有するように、各ノードに安定した識別子を割り当てたいと考えています。 

これは、反復的な安定化プロセスを示唆しています。 まず、スカラー値のみに基づいて、すべてのノードに初期ラベルを与えます。 次に、ノードのスカラー値とその参照オブジェクトの現在のラベルのシーケンスによって形成されるタプルを考慮して、ラベルを繰り返し調整します。 各反復では、これらのタプルが新しい一意の識別子に圧縮されます。 ラベルは前のラベルにのみ依存するため、再帰ではなく反復するため、サイクルは問題を引き起こしません。

これは本質的に、グラフのラベル付け関数に対する固定小数点の計算です。 グラフには最大 100,000 個のノードがあり、各ノードには最大 10 個のエッジがあるため、各リファインメント ステップの入力サイズは線形です。 実際には、各反復が同値クラスを厳密に調整または安定化し、状態空間がノードの数によって制限されるため、必要な反復の数は少なくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰ハッシュ | O(n² + 再帰オーバーヘッド) | O(n) | 遅すぎる/サイクルが原因で不正確 |
 | ラベルの反復改良 | O(k · n log n) | O(n) | 承認済み |

 ここで、k は安定化するまでのリファインメント ラウンドの数で、通常は小さいです。 

## アルゴリズムのチュートリアル

 各オブジェクトを有向グラフのノードとして扱い、エッジは順序を保持します。 各ノードは、出力エッジの値とリストを保持します。 

1. 各ノードに、そのスカラー値に等しい初期ラベルを割り当てます。 これにより、同一の値のみが等しいとみなされる、大まかなグループ化が行われます。 
2. 各ノードに対して、そのスカラー値とその参照ノードの現在のラベルで構成される署名を順番に構築します。 この署名は、現在の等価近似のもとでのオブジェクトの現在の「ビュー」を表します。 
3. これらの署名をソートまたはハッシュして、新しいコンパクトな識別子を割り当てます。 同一の署名を持つノードには、同じ新しいラベルが付けられます。 このステップは本質的に、構造情報を同値クラスに圧縮することです。 
4. 反復間でラベルの変更が停止するまで、更新されたラベルを使用して署名の構築を繰り返します。 ラベルが変更されない場合、構造的等価性が安定する固定点に到達しています。 
5. 各ノードの最終ラベルをクラス識別子として出力します。 

再帰ではなく反復に依存する理由は、サイクルによって明確に定義された評価順序が妨げられるためです。 反復により制約がグローバルに伝播され、一貫性が達成されるまで情報がサイクルを循環できるようになります。 

### なぜ効果があるのか

 重要な不変条件は、各反復後に 2 つのノードが同じラベルを共有する場合、それらのスカラー値が等しく、隣接するノードのラベルが前の反復での順序で一致することです。 これにより、ラベルの識別性がさらに高まるか、安定したままになることが保証されます。 ノードの数は有限であるため、リファインメント プロセスを無限に続けることはできず、最終的にはそれ以上のリファインメントが不可能になる点に達します。 その時点で、ラベルの等価性は構造的等価性と正確に一致します。これは、構造的な違いがあると、反復中に異なるシグネチャが生成されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    val = [0] * n
    adj = [[] for _ in range(n)]

    for i in range(n):
        parts = list(map(int, input().split()))
        val[i] = parts[0]
        m = parts[1]
        adj[i] = [x - 1 for x in parts[2:]]

    # initial labels based on scalar value
    label = val[:]

    while True:
        sig_map = {}
        new_label = [0] * n
        cur_id = 1

        for i in range(n):
            sig = (label[i], tuple(label[v] for v in adj[i]))
            if sig not in sig_map:
                sig_map[sig] = cur_id
                cur_id += 1
            new_label[i] = sig_map[sig]

        if new_label == label:
            break
        label = new_label

    print(*label)

if __name__ == "__main__":
    solve()
```この実装では、構造的同一性を近似するラベル配列が維持されます。 各反復では、現在のラベルと隣接ラベルの順序付きリストで構成されるタプル署名が構築されます。 Python タプルは、構造状態を一意に識別するための辞書キーとして直接使用されます。 

停止条件は、反復全体にわたるラベルの安定性をチェックします。 これにより、それ以上の精製が不可能になることが保証され、すべての識別可能な構造が分離されたことになります。 

微妙な点の 1 つは、DFS や再帰をまったく試みていないことです。 すべての依存関係は反復ごとに同時に解決されるため、循環グラフでの無限ループが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k · n log n) | 各反復ではすべてのノードが処理され、署名がハッシュ/ソートされます。 k は安定化ラウンドの数 |
 | スペース | O(n) | 隣接リストと現在のラベルを保存します。 

n が最大 100,000、ノードあたりの m が最大 10 であるとすると、実際には各反復は線形になります。 反復回数は、収束前の個別の洗練レベルの数によって制限されますが、同値クラスが急速に分割されるため、このレベルは小さくなります。 

これは、時間とメモリの制限内に快適に収まります。

 ## 特殊なケース

 各反復では、前のステップですでに定義されているように隣接ラベルを扱うため、ノード間の直接サイクルは自然に処理されます。 2 ノードの相互参照の場合、両方のノードが同一で開始されるため、同一の署名が永久に保持され、同じクラスが正しく割り当てられます。 

自己参照ノードも同様に動作します。 それ自体を指すノードは、自身の近隣リストに現在のラベルを含む署名を生成します。 すべての反復で両方のノードが等しいため、固定小数点はすぐに安定します。 

同一の参照パターンを持つ同一のオブジェクトの大規模なセットは、それらのシグネチャがすべての改良段階で同一のままであり、不必要な分割を防ぐため、1 回または 2 回の反復で単一のクラスにまとめられます。
