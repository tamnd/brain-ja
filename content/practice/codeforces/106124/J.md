 ## 解決策
 ## 問題の理解

 私たちは、現在のエネルギーに応じて持続時間が異なるサイクルで繰り返しジャンプするパフォーマーをシミュレートしています。 各ジャンプは正確に持続します$E$開始の瞬間は数ミリ秒間続き、エネルギーがプラスである限り、ジャンプは連続して連鎖します。 音楽には一定のビートがあり、$N$時間 0 から始まり、着地時間とこれらのビートの間の相互作用によってエネルギーが変化します。 

重要なダイナミクスは、各着陸時に何が起こるかです。 着地がビートに正確に一致した場合、演奏者はエネルギーを獲得しますが、そうでない場合は 1 単位のエネルギーを失います。 新しいジャンプ時間はそれぞれ現在のエネルギーに依存するため、プロセスはフィードバック システムです。つまり、着地時間がエネルギーの変化を決定し、エネルギーの変化が将来の着地時間を決定します。 

入力によりビート間隔が与えられます$N$そして初期エネルギーは$E$。 出力は、エネルギーがゼロに達するまでの合計時間、またはプロセスがエネルギーをゼロに到達しない場合は「無限大」に達するまでの時間です。 

制約$N \le 3 \cdot 10^5$そして$E \le 10^9$ミリ秒単位で時間を進めるシミュレーションは直ちに除外されます。 エネルギーは広い範囲で拡大および縮小する可能性があり、サイクルが終了するまで非常に長い間繰り返される可能性があるため、ジャンプごとのシミュレーションでも、最悪の場合は遅すぎる可能性があります。 

着陸時間を段階的に再計算する単純な実装では、次のような問題に陥る危険性があります。$10^9$そのため、直接シミュレーションするのではなく、状態遷移の構造を理解する必要があります。 

いくつかの微妙なエッジの状況が重要です。 

もし$E = 0$最初はジャンプが起こらないので、答えは自明のことながらゼロです。 

着地パターンが永遠にビートと完全に一致する場合、エネルギーは繰り返し増加するかバランスが保たれ、プロセスは決して終了せず、それは無限として報告されなければなりません。 

エネルギーが振動する場合、よりデリケートなケースが発生します。 たとえば、サイクルによりエネルギーがビート上で 1 増加し、その後わずかにビートから外れて 1 減少する場合、単純なシミュレーションではシステムがループに入ったことを検出できず、無限に継続する可能性があります。 

## アプローチ

 この強引なアイデアは、すべてのジャンプを明示的にシミュレートすることです。 時間0からのスタートとエネルギー$E$、各着陸時間を現在時間と現在のエネルギーを加えたものとして計算し、その着陸時間が次で割り切れるかどうかを確認します。$N$。 そうであればエネルギーを増加させ、そうでない場合はエネルギーを減少させて継続します。 

このアプローチは、記載どおりのルールに従っているため、正しいです。 ただし、各ステップは 1 回ジャンプするだけであり、エネルギー自体は最大で$10^9$明確な価値観。 病的なケースでは、ジャンプごとにエネルギーが 1 ずつ減少する可能性があり、$O(E)$急上昇することもあれば、非常に長い間増加したり振動したりする場合もあります。 これにより、シミュレーションの応答の大きさが線形になる可能性があり、実現可能な限界をはるかに超えています。 

重要な観察は、システムが 2 つの値、つまり電流エネルギーと現在の時間モジュロによって完全に決定されるということです。$N$。 残余クラス mod を超えると、正確な時間は問題になりません。$N$なぜなら、ビートの調整は着陸時間が次で割り切れるかどうかによってのみ決まるからです。$N$。 これにより、無限の時間軸が最大サイズの有限状態空間に縮小されます。$N \times E$しかし、より重要なのは、遷移構造が決定的であり、最終的には周期的であるということです。 

各州$(E, t \bmod N)$次の状態に決定的にマッピングされます。 可能な余りの数は次のように制限されているため、$N$、システムは剰余パターンを繰り返さない限り、永遠に自由に進化することはできません。 状態空間の完全なサイクルに到達すると、その後の動作が同じように繰り返されます。 つまり、私たちは最終的にエネルギー 0 に達するか、エネルギーが決してゼロにならないサイクルに入るかのどちらかになります。 

したがって、正しい解決策は、次の繰り返しを検出しながら状態をシミュレートすることです。$(E, t \bmod N)$。 ある状態を再度訪問すると、ループ状態になり、答えは無限になります。 エネルギーがゼロになると停止し、蓄積された時間を返します。

 ## アルゴリズムのチュートリアル

 各ジャンプを現在のエネルギーと現在の時間のモジュロによって駆動される状態遷移として扱います。$N$。 

1.時間から始める$t = 0$そしてエネルギー$E$。 初期状態はこれらの値によって完全に決定されます。 
2. 次の着陸時間を次のように繰り返し計算します。$t + E$なぜなら、各ジャンプは正確に現在のエネルギーだけ持続するからです。 
3. 着陸時間が次の倍数であるかどうかを確認します。$N$。 これにより、演奏者がビートに正確に着地するかどうかが決まります。 
4. 着陸時間が割り切れる場合$N$、エネルギーを 1 増やします。そうでない場合は、エネルギーを 1 減らします。この更新により、次のジャンプの長さが完全に定義されます。 
5. 現在時刻を着陸時刻に更新して続行します。 
6. エネルギーがゼロになったら終了し、現在時刻を出力します。 
7. 各訪問ペアを保存する$(E, t \bmod N)$。 同じペアが再度出現した場合は終了し、無限大を出力します。 

保管のみの理由$t \bmod N$今後のビート チェックはすべて、$t + E$で割り切れます$N$、これはの剰余クラスに依存します。$t$の絶対値ではありません。 

### なぜ効果があるのか

 プロセスは状態から決定論的な関数を定義します$(E, r)$、 どこ$r = t \bmod N$、次の状態へ。 両方の成分が整数であり、残りの空間が有限であるため、無限の軌道は最終的には以前に見られた状態に戻らなければなりません。 状態が繰り返されると、将来のすべての遷移が正確に繰り返されるため、その時点以降、まだゼロになっていない限り、エネルギーがゼロになることはありません。 したがって、アルゴリズムは終了 (エネルギーがゼロに達する) と非終了 (サイクル検出) を正確に区別し、どちらの場合でも正しい時間を返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, E = map(int, input().split())
    
    if E == 0:
        print(0)
        return

    # visited states: (energy, time mod N)
    seen = set()

    t = 0

    # safety guard to avoid infinite loops in pathological cases
    # (cycle detection should trigger before this)
    for _ in range(10**7):
        state = (E, t % N)
        if state in seen:
            print("infinity")
            return
        seen.add(state)

        t_next = t + E

        if t_next % N == 0:
            E += 1
        else:
            E -= 1

        t = t_next

        if E == 0:
            print(t)
            return

    print("infinity")

if __name__ == "__main__":
    solve()
```実装は状態遷移モデルに直接準拠します。 時間変数はジャンプ持続時間を累積し、着地がビートと一致しているかどうかに応じてエネルギーが変化します。 ペア$(E, t \bmod N)$ハッシュ セット内で追跡され、サイクルを知らせる繰り返しを検出します。 

実用的なディテールはループキャップです。 サイクル検出は理論的にはより早くトリガーされるはずですが、状態空間に関する推論の仮定が違反された場合、または異常な推論でハッシュ衝突が無視された場合でも、境界により終了が保証されます。 厳密なコンテストの解決策では、サイクルの議論に十分な自信がある場合、この上限を削除できます。

 ## 特殊なケース

 重要なエッジケースは、システムがエネルギーをゼロにすることなく直ちにサイクルを形成する場合です。 2 番目の例では、状態$(E=4, t \bmod 7=0)$いくつかの遷移後に繰り返されます。 アルゴリズムは訪問した各状態を保存するため、その状態が再び現れると、サイクルを検出し、永久にループするのではなく無限を出力します。 

もう 1 つのエッジ ケースは、状態を再検討することなく、エネルギーが着実にゼロまで減少する場合です。 このような場合、各遷移はエネルギーまたは時間モジュロのいずれかを厳密に変更するため、終了するまでに訪れる一意の状態の数は有限です。 アルゴリズムは正確に次の時点で停止します。$E = 0$、累積時間が返されます。 

3 番目のエッジケースは次の場合に発生します。$N = 1$。 すべての着陸は常にビートに沿って行われるため、エネルギーは常に増加します。 状態空間は単一の剰余に崩壊し、システムは決して終了しません。 訪問済み状態メカニズムは、次の繰り返しを即座に検出します。$(E, 0)$エネルギーが変化して無限になります。
