 ## 問題の理解

 入力は、長方形グリッドの三角形の「ピラミッド型」サブセットを表します。 各行は、固定幅のサイズのグリッド内で中央に配置されます。$2N-1$、行$i$正確に含まれています$2i-1$対称の三角形を形成する使用可能なセル。 この三角形の外側には、`#`セルは構造体に属さないため、出力では変更されないままにする必要があります。 

ピラミッドセル内のいくつかの位置には特別なマーカーが含まれています`C`、「ケーシングストーン」を表し、残りの有効なセルは空です`.`、それでも2人の考古学者のうちの1人に割り当てられなければなりません。 タスクは、すべてのピラミッド セルに色を付けることです。`A`または`B`以下の条件が同時に成立するようにする。 

ピラミッド セルのみを考慮して、両方の領域を 4 方向の隣接の下で接続する必要があります。 すべてのピラミッド セルは、2 つの領域のいずれかに正確に属している必要があります。 最後に、その数は、`C`に割り当てられたセル`A`の数と等しくなければなりません`C`に割り当てられたセル`B`。 

グリッドのサイズは最大です$N \le 300$, したがって、錐体細胞の総数は次のとおりです。$N^2$、およそ最大4万5千。 これにより、サブセットに対する指数関数的な検索が除外されます。 二次アプローチであっても、線形または線形に近いグラフの走査を中心に注意深く構成する必要があります。 

微妙な問題は、この制約がセルの合計のバランスをとることではなく、セルの数のみのバランスをとることであることです。`C`細胞。 空のセルは、接続を維持するために使用できる柔軟なパディングです。 見た目以上に重要なもう 1 つの制約は、結果として得られる両方の領域が、割り当てられたラベル内の隣接性の点で接続されているだけでなく、元のグリッド内で接続されたままでなければならないことです。 

単純なアプローチでは、いくつかの失敗モードが発生します。 

よくある間違いの 1 つは、貪欲に半分を割り当てることです。`C`行ごとにスキャンしてセルをスキャンします。 これにより、切断された領域が容易に生成されます。 たとえば、すべてが存在する小さなピラミッドでは、`C`セルは狭い垂直チェーン内にあり、残りのセルが複数のコンポーネントに分割される可能性があるため、最初の半分を取ると接続が切断されます。 

もう 1 つの問題は、`C`三角形を通る対角線などの幾何学的なカットを選択することで、セルを強制できます。 簡単な反例は次のような場合です`C`細胞はジグザグパターンで散在しています。 まっすぐにカットすると不均一に分離されます。 

3 番目の微妙な問題は、両側の接続を同時に無視することです。 片側が接続されている場合でも、スパニング ツリーから単一のエッジを削除するなど、グローバル接続を維持する構造によって分割が引き起こされない限り、補完部分は複数のコンポーネントに分割される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各ピラミッドセルをグラフ内のノードとして扱い、それを次のノードに割り当てようとします。`A`または`B`両方の誘導サブグラフの接続性と等価性という 2 つの制約を維持しながらバックトラッキングを行う`C`カウントします。 各ステップで、セルのラベルを決定し、両方の部分構造が潜在的に接続されたままであるかどうかを確認します。 部分的な割り当てでの接続チェックは高価であり、分岐係数はセル数において事実上指数関数的であるため、これはすぐに手に負えなくなります。$2^{O(N^2)}$州。 

重要な構造の簡素化は、接続性が機械的に保証できるグラフ分割問題として問題を再構成することで実現します。 構築中に接続性を制約として維持するのではなく、構築によって強制します。スパニング ツリーから 1 つのエッジを削除して接続されたグラフを分割すると、結果として得られる両方の部分が自動的に接続されます。 

これにより、問題は別の質問に移ります。 ピラミッドグラフのスパニングツリーを構築し、その数を計算します。`C`ノードは各サブツリー内にあり、削除するとツリーが等しい 2 つの部分に分割されるツリー エッジを見つけようとします。`C`カウントします。 空のセルはバランスをとるためには重要ではありませんが、それでも接続構造の一部です。 

残りの重要な主張は、元のグラフに有効なパーティションが存在する場合、そのようなバランスの取れたカットをツリー エッジとして露出するグラフのスパニング ツリーが存在するということです。 グリッド状の接続グラフでは、DFS スパニング ツリーを構築すると、接続されたパーティションをサブツリー境界に揃えることができる十分な構造が維持されるため、コンテスト設定でこの削減が安全になります。

 ## アルゴリズムのチュートリアル

 私たちはあらゆる錐体細胞を治療します（除く）`#`）グラフ内のノードとして、直交する隣接する有効なセルの間にエッジがあります。 

1. まず、合計数を計算します。`C`ピラミッド内の細胞。 この合計が奇数の場合、均等に分割することはできないため、すぐに出力します。`impossible`。 これにより、不必要なグラフ作業が回避されます。 
2. 隣接するセルがピラミッド内にある場合は、各セルをその上下左右の隣接セルに接続することにより、すべての有効なピラミッド セルの隣接リストを作成します。 これにより、接続されたグラフが得られます。 
3. 任意の有効な開始セルから DFS を実行して、グラフのスパニング ツリーを構築します。 その際、各ノードの親を記録し、ツリーの子を保存します。 
4. このツリーの事後走査中に、各ノードの数を計算します。`C`そのサブツリー内のセル。 これは、子からの寄与を合計し、現在のノードが`C`。 
5. サブツリーの合計を計算するときに、ノードからその子までの各ツリー エッジをチェックします。 子のサブツリーにすべてのサブツリーがちょうど半分含まれている場合`C`セルを分割し、そのエッジをカットして有効なパーティションを定義します。 
6. そのような子が見つかったら、そのサブツリー内のすべてのノードを`A`ツリーのエッジに制限された DFS を使用し、残りのすべてのノードを`B`。 
7. グリッドを保存して出力します。`#`セルを作成し、各ピラミッド セルを割り当てられたラベルで置き換えます。 

この構築が機能する主な理由は、ツリー エッジを削除するとスパニング ツリーが 2 つの接続されたコンポーネントに分割され、ツリー エッジが元の隣接グラフのサブセットであるため、これらのコンポーネントは元のグリッド内で接続されたままになるためです。 サブツリー合計条件は、次のバランスを保証します。`C`細胞。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

N = int(input().strip())
grid = [list(input().strip()) for _ in range(N)]

# Collect valid nodes
nodes = []
id_of = [[-1] * (2 * N - 1) for _ in range(N)]

for i in range(N):
    for j in range(2 * N - 1):
        if grid[i][j] != '#':
            id_of[i][j] = len(nodes)
            nodes.append((i, j))

n = len(nodes)

# Build graph
dirs = [(1,0),(-1,0),(0,1),(0,-1)]
g = [[] for _ in range(n)]

for i, (r, c) in enumerate(nodes):
    for dr, dc in dirs:
        nr, nc = r + dr, c + dc
        if 0 <= nr < N and 0 <= nc < 2 * N - 1:
            if id_of[nr][nc] != -1:
                g[i].append(id_of[nr][nc])

# Count C
totalC = sum(1 for r, c in nodes if grid[r][c] == 'C')
if totalC % 2:
    print("impossible")
    sys.exit()

half = totalC // 2

# Build DFS tree
parent = [-1] * n
tree = [[] for _ in range(n)]
root = 0

stack = [root]
parent[root] = root

order = []

while stack:
    v = stack.pop()
    order.append(v)
    for to in g[v]:
        if parent[to] == -1:
            parent[to] = v
            tree[v].append(to)
            stack.append(to)

# subtree DP
sub = [0] * n

ans_edge = None

for v in reversed(order):
    val = 1 if grid[nodes[v][0]][nodes[v][1]] == 'C' else 0
    for to in tree[v]:
        val += sub[to]
    sub[v] = val
    for to in tree[v]:
        if sub[to] == half:
            ans_edge = (v, to)

if ans_edge is None:
    print("impossible")
    sys.exit()

# assign colors
color = ['?'] * n

v, cut = ans_edge

def dfs_assign(u, c):
    stack = [u]
    color[u] = c
    while stack:
        x = stack.pop()
        for y in tree[x]:
            if color[y] == '?':
                color[y] = c
                stack.append(y)

dfs_assign(cut, 'A')
dfs_assign(v, 'B')

# output
out = [row[:] for row in grid]
for i, (r, c) in enumerate(nodes):
    if out[r][c] != '#':
        out[r][c] = color[i]

for row in out:
    print("".join(row))
```実装は、使用可能なすべてのピラミッド セルをグラフ インデックスに圧縮することから始まり、これにより隣接関係の処理が簡素化されます。 DFS ツリーは、再帰の深さの問題を回避するために反復的に構築されます。 サブツリーのサイズは、親の前に子が処理されるように、逆 DFS 順序で計算されます。 

実装の重要な詳細は、DFS ツリーの親子エッジに沿ってのみ切り取ることです。 これにより、結果として得られる両方の領域がツリー構造内で接続されることが保証されます。これは、有効な隣接関係ではないエッジを追加しないため、元のグリッド内の接続性を直接意味します。 

## 実用的な例

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、`C`セルは 0 または 1 です。 どちらの場合も、接続された 2 つの空でない領域は両方とも同じカウントを受け取ることができないため、アルゴリズムは奇数の合計または些細な不均衡については不可能であると直ちに宣言します。 

別のケースは、ピラミッドが完全に満たされている場合です。`C`。 ここで、アルゴリズムは同じように動作します。依然として DFS ツリーを構築し、ノードのちょうど半分を含むサブツリーを検索します。 構造のバランスが十分に取れていれば、カットが存在します。 それ以外の場合は、失敗が正しく報告されます。 

最後の微妙なケースは、ピラミッド グラフが実質的に細いチェーンである場合です。 このような場合、DFS ツリーもチェーンであり、サブツリーの合計はそのチェーンに沿ったプレフィックスの合計に対応します。 このアルゴリズムは、線形シーケンス内の分割点を見つけることに帰着します。これは、特別なケースを必要とせずに、同じサブツリー計算によって自然に処理されます。
