 ## 解決策
 ## 問題の理解

 位置に隠された順列が与えられています$1 \ldots N$。 この順列は、長さのバイナリ文字列をどのように定義するかを定義します。$N$は変換されます。各ステップは単純に順列に従ってビットを並べ替えます。 順列を繰り返し適用すると、最終的には固定バイナリ文字列が元に戻ります。これは、順列が互いに素なサイクルに分解され、各サイクルがビットをローテーションするだけであるためです。 

バイナリ文字列ごとに$x \in \{0,1\}^N$、文字列を元の状態に戻すために必要な置換アプリケーションの最小数としてその期間を定義します。 順列は与えられていません。 代わりに、複数の期間値のセットが与えられ、各期間に対して、$p$、正確にそのピリオドを持つバイナリ文字列がいくつあるか。 

タスクは、まさにこの期間の分布を生成する可能性のある順列を再構築するか、そのような順列が存在しないことを報告することです。 

という点では制約は小さい$N$、 と$N \le 100$ただし、文字列の数は天文学的に大きくなる可能性があります。$2^{100}$。 これは、ソリューションが文字列をシミュレートしたり状態を列挙したりできないことを直ちに示します。 すべてをサイクル構造の算術に還元する必要があります。 

重要な構造上の事実は、順列によってバイナリ文字列の周期が完全に決定され、それらの周期はサイクル分解のみに依存するということです。 したがって、実際の問題は、指定された集計カウントと一致するサイクル構造を再構築することです。 

期間が周期の長さに直接対応すると仮定すると、微妙な失敗例が現れます。 これは誤りです。バイナリ文字列は同時に複数のサイクルで周期的になる可能性があり、その周期はサイクル寄与の最小公倍数であるからです。 サイクル間の相互作用を無視したアプローチでは、カウントが誤ります。 

たとえば、置換に長さ 2 と 3 のサイクルがある場合、両方のサイクルで一定の文字列の周期は 1 ですが、ビットを異なるように混合すると、アライメントに応じて周期 2、3、または 6 が生成されます。 したがって、「1 サイクルは 1 周期クラスに等しい」という素朴な推論はすぐに破綻します。 

## アプローチ

 強引なアイデアは、次のすべての順列を列挙することです。$N$、それらの周期分解を計算し、各順列についてすべてのバイナリ文字列をシミュレートして周期を計算します。 これは概念的には簡単です。文字列ごとに、結果が返されるまで順列を繰り返し適用します。 ただし、$2^N$文字列まで$N!$順列が異なるため、これは完全に不可能になります。 単一の順列であっても、すべての文字列の周期の計算は指数関数的になります。 

重要な点は、個々の文字列を確認する必要がないということです。 順列は互いに素なサイクルに分割され、複数のサイクルが関与する場合に最小公倍数を取ることを除いて、各サイクルは独立して動作します。 バイナリ文字列の周期は、各サイクルの周期性、具体的には各サイクル内でビットが回転しながらどのように繰り返されるかによって決まります。 

長さのサイクルの内側$L$、バイナリ文字列の制限は、ピリオドで分割される循環文字列のように動作します。$L$。 より正確には、各サイクルは回転によって支配される除数構造に寄与し、グローバル周期は、そのサイクルによって引き起こされるローカル周期のサイクルにわたる最小公倍数になります。 

これにより、問題は、与えられた期間のヒストグラムと一致する算術演算を行うサイクル長のマルチセットを構築することになります。 文字列について推論する代わりに、サイクルによって引き起こされる約数と最小公倍数について推論します。 

重要な単純化は、各サイクルが独立して乗算構造に寄与し、特定の周期を持つ文字列の総数がサイクル構造上の包含/除外を介して表現できることです。 これにより、問題は、約数の相互作用が指定されたカウントと一致する整数のマルチセットを再構築することに変わり、候補期間の約数に対するメビウス反転によって処理できます。 

基本的にサイクル構造を推測し、サイクル長の約数に関する算術恒等式を使用して一貫性を検証します。

 ## アルゴリズムのチュートリアル

 まず入力を再解釈します。 私たちには役割が与えられている$F(p)$、ピリオドが正確に一致するバイナリ文字列の数$p$。 これから累積関数を導き出します$G(p)$、ピリオドで区切られる文字列の数$p$。 これはすべてを合計することで得られます$F(d)$約数を超える$d \mid p$。 

この累積形式は、「期間が分割される」ため、より自然です。$p$」は順列を適用して固定することに相当します。$p$回。 

次に、文字列が次のように固定されるという事実を利用します。$f^p$長さのサイクルごとに正確に$L$以下で尊重されています$p$回転は、間の gcd 構造のみに依存します。$p$そして$L$。 一定の長さのサイクルの場合$L$、貢献します$2^{\gcd(L,p)}$固定割り当て。 サイクルを乗算すると、固定カウントの合計が得られます。 

それで$G(p)$はサイクルにわたる積に等しい：$$G(p) = \prod_{cycles\;L} 2^{\gcd(L,p)} = 2^{\sum \gcd(L,p)}$$2 を底とする対数を計算すると、乗算が加算に変換されます。$$\log_2 G(p) = \sum \gcd(L,p)$$ここで問題は、この gcd-sum の同一性がすべてのサイクル長に対して保持されるようなサイクル長のマルチセットを見つけることです。$p$。 

これを除数変換逆変換を使用して解決します。 

## アルゴリズムのチュートリアル

 1. 指定された正確な期間カウントを変換します。$F(p)$累積カウントに$G(p)$約数を合計することによって。 これにより、置換べき乗の下でデータが固定小数点カウントに揃えられます。 
2. すべての 2 を底とする対数を計算します。$G(p)$。 構造上、値は 2 のべき乗であるため、これにより、次のことを表す整数が得られます。$\sum \gcd(L,p)$。 値が 2 の累乗でない場合、順列は存在しません。 
3. アレイをセットアップする$A(p) = \log_2 G(p)$。 これは、gcd 相互作用によるサイクル長の寄与をエンコードします。 
4. 除数に対するメビウス反転を使用して、正確なサイクル長に対応する寄与を抽出します。 関数を計算します$C(L)$それは長さのサイクル数を表します$L$gcd 寄与が再構築されるように存在する必要があります。$A(p)$。 
5. すべてのことを確認します。$C(L)$負でない整数およびすべての合計です$L \cdot C(L)$等しい$N$。 これにより、有効な置換構造が保証されます。 
6. サイクルを連結して順列を構築します: 長さごとに$L$、 作成する$C(L)$サイズのばらばらのサイクル$L$ラベルの昇順です。 

### なぜ効果があるのか

 核となる不変条件は、置換べき乗に基づく固定小数点カウントが gcd 演算を通じてサイクル構造を一意に決定することです。 すべてのサイクルが相加的に貢献します$\log_2 G(p)$経由$\gcd(L,p)$、メビウス反転は、他の長さからの干渉なしに各サイクル長の寄与を分離します。 gcd は除数格子に対して乗算的であるため、この分離は正確であり、サイクル多重度の完全な回復が可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, K = map(int, input().split())
    p = list(map(int, input().split()))
    m = list(map(int, input().split()))

    F = {}
    for pi, mi in zip(p, m):
        F[pi] = mi

    # build divisors map up to max p
    maxp = max(p)

    def get_divs(x):
        divs = []
        i = 1
        while i * i <= x:
            if x % i == 0:
                divs.append(i)
                if i * i != x:
                    divs.append(x // i)
            i += 1
        return divs

    G = {}
    for pi in p:
        s = 0
        for d in get_divs(pi):
            if d in F:
                s += F[d]
        G[pi] = s

    # check powers of two
    A = {}
    for pi in p:
        v = G[pi]
        if v <= 0 or (v & (v - 1)) != 0:
            print("impossible")
            return
        A[pi] = v.bit_length() - 1

    # transform by Möbius-like inversion on divisor poset
    C = {}

    for i in sorted(p, reverse=True):
        val = A[i]
        for j in p:
            if j < i and i % j == 0:
                val -= C.get(j, 0)
        C[i] = val
        if val < 0:
            print("impossible")
            return

    # build permutation
    res = list(range(1, N + 1))
    idx = 0
    for length in sorted(C):
        cnt = C[length]
        for _ in range(cnt):
            if idx + length > N:
                print("impossible")
                return
            cycle = res[idx:idx + length]
            for t in range(length):
                cycle[t] = cycle[(t + 1) % length]
            res[idx:idx + length] = cycle
            idx += length

    if idx != N:
        print("impossible")
        return

    print(*res)

if __name__ == "__main__":
    main()
```最初のステージでは、指定された期間カウントを除数にわたる累積固定カウントに集計します。 これが必要なのは、順列パワーの挙動が正確な最小期間ではなく、繰り返し適用される固定点の観点から自然に表現されるためです。 

サイクル寄与は固定小数点カウントで乗算されるため、対数ステップは非常に重要です。 値が 2 のべき乗でない場合、構造はサイクルごとの独立したバイナリ割り当てに対応できないため、インスタンスは不整合になります。 

反転ステップは、値を処理するときに、厳密な除数からのすべての寄与がすでに考慮されるように、大きいインデックスから下に向かって進みます。 これは、除数格子における古典的なメビウス反転を反映しています。 

最後に、並べ替えの構築では、指定された長さの互いに素なサイクルを単純にレイアウトします。 正確さは、サイクル数が固定されると、互いに素なサイクルをどのように配置しても同等の順列が得られるという事実に依存します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての質量が周期 1 に集中する場合です。この場合、すべての文字列が 1 つのアプリケーションで固定され、順列が恒等になることが強制されます。 すべての累積値が最小の 2 のべき乗であり、長さ 1 のサイクルのみが生成されるため、アルゴリズムはこれを検出します。 

もう 1 つの特殊なケースは、一貫性のない対数値です。 もしあれば$G(p)$が 2 の累乗ではない場合、反転ステップはすぐに失敗します。 これにより、乗算構造に違反する人為的に膨らんだカウントなど、独立したサイクル寄与に対応できない入力が正しく処理されます。 

3 番目のケースは、反転中に除数の一貫性が失敗する場合です。 より大きな除数から寄与を差し引いた後、候補サイクル長が負の多重度を暗示している場合、それは入力分布での過大なカウントを示しており、アルゴリズムはそれを正しく拒否します。
