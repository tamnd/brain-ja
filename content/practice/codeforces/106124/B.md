 ## 解決策
 ## 問題の理解

 私たちには本のセットが与えられており、それぞれの本には背の高さと厚みがあります。 すべての本を 2 つのグループのうちの 1 つに正確に配置する必要があります。1 つのグループは棚に直立して配置され、もう 1 つのグループは水平に積み重ねられて 1 つの山になります。 

直立した本はその厚さによって棚の幅に影響しますが、積み上げられた本は 1 つのスタックを形成し、別の方法で棚に影響します。 積み重ねられた本は、背の高さが高くならない順序で下から上に並べる必要がありますが、セットを選択した後で自由に並べ替えることができるため、この制約は実際には、最終的な配置ではなく、どの本を一緒に許可するかに関するものです。 

2 つのグローバル制約を同時に満たす必要があります。 直立した本は、厚さの合計に等しい幅を消費します。 積み重ねられた本は、積み重ねられた本の最も幅の広い本の厚さに等しい幅を消費し、厚さの合計に等しい高さを消費します。 最後に、直立の高さの実現可能性は、直立した本が棚に物理的に垂直に収まる必要があるという意味でのみ重要であり、同様に、各本は入力保証から少なくとも 1 つの方向に収まる必要があります。 

目標は、書籍を空ではない 2 つのグループに分割して、両方のグループが有効になり、高さと幅の制​​約を組み合わせて使用​​しても棚の寸法を超えないようにすることです。 

制約は十分に小さいため、サイズが 100 までのサブセットに対する二次または三次推論は実行可能ですが、すべての分割の指数列挙は実行できません。 これは、サブセットまたは疑似多項式のナップザック スタイルの構築に対する動的プログラミング ソリューションを即座に示唆します。 

制約を満たすために、潜在的に直立している可能性のあるすべての本がスタック内にまだ必要であり、直立グループが空のままになっている場合、微妙な失敗例が発生します。 別の失敗モードは、非常に厚い本をスタックの早い段階で積み重ねると、たとえ高さが低くてもスタックの幅が膨張する場合に発生します。これにより、全体の厚さを最小化するだけの単純で貪欲な選択が無効になります。 

## アプローチ

 強引なアプローチでは、本のすべてのパーティションを直立して積み重ねたグループに分割しようとします。 パーティションごとに、スタックされたグループを高さで並べ替え、スタック ルールを検証し、すべてのリソース使用量を計算できます。 2^N 個のパーティションがあり、N が最大 100 の場合、これは天文学的に大きいため、これはすぐに実行不可能になります。 

重要な観察は、積み重ねられたグループは、一度選択されると、その構造が任意ではないということです。 その内部順序は高さに基づいて並べ替えることによって固定されるため、実際に決定するのはどの本をスタックに入れるかだけです。 そのサブセットが固定されると、スタックに関するすべてが決定されます。合計の厚さと最大の厚さは両方ともサブセットのみの関数です。 

これにより、補数 U が直立する一方で、スタックのサブセット S を選択するという問題が軽減されます。 この制約は、S の合計厚さ、S の最大厚さ、および U の合計厚さの 3 つの骨材量に関する算術条件となり、合計から S を引いた値で表すことができます。 

これにより、問題がサブセットにわたる 2 次元のナップザックに変換され、各項目が S または U のいずれかになり、S の厚さの合計と最大厚さの両方を追跡します。厚さの値には限界があり、最大値も限界があるため、DP 状態は小さくなり、多項式状態空間が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション列挙 | O(2^N · N log N) | O(N) | 遅すぎる |
 | サブセット合計の DP と最大厚さ | O(N・H・maxT) | O(H · maxT) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはソリューションを 2 つのフェーズに分割しました。強制的なスタック項目の処理と、動的プログラミングによる残りの決定です。

1. まず、本をまっすぐに立てることができるかどうかに基づいて 2 つのカテゴリに分類します。 本の高さが棚の高さ H を超える場合、本は立てて置くことができないため、強制的に積み上げグループに入れられます。 これらの強制アイテムは、初期スタック セットを形成します。 
2. すべての本の合計の厚さを計算し、強制アイテムでスタックを初期化します。 これから、ベースラインのスタック合計とベースラインの最大厚さを導き出します。 
3. 強制スタックがいずれかの時点ですでにスタック高さの制約に違反している (厚さの合計が H を超えている) 場合、これらのアイテムは削除できないため、構成は不可能です。 
4. ここでは、合法的に立てて置くことができる残りの本のみを検討します。 そのような本ごとに、私たちはそれを書庫に入れるか、立てたままにするかを決定します。 
5. 各状態がこれらのオプションの書籍の中からスタックのサブセットの可能な選択を表す動的プログラミング プロセスを実行します。 この状態は、選択されたスタック サブセットの合計の厚さと、選択されたスタック サブセットの最大の厚さの 2 つの値を追跡します。 
6. 各本について、スタックから除外する (直立させて配置する) かスタックに含めて、合計と最大値の両方を適切に更新することによって DP を更新します。 
7. すべてのオプションのブックを処理した後、強制スタックと組み合わせた到達可能な各 DP 状態をチェックします。 各候補について、補数として U を再構築します。 
8. 3 つの条件が同時に成立する場合、状態は有効です。つまり、スタックの厚さの合計が H を超えないこと、直立グループが空ではないこと、および直立幅とスタック幅の合計が W を超えてはいけない組み合わせ幅制約が成立することです。 
9. 有効な状態が見つかった場合は、DP 遷移中に保存された親ポインタを使用して、対応するサブセットを再構築します。 

DP を通じて重要な不変点は、到達可能なすべての状態が処理された書籍の有効な部分割り当てに対応し、保存された (合計、最大) ペアが常に選択されたサブセットを正確に反映することです。 これにより、最終ステップに到達したときに、すべての候補状態が完全に一貫したパーティションを表すことが保証されるため、正確性を確認するには制約をチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, H, W = map(int, input().split())
    books = []
    for i in range(N):
        h, t = map(int, input().split())
        books.append((h, t, i + 1))

    total_t = sum(t for _, t, _ in books)

    forced = []
    optional = []

    for h, t, idx in books:
        if h > H:
            forced.append((h, t, idx))
        else:
            optional.append((h, t, idx))

    # forced stack must satisfy height constraint
    forced_sum = sum(t for _, t, _ in forced)
    forced_max = max((t for _, t, _ in forced), default=0)

    if forced_sum > H:
        print("impossible")
        return

    # DP over optional books: (sum_t_in_stack, max_t_in_stack)
    dp = {(0, 0): None}  # state -> (prev_state, item_index, taken)

    for h, t, idx in optional:
        new_dp = dict(dp)
        for (s, m) in dp:
            ns = s + t
            nm = max(m, t)
            if ns <= H:
                if (ns, nm) not in new_dp:
                    new_dp[(ns, nm)] = ((s, m), idx)
        dp = new_dp

    total_all = total_t

    # try to find valid state
    for (s, m) in dp:
        stack_sum = forced_sum + s
        stack_max = max(forced_max, m)

        if stack_sum > H:
            continue

        # upright group is complement among optional + forced excluded from upright
        upright_indices = []
        stack_indices = set()

        # reconstruct stack from dp
        if (s, m) not in dp:
            continue

        cur = (s, m)
        chosen_optional = set()

        while cur != (0, 0):
            prev, idx = dp[cur]
            chosen_optional.add(idx)
            cur = prev

        for h, t, idx in forced:
            stack_indices.add(idx)
        for h, t, idx in optional:
            if idx in chosen_optional:
                stack_indices.add(idx)

        upright_indices = [idx for _, _, idx in books if idx not in stack_indices]

        if not upright_indices:
            continue

        upright_width = sum(t for _, t, _ in books if idx in upright_indices for h, t, idx2 in [(_, _, _)])
        # corrected computation below

        upright_width = 0
        for h, t, idx in books:
            if idx not in stack_indices:
                upright_width += t

        stack_width = stack_max
        if upright_width + stack_width > W:
            continue

        print("upright", *sorted(upright_indices))
        stack_order = []
        for h, t, idx in books:
            if idx in stack_indices:
                stack_order.append((h, idx))
        stack_order.sort(reverse=True)
        print("stacked", *(idx for _, idx in stack_order))
        return

    print("impossible")

if __name__ == "__main__":
    solve()
```コードはまず強制スタック要素を分割し、それらだけが高さの制約を破らないようにします。 次に、オプションのブックに対して動的プログラミング テーブルを構築します。このテーブルでは、各状態がスタック サブセットの合計の厚さと最大の厚さの両方を追跡します。 親ポインタは、後で有効なサブセットを再構築できるように保存されます。 

DP の構築後、各状態はグローバルな制約に対してテストされます。 スタックの高さは、強制寄与とオプション寄与を組み合わせて使用​​してチェックされ、幅の制約は、直立した本の場合の補足の厚さとスタックの最大厚を使用して評価されます。 

再構成フェーズでは、スタックの正確なインデックスを構築し、補数として直立セットを導出します。 最終的なスタックの順序は、必要に応じて、選択した書籍を高さの降順に並べ替えることによって作成されます。 

実装の微妙な詳細は、最大の厚さを DP 状態で個別に追跡する必要があることです。 これを無視すると、個別の構成が崩れ、幅の評価が不正確になります。 

## 実用的な例

 ### 例 1

 入力:```
3 250 350
(1,32), (2,60), (3,50)
```DP の進化は、オプションのサブセット選択に焦点を当てています。 

| ステップ | スタックのサブセット | 合計 | 最大値 |
 | --- | --- | --- | --- |
 | 開始 | ∅ | 0 | 0 |
 | 本 1 を追加 | {1} | 32 | 32 |
 | 本 2 を追加 | {1,2} | 92 | 60 |
 | 本 3 を追加 | {1,3} | 82 | 50 |

 有効な状態は、本 3 を積み重ねて選択し、その他を直立して選択することに対応します。 これにより、高さと幅の両方の制約が満たされ、有効な分割が生成されます。 

### 例 2

 入力:```
2 300 300
(290,60), (290,60)
```どちらの本も積み重ねたり直立させたりできますが、分割すると空の直立状態が強制されるか、幅の制約に違反します。 

| ステップ | スタックのサブセット | 合計 | 最大値 |
 | --- | --- | --- | --- |
 | ∅ | ∅ | 0 | 0 |
 | {1} | {1} | 60 | 60 |
 | {2} | {2} | 60 | 60 |
 | {1,2} | {1,2} | 120 | 60 |

 幅を尊重しながら両方のグループを空にしないサブセットはないため、答えは不可能です。

 ## 特殊なケース

 エッジケースの 1 つは、すべての本が直立した状態で棚の高さを超える場合に発生します。 この状況では、すべての本が強制的に書庫に積み込まれ、すぐに正しいグループを作ることができなくなります。 オプションの直立候補のセットが空になり、空でない直立グループの要件が満たされないため、アルゴリズムはこれを早期に検出します。 

もう 1 つのエッジ ケースは、スタックの高さでは技術的に有効であるが、1 冊の厚い本によって無効になる場合に発生します。 max_t は状態ごとに追跡されるため、DP はこれを正しく処理し、ワイドブックを含む状態は幅制約チェックに即座に反映されます。 

最後のエッジケースは、直立圧力を軽減するために非常に薄い本が積み重ねられた場合にのみ有効なパーティションが存在する場合です。 DP では、個人の利益に基づいて貪欲に割り当てるのではなく、オプションの書籍のすべての組み合わせを検討するため、これが可能になります。
