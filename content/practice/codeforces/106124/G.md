 ## 解決策
 ## 問題の理解

 私たちには、頂点が子供、エッジが友情を表す無向グラフとして表される子供たちのソーシャル ネットワークが与えられています。 各子供には、k 個の可能なバリエーションのプールから 1 つのゲーム バリエーションを正確に割り当てる必要があります。 各バリアントには固定のポケモンのセットが含まれており、すべてのバリアントにわたってすべてのポケモンがどこかに存在しますが、一部のポケモンは特定のバリアント専用です。 

重要なメカニズムは、友情のエッジに沿って取引することです。 2 人の子供が友情グラフの同じ接続されたコンポーネントに存在する場合、彼らは繰り返し交換することができ、最終的にはそのコンポーネント内のどこにでも存在するすべてのポケモンを共有することができます。 これは、接続されたコンポーネント内で、割り当てられたすべてのバリアントが集合的に、どのポケモンがそのコンポーネント全体にアクセスできるかを決定することを意味します。 

子供は、接続されたコンポーネント内で、すべてのポケモンが、そのコンポーネント内の子供の中で少なくとも 1 つの割り当てられたバリアントに表示される場合に限り、ポケモン図鑑を完成させることができます。 各バリアントにはすべての非独占ポケモンと一部の限定ポケモンのサブセットが含まれているため、コンポーネントでポケモンが使用可能になる唯一の方法は、そのコンポーネント内の少なくとも 1 人の子供がそのポケモンを含むバリアントを受け取る場合です。 

これにより、すべての接続されたコンポーネントについて、割り当てられたバリアント間のポケモン セットの結合が完全なグローバルポケモン図鑑をカバーするようにするという問題が軽減されます。 各バリエーションにはそのポケモンのコピーが無制限に付属しているため、唯一の制約は多重度ではなく適用範囲です。 

重要な構造上の解釈は、各ポケモンは少なくとも 1 つのバリアントによって「所有されている」と考えることができ、各コンポーネントには各ポケモンを所有する少なくとも 1 つのバリアントが含まれている必要があるということです。 同様に、すべてのポケモンについて、すべての接続コンポーネントには、それを含むバリアントが割り当てられた子が少なくとも 1 つ含まれている必要があります。 

割り当ては子供ごとに行われ、コンポーネントは独立しているため、問題は接続されたコンポーネントにわたる制約システムになります。各コンポーネントは、利用可能なポケモンの結合がフルセットであるバリアントのマルチセットを受け取る必要があります。 

n が 100000 まで、m が 200000 までという制約は、ほぼ線形または線形算術解が必要であることを示しています。 バリアントのサブセットを推論しようとしたり、取引のシミュレーションを繰り返して貪欲に割り当てようとしたりするアプローチは遅すぎます。 解決策では、グラフ構造を圧縮し、単純な割り当てルールを使用して問題をコンポーネントごとの推論に削減する必要があります。 

明らかではない失敗ケースは、友情グラフが切断されている場合に発生しますが、一部のコンポーネントが「小さすぎて」すべてのポケモンをまとめてカバーできない場合があります。 たとえば、コンポーネントが 1 人の子供で構成され、すべてのポケモンが単独で含まれるバリアントがない場合、それは不可能です。 もう 1 つの微妙なケースは、コンポーネントが大きいにもかかわらず、バリアント カバレッジの構造がグローバルに整合していない場合です。つまり、コンポーネントごとにバリアントを個別に割り当てる必要がある場合です。 

中心的な課題は、取引の到達可能性にとって接続性のみが重要であることを認識することであり、問​​題は、接続された各コンポーネントがグローバル カバレッジ制約を満たすようにラベルを割り当てることになります。 

## アプローチ

 強引なアイデアは、各子供にバリアントを割り当て、各接続コンポーネントのすべての子供が交換を繰り返した後にすべてのポケモンを入手できるかどうかをシミュレートすることです。 これには、割り当てごとに、接続されたコンポーネントを計算し、そのコンポーネント内の割り当てられたバリアント間のポケモン セットの和集合が完全なポケモン図鑑をカバーしているかどうかを確認することが含まれます。 1 つの代入の検査が n + m で線形であるとしても、代入の検索は最悪の場合でも k^n となり、これはまったく実行不可能です。 

バックトラッキングによってコンポーネントごとにバリアントを割り当てようとする、より構造化された総当りアプローチでも、コンポーネントが大きくなり、k も大きくなる可能性があるため、組み合わせ探索が指数関数的になる可能性があるため、依然として失敗します。

重要な観察は、実際にはポケモンを個別に推論する必要はないということです。 「各子供が最終的にすべてのポケモンを入手できる」という要件は、「各接続コンポーネントは、フルセットをカバーするために必要なすべてのバリアント タイプを集合的に参照する必要がある」と同等です。 各バリアントには少なくとも共通のベースライン ポケモンが含まれており、違いは排他的なものからのみ生じるため、問題は、各コンポーネント内で、必要なすべての範囲を集合的に表す方法でバリアントを割り当てることを保証することになります。 

決定的な簡素化は、すべてのコンポーネントが内部的に一貫していることを確認するだけで済み、バリアントを任意に選択できるため、コンポーネント全体に繰り返しパターンを構築できることです。 連結成分ごとに決定論的な割り当てルールを修正すると、すべての制約を満たすか、不可能性を検出できます。 

これにより、問題はグラフ接続性圧縮問題に変わり、その後に建設的なラベル付けが行われ、線形時間で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース割り当て + シミュレーション | O(k^n · (n + m)) | O(n + m) | 遅すぎる |
 | 接続されたコンポーネント + 建設的なラベル付け | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DFS または DSU を使用して、友情グラフの連結成分を計算します。 各コンポーネントは、交換を通じてポケモンを完全に共有できる子供たちのグループを表します。 すべての制約は個々のエッジではなくコンポーネント レベルで動作するため、この手順が必要です。 
2. c を連結成分の数とします。 任意にバリアントを割り当てる場合、各コンポーネントは完全なポケモン図鑑の要件を独立して「シミュレート」できなければなりません。 割り当てには自由があるため、各コンポーネントにバリアントがバランスよく分散されるようにすることを目指しています。 
3. k が成分数未満の場合は、直ちに出力不可能となります。 その理由は、各コンポーネントには少なくとも 1 つの代表的なバリアントが必要であり、コンポーネントよりもバリアントの数が少ないと、排他的が敵対的に解釈される場合にコンポーネント間で明確なカバレッジ パターンを保証できないためです。 
4. 巡回的または順次的な方法でコンポーネントにバリアントを割り当てます。コンポーネント i については、そのコンポーネント内のすべてのノードにバリアント (i mod k) + 1 を割り当てます。 これにより、すべてのコンポーネントが一貫したバリアント割り当てを取得し、内部の不整合が回避されることが保証されます。 
5. コンポーネントのマッピングに基づいて、各ノードに割り当てられたバリアントを出力します。 

重要なアイデアは、接続されたコンポーネント内では、すべての子供が任意に取引できるため、バリアントの割り当てを効果的にプールできるということです。 したがって、コンポーネント内の割り当ての一貫性により、コンポーネントがポケモンの利用可能性に関して単一のユニットとして動作することが保証されます。 

### なぜ効果があるのか

 接続された各コンポーネント内で、トレードにより、そのコンポーネントに割り当てられたバリアントに存在するすべてのポケモンがコンポーネント内のあらゆる場所に伝播することが可能になります。 したがって、コンポーネントは、すべてのポケモンのタイプを含めるために、割り当てられたバリアントをまとめて必要とするだけです。 コンポーネントごとに固定のバリアント パターンを割り当てることで、各コンポーネントの内部一貫性が確保され、カバレッジにギャップが生じないようにします。 制御された方法でコンポーネント全体にバリアントを割り当てるため、コンポーネントが表現されずに残されることはなく、すべての制約は割り当て中に強制される実現可能性条件にまで減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m, k = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

comp = [-1] * n
components = []

def dfs(start, cid):
    stack = [start]
    comp[start] = cid
    nodes = [start]
    while stack:
        v = stack.pop()
        for to in g[v]:
            if comp[to] == -1:
                comp[to] = cid
                stack.append(to)
                nodes.append(to)
    return nodes

cid = 0
for i in range(n):
    if comp[i] == -1:
        nodes = dfs(i, cid)
        components.append(nodes)
        cid += 1

# If there are more components than variants, impossible
if cid > k:
    print("impossible")
    sys.exit()

ans = [0] * n

for i, nodes in enumerate(components):
    variant = i + 1
    for v in nodes:
        ans[v] = variant

print(*ans)
```このコードは、最初に友情グラフの隣接リストを構築し、次に反復 DFS を使用して接続コンポーネントを計算して、再帰の深さの問題を回避します。 各ノードにはコンポーネント ID が付けられており、コンポーネントごとにノードも収集します。 

分解後、成分数がkを超えているかどうかを確認します。 その場合、構築戦略ではコンポーネントごとに異なるバリアントを 1 つも割り当てることができないため、不可能と出力されます。 

それ以外の場合は、コンポーネント i のすべてのノードにバリアント i+1 を割り当てます。 これは、コンポーネントからバリアントへの直接的な建設的なマッピングです。 

重要な実装の詳細は、明示的なスタック DFS を使用することです。 再帰的 DFS は、n = 100000 でスタック オーバーフローの危険があります。もう 1 つの微妙な点は、出力が 1 から始まる一方で、内部では 0 から始まるインデックス付けであることです。

    sys.setrecursionlimit(10**7)
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())

        b -= 1
        g[a].append(b)
        g[b].append(a)

 ## 特殊なケース

 エッジ ケースの 1 つは、完全に切り離されたグラフです。 各ノードは独自のコンポーネントを形成します。 アルゴリズムはバリアントを順番に割り当てるため、各ノードはバリアント ID を取得します。 k が少なくとも n の場合、これは直接機能します。 k が小さい場合、チェックがトリガーされ、不可能と出力されます。 

もう 1 つのエッジ ケースは、完全に接続されたグラフです。 コンポーネントは 1 つだけであるため、すべてのノードは同じバリアントを受け取ります。 取引はすべての人を結び付けるため、k が少なくとも 1 である限り、これは要件を自明に満たします。 

3 番目のケースは、成分が大きいが k が小さい場合です。 たとえば、100000 個のノードが 50001 個のコンポーネントに分割されているが、k = 50000 である場合、アルゴリズムは割り当てを試行する前に不可能を正しく検出し、部分的に無効なラベル付けを回避します。
