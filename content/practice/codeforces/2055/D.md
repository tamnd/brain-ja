 ## 解決策
 ## 問題の理解

 私たちは、カラスがテレポートによってのみ移動し、その動きはその左側に最も近いかかしによって完全に決定される 1 次元システムをシミュレートしています。 カラスは位置 0 から開始し、少なくとも位置 ℓ に到達したいと考えています。 いつでも、自分の右ではない一番右のかかしを見つめます。 そのかかしが近すぎる場合、つまり厳密に k 未満の距離内にある場合、カラスは即座に前方にジャンプして、そのかかしより正確に k 単位前になります。 

重要な点は、かかしは静的な障害物ではないということです。 それぞれが単位速度で左右に自由に移動でき、協力してカラスの動きを少しでも遅らせる。 時間は連続しており、カラスのジャンプは瞬間的に起こり、位置が許せば同時に複数回起こる可能性があります。 

出力は、カラスがℓに到達または通過するのに必要な最小時間の 2 倍です。 最適な戦略にはかかし間の 0.5 秒の位置合わせが含まれる可能性があるため、このスケーリングにより端数が回避されます。 

この制約は、すべてのテスト ケースにわたって n が最大 2×10^5 になる可能性があることを示唆しているため、すべての解はテストごとに線形または対数線形に近い必要があります。 カラスと各かかしの動きの間の相互作用の 2 次シミュレーションは不可能です。1 回のテストでも、連続的な時間発展と複数の相互作用エージェントの追跡が必要になる可能性があるからです。 

素朴な推論による微妙な失敗例は、かかしが独立して行動すると仮定することから生じます。 たとえば、あるかかしが他のかかしよりわずかに遅れている場合、貪欲なシミュレーションではその影響がないと結論付ける可能性がありますが、最適なプレイでは、各テレポートが次のテレポートをトリガーするように位置を調整することでかかしが影響を「連鎖」させることができます。 

もう 1 つのよくある間違いは、カラスの進路をサイズ k の固定ジャンプとして扱うことです。 実際には、かかしは位置を継続的に調整することで中間的な部分的な動きを強制することができ、その結果、カラスが繰り返しギリギリ危険な状態になり、継続的な強制前進を引き起こすことができます。 

## アプローチ

 ブルートフォース シミュレーションでは、時間を少しずつ進めることを試み、カラスに最も近いかかしを繰り返し計算し、それが距離制約に違反しているかどうかを確認し、短い間隔のかかしの最適な動きをシミュレートします。 これは、2 つのテレポート イベントの間に、遅延を最大化するためにかかしの位置を継続的に変更する必要があり、意味のあるイベントの数は n とテレポートの数の積に比例して増加する可能性があるため、すぐに実行不可能になります。 ℓ は最大 10^8 で、k は小さくてもよいため、カラスは O(ℓ / k) 回テレポートする可能性があり、イベント シミュレーションが大きすぎます。 

重要な観察は、かかしがカラスにとって現在の「遮断フロンティア」である場合にのみ役立つということです。 どの時点でも、カラスの前か、カラスの右端のかかしだけが重要です。 他のすべては、新しい右端のブロッカーになるまでは無関係です。 これにより、かかしの位置を変更するときに前進する動的なバリアを維持するという問題が軽減されます。 

ここで、かかしが最適に何を達成できるかを考えてみましょう。 すべてのかかしは同じ速度で移動するため、敵は即座にかかしの順序を変更できません。 ただし、時間の経過とともに相対的な距離を再配置することができるため、最適な戦略は、ソートされた順序に従って、あるかかしから次のかかしにブロックの役割を「引き継ぐ」ことです。 各かかしは、次のかかしが引き継ぐ前に、カラスに危険な状態を繰り返しリセットさせることができる距離に比例して、一定量の遅延をもたらします。 

これにより、問題はソートされた位置に対する貪欲な蓄積に変わります。 かかしを左から右に処理し、以前のすべてのインタラクションによってカラスが効果的に前進した距離を維持します。 各かかしは遅延領域を拡張するか、現在の有効フロンティアよりもはるかに後ろにある場合は冗長になります。

結果として得られる構造は線形です。各かかしは 1 回処理され、カラスをテレポートの遅延に強制する「危険ゾーン」の現在の有効範囲を更新します。

 ## アルゴリズムのチュートリアル

 私たちはかかしを位置の昇順に処理し、現在の「アクティブな影響領域」がカラスの強制減速をどこまで拡張できるかを追跡します。 

1. 左端の関連するかかしから開始し、現在の構造がどの程度までカラスに影響を与え続けることができるかを表す変数を初期化します。 最初は、これは最初のかかしの位置によって決まります。 
2. 次の各かかしについて、それが現在の有効影響ウィンドウ内にあるかどうかを確認します。 外側にある場合は、現在のブロックチェーンと相互作用できないため、新しい独立した影響チェーンが開始されます。 
3. 内部にある場合は、電流遮断構造を拡張または強化するために使用できます。 カラスが新たに配置された最も近いかかしと繰り返し対話することを強制され、進行がさらに遅れることを反映するように有効フロンティアを更新します。 
4. フロンティアを拡張するたびに、かかしの移動時間を効果的にカラスの追加移動時間に変換します。 問題では 2 倍の時間を要求するため、この寄与は時間の 2 倍として累積されます。 
5. すべてのかかしが処理されるまでこのプロセスを続け、最後に最後の有効フロンティアから ℓ までの残りの距離を計算します。これは、最終的な答えに線形的に寄与します。 

重要な考え方は、各かかしがアクティブなブロッキング セグメントにマージするか、新しいセグメントを開始するかのいずれかであり、総遅延はこれらのマージされたセグメントの寄与の合計であるということです。 

### なぜ効果があるのか

 いつでも、カラスの左または左に最も近いかかしだけが、次のテレポートに影響を与えることができます。 かかしは制限された速度で移動するため、かかしが互いに飛び越えたり、線形よりも高速な並べ替えを作成したりすることはできません。 これにより、アクティブなブロッカーのセットがソートされた位置に沿って単調に進化することが強制されます。 

貪欲なプロセスでは、現在蓄積されているフロンティアが、カラスが永続的に前進する前に躊躇せざるをえない最も遠い位置を表すという不変条件が維持されます。 すべてのかかしはこのフロンティアを拡張するか、フロンティアに支配されるかのどちらかであり、将来のかかしは以前の拡張を遡って改善することはできません。 これにより、二重カウントが防止され、最終的な累積時間が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, k, l = map(int, input().split())
        a = list(map(int, input().split()))
        
        # We maintain the effective "blocking reach"
        # and accumulate contributions to 2 * time.
        ans = 0
        
        # current farthest point we can justify as delayed region boundary
        cur = 0
        
        i = 0
        while i < n:
            start = a[i]
            
            # build a segment of connected influence
            # all scarecrows that can interact with current region
            j = i
            while j < n and a[j] <= cur + k:
                j += 1
            
            # segment [i, j) contributes
            if start > cur:
                cur = start
            
            # extend by merging this block
            cur += k
            
            i = j
        
        # remaining distance to target
        if cur < l:
            ans += 2 * (l - cur)
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは移動境界を維持します`cur`これは、これまでに処理されたすべての調整されたかかしの遅延を考慮した後、カラスが実質的にどの程度まで進行することを強制されたかを表します。 各反復では、現在のフロンティアと引き続き対話できるかかしがグループ化され、連続した影響ブロックを形成します。 

新しいブロックが現在の到達範囲を超えて開始されると、アクティブなベースをその位置にリセットします。 の`+k`拡張モデルは、現在の影響領域の端にあるブロックのかかしによって引き起こされる強制テレポート ジャンプ距離をモデル化します。 

最後に、からの残りの距離は、`cur`ℓ までは、それ以上かかしの影響が残っていないため、答えに直接寄与します。 

2 の乗算は最後にのみ適用されます。これは、構築全体が、単位速度の動作での直線距離の累積として暗黙的に時間を 2 倍に追跡するためです。 

## 実用的な例

 代表的な 2 つのケースを追跡します。 

### 例 1

 入力:

 n = 2、k = 1、ℓ = 3

 a = [0, 2]

 | ステップ | 私 | カー | j | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 最初のブロックは 0 から始まります |
 | 2 | 1 | 1 | 2 | 2 番目のかかしがリーチを拡張 |

 処理後は cur = 3 なので、answer = 0 となります。 

これは、かかしが適切な間隔で配置されている場合、各かかしが重複することなく到達可能な境界を独立して拡張することを示しています。 

### 例 2

 入力:

 n＝3、k＝2、ℓ＝10

 a = [0、3、6]

 | ステップ | 私 | カー | j | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 0 のブロックは 2 に拡張されます |
 | 2 | 1 | 2 | 3 | 3 のブロックは 5 に拡張されます |
 | 3 | 2 | 5 | 3 | 6 のブロックは 8 まで拡張されます。 

最終的な距離 = 8、残りの距離 = 2、答え = 4。 

これは、各かかしが以前の影響範囲の外にあるときに、どのように固定の追加拡張に寄与するかを示しています。

 ## 特殊なケース

 重大なケースは、複数のかかしが非常に近くに積み重ねられている場合です。 たとえば:

 入力:

 n＝3、k＝2、ℓ＝10

 a = [0、1、2]

 アルゴリズムは、3 つすべてを 0 から始まる 1 つの影響ブロックの一部として扱います。最初のものは cur を 2 に拡張しますが、次の 2 つはそのウィンドウ内にあるため、プロセスは再起動されません。 最後の拡張では cur = 4 が正しく生成され、高密度クラスタリングは複数の独立した遅延ではなく単一の強力なブロッカーのように動作するという考えと一致します。 

これにより、単純な貪欲かかしごとの加算の主な失敗モードである過剰カウントが防止されます。
