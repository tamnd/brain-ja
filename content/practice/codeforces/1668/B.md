 ## 解決策
 ## 問題の理解

 円形の配置が与えられています$m$座席とリスト$n$人々。 各人には個人的な「除外範囲」があります$a_i$: 彼らがどこかの席に座っていたら、一番近い席$a_i$サークルの両側の席は空席のままにしておく必要があります。 言い換えれば、各人は 1 つの椅子を占有するだけでなく、連続した椅子の弧を効果的にブロックします。$2a_i + 1$サークル上の座席をその位置の中心に配置します。 

タスクは、これらのブロックされた領域が重ならないように、すべての人々を円上に配置できるかどうかを決定することです。 

重要な構造上の詳細は、これは単に円上に間隔を詰めることに関するものであり、各間隔には長さがあるということです。$2a_i + 1$、間隔は互いに素である必要があります。 

この制約により、強引な配置は不可能になります。 すべてのテスト ケースの合計人数は最大です。$10^5$、椅子の数は次のとおりです。$10^9$。 座席をシミュレートしたり、位置を個別に確認しようとするアプローチは直ちに除外されます。 平$O(n^2)$テストケースごとに実行すると遅すぎます。 

微妙なエッジケースは、総需要が円のサイズに近い場合です。 たとえば、次の場合$m = 5$そしてすべて$a_i = 2$の場合、各人が 5 席をブロックすることになり、最大で 1 人しか座ることができなくなります。 循環ラップアラウンドを無視する貪欲なアプローチは、線形間隔が機能すると誤って仮定する可能性がありますが、ラップアラウンドにより最後の配置と最初の配置の間に重複が発生します。 

もう 1 つの注意が必要な状況は、小規模なものが多数ある場合です。$a_i$複数の値が 1 つの大きな値と共存します。 大きな値が優勢で使用可能なスペースをほとんど消費し、小さな値が柔軟に見えても有効な配置が残らない可能性があります。 

## アプローチ

 直接的な強引なアイデアは、円上の座席位置をシミュレートすることです。 各人を空いている席に配置し、ブロックされた間隔にマークを付けることもできます。 これには、空きセグメントの構造を維持し、重複を確認しながらインターバルを繰り返し挿入することが含まれます。 最悪の場合、すべての配置で残りのスペースのほぼすべてをスキャンする必要が生じ、$O(nm)$素朴に行われた場合の行動は不可能です$m$まで$10^9$。 

重要な観察は、個々の立場はまったく重要ではないということです。 占有およびブロックされたスペースの合計量のみが重要です。 一人一人が正確に摂取する$2a_i + 1$これらの消費は重複してはなりません。 円には境界がないため、これを総容量の問題として扱うことができます。つまり、合計の長さが超えてはいけないセグメントをパックしようとしているのです。$m$。 

したがって、問題は次のことを確認することになります。$$\sum (2a_i + 1) \leq m$$ただし、隣接制約ではスペースを削減するための任意のパッキング順序が許可されないため、これは循環設定では若干誤解を招きます。 すべてのセグメントは固定であり、重複したり圧縮したりできないため、正しい調整は、合計のみを介して暗黙的にサイズで並べ替えることです。 

したがって、実現可能条件は純粋にサムチェックです。

 ## アルゴリズムのチュートリアル

 1. 各人について、実際に占有している座席の数を計算します。$2a_i + 1$。 これは、座席と両側に必要な空のバッファを表します。 
2. すべての人々のこれらの値を合計して、必要な合計スペースを取得します。 
3. この合計を次と比較します。$m$、円のサイズ。 
4. 必要なスペースの合計が以下の場合$m$、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

合計の背後にある理由は、各人の禁止領域は互いに素である必要があり、各領域は配置に関係なく固定長であるということです。 

### なぜ効果があるのか

 各人は、他のブロックと重ならない連続した座席のブロックを誘導します。 これらのブロックは剛体で独立しているため、有効な構成はすべて、円をこれらの正確な長さの互いに素なセグメントに分割することに対応します。 サークルには総容量があります$m$したがって、必要な条件は、セグメントの長さの合計が以下を超えないことです。$m$。 また、全長が適合する場合は、必要な間隔より小さい隙間を作ることなく、常に円の周囲にセグメントを連続して配置でき、ラップアラウンドによって総容量を超える新たな制約が発生しないため、これで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        total = 0
        for x in a:
            total += 2 * x + 1
        
        if total <= m:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装は、派生条件を直接変換したものです。 それぞれ$a_i$占有セグメント長全体に拡張されます$2a_i + 1$、累計で累計されます。 最終的な比較$m$実現可能性を決定します。 

ここでよくある間違いは、中央の座席を忘れることです。$2a_i + 1$、のみを使用して$2a_i$、合計使用量が過小評価され、誤った「YES」出力が発生します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n = 1$。 この式は、次のことを確認することになります。$2a_1 + 1 \leq m$。 たとえば、次の場合$m = 3$そして$a_1 = 1$、その人は 3 つの座席すべてを正確に占有しており、これは有効です。 アルゴリズムは合計を 3 として正しく計算し、YES を返します。 

もう 1 つの特殊なケースは、すべてが$a_i = 1$。 1人あたり3席を占有します。 もし$m = 8$そして$n = 3$、合計は 9 になり、視覚的にはラップアラウンドで「適合」させようとしても容量を超えます。 総需要が供給を超える場合、循環オーバーラップを回避できないため、アルゴリズムはこれを正しく拒否します。 

最後のエッジケースは次のような場合です$m$とても大きいですが、$n$小さいです。 例えば、$n = 2$、$m = 10^9$、$a = [10^9, 10^9]$。 合計は次のようになります$4 \cdot 10^9 + 2$をすぐに超えます$m$、幾何学的推論なしで正しく NO を生成します。
