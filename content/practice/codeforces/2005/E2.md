 ## 解決策
 ## 問題の理解

 シーケンスがあります$a$そして$n \times m$マトリックス$b$。 

ゲームは左から右のシーケンスに従います。 移動中$k$、現在のプレイヤーは値が次のセルを選択する必要があります。$a_k$。 選択したセルが$(r,c)$、次の動きは厳密に右下の部分行列、つまり行に制限されます。$> r$とコラム$> c$。 

プレイヤーは必要な動きを行えなかった場合に負けます。 シーケンスの最後の要素がすでに選択されている場合、次のプレイヤーも負けます。 

マトリックスのサイズが大きいです。 すべてのテスト ケースで、セルの総数は次のとおりです。$3 \cdot 10^6$。 に比例した作業を実行するソリューション$l \cdot n \cdot m$すぐに遅すぎます。 以来$l$せいぜい$1500$、唯一の実行可能な方向は、各行列セルを一定の回数処理し、シーケンスに関するすべての情報を何らかの方法で圧縮することです。 

危険なケースは、マトリックス内に同じ値が何度も出現するケースです。 素朴なミニマックスはすべての出来事に分岐し、すぐに爆発します。 

考慮する```
a = [1,2]

1 1 1
1 2 1
1 1 1
```さまざまな出現を選択する`1`利用可能な右下の領域が劇的に変化します。 すべての等しい値を交換可能として扱うと、間違った答えが得られます。 

もう 1 つの微妙なケースは、移動によって右下隅に非常に近いセルが意図的に選択される場合です。```
a = [1,2]

1 5
6 1
```最初のプレイヤーは右下を選択できます`1`。 残りのサブマトリックスは空であるため、2 番目のプレーヤーはすぐに負けます。 かどうかだけをチェックするアルゴリズム`2`マトリックスのどこかに存在すると、最初のプレイヤーの損失が誤って宣言されてしまいます。 

最後のトラップは、シーケンス内で繰り返される値です。 ポジションの勝利ステータスは、重要な値の最も早い出現に関連付けられます。 その後の発生は新しい戦略的状態を作成しないため、慎重に圧縮する必要があります。 

## アプローチ

 直接的なミニマックス定式化は簡単です。 

させて$W_k$現在必要な要素が次の場合に、選択肢となるセルのセットになります。$a_k$。 細胞$(r,c)$に属します$W_k$引っ越しに対するあらゆる法的対応があれば$k+1$負けています。 同様に、次のセルは存在しません。$W_{k+1}$右下の四角形の内側$(r,c)$。 

この繰り返しは正しいですが、それを計算するには文字通り、シーケンスの位置ごとに勝ちセットを維持する必要があります。 各レイヤーで処理しても$O(nm)$、複雑さは次のようになります$O(lnm)$、それは周りにあります$4.5 \cdot 10^9$最悪の場合の運用。 

重要な観察は、実際にはすべてのシーケンス位置に DP 層が必要ないということです。 

セルの場合、重要なのは次の 2 つの情報だけです。 

1. サフィックス四角形内で到達可能な偶数パリティの最小の勝ちシーケンス インデックス。 
2. サフィックス四角形内で到達可能な奇数パリティの最小の勝ちシーケンス インデックス。 

これら 2 つの値がわかれば、現在のセル自体が勝利状態を作成するかどうかを判断できます。 

これでは全てが崩壊してしまう$l$DP レイヤーを 2 つのマトリックスに分割します。 

ハードバージョンではさらに圧縮が追加されます。 各値については、最初の繰り返しの前にシーケンス内で最初に出現した値のみが関係します。 同じ値が後で発生しても、より小さい勝利インデックスが生成されることはなく、無視できます。 これにより、シーケンス情報が値ごとに 1 つのインデックスに削減されます。 公式に認められたソリューションは、まさにこの圧縮を使用します。 

圧縮後、すべての行列セルはサフィックスを最小限に維持しながら 1 回処理され、行列サイズに線形の複雑さが与えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シーケンスレイヤー上のブルートフォースDP |$O(lnm)$|$O(nm)$| 遅すぎる |
 | 最適なサフィックス最小 DP |$O(nm)$テストケースごと |$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンス内に出現するすべての値について、その値が出現する最初のインデックスを保存します。 値が繰り返されると、それ以降の値は無関係になるため、無視できます。 
2. 2 つの DP テーブルを作成します。`dp0[r][c]`で始まるサフィックス四角形内のどこかで達成できる偶数パリティの最小の勝利シーケンス インデックスを格納します。`(r,c)`。`dp1[r][c]`奇数パリティの類似値を格納します。 
3. すべてのエントリを無限大で初期化します。 
4. マトリックスを右下から左上に向かって処理します。 
5. 現在のセルを検討する前に、サフィックス最小値を伝播します。$$dp0[r][c] = \min(dp0[r+1][c], dp0[r][c+1])$$

$$dp1[r][c] = \min(dp1[r+1][c], dp1[r][c+1])$$このステップの後、各テーブルには、現在位置の厳密に下または厳密に右にあるすべてのセルからの情報がすでに含まれています。 
6. しましょう`p`現在の行列セルの値に対応する格納されたシーケンス インデックスになります。 
7. もし`p`偶数パリティがある場合、このセルはインデックスの勝利状態になります。`p`サフィックス四角形にインデックスの勝利状態が含まれていない場合`p+1`。 

圧縮表現では、その条件は正確に次のようになります。$$p + 3 \le dp1[r+1][c+1].$$保持されたら更新する$$dp0[r][c] = \min(dp0[r][c], p).$$8. 奇数パリティに対称ルールを適用します。$$p + 3 \le dp0[r+1][c+1].$$本当なら、$$dp1[r][c] = \min(dp1[r][c], p).$$9. マトリックス全体を処理した後、シーケンス インデックスが正確に一致した時点で最初のプレーヤーが勝ちます。`0`は、行列全体から到達可能な勝利の偶パリティ状態です。 

それは以下と同等です```
dp0[0][0] == 0
```この漸化式は、上で説明したミニマックス関係のコンパクトな形式です。 

### なぜ効果があるのか

 すべての接尾辞の四角形について、`dp0`そして`dp1`その長方形の中に存在する各パリティの最小の勝ち順インデックスを維持します。 

シーケンスインデックスに対応する動き`p`相手がインデックスの勝利状態に移行できないときこそ、勝利しているのです`p+1`右下の四角形の中にあります。 接尾辞の最小値は、そのような状態が存在するかどうかを示します。 存在しない場合は、現在のセル自体がインデックスの勝利状態になります。`p`。 

スキャン順序は右下から左上であるため、必要な右下の四角形に関するすべての情報は、セルの処理時にすでに計算されています。 不変式はスキャン全体を通じて true のままであるため、最終的な答えは`(0,0)`は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10 ** 9

def solve():
    t = int(input())
    out = []

    pos = {}

    for _ in range(t):
        l, n, m = map(int, input().split())
        a = list(map(int, input().split()))

        pos.clear()

        for i, x in enumerate(a):
            if x in pos:
                break
            pos[x] = i

        dp0 = [[INF] * (m + 1) for _ in range(n + 1)]
        dp1 = [[INF] * (m + 1) for _ in range(n + 1)]

        b = [list(map(int, input().split())) for _ in range(n)]

        for r in range(n - 1, -1, -1):
            for c in range(m - 1, -1, -1):

                if dp0[r + 1][c] < dp0[r][c]:
                    dp0[r][c] = dp0[r + 1][c]
                if dp0[r][c + 1] < dp0[r][c]:
                    dp0[r][c] = dp0[r][c + 1]

                if dp1[r + 1][c] < dp1[r][c]:
                    dp1[r][c] = dp1[r + 1][c]
                if dp1[r][c + 1] < dp1[r][c]:
                    dp1[r][c] = dp1[r][c + 1]

                p = pos.get(b[r][c], -1)

                if p >= 0:
                    if p % 2 == 0:
                        if p + 3 <= dp1[r + 1][c + 1]:
                            if p < dp0[r][c]:
                                dp0[r][c] = p
                    else:
                        if p + 3 <= dp0[r + 1][c + 1]:
                            if p < dp1[r][c]:
                                dp1[r][c] = p

        out.append('T' if dp0[0][0] == 0 else 'N')

    sys.stdout.write("\n".join(out))

solve()
```最初のセクションでは、値からシーケンス インデックスへの圧縮マッピングを構築します。 各値の最初の出現のみが保存されます。 

2 つの DP テーブルは無限大で初期化されます。 無限値は、そのパリティの勝ちシーケンス インデックスが対応するサフィックス四角形に存在しないことを意味します。 

マトリックスは逆の順序でスキャンされます。 その時には`(r,c)`長方形が処理される`(r+1,c+1)`すでに完全な情報が含まれており、これはまさにゲームの移行に必要な領域です。 

条件`p + 3 <= ...`は、「相手には次のシーケンス位置に対する勝利状態がない」の圧縮形式です。 使用する`p + 1`テーブルには正確なインデックスではなく、パリティの最小の勝者インデックスが保存されるため、これは不正確です。 

答えはシーケンスインデックスかどうかによって完全に決まります。`0`勝利状態になります。

 検討してください```

5
1 2
3 4
```行列セルには次のものが含まれていません`5`。 DP はシーケンス インデックスに対応する勝利状態を決して作成しません。`0`、 それで`dp0[0][0]`無限大のままで、答えは`N`。
