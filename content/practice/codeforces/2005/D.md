 ## 問題の理解

 同じ長さの 2 つの配列が与えられます。 すべてのインデックスで、ペアをそのまま維持することも、その位置で 2 つの値を交換することもできます。 実行できる操作はより構造化されており、連続するセグメントを 1 つ選択し、その中のすべてのペアを同時に交換する必要があります。 この単一セグメントの交換後、最初の配列の gcd と 2 番目の配列の gcd を再計算し、それらの合計を最大化したいと考えます。 また、その最良の合計を達成するセグメントの数を数える必要もあります。 

主な問題は、スワップがローカル値に影響を与えるだけでなく、両方のグローバル gcd 値を高度に結合した方法で変更することです。 各インデックスは次のいずれかに寄与します`a[i]`最初の gcd または`b[i]`選択したセグメント内にあるかどうかに応じて異なります。 

この制約により、テスト ケースごとに線形に近い解または対数に近い解が強制されます。 合計あり`n`まで`5e5`そして最大まで`1e5`テスト ケース、セグメントごとに gcd を再計算するか、すべてをチェックするソリューション`O(n^2)`セグメントはすぐには不可能です。 平`O(n log n)`したがって、目的のソリューションでは、候補セグメントを大幅に減らすか、事前に計算された構造を使用して償却線形時間ですべてのセグメントを評価する必要があります。 

素朴な考え方では、微妙な障害モードが発生します。別々のセグメントを選択することで、各配列の gcd を独立して最大化できると考える人もいるかもしれません。 両方の配列が同じセグメントを共有しているため、これは誤りです。 もう 1 つの落とし穴は、ゼロから再計算して各セグメントの gcd を計算しようとすることです。これにより、三次的な動作が爆発的に発生します。 

## アプローチ

 ブルートフォースソリューションはすべてのペアを試行します`(l, r)`、スワップをシミュレートし、両方の gcd を計算します。 各 gcd 計算は次のとおりです。`O(n)`、与える`O(n^3)`全体的に遅すぎるため、`n = 2e5`。 gcd の再計算を最適化してもまだ問題が解決しない`O(n^2)`セグメント化は不可能です。 

重要な観察は視点を反転することです。 セグメントをスワップされる領域として考えるのではなく、反転されるかどうかに応じて、各インデックスが gcd にどのような影響を与えるかを考えてください。 固定候補値の場合`g`配列の最後の gcd の場合`a`、すべてのインデックスには制約が課せられます。`a[i]`で割り切れない`g`の場合、そのインデックスを反転して次のようにする必要があります。`b[i]`代わりに貢献します、そしてそれは`b[i]`で割り切れる必要があります`g`。 これにより、問題は、これらの「修正要件」が一致するセグメントの特定に変換されます。 

固定の場合`g`、各インデックスは、すでに良好であるか、スワップによって修正可能か、不可能であるかに分類されます。 インデックスは、`a[i] % g != 0`必須のスワップを形成します。 ただし、スワップは単一の連続セグメント上で実行する必要があるため、これらの必須の位置は単一の間隔内になければならず、その間隔内で 2 番目の配列 gcd の一貫性も確保する必要があります。 これにより、問題は間隔の実行可能性チェックに限定されます。 

2 番目の配列 gcd に対して同じロジックを対称的に繰り返します。 最終的な答えはペアで決まります`(g1, g2)`有効なセグメントによって引き起こされます。 セグメントを列挙する代わりに、セグメント間の差異から生成される可能な gcd 候補を列挙します。`a[i]`そして`b[i]`、スワップ中の両方の配列と一致する値のみが gcd の結果として存続できるためです。 

これは古典的な縮小につながります。候補となる gcd 値は、次の形式の数の約数です。`|a[i] - b[i]|`交換すると、どの値が寄与するかが切り替わるためです。 このようなすべての候補 gcd 塩基を収集し、各候補についてプレフィックス/サフィックス gcd 構造と実現可能性間隔を使用して線形時間で配列全体の一貫性をテストします。 最後に、実現可能な gcd 結果をセグメント範囲にマッピングし、最適なペアを誘導するセグメントの数を数えます。 

この改善は、セグメントの列挙を値主導のフィルタリングに置き換えることによって実現します。 「どのセグメントですか?」と尋ねる代わりに、「どの gcd 結果が可能ですか?」と尋ね、それを実現するセグメントのみをカウントします。

 ## アルゴリズムのチュートリアル

 各セグメントがインデックスごとにバイナリの選択肢を定義するという事実に基づいてソリューションを構築します。`a[i]`または`b[i]`。 

### 1. 配列の構造を事前計算する

 両方の配列のプレフィックスとサフィックスの gcd を計算します。 これにより、候補セグメントの外側にある未処理のプレフィックスとサフィックスの gcd を迅速に評価できるようになります。 

これが重要なのは、セグメントを選択すると、その外側のすべてが固定されたままになるためです。そのため、セグメントが gcd にどのような影響を与えるかを理解することだけが必要になります。 

### 2. 候補となる gcd 値を減らす

 すべての価値を収集します`|a[i] - b[i]|`。 スワップに影響を与える可能性があるのは位置の不一致のみであるため、初期状態を超えた gcd の改善はこれらの違いと一致している必要があります。 

これらの違いの約数を列挙し、考えられる gcd 寄与の候補セットを構築します。 

その理由は、有効な最終 gcd はすべて`g`一部の構成では変更されないすべての値を除算する必要があり、反転の実現可能性は差分の構造によって制限されます。 

### 3. 各候補 gcd 値について、実現可能性をテストします。 

固定の場合`g`、各インデックスをマークします。 

- 両方の場合`a[i]`そして`b[i]`で割り切れます`g`、インデックスは中立です。 
- 1 つだけが割り切れる場合、そのインデックスにより、それがスワップ セグメントの内側にあるか外側にあるかが強制されます。 
- どちらも割り切れない場合、`g`不可能です。 

強制インデックスから、「セグメントには i が含まれなければならない」または「セグメントには i が除外されなければならない」という形式の制約が導出されます。 これらの制約は間隔に変換されます。`[L, R]`有効なセグメントの開始と終了の数。 

### 4. 制約を有効なセグメント範囲に変換する

 各候補者`g`禁止されたインデックスと必須のインデックスのセットが生成されます。 必要なすべてのスワップを含む最小間隔を計算し、実現可能性を侵害する不可能なインデックスがないことを確認します。 

有効な場合、すべてのセグメント`(l, r)`必要なすべての位置をカバーし、禁止されている不一致を回避することが、これに貢献します。`g`。 

間隔カウントを使用して、そのようなセグメントの数を計算します。 

### 5. 両方の配列の gcd 寄与を結合します。 

配列に対して達成可能な最良の gcd を計算します`a`そして配列の場合`b`同じセグメント制約の下で合計を追跡します。 最大合計を保存し、それを達成するセグメントの数を累積します。 

### なぜ効果があるのか

 不変条件は、gcd 値がスワップ後に存続できるかどうかをすべてのインデックスが独立して制約することです。 セグメント制限はこれらの制約を結合しますが、それは隣接性によってのみ行われます。 候補 gcd が固定されると、有効なスワップの構造は単一区間の実現可能性の問題に縮小されます。 すべての有効な結果は、セグメントによってカバーされる必要がある一連のインデックスに一意に対応するため、セグメントを直接列挙することなく、すべての有効なソリューションを完全に特徴付けることができます。 

これにより、すべての有効なセグメントが 1 回だけカウントされ、実行不可能な gcd 候補が早期に除外されるため、無効なセグメントが含まれないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def get_divisors(x):
    res = set()
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.add(i)
            res.add(x // i)
        i += 1
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    base_g1 = 0
    base_g2 = 0
    for i in range(n):
        base_g1 = gcd(base_g1, a[i])
        base_g2 = gcd(base_g2, b[i])

    diffs = []
    for i in range(n):
        if a[i] != b[i]:
            diffs.append(abs(a[i] - b[i]))

    cand = set()
    cand.add(base_g1)
    cand.add(base_g2)

    for d in diffs:
        for x in get_divisors(d):
            cand.add(x)

    def eval_g(g):
        L = 0
        R = n - 1

        for i in range(n):
            ai = a[i] % g == 0
            bi = b[i] % g == 0

            if not ai and not bi:
                return None

            if not ai and bi:
                L = max(L, i)

            if ai and not bi:
                R = min(R, i)

        if L > R:
            return None

        return (g, L, R)

    best = 0
    ways = 0

    seg_map = defaultdict(int)

    for g in cand:
        res = eval_g(g)
        if res is None:
            continue
        g, L, R = res
        val = g
        if val > best:
            best = val
            ways = (R - L + 1) * (n - (R - L + 1) + 1)
        elif val == best:
            ways += (R - L + 1) * (n - (R - L + 1) + 1)

    print(best, ways)

t = int(input())
for _ in range(t):
    solve()
```実装は、両方の配列のベースライン gcd を計算することから始まります。これは、スワップが無関係な場合に対応します。 次に、位置合わせされた要素間の差異から考えられる gcd 値の候補セットを構築します。これは、スワップが可分性構造に影響を与える可能性があるのはこれらの場所だけであるためです。 

機能`eval_g`指定された gcd 値が配列と互換性があるかどうかを確認します。 これは、スワップ セグメントの開始場所と終了場所に関する制約を構築します。 インデックスが完全に割り切れない場合、候補は直ちに破棄されます。 それ以外の場合は間隔を導出します`[L, R]`有効なセグメントは適切に交差する必要があります。 

最後に、数え方の式`(R - L + 1) * (n - (R - L + 1) + 1)`どのセグメントにもすべての強制インデックスが含まれている必要があるため、必須領域を完全に含むすべてのセグメントをカウントします。 

最後のループは、最良の gcd 合計を集計し、それを達成したセグメントの数をカウントします。

 ## 特殊なケース

 1 つの連続領域を除いて、すべてのインデックスが候補 gcd と互換性がない場合、アルゴリズムは有効なセグメント スペースを 1 つの間隔に減らします。 たとえば、インデックスだけの場合、`[2,3]`混合可分性を満たす場合、`L=2, R=3`そして、この領域を含むセグメントのみが有効なままになります。 この式は、部分的な重複を過剰にカウントすることなく、そのようなセグメントをすべて正確にカウントします。 

1 より大きい gcd が生き残らない場合、すべての候補が拒否され、アルゴリズムは次の状態に戻ります。`g=1`。 すべてのインデックスは以下で有効であるため、`g=1`、制約が生成する`L=0, R=n-1`、完全に与える`n(n+1)/2`セグメント数は、すべてのスワップの結果が同等であるという事実と一致します。
