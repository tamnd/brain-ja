 ## 問題の理解

 長さのあるボックスがあります`n`平行レール上に 2 本のバーが含まれています。 ショートバーには長さがあります`a`、長いバーには長さがあります`b`、 と`a < b`。 長いバーには両端にストッパーが付いており、短いバーはこれら 2 つのストッパーの間に完全に留まる必要があります。 

最初は、両方のバーがボックスの左側と同じ高さで始まります。 目標は、できるだけ少ない動きで、両方のバーを右側と同じ高さになるまで移動することです。 1 回の移動中に、ちょうど 1 つのバーの位置が変更され、もう 1 つのバーは固定されたままになります。 唯一の制限は、すべての動きの後、短いバーが長いバーの 2 つのストッパーの間に位置していなければならないことです。 

入力には以下が含まれます`a`、`b`、 そして`n`、 どこ`1 ≤ a < b ≤ n ≤ 10^7`。 の上限`10^7`は、一定量の作業を実行するアルゴリズムが理想的であることを示していますが、アルゴリズムが`n^2`全く実現不可能です。 線形シミュレーションは最悪の場合でも約 1,000 万回の反復に達する可能性があり、これは Python の 2 秒の制限を下回る境界線となる可能性があります。 直接式は、計算を数回の算術演算に減らすため、推奨されます。 公式の制限は 2 秒で、メモリ制限は 512 MB です。 

最初のエッジケースは、長いバーがすでにボックス全体を満たしている場合です。 たとえば、入力の場合`1 3 3`、長いバーには長さがあります`3`箱にも長さがあります`3`。 ショートバーは左のストッパーから右のストッパーまで直接移動できますが、ショートバーはまったく動かないので、答えは次のようになります。`1`。 常に両方のバーが移動する必要があると想定する不用意な解決策では、少なくとも次の結果が返されます。`2`。 

2 番目のエッジ ケースは次の場合に発生します。`b - a = 1`。 例えば、`2 3 5`短いバーの周囲の長いバーの内側に空きスペースが 1 ユニットだけあります。 長いバーは​​移動しなければなりません`5 - 3 = 2`単位であり、各動きのペアは 1 単位だけ進めることができるため、答えは次のようになります。`2 * 2 + 1 = 5`。 上限の代わりに整数除算を使用する数式では、誤って計算されるのは次のとおりです。`3`動きます。 

3 番目のエッジケースは、長いバーの必要な動きが次の式で割り切れない場合です。`b - a`。 例えば、`2 5 8`移動するには長いバーが必要です`3`単位ですが、短いバーは最大で 1 単位の隙間を作ることができます。`3`単位。 ここでは、1 つの完全なペアの動きで長いバーを 1 つ進めます。`3`、与える`3`合計で動きます。 と`2 4 9`ただし、長いバーは​​移動する必要があります`5`ユニットと各ペアは最大でそれを進めることができます`2`、つまり 3 つのペアが必要であり、答えは次のようになります。`7`。 天井操作は必須です。 

## アプローチ

どちらの動きも、可能な最大位置よりも前に停止してもメリットはありません。 後の法的立場もすべて右寄りになるため、右寄りに移動しても将来の状態が悪化することはありません。 これにより、バーを貪欲に交互に配置し、最後のショートバーの動きを除くすべての動きを正確に反映させることができます。`d`長いバーの進行単位。 公式チュートリアルでは、同じ観察と結果の式が提供されています。

 ## アルゴリズムのチュートリアル

 1.読む`a`、`b`、 そして`n`。 移動カウントで重要となる唯一の数量は、長いバーが移動する必要がある距離です。`n - b`、およびバー間で利用可能な最大相対シフト、`b - a`。 
2. コンピューティング`distance = n - b`。 これは、長いバーがボックスの右側に到達する前に、長いバーの左端点が移動する必要がある合計距離です。 
3. コンピューティング`gap = b - a`。 これは、長いバーの 2 つのストッパーの間に留まりながら、短いバーを長いバーの前に配置できる最大距離です。 
4. コンピューティング`pairs = (distance + gap - 1) // gap`。 すべてのペアは、短いバーをできるだけ右に移動し、次に長いバーをできるだけ右に移動することで構成されます。 このようなペアは長いバーを次のように進めます。`gap`ただし、おそらく最後のペアは除きます。長いバーが境界に達しているため、少しずつ進む可能性があります。 
5. 乗算`pairs`すべてのペアに 1 つの短いバーの動きと 1 つの長いバーの動きが含まれるため、2 倍になります。 
6. ショートバーに最後の動きを 1 つ追加します。 長いバーが目標位置に到達した後、短いバーは最終ストッパーの間に留まりながら直接目標位置に移動できます。 

### なぜ効果があるのか

 不変条件は、長いバーが移動する直前に、短いバーは最大でも配置できるということです。`b - a`長いバーの前のユニット。 その結果、単一の長いバーの移動で左端点を最大で 1 つ進めることができます。`b - a`。 貪欲な戦略は、さらなる進歩が必要になるたびにまさにその最大値に達するため、手数の点で長いバーをより速く移動できる戦略はありません。 

長いバーは​​移動する必要がある`n - b`単位なので、少なくとも`ceil((n - b) / (b - a))`長いバーの動きが必要です。 初期構成を除き、このような長いバーの移動の前に、必要なギャップを作成するために短いバーの移動が必要です。 ロングバーがターゲットに到達すると、ショートバーの移動が 1 つだけ残ります。 構築されたシーケンスはこの下限を達成し、次のようになります。`2 * ceil((n - b) / (b - a)) + 1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, n = map(int, input().split())

    distance = n - b
    gap = b - a

    pairs = (distance + gap - 1) // gap
    answer = 2 * pairs + 1

    print(answer)

if __name__ == "__main__":
    solve()

表現`(distance + gap - 1) // gap`浮動小数点演算を行わずに天井除算を実行します。 ここでは浮動小数点は不要であり、回避可能な精度の問題が発生する可能性がありますが、整数演算は入力範囲全体に対して正確です。
