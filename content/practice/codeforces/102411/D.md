 ## 解決策
 ## 問題の理解

 (1) から (n) までの空でないすべての長さを考慮して、サイズ (k) のアルファベットにわたる文字列をカウントする必要があります。 文字列は、それ自体が回文であるか、2 つの回文に分割できる場合に有効です。 2 つの部分の長さは異なる場合があり、同じである場合もあります。 

有用な解釈は、分割位置を選択し、両側を回文にすることで有効な文字列を生成できるということです。 問題は、同じ文字列に複数の有効な分割位置が存在する可能性があるため、各分割の可能性の数を単純に加算するとカウントが大きくなってしまうことです。 

アルファベットは最大 26 文字ですが、最大長は (10^5) です。 すべての (k^n) 文字列を検査する方法は、回文チェックを行う前であっても不可能です。 (n=10^5) の場合、(O(n^2)) アルゴリズムも 2 秒の制限をはるかに超えています。 単純な算術演算で、おおよそ (O(n\log n)) 以上の演算が必要です。 

誤って対処しやすい特殊なケースがいくつかあります。 入力用`1 5`、すべての 1 文字の文字列は回文なので、答えは正確に (5) になります。 長さ 1 の文字列にはそのような分割がないため、空ではない 2 つの部分のみを考慮するソリューションではゼロが返されます。 

入力用`2 3`、(3^2=9) 文字列はすべて二重回文です。 文字列`ab`そして`ba`たとえば、それ自体は回文ではありませんが、それぞれは 2 つの 1 文字の回文を連結したものです。 回文のみをカウントする解法では、(9) ではなく (3+3=6) が返されます。 

入力用`5 1`、すべての正の長さの文字列は 1 つだけ存在します。つまり、完全に以下から構成される文字列です。`a`。 このような文字列はすべて回文なので、答えは (5) になります。 この場合は、(k) のべき乗を含む多くの式が (1) になり、長さの合計におけるオフバイワンのエラーが特に目立つため便利です。 

さらに微妙な問題は、複数の表現です。 文字列`abacabacabac`2 つの回文にいくつかの異なる分割があります。 したがって、すべての有効な分割を個別にカウントすると、文字列はカウントされず、文字列の表現がカウントされます。 コンテストの公式チュートリアルでは、まさにこの現象を利用して、最小期間の議論を動機付けています。 

## アプローチ

 直接的なアプローチでは、(n) までのあらゆる長さのすべての文字列を列挙します。 各文字列について、それが回文であるかどうかをテストし、次にすべての分割を試して、結果の 2 つの部分が回文であるかどうかをテストできます。 これは定義に直接従うので正しいですが、絶望的に高価です。 あります

 [
 \sum_{m=1}^{n} k^m
 】

 文字列はすでに (\Theta(k^n)) であり、単純な回文チェックですべての分割をテストすると、最悪の場合、別の二次係数が追加されます。 したがって、単純な実装では、総作業量は (\Theta(n^2k^n)) となります。 (n=10^5) と (k=26) の場合、文字列を生成することさえ完全に不可能です。 

最初の有用な削減は、個別の文字列ではなく表現をカウントすることです。 最初の回文の長さ (l) を固定し (l=0)、回文全体が空の最初の部分で表されるようにします。 長さ (l) の回文は、最初の (\lceil l/2\rceil) 文字によって決まります。 

[
 k^{\lceil l/2\rceil}
 】

 そんな回文。 2 番目の部分の長さは (n-l) で、次のようになります。 

[
 k^{\lceil(n-l)/2\rceil}
 】

 可能性。 したがって、(R(n,k)) が長さ (n) の文字列を 2 つの回文として表現する数を表す場合、次のようになります。 

[
 R(n,k)=
 \sum_{l=0}^{n-1}
 k^{\lceil l/2\rceil}
 k^{\lceil(n-l)/2\rceil}。 
】

 この合計は非常に単純な閉じた形式になります。 (n=2m) の場合、(l) の (m) 個の偶数値はそれぞれ (k^m) に寄与し、(m) 個の奇数値はそれぞれ (k^{m+1}) に寄与します。 したがって、

 [
 R(2m,k)=m(k+1)k^m。 
】

 (n=2m+1) の場合、(2m+1) 個の可能な分割位置のすべてが (k^{m+1}) に寄与します。 

[
 R(2m+1,k)=(2m+1)k^{m+1}。 
】

 残りの問題は、重複した表現を削除することです。 重要な構造上の観察は、文字列に 2 つの異なる回文分割がある場合、それらの分割位置間の距離が文字列の周期であるということです。 実際、文字列はその反転の循環シフトとみなすことができ、2 つの異なる有効な分割位置により 2 つのそのようなシフトが生成されます。 それらの違いは期間を与えます。 

長さ (n) の二重回文をとり、(p) をその最小周期とします。 長さ (p) の基本文字列自体は二重回文です。 さらに重要なことは、この基本文字列には 2 つの回文として 1 つの表現が含まれているということです。 これを (n/p) 回繰り返すと、結果として得られる長さ (n) の文字列が (R(n,k)) 内に正確に (n/​​p) 回、互換性のある分割位置ごとに 1 回ずつ表示されます。 

(D(n,k)) を 2 つの回文に一意に分割する長さ (n) の二重回文の数とします。 (R(n,k)) によってカウントされるすべての表現は、この一意のクラスに属するか、より短い一意のオブジェクトの繰り返しから得られます。 したがって、

 ## R(n,k)

 \sum_{\substack{l\mid n\l<n}}
 \frac{n}{l}D(l,k)。 
】

 (D(l,k)) が既知になると、長さ (l) のプリミティブ二重回文を繰り返すたびに、(l) の倍数である各長さの 1 つの異なる文字列が得られます。 したがって、長さ (n) の異なる二重回文の数は次のようになります。 

[
 T(n,k)=\sum_{l\mid n}D(l,k)。 
】

 必要な答えには (1) から (n) までのすべての長さが含まれるため、合計を逆にすることができます。 

\sum_{l=1}^{n}D(l,k)
 \左\lf床\frac nl\右\r床。 
】

 約数の再帰性はふるいを使用して評価できます。 (D(l,k)) を計算した後、(l) の倍数 (m) ごとに ((m/l)D(l,k)) をアキュムレータに加算します。 数値とその倍数の 1 つの各ペアが 1 回処理され、合計作業量は (O(n\log n)) になります。

 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべて (0\le i\le\lceil n/2\rceil) について (k^i\bmod 998244353) を事前計算します。 (R(n,k)) の閉形式は、この指数まで累乗するだけで済みます。 
2. すべての長さ (m) について、表現数 (R(m,k)) を計算します。 偶数 (m=2q) の場合、次を使用します。 
[
 R(m,k)=q(k+1)k^q。 
】
 奇数 (m=2q+1) の場合、次を使用します。 
[
 R(m,k)=m k^{q+1}。 
】
 これにより、すべての長さに対して考えられるすべての分割位置を反復処理する必要がなくなります。 
3. 配列を維持する`sub[m]`。 (D(l,k)) が計算されたら、次の値を加算します。 
[
 \frac{m}{l}D(l,k)
 】
 に`sub[m]`倍数ごと (m=2l,3l,\ldots)。 その後(m)に到達したとき、`sub[m]`(m) のすべての適切な約数の寄与が正確に含まれます。 
4. コンピューティング
 [
 D(m,k)=R(m,k)-sub[m]。 
】
 長さを昇順に処理すると、ここで必要なすべての (D(l,k)) がすでに計算されていることが保証されます。 
5.追加
 [
 D(m,k)\left\lfloor\frac nm\right\rfloor
 】
 最終的な答えへ。 長さ (m) のプリミティブ オブジェクトは (1,2,\ldots,\lfloor n/m\rfloor) 回繰り返すことができ、各繰り返しの長さは異なります。 
6. すべての累積値を剰余 (998244353) で減算します。 Python の整数はオーバーフローしませんが、モジュラー リダクションにより中間値が小さく保たれ、必要な出力と一致します。 

### なぜ効果があるのか

 再発の背後にある不変条件は次のとおりです。`D[m]`は、回文分割が一意である長さ (m) の二重回文を正確にカウントします。`R[m]`繰り返される表現を含む、すべての有効な分割をカウントします。 文字列が一意でない表現を持つ場合、2 つの分割位置の差により自明ではないピリオドが与えられるため、文字列は短い二重回文の繰り返しになります。 その最短周期は一意の表現を持ち、長さ (l) のプリミティブ オブジェクトは正確に (m/l) の表現を (R[m]) に提供します。 したがって、これらの寄与を差し引くと、正確に一意の表現が残ります。 すべての二重回文には 1 つの最短周期プリミティブ基底があるため、合計すると`D[l]`over divisor は、それぞれの個別の文字列を 1 回だけ与えます。 

これは、コンテストの公式チュートリアルで使用されているのと同じ最小周期分解であり、一意の表現の漸化式は (D(n,k)=R(n,k)-\sum_{l\mid n,l<n}(n/l)D(l,k)) として与えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())

    # We only need powers up to ceil(n / 2).
    half = (n + 1) // 2
    pw = [1] * (half + 1)
    for i in range(1, half + 1):
        pw[i] = pw[i - 1] * k % MOD

    # sub[m] will contain
    # sum_{l | m, l < m} (m / l) * D[l].
    sub = [0] * (n + 1)
    d = [0] * (n + 1)

    ans = 0

    for m in range(1, n + 1):
        if m & 1:
            q = m // 2
            r = m * pw[q + 1] % MOD
        else:
            q = m // 2
            r = q * (k + 1) % MOD
            r = r * pw[q] % MOD

        d[m] = (r - sub[m]) % MOD

        # Every primitive object of length m contributes one
        # distinct string for each repetition count up to n / m.
        ans = (ans + d[m] * (n // m)) % MOD

        # Make d[m] available to all larger multiples.
        for multiple in range(2 * m, n + 1, m):
            sub[multiple] = (
                sub[multiple] + (multiple // m) * d[m]
            ) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```べき乗配列には、必要な係数を法とする (k^i) が格納されます。 長さ (m) の回文はその位置の半分だけで決まるため、最大の指数は (\lceil n/2\rceil) です。 

それぞれの長さごとに`m`、コードは計算します`r`、これは (R(m,k)) の閉じた形式です。 奇数式と偶数式は、組み合わせの数が異なるため、意図的に分離されています。 

の`sub`配列は主な sieve 構造です。 いつ`d[m]`既知になると、その倍数にわたるループは、長さ (m) プリミティブがより大きな各倍数の表現カウントに寄与する量を正確に追加します。 したがって、長さが`multiple`に達し、`sub[multiple]`はすでに漸化式の減算項全体と等しくなります。 

表現`n // m`答えには別の約数が含まれていますが、意味は異なります。 長さのプリミティブ ブロックを繰り返すことで取得できる、許容される長さの数をカウントします。`m`。 これが現時点で答えが蓄積されている理由です`d[m]`は、(T(m,k)) ごとに個別に構築するのではなく、計算されます。 

すべての乗算の後にモジュラーリダクションが続きます。 要因`multiple // m`は最大 (10^5) であるため、Python はこれを快適に処理します。 ループは使用します`range(2 * m, n + 1, m)`なぜなら`m`それ自体を含めてはなりません`sub[m]`: 再帰では適切な約数のみが減算されます。

## テストケース```python
import sys
import io

MOD = 998244353

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, k = map(int, sys.stdin.readline().split())

    half = (n + 1) // 2
    pw = [1] * (half + 1)
    for i in range(1, half + 1):
        pw[i] = pw[i - 1] * k % MOD

    sub = [0] * (n + 1)
    d = [0] * (n + 1)

    ans = 0

    for m in range(1, n + 1):
        if m & 1:
            q = m // 2
            r = m * pw[q + 1] % MOD
        else:
            q = m // 2
            r = q * (k + 1) % MOD
            r = r * pw[q] % MOD

        d[m] = (r - sub[m]) % MOD
        ans = (ans + d[m] * (n // m)) % MOD

        for multiple in range(2 * m, n + 1, m):
            sub[multiple] = (
                sub[multiple] + (multiple // m) * d[m]
            ) % MOD

    sys.stdin = old_stdin
    return str(ans)

assert solve_case("3 3\n") == "33", "sample 1"
assert solve_case("6 2\n") == "114", "sample 2"
assert solve_case("42 7\n") == "83419789", "sample 3"

# Minimum length
assert solve_case("1 5\n") == "5", "one-letter strings"

# Every string is valid when the alphabet has one character
assert solve_case("5 1\n") == "5", "single-letter alphabet"

# Maximum n, exercising the full sieve with the simplest alphabet
assert solve_case("100000 1\n") == "100000", "maximum n"

# Boundary where length 2 already contains every possible string
assert solve_case("2 3\n") == "12", "all strings of lengths 1 and 2"

## 特殊なケース

 入力用`1 5`、べき乗配列には (5) が含まれます。 式は (R(1,5)=1\cdot5=5) を与えます。`sub[1]`はゼロなので (D(1,5)=5)。 (1//1=1) なので、答えは 5 です。最初の回文の長さをゼロにすると、1 文字の回文全体を表現できるようになります。 

入力用`2 3`、アルゴリズムは (D(1)=3) を計算します。 長さ 2 では (R(2)=1(3+1)3=12)、一方`sub[2]=2D(1)=6`、つまり (D(2)=6)。 最終的な答えは (3\cdot2+6=12) です。 6 つのプリミティブ長さ 2 文字列は、長さ 1 プリミティブからの 6 つの寄与と結合して、3 つの長さ 1 文字列とともに 9 つの異なる長さ 2 文字列すべてを説明します。 

入力用`5 1`、(k) のすべてのべき乗は 1 です。結果の値は (D(1)=1,D(2)=0,D(3)=2,D(4)=0,D(5)=4) となり、加重合計は (5) になります。 プリミティブ分解自体は自明ではありませんが、結果として得られるすべての文字列は単なる`a`、`aa`、`aaa`、`aaaa`、 または`aaaaa`したがって、各長さの有効な文字列が 1 つだけ存在します。 

入力用`3 3`、重複表現は長さ 2 と長さ 3 ですでに表示されています。長さ 2 では、`aaa`まだ関連性はありませんが、次のような文字列`ab`分割する`a|b`; 長さ 3、次のような文字列`aba`回文である一方、自明ではない回文分割を持つものもあります。 繰り返しでは、これらの文字列を個別に識別しようとはしません。 代わりに、より短い周期プリミティブによって生成された表現が正確に減算されます。これが、最終的なカウントが大きな表現カウントではなく 33 になる理由です。
