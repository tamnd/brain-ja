 ## 解決策
 ## 問題の理解

 配列があります`a`連日発表される問題の難しさを解説。 3 つのインデックスを選択する必要があります`i < j < k`真ん中の難易度が他の 2 つの難易度のちょうど中間になるようにします。 

[
 a_j-a_i=a_k-a_j。 
]

 並べ替えると

 [
 a_i+a_k=2a_j。 
]

 したがって、タスクは、3 つの難易度が元の配列順序で等差数列を形成するすべてのインデックス トリプルをカウントすることです。 値自体は別個である必要はなく、共通の差は正、ゼロ、負のいずれかになります。 

多くてもあります`n = 2000`ポジション。 三次アルゴリズムは次のことを調べます

 [
 \binom{2000}{3}=1,331,334,000
 ]

 最大のテストケースでは 3 倍になります。 最大 10 個のテスト ケースと 2 秒の制限があるため、その作業量は Python が処理できる量をはるかに超えています。 一方、二次関数の解は約

 [
 \binom{2000}{2}=1,999,000
 ]

 テスト ケースごとに内部反復が行われるため、実用的です。 

値は (10^9) まで大きくすることができるため、式は次のようになります。`2 * a[j] - a[k]`大きさはおよそ (2\cdot10^9) に達します。 Python の整数はこれを直接処理しますが、固定幅の整数型を使用する言語では十分な幅の符号付き型を使用する必要があります。 答え自体の値は (10^9) を超え、(1,331,334,000) に達する可能性があるため、ここでは 64 ビット整数が従来の選択ですが、32 ビット符号付き整数でも十分です。 

微妙なケースの 1 つは、値が繰り返されることです。 たとえば、`a = [5, 5, 5, 5]`、3 つの位置のすべての選択が機能するため、答えは 4 になります。値が出現する回数ではなく、値が存在するかどうかのみを保存する不注意な実装では、多重性が失われ、過少カウントになります。 

もう 1 つのケースは、ゼロまたは負の公差です。 のために`a = [30, 20, 10]`、トリプルのみ違いがあります`-10`そして`-10`したがって、答えは 1 です。配列が増加する必要があると仮定するアプローチ、または正の差のみをチェックするアプローチでは、誤ってゼロが返されます。 

3 番目のケースは、必要な値がプレフィックスに存在しない場合です。 のために`a = [1, 1, 2]`、中間の位置をとると、`2 * 1 - 2 = 0`、しかし、それ以前のゼロはないので、答えは 0 です。ルックアップでは任意のターゲット値を許可し、ターゲットが存在しない場合は単純にゼロを返す必要があります。 

最後に、インデックスの順序が重要です。 のために`a = [1, 2, 1]`、値は等差数列を含むセットですが、可能なトリプルのみが違います`1`そして`-1`したがって、答えは 0 です。元のインデックスの順序を尊重せずに値の組み合わせをカウントすると、間違った結果が生成されます。 

## アプローチ

 直接的な解決策は、可能なすべてのトリプルを列挙することです`i < j < k`かどうかをテストします`a[i] + a[k] == 2 * a[j]`。 これは正しいです。すべての有効な答えがそのようなトリプルの 1 つであり、方程式を満たすすべてのトリプルが 1 回だけカウントされるからです。 問題はトリプルの数です。 のために`n = 2000`、ちょうど 1,331,334,000 個あり、三次列挙が非常に遅くなります。 

有用な観察は、中央のインデックスを修正することで得られます。`j`。 一度`j`そして正しいエンドポイント`k`が修正されると、必要な左の値が不明ではなくなります。 から

 [
 a_i+a_k=2a_j
 ]

 私たちは得る

 [
 a_i=2a_j-a_k。 
]

 したがって、どのポジションでも`k > j`、以前のポジションがいくつあるかを知る必要があるだけです`i < j`値を含む`2 * a[j] - a[k]`。 

これにより、問題は周波数検索問題に変わります。 位置を左から右に処理している間、現在の中央位置より前の位置の値を正確に含む周波数マップを維持します。 それぞれの可能性について`k`右側で、左側で必要な値を計算し、その頻度を答えに加算します。 

ブルート フォースは、可能なすべてのトリプルを明示的にチェックするため機能しますが、トリプルが多すぎるため失敗します。 1 つのエンドポイントが他の 2 つのエンドポイントから決定できるという観察により、最も内側のループを (O(1)) 平均ハッシュ マップ ルックアップに置き換えることができます。 ここでも、中間位置を含むすべてのペアを考慮し、(O(n^2)) アルゴリズムを与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n²) が期待されます | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の周波数マップを作成します。`freq`。 現在の中間位置よりも前に、各難易度が厳密に出現した回数が保存されます。 
2. 可能な中間インデックスを反復処理します。`j`左から右へ。 この繰り返しの初めに、`freq`より小さいインデックスを持つ要素が正確に含まれます`j`。 
3. ポジションごとに`k > j`、計算します

 [
 ターゲット=2a_j-a_k。 
]

 任意の有効な左インデックス`i`満たさなければなりません`a[i] = target`、つまり、この特定の有効な選択肢の数は`j`そして`k`まさに`freq[target]`。 
4.追加`freq[target]`それぞれの答えに`k`右の方へ。 頻度ルックアップは、さまざまな位置で繰り返される値を含め、すべての有効な左インデックスを一度にカウントします。 
5. すべての右側の位置が処理された後、`a[j]`の中へ`freq`。 処理後にのみ挿入する必要があります`j`、 なぜなら`j`同じ反復内で、後の右エンドポイントに対して独自の左エンドポイントとして機能することはできません。 
6. すべての可能な中間位置が処理された後、累積された答えを出力します。 

### なぜ効果があるのか

 不変条件は、中間インデックスを処理する直前に`j`、`freq[x]`インデックスの数と等しい`i < j`誰のために`a[i] = x`。 あらゆる人にとって`k > j`、等差数列条件は次と同等です。`a[i] = 2a[j] - a[k]`。 アルゴリズムは、そのような以前のインデックスの数を正確に追加するため、中間のインデックスを持つすべての有効なトリプルが追加されます。`j`カウントされます。 各トリプルには中間インデックスが 1 つだけあるため、どのトリプルも複数回カウントされません。 加工後`j`、追加`a[j]`次の中間インデックスの不変式を復元します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    answers = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        ans = 0

        for j in range(n):
            middle = a[j]

            for k in range(j + 1, n):
                target = 2 * middle - a[k]
                ans += freq.get(target, 0)

            freq[middle] = freq.get(middle, 0) + 1

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```外側のループは中央のインデックスを選択します`j`、アルゴリズムの最初のステップと一致します。 ループが始まる前に、`freq`インデックス 0 より前に位置がないため、空です。 

固定の場合`j`、内側のループは次の間隔でアクセスします。`k > j`。 表現`2 * middle - a[k]`は、以前の値とまったく同じです`a[i]`トリプルが等差数列を形成するには必ず必要です。`freq.get(target, 0)`はそのような以前の位置の数を与えるので、それを追加すると、互換性のあるすべての選択肢がカウントされます。`i`すぐに。 

へのアップデート`freq`内側のループの後に発生します。 この順序が必要な理由は、`freq`より厳密に小さいインデックスを表す必要があります`j`。 もし`a[j]`が最初に挿入された場合、現在の中間位置が誤って左端点としてカウントされる可能性がありました。 

範囲`range(j + 1, n)`強制する`k > j`、一方、周波数マップはすでに適用しています`i < j`。 したがって、3 つのインデックスすべての厳密な順序付けが反復構造に直接組み込まれます。 

Python の辞書は、予想される (O(1)) 挿入と検索を提供し、二次関数の予想実行時間を示します。 Python の整数は計算時のオーバーフローも回避します`2 * middle - a[k]`または答えを保存します。

 ## 特殊なケース

 値が繰り返される場合については、次のように考えます。`a = [5, 5, 5, 5]`。 考えられる 4 つのトリプルはすべて有効であるため、出力は 4 になります。`j = 2`たとえば、頻度マップには、以前に発生した 2 つの`5`。 適切なエンドポイント`k = 3`必要`target = 2 * 5 - 5 = 5`したがって、アルゴリズムは、考えられる 2 つの左端点に 2 を加算します。 初期の反復は、他の 2 つのトリプルに寄与します。 最終的な答えはまさに 4 です。 

負の公差については、次のように考えます。`a = [30, 20, 10]`。 で`j = 1`、右のエンドポイントの値は 10 であり、次のようになります。`target = 40 - 10 = 30`。 プレフィックスには 30 が 1 つ含まれているため、アルゴリズムによって 1 が追加されます。 答えは 1 です。計算のどこにも値の増加に関する仮定は存在しません。 

ターゲットが存在しない場合は、次のように考えます。`a = [1, 1, 2]`。 で`j = 1`の目標`k = 2`は`2 * 1 - 2 = 0`。 周波数マップには、`{1: 1}`、 それで`freq.get(0, 0)`ゼロを返します。 アルゴリズムは 0 を生成し、唯一の可能なトリプルを正しく拒否します。 

順序が重要な場合は、次のことを考慮してください。`a = [1, 2, 1]`。 で`j = 1`、`k = 2`の左の値が必要です`2 * 2 - 1 = 3`。 プレフィックスには次のみが含まれます`1`, したがって、何もカウントされません。 答えは 0 です。値には次の値が含まれていますが、`1, 2, 1`、それらの連続的な差は、`1`そして`-1`、そのため、必要な等差数列を形成しません。 

最大応答のケースは次のとおりです。`n = 2000`すべての値が次と等しい`1`。 3 つのインデックスのどの選択肢も機能し、次のようになります。 

[
 \binom{2000}{3}=1,331,334,000。 
]

 アルゴリズムは、これらの組み合わせを個別に列挙するのではなく、頻度を通じてカウントします。これが、有効なトリプル自体の数が 10 億を超えた場合でも、二次アプローチが高速である理由です。
