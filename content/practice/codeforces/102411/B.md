 ## 問題の理解

 トレプは、キー (x) による二分探索ツリーであると同時に、優先度 (y) による最小ヒープでもあります。 この問題では、優先順位はランダムではありません。すべての整数キー (x) について、次のように固定されます。 

[
 y=\sin(x)。 
】

 結果のトリープの高さが正確に (n) になるように、それぞれが符号付き 32 ビット整数に収まる (n) 個の異なる整数を出力する必要があります。 (n) 個の頂点を含むバイナリ ツリーの高さは (n) を超えることができないため、すべてのノードを根から葉までの 1 つの長いパスに強制的に配置する必要があることを意味します。 

重要なのは、両方の座標を同じ方向に並べることです。 もし

 [
 x_1<x_2<\cdots<x_n
 】

 そして同時に

 [
 \sin(x_1)<\sin(x_2)<\cdots<\sin(x_n)、
 】

 その場合、デカルト木には分岐がありません。 最小の (y) は (x_1) に属するため、(x_1) がルートになります。 1 つおきのキーの方が大きいため、残りのすべてのノードはその右側のサブツリーに属します。 同じ引数が再帰的に繰り返され、(n) 個の頂点のチェーンが得られます。 

制約 (n\le 50000) は十分小さいため、(O(n)) 個の整数を出力するのは簡単です。 本当の難しさは計算の複雑さではなく、正弦曲線の厳密に増加する部分の内側に留まる正弦の整数引数を構築することです。 32 ビットの制限により、非常に正確な近似値に任意の大きな係数を単純に乗算することはできないため、構築はおよそ 40 億の可能な整数値内に快適に収まる必要があります。 

留意する価値のあるいくつかの特殊なケースがあります。 (n=1) の場合、1 ノード ツリーの高さはすでに 1 であるため、任意の有効な整数が機能します。 例えば、```

```そして木の高さは(1)です。 

もう 1 つの境界は (n=50000) です。 (-25000d) から (24999d) までの値を使用する構造では、その最大絶対値を (2^{31}) 未満に保つ必要があります。 (d=710) では、最大の大きさは (17750000) のみであるため、符号付き 32 ビット条件は厳密とは言えません。 

より微妙なエッジ ケースがゼロ付近で発生します。 次のような小さな連続整数を取得します。```
4
```(x=-1,0,1,2) を試みても機能しません。サイン値が

 [
 -\sin(1),0,\sin(1),\sin(2),
 】

 ここでは問題になりませんが、シーケンスはすぐに転換点に達します。 サインがゼロ付近で増加するという局所的な事実のみに基づいた不注意な構築は、引数がその間隔を離れると、静かに失敗する可能性があります。 サンプルの正しい出力は、次のような 1 つの可能なセットです。```
-2

最も危険な問題は、出力される整数の順序とツリーの構造を混同することです。 たとえば、印刷```
-17750000

## アプローチ

 直接的な総当たり戦略は、整数のコレクションを検索し、対応するデカルト ツリーを構築し、その高さが (n) であるかどうかを確認することです。 提案された 1 つのコレクションをチェックすることは効率的に実行できますが、可能性のあるコレクションのスペースを検索することは絶望的です。 (2^{32}) 個の可能な符号付き 32 ビット値があるため、順序を少し超えた (n) タプルを検索しても次の結果が得られます。 

[
 \binom{2^{32}}{n}
 】

 可能性。 (n=50000) の場合、これは計算限界を大幅に超えています。 開始値と正のステップに対するはるかに狭い総当たり検索でも、(n) 個の生成された値をチェックする前に、おおよそ (2^{32}\cdot 2^{32}) 個の候補ペアがあり、その後、候補ごとに (O(n)) 個の作業が続きます。 この問題には明らかに、検索ではなく数学的構築が必要です。 

有益な観察は、ツリーを明示的に構築する必要がないということです。 (x) 座標とその優先順位を一貫して順序付ける必要があるだけです。 したがって、問題は (\sin(x)) が厳密に増加する多くの整数 (x) を見つけることになります。 

正弦は区間上で厳密に増加します

 [
 \left[-\frac{\pi}{2},\frac{\pi}{2}\right]。 
】

 任意の実数を選択できる場合は、すべての (x) 値をこの間隔内に配置するだけです。 間隔が (50000) よりもはるかに短いため、整数値では十分な個別のポイントを得ることができません。 

これを回避する方法は、ピリオド (2\pi) を利用することです。 (2\pi) の倍数に非常に近い整数 (d) が必要です。 それから

 [
 d = 2\pi k+\デルタ
 】

 非常に小さな正 (\delta) の場合。 サインには周期 (2\pi) があるので、

 [
 \sin(id)=\sin(i\delta)。 
】

 したがって、大きな整数 (d) の倍数は、サインに関する限り、(\delta) の小さな倍数のように動作します。 

特に便利な選択は (d=710) です。 以来

 [
 113\cdot 2\pi \約 709.9999397、
 】

 私たちは持っています

 [
 710=113\cdot 2\pi+\デルタ
 】

 と

 [
 \デルタ\約 0.0000603。 
】

 (-25000) から (24999) までのすべての整数 (i) について、

 [
 i\デルタ
 】

 およそ (-1.5075) と (1.5074) の間に留まります。 両方のエンドポイントは厳密に ([-\pi/2,\pi/2]) の内側にあり、その境界は約 (1.5708) です。 その結果、正弦は、使用するすべての値を通して厳密に増加します。 

今、私たちは取ることができます

 [
 x_i=710i,\qquad -25000\le i\le24999。 
】

 (x_i) 値は厳密に増加しており、

また、絶対値が最大 (25000\cdot710=17,750,000) であるため、この構造は符号付き 32 ビット範囲内に安全に収まります。

 ## アルゴリズムのチュートリアル

 1. 必要なノード数 (n) を読み取ります。 
2. 固定ステップ (710) を使用します。 (i) 番目の答えを次のように書きます

 [
 x_i=(i-25000)\cdot710
 】

 (i=0,1,\ldots,n-1) の場合。 

連続する値は正確に (710) だけ異なるため、これにより個別の整数が得られます。 
3. (710=113\cdot2\pi+\delta) が小さな正 (\delta) であることを観察します。 したがって、

 [
 \sin(710k)=\sin(k\デルタ)。 
】

 使用する (k) の絶対値の最大値は (25000) であるため、(|k\delta|<\pi/2) となります。 正弦はこの区間全体で厳密に増加しています。 
4. (x_i) と (\sin(x_i)) は両方とも (i) とともに増加するため、最小のキーを持つ点の優先順位も最小になります。 これがルートとなり、1 つおきの点が二分探索ツリーの右側に位置します。 同じ引数を再帰的に適用すると、すべて (n) 個のノードを含む単一のパスが得られます。 
5. (n) 個の構築された整数を出力します。 この構造では (-17750000) から (17749290) までの値を使用するため、すべての答えは必要な 32 ビット符号付き範囲内に快適に収まります。

不変条件は、構造の接頭辞を選択した後、キーが厳密に増加し、その正弦値も厳密に増加するということです。 したがって、最小優先順位のポイントは常に左端のキーとなり、他のすべてのポイントはその右のサブツリーに属します。 そのルートを削除すると、残りの接尾辞にまったく同じプロパティが残るため、帰納法により (n) 個のノードのチェーンが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    base = -25000 * 710
    ans = []
    for i in range(n):
        ans.append(str(base + i * 710))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```表現`base + i * 710`まさに構造上の公式です。 (-25000\cdot710) から開始して乗数を 1 ずつ増やすと、次のシーケンスが得られます。 

[
 -25000\cdot710,,-24999\cdot710,\ldots
 】

 これは、完全な (50000) 要素構成に必要なプレフィックスです。 

コードでは Python 整数を使用しているため、問題自体は出力された値を符号付き 32 ビット整数に適合させる必要がありますが、オーバーフローは問題になりません。 実際の値は (1.8\times10^7) 程度であり、(2^{31}-1) よりはるかに低くなります。 

計算する必要はありません`sin`提出されたプログラムで。 浮動小数点の正弦値を計算すると、不必要な作業が追加され、証明に無関係な数値比較が発生する可能性があります。 (710) を選択する全体の目的は、数学的引数によって順序付けがすでに保証されていることです。 

出力順序は増加しています。 これは便利ですが、問題によっては必要ありません。 トレプは点の集合 ((x,\sin x)) によって定義されるため、同じ有効なキーの順列は同じデカルト ツリーを表します。

## テストケース

import io
import math

def solve_data(inp: str) -> str:

    n = int(data[0])

    base = -25000 * 710
    return "\n".join(str(base + i * 710) for i in range(n))

def run(inp: str) -> str:
    return solve_data(inp)

    assert len(set(values)) == n

## 特殊なケース

 (n=1) の場合、アルゴリズムは (-17750000) のみを出力します。 別のノードと比較するための順序付け条件がないため、結果として得られる treap は 1 つの頂点で構成され、高さは 1 になります。 

最大値 (n=50000) の場合、乗数の範囲は (-25000) ～ (24999) です。 対応するキーの範囲は (-17750000) ～ (17749290) です。 完全な周期を削除した後の正弦引数は、おおよそ (-1.5075) から (1.5074) までの範囲にありますが、厳密には正弦が増加する区間内にあります。 結果として得られる treap は、すべて (50000) ノードのパスです。 

(n) が十分に大きい場合、この構造は乗数 0 も通過します。 (k=0) では、キーは (0) で、優先度は (\sin(0)=0) です。 その近傍は小さな負と正の縮小角度に対応するため、それらの正弦値はそれぞれ小さく、大きくなります。 ゼロでは重複する優先度はありません。 

最後に、印刷されたキーが (710) の倍数であるという事実は、正弦値が等しくなるわけではありません。 全期間関係

 [
 \sin(710k)=\sin(k\デルタ)
 】

 問題は、厳密に増加する区間 ((-\pi/2,\pi/2)) 内の個別の (k\delta) 値に縮小されます。 乗数 (k) は個別であるため、その換算角も個別かつ順序付けされており、そのため、正弦値も個別かつ順序付けされています。 これは、最初は難しい treap 構築問題のように見えるものを、定数ステップの算術構築に変える特性です。
