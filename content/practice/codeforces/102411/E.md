 ## 解決策
 ## 問題の理解

 鉄道網は一本の木です。 各都市は頂点であり、各鉄道はエッジであり、1 つのエッジを通過するのに 1 時間かかります。 頂点のサブセットには、チームが所在する都市が含まれます。 すべてのチーム都市までのツリー距離がまったく同じである都市を見つける必要があります。 そのような都市が存在する場合は、有効な都市を 1 つ印刷できます。 

グラフがツリーであるという事実は、重要な構造特性です。 2 つの都市間には 1 本の経路が存在するため、距離や 2 つの経路が交わる場所について曖昧さはありません。 都市の数は (2 \cdot 10^5) に達し、チームの数も (2 \cdot 10^5) に達します。 2 秒の制限がある場合、(O(n^2)) または (O(nm)) アルゴリズムでは、最悪の場合、約 (4 \cdot 10^{10}) 回の演算が必要になりますが、これは現実的な値をはるかに超えています。 ツリーのサイズが線形に近いアルゴリズムが必要です。 

一見合理的と思われるソリューションが失敗する可能性のあるエッジケースがいくつかあります。 チームが 1 つしかない場合、比較する距離が 1 つだけあるという自明な意味でのみ、どの都市もその 1 つの都市から等距離にあるため、どの都市も有効です。 例えば、```
1 1
1
```答えがあります`YES`都市と`1`。 2 つのチーム都市を盲目的に取得するソリューションは、存在しない 2 番目の要素にアクセスすることになります。 

2 つのチームの場合、パスの長さは均等でなければなりません。 例えば、```
2 2
1 2
1 2
```チーム間にはエッジが 1 つしかないため、チーム間のちょうど中間にある頂点はありません。 正しい答えは、`NO`。 不用意な解決策では、距離に整数の除算を使用して 1 つのエンドポイントを選択する可能性がありますが、そのエンドポイントは、一方のチームからの距離が 0、もう一方のチームからの距離が 1 になります。 

少なくとも 3 つのチームがある場合、2 番目の失敗モードもあります。 最初の 2 チームだけをチェックするだけでは十分ではありません。 考慮する```
5 3
1 2
2 3
3 4
4 5
1 5 2
```最初の 2 チームは都市 1 と 5 にあるため、その中間点は都市 3 です。都市 1 と 5 までの距離はどちらも 2 ですが、都市 2 にある 3 番目のチームまでの距離はわずか 1 です。正解は次のとおりです。`NO`。 各チームに対する最終検証が不可欠です。 

## アプローチ

 直接的な総当たりソリューションでは、すべての都市を最終的な場所として試すことができます。 候補都市ごとに、ツリーを 1 回横断して距離を計算し、マークされたすべての都市の距離が同じかどうかを確認します。 1 回の横断には (O(n)) のコストがかかり、(n) 個の候補都市が存在する可能性があるため、(O(n^2)) 時間がかかります。 (n=2\cdot10^5) の場合、最悪の場合、これは約 (4\cdot10^{10}) 回の頂点訪問になります。 ブルートフォースは考えられるすべての答えを明示的にチェックするので正しいですが、遅すぎます。 

有益な観察は、2 つのチーム都市だけを考慮することで得られます。 有効な最終都市 (x) が存在し、2 つのチームが (a) と (b) にあると仮定します。 (d(x,a)=d(x,b)) であるため、(a) から (b) への一意のパスは (x) を通過する必要があり、そのパスの 2 つの部分は同じ長さでなければなりません。 したがって、(x) は (a) から (b) へのパスの正確な中間点です。 

これで候補者が完全に決まります。 (a)と(b)の間の距離が奇数の場合は、中点に頂点が存在しないため、直ちに答えは不可能になります。 距離が偶数の場合、中間頂点は 1 つだけ存在します。 1 回のツリー トラバースでそれを見つけ、すべてのチームがその頂点までの距離が同じであることを確認できます。 

ブルート フォース ソリューションは、考えられるすべてのセンターをテストするため機能しますが、センターが多すぎるために失敗します。 有効な中心はいずれも 2 つのチーム間のパスの中間点でなければならないという観察により、すべて (n) の都市から 1 つの候補への検索を減らし、その後 1 回の検証トラバースを行うことができます。 

1 つのチームでは利用可能なペアがないため、そのケースを個別に処理し、単純にチームの都市自体を返します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーとチーム都市のリストを読みます。 チームが 1 つしかない場合は、その都市をすぐに出力します。 距離は 1 つだけなので、他のチームと比較する必要はありません。 
2. 最初の 2 つのチーム都市を選択し、(a) と (b) と呼びます。 (a) でツリーをルートし、反復 DFS を実行して計算します。`parent[v]`そして`dist[v]`あらゆる都市に。 親配列は、すべての都市から (a) に戻る一意のパスを記録します。`dist[b]`(a) から (b) までのパスの長さを示します。 
3. (D=dist[b]) とします。 (D)が奇数の場合、出力`NO`。 奇数の長さのパスには頂点ではなく中央にエッジがあるため、両方の終点から同じ距離にある都市は存在しません。 
4. (D) が偶数の場合、(b) から開始して上に移動して中点を見つけます。`parent`ちょうど (D/2) 回です。 結果の都市を (x) と呼びます。 (a) と (b) の両方からの距離は正確に (D/2) です。 
5. (x) から開始して別のトラバースを実行し、(x) からすべての都市までの距離を計算します。 させて`target`(x) から最初のチームの都市までの距離になります。 
6. すべてのチーム都市を確認します。 (x) からの距離が異なる場合`target`、出力`NO`。 それ以外の場合は出力`YES`そして(x)。 
7. この検証の後、候補者が間違っているはずはありません。 有効な答えは、最初の 2 つのチーム都市の中間点でなければなりません。この中間点が残りのすべてのチームまで同じ距離であることを明示的に確認しました。 

これが機能する理由: 有効な都市 (y) が存在すると仮定します。 最初の 2 つのチーム都市 (a) と (b) の場合、等式 (d(y,a)=d(y,b)) により、(y) は独自のパス上に位置し、その中間点になります。 したがって、パスの長さが奇数の場合、有効な都市は存在しません。一方、パスの長さが偶数の場合、可能な唯一の答えはアルゴリズムによって構築された中点 (x) になります。 最後の走査では、すべてのチームの元の条件が正確にチェックされるため、アルゴリズムは、その一意の候補が有効である場合を正確に受け入れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    teams = list(map(int, input().split()))

    if m == 1:
        print("YES")
        print(teams[0])
        return

    a = teams[0]
    b = teams[1]

    parent = [0] * (n + 1)
    dist = [-1] * (n + 1)

    dist[a] = 0
    stack = [a]

    while stack:
        v = stack.pop()
        for u in graph[v]:
            if u == parent[v]:
                continue
            parent[u] = v
            dist[u] = dist[v] + 1
            stack.append(u)

    d = dist[b]

    if d % 2 == 1:
        print("NO")
        return

    center = b
    for _ in range(d // 2):
        center = parent[center]

    center_dist = [-1] * (n + 1)
    center_dist[center] = 0
    stack = [center]

    while stack:
        v = stack.pop()
        for u in graph[v]:
            if u == parent[v]:
                continue
            if center_dist[u] != -1:
                continue
            center_dist[u] = center_dist[v] + 1
            stack.append(u)

    target = center_dist[a]

    for city in teams:
        if center_dist[city] != target:
            print("NO")
            return

    print("YES")
    print(center)

if __name__ == "__main__":
    solve()
```最初の横断は最初のチームの都市に根ざしています。`dist[b]`最初の 2 チーム間の正確な距離を示します。`parent`彼らのユニークな道を逆向きに歩いてみましょう。 一方のエンドポイントがルートであるため、別の最下位共通祖先構造は必要ありません。そのため、もう一方のエンドポイントへのパス全体がすでに親チェーンに格納されています。 

中間点の計算には次のものを使用します。`d // 2`親が引っ越してくる`b`。 パスに長さ (d=2k) がある場合、都市`b`からの (2k) エッジです`a`、上方に (k) 個のエッジを移動すると、どちらかの端点に正確に (k) 個のエッジが残ります。 奇数長のパスには頂点の中点がないため、この計算の前に奇数距離のチェックを行う必要があります。 

2 番目のトラバースは、提案された中心から開始されます。 その目的は、別の候補を検索することではなく、元の状態を確認することだけです。 基準距離は次から取得できます。`a`、そしてどのチームもまさにその距離を持たなければなりません。 

トラバーサルは、再帰的 DFS ではなく明示的なスタックを使用して実装されます。 ツリーは (2\cdot10^5) 個の頂点のチェーンにすることができます。これは、再帰的 DFS が使用されている場合、Python の通常の再帰の深さを超えます。 明示的なスタックにより、この問題が回避されます。 

の`center_dist[u] != -1`2 番目のトラバーサルをチェックインすると、親に再度アクセスできなくなります。 最初のトラバースでチェックする`u == parent[v]`新しく到達した各頂点にはルート ツリー内の親が 1 つだけあるため、これで十分です。 

すべての距離は最大 (n-1) であるため、Python 整数はそれらを簡単に処理できます。 入力では 1 から始まる頂点番号が使用され、配列は次のように割り当てられるため、都市にインデックス変換は必要ありません。`n + 1`ポジション。

 ## 特殊なケース

 シングルチームのケースは、ペアベースの推論の前に処理されます。 のために```
1 1
1
```アルゴリズムが見る`m == 1`そしてすぐに印刷します`YES`そして`1`。 セカンド チームがないため、中間点を定義する必要はありません。 常に読まれるソリューション`teams[1]`ここで失敗するだろう。 

奇数距離の場合は、中間点の構築前に拒否されます。 のために```
2 2
1 2
1 2
```最初のトラバースで得られるのは`dist[2] = 1`。 以来`1 % 2 == 1`、アルゴリズムは出力します`NO`。 2 つのチーム都市の間には、整数値の都市はありません。 

最初のペアは有効に見えても、別のチームが中心にない場合は、2 番目のトラバーサルによって処理されます。 のために```
5 3
1 2
2 3
3 4
4 5
1 5 2
```1 から 5 までの距離は 4 であるため、アルゴリズムは都市 3 を選択します。都市 3 からの距離配列は次のようになります。`d(3,1)=2`、`d(3,5)=2`、 そして`d(3,2)=1`。 3 番目の値は基準距離 2 と異なるため、アルゴリズムは次のように出力します。`NO`。 これにより、候補の構築に使用されたペアのみをチェックするというよくある間違いを防ぐことができます。 

最大深さのツリーは、Python のもう 1 つの実用的なエッジ ケースです。 頂点が 200,000 個あるパスでは、再帰的 DFS が Python の再帰制限を超える可能性があります。 このソリューションでは両方の走査に明示的なスタックを使用するため、次のようなツリーが使用されます。```
1 - 2 - 3 - ... - 200000
```再帰なしで処理されます。 スタックには処理を待機している頂点が含まれており、親配列と距離配列には中間点フェーズと検証フェーズに必要なツリー情報が保持されます。 

最後に、大規模なチームの集合がすべて 1 つの都市から等距離にある可能性があります。 最大サイズのスターでは、都市 1 は他のすべての都市に直接接続されており、2 から 200,000 までのすべての都市にチームが含まれています。 最初の 2 チームは都市 1 を介して互いに距離 2 にあるため、中間点は都市 1 になります。2 番目のトラバースではすべてのチームまでの距離 1 が見つかり、すべての比較が成功します。 アルゴリズムは出力します`YES`そして`1`、チームの数によって線形の複雑さが変化しないことを示しています。
