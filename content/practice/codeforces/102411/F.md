 ## 問題の理解

 整数配列があります`a`長さの`n`そしてそれをターゲット配列に変換したいと考えています`b`。 印刷が許可されている唯一の命令は 2 つの特別な命令です。`foreach`ループします。 参照ループは、次の方法で配列の要素を記憶します。`⟦PROTECT_12⟧x`。 PHP では新しいスコープが導入されないため、`$x`、古い参照は 2 つのループ間で残ります。 この偶然に見える動作は、制限されたプログラムが配列を変更できるようにするメカニズムです。 

最初のいくつかの例を読めば、PHP 構文について考えることなく、その有益な効果が理解できるでしょう。 現在の配列に次のものが含まれているとします。`x`、最初の出現で停止する参照ループを実行します。`x`。`⟦PROTECT_13⟧x`最後の要素を参照するため、次の非参照ループは最後の要素を既存の値に置き換えることができます。 

配列には最大 50 個の要素があり、すべての値は 1 ～ 100 の範囲になります。`n`二次構造は完全に合理的になります。 アン`O(n^2)`アルゴリズムはせいぜい数千の基本スキャンを実行しますが、可能性のあるプログラムを介した指数関数的な検索では、すでに膨大な分岐要素が存在します。 出力自体には最大 10,000 行を含めることができるため、構築もその制限内に収まる必要があります。 

特に誤って対処しやすいケースが 2 つあります。 まず、最初に値が発生しなかった場合、その値はターゲットに表示されません。 例えば、```
2
1 2
1 3
```生産しなければならない```
-1
```値を作成できる操作は許可されていないため`3`。 

次に、ターゲットに個別の値のみが含まれており、最初の配列と異なる場合、変換は不可能です。 例えば、```
3
1 2 3
2 3 1
```にはすべて最初に発生するターゲット値がありますが、重要な操作では必ずどこかに重複した値が作成されます。 ターゲット自体が 3 つの異なる値を必要とする場合、そのような変更を行った後は最終状態に到達できません。 公式のソリューションは、まさにこの不可能性の基準を使用しています。 

ターゲットの最後の値が 1 回だけ発生する場合、微妙な境界のケースもあります。 最後の要素を一時ストレージとして使用する構造では、その値の唯一のコピーが誤って破壊される可能性があります。 このソリューションは、最初にターゲットを一時的に変更して、最後の値が 2 回目に出現するようにし、その変更されたターゲットに変換してから、変更された位置を復元することでこれを処理します。 

## アプローチ

 ブルートフォースアプローチでは、すべての合法な行を選択肢とみなし、ターゲットに到達するシーケンスを検索する可能性があります。 条件値は 1 ～ 100 の任意の整数にすることができ、ループは参照または非参照にすることができるため、各行には最大 200 個の可能な形式があります。 深くまで検索する`k`したがって、最悪の場合の分岐数は次のようになります。`200^k`、許可される深さは 10,000 に達する可能性があります。 たとえ小さな配列であっても、これは完全に不可能です。 

より有用な単純なアイデアは、すべての位置を独立して直接操作しようとすることです。 問題は、プリミティブ操作が任意のインデックスに対応していないことです。 これは、値の最初の出現、または最後の要素を扱います。 変更したい値が配列の前の方にある場合、おそらくローカルな操作によって間違った位置が変更されます。 構築では、最初にどの出現が最初であるかを制御する必要があります。 

重要な観察は、2 つの非常に単純な配列演算が奇妙な配列から構築できることです。`foreach`セマンティクス。 既存の値の最初の出現を置き換えることができます`x`別の既存の値による`y`。 最後の要素を既存の値に置き換えることもできます`y`。 これらの抽象演算のそれぞれに、ちょうど 2 つの印刷ループがかかります。 公式チュートリアルでは、同じ 2 つのプリミティブが特定されています。 

次に、配列を右から左に固定することを考えてみましょう。 位置決め時`i`から変更する必要があります`x`に`z`、まず、以前に発生したものをすべて削除します。`x`。 それがポジションを作る`i`最初の出来事`x`, そのため、最初に出現するプリミティブは正確にこの位置をアドレス指定できます。 一時的にコピーする`x`を最後の要素に挿入し、最初の要素を置き換えます`x`による`z`。 最後の要素は、移動する値の一時的なコピーとして機能します。 

唯一の危険は、最後の要素に格納されている値が失われることです。 処理するポジションが残っている場合は常に最後の値の重複を維持することで、これを回避します。 最後の値が 1 回だけ出現する場合は、続行する前に、その値を未処理のプレフィックス内の安全な位置にコピーします。 安全性テストでは、上書きされた値がまだどこかに存在しているか、サフィックスですでに修正されているか、または残りのターゲット プレフィックスで必要ないかどうかがチェックされます。 

最後の値自体が一意であり、他の場所で繰り返される値がある、扱いにくいターゲット ファミリが 1 つあります。 保存ロジックをターゲットの特別な配置に依存させるのではなく、ターゲットを一時的に変更できます。 繰り返される値を 1 つ取得し、それを一意の最後の値に置き換えます。 変更されたターゲットには、最後の値のコピーが 2 つあります。 変更されたターゲットに到達すると、変更された位置が最後の値の最初の出現となるため、最後の最初の出現操作によって元のターゲットが復元されます。 

ターゲットに繰り返し値がなく、ソースと異なる場合、不可能性テストはすでにそれを拒否します。

 ## アルゴリズムのチュートリアル

 1. 初期配列を読み取る`a`とターゲット配列`b`。 何らかの値が発生した場合`b`しかし決して発生しない`a`、どのプログラムもその値を作成できないため、印刷します`-1`。 
2. もし`a`すでに等しい`b`、ゼロ操作を出力します。 特別な処理は必要ありません。 
3. のすべての値が`b`が 1 回だけ発生すると、変換は拒否されます。 重要な操作では重複が作成されますが、要求された最終配列には重複はありません。 これが、この条件が次の場合にのみ関係する理由でもあります。`a != b`。 
4. 最後の値が`b`1 回だけ発生するため、一時的なターゲットを構築する`c`。 少なくとも 2 回出現する値を検索します。`b`、その出現を次のように置き換えます。`b[n-1]`。 繰り返される値がもう 1 つ出現する場合は、そのままにしておきます。 一時ターゲットには、最後の値のコピーが 2 つ含まれています。 
5. 2 つの抽象プリミティブを維持します。`first_to(x, y)`最初に出現したものを置き換えます`x`による`y`。`last_to(y)`最後の要素を次のように置き換えます`y`。 どちらも合法なので、`y`呼び出されたときに存在することが保証されます。 
6. からの位置を処理します`n-2`まで`0`。 最後の位置は一時的な保管場所であるため、意図的に最後まで残されます。 
7. もし`a[i]`すでに等しい`c[i]`、この位置は放っておいてください。 それ以外の場合は、`x = a[i]`そして`z = c[i]`。 
8. すべての出現箇所を削除します。`x`位置の前`i`。 そのような出現はそれぞれ、配列内にすでに存在する安全な値に置き換えられます。 最後の要素がそうでない場合は、`x`, its value is a convenient choice. 最後の要素が`x`、 それから`z`とは異なります`x`この立場は変える必要があるので、`z`代わりに使用できます。 
9. 結局のところ、以前のコピーは`x`いなくなった、位置`i`の最初の出現です`x`。 コピー`x`最後の位置に移動し、最初の位置を置き換えます`x`による`z`。 位置`i`現在は正しいですが、古いものは`x`最後までまだ利用可能です。 
10. 最後の値が一意になっている場合は、値を検索します`v`最後の値で安全に置き換えることができる、まだ処理されていないプレフィックス内。 別のコピーがプレフィックスに存在する場合、処理されたサフィックスにすでに存在する場合、または残りのターゲット プレフィックスのどこにも必要ない場合、値は安全です。 最後の値を最初に出現する次の値にコピーします。`v`。 最後の値には再び少なくとも 2 つのコピーが含まれます。 
11. 最後の要素より前のすべての位置が正しくなったら、最後の要素を次のように置き換えます。`c[n-1]`。 一時ターゲットは、この値がプレフィックス内のどこかで引き続き使用できるように構築されています。 
12. 一時的なターゲットが使用されていた場合は、変更されたターゲットの位置を復元します。 その時点で、一時値は元の最後の値の最初の出現となるため、単一の`first_to`操作により、元の目標値に戻ります。 

### なぜ効果があるのか

 中心的な不変条件は、既に右から左に処理されたすべての位置が一時ターゲットと等しく、未処理のプレフィックスまたは最終位置で必要なすべての値が配列内のどこかにまだ存在することです。 位置を変える前に`i`、現在の値の以前のコピーはすべて削除されるため、`i`が最初の出現になります。 これにより、最初に出現するプリミティブが意図した位置に正確に作用するようになります。 最後の要素は、移動される値の一時コピーを提供し、修復ステップにより、その一時コピーがまだ必要な値の唯一のコピーになるのを防ぎます。 プレフィックスが完了すると、最後の最後の要素の操作によって一時ターゲットが正確に生成され、オプションの復元によってそれが要求されたターゲットに変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_program(a, target):
    n = len(a)
    ops = []

    def first_to(x, y):
        if x == y:
            return
        p = a.index(x)
        ops.append(("ref", x))
        ops.append(("val", y))
        a[p] = y

    def last_to(y):
        if a[-1] == y:
            return

        # n <= 50 and all values are <= 100, so an absent
        # value among 1..100 always exists when this is needed.
        used = set(a)
        absent = next(v for v in range(1, 101) if v not in used)

        ops.append(("ref", absent))
        ops.append(("val", y))
        a[-1] = y

    for i in range(n - 2, -1, -1):
        if a[i] == target[i]:
            continue

        x = a[i]
        z = target[i]

        # Make i the first occurrence of x.
        while True:
            p = -1
            for j in range(i):
                if a[j] == x:
                    p = j
                    break

            if p == -1:
                break

            spare = a[-1]
            if spare == x:
                spare = z

            # z != x here, so spare is different from x.
            first_to(x, spare)

        # Preserve x at the last position, then make i correct.
        if a[-1] != x:
            last_to(x)

        first_to(x, z)

        # If the last value is unique, duplicate it somewhere safe
        # in the still-unprocessed prefix.
        if i > 0:
            last_value = a[-1]
            if a.count(last_value) == 1:
                prefix = a[:i]
                suffix = a[i + 1:]

                safe = None
                for v in prefix:
                    if v == last_value:
                        continue

                    cnt_prefix = prefix.count(v)
                    in_suffix = v in suffix
                    needed = v in target[:i]

                    if cnt_prefix >= 2 or in_suffix or not needed:
                        safe = v
                        break

                if safe is None:
                    # With the temporary-target construction below,
                    # this case cannot occur.
                    return None

                first_to(safe, last_value)

    # The last position was intentionally skipped.
    if a[-1] != target[-1]:
        last_to(target[-1])

    return ops

def solve_case(n, s, b):
    if s == b:
        return []

    if any(x not in set(s) for x in b):
        return None

    freq = {}
    for x in b:
        freq[x] = freq.get(x, 0) + 1

    if all(freq[x] == 1 for x in b):
        return None

    target = b[:]
    restore_pos = -1
    restore_value = -1

    # If the last target value is unique, temporarily make it
    # appear twice by replacing one occurrence of a repeated value.
    last_value = target[-1]

    if freq[last_value] == 1:
        repeated_pos = -1
        for i in range(n - 1):
            if freq[target[i]] >= 2:
                repeated_pos = i
                break

        if repeated_pos == -1:
            return None

        restore_pos = repeated_pos
        restore_value = target[repeated_pos]
        target[repeated_pos] = last_value

    a = s[:]
    ops = build_program(a, target)

    if ops is None:
        return None

    # Restore the temporary target modification.
    if restore_pos != -1:
        x = target[-1]
        y = restore_value

        # target[restore_pos] == x, and x was unique in the
        # original target. Hence restore_pos is the first x.
        if a[restore_pos] != x:
            return None

        ops.append(("ref", x))
        ops.append(("val", y))
        a[restore_pos] = y

    if a != b or len(ops) > 10000:
        return None

    return ops

def format_ops(ops):
    out = [str(len(ops))]
    for typ, value in ops:
        if typ == "ref":
            out.append(
                f"foreach ($a as &$x) if ($x == {value}) break;"
            )
        else:
            out.append(
                f"foreach ($a as  $x) if ($x == {value}) break;"
            )
    return "\n".join(out)

def solve():
    n = int(input())
    s = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ops = solve_case(n, s, b)

    if ops is None:
        print(-1)
        return

    print(format_ops(ops))

if __name__ == "__main__":
    solve()
```の`first_to`helper は、最初の抽象プリミティブの実装です。 最初に出力されたループは終了します`$x`最初のものを参照して`x`、そして 2 番目のループは、次のループに遭遇するまで歩きます。`y`、古い参照を通じて検出された各値を書き込みます。 結果として得られる参照要素は次のようになります。`y`。 

の`last_to`ヘルパーには、現在の配列では発生しない条件が必要です。 配列には最大 50 個の値が含まれますが、有効な範囲には 100 個の値が含まれるため、このような値は常に存在します。 その結果、参照ループは次のように正常に終了します。`$x`最後の配列要素を参照します。 次の非参照ループは、要求された値をその位置にコピーします。 

右から左へのループが構築の中心です。 の`while`ループは、現在の値の以前のコピーを削除して、目的の位置が最初に出現するようにします。 の選択`spare`意図的に異なるように作られています`x`そうでない場合、最初に発生する操作は進行しません。 

修復ステップでは、未処理のプレフィックスのみが処理されます。 別のコピーを持つ値は、1 つのオカレンスを安全に失う可能性があります。 処理されたサフィックスにすでに存在する値も、必要な最終出現がすでに修正されているため、安全です。 最後に、残りのターゲット プレフィックスに存在しない値は、そこでは必要なくなります。 

Python の整数はオーバーフローせず、関連する最大のコレクションはわずか 50 要素です。 潜在的に微妙な部分は、非参照ループ内の正確な間隔です。 このステートメントでは、間に 2 つのスペースが明示的に必要です。`as`そして`⟦PROTECT_14⟧a as  $x)`その空白を正規化するのではなく。 公式声明では、フォーマットの失敗は誤った回答として扱われます。

    a = a[:]

 ## 特殊なケース

 利用できない目標値の場合、次のようになります。```
2
1 2
1 3
```ソルバーは操作を試行する前にメンバーシップをチェックします。 以来`3`初期配列に存在しない場合は、すぐに返されます`-1`。 これにより、構築が、利用可能なはずのソース値が欠落している状態に達するのを防ぎます。 

単一要素の配列の場合、```
1
7
7
```答えはゼロオペレーションです。 もしターゲットが`8`、答えは次のようになります`-1`。 別の値のソースとして機能できる 2 番目の配列要素はなく、正当なループだけが単一の要素をそれ自体で書き換えることができます。 

すべての個別の値を含むターゲットの場合、```
3
1 2 3
2 3 1
```ソルバーはそれを即座に拒否します。 最初の重要な操作では、既存の値を別の位置にコピーして重複を作成しますが、要求されたターゲットには重複がありません。 これらの制限された操作を使用して、配列を完全に異なる順列に戻すことはできません。 

独自の最終目標値の場合、```
5
5 1 2 3 4
1 2 2 3 4
```値`4`最終目標位置でのみ発生します。 単純な一時ストレージ戦略では、唯一のストレージが上書きされる可能性があります。`4`そして後でそれを再作成する方法がないことがわかります。 ソルバーは、繰り返されるターゲット値の 1 回の発生を一時的に変更します。`2`の中へ`4`、補助ターゲットを生成します`[1, 4, 2, 3, 4]`。 最後の値には 2 つのコピーがあるため、一時ストレージとして安全に使用できます。 補助目標が達成されると、最初の`4`まさに一時的に変更された位置であり、`first_to(4, 2)`元のターゲットを復元します。 

交互の最大サイズの場合、```
50
1 2 1 2 1 2 ...
2 1 2 1 2 1 ...
```同じ最初の発生メカニズムが繰り返し実行されます。 値の以前のコピーは、目的の位置にアドレス指定する前に邪魔にならない場所に移動する必要があります。 これにより、公式解析で説明されている二次関数の動作が生成され、なぜ`O(n^2)`建設は自然な目標です`n = 50`。 

ちょっとした注意点: 上記の構造は公式の 2 プリミティブ戦略に従っており、保存の議論を単純化する一時ターゲットのバリアントが含まれています。 社説の重要な不変性と複雑さは公式分析と一致しています。
