 ## 解決策
 ## 問題の理解

 整数の中心を選択する必要があります`(X, Y)`整数の高さ`H`軸が揃った四角錐の場合。 どの面もちょうど傾斜があるので`45°`、中心から水平方向または垂直方向に 1 単位離れると、ピラミッドがちょうど 1 単位だけ下がります。 したがって、位置的には`(x, y)`、ピラミッドの高さは

 [
 H-\max(|x-X|,|y-Y|)。 
】

 オベリスク`(x_i, y_i, h_i)`高さがこの値を超えない場合に適合します。 タスクは、すべてのオベリスクを含む可能な限り最小の高さのピラミッドを見つけ、その最小値を達成する中心を出力することです。 

入力には最大でも次のものが含まれます`1000`オベリスク。 座標と高さは到達可能です`10^8`したがって、可能な座標を列挙することは完全に不可能です。 座標は大まかに指定できます`2 * 10^8`可能な値、おおよその値`4 * 10^16`可能性のあるセンター。 と`1000`オベリスク、すべてを確認するには約`4 * 10^19`初歩的なチェック。 ソリューションでは、入力を基本的に線形に処理する必要があります。 

整数の制限も重要です。 中心と高さは整数でなければならないため、連続的な幾何学的最適化だけでは十分ではありません。 幸いなことに、関連する制約はすべて整数間隔であるため、浮動小数点演算を行わずに正確な整数の最適値を取得できます。 

不注意な解決策が失敗する可能性があるいくつかのエッジケースがあります。 一本のオベリスクで、```
1
0 0 5
```答えは`0 0 5`。 中心を極端な座標の中間に盲目的に配置しようとする方法は、オベリスクの真下に中心を配置するのが最適であるにもかかわらず、誤って高さを増加させる可能性があります。 

さらに興味深い境界ケースは次のとおりです。```
2
0 0 1
2 0 1
```正しい答えは次のとおりです```
1 0 2
```ピラミッドには高さがあるので`2`、両方のオベリスクは中心からちょうど 1 単位です。 最適な中心の間隔は、単一の整数点で終了します。 包括的な不等式の代わりに厳密な不等式を使用すると、この解決策が誤って拒否されます。 

寸法が異なれば、必要な高さも異なる場合があります。 例えば、```
2
0 0 100
10 0 1
```最適な高さがある`100`、センター付き`(0, 0)`。 2 番目のオベリスクは遠くにありますが、非常に高い 1 番目のオベリスクが答えを支配します。 すべてのオベリスクを同じ高さであるかのように扱うと、間違った結果が生じます。 

最後に、大きな負の座標は、座標が非負であるという前提を持たずに処理する必要があります。 のために```
2
-100000000 -100000000 1
100000000 100000000 1
```最適な高さは`100000001`、 そして`(0, 0)`は有効なセンターです。 Python の整数はこの範囲を自然に処理しますが、固定幅の実装には十分な幅の整数型が必要です。 

## アプローチ

 直接的なアプローチでは候補センターを列挙することになる`(X, Y)`。 各中心について、必要な最小の高さは次のように計算できます。 

[
 \max_i\left(h_i+\max(|x_i-X|,|y_i-Y|)\right)。 
】

 これは正しいです。各オベリスクがその中心に必要な最小の高さを個別に示しているからです。 ただし、約`4 * 10^16`座標範囲内の整数の中心とチェック`1000`それぞれのオベリスクは大まかに与えます`4 * 10^19`最悪の場合の運用。 制限時間により、これは直ちに無効になります。 

有用な観察は内部に隠されています`max`。 書き換えることができます

 \max(h_i+|x_i-X|,\ h_i+|y_i-Y|)。 
】

 すべてのオベリスクの最大値を取ると、

 [
 H=
 \max\left(
 \max_i(h_i+|x_i-X|),
 \max_i(h_i+|y_i-Y|)
 \右）。 
】

 二つの座標は完全に分離してしまいました。 必要な最小の高さを独自に決定できます。`x`コーディネートと`y`座標を求め、2 つの高さのうち大きい方を採用します。 

1 つの次元だけを考えてみましょう。 私たちにはポジションがあります`c_i`、高さ`h_i`、最小の整数が必要です`H`整数の中心`C`満足する

 [
 h_i+|c_i-C|\le H
 】

 あらゆる人にとって`i`。 並べ替えると

 [
 c_i+h_i-H\le C\le c_i-h_i+H。 
】

 したがって、各オベリスクには許容間隔が与えられます。`C`。 これらの間隔に共通点がある場合、すべてのオベリスクを正確に満たすことができます。 

定義する

 [
 L=\max_i(c_i+h_i),
 \qquad
 R=\min_i(c_i-h_i)。 
】

 すべての区間を交差させた後、考えられる中心は正確に次のようになります。 

[
 [L-H、\ R+H]。 
】

 この間隔が空ではないのは、次の場合です。 

[
 L-H\le R+H、
 】

 または

 [
 2H\ge L-R。 
】

 したがって、この座標に必要な最小の整数の高さは次のようになります。 

[
 H_{\text{dim}}=\left\lceil\frac{L-R}{2}\right\rceil。 
】

 これを一度計算します。`x`そして一度だけ`y`。 ピラミッドは両方の寸法を満たす必要があるため、その最小高さはこれら 2 つの値の最大値になります。 その高さが判明すると、結果として得られる各間隔内の任意の整数点が有効な中心となります。 左側のエンドポイントを選択すると、`L-H`は便利で、丸めの問題を回避できます。 

ブルートフォースアプローチは、考えられるすべての中心を明示的に評価するため機能します。 座標空間が膨大なため失敗します。 という観察`max`独立して分離します`x`そして`y`これらの項は、幾何学的問題を 2 つの 1 次元区間交点に縮小し、それぞれを 1 パスで処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n · C²)`どこ`C`は座標範囲です |`O(n)`| 遅すぎる |
 | 最適 |`O(n)`|`O(n)`入力を保存するため、または`O(1)`それを超えて | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのオベリスクを読みます。 のために`x`次元、計算

 [
 L_x=\max_i(x_i+h_i)
 】

 そして

 [
 R_x=\min_i(x_i-h_i)。 
】

 これら 2 つの値は、ピラミッドの高さが固定された後のすべての可能な中心間隔の交差を表します。 
2. の同じ量を計算します。`y`寸法:

 [
 L_y=\max_i(y_i+h_i),
 \qquad
 R_y=\min_i(y_i-h_i)。 
】

 ピラミッドに必要な高さは 2 つの座標の要件の最大値であるため、2 つの次元は独立して処理できます。 
3. 必要な最小高さを見つけます。`x`寸法:

 [
 H_x=\left\lceil\frac{L_x-R_x}{2}\right\rceil。 
】

 整数値の場合、これは次のように計算されます。`(L_x - R_x + 1) // 2`。 
4. に対応する値を見つけます。`y`寸法:

 [
 H_y=\left\lceil\frac{L_y-R_y}{2}\right\rceil。 
】
 5.セット

 [
 H=\max(H_x,H_y)。 
】

 この高さは両方の次元にとって十分ですが、2 つの次元のうちの 1 つですでに少なくともこの高さが必要であるため、これを減らすことはできません。 
6.選択します

 [
 X=L_x-H、
 \qquad
 Y=L_y-H。 
]

以来`H >= H_x`そして`H >= H_y`、これらの値はそれぞれの実行可能な間隔に属します。 関係するすべての量が整数であるため、これらは整数です。 
7. 出力`X`、`Y`、 そして`H`。 結果として得られるピラミッドにはすべてのオベリスクが含まれており、高さがこれより低いピラミッドにはすべてのオベリスクを含めることはできません。 

### なぜ効果があるのか

 任意の固定高さの場合`H`、オベリスク`(c_i,h_i)`1 次元では中心間隔が正確に許容されます`[c_i+h_i-H, c_i-h_i+H]`。 これらすべての間隔の交差点は、`[L-H,R+H]`、したがって、有効な中心はまさに次のときに存在します。`2H >= L-R`。 したがって、`H_x`そして`H_y`は、2 つの座標によって強制される正確な最小の高さです。 

完全なピラミッドでは、両方の 1 次元の不等式が同時に必要になります。 高さ要件は独立した最大値であるため、`x`そして`y`要件を満たすと、全体的な最適値は正確に`max(H_x,H_y)`。 選択する`L_x-H`そして`L_y-H`両方の実行可能な交差点の内側に中心を配置するため、高さは最小限でありながらすべてのオベリスクが含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lx = -10**30
    rx = 10**30
    ly = -10**30
    ry = 10**30

    for _ in range(n):
        x, y, h = map(int, input().split())

        lx = max(lx, x + h)
        rx = min(rx, x - h)

        ly = max(ly, y + h)
        ry = min(ry, y - h)

    hx = (lx - rx + 1) // 2
    hy = (ly - ry + 1) // 2

    H = max(hx, hy)

    X = lx - H
    Y = ly - H

    print(X, Y, H)

if __name__ == "__main__":
    solve()
```4 つの変数`lx`、`rx`、`ly`、 そして`ry`区間の交差に必要な極値を維持します。 例えば、`lx`最大のものを保管する`x_i + h_i`、すべての実行可能な中心は少なくとも`x_i + h_i - H`。 

表現`x + h`そして`x - h`という順序で保管する必要があります。 それらの 1 つを反転すると、実行可能な区間のどちら側が表現されるかが変わり、不正確な中心が表示されます。 

天井部門もオフバイワンエラーが発生しやすい場所です。 非負の整数の場合`d`、`ceil(d / 2)`は`(d + 1) // 2`。 ここ`L - R`すべてのオベリスクについて、`x_i + h_i > x_i - h_i`、同じ順序が最大値と最小値を取得して存続します。 

浮動小数点計算はありません。 正確な整数ジオメトリで十分であり、Python の任意精度の整数はすべての中間値を快適に処理します。 関連する最大の式は次のとおりです。`2 * 10^8`したがって、固定幅整数を使用する言語では、符号付き 64 ビット整数でも十分です。 

コードではオベリスクを保存する必要はありません。 それぞれは 4 つの実行極値にのみ寄与するため、実装は単一パスで入力を処理できます。 

## 実用的な例

 ### サンプル 1

 入力には 1 つのオベリスクが含まれています`(0,0)`高さのある`5`。 

| 変数 | オベリスクを読んだ後 |
 | --- | --- |
 |`lx`|`5`|
 |`rx`|`-5`|
 |`ly`|`5`|
 |`ry`|`-5`|
 |`hx`|`5`|
 |`hy`|`5`|
 |`H`|`5`|
 |`X`|`0`|

 実行可能な間隔は、`x`高さの中心`5`は`[5-5,-5+5] = [0,0]`、同様のことが当てはまります`y`。 したがって、センターは強制的に`(0,0)`、ピラミッドには高さがあります`5`。 

### サンプル 2

 オベリスクは、`(3,3,3)`そして`(6,6,2)`。 

| オベリスク |`x+h`|`x-h`|`y+h`|`y-h`|
 | --- | --- | --- | --- | --- |
 |`(3,3,3)`|`6`|`0`|`6`|`0`|
 |`(6,6,2)`|`8`|`4`|`8`|`4`|

 両方のオベリスクを終えたら、`lx = 8`、`rx = 0`、`ly = 8`、 そして`ry = 0`。 

| 変数 | 値 |
 | --- | --- |
 |`hx`|`(8-0+1)//2 = 4`|
 |`hy`|`(8-0+1)//2 = 4`|
 |`H`|`4`|
 |`X`|`8-4 = 4`|
 |`Y`|`8-4 = 4`|

 で`(4,4)`、最初のオベリスクは両方の座標で 1 単位離れているため、ピラミッドの高さは`4-1=3`。 2 つ目は 2 単位離れているため、利用可能な高さは次のとおりです。`4-2=2`。 どちらも正確にサポートされており、必要な出力が得られます。`4 4 4`。

 ## 特殊なケース

 単一オベリスクの場合```
1
0 0 5
```生成する`lx = ly = 5`そして`rx = ry = -5`。 両方の 1 次元の最小高さは次のとおりです。`(5 - (-5) + 1) // 2 = 5`。 選ばれたセンターは`5 - 5 = 0`両方の次元で、`0 0 5`。 このアルゴリズムは、間隔を形成するために複数のオベリスクがあることに依存しません。 

正確な境界の場合```
2
0 0 1
2 0 1
```与える`lx = 3`そして`rx = -1`。 必要な`x`身長は`(3 - (-1) + 1) // 2 = 2`。 高所で`2`、実現可能`x`間隔は`[3-2,-1+2] = [1,1]`、したがって、可能な中心は次のとおりです。`X=1`。 の`y`寸法には高さだけが必要です`1`なので、最終的な高さは残ります。`2`。 これにより、フロア分割を誤って使用する実装が捕捉されます。 

高さが不等な場合```
2
0 0 100
10 0 1
```の`x`極値は`100`そして`-100`、高さが必要です`100`、一方、`y`極値も`100`そして`-100`ですが、結果の中心の計算は次のようになります。`(0,0)`。 その中心で最初のオベリスクが正確な高さに達します`100`、2番目には利用可能な高さがあります`90`、必要な高さをはるかに超えています`1`。 高いオベリスクが最小値を決定します。 

座標境界の場合```
2
-100000000 -100000000 1
100000000 100000000 1
```私たちは得ます`L_x = L_y = 100000001`そして`R_x = R_y = -100000001`。 したがって`H = (100000001 - (-100000001) + 1) // 2 = 100000001`。 選ばれたセンターは`0,0`。 それぞれのオベリスクはまさに`100000000`高さはそのままにして、関連する座標で単位を離す`1`したがって、両方が境界に正確に含まれます。 

最大サイズのテスト`1000`同一のオベリスクは、数学的構造を変更せずに入力境界を実行します。 最初のオベリスク以降、更新のたびに 4 つの極値が変更されないため、最終的な答えは変わりません。 これは、繰り返されるポイントに特別な処理が必要ない理由と、リニア スキャンの効率性が維持される理由を示しています。
