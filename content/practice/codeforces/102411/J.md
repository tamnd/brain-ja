 ## 問題の理解

 この丘は、頂点がスポット (1,\ldots,n) である有向非巡回グラフとして見ることができます。 すべてのトレイルは小さいインデックスから大きいインデックスに進むため、頂点の番号付け自体がトポロジー的な順序を与えます。 

すべてのペア (i<j) について、入力は (i) から (j) への有向パスの数の最後の 10 進数のみを与えます。 トレイル (i\to j) 自体がパスですが、中間の頂点を通過することでより長いパスが得られます。 タスクは、すべての可能な有向エッジが存在するかどうかを回復することです。 

有用な区別は、(i) から (j) に直接進むパスと、最初に何らかの中間頂点 (k) を訪れるパスとの間の区別です。 (i<k<j) のすべてのエッジ (i\から k) がすでにわかっている場合、(i) から (j) までの間接パスの数は次のようになります。 

[
 \sum_{i<k<j} E_{i,k}P_{k,j},
 ]

 ここで、(E_{i,k}) は (0) または (1) のいずれかであり、(P_{k,j}) は (k) から (j) までのパスの総数です。 (P_{k,j}) モジュロ (10) しかわかりませんが、最終的な答えもモジュロ (10) の値にのみ依存するため、これで十分です。 

境界 (n\le 500) は十分に大きいため、すべての可能なパスを列挙することは完全に不可能です。 すべてのトリプル ((i,k,j)) を検査するはるかに優れた動的再帰でも、

 [
 \frac{n(n-1)(n-2)}6
 ]

 内部反復回数は、(n=500) の場合、約 2,070 万回です。 最適化された C++ ではこれは合理的ですが、数百万ものネストされた解釈操作を実行する Python 実装では、制限時間に不必要に近づく可能性があります。 わずか 10 桁の固定 10 進アルファベットを使用して、高価な部分をおよそ (10\binom n2) ビットの演算に削減します。 

単純な実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 1 つ目は隣接するペアです。 (j=i+1) の場合、中間頂点がないため、間接パスの合計は正確にゼロになります。 例えば、```
2
01
00
```頂点 (1) から頂点 (2) までのパスが 1 つあるため、答えは次のようになります。```
01
00
```無効な中間インデックスに誤ってアクセスする実装は、ここで失敗する可能性があります。 

2 番目のエッジ ケースはモジュラー ラップアラウンドです。 最後の桁が 0 であっても、必ずしも直接エッジが存在しないことを意味するわけではありません。 9 つの間接パスと 1 つの直接パスがあり、合計 10 のパスが存在します。 たとえば、次の有効なグラフには直接エッジ (1\to6) がありますが、(1) から (6) までの正確に 10 個のパスがあります。```
6
012350
001124
000112
000001
000001
000000
```その正しい出力は次のとおりです```
011111
001011
000100
000011
000001
000000
```入力の位置 ((1,6)) にゼロが含まれていますが、エッジ (1\to6) が存在します。 9 つの間接パスを考慮せずに入力ゼロを「エッジなし」と解釈するソリューションでは、この問題が発生します。 

3 番目のエッジ ケースは、入力行列に隣接情報ではなくパス カウントが含まれる場合です。 たとえば、(i\to k) が存在し、(k) から (j) までの 2 つのパスがある場合、これら 2 つのパスは (i) から (j) までの間接カウントに寄与する必要があります。 元の入力数字を (E_{i,k}) を直接表すかのように使用すると、2 つの異なる量が混合されます。 

## アプローチ

 直接的な総当たりアプローチは、パス分解を正確にたどります。 ペア ((i,j)) を距離を増加しながら処理します。 各ペアについて、すべての中間値 (k) を列挙し、(E_{i,k}P_{k,j}) を加算し、結果を指定された最後の桁と比較します。 (k<j) のすべての (E_{i,k}) が既に復元されているため、これは正しいです。 

より正確には、(S) が (i) から (j) への間接パスの数である場合、

 [
 P_{i,j}\equiv S+E_{i,j}\pmod {10}。 
]

 (E_{i,j}) は 0 または 1 のみであるため、エッジは正確に次のときに存在します。 

[
 (S+1)\bmod 10=P_{i,j}。 
]

 最も内側の反復回数は次のとおりです。 

\frac{n(n-1)(n-2)}6.
 ]

 (n=500) では、(20,708,500) 回の反復になります。 漸化式は数学的に単純であり、問​​題の標準的に受け入れられている三次定式化です。 

グラフが DAG であるため、総当たり再帰が機能します。 すべての短い間隔が処理されると、考えられるすべての最初の中間頂点 (k) にはすでに再構築されたエッジ (i\to k) があり、パス カウント (P_{k,j}) は入力にすでに存在します。 

Python の問題は数学ではなく、数千万のネストされた操作を実行するコストです。 計算を大幅に安価にする観察結果は、すべての (P_{k,j}) がわずか 10 桁の 1 つであるということです。 固定された宛先 (j) と数字 (d) の場合、(P_{k,j}=d) となる頂点 (k) を正確に含むビットセットを保存できます。 

固定ソース (i) の場合、既に再構築された出力エッジ (i\to k) を含む別のビットセットを維持します。 この場合、両方の条件を満たす中間頂点の数は、単純にビット交差の後に次のものが続きます。`bit_count()`。 

もし`edges`(E_{i,k}=1) の既知の頂点 (k) が含まれており、`mask[j][d]`(j) までのパス カウントの桁が (d) に等しい頂点が含まれている場合、

 \sum_{d=0}^{9}
 d\cdot
 \オペレーター名{ポップカウント}
 \左(
 \text{エッジ}\mathbin{&}\text{マスク}[j][d]
 \右）。 
]

 Python の整数は、最適化されたネイティブ コードで任意の長さのビットセットを実装するため、これらの交差と母数のカウントは、すべて (k) で明示的にループするよりもはるかに安価です。 

重要な構造上の事実は、(j) を左から右に処理する際に、`edges`(j) より小さい頂点のみが含まれます。 したがって、範囲 (i<k<j) を明示的にマスクする必要はありません。 再構築の順序によって、その制限が自動的に提供されます。

 ## アルゴリズムのチュートリアル

 1. 最後の桁のマトリックスを読み取り、変更しないでください。 これはグラフ自体ではなく (P_{i,j}\bmod 10) を表すため、新しいエッジを決定するときは常に利用可能な状態にしておく必要があります。 
2. すべての宛先 (j) に対して 10 個のビットマスクを作成します。 位置 (k) のビットは次のように設定されます。`mask[j][d]`まさに、(k) から (j) までのパスの数が数字 (d) で終わることが入力で示されているときです。 (k<j) のみを保存する必要があります。 
3. 最初は空の隣接行列を作成し、ソース頂点 (i) を左から右に処理します。 各固定 (i) について、単一の整数を維持します`edge_mask`。 直接エッジ (i\to k) がすでに確立されている場合、その (k) 番目のビットは 1 になります。 
4. すべての宛先 (j>i) について、(i) から (j) への間接パスの数を計算します。 各桁 (d) の交差`edge_mask`と`mask[j][d]`。 母集団数は、(i\to k) がエッジであり、(P_{k,j}) が最後の桁 (d) を持つ中間頂点 (k) の数を示します。 そのカウントに (d) を掛けて、間接合計に加算します。 
5. 間接合計モジュロ (10) を減らします。 直接のエッジがない場合、観察される数字はこの値に等しい必要があります。 直接エッジが存在する場合、観察される数字は間接値に 1 を法 (10) 加えた値に等しくなければなりません。 有効な入力が保証されているため、エッジは正確に存在します。 

[
 (\text{間接}+1)\bmod 10=P_{i,j}。 
]

 1. エッジが存在する場合は、ビット (j) を設定します。`edge_mask`ペア((i,j))を決定した直後。 直接エッジ (i\to j) は (i) から (j) へのパスの中間エッジではないため、(j) の計算の前に挿入してはなりません。 
2. (i) のすべての宛先を処理した後、隣接行列の対応する行を出力します。 すべてのソース頂点に対して繰り返します。 

不変条件は、ペア ((i,j)) を処理する直前に、`edge_mask`(i<k<j) の直接エッジ (i\to k) が正確に含まれます。 したがって、(i) から (j) までのすべての間接パスは一意の最初のエッジ (i\to k) を持ち、(k) から (j) に続くすべてのパスは (P_{k,j}) によってカウントされます。 それらの合計は、直接エッジ (i\to j) を使用しないパスの数と正確に一致します。 1 を追加すると直接エッジが考慮されるため、観察された最後の桁との比較により、そのエッジが存在するかどうかが一意に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [input().strip() for _ in range(n)]

    # masks[j][d] has bit k set iff p[k][j] == digit d.
    masks = [[0] * 10 for _ in range(n)]

    for k in range(n):
        bit = 1 << k
        row = p[k]
        for j in range(k + 1, n):
            masks[j][ord(row[j]) - 48] |= bit

    ans = [bytearray(n) for _ in range(n)]

    for i in range(n - 1):
        edge_mask = 0
        row = ans[i]

        for j in range(i + 1, n):
            col_masks = masks[j]

            indirect = 0
            for d in range(1, 10):
                indirect += d * (edge_mask & col_masks[d]).bit_count()

            given = ord(p[i][j]) - 48

            if (indirect + 1) % 10 == given:
                row[j] = 1
                edge_mask |= 1 << j

    sys.stdout.write(
        '\n'.join(''.join('1' if x else '0' for x in row) for row in ans)
    )

if __name__ == "__main__":
    solve()
```最初のループは数字マスクを構築します。 固定された中間頂点 (k) の場合、`bit = 1 << k`行全体で再利用されるため、繰り返しのシフトが回避されます。 ループは次から始まります`k + 1`なぜなら、対角線以下のエントリはゼロであることが保証されており、順方向パスの中間頂点になることはあり得ないからです。 

第 2 フェーズではグラフを再構築します。`edge_mask`は、そのソースから出るエッジのみを表すため、ソース (i) ごとにリセットされます。 宛先 (j) は昇順に処理されるため、宛先 (j) にすでに存在するすべてのビットが処理されます。`edge_mask`有効な中間頂点に対応します。 

表現```
(edge_mask & col_masks[d]).bit_count()
```は、(k) のループ全体の最適化された置換です。 交差部分は、(E_{i,k}=1) と (P_{k,j}\equiv d\pmod{10}) の両方を満たす (k) を正確に保持します。 

数字のゼロは、合計への寄与がゼロであるため、処理する必要はありません。 ゼロのマスクは表現を完全にし、構築を単純に保つため、依然として構築されています。 

ダイレクトエッジが挿入されます`edge_mask`((i,j)) を決定した後でのみ。 計算の前にその操作を移動すると、直接エッジが中間頂点として誤ってカウントされます。 

Python では整数オーバーフローの問題はありません。 間接合計が 10 を超える場合でも、重要なのは 10 を法としたその値のみです。 この実装では、簡単にするために完全な小さい合計を保持し、1 つのペアに対して最大 (9(n-2)) が追加されます。

 (0+1)\bmod10\ne0,
 ]

 エッジがありません。 結果として得られる行列はすべてゼロのままです。 

最も欺瞞的なケースは、モジュラー ラップアラウンドです。 考慮する```
6

```(1\to6) の場合、既に再構築されたエッジは (1\to2,1\to3,1\to4,1\to5) です。 彼らの貢献は、

 [
 P_{2,6}=4,\qquad
 P_{3,6}=2,\qquad
 P_{4,6}=2,\qquad
 P_{5,6}=1。 
]

 間接合計は (9) です。 観測された桁は 0 ですが、直接エッジを追加すると 10 個のパスが生成されるため、正しい決定は (E_{1,6}=1) になります。 アルゴリズムのテスト`(9 + 1) % 10 == 0`そしてそのエッジを正しく回復します。 

最後に、再建命令が不可欠です。 (E_{i,j}) を決定するとき、(k<j) のエッジ (E_{i,k}) のみが間接パスの合計に参加することが許可されます。 (j) を左から右に処理すると、すべてのビットが`edge_mask`は、すでに確立されているエッジと、現在の候補エッジ (i\to j) が誤ってそれ自体の中間寄与としてカウントされていないことを表します。
