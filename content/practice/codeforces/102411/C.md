 ## 解決策
 ## 問題の理解

 ファブリックは、セルの長方形グリッドです。 マークされたすべてのセル`X`表側で十字を受け取る必要があります。つまり、そのセルの両方の対角線をステッチする必要があります。 糸は連続した 1 本の糸であるため、1 つの表側の対角線を終了した後、針は裏側を通って別の表側の対角線の開始点まで移動し、その後表側に戻るという手順を繰り返す必要があります。 

出力は一連のグリッド点です。 連続した点は 1 つのステッチを表し、1 番目、3 番目、5 番目、その他の奇数番目のステッチが表側にあり、交互のステッチが裏側にあります。 フロントサイドセグメントは、必要なすべての十字を正確に 1 回描画する必要があります。 裏側のセグメントは繰り返すことができるので、本当に難しいのは、長さゼロのステッチを作成せずに 1 つの交互の糸に結合できるすべての表側の対角線の順序を見つけることです。 必要な座標は、境界点を含むグリッドの交点です。`(0, 0)`を通して`(w, h)`。 

寸法は満たしています`1 <= w, h <= 100`, したがって、最大でも`10000`細胞なのでせいぜい`10000`十字架。 受け入れられているソリューションは、すべてのセルを一定回数快適に処理できます。 ここでは二次アルゴリズムも無害ですが、交差の数が指数関数的に増加するものは完全に実行不可能です。 特に、答えにはほとんどのものが含まれる可能性があります。`40000`したがって、構造自体はセルの数において線形である必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 十字が 1 つあるだけで、答えはすでに自明ではありません。```
1 1
X
```十字が1本、前斜めが2本必要なので、少なくとも3針必要です。 最適な答えは、`3`ステッチではなく、`2`2 つの前面対角線は 1 つの背面セグメントで区切られている必要があるためです。 

クロスはコーナーでのみ他のクロスに接触することもあります。 例えば、```
2 2
X.
.X
```2 つの十字が 8 接続されているため、 は有効です。 通常の 4 方向接続を想定した構造では、これらの十字が別個のコンポーネントとして誤って扱われてしまいます。 

境界上の十字は、座標誤差のもう 1 つの一般的な原因です。```
1 1
X
```4 隅の座標をすべて使用します`(0,0)`、`(1,0)`、`(0,1)`、 そして`(1,1)`。 座標はセルの中心ではなくグリッド点を参照するため、番号を付ける実装は`w * h`の代わりにセル`(w+1) * (h+1)`グリッド ポイントは無効なエンドポイントを生成します。 

最後に、1 つのセルの 2 つの対角線が両方とも前面に表示される必要があります。 あらゆる場所を訪れるだけの建設`X`1 つのセルが 2 つの異なるフロントサイド セグメントに寄与するため、セル 1 回だけでは不十分です。 上記の単一セルの例では、正しい出力は 3 つのステッチで始まり、両方の対角線が最初と 3 番目のセグメントの間に発生する必要があります。 

## アプローチ

 直接的な総当たりアプローチは、以下をリストすることから始まります。`2k`必須の前対角線、ここで`k`の数です`X`細胞。 次に、それらの対角線のすべての順序を試し、連続する対角線が有効な裏側ステッチで接続できるかどうかを確認できます。 これは正しいです。なぜなら、最適解は正面の対角線を繰り返すことができないため、すべての要素のいくつかの順列が必要になるからです。`2k`対角線は、考えられるすべての最適な順序を表します。 

問題は順列の数です。 がある`(2k)!`可能な注文、および 1 つの注文を確認するのに時間がかかります`O(k)`時間。 結果として生じる複雑さは、`Theta(k * (2k)!)`。 最大でも`k = 10000`、これはリモートで計算できません。 ブルート フォースは、出現する必要があるオブジェクトを正確に考慮するため機能しますが、オブジェクトの順序を無制限の組み合わせ問題として扱うため、失敗します。 

重要な観察点は、それぞれが`X`セルは、その 2 つの前面対角線だけでなく、慎重に選択された 2 つの背面エッジにも寄与できます。 角のあるセルを考えてみましょう`A`左上に、`B`右上に、`C`左下にあり、そして`D`右下にあります。 2つの対角線を置きます`A-D`そして`C-B`正面のグラフに。 2つの垂直辺を置きます`A-C`そして`B-D`裏側のグラフに。 

このセルのすべての角について、ちょうど 1 つの前端と 1 つの後端がその角に接触します。 したがって、4 つのエッジは交互のサイクルを形成します。```
A --front-- D
|           |
back       back
|           |
C --front-- B
```複数のとき`X`セルが存在する場合、これらの小さな 4 エッジ サイクルを単純にオーバーレイします。 十字は 8 接続されているため、同じ接続パターンに属する 2 つのセルは辺を共有するか、角で接触します。 対応する 4 エッジ サイクルは、少なくとも 1 つの格子点を共有します。 その結果、構築されたグラフ全体が接続されます。 

もう 1 つ便利なプロパティがあります。 すべてのグリッド点で、入射する前側エッジの数は入射する後側エッジの数と等しくなります。 その点に接触するすべてのセルは、各タイプのエッジを 1 つだけ提供します。 これは、一方のタイプのエッジを使用して交互トラバーサルが頂点に入るたびに、ローカル サイクルが完了するまで、もう一方のタイプの未使用のエッジが使用可能であることを意味します。 

したがって、表側のグラフと裏側のグラフを交互に切り替えながら、オイラー スタイルのトラバーサルを実行できます。 トラバースでは、構築されたすべてのエッジが 1 回だけ使用されます。 最後のエッジはサイクルを終了して開始点に戻りますが、その終了エッジを出力する必要はないため、ステッチ数は構築されたエッジの総数より 1 つ減ります。 

それぞれ`X`2 つの前面エッジと 2 つの背面エッジが寄与し、4 つのグラフ エッジが得られます。 のために`k`十字架、あるよ`4k`エッジがあるため、生成された糸には次のものが必要です`4k - 1`ステッチ。 

これも最適です。 すべての十字には 2 つの異なる正面対角線が必要です。`2k`フロントステッチ。 完全なスレッドに次の内容が含まれている場合、`n`ステッチして前面から始めます。`ceil(n / 2)`フロントセグメント。 したがって、`ceil(n / 2) >= 2k`そしてその結果として`n >= 4k - 1`。 私たちの構築はまさにこの下限に達します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |`Theta(k * (2k)!)`|`O(k)`| 遅すぎる |
 | 最適 |`O(wh)`|`O(wh)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての格子点に整数 ID を割り当てます。`(x, y)`すべての細胞ではありません。 がある`(w + 1)(h + 1)`セルの角がすべてのステッチの開始点と終了点となるため、このような点が重要になります。 
2. を含むすべてのセルに対して、`X`、その 2 つの対角線を前面のグラフに追加します。 角が`(x, y)`、`(x+1, y)`、`(x, y+1)`、 そして`(x+1, y+1)`、前端は 2 つのセグメントです`(x, y) -> (x+1, y+1)`そして`(x+1, y) -> (x, y+1)`。 
3. 同じセルについて、その 2 つの垂直辺を裏面グラフに追加します。 これらは`(x, y) -> (x, y+1)`そして`(x+1, y) -> (x+1, y+1)`。 垂直側面の選択は精神的に任意ですが、この特定の選択により、すべての角にちょうど 1 つの前面エッジと 1 つの背面エッジが与えられます。 
4. に属する任意のグリッド点から開始します。`X`細胞。 トラバース中に、現在の頂点と次に使用する必要があるエッジ タイプを保持します。 現在のタイプがフロントの場合は、未使用の前エッジを選択します。 取得後は裏側のグラフに切り替えます。 現在のタイプが背面の場合は、その逆を実行します。 
5. Hierholzer のオイラー ツアー手法を使用します。 未使用のエッジが利用可能な場合は、すぐにそれに従うようにしてください。 現在の頂点に必要なタイプのエッジが残っていない場合は、その頂点をトラバーサル スタックから削除して記録します。 バックトラック中に頂点を記録すると、ローカル オイラー構造が必要な連続シーケンスに反転されます。 
6. 印刷する前に、記録された頂点を反転します。 結果として得られる連続したペアは、まさに`4k - 1`ステッチ。 最初のペアは前面の対角線、2 番目のペアは背面のエッジで、パリティはシーケンス全体で交互になります。 

交互トラバーサルが誤ってスタックしない理由は、すべての頂点における表側次数と裏側次数が等しいためです。 フロントエッジを使用して頂点に到達するとします。 その頂点における未使用のフロント エッジと未使用のバックサイド エッジの数は、トラバースが進むにつれてロックステップで変化します。 したがって、交互ツアーを継続する必要がある場合はいつでも、未使用の裏側エッジを利用できます。 同じ議論が 2 つのエッジ タイプを交換する場合にも当てはまります。 

### なぜ効果があるのか

 すべての前面エッジと背面エッジによって形成されるグラフを考えてみましょう。 毎`X`4 エッジの交互サイクルに寄与するため、すべてのグリッド点で、入射する前側エッジの数は入射する後側エッジの数と等しくなります。 入力クロスは 8 接続されているため、これらのローカル サイクルの和集合が接続されます。 したがって、交互の Hierholzer トラバーサルでは、構築されたすべてのエッジが 1 回だけ使用され、開始点に戻ります。 最後の閉じエッジを削除すると、すべての前対角線を 1 回だけ含む単一のシーケンスが残り、連続する前エッジの間に後側エッジが存在します。 

まさにあります`2k`フロントエッジなので、シーケンスは正確に`2k`フロントステッチと`2k - 1`裏側ステッチ、`4k - 1`合計でステッチします。 上記で証明された下限は、有効なソリューションではこれより少ない量を使用できないため、構築が最適であることを示しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    w, h = map(int, input().split())
    grid = [input().strip() for _ in range(h)]

    # Vertex id for grid point (x, y).
    # There are (w + 1) points in every row.
    def vid(x, y):
        return y * (w + 1) + x

    vertices = (w + 1) * (h + 1)

    # front[0] contains the two diagonals of every X-cell.
    # back[1] contains the two vertical sides of every X-cell.
    front = [[] for _ in range(vertices)]
    back = [[] for _ in range(vertices)]

    front_edges = []
    back_edges = []

    def add_edge(graph, edges, u, v):
        eid = len(edges)
        edges.append((u, v))
        graph[u].append((v, eid))
        graph[v].append((u, eid))

    start = -1
    crosses = 0

    for y in range(h):
        for x in range(w):
            if grid[y][x] != 'X':
                continue

            crosses += 1

            nw = vid(x, y)
            ne = vid(x + 1, y)
            sw = vid(x, y + 1)
            se = vid(x + 1, y + 1)

            if start == -1:
                start = nw

            # Front: the two diagonals.
            add_edge(front, front_edges, nw, se)
            add_edge(front, front_edges, ne, sw)

            # Back: the two vertical sides.
            add_edge(back, back_edges, nw, sw)
            add_edge(back, back_edges, ne, se)

    # There are 4 edges per cross in the auxiliary graph.
    # The Euler cycle is closed by one edge which we do not print.
    print(4 * crosses - 1)

    graphs = (front, back)
    edge_count = (len(front_edges), len(back_edges))
    used = [
        [False] * edge_count[0],
        [False] * edge_count[1],
    ]
    ptr = [0, 0]
    adjacency = [front, back]

    # Iterative alternating Hierholzer traversal.
    # state = (vertex, next edge type)
    stack = [(start, 0)]
    order = []

    while stack:
        u, typ = stack[-1]

        adj = adjacency[typ]

        while ptr[typ] < len(adj[u]):
            v, eid = adj[u][ptr[typ]]
            ptr[typ] += 1

            if used[typ][eid]:
                continue

            used[typ][eid] = True
            stack.append((v, typ ^ 1))
            break
        else:
            stack.pop()
            if stack:
                order.append(u)

    order.reverse()

    out = []
    for u in order:
        x = u % (w + 1)
        y = u // (w + 1)
        out.append(f"{x} {y}")

    sys.stdout.write("\n".join(out) + "\n")

if __name__ == "__main__":
    solve()
```の`vid`関数は、行優先の順序を使用して、グリッドの交点を 1 つの整数にマップします。 表現`y * (w + 1) + x`行ごとのグリッド ポイントの数に基づきます。`w + 1`、 ない`w`。 これは、この構造で最も一般的な座標インデックス付けの間違いです。 

あらゆる人にとって`X`の場合、コードは 2 つの前面エッジと 2 つの背面エッジを作成します。 前端はまさに十字架に必要な対角線です。 裏面エッジは補助的なものであるため、元のパターンが特定の裏面セグメントを要求するためではなく、そのジオメトリがグラフ プロパティ用に選択されます。 

の`used`配列にはエッジ タイプとエッジ ID によってインデックスが付けられます。 特に異なるセルが近くのセグメントに寄与している場合、2 つのグラフ エッジが同じ端点を持つ可能性があるため、端点だけをチェックするだけでは十分ではありません。 構築された個々のエッジはそれぞれ独自の ID を取得します。 

の`ptr`アレイは、すでに調査された隣接エントリを繰り返しスキャンすることを避けます。 各隣接エントリは最大 1 回渡されるため、構築されたグラフのサイズにおいて走査は線形になります。 

最大ツアーには次のものが含まれるため、走査は再帰的ではなく反復的です。`4 * 10000 = 40000`エッジ。 Python の通常の再帰 DFS では、再帰制限を変更する必要があり、不必要に大量のコール スタックを消費します。 明示的なスタックは、同じ Hierholzer バックトラッキングを安全に実装します。 

トラバーサルでは、頂点がスタックから削除されるときに頂点が記録されます。 これにより、オイラーツアーが逆の順序で生成されます。`order.reverse()`印刷前に必要です。 この反転を忘れると、同じエッジが間違った順序で表示されます。 

構築されたすべてのグラフ エッジが 2 つの異なる隣接するグリッド ポイントを結合するため、長さ 0 のステッチは作成されません。 省略された終了エッジもゼロではありませんが、スレッドが開始点に明示的に戻る必要がないため、出力されません。

    for y in range(h):
        for x in range(w):
            if grid[y][x] != 'X':
                continue

            crosses += 1

            nw = vid(x, y)
            ne = vid(x + 1, y)
            sw = vid(x, y + 1)
            se = vid(x + 1, y + 1)

            if start == -1:
                start = nw

            add_edge(front, front_edges, nw, se)
            add_edge(front, front_edges, ne, sw)

            add_edge(back, back_edges, nw, sw)
            add_edge(back, back_edges, ne, se)

    graphs = (front, back)
    adjacency = [front, back]

    used = [
        [False] * len(front_edges),
        [False] * len(back_edges),
    ]
    ptr = [0, 0]

    stack = [(start, 0)]
    order = []

    while stack:
        u, typ = stack[-1]
        adj = adjacency[typ]

        while ptr[typ] < len(adj[u]):
            v, eid = adj[u][ptr[typ]]
            ptr[typ] += 1

            if used[typ][eid]:
                continue

            used[typ][eid] = True
            stack.append((v, typ ^ 1))
            break
        else:
            stack.pop()
            if stack:
                order.append(u)

    order.reverse()

    out = [str(4 * crosses - 1)]
    for u in order:
        out.append(f"{u % (w + 1)} {u // (w + 1)}")

    return "\n".join(out) + "\n"

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def validate(inp: str, output: str):
    lines = output.strip().splitlines()
    w, h = map(int, inp.splitlines()[0].split())
    grid = inp.splitlines()[1:1 + h]

    crosses = sum(row.count('X') for row in grid)

    n = int(lines[0])
    assert n == 4 * crosses - 1

    points = [tuple(map(int, line.split())) for line in lines[1:]]
    assert len(points) == n + 1

    for x, y in points:
        assert 0 <= x <= w
        assert 0 <= y <= h

    required = set()

    for y in range(h):
        for x in range(w):
            if grid[y][x] == 'X':
                nw = (x, y)
                ne = (x + 1, y)
                sw = (x, y + 1)
                se = (x + 1, y + 1)

                required.add(frozenset((nw, se)))
                required.add(frozenset((ne, sw)))

    seen = set()

    for i in range(n):
        a = points[i]
        b = points[i + 1]

        assert a != b

        if i % 2 == 0:
            edge = frozenset((a, b))
            assert edge in required
            assert edge not in seen
            seen.add(edge)

    assert seen == required

 ## 特殊なケース

 最低限の入力に関しては```
1 1
X
```アルゴリズムは 4 つの補助エッジを作成します`A-D`、`B-C`、`A-C`、 そして`B-D`。 交互のトラバースでは 4 つすべてを使用し、4 つの点と`4 - 1 = 3`ステッチ。 前端は正確に 2 つの対角線であるため、必要な表ステッチはどちらも複製されません。 

斜め接続の場合、```
2 2
X.
.X
```2 つのセルはグリッド点を共有します`(1,1)`。 したがって、それらの補助 4 エッジ サイクルはその頂点を共有するため、セルに共通の側面がない場合でも、結合されたグラフは接続されます。 横断は、最初のセルに属するサイクルから 2 番目のセルに属するサイクルに進むことができます。 元の条件で 4 接続ではなく 8 接続が使用されるのはまさにこのためです。 

境界セルについては、次の点を考慮してください。```
2 1
XX
```左のクロスはコーナーを使用しています`x`座標`0`そして`1`、右のクロスは使用します`1`そして`2`。 したがって、グラフには境界上の点が含まれます。`x = 0`そして`x = 2`。 頂点の番号付けには`w + 1 = 3`行あたりのポイント数に応じて、両方の境界座標が正しく表現されます。 使用する`w`代わりに、いくつかの点が間違った行にマップされます。 

最大入力の場合、```
100 100
XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
...
```みんなで`10000`以下に等しいセル`X`、アルゴリズムが作成する`40000`補助エッジと出力`39999`ステッチ。 すべてのセルは 2 つの異なる前方対角線に寄与し、交互のオイラー トラバーサルによってすべてのセルが 1 つのスレッドに結合されます。 演算の数はセルの数に比例するため、大きな出力サイズは組み合わせ検索なしで処理されます。
