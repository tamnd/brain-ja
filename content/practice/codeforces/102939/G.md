 ## 解決策
 ## 問題の理解

 このタスクは、スキー場を表す長方形のグリッド上でロボットをナビゲートし、グリッドの左側から右側に移動することです。 各セルはブロックされている、通常の雪、またはランプのいずれかです。 ロボットは、最初の列の到達可能なスノー セルで開始でき、最後の列の到達可能なスノー セルで終了することができます。 目標は、移動の数を最小限に抑えることです。 

移動は主に、各ステップで 1 列右に進むように制限されます。 ロボットは、通常のセルから、次の列にある 3 つの隣接するセル (セルがブロックされていなければ、右直下、右上、または右下) のいずれかに移動できます。 これにより、グリッドは列インデックスの点で効果的に有向非循環構造になりますが、行次元では依然として分岐が作成されます。 

ランプは 2 番目のタイプのトランジションを導入します。 ロボットがランプ セルに足を踏み入れると、単に隣接するセルに移動するわけではありません。 代わりに、発射され、固定された「下り坂」方向に沿って、最初に利用可能なクリアセルに着陸します。 このステートメントを正確に解釈すると、これはランプが有効な着地セルが見つかるまで中間セルをスキップする強制ジャンプをトリガーし、ジャンプ全体のコストがちょうど 1 回であることを意味します。 

重要な結果は、各セル遷移には単位コストがあるが、一部の遷移は多くの中間グリッド位置をスキップすることです。 これは、最大で有向グラフ上の最短経路問題を即座に示唆します。$N \cdot M$ノード。エッジはローカルな移動か、ランプからの事前計算されたロング ジャンプのいずれかです。 

制約$N, M \le 1000$最大 100 万ノードを意味します。 特にランプ シミュレーションがステップごとに単純に実行される場合、注意深い前処理を行わずにパスを動的に拡張しようとするソリューションは困難になります。 暗黙的なグラフに対する BFS などの線形または線形に近いグラフ走査が必要です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

ランプはブロックされたセルの長いチェーンをスキップする可能性があるため、クエリごとに「何かに到達するまで段階的に移動する」という単純な操作を繰り返すと、時間がかかりすぎます。 もう 1 つの問題は、ランプとその着陸セルの間に複数のランプまたは障害物が存在する可能性があり、最初の有効な着陸セルのみが問題となることです。 最後に、開始位置と終了位置は固定点ではなく、最初と最後の列にある可能なセルのセットであるため、アルゴリズムはそれらすべてを同時にソースとシンクとして扱う必要があります。 

## アプローチ

 ブルートフォースのアイデアは、各セルを状態として扱い、ランプに遭遇するたびに、着地セルが見つかるまでランプ方向に前方にスキャンしてその効果をシミュレートすることです。 各 BFS 拡張は、ランプの宛先を解決するためにグリッドに沿って繰り返し歩きます。 最悪の場合、単一のランプ遷移でスキャンが行われる可能性があります。$O(N)$または$O(M)$これはすべてのエッジ緩和で発生する可能性があり、全体の複雑さが近づきます。$O(N^2 M)$あるいはさらに悪いことに。 細胞数が 100 万個あると、これは不可能です。 

重要な観察は、ランプ遷移が決定論的であり、そこに到達するまでのパスではなく、グリッド ジオメトリのみに依存するということです。 つまり、すべてのランプ セルには、一度だけ事前計算できる固定の宛先があります。 この前処理の後、グリッド全体は、各ノードが最大 4 つの発信エッジ (3 つの通常の移動と 1 つのランプ ジャンプ) を持つ標準的な重み付けされていないグラフになります。 

グラフが明示的になると、最初の列のすべての有効なセルから開始するマルチソース BFS を使用して最短パスを見つけることができます。 BFS は最小距離値を自然に伝播し、最後の列のいずれかのセルに初めて到達すると最適な答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 動きごとの単純なシミュレーション |$O(N^2 M)$|$O(NM)$| 遅すぎる |
 | 事前計算ランプ + BFS |$O(NM)$|$O(NM)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の列で有効な開始状態をすべて特定します。 列 0 のブロックされていない各セルは、距離 0 のキューに挿入されます。 これは、スキーヤーが左端のどこからでもスタートできることを反映しています。 
2. 各ランプ セルの効果を事前計算します。 ランプを含むセルごとに、その起動を 1 回シミュレートし、着陸セルを保存します。 シミュレーションは、クリアなセルが見つかるまでランプの固定方向に従います。 このステップは、後の走査で作業が繰り返されないように、ランプ セルごとに 1 回実行されます。 
3. 各セルの暗黙的な遷移を構築します。 通常のセルから、有効であれば次の列の 3 つの隣接するセルへの移動を許可します。 ランプ セルから、事前計算されたランディング セルに単一の有向エッジを追加します。 
4. キューを使用してこのグラフに対して BFS を実行します。 各遷移のコストは 1 であるため、BFS は最初にノードに到達するときに可能な限り最短の移動回数であることを保証します。 
5. 最後の列のすべてのセル間の最適な距離を追跡します。 BFS が右端の列のセルに到達したらすぐに、答えを更新します。 このような到着すべての最小値が最終結果となります。 

### なぜ効果があるのか

 状態空間は列次元で有向非循環構造を形成するため、水平方向の動きだけからサイクルが発生することはありません。 また、ランプエッジは、以前のコラムを再訪問するのではなく、中間の地形をスキップするため、効果的な進歩という点でスキーヤーを常に前に動かします。 これにより、BFS は、ランプを通る代替のより短い迂回を見逃すことなく、パス長の増加順に状態を探索することが保証されます。 すべての有効な移動は事前計算されたグラフ内で 1 回だけ表現されるため、このグラフの BFS は元の暗黙的な移動システムでの最短経路探索と同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    # Precompute ramp destinations
    # direction: assumed (r-1, c+1), moving "up-right"
    dest = [[None] * m for _ in range(n)]

    def find_landing(r, c):
        rr, cc = r - 1, c + 1
        while 0 <= rr < n and 0 <= cc < m:
            if g[rr][cc] == '.':
                return (rr, cc)
            rr -= 1
            cc += 1
        return None

    for i in range(n):
        for j in range(m):
            if g[i][j] == '>':
                dest[i][j] = find_landing(i, j)

    INF = 10**18
    dist = [[INF] * m for _ in range(n)]
    q = deque()

    # multi-source start
    for i in range(n):
        if g[i][0] != '#':
            dist[i][0] = 0
            q.append((i, 0))

    while q:
        r, c = q.popleft()
        d = dist[r][c]

        if c == m - 1:
            continue

        # normal moves to next column
        for dr in (-1, 0, 1):
            nr, nc = r + dr, c + 1
            if 0 <= nr < n and 0 <= nc < m and g[nr][nc] != '#':
                if dist[nr][nc] > d + 1:
                    dist[nr][nc] = d + 1
                    q.append((nr, nc))

        # ramp transition
        if g[r][c] == '>' and dest[r][c] is not None:
            nr, nc = dest[r][c]
            if dist[nr][nc] > d + 1:
                dist[nr][nc] = d + 1
                q.append((nr, nc))

    ans = min(dist[i][m - 1] for i in range(n))
    print(ans)

if __name__ == "__main__":
    solve()
```ランプ遷移が明示的なエッジに正規化されると、BFS が標準になります。 微妙な部分は、走査中にランプの宛先を再計算するとパフォーマンスの低下につながるため、ランプの宛先が一度計算されて再利用されるようにすることです。 

注意する価値のある詳細の 1 つは、ランプ トランジションはランプ セル上に立っている場合にのみトリガーされ、隣接を介してランプ セルを通過する場合にはトリガーされないことです。 もう 1 つは、すべての有効な開始セルを最初にキューに入れる必要があることです。そうしないと、BFS が誤って単一の開始状態を想定します。

 小さなグリッドを考えてみましょう。```

```列 0 のブロックされていないすべてのセルを開始として扱います。 左上のみが有効であると仮定します。 

| ステップ | キュー | (r,c) | アクション | 距離の最新情報 |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | (0,0) | 開始 | 距離[0][0]=0 |
 | 2 | (0,0) | (0,0) | 次の列に移動 | (0,1),(1,1),(2,1) |
 | 3 | (0,1) | ランプ？ いいえ | 通常の BFS 拡張 | 続ける |
 | 4 | (0,2) | '>' | ランプトリガー | 着陸セルにジャンプ |

 このトレースは、ランプ圧縮が中間走査をどのように回避するかを示しています。 

### 例 2```
4 6
.>..#.
..#...
#..>..
......
```ここには複数のランプが存在します。 BFS は早期にランプに到達する可能性がありますが、キューにより最短の到着時間が優先されます。 

| ステップ | キュー | ポジション | イベント | メモ |
 | --- | --- | --- | --- | --- |
 | 1 | すべての列0 | 複数のスタート | 初期化 | マルチソースBFS |
 | 2 | ... | (0,1) | ランプ | 使用される事前計算されたジャンプ |
 | 3 | ... | (2,3) | ランプ | 代替ショートカット |
 | 4 | ... | Col5 セル | 仕上げ | 所要時間 |

 これは、複数のランプ ショートカットが明示的な優先順位付けなしで BFS によって自然に比較されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(NM)$| 各セルは BFS で 1 回処理され、ランプ前処理は線形です。 
| スペース |$O(NM)$| 距離配列、グリッド ストレージ、キュー |

 ## 特殊なケース

 重要なエッジ ケースは、セルからの唯一の有用な遷移がランプである場合です。 このような状況では、着陸セルの事前計算に失敗するとスキャンが繰り返され、パフォーマンスが低下します。 前処理を使用すると、アルゴリズムは保存された宛先を直接使用します。 

もう 1 つのケースは、複数のランプが斜めのパスに沿って配置されている場合です。 単純なアプローチでは中間のランプ セルを繰り返し通過する可能性がありますが、BFS は各ランプを単一のエッジとして扱い、正確な最小カウントを保証します。 

最後に、開始列に 1 つの孤立したパスを除いてブロックされたセルのみが含まれている場合、マルチソース BFS は探索をその単一の実行可能なエントリ ポイントに正しく制限し、グリッド内の他の場所での不必要な状態の拡張を回避します。
