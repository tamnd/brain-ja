 ## 解決策
 ## 問題の理解

 整数のマルチセットが与えられており、それらのサブセットを削除することができます。 削除後、残りの要素がペアリング条件を満たす必要があります。すべての残りの値は、それらの合計が 2 の累乗に等しくなるように、少なくとも 1 つの他の残りの値を見つけることができなければなりません。 

この条件は要素ごとにローカルですが、パートナーの選択は同じ最終セットから行われる必要があります。 したがって、問題は実際には、すべての要素が少なくとも 1 つの有効な「2 のべき乗の和のペア」に参加する可能な最大のサブセットを求め、そのサイズを元の配列の長さから減算します。 

n が 120000 までという制約により、二次関数や素朴な形式の n√n さえも避けられます。 すべてのペアを試行するか、再利用せずに要素ごとに一致を個別に再計算するソリューションはタイムアウトします。これは、すべての候補ペアをチェックするには、最悪の場合、約 n² の操作が必要になるためです (最悪の場合、10¹⁰ 程度)。 

ペアリングがまったくできない場合、微妙なエッジケースが発生します。 たとえば、配列に [16] のような単一の要素が含まれている場合、条件を満たす方法はないため、最適な答えはすべてを削除することです。 もう 1 つの興味深いケースは、値が大きすぎて 2 の累乗の合計範囲に組み込むことができない場合です。たとえば、[4, 16] では、可能な限り最良の補数 (4 + 16 = 20) でさえ 2 の累乗にはなりません。 

主な問題点は、この条件が建設的な意味で対称的ではないことです。各要素には複数の可能なターゲットがありますが、すべての要素が何らかの一致する構造によってカバーされることをグローバルに保証する必要があります。 

## アプローチ

 直接的なアプローチは、配列のすべてのサブセットを試して、それが適切かどうかをテストすることです。 固定サブセットの場合、各要素をチェックし、残りの要素の中から合計が 2 の累乗となるパートナーを見つけようとします。 ハッシュ セットを使用してメンバーシップ チェックを最適化したとしても、1 つのサブセットの検証には最悪の場合 O(n²) のコストがかかります。 サブセットが 2ⁿ あるため、これは完全に不可能です。 

要素ごとに貪欲にペアリングするという考えに限定したとしても、すぐに競合が発生します。 要素には複数の可能なパートナーが存在する可能性があり、ローカルで 1 つを選択すると、別の要素が必要な一致を見つけることができなくなる可能性があります。 したがって、各要素を最初から純粋に貪欲にマッチングすると、グローバルな一貫性が無視されるため失敗します。 

重要な観察は、形式 2ᵈ の合計のみが重要であり、各値 aᵢ は 1 つのパートナーのみを見つける必要があるということです。 これは、問題をグラフ上のマッチング問題として再構成することを示唆しています。各数値はノードであり、aᵢ + aⱼ が 2 の累乗である場合、i と j を接続します。 誘導されたサブグラフ内で残りのすべてのノードの次数が少なくとも 1 になるように、削除するノードの数をできるだけ少なくしたいと考えています。 

この巨大なグラフを明示的に構築する代わりに、視点を反転します。 各値 x について、その有効なパートナーは 2ᵈ − x の形式の数値です。 値が最大 10⁹ であるため、d は約 31 または 32 まで増加するだけで済みます。これにより、要素ごとの検索スペースが大幅に制限されます。 

次に、周波数マップを使用して、有効なペアの形成を貪欲に試みます。 重要な構造は、ペアリングが対称であるため、値を反復処理し、各出現箇所を利用可能な補数と貪欲に照合して、各要素が最大 1 回使用されるようにすることができることです。 

最終的な目標は、少なくとも 1 つの成功したペアリングに参加する要素の数を最大化することに相当します。これは、可能な限り、素のペアを繰り返し形成することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 周波数 + 電力の列挙 | O(n log A) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列内のすべての値の頻度マップを作成します。 これにより、数値の未使用のコピーがいくつ残っているかに常時アクセスできます。 
2. マップ内の各個別の値 x を反復処理します。 各 x について、その出現を 1 つずつペアリングしようとします。 
3. x が出現するたびに、2ᵈ − x が候補値となるように 2 の和のすべてのべき乗 2ᵈ を試行します。 正の残り頻度を持つ補数 y = 2ᵈ − x がマップ内に存在する場合、ペア (x, y) を形成し、両方のカウントをデクリメントします。 
4. x に対して形成できるペアがなくなるまでこのプロセスを続け、次の値に進みます。 
5. ペアリングに成功した要素の数を数えます。 各ペアは 2 つの保持された要素を提供するため、答えは n から成功したペアに使用される要素の数を引いたものになります。 

値ごとに 2 の累乗をすべて試行する理由は、各要素には O(log maxA) 個の潜在的なパートナーしか存在しないためです。これにより、検索が小さくなり、有効なペアを見逃すことがなくなります。 

### なぜ効果があるのか

 すべての要素には少なくとも 1 つのパートナーが必要であり、単一のパートナーで十分であるため、有効な各構成は素のペアに分解されます。 互換性グラフのエッジの選択のみを考慮することを修正すると、保持される要素を最大化することは、頂点を再利用せずにできるだけ多くの有効なエッジを選択することになります。 各頂点は構築されたソリューションの最大でも 1 つのエッジに参加するため、各エッジが独立して条件を満たしていると仮定すると、最適なソリューションは損失なくそのような素の一致に再配置できるため、すべての可能な電力ターゲットにわたる貪欲なペアリングで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    from collections import Counter
    cnt = Counter(a)
    
    powers = [1 << i for i in range(32)]
    
    used = Counter()
    ans_pairs = 0
    
    for x in list(cnt.keys()):
        while cnt[x] > 0:
            matched = False
            for p in powers:
                y = p - x
                if y < 0:
                    continue
                if cnt[y] > 0:
                    cnt[x] -= 1
                    cnt[y] -= 1
                    ans_pairs += 1
                    matched = True
                    break
            if not matched:
                break
    
    print(n - 2 * ans_pairs)

if __name__ == "__main__":
    solve()
```この実装は周波数カウンターに依存しているため、すべてのペアを明示的に構築するわけではありません。 2 のべき乗のリストは 2¹ まで事前に計算されており、制約が与えられた場合に考えられるすべての合計を安全にカバーします。 

それぞれの値について、有効な 2 の累乗和を形成する補数を見つけることを繰り返し試みます。 ペアが形成されると、両方の周波数が直ちに減少し、要素が再利用されなくなります。 

微妙な点は、以前のペアリングが後の可用性に影響を与えるため、固定スナップショットではなく周波数マップの現在の状態に対して補数を再計算することです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log A) | 各値は最大で最大 32 の 2 のべき乗ターゲットを試行します。 
| スペース | O(n) | 個別の値にわたる周波数マップ |

 対数係数は、各値の 2 のべき乗の候補を列挙することで得られます。 A ≤ 10⁹ であるため、これは要素ごとに 31 回の反復によって制限され、これは n の最大 120000 の時間制限内に問題なく収まります。

    cnt = Counter(a)

            matched = False
            for p in powers:

                if y < 0:
                    continue
                if cnt[y] > 0:
                    cnt[x] -= 1
                    cnt[y] -= 1
                    ans_pairs += 1
                    matched = True
                    break
            if not matched:
                break

    return str(n - 2 * ans_pairs)

 ## 特殊なケース

 [16] のような単一要素の配列は、すべての値がパートナーを見つけることができると仮定した戦略が失敗することを示しています。 アルゴリズムは値を処理し、2ᵈ − 16 の中で補数を見つけず、一致しないままにし、完全な削除に正しく寄与します。 

[1, 1] のような場合、アルゴリズムは 1 + 1 = 2 (2 の累乗) を即座に検出し、両方の出現を消費し、削除はゼロになります。 周波数ベースの構造により、両方のコピーが二重にカウントされることなく対称的に処理されることが保証されます。 

[1, 3, 2, 8] など、複数のペアリング オプションが存在する配列では、アルゴリズムによる頻度の順次消費により、ある値が 1 つのペアで使用されると、その値が別のペアに誤って参加することがなくなり、素ペアの要件の下で正確さが維持されます。
