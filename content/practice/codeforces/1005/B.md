 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられ、どちらの文字列からも左端の文字だけを繰り返し削除できます。 削除するたびに、文字列の 1 つが 1 文字だけ短くなります。 目標は、できるだけ少ない削除を使用して、結果として得られる 2 つの文字列を同一にすることであり、削除の数は最小限に抑えたいと考えています。 

重要な点は、削除はプレフィックスにのみ影響するということです。 各文字列の左側からいくつかの文字を削除すると、元の文字列の接尾辞が残ります。 したがって、この問題は、各文字列から 1 つずつ、等しい 2 つの接尾辞を見つけて、それらに到達するために必要な削除される文字の総数を最小限に抑えることと同じです。 

この制約により、各文字列の長さは最大 200,000 になります。 サフィックスのすべてのペアを比較したり、可能性ごとに削除をシミュレートしたりする二次アプローチでは、最悪の場合でも 10^10 のオーダーの演算が必要になりますが、これは実行可能な限界をはるかに超えています。 これにより、サフィックスのブルートフォースペアワイズマッチングや、ネストされたループ内で繰り返される文字列スライスが即座に排除されます。 

文字列に共通の接尾辞がまったくない場合、微妙なエッジケースが発生します。 たとえば、次の場合`s = "abc"`そして`t = "xyz"`、空でないサフィックスは一致しないため、それらを等しくする唯一の方法は両方を完全に削除することです。 答えは 6 です。少なくとも 1 つの一致文字を想定する単純なアプローチでは、空一致の場合を正しく処理せずに最後から整列しようとすると失敗する可能性があります。 

もう 1 つのエッジ ケースは、一方の文字列がすでに他方の文字列のサフィックスになっている場合に発生します。 例えば、`s = "abcde"`そして`t = "cde"`。 最適な戦略は、両方が一致するまで長い文字列のみを削除することです。`"cde"`、2手与えます。 サフィックスの包含をチェックせずに両側からの削除を同期しようとするアプローチでは、操作が過剰にカウントされる可能性があります。 

## アプローチ

 ブルートフォースの観点では、両方の文字列の左側から文字を削除するあらゆる可能な方法を検討することから始まります。 削除したら`i`からのキャラクター`s`そして`j`からのキャラクター`t`、結局比較してしまう`s[i:]`そして`t[j:]`。 ペアが欲しいです`(i, j)`これにより、これらのサフィックスが最小化されながら等しくなります。`i + j`。 

このアプローチは正しいです。なぜなら、有効な削除シーケンスはすべて、各文字列に残る文字数の選択に正確に対応しているからです。 ただし、すべて試してみると、`(i, j)`ペアでは O(nm) 回の比較が行われ、単純に実行すると各比較に最悪の場合 O(n) 時間かかる可能性があります。 これは、長さ 200,000 の文字列にとっては非常に遅くなります。 

重要な洞察は、すべての接尾辞のペアを検索する必要はないということです。 代わりに、視点を逆にします。両方の文字列の末尾から文字を比較し、それらの接尾辞の一致がどれだけ長く続くかをカウントします。 文字が異なると、それ以上一致を拡張することはできないため、最も長い共通の接尾辞によって最適な解決策が完全に決まります。 

最長の共通サフィックスに長さがある場合`k`、その後、それらを保持できます`k`両方の文字列の文字。 それ以前のものはすべて削除する必要があります。 したがって、答えは次のとおりです`(len(s) - k) + (len(t) - k)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 削除はプレフィックスにのみ影響し、サフィックスの同等性はサフィックスの構造に依存するため、両方の文字列の最後の文字から開始します。 2 つの文字列がどこまで遡って一致するかを最大化しようとしています。 
2. 終了時に 2 つのポインタを初期化します。`s`そして`t`。 カウンタも初期化します`k = 0`一致するサフィックスの長さを追跡します。 
3. 両方のポインタが有効で、それらの位置の文字が等しい間は、値を増やします。`k`両方のポインタを左に 1 ステップ移動します。 これにより、最長の共通サフィックスが右から左に直接構築されます。 
4. いずれかのポインタが範囲外になるか、不一致が発生した場合は停止します。 この時点では、不一致によってサフィックスの等価性が損なわれるため、共通サフィックスをこれ以上拡張することはできません。 
5. 答えを次のように計算します。`(len(s) - k) + (len(t) - k)`, since all characters outside the matched suffix must be deleted.

 ### なぜ効果があるのか

 Every valid final configuration corresponds to choosing a suffix of`s`と接尾辞`t`それは同一です。 このアルゴリズムは、一致を末尾から貪欲に拡張することによって、可能な最大のサフィックスを見つけます。これは、一致が短くても削除の数が増えるだけであるため、これが最適です。 文字はサフィックス内で位置的に一致する必要があるため、相違があればすぐに長い拡張子が無効になり、貪欲な逆方向スキャンが十分かつ最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    i = len(s) - 1
    j = len(t) - 1

    while i >= 0 and j >= 0 and s[i] == t[j]:
        i -= 1
        j -= 1

    common_suffix_len = len(s) - (i + 1)
    # equivalently len(t) - (j + 1), but both are same at this point

    ans = (len(s) - common_suffix_len) + (len(t) - common_suffix_len)
    print(ans)

if __name__ == "__main__":
    solve()
```コードは、アルゴリズムで説明されている逆方向スキャンを直接実装します。 このループは、各文字列の末尾から移動する 2 つのインデックスを維持し、接尾辞の一致がどれだけ長く続くかをカウントします。 最後の式では、一致したサフィックスの長さを両方の文字列から減算して、削除を計算します。 引き算`(i + 1)`最終的な不一致位置を一致した領域の長さに変換します。 

Python では負のインデックスが許可されているため、インデックスを作成する前にループ条件で境界をチェックするように注意する必要があります。これは、適切に保護されていない場合、誤った一致を暗黙的に生成する可能性があります。 明示的な`i >= 0 and j >= 0`によりこの問題が防止されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    s = input().strip()
    t = input().strip()

    i = len(s) - 1
    j = len(t) - 1

    while i >= 0 and j >= 0 and s[i] == t[j]:
        i -= 1
        j -= 1

    k = len(s) - (i + 1)
    return str((len(s) - k) + (len(t) - k))

assert run("test\nwest\n") == "4", "sample 1"

assert run("abc\nxyz\n") == "6", "no common suffix"

assert run("abcde\ncde\n") == "2", "one is suffix of other"

assert run("a\nb\n") == "2", "single char mismatch"

assert run("aaaa\naaaa\n") == "0", "identical strings"

assert run("abacaba\nxxcaba\n") == "5", "partial suffix match"
```| テスト入力 | 期待される出力 | 検証内容 |

 | テスト / 西 | 4 | 基本的な接尾辞の一致 |

 ## 特殊なケース

 のために`s = "abc"`そして`t = "xyz"`、アルゴリズムは最後から比較を開始します。`c`対`z`、すぐに不一致になるため、`k = 0`。 答えは次のようになります`3 + 3 = 6`これは、両方の文字列を完全に削除する必要があることを正しく反映しています。 

のために`s = "abcde"`そして`t = "cde"`、比較は次のように進行します。`e`対`e`、`d`対`d`、`c`対`c`、次に停止します`b`vs 文字列の終わり。 ここ`k = 3`、したがって、答えは次のとおりです`2`、削除の必要性のみに一致します`"ab"`最初の文字列から。 

これらのケースでは、アルゴリズムが完全な不一致と完全な封じ込めの両方の極端な状況を正しく処理していることが確認されます。
