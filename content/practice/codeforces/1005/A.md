 ## 解決策
 ## 問題の理解

 ターニャが建物の階段を登るときに言ったことを表す単一の整数シーケンスが与えられます。 新しい階段を開始するたびに、常に 1 から数え始め、その階段の最後のステップに到達するまで、ステップごとに 1 ずつ増えます。 

したがって、順序は任意ではありません。 これは、いくつかの連続したセグメントを連結することによって形成されます。各セグメントは、1 で始まり、ある値 x で終わる自然数の接頭辞です。 私たちのタスクは、シーケンスをこれらのセグメントに分割し、セグメントの数と各セグメントの長さを報告することです。 

入力サイズは最大 1000 個の数値です。 これにより、アレイを一定回数スキャンするソリューションや、ネストされたリニア スキャンを実行するソリューションであれば、十分に高速であることがすぐに分かります。 前処理、ハッシュ、高度なデータ構造は必要ありません。 

唯一の微妙な点は、1 つの階段がどこで終わり、次の階段が始まるかを正確に識別することです。 単純な間違いは、シーケンス値が減少するたび、または 1 が表示されるたびに、境界を慎重に処理せずに新しいセグメントを開始すると考えることです。 たとえば、次のようなシーケンスでは、`1 2 3 1 2 3 4`、1 から再開するのは明らかですが、より一般的なシーケンスでは、シーケンスが 1 から開始して 1 ずつ増加し続けるのをやめたときに、常にブレークが発生します。 

典型的な間違ったアプローチは、`a[i] == 1`境界マーカーとして。 この問題では妥当性が保証されているため、これは機能しますが、不注意な実装では、セグメントの最後の要素の後に必ずしも 1 が続くわけではないことを見逃す可能性があります。 代わりに、次の値が 1 になるか、配列の最後に到達すると、セグメントは終了します。 

正しい解釈は、各階段は値が正確に一致する最大の連続セグメントであるということです。`1, 2, 3, ..., k`。 

## アプローチ

 これを考える強引な方法は、シーケンスの可能なすべての分割を有効な階段に試して、それぞれを検証することです。 潜在的なカット位置ごとに、その開始インデックスのセグメントが 1 から始まり 1 ずつ増加する有効なシーケンスを形成しているかどうかをチェックします。最悪の場合、検証のために配列の一部を繰り返し再スキャンする可能性があり、チェックの構造に応じて 2 次または 3 次の動作が発生する可能性があります。 これは、n が 1000 までの制限内にありますが、不必要であり、概念的に必要以上に重くなります。 

重要な観察は、セグメントがどこで終わるかを推測する必要がないということです。 有効な階段は常に次のように見えるため、セグメントは現在の値がそれまでのセグメントの長さと一致したときに正確に終了する必要があります。`1, 2, ..., length`。 したがって、現在のセグメント サイズと等しい数値が表示されるまでセグメントを貪欲に拡張し、その後セグメントを閉じることができます。 

これにより、問題は 1 つの線形パスに軽減され、セグメント内の現在の期待される次の値が維持されます。

 ## アルゴリズムのチュートリアル

 1. 配列のスキャンを左から右に開始し、新しいセグメントをそれぞれ新しい階段として扱います。 

すべての階段は 1 で始まる必要があることがわかっているため、セグメントの最初の要素は 1 であることが期待されます。 
2. 新しいセグメントを開始するときに、カウンターを設定します`expected = 1`そして、このセグメントが開始されたことを記録します。 
3. 配列内を前に進み、各値を確認します。 

現在の値が一致する場合`expected`、まだ有効な階段の内側にいるので、インクリメントします。`expected`1までに。 
4. どこかの時点で、`expected`セグメントが終了すると再び 1 になり、新しい階段の開始を示します。 
5. セグメントは、1 から k までの完全なプレフィックスを消費したときに正確に終了します。これは、新しい 1 を開始しようとしている瞬間、または配列の最後に到達した瞬間に対応します。 
6. 完成した各セグメントの長さを保存します。 

### なぜ効果があるのか

 有効な各階段は、その開始点によって一意に決定され、1 から始まる連続した整数の増加に厳密に従う必要があります。入力が有効であることが保証されているため、セグメント化に曖昧さはありません。1 が表示されると、新しいセグメントが開始され、2 つの連続する 1 の間でシーケンスが連続的に増加するランを形成する必要があります。 この構造により、1 ずつ増加することからの逸脱は妥当性と矛盾するため、貪欲なセグメンテーションではバックトラッキングや推測が必要なくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

segments = []
i = 0

while i < n:
    expected = 1
    length = 0
    
    while i < n and a[i] == expected:
        length += 1
        expected += 1
        i += 1
    
    segments.append(length)

print(len(segments))
print(*segments)
```コードは配列を 1 回スキャンします。 外側のループは階段間を進み、内側のループは 1 から始まる増加シーケンスと一致させることで、有効な階段を 1 つだけ消費します。`expected`変数は有効な階段の構造を強制します。`length`含まれているステップ数を記録します。 

微妙な点は、次の 1 を明示的に検索しないことです。代わりに、シーケンスが中断されたときに内側のループが自然に停止します。これは、入力が有効であることが保証されているため、階段間の境界でのみ発生します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    segments = []
    i = 0

    while i < n:
        expected = 1
        length = 0
        while i < n and a[i] == expected:
            length += 1
            expected += 1
            i += 1
        segments.append(length)

    return str(len(segments)) + "\n" + " ".join(map(str, segments))

# provided sample
assert run("7\n1 2 3 1 2 3 4\n") == "2\n3 4"

# single stairway
assert run("3\n1 2 3\n") == "1\n3"

# multiple single-step stairways
assert run("3\n1 1 1\n") == "3\n1 1 1"

# alternating short stairs
assert run("5\n1 2 1 2 3\n") == "2\n2 3"

# maximum length single staircase
assert run("1\n1\n") == "1\n1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 3 | 1 / 3 | 単一の完全な階段 |
 | 1 1 1 | 3 / 1 1 1 | 連続再起動 |
 | 1 2 1 2 3 | 2 / 2 3 | 混合セグメンテーション |
 | 1 | 1 / 1 | 最小サイズ |

 ## 特殊なケース

 エッジ ケースの 1 つは、シーケンス全体が長さ 1 の複数の独立した階段で構成されている場合です。`1 1 1 1`。 アルゴリズムは、次の時点でセグメントを開始します。`1`、すぐに一致します`expected = 1`、単一の要素を消費し、セグメントを閉じます。 これにより、長さ 1 の 4 つのセグメントが生成され、意図した解釈と一致します。 

もう 1 つのエッジ ケースは、次のような 1 つの長い階段です。`1 2 3 4 5`。 ここでは、内側のループが早期に中断されることはありません。`expected`最後までスムーズに増加し、正確な全長で 1 つのセグメントが記録されます。
