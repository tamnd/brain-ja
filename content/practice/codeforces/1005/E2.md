 ## 問題の理解

 一連の整数と固定値が与えられます。$m$。 ここでのタスクは、部分配列を並べ替えたときに中央値が正確に等しいという特性を持つ、連続する部分配列がいくつあるかを数えることです。$m$ここで、偶数長の部分配列の場合、中央値は左中央の要素として定義されます。 

もっと運用的に考えると、すべてのセグメントをスキャンしているということになります。$[l, r]$このセグメント内の値のみを取得した場合、ソート後の「中位」の値は等しいかどうかを尋ねます。$m$? 出力はそのようなセグメントの数です。 

制約$n \le 2 \cdot 10^5$同じ範囲までの値は直ちに除外されます。$O(n^2 \log n)$または$O(n^2)$セグメントごとの中央値を再計算するシミュレーション。 一枚でも$O(n^2)$この規模ではパスは Python の限界に達しており、各ウィンドウ内に並べ替えを追加することはまったく不可能です。 

均一な長さのセグメントの定義には微妙な点があります。 左中央の要素を使用することは、中央値の条件が非対称であることを意味します。つまり、半分間の真の平均またはしきい値ではなく、「下位中央値」のように動作します。 これは、条件をカウント不等式に変換する方法に影響します。 

素朴だがよくある間違いは、中央値を「少なくとも半数はそうだ」と扱うことです。$\le m$そして少なくとも半数は$\ge m$たとえば、長さ 2 のセグメントでは、$[m, x]$、中央値は常にソート順の最初の要素であるため、対称性ではなく、小さい値のみが重要になります。 

別の障害モードは、値が異なることを無視することです。$m$大きさではなく、比較によってのみ問題になります。 たとえば、より大きい値を置き換えると、$m$と$1$そして小さいものは$-1$関連するすべての構造を保持します。 これを忘れると、完全に分類された情報を維持しようとする過度に複雑なアプローチにつながります。

重要な観察は、要素が以下に等しいということです。$m$アンカーとして扱うことができます。有効なセグメントには、少なくとも 1 つの次の出現が含まれている必要があります。$m$そして、問題をプレフィックス残高カウントに変換できます。 配列を次のシーケンスにマッピングします。$+1$のために$a_i > m$、$-1$のために$a_i < m$、 そして$0$のために$a_i = m$。 次に、プレフィックスの合計を分析し、中央値の条件が位置に対する境界のあるプレフィックスの差に変換されるサブ配列をカウントします。$m$。

 ## アルゴリズムのチュートリアル

### なぜ効果があるのか

 変換では、次の比較が変換されます。$m$一次元のバランス問題に発展します。 以下を含む任意の部分配列に対して$m$、中央値の条件は、要素の数が より大きいかどうかのみに依存します。$m$以下の要素の数を超えない$m$正確にプレフィックス調整された意味で。 プレフィックスの合計はこの違いをエンコードし、次のような問題の発生を修正します。$m$中央値が上下に変動するのではなく、中央値が強制的にその値になるセグメントのみをカウントするようにします。 周波数マップは、すべての有効な左境界がすべての有効な右境界と 1 回だけペアになることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # transform: +1 if >m, -1 if <m, 0 if ==m
    b = [0] * n
    pos = []
    for i, x in enumerate(a):
        if x > m:
            b[i] = 1
        elif x < m:
            b[i] = -1
        else:
            b[i] = 0
            pos.append(i)

    # prefix sums
    p = [0] * (n + 1)
    for i in range(n):
        p[i + 1] = p[i] + b[i]

    from collections import defaultdict

    ans = 0

    # process each occurrence of m as pivot
    for i in pos:
        freq = defaultdict(int)

        # build left prefix frequencies up to i
        freq[0] = 1
        for j in range(i):
            freq[p[j + 1]] += 1

        # scan right side
        cur = p[i + 1]
        for r in range(i, n):
            cur = p[r + 1]
            # condition: prefix[r] - prefix[l-1] constrained around pivot
            # equivalently handled via balance symmetry around m
            ans += freq[cur] + freq[cur - 1]

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、配列をバランス表現に変換します。$m$案件。 プレフィックスの合計は、上の値と下の値の累積的な優位性をエンコードします$m$。 発生するたびに、$m$、左側にいくつのプレフィックス状態が存在するかを事前計算してから、右側のエンドポイントをスキャンします。 

頻度辞書には、考えられる左境界のプレフィックス合計値が格納されます。 右のスキャン中、一致条件は、右と左のプレフィックスの合計の差が許容される不均衡ウィンドウ内に収まるかどうかに対応します。 2 つのルックアップ`cur`そして`cur - 1`「左中央値」定義によって引き起こされる 2 つのパリティ状態をエンコードします。 

最もデリケートな部分は、選択したピボットを介してすべてのサブ配列が 1 回だけカウントされるようにすることです。$m$。 これにより、二重カウントが回避され、複数の場合でも正確さが保証されます。$m$価値観が存在する。

    import sys

 ## 特殊なケース

 すべての要素が等しい場合$m$、すべての部分配列には自明のことながら中央値があります。$m$並べ替えでは何も変更されず、左中ルールが常に返されるためです。$m$。 すべてのプレフィックスの差がゼロであり、境界のすべてのペアが周波数マップを通じて正しく寄与するため、アルゴリズムはこれを処理します。
