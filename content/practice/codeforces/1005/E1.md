 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列と、配列内のどこかに 1 回だけ出現する識別値 m が与えられます。 ここでのタスクは、部分配列をソートすると中央値要素が m に等しくなるという性質を持つ、連続する部分配列がいくつあるかを数えるということです。 

主な問題は、中央値が元の配列内の位置ではなく、各セグメント内の相対的な順序に依存することです。 長さ k のセグメントの場合、中央値は並べ替え後のインデックス (k+1)//2 の要素として定義されます。これは、k が偶数の場合、中央の下側の要素であることを意味します。 

単純に解釈すると、すべての部分配列をチェックし、ソートによって中央値を計算する必要がありますが、これは n が 200,000 までの場合は遅すぎます。 O(n^2) 個の部分配列のそれぞれをソートすると、既に 2 次的なカウントが行われ、各ソートには対数または線形の時間がかかり、実行不可能なパフォーマンスが発生します。 

順列の構造により、重要な単純化が行われます。 すべての要素は個別であるため、m を基準にしてすべてを比較できます。m より大きい要素と m より小さい要素は、m がセグメント内の中央値になり得るかどうかを完全に決定します。 

均等な長さのセグメントからは、微妙なエッジ ケースが発生します。 中央値は左中央の要素として定義されているため、m が小さい値と大きい値の間で正確にバランスが取れているセグメントでも、パリティが正しく処理されないと失敗する可能性があります。 たとえば、m 未満の数値と m を超える数値の数が等しいセグメントでは、含まれる要素の数によって中央値が曖昧になります。 

素朴な推論によるもう 1 つの失敗例は、「位置による中央であれば m は中央値である」と仮定することです。 配列はインデックス順ではなくソート順に考慮されるため、これは不正確です。 たとえば、`[3, 1, 4, 2]`、m = 3 は終わり近くに表示される可能性がありますが、中央に配置されていない一部の部分配列の中央値であることに変わりはありません。 

## アプローチ

 ブルート フォース ソリューションでは、すべての部分配列を列挙し、ソートによって中央値を計算し、それが m に等しいかどうかを確認します。 これは定義が直接的であるため機能しますが、O(n^2) 個の部分配列があり、各中央値の計算が少なくとも O(k log k) であるため失敗します。 最適化を行ったとしても、n = 200,000 ではこれは遅すぎます。 

重要な観察は、m の位置を固定することです。 すべての有効な部分配列には m が含まれている必要があります。そうでない場合は、その中央値を m にすることはできません。 部分配列を m の位置に固定したら、問題を、バランス状態を維持する左右の拡張の数を数えるという問題に変換します。 

配列を m を基準とした符号配列に変換します。m より大きいすべての要素は +1 に寄与し、m より小さいすべての要素は -1 に寄与します。 値 m 自体がピボットです。 ここで、これらの変換された値の合計が中央位置要件から導出される制約を満たす場合に限り、部分配列は中央値 m を持ちます。 

次に、問題を m の位置の周囲のプレフィックス合計に還元します。 m を含む部分配列は、そのインデックスの周囲の左境界 l と右境界 r を選択することに対応します。 中央値に関する条件は、両側のプレフィックスの合計がどのように比較されるかに関する条件になります。 

m の左側でプレフィックス合計値の頻度カウントを維持し、右側をスイープして、有効な一致を蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列内の m の位置を見つけます。 すべての有効な部分配列にはこの位置が含まれている必要があるため、これが以降のすべての推論のアンカー ポイントになります。 
2. 配列を、各要素が m より大きい場合は +1、m より小さい場合は -1 になる変換配列に変換します。 値 m 自体はニュートラルとして扱われますが、概念的には配列を左右の動作ゾーンに分割します。 この変換は、中央値の比較に必要な順序関係をエンコードします。 
3. この変換された配列上でプレフィックスの合計を作成しますが、m を基準とした位置のみを対象とします。 m から左に移動する残高と m から右に移動する残高を別々に計算します。 
4. m の左側について、すべてのプレフィックスのバランスを計算し、ハッシュ マップ内の頻度をカウントします。 各バランスは、特定の左境界で終わるプレフィックスに、小さな要素よりも大きな要素がいくつ多く現れるかを表します。 
5. m 自体で開始および終了するか、わずかに拡張するすべての部分配列を使用して答えを初期化し、実行バランスを維持しながら m の右側をスイープします。 
6. 右拡張ごとに、結合された部分配列が中央値条件を満たすように、左側に存在する必要がある必要な相補バランスを計算します。 左側の周波数マップを使用して、有効な部分配列を累積します。 
7. すべての権利境界からのすべての寄与を合計して、最終的なカウントを取得します。 

### なぜ効果があるのか

 この変換により、中央値条件が、m より大きい要素と m より小さい要素の間のバランス条件に変換されます。 m はすべての有効な部分配列内で固定されているため、正確さは絶対値ではなく相対カウントのみに依存します。 プレフィックス合計不変式により、m を含むサブ配列を左側の寄与と右側の寄与に分解できることが保証され、その結合バランスによって m がソート順で中央値として配置されるかどうかが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))

    pos = p.index(m)

    # transform: +1 if > m, -1 if < m
    a = [1 if x > m else -1 for x in p]

    # prefix sums to the left of m
    freq = {0: 1}
    s = 0

    for i in range(pos - 1, -1, -1):
        s += a[i]
        freq[s] = freq.get(s, 0) + 1

    ans = 0

    # sweep to the right including m
    s = 0
    for i in range(pos, n):
        if i != pos:
            s += a[i]

        # balance condition for median being m
        ans += freq.get(-s, 0)
        ans += freq.get(-s + 1, 0)

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず m の位置を特定し、次に m との比較に基づいて順列を +1 および -1 の値にエンコードします。 左側はプレフィックス合計の周波数マップに処理され、m で始まるか左方向に広がるサブ配列からの考えられるすべての寄与を表します。 

右スイープは実行中の合計を蓄積し、それを使用して相補的な左の合計をクエリします。 2 つのルックアップは、サブ配列の長さの 2 つの有効なパリティ構成に対応します。これは、偶数の長さの左中央の要素としての中央値の定義から生じます。 

左側のプレフィックス マップを 0 で初期化する場合は注意が必要です。これは、正確に m で始まる部分配列を表します。 右のスイープは m 自体から開始され、外側に移動した後にのみ蓄積されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    p = list(map(int, input().split()))

    pos = p.index(m)
    a = [1 if x > m else -1 for x in p]

    freq = {0: 1}
    s = 0
    for i in range(pos - 1, -1, -1):
        s += a[i]
        freq[s] = freq.get(s, 0) + 1

    ans = 0
    s = 0
    for i in range(pos, n):
        if i != pos:
            s += a[i]
        ans += freq.get(-s, 0)
        ans += freq.get(-s + 1, 0)

    return str(ans)

# provided sample
assert run("5 4\n2 4 5 3 1\n") == "4"

# minimum size
assert run("1 1\n1\n") == "1"

# m at start
assert run("3 1\n1 2 3\n") == "1"

# m at end
assert run("3 3\n1 2 3\n") == "1"

# all increasing
assert run("5 3\n1 2 3 4 5\n") == "5"

 ## 特殊なケース

 エッジ ケースの 1 つは、順列の最初の位置に m がある場合です。 この場合、左側のプレフィックス マップには、合計が 0 の空のプレフィックスのみが含まれます。すべての有効な部分配列は右に拡張する必要があり、すべての寄与は右側のスイープによって処理されるため、アルゴリズムは引き続き機能します。 

もう 1 つのエッジ ケースは、m が最後の位置にある場合です。 ここで、右側のスイープにはピボット自体のみが含まれており、すべての組み合わせは純粋に左側のプレフィックスから得られます。 周波数マップにより、すべての左のみのサブ配列が正しくカウントされることが保証されます。 

3 番目の微妙なケースは、m より小さいすべての要素が一方の側に表示され、それより大きいすべての要素がもう一方の側に表示される場合です。 これは高度に構造化されているように見えますが、プレフィックス合計表現は絶対的な配置ではなく累積的な不均衡のみに依存するため、すべての有効な組み合わせを捕捉します。
