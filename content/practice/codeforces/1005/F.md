 ## 解決策
 ## 問題の理解

 都市 1 が首都である都市の接続された無向グラフが与えられます。 このグラフから正確に選択する必要があります$n-1$選択したエッジがすべての都市を接続するように、つまりスパニング ツリーを形成するように道路を配置します。 

すべてのスパニング ツリーの中から、ただ 1 つのツリーを探しているわけではありません。 選択したツリー内の都市 1 からの最短経路距離を計算し、すべての頂点にわたるそれらの距離を合計し、この合計ができるだけ小さくなるようにします。 タスクは、最大で出力することです。$k$この最小可能な合計を達成するさまざまなスパニング ツリー。 

したがって、実際の問題は、ノード 1 をルートとする最適な BFS ツリーをすべて見つけることです。ここでの「最適」とは、個々の最短パスを確保するだけではなく、結果として得られるツリー内の距離の合計を最小化することを意味します。 

この制約により、私たちは構築ベースのソリューションを余儀なくされます。 と$n, m \le 2 \cdot 10^5$、スパニング ツリーを列挙したり、エッジ上で組み合わせ検索を実行したりすることは不可能です。 すべてのスパニング ツリーを保存するだけでも、指数関数的に処理されます。 追加の制約$m \cdot k \le 10^6$これが本当のヒントです。複数の有効な構造を生成することが期待されていますが、それぞれの構造は効率的に、ほぼ直線的に生成される必要があります。$m$。 

最短パスの選択肢が複数存在する場合、微妙なエッジ ケースが発生します。 たとえば、ノード 3 が 1-2-3 または 1-4-3 経由で等しい距離で到達できる場合、異なる最適なツリーには異なる親が含まれる可能性があります。 ノードごとに 1 つの親を修正する単純な BFS では、有効な代替が欠落し、答えが 1 つだけ生成されます。 もう 1 つの問題は、BFS ツリーが最適であると仮定することです。親の割り当てが異なるとすべてのノードにわたる合計距離の合計が変化することを考慮せずに、BFS タイが恣意的に切断された場合、必ずしも正しいとは限りません。 

## アプローチ

 ブルートフォース手法では、すべてのスパニング ツリーの生成を試行し、それぞれの距離を 1 から計算し、それらの合計を最小値に保ちます。 一般的なグラフ内のスパニング ツリーの数は指数関数的に増加する可能性があるため、これはすぐに失敗します。$n$。 BFS ツリーに制限してもあまり役に立ちません。各ノードには複数の有効な親がある可能性があり、組み合わせの選択肢が爆発的に増加します。 最悪の場合、すべてのノードがレベルにある場合、$d$レベルに 2 人以上の親がいる$d-1$、BFS ツリーの数は指数関数的です。 

重要な観察は、最適な構造はルート 1 をルートとする最短パス ツリーでなければならないということです。距離を置いてノードを接続する任意のエッジ$d$等しくない距離にあるノードまで$d-1$最短距離が維持されないため、最適解には現れません。 したがって、最初にノード 1 からの BFS 距離を計算します。これにより、各ノードの階層構造が修正されます。$v$距離がある$dist[v]$、有効な親エッジはレベルからのものでなければなりません$dist[v]-1$に$dist[v]$。 

ここで、問題はノードごとに選択することになります。$v \neq 1$、前の BFS レイヤーの隣接する親のうち 1 つだけの親。 このような選択により、有効な最短パス ツリーが生成され、距離は BFS レベルによって固定されるため、そのようなツリーはすべて同じ距離合計を持ちます。 有効なツリーの数は各ノードの BFS プリプロセッサの数の積ですが、最大で出力する必要があるだけです。$k$彼らのうち。 

これらのツリーは反復構築によって生成できます。 各ノードの最初の有効な親を使用して、正規の BFS ツリーから開始します。 次に、複数の有効な親を持つノードごとに、親の選択を変更することで分岐できます。 制御された DFS 方式で組み合わせを生成しますが、$k$出力。 制約$m \cdot k \le 10^6$列挙することを保証します$k$それぞれの構成$O(n)$、許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのスパニング ツリー) | 指数 | O(n + m) | 遅すぎる |
 | BFS + 親選択肢の制御された列挙 | O(k(n + m)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 から BFS を実行して最短距離を計算します$dist[v]$すべてのノードに対して。 これにより、最適なソリューションに現れる可能性のある唯一のレイヤーを知ることができます。 
2. すべてのノードについて$v \neq 1$、すべての隣人を集めます$u$そのような$dist[u] = dist[v] - 1$。 これらの唯一の可能な親は、$v$任意の最適なツリーで。 
3. 各ノードについて、候補となる親エッジのリストを保存します。 ノードに親候補がない場合、グラフに一貫性がなくなりますが、ノード 1 からの接続があるため、このようなことは起こりません。 
4. すべてのノードの最初の親候補を選択して、初期ツリーを構築します。 これにより、有効な最適解が 1 つ得られます。 
5. 各ノードの親の選択を決定変数として扱い、ノード全体で制御された DFS を実行し、親の割り当てを変更することにより、追加のソリューションを生成します。 完全な割り当てが形成されるたびに、対応するエッジ マスクを出力します。 
6.一旦停止$k$ソリューションが生み出されてきました。 

DFS は、意味のある分岐点、つまり複数の可能な親を持つノードのみを探索します。 単一の親を持つノードは分岐に寄与しないため、検索がコンパクトに保たれます。 

### なぜ効果があるのか

 すべての最適解では、ノード 1 からの BFS 距離を維持する必要があります。これは、偏差があると少なくとも 1 つの距離が増加し、合計が増加するためです。 距離が固定されると、すべての有効なスパニング ツリーは、ノードごとに 1 つの受信 BFS レイヤ エッジを選択することによって完全に決定されます。 アルゴリズムはこれらの選択肢を漏れなく正確に列挙し、それぞれの組み合わせが同一の距離構造を持つ有効なスパニング ツリーを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m, k = map(int, input().split())

g = [[] for _ in range(n)]
edges = []

for i in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append((b, i))
    g[b].append((a, i))
    edges.append((a, b))

# BFS distances
dist = [-1] * n
q = deque([0])
dist[0] = 0

while q:
    v = q.popleft()
    for to, _ in g[v]:
        if dist[to] == -1:
            dist[to] = dist[v] + 1
            q.append(to)

# candidate parents for each node
parents = [[] for _ in range(n)]
for v in range(n):
    for to, eid in g[v]:
        if dist[to] == dist[v] - 1:
            parents[v].append(eid)

# build initial solution (choose first parent edge)
choice = [0] * n  # edge index chosen for node v
for v in range(1, n):
    choice[v] = parents[v][0]

res = []
def build():
    mask = ['0'] * m
    for v in range(1, n):
        mask[choice[v]] = '1'
    return ''.join(mask)

# DFS enumeration
ans = []

def dfs(v):
    if len(ans) >= k:
        return
    if v == n:
        ans.append(build())
        return

    if v == 0:
        dfs(v + 1)
        return

    # iterate all parent choices
    saved = choice[v]
    for eid in parents[v]:
        choice[v] = eid
        dfs(v + 1)
        if len(ans) >= k:
            break
    choice[v] = saved

dfs(1)

print(len(ans))
print("\n".join(ans))
```BFS フェーズはレイヤー構造を修正し、その後のすべての決定が有効な最短パス エッジのみに制限されるようにします。 の`parents`list は、各ノードに対して許可される入力エッジを正確にエンコードします。 

DFS は、ノードごとに 1 つの受信エッジを選択することにより、すべての組み合わせを構築します。 再帰の深さは$n$ただし、分岐はノードに複数の有効な親がある場合にのみ発生します。 停止条件により、決して超えないことが保証されます$k$出力。 

微妙な点は、解決策の表現です。 完全なツリーを保存する代わりに、次の長さのバイナリ文字列を直接構築します。$m$、選択したエッジをマークします。 これにより、高価なエッジ再構成が回避され、各出力操作が線形に保たれます。$m$、制約の下で必要です$m \cdot k \le 10^6$。

 ## 特殊なケース

 次のような折れ線グラフでは、$1 - 2 - 3 - 4$、最初を除くすべてのノードには、親候補が 1 つだけあります。 このアルゴリズムの DFS は分岐のない単一のパスに縮退し、正確に 1 つのツリーを出力します。 これにより、代替の親が存在しなくても列挙ロジックが壊れないことが確認されます。 

完全に接続された三角形では、ノード 3 には 2 つの有効な親があります。 BFS レイヤーは単一の分岐点を生成し、アルゴリズムは正確に 2 つの構成を生成します。 この構造では、BFS 距離と一致するエッジのみが考慮されるため、無効な選択が正しく回避され、出力にサイクルや距離の違反が表示されないことが保証されます。
