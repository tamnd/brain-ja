 ## 解決策
 ## 問題の理解

 各文字が固定のブール値であるバイナリ文字列が与えられます。 プレイヤーはこれらの値を変更しません。 彼らの唯一のアクションは、隣接する位置の間のどこに二項演算子を配置するかを決定すること、具体的には各ギャップに対して AND または OR のいずれかを選択することです。 キャラクターが n 人いるため、n−1 個のギャップがあり、各ギャップはゲーム中に 1 回だけ埋められ、アリスとボブが交互に選択します。 

すべての演算子を配置した後、結果のブール式は固定リダクション ルールを使用して評価されます。AND 演算は OR 演算の前に任意の順序で解決されますが、最終値はリダクション順序に関係なく明確に定義されます。 

アリスは最終結果が true であることを望み、ボブはそれが false であることを望み、両方とも最適に実行されます。 

主な難しさは、プレイヤーが表現を直接評価しているのではなく、表現を形作っていることです。 それぞれの動きは、その直接の値ではなく、最終的な式の構造を変更します。 

この制約では、テスト ケース全体で合計 2⋅10^5 文字までが許可されるため、どのソリューションもテスト ケースごとに基本的に線形である必要があります。 すべてのゲーム、すべてのオペレーターの配置、またはすべての削減をシミュレートしようとするものは、実行可能な限界をはるかに超えています。 テスト ケースごとの O(n^2) 推論でも、最悪の場合にはすでに遅すぎます。 

素朴なアプローチは、考えられるすべての演算子の割り当てをシミュレートするか、すべての状態に対してミニマックスを実行することです。 n-1 個のギャップにはそれぞれ 2 つの選択肢があり、2^(n-1) の構成が得られるため、この問題はすぐに爆発します。 

また、微妙な落とし穴もあります。還元プロセスでは AND が OR よりも前に評価されるため、グループ化の効果は局所的な直感が示唆するよりも重要になります。 たとえば、101111 のような文字列は、AND がゼロを分離する方法に応じて大きく異なる動作をする可能性があります。 

よくある誤った仮定は、0 または 1 の数のみが重要であるというものです。 たとえば、「ゼロが少なくとも 1 つあれば、ボブは false を強制できる」と考えるのは間違いです。OR を使用するとゼロが最終評価から分離される可能性があるからです。 

## アプローチ

 ブルートフォース戦略では、n−1 個のギャップに AND/OR を割り当て、結果の各式を評価し、アリスに勝利の割り当てがあるかどうかをチェックして最適なプレイを想定するすべての可能な方法を列挙します。 最適なプレイ構造を無視してすべての割り当てを試しただけでも、すでに指数関数的な増加に直面しています。つまり、テスト ケースごとに 2^(n−1) の可能性があり、各評価のコストが O(n) となり、合計動作が実行不可能な O(n・2^n) になります。 

核となる単純化は、最適なプレイの下で AND と OR がどのような構造を課すかを理解することから生まれます。 AND は存続のために両方の側が真であることを強制するため「破壊的」ですが、OR は 1 つの真の側で十分であるため「寛容」です。 AND は OR より前に評価されるため、AND はセグメントを分離する傾向があり、結果が OR によって結合されるコンポーネントに文字列を効果的に分割します。 

これは戦略的な緊張を生み出します。AND を早めに配置すると、より大きな OR チェーンに吸収されるのを防ぐことでゼロを「保護」できますが、OR は 1 の影響を広げる傾向があります。 

重要な洞察は、ゲームがゼロを強制損失に分離できるかどうか、またはゼロを保護して最終的に生き残る真のセグメントにマージできるかどうかを制御することに帰着するということです。 最適なプレイでは、文字列の非常に小さな構造上の特徴のみが問題になります。つまり、重要な位置に少なくとも 1 組の連続する等しいビットが存在すること、および「含まれる」可能性がある孤立したゼロを除いて文字列が 1 によって支配されているかどうかです。

これは貪欲な特徴付けにつながります。結果は、アリスが OR-AND 削減を生き残るために連続するセグメントの少なくとも 1 つのセグメントを強制できるかどうかによって決まります。一方、ボブは戦略的に AND を挿入することでそのような生き残ったセグメントをすべて破壊しようとします。 完全な導出は、ローカル パターンのチェック、具体的には、ボブが周囲のゼロを分離する前に、アリスが 2 つの 1 を強制的にマージできる場所が存在するかどうかを確認することに要約されます。 

最適なプレイのインタラクションを単純化した後、決定は、ボブが結果をゼロにすることを可能にする特定のブロック構成をストリングが回避しているかどうかをチェックする線形スキャンに減ります。

 ## アルゴリズムのチュートリアル

 重要なのは、AND 配置によるボブの干渉にもかかわらず、アリスが確実に存続する真のコンポーネントを作成できるかどうかを検出することです。 

文字列をスキャンして、ローカル構造を推論します。 

1. 文字列が完全に 1 の場合、アリスが自明に勝つことに注目してください。 すべての 1 に対する AND/OR の組み合わせは、配置に関係なく true のままであるため、すべての演算は真実を保持します。 
2. 文字列にゼロが含まれている場合、ボブの目標は、AND 演算を使用してそれらを分離し、式を false に向けて折りたたむことです。 ただし、OR を配置すると、0 と 1 を接続することでこれに対処できます。 
3. 危機的な状況は、ゼロが「内部」にある場合、つまり両側に 1 がある場合に発生します。 その場合、ボブは多くの場合、アリスが式を支配するのに十分な分割をマージできないように分割を強制することができます。 
4. 決定的な構造は、隣接するペアが少なくとも 1 組存在するかどうか、または交互に移動しても完全に破壊できないセグメントを形成しているかどうかです。 このような安定した隣接関係が存在し、アリスが最初に利用できる場合、アリスが勝ちます。 
5. 具体的には、既知の削減は単純なルールにつながります。文字列がボブによって強制的に誤った評価に「完全に分離可能」にならない限り、アリスが勝ちます。これは、1 が分離しすぎて、すべての重要な領域で区切り文字として 0 が使用できる場合に発生します。 

実装面では、対称ブロック パターンで周囲のゼロによって完全に中和されていない連続する等しい文字のペアが少なくとも 1 組含まれているかどうかを文字列にチェックすることが簡素化されます。 実際には、これは、アリスに強制的な「マージの機会」があるかどうかを検出する線形スキャンに帰着します。 

### なぜ効果があるのか

 ゲームのダイナミクスは、文字列上にバイナリ ツリーを構築するものとして解釈できます。AND ノードはサブツリーを制約し、OR ノードはサブツリーを結合します。 ボブの最適なプレイは常に、生き残る真のコンポーネントの数を減らす境界に AND を挿入しようとしますが、アリスは OR 接続を通じて少なくとも 1 つの連続する 1 のチェーンを保持しようとします。 

不変条件は、各移動後の「実際の真のコンポーネント」の数は元の文字列の隣接構造によってのみ制御でき、連続したセグメントを越えた長距離相互作用は存在しないということです。 これにより、ゲーム状態空間がローカル パターンに折りたたまれ、貪欲なスキャンで十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        # If all ones, Alice wins immediately
        if '0' not in s:
            print("YES")
            continue

        # If all zeros, Alice loses
        if '1' not in s:
            print("NO")
            continue

        # Check for a pair of consecutive equal characters (key structural feature)
        ok = False
        for i in range(n - 1):
            if s[i] == s[i + 1]:
                ok = True
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この解決策は、まず、プレイに関係なく結果が固定される、すべて 1 またはすべて 0 のような些細なケースを削除します。 興味深い動作は、両方のシンボルが存在する場合にのみ現れます。 

最後のスキャンでは、隣接する等しいペアが少なくとも 1 つ存在するかどうかがチェックされます。 これは、アリスが最適なプレイの下で支配的な真のセグメントを保存または作成できるようにする構造的な「アンカー」です。 そのようなペアが存在しない場合、文字列は交互になり、Bob は安定した OR の伝播を妨げる破壊的な配置を強制することで評価を完全に制御できます。

 ## 特殊なケース

 010101010 のような完全に交互の文字列は、安定した領域を強化する隣接関係がない状況を作り出します。 この場合、アルゴリズムは等しいペアを見つけられず、正しく NO を返し、アリスが生き残った真のセグメントを形成するのを防ぐボブの能力と一致します。 

評価ルールの下では演算子の配置によってすべての 1 が false にならないため、完全に均一な 1 の文字列によってアリスは即座に勝利します。 スキャンはこれを早期に検出し、それ以上の理由を説明することなく YES を返します。 

0011100 など、ゼロで囲まれた 1 の単一ブロックを持つ文字列には、ブロック内に隣接する等しい 1 が含まれます。 アルゴリズムはこれを識別し、YES を返します。これは、ボブがブロックを分離しようとするのに対してアリスがそのブロックを保持できることを反映しています。
