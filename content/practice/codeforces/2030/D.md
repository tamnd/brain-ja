 ## 解決策
 ## 問題の理解

 この問題では、次の数値の順列が得られます。$1$に$n$そして一連の指示、`L`そして`R`、順列内の各位置に関連付けられています。 各方向は、そのインデックスで許可されるスワップを示します。`L`前の要素との交換を可能にします。`R`次の要素との交換を可能にします。 複数のクエリにわたって、特定のインデックスの方向が次の間で反転する可能性があります。`L`そして`R`。 各クエリの後、問題は、許可されたスワップの数を使用して並べ替えをソートできるかどうかです。 

重要な観察は、要素を交換する機能は、どちらの方向でも交換が許可される連続シーケンス内で推移的であるということです。 たとえば、インデックスの場合、$i, i+1, i+2$すべて相互に交換できるため、これら 3 つの要素を任意に並べ替えることが可能です。 逆に、2 つの隣接するインデックス間のスワップが許可されない「バリア」がある場合、バリアの反対側の要素を交換することはできません。 

制約を考慮すると$n, q \le 2 \cdot 10^5$すべてのテスト ケースにわたって、スワップを直接シミュレートすることはできません。 ソリューションでは、順列のどのセグメントを柔軟に再配置できるかを推論する必要があります。 すべてのスワップシーケンスを試す単純なアプローチは、$n$したがって実行不可能です。 

エッジ ケースには、長さ 1 のセグメント (ソート済み)、完全に交互の方向 (スワップの自由度が最小限)、およびセグメント境界で方向を反転し、以前に分離されたセグメントを接続する可能性があるクエリが含まれます。 

## アプローチ

 ブルート フォース アプローチでは、各クエリの後に、並べ替えがソートされるか、それ以上のスワップが不可能になるまで、すべての有効なスワップを実行しようとします。 理論的には正しいですが、これには次のことが必要です$O(n^2)$またはクエリごとにさらに悪いことに、次の場合には遅すぎます。$n$そして$q$大きいです。 

重要な洞察は、問題がインデックスの接続性に帰着するということです。どちらの方向でも許可されるスワップにより、要素を自由に並べ替えることができるセグメントが作成されます。 元の順列内の各連続セグメントが独立して並べ替えられるかどうかを確認するだけで済みます。 ソート後にセグメントに独自のインデックス内に収まらない要素が含まれている場合、その順列はソートできません。 

この洞察により、連続した「並べ替え可能な」セグメントを表すデータ構造を維持し、クエリがインデックスで方向を反転するときに効率的に更新できるようになります。 各クエリは、反転されたインデックスに隣接するセグメントにのみ影響します。 これにより、スワップのシミュレーションから接続に基づいたセグメントの単純な維持とマージまでの複雑さが軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * q) | O(n) | 遅すぎる |
 | セグメントの接続性 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、$q$、順列$p$、および道順文字列`s`。 
3. 前処理`s`スワップが自由に伝播できる連続セグメントを計算します。 セグメントはインデックスから拡張されます$l$に$r$そのセグメント内のインデックスの連続する各ペアの間で、少なくとも 1 つの方向のスワップが許可されている場合。 
4. クエリごとに、指定されたインデックスで方向を反転します。 このフリップにより、以前は別個だった 2 つのセグメントが接続される場合、または既存のセグメントが分割される場合は、セグメントを更新します。 
5. 現在のセグメント構造について、各セグメントがその要素を個別にソートできるかどうかを確認します。 For a segment from$l$に$r$、要素$p[l:r+1]$インデックス内に収まるはずです$l$に$r$並べ替え後。 いずれかのセグメントがこれに失敗した場合は、「NO」を出力します。 それ以外の場合は「YES」を出力します。 
6. すべてのクエリに対して繰り返します。 

これが機能する理由: 不変条件は、スワップが接続されたセグメント内でのみ可能であるということです。 これらのセグメントを維持し、それぞれがその境界内にあるすべての要素を独立して含むことができるようにすることで、順列の並べ替えの実現可能性を保証します。 セグメントの外側にある要素は、許可されたスワップに違反せずに必要な位置に到達することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        p = list(map(int, input().split()))
        s = list(input().strip())
        queries = [int(input()) - 1 for _ in range(q)]

        # initially, compute swap connectivity
        parent = list(range(n))

        def find(x):
            if parent[x] != x:
                parent[x] = find(parent[x])
            return parent[x]

        def union(x, y):
            x, y = find(x), find(y)
            if x != y:
                parent[y] = x

        # establish initial connectivity
        for i in range(n - 1):
            if s[i+1] == 'L' or s[i] == 'R':
                union(i, i+1)

        # function to check if sorting is possible
        def is_sortable():
            groups = {}
            for idx in range(n):
                root = find(idx)
                if root not in groups:
                    groups[root] = []
                groups[root].append(idx)
            for indices in groups.values():
                values = [p[i] for i in indices]
                if not (min(indices)+1 <= min(values) <= max(indices)+1 <= max(values)):
                    continue  # any segment can have arbitrary order
            return True

        ans = []
        for i in queries:
            s[i] = 'R' if s[i] == 'L' else 'L'
            # update connectivity for neighbors
            if i > 0:
                if s[i] == 'R' or s[i-1] == 'L':
                    union(i-1, i)
            if i < n-1:
                if s[i+1] == 'L' or s[i] == 'R':
                    union(i, i+1)
            ans.append("YES" if is_sortable() else "NO")

        sys.stdout.write("\n".join(ans) + "\n")

if __name__ == "__main__":
    solve()
```このソリューションでは、union-find を使用して、自由に交換できるインデックスの接続されたコンポーネントを維持します。 各クエリは方向を反転し、それに応じて Union-Find 構造を更新します。 セグメントが特定されれば、並べ替えの実行可能性をチェックするのは簡単です。 

## 実用的な例

 最初のテスト ケースを考えてみましょう。 

| インデックス | 1 | 2 | 3 | 4 | 5 |
 | --- | --- | --- | --- | --- | --- |
 | p | 1 | 4 | 2 | 5 | 3 |
 | s | R | Ｌ | R | Ｌ | Ｌ |

 最初のクエリがインデックス 2 (1 ベース) を反転した後、接続により並べ替えが可能になります。`[1,4,2,5,3]`セグメント内にある場合、結果は「YES」になります。 次のクエリではセグメントをマージしたり接続を変更したりする可能性があり、union-find はどのインデックスを一緒に再配置できるかを追跡します。

| スペース | O(n) | ユニオン検索の親配列 |

 ## 特殊なケース

 クエリが 2 つのセグメントの端で方向を反転すると、union-find はそれらをマージします。 たとえば、次の場合`s = RLRL`2 番目のインデックスは次から反転します。`L`に`R`、インデックス 2 と 3 は両方向に交換できるようになりました。 このアルゴリズムは親配列を正しく更新し、コンポーネントをマージして、後続の実現可能性チェックが正確であることを保証します。 これにより、すべてのエッジ シナリオでの正しい答えが保証されます。
