 ## 解決策
 ## 問題の理解

 配列が与えられ、処理する前に配列を並べ替えることができます。 修正したら、左から右にスキャンして、これまでに確認された最小要素とこれまでに確認された最大要素の 2 つの現在の値を維持します。 すべてのポジションで、これら 2 つの極端な差を記録し、最終スコアはこれらすべてのポジションごとのスプレッドの合計になります。 

私たちが持つ自由は完全に配列の順列にあります。 その後、プレフィックスの最小値とプレフィックスの最大値は決定的に変化します。 

制約は十分小さいので、$O(n^2)$あるいは$O(n \log n)$テスト ケースごとのアプローチは合計なので問題なく合格します。$n$これは、最適化のトリックではなく構造的な推論に焦点を当てるべきであることを示しています。 

ここでよくある間違いは、大きな数値を貪欲に最初または最後に置くと常にうまくいくと思い込むことです。 これは、プレフィックスの最小値とプレフィックスの最大値がローカルではなくグローバルに相互作用するため、失敗します。 たとえば、最大の要素を配置するのが早すぎると、局所的には有益であるように見えても、すぐに多くのプレフィックスの最大値が修正され、将来の寄与が減少します。 

もう 1 つの落とし穴は、プレフィックスの寄与を個別に最適化しようとすることです。 単独では最適に見えるプレフィックスは、最大値と最小値のギャップの将来の増分を破壊する可能性があるため、配置は全体として考慮する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべての順列を試し、それぞれのスコアを計算します。 スコアリング関数は明確に定義されているため、概念的には機能しますが、複雑さは階乗的であり、非常に小さな値を超えると不可能です。$n$。 

重要な観察は、スコアは中間要素の正確な順序ではなく、極端な要素がどのように進化するかのみに依存するということです。 最小値の増加を可能な限り遅らせながら、最大値を可能な限り「高い」状態にできるだけ長く維持したいと考えています。 これは、小さな要素を早めに配置してプレフィックスの最小値を低く維持し、大きな要素を後で配置してプレフィックスの最大値を徐々に増やし続けることを示唆しています。 

これを最適に達成する構造は、単純な貪欲な配置です。つまり、現在残っている最小値と最大値を交互にシーケンスにプッシュします。 これにより、最大値と最小値の間のギャップが大きいプレフィックスの数が最大化されます。 

直感的には、シーケンスを拡張するたびに、新しい全体的な最大値を導入するか、小さな最小値を維持する必要があり、極値を交互に繰り返すことで両方の力が最大限に活用されるようになります。

 ## アルゴリズムのチュートリアル

 まず配列をソートします。 並べ替えにより、最小要素と最大要素へのアクセスを制御できるようになります。 

次に、2 つのポインター (ソートされた配列の先頭と末尾に 1 つ) を使用して順列を構築します。 

各ステップで、残りの最小要素または残りの最大要素のいずれかを追加します。 選択は交互に行われます。 

プレフィックス評価を暗黙的にシミュレートします。プレフィックスの最小値と最大値を再計算する代わりに、極値を設定することで将来のスプレッド寄与が最大化されるという事実に依存します。 

最後に、構築された配列をスキャンし、プレフィックスの最小値と最大値を維持することでスコアを計算します。 

### なぜ効果があるのか

 各ポジションのスコアは、実行中の最小値と最大値がどれだけ離れているかによってのみ決まります。 多くのプレフィックス間でこの差を大きく保つ唯一の方法は、どちらかの極端な値の安定化を遅らせることです。 残りの最小値と最大値を交互に使用することで、どちらの極端な値も早期に「スタック」することがなくなり、すべてのプレフィックスにわたる累積差が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        l, r = 0, n - 1
        arr = []
        take_max = True
        
        while l <= r:
            if take_max:
                arr.append(a[r])
                r -= 1
            else:
                arr.append(a[l])
                l += 1
            take_max = not take_max
        
        mn = arr[0]
        mx = arr[0]
        ans = 0
        
        for x in arr:
            mn = min(mn, x)
            mx = max(mx, x)
            ans += mx - mn
        
        print(ans)

if __name__ == "__main__":
    solve()
```並べ替え後、残った最大値と最小値を交互に取得して順列を構築します。 これにより、極端な値がプレフィックス構造全体にバランスよく分散されるようになります。 最後のループでは、プレフィックスの最小値と最大値を使用して、定義に従ってスコアを単純に計算します。 

微妙な点は初期化です。最初の要素は最小値と最大値の両方を設定するため、最初の寄与は常にゼロになります。 また、交互方向は一貫して開始する必要があります。 構造全体で一貫している限り、どちらの側から始めても問題ありません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = []

            if take_max:

        mn = mx = arr[0]

        for x in arr:
            mn = min(mn, x)
            mx = max(mx, x)

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 一様な配列は最も単純な境界ケースです。 プレフィックスの最小値と最大値は常に等しいため、順列に関係なくすべての項がゼロとなるため、どのアルゴリズムもゼロを返さなければなりません。 

2 要素の配列は、コアのメカニズムを直接公開します。スコアは正確に絶対的な差であり、どの順序でも同じプレフィックス構造が生成されます。 

厳密に増加または減少する配列は、貪欲な交互が実際に有益であるか冗長であるかを構造に明らかにさせるため、便利です。 このような場合でも、交互戦略は、最大値が早期に導入され、最小値が遅れることを保証することにより、プレフィックス間の最大拡散を維持します。
