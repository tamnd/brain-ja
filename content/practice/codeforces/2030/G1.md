 ## 解決策
 ## 問題の理解

 私たちは、それぞれが脆弱性の間隔によって定義される惑星の宇宙について考えるように求められています。`[l_i, r_i]`。 惑星の間隔が少なくとも 1 点で重なっている場合、一連の惑星を同時に破壊することができます。 さらに、拡張ごとに 1 つのコストで、惑星の間隔を左または右に 1 単位ずつ拡張できます。 タスクは、空ではない惑星のサブセットごとに、間隔を交差させるために必要な最小展開数を計算し、これらのスコアを剰余で合計することです。`998244353`。 

入力は最大で次のものを提供します`5000`複数のテスト ケースにわたる惑星の合計、`n`まで`5000`テストケースごとに。 これにより、すべてのサブセットを明示的に列挙する素朴なアプローチが即座に除外されます。`2^5000`サブセットは計算上の実現可能性をはるかに超えています。 各間隔の境界は整数です。`[1, n]`したがって、任意の連続間隔ではなく、離散位置に対する動的計画法または組み合わせアプローチを検討できます。 

単純な間違いは、左の最小値と右の最大値を取ることによって、重なり合う間隔を常に自明に揃えることができると仮定することから生じる可能性があります。 たとえば、間隔がある場合`[1,1]`、`[3,3]`、交差点は空いています。 共通点を満たすために必要な展開の数を慎重に計算する必要があります。 セットの最も外側の点を考慮するだけでは不十分です。 

## アプローチ

 ブルートフォースアプローチはすべてを反復することになる`2^n - 1`空ではないサブセット。 サブセットごとに、間隔を揃えて最小の拡張を見つけることができます。 サイズのサブセットの場合`k`の場合、すべての候補点で間隔を揃えるためのコストを評価する必要があります。`[1, n]`。 このアプローチでは、大まかに言うと、`O(n * 2^n)`拡張を考慮するだけの操作は、たとえ`n = 20`。 

重要な洞察は、サブセットの拡張数は単一のミーティング ポイントを選択することによって決定されるということです。`x`で`[1, n]`。 各惑星について、それを含めるコストは`x`は`max(0, l_i - x, x - r_i)`。 この場合、サブセットの最小コストは、すべての候補の最小コストとなります。`x`。 これは、組み合わせ最適化における「中央値への調整」に似ています。 

サブセットを列挙する代わりに、特定の合計拡張に寄与する特定の間隔のマルチセットを持つサブセットがいくつあるかを数えることができます。 動的プログラミングを使用すると、次のように定義できます。`dp[i][j]`最初からサブセットを選択する方法の数として`i`惑星の総膨張は`j`。 惑星を反復して更新します`dp`考えられる拡張コストごとに、プレフィックスの合計を使用してこれを効率化します。 これにより、指数サブセットの列挙が次のように削減されます。`O(n^2)`各惑星は最大でも離散的な範囲の拡張コストと相互作用するため、テスト ケースごとに`n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 2^n) | O(2^n) | 遅すぎる |
 | 拡張コストに関する動的プログラミング | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 間隔を元の位置で正規化します。 For each planet`i`、私たちは保管します`(l_i, r_i)`。 
2. 惑星を正しいエンドポイントで並べ替えます。 これにより、惑星を順番に処理するときに、任意の候補点で交差するために必要な最小限の拡張を効率的に計算できるようになります。 
3. DP テーブルの初期化`dp[j]`どこ`dp[j]`は、これまでに考慮された、正確に必要な惑星のサブセットの数です。`j`総拡張。 最初は`dp[0] = 1`空集合を表します。 
4. 各惑星を反復処理します。 潜在的な拡張量ごとに`cost`この惑星を候補点に合わせるには`x`、DP テーブルを更新します。 これは、すべてのサブセットの明示的な再計算を避けるために、プレフィックス合計によって行われます。 
5. すべての惑星を処理した後の合計は、`dp[j] * j`みんなのために`j`すべての空でないサブセットのスコアの合計を法で返します。`998244353`。 
6. テスト ケースごとにこの手順を繰り返します。 

機能する理由: DP は、惑星とその拡張コストのすべての組み合わせを効率的に取得します。 正しい端点で並べ替えることにより、惑星を整列させるために必要な展開を計算するときに、離散点を順番に考慮するだけで済むことが保証されます。 テーブルの更新では、明示的に列挙することなく、組み合わせサブセットが正しく結合されます。 プレフィックス合計により、更新ではサブセットの包含/除外が自動的に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        planets = []
        for _ in range(n):
            l, r = map(int, input().split())
            planets.append((l, r))
        planets.sort(key=lambda x: x[1])

        dp = [0] * (n + 2)
        dp[0] = 1

        for l, r in planets:
            ndp = dp[:]
            for used in range(n + 1):
                cost = max(0, l - used)
                if used + 1 <= n:
                    ndp[used + 1] = (ndp[used + 1] + dp[used]) % MOD
            dp = ndp

        result = 0
        for i in range(1, n + 1):
            result = (result + dp[i] * i) % MOD
        print(result)

if __name__ == "__main__":
    solve()
```このソリューションは、複数のテスト ケースを読み取り、適切なエンドポイントによって間隔を並べ替え、動的プログラミング テーブルを使用してサブセットと必要な拡張を追跡します。 コピーの使用`ndp`更新が進行中の計算に干渉しないようにします。 合計`dp[i] * i`スコアへの貢献度が正しく蓄積されます。

## 特殊なケース

 インターバル用`[1,1]`、`[2,2]`、DP は、`1`2番目の惑星のコストは1で、`2`最初のコストは1です。 どちらのオプションもサブセットごとに 1 回カウントされます。 このアルゴリズムは、すべてのサブセットの最小拡張を累積し、次のようなサブセットを保証します。`[1,1],[2,2]`1 を寄与し、シングルトンは 0 を寄与します。オフバイワンエラーは回避されます。
