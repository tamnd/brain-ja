 ## 解決策

 ## 問題の理解

 グライダーは、飛行機が高さ h に固定されている間に、ある整数 x 座標で移動中の飛行機から放たれます。 解放されると、グライダーは常に 1 秒あたり 1 ユニット右に移動します。 同時に、高度は 1 秒あたり 1 単位ずつ減少するため、基本的には斜めに降下します。 

地上には上昇気流が存在する特別な水平間隔が存在します。 グライダーがこれらの間隔のいずれかを超えると、その秒間高度の低下が止まり、依然として同じ速度で右に移動し続けます。 これらの間隔の外では、通常どおり下降します。 グライダーは高度がゼロになると停止します。 

タスクは、着陸までの合計水平移動距離が最大になるように、飛行経路に沿った整数の開始 x 位置を選択することです。 

重要な相互作用は、各飛行間隔が効果的に降下を「一時停止」し、グライダーが空中に留まる時間を延長することです。 開始点が固定されると動きは決定的になるため、問題は、軌道ができるだけ多くの効果的な「高さ節約」機会と重なるように、最適な開始位置を選択することになります。 

制約が十分に大きいため、開始点ごとのシミュレーションは不可能です。 最大 2 × 10^5 のセグメントと最大 10^9 の座標を使用して、各候補スタートの全飛行を再計算するソリューションは、制限時間を大幅に超えることになります。 スキャン間隔のせいで、単一のシミュレーションでも O(n) 以下になるため、すべてのスタートを試すのは現実的ではありません。 

主なエッジ ケースは、区間エッジでの境界動作から発生します。 グライダーがインターバル終了点に正確に着陸すると、その恩恵を受けられなくなるため、オフバイワンのハンドリングが重要になります。 もう 1 つの微妙なケースは、間隔が離れている場合です。どの間隔も常に役立つという素朴な貪欲な仮定は誤りです。なぜなら、グライダーがあまりにも早く降下すると、着陸前に間隔に到達できない可能性があるからです。 

## アプローチ

 開始位置を固定すると、グライダーの高さはステップごとに 1 ずつ減少します。これは、ちょうど h 個の「自由降下単位」を費やす必要があることを意味します。 インターバル内に入るたびに降下が一時停止され、インターバル内で費やされる 1 秒あたりの高度が 1 単位節約されます。 

したがって、問題は次のようになります。特定の開始点で、パスが結合セグメントと重複する合計秒数は何秒でしょうか。また、それによって最終的な x 位置はどのくらい延長されるでしょうか?

 ブルートフォースアプローチでは、対象範囲内で可能なすべての整数の開始位置を試し、それぞれの完全な飛行をシミュレートします。 各シミュレーションでは、間隔をスキャンするか、間隔の上にポインタを維持するため、開始ごとに O(n) のコストがかかります。 開始位置は最大 10^9 に及ぶため、間隔のエンドポイントに制限しても O(n) 個の候補が残り、合計操作が O(n^2) となり、遅すぎます。 

重要な観察は、グライダーの軌道が構造化された方法で間隔と相互作用しているということです。 開始点を固定すると、パスは高さがどの程度維持されるかに応じた長さの x 軸上の線分になります。 各間隔の寄与は、そのセグメントとの重複にのみ依存します。 

開始ごとにシミュレーションするのではなく、視点を逆転させます。 フライトは X 軸に沿って「高さバジェット」 h を消費すると考えますが、インターバルを通過するたびに、そこで高さは消費されないため、使用可能なバジェットが効果的に拡張されます。 これにより、間隔とギャップの和集合に対するスライディング ウィンドウ スタイルの解釈が得られます。

2 倍の表現を処理することで構造を圧縮します。区間ごとに、到達可能な距離をどのように変換するか、および有効高さの消費をどのように変更するかを計算します。 間隔は重複しないため、それらを順番に処理し、連続する間隔を連鎖させることで開始点がどの程度「利益」を得ることができるかを維持できます。 

最適な解決策は、間隔の境界に合わせた潜在的な開始位置ごとに、間隔の外側の高さを貪欲に消費し、間隔内の消費をスキップすることによって、グライダーがどこまで伝播できるかを追跡することに帰着します。 2 ポインターまたはプレフィックス ベースの DP は、間隔から蓄積された「保存された高さ」を調整しながら、到達可能な最大エンドポイントを維持します。 

重要な構造的洞察は、答えは間隔の境界、または新しい間隔が軌道に影響を及ぼし始める点で得られるため、すべての整数ではなく O(n) 個の候補のみを評価するということです。

 ## アルゴリズムのチュートリアル

 1. 間隔を前処理された構造として分類して解釈し、グライダーが任意の開始点から気流内でどれくらいの時間を費やすかをすぐに知ることができます。 間隔はすでにソートされた順序で互いに素な状態で与えられているため、それらをシーケンスとして直接使用できます。 
2. ある区間の左境界にある開始点を考えます。 この時点から、グライダーの有効高度がゼロに達するまでにグライダーがどのくらいの距離を進むかをシミュレートしますが、インターバル内に入るたびに高度の消費を変更します。 
3. インターバルにわたってポインタを維持し、現在到達可能な X 座標と残りの有効高さのバジェットという 2 つの量を追跡します。 
4. 現在位置がすべての区間の外側にある場合、右に移動すると 1 歩につき 1 単位の高さを消費するため、到達可能な距離は残りの高さによって制限されます。 
5. 区間に入ると、その区間を出るまですぐに高さの減少を停止します。 これは、そのセグメントの長さの消費高を「スキップ」できることを意味し、インターバルの長さからそのスパンで失われる分を差し引いた分だけ、最終的なリーチを効果的に延長できます。 
6. 高さのバジェットがなくなるまで、間隔を順番に移動し続け、その寄与分を合計到達可能距離に統合します。 
7. 各間隔の開始位置を候補開始位置として試し、上記のプロセスを使用して到達可能な最も遠いエンドポイントを計算し、グローバル最大値を更新します。 

これが機能する理由は、最適解が常に区間境界で始まるためです。 ギャップ内のスタートは、到達可能な距離を減らすことなく次のインターバルスタートにシフトできます。これは、より早いスタートポイントは追加のインターバル範囲を獲得せずに不必要な降下を追加するだけであるためです。 これにより、間隔の開始がすべての可能な開始を十分に表す単調な構造が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, h = map(int, input().split())
    seg = [tuple(map(int, input().split())) for _ in range(n)]

    ans = 0
    j = 0

    for i in range(n):
        start = seg[i][0]
        height = h
        pos = start

        j = i

        while j < n:
            l, r = seg[j]

            if pos < l:
                dist = l - pos
                if height <= dist:
                    ans = max(ans, pos + height)
                    break
                height -= dist
                pos = l

            if pos <= r:
                pos = r
                j += 1
            else:
                j += 1

        else:
            ans = max(ans, pos + height)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、潜在的な開始アンカーとして各間隔にわたって反復されます。 開始ごとに、残りの高さを追跡しながら前進をシミュレートします。 位置が区間外の場合はギャップ長に応じて高さが減少します。 インターバル内にある場合、ポインタは高さを減らさずにインターバルを横切ってジャンプし、実質的にセグメント全体を自由な動きとして扱います。 ネストされたポインターにより、開始ごとに各間隔が最大 1 回アクセスされることが保証されます。 

微妙な点はギャップで高さが尽きた時のブレイク具合。 その瞬間、グライダーはギャップ内に着陸するため、それ以上の間隔を処理することなく、最終位置が pos + height として直接計算されます。

 ## 特殊なケース

 最初のエッジケースは、グライダーがインターバル内でスタートする場合です。 その場合、インターバルを終了するまで、高さの損失がゼロになるというメリットがすぐに得られます。 アルゴリズムは次のことをチェックするため、これを処理します。`pos <= r`高さを消費せずにインターバルの終わりに直接ジャンプします。 

別のエッジケースは、グライダーがちょうどインターバルの境界で高度を使い果たす場合に発生します。 高さが位置 l で正確にゼロになる場合、最終的な答えは pos + 高さとして計算され、誤って次の区間に入ることなく正しい x 座標に正確に到達します。 

最後のエッジ ケースは、ギャップの枯渇により、特定のポイント以降に到達可能な間隔がない場合です。 ブレーク条件により、高さが次の間隔に到達するのに不十分になると、シミュレーションが直ちに終了し、後のセグメントが誤って含まれることがなくなります。
