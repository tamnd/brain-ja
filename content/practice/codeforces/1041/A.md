 ## 解決策
 ## 問題の理解

 私たちは、盗難に遭っても生き残ったキーボードのインデックスのセットを受け取りました。 重要な隠された構造は、盗難前はすべてのキーボードが、x、x+1、x+2 など、未知の長さまでの整数の 1 つの連続ブロックを形成していたことです。 盗難の後、それらの連続した整数の一部が失われ、元の連続したセグメントの順序付けされていないサブセットが残ります。 

私たちの仕事は、開始値 x と完全な連続セグメントの元の長さの両方を自由に選択できると仮定して、盗まれた可能性のあるキーボードの最小数を決定することです。 

私たちが実際に行っていることは、指定された数値を連続する値の最小長の整数間隔に埋め込むことです。 その間隔が固定されると、指定されたセットにないその間隔内のすべての整数が盗まれているはずです。 したがって、盗まれたキーボードを最小限に抑えることは、選択した間隔内にあるものの入力に含まれない整数の数を最小限に抑えることと同じです。 

制約 n ≤ 1000 は、O(n^2) の推論を快適に実行できることを意味します。 要素間のすべてのギャップを並べ替えて検査するソリューションは、すでに限界内に十分収まっています。 立体的以上のものは不要です。 

開始点 x が固定されていないという事実から、微妙なエッジ ケースが発生します。 たとえば、観測された最小値が 8 の場合、欠損値の解釈方法に応じて、真のシーケンスは 1、8、または 10 から始まっている可能性があります。 単純な間違いは、シーケンスが min(a) で開始する必要があると想定することです。これは、元の連続ブロックがさらに左に拡張されている可能性を無視します。 

もう 1 つの失敗モードは、内部ギャップを無視することです。 たとえば、残りのキーボードが 1、10、11、12 の場合、極端な値だけを見るだけでは十分ではありません。 1 と 10 の間のギャップは、一貫した再構築における同じ元の連続ブロックの一部である要素 2 から 9 が欠落していることを意味します。 

## アプローチ

 ブルートフォースのアイデアは、与えられたすべての数値が [x, y] に収まるように、考えられるすべての開始点 x とすべての終了点 y を試すことです。 候補区間ごとに、その区間で欠落している整数の数を確認します。 これは、未知の元のストア構成を直接シミュレートするため、正しいです。 ただし、間隔の境界は最大 10^9 の範囲に及ぶ可能性があり、すべての可能性を試すには膨大な範囲にわたって反復する必要があり、実行不可能になります。 

重要な観察は、最適な間隔は、端に不必要なたるみを持たずに既存の数値をしっかりと包み込む必要があるということです。 残りのキーボードをソートして順序を修正する場合、有効な元のシーケンスは観測された最小値から観測された最大値までをカバーする必要がありますが、不一致を減らすために必要な場合にのみ間隔を内側のギャップに拡張することも最適な場合があります。 ただし、間隔を延長しても潜在的な欠落要素の数が増加するだけであるため、最良の戦略は、指定されたすべての値を含む最小の連続ブロックとして間隔を固定することです。 

その間隔内で欠落しているキーボードの数は、単に間隔の長さと観察された要素の数の差に相当します。 間隔の長さは max(a) - min(a) + 1 であり、n を減算します。 

したがって、問題は並べ替え (または最小値と最大値のスキャン) と単純な算術式の計算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 間隔を超えた総当たり攻撃 | O(範囲・n) 以上 | お(1) | 遅すぎる |
 | ソート + スパンの計算 | O(n log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 残りのキーボード インデックスをすべて読み取り、リストに保存します。 これらは、未知の連続区間内の点を表します。 
2. それらの中で最小値と最大値を特定します。 これら 2 つの値は、残りのすべてのキーボードを含めることができる最小間隔を決定します。これは、有効な元の連続ブロックは少なくとも、観察されたインデックスの最小値から最大値までにわたる必要があるためです。 
3. max_value - min_value + 1 を使用して、この間隔内の整数の合計数を計算します。これは、欠落要素による制約が考慮されない場合の完全な候補元店舗在庫を表します。 
4. この間隔の長さから、観察されたキーボードの数 n を引きます。 残っているのは、元のブロックには存在していたはずだが最終セットには存在しない整数であり、これは盗まれたキーボードに正確に対応します。 

### なぜ効果があるのか

 有効な元の構成はすべて、観測された値をすべて含む必要がある連続した整数のシーケンスです。 したがって、そのエンドポイントは最大でも min(a)、少なくとも max(a) である必要があり、そうでない場合は、観測値の一部がシーケンスの外側に存在することになります。 これらの境界を超えて拡張しても、実現可能性は向上せず、暗黙の欠落要素の数が増加するだけです。 したがって、可能な最小の元のシーケンスは正確に間隔 [min(a), max(a)] であり、その間隔内に存在しないすべての整数は盗まれたキーボードに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    mn = min(a)
    mx = max(a)
    
    print((mx - mn + 1) - n)

if __name__ == "__main__":
    solve()
```このソリューションは入力を線形時間で読み取り、最小値と最大値の 2 つの集計統計のみを計算します。 引き算`(mx - mn + 1) - n`残りのすべてのキーボードをカバーする可能な最小の連続間隔内の欠落している整数を直接カウントします。 

よくある実装上の間違いは、並べ替えてからギャップを個別にカウントしようとすることですが、これはここでは不要であり、off-by-one エラーのリスクが高まります。 もう一つの間違いは、`+1`間隔の長さを計算するときは、両方のエンドポイントが含まれるためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 最小値と最大値を計算する単一パス |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    return str(max(a) - min(a) + 1 - n)

# provided sample
assert run("4\n10 13 12 8\n") == "2"

# single element
assert run("1\n100\n") == "0"

# already consecutive
assert run("5\n1 2 3 4 5\n") == "0"

# large gap
assert run("3\n1 100 101\n") == "98"

# unordered input
assert run("4\n8 10 13 12\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 0 | キーボードが 1 つしかない場合、盗難は発生しません。 
| 連続ブロック | 0 | 完全なシーケンスを処理します。 
| 大きなギャップ | 98 | 広い間隔にわたる正確性 |

 ## 特殊なケース

 入力などの単一キーボードの場合`1 / 100`、アルゴリズムは min = max = 100、区間の長さ 1、結果 0 を計算します。これは、モデルが縮退区間を正しく処理していることを確認します。 

次のような完全に連続したセットの場合`1 2 3 4`、最小は 1、最大は 4 で、間隔の長さは 4、結果は 0 になります。これにより、要素が欠落していない場合に誤検知が発生しないことが保証されます。 

大きな隙間の場合は、`1 100 101`、min = 1、max = 101 の場合、間隔の長さは 101 となり、3 を引くと 98 個のキーボードが欠落します。 これは、分布に関係なく、このメソッドが境界区間内のすべての目に見えない整数をどのように考慮するかを直接示しています。
