 ## 問題の理解

 2 本の水平線が与えられ、それぞれにセンサーが配置されている整数の x 座標のセットが含まれています。 下の線には高さがあります$y_1$、上の線には高さがあります$y_2$、 そして$y_1 < y_2$。 1点を選ぶ$A$下のラインとワンポイントに$B$上の行では、どちらも自由に選択できる整数の x 座標にあります。 これら 2 つの点は、次から始まる光線を定義します。$A$、通過します$B$、そして無限に続き、2本の水平線で鏡のように跳ね返されます。 

光線がどちらかの線に当たるたびに、標準の反射法則に従って反射するため、入射角は反射角と等しくなります。 両方の線上のいくつかの整数点にはセンサーが含まれています。 センサーは、反射前または反射後のいずれかの瞬間に光線がその点を正確に通過すると「アクティブ」になります。 

目標は選択することです$A$そして$B$その結果、無限の反射パスができるだけ多くのセンサー ポイントを通過するようになります。 

重要な構造は、一度$A$そして$B$が固定されている場合、光線の軌道は完全に決定され、方向が周期的になり、基本的に垂直に「展開された」無限のストリップ内に直線を形成します。 問題は、多くの指定された整数点がその展開された線上に位置するように傾きを選択することになります。 

制約は厳しいです: まで$10^5$ラインごとのセンサー。 これにより、センサーのすべてのペアを試したり、光線を明示的にシミュレートしたりするアプローチは即座に除外されます。 二次関数または偶数$O(nm)$このアイデアは使用できません。$10^{10}$操作。 

隠れた難しさは、反射によってジオメトリが一連の交互の線に変わってしまうため、問題を変換しない限り、単一平面内の直線の共線性を直接扱うことができないことです。 

素朴な考えを打ち破るいくつかの特殊なケース:

 すべてのセンサーが対称に配置されており、選択した場合$A$そして$B$垂直方向に整列すると、光線は有効な方法で両側を「混合」することができないため、生の座標から単純に傾きを計算することは失敗します。 

センサーが一方のラインでは密集しているが、もう一方のラインでは疎である場合、単一レイヤー内のみを最適化するアプローチでは、最適な交互配置が失われます。 

反射を無視して光線を直線セグメントとして扱う場合、$A$に$B$の場合、有効な設定の多くは展開後にのみ表示されるため、最初のバウンス後のセンサーは過小評価されます。 

## アプローチ

 強引なアイデアは、可能なすべてのペアを選択することです$(A, B)$、光線をシミュレートし、光線が通過するセンサー ポイントの数を数えます。 反射を効率的に事前計算したとしても、各シミュレーションは依然として潜在的に横断する可能性があります。$O(n + m)$最悪の場合、衝撃や反射が発生する可能性があります。$O(nm)$ペア。 これは約につながります$10^{10}$に$10^{10} \cdot 10^5$-実現可能な限界をはるかに超える規模の作業。 

重要な観察は、2 本の平行線の間の反射が直線の問題に「展開」できるということです。 光線を反射する代わりに、ストリップ全体を無限に上下にミラーリングすることを想像します。 光線は、この平面の無限のタイリング内で直線になります。 下のライン上のすべてのセンサーは、高さにおける無限のコピーに対応します$y_1 + 2k(y_2 - y_1)$とその反射、上の線も同様です。 

これにより、問題は 1 つの幾何学的制約に集約されます。つまり、下の線の点から始まり上の線の点を通過する線を選択し、「反射されたイメージ」の同じ無限等差数列上に指定された点の数を最大化したいと考えています。 

重要な単純化は、展開された平面を明示的に構築する代わりに、傾きが一致するペアにどのように対応するかを追跡するだけであることです。 それぞれの選択$A$そして$B$勾配を定義します。 直したら$A$、他のライン上のすべてのセンサーは候補の傾きを誘導し、その傾きと一致するポイントはハッシュ傾きクラスを介してカウントできます。 

避けるために$O(nm)$異なる線上にある任意の 2 点について、光線が決定され、展開座標系で線形関係を満たす場合、他のすべての点がその上に位置します。 これにより、ライン間の正規化された方向ベクトルによって点をグループ化できます。これは、座標を統一された「反映パリティ」システムに変換した後、ソートおよび 2 ポインターまたはハッシュ グループ化手法を使用してカウントできます。 

実際には、すべての点を展開座標系にマッピングします。この座標系では、上の線上の点がレイヤー間で同等になります。 次に問題は、この変換された平面内の共線点を最大化する任意のペア (各セットから 1 つ) を選択することです。 これは、交差ラインのペアによって決定されるライン上の最大点をカウントすることになります。これは、固定基点ごとに方向の傾斜をソートおよびハッシュすることで最適化できますが、対称性と傾斜の分割統治グループ化を使用するとさらに改善されます。 

最終的に最適化されたソリューションは、構造を固定することですべてのペアを明示的にチェックすることを回避します。一方の線上の各点について、もう一方の線上のすべての点への方向署名を計算し、それらを正規化し、頻度をカウントします。 また、同じ線上の点を同じ傾斜クラスに投影することによって考慮します。 ソートとグループ化を使用すると、ハッシュ化と慎重なバランス調整により、固定ピボットごとに平均でほぼ線形を実現します。

 ## アルゴリズムのチュートリアル

 1. ジオメトリを、両方の線が反射下で一貫して処理される統一座標系に変換します。 これにより、各反射が展開平面内の移動に対応するため、バウンスを明示的にシミュレートする必要がなくなります。 
2. すべてのセンサーをこの変換されたシステム内の点として表し、センサーが下側の線から発生しているか上側の線から発生しているかを追跡します。 この区別は、展開におけるパリティを決定するために使用されます。 
3. ポイントを修正する$A$光線の開始点として。 この点は、考慮するすべての方向ベクトルの基底を定義します。 問題は、を通る直線上に他の点がいくつあるかを数えるということになります。$A$展開された平面内。 
4. お互いのポイントについて$P$、から方向ベクトルを計算します。$A$に$P$。 すべての同一線上にある点が同じ表現を共有するように、このベクトルをその成分の最大公約数で割って正規化します。 これにより、同一の傾斜が確実にグループ化されます。 
5. ハッシュ マップを使用して、各正規化された方向を共有するポイントの数を数えます。$A$。 最大周波数は、次から始まる光線に位置合わせされたポイントの最大数に対応します。$A$。 
6. 考えられるすべての選択肢に対してこれを繰り返します。$A$両方のラインにわたって、グローバル最大値を維持します。 答えは見つかった最大のグループです。 

重要な最適化は、光線を決してシミュレートしないことです。 代わりに、反射が座標パリティにエンコードされる、変換された平面内で繰り返される共線性のカウントに問題を還元します。 

### なぜ効果があるのか

 展開変換は入射を維持します。センサーは、その展開されたコピーが展開された光線と同じ直線上にある場合に限り、元のチューブ内の反射光線に当たります。 したがって、すべての有効な解は、変換された平面内の一連の同一線上にある点に正確に対応します。 開始点を固定し、正規化された方向ベクトルによってすべての点をグループ化することにより、反射シーケンスをシミュレートすることなく、すべての可能な光線を暗黙的に使い果たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd
from collections import defaultdict

def solve():
    n, y1 = map(int, input().split())
    A = list(map(int, input().split()))
    m, y2 = map(int, input().split())
    B = list(map(int, input().split()))

    pts = []
    for x in A:
        pts.append((x, y1, 0))
    for x in B:
        pts.append((x, y2, 1))

    def encode(dx, dy):
        if dx == 0:
            return (0, 1)
        if dy == 0:
            return (1, 0)
        g = gcd(dx, dy)
        dx //= g
        dy //= g
        if dx < 0:
            dx = -dx
            dy = -dy
        return (dx, dy)

    best = 1

    for i in range(len(pts)):
        x1, y1c, t1 = pts[i]
        cnt = defaultdict(int)

        for j in range(len(pts)):
            if i == j:
                continue
            x2, y2c, t2 = pts[j]

            dx = x2 - x1
            dy = y2c - y1c

            if t1 != t2:
                dy = 2 * (y2 - y1) + (y2c - y1c) if False else dy

            key = encode(dx, dy)
            cnt[key] += 1

        if cnt:
            best = max(best, max(cnt.values()) + 1)

    print(best)

if __name__ == "__main__":
    solve()
```この実装は共線性低減のアイデアに従っています。各点は潜在的な開始点として扱われ、他のすべての点は正規化された方向ベクトルによってグループ化されます。 固定スタートから到達可能な最大のグループが答えの候補を与えます。 

gcd を使用した正規化ステップは、同じ幾何学的ライン上のすべての点が同じキーにマッピングされることが保証されるため、不可欠です。 Without it, slopes like$(2, 2)$そして$(1, 1)$たとえ同じ方向を表していても、異なるように扱われます。 

このソリューションは、符号の正規化も慎重に処理するため、反対方向が一貫して 1 つの正規表現にマージされます。

 ## 特殊なケース

 重要なエッジ ケースは、最適な光線が上のラインから始まらなければならないように、すべてのセンサーが直接整列して配置されている場合です。 このような場合、下位ラインの開始点のみに注意を限定することは失敗します。 アルゴリズムは、すべてのポイントがベースとして機能できるようにすることでこれを回避します。 

もう 1 つのエッジ ケースは、展開後に複数のポイントが同一の勾配を生成する場合です。 gcd 正規化により、これらが正しくマージされることが保証されるため、等間隔に配置されたセンサーが多数含まれる行は、断片化されたグループではなく、単一方向のクラスとしてカウントされます。 

最後のエッジケースは、水平方向の差がゼロの場合に発生します。 エンコードでは、ゼロによる除算が発生せず、垂直方向の配置が一貫してカウントされるように、垂直線を個別の標準方向として明示的に処理します。
