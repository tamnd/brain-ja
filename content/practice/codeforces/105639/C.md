 ## 解決策
 ## 問題の理解

 私たちには、一方向のトランジションによって接続された交差点の有向ネットワークが与えられています。 各遷移には、移動時間と熱変化という 2 つの属性があります。 トランジションが屋外の通りを表す場合、現在の熱が減少します。 建物の廊下内にある場合、熱が増加します。 解釈に関係なく、各動作は実行中の「温度状態」を決定的に変化させます。 

旅行者は熱がちょうど 0 の交差点 1 から出発し、交差点に到達したいと考えています。\(n\)。 移動は、常に熱量が以下の範囲内に留まっている場合にのみ有効です。\(-30\)に\(+30\)。 熱がこの範囲外に押し出されるような動きをした場合、その動きは禁止されます。 

目標は、ノード 1 からノードまでのすべての有効なルートの中での最小合計移動時間を計算することです。\(n\)、または報告不可能です。 

制約構造は非常に重要です。 まであります\(10^5\)ノードと\(10^5\)すべてのテスト ケースにわたるエッジであり、各エッジで熱が最大 30 変化する可能性があります。熱の次元は小さく、制限されているため、それを完全な追加のグラフ次元のサイズとして扱うソリューションは、\(61n\)慎重に扱えば、メモリと時間の点ですでに許容可能です。 ただし、最短パス構造を持たないパス上の単純な動的プログラミングは、サイクルや繰り返し状態によって爆発的に発生します。 

異なる発熱量で同じノードに到達すると、将来の可能性も異なるため、ノードごとのベストタイムのみを追跡する単純なアプローチは正しくありません。 たとえば、ノードに到着すると、\(v\)heat 30 を使用すると、すべての発信負のエッジがブロックされる可能性がありますが、heat -30 を使用して到着すると、後でより柔軟な対応が可能になる可能性があります。 

微妙な失敗のケースは、小さな循環グラフに表示されます。 考慮する：```
1 -> 2 (dt = +30)
2 -> 1 (dt = -30)
```ヒート 0 の 1 から開始して、状態 (1,0) → (2,30) → (1,0) の間でループできますが、ノード 1 を「すでに最適に訪問されている」ものとして扱う試みは、異なるヒート状態で再訪問することが重要であるため、正確性が損なわれます。 

もう 1 つのエッジ ケースは、最終的な効果は安全であるにもかかわらず、パスが一時的に境界の外に出る場合です。 例えば：```
1 -> 2 (dt = +30)
2 -> 3 (dt = -30)
3 -> 4 (dt = +30)
```最終熱が有効なままであっても、中間ステップは境界を尊重する必要があるため、パスの実現可能性はすべてのエッジで状態に依存します。 

## アプローチ

 強引なアイデアは、1 から 2 までのすべての可能なパスを考慮することです。\(n\)、各パスに沿って熱を追跡します。 各ステップで熱が更新され、有効性がチェックされます。 これは制約を正確に適用するので原理的には正しいですが、サイクルのある一般的なグラフではパスの数が指数関数的に増加します。 熱状態はサイクルで繰り返される可能性があり、慎重に制限しない限り、無限に多くの有効なバリエーションが作成されるため、単純なパスに制限しても役に立ちません。 

重要な構造的洞察は、唯一の意味のある状態はペア \((ノード, 熱)\) であり、熱は 61 の可能な値に制限されているということです。 これにより、問題は階層化グラフ上の最短経路問題に変換されます。\(61n\)州。 元の各エッジはレイヤー間の遷移を引き起こし、すべてのエッジの重みは負ではない (時間は常に正である) ため、ダイクストラのアルゴリズムが直接適用されます。 

パスに対するブルート フォースは、同じ \((node, heat)\) 状態を何度も再計算するため失敗します。 階層化された状態の定式化は、すべての等価な履歴を展開されたグラフ内の単一のノードに集約し、指数関数的な探索を多項式の最短経路の計算に変えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | パスに対するブルート フォース | 指数 | O(1) おまけ | 遅すぎる |
 | 国家拡張されたダイクストラ | O(m · 61 log (n · 61)) | O(n・61+m・​​61) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ペア \((v, h)\) を扱います。\(v\)はノードであり、\(h \in [-30, 30]\)は、グラフ内の個別の状態として有効な熱量です。 

1. 距離テーブルの初期化`dist[v][h]`すべてのノードとヒート値に無限大を設定します。 この表は、ノードに到達するまでの最良の既知の時間を表します。\(v\)熱で\(h\)。 設定しました`dist[1][0] = 0`なぜなら、時間ゼロで熱が中性のノード 1 から開始するからです。 

2. 初期状態 \((1, 0)\) を累積時間順に優先キューにプッシュします。 

3. 優先キューが空でない間に、既知の最小時間の状態 \((v, h)\) を抽出します。 これにより、ダイクストラの貪欲な特性を維持しながら、常に現在最適な部分ルートを最初に拡張することが保証されます。 

4. からの各発信エッジについて\(v\)に\(u\)時間コストがかかる\(l\)そして熱変化\(dt\)、新しい熱を計算します\(h' = h + dt\)。 もし\(h'\)外にいる\([-30, 30]\)、すぐに制約に違反するため、この遷移をスキップします。 

5. トランジションが有効で、新しい時刻になっているかどうか\(dist[v][h] + l\)改善する`dist[u][h']`を更新し、\((u, h')\) を優先キューにプッシュします。 

6. 到達可能なすべての状態を処理した後、答えはすべての状態の最小値になります。`dist[n][h]`のために\(h \in [-30, 30]\)。 すべてが無限の場合は、-1 を出力します。 

ノードごとの熱状態を折りたたまない理由は、将来の遷移が熱に大きく依存しており、マージによって実現可能性の情報が失われるためです。 

### なぜ効果があるのか

 正確さは、各 \((node, heat)\) ペアを、非負のエッジ重みを持つより大きな有向グラフ内のノードとして扱うことにかかっています。 元の問題内のすべての有効なウォークは、この拡張されたグラフ内のパスに正確に対応し、その逆も同様です。 すべてのエッジの重みは負ではないため、ダイクストラのアルゴリズムは、状態が最小距離でポップされると、その後のパスでそれを改善できないことを保証します。 熱制約はエッジ上で局所的に適用されるため、無効なパスが状態空間に入ることはありません。 これにより、潜在的に最適なルートを破棄したり、無効なルートを受け入れたりすることがなくなります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**18
OFFSET = 30
MAXH = 61

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v, l, dt = map(int, input().split())
        graph[u].append((v, l, dt))

    dist = [[INF] * MAXH for _ in range(n + 1)]
    dist[1][OFFSET] = 0

    pq = [(0, 1, OFFSET)]

    while pq:
        d, v, h = heapq.heappop(pq)
        if d != dist[v][h]:
            continue

        for to, cost, dh in graph[v]:
            nh = h + dh
            if nh < 0 or nh >= MAXH:
                continue
            nd = d + cost
            if nd < dist[to][nh]:
                dist[to][nh] = nd
                heapq.heappush(pq, (nd, to, nh))

    ans = min(dist[n])
    print(-1 if ans == INF else ans)
```この実装は、拡張状態グラフのアイデアを直接反映しています。 オフセット 30 は、熱値のマッピングに使用されます。\([-30, 30]\)配列インデックスに\([0, 60]\)。 優先キューにより、状態が時間の昇順に処理されることが保証されます。 

微妙なディテールは古い状態のチェックです`if d != dist[v][h]`これにより、古いキュー エントリの処理が回避されます。 これがないと、繰り返しプッシュされるため、パフォーマンスが大幅に低下する可能性があります。 

もう 1 つの重要な詳細は、最後にすべての熱値を反復処理することです。 ターゲット ノードは特定の最終熱を必要とせず、境界内にあることのみを必要とします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | \(O(m \cdot 61 \log(n \cdot 61))\) | 各エッジは最大 61 の熱状態にわたって緩和でき、各緩和は優先キューを通過します。 
| スペース | \(O(n \cdot 61 + m)\) | 距離テーブルにはノードごとに 61 の状態が保存され、隣接リストにはエッジが保存されます。 

熱範囲が固定されており狭いため、定数は小さいままです。 と\(n, m \le 10^5\)、これはバイナリ ヒープを使用したダイクストラの制限内で快適に実行されます。

 ## 特殊なケース

 重要なエッジ ケースは、パスが異なる熱状態のノードを再訪問する場合です。 アルゴリズムは状態をマージしないため、これを正しく処理します。 たとえば、熱 -10 でノード 2 に到達した場合と熱 +10 で到着した場合は別々に保存され、両方が独立して探索されます。 

別のケースは、すべてのパスがノードに到達する場合です。\(n\)ただし、途中のどこかで無効な熱遷移が発生します。 これらは移行ステップで自動的に破棄されるため、最終的な`min(dist[n])`正しくは無限大となり、-1 が生成されます。 

最後の微妙なケースは、複数のエッジが異なる熱効果を持つ同じノードのペアを接続する場合です。 アルゴリズムはそれらを独立して処理し、エッジ間の優位性を想定せずに最適な組み合わせを確実に発見します。
