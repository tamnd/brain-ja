 ## 解決策
 ## 問題の理解

 それぞれに固定の強度値を持つ一連のヘルパーが与えられます。 任意の順序で並べ替えることができます。 列に配置されると、ヘルパーの貢献度はその位置に応じて異なります。力のあるヘルパーであれば、$a$所定の位置に立つ$i$(ロープの遠端の 1 から数えて)、貢献します。$a / i$総引っ張り力に。 総力はこれらすべての貢献の合計です。 私たちは、この総力が少なくとも次のようなヘルパーの順序が存在するかどうかを知りたいと考えています。$x$。 

重要な問題は、同じ数値セットでもその位置に応じて異なる結果が生成され、後の位置はより小さいインデックスで除算されるため、より「価値がある」ということです。 したがって、問題は基本的に、加重和を最大化する方法で小さな分母に大きな値を割り当てることです。 

入力サイズが十分小さいため、$O(n^2)$または$O(n \log n)$解決策は実現可能です。 と$n \le 1000$、数百万の操作でも問題ありませんが、3 次的な操作や、スワップのたびに合計の完全な再計算を繰り返す操作は遅すぎます。 

素朴な解釈では、すべての順列を試してみることになりますが、$n!$たとえ成長が早すぎる$n=15$, したがって、目的の構造を活用する必要があります。 

いくつかの特殊なケースでは、よくある間違いが明らかになります。 すべての強さが等しい場合、順序は重要ではないため、答えは次のとおりであるかどうかによってのみ決まります。$a \cdot (1 + 1/2 + \dots + 1/n)$到達する$x$。 たとえば、$n=3$、$a=[2,2,2]$、 そして$x=10$、可能な最大値は$2 \cdot (1 + 1/2 + 1/3) = 3.66$、したがって、答えはNOです。 あらゆる順序付けが機能すると誤って想定している欲深い人は、ここで失敗します。 

もう 1 つの特殊なケースは、多数の小さな値の中に 1 つの非常に大きな値が存在する場合です。 その値を位置 1 に配置すると完全にカウントされますが、後から配置すると影響が大幅に軽減されます。 早いポジションを優先しない戦略は、答えを過小評価することになります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。ヘルパーのすべての順列を試し、結果として得られる加重合計を計算し、最大値を取得します。 これは、位置への値の可能なすべての割り当てを評価するため、正しいです。 問題は、それが必要であるということです$n!$各順列の計算の合計は次のようになります。$O(n)$、与える$O(n \cdot n!)$、小さいときはすでに不可能になります$n$。 

式の構造を見ると、並べ替えが重要になる理由がわかります。 各ポジション$i$固定乗数を適用します$1/i$、これらの乗数は次のように減少します。$i$が増加します。 したがって、問題は古典的な割り当てタスクになります。つまり、大きな数値と大きな重みを一致させるということです。 以来$1/1 \ge 1/2 \ge \dots \ge 1/n$、再配置の不等式が直接適用されます。 これは、最大の強度と最大の係数、2 番目に大きい強度と 2 番目に大きい係数などを組み合わせることによって最大の合計が得られることを示しています。 

したがって、順列を調べる代わりに、強さを降順に並べ替え、可能な限り最適な配置を直接計算します。

 ## アルゴリズムのチュートリアル

 1. 強さの配列を降順に並べ替えます。 これにより、利用可能な最大の強度が常に最も価値のある残りのポジションに割り当てられるようになります。 
2. フォームの累計を事前計算するか、反復的に維持します。$\sum a_i / i$、ここでインデックスは$i$1から$n$。 反復の順序は最適な割り当てに対応するようになりました。$i$配列がソートされると修正されます。 
3. 値が大きくなる可能性があるため、必要に応じて浮動小数点演算または高精度演算を使用して加重合計を累積します。 
4. 最終的な合計を次と比較します。$x$。 少なくともそれであれば$x$の場合はYESを出力し、それ以外の場合はNOを出力します。 

唯一明白ではないステップは、なぜ降順で並べ替えるのが正しいのかということです。 これはまさに、重みの固定減少シーケンスを使用してドット積を最大化する例です。 

### なぜ効果があるのか

 重み$1, 1/2, \dots, 1/n$厳密に減少するシーケンスを形成します。 割り当ての反転、つまり小さな強度を大きな強度の前に配置すると、合計が減少するだけです。これは、それらを交換すると、より大きな値がより大きな係数を持つ位置に移動するためです。 このような反転を繰り返し除去すると、値を減少させることなく、あらゆる配置がソートされた配置に変換され、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    total = 0.0
    for i, val in enumerate(a, start=1):
        total += val / i
    
    print("YES" if total >= x else "NO")

if __name__ == "__main__":
    solve()
```解決策は、強度を降順に並べ替えることから始まり、これにより位置への値の最適な割り当てが修正されます。 次に、ループは、導出された最適な構造に従って重み付けされた合計を直接計算します。 

実装の微妙な詳細の 1 つは、浮動小数点演算の使用です。 以来$a_i$まで可能です$10^{12}$そして$n$まで$1000$、合計は Python 浮動小数点数の安全な精度制限内に残ります。 これがより厳密な場合は、合理的またはスケーリングのアプローチが必要になる可能性がありますが、ここでは倍精度で十分です。

 ## 特殊なケース

 いつ$n = 1$、アルゴリズムは、単一の値が満たしているか超えているかをチェックすることになります。$x$。 並べ替えは関係なく、ループは正確に計算します。$a_1 / 1$、唯一可能な構成と一致します。 

すべての値が同一の場合、次のようにします。$a_i = k$、並べ替えによって配列は変更されません。 アルゴリズムは計算します$k \cdot H_n$、 どこ$H_n$は高調波数です。 どのように再配置しても同じ結果が得られるため、貪欲な解決策は正確です。 

非常に大きな値が 1 つある場合、ソート順によりその値が位置 1 に配置されます。寄与は最大になります。 代替の配置では、それをより低い位置に配置し、合計を厳密に減らすことになりますが、アルゴリズムはそのようなことを構造上回避します。
