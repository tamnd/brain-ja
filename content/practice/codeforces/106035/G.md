 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n+1$頂点と配列$n$数字。 ノードに値を直接割り当てているわけではありません。 代わりに、これらの数値は、頂点を徐々に「アクティブ化」するプロセス中にエッジに割り当てられる重みを表します。 

このプロセスは、最初にアクティブな頂点 (黒く塗られた頂点) を選択することから始まります。 その後はまさに、$n$という手順が実行されます。 各ステップで、少なくとも 1 つのすでにアクティブな頂点に隣接するまだ非アクティブな頂点を選択し、それをアクティブにして、現在のステップの番号を割り当てます。$a_i$アクティブ化に使用されるすでにアクティブなネイバーに接続するエッジの重みとして使用されます。 新しくアクティブ化された各頂点は 1 つのエッジを介して既存の黒コンポーネントに接続されるため、構造は常にすべてのエッジに最終的に重みが割り当てられたツリーのままになります。 

目標は、結果として得られる重み付きツリーの直径が最大になるように、最初のルートとアクティブ化の順序の両方を選択することです。直径とは、単純なパスに沿ったエッジの重みの最大合計を意味します。 

制約$n \le 150$は十分小さいため、次のような解が得られます。$O(n^3)$あるいは$O(n^4)$慎重に実装すればテスト ケースごとに合格する可能性はありますが、指数関数的なものはすべて合格します。$n$または、すべての順列を列挙することは不可能です。 テスト ケースの数が多いため、事前に計算された構造を再利用するか、非常に厳密な多項式制限を持つソリューションも必要です。 

微妙な問題は、アクティブ化の順序によって固定エッジに重みが割り当てられないことです。 代わりに、重みは頂点に到達する順序に依存するため、同じエッジが戦略に応じて異なる重みを受け取る可能性があります。 これが複雑さの主な原因です。ツリー構造は固定されていますが、重みからエッジへのマッピングは柔軟です。 

素朴な推論を打ち破るようなエッジケースは、この柔軟性の誤解から生じます。 たとえば、星型ツリーでは、重みが BFS 順序で外側に向かう必要があると仮定すると、直径を過小評価する可能性があります。 ただし、長いパスの深いエッジに早い段階で高い重みが割り当てられると、直径が大幅に大きくなる可能性があります。 

もう 1 つの落とし穴は、最終的な重み付けツリーがアクティブ化順序ではなく構造のみに依存すると仮定していることです。 同じツリー上の 2 つの異なるアクティブ化シーケンスは、基礎となるエッジが同一であっても、まったく異なる直径値を生成する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、開始頂点と隣接制約を考慮したすべての可能なアクティブ化順序を選択するためのすべての可能な方法が試行されます。 このような各順序は、$n$重みと$n$エッジ。 有効な構造ごとに、重み付けされたエッジ上の 2 つの BFS 実行を使用して直径を計算します。 

有効なアクティベーション注文の数は膨大です。 最初の根の選択を無視したとしても、葉を 1 枚ずつ追加して木を成長させる方法の数は、次のように指数関数的に増加します。$n$、各ステップで複数の境界頂点が利用できる可能性があるためです。 これにより、ブルートフォースアプローチが爆発的に増加します。$n = 20$なぜなら、フロンティアの選択肢の数はステップごとに増えるからです。 

重要な観察は、すべての有効な成長シーケンスを明示的にシミュレートする必要がないということです。 重要なのは、ツリー内のパスに沿ってウェイトをどのように分散できるかです。 すべてのアクティブ化ステップでは、正確に 1 つのエッジを介して新しい頂点を既存のコンポーネントに接続します。これは、プロセスがツリーのルート方向を定義することを意味します。 各ノード (ルートを除く) は、アクティベーション ツリー内のその親に 1 回だけアタッチされます。 したがって、プロセス全体は、ルートを選択してツリーを外側に向けると同時に、子がアクティブになる順序で親子エッジに重みを割り当てることと同じです。 

重要な単純化は、パスの観点から考えることです。 直径は、パスに沿ってどれだけ大きな重みを蓄積できるかによってのみ決まり、根から葉へのパスに沿って割り当てられる重みは、アクティブ化時間によって引き起こされるそのパスに沿ったエッジの順序に対応します。 これにより、問題はシーケンスを分散する方法を決定することに変わります。$a_i$一部のルートからリーフへのパスで大きな合計が収集されるようにします。 

正しい戦略は、各頂点を潜在的な中心とみなして、その周囲の 3 つの「枝」の可能な限り最良の寄与を計算することです。これは、古典的な木の直径 DP と似ていますが、重みの順序が追加されています。 重みはグローバルであり、順番に割り当てる必要があるため、最適な戦略は、有望な分岐のより深い位置にあるエッジにより大きな重みを割り当てることです。これにより、重みをソートし、ツリー上の DP によって計算された構造的寄与と重みを貪欲に一致させることができます。 

DP は、ノードごとに、(パス内のエッジの数に関して) 最良の 2 つの下向き寄与を計算し、これらを利用可能な最大の重みと組み合わせます。 構造とソートされた重みの間の相互作用により、アクティベーション順序の指数関数的な自由が失われます。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$a$大きい重みが最初に考慮されるように降順で並べられます。 これが必要なのは、最適な構成では、より大きな重みが短いエッジや無関係なエッジで無駄になるのではなく、より長いパスに寄与するはずだからです。 
2. ツリーを任意にルート化し、DFS を使用してサブツリー構造を計算します。 各ノードについて、そのノードから各子サブツリーまでの最適な下向きパス長を計算します。 これにより、各ブランチがどの程度「深い」かがわかります。 
3. すべてのノードについて、その子から上位 2 つの最も深い下向きパスを収集します。 これらは、エッジを再度訪問することなく、このノードを通るパスを延長する最良の方法を表します。 
4. 各ノードを直径パスの潜在的な「接続点」として解釈します。 ノードを通る最適なパスは 2 つの下向き分岐を組み合わせることによって形成されるため、ノードの構造的寄与は、その 2 つの最適な深さの合計になります。 
5. 次に、重みを貪欲に割り当てます。より深い寄与の一部であるエッジに、より大きな重みを一致させます。 概念的には、長いパスの中央に近いほど重い重みが必要です。これは、これらのエッジが多くの候補直径パスに現れるためです。 
6. 構造の深さの寄与と割り当てられた重みを組み合わせて、すべてのノードで達成可能な最良の値を計算します。 すべてのノードの最大値が答えです。 

### なぜ効果があるのか

 重要な不変条件は、有効な構築ではツリーのルート方向が誘導され、ルートからリーフへのパスに沿って、頂点がアクティブ化されるタイミングによって決定される厳密な順序でエッジが使用されることです。 これは、各パスが深さに応じた順序で一連の重みを効果的に受け取ることを意味します。 

直径は 1 つのパスにわたる合計であり、すべてのエッジが固定重みで 1 回だけ使用されるため、問題は、あるノードで出会う 2 つの素の根から葉の枝にわたる重み付き合計を最大化することに帰着します。 DFS ベースの分解により、考えられるすべての直径パスが 2 つの下向きパスの組み合わせとして表現されることが保証され、重みの貪欲な並べ替えにより、最大の寄与が最大の効果を発揮する場所に配置されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = n + 1

    g = [[] for _ in range(m)]
    for _ in range(n):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    a.sort(reverse=True)

    parent = [-1] * m
    order = []

    def dfs(v, p):
        parent[v] = p
        for to in g[v]:
            if to == p:
                continue
            dfs(to, v)
        order.append(v)

    dfs(0, -1)

    dp = [0] * m

    ans = 0
    idx = 0

    # process nodes bottom-up
    for v in order:
        best1 = 0
        best2 = 0

        for to in g[v]:
            if to == parent[v]:
                continue
            best = dp[to] + 1
            if best > best1:
                best2 = best1
                best1 = best
            elif best > best2:
                best2 = best

        # assign weights to the best two edges available so far
        if idx < n:
            best1 += a[idx]
            idx += 1
        if idx < n:
            best2 += a[idx]
            idx += 1

        dp[v] = best1
        ans = max(ans, best1 + best2)

    print(ans)

if __name__ == "__main__":
    solve()
```DFS は、各ノードがエッジを再度訪問することなく子からの情報を集約できるように、親をルートとする構造を構築します。 DP 配列には、エッジ数で測定された各ノードから始まる最長の下向きパスが格納されます。 ポストオーダーでノードを走査しながら、最も強い 2 つの子ブランチを計算し、残りの最大の重みをそれらに付加します。 

実装の微妙な詳細は、ソートされた配列からの代入の順序です。 このコードは、同じ走査順序で貪欲に重みを割り当てます。 これが機能するのは、より深い分岐がポストオーダーの早い段階で処理され、より影響力のある構造位置に重いウェイトが自然に流れることが保証されるからです。 

もう 1 つの重要な点は、ツリーを任意のノードにルートがあるものとして扱うことです。 直径の計算ではすべてのノードが潜在的な中心として考慮され、DP では寄与が対称的にマージされるため、任意のルートが機能します。 

## 実用的な例

 4 つのノードと重みを持つパスのような形をした小さなツリーを考えてみましょう。$[5, 2, 1]$。 この構造では単一の長いチェーンが強制されるため、すべてのノードには意味のある下向き分岐が 1 つしかありません。 

| ノード | ベスト1 | ベスト2 | 割り当てられた重み | dp[v] |

 | 葉 | 0 | 0 | 5 | 5 |
 | ミッド | 1 | 0 | 2 | 3 |

 | ルート | 3 | 0 | - | 3 |

 最終的な直径は、パスに沿ってウェイトが分散されたすべてのエッジの単純な合計であり、線形ツリーでは、解が単一のチェーンに沿ったウェイトの累積に崩壊することが確認されます。 

次に、中心が 3 つの葉と重みに接続されている星を考えます。$[10, 5, 1]$。 センターは直径に対して2枚の葉を組み合わせることができます。 

| ノード | ベスト1 | ベスト2 | 割り当てられた重み | dp[v] |

 ## 特殊なケース

 単一エッジ ツリーでは、アルゴリズムはそのエッジにのみ重みを割り当てます。 DP はその値をすぐに返し、どの組み合わせステップでもその値を改善できないため、出力は構造上正しいものになります。 

純粋なチェーンでは、すべてのノードに子が 1 つしかないため、2 番目に最適なブランチは常に 0 になります。 したがって、アルゴリズムは、唯一可能な直径と一致するパスに沿って重みを線形に累積します。 

星型ツリーでは、中心ノードが 2 つの枝を結合できる唯一の場所になります。 DP は、2 つの最良のリーフを正確に識別し、それらに 2 つの最大の重みを割り当て、中心を通る最適な直径パスを生成します。
