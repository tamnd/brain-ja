 ## 解決策
 ## 問題の理解

 各頂点を 1 回だけ訪問するウォークを表すシーケンスが与えられているため、それはすでに 1 から n までの数値の並べ替えになっています。 タスクは、この順序が非常に特殊な形をしているかどうかを判断することです。 

許容される形状は、次の意味での「ピラミッド型」です。 左から右への順列を見る場合、まず値に関して厳密に一方向に移動する必要があり (厳密に増加または厳密に減少)、その後、方向を 1 回だけ切り替えて、厳密に逆方向に継続する必要があります。 両方の部分の長さは少なくとも 2 でなければなりませんが、転換点自体は 2 つのセグメントで共有されるという意味で両方の単調解釈に属します。 

したがって、構造は本質的に単一の山または単一の谷になります。つまり、値が上昇してから下降するか、下降してから上昇するかのいずれかであり、2 回目の反転は許可されません。 

入力は n の後に順列が続くだけです。 出力は、そのような単一変更の単調構造が存在するかどうかに応じて、単純な「はい」または「いいえ」になります。 

n が 100000 までの制約により、二次関数は最悪の場合でも約 10^10 の演算になり、通常の時間制限では直ちに不可能となるため、あらゆる解が線形になるように強制されます。 O(n log n) アプローチでも許容されますが、ここでは不要です。 構造は十分に局所的であるため、単一パスで十分です。 

主なエッジケースは、「ほぼ単調な」シーケンスの微妙な失敗です。 

最初の例は、[1、2、3、4、5] のような完全に単調な配列です。 一見すると、違反がないため許容できるように見えますが、方向の変更によって 2 つのセグメントが形成されることはないため、拒否する必要があります。 

別の例は、[4、5、6、1、2、3] のようなものです。 これには、実際の値に関して 1 回の明確な増加とそれに続く減少がありますが、完全な順列順序で解釈すると方向が複数回変化するため、遷移はシーケンス全体にわたる単一の山または谷と一致しません。 

より微妙なケースは、[1, 3, 2] のような短い振動です。 これは、一度増加してから一度減少し、両方のセグメントに十分な長さがあるため、有効です。 

## アプローチ

 ブルートフォース解釈では、プレフィックスを 1 つの単調方向として扱い、サフィックスを反対方向として扱い、可能なすべての分割点 i を試します。 各分割について、両方の半分をスキャンして単調性を検証します。 各分割には O(n) のコストがかかり、O(n) 回の分割があるため、これにより O(n^2) の動作が行われます。 n = 10^5 では、これは実現可能な限界をはるかに超えています。 

問題の構造は、シーケンスがすでに順列であるため、隣接するもの間の比較によって傾向のすべての変化が完全に記述されるということです。 すべての分割点をテストする代わりに、隣接する差分の方向が何回変化したかを検出するだけで済みます。 

隣接する各差分の符号を計算すると、問題全体は、符号シーケンスに正から負、または負から正への遷移が最大 1 つあるかどうか、および変化が存在する場合には最初のセグメントに各方向に少なくとも 1 つのステップがあるかどうかをチェックすることに帰着します。 これは、シーケンスの増加傾向と減少傾向が何回切り替わるかを数えるのと同じです。 

重要な洞察は、ピラミッド シーケンスには極値が 1 つしかないため、方向が変わるのは最大 1 回だけであるということです。 変化がゼロ回の場合、シーケンスは単調で無効です。 一度変更すると、両側が空でない限り有効です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース分割チェック | O(n^2) | お(1) | 遅すぎる |
 | 方向転換のカウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 隣接する差異を処理し、方向の変化を追跡します。

1. a[i] と a[i+1] を比較して、隣接する各ペアが増加しているか減少しているかを計算します。 これにより、シーケンスがバイナリ トレンド表現に圧縮されます。 
2. このトレンド配列をたどって、トレンドが増加から減少、またはその逆に反転した回数を数えます。 各フリップは、潜在的なピークまたは谷に対応します。 
3. フリップの数が 1 より大きい場合、複数の転換点を意味するため、構造をピラミッド型にすることはできません。 
4. 反転がゼロの場合、配列は完全に単調であり、必要な単一の山または谷の構造が含まれていないため、無効になります。 
5. 反転が 1 つだけある場合は、この反転によって形成された両方のセグメントが元のシーケンスで少なくとも 2 の長さを持っていることを確認します。 これにより、「ピラミッド」に意味のある上昇部分と下降部分が確実に存在します。 

中心となるアイデアは、グローバルな形状条件を遷移のローカルなプロパティに還元するということです。 

### なぜ効果があるのか

 不変条件は、シーケンスが常に区分的単調パスとして解釈されるということです。 隣接する差異の符号の変化を見るたびに、単調セグメント間の境界が識別されます。 有効なピラミッド パスには、正確に 2 つの単調セグメント (いずれかの順序で増加するものと減少するもの) が含まれている必要があります。 複数の境界が存在する場合は、少なくとも 3 つの単調セグメントが存在することになり、シーケンスの方向が複数回変更されることになり、定義に違反します。 境界が存在しない場合、シーケンスは方向を切り替えないため、ピラミッドを形成できません。 単一パスにわたってこの不変条件を維持することで、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

# build trend array: +1 for up, -1 for down
trend = []
for i in range(n - 1):
    if a[i] < a[i + 1]:
        trend.append(1)
    else:
        trend.append(-1)

changes = 0
for i in range(1, len(trend)):
    if trend[i] != trend[i - 1]:
        changes += 1

# valid pyramidal path must have exactly one change
if changes != 1:
    print("NO")
else:
    print("YES")
```コードはまず、順列を隣接するもの間の方向のシーケンスに圧縮します。 これは、価値観について直接推論することを避け、代わりに構造の変化に焦点を当てます。 

2 番目のループでは、この方向が何回反転したかをカウントします。 この数は、モノトーン セグメントの数から 1 を引いた値に直接対応します。 

最後に、この決定では、単一の山または谷の構造の特徴であるそのような反転が 1 つだけ存在するかどうかがチェックされます。 

微妙な点は、入力が順列であるため、等価性は決して起こらず、隣接するすべての比較は厳密に増加または減少していることです。 これにより、トレンド抽出における曖昧さが解消されます。 

## 実用的な例

 ### 例 1

 入力:```
5
4 3 1 2 5
```トレンド構築:

 | 私 | a[i] 対 a[i+1] | トレンド |
 | --- | --- | --- |
 | 0 | 4 > 3 | -1 |
 | 1 | 3 > 1 | -1 |
 | 2 | 1 < 2 | +1 |
 | 3 | 2 < 5 | +1 |

 変化の検出:

 | 私 | トレンド[i-1] | トレンド[i] | 変更 |
 | --- | --- | --- | --- |
 | 1 | -1 | -1 | 0 |
 | 2 | -1 | +1 | 1 |
 | 3 | +1 | +1 | 1 |

 変更の合計 = 1 なので、出力は YES になります。 

これは、減少してから増加する単一の谷構造を裏付けています。 

### 例 2

 入力:```
6
4 5 6 1 2 3
```傾向:

 | 私 | トレンド |
 | --- | --- |
 | 0 | +1 |
 | 1 | +1 |
 | 2 | -1 |
 | 3 | +1 |
 | 4 | +1 |

 変化の検出:

 | 私 | 変更 |
 | --- | --- |
 | 1 | 0 |
 | 2 | 1 |
 | 3 | 1 |
 | 4 | 1 |

 変更の合計 = 2 なので、出力は NO になります。 

これは、シーケンスが複数の方向にシフトしていることを示しています。つまり、シーケンスには複数の極値があり、ピラミッド型にはなり得ないことを意味します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 傾向を構築するために一度順列をスキャンし、変化をカウントするために一度順列をスキャンします。 
| スペース | O(n) | サイズ n−1 | のトレンド配列を保存します。 

この制約では最大 100,000 個の要素が許可されるため、リニア スキャンは実行時とメモリの両方で制限内に快適に収まります。 トレンドをオンザフライで計算することで、一定空間バージョンも可能ですが、ここでは不要です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    trend = []
    for i in range(n - 1):
        trend.append(1 if a[i] < a[i + 1] else -1)

    changes = 0
    for i in range(1, len(trend)):
        if trend[i] != trend[i - 1]:
            changes += 1

    return "YES\n" if changes == 1 else "NO\n"

# provided samples
assert run("5\n4 3 1 2 5\n") == "YES\n"
assert run("3\n1 3 2\n") == "YES\n"

# custom cases
assert run("3\n1 2 3\n") == "NO\n", "fully increasing"
assert run("3\n3 2 1\n") == "NO\n", "fully decreasing"
assert run("4\n2 1 3 4\n") == "YES\n", "single valley"
assert run("6\n1 3 2 4 5 6\n") == "NO\n", "multiple changes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 3 | いいえ | 単調増加は拒否されるべきです。 
| 3 2 1 | いいえ | 単調減少は拒否されるべきです |
 | 2 1 3 4 | はい | 単一の谷構造は有効です |
 | 1 3 2 4 5 6 | いいえ | 複数の方向の変化がピラミッドの形を壊す |

 ## 特殊なケース

 次のような厳密に増加するシーケンス`1 2 3 4`変更ゼロのすべて +1 のトレンド配列が生成されるため、すぐに拒否されます。 アルゴリズムはフリップをカウントせず、正しく NO を出力します。 

次のような厳密に減少するシーケンス`4 3 2 1`対称的に動作し、ゼロ フリップを生成し、NO を返します。 

次のような最小限の有効なピラミッド`2 1 3`-1 から +1 までの 1 つの変化を生成します。 アルゴリズムは 1 つの反転を正確に検出し、YES を返します。これは、両方のセグメントが存在し、空ではないという要件に一致します。 

次のような複数の振動を含むシーケンス`1 3 2 4`トレンド配列に 2 つの反転が生成され、複数の極値が含まれているため拒否され、ピラミッド型制約に違反します。
