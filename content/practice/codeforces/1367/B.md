 ## 解決策
 ## 問題の理解

 各位置に固定の「必要なパリティ」を持つ配列が与えられます。偶数のインデックスには偶数が含まれ、奇数のインデックスには奇数が含まれなければなりません。 任意の 2 つの位置間のスワップを使用して配列を再配置することができますが、すべてのパリティ要件を満たすために必要なスワップの最小数を知りたい、またはそれがまったく不可能であると判断したいと考えています。 

タスクを再解釈する便利な方法は、各位置がターゲット タイプ (偶数インデックスまたは奇数インデックス) を持ち、各値もタイプ (偶数値または奇数値) を持つと考えることです。 目標は、型が位置の要件と一致するように値を並べ替えることです。 

スワップには制限がないため、この構造は隣接性や順序に関するものではなく、2 つのグループ間の不一致の数のみに関するものです。 

制約は小さく、n は最大 40、テスト ケースは最大 1000 です。 これは、テスト ケースごとに O(n) または O(n log n) の解があれば簡単に十分であり、O(n^2) の解でも問題なく合格することを意味します。 ただし、問題の構造は、スワップをシミュレートするのではなく不一致をカウントすることで、各テスト ケースを線形時間で解決できるはずであることを示唆しています。 

偶数の値の数が偶数のインデックス位置の数と一致しない場合、微妙なエッジ ケースが発生します。 たとえば、n が 3 の場合、インデックス 0 と 2 には偶数が必要なので、偶数の値が 2 つだけ必要になります。 配列に偶数値が 1 つしかない場合、スワップによって存在する偶数の数は変わらないため、いくらスワップしてもこの問題は解決できません。 

もう 1 つのエッジ ケースは、すべてがすでにパリティと一致している場合に発生します。 その場合、答えはゼロであり、単純なスワッピング戦略では、すでに正しい位置を「修正」しようとすると、依然として不必要な操作を誤ってカウントする可能性があります。 

## アプローチ

 強引な解釈では、問題を配列の順列の検索として扱うことになります。 要素を再配置し、それぞれの有効な構成に到達するために必要なスワップの数を計算するために考えられるすべての方法を試してみることができます。 ただし、順列の数は n! であり、n = 40 の場合でも天文学的に大きくなります。順列間のスワップ距離の観点から推論しようとしても、状態空間は依然として大きすぎます。 

重要な単純化は、実際の値ではなくパリティのみが重要であるという観察から得られます。 すべての要素は、偶数または奇数の 2 つのカテゴリのいずれかに属します。 すべてのインデックスは、偶数位置または奇数位置の 2 つのカテゴリのいずれかに属します。 問題は、これら 2 つのパーティション間のカウントの一致に帰着します。 

各パリティのインデックスがいくつ存在するか、各パリティの要素がいくつあるかを数えると、解決策が可能かどうかがすぐにわかります。 カウントが一致しない場合は、再配置しても修正できません。 

実現可能性が確立されると、残る問題は何回のスワップが必要かということです。 誤って配置された奇数位置の偶数要素と偶数位置の誤って配置された奇数要素の間の各スワップにより、2 つの誤った位置が一度に修正されます。 このペア構造が答えを直接決定します。 

ブルート フォースは有効な順列を明示的に構築しようとするため機能しますが、パリティのバイナリ構造を利用していないため失敗します。 カウントの不一致のみが問題であるという観察により、問題はカウントとペアの不一致に帰着します。

 ## アルゴリズムのチュートリアル

 1 つのテスト ケースに焦点を当てます。

1. 偶数の値を必要とする配列位置の数を数えます。 これらはまさにインデックス 0、2、4 などです。 これをneed_even_positionsとします。 
2. 配列内に偶数がいくつ存在するかを数えます。 これをhave_even_valuesとします。 これにより、偶数の位置を満たすために使用できる要素の数が決まります。 
3. have_even_values が need_even_positions と等しくない場合は、-1 を返します。 その理由は、スワップでは偶数値の合計数を変更できないため、合計が一致しない場合はすべての制約を満たすことができないためです。 
4. 配列をスキャンして不一致を計算します。 すべてのインデックス i について、i が偶数であるが a[i] が奇数である場合、この位置は偶数の値の不足です。 i が奇数だが a[i] が偶数の場合、これは偶数の値が誤って配置された余剰です。 
5. missmatch_even_to_odd を、奇数のインデックスにある偶数値の数とします。 これは、反対側からの修正が必要な位置の数と同じです。 
6. 誤って配置された偶数値と誤って配置された奇数の間の各スワップにより、両方の位置が一度に修正されるため、スワップの最小数は、mismatch_even_to_odd です。 

### なぜ効果があるのか

 すべての有効なスワップは最大 2 つの誤った位置を修正でき、すべての誤った位置は 2 つの対称不一致タイプのいずれかに正確に属します。 実現可能性により、必要なパリティ スロットと利用可能なパリティ値の数が等しいことが保証されると、不一致は完全なペアを形成します。 各スワップは、他の場所に新たな不一致を作成することなく 1 つのペアを解決するため、これらのペアをカウントすることで最適な操作数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    need_even = (n + 1) // 2
    have_even = sum(1 for x in a if x % 2 == 0)
    
    if have_even != need_even:
        print(-1)
        continue
    
    mismatches = 0
    for i, x in enumerate(a):
        if i % 2 != x % 2:
            if i % 2 == 0:
                mismatches += 1
    
    print(mismatches)
```この解決策は、偶数のインデックスがいくつ存在するかを計算することから始まります。これは、偶数で埋める必要がある位置の数です。 次に、配列内に偶数値がいくつ存在するかをカウントします。 スワップでは複数の値セットを変更できないため、この実現可能性チェックは不可欠です。 

不一致カウント ループは、偶数のインデックスに奇数が含まれている場合にのみ増加します。 このようなすべての不一致は、奇数のインデックスで対応する反対側の不一致とペアにする必要があり、片側のみをカウントすることで二重カウントの交換が回避されるため、これで十分です。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        need_even = (n + 1) // 2
        have_even = sum(x % 2 == 0 for x in a)
        
        if have_even != need_even:
            out.append("-1")
            continue
        
        mismatches = 0
        for i, x in enumerate(a):
            if i % 2 == 0 and x % 2 == 1:
                mismatches += 1
        
        out.append(str(mismatches))
    
    return "\n".join(out)

 ## 特殊なケース

 サイズ 1 の最小配列は、インデックス 0 が偶数パリティを必要とするため、値が偶数であれば常に条件を満たします。 不一致が検出されないため、アルゴリズムは正しくゼロ スワップを返します。 

配列に正しい数の偶数値があり、それらがすべて間違った位置にある場合、実現可能性は合格ですが、カウントの不一致により、必要なスワップの正確な数が生成されます。 各スワップは、奇数インデックスの偶数要素と偶数インデックスの奇数要素のペアに対応し、他の構造は結果に影響を与えません。
