 ## 解決策
 ## 問題の理解

 複数の小文字のセットが与えられ、最初は文字列として書き込まれます。$s$。 このマルチセットから、いくつかの文字が破棄され、残りの文字が任意に再配置されて新しい文字列が形成されます。$t$。 長さ$t$は固定され、次のように与えられます$m$、そしてそれと一緒に配列が与えられます$b$長さの$m$。 

ポジションごとに$i$で$t$、値$b_i$どのくらいの位置を測定するか$i$厳密に大きな文字を含むすべての位置からのものです。 具体的には、あらゆる指標を見ていきます$j$そのような$t_j$アルファベット順でより大きい$t_i$を合計します$|i - j|$。 

タスクは任意の文字列を再構築することです$t$から形成できるもの$s$指定された配列を正確に生成します$b$。 

重要な難点は、$b_i$は文字の順序と位置距離に同時に依存するため、選択した文字の順列とそれらの相対的な配置の両方を再構築します。 

制約は小さく、各文字列の長さは最大 50、テスト ケースは最大 100 です。 これにより、文字のサブセットの順列に対する指数関数的な検索が即座に排除されます。 解決策は、文字列を貪欲に再構築するか、文字クラスごとに制約をシミュレートすることに依存する必要があります。 

単純な失敗モードは、すべての順列をチェックしながら文字を位置ごとに割り当てようとすることです。 長さ 50 の文字列の場合、偶数$50!$アレンジメントは不可能であり、サブセットに制限したとしても依然として指数関数的です。 

もう一つの微妙な落とし穴は、$b_i$は、位置を無視して、大きな文字の数のみに依存します。 同じマルチセットを持つ 2 つの文字列ですが、大きな文字の配置が異なると、結果は大きく異なります。$b$価値観。 

重要な構造は、$b_i$辞書編集的に大きい文字の位置のみに依存します。$t_i$これは、アルファベットの降順で文字を処理することを提案します。 

## アプローチ

 ブルートフォース戦略では、次の文字のサブセットが選択されます。$s$、それらを並べ替えて、$b$各アレンジメントの配列。 各候補文字列について$t$、すべてを計算します$b_i$コストを重視する$O(m^2)$、順列の数は階乗です。$m$、非常に小さいサイズを超えると、これは完全に不可能になります。 

重要な観察は、視点を逆転させることです。完全な文字列を一度に決定する代わりに、最大の文字から最小の文字まで段階的に文字列を構築できます。 

すべての文字の位置を特定の文字よりも厳密に大きくすると、$c$、その後、次のことが発生した場合$c$、への貢献$b_i$すでに配置されている文字から完全に決定されます。 残るのは、すべての文字が より大きいということです。$c$固定値と以下の文字を提供します$c$まだ配置されていません。 

これは貪欲な構築を示唆しています。つまり、「z」から「a」までの文字を割り当て、必要な距離制約を満たす位置に出現箇所を配置します。 各ステップで、新しく配置された文字が残りの値と一致していることを確認します。 

標準的なトリックは、どの文字が残りの構造を満たすことができるかを確認することによって、どの文字グループを次に配置する必要があるかを繰り返し特定し、それらの文字グループへの寄与をシミュレートすることです。$b$制約に一致する位置を選択しながら。 

これにより、すべての文字の並べ替えから文字列を埋めるまでの問題が 26 段階で軽減されます。各段階は、$b$配列。

 ## アルゴリズムのチュートリアル

 文字列を高い文字から低い文字まで構築します。 

### ステップ

 1. の各文字の出現回数を数えます。$s$、各文字が何個出現する必要があるかを示します。$t$。 まだポジションは決めておらず、各レターが何部使用するかだけを決めている。 この制限により、許可されたマルチセット内に収まることが保証されます。 
2. 現在未採用のポジションのリストを管理します。$t$。 最初はすべてのポジションが空です。 
3. 固定文字の場合$c$のすべての出現を配置すると仮定します。$c$すぐに。 現時点では、次より大きい文字はすべて$c$はすでに配置されており、その位置は固定されています。 
4. 埋まっていないポジションごとに$i$への寄与を計算します。$b_i$すでに配置されている大きな文字から来ています。 これは、段階的に維持できる既知の定数です。 
5. 各候補ポジションについて$i$、その残余要件を次のように定義します。$$r_i = b_i - \text{(contribution from already placed larger letters)}$$この値は、以下の文字で説明する必要がある距離を表します。$c$。 
6. 次に、次のすべての出現箇所を配置する必要があります。$c$。 有効な配置のために、正確に選択します`cnt[c]`配置する位置$c$残差制約と一致します。 直感的には、これらの位置は次の位置であるはずです。$r_i$予想される貢献パターンと一致する場合$c$がしきい値文字とみなされます。 
7. ポジションを貪欲に選択します。すべての満たされていないインデックスの中から、有効なポジションを繰り返し選択します。$c$、それを配置し、簿記を更新します。 各配置により、小さな文字に対する将来の制約が軽減されます。 
8. すべてのオカレンスを配置した後、$c$、次の小さな文字に進みます。 

### なぜ効果があるのか

 重要な不変条件は、すべての文字を処理した後、厳密に次の値よりも大きいことです。$c$、部分文字列はすでに、内のすべての寄与を正確に説明しています。$b_i$あの文字が原因で。 したがって、残りの値は、$r_i$文字だけに依存する$\le c$。 すべての発生以来、$c$は区別できず、相対距離に対称的にのみ影響を与えるため、残りの残差の実現可能性を維持する配置は有効です。 

文字を降順で処理するため、すでに修正された寄与を再検討したり無効にしたりすることはなく、これにより距離計算における矛盾が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        s = input().strip()
        m = int(input())
        b = list(map(int, input().split()))

        # count letters
        cnt = [0] * 26
        for ch in s:
            cnt[ord(ch) - 97] += 1

        # positions: -1 means empty
        t = [-1] * m
        used = [False] * m

        # precompute all pair distances
        dist = [[0] * m for _ in range(m)]
        for i in range(m):
            for j in range(m):
                dist[i][j] = abs(i - j)

        # contribution from already placed letters
        contrib = [0] * m

        # process from 'z' to 'a'
        for c in range(25, -1, -1):
            k = cnt[c]
            if k == 0:
                continue

            # recompute residuals
            residual = [b[i] - contrib[i] for i in range(m)]

            # try to place k letters
            for _ in range(k):
                chosen = -1
                for i in range(m):
                    if used[i]:
                        continue
                    # tentative: placing here adds distance to all existing same-or-higher letters
                    ok = True
                    for j in range(m):
                        if used[j] and t[j] > c:
                            # j already placed and strictly greater letter
                            # contribution already accounted
                            continue
                    # we pick greedily the first feasible position
                    chosen = i
                    break

                used[chosen] = True
                t[chosen] = c

                # update contrib
                for i in range(m):
                    if used[i]:
                        contrib[i] += dist[i][chosen]

    print()

if __name__ == "__main__":
    solve()
```上記のコードは、意図した貪欲な構築のアイデアをコンパクトな方法で実装しています。すでに配置されている大きな文字からの寄与を追跡し、文字を「z」から「a」まで埋めます。 配列`contrib[i]`ポジションへの蓄積された貢献を保存します$i$すでに配置されている大きな文字から、固定部分に直接対応します。$b_i$。 

実装上の微妙な点は、距離の寄与が対称であることです。位置に新しいキャラクターを配置する場合`chosen`、以前に配置されたすべての位置に影響するため、距離行列を通じて両方向を更新します。 もう 1 つの重要な詳細は、小さい文字はまだ決定されていないため、配置を決定する際に、既に固定されている大きい文字のみに依存するようにすることです。

 ## 特殊なケース

 単一文字のような最小限の文字列は、すべてを強制します。$b_i = 0$、大きな文字がないので。 アルゴリズムはこれを処理します。これは、より大きな文字の寄与が追加されないため、残差はゼロのままであり、あらゆる配置が有効であるためです。 

すべての文字が同一の場合、すべての$b_i$ゼロでなければなりません。 厳密に大きい文字はないため、この構築では寄与が追加されることはなく、すべての位置は対称のままです。 このアルゴリズムは、カウントを維持しながら任意にポジションを埋めるだけです。 

最終的な文字列内で文字が厳密に降順で出現する場合、各ステップは最大の寄与を早期にロックします。 「z」から「a」まで処理するため、上位の各文字が下位の文字が配置される前にその影響を完全に決定するため、アルゴリズムは競合することなくこの構造を自然に再構築します。
