 ## 問題の理解

 1 から n までの数値のランダム化された入力順列が与えられ、限られた再帰深さ k に対してのみ実際のクイックソートのように動作する非標準の QuickSort プロシージャを繰り返し適用します。 パーティション ステップは構造的には決定的ですが、現在のセグメントの中間位置の値に依存し、ピボットより小さいものはすべて左側に、大きいものはすべて右側に配置されるように要素を再配置します。 

再帰は深さが制限されています。許容される高さのパラメーターが 1 に低下すると、アルゴリズムはサブ配列の分割を停止します。 これは、配列を完全にソートするのではなく、部分的にのみ深さ k の階層ブロック構造に「編成」することを意味します。 その後、残りのセグメント内の内部順序は、さらに調整することなく、以前のパーティション操作によって生成されたままになります。 

私たちが気にする量は、この部分的な QuickSort プロセス後の最終配列内の反転の数ですが、最初のすべての並べ替えの平均です。 問題が要求する最終的な答えは、この期待値そのものではありません。 代わりに、n! を出力するように求められます。 これに予想される反転数を掛けます。これにより、整数の結果が保証され、分数が回避されます。 

制約は大きく、n と k は両方とも最大 6000 まで可能で、テスト ケースは最大 300000 個あります。 これにより、クエリごとまたは順列ごとのシミュレーションが即座に除外されます。 許容可能なソリューションはすべて、構造化 DP または組み合わせ形式ですべての回答を事前計算し、一定時間内に各クエリに回答する必要があります。 

QuickSort の 1 回の実行でも O(n log n) であり、n 回の平均を取る必要があるため、プロセスの単純なシミュレーションはすでに実行不可能です。 順列。 モンテカルロ サンプリングでさえ、精度と時間の制約により失敗します。 

見落としがちな微妙な点は、この QuickSort が安定しておらず、完全に並べ替えられていないことです。 制限された深さの再帰ツリーに沿ってパーティション制約のみを強制します。 つまり、要素は値によってグローバルに順序付けされるのではなく、遭遇したピボットによってのみローカルに制約されます。 

2 番目の落とし穴は、k レベルの後に、すべてがディスプレイスメント限界の意味で k ソートされると仮定することです。 これは誤りです。なぜなら、パーティションは要素を不安定に再配置するため、セグメント内のローカルな順序付けは依然として本質的には前の分割によってのみ制約される完全なランダムな並べ替えであるからです。 

## アプローチ

 強引なアイデアは、すべての順列を生成し、切り捨てられた QuickSort を実行し、反転を数えて平均することです。 これは定義上は正しいですが、n 個あるためすぐに爆発します。 順列。 

単一の順列を修正する場合でも、再帰のシミュレーションは O(n log n) です。 n倍する！ そのアイデアは完全に使用できなくなります。 

重要な構造的観察は、順列をシミュレートする必要がまったくないということです。 このプロセスはすべての順列にわたって対称であり、分割はセグメント内の要素間のピボットの相対ランクにのみ依存します。 入力は一様にランダムであるため、ピボット ランクは一様に分布します。 

これにより、「順列の追跡」から「すべての順列にわたるカウントの追跡」に切り替えることができます。 期待値を計算する代わりに、n! を計算します。 期待値を直接乗算し、すべての確率を整数の組み合わせ重みに変換します。 

再帰により、各分割後に問題が左右の独立した部分問題に自然に分割されます。 すべての左側の値は厳密にピボットよりも小さく、すべての右側の値は厳密に大きく、パーティションでは左側のブロック全体が右側のブロックの前に配置されるため、パーティション化後に左右の間で交差反転は作成されません。

したがって、反転への寄与全体はサブセグメントの独立した寄与に分解され、唯一の困難は、各分割構成につながる順列の数と、それらのサブ問題がどのように結合するかを数えることになります。 

これにより、セグメント サイズ n と再帰深さ k にわたる動的プログラミングが可能になり、遷移はピボット ランクの二項選択と左右の順列の階乗重み付けの組み合わせによって表現されます。

 ## アルゴリズムのチュートリアル

 dp[n][k] を、高さ k で切り捨てられた QuickSort を実行した後の、サイズ n のすべての順列にわたる反転カウントの合計として定義します。 

また、fact[n] を階乗として定義します。これは、順列がどのように分割されるかを数えるときに繰り返し現れるためです。 

### ステップ 1: 基本ケース

 k = 1 の場合、アルゴリズムは分割をまったく実行しないため、配列は元のランダムな順序のままになります。 ランダムな置換で期待される反転数は n(n−1)/4 であるため、合計値は dp[n][1] = fat[n] · n(n−1)/4 となります。 

### ステップ 2: 1 つのパーティション レベルを理解する

 k ≥ 2 の場合、最初の呼び出しでは、中央のインデックスから取得したピボットを中心に配列を分割します。 一様ランダム順列では、ピボット値はすべての n 要素間で一様にランダムであるため、そのランク i を条件にすることができます。 

ピボットのランクが i の場合、ちょうど i−1 個の要素が左に移動し、n−i 個の要素が右に移動します。 

ピボットの値を固定し、残りの要素を任意に並べ替えるので、ピボットのランク i が固定されている場合の並べ替えの数は正確に (n−1)! です。 

分割後、すべての反転は完全に左セグメントまたは右セグメント内に含まれます。 すべての左の値がすべての右の値よりも小さく、パーティションではすべての左の要素がすべての右の要素の前に配置されるため、相互反転は存続しません。 

### ステップ 3: 再帰的分解

 固定ピボット ランク i の場合、サイズ i-1 の左セグメントは深さ k-1 で処理され、サイズ n-i の右セグメントも深さ k-1 で処理されます。 

左側の場合、サイズ i-1 のすべての可能な順列が dp[i-1][k-1] の反転合計に寄与します。 このような左の順列ごとに、右側は (n-i) に寄与するサイズ n-i の任意の順列にすることができます。 可能性。 対称的に、右順列の修正は (i−1)! に寄与します。 左側の選択肢。 

これにより、すべての順列を合計すると、両側が均等に寄与する対称式が得られます。 

### ステップ 4: 対称の重複を除去する

 再インデックス化後、左右の寄与は両方とも同じ畳み込み構造に減少します。 繰り返しは次のようになります。 

dp[n][k] = 2 · (n−1)! · dp[j][k-1] · (n-1-j) の 0 から n−1 までの j の合計！ 

この式は、階乗項によって重み付けされた、前の深さレベルでの dp のプレフィックス値にのみ依存します。 

### ステップ 5: DP 計算戦略

 固定 k ごとに、dp[_][k−1] から dp[_][k] を O(n²) 時間で計算します。 

階乗を一度事前計算します。 次に、各 k について、逆順に階乗を乗算した dp[j][k−1] に対してサフィックス加重プレフィックス合計を構築します。これにより、各 dp[n][k] を k ごとに前処理した後に O(1) で計算できるようになります。 

### ステップ 6: 質問に答える

 各クエリは dp[n][k] を直接要求しますが、これはすでに事前計算されています。 

### なぜ効果があるのか

 核となる不変条件は、すべての分割ステップの後、配列が独立した部分問題に分解され、その内部の置換がすべての有効な構成にわたって均一に分散されるということです。 ピボットの選択は構造ではなくランクのみに依存し、入力は均一な順列であるため、この均一性は維持されます。 その結果、再帰の各レベルは問題を、純粋に組み合わせカウントによって重み付けされた独立した小さなインスタンスに変換します。これはまさに dp 再帰が捉えるものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 6000

# factorials
fact = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

# dp[k][n] flattened as dp[k][n]
dp = [[0] * (MAXN + 1) for _ in range(MAXN + 1)]

# k = 1 base case
for n in range(MAXN + 1):
    dp[1][n] = fact[n] * (n * (n - 1) // 2 % MOD) % MOD * pow(2, MOD - 2, MOD) % MOD

# main transitions
for k in range(2, MAXN + 1):
    pref = [0] * (MAXN + 2)

    # build weighted suffix-like structure
    for j in range(MAXN, -1, -1):
        val = dp[k - 1][j] * fact[j] % MOD
        pref[j] = (pref[j + 1] + val) % MOD

    for n in range(MAXN + 1):
        dp[k][n] = 2 * fact[n - 1] % MOD * pref[n] % MOD if n > 0 else 0

# answer queries
t = int(input())
out = []
for tc in range(1, t + 1):
    n, k = map(int, input().split())
    if k > MAXN:
        k = MAXN
    out.append(f"Case #{tc}: {dp[k][n]}")

print("\n".join(out))
```The factorial array is required because the DP works on counts over all permutations rather than probabilities. The division by 2 in the base case converts n(n−1) into n(n−1)/2 while keeping modular arithmetic consistent.

 The main DP table is indexed by depth first because each level depends only on the previous one, and we never revisit earlier states. The suffix accumulation allows each dp[n][k] to be computed without recomputing inner sums.

 A subtle implementation detail is handling k larger than the precomputed limit. Since depth beyond n effectively stabilizes the process, we safely clamp k.

 ## 特殊なケース

 n = 1 の場合、ペアは存在しないため、k に関係なく反転は常に 0 になります。 階乗重み付けは空の反転カウントを乗算するため、DP は正しくゼロを返します。 

k = 1 の場合、再帰は起こらず、アルゴリズムは一様な順列に対する古典的な逆変換の期待に帰着します。 DP 基本ケースはこれを明示的にエンコードするため、大きな n であってもシミュレーションなしで正しく動作します。 

k ≥ n の場合、再帰の深さは要素をシングルトンまで完全に分離するのに十分であり、反転がゼロで完全にソートされた配列が得られます。 すべてのより深い部分問題は、反転寄与がゼロであるサイズ 1 のセグメントに崩壊するため、DP は自然にゼロに収束します。
