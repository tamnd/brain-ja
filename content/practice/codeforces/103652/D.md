 ## 解決策
 ## 問題の理解

 入力はいくつかの独立したテスト ケースを記述し、それぞれが ASCII アートで描かれた有限の六角形グリッドを与えます。 この図内にはマークされたセルがあり、それぞれの中央に星印が付いています。 これらの星付きセルが対象となる唯一の頂点です。 

星付きセルの各ペアは、基礎となるハニカム グラフに対する接続性の質問を暗黙的に定義します。 グリッドは、頂点がセルの中心に対応し、エッジが共有六角形の境界に対応するグラフをエンコードします。 2 つの隣接セル間の各隣接セルには、図面に応じて、通過可能なエッジまたはブロックされたエッジがある場合があります。 

各テスト ケースについて、特別な (スター付き) セルのすべてのペアを考慮する必要があります。 特定のペアについては、通過可能なエッジをブロックされたエッジに変換することでエッジを「カット」できます。 カット料金は1刃につき1枚の料金となります。 ペアの目標は、結果のグラフで 2 つの星付きセルが切り離されるようにカットする必要があるエッジの最小数を決定することです。 これはまさに、無向単位容量グラフの 2 つのノード間の最小エッジ カットです。 最後に、各ペアの答えを出力する代わりに、星付きセルのすべてのペアにわたるこれらの最小カットを合計する必要があります。 

グリッド サイズは最大 100 x 100 セルですが、ASCII 表現はさらに大きくなります。 すべてのテスト ケースにわたるスター付きセルの数は最大 3000 であり、これがソリューション設計の真の推進力です。3000 ノードを超えるペアワイズ処理は境界線にありますが、適切な max-flow または Gomory-Hu ツリー スタイルの削減により実現可能です。 

単純なアプローチでは、ペアごとの最小カットを個別に計算します。 たとえ各 min-cut が max-flow を介して計算されたとしても、数千のノードとエッジを含むグラフ上でヘビー フロー アルゴリズムを最大 3000 回実行することになり、これでは遅すぎます。 

さらに微妙な問題は解析です。ハニカムは標準の長方形グリッドではなく、隣接関係は ASCII でエンコードされた 16 進数のジオメトリに依存します。 斜めのエッジを誤解したり、隣接の一方向を欠落したりすると、接続が不正確になり、その結果、切断が不正確になります。 

一般に単純なソリューションを破壊するエッジ ケースには、次のような構成が含まれます。 

スター付きセルのペアはすでに切断されています。 正しい答えはゼロであり、流量は計算されません。 

セル間に斜めの接続のみが存在する構成では、隣接関係の抽出ではスラッシュとバックスラッシュの両方を正しく解釈する必要があります。 

スター付きセルの密なクラスター (最大 3000)。ペアごとの再計算が実行できなくなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 グリッドを、各セルの中心がノードである無向グラフとして扱います。 スター付きノードのペアごとに、最小 s-t カットを計算します。これは、エッジ上のユニット容量を使用して max-flow アルゴリズムを実行するのと同等です。 スター付きノードが k 個ある場合、k(k−1)/2 回のフロー計算が行われます。 

最大約 O(nm) のノードとエッジを持つグラフ上の各最大フローは、たとえ Dinic を使用したとしても高価になる可能性があり、それを何千回も実行すると膨大な実行時間につながり、制限を数桁も簡単に超えてしまいます。 

重要な観察は、すべてのペアごとの最小カットを独立して行う必要はないということです。 これは、古典的な全ペアの最小カット集計問題です。 活用すべき正しい構造は、無向グラフ上のペアごとの最小カットが Gomory-Hu ツリーによってコンパクトに表現できることです。 このツリーを構築すると、星付きの 2 つのノード間の最小カットは、ツリー内のそれらの間のパスに沿った最小エッジの重みになります。 これにより、問題が 2 次の流れ計算から線形数の流れ計算に減ります。 

スター付きノードは最大 3000 個あるため、これらの端末上に Gomory-Hu ツリーを構築するには最大 2999 回の最大フロー計算が必要です。 各計算はノードのサブセットに分割され、総コストは管理可能です。

残りの課題は、ASCII ハニカムから基礎となるグラフを正しく構築することです。 グラフが構築されると、すべてが標準の最大流量機械に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (全ペア最大フロー) | O(k²・F) | O(V + E) | 遅すぎる |
 | ゴモリー・フーの木 | O(k・F) | O(V + E + k²) | 承認済み |

 ここで、F は 1 回の最大フロー計算のコストを示します。 

## アルゴリズムのチュートリアル

 まず、ASCII 表現をグラフに変換します。 

1. グリッドを解析し、星を含む各セルの中心に整数インデックスを割り当てます。 これらを終端ノードとして保存し、そのペアごとのカットを評価する必要があります。 
2. 各セルがノードとなるグラフを作成します。 ハニカム ジオメトリによって暗示されるあらゆる隣接関係について、2 つの隣接するセル間のエッジが通過可能かどうかを確認します。 存在する場合、容量 1 の無向エッジを追加します。エッジの削除ごとに正確に 1 コストがかかるため、容量は 1 です。 
3. 通過できないエッジをすべて無視します。 単にグラフに存在しないだけです。 これにより、すべてのカットが通過可能な接続の削除に正確に対応することが保証されます。 
4. 終端ノード (星付きセル) のリストを抽出します。 k をその数とします。 
5. 反復最小カット計算を使用して、これらの k ノード上に Gomory-Hu ツリーを構築します。 親配列と、最初に任意に接続された k ノードのツリーを維持します。 
6. 1 から k−1 までの各ノード i について、Dinic のアルゴリズムを使用して、ノード i とツリー内の現在の親との間の最小 s-t カットを計算します。 これにより、カット値とノードの 2 つのセットへの分割が得られます。 
7. ツリー構造を更新します。必要に応じて、同じパーティション内のすべてのノードの親が更新され、Gomory-Hu 構造の正確さを維持します。 カット値は、i とその親の間の木のエッジの重みになります。 
8. Gomory-Hu ツリーを構築した後、スター付きノードに対するすべてのペアの寄与を計算します。 すべてのペアを明示的に列挙し、パス最小値を繰り返しクエリする代わりに、ツリーのエッジをソートし、共用体検索寄与手法を使用することで、すべてのペアの合計を計算できることを利用します。 木の各エッジは、その重みに、それが分離するペアの数を乗じたものになります。 
9. 最終的な累積合計を出力します。 

### なぜ効果があるのか

 Gomory-Hu 構築の重要な不変条件は、ノード i の処理後、ツリーが最初の i ノード間のすべてのペアの最小 s-t カットを正しく表すことです。 最小カットは縮小とパーティションのリファインの下でも一貫しているため、計算された各カットはグローバルに有効です。 これにより、最終的なツリーが正確なペアごとの最小カット値をエンコードし、任意の 2 つのノードの最小カットがこのツリー内のパス上の最小エッジの重みに対応することが保証されます。 すべてのペアの合計は、分離されている端子ペアの数によって重み付けされたツリー エッジの寄与を合計することと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0
        while q:
            u = q.popleft()
            for v, c, _ in self.adj[u]:
                if c > 0 and self.level[v] < 0:
                    self.level[v] = self.level[u] + 1
                    q.append(v)
        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f
        for i in range(self.it[u], len(self.adj[u])):
            self.it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and self.level[v] == self.level[u] + 1:
                ret = self.dfs(v, t, min(f, c))
                if ret:
                    self.adj[u][i][1] -= ret
                    self.adj[v][rev][1] += ret
                    return ret
        return 0

    def maxflow(self, s, t):
        flow = 0
        INF = 10**18
        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                f = self.dfs(s, t, INF)
                if not f:
                    break
                flow += f
        return flow

## 実用的な例

 2 つの星付きセルが 1 つの通過可能なエッジで接続されている最小のケースを考えてみましょう。 その単一のエッジを削除すると切断されるため、それらの間の最小カットは 1 です。 Gomory-Hu 構造は、そのエッジの重みを直接割り当てます。 

3 つの星付きセルがチェーン状に配置されたやや大きな構成では、中央のエッジが容量 1 のボトルネックとなり、ペアワイズ カットは次のように動作します。エンドポイントでは 1 つのエッジをカットする必要がありますが、中央へのエンドポイントも 1 つです。 ペアの合計は 3 になり、Gomory-Hu ツリーのツリー エッジ寄与の合計と一致します。 

| ステップ | アクティブなペア | フロー結果 | ツリーの状態 |
 | --- | --- | --- | --- |
 | 1 | (1,2) | 1 | エッジ1 |
 | 2 | (2,3) | 1 | エッジ2 |

 これは、繰り返された最小カット計算が一貫しており、ツリー構造にきれいに集約されていることを示しています。 

## 複雑さの分析

 ## 特殊なケース

 2 つの星付きセルがすでに切断されている場合は、それらの間の最大流量がゼロであるため、自然に処理されます。 このアルゴリズムには特別なケースは必要ありません。 拡張パスが存在しないため、Dinic はすぐにゼロを返します。 

すべてのエッジがブロックされている場合、頂点が孤立したグラフが生成されます。 すべてのペアには最小カット ゼロがあり、Gomory-Hu 構築では空の重みツリーが生成されるため、最終的な合計は予想どおりゼロになります。 

密接に接続されたクラスターにより、複数のエッジが最小カットに表示されることが保証されます。 Gomory-Hu ツリーは、真のボトルネック エッジを分離することで一貫性を確保し、各カット値は再計算せずにすべてのペアで正しく再利用されます。
