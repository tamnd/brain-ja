 ## 解決策
 ## 問題の理解

 文字列が与えられ、「正方形」を形成する部分列を抽出するように求められます。 正方形の文字列とは、長さが偶数で、前半と後半が同じである文字列です。 つまり、文字列を 2 つの等しい部分に分割した場合、両方の部分が 1 文字ずつ一致する必要があります。 タスクは部分文字列を見つけることではなく、部分シーケンスを見つけることであるため、順序を維持しながら文字を削除することができます。 

各テスト ケースでは、可能な限り長い正方形のサブシーケンスが必要であり、そのようなサブシーケンスを 1 つ出力する必要もあります。 

主な制約は、すべてのテスト ケースの合計の長さが最大 ​​3000 であることです。これは、テスト ケースごとに 2 次またはわずかに 3 次の動作を中心とした解は許容できることをすぐに示唆していますが、テスト ケースごとに 3000 の 3 次のものは、繰り返した場合に遅すぎます。 テスト ケースごとにおよそ O(n^2)、または最適化を使用した場合は O(n^3 / 26) のソリューションがターゲット領域です。 

ここでよく見られる素朴な誤解は、連続した半分を一致させていると考えることです。 これにより、問題は些細なものに減りますが、サブシーケンスでは任意の間隔が許可されるため、組み合わせの問題になります。 

いくつかの特殊なケースでは、よくある誤った推論が明らかになります。 

文字列が「abcd」の場合、文字の繰り返しがないため、空でない正方形の部分列は存在しません。 正解は 0 です。順序を考慮せずに位置をペアにしようとする貪欲な試みは、非正方形または無効なものを誤って生成します。 

文字列が「aaaa」の場合、最適な答えは「aa aa」で、長さは 4 になります。2 つの同一の互いに素な部分文字列を見つけようとするだけの単純なアプローチでは、選択肢をインターリーブできることを見逃してしまう可能性があります。 

文字列が「abac」の場合、「abac」は長さ 4 の正方形を生成できると誤って考えるかもしれませんが、部分列制約の下では 2 つの同一の半分に分割しようとすると失敗するため、生成できません。 

重要な問題は、元の文字列から 2 つの同一のサブシーケンスを選択し、それらの共通の長さを最大化したいことです。 

## アプローチ

 この問題は、A が B と等しく、全長が最大になるように、元の文字列から 2 つのサブシーケンス A および B を選択するものとして再解釈できます。 A の長さが k の場合、答えは 2k です。 

これにより、同じ文字列の 2 つのコピー間の最長の共通部分列を見つけるようにタスクが即座に再構成されますが、制約があります。2 つのコピーは元の文字列内の互いに素なインデックスのセットに対応する必要があり、インデックスの次数は両方の半分で同時に増加する必要があります。 これはまさに自己 LCS 問題の構造に、インデックスの使用において 2 つのサブシーケンスが互いに素でなければならないという制限が追加されています。 

ブルートフォースアプローチでは、前半のすべてのサブシーケンスを列挙し、後半のすべてのサブシーケンスと照合しようとします。 これは n で指数関数的であり、およそ O(2^n) であり、n = 30 の場合でも完全に実行不可能です。 

標準的な改善は、位置のペアに対する動的プログラミングです。 dp[i][j] を、位置 i と j から始まる一致するサブシーケンスの最適な長さとして定義しますが、これでも、次に発生する状態と遷移は O(n^2) であり、遷移ごとに O(n) になる可能性があり、O(n^3) が得られます。これは境界線ですが、3000 には遅すぎます。 

重要な点は、アルファベットが小さい (小文字のみ) ということです。 これにより、文字を照合するときに前方に直線的にスキャンすることを回避できます。 代わりに、位置ごとに各文字の次の出現を事前計算して、O(1) ジャンプを有効にすることができます。 

これにより、DP 遷移が状態ごとの一定時間に変換され、O(n^2) の解が得られます。 

次に、一致したペアを構築して答えを再構築し、増加するインデックスを尊重し、各一致が有効な文字ペアに対応していることを確認します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサブシーケンス列挙 | O(2^n) | O(n) | 遅すぎる |
 | 最適化なしで DP をペアにする | O(n^3) | O(n^2) | 遅すぎる |
 | 次回出現最適化を備えた DP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、同じ文字列から 2 つの同一のサブシーケンスを構築し、それらの共通の長さを最大化するものとして扱います。 

### 1. 次の出現を事前計算する

 各位置および各文字について、その文字が出現する次のインデックスを計算します。 これにより、線形にスキャンするのではなく、次の使用可能な一致に直接ジャンプすることができます。 DP は「i の後の文字 c の次の位置」を繰り返し必要とするため、これは非常に重要です。 

### 2. DP 状態を定義する

 dp[i][j] を、位置 i と j で始まる接尾辞を使用して形成できる正方形サブシーケンスの最大長として定義します。ここで、i は前半の次に未使用のインデックス、j は後半のインデックスです。 両方の半分で同じ文字インデックスが再利用されることを避けるために、i < j の状態のみを考慮します。 

この順序制約により、元の文字列内の 2 つのサブシーケンスが確実に互いに素になることが保証されます。 

### 3. 移行ロジック

 状態 (i, j) から、文字 c との一致を試みます。 i の次に出現する c を見つけて i2 と呼び、j の次に出現するものを j2 と呼びます。 両方が存在する場合は、ペアを形成し、(i2 + 1, j2 + 1) に移動することで答えに 2 を加算できます。 すべてのキャラクターの最高のものを採用します。 

また、どちらかの半分で位置をスキップすることもできます。つまり、より良い一致を探索するために i または j を個別に進めます。 

これにより、局所的に不適切なペアリングの選択に行き詰ることがなくなります。 

### 4. 逆の順序で DP を計算します。 

dp[i][j] を計算するときに、より大きなインデックスを持つすべての dp 状態がすでに既知であるように、文字列の末尾から逆方向に dp を埋めます。 

### 5. ソリューションを再構築する

 dp[0][0] から開始して、最適値に達した遷移をたどり、ペアリング遷移を選択するたびに一致した文字を出力します。 

### なぜ効果があるのか

 すべての状態 (i, j) で、プレフィックスの決定がすでに修正されており、インデックスの使用が厳密に i と j の後にのみ許可されている場合、 dp[i][j] は可能な限り最良の完了を表します。 順序不変条件により、文字を再利用することがなく、サブシーケンスの順序が常に保持されることが保証されます。 すべての遷移は文字をスキップするか、一致したペアを消費するため、すべての有効な構造が暗黙的に探索され、それらの最大値が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    if n == 0:
        return "Case #1: 0\n"

    # next occurrence array
    nxt = [[n] * 26 for _ in range(n + 1)]
    for c in range(26):
        nxt[n][c] = n

    for i in range(n - 1, -1, -1):
        for c in range(26):
            nxt[i][c] = nxt[i + 1][c]
        nxt[i][ord(s[i]) - 97] = i

    # dp[i][j] for i <= j
    dp = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n, -1, -1):
        for j in range(n, -1, -1):
            if i >= j:
                continue
            best = dp[i + 1][j]
            best = max(best, dp[i][j + 1])

            for c in range(26):
                i2 = nxt[i][c]
                j2 = nxt[j][c]
                if i2 < j2 and i2 < n and j2 < n:
                    best = max(best, 2 + dp[i2 + 1][j2 + 1])

            dp[i][j] = best

    # reconstruction
    i, j = 0, 0
    left = []
    right = []

    while i < n and j < n:
        if i >= j:
            j = i + 1
            continue

        cur = dp[i][j]

        if dp[i + 1][j] == cur:
            i += 1
            continue
        if dp[i][j + 1] == cur:
            j += 1
            continue

        found = False
        for c in range(26):
            i2 = nxt[i][c]
            j2 = nxt[j][c]
            if i2 < j2 and i2 < n and j2 < n:
                if dp[i][j] == 2 + dp[i2 + 1][j2 + 1]:
                    left.append(s[i2])
                    right.append(s[j2])
                    i = i2 + 1
                    j = j2 + 1
                    found = True
                    break
        if not found:
            break

    ans = left + right[::-1]
    res = ''.join(ans)
    return f"{len(res)}\n{res}\n" if res else "0\n"

def main():
    T = int(input())
    out = []
    for tc in range(1, T + 1):
        res = solve().strip()
        if res == "0":
            out.append(f"Case #{tc}: 0")
        else:
            lines = res.split("\n")
            out.append(f"Case #{tc}: {lines[0]}")
            out.append(lines[1])
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、スキャンを回避するために次の出現テーブルに大きく依存しています。 DP テーブルはボトムアップで埋められるため、必要なときに将来のすべての状態が準備されます。 再構築中は、常に最初にスキップ遷移をチェックし、次に文字の一致を試みて、有効な最適なパスをたどることを保証します。 

微妙な点は、再構築中に i < j を維持することです。 その不変式が壊れた場合、j を i + 1 にリセットして、素の半分を保持します。 

## 実用的な例

 ### 例: 「アバ」

 次の出現と DP の選択を計算します。 

| 私 | j | アクション | 選択された遷移 | dp[i][j] |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 「a」に一致 | (0,3) → ターミナル | 2 |
 | 0 | 0 | jをスキップ | jを移動 | 2 |

 アルゴリズムは「aa」を選択します。 

これは、「abba」に対称性があるとしても、実行可能な唯一の正方部分列は長さ 2 であることを示しています。 

### 例: 「アバブ」

 ここには複数の一致が存在します。 

| 私 | j | アクション | 移行 | DP |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 「a」に一致 | 位置 (0,3) を使用します。 4 |
 | 0 | 0 | 有効な j | までスキップします。 調整 | 4 |

 再構築により「abab」が得られます。 

これは、スキップによって、将来のより長い構造をブロックする初期の 'b' の組み合わせなど、局所的に悪い一致を確実に回避できることを示しています。

 | 測定 | 複雑さ | 説明 |

| スペース | O(n^2) | DP テーブルと次の出現テーブル |

 ## 特殊なケース

 入力「abcd」の場合、DP は双方が前進できる有効な文字ペアをまったく見つけられないため、すべての状態がスキップ遷移に崩壊します。 最終的な dp[0][0] は 0 のままで、再構築により空の文字列が生成されます。 

「aaaa」の場合、すべての文字には有効な次の出現があり、DP は両方の半分が使い果たされるまで一貫してペア遷移を選択します。 再構築により、左側に「aa」が直接構築され、それが右側に反映され、予想どおり「aaaa」が生成されます。
