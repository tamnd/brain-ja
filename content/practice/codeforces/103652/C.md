 ## 問題の理解

 パラメーターによって定義された一般化されたフィボナッチ数列が与えられます。$P$。 シーケンスは固定シードから始まります$F_0 = 0$そして$F_1 = 1$、次のすべての項は線形漸化式によって形成されます$F_n = P \cdot F_{n-1} + F_{n-2}$。 これは、次の場合に標準のフィボナッチ数列のように動作します。$P = 1$、しかし、はるかに速く成長します$P$が増えます。 

このタスクが標準的でないのは、このシーケンスの単一のインデックスについて質問されないことです。 代わりに、シーケンスの「二重適用」を見てみましょう。まず次のことを計算します。$F_n$そして、その値を再びインデックスとして使用して計算します。$F_{F_n}$。 結果は巨大な整数ですが、注目するのはその最後の整数だけです$k$10 進数。 

テストケースごとに、次のものが与えられます。$P$、下限$m$、および最後の文字列を表す文字列$k$の桁$F_{F_n}$。 目標は最小のものを見つけることです$n \ge m$最後のような$k$の桁$F_{F_n}$指定された文字列と一致するか、そのような文字列が存在しないと判断します$n$存在します。 

制約から得られる重要な観察は次のとおりです。$k \le 18$したがって、すべての比較はモジュロです$10^k$、これでも 64 ビット整数に収まります。 しかし、$n$と同じ大きさにすることができます$10^{18}$したがって、すべてのインデックスを反復処理することはできません。 これにより、シーケンスモジュロの周期構造に頼らざるを得なくなります。$10^k$。 

シーケンスがサイクルモジュロに入ると、微妙なエッジケースが発生します。$10^k$。 合成数を法とするフィボナッチ型シーケンスは常に周期的になるため、単調性または増加を仮定する単純な検索はすぐに失敗します。 もう 1 つの問題は、内項$F_n$それ自体がインデックスとして使用されるため、たとえ$F_n$何かを法として繰り返します。シーケンスへの実際のインデックスは、の完全な値に依存します。$F_n$、その残留物だけではありません。 

たとえば、2 つの異なるインデックス$n$そして$n'$同じものを生み出すかもしれない$F_n \bmod 10^k$、しかしそれでも異なる価値観につながります$F_{F_n}$インデックス付けのステップは整数の縮小ではなく完全な整数に依存するためです。 これはまさに、単純なモジュールのみの推論を打ち破る一種の隠れた依存関係です。 

## アプローチ

 ブルートフォースのアイデアは単純です: 計算する$F_n$増やすための$n$、次に計算します$F_{F_n}$、最後を取る$k$数字を入力して比較します。 これは定義を直接評価するため、原則として正しいです。 ただし、コンピューティング$F_{F_n}$高速倍増が必要$O(\log F_n)$、 そして$F_n$それ自体が指数関数的に成長します$n$、そのため、インデックスは非常に急速に天文学的に大きくなります。 数千の値をチェックしたとしても$n$各チェックには非常に大きなインデックスに対する 2 つの高速累乗が含まれるため、実行不可能になります。 

重要な洞察は、関連するものはすべてモジュロで発生するということです$10^k$、そしてシーケンス$F_n \bmod 10^k$定期的です。 期間がわかったら、1 つの完全なサイクルを調べるだけで済みます。 サイクル内では、次のすべての値が$F_n \bmod 10^k$内部インデックスの固定パターンに対応し、関数$F_{F_n} \bmod 10^k$独立して評価することができます。 

したがって、問題は 2 つの層に集約されます。 まず、シーケンスの周期を検出します。$F_n \bmod 10^k$与えられた再発の下で。 次に、そのサイクル内の各位置について、対応する$F_{F_n} \bmod 10^k$そしてそれをターゲットのサフィックスと照合します。 

状態遷移は連続するペアのみに依存するという事実を利用します。$(F_n, F_{n-1}) \bmod 10^k$。 これにより、最大で次のサイズの有限状態空間が得られます。$(10^k)^2$、そして実際には、サイクルははるかに早い段階で現れるため、ハッシュまたはフロイドスタイルのサイクル検出を使用してそれを検出できます。 

サイクルがわかったら、各クエリへの応答は、最初のインデックスから始まるサイクルにわたる線形スキャンになります。$\ge m$、状態を確認します。

 ## アルゴリズムのチュートリアル

 私たちはフィボナッチのような数列をペアに対する決定論的な状態マシンとして扱います。 

### 1. シーケンスモジュロを構築する$10^k$私たちは生成します$F_n \bmod M$どこ$M = 10^k$、回帰を使用します。 各状態はペアです$(F_n, F_{n-1})$。 これにより、次の値が完全に決まります。 

すべての比較は最後のもののみに依存するため、この手順が必要です。$k$数字なので、完全な整数は必要ありません。 

### 2. 状態のサイクルを検出する

 から反復します$n = 0$確認された状態を保存します$(F_n, F_{n-1})$。 状態が繰り返されると、サイクルが特定されます。 

これが機能する理由は、状態空間が有限であるためです。$M^2$可能なペアのモジュロ$M$なので、繰り返しが保証されます。 エントリーポイントとサイクルの長さを記録します。 

### 3. 内部フィボナッチ評価を事前計算する

 インデックスごとに$n$1 サイクルで計算します$F_{F_n} \bmod M$。 これには、任意のインデックスでフィボナッチを評価する必要があります。これは、高速ダブリングを使用して行います。$O(\log F_n)$。 

重要な観察は、これはすべてのサイクル位置ではなく、サイクル位置に対してのみ必要であるということです。$n$。 

### 4. 有効なインデックスをスキャンする

 に対応するサイクル インデックスを反復処理します。$n \ge m$。 そういったものごとに$n$、計算されたサフィックスをターゲット文字列と比較します。 

最初の一致で答えが得られます。 

サイクル内に一致するものが存在しない場合、答えは不可能です。 

### なぜ効果があるのか

 正しさは、サイクルに入った後、ペアのシーケンスが$(F_n, F_{n-1}) \bmod 10^k$正確に繰り返します。 両方なので$F_n \bmod 10^k$そして後続のすべての計算はこのペア、つまり次の値のみに依存します。$F_{F_n} \bmod 10^k$も同じ周期で繰り返します。 したがって、すべての有効なソリューションは最初の完全なサイクル内に出現する必要があり、それ以降をチェックしても新たな可能性は追加されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def fib_pair(n, mod):
    # returns (F_n, F_{n+1}) mod mod using fast doubling
    if n == 0:
        return (0, 1)
    a, b = fib_pair(n >> 1, mod)
    c = (a * ((2 * b - a) % mod)) % mod
    d = (a * a + b * b) % mod
    if n & 1:
        return (d, (c + d) % mod)
    else:
        return (c, d)

def fib(n, mod):
    return fib_pair(n, mod)[0]

def solve():
    t = int(input())
    for tc in range(1, t + 1):
        parts = input().split()
        P = int(parts[0])
        m = int(parts[1])
        target = parts[2]
        k = len(target)
        M = 10 ** k

        # build sequence modulo M
        seq = []
        seen = {}
        a, b = 0, 1

        idx = 0
        while True:
            state = (a, b)
            if state in seen:
                start = seen[state]
                cycle = seq[start:]
                seq = seq[:start]
                break
            seen[state] = idx
            seq.append(a)
            a, b = b, (P * b + a) % M
            idx += 1

        # compute answers over cycle
        best = None
        for i, val in enumerate(seq + cycle):
            n = i
            if n < m:
                continue
            fn = fib(n, M)
            inner = fib(fn, M)
            if str(inner).zfill(k) == target:
                best = n
                break

        if best is None:
            ans = -1
        else:
            ans = best

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```実装では外部再帰モジュロが維持されます。$10^k$状態ペアからのマップを使用して繰り返しを検出します。 サイクルが見つかると、そのシーケンスは周期的として扱われます。 

フィボナッチ評価では高速 2 倍化が使用され、クエリごとに最初から再計算する必要がなくなります。 比較は、サフィックスの動作を正確に一致させるためにゼロ埋めされた文字列を使用して行われます。 

実装の微妙な点は、サイクル抽出で正しいインデックス付けが確実に保持されるようにすることです。 インデックスを元のインデックスと揃えるために、プレフィックスとサイクルに分割する必要があります。$n$。

 ## 特殊なケース

 重要なエッジケースの 1 つは、サイクルが開始される前に発生します。$m$。 この状況では、有効な回答は繰り返されるセグメント内にのみ存在し、アルゴリズムは以前の回答を返してはなりません。 プレフィックスとサイクルを明示的に分離すると、スキャンではすべての無効なインデックスが自然にスキップされます。 

もう 1 つの微妙なケースは、サイクル内の複数の位置で同じ接尾辞が生成される場合です。 アルゴリズムは最小のインデックスを選択する必要があります$n \ge m$、サイクル順序の最初ではありません。 絶対インデックスに対する線形スキャンにより、この順序が維持されることが保証されます。 

最後のケースは、サイクル内のどの位置もターゲット サフィックスと一致しない場合です。 すべての将来の値は同じサイクルを繰り返すため、それを超えて検索を拡張しても解は得られないため、次の値を返します。$-1$は正しいです。
