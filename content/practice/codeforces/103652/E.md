 ## 解決策
 ## 問題の理解

 非負の整数に対して定義された決定論的な関数が与えられています。 任意の整数から$n$、関数はそれを固定定数で割ります。$k$可能であれば、それを 1 つ減らします。 この関数を複数回繰り返し適用することに興味があり、特に、指定された間隔内の整数から開始して、値 1 に達するまでにこの関数を何ステップ適用できるかを理解することに興味があります。$[l, r]$。 

正式には、各開始値に対して$n$、関数を繰り返し適用して定義できます。$f^m(n)$適用した結果として$m$回。 最大の指数を見つけたい$m$少なくとも 1 つ存在するように$n$合間に$[l, r]$誰のために$f^m(n) = 1$。 この最大深さがわかったら、1 に到達するためのこの最大ステップ数を達成する間隔内の最小および最大の開始値を特定する必要もあります。 

この制約により、各クエリに対するブルート フォースが不可能になります。 数値範囲は次のとおりです$10^{18}$、最大で$3 \cdot 10^5$テストケース。 これにより、値ごとのシミュレーションや、すべての候補のパスに沿って状態を列挙するアプローチさえも即座に除外されます。$n$。 

微妙な問題は、関数の動作が次の割り算に応じて大きく異なることです。$k$。 除算の長い連鎖$k$1 を減算すると、値がすぐに崩壊する可能性がありますが、除算が可能になる前に長い「調整」フェーズが作成される可能性があります。 これにより、ステップ数が単純な線形では単調ではない区分的な動作が作成されます。 

よくある落とし穴は、より大きなものを想定していることです。$n$1 に達するまでに常に時間がかかります。これは誤りです。なぜなら、数値が の倍数のすぐ上であるからです。$k$除算の恩恵を受けるまでに多くの減分ステップが必要になる場合がありますが、わずかに小さい数値であればすぐに除算できる場合があります。 

具体的な例として考えてみましょう$k=2$。 から$n=4$、クイックチェーンを取得します$4 \to 2 \to 1$。 から$n=5$、行きます$5 \to 4 \to 2 \to 1$5 は 4 よりもわずかに大きいだけですが、これは長いです。この非単調な動作こそが、問題に貪欲なシミュレーションではなく構造的推論を必要とさせる原因となっています。 

## アプローチ

 直接的なアプローチでは、すべての開始値に対して関数をシミュレートします。$n$で$[l, r]$、1 に到達するまでに必要なステップ数を計算します。これは正しいですが、各シミュレーションに時間がかかる可能性があるため、実行不可能です。$O(\log_k n + k)$最悪の場合、長い減算フェーズによりステップ数が増加し、間隔自体は次のように大きくなる可能性があります。$10^{18}$。 この関数は、開始点ごとに再計算する必要がある長い決定論的なチェーンを作成するため、狭い範囲に制限した場合でも、このアプローチは失敗します。 

重要な観察は、プロセスを逆から見ると非常に厳格な構造をしているということです。 そこから先を考えるのではなく、$n$, 最終的に 1 に達する数値がどのように構成されるかを考えると簡単になります。 逆関数を適用するたびに、数値は次のいずれかになります。$x \cdot k$(除算ステップから来た場合) または$x+1$(デクリメントステップから得られた場合、元の数値が次の値で割り切れない場合に限ります)$k$）。 

この逆の見方では、各数値には 1 に戻る一意のパスがあり、次の 2 つの演算で構成されていることがわかります。$k$したがって、数値の深さは、その固有の後方構築シーケンスの長さになります。 タスクは全体として、見つけることになります$n \in [l, r]$、1 に到達するために必要な逆ステップの最大可能数、およびこの深さが最大になる区間の終点。 

この構造は、最適なシーケンスは、次の数で割り切れる数値に達するまで繰り返し「+1」を取ることに対応することを意味します。$k$、次に除算を適用して値を圧縮します。 間隔の制約内に収まりながら、分割をできるだけ長く遅らせると、深さが最大になります。 これは、倍数の直前まで数値を繰り返し「押し上げる」貪欲な構造につながります。$k$、次に、除算によって作成されたジャンプを考慮します。 

これにより、問題は、範囲内に留まりながら、長い減算セグメントと除算圧縮ステップを何回交互に実行できるかを分析することに変わります。$[l, r]$。 最大の深さは、強制除算の前に、連続するデクリメント操作の可能な最大のチェーンを繰り返し抽出することに対応します。

 ## アルゴリズムのチュートリアル

 私たちはプロセスを逆に扱います。1 から始めて、「乗算」と「乗算」を交互に繰り返すことで、可能な限り最大の深さを構築します。$k$」と「1 つの拡張を追加」しますが、これらの拡張がどのように内部に収まるかを追跡するだけです$[l, r]$。 

### ステップ

 1. 超過する前に、逆プロセスでどこまで上に進むことができるかを計算します。$r$有効な転送パスに固定されたままであることを確認しながら。 各乗算$k$は順方向の強い圧縮に対応するため、境界内に留まりながら圧縮を何回適用できるかを数えたいと思います。 
2. 固定深さ候補の場合$m$、有効な開始番号は少なくとも存続できる必要があることがわかります。$m$以下に落ちずに逆のステップを実行する$l$。 これは、少なくとも深さを持つ最小数と最大数を構築することになります。$m$。 
3. 逆プロセスを貪欲にシミュレートします。1 から開始して、値が範囲内に収まるように乗算による拡張を繰り返し試行します。$r$、それ以外の場合は、加算拡張を使用します。 このような拡張の数により、可能な最大の深さが得られます。 
4. 最大深度が決定されたら、間隔変換を逆方向に追跡することによって、この深度を達成する開始値の範囲を再構成します。 各逆ステップは間隔をマッピングします$[x, y]$どちらかに$[x+1, y+1]$または$[xk, yk]$、そして私たちはその範囲内に残る最も狭い間隔を維持します。$[l, r]$。 
5. 最終的な答えは、計算された最大の深さと、最小および最大の深さです。$n$で$[l, r]$この深さに相当します。 

### なぜ効果があるのか

 このプロセスでは、各ノードが 1 つの親を持つ、ルート 1 のツリーを定義します。$k$あるいは逆に1を引くこともできます。 この一意性により、すべての数値が 1 への単一のパスを持つことが保証されるため、深さが明確に定義されます。 貪欲な構築は、次の乗算を行うため機能します。$k$将来の深さを減らすという点では常に減算の方が優勢であり、乗算をできるだけ長く遅らせると、逆ステップの総数が増加します。 間隔制約は線形であり、単調変換下で保存されるため、境界間隔のみを追跡するだけで、実現可能性と極値の両方を決定するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for tc in range(1, T + 1):
        k, l, r = map(int, input().split())

        # We compute maximum depth by simulating reverse growth.
        # Start from 1 as base.
        depth = 0
        cur_min = cur_max = 1

        # Track the range of values reachable at current depth.
        # At each step, we either do +1 expansion or *k expansion.
        while True:
            # Try multiplication step
            nxt_min_mul = cur_min * k
            nxt_max_mul = cur_max * k

            if nxt_min_mul <= r:
                cur_min, cur_max = nxt_min_mul, min(nxt_max_mul, r)
                depth += 1
                continue

            # Otherwise try +1 expansion
            if cur_max + 1 <= r:
                cur_min += 1
                cur_max += 1
                depth += 1
                continue

            break

        # Now depth is maximal reachable inverse length.

        # Reconstruct interval of starting values in [l, r]
        # that achieve exactly this depth.
        lo, hi = l, r

        # We "peel back" operations in reverse.
        for _ in range(depth):
            # If interval fully divisible by k, prefer inverse multiplication
            if lo % k == 0:
                lo //= k
                hi //= k
            else:
                lo += 1
                hi += 1

        out.append(f"Case #{tc}: {depth} {lo} {hi}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、逆演算の下で到達可能な間隔を拡大するという考えが維持されています。 変数`cur_min`そして`cur_max`指定された数の逆ステップの後に、以下を超えることなく生成できる最小値と最大値を表します。$r$。 各反復では、最初に乗算ステップが試行されます。これは、深さをより積極的に増加させ、乗算が限界を超える場合にのみ増分にフォールバックするためです。 

最大深度を計算した後、変換を逆にして、どの元の値が含まれているかを特定します。$[l, r]$その深さに相当します。 逆算では、順推論と同じ構造が使用されます。可能な場合は除算、そうでない場合は増分します。 

微妙な点は、範囲内にとどまるように間隔を常に固定する必要があることです。 なしで`min(..., r)`調整すると、間隔の一部が有効なままであっても、成長ステップによって無効な値が生成される可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、間隔に 1 のみが含まれる場合です。この場合、関数はすでにターゲットにあるため、最大深度は 0 で、両方のエンドポイントは 1 でなければなりません。逆拡張では範囲を超えて間隔が増加せず、初期状態は変更されないため、アルゴリズムはこれを自然に処理します。 

もう一つのケースは次のような場合です。$k$に比べて大きいです$r$。 その場合、乗算はほとんど不可能になり、プロセスは逆にデクリメント動作を繰り返すようになります。 アルゴリズムは境界に達するまで +1 拡張のみを正しく実行し、深さの線形チェーンを生成します。$r-l$。 

3 番目のケースは、間隔が次の倍数にまたがる場合に発生します。$k$。 ここでは、一方の側はすぐに除算ステップを実行できますが、もう一方は最初に複数の減分ステップを費やす必要があります。 間隔ベースの再構成では、間隔全体で均一な動作を想定せず、両方のエンドポイントを独立して追跡するため、両方の動作が同時に保存されます。
