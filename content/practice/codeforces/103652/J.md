 ## 解決策
 ## 問題の理解

 文字列とそれに対する多くの独立したクエリが与えられます。 各クエリは文字列のセグメントを指定し、その範囲内の「完全な正方形」であるサブセグメントがいくつあるかをカウントする必要があります。 

部分文字列の長さが偶数で、前半と後半が同一である場合、その部分文字列は正方形と呼ばれます。 したがって、正方形の部分文字列はまさに次の形式の文字列です。`xx`、 どこ`x`空ではない文字列です。 

クエリ間隔ごとに`[l, r]`、部分文字列を列挙するように求められるのではなく、ペアの数を数えるように求められます。`(L, R)`その内部では、このような正方形の部分文字列が形成されます。 

制約は、テスト ケースごとではなく、全体として大きくなります。 すべての文字列の合計長とクエリの合計数は、それぞれ 100 万に達する可能性があります。 これにより、テスト ケースごとまたはクエリごとに二次関数が即座に除外されます。 クエリ内のすべての部分文字列を暗黙的に反復するソリューションでも、単一の長さの文字列が存在するため、爆発する可能性があります。`10^6`すでに注文済みです`10^12`部分文字列。 

1 つ目の微妙なエッジ ケースは、正方形の部分文字列が重なり合い、多くの位置で開始される可能性があることです。 たとえば、`aaaaaa`、どこでも中心にある偶数長の部分文字列はすべて正方形であるため、単純にカウントすると、「貪欲にスキャン」しようとすると二重にカウントされたり、重複を誤って管理したりする危険があります。 

もう 1 つの問題は、同じ正方形の部分文字列が複数のクエリの一部として表示される可能性があることです。 範囲全体を個別にスキャンするクエリごとの再計算が主なトラップです。 

## アプローチ

 ブルートフォースソリューションは簡単に説明できます。 クエリごとに`[l, r]`、あらゆるスタートポジションを試します`L`範囲内で均等な長さに伸ばします`2k`、どうかを確認してください。`s[L..L+k-1] == s[L+k..L+2k-1]`。 それぞれの比較にかかる費用`O(k)`素朴に行われた場合、または`O(1)`ハッシュを使用しますが、ハッシュを使用しても、すべての可能な部分文字列を反復処理します。`O(n^2)`最悪の場合、クエリごとに。 まで`10^6`クエリ、これは制限をはるかに超えています。 

重要な構造上の観察は、すべての正方形の部分文字列が 2 つの文字間の中心によって決定されるということです。 1 から始まる文字にインデックスを付けると、長さの正方形の部分文字列になります。`2k`から始まる`L`立場の平等を意味します`(L + i)`そして`(L + k + i)`みんなのために`i`。 これは、問題は基本的に、次のシフトの下での等しい文字に関するものであることを意味します。`k`。 

これにより、問題は、クエリ間隔ごとにペアの数を数えるという問題に変換されます。`(i, j)`満足する`i < j`、`j - i`は偶数であり、`s[i] = s[j]`さらに、このペアは、中央で不一致が発生しないように、それらの間を中心とする正方形を形成します。 これでもまだグローバルに見えますが、それを再構成できます。正方形を直接構築する代わりに、すべての位置について、その位置から開始して正方形をどこまで拡張できるかを事前に計算します。 つまり、それぞれについて、`L`、 定義する`best[L]`最大として`R`そのような`s[L..R]`は正方形です。 次に、有効な正方形の部分文字列はすべて、その左の端点によって一意に表されます。 

ここで問題は、クエリごとに次のようになります。`[l, r]`、何個数えますか`L`で`[l, r]`満足する`best[L] >= r`。 ただし、正方形がクエリ内で終了する場合もあるため、これでは十分ではありません。 すべてを数える必要があります`[L, R]`完全にクエリ内にあります。 したがって、代わりに、有効な正方形の部分文字列をそれぞれイベントとして扱います。`(L, R)`そしてタスクを 2D 範囲カウントに減らします。 

したがって、すべての最大平方部分文字列が必要になります。 これらは、Z 関数スタイルのアイデアまたはハッシュを使用して見つけることができます。`i`そして`i+1`、一致する外側の文字の最長半径を計算できます。 これは回文を見つけることとまったく同じですが、点の周りに鏡映するのではなく、半分の間に適用されます。 ローリング ハッシュとバイナリ リフティング、または変換された文字列に対する Manacher のような適応を使用して計算できます。 

すべての中心の最大半径がわかったら、各中心は正方形の部分文字列のファミリーを生成します。 中心の位置`c`半径あり`k`すべての正方形に貢献します`[c-k+1 .. c+k]`しかし、より重要なのは、すべての小さな半径も有効な正方形に寄与することです。 各センターが貢献します`k`部分文字列を効率的に集約する必要があります。 

これは古典的なオフラインのカウント問題になります。すべての正方形の部分文字列を暗黙的にセグメントとして生成し、クエリ範囲内に完全に収まる部分文字列の数を答えます。 左のエンドポイントで並べ替え、右のエンドポイントに対してフェンウィック ツリーを使用します。 

ブルート フォースは構造を直接チェックするため機能しますが、部分文字列を繰り返しスキャンするため失敗します。 正方形が中心の周りの対称一致に対応するという観察により、すべての部分文字列を線形展開数に圧縮し、範囲カウントで処理できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(クエリごとの n²) | お(1) | 遅すぎる |
 | 最適 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての正方形の部分文字列を明示的なセグメントとしてカウントし、範囲包含クエリに応答することに問題を集約します。 

1. 文字間の境界を考慮して、正方形の部分文字列の中心をすべて見つけるように問題を変換します。 私たちは間の各ギャップを扱います`i`そして`i+1`潜在的なセンターとして。 正方形の部分文字列は均等な長さを必要とし、正確に中央で分割する必要があるため、これが必要です。 
2. 各中心について、最大半径を計算します。`k`長さの部分文字列`2k`その周りは広場です。 前処理後に一定時間内に任意の 2 つの半分を比較できるように、ローリング ハッシュを使用してこれを行います。 
3. 各中心の最大半径を取得したら、最大の正方形のみを保存しません。 代わりに、からのすべての半径`1`に`k`有効な正方形の部分文字列に対応します。 これにより、構造化された一連の間隔が生成されます。 
4. 各センターの貢献を一連のイベントに変換する`(L, R)`どこ`L = c-k+1`そして`R = c+k`。 これらのイベントをスイープすることで暗黙的に処理します。`L`。 
5. すべてのイベントを左のエンドポイントで並べ替えます。 クエリごとに`[l, r]`を満たしているイベントの数を数えたいとします。`L >= l`そして`R <= r`。 クエリを次の基準で並べ替えます`l`降順で並べてあるため、左に移動するにつれてイベントをアクティブ化できます。 
6. 右側のエンドポイント上にフェンウィック ツリーを維持します。 イベントをアクティブにするとき`(L, R)`、挿入します`R`。 お問い合わせの場合`[l, r]`、アクティブなイベントの数をクエリします。`R <= r`。 

ここでの直感的な文章は、一度修正すると、`L`、以降で始まるすべての四角形`L`は 2D 平面内の点のように動作し、その平面上で優勢カウントを実行します。 

### なぜ効果があるのか

 すべての正方形の部分文字列は、正確に 1 つの中心と 1 つの半径に対応し、私たちの構築ではそのようなペアをすべて重複なく列挙します。 スイープにより、左境界を持つクエリを処理するときに、`l`、すべての有効な開始点`L >= l`はすでに挿入されています。 フェンウィック ツリーは右側の境界制約を強制します。 両方の制約が直交方向に 1 回だけ適用されるため、有効な正方形の部分文字列はすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n, q = map(int, input().split())
        s = input().strip()

        # build all square substrings via centers
        # store events (L, R)
        events = []

        # expand around gaps (i, i+1)
        for c in range(n - 1):
            k = 0
            l = c
            r = c + 1
            while l >= 0 and r < n and s[l] == s[r]:
                events.append((l + 1, r + 1))
                l -= 1
                r += 1

        events.sort(reverse=True)

        queries = []
        for i in range(q):
            l, r = map(int, input().split())
            queries.append((l, r, i))
        queries.sort(reverse=True)

        bit = Fenwick(n)
        ans = [0] * q
        ei = 0

        for l, r, idx in queries:
            while ei < len(events) and events[ei][0] >= l:
                _, rr = events[ei]
                bit.add(rr, 1)
                ei += 1
            ans[idx] = bit.sum(r)

        print(f"Case #{tc}:")
        for x in ans:
            print(x)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、特定の右境界より前で終了するアクティブな正方形の部分文字列の数をカウントするためにのみ使用されます。 イベントとクエリを左端の降順で並べ替えると、左端がクエリ範囲内にある部分文字列のみが挿入されます。 

最もデリケートな部分はインデックス作成です。 0 ベースの内部インデックスと 1 ベースの Fenwick インデックス間の変換は一貫性を保つ必要があります。`L+1`そして`R+1`BIT 操作がクエリ境界と一致するように格納されます。 

## 実用的な例

 検討してください`s = "ababa"`。 

正方形の部分文字列を列挙します。`"bb"`存在しませんが、`"abaaba"`長すぎるでしょう。 この場合に限っては`"aa"`-type 構造体が存在する場合は表示されます。 

より具体的な文字列は次のとおりです。`s = "aaaa"`。 

| センター | 拡張 | 生成された正方形の部分文字列 |
 | --- | --- | --- |
 | 1-2の間 | (1,2)、(0,3 は無効) | 異なる中心を経由した (1,2)、(2,3)、(3,4) の「aa」 |
 | 2-3の間 | (2,3)、(1,4) | もっと正方形 |
 | 3-4の間 | (3,4) | 最小の正方形 |

 クエリ`[1,4]`すべて有効なものを数える`(L,R)`ペア。 

このトレースは、複数の中心が重複する候補を生成する可能性があることを示していますが、各部分文字列は中心拡張ステップごとに 1 回だけ挿入され、BIT 集約により正確なカウントが保証されます。 

2 番目の例`s = "ababab"`は、交互構造を示しています。長さ 2 を超える展開はほとんど成功しないため、隣接する等しいペアのみが存在します。 

これらの例では、アルゴリズムが位置のみではなく実際の文字の同等性に敏感であることが確認されています。

 ## 特殊なケース

 次のような単一文字の文字列`"a"`正方形の長さは偶数である必要があるため、有効な正方形部分文字列がありません。 文字間に有効な中心がないため、展開ループはトリガーされず、イベント リストは空のままで、すべてのクエリは正しくゼロを返します。 

次のような完全に均一な文字列`"aaaaaa"`最大限のオーバーラップを作成します。 すべてのセンターは複数の拡張を生成しますが、各拡張は依然としてその左右のエンドポイントによって一意に識別されます。 スイープ中、これらすべての間隔は左の降順で挿入され、各クエリは単純にしきい値以下のすべての有効な右エンドポイントを累積し、重複することなく密なオーバーラップを正確にカウントします。
