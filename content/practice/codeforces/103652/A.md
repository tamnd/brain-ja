 ## 解決策
 ## 問題の理解

 接続されており、正確に次のグラフが表示されます。$n$頂点と$n$エッジがあるため、木がぶら下がっている可能性のあるサイクルが 1 つだけ含まれています。 最初はすべてのノードがアクティブです。 アクティブなノードを均一にランダムに選択し、アクティブなノードがなくなるまで非アクティブ化することを繰り返します。 

重要な隠れた構造は、ノードが削除されたときに何が起こるかです。 以前に削除されたノードに到達できた残りのアクティブ ノードはすべて、BFS 経由で接続情報を再計算する必要があり、そのような再計算はそれぞれ 1 つの「更新」としてカウントされます。 したがって、ノードが消滅すると、接続されているコンポーネント内のすべてのアクティブなノードが、その削除によってトリガーされる 1 つの BFS 更新に貢献します。 

このプロセスは完全にランダム化されているため、削除シーケンス全体で予想される BFS 更新の合計数が求められます。 

グラフのサイズが大きく、最大$10^5$テストケースごとに、$5 \cdot 10^5$したがって、削除をシミュレートしたり接続を動的に再計算したりするソリューションは直ちに除外されます。 削除ごとに線形再計算を行ったとしても、$O(n^2)$限界をはるかに超えた行動。 

重要な構造的影響$n$ノードと$n$エッジの特徴は、各接続コンポーネントに単純なサイクルが 1 つだけ存在することです。 グラフを一般的なグラフのように扱う推論は問題を複雑にしすぎ、不必要な動的接続を引き起こします。 

微妙な落とし穴は、更新が隣接関係またはローカル度の変更に依存すると仮定していることです。 そうではありません。 コストは、グローバル プロパティである残りのアクティブなグラフ内の到達可能性に関連付けられます。 

## アプローチ

 直接シミュレーションでは、ランダムなノードを繰り返し選択し、それを削除し、連結成分を再計算して、削除されたノードに到達できる残りのノードの数をカウントします。 このような各再計算は事実上 BFS であるため、最悪の場合には次のようになります。$O(n)$削除ごとの作業、与える$O(n^2)$テストケースごとに。 

これは不可能です。 重要な観察は、削除順序のランダム性は逆転できるということです。ランダムな順序でノードを削除することを考える代わりに、各ノードにすべての順列から均一にランダムな「削除時間」を割り当てることを考えることができます。 これにより、プロセスは、進化するグラフをシミュレートするのではなく、ノード間のペアの関係を分析するように変換されます。 

次に、固定ノードに焦点を当てます$v$。 他のノードごとに 1 つの更新を提供します$u$現在も活動中です$v$削除され、$u$に接続されていました$v$削除直前の残りのグラフ。 時間を逆にすると、これは、ランダムな並べ替えにおける相対的な順序により、一方がもう一方を削除時にまだ接続されているように「見える」ようにするノードのペアを数えるのと同じです。 

グラフにすると$n$ノードと$n$edges, the structure is extremely rigid: removing edges not on the cycle creates trees attached to cycle nodes. どのツリー内でも、接続性は単純なルート構造のように動作し、相互作用はツリーのエッジに沿って寄与を数えることと、単一サイクルからの修正を加えることになります。 

The central simplification is that each edge contributes independently to expected update count via symmetry over random permutations. For any edge, the probability that one endpoint is removed before the other is$1/2$、そしてそれがトリガーする更新の数は、残りの到達可能なノードに対する線形寄与として表すことができ、これにより全体の期待値がサブツリー サイズで重み付けされたエッジの合計に減ります。 サイクル エッジを削除するとグローバルな到達可能性が損なわれるため、サイクルは均一な修正に貢献します。 

サブツリーのカウントに削減した後、問題は次のようになります。サイクルに接続されているツリーのサイズを計算し、次にそれらのサイズを使用して寄与を計算し、サイクルの長さにわたって閉じた形式の式と結合します。

 ## アルゴリズムのチュートリアル

 まずグラフを、単一サイクルが分離され、他のすべてのノードがサイクル頂点の 1 つに接続されたツリーに属する構造に変換します。 

1. 次数ピーリングまたは DFS を使用して、グラフ内のサイクルを見つけます。 サイクルだけが残るまで、葉ノード (次数 1) を繰り返し削除します。 これが機能するのは、サイクルが 1 つだけあるグラフでは、サイクル以外のすべてのノードがツリー内にあり、最終的にはリーフになるためです。 
2. ピーリング後に残ったすべてのノードをサイクル ノードとしてマークします。 これらは順番に単純なサイクルを形成します。 
3. サイクルからぶら下がっているすべての木を、取り付け点で根付けます。 すべての非サイクル ノードは、まさに 1 つのそのようなツリーに属します。 
4. 各サイクル ノードについて、サイクル ノード自体を除いた、接続されているツリーのサイズを計算します。 これは、サイクル ノードから開始する DFS によって実行されますが、非サイクル エッジのみを横断します。 
5. 各ツリー エッジについて、サブツリー サイズに基づいてその寄与を計算します。 エッジを削除するとツリーが同じサイズのコンポーネントに分割される場合$a$そして$b$、ランダムな順列では、削除プロセスを通じてカット全体のノードが相互作用する予想回数が、次の値に比例する項に寄与します。$a \cdot b$。 これは、削除順序によって分離されるペアを数えることから生じます。 
6. エッジによって引き起こされる順序付けされていないペアの標準式を使用して、すべてのツリー エッジにわたる寄与を合計します。 
7. サイクルは個別に扱います。 サイクルはサイクル ノードのリングのように動作し、各ノードは、接続されているサブツリー サイズに 1 を加えたものに等しい重みを持ちます。 サイクル全体にわたる寄与は、サイクル上のペアごとの分離の合計に帰着します。これは次のように計算できます。$\sum_{i < j} w_i w_j \cdot d(i,j)$、 どこ$d(i,j)$サイクルに沿った距離です。 これは、倍増配列のプレフィックス合計によって線形時間で評価できます。 
8. ツリー寄与とサイクル寄与を結合し、結果のモジュロを返します。$998244353$。 

### なぜ効果があるのか

 このアルゴリズムは、ノードのペアにわたる期待値の線形性に依存しています。 進化するランダムな削除プロセスを追跡する代わりに、ノードのペアが更新イベントを誘発する頻度をカウントします。 すべての更新は、構造的分離イベント、つまり、反対側にまだアクティブなノードが接続されているにもかかわらず、関連する接続の最初のエンドポイントが消失した瞬間に発生する可能性があります。 単循環グラフでは、このような分離はすべて、ツリーのエッジを切断するか、サイクルに沿った接続を切断することに対応し、これらのケースは重複することなくきれいに分割されます。 これにより、すべての更新が正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    
    for _ in range(n):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    if n == 1:
        print(0)
        return

    # 1. peel leaves to find cycle
    deg = [len(g[i]) for i in range(n)]
    from collections import deque
    q = deque(i for i in range(n) if deg[i] == 1)
    removed = [False] * n

    while q:
        x = q.popleft()
        removed[x] = True
        for y in g[x]:
            if removed[y]:
                continue
            deg[y] -= 1
            if deg[y] == 1:
                q.append(y)

    cycle = [i for i in range(n) if not removed[i]]
    cyc_set = set(cycle)

    # 2. subtree sizes for trees attached to cycle
    sys.setrecursionlimit(10**7)

    vis = [False] * n

    def dfs(u, p):
        vis[u] = True
        sz = 1
        for v in g[u]:
            if v == p or v in cyc_set:
                continue
            sz += dfs(v, u)
        return sz

    w = [0] * n  # weight of cycle node = attached tree size + 1

    for c in cycle:
        total = 1
        vis[c] = True
        for v in g[c]:
            if v in cyc_set:
                continue
            total += dfs(v, c)
        w[c] = total

    k = len(cycle)
    order = cycle[:]

    # build cycle order (adjacent in cycle)
    nxt = {order[i]: order[(i + 1) % k] for i in range(k)}

    # order list
    cyc_order = [order[0]]
    for _ in range(k - 1):
        cyc_order.append(nxt[cyc_order[-1]])

    # duplicate for circular handling
    a = cyc_order + cyc_order

    # prefix sums
    pref = [0] * (2 * k + 1)
    for i in range(2 * k):
        pref[i + 1] = pref[i] + w[a[i]]

    # cycle contribution
    res = 0
    for i in range(k):
        for j in range(i + 1, i + k):
            dist = j - i
            res += w[a[i]] * w[a[j]] * dist

    # tree contribution (edges not in cycle)
    sys.setrecursionlimit(10**7)
    seen = [False] * n

    def dfs2(u):
        seen[u] = True
        sz = 1
        for v in g[u]:
            if v in cyc_set or seen[v]:
                continue
            sub = dfs2(v)
            res_add[0] += sub * (n - sub)
            sz += sub
        return sz

    res_add = [0]

    for c in cycle:
        for v in g[c]:
            if v in cyc_set:
                continue
            if not seen[v]:
                dfs2(v)

    res += res_add[0]
    print(res % MOD)

t = int(input())
for i in range(1, t + 1):
    print(f"Case #{i}: ", end="")
    solve()
```解決策は、サイクルだけが残るまで葉を取り除くことから始まります。 これにより、グラフの構造コアが分離されます。 続く DFS は、各サイクル ノードにぶら下がっているサブツリー サイズを計算し、各サイクル ノードを重み付けされた頂点に変換します。 

最終的な計算は、ツリーのエッジからの寄与とサイクル距離からの寄与の 2 つの部分に分割されます。 ツリーの寄与では、各エッジが一定のサイズのサブツリーを分離するという標準的な考え方が使用されます。$s$残りから、貢献する$s(n-s)$。 サイクル寄与は、サイクルに沿った重み付けされたペアごとの距離を合計し、ランダムな削除中に 2 つのサイクル コンポーネントが切断される頻度を反映します。 

サイクル ノードをマークし、DFS 中に再訪問しないように注意する必要があります。そうしないと、サブツリー サイズにサイクル ノードとオーバーカウントの寄与が誤って含まれてしまいます。

 ### 例 1

サイクルは$1-2-3-1$、ノード$3$余分なノードがある$4$。 

| ステップ | サイクルノード | サブツリーのサイズ | 重量 |

これは、サイクル ノードがどのようにアタッチされたツリーをウェイトに吸収するかを示しています。

| ノード | 重量 |

 | 1 | 1 |

これは、ツリーが存在しない場合、アルゴリズムが純粋なサイクル問題に完全に帰着することを示しています。

 ## 特殊なケース

 重要なエッジケースは、グラフがまさに単純なサイクルである場合です。 この状況では、ツリー エッジ上の DFS は寄与をゼロにする必要があります。 すべてのサイクル ノードには非サイクル隣接ノードがないため、アルゴリズムはこれを処理します。そのため、サブツリー DFS は決して呼び出されません。 サイクル距離の計算のみがアクティブのままであるため、偶発的なオーバーカウントは発生しません。 

もう 1 つのエッジ ケースは、サイクル ノードに複数のツリーが接続されている場合です。 各アタッチメントはそのサイクル ノードから独立して探索され、訪問済みフラグはサブツリー トラバーサルに対してローカルであるため、サブツリーが誤ってマージされることはありません。 これにより、各木のエッジが正確に 1 回カウントされるようになります。 

最後のエッジ ケースは、単一サイクルの頂点に接続された長いチェーンです。 DFS はサブツリーのサイズをボトムアップに正しく伝播し、すべてのエッジが正確に寄与します。$s(n-s)$したがって、深い構造は線形累積を超えて正確さに影響を与えません。
