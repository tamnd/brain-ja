 ## 解決策
 ## 問題の理解

 私たちには円が与えられています$2n$～からラベル付けされた点$1$に$2n$。 サンタさんが描く$n$異なる点のペアを接続するコード。 コードが交差する場合があります。 コードの接頭辞ごとに$1$を通して$\ell$では、コードが**緊密に**されているかどうかが尋ねられます。 コードのセット内の連続するコードのペアがすべて交差する場合、そのセットは **チェーン** と呼ばれます。 あらゆる単一のコードがサイズの連鎖を形成します$1$。 **すべてのコードがそのプレフィックスから形成できる偶数のチェーンに出現する**場合、そのプレフィックスは緊密に結合されています。 

入力は複数のテスト ケースを提供します。 各テスト ケースが提供するのは、$n$そして$n$コードのエンドポイント。 出力は長さのバイナリ文字列です。$n$各プレフィックスの緊密なステータスを示します。 

とすれば$n$到達できる$5 \cdot 10^5$そしてあるかもしれない$10^4$テスト ケースでは、チェーンを明示的に列挙するソリューションは非常に遅すぎます。 テスト ケースごとの 2 次アルゴリズムであっても危険です。 これは、$O(n \log n)$または$O(n)$テストケースごとのソリューション。 

単純な実装では、交差するすべてのコード チェーンを直接カウントしようとする可能性があります。 最初の例を考えてみましょう。```
3
1 6
2 3
4 5
```ここでは交差するコードがないため、各コードは単一コード チェーンのみに属します。 それぞれが **1 つのチェーン**で表示されますが、これは奇妙であるため、すべてのプレフィックスが緊密に結合しているわけではありません。 注意深いカウントを行わずにチェーンが確実にペアになると仮定する単純なアプローチは、ここでは失敗します。 

エッジ ケースには、前のコードと交差しないコード、または交差が 1 つだけ作成されるネストされたコードが含まれます。 パリティの数え間違いは最も微妙な点です。 

## アプローチ

 ブルートフォースアプローチは、最初のすべてのサブセットを生成することです。$\ell$コードを調べ、各サブセットがチェーンであるかどうかを確認し、各コードの出現数をカウントします。 これは問題定義に直接従うため、正解です。 しかし、サブセットの数は$2^\ell$これは天文学的な数字になります。$\ell=20$。 と$\ell$まで$5 \cdot 10^5$、これは不可能です。 

重要な観察は、*各コードの出現のパリティのみが必要である**ということです。 包含/排他と円の交差の特性により、問題を **区間にわたるビットごとの XOR** に減らすことができます。 各コードは音程として表すことができます$(a_i,b_i)$。 2 つのコードが交差するのは、コードの一方の終点がもう一方のコードの音程の内側にあり、もう一方の終点が外側にある場合に限られます。 **フェンウィック ツリー (BIT) またはセグメント ツリー** を使用すると、アクティブなインターバルにわたってコードの XOR を効率的に維持できます。 

問題の構造により、各コードを点のペアとして表現し、どのコードが交差するかを段階的に維持することができます。 次に、各コードのチェーン数のパリティは、**各コードについて、奇数の以前のコードと特定の方法で交差する場合に限り、そのコードが参加するチェーンの数が奇数である**という特性を使用して計算できます。 慎重に順序付けを行うことで、それぞれの状態を段階的に更新できます。$\ell$、降伏$O(n \log n)$テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そしてコードのリスト。 コードのエンドポイントを次のように正規化します。$a_i < b_i$。 各コードを次のように表します$(a_i, b_i)$。 
2. コードを最初のエンドポイントで並べ替えます$a_i$。 これにより、円周上でコードを順番に処理できるようになります。 
3. フェンウィック ツリー (バイナリ インデックス ツリー) を維持します。$2n$交点に関してどのコードが現在「アクティブ」であるかを追跡する位置。 
4. コードを繰り返します。 コード用$i$:

 - ツリーをクエリして、区間内に 2 番目のエンドポイントを持つ以前に挿入されたコードの数を確認します。$(a_i, b_i)$。 このカウントのパリティによって、コードが$i$奇数または偶数のチェーンに寄与します。 
- コードを追加してツリーを更新します$i$位置にある$b_i$。 
5. 各コードを処理した後、その時点までのすべてのコードが偶数パリティであるかどうかを確認します。 「はい」の場合、このプレフィックスを緊密なものとしてマークします (`1`)、それ以外の場合はマークを付けます`0`。 
6. すべてのコードが終了したら、緊密な状態を表すバイナリ文字列を出力します。 

**機能する理由:** フェンウィック ツリーは交差点を効率的に追跡します。 現在のコードのインターバル内に 2 番目のエンドポイントがあるコードの数を数えるということは、このコードがモジュロ 2 で現れるチェーンの数を数えるのと同じです。パリティのみを維持することで、指数関数的な列挙を回避します。 不変条件は、各ステップでツリーに正しいアクティブ コード エンドポイントが含まれており、クエリによって厳密なチェックに必要なパリティが得られることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    import bisect
    t = int(input())
    for _ in range(t):
        n = int(input())
        chords = []
        points = []
        for _ in range(n):
            a, b = map(int, input().split())
            if a > b:
                a, b = b, a
            chords.append((a, b))
            points.append(a)
            points.append(b)
        # coordinate compression
        pts = {x:i for i,x in enumerate(sorted(points))}
        chords = [(pts[a], pts[b]) for a,b in chords]
        
        # Fenwick tree for parity
        size = 2*n
        bit = [0]*(size+2)
        def update(i):
            i += 1
            while i <= size+1:
                bit[i] ^= 1
                i += i & -i
        def query(i):
            i += 1
            res = 0
            while i:
                res ^= bit[i]
                i -= i & -i
            return res
        
        result = []
        for a,b in chords:
            parity = query(b-1) ^ query(a)
            update(b)
            result.append('1' if parity == 0 else '0')
        print(''.join(result))

if __name__ == "__main__":
    solve()
```**説明:** コードは、BIT で使用するために、最初にインデックスに圧縮されます。 コードごとに、`query(b-1) ^ query(a)`インターバル内のアクティブなコードの XOR を計算します`(a, b)`。 更新中`b`コードを今後のコードに対してアクティブとしてマークします。 パリティ 0 はこのコードの緊密な結合を意味し、それ以外の場合はそうではありません。
