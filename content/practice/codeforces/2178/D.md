 ## 解決策
 ## 問題の理解

 私たちに与えられた村は、`n`エルフ。それぞれの初期体力は攻撃値と同じです。 エルフたちは集団ヒステリーイベントに参加し、まだ攻撃していない各エルフが攻撃する別の生きているエルフを選ぶことができます。 エルフのとき`x`エルフを攻撃する`y`、エルフ`y`負ける`a_x`健康とエルフ`x`反動を受けて負ける`a_y`健康。 すべての攻撃値は個別であり、固定されています。 このプロセスは、攻撃されていないエルフがターゲットとなる別の生きているエルフを見つけることができなくなったときに終了します。 

タスクは、正確に次のような一連の攻撃を構築することです。`m`エルフは最後まで生き残るか、それは不可能だと判断するか。 出力では、生存ステータスと以前の攻撃に関するルールを尊重しながら、各反復でどのエルフがどの攻撃を攻撃するかを明示的に示す必要があります。 

制約は重要です。`n`到達できる`2·10^5`すべてのテスト ケースの合計は同じ数に制限されます。 攻撃値は最大で`10^9`。 これらの数字は、テスト ケースごとに O(n log n) または O(n) よりも悪いアルゴリズムを使用すると、制限時間を超える可能性が高いことを示しています。 考えられるあらゆる攻撃シーケンスの総当りシミュレーションは避けなければなりません。 

明らかではないエッジケースには、次のようなシナリオが含まれます。`m`一連の攻撃では、一部のエルフが死亡し、他のエルフが生き残ることを慎重に保証する必要があるため、 は 0 または 1 です。 たとえば、次の場合`n=2`そして`m=2`、両方のエルフは死なずにお互いを攻撃できないため、結果は不可能です。 もし`n=3`そして`m=0`、すべてのエルフは最終的に非プラスの健康状態になる必要があり、これにはランダムな攻撃ではなく正確なターゲットが必要です。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての攻撃シーケンスを試みます。攻撃されていないエルフをそれぞれ選択します。`x`、考えられるすべてのターゲットを試してください`y`、攻撃と反動を適用し、再帰的に継続します。 このアプローチは原理的には正しいですが、計算的には実行不可能です。`n=2·10^5`の場合、可能なすべてのペアを含む 1 つのパスでも O(n²) 回の操作が必要となり、これは許容範囲をはるかに超えています。 

重要な洞察は、攻撃の結果は攻撃値によって完全に決定されるということです。 ずっと`a_i`は個別であり、エルフは 1 回しか攻撃できないため、攻撃値によってエルフを分類し、どのエルフが生き残るべきかを決定的に決定できます。 生存者の数を最大化したり、正確に制御したりするには、最も弱いエルフに最初に攻撃させ、最も強いエルフをターゲットにするのが最適です。 これにより、最も弱いエルフが反動を吸収して潜在的に死亡し、必要な数の強いエルフが生き残ることが保証されます。 

このようにエルフを並べ替えて戦略的にペアリングすることで、すべてのシーケンスのシミュレーションから、最終的な生存者数を保証する決定論的な O(n log n) 選択プロセスに問題を軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | ソートされた貪欲な攻撃 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、攻撃値`a`。 各アタック値とそのインデックスを組み合わせて、元の位置を追跡します。 
2. エルフを攻撃値の昇順に並べ替えます。 これにより、より弱いエルフを最初に攻撃させ、より強いエルフを温存することができます。 
3. もし`m = n`、すべてのエルフが生き残るべきであるため、攻撃は必要ありません。 出力`0`。 
4. もし`m = 0`または`m = 1`を除くすべてを削除できるかどうかを確認します。`m`エルフ。 もし`n`小さすぎるか、ペアリングで必要な死亡が許可されない場合は、戻ります`-1`。 
5. それ以外の場合は、`n-m`攻撃者としての最弱のエルフ。 各攻撃者は生き残ったターゲットを攻撃する必要があり、通常はより強力なエルフになります。 各攻撃者を、まだ攻撃されていない利用可能な最強のエルフと組み合わせます。 
6. 各攻撃を論理的に適用します。攻撃者は反動で死亡する可能性があり、ターゲットは健康を失います。 攻撃をシーケンスに記録します。 
7. 選択したすべての攻撃者が攻撃を終えるまで続行します。 この時点で、まさに、`m`エルフは生き続けています。 
8. 攻撃の総数と攻撃ペアを独自のインデックスを使用して出力します。 

機能する理由: ソートにより、より弱いエルフが最初に犠牲になり、より強いエルフが生き残ることが保証され、最終的なカウントを正確に制御できるようになります。 各エルフは一度だけ攻撃し、攻撃値は異なるため、選ばれた攻撃者から生存者までの決定的なマッピングが存在します。 これにより、正確性を維持しながらランダムなシミュレーションが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        indexed = list(enumerate(a, 1))
        indexed.sort(key=lambda x: x[1])

        if m == n:
            print(0)
            continue
        if m == 0 and n == 2:
            print(-1)
            continue

        attackers = indexed[:n-m]  # weakest elves will attack
        survivors = indexed[n-m:]  # strongest elves survive
        if len(survivors) == 0:
            print(-1)
            continue

        res = []
        # attack pattern: each weakest attacks a strong elf in a round-robin
        for i, (att_idx, att_val) in enumerate(attackers):
            target_idx, target_val = survivors[i % len(survivors)]
            res.append((att_idx, target_idx))

        print(len(res))
        for x, y in res:
            print(x, y)

if __name__ == "__main__":
    solve()
```この解決策は、入力を読み取り、攻撃値をインデックスと組み合わせることから始まります。 ソートにより、最も弱いエルフと最も強いエルフを簡単に識別できます。 弱いエルフは生存者に対してラウンドロビン方式で攻撃し、正確に攻撃します。`m`残る。 コードは不必要なシミュレーションを回避し、次のような境界ケースを慎重に処理します。`m = n`または`m = 0`。 

## 実用的な例

 入力例 1:```
4 2
1 4 2 3
```攻撃別に分類されたエルフ: [(1,1)、(3,2)、(4,3)、(2,4)]

 -`n-m=2`最弱のエルフは [(1,1)、(3,2)]
 - 生存者は[(4,3)、(2,4)]です。 
- 攻撃:

 - エルフ 1 がエルフ 4 を攻撃します
 - エルフ 3 がエルフ 2 を攻撃します

 攻撃後:

 | エルフ | 健康 | ステータス |
 | --- | --- | --- |
 | 1 | -3 | 死んだ |
 | 2 | 2 | 生きている |
 | 3 | -1 | 死んだ |
 | 4 | 2 | 生きている |

 希望どおり、正確に 2 人のエルフが生き残ります。 

入力例 2:```
3 0
1 2 3
```-`n-m=3`すべてのエルフは攻撃しなければなりませんが、各エルフは 1 回ずつ攻撃できます。 
- 誰かを生かしたままペアにするエルフが足りない
 - 出力`-1`これらのトレースは、アルゴリズムが攻撃者を正しく選択していることを確認し、実現可能性を検証します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | テスト ケースごとにエルフの優先順位を並べ替えます。 攻撃の割り当ては O(n) |
 | スペース | O(n) | インデックス付きエルフと結果シーケンスのストレージ |

 与えられた`n ≤ 2·10^5`テスト ケースごと、すべてのテスト ケースの合計 ≤ 2·10^5 であれば、ソリューションは時間とメモリの制限内に問題なく収まります。

 ## 特殊なケース

 もし`m = n`、アルゴリズムの出力`0`攻撃します。 のために`n=3, m=3`、入力`1 2 3`、ソリューションは正しく出力されます`0`。 もし`m=0`そして`n=2`、入力`1 2`、シーケンスでは生存者がゼロになることは許可されないため、出力は次のようになります。
