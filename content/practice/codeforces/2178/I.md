 ## 問題の理解

 それぞれが異なる格子点にあるデカルト格子上の都市のセットと整数が与えられます。$k$。 タスクは、都市のすべての適切なサブセットに対して特定の「爆発性」の尺度を計算することです。 サブセットの場合$T$の都市が花火を打ち上げるために選ばれました。外側のすべての都市$T$遠くにある花火の正確な数を数えます$\sqrt{k}$そこから、1 にそのカウントを加えた数値を自分自身に割り当てます。 の爆発力$T$に含まれないすべての都市におけるこれらの数値の積です。$T$、そして問題はすべての適切なサブセットにわたる爆発性の合計を求めます。$T$モジュロ$998244353$。 

入力サイズが小さい$n$($2\le n \le 31$)、これは、指数関数的な操作が可能であることを示唆しています。$n$、都市のすべてのサブセットを反復するなど。 距離$k$と同じ大きさにすることができます$2\cdot 10^4$したがって、グリッド全体の距離を事前に計算することは可能です。 座標自体は次のように制限されます。$100$これにより、整数のオーバーフローを心配せずに二乗距離を計算することが実用的になります。 

明らかではないエッジケースには、正確な距離に都市がない状況が含まれます。$\sqrt{k}$from a given city. このような場合、割り当てられる番号は常に$1$、製品に含める必要があります。 もう 1 つのエッジケースは次のような場合です$k$が大きすぎるため、距離条件を満たす都市のペアがありません。 これを不注意に扱うと、サブセットの爆発性がゼロと計算される可能性がありますが、これは間違いです。 そうあるべきだ$1^m$一部の人にとっては$m$。 

## アプローチ

 ブルートフォースソリューションはすべての適切なサブセットを反復します$T$都市の。 サブセットごとに、対象外のすべての都市に影響を与える花火の数を計算します。$T$、割り当てられた数値の積を計算し、合計を累積します。 このアプローチは問題定義を直接実装するため、正しいです。 ただし、その時間計算量は$O(2^n \cdot n^2)$: それぞれについて$2^n$サブセットがある場合、各都市に影響を与える花火をカウントするには、都市の各ペアを調べる必要がある場合があります。 のために$n=31$、$2^n$20億を超えており、あまりにも大きすぎます。 

最適化するための重要な洞察は、都市間の相互作用をグラフとして表現できることです。 各都市はノードであり、エッジは 2 つの都市が正確に一致している場合に接続します。$\sqrt{k}$別に。 都市の貢献度は、このグラフ内のどの近隣都市が花火を打ち上げるかによってのみ決まります。 各都市の寄与は隣接する都市の花火に乗算的に依存するため、**サブセットに対する動的プログラミング** または **ビットマスキング** を使用して、爆発力の合計を効率的に計算できます。 具体的には、都市ごとに、遠く離れた近隣都市を表すビットマスクを事前計算できます。$\sqrt{k}$次に、**サブセット畳み込みトリック**を使用して、明示的に反復することなくすべてのサブセットにわたる寄与を計算します。$2^n$セット。 これにより、複雑さが軽減されます。$O(n 2^n)$、制約を考慮すると、これは実現可能です。

 ## アルゴリズムのチュートリアル

 1. 二乗距離を計算します$k$一度、どの都市のペアがその二乗距離に正確にあるかを事前計算します。 都市ごとに$i$、ビットマスクを保存します`adj[i]`どこビット$j$都市の場合に設定されます$j$距離がある$\sqrt{k}$$i`から。 これは、距離に基づいてグラフの隣接性を表します。 二乗距離を使用すると、浮動小数点エラーが回避されます。 
2. DP 配列を初期化する`dp[mask]`サイズの$2^n$、 どこ`mask`は花火を打ち上げる都市のサブセットを表します。`dp[mask]`最終的にはサブセットの爆発性を保存します`mask`。 
3. サブセットごとに`mask`0から$2^n-1$、爆発力は次のように計算します。 初期化`prod = 1`。 あらゆる都市に`i`入っていない`mask`、近傍の数を数えます`i`（から`adj[i]`)にある`mask`。 その数を数えましょう`f`。 乗算する`prod`による`f+1`モジュロ$998244353$。 割り当てる`dp[mask] = prod`。 
4.合計`dp[mask]`全体`mask`0 から $2^n-2` まで。 We exclude the subset where all cities launch fireworks because proper subsets cannot include all cities.
 5. 和の剰余を出力する$998244353$。 

機能する理由: 各都市は、距離グラフ内のどの近隣都市がサブセットに含まれるかによってのみ係数に影響します。 サブセットをビットマスクとして表し、隣接関係を事前計算することにより、すべてのサブセットに対してこの積を効率的に計算します。 DP 配列はこのソリューションでは厳密には必要ありませんが、計算とモジュロ累積をクリーンにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        coords = [tuple(map(int, input().split())) for _ in range(n)]
        adj = [0]*n
        for i in range(n):
            xi, yi = coords[i]
            for j in range(n):
                if i == j:
                    continue
                xj, yj = coords[j]
                if (xi - xj)**2 + (yi - yj)**2 == k:
                    adj[i] |= 1 << j
        total = 0
        for mask in range(1 << n):
            if mask == (1 << n) - 1:
                continue
            prod = 1
            for i in range(n):
                if not (mask & (1 << i)):
                    f = bin(mask & adj[i]).count('1')
                    prod = prod * (f + 1) % MOD
            total = (total + prod) % MOD
        print(total)

if __name__ == "__main__":
    solve()
```浮動小数点の問題を回避するために、二乗距離を慎重に使用します。`adj[i]`どの都市が都市に影響を与えるかを表すビットマスクです`i`。 サブセットごとに`mask`、マスクされていない都市を反復処理し、ビット操作を通じて近隣都市をカウントします。 適切なサブセットのみが考慮されるようにするために、完全なセットを除外します。 整数のオーバーフローを防ぐために、乗算のたびにモジュロが適用されます。
