 ## 解決策
 ## 問題の理解

 まずは地下鉄の駅のツリーから始めます。 すべてのステーションはノードであり、すべてのトンネルはエッジであるため、2 つのステーション間には単純なパスが 1 つだけ存在します。 私たちが気にする量は、すべての順序付けされていないステーションのペアにわたる合計距離です。ここで、距離は、それらの間の一意のパス上のエッジの数を意味します。 

その後、都市は非常に特殊な方法で変更されます。 各駅ごとに$w$、隣人がいる場合$u$そして$v$、その後、新しい直接トンネルが間に追加されます。$u$そして$v$。 言い換えれば、すべてのノードは隣接するノードにクリークを誘発します。 これらのエッジは、反復的にではなく、元のツリー構造に基づいて同時に追加されます。 

これらの余分なエッジをすべて追加すると、グラフはツリーではなくなります。 タスクは、この新しいグラフ内のノードのすべてのペアにわたる最短パス距離の合計を計算することです。 

制約$n \le 2 \cdot 10^5$すべてのペア間の最短パスを再計算したり、ノードごとに BFS を実行したりするアプローチは直ちに除外されます。 二次方程式または$O(n^2 \log n)$アプローチがすでに遅すぎます。 通常、線形または線形に近いものが必要です。$O(n)$または$O(n \log n)$、追加されたエッジの強力な構造特性を利用する必要があります。 

微妙な問題は、距離は減少することはあっても、明らかに均一な方法では減少しないことです。 2 つのノードは、親を共有している限り、元のツリー内で遠く離れていても直接接続される可能性があります。 これにより多くのショートカットが作成され、「木の距離からローカルなものを差し引く」という単純な推論は失敗します。 

いくつかの特殊なケースは、素朴な考え方の危険性を浮き彫りにしています。 スターでは、変換後に葉のすべてのペアが直接接続され、ほぼすべての距離が 1 に折りたたまれます。パスでは、距離がちょうど 2 にあるノードのみが接続され、まだ疎であるがツリーではないグラフが生成されます。 単純な「LCA の深さごとにツリーの距離から 2 を引く」スタイルのアイデアは、両方の構造で破綻します。これは、ショートカット条件が祖先の距離だけではなく兄弟関係に依存するためです。 

## アプローチ

 ブルート フォース アプローチでは、すべてのノードの隣接ペア間にエッジを追加することで新しいグラフを明示的に構築し、すべてのノードから BFS を実行してすべてのペアの最短パスを計算します。 星では、これはすでに作成されています$\Theta(n^2)$エッジ、およびノー​​ドごとの BFS により、$\Theta(n^3)$最悪の場合。 グラフを保存することさえ不可能になります。 

重要な観察は、すべての新しいエッジが、元のツリーで共通の隣接ノードを共有する 2 つのノードの間にあることです。 したがって、ツリー内の長さ 2 のショートカット パスはすべて直接エッジになります。 これは、新しいグラフでは、2 つのノード間の距離が 1 (ツリー内で距離 2 以内にある場合)、または離れている場合は少なくとも 2 であることを意味します。 

さらに重要なのは、この構造により、元のツリーの観点から最短パスを再解釈できるようになります。ノードのすべてのペアは、ツリー状のパスを介して接続されたままになるか、長さ 2 のステップが利用可能な場合に正確に短縮されます。 問題は、距離 1、距離 2 などを持つペアの数を数えることになりますが、距離をシミュレートする代わりに、各ノードの周囲でローカルに寄与を計算できます。 

重要な再フレームはノードを修正することです$w$そしてその隣人に配慮してください。 新しいグラフでは、次のすべての近傍が$w$クリークを形成するので、それらの間のどのペアも距離 1 になります。元のツリーでは、これらのペアは次のように距離 2 にありました。$w$そして今度はそれらが 1 に折りたたまれ、各ノードの隣接するノードのペアごとに合計距離がちょうど 1 だけ減少します。 

そこから、問題を、新しいエッジによって接続されるノードのペア、または最短パスが正確に 1 だけ短縮されるノードのペアの数を計算し、これを元のツリーの寄与の慎重な分解と組み合わせます。 最終的な計算は、サブツリーのサイズと次数ベースの寄与をカウントする DFS を使用して実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ビルド + BFS すべてのペア) |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | 隣接クリーク + 寄与分解をカウントする最適な DFS |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意のノード (たとえば 1) でツリーをルート化し、DFS を使用してサブツリーのサイズを計算します。 これが必要なのは、多くの寄与がエッジがツリーをコンポーネントに分割する方法に依存するためです。 
2. 標準的なエッジ寄与法を使用して、ツリー内のすべてのペア間の距離の元の合計を計算します。エッジを削除するとツリーがサイズのコンポーネントに分割される場合は、エッジごとに計算します。$a$そして$b$、貢献します$a \cdot b$総距離まで。 これにより、ベースラインの合計が得られます。 
3. 距離が減少する唯一の方法は、同じノードの隣接ノードを接続する新しいエッジを経由することであることに注意してください。 すべてのノードについて$w$、異なる近隣のすべてのペア$u, v$直接的な優位性を獲得します。 
4. 固定ノードの場合$w$、程度があるとします。$d$。 そして、その隣人の中には、$\binom{d}{2}$新しいエッジが追加され、それぞれのペア間の距離が 2 から 1 に減少し、ペアごとに合計が 1 ずつ減少します。 
5. したがって、次のように減算します。$\sum_w \binom{\deg(w)}{2}$元の総距離から。 
6. 最終的な答えは、元の木の距離の合計からこの合計の減少を引いたものになります。 

### なぜ効果があるのか

 元のツリーでは、ノードの任意の 2 つの隣接ノード$w$距離は正確に 2 経由です$w$。 新しいエッジを追加すると、それらは直接接続されるため、それらの距離は 1 になり、それ以上減らすことはできません。 長さ 1 のショートカットは元のツリー内のノードの共有に正確に対応するため、他のペアは単一の共有ネイバーによって既にキャプチャされているパスよりも短いパスを取得することはありません。 このような改善はそれぞれ独立しており、中心ノードごとに 1 回だけカウントされるため、$\binom{\deg(w)}{2}$ノードごとに、重複のないすべての距離の減少が正確に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    deg = [0] * n

    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
        deg[u] += 1
        deg[v] += 1

    # compute subtree sizes and original distance sum
    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = 0

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            if parent[v] == -1:
                parent[v] = u
                stack.append(v)

    sz = [1] * n
    for u in reversed(order):
        for v in g[u]:
            if v == parent[u]:
                continue
            sz[u] += sz[v]

    # original sum of distances
    total = 0
    for u in range(n):
        for v in g[u]:
            if parent[v] == u:
                total += sz[v] * (n - sz[v])

    total //= 2

    # subtract improvements from new edges between neighbors
    reduction = 0
    for d in deg:
        reduction += d * (d - 1) // 2

    print(total - reduction)

if __name__ == "__main__":
    solve()
```このコードは、再帰制限を回避するために、最初に反復 DFS を使用してサブツリー サイズを計算します。 次に、エッジの寄与を使用して元のツリー内の距離の合計を計算します。各エッジは、ルート化されたツリーの子側を介して 1 回だけカウントされます。 

その後、各ノードに存在する隣接ペアの数が計算されます。 このような各ペアは新しく追加されたエッジに対応し、それぞれの合計距離が正確に 1 単位だけ減少します。 

隣接トラバーサルでは各無向エッジが方向ごとに 1 回カウントされるため、ツリー寄与の合計を 2 で割るには注意が必要です。

このトレースは、ノードの兄弟関係のみが削減に影響を与えることを確認します。

 ## 特殊なケース

 1 つのノードが他のすべてのノードに接続する星形の入力では、次数ベースの削減が支配的になります。 セントラルノードが貢献する$\binom{n-1}{2}$減少し、ほぼすべての距離が崩壊します。 サブツリーの計算は次数のみに依存するリダクションとは無関係であるため、このアルゴリズムはこれをきれいに処理します。 

パスでは、すべての内部ノードに次数 2 があり、それぞれちょうど 1 つの削減に寄与します。 これは、距離 2 のペアのみが接続されるという事実と一致します。 DFS ベースの元の距離計算は、追加されたエッジではなくサブツリー サイズのみに依存するため、正しいままです。
