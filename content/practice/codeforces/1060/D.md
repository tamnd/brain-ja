 ## 解決策
 ## 問題の理解

 私たちには数人のゲストが与えられますが、各ゲストは円形の配置でどのように座るかについて個人的な要件を持っています。 ゲストが円の中に配置されている場合、円の周囲を見ると 2 つの方向があり、ゲストには両側に十分な空の椅子が必要です。$l_i$一方向に空の椅子を並べ、少なくとも$r_i$反対側の空の椅子。 

複数の独立したサークルを作成することができます。 各サークルは単に椅子を周期的に並べたものであり、いくつかの椅子はゲストによって占められており、残りは空になっています。 タスクは、すべてのゲストをいくつかの円のセットに配置し、使用する椅子の総数を最小限に抑えながら、すべてのゲストの左右の要件を満たすように椅子の総数を選択することです。 

主な問題は、空の椅子が隣のゲストの間で輪になって共有されることです。 2 人のゲストが隣り合って座る場合、ゲストの間の空のセグメントは、一方の「右側」要件ともう一方の「左側」要件に同時に寄与します。 この共有により、問題が非加算的なものになり、個々の配置ではなく隣接性について推論する必要が生じます。 

制約により、最大で$10^5$ゲストなので、これより悪い解決策はありません$O(n \log n)$遅すぎるでしょう。 すべての可能なペアリングまたは円形配置にわたる二次構造は直ちに除外されます。$10^5$二乗は制限時間をはるかに超えています。 

すべてのゲストが同一である場合、微妙なエッジケースが発生します。たとえば、$l_i = r_i = 1$。 素朴な解釈では、ゲストをペアにするか、複数のサークルに分散させることで、空の椅子を減らすことができるかもしれません。 ただし、両側の制約を無視してグループ化しようとする間違ったグリーディーは、単一の隣接制約に違反すると円全体が無効になるため、必要な間隔を簡単に過小評価する可能性があります。 

1 人のゲストが非常に大きなデータを持っている場合、別の厄介な状況が発生します。$l_i$そして小さい$r_i$、一方、別のものはその逆です。 ここでは、左右の要件を単純に対称的に扱うことは失敗します。共有の空の椅子からの節約が実際にどのように波及するかは方向性によって決まるためです。 

## アプローチ

 ブルートフォース ビューでは、ゲストの考えられるすべての循環順序を構築し、それぞれに必要な椅子の数を計算しようとします。 固定順序の場合、コストは、隣接する各ペアの間に必要な空の椅子の数によって決まります。 残念ながら、順列の数は$n!$、単一の配置をチェックするだけでも直線的に時間がかかるため、このアプローチは小規模な場合でも完全に実行不可能になります。$n$。 

循環順序を修正すると、問題の構造がより明確になります。 ゲストが2人だとします$i$そして$j$隣接している。 それらの間にある空の椅子の数を次のようにします。$x$。 この場合、両方の制約が同時に保持される必要があります。$x \ge r_i$（のために$i$の右側）と$x \ge l_j$（のために$j$の左側）。 したがって、必要なギャップは正確に$\max(r_i, l_j)$。 

これにより、問題は、エッジコストの合計を最小化する循環順序付けの構築に変換されます。$$\text{cost}(i \to j) = \max(r_i, l_j),$$さらにゲスト1人につき椅子1脚。 

したがって、すべての頂点に 1 つの出力エッジと 1 つの入力エッジがあり、エッジ コストがこの非対称最大構造を持つ、最小コストの有向サイクル カバーを構築しようとしています。 ここで貪欲な構造が悪用可能になります。コストは、左ノードからの「右圧力」と右ノードからの「左圧力」にのみ依存します。 

重要な観察は、サイクル構築の初期にノードを配置する方法を決定する際に、各ノードの片側のみが重要であるということです。 ゲストを降順に処理すると、$r_i$, 次に、大きなゲストを配置するとき$r_i$、それに接続する将来のゲストには、ほぼ確実に、その側でより小さい、または同等の制約が課せられることになります。 これにより、どの用語が優先されるかを制御できるようになります。$\max$。 

その後、常に現在の最高値をペアにすることで、貪欲に順列を構築できます。$r$最小限の要素を持つまだ使用されていない要素を持つ要素$l$、その選択により、$\max(r_i, l_j)$各ステップで。

 ## アルゴリズムのチュートリアル

 1. すべてのゲストを降順に並べ替えます$r_i$。 これにより、最も強力な「適切な要件」を最初に処理できるため、後の割り当てが予期せぬ形でその要件を超えることがなくなります。 
2. をキーとするデータ構造 (マルチセットや優先キューなど) を維持します。$l_i$、最初はすべてのゲストが含まれています。 これにより、最小の左要件を持つゲストを繰り返し抽出することができます。 
3. 並べ替えられた順序でゲストを繰り返し処理します。 ゲストごとに$i$、まだ存在する場合は構造から削除します。 
4. 次のゲストを選択する$j$残りの最小のゲストとして$l_j$。 これにより、次の値が最小化されます。$\max(r_i, l_j)$、減らして以来$l_j$場合を除き、エッジコストを直接削減します。$r_i$とにかく支配する。 
5. 削除する$j$そしてそれを記録します$i \to j$最終的なサイクル構築における有向隣接関係です。 コストを蓄積する$\max(r_i, l_j)$。 
6. すべてのゲストが使用されるまで繰り返します。 最後に、最後の要素を一貫してサイクルに接続し直します。 この貪欲なペアリングの下で​​は、全体の構造が自動的にサイクルに分解されます。 
7.追加$n$各ゲストが自分の占有椅子を 1 回だけ提供するため、累積エッジコストが増加します。 

### なぜ効果があるのか

 このアルゴリズムは、各隣接コストが最大 2 つの独立した制約によって決定されるという事実に基づいています。 減少処理により$r_i$大きな右側の要件を「費やした」場合、それをすぐに利用可能な最小の左側の要件にアタッチして、最大値の両方の項が大きい無駄なペアリングを防止します。 大きなペアリングからの逸脱$r_i$最小限で$l_j$サイクルの少なくとも 1 つの方向でのみ制御項を増加させることができ、すべてのノードは 1 つの発信隣接関係にのみ参加するため、後でその増加を回復する機会はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = []
    for i in range(n):
        l, r = map(int, input().split())
        a.append((r, l, i))

    a.sort(reverse=True)

    import heapq
    pq = []
    used = [False] * n

    for r, l, i in a:
        heapq.heappush(pq, (l, i))

    total = 0

    for r, l, i in a:
        if used[i]:
            continue
        used[i] = True

        while pq and used[pq[0][1]]:
            heapq.heappop(pq)

        pq2 = []
        while pq and pq[0][1] == i:
            heapq.heappop(pq)

        while pq and used[pq[0][1]]:
            heapq.heappop(pq)

        if not pq:
            break

        l2, j = heapq.heappop(pq)
        while used[j]:
            if not pq:
                break
            l2, j = heapq.heappop(pq)

        used[j] = True
        total += max(r, l2)

    print(total + n)

if __name__ == "__main__":
    solve()
```この実装では、すべての候補を左側の要件に従って順序付けし、右側の要件を降順に処理します。 各ステップは、最終的なサイクル構造内の 1 つの出力エッジを固定する貪欲な隣接関係を形成します。 最終的な答えは追加します$n$占有された椅子を考慮する一方、空の椅子の寄与はすべて、計算された最大値を通じて取得されます。 

実装上の微妙な問題は、ヒープから抽出されるときに、すでに使用されているノードが正しくスキップされるようにすることです。 要素は積極的に削除されないため、古いエントリが見つかった場合は破棄する必要があります。 

## 実用的な例

 3 つの同一のゲストが含まれる小規模な構成を考えてみましょう。$l = r = 1$。 ソート順$r$すべて等しいので任意です。 

| ステップ | 現在$r_i$| 選ばれた$l_j$| エッジコスト$\max(r_i, l_j)$| 残り |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 | 2ノード |
 | 2 | 1 | 1 | 1 | 1 ノード |
 | 3 | 1 | 1 | 1 | 0 ノード |

 端からの空の椅子の合計は 3 で、占有されている 3 つの椅子を追加すると 6 になります。これは、各ペアの間に空席が 1 つある単一の 3 人乗りサイクルの最適な構造と一致します。 

次に、非対称制約について考えてみましょう。$(r,l)$ペア$(10,0)$、$(0,10)$、$(5,5)$。 貪欲なペアリングは常に大きなものと一致します$r$利用可能な最小のもので$l$、高価な方向が両方にまたがって複合するのではなく、常に片側によって制御されるようにします。 

このトレースは、単純なペアリング戦略における非効率性の主な原因である 2 つの大きな値が 1 つの隣接関係で遭遇することをアルゴリズムがどのように防ぐかを示しています。

 ## 特殊なケース

 すべてのゲストが同じ要件を持っている場合、ゲストを複数のサークルに「分割」しようとする誤った試みは、完全なサイクルの共有構造を失うため、空の椅子の合計が増加する傾向があります。 正しい構造により、それらは単一サイクルに保たれ、すべての隣接がまったく同じ制御されたギャップに寄与し、空のスペースの重複が防止されます。 

ゲストの一人が極端にバランスを崩している場合$l_i \gg r_i$もう 1 つは逆の単純なペアリング戦略を持ち、制約の一方の側を明示的に優先しないため、最適にペアリングされません。 正しい貪欲な動作により、2 つの大きな値のうち 1 つだけが 1 つの隣接コストでアクティブになり、両方の制約が同じギャップを同時に拡大することがなくなります。
