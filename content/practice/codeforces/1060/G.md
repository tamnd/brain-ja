 ## 解決策
 ## 問題の理解

 ゼロから始まる無限の位置の行が与えられます。 初めはそれぞれのポジションで`i`ラベルが貼られたボールを保持している`i`なので、構成は完全に一致しています。位置はボール番号と同じです。 

一部の位置はポケットとしてマークされています。 1 回の操作中に、すべてのポケットが現在ポケット上にあるボールを同時に取り除きます。 削除の直後、残りのすべてのボールは順序を維持しながら可能な限り左にシフトされ、結果として得られる構成は再びゼロから始まる連続するセルを占める非負の整数の順列になります。 

この操作を複数回繰り返します。 繰り返すたびに、システムは再び安定して、隙間のないコンパクトな形状になります。 

タスクは、操作の実行後、次の形式のクエリに答えることです。`k`回、どのボールがその位置にあるか`x`?

 制約が十分に大きいため、フルラインにわたるシミュレーションは不可能です。 ポケットとクエリの数は両方とも 10 万に達し、位置と反復数は両方とも 10 億に達する可能性があります。 これにより、各フィルタリング ステップをシミュレートしたり、個々のボールを時間の経過とともに動的に追跡したりするアプローチは即座に除外されます。 ラインには境界がないため、状態全体を保存することさえ不可能です。 

ポケットに位置 0 が含まれる場合、またはポケットが原点付近で非常に密集している場合、微妙なエッジ ケースが発生します。 たとえば、ポケットが`0, 1, 2`、最初の操作により最初の 3 つのボールが削除され、番号付け全体が 3 ずつ移動します。 削除のみを追跡し、番号の再割り当ては行わない単純なシミュレーションでは、最初のステップの後でインデックスの位置がずれ、不正確な結果が連鎖的に発生します。 

圧縮が繰り返されるアプリケーションとどのように相互作用するかを考慮せずに、削除された位置のみについて推論すると、別の障害モードが発生します。 主な問題は、圧縮後に削除が元のインデックスと比較して適切な位置に留まらないことです。 

## アプローチ

 直接シミュレーションでは、配列を明示的な状態として扱います。ポケットの位置でボールを削除し、すべてを左にシフトし、繰り返します。`k`回。 1 つの操作には、現在アクティブな要素の数に比例した時間がすでにかかります。 ポジションは際限なく増加する可能性があるため、最初の`n + m`領域はすでに大きいので、これを繰り返す`10^9`クエリあたりの回数は不可能です。 各圧縮ステップでは依然として構造のスキャンと再構築が必要なため、単一の完全なシミュレーションを実行するだけでも時間がかかりすぎます。 

重要な観察は、このプロセスは、すべてのボールの正確な動きではなく、特定の位置の前に発生した削除の数にのみ依存するということです。 各操作の後、すべてのポケットからちょうど 1 つのボールが取り出され、システムは残りのすべてのボールが再び連続する整数を占めるようにシフトします。 これは、1 回の操作の後、すべての位置が`i`厳密に言うと、各ポケットの「オフセット」の 1 単位が実質的に失われます。`i`。 

動きをシミュレートする代わりに、特定の元のインデックスまで除去されたボールの数を追跡します。 後`k`オペレーション、ポジション`i`まさに負ける`k`効果が到達する各ポケットのボール。これは削除するものとして理解できます。`k`ポケットセットのコピーを作成し、圧縮します。 

これにより、より単純な静的解釈が得られます。`k`操作、位置の前に取り出されたボールの数`i`ポケットの数と同じです`a_j`そのような`a_j + (shift from previous deletions) <= i`。 構造は単調な変換に安定し、各クエリの答えは、プレフィックスに影響を与えるポケット シフトの数をカウントすることだけに依存します。 

より使いやすい定式化は、ポケット間のギャップを事前に計算することです。 させて`b[i]`各ポケットの前の非ポケット位置の数になります。 各操作では、削除を蓄積することでこれらの境界を効果的にシフトします。 クエリへの回答がマッピングになります`x`調整されたインデックスの前にあるポケットの数によって定義されるプレフィックス関数を使用します。 

各クエリをポケットの位置の数を見つけることに縮小します。`<= x + k * something`これは、ソートされたポケット配列に対する算術補正を伴う二分探索になります。 最終的なマッピングは、クエリごとに 1 つの下限を使用して評価できる単調関数になります。

 ## アルゴリズムのチュートリアル

 1. ポケットは、ソートされた順序での位置によってのみ重要であることに注意してください。 ソートされた配列に格納する`a`。 
2. 指定されたインデックスの前に厳密に存在するポケットの数を伝えるヘルパー関数を定義します。`x`。 これは二分探索で計算できます。 
3. 一定回数の操作の場合`k`、効果を有効位置の一様なシフトとして解釈します。 各ポケットは操作ごとに 1 つの除去に寄与するため、`k`オペレーション、システムが削除しました`k`各プレフィックス構造のコピー。 これにより、インデックスに線形補正が生じます。 
4. お問い合わせの場合`(x, k)`、 変身`x`その前に発生した削除の数を加算し直すことで、元の番号付けの「プレイメージ」に戻ります。 これには、その時点までのポジションに影響を与えるポケットの数を考慮する必要があります。`k`ラウンドします。 
5. 実効指数を計算する`y = x + k * (number of pockets ≤ y in the stable interpretation)`。 機能が単調なので、`y`、最小のものを二分探索することで解決できます。`y`以前に削除された要素の数が`y`必要なシフトと一致します。 
6. 1回`y`が決定される場合、答えは単に ID マッピングからその前に削除された要素の数を引いたものになります。`answer = y - count_pockets(y)`。 

重要な計算ステップは繰り返し評価することです`count_pockets(mid)`二分探索内。 それぞれの評価は、`O(log n)`下限を使用するため、各クエリは次のようになります。`O(log^2 n)`または次のように最適化されます`O(log n)`実装に応じて。 

### なぜ効果があるのか

 このプロセスでは順序が維持され、要素のみが削除されます。 各ステップの後の圧縮により、構造は、要素のアイデンティティではなく、各位置の前に削除された要素の数のみに依存することが保証されます。 これにより、変換が単調になります。ターゲット位置を増やしても、それに影響するポケットの数が増えるだけです。 単調性により、バイナリ検索が元のインデックスと最終インデックス間の固定小数点マッピングを正しく識別することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import bisect

n, m = map(int, input().split())
a = list(map(int, input().split()))

def removed(x, k):
    # number of pockets affecting position x after k rounds
    # equivalent to: count pockets <= x + k_effect_correction
    # we resolve via fixed point iteration inside binary search
    lo, hi = x, x + k + n + 5  # safe upper bound

    while lo < hi:
        mid = (lo + hi) // 2
        cnt = bisect.bisect_right(a, mid)
        val = x + k * cnt
        if mid >= val:
            hi = mid
        else:
            lo = mid + 1
    return lo

def solve_query(x, k):
    y = removed(x, k)
    cnt = bisect.bisect_right(a, y)
    return y - cnt

for _ in range(m):
    x, k = map(int, input().split())
    print(solve_query(x, k))
```実装は、最終的な位置が次のとおりであるという事実に依存します。`y`元々のボールの`x`は、その前にポケットがいくつあるかを含む首尾一貫した方程式を満たします。 不動点を探すことでこれを解決します。 正しい最終座標が見つかったら、元のボール インデックスを得る前に、削除された位置の数を減算します。 

最もデリケートな部分は、バイナリ検索範囲を十分に大きくすることです。 各ポケットが貢献できるのはせいぜい`k`シフト、上限`x + k + n`あらゆる動きを安全にカバーします。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import bisect

    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    def solve(x, k):
        # simplified correct implementation
        lo, hi = x, x + k + n + 5
        while lo < hi:

            cnt = bisect.bisect_right(a, mid)
            val = x + k * cnt
            if mid >= val:

        y = lo

    out = []
    for _ in range(m):
        x, k = map(int, input().split())
        out.append(str(solve(x, k)))
    return "\n".join(out)

 ## 特殊なケース

 ポケットが位置 0 にある場合、最初の操作により最初のボールが直ちに削除され、シーケンス全体が圧縮されます。 アルゴリズムはこれを処理します。`bisect_right`プレフィックス内のポケットを正確にカウントし、シフトが最初の位置から適用されることを保証します。 

ポケットがゼロから連続している場合、各操作により長い初期プレフィックスが削除されます。 マッピングが単調なままであるため、二分探索は依然として収束します。候補位置が増加するたびに、影響を与えるポケットの数が増加するだけです。 

いつ`k = 0`、条件が次のとおりであるため、二分探索は恒等マッピングに折りたたまれます。`x + k * cnt`等しい`x`。 減算ステップは、前にポケットを数えることに減ります。`x`、これは最初のラベル付けに影響を与えず、正確さを維持します。 

すべての場合において、正確さは、影響を与えるポケットの単調な数に対して位置のバランスをとることによってすべてのクエリが解決されるという不変条件から導き出され、それぞれに一意の固定点が存在することを保証します。`(x, k)`ペア。
