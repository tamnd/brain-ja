 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられており、それをソートされた順序に変換したいとします。バイナリ文字列の場合、これはすべてのことを意味します。`0`すべての前に現れる`1`s.

 1 つの操作で、値が増加しないサブシーケンスを選択できます。 文字列にはのみが含まれているため、`0`そして`1`、そのようなサブシーケンスは、いくつかの部分のようにしか見えません。`1`s の後にいくつかの`0`s. 次に、選択したサブシーケンスをその場で反転します。 

このタスクは、操作の最小数を決定するだけでなく、その最小値を達成する 1 つの有効な操作シーケンスを出力することも目的としています。 

制約は非常に小さいです。 すべての文字列の合計の長さは最大 1000 であるため、テスト ケースごとの二次作業でも許容されます。 本当の課題は、操作の構造を発見することです。 

微妙な点は、部分文字列ではなく部分シーケンスを操作していることです。 選択した位置は連続している必要はありません。 

文字列を考えてみましょう`0011111`。 すでに整理されています。 常に操作を実行するソリューションは、操作の最小数がゼロであるため、正しくありません。 

考慮する`10100`。 間違った文字は左端にあります`1`それは右と右端に移動するはずです`0`左に移動する必要があります。 隣接する文字を交換する単純な戦略は機能しますが、問題で定義された操作は尊重されません。 

考慮する`111000`。 文字列はソートとは程遠いですが、慎重に選択した 1 つの操作で十分です。 この観察を怠ると、不必要に多くの操作を使用するソリューションが必要になります。 

## アプローチ

 強引な視点は、反転を繰り返し修正することを考えることです。 反転とは、`1`の前に表示されます`0`。 文字列がソートされるまで文字を移動してみることもできます。 このようなアプローチは不必要であり、操作の特別な構造を利用しません。 

重要な観察は、バイナリ文字列内の有効なサブシーケンスがどのように見えるかを調べることから得られます。 サブシーケンスは非増加である必要があるため、任意のコレクションを含めることができます。`1`および任意のコレクション`0`後から登場するもの。 その部分シーケンスが反転されると、選択されたすべての`1`右側に向かって移動し、選択されたすべての`0`左側に向かって移動します。 

次に、文字列をソートされたバージョンと比較します。 現在の文字列に含まれるすべての位置`1`しかし、ソートされた文字列には次のものが含まれます`0`場違いです`1`。 同様に、現在の文字列に含まれるすべての位置`0`しかし、ソートされた文字列には次のものが含まれます`1`場違いです`0`。 

全部置き忘れた`1`すべてが置き忘れられる前に発生します`0`s. これらの位置を正確に 1 つのサブシーケンスに収集すると、そのサブシーケンスはいくつかの部分で構成されます。`1`に続いていくつか`0`s、動作要件を満たします。 逆にすると、選択したすべての文字が直ちに正しい位置に配置されます。 

これは、ソートされていないすべての文字列を 1 回の操作で修正できることを意味します。 文字列がすでにソートされている場合、操作は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 反転固定をシミュレートする | O(n²) | O(n) | 不要 |
 | ソートされた文字列と比較する | O(n log n) | O(n) | 承認済み |

 アルファベットだけなので、`{0,1}`、ソートステップさえゼロを数えることで置き換えることができますが、ソートを伴う標準実装はすでに十分以上に高速です。 

## アルゴリズムのチュートリアル

 1. 現在の文字列について、ソートされたバージョンを作成します。 
2. 元の文字列がソートされた文字列と異なるすべてのインデックスを検索します。 
3. このようなインデックスをすべて保存します。 
4. 異なるインデックスがない場合、文字列はすでにソートされています。 出力`0`。 
5. それ以外の場合は出力`1`一回の操作で十分だからです。 
6. 収集したインデックスを選択したサブシーケンスとして出力します。 

ステップ 6 が機能する理由は、左側の不一致位置がすべて、`1`これは右に移動する必要があり、右側のあらゆる不一致な位置が影響を及ぼします。`0`それは左に移動する必要があります。 したがって、収集されたサブシーケンスは次のシーケンスになります。`1`に続いて`0`s。これは操作に有効です。 

### なぜ効果があるのか

 しましょう`t`文字列のソートされたバージョンになります。 

いつでも`s[i] != t[i]`、位置の文字`i`成功する変革には必ず参加しなければなりません。 の数以来、`0`と`1`s は変化せず、不一致の位置は自然に 2 つのグループに分けられます: 余分なものを含む位置`1`と余分な位置を含む`0`s.

 すべて追加`1`余計なことより先に嘘をつく`0`s. したがって、不一致の位置にある文字は、非増加のサブシーケンスを形成します。 このサブシーケンスを逆にすると、2 つのグループが交換され、不一致の位置がすべて正しい値に配置されます。 反転後、文字列全体は次と等しくなります。`t`。 

したがって、文字列がまだソートされていない場合は 1 回の操作で十分であり、すでにソートされている場合は操作は不要です。 これが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        s = input().strip()

        target = ''.join(sorted(s))

        pos = []
        for i in range(n):
            if s[i] != target[i]:
                pos.append(i + 1)

        if not pos:
            print(0)
        else:
            print(1)
            print(len(pos), *pos)

solve()
```このソリューションでは、まずソートされたターゲット文字列を構築します。 元の文字列がターゲットと異なる箇所はすべて修正する必要があります。 これらの位置は、単一の操作で使用されるインデックスとまったく同じです。 

インデックスは昇順で出力されますが、これはサブシーケンスを形成するために必要です。 この問題では 1 から始まるインデックスが使用されているため、各位置は次のように報告されます。`i + 1`。 

最も一般的な実装上の間違いは、1 ベースの変換を忘れることです。 もう 1 つのよくある間違いは、ソートされていないバイナリ文字列ごとに常に 1 つの操作で十分であるにもかかわらず、複数の操作を出力しようとすることです。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    data = io.StringIO(inp)

    def input():
        return data.readline()

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        target = ''.join(sorted(s))
        pos = [i + 1 for i in range(n) if s[i] != target[i]]

        if not pos:
            out.append("0")
        else:
            out.append("1")
            out.append(str(len(pos)) + " " + " ".join(map(str, pos)))

    return "\n".join(out)

# sample-style checks
assert run("1\n7\n0011111\n") == "0"

# already sorted
assert run("1\n1\n0\n") == "0"

# all ones
assert run("1\n5\n11111\n") == "0"

# reverse-sorted binary string
assert run("1\n6\n111000\n").splitlines()[0] == "1"

# alternating pattern
assert run("1\n4\n1010\n").splitlines()[0] == "1"

 ## 特殊なケース

 インプットを考慮する`1`続いて文字列`0`。 ソートされたバージョンは同一であるため、不一致セットは空です。 アルゴリズムは直ちにゼロ操作を出力します。 

文字列を考えてみましょう`111000`。 並べ替えたバージョンは、`000111`。 すべての位置が異なるため、6 つのインデックスがすべて選択されます。 選択されたサブシーケンスは`1 1 1 0 0 0`、増加していません。 逆にすると、ソートされた文字列が直接生成されます。 

文字列を考えてみましょう`001011`。 並べ替えたバージョンは、`000111`。 不一致は中間の位置でのみ発生します。 それらの位置を正確に選択すると、すでに正しい文字に触れることはなくなり、1 回の反転で文字列が完全に修正されます。 

これらのケースは中心不変式を示しています。つまり、不一致の位置は常に有効な非増加サブシーケンスを形成し、そのサブシーケンスを逆転させるとすべての不一致が同時に解決されます。
