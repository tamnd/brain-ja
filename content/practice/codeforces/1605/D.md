 ## 解決策
 ## 問題の理解

 最初のプレイヤーである Eikooc が保証される勝利開始位置の数を最大化できるように、ツリーのノードのラベルを変更するように求められます。 ゲーム自体はツリー上でトークンを移動するゲームであり、プレイヤーは交互にビット単位の XOR 条件を使用して未訪問の隣接ノードにトークンを移動します。トークンがノード上にある場合`v`、隣に移動できる`u`場合のみ`u XOR v ≤ min(u, v)`。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、次のツリーを指定します。`n`ノードと`n-1`エッジ。 出力は数値の順列である必要があります`1`を通して`n`Eikooc ができるだけ多くの確実な勝利の初手を持つように、ノードの新しいラベルを与えます。 

制約は大きいです:`n`すべてのテスト ケース全体で最大 2 · 10^5 にすることができ、最大 10^5 のテスト ケースを含めることができます。 O(n^2) でも遅すぎるため、考えられるすべてのゲームをシミュレートしたり、ノード ラベルのすべての順列をチェックしたりするソリューションは除外されます。 この問題は建設的です。ゲームをシミュレートすることは求められておらず、最適な最初の手を保証する再ラベルを作成することだけが求められています。 エッジケースには、次のような非常に小さな木が含まれます。`n = 1`または`n = 2`、星や長い道など、非常にバランスの悪い木。 

たとえば、2 つのノードが接続されたツリーがある場合、1 XOR 2 = 3 が min(1,2) = 1 より大きいため、XOR 条件がクリティカルになり、移動は不可能になります。 この場合、最初のプレイヤーが自動的に勝つため、どのような順列でも機能します。 不注意なアプローチでは、XOR 条件が失敗した場合に特定の小さなサブツリーが移動をブロックする可能性があることを考慮せずに、恣意的にラベルを付けようとする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのデータを生成しようとします。`n!`ラベルを並べ替えて、考えられるそれぞれの最初の動きからゲームをシミュレートします。 最初の動きごとに、Eikooc が強制的に勝利したかどうかを再帰的に確認できます。 これは明らかに不可能です`n > 10`、 なぜなら`n!`は指数関数的よりも速く増加し、ゲーム自体のシミュレーションは開始ノードごとに O(n) になる可能性があり、最大の制約では実行時に不可能になります。 

重要な洞察は、XOR 条件を調べることで得られます。 任意の 2 つの隣接ノードの場合`u`そして`v`、次の場合、移動はブロックされます。`u XOR v > min(u,v)`。 勝利する開始ノードの最大数については、開始ノードに接続されているすべてのエッジで XOR 不等式が失敗し、最初のプレーヤーは移動できるが、2 番目のプレーヤーは移動できないようにする必要があります。 これは、ツリーの奇数の深さのノードが 1 つの数値パリティを持ち、偶数の深さのノードが別のパリティを持つようにノードにラベルを付けることで保証できます。 具体的には、2 分割の一方の部分に小さな番号を割り当て、もう一方の部分に大きな番号を割り当てることができます。 上位ビットが異なる数値の XOR は小さい数値を超えるため、小さいノードから大きいノードへの移動は XOR 条件によってブロックされます。 ツリーは本来 2 部構成であるため、深さによってノードを分割することで、2 分割の小さいセット内のどのノードからも Eikooc が確実に勝つようにする簡単なラベル付けが可能になります。 

このアプローチは次の点で線形です。`n`: DFS は 2 つのパーティションを見つけ、各部分に番号を順番に割り当てることによって再ラベル付けが行われます。 ツリー構造と XOR 不等式を巧みに利用し、シミュレーションを回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`そして`n-1`ツリーを定義するエッジ。 ツリーの隣接リストを作成します。 
2. 任意のノード (ノード 1 など) から開始して深さ優先検索を実行し、各ノードの深さを計算します。 深さのパリティに基づいてノードを 2 つのセットに割り当てます: set`A`均一な深さの場合は、設定します`B`奇妙な深さ用。 これにより、ツリーが自然に 2 つに分割されます。 
3. セット内のノードの数を数える`A`そして`B`。 最初のプレイヤーの勝利開始ノードの数を最大化するには、小さいセットに次の小さい番号のラベルを付ける必要があります。`1`に`size_of_smaller_set`。 これにより、これらのノードから他のセットへの移動は XOR 条件に違反します。これは、より大きな数値の XOR より小さい数値が小さい数値を超えるためです。 大きいセットは、残りのより大きい数値を受け取ります。 
4. ノードに番号を割り当てます。小さいセットを反復して、1 から始まる増加する番号を割り当てます。大きいセットを反復して、残りの番号を割り当てます。 
5. ラベルの順列を元のノード インデックスの順序で出力します。 

これが機能する理由: 不変条件は、小さいセット内のノードから大きいセットへのすべての移動が XOR 条件によってブロックされることです。 最初の動きは打ち消されないため、小さいセット内のノードは最初の動きで勝つことが保証されます。 より大きなセット内のノードは勝っている場合と勝てない場合がありますが、問題は保証された勝利を最大化することのみを要求します。 このラベルはその特性を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 20)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)
        
        depth = [0] * n
        visited = [False] * n
        
        def dfs(u, d):
            visited[u] = True
            depth[u] = d
            for v in adj[u]:
                if not visited[v]:
                    dfs(v, d + 1)
        
        dfs(0, 0)
        
        setA = [i for i in range(n) if depth[i] % 2 == 0]
        setB = [i for i in range(n) if depth[i] % 2 == 1]
        
        if len(setA) > len(setB):
            setA, setB = setB, setA
        
        perm = [0] * n
        num = 1
        for node in setA:
            perm[node] = num
            num += 1
        for node in setB:
            perm[node] = num
            num += 1
        
        print(" ".join(map(str, perm)))
```このコードは、まず隣接リストを構築し、DFS を介して深さを計算します。 深さのパリティによってノードをセットに収集します`A`そして`B`。 小さいセットは、最初の動きで勝利を保証するために最小の数字を取得します。 最後に、元のノードの順序に従って順列を出力します。 DFS はすべてのノードが確実にアクセスされるようにし、`sys.setrecursionlimit`線形ツリーの深い再帰を可能にします。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
