 ## 問題の理解

 初期配列が与えられます`a`とターゲット配列`b`長さの`n`、ただし、の最初の値は`b`は不明であり、クエリごとに個別に提供されます。 すべてのクエリ値について`x`、一時的に設定します`b[1] = x`そして変身したい`a`この完全に指定されたものに`b`。 

唯一許可される動きはインデックスを選択することです`i`次に、次の倍数のすべての位置を増減します。`i`1単位ずつ。 言い換えれば、各操作はインデックスに対して除数パターンを選択し、影響を受けるすべての位置を均一にシフトします。 

タスクは、各候補値について計算することです。`b[1]`、変換するために必要なそのような操作の最小数`a`の中へ`b`。 

制約は大きく、`n`そして`q`まで`2 × 10^5`。 これにより、クエリごとに変換を個別に再計算したり、操作を明示的にシミュレートしたりするソリューションは即座に除外されます。 クエリごとにすべての約数を単純に処理するアプローチは失敗します。 

インデックスごとにローカルに考えると、微妙なエッジケースが現れます。 たとえば、独自のインデックスでの操作を使用して各位置を個別に調整しようとする可能性がありますが、これは重複を無視します。インデックスでの操作`i`すべての倍数に影響を与える`i`、したがって、ポジションは約数の関係を通じて密接に結合されます。 もう 1 つの落とし穴は、各位置を独立して扱い、絶対的な差を合計することです。 これは共有構造を無視し、操作を大幅に過少カウントまたは過大カウントします。 

## アプローチ

 強引なアイデアは、各操作が配列にどのような影響を与えるかをシミュレートすることです。 インデックスごとに`i`を適用する回数を決定してみることもできますが、各インデックスが無制限の整変数 (増分または減分の数) に寄与するため、選択肢の数は指数関数的に増加します。 値を制限したとしても、各位置はそのすべての約数の影響を受けるため、インデックス間の相互作用はグローバルのままです。 

より構造化されたビューは、視点を逆にすることです。 オペレーションについて考えるのではなく、各オペレーションが各インデックスに与える最終的な最終的な効果について考えます。 それぞれの操作は、`i`整数を追加します`c[i]`すべての倍数に`i`。 次に、位置の最終値`j`すべての合計になります`c[i]`そのような`i`分割する`j`。 これは古典的な除数畳み込み構造です。 

ということで、それぞれのポジションごとに`j`、 我々は持っています：```
final[j] = sum_{i | j} c[i]
```私たちが欲しいのは`final[j] = b[j] - a[j] = d[j]`。 

したがって、整数値を見つける必要があります`c[i]`次のような:```
for all j: d[j] = sum_{i | j} c[i]
```これは除数格子上のメビウス反転です。 計算したら`c`、コストは単純に次のとおりです。```
sum |c[i]|
```残る唯一の難点は、`b[1]`クエリごとに変更され、直接影響します`d[1]`、すべてに伝播します`c[i]`反転による値。 この依存関係を分離し、それぞれを表現します。`c[i]`の線形関数として`b[1]`。 システムは約数にわたって三角形であるため、それぞれ`c[i]`の倍数のみに依存します`i`、特にすべての変更は、構造化されたプレフィックスと除数の方法で伝播されます。 これにより、次の寄与を事前に計算することができます。`b[1]`あらゆる人に`c[i]`、固定位置からの一定部分も。 

この変換の後、各クエリは次の線形関数の絶対値の合計を評価することになります。`x`これは、ブレークポイントをソートし、区分的線形セグメントを維持することで処理できます。

 ## アルゴリズムのチュートリアル

 1. を定義して問題を差分形式に変換します。`d[j] = b[j] - a[j]`。 各クエリについてのみ、`d[1]`それ以来の変化`b[1] = x`。 
2. 各操作タイプのモデル化`i`変数として`c[i]`、インデックスで操作を適用する回数を表します`i`肯定的にも否定的にも。 この場合、各位置は次の条件を満たします。```
d[j] = sum of c[i] over all i dividing j
```これにより、問題が除数畳み込み方程式として再定式化されます。 
3. メビウス反転を約数構造に適用して回復します`c[i]`から`d[j]`。 概念的には、倍数の寄与を差し引いて、大きいインデックスから小さいインデックスまで処理します。```
c[i] = d[i] - sum_{k=2i, 3i, ...} c[k]
```このステップが機能する理由は、次の倍数であるためです。`i`が唯一のインデックスです。`c[i]`貢献します。 
4. 様子を観察する`d[1] = x - a[1]`クエリに依存する唯一の変数です。 その他すべて`d[j]`は定数です。 したがって、すべての`c[i]`のアフィン関数になります`x`:```
c[i] = alpha[i] * x + beta[i]
```5. 事前計算`alpha[i]`そして`beta[i]`同じ反転順序を使用します。 のために`i = 1`、`alpha[1] = 1`そして`beta[1] = -a[1]`。 その他の場合`i`、伝播:

 係数が一貫して累積されるように、倍数から寄与を差し引きます。 
6. 質問に対する答え`x`は：```
sum |alpha[i] * x + beta[i]|
```各項は区分的に線形であり、ブレークポイントは最大 1 つです。`x = -beta[i]/alpha[i]`いつ`alpha[i] ≠ 0`。 
7. すべてのブレークポイントを並べ替えてそれらをスイープし、合計式の変化の傾きを維持します。`x`が増加します。 事前に計算されたイベント ポイントに対する二分探索を介して各クエリを評価します。 

### なぜ効果があるのか

 重要な不変条件は、反転の各段階で、割り切れない三角形システムを解いているということです。`c[i]`の倍数の値にのみ依存します`i`、これらは厳密に大きなインデックスです。 これにより、すべての倍数の寄与を修正すると、次の値が保証されます。`i`は一意に決まります。 線形依存性`d[1]`次に、同じ三角形構造を通ってきれいに伝播するため、次のすべての係数が`c[i]`に関して`x`明確に定義されており、クエリの順序に依存しません。 

最終コストはアフィン関数の L1 ノルムであり、各関数の符号の変更は最大 1 回であるため、グローバル構造は区分的に線形であり、ブレークポイントはこれらの符号反転によって完全に決定されます。 これにより、クエリごとに効率的な評価が可能になります。

    alpha = [0] * (n + 1)

## 実用的な例

 小さな例を考えてみましょう。`n = 2`、`a = [3, 7]`、 そして`b[2] = 5`。 私たちは異なります`b[1] = x`。 

私たちは計算します`d[2] = 5 - 7 = -2`、 そして`d[1] = x - 3`。 

逆変換により次の結果が得られます。```
c[2] = d[2]
c[1] = d[1] - c[2]
```| ステップ | c[2] | c[1] |

 ## 特殊なケース

 重大なエッジケースは次のような場合にのみ発生します。`b[1]`は変化し、その他の差はすべてゼロです。 この場合、システムはインデックス 1 からの純粋な除数の累積に還元され、反転によってそれぞれの要素が一致するクリーンなチェーンが生成されるはずです。`c[i]`の倍数です`x`貢献。 すべての定数項が消滅し、三角伝播のみがアクティブのままであるため、アルゴリズムはこれを正しく処理します。 

もう一つのケースは次のような場合です。`n`は素数が多い、つまりほとんどのインデックスには自明でない約数がないことを意味します。 それからそれぞれ`c[i]`ほぼ完全に依存している`d[i]`、そして反転はほぼ独立したシステムに退化します。 これは、構造を変更することなく、アルゴリズムが密な除数グラフと疎な除数グラフの間で適切に適応することを確認します。
