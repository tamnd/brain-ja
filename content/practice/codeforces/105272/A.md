 ## 解決策
 ## 問題の理解

 円形の刑務所の周りに配置された占有セルの位置が 1 から 360 までのラベルで与えられます。構造が円形であるため、セル 360 はセル 1 に隣接しており、連続する監視間隔はこの境界を囲む可能性があります。 

私たちのタスクは、セルの 1 つの連続した円形セグメントを正確にカバーするカメラを配置することです。 このセグメントには、占有されているすべてのセルが含まれている必要があります。 このようなすべての有効なセグメントの中で、長さが最小のセグメントが必要です。長さは、両端を含む区間内のセルの数としてカウントされます。 

入力により、占有セルのインデックスのリストが得られます。 出力は、すべての占有位置をカバーする連続円弧の最小サイズです。 

n ≤ 360 という制約は十分に小さいため、全円にわたる 3 次または 2 次のアプローチも許容されます。 ただし、循環構造が重要な問題です。360 から 1 に戻る間隔は一貫して処理する必要があります。 単純な線形間隔アプローチは、ラップアラウンドを明示的に考慮しない限り失敗します。 

占有セルが番号範囲の両端近くに集まっている場合、微妙な障害が発生します。 たとえば、占有セルが {350, 355, 5} の場合、5 から 350 までの線形間隔は直接意味を持ちませんが、最適な解決策は 350 → 5 をカバーするラップされた間隔であり、これは短いです。 線形の最小位置と最大位置のみを考慮するソリューションでは、正しい小さな円弧ではなく、誤って 345 に近い値が返されます。 

もう 1 つのエッジ ケースは、{10、11、12、13} など、占有セルが小さなセグメント内ですでに連続している場合です。 その場合、答えは単純に 4 となり、ラップは必要ありません。 

## アプローチ

 ブルートフォースのアイデアは、円上のすべての可能な開始セルを試し、すべての占有セルが含まれるまで前方に拡張することです。 開始するたびに、必要な位置をすべてカバーするまで時計回りに移動し、セグメントに占有されているすべてのセルが含まれているかどうかを確認し、その長さを計算します。 可能な開始点は 360 個、終了点は最大 360 個あり、各チェックで最大 n 個の点をスキャンできるため、おおよそ O(360 × 360 × n) となり、この制約には十分小さい値ですが、概念的には無駄です。 

この非効率性は、セグメントが占有されているすべてのセルをカバーしているかどうかを繰り返し再チェックすることから生じます。 すべての間隔を明示的にテストする代わりに、問題を再定式化できます。占有点が円上で「最も広がっている」円形のカットを選択しています。 占有位置を並べ替えると、最適なセグメントは、円上の連続する占有点間の最大ギャップを補完するものになります。 その最大のギャップを削除すると、すべての点を含む最小の円弧が得られます。 

重要な洞察は、円上のカットポイントを選択した後、円形のカバー間隔は線分として考えることができるということです。 最大の空のギャップ内に位置するカットを選択した場合、すべての占有点は単一の線形間隔に収まり、その間隔は最小になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 間隔を超えた総当たり攻撃 | O(360²・n) | お(1) | 受け入れられるが不要 |
 | 並べ替え + 最大ギャップ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての占有位置を読み取り、昇順に並べ替えます。 ソートにより、円上で連続して占有されているセルを推論することができます。 
2. この並べ替えられた順序で、連続する占有セル間のギャップを計算します。 0 から n − 2 までの各 i について、ci+1 − ci を計算します。 これらは、時計回りに移動するときの空のストレッチを表します。 
3. また、最後の要素と最初の要素の間の循環ギャップ (360 − last + first) を計算します。 これにより、ラップアラウンドの空のセグメントがキャプチャされます。 
4. これらすべてのギャップの最大値を見つけます。 このギャップは、円上の未使用セルの最大領域を表します。 
5. 答えは 360 − (最大ギャップ) です。 これは、占有されているすべてのセルが 1 つの連続した円弧内に収まるように、最大​​の空き領域内のカットを選択することに対応します。 

### なぜ効果があるのか

 すべての占有セルをカバーする円形の間隔では、円の連続する空の円弧を 1 つだけ除外する必要があります。 最大の空のアークを除外することを選択した場合、残りの覆われたアークは最小化されます。 他の選択では、より小さいギャップが除外され、カバーされる間隔が円の周囲にさらに拡張されます。 したがって、最適解は、循環順序で連続する占有点間の最大ギャップによって完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    a.sort()

    if n == 1:
        print(1)
        return

    max_gap = 0

    for i in range(n - 1):
        max_gap = max(max_gap, a[i + 1] - a[i])

    # circular gap
    max_gap = max(max_gap, 360 - a[-1] + a[0])

    print(360 - max_gap)

if __name__ == "__main__":
    solve()
```実装は、連続する差分が実際の時計回りのギャップに対応するように占有セルをソートすることから始まります。 隣接するペアに対するループは、すべての内部ギャップを計算します。 円形のギャップは、最後の要素と最初の要素を 360 のラップアラウンド境界を通して接続することによって個別に処理されます。360 から最大のギャップを減算すると、最小のカバー円弧が得られます。 

特殊なケース n = 1 は、ギャップがないため明示的に処理されます。 単一点をカバーする最小の円弧は 1 つのセルです。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
occupied = [10, 20, 30]
```ソート順序はすでに同じです。 ギャップは次のとおりです。 

| ステップ | ペア | ギャップ |
 | --- | --- | --- |
 | 1 | 10→20 | 10 |
 | 2 | 20 → 30 | 10 |
 | 3 | 30 → 10 (ラップ) | 340 |

 最大ギャップは 340 です。 

答えは 360 − 340 = 20 です。 

これは、30 から 10 までの大きな空の領域を通る円を切り取り、10 から 30 までの狭い円弧を残すことに対応します。 

### 例 2

 入力:```
n = 4
occupied = [350, 355, 2, 10]
```並べ替え:

 350、355、2、10

 次に、循環的に計算します。 

| ステップ | ペア | ギャップ |
 | --- | --- | --- |
 | 1 | 350 → 355 | 5 |
 | 2 | 355 → 2 | 7 (360 度にわたってラップ) |
 | 3 | 2→10 | 8 |
 | 4 | 10 → 350 (ラップ) | 340 |

 最大ギャップは 340 です。 

答えは 360 − 340 = 20 です。 

これは、最適な円弧が境界を越えてラップし、10 ～ 350 の間の大きな空の領域を無視する理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、ギャップ スキャンは線形です。 
| スペース | O(n) | 占有位置の保存 |

 制約の上限は n で 360 であるため、ソートと 1 回のリニア スキャンは非常に高速です。 この解決策は、最悪の場合でも時間とメモリの制限内に十分収まります。 

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input().strip())
    a = list(map(int, input().split()))
    a.sort()

    if n == 1:
        return 1

    max_gap = 0
    for i in range(n - 1):
        max_gap = max(max_gap, a[i + 1] - a[i])
    max_gap = max(max_gap, 360 - a[-1] + a[0])

    return 360 - max_gap

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return str(solve())

# minimum case
assert run("1\n100\n") == "1"

# simple linear segment
assert run("3\n10 20 30\n") == "20"

# wraparound case
assert run("3\n350 355 2\n") == "12"

# all consecutive
assert run("4\n1 2 3 4\n") == "4"

# symmetric split
assert run("2\n1 180\n") == "179"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 1 | 基本ケースの処理 |
 | 10 20 30 | 20 | 基本的な線形圧縮 |
 | 350 355 2 | 12 | 円形ラップの正確性 |
 | 1 2 3 4 | 4 | ラップなし、タイトなクラスター |
 | 1 180 | 179 | 大きな対称ギャップ |

 ## 特殊なケース

 占有セルが 1 つだけの場合、ギャップ計算は意味がないため、アルゴリズムは直接 1 を返します。 360 個のセルからなる完全な円を想像する場合でも、円の推論は依然として当てはまります。単一の点を除く円全体を削除すると、長さ 1 の円弧が得られます。 

[350, 355, 2] のような入力の場合、ソートによりラップ境界で不連続性が生じます。 正しく計算されたギャップには、ラップアラウンド ロジックを介して 355 と 2 の間にある大きな 340 セル ギャップが含まれています。 これが最大ギャップとなるため、最終的な答えは 360 − 340 = 20 となり、360 → 1 の境界にまたがる小さな円弧と一致します。 

[1, 121, 241] のような等間隔の入力の場合、すべてのギャップは等しく、単一の方向が支配することはありません。 選択された最大ギャップが有効な最小円弧につながり、それを差し引くと正しい最小カバー セグメント サイズが得られるため、アルゴリズムは引き続き機能します。
