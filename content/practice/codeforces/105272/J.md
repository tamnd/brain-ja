 ## 解決策
 ## 問題の理解

 私たちには、一列に並べられた一連のリクエストが与えられます。各位置は、特定の種類の料理を注文した人に対応します。 これに加えて、制約もあります。ウェイターには k 個の「アーム」しかなく、各アームは任意の数の料理を運ぶことができますが、料理の種類は 1 つだけです。 これは、顧客の間隔に最大 k 種類の異なる料理が含まれる場合、ウェイターは 1 回の移動ですべての料理を提供できることを意味します。 

タスクは、最大で k 個の個別の値を含む配列の連続したセグメントを見つけることであり、そのようなすべてのセグメントの中で、可能な最大長のセグメントが必要です。 1 つの最適なセグメントの長さとインデックスの両方を出力する必要があります。 

配列の長さと k は 200000 に達する可能性があるため、二次または二次に近いアプローチは失敗します。 ソリューションは、線形または線形に近い時間 (通常は O(n) または O(n log n)) で配列を処理する必要があります。 これは、周波数追跡を伴うスライディング ウィンドウまたは 2 ポインター技術を強く示唆しています。 

素朴なアプローチでは、すべてのサブ配列を試し、それぞれの異なる要素をカウントします。 これにより、O(n²) 個のサブ配列が発生し、最適化されたカウントを使用したとしても、個別のカウントを維持するには O(1) の償却コストがかかりますが、サブ配列の数が多すぎるため、速度が非常に遅くなります。 

単純な推論によるさらに微妙な失敗例は、配列に繰り返しブロックが多数ある場合に発生します。 たとえば、すべての要素が個別であり、k が小さい場合、ほとんどの間隔は無効になりますが、それでもチェックに時間を浪費することになります。 逆に、k が大きい場合、多くの間隔が有効になり、ブルート フォースが再び爆発します。 

中心となる困難は、有効性をチェックすることではなく、すべての候補区間を移動しながら一連の個別の要素を効率的に維持することです。 

## アプローチ

 ブルートフォースのアイデアは単純です。左端のすべての端点 l を選択し、r を l から n まで拡張し、現在のセグメント内に個別の値がいくつあるかを追跡します。 r を拡張するたびに、頻度テーブルが更新されます。 個別の要素の数が最大でも k 個の場合、最良の回答が更新されます。 これは、考えられるすべての間隔を調査するため、正しいです。 

ただし、区間の数は O(n²) です。 r を展開するときの更新頻度は O(1) ですが、それでも約 n(n+1)/2 回の展開を実行します。これは、n が 200000 までの場合は大きすぎます。 

重要な観察は、「最大で k 個の異なる値」という制約が、間隔の縮小と拡大に関して単調であるということです。 間隔が有効な場合、拡張すると有効性が失われる可能性があり、無効な場合は縮小すると有効性が回復する可能性があります。 この構造はまさに 2 ポインタ スライディング ウィンドウ アプローチを可能にするものです。 

l ごとに最初から再計算する代わりに、ウィンドウ [l, r] を維持し、それが常に制約を満たすようにします。 私たちは貪欲に r を前進させ、制約に違反するたびに、再び有効になるまで l を前進させます。 各インデックスはウィンドウに入ったりウィンドウから出たりするのは最大 1 回であるため、線形の複雑さが生じます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 2 つのポインタ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のウィンドウ内の値の頻度マップと、現在存在する個別の値の数を追跡するカウンターを維持します。 また、現在のセグメントを定義する 2 つのポインター l および r と、これまでに確認された最良のセグメントを追跡する変数も維持します。

1. l = 0、best_length = 0、および空の周波数構造を初期化します。 ウィンドウが空であるため、現在の個別カウントは 0 です。 
2. r を左から右に展開します。 新しい要素 a[r] ごとに、その頻度を増加させます。 この値が以前にウィンドウに存在しなかった場合は、個別のカウンタをインクリメントします。 このステップにより、ウィンドウが貪欲に拡大されます。 
3. a[r] を挿入した後、個別の値の数が k を超えた場合は、有効性を復元する必要があります。 これを行うには、l を前進させます。 ステップごとに、a[l] の頻度を減らします。 ゼロになると、個別のカウンターを減らします。 ウィンドウに再び最大 k 個の個別の値が含まれるまで続行します。 
4. ウィンドウが有効になったら、その長さ (r - l + 1) をこれまでに見つかった最適な長さと比較します。 それが大きい場合は、最良の回答を更新し、現在の l と r を保存します。 
5. r が配列の終わりに達するまで続けます。 

これが機能する理由: r ごとに、r で終わる最長の有効なセグメントが見つかります。 r で終わる短いセグメントはその中に含まれるため、すでに検討したものを超えて答えを改善することはできません。 スライディング調整により、制約が成立するように l が常に最小になることが保証されるため、ウィンドウは常にその r の最大有効ウィンドウになります。 

不変条件は、r の各反復の開始時に、ウィンドウ [l, r-1] に最大 k 個の個別の値が含まれ、r を処理して l を調整した後、ウィンドウ [l, r] が最大 k 個の個別の値を保持する最小の左境界になることです。 これにより、有効なセグメントがスキップされず、すべての候補最大セグメントが 1 回だけ検査されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    distinct = 0

    l = 0
    best_len = 0
    best_l = 0
    best_r = 0

    for r in range(n):
        x = a[r]
        if x not in freq or freq[x] == 0:
            freq[x] = 1
            distinct += 1
        else:
            freq[x] += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            if freq[y] == 0:
                distinct -= 1
            l += 1

        if r - l + 1 > best_len:
            best_len = r - l + 1
            best_l = l
            best_r = r

    print(best_len)
    print(best_l + 1, best_r + 1)

if __name__ == "__main__":
    solve()
```頻度ディクショナリは、現在のウィンドウ内で各ディッシュ タイプが何回表示されるかを追跡します。 個別のカウンターにより、辞書キーを繰り返しスキャンすることが回避されます。 内側のループは、r を拡張するたびにウィンドウが常に k-distinct 制約を満たすことを保証します。 

インデックス付けは、best_l と best_r を 0 ベースの形式で保存し、最後に 1 ベースの出力に変換することで慎重に処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    distinct = 0
    l = 0

    best_len = 0
    best_l = best_r = 0

    for r in range(n):
        x = a[r]
        freq[x] = freq.get(x, 0) + 1
        if freq[x] == 1:
            distinct += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            if freq[y] == 0:
                distinct -= 1
            l += 1

        if r - l + 1 > best_len:
            best_len = r - l + 1
            best_l, best_r = l, r

    return f"{best_len}\n{best_l+1} {best_r+1}\n"

# provided samples
assert run("5 2\n1 2 3 2 1\n") == "3\n2 4\n"
assert run("8 3\n4 1 2 3 3 2 1 4\n") == "6\n2 7\n"

assert run("1 1\n7\n") == "1\n1 1\n"

 ## 特殊なケース

 n = 1 の最小ケースでは、アルゴリズムが縮小ループに入らずに最良の回答を正しく初期化するかどうかをテストします。 ウィンドウは有効になり、すぐに記録される必要があります。 

k ≥ 個別の値の数の場合は、アルゴリズムが不必要な縮小を回避するかどうかをテストします。 ウィンドウは縮小せずに完全に拡大し、「必要な場合のみ縮小する」ロジックが正しいことを確認します。 

k = 1 ですべての要素が異なる場合は、積極的な縮小動作をテストします。 ウィンドウは常に 1 つの要素に折りたたまれ、周波数マップがカウントを正しくリセットし、値がウィンドウから完全に外れたときに個別のカウンターが正確にデクリメントされるようにする必要があります。
