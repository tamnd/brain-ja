 ## 解決策
 ## 問題の理解

 私たちに与えられたグループは、$n$人々、どこ$n$は 3 で割り切れるため、これらの人々はすでに 3 人ずつのメンバーからなるチームに分割されています。 各チームは、メンバー 3 名のうち少なくとも 2 名が出場を確信した場合にのみ、競技会への参加に同意します。 

コーチは個人を直接説得することができます。 チームの少なくとも 2 人のメンバーが同意すると、3 人目のメンバーも自動的に同意します。 目標は、最終的にすべてのチームが参加するために、直接説得する必要がある人の数を最小限に抑えることです。 

再構成すると、3 人からなる各グループはしきい値ガジェットのように動作します。1 人を説得するだけではチームを活性化するのに十分ではありませんが、2 人を説得するだけでは 3 人目が従うように強制されます。 タスクは、各トリプルに少なくとも 2 つのシードが選択されるか、強制的に伝播されるように、最小数の初期「シード」を選択することです。 

制約$n \le 100$これは、サブセットに対するブルートフォースが実行できないことを意味します。 平$2^{100}$全く実現不可能です。 どのようなソリューションでも、組み合わせを検討するのではなく、各トリプルの構造を直接推論する必要があります。 

構造を持たずに貪欲に考えると、微妙な落とし穴が現れます。 たとえば、チームごとにちょうど 2 人を選択しようとすると、次のようになります。$2n/3$, しかし、チーム間の効果がこれをさらに削減できるかどうかは明らかではありません。 もう 1 つの素朴な考えは、チームごとに 1 人を選ぶと何らかの形でカスケードされる可能性があるというものですが、チームは独立しているため、カスケードは境界を越えることはありません。 

## アプローチ

 ブルートフォースの観点は、人々のサブセットを選択してプロセスをシミュレーションすることを検討することです。各チームについて、少なくとも 2 人のメンバーが選択されているかどうかを確認し、選択されていない場合は、繰り返しの伝播によって 3 人目のメンバーが確信するかどうかを確認します。 チーム間の伝播が存在せず、チーム内ではルールが単純なしきい値条件に崩壊するため、これはすぐに複雑になります。 サブセットを列挙すると正確性が得られますが、コストがかかります$O(2^n \cdot n)$、それは限界をはるかに超えています。 

重要な単純化は、チームが完全に独立していることを認識することです。 あるチームの決定が他のチームに影響を与えることはありません。 これは、3 つのグループを個別に最適化し、答えを合計できることを意味します。 

単一のチーム内では、最終的に 3 人全員が同意するように、最初に納得したメンバーの最小数が必要です。 0 人または 1 人のメンバーを説得した場合、チームは 2 人の説得メンバーのしきい値に到達しないため、プロセスは完了できません。 2 人のメンバーを説得すると、ルールがすぐに有効になり、3 人目が続きます。 したがって、最適なチームあたりのコストはちょうど 2 です。 

あるので$n/3$チームの場合、合計の答えは次のように決まります。$2 \cdot (n/3)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | チームごとの推論 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. チーム数を次のように計算します。$n // 3$。 これが機能するのは、入力が 3 で割り切れることが保証されているため、剰余処理が必要ないためです。 
2. 各チームについて、チームが確実に参加するために直接説得する必要がある最小人数を決定します。 チームは、最初に少なくとも 2 人のメンバーが選択された場合にのみアクティブになります。しきい値に達すると、3 人目が自動的に続くためです。 
3. チームごとにコスト 2 を割り当てます。これは、2 つ未満を選択するとアクティブ化をトリガーできず、2 つを選択すれば十分であるためです。 
4. チームの数に 2 を掛けて、最終的な答えを求めます。 

### なぜ効果があるのか

 各チームは独立して動作し、メンバー 3 人中 2 人という厳格なアクティブ化しきい値が設定されています。 チーム間の相互作用は存在しないため、グローバル戦略はチームごとの同一の決定に分解されます。 単一のトリプル内では、どのソリューションでも少なくとも 2 つのメンバーを選択する必要があります。 そうしないと、アクティブ化ルールが満たされなくなります。 すぐに完全な承認がトリガーされるため、正確に 2 つを選択するだけで十分です。 これにより、チームごとの最小値が固定され、すべてのチームにわたって加算されることが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    print(2 * (n // 3))

if __name__ == "__main__":
    solve()
```このソリューションは、単一の整数を読み取り、3 つの素なグループがいくつ存在するかを計算します。 各グループは、必要な直接選択を 2 つだけ提供するため、計算は直接乗算になります。 

この実装では、チーム間に対話が存在しないため、ループが完全に回避されます。 唯一の微妙な点は、整数除算が使用されていることを確認することです。

 ## 特殊なケース

 意味のある最小のケースは、$n = 3$、ちょうど 1 つのチームが存在します。 アルゴリズムはコスト 2 を割り当てます。これは、唯一のチームをアクティブ化するには少なくとも 2 人のメンバーを説得する必要があるという要件に一致します。 

で$n = 0$、制約に明示的に記載されていませんが、数式は依然として 0 を生成し、チームがないことと一致します。 

次のような大きな値では、$n = 99$、アルゴリズムは 33 チームを数え、66 人の確信メンバーを割り当てることによって線形にスケールします。 各チームは独立したままであるため、相互作用効果によってこの数値がさらに減少することはなく、計算された値は最適なままになります。
