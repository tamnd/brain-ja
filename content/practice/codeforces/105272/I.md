 ## 解決策
 ## 問題の理解

 長方形のグリッドが与えられ、各セルは空、壁、またはロボットの固有の開始位置のいずれかになります。 ロボットは、開始セルにエンコードされた初期方向から開始し、決定的な動作ルールを繰り返し適用します。 

各ステップで、ロボットはまず現在の方向に 1 つのセルを前進させようとします。 壁によって、またはグリッドの外側に出ることによってセルがブロックされている場合 (境界は壁として扱われるため)、セルは移動せず、反時計回りに 90 度回転して再試行します。 この回転と再試行は、有効な移動が見つかるまで継続され、有効な隣接セルが見つかると、そこに移動し、移動が成功した後も現在の方向を維持します。 

タスクは、このプロセスが無限に進化する間に、ロボットが少なくとも 1 回訪問する個別のグリッド セルの数を決定することです。 

グリッド サイズは最大 1000 x 1000 に達する可能性があり、これは最大 100 万個のセルを意味します。 制限のない方法で、またはメモ化せずに繰り返し再訪する方法で動きをシミュレートするソリューションは、制限時間を超える危険があります。 ステップにわたる直接シミュレーションは、関連する各構成が一定回数処理されることを保証できる場合にのみ許容されます。 

微妙な難しさは、ロボットがセル上を移動するだけではなく、位置と方向の両方から構成される状態上で移動することです。 これは、システムが異なる方向で同じセルを複数回再訪問する可能性があり、単純な「訪問セルのみ」の追跡では終了を検出するには不十分であることを意味します。 

一般的な失敗ケースは、ロボットが状態空間のサイクルに入ったにもかかわらず、以前に確認されたセルを訪問し続ける場合に発生します。 このような場合、早めに停止したり、方向を無視したりすると、誤ったカウントが発生します。 

たとえば、空のセルの小さなループ内で、ロボットは無限に循環する可能性があります。 

セルだけを追跡すると、プロセスが無限であると考えて間違って停止したり、同じループを繰り返し走査して過剰にカウントしたりする可能性があります。 

## アプローチ

 ブルートフォース解釈はロボットをステップバイステップで永遠にシミュレートし、ルールに従って位置と方向を更新し、訪問したすべてのセルを記録します。 プロセスは、以前に確認された構成に戻ると停止します。 構成は単なるセルではなく、セルと方向のペアです。 

システムは決定論的で有限であるため、このアプローチは正しいです。 考えられる状態は最大 4 × n × m であるため、最終的には状態が繰り返され、サイクルを意味します。 ただし、不用意に実装すると、完全な状態ではなく、訪問したセルのみが保存される可能性があり、正確性が損なわれます。 遷移をキャッシュせずに動きをシミュレートすると、別の非効率が生じます。 各ステップでは、最大 4 方向の繰り返しスキャンが必要になる場合があります。 

重要な観察は、各状態が 1 つの次の状態に正確に遷移するということです。 これにより、すべての (セル、方向) ペアにわたる有向関数グラフが形成されます。 初期状態からの移動は、サイクルに入るまで単一のパスに従います。 すべての状態は、反復の前に最大 1 回訪問されるため、状態空間を線形に横断するだけで十分です。 

繰り返しを検出するために訪問済みの状態のセットを維持し、一意の位置をカウントするために訪問済みのセルのセットを維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (再計算を伴う状態シミュレーション) | O(n m · k) | O(nm) | 遅すぎる |
 | 最適 (状態グラフのトラバーサル) | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態を行、列、方向の 3 つの要素としてモデル化します。 方向は整数としてエンコードされ、反時計回りに回転するとこれらの値が固定的に並べられます。 

## アルゴリズムのチュートリアル

1. グリッドを解析し、一意の開始セルを特定し、その初期方向も抽出します。 これにより、シミュレーションの初期状態が得られます。 
2. 状態から移行しようとする関数を定義します。 今のセルと方向性から、一歩前進してみます。 次のセルが無効であるか壁である場合は、反時計回りに回転して再試行します。 有効な手が見つかるまで、これを最大 4 回繰り返します。 これにより、少なくとも 1 つの方向が有効である必要があり、そうでない場合はすべてブロックされ、ローテーションが元に戻るため、終了が保証されます。 
3. 訪問した状態 (セル、方向) のブール配列またはハッシュ セットを維持します。 これは、関数グラフ内のサイクルを検出するために不可欠です。 
4. 訪問したセルの別のブール配列を維持します。 新しい状態に入るたびに、そのセルを訪問済みとしてマークします。 
5. 初期状態から繰り返し遷移関数を適用します。 結果の状態がすでに確認されている場合は、シミュレーションを停止します。 
6. 答えは、訪問済みとマークされた一意のセルの数です。 

### なぜ効果があるのか

 ロボットの動作は、有限の状態セットからロボット自身への決定論的な関数を定義します。 状態の数は有限であるため、繰り返し適用すると、最終的には状態を再訪し、サイクルを形成する必要があります。 サイクルに入る前に、各状態は 1 回だけ訪問されます。 すべての訪問は正確に 1 つのセルに対応するため、このプレフィックスを介して訪問セルをカウントすると正しい結果が得られます。 訪問済み状態チェックにより、それより早くも遅くもなく、繰り返しの開始時に正確に停止することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]

    # Directions: U, L, D, R (counterclockwise rotation order)
    dirs = ['U', 'L', 'D', 'R']
    dr = [-1, 0, 1, 0]
    dc = [0, -1, 0, 1]
    dir_idx = {d: i for i, d in enumerate(dirs)}

    # Find start
    sr = sc = sd = -1
    for i in range(n):
        for j in range(m):
            if grid[i][j] in "ULDR":
                sr, sc = i, j
                sd = dir_idx[grid[i][j]]
                grid[i][j] = '.'

    vis_state = [[[False] * 4 for _ in range(m)] for _ in range(n)]
    vis_cell = [[False] * m for _ in range(n)]

    r, c, d = sr, sc, sd
    vis_state[r][c][d] = True
    vis_cell[r][c] = True
    ans = 1

    def blocked(x, y):
        if x < 0 or x >= n or y < 0 or y >= m:
            return True
        return grid[x][y] == '#'

    while True:
        nd = d
        nr = r + dr[nd]
        nc = c + dc[nd]

        for _ in range(4):
            if not blocked(nr, nc):
                break
            nd = (nd + 1) % 4
            nr = r + dr[nd]
            nc = c + dc[nd]

        if vis_state[nr][nc][nd]:
            break

        r, c, d = nr, nc, nd

        if not vis_cell[r][c]:
            vis_cell[r][c] = True
            ans += 1

        vis_state[r][c][d] = True

    print(ans)

if __name__ == "__main__":
    solve()
```このコードはまず初期状態を特定し、次に順方向と反時計回りに最大 4 回回転することを確認して、次の有効な動きを繰り返し計算します。 の`blocked`ヘルパーは境界外を壁として扱い、他の場所での特別な境界ロジックを回避します。 

実装の重要な詳細は、方向を含む訪問した状態を保存することです。 指示がないと、ロボットは異なる方向でセルを再訪問し、誤って早期に終了したり、無限ループしたりする可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
2 2
.L
.#
```L を含むセルから開始して左に移動します。 そのセルからは左がブロックされているため、ロボットは反時計回りに回転し、有効な動きが見つかるまで下に、次に右に試行します。 この小さなグリッドでは、ロボットはすぐに拘束され、短いサイクルに入ります。 

| ステップ | ポジション | 方向 | 次のアクション | 訪問したセル |
 | --- | --- | --- | --- | --- |
 | 1 | (0,1) | Ｌ | 有効な移動になるまで回転 | {(0,1)} |
 | 2 | (1,1) | ... | サイクル | まで継続します。 成長してから安定します |

 トレースは、運動が続いているにもかかわらず、サイクルに入った後に新しい細胞が発見されていないことを示しています。 

### 例 2

 入力:```
4 4
#..#
#...
##.#
U..#
```ここでは、ロボットは最初はより自由度があり、繰り返しのパターンに強制される前に複数の廊下を探索します。 訪問されたセットは、状態の繰り返し点に達するまで着実に増加します。 

| ステップ | ポジション | 方向 | アクション | 新しい細胞？ |
 | --- | --- | --- | --- | --- |
 | 1 | 開始 | う | 移動 | はい |
 | 2 | ... | ... | 移動 | はい |
 | 3 | ... | ... | 移動 | いいえ |
 | 4 | サイクル開始 | ... | リピートが検出されました | 停止 |

 これにより、停止条件が位置の繰り返しではなく完全な状態の繰り返しに基づいていることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各状態 (セル、方向) は最大 1 回訪問され、遷移は一定時間です。 
| スペース | O(nm) | すべてのグリッド セルと方向にわたる訪問済みの州のストレージ |

 ## 特殊なケース

 重要なエッジケースは、ロボットがすぐに四方すべてを囲まれる場合です。 その状況では、試みられるすべての動きがブロックされ、ロボットは状態のサイクル内で効果的に所定の位置に留まる前に全方向に回転します。 このアルゴリズムは初期状態を記録し、同じセルで 4 つの方向の状態を循環した後に繰り返しを検出するため、これを正しく処理します。 

もう 1 つのエッジ ケースは、ロボットが長い通路に入り、最終的には前の位置に戻るが方向は異なる場合に発生します。 単純な訪問セルのアプローチでは、間違って停止したり、カウントを誤ったりする可能性があります。 状態ベースの追跡により、同じセルを別の方向に再訪問することが別個の構成として扱われることが保証され、真のサイクルに達するまで正確さが維持されます。
