 ## 解決策
 ## 問題の理解

 私たちには偶数の友人、たとえば 2n 人が与えられ、各友人はピザの味の好みを表す 1 つの整数値を持っています。 このグループはちょうど n 枚のピザを注文したいと考えており、各ピザは 2 人の異なる友人の好みに基づいて作らなければなりません。 各設定値は 1 回だけ使用する必要があります。これは、すべての 2n 個の数値を n 個のペアにペアにすることを意味します。 

各ペアは 1 つのピザを形成し、ピザのコストはそのペアの 2 つの値の最大値として定義されます。 目標は、これらの最大値の合計を最小化するペアリング戦略を選択することです。 

したがって、問題は、2n 個の数値を n 個のペアにペアにして、ペアごとの最大値の合計を最小化することに帰着します。 

この制約により、n は最大 100,000、つまり最大 200,000 個の数値が許可されます。 O(n log n) よりも悪い解決策は、遅すぎる危険性があります。 すべてのペアの組み合わせを試したり、サブセットに対して動的計画法を使用したりする 2 次ペアリング戦略は、実行可能な限界をはるかに超えるおよそ n² または 2^(2n) の動作を伴うため、直ちに不可能です。 

値のバランスが著しく崩れている場合、微妙な特殊なケースが発生します。 たとえば、ほとんどの値が小さく、1 つの値が非常に大きい場合、大きな値を誤って付加する単純な貪欲な組み合わせにより、合計コストが膨らむ可能性があります。 1 1 1 1 100 のような入力を考えてみましょう。ペアリングが不十分な場合、100 は間接的な貪欲スキームで複数のペアのコストを増加させる可能性がありますが、最適な構造では 1 つのペアにのみ分離されます。 

もう 1 つのエッジ ケースは、値がすでに並べ替えられているか、ほぼ同一である場合です。 このような場合、異なるペアリング戦略は局所的には同等に見えるかもしれませんが、グローバルな最適性を保証するのは 1 つの構造だけです。 

## アプローチ

 ブルートフォースのアイデアは単純です。2n 個の要素をペアにするすべての可能な方法を試し、各ペアの最大値の合計を計算します。 これは、配列のすべての有効なパーティションをペアに探索するため、正しいです。 ただし、ペアリングの数は (2n - 1)!! であり、n の指数関数よりも速く増加します。 n = 20 の場合でもこれは実行不可能になり、n = 100,000 になると完全に不可能になります。 

改善するために、ペアの最大値が合計にどのように寄与するか構造を探します。 各ペアは、2 つの要素のうち大きい方に寄与します。 配列をソートすると、どの要素が最大値になる可能性が高いかを制御できます。 重要な観察は、無駄な大きな値を最小限に抑えるために、「各大きな要素が 1 回だけ支払いを行い、不必要にさらに大きな要素とペアにならないように、大きな要素を慎重にペアリングする」必要があるということです。 

並べ替えると、最適な戦略は並べ替えられた順序で隣接する要素をペアにすることであることがわかります。 これにより、各ペア内で、残りの選択肢の中で大きい要素ができるだけ小さいことが保証されます。 隣接関係のペアリングをスキップしようとすると、後で大きな要素とさらに大きな要素がペアになり、合計が増加する危険があります。 

したがって、問題は、最後から 2 番目の要素ごとに並べ替えて合計することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((2n−1)!!) | O(n) | 遅すぎる |
 | 最適 (ソート + 貪欲なペアリング) | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、2n 値の配列を非降順で並べ替えます。 

1. すべての値を並べ替えます。 これにより、ローカルな隣接関係が値の近さを反映するグローバル構造が作成されます。これは、各ペアの最大値を最小限に抑えるために重要です。 
2. 最大値から下に向かって繰り返し、毎回 2 桁ずつステップを進めます。 つまり、インデックス 2n-1、2n-3、2n-5 などを取得します。 
3. これらの選択した要素を合計します。 これらのそれぞれは、ソート順で直前の要素で形成されたペアの最大値に対応します。 
4. 合計を出力します。 

ソート後のペアは暗黙的に次のようになります: (a[0], a[1])、(a[2], a[3])、...、(a[2n−2]、a[2n−1])。 最大値のみが重要であるため、明示的にペアを構築しません。 

### なぜ効果があるのか

並べ替えた後、最適な組み合わせを検討します。 最大の要素に焦点を当てます。 有効なソリューションでは、他の要素と組み合わせる必要があります。 コストの寄与を最小限に抑えるための最良のパートナーは、有効なペアを形成しながら、可能な限り小さい残りの最大の要素です。 それより小さいものと組み合わせてもコストは削減されません。これは、最大値自体が依然として最大の要素であるためです。 ただし、大きな要素をペアにすると、2 番目に大きな要素がわずかに小さな要素とペアになる場合に、別の最大値として無駄になることがなくなります。 この議論を帰納的に繰り返すと、ソートされた順序で連続する要素をペアにすると、各ペアの最大値が選択された「最後から 2 番目の要素」の 1 つになる配置が得られ、並べ替えを行わなくても合計をさらに減らすことができないことがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = 0
    for i in range(2 * n - 1, -1, -2):
        ans += a[i]
    
    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、n と 2n の値を読み取ることから始まります。 ソートは要素を整列させ、最適なペアリングがグローバルな検索問題ではなくローカルな決定となるため、ソートは不可欠です。 

ループは配列の最後から 2 つのステップで進み、各最適なペアの最大値として機能する要素を直接累積します。 最大値のみが最終的な答えに寄与するため、明示的にペアを構築することはありません。 

よくある実装上の間違いは、インデックスを誤って反復すること、特に n と 2n を混合したり、間違った境界で停止したりすることです。 正しい範囲はちょうど 2n 要素であり、ストライドは 2 である必要があります。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a = [5, 3, 4, 1, 2, 6]
```並べ替え後:```
[1, 2, 3, 4, 5, 6]
```隣接する要素をペアにします。 

(1,2)、(3,4)、(5,6)

 | ステップ | 選択されたインデックス | 値 | 累計額 |
 | --- | --- | --- | --- |
 | 1 | 5 | 6 | 6 |
 | 2 | 3 | 4 | 10 |
 | 3 | 1 | 2 | 12 |

 出力は12です。 

このトレースは、端から 2 つおきの要素を取得することで、各最適ペアの最大値が正しく取得されることを示しています。 

### 例 2

 入力:```
n = 2
a = [10, 1, 9, 2]
```並べ替え後:```
[1, 2, 9, 10]
```ペアは次のとおりです。 

(1,2)、(9,10)

 | ステップ | 選択されたインデックス | 値 | 累計額 |
 | --- | --- | --- | --- |
 | 1 | 3 | 10 | 10 |
 | 2 | 1 | 2 | 12 |

 出力は12です。 

これにより、大きな値が効率的に分離され、それぞれが 1 回だけ寄与することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、その後リニア スキャンが行われます。 
| スペース | O(1) から O(n) | インプレースソートと入力ストレージ |

 最大 200,000 要素の入力サイズにより、実行可能な唯一の重い操作はソートになります。 ソート後のリニアスキャンにより、ソリューションが制限時間内に確実に収まるようになります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        n = int(input().strip())
        a = list(map(int, input().split()))
        a.sort()
        ans = 0
        for i in range(2 * n - 1, -1, -2):
            ans += a[i]
        print(ans)

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

# sample-like cases
assert run("3\n5 3 4 1 2 6\n") == "12"
assert run("2\n10 1 9 2\n") == "12"

# minimum case
assert run("1\n5 1\n") == "5"

# all equal
assert run("3\n4 4 4 4 4 4\n") == "12"

# already sorted
assert run("2\n1 2 3 4\n") == "6"

# reverse sorted
assert run("2\n4 3 2 1\n") == "6"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 5 1 | 5 | 最小限のエッジケース |
 | すべて等しい | 12 | 対称性の正確さ |
 | ソート / 逆ソート | 6 | 注文時の安定性 |

 ## 特殊なケース

 すべての値が同一の場合、並べ替えによって意味のある構造の変更は生じません。 このアルゴリズムでは、引き続き隣接する要素をペアにし、最後から 2 番目の要素ごとに合計することで、正確に n 倍の同じ値が得られます。 入力 4 4 4 4 4 4 の場合、並べ替えられた配列は変更されず、合計は n = 3 の場合 12 になり、有効なペアと一致します。 

配列が 1 2 3 4 のようにすでに昇順にソートされている場合、アルゴリズムは (1,2) と (3,4) をペアにします。 最大値として 2 と 4 を選択することは、最後から 2 番目の要素ごとにステップ実行することと一致しており、(1,4) のようなクロス ペアリングは (2,3) を強制して合計を増加させるため、他のペアリングは合計を減らすことができません。 

4 3 2 1 など、値が逆ソートされている場合、ソートにより最初に構造が正規化されます。 同じロジックが適用され、並べ替え後のアルゴリズムも同様に動作するため、入力順序が正確さに影響を与えることはありません。
