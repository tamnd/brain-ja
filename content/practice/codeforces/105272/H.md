 ## 解決策
 ## 問題の理解

 私たちは、それぞれが次のいずれかに着色された小惑星の線形シーケンスを与えられています。`a`または`b`。 このシーケンスの連続するセグメントを選択して削除し、その端を接着してサイクルを形成することができます。 この操作の後、結果のサイクルを 2 つの連続する半分に分割し、半分には のみが含まれるようにします。`a`残りの半分には、`b`。 

目標は、選択したセグメントの長さを最大化することです。 同様に、「完全な 2 分割サイクル」に変換できる最長の部分文字列が必要です。その端を接続した後、結果として得られる円形文字列は 2 つの単色の半分に分割できます。 

循環条件が重要です。部分文字列を選択すると、その終端と開始の間の境界が隣接するため、有効な最終構造は、元の線形形式ではなく、その部分文字列の回転に依存します。 

制約`n ≤ 2 · 10^5`部分文字列の二次列挙を除外します。 すべての O(n^2) セグメントを試行するか、O(n) 内の各セグメントをチェックするソリューションは、制限を数桁超えます。 

単純な落とし穴は、等しい数だけが必要だと仮定することです。`a`そして`b`。 それは必要ですが十分ではありません。 例えば、`abbaab`カウントは等しいですが、回転しないと純粋な 2 つの半分に分割されます。 

もう 1 つの微妙な問題は、最良のセグメントが常にプレフィックスまたはサフィックスを除いた文字列全体であると考えることです。 反例は、最適なセグメントが厳密に内部にある場合に存在します。 

## アプローチ

 ブルートフォース手法では、すべての部分文字列が列挙されます。`[l, r]`、円形にすることをシミュレートし、回転によって 2 つの均等な半分に分割されるかどうかをテストします。 部分文字列ごとに、すべての回転を試すか、少なくとも分割点を検証する必要があり、コストは O(長さ) です。 O(n^2) 個の部分文字列があり、各チェックは O(n) であるため、最悪の場合は O(n^3) になります。 O(n^2) に最適化したとしても、2 · 10^5 ではまだ遅すぎます。 

重要な観察は、部分文字列を固定すると、「回転後に 2 つの単色の半分に分割できる」という条件が非常に制限されるということです。 回転後、文字列は同じ文字の 2 つの連続したブロックになります。 つまり、循環文字列は正確に 2 つの実行で構成されている必要があります。`a`そしてそのうちの1つ`b`、両方の実行はサイクル内で連続した間隔である必要があります。 

これは、選択された部分文字列では、文字間のすべての遷移が循環的な意味で最大 1 か所に集中する必要があることを意味します。 線形ビューでは、遷移境界にカットを最適に配置した場合、部分文字列は最大 2 つのブロックを持つことができることを意味します。 

したがって、問題は、線形順序で同じ文字のランが最大 2 つ含まれる最長の部分文字列を見つけることになります。これは、ラン間の境界がカットになるようにサブストリングを回転できるためです。 

ただし、両方の文字が表示されることも確認する必要があります。そうしないと、サイズ 0 を許可しない限り、空ではない 2 つの単色の半分に分割することは不可能になります。 

これは自然に、ランまたはキャラクター上のスライディング ウィンドウに縮小され、最大 2 つの連続したブロックを持つウィンドウを維持します。 

右ポインタを拡大し、文字間の遷移を追跡し、2 ブロックを超えると縮小します。 有効なウィンドウの最大長が答えです。

 ## アルゴリズムのチュートリアル

 文字列は同一の文字の連続で構成されているものとして扱います。 引き違い窓を維持しております`[l, r]`文字列を調べて、その中に存在する文字ブロックの数を追跡します。 

1. 2 つのポインタを初期化する`l = 0`、ウィンドウ内のトランジションの数を追跡します。 遷移が発生するのは、`s[i] != s[i-1]`。 現在のウィンドウ内の遷移の数を維持します。 
2. 展開する`r`左から右へ。 延長するたびに`r`かどうかを確認します。`s[r] != s[r-1]`。 そうであれば、遷移カウントをインクリメントします。 これは、新しい文字ブロックを入力することを表します。 
3. トランジションの数が 1 を超える場合、ウィンドウには少なくとも 3 つのブロックが含まれることになり、正確に 2 つのモノクロの半分に回転させることはできません。 ウィンドウが再び有効になるまで、左側から縮小する必要があります。 
4. 縮小するには、移動します`l`2 つの異なる文字間の境界を削除するときに、前方およびデクリメントのトランジション カウントを実行します。 具体的に言うと、`s[l] != s[l+1]`、トランジションを削除し、カウントを減らします。 
5. 有効性を復元した後、次のように回答を更新します。`r - l + 1`。 

これが問題と一致する理由: 有効な円形分割は、回転可能なセグメントを選択することに相当するため、境界が 1 つだけになるようになります。`a`そして`b`が分岐点です。 これは、部分文字列に、最適なカット配置後の線形形式の文字間の交互が最大 1 つ含まれている場合にのみ可能であり、これは最大 2 つの実行に相当します。 

### なぜ効果があるのか

 不変条件は、現在のウィンドウには、回転後に重要となる遷移点が常に 1 つだけ含まれるということです。 ウィンドウに 2 つのトランジションがある場合、どのように回転させても、円内に少なくとも 3 つの交互のブロックが存在することになり、2 つの単色の半分に分割することは不可能になります。 逆に、最大 1 つのトランジションを持つウィンドウを回転して、カットがそのトランジションに正確に配置され、2 つの均一な半分が生成されるようにすることができます。 この等価性により、すべての最大有効ウィンドウが有効な構造に対応することが保証されるため、スライディング ウィンドウの最大値が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    l = 0
    transitions = 0
    ans = 0

    for r in range(n):
        if r > 0 and s[r] != s[r - 1]:
            transitions += 1

        while transitions > 1:
            if l + 1 <= r and s[l] != s[l + 1]:
                transitions -= 1
            l += 1

        ans = max(ans, r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは単一のウィンドウを保持し、その中の文字の変更のみをカウントします。 微妙な点は、トランジションは隣接する文字間でのみカウントされ、左ポインタがそのような境界を通過した場合にのみ削除されることです。 これにより、構造を最初から再計算しなくても正確さが保証されます。

 入力用`aaaaa`、アルゴリズムは遷移を認識しないため、ウィンドウはから完全に拡張されます。`0`に`n-1`。 答えは次のようになります`5`これは、セグメント全体を簡単に回転できるという事実と一致します。 

入力用`abab`、トランジションはすぐに蓄積されます。 で`r = 2`、3 回目のブロック試行では、左ポインタが強制的に進められ、サイズ 2 の有効なウィンドウのみが保持されます。アルゴリズムでは複数の変更が許可されないため、答えは次の値で安定します。`2`、これは回転を生成することに対応します。`aa|bb`または`bb|aa`カットにもよりますが。
