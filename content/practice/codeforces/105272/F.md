 ## 解決策
 ## 問題の理解

 私たちは、参加者全員がちょうど 1 枚のチケットを購入した単一のフェスティバルを観察しています。 チケットには 2 種類あります。通常料金のチケットです。`v`そしてそのちょうど半分の割引価格の月のチケット、`v/2`、 どこ`v`均等であることが保証されています。 

参加者の総数が表示されます`p`、集められた総収益`a`、チケットの全額`v`。 参加者の数は不明ですが、月の住人は常に割引価格を支払いますが、他の参加者は全額を支払います。 タスクは、次の数を決定することです。`p`参加者は割引チケットを購入しました。 

制約は大きいですが、構造は非常に単純です。すべての値は最大 100 万であり、算術関係のみが重要です。 これにより、個人に対するシミュレーションや、最大で反復することに依存する単純な方法での可能なカウントの検索が即座に除外されます。`p`または`a`。 正しい解決策は、問題を方程式から導出される定数時間の計算に帰着させる必要があります。 

方程式を立てずに貪欲に推論しようとすると、微妙な失敗例が出てきます。 たとえば、割引参加者の最大化が常に有効であると仮定すると、総収益の制約との一貫性が崩れる可能性があります。 もう 1 つのよくある間違いは、割引がちょうど半額であることを忘れることです。`v`、任意の分数ではなく、きれいな線形関係を形成するために不可欠です。 

## アプローチ

 強引な解釈では、考えられるすべての数値が試行されます。`x`からの月の参加者の数`0`に`p`、結果として生じる収益を計算し、それが一致するかどうかを確認します。`a`。 これは、各候補者が収益を完全に決定するため機能しますが、コストがかかります`O(p)`テストケースごとに。 と`p`100 万までは、これは単独でも実行可能ですが、関係が線形で直接解決できることを考えると、不必要で概念的に非効率的になります。 

重要な観察は、総収益が未知の変数の一次関数として表現できることです。`x`。 もし`x`参加者は半額を支払い、`p - x`全額を支払った場合、収益は完全に次のように決定されます。`x`。 これにより、問題は 1 つの変数で 1 つの線形方程式を解くように変換されます。 この方程式を整理すると、反復することなく直接答えが得られます。 

問題の構造により、結果の値が整数で負でないことが保証されているため、追加の検索や丸めロジックは必要ありません。

 ## アルゴリズムのチュートリアル

 1. まず次のように仮定します。`x`人々はお金を払う月の参加者です`v/2`、残りは`p - x`支払う`v`。 

これは、システム内の唯一の未知のものを直接エンコードします。 
2. 総収益を寄付金の合計として表現します。`a = x * (v/2) + (p - x) * v`。 

このステップでは、ストーリーを決定論的な方程式に変換します。 
3. 式を展開します。`a = x*v/2 + p*v - x*v`。 
4. 関係するグループ用語`x`:`a = p*v - x*(v/2)`。 
5. 並べ替えて分離する`x`:`x*(v/2) = p*v - a`。 
6. を解く`x`:`x = (2 * (p*v - a)) / v`。 

2 を掛けると分数の除算が回避されます。`v`は均等です。 
7. 戻る`x`月の参加者の数として。 

### なぜ効果があるのか

 収益関数は次のように線形です。`x`つまり、月の参加者が増えるたびに、正規料金のチケットが半額のチケットに置き換えられ、収益がちょうど 0.5 減少することになります。`v/2`。 割引なしのベースライン収益は`p*v`、 違い`p*v - a`割引された参加者によって引き起こされる合計削減額を測定します。 この総削減量を で割ると、`v/2`は、そのような削減が発生した正確な数を示します。これは、次のように一意に対応します。`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, p, v = map(int, input().split())
    # derived formula: x = 2*(p*v - a) / v
    x = (2 * (p * v - a)) // v
    print(x)

if __name__ == "__main__":
    solve()
```実装では、派生した式を直接エンコードします。 掛け算`p * v`これは Python の整数の範囲内に安全に収まります。 この問題では結果が整数であることが保証されているため、最後に整数の除算が使用されます。 

よくある実装上の間違いは、浮動小数点除算を導入する方法で数式を再配置することですが、これは不必要であり、他の言語では精度の問題を引き起こす可能性があります。 もう 1 つの間違いは、2 で割る前に 2 を掛けるのを忘れたことです。`v`、割引は正規価格のちょうど半分であるため、正確性が失われます。

 ## 特殊なケース

 参加者全員が全額を支払った場合、収益は次のとおりです。`p * v`。 式に代入すると、次のようになります。`x = 0`これは、割引チケットが使用されなかったことを正しく反映しています。
