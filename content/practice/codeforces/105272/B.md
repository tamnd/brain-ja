 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが順番に数字を書きます。 まず相手が整数を発表します`n`。 それを見た後、独自の整数を選択します`m`。 より大きな数字を書いた人がすぐに勝ちます。 

目標は、何が起こっても常に勝利を保証することです`n`つまり、選択した数値は次の範囲内になければならないという制約を尊重します。`0`そして`100000`。 

これにより、問題は固定された上限の下で行われる単純な決定に変わります。 複数のラウンドにわたって動的に反応したり、データ構造を維持したりしようとしているのではなく、1 つの入力を観察した後に 1 つの値を選択しています。 

制約`1 ≤ n ≤ 100`重要です。 これは、対戦相手の数値が、最大許容値と比較して常に非常に小さいことを示しています。`m`。 これはすでに、ケースごとに慎重に比較または適応しようとする戦略は不要であることを示唆しています。`m`相手が生み出すことができるものよりもはるかに大きい。 

単純な間違いは、次のようなものを計算することです。`m = n + 1`。 これは、このタイプのほとんどの競技プログラミング問題で機能しますが、ここでは必須ではなく、厳密なアドバンテージマージンを保証するという点では最適ではありません。 さらに重要なのは、不注意な実装は依然として範囲内にとどまる可能性がありますが、次のような亜種では失敗する可能性があります。`n`に近いかもしれない`100000`。 

たとえば、ルールが異なる場合は次のようになります。 

入力:```
100000
```それから`m = n + 1`限界を超えてしまうだろう。 この問題では安全ですが、この制約により、より単純な定数解が可能になります。 

## アプローチ

 強引な解釈では、可能なすべての値を試してみることになります。`m`から`0`に`100000`より厳密に大きいものを選択してください`n`。 これは正しいです。なぜなら、すべての候補者のルールを直接シミュレートし、それが勝つかどうかをチェックしているからです。 費用はせいぜい`100001`これは、多くのテスト ケースでも簡単です。 

ただし、問題の構造は単一の比較を超える相互作用に依存しないため、このアプローチは不要です。 勝利に左右されるのは、厳密に次のレベルよりも優れていることだけであることに気付いたら、`n`、もう検索する必要はありません。 

重要な点は、許容される最大の数が必要であるということです。 以来`100000`は出力できる最大値であり、それが勝利を保証するかどうかを確認します。 なぜなら`n ≤ 100`、それは常に当てはまります`100000 > n`したがって、あらゆる場合において、可能な最大の選択肢がすでに勝利条件を満たしています。 

これにより、問題は一定時間の決定に帰着します。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`入力から。 相手の固定数を表します。 
2. 私たちの番号を認識してください`m`2 つの条件を同時に満たさなければなりません: 以内でなければなりません`[0, 100000]`、そしてそれは厳密により大きくなければなりません`n`。 
3. 可能な最大の候補が`100000`という制約のもとでは有効です。 
4. 暗黙的に比較します。`n ≤ 100`、不等式`100000 > n`常に保持されます。 
5. 出力`100000`それは有効であり、勝つことが保証されているためです。 

### なぜ効果があるのか

 このアルゴリズムは問題の単調構造に依存しています。つまり、より大きな数は常に、より小さな数よりも優先されます。 許容範囲内で可能な最大値を選択することができ、対戦相手の値はその値をはるかに下回って厳密に制限されるため、最大値が常に優勢な戦略となります。 より小さい選択肢が優れたパフォーマンスを発揮する構成はありません`100000`、勝利は厳密に次よりも大きいことのみに依存するため、`n`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    print(100000)

if __name__ == "__main__":
    solve()
```ソリューションは単一の入力値を読み取り、すぐに出力します。`100000`。 制約があるため分岐はありません。`n`この値が常にそれを上回ることを保証します。 この実装では、不必要な比較や演算が回避され、ロジックが最小限かつ堅牢に保たれます。
