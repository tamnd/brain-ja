 ## 解決策
 ## 問題の理解

 2 つの水平レイヤーの点が与えられます。 1 つのレイヤーが線上にあります$y=0$、もう一方は上にあります$y=2$。 各レイヤーには個別の x 座標が含まれています。 移動は、単一線上にない残りの 3 つの点を選択し、それらが形成する三角形の面積を取得してから、それらの点を永久に削除することで構成されます。 

各レイヤー内のすべてのポイントは同じ y 値を共有するため、両方のレイヤーからポイントを選択した場合にのみ、トリプルは非縮退になります。 1 つの行内で完全に形成される三角形は常に同一直線上にあり、何も寄与しないため、有効な演算はすべて 2 つの行の点を混合する必要があります。 

タスクは、そのような操作の最大数を見つけるだけでなく、考えられるすべての操作数についても見つけることです。$k$、正確に実行する必要がある場合に、達成可能な最良の総面積を計算します。$k$より小さい値とは無関係に動作します。 

制約は大きく、最大で$2\cdot 10^5$全体的なテストごとのポイント。 演算をシミュレートしたり、トリプルを直接検査しようとするソリューションは、トリプルの数が 3 次であるため、すぐに失敗します。 テストごとにソートベースの二次推論を行ったとしても、すべてのケースで依然として遅すぎるでしょう。 解決策は、問題を、注文から導き出される少数の集合数量に縮小する必要があります。 

微妙な特殊ケースは、行の 1 つが非常に小さい場合です。 たとえば、次の場合$n=1, m=1$、合計 2 つの点しかないため、三角形は存在せず、答えは次のようになります。$k_{\max}=0$。 もう 1 つのケースは、1 つの行にちょうど 2 つの点がある場合です。その場合、すべての三角形は両方を使用する必要があり、各操作で 1 つの行からちょうど 2 つの点、もう一方の行から 1 つの点が消費されるという厳格な構造に強制されます。 

「常に最も左と右の点を取得する」などの単純な貪欲な戦略は失敗する可能性があります。これは、三角形の寄与が個々の極値だけでなく、操作全体のペア構造に依存するためです。 最適な配置は、グローバルな順序付けとペアリングの一貫性に依存します。 

## アプローチ

 ブルート フォース パースペクティブでは、操作のシミュレーションが試行されます。各ステップで、点のトリプルをすべて試し、面積を計算し、最適なトリプルを削除し、これを繰り返します。 メモ化を行っても、状態空間の点数は指数関数的であり、各ステップでスキャンが必要になります。$O(n^3)$候補者たち。 これは、小さな入力を超えるとすぐに失敗します。 

重要な観察は幾何学的構造です。 すべての点は 2 本の平行な水平線上にあるため、有効な三角形の面積は大幅に単純化されます。 一方の線から 2 点を選択し、もう一方の線から 1 点を選択すると、面積は同じ行にある 2 つの点間の水平距離に比例します。 垂直の高さは 2 に固定されているため、面積は基本的に x 座標の差に定数を乗算したものになります。 

これにより、問題がジオメトリからソートされた配列のペアリングの問題に変換されます。 各操作は、一方の行の 2 つの点をもう一方の行の 1 点と効果的に照合し、合計スコアは選択されたペアごとの距離の合計になります。 構造はさらに縮小されます。最適解は常に極値点をペアにします。 

ここで問題は、操作ごとに各側から何点を取るかを決定することになります。 各演算は 3 つの点を消費するため、演算の合計数は、各三角形が反対側の行から少なくとも 1 つの点を使用する必要があるという制約の下で形成できるトリプルの数によって制限されます。 これにより、単純なカウント限界が得られます。$$k_{\max} = \min\left(\frac{n+m}{3}, n, m\right)$$しかし、実際の構造はもう少し強力です。最適な構成では、各操作で 1 つの行の 2 つの点と、もう 1 つの行の 1 つの点を使用する必要があります。 

面積を最大化するには、一定の範囲内で$k$、ソートされた配列の貪欲なペアリングで可能な最大のペアワイズ距離を選択したいと考えています。 これは古典的な「極端な組み合わせ」マッチングになります。両方の配列をソートし、両端から最適なペアを選択するシミュレーションを行います。 追加の各操作の限界寄与は段階的に導き出すことができます。 

それぞれを最初から再計算するのではなく、$k$では、寄与度を降順で構築します。つまり、最適な最初の操作では利用可能な最大のスパンが使用され、次の操作では次に最適な残りの構成が使用されます。 これにより、単調なゲインのシーケンスが生成され、プレフィックスの合計がすべてのゲインを生成できるようになります。$f(k)$。

 ## アルゴリズムのチュートリアル

 1. 両方の配列をソートします$a$そして$b$。 最適な三角形は常に任意の順序ではなく極端な座標のギャップに依存するため、ソートは不可欠です。 
2. ペアリングの極値の絶対寄与を事前計算します。 唯一有用な構造は、垂直方向の距離が固定されているため、同じ行上で選択した点間の距離です。 これにより、各三角形が重み付けされた水平スパンに縮小されます。 
3. 配列ごとに 2 つのポインターを維持します。1 つは左端に、もう 1 つは右端にあります。 すべてのステップで、どちらかの配列から残りの最大のスパンを、反対側の行のポイントと組み合わせて取得することを検討してください。 
4. 各操作は 2 つの候補構造から選択します。次の 2 つの極点を使用します。$a$そしてからの1つ$b$、または 2 つから$b$そしてからの1つ$a$。 私たちは常に、より大きな即時ゲインが得られる構成を選択します。 
5. 構成を選択した後、使用したポイントを削除し、ポインターを更新します。 これにより、将来の選択が常に残りの極限構造に作用することが保証されます。 
6. 各操作のゲインをリストに記録します。 各ステップでは常に極端な値が除去されるため、一連のゲインは増加しません。 
7. ゲイン配列に対してプレフィックスの合計を計算して取得します。$f(1), f(2), \ldots, f(k_{\max})$。 

### なぜ効果があるのか

 重要な不変条件は、ソート後、合計スコアを下げることなく、各操作が現在の極値点のみを使用するように、最適な三角形分解を再配置できることです。 面積は水平方向の差のみに依存するため、使用可能なスパンを減らすことなく内部の点を外側に交換できます。 この交換議論により、貪欲な極端なペアリングに注意を制限しても最適性が失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, a, b):
    a.sort()
    b.sort()

    # total number of operations is bounded by triples
    kmax = min((n + m) // 3, n, m)

    # We will construct gains greedily from extremes
    i, j = 0, 0
    i2, j2 = n - 1, m - 1

    gains = []

    # We simulate taking kmax operations
    for _ in range(kmax):
        if i2 - i + 1 < 2 and j2 - j + 1 < 2:
            break

        # option 1: take 2 from a, 1 from b
        gain_a = 0
        if i2 - i + 1 >= 2 and j <= j2:
            gain_a = (a[i2] - a[i]) * 2

        # option 2: take 2 from b, 1 from a
        gain_b = 0
        if j2 - j + 1 >= 2 and i <= i2:
            gain_b = (b[j2] - b[j]) * 2

        if gain_a >= gain_b:
            gains.append(gain_a)
            i += 1
            i2 -= 1
        else:
            gains.append(gain_b)
            j += 1
            j2 -= 1

    # prefix sums
    for k in range(1, len(gains)):
        gains[k] += gains[k - 1]

    return len(gains), gains

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        kmax, vals = solve_case(n, m, a, b)
        out.append(str(kmax))
        if kmax > 0:
            out.append(" ".join(map(str, vals)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションでは、まず両方のレイヤーを並べ替えて、極端なペアが最大の水平スパンに対応するようにします。 2 つのポインターの境界は、未使用のポイントを追跡します。 各ステップで、現在の幅に基づいて、上の行と下の行のどちらから 2 ポイントを費やした方がより大きな貢献が得られるかを比較します。 係数 2 は、固定された垂直高さ 2 に由来し、面積をスケールされた x 座標の差に変換します。 

プレフィックスの累積により、操作ごとのゲインがすべての正確なカウントの答えに変換されます。$f(k)$最初の合計です$k$最適な動きを選択します。

 ## 特殊なケース

 たとえば一辺が非常に小さい場合$n=1, m=3$の場合、アルゴリズムはその側に同じ行の極値の有効なペアが存在しないことをすぐに検出するため、三角形を形成できなくなるまで常に他の行を選択します。 ゲイン リストは自然に早期に切り捨てられ、$k_{\max}=0$。 

両方の配列がゼロの周りで完全に対称である場合、極端な差は両側で等しくなります。 どの選択をしても最適な合計スパンが維持されるため、タイブレーク ルールは無関係になります。 プレフィックスの合計は、ブランチの選択に関係なく一貫したままになります。 

ポイントが 1 つの行に密集し、もう 1 つの行に広く分散している場合、アルゴリズムは一貫して広い行を最初に優先します。 ゲイン間の比較はローカルであり、将来の構造に依存しないため、使い果たされると他の行にスムーズに移行します。
