 ## 解決策
 ## 問題の理解

 配列とターゲットセグメントが与えられます$[l, r]$。 このセグメント内の要素の合計を計算しますが、測定する前にグローバル操作を 1 つだけ実行することができます。 

この演算は部分配列の標準的な反転ではありません。 代わりに、任意のインデックスのセットを昇順で選択し、それらのインデックスに配置された値をそれらの間で反転します。 言い換えれば、値のサブシーケンスを取得し、他のすべてを固定したままにして、選択した値のみをその順序を逆にして並べ替えます。 

目標は、固定セグメント内に収まる値の合計を最小限に抑えることです。$[l, r]$この単一のサブシーケンスの反転の後。 

重要な点は、連続スワップに限定されないということです。 選択したサブシーケンスに両方のインデックスを選択する限り、セグメントの外側の任意の位置はセグメント内の任意の位置と相互作用できます。 

この制約により、私たちは組み合わせた探求から遠ざかってしまいます。 と$n \le 10^5$テストごとのサイズと合計サイズも$10^5$、任意の二次関数または偶数$O(n \log n)$テストごとのソリューションは単純な場合にのみ許容されますが、サブセットの列挙や間隔 DP を含むものは直ちに不可能になります。 

セグメント内のすべての値が残りの値と比較してすでに最小または最大になっている場合、微妙なエッジ ケースが発生します。 素朴な貪欲スワップ アプローチでは、セグメントを繰り返し改善しようとする可能性がありますが、この操作はグローバルで使い捨てであるため、直感を過度に更新すると失敗します。 もう 1 つのエッジケースは次のような場合です$l = r$、ここでは単一の要素を最小化しています。 ここでの操作は、ペアリングを介してその要素を外部の何かで置き換えることができるかどうかを選択することに退化します。 

## アプローチ

 ブルートフォース解釈では、考えられるすべてのサブシーケンスをシミュレートしようとします。 インデックスのサブセットを選択し、その値を逆にして、セグメントの合計を再計算します。 サブセットサイズを固定しても$k$、インデックスの選択は$\binom{n}{k}$、そしてすべてを合計すると$k$指数関数的です。 これはたとえであってもすぐに爆発します$n = 40$、したがって、概念的な正しさを超える意味はありません。 

重要な構造的洞察は、順列の観点から考えるのをやめ、代わりにペアの観点から考えることです。 

サブシーケンスを反転すると、非常に具体的なことが行われます。つまり、選択したセット内に素のインデックスのペアが作成され、各ペアの値が交換されます。 インデックスがペアになっていない場合、インデックスは変更されないままになります。 したがって、この操作は、位置間の素のスワップを選択することと同じです。 

ここでは、セグメントの合計がどのように変化するかのみに注目してください。 境界を越えるスワップのみ$[l, r]$案件。 両方の内側または両方の外側の 2 つの位置を交換しても、セグメントの合計は変わりません。 内側と外側を交換すると、事実上、セグメント内の値が外側の値に置き換えられます。 

したがって、問題は次のようになります。$(r-l+1)$セグメント内の要素を外部の要素と照合し、セグメントの値を外部の値に置き換えます。ただし、制約があります。各外部要素は最大 1 回使用でき、スワップごとに内部インデックスと外部インデックスが 1 つずつ消費されます。 

合計を最小化するには、セグメント内の最大値を外側の最小値に置き換えます。 これは、候補を並べ替えることを示唆しています。すべてのセグメント値とすべての外側の値を取得し、合計が改善されるたびに、セグメント内の大きい値と外側の小さい値を貪欲に一致させます。 

それぞれの有益なスワップは合計に対して独立しているため、この貪欲なペアリングを超える完全なマッチング構造は必要ありません。

 ## アルゴリズムのチュートリアル

 1. 配列を 2 つのマルチセットに分割します: 内部の値$[l, r]$そしてその外側の価値観。 セグメントの合計は内部セットから計算されます。 
2. 内部の値を降順に並べ替えて、最大の要素を最初に検討できるようにします。 小さいものを交換しても、大きいものを交換するよりも合計が効率的に改善されることはないため、これらは交換する価値がある唯一のものです。 
3. 外側の値を昇順に並べ替えて、使用可能な最小の置換を最初に検討できるようにします。 これらは、セグメントに組み込むのに最適な候補者です。 
4. 両方のリストを同時に繰り返します。 残っている最大の内部値と最小の残りの外部値を組み合わせてみてください。 
5. 外側の値が内側の値よりも厳密に小さい場合にのみ、スワップを実行します。 この条件により、セグメントの合計が確実に減少します。 それ以外の場合、スワップは有害または中立であるため、使用すべきではありません。 
6. ペアリングが成功するたびに、内側の値と外側の値の差分だけセグメントの合計が減り、両方のポインタが進みます。 
7. いずれかのリストが使い尽くされるか、それ以上の改善が不可能な場合は停止します。 

最終的な答えは、元のセグメントの合計から、成功したスワップによって得られたすべての改善を差し引いたものになります。 

### なぜ効果があるのか

 この操作では、サブシーケンスの反転を通じて任意のペアを作成できるため、セグメントに対するすべての効果的な変更は、内部インデックスと外部インデックスの間で値を交換することと同等になります。 各要素は最大でも 1 つのスワップに参加するため、問題は独立した有益な交換を選択することになります。 

すべてのスワップは総和の変化に対する寄与が独立しているため、貪欲な戦略は正しいです。つまり、スワップは常に一定の差分だけ和を変更します。 利用可能な最大のゲインと利用可能な最小のコストを組み合わせることで、将来のより良い選択肢が妨げられることはありません。これは、より小さな外部値の代わりにより大きな外部値を使用すると、厳密には結果が悪化するか改善されないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = list(map(int, input().split()))
        
        l -= 1
        r -= 1
        
        inside = a[l:r+1]
        outside = a[:l] + a[r+1:]
        
        inside.sort(reverse=True)
        outside.sort()
        
        base = sum(inside)
        
        i = 0
        j = 0
        
        while i < len(inside) and j < len(outside):
            if outside[j] < inside[i]:
                base += outside[j] - inside[i]
                i += 1
                j += 1
            else:
                break
        
        print(base)

if __name__ == "__main__":
    solve()
```この実装では、配列が内側と外側のセグメントにきれいに分離され、位置ではなく値のみを考慮することが保証されます。 両方のグループをソートすることは、ペアリングの決定を単調なプロセスに変えるため、不可欠です。 

微妙な点は、スワップ条件が厳密に不平等であることです。 等価性を許可しても合計は改善されず、有用な要素が誤って消費される可能性があります。 

もう 1 つの重要な点は、配列を再構築する必要がないことです。 サブシーケンス反転操作はペアリング容量を超えて位置制約を保持しないため、マルチセット構造のみが重要になります。 

## 実用的な例

 次のような単純なケースを考えてみましょう。$a = [1, 2, 3]$そして$[l, r] = [2, 3]$。 

中には$[2, 3]$、外側は$[1]$。 仕分けは内部に与える$[3, 2]$、 外$[1]$。 

| ステップ | 内部 | 外側 | アクション | セグメント合計 |
 | --- | --- | --- | --- | --- |
 | 初期化 | [3、2] | [1] | なし | 5 |
 | 1 | [3、2] | [1] | 3 を 1 と交換する | 3 |

 アルゴリズムは 1 つの有益なスワップを実行し、3 を 1 に置き換え、合計を 5 から 3 に減らします。外部要素が 1 つだけ存在するため、これは最適な構成と一致します。 

ここで考えてみましょう$a = [5, 1, 4, 2]$と$[l, r] = [2, 3]$。 

中には$[1, 4]$、外側は$[5, 2]$。 仕分けは内部に与える$[4, 1]$、 外$[2, 5]$。 

| ステップ | 内部 | 外側 | アクション | セグメント合計 |
 | --- | --- | --- | --- | --- |
 | 初期化 | [4,1] | [2、5] | なし | 5 |
 | 1 | [4, 1] | [2、5] | 4 と 2 を交換 | 3 |
 | 停止 | [1] | [5] | 2 ≥ 1 スワップなし | 3 |

 このトレースは、貪欲な停止が必要な理由を示しています。利用可能な最適な外部候補が現在の内部値よりも小さくならないと、それ以上の改善は不可能です。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

                s += outside[j] - inside[i]
                i += 1
                j += 1

        out.append(str(s))

 ## 特殊なケース

 セグメントが単一の要素である場合、アルゴリズムは、外側の値が小さいかどうかをチェックすることになります。 並べ替えロジックは引き続き機能しますが、内部候補は 1 つしか存在しないため、置換できるのは最大 1 つだけです。 トレースは些細なものであり、直感と一致します。 

すべての要素が等しい場合、並べ替えにより同一のリストが生成されます。 スワップ条件はすぐに失敗するため、変更は適用されず、元の合計が返されます。均一な値を改善できる操作はないため、これは正しいことです。 

セグメントが境界にある場合、次のようになります。$l = 1$または$r = n$、リストの 1 つが空になります。 アルゴリズムは当然のことながらゼロ スワップを実行し、交換する外部マテリアルがないため、答えはセグメントの合計のままになります。
