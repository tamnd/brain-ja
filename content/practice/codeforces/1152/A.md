 ## 解決策
 ## 問題の理解

 宝箱のコレクションと鍵のコレクションが与えられます。 各チェストには番号が書かれており、各キーにも番号が書かれています。 鍵は、その数字の合計が奇数の場合にのみ宝箱を開けることができます。 鍵は一度使用すると消え、各宝箱は最大 1 回まで開けることができます。 

タスクは、パリティ条件が満たされ、成功したペアの数ができるだけ多くなるように、キーとチェストをペアにすることです。 

重要な観察は、パリティのみが重要であるということです。 実際の値は、偶数か奇数か以外は無関係です。 したがって、すべてのチェストとキーは、偶数または奇数の 2 つのグループに分類できます。 

制約$n, m \le 10^5$つまり、すべてのチェストキーの組み合わせを試みる二次ペアリング戦略は失敗します。 ソリューションは周波数またはカウントを線形時間で処理する必要があります。$O(nm)$の順序です$10^{10}$操作。 

パリティ グループの 1 つが空の場合、微妙なエッジ ケースが発生します。 たとえば、すべてのチェストが均等で、すべてのキーが均等である場合、ペアリングはまったく不可能です。 同様に、すべてのチェストが奇数で、すべてのキーが奇数の場合も、ペアリングはできません。 パリティ分離を無視して任意のマッチングを試みる単純な実装では、明示的にチェックしない限り、一部のマッチングが存在すると誤って想定されます。 

## アプローチ

 ブルートフォースソリューションでは、すべてのチェストキーのペアを試し、その合計が奇数かどうかを確認します。 有効で両方が未使用の場合は、貪欲に一致させます。 有効な各ペアリングは独立しているため、これは正しいですが、遅すぎます。 まで$10^5$各リスト内の要素は、最大で次のようになります。$10^{10}$チェックですが、それは不可能です。 

重要な単純化は、「合計が奇数である」という条件が「一方が偶数で他方が奇数である」と同等であると認識することから生まれます。 これにより、問題は 2 つのグループ (偶数と奇数) 間の 2 部マッチングに変わります。 ただし、各グループ内に追加の構造がないため、実際のグラフ マッチング アルゴリズムは必要ありません。 偶数のチェストは奇数のキーと組み合わせることができ、その逆も同様であるため、重要なのはカウントだけです。 

したがって、問題は、両方の配列に存在する偶数と奇数の値の数をカウントし、貪欲にペアリングすることになります。つまり、偶数の各チェストは奇数のキーと一致し、各奇数のチェストは偶数のキーと一致する可能性があります。 答えは、これら 2 つの独立した一致の合計です。

 ## アルゴリズムのチュートリアル

 1. 偶数のチェストと奇数のチェストがいくつあるかを数えます。 

これにより、問題が 2 つの独立したカテゴリに分類されます。 
2. 偶数のキーと奇数のキーの数を数えます。 

これらの数によって、考えられるすべての有効なペアが決定されます。 
3. 偶数のチェストと奇数のキーの間で形成できるペアの数を計算します。 

各オブジェクトは 1 回使用されるため、これは 2 つのカウントのうち小さい方によって制限されます。 
4. 奇数のチェストと偶数のキーの間で形成できるペアの数を計算します。 

繰り返しますが、これは利用可能なカウントの最小値です。 
5. 2 つの結果を合計して出力します。 

それぞれのケースで最小値を採用する理由は、すべてのペアリングで 1 つのチェストと 1 つのキーを消費するため、小さいグループが常にボトルネックになるためです。 

### なぜ効果があるのか

 パリティ条件は有効性を完全に決定します。要素が反対のパリティを持つ場合に限り、ペアは有効です。 項目を偶数と奇数に分割すると、特定の要素をリンクするさらなる制約はなくなります。 反対のパリティ要素をペアにするマッチング戦略はすべて同等であるため、マッチングを最大化すると、独立した 2 部ペアの数を最大化することになります。これは、2 つのグループ間で可能な限り多くのマッチングを貪欲に行うことによって実現されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    even_a = sum(x % 2 == 0 for x in a)
    odd_a = n - even_a
    
    even_b = sum(x % 2 == 0 for x in b)
    odd_b = m - even_b
    
    # even chest with odd key
    match1 = min(even_a, odd_b)
    
    # odd chest with even key
    match2 = min(odd_a, even_b)
    
    print(match1 + match2)

if __name__ == "__main__":
    solve()
```コードはまず、単一パスで両方の配列をパリティ カウントに分割します。 次に、考えられる 2 つのペアリング方向を個別に計算します。 これらの組み合わせは使用される要素の点で素であるため、最終的な答えは両方の合計になります。 

主な微妙な点は、カウントを誤って混合しないようにすることです。偶数のチェストは奇数のキーの一致にのみ寄与でき、その逆も同様です。 各最小計算では、1 対 1 の使用制限が適用されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、片側に 1 つのパリティ タイプしかない場合です。 たとえば:

 入力:```
4 3
2 4 6 8
1 3 5
```ここでは、すべてのチェストが偶数で、すべてのキーが奇数です。 アルゴリズムは計算します`even_chests = 4`、`odd_keys = 3`、 それで`min(4,3)=3`は一致し、反対方向はゼロになります。 出力は 3 です。すべてのキーでチェストを開けることができますが、1 つのチェストは未使用のままであるため、これは正しいです。 

もう 1 つのケースは、両方の側面が混在しているものの、著しく不均衡な場合です。```
5 5
1 1 1 2 2
2 2 2 1 1
```偶数と奇数のペアリングにより、`even_chests=2, odd_keys=3 → 2`そして`odd_chests=3, even_keys=2 → 2`それぞれの最小値により限られたリソースの消費が強制されるため、アルゴリズムは過剰カウントを正しく回避します。
