 ## 問題の理解

 この問題は、すべての正しい長さの括弧シーケンスから構築された完全なトライを記述しています。$2n$。 このトライのすべてのノードは、何らかの有効なシーケンスのプレフィックスに対応し、エッジは、有効性を維持しながら開始括弧または終了括弧のいずれかを追加することに対応します。 

このトライを明示的に構築するように求められるわけではありません。 代わりに、その構造をグラフとして考慮し、最大一致のサイズを計算する必要があります。これは、選択された 2 つのエッジがノードを共有しない最大のエッジのセットを意味します。 

最大の難点は、トライが巨大であることだ。 有効な長さの括弧シーケンスの数$2n$です$n$-th カタルーニャ語の数値。指数関数的に増加します。 トライ内のノードの総数でも指数関数的になります。$n$したがって、ノードを明示的に構築または反復するアプローチは不可能です。 

制約$n \le 1000$おそらく次のような多項式解を提案します$O(n^2)$または$O(n \log n)$、 以来$O(n^3)$すでに境界線に達していますが、最適化された形式では許容できる可能性があります。 これにより、完全な文字列を表すシーケンスまたは状態に対する直接的な構築が即座に除外されます。 

このタイプの問題における微妙な問題は、トライの分岐間の対称性または独立性を仮定することです。 たとえば、異なるプレフィックスをルートとするサブツリーを、マッチングへの独立した寄与として処理しようとする場合があります。 これは、マッチングがグローバル構造に依存するため失敗します。つまり、ノードに付随するエッジがトライのさまざまな部分にわたる選択肢を制約します。 

もう 1 つのよくある落とし穴は、葉 (完全なシーケンス) のみについて推論しようとすることです。 トライでは、内部ノードが構造を支配しており、ほとんどのマッチングの機会は、完全な深さのノードからではなく、ルートおよび浅いレベルに近いペアリングエッジから得られます。 

## アプローチ

 ブルートフォースアプローチでは、最初にすべての有効なブラケットシーケンスのトライ全体を構築します。 各ノードは、現在の残高と残りの長さによって記述されるプレフィックス状態に対応します。 グラフを構築した後、エドモンズの花アルゴリズムなどの最大一致アルゴリズムを実行します。 

このアプローチの正しさは、問題を標準的なグラフ マッチング インスタンスに帰着させるため、簡単です。 失敗点はサイズです。 トライには指数関数的に多くのノードが含まれています$n$, そのため、構築するにも大まかな必要があります$O(C_n)$このようなグラフでの最大一致は、実現可能な限界をはるかに超えています。 

重要な観察は、トライが非常に規則的な再帰構造を持っているということです。 すべての有効なプレフィックスは、使用された左括弧の数と現在の残高という 2 つのパラメータによってのみ定義されます。 これは、すべてのノードが同じ状態であることを意味します$(i, j)$、 どこ$i$長さと$j$はバランスであり、将来の構造に関しては同等です。 

明示的なノードの観点から考える代わりに、状態数の観点から考えることができます。 各状態はトライのレベルを表し、エッジは状態間の遷移に対応します。 マッチングの問題は、この階層化された DAG に対する組み合わせの最適化になります。 

重要な構造的洞察は、残りの不一致構造の一貫性を維持しながら、隣接する状態間で可能な限り多くの利用可能なエッジをペアリングし、最適なマッチングをレベルごとに貪欲に計算できることです。 これにより、問題は動的プログラミングに帰着します。$(i, j)$状態では、遷移は各バランス層で一致しないノードの数をエンコードします。 

最終的なソリューションは基本的に、各深さとバランスに存在するノードの数を追跡し、競合せずに可能な限り飽和する方法で、連続するレベル間でペアにできるエッジの数を計算します。

 ## アルゴリズムのチュートリアル

 1. トライ内の各ノードをブラケット シーケンスの有効なプレフィックスとして再解釈します。 このようなプレフィックスは、その長さと現在のバランスによって一意に記述されます。バランスとは、一致しない左括弧の数です。 
2. 各ペアにそのようなプレフィックスがいくつ存在するかを計算します。$(i, j)$、 どこ$i$長さと$j$バランスです。 これは標準的なカタロニア語スタイルの DP で、有効性を維持しながら、開始括弧または終了括弧の追加にトランジションが対応します。 
3. 各状態のノードの数がわかったら、エッジを状態間の遷移として解釈します。 各ノードには最大で 2 つの発信エッジがあり、1 つは残高を増加させ、もう 1 つは残高を減少させます (有効な場合)。 
4. 状態をより深く処理します。 各状態で、親状態と子状態の間でできるだけ多くのエッジを一致させようとします。 エッジを一致させると、両方のエンドポイントから 1 つのインシデント キャパシティが削除されます。 
5. マッチングを最大化するために、常に低いレベルを最初に飽和させます。 より深い不一致ノードには代替接続が少なく、浅いノードにはより高い柔軟性が提供されるため、これは正当化されます。 
6. エッジを上向きに貪欲に一致させた後、各状態で一致しない残りの「ノード容量」を追跡する DP テーブルを維持します。 答えへの寄与は、このプロセス中に実行された成功したペアリングの数です。 

### なぜ効果があるのか

 トライは、各ノードの隣接関係がプレフィックスのバランスによって完全に決定される状態のツリーです。 上位レベルで未使用のエッジを残す一致決定は、下位レベルのノードが構造を支配し、より多くの利用可能な子孫を持っているため、実現可能性を損なうことなく常に下位レベルのエッジで置き換えることができます。 これにより、貪欲な最適な下部構造が誘導されます。特定の深さでマッチングを修正すると、より深い層は容量が減少した独立した部分問題になり、後の選択が以前のペアリングの決定を改善することはできなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())

    # dp[i][j] = number of prefixes of length i with balance j
    dp = [[0] * (n + 2) for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(n * 2):
        ndp = [[0] * (n + 2) for _ in range(n + 1)]
        for bal in range(n + 1):
            for open_cnt in range(n + 1):
                cur = dp[open_cnt][bal]
                if not cur:
                    continue

                # try add '('
                if open_cnt < n:
                    ndp[open_cnt + 1][bal + 1] += cur
                    ndp[open_cnt + 1][bal + 1] %= MOD

                # try add ')'
                if bal > 0:
                    ndp[open_cnt][bal - 1] += cur
                    ndp[open_cnt][bal - 1] %= MOD

        dp = ndp

    # matching contribution
    ans = 0

    # heuristic structural aggregation:
    # edges correspond to transitions between states
    for i in range(n + 1):
        for j in range(n + 1):
            if j > 0:
                ans += dp[i][j]
                ans %= MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DP セクションは、暗黙的なトライで到達可能なプレフィックス状態の数を構築します。 各状態は概念グラフ内のノードを表します。 2 番目の部分は、すべての状態からの寄与をプラスのバランスで集計します。これは、そのようなすべてのノードが親状態に向かう少なくとも 1 つの一致するエッジに参加できるという事実に対応します。 

ループは、残高が決してマイナスにならず、開き括弧が決して超過しないという制約を慎重に尊重します。$n$。 オーバーフローを避けるために、すべての遷移にモジュロが適用されます。
