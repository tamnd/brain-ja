 ## 解決策
 ## 問題の理解

 私たちは、任意の惑星から開始して正確に到達するキャラクターが訪問する個別の惑星の順序付けされたシーケンスを数えるように求められます。$k-1$動く。 それぞれの動きは現在の惑星から行われます$x$新しい惑星へ$y$、次の 2 つの制限があります。$y$以前に訪れたことがなく、範囲内にある必要があります$[1, x + m]$。 訪問後にプロセスが停止する$k$異なる惑星であり、訪問順序のいずれかの位置で異なる場合、2 つのシーケンスは異なるものとみなされます。 

重要な点は、制約が対称ではないということです。 から$x$、右側にあまり遠くない惑星にのみ移動できますが、左側にはその惑星を訪問してはいけないことを除いて制限はありません。 これにより、これまでに到達した現在の最大位置に応じたダイナミック レンジの制約が作成されます。 

制約は非常に重要です。 惑星の数$n$までです$10^5$したがって、すべてのシーケンスを明示的にシミュレートすることはできません。 しかし、$k \le 12$、非常に小さいです。 これは直ちに指数関数的アルゴリズムを示唆します。$k$に大きく依存しない限り、許容されます。$n$。 値$m \le 4$さらに、遷移は非常に局所的で構造化されており、通常、小さな近傍の周囲で状態圧縮が可能であることが示唆されています。 

素朴な考えは、各状態を次のように扱うことです。$(visited\_set, current)$。 訪問されたセットのサイズが次から選択された最大 12 要素であるため、これはすぐに失敗します。$10^5$、それは天文学的な大きさです。 

さらに微妙な問題は、訪問済みのセットを無視して各位置からの選択肢を貪欲に数えようとしたとしても、利用可能かどうかは現在の位置と、まだ使用されていない近くの惑星の小さなセットの両方に依存するという事実を見逃してしまうということです。 

素朴な貪欲な思考による具体的な失敗例は次のとおりです。$n=5, k=3, m=1$。 位置 3 から 4 に進むことができますが、別のブランチですでに 4 が以前に訪問されている場合は、単純なカウントにはまだそのパスが含まれているとしても、そのパスは無効になります。 

したがって、本当の難しさは、次の事実を利用しながら、「使用済み/未訪問」ステータスを効率的に管理することです。$k$小さいし、$m$とても小さいです。 

## アプローチ

 ブルートフォース ソリューションでは、すべてのシーケンスを試行します。つまり、すべての惑星から開始し、有効な次の動きをすべて再帰的に試行し、訪問した配列を維持します。 各ステップは次のように分岐します。$m+1$最悪の場合の候補者は、$x$私たちが行けるのはせいぜい$x+m$、ただし、ローカルに関連するものは一定数だけです。 ただし、再帰の深さは$k$したがって、全体の複雑さはおおよそ次のようになります。$O(n \cdot (m+1)^k)$これは、小さな定数であってもすでに境界線に達しており、本当の致命的な点は、各遷移で候補が訪問されたかどうかを確認する必要があるため、有効な状態空間が訪問されたノードの実際の ID に依存することです。 

重要な観察は、重要な唯一の「記憶」は、約サイズのスライディングウィンドウ内の訪問惑星の相対的な構造であるということです。$m+k$。 以来$m \le 4$そして$k \le 12$、有効なシーケンスは、現在の最大位置の周囲の非常に小さな近傍にのみ依存します。 私たちが十分に右端に到達すると、はるか左の惑星は無関係になります。なぜなら、境界のある地平線を超えて将来の利用可能性に影響を与えるような形で、未踏の構造に任意に後戻りすることは決してできないからです。 

これは、状態をビットマスクに圧縮して、最後のいくつかの位置 (現在の最大値または現在の基準点に対して) のどれが使用されたかを表すことを示唆しています。 以来$m$は小さいため、遷移は小さなシフト ウィンドウにのみ影響し、このウィンドウ内で訪問したパターンをエンコードできます。 

次に、現在の位置とサイズのビットマスクによって定義された状態に対して動的プログラミングを実行します。$O(m + k)$ですが、重要なのは、最大の相対オフセットを追跡するだけでよいということです。$m$トランジションはその範囲のみを検査するためです。 これにより、問題は約$2^{m+k}$レイヤーごとの状態、および$k \le 12$これを管理しやすくします。 

各ステップで、ある状態から遷移します。$(current, mask)$すべての有効な次の位置へ$y \in [1, current+m]$マスク表現内でまだ訪問されていないものを選択し、それに応じてマスクを更新します。 

ブルート フォースに対する改善点は、絶対的な訪問ノードを追跡する代わりに、圧縮されたローカル構成のみを追跡し、到達可能性をグローバルに再計算する代わりに、ビットマスク上で事前に計算された遷移を再利用することです。

 ## アルゴリズムのチュートリアル

 考えられるすべての開始惑星を処理し、開始位置ごとに、訪問したノードの数に対して階層化された DP を実行します。 

1. DP テーブルを初期化します。$dp[t][state]$有効な長さのシーケンスを構築する方法の数を表します$t$、によってエンコードされた構成で終わる`state`。 状態は、小さなウィンドウに対する現在の位置と、どの近くの位置が使用されているかの両方をエンコードします。 
2. 開始惑星ごとに$s$、 セット$dp[1][initial\_state(s)] = 1$。 初期状態では訪問惑星は 1 つだけです。 
3. 以下のステップ数を繰り返します。$1$に$k-1$。 各ステップで、レイヤーからすべての DP 状態を展開します。$t$レイヤーに$t+1$。 
4. 各状態について、現在位置をデコードします。$x$。 次のポジションの候補をすべて列挙する$y$そのような$1 \le y \le x+m$。 このループは小さいため、$m \le 4$。 
5. 各候補者について$y$、エンコードされた状態ですでにアクセスされているかどうかを確認します。 訪問していない場合は、マークを付けて新しい状態を構築します$y$訪問したとおりに、現在位置を次のように更新します$y$。 
6. 次の DP 層で古い状態から新しい状態に至るウェイの数を追加します。 
7.加工後$k$レイヤーでは、すべてのエンドポイントと開始位置にわたるすべての DP 状態を合計します。 

これが機能する理由は、すべての有効なシーケンスがこれらの DP 状態を通る 1 つのパスに正確に対応するためです。これは、状態エンコードによって、将来の移動に影響を与える可能性がある唯一の領域内で順序付け情報と訪問情報の両方が保存されるためです。 遷移はローカル制約のみに依存するため、同じローカル マスクを誘発する 2 つの異なるグローバル ヒストリは、今後も同様に動作します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

def solve():
    n, k, m = map(int, input().split())

    # We compress the DP using the fact k <= 12 and m <= 4.
    # We represent states as (current_position, visited_mask over last window).
    
    # Window size: we keep relative indices in [0 .. m+k]
    W = k + m + 1
    FULL = 1 << W

    # dp[position][mask] only for reachable positions
    dp = [dict() for _ in range(k + 1)]

    # initialize
    for s in range(1, n + 1):
        mask = 1 << (s % W)
        dp[1][(s, mask)] = (dp[1].get((s, mask), 0) + 1) % MOD

    for t in range(1, k):
        ndp = [dict() for _ in range(k + 1)]
        for (x, mask), val in dp[t].items():
            for y in range(1, min(n, x + m) + 1):
                bit = 1 << (y % W)
                if mask & bit:
                    continue
                nm = mask | bit
                key = (y, nm)
                ndp[t + 1][key] = (ndp[t + 1].get(key, 0) + val) % MOD
        dp = ndp

    ans = 0
    for state, val in dp[k].items():
        ans = (ans + val) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
