 ## 問題の理解

 2 つの開始整数が与えられます。 両方の数値から、同じ非負の量だけ上にシフトすることができます。$k$、ペアを生成します$a+k$そして$b+k$。 このようなシフトごとに、結果として得られる 2 つの数値の最小公倍数を計算できます。 考えられるすべてのシフトの中で、この最小公倍数をできるだけ小さくするシフトが必要であり、複数のシフトが同じ最小値に達する場合は、最小のシフトが優先されます。 

これについて考えるのに役立つ方法は、数直線上の 2 つの固定点をそれらの距離を維持しながら一緒にスライドさせ、各位置でそれらが可分性構造の観点からどの程度「互換性」を持つかを測定することです。 課題は、LCM を通じて測定されたこの互換性が最適な位置を見つけることです。 

制約は次のとおりです$10^9$、つまり、次のすべての値を試すソリューションは、$k$すぐには実行不可能です。 直接スキャンでは、テストごとに最大 10 億人の候補者を検査することになりますが、テスト ケースの数が中程度であっても 1 秒以内にこれを行うことは不可能です。 

微妙な問題は、両方の数値をシフトすると LCM が単調に動作しないという事実にあります。 小さな変化によって最大公約数が大幅に変化する可能性があります。$\mathrm{lcm}(x,y) = \frac{xy}{\gcd(x,y)}$、目標は、製品の成長と gcd の予測できない上昇の両方に影響されます。 

よくある落とし穴は、最良の答えが常に近くにあると仮定することです$k = 0$または、一方の数字がもう一方の数字を割る点の近く。 たとえば、$a=8, b=12$、小さなシフトだけを試すこともできますが、最適なシフトは必ずしも元の値での割り切れるとは限りません。 

## アプローチ

重要な観察は、問題の構造は値のみに依存するということです。$x = a+k$そして$y = b+k$、それらの差は一定のままです。 させて$d = |a-b|$。 すると、すべての候補ペアは次の形式になります。$(x, x+d)$。 これにより、問題は値の選択に変わります$x \ge \max(a,b)$の最小公倍数が$x$そして$x+d$最小化されます。

各約数について$g$の$d$、私たちは強制しようとします$\gcd(x, x+d) = g$。 もし$g$両方の数値を除算し、両方を除算します$x$そして$x+d$の倍数でなければなりません$g$。 書き込み$x = g \cdot t$、条件を選択に減らします$t$次のような:$$g t + d \equiv 0 \pmod{g} \Rightarrow d \equiv 0 \pmod{g},$$それはすでに満足しています。 実際の制約は、より大きな約数が存在しないようにすることです。$d$divides both numbers simultaneously. 実際には、複数の条件を検索することで条件を強制します。$g$有効な$x$、そして gcd を明示的にチェックします。 

検索空間は次のすべての約数になります。$d$、各約数について最小のものを見つけます。$x \ge \max(a,b)$そのような$\gcd(x, x+d) = g$。 約数の数は最大でも約 であるため、これは効率的です。$1e4$最悪の場合の値は、通常ははるかに小さくなります。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$d = |a-b|$。 もし$d = 0$、シフト後の 2 つの数値は常に等しいため、LCM は単純に次のようになります。$a+k$、で最小化されます$k=0$。 すぐに戻れます。 
2. すべての約数を抽出します。$d$。 各約数は、最終ペアの gcd の可能な候補を表します。 
3. 各約数について$g$、最小の有効な値を構築しようとします。$x \ge \max(a,b)$両方とも$x$そして$x+d$gcd を正確に共有する$g$。 これは、次の最初の倍数から開始することによって行われます。$g$より小さくない$\max(a,b)$。 
4. 一度そのようなことがあれば$x$が選択されている場合は、次を使用して対応する LCM 値を計算します。$\frac{x(x+d)}{\gcd(x, x+d)}$。 
5. すべての候補の最小 LCM を追跡します。 複数の場合$x$同じ LCM を生成する場合は、最小のものを選択します$k = x - \max(a,b)$。 

### なぜ効果があるのか

 中心的な不変条件は、次の公約数です。$x$そして$x+d$分けなければなりません$d$、すべての可能な gcd 値を次の除数格子に制限します。$d$。 すべての有効な構成は、そのような約数を 1 つ選択し、それを達成する剰余構造内の最小点を見つけることに対応します。 LCM はのみに依存するため、$x$、$d$、および gcd をすべて列挙すると、グローバル最小値を見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

a, b = map(int, input().split())

if a > b:
    a, b = b, a

d = b - a

if d == 0:
    print(0)
    sys.exit()

# get divisors of d
divs = []
i = 1
while i * i <= d:
    if d % i == 0:
        divs.append(i)
        if i * i != d:
            divs.append(d // i)
    i += 1

best_lcm = None
best_k = None

for g in divs:
    # smallest x >= b such that x % g == 0
    x = ((b + g - 1) // g) * g
    y = x + d
    g_val = math.gcd(x, y)
    lcm_val = x // g_val * y

    k = x - b

    if best_lcm is None or lcm_val < best_lcm or (lcm_val == best_lcm and k < best_k):
        best_lcm = lcm_val
        best_k = k

print(best_k)
```コードはまずペアを正規化して、次のようにします。$a \le b$違いを生む$d$一貫性のある。 約数$d$で生成されます$O(\sqrt{d})$、各約数は、最初の有効な候補を構築することによってテストされます。$x$その除数に合わせて調整されます。 

gcd の計算は、アライメントによって最大の gcd が保証されるという想定を避けるために明示的に実行されます。 これにより、両方の数値のより大きな隠れた約数が存在する場合の、微妙な過大カウント エラーが防止されます。 

最終的な比較では、LCM 値とシフトの両方を注意深く追跡します。$k$、辞書編集的に最小限の選択が保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    a, b = map(int, input().split())

    if a > b:
        a, b = b, a

    d = b - a
    if d == 0:
        return "0\n"

    divs = []
    i = 1
    while i * i <= d:
        if d % i == 0:
            divs.append(i)
            if i * i != d:
                divs.append(d // i)
        i += 1

    best_lcm = None
    best_k = None

    for g in divs:
        x = ((b + g - 1) // g) * g
        y = x + d
        g_val = math.gcd(x, y)
        lcm_val = x // g_val * y
        k = x - b

        if best_lcm is None or lcm_val < best_lcm or (lcm_val == best_lcm and k < best_k):
            best_lcm = lcm_val
            best_k = k

    return str(best_k) + "\n"

# provided sample
assert run("6 10") == "2\n"

# custom cases
assert run("1 1") == "0\n"

 ## 特殊なケース

 いつ$a = b$、アルゴリズムはすぐに戻ります$k=0$シフトすると両方の数値が等しく増加するだけなので、LCM は単調に増加するからです。 早期終了により、不必要な除数の計算が回避されます。 

いつ$d$が素数の場合、約数セットは次のようになります。$\{1, d\}$であり、アルゴリズムは、gcd が 1 に崩壊する場所と、gcd が 1 に到達できる場所の 2 つの構造化された候補を効果的に比較します。$d$。 正しい答えは、これら 2 つの構成を直接比較することで常に得られます。 

いつ$a$そして$b$が大きく離れていても、各約数の構築された候補により、引き続き構造化された倍数のみを検査することが保証され、gcd チェックにより、割り算のアライメントに関する誤った仮定が防止されます。
