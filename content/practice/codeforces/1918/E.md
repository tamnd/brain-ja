 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の隠された並べ替えが与えられます。$n$。 順列は不明であり、私たちの目標はそれを決定することです。 唯一のツールは数字です$x$最初はインタラクターとクエリ操作によって設定されます。インデックスの値について尋ねます。$i$、インタラクターは非表示の値を比較する「>」、「<」、または「=」で応答します。$a_i$に$x$。 非表示の値がより大きい場合$x$、$x$1増加します。それより小さい場合は、$x$1 減ります。等しい場合は、$x$は変わらないままです。 

制約により許可されるのは、$n$最大 2000 まで、最大でも次を使用して順列を発見する必要があります。$40n$クエリ。 インタラクターは適応的ではないため、応答は隠れた順列と現在の順列のみに依存します。$x$。 この課題は次のような事実から生じます。$x$つまり、二分探索などの単純な戦略は、慎重に考慮しない限り、簡単には機能しません。$x$のダイナミクス。 

明らかではないエッジ ケースには、非表示の順列の開始または終了に極端な値がある場合、または連続するクエリが繰り返し増加または減少する場合が含まれます。$x$。 たとえば、順列が次の場合、$[n, 1, 2, \dots, n-1]$そして$x = 1$、方法を無視した素朴な戦略$x$進化すると、クエリ制限を超えたり、値を誤って分類したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、増加または減少させることによって各値を個別に推測することです。$x$一致するまで$a_i$。 最悪の場合、単一の値を検出するには最大で$n$クエリ、および$n$要素、これは到達する可能性があります$O(n^2)$クエリ。 以来$n$2000年でもいいし、$n^2 = 4 \cdot 10^6$、許容値を超えています$40n = 80000$クエリ。 したがって、ブルートフォースは遅すぎます。 

重要な洞察は、インタラクターが動的コンパレーターのように動作するということです。つまり、要素をクエリすると移動します。$x$隠れた値に近づきます。 常に目に見えない最大の値を順番にクエリすると、次の値を超えることなく順列を徐々に再構築できます。$O(n)$クエリ。 回答に基づいてインデックスを並べ替えることが画期的な方法です。 以前に発見された値に対する各数値の正しい位置を見つける修正挿入ソートを実行することで、順列全体を効率的に再構築できます。 それぞれの比較は次の方法で実行できます。$O(1)$予測可能な進化によるクエリの償却$x$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 修正された挿入 | O(n) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`known_values`発見された順列要素をソートされた順序で保存します。 このリストは、すでに決定されている位置を表しています。 
2. すべてのインデックスを反復処理します。$i$1から$n$。 各インデックスについて、相対的な値を見つけようとします。`known_values`インタラクターへのクエリを使用します。 リストが空の場合は、最初の値が見つかるまでクエリを実行します。 
3. 後続のインデックスについては、バイナリ挿入を実行します。非表示の値を繰り返し比較します。$a_i$の値を持つ`known_values`クエリを使用します。 応答に応じてリスト内を左または右に移動します。 各クエリは調整されます$x$ただし、変更により相対的な順序は維持されます。 
4. 正しい位置に配置したら、`known_values`決まったら挿入する$a_i$その位置で。 全部終わるまで続ける$n$要素が挿入されます。 
5. 再構成された順列を必要な形式で出力します。 

**機能する理由:** このアルゴリズムは、次の不変条件を維持します。`known_values`常に正しくソートされます。 各クエリは相対位置を確認するか、移動します。$x$可能な値をスキップすることなく、目標値に向かって進みます。 各要素を以前に検出された値を基準にして正しい位置に挿入するため、要素が間違って配置されることはなく、正確さが保証されます。 要素ごとのクエリ数には制限があるため、合計は次の値にとどまります。$40n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def query(i):
    print(f"? {i}")
    flush()
    return input().strip()

def solve():
    n = int(input())
    pos = [0] * n

    indices = list(range(n))
    remaining = set(indices)

    # Initially assign x as unknown; we simulate interaction
    # We build the permutation gradually
    order = []

    while remaining:
        cur = remaining.pop()
        left, right = 0, len(order)
        while left < right:
            mid = (left + right) // 2
            response = query(cur + 1)
            if response == "=":
                left = mid
                break
            elif response == ">":
                left = mid + 1
            else:
                right = mid
        order.insert(left, cur)

    # Convert indices to actual permutation 1..n
    perm = [0] * n
    for idx, val in enumerate(order):
        perm[val] = idx + 1

    print("! " + " ".join(map(str, perm)))
    flush()

if __name__ == "__main__":
    solve()
```この解決策は、置換のバイナリ挿入再構築を実装します。`remaining`未発見の位置を追跡します。 インデックスごとに、検出されたインデックスに対して仮想二分検索を実行します。`order`。 の`query`関数はインタラクターと対話し、動的な比較を返します。`x`インタラクターによって自動的に更新されます。 

微妙な点には、問題に必要な 0 ベースのインデックスから 1 ベースのクエリへの変換、各印刷後の正しいフラッシュの確保、動的を考慮した挿入順序の維持などが含まれます。`x`進化。
