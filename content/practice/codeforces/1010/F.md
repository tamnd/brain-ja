 ## 解決策
 ## 問題の理解

 ルートが頂点 1 に固定され、各頂点に最大 2 つの子を持つルート付きツリーが与えられます。 「枝刈り」のプロセスの後、ルートを含む必要がある接続された頂点のセットが保持されます。 これは、残りの頂点が常にルート付きサブツリーを形成することを意味します。頂点が保持されると、ルートまでのその親も保持され、頂点が削除されると、そのサブツリー全体も同様に消えます。 

特定の残りのサブツリーが修正されたら、「フルーツ」として解釈される頂点に非負の整数値を割り当てます。 ルートには、正確に x 個のフルーツが含まれるように制約されます。 他のすべての頂点は単調性条件を満たさなければなりません。その値は、少なくとも残りのサブツリー内の子の値の合計です。 葉には非負性以外の制約はありません。 

選択された残りのサブツリーが異なる場合、または同じサブツリーが選択されてもフルーツ値の割り当てが頂点で異なる場合、2 つの結果は異なります。 タスクは、998244353 を法とするすべての有効な結果をカウントすることです。 

この制約により、私たちは非常に厳しい計算体制に追い込まれます。 頂点が最大 100,000 個になると、接続されたサブツリーの制限された列挙ですら指数関数的に増加するため、頂点のすべてのサブセットを反復するソリューションは直ちに不可能になります。 同様に、畳み込みアクセラレーションを使用しないサブツリー サイズに対する状態ごとの 2 次 DP は、ツリー全体でマージが繰り返されるため失敗します。 

過小評価されがちな 2 つの構造的な問題があります。 まず、ルートが 1 である有効な接続サブツリーの数は、一般的なツリーではすでに指数関数的であるため、それらを明示的に列挙することはできません。 第 2 に、そのようなサブツリーごとに、有効なフルーツの割り当ての数は非常に自明ではない形でサブツリーのサイズに依存し、単純な DP では同様の組み合わせを繰り返し再計算することになります。 

よくある失敗例は、フルーツ制約をローカルに扱うことです。 たとえば、各ノードが親からある境界までの値を独立して選択すると考えると、制約が個々のエッジではなく合計を通じて伝播することが無視されます。 部分的な子サブツリーを選択する方法の数を正確にカウントせずに、サブツリー サイズのみを DP しようとすると、別の微妙な失敗が発生します。 これにより、組み合わせの多重性が失われ、小さな星であってもアンダーカウントが生じます。 

## アプローチ

 値の割り当てを簡素化する鍵は、兄弟間の依存関係を削除する方法で不等式制約を書き直すことです。 

すべてのノードについて、その値を次のようにします。$a_u$、スラック変数を定義します$$b_u = a_u - \sum_{\text{child } v} a_v \ge 0.$$並べ替えると$$a_u = b_u + \sum_{\text{child } v} a_v.$$これを再帰的に展開すると、それぞれ$a_u$すべての合計になります$b$-そのサブツリー内の値。 これは、すべての$b_v$のすべての祖先に正確に 1 回貢献します$v$、そしてそれらの先祖にのみ。 したがって、$$a_u = \sum_{v \in \text{subtree}(u)} b_v.$$ルート制約は特にきれいになります。$$x = a_1 = \sum_{v \in S} b_v,$$どこ$S$選択された残りのサブツリーです。 

したがって、残りのサブツリーを修正したら、$S$、問題は配布方法の数を数えるということになります。$x$区別できない単位$|S|$ノード、ゼロを許可します。$$\#\text{assignments for } S = \binom{x + |S| - 1}{|S| - 1}.$$ツリーの構造は、各サイズの接続されたルート付きサブツリーの数によってのみ重要になるようになりました。 させて$f_k$正確にルートを含む接続されたサブツリーの数になります。$k$頂点。 最終的な答えは次のようになります$$\sum_{k=1}^{n} f_k \cdot \binom{x+k-1}{k-1}.$$残りのタスクはツリー上で純粋に組み合わせです: 計算$f_k$。 各ノードは、その子からの選択を独立して組み合わせます。 子の場合は、そのブランチから何も取得しないか、その有効なルートサブツリーの 1 つを取得します。 これにより、各ノードがサブツリー サイズにわたって母関数を維持する多項式 DP が得られます。 

各ノードには最大でも 2 つの子があるため、サブツリーのサイズに比例するサイズの多項式を繰り返しマージします。 単純なマージは全体として 2 次ですが、NTT ベースの畳み込みによる小規模から大規模のマージを使用すると、各多項式要素が対数的に多くのマージにのみ参加することが保証され、ほぼ次の結果が得られます。$O(n \log^2 n)$複雑。

 ## アルゴリズムのチュートリアル

 1. ツリーを 1 でルートし、DFS トラバーサルを実行して、親の前に子を処理します。 これにより、各サブツリー DP がマージで使用される前に完全に計算されるようになります。 
2. すべてのノードについて$u$、多項式を定義します$F_u[k]$、 どこ$F_u[k]$をルートとする接続されたサブツリーを選択する方法の数です。$u$正確に含む$k$ノード。 
3.初期化$F_u$ノード自体のみを表す多項式として、$F_u[1] = 1$。 
4. それぞれの子どもたちに$v$の$u$、補助多項式を構築します$G_v$どこ$G_v[0] = 1$（つまり、子供を完全に無視するという意味です）$G_v[k] = F_v[k]$のために$k \ge 1$。 これは、ブランチを除外するか、ルートから完全なサブツリーを取得するかの選択をエンコードします。 
5. 子の貢献を$F_u$畳み込みの使用: 子の処理後$v$、 アップデート$$F_u \leftarrow F_u * G_v.$$この手順により、子サブツリーの取得またはスキップのすべての組み合わせが正しくカウントされるようになります。 
6. 複雑さを制御するには、常に小さい多項式を大きい多項式にマージします。 これにより、各係数が DFS 全体にわたって対数的に多くの畳み込みにのみ関与することが保証されます。 
7. 計算後$F_1$、すべてのサイズを合計して最終的な答えを計算します。$$\text{answer} = \sum_{k=1}^{n} F_1[k] \cdot \binom{x+k-1}{k-1}.$$正確さは構造的不変式に依存します: ノードの処理後$u$、その多項式$F_u$をルートとする有効な接続サブツリーの数を正確にエンコードします。$u$、各サブツリー分解は各子ブランチの独立した選択によって一意に決定されるため、過剰カウントなしでサイズごとにグループ化されます。 ツリー制約から多項式畳み込みへの変換により、分岐間の独立性が維持され、スラック変数の再定式化により、サブツリーが固定されると、すべての有効なフルーツの割り当てが形状ではなくサイズのみに依存することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

def ntt(a, invert=False):
    n = len(a)
    j = 0
    for i in range(1, n):
        bit = n >> 1
        while j & bit:
            j ^= bit
            bit >>= 1
        j ^= bit
        if i < j:
            a[i], a[j] = a[j], a[i]

    length = 2
    while length <= n:
        wlen = pow(3, (MOD - 1) // length, MOD)
        if invert:
            wlen = pow(wlen, MOD - 2, MOD)

        i = 0
        while i < n:
            w = 1
            half = length >> 1
            for j in range(i, i + half):
                u = a[j]
                v = a[j + half] * w % MOD
                a[j] = (u + v) % MOD
                a[j + half] = (u - v) % MOD
                w = w * wlen % MOD
            i += length
        length <<= 1

    if invert:
        inv_n = pow(n, MOD - 2, MOD)
        for i in range(n):
            a[i] = a[i] * inv_n % MOD

def multiply(a, b):
    if not a or not b:
        return []
    n = 1
    while n < len(a) + len(b) - 1:
        n <<= 1
    fa = a[:] + [0] * (n - len(a))
    fb = b[:] + [0] * (n - len(b))
    ntt(fa)
    ntt(fb)
    for i in range(n):
        fa[i] = fa[i] * fb[i] % MOD
    ntt(fa, True)
    while fa and fa[-1] == 0:
        fa.pop()
    return fa

n, x = map(int, input().split())
g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    a, b = map(int, input().split())
    g[a].append(b)
    g[b].append(a)

parent = [0] * (n + 1)
order = []

stack = [1]
parent[1] = -1
while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

children = [[] for _ in range(n + 1)]
for v in range(2, n + 1):
    children[parent[v]].append(v)

dp = [None] * (n + 1)

def dfs(u):
    poly = [1]  # size 1
    for v in children[u]:
        cv = dfs(v)
        take = [1] + cv
        poly = multiply(poly, take)
    dp[u] = poly
    return poly

dfs(1)

# factorials for combinations
fact = [1] * (n + 1)
invfact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD
invfact[n] = pow(fact[n], MOD - 2, MOD)
for i in range(n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C_large_x(x, k):
    if k <= 0:
        return 1
    res = 1
    for i in range(k):
        res = res * ((x + i) % MOD) % MOD
    return res * invfact[k] % MOD

res = 0
root_poly = dp[1]
for k in range(1, len(root_poly)):
    res = (res + root_poly[k] * C_large_x(x, k - 1)) % MOD

print(res)
```DFS は、その子からの「テイクまたはスキップ」の選択肢をマージすることによって、各ノードの多項式を構築します。 畳み込みステップは、組み合わせ構造が結合される唯一の場所であり、まさにサブツリーの選択が乗算的に相互作用する場所です。 

最後のループでは、立ち下がり階乗オーバーを使用して整数分布の閉じた形式のカウントを適用します。$x$、で割る$(k-1)!$、これは配布方法の数と一致します。$x$全体の単位$k$ノード。

 ## 特殊なケース

 重要なエッジケースは、ツリーが単一チェーンである場合です。 この状況では、すべての DP マージは繰り返しの多項式拡張に縮退し、畳み込み基本ケースの処理が間違っていると、空の選択オプションが削除されるか、サイズ 1 の寄与が二重にカウントされます。 変革$G_v[0] = 1$これがないと、DP はすべての子サブツリーを含めることを強制し、すべての有効なプレフィックスの代わりに単一の厳格な構造を生成するため、ここではこれが不可欠です。 

もう一つの微妙なケースは、$x = 0$。 ここで、唯一の有効なフルーツ割り当てはすべてゼロですが、接続されているすべてのサブツリーは引き続き許可されます。 答えはルート接続されたサブツリーの数に集約されます。これは、値の割り当てとは関係なく、DP が構造構成を正しくカウントするかどうかを直接テストします。
