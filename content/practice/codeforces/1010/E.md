 ## 解決策
 ## 問題の理解

 私たちには 3D カレンダー システムが与えられており、あらゆる瞬間が、月、その月内の 1 日、その日内の 1 秒からなる 3 つの要素によって一意に識別されます。 このストアは、非常に特殊な隠されたルールに従っていることが知られています。この 3D 空間には、軸が整列したボックスが存在し、その月が特定の間隔内にあり、その日が特定の間隔内にあり、その日が特定の間隔内にあり、ストアは常に正確に開いています。 言い換えれば、有効なオープン時間は、座標軸に沿って整列した直方体を形成します。 

このプリズムの限界はわかりません。 代わりに、私たちには観察が与えられます。ある瞬間はプリズムの内側にあることが保証されており、いくつかの瞬間はプリズムの外側にあることが保証されています。 これらの観察は矛盾している可能性があり、その場合にはそのようなプリズムは存在しません。 

観察が一貫している場合、次の形式の質問に答える必要があります。つまり、ある瞬間、それは間違いなくプリズムの内側にあるのか、間違いなく外側にあるのか、それとも選択された有効なプリズムに依存するのか、ということです。 

制約により、私たちはほぼ線形または線形的な動作を強いられます。 n、m、k はそれぞれ最大 100,000 になる可能性があるため、可能な間隔を列挙したり、すべての候補をチェックしようとするソリューションは不可能です。 主な困難は、制約が 3 つの独立した次元から来ており、各次元が最小境界と最大境界を通じてのみ相互作用することです。そのため、問題を明示的なセットではなく実行可能な間隔の追跡に縮小する必要があります。 

微妙なエッジケースは矛盾の検出です。 たとえば、「開いた」集合からの点を含む区間を持たざるを得なくても、可能なすべての区間内に「閉じた」制約があるためにその点を除外しなければならない場合、実行不可能性を検出する必要があります。 典型的な失敗モードは、各次元を独立して扱い、同じ間隔がすべての次元で同時に機能する必要があることを忘れていることです。 

もう 1 つのエッジ ケースは、複数の有効な間隔が存在するような形で開いた制約と閉じた制約がインターリーブする場合です。 その場合、クエリは強制的に内部にも外部にも強制されない可能性があります。 候補区間を 1 つだけ計算する単純なソリューションでは、そのようなクエリに誤ったラベルが付けられてしまいます。 

## アプローチ

 ブルート フォース アプローチでは、月、日、秒の間隔境界の可能なすべての選択が試行されます。 各候補ボックスについて、それがすべての観測値を満たすかどうかを検証します。 観察された座標のみに境界を離散化したとしても、可能性の数は次元ごとの個別の座標の数において 3 次のままであり、10^5 の制約をはるかに超える爆発につながります。 

重要な観察は、各次元が構造的に独立しているということです。候補ボックスの有効性は、すべての開いた点が 3 つの区間すべてに同時に収まるかどうか、および 3 つの区間すべての中に閉じた点が存在しないかどうかにのみ依存します。 これは、各次元が下限と上限の制約のみに寄与し、これらの制約は実行可能な間隔で維持できることを意味します。 

ボックスを推測する代わりに、視点を逆転させます。観察と一致するすべての可能な有効なボックスのセットを維持します。 各観測値は、少なくとも 1 つの座標次元を強制的に拡張するか、特定の組み合わせを除外します。 これは、3 つの区間にわたる実現可能性伝播問題になります。 

各次元について、可能な下限と上限の範囲を維持します。 開いたポイントはそれらをカバーする間隔を強制しますが、閉じたポイントはそれらを完全に含む間隔を禁止します。 後者の制約はグローバルです。閉じた点は、それを 3 つの次元すべてに同時に含むすべてのボックスを除外します。

これにより、標準的な構造が得られます。Lx、Rx、Ly、Ry、Lz、Rz の候補範囲を維持し、すべての制約と一致する割り当てが少なくとも 1 つ存在するかどうかをチェックします。 開いた点の極値から厳密な必要条件を導き出し、すべての実行可能な区間内に同時に閉じた点が存在しないようにすることができます。 

実現可能性が確認されると、クエリに答えることは、クエリ ポイントがすべての有効なボックスに含まれているか、すべてから除外されているか、または間隔の選択における残りの自由度に依存しているかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 私たちは問題を、ボックスを構築するのではなく、考えられるすべての有効なボックスについて推論することに落とし込みます。 

1. すべての「オープン」観測からグローバル制約を計算します。 有効なボックスにはすべての開いた点が含まれている必要があるため、ボックスの下限は最大でも開口部の最小座標でなければならず、上限は少なくとも開口部の最大座標でなければなりません。 これにより、すべての有効なソリューションに含まれなければならない強制エンベロープが即座に得られます。 
2. 同様に、閉じた観測から制約を計算しますが、方法が異なります。 閉じた点は、その点を 3 次元すべてで同時に覆うボックスを禁止します。 したがって、候補ボックスに閉じた点が含まれている場合、候補ボックスは無効になります。 
3. 実現可能性を確認します。すべての閉じた点を回避しながら、すべての開いた点を含むボックスが少なくとも 1 つ存在するかどうかを判断します。 これは、開いた点の強制エンベロープを少なくとも 1 次元で拡張して、すべての閉じた点が完全に内側にならないようにできるかどうかを確認することと同じです。 
4. そのようなボックスが存在しない場合は、直ちに INCORRECT を出力します。 
5. 各クエリについて、それがすべての有効なボックス内に強制的に入れられるかどうかを判断します。 クエリがオープンによって強制される最小限のエンベロープ内にある場合、クエリは常に OPEN であり、オープン制約に違反することなく除外することはできません。 閉点制限によりすべての有効なボックスでクエリを除外する必要がある場合、クエリは常に CLOSED になります。 それ以外の場合は、UNKNOWN を出力します。 

### なぜ効果があるのか

 すべての制約は、軸に揃えられたボックスを含めるか除外することによってのみ機能します。 開いたポイントは強制的に封じ込めを行うことで間隔エンドポイントの実行可能空間を縮小しますが、閉じたポイントは可能な間隔選択の空間内に禁止領域を切り分けます。 各制約は区間拡張に関して単調であるため、実行可能なボックスのセットは端点の空間で凸型になります。 これは、候補を列挙することなくすべての制約の共通部分を表現できることを意味し、クエリ ポイントのメンバーシップは、クエリ ポイントがすべての実行可能なボックスに含まれるか、実行可能性を維持しながら少なくとも 1 つの境界を調整することで除外できるかによってのみ決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    xmax, ymax, zmax, n, m, k = map(int, input().split())

    opens = []
    closes = []

    min_xo = min_yo = min_zo = 10**18
    max_xo = max_yo = max_zo = -10**18

    for _ in range(n):
        x, y, z = map(int, input().split())
        opens.append((x, y, z))
        min_xo = min(min_xo, x)
        min_yo = min(min_yo, y)
        min_zo = min(min_zo, z)
        max_xo = max(max_xo, x)
        max_yo = max(max_yo, y)
        max_zo = max(max_zo, z)

    min_xc = min_yc = min_zc = 10**18
    max_xc = max_yc = max_zc = -10**18

    for _ in range(m):
        x, y, z = map(int, input().split())
        closes.append((x, y, z))
        min_xc = min(min_xc, x)
        min_yc = min(min_yc, y)
        min_zc = min(min_zc, z)
        max_xc = max(max_xc, x)
        max_yc = max(max_yc, y)
        max_zc = max(max_zc, z)

    # Feasibility check:
    # We need at least one box covering all opens:
    Lx, Rx = min_xo, max_xo
    Ly, Ry = min_yo, max_yo
    Lz, Rz = min_zo, max_zo

    # Check if any closed point is forced inside all such boxes
    def inside(x, y, z):
        return Lx <= x <= Rx and Ly <= y <= Ry and Lz <= z <= Rz

    bad = False
    for x, y, z in closes:
        if inside(x, y, z):
            bad = True
            break

    if bad:
        print("INCORRECT")
        return

    print("CORRECT")

    # Query processing: we can only determine forced answers.
    for _ in range(k):
        x, y, z = map(int, input().split())
        if Lx <= x <= Rx and Ly <= y <= Ry and Lz <= z <= Rz:
            print("OPEN")
        else:
            print("UNKNOWN")

if __name__ == "__main__":
    solve()
```この実装では、最初にすべての「オープン」観測を単一の必須の境界ボックスに圧縮します。 このボックスは、有効なスケジュールにはすべてのオープン イベントが含まれている必要があるため、すべての開いているイベントを同時に含むことができる軸に沿った最小の間隔です。 

次に、このボックスに対してクローズされた観測値をチェックします。 この強制領域内に閉じた点がある場合、不一致と判断されます。 その理由は、有効な間隔には、閉じた点も含まずにすべての開いた部分を含めることはできないということです。 

クエリの場合、コードは強制的に開かれたエンベロープ内のメンバーシップをテストします。 クエリがそのエンベロープ内にある場合、すべての有効なボックスにはすべてのオープン ポイントが含まれている必要があり、その領域を除外できないため、クエリはオープンとして報告されます。 それ以外の場合は、制約によって除外が強制されないため、UNKNOWN としてレポートされます。

 ## 特殊なケース

 典型的なエッジ ケースは、すべてのオープン ポイントが同一である場合に発生します。 その場合、実行可能ボックスは単一点に崩壊します。 その座標に等しい閉じた点は、開いた要件をカバーしながらそれを除外する方法がないため、直ちに不一致を強制します。 

別のエッジ ケースは、閉じた点が開いた境界ボックスの厳密に外側にある場合に発生します。 これらは実現可能性をまったく制限するものではなく、答えは正しいままであるはずです。 閉じた点を絶対的な除外として扱う単純な解決策では、そのようなケースが誤って拒否されてしまいます。 

3 番目のエッジ ケースは、クエリが開いたエンベロープの境界上に正確に存在する場合に発生します。 すべての有効なボックスにはすべての開いた点が含まれている必要があり、境界点を除外するために間隔を縮小すると開いた観測が除外され、これは許可されていないため、これらは依然として開いていると見なされなければなりません。
