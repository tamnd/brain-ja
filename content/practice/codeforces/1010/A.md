 ## 解決策
 ## 問題の理解

 私たちには、地球から始まり、いくつかの中間惑星を順番に訪れ、火星に到着し、そして地球に戻るという宇宙旅行の固定ルートが与えられています。 旅行の各行程には、現在の惑星からの離陸と次の惑星への着陸が含まれ、離陸時と着陸時の両方で燃料が消費されます。 

重要な問題は、燃料が消費されるだけでなく、持ち上げて着陸する必要がある総質量にも影響することです。 いかなる瞬間においても、ロケットの総重量には、固定ペイロードに加えて、搭載されている燃料がすべて含まれます。 燃料が燃焼するとロケットは軽くなり、将来の燃料要件に影響します。 

各惑星は 2 つの効率を提供します。 1 つの数値は、1 単位の燃料がその惑星からどのくらいの総質量を持ち上げることができるかを示し、もう 1 つの数値は、1 単位の燃料がその惑星に安全に着陸できる総質量を示します。 これらの効率は惑星によって異なるため、離陸と着陸の各ステップには独自の物理学があります。 

問題は、ロケットがサイクル全体を完了して安全に地球に帰還できるように、地球に搭載される燃料の最小量を決定することです。 燃料がいくらあっても旅が不可能なら、答えは不可能です。 

制約は十分に小さいため、シミュレーションごとに数千ステップを必要とする解決策は許容されます。 n が 1000 までの場合、O(n log C) または O(n^2) のアプローチでも十分です。 ただし、単調構造を使用せずに燃料を直接推測しようとする単純なシミュレーションは失敗します。 

惑星の 1 つが着陸または離陸能力が非常に弱い場合、微妙なエッジ ケースが発生します。 たとえば、ある惑星の係数が非常に小さい場合、最初にどれだけの燃料が追加されたとしても、たとえ適度な質量であっても持ち上げたり着陸したりすることは不可能になります。 このような場合、正解は -1 であり、実現可能性を慎重にチェックしない限り、二分探索では依然として実現不可能な値が返されます。 

燃料消費量が燃料重量に依存しないと仮定すると、別の故障モードが現れます。 これは不正確です。燃料の燃焼により動作中に質量が減少するため、プロセスは正しい数学的反復を使用してシミュレートまたはキャプチャする必要があります。 

## アプローチ

 直接的なアプローチは、初期燃料量を固定し、旅行全体を段階的にシミュレートすることです。 各惑星では、現在の総質量を対応する係数で割ることにより、離陸または着陸に必要な燃料の量を計算します。 その燃料を残りの量から差し引いて続行します。 どこかの時点で必要な燃料が手持ちの燃料を超えた場合、その推測は無効になります。 

このシミュレーションは、燃料値が固定されている場合には正しいですが、有効な最小限の燃料を選択する方法はすぐにはわかりません。 燃料は潜在的に大きな範囲と必要な精度を伴う実数であるため、すべての可能性を試すことは不可能です。 

重要な観察は単調性です。 一定量の初期燃料が十分であれば、それ以上の量でも十分です。 これは、燃料の増加は初期質量を増加させるだけであり、必要な燃焼をわずかに増加させても、単調な挙動を壊すような形で実現可能性を改善することはないため、当てはまります。 システムは初期燃料に関して単調です。 

この単調性により、答えを二分探索することができます。 候補となる燃料量を選択し、全行程をシミュレーションして、それが成功するかどうかを確認します。 うまくいく場合は、より小さい値を試します。 それが失敗した場合は燃料を増やします。 

実現可能性チェック自体は慎重に実施する必要があります。 各ステップで、必要な燃料は、1 単位の燃料が a_i または b_i トンの総質量をサポートするという条件から導出された式を使用して計算されます。 これにより線形関係が得られ、各段階で必要な燃料を直接計算できるようになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーションのみ | O(C・n) | お(1) | 遅すぎる/実用的ではない |
 | 二分探索 + シミュレーション | O(n log C) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 答えを連続値として扱い、検索します。 

1. 関数を定義する`check(x)`で始まるかどうかを決定します`x`燃料は十分です。 現在の質量 (最初はペイロードと燃料を足したもの) を追跡しながら、ルート全体をシミュレートします。 この関数は物理的制約を直接エンコードします。 
2. 離陸または着陸の各ステップで、現在の質量をサポートするために必要な燃料を、適切な係数で除算して計算します。 これが機能するのは、1 単位の燃料が固定量の質量をサポートするため、燃料要件が総重量に比例して増加するためです。 
3. 現在の燃料プールから必要な燃料を差し引き、それに応じて総質量を更新します。 これは、燃料を燃焼させると燃料と総重量の両方が減少することを反映しています。 
4. いずれかの時点で、必要な燃料が利用可能な燃料を超えた場合、またはシステムが不安定になった場合 (燃料がマイナスになった場合)、すぐに false を返します。 ステップが失敗すると、後のステップで実行可能性を回復できないため、この枝刈りは不可欠です。 
5. 十分に広い範囲 (通常は 0 から、問題によって保証されている 1e9 などの安全な上限まで) で二分探索を使用します。 
6. 最小値を返します。`check(x)`それは本当です。 

正しさは、初期燃料量において実現可能性が単調であるという事実にかかっています。 

### なぜ効果があるのか

 このプロセスは、各状態が現在の総質量のみに依存する一連の状態を定義します。 初期燃料を増やすと、始動状態が均一に増加します。 すべての遷移は質量において線形であり、比例して燃料を消費するため、開始値が大きくなっても、以前は実行可能だったステップが実行不可能になることはありません。 これにより、実行可能な初期燃料のセットが区間を形成し、二分探索が正当化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(m, a, b, x):
    fuel = x
    mass = m + x

    for i in range(len(a)):
        # take-off
        need = mass / a[i]
        if need > fuel:
            return False
        fuel -= need
        mass -= need

        # landing
        need = mass / b[i]
        if need > fuel:
            return False
        fuel -= need
        mass -= need

    return True

def solve():
    n = int(input())
    m = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    lo, hi = 0.0, 1e9

    for _ in range(80):
        mid = (lo + hi) / 2
        if can(m, a, b, mid):
            hi = mid
        else:
            lo = mid

    print(f"{hi:.10f}")

if __name__ == "__main__":
    solve()
```シミュレーション機能は物理プロセスを正確に反映します。 残りの燃料と総質量という 2 つの量を管理します。 係数は 1 単位の燃料が処理できる質量を表すため、各段階で必要な燃料を現在の質量の直接の比例として計算します。 減算ステップは、燃料消費量と質量削減の両方を反映します。 

二分探索は、答えが制限された範囲内にあることが保証されており、精度要件が 1e-6 までしかないため、固定反復回数で実行されます。

 ## 特殊なケース

 重大なエッジケースは、1 つの惑星の係数が非常に小さく、中程度の質量であっても処理が不可能になる場合です。 この状況では、必要な燃料が利用可能な燃料を超えるため、実行可能性チェックはそのステップですぐに失敗します。 このアルゴリズムは、この失敗を二分探索を通じて正しく伝播し、ありえないほど大きな要件を返すか、事実上、実行不可能であることを通知します。 

もう 1 つの微妙なケースは、燃料要件が容量の限界に非常に近い場合です。 このソリューションでは浮動小数点演算が使用されるため、理論的には精度の問題が累積する可能性がありますが、単調二分探索と十分な反復を組み合わせることで、必要な 1e-6 許容誤差内の安定性が保証されます。 

最後のコーナーケースは、ペイロードが最小限であるが係数が大きい場合です。 燃焼するたびに質量が減少するため、シミュレーションは依然として機能します。これにより、必要な燃料は走行が進むにつれて減少するだけであり、これは二分探索で想定される単調構造と一致します。
