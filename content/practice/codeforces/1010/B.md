 ## 問題の理解

## アプローチ

 正しい解決策では、周期的な破損を無視するのではなく、無効にする必要があります。 重要な観察は、個々の応答が反転する可能性があるにもかかわらず、反転パターンが毎回繰り返されるということです。$n$クエリ。 これは、サイクルを法として制御されたオフセットで比較が繰り返されることを保証すれば、エラーを強制的にキャンセルできることを意味します。 

強引なアイデアは、すべてのサイクル位置の応答シーケンス全体を再構築し、サイクルとサイクルの両方を推定しようとすることです。$x$。 探索が必要になるため、60 クエリ未満ではこれは不可能です$O(mn)$動作、または少なくとも複数の完全なサイクルを完全に観察することはコストがかかりすぎます。 

最適なアイデアは、二分探索を組み合わせることです。$x$構造化されたクエリの繰り返しにより、各決定はサイクルのバランスのとれた見方に基づいて行われます。 単一の比較を信頼するのではなく、隠れサイクルのすべてのフェーズにわたって集計された応答を比較します。 

以来$n \le 30$、サイクルのすべてのフェーズが均一にサンプリングされるように、戦略的に選択された値を繰り返し尋ねることによってクエリ プロセスを「同期」する余裕があります。 これにより、信頼できる比較オラクルをシミュレートできるようになります。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、あらゆる固定要素について信頼できる比較を構築することです。$y$隠れた周期的なノイズにもかかわらず。 

1. かどうかを判断したいかのようにインタラクションを扱います。$x \ge y$。 各クエリは、この比較のノイズを含むバージョンを提供します。 
2. 同じ値で複数のクエリを発行します$y$、隠れたサイクルのすべての位置を均一にカバーするように間隔をあけます。 なぜなら、サイクルの長さは$n$、同じクエリを繰り返す$n$回では、サイクル内の各位置が 1 回だけ寄与することが保証されます。 
3. 答えを合計して解釈します。 真実のシステムは一貫した符号パターンを生成します。つまり、すべての結果が真の比較と一致します。 サイクル内のすべての位置が正確に 1 回サンプリングされるため、サイクルによって引き起こされる敵対的な反転は全期間にわたって相殺されます。 
4. これらから$n$応答に対して、集合符号を計算します。 合計が正の場合、次のように扱います。$x > y$。 負の場合、次のように扱います。$x < y$。 ゼロの場合は、等しいと結論付けます。 
5. この信頼性の高いコンパレータを使用して、間隔で二分探索を実行します。$[1, m]$。 各ステップで、集約クエリ プロシージャを使用して中間点をテストします。 
6. 検索間隔が単一の値になるまで続けます。$x$。 その時点で、それを出力し、すぐに終了します。 

### なぜ効果があるのか

 隠れた不変条件は、サイクル内の各クエリ位置がすべての決定に 1 つの観測値だけを寄与するということです。 シーケンス以来$p$は固定かつ周期的であるため、決定を下す前にすべての位置が同じ頻度でサンプリングされます。 これにより、位置バイアスが除去されます。誤ったフリップは決定ウィンドウ全体で相関付けられないため、それらの正味の寄与はキャンセルされます。 結果として得られる集約された応答は、真の順序付けのための一貫したコンパレータのように動作します。$x$これにより、バイナリ検索で検索空間の正しい半分が決して破棄されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(y):
    print(y)
    sys.stdout.flush()
    return int(input())

def check(y, n):
    # repeat query n times and aggregate
    s = 0
    for _ in range(n):
        r = ask(y)
        if r == 0:
            sys.exit(0)
        s += r
    if s > 0:
        return 1   # x > y
    elif s < 0:
        return -1  # x < y
    else:
        return 0   # x == y

def main():
    m, n = map(int, input().split())

    lo, hi = 1, m
    while lo <= hi:
        mid = (lo + hi) // 2
        res = check(mid, n)

        if res == 0:
            return
        elif res < 0:
            hi = mid - 1
        else:
            lo = mid + 1

    sys.exit(0)

if __name__ == "__main__":
    main()
```の`ask`関数は厳密な対話型プリミティブです。出力されたすべてのクエリは直ちにフラッシュされ、応答が読み取られます。 応答がゼロの場合、プログラムは必要に応じて終了します。 

の`check`機能は中核となる安定化メカニズムです。 同じクエリを繰り返します`n`隠れたサイクル全体を確実にカバーできるようにします。 応答の合計は多数決信号として使用され、ノイズの多いコンパレータを決定的なコンパレータに変換します。 

二分探索では、標準の探索問題とまったく同じように、この安定化されたコンパレータが使用されます。 

実装の微妙な詳細は、ゼロを読み取ると即時に終了することです。 それ以降の実行の継続は、対話型プロトコルでは無効になります。 

## 実用的な例

 ## 特殊なケース

 いつ$m = 1$、すべてのクエリは、唯一の有効な値に即座に収束する必要があります。 いずれかの中間点が 1 であるため、二分探索ループは曖昧さなく終了します。 

いつ$n = 1$、システムは完全に敵対的ですが、ステップごとに一貫性があります。 各クエリはサイクル長にわたる繰り返しによって個別に修正されるため、このアルゴリズムは引き続き機能しますが、この場合は自明です。 

いつ$x$1 または$m$比較では常に制御された方法で区間が内側に移動し、集計により単一の反転された応答によって移動方向が損なわれないことが保証されるため、二分探索では誤って分類されることはありません。 

これらのケースは、アルゴリズムが極端なパラメーター設定の下でも安定したままであり、確率的な仮定に依存しないことを確認します。
