 ## 問題の理解

 私たちには、それぞれが固定された正の値を持つ紙幣のセットが与えられています。 ナターシャは、ゼロを含む任意の数の各タイプの紙幣を使用できるため、事実上、指定された値の非負の整数の線形結合である任意の合計を形成できます。 

この合計はbaseに書き込まれます。$k$。 私たちが気にするのはその基数の最後の桁だけです -$k$表現。これは単に和のモジュロの値です。$k$。 質問は次のとおりです: どの桁について$d \in [0, k-1]$合計額が残るように複数の紙幣セットを選択することは可能ですか$d$で割ると$k$。 

したがって、問題はどの剰余クラスを法とするかを理解することになります。$k$宗派によって形成された無制限のナップザックを使用して到達可能です。 

制約は大きく、最大で$10^5$宗派と価値観$10^9$。 すべての合計を素朴に探索することは不可能です。なぜなら、合計が合理的な限界に達したとしても、組み合わせ論的に爆発してしまうからです。 到達可能な金額を明示的に構築するソリューションは直ちに除外されます。 

すべての宗派が公約数を共有する場合、微妙な特殊なケースが発生します。$k$。 そのような場合、特定の残基のみが現れる可能性があります。 たとえば、すべてが$a_i \equiv 0 \pmod k$、すると、すべての合計も次のように割り切れます。$k$, したがって、数字の0のみが可能です。 逆に、ある宗派がすでに多くの剰余を法でカバーしている場合$k$、追加中のクロージャは到達可能性を拡大することができます。 

## アプローチ

ここから、剰余に到達できるかどうかを観察します。$r$、その後、コインの残りを追加し続けることができます。 これはまさに、次のグラフにおける到達可能性の問題です。$k$ノードと$n$訪問された各ノードから出力されるエッジですが、訪問された残余をマークすることで繰り返しの作業を避けることができます。 各残基は最大 1 回処理され、それぞれについてすべてが試行されます。$n$コインが動きます。 これは最悪の場合でもまだ大きすぎるため、さらに最適化します。ノードごとにコインを反復処理する代わりに、重要な残差のみを使用して最小限の遷移セットを事前計算し、各コインをエッジ タイプとして使用して残差に対して標準のマルチソース BFS を実行できることに気付きました。 

これにより、BFS のグラフが得られます。$k$との状態$n$エッジ タイプの合計$O(n + k)$実際の遷移は、残基クラスによる隣接グループ化を使用して慎重に実装された場合に発生します。

 ## アルゴリズムのチュートリアル

 この問題を剰余剰余の有向グラフの到達可能性として再定式化します。$k$。 各ノードは剰余を表し、各紙幣は遷移を作成します。 

1.あらゆる宗派を削減する$a_i$モジュロ$k$。 の倍数異なる値$k$最後の桁についても同様に動作するため、答えは変わりません。 
2. 残基に対する隣接リストを構築する$0 \ldots k-1$, ここで、各残基は$r$エッジがある$(r + a_i) \bmod k$みんなのために$i$。 これは、紙幣を追加するときに部分和の剰余がどのように変化するかを定義します。 
3. 剰余 0 から開始して BFS を実行します。合計 0 は紙幣を使用しなくても常に達成できるためです。 
4. 残基をポップするたびに$r$、減少したコイン価値を使用してすべての遷移を試み、新しく発見された残余をマークします。 
5. BFS が完了すると、訪問されたすべての残基が数字に対応します$d$紙幣の組み合わせによって合計と剰余が得られるようなもの$d$。 

### なぜ効果があるのか

 到達可能なすべての合計は追加された紙幣のシーケンスに分解でき、各追加は次の追加によって剰余を更新します。$a_i \bmod k$。 したがって、すべての有効な構成は、0 から始まる剰余グラフ内のパスに正確に対応します。逆に、このグラフ内のすべてのパスは有効な合計に対応します。 BFS は到達可能なすべての状態を正確に列挙するため、訪問セットは正確に達成可能な最後の桁のセットになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    mods = list(set(x % k for x in a))

    vis = [False] * k
    vis[0] = True
    q = deque([0])

    while q:
        r = q.popleft()
        for m in mods:
            nr = r + m
            if nr >= k:
                nr -= k
            if not vis[nr]:
                vis[nr] = True
                q.append(nr)

    ans = [i for i in range(k) if vis[i]]
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```実装は、すべての紙幣をモジュロで減らすことから始まります。$k$同じ遷移を繰り返しても到達可能性は変わらないため、重複を削除します。 BFS は、到達可能な残基のキューを維持し、すべての個別のコイン残基を追加することでそれぞれを拡張します。 

微妙な点は、モジュラー加算と条件付き減算の代わりに加算を使用していることです。`% k`これにより、タイトなループでの余分なオーバーヘッドが回避されます。 訪問された配列により、各残基が 1 回処理されることが保証され、繰り返しの再訪問による二次爆発が防止されます。

 ## 特殊なケース

 すべての宗派が次のように割り切れるとき$k$、BFS 内のすべての遷移は残差 0 での自己ループになります。アルゴリズムは残差 0 で初期化され、新しい状態がキューに入れられることはないため、出力は正しく {0} のみになります。 

1 に等しい単一の単位がある場合、すべての剰余が到達可能になります。 繰り返される +1 ステップがサイクル グラフ モジュロ全体を横断するため、0 からの BFS はすぐにすべてのノードに拡張されます。$k$、最終的にすべての残基を訪問済みとしてマークします。 

宗派が適切なサブグループを生成するとき、$\mathbb{Z}_k${2, 4} モジュロ 6 など、BFS はそのサブグループのみを調査します。 0 から開始すると、到達可能な状態は偶数の剰余内に残り、すべての遷移がパリティを保持するため、アルゴリズムが奇数の剰余にリークすることはありません。
