 ## 解決策
 ## 問題の理解

 与えられた構造は、すべてのノードが論理コンポーネントのように動作するルート付きツリーです。 リーフは固定のブール入力ですが、内部ノードは AND、OR、XOR、NOT などの標準ゲートを使用して子からブール値を計算します。 ルート ノードは、回路全体の最終出力を生成します。 

問題は、すべての入力リーフが既知の初期値を持っていることですが、値が反転される可能性があるという意味で、これらの入力のうちの 1 つだけが故障していることがわかります。 課題は、どれが壊れているかを見つけることではありません。 代わりに、入力リーフごとに、その特定のリーフが反転され、他のすべてのリーフが変更されない場合にルートの出力がどうなるかを個別に判断する必要があります。 

したがって、各入力リーフに対して、概念的にはそのリーフでシングルビット反転を適用し、ルート出力を再計算します。 これを単純に行うと、大きなツリーを葉ごとに 1 回再評価することになりますが、ノード数が 100 万に達すると、これでは遅すぎます。 

この制約は、入力ごとに値を最初から再計算するソリューションは実行不可能であることを直ちに意味します。 完全な走査には線形時間がかかるため、すべてのリーフに対してこれを繰り返すと、最悪の場合、二次的な動作が発生します。 代わりに、すべてのクエリで計算を再利用し、「反転の効果」情報をツリー全体に伝播する方法が必要です。 

ローカルで考えると、微妙な落とし穴が現れます。入力を反転すると、その親に影響を与えるだけでなく、信号が計算パスに実際に関連するかどうかに応じて、ルートに影響を与える場合もあれば、影響しない場合もあります。 たとえば、AND ゲートでは、もう一方の入力が 0 の場合、1 つの子を反転しても出力は変わりません。 正しいソリューションでは、生の値の伝播ではなく、この感度の概念を捉える必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 入力リーフごとに、その値を反転し、事後探索ですべてのノード値を再計算し、ルートを記録します。 これは正しいです。各評価で決定論的回路が完全に再計算されるからです。 ただし、各再計算には O(n) のコストがかかり、最大 O(n) 個の葉に対してこれを実行すると O(n²) になります。これは、n が 10⁶ である場合の制限をはるかに超えています。 

重要な点は、回路がツリーであり、各ノードの出力がその子にのみ依存していることです。 さらに重要なのは、計算を 2 つの独立した情報、つまり各ノードが現在生成している値と、そのノードが各子の変更に対する感度をどの程度受けているかに分離できることです。 

これは、関数グラフ上のツリー DP の標準的なアイデアにつながります。出力を最初から再計算する代わりに、すべてのノードの出力を 1 回計算し、次に「このノードが反転すると、ルートも反転しますか?」という質問に答える 2 回目のトラバーサルを使用して、ルートに対する各サブツリーの寄与を計算します。 

すべてのノードに対して、元の回路で生成される値を定義します。 次に、2 番目の量、つまりルート出力に対するノードの値を切り替える効果を定義します。 これは本質的に、ツリーを介した逆伝播です。 ルートの感度は 1 に固定され、親子関係ごとにゲートの種類と兄弟の値に応じて影響がどのように流れるかを決定します。 

重要な簡素化は、各ゲートをローカルで分析できることです。 たとえば、AND ゲートでは、出力は他の子が 1 の場合にのみ子に依存します。他の子が 0 の場合、出力はすでに固定されており、影響を受けません。 同様の推論が OR と XOR にも当てはまりますが、NOT は単に反転によって感度を渡します。 

これにより、問題はツリー上の 2 つの線形パスに変換されます。

 ## アルゴリズムのチュートリアル

ツリーをノード 1 にルートし、エッジを親子関係として扱います。 入力 (葉) は初期値のソースです。 

1. リーフからルートへの事後探索を使用して、すべてのノードの値を計算します。 各内部ノードについて、その論理演算をその子の値に適用します。 これにより、システムの最終出力と、感度推論に必要なすべての中間値が得られます。 
2. すべての内部ノードについて、解析中にその子を明示的に記録し、後で影響を後方に伝播できるようにします。 感度は兄弟値に依存するため、この構造は不可欠です。 
3. ブール配列を定義する`dp[v]`ノードを反転するかどうかを意味します`v`ルート出力を反転します。 
4.初期化`dp[1] = 1`ルートを反転すると、明らかにそれ自体が反転するからです。 
5. DFS または反復スタックを使用して、ツリーをルートから下にたどります。 各ノードで`v`、私たちは方法を決定します`dp[v]`その子供たちに配布します。 
6. それぞれの子どもたちに対して`u`ノードの`v`、変更するかどうかを計算します`u`影響を与える`v`。 これは、ゲートのタイプと、ゲートの他のすべての子の値によって異なります。`v`。 

AND の場合、子は他のすべての子が 1 の場合にのみ親に影響します。OR の場合、子は他のすべての子が 0 の場合にのみ親に影響します。XOR の場合、すべての子は他の子に関係なく独立して親に影響します。 NOT の場合、単一の子は常に親に影響を与えます。 
7. お子様の場合`u`親に影響を与える`v`、 それから`dp[u]`になる`dp[v]`の変化のため、`u`に伝播します`v`、そしてそれが到達した場合`v`、すでに捕捉されているのと同じ感度で上向きに伝播し続けます。`dp[v]`。 
8. ツリー全体に伝播した後、出力`dp[v]`すべての入力ノードに対して。 

### なぜ効果があるのか

 正確さは、ルートの出力がリーフに対するブール関数であり、各内部ノードがローカルのブール関数を構成しているという事実に基づいています。 ノードに対するルートの依存関係は、そのノードからルートへの「アクティブな影響」のパスが存在するかどうかによって完全に決定されます。 dp 値はそのようなパスが存在するかどうかを正確に追跡し、ローカル ゲート条件により、ゲートが他の入力によってまだ固定されていない場合にのみインフルエンスが通過することが保証されます。 これにより、過剰なカウントが防止され、反転によって最終出力が変更される場合に限り、各リーフがルートに対して敏感であるとマークされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())

g = [[] for _ in range(n + 1)]
typ = [""] * (n + 1)
val = [0] * (n + 1)

children = [[] for _ in range(n + 1)]
parent = [0] * (n + 1)

for i in range(1, n + 1):
    tmp = input().split()
    typ[i] = tmp[0]
    if typ[i] == "IN":
        val[i] = int(tmp[1])
    else:
        for x in tmp[1:]:
            x = int(x)
            children[i].append(x)
            parent[x] = i
            g[i].append(x)
            g[x].append(i)

# compute values bottom-up using postorder
order = []
stack = [1]
visited = [False] * (n + 1)
visited[1] = True

while stack:
    v = stack.pop()
    order.append(v)
    for u in g[v]:
        if not visited[u]:
            visited[u] = True
            stack.append(u)

order.reverse()

for v in order:
    if typ[v] == "IN":
        continue
    if typ[v] == "NOT":
        val[v] = 1 - val[children[v][0]]
    elif typ[v] == "AND":
        val[v] = val[children[v][0]] & val[children[v][1]]
    elif typ[v] == "OR":
        val[v] = val[children[v][0]] | val[children[v][1]]
    elif typ[v] == "XOR":
        val[v] = val[children[v][0]] ^ val[children[v][1]]

dp = [0] * (n + 1)
dp[1] = 1

def dfs(v):
    for u in children[v]:
        if typ[v] == "NOT":
            dp[u] = dp[v]
            dfs(u)
        elif typ[v] == "XOR":
            dp[u] = dp[v]
            dfs(u)
        elif typ[v] == "OR":
            other = children[v][0] ^ children[v][1] ^ u
            if val[other] == 0:
                dp[u] = dp[v]
                dfs(u)
        elif typ[v] == "AND":
            other = children[v][0] ^ children[v][1] ^ u
            if val[other] == 1:
                dp[u] = dp[v]
                dfs(u)

dfs(1)

res = []
for i in range(1, n + 1):
    if typ[i] == "IN":
        res.append(str(dp[i]))
print("".join(res))
```最初のフェーズでは、逆のトポロジー順序を使用して実際のゲート出力を計算します。 第 2 フェーズでは、感度をルートから下に伝播します。 重要な詳細は、XOR トリックを使用して「他の子」を効率的に計算することです。これにより、ノードごとの余分なループが回避されます。 条件チェックは、子がその親に関連するゲート固有の条件を実装します。 

実装上の微妙な点の 1 つは、現在の兄弟値が指定された場合に、子が実際に親に影響を与えることができる場合にのみ、感度が伝播されることです。 これが、OR ではもう一方の入力が 0 である必要があり、AND ではもう一方の入力が 1 である必要があるすべての理由です。 

## 実用的な例

 いくつかの入力が小さなツリーを介して結合されるサンプル回路を考えてみましょう。 

最初に値を計算します。 

| ノード | タイプ | 子どもたち | 値 |
 | --- | --- | --- | --- |
 | 2 | インド | - | 1 |
 | 3 | インド | - | 1 |
 | 6 | インド | - | 0 |
 | 8 | インド | - | 1 |
 | 9 | インド | - | 1 |
 | 10 | そして | 2,8 | 1 |
 | 4 | XOR | 6,5 | 依存します |
 | 1 | そして | 9,4 | 最終 |

 ここで、感度を伝播します。 

| ノード | DP | 理由 |
 | --- | --- | --- |
 | 1 | 1 | ルート |
 | 9 | 0 | AND | の兄弟に依存します。 
| 4 | 1 | XOR | を通過します。 
| 6 | 0 | 上流の OR/AND 条件によってブロックされています。 
| 8 | 1 | 兄弟が影響力を与える |
 | 2 | 1 | 兄弟が 1 なので AND を通過します |

 これにより、構造的に関連する入力のみがルートに影響を与えることが確認されます。 

2 番目のトレースは、一方の子がもう一方の子からの影響を完全にブロックする OR ゲート シナリオに焦点を当てています。 これは、ゲート条件なしの生の DFS 伝播がすべてのリーフを影響があると誤ってマークする理由を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、ノードが AND ゲートで、一方の子がすでに 0 である場合に発生します。その場合、他方の子を反転しても出力に影響を与えることができないため、感度はそこで停止する必要があります。 アルゴリズムは、dp を伝播する前に兄弟値をチェックすることでこれを処理します。 

もう 1 つのケースは、一方の子が 1 である OR ゲートです。もう一方の子の変更は無関係で、dp の伝播は条件によって正しくブロックされます。`val[other] == 0`。 

最後のケースは XOR ゲートと NOT ゲートのチェーンで、すべてのフリップが常にパスを介して伝播します。 XOR と NOT には固定出力のブロッキング動作がないため、dp は自由に流れ、深い線形構造であっても正確性が保証されます。
