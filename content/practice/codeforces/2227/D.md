 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$2n$。 からのすべての値$0$に$n-1$正確に 2 回表示されます。 タスクは、左から右と右から左に同​​じ内容を読み取るこの配列の連続したセグメントを選択することです。そのようなすべてのセグメントの中で、mex ができるだけ大きいセグメントが必要です。 

セグメントの mex は、純粋にセグメント内にどの小さな値が存在するかによって決まります。 セグメントに次のすべての数値が含まれている場合、$0$まで$k-1$、その場合、その mex は少なくとも$k$。 したがって、この問題は、$0$できるだけ。 

制約が意味するのは、$n$まで可能です$10^5$テスト ケースごとに、すべてのテストの合計配列サイズは最大でも$2 \cdot 10^5$。 これにより、部分配列の二次列挙が除外されます。 すべてのセグメントをチェックしたり、候補間隔ごとにプロパティを再計算しようとしたソリューションは、すぐに制限時間を超過します。 入力の構造、特にすべての数値が正確に 2 回出現するということは、値の位置と間隔の包含が中心となることを示唆しています。 

「必要な値をすべてカバーする」だけで十分であると想定すると、微妙な問題が生じます。 セグメントに必要なすべての数値が両方とも含まれている場合でも、回文ではない可能性があります。 たとえば、セグメントには値の対称カバレッジが含まれていても、他の要素によって導入された順序付けの制約によりミラー対称性が崩れる場合があります。 もう 1 つのエッジ ケースは、より必要な値を含めるために有効な回文セグメントを拡張すると、回文性が破壊される可能性があるため、単純な意味では実現可能性は単調ではありません。 

## アプローチ

 ブルートフォース手法は簡単です。すべての部分配列を列挙し、それが回文であるかどうかを確認し、その mex を計算し、最大値を追跡します。 回文のコストをチェックする$O(n)$直接実行した場合はサブ配列ごとに、$O(n^2)$サブ配列、結果として$O(n^3)$最悪の解釈でのテストごとの合計時間、または$O(n^2)$回文チェックのためのハッシュを使用します。 いずれにせよ、これは許容範囲をはるかに超えています$n = 10^5$。 

重要な構造観察は、mex がどのように動作するかから得られます。 少なくともmexを達成するには$k$、部分配列にはすべての値が含まれている必要があります$0,1,\dots,k-1$。 各値は正確に 2 回出現するため、必要な値のセットを決定すると、すべての出現を含む最小間隔が固定されます。つまり、最初の出現の最小値から始まり、2 回目の出現の最大値で終了します。 mex の有効な候補セグメント$k$にはこの間隔が含まれている必要があります。 

これにより、問題はそれぞれの単一の正規候補間隔に縮小されます。$k$。 これらの間隔は段階的に計算できます。 残りの問題は、この間隔が回文を形成するかどうかです。 これは、配列に対するローリング ハッシュとその逆を使用して一定時間でチェックできます。 これにより、問題は最大の値を探すことに変わります。$k$対応する間隔は回文形式になります。

 ## アルゴリズムのチュートリアル

 2 つの要素を中心にソリューションを構築します。値のすべての出現を含む最小間隔です。$0$を通して$k-1$、高速回文チェッカー。 

1. すべての値の最初と 2 番目の出現を事前計算します。 

これが必要なのは、値を含む有効なセグメントには両方のオカレンスが含まれている必要があり、そうでないとその値を完全に含むことができず、mex の増加に寄与できないためです。 
2. 2 つのアレイを構築する$L[k]$そして$R[k]$。$L[k]$値の中で最初に出現する最小値です$0 \dots k-1$、 そして$R[k]$同じ値の 2 番目の出現の最大値です。 これにより、必要な値をすべて含む最小のセグメントが得られます。 
3. 配列のプレフィックス ハッシュと反転配列のプレフィックス ハッシュを事前計算します。 

これにより、セグメントが存在するかどうかをテストできます。$[l,r]$の回文です$O(1)$その順方向ハッシュを対応する逆方向セグメント ハッシュと比較することによって。 
4. 固定の場合$k$、候補セグメントを定義します$[L[k], R[k]]$。 

このセグメントは、すべての値が含まれることが保証されている唯一の最小領域です。$0 \dots k-1$。 他の有効なセグメントにはそれが含まれている必要があるため、このセグメントが失敗した場合、より小さい対称拡張では mex 制約を変更せずに不足している必要な値を修正できません。 
5. ハッシュを使用して、このセグメントが回文であるかどうかを確認します。 

もしそうなら、少なくともメキシコ$k$達成可能です。 
6. 最大の二分探索$k$このセグメントは回文です。 

任意の問題では実現可能性は厳密には単調ではありませんが、ここでは$L[k]$そして$R[k]$として展開$k$が増加し、回文条件が満たされなくなると、より大きな間隔を満たすことがさらに難しくなります。 

### なぜ効果があるのか

 少なくとも mex を含むすべての有効な回答$k$のすべての出現を含める必要があります$0 \dots k-1$をセグメントに強制的に含めます。$[L[k], R[k]]$。 このようなセグメントは、この間隔より短くすることはできません。 したがって、この最小のカバー間隔さえ回文でない場合、mex を達成するセグメントは存在しません。$k$存在します。 逆に、回文の場合は、必要な値がすべて含まれており、有効な候補となります。 これにより、サブ配列のグローバル検索が、1 つのインターバルごとの決定的なチェックに減ります。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hash(arr, base=91138233, mod=10**9+7):
    n = len(arr)
    pref = [0] * (n + 1)
    p = [1] * (n + 1)
    for i in range(n):
        pref[i + 1] = (pref[i] * base + (arr[i] + 1)) % mod
        p[i + 1] = (p[i] * base) % mod
    return pref, p

def get_hash(pref, p, l, r, mod=10**9+7):
    return (pref[r + 1] - pref[l] * p[r - l + 1]) % mod

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        first = [n] * n
        second = [-1] * n

        for i, x in enumerate(a):
            if first[x] == n:
                first[x] = i
            second[x] = i

        L = [0] * (n + 1)
        R = [0] * (n + 1)

        L[0] = n
        R[0] = -1

        for i in range(n):
            L[i + 1] = min(L[i], first[i])
            R[i + 1] = max(R[i], second[i])

        ra = a[::-1]
        pref_f, pf = build_hash(a)
        pref_r, pr = build_hash(ra)

        def is_pal(l, r):
            n2 = len(a)
            h1 = get_hash(pref_f, pf, l, r)
            rl = n2 - 1 - r
            rr = n2 - 1 - l
            h2 = get_hash(pref_r, pr, rl, rr)
            return h1 == h2

        lo, hi = 0, n
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            l = L[mid]
            r = R[mid]

            if l <= r and is_pal(l, r):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装は、すべての値の最初と最後の出現を記録することから始まります。 特定の mex の候補セグメントには、必要な各値の両方の出現が含まれている必要があるため、これらは不可欠です。 

配列$L$そして$R$値の各プレフィックスが一致するように増分的に構築されます。$0 \dots k-1$明確に定義された最小カバー間隔があります。 これにより、最小値と最大値を繰り返し再計算することが回避されます。 

2 つのローリング ハッシュ構造が構築され、1 つは元の配列上に、もう 1 つはその反転バージョン上に構築されます。 これにより、対応する前方セグメントと後方セグメントを比較することにより、定数時間の回文チェックが可能になります。 

二分探索では、考えられる mex 値を調べます。 候補者ごとに$k$、すべての必要な値をカバーする最小間隔が回文であるかどうかをテストします。 そうであれば、増やすように努めます$k$; それ以外の場合は、それを減らします。 

一般的な実装の落とし穴は、ハッシュを比較する際に、反転された配列と元の配列の間でインデックスが正しく変換されないことです。 マッピング$l \rightarrow n-1-r$そして$r \rightarrow n-1-l$off-by-one エラーを避けるために、慎重に扱う必要があります。

 ## 特殊なケース

 重大なエッジ ケースは、一連の値の最小カバー間隔が大きいにもかかわらず対称的な場合に発生します。 このような場合、単純なアプローチでは間隔を縮小しようとする可能性がありますが、縮小すると必要な値が 1 回発生する可能性があるため、縮小するとすぐに mex 保証が無効になります。 アルゴリズムは常に強制間隔を使用することでこれを回避します。$[L[k], R[k]]$、結果として得られるセグメントの構造的妥当性のみをテストしながら、必要な値の完全性を保証します。
