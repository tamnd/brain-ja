 ## 解決策
 ## 問題の理解

 開き括弧と閉じ括弧のみで構成される文字列が与えられます。 1 回の操作で、連続したブロックを取得して削除し、残りの文字列の任意の場所にその文字を再挿入することができます。削除された文字を完全に自由に並べ替えて、それぞれを独立して配置することができます。 

問題は、何もしないか、この 1 つの動きを適用した後、すべてのプレフィックスに開き括弧よりも閉じ括弧が多くなることはなく、開いている括弧の合計数が閉じている括弧に等しい有効な括弧シーケンスを取得できるかどうかです。 

制約は大きく、すべてのテスト ケースの合計長は最大 200,000 です。 これにより、テスト ケースごとの 2 次または 3 次のアイデアが即座に排除されます。 どのソリューションも、入力に対して線形または線形に近い時間で実行する必要があります。 

この操作の微妙な点は、削除されたセグメントの内部順序が保持されないことです。 削除された文字は、どこにでも挿入できる無料のマルチセットになります。 これにより、任意に配置された括弧を使用して不均衡を局所的に「修復」できるため、この操作は標準的な部分文字列の移動や回転よりもはるかに強力になります。 

素朴な推論を破る傾向があるエッジケースは、操作が構造を保持すると仮定することから生じます。 たとえば、「())(」のような文字列では、単純な試みでは隣接するスワップだけが重要であると考えるかもしれませんが、この操作では選択したブロックを完全に再シャッフルし、局所的ではない方法でグローバルな実現可能性を変更する可能性があります。

 もう 1 つのよくある落とし穴は、プレフィックス制約を無視することです。 オープンの総数がクローズに等しい場合でも、「())(()」のような文字列は、リムーバブル ブロックを使用してプレフィックスの不足をどのように修正できるかを明示的に推論しない限り、単純な再配置の直観によって修正することはできません。

 ## アプローチ

 ブルートフォースアプローチでは、すべての部分文字列を削除しようとします。 選択ごとに、その文字の削除をシミュレートし、残りの文字列への文字の挿入をすべて試して、有効なブラケット シーケンスが生成される配置かどうかを確認します。 削除されたブロック内の順列を無視し、配置のみを考慮したとしても、文字を分散する方法の数は部分文字列の長さで指数関数的に増加します。 これは、50 歳前後の n でもすぐに実行不可能になります。 

重要な簡素化は、操作で変更できるものと変更できないものを分離することで実現します。 部分文字列を削除すると、2 つの部分が生成されます。固定された順序付けされたシーケンスと、どこにでも配置できる括弧のバッグです。 固定部分は、満たさなければならないプレフィックス制約を課しますが、バッグは、マイナスのプレフィックス バランスを修復するのに十分な早めに追加の開始ブラケットを提供することによってのみ役立ちます。 

これにより、問題は、削除後の残りのシーケンスにおけるプレフィックスの不均衡に関する推論に帰着します。 候補の残りのシーケンスを調べる場合、その最悪のプレフィックス不足を、残高がゼロよりどの程度下回るかとして定義します。 取り外し可能なブロックは、問題のあるプレフィックスの前に開口部を配置できるため、その不足を補うのに十分な開口部ブラケットを提供できます。 

したがって、タスクは次のようになります。削除する左括弧の数が、少なくとも残りの文字列の最大プレフィックス不足と同じになるように、削除されるセグメントを選択できるか?

 これにより、問題は、考えられるすべての削除にわたる単一の数量の制御に変換され、元の文字列の接頭辞分析によって処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース削除 + 再構築 | 指数 | O(n) | 遅すぎる |
 | プレフィックスバランス + 最適な分割推論 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックスバランスを、開始ブラケットと終了ブラケットのランニングの差として定義します。

1. 文字列全体にわたるプレフィックスのバランスを計算します。 これは、変更せずに左から右に読まれた場合にシーケンスがどのように動作するかを示します。 
2. 開き括弧と閉じ括弧の合計数が等しいかどうかを確認します。 そうでない場合、操作により文字数が保持されるため、再配置しても不均衡を修正できません。 
3. 文字列全体のプレフィックスの最小バランスを追跡します。 この値は、シーケンスが有効な状態を下回るまでにどれだけ深くなるかを測定します。 
4. プレフィックスの最小残高がすでに負でない場合、その文字列はすでに有効な括弧シーケンスであるため、すぐに「はい」と答えることができます。 
5. それ以外の場合は、部分文字列を削除するとどうなるかを検討してください。 セグメントを削除すると、一部の右括弧と左括弧がプレフィックス構造から削除されます。これにより、影響を受ける領域のプレフィックスのバランスが増加するだけです。 
6. 重要な観察は、削除されたセグメントの唯一の有益な効果は、再挿入されたときに元に戻る左括弧の数だけであるということです。 その数をkとしましょう。 
7. 残りの固定部分には、最大接頭辞不足 d があり、これは、閉じ括弧と比べて開き括弧が d だけ短い接頭辞が存在することを意味します。 
8. 問題は、k が少なくとも d である k 個の開き括弧を提供する削除されたセグメントを選択できるかどうかに帰着します。 
9. 削除するセグメントを自由に選択できるため、常に最悪の欠損を減らす領域をキャプチャするように削除を調整できます。最適な選択は、最も深いプレフィックス ディップの周囲をカットすることに対応します。 
10. したがって、開始カウントが残りの部分の避けられないプレフィックス不足をカバーするのに十分な大きさのセグメントが存在するかどうかを判断するだけで済みます。これは、元の文字列のプレフィックスの極値から推測できます。 

### なぜ効果があるのか

 この操作では 1 つの括弧の複数セットに対してのみ自由が与えられ、残りのシーケンスでは順序の制約が維持されます。 残りのシーケンス内のすべての無効なプレフィックスは、そのプレフィックスが始まる前に十分な左括弧を挿入して修正する必要があります。 利用可能な開口部の数は、削除される開口部の数にのみ依存し、この数量は選択したセグメントによって全体的に制限されます。 元の文字列のプレフィックス構造は、欠損が現れる可能性のある場所を正確にエンコードしており、セグメントを削除しても、その構造の連続部分のみを平滑化できます。 これにより、実現可能性の条件は、プレフィックスの最小値と、それらをどれだけオフセットできるかに完全に依存します。これは、バランス配列をスキャンすることによって完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        bal = 0
        min_bal = 0

        for ch in s:
            if ch == '(':
                bal += 1
            else:
                bal -= 1
            if bal < min_bal:
                min_bal = bal

        # necessary condition: equal number of brackets
        if bal != 0:
            print("NO")
            continue

        # already valid if never dips below 0
        if min_bal >= 0:
            print("YES")
        else:
            print("YES")

solve()
```この実装では、推論がその中核となる観察可能な部分、つまりプレフィックスのバランスとその最小値に圧縮されます。 プレフィックスの不均衡はリムーバブル セグメントの柔軟性を利用することで修正できるため、最終的な決定は崩れます。唯一絶対に不可能なのはカウント全体の不一致です。 

重要な点は、操作をまったくシミュレートしていないことです。 代わりに、プレフィックス不足がどのように動作するか、および削除された部分文字列を通じてどの程度の「開始予算」を再配置できるかという観点から完全に推論します。 

## 実用的な例

 ### 例 1

 入力文字列：「()()」

 このシーケンスは、プレフィックスバランスにおいてゼロを下回ることはありません。 最小プレフィックス残高は 0 で、合計残高は 0 です。 

| ステップ | 文字 | バランス | 最小残高 |
 | --- | --- | --- | --- |
 | 1 | ( | 1 | 0 |
 | 2 | ) | 0 | 0 |
 | 3 | ( | 1 | 0 |
 | 4 | ) | 0 | 0 |

 シーケンスはすでに有効であるため、何も操作する必要がなく、答えは「YES」です。 これは、操作が無関係である場合を示しています。 

### 例 2

 入力文字列: “)(()”

 | ステップ | 文字 | バランス | 最小残高 |
 | --- | --- | --- | --- |
 | 1 | ) | -1 | -1 |
 | 2 | ( | 0 | -1 |
 | 3 | ( | 1 | -1 |
 | 4 | ) | 0 | -1 |

 プレフィックスの最小値は負であり、元の構造が無効であることを意味します。 ただし、問題のある配置には開始部と終了部が 1 つずつ存在し、単一の部分文字列を削除することで反転を分離して再分配することができ、有効な再構築が可能になります。 これは、この操作の役割を示しています。局所的な不均衡を解消し、その修正をグローバルに再配分できるということです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | 各文字列は 1 回スキャンされ、プレフィックスのバランスが計算されます。 
| スペース | お(1) | 少数のカウンターのみが維持されます。 

合計入力サイズは 2 × 10^5 で制限されるため、テスト ケースごとの線形スキャンは時間制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        bal = 0
        min_bal = 0
        for ch in s:
            bal += 1 if ch == '(' else -1
            min_bal = min(min_bal, bal)

        if bal != 0:
            out.append("NO")
        else:
            out.append("YES")

    return "".join(out)

# provided sample (interpreted)
assert run("1\n2\n()\n") == "YES", "sample 1"

# all opens then closes
assert run("1\n4\n(())\n") == "YES", "already valid"

# invalid imbalance
assert run("1\n3\n())\n") == "NO", "impossible due to count/structure"

# alternating bad
assert run("1\n4\n)(() \n".replace(" ", "")) == "YES", "fixable case"
```カスタム ケースでは、すでに有効なシーケンス、構造的に不可能なシーケンス、および許可された操作の柔軟性を使用してローカル反転を修復できるケースが区別されます。
