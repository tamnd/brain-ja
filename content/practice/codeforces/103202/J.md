 ## 解決策
 ## 問題の理解

 さまざまなサイズを維持しています$n$、最初はすべてゼロで、値は増加するだけです。 ただし、増分は均一に適用されません。 代わりに、トレーニング操作は値をターゲットとします。$x$現在等しい位置のみをインクリメントします$x$セグメント内。 

これにより、「階層化された」展開が作成されます。値は 0 から 1、次に 1 から 2 などに移動しますが、これは現在の値と一致するクエリによって明示的にアクティブ化された場合に限られます。 

出力クエリはいつでも範囲の最大値を要求するため、選択的な値の遷移と高速な範囲の最大値取得の両方をサポートする構造が必要です。 

制約は大きく、両方とも$n$そして$q$まで$5 \times 10^5$これにより、クエリごとに各要素に触れるソリューションが即座に除外されます。 平$O(n \log n)$クエリごとに実行すると遅すぎます。 影響を受けるセグメントごとの償却対数に近い値が必要です。 

微妙なエッジ ケースは、同じ値の繰り返し更新によって引き起こされます。 

素朴なアプローチが失敗する例は、次のようなシーケンスです。 

入力:$n = 5$操作:

 トレーニング$1, 5, 0$トレーニング$1, 5, 1$クエリ$1, 5$単純な実装では、各操作の範囲全体を繰り返しスキャンして要素を更新する可能性があり、密度が高い場合には二次関数になります。 

トレーニング操作により、次の範囲内のすべての値が均一に増加すると仮定すると、別の障害モードが発生します。$x$に$x+1$。 完全一致のみが移動されるはずなので、これは不正確です。 

## アプローチ

 ブルート フォース シミュレーションでは、各クエリを反復処理して直接処理します。$[l, r]$、各要素をチェックし、一致する場合は値を更新します。$x$。 これは正しいですが、高価です。 それぞれの操作にかかる費用$O(n)$、合計を与えます$O(nq)$のオーダーです。$2.5 \times 10^{11}$最悪の場合の操作は明らかに実行不可能です。 

重要な観察は、値を決して減少させず、すべての要素が離散状態を経て遷移するということです。$0 \to 1 \to 2 \to \dots$。 各要素は最大でも値を変更します$O(\text{max level})$しかし、より重要なのは、各遷移は現在の値の特定の「バケット」内にあるかどうかにのみ依存することです。 

これは、値ごとに維持することを示唆しています$x$、現在保持しているポジションのセット$x$。 次に、トレーニング操作$[l, r, x]$は、値のセットの共通部分にあるすべてのインデックスを検索します。$x$と$[l, r]$、バケツから取り出します$x$、バケットに挿入します$x+1$。 

範囲の交差を効率的にサポートするために、各バケットをバランスの取れた BST または一連の素な間隔のような順序付けされた構造として保存できますが、標準的な競技プログラミング ソリューションではセグメント ツリーまたは値ごとの順序付きセットを使用し、間隔を慎重にマージおよび分割します。 

より効率的な観点は、各ノードが値の頻度または圧縮されたセグメントを表すマップまたは構造を格納するセグメント ツリーを維持することですが、それは重くなります。 

意図したソリューションでは、代わりに DSU のような賢い間隔圧縮トリックを使用します。つまり、等しい値の互いに素なセグメントを維持し、更新が発生するたびにそれらをマージ/分割します。 各更新は境界セグメントのみに触れ、各セグメントは対数的に分割/マージされて償却されます。 

これにより、問題は、値が同種の間隔への配列の動的な分割を維持し、各クエリ中に影響を受ける間隔のみを更新するという問題に軽減されます。 

防御クエリは、これらのセグメントにわたる標準セグメント ツリーまたは RMQ になり、または最大セグメント値を直接追跡します。

 ## アルゴリズムのチュートリアル

 配列は要素ごとではなく、各間隔が定数値を持つ一連の素な間隔として維持されます。 

1. 最初に、範囲全体を表します。$[1, n]$すべてのドラゴンはレベル 0 から始まるため、値 0 の単一の間隔として。 
2. 各トレーニング クエリについて$(l, r, x)$、まず交差するすべての区間を見つけます。$[l, r]$。 これらの間隔は、部分的に重なったり、完全にクエリ範囲内に収まったりする場合があります。 
3. 異なる値を持つ任意の間隔$x$この操作は完全一致にのみ影響するため、無視されます。 これは、正確性を維持するための重要なフィルタリング手順です。 
4. 正確に値を持つ各間隔について$x$、最大 3 つの部分に分割します: 外側の左側の部分$[l, r]$、中央部分が内側、右部分が外側です。 中央部分が構造から削除されます。 
5. 削除されたすべての中間セグメントが、値を持つ新しい間隔として再挿入されます。$x+1$。 挿入後、最小限のセグメンテーションを維持するために、同じ値を持つ隣接する間隔がマージされます。 
6. 弁護側の質問について$(l, r)$、重なり合うすべての区間を横断します$[l, r]$そしてそれらの中で最大の保存値を取得します。 

### なぜ効果があるのか

 あらゆる瞬間において、配列は等しい値の最大セグメントへの分割として正確に表現されます。 各トレーニング操作では要素を値から移動するだけです$x$に$x+1$したがって、セグメントの境界を越えて不整合が生じることはありません。 変更前に常に間隔を分割し、後で同じ値の隣接する間隔をマージするため、どのセグメントも 2 つの異なる値を混合することはありません。 

したがって、構造は常に実際の基になる配列と等価であり、すべてのクエリは近似ではなく正確な表現から読み取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.maxv = [0] * (4 * n)

    def update(self, i, v, idx=1, l=1, r=None):
        if r is None:
            r = self.n
        if l == r:
            self.maxv[idx] = v
            return
        mid = (l + r) // 2
        if i <= mid:
            self.update(i, v, idx*2, l, mid)
        else:
            self.update(i, v, idx*2+1, mid+1, r)
        self.maxv[idx] = max(self.maxv[idx*2], self.maxv[idx*2+1])

    def query(self, ql, qr, idx=1, l=1, r=None):
        if r is None:
            r = self.n
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return self.maxv[idx]
        mid = (l + r) // 2
        return max(
            self.query(ql, qr, idx*2, l, mid),
            self.query(ql, qr, idx*2+1, mid+1, r)
        )

def main():
    n, q = map(int, input().split())
    seg = SegTree(n)
    arr = [0] * (n + 1)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, l, r, x = tmp
            for i in range(l, r + 1):
                if arr[i] == x:
                    arr[i] = x + 1
                    seg.update(i, x + 1)
        else:
            _, l, r = tmp
            print(seg.query(l, r))

if __name__ == "__main__":
    main()
```この実装は意図的に単純化されており、最大のクエリに応答するためだけにセグメント ツリーを使用してブルート フォース ロジックをミラーリングします。 更新ステップでも範囲をスキャンするため、意図した完全なソリューションではなく概念的なベースラインになります。 このように示されている理由は、条件付き更新の考え方と、スキャンが間隔構造のメンテナンスに置き換えられる最終的な最適化の方向とを明確に結び付けるためです。 

重要な点は、正確かどうかは更新前に同等性をチェックするかどうかにかかっているということです。 等価性チェックをスキップする実装では問題が根本的に変わります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    arr = [0] * (n + 1)
    out = []

    class Seg:
        def __init__(self, n):
            self.n = n
            self.t = [0] * (4*n)

        def upd(self, i, v, idx=1, l=1, r=None):
            if r is None: r = self.n
            if l == r:
                self.t[idx] = v
                return
            m = (l+r)//2
            if i <= m:
                self.upd(i,v,idx*2,l,m)
            else:
                self.upd(i,v,idx*2+1,m+1,r)
            self.t[idx] = max(self.t[idx*2], self.t[idx*2+1])

        def qry(self, L,R,idx=1,l=1,r=None):
            if r is None: r=self.n
            if R<l or r<L: return 0
            if L<=l and r<=R: return self.t[idx]
            m=(l+r)//2
            return max(self.qry(L,R,idx*2,l,m), self.qry(L,R,idx*2+1,m+1,r))

    seg = Seg(n)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, l, r, x = tmp
            for i in range(l, r+1):
                if arr[i] == x:
                    arr[i] = x+1
                    seg.upd(i, x+1)
        else:
            _, l, r = tmp
            out.append(str(seg.qry(l,r)))

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、トレーニング クエリが範囲内に存在しなくなった値を繰り返しターゲットにする場合です。 たとえば、すべての 0 を 1 にプロモートした後、後のクエリで$x = 0$何もすべきではありません。 値 0 の間隔が範囲と交差しないため、アルゴリズムはこれを自然に処理し、更新は行われません。 

もう 1 つのエッジ ケースは、交互のシングルポイント更新など、更新が短い間隔で繰り返し分割とマージを行う場合です。 間隔ベースの表現により、この最悪の断片化シナリオでも、各要素は$O(\log n)$分割と結合におけるバランスのとれたツリー動作による構造操作。 

最後のエッジ ケースは、一律の値による全範囲の更新であり、単純なスキャンではひどく劣化します。 間隔メソッドはセグメント全体を 1 つのブロックとして扱うため、操作は要素ごとではなく、影響を受ける間隔ごとに一定時間継続します。
