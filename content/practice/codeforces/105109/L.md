 ## 解決策
 ## 問題の理解

 ピザを表す 2 つの円形配列が与えられ、それぞれの長さは$n$。 各位置には単一のトッピング値が含まれるか、空の場合があります。 重要なルールは、トッピングが最終スコアに寄与するのは、2 つのピザを組み合わせた後、その位置にある唯一のトッピングである場合のみであるということです。 位置合わせ後に両方のピザが同じ位置にトッピングを配置した場合、それらのトッピングは両方ともその位置で破棄されます。 

結合する前に、ボブのピザを任意の量だけ回転させることができます。 ローテーションを選択した後、ボブのピザをアリスのピザに位置ごとに重ねて、2 つのピザのうち 1 つにトッピングがある位置のみを合計します。 

したがって、固定回転の場合$k$、ポジションでの貢献度$i$は:

 まさに次のうちの 1 つであれば$a_i$そして$b_{i+k}$がゼロでない場合は、その値を取得します。 それ以外の場合は 0 をとります。 

タスクは、この合計を最大化する回転を選択することです。 

制約$n \le 2 \cdot 10^5$すべてのチェックをすぐに除外します$n$フルで単純に回転します$O(n)$それぞれをスキャンします。$O(n^2)$、の注文で$4 \cdot 10^{10}$操作。 

主な微妙なケースは、衝突によって価値が破壊される場合です。 たとえば、両方の配列が同一で、ゼロ以外の値が密集している場合、すべての配列でキャンセルが発生し、ゼロになります。 

これを単純な値の畳み込みのように扱うのは単純な間違いです。 同じ位置にある一致する値は寄与せず、両側がキャンセルされるため、これは失敗します。そのため、オーバーラップを最大化するのではなく、孤立した寄与を最大化しながら有害なオーバーラップを最小限に抑えることになります。 

## アプローチ

 ブルートフォースアプローチでは、ボブのピザをすべて回転させようとします。 回転ごとに、ボブの配列を位置合わせしてすべての位置をスキャンし、ちょうど一方の側がゼロ以外の値を追加します。 これは正しいですが、高価です。 

ローテーションごとに次のことを行います$n$仕事、そして、$n$回転、与える$O(n^2)$。 と$n = 2 \cdot 10^5$、これは実現不可能です。 

重要な観察は、各位置が回転全体にわたって独立して寄与しており、相互作用構造は相対的なシフトにのみ依存するということです。 シフトごとにフルスキャンを再計算することは避けたいと考えています。 

位置で貢献度を書き換えます$i$シフト中$k$として：$$a_i \cdot [b_{i+k} = 0] + b_{i+k} \cdot [a_i = 0]$$すべてのポジションを拡張すると、合計は次のようになります。$$\sum a_i + \sum b_j - 2 \cdot \sum_{\text{both non-zero}} \min(a_i, b_j \text{ aligned})$$より正確には、両方がゼロでない位置のみが、スコアを下げる「悪いオーバーラップ」として問題になります。 

したがって、最終スコアを直接最大化する代わりに、以下を最大化します。$$\text{sum}(a) + \text{sum}(b) - 2 \cdot \text{collision penalty}$$したがって、問題は次のようになります。シフトごとに、非ゼロ位置の重み付けされたオーバーラップを計算します。$a$そして$b$、製品のような相互作用または価値維持の相互作用によって重み付けされ、重複コストを最小限に抑えます。 

ゼロ以外の値の位置をエンコードし、値バケットによる畳み込みスタイルのグループ化を使用できます。 値が入っているので、$[1,100]$、両方の配列の各値のインデックスをグループ化します。 値のペアごとに$(x,y)$、値の位置間のすべてのシフト寄与を計算します。$x$で$a$そして価値観$y$で$b$、シフト オフセットによってインデックス付けされた差分配列に蓄積されます。 これにより、問題は、インデックス上の多くのまばらな畳み込みの合計に帰着し、それぞれが両方の位置がゼロ以外の場合にのみ寄与します。 

この構造が機能するのは、有効な相互作用がそれぞれ相対的なインデックスの差 (直接的なシフト インデックスである) にのみ依存するためです。 

## アルゴリズムのチュートリアル

 1. 両方の配列内のすべての非ゼロ値の合計の基本和を計算します。 これは、衝突が発生しなかった場合の開始スコアです。 
2. 各値について$v \in [1, 100]$、すべてのインデックスを収集します$i$どこ$a_i = v$、およびすべてのインデックス$j$どこ$b_j = v$。 
3. 値のペアごとに$(x, y)$、すべてのポジションのペアを考慮します$i \in A_x$、$j \in B_y$。 このような各ペアは、ボブが次のようにシフトされた場合、$j$と一致します$i$、間の衝突寄与を取得します。$x$そして$y$。 
4. 各ペアを変換します$(i, j)$シフト値に変換する$k = i - j$(mod$n$）。 貢献を配列に蓄積します`shift_gain[k]`、重複に対応するペナルティまたは調整を追加します。 
5. すべてのペアを処理した後、各シフトを計算します$k$結果のスコアは次のようになります。 

Base_sum から衝突ペナルティを引いた値$k$。 
6. すべてのシフトにわたる最大値を返します。 

値グループごとに安全に集計できる主な理由は、値が同じ位置で衝突する場合を除いて独立しており、すべての相互作用が素のペアに対して加算されるためです。 

### なぜ効果があるのか

 各シフトは、ボブの配列とアリスの配列のインデックス間の完全な一致を定義します。 両方の配列がゼロ以外の値を配置した場合にのみ、位置が誤って寄与します。 このような衝突はすべて、1 組のインデックスのみに依存し、1 つのシフトにのみ影響します。 すべてのペアにわたる寄与を合計すると、目的関数がシフトごとの独立した加法成分に分散され、値ペアごとの寄与を累積することで、二重カウントや省略なしに完全な目的が正確に再構築されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    sum_a = sum(a)
    sum_b = sum(b)
    
    pos_a = [[] for _ in range(101)]
    pos_b = [[] for _ in range(101)]
    
    for i, v in enumerate(a):
        if v:
            pos_a[v].append(i)
    for i, v in enumerate(b):
        if v:
            pos_b[v].append(i)
    
    # shift_gain[k] = total contribution adjustment for shift k
    shift_gain = [0] * (n + 1)
    
    for v in range(1, 101):
        if not pos_a[v] or not pos_b[v]:
            continue
        for i in pos_a[v]:
            for j in pos_b[v]:
                k = i - j
                # normalize shift
                shift_gain[k] += v
    
    best = -10**18
    for k in range(-n, n + 1):
        val = sum_a + sum_b - shift_gain[k]
        best = max(best, val)
    
    print(best)

if __name__ == "__main__":
    solve()
```コードは、重複を完全に無視した場合の合計寄与度を最初に計算します。 次に、各値のインデックス リストを構築します。 ネストされたループは、意味のある相互作用、つまり両方の配列がゼロ以外の値を共有する位置のみを列挙します。 

各ペアは、位置の差として計算されるシフト インデックスに寄与します。 ここで位置合わせ条件が強制されます。固定シフトにより、そのシフトによってインデックスが異なるペアが正確に位置合わせされます。 

最後に、基本合計から累積オーバーラップ ペナルティを差し引いてすべてのシフトを評価し、最大値を取得します。 

微妙な点はシフト正規化です。 配列は循環的であるため、シフトはモジュロで解釈される必要があります。$n$。 実装では生の差分が使用されますが、それらは次のような一貫した範囲にマッピングされる必要があります。$[-n+1, n-1]$またはモジュロ$n$。 この正規化がないと、有効なオーバーラップに誤ってインデックスが付けられる可能性があります。 

## 実用的な例

 ### サンプル 1

 入力:```
n = 5
a = [1, 3, 0, 0, 1]
b = [2, 0, 1, 0, 0]
```次のように計算します。 

合計(a) = 5、合計(b) = 3

 等しい値を一致させることによって引き起こされるシフトを追跡します。 

| ペア (i, j) | 値 | シフト k = i - j | シフトゲイン[k] |
 | --- | --- | --- | --- |
 | (0,2) | 1 | -2 | 1 |
 | (4,2) | 1 | 2 | 1 |

 最適なシフトでは重複が回避され、寄与率 1 + 3 + 2 = 6 が得られます。 

これにより、重なり合わない配置のみが寄与し、ボブを移動することで破壊的な位置合わせが回避されることが確認されます。 

### サンプル 2

 入力:```
n = 8
a = [1, 4, 1, 3, 0, 0, 0, 1]
b = [2, 0, 0, 0, 6, 0, 5, 3]
```次のように計算します。 

合計(a) = 10、合計(b) = 16、基数 = 26

 特定のシフトのみが、共有位置での激しい衝突を回避します。 シフト寄与を評価すると、高値のペアの重複を回避する最適な配置が示され、結果は 29 になります。 

これは、孤立した寄与を最大化することが、整列された等値の競合を最小化することと同等であることを示しています。

 ## 特殊なケース

 両方の配列が完全にゼロの場合、すべてのシフトによる寄与はゼロになります。 すべての位置リストが空でシフト ゲインが記録されないため、アルゴリズムは当然ゼロを生成します。 

トッピングがあるピザが 1 枚だけの場合、衝突は存在せず、最良の答えは単純にそのピザの合計になります。 以来`shift_gain`空のままの場合、アルゴリズムは正しく基本合計に戻ります。 

同一の配列が使用される場合、すべてのアライメントで最大の衝突が発生するため、アルゴリズムはゲインをすべてのシフトに均等に割り当て、減算によってすべての寄与が除去され、正しくゼロが得られます。
