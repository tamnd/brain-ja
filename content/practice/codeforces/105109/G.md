 ## 解決策
 ## 問題の理解

 私たちには指示された構造が与えられています$n$ラベル付きの位置。各位置は$i$ちょうど 1 つの次の位置を指します$b_i$。 これは関数グラフを定義します。すべてのノードの出次数 1 があるため、グラフは有向サイクルに分解され、ツリーがそれらのサイクルにフィードされます。 

各ポジションには次のいずれかを割り当てる必要があります。$m$利用可能なラベル。曲として解釈されます。 割り当てはすべてのポジションに対して有効です$i$に割り当てられた曲$i$後継者に割り当てられた曲とは異なります$b_i$。 言い換えれば、あらゆる有向エッジに沿って$i \to b_i$、隣接するノードが同じ色を共有してはなりません。 

タスクは、そのような色がいくつ存在するかを数えることです。$10^9+7$。 

制約$n, m \le 2 \cdot 10^5$あらゆる解が線形または線形に近いものでなければならないことを意味します。$n$。 エッジや代入に対する二次アプローチは不可能です。$O(n^2)$のオーダーになります$4 \cdot 10^{10}$。 したがって、シミュレーションではなく、グラフの分解または構造式を探しています。 

ノードがそれ自体を指す場合、微妙なエッジケースが発生します。$b_i = i$。 これにより直ちに強制的に$a_i \ne a_i$, それは不可能なので、答えはゼロになります。 もう 1 つの障害モードは、グラフに複数のサイクルが含まれている場合です。各ノードを個別に処理すると、サイクルの制約を考慮せずに誤って選択肢が増えてしまいます。 

## アプローチ

 ブルートフォース手法では、それぞれの$n$ノードのうちの 1 つ$m$色を付けてすべてのエッジをチェックします。 これにより、$m^n$割り当てと各テイクの確認$O(n)$、合計は$O(n \cdot m^n)$、非常に小さい場合でも完全に実行不可能です。$n$。 

重要な構造的観察は、グラフが関数グラフであるため、各接続コンポーネントには 1 つの有向サイクルが含まれており、ツリーがそのサイクルを指しているということです。 制約$a_i \ne a_{b_i}$はエッジに沿ってローカルですが、親が固定されると樹木はいつでも自由に色付けできるため、グローバルな困難はサイクルによってのみ発生します。 

各ツリーをそのサイクルのエントリ ポイントでルートすると、すべてのツリーのエッジは単純な親子制約のように動作します。つまり、子は親と異なっていなければなりません。 これは、ルートの色が固定されると、すべての子が$m-1$独立した選択。 

本当の難しさはサイクルそのものです。 長さの有向サイクル上$k$、隣接するノードが異なるサイクル グラフの色をカウントする必要があります。 これは、閉じた形式を持つサイクルの適切な色を数えるのと同じです。$(m-1)^k + (-1)^k (m-1)$。 サイクル ノードに接続されたツリーは、次の乗算係数に寄与します。$(m-1)^{\text{size of tree}}$ただし、ノードをサイクルから外側に向かって注意深く処理すると、これらの寄与はすでに含まれています。 

したがって、解決策は、グラフをサイクルに分解し、各サイクルのサイズを計算し、サイクルの色付け式を使用して各コンポーネントの寄与を乗算することになります。

 ## アルゴリズムのチュートリアル

 ノードをサイクルに分割し、サイクルにフィードするツリーを分割し、コンポーネントごとに有効なカラーリングをカウントすることで、関数グラフ構造を活用します。 

1. まず、サイクルに属するすべてのノードを検出します。 これは、次数枝刈りまたは DFS 訪問状態を使用して実行できます。 目標は、グラフ内のすべての有向サイクルを分離することです。 ツリーのエッジとは異なり、サイクル制約はグローバルに結合されるため、これは重要です。 
2. 各サイクルについて、その長さを計算します。$k$。 サイクル上のすべてのノードは後続ノードとは異なる必要があり、閉じた制約ループを形成します。 これは、制約がラップアラウンドして非ローカルな制約を作成する唯一の部分です。 
3. サイクルの長さの有効な色の数を計算します。$k$。 サイクルを適切に色付けするための標準的な繰り返しは次のようになります。$$f(k) = (m-1)^k + (-1)^k (m-1)$$2 番目の項は、ラップアラウンド制約を満たさない線形パスのカラーリングによるオーバーカウントを修正します。 
4. サイクル内にない各ノードは、ルートがサイクル ノードである有向ツリーに属します。 これらのツリーは暗黙的に処理されます。サイクル ノードが色付けされると、他のすべてのノードは親を除く任意の色を選択できます。 これにより次の係数が得られます$m-1$木のエッジごとに、したがって合計係数は (m-1)^{n - \text{cycle_nodes}} になります。 
5. すべてのコンポーネントの寄与をモジュロで乗算します。$10^9+7$。 各サイクルはそのサイクル式に寄与し、すべての非サイクル ノードは独立した乗算因子に寄与します。 

### なぜ効果があるのか

 関数グラフでは、すべてのノードに出力制約が 1 つだけ存在することが保証されるため、グラフは、それぞれが 1 つのサイクルを含む互いに素なコンポーネントにきれいに分解されます。 ツリー エッジは、追加の依存関係を作成することなく、サイクル ノードから外側に伝播するローカルな不等式制約のみを課します。 サイクルのカラーリングが修正されると、残りの各ノードには 1 つの禁止色 (その親) が割り当てられるため、選択はノード間で独立します。 唯一のグローバルな依存関係は、制約がサイクルに近づいたときに発生します。これはまさにサイクルの式で捉えられるものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, m = map(int, input().split())
    b = list(map(lambda x: int(x) - 1, input().split()))
    
    if any(b[i] == i for i in range(n)):
        print(0)
        return

    vis = [0] * n
    in_stack = [0] * n
    on_cycle = [False] * n

    sys.setrecursionlimit(10**7)

    def dfs(u):
        vis[u] = 1
        in_stack[u] = 1
        v = b[u]
        if not vis[v]:
            dfs(v)
        elif in_stack[v]:
            cur = u
            while True:
                on_cycle[cur] = True
                if cur == v:
                    break
                cur = b[cur]
        in_stack[u] = 0

    for i in range(n):
        if not vis[i]:
            dfs(i)

    cycle_nodes = sum(on_cycle)

    # compute cycle components lengths (each cycle is a single component)
    vis2 = [0] * n
    ans = 1

    def walk_cycle(start):
        cur = start
        length = 0
        while not vis2[cur]:
            vis2[cur] = 1
            length += 1
            cur = b[cur]
        return length

    for i in range(n):
        if on_cycle[i] and not vis2[i]:
            k = walk_cycle(i)
            part = (mod_pow(m - 1, k) + ( -1 if k % 2 else 1) * (m - 1)) % MOD
            ans = ans * part % MOD

    # tree nodes contribution: every non-cycle node has (m-1) choices vs parent
    tree_nodes = n - cycle_nodes
    ans = ans * mod_pow(m - 1, tree_nodes) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、再帰スタック追跡を備えた DFS を使用して、関数グラフを明示的なサイクル マーカーに変換します。 バックエッジに沿って遡って発見されたノードは、サイクル ノードとしてマークされます。 次に、各サイクルを 1 回横断してその長さを決定します。 各サイクルには、古典的なサイクルのカラーリング式が適用されます。 最後に、すべての非サイクル ノードは、次の均一な乗算係数に寄与します。$m-1$なぜなら、そのような各ノードは親の色のコピーを避けるだけでよいからです。 

微妙な点は、サイクル式でのパリティ項の処理です。 交互補正なし$(-1)^k (m-1)$場合、カウントには無効なラップアラウンド割り当てが誤って含まれてしまいます。 

## 実用的な例

 ### サンプル 1

 入力:```
5 3
2 3 4 1 4
```まずサイクルノードを特定します。 ノード 1-2-3-4 はサイクルを形成し、ノード 5 はノード 4 を指します。 

サイクル構造:

 | ステップ | ノード | 親 | サイクルステータス |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | サイクル |
 | 2 | 2 | 3 | サイクル |
 | 3 | 3 | 4 | サイクル |
 | 4 | 4 | 1 | サイクル |
 | 5 | 5 | 4 | 木 |

 サイクルの長さは$k=4$、ツリー ノード = 1。 

サイクル貢献度:$$(m-1)^4 + (m-1) = 2^4 + 2 = 18$$木の貢献:$$(m-1)^1 = 2$$合計：$$18 \cdot 2 = 36$$これは、ツリー ノードが独立して寄与する一方で、サイクルが制約構造をどのように支配するかを確認します。 

### サンプル 2

 入力:```
2 1
2 1
```ここでは両方のノードが長さ 2 のサイクルを形成しています。ただし、存在する曲は 1 つだけです。 

| ステップ | ノード | 制約 | 有効な選択肢 |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 とは異なる必要があります | 不可能 |
 | 2 | 2 | 1 | とは異なる必要があります 不可能 |

 サイクル式は次のようになります。$$(m-1)^2 + (m-1) = 0^2 + 0 = 0$$したがって、答えは 0 です。これは、次のことを示しています。$m=1$、エッジがあると、すべての有効なカラーリングが即座に無効になります。

 ## 特殊なケース

 のような自己ループの場合$b_i = i$すぐに制約に違反します$a_i \ne a_i$したがって、アルゴリズムは計算の前に 0 を返します。 これは初期スキャンで明示的に処理されます。 

純粋なサイクルの場合、次のような$1 \to 2 \to 3 \to 1$、コアサイクル公式を実行します。 DFS はすべてのノードをサイクル ノードとしてマークし、トラバース長の計算により正しい指数が使用されるようにします。 交互の補正項により、ラップアラウンドの一貫性が保証されます。 

フォレストがサイクルにフィードされると、乗法分解が正しいことが保証されます。 各非サイクル ノードは、次の 1 つの要素にのみ寄与します。$m-1$各ノードはその親にのみ依存し、兄弟やより深い子孫には依存しないため、独立性が保たれます。
