 ## 解決策
 ## 問題の理解

 頂点 1 をルートとする木が与えられ、すべての辺が同じ長さになります。 ツリーの「コスト」は、単に現在のルートから最も遠い頂点がどのくらい離れているかということです。 すべてのエッジの重みは同じであるため、このコストは木の高さにエッジの長さを掛けたものにすぎません。 

面白いのは、ルートを移動できるのは、エッジに沿ってのみ、一度に 1 ステップずつ移動できることです。 移動するたびにルートが隣接する頂点に移動し、固定枚数のコインがかかります。 このような移動を何度でも行った後、新しいルートからツリーのコストを再度評価し、総移動コストを差し引きます。 目標は、最終的な利益を最大化する一連のルート シフトを選択することです。 

入力はツリーであるため、頂点のペアの間にはサイクルはなく、単純なパスが 1 つだけ存在します。 すべての根の動きは実質的にこの木の上を歩くことになるため、この構造は非常に重要です。 

制約により、線形または線形に近い解が強制されます。 テスト ケース全体の頂点の合計が最大 200,000 個になると、考えられるすべてのルートについて最初から距離を再計算するソリューションは失敗します。 候補ルートごとの BFS または DFS でさえ二次関数の動作につながり、これは許容範囲をはるかに超えています。 

欲張って考えると微妙な問題が見えてきます。 単純な考えは、高さを増やすために根を木の深い部分に移動し続けることです。 これは、すべての移動にコストがかかり、深さを増やしてもルートの全体的な偏心率が必ずしも増加するとは限らないため、失敗します。 

もう 1 つのよくある落とし穴は、最適な最終ルートが直径の重心または中点である必要があると仮定することです。 静的ルートを選択しているのではなく、そこまで歩くためにお金を払っているので、これでは十分ではありません。 

本当の難しさは、移動コストがたどる経路に依存するのに対し、木のコストは最終ルートのみに依存することです。 

## アプローチ

 強引な解釈では、ルート移動の考えられるすべてのシーケンスを考慮することになります。 与えられたルートから任意の近傍への移動を試み、すべての状態を再帰的に探索し、その結果得られる利益を計算します。 状態空間は本質的にすべてツリー上を歩き、深さが指数関数的であるため、これはすぐに爆発します。 

最終的なルート位置のみに限定したとしても、すべてのノードについて、最も遠いノードまでの距離 (離心率) を計算する必要があります。 この部分は、BFS または DFS を使用するノードあたりすでに O(n) であり、テスト ケースあたり O(n²) になります。 

重要な点は、すべての移動パスを明示的にシミュレートする必要がないということです。 ルートを移動するコストは、通過するエッジの数に比例するため、最終的なルートを修正すると、移動コストは、ツリー内の 1 からそのルートまでの距離に c を掛けたものとなります。 

したがって、問題は最大化するノードの選択に帰着します。 

利益(v) = 離心率(v) * k - 距離(1, v) * c

 これはノードに対するツリー DP スタイルの最適化になり、各ノードに 2 つの量 (元のルートからの距離と離心率) が必要になります。 

ルート 1 からの距離は、DFS または BFS を介して簡単にわかります。 この偏心には、古典的なツリー トリック、つまり 2 つの BFS トラバーサルが必要です。 まず直径の 1 つの端点を見つけ、次にそこから最も遠いノードを見つけて、両方の端点からの距離を計算します。 ノードの離心率は、2 つの直径の端点までの距離の最大値です。 

これらの値が事前に計算されると、すべてのノードの評価が線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース | 指数 | O(n) | 遅すぎる |
 | 偏心を計算 + すべての根を評価 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ノード 1 から BFS/DFS を実行して、元のルートからすべてのノード v までの距離 dist1[v] を計算します。各移動は 1 つのエッジでコスト c であるため、これにより、ルートを v に移動する総コストが取得されます。 
2. 任意のノード (通常はノード 1) から BFS を実行して、ツリー直径の 1 つのエンドポイントを見つけます。このエンドポイントを a と呼びます。 
3. a から BFS を実行して、距離 da[v] を計算します。 次に、a から最も遠いノードを見つけて、それを b と呼びます。 
4. b から別の BFS を実行して、距離 db[v] を計算します。 
5. すべてのノード v について、その離心率を max(da[v], db[v]) として計算します。 これが機能するのは、ツリーでは v から最も遠いノードが常に直径の端点の 1 つであるためです。 
6. 各ノード v について、利益候補を ecc[v] * k - dist1[v] * c として計算します。 
7. すべてのノードの最大値を返します。 

離心率の計算を直径の端点に制限できる理由は、ツリーではすべての最長パスが直径を通過するため、最も遠いノードはいずれかの端点に存在する必要があるためです。 

### なぜ効果があるのか

 このアルゴリズムは、2 つの競合する効果を明確に分離します。ルートの移動には木の端に沿って線形のコストがかかりますが、利点は新しいルートが最も遠い葉からどれだけ離れているかによってのみ決まります。 どちらの量もパスベースであり、BFS 距離を使用して完全にキャプチャできます。 直径の端点は、すべての偏心を境界付けるグローバル構造を提供し、ノードの最遠距離が見逃されることを保証します。 考えられるすべての最終状態はノードによって一意に表現され、そのようなノードはすべて 1 回だけ評価されるため、計算された最大値は全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

t = int(input())
for _ in range(t):
    n, k, c = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    dist1 = bfs(1, adj)

    a = max(range(1, n + 1), key=lambda x: dist1[x])
    da = bfs(a, adj)
    b = max(range(1, n + 1), key=lambda x: da[x])
    db = bfs(b, adj)

    ans = 0
    for v in range(1, n + 1):
        ecc = max(da[v], db[v])
        ans = max(ans, ecc * k - dist1[v] * c)

    print(ans)
```最初の BFS は、潜在的な最終ルートに到達するコストを修正します。 2 番目と 3 番目の BFS 計算により直径の終点が特定され、ノードごとに一定時間で離心率を導き出すことができます。 

最後のループでは、考えられるすべてのルートを直接評価します。 k と c による乗算は一貫して整数演算として維持されるため、精度の問題が回避されます。 

微妙な実装の詳細は、二次関数になるため、すべてのノードから BFS を再計算しないことです。 代わりに、直径構造を再利用します。これにより、偏心計算が線形時間に短縮されます。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 星型の木は、直感が失敗する可能性がある最も明らかなケースです。 中心の離心率は最小ですが、移動コストはゼロですが、葉の離心率は最大ですが、移動コストは高くなります。 アルゴリズムは両方を正しく評価し、純利益に基づいて選択します。 

パス グラフでは、すべてのノードが直径上にあるため、離心率は一方の端点または他方の端点までの距離に等しくなります。 BFS-from-diameter-ends メソッドは、ノードごとの BFS を必要とせずに、各ノードに最も遠い距離を正しく割り当てます。 

k が c に比べて小さい場合、ルートを移動することは決して有益ではありません。 dist1 * c 項がすべてのゲインを支配し、最大値が自然にノード 1 で発生するため、アルゴリズムは引き続きこれを処理します。
