 ## 解決策
 ## 問題の理解

 フィードは、ビデオの線形リストとして考えることができ、各ビデオには、視聴にかかる時間と楽しさという 2 つの属性があります。 Mushroom Filippov は最初のビデオから開始し、リスト内を右に移動し、1 ステップあたり 1 秒をかけて次の項目にスキップします。 いつでもスキップをやめてビデオを見始めることができます。 位置でビデオを選択したら`i`、合計消費時間は、位置 1 から位置 1 までのスキップに費やした時間です。`i`ビデオ自体の長さに加えて。 

テスト ケースごとに、「到達するまでの時間」と「視聴時間」の合計が昼食時間の合計を超えないように、どの単一のビデオを選択するかを決定する必要があります。`t`。 この制約を満たすすべてのビデオの中から、エンターテインメント価値が最大のものを選択します。 

このモデルの重要な部分は、ビデオに到達するまでのコストです。`i`固定的かつ決定的です: まさにそうです`i - 1`秒。 選択肢間の分岐や相互作用がないため、各インデックスを独立して評価できます。 

制約は小さいです。`n ≤ 50`そして`q ≤ 1000`。 これは、全体で最大 50,000 件のビデオ チェックが行われることを意味します。 線形のソリューションはすべて、`n`テスト ケースごとの処理は簡単に十分に高速ですが、ビデオごとにネストされた重い計算を伴うものは許容されますが、不要です。 

よくある間違いは、スキップコストを無視して比較のみを行うことです。`a[i] ≤ t`。 より深いビデオに到達するには時間がかかるため、これは失敗します。 たとえば、次の場合`t = 5`、位置 4 にあるビデオの長さ 2 は、そのビデオに到達するのにすでに 3 秒かかり、合計時間が 5 になるため無効です。もう 1 つの間違いは、フィードを動的にシミュレートしようとすることです。 各候補者は独立しているため、これは不要です。 

エッジケースは次の場合に発生します。 

- 時間内にビデオにアクセスできません。 例：`n = 3, t = 1`、持続時間`[10,10,10]`。 最初の動画でも、視聴には少なくとも 1 秒、視聴には 10 秒かかります。`t`。 出力は次のようにする必要があります`-1`。 
- 最高のエンターテイメント ビデオは最も古い有効なビデオではないため、最大限のビデオを追跡する必要があります`b[i]`最初の有効なインデックスで停止しないでください。 

## アプローチ

 ブルートフォースアプローチは、ビデオごとに直接的です。`i`かどうかを計算します。`i - 1 + a[i] ≤ t`。 有効であれば、エンターテイメント性を考慮してください`b[i]`。 すべての有効なインデックスの中で最良のものを維持します。 これには、すべてのテスト ケースのすべてのビデオをチェックする必要があり、その結果、`O(n)`テストケースごとに作業します。 

と`n ≤ 50`テスト ケースが 1,000 件までの場合、評価数は最大 50,000 件であり、非常に少ないです。 単純な実装でも安全です。 

各ビデオの実現可能性は独自のインデックスと再生時間のみに依存するため、より深い最適化構造は必要ありません。 「スキップコスト」は位置ごとに線形で独立しているため、プレフィックス合計、ソート、貪欲な並べ替えには利点がありません。 

重要な観察は、問題が独立したフィルタリングに帰着するということです。つまり、単純な制約によって定義されたセットから最適な要素を選択しているということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 承認済み |
 | 最適 | O(nq) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`t`、期間配列`a`、およびエンターテイメントの配列`b`。 各ビデオはペアになったオブジェクトであるため、インデックスによって整列させます。 
2. 変数の初期化`best_value = -1`そして`best_index = -1`。 これらは、これまでに確認された最良の有効なビデオを追跡します。 番兵`-1`は有効なビデオが存在しない場合を表します。 
3. 各ビデオインデックスを反復処理します。`i`から`1`に`n`。 
4. ビデオの選択に必要な時間を計算します。`i`、つまり`(i - 1) + a[i]`。 最初の項はフィードの開始からのスキップ時間を表し、2 番目の項は視聴時間を表します。 
5. この合計時間が以下の場合`t`、ビデオは昼食の制約内で実現可能です。 
6. 可能であれば、エンターテイメント性を比較してください`b[i]`と`best_value`。 それより大きい場合は両方を更新します`best_value`そして`best_index`このビデオに。 
7. すべてのビデオをスキャンした後、出力します`best_index`。 有効なビデオが見つからなかった場合は、`best_index`残る`-1`。 

### なぜ効果があるのか

 各ビデオは、その位置のみに依存する固定の決定論的コスト モデルに基づいて評価されます。 選択肢間には相互作用がないため、実現可能性は要素ごとのプロパティになります。 アルゴリズムは、最初の処理後の不変条件を維持します。`i`ビデオ、`best_index`プレフィックス内のすべての有効なビデオの中で最もエンターテイメント性の高いものです`[1..i]`。 すべてのビデオが 1 回だけチェックされるため、最終結果は配列全体のすべての有効な候補の中で最良のものとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n, t = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    best_val = -1
    best_idx = -1

    for i in range(n):
        time_needed = i + a[i]  # i == i-1 in 0-based indexing

        if time_needed <= t:
            if b[i] > best_val:
                best_val = b[i]
                best_idx = i + 1

    print(best_idx)
```このコードは、スキップ時間が正確にゼロベースのインデックス付けのインデックス オフセットであるという観察に直接従っています。 ループは実現可能性をチェックし、最良の答えを貪欲に更新します。 

微妙な点は、インデックス付けの一貫性を保つことです。Python では次のように使用します。`i`0から始まるので動画まで`i`費用`i`秒ではありません`i-1`。 返されたインデックスは、1 から始まるインデックスに調整されます。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        n, t = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        best_idx = -1

        for i in range(n):
            if i + a[i] <= t:
                if b[i] > best_val:
                    best_val = b[i]
                    best_idx = i + 1

        out.append(str(best_idx))

    return "\n".join(out)

 ## 特殊なケース

 いつ`t`は非常に小さいため、後の位置ごとに少なくとも 1 秒のスキップ コストが追加されるため、唯一の候補は最初のビデオになることがよくあります。 アルゴリズムはこれを自然に処理します。`i + a[i]`すぐに超える`t`みんなのために`i > 0`。 

例えば：```
n = 3, t = 2
a = [5, 1, 1]
b = [10, 20, 30]
```実行チェック:

 - i = 1: 0 + 5 = 5 > 2、無効
 - i = 2: 1 + 1 = 2 ≤ 2、有効 → 最良 = 20
 - i = 3: 2 + 1 = 3 > 2、無効

 出力はインデックス 2 になり、前のビデオが長い場合でも、コストをスキップすることで後の短いビデオが好まれる可能性があることを示しています。 

このアルゴリズムは、各候補を独立して正しく評価し、エンターテイメントの価値や継続時間が単調であることを決して想定しません。
