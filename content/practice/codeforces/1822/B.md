 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、残っているものの相対的な順序を維持しながら、要素のサブセットを削除することができます。 削除後は、少なくとも 2 つの要素を保持する必要があり、すべての隣接するペアを調べてそれらの最大の積を取得することによって、結果の配列を評価します。 目標は、この最大隣接積ができるだけ大きくなるように、保持する要素を選択することです。 

重要な点は、削除により、元々隣接していなかった 2 つの生き残った要素を「接続」できるということです。 したがって、問題は元の近傍ではなく、インデックスのペアの選択にあります。$i < j$間にあるものをすべて削除し、最大化した後に連続するもの$a_i \cdot a_j$。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$テスト ケース全体の要素の合計が計算され、すべてのペアまたはすべてのサブシーケンスの二次探索が即座に除外されます。 すべてのペアを試行したり、削除を明示的にシミュレートしたりするソリューションでは、単一のテスト ケースで既に次のものが必要になる可能性があるため、時間がかかりすぎます。$10^{10}$最悪の場合の運用。 

元の配列内の隣接する要素だけを考えると、微妙な故障モードが現れます。 たとえば、次のような配列では、$[1, 100, 2]$、最良の隣接製品は$100$、ただし、削除後は選択できます$[1, 2]$取得するため$2$、どちらが悪いのか、それとも$[100]$は無効です。 ただし、より興味深いケースには、要素をスキップして、元々隣接していなかった遠く離れた大きな値を接続することが含まれます。 

もう 1 つの特殊なケースは負の数です。 大きな絶対値のみを考慮する単純なアプローチは失敗します。積は符号に依存し、最大積は 2 つの負の値から得られる可能性があるためです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。少なくとも 2 つのサイズのすべてのサブセットを考慮し、その最良の隣接積を計算し、最大値を追跡します。 削除後のペアのチェックに限定したとしても、インデックスのすべてのペアを効果的に考慮します。$(i, j)$と$i < j$なぜなら、そのようなペアは、その間の要素を削除することで隣接させることができるからです。 ペアごとに計算します$a_i \cdot a_j$そして最大値を取る。 

これはすぐに次のようになります$O(n^2)$テストケースごとに、これは大きすぎます。$n$到達する$2 \cdot 10^5$。 

重要な観察は、削除により構造を完全に無視できるということです。 選択した 2 つの要素は隣接する可能性があるため、最終的な答えは単純にすべてのペアの最大積になります。$i < j$。 これにより、問題はシーケンスを調整するのではなく、最適なペアを選択することになります。 

これが認識されると、タスクは配列内の 2 つの数値の最大積を見つけるようになります。 唯一の微妙な点は符号です。最大積は、2 つの最大の正の数から、または 2 つの最小 (最も負の) 数から得られます。 

したがって、追跡する必要があるのは 4 つの候補、つまり最大の 2 つの値と最小の 2 つの値だけです。

 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. これまでに確認された 2 つの最大値と 2 つの最小値を維持しながら、配列を 1 回スキャンします。 

最適なペアはこれらの境界ケースのいずれかに由来する必要があるため、これらの極端な値を維持します。 
2. 各要素について$x$、最大ペアを更新します$(max1, max2)$となることによって$max1 \ge max2$、同様に最小ペアを更新します$(min1, min2)$となることによって$min1 \le min2$。 

これにより、ポジティブな貢献とネガティブな貢献の最適な候補者を常に保持できるようになります。 
3. すべての要素を処理した後、2 つの答えの候補を計算します。$max1 \cdot max2$そして$min1 \cdot min2$。 
4. これら 2 つの値の最大値を返します。 

これら 2 つのケースに分けた理由は、符号が変化すると乗算の動作が異なるためです。 大きな正の値は積を直接最大化しますが、大きな負の値は乗算すると大きな正の積を生成する可能性があります。 

### なぜ効果があるのか

 最適なソリューションは、選択した 2 つのインデックスのみに依存します。$i < j$。 削除後に任意のペアを隣接させることができるため、問題は積を最大化する 2 つの要素を選択することになります。 このような最適なペアは、極値、つまり最大の 2 つの数値または最小の 2 つの数値から得られる必要があります。 正しい組み合わせの場合、選択した要素をより極端な値に置き換えることで絶対的な寄与が常に改善または維持されるため、内部値はこれらの組み合わせを上回ることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # initialize extremes
        max1 = max2 = -10**30
        min1 = min2 = 10**30
        
        for x in a:
            # update max pair
            if x > max1:
                max2 = max1
                max1 = x
            elif x > max2:
                max2 = x
            
            # update min pair
            if x < min1:
                min2 = min1
                min1 = x
            elif x < min2:
                min2 = x
        
        ans = max(max1 * max2, min1 * min2)
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、単一パスで 2 つの最大値と 2 つの最小値を追跡します。 初期化では、すべての数値が負であるか、すべてが正の場合でも正しい更新を保証するために、非常に大きなセンチネル値が使用されます。 

2 つの候補製品間の最終比較は、ポジティブ ペアの優位性とネガティブ ペアの優位性の両方を把握するため、不可欠です。

 ## 特殊なケース

 配列に大きな正の値と大きな振幅の負の値の両方が含まれる場合、厄介な状況が発生します。 例えば、$[-100, 1, 2, 3, 4]$。 アルゴリズムは両方の極値を追跡するため、最大ペアは次のようになります。$4 \cdot 3 = 12$一方、最小ペアは、大きなマイナスが 1 つしかないため、競争力がありません。 

のために$[-5, -6, 2]$の場合、追跡された値は max1 = 2、max2 = -5 および min1 = -6、min2 = -5 で終了します。 アルゴリズムが評価するのは、$2 \cdot -5 = -10$そして$(-6) \cdot (-5) = 30$、負のペアを正しく選択します。 

次のようなゼロがある場合$[0, -1, -2]$、ゼロは当然最大追跡に含まれますが、最小ペアには干渉せず、正しい答えが確実に得られるようにします。$(-1) \cdot (-2)$。
