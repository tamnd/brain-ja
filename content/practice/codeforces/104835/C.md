 ## 問題の理解

 私たちは、考えられるバクラヴァ層の数を表す 9 桁の数字を調べています。 このような各数値は有効な設定であるため、検索スペースは単純に 100,000,000 ～ 999,999,999 のすべての整数になります。 

有効な構成には 2 つの条件があります。 まず、数値の桁を逆にすると、結果の数値は 5 で割り切れる必要があります。次に、元の数値自体が指定された値で割り切れる必要があります。$K$、テストケースごとに変化します。 それぞれについて$K$, 両方の条件を同時に満たす 9 桁の数字がいくつあるかを数える必要があります。 

5 で割り切れるかどうかに関する重要な観察は、それが反転した数の最後の桁にのみ依存するということです。 数値は、最後の桁が 0 または 5 の場合に限り、5 で割り切れます。9 桁の数値を反転すると、最後の桁が元の数値の最初の桁になります。 有効な数値はすべて 9 桁の整数であり、その最初の桁は 1 から 9 の範囲内にあるため、反転された数値が 0 または 5 で終わる唯一の方法は、元の数値が 5 で始まることです。これにより、次で割り切れる 5 桁で始まる 9 桁の数値を数えるという問題が解決されます。$K$。 

したがって、次の形式の数値を効果的に処理します。$$5xxxxxxx x$$残りの 8 桁は空いています。 

制約は非常に大きいです。 テストケースの数は最大で$10^5$であり、各クエリは最大範囲のカウントを要求します。$10^8$数字。 範囲にわたるクエリごとのリニア スキャンは不可能です。 たとえ$O(\sqrt{N})$または$O(\log N)$数字ごとの戦略は失敗します。 

エッジケースは次の場合に発生します。$K$大きいか小さいかです。 もし$K = 1$、5 で始まるすべての有効な 9 桁の数字がカウントされます。 もし$K > 999,999,999$の場合、答えは割り算の構造に応じて 0 または 1 になりますが、候補ごとに強引に割り算を行うことは不可能です。 もう 1 つの微妙なエッジ ケースは、推論が倍数の位置合わせを考慮せずに、範囲にわたって均一に割り切れると誤って想定している場合です。 

## アプローチ

 ブルートフォース手法では、考えられる 9 億個の 9 桁の数字すべてを反復処理し、最初の桁が 5 であるかどうかを確認し、次のように割り切れるかどうかをテストします。$K$。 割り算のチェックが定数時間だったとしても、これは$10^9$クエリごとの操作数は制限をはるかに超えています。 

問題の構造は、組み合わせというよりも算術的なものです。 5 で始まる数字に限定すると、基本的には等差数列を観察することになります。$$500000000 \text{ to } 599999999$$この区間内で割り切れる整数がいくつあるかを数える必要があります。$K$。 

これにより、問題は古典的な倍数の範囲カウントに変換されます。 値を列挙する代わりに、次の値の倍数を計算します。$K$プレフィックス除算を使用して閉区間内にあります。$$\text{count} = \left\lfloor \frac{R}{K} \right\rfloor - \left\lfloor \frac{L-1}{K} \right\rfloor$$5 で割り切れる制約はすでに間隔制限に吸収されているため、追加のフィルタリングは必要ありません。

 ## アルゴリズムのチュートリアル

 1. 有効な数値の範囲を、反転した形式が 0 または 5 で終わる数値に制限します。これにより、元の数値が 5 桁で始まることが強制されるため、間隔を定義します。$[L, R] = [500000000, 599999999]$。 これにより、桁反転条件が数値自体の構造的制約に変換され、完全に削除されます。 
2. 各テスト ケースについて、整数を読み取ります。$K$、元の数値の割り算条件を定義します。 タスクは、次の数字がいくつあるかを数えるようになります。$[L, R]$で割り切れます$K$。 
3. の倍数を計算します。$K$以下である$R$整数の除算を使用する$R // K$。 これにより、上限までの有効な倍数の合計数が得られます。 
4. の倍数を計算します。$K$厳密に以下です$L$使用して$(L-1) // K$。 これにより、間隔を下回る無効な倍数がすべて削除されます。 
5. 2 つの値を減算して、範囲内の有効な倍数の数を取得します。 これは、その有効なバクラヴァ構成の数に直接対応します。$K$。 

### なぜ効果があるのか

 すべての有効な設定は、間隔内の 1 つの整数に正確に対応します。$[500000000, 599999999]$。 で割り切れる条件$K$整数をステップの互いに素な等差数列に分割します$K$。 このような数列に含まれる区間の要素の数をカウントすることは、境界の位置合わせによって完全に決定されるため、フロア分割の公式は正確であり、エッジ要素の過剰カウントや欠落を回避できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

L = 500_000_000
R = 599_999_999

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        if k == 0:
            print(0)
            continue
        ans = R // k - (L - 1) // k
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に有効なユニバースを 1 回修正するため、クエリごとに境界を再計算する必要がなくなります。 その後、各クエリは 2 つの整数除算と 1 つの減算に削減されます。 

微妙な点は扱い方$K = 0$ただし、通常は制約によってそれが妨げられます。 ガードは堅牢性を保証しますが、ゼロで割り切れる可能性が定義されていないため、論理的にそのような場合は有効な数値がゼロになります。

 ## 特殊なケース

 厄介なケースは次のような場合です$K$上限より大きいです$R = 599999999$。 たとえば、次の場合$K = 10^9$、 両方$R // K$そして$(L-1) // K$はゼロなので、答えはゼロになります。 アルゴリズムは特別な分岐を行わずにこれを自然に処理します。 

もう一つのケースは次のような場合です。$K = 1$。 この場合、間隔内のすべての数値が有効になります。 式は次のようになります。$$599999999 - 499999999 = 100000000$$これは、5 で始まる 9 桁の数字の数と正確に一致します。 

最後に、いつ$K$境界付近の値を分割します。たとえば、$K = 500000000$、間隔には 1 つの倍数、つまり 500000000 自体が含まれます。 減算により境界点の包含が正しく保存され、エッジでの正確性が確認されます。
