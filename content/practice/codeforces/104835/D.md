 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 1 つの配列は顧客の注文を表し、各値は顧客が希望するバクラバの数です。 もう 1 つの配列は、各バッチで現在準備されているバクラバの数を表します。 許可される唯一の操作は、単一のバクラヴァをあるバッチから別のバッチに移動することです。 移動するたびに、1 つのバッチが 1 単位減少し、別のバッチが 1 単位増加します。 

タスクは、少なくとも 1 つのバッチが最終的に要求された注文値のいずれかと同じサイズになるように、必要な単一単位の移動の最小数を決定することです。 注文サイズに一致するようにバッチを変換できない場合は、-1 を返します。 

重要な点は、すべてのバッチを注文に一致させようとしているわけではなく、1 つのバッチだけが任意の 1 つの目標値に一致する必要があるということです。 これにより、問題はグローバルな再分配から単一ターゲットの実現可能性の問題に移ります。 

制約は、最大 10^9 の値を持つ 200,000 要素まで適用されます。 これにより、すべての注文とすべてのバッチ間の二次ペアリングが即座に排除されます。 すべてのペアを試行するソリューションは遅すぎます。 ソートベースのアプローチまたはハッシュベースの検索が必要になります。 

理論上でも注文値に到達できない場合、微妙なエッジケースが発生します。 操作では合計が保持されるため、システムが供給できる量を超えてバッチを増減する必要がある場合、それが不可能になる可能性があります。 たとえば、すべてのバッチが同一で、ターゲットが大幅に異なる場合、実現可能性は局所的な違いだけでなく、総和の調整に依存します。 

## アプローチ

 ブルートフォース手法では、注文値とバッチ値のすべてのペアを試し、そのバッチをその注文サイズに変換するために必要な手数を計算します。 サイズ b のバッチを修正し、それを a にしたい場合は、|a - b| を正確に移動または取り込む必要があります。 バクラヴァ。 これは計算が簡単で、答えはすべてのペアの最小値になります。 

ただし、これはグローバル制約を無視します。バッチ間でバクラバを移動すると、共有された合計値を通じてすべての値が結合されるため、各バッチを個別に調整することはできません。 この結合を無視した単純なアプローチは、実現可能性を誤って主張したり、再分配が不可能なエッジケースで実現可能性を過小評価したりする可能性があります。 

重要な洞察は、固定目標注文値 a について、任意のバッチをサイズ a に変換できるかどうか、およびそのコストがいくらになるかを知る必要があるだけであるということです。 サイズ b のバッチを a に変換するには、正確に |a - b| が必要です。 移動しますが、これは合計がすべてのバッチにわたる再分配を許可する場合にのみ有効です。 

転送をシミュレートする代わりに、すべてのバクラバの合計 S を計算します。 ターゲット a について、a となるバッチを選択した場合、残りの合計は残りの N-1 個のバッチに分配する必要があります。 これは、残りの合計 S - a が負でない場合にのみ可能であり、常に真であるため、実現可能性は制限要因ではありません。 本当の制約は、合計を維持する限り自由に再分配できるということです。 

したがって、任意のバッチを a に等しくするコストは、単に |b_i - a| のすべてのバッチにわたる最小値になります。 答えは、すべての順序値 a_i におけるこの値の最小値です。 

両方の配列は独立してソートできるため、二分探索を使用してこれを高速化できます。各順序値 a について、ソートされた b で最も近いバッチ値を見つけて、距離を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアリング | O(N²) | お(1) | 遅すぎる |
 | ソート + 二分探索 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. バッチ サイズの配列を並べ替えます。 これにより、あらゆるターゲット注文サイズに対して効率的な最近傍クエリが可能になります。 
2. 各順序値 a について、ソートされたバッチ配列に対して二分検索を実行して、a に最も近い値を見つけます。 この順序に一致させることを目的とする場合、最も近い値によって必要な最小手数が決まります。 
3. a と、移動する必要があるバクラバの数を表す最も近いバッチ値との間の絶対差を計算します。 
4. すべての注文値にわたる最小値を追跡します。 
5. すべての注文を処理した後、この最小値を出力します。 

ここで二分探索が機能する理由は、ソートされた配列では、ターゲットに最も近い値が、下限によって返される 2 つの隣接する位置のいずれかに存在する必要があるためです。 

### なぜ効果があるのか

 固定ターゲット a の場合、サイズ b のバッチを a に変換するには、正確に |a - b| が必要です。 ユニットが動きます。 移動するたびに 2 つのバッチ間で 1 ユニットが移動するため、ユニット フローの観点から効果的に距離を測定することになります。 すべてのバッチは変換の独立した候補であり、単位転送以外の相互作用コストはないため、最適な選択は常に a に最も近い利用可能なバッチ サイズです。 ソートされた構造により、値の最近傍が効率的かつ正確に見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    b.sort()
    
    import bisect
    
    ans = 10**30
    
    for x in a:
        i = bisect.bisect_left(b, x)
        
        if i < n:
            ans = min(ans, abs(b[i] - x))
        if i > 0:
            ans = min(ans, abs(b[i - 1] - x))
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、近接クエリが効率的になるように、まずバッチ配列を並べ替えます。 注文値ごとに、二分検索を使用して最も近いバッチ サイズを見つけます。 ソート順ではより近い値が隣接する必要があるため、挿入ポイントの周囲の 2 つの候補位置で十分です。 このようなすべての比較におけるグローバル最小値が答えです。 

ここでよくある間違いは、挿入ポイントの両側を確認するのを忘れることです。 片側をチェックするだけでは、真に最も近いバッチ値を見逃す可能性があります。

 ## 特殊なケース

 エッジケースの 1 つは、ターゲット注文がバッチサイズと正確に一致する場合です。 たとえば、a = 7 で、b に 7 が含まれる場合、二分探索では 7 が有効な位置に配置され、差の絶対値は 0 になります。 操作が必要ないため、アルゴリズムは正しくゼロを返します。 

別のエッジ ケースは、最も近い値が挿入ポイントの片側にのみ存在する場合に発生します。 たとえば、b = [10, 20, 30] および a = 5 の場合、下限はインデックス 0 であり、10 とのみ比較します。アルゴリズムは無効なインデックス付けを正しく回避し、正しいコスト 5 を返します。 

最後のエッジケースは、すべてのバッチ値が同一である場合です。 その場合、すべてのクエリは単一の値との比較になり、答えはその定数とすべての次数の値の間の絶対差の最小値となり、アルゴリズムは比較を繰り返すことで自然にこれを取得します。
