 ## 解決策
 ## 問題の理解

 辺の長さの正方形のペストリーから始めます`l`。 ミラは、現在の正方形を、中点を対称的に結合して形成された小さな正方形に置き換える幾何学的操作を繰り返し実行します。 各ラウンドでは、厳密に前の正方形の内側に新しい正方形が生成され、プロセスが正確に繰り返されます。`k`回。 タスクは、すべてのカット後の最終的な内側の正方形の辺ベースの「サイズ」を決定することです。サンプルは、予想される出力がその最終的な正方形の面積に対応することを示しています。 

入力は、単一の初期辺の長さと、繰り返される幾何学的変換の数です。 出力は実数であるため、変換ではシミュレーションではなく閉じた形式の式を生成する必要があります。 制約により許可されるのは、`l`まで`10^9`これにより、直接的な幾何学的構築や座標シミュレーションは不要になりますが、いずれにせよ試してみると、浮動小数点ドリフトによるリスクも伴います。 ラウンド数`k`は最大 25 であり、これは、組み合わせ爆発ではなく、指数関数的または反復的なスケーリング パターンが意図されていることを示唆しています。 

単純なアプローチでは、ジオメトリをシミュレートします。つまり、正方形の座標を構築し、中点を計算し、次の正方形を形成し、これを繰り返します。 これは小さい場合は安定しています`k`ですが、浮動小数点の平方根と座標の更新が繰り返されます。 それでも`k ≤ 25`が小さい場合、幾何学的推論は過度になり、精度誤差が蓄積するリスクが増加します。 

微妙なエッジ ケースは、ステップごとに三角根または平方根を使用してジオメトリを繰り返し計算しようとすると、浮動小数点が不安定になることです。 たとえば、回転した正方形の座標を繰り返し再計算するとドリフトが発生し、最終的な領域が許容範囲をわずかに超えてしまう可能性があります。`1e-6`許容範囲。 このため、直接式が必要になります。 

## アプローチ

 重要な観察は、各操作の構造が同一であるということです。正方形から辺の中点を接続して、新しい内側の正方形を形成します。 この変換はスケール不変です。つまり、新しい正方形の辺の長さと古い正方形の辺の長さの比率は、要素に関係なく一定です。`l`。 

これを理解するには、原点を中心とする辺のある正方形を考えてください。`l`。 側面の中点は離れています`l/2`中心から軸に沿って。 隣接する中点を接続すると、45 度回転した新しい正方形が形成されます。 この新しい正方形の辺の長さは、2 つの連続する中点の間の距離です。たとえば、`(l/2, 0)`に`(0, l/2)`。 その距離は次のとおりです。$$\sqrt{(l/2)^2 + (l/2)^2} = \frac{l}{\sqrt{2}}$$したがって、各演算では辺の長さに次の値が乗算されます。`1/√2`。 

後`k`演算すると、辺の長さは次のようになります。$$l \cdot \left(\frac{1}{\sqrt{2}}\right)^k = \frac{l}{2^{k/2}}$$この問題は最終的な「サイズ」を求めており、サンプルはそれが結果として得られる正方形の面積であることを確認します。 したがって、辺を正方形にします。$$\text{area}_k = \left(\frac{l}{2^{k/2}}\right)^2 = \frac{l^2}{2^k}$$これにより、問題全体が 1 つのべき乗の計算に集約されます。 

ブルートフォース幾何学シミュレーションでは、各ラウンドで一定時間内に座標が再計算され、次のようになります。`O(k)`動作しますが、依然として浮動小数点の不安定性が隠れています。 閉じた形式のソリューションは反復を完全に回避し、浮動小数点精度内で正確です。

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`l`そして`k`。 これらは、最初の正方形と中点カット変換が適用される回数を定義します。 
2. 元の正方形の面積を次のように計算します。`l * l`。 これは、縮小が発生する前の不変ベースラインを表します。 
3. 各変換によって導入されるスケーリング係数を計算します。 各ラウンドは、乗算的な意味で正方形の面積を半分にします。これは、で割ることに相当します。`2`ステップごとに。 
4. 変換を適用する`k`初期面積を次の値で割って倍します。`2^k`。 これにより、すべての幾何学的収縮が単一の指数項に集約されます。 
5. 結果の値を浮動小数点数として出力します。 

### なぜ効果があるのか

 変換は自己相似です。各ステップは中点のみを使用して正方形を別の正方形にマッピングします。これにより、形状は維持され、スケールのみが変更されます。 連続する領域間の比率は一定で、位置やサイズに依存しないため、プロセスは等比数列を形成します。 不変条件は、各ステップ後の面積が前の面積のちょうど半分になるということです。`k`ステップ数分の面積を減らす必要があります`2^k`。 幾何学的歪みや方向はこの比率に影響しないため、閉じた形状は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

l, k = map(int, input().split())

area = (l * l) / (2 ** k)

print(area)
```計算により、導出された式が直接エンコードされます。 掛け算`l * l`精度を保つために除算の前に行われます。 べき乗`2 ** k`安全なので`k ≤ 25`、そのため、値は浮動小数点表現で小さく正確なままになります。 

重要な実装の詳細は、反復的なジオメトリ更新を完全に回避することです。 この問題では繰り返しカットが記述されていますが、解決策は一定のスケーリング係数をシミュレートするのではなく、それを認識することに依存しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    l, k = map(int, input().split())
    area = (l * l) / (2 ** k)
    return str(area)

# provided samples
assert abs(float(run("2 1")) - 2.0) < 1e-9
assert abs(float(run("10 25")) - 0.00000298023223876953) < 1e-18

# custom cases
assert abs(float(run("1 0")) - 1.0) < 1e-9
assert abs(float(run("1 1")) - 0.5) < 1e-9
assert abs(float(run("1000000000 1")) - 5e17) < 1e-1
assert abs(float(run("3 5")) - (9 / 32)) < 1e-9
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 0 | 1 | 変換なし |

 | 1000000000 1 | 大規模な安定性 | オーバーフローの問題を回避します。

 ## 特殊なケース

 のために`k = 0`、変換は決して起こらず、出力は元の領域と等しくなる必要があります。`l^2`。 この式は自然にこれを処理します。`2^0 = 1`したがって、特別な分岐は必要ありません。 

大型用`k`のような`k = 25`の場合、値は非常に小さくなりますが、それでも Python の浮動小数点アンダーフロー制限を大幅に超えています。 直接除算を行うことで、繰り返しによる精度の損失が蓄積されなくなります。 

大型用`l`近く`10^9`、二乗値は次の値に達します`10^18`これは、必要な誤差許容度を十分に満たす精度を備えた浮動小数点形式で安全に表現できます。
