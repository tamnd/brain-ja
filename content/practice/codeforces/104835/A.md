 ## 解決策
 ## 問題の理解

 独立したベーカリーからいくつかの注文を受けています。 各次数は層のスタックを表します。最初の層には初期の厚さがあり、次の層はすべて前の層よりもちょうど 1 単位厚くなります。 最初の厚さと使用される層の数がわかれば、構造は完全に決定されます。 

注文ごとに、スタック全体の合計の厚さを計算する必要があります。これは、単純にすべての層の厚さの合計です。 抽象的なシーケンスについて考える代わりに、これを、次から始まるシーケンスを合計する等差数列として見ると役立ちます。$L$、ステップごとに 1 ずつ増加し、$N$条項。 

制約は非常に小さく、最大でも 100 個のテスト ケースと次の値があります。$L$そして$N$これは、テスト ケースごとに一定時間で実行されるソリューションは簡単に十分に高速であることを意味します。$O(N)$テスト ケースごとのシミュレーションは、操作の総数が最大でも$10^5$, これは Python では簡単なことです。 

注意すべき主なエッジケースは、レイヤーが 1 つしかない場合です。 その場合の答えは単純に、$L$増分が発生しないためです。 もう一つのコーナーは、$N$に比べて大きい$L$、ただし、ここではまだ安全であるにもかかわらず、不必要なループを避けるために算術加算を慎重に行う必要がある範囲内です。 

## アプローチ

 答えを計算する簡単な方法は、各層の厚さを明示的に構築し、それらを合計することです。 特定のテスト ケースについては、次から開始します。$L$、次に 1 を繰り返し追加して次のレイヤーを生成し、このプロセスを続行します$N$合計を累積しながら回します。 これは問題の定義に直接従うため機能します。 問題は正確さではなく効率性の考え方です。このアプローチは次のように直線的にスケールします。$N$、各テスト ケースにコストがかかることを意味します$O(N)$操作。 と$T = 100$そして$N = 1000$、せいぜいこれくらいです$10^5$追加することはまだ問題ありませんが、シーケンスの構造を考えると不必要な作業です。 

重要な観察は、シーケンスが等差数列であるということです。 シミュレーションの代わりに、等差数列の合計の公式を使用できます。 最初の項は$L$、最後の項は$L + (N - 1)$、そして、あります$N$条項。 したがって、合計は次のようになります。$$\text{sum} = \frac{N}{2} \cdot (2L + (N - 1))$$これにより、各テスト ケースが一定時間の計算に減り、反復が完全に排除されます。 正しさは等差級数の標準特性から得られ、問題の構造により、このパターンから逸脱しないことが保証されています。

 ## アルゴリズムのチュートリアル

 等差数列公式を使用して、各テスト ケースを個別に計算します。 

1. テストケースの数を読み取る$T$。 これにより、処理する必要がある独立したシーケンスの数が設定されます。 
2. 各テスト ケースについて、次の内容を読んでください。$L$そして$N$、シーケンスの開始点と長さを定義します。 
3. もし$N = 1$、 戻る$L$レイヤーが 1 つしかなく、進行が発生しないため、すぐに実行されます。 
4. それ以外の場合は、次の式を使用して合計を計算します。$N \cdot (2L + (N - 1)) // 2$。 これが機能するのは、最初と最後の項をペアにすると常に同じ合計が得られるためです。 
5. 各テストケースの計算値を出力します。 

### なぜ効果があるのか

 各シーケンスはステップごとに厳密に 1 ずつ増加し、定数差 1 の等差数列を形成することが保証されます。このようなシーケンスでは、最初と最後の項、2 番目と最後から 2 番目などをペアにすることで合計を書き換えることができます。 すべてのペアの合計は同じになります$2L + (N - 1)$、そしてまさにあります$N/2$このようなペア (偶数と奇数の両方のケースをカバーする整数処理)。 この不変式は、次の大小に関係なく成立します。$L$または$N$、数式が常にシーケンスの直接和と一致するようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        L, N = map(int, input().split())
        # sum of arithmetic progression: L + (L+1) + ... + (L+N-1)
        # = N * (2L + (N-1)) / 2
        total = N * (2 * L + (N - 1)) // 2
        print(total)

if __name__ == "__main__":
    solve()
```このソリューションはすべてのテスト ケースを読み取り、閉じた形式の式を直接適用します。 整数演算と整数除算を維持するために、乗算は除算の前に行われます。`//`全体を通して整数にとどまることを保証します。 これにより、浮動小数点エラーが回避されます。 

重要な実装の詳細は、式を整数セーフな形式に保つことです。 書き込み`(N / 2) * (...)`would risk floating-point issues in other languages, but here we explicitly use integer multiplication and floor division.

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    T = int(input())
    for _ in range(T):
        L, N = map(int, input().split())
        total = N * (2 * L + (N - 1)) // 2
        output.append(str(total))

 ## 特殊なケース

 ### 単層ケース

 入力:```
10 1
```ここで、シーケンスには値 10 が 1 つだけあります。アルゴリズムは次のように計算します。$$1 \cdot (2 \cdot 10 + 0) // 2 = 20 // 2 = 10$$最後の項が最初の項と等しいため、この式は引き続き機能し、ペアリングは正しく縮退します。 

### 最大長の進行

 入力:```
1 1000
```シーケンスは 1 から 1000 まで実行されます。アルゴリズムは次を計算します。$$1000 \cdot (2 + 999) // 2 = 1000 \cdot 1001 // 2$$これは整数演算で正確に評価され、Python にはオーバーフローの問題は存在しません。 この構造により、正確な合計を生成しながら、1000 項すべてのループが回避されます。
