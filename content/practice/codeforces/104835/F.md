 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$, ここで、各セルには高さの値が含まれています。 このグリッドは、高さの異なるバクラヴァの作品の風景として考えてください。 ゼイネプはいくつかの開始セルに繰り返しシロップを注ぎます。 シロップは各開始点から隣接するセルに広がりますが、シロップが「下り坂に流れるか水平に留まる」ことが許可される移動に沿ってのみ行われます。 

セルから許可される移動$(i, j)$隣接する 4 つの位置 (真上、真下、左斜め上、右斜め下) に移動します。 記号で言えば、これらは$(i-1, j)$、$(i+1, j)$、$(i-1, j-1)$、 そして$(i+1, j+1)$。 シロップは、隣接セルの高さが現在のセルの高さ以下である場合にのみ、隣接セルに移動できます。 シロップがクエリポイントに注がれると、これらのルールに従って可能な限り遠くまでシロップが広がり、到達したすべてのセルを記録します。 1 つの注ぎが終了すると、プロセスがリセットされ、次の注ぎが新たに開始されます。 

タスクは、すべての流し込みにおいて、どのグリッド セルが最も多くアクセスされたかを判断することです。 複数のセルが結合されている場合は、行インデックスが最も小さいセルを選択する必要があり、依然として結合されている場合は列インデックスが最小のセルを選択する必要があります。 

グリッドには最大 100 x 100 のセルがあるため、ノードの数は最大 10,000 個になります。 各クエリはフラッドのようなトラバーサルを開始する可能性があり、クエリは最大 1,000 個あります。 これにより、グリッド サイズでの線形または線形に近い作業を超えて、クエリごとにグリッド全体で高価な再計算を実行しようとするアプローチは直ちに排除されます。 おおよその解決策は$O(q \cdot n \cdot m)$のオーダーであるため、許容されます。$10^7$操作。 

素朴な実装の微妙な失敗例は、動きが高さによって制限されることを忘れていることです。 たとえば、すべての高さがパスに沿って厳密に増加しているにもかかわらず制約を無視した場合、グリッドが完全に接続されているものとして誤って扱われることになります。 

もう 1 つの落とし穴は、異なる注入間で接続が混在していることです。 各クエリは独立して処理する必要があります。 誤ってクエリ間で訪問済みの状態を保持すると、以前の BFS 結果が後の結果を汚染し、カウントが人為的に増大します。 

## アプローチ

 この問題を直接解釈すると、各クエリ セルからフラッド フィルを実行することが示唆されます。 開始位置から、キューまたはスタックを使用して、高さの制約を満たす有効な移動のみに従って、到達可能なすべてのセルを探索します。 セルに到達するたびに、そのグローバル カウンターがインクリメントされます。 

この総当たり戦略は、制約を考慮するとすでに最適に近いものになっています。 各 BFS または DFS は、最大ですべてのデータを探索します。$n \cdot m$各セルは 4 つの可能な移動により一定の回数処理されます。 最大 1000 クエリの場合、最悪の場合の作業は約$1000 \times 10000 = 10^7$州訪問。慎重に実装すれば Python で許容されます。 

到達可能性が開始点と単調高さの条件に依存するという意味で、グラフ構造はクエリに依存するため、より高度な前処理は必要ありません。 すべてのペア間の到達可能性を事前に計算することは不必要であり、コストも高くなります。 

重要な観察は、各クエリが独立しており、固定グリッド上で単純な加算頻度に寄与していることです。 これにより、問題は、制約付きの到達可能性のカウントが繰り返されるという問題に変わります。

 ## アルゴリズムのチュートリアル

 各シロップの注入を個別にシミュレートし、カバレッジ カウントを蓄積します。 

1. 2D 配列を初期化する`cnt`サイズの$n \times m$ゼロ付き。 これにより、すべての注入で各セルに到達した回数が保存されます。 
2. クエリ開始セルごとに、BFS または DFS を実行します。 また、1 回の注入内で同じセルを 2 回処理しないようにするために、ローカルの訪問先配列も維持します。 これは、複数のパスが同じセルに到達する可能性があるため必要ですが、クエリごとに 1 回のみカウントする必要があります。 
3. 開始セルからキューにプッシュし、訪問済みとしてマークします。 セルの処理中$(i, j)$、許可された 4 つの方向をすべて試します。 隣人ごとに$(ni, nj)$では、2 つの条件をチェックします。それはグリッド内にあり、その高さは以下です。$h[i][j]$。 両方が保持され、このクエリで訪問されていない場合は、訪問済みとしてマークし、キューに追加します。 
4. クエリで訪問したセルにマークを付けるたびに、値が増加します。`cnt[i][j]`1つずつ。 これにより、各セルが注入ごとに最大 1 回だけ寄与することが保証されます。 
5. すべてのクエリを処理した後、`cnt`配列を使用して最大値を見つけます。 複数のセルが同じ最大値を共有する場合は、行が最小、列が最小のセルが選択されます。 

### なぜ効果があるのか

 各クエリの BFS は、許可された移動を使用した単調非増加高さ制約の下で到達可能なすべてのセルを正確に列挙します。 クエリごとに訪問済みをマークするため、各セルは注入ごとに最大 1 回カウントされ、「シロップで覆われた」の定義と一致します。 クエリを合計すると、独立した寄与が蓄積されます。 クエリごとにすべての到達可能な状態を評価するため、到達可能なセルが見逃されることはなく、到達不能なセルも含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, q = map(int, input().split())
    h = [list(map(int, input().split())) for _ in range(n)]

    cnt = [[0] * m for _ in range(n)]

    dirs = [(-1, 0), (1, 0), (-1, -1), (1, 1)]

    for _ in range(q):
        si, sj = map(int, input().split())
        si -= 1
        sj -= 1

        vis = [[False] * m for _ in range(n)]
        dq = deque()
        dq.append((si, sj))
        vis[si][sj] = True
        cnt[si][sj] += 1

        while dq:
            i, j = dq.popleft()
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    if not vis[ni][nj] and h[ni][nj] <= h[i][j]:
                        vis[ni][nj] = True
                        cnt[ni][nj] += 1
                        dq.append((ni, nj))

    best_i, best_j = 0, 0
    for i in range(n):
        for j in range(m):
            if cnt[i][j] > cnt[best_i][best_j]:
                best_i, best_j = i, j
            elif cnt[i][j] == cnt[best_i][best_j]:
                if i < best_i or (i == best_i and j < best_j):
                    best_i, best_j = i, j

    print(best_i + 1, best_j + 1, cnt[best_i][best_j])

if __name__ == "__main__":
    solve()
```グリッドは整数として直接保存され、クエリごとに新しい訪問行列が作成されます。これは、クエリ間で再利用すると独立したフラッド フィルが誤ってマージされるためです。 BFS は両端キューを使用して、クエリごとの線形時間トラバーサルを保証します。 

方向リストは、許可される 4 つの動きを正確にエンコードします。 高さチェックはエッジを拡張するときに適用され、有効な下り坂または平坦な遷移のみを追跡することが保証されます。 

最後に、最大周波数と辞書編集規則の両方を考慮して、グリッド上の 1 回のスキャンで最適なセルの選択が行われます。 

## 実用的な例

 サンプル入力の簡略化されたバージョンでプロセスをトレースします。 

小さなグリッドを考えてみましょう。 

| ステップ | クエリ開始 | 訪問したセル | 主な更新情報 |

これは、各注入が独立して寄与し、重複が自然に蓄積されることを示しています。`cnt`。 

ここで、すべての高さが等しい縮退ケースを考えてみましょう。 すべての BFS は完全なグリッド トラバーサルになるため、各セルは正確に受信します。$q$増加します。 次に、タイブレーク ルールによってセル (1,1) が選択され、正しい辞書編集処理が確認されます。

 ## 特殊なケース

 すべての値が等しく、すべてのセルがすべての開始点から到達できるグリッドを考えてみましょう。 各 BFS はグリッド全体をフラッディングするため、すべてのセルが正確に蓄積されます。$q$増加します。 その後、アルゴリズムはグリッドをスキャンし、必要なタイブレーク ルールに一致する辞書編集上の最小の座標 (1,1) を選択します。 

ここで、(2,2) に厳密な高さのピークがあり、その周囲が下位の近傍に囲まれている場合を考えてみましょう。 クエリが低いセルから開始される場合、すべての移動で高さが増加しないことが必要となるため、クエリはピークまで登ることができません。 クエリがピークで開始される場合、BFS はパターンに応じて、同じかそれ以下の接続されたすべてのセルに外側に拡張できます。 クエリごとの訪問済みチェックにより、有効な開始点ごとにピークが 1 回だけカウントされることが保証され、BFS 制限により、不正な上向き遷移が発生しないことが保証されます。
