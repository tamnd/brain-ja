 ## 解決策
 ## 問題の理解

 私たちは道路で結ばれた都市のツリーを与えられており、どの道路でも所要時間は等しい。 これらの都市のサブセットにはチームが含まれています。 タスクは、すべてのチームがまったく同じ数のエッジで到達できるように 1 つの都市を選択することです。 そのような都市が存在しない場合は、不可能であることを報告する必要があります。 

これを言い換えると、マークされたすべての頂点までの距離が同じ頂点を探しているということになります。 グラフはツリーであるため、距離はパスによって一意に定義されるため、この条件は、選択されたすべての都市が、ある頂点を中心とする共通の「球」上に存在することを要求するのと同等です。 

この制約により、最大 200,000 都市が許可されるため、すべてのペアの距離を計算したり、距離を最初から再計算しながらすべての候補中心を試行したりするアプローチは直ちに除外されます。 テスト アクションごとの線形または線形に近い走査が唯一の実行可能な方向であるため、O(n log n) を超えるものは回避する必要があります。 

選択した都市が「バランスのとれた」構造を形成しているが、どの頂点にも中心がない場合、微妙なエッジケースが現れます。 たとえば、ライン 1-2-3-4 で、チームが 1 と 4 にある場合、その中点は頂点ではなくエッジ (2,3) であるため、有効な答えは存在しません。 距離を平均したり、中間点のインデックスを選択したりする単純なアプローチでは、丸めに応じて誤って 2 または 3 が返されます。 

もう 1 つのエッジケースは、チーム都市が 1 つしかない場合です。 単一の点までの距離が等しい頂点は、自明に条件を満たします。そのため、すべての都市は、要件が正しく解釈された場合にのみ有効です。距離の制約は空ですが、すべての距離が等しくなければならないため、どの中心でも機能します。 

## アプローチ

 強引なアイデアは、各都市を候補地として試すことから始まります。 各候補について、BFS を使用してその中心から m チームのすべての都市までの距離を計算し、すべての距離が一致するかどうかを確認します。 各 BFS は O(n) であるため、合計の複雑さは O(nm) となり、最悪の場合は 4 × 10^10 の演算になります。 これは実現可能な限界をはるかに超えています。 

重要な観察は、実際には候補ごとに独立して距離を照合しようとしていないということです。 代わりに、ツリー内の距離の構造により、中心の可能性に対して強い制約が課されます。 頂点が機能する場合、マークされたすべてのノードはその頂点に対して同じ深さに存在する必要があります。これは、それらのペア構造が高度に制約されていることを意味します。 特に、マークされたノードを基準として使用する場合、候補中心は、他のすべてのマークされたノードまでの距離のバランスが取れたパス上に存在する必要があります。 

これは、問題を、マークされたノードのみによって引き起こされる構造を理解することに帰着させることを示唆しています。 マークされたノードを選択し、そこからの距離を考慮する場合、他のすべてのマークされたノードについて、このノードに対する距離の差が一貫している必要があります。 これは、マークされた 1 つのノードをルートとして、深さの差と極値を分析するという古典的なツリー手法につながります。 

最終的な縮小は、可能な中心のみが、最も遠くにマークされたノードによって課される制約の交点に存在する必要があるということです。 マークされたノード間の直径の端点を計算すると、最も厳しい境界が得られます。中心が存在する場合、それはこの直径の固定された中点領域に存在する必要があり、その構造から導出された候補を検証します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 直径ベースの縮小 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 任意のチーム都市を選択し、BFS を実行して、マークされたすべてのノードの中でそこから最も遠いチーム都市を見つけます。 これにより、ツリー内のマークされたノードの直径の 1 つの端点が識別されます。 
2. そのエンドポイントから 2 番目の BFS を実行して、そのエンドポイントから最も遠いマーク付きノードを見つけます。 これにより、マークされた都市によって引き起こされる直径の反対側の端点が得られます。 
3. これら 2 つの端点間の距離を計算します。 距離が奇数の場合は、両端から正確に等しい距離にある頂点が存在しないため、すぐに「NO」を返します。これは、ツリー内に整数の中心が存在しないことを意味します。 
4. 2 つのエンドポイント間のパス上で中間点ノードを見つけます。 距離が偶数の場合、中間頂点は 1 つだけ存在します。 それ以外の場合は 2 つの候補がありますが、ここでは正確な頂点の場合のみが有効です。 
5. 候補中心を取得し、この候補から BFS を使用してマークされたすべての都市までの距離を計算することによって検証します。 すべての距離が等しいことを確認してください。 
6. 検証に合格した場合は、「YES」と候補都市を出力します。 それ以外の場合は「NO」を出力します。 

最後の検証ステップを行う理由は、直径の制約は必要ですが、単独では十分ではないためです。 複数のマークされたノードは、明示的にチェックされない限り、中点からの全体的な等距離に違反しながらも、同じ直径の端点を共有できます。 

### なぜ効果があるのか

 頂点がすべてのマークされたノードから等距離にある場合、特に、頂点は最も遠い 2 つのマークされたノードから等距離にあり、誘導メトリック内で直径のペアを形成する必要があります。 有効な中心は、それらの間の一意のパス上にあり、両端から等距離にある必要があります。これにより、中心が中点に移動します。 逆に、中間点が存在し、すべてのマークされたノードがそこから同じ BFS 深さにある場合、パスが一意で追加的なツリー内の構築により、すべての距離が等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, n, adj):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    teams = list(map(int, input().split()))

    if m == 1:
        print("YES")
        print(teams[0])
        return

    # first BFS from any team node
    d0 = bfs(teams[0], n, adj)
    a = max(teams, key=lambda x: d0[x])

    # second BFS from a
    d1 = bfs(a, n, adj)
    b = max(teams, key=lambda x: d1[x])

    # check midpoint feasibility
    dist_ab = d1[b]

    # BFS again from a to reconstruct path parents
    parent = [-1] * (n + 1)
    q = deque([a])
    parent[a] = 0
    while q:
        v = q.popleft()
        for to in adj[v]:
            if parent[to] == -1:
                parent[to] = v
                q.append(to)

    path = []
    cur = b
    while cur != 0:
        path.append(cur)
        if cur == a:
            break
        cur = parent[cur]
    path.reverse()

    if len(path) != dist_ab + 1:
        print("NO")
        return

    mid = len(path) // 2
    if len(path) % 2 == 0:
        print("NO")
        return

    c = path[mid]

    dist_c = bfs(c, n, adj)
    target = dist_c[teams[0]]

    for t in teams:
        if dist_c[t] != target:
            print("NO")
            return

    print("YES")
    print(c)

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装では、まず BFS 距離比較を使用して 2 つの極値チーム ノードを抽出します。これにより、サブセットの直径の端点が効果的に近似されます。 次に、1 つのエンドポイントをルートとする BFS ツリーからの親ポインターを使用して、これらのエンドポイント間のパスを再構築します。 

中間点ロジックは、パス長パリティに厳密に関連付けられています。 パスの長さがエッジに関して均等である場合、中央ノードは 1 つです。 そうしないと、正確な頂点が中心として機能できなくなります。 

最後に、候補者センターからの BFS が不可欠です。 直径引数は候補を絞り込みますが、すべての構成での正確性が保証されるわけではないため、マークされたすべてのノードまでの距離が等しいことを明示的に検証します。

 中間点はノード 3 です。3 からの最終的な BFS により、ノード 1、5、6 までの距離 2、2、2 が得られ、有効性が確認されます。 

これは、中心頂点が存在し、マークされたすべてのノードから正確に等しい距離にある場合を示しています。

```ここで、マークされた 2 つのノードは 1 つのエッジの端点です。 パスの長さは 1 で、これは奇数です。 

| ステップ | エンドポイント A | エンドポイント B | パス | 中間点 |

 ## 特殊なケース

 チーム都市が 1 つだけの場合、アルゴリズムはすぐにそれを中心として受け入れます。 比較する値が 1 つだけであるため、任意の候補中心からの BFS は、自明に等しい距離を報告します。そのため、正確さの条件は空虚に成立します。 

すべてのチームが折れ線グラフの直線パス上にあるが、端のチーム間のエッジの数が奇数である場合、計算された中点は頂点の間に位置します。 このアルゴリズムは中心を選択する前にパリティを明示的にチェックし、無効な頂点の選択を防ぎます。 

複数のブランチが存在するが、チーム セットが中心頂点を中心に対称である場合、直径に基づく候補が誤解を招く場合でも、BFS 検証ステップによって正確さが保証されます。 等距離チェックでは、グローバルな均一性を満たさない候補は拒否され、真にバランスの取れた構成のみが合格することが保証されます。
