 ## 解決策
 ## 問題の理解

 各ノードがキーと、固定関数を使用してキー自体から導出される優先順位を持つ、決定論的な treap 定義が与えられます。$y = \sin(x)$。 優先順位がランダムである通常の treap とは異なり、ここではキーのセットを選択すると構造が完全に決定されます。 

トレプは 2 つの制約を同時に適用します。 キーは二分探索ツリーのルールを満たす必要があります。つまり、左側のサブツリーのすべてのキーは小さく、右側のサブツリーのすべてのキーは大きくなります。 優先順位はヒープ ルールを満たします。つまり、親ノードは子ノードよりも高い優先順位を持つ必要があります (ステートメントでは、下方向に流れる優先順位が小さいか等しいと定義されているため)。 

優先順位が決定的であるため、ツリーの形状はランダムではなくなります。 それはペアから構築されたデカルト木です$(x, \sin(x))$。 この問題は私たちに構築を求めます$n$それぞれが 32 ビットの符号付き範囲内にある個別の整数キー。結果として得られる treap の高さが可能な限り最大になるように、つまり長さのチェーンに縮退します。$n$。 

重要な制約は、構造が順序比較によって完全に決定されることです。$x$そしてさらに$\sin(x)$。 優先順位を変更したり、トレプに直接影響を与えることはできません。キーの選択のみが許可されます。 

明白ではない難しさは、$\sin(x)$有界かつ振動的です。 単調な整数シーケンスを使用しようとする単純なアプローチは失敗します。$\sin(x)$長距離にわたって単調ではありません。 

たとえば、次のような連続した整数を試してみるとします。 

入力:```
5
0 1 2 3 4
```サイン値は次のようになります。$$0, 0.84, 0.91, 0.14, -0.75$$最大の正弦値がシーケンスの中央に現れ、ツリーが分割されるため、構造はチェーンではなく自明ではない方法ですぐにバランスが取れます。 

目標は、キーの順序と優先順位の間で一貫した順序付けを強制する方法を理解して、すべての再帰的な分割で意味のある 1 つの側面だけが繰り返し生成され、縮退したツリーが生成されるようにする方法を理解することです。 

制約から、$n \le 5 \cdot 10^4$、したがって、$O(n)$または$O(n \log n)$工事。 構造を持たずに整数を盲目的に繰り返し検索しようとすると、慎重に指導しないと遅くなりすぎる危険があります。 

## アプローチ

 ブルートフォースのアイデアは、整数のランダムなセットを試し、チェーンが見つかるまでトレプを構築することです。 これは理論的には正しいです。ランダム サンプリングによって最終的に順序が揃う可能性があるからです。$\sin(x)$の注文で$x$徹底的にモノトーンで。 ただし、トレプコストの構築と検証は$O(n \log n)$、この検索を繰り返すと実行できなくなります。 最悪の場合、成功する確率は非常に低くなります。$\sin(x)$振動しており、整数の順序と自然には一致しません。 

重要な洞察は、考えるのをやめるということです$\sin(x)$カオス関数として使用し、代わりに構造特性を使用します。振動しますが、整数上のそのイメージは密集しています。$[-1, 1]$。 これは、必要な増加シーケンスに近い正弦値を持つ整数を見つけることができ、慎重に選択することでグローバルな順序付けを強制できることを意味します。 

整数のシーケンスを構築できた場合$x_1 < x_2 < \dots < x_n$そのような$$\sin(x_1) < \sin(x_2) < \dots < \sin(x_n),$$その場合、デカルト木は完全に退化します。 その理由は、最大のサイン値は常に右端の要素に属し、それがルートとなり、すべてのサブツリーが再帰的に同じ構造を繰り返し、単一のチェーンを生成するためです。 

構築の問題は、シーケンスの厳密に増加するサブシーケンスを見つけることに帰着します。$\sin(k)$整数を超えて使用できますが、必ずしも連続した整数である必要はありません。 整数を超えるサイン値は密度が高いため、$[-1,1]$、サイン値が徐々に増加する整数を貪欲に選択できます。 

これにより、問題は構造ツリー操作の問題ではなく、整数に対する貪欲な選択プロセスに変換されます。

 ## アルゴリズムのチュートリアル

 1. 選択したキーの空のリストと、最初に以下に設定された最後の正弦値を追跡する変数から開始します。$-1$、 のような$-2$。 これにより、実際の正弦値は最初は確実に大きくなります。 
2. 十分に小さい値から開始して整数を反復します。たとえば、$-10^9$上向きに、候補となる整数を 1 つずつチェックします。 各整数について$x$、計算する$\sin(x)$。 
3. もし$\sin(x)$最後に記録された正弦値より厳密に大きい場合、受け入れます$x$をシーケンス内の次のキーとして使用し、最後の正弦値を更新します。 それ以外の場合は、スキップして検索を続けます。 
4.正確になるまで繰り返します$n$整数が選択されました。 サイン値は密で振動しているため、指数関数的な検索を必要とせずに、最後の値を改善する候補を継続的に見つけます。 
5. 選択した整数を選択した順序で出力します。 

重要な考え方は、選択プロセスでは、増加するキーに合わせて厳密に増加する優先順位を強制するということです。 この調整により、トレプが強制的に縮退します。 

### なぜ効果があるのか

 から構築された秘宝$(x, \sin(x))$ルートが最大値を持つノードであるデカルト ツリーです。$\sin(x)$、同じルールがキーによる左右のパーティションに再帰的に適用されます。 キーが増加し、優先順位も同じ順序で増加する場合、各ステップで最大の優先順位は常に現在のセグメントの右端になります。 これにより、各再帰的分解で末尾から 1 つのノードだけが削除され、長さのチェーンが生成されることが保証されます。$n$。 

不変条件は、選択後のものです。$k$要素では、そのサイン値は厳密に増加し、キーは厳密に増加します。 これにより、サブ問題の次に選択されるルートが常にキー順序の最後の要素となり、分岐が発生しないことが保証されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    res = []
    
    last_val = -2.0
    x = -10**6  # starting search point
    
    while len(res) < n:
        val = math.sin(x)
        if val > last_val:
            res.append(x)
            last_val = val
        x += 1
    
    sys.stdout.write("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```このソリューションは、正弦値を改善する値を貪欲に収集しながら、整数に対して単一の線形スキャンを実行します。 重要な点は、選択したサブシーケンスで厳密な単調性を維持することです。 ここでは、正確な値ではなく順序のみに依存するため、浮動小数点比較は安全です。 

キー挿入とサイン値の間の順序は、トレプ構造を直接決定するものであるため、両方が一緒に増加することを保証することで、最大限の縮退が強制されます。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n = int(input())
    res = []
    last = -2.0
    x = -1000
    
    while len(res) < n:
        v = math.sin(x)
        if v > last:
            res.append(x)
            last = v
        x += 1
    
    return "\n".join(map(str, res)) + "\n"

# minimal
assert len(run("1\n").strip().splitlines()) == 1

# small case
assert len(run("3\n").strip().splitlines()) == 3

# monotonic check
out = run("5\n").strip().splitlines()
vals = [math.sin(int(x)) for x in out]
assert all(vals[i] < vals[i+1] for i in range(len(vals)-1))

# larger case
assert len(run("10\n").strip().splitlines()) == 10

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは、サインが初期しきい値を超える最初の整数を直ちに受け入れ、有効な単一ノード トリープを生成します。 

非常に小さい場合$n$、貪欲スキャンは増加する正弦値を見つける前にいくつかの整数をスキップする可能性がありますが、正弦波は短い間隔でも密に振動するため、選択はそれでもすぐに終了します。 

大型の場合$n$、主な懸念は、スキャンが停止するかどうかです。 十分に長い間隔内では、正弦値が全範囲を横切るため、そうではありません。$[-1, 1]$、現在のしきい値を超えて建設を継続する機会が繰り返し保証されます。
