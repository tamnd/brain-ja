 ## 解決策
 ## 問題の理解

 平面上に配置された一連の垂直柱が与えられ、それぞれの柱は整数座標に位置し、必要な最小高さを持っています。 すべての辺が頂点から正確に 45 度で下に傾斜するという固定の幾何学的制約を使用して、辺が座標軸と一致する正方形ベースのピラミッドを配置したいと考えています。 頂点は整数の座標中心に位置し、整数の高さを持ちます。 

ピラミッドは、平面上の高さ関数を定義します。 どの点でも、高さはチェビシェフの意味でその点が中心からどのくらい離れているかによって決まります。つまり、水平方向と垂直方向の変位の最大値によって高さが線形に減少します。 その座標におけるピラミッドの高さが少なくとも柱に必要な高さである場合、点はピラミッドの内側にあります。 

タスクは、ピラミッドの高さをできるだけ小さくしながら、すべての柱が覆われるようにピラミッドの中心と高さを選択することです。 

入力サイズは十分に小さいため、候補チェックごとにおよそ n log n または n log C の解が許容されます。 n が 1000 までの場合、O(n^2 log C) 構造でも限界に達しますが、遅すぎる可能性がありますが、実現可能性チェックを行った O(n log C) または O(n log C) は安全です。 

素朴なアプローチでは、入力座標の影響を受けるすべての整数グリッド点の間で考えられるすべての中心を試し、必要な高さを計算します。 座標の範囲は 10^8 までであるため、すべての候補を列挙することは不可能です。 入力座標に制限しても O(n^2) 個の候補が残り、各評価のコストは O(n) となり、O(n^3) となり、非常に遅すぎます。 

素朴な推論による微妙な失敗例は、最良の中心がオベリスクの位置の 1 つであるに違いないと仮定することから生じます。 たとえば、(0,0,1) と (100,100,1) の 2 つの点は、(50,50) の周りの対称性を示唆していますが、これは入力点ではありません。 候補を入力座標に制限するアプローチでは、そのような最適な解決策が失われます。 

もう 1 つの問題は、チェビシェフ距離の代わりにユークリッド距離またはマンハッタン距離を仮定することです。 傾き制約は四角錐を定義するため、正しいメトリックは max(|dx|,|dy|) です。 間違ったジオメトリを使用すると、体系的に不正確な実行可能性チェックが行われます。 

## アプローチ

 主な問題点は、高さ制約が中心とオベリスクの高さの両方を含む最大式を通じてすべてのポイントを結合することです。 固定中心 (x, y) の場合、必要なピラミッドの高さは最悪のオベリスク、具体的には hi + max(|xi − x|, |yi − y|) のすべての i の最大値によって決まります。 

ブルート フォース戦略では、境界ボックス内のすべての可能な整数の中心を反復処理し、各中心のこの値を計算します。 各候補中心について、すべてのオベリスクをスキャンし、必要な高さを計算し、最大値を取得します。 これは正しいですが、最悪の場合のコストは格子点の数と n の積に比例します。これは、最大 10^8 の座標範囲では実行不可能です。 

重要な観察は、(x, y) を直接検索する代わりに、チェビシェフ距離の構造を使用して問題を再定式化できることです。 式 max(|xi − x|, |yi − y|) は、標準の座標変換後に線形になります。 A = x + y および B = x − y を導入すると、チェビシェフ距離は 2 つの独立した軸上の制約に分解されます。 これにより、問題は (A, B) で定義される 2D 空間内で重複する間隔を見つけることに変換されます。ここで、各オベリスクは両方の座標に独立した制約を課します。 

この分離により、平面上の幾何学的最適化の問題が、実現可能性チェック内の 2 つの独立した区間交差問題に縮小されます。 固定高さの実現可能性が線形時間でチェック可能になったら、最小高さを二分探索できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | センターに対するブルートフォース | O(R²・n) | お(1) | 遅すぎる |
 | 二分探索 + 区間の実現可能性 | O(n log C) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ピラミッド制約を候補の高さの実現可能条件に再公式化し、その高さの最小値を検索します。 

1. オベリスクごとに pi = xi + yi および qi = xi − yi を定義して座標を変換します。 この線形変更により、チェビシェフ ジオメトリが、変換された空間内の軸に沿った拘束に変換されます。 
2. ピラミッドの高さの 2 倍を表す候補値 T について、各オベリスクのマージン di = T − 2hi を導出します。 これは、オベリスクを覆いながら、変換された空間内で中心がどの程度偏ることができるかを表します。 
3. 各オベリスクについて、その要件を A = x + y および B = x − y の間隔制約に変換します。 具体的には、A は [pi − di, pi + di] に存在し、B は [qi − di, qi + di] に存在する必要があります。 
4. 固定 T の場合、すべての A 間隔とすべての B 間隔の交差を個別に計算します。 実現可能条件は、両方の交差点が空ではないことです。 これにより、高さ T 未満のすべてのオベリスクと一致する中心が存在することが保証されます。 
5. 実現可能性を満たす最小の T を二分探索します。 有効なピラミッドは少なくとも距離 0 の最も高いオベリスクをカバーする必要があるため、探索空間は 2 · max(hi) から始まります。 
6. T を見つけた後、両方の交点内の任意の整数を選択して、有効な A と B を再構築します。 次に、x = (A + B) / 2 および y = (A − B) / 2 を使用して x と y を回復します。 

唯一の微妙な部分は、x と y が整数のままとなるように A と B が同じパリティを持つようにすることです。 最初に選択したペアがパリティに違反している場合は、共通部分内で A または B を最大 1 ステップ調整するだけで十分です。 

### なぜ効果があるのか

 各オベリスクは、変換された座標系におけるピラミッドの中心の可能な位置を個別に制限します。 これらの制限により、A 軸と B 軸の両方に凸状の間隔が形成されます。 ピラミッドは、これらすべての凸型制約が同時に重なる場合に正確に有効になります。 二分探索により、この交差部分が空でない最小のグローバル スラック T が分離され、変換により、次元を分離する際に幾何学的情報が失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(n, pts, T):
    lowA = -10**30
    highA = 10**30
    lowB = -10**30
    highB = 10**30

    for x, y, h in pts:
        d = T - 2 * h
        if d < 0:
            return None
        p = x + y
        q = x - y

        lowA = max(lowA, p - d)
        highA = min(highA, p + d)
        lowB = max(lowB, q - d)
        highB = min(highB, q + d)

    if lowA > highA or lowB > highB:
        return None
    return (lowA, highA, lowB, highB)

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    lo = 2 * max(h for _, _, h in pts)
    hi = 2 * (10**8 + 10**8 + max(h for _, _, h in pts))

    ans = None

    while lo <= hi:
        mid = (lo + hi) // 2
        res = check(n, pts, mid)
        if res is not None:
            ans = (mid, res)
            hi = mid - 1
        else:
            lo = mid + 1

    T, (lowA, highA, lowB, highB) = ans

    A = lowA
    B = lowB

    if (A & 1) != (B & 1):
        if A + 1 <= highA:
            A += 1
        else:
            B += 1

    x = (A + B) // 2
    y = (A - B) // 2
    h = T // 2

    print(x, y, h)

if __name__ == "__main__":
    solve()
```実現可能性チェックでは、変換された座標 A および B に対応する 2 つの独立した間隔の交差が維持されます。各オベリスクは、高さ調整されたリーチに基づいて両方の間隔を狭めます。 二分探索では、最小のグローバル スラック T が探索され、見つかったら、再構成によって一貫した点が選択され、小さなパリティ補正によって元の座標の整数の復元が保証されます。 

よくある実装の落とし穴は、変換には A と B 間のパリティ アラインメントが必要であることを忘れていることです。これを修正しないと、有効な整数解が存在する場合でも、計算された x と y が半整数になる可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
1
0 0 5
```可能な最小値として T = 10 から始めます。 変換された制約により、p = 0、q = 0、および d = 10 − 10 = 0 が得られます。 

| オベリスク | p、q | d | 間隔 | B 間隔 |
 | --- | --- | --- | --- | --- |
 | (0,0,5) | 0,0 | 0 | [0,0] | [0,0] |

 両方の間隔が 1 点で交差します。 したがって、A = 0 および B = 0 となり、x = 0 および y = 0、高さ h = 5 となります。 

これは、ピラミッドが単一の柱の上に直接崩壊する退化したケースを示しており、解決策はアイデンティティの配置に帰着します。 

### 例 2

 入力:```
2
3 3 3
6 6 2
```T = 8 の場合、制約を計算します。 

| オベリスク | p、q | d | 間隔 | B 間隔 |
 | --- | --- | --- | --- | --- |
 | (3,3,3) | 6,0 | 2 | [4,8] | [-2,2] |
 | (6,6,2) | 12,0 | 4 | [8,16] | [-4,4] |

 A の交差は [8,8]、B の交差は [0,2] なので、実行可能です。 T が小さい場合、A 間隔は重なり合わなくなるため、これは最小限になります。 

A = 8 および B = 0 を選択すると、x = 4 および y = 4 となります。 

このトレースは、2 つの離れた制約のバランスから最適な中心がどのように現れるかを示しており、そこに入力点がないにもかかわらず、解は元のジオメトリの中点に収束します。

 ## 特殊なケース

 任意の座標にある単一のオベリスクは、二分探索により、最小ピラミッドの中心がその座標に正確に配置され、高さがオベリスクの高さに等しいことがすぐに識別されるため、正しく処理されます。 区間の構築は、変換された両方の軸の単一点に縮退します。 

2 つのオベリスクが遠く離れている場合、実現可能性チェックにより、両方の間隔ファミリーがオーバーラップするように T が十分に大きくなることが確認されます。 たとえば、(0,0,1) と (100,100,1) の点では、中間点領域が表示されるまで A と B の間隔が強制的に拡張されます。 アルゴリズムは、中間座標を推測する必要なく、これを自然に取得します。 

パリティの処理は、区間交差が有効であるが、固定パリティの整数のみが含まれる場合に重要です。 調整ステップにより、再構成された A および B が整数 x および y と一貫性を保ち、未処理の交差エンドポイントがパリティ制約によって異なる場合でも正確さが保たれることが保証されます。
