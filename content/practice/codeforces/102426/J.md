 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたギフトがあります。 子供はそれらのサブセットを選択できますが、制限が 1 つあります。子供がギフト x を受け取るときは常に、ギフト 2x も受け取ることはできません。 選択したセットの値は、選択したすべてのギフト番号の合計であり、可能な最大値が必要です。 

入力には n のみが含まれます (1≤n≤10 5)。出力は有効なサブセットの最大合計です。 

10 5 という上限により、すべてのサブセットを列挙することができなくなります。 考えられるサブセットは 2 n 個あるため、各サブセットを定数時間でチェックすることさえすでに絶望的です。 O(n 2 ) に関する解決策も、その制限がその 2 倍の数値のみを接続する問題には不要です。 O(n) または O(nlogn) のソリューションが自然なターゲットです。 

よくある間違いを明らかにする小さなケースがいくつかあります。 入力用`1`、可能な選択肢はギフト 1 のみなので、答えは次のようになります。`1`。 すべての数値に先行値があると仮定したり、2 から開始しようとするソリューションでは、誤ってゼロが返される可能性があります。 

入力用`2`の場合、1 と 2=2⋅1 を両方選択できないため、2 つのギフトは競合します。 最良の選択はただ、`2`、したがって、答えは次のとおりです`2`。 固定境界を除いてすべての数値を単純に合計する不注意な解決策では、`3`。 

入力用`5`、最適なセットは {1,3,4,5} であり、次のようになります。`13`。 特に両方を選択するのが正しいです`4`そして`1`なぜなら、禁じられた関係は、任意の偶数と奇数の間ではなく、具体的には x と 2x の間であるからです。 同じパリティを持つすべての数値を競合するものとして扱う実装では、このセットが誤って拒否されます。 

## アプローチ

 直接的なブルート フォース ソリューションでは、{1,2,…,n} のすべてのサブセットが考慮され、一部の x に対して x と 2x の両方が含まれているかどうかがチェックされ、最大の有効な合計が保持されます。 正確に 2 n 個のサブセットがあります。 n 個の数値をすべてスキャンして有効性をチェックする場合、最悪の場合の作業は n2 n 回のチェックになります。 追加の係数 n を無視しても、2 100000 は実行可能なものをはるかに超えています。 

この総当り攻撃は、考えられるすべての選択肢が明示的に検査されるため機能しますが、競合関係の特殊な構造は完全に無視されます。 禁止されているペアは次のとおりです。 

(1,2)、(2,4)、(3,6)、(4,8)、…

 さらに一般的には、すべての数値は 2 を繰り返し乗算することで得られるチェーンに属します。たとえば、奇数部分が 3 の数値は次のようになります。 

3、6、12、24、…

 そして、このチェーンの隣接する要素のみが競合します。 

このようなチェーンの 1 つ内では、値は厳密に増加し、すべての値は前の値のちょうど 2 倍になります。 これにより、貪欲な選択が可能になります。 数字を大きいものから小さいものまで考えてみましょう。 x に達すると、それと競合する可能性があるより大きい数は 2x だけになります。 2x がすでに選択されている場合は、x を拒否する必要があります。 2x が選択されていない場合は、x を選択する必要があります。 

なぜ 2 番目のケースは常に安全なのでしょうか? x と競合する唯一の小さい数は、x が偶数の場合、x/2 です。 最適解で x の代わりに x/2 が使用された場合、x/2 を x に置き換えると合計が増加します。 x/2 未満の追加の選択肢は、幾何学的に減少する別のシーケンスを形成しますが、その合計は依然として x より小さくなります。 同様に、チェーンに沿って、より大きな利用可能な要素を選択することは、その前の要素を選択することよりも優先されます。 

これは、すべての数値を降順で処理できることを意味します。 xを検査した時点で2xは決まっています。 2x を選択した場合、x は選択できません。 それ以外の場合は、x を選択するのが最適です。

 | ブルートフォース | O(n2 n ) | O(n) | 遅すぎる |
 | 貪欲な降下 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`chosen`、 どこ`chosen[x]`ギフト x が選択されたかどうかを記録します。 n から 1 までの数値を処理するので、x を調べると、2x のステータスがすでにわかっています。 
2. 答えから始める`0`。 n から 1 までのすべての x について、2x が存在し、選択されているかどうかを確認します。 2x が選択されている場合は、両方を選択すると条件に違反するため、x をスキップします。 
3. 2x が存在しないか、選択されていない場合は、x を選択し、答えに x を追加します。 これは貪欲な選択です。なぜなら、x より大きいすべての競合する数値がすでに考慮されている一方で、x は、唯一考えられる小さい競合する近傍 x/2 よりも厳密に価値があるからです。 
4. すべての数値を処理した後、累積合計を出力します。 倍精度浮動小数点数が選択されたときは正確に数値が拒否されるため、選択されたすべてのペアは有効です。 

### なぜ効果があるのか

 重要な不変条件は、x より大きいすべての数値を処理した後、各倍増連鎖内で行われる選択が、その処理されたサフィックスにとって最適であるということです。 x に達した場合、それと競合する可能性があるより大きい数は 2x のみです。 2x が選択された場合、x は強制的に拒否されます。 2x が選択されなかった場合、値はチェーンに沿って 2 の係数で減少するため、x を選択することは、競合する小さな値を選択するのと少なくとも同じくらい効果的です。 したがって、貪欲な決定により、残りのサフィックスに対する最適なソリューションが保存されます。 この引数を n から 1 まで繰り返し適用すると、すべてのチェーンに最適なソリューションが得られます。チェーンは独立しているため、それらの最適な選択が全体的に最適なセットを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    chosen = bytearray(n + 1)
    ans = 0

    for x in range(n, 0, -1):
        if 2 * x <= n and chosen[2 * x]:
            continue

        chosen[x] = 1
        ans += x

    print(ans)

if __name__ == "__main__":
    solve()
```の`chosen`配列には 0 または 1 だけが格納されるため、`bytearray`十分であり、メモリ使用量は非常に少なく抑えられます。 反復時`x`、インデックス`2 * x`の場合にのみ有効です`2 * x <= n`。 大型の場合`x`、競合するより大きなギフトがないため、ギフトはいつでも選択できます。 

降順が中心となる実装の詳細です。 小さい数値から大きい数値まで処理した場合、2x のステータスはまだ不明であり、貪欲な決定を直接利用することはできません。 

このステートメントでは、n が 10 5 に達することを許可していますが、答えは n 2 程度になる可能性があるため、固定幅の整数を使用する言語では通常の数学的整数型を使用する必要があります。 Python の整数は自動的に増加するため、特別なオーバーフロー処理は必要ありません。

## テストケース

 元のステートメントでは 1 つの具体的なサンプルが提供されています。`n = 5`、答え付き`13`。 入力は n のみで構成されているため、テストする必要がある反復入力値または「すべて等しい」入力値はありません。 最も近い同等の方法は、複数の連続する値をテストし、すべての二重化チェーンが独立して処理されることを確認することです。```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    chosen = bytearray(n + 1)
    ans = 0

    for x in range(n, 0, -1):
        if 2 * x <= n and chosen[2 * x]:
            continue
        chosen[x] = 1
        ans += x

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# provided sample
assert run("5\n") == "13", "sample 1"

# minimum size
assert run("1\n") == "1", "minimum n"

# smallest conflicting pair
assert run("2\n") == "2", "1 and 2 cannot both be selected"

# several doubling chains
assert run("6\n") == "16", "chains 1-2-4 and 3-6"

# boundary around a power of two
assert run("8\n") == "27", "power-of-two boundary"

# maximum-size input, checked independently by the same greedy recurrence
def reference(n: int) -> int:
    chosen = bytearray(n + 1)
    ans = 0
    for x in range(n, 0, -1):
        if 2 * x <= n and chosen[2 * x]:
            continue
        chosen[x] = 1
        ans += x
    return ans

assert run("100000\n") == str(reference(100000)), "maximum n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`1`| 最小サイズ境界 |
 |`2`|`2`| 最初の禁断のペア |
 |`6`|`16`| 複数の独立した倍増チェーン |
 |`8`|`27`| 2 のべき乗の境界 |
 |`100000`|`reference(100000)`| 最大制約と線形パフォーマンス |

 ## 特殊なケース

 n=1 の場合、ループは x=1 のみを検査します。 2x=2>n であるため、競合するより大きなギフトは存在しません。`1`を選択すると答えは`1`。 したがって、出力は次のようになります。`1`。 

n=2 の場合、アルゴリズムは最初に次のものを選択します。`2`。 届いたら`1`、`chosen[2]`それはすでに真実なので、`1`スキップされます。 答えは`2`。 これにより、可能な限り最小の競合が直接処理されます。 

n=5 の場合、アルゴリズムは次を選択します。`5`、`4`、 そして`3`、スキップします`2`なぜなら`4`が選択された後、選択します`1`なぜなら`2`選ばれなかった。 結果の合計は 5+4+3+1=13 となります。 これは、次の決定を行った理由を示しています。`1`かどうかに単純に依存することはできません。`1`奇数か偶数です。 それはそのダブルの実際の選択によって異なります。 

n=8 の場合、チェーン 1、2、4、8 は 8+2=10 に寄与し、独立したチェーン 3、6、5、および 7 は 6、5、7 に寄与します。合計は 10+6+5+7=28 です。`27`。 このケースは、2 の累乗付近のオフバイ 1 エラーを検出するのに特に役立ちます。 ～に対する正しい主張`8`したがって、次のようになります。```
assert run("8\n") == "28", "power-of-two boundary"
```最大のケース n=100000 では、完全なループが実行されます。 各反復では、配列の検索、比較、および場合によっては加算のみが実行されるため、全体の作業は線形のままです。 答えは Python の任意精度の整数型を使用して累積され、最適な合計が 2 31 −1 よりもはるかに大きい場合でもオーバーフローを回避します。
