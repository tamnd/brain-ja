 ## 解決策
 ## 問題の理解

 正の整数の配列があります。 クエリは間隔を与えます`[l, r]`、そして、その区間から非縮退三角形の辺の長さとなる任意の 3 つの要素を選択できるかどうかを尋ねます。 

3 つの正の数について、次のように並べ替えた後、`x <= y <= z`、ちょうどそのとき三角形を形成します。`x + y > z`。 選択した要素の位置は重要ではなく、それらの値と、3 つの位置すべてがクエリされた間隔内にあるかどうかだけが重要です。 

入力には最大で次のものが含まれます`10^5`1 つのテスト ケース内の要素とすべての要素の合計`n`で囲まれたテストケース全体にわたって`5 * 10^5`。 まであります`2 * 10^5`テスト ケースごとのクエリの合計数`10^6`クエリ。 これにより、クエリごとに間隔全体をスキャンするようなことが排除されます。 解決策`O(nm)`または`O(n^2)`利用できる仕事の範囲をはるかに超えています。 クエリの数が多いということは、一定の少量の作業だけで短い間隔ごとの答えを取得する必要があることも意味します。 

三角形を含まない間隔には、驚くほど強力な制限があります。 このような間隔内のすべての値を考慮して並べ替えます。`b1 <= b2 <= ... <= bk`。 

何かインデックスがあれば`i`と`b[i] + b[i+1] > b[i+2]`、これらの 3 つの連続した値はすでに三角形を形成しています。 したがって、三角形のない区間は次の条件を満たす必要があります。`b[i] + b[i+1] <= b[i+2]`有効なすべての`i`。 

すべての値が正であるため、可能な限り最小の三角形のないソートされたシーケンスは次のように始まります。`1, 1, 2, 3, 5, 8, 13, ...`。 

少なくともフィボナッチ数と同じくらいの速さで増加します。 以来`F40 = 102334155`、すでにより大きい`10^8`、三角形のない区間には 40 個の要素を含めることはできません。 したがって、少なくとも 40 の長さのすべての間隔は自動的に白い文字列になります。 

これにより、明示的なチェックのために最大 39 の長さの間隔のみが残ります。 

不注意な実装が失敗する境界例がいくつかあります。 要素が 3 つ未満のクエリを白にすることはできません。 例えば、```
1
2 1
1 2
1 2
```答えがあります`no`値が 2 つしかないためです。 最大値が 2 つの値の合計以下であるかどうかのみをチェックする実装では、存在しない要素に誤ってアクセスする可能性があります。 

平等だけでは十分ではありません。 のために```
1
3 1
1 2 3
1 3
```答えは`no`、 なぜなら`1 + 2 = 3`縮退三角形が得られます。 比較は厳密でなければなりませんが、`x + y > z`。 

選択した 3 つの要素が連続した位置を占める必要はありません。 例えば、```
1
4 1
2 100 3 4
1 4
```答えがあります`yes`、 なぜなら`2, 3, 4`位置 1、3、4 にある場合でも、三角形を形成します。連続する配列位置のみをチェックすると、間違った結果が得られます。 

最後に、値の順序は無関係です。 で```
1
4 1
4 1 3 2
1 4
```答えは`yes`、ソート後に取得するため、`1, 2, 3, 4`そして`1 + 2 > 3`。 元の順序でトリプルのみをチェックするメソッドでは、有効な選択肢が失われます。 

## アプローチ

 直接的なブルート フォース ソリューションは定義に従います。 クエリごとに、次のすべての値を取得します。`[l, r]`、それらを並べ替えて、連続する 3 つの値ごとにチェックします。 任意の 3 つの値が三角形を形成する場合、セット全体をソートした後、三角形を形成する連続したトリプルも存在するため、ソートは十分です。 並べ替えられた値が次の場合`b1 <= b2 <= ...`、最大の辺が可能な限り小さいインデックスを持つ三角形を選択します。 直前の 2 つの値は、より大きな値に置き換えることができないため、それらの合計は、元の 2 つの小さい辺の合計と少なくとも同じ大きさになります。 

このアプローチの問題は、間隔のサイズです。 最悪の場合、クエリに長さがある場合`10^5`したがって、1 つのクエリですでに`O(10^5 log 10^5)`仕事。 と`2 * 10^5`クエリ、これはおおよその範囲に到達します`2 * 10^5 * 10^5`ソートを考慮する前の要素レベルの作業ですが、これは大きすぎます。 

有用な観察は、上記のフィボナッチ成長特性です。 ブルート フォース手法は、クエリされた間隔内の値のみが必要なため機能します。 間隔が大きくなる可能性があるため、失敗します。 三角形のないすべての区間の長さが 40 未満であるという観察により、まさにその問題が解消されます。 

すべてのクエリについて、`r - l + 1 >= 40`、すぐに答えます`yes`。 それ以外の場合、間隔には最大 39 個の要素が含まれるため、それをコピーし、それらの値を並べ替えて、連続するトリプルを検査します。 最大値は次の値に制限されるため、数値 39 は真の定数です。`10^8`。 

これは、複雑なセグメント ツリーやバランスの取れた検索ツリーが必要ない理由でもあります。 データ構造は、フィボナッチ境界によってすでに解消されている問題を解決することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(m n log n)`最悪の場合 |`O(n)`| 遅すぎる |
 | 最適 |`O(n + m * 39 log 39)`|`O(39)`クエリごとの追加 | 承認済み |

 39 は定数であるため、最適な複雑さは実質的に次のようになります。`O(n + m)`。 

## アルゴリズムのチュートリアル

 1. 配列とすべてのクエリを読み取ります。 三角形のない最大長を利用すると、すべてのクエリを独立して処理できるため、配列自体は変更されません。 
2. お問い合わせの場合`[l, r]`、その長さを次のように計算します。`r - l + 1`。 この長さが 40 以上の場合は、次のように出力します。`yes`すぐに。 40 個の正の整数の三角形のない間隔には、少なくとも次のシーケンスが必要です。`1, 1, 2, 3, 5, ...`、その 40 番目の値はすでに超えています`10^8`, したがって、そのような間隔は存在しません。 
3. 長さが 40 未満の場合は、間隔から最大 39 個の値を抽出して並べ替えます。 並べ替えは、3 つの要素の任意の選択を、連続する値のローカル チェックに変換します。 
4. 並べ替えられた値をスキャンします。 連続する 3 つの値ごとに`x, y, z`かどうかをテストします。`x + y > z`。 これがどのトリプルにも当てはまる場合は、次のように出力します。`yes`。 
5. 連続するトリプルがすべて満たす場合`x + y <= z`、印刷`no`。 並べ替えられたシーケンスには、三角形が存在する可能性がありません。これは、どの三角形でも有効な連続トリプルが生成されるためです。 

### なぜ効果があるのか

 重要な不変条件は、ソートされたコレクションの場合です。`b1 <= b2 <= ... <= bk`、連続するトリプルが条件を満たす場合にのみ、コレクションには三角形が含まれます。`b[i] + b[i+1] > b[i+2]`。 三角形が存在する場合は、その最大の辺を取ります`z`。 以下の最大 2 つの値`z`少なくとも三角形の小さい 2 辺と同じ大きさの合計があるため、対応する連続したトリプルも三角形を形成します。 逆に、不等式を満たす連続したトリプルはすべて、そのまま有効な三角形です。 

少なくとも 40 個の要素を含む区間の場合、フィボナッチ引数は三角形が存在する必要があることを証明します。 間隔が短い場合、明示的な並べ替えチェックは正確です。 これら 2 つのケースは考えられるすべてのクエリをカバーしているため、すべての答えが正解です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 40

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        for _ in range(m):
            l, r = map(int, input().split())

            length = r - l + 1

            if length >= LIMIT:
                out.append("yes")
                continue

            b = sorted(a[l - 1:r])

            ok = False
            for i in range(length - 2):
                if b[i] + b[i + 1] > b[i + 2]:
                    ok = True
                    break

            out.append("yes" if ok else "no")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力では 1 から始まる位置が使用されますが、Python スライスは 0 から始まり、正しいエンドポイントは除外されます。 したがって`[l, r]`になる`a[l - 1:r]`、これには必要な要素が正確に含まれています。 

長さのチェックは、スライスを構築して並べ替える前に行われます。 これが重要なのは、長い間隔はすでに白であることがわかっているため、その値の処理に時間を費やす理由がないからです。 

短い間隔で、`sorted`最大 39 個の整数を含む新しいリストを作成します。 次にループは、ソートされたリストから連続するトリプルを正確にチェックします。 厳密な比較`>`次のような縮退したケースを処理します`1, 2, 3`正しく。 

Python の整数には任意の精度があるため、`b[i] + b[i + 1]`オーバーフローすることはできません。 固定幅の整数を使用する言語では、指定された`10^8`bound はすでに合計に十分な 32 ビット符号付き整数を作成していますが、より広い型を使用しても問題はありません。 

定数 40 は、三角形を含むことが保証される最初の長さとして意図的に選択されています。 以来`F40 = 102334155 > 10^8`、三角形のないシーケンスには最大 39 個の要素を含めることができます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n + m * 39 log 39)`| 長いクエリはすべて即座に回答されます。 短いクエリごとに最大 39 個の値が並べ替えられます。 
| スペース |`O(39)`番外編 | 短いクエリにより、最大 39 個の値の一時リストが作成されます。 

39 は次の式で決まる固定定数であるため、`10^8`値が制限されているため、クエリ作業は事実上一定です。 アルゴリズムは入力全体にわたって次の処理を実行します。`O(sum n + sum m)`小さな定数係数を使用した漸近作業。これは、`sum n <= 5 * 10^5`そして`sum m <= 10^6`。

 ## 特殊なケース

 ### 要素が 3 つ未満

 入力用```

 のために```

3 1
1 2 3
1 3
```並べ替えられた値は`[1, 2, 3]`。 唯一のチェックは、`1 + 2 > 3`、合計が最大の辺に等しいため、これは false です。 アルゴリズムは出力します`no`、等式を有効な三角形ではなく退化した三角形として正しく処理します。

### ちょうど 40 個の要素
