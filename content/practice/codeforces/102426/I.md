 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます`a`そして`b`2 つの未知の素数から生成される`p`そして`q`:

 [
 a=(pq)\oplus(p+q)、
 ]

 [
 b=(pq)\oplus(p-q)。 
]

 タスクは、元の順序ペアを回復することです。`(p, q)`。 2 番目の式には次のものが含まれるため、順序は重要です。`p-q`したがって、2 つの素数を交換すると、一般的に変化します。`b`。 

課題は、`pq`それ自体は与えられていません。 通常の整数因数分解方法は、因数分解する既知の積が存在しないため、直接適用できません。 得られる情報は、積、和、差を含む 2 つの XOR 式だけです。 

入力には最大 3000 の独立したテスト ケースが含まれます。 それぞれ`a`そして`b`符号付き 64 ビット整数に収まります。 これにより、最大で列挙値に依存するアルゴリズムが作成されます。`2^63`まったく不可能です。 考えられるすべての素数値を線形スキャンするだけでもすでに数十億回または数兆回の操作が必要になりますが、すべてのペアを試すと天文学的に悪くなるでしょう。 

直接実装で正しく処理する必要があるエッジケースがいくつかあります。 初め、`p`より小さくてもよい`q`、 それで`p-q`はマイナスです。 たとえば、`p=2,q=3`、

 [
 pq=6、\quad p+q=5、\quad p-q=-1、
 ]

 それで

 [
 a=6\oplus5=3、
 ]

 そして、通常の 2 の補数の解釈では、

 [
 b=6\oplus(-1)=-7。 
]

 したがって、入力```
3 -7
```出力があります```
2 3
```を想定した解決策`p-q`が非負である場合、ここでは失敗します。 

2 番目のエッジケースは、`p=q`。 2 つの素数が等しくなる唯一の方法は、両方が同じ素数になることです。 のために`p=q=2`、

 [
 a=4\oplus4=0,\qquad b=4\oplus0=4,
 ]

 それで```
0 4
```生産しなければならない```
2 2
```2 つの素数が別個であると仮定する不用意な実装は、この有効なケースを拒否する可能性があります。 

ここに再現されているように、ステートメントには微妙な入力形式の問題もあります。 正式な入力の説明には次のものが含まれます。`T`、表示されたサンプルにはペアのみが含まれています`1279 1201`。 以下の実装は両方の形式を受け入れるため、正式な審査員形式と表示されたサンプル形式で動作します。 

## アプローチ

 最も直接的なアプローチは推測することです`p`そして`q`、計算します

 [
 (pq)\oplus(p+q)
 ]

 そして

 [
 (pq)\oplus(p-q)、
 ]

 そしてそれらを比較してください`a`そして`b`。 関連する値は 64 ビット整数である可能性があるため、膨大な検索スペースが必要になります。 両方の素数が 64 ビット値の範囲にあることを許可すると、すべてのペアのチェックには (2^{128}) 個の候補が含まれます。 製品自体が不明であるため、検索を可能な製品の平方根付近の値に制限することさえ不可能です。 

有益な観察は、XOR、加算、減算、乗算はすべて、2 の累乗を法とする数値の取得と互換性があるということです。 最低の`k`のビット`p*q`最低のものだけに依存する`k`のビット`p`そして`q`。 同じことが当てはまります`p+q`そして`p-q`。 結果として、最低の`k`両方の出力のビットは最下位のみに依存します`k`2 つの未知の素数のビット。 

これにより、まったく異なる検索方法が提供されます。 64 ビットの素数全体を一度に推測するのではなく、最下位ビットから上に向かって再構築します。 

すでに知っていると仮定してください`k`可能なペアの下位ビット`(p,q)`。 次のビットについては、可能性は 4 つだけです。 

[
 (p_k,q_k)\in{0,1}\times{0,1}。 
]

 これら 4 つの可能性をそれぞれ追加し、(2^{k+1}) を法とする 2 つの式を計算します。 いずれかの式が対応する下位ビットと一致しない場合、`a`または`b`、通常の加算、減算、乗算、または XOR の下位ビットを上位ビットが変更できないため、その候補は決して真の解にはなりません。 

したがって、ブルート フォース検索は、巨大な整数のペアを推測することから、有効な低ビット プレフィックスの非常に小さなセットを維持することに変わります。 各レベルでは 4 倍の数のプレフィックスが作成されますが、2 つの出力制約によりそれらの約 4 分の 3 が削除されます。 これは、密接に関連する 2018 年の USTC RSA 問題の公式解決策で使用されているのと同じ、ビットごとの再構成のアイデアです。 

64 ビット インスタンスの場合、必要なのは 64 レベルのみです。 各レベルで、生き残った候補者ごとに一定量の演算を実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^{128})) | (O(1)) | 遅すぎる |
 | 最適 | (O(64C))、予想される (O(64)) | (O(C)) | 承認済み |

 ここ`C`は、生き残るビットプレフィックスの最大数です。 2 つの独立した XOR 方程式は次のようになります。`C`実際には非常に小さく、ビット数において効果的に線形の仕事を与えます。 

## アルゴリズムのチュートリアル

 1. 可能な唯一のゼロビットプレフィックスから始めます。`(p,q)=(0,0)`。 どちらの素数もまだ選択されていません。 
2. 最下位ビットから最上位ビットまで処理します。 ビット位置で`k`、残っているすべてのペアはすでにモジュロ (2^k) で検証されています。 
3. 生き残ったペアごとに、次の部分について 4 つの選択肢すべてを試します。`p`そして`q`。 現在のプレフィックスが`(x,y)`、4つの拡張子は次のとおりです。 

[
 (x,y),\quad
 (x+2^k,y),\quad
 (x,y+2^k),\quad
 (x+2^k,y+2^k)。 
]

 1. 拡張子ごとに、次のように計算します。 

[
 f_1(x,y)=(xy)\oplus(x+y)
 ]

 そして

 [
 f_2(x,y)=(xy)\oplus(x-y)。 
]

 最低のものだけ`k+1`この段階ではビットが重要です。 マスクを使用する

 [
 2^{k+1}-1
 ]

 すべての上位ビットを破棄します。 

1. 次の場合にのみ拡張子を保持します。 

[
 f_1(x,y)\bmod 2^{k+1}=a\bmod 2^{k+1}
 ]

 そして

 [
 f_2(x,y)\bmod 2^{k+1}=b\bmod 2^{k+1}。 
]

 整数に対する演算では、すでに決定されている下位ビットを上位ビットで変更することができないため、この枝刈りは有効です。 

1. 十分なビットが再構築された後、マスクされたバージョンのみではなく完全な式を使用して、残っている各候補をチェックします。 いつ

 [
 f_1(p,q)=a
 ]

 そして

 [
 f_2(p,q)=b、
 ]

 必要な順序ペアを回復しました。 

1. 64 個の再構成ビットを使用します。 指定された出力は符号付き 64 ビット値であり、対応する素因数は問題で必要な範囲内にあります。 Python の任意精度の整数を使用すると、オーバーフローせずに最終積を評価することもできます。 

なぜ効果があるのか

 不変条件は、ビットを処理した後の値です。`k`、生き残ったすべての候補者`(x,y)`全く同じ最低値を持っています`k`考えられる解決策としてビット`(p,q)`、そして、破棄されたすべての候補が同じ出力ビットを持つ可能性はありません。 理由は、低いからです`k`乗算、加算、減算、XOR のビットは下位ビットのみに依存します。`k`オペランドの一部。 したがって、候補者はレベルで拒否されました`k`異なる上位ビットを選択しても修復できません。 逆に言えば、本当の`(p,q)`そのプレフィックスは、対応するプレフィックスを正確に生成するため、すべてのレベルに合格します。`a`そして`b`。 関連するすべてのビットが処理された後、実際のペアが残り、最終的な正確なチェックにより、完全なソリューションを表さない残りのプレフィックスが削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a, b):
    def f1(x, y):
        return (x * y) ^ (x + y)

    def f2(x, y):
        return (x * y) ^ (x - y)

    candidates = {(0, 0)}

    for bit in range(64):
        mask = (1 << (bit + 1)) - 1
        target_a = a & mask
        target_b = b & mask

        next_candidates = set()

        for x, y in candidates:
            add = 1 << bit

            for bx in (0, 1):
                xx = x + bx * add

                for by in (0, 1):
                    yy = y + by * add

                    if (f1(xx, yy) & mask) != target_a:
                        continue

                    if (f2(xx, yy) & mask) != target_b:
                        continue

                    next_candidates.add((xx, yy))

        candidates = next_candidates

        # A complete solution may be smaller than 2^(bit+1).
        for x, y in candidates:
            if f1(x, y) == a and f2(x, y) == b:
                return x, y

        if not candidates:
            break

    # The problem guarantees a unique solution.
    for x, y in candidates:
        if f1(x, y) == a and f2(x, y) == b:
            return x, y

    raise ValueError("No solution found")

def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    # The formal statement has T, while the displayed sample omits it.
    if len(data) >= 3 and len(data) == 1 + 2 * data[0]:
        t = data[0]
        values = data[1:]
    else:
        t = len(data) // 2
        values = data

    out = []

    for i in range(t):
        a = values[2 * i]
        b = values[2 * i + 1]
        p, q = solve_case(a, b)
        out.append(f"{p} {q}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```2 つのヘルパー関数は、問題からの 2 つの式を直接エンコードします。 それらを分離しておくと、ビットプレフィックス条件が読みやすくなり、2 番目の式で誤って間違った符号を使用することを回避できます。`mask = (1 << (bit + 1)) - 1`これまでに再構築されたビットを正確に保持します。 との比較`a & mask`そして`b & mask`中心的な剪定作業です。 

ネストされたループオーバー`bx`そして`by`次のビットに対して可能な 4 つの割り当てをすべて生成します。 よくある間違いは、既存の候補を適切に変更することです。 代わりに、4 つの可能性のそれぞれを独立した候補として扱う必要があります。 

このコードでは、固定幅の整数演算を意図的に使用していません。 Python の整数は積を表すことができます`x*y`符号付き 64 ビット整数よりはるかに大きい場合でも、正確に。 積はどちらの入力よりも多くのビットを占有する可能性があるため、これは最終検証時に重要になります。 

負の値`b`も介護が必要です。 負の整数に対する Python のビット単位の演算では、無限の 2 の補数表現が使用され、固定幅の符号付き整数と同じ下位ビットが得られます。 すべての中間比較がマスクされるため、`mask`、関連する下位ビットは、問題で必要とされるものとまったく同じです。 

正確な比較は、メイン ループの後だけでなく、すべてのレベルの後でも実行されます。 真の素数が小さい場合、その上位ビットは単にゼロであるため、64 レベルすべてが処理される前に完全な式がすでに一致している可能性があります。

 ## 特殊なケース

 負の差の場合は、特別な分岐を行わずに処理されます。 のために```
3 -7
```正しいペアは`(2,3)`。 低ビットレベルでは、`-7`は 2 の補数表現と同じ下位ビットを持ち、次のマスクを使用します。`1`、`3`、`7`など、一致する必要があるビットを正確に抽出します。 再構築後`2`そして`3`、Pythonは評価します`6 ^ -1`として`-7`, したがって、最終的な正確なチェックは成功します。 

素数が等しい場合は、```
0 4
```答え付き`(2,2)`。 アルゴリズムは次のことを想定していません`p-q`ゼロ以外です。 2 番目の式は単純に次のようになります。`4 ^ 0`、つまり`4`。 2 ビット再構成は次の範囲に達します。`(2,2)`、正確なチェックはそれを受け入れます。 

逆の順序の場合は、```
3 7
```答え付き`(3,2)`。 素数を入れ替えても積と和は変わりませんが、差は`1`に`-1`。 したがって、2 番目の方程式は 2 つの方向を区別します。 アルゴリズムは常に次のビットを処理するため、順序付きペアを再構築します。`p`そして`q`別に。 

大きな境界の場合は、```
2147483647 2147483651
```答え付き`(2147483647,2)`。 ここ

 [
 pq=4294967294、
 ]

 [
 p+q=2147483649、
 ]

 [
 p-q=2147483645。 
]

 最初の XOR は次のとおりです。 

[
 4294967294\oplus2147483649=2147483647、
 ]

 [
 4294967294\oplus2147483645=2147483651。 
]

中心的な教訓は、この問題は一見すると整数の因数分解にしか見えないということです。 実際の構造は、バイナリ プレフィックスに対する制約システムです。 2 つの XOR 方程式を 2 のべき乗を法として表示すると、汎用の因数分解アルゴリズムを回避して、未知の素数を一度に 1 ビットずつ再構成できます。
