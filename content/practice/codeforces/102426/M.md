 ## 解決策
 ## 問題の理解

 (N) 個の同一の円形照明領域があります。 それらの中心は 1 つの直線の通り上にあり、連続する中心は正確に (L) 単位離れており、すべての円は半径 (R) を持ちます。 タスクは、少なくとも 1 つのライトでカバーされるエリアを計算することです。 

円は 1 次元の鎖状に配置されており、これが重要な構造特性です。 照射領域は 2 次元ですが、その中心の自由度は 1 つだけであるため、オーバーラップ パターンは任意の円の場合よりもはるかに単純になります。 

テスト ケースは (10^5) 個まで存在できますが、(N)、(R)、および (L) はそれぞれ (10^9) 個まで大きくできます。 テスト ケースごとに (N) 個のランプを反復するアルゴリズムでは、制限時間を大幅に超える最悪の場合、(10^{14}) 回の操作が必要になる可能性があります。 テスト ケースごとに一定量の演算が必要です。 (R) と (L) の値が大きいということは、Python の整数自体はオーバーフローしませんが、中間の幾何学的表現を浮動小数点演算で慎重に評価する必要があることも意味します。 

いくつかの境界ケースは誤って処理されやすいものです。 たとえばランプがない場合 (N=0、R=10、L=3)、他のパラメータに関係なく、照射領域は正確に (0) になります。 (N\pi R^2) で始まる数式はこれを自然に処理しますが、少なくとも 1 つの円を想定したコードは失敗する可能性があります。 

(N=1)、たとえば (N=1,R=2,L=100) の場合、円は 1 つだけなので、答えは (4\pi) になります。 連続するペアがないため、連続するランプ間の距離は関係ありません。 

(L\ge 2R) の場合、隣接する円は重なりません。 たとえば、(N=2,R=1,L=2) の面積は (2\pi) になります。 境界を慎重に処理せずにオーバーラップ公式を使用すると、浮動小数点演算により小さな負の平方根引数が発生したり、ゼロ領域の交差が誤ってカウントされたりする可能性があります。 

反対の極端な場合、(L=0) は、すべてのランプがまったく同じ位置にあることを意味します。 たとえば、(N=5,R=3,L=0) の面積は (45\pi) ではなく (9\pi) です。 正しいオーバーラップ公式では、一致する 2 つの円の交点が円全体であることを認識する必要があります。 

最後に、(R=0) は、すべての照射領域を面積ゼロの点にします。 たとえば、(N=10,R=0,L=7) の答えは (0) になります。 このケースは、(L/(2R)) などの式を評価する前に処理する必要があります。そうしないとゼロによる除算が発生するためです。 

## アプローチ

 直接的なアプローチでは、ランプを左から右に処理し、新しい円のどの部分が既に照明されているかを明示的に維持します。 幾何学的には、これは、以前に配置された円との交差を計算することによって実行できます。 この方法は正しいです。結合領域は、新しい円のそれぞれの前にカバーされていなかった部分を追加することによって取得できるためです。 

問題は、(N) 個の円が存在する可能性があり、単純な実装では、それぞれの新しい円を以前のすべての円と比較してしまう可能性があることです。 1 つのテスト ケースでは、(\Theta(N^2)) ペア チェックが必要になります。これは、(N=10^9) の場合、(10^{18}) 個の演算になりますが、そのような反復を実用化するのではなく、入力自体がテスト ケースの数を制限します。 (10^5) 個のケースに大きな (N) が含まれる場合、ケースごとに (O(N)) 個のアルゴリズムでもコストがかかりすぎます。 

有益な観察は、円を以前のすべての円と実際に比較する必要がないということです。 位置 (0、L、2L) にある 3 つの連続する中心を考えてみましょう。 最初の円と 3 番目の円の両方に属する点を取得します。 中央の中心は外側の 2 つの中心の間にあるすべての点に近いため、その点も中央の円に属します。 より一般的には、円を左から右に追加すると、以前の円ですでに覆われていた新しい円のすべての点も、直前の円で覆われます。

したがって、新しい円は、直前の円とまったく同じ領域で前の結合全体と重なり合います。 これは、複数の円が同時に重なっている場合でも当てはまります。 三重以上のオーバーラップは、新しい円が追加されるたびにすでに考慮されているため、個別の包含/除外項は必要ありません。 

したがって、結合領域は非常に単純な形式になります。 (N) 個の個々の円領域 (N\pi R^2) から開始し、同じ隣接ペアのオーバーラップを (N-1) 回減算します。 (L\ge 2R) の場合、重複はなく、何も減算する必要はありません。 

半径 (R) の 2 つの等しい円の中心が (L) 離れている場合、(0\le L<2R) のそれらの交差面積は次のようになります。 

## 2R^2\arccos\left(\frac{L}{2R}\right)

 \frac{L}{2}\sqrt{4R^2-L^2}。 
]

 したがって、(N>0) の場合、

 [
 S=
 N\pi R^2-(N-1)S_{\text{オーバーラップ}}、
 ]

 (L\ge 2R) の場合、(S_{\text{overlap}}=0) となります。 

重要なのは、単に標準的な円と交点の公式を認識することではありません。 本当の単純化は、すべての新しい円が、その直前の円と共有するのと同じ領域でのみ前の結合全体と交差することを証明することです。

 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとの (O(N^2)) | (O(N)) | 遅すぎる |
 | 最適 | テスト ケースごとの (O(1)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (N)、(R)、(L) を読み取ります。 (N=0) または (R=0) の場合、正領域の照射領域がないため、(0) を出力します。 
2. 1 つの円の面積を (\pi R^2) として計算し、合計を (N\pi R^2) として初期化します。 これは、重なりを削除する前の領域を表します。 
3. (L<2R) かどうかを確認します。 そうでない場合、連続する円は互いに素であるか接しているため、重なり合う領域はゼロとなり、最初の合計がすでに答えになります。 
4. (L<2R) の場合、隣接する 2 つの円の交差面積を計算します。 

\frac{L}{2}\sqrt{4R^2-L^2}。 
]

 最初の項は 2 つの円セクターで構成されますが、平方根項では弦と中心の間の 2 つの三角形の部分が削除されます。 

1. この重複を正確に (N-1) 回減算します。 (N-1) 個の隣接するペアがあり、新しい円を追加すると、その全面積から前の円との重なりを正確に差し引いた分だけ結合が増加します。 
2. 結果の浮動小数点値を十分な桁数で出力します。たとえば、次のようにします。`:.10f`。 小数点以下 10 桁の場合、必要な精度 (10^{-6}) よりもかなり高い精度が得られます。 

これが機能する理由: (i) 番目の円が追加されるとき、その中の点が前の円にも属していると仮定します。 直前の円の中心は、新しい円の中心と前の中心の間にあります。 両方の端点の円の内側にある点については、中央の中心までの距離が、遠い方の端点の中心までの距離よりも大きくなりません。 したがって、この点は前の円にも属します。 したがって、新しい円と既存の結合全体との交点は、まさに前の円との交点になります。 同じ重複領域が (N-1) 個の加算ごとに 1 回減算されるため、複数の円で覆われたすべての点は、最終的な結合で 1 回だけカウントされます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, r, l = map(int, input().split())

        if n == 0 or r == 0:
            out.append("0.0000000000")
            continue

        circle_area = math.pi * r * r
        area = n * circle_area

        if l < 2 * r:
            x = l / (2.0 * r)

            # Protect acos from a possible tiny floating-point drift.
            x = max(-1.0, min(1.0, x))

            overlap = (
                2.0 * r * r * math.acos(x)
                - 0.5 * l * math.sqrt(4.0 * r * r - l * l)
            )

            area -= (n - 1) * overlap

        out.append(f"{area:.10f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のブランチは、除算または平方根の前に、面積がゼロの 2 つのケースを処理します。 オーバーラップ式に (L/(2R)) が含まれるため、これが必要になります。 

初期の`area`すべて (N) 個の円の面積の合計です。 (L\ge2R) の場合、円は互いに素であるか接しているため、重なりはゼロであり、値はすでに正しいです。 

重なり合う円の場合、`x`は (L/(2R))、共通の弦によって定められる角度の半分の余弦です。 の`max`そして`min`クランプが保護する`math.acos`次のような浮動小数点値から`1.0000000000000002`ただし、数学的値は正確に有効な間隔内にあります。 

下の式`sqrt`常に負ではありません (L<2R)。 比較は元の整数を使用して行われるため、境界 (L=2R) に曖昧さはありません。 

Python の整数は、オーバーフローすることなく、最大 (10^9) の値を含む積を表すことができます。 最終的な幾何学的計算では、`float`、その精度は必要な (10^{-6}) 許容差を十分に満たしています。 小数点以下 10 桁を印刷すると、書式設定エラーに対する安全性がさらに高まります。

    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:

    assert len(actual) == len(expected)

    for a, e in zip(actual, expected):
        assert abs(a - e) <= eps * max(1.0, abs(e)), (a, e)

## 特殊なケース

 (N=0) の場合、次のように考えます。```
1
0 1000000000 1000000000
```アルゴリズムはすぐに最初の条件に入り、戻ります。`0.0000000000`。 円が存在しないため、照らされる領域はありません。 (N\ge1) を前提とした不注意な実装では、ランプの数をチェックせずに半径を使用すると、依然としてゼロ以外の式が返される可能性があります。 

(N=1) の場合、次のように考えます。```
1
1 2 100
```このアルゴリズムは 1 つの円の領域 (4\pi) を計算しますが、(N-1=0) であるため、オーバーラップの式は必要ありません。 この場合、間隔の値は実際のランプのペアを表しません。 出力はおよそ`12.5663706144`。 

一致する円については、次のことを考慮してください。```
1
5 3 0
```オーバーラップ式は次のようになります。 

[
 2\cdot9\arccos(0)-0=9\pi。 
]

 最初の合計は (5\cdot9\pi) で、(9\pi) の 4 つの重複が削除されます。 

[
 45\pi-4(9\pi)=9\pi。 
]

 したがって、アルゴリズムは 5 つのランプすべてを 1 つの照明されたディスクとして正しく処理します。 このケースでは、この方法が一般的な交差式を超える特別な式を必要とせずに、可能な最大のオーバーラップの極端な値を処理できることも確認されています。 

接円については、次のことを考慮してください。```
1
2 3 6
```(L=2R) なので、重複分岐はスキップされます。 答えは

 [
 2\pi\cdot3^2=18\pi。 
]

 円は境界点を 1 つだけ共有し、その面積はゼロです。 厳密な使用法`<`比較により、ゼロでの平方根を不必要に評価することが回避され、境界の幾何学的意味が明確になります。 

分離された円については、次の点を考慮してください。```
1
4 2 5
```ここでは (2R=4<L=5)、したがって、すべての円は次の円から独立しており、その結果、他のすべての円から独立しています。 答えは単純です

 [
 4\cdot\pi\cdot2^2=16\pi。 
]

 アルゴリズムは決して呼び出しません`acos`または`sqrt`このブランチでは、その幾何学的領域の外で交差式を評価するリスクはありません。 

多くの重なり合う円については、(N=10,R=10,L=1) を考慮してください。 新しく追加されたすべての円は前の結合と重なっていますが、削除する必要がある量は依然として正確に 2 つの円の重なりです。 このアルゴリズムは、3 倍、4 倍、またはより高次の交差を列挙しようとするのではなく、その減算を 9 回実行します。 これはソリューションの中心的な不変条件であり、ジオメトリ問題全体をテスト ケースごとに (O(1)) 回の作業量に減らすものです。
