 ## 解決策
 ## 問題の理解

 幅 (W) と高さ (H) のスクリーンと、最大 10 個の長方形のウィンドウがあります。 この座標系は少し特殊です。最初の座標は下方向に増加し、2 番目の座標は右方向に増加します。 ウィンドウは画面の外に広がることもありますが、実際にレンダリングできるのは画面との交差部分のみです。 

ウィンドウは Z インデックスによって並べられます。 z インデックスが小さいほど、ウィンドウが前にあることを意味します。 最初はウィンドウ (0) が最前面にあり、次にウィンドウ (1) が続きます。 常に 1 つのウィンドウがアクティブになります。 マウスのクリックは、現在レンダリングされている画面を使用して解釈されます。クリックされた画面ポイントを含むすべてのウィンドウのうち、最前面のウィンドウがクリックを受け取ります。 ウィンドウにそのポイントが含まれていない場合は、何も変わりません。 

クリックしたウィンドウがアクティブウィンドウと異なる場合は、アクティブとなり最前面に移動します。 他のウィンドウは相対的な順序を維持します。 ウィンドウを前方に移動すると、その前のウィンドウで覆われていたウィンドウの部分が表示されることがあります。 必要な出力は、まさに新たに表示されるようになり、結果的に再描画する必要がある領域です。 

入力により、画面の寸法、初期の Z オーダーでのすべてのウィンドウの四角形、およびマウス クリックのシーケンスが得られます。 クリックごとに、そのクリックの処理後に再描画する必要がある最小領域を出力します。 

ウィンドウ数とクリック数という制約が異常に少ないです。 (n,q\le 10) ですが、画面は (2000\times2000) まで大きくすることができます。 これにより、アルゴリズムが (n) で指数関数的に実用的になりますが、画面のすべてのピクセルに依存するアルゴリズムは不必要に高価になります。 ピクセル シミュレーションでは、最悪の場合、(10\cdot2000\cdot2000\cdot10=400{,}000{,}000) 回のウィンドウ封じ込めチェックが実行される可能性があります。 ジオメトリは連続的であるため、すべての単位正方形を個別に扱うことは、概念的にも必要以上に複雑になります。 

最初の微妙な点は、クリックを元の入力の最初のウィンドウではなく、レンダリングされた最上位のウィンドウに割り当てる必要があることです。 例えば：```
1 1
2

0 0 1 1
1
0 0
```答えは次のとおりです。```
0
```2 番目のウィンドウにもポイントが含まれていますが、最初のウィンドウはすでにアクティブでクリックをカバーしています。 アクティブ化するたびに入力順序でウィンドウを検索する不注意な実装では、最終的に現在の Z オーダーが失われます。 

2 番目の微妙な点は、ウィンドウが画面を超えて拡張できることです。 考慮する：```

```クリッピングを無視する実装では、再描画領域を計算するときにオフスクリーンの四角形全体が誤って使用される可能性があります。

## アプローチ

 直接的なアプローチは、画面を (W\times H) 単位セルとして表すことです。 すべての座標は整数であるため、すべての長方形の境界はグリッド線上にあり、したがってその面積は実際に多数の単位セルで表すことができます。 クリックするたびにすべてのセルを検査し、どのウィンドウが一番上にあるのかを判断し、古いレンダリングと新しいレンダリングを比較することができます。 これは正しいですが、最悪のケースでは、(2000\cdot2000) 個のセルがあり、セルごとに最大 (10) のクリックと最大 (10) のウィンドウが検査されます。 これにより、(4 億) 回のウィンドウ チェックが行われます。 1 秒の制限では、これは不適切な粒度レベルです。 

ブルート フォースは画面を明示的に表すため機能しますが、画面自体には問題が必要とするよりもはるかに多くの情報が含まれています。 再描画領域は常に長方形の交差と結合によって形成され、長方形は 10 個しかありません。 

ウィンドウ (t) が前面に移動されているとします。 操作前は、z オーダーで (t) より前のすべてのウィンドウが (t) の一部をカバーしています。 操作後、(t) はそれらのウィンドウをすべて覆います。 したがって、新たに表示される唯一の領域は、

 [
 R_t\cap(R_1\cup R_2\cup\cdots\cup R_k),
 ]

 ここで、(R_i) は正確に現在 (t) の前にあるウィンドウであり、すべての四角形は画面によってクリップされていると理解されます。 

これにより、問題は 1 つのターゲット四角形内にある最大 9 個の四角形の結合領域を見つけることになります。 長方形の数が非常に少ないため、包含/除外が特に便利です。 カバーする長方形の空でないサブセットごとに、そのサブセット内のすべての長方形の交差を計算します。 サブセットに奇数の四角形が含まれる場合はその面積を加算し、サブセットに偶数が含まれる場合はその面積を減算します。 

1 回のアクティベーションに対して、最大 (2^9-1=511) 個の空でないサブセットが存在します。 マウス ターゲットは、現在の Z オーダーをスキャンすることで見つけることができます。コストは (O(n)) のみです。 再描画領域を計算した後、選択したウィンドウを前面に移動するのは単なるリスト操作です。 

この総当りアプローチは、目に見えるすべての領域単位を明示的にモデル化するため機能しますが、画面が幾何学的オブジェクトの数よりはるかに大きいため失敗します。 最大 9 つの長方形の結合のみが重要であるという観察により、数百万のセル演算を数百の長方形の交差に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(qWHn)) | (O(WH)) | 遅すぎる |
 | 最適 | (O(qn^2 2^n)) | (O(n)) | 承認済み |

 最適境界内の (n) 係数は、そのサブセットに属する長方形をスキャンすることによって各サブセットの交差を計算することで得られます。 (n\le10) なので、これは十分に小さいです。 

## アルゴリズムのチュートリアル

 1. すべてのウィンドウを、その垂直間隔と水平間隔を表す 4 つの座標として保存します。 最初の座標は垂直なので、ウィンドウ`(x, y, w, h)`垂直方向に (x\ldots x+h)、水平方向に (y\ldots y+w) を占めます。 初期の Z オーダーをそのままにしておきます。`[0, 1, ..., n-1]`, ここで、最初の要素は最前面のウィンドウです。 
2. クリックするたびに、現在の Z オーダーを前から後ろにスキャンします。 各ウィンドウについて、まずその四角形を画面と交差させてから、マウスの位置がその切り取られた四角形の内側にあるかどうかをテストします。 このステートメントではウィンドウ境界をレンダリング領域の一部として明示的に扱うため、ポイント テストには包括的な比較を使用してください。 
3. マウス位置を含むウィンドウがない場合は、ゼロを出力し、Z オーダーを変更しないままにします。 アクティベーションがないため、レンダリングされた画面は変化しません。 
4. 選択したウィンドウがすでにアクティブなウィンドウである場合は、ゼロを出力し、Z オーダーを変更しないままにします。 すでにアクティブなウィンドウをクリックしても何も移動しません。 
5. それ以外の場合、選択されたウィンドウを (t) とします。 現在の Z オーダーでは、(t) より前のすべてのウィンドウがその前にあります。 それらのウィンドウを正確に収集します。 再描画する必要がある領域は、これらの前面ウィンドウの結合によってカバーされる (t) の領域です。 
6. 面積を計算する前に、ターゲット ウィンドウを画面に対してクリップします。 フロント ウィンドウの空ではないすべてのサブセットについて、ターゲットの四角形とそのサブセット内のすべての四角形を交差させます。 結果の交差の幅と高さが正の場合、その面積は奇数サイズのサブセットに対して加算され、偶数サイズのサブセットに対して減算されます。 これは、ユニオンの標準的な包含/除外式です。 
7. Z オーダーの現在の位置から (t) を削除し、先頭に挿入します。 これは、以前のすべての Z インデックスを 1 ずつ増やしながら、Z インデックスを 0 に変更することを正確にモデル化しています。 
8. 計算された再描画領域を出力し、次のクリックに進みます。 維持された順序は、次のマウス イベントを処理するために必要な完全な状態になります。 

### なぜ効果があるのか

 重要な不変条件は、z オーダー リストが常にウィンドウ システムが現在行っているのとまったく同じように前から後ろにウィンドウを格納することです。 したがって、クリックを含む最初のウィンドウは、レンダリングされたピクセルがそのクリックを受け取るウィンドウとまったく同じになります。 

別のウィンドウ (t) がアクティブになると、現在そのウィンドウの前にあるウィンドウとの関係のみが変化します。 このようなすべてのフロント ウィンドウは、以前は (t) との重なりの上に表示されていましたが、アクティブ化後は (t) が同じ重なりの上に表示されます。 画面の他の部分は変化しません。 したがって、再描画領域は、(t) とその前のすべてのウィンドウの間の交差部分の結合となります。 

包含-排他は、複数のカバー ウィンドウが重なっている場合でも、その結合を正確に計算します。 (t) を前に移動した後、z オーダーの不変量が復元されます。 したがって、すべてのクリックは正しい画面状態に基づいて処理され、報告されるすべての領域は、レンダリングが変更される正確な領域になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def intersect(a, b):
    x1 = max(a[0], b[0])
    y1 = max(a[1], b[1])
    x2 = min(a[2], b[2])
    y2 = min(a[3], b[3])
    if x1 >= x2 or y1 >= y2:
        return None
    return (x1, y1, x2, y2)

def area(r):
    if r is None:
        return 0
    return (r[2] - r[0]) * (r[3] - r[1])

def union_inside(target, rects):
    k = len(rects)
    if k == 0:
        return 0

    ans = 0

    for mask in range(1, 1 << k):
        cur = target
        bits = 0

        for i in range(k):
            if mask & (1 << i):
                bits += 1
                cur = intersect(cur, rects[i])
                if cur is None:
                    break

        if cur is not None:
            a = area(cur)
            if bits & 1:
                ans += a
            else:
                ans -= a

    return ans

def solve():
    W, H = map(int, input().split())
    n = int(input())

    windows = []

    for _ in range(n):
        x, y, w, h = map(int, input().split())

        # x is vertical, y is horizontal.
        # The screen is [0, H] x [0, W].
        windows.append((x, y, x + h, y + w))

    q = int(input())

    clicks = [tuple(map(int, input().split())) for _ in range(q)]

    # Frontmost to backmost.
    order = list(range(n))

    screen = (0, 0, H, W)

    out = []

    for u, v in clicks:
        target_pos = -1

        # Find the frontmost rendered window containing the click.
        for pos, idx in enumerate(order):
            clipped = intersect(windows[idx], screen)

            if clipped is not None:
                if clipped[0] <= u <= clipped[2] and clipped[1] <= v <= clipped[3]:
                    target_pos = pos
                    break

        if target_pos == -1:
            out.append("0")
            continue

        target = order[target_pos]

        # Clicking the active window causes no change.
        if target_pos == 0:
            out.append("0")
            continue

        # Windows before target are exactly the windows currently
        # covering it from the front.
        front_rects = [
            windows[idx]
            for idx in order[:target_pos]
        ]

        clipped_target = intersect(windows[target], screen)

        repaint = union_inside(clipped_target, front_rects)
        out.append(str(repaint))

        # Move target to the front.
        order.pop(target_pos)
        order.insert(0, target)

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`windows`配列は各四角形を次のように格納します`(top, left, bottom, right)`問題の座標方向で。 垂直範囲は次を使用します`h`、一方、水平範囲は使用します`w`。 ここは、幅と高さを誤って交換してしまいやすい場所です。 

の`intersect`関数は厳密を使用します`x1 < x2`そして`y1 < y2`交差点に正の面積があるかどうかを判断するとき。 境界にはマウス クリックが含まれる場合がありますが、境界には面積がゼロであるため、再描画の計算に影響を与えることはできません。 

画面の四角形は`(0, 0, H, W)`。 ウィンドウをこの四角形と交差させると、すべてのオフスクリーンのケースが自動的に処理されます。 元のウィンドウ座標を変更する必要はありません。 

クリック検索では、`<=`両端にあります。 これは、表示される境界がレンダリングされたウィンドウに属するというステートメントの規則に従います。 2 つのウィンドウが境界で交わる場合でも、どちらがそこでクリックを受けるかは現在の Z オーダーによって決まります。 

の`union_inside`関数は包含と除外を直接適用します。 奇数の四角形を持つサブセットはプラスに寄与しますが、偶数サイズのサブセットはマイナスに寄与します。 ターゲットの四角形はすべての交差に含まれるため、計算された和集合はアクティブ化されているウィンドウの領域に自動的に制限されます。 

Python の整数はすべての領域で十分です。 最大画面領域は (4{,}000{,}000) のみですが、包含/除外により、そのようないくつかの領域が一時的に追加および減算される場合があります。 

最後に、選択したウィンドウが古い位置から削除され、インデックス 0 に挿入されます。 これは、問題で説明されている z インデックス変換を直接表しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(qn^2 2^n)) | 各クリックで (O(n)) 個のウィンドウがスキャンされ、アクティブ化では最大 (2^n) 個のサブセットが評価され、サブセットごとに最大 (O(n)) 個の四角形の交差が評価されます。 |
 | スペース | (O(n)) | このアルゴリズムは、長方形、Z オーダー、および一定量の一時ジオメトリを保存します。 |

 (n,q\le10) の場合、最大の指数係数は (2^{10}=1024) のみです。 (n^2) という追加の係数を使用しても、原始演算の数は少なくなります。 アルゴリズムは個々のピクセルまたは単位セルを反復することがないため、画面の寸法は複雑さの中に現れません。

                    break

        if cur is not None:
            if bits & 1:
                ans += area(cur)
            else:
                ans -= area(cur)

    return ans

def solve():
    input = sys.stdin.readline

    W, H = map(int, input().split())
    n = int(input())

    windows = []
    for _ in range(n):
        x, y, w, h = map(int, input().split())
        windows.append((x, y, x + h, y + w))

    q = int(input())
    order = list(range(n))
    screen = (0, 0, H, W)

    ans = []

    for _ in range(q):
        u, v = map(int, input().split())

        pos = -1

        for i, idx in enumerate(order):
            r = intersect(windows[idx], screen)
            if r is not None and r[0] <= u <= r[2] and r[1] <= v <= r[3]:
                pos = i
                break

        if pos <= 0:
            ans.append("0")
            continue

        target = order[pos]
        target_rect = intersect(windows[target], screen)

        front = [windows[idx] for idx in order[:pos]]
        repaint = union_inside(target_rect, front)

        ans.append(str(repaint))

        order.pop(pos)
        order.insert(0, target)

    return "\n".join(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

 ## 特殊なケース

 最小サイズの入力には、(1\times1) 画面と 1 つの (1\times1) ウィンドウがあります。 唯一のウィンドウがアクティブになり、ウィンドウ内をクリックすると、すでにアクティブなウィンドウが選択されます。 アルゴリズムはそれを位置 0 で見つけます。`order`、すぐにゼロを出力し、順序を変更することはありません。 

クリッピングケースは窓を使用します`(-1,-1,3,3)`(4\times4) 画面上。 その可視領域は、との交差点のみです。`[0,4] × [0,4]`。 でのクリック`(2,2)`はその可視領域の内側にありますが、最初のウィンドウの外側にあるため、2 番目のウィンドウがアクティブになります。 最初のウィンドウとの交点は正確に (1\times1) の正方形です`[0,1] × [0,1]`、再ペイント領域(1)を与えます。 

オーバーラップウィンドウの場合は、その前に 2 つのウィンドウがあるときに 3 番目のウィンドウがアクティブになります。 ターゲットとの個々のオーバーラップには領域 (3) と (3) がありますが、共通のオーバーラップには領域 (1) があります。 包含/除外の計算は (3+3-1=5) であるため、アルゴリズムの出力は次のようになります。`5`間違った合計ではなく`6`。 

動的順序の場合、最初にウィンドウがアクティブになります。`2`から順序を変更します`[0,1,2]`に`[2,0,1]`エリア (1) を再ペイントします。 次のクリックがウィンドウに到達します`0`、アクティブになり、注文が に移動します。`[0,2,1]`; 窓と重なっています`2`の面積はゼロなので、再ペイント量はゼロです。 最後のクリックがウィンドウに到達する`1`。 その瞬間、両方の窓が`0`そして窓`2`がその前にあり、ウィンドウと重なっています`1`は互いに素な単位正方形であり、(2) の再描画領域が生成されます。 これは、アルゴリズムが元の入力順序ではなく現在の Z オーダーを使用していることを確認します。 

最大サイズのケースには、10 個の同一の全画面ウィンドウがあります。 最前面のウィンドウだけが他のすべてのウィンドウを完全に覆っているため、クリックを受けることができます。 クリックするたびにすでにアクティブになっているため、すべての答えはゼロになります。 このテストでは、大きな画面サイズによってアルゴリズムが (2000\times2000) グリッドを割り当てたり走査したりしないことが確認されています。
