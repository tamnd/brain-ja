 ## 問題の理解

 与えられた整数を表現するように求められます`n`正確に合計として`k`すべての加数は 2 の累乗でなければなりません。 したがって、選択された各数値は次の形式になります。`1, 2, 4, 8, ...`、同じ力を複数回使用できるため、繰り返しが許可されます。 

入力は目標金額を記述します`n`および必要な数の加数`k`。 出力は、分解が不可能であるというステートメント、または具体的なマルチセットのいずれかです。`k`和が等しい 2 のべき乗`n`。 

問題の構造は 2 つの独立した方向に制約されます。 値`n`分配できる総質量は制限されますが、`k`その塊を一定数の部分に分割することを強制します。 これにより、「少数の大国」と「多数の小国」との間に緊張が生じます。 

境界が非常に厳しいため、パーティションを列挙したり組み合わせを明示的に構築しようとするアプローチは失敗します。 の値`n`まで上がります`10^9`したがって、バイナリで表現しても有効ビット数は最大 30 です。 の値`k`まで上がります`2 * 10^5`、そのため、出力自体が大きくなる可能性があり、アルゴリズムは最終的な答えのサイズが線形に近くなければならないことを意味します。 

重要なエッジケースは次の場合に発生します。`k`よりも大きいです`n`。 許容される最小値は次のとおりです。`1`、の合計`k`正の整数は少なくとも`k`, したがって、どのような場合でも`k > n`すぐには無理です。 

別の微妙なケースが発生するのは、`n`バイナリには設定ビットがほとんどありません。 たとえば、次の場合`n = 8`、自然な表現は次のとおりです。`[8]`。 もし`k = 3`、分割しなければなりません`8`2の3乗になります。 分割することで可能になります`8 -> 4 + 4`、さらに 1 つを分割します`4 -> 2 + 2`必要な分割数に応じて異なります。 正しさは、2 の累乗を分解し続けることができるかどうかにかかっています。 

## アプローチ

 直接的だが素朴なアプローチは、以下から始めることです。`n`バイナリ形式の 2 の累乗の和として記述されます。 各ビット`1 << i`一つの要素になります。 これにより、最小の加数数は、設定されたビット数と等しくなります。`n`。 

この数値が既に次の値を超えている場合は、`k`、2 つのべき乗を結合することは不可能であるため、すぐに失敗します。 2 のべき乗は、等しくない限り、別の 2 のべき乗と結合して別の 2 のべき乗を形成することはできないため、カウントを任意に減らすことはできません。 

初期項の数が最大でも`k`、正確に到達するまで項の数を増やそうとします。`k`。 要素の数を増やしながら合計を保持する唯一の操作は、2 の累乗を 2 つの等しい半分に分割することです。 分割するたびにカウントが 1 つずつ増加します。 

ブルート フォース バージョンでは、より大きい数値を繰り返し選択します。`1`に達するまで分割します`k`条項。 最悪の場合、分割ごとに高い電力が多くの電力に減少し、約`O(n)`操作が配列操作として非効率的に実装されている場合。 これでは遅すぎる`k`まで`2e5`。 

重要な点は、恣意的な分割を考慮する必要がないということです。 必要なのは、常に最大の利用可能な 2 のべき乗を分割するという貪欲な戦略だけです。 これにより、将来の分割に対する柔軟性を最大限に高めながら、実現可能性を維持することが保証されます。 

2 のべき乗の計算の構造を維持します。 分割するたびに、`2^i`を 2 つに置き換えます。`2^(i-1)`価値観。 要素数が到達するまで続行します`k`またはそれ以上の分割はできません。

 ## アルゴリズムのチュートリアル

 1.変換`n`バイナリ分解に変換し、2 の累乗ごとのカウントを保存します。 これにより、加数の数が最小限になります。 2 のべき乗がすべての整数に対して素の基底を形成するため、このステップが強制されます。 
2. 初期加数の数を数えます。 この数が次の値よりも大きい場合、`k`、出力`NO`なぜなら、異なる 2 のべき乗を 1 つの有効な 2 のべき乗にマージすることはできないからです。 
3. 2 のすべての累乗を max-struct (概念的には指数による優先キュー) に挿入します。 将来の分割で最も柔軟性が得られるため、利用可能な最大の電力を常に分割したいと考えています。 
4. 加数の数が以下の場合`k`、最大の力を引き出す`2^x`。 もし`x = 0`、値が`1`、これ以上分割できないので停止します。 それ以外の場合は、次の 2 つのコピーと置き換えます。`2^(x-1)`そしてカウントを 1 つ増やします。 
5. 正確に到達できれば`k`要素、マルチセットを出力します。 辿り着く前に行き詰まったら`k`、出力`NO`。 

### なぜ効果があるのか

 アルゴリズムは次の表現を維持します。`n`常に合計が次になる 2 のべき乗の集合として`n`。 置換するため、各操作では合計値が保存されます。`2^x`二人で`2^(x-1)`値を変更しないで維持します。 要素の数は分割ごとに 1 つずつ単調増加するため、最終的なサイズを正確に制御します。 最大の電力を分割するという貪欲な選択により、実現可能な解決策が存在する場合に、分割可能な質量が早期に不足することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())

    # initial decomposition
    cnt = 0
    heap = []

    for i in range(31):
        if n & (1 << i):
            heap.append(-i)
            cnt += 1

    if cnt > k:
        print("NO")
        return

    heapq.heapify(heap)

    # we store exponents as negatives for max-heap behavior

    while cnt < k:
        if not heap:
            break

        x = -heapq.heappop(heap)

        if x == 0:
            break

        # split 2^x into two 2^(x-1)
        heapq.heappush(heap, -(x - 1))
        heapq.heappush(heap, -(x - 1))
        cnt += 1

    if cnt != k:
        print("NO")
        return

    print("YES")
    res = []
    while heap:
        x = -heapq.heappop(heap)
        res.append(1 << x)

    print(*res)
```解決は分解から始まります`n`を 2 のべき乗に変換し、最小の有効な表現を形成します。 ヒープは、常に最大の指数を効率的に抽出するために使用されます。 これが重要なのは、繰り返し分割できるのはより大きな勢力だけであり、最初にそれらを選択することで、多くの勢力で行き詰まるのを避けることができるからです。`1`早すぎるよ。 

各分割操作では 1 つの要素が削除され、2 つの小さな要素が追加され、合計数がちょうど 1 つ増加します。 これにより、次の目標に向けた進捗状況を簡単に追跡できるようになります。`k`。 

終了条件は正確に到達するか、`k`要素を使用したり、分割可能なすべての権限を使い果たしたりします。

 ## 特殊なケース

 いつ`n = 1`そして`k > 1`、ヒープには単一の指数のみが含まれます`0`。 アルゴリズムはすぐに停止します。`0`分割できないため、正しく返されます`NO`。 

いつ`n`すでに大きいですが、ビットがまばらです。`n = 2^30`、アルゴリズムは単一の要素から始まります。 繰り返し分裂していきます`1`どちらかに到達するまで`k`または分割容量をすべて使い果たします。 すべての分割で合計が維持されるため、各ステップの正確性が維持されます。 

いつ`k`の初期ビット数に等しい`n`、分割する必要はありません。 このアルゴリズムは、最適な最小分解に一致するバイナリ表現を直接出力します。
