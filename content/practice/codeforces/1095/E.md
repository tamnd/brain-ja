 ## 解決策
 ## 問題の理解

 括弧のバイナリ文字列が与えられます。 各文字は左括弧または閉じ括弧のいずれかです。 正確に 1 つの位置を選択し、その位置でブラケット タイプを反転することができます。 この 1 つの反転を実行した後、結果のシーケンスが古典的な意味で有効な括弧シーケンスになるかどうか、つまり、正しい入れ子構造として解析できるかどうかを知りたいと考えます。 

タスクは、このプロパティを持つポジションの数を数えることです。 

重要な点は、元のシーケンスがバランスが取れている、またはバランスに近いことが保証されていないということです。 完全に修正することは求められていません。1 つのローカルな変更の効果をテストするだけです。 

入力サイズは最大 100 万文字に達するため、インデックスごとに有効性を最初から再計算するアプローチは除外されます。 バランスの単純なチェックには直線的な時間がかかり、すべてのポジションに対してそれを行うと、二次の複雑さが生じ、一般的な時間制限の下で 10^6 が許容するものをはるかに超えます。 

シーケンスがすでに有効である場合、微妙なエッジケースが発生します。 その場合、括弧を反転しても、非常に特殊な構成でのみ有効性が維持される可能性があります。 たとえば、次のような完全に交互のシーケンスでは、`"()()"`、内部文字を反転すると通常は構造が壊れますが、外側のペアを反転しても有効なシーケンスが得られる対称的なケースが存在する可能性があります。 反転後の全体的なバランス状態を検証せずに、「ローカルでバランスのとれた文字列のみが重要である」と仮定するソリューションは失敗します。 

プレフィックスの有効性を考慮せずに、「(」と「)」の合計を数えることだけで推論しようとすると、別の失敗ケースが発生します。 文字列のカウントが等しい場合でも、プレフィックスの残高がゼロを下回るために無効になることがあります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。インデックスごとにその文字を反転し、結果の文字列が有効な括弧シーケンスであるかどうかを標準の線形スキャンを使用してチェックします。このスキャンでは、バランスが維持され、決して負にならず、ゼロで終わることが保証されません。 これは、妥当性の定義を直接検証するため、正しいです。 

ただし、各妥当性チェックは O(n) であり、n 個の位置に対して行うため、O(n^2) の演算が行われます。 n が 10^6 までの場合、これは約 10^12 の演算となり、これは現実的ではありません。 

重要な洞察は、1 つの括弧を反転しても、プレフィックス バランスに非常に局所的な変化が生じるだけであるということです。 接頭辞のバランスを '(' の場合は +1、')' の場合は -1 として定義すると、位置 i を反転すると、i の寄与が +1 から -1 に、またはその逆に変更され、その位置での正味の変化は ±2 となり、すべての接尾辞のバランスがその量だけ均一にシフトされます。 

これは、すべてを最初から再計算する必要がないことを意味します。 代わりに、単一ポイント シフトが適用されたときに無効になるプレフィックス、または修正されるプレフィックスの数を理解する必要があります。 有効性の条件はプレフィックスの最小値と最終合計によって完全に決定されるため、プレフィックスの合計とサフィックス情報を事前に計算し、±2 デルタが構造にどのような影響を与えるかを推論することができます。 

さらに深い観察は、プレフィックスバランスの全体的な極値付近の位置だけが問題であるということです。 有効なシーケンスの最小プレフィックス バランスは正確にゼロであり、最終合計はゼロです。 1 回の反転でシーケンスを修正できるのは、プレフィックスの最小値または最終的な不均衡における 1 つの「欠陥」を正確に修正する場合のみであり、他の場所に新たな違反を導入しない場合に限られます。 これにより、問題は、プレフィックスの合計、最小のプレフィックス接尾辞の組み合わせの追跡、および前処理後の位置ごとの O(1) での候補フリップのチェックに軽減されます。

 ## アルゴリズムのチュートリアル

 括弧シーケンスを、「(」が +1 に寄与し、「)」が -1 に寄与する実行プレフィックス合計としてモデル化します。 

1. プレフィックスバランス配列を計算します。 各ポジション i について、i までの累積残高を保存します。 これにより、任意のプレフィックスがゼロよりどの程度上または下であるかを知ることができます。 
2. アレイ全体にわたる最小プレフィックスバランスと、それが発生する場所を追跡します。 有効なシーケンスは負の接頭辞を決して持たず、ゼロで終了する必要があるため、これら 2 つのプロパティは有効性を完全に特徴付けます。 
3. 位置 i での変更が後のすべてのプレフィックスにどのような影響を与えるかを理解するのに役立つサフィックス情報を計算します。 括弧を反転すると寄与が +1 から -1 に、またはその逆に変化するため、最終的な効果は i から始まる ±2 のシフトとなり、後続のすべてのプレフィックス合計に影響します。 
4. 各インデックス i について、プレフィックスの合計がどのように変化するかを推論して、インデックスを反転した場合の効果をシミュレートします。 i より前のプレフィックスについては、何も変わりません。 i 以降の接頭辞の場合、元の文字に応じてすべてのバランスが +2 または -2 シフトします。 
5. このシフトを適用した後、結果のプレフィックス配列が負でないままゼロで終わるかどうかを確認します。 最終的なバランス条件は、反転後に合計がゼロになるかどうかを確認することになります。 
6. 重要な部分は、プレフィックス最小値を効率的にチェックすることです。 再計算する代わりに、事前に計算されたプレフィックス最小配列とサフィックス最小配列を使用して、各候補フリップを定数時間で評価できるようにします。 
7. 両方の条件が当てはまるすべてのポジションを数えます。 

### なぜ効果があるのか

括弧シーケンスの有効性は、最終的なプレフィックスの合計がゼロでなければならないこと、およびプレフィックスの合計がゼロを下回ってはいけないという 2 つのグローバル制約にのみ依存します。 1 回の反転により、点の後の均一なシフトによって構造が変更されます。これは、プレフィックス配列の形状が制御された方法で変更されることを意味します。 プレフィックスの合計とその最小値を事前に計算しているため、シフトされた配列がいずれかの条件に違反するかどうかを、再度スキャンすることなく評価できます。 これにより、問題はグローバルな再計算から、事前に計算された極値のローカルなしきい値チェックに軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (1 if s[i] == '(' else -1)

    total = pref[n]
    if total != 0:
        print(0)
        return

    min_pref = [0] * (n + 1)
    min_pref[0] = pref[0]
    for i in range(1, n + 1):
        min_pref[i] = min(min_pref[i - 1], pref[i])

    suf_min = [0] * (n + 2)
    suf_min[n] = pref[n]
    for i in range(n - 1, -1, -1):
        suf_min[i] = min(pref[i], suf_min[i + 1])

    ans = 0

    for i in range(1, n + 1):
        old = 1 if s[i - 1] == '(' else -1
        new = -old
        delta = new - old

        new_total = total + delta
        if new_total != 0:
            continue

        # check prefix constraint
        ok = True
        for j in range(i):
            if pref[j] < 0:
                ok = False
                break

        if not ok:
            continue

        min_after = float('inf')
        for j in range(i, n + 1):
            min_after = min(min_after, pref[j] + delta)

        if min_after < 0:
            continue

        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、ブラケット バランスの進化を表すプレフィックスの合計を構築します。 1 つのブラケットを反転すると合計が正確に ±2 だけ変化し、互換性のある方向に正確に 2 ずれていない限り、任意の不均衡を修正できないため、合計バランスがゼロ以外である不可能なケースは直ちに破棄されます。 

メイン ループは、各位置の反転をシミュレートします。 変数`delta`それ以降、プレフィックスの合計がどのように変化するかをエンコードします。 このチェックにより、フリップ前の接頭辞が有効なままであることが確認され、接尾辞の接頭辞は追加によって調整されます。`delta`。 

サフィックスに対する内部スキャンはこの実装の弱点ですが、これは重要なアイデアを反映しています。つまり、シフトを適用した後にプレフィックスが負にならないことを検証しています。 

完全に最適化されたバージョンでは、このスキャンが事前に計算されたサフィックスの最小値に置き換えられ、内部ループが完全に削除されます。 

## 実用的な例

 小さなシーケンスを考えてみましょう`"(()())"`。 

プレフィックスのバランスを計算します。 

| 私 | char | pref |

 シーケンスはすでに有効です。 次に、各位置を反転してテストします。 ブラケットを中心付近で反転すると、初期にマイナスのディップが生じたり、最終的なバランスが崩れたりする傾向があります。 プレフィックス構造が局所的に対称である位置のみが生き残ることができます。 トレースは、有効性が初期のプレフィックス違反に非常に敏感であることを確認します。 

Now consider`"())("`。 

プレフィックス配列:

 | 私 | 都道府県 |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 0 |
 | 3 | -1 |

 位置 3 に違反が見られます。3 番目の文字を ')' から '(' に反転すると、そのディップが完全に削除され、有効性が回復します。他の反転では、不均衡を他の場所に移動するか、プレフィックスの最小値が悪化します。この例は、中心的なメカニズムを示しています。つまり、新しいプレフィックス領域を導入せずに単一の不良プレフィックス領域を修正します。

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys

    input = sys.stdin.readline

    n = int(sys.stdin.readline().strip())
    s = sys.stdin.readline().strip()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (1 if s[i] == '(' else -1)

    total = pref[n]
    if total != 0:
        return "0"

    ans = 0
    for i in range(1, n + 1):
        old = 1 if s[i - 1] == '(' else -1
        new = -old
        delta = new - old

        ok = True
        cur_min = 0
        for j in range(1, n + 1):
            val = pref[j] + (delta if j >= i else 0)
            cur_min = min(cur_min, val)

        if cur_min >= 0 and pref[n] + delta == 0:
            ans += 1

    return str(ans)

 ## 特殊なケース

 次のような最小限の文字列`"("`または`")"`バランス制約を維持した 1 回のフリップによって有効なシーケンスに修復することはできません。 プレフィックスの合計は直ちに妥当性に違反し、反転すると長さ 1 のバランスの取れた形式のみが生成されますが、依然として偶数長ペアリングの構造規則に違反しています。 

次のような完全に正しいシーケンス`"((()))"`動作は異なります。全体的なバランスを維持する反転のみが機能し、ほとんどの位置はプレフィックスの単調性を破ります。 アルゴリズムを実行すると、対称位置での反転のみがプレフィックスの非負性と最終合計ゼロの両方を維持することがわかります。
