 ## 解決策
 ## 問題の理解

 標準的な 6 面のサイコロが与えられますが、その面には通常の 1 から 6 の値の代わりに、2、3、4、5、6、7 というすべて異なる整数が含まれています。 各ロールはこれらの数値の 1 つを生成し、一連のロールのスコアは表示されている面の合計になります。 

各クエリ値について$x$、任意のロール数を決定するように求められます。$k$正確に合計を得ることができるように$x$正確に使用して$k$ロール。 ロールのシーケンスを構築する必要はなく、有効なロールを出力するだけです。$k$。 

重要な解釈は、一度修正すると、$k$を表現できるかどうかが問題になります。$x$合計として$k$それぞれから選択される整数$\{2,3,4,5,6,7\}$。 

制約は小さいです。$t \le 100$そして$x \le 100$。 これにより、大量の組み合わせや検索の必要性が即座に排除されます。 クエリごとに一定時間で各答えを計算するソリューションであれば十分です。 

微妙な点は、$k$同じように働くことができる$x$。 この問題では最小値や最大値は求められず、有効な値のみが求められます。 この柔軟性により、構築が簡単になります。 

このステートメントはすべてのクエリに対して解決策が存在することを保証するため、不可能を伴う実際のエッジ ケースはありません。 

## アプローチ

 強引な解釈では、可能な限りすべてのロール数を試すことになります。$k$、それぞれについて$k$、どうかを確認してください$x$を使用して形成できます$k$2 ～ 7 の数字。固定の場合$k$、これは次のことを尋ねることと同じです。$x$範囲内にあります$[2k, 7k]$2 がロールの最小貢献度であり、7 が最大貢献度であるためです。 

すべてを総当りでやると$k$たとえば、$x$、それぞれについて$k$チェックを実行すると、制約があれば複雑さは小さいままですが、その必要はありません。 問題の構造は直接的な構築を示唆しています。 

重要な観察は、選択されたものに対して、$k$、達成可能な合計は、からの連続的な間隔を形成します。$2k$に$7k$。 許容額面内に収まりながら、個々のロールを 1 ステップで調整できるため、この間隔にはギャップがありません。 したがって、シーケンスを検索する代わりに、任意の整数を見つけるだけで済みます。$k$そのような$2k \le x \le 7k$。 

並べ替えると、次のようになります。$$\frac{x}{7} \le k \le \frac{x}{2}$$以来$k$整数である必要があります。この範囲内の任意の整数が機能します。 単純で建設的な選択は、有効な最小値を採用することです。$k$それでも到達できる$x$、つまり:$$k = \left\lceil \frac{x}{7} \right\rceil$$これを修正したら$k$、残りの差額$x - 2k$ロールを 2 から 7 に増やすことでいつでも配布できます。

 ## アルゴリズムのチュートリアル

 1. クエリ数を読み取る$t$。 各クエリは目標合計を示します$x$。 
2. それぞれについて$x$、最小の整数を計算します$k$そのような$7k \ge x$。 これにより、すべての出目が 7 であっても、到達またはそれを超えることができます。$x$。 
3. これを出力します$k$クエリの答えとして。 

天井を選択する理由$x/7$それは、ロールの数を最小限に抑えながら、到達するのに十分な総容量を保証することです。$x$。 それより小さいもの$k$達成可能な最大額は以下のとおりです$x$、不可能になります。 

### なぜ効果があるのか

 任意の固定数のロールに対して$k$、達成可能な合計のセットは正確に間隔です$[2k, 7k]$。 これは、各ロールが独立して 2 ～ 7 の任意の値に寄与し、1 つのロールを ±1 調整すると、有効なまま合計がちょうど 1 だけ変更されるためです。 したがって、範囲内のすべての整数に到達可能です。 

選択する$k = \lceil x/7 \rceil$保証する$x \le 7k$。 同時に、それ以来、$k \ge 1$を表現するのに十分な構造が常にあります。$x$すべて 2 から始めて、いくつかのロールを増やします。 したがって$x \ge 2k$問題制約のこの構築範囲にも自動的に適用され、残りのギャップは選択したロールを 7 まで増分することで埋めることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())
        k = (x + 6) // 7
        print(k)

if __name__ == "__main__":
    solve()
```コードは各クエリを独立して処理します。 表現`(x + 6) // 7`の標準的な整数の上限の除算です。$x/7$常に最小のものを選択するようにします$k$そのような$7k \ge x$。 

この実装では、サイコロの出目のシミュレーションが回避されます。 このロジックは、実行可能なロールの最小数を直接計算します。この問題では有効な構成が許容されるため、これで十分です。

 ## 特殊なケース

 重要な境界線の 1 つは、次の場合です。$x$は正確に 7 で割り切れます。たとえば、$x = 14$。 アルゴリズムが与えるのは、$k = 2$。 2 ロールの場合、最大は$14$、によって達成されました$7 + 7$、上限の正しさを確認します。 

もう一つのケースは次のような場合です。$x$は 7 の倍数のすぐ上です。たとえば、$x = 8$。 ここ$k = 2$。 範囲は$[4, 14]$したがって、たとえば 8 は達成可能です。$2 + 6$。 これは、1 つのロールが不足している場合でも、2 番目のロールを追加することで隙間を埋めるのに十分な柔軟性が得られることを示しています。 

最後に、次のような非常に小さな値の場合、$x = 2$、式は次のようになります$k = 1$。 唯一可能な合計は正確に 1 つのロールであり、要件に正確に一致する 2 でなければなりません。
