 ## 解決策
 ## 問題の理解

 1 から n までの同じ値セットの 2 つの順列を使用しています。 1 つの順列 (a と呼びます) は位置に基づいた配置を与え、もう 1 つの順列 b も同じ値の異なる順序を与えます。 各クエリでは、これら 2 つの異なる「座標系」で定義された間隔を比較するよう求められます。 

最初のタイプのクエリは、a の位置の連続セグメントと b の位置の連続セグメントを選択し、選択された両方のセグメントに出現する値の数を尋ねます。 両方の配列は順列であるため、各値は a の 1 つの位置と b の 1 つの位置に正確に対応します。 したがって、実際の質問は、ある区間内の a での位置と、別の区間内の b での位置を持つ値 x がいくつあるかということです。 

2 番目のクエリは b の 2 つの要素を交換します。これは、b の値の位置マッピングが動的に変化することを意味します。 これが難しい部分です。交差クエリに応答しながら移動順列を維持しているのです。 

制約は最大 200,000 の要素とクエリに及ぶため、クエリごとに 2 次の解法は直ちに不可能になります。 最悪の場合、クエリあたり O(n) でも遅すぎます。 データ構造を慎重に設計して、操作ごとに O(log n) または O(√n) に近いものが必要です。 

微妙なエッジ ケースは、更新が将来のクエリに非ローカルで影響を与えることです。 たとえば、b が [1,2,3] で、位置 1 と 3 を交換すると、値 1 は位置 1 から位置 3 に移動します。位置を 1 回事前計算し、決して更新しない単純な解決策では、最初の交換の前にのみ正しい答えが生成されます。 

もう 1 つの失敗例は、カウントする必要があるのはインデックスではなく値であるという誤解です。 値の位置ではなくインデックス セットを誤って交差すると、a と b の範囲の重複が直接計算される可能性がありますが、順列によって値が恣意的に並べ替えられるため、これは意味がありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリについて、a のセグメント内のすべての位置を反復処理して値を収集し、b 内のその位置が 2 番目のセグメント内にあるかどうかをそれぞれチェックできます。 事前に計算された位置配列 posB[value] を使用すると、これは O(a 内のセグメントの長さ) になります。 最悪の場合、両方のセグメントのサイズが n になる可能性があるため、各クエリのコストは O(n) となり、合計操作数は O(nm) となり、許容範囲をはるかに超えています。 

改善するために、すべての値が 2D グリッド内の点を定義していることを観察します: (posA[value], posB[value])。 各クエリは、[l_a, r_a] × [l_b, r_b] で定義される軸に沿った長方形の中にある点の数を尋ねます。 これは、b の交換により点が 1 つの軸に沿って移動することを除いて、古典的な動的 2D 直交範囲計数問題になりました。 

重要な観察は、posA が静的であるということです。 したがって、すべての点の x 座標は固定されますが、y 座標はスワップによって変化します。 b の各スワップでは、2 つのポイントの y 値のみが変更されます。 この構造により、更新を局所的な変更として扱うことができ、クエリを y にわたる動的構造を備えた x にわたる範囲として扱うことができます。 

X 軸をブロックに分割することで配列を処理できます (sqrt 分解)。 各ブロックについて、そのブロック内に x がある点の y 値のソートされた構造を維持します。 次に、クエリはバイナリ検索を使用してブロック全体からの寄与を合計し、スキャンによって部分ブロックを処理します。 

b で交換が発生すると、2 つの点の y 値のみが更新されるため、それらを削除してそれぞれのブロックに再挿入します。 これにより、操作ごとのコストが O(√n log n) 程度に抑えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n) | O(n) | 遅すぎる |
 | ブロックごとに順序付けされた y を使用した x の sqrt 分解 | 操作ごとに O(√n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、両方の順列を位置マッピングに変換します。 posA[x] と posB[x] を計算し、2D 平面内の各値の座標を与えます。 

次に、posA のインデックス範囲 (各値は 1 回出現するため、値 1 ～ n に対応) を約 √n のサイズのブロックに分割します。 各ブロックには、そのブロック内に posA インデックスがある要素の posB 値のマルチセットが格納されます。 

各クエリは次のように処理されます。 

1. クエリ (l_a、r_a、l_b、r_b) の場合、posA[x] が [l_a, r_a] にあり、posB[x] が [l_b, r_b] にあるような値 x をカウントしたいとします。 posA のブロックを反復処理します。 

[l_a, r_a] 内の完全なブロックは、マルチセットを使用して処理されます。 並べ替えられたデータの二分探索を使用して、[l_b, r_b] に含まれる y 値の数を数えます。 各ブロックにはその x 範囲内の点が正確に含まれているため、これは正しいです。 
2. クエリ範囲の端にある部分ブロックについては、要素ごとに繰り返し、両方の座標が制約を満たしているかどうかを直接チェックします。 ブロックが完全に含まれていないため、これが必要です。 
3. 更新クエリ (x, y) の場合、b の値を交換し、posB を 2 つの値に変更します。 v1 = b[x]、v2 = b[y] とします。 b 内の位置を交換するので、posB[v1] と posB[v2] が更新されます。 古い posB 値をブロックから削除し、新しい値を挿入します。 

更新の正確性は、posB とブロック構造間の一貫性の維持に依存します。 

### なぜ効果があるのか

 常に、すべての値 x は点 (posA[x]、posB[x]) として表されます。 ブロック分解では、x 座標によってポイントが分割されます。 各ブロックは、そのブロック内に x がある点の正確な y 座標の複数セットを維持します。 クエリは、x 範囲をブロックの素結合と小さな残りに分解します。 すべてのポイントは、ブロック全体または部分スキャンで 1 回だけカウントされます。 ブロックがインデックス軸のパーティションを形成し、更新により値から位置への不変マッピングが保持されるため、ポイントの欠落や二重カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

class Block:
    def __init__(self):
        self.arr = []

    def rebuild(self):
        self.arr.sort()

    def add(self, x):
        self.arr.append(x)

    def remove(self, x):
        # remove one occurrence
        i = bisect_left(self.arr, x)
        self.arr.pop(i)

    def query(self, l, r):
        return bisect_right(self.arr, r) - bisect_left(self.arr, l)

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

posA = [0] * (n + 1)
posB = [0] * (n + 1)

for i, v in enumerate(a, 1):
    posA[v] = i
for i, v in enumerate(b, 1):
    posB[v] = i

import math
B = int(math.sqrt(n)) + 1
blocks = [Block() for _ in range((n + B - 1) // B)]

def block_id(x):
    return (x - 1) // B

for v in range(1, n + 1):
    blocks[block_id(posA[v])].add(posB[v])

for blk in blocks:
    blk.rebuild()

def range_query(lx, rx, ly, ry):
    res = 0
    i = lx
    while i <= rx:
        if i % B == 1 and i + B - 1 <= rx:
            bidx = block_id(i)
            res += blocks[bidx].query(ly, ry)
            i += B
        else:
            v = a[i - 1]
            if ly <= posB[v] <= ry:
                res += 1
            i += 1
    return res

for _ in range(m):
    tmp = input().split()
    if tmp[0] == '1':
        la, ra, lb, rb = map(int, tmp[1:])
        print(range_query(la, ra, lb, rb))
    else:
        x, y = map(int, tmp[1:])
        v1 = b[x - 1]
        v2 = b[y - 1]

        # remove old
        blocks[block_id(posA[v1])].remove(posB[v1])
        blocks[block_id(posA[v2])].remove(posB[v2])

        # swap in b
        b[x - 1], b[y - 1] = b[y - 1], b[x - 1]

        # update positions
        posB[v1], posB[v2] = y, x

        # insert new
        blocks[block_id(posA[v1])].add(posB[v1])
        blocks[block_id(posA[v2])].add(posB[v2])
```このソリューションは、値から両方の順列の位置への直接座標マッピングを構築します。 ブロック構造は posA を超えており、各ブロックには範囲カウント用にソートされた posB 値が格納されます。 クエリ機能は、不必要なスキャンを避けるために、完全なブロックと部分的なブロックを注意深く区別します。 

スワップ ロジックは最もデリケートな部分です。 posB を更新する前に、影響を受ける両方の値を古いブロックから削除する必要があります。そうしないと、古い座標を追跡できなくなります。 更新後、構造の一貫性を保つために再挿入します。 

再構築ステップでは、最初の構築後に各ブロックを 1 回ソートし、バイナリ検索が正しく機能することを保証します。 

## 実用的な例

 小さな例を考えてみましょう。 

a = [1、3、2、4]

 b = [3, 1, 4, 2]

 クエリ: (1、3、2、4)

 位置を計算します。 

| 値 | posA | posB |
 | --- | --- | --- |
 | 1 | 1 | 2 |

 | 4 | 4 | 3 |

| 値 | [1,3] の posA | [2,4] の posB | 含まれています |
 | --- | --- | --- | --- |
 | 1 | はい | はい | はい |
 | 2 | はい | はい | はい |
 | 3 | はい | いいえ | いいえ |
 | 4 | いいえ | はい | いいえ |

 答えは2です。 

ここで b にスワップを適用します: 位置 2 と 4 を交換します。 

bは[3, 2, 4, 1]になります。 ここで posB が更新されます。 

1→4、2→2、3→1、4→3

 再度クエリを実行します (1,4,1,2):

 すべての値をチェックします。 

| 値 | posA | posB | 含まれています |
 | --- | --- | --- | --- |
 | 1 | 1 | 4 | いいえ |
 | 2 | 3 | 2 | はい |
 | 3 | 2 | 1 | はい |
 | 4 | 4 | 3 | いいえ |

 答えは2です。 

これらのトレースは、動的更新は posB にのみ影響を及ぼし、posA は安定したままであり、クエリは常に四角形内のポイントをカウントしていることを確認します。

 ## 特殊なケース

 重要なエッジケースの 1 つは、同じ 2 つのポジションが繰り返しスワップに関与する場合です。 この状況では、同じ値が複数回削除され、再挿入されます。 この構造は、各更新で新しい座標を挿入する前に古い座標を厳密に削除し、ブロック内に重複が蓄積しないようにするため、これを安全に処理します。 

もう 1 つのケースは、クエリ範囲がブロック境界と正確に一致する場合です。 その場合、アルゴリズムは部分的なスキャンを行わずにブロック クエリを完全に使用する必要があります。 条件`i % B == 1 and i + B - 1 <= rx`完全に位置合わせされたブロックのみが一括して取得されることを保証し、偶発的な二重カウントや要素の欠落を防ぎます。 

最後の微妙なケースは、最小入力サイズ (n = 2) です。ブロックが単一要素グループに縮退し、すべての操作が直接スキャンにフォールバックするため、分解は引き続き機能し、特別なケースを使用しなくても正確さが維持されます。
