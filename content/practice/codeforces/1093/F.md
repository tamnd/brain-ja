 ## 解決策
 ## 問題の理解

 部分的に指定された長さの配列が与えられます$n$。 各位置には、次のいずれかの固定値がすでに含まれています。$1$そして$k$、または不明で次のようにマークされています$-1$。 すべての未知の位置を次の値に置き換える必要があります。$1$に$k$、完全に埋められた配列を生成します。 

塗りつぶされた配列は、正確な値の連続ブロックが含まれていない場合、有効であるとみなされます。$len$等しい値。 つまりインデックスが無い$i$セグメントが$a[i], a[i+1], \dots, a[i+len-1]$同じ数字で構成されます。 

課題は、すべてを置き換えることができる方法が何通りあるかを数えるということです$-1$最終的な配列がこの制約を満たすようにエントリを追加します。$998244353$。 

この制約により、私たちはすぐに動的プログラミングの考え方を強いられます。 配列の長さは最大です$10^5$したがって、割り当てを明示的に分岐しようとするソリューションは、その数が指数関数的に増加します。$-1$価値観があり、まったく実行不可能です。 アルファベットのサイズ$k$は小さく、最大でも 100 です。これは、前の値または短い履歴に依存する遷移が実行可能であることを強く示唆しています。 

微妙な点は、禁止条件が正確に同じ長さの値の連続に依存することです。$len$、隣接する要素間の不平等だけではありません。 これにより、単純な貪欲な入力やローカル チェックが除外されます。実行の早い段階で決定すると、その後の多くのステップで構成が無効になる可能性があるためです。 

素朴な推論を打ち破るエッジケースは簡単に構築できます。 もし$len = 1$の場合、すべての単一要素がそれ自体で禁止セグメントを形成するため、問題定義が暗黙的にそうでないことを保証しない限り、答えは常にゼロになります。 これにより、アルゴリズムがこれを直ちに検出して処理するようになります。 もう 1 つの重要なケースは、配列が完全に固定されており、すでに一連の長さが含まれている場合です。$len$、 例えば$len = 3$、 配列$[5, 5, 5]$、選択肢がないにもかかわらず、答えは明らかにゼロです。 すべての違反が割り当て中に作成されると想定している場合、充填中に制約をチェックするだけの単純なアプローチでは、これを見逃す可能性があります。 

## アプローチ

 ブルートフォース戦略では、それぞれの値を割り当てようとします。$-1$再帰的に実行し、完了するたびに有効性をチェックします。 各ポジションには最大で$k$したがって、すべてのエントリが次と等しい最悪の場合、$-1$、割り当ての数は$k^n$、これは天文学的に大きいです$n = 10^5$。 無効な部分的な実行を削除しても、局所的に役立つだけで、指数関数的な分岐は防止できません。 

重要な観察は、制約が実行に関して純粋にローカルであるということです。重要なのは、等しい値の現在のサフィックスの長さだけです。 配列の完全な履歴を記憶する必要はなく、最後の値と、それがこれまでに連続して繰り返された回数だけを記憶する必要があります。 ランの長さに達すると$len$、同じ値をさらに拡張することは禁止されています。 

これにより、問題は、最後の値とそのランレングスを追跡する動的プログラミング状態、またはより効率的には、各位置で可能な値ごとに現在のランの長さを追跡するという動的プログラミング状態に縮小されます。 なぜなら$k \le 100$、値全体にわたって DP を維持し、ランレングス全体にわたるプレフィックス合計を使用して遷移を圧縮できます。 

より効率的な定式化は、配列を左から右に構築し、位置ごとにその位置で終了する方法の数を維持する DP を定義することです。$i$最後の値で$v$、現在のランレングスが厳密に以下であることを保証しながら、$len$。 ランを延長するときは、同じ値を継続するか (許可されている場合)、別の値に切り替えてランの長さを 1 にリセットします。 

重要な技術的トリックは、状態ごとに完全なランレングスを明示的に追跡することを回避し、代わりに値ごとに、正確な長さのランレングスで終了できる方法の数を維持することです。$t$、次にプレフィックス合計を使用してトランジションを圧縮し、ランの拡張が次のようになります。$O(1)$州ごとに。

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、各位置で終わる有効なプレフィックスを記述する DP 状態を維持します。 

1. DP テーブルを定義します。$dp[v][c]$最後の値が次のように現在位置まで埋める方法の数を表します。$v$現在の連続ランの長さは$c$、 どこ$1 \le c < len$。 これは、長さに達する状態を決して保存しないため、構築によって禁止条件を直接エンコードします。$len$。 
2. DP を位置 0 で初期化します。最初の要素が値に固定されている場合$x$、設定しました$dp[x][1] = 1$。 そうであれば$-1$、設定しました$dp[v][1] = 1$みんなのために$v \in [1, k]$。 これは、すべての有効な配列が長さ 1 の連続で開始する必要があることを反映しています。 
3. 次のポジションごとに、新しい DP テーブルを構築します$ndp$ゼロに初期化されます。 すべての値を反復処理します$v$ランレングスと$c$現在カウントがゼロではないもの。 
4. 現在の配列位置が値に固定されている場合$x$、新しい最後の値が次の状態になる状態への遷移のみを許可します。$x$。 それ以外の場合は、すべての値が考慮されます$1 \dots k$。 
5. 州から$(v, c)$では、2 種類の遷移を考えます。 同じ価値観を置くなら$v$、実行を延長できます$c+1$場合のみ$c+1 < len$。 これは貢献します$dp[v][c]$に$ndp[v][c+1]$。 
6. 別の値を設定した場合$u \ne v$、実行がリセットされるため、貢献します$dp[v][c]$に$ndp[u][1]$。 可能性はたくさんあるので、$u$、すべての状態の合計を使用して寄与度を集計し、同じ値に留まる寄与度を減算します。 
7. すべての状態を処理した後、次のように置き換えます。$dp$と$ndp$そして続けます。 

すべての位置を処理した後の答えは、すべての値とランレングスにわたるすべての有効な DP 状態の合計になります。 

### なぜ効果があるのか

 DP 状態は、将来の拡張の有効性を決定するために必要な情報を正確にエンコードします。最後の値とそれが繰り返された時間だけが問題となります。 同じ最後の値と同じランレングスで終わる 2 つのプレフィックスは、将来の決定に関して交換可能です。 遷移は最後の値との等しいか不等さにのみ依存するため、追加の履歴が正確さに影響を与えることはありません。 維持される不変条件は、すべての DP 状態が禁止された実行のない有効なプレフィックスに対応し、すべての有効なプレフィックスが 1 つの状態で 1 回だけカウントされるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k, L = map(int, input().split())
    a = list(map(int, input().split()))
    
    if L == 1:
        print(0)
        return
    
    dp = [[0] * (L - 1) for _ in range(k + 1)]
    
    if a[0] == -1:
        for v in range(1, k + 1):
            dp[v][0] = 1
    else:
        dp[a[0]][0] = 1
    
    for i in range(1, n):
        ndp = [[0] * (L - 1) for _ in range(k + 1)]
        
        total = 0
        for v in range(1, k + 1):
            for c in range(L - 1):
                total = (total + dp[v][c]) % MOD
        
        if a[i] == -1:
            for v in range(1, k + 1):
                for c in range(L - 1):
                    val = dp[v][c]
                    if not val:
                        continue
                    # switch to same value
                    if c + 1 < L - 1:
                        ndp[v][c + 1] = (ndp[v][c + 1] + val) % MOD
                    # switch to different values
                    ndp[v][0] = (ndp[v][0] + (total - val)) % MOD
        else:
            x = a[i]
            for v in range(1, k + 1):
                for c in range(L - 1):
                    val = dp[v][c]
                    if not val:
                        continue
                    if v == x:
                        if c + 1 < L - 1:
                            ndp[v][c + 1] = (ndp[v][c + 1] + val) % MOD
                    else:
                        ndp[x][0] = (ndp[x][0] + val) % MOD
        
        dp = ndp
    
    ans = 0
    for v in range(1, k + 1):
        for c in range(L - 1):
            ans = (ans + dp[v][c]) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、値と現在のランレングスから 1 を引いた値によってインデックス付けされ、長さの保存を回避します。$len$それ自体は無効なので。 各反復で新しいテーブルが再計算され、位置間の汚染がないことが保証されます。 

重要な実装の詳細は、異なる値への遷移の処理です。 考えられるすべてのターゲット値を明示的に反復する代わりに、すべての DP 状態の合計を使用し、現在の状態を減算します。これにより、追加の要因が回避されます。$k$移行ロジックのその部分で。 

もう 1 つの微妙な点は、ランレングスの 1 つずつの処理です。 このコードでは、1 ではなく 0 から始まるランレングスを格納するため、次のような状態になります。$c = 0$これにより、インデックス作成が簡素化されますが、ランを拡張するときに慎重な境界チェックが必要になります。

 ## 特殊なケース

 いつ$len = 2$、制約は、等しい隣接ペアを禁止します。 DP はすぐに同等の隣接要素を持たない標準のカラーリングに縮退し、トランジションでランを延長してはなりません。 長さ 1 を超えてランを増分しようとする試みは拒否されるため、アルゴリズムはこれを自然に処理します。 

配列が完全に固定されている場合、DP は決して分岐しません。 状態は単に固定値を介して伝播し、不正なランレングスに達した有効な DP 状態が存続しないため、違反は自動的に排除されます。 

いつ$k = 1$、可能な配列はすべて 1 だけです。 答えは 1 です$n < len$、それ以外の場合は 0。DP は実行拡張の単一チェーンに折りたたまれ、ラン長が次の値に達すると、遷移ルール​​が禁止されたケースを直接ブロックします。$len$。
