 ## 解決策
 ## 問題の理解

 隠れた非減少配列が与えられます`a`均等な長さの`n`。 私たちは決して見ません`a`直接。 代わりに、その構造の半分が示されます。対称的な位置のペアごとに、端の要素の合計がわかります。 具体的にはそれぞれに`i`左から、`a[i] + a[n - i + 1]`が与えられ、配列が形成されます`b`。 

タスクは、有効な配列を再構築することです。`a`これは減少せず、非負の整数で構成され、これらすべてのペアごとの合計と一致します。 多くの異なる配列が条件を満たす可能性があり、有効な構成はどれでも受け入れられます。 

制約により、線形または線形に近い再構成が行われます。 と`n`まで`2 · 10^5`、`O(n^2)`あるいは`O(n log n)`重い定数を使用することは許容されますが、グローバル検索を繰り返したり、それぞれの分割の可能性をバックトラッキングしたりするものはすべて許容されます。`b[i]`が遅すぎるため、`b[i]`ペアへの多くの可能な分解に対応できます`(x, y)`。 

主な難点は、それぞれの合計が`b[i]`2 つの未知の値を非表示にします。これらの値は、完全に再構築された配列がソートされるという要件によってグローバルに制約されます。 それぞれを独立して分割する素朴なアプローチ`b[i]`異なるペア間の相互作用が無視されるため、失敗します。 

それぞれを貪欲に分割すると、よくある落とし穴が現れます。`b[i]`の中へ`(0, b[i])`または`(b[i]/2, b[i]/2)`。 たとえば、入力の場合`n = 4`、`b = [1, 100]`、選択する`(0,1)`そして`(0,100)`生成する`a = [0,0,100,1]`、各ペアは個別に有効であるにもかかわらず、ソートされていません。 

もう 1 つの失敗モードは、左のエンドポイントが非減少で右のエンドポイントが非増加であることを強制せずに、対称ペアを左から右に独立して割り当てることです。 そのローカルな自由こそが、まさにグローバルな一貫性を壊すものなのです。 

## アプローチ

 強引なアイデアは、それぞれの分割をすべて試してみることです。`b[i]`。 ペアごとに、`x`から`0`に`b[i]`そしてセット`y = b[i] - x`次に、すべてのペアをグローバルにソートされたシーケンスに配置できるかどうかを確認します。 これはすぐに爆発します。`n/2`ペアには最大`10^{18}`可能性があり、完全に実行不可能になります。 

構造上の重要な洞察は、ペアを個別に割り当てる必要がないということです。 代わりに、順序付けの制約を維持しながら、外側から内側に向​​かって配列を構築します。 最終的な配列は 2 つの単調シーケンスとして見ることができます。左半分は非減少、右半分は非増加であり、それぞれ`b[i]`各側から 1 つの要素をバインドします。 

大きな制約が最初に修正されるように、合計を降順で処理します。 各ステップでペアを決定します`(x, y)`そのような`x + y = b[i]`、これまでに構築されたシーケンスが単調性と一貫性を維持していることを維持しながら。 貪欲な選択はプッシュすることです`y`右側の要件が増加しないため、右側の値が大きくなると、後で対応することが困難になるため、できるだけ大きくします。 一度`y`固定されており、`x`強制されます。 

これにより、問題は 2 つの実行境界を持つ単一の線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 それぞれを解釈していきます`b[i]`1 つのペアを定義するものとして`(x_i, y_i)`どこ`x_i + y_i = b[i]`、そして最後の配列ではすべて`x_i`全員が左半分を形成する間、`y_i`右半分を形成します。 

2 つの単調な構造を強制します。`x_i`は減少しない必要があり、次のシーケンスは`y_i`増加しないことが必要です。 さらに、各ペアについて、`x_i ≤ y_i`マージされた配列がソートされたままになるようにします。 

これらの制約を一貫して強制するために、次のように処理します。`b`降順で。 

## アルゴリズムのステップ

 1. 並べ替え`b`昇順ではない順に。 

最初に大きな合計を処理すると、後の小さな合計が制約された位置に不可能な大きな値を強制することを防ぎます。 
2. 2 つの実行変数を初期化します。`prev_x = 0`そして`prev_y = +∞`。`prev_x`最後に選択された左側の値を追跡し、左側で非降順であることを保証します。`prev_y`最後に選択された正しい値を追跡し、右側の非増加順序を保証します。 
3. 各値について`b_i`ソートされた順序で、正しいエンドポイントの実行可能な範囲を計算します。`y`。 

以来`x = b_i - y`満たさなければなりません`x ≥ prev_x`、私たちは得ます`y ≤ b_i - prev_x`。 

また、右側の単調性を維持するには、`y ≤ prev_y`。 

それで`y`満たさなければなりません`y ≤ min(prev_y, b_i - prev_x)`。 
4.選択します`y`有効な範囲内で可能な限り大きい値:`y = min(prev_y, b_i - prev_x)`。 

この貪欲な選択により、将来のステップに対して最大限の柔軟性が維持されます。 
5.セット`x = b_i - y`。 

これにより、和制約と和制約の両方が自動的に満たされます。`x ≥ prev_x`。 
6.アップデート`prev_x = x`そして`prev_y = y`、およびストア`x`そして`y`別々のリストに分割します。 
7. すべてのペアを処理した後、左側が収集されたものになります。`x`値を順番に並べ、右側が収集したものです`y`値を逆順に並べます。 それらを連結して最終的な配列を形成します。 

## なぜ機能するのか

 この構造では、厳密な不変条件が維持されます。各処理の後、`b_i`、選ばれた`x`値は、すでに固定された決定と一致する最小の非減少シーケンスを形成しますが、`y`値は、同じ決定と一致する可能な最大の非増加シーケンスを形成します。 それぞれのステップが貪欲に最大化するから`y`実現可能性の制約の下では、後の代入によって右側に矛盾が生じる可能性があり、導出された`x`は自動的に、和と左単調性の両方と互換性のある最小値になります。 これにより、将来の合計で、すでに固定されている値よりも小さい左の値が必要になることが防止されます。これが、構築が失敗する唯一の方法です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    
    b.sort(reverse=True)
    
    prev_x = 0
    prev_y = 10**30
    
    left = []
    right = []
    
    for val in b:
        y = min(prev_y, val - prev_x)
        x = val - y
        
        left.append(x)
        right.append(y)
        
        prev_x = x
        prev_y = y
    
    a = left + right[::-1]
    print(*a)

if __name__ == "__main__":
    solve()
```実装は貪欲な構築に直接続きます。 仕分け`b`最大の制約を最初にロックするようにします。 2 つの実行変数は、再構築された半分の単調性という重要な唯一のグローバル制限をエンコードします。 の選択`y`将来の制約を破ることを避けるために意図的に最大値にしていますが、`x`は合計方程式から決定論的に決定されます。 

最後の連結`left + reversed(right)`右側が非増加順序で構築されているため、これが機能するため、これを逆にすると、最終配列に必要な非減少のサフィックスが生成されます。

 ## 特殊なケース

 微妙なエッジケースが現れるのは、`b[i]`等しいです。 この状況では、すべてのペアが同一の柔軟性を持ち、単純な構造は、グローバルな順序を壊す方法で対称的に分割されることがよくあります。 貪欲なアプローチでは、常にプッシュすることでこれを回避します。`y`許容最大値まで大きくすると、対称性に関係なく厳密に一貫した単調構造が生成されます。 

小さな場合には別のケースが発生します。`b[i]`大きいものの後に出現します。 並べ替えを行わないと、少額の場合は時期尚早に制限される可能性があります`prev_x`そのため、以前の大きな値を適合させることができなくなります。 並べ替えると、大きな制約が最初に配置されるため、構造が実行不可能になることはありません。 

最後に、次のようなケース`b[i]`以前の選択とかろうじて一致しているが、厳密な境界をテストする`y ≤ b_i - prev_x`。 アルゴリズムは、この不等式が正確に適用されることに依存しています。 緩和すると、無効な負の値または左側の値が減少し、すぐに並べ替えが壊れます。
