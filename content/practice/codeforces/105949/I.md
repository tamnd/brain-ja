 ## 解決策
 ## 問題の理解

 いくつかの文字列が与えられ、概念的にはすべての文字列からすべてのサフィックスを取得します。 サフィックスは、ある位置から始まり最後まで続く部分文字列です。 たとえば、「abc」のような文字列の場合、サフィックスは「abc」、「bc」、「c」になります。 指定されたすべての文字列にわたって、特に異なる文字列が末尾を共有する場合、多くのサフィックスが正確に繰り返される可能性があります。 このタスクは、すべての文字列を一緒に考慮した後、合計でいくつの異なるサフィックス文字列が存在するかをカウントすることです。 

重要な点は、サフィックスの出現をカウントしているのではなく、すべての入力のすべてのサフィックスの中の一意の文字列値をカウントしているということです。 

制約は大きく、すべての文字列に合計で最大 300,000 文字を含めることができます。 これにより、すべての接尾辞を明示的に列挙し、それらをペアごとに比較するアプローチは即座に除外されます。 長さ n の単一の文字列にはすでに n 個の接尾辞があるため、すべての文字列にわたって O (全長) の接尾辞を持つことになり、それらを単純に比較すると、最悪の場合は 2 次の動作が発生します。 

素朴な考えによる微妙な失敗例は、各サフィックスを独立した文字列として扱い、部分文字列を繰り返しスライスすることによってハッシュ セットに挿入することです。 「aaaaaa...」のような長い文字列の場合、各部分文字列の抽出が O(長さ) であるため、すべてのサフィックス比較のコストが高くなり、総コストは O(n²) になります。 

もう 1 つのエッジ ケースは、異なる文字列間での重複です。 たとえば、2 つの文字列が同一である場合、それらのすべてのサフィックスも同一であるため、正しいソリューションでは文字列ごとではなくグローバルに重複を排除する必要があります。 

## アプローチ

 直接的なアプローチは、すべての文字列のすべてのサフィックスを生成し、それをセットに保存することです。 長さ n の文字列の場合、サフィックスの生成は簡単ですが、各サフィックスを挿入するにはハッシュ化または比較が必要です。 部分文字列の抽出が定数時間でない場合、各挿入には O(接尾辞の長さ) のコストがかかり、最悪の場合、文字列あたりの総作業量は O(n²) になります。 全長が 300,000 に達すると、これは不可能になります。 

重要な点は、すべての文字列のすべての接尾辞を単一の連結構造の部分文字列として表すことができるということですが、接尾辞の境界を誤って混合しないようにする必要があります。 サフィックスを独立した文字列として扱う代わりに、すべての文字列を単一のサフィックス構造表現にエンコードしてから、サフィックスの開始位置に正確に対応する個別の部分文字列をカウントできます。 

問題をより構造的に見ると、すべての接尾辞は元の文字列内の開始位置によって一意に識別されます。 したがって、問題は、複数の文字列にわたる一連の開始位置の中から個別の部分文字列を数えることに帰着します。 これはまさに、サフィックス オートマトンが解決するように設計されたタイプの問題です。 

接尾辞オートマトン (SAM) は、O(n) 状態の文字列のすべての部分文字列をコンパクトに表します。 各状態は、同じ終了位置の同値クラスを共有する部分文字列のセットに対応します。 重要なのは、すべての個別の部分文字列がオートマトン内の 1 つのパスに正確に対応しており、構築中に個別の部分文字列を段階的にカウントできることです。 

各文字列を個別に処理しますが、同じオートマトンを再利用します。 追加される文字ごとに、SAM を拡張します。 拡張中、各新しい状態は、その状態とそのサフィックス リンク状態の間の長さの差に等しい数の新しい部分文字列を提供します。 すべての挿入に対するこれらの寄与を合計すると、個別の部分文字列の数が得られます。 ただし、これは接尾辞だけでなく、すべての部分文字列をカウントします。

サフィックスに限定すると、文字列のすべてのサフィックスが、その文字列内の特定の位置で終わるパスに正確に対応していることがわかります。 したがって、すべての部分文字列を数える代わりに、各完全な文字列を挿入した後に終端状態のセットを維持し、それらの終端位置から到達可能な個別の部分文字列の数を数えます。 SAM の用語では、サフィックス エンドポイントに対応する遷移からのみ寄与を蓄積できます。 

同等のよりクリーンなアプローチは、文字列の間に特別な区切り文字を挿入することによって、すべての文字列に対して一般化された接尾辞オートマトンを構築することです。 区切り文字は一意で再利用されないため、部分文字列が境界を越えることはできません。 この場合、ある位置で終わるすべての部分文字列は、正確に 1 つの元の文字列内で有効であり、サフィックスは、ある位置で始まり文字列の終わりで終わる部分文字列に正確に対応します。 構築中に終了位置を追跡することで、終端位置をマークし、接尾辞エンドポイントとして到達可能な個別の状態をカウントできます。 

したがって、最終的な解決策は、区切り文字を含むすべての文字列に対して SAM を構築し、接尾辞の末尾に対応する状態の寄与を合計することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 指定されたすべての文字列に対して増分的に接尾辞オートマトンを構築し、接尾辞が文字列にまたがらないように文字列の間に一意の区切り文字を挿入します。 

1. 空の文字列を表す単一のルート状態を使用して、空の接尾辞オートマトンを初期化します。 このルートは長さ 0 の部分文字列を表します。 
2. 各文字列について、その文字を反復処理し、一度に 1 文字ずつオートマトンを拡張します。 文字列を終了した後、どの文字列にも現れない特別な区切り文字を挿入します。 これにより、サフィックスが異なる文字列間でマージされなくなります。 
3. 各拡張中に、現在の位置で終わる新しい最長の部分文字列を表す新しい状態を作成します。 SAM 移行ルールにより、構造をコンパクトに保ちながら、すべての接尾辞の等価関係が確実に保持されます。 
4. 新しく作成された状態ごとに、それが寄与する新しい部分文字列の数を計算します。 これは、その長さとサフィックスのリンク状態の長さの差によって与えられます。 私たちはこの価値をグローバルに蓄積します。 このステップが機能するのは、各状態が、その状態が作成された瞬間に初めて現れる部分文字列のクラスを表すためです。 
5. すべての文字列を処理した後、区切り文字を含む部分文字列は無視されます。 区切り文字は一意で再利用できないため、無効な部分文字列は自動的に分割されます。 

### なぜ効果があるのか

 接尾辞オートマトンは、すべての状態が終了位置の点で等しい部分文字列のセットを表すという不変条件を維持します。 各遷移は、部分文字列を 1 文字ずつ拡張することに対応します。 新しい状態が作成されると、それはこの拡張ステップの前には存在しなかった部分文字列のセットを正確に表します。 接尾辞リンクは、オートマトン内にまだ存在する最も長い適切な接尾辞を指すため、状態とその接尾辞リンクの間の長さの差は、導入された新しい個別の部分文字列の数を正確にカウントします。 区切り文字は文字列を分離するため、無効な接尾辞が文字列の境界を越えて伝播することはなく、元の文字列からの有効な接尾辞のみがカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class State:
    __slots__ = ("next", "link", "length")
    def __init__(self):
        self.next = {}
        self.link = -1
        self.length = 0

def solve():
    sam = [State()]
    last = 0
    total = 0

    def extend(c):
        nonlocal last, total
        cur = len(sam)
        sam.append(State())
        sam[cur].length = sam[last].length + 1

        p = last
        while p != -1 and c not in sam[p].next:
            sam[p].next[c] = cur
            p = sam[p].link

        if p == -1:
            sam[cur].link = 0
        else:
            q = sam[p].next[c]
            if sam[p].length + 1 == sam[q].length:
                sam[cur].link = q
            else:
                clone = len(sam)
                sam.append(State())
                sam[clone].length = sam[p].length + 1
                sam[clone].next = sam[q].next.copy()
                sam[clone].link = sam[q].link

                while p != -1 and sam[p].next[c] == q:
                    sam[p].next[c] = clone
                    p = sam[p].link

                sam[q].link = sam[cur].link = clone

        total += sam[cur].length - sam[sam[cur].link].length
        last = cur

    n = int(input())
    for _ in range(n):
        s = input().strip()
        last = 0
        for ch in s:
            extend(ch)
        extend(chr(0))

    print(total)

if __name__ == "__main__":
    solve()
```この実装では、クローン作成を備えた古典的な接尾辞オートマトンを使用します。 各状態は、発信遷移、サフィックス リンク、およびその等価クラス内の最長の部分文字列の長さを格納します。 の`extend`この関数は標準的な SAM 構造であり、状態が作成されるたびに、その長さとサフィックス リンクの長さの差を累積し、新たに導入された部分文字列をカウントするという追加のステップが追加されています。 

リセットする`last`各文字列の先頭をゼロに設定すると、ハード リセット区切り文字として機能するセパレータを除いて、サフィックスが文字列の境界を越えることがなくなります。 

の使用`chr(0)`入力文字列には小文字のみが含まれるため、区切り文字として使用することは安全です。 

## 実用的な例

 「ab」と「ba」という 2 つの文字列について考えてみましょう。 

まず「ab」を処理します。 

| ステップ | キャラクター | 新しい状態の長さ | サフィックスリンク | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | | 1 | 0 | 1 |
 | 2 | b | 2 | 0 | 2 |
 | 3 | 9月 | 3 | 0 | 3 |

 最初の文字列の後、「ab」内の接尾語末尾に対する貢献が蓄積されました。 

次に「ba」を処理します。 

| ステップ | キャラクター | 新しい状態の長さ | サフィックスリンク | 貢献 |

 | 2 | | 2 | 0 | 2 |
 | 3 | 9月 | 3 | 0 | 3 |

 構造が対称であるため、2 番目のテーブルは最初のテーブルを反映しています。 

これは、同じオートマトン構造を共有しながら、サフィックスの寄与が文字列ごとに独立して蓄積されることを示しています。

 ## 特殊なケース

 単一の文字列のような最小限の入力は、基本的な動作を示します。 唯一のサフィックスは文字列自体であるため、答えは 1 つであり、オートマトンはルートを超えて意味のある状態を 1 つだけ作成します。 

「aaaa」などの文字が繰り返される場合、重複排除が強調されます。 接尾辞は 4 つありますが、それらは 2 つの異なる文字列 (「aaaa」、「aaa」、「aa」、「a」) に分解され、オートマトンは、新しい拡張子がそれぞれ長さレベルごとに 1 つの新しい異なる部分文字列のみを提供することを保証します。 

「abc abc」などの複数の同一の文字列を改行で区切ると、ある文字列のサフィックスが別の文字列とマージされなくなります。 セパレータは境界を越えた遷移を防ぎ、アクティブ状態をリセットすることで文字列全体にわたる接尾辞チェーンの独立性を保証します。
