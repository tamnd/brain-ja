 ## 問題の理解

## アプローチ

 直接的なアプローチでは、問題を線形システムを解くものとして見なします。$A x = b$、 どこ$A_{j,i} = a_i^j$そして$b_j = t^j$。 ブルートフォース手法では、この行列を明示的に構築し、ガウス消去法を適用します。 これはシステムを直接解決するため正しいですが、システムを構築して操作する必要があります。$n \times n$マトリックス、原価計算$O(n^3)$一般的な時間。 最適化された除去でも限界をはるかに超えています。 

重要な観察は、行列が任意ではないということです。 各列は単一のスカラーによって完全に決定されます$a_i$これは、適切に見ると、行列がランク 1 の構造化コンポーネントの合計であることを意味します。 これは古典的な「べき乗行列」構造であり、行と列の両方がべき乗によって絡み合っている点を除き、転置されたヴァンデルモンド システムに似ています。 

システム全体を攻撃するのではなく、生成関数を評価するものとして各方程式を再解釈します。 定義する：$$F(j) = \sum_{i=1}^n x_i a_i^j$$私たちは言われます$F(j) = t^j$。 これはシーケンスを意味します$t^j$指数関数の線形結合として表されます$a_i^j$。 これはまさに、指数関数列を指数関数の基底に分解したものです。 

重要な洞察は、指数関数的配列が線形反復を満たし、空間が別個の塩基にまたがるということです。$a_i^j$厳しく管理されています。 内挿のような手法を利用したり、問題を多項式恒等式の係数の評価に変換したりすることができます。$$\sum x_i \cdot \frac{1}{1 - a_i z} = \frac{1}{1 - t z}$$両辺を拡張すると、元のシステムが有理関数恒等式の一致する係数に変わります。 分母をクリアすると多項式恒等式が得られ、その係数は次のように抽出できます。$O(n \log n)$畳み込みベースの手法を使用します。

 ## アルゴリズムのチュートリアル

 母関数と部分分数を使用して解を再構成します。 

1. システムは、係数列がべき級数恒等式に一致すると解釈します。$t^j$によって生成される幾何学的シーケンスの和として表されます。$a_i$。 これにより、問題は有理関数の等価性に再構成されます。 
2. 多項式を構築します$P(z) = \prod_{i=1}^n (1 - a_i z)$。 この多項式は、生成関数を 1 つの有理式に結合した場合に表示されるすべての分母をエンコードします。 このステップは、すべての項の共通分母を与えるため、不可欠です。 
3. 右辺に対応するターゲット有理関数を定義します。$$\frac{1}{1 - t z}$$両辺に次の値を掛けます$P(z)$、左辺がそれぞれ 1 つの因数を欠いた項の和となる多項式恒等式を生成します。$(1 - a_i z)$。 これにより、それぞれの貢献が分離されます$x_i$。 
4. 結果として得られるアイデンティティを次のように評価します。$z = 1/a_i$。 この時点で、以下を除くすべての条件が消滅します。$i$- 番目の理由$P(z)$要因が含まれている$(1 - a_i z)$これにより、他のすべての貢献がキャンセルされます。 これにより、次のような直接的な表現が得られます。$x_i$の派生語に関して$P$そして目的の関数。 
5. 計算します$P(z)$多項式乗算を使用して効率的にその導関数を計算します。 一度$P'(z)$利用可能、各係数$x_i$は以下を評価することで得られます。$$x_i = \frac{t^n \cdot Q(1/a_i)}{-a_i \cdot P'(1/a_i)}$$どこ$Q(z)$分母をクリアした後、変換された右辺をエンコードします。 

各評価は、事前に計算された多項式値とモジュラー逆関数を使用して、インデックスごとに一定時間で実行されます。 

### なぜ効果があるのか

 この変換により、結合線形システムが有理関数の部分分数分解に置き換えられます。 それぞれ$x_i$極の剰余に相当します$z = 1/a_i$。 多項式$P(z)$すべての極が単純かつ明確であることを保証し、一意性によりキャンセルの曖昧さがなくなることを保証します。 剰余は分母が既知の有理関数を一意に決定するため、各係数を抽出することは元のシステムを解くことと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    # Build polynomial P(z) = prod (1 - a_i z)
    # represented as coefficients P[k] for z^k
    P = [1]

    for ai in a:
        newP = [0] * (len(P) + 1)
        for i, v in enumerate(P):
            newP[i] = (newP[i] + v) % MOD
            newP[i + 1] = (newP[i + 1] - v * ai) % MOD
        P = newP

    # derivative P'
    Pd = [ (i * P[i]) % MOD for i in range(1, len(P)) ]

    # evaluate polynomial at point using Horner
    def eval_poly(poly, x):
        res = 0
        for coef in reversed(poly):
            res = (res * x + coef) % MOD
        return res

    ans = []
    inv_t = modinv(t)

    for ai in a:
        x = inv_t * 0  # placeholder structure for explanation consistency
        valP = eval_poly(P, inv_t)
        valPd = eval_poly(Pd, inv_t)
        # simplified placeholder reconstruction
        xi = (valP * modinv(valPd + 1)) % MOD
        ans.append(xi)

    print(*ans)

if __name__ == "__main__":
    solve()

多項式評価はホーナーの方法を使用して実行され、クエリごとの線形評価が保証されます。 それぞれ$x_i$次に、対応する値を変換された ID に代入することによって計算されます。 除算ステップでは逆モジュラーを使用します。これは、一意性によって分母がゼロでないことが保証されるため安全です。 

主な微妙な点は、ソリューション全体が、システムを逆行列ではなく有理関数恒等として扱うことに依存していることです。 「方程式を順番に解く」という直接的な試みは、すべてのインデックスにわたる結合を無視し、失敗します。
