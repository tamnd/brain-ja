 ## 問題の理解

 完全な有向グラフが与えられます。$n$頂点のすべてのペアの間に有向エッジが 1 つだけ存在し、トーナメントを形成するラベル付き頂点。 このようなすべてのトーナメントの中で、正確な長さの指示された単純なサイクルが少なくとも 1 つ含まれるトーナメントがいくつあるかを数える必要があります。$k$。 長さのサイクル$k$選択できることを意味します$k$個別の頂点を作成し、連続する各ペアが有向エッジに従い、最後の頂点が最初の頂点を指すように順序付けします。 

入力は 2 つの整数で構成されます$n$そして$k$。 出力は、ラベル付きトーナメントの数です。$n$少なくとも 1 つのそのような頂点を含む頂点$k$-cycle、モジュロ 998244353 を取得します。 

のトーナメント$n$頂点には$2^{\binom{n}{2}}$これは、順序付けされていないすべてのペアが方向の 1 つの独立したバイナリ選択に寄与するためです。 これは非常に急速に増加するため、どのソリューションでもグラフを直接列挙することは避けなければなりません。 

この制約は、頂点のサブセットの反復や各トーナメント内のサイクルの明示的なチェックに依存する解決策は不可能であることを示唆しています。 単一のトーナメントの処理でも指数関数的に処理されます。$n^2$, したがって、視点を個々のグラフからトーナメントの構造特性に移す必要があります。 

単純な間違いは、すべてをチェックしようとすることです。$k$-頂点のサブセットと、それに有向サイクルが含まれているかどうかを確認します。 固定サブセットの場合、これは管理可能ですが、$\binom{n}{k}$サブセットは大きすぎます$n$まで$10^5$。 

2 番目の微妙な落とし穴は、「いいえ」と考えるときに現れます。$k$-cycle」は、例のように「サイクルがまったくない」ように動作する可能性があります$k=3$。 のために$k=3$、唯一のサイクルフリー トーナメントは推移的なトーナメントであり、そのカウントは正確に$n!$。 ただし、より大きな場合には、$k$、トーナメントには、より長いサイクルを避けながら三角形が含まれる場合があるため、構造はより複雑になります。 

具体的な例を挙げると、次のようなときです。$n=3, k=3$、答えは$2^3 - 3! = 8 - 6 = 2$。 But for$k=4$, a tournament on 4 vertices may contain a 3-cycle while still having no 4-cycle, so simply subtracting acyclic cases is insufficient.

 ## アプローチ

 The brute-force perspective is to iterate over all tournaments and check whether a$k$-cycle exists. あるので$2^{\binom{n}{2}}$トーナメントでは、サイクル検出を試みる前にこれはすでに実行不可能です。 

次のステップは、問題を逆転させることです。 を含むトーナメントを数える代わりに、$k$-cycle、何も含まないものをカウントします。$k$-サイクルしてトーナメントの総数から減算します。 

重要な構造的洞察は、強く結びついたコンポーネントを通じてトーナメントを観察することです。 すべてのトーナメントは、強く接続されたコンポーネントのトポロジカルな順序に一意に分解でき、コンポーネント間のエッジは常に 1 つの一貫した方向に向けられます。 各コンポーネント内では、すべての頂点が他のすべての頂点に到達でき、トーナメントの古典的な特性は、強く接続されたトーナメントがすべてのコンポーネントに存在することを意味します。$m$頂点には、3 から 3 までのすべての長さの有向サイクルが含まれます。$m$。 

これは重要な等価性を意味します。トーナメントには長さの指示されたサイクルがありません。$k$少なくともサイズの強く関連したコンポーネントがない場合に限ります$k$。 このようなコンポーネントがあった場合、そのコンポーネントには自動的に長さのサイクルが含まれることになります。$k$。 逆に、すべてのコンポーネントのサイズが最大でも$k-1$、その場合、サイクルはまたがることができません$k$頂点。 

したがって、補数の問題は、SCC サイズがすべて次の範囲に制限されているトーナメントをカウントすることになります。$k-1$。 

ここで、そのようなトーナメントを構造的に説明します。 各トーナメントは、SCC に設定された頂点の順序付けられたパーティションに対応し、各ブロックは強く接続されたトーナメントです。 ブロック間では、すべてのエッジが順序に従って一方向に進みます。 

させて$g[m]$強く結びついたトーナメントの数を示します$m$ラベル付きの頂点。 次に、SCC 分解がブロック サイズを持つトーナメントの数$s_1, s_2, \dots, s_t$は：$$\frac{n!}{s_1! s_2! \cdots s_t!} \cdot g[s_1] g[s_2] \cdots g[s_t]$$すべての構成を合計します$n$それぞれと$s_i \le k-1$。 

最後に、答えは次のとおりです。$$2^{\binom{n}{2}} - \text{(number of tournaments with all SCC sizes } < k)$$残りのタスクはコンピューティングです$g[m]$効率的に。 これは、強くないトーナメントには重要なカットがあるという事実を利用して、トーナメントが強く結びついていないあらゆる方法に対して包含-排除によって行われます。$(S, V \setminus S)$すべてのエッジを一方向に向けます。 これにより、次のように計算できる標準的な再帰が得られます。$O(n^2)$、コンポーネント サイズに対する最終的な DP は次のように切り捨てられます。$k-1$、畳み込みが可能になります。

 ## アルゴリズムのチュートリアル

 私たちは、グローバルなカウントから始まり、構造化された分解で終わる、レイヤーでソリューションを構築します。 

1. トーナメントの合計数を計算します。$n$頂点として$2^{\binom{n}{2}}$。 これは、差し引く対象となる宇宙全体を表します。 
2. 少なくとも規模に強く関連する要素がないトーナメントをカウントするように目標を再定式化する$k$。 これにより、必然的に含まれるすべての構成が削除されます。$k$-サイクル。 
3. 事前計算$g[m]$、強く結びついた規模のトーナメントの数$m$。 強く関連性のないトーナメントを除いたすべてのトーナメントからこの値を導き出します。 
4. 計算するには$g[m]$、自明でないサブセットが存在する場合、トーナメントは強く結びついていないことに注目してください。$S$すべてのエッジが$S$に$V \setminus S$。 このようなカットを列挙し、ソース セットのサイズに対する包含を使用して寄与を差し引きます。 これにより、より小さい値のみに基づいて反復が生成されます。$g$。 
5. DP アレイを構築する$dp[i]$有効なトーナメントの数を意味します$i$すべての SCC サイズが最大である頂点$k-1$。 初期化する$dp[0] = 1$。 
6.各サイズについて$i$、最初の SCC ブロックのサイズを選択して拡張します$s$1から$k-1$、乗算:

 頂点を選択する方法の数、

 強く結びついたトーナメントの数$s$頂点、

 そして残りを整理する方法$i-s$頂点。 
7. すべての有効な分解を合計して、$dp[n]$。 
8. 出力$2^{\binom{n}{2}} - dp[n]$。 

### なぜ効果があるのか

 すべてのトーナメントには、完全な順序で配置された、強く結びついたコンポーネントが独特に凝縮されています。 この構造は厳格です。SCC が固定されると、すべてのコンポーネント間のエッジが強制されます。 したがって、トーナメントのカウントは、各ブロック内の強く接続されたトーナメントの数によって与えられる重みを持つ SCC の順序付けられたシーケンスをカウントすることになります。 SCC サイズの境界$k-1$長さのサイクルが存在しないことを正確に強制します$k$なぜなら、より大きな SCC にはそのようなサイクルが自動的に含まれるからです。 これにより、補数のカウントが近似値ではなく正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    r = 1
    while e:
        if e & 1:
            r = r * a % MOD
        a = a * a % MOD
        e >>= 1
    return r

def solve():
    n, k = map(int, input().split())

    total = modpow(2, n * (n - 1) // 2)

    if k == 2:
        print(0)
        return

    max_s = k - 1

    # g[m] = strongly connected tournaments count
    g = [0] * (n + 1)
    g[0] = 1

    pow2 = [1] * (n * (n - 1) // 2 + 1)
    for i in range(1, len(pow2)):
        pow2[i] = pow2[i - 1] * 2 % MOD

    # precompute binomial via multiplicative formula
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = modpow(fact[n], MOD - 2)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    # compute g[m] via inclusion over non-strong tournaments
    for m in range(1, n + 1):
        total_m = pow2[m * (m - 1) // 2]
        bad = 0

        # subset S is "source side" in a cut
        for s in range(1, m):
            ways = C(m, s)
            ways = ways * pow2[s * (s - 1) // 2] % MOD
            ways = ways * pow2[(m - s) * (m - s - 1) // 2] % MOD
            bad = (bad + ways) % MOD

        g[m] = (total_m - bad) % MOD

    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        for s in range(1, min(i, max_s) + 1):
            ways = C(i - 1, s - 1)
            ways = ways * g[s] % MOD
            ways = ways * dp[i - s] % MOD
            dp[i] = (dp[i] + ways) % MOD

    ans = (total - dp[n]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、高速累乗を使用してトーナメントの総数を計算します。 次に、頂点を SCC ブロックに分割するために必要な組み合わせの階乗テーブルを構築します。 

配列`g[m]`は、すべてのトーナメントからのカットベースの減算を使用して計算され、方向性の分離を許容する構造から強く接続された構造を区別します。 その後、`dp[i]`SCC ブロックのサイズが以下に制限されているすべてのトーナメントを構築します$k$、標準の順序付きセット パーティション DP を使用します。 

微妙なポイントは組み合わせの使用です$C(i-1, s-1)$これは、同一のブロック構造の順列の過剰カウントを避けるために、1 つの頂点を最初の SCC ブロックの最初の要素として固定します。

 ## 特殊なケース

 いつ$k > n$、トーナメントに以下を含めることはできません。$k$-cycle は単純に頂点が足りないためです。 この場合の DP はすべてのトーナメントをカウントし、それを引くとゼロになります。これは、すべてのトーナメントがそのようなサイクルを自明に回避しているという事実と一致します。 

いつ$k = 3$、SCC 制限は、すべてのコンポーネントがサイズ 1 であることを要求するようになり、推移的なトーナメントのみが強制されます。 アルゴリズムは正しく減算を行います$n!$から$2^{\binom{n}{2}}$、非周期トーナメントの既知の特徴と一致します。 

のために$n = k$、DP はちょうど 1 つのサイズのブロックを許可します$k$で重み付けされます。$g[k]$。 強く結びついたトーナメント以来、$k$頂点には$k$-cycle、これは答えに寄与する構成を正確にカウントし、そのようなコンポーネントが存在するトーナメントが減算によって正確に削除されることを保証します。
