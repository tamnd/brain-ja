 ## 解決策
 ## 問題の理解

 私たちは、0 から N までの整数に基づいて発展するシステムを検討しています。現在の状態 x から、何か他のことが起こる前に、毎秒 1 つの決定が与えられます。 

パッシブ オプションを選択した場合、状態は 1 秒後に x から x − 1 に決定的に移行するだけです。 

アクティブなオプションを選択した場合、最初に特別なセット S(x) から均一に選択されたランダムな状態にジャンプし、そのジャンプ後にのみ同じ強制 1 減少が適用されます。 

セット S(x) は 2 つのソースから構築されます。 これには、x のすべての約数が含まれており、1 から N の範囲内にある x のすべての倍数も含まれています。したがって、S(x) には、「現在位置の係数」と「制限されたユニバース内の到達可能な倍数」が混合されます。 

目標は、特定の x から開始して、最終的に状態 0 に到達するまでに必要な予想秒数を最小限に抑えることです。 各クエリはこの最適な期待時間を個別に要求しますが、構造はすべての x に対して同じシステムです。 

制約は N, Q ≤ 100000 までです。これは、クエリごとに遷移や期待値を再計算するソリューションが実行不可能であることを直ちに意味します。 状態空間は高密度であるため、合計前処理がおよそ O(N log N) よりも悪いものは制限時間内に失敗し始めます。 

微妙な点は、ランダムな選択の後に遷移が直接 y に移動するのではなく、各秒の終わりに必須のデクリメントがあるため y − 1 に移動することです。 これにより、すべてのトランジションが 1 つずつシフトされ、オフバイワンの間違いの最も一般的な原因になります。 たとえば、x = 2 から除数遷移を選択すると、サンプリングされた値に応じて、1 秒後に 1 または 0 になる可能性があります。 

エッジケースは小さな x に表示されます。 x = 1 では、S(1) には 1 のみが含まれるため、ランダムな選択は退化し、両方のアクションは事実上同様に動作します。 S(x) が常に空ではないことを忘れると、DP 反復が誤って無効な状態を仮定する可能性があります。 

## アプローチ

 直接シミュレーションでは、各状態 x のすべての遷移を明示的にモデル化します。 各 x について、S(x) を計算し、ゼロに達するまで選択を繰り返してシミュレーションし、期待値を推定します。 シミュレーションを動的プログラミングに置き換えたとしても、単純な構造では依然として大きな遷移セットを繰り返しスキャンする方法で期待値を再計算することになります。 S(x) にはすべての約数と倍数が含まれるため、x から N までのすべての S(x) の合計サイズは N log N のオーダーとなり、状態ごとに不注意に再計算するとこれを N 倍することになり、これはあまりにも大きすぎます。 

重要な観察は、このプロセスが固定有向システム上の最短期待 DP であり、各状態には 2 つの可能なアクションしかないということです。 1 つのアクションは前の状態 x − 1 のみに依存し、もう 1 つは事前計算可能な近傍 S(x) の平均に依存します。 これは、E[x] が既に計算されたより小さい値のみに依存する順方向 DP を直ちに示唆します。 

残る唯一の困難は、S(x) の平均を効率的に計算することです。 約数の部分は、標準的なふるいのようなループを使用して合計 O(N log N) 個の約数を列挙することで累積できます。 各 x の倍数を反復することにより、倍数部分を同様の調和系列の複雑さに累積することもできます。 

すべての x に対して S(x) がリストとして事前計算されると、すべてのターゲットが y − 1 (y ≤ x) または乗算の場合 y < x のいずれかであるため、ランダム アクションの期待値を既知の DP 値の単純平均として計算できます。 

これにより、事前に計算された遷移リストを使用した 1 対 N にわたるクリーンな DP に問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N²) 以上 | O(N) | 遅すぎる |
 | 事前計算された S(x) を使用した DP | O(N log N) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 E[x] を、状態 x から開始して 0 に到達するまでの最小予想時間として定義します。

すべての依存関係が必要なときにすでに利用できるように、E を 0 から N まで昇順に計算します。 

1. すでに目標状態に達しており、時間は必要ないため、E[0] = 0 を初期化します。 
2. すべての約数と N までのすべての有効な倍数を収集することにより、1 から N までのすべての x について S(x) を事前計算します。これにより、各状態の可能なランダムな宛先の完全なセットが構築されます。 
3. 1 から N までの各 x について、受動的アクションの値を計算します。 1 秒が経過すると状態は確定的に x − 1 に移行するため、これは単純に 1 + E[x − 1] になります。 
4. アクティブなアクションについて、S(x) に対する期待値を計算します。 S(x) のすべての y について、丸 1 秒後の状態は y − 1 になるため、寄与は E[y − 1] になります。 これらの値を平均すると、ランダム ジャンプを選択する場合の予想コストが求められます。 
5. 2 つのアクションの最小値を取得し、E[x] = 1 + min(passive_value − 1, active_value − 1) を同等に割り当てるか、より直接的に、1 秒あたりの +1 を含む両方の完全な式を一貫して計算します。 

より明確な定式化は、両方のオプションを 1 秒あたりの全コストとして計算し、小さい方を選択することです。 

1. すべての x について E[x] を計算した後、E[x] を出力することで各クエリに直接答えます。 

なぜそれが機能するかは、単調な依存構造に関係しています。 すべての状態 x は状態 y − 1 にのみ依存します。ここで、約数の場合は y ≤ x、倍数の場合は y ≤ x であるため、すべての依存関係は以前に計算された DP 値を指します。 このシステムには DP 次数に関するサイクルがなく、各状態が 2 つの決定論的コスト関数を正確に評価するため、局所的に最小値を選択することで全体的な最適な期待値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, Q = map(int, input().split())
    
    divs = [[] for _ in range(N + 1)]
    mults = [[] for _ in range(N + 1)]
    
    for i in range(1, N + 1):
        for j in range(i, N + 1, i):
            mults[i].append(j)
            divs[j].append(i)
    
    S = [[] for _ in range(N + 1)]
    for x in range(1, N + 1):
        S[x] = divs[x] + mults[x]
    
    E = [0.0] * (N + 1)
    
    for x in range(1, N + 1):
        # option 1: do nothing
        cost_stay = 1.0 + E[x - 1]
        
        # option 2: random jump
        total = 0.0
        for y in S[x]:
            total += E[y - 1]
        cost_jump = 1.0 + total / len(S[x])
        
        E[x] = min(cost_stay, cost_jump)
    
    for _ in range(Q):
        x = int(input())
        print(E[x])

if __name__ == "__main__":
    main()
```DP 配列 E には、各状態の最適な予想時間が格納されます。 受動的アクションは、直前のアクションにのみ依存するため、簡単です。 アクティブなアクションは S(x) にわたって集計され、重要な実装の詳細はインデックス付けにおける 1 つのシフトです。アクション後の必須のデクリメントにより、サンプリングされたすべての y は y − 1 に遷移します。 

div と mult の構築により、S(x) が合計でおよそ O(N log N) になるように構築されます。これは、100000 までの N には十分です。 

## 実用的な例

 N = 3 の小さな例を考えてみましょう。 

次のように S セットを構築します。 結合後は概念的には S(1) = {1, 1, 2, 3} が {1, 2, 3} になります。 S(2) には約数 {1, 2} と倍数 {2} が含まれているため、実質的には {1, 2} になります。 S(3) には約数 {1, 3} と倍数 {3} が含まれるため、{1, 3} になります。 

E を順番に計算します。 

| × | S(x) | 滞在費 | コストジャンプ | E[x] |
 | --- | --- | --- | --- | --- |
 | 1 | {1,2,3} | 1 + E[0] = 1 | 平均(E[0],E[1],E[2]) + 1 | 分 |
 | 2 | {1,2} | 1 + E[1] | 1 + 平均(E[0],E[1]) | 分 |
 | 3 | {1,3} | 1 + E[2] | 1 + 平均(E[0],E[2]) | 分 |

 このトレースは、各状態が以前に計算された値のみにどのように依存するかを示しており、順方向 DP 順序で十分であることが確認されています。 

ここで、縮退ケース N = 1 を考えてみましょう。 

| × | S(x) | 滞在費 | コストジャンプ | E[x] |
 | --- | --- | --- | --- | --- |
 | 1 | {1} | 1 + E[0] | 1 + E[0] | 1 |

 ランダムな選択が強制されるため、両方のアクションが一致します。これは、DP がシングルトン遷移セットを正しく処理することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | 各数値は、高調波系列の動作ごとに 1 回、除数と複数の列挙に寄与します。 
| スペース | O(N log N) | すべての状態にわたる S(x) リストの保存 |

 前処理コストは N = 100000 で許容可能であり、各クエリは O(1) で応答されます。 DP 自体は、前処理後の状態にわたって線形順序で実行されるため、ソリューションは制限内に問題なく適合します。

 ## 特殊なケース

 x = 1 では、S(1) はシングルトン構造に崩壊します。 DP は、唯一のサンプリング値 y = 1 が状態 0 にマップされるため、cost_stay = 1 + E[0] およびcost_jump = 1 + E[0] を計算します。両方の選択が一致するため、アルゴリズムは曖昧さなく一貫して E[1] = 1 を割り当てます。 

x = 12 のような高度に合成された数では、多くの約数と複数の有効な倍数の両方により S(x) が大きくなります。 y ≤ 12 に必要なすべての E[y − 1] 値が以前の反復ですでに計算されているため、実装はこれを正しく処理します。そのため、平均は明確に定義され、安定しています。 

N に近い素数では、S(x) は {1, x} といくつかの倍数によって支配されており、DP は単純な線形フォールバック 1 + E[x − 1] と比較することによって、ジャンプが有益かどうかのバランスを正しくとります。
