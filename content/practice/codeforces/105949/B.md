 ## 解決策
 ## 問題の理解

 私たちには、長さの 3 進数の数字を 1 桁ずつ処理する、隠された「暗号化システム」が与えられています。$n$。 それぞれのポジションで$i$、固定された順列があります$f_i$数字の$\{0,1,2\}$。 数値が暗号化されると、各桁はその位置の順列を使用して個別に置き換えられます。 

複雑なのは、順列を直接見ることができないことです。 代わりに、2 つの暗号化された 3 値文字列で構成されるクエリを送信できます。$a$そして$b$。 システムは、未知のマッピングを使用してそれらを復号化し、結果として得られる単純な 3 進数 (基数 3 のキャリー付き) を加算し、結果を 1 桁ずつ再暗号化します。 

正式に言うと、$f^{-1}(a)$そして$f^{-1}(b)$は復号化された値であり、裁判官はそれらの合計を基数 3 で計算し、適用します。$f$再び各桁に個別に入力します。 キャリーはポジション間の相互作用の唯一の源です。 

タスクはすべての順列を復元することです$f_i$このようなクエリは最大 2 つ使用します。 

主な問題点は、加算により桁上げ伝播が発生し、一般に位置を結合することです。 キャリーを制御せずに数字を 1 つずつ推測しようとする単純なアプローチは、低い位置に関する 1 つの間違った仮定が高い位置すべてに影響を与えるため、すぐに信頼できなくなります。 

制約は大きいです:$n$まで可能です$10^5$、まであります$10^4$全長が最大のテストケース$10^6$。 これは、どのソリューションも各テスト ケースを線形時間で処理し、一定数の対話型クエリのみを実行する必要があることを意味します。 位置ごとの適応クエリに依存する戦略は不可能です。 

素朴な推論が微妙に失敗するケースは、観察された出力桁が固定入力桁に直接対応すると仮定することです。 たとえば、単一の位置を異なる分離パターンでクエリしようとした場合、慎重にキャリーをゼロに強制しない限り、隣接する位置からのキャリーによって結果が汚染されてしまいます。 

## アプローチ

 ブルートフォース的な考え方では、各順列を決定しようとするでしょう。$f_i$位置を分離することで独立して$i$。 他の数字を固定したまま、1 つの数字だけに影響を与えるクエリを構築しようとする場合があります。 問題は、下位のゼロ以外の数字が 1 つでも、上位のすべての位置を変更するキャリーを生成する可能性があり、分離が高価で脆弱になることです。 最悪の場合、これは次のような事態につながります。$O(n)$位置ごとのクエリ、または合計 2 つのクエリという制限の下では不可能な適応実験。 

重要な観察は、実際には複雑なキャリー制御を使用してポジションを分離する必要がないということです。 キャリーがまったく発生しないことを確認するだけで済みます。 すべての桁ごとの加算が独立していることが保証できれば、各位置は単純な置換暗号のように動作します。 

基数 3 のキャリーは、合計が 3 以上になる数字を加算する場合にのみ発生します。これは、数字 0 と 1 のみに制限すると、解読された数字は依然として 0 または 1 であり、その合計が最大 2 であるため、未知の順列に関係なく、キャリーは決して現れないことをすぐに示唆しています。 

これにより、対話型システムを純粋に位置ごとの観察ツールに変えることができます。 各クエリは、独立した桁ごとの評価のベクトルになります。$f_i(x)$、 どこ$x$は、その位置の復号化された数字の合計です。 

慎重に選択した 2 つのクエリを使用して、これを利用できます。 

最初のクエリでは、すべてゼロの暗号化された 2 つの数値が使用されます。 復号化後は、両方の入力がすべてゼロになるため、すべての位置が計算されます。$0 + 0 = 0$、出力数字を生成します$f_i(0)$独立して。 

2 番目のクエリでは、すべて 1 で暗号化された数値が 1 つと、すべて 0 で暗号化された数値が 1 つ使用されます。 復号化後、すべての位置が計算されます$1 + 0 = 1$、やはりキャリーなしで、出力桁を生成します$f_i(1)$。 

わかったら$f_i(0)$そして$f_i(1)$、の残りの桁$\{0,1,2\}$でなければなりません$f_i(2)$。

 ## アルゴリズムのチュートリアル

 1. 2 つの長さを構築します。$n$完全に以下から構成される 3 項文字列`'0'`。 それらをクエリして結果文字列を受け取ります$c^{(0)}$。 各キャラクター$c^{(0)}_i$まさに$f_i(0)$なぜなら、どのポジションもキャリーを経験しないからです。 
2. すべての文字列を構築します`'1'`そして、それをすべてゼロの文字列と組み合わせます。 問い合わせて受け取る$c^{(1)}$。 各キャラクター$c^{(1)}_i$まさに$f_i(1)$同じ理由で、すべての桁はキャリーなしで独立して 1 に加算されます。 
3. ポジションごとに$i$、 決定する$f_i(2)$唯一の数字として$\{0,1,2\}$に登場しない$\{f_i(0), f_i(1)\}$。 
4. すべての順列を文字列として順番に出力します。 

これが機能する主な理由は、すべての桁の合計が最大 1 になるように意図的に制限しており、キャリーの伝播を防止しているためです。 これにより、すべてのクロスポジションインタラクションが削除され、インタラクティブシステムが縮小されます。$n$独立したローカル関数。 

### なぜ効果があるのか

 キャリーが除去されると、各ポジションは独立したチャネルのように動作します。 暗号化は加算後の位置ごとに独立して適用されるため、復号化された加算でキャリーが生成されない場合、位置の出力は$i$の値のみに依存します$f_i^{-1}(a_i) + f_i^{-1}(b_i)$。 から入力を選択することで、$\{0,1\}$ただし、その合計が 1 を超えることはないため、各位置のマッピングは他の位置からの干渉なしに直接明らかになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(a, b):
    print("?", a, b)
    sys.stdout.flush()
    return input().strip()

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())

        a0 = "0" * n
        a1 = "1" * n
        a2 = "0" * n

        # first query: 0 + 0
        c0 = ask(a0, a2)

        # second query: 1 + 0
        c1 = ask(a1, a2)

        res = []
        for i in range(n):
            used = {c0[i], c1[i]}
            for ch in "012":
                if ch not in used:
                    res.append(ch)
                    break

        print("!", "".join(res))
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```最初のクエリは、次のベクトル全体を構築します。$f_i(0)$。 両方のオペランドがゼロであるため、桁上げを生成できない桁位置があるため、返される文字列はゼロの位置ごとの直接マッピングになります。 

2 番目のクエリは同じ構造を繰り返しますが、単一の単位数字をあらゆる場所に挿入します。 加算する前はすべての桁が 1 または 0 であるため、合計が 3 になることはなく、キャリーは依然として不可能です。 これにより、出力のエンコードが保証されます。$f_i(1)$独立して。 

最後に、各順列の再構築は純粋に集合完了です。3 つの要素にわたる全単射の 2 つのイメージがわかれば、3 番目のイメージが一意に決定されます。 

## 実用的な例

 次の小さな例を考えてみましょう$n = 3$。 隠れたマッピングが位置ごとの任意の置換であると仮定します。 

最初のクエリの場合:

 | ステップ | 位置 0 | 位置 1 | 位置 2 |
 | --- | --- | --- | --- |
 | |を入力してください 0 | 0 | 0 |
 | 入力 b | 0 | 0 | 0 |
 | 復号化された合計 | 0 | 0 | 0 |
 | 出力 | f0(0) | f1(0) | f2(0) |

 これにより、各順列の 1 つの画像が明らかになります。 

2 番目のクエリの場合:

 | ステップ | 位置 0 | 位置 1 | 位置 2 |
 | --- | --- | --- | --- |
 | |を入力してください 1 | 1 | 1 |
 | 入力 b | 0 | 0 | 0 |
 | 復号化された合計 | 1 | 1 | 1 |
 | 出力 | f0(1) | f1(1) | f2(1) |

 ここで、各順列は除外によって決定されます。 

これら 2 つのトレースは、キャリーが回避されると、システムが独立したポジションごとの関数に完全に分解されることを示しています。

 ## 特殊なケース

 潜在的な懸念は、数字 0 と 1 だけを使用している場合でもキャリーが予期せず発生する可能性があるかどうかです。たとえば、位置合わせが間違っていると仮定したり、誤って上位の数字を導入した場合、キャリーが伝播し、上位のすべての位置が破損します。 この構築では、両方のクエリにすべてのローカル合計を 3 未満に保つ数字のみが含まれるようにすることで、これを完全に回避します。 

もう 1 つの微妙なケースは、立場の独立性を誤解していることです。 暗号化は位置ごとに行われますが、加算はそうで​​はありません。 このソリューションでは、桁セットを制限することで加算が効果的に無効化されるため、隠れた相互作用が残らないようになります。 

のために$n = 1$、システムは単一の順列に縮小されます。 最初のクエリは直接返します。$f_0(0)$、2番目が戻ります$f_0(1)$と答えればすぐに答えが得られます。
