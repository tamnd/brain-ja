 ## 解決策
 ## 問題の理解

 無限整数グリッド上の点とターゲット点が与えられます。 1 回の移動で、トークンは「ナイトのような、しかし斜めに偏った」パターンでステップすることによってその位置を変更できます。両方の座標が同時に変化し、許可される絶対ステップ ペアは (1,1)、(2,2)、(1,2)、または (2,1) で、すべての符号の組み合わせが含まれます。 各移動では、x と y が常に同時にシフトされるという事実が維持されますが、必ずしも同じ大きさである必要はありません。 

タスクは、各クエリの開始点をターゲット点に変換するために必要な最小移動数を計算することです。 最大 100 万のクエリが存在し、座標の大きさは 10^9 に達する可能性があるため、クエリごとに一定時間のソリューションが必要です。 たとえ小さな拡張でも境界のないグリッドに成長するため、BFS または状態検索は直ちに不可能になります。 

最初の構造的観察は、相対的な変位のみが重要であるということです。 dx = |X − x| と定義すると、 dy = |Y − y| の場合、問題は次のようになります。(0,0) から開始して、両方の座標が同時に変化する許容移動を使用して (dx, dy) に到達します。 

単純なアプローチでは、動きをシミュレートしたり、最初に 1 つの座標を貪欲に減らそうとしたりする可能性があります。 これは、移動が両方の軸を結合するため失敗します。 dx を貪欲に減らすと、最適なパリティに対して dy が過剰に増加し、後で追加の修正が強制される可能性があります。 たとえば、(2,1) を繰り返し移動すると、移動タイプを混合する場合と比較して、より小さな寸法でオーバーシュートし、ステップが無駄になる可能性があります。 

dx と dy が小さい場合、より微妙なエッジ ケースが発生します。 たとえば、(0,0) から (1,1) まで、答えは 1 です。ただし、(0,0) から (1,0) までは到達不可能ということは当てはまりません。両方の座標をいつでも一緒に変更できますが、軸を分離することはできないため、不均衡のある構成は異なる動作をするため、慎重に扱う必要があります。 

主な難点は、このムーブ セットでは 2 つの異なる「対角速度」が許可されていることです。(1,1) のようなタイトな対角のムーブと、(2,1) のような引き伸ばされた対角のムーブです。 これは、答えが主に max(dx, dy)、min(dx, dy)、およびそれらのパリティ関係に依存することを示唆しています。 

## アプローチ

 ブルート フォース戦略では、各状態 (x、y) をグラフ内のノードとして扱い、最初からターゲットに到達するまで BFS を実行します。 各ノードには、符号の選択により最大 8 つの発信エッジがあります。 それは正しいのですが、k ステップ内で到達可能な状態の数は k で指数関数的に増加し、10^9 までの適度な距離でもこれは完全に不可能になります。 

重要な観察は、問題が対称的でスケールに依存しないということです。 dx と dy のみが重要であり、最適な戦略は常に両方の座標を可能な限り一緒に減らし、残った不均衡を修正することです。 移動は (2,2) のような進行と (2,1) のような非対称の対角補正の両方を可能にするため、最適な答えは、1 つの座標が優勢であるかどうか、およびそれらの差が完全な対角ステップを無駄にすることなく解決できるほど十分小さいかどうかによって異なります。 

私たちは、dx ≥ dy または dy > dx に基づいて問題を幾何学的ケースの小さなセットに還元し、次に適用できる「効率的なペア削減」の数を分析します。 小さい座標が使い果たされると、残りの移動は、制約された対角操作の下で単一の軸上の点に到達するかのように動作し、小さな定数の場合の補正に崩壊します。

 ## アルゴリズムのチュートリアル

 dx = |X − x| のみを扱います。 dy = |Y − y| であり、必要に応じて交換後は dx ≥ dy と仮定します。

1. dx と dy を絶対座標差として計算します。 dx < dy の場合は、dx の方が大きい値になるようにそれらを入れ替えます。 この正規化により、すべてのケースが単一の幾何学的方向に縮小されます。 
2. dx と dy が両方とも 0 の場合、すでに目的地に到着しているため、答えは 0 になります。 
3. 差 d = dx − dy を考えます。 これは、点が主対角線からどのくらい離れているかを測定します。 動きの構造を見ると、ほとんどのステップで両方の座標が同時に減少するため、dx や dy 自体に比べて d の変化がゆっくりであることがわかります。 
4. dx が dy に比べて非常に大きい場合、最適な戦略は (2,1) タイプの手を繰り返し使用して、dy を制御しながら dx を積極的に減少させます。 このような動きはそれぞれ、実効的な不均衡を一定の割合で減少させるため、ステップ数は max(dx, (dx + dy + 1) // 3) スタイルのバランス動作によって決まります。 
5. 最終的な答えは、合計距離 (dx + dy) をどれだけ早く減らすことができるか、もう 1 つは非対称ステップを使用して支配的な座標をどれだけ早く減らすことができるかという 2 つの制約の最大値によって決まります。 これにより、閉じた形式が得られます。 

各手で合計が最大 3 減少するため、少なくとも ceil((dx + dy) / 3) ステップが必要です。絶対値で 2 より早く x を減少させる手はないため、少なくとも ceil(dx / 2) ステップが必要です。 最終的な答えは、(dx + dy) mod 3 ≠ 0 および dx % 2 の不一致により 1 つの余分なステップが強制される場合に、パリティに対する小さな修正を加えた、これら 2 つの限界の最大値です。 
6. この計算された値を返します。 

### なぜ効果があるのか

 すべての移動は、固定された有限のベクトルのセットの 1 つによって (dx、dy) 変化します。それぞれのベクトルにより、L1 のような潜在的な dx + dy が最大 3 だけ減少し、より大きな座標が最大 2 だけ減少します。これら 2 つの制約は、必要な移動の数に関する厳密な下限を定義します。 最適なパスは、総削減量を最大化する移動と同等のバランスをとる移動を常に交互に行います。 状態空間は 2 次元ですが、制約は dx と dy で線形不等式に崩壊するため、最適なシーケンスはこれらの境界の 1 つを飽和させ、2 つの最大値を十分にする必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(x, y, X, Y):
    dx = abs(X - x)
    dy = abs(Y - y)
    
    if dx < dy:
        dx, dy = dy, dx
    
    if dx == 0:
        return 0
    
    # lower bounds
    a = (dx + dy + 2) // 3
    b = (dx + 1) // 2
    
    return max(a, b)

def main():
    T = int(input())
    out = []
    for _ in range(T):
        x, y, X, Y = map(int, input().split())
        out.append(str(solve_one(x, y, X, Y)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、対称性が除去されるように、まず問題を非負の差に正規化します。 その後、ロジックは 2 つの独立した下限を計算します。1 つは移動ごとに除去できる合計変位の量から得られ、もう 1 つは支配軸をどれだけ速く減らすことができるかから得られます。 

ディビジョンの上限は、部分的な進行でも完全な移動を消費するという事実を実装しています。 最大値を取ると、両方の制約が同時に満たされることが保証されます。 

微妙な点は、正規化の順序です。dx と dy の交換は、境界を計算する前に行う必要があります。そうしないと、大きい方の軸に対する非対称制約が誤って適用されます。 

## 実用的な例

 ### 例 1: (1, 1) → (3, 4)

 dx = 2、dy = 3 を計算し、交換して dx = 3、dy = 2 を取得します。 

| ステップ | DX | ダイ | (dx+dy)/3 バウンド | dx/2 バウンド | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 3 | 2 | 2 | 2 | 2 |

 境界は一致するので、答えは 2 です。これは、両方の座標を効率的に減少させる 2 つの混合対角移動を使用することに対応します。 

### 例 2: (1, 1) → (98, 98)

 ここで dx = dy = 97 となります。 

| ステップ | DX | ダイ | (dx+dy)/3 バウンド | dx/2 バウンド | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | 97 | 97 | 65 | 49 | 65 |

 制限要因は、移動ごとの合計減少量です。 各ステップで除去できる合計距離は最大 3 単位であるため、約 194/3 ステップが必要になります。 

これは、完全にバランスの取れたターゲットであっても、軸ごとの動きではなく、集合的な制約によって支配されることを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve_one(x, y, X, Y):

        dy = abs(Y - y)
        if dx < dy:
            dx, dy = dy, dx
        if dx == 0:
            return 0
        return max((dx + dy + 2)//3, (dx + 1)//2)

    T = int(input())
    out = []
    for _ in range(T):
        x, y, X, Y = map(int, input().split())
        out.append(str(solve_one(x, y, X, Y)))
    return "\n".join(out)

# custom cases

 ## 特殊なケース

 重要なエッジケースは、目標がすでに達成されている場合です。 dx = dy = 0 の場合、両方の境界は 0 と評価され、アルゴリズムは除算のコーナー ケースを入力することなく正しく 0 を返します。 

もう 1 つの微妙な状況は、(0,0) から (100,1) への移動など、1 つの座標が優勢な場合です。 正規化 dx = 100、dy = 1 の後、支配軸の限界 (dx+1)//2 は 50 になりますが、総削減限界は (101+2)//3 = 34 になります。アルゴリズムは 50 を選択します。これは、小さい座標が必要なステップ数の削減に意味を持たないことを反映しています。 これは、すべての移動で大きな座標が最大 2 だけ減少する可能性があるという事実と一致します。 

最後に、(n,n) のような完全にバランスのとれた点は、集約制約を強調します。 dx = dy = n の場合、答えはおよそ 2n/3 になり、すべての移動の組み合わせによる削減能力には制限があるため、たとえ対称であっても純粋な対角最適化ができないことがわかります。
