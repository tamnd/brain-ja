 ## 解決策
 ## 問題の理解

 ツリーが与えられ、各ノードには 1 つの大文字が含まれます。 クエリでは、このツリー内のちょうど 5 つのノードを含む単純なパスがいくつあるかを数えるように求められます。パスに沿って文字を順番に読むと、固定パターン「S C C PC」を形成する必要があります。 

ここでの単純なパスとは、ツリー内の任意の 2 つのエンドポイントを選択し、それらの間の一意のパスを読み取ることを意味します。 ツリーには方向がないため、同じノードのセットをどちらの方向にもたどることができますが、必要な文字列と一致させるには順序が重要であるため、有効なパスの一方向のみが寄与します。 

制約は非常に大きく、すべてのテスト ケースにわたるノードの総数は 200 万に達する可能性があります。 これにより、すべてのパス、さらにはエンドポイントのすべてのペアを列挙しようとするソリューションは即座に除外されます。 n 個のノードを持つツリーには Θ(n²) 個の単純なパスがあるため、暗黙的にすべてのパスに触れるアプローチであっても失敗します。 

ターゲット パターンの長さは 5 に固定されており、これは重要な構造上の制限です。 任意のパスについて推論する代わりに、長さ 4 のエッジ パス (5 つの頂点) だけを探しています。これは、有効なパスはすべて「ローカル」であり、境界のある深さの構造上で動的プログラミングによってキャプチャできることを示唆しています。 

素朴だが重要なエッジ ケースは、パターンがツリー構造内でそれ自体と重なる場合です。 たとえば、S C C P C C C のようなチェーンには、重複する有効なセグメントが複数含まれている場合があり、パスが開始ノードに一貫して固定されていない場合、誤ってカウントしすぎてしまう可能性があります。 

もう 1 つの微妙なケースは方向性です。 パスが C P C C S を逆に読み取る場合、その逆のシーケンスがパターンと一致しない限り、そのパスは無効になりますが、一致しません。 したがって、一貫した「開始から終了」方向を強制する場合、各有効なパスは 1 回だけカウントされます。 

## アプローチ

 最も簡単なアイデアは、ノードのすべてのペアをエンドポイントとみなして、そのパスを計算し、シーケンスがパターンに一致するかどうかを確認することです。 これは原理的には正しいです。すべての単純なパスはそのエンドポイントによって一意に決定され、LCA 前処理を使用してシーケンスを取得できるからです。 

ただし、これではすぐにスケールが失われます。 Θ(n²) 個のペアがあり、各パス抽出には Θ(長さ) のコストがかかり、Θ(n³) 付近で最悪のケースが発生します。 LCA によってパスの構築が親ポインターに沿った対数または線形の走査に削減されたとしても、パスの総数は依然として 2 次であり、制限をはるかに超えています。 

重要な観察点は、パターンの長さが固定されており、非常に小さいということです。 これは、グローバル パスの列挙が必要ないことを意味します。 代わりに、パターン プレフィックスに一致する長さ 4 エッジ以下のルートから子孫へのパスをすべて数えるという問題として再構成できます。 ルートを修正すると、すべての有効なパスがツリー内に一意の「開始ノード」を持つことになるため、有効なパスを最初のノードに固定することで、有効なパスを 1 回だけカウントできます。 

これは、ツリー動的プログラミングの定式化につながります。 各ノードについて、そのノードから始まる下向きのパスが、k のパターンの最初の k 文字 (最大 5) に一致する数を計算します。有効なパスはすべて、その開始点から深さ 4 のサブツリーに完全に含まれるため、この DP で十分です。

 ## アルゴリズムのチュートリアル

 固定パターン P = “S C C PC” を定義します。 

便宜上、ノード 1 を任意の場所にルートします。次に、ルート ツリーの DP を計算します。ここで、 dp[u][k] は、ノード u から始まり、パターンの最初の k 文字に一致し、子エッジのみをたどる下向きのパスの数を表します。

1. ツリーの深さ優先の走査を実行して、親の前に子を処理します。 これにより、ノードの値を計算するときに、そのすべてのサブツリー情報がすでに利用可能であることが保証されます。 
2. 各ノード u について、u の文字が P[0] に等しい場合は dp[u][1] を 1 に初期化し、そうでない場合は 0 に初期化します。これは、長さ 1 の接頭辞の一致は開始文字が一致する場合にのみ可能であるという事実を反映しています。 
3. 2 から 5 の k について、すべての子 v からの寄与を合計することによって dp[u][k] を計算します。 dp[v][k-1] がゼロ以外で、u の文字が P[k-1] と一致する場合、子 v は dp[u][k] に寄与します。 これにより、パスが u から始まり、順番にパターンと一致するように下方向に継続することが強制されます。 
4. すべてのノードを処理した後の最終的な答えは、dp[u][5] のすべてのノード u の合計になります。 このような各値は、正確に u から始まりツリーに下降する有効な長さ 5 のパスに対応します。 

重要な設計上の選択は、パスを最初のノードに固定することです。 これにより曖昧さが解消されます。この定式化では、すべての有効なパスに有効な開始点が 1 つだけ存在するため、パスが二重にカウントされることはありません。 

### なぜ効果があるのか

 5 つのノードからなる有効なパスには、その方向に沿って一意の最初のノードがあります。 ツリーをルート化することにより、すべての単純なパスは、その最初のノードからその誘導されたサブツリー方向に始まる下向きのパスとして固有の表現を持ちます。 DP は、最大 4 つのエッジの長さの下向きの継続がすべて、開始ノードごとに 1 回だけ探索されることを保証します。 遷移は親から子のエッジに沿ってのみ拡張され、パターンの順序に厳密に従っているため、無効なシーケンスは構築できず、すべての有効なシーケンスは開始ノードで 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

PAT = "SCCPC"

def solve():
    n = int(input())
    s = input().strip()

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    dp = [[0] * 6 for _ in range(n)]
    parent = [-1] * n

    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    for u in reversed(order):
        if s[u] == PAT[0]:
            dp[u][1] = 1

        for v in g[u]:
            if v == parent[u]:
                continue
            for k in range(2, 6):
                if s[u] == PAT[k - 1]:
                    dp[u][k] += dp[v][k - 1]

    ans = 0
    for u in range(n):
        ans += dp[u][5]

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このソリューションでは、最初にツリー隣接リストを構築し、次に反復 DFS を使用してそれをルート構造に変換して、再帰の深さの問題を回避します。 次に、子が親の前に処理されるように、dp テーブルが逆走査順序で埋められます。 

移行ステップは重要な部分です。各ノード u について、u がパターン内の対応する文字と一致する場合にのみ、有効なプレフィックスを拡張します。 これにより、無効な部分一致が上方に伝播するのを防ぎます。 

最後に、すべてのノードの dp[u][5] を合計します。 この DP 定式化では、各有効なパスがその開始ノードによって一意に識別されるため、これは安全です。 

## 実用的な例

 ### 例 1

 ツリーは、SCCPC というラベルが付いた単純なチェーン 1-2-3-4-5 です。 

葉から上に向かって処理していきます。 

| ノード | s[u] | dp[1] | dp[2] | dp[3] | dp[4] | dp[5] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | S | 1 | 1 | 1 | 1 | 1 |
 | 2 | C | 0 | 1 | 1 | 1 | 1 |
 | 3 | C | 0 | 0 | 1 | 1 | 1 |
 | 4 | P | 0 | 0 | 0 | 1 | 1 |
 | 5 | C | 0 | 0 | 0 | 0 | 1 |

 最終的な答えは 1 で、チェーン全体に対応します。 

このトレースは、プレフィックス一致が形成されると、分岐の曖昧さなしにチェーンに沿って正確に上向きに伝播することを示しています。 

### 例 2

 ノード 1 を中心とし、リーフ 2、3、4、5 があり、1 つの枝に沿って 1 つの有効なチェーンが埋め込まれているスターがあるとします。 

S → C → C → P → C に一致するブランチのみが、その開始ノードで dp[5] に寄与します。 他のすべてのブランチは、文字の不一致または深さの欠如により早期に失敗します。 

これは、無効な部分一致が無関係なサブツリーに漏れないことを示しています。

 ## 特殊なケース

 主なエッジ ケースは、複数のブランチがプレフィックスを共有しているが、完全なパターンを完了しているのは 1 つだけである場合です。 DP は、完全な深さ 4 の拡張のみが dp[u][5] に寄与することを保証するため、他のブランチの部分一致が累積して誤検知になることはありません。 

もう 1 つの特殊なケースは、ツリーが長いチェーンに退化する場合です。 この場合、DP はチェーン上のスライディング ウィンドウのように動作し、各開始ノードが独立して寄与するため、答えは重複せず、有効な出現ごとに 1 つだけ残ります。
