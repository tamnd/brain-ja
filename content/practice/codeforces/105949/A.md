 ## 解決策
 ## 問題の理解

 すべてのエッジが 2 つの小さな正の重みを持つ有向グラフが与えられます。 ノード 1 からノード N へのパスはこれらの重みを個別に累積します。1 つの合計はパスに沿ったすべての最初のコンポーネントを加算することによって形成され、もう 1 つの合計はすべての 2 番目のコンポーネントを加算することによって形成されます。 パスの値は、これら 2 つの累積合計の積として定義されます。 

タスクは、この積を最小化するノード 1 からノード N までのパスを見つけることです。 複数のパスが同じ最小積を達成する場合、最初の累積合計が最も小さいパスがその中から選択され、まだ同点である場合は、その選択されたパスからの 2 番目の合計も報告されます。 

すべてのテスト ケースにわたるノードと合計エッジの点で制約は十分に小さいため、状態の表現に注意している限り、かなり直接的な最短パス スタイルのソリューションを実現できることがわかります。 各エッジの重みは最大 200 で、パスの長さは最大で数百のエッジになるため、累積合計は管理可能な範囲内に収まります。 

素朴な試みは、1 から N までのすべての単純なパスを列挙し、それらの (合計 A、合計 B) ペアを計算することです。 パスの数は分岐に伴って指数関数的に増加するため、小さなグラフではすぐに均衡を破ってしまいます。 分岐係数が中程度のグラフであっても、非常に多くの可能性が生じます。 

より微妙な障害モードは、A を最小化するか B を個別に最小化するなど、1 つの次元のみで標準の最短パスを実行しようとすることから発生します。 たとえば、A が非常に小さいが B が非常に大きいパスは、乗算するとバランスの取れたパスに負ける可能性があり、その逆も同様であるため、単一パラメータの削減によって最適な候補が破棄されます。 

本当の難しさは、目的が 2 つの結合された累積量に依存しており、どちらも独立して最適化できないことです。 

## アプローチ

 ブルート フォースの観点では、考えられるすべてのルートを候補として扱い、その 2 つの合計を累積し、積を計算して、最良の結果を追跡します。 これは問題の定義を直接評価するため、原則として正しいです。 ただし、有向グラフ内のパスの数は N とともに指数関数的に増加する可能性があるため、N が数百にすぎない場合でも、このアプローチはすぐに実行不可能になります。 

重要な観察は、目的は非線形であるにもかかわらず、パス コストが両方のコンポーネントで依然として加算されるということです。 すべてのパスはペア (A_sum、B_sum) によって完全に記述され、パスを拡張するとエッジの寄与が両方の座標に追加されるだけです。 これは、各ノードを「最もよく知られたペア」を持つものとして扱い、最短パスと同様にグラフ全体に改善を伝播することを示唆していますが、スカラー比較ではなくペア比較を行います。 

重要なアイデアは、問題のルールを使用して、これらのペアに全体的な順序を課すことができるということです。最初に A × B を最小化し、次に A × B を最小化します。エッジの重みは負ではないため、パスを拡張すると両方の合計の単調性が維持されます。そのため、ノードに最適なペアがダイクストラのようなプロセスで確認されると、後で何らかの代替ルートによって改善されることはありません。 

これにより、距離がペアとなり、比較が (A × B, A, B) によって辞書編集的に行われる標準的な最短パス アルゴリズムを実行できます。 順序付けは全体的であり、加算的遷移と一貫しているため、状態空間をノードを超えて拡張する必要はありません。

 | --- | --- | --- | --- |

 ## アルゴリズムのチュートリアル

 各ノードは、問題によって定義された順序に従って、最もよく知られているペア (A、B) を格納しているものとして処理されます。

1. (0, 0) で始まるノード 1 を除くすべてのノードを無限コスト ペアで初期化します。 これは、それらのノードへのパスがまだ発見されていないことを表します。 
2. (A × B, A, B) の順序で優先キューを使用します。 エッジの重みが負ではないため、状態が悪化しても最終的な答えは改善されないため、現在最もよく知られている状態を常に展開します。 
3. キューから最良の状態 (u、A、B) をポップします。 この状態がすでに記録されている最高の状態よりも悪い場合は、それをスキップします。 これにより、古いリラクゼーションの処理が回避されます。 
4. 重み (a, b) を持つ出力エッジ u → v ごとに、新しいペア (A + a, B + b) を計算します。 これは電流経路を 1 つのエッジだけ延長することを表し、両方の累積和は単調増加します。 
5. この新しいペアを、順序 (A × B、A、B) を使用して現在記録されている v の最良のペアと比較します。 より良い場合は、v の最適なペアを更新し、優先キューにプッシュします。 
6. キューが使い果たされた後、ノード N に保存されている最良のペアが答えとなります。 

このプロセスが有効である理由は、すべての緩和ステップで候補パスの正確さが維持され、優先キューにより、ノードが最適なペアで最終的に決定されると、その後の緩和では厳密に優れたペアが生成されないことが保証されるためです。 正の値を追加すると A と B の両方が増加するだけなので、以前の最適な決定を無効にすることはできないため、順序付けはパス拡張と一致します。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**30

def better(a1, b1, a2, b2):
    p1 = a1 * b1
    p2 = a2 * b2
    if p1 != p2:
        return p1 < p2
    if a1 != a2:
        return a1 < a2
    return b1 < b2

def solve():
    T = int(input())
    for _ in range(T):
        N, M = map(int, input().split())
        g = [[] for _ in range(N + 1)]
        for _ in range(M):
            u, v, a, b = map(int, input().split())
            g[u].append((v, a, b))

        bestA = [INF] * (N + 1)
        bestB = [INF] * (N + 1)

        bestA[1], bestB[1] = 0, 0
        pq = []
        heapq.heappush(pq, (0, 0, 0, 1))  # (A*B, A, B, node)

        while pq:
            prod, A, B, u = heapq.heappop(pq)

            if not better(A, B, bestA[u], bestB[u]):
                continue

            bestA[u], bestB[u] = A, B

            for v, a, b in g[u]:
                nA = A + a
                nB = B + b
                nP = nA * nB
                if better(nA, nB, bestA[v], bestB[v]):
                    heapq.heappush(pq, (nP, nA, nB, v))

        print(bestA[N], bestB[N])

if __name__ == "__main__":
    solve()
```このソリューションでは、候補状態の優先キューを引き続き使用しながら、ノードごとに最もよく知られているペアのみを保持します。 重要な点は、比較関数が単なる積ではなく、タイブレーク ルールを含んでおり、緩和と抽出の両方で同じ順序が一貫して使用されていることです。 

よくある落とし穴は、A × B のようなスカラー距離のみを保存しようとすることです。2 つの異なるペアが同じ積を持つ可能性があるため、タイブレークでは異なる結果が得られるため、情報が失われます。 完全なペアを保持する必要があります。 

もう 1 つの微妙な点は、後で別の拡張パスの下で最適になる可能性がある場合に、より悪い製品を持っているという理由だけで候補を破棄することは決してないことです。 プライオリティ キューにより、完全な比較キーのグローバルな昇順で探索が進行することが保証されるため、時期尚早なプルーニングが安全になります。 

## 実用的な例

 小さなグラフを考えてみましょう。 

入力:```
1
3 3
1 2 2 1
2 3 1 3
1 3 5 1
```2 つのパスを比較します。1→2→3 では A=3、B=4、積 12 が得られます。 direct 1→3 は A=5、B=1、積 5 を与えます。 

| ステップ | ノード | あ | B | 製品 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 0 | 0 | 0 |

 | リラックス | 3 | 5 | 1 | 5 |
 | リラックス | 3 経由 2 | 3 | 4 | 12 |

 積 5 が最小であるため、アルゴリズムは正しく (5,1) を持つノード 3 を優先します。 

次に、タイブレークが重要となるケースです。```
1

1 2 1 4
2 3 4 1
1 3 2 2
```パス 1→2→3 では、A=5、B=5、積 25 が得られます。直接パスでは、A=2、B=2、積 4 が得られます。 

| ステップ | ノード | あ | B | 製品 |

 最適なパスは 1 つだけ存在し、タイブレークはここでは無関係ですが、両方のコンポーネントがどのように明示的に追跡されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O((N + M) log N) | 各ノードの状態は、エッジ上のヒープ操作を使用してダイクストラのような方法で処理されます。 
| スペース | O(N + M) | グラフ ストレージとベスト ペア アレイおよび優先キュー |

 この制約により、テスト全体の N と M の合計が小さくなることが保証されるため、このアプローチは、ヒープからの対数オーバーヘッドがあっても制限内で快適に実行されます。

    from collections import deque

    INF = 10**30

    def better(a1, b1, a2, b2):
        p1 = a1 * b1
        p2 = a2 * b2
        if p1 != p2:
            return p1 < p2
        if a1 != a2:
            return a1 < a2
        return b1 < b2

    out = []

            u, v, a, b = map(int, input().split())
            g[u].append((v, a, b))

 ## 特殊なケース

 重要なエッジ ケースは、長いパスのプロダクトがわずかに劣るが、タイブレーク構造は優れている場合です。 すべての候補は優先キューに受け入れられる前に完全な順序付けを使用して比較されるため、アルゴリズムはこれを正しく処理します。 パスの A が小さく、B が大きい場合でも、製品の比較が許可する場合にのみ、別のパスが置き換えられます。 

もう 1 つの微妙なケースは、同じノード間に異なる重みを持つ複数のエッジです。 リラクゼーションでは各エッジが独立して処理されるため、アルゴリズムは両方の可能性を自然に探索し、最良のペアを維持し、平行エッジに特別な処理が必要ないことを保証します。
