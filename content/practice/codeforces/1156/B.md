 ## 解決策
 ## 問題の理解

 小文字の短い文字列が与えられ、その文字を任意に並べ替えることができます。 目標は、隣接する 2 つの文字がアルファベットの 1 つの位置だけ異なる配置を作成することです。 たとえば、「c」を「d」の隣に配置したり、「d」を「c」の隣に配置したりすることは禁止されていますが、同じ文字をその文字の隣に繰り返すことは許可されています。 

文字列の長さの制約は小さく、テスト ケースあたり最大 100 文字、テスト ケースあたり最大 100 個です。 これは、三次解や階乗解であっても、慎重に実装すれば技術的に合格することがすぐにわかりますが、配置の数は指数関数的であるため、それでも決定論的で高速な構築が必要です。 

微妙な問題は、ローカル制約がグローバルに相互作用することです。 文字の配置が局所的に安全であるように見えても、将来の文字がアルファベットの隣の文字と隣接する位置に強制的に配置される可能性があります。 常に次の有効な文字を選択する単純な貪欲な人は行き詰まる可能性があります。 

典型的な失敗例は、「abcde」や「abac」などの文字列など、アルファベット空間に文字が密集している場合に発生します。 計画なしに左から右に構築しようとすると、多くの場合、最後の近くで「ab」または「bc」のような隣接文字が強制的に挿入され、代替文字が残らないことになります。 

## アプローチ

 強引なアイデアは、文字列のすべての順列を試して、それぞれの配置が有効かどうかを確認することです。 これは検索空間全体を探索するので正しいですが、順列の数は O(n!) として増加し、n が約 10 の場合は枝刈りを行ってもすでに実行不可能です。 妥当性のチェックは O(n) であるため、全体の複雑さは O(n! · n) となり、限界をはるかに超えています。 

重要な観察は、アルファベットが固定されており小さい (26 文字) ため、問題の構造は個々の位置ではなく、これら 26 個のバケットにわたる頻度分布のみに依存するということです。 この制約は、ASCII コードが 1 だけ異なる文字を隣に配置することのみを禁止します。 

これは、文字をアルファベット グラフの独立したセットにグループ化するという観点から考えることを示唆しています。 アルファベットはパス グラフとして見ることができます。 

a - b - c - ... - z

 (このグラフに対して) 偶数のインデックスが付いた文字をすべて最初に配置し、その後に奇数のインデックスが付いた文字をすべて配置した場合、グループ内では文字のインデックスが少なくとも 2 異なるため、各グループ内の隣接関係は無効になります。 隣接関係の競合は、2 つのグループの境界文字間でのみ発生します。 慎重に注文することで、連続したアルファベットの隣接するペアが作成されるのを避けることができます。 

パス グラフにはインデックスのパリティ クラスが 2 つしかないため、グループ内のすべての禁止エッジを削除するには、インデックス パリティによる分割で十分です。 次に、2 つのグループの可能な連結順序を両方試して、妥当性をチェックします。 

これが機能するのは、禁止されたペアは常に反対のパリティ セットに分類される連続したインデックスを接続する必要があるためです。そのため、内部構造は安全であり、境界のみが問題となります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n! · n) | O(n) | 遅すぎる |
 | パリティ分割の構築 | O(26 + n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 文字列内の各文字の頻度をカウントします。 これにより、個々の文字ではなく 26 個のバケットの順序を決定するという問題が軽減されます。 
2. アルファベットのインデックスに基づいて文字を 2 つのグループに分割します。グループ A には偶数のインデックス (a、c、e、...) の文字が含まれ、グループ B には奇数のインデックス (b、d、f、...) の文字が含まれます。 この手順により、各グループ内でアルファベット内に 2 つの文字が隣接しないことが保証されます。 
3. 2 つの候補文字列を作成します。1 つはグループ A のすべての文字をグループ B の後に配置し、もう 1 つはグループ B の後にグループ A を配置します。各グループ内では、任意の順序 (通常はアルファベット順) で文字を追加します。 
4. 各候補文字列について、アルファベット インデックスが 1 だけ異なる隣接する文字のペアが含まれているかどうかを確認します。 これはリニアスキャンです。 
5. 有効な配置が見つかった場合は、それを出力します。 それ以外の場合は「無回答」を出力します。 

両方の連結順序を試す理由は、隣接性違反がグループ間の境界でのみ発生し、偶数のインデックスが付いた文字が奇数のインデックスが付いた文字の隣に位置する可能性があるためです。 

### なぜ効果があるのか

 アルファベットの隣接制限によりパス グラフが形成されます。 パリティによる分割では、頂点が 2 つの独立したセットに分割されます。これは、どちらのセット内にもエッジが存在しないことを意味します。 したがって、無効な隣接関係はパーティション境界を越えて発生する必要があります。 これらのセットを順序付ける方法は 2 つしかないため、両方をチェックすることで、この構造の下に有効な配置が存在する場合、2 つのうち 1 つで境界の競合が回避されることが保証されます。 グループ内の順序付けはルールによって制約されないため、各グループ内の並べ替えは有効性を保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid(s):
    for i in range(len(s) - 1):
        if abs(ord(s[i]) - ord(s[i+1])) == 1:
            return False
    return True

def solve(s):
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    even = []
    odd = []

    for i in range(26):
        if i % 2 == 0:
            even.append(chr(97 + i) * cnt[i])
        else:
            odd.append(chr(97 + i) * cnt[i])

    cand1 = "".join(even) + "".join(odd)
    cand2 = "".join(odd) + "".join(even)

    if valid(cand1):
        return cand1
    if valid(cand2):
        return cand2
    return "No answer"

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve(s))

if __name__ == "__main__":
    main()
```実装では、まず文字列を頻度カウントに圧縮します。 次に、アルファベットのパリティに基づいて 2 つの構造化された置換を再構築します。 パリティ分離により内部矛盾は解消されますが、グループを混合する場合、境界によって「c」の後に「d」が続くなどの隣接するアルファベットのペアが作成される可能性があるため、妥当性チェックが必要です。 

この構築では、複雑な後戻りを回避し、純粋に決定論的なグループ化と最終検証ステップに依存します。 

## 実用的な例

 ### 例 1:`"abcd"`頻度を計算します: a:1、b:1、c:1、d:1。 

偶数インデックス文字は a (0) と c (2) です。 奇数のインデックス文字は b (1) と d (3) です。 

| ステップ | 偶数グループ | 奇数グループ | 候補者 |
 | --- | --- | --- | --- |
 | ビルド | a c | b d | acbd |
 | ビルド | a c | b d | BDAC |

 チェック`acbd`: |c-b| であるため無効な「cb」が含まれています。 = 1 なので拒否します。 

チェック`bdac`: 遷移 b-d、d-a、a-c はすべて安全なので、受け入れます。 

これは、グループ化した後でも境界の配置が重要であることを示しています。 

### 例 2:`"abaca"`頻度: a:3、b:1、c:1。 

偶数グループ: a、c。 奇数グループ: b.

 | ステップ | 偶数グループ | 奇数グループ | 候補者 |
 | --- | --- | --- | --- |
 | ビルド | ああああ | b | ああああ |
 | ビルド | b | ああああ | ばあく |

 チェック`aaacb`: 最後のペア c-b は |c-b|=1 であるため無効です。拒否します。 

チェック`baaac`: b-a は開始時に無効です。拒否します。 

有効な取り決めが存在しません。 

これは、構造化されたパーティションを使用しても、一部の周波数分布では隣接関係の競合を回避できないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストごとに O(26 + n) | カウント + 構築 + 線形検証 |
 | スペース | お(26) | 頻度配列と一時文字列 |

 制約は十分に小さいため、検証ステップも無視できます。 各テスト ケースは最大 100 文字で動作するため、ソリューションは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def valid(s):
        for i in range(len(s) - 1):
            if abs(ord(s[i]) - ord(s[i+1])) == 1:
                return False
        return True

    def solve(s):
        cnt = [0] * 26
        for ch in s:
            cnt[ord(ch) - 97] += 1

        even = []
        odd = []
        for i in range(26):
            if i % 2 == 0:
                even.append(chr(97 + i) * cnt[i])
            else:
                odd.append(chr(97 + i) * cnt[i])

        c1 = "".join(even) + "".join(odd)
        c2 = "".join(odd) + "".join(even)

        if valid(c1):
            return c1
        if valid(c2):
            return c2
        return "No answer"

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve(input().strip()))
    return "\n".join(out)

 ## 特殊なケース

 隣接関係が存在しないため、単一文字の文字列は常に成功し、どのような構造も有効です。 このアルゴリズムは 1 文字のグループを生成し、それを変更せずに渡します。 

「ab」や「ba」などの 2 つの連続するアルファベット文字で構成される文字列は常に失敗します。 このような場合、両方の文字が反対のパリティ グループに属し、順序付けによって境界に禁止された隣接関係が作成されます。 

「aaaaa」などの繰り返しの多い文字列は、1 だけ異なるペアがなく、グループ化が単一のクラスターに縮退するため、簡単に成功します。 有効性チェックはすぐにパスするため、アルゴリズムは同じ文字列を返します。 

「アババブ」のような密な交互パターンは、境界の敏感さを露呈します。 各グループは内部的には安全ですが、配置ごとにパーティション全体の隣接関係が強制されるため、両方の連結が検証ステップで失敗します。
