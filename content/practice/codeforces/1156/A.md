 ## 解決策
 ## 問題の理解

 私たちは一連の幾何学図形を与えられています。 各数字は、次の 3 つの形状のいずれかを表します。 

-`1`= 円
 -`2`= 高さが底辺の長さに等しい二等辺三角形
 -`3`= 正方形

 すべての図は前の図に内接され、可能な限り最大のサイズが選択されます。 すべての三角形と四角形の向きは固定されているため、連続する図形の各ペアは固有の相対配置を持ちます。 

私たちの仕事は座標を再構築することではありません。 必要なのは、連続するすべての図形ペアの間に、個別の接触点がいくつ現れるかを判断することだけです。 場合によっては、2 つの図形が孤立した点ではなく、セグメント全体に沿って接触することがあります。 その場合、答えは無限にあります。 

数字の数は多くても 100 個と少ないです。 シーケンスを数回スキャンするアルゴリズムは、十分以上の速度を発揮します。 課題は純粋に幾何学的なものであり、図形タイプの各ペアがどのように相互作用するかを理解することです。 

最初の罠は、接触数が実際のサイズに依存しないことです。 すべての図形は最大限に内接されるため、図形タイプの各ペアは常に同じパターンの接触点を生成します。 

2 番目の罠は無限の場合です。 例えば：```
2
2 3
```特別な三角形に内接する正方形は、その底面全体に沿って三角形に接します。 その辺には無限に多くの点が含まれているため、正しい出力は次のようになります。```
Infinite
```3 番目のトラップは、一部のトリプルには修正が必要であることです。 考慮する```
3
3 1 2
```正方形には円が含まれ、円には三角形が含まれます。 単純にペアの寄与を追加すると、`4 + 3 = 7`, ただし、1 つの接触点は幾何学的に 2 回数えられます。 正解は 6 です。この特別な構成が問題の重要な観察点です。 

## アプローチ

 ブルートフォース幾何学的手法では、すべての図形の正確な座標を再構築し、連続する図形の境界間の交差を計算し、等しい点を結合し、重複セグメントが存在するかどうかを検出しようとします。 

このような解決策は不必要に複雑になります。 それでも`n ≤ 100`、円、三角形、四角形を正確に表すと、無理座標や重複点の検出を伴う難しい幾何学的計算が必要になります。 

実際の構造はもっと単純です。 すべての図形は最大限に内接され、方向が固定されているため、連続するペアの相互作用はそれらのタイプにのみ依存します。 

考えられるすべてのペアを一度に分析できます。 

円と三角形の場合、三角形の 3 つの頂点が円上にあり、3 つの接触点が得られます。 

円と正方形の場合、正方形の 4 つの頂点が円上にあり、4 つの接触点が得られます。 

三角形と円の場合、円は三角形の 3 つの辺に触れ、3 つの接触点が得られます。 

正方形と円の場合、円は正方形の 4 つの辺に接しており、4 つの接触点が得られます。 

三角形と正方形、または正方形と三角形の場合、図形は辺セグメント全体を共有します。 タッチポイントの数は無限です。 

これにより、隣接するペアの処理の問題が即座に軽減されます。 

詳細が 1 つ残っています。 シーケンス```
3 1 2
```からポイントがカウントされる構成を作成します。`(3,1)`そしてそこからカウントされるポイントは`(1,2)`一致する。 公式の幾何学的分析では、連続するトリプルが出現するたびに、`(3,1,2)`合計が 1 減ります。 

強引なジオメトリは完全に消えます。 必要なのは、小さなルックアップ テーブルと 1 つの特別な補正だけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースジオメトリ再構築 | 実装の複雑さが非常に大きい | O(n) | 非現実的 |
 | ペア分析 + 特別なトリプル補正 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 一連の図タイプを読み取ります。 
2. すべての隣接するペアをスキャンします。 
3. ペアが`(2,3)`または`(3,2)`、印刷`"Infinite"`そしてやめてください。 

これら 2 つの組み合わせにより、孤立した接触点ではなく、共通の側面セグメントが生成されます。 
4. それ以外の場合は、ペアの寄与を答えに追加します。 

可能な有限ペアは次のとおりです。 

-`(1,2)`または`(2,1)`貢献する`3`-`(1,3)`または`(3,1)`貢献する`4`5. すべてのペアを処理した後、連続するトリプルをすべてスキャンします。 
6. 発生するたびに、`(3,1,2)`、減算`1`答えから。 

これにより、固有の二重カウントされた接触点が削除されます。 
7. 印刷`"Finite"`そして結果として得られるカウント。 

### なぜ効果があるのか

 2 つの許可された図形タイプの間のすべての最大の刻印は、スケールに依存しない固定接触パターンを生成します。 したがって、接触点の総数はペアの寄与の合計となります。 

無限に多くの接触点が生じる唯一の方法は、正方形と特別な三角形が辺セグメント全体を共有する場合です。 まさにそのペアですね`(2,3)`そして`(3,2)`。 

すべての有限構成の中で、隣接するペアによって寄与される接触点間の重複は、トリプル構成でのみ発生します。`(3,1,2)`。 このようなトリプルごとに 1 を減算すると、重複した点が削除されます。 他のトリプルは繰り返しの接触点を作成しません。 したがって、アルゴリズムはすべての個別のタッチ ポイントを正確に 1 回カウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = 0

for i in range(n - 1):
    x = a[i]
    y = a[i + 1]

    if (x == 2 and y == 3) or (x == 3 and y == 2):
        print("Infinite")
        sys.exit(0)

    if x + y == 3:
        ans += 3
    else:
        ans += 4

for i in range(n - 2):
    if a[i] == 3 and a[i + 1] == 1 and a[i + 2] == 2:
        ans -= 1

print("Finite")
print(ans)
```最初のループでは、隣接するペアを処理します。 三角形と四角形が隣接すると、答えはすぐに無限大になるため、プログラムはすぐに終了します。 

有限ペアの場合、可能性は 2 つだけです。 円と三角形のペアは 3 つの接触点に寄与し、円と四角形のペアは 4 つの接触点に寄与します。 隣接する数字は異なることが保証されているため、チェックする`x + y == 3`円と三角形の組み合わせを認識するには十分です`(1,2)`そして`(2,1)`。 

2 番目のループでは、すべての項目に補正を適用します。`(3,1,2)`トリプル。 この調整を怠ることは、この問題で最もよくある間違いです。 

特別な処理はありません`(2,1,3)`が必要です。 のみ`(3,1,2)`重複したタッチポイントを作成します。

## テストケース```python
# helper: run solution on input string, return output string
import io
import sys

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    for i in range(n - 1):
        x = a[i]
        y = a[i + 1]

        if (x == 2 and y == 3) or (x == 3 and y == 2):
            return "Infinite\n"

        if x + y == 3:
            ans += 3
        else:
            ans += 4

    for i in range(n - 2):
        if a[i] == 3 and a[i + 1] == 1 and a[i + 2] == 2:
            ans -= 1

    return f"Finite\n{ans}\n"

# sample-like finite case
assert run("3\n2 1 3\n") == "Finite\n7\n"

# infinite case
assert run("2\n2 3\n") == "Infinite\n"

# special correction
assert run("3\n3 1 2\n") == "Finite\n6\n"

# minimum size finite
assert run("2\n1 2\n") == "Finite\n3\n"

# minimum size finite, circle-square
assert run("2\n1 3\n") == "Finite\n4\n"

# multiple corrections
assert run("5\n3 1 2 1 2\n") == "Finite\n11\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 / 2 1 3`|`Finite 7`| 標準の有限構成 |
 |`2 / 2 3`|`Infinite`| 無限セグメント接触 |
 |`3 / 3 1 2`|`Finite 6`| 特別トリプル補正 |
 |`2 / 1 2`|`Finite 3`| 最小の有限円-三角形の場合 |
 |`2 / 1 3`|`Finite 4`| 最小の有限円-正方形の場合 |
 |`5 / 3 1 2 1 2`|`Finite 11`| 複数のペアの貢献と 1 つの修正 |

 ## 特殊なケース

 ### 正方形に隣接する三角形

 入力:```
2
3 2
```最初のペアは`(3,2)`。 アルゴリズムは、2 つの禁止された隣接関係の 1 つを即座に検出し、次のように出力します。```
Infinite
```共有セグメントはすでに無限に多くのタッチ ポイントを作成しているため、これ以上の処理は必要ありません。 

### スペシャルトリプル`(3,1,2)`入力：```
3
3 1 2
```ペアの貢献により、`4 + 3 = 7`。 

トリプル スキャンでは、次の現象が 1 つだけ検出されます。`(3,1,2)`そして1を減算します。 

最終的な答えは次のようになります。```
Finite
6
```ペアの寄与を合計するだけのソリューションでは、誤って 7 が出力されます。 

### 無限ペアを含む長いシーケンス

 入力:```
5
1 3 2 1 3
```アルゴリズムの処理`(1,3)`成功して、その後遭遇`(3,2)`。 

このペアはすでに無限に多くの接触点を作成しているため、正しい出力は次のようになります。```
Infinite
```残りの数字は無関係です。 このようなペアを発見した後もカウントを続ける実装では、無限の構成に対する有限の答えが生成される危険があります。
