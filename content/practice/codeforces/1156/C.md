 ## 解決策
 ## 問題の理解

 数直線上に配置された点の集合が与えられ、目的はできるだけ多くの素なペアを形成することです。 ペアは、選択した 2 つの点が十分に離れている場合、つまりそれらの座標間の絶対差が少なくとも固定しきい値である場合にのみ有効です。$z$。 各ポイントは最大 1 ペアに所属できるため、一度ポイントを使用すると再度参加することはできません。 

タスクは、合計距離や加重スコアではなく、カウントを最大化するペアを選択することです。 これは、相対的な位置のみが重要となる、ソートされた構造上でのマッチングの問題を扱っていることを直ちに示唆しています。 

入力サイズは次のとおりです$2 \cdot 10^5$これにより、二次関数のアプローチが除外されます。 すべてのペアの組み合わせを試したり、パートナーを繰り返しスキャンしたりするものはすべてヒットします。$10^{10}$最悪の場合、制限時間内に操作が失敗する可能性があります。 これにより、線形または対数ペアリング戦略と組み合わせたソートが推進されます。 

ソートなしで貪欲なペアリングが実行されると、微妙な失敗のケースが発生します。 次のような入力を検討してください。```
n = 4, z = 3
points = [1, 10, 2, 11]
```最適な答えは 2、(1,10) と (2,11) の組み合わせです。 ソートを行わない単純なスキャンでは、隣接する入力順序をチェックする場合、最初に (1,2) をペアにする可能性がありますが、距離が 1 しかないためこれは無効であり、その後、最適な構造を完全に見逃してしまいます。 別の障害モードは、グローバル順序を考慮せずに、各点を最も近い有効なパートナーと貪欲に組み合わせた場合に発生します。 これにより、後の試合のために確保しておく必要がある大きなポイントが無駄になる可能性があります。 

中心的な問題は、ローカルのペアリングの決定が、ラインに沿ったグローバルな順序を尊重する必要があるということです。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての組み合わせが試行されます。 点をマークし、距離が少なくとも$z$、そしてあらゆる可能性を探ります。 原理的には正しいですが、分岐要素は膨大です。 最悪の場合、有効なペアが多数あると、一致の数が組み合わせ的に増加し、指数関数的に複雑になります。 

各ポイントを前方にスキャンして有効なパートナーを見つけるという、より単純な総当たりの改善でも、$O(n^2)$行動。 と$n = 2 \cdot 10^5$、これは実現可能な限界をはるかに超えています。 

重要な観察は、ポイントを分類することから得られます。 並べ替えると、問題は最小のギャップを尊重しながら小さな要素と大きな要素をペアにするという問題になります。 順序を修正すると、左から右への貪欲なペアリングが意味を持つようになります。つまり、最小の未使用ポイントが、制約を満たす最も早いポイントと一致する必要があります。 代わりに、後で不必要に大きな候補と一致させようとすると、その大きな値が無駄になり、将来のペアリングの機会が減少する可能性があります。 

これは、左側のポインター (未使用の最小点) と、有効なパートナーを検索する別のポインターを維持するという 2 つのポインター戦略を示唆しています。 

ソート後、両方のポインタを制御された方法で貪欲に進めることができるため、ペアリングが成功するたびに 2 ポイントが消費され、試行が失敗するたびに正しいポインタのみが移動します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$それより悪い |$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポイントを降順でない順に並べ替えます。 これにより、ペアリングを検討するときに、右側のすべての候補が大きいか等しいことが保証されるため、距離の比較は単調になります。 
2. 2 つのポインターを初期化します。1 つは配列の先頭にあります (これを$i$)、実装戦略に応じて、別の位置が途中の位置、または同じ位置から開始されます。 クリーンな処方で治療します$i$最初の不一致要素として、$j$パートナー候補として前に進みます。 
3. 移動$j$次のような点が見つかるまで前進します$x[j] - x[i] \ge z$。 移動の各ステップ$j$より小さい候補はすでに条件を満たしておらず、後で有効になることはないため、この条件は正当化されます。 
4. そのような場合は、$j$が見つかったら、ペアを記録し、両方を進めます$i$そして$j$。 これは両方のポイントを消費したことを反映しています。 
5. もし$j$有効なパートナーを見つけられずに終わりを迎える$i$、その場合、ポイントはペアリングできません$i$、残りのすべての点はさらに右にあるためですが、この構成で実行可能な一致の構造を貪欲な順序ですでに使い尽くしているためです。 だから私たちは移動します$i$前進して、次の潜在的なベースポイントの検索を続けます。 
6. いずれかのポインタが配列の末尾に到達するまで続行します。 

微妙なのは、決して後戻りしないということです。 各ポインターは前方にのみ移動するため、ソート後の直線的な複雑さが保証されます。 

### なぜ効果があるのか

 ソートされた順序により、ポイントを含む有効なペアがすべて強制されます。$i$右側のパートナーを使用する必要があります。 もし$i$が一致する場合、可能な限り最小の有効なパートナーとペアにすることは常に安全です。より大きなパートナーを使用しても、ペアの数を増やすことなく、将来の柔軟性が低下するだけです。 もし$i$現在の最小の実現可能な候補と照合できない場合、以前の候補と照合することはできず（存在しないため）、より大きな候補のみが残ります。これは、以前の選択肢と比較して距離制約を満たすことが厳密に困難です。 貪欲な選択では、以前のすべての決定によって配列のサフィックスの残りの柔軟性が最大化されるという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, z = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    i = 0
    j = n // 2
    ans = 0

    while i < n // 2 and j < n:
        if a[j] - a[i] >= z:
            ans += 1
            i += 1
            j += 1
        else:
            j += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず配列をソートし、次に 2 ポインター戦略を使用します。`i`潜在的なペアの小さい側を追跡し、`j`有効なパートナーを検索します。 初期化の選択`j`で`n // 2`これは、一般的な貪欲な最適化を反映しています。つまり、下半分の要素と上半分の候補を組み合わせて、不必要な比較を削減しようとします。 たとえ次のような場合でもロジックは機能します`j`は 0 から始まりますが、実際には中間点から始めるとスキャンのオーバーヘッドが軽減されます。 

重要な実装の詳細は、両方のポインターが前方のみに移動することです。 これにより、並べ替え後の線形スキャンが保証され、要素の再訪問が回避されます。

## 特殊なケース

 重要なエッジ ケースは、多くのポイントが同一であるか、有効なパートナーが存在せずに緊密にクラスター化されている場合です。 その状況では、アルゴリズムは、枯渇するまで正しいポインターを進め続け、誤ったペアリングが発生しないようにします。 例えば：```
[5, 5, 5, 5], z = 1
```ソートされた配列は変更されません。 ポインタ`i`0でスキャンします`j`すべての要素にわたって、有効な違いが見つからず、最終的には`i`増加します。 これは、すべての要素が使い果たされてペアが 0 になるまで繰り返されます。 

もう 1 つのエッジ ケースは、次のような有効なペアが極端な値の間にのみ存在する場合です。```
[1, 2, 3, 100], z = 50
```ここでは (1,100) のみが有効です。 アルゴリズムは、しきい値を満たさないため、2 と 3 を 1 のパートナーとしてスキップし、最終的に 100 に達し、正確に 1 つのペアを形成します。
