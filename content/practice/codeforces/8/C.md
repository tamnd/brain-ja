 ## 解決策
 ## 問題の理解

 固定の開始点であるハンドバッグと、2D 平面上に最大 24 個の散在オブジェクトがあります。 レナは常にハンドバッグから始めて、最大 2 つのオブジェクトを集めて歩き回り、ハンドバッグに戻り、すべてのオブジェクトが元に戻るまで繰り返します。 

2 つの位置間の移動コストは、ユークリッド距離の 2 乗です。 レナがポイントから移動した場合`(x1, y1)`に`(x2, y2)`、かかった時間は次のとおりです。$(x_1-x_2)^2 + (y_1-y_2)^2$ハンドバッグ自体は決して動かないので、すべての旅行はポイントから始まります`0`そして点で終わります`0`。 

1 回の旅行は次のようになります。```
0 -> i -> 0
```またはこのように:```
0 -> i -> j -> 0
```このタスクは、最小の総旅行コストを計算するだけでなく、1 つの最適な一連の旅行を再構築することも目的としています。 

制約`n ≤ 24`要因的なものはすぐに除外されます。 オブジェクトの可能な順序をすべて試してみると、大まかに次のことが必要になります。`24!`順列、それは完全に不可能です。 

同時に、`2^24`1600万くらいです。 これは大きいですが、定数係数の低い言語で慎重に最適化されたビットマスク DP では管理可能です。 各トリップは 1 つまたは 2 つのオブジェクトを処理するため、問題の構造は当然、「どのオブジェクトがすでに収集されているか」をビットマスクとして表現することを示唆しています。 

この問題の珍しい部分は、パスが独立した移動に分割され、常にハンドバッグに戻ることです。 それは通常の巡回セールスマンの構造を破壊します。 すべてを一度に訪問する巨大なルートは必要ありません。 オブジェクトをサイズ 1 または 2 のグループに分割し、各グループ内で最適な順序を選択するだけです。 

2 つのオブジェクトを取得する方が、実際には個別に取得するよりも悪い場合には、微妙なエッジ ケースが発生します。 

例：```
0 0
2
100 0
-100 0
```両方を合わせると次のようなコストがかかります。```
0 -> A -> B -> 0
= 10000 + 40000 + 10000
= 60000
```それらを別々に考えると、次のような費用がかかります。```
0 -> A -> 0 = 20000
0 -> B -> 0 = 20000
total = 40000
```近くのオブジェクトを常にペアにするという貪欲な戦略は、ここでは失敗します。 

もう 1 つの危険なケースは、オブジェクトが 1 つだけ収集されずに残っている場合です。 

例：```
0 0
3
1 0
2 0
100 0
```最適な解決策は、最初の 2 つを組み合わせ、3 つ目はそのままにします。 すべての遷移でちょうど 2 つのオブジェクトが削除されると想定するバグのある実装では、クラッシュするか、有効な状態がスキップされます。 

再建にも落とし穴がある。 DP は最小コストのみを計算しますが、出力には実際の一連の旅行が必要です。 親情報を慎重に保存しないと、後でルートを再構築できなくなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる可能な一連の旅行を生成することができます。 各ステップで、残りのオブジェクトを 1 つまたは 2 つ選択し、トリップを追加して、残りのセットを再帰します。 

すべての有効な戦略はオブジェクトを順序付けられた旅行に分割したものにすぎないため、この強引な方法は正しいです。 再帰により、最終的にそれらすべてが列挙されます。 

問題は可能性の数です。 ペアだけを数えたとしても、24 個のオブジェクトを単一とペアに分割する方法の数は膨大です。 おおよそ次のように成長します。$\sum_{k=0}^{12} \frac{24!}{(24-2k)!\,2^k\,k!}$これは 4 秒で実行できる速度をはるかに超えています。 

重要な観察は、旅行間の順序は将来のコストには関係ないということです。 オブジェクトのサブセットが収集されると、関連する情報はまさにそのサブセットのみになります。 レナは旅行のたびに必ずハンドバッグに戻るため、「現在位置」の状態はありません。 

つまり、次のように定義できます。```
dp[mask] = minimum cost to collect all objects in mask
```州から`mask`、未収集のオブジェクトを 1 つ選びます`i`。 次に、次のいずれかを行います。```
take only i
```または：```
take i together with another uncollected object j
```これにより、より大きなマスクへの移行が作成されます。 

重要な最適化は、最初の未収集のオブジェクトのみを選択することです。 このトリックがなければ、すべての州がすべての順序付けされたペアを繰り返し試行することになります。 1 つの正規オブジェクトを修正することにより、すべての遷移が 1 回生成されます。 

状態の総数は`2^n`。 各状態について、最大でも試行します`n`最初の空きオブジェクトとペアリングするため、複雑さはおおよそ次のようになります。$O(n\cdot 2^n)$快適にフィットする`n = 24`最適化された実装で。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的超過`2^n`| 指数 | 遅すぎる |
 | 最適なビットマスク DP |`O(n * 2^n)`|`O(2^n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ハンドバッグの座標とすべてのオブジェクトの座標を読み取ります。 
2. すべての点のペア間の距離を事前計算します。 

コスト関数では、二乗ユークリッド距離が何度も使用されます。 DP 遷移内で再計算すると時間が無駄になります。 

1. あらゆるオブジェクトに対して`i`、そのオブジェクトのみを取得するコストを事前計算します。```
0 -> i -> 0
```これは次と同等です。```
dist(0, i) + dist(i, 0)
```1. オブジェクトのペアごとに`(i, j)`、それらを一緒にするコストを事前計算します。```
0 -> i -> j -> 0
```これは次と同等です。```
dist(0, i) + dist(i, j) + dist(j, 0)
```1. 以下を定義します。```
dp[mask]
```ビットが設定されているオブジェクトを正確に収集するために必要な最小コストとして`mask`。 

初期化:```
dp[0] = 0
```なぜなら、何も収集するのには費用がかからないからです。 

1. すべてのマスクを繰り返し処理します。 

各マスクについて、最初のオブジェクトを見つけます`i`まだ集められていない。 

最初に欠落しているオブジェクトのみを選択すると、トランジションの重複が回避されます。 すべての状態の拡張は独自のものになります。 

1. 物体を取ってみる`i`一人で。 

作成する：```
new_mask = mask | (1 << i)
```アップデート：```
dp[new_mask]
```の旅行費と一緒に`i`。 

1. ペアリングしてみる`i`他の未収集オブジェクトごとに`j`。 

作成する：```
new_mask = mask | (1 << i) | (1 << j)
```事前に計算されたペア旅行コストを使用して DP を更新します。 

1. 遷移によって DP 値が改善されるたびに、親情報を保存します。 

各州でどの旅行が選択されたかを再構築するには十分な情報が必要です。 

1. すべてのマスクを処理した後、以下から逆方向に答えを再構築します。```
(1 << n) - 1
```マスクに到達するまで親ポインタに従います`0`。 

1. 再構築されたシーケンスを反転し、必要な形式で印刷します。 

すべての旅行は次のように始まり、次のように終わる必要があります。`0`。 

### なぜ効果があるのか

 DP の不変条件は次のとおりです。```
dp[mask] = minimum possible cost to collect exactly the objects in mask
```すべての有効な戦略は、最後の旅行の前に、ある以前の状態に到達します。 この最後のトリップでは、1 つまたは 2 つのオブジェクトが削除されます。 遷移公式はまさにそれらの可能性を列挙しています。 

状態が遷移するたびに 1 つの独立した旅行の正確なコストが加算され、旅行は常にハンドバッグで始まり終了するため、異なる旅行の間に隠れた相互作用は存在しません。 状態の最適解はより小さな状態にのみ依存するため、動的プログラミングが有効になります。 

最初の未収集オブジェクトを修正しても、有効な解決策は削除されません。 すべてのトランジションは、正規の順序で 1 回だけ表示されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def dist(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return dx * dx + dy * dy

def solve():
    xs, ys = map(int, input().split())
    n = int(input())

    points = [(xs, ys)]
    for _ in range(n):
        points.append(tuple(map(int, input().split())))

    single = [0] * n
    pair = [[0] * n for _ in range(n)]

    for i in range(n):
        single[i] = (
            dist(points[0], points[i + 1]) * 2
        )

    for i in range(n):
        for j in range(n):
            pair[i][j] = (
                dist(points[0], points[i + 1])
                + dist(points[i + 1], points[j + 1])
                + dist(points[j + 1], points[0])
            )

    size = 1 << n

    dp = [INF] * size
    parent = [-1] * size
    take = [()] * size

    dp[0] = 0

    for mask in range(size):
        if dp[mask] == INF:
            continue

        first = -1

        for i in range(n):
            if not (mask & (1 << i)):
                first = i
                break

        if first == -1:
            continue

        # take first alone
        new_mask = mask | (1 << first)

        cost = dp[mask] + single[first]

        if cost < dp[new_mask]:
            dp[new_mask] = cost
            parent[new_mask] = mask
            take[new_mask] = (first,)

        # take first with another object
        for j in range(first + 1, n):
            if mask & (1 << j):
                continue

            pair_mask = new_mask | (1 << j)

            cost = dp[mask] + pair[first][j]

            if cost < dp[pair_mask]:
                dp[pair_mask] = cost
                parent[pair_mask] = mask
                take[pair_mask] = (first, j)

    full = size - 1

    print(dp[full])

    path = []

    cur = full

    while cur:
        objs = take[cur]

        trip = [0]

        for x in objs:
            trip.append(x + 1)

        trip.append(0)

        path.extend(trip)

        cur = parent[cur]

    path.reverse()

    print(*path)

solve()
```最初のセクションでは座標リストを作成します。 ハンドバッグはインデックスに収納されています`0`、オブジェクトはから保存されますが、`1`これからも。 これにより、すべての旅行で自然にポイントが参照されるため、距離の計算が簡素化されます。`0`。 

の`single`配列には、1 つのオブジェクトを単独で取得するコストが格納されます。 の`pair`行列には、1 回の旅行で 2 つの物体を一緒に運ぶコストが格納されます。 これらの値を事前計算すると、DP ループから繰り返される演算が削除されます。 

The DP state uses a bitmask. 噛まれたら`i`設定されている、オブジェクト`i`すでに回収されています。 配列のサイズは`2^n`、これは実現可能です`n = 24`。 

遷移ロジックは常に最初の未収集オブジェクトを選択します。 これは、重複した作業を減らす標準の最適化です。 これがなければ、すべての状態が異なる順序で同等のペアを繰り返し生成することになります。 

再構成配列は微妙です。`parent[new_mask]`前のマスクを保存します。`take[new_mask]`この状態を生成した最後の旅行でどのオブジェクトが収集されたかを格納します。 

再構築中は、完全なマスクからゼロまで逆方向に歩きます。 保存された各旅行は次のようになります。```
0 -> objects -> 0
```再構成は逆方向に蓄積されるため、印刷する前に最終リストを逆にする必要があります。 

簡単な間違いの 1 つは、`+1`出力中。 内部的にはオブジェクトのインデックスは 0 ですが、問題のステートメントではインデックスが 1 の番号付けが使用されています。 

もう 1 つの一般的なバグは、すでに収集されたオブジェクトのペア遷移を生成することです。 条件:```
if mask & (1 << j):
    continue
```無効な遷移を防ぎます。
