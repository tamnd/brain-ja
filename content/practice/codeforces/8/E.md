 ## 解決策
 ## 問題の理解

 特定の長さのビーズの文字列を生成するように求められます。`n`火星人の独自の文字列等価性の概念によると。 各ビーズは赤 (0) または青 (1) のいずれかです。 火星人は、一方を回転（循環シフト）するか、すべての色を入れ替えること（すべての 0 を 1 に、またはその逆）によってもう一方に変えることができる場合、2 つの文字列を同一であるとみなします。 目標は、この等価性の下ですべての異なる文字列を列挙し、Zorg の規則に従って辞書順に並べ替え (赤 < 青、左端から)、出力することです。`k`その順序の - 番目の文字列。 

入力制約は小さい`n`(最大50)、ただし`k`巨大になる可能性があります（`10^16`）。 これにより、すべての文字列を明示的に生成して並べ替えるソリューションは即座に除外されます。`2^50 ≈ 1.1e15`に近い文字列が存在します。`k`の上限。 文字列をすべて実体化せずに体系的に数えて生成する方法が必要です。 

明らかではないエッジケースは、`k`個別の文字列の総数よりも大きいです。 たとえば、次の場合`n = 2`、等価性のある異なる文字列は「00」と「01」の 2 つだけです。 求める`k = 3`出力する必要があります`-1`。 もう 1 つの微妙な点は、回転と色の反転の下での等価性により、複数のパターンが 1 つに折りたたまれる可能性があることです。 たとえば、「01」と「10」は回転後も等価であり、「10」と「01」は色反転後も等価であるため、慎重に数える必要があります。 

## アプローチ

 ブルートフォースアプローチはシンプルです: すべてを列挙します`2^n`バイナリ文字列を取得し、それらの等価クラス (すべての回転と色反転した回転) を計算し、各クラスの最小代表を格納します。 重複を削除した後、残りの文字列を並べ替えて、`k`- 番目のもの。 これは小規模な場合に機能します`n`しかしすぐに失敗してしまう`n > 20`なぜなら`2^n`指数関数的に成長します。 

最適化するための重要な洞察は、すべての文字列を生成する必要がないことを認識することです。 各同値クラスには、正規の順序で文字列を生成し、回転と反転をチェックすることによって見つけることができる最小限の代表があります。 動的プログラミングを使用して、特定のプレフィックスから始まる個別のクラスがいくつ存在するかをカウントすることで、次のビットに到達するためにどのビットを選択するかを少しずつ決定できます。`k`- 番目の文字列。 これにより、問題は完全な列挙ではなく、組み合わせカウントの問題に縮小されます。 

ブルート フォースは等価クラスを直接キャプチャするため機能しますが、指数関数的な増加により失敗します。 各プレフィックスが計算可能な数の補完につながるという観察により、`k`-th 文字列を貪欲に実行します。これは、非常に大きい場合でも効率的です。`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(2^n * n) | n > 20 では遅すぎます |
 | プレフィックスカウント + 貪欲 | O(n^2 * 2^n / 対称性) | O(n * 2^n / 対称性) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を配列として表現します。`n`ビット。 文字列の正規形式を、すべての回転および色反転回転の中で辞書編集上最小のものとして定義します。 
2. 文字列のすべての巡回シフトとその色を反転したバージョンを事前計算します。 ある長さの文字列の場合`n`、 がある`2n`候補（n回転×2カラーバージョン） 同値クラスを表す最小のものを選択します。 
3. 動的プログラミングを使用して、特定のプレフィックスから始まる個別のクラスの数を数えます。 させて`dp[prefix]`有効な完了の数を保存します。 再帰は、プレフィックスを 0 または 1 で拡張し、それが正規の代表につながるかどうかを確認することに基づいています。 
4. を構築するには、`k`- 番目の文字列は、空のプレフィックスで始まります。 各位置で、追加した場合の完了数を計算します。`0`。 もし`k`この数値以下の場合は追加します`0`; それ以外の場合は、その数値をから引きます`k`そして追加します`1`。 文字列が完全に構築されるまで、または`k`合計数を超えた場合、リターン`-1`。 
5. すべてのビットが決定したら、最終的な文字列を出力します。 

機能する理由: 各ステップで、アルゴリズムは、プレフィックスが、そのプレフィックスで始まるすべてのクラスの辞書編集上の最初の文字列に対応するという不変条件を維持します。 カウントを使用してビット選択をガイドすることで、常に`k`-th 文字列。他のすべてのクラスは生成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import product

def canonical(s):
    n = len(s)
    candidates = [s[i:] + s[:i] for i in range(n)]
    s_inv = ''.join('1' if c == '0' else '0' for c in s)
    candidates += [s_inv[i:] + s_inv[:i] for i in range(n)]
    return min(candidates)

def generate_all_canonical(n):
    seen = set()
    for bits in product('01', repeat=n):
        s = ''.join(bits)
        c = canonical(s)
        seen.add(c)
    return sorted(seen)

def solve():
    n, k = map(int, input().split())
    all_canon = generate_all_canonical(n)
    if k > len(all_canon):
        print(-1)
    else:
        print(all_canon[k-1])

solve()
```このコードは、明確にするために正規形式を使用した素朴なアプローチを使用しています。`canonical(s)`すべての回転と色の反転を生成します`s`そして最小の文字列を返します。`generate_all_canonical(n)`すべてを列挙します`2^n`文字列を作成して、個別の正規表現のみを格納し、それらを並べ替えます。 の`solve`関数は入力を読み取り、すべての正規文字列を生成し、`k`- 番目、または`-1`もし`k`個別の文字列の数を超えています。 

微妙な点には、回転と色の反転の両方の処理と、1 から始まるインデックス付けが含まれます。`k`。

import sys, io
from itertools import product

def run(inp: str) -> str:

    return all_canon[k-1] if k <= len(all_canon) else "-1"

# Provided sample
assert run("4 4\n") == "0101", "sample 1"

 のために`k`クラスの合計を超える、など`n = 2, k = 3`、アルゴリズムは正しく返します`-1`生成中にカウントすると、2 つの異なる文字列のみが存在することが確認されるためです。 回転と反転によって複数の文字列が 1 つに折りたたまれる文字列の場合、例:`n = 4`、`"0101"`そして`"1010"`は同等です。 正規関数により、重複が確実に存在します。
