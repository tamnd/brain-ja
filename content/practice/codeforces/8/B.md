 ## 解決策
 ## 問題の理解

 無限の 2D グリッド上でロボットの経路を分析するように求められます。 ロボットは上下左右に移動でき、その動きは文字 U、D、L、R の文字列として記録されます。課題は、この正確なパスが開始マスから最後のマスまでの最短パスとなる**空のセルとブロックされたセルの可能な配置**が存在するかどうかを判断することです。 

ロボットは決してブロックされた広場に入ろうとはしません。 本質的には、ロボットの記録された経路がすでに占有している正方形を再び訪問しないように、開始正方形をどこかに配置できるかどうかを確認する必要があります。 ロボットが別のルートを使用すれば、より少ないステップでその正方形に到達できた可能性があるため、再訪問すると最短経路ではないことが示されます。 

入力は最大 100 までの長さの文字列です。これは比較的小さいため、おおよその動作を行うアルゴリズムであれば、$O(n^2)$以上の場合は、2 秒の制限時間内で快適に実行できます。 重要なエッジ ケースは、ロボットのパス自体が交差するときに発生します。ロボットがすでに訪問した正方形にどこかの時点で移動した場合、それはルート内の循環を意味するため、それが最短パスであることはできません。 たとえば、パス`LR`すぐに開始マスに戻り、出力する必要があります`BUG`。 再訪を無視する単純な実装では、誤って出力されます。`OK`。 

## アプローチ

 ブルートフォースアプローチを説明するのは簡単です。 巨大なグリッドを構築し、考えられるすべての開始マスをシミュレートし、それ自体が交差するかどうかを確認しながらパスを配置しようとすることを想像できます。 原理的には正しいですが、これは非現実的です。たとえ長さが 100 であっても、すべての相対位置をマッピングしようとすると、ロボットは 10,000 の異なる座標をカバーできる可能性があります。 可能な開始点ごとに重複をチェックするため、操作数は急速に増加します。 

重要な洞察は、ロボットの絶対座標は重要ではないということです。 パスに沿った**相対位置**のみが重要です。 任意の原点から開始するロボットをシミュレートすると`(0, 0)`訪問する座標を段階的に追跡すると、自己交差を即座に検出できます。 最終ステップの前に座標が繰り返される場合、ロボットは正方形を再訪問することになりますが、これは最短経路と互換性がありません。 それ以外の場合、パスは有効なマップに対応する可能性があります。 これにより、問題は単一のパスに沿った単純なセットのメンバーシップ チェックに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | 最適 (訪問座標の追跡) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ロボットに任意の開始座標を割り当てます。`(0, 0)`。 これは開始マスを表します。 
2. すべての訪問座標を保存するセットを初期化します。 開始座標をこのセットに追加します。 
3. パス文字列内の各移動について:

 1. 移動に基づいて次の座標を計算します。x をデクリメントします。`L`、x を増分します。`R`, y をデクリメントします`D`、yをインクリメントします`U`。 
2. 次の座標がすでに訪問済みセット内にあるかどうかを確認します。 そうなったらすぐに返す`BUG`。 
3. それ以外の場合は、新しい座標を訪問セットに追加します。 
4. 座標を再度訪問することなくパスが完了した場合は、戻り値を返します。`OK`。 

これが機能する理由: グリッド上の最短パスは正方形を再訪することはありません。 座標を追跡し、再訪問を検出することにより、経路が最短にならない条件を正確に捕捉します。 これは、無限マップが他の場所でどのように埋められているかに関係なく機能します。これは、任意の開始位置を次のように変換できるためです。`(0, 0)`一般性を失うことなく。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    moves = input().strip()
    
    x, y = 0, 0
    visited = set()
    visited.add((x, y))
    
    for move in moves:
        if move == 'L':
            x -= 1
        elif move == 'R':
            x += 1
        elif move == 'U':
            y += 1
        elif move == 'D':
            y -= 1
        
        if (x, y) in visited:
            print("BUG")
            return
        visited.add((x, y))
    
    print("OK")

if __name__ == "__main__":
    main()
```この実装は、パスを読み取り、ロボットのステップごとの移動をシミュレートし、定数時間の検索のために訪問先の座標をセットに保存します。 セットを使用すると、各ステップでの O(n) スキャンが回避されます。 開始の選択`(0, 0)`は任意ですが、表現を簡略化します。 操作の順序は重要です。新しい座標を訪問セットに追加する**前**に、再訪問をチェックします。 

## 実用的な例

 **サンプル 1:`LLUUUR`**

 | 移動 | コーディネート | 訪問 | 結果 |
 | --- | --- | --- | --- |
 | 開始 | (0,0) | {(0,0)} | - |
 | Ｌ | (-1,0) | {(0,0),(-1,0)} | OK |
 | Ｌ | (-2,0) | {(-2,0),(-1,0),(0,0)} | OK |
 | う | (-2,1) | {(-2,0),(-2,1),(-1,0),(0,0)} | OK |
 | う | (-2,2) | {(-2,0),(-2,1),(-2,2),(-1,0),(0,0)} | OK |
 | う | (-2,3) | {(-2,0),(-2,1),(-2,2),(-2,3),(-1,0),(0,0)} | OK |
 | R | (-1,3) | {(-2,0),(-2,1),(-2,2),(-2,3),(-1,0),(-1,3),(0,0)} | OK |

 再訪問は発生しません。 出力は`OK`。 

**サンプル 2:`LR`**

 | 移動 | コーディネート | 訪問 | 結果 |
 | --- | --- | --- | --- |
 | 開始 | (0,0) | {(0,0)} | - |
 | Ｌ | (-1,0) | {(0,0),(-1,0)} | OK |
 | R | (0,0) | {(0,0),(-1,0)} | 再訪問が検出されました |

 再訪問は次の時間に行われます`(0,0)`。 出力は`BUG`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各移動は 1 回処理されます。 セットの挿入と検索は平均 O(1) です。 
| スペース | O(n) | 長さ n のパスに対して最大 n+1 個の一意の座標が保存されます。 

n ≤ 100 の場合、指定された 2 秒、64 MB の制限では、これは簡単です。

 ## 特殊なケース

 最初の正方形にすぐに戻るパスを考えてみましょう。`UD`。 から開始するシミュレーション`(0,0)`、最初の動き`U`につながる`(0,1)`。 The next move`D`に戻ります`(0,0)`。 訪問した座標のセットにはすでに含まれています`(0,0)`、アルゴリズムは正しく出力します`BUG`。 

長い道のりのような`L*100 + R*100`、各移動は最初は新しい座標に拡張されますが、100 回の左移動の後、次の 100 回の右移動は同じパスをたどります。 訪問セットは最初に繰り返される座標を検出し、出力が次のようになります。`BUG`。 これにより、アルゴリズムが小さい自己交差と大きい自己交差の両方をエラーなく処理することが確認されます。 

座標を再訪しないすべてのパスは、たとえ形状が 2 倍に戻ったとしても (らせん状など)、次のような結果になります。`OK`、有効な最短パスの正しさを示します。 

この編集では、最短パスの有効性チェックの背後にあるロジックを完全に再構築し、自己交差パスを検出するための明確で再現可能な方法を提供します。
