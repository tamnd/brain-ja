 ## 解決策
 ## 問題の理解

 すべてのエッジがすでに 2 つのカテゴリのいずれかに属している無向グラフが与えられています。 標識のある道路`"S"`エルフが切り開く狭い道、そして標識が付けられた道路`"M"`サンタさんがクリアする広い道です。 

2 つの条件を同時に満たす道路のサブセットを選択する必要があります。 

まず、選択した道路がすべての小屋の上に木を形成する必要があります。 小屋の各ペアの間には、単純なパスが 1 つだけ存在する必要があります。これがスパニング ツリーの特徴です。 上のスパニングツリー`n`頂点には常に正確に含まれます`n - 1`エッジ。 

第二に、その数`"S"`エッジと`"M"`そのスパニング ツリー内のエッジは等しい必要があります。 

それはすぐに重要な観察を与えます。 木があるので、`n - 1`エッジの合計は偶数である必要があります。 そうしないと、2 つのタイプ間でエッジを均等に分割することができません。 

グラフの頂点の数は小さく、最大でも`1000`、ただしエッジの数は次の数に達します。`100000`。 これにより、ソリューションの形状が完全に変わります。 多くのエッジのサブセットを試行するアルゴリズムは絶望的ですが、DSU はほぼ一定の償却時間で実行されるため、繰り返しの DSU 操作に基づくアルゴリズムは十分に高速です。 アン`O(m α(n))`または`O(m log n)`解決策は容易に受け入れられます。 

見落としやすいエッジケースがいくつかあります。 

エッジの種類を無視しても、グラフはすでに切断されている可能性があります。```
4 2
1 2 S
3 4 M
```ここにはスパニング ツリーが存在しないため、正解は次のとおりです。`-1`。 

もう 1 つの微妙なケースは、1 つのエッジ タイプがスパニング ツリー内で十分な回数出現できない場合に発生します。```
3 2
1 2 S
2 3 S
```スパニング ツリーは存在しますが、含まれているのは`"S"`エッジ。 有効な回答には回答が必要なので、`"S"`そして1つ`"M"`エッジ、答えはまだある`-1`。 

自己ループも罠です。```
2 2
1 1 S
1 2 M
```自己ループはコンポーネントの接続には決して役立ちません。そのため、タイプごとにエッジを盲目的にカウントする不注意な実装では、自己ループが誤って受け入れられる可能性があります。 

平行なエッジも重要です。```
2 3
1 2 S
1 2 S
1 2 M
```スパニング ツリーに表示できるエッジは 1 つだけです。 アルゴリズムはすべてのエッジを独立して処理し、サイクルを形成する重複の追加を回避する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 上のスパニングツリー`n`頂点には正確に含まれます`n - 1`エッジがあるため、そのサイズのすべてのサブセットを試し、それがツリーを形成しているかどうかを確認し、エッジの数を確認できます。`"S"`そして`"M"`エッジは等しいです。 

有効な答えを定義する制約はテストしやすいため、これは論理的に機能します。 接続性と非周期性は両方とも DSU または DFS でチェックできます。 

問題はサブセットの数です。 最悪の場合は検査させていただきます$$\binom{100000}{999}$$サブセット、これは完全に不可能です。 

重要な点は、唯一難しい部分はエッジ タイプの数のバランスを取ることであるということです。 スパニングツリー構造自体は、DSU を使用して管理するのが簡単です。 

仮定する`k = (n - 1) / 2`。 有効なツリーには、正確に含まれている必要があります。`k` `"S"`エッジと正確に`k` `"M"`エッジ。 

ツリー全体を一度に構築するのではなく、実現可能範囲の観点から考えることができます。 

まず、最小数はいくらですか`"S"`スパニング ツリーに含まれなければならないエッジは何ですか? のみを使用してコンポーネントを貪欲に接続すると、`"M"`最初にエッジを使用し、その後、残りのすべての強制接続を使用する必要があります。`"S"`エッジ。 これにより、可能な最小限の数が得られます。`"S"`エッジ。 

同様に、貪欲に使用すると、`"S"`最初にエッジを取得し、可能な最大数を取得します。`"S"`エッジ。 

もし`k`がこの間隔の外にある場合、答えは存在しません。 

さらに良いのは、実現可能性が確認されたら、そのようなツリーを明示的に構築できることです。 まず正確に強制します`k` `"S"`スパニングツリーへの拡張性を維持しながらエッジを実現します。 次に、次を使用して残りの接続を終了します。`"M"`エッジ。 

ソリューション全体は、エッジ リストを通過する一連の DSU になります。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、それらを 2 つのリストに分割します。`"S"`エッジと`"M"`エッジ。 
2. もし`n - 1`奇数です、すぐに印刷してください`-1`。 

有効なスパニング ツリーでは、両方のエッジ タイプの数が等しい必要があるため、エッジの合計数は 2 で割り切れる必要があります。 
3. しましょう`k = (n - 1) / 2`。 
4. 可能な最小数を計算します。`"S"`スパニングツリーのエッジ。 

DSU を開始し、可能な限りすべてを貪欲に追加します`"M"`まずエッジ。 その後、追加してみてください`"S"`エッジ。 毎`"S"`実際に 2 つのコンポーネントをマージするエッジは避けられないため、カウントしてください。 
5. この最小値を超える場合`k`、印刷`-1`。 

すべてのスパニング ツリーには多すぎるものが含まれます`"S"`エッジ。 
6. 可能な最大数を計算します。`"S"`エッジ。 

別の DSU を開始し、可能な限りすべてを貪欲に追加します`"S"`まずエッジ。 何個追加されたかを数えてください。 
7. この最大値が以下の場合`k`、印刷`-1`。 

スパニング ツリーには十分な量を含めることができません`"S"`エッジ。 
8. 正確に構築する`k` `"S"`エッジ。 

新しい DSU から始めます。 まずは貪欲に追加`"S"`異なるコンポーネントを接続するときは必ずエッジを使用します。 これらのエッジを一時的に保存します。 

これにより、次を使用して最大の森が作成されます。`"S"`エッジ。 
9. そのうちのいくつか`"S"`エッジは不要かもしれません。 まさに必要なのは`k`。 

DSU を最初から再構築します。 保存されたものを反復処理する`"S"`エッジを追加し、正確になるまで 1 つずつ追加します`k`選ばれてきました。 
10. すべてのスキャンを続行します`"S"`またエッジ。 

まだ数が少ない場合は、`k`選択された`"S"`エッジは、異なるコンポーネントを接続するたびに追加します。 

この時点で、正確に`k` `"S"`森を形成するエッジ。 
11. 次を使用してスパニング ツリーを終了します。`"M"`エッジ。 

全体を反復処理する`"M"`エッジを追加し、その端点が異なるコンポーネントに属するエッジを追加します。 
12. 選択したエッジの総数が一致しない場合`n - 1`、印刷`-1`。 

それ以外の場合は、選択したエッジ インデックスを出力します。 

### なぜ効果があるのか

 最小および最大の実現可能性チェックは、標準のスパニングツリー交換引数に基づいています。 貪欲にできることはすべて取る`"M"`エッジにより必要な数が最小限に抑えられます`"S"`すべてのマージを使用して回避されたため、エッジ`"M"`別のものを強制するだけです`"S"`後で結合します。 対称引数は最大値を与えます。 

建設中に、選択された`"S"`エッジは常に非循環フォレストを形成します。 1 つ追加するたびに、以前に切断された 2 つのコンポーネントがマージされます。 実行可能区間はすでにそれを正確に証明しているので、`k` `"S"`エッジが達成可能、選択後に安全に停止できる`k`このようなエッジを作成し、次を使用して残りの接続を完了します。`"M"`エッジ。 

最終的な DSU 状態では、非周期性と接続性の両方が保証されます。 異なるコンポーネントを接続するエッジを追加するだけなので、サイクルは表示されません。 上のスパニングツリー`n`頂点と`n - 1`エッジは自動的に接続され、非循環になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    n, m = map(int, input().split())

    edges_s = []
    edges_m = []

    all_edges = []

    for idx in range(1, m + 1):
        u, v, t = input().split()
        u = int(u)
        v = int(v)

        edge = (u, v, idx)

        all_edges.append((u, v, t, idx))

        if t == 'S':
            edges_s.append(edge)
        else:
            edges_m.append(edge)

    if (n - 1) % 2:
        print(-1)
        return

    k = (n - 1) // 2

    # minimum possible number of S edges
    dsu = DSU(n)

    for u, v, _ in edges_m:
        dsu.union(u, v)

    min_s = 0

    for u, v, _ in edges_s:
        if dsu.union(u, v):
            min_s += 1

    if min_s > k:
        print(-1)
        return

    # maximum possible number of S edges
    dsu = DSU(n)

    max_s = 0

    for u, v, _ in edges_s:
        if dsu.union(u, v):
            max_s += 1

    if max_s < k:
        print(-1)
        return

    # build exactly k S edges
    dsu = DSU(n)

    useful_s = []

    for u, v, idx in edges_s:
        if dsu.union(u, v):
            useful_s.append((u, v, idx))

    dsu = DSU(n)

    answer = []
    used_s = 0

    for u, v, idx in useful_s:
        if used_s == k:
            break

        if dsu.union(u, v):
            answer.append(idx)
            used_s += 1

    for u, v, idx in edges_s:
        if used_s == k:
            break

        if dsu.union(u, v):
            answer.append(idx)
            used_s += 1

    # finish with M edges
    for u, v, idx in edges_m:
        if dsu.union(u, v):
            answer.append(idx)

    if len(answer) != n - 1:
        print(-1)
        return

    print(len(answer))
    print(*answer)

```最初の重要な詳細は分離です`"S"`そして`"M"`エッジ。 構造全体は、2 つのタイプを個別に処理することに依存します。 

最小および最大の実現可能性チェックでは、同じ DSU 構造が逆の順序で再利用されます。 順序付けが議論全体です。 すべて追加`"M"`エッジは最初に強制的にのみ残します`"S"`すべてを追加しながらマージします`"S"`エッジはまず、参加できるそのようなエッジの数を最大化します。 

建設フェーズは微妙な 2 段階構造になっています。 最初のパスオーバー`"S"`エッジは潜在的に役立つ可能性のある最大フォレストを計算します。`"S"`エッジ。 2 回目のパスでは、`k`彼らのうち。 

第 2 フェーズの前に DSU を再構築しないと、誤って多くの DSU を保持してしまうことになります。`"S"`エッジはすでに構造にマージされています。 

もう 1 つの簡単な間違いは、正確に到達すると仮定することです。`k` `"S"`エッジは接続を自動的に保証します。 そうではありません。 最後のパスオーバー`"M"`残りのすべてのコンポーネントを接続するには、エッジがまだ必要です。 

最終チェック`len(answer) != n - 1`切断されたケースをきれいにキャッチします。
