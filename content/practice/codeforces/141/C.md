 ## 解決策
 ## 問題の理解

 各人は、列の中で自分の前に背の高い人が何人立っていたかを 1 つの数字で覚えています。 元の順序も実際の高さももはやわかりません。 タスクは、すべての人の記憶値を満たす高さとともに、有効なキューの順序を再構築することです。 

人に価値があると仮定します`a = 2`。 つまり、前の 2 人は厳密にそれよりも身長が高くなければなりません。 同じ身長の人はカウントされません。 

興味深いのは、実際の高さが固定されていないことです。 相対比較によって必要なカウントが生成される限り、任意の正の整数を高さとして自由に割り当てることができます。 

制約`n ≤ 3000`は二次アルゴリズムにとって十分小さいです。 アン`O(n^2)`このソリューションは最悪の場合でも約 900 万回の操作を実行しますが、これは Python では十分に高速です。 三次アプローチは危険になります。`3000^3`は 270 億回の操作であり、2 秒以内ではまったく不可能です。 

主な問題は、記憶される値が位置に直接依存するのではなく、相対的な高さの順序に依存することです。 貪欲に人々を左から右に配置しようとする単純な試みは、後で簡単に罠にはまる可能性があります。 

次の例を考えてみましょう。```
3
a 0
b 1
c 0
```不注意で貪欲な戦略により、`a`まず、なぜなら`a=0`、 それから`c`、その後配置に失敗します`b`。 しかし、正しい配置は存在します。```
a 2
b 1
c 2
```ここだけ`a`よりも背が高いです`b`そして彼の前に立つ。 

もう 1 つの微妙なケースは、不可能性の検出です。```
2
a 1
b 1
```最初に立つ人にはその前に人がいないため、自分より背の高い人を 1 人要求することはできません。 解決策は存在しません。 

高さが同じであることも間違いの原因です。 厳密には背の高い人のみがカウントされるため、2 人が互いのカウントに影響を与えることなく同じ身長を共有する場合があります。 

例：```
3
a 0
b 0
c 1
```有効な割り当ては次のとおりです。```
a 2
b 2
c 1
```両方`a`そして`b`より背が高いです`c`, しかし、彼らはお互いより背が高いわけではありません。 

## アプローチ

 ブルートフォースアプローチでは、人々のすべての順列を試し、何らかの身長の割り当てが存在するかどうかを確認します。 単一の順列をチェックするだけでも簡単ではありません。なぜなら、taller-before の数を検証する必要があるからです。 あるので`n!`順列では、これは役に立たなくなります`n = 15`。 

条件の中に隠された構造を利用する必要があります。 

身長の低い順に人々を処理するとします。 人物を配置する場合、以前に処理されたすべての人物は背が低いか等しいため、その人物の前にある背の高い人の数には影響しません。 重要なのは、後で処理される人、つまり背の高い人だけです。 

これで視点が見事に逆転します。 

人々を次の基準で分類すると想像してみてください`a`。 大きめの人`a`彼らの前にはより背の高い人がいるはずなので、通常は背の高い人よりも右の方に表示される必要があります。 

重要な観察結果は次のとおりです。 

人が増えていくのを処理すれば`a`、次に、価値のある人を配置するとき`a`、彼らは位置を占めなければなりません`a`現在構築されているシーケンスの中にあります。 

なぜこれが機能するのでしょうか?

 その時点で、そのシーケンスに既に含まれている全員の身長が低いか同等になります。 将来の挿入は背の高い人に対応します。 現在の人がインデックスに挿入されている場合`a`、 その通り`a`将来、より背の高い人が後で彼らの前に現れる可能性があります。 

これにより、問題は建設的な挿入プロセスに変換されます。 

私たちは人を次の基準で分類します`a`、インデックスに各人物を繰り返し挿入します`a`現在のリストにあります。 

いつでも`a`現在のリストのサイズを超えているため、構成は不可能です。 

オーダーが構築された後、高さを割り当てます。 平等な人だから`a`同じ高さを共有できるため、同じグループごとに高さを圧縮します`a`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n²) | O(n) | 遅すぎる |
 | 最適 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての人をペアとして読みます`(name, a)`。 
2. 人数の多い順に並べ替える`a`。 

より小さい`a`値は、その前に背の高い人が少なくて済むため、最初に配置するのが簡単です。 
3. 構築中のキューを表すリストを維持します。 
4. ソート順に各人ごとに次のようにします。 

1. 必要な数を次のようにします。`a`。 
2. もし`a`が現在のキューの長さを超えているため、有効な位置が存在しません。 印刷する`-1`。 
3. それ以外の場合は、インデックスに人物を挿入します`a`。 

インデックスに挿入`a`それを正確に保証します`a`将来背の高い人がこの人より先に着くかもしれない。 
5. キューの順序が確定したら、高さを割り当てます。 

同じような人たち`a`お互いの身長が高いとみなすべきではないため、同じ身長を受け取ることができます。 
6. 最後のキューを左から右にたどります。 

1. 身長から始める`1`。 
2.現在の人の`a`前の人とは違う`a`、高さを上げます。 
3. Store the assigned height.
 7. Output the queue order together with heights.

 ### なぜ効果があるのか

 不変条件は、価値のある人を処理するとき、`a`、すでにキューに配置されている全員の身長は彼らより高くありません。 未来に挿入された人は背の高い人に相当します。 

インデックスに現在の人物を挿入することで`a`、 その通り`a`彼らの前のポジションは、将来の背の高い人のために残されています。 その後処理されたすべての人は、`a' ≥ a`, したがって、それらにはそれ以上の高さが割り当てられます。 厳密にはより高い高さのみが重要であり、同等であることは、`a`グループは高さを共有します。 

したがって、各人の前には、必要な数の背の高い人が正確に存在することになります。 

ある段階でしたら`a`現在のキュー サイズを超えている場合、その人の前に将来の背の高い人のために利用できる十分なポジションがないため、解決策は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    people = []
    for _ in range(n):
        name, a = input().split()
        people.append((name, int(a)))
    
    people.sort(key=lambda x: x[1])
    
    queue = []
    
    for name, a in people:
        if a > len(queue):
            print(-1)
            return
        
        queue.insert(a, (name, a))
    
    heights = {}
    current_height = 1
    
    for i, (name, a) in enumerate(queue):
        if i > 0 and a != queue[i - 1][1]:
            current_height += 1
        
        heights[name] = current_height
    
    for name, a in queue:
        print(name, heights[name])

solve()
```最初のフェーズでは、記憶されている価値観に基づいて人々を分類します。 後の挿入を背の高い人として解釈するため、この順序は重要です。 

リスト`queue`部分的に再構築された順序を保存します。 Pythonのリスト挿入は`O(n)`、これは許容されます`n ≤ 3000`。 

不可能条件は微妙。 もし`a > len(queue)`, その場合、たとえ将来のすべての人の身長が高くなったとしても、この人の前には十分なポジションがありません。 建設はただちに中止しなければなりません。 

高さの割り当ては、見た目よりも簡単です。 相対的な比較のみが重要です。 同一性を持つ人`a`値は互いに高いものとしてカウントされるべきではないため、同じ高さを安全に共有できます。 

コードは次の場合にのみ高さを増加します。`a`変化します。 最後のキューは構造的にすでに有効であるため、この圧縮された高さの割り当てにより、必要なすべてのカウントが保持されます。 

よくある間違いは、全員に厳密に増加する身長を割り当てることです。 それは誤って等しくなります-`a`人々はお互いを背の高いものとして数えます。

 ## 特殊なケース

 不可能な構成を考えてみましょう。```
2
a 1
b 1
```処理順序は変わりません。 最初の人は、キューが空の間、インデックス 1 に挿入する必要があります。 以来`1 > 0`、アルゴリズムはすぐに報告します`-1`。 

どのキューの最初の位置にもその前に誰もいないため、これは正しいです。 

ここで、等しい値を考えてみましょう。```
4
a 0
b 0
c 0
d 0
```すべての挿入は位置 0 で行われます。```
[d, c, b, a]
```すべての人は同じ高さを受け取ります。 自分より背の高い人は誰もいないので、すべての評価が満足されています。 

最後に、境界の挿入について考えてみましょう。```
4
a 0
b 1
c 2
d 3
```挿入順序:```
[a]
[a, b]
[a, b, c]
[a, b, c, d]
```各ユーザーは現在のキュー サイズで正確に挿入されます。つまり、最後に進みます。 これは次のことを証明します`a == len(queue)`は有効ですが、厳密にそれより大きな値のみは不可能です。
