 ## 解決策
 ## 問題の理解

 私たちは位置から一次元の軌道上を移動しています`0`位置を決める`L`。 歩くことは簡単で、1 メートルにかかる時間はちょうど 1 秒です。下に行かない限り、どちらの方向に進んでも構いません。`0`。 

ランプはショートカットを提供しますが、これを使用するには厳密な構造があります。 ランプ用`(x, d, t, p)`、ヴァシャはまず所定の位置に立たなければなりません`x - p`、その後、支出します`p`通常スキーで到達するまでの秒数`x`、そして最後に飛びます`x + d`で`t`秒。 飛行機はいつも右に進みます。 

これを通常の歩行と比較すると、`x - p`に`x + d`徒歩だと費用がかかります`p + d`秒。 代わりにランプを使用するとコストがかかります`p + t`秒。 ランプは次の場合にのみ役立ちます。`t < d`。 

タスクは、最小合計時間を計算するだけでなく、どのランプが使用されるかを再構築することも必要です。 

この制約により、二次最短経路構築は即座に除外されます。 まであります`10^5`ランプがあるため、すべてのペアごとの遷移を構築する場合でも、約`10^10`限界をはるかに超えたエッジ。 に近いものが必要です`O(n log n)`。 

トラックの長さ`L`到達できる`10^9`、つまり、ポジションを超えて DP を構築することはできません。 ランプのエンドポイントのみが重要です。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

準備セグメントがゼロより前から始まるため、ランプは使用できない場合があります。 

例：```
1 20
4 10 1 7
```ランプは次から開始する必要があります`-3`、これは禁止されています。 正解はただ歩くこと`20`秒。 

スロープは、たとえ到達可能であっても役に立たない場合もあります。 

例：```
1 20
5 3 10 2
```そのセクションを歩くと費用がかかります`2 + 3 = 5`、スロープには費用がかかりますが、`2 + 10 = 12`。 到達可能なすべてのランプを盲目的に取得する実装では、最適ではない答えが生成されます。 

もう一つの微妙なケースは後退している。 このステートメントにより、両方向への移動が許可されます。 不注意で貪欲な解決策では、離陸点の昇順でランプを使用する必要があると想定する可能性があります。 ローカルでは必ずしもそうとは限りません。 それでも、最適なグローバル構造は圧縮後に非循環であることが判明し、それを証明することが問題の重要な洞察です。 

例：```
2 30
10 10 1 1
5 20 100 1
```2 番目のランプはひどいですが、最初のランプは素晴らしいです。 ベストルートはやはり単調な右へ。 

## アプローチ

 ブルート フォース ビューは、すべてのランプを状態としてモデル化します。 1 つのランプから別のランプの準備ポイントまで歩いて、次にそれを使用できます。 直接歩いて終了することもできます`L`。 

各ノードがランプに加え、開始ノードと終了ノードを表すグラフを定義するとします。 現在の位置にいる場合`a`、別のランプが で準備を開始します。`b`、そこまで歩くと費用がかかります`|a - b|`。 ランプを使用すると飛行時間が追加されます。 

すべての有効なルートがグラフ内のパスになるため、このグラフは正しいです。 残念ながら、すべてのランプは他のすべてのランプに移行する可能性があるため、グラフは次のようになります。`O(n^2)`エッジ。 と`10^5`ランプ、これは完全に不可能です。 

重要な観察は、ランプの外の世界は非常に単純であるということです。 2 つの位置間の歩行コストは直線距離にすぎません。 つまり、実際には任意の遷移は必要ありません。 

スロープを検討してください`(x, d, t, p)`。 これを使用すると、一定の長さの区間を歩くことになります`p + d`の費用で`p + t`。 純粋な歩行と比較して、ランプにより合計は次のように変化します。$$t - d$$準備部分はキャンセルされます。 

これにより問題全体が変わります。 Vasyaがいつもそこから歩いていることを想像してみてください`0`に`L`、支払い`L`秒。 使用されるすべてのランプは追加の価値に貢献します`t - d`。 良いランプは満足するので`t < d`、合計を減らします。 

ここで必要なのは、ランプをチェーンできるかどうかだけを知ることだけです。 ランプ`A`で終わる`x_A + d_A`ランプの後に続くことができます`B`もし：$$x_B - p_B \ge x_A + d_A$$なぜなら、私たちは彼らの間を前進できるからです。 

後ろ向きに歩くことは決して有益ではありません。 後方に移動すると、歩行距離が増えるだけであり、スロープ自体は左に移動することはありません。 逆方向の動きを伴うパスは、大きなコストをかけずに単調なパスに直線化できます。 

これにより、位置順に並べられた DAG が得られます。 

準備開始点によってソートされたランプ上で最短パス DP を実行できるようになりました。 遷移は次のようになります。$$dp[i] = (t_i - d_i) + \min dp[j]$$すべてのスロープの上で`j`ランプの前で終わる`i`準備が始まります。 

これは古典的なスイープラインの最小クエリの問題です。 ソートされた順序でランプを処理するため、着地位置がすでに到達可能なランプの中で最良の DP 値が維持されます。 

プライオリティ キューまたは順序付きスイープにより、複雑さが軽減されます。`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグラフ | O(n²) | O(n²) | 遅すぎる |
 | スイープラインDP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのランプを破棄します。`x - p < 0`。 

スタートラインより前から準備が始まるため、このようなスロープは決して使用できません。 
2. 残りのランプごとに、次を計算します。$$s = x - p$$そして$$e = x + d$$ここ`s`は準備開始位置、`e`着陸位置です。 
3. ランプを並べ替える`s`。 

これにより、以前のどのランプを現在のランプに接続できるかを維持しながら、ランプを左から右に処理できます。 
4. 定義する`dp[i]`最後に使用したランプがランプである場合の純粋な歩行に対する最小の追加コストとして`i`。 

トラック全体を歩くと費用がかかるため、`L`、最終的な答えは次のようになります。$$L + \min(0, dp[i])$$5. 最初から直接使用される 1 つのランプの場合、追加コストは次のとおりです。$$t_i - d_i$$から歩いているので`0`に`L`準備距離と着陸距離がすでに含まれています。 
6. 着陸位置順のランプの優先構造を維持する`e`。 

ランプの処理中`i`、以前のすべてのランプ`e \le s_i`それに先行することができます。 
7. 現在有効なすべての先行ランプの中で最小の DP 値を追跡します。 

それから：$$dp[i] = (t_i - d_i) + best$$どこ`best`どちらかです`0`直接開始する場合、または最小の先行 DP。 
8. 先行者が値を改善するたびに、親ポインタを保存します。 

これにより、選択したランプの再構築が可能になります。 
9. すべてのランプを処理した後、次の中から最適なものを選択します。`L`スロープなしで、

 または$$L + dp[i]$$すべてのランプに。 
10. 親ポインターを使用してパスを再構築し、元のランプ インデックスを出力します。 

### なぜ効果があるのか

 不変条件は、準備開始の昇順でランプを処理している間、維持される最小 DP 値が現在のランプに合法的に先行できるすべてのランプに正確に対応するということです。 

すべてのランプは厳密に右に移動するため、実行可能なランプのシーケンスは単調なチェーンを形成します。 ランプ間の歩行は位置によって一意に決定されるため、唯一意味のある最適化は、歩行に代わる有益なセグメントを選択することです。 

DP には、ベースライン ウォーキングを超える最小の追加コストが保存されます。 すべてのランプが独立して貢献します`t - d`、有効な遷移には重複しない順序のみが必要です。$$e_j \le s_i$$したがって、すべての実行可能なソリューションは DP 内で 1 回だけ表現され、すべての DP 遷移は有効なルートに対応します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())

    ramps = []

    for idx in range(1, n + 1):
        x, d, t, p = map(int, input().split())

        s = x - p
        if s < 0:
            continue

        e = x + d
        gain = t - d

        ramps.append((s, e, gain, idx))

    ramps.sort()

    m = len(ramps)

    dp = [0] * m
    parent = [-1] * m

    heap = []

    best_value = 0
    best_idx = -1

    answer = L
    answer_idx = -1

    ptr = 0

    by_end = sorted(
        [(ramps[i][1], i) for i in range(m)]
    )

    for s, end_idx in by_end:
        pass

    events = sorted(
        [(ramps[i][1], i) for i in range(m)]
    )

    ptr = 0

    for i in range(m):
        s_i, e_i, gain_i, orig_i = ramps[i]

        while ptr < m and events[ptr][0] <= s_i:
            _, j = events[ptr]

            heapq.heappush(heap, (dp[j], j))
            ptr += 1

        if heap:
            best_value, best_idx = heap[0]
        else:
            best_value, best_idx = 0, -1

        dp[i] = gain_i + best_value
        parent[i] = best_idx

        total = L + dp[i]

        if total < answer:
            answer = total
            answer_idx = i

    path = []

    cur = answer_idx

    while cur != -1:
        path.append(ramps[cur][3])
        cur = parent[cur]

    path.reverse()

    print(answer)
    print(len(path))

    if path:
        print(*path)
    else:
        print()

```この解決策は、無効なランプをフィルタリングすることから始まります。 これは重要です。`x - p < 0`準備を始めることさえできないので、決してDPに参加してはなりません。 

各ランプは、その準備開始を含むコンパクトな形式に変換されます`s`、着陸地点`e`、および貢献`t - d`。 普通の歩行をベースライン コストとして扱うと、その寄与分が最適化に影響を与える唯一の部分になります。 

ランプは次の基準で並べ替えられます。`s`これにより、すべての有効な先行処理が処理順序の最初に現れることが保証されます。 

微妙な部分は、到達可能な最良の先行ファイルを維持することです。 以前のランプをすべてスキャンすると二次複雑さに戻ってしまうため、スキャンすることはできません。 代わりに、着地位置がすでに十分に小さいランプを処理します。 ランプが次の条件を満たすと、```
e_j <= s_i
```将来のすべてのランプに永続的に適格になります。`s_i`価値は上がるだけです。 

ヒープにはペアが格納されます`(dp[j], j)`, そのため、先頭は常に到達可能な最小の DP 値を与えます。 

よくある間違いは、有益なランプをすべて貪欲に使用しようとすることです。 個別に優れた 2 つのランプが重なって互換性がなくなる場合があります。 DP は、次の準備開始前に着地点が存在するランプからのみ移行することでこれを回避します。 

もう 1 つの簡単なバグは、最適なソリューションではランプをまったく使用しない可能性があることを忘れていることです。 最初の答えは次のように設定されています`L`、純粋な歩行を表します。 

値はおよそに達する可能性があるため、すべての算術演算は Python の整数に安全に適合します。`10^14`。
