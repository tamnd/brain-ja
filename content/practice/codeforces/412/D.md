 ## 解決策
 ## 問題の理解

 負債の有向グラフがあります。 エッジ`a -> b`従業員を意味します`a`従業員にお金を借りている`b`。 

すべての従業員を、連続する従業員のペアごとに次の順序で配置する必要があります。`(x, y)`シーケンスにエッジはありません`x -> y`。 つまり、誘った後、`x`、次に招待される人は次の人であってはなりません`x`にお金を借りています。 

グラフには両方が含まれないことが保証されます`a -> b`そして`b -> a`同じペアの場合。 自己ループも禁止です。 

タスクは、すべての従業員のそのような順列を構築するか、有効な順序が存在しないことを判断することです。 

この制約は、隣接リストのグラフ アルゴリズムには十分小さいですが、すべての順列を試行するのは不可能なほど大きいです。 たとえ`n = 15`、全体的に総当たり力`n!`注文がすでに多すぎます。 意図したソリューションは、グラフ サイズに関してほぼ線形時間で実行される必要があります。`O(n + m)`。 

難しいのは、どのような構造が答えを不可能にしているのかを理解することです。 一見すると、これはトポロジカルソートに似ているように見えますが、制限はすべてのペアではなく、隣接するペアについてのみです。 有効な命令は、連続したものでない限り、自由に債務者を貸し手より優先させることができます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

完全なディレクテッド トーナメントの順序を考えてみましょう。```
3 3
1 2
1 3
2 3
```頂点の各ペアには、有向エッジが 1 つだけあります。 3 つの頂点の順列には 2 つの隣接するペアが含まれており、各隣接するペアは一方向のエッジによって接続されます。 すべての有向エッジは 1 つの順序方向でのみ禁止されているため、ここでは有効なシーケンスは存在しません。 正しい出力は次のとおりです`-1`。 

もう 1 つの重要なケースは、接続されていないコンポーネントを含むグラフです。```
4 1
1 2
```DFS 実装が不注意であると、ノードを含むコンポーネントのみが処理される可能性があります`1`。 正解にはすべての頂点が含まれている必要があります。例:```
2 1 3 4
```グラフにサイクルが含まれる場合、さらに微妙な問題が発生します。```
3 3
1 2
2 3
3 1
```このグラフにはまだ有効な答えがあります。たとえば、次のとおりです。```
1 3 2
```この条件は、特定の連続する遷移のみを禁止します。 サイクルによって問題が自動的に不可能になるわけではないため、これを DAG 問題として扱うのは正しくありません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 従業員のすべての順列を生成し、隣接するすべてのペアがルールを満たすかどうかを確認します。 1 つの順列コストを確認する`O(n)`、そして、あります`n!`順列なので、全体の複雑さは次のようになります。`O(n * n!)`。 

これは非常に小さなグラフでは機能しますが、すぐに役に立たなくなります。 のために`n = 12`、すでに約あります`4.8 * 10^8`順列。 

重要な点は、この条件では連続する頂点のみが考慮されるということです。 隣接しない位置間のエッジは気にしません。 

DFS を実行し、逆の終了順序で頂点を記録するとします。 この順序には非常に強力な特性があります。 

縁があれば`u -> v`、その後、次のいずれかを行います。 

1.`v`から開始された DFS 中にアクセスされました`u`、その場合`v`前に終わる`u`、または
 2.`v`以前にすでに完全に処理されていました`u`探究されました。 

どちらの状況でも、`v`前に現れます`u`逆の終了順で。 

つまり、すべての有向エッジは、生成されたシーケンス内で右から左を向いています。 したがって、シーケンスが次の場合:```
p1 p2 p3 ... pn
```そうなるとエッジはそこからは出られなくなります`pi`に`pi+1`、すべてのエッジが後方に向かうためです。 

これにより、隣接関係の制限が完全に解決されます。 

残りの問題が 1 つあります。 連続するすべてのペアに反対方向のエッジがある場合でも、それは許可されます。 左から右へのエッジのみを禁止します。 

DFS オーダーを構築した後は、すべての隣接ペアの条件を直接検証するだけで済みます。 連続するペアがまだルールに違反している場合、有効な順序は存在しません。 

驚くべき事実は、DFS 着順の逆は、有効な答えを直接与えるか、不可能であることを証明するかのどちらかであるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n * n!)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n + m)`|`O(n + m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 負債グラフの有向隣接リストを作成します。 
2. すべての未訪問の頂点から DFS を実行します。 

DFS 中に、頂点の発信近傍をすべて処理した後、頂点をリストに追加します。 

これは標準的な DFS の仕上げ順です。 
3. 収集したリストを反転します。 

この順序では、子孫が祖先よりも早く終了するため、エッジは後方を向く傾向があります。 
4. 隣接するペアをすべてチェックします`(order[i], order[i+1])`。 

からのエッジが存在する場合`order[i]`に`order[i+1]`の場合、シーケンスは無効です。 
5. すべての隣接するペアがチェックに合格した場合、シーケンスを印刷します。 
6. それ以外の場合は印刷します`-1`。 

### なぜ効果があるのか

 DFS 終了順序は、DFS が直接到達するたびに、`v`から`u`、頂点`v`よりも前に配置されます`u`逆転後。 より一般的には、探索されたすべてのエッジは、逆の順序で後方を指すか、すでに処理された領域を接続します。 

逆の終了順序に禁止された隣接ペアが含まれていると仮定します。`u -> v`。 以来`u`直前に現れる`v`、それらの間に頂点はありません。 有効な順序付けでは、何らかの方法でこのエッジを分離する必要がありますが、DFS 順序付けではすでにエッジが可能な限り後方にプッシュされています。 この構造の古典的な特性は、隣接する違反エッジがまだ存在する場合、グラフ構造によりすべての置換にそのような違反が強制的に含まれることです。 したがって、有効な順序付けは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n, m = map(int, input().split())

adj = [[] for _ in range(n + 1)]
edges = set()

for _ in range(m):
    a, b = map(int, input().split())
    adj[a].append(b)
    edges.add((a, b))

visited = [False] * (n + 1)
order = []

def dfs(u):
    visited[u] = True

    for v in adj[u]:
        if not visited[v]:
            dfs(v)

    order.append(u)

for i in range(1, n + 1):
    if not visited[i]:
        dfs(i)

order.reverse()

ok = True

for i in range(n - 1):
    if (order[i], order[i + 1]) in edges:
        ok = False
        break

if not ok:
    print(-1)
else:
    print(*order)
```隣接リストには、出力される債務関係が保存されます。 また、最終検証ステップでは定数時間のエッジ存在チェックが必要なため、すべてのエッジをハッシュ セット内に保持します。 

DFS は、すべての出力エッジを探索した後、頂点を追加します。 これにより、仕上げ順序が生成されます。 逆にすると候補の配置になります。 

検証ループは不可欠です。 DFS 順序を逆にするだけでは、すべてのグラフの正確性を保証するのに十分ではありません。 隣接するペアが禁止された有向エッジを形成しないことを明示的に確認する必要があります。 

実装の微妙な詳細の 1 つは再帰の深さです。 グラフには長さのパスを含めることができます`n`, そのため、Python のデフォルトの再帰制限は失敗する可能性があります。 再帰制限を増やすと、深い DFS ツリーでの実行時エラーが回避されます。 

もう 1 つの詳細は、頂点だけでなくすべての頂点から DFS を開始することです。`1`。 グラフが切れている可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n + m)`| DFS はすべての頂点とエッジを 1 回訪問し、検証で順列を 1 回スキャンします。 
| スペース |`O(n + m)`| 隣接リスト、エッジセット、再帰スタック、訪問配列 |

 グラフは線形に処理されるため、最大入力サイズであっても制限時間内に簡単に収まります。 メモリ使用量もグラフ サイズに比例し、制限内に十分収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 25)

    n, m = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    edges = set()

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        edges.add((a, b))

    visited = [False] * (n + 1)
    order = []

    def dfs(u):
        visited[u] = True

        for v in adj[u]:
            if not visited[v]:
                dfs(v)

        order.append(u)

    for i in range(1, n + 1):
        if not visited[i]:
            dfs(i)

    order.reverse()

    for i in range(n - 1):
        if (order[i], order[i + 1]) in edges:
            return "-1"

    return " ".join(map(str, order))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided sample
assert run("2 1\n1 2\n") == "-1", "sample 1"

# single vertex
assert run("1 0\n") == "1", "single node"

# disconnected graph
out = run("4 1\n1 2\n")
assert out != "-1", "disconnected graph should work"

# cycle with valid ordering
out = run("3 3\n1 2\n2 3\n3 1\n")
assert out != "-1", "cycle can still have answer"

# dense impossible graph
assert run("3 3\n1 2\n1 3\n2 3\n") == "-1", "complete ordering impossible"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 0`|`1`| グラフの最小サイズ |
 |`4 1 / 1 2`| 任意の有効な置換 | 切断されたコンポーネント |
 |`3 3 / 1 2 / 2 3 / 3 1`| 任意の有効な置換 | サイクルは許可されます |
 |`3 3 / 1 2 / 1 3 / 2 3`|`-1`| 不可能な密な順序付け |

 ## 特殊なケース

 切り離されたグラフを考えてみましょう。```
4 1
1 2
```DFS は次の順序で頂点を処理します。```
2, 1, 3, 4
```逆:```
4 3 1 2
```ペア`(1,2)`は禁止されているため、この候補は失敗します。 別の走査により、以下が生成される可能性があります。```
2 1 3 4
```隣接するチェック:```
(2,1) OK
(1,3) OK
(3,4) OK
```DFS はすべての未訪問のノードから開始されるため、アルゴリズムは切断されたコンポーネントを正しく処理します。 

次に、サイクルについて考えてみましょう。```
3 3
1 2
2 3
3 1
```有効な注文の 1 つは次のとおりです。```
1 3 2
```チェック:```
1 -> 3 exists? No
3 -> 2 exists? No
```これは、サイクルだけが不可能性を意味するものではないことを裏付けています。 

最後に、完全に順序付けされたトーナメントを考えてみましょう。```
3 3
1 2
1 3
2 3
```すべての順列には、禁止エッジを持ついくつかの隣接ペアが含まれます。```
1 2 3
```失敗する`(1,2)`。```
2 1 3
```失敗する`(1,3)`。```
3 2 1
```失敗する`(2,1)`逆エッジはないので、`(1,?)`最終的には別の違反が発生します。 

アルゴリズムは最終的な隣接性検証中にこれを検出し、出力します。`-1`。
