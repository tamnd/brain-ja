 ## 解決策
 ## 問題の理解

 長さの 2 つの配列が与えられます$n$。 アリスは$n$固定値を持つカード、ボブも持っています$n$カードは固定された順序でプレイされます。 以上$n$ラウンドでは、アリスはカードをプレイする順序を選択できます。 各ラウンドで、2 つの明らかにされた値が比較されます。 アリスの値がすでにボブの値以上である場合は、何も起こりません。 それ以外の場合、彼女は現在のカードを 1 ずつ増やす操作を繰り返し適用する必要があります。$k$それが少なくともボブの価値になるまで、そしてそのような各操作はコストの 1 単位としてカウントされます。 

目標は、アリスのカードを並べ替えて、すべてのラウンドにわたるこれらの「+k 増分」の合計数を最小限に抑えることです。 

単一ラウンドのコストを解釈する便利な方法は、アリスがバリューをプレイした場合、$a$に対して$b$、必要な操作の数は正確に$$\left\lceil \frac{\max(0, b - a)}{k} \right\rceil.$$これにより、問題は、アリスのマルチセットとボブの固定シーケンスの間のペアリング順序の選択に変わります。 

制約$n \le 10^5$すぐに除外します$O(n^2)$すべての順列にわたる戦略またはシミュレーションのマッチング。 通常、ソートまたは貪欲なマッチングに近いものが必要です。$O(n \log n)$。 

最小値から最小値、または最大値から最大値を個別に貪欲に一致させることができると仮定すると、素朴な危険が生じます。 各ペアリングのコストは、ペアとの相対的なギャップに依存するため、これは失敗します。$k$、ただ注文するだけではありません。 

たとえば、次のように考えてみましょう$k = 5$、アリスカード$[1, 6]$、ボブシーケンス$[5, 10]$。 アリスが遊ぶなら$1 \to 5$、コストは 1、そして$6 \to 10$コストは 1、合計 2。彼女が一致しない場合、$1 \to 10$コスト2、$6 \to 5$コストは0、合計も2です。 これは、ローカル推論は微妙ですが、より大きなインスタンスでは単純なペアリング ルールを破る可能性があることを示しています。 

主な問題点は、各アリス カードが事実上ボブの要件に対する「予算カバー」であるため、大幅な赤字が可能な限り回避されるように、異なるボブの値をアリスの値に割り当てる必要があることです。 

## アプローチ

 ブルートフォースアプローチでは、アリスのカードのすべての順列を試し、ボブの固定シーケンスとの各ペアのコストをシミュレートします。 これは正しいですが、複雑さの要因となります。$n!$課題と各評価コスト$O(n)$、につながる$O(n \cdot n!)$、それはたとえ小さくても実行不可能です$n$。 

より構造化された総当たり攻撃は、アリスのマルチセットとボブのシーケンスの間の割り当て問題として考えることです。 これは最小コストの一致を示唆していますが、上限による分割によりコスト関数は単純には線形ではありません。$k$。 それでもコストは隙間で単調$b_i - a_j$、貪欲な構造を示唆しています。 

重要な観察は、剰余モジュロのみが$k$必要な増分数を決定する際に重要になります。 各アリス カードは、ボブの要件をいくつかのサイズに分割してカバーしていると考えることができます。$k$無駄な増分を最小限に抑えたいと考えています。 これにより、「最もカバーしにくい」ボブ カードと入手可能な最も強力なアリス カードを組み合わせる方向に進むことになりますが、注意が必要です。大きな天井ジャンプを回避するのであれば、わずかに弱いアリス カードが依然として最適である可能性があるという事実を考慮する必要があります。 

この構造は、片側が順番に固定されている、ソートされた配列間の貪欲なマッチングの典型的なものです。 最適な戦略は、ボブのシーケンスを順番に処理し、コストの増加を最小限に抑える可能な限り最良のアリス カードを常に割り当てるときに現れます。 

私たちはアリスのカードをソートされた構造に維持し、ボブの値ごとに、必要以上にコストを悪化させない最小のアリス カードを選択します。 存在しない場合は、最小のものを採用し、超過コストを支払います。 これにより、問題はマルチセット上で繰り返される後続クエリに軽減されます。

 ## アルゴリズムのチュートリアル

 ボブのカードを指定された順序で処理し、アリスのカードを動的に割り当てます。 

1. アリスのカードを昇順にソートし、バランスの取れたツリーや二分探索でソートされたリストなど、除去をサポートする構造にそれらを保管します。 これにより、各ラウンドで常に最良の残りの候補を選択できるようになります。 
2. 各ボブカードについて$b_i$、アリスカードを選びたいです。$a$それは最小限に抑えます$\lceil (b_i - a)/k \rceil$。 もし$a \ge b_i$、コストはゼロなので、私たちは常にそのようなカードを最初に選ぶようにします。 
3.アリスカードが存在する場合$\ge b_i$、そのような最小のカードを選択します。 これにより、コストゼロを保証しながら、大きなカードを不必要に浪費することがなくなります。 実行可能な最小の候補を削除すると、将来のより困難なボブの値に備えてより強力なカードが保存されます。 
4. そのようなカードが存在しない場合は、いくつかのカードを選択する必要があります$a < b_i$。 費用は$\lceil (b_i - a)/k \rceil$、だから私たちは欲しいのです$a$隙間を最小限に抑えるために、できるだけ大きくします。 したがって、残っている最大のアリス カードを選択します。 
5. カードを選択した後、出力順列にそのインデックスを記録し、利用可能なセットからカードを削除します。 
6. 選択したペアの上限計算式を使用してコストを累積します。 

このプロセスは、すべてのラウンドが割り当てられるまで続きます。 

### なぜ効果があるのか

 アルゴリズムは局所的な最適性条件を維持します。ボブの各ステップで、コストを回避する最小のアリス カード、またはコストが避けられない場合は最大のアリス カードのいずれかを選択します。 これらの選択肢から逸脱した場合は、総コストを増加させることなく、選択したカードと交換できます。 特に、ソリューションがゼロコストの状況で必要以上に大きいカードを使用している場合、それを実行可能な小さいカードと交換することで、将来のステップの実行可能性を維持しながら、後でより強力なカードを解放できます。 同様に、コストが避けられないソリューションで小型のカードが使用されている場合、それをより大型のカードに交換すると上限ギャップが減り、厳密にコストが改善または維持されます。 これらの交換引数により、貪欲な構造によって将来の最適な割り当てがブロックされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_cost(a, b, k):
    if a >= b:
        return 0
    return (b - a + k - 1) // k

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # store (value, original_index)
    A = sorted([(a[i], i) for i in range(n)])

    import bisect

    values = [x[0] for x in A]
    used = [False] * n
    remaining = list(range(n))

    # we simulate a sorted multiset via list + bisect + lazy removal
    # to keep explanation simple and deterministic for CF style
    alive = A

    # we maintain indices in a list; we will rebuild when needed
    import bisect

    alive_vals = [x[0] for x in alive]
    alive_ids = [x[1] for x in alive]

    def remove_at(pos):
        alive_vals.pop(pos)
        alive_ids.pop(pos)

    ans_cost = 0
    res = []

    for bi in b:
        # find first >= bi
        pos = bisect.bisect_left(alive_vals, bi)

        if pos < len(alive_vals):
            # take smallest >= bi
            ans_cost += 0
            res.append(alive_ids[pos])
            remove_at(pos)
        else:
            # take largest < bi
            pos = len(alive_vals) - 1
            a_val = alive_vals[pos]
            ans_cost += (bi - a_val + k - 1) // k
            res.append(alive_ids[pos])
            remove_at(pos)

    print(ans_cost)
    print(*[x + 1 for x in res])

if __name__ == "__main__":
    solve()
```このコードは、アリスの残りのカードを値ごとにソートして維持し、二分探索で現在のボブ カードにゼロコストのオプションが存在するかどうかを判断できるようにします。 そのようなカードが存在する場合、より強力なカードを保存するために、条件を満たす最小のカードが削除されます。 それ以外の場合は、必要な枚数を最小限に抑えるために、残っている最も強力なカードが選択されます。$+k$増加します。 結果リストには元のインデックスが保存され、最終的に順列として出力されます。 

唯一の微妙な実装上の問題は、Python リストの途中からの削除です。$O(n)$。 厳しい制約では、これによりパフォーマンスが低下する可能性があります。 実際には、`sortedcontainers`構造またはバランスの取れたツリーが目的のツールです。 貪欲ロジック自体は、コンテナーの選択とは無関係です。

 ## 特殊なケース

 重大なエッジケースは、すべてのアリス カードがすべてのボブ カードよりも小さい場合です。 その状況では、すべてのラウンドにコストが発生し、貪欲なルールにより常に最大の残りのアリス カードが選択されます。 これにより、個々の天井ジャンプが最小限に抑えられ、早い段階で弱いカードを使用することによる余分な増分の蓄積が回避されます。 

もう 1 つのエッジ ケースは、すべてのアリス カードがすでに十分な大きさになっている場合です。 アルゴリズムは常に実行可能な最小のカードを選択するため、より強力なカードは保存されますが、必要になることはなく、総コストはゼロになります。 

混合ケースを見ると、順序が重要である理由がわかります。 大きなボブ値が早い段階で出現した場合、アルゴリズムは非常に強力なアリス カードを即座に消費する可能性があります。 これを遅らせると後でさらに大きなコストが強制されるか、構造的により価値のあるゼロコストの割り当てがブロックされるだけであるため、これは依然として最適です。
