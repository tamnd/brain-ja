 ## 解決策
 ## 問題の理解

 私たちは整数線上に位置を持つ 1 次元のゲーム世界を与えられています。 座標 0 から n までの柱があり、柱 i には i ≥ 1 で宝の値 ai があり、柱 0 は出発点で宝はありません。 位置 n+1 の先には安全な無限プラットフォームがあり、そのプラットフォームのどこかに到達するとゲームは正常に終了します。 

移動は、現在位置から座標がより大きい別の位置へ厳密に右にジャンプすることで構成され、すべてのジャンプの長さは最大 p です。 プレーヤーは位置 0 から開始し、柱に着地するか、最終的には最終プラットフォームに着地する必要があり、目標はプラットフォームに到達することです。 

工夫としては、各クエリでレベル x が定義され、レベル x では、プレーヤーはインデックスが x の倍数である柱を踏むことのみに制限されます。 したがって、すべての柱を考慮するのではなく、インデックス x、2x、3x などを最大 n まで保持します。 これらの許可された柱の中で、ジャンプ制限 p を考慮して 0 から始まり、最終的にプラットフォームに到達する有効な増加シーケンスが必要です。 スコアは、訪問したすべての柱の ai の合計です。 

各クエリは、そのレベルで可能な最大スコアを要求するか、有効なパスがプラットフォームに到達できない場合は不可能を報告します。 

制約 n と q は最大 10^6 であるため、許可されたすべてのジャンプを個別にシミュレートすることによって各クエリを処理するソリューションは失敗します。 クエリあたり O(n) であっても、最悪の場合、すでに 10^12 の演算を超えてしまいます。 これにより、開始除数構造ごとに効率的に前処理し、すべてのクエリにわたる合計作業量が線形または線形に近い状態に保たれるようにする必要があります。 

いくつかのエッジの状況は見逃しがちです。 

x が p より大きい場合、0 からピラー x への最初のジャンプはジャンプ制限を超えているため、すでに不可能です。 たとえば、p = 3 および x = 5 の場合、シーケンスを開始することさえできないため、答えは直ちに不可能になります。 

もう 1 つの微妙なケースは、プラットフォームに到達することです。 選択したピラーを通る適切なパスを計算したとしても、n + 1 − j ≤ p を満たすためには最後のピラー j が必要です。 たとえば、n = 10 および p = 2 の場合、11 − 8 ≤ 2 が成立しない限り、ピラー 8 に到達するだけでは十分ではありません。そうでない場合は、終了できません。 

最後に、有効な位置の構造は x に大きく依存します。 クエリが異なると、許可されるノードのセットが完全に変わるため、算術構造を利用しない限り、すべてのノードにわたるグローバル DP を直接再利用することはできません。 

## アプローチ

 各クエリの直接シミュレーションでは、x の倍数のシーケンスが構築され、それらに対して動的プログラムが実行されます。 倍数 i = kx から、j < i および i − j ≤ p で以前のすべての倍数 j = tx を試し、到達可能な最良の合計を取得します。 これは問題を正しくモデル化しますが、クエリごとに O(n/x) 個のノードをスキャンし、各ノード内で最大 O(p/x) 個の先行ノードをスキャンする可能性があり、最悪の場合は 2 次の動作が発生します。 

重要な簡略化は、固定レベル x 内で、許可されるすべてのノードが x、2x、3x などの等間隔に配置されていることを観察することによって得られます。 このシーケンスで位置をインデックス k で書き直すと、k から前の有効な位置 k' への移動は、座標での距離 (k − k')x に相当します。 ジャンプ制約 (k − k′)x ≤ p は k − k′ ≤ ⌊p / x⌋ になります。 これにより、遷移が k でインデックス付けされた DP 配列上の固定サイズのスライディング ウィンドウに変わります。 

したがって、各クエリはスライディング ウィンドウの最大値を伴う行内の最長パスの問題になり、これは x の倍数にわたる線形時間の単調デキューで維持できます。 

これをクエリと効率的に結び付ける必要があります。 各クエリは独立していますが、同じ構造を使用しているため、この最適化された DP を使用して 1 から n までのすべての x に対する答えを事前計算します。 合計の仕事は調和的になり、n/1 + n/2 + n/3 + …、つまり O(n log n) になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(q · n) 最悪の場合 | O(n) | 遅すぎる |
 | スライディング ウィンドウを備えた Per-x DP | O(n log n) 合計 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各レベル x について、許可される柱のシーケンス x、2x、3x、…、mx (mx ≤ n) に制限します。 

1. 元の制約をシーケンス インデックスに変換します。 k 番目のノードを、値 a[kx] を持つ位置 kx として定義します。 これにより、問題は整数の疎なグラフから単純なチェーンに縮小されます。 
2. 開始できるかどうかを判断します。 最初の移動は 0 から x までであるため、これは x ≤ p の場合にのみ可能です。 x > p の場合、このレベルに有効なパスが存在しないことがすぐにわかります。 
3. k 上に DP 配列を構築します。 dp[k] を柱 kx に到着したときに集めた最大コインを表すものとします。 
4. dp[k] の遷移では、1 回のジャンプで kx に到達できる以前の位置のみが考慮されます。 距離制約は (k − j)x ≤ p であるため、j は [k − W, k − 1] (W = ⌊p / x⌋) 内になければなりません。 この範囲では最大値を維持します。 
5. 単調デキューを使用して、最後の W 位置にわたる候補 dp 値を保存します。 k を前方に移動すると、dp[k − 1] がプッシュされ、ウィンドウから外れた古いインデックスがポップされます。 
6. x ≤ p の場合、dp[1] を a[x] に 0 を加えたものとして初期化します。 x > p の場合、処理を完全にスキップします。 
7. dp を満たした後、どの k がプラットフォームに正常に到達できるかを特定します。 kx ≥ n + 1 − p の場合、柱 kx から抜け出すことができます。 
8. すべての有効な出口位置にわたって最大 dp[k] を取得します。 何も存在しないか、すべての状態に到達できない場合、答えは不可能です。 

### なぜ効果があるのか

 有効なパスはすべて、許可されたサブセット内でのみ昇順でピラーを訪問する必要があるため、DP 状態は、許可された各ピラーに到達するためのすべての有効な方法を完全にキャプチャします。 スライディング ウィンドウ制限は、x による再スケーリング後のジャンプ制限と正確に一致するため、すべての実行可能な先行要素が考慮され、無効な先行要素は含まれません。 単調デキューにより、各状態の最適な遷移値が常に計算され、最大部分構造の正確さが維持されます。 

最後のフィルタリング ステップにより、プラットフォームへの最後のジャンプの実行可能性が保証されるため、DP は実際に終了できないパスを過剰にカウントしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q, p = map(int, input().split())
a = [0] + list(map(int, input().split()))

# store answers for all x
ans = [None] * (n + 1)

for x in range(1, n + 1):
    m = n // x
    if m == 0:
        ans[x] = None
        continue

    # cannot even start
    if x > p:
        ans[x] = None
        continue

    W = p // x

    dp = [0] * (m + 1)
    dq = []  # store indices, maintain decreasing dp

    dp[1] = a[x]

    dq.append(1)

    for k in range(2, m + 1):
        # remove out of window
        while dq and dq[0] < k - W:
            dq.pop(0)

        best_prev = dp[dq[0]] if dq else 0
        dp[k] = a[k * x] + best_prev

        # maintain monotonic deque
        while dq and dp[dq[-1]] <= dp[k]:
            dq.pop()
        dq.append(k)

    # compute best reachable ending
    limit = n + 1 - p
    best = None

    for k in range(1, m + 1):
        pos = k * x
        if pos >= limit:
            if best is None or dp[k] > best:
                best = dp[k]

    ans[x] = best

for _ in range(q):
    x = int(input())
    if ans[x] is None:
        print("Noob")
    else:
        print(ans[x])
```このコードは、考えられる各レベルを個別に処理しますが、デキューを使用して、各 DP 遷移が一定の償却時間で計算されるようにします。 重要な実装の詳細は、W = p // x を使用した座標距離からインデックス距離への変換です。これにより、幾何学的制約が単純なスライディング ウィンドウに変わります。 

最後のフィルタリング ステップでは、DP 配列の最後の有効なセグメントのみをスキャンして、エンドポイントがプラットフォームに到達できることを確認します。これは不可欠ですが、合計の最大化のみに焦点を当てている場合は見逃しがちです。 

## 実用的な例

 ### 例 1

 入力:

 n = 5、p = 4

 a = [2、5、-6、-4、3]

 クエリ x = 1

 すべての位置 1、2、3、4、5 を考慮するため、k はインデックスに直接対応します。 

| k | 位置 | dp[k] | ウィンドウ最大使用 |
 | --- | --- | --- | --- |
 | 1 | 1 | 2 | 0 |
 | 2 | 2 | 7 | 2 |
 | 3 | 3 | 1 | 7 |
 | 4 | 4 | 3 | 7 |
 | 5 | 5 | 6 | 7 |

 最適な終了位置は、position ≥ 6 − 4 = 2 の位置であるため、k ≥ 2 です。最大 dp は 7 で、k = 2 で達成されます。これは、負の値によってゲインが低下する前に 1 → 2 を実行するのが最適であるという直感と一致します。 

### 例 2

 入力:

 n = 10、p = 8

 a = [5、4、-6、8、-11、5、-6、4、-7、3]

 クエリ x = 2

 許可される位置は 2、4、6、8、10 です。 

| k | 位置 | dp[k] | 最も前のウィンドウ |
 | --- | --- | --- | --- |
 | 1 | 2 | 4 | 0 |
 | 2 | 4 | 12 | 4 |
 | 3 | 6 | 17 | 12 |
 | 4 | 8 | 21 | 17 |
 | 5 | 10 | 24 | 21 |

 終了条件には pos ≥ 11 − 8 = 3 が必要なので、すべての k が有効です。 最良の答えは 24 です。 

このトレースは、ウィンドウ制約によってすべての有効なジャンプが強制されるため、スライディング ウィンドウ DP が以前の決定を再考することなく最適な選択肢を着実に蓄積する様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q) | 各 x は n/x 状態を処理し、すべての x にわたる調和系列を合計します。 
| スペース | O(n) | x ごとに再利用される DP 配列とグローバルな回答配列 |

 調和分解により、n が最大 10^6 であっても、合計処理状態は数千万程度にとどまり、効率的な I/O を備えた Python の制限内に快適に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、x が p を超える場合です。 この状況では、0 から x への最初のジャンプが無効であるため、DP は開始すらされません。 アルゴリズムはこれを明示的にチェックし、不可能な結果を​​即座に割り当てて、不必要な計算を回避します。 

もう 1 つのケースは、有効な出口位置が DP に存在するが、プラットフォーム条件を満たすものがない場合です。 dp 値が大きい場合でも、kx ≥ n + 1 − p を保証する必要があります。 アルゴリズムはこのしきい値を使用して候補をフィルタリングするため、終了できないパスが誤って受け入れられることはありません。 

最後の微妙なケースは、p < x であっても x が n を割る場合に発生します。 多数の倍数が存在する場合でも、開始制約が優先されます。 このアルゴリズムは、これらのケースを早期に正しく短絡し、誤解を招く合計を生成する誤った DP 初期化を防ぎます。
