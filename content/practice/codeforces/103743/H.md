 ## アルゴリズムのチュートリアル

 入力バイナリ文字列をビットの配列として扱います。$S[0 \dots n-1]$、インデックスは最上位ビットから最下位ビットに向かって増加します。 

1. まず、作業配列を初期化します。$res = S$。 これは、変換をまったく適用しなかった後の現在の状態を表します。 
2. 各ビット位置を反復処理します。$b$のバイナリ表現では$k$。 もし$b$-番目のビット$k$が設定されていない場合は無視します。 設定されている場合、シフトに対応する変換を適用します。$2^b$。 

これが機能する理由は、それぞれのビットが$k$独立してシフトに寄与し、これらのシフトのすべての組み合わせは、次のサブマスクに正確に対応します。$k$。 
3. 選択したビットについて$b$、フォームのインプレース更新を実行します。$res[i] = res[i] \oplus res[i + 2^b]$すべて有効な$i$左から右へ。 

このステップでは、次のように区切られた位置からの情報をマージします。$2^b$、この部分を含むサブセットに対応するすべての寄与を効果的に追加します。$k$。 
4. 設定されているすべてのビットに対してこのプロセスを繰り返します。$k$。 各ステップにより、ビット文字列内の依存関係の相互作用範囲が 2 倍になります。 
5. すべてのビットを処理した後、$k$、配列$res$が最終的な答えです。 

明らかではない部分は、なぜ 2 のべき乗によるシフトで十分なのかということです。 これは、繰り返されるグレイ変換の二項展開を分解することで得られます。 各アプリケーションには、プレフィックス XOR 伝播のように動作する依存関係が導入され、その演算子の累乗により独立したシフト演算子の組み合わせが生成されます。 

### なぜ効果があるのか

 グレイ コードの置換は、GF(2) 上のビット文字列のベクトル空間での線形変換に対応します。 変換を適用するたびに、構造化された XOR パターンで情報が上位のインデックスから下位のインデックスに伝播されます。 この演算子を累乗すると$k$回、結果は、サイズが次のビットのサブセットに対応するシフト演算子の構成をすべて合計することと等価になります。$k$。 XOR は GF(2) の加算であるため、これらの合成は 2 の累乗にわたって独立して分布します。 したがって、最終的な変換は、設定された各ビットに対するシフト XOR ステップの反復適用と正確に一致します。$k$、すべての投稿を漏れや重複なく保存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    s = input().strip()
    
    res = [0] * n
    for i, ch in enumerate(s):
        res[i] = 1 if ch == '1' else 0

    b = 0
    while (1 << b) <= k:
        if k & (1 << b):
            shift = 1 << b
            # apply res[i] ^= res[i + shift]
            for i in range(n - shift):
                res[i] ^= res[i + shift]
        b += 1

    print("".join(map(str, res)))

if __name__ == "__main__":
    main()
```このコードは、shift-XOR 分解を直接実装しています。 入力文字列は変更可能な整数配列に変換されるため、ビット操作が高速になります。 設定されたビットごとに$k$、対応するシフト距離を計算し、シングルパス更新を適用します。 

実装の微妙な詳細は、反復方向です。 常に左から右に計算しますが、各ステップでは現在のシフト層の前にある前の状態の値が使用されるため、これは安全です。 各変換は以前の完全な状態に基づいて定義されているため、順序付けによって同じビット層内の更新間の干渉が発生することはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    s = input().strip()

    res = [1 if c == '1' else 0 for c in s]

    b = 0
    while (1 << b) <= k:
        if k & (1 << b):
            shift = 1 << b
            for i in range(n - shift):
                res[i] ^= res[i + shift]
        b += 1

    return "".join(map(str, res))

# minimal case
assert run("1 1\n0\n") == "0"

# single bit flip propagation
assert run("3 1\n101\n") == "111"

# no operation
assert run("4 0\n1100\n") == "1100"

# small structured case
assert run("4 3\n1011\n") == "1001"

 ## 特殊なケース

 いつ$k = 0$の場合、アルゴリズムはシフト演算を実行せず、元の文字列を変更せずに返します。 これは、順列を 0 回適用するという定義と一致します。 

のために$n = 1$、シフトの長さは常に文字列の長さ以上であるため、ビットが変化しても更新は行われません。$k$が設定されています。 出力は安定したままであり、1 ビットのグレイ コードが単純なスワップ順列であり、その繰り返し構造が境界条件下で崩壊するという事実と一致しています。 

いつ$k$複数のビットが設定されています。たとえば、$k = 3$、1 によるシフトと 2 によるシフトの両方が適用されます。 XOR 合成では、明示的に列挙することなくすべてのサブセット相互作用が自然にエンコードされるため、アルゴリズムはそれらを独立して処理し、最終結果はこれらのシフトのすべての組み合わせを正しく累積します。
