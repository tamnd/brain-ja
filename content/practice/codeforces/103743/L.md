 ## 解決策
 ## 問題の理解

 文字 A、B、C のみで構成される文字列が与えられています。これは、左から右に配置されたひし形の列と考える必要があります。 このプロセスにより、現在の構成でパターン A、B、C を形成する 3 つのダイヤモンドの連続ブロックを繰り返し選択することができます。 ある位置から始まるこのようなブロックを選択すると、文字列が変更されます。選択したブロックが現在の動的に変化する文字列の奇数位置で始まるか偶数位置で始まるかに応じて、ブロックの外側の 2 つの要素が削除されるか、中央の要素が削除されます。 各操作の後、残りのダイヤモンドがクローズアップされ、左から右に再インデックスされ、このプロセスが繰り返されます。 

タスクは、削除されるダイヤモンドの数を最大化することではなく、有効な A-B-C ブロックが存在しなくなる前に実行できるそのような操作の数を最大化することです。 

重要な問題は、「奇数インデックス」の意味が元の文字列で固定されていないことです。 削除するたびに、残りのすべての文字のインデックスが変更されます。これは、同じ元のセグメントを選択した場合でも、時間の経過とともに潜在的な操作のパリティが変化することを意味します。 

n が 2×10^5 までという制約は、各操作の後に文字列を繰り返し再構築したり、すべての部分文字列をスキャンしたりするソリューションは遅すぎることを意味します。 削除のたびにすべてのトリプルをチェックする単純なシミュレーションでは、各操作で O(n) 個の要素がシフトされ、O(n) 個の操作が存在する可能性があるため、2 次またはさらに悪い動作に低下します。 

微妙なエッジ ケースは、削除によるパリティの反転から発生します。 ある時点では「奇数インデックス」になっているトリプルは、それ以前に数回削除すると「偶数インデックス」になる可能性があり、これにより削除される内容が変更され、したがって非ローカルな方法で文字列の構造が変更されます。 

たとえば、ABCABCABC のような文字列では、重複するトリプルを繰り返し選択するとパリティがシフトし、異なる削除結果が発生し、将来の有効な操作の数が変化する可能性があります。 この動的パリティを無視する貪欲なアプローチでは、操作が過大カウントまたは過少カウントされます。 

## アプローチ

 ブルートフォースのアイデアは単純です。現在の文字列を維持し、左から右にスキャンして A、B、C の出現を見つけ、いずれかを選択し、現在の位置に応じて削除ルールを適用し、文字列を再構築し、有効なトリプルが存在しなくなるまで繰り返します。 これはプロセスを直接シミュレートするため正しいですが、各操作ではスキャンが必要になり、場合によっては線形構造を再構築する必要があります。 最悪のケースで最大 O(n) の操作があり、操作ごとに O(n) の作業が行われる場合、これは O(n^2) となり、最大 2×10^5 の n に対しては遅すぎます。 

重要な観察は、文字列構造が選択されたトリプルの周囲でのみ局所的に変化するということです。 他のすべては同じ相対順序のままであり、効率的に追跡する必要がある唯一のグローバル効果は、インデックスがどのように変化するかです。 操作のたびに文字列を物理的に再構築するのではなく、ライブ文字列内で位置が現在 A-B-C パターンを形成しているかどうかを確認することと、現在の動的インデックス作成でその位置が奇数であるか偶数であるかを判断するという 2 つのことをサポートする構造を維持します。 

これは、生きている文字に対するバイナリ インデックス付きツリーなどの動的な削除構造で文字列を表現することを示唆しています。 各キャラクターは生きている状態で開始され、削除すると位置が削除されたものとしてマークされます。 BIT を使用すると、その前に生きている文字が何個あるかを数えることによって、対数時間での元の位置の現在のインデックスを計算できます。

次に、元の文字列に A、B、C が含まれる候補インデックスのセットまたはキューを維持します。候補を処理するたびに、以前の削除によって壊れたり移動したりしている可能性があるため、候補が現在の有効な構造でまだ有効であるかどうかを確認します。 有効な場合、現在のインデックスを計算し、正しい削除ルールを適用して、生きている構造を更新します。 削除後は、影響を受ける位置の周囲の一定サイズの近傍のみが新しい有効なトリプルを作成または破棄できるため、候補をローカルで再計算します。 

これにより、問題は、フル スキャンを繰り返すのではなく、小さな移動時間枠での動的なメンテナンス タスクに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(n^2) | O(n) | 遅すぎる |
 | BIT + ローカル更新による動的シミュレーション | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 どの文字がまだ存在しているかを追跡する別の構造を使用して、文字列を固定位置として扱います。 また、元のインデックス付けで有効な A-B-C トリプルの開始位置の候補を維持し、現在の有効なセットに対する有効性を更新し続けます。 

## アルゴリズムのチュートリアル

 1. 位置 1 ～ n にわたってバイナリ インデックス付きツリーを構築します。各位置は、生きていることを意味する 1 から始まります。 これにより、特定の元のインデックスの前にまだ生きている文字が何文字あるかをクエリできるようになり、再インデックスされた文字列内の現在の位置がわかります。 これが必要なのは、パリティが元のインデックスではなくライブ インデックスに依存するためです。 
2. s[i]、s[i+1]、s[i+2] が元の文字列の A、B、C と等しくなるように、すべてのインデックス i を使用してキューを初期化します。 これらは潜在的な出発点にすぎません。 一部は削除により後で無効になる可能性があります。 
3. キューから候補インデックス i を繰り返し取得します。 これを使用する前に、位置 i、i+1、および i+2 がすべてまだ生きていて、A、B、C を形成していることを確認します。そうでない場合は、破棄します。 
4. BIT のプレフィックス合計クエリを使用して、ライブ文字列内の i の現在位置を計算します。 この位置が奇数の場合は、位置 i と i+2 を削除します。 それ以外の場合は、位置 i+1 を削除します。 これは、現在の状態に適用される問題のルールと一致します。 
5. 削除するすべての位置について、BIT を更新して削除済みとしてマークします。 これにより、今後の位置クエリに圧縮された構造が確実に反映されます。 
6. 削除の影響を受ける可能性があるのは [i-2, i+2] の範囲内のすべての開始インデックスのみを削除した後、再チェックします。 このようなインデックス j ごとに、現在のアライブ構成で A、B、C が形成される場合、それをキューにプッシュします。 
7. キューが空になるまで続行します。 実行された削除が成功した回数が答えです。 

重要な考え方は、すべての構造的変更は、可能性のある新しいトリプルに関して一定の近傍にのみ影響を与えるため、文字列全体を再スキャンする必要がないということです。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、現在有効な構成で有効なトリプルのみを処理します。 BIT は、ある位置の前に残っている要素の数を正確にカウントするため、計算されたインデックス パリティが現在の状態に対して常に正しいことを保証します。 ローカル再挿入ステップでは、新しく形成された A-B-C トリプルが欠落しないことが保証されます。これは、新しい有効なトリプルには、削除に隣接する少なくとも 1 つの文字が含まれている必要があるためです。 削除はローカルな接続にのみ影響するため、将来の候補はすべて、前の操作から一定の距離内に発生する必要があります。 これにより、グローバルな再スキャンを回避しながら、候補生成の完全性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    s = input().strip()
    n = len(s)

    alive = BIT(n)
    for i in range(1, n + 1):
        alive.add(i, 1)

    q = []
    inq = [False] * (n + 1)

    def is_alive(i):
        return alive.range_sum(i, i) == 1

    def valid(i):
        if i < 1 or i + 2 > n:
            return False
        if not (is_alive(i) and is_alive(i + 1) and is_alive(i + 2)):
            return False
        return s[i - 1] == 'A' and s[i] == 'B' and s[i + 1] == 'C'

    for i in range(1, n - 1):
        if s[i - 1:i + 2] == "ABC":
            q.append(i)
            inq[i] = True

    ans = 0
    head = 0

    while head < len(q):
        i = q[head]
        head += 1
        if i < 1 or i + 2 > n:
            continue
        if not valid(i):
            continue

        pos = alive.sum(i)

        if pos % 2 == 1:
            remove = [i, i + 2]
        else:
            remove = [i + 1]

        for x in remove:
            if alive.range_sum(x, x):
                alive.add(x, -1)

        ans += 1

        for j in range(i - 2, i + 3):
            if j < 1 or j + 2 > n:
                continue
            if valid(j):
                q.append(j)

    print(ans)

if __name__ == "__main__":
    solve()
```BIT は、インデックスの前にまだ存在する文字の数を追跡します。これはまさに、パリティに使用される現在の再インデックス位置を決定します。 有効性チェックにより、以前の削除後にまだ存在するトリプルのみを操作することが保証されます。 文字を削除した後、変更された領域を横切る新しい ABC パターンが形成される可能性があるため、ローカル再挿入ループは重要です。 

キューには重複エントリや古いエントリを含めることができますが、すべての候補が使用前に再検証されるため、正確さが保たれます。

 ## 特殊なケース

 ABC のような最小限の文字列は、1 つの操作のみが可能であり、削除後にはそれ以上の構造が残らないため、基本的な妥当性条件をテストします。 

ABCABCABC などの繰り返しパターンでは、アルゴリズムが削除後の新しいトリプルのカスケード形成を正しく処理するかどうかをテストします。 変更された領域の周囲に候補を再挿入することで、新しい重複パターンが確実に発見されます。 

ABC 部分文字列を含まない文字列を使用すると、無効な操作を試行することなく、キュー駆動プロセスが直ちに正しく終了することが保証されます。
