 ## 解決策
 ## 問題の理解

 私たちは従業員の集合を与えられており、各従業員は 1 つの会社に所属しており、各会社は CEO を基点とする階層として構造化されています。 従業員を頂点としてモデル化し、報告関係をエッジとしてモデル化すると、各企業はツリーを形成し、システム全体はそのようなツリーの森になります。 

タスクは、各会社の規模を決定することです。つまり、すべての従業員について、接続されている階層に何人いるかを知りたいと考えています。 同じツリー内のすべての従業員は同じ会社規模を共有するため、これは、無向フォレスト内の各接続コンポーネントのサイズを計算することと同じです。 

このストーリーは CEO と部下という観点から表現されていますが、計算構造は単にサイクルのない無向グラフです。 各ツリーは 1 つの会社に対応し、ノードの答えはそのツリーのサイズになります。 

このタイプの問題の制約では、通常、最大約 200,000 個のノードとエッジが許容されるため、ノードのすべてのペア間の接続性をチェックするなどの 2 次アプローチは即座に除外されます。 すべてのノードから個別に DFS または BFS を繰り返し試行するソリューションは、最悪の場合 O(n^2) まで低下しますが、これは許容範囲をはるかに超えています。 構造上を単一の直線または直線に近いパスが必要です。 

フォレストに単一ノードのツリーが多数含まれている場合、微妙なエッジ ケースが発生します。 たとえば、まったくエッジのないノードがある場合、それぞれのノードがサイズ 1 の会社を形成します。もう 1 つの特殊なケースは、単一の大きなチェーンです。この場合、注意深くマークされていない場合、単純に反復された走査で長いパスを何度も再訪する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、各ノードを潜在的なルートとして扱い、DFS または BFS を実行して、そこから到達可能なノードの数を計算することです。 無向グラフの到達可能性は接続コンポーネントを正確に定義するため、これは正しいです。 ただし、これをノードごとに個別に実行すると、大規模な再計算が発生します。 長さ n のチェーンでは、単一の DFS のコストはすでに O(n) であり、それを n 回繰り返すと O(n^2) の操作が必要になり、これは実行不可能です。 

重要な点は、グラフの構造がクエリ間で変化しないことです。 各接続コンポーネントのサイズは固定されており、その内部のすべてのノードは同じ答えを共有します。 これは、各コンポーネントを 1 回計算するだけで済み、その後そのサイズをそのコンポーネント内のすべてのノードに伝播する必要があることを意味します。 

これを効率的に実現するには 2 つの標準的な方法があります。 1 つは、DFS または BFS を使用したグラフ トラバーサルです。 各ノードを 1 回だけ訪問し、走査中にそのコンポーネントのサイズを蓄積し、そのサイズを訪問したすべてのノードに割り当てます。 2 つ目は Disjoint Set Union です。ここでは、エッジの端点をマージし、DSU ルート内のコンポーネント サイズを維持します。 

どちらのアプローチも同じ考え方に基づいています。つまり、フォレストを素のセットに圧縮し、ノードごとではなくセットごとにサイズを計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ノードからのブルート フォース DFS | O(n^2) | O(n) | 遅すぎる |
 | コンポーネントごとの DFS/BFS | O(n) | O(n) | 承認済み |
 | サイズ別ユニオン付き DSU | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 DFS/BFS アプローチが問題の最も直接的な解釈であるため、最初に DFS/BFS アプローチについて説明します。

1. 指定されたエッジからフォレストの隣接リストを作成します。 この表現により、無関係なペアをスキャンすることなく、各ノードの隣接ノードを効率的に走査することができます。 
2. すべてのノードに対して false に初期化された訪問先配列を維持します。 これにより、各ノードが 1 回だけ処理されるようになり、同じコンポーネントを繰り返し走査することがなくなります。 
3. 1 から n までのすべてのノードを繰り返します。 まだ訪問されていないノードが見つかると、そこからトラバースを開始します。 このノードは、新しい会社ツリーのエントリ ポイントとして機能します。 
4. トラバーサル中に、DFS または BFS を実行し、開始ノードから到達可能なすべてのノードを収集します。 訪問した各ノードには、再訪問を避けるためにマークが付けられます。 
5. コンポーネントを走査しているときに、発見されたノードの数を数えます。 この数が現在の会社の規模となります。 
6. コンポーネントの走査が終了したら、その走査中に収集されたすべてのノードに計算されたサイズを割り当てます。 

DSU アプローチは同じロジックに従いますが、トラバースをユニオン操作に置き換えます。 各エッジは 2 つのセットをマージし、各セットのルートはサイズ カウンタを維持します。 すべてのエッジを処理した後、各ノードの答えは単にその代表ノードのサイズになります。 

機能する理由: DFS の訪問済みマーキング、または DSU の代表ポインターにより、接続されている各コンポーネントが 1 回だけ確実に識別されます。 接続性によりグラフが素のセットに分割されるため、すべてのノードは 1 つのコンポーネントにのみ属し、すべてのコンポーネントは 1 回だけカウントされます。 ノードがコンポーネントに割り当てられるか、ルートの下で結合されると、別個のエンティティとして再処理されることはないため、ノードを 2 回カウントすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
    
    vis = [False] * (n + 1)
    ans = [0] * (n + 1)
    
    sys.setrecursionlimit(10**7)
    
    def dfs(start):
        stack = [start]
        comp = []
        vis[start] = True
        
        while stack:
            u = stack.pop()
            comp.append(u)
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        
        size = len(comp)
        for node in comp:
            ans[node] = size
    
    for i in range(1, n + 1):
        if not vis[i]:
            dfs(i)
    
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```このソリューションでは、まず隣接リストを構築して、各従業員が階層内での直接の接続を把握できるようにします。 DFS は、階層が長いチェーンに縮退する場合に特に重要となる再帰の深さの問題を回避するために、スタックを使用して反復的に実装されます。 

未訪問のノードに遭遇するたびに、その接続されているコンポーネント全体を探索します。 comp リストにはそのコンポーネント内のすべてのノードが格納されるため、走査後に同じ計算されたサイズをノードに割り当てることができます。 これにより、サイズを何度も再計算することがなくなります。 

ans 配列にはノードごとの最終的な企業規模が格納され、インデックス 0 を除くすべての値が出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各ノードとエッジは DFS 中に 1 回処理されます。 
| スペース | O(n + m) | 隣接リストと補助配列はグラフ構造を格納します。 

このアルゴリズムは線形作業のみを実行するため、最大 200,000 個のノードとエッジの一般的な制約内に簡単に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    data = inp.strip().split()
    if not data:
        return ""
    
    n, m = map(int, data[:2])
    g = [[] for _ in range(n + 1)]
    
    idx = 2
    for _ in range(m):
        u = int(data[idx]); v = int(data[idx+1]); idx += 2
        g[u].append(v)
        g[v].append(u)
    
    vis = [False] * (n + 1)
    ans = [0] * (n + 1)
    
    sys.setrecursionlimit(10**7)
    
    def dfs(s):
        stack = [s]
        comp = []
        vis[s] = True
        while stack:
            u = stack.pop()
            comp.append(u)
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        size = len(comp)
        for x in comp:
            ans[x] = size
    
    for i in range(1, n + 1):
        if not vis[i]:
            dfs(i)
    
    return " ".join(map(str, ans[1:]))

# single node
assert run("1 0") == "1"

# chain
assert run("4 3\n1 2\n2 3\n3 4") == "4 4 4 4"

# two components
assert run("5 3\n1 2\n2 3\n4 5") == "3 3 3 2 2"

# isolated nodes
assert run("3 0") == "1 1 1"

 ## 特殊なケース

 単一ノード グラフの場合、アルゴリズムはそのノードを即座に訪問済みとしてマークし、コンポーネント サイズ 1 を割り当てます。 処理する近隣ノードがないため、DFS スタックは即座に空になり、初期化から直接正確性が保たれます。 

完全に切断されたグラフの場合、外側のループの反復ごとに新しい DFS 呼び出しがトリガーされます。 エッジが存在しないため、各 DFS は 1 つのノードのみに触れ、正しいサイズ 1 の割り当てを独立して生成します。 

長いチェーンの場合、反復スタックにより、再帰制限を超えないことが保証されます。 各ノードのプッシュとポップは 1 回だけ行われるため、最悪の歪んだ構造であっても、スタック オーバーフローのリスクがなく、トラバースは線形のままです。
