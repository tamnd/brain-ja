 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、それをいくつかのグループに分割するように求められます。 ソリューションのコストはグループの数であり、すべての要素は 1 つのグループにのみ属している必要があります。 グループは、その内部で 2 つの条件が満たされる場合にのみ有効とみなされます。つまり、要素の数が固定制限を超えないこと、およびそのグループ内の最小要素と最大要素の差が固定しきい値を超えないことです。 

このステートメントの重要な構造上の主張は、入力内の要素の順序は重要ではないということです。 配列をソートすると、どの最適解も、各グループがこのソートされた配列の連続セグメントに対応する別の最適解に変換できます。 これにより、問題は任意のパーティションから線に沿ったカット位置の選択まで軽減されます。 

複雑さの観点から見ると、配列のサイズが十分に大きいため、n を超える二次関数は遅すぎます。 すべてのパーティションを試行するかセグメントの有効性を繰り返し再計算するソリューションは、最悪の場合でも n² チェックのオーダーで実行されますが、これはこのタイプの一般的な制約では許容できません。 

いくつかの特殊なケースについては、覚えておく価値があります。 すべての値が等しい場合、唯一の制限はサイズ制限によるものであるため、答えは単純にサイズ k のブロックの数になります。 k が非常に大きいが、値の間隔が広い場合、範囲の制約により、すべての要素が独自のグループに分類される可能性があります。 1 つの条件だけをチェックし、もう 1 つの条件を無視する素朴な貪欲さは失敗する可能性があります。 たとえば、要素の値は近いものの、セグメントが長くなりすぎる場合、値の条件が満たされていても、サイズ制限を無視すると無効なグループが生成されます。 

## アプローチ

 ブルート フォースの観点では、ソートされた配列を連続セグメントに分割するあらゆる可能な方法を検討し、各セグメントが両方の制約を満たすかどうかを検証します。 各セグメントについて、その要素をスキャンしてそのサイズと範囲を計算します。最悪の場合、セグメントあたり O(n) になります。 配列を分割する方法は指数関数的に多く存在するため、このアプローチはすぐに実行不可能になります。 以前のすべてのカット位置に対する動的プログラミングでも O(n²) になります。これは、位置ごとに以前のすべてのブレークポイントを試して妥当性を再計算するためです。 

重要な観察は、配列がソートされると、セグメントの有効性はその左側の境界と右側にどれだけ拡張されるかのみに依存するということです。 セグメントを拡張すると、サイズと値の範囲の両方が単調に変化します。 これは、セグメント内の以前の決定を再考する必要がないことを意味します。次の要素を追加することでいずれかの制約に違反するまで、現在のセグメントを貪欲に拡張できます。その後、新しいセグメントを開始する必要があります。 

これにより、問題は各要素が 1 回処理される単一の線形スキャンに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング | O(2^n) または O(n²) DP | O(n) | 遅すぎる |
 | ソートされた配列の貪欲なスイープ | O(n log n) (ソート) + O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列を降順でない順に並べ替えます。 これにより、有効なグループを連続したセグメントとして表すことができ、セグメントの最小要素と最大要素の両方が常にその端にあることが保証されます。 
2. 最初の要素から新しいグループを開始します。 現在のグループの最初の値とそのインデックス位置の 2 つの情報を保存します。 
3. 配列を左から右に繰り返します。 各要素で、その要素を現在のグループに追加するといずれかの制約に違反するかどうかを確認します。 
4. 現在の要素とグループの最初の要素の差が許容しきい値を超える場合、またはグループ内の要素の数が k を超える場合は、この要素の前で現在のグループを閉じ、この位置で新しいグループを開始します。 
5. 新しいグループを開始するときは、保存されている最初の値と位置をリセットします。 
6. すべての要素が処理されるまで続行します。 新しいグループを立ち上げた回数が答えです。 

この実装では、現在のセグメントの左側の境界のみが維持されます。 配列はソートされているため、最小値は常に左側の境界にあり、最大値は考慮されている現在の要素であるため、これで十分です。 

### なぜ効果があるのか

 この正しさは、ソート順にグループの開始点を固定すると、グループを拡張すると 2 つの制約が悪化するだけであるという事実から来ています。サイズは 1 つ増加し、範囲は同じままか増加します。 したがって、次の要素が制約に違反している場合、後の拡張機能ではそれを修正できず、最適な解決策もその位置でカットする必要があります。 これにより、可能な限り早い段階でカットを行っても、最適な配置に比べてグループの数が決して増加しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    ans = 0
    first = None
    first_pos = 0
    
    for i, val in enumerate(a):
        if first is None:
            ans += 1
            first = val
            first_pos = i
            continue
        
        if val - first > m or i - first_pos >= k:
            ans += 1
            first = val
            first_pos = i
    
    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、配列をソートすることから始まります。これは、グループ化の問題を 1 次元のセグメンテーションの問題に変えるため、不可欠です。 変数`first`現在のグループ内の最小の要素を追跡します。これは、並べ替えにより常に左端の要素になります。 変数`first_pos`現在のグループにこれまでに含まれている要素の数を追跡し、O(1) でサイズ制約を強制できるようにします。 

現在の要素を追加すると範囲制約またはサイズ制約に違反することが検出されるたびに、すぐに新しいグループを開始します。 これ以上拡張しても両方の制約が悪化するだけなので、この貪欲な再起動は安全です。

 ## 特殊なケース

 配列に単一の要素が含まれている場合、どちらの制約にも違反できないため、アルゴリズムは 1 つのグループを直ちに開始および終了します。 ループは最初の要素で新しいセグメントを初期化し、その後はカットをトリガーしないため、状態は正しくリセットされます。 

すべての要素が同一の場合、差は常にゼロであるため、範囲条件はトリガーされません。 唯一の制限要因は k になり、アルゴリズムは現在のセグメントがサイズ k に達したときに正確に新しいグループを開始し、均等なサイズのブロックを生成します。 

k が非常に大きく、m が非常に小さい場合、動作は完全に値のギャップによって支配されます。 このアルゴリズムは、セグメント サイズがまだ k よりはるかに小さい場合でも、次の要素が現在のセグメント開始からの許容差を超えるたびに正しく分割します。 

m が大きく k が小さい場合、すべてのセグメントはサイズに応じて強制的にカットされます。 このアルゴリズムは、セグメント内の最初の要素の位置を追跡し、値とは関係なくインデックスを直接比較するため、正確性が保証されます。
