 ## 解決策
 ## 問題の理解

 私たちには、それぞれ 2 つの数字で表されるモンスターのコレクションが与えられています。 1 つの値は、そのモンスターを倒す前に必要なゴールドの量を表し、もう 1 つの値は、モンスターを倒した後に獲得できるゴールドの量を表します。 最初にある程度のゴールドを用意して、戦うモンスターを繰り返し選択します。 モンスターは、現在のゴールドが必要なしきい値以上の場合にのみ戦うことができます。 倒すと報酬によってゴールドが増加します。 

課題は、最適な戦闘順序を選択して、倒せるモンスターの最大数を決定することです。 

重要な問題は、順序が重要であるということです。 要件が小さいモンスターは、後で別のモンスターへのアクセスのロックが解除される可能性があります。また、大きな報酬を持つモンスターは、将来のリーチが増えるため、より早く価値がある可能性があります。 

制約の観点から見ると、目的のソリューションはおよそ O(n log n) で実行される必要があります。 残りのすべてのモンスターを繰り返しスキャンして次のモンスターを選択するアプローチは O(n²) まで低下し、大規模な入力には遅すぎます。 

貪欲な直感が微妙に失敗するケースは、わずかに高い要件を持つモンスターが実際にははるかに良い報酬を与えるが、すぐにアクセスできず、それを遅らせると他のどのモンスターが利用可能になるかが変わってしまう場合です。 たとえば、あるモンスターが 5 必要で 1 ゴールドを提供し、別のモンスターが 4 必要で 10 ゴールドを提供する場合、最初に間違ったモンスターを選択すると、たとえローカルで見栄えが悪くても、将来のアクセスがブロックされる可能性があります。 

## アプローチ

 直接総当たり戦略では、モンスターのあらゆる可能な順序を試し、戦闘をシミュレートし、どの順序が有効であるかをチェックしてカウントを最大化します。 これはすべての順列を探索するので原理的には正しいですが、階乗的に増加し、中程度の n の場合でも使用できなくなります。 

より構造化されたアプローチは、プロセスを段階的にシミュレートすることです。各時点で、現在購入できるすべてのモンスターを検討し、1 つを選択します。 問題はどれを選ぶかです。 重要な観察は、現在手頃な価格のすべてのモンスターの中で、最大の報酬を持つモンスターを選択することが常に最適であるということです。 これは、ローカル交換の議論によって正当化できます。より大きな報酬が利用可能であるときに、より小さな報酬を最初に選択した場合、それらを交換しても将来の状態へのアクセスが失われることはなく、合計ゴールドを向上または維持することしかできません。 

これにより、問題は「利用可能なモンスター」の動的なセットを維持し、最適な候補を繰り返し抽出することに変わります。 ただし、すべてのステップでリスト全体をスキャンするのはまだ遅すぎます。 

これを最適化するために、モンスターをまだ手頃な価格ではないものと現在手頃な価格のモンスターの 2 つのグループに分けます。 モンスターを利用可能なセットに素早く移動できるように、要件によって順序付けされた 1 つの構造を維持し、最適な次のモンスターをすぐに選択できるように、報酬によって順序付けされた別の構造を維持します。

 | ブルートフォース順列 | お(ん!) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 私たちは 2 つの優先体制を維持しています。 1 つは、十分なゴールドが不足しているためにまだ到達できないモンスターを、要件の増加順に保管します。 現在倒せる他の店のモンスターを報酬の少ない順に並べています。 

また、現在のゴールドを表す変数 cw と、倒したモンスターの数を示すカウンターも維持します。 

プロセスは次のとおりです。

1. 必要なゴールドごとに分類されたすべてのモンスターを構造物に挿入します。 これにより、CW が増加するにつれてどのモンスターが利用可能になるかをすぐに識別できます。 
2. cw を開始ゴールドで初期化し、すべてのモンスターを最初は「選択不可」としてマークします。 
3. 要件が最大でも CW であるすべてのモンスターを利用可能なプールに移動します。 このステップにより、利用可能なプールが、現時点で戦えるものを常に正確に反映するようになります。 
4. 利用可能なモンスターがない場合は、それ以上進むことができないため、プロセスは停止します。 残りのモンスターには、到達できないほど多くのゴールドが必要です。 
5. それ以外の場合は、利用可能なプールから最も高い報酬を持つモンスターを選択して倒します。 報酬によってCWを増加させ、答えを増加させます。 
6. ゴールドを獲得したら、新しいモンスターに到達できるようになる可能性があるため、ステップ 3 からのプロセスを繰り返します。 

### なぜ効果があるのか

 どの時点でも、現在手頃な価格のすべてのモンスターの中で、最適性を損なうことなく最も高い報酬を持つモンスターを選択できます。 最適なシーケンスが最初に別の手頃な価格のモンスターを選択した場合、それを最も高い報酬のモンスターと交換しても、後のモンスターへのアクセス可能性は低下しません。これは、すべての要件が現在のゴールドのみに依存し、交換によって将来の決定の瞬間にゴールドが減少することはないためです。 これにより、cw の単調増加と組み合わせた貪欲な選択特性が確立され、すべてのステップが局所的に最適でグローバルに一貫していることが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, start = map(int, input().split())
    monsters = [tuple(map(int, input().split())) for _ in range(n)]

    monsters.sort(key=lambda x: x[0])

    i = 0
    cw = start
    ans = 0

    # min-heap by requirement (bi)
    not_ready = []
    # max-heap by reward (gi), store negative
    ready = []

    while True:
        while i < n and monsters[i][0] <= cw:
            heapq.heappush(ready, -monsters[i][1])
            i += 1

        if not ready:
            break

        g = -heapq.heappop(ready)
        cw += g
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、モンスターを 1 回だけスキャンできるように、要件ごとにモンスターを並べ替えることに依存しています。 ポインタ i により、各モンスターがヒープに 1 回だけ移動されることが保証され、ヒープ挿入コストの合計は O(n log n) になります。 

Python の heapq は最小ヒープであるため、ヒープには報酬がマイナスとして格納されます。 各ステップでは、貪欲なルールに一致して、現在入手可能なモンスターの中から最大の報酬モンスターを抽出します。 

ループ終了条件は、現在到達可能なモンスターが存在しない場合に発生します。つまり、cw をこれ以上増やすことができないため、今後モンスターを入手できなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各モンスターはヒープに挿入およびヒープから削除されるのは最大 1 回であり、ソートが優先されるのは 1 回だけです。 
| スペース | O(n) | すべてのモンスターを配列に格納し、最大で n 個の要素をヒープに格納します。 

複雑さは、n が 2e5 または 1e5 までの一般的な制約内に収まります。この場合、O(n log n) 演算が標準です。

 ## 特殊なケース

 エッジケースの 1 つは、最初は手頃な価格のモンスターが存在しない場合です。 このアルゴリズムは、空の準備完了ヒープを正しく初期化し、無効な選択を試行せずにただちに終了し、ゼロを生成します。 

もう 1 つのケースは、複数のモンスターが同じ要件を共有しているが、報酬が大きく異なる場合です。 ヒープにより、最適な報酬だけが最初に選択されることが保証され、全体的なリーチを減らす可能性のある弱い報酬の最適以下の消費が防止されます。 

最後のケースには、各モンスターがもう 1 つだけロックを解除する長いチェーンが含まれます。 各ゲインはすぐに cw に反映され、新しく利用可能なモンスターはすべて選択前にヒープにプッシュされるため、アルゴリズムは、プロセスの途中で利用可能になる新しくロックが解除された高報酬のオプションを見逃すことはありません。
