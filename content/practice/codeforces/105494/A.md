 ## 解決策
 ## 問題の理解

 パーツと呼ばれる単一のオブジェクトから始まる非常に単純なプロセスが与えられています。 Enter キーを押すたびに、パーツの数が 1 つずつ増えます。 ある程度の回数押した後、システムは正確に終了します。$n$部品。 

この質問は基本的に、初期状態から最終状態に到達するまでに Enter キーが何回押されたかを尋ねています。 

1 パートから始まり で終わります$n$このタスクは、最終的なカウントに達するまでに必要な操作の数を決定することです。 

入力は最終的な部品数として解釈できます。$n$、出力は、それに到達するまでに必要なキーの押下回数です。 

各操作は正確に 1 つの増分に寄与するため、初期状態と最終状態の関係は線形で決定的です。 

隠れた依存関係や分岐状態はありません。 このプロセスは厳密に単調であるため、あいまいさの可能性があるのは、次のような境界ケースの誤った処理によってのみ発生します。$n = 1$。 

素朴な解釈の間違いは、次のように出力することです。$n$の代わりに$n - 1$、最終状態を、追加の暗黙的な操作が含まれているかのように扱います。 たとえば、次の場合$n = 1$、何も押されないため、正解は 0 でなければなりません。初期状態を忘れた解は誤って 1 を出力します。 

もう 1 つの考えられる間違いは、Enter キーを押すと最初の部分が生成され、それが増加すると仮定することです。これにより、すべての結果が 1 ずつ誤ってシフトされます。 

## アプローチ

 ブルートフォース解釈では、プロセスを直接シミュレートします。 カウンターを 1 から開始し、カウンターが 1 に達するまで繰り返しインクリメントします。$n$、実行したインクリメントの数を数えます。 これは、説明されているプロセスに正確に従っているため、正しいです。 

ただし、このシミュレーションは増分ごとに 1 ステップを実行するため、最悪の場合は実行されます。$n - 1$操作。 もし$n$たとえば、大きいです$10^9$、これは線形ランタイムのため実行不可能になります。 

重要な観察は、プロセスが分岐したり、中間構造に依存したりしないことです。 どの操作でも同じ効果があり、1 ずつ増加します。 これは、最終状態が開始と終了の差だけによって決定されることを意味します。 

したがって、遷移をシミュレートする代わりに、1 から 2 に移行するために必要な増分数を直接計算します。$n$、これは単純に$n - 1$。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n)$|$O(1)$| 遅すぎる |
 | ダイレクトフォーミュラ |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 最終的な部品数を読み取ります。$n$まず、すべての操作が適用された後のシステムの最終状態を表す入力値を取得します。 

### 2. 初期状態を認識する

 プロセスは常に 1 つのパートから始まります。 この開始点は固定されており、入力には依存しません。 

### 3. 差を計算する

 各操作でカウントが 1 つずつ増加するため、必要な操作数は最終値と初期値の差、つまり次のようになります。$n - 1$。 

### 4. 結果を出力する

 計算された差を答えとして出力します。 

### なぜ効果があるのか

 システムは厳密に線形的に進化します。各操作により状態が 1 つずつ増加し、どの操作も増分サイズを減少または変更することはありません。 これにより、操作と部品数の増加との間に 1 対 1 のマッピングが作成されます。 初期状態は1に固定されているので、$n$正確に必要です$n - 1$増加します。 代替の操作シーケンスは存在しないため、この数は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    print(n - 1)

if __name__ == "__main__":
    main()
```このソリューションは、単一の整数を読み取り、固定開始値との差を出力します。 減算は、1 を次のように変換するために必要な増分数を直接エンコードします。$n$。 

唯一の微妙な点は、$n = 1$。 この場合、結果は正しく 0 になり、操作が必要ないという事実と一致します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import builtins
    input_backup = builtins.input
    builtins.input = lambda: sys.stdin.readline()
    from contextlib import redirect_stdout
    out = io.StringIO()
    import sys as _sys

    def solve():
        n = int(_sys.stdin.readline().strip())
        print(n - 1)

    with redirect_stdout(out):
        solve()

    builtins.input = input_backup
    return out.getvalue().strip()

# provided samples

assert run("1\n") == "0"

# custom cases

 ## 特殊なケース

 ### ケース:$n = 1$入力：```

```アルゴリズムは計算します$1 - 1 = 0$。 これは、システムがすでに必要な状態で開始されていることを反映しています。 増分は発生しないため、出力は正確です。 

### ケース: 最小増分

 入力:```
2
```計算は$2 - 1 = 1$。 1 つのパートから開始して、2 つのパートに到達するまでに 1 回の操作が必要です。 減算は単一の遷移に直接一致します。 

### ケース: 大量の入力

 入力:```
1000000000
```このアルゴリズムは単一の算術演算を実行し、次の結果をもたらします。$999999999$。 反復が含まれないため、パフォーマンスは大きさに関係なく一定に保たれ、正確性は各操作が 1 単位の増加に対応するという同じ不変式に基づいて決まります。
