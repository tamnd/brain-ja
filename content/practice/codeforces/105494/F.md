 ## 解決策
 ## 問題の理解

 一連の信号機を通過するバスをシミュレートしています。 交差点間のバスの走行時間は一定であり、定期信号の状況によっては各交差点で待ち時間が発生する場合があります。 

各信号機には、青の継続時間と赤の継続時間によって定義される独自のサイクルがあります。 このサイクルは固定期間ごとに繰り返され、時間ゼロの時点で、移動が始まる特定の秒数前に緑がアクティブであったという意味で、光がそのサイクルに対してどのようにオフセットされたかがわかります。 バスが各交差点に到着したら、その瞬間に信号が青であるかどうかを判断する必要があります。 赤の場合は、再び緑になるまで待ってから続行します。 

入力は一連の交差を記述します。 各交差点 i について、前の交差点からその交差点に到達するまでの移動時間、青の継続時間 gi、赤の継続時間 ri、および最後の青の段階が開始されるどれだけ前に開始されたかを示すオフセット di が与えられます。 目標は、バスがすべての交差点を通過し終わるまでの合計経過時間を計算することです。 

制約が非常に大きいため、毎秒シミュレーションすることは不可能です。 直接的な段階的な時間の進化でも O(合計時間) にまで低下し、待ち時間が累積すると最悪の場合、非常に長くなる可能性があります。 

バスがちょうど緑と赤の間の遷移点に到着すると、微妙なエッジ ケースが発生します。 レミがギに等しい場合、その瞬間はすでに赤の始まりであるため、待つ必要があります。 もう 1 つのエッジ ケースは、gi が 0 の場合です。これは、信号が常に赤であり、到着するたびにフル サイクルの待機が強制されることを意味します。 

単純な実装では、特にオフセット di が大きい場合に、オフセット di を誤って処理する可能性があります。 di はサイクル周期よりもはるかに大きくなる可能性があるため、サイクルを法として di を小さくしないと、不正確な位相計算が行われます。 

## アプローチ

 ブルート フォース シミュレーションでは継続的に時間を追跡し、交差点ごとに信号が青になるまで時間を増分します。 各交差点に移動後はaiで時間を進め、そのサイクルを秒単位でシミュレーションして照明の状態を繰り返し確認します。 これは実際のプロセスを正確に反映しているため正しいですが、O (すべての待機時間の合計) に低下する可能性があり、待機時間が長い場合にはこれは現実的ではありません。 

重要な観察は、個々の秒をシミュレートする必要がないということです。 信号機の状態は周期的であるため、いつでも、自分がそのサイクル内のどこにいるのかを知る必要があるだけです。 一度に 1 秒ずつ進める代わりに、モジュラー演算を使用して光の位相を直接計算できます。 

交差点 i に到着すると、スタートからの経過時間がわかります。 光のサイクルは gi + ri 秒ごとに繰り返されます。 最後の青信号は時刻 0 秒前に開始したため、基準となる青信号の開始からの合計経過時間は時間 + di になります。 このモジュロをサイクル長に換算すると、サイクル内の現在位置が得られます。 この位置が緑の区間内にある場合は、すぐに通過します。 それ以外の場合は、次の緑のフェーズに直接ジャンプします。 

これにより、モジュラー演算がシミュレーションに置き換わるため、各交差の計算が O(1) に減ります。

 ## アルゴリズムのチュートリアル

 time が旅行開始からの現在の経過時間を表すものとします。

1. 時間を 0 に初期化します。これは、移動が発生していない最初のセグメントに入る前の瞬間を表します。 
2. 各交差点 i について、まず時間を ai だけ増加させます。 これは、信号に到達するまでに必要な移動時間を計算します。 
3. 既知の緑色基準からの合計経過時間を totali = time + di として計算します。 これによりタイムラインがシフトし、現在の瞬間をサイクルのフェーズの定義に合わせることができます。 
4. periodi = gi + ri を計算します。 これは、交通信号の完全な繰り返しの長さを表します。 
5. remi = totali mod periodi を計算します。 これにより、現在のサイクル内の位置がわかります。 モジュロが機能するのは、信号の動作が周期ごとに同じように繰り返されるためです。 
6. remi < gi の場合、到着時に信号は青になり、遅滞なく続行します。 それ以外の場合、信号は赤となり、次の緑の位相境界に到達するまで正確に periodi − remi 秒待つ必要があります。 待機した後、この遅延を時間に追加します。 

すべての交差点を処理した後、時間にはすべての待ち時間を含む合計移動時間が含まれます。 

重要な不変条件は、各ステップにおいて、時間は、以前のすべての待機決定を完全に解決した後、バスが次の交差点に到着できる最も早い瞬間を常に反映するということです。 各更新は現在の時間と次の光サイクルの決定論的なモジュロ計算にのみ依存するため、現在の状態にどのように到達したかによって将来の決定が決まることはありません。 このプロセスはすべての交差点で局所的に最適であるため、全体的には正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    time = 0

    for _ in range(n):
        a, g, r, d = map(int, input().split())
        time += a

        period = g + r
        total = time + d
        rem = total % period

        if rem >= g:
            time += period - rem

    print(time)

if __name__ == "__main__":
    solve()
```このソリューションでは、単一の実行時間変数を保持し、交差点ごとにそれを更新します。 到着は信号チェックの前に行われるため、移動時間は常に最初に追加されます。 

実装の重要な詳細は演算の順序です。モジュロはオフセット di を追加した後に計算する必要があり、待機時間は位相が赤色の場合にのみ追加する必要があります。 rem >= g を使用すると、光が到着の瞬間に正確に切り替わる境界ケースが正しく処理されます。 

## 実用的な例

 2 つの交差がある単純なケースを考えてみましょう。 

入力：```
2
3 5 5 0
4 2 3 1
```時間を段階的に追跡します。 

最初の交差点では、走行後の時間は 3 になります。 サイクルは 10 です。total = 3、rem = 3、これは 5 未満であるため、すぐに合格します。 

2 番目の交差では、時間は 7 になります。total = 7 + 1 = 8、cycle = 5、rem = 3。緑の長さは 2 秒であるため、rem >= 2 は赤であることを意味するため、5 − 3 = 2 秒待機します。 

| 私 | 旅行後の時間 | 合計 = 時間 + d | 期間 | レム | アクション | 新しい時間 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | 10 | 3 | 緑 | 3 |
 | 2 | 7 | 8 | 5 | 3 | レッドウェイト2 | 9 |

 これは、モジュラー位置が緑色のウィンドウを超えた場合にのみ待機がトリガーされる方法を確認します。 

ここで、バスがちょうど赤い境界に到着するというエッジケースを考えてみましょう。 

入力：```
1
5 3 4 0
```移動後、時間 = 5、合計 = 5、期間 = 7、レム = 5。緑は 3 なので、レム >= 3 は赤を意味します。 7 − 5 = 2 を待ち、時間を 7 に移動します。 

これは、緑の境界に正確に到達すると通行が許可されないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、到着時間がちょうど赤のフェーズの開始時刻になる場合です。 たとえば、gi = 3、ri = 4 の場合、rem = 3 であれば、まさに遷移点にいます。 条件 rem >= gi により、これが赤として扱われ、待機が適用されます。 計算された待機時間は period − rem で、次の緑色のスタートに正しくジャンプします。 

もう 1 つの特殊なケースは、di 値が大きいことです。 周期が小さいときに di が 10^12 であるとします。 モジュロ演算によりこれが自動的に正規化されるため、事前に di を明示的に減らす必要はありません。 たとえば、period = 6 および di = 10^12 の場合、(time + di) % 6 は、オーバーフローや不正なスケーリングを発生させることなく、位相を正しくキャプチャします。 

最後の微妙なケースは、gi = 0 の場合です。その場合、rem < gi は決して真ではないため、到着するたびに完全なサイクルの待機がトリガーされます。 period − rem は常に次のサイクル境界に進み、特別なケースを使用しなくても正確さが保証されるため、この式は引き続き機能します。
