 ## 解決策
 ## 問題の理解

 1 から始まる一連のルームが与えられ、それらを厳密に順番に処理します。 ルームのプレフィックスを移動している間、現在の回答と呼ばれる単一の整数値を維持します。 

各部屋は 2 つの方法のいずれかで貢献します。 どの部屋に入ると、常に現在の答えが 1 つだけ増えます。 さらに、一部の部屋はジャンクションとしてマークされており、ジャンクション ルームに入ると、増分を適用した直後に現在の答えが 2 倍になります。 

タスクは、すべての部屋を順番に処理した後、この実行中のプロセスの最終値を計算することです。 

これを解釈する便利な方法は、答えが一連の決定論的な変換を通じて進化するということです。 すべてのステップで固定の「1 を加える」が適用され、場合によっては追加の「2 を掛ける」が適用されます。 難しいのは 1 回の操作ではなく、繰り返される 2 倍化が以前の増分とどのように相互作用するかを理解することです。 

最大 10^5 の部屋がある場合は、部屋ごとに一定量を超える作業をシミュレートするあらゆるソリューションが許容されます。 ただし、以前の各寄与が将来の 2 倍化を通じてどのように伝播するかを明示的にモデル化しようとする素朴な解釈は、各結合点が以前のすべての寄与に潜在的に影響を与えるため、すぐに 2 次関数になります。 

ジャンクションごとに「寄与を再計算」しようとすると、微妙な失敗のケースが発生します。 たとえば、すべての部屋がジャンクションであるシーケンスを考えてみましょう。 保存されている以前の増分の合計を繰り返し 2 倍にし、同時に履歴を再適用しようとする単純な方法では、事実上同じプレフィックスを何度も再処理することになり、繰り返しの作業がステップごとに線形に増加することになります。 

もう 1 つのエッジ ケースは、ジャンクションがまったくない場合です。 この場合、部屋ごとに 1 つずつ追加するだけで、決して乗算しないため、答えは単純に n になります。 少なくとも 1 つの 2 倍算を前提とした誤った実装や、乗算の前後で誤った初期化を行うと、誤った結果が生成されます。 

## アプローチ

 ブルートフォース解釈は、答えの進化を直接シミュレートしようとします。 ゼロから開始して、部屋を左から右に繰り返し、部屋ごとに 1 を追加し、ジャンクションに遭遇するたびに、現在の値全体に 2 を掛けます。 

このシミュレーションは、記載どおりのルールに従っているため、正確です。 しかし、重要な問題は「現在値」が何を表すかに隠されています。 2 を掛けると、以前のすべての寄与も暗黙的に 2 倍になります。 個々の +1 操作の寄与という観点から考えると、その後に出現するジャンクションの数に応じて、それらの寄与はそれぞれ 2 倍になる可能性があります。 

最終値をより構造的に計算する直接的な方法は、視点を逆にすることです。 値を前方に追跡する代わりに、各位置の寄与が将来のジャンクションによって何倍に拡大されるかを追跡します。 ジャンクションを通過するたびに、そのジャンクションの前にあるすべてのものは、将来の影響において実質的に 2 倍の係数をさらに 1 つ獲得します。 これは、ジャンクションの効果が接尾辞に対して乗算的であることを示唆しています。 

重要な観察は、すべての位置が基本値 1 に寄与し、その最終的な重みは、その位置またはその後に出現するジャンクションの数によって決定されるということです。 位置 i で始まるサフィックスに k 個のジャンクションがある場合、位置 i の寄与は 2^k 倍されます。 

これにより、問題は単純な接尾辞の計算に簡素化されます。つまり、右側に残っているジャンクションの数を数え、それに応じて寄与を蓄積します。 サフィックス数を逆の順序で計算し、1 回のパスで答えを更新できます。

 | サフィックス倍加数 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

部屋を右から左に処理して、サフィックスに存在するジャンクションの数を常に把握できるようにします。 

1. 変数を初期化する`multiplier`これは、右側のジャンクションによって新しい +1 寄与が何倍にスケールされるかを表します。 
2.初期化`answer`これにより、最終結果が累積されます。 
3. n から 1 までの部屋を移動します。 
4. 部屋ごとに、次を追加します。`multiplier`に`answer`。 これは、現在の部屋の寄与が 1 であることを反映していますが、その後に来るすべてのジャンクションの影響を受け、それぞれのジャンクションの値が 2 倍になります。 
5. 部屋 i がジャンクションの場合、乗算します。`multiplier`by 2。これにより、将来の 2 倍化がさらに 1 つ適用されるため、以前のすべての部屋の効果が更新されます。 
6. すべての部屋が処理され、出力されるまで続行します。`answer`。 

各ステップ内の操作の順序は重要です。 サフィックスベースの 2 倍化を考慮する場合、現在の部屋はそれ自体のジャンクション ステータスの影響を受けるべきではないため、更新する前にまず現在の乗数を使用して寄与を適用する必要があります。 

### なぜ効果があるのか

 重要な不変条件は、位置 i にいるとき、`multiplier`2 は、厳密に i の右側にあるジャンクションの数に累乗したものと等しくなります。 これにより、追加するときに`multiplier`その答えに対して、部屋 i からのユニット寄与に将来の 2 倍化の正しい数を正確に適用しています。 更新中`multiplier`現在のルームは処理後にのみこの厳密なサフィックス定義を保持し、自己影響を防ぎ、正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # assuming a[i] = 1 if junction, 0 otherwise
    answer = 0
    multiplier = 1

    for i in range(n - 1, -1, -1):
        answer += multiplier
        if a[i] == 1:
            multiplier *= 2

    print(answer)

if __name__ == "__main__":
    solve()
```このソリューションは、将来のジャンクションによってユニット寄与が実質的に何倍になるかを捕捉する実行中のサフィックス乗数を維持します。 各部屋は 1 回だけ寄与し、適切にスケーリングされ、ジャンクションは以前のすべての位置のスケーリングを更新します。 

よくある間違いは、答えに追加する前に乗数を更新することです。これにより、部屋自体のジャンクション エフェクトが誤って適用されてしまいます。 もう 1 つの微妙な問題は、オーバーフローの安全性を想定していることです。 Python ではこれは自動的に行われますが、固定幅の整数言語では注意して処理する必要があります。 

## 実用的な例

 ### 例 1

 部屋がどこにあるのかを考慮する`[0, 1, 0]`、つまり 2 番目の部屋のみがジャンクションであることを意味します。 

| 私 | 部屋 | 乗数 | 貢献が追加されました | 答え |
 | --- | --- | --- | --- | --- |
 | 2 | 0 | 1 | 1 | 1 |
 | 1 | 1 | 1 | 1 | 2 |
 | 0 | 0 | 2 | 2 | 4 |

 このトレースは、位置 1 のジャンクションが左側へのすべての寄与を 2 倍にし、右側への寄与は影響を受けない様子を示しています。 

### 例 2

 すべての部屋がジャンクションであると考えてください。`[1, 1, 1]`。 

| 私 | 部屋 | 乗数 | 貢献が追加されました | 答え |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | 1 | 1 | 1 |
 | 1 | 1 | 2 | 2 | 3 |
 | 0 | 1 | 4 | 4 | 7 |

 初期の各位置には追加の倍加係数が見られ、サフィックスの倍増の繰り返しと一致する幾何学的増加が生じます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    answer = 0
    multiplier = 1

    for i in range(n - 1, -1, -1):
        answer += multiplier
        if a[i] == 1:
            multiplier *= 2

    return str(answer)

# minimum size
assert run("1\n0\n") == "1"
assert run("1\n1\n") == "1"

# no junctions
assert run("3\n0 0 0\n") == "3"

# all junctions
assert run("3\n1 1 1\n") == "7"

# alternating
assert run("4\n1 0 1 0\n") == "6"

 ## 特殊なケース

 ジャンクションではない単一の部屋が最も単純なケースです。 このアルゴリズムは乗数を 1 に設定し、1 回加算して 1 を出力します。これは 2 倍化が発生しないため、予想される結果と一致します。 

単一ジャンクション ルームの場合、アルゴリズムは乗算を適用する前に 1 を加算します。 右側には部屋がないため、乗数は全体を通して 1 のままで、結果は再び 1 になります。これは、2 倍化は以前の部屋にのみ影響し、部屋は存在しないという事実と一致します。 

完全に非接合の配列では、乗数は 1 から変化しません。各反復では正確に 1 が加算されるため、最終結果は n となり、増分のみが発生するという解釈と一致します。 

完全ジャンクション配列では、左に移動するにつれて乗数は 1、2、4、8 と変化します。 各寄与は将来のジャンクションの数によって重み付けされ、最終的な幾何学和は逆累積によって正しく生成されます。
