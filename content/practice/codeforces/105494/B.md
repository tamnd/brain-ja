 ## 解決策
 ## 問題の理解

 時間の経過とともに適用される一連の変更が与えられます。各要素は、観察後に蟻塚内のアリの数がどのように変化するかを記述します。 正の値はアリが追加されることを意味し、負の値はアリが去ることを意味します。 

蟻塚の初期のアリの数はわかりません。 その代わりに、どの時点においてもアリの数がマイナスになってはいけないと言われます。 最初の数を次のように表すと、`ans`、最初の処理後`i`変化すると、アリの総数は`ans + p[i]`、 どこ`p[i]`最初のプレフィックスの合計です`i`変化します。 制約は、この値がすべてのプレフィックスに対して非負でなければならないということです。 

したがって、問題は可能な限り小さい初期値を選択することになります。`ans`そのため、どの時点でも累計がゼロを下回ることはありません。 

入力は単なる変更のリストであり、出力はこの最小の有効な開始値です。 

複雑さの観点から見ると、配列は O(n²) シミュレーションが実行不可能なほど大きくなる可能性があります。 当然の制約は、データを 1 回または一定の回数だけ通過する必要があるということであり、これは O(n) 個の解を指します。 

すべてのプレフィックスの合計を明示的に再構築し、妥当性をチェックする素朴なアプローチでは、依然として O(n) になりますが、より危険な素朴な亜種は、考えられるすべての初期値を試してシミュレーションするもので、すぐに O(n · maxValue) まで膨れ上がってしまいます。 

すべての変化がマイナスの場合、微妙なエッジケースが発生します。 たとえば、シーケンスが次の場合、`[-5, -2, -3]`、プレフィックスの合計は以下に達します`-10`したがって、答えはその最も深い落ち込みを補う必要があります。 もう 1 つのエッジ ケースは、シーケンスがプレフィックスの合計で負にならない場合です。`[2, 1, 3]`、正解はゼロです。 プレフィックスの最小値を考慮することを忘れたアプローチは、これらの極端ないずれかで失敗します。 

## アプローチ

 強引な解釈は、アリの初期数を選択し、そのプロセスをシミュレートすることを想像することです。 各候補の開始値について、配列を調べて累計を維持し、それが負になるかどうかを確認します。 一致する場合は、開始値が小さすぎるため、より大きな値を試します。 

これは、すべてのステップで制約を直接強制するため機能します。 ただし、候補ごとに配列全体をスキャンし、最悪の場合、プレフィックス合計の負のドリフトの大きさに比例する開始値を試行する必要がある場合があります。 これにより、最悪の場合、候補ごとに n 個のチェックが行われ、最大 O(maxPrefix) 個の候補が生成され、非常に大きくなります。 

重要な観察は、ゼロから開始すると仮定した場合、開始値の実現可能性は、実行中のプレフィックス合計が到達する最低点によって完全に決定されるということです。 プレフィックス合計を定義すると`p[i]`、から始まります`ans`曲線全体を上にシフトします`ans`。 唯一の危険な点は、合計が最小となる最小プレフィックス値です。 あらゆる場所で非ネガティブ性を確保することは、`ans + min(p) ≥ 0`。 

これにより、問題は単一の数量、つまり最小プレフィックス合計の計算に分解されます。 それがわかったら、最小の有効な開始値は、単にその最小値をゼロまで上げるのに必要な量になります。

 | プレフィックス最小追跡 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ゼロに初期化された累計値から開始します。 これは、開始値がゼロであると仮定した場合のプレフィックスの合計を表します。 
2. 現在までに到達した累計の最小値を格納する別の変数を維持します。 要素を処理する前は合計がゼロになるため、これをゼロに初期化します。 
3. 配列内の各値を反復処理し、現在の値を加算して累計を更新します。 これは、プレフィックス合計を保存せずに段階的に構築することをシミュレートします。 
4. 各更新後に、現在の合計を保存された最小値と比較し、現在の合計の方が低い場合は最小値を更新します。 これは赤字の最も深い点を捉えています。 
5. すべての値を処理した後、最小プレフィックス合計の否定として答えを計算します。 これは、最低点が確実にゼロになるために必要な最小の上方シフトです。 

### なぜ効果があるのか

 各ステップの累計は、ゼロから開始すると仮定して、システムがゼロからどれだけドリフトしたかを表します。 有効な初期値は、これらすべての値を定数だけ上方にシフトするだけです。 最悪の制約は常に最小のプレフィックス合計です。シフト後にその点が負でない場合、その後のすべての点も負ではないからです。 したがって、最適なシフトは、最小プレフィックス合計をゼロにするのに必要な量であり、それより大きいものは最小ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    delta = 0
    min_delta = 0

    for v in a:
        delta += v
        if delta < min_delta:
            min_delta = delta

    print(-min_delta)

if __name__ == "__main__":
    solve()
```このソリューションはシーケンスを読み取り、現在のプレフィックス合計とこれまでに確認された最小プレフィックス合計の 2 つの変数のみを維持します。 初期のゼロ状態を含むすべてのプレフィックス状態の最小値が必要なため、更新順序が重要になります。 

最終出力は、最小プレフィックス合計の否定です。 数列がゼロを下回らない場合、`min_delta`ゼロのままであり、答えは正しくゼロです。 

## 実用的な例

 入力シーケンスを考慮する`[3, -4, 2]`。 

| ステップ | 値 | プレフィックス合計 (デルタ) | 最小プレフィックス (min_delta) |
 | --- | --- | --- | --- |
 | 開始 | - | 0 | 0 |
 | 1 | 3 | 3 | 0 |
 | 2 | -4 | -1 | -1 |
 | 3 | 2 | 1 | -1 |

 最小プレフィックス合計は次のとおりです。`-1`、したがって、答えは次のとおりです`1`。 これは、最低点が正確にゼロに達するように 1 つのアリから開始することに対応します。 

ここで考えてみましょう`[2, 2, 2]`。 

| ステップ | 値 | プレフィックス合計 (デルタ) | 最小プレフィックス (min_delta) |
 | --- | --- | --- | --- |
 | 開始 | - | 0 | 0 |
 | 1 | 2 | 2 | 0 |
 | 2 | 2 | 4 | 0 |
 | 3 | 2 | 6 | 0 |

 プレフィックスはゼロを下回ることはありません。そのため、最小値はゼロであり、答えはゼロです。 これにより、補償が必要ない場合が確認されます。

このアルゴリズムは、プレフィックス配列の保存やネストされた計算の実行を回避し、入力サイズを線形にするため、制約内に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    a = list(map(int, input().split()))

    delta = 0
    min_delta = 0

    for v in a:
        delta += v
        if delta < min_delta:
            min_delta = delta

    return str(-min_delta)

# minimum size
assert run("1\n5\n") == "0", "single positive"

# single negative
assert run("1\n-7\n") == "7", "single negative"

# all positive
assert run("3\n1 2 3\n") == "0", "no deficit"

# mixed case
assert run("3\n3 -4 2\n") == "1", "prefix dip"

# all negative
assert run("3\n-1 -2 -3\n") == "6", "strong deficit"

 ## 特殊なケース

 正の数を含む単一要素配列の場合、累計がゼロを下回ることはありません。そのため、最小プレフィックスはゼロとなり、出力はゼロになります。 次のような単一の負の要素の場合、`[-7]`、プレフィックスの合計はすぐに負になり、次の値に達します。`-7`したがって、必要なオフセットは正確に`7`。 このアルゴリズムは、最小プレフィックスをゼロに初期化し、より低い実行合計が表示された場合にのみそれを更新するため、両方のケースを正しく捕捉します。
