 ## 解決策
 ## 問題の理解

 利用可能なアイスクリームのフレーバー、利用可能な霧雨、利用可能なトッピングという 3 つの独立した文字列リストが与えられます。 有効なデザートは、アイスクリームを正確に 2 スクープ選択し、次に小雨とトッピングを 1 つ選択することで構成されます。 2 つのスクープはフレーバー リストから選択され、繰り返しは許可されますが、2 つのスクープを交換しても新しいデザートは作成されません。 スコップを固定した後、霧雨とトッピングをそれぞれ 1 つずつ選択します。 

課題は、これらのルールに従って、いくつの異なるデザートを形成できるかを数えることです。 区別は純粋に組み合わせによるものです。選択したフレーバーの組み合わせ、霧雨、またはトッピングが異なると、2 つのデザートが異なります。 霧雨とトッピングは単一選択コンポーネントであるため、独立した乗算因子のように動作します。 

制約は小さく、各リストの要素は最大 100 個です。 これは、約数百万回の操作までのソリューションは安全であることを直ちに意味します。 フレーバーに関する 2 次または 3 次の組み合わせ列挙は許容されますが、3 次よりも悪いものは制限により通過する可能性があります。 

正確さのためには、いくつかの特殊なケースが重要です。 

味が 1 つしかない場合は、次のように言います。`A`の場合、唯一の有効なスクープ ペアは`(A, A)`。 異なるフレーバーのペアのみを考慮する単純なアプローチでは、誤ってゼロが返されます。 たとえば、次のように入力します。```
A
B
C
```正しい出力は`1`、まだ選択できるからです`(A, A)`。 

フレーバーが複数であるが、繰り返し選択が許可されている場合、順序付けされていないペアが二重にカウントされないことを確認する必要があります。 例えば、`(A, B)`そして`(B, A)`一つとして扱わなければなりません。 

もう 1 つの微妙なケースは、すべての自己ペアを正しく含めることです。`(A, A)`個別のペアだけでなく、あらゆるフレーバーに対応します。 

## アプローチ

 直接的な総当たりアプローチは簡単です。 考えられるすべてのフレーバーのペアを列挙し、繰り返しを許可し、ペアを順序付けされていないものとして扱います。 そのようなペアごとに、霧雨とトッピングを個別に選択します。 あれば`n`フレーバー、`d`霧雨、そして`t`トッピング、ブルートフォースはすべてを反復します`n × n`順序付きペア、順序制約を適用して重複をフィルタリングし、乗算します。`d × t`。 

これは正しく機能しますが、不必要に重くなり、構造がわかりにくくなります。 重要な観察は、霧雨とトッピングがスクープの選択から完全に独立しているということです。 有効な順序付けされていないスクープ ペアを数えたら、残りは単に乗算するだけです。 

したがって、問題は、繰り返しのある組み合わせ、つまり 2 つの要素を選択する方法の数を数えるということになります。`n`順序は重要ではなく、繰り返しが許可されるフレーバー。 これは古典的な組み合わせカウントです。$$\binom{n+1}{2} = \frac{n(n+1)}{2}$$この値を計算した後、霧雨とトッピングの数を掛けます。 

これにより、問題全体が単純な解析と算術に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(n² + d + t) | お(1) | 承認済み |
 | 組み合わせ公式 | O(n + d + t) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. フレーバーのリストを読み、何種類あるか数えます。 これに電話してください`n`。 個々の名前はカウントに影響しないため、これが必要なフレーバーの唯一のプロパティです。 
2. 霧雨を読み、次のように数えます。`d`。 
3. トッピングを読み、次のように数えます。`t`。 
4. 次の式を使用して、繰り返しが許可される順序付けされていないフレーバーのペアの数を計算します。`n * (n + 1) // 2`。 これは、個別のペアと自己ペアの両方を説明します。 
5. フレーバーペアの数を次のように掛けます。`d`そして`t`最終的な答えを得るために。 
6. 結果を出力します。 

重要なステップは、サイズ 2 のマルチセットの組み合わせの同一性を使用することです。その理由は、有効な各デザートは、フレーバーからサイズ 2 のマルチセットを選択し、その後、1 つの霧雨と 1 つのトッピングを個別に選択することによって完全に決定されるということです。 

### なぜ効果があるのか

 すべてのデザートは、正確に 1 つのトリプルに対応します。つまり、2 つのフレーバー、1 つの霧雨、および 1 つのトッピングのマルチセットです。 フレーバー コンポーネントは、他の 2 つの選択肢から独立しています。 から抽出されたサイズ 2 のマルチセットの数`n`-要素セットは正確です`n(n+1)/2`で 2 つの同一の要素を選択できるため、`n`または 2 つの異なる要素を選択します`n(n-1)/2`方法。 これらを合計すると、`n(n+1)/2`。 すべての有効なデザートは、そのようなマルチセット 1 つと他の 2 つのリストからのそれぞれ 1 つの選択肢によって一意に決定されるため、カウントを乗算するとデザートの総数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    flavors = input().split()
    drizzles = input().split()
    toppings = input().split()

    n = len(flavors)
    d = len(drizzles)
    t = len(toppings)

    scoop_pairs = n * (n + 1) // 2
    print(scoop_pairs * d * t)

if __name__ == "__main__":
    main()
```この実装は、行ごとのトークンのカウントのみに依存します。 名前は身元を超えて無関係であるため、各行を分割して長さを取得するだけで十分です。 

唯一の微妙な点は、`n * (n + 1) // 2`それよりも`n * n`、これは誤った扱いになります`(A, B)`そして`(B, A)`明確に。 整数の除算により、浮動小数点のリスクなしで正確な組み合わせカウントが保証されます。

 ## 特殊なケース

 単一のフレーバーの場合、次のようになります。```
A
B
C
```我々は持っています`n = 1`、つまりスクープペア =`1 * 2 / 2 = 1`。 アルゴリズムには正しく含まれています`(A, A)`。 の乗算`d`そして`t`結果は変更されず、`1`。 

2 つのフレーバーの場合:```
A B
X Y
Z
```アルゴリズムが計算します`n = 2`、スクープ ペア = 3。これらは次のとおりです。`(A, A)`、`(B, B)`、`(A, B)`。 それぞれに 1 つのトッピングと 2 つの霧雨が組み合わされ、合計 6 つのデザートが作成されます。 数式は二重カウントを正しく回避します`(B, A)`組み合わせ式によってすでに順序なしの選択が強制されているためです。 

繰り返しを最大限にするには:```
F F F ... (100 times)
D
T
```すべての名前が同一であっても、フレーバー リストでは別個の要素としてカウントされるため、`n = 100`。 アルゴリズムは計算します`100 * 101 / 2 = 5050`、これは、繰り返しが許可された 2 つの位置のインデックスベースの選択の数と一致します。 これにより、モデルが等価性を超えた文字列の一意性ではなく、リスト内の位置に基づいていることが確認されます。
