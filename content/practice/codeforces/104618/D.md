 ## 解決策
 ## 問題の理解

 垂直方向のスタックが与えられます$n$アイスクリームの層。 各レイヤーはアルファベット上の文字列です$\{R, G\}$、そのレイヤー内のキャンディーを左から右に表します。 このプロセスは厳密にシーケンシャルです。レイヤー 1 から開始し、次にレイヤー 2 というようにレイヤーが完成するまで続きます。$n$。 レイヤー内では、指定された順序でキャンディーを消費する必要があり、レイヤー内またはレイヤー間で順序を変更することはできません。 

すべてのレイヤーを順番に連結して 1 つの長いシーケンスに平坦化することを想像すると、問題は次のようになります。1 つの色のみで構成される最長の連続セグメントを見つけるか、すべての色で構成されるかを見つけます。$R$またはすべて$G$ただし、セグメントはレイヤーの境界と走査順序を尊重するという制限があります。 

つまり、事実上、指定されたすべての文字列を連結した単色の部分文字列の最大長を探していることになります。 

重要な微妙な点は、合計の長さが最大になる可能性があるため、連結された文字列を明示的に構築しないことです。$2 \cdot 10^5$これは問題ありませんが、レイヤー間の遷移を追跡することでストリーミング形式で解決することもできます。 

制約$\sum c_i \le 2 \cdot 10^5$を暗示します$O(N)$または$O(N \log N)$解決策が必要ですが、直線的な構造なのでシングルパスで十分です。 レイヤーまたは位置に対する二次アプローチは遅すぎます。 

実行がレイヤー境界を越える場合、エッジケースが発生します。 たとえば:

 入力:```
2
RRR
RR
```実行はレイヤー間で継続されるため、正しい出力は 5 です。 単純なレイヤーごとの最大値は誤って 3 を返します。 

別のケース:```
3
RR
GR
RR
```不注意なアプローチを行うと、すべてのレイヤー境界でリセットされ、境界文字に基づいて実行が再開または続行される可能性があります。 

主なリスクは、境界文字が一致する場合に連続するレイヤーのマージに失敗することです。 

## アプローチ

 強引な解釈では、すべての文字列を 1 つのシーケンスに連結し、それをスキャンして同一文字の最長の連続を計算します。 これは簡単です。すべての文字を反復処理し、現在のストリークの長さを追跡し、文字が変更されたときにリセットし、最大値を更新します。 

この問題は基本的に線形シーケンス上のランレングス問題であるため、これは正しく機能します。 ただし、連結は概念的には単純ですが、文字列を明示的に構築する必要はなく、トランジションをマージせずにレイヤーごとに繰り返し処理を行うと、慎重に扱わないと誤ったロジックが発生する可能性があります。 

この改善は、ランダム アクセスやバックトラッキングがまったく必要ないことに気づいたことから生まれました。 ストリーミング入力全体で現在のストリークを維持することだけが必要です。 どの時点でも、必要な情報は最後に表示された文字と現在のストリークの長さだけです。 

これにより、問題はすべてのレイヤーのすべての文字を 1 回通過するだけで済みます。

 ## アルゴリズムのチュートリアル

 レイヤーを 1 つずつ処理し、各レイヤー内でグローバル ストリークを維持しながら文字を左から右に処理します。 

1. 変数の初期化`last`空として、`cur`0として、そして`best`0として。 

これらは、前の文字、現在のランの長さ、およびこれまでに確認された最大ランを追跡します。 
2. 各レイヤー文字列を 1 から 1 までの順序で繰り返します。$n$。 

これにより、必要な消費順序が保持されます。 
3. キャラクターごとに$ch$現在の文字列内:

 もし$ch = last$、増分`cur`それ以外の場合はリセット`cur`1に設定してください`last = ch`。 

このステップでは、次の不変条件が維持されます。`cur`は、同一の文字で構成される現在の最大サフィックスの長さと正確に一致します。 
4. アップデート後`cur`、 アップデート`best = max(best, cur)`。 

これにより、すべてのポジションで終了する最大のランを確実に捉えることができます。 
5.全レイヤー処理後、出力`best`。 

### なぜ効果があるのか

 アルゴリズムは、平坦化されたシーケンス内のすべての位置で、その位置で終わる最大の連続ブロックの長さを維持します。 有効な答えはいずれも何らかの位置で終了する必要があり、実行可能なすべての実行は終了時に 1 回だけ考慮されるため、これで十分です。 状態圧縮`(last, cur)`キャラクターが変更されると、現在の実行以降の以前の履歴はすべて無関係になるため、これで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    last = None
    cur = 0
    best = 0

    for _ in range(n):
        s = input().strip()
        for ch in s:
            if ch == last:
                cur += 1
            else:
                last = ch
                cur = 1
            if cur > best:
                best = cur

    print(best)

if __name__ == "__main__":
    solve()
```この実装は、結合された文字列を構築せずに、すべてのレイヤーを直接ストリーミングします。 変数`last`状態は文字列上のループ間で持続するため、層の境界を越えても遷移を正しく検出できます。 

よくある間違いはリセットです`last`または`cur`新しいレイヤーごとに、複数のレイヤーにまたがる有効な実行が誤って破壊されてしまいます。

 ## 特殊なケース

 重要なエッジケースは、実行がレイヤー境界を正確に越えて継続する場合です。 考慮する：```
2
RRR
RR
```アルゴリズムは維持します`last = 'R'`1層目を終えた後なので、2層目に入っても自然にスジが続きます。 状態は次のようになります。`cur = 5`、正解を生成します。 

もう 1 つのケースは、リセットが繰り返される場合です。```
3
R
G
R
```ここで各文字変更が強制されます`cur = 1`。 このアルゴリズムは、不連続なセグメントを誤ってマージすることはありません。`last`常に直前の文字をグローバルに追跡します。 

最後に、レイヤー内の境界の変更は、レイヤー間の境界の変更と同じように処理されます。これは、どちらも単一の s での単なる文字比較であるためです。
