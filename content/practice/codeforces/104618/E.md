 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$N$染料。それぞれが正の整数の美しさの値を持ちます。 このシーケンスから、選択した 2 つの位置が元の行で隣接しないように位置のサブセットを選択します。 選択のスコアは選択された美しさの値の合計であり、このスコアを最大化したいと考えています。 

より身近な言葉で言えば、これはパス グラフ上の最大重み独立セットです。各位置はノードであり、エッジは連続するインデックスを接続しており、隣接するノードを選択することはできません。 

制約$N \le 10^5$指数関数的なサブセットの列挙を除外します。 ナイーブ$O(2^N)$アプローチは不可能ですし、$O(N^2)$サブ配列上の遷移は遅すぎます。 線形または線形に近い動的プログラミング ソリューションが必要です。 

微妙なエッジケースは、貪欲な直感が役に立たない小さな配列から発生します。 たとえば、次のことを考えてみましょう。 

入力:```
3
10 1 10
```局所的に最適な要素を選択するような素朴な貪欲な戦略は、注意しないと両方の 10 を選択する可能性がありますが、それらは隣接していないため、ここでは機能します。 ただし:

 入力:```
4
8 9 8 9
```状態追跡を行わずに残りの最大要素を貪欲に繰り返し選択すると、実装順序によっては失敗する可能性がありますが、正解は 18 (インデックス 2 と 4 を選択) です。 

もう 1 つのエッジケースは次のような場合です$N=1$ここで、答えは単一の値にすぎず、DP 定式化は基本状態を正しく初期化する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、インデックスのすべてのサブセットを試し、隣接するペアが含まれているかどうかを確認します。 各サブセットについて、その合計を計算し、最大値を追跡します。 がある$2^N$サブセット、および各サブセットのコストの確認$O(N)$直接実装した場合、$O(N2^N)$時間。 ビット操作を使用してサブセットのチェックを最適化したとしても、サブセットの指数関数的な数がボトルネックのままです。 

重要な観察は、決定がインデックスでローカルに行われるということです。$i$、私たちが知っている必要があるのは、摂取したかどうかだけです。$i-1$。 インデックスをスキップすると$i$までのベストスコア$i$までと同じです$i-1$。 インデックスを取ると$i$、その値を最適なソリューションに追加する必要があります。$i-2$。 これにより、次のような答えが得られる最適な下部構造が作成されます。$i$前の 2 つの状態にのみ依存します。 

これにより、問題は古典的な「隣接しない要素の最大合計」と同様の単純な反復に帰着します。 

させて$dp[i]$最初の値のみを使用して達成可能な最大の合計になります。$i$要素。 それから：$$dp[i] = \max(dp[i-1], dp[i-2] + b_i)$$これにより、直ちに線形時間 DP が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N2^N)$|$O(N)$| 遅すぎる |
 | 動的プログラミング |$O(N)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最後の 2 つの DP 状態のみを維持しながら、配列を左から右に処理します。 

1. 空のプレフィックスと長さ 1 のプレフィックスに対する最良の回答を表す 2 つの変数を初期化します。 空のプレフィックスの値は 0 で、最初の要素の値は です。$b_1$。 
2. ポジションごとに$i$2から$N$、2 つの可能性を計算します。現在の要素をスキップして以前の最良を維持するか、現在の要素を取得して追加します。$b_i$2歩後退から最良の結果へ。 これら 2 つのうちの大きい方が新しい状態になります。 
3. 新しい状態を計算した後、「前の」値と「2 ステップ前の」値が次の反復で常に正しく位置合わせされるように、前の状態を前方にシフトします。 
4. すべての要素が処理されるまで続行します。 最終的な答えは、最後の位置の最良の値です。 

これが機能する理由は、すべての最適解には最後の要素が含まれるか除外される必要があり、どちらの場合も、必要な制約で重複しない厳密に小さなサブ問題に縮小されるためです。 

### なぜ効果があるのか

 すべてのインデックスで$i$、有効な選択は 2 つの互いに素なクラスに分割されます。$i$、これらは正確に最初のすべての有効な選択です$i-1$要素、およびそれを含む要素$i$の除外を強制します。$i-1$最初の選択を有効な選択に減らします$i-2$要素。 これら 2 つのケースはすべての可能性をカバーし、最適な下部構造を維持するため、最大値を取得することで帰納的に全体的な最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
b = list(map(int, input().split()))

if n == 0:
    print(0)
    sys.exit()

if n == 1:
    print(b[0])
    sys.exit()

prev2 = 0
prev1 = b[0]

for i in range(1, n):
    take = prev2 + b[i]
    skip = prev1
    cur = max(skip, take)
    prev2 = prev1
    prev1 = cur

print(prev1)
```この実装では、DP 配列を 2 つの変数に圧縮します。`prev1`を表します$dp[i-1]$、 その間`prev2`を表します$dp[i-2]$。 各ステップで、反復を直接計算します。 

基本ケースのハンドル$N=1$未定義の DP 値に依存しないように、明示的に指定します。 移行順序は重要です。`prev2`現在の状態を計算した後に更新する必要があります。そうしないと、次の反復に必要な値が上書きされてしまいます。 

## 実用的な例

 ### 例 1

 入力:```
5
5 10 9 10 7
```| 私 | b[i] | スキップ (dp[i-1]) | take (dp[i-2]+b[i]) | dp[i] |
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 0 | 5 | 5 |
 | 1 | 10 | 5 | 10 | 10 |
 | 2 | 9 | 10 | 14 | 14 |
 | 3 | 10 | 14 | 20 | 20 |
 | 4 | 7 | 20 | 21 | 21 |

 最終的な値 21 は、1 ベースのインデックス付け (10 + 10 + 7) でインデックス 1、3、および 5 を選択することによって得られます。 この表は、各状態がスキップと取得をどのように明示的に比較し、隣接関係の制約が確実に尊重されるかを示しています。

4

```| 私 | b[i] | スキップ | 取る | DP |

 最適なソリューションでは、隣接を避けるために選択を交互に行います。 DP は交互のピックを正しく蓄積し、以前の決定を追跡せずに貪欲なローカル選択では不十分であることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N)$| 各要素は定数時間遷移で 1 回処理されます。 
| スペース |$O(1)$| ローリング DP 状態は 2 つだけ保存されます。 

リニアスキャンは以下の用途に最適です。$N = 10^5$、定数メモリにより、256 MB の制限を圧迫することはありません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input().strip())
    b = list(map(int, input().split()))
    
    if n == 0:
        return "0"
    if n == 1:
        return str(b[0])

    prev2 = 0
    prev1 = b[0]

    for i in range(1, n):
        cur = max(prev1, prev2 + b[i])
        prev2 = prev1
        prev1 = cur

    return str(prev1)

# provided sample
assert run("5\n5 10 9 10 7\n") == "21"

# minimum size
assert run("1\n42\n") == "42"

# two elements
assert run("2\n5 100\n") == "100"

# all equal
assert run("5\n7 7 7 7 7\n") == "21"

# alternating high values
assert run("4\n10 1 10 1\n") == "20"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 要素 | 42 | 基本ケースの正確性 |
 | 2つの要素 | 100 | 隣接するペア間の正しい最大値の選択 |
 | すべて等しい | 21 | 複数の最適な選択を処理する |
 | 交互のピーク | 20 | DP は交互のインデックスを最適に選択します。 

## 特殊なケース

 のために$N=1$の場合、ループが完全にスキップされるため、アルゴリズムは単一の値を直接返します。 これにより、無効な DP 状態へのアクセスが回避されます。 

のために$N=2$の場合、遷移は初期化以降の特別なロジックを必要とせずに、最初または 2 番目の要素の取得を正しく比較します。 

例えば：```
2
5 100
```初期化すると、`prev2 = 0`、`prev1 = 5`。 インデックス 2 で次のように計算します。`take = 100`、`skip = 5`、結果は 100 になります。これは、2 番目の要素のみを選択するという最適な選択と一致します。 

これは、分岐ロジックを追加しなくても、最小限の構成であっても繰り返しが隣接関係の制約を自然に処理することを示しています。
