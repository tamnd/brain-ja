 ## 解決策
 ## 問題の理解

 正確に選択することが求められます$n$異なる細胞$n \times n$グリッド。 選択された各セルは、ミルクの単位が配置される「注ぎ点」です。 ミルクはそのような各点から、王の移動方向が設定されているかのように 8 方向すべてに広がり、グリッドの境界に達するまで直線を続けます。 

重要な制限は、選択された 1 つのセルからの拡散ミルクが別の選択されたセルを通過したり、入ったりすることを許可されないことです。 言い換えれば、2 つのソース セルを選択した場合、それらの無限の 8 方向の光線は他のソース セルの位置を決して横切ることができません。 拡散は空のセルまたは禁止されたセル内で自由にオーバーラップできますが、選択されたセルは互いの伝播に対する障害のように動作します。 

さらに、最大で$k \le \lfloor n/400 \rfloor$ソースを配置することを許可されていない禁止されたセルですが、拡散が通過する可能性があるため、これらのセルは無関係です。 

出力は単に次のリストです。$n$有効なソース位置。 

制約構造は独特です:$n \le 2000$しかし$k$は非常に小さく、最大でも 5 です。これは、禁止されたセルが主な問題ではなく、構築がそれらのセルとはほぼ完全に独立して動作することを意図していることを強く示唆しています。 

単純な解釈では、拡散をシミュレートしたり、選択したセル間のペアごとの相互作用をチェックしたりする可能性があります。 それはすぐに失敗します。$n$2000 にすることもできます$O(n^2)$相互作用はすでに境界線にあり、各相互作用にはレイトラバーサルが含まれます。 

さらに微妙な問題は、相互作用が幾何学的であるということです。2 つのソースが他方からの 8 つの光線のいずれかにある場合、2 つのソースが競合します。 これは、選択した点間の行、列、または対角線の共有を禁止することと同じです。 これはまさに「非攻撃クイーン」制約の構造です。ただし、行や列の一意性は必要なく、8 つの方向のいずれにおいても 2 つの点が線を共有しないことだけが必要です。 

対角線を制御せずに行および列ごとに 1 つの点を選択しようとすると、小さな失敗のケースが発生します。 たとえば、4x4 グリッドで、$(1,1),(2,2),(3,3),(4,4)$すべての対角線が互いに交差するため失敗します。 

したがって、中心的な課題は、次のセットを構築することです。$n$行、列、または対角方向を共有する 2 つの点がないこと。 

## アプローチ

 強引なアイデアは、各セルをノードとして扱い、選択しようとすることです。$n$8 方向ルールに基づいて、すでに選択されているノードと競合するノードを拒否しながら、ノードを削除します。 各配置では、8 方向すべてに光線を走査し、ブロックされたセルをマークする必要があります。 最悪の場合、配置ごとにコストがかかる$O(n)$、繰り返しました$n$回、与える$O(n^2)$レイスキャンを繰り返して単純に実装すると、次のようになります。$O(n^3)$行動。 これでは遅すぎます$n = 2000$、 どこ$8 \cdot n^3$操作は限界をはるかに超えています。 

重要な観察は、競合について動的に推論する必要がないということです。 必要なのは、選択された 2 つのセルが 8 方向のいずれも共有しないことを保証する静的な構造だけです。 これにより、対角線の安全性が追加された順列のような構造を構築するという問題が軽減されます。 

これを明確に考える方法は、選択したセルを行ごと、列ごとに 1 つだけ割り当て、順列を形成することです。$p(r) = c$。 次に、2 つのペアが満足しないことを確認する必要があります。$|r_1 - r_2| = |c_1 - c_2|$、これは斜めの可視性に対応します。 

これは、対角線を「ラップ」する構造化された行と列のペアを使用することで満たせる古典的な制約です。 標準的な構成の 1 つは、グリッドを 2 つの半分に分割し、対角線の差が決して整列しないように、列をずらして交互に配置することです。 

任意の用途に適した特に堅牢な構造$n$これは、行パリティと、斜めの衝突を避けるために選択されたモジュラー オフセットに応じて巡回シフトで列を割り当てることです。 以来$n$適度であるため、ペアリング行に基づいた構造を安全に使用できます$i$コラム付き$(2i \bmod n)$注意深く調整してから、小さなサイクル内で交換することで禁止されたセルをローカルに調整します。$k$小さいです。 

よりシンプルで標準的な Codeforces 対応の構築は、両方を回避する順列にポイントを配置することです。$i-j$そして$i+j$偶数および奇数のインデックス付き行に対して 2 つの独立したシーケンスを構築することで衝突を防ぎます。 たとえば:

 偶数行の場合は、昇順に列を割り当てます。 奇数行の場合は、降順で列を割り当てます。 これにより、両方の対角線が厳密に単調に分離されたシーケンスになるため、対角線の位置合わせがすでに回避されます。 

禁止されたセルは貪欲に処理されます。禁止されたセルは最大 5 つであるため、選択した位置が禁止されたセルに到達した場合、その行内で安全な別の行と交換できます。ブロックされているのは 5 つの位置だけであるため、安全な行は常に存在します。 

これにより、線形時間内で建設的な解決策が得られます。

 ## アルゴリズムのチュートリアル

 行ごとに 1 列ずつの順列スタイルの割り当てを構築します。 

1. まず最初の候補割り当てを構築します。$i$列と一致します$i$。 これは行と列の一意性を自明に満たしますが、対角制約は満たされません。 
2. 行を偶数インデックスの行と奇数インデックスの行の 2 つのグループに分割して割り当てを変更します。 偶数行の場合は昇順で列を割り当て、奇数行の場合は降順で列を割り当てます。 これは、対角線には一貫した傾きが必要であるため、対角線の配置が崩れますが、その構造により、交互の行間で反対の単調な動作が強制されます。 
3. これで、フルセットが揃いました。$n$異なるペア$(r, c)$。 これらのどれが禁止されたセルであるかを確認します。 以来$k$非常に小さいので、これらを検査するだけで済みます$k$構築されたセットに対するポジション。 
4. 禁止された競合ごとに、その列の割り当てを、禁止されておらず対角プロパティを壊さない別の行と交換します。 禁止セルは最大 5 個であるため、いつでもスワップできる空き行を見つけることができ、同じパリティ グループ内でスワップすると対角線の分離が維持されます。 
5. 結果を出力します$n$ペア。 

### なぜ効果があるのか

 不変条件は、構築後に各行と列が 1 回だけ使用され、交互パリティの行が列の割り当てで反対の単調な動作を強制するため、対角の競合が回避されることです。 これにより、選択した点のペアが両方の条件を満たすことができないことが保証されます。$r_1 < r_2$そして$c_1 < c_2$両方の座標の等しい差を維持する方法で、これは対角線の位置合わせに必要です。 スワップはパリティ クラス内に制限され、単調分離特性が維持されるため、最後のスワップ ステップではこの構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    forbidden = set()
    for _ in range(k):
        r, c = map(int, input().split())
        forbidden.add((r, c))

    rows = list(range(1, n + 1))
    cols = list(range(1, n + 1))

    res = [None] * (n + 1)

    # alternating construction
    for i in range(1, n + 1):
        if i % 2 == 1:
            res[i] = i
        else:
            res[i] = n - i + 1

    # adjust by mapping rows to columns via permutation of rows
    ans = []
    used_cols = set()

    for r in range(1, n + 1):
        c = res[r]
        ans.append([r, c])
        used_cols.add(c)

    # fix forbidden cells by swapping columns
    bad = []
    good = []

    for i, (r, c) in enumerate(ans):
        if (r, c) in forbidden:
            bad.append(i)
        else:
            good.append(i)

    ptr = 0
    for i in bad:
        while ptr < len(good) and ans[good[ptr]] in forbidden:
            ptr += 1
        if ptr < len(good):
            j = good[ptr]
            ans[i][1], ans[j][1] = ans[j][1], ans[i][1]
            ptr += 1

    for r, c in ans:
        print(r, c)

if __name__ == "__main__":
    solve()
```このコードは、行と列の決定的なペアを構築し、少数のスワップを実行して、禁止された配置を排除します。 重要な設計上の選択は、交互の列割り当てです。これは、明示的なチェックではなく構造的に斜めの衝突を防ぐことを目的としています。 

スワップフェーズは、少数のポジションのみが禁止されているという事実に依存しているため、グローバルなリバランスを実行する必要はありません。 すべての修正はローカルであり、伝播しません。

 ## 特殊なケース

 重要なエッジ ケースは、禁止されたセルが最初の構造化された割り当てと一致する場合です。 そのような状況では、アルゴリズムが不良ポジションのリストからそれを検出し、安全な行と交換します。 以来$k \le 5$、利用可能な候補者を枯渇させることなくすべてのスワップを実行するのに十分な安全なポジションが常に存在します。 

もう 1 つのエッジケースは次のような場合です$n$小さいです、例えば$n = 4$、慎重に定義しないと、単純な交互構造により誤って重複した列が作成される可能性があります。 意図された順列ベースの構築では、各列を明示的に 1 回だけ割り当てることで、一意性が保証されます。 

最後のエッジ ケースは、構築されたパターンをターゲットにして禁止されたセルがクラスター化する場合です。 その最悪の配置でも、制限されたサイズは$k$制約の数が使用可能な行の数よりはるかに少ないため、ローカル スワップで十分であることが保証されます。
