 ## 解決策

 ## 問題の理解

 一連の区画が与えられ、各区画には許容される建物の高さの最大値が設定されています。 選択したすべての高さの合計を最大化しながら、制限を超えないように各プロットの実際の高さを選択する必要があります。 

この制限は局所的なものではなく、構造的なものです。 選択した位置の高さ`i`左側のどこかに高い建物があり、右側のどこかにも高い建物がある場合は禁止されます。 言い換えれば、位置は両側の少なくとも 1 つの建物よりも厳密に低い「くぼみ」になることはできません。 

この条件は、より構造的な方法で言い換えることができます。最終的な高さプロファイルには、左側の最大値と右側の最大値の両方より厳密に小さい点が含まれてはなりません。 有効な構成はどれも、ピークで交わる一連の単調なセグメントに分解できる風景のように動作します。 

制約は大きく、`n`最大 500,000 ですが、これにより二次または二次に近い動的計画法が即座に排除されます。 どのような解も線形または線形算術的でなければなりません。 配列に対する複数のパスを含む解であっても、各パスが O(n) である場合にのみ受け入れられます。 スタックまたは単調な処理を伴うデータ構造ソリューションが自然な候補です。 

いくつかのエッジケースは、単純な貪欲が失敗する理由を明らかにします。 常に設定する場合`a[i] = m[i]`、2 つのより大きなピークの間に極大値が現れると、制約に違反します。 たとえば、`m = [5, 1, 5]`、すべての値を最大に設定すると、`[5, 1, 5]`、インデックス 2 が両側より低いため、ルールに違反します。 最適な解決策は、代わりに片側のピークを下げて、合計のトレードオフを維持しながら構造を維持します。 

もう 1 つの失敗例は、ローカルな決定に起因します。 中間の高い値を選択するなど、ピークを早い段階で修正すると、たとえピークをわずかにずらすことで全体の合計がより良くなる可能性がある場合でも、後で多くの要素に不必要な削減を強制する可能性があります。 

主な問題点は、各位置が隣接する位置だけでなく、左右の最大値を通じてグローバルに相互作用することです。 

## アプローチ

 ブルートフォース戦略では、次の点に基づいて有効な高さの割り当てをすべて試行します。`a[i] ≤ m[i]`禁止パターンの条件を確認します。 値を次のように制限しても、`[1, m[i]]`指数関数的な検索スペースにつながります。 制約チェック自体は線形であるため、候補が 1 つであってもコストは O(n) です。 検索スペースが指数関数的に増大するため、小規模な検索スペースであってもこれは実行不可能です。`n`。 

より構造化されたブルート フォースのアイデアは動的プログラミングです。プレフィックスに対して DP を定義し、将来の選択に応じて位置が禁断の谷になるかどうかを追跡します。 ただし、状態はどのインデックスが依然として左右で優勢であるかをエンコードする必要があり、すぐに効率的に表現するには大きすぎます。 

重要な観察は、最終的な構造が「単峰性のセグメントを縫い合わせたもの」でなければならないということです。これは、左から右にスキャンするときに、シーケンスがあるピークに対して減少し始めると、禁制の谷を作成せずにその後そのピークを超えて増加することはできないことを意味します。 

これは、最終的な答えが「ピーク分解」を選択することによって決定されることを示唆しています。各セグメントは、選択したピーク高さから増加しない接尾辞のように動作しますが、最小 2 つの単調エンベロープによって制限されます。 

この構造を強制する標準的な方法は、すべての位置について、左の最大値と右の最大値の間の最小境界として機能すると仮定して、可能な限り最良の寄与を計算することです。 これにより、当然のことながら、モノトーン スタックを使用して両側で最も近いより大きな制約が計算され、セグメントの最小値に基づいて高さが再構築されます。 

問題は、すべての位置が両側で最も近い強い制約と一致していることを確認し、それらのエンベロープ制約の下で合計を最大化することに帰着します。 モノトーン スタックを使用すると、インデックスごとに、最適な構造において厳密に上位となる左右に最も近い位置を計算し、セグメントごとに寄与を決定できます。

 ## アルゴリズムのチュートリアル

 局所的に高さを最大化しながら全体的に構造上の制約を強制する単調増加スタックを使用してソリューションを構築します。 

1. 最終的な制約に関して、割り当てられた高さがまだ「固定されていない」インデックスのスタックを維持します。 スタックは、候補の高さの増加しない構造を保存します。 
2. 左から右に繰り返します。 ポジションごとに`i`、可能な最大の高さを割り当てようとします`m[i]`。 
3. スタックが空ではなく、最上位要素に割り当てられた高さが`m[i]`、ポップします。 このステップにより、前のピークによって後で禁止された谷が強制される構造が維持されなくなります。 より高いピークが単峰性制約に違反するセグメントを効果的にマージします。 
4. ポップ後、現在位置が左側の構造と右側の構造の間の新しい境界になることがわかります。 私たちは押します`i`新しいピーク境界候補としてスタックに追加します。 
5. 各セグメントに割り当てられた高さは暗黙的に決定されます。セグメントをポップまたはクローズするたびに、そのセグメント内のすべての要素が、合計を最大化しながら有効性を維持する制限最小値で満たされる必要があることがわかります。 これは、最後の有効な境界の高さを使用してセグメント範囲を埋めることによって処理されます。 
6. 最後に、スタック境界によって定義されたセグメント値を伝播することによって配列を再構成し、すべての位置がその最大値と隣接するピークによって課せられる構造エンベロープの両方を尊重するようにします。 

重要な不変条件は、スタックが常に、各セグメントが一貫した限界ピークを持つセグメントへのアレイの分解を表すことです。 禁止パターンの違反には、より高い 2 つのピークの間に谷が必要になりますが、スタック構造では、検出されるとすぐにそのようなピークをマージすることで谷を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = list(map(int, input().split()))

    stack = []
    res = [0] * n

    for i in range(n):
        last = i
        while stack and m[stack[-1]] > m[i]:
            j = stack.pop()
            height = m[j]
            for k in range(last, j, -1):
                res[k] = height
            last = j

        stack.append(i)
        res[last:i] = [m[i]] * (i - last)

    # finalize remaining segments
    last = n
    while stack:
        j = stack.pop()
        height = m[j]
        for k in range(last, j, -1):
            res[k] = height
        last = j

    for i in range(n):
        if res[i] == 0:
            res[i] = m[i]

    print(*res)

if __name__ == "__main__":
    solve()
```この実装は、許容される高さによってソートされたインデックス上のモノトーン スタックに依存します。 新しい高さによって単調性が崩れると、ポップされた要素によって境界が定められたセグメントが完成します。 各セグメントは、現在の境界と一致する可能な限り最適な高さで埋められます。 

微妙な点は、単独ですぐに値を割り当てることは決してないということです。 代わりに、ポップ操作によって境界が確認されるまで割り当てを延期します。 これにより、ローカルで最大合計を確保しながら、グローバル制約への違反が回避されます。 

最終的なクリーンアップにより、残りの未割り当ての位置がそれぞれの最大許容高さを確実に継承します。これは、右側に競合するより高い境界が存在しないため安全です。

 ## 特殊なケース

 左右の比較が存在しないため、単一要素配列はすべての制約を自明に満たします。 スタック操作ではポップがトリガーされず、値が直接割り当てられるため、アルゴリズムがこれを処理します。 

左右の大きい要素よりも同時に小さい要素はないため、厳密に増加する配列では違反が発生することはありません。 スタックはモノトーンのままで、セグメントのマージは発生しないため、出力は入力と等しくなります。 

みたいなパターン`[5, 1, 5]`コアのメカニズムをトリガーします。さもなければ、中央の要素が 2 つのピークの間の谷になってしまいます。 スタックは右ピークを処理するときにこれを検出し、無効な構成を防止してセグメントを一貫して調整するマージを引き起こします。 

厳密に減少する配列も、どの位置にも右側の大きい要素が存在しないため変更されず、制約がアクティブになることはありません。
