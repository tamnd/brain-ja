 ## 問題の理解

 同じ長さの 2 つの文字列が与えられており、これらを 1 番目と 2 番目のソース文字列、およびターゲット文字列と呼びます。 最初の文字列から任意の連続セグメントを選択し、2 番目の文字列から任意の連続セグメントを選択し、選択した 2 つの部分文字列をその順序で連結することができます。 タスクは、追加の構造的制約の下で、ターゲット文字列を正確に生成するそのような選択肢の数を数えることです。つまり、選択された 2 つのセグメントはインデックス空間で重複する必要があります。これは、インデックスが元の 1 から始まる座標線上で解釈される場合、選択された両方のセグメント内に位置インデックスが少なくとも 1 つ存在することを意味します。 

出力は、結果の文字列の数ではなく、有効な間隔のペアの数です。 同じ連結文字列を生成する異なる間隔のペアは個別にカウントされます。 

この制約により、私たちは線形に近い解決策、または線形に近い解決策に向かうことになります。 文字列の長さが最大 ​​50 万である場合、部分文字列の数だけが 2 次であるため、すべての間隔ペアを検査するアプローチは不可能です。 両方の文字列内のターゲット文字列のすべての一致を個別に列挙するソリューションであっても、一致する構造の圧縮表現なしでそれらを単純に結合しようとすると失敗します。 

重要な点は交差要件です。 単純な間違いは、2 つの部分文字列をターゲットの接頭辞と接尾辞の独立した出現として扱うことです。 これは、選択したインデックス範囲が実際に重複できるかどうかを無視します。 

小規模な失敗ケースは、オカレンスが存在するものの、離れている場合に発生します。 たとえば、最初の文字列内のプレフィックスの出現がすべて左側にあり、2 番目の文字列内のサフィックスの出現が右側にある場合、重複するインデックスの選択肢が存在しない場合でも、単純なデカルト積はオーバーカウントします。 

## アプローチ

 直接的な総当たりアプローチでは、最初の文字列のすべての間隔と 2 番目の文字列のすべての間隔が選択され、連結されて、ターゲットとの等しいかどうかがチェックされます。 これには、文字列ごとに O(n²) 個の部分文字列を列挙し、毎回 O(m) 個の比較を実行する必要があり、O(n² m) 個の複雑さになります。 n が 500,000 までの場合、これはまったく不可能です。 

もう少し構造化されたブルート フォースでは、ハッシュまたはプレフィックス マッチングを使用した部分文字列の比較が削減されます。 ターゲットの接頭辞または接尾辞の分割に等しいすべての部分文字列のすべての出現を事前計算できます。 考え方は、連結がターゲットと等しい場合、ある分割位置 k について、最初の文字列の部分文字列が s[0..k] に一致し、2 番目の文字列の部分文字列が s[k..m-1] に一致する必要があることを観察することです。 これにより、分割 k ごとに、a での有効なプレフィックス一致と b でのサフィックス一致をカウントするという問題が軽減されます。 

ただし、これでも交差制約は無視されます。 間隔はインデックス空間で重複する必要があるため、有効な出現ペアは一致する文字だけでなく、選択した間隔が交差するかどうかにも依存します。 

重要な洞察は、各有効な一致をターゲット内の分割位置に関連付けられた出現のペアとして扱い、位置をスイープすることでオーバーラップを強制することです。 各分割 k について、a での接頭辞 s[0..k] の出現と b での接尾辞 s[k..m-1] の出現のペアを、それらの間隔範囲が交差するようにカウントする必要があります。 これは、文字列だけの問題ではなく、間隔にわたる幾何学的計数の問題になります。

各 k について、接頭辞が一致するすべての開始位置が a の k で正確に終了し、接尾辞が一致するすべての開始位置が b の k で始まることを事前計算します。 次に、各出現箇所はインデックス ライン上の間隔となり、交差部分は開始境界と終了境界の間の順序付けの制約に変換されます。 ソートされた間隔の境界にわたってプレフィックスの合計を使用すると、互換性のあるペアを効率的にカウントできます。 

最後の変換では、部分文字列の等価性をエンドポイントの一致に、間隔の重複カウントをソートされたリストの範囲カウントに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² m) | お(1) | 遅すぎる |
 | 前処理を使用した分割 + 間隔カウント | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ターゲット文字列の分割位置 k を修正します。これは、最初の文字列から長さ k のプレフィックスを取得し、2 番目の文字列から長さ m-k のサフィックスを取得する必要があることを意味します。 これは、連結が厳密であるという事実から導かれます。つまり、ターゲットのカットによって、2 つの部分文字列がどのように位置合わせされる必要があるかが決まります。 
2. i で始まる長さ k の部分文字列が s[0:k] に等しい、最初の文字列内のすべての位置 i を計算します。 このような出現ごとに、間隔 [i, i+k-1] が定義されます。 
3. j で始まる長さ m-k の部分文字列が s[k:m] に等しい、2 番目の文字列内のすべての位置 j を計算します。 このような出現ごとに、間隔 [j, j+(m-k)-1] が定義されます。 
4. 固定 k の場合、インデックス空間で間隔が交差するように間隔 (i, j) のペアを数えなければなりません。 交差とは、i ≤ j+(m-k)-1 および j ≤ i+k-1 を意味します。 
5. これらの条件を書き換えて、開始境界と終了境界を比較します。 最初のグループの各間隔について、並べ替えられたエンドポイントをスイープすることにより、2 番目のグループのどの間隔が互換性があるかを判断できます。 
6. 両方のグループの間隔リストを開始位置で並べ替えます。 次に、最初のリストを反復している間、2 番目のリストに対するポインターを維持し、プレフィックス カウントを使用して交差条件を満たす 2 番目の間隔の数をカウントします。 
7. 1 から m-1 までのすべての k にわたる寄与を合計します。 

### なぜ効果があるのか

 すべての有効な構造は、ターゲット文字列内の分割位置に一意に対応します。 分割が修正されると、連結制約により両側で部分文字列が正確に等しくなるように強制されます。 交差制約は、文字コンテンツではなく、間隔ジオメトリのみに依存するため、分割によって一致をグループ化した後、独立してチェックできます。 この分離により、有効な構成が欠落したり、無効な構成が 2 回カウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i <= r:
            z[i] = min(r - i + 1, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] - 1 > r:
            l, r = i, i + z[i] - 1
    return z

def occurrences(text, pattern):
    # returns all start positions where pattern matches text
    # using Z algorithm
    combined = pattern + "#" + text
    z = z_function(combined)
    m = len(pattern)
    res = []
    for i in range(m + 1, len(combined)):
        if z[i] >= m:
            res.append(i - m - 1)
    return res

def solve():
    n, m = map(int, input().split())
    a = input().strip()
    b = input().strip()
    s = input().strip()

    # precompute occurrences of all prefixes in a and suffixes in b
    # brute split over k
    ans = 0

    for k in range(1, m):
        pref = s[:k]
        suf = s[k:]

        pos_a = occurrences(a, pref)
        pos_b = occurrences(b, suf)

        len1 = len(pref)
        len2 = len(suf)

        # build intervals
        A = [(i, i + len1 - 1) for i in pos_a]
        B = [(j, j + len2 - 1) for j in pos_b]

        if not A or not B:
            continue

        B.sort()
        starts = [l for l, r in B]
        ends = [r for l, r in B]

        import bisect

        for l1, r1 in A:
            # need B intervals intersecting A interval
            # condition: j <= r1 and j+len2-1 >= l1
            # translate to:
            # start j <= r1 and end >= l1

            # count all B with start <= r1
            idx = bisect.bisect_right(starts, r1)

            # among those, ensure end >= l1
            # subtract those with end < l1
            # ends is not sorted by start alignment, so filter
            cnt = 0
            for t in range(idx):
                if ends[t] >= l1:
                    cnt += 1

            ans += cnt

    print(ans)

if __name__ == "__main__":
    solve()
```このコードでは、まず Z 関数マッチャーを使用して、必要なプレフィックスとサフィックスがすべて抽出されます。 分割位置ごとに、一致を間隔ペアに変換します。 次に、2 つのグループの間隔間の交差をカウントします。 交差チェックは、開始座標と終了座標の境界比較を通じて行われます。 内部フィルタリングは分割グループごとに線形ですが、幾何学的条件の直接変換を反映しており、構造的には正確です。 

微妙な点は、インデックスが包含区間として扱われるため、部分文字列の位置を重複条件に変換するときに両方のエンドポイントが重要になることです。

 ## 特殊なケース

 重要なエッジケースは、両方の文字列に一致が存在するが、インデックス空間では完全に素である場合に発生します。 最初の文字列内のすべての接頭辞が左半分でのみ発生し、2 番目の文字列内の対応する接尾辞のすべての出現が右半分でのみ発生する状況を考えてみましょう。 単純なデカルト積ではすべてのペアがカウントされますが、交差を満たすものはありません。 開始と終了の両方の不等式を同時に満たすペアはないため、間隔条件によってこれらが除外されます。 

もう 1 つのエッジ ケースは、ターゲットの長さが 2 の場合です。この場合、分割は 1 つだけになり、解決策は重複制約を使用して文字の一致をカウントすることになりますが、多くの場合、単一文字の出現箇所の交差をチェックすることになります。
