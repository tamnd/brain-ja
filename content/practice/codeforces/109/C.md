 ## 解決策
 ## 問題の理解

 各エッジが正の重みを持つ _n_ 個の頂点を持つツリーが与えられます。 一部のエッジは、重みが数字 4 と 7 のみで構成されている場合、「幸運」であると見なされます。タスクは、_i_ から _j_ および _i_ から _k_ へのパスがそれぞれ少なくとも 1 つの幸運なエッジを通過するように、個別の頂点 (_i_、 _j_、 _k_) の順序付けされたトリプルの数をカウントすることです。 

入力は頂点の数と、それに続くエッジとその重みを記述する _n_ - 1 行で構成されます。 出力は単一の整数、つまり有効なトリプルの数です。 

_n_ が 10^5 まで大きくなり、制限時間が 2 秒であることを考えると、すべての頂点トリプルを明示的に列挙しようとする解決策は実行不可能です。 すべてのトリプルを列挙するには、O(n³) 回の演算が必要になります。これは、最悪の場合、およそ 10^15 であり、許容範囲をはるかに超えています。 トリプルチェックごとに O(n²) を試行しても遅すぎます。 

明らかではないエッジ ケースには、エッジが幸運ではない木、またはすべてのエッジが幸運である木が含まれます。 最初のケースでは、条件を満たすトリプルがないため、答えはゼロになるはずです。不注意な実装では、切断されたコンポーネントに基づいて何かを誤ってカウントする可能性があります。 2 番目のケースでは、すべてのトリプルが有効で、合計 n・(n-1)・(n-2) 個のトリプルが得られ、頂点の順序を見落とすとカウントが低くなる可能性があります。 n = 1、2、または 3 のような小さなツリーも、可能なトリプルの数がゼロになる可能性があるため、慎重な取り扱いが必要です。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのトリプル (_i_、 _j_、 _k_) を反復処理し、_i_ から _j_ および _i_ から _k_ へのパス上に幸運なエッジの存在をチェックしようとします。 トリプルごとに、ツリーを走査するかパスを事前計算する必要があります。 最悪の場合、コストは O(n³) になりますが、これは n が 10^5 までの場合には実現不可能です。 

重要な観察は、条件を満たさない唯一のパスは、すべての幸運なエッジが削除されたときに形成されるツリーの接続されたコンポーネント内に完全に含まれるパスであるということです。 すべての幸運なエッジを削除すると、残りの接続コンポーネントは完全に「不運な」エッジで構成されます。 それぞれのコンポーネント内に幸運な要素はありません。 したがって、_i_ と _j_ と _k_ の両方が同じアンラッキー コンポーネントに属するトリプルは条件を満たすことができません。 

ここから、視点を切り替えることができます。条件を満たすトリプルを数える代わりに、すべてのトリプルを数え、単一の不運なコンポーネント内に完全に含まれるトリプルを差し引きます。 _sz_ を不運なコンポーネントのサイズとします。 その中に完全に含まれる順序付けされたトリプルの数は、sz・(sz−1)・(sz−2) です。 すべての不運な要素を合計すると、条件を満たさないトリプルの数が得られ、これを合計 n・(n−1)・(n−2) から減算して最終的な答えを求めます。 これにより、問題はツリー上の単純な DFS に縮小され、不運なコンポーネントのサイズが検出され、O(n) の解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 数字を反復処理し、各数字が 4 または 7 のいずれかであることを確認することで、数字が幸運かどうかをチェックする関数を定義します。これにより、エッジを効率的に分類できるようになります。 
2. エッジの重みを追跡しながら、ツリーの隣接リストを作成します。 
3. コンポーネントに既に割り当てられている頂点をマークするために、訪問済みの配列を作成します。 すべての頂点を未訪問として初期化します。 
4. すべての頂点を反復処理します。 未訪問の頂点ごとに、DFS または BFS を実行して、幸運ではないエッジによって形成された接続コンポーネントを横断します。 このコンポーネントの頂点の数を数えます。 このカウントを _sz_ とします。 
5. sz・(sz−1)・(sz−2) を現在の合計_bad_triples_に加算します。これは、不運なコンポーネントに完全に含まれる順序付けされたトリプルの数を表します。 
6. すべてのコンポーネントを処理した後、ツリー内の順序付けられたトリプルの総数を n・(n-1)・(n-2) として計算します。 
7. トリプルの合計から _bad_triples_ を減算して、答えを求めます。 

機能する理由: すべてのトリプルには、最初の頂点から他の 2 つの頂点までの少なくとも 1 つのパスにラッキー エッジが含まれているか、アンラッキー コンポーネント内に完全に含まれています。 後者を数えて減算することで、条件を満たさないトリプルを正確に捕捉します。 コンポーネントが互いに素であるため、二重カウントが回避されます。 各頂点を正確に 1 回走査すると、O(n) 時間が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

def is_lucky(x):
    while x > 0:
        d = x % 10
        if d != 4 and d != 7:
            return False
        x //= 10
    return True

def main():
    n = int(input())
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        if not is_lucky(w):
            adj[u].append(v)
            adj[v].append(u)
    
    visited = [False] * n
    
    def dfs(u):
        visited[u] = True
        count = 1
        for v in adj[u]:
            if not visited[v]:
                count += dfs(v)
        return count
    
    bad_triples = 0
    for i in range(n):
        if not visited[i]:
            sz = dfs(i)
            if sz >= 3:
                bad_triples += sz * (sz - 1) * (sz - 2)
    
    total_triples = n * (n - 1) * (n - 2)
    print(total_triples - bad_triples)

if __name__ == "__main__":
    main()
```DFS は、接続されている各アンラッキー コンポーネントのサイズをカウントします。 幸運でないエッジのみが隣接リストに追加されるため、トラバーサルによって自然に幸運でないコンポーネントが分離されます。 sz・(sz−1)・(sz−2)を乗算すると、コンポーネント内の順序付けられたトリプルがすべてカウントされ、合計から減算すると有効なトリプルが得られます。 再帰制限を使用すると、DFS が深いツリーを処理できるようになります。

```| 頂点 | コンポーネント | DFS サイズ | bad_triples への貢献 |

 | 1 | {1} | 1 | 0 |
 | 3 | {3} | 1 | 0 |

 トリプルの合計: 4・3・2 = 24

 悪いトリプル: 0

 答え: 24 − 0 = 24

 説明: ラッキー エッジは 2 つあります (1-2 重み 4、1-4 重み 7)。 それらを削除すると、ツリーがサイズ 2、1、1 のコンポーネントに分割されます。頂点が 3 つ以上あるコンポーネントはないため、bad_triples = 0 になります。他のすべてのトリプルには少なくとも 1 つのラッキー エッジが含まれており、正しい答えが得られます。
