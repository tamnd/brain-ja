 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられているので、それを降順でない順序で並べ替えたいと考えています。 面白いのは、関係する 2 つの数字のうち少なくとも 1 つが幸運な場合にのみ要素を交換できることです。 ラッキー ナンバーは、数字 4 と 7 のみを含む数字として定義されます。目標は、並べ替えを完了する一連の交換を見つけるか、並べ替えが不可能であると判断することです。 スワップのシーケンスの長さは 2*n を超えてはなりません。 

ここでの重要な制約は、配列のサイズ (最大 10^5 要素) です。 これにより、メインの並べ替えロジックの時間計算量が O(n log n) よりも悪いアルゴリズムが除外されます。 すべてのスワップ ペアを反復処理するには O(n^2) の操作 (最悪の場合はおよそ 10^10) が必要となるため、単純な総当り攻撃を試みて、考えられるすべてのスワップ ペアを繰り返しチェックすることは直ちには不可能です。 

配列にラッキーナンバーがまったく含まれていない場合、重要なエッジケースが発生します。 この状況では、スワップには少なくとも 1 つの幸運な数字が必要であるため、要素を移動することは不可能であり、出力は -1 でなければなりません。 もう 1 つの微妙なケースは、配列がすでにソートされている場合です。 アルゴリズムはこれを認識し、スワップをゼロにする必要があります。 配列に幸運な数字がある場合は、スワップ戦略が他の要素を所定の位置に移動するための「ピボット」として常にそれらを効果的に使用することを保証する必要があります。 

たとえば、入力が次の場合、`5 3 2 1`幸運な数字がない場合、出力は次のようになります。`-1`。 入力が`4 2 7 1`単一の幸運な数字 7 を使用すると、配列をソートするために 7 を使用してスワップを調整できます。 

## アプローチ

 ブルート フォースのアプローチは簡単です。配列を繰り返しスキャンして、少なくとも 1 つの数字が幸運である順序の異なるペアを探し、交換を実行し、配列がソートされるまで繰り返します。 これは原理的には正しいですが、最大 O(n^2) の操作が必要になる可能性があるため、非効率的です。 n が 10^5 までの場合、時間計算量は 10^10 になります。これは、3 秒の時間制限では実現不可能です。 

重要な観察は、幸運な数字が可動軸として機能するということです。 少なくとも 1 つの幸運な数字がある場合は、それを一時的な保持点として使用して配列をいつでも並べ替えることができます。 この手順では、任意のラッキー ナンバーのインデックスを特定し、そのピボットを使用して選択並べ替えをシミュレートします。 数字が適切でない場合は、その数字を幸運のピボットと交換し、必要に応じてピボットを元に戻します。 これにより、各要素にはピボットとのスワップが最大でも一定数必要となるため、問題は管理可能な O(n) シーケンスのスワップに軽減されます。 

幸運な数字がなく、配列がまだソートされていない場合、ソートは不可能です。 それ以外の場合、柔軟なメディエーターとして 1 つの幸運な数字を使用すると、2*n 回以内の交換ですべての要素を正しい位置に配置でき、問題の制約が満たされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 (ラッキー ピボット) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をスキャンしてすべてのラッキーナンバーを特定します。 何も存在せず、配列がソートされていない場合は、すぐに -1 を返します。 それ以外の場合は、任意の幸運な数字をピボットとして選択します。 
2. 並べ替えられた配列のコピーを作成します。 これは、各番号の最終的なターゲット位置を表します。 
3. 現在の位置の配列を維持して、ソートされた配列内の各数値がどこに配置されるべきかを素早く見つけます。 
4. 配列を左から右に繰り返します。 各要素がすでに正しい位置にある場合は、次の要素に移動します。 そうでない場合は、要素自体が幸運でない場合は、幸運なピボット要素と交換します。 各交換を記録します。 
5. 現在の要素が運が良ければ、間違って配置された要素と直接交換できます。 それ以外の場合は、まず現在の要素とピボットを交換してから、ピボットを最終位置に配置します。 
6. すべての要素がソート順になるまで繰り返します。 スワップの合計数が 2*n を超えないようにしてください。 

機能する理由: 不変条件は、ピボットのラッキー ナンバーを配列内のどこにでも移動したり元に戻すことができ、要素を再配置するための経路を提供することです。 所定の位置にない各要素は、運が良ければ直接移動できるか、ピボットを一時的な保持スポットとして使用して移動できます。 このアルゴリズムは、要素ごとに最大 2 回のスワップ後に、ソートされた構成に到達することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_lucky(x):
    s = str(x)
    return all(c in '47' for c in s)

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    lucky_indices = [i for i, val in enumerate(a) if is_lucky(val)]
    
    if not lucky_indices:
        if a == sorted(a):
            print(0)
        else:
            print(-1)
        return
    
    pivot = lucky_indices[0]
    sorted_a = sorted(a)
    pos = {v: i for i, v in enumerate(a)}
    swaps = []
    
    for i in range(n):
        correct_val = sorted_a[i]
        while a[i] != correct_val:
            j = pos[correct_val]
            if i != pivot:
                swaps.append((pivot + 1, j + 1))
                a[pivot], a[j] = a[j], a[pivot]
                pos[a[pivot]] = pivot
                pos[a[j]] = j
            swaps.append((i + 1, pivot + 1))
            a[i], a[pivot] = a[pivot], a[i]
            pos[a[i]] = i
            pos[a[pivot]] = pivot
    
    print(len(swaps))
    for x, y in swaps:
        print(x, y)

if __name__ == "__main__":
    main()
```コードは、幸運な数字を特定することから始まります。 存在せず、配列がソートされていない場合は、-1 が出力されます。 それ以外の場合は、幸運な数字をピボットとして使用して、間違って配置された要素を繰り返し交換します。 辞書は、効率的な検索のために現在位置を追跡します。 スワップ シーケンスでは、各要素が最大 2 回移動されるようにすることで、2*n の制限が尊重されます。
