 ## 解決策
 ## 問題の理解

 Petya と Vasya がそれぞれの間隔からランダムに整数を選択した場合、選択した 2 つの数値間の間隔に正確に次の値が含まれる確率を計算するように求められています。`k`幸運な数字。 ラッキー ナンバーは、数字 4 と 7 のみを含む数字です。入力により、両方のプレーヤーの間隔の境界が提供されます (`pl`に`pr`ペティアのために、`vl`に`vr`Vasya の場合）と目標数`k`幸運な数字の。 出力は浮動小数点数としての確率です。 

制約により、次の上限が与えられます。$10^9$間隔と`k`ペアの合計数は最大 1000 になる可能性があるため、区間内のすべての整数を直接反復するアプローチは直ちに除外されます。$(10^9)^2 = 10^{18}$、これは計算上不可能です。 この問題には、潜在的に巨大な間隔サイズと比較して少数の幸運な数字を活用するアプローチが必要です。 

単純な実装では、両方の間隔ですべての整数を列挙し、結果として得られる各部分間隔で幸運な数字を数え、ペアの合計数で割ろうとする可能性があります。 これは、間隔が長くなると失敗します。 もう 1 つの微妙な特殊ケースは、幸運な数字が一方または両方の間隔から完全に外れる場合に発生します。 たとえば、次の場合`pl = pr = 1`そして`vl = vr = 2`そして`k = 1`、1 と 2 の間に幸運な数字はありません。不注意な実装では、確率がゼロ以外であると想定される可能性がありますが、実際には 0 が返されるはずです。 

## アプローチ

 ブルートフォースアプローチは、すべての整数を反復処理することです。`p`ペティアの合間に、`v`Vasya の間隔で、間隔を計算します`[min(p,v), max(p,v)]`、その間隔内の幸運な数字を数え、それが等しいかどうかを確認します`k`。 このアプローチは正しいですが、最悪の場合の複雑さは次のとおりです。$O((pr - pl + 1) \cdot (vr - vl + 1) \cdot \text{number of lucky numbers})$を超える可能性があります$10^{18}$操作。 これは不可能です。 

重要な洞察は、幸運な数字の数は非常に少なく、最大でも約 1022 個であるということです。$10^9$(2桁しかなく最大10桁なので、$2^{10}-2$1 桁の 0 は無視されます）。 間隔内のすべての整数をチェックするのではなく、すべての幸運な数字を事前計算し、間隔に対する相対的な位置に焦点を当てることができます。 

すべての数値を繰り返す代わりに、次の値の数を数えることができます。`p`そして`v`正確に含む間隔を生成します`k`連続するラッキーナンバーによって定義された範囲を操作して、ラッキーナンバーを取得します。 これにより、問題は間隔カウントに縮小されます。開始ラッキーナンバーごとに、`k`- 番目の幸運な数字の前に、有効な範囲を計算します`p`そして`v`それらの間の間隔が正確に含まれるように`k`ラッキーナンバーを決定し、貢献を合計します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((pr-pl+1)*(vr-vl+1)) | お(1) | 遅すぎる |
 | 最適 | O(L^2) ここで、L ~ 1022 | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. までのすべてのラッキーナンバーを生成します。$10^9$。 これは、制限を超えるまで各ステップで 4 または 7 を追加する再帰関数を使用して実行できます。 それらを並べ替えたリストに保存します。 
2. センチネル値を次の場所に追加します。`0`そして`10^9 + 1`追加の条件なしで境界を含む間隔を処理します。 
3. 連続する各シーケンスに対して、`k`幸運な数字。これらを正確に含む間隔を生成できる最小値と最大値を特定します。`k`幸運な数字。 させて`a`シーケンスの直前の幸運な数字 (または 0)、および`b`シーケンスの直後の幸運な数字 (または 10^9 + 1)。 可能性のあるもの`p`そして`v`値は厳密に次の範囲内に収まる必要があります`a+1`および下限のシーケンス内の最初の幸運な数字であり、厳密に次の値よりも小さい`b`上限について。 
4. このようなシーケンスごとに、有効なシーケンスの数を計算します。`(p,v)`ペア。 これには、Vasya についても同様に、下限範囲と上限範囲と重複する Petya 間隔内の整数の数を計算することが含まれます。 の数を合計します。`p<v`そして`v<p`ケース。 
5. すべてのシーケンスにわたるすべての寄与を合計します。`k`連続する幸運な数字。 可能なペアの総数で割ります`(pr-pl+1)*(vr-vl+1)`確率を得るために。 
6. 確率を高精度で出力し、絶対誤差が次を超えないことを確認します。$10^{-9}$。 

機能する理由: このアルゴリズムは、正確に取得する唯一の方法であるという事実を利用しています。`k`間隔内のラッキーナンバーは、間隔を正確に制限することです。`k`-番目の幸運な数字。 区間内の整数ではなく幸運な数字を反復処理することで、扱いにくい問題を管理可能な区間演算に縮小します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate_lucky(limit):
    result = []
    def dfs(x):
        if x > limit:
            return
        if x > 0:
            result.append(x)
        dfs(x*10 + 4)
        dfs(x*10 + 7)
    dfs(0)
    return sorted(result)

pl, pr, vl, vr, k = map(int, input().split())
lucky = generate_lucky(10**9)
lucky = [0] + lucky + [10**9 + 1]  # add sentinels

total = 0

for i in range(1, len(lucky) - k):
    left = lucky[i-1] + 1
    right = lucky[i+k] - 1
    low = lucky[i]
    high = lucky[i+k-1]
    
    # compute overlap of intervals with player ranges
    len_p_low = max(0, min(pr, high) - max(pl, left) + 1)
    len_v_low = max(0, min(vr, high) - max(vl, left) + 1)
    
    len_p_left = max(0, min(pr, low-1) - max(pl, left) + 1)
    len_p_right = max(0, min(pr, right) - max(pl, high+1) + 1)
    len_v_left = max(0, min(vr, low-1) - max(vl, left) + 1)
    len_v_right = max(0, min(vr, right) - max(vl, high+1) + 1)
    
    total += len_p_left * len_v_right
    total += len_v_left * len_p_right

prob = total / ((pr - pl + 1) * (vr - vl + 1))
print(f"{prob:.12f}")
```このソリューションでは、まず、再帰的 DFS を使用してすべての幸運な数字を効率的に生成します。 センチネル`0`そして`10^9+1`エッジ処理を簡素化します。 間隔の重複は次を使用して計算されます。`max`そして`min`プレーヤーの間隔に合わせて範囲をクリップします。 カウント式は、影響を与える間隔を慎重に区別します。`p<v`そして`v<p`。 最後に、確率をペアの総数で割ります。
