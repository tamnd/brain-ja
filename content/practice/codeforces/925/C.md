 ## 解決策

 ## 問題の理解

 整数の複数セットが与えられます。 任意に並べ替えることができます。 順序を選択した後、ゼロから開始して実行中のプレフィックス XOR を計算します。次の各値は、前のプレフィックスの結果と次に選択した要素を XOR 演算することによって取得されます。 

タスクは、これらのプレフィックス XOR 値が厳密に増加するシーケンスを形成するような順序付けが存在するかどうかを判断することです。 そのような順序が存在する場合は、それを出力する必要があります。 そうでなければ、それは不可能であると印刷します。 

重要な制約は、配列のサイズが最大 100,000 であり、各値は 60 ビット未満に収まることです。 これは、サイズが階乗になるため、すべての順列を試行するアプローチを即座に除外します。 順列に対する二次検査さえ実行不可能です。 私たちは線形時間または線形演算時間に近いものを探しており、順序付けされた検索ではなくビット構造に依存している可能性があります。 

微妙な問題は、XOR が数値の順序に関して単調に動作しないことです。 大きな数値を追加すると実際にはプレフィックス XOR が減少する可能性があり、小さな数値を追加すると増加する可能性があります。 これにより、「次の要素が大きいほど優れている」という素朴な直感が打ち破られます。 

典型的な障害モードは、値のサイズのみに基づいた貪欲な戦略から発生します。 たとえば、数値を昇順または降順で取得すると、上下に進むプレフィックス XOR シーケンスが簡単に生成されます。 もう 1 つの隠れた罠は、プレフィックス XOR が増加すると常に増加し続けると仮定することですが、XOR は上位ビットをゼロに戻す可能性があるため、これは誤りです。 

## アプローチ

 ブルートフォース ソリューションでは、指定された数値のすべての順列を試し、プレフィックス XOR シーケンスを計算し、それが厳密に増加しているかどうかを確認します。 これは定義上正しいですが、n! が必要です。 順列があり、各チェックのコストは O(n) であるため、n が 10 程度であっても実行時間は天文学的に長くなります。 

複雑さを軽減するには、要素を 1 つ追加した後にプレフィックス XOR が増加するかどうかを実際に制御するものを理解する必要があります。 現在のプレフィックス XOR が x であり、数値 b を追加しようとするとします。 新しい値は x XOR になります。 b. これが x より大きいかどうかは、x と b が異なる最上位ビットに完全に依存します。 そのビットで、結果が 1 で x が 0 の場合、値は増加します。 それ以外の場合は減少します。 

この観察は、強力な構造上の制限につながります。 msb(x) を x の最も高い設定ビットの位置とする。 XOR が最上位ビットにどのような影響を与えるかを調べると、決定的なことがわかります。b の最上位ビットが msb(x) より厳密に大きい位置にある場合、x の XOR b は x より大きくなければなりません。これは、結果では新しい上位ビットが 1 になるのに対し、x には 0 が存在するためです。 ただし、b の最上位ビットが msb(x) 以下の場合、最上位の異なるビットにより結果が小さくなります。 

これは、すべてのステップで、現在のプレフィックス XOR の最高設定ビットよりも厳密に大きい設定ビットを持つ要素を選択する必要があることを意味します。 このような要素を選択すると、プレフィックス XOR の最上位ビットがまさにそのビットになります。 このプロセスでは、各ステップでプレフィックス XOR の最上位ビットが厳密に増加します。 

これは、入力自体に対する強い制約を直ちに意味します。 同じ最上位ビットを共有する 2 つの数値がある場合、そのうちの 1 つだけを使用できます。これは、それらの 1 つを使用すると、プレフィックス XOR がそのビットに到達し、同じ最上位ビットを持つそれ以上の数値が許可されないためです。 したがって、有効な解には、最上位ビット クラスごとに最大でも 1 つの数値が含まれている必要があります。 

この条件が成立すると、構築は決定論的になります。つまり、数値を最も高い設定ビットで昇順に並べ替えて出力します。 各ステップは強制的であり、有効です。

## アルゴリズムのチュートリアル

 各数値の最も高い設定ビットを中心にソリューションを構築します。 

1. すべての数値について、その最上位設定ビットのインデックスを計算します。 これにより、各値が XOR との相互作用を制御する単一の構造ラベルに圧縮されます。 
2. この最上位ビットのインデックスによって番号をグループ化します。 グループに複数の要素が含まれている場合、有効な順序付けが存在しないと直ちに結論付けられます。 これは、そのグループから 1 つの要素を選択した後、プレフィックス XOR がそのビットに到達し、同じ最上位ビットを持つ別の数値を受け入れることができないためです。 
3. すべてのグループに要素が 1 つしか含まれていない場合は、順序付けに進みます。 すべての数値を最上位ビットのインデックスで昇順に並べ替えます。 これにより、次に選択される各数値が、現在のプレフィックス XOR よりも厳密に高い最上位ビットを持つことが保証されます。 
4. このソートされた順序で数値を出力します。 

この順序が正しい理由は、プレフィックス XOR を追跡すると明らかになります。 各ステップの後、プレフィックス XOR の最上位ビットは、まさに最後に選択された数値の最上位ビットになります。 常に厳密に上位のビットに移動するため、次の XOR 演算ごとに結果の新しい上位の位置が 0 から 1 に反転され、値の厳密な増加が保証されます。 

不変条件は、k 要素を処理した後、プレフィックス XOR の最高設定ビットが k 番目に選択された要素の最高ビットと等しく、残りのすべての未使用要素が厳密に大きい最高ビットを持つことです。 これにより、いかなる減少も防止され、厳密な単調増加が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def msb(x):
    return x.bit_length() - 1

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    groups = {}
    for x in b:
        g = msb(x)
        if g in groups:
            groups[g].append(x)
        else:
            groups[g] = [x]

    for g in groups:
        if len(groups[g]) > 1:
            print("No")
            return

    order = sorted(b, key=msb)

    print("Yes")
    print(*order)

if __name__ == "__main__":
    solve()
```この実装では、まず Python の組み込み bit_length を使用して各数値の最上位ビットを計算します。 次に、その値に基づいて数値をグループ化し、実現可能性をチェックします。 重要な決定点は、サイズが 1 を超えるグループを拒否することです。 

msb による並べ替えでは、プレフィックス XOR が特定のビットに達すると、残りの数値は厳格な増加条件に違反することなく再びそのビットに触れることができないため、必要な順列が生成されます。 

よくある間違いは、ビット構造ではなく生の値で並べ替えようとすることです。 もう 1 つの微妙な問題は、最上位ビットの等価性がすでに無効であり、単に「増加しない」だけでなく厳密に禁止されていることを忘れていることです。

 ## 特殊なケース

 n が 1 に等しい場合、特殊なケースが発生します。最高ビット クラス間に競合が存在する可能性はなく、単一プレフィックス XOR が厳密に増加することは明らかであるため、アルゴリズムはそれをすぐに受け入れます。 

もう 1 つの微妙なケースは、複数の数値が同じ最上位ビットを共有する場合です。 グループ化ステップはそれを早期に拒否します。 たとえば、入力`8 9`どちらも最上位ビット 3 を持っているため、1 つを選択すると、プレフィックス XOR はそれ以上有効な遷移が存在しない状態に達し、あらゆる置換が無効になります。 

最後に、数値がすでに最上位ビットでソートされて表示されている場合でも、アルゴリズムは引き続きグループ化とソートを実行しますが、事実上同じシーケンスを返します。 これは、構築が入力順序にまったく依存していないことを確認します。
