 ## 解決策

 ## 問題の理解

 私たちは非常に大規模なホテルグリッドと協力しています。`n`床と`m`フロアごとに部屋が形成され、`n × m`格子。 各部屋は座標によって識別されます`(floor, section)`。 

一部の垂直柱は特殊です。階段またはエレベーターが含まれています。 柱が階段柱の場合、その柱の隣接するフロア間を垂直に移動するには、フロアごとに 1 コストがかかります。 エレベーターの柱の場合は、垂直方向に移動するほうが速くなります。任意の数の階を上下に移動できますが、時間コストは階数を で割ったものほど大きくなります。`v`、切り上げます。 床に沿った水平移動には、隣接するセクションごとに常に 1 のコストがかかります。 

各クエリは、指定された 2 つの部屋間の最小移動時間を尋ねます。この場合、水平に歩いて階段またはエレベーターの柱に到達し、それを使用して垂直に移動し、目的地まで再び水平に歩きます。 

重要な制約は、`n`そして`m`は 10^8 まで大きくなる可能性があるため、グリッドを明示的にモデル化することはできません。 特別な列の数は最大 10^5 で、最大 10^5 のクエリがあるため、各クエリはほぼ対数時間で処理する必要があります。 

グリッド上の単純な最短パスでは、多くの中間位置を考慮するか、BFS のようなロジックを実行しようとしますが、この規模では不可能です。 

微妙な問題は、最適パスでは常に最大 1 つの特別な列が使用されることです。 複数の階段やエレベーターを切り替えることが効果があるように見えても、スイッチを追加しても垂直方向の効率は向上せず、水平方向のコストが増加するだけです。 

エッジケースは、最適な列がインデックス順序で最も近いのではなく、2 番目に近い場合に発生します。 たとえば、階段の位置が 2 と 100 で、1 付近から開始する場合、目的地が 100 に近い場合でも、最適な選択は 2 になる可能性があります。「常に目的地側に向かう」という欲張りなアプローチは失敗します。 

別の特殊なケースは、階段がまったく存在しない場合、またはエレベーターが存在しない場合に発生します。 その後、ソリューションは、利用可能な構造のみを使用するように正常に機能を低下させる必要があります。 

## アプローチ

 強引な解釈では、考えられるすべての階段やエレベーターの柱を中間停止点と見なすことになります。 クエリごとに、先頭からその列に移動し、垂直に移動して、目的地に移動するコストを計算します。 最大 10^5 の特別な列があるため、クエリごとに O(k) の作業が発生し、最悪の場合は制限をはるかに超える約 10^10 の操作が発生します。 

重要な点は、最適なパス構造が非常に単純であるということです。 有効なルートでは、垂直移動を実行するために正確に 1 つの列を選択する必要があります。 その列が固定されると、コストは 3 つの独立した部分にきれいに分解されます。開始点から列までの水平移動、列内の垂直移動、列から目的地までの水平移動です。 

これにより、問題はソートされた候補列のセットに対する検索に変わります。 水平距離は線上の絶対値であるため、特定の位置の最適な候補は常に、左右に最も近い利用可能な列の中にあります。 これは、ソートされたセットに対する凸コストの標準的な特性です。ソートされたリスト内の最近傍のみをチェックするだけで十分です。 

したがって、クエリごとに、階段リストとエレベーター リストの両方で二分探索を行い、両側で最も近い候補のみを評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての列に対するブルート フォース | O(q · (c_l + c_e)) | O(c_l + c_e) | 遅すぎる |
 | 二分探索の最も近い候補 | O(q log(c_l + c_e)) | O(c_l + c_e) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階段の位置とエレベーターの位置を並べ替えられた配列に保存します。 二分検索を実行して最も近い候補を効率的に見つけるには、並べ替えが必要です。 
2. 各クエリに対して、抽出開始`(x1, y1)`そして目的地`(x2, y2)`。 
3. ベースラインの答えを純粋な水平移動コストとして計算します。`|y1 - y2| + |x1 - x2|`。 これは、すべての階段とエレベーターを無視して直接歩くことに相当し、常に有効なフォールバックです。 
4. このベースラインを改善するには、階段柱の使用を検討してください。 二分探索を使用して、`y1`階段配列で。 
5. その位置から、左側に最も近いものと右側に最も近いものから、最大 2 つの階段柱の候補を選択します。 これらは、開始点からの水平距離を最小限に抑えることができる唯一の列です。 
6. 各候補階段柱について`c`、開始から終了までの水平歩行として総コストを計算します。`c`、垂直方向の動き`|x1 - x2|`、からの水平歩行`c`目的地へ。 回答を更新します。 
7. エレベーターの支柱に対して同じプロセスを繰り返しますが、垂直コストを次のように計算します。`ceil(|x1 - x2| / v)`線形差の代わりに。 ここでも、二分探索から最も近い 2 つの候補のみを考慮します。 
8. ベースラインを超える最小値、階段ベースのルート、およびエレベーターベースのルートを出力します。 

正確さは、固定タイプの垂直輸送の場合、コスト関数が 2 つの固定点からの絶対水平距離によってのみ選択された列に依存するという事実に依存します。 この関数は利用可能な最も近い列で最小化されるため、バイナリ検索位置の周囲の近傍をチェックすることで全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

n, m, cl, ce, v = map(int, input().split())

stairs = []
elevators = []

if cl:
    stairs = list(map(int, input().split()))
if ce:
    elevators = list(map(int, input().split()))

q = int(input())

def best_cost(col_list, x1, y1, x2, y2, vertical_cost_fn):
    import bisect
    if not col_list:
        return float('inf')

    pos = bisect.bisect_left(col_list, y1)
    res = float('inf')

    for i in (pos - 1, pos):
        if 0 <= i < len(col_list):
            c = col_list[i]
            cost = abs(y1 - c) + abs(y2 - c) + vertical_cost_fn()
            res = min(res, cost)

    return res

for _ in range(q):
    x1, y1, x2, y2 = map(int, input().split())
    dx = abs(x1 - x2)

    ans = abs(y1 - y2) + dx

    ans = min(ans, best_cost(
        stairs, x1, y1, x2, y2,
        lambda dx=dx: dx
    ))

    ans = min(ans, best_cost(
        elevators, x1, y1, x2, y2,
        lambda dx=dx: ceil_div(dx, v)
    ))

    print(ans)
```このソリューションは、候補列を効率的に評価することを中心に構成されています。 の`best_cost`関数は階段とエレベーターの両方のロジックを分離しますが、垂直コスト モデルのみが異なります。 

二分探索ステップは非常に重要です。すべての列をスキャンするのではなく、ソートされた配列内の最も近い 2 つの位置のみを検査します。 ラムダは垂直距離を取得するため、階段とエレベーターのロジックは同じ水平方向の処理を共有します。 

よくある実装の落とし穴は、直接の水平パスを候補として含めることを忘れることです。 このパスは常に最適であるとは限りませんが、列が役に立たない場合の正確性のベースラインとして必要です。 

## 実用的な例

 ### トレースの例

 に階段がある単純化されたシナリオを考えてみましょう。`[2]`とエレベーター`[5]`、そしてからの問い合わせ`(1,1)`に`(5,6)`と`v = 3`。 

階段の場合は柱を評価します`2`:

 | ステップ | 値 |
 | --- | --- |
 | 2 までの水平開始 | 1 |
 | 垂直 | 4 |
 | 端まで水平 | 4 |
 | 合計 | 9 |

 エレベーターの場合はコラムを評価します`5`:

 | ステップ | 値 |
 | --- | --- |
 | 5 までの水平開始 | 4 |
 | 垂直天井(4/3) | 2 |
 | 端まで水平 | 1 |
 | 合計 | 7 |

 ベースラインのダイレクトパスは`|1-5| + |1-6| = 4 + 5 = 9`、したがって、答えは`7`。 

このトレースは、柱までの水平距離が長い場合でもエレベーターの選択が優勢である理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q log(c_l + c_e)) | 各クエリは 2 つのバイナリ検索と定数候補チェックを実行します。 
| スペース | O(c_l + c_e) | 階段とエレベーターの位置の保存 |

 この制約により最大 10^5 のクエリが許可されるため、クエリごとの対数作業は時間制限内に無理なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, cl, ce, v = map(int, input().split())

    stairs = []
    elevators = []

    if cl:
        stairs = list(map(int, input().split()))
    if ce:
        elevators = list(map(int, input().split()))

    q = int(input())

    import bisect

    def ceil_div(a, b):
        return (a + b - 1) // b

    def best(col_list, x1, y1, x2, y2, vert):
        if not col_list:
            return float('inf')
        pos = bisect.bisect_left(col_list, y1)
        res = float('inf')
        for i in (pos - 1, pos):
            if 0 <= i < len(col_list):
                c = col_list[i]
                res = min(res, abs(y1 - c) + abs(y2 - c) + vert)
        return res

    out = []
    for _ in range(q):
        x1, y1, x2, y2 = map(int, input().split())
        dx = abs(x1 - x2)
        ans = abs(y1 - y2) + dx

        ans = min(ans, best(stairs, x1, y1, x2, y2, dx))
        ans = min(ans, best(elevators, x1, y1, x2, y2, ceil_div(dx, v)))

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 階段がない場合、アルゴリズムは当然その分岐をスキップし、エレベーターと直接移動に依存します。 候補関数は空のリストに対して無限大を返すため、誤って答えを支配することはできません。 

クエリ ポイントが、目的地に向かう絶対方向に最も近い列ではない列に最も近い場合でも、二分検索では挿入ポイントの周囲の両方の隣接点が検査されます。 これにより、合計水平距離を短縮するわずかに遠い列が引き続き考慮されるようになります。 

垂直距離がゼロの場合、つまり両方のポイントが同じフロア上にある場合、エレベーターと階段のコストは、選択した柱を通る純粋に水平なルーティングに崩壊します。 アルゴリズムは引き続きすべての候補を正しく評価し、ダイレクト パスの競争力が維持され、正確性が保証されます。
