 ## 解決策
 ## 問題の理解

 整数のグリッドが与えられ、それぞれが長方形のサブ領域を記述する多くのクエリに答える必要があります。 すべてのクエリについて、その四角形内のすべての値がペアごとに異なるかどうかを判断する必要があります。これは、選択した部分行列内に複数回出現する数値がないことを意味します。 

クエリについて直接考える方法は、四角形内のすべてのセルを抽出し、値が繰り返されているかどうかを確認することです。 すべての値が一意である場合は「YES」と答え、そうでない場合は「NO」と答えます。 

制約は十分に大きく、両方のディメンションを掛け合わせても最大 100,000 になり、クエリも最大 100,000 になります。 これにより、最悪の場合、クエリごとに四角形全体をスキャンするアプローチは即座に除外されます。 1 つの大規模なクエリですでに最大 100,000 個のセルが処理される可能性があり、これを 100,000 個のクエリにわたって繰り返すと、10^10 のオーダーの操作が行われることになります。これは、Python で許容される 2 秒をはるかに超えています。 

より微妙な制約は、値が n * m で制限されるため、すべての値が管理可能な範囲内に収まり、ハッシュの問題なく一意に識別できることです。 主要な問題は、多数の長方形領域にわたる値の出現を追跡することであるため、これは重要です。 

ソリューションでよく見られる単純な間違いは、行または列ごとに頻度を事前計算してそれらを結合しようとすることです。 重複が行と列にわたって斜めに現れる可能性があるため、これは失敗します。 

たとえば、グリッドについて考えてみましょう。```
1 2
3 1
```グリッド全体をカバーするクエリには 2 つの 1 が含まれます。 行ベースまたは列ベースの集計では、完全な位置を追跡しない限り、この境界を越えた重複を見逃す可能性があります。 

もう 1 つの微妙な失敗例は、隣接する重複をチェックするだけで十分であると想定している場合です。 長方形の場合:```
1 2 3
4 1 5
```重複する 1 は遠く離れているため、ローカル チェックは失敗します。 

本当の難しさは、構造、順序、合計についてではなく、任意の部分四角形内のグローバルな一意性について問われるため、行列全体で繰り返される値の位置について推論する必要があることです。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に処理されます。 各四角形について、そのすべてのセルを反復処理し、値をハッシュ セットに挿入します。 値が繰り返される場合は、すぐに NO を返し、それ以外の場合は YES を返します。 セットが一意性を直接強制するため、これは正しいです。 

ただし、最悪の場合、クエリはグリッド全体をカバーできるため、各クエリのコストは O(nm) になります。 最大 100,000 クエリの場合、O(nm · q) になりますが、これはまったく実行不可能です。 

重要な観察は、問題は基本的に同じ値の繰り返し発生にあるということです。 クエリごとに一意性を最初から再計算する代わりに、同じ値の出現間の関係を事前に計算できます。 

重要な再定式化は次のとおりです。部分行列は、その内部のすべての値が内部に最大 1 回出現する場合にのみ有効です。 同様に、各値の出現をすべて取得する場合は、クエリ四角形内に同じ値が 2 つ出現しないことを確認する必要があります。 

したがって、クエリ内のすべての値をチェックする代わりに、視点を反転します。 それぞれの値について、そのすべての出現を調べ、スイープ オーダー内の連続した出現を競合の潜在的な原因として扱います。 次に、問題を「不正なペア」がクエリ四角形の内側に完全に存在するかどうかを確認することに縮小します。 

これは、ペアの疎なセットに対する 2D 優勢クエリになります。 各値は連続する出現間のエッジに寄与し、各エッジは有効なクエリ四角形内に 2 つのセルが同時に存在できないという制約を表します。 

次に、これらのエッジのいずれかがクエリ四角形の中に完全に収まるかどうかを尋ねるオフライン クエリをサポートする必要があります。 これは古典的なジオメトリ削減です。各エッジを 4D 拘束空間内の点に変換し、次に、ある次元ではスイープ ラインを使用し、別の次元ではフェンウィック ツリーを使用してクエリを処理します。 

実際的な簡略化の 1 つは、各セルを行優先の順序で 1D インデックスにマップすることです。 値が出現するたびに、ソートされた位置のリストが形成されます。 連続するペア (p、q) ごとに、p と q の行と列の最小/最大境界によって定義される四角形制約を保​​存します。 クエリ四角形にそのようなペアの両方のエンドポイントが完全に含まれている場合、その四角形は無効になります。 

問題をクエリ四角形内に禁止されたペアが存在するかどうかをチェックすることに集約します。これは、オフライン ソートとフェンウィック ツリーを使用した 2D 座標系上の範囲追加および範囲クエリ構造になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・n・m) | お(1) | 遅すぎる |
 | 最適 | O((n・m + q) log(n・m)) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各セルが座標のペア (i, j) で表されるようにグリッドを位置に平坦化します。 グリッド内のすべての値について、行優先順にソートされたリスト内のすべての位置を収集します。 

値ごとに、その出現リストを反復処理し、連続するすべてのペアを検討します。 各ペアは 2 つの同一の値を表し、有効なクエリ四角形内に両方が現れることはありません。 各ペアを、両方の点をカバーする最小および最大の行インデックスと列インデックスを記述する幾何学的オブジェクトに変換します。 

その後、クエリをオフラインで処理します。 各クエリは、その四角形の内側に完全に禁止されたペアが存在するかどうかを尋ねます。 これを 2D 範囲クエリの問題として扱います。 

イベントを行境界でソートし、列空間上でフェ​​ンウィック ツリーを使用して、スイープ中に禁止されたペアのエンドポイントをアクティブにします。 各クエリは、行の境界を尊重しながら、アクティブな制約がその列の範囲に該当するかどうかをチェックすることによって回答されます。 

### なぜ効果があるのか

重要な不変条件は、すべての一意性の違反が少なくとも 1 つの等しい値のペアによって目撃されるということです。 四角形に重複が含まれる場合、その四角形には同じ値の出現が 2 つ含まれている必要があり、それらの出現のうち、境界四角形がクエリ四角形内に完全に含まれる、ソートされた出現リスト内に少なくとも 1 つの連続するペアが存在します。 したがって、すべてのペアではなく、値ごとに連続する出現のみをチェックするだけで十分です。 スイープ構造により、クエリ制約の下で完全にアクティブになったときに、そのようなすべての境界四角形が正確にカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    n, m = map(int, input().split())
    a = []
    pos = defaultdict(list)

    for i in range(n):
        row = list(map(int, input().split()))
        a.append(row)
        for j, v in enumerate(row):
            pos[v].append((i + 1, j + 1))

    events = []
    for v, lst in pos.items():
        lst.sort()
        for k in range(len(lst) - 1):
            (r1, c1) = lst[k]
            (r2, c2) = lst[k + 1]
            rmin, rmax = min(r1, r2), max(r1, r2)
            cmin, cmax = min(c1, c2), max(c1, c2)
            events.append((rmin, rmax, cmin, cmax))

    queries = []
    for idx in range(int(input())):
        i1, j1, i2, j2 = map(int, input().split())
        queries.append((i1, j1, i2, j2, idx))

    queries.sort(key=lambda x: x[2])  # sort by i2

    BIT = [0] * (m + 2)

    def add(i, v):
        while i <= m:
            BIT[i] += v
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += BIT[i]
            i -= i & -i
        return s

    def range_sum(l, r):
        return sum_(r) - sum_(l - 1)

    events.sort(key=lambda x: x[1])

    ans = [True] * len(queries)
    e = 0

    for i2 in range(1, n + 1):
        while e < len(events) and events[e][1] <= i2:
            rmin, rmax, cmin, cmax = events[e]
            add(cmin, 1)
            add(cmax + 1, -1)
            e += 1

        while queries and queries[0][2] == i2:
            i1, j1, i2q, j2, idx = queries.pop(0)
            total = range_sum(j1, j2)
            ans[idx] = (total == 0)

    print("\n".join("YES" if x else "NO" for x in ans))

if __name__ == "__main__":
    solve()
```この実装では、まず、同じ値のすべての位置をグループ化します。 次に、隣接する各ペアを長方形の制約に変換し、その下の境界でソートされたイベントとして保存します。 フェンウィック ツリーは、アクティブな各制約が列間隔に寄与するように、列の差分配列として使用されます。 

行をスイープすると、垂直スパンが現在の行しきい値に完全に含まれるすべての制約がアクティブになります。 クエリは、その下限に達したときに応答されるように設計されています。 このチェックは、アクティブな制約がクエリの列間隔と重複しているかどうかを確認することになります。 

実装の微妙な詳細は、列間隔を表すためにフェンウィック ツリーの差分更新を使用することです。 各イベントは cmin で +1、cmax + 1 で -1 を加算するため、プレフィックスの合計は各列をカバーするアクティブな制約の数を反映します。 

もう 1 つの重要な点は、行スイープとクエリ処理の間の正しい同期を維持することです。これは、どちらもクエリの下限に依存するためです。

 ## 特殊なケース

 重要なエッジ ケースは、重複が存在するがクエリ四角形の外側にある場合です。 その場合、アルゴリズムはそれらに誤ってフラグを立ててはなりません。 イベントベースの構築では、行と列の境界に完全に含まれるペアのみがアクティブな制約に寄与するため、これが保証されます。 

もう 1 つの特殊なケースは、同じ行または列で重複が発生する場合です。 例えば：```
1 2 1
```1 つの出現を除外するクエリでも YES を返す必要があります。 クエリ境界に完全に含まれるペアのみがアクティブ化されるため、アルゴリズムはこれを処理します。 

最後のエッジ ケースは単一セル クエリであり、常に YES を返す必要があります。 どのペアも 1x1 の長方形内に収まらないため、イベントはアクティブ化されず、BIT は空のままとなり、正しく肯定的な応答が生成されます。
