 ## 問題の理解

 私たちにはコインの山が与えられ、2 人のプレイヤーが交互にターンをします。 ターンでは、プレーヤーはいくつかのコインを持って開始します。$x$。 彼らには2種類の動きがあります。 彼らは常にちょうど 1 枚のコインを取り除き、残されたままにすることができます。$x-1$。 あるいは、一度に複数のコインを削除することもできますが、それは削除後に残ったコインの数が現在の山のサイズの約数である場合に限られます。$x$。 最後のコインを取り除いたプレイヤーが勝ちです。 

タスクは、それぞれの開始値を決定することです。$n$、最初のプレイヤーが最適なプレイの下で強制的に勝利するかどうか。 

制約$n \le 10^9$ゲームをシミュレートしたり、すべての州にわたって DP を構築したりするアプローチを除外します。$n$。 すべての状態のすべての約数をチェックするソリューションであっても、多くのテスト ケースで繰り返すと遅すぎるため、最終的なソリューションでは、各クエリを定数時間の分類、または最悪の場合は 2 の累乗や素数のような構造のチェックなどの対数演算に削減する必要があります。 

非常に小さな値では、微妙なエッジケースが現れます。 いつ$n = 1$、移動は不可能なので、最初のプレイヤーはすぐに負けます。 いつ$n = 2$への移動のみ$1$存在するため、最初のプレイヤーの勝ちとなります。 のようなわずかに大きな値の場合$n = 3$または$n = 4$、複数のムーブタイプが相互作用し、約数にジャンプする能力や 1 を減算する能力が常に勝利のムーブを保証するかどうかは、すぐにはわかりません。 これはまさに、ローカル分岐オプションが単純なグローバル パターンを隠す種類のゲームです。 

## アプローチ

 ブルートフォース戦略は各州を扱います$x$ゲームグラフ内のノードとして。 から$x$、有効な次の状態をすべて列挙します。$x-1$そしてすべて$y < x$そのような$y$分割する$x$。 次に、標準ゲーム DP を使用して勝敗状態をマークします。 

これは概念的に機能します。これは、グラフが非周期的であり、すべての動きが厳密にコインの数を減少させるためです。 ただし、コストが大きい。 それぞれについて$x$、すべての約数のコストを確認する$O(\sqrt{x})$最悪の場合、次の状態までのすべての状態を処理する必要があるかもしれません。$n$、おおよそにつながります$O(n\sqrt{n})$最悪の解釈での単一のテストの動作。これは次の場合には不可能です。$n$到達する$10^9$。 

重要な観察は、許可される手の構造が非常に非対称であるということです。 動き$x \to x-1$は常に利用可能であり、除数ジャンプにより構造化された位置にスキップできます。 これにより通常、負けたポジションが非常にまばらなセットに強制されます。 小さな値を分析すると、パターンが現れます。2 の累乗であるポジションは、その約数もすべて 2 の累乗であるため、他のポジションとは異なる動作をし、そこから到達可能な状態は、常に対戦相手に利益をもたらす厳密に制約されたセットに崩壊します。 

これにより、負けているポジションは正確に 2 のべき乗である一方、他のすべての数字は、強制的に勝つ方法で 2 のべき乗に移動できるという単純化につながります。

 ## アルゴリズムのチュートリアル

 各クエリを以下のチェックに集約します。$n$は 2 の累乗です。 

1. 各テスト ケースについて、整数を読み取ります。$n$。 
2. もし$n = 1$、手は存在しないため、最初のプレイヤーが負けたとすぐに宣言します。 
3. のために$n \ge 2$、どうかを確認してください$n$は 2 の累乗です。 これはビットトリックを使用して行うことができます$n \& (n-1) = 0$。 
4. もし$n$は 2 のべき乗であり、2 番目のプレーヤーが勝つという出力です。 それ以外の場合は、最初のプレイヤーが勝つことを出力します。 

ステップ 3 の背後にある推論は、2 のべき乗にはバイナリ表現で 1 つのセット ビットが正確に 1 つあり、これが次の形式の数値を特徴付けるということです。$2^k$。 

### なぜ効果があるのか

 ゲームは常に厳密に小さい数に移動するため、状態空間は有向非巡回グラフを形成します。 重要な構造的事実は、2 のべき乗が約数条件の下で閉じた族を形成するということです。2 のべき乗のすべての約数も 2 のべき乗です。 これにより、追加の柔軟性を提供する「混合要素」状態に陥るのを防ぐ方法で、対戦相手の反応が制限されます。 

非 2 のべき乗の場合、少なくとも 1 つの奇数因子または混合因子が存在し、プレイヤーは一連の動きの後にゲームを強制的に 2 のべき乗状態にすることができます。 それが起こると、対戦相手はポジションに拘束され、最終的にはコントロールを負けた構成に戻します。 この分離により、正確に 2 つのクラスの状態が作成されます。2 のべき乗でポジションを失い、それ以外の場所でポジションを獲得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        if n & (n - 1) == 0:
            # power of two
            print("Second")
        else:
            print("First")

if __name__ == "__main__":
    solve()
```すべての複雑さは数学的分類に組み込まれるため、実装は意図的に最小限に抑えられています。 唯一の重要な演算は、2 の累乗のビット単位のチェックです。 これが機能するのは、2 の累乗には設定ビットが 1 つだけあるため、1 を減算すると下位ビットがすべて反転され、どのビット位置でも元のビットと重ならない数値が生成されるためです。 

よくある間違いはそれを忘れることです$n = 1$この表現では も 2 の累乗になります。 ロジックは引き続き正しく処理します。$1$同じ条件を満たしており、正しく「Second」が出力されます。 

## 実用的な例

 いくつかの代表的な入力をトレースして、分類がどのように動作するかを確認します。 

のために$n = 1$:

 | n | チェック$n \& (n-1)$| 結果 |
 | --- | --- | --- |
 | 1 | 0 & 0 = 0 | 2番目 |

 ゲームには有効な手がないため、当然のことながら 2 番目のプレーヤーが勝者となります。 

のために$n = 6$:

 | n | チェック$n \& (n-1)$| 結果 |
 | --- | --- | --- |
 | 6 (110) | 4 (100) ≠ 0 | 最初 |

 ここでの数字は 2 の累乗ではないため、最初のプレイヤーはいつでも負け構造への移行を強制することができます。 

のために$n = 8$:

 | n | チェック$n \& (n-1)$| 結果 |
 | --- | --- | --- |
 | 8 (1000) | 0 | 2番目 |

 これは純粋な 2 のべき乗の状態であり、すべての動きが制限された一連の状態に崩壊し、最終的には相手にアドバンテージを返すことを意味します。

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムはすぐに 2 の累乗として分類し、「秒」を出力します。 これは、開始プレイヤーが正当な手を持たず、定義上負けであるという事実と一致します。 

のために$n = 2$、ビット チェックでも 2 の累乗であることが識別され、結果は「2 番目」になります。 ゲームの観点から見ると、唯一の動きは次のことにつながります。$1$、次のプレイヤーにとってはターミナル負けの状態です。 

非パワーのような場合$n = 12$、バイナリ表現には複数の設定ビットが含まれています。 アルゴリズムは「First」を出力します。これは、最適なプレイの下で最終的に 2 のべき乗の構造にまで縮小する、常に対戦相手を制約された位置に追い込む可能性のある一連の動きが存在することを反映しています。
