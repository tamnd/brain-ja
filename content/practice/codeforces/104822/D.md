 ## 問題の理解

 固定の順列が与えられています$p$サイズの$n$そして、それを辞書編集的に以前に存在する同じサイズの他のすべての順列と比較したいと考えています。$p$。 そのような順列ごとに$p'$、統計を計算します$f(p')$、値の直後に後続値が続く回数をカウントします。 より正確には、インデックスのペアを数えます。$i < j$そのような$p'_i + 1 = p'_j$隣接しているかどうかに関係なく。 

次に、すべての順列を分類します$p'$辞書順に小さいもの$p$の値に従って$f(p')$、そしてすべてについて$k$、そのような順列がいくつあるかを数える必要があります。$f(p') = k$。 

出力は、すべての可能な値にわたる頻度分布です。$f(p')$指定された順列よりも辞書編集的に小さい順列の中で。 

主な問題は、すべての順列をカウントしているのではなく、辞書編集順序の接頭辞のみをカウントしていることです。 これにより、この問題は基本的に、グローバルな計数の問題ではなく、順列に対する接頭辞 DP になります。 

制約$n \le 100$階乗列挙は即座に除外されます。 すべての順列を生成することさえ不可能です。$n!$天文学的に大きいです。 すべての解は多項式でなければなりません$n$、通常は約$O(n^3)$または$O(n^4)$。 

次の場合、微妙なエッジケースが発生します。$p$最小の順列です$[1,2,\dots,n]$。 この場合、辞書編集的に小さい順列は存在しないため、すべての答えはゼロでなければなりません。 

別のエッジケースが発生するのは次の場合です。$p$は最大の順列です$[n,n-1,\dots,1]$。 次に、すべての順列がカウントされ、答えはすべての順列にわたる完全な分布に帰着します。これは、正しさの健全性チェックに役立ちます。 

明白ではない課題は、$f(p')$隣接構造ではなく、順列におけるグローバルな順序関係に依存します。 ローカル遷移のみを追跡する単純な DP は、慎重に強化しない限り不十分です。 

## アプローチ

 ブルートフォースソリューションでは、すべての順列を列挙します。$p'$、それぞれを比較します$p$、そして計算します$f(p')$。 それぞれの評価は、$f$かかります$O(n^2)$、そして、あります$n!$順列。 これはたとえ$n = 10$、 以来$10! \approx 3.6 \times 10^6$、そしてのために$n = 100$それは不可能です。 

重要な観察は、辞書編集上の制限は、左から右への置換を構築し、厳密に下にとどまることができる方法が何通りあるかを数えることによって処理できるということです。$p$。 これは順列に対する古典的な数字の DP です。最初の位置では、以下より小さい値を選択します。$p_i$、サフィックスは無制限になります。 

2 番目の要素は理解です$f(p')$。 関数はペアをカウントします$(x, x+1)$どこ$x$前に現れます$x+1$。 これは、値ごとにカウントすることと同じです。$x$、 かどうか$x$よりも前に配置されます$x+1$。 したがって$f(p')$は、連続する値間の相対的な順序制約によって完全に決定されます。 

これにより、問題は、値空間における隣接する値の順序関係に関する制約と、位置空間における辞書編集的な接頭辞の制約とを組み合わせた順列のカウントに変わります。 これら 2 つの構造間の相互作用は、位置、値、およびそれぞれの構造が正しいかどうかを追跡する部分的な順序付け状態に関する DP を示唆しています。$x < x+1$関係は満たされました。 

これをエンコードする標準的な方法は、配置された値の数、使用された値のセット、および現在の寄与度に関する DP を維持することです。$f$。 以来$n \le 100$では、値の順序に対してビット単位または増分 DP を使用して状態を圧縮しますが、唯一の依存関係が連続する整数間であることに注意して、完全なサブセット DP を回避します。 

値を昇順に処理し、それらの相対的な配置を決定します。 それぞれについて$x$、両方の場合$x$そして$x+1$すでに配置されているため、それらが貢献しているかどうかがわかります。$f$。 ただし、辞書編集上の制限も同時に尊重する必要があります。これは、タイト/ルーズ状態の位置に対して標準の接頭辞 DP を使用して処理されます。 

最終的な解決策は、位置を反復し、現在のプレフィックスよりも小さい値がいくつ使用されているかを追跡し、連続する値間で満たされた隣接関係の数にわたって DP を維持する DP です。

 ## アルゴリズムのチュートリアル

 辞書編集上の制限と計算に必要な構造の両方を追跡しながら、位置ごとに順列を構築します。$f(p')$。 

1. DP 状態を次のように定義します。$dp[i][k][t]$、 どこ$i$埋まったポジションの数は、$k$の現在値です$f$、 そして$t$構築されたプレフィックスが依然として次のプレフィックスと等しいかどうかを示します。$p$（きつい状態）またはすでに小さくなっている（緩い状態）。 辞書編集上の制限は最初の逸脱までしか問題にならないため、この分離が必要です。 
2. どの値がすでに使用されているかを追跡する構造を維持します。 完全なセットを明示的に保存する代わりに、さまざまな範囲に未使用の値がどれだけ残っているかをカウントすることで、暗黙的に可用性をエンコードします。$p_i$。 遷移はプレフィックス制約に対する相対的な順序のみに依存するため、この圧縮は有効です。 
3. 各ポジションで$i$、すべての候補値を反復処理します。$v$まだ使用されていません。 次の 2 つのケースに分けます。$v = p_i$密着性を維持し、$v < p_i$強制的に緩んだ状態に移行します。 価値観$v > p_i$きつい状態では許可されませんが、緩い状態では許可されます。 
4. 値を入れる場合$v$への投稿を更新します。$f$かどうかを確認することで$v-1$すでに配置されています。 そうである場合、この配置により、新しい有効なペアが 1 つだけ作成され、$f$。 これは重要な削減です。$f$段階的に更新できます$O(1)$移行ごとに。 
5.それに応じて DP 遷移を更新し、状態からの方法を追加します$dp[i][k][t]$に$dp[i+1][k']$隣接しているかどうかに応じて$(v-1, v)$満足しています。 
6. すべてのポジションを処理した後、タイトな状態とルーズな状態の両方を合計します。$i = n$、最終的な分布を生成します$k$。 

重要な不変条件は、処理後の$i$位置、DP は長さのすべての部分順列を正確に表します$i$辞書編集上の制約と一致しており、貢献度が正しく蓄積されています。$f$すでに決定されている連続する整数の相対的な配置のみに基づきます。 なぜなら、それぞれの貢献は、$v-1$以前に決定されたため、将来の決定を遡って変更することはできません$f$、増分更新の正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, mod = map(int, input().split())
    p = list(map(int, input().split()))

    # dp[pos][mask of used compressed state is infeasible for n=100]
    # We instead use DP over positions, value-placed relations:
    # dp[i][k][tight]
    dp = [[[0] * 2 for _ in range(n + 1)] for _ in range(n + 1)]
    dp[0][0][1] = 1

    used = [False] * (n + 1)

    for i in range(n):
        new = [[[0] * 2 for _ in range(n + 1)] for _ in range(n + 1)]

        for k in range(n + 1):
            for tight in range(2):
                cur = dp[i][k][tight]
                if not cur:
                    continue

                for v in range(1, n + 1):
                    if used[v]:
                        continue

                    if tight and v > p[i]:
                        continue

                    ntight = tight and (v == p[i])

                    nk = k
                    if v > 1 and used[v - 1]:
                        nk += 1

                    if nk <= n:
                        new[i + 1][nk][ntight] = (new[i + 1][nk][ntight] + cur) % mod

        used[p[i]] = True
        dp = new

    res = [0] * n
    for k in range(n):
        res[k] = (dp[n][k][0] + dp[n][k][1]) % mod

    print(*res)

if __name__ == "__main__":
    solve()

の`used`配列は順列の有効性を強制します。 遷移ループは、すべての未使用の値を反復処理します。 値を配置するとき、その前の値がすでに使用されているかどうかを確認します。 そうであれば、貢献度を増額します$f$。 これが重要な簡素化です。$f$遷移ごとに一定時間で計算可能。 

DP 配列はカウントをモジュロで保存します$m$。 最終的な答えは、厳密さに関係なくすべての最終状態を集約します。これは、どちらも厳密にプレフィックス条件以下の有効な置換を表しますが、最後に到達したものだけが完全な置換に対応するためです。
