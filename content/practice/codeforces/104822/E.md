 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、好きな場所にある文字を削除できます。 削除後、残りのシーケンスを確認します。そして、非常に特殊な種類の局所的無秩序を回避したいと考えています。つまり、連続する 3 つの位置 (元の文字列では必ずしも隣接している必要はありませんが、結果の文字列では連続している) がどちらかを形成することはありません。`010`または`101`。 

言い換えれば、文字の削除が完了すると、残りの文字列の長さ 3 のウィンドウはすべて定数 (`000`、`111`)、または遷移方向は最大 1 つですが、3 つの位置を 2 回反転することはできません。 

タスクは、最終的な文字列がこの条件を満たすために必要な最小の削除数を計算することです。 同様に、削除は単なる削除であるため、これらの禁止されたパターンを含まない可能な限り長いサブシーケンスを保持したいと考えます。`n minus kept length`。 

この制約により、すべてのテスト ケースで最大 300,000 文字が許可されます。 これにより、部分文字列や削除に対する 3 次または 2 次のアプローチは即座に除外されます。 テスト ケースごとに線形または線形に近いものを超えると、遅すぎます。 ネストされたループ内の位置ごとに何かを再計算するソリューションは、完全な入力には耐えられません。 

微妙な点は、条件が元の文字列の部分文字列ではなく、削除後の部分列に関するものであることです。 1 文字を削除すると、多くの禁止されたトリプルが同時に破棄される可能性があるため、単純なパターン削除は誤解を招きます。 

単純なアプローチでは、パターンが検出されるたびに貪欲にスキャンして削除しようとする可能性があります。`010`または`101`が表示されます。 局所的な貪欲な削除により全体的に最適な構造が破壊される可能性があるため、これは失敗します。 

たとえば、次のように考えてみましょう`01010`。 貪欲に削除すると、最初の文字の中央の文字が削除される可能性があります。`010`、生産`0110`、その後、続行してさらに削除し、必要以上に短い結果で終了します。 最適な戦略では、代わりに次のような構造化されたサブシーケンスが維持されます。`000`または`111`または、カウントに応じてシングルスイッチ形式。 

主な問題点は、キャラクタを削除すると隣接関係がグローバルに変更されるため、ローカルな修正が安定しないことです。 

## アプローチ

 ブルート フォース ソリューションでは、文字のすべてのサブセットを試し、結果の文字列が有効かどうかを確認し、最大サイズを追跡します。 部分系列だけで考えても、`2^n` possibilities, and each validity check costs `O(n)`、不可能な指数関数的爆発につながります。 

構造的な洞察は、`010`そして`101`長さ 3 の交互パターンをすべて削除します。それらを回避する文字列は、「方向を 2 回切り替える」ことはできません。 一度 0 から 1 になると、後で 0 に戻ることはできません。また、その逆も同様です。 これは、すべての有効な文字列には、文字間に最大 1 つの遷移が必要であることを意味します。 

したがって、有効な最終文字列はすべて、すべて 0、すべて 1、0 の後に 1、または 1 の後に 0 の 3 つの形式のいずれかである必要があります。 

これが分かると、問題は 4 つの単純なテンプレートの下での最長部分列問題になります。 テンプレートごとに、保持できる最大文字数を計算し、から減算します。`n`。 

プレフィックスとサフィックスの数を使用して、各ケースを線形時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 許可された構造形式の 1 つに適合する最長のサブシーケンスが必要です。 私たちは各フォームを個別に評価し、最良のものを採用します。 

1. 文字列全体の 0 と 1 のプレフィックス数を計算します。 

これにより、プレフィックスまたはサフィックスに各文字が何個存在するかをすぐに知ることができます。 
2. 最後の文字列がすべてである場合を考えてみましょう。`0`。 

私たちにできる最善のことは、元の文字列のすべてのゼロを維持することです。 これは貢献します`count(0)`。 
3. 最後の文字列がすべてである場合を考えてみましょう。`1`。 

同様に、すべてを保持して貢献することもできます`count(1)`。 
4. フォームを考慮する`0*1*`、最初にゼロ、次に 1 の順序で意味します。 

スプリットポイントを選択します`i`。 左側にあるものはすべて 0 でなければならず、右側にあるものはすべて 1 である必要があります。 

スプリットのスコアは`i`は：`zeros in prefix [0..i] + ones in suffix [i+1..n-1]`。 
5. すべての分割位置をスイープし、可能な限り最良の値を計算します。`0*1*`。 

これは、戻ることなく 0 から 1 への 1 つの遷移を許可する最良の方法を捉えています。 
6. 対称構造を繰り返します。`1*0*`。 

分割ごとに、次を計算します。`ones in prefix + zeros in suffix`。 
7. 4 つのケースすべての最大値を取得します。 

答えは`n - best_kept`。 

### なぜ効果があるのか

 有効な最終文字列には両方のパターンを含めることはできません`010`そして`101`これは、方向を 2 回切り替えることができないことを意味します。 この制限により、文字シーケンスをランに圧縮する場合、値の変更は最大 1 回のみとなります。 したがって、すべての有効なサブシーケンスは、上で列挙した 4 つの構造ファミリーのいずれかに属している必要があります。 すべての候補ファミリーは、その制約の下で可能な最大のサブシーケンスについて明示的に評価されるため、それらの最大値がグローバルに最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        pref0 = [0] * (n + 1)
        pref1 = [0] * (n + 1)

        for i, ch in enumerate(s):
            pref0[i + 1] = pref0[i]
            pref1[i + 1] = pref1[i]
            if ch == '0':
                pref0[i + 1] += 1
            else:
                pref1[i + 1] += 1

        total0 = pref0[n]
        total1 = pref1[n]

        best = max(total0, total1)

        for i in range(n + 1):
            best = max(best, pref0[i] + (total1 - pref1[i]))
            best = max(best, pref1[i] + (total0 - pref0[i]))

        print(n - best)

if __name__ == "__main__":
    solve()
```この実装では、接頭辞または接尾辞のクエリが O(1) になるように、0 と 1 の接頭辞の合計が構築されます。 分割位置のループは、位置ごとに両方の遷移方向を一定時間で評価します。 最後の減算により、保持されるサブシーケンスの最大長が最小の欠失に変換されます。 

よくある間違いは、分割が包含-排他的であることを忘れていることです。そのため、プレフィックスは`i`と接尾辞の使用`i`慎重に先に進んでください。 もう 1 つは二重カウントです。これは、相補的なプレフィックスとサフィックスのペアを使用することで回避されます。 

## 実用的な例

 ### 例 1

 検討してください`s = 00110`。 

プレフィックス数を計算します。 

| 私 | プレフィックス 0 | プレフィックス 1 |
 | --- | --- | --- |
 | 0 | 0 | 0 |
 | 1 | 1 | 0 |
 | 2 | 2 | 0 |
 | 3 | 2 | 1 |
 | 4 | 2 | 2 |
 | 5 | 3 | 2 |

 合計 0 = 3、合計 1 = 2。 

分割貢献を評価します。 

| 分割します | 0_1_値 | 1_0_値 |
 | --- | --- | --- |
 | 0 | 0 + 2 = 2 | 0 + 3 = 3 |
 | 2 | 2 + 2 = 4 | 0 + 3 = 3 |
 | 3 | 2 + 1 = 3 | 1 + 3 = 4 |
 | 5 | 3 + 0 = 3 | 2 + 0 = 2 |

 最適な長さは 4 なので、答えは次のようになります。`5 - 4 = 1`。 

これは、単一の文字を削除すると、きれいな単調な構造が強制できるという直観と一致します。

 | 3 | 1 | 2 |

 合計 0 = 2、1 = 3。 

最良の分割評価では、最適に保持されるサブシーケンスが 3 であることが示され、答え 2 が得られます。 

トレースは、両方向を保存しようとすると禁止されたトリプルが強制されるため、交互構造は欠失なしでは存続できないことを示しています。

 ## 特殊なケース

 次のような単一の文字の場合`0`、アルゴリズムは、すべての遷移形式が単純な値に折りたたまれるプレフィックス値を計算します。 最適に保持される長さは 1 になり、削除はゼロとなり、予想される出力と一致します。 

次のようなすでに均一な文字列の場合`00000`すべての構成の中で最も良いのは、単純にすべてゼロを維持することです。 分割ロジックは合計ゼロカウントを超えて改善されることはないため、結果は削除がゼロになります。 

次のような完全に交互の文字列の場合`010101`、分割するたびに、オルタネーションを破壊するか、構造の半分を破棄するかのどちらかが強制されます。 プレフィックスとサフィックスの評価は、長く交互するサブシーケンスが有効ではないことを正確に捕捉し、最適に維持される長さは小さな定数で安定します。 

次のようなブロック構造の文字列の場合`001111`、最適な分割はブロック間の自然な境界と一致します。 の`0*1*`case はすべてを保持し、アルゴリズムは完全な長さを選択して、削除はゼロになります。
