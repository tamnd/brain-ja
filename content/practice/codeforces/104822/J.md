 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは長さの順列を提供します`n`、非常に特殊なローカル操作を繰り返し適用することができます: 任意の位置を選択します`i`そこから始まる 3 つの連続する要素のブロックが存在し、その長さ 3 のブロックを反転します。 

タスクは、指定された順列から始めて、それをソートされた順列に変換できるかどうかを判断することです。`1, 2, 3, ..., n`これらの三重反転を任意の数だけ使用します。 

この操作では、一度に 3 つの隣接する要素のみに触れます。これは、恣意的な再配置を行っていないことをすでに示唆しています。 代わりに、制約付き順列ジェネレーターのように動作する非常にローカルな変換に制限されます。 

制約は大きく、`n`すべてのテストケースにわたって、`2 · 10^5`。 これにより、状態空間のサイズは階乗であり、多くの操作が必要な場合は操作ごとの線形時間でさえ遅すぎるため、ソート プロセスや順列にわたる BFS のシミュレーションは即座に除外されます。 

最も小さな興味深いエッジケースが現れるのは、`n < 3`。 その場合は一切の操作ができなくなります。 もし`n = 1`、順列は常にソートされます。 もし`n = 2`、スワップを修正することは決してできないため、すでにソートされた順列のみが有効です。 これらのケースは、到達可能性が値の比較に関するものではなく、許可された操作の構造上の制約に関するものであることをすでに示しています。 

より微妙なエッジ ケースは、順列が「ほぼソートされている」ものの、隣接する要素の 1 回の交換が必要な場合に発生します。 例えば、`1 3 2`どの演算にも 3 つの要素の完全なブロックが必要であり、置換のローカル パリティが関係するため、単一の三重反転では修正できません。 これは、順序を超えた何らかの不変性が保存されていることを示唆しています。 

## アプローチ

 ブルートフォース解釈では、問題を順列にわたる最短経路検索として扱います。各ノードは順列であり、エッジはあるインデックスでの三重反転の適用に対応します。 各州からは、`O(n)`移動とそれぞれの移動にかかる費用`O(n)`配列をコピーすると、分岐係数と状態サイズの両方が爆発的に増加します。 状態空間のほんの一部を探索することさえ不可能になります。`n = 200000`。 

重要な観察は、三重反転は恣意的な再配置を許可しないが、局所構造の制御された並べ替えを許可するということです。 3つの要素の逆転`[a, b, c] → [c, b, a]`スワッピングと同等です`a`そして`c`保ちながら`b`修理済み。 これは、エンドポイントが位置を交換する間、中央の要素がピボットとして機能することを意味します。 

このことから、要素は中間位置を交換することで効果的に「移動」できると推測できますが、各移動はグローバルなパリティの不変条件を保持します。つまり、すべての操作は 3 つの要素に対する奇数の置換ですが、重複するトリプル間で制約された方法で構成されます。 重要な結果は、恒等式から到達可能な順列のパリティが、与えられた条件に対して固定されるということです。`n`。 

それを確認するより直接的な方法は、この操作が反転パリティにどのような影響を与えるかを検討することです。 トリプル反転のたびに反転カウントが偶数だけ変化します。これは、反転パリティが不変であることを意味します。 したがって、反転パリティがソートされた配列の反転パリティ (ゼロ) と一致する順列のみに到達できます。 

したがって、問題全体は、指定された順列が偶数反転パリティを持つかどうかをチェックすることに帰着します。 

残っている唯一のタスクは、逆パリティを効率的に計算することです。

 ## アルゴリズムのチュートリアル

 許可された操作を使用して、並べ替えを並べ替え順序に変換できるかどうかを判断したいと考えています。 到達可能性は反転パリティのみに依存するため、反転の数が偶数であるかどうかを計算します。 

1. 各テスト ケースについて、順列を読み取ります。 パリティを決定することだけが必要であるため、反転カウントに必要な以上のものは保存しません。 
2. フェンウィック ツリー (バイナリ インデックス付きツリー) を使用して反転パリティを計算します。 現在の要素より大きい前の要素の数を維持しながら、要素を左から右に処理します。 このような各カウントは反転合計に寄与します。 
3. 完全な反転カウントを計算する代わりに、2 を法とする値のみを追跡します。これにより、オーバーフローが回避され、ロジックが簡素化されます。 
4. 各要素について`a[i]`より大きい要素がいくつあるかをクエリします。`a[i]`すでに見られています。 そのカウントを法 2 で実行パリティに追加します。 
5. 配列全体を処理した後、最終パリティがゼロの場合、出力`YES`、それ以外の場合は出力`NO`。 

フェンウィック ツリーを使用できる理由は、順列をスキャンする際に動的なプレフィックス頻度カウントが必要になるためです。 

### なぜ効果があるのか

 各三重反転は、距離 2 での要素のスワップのシーケンスであり、そのような各操作では反転パリティが保存されます。 ソートされた順列は反転パリティ 0 を持つため、到達可能な順列もパリティ 0 を持つ必要があります。 逆に、トリプル反転を使用して隣接するスワップをペアでシミュレートできることを示すことができます。これは、任意の偶数パリティ順列が達成可能であることを意味します。 これにより、完全な特性評価が作成されます。到達可能性は、偶数反転パリティを持つことと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] ^= v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s ^= self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # inversion parity using BIT storing counts mod 2
        bit = Fenwick(n)
        inv_parity = 0

        for i, x in enumerate(a):
            # number of elements <= x seen so far
            leq = bit.sum(x)
            seen = i
            gt = seen - leq
            inv_parity ^= (gt & 1)
            bit.add(x, 1)

        print("YES" if inv_parity == 0 else "NO")

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、すでに処理された値の頻度を維持します。 新しい要素ごとに`x`、以前に確認された値がどれだけ大きいかを計算します。`x`プレフィックス数を減算することによって`<= x`見た要素の合計から。 パリティのみを考慮しているため、寄与を XOR します。`inv_parity`。 

整数加算の代わりに XOR を使用すると、算術状態の定数メモリを超えることがなくなります。 

微妙な点は、次の順列である値に依存していることです。`1..n`したがって、Fenwick のインデックス付けは、圧縮せずに値と直接一致します。 

## 実用的な例

 順列を考慮してください`3 1 2`。 

逆パリティを段階的に追跡します。

ここで考えてみましょう`2 1 3`。

これらのトレースは、アルゴリズムが動きをシミュレートするのではなく、反転構造を効果的に追跡していることを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] ^= v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s ^= self.bit[i]
                i -= i & -i
            return s

    def solve():
        t = int(input())
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            bit = Fenwick(n)
            inv = 0
            for i, x in enumerate(a):
                leq = bit.sum(x)
                gt = i - leq
                inv ^= (gt & 1)
                bit.add(x, 1)
            output.append("YES" if inv == 0 else "NO")

    solve()
    return "\n".join(output)

assert run("1\n3\n3 1 2\n") == "YES"

 ## 特殊なケース

 のために`n = 1`、アルゴリズムはすぐに戻ります`YES`なぜなら、反転は存在せず、ループは何も行わないからです。 フェンウィック構造は意味のある形で使用されることはありませんが、パリティはゼロのままです。 

のために`n = 2`、単一のスワップのような`2 1`反転が 1 つだけ生成されるため、パリティが 1 になり、アルゴリズムは正しく出力します。`NO`。 これは、次の場合には操作が不可能であるという事実と一致します。`n < 3`。 

次のような完全に逆の順列の場合`n n-1 ... 1`、反転パリティは次のように依存します。`n(n-1)/2`。 アルゴリズムは、BIT クエリを通じてこれを自然に蓄積し、この値が偶数である場合にのみ受け入れます。これは、トリプル反転時の到達可能性条件と一致します。
