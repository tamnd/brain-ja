 ## 解決策
 ## 問題の理解

 すべてのノードに範囲内の色が割り当てられるツリーを操作しています。$1$に$k$。 各色ごとに$i$、色が次のノードを少なくとも 1 つ含む単純なパスがツリー内にいくつあるかを数える必要があります$i$。 

2 つのノードを選択することで単純なパスが決定されます$u$そして$v$、ツリー内のそれらの間の固有のパスをたどります。 次の場合、パスは単一のノードで構成される場合もあります。$u = v$。 パスはノードのシーケンスとしてカウントされるため、方向が重要になります。$(u \rightarrow v)$そして$(v \rightarrow u)$常に異なるパスとして扱われます$u \ne v$。 

主要な出力は、色ごとに、その色のノードを少なくとも 1 つ含む、そのような順序付けされたノード ペア パスの数です。 

この制約により、直ちに二次関数から遠ざけられることになります。$n$。 テスト ケース全体のノードの総数は最大なので、$3 \cdot 10^5$、たとえ単一のツリーであっても、すべてのパスを明示的に検査するソリューションでは、次のことを考慮しようとします。$O(n^2)$エンドポイントのペアが必要であり、完全に実行不可能です。 

2 番目の微妙な点は、色がまったく存在しない可能性があることです。 特定の色を持つノードがない場合、その色の答えはゼロでなければなりません。これにより、後で減算ベースの推論が中断されてはなりません。 

単純だが危険なエッジ ケースは、順序付けされたパスをカウントすることから発生します。 たとえば、2 ノード ツリーの場合、$1 - 2$、次の 4 つのパスがあります。$[1], [2], [1 \rightarrow 2], [2 \rightarrow 1]$。 両方のノードが同じ色を共有する場合、4 つのパスすべてがその色についてカウントされます。 方向性を忘れた解法では、ちょうど半分の正解が得られます。 

## アプローチ

 最初の本能は色を固定することです$c$そして、その色のノードを少なくとも 1 つ含むすべてのパスを数えてみます。 エンドポイントのすべてのペアを列挙し、それらの間のパスを抽出し、ノードに色があるかどうかを確認することを想像できます。$c$。 すべての単純なパスはエンドポイントのペアに対応するため、これは原理的には正しいですが、列挙は$O(n^2)$テストケースごとに、約$10^{10}$最悪のシナリオでの作戦。 

重要なシフトは、条件を反転することです。 特定の色を含むパスを数える代わりに、考えられるすべてのパスを数え、その色を完全に避けるパスを減算します。 これは木の標準的な補完トリックです。色を避けるということは、その色のすべてのノードを削除することによって形成される森に制限されることを意味します。 そのフォレストでは、有効なパスはすべて、接続されたコンポーネント内に完全に存在します。 

したがって、固定色の場合$c$色のノードをすべて削除すると、$c$、ツリーはいくつかの接続されたコンポーネントに分割されます。 同じコンポーネント内のノードの順序付きペアはすべて、色を回避する有効なパスを定義します。$c$。 サイズのコンポーネント内のそのような順序付けされたパスの数$s$は$s^2$なぜなら、開始と終了を独立して選択できるからです。 

したがって、色ごとに、その色のすべてのノードを削除した後でツリー内の接続されたコンポーネントのサイズを計算し、元のツリー内の順序付きノード ペアの合計数からそれらのコンポーネント内の順序付きペアの合計数を引く必要があります。$n^2$。 

残りの課題は効率です。 カラーごとに個別に DFS を再構築することはできません。 代わりに、色がノードを分割することを観察し、その色ではないノードによって引き起こされるサブグラフのみをトラバースすることによって各色を処理できます。 各ノードはカラークラスの処理ごとに 1 回アクセスされますが、隣接リストを使用して接続されたコンポーネントによって処理し、禁止されたノードをスキップするため、合計作業量はテスト ケースごとにすべての色にわたって線形のままです。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. ツリー内の順序付けられたノード ペアの合計数を計算します。 注文したペアごとに$(u, v)$有効な単純なパスを定義します。この値は$n^2$。 これは、各色の無効なパスを差し引くベースラインになります。 
2. ノードを色ごとにグループ化することで、特定の色を処理するときに除外されるノードを効率的に識別できるようになります。 これにより、「色を取り除く」という治療が可能になります。$c$」は、トラバーサル中にそれらのノードを単にスキップするだけです。 
3.各色ごとに$c$、色が異なるノードのみを考慮します。$c$。 この誘導されたセットで、DFS または BFS を使用して接続されたコンポーネントを見つけ、両方のエンドポイントが許可されている場合にのみエッジを使用できるものとして扱います。 
4. 見つかったすべてのコンポーネントのサイズを次のようにします。$s$。 内部のノードの順序付けられたペアはすべて、色に触れないパスに対応します。$c$、貢献$s^2$安全な道。 
5. すべてを合計します$s^2$すべてのコンポーネントにわたる値。 これにより、色を完全に回避するパスの数が得られます。$c$。 
6. これをから引きます$n^2$。 残りは、少なくとも 1 つの色のノードを含むパスの数です。$c$。 
7. すべての色に対して繰り返し、結果を出力します。 

中心的な考え方は、すべてのパスが色を避けるか、$c$完全に、または少なくとも 1 回含まれており、これら 2 つのカテゴリは、順序付けされたすべてのパスを分割します。 

### なぜ効果があるのか

 固定色の場合$c$、色のないノードに制限されたツリー$c$森を形成します。 同じ接続コンポーネント内のノードの順序付きペアは、そのコンポーネント内に留まる一意の単純なパスを定義するため、色が避けられます。$c$。 逆に、色を避けるパスは$c$コンポーネントを離れるには、削除されたノードを通過する必要があるため、コンポーネントはそのようなコンポーネントの 1 つの内部に完全に存在する必要があります。 これにより、有効な「回避」パスとコンポーネント内の順序付きペアの間の全単射が確立され、$s^2$数えています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        col = list(map(int, input().split()))
        col = [c - 1 for c in col]

        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        total = n * n
        ans = [0] * k

        for c in range(k):
            vis = [False] * n

            def dfs(start):
                stack = [start]
                vis[start] = True
                size = 0
                while stack:
                    u = stack.pop()
                    size += 1
                    for v in adj[u]:
                        if not vis[v] and col[v] != c:
                            vis[v] = True
                            stack.append(v)
                return size

            avoid = 0
            for i in range(n):
                if col[i] != c and not vis[i]:
                    sz = dfs(i)
                    avoid += sz * sz

            ans[c] = total - avoid

        print(*ans)

if __name__ == "__main__":
    solve()
```実装は補完戦略に直接従います。 色ごとに、訪問した配列を再構築し、その色ではないノードでのみ DFS を実行します。 各 DFS はフィルター処理されたグラフ内の連結成分のサイズを返し、そのサイズの 2 乗を累積します。 

微妙な点は、パスを順序付きペアとして扱うため、寄与は次のようになります。$s^2$、 ない$\frac{s(s-1)}{2}$。 これは、方向が重要であるという定義と一致します。 

もう 1 つの重要な実装の詳細は、各色の訪問済み配列をリセットすることです。 これにより定数要素が増加しますが、正確性が維持され、ロジックが単純に保たれます。 制約を考慮すると、このアプローチは受け入れられます。 

## 実用的な例

 色が構造を分割する小さな木を考えてみましょう。 

入力:```

1 2 1
1 2
2 3
```チェーンがあります$1 - 2 - 3$。 ノード 1 と 3 はカラー 1、ノード 2 はカラー 2 です。順序付けられたパスの合計は次のとおりです。$9$。 

カラー 1 の場合、ノード 1 と 3 を削除するとノード 2 だけが残ります。唯一のコンポーネントのサイズが 1 であるため、回避パスは$1^2 = 1$。 したがって、答えは$9 - 1 = 8$。 

カラー 2 の場合、ノード 2 を削除すると、サイズ 1 と 1 の 2 つの独立したノードに分割されます。回避パスは次のとおりです。$1^2 + 1^2 = 2$、したがって、答えは$9 - 2 = 7$。 

| ステップ | 残りのノード | コンポーネント | 回避された合計 |

 ## 特殊なケース

 単一ノードのケースは、パス定義の最も単純なストレス ポイントです。 色のノードが 1 つある場合$c$、その色を削除すると空の森が生成されるため、回避はゼロとなり、答えは次のようになります。$1^2 = 1$、唯一の有効なパスに一致します$[u]$。 ノードが除外されるため、DFS ループは決して実行されず、回避に寄与するコンポーネントはありません。これは補完ロジックと一致します。 

2 番目に重要なケースは、すべてのノードが同じ色を共有する場合です。 その状況では、その色の誘導グラフは空になり、すべての順序付きペア パスが答えにカウントされます。 他の存在しない色の場合も、その答えは次のようになります。$n^2$存在しない色を削除しても何も起こらず、ツリー全体がサイズの 1 つのコンポーネントのままになるためです。$n$、回避を与える$n^2$補色を慎重に解釈した場合、実際に存在する色と色間で完全に対称な場合のみ。
