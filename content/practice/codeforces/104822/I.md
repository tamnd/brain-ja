 ## 問題の理解

 整数が与えられます$a$。 各テスト ケースに対して、最小の正の整数を選択する必要があります。$b$そのような数字$a + b$製品を分割します$a \cdot b$その通り。 

より具体的には、最初のポジティブシフトを模索しています。$b$数字を取ると$a$それを乗算します$b$、その積は合計で完全に割り切れます。$a + b$。 このタスクは、多くの値に対して繰り返されます。$a$、それぞれについて、有効な最小値を出力します。$b$。 

制約$a \le 10^9$そして$t \le 10^4$あらゆることを試みるアプローチを除外する$b$まで$a$または最大まで$\sqrt{a}$テストケースごとに独立して実行されます。 テスト ケースごとのリニア スキャンには、最大で$10^{13}$限界をはるかに超えた最悪の場合の操作。 

素朴な推論が微妙に失敗するケースは、「一度除数が失敗すると、より大きな除数が予測どおりに動作する」などの単調な構造を仮定することから生じます。 たとえば、$a = 6$、 チェック中$b = 1, 2, 3, 4, 5, \dots$有効な値が不規則に出現することがわかります。 正しい答えは、$b = 2$、 以来$6 + 2 = 8$分割する$12$。 貪欲なスキップ戦略では、そのようなケースを見逃してしまいます。 

もう 1 つのよくある落とし穴は、キャンセルして簡素化しようとすることです。$a$攻撃的すぎる。 条件には和と積の両方が含まれるため、直接キャンセルしても分離されません。$b$きれいに。 

## アプローチ

 定義条件から始めます。$$a + b \mid a \cdot b$$これは整数が存在することを意味します$k$次のような:$$a \cdot b = k(a + b)$$拡張:$$ab = ka + kb$$並べ替え:$$ab - kb = ka$$

$$b(a - k) = ka$$この方程式はすぐには役に立ちません。$k$は不明です。 ただし、元の条件をより構造的な方法で書き直すことができます。$$\frac{ab}{a+b} \in \mathbb{Z}$$重要な変換は、gcd 構造の観点から割り算条件を表現することから生まれます。 させて：$$g = \gcd(a, b)$$書く：$$a = gA, \quad b = gB, \quad \gcd(A, B) = 1$$それから：$$a+b = g(A+B), \quad ab = g^2 AB$$条件は次のようになります。$$g(A+B) \mid g^2 AB$$1つキャンセル$g$:$$A+B \mid gAB$$なぜなら$\gcd(A,B)=1$、対話は次のように簡素化されます。$A+B$分けなければなりません$g \cdot AB$、 しかし$A+B$明らかな強制要因を共有していない$A$または$B$。 これは、構造が次のように制御されていることを示唆しています。$a+b$の倍数と揃える$a$または$b$、特に最小の解決策は、構造化された変換の約数をテストするという方法で割り算が「厳密」である場合に達成されます。$a$。 

条件を次のように書き換えると、より直接的で実装可能な観察が得られます。$$a \cdot b \equiv 0 \pmod{a+b}$$させて$x = a+b$、 それで$b = x-a$。 代わりの：$$a(x-a) \equiv 0 \pmod{x}$$拡張:$$ax - a^2 \equiv 0 \pmod{x}$$以来$ax \equiv 0 \pmod{x}$、これは次のようになります。$$-a^2 \equiv 0 \pmod{x}$$それで：$$x \mid a^2$$これが重要な削減です: 検索する代わりに$b$、私たちは検索します$x = a+b$、 どこ$x > a$、そしてそれを要求します$x$分割する$a^2$。 そのようなものを選択すると、$x$、対応する$b$は$x - a$。 最小化$b$を最小化するのと同じです$x$の対象となる$x > a$そして$x \mid a^2$。 

問題は次のようになります: の最小の約数を見つけます$a^2$それは厳密にはより大きいです$a$。 

ブルーフォースはすべてをチェックします$x$から$a+1$に$a^2$、の割り算をテストします$O(1)$、それは不可能です。 代わりに、次の約数を生成します。$a^2$因数分解によって$a$そして素数から約数を構築します。 

以来$a \le 10^9$、それぞれを因数分解します$a$トライアル部門を経て、$\sqrt{a}$全体的には十分に速いです$t \le 10^4$実際には、その素因数分解から約数を列挙できます。$a^2$効率的に。 次に、次の値を超える最小の約数を選択します。$a$。

 ## アルゴリズムのチュートリアル

 有効な候補が約数であるという還元を使用します$x$の$a^2$、そして私たちはそのような最小のものを望んでいます$x$それはより大きい$a$。 

1.因数分解$a$素数に$p_1^{e_1} p_2^{e_2} \cdots$。 このステップが必要となるのは、$a^2$これらの指数の 2 倍に直接依存します。 
2. の指数のリストを作成します。$a^2$となり、$p_i^{2e_i}$。 の構造$a^2$すべての有効な候補者を完全に決定します$x$。 
3. すべての約数を生成します。$a^2$各素数を選択して再帰的に$p_i$からの指数$0$に$2e_i$。 各組み合わせにより 1 つの約数が得られます。 
4. 生成された各約数について$x$と比較してください$a$。 もし$x > a$、それは答えの有効な候補です。 これらの値の最小値を追跡します。 
5. 最良のものを変換する$x$の中へ$b = x - a$、必要な出力が得られます。 

約数を検索する背後にある推論$a^2$それは、元の条件をモジュラー変換すると、問題が完全に次の可分性構造に崩壊するということです。$a^2$、への依存を取り除く$b$検索中。 

### なぜ効果があるのか

 変換により、元の条件が次と同等であることがわかります。$a+b \mid a^2$。 すべての有効な$b$約数に相当する$x = a+b$の$a^2$、逆にすべての約数$x > a$の$a^2$有効な結果を生成します$b = x-a$。 このような約数をすべて 1 回だけ列挙し、最小のものを取得するため、$x$、必然的に可能な限り最小のものを取得します$b$。 すべての解は次の約数としてエンコードされるため、有効な解が失われることはありません。$a^2$、割り算が直接適用されるため、無効な候補は含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def factorize(n):
    res = {}
    d = 2
    while d * d <= n:
        while n % d == 0:
            res[d] = res.get(d, 0) + 1
            n //= d
        d += 1
    if n > 1:
        res[n] = res.get(n, 0) + 1
    return res

def gen_divs(i, primes, exps, cur, res):
    if i == len(primes):
        res.append(cur)
        return
    p = primes[i]
    for e in range(exps[i] + 1):
        gen_divs(i + 1, primes, exps, cur * (p ** e), res)

def solve_one(a):
    fac = factorize(a)
    primes = list(fac.keys())
    exps = [fac[p] * 2 for p in primes]  # for a^2

    divs = []
    gen_divs(0, primes, exps, 1, divs)

    ans_x = None
    for x in divs:
        if x > a:
            if ans_x is None or x < ans_x:
                ans_x = x

    return ans_x - a

def main():
    t = int(input())
    for _ in range(t):
        a = int(input())
        print(solve_one(a))

if __name__ == "__main__":
    main()
```コードは因数分解から始まります$a$、解全体は次の約数の構築に依存しているため、$a^2$。 の`factorize`関数は試行除算を実行しますが、これは制約に対して十分です。 

の`gen_divs`関数はすべての約数を構築します$a^2$素数指数に対する再帰を使用します。 各再帰的分岐は、指定された素数を 0 からその指数の 2 倍まで含める回数を選択します。$a$。 

すべての約数を生成した後、ソリューションは次の値を超える最小の約数をスキャンします。$a$。 引き算`x - a`除数を必要な値に変換し直します$b$。 

実装の微妙な点は、累乗を繰り返し再構築することを避けるために、再帰では乗算累積を慎重に渡す必要があることです。 これにより、一般的な制約に対して十分な効率の除数生成が維持されます。

 ## 特殊なケース

 のために$a = 2$、 我々は持っています$a^2 = 4$。 約数は$1, 2, 4$。 2 より大きい最小値は 4 です。$b = 2$。 アルゴリズムは、すべての約数を正しく列挙します。$4$そして選択します$4$。
