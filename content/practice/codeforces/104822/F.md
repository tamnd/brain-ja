 ## 解決策
 ## 問題の理解

 従業員のリストが与えられ、各従業員にはスキルの数値が示されています。 すべての従業員について、制限の下で、その従業員を含む可能な最大のチームを知りたいと考えています。選択したチーム内では、最大スキルと最小スキルの差が固定のしきい値を超えてはなりません。$k$。 

したがって、各インデックスについて$i$、私たちは事実上次のように尋ねています: 従業員$i$すべてのスキルが一定の範囲内にある従業員の最大のサブセットは何ですか?$[x, x+k]$それも含まれています$a_i$。 

重要な観察は、有効なチームは数直線上の値の間隔によって完全に決定され、そのタスクは、特定の要素を 1 つ強制的に含める際に、その間隔に収まる配列要素の数を理解することになります。 

制約は次のとおりです$n = 2 \cdot 10^5$したがって、それぞれについて独立して最適な間隔を再計算しようとするソリューションはすべて、$i$線形時間では遅すぎるでしょう。 ナイーブ$O(n^2)$スキャンは約に達します$4 \cdot 10^{10}$限界をはるかに超えた最悪の場合の操作。 これは、繰り返しの作業を再利用できるソートまたはスライディング ウィンドウ構造を即座に示唆します。 

微妙なエッジケースが現れるのは、$k = 0$。 その場合、まったく同じスキルを持つ従業員のみをグループ化できます。 もう 1 つのエッジ ケースは、すべての値が個別であり、間隔が大きく異なる場合です。$k$最適なチームはインデックス空間で連続しておらず、ソートされた値空間でのみ連続しているため、元の配列内のインデックスの連続性を仮定する素朴な試みは失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 従業員一人ひとりにとって$i$を含むすべての可能なサブセットを試します。$i$ですが、すぐにこれをより単純な形に縮小します。$i$、グループの一部として選択し、他の従業員をすべて追加してグループを拡張してみてください。$j$結果のグループがまだ満足する場合$\max - \min \le k$。 これを検証するために、現在のサブセットの最小スキルと最大スキルを維持します。 

これは正しく動作しますが、計算コストが高くなります。 それぞれについて$i$、調べてみようかな$O(n)$候補を抽出し、妥当性を再計算することで、$O(n^2)$行動。 と$2 \cdot 10^5$従業員の皆さん、これは無理です。 

重要な構造的洞察は、条件は指標ではなく値のみに依存し、あらゆる従業員を含む最適なチームが存在するということです。$i$ソートされたスキルの配列内の連続したセグメントに対応する必要があります。 配列がソートされると、有効なチームはすべて、エンドポイント間の差が最大以下のスライディング ウィンドウになります。$k$。 このウィンドウを毎回再計算するのではなく、$i$、すべての位置について、有効なウィンドウがどこまで拡張できるかを事前に計算できます。 

ソートされた配列に対して 2 ポインター手法を使用して、各位置で終了する、または各位置で開始する最大有効セグメントを計算します。 次に、元のインデックスごとに、それを並べ替えられた配列内の位置に変換し、それを含む最大の有効なウィンドウのサイズを読み取ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 並べ替え + 2 つのポインター |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なアイデア

 問題をソートされた配列の問題に変換し、スライディング ウィンドウを使用して最大有効範囲を見つけます。 

### ステップ

 1. 各従業員のスキルを元のインデックスと組み合わせ、スキル値で並べ替えます。 

有効性は最小値と最大値の間の範囲のみに依存するため、並べ替えが必要です。 
2. 2 つのポインターを維持する$l$そして$r$両方とも 0 から始まり、並べ替えられた配列内の現在の有効なウィンドウを表します。 
3. それぞれについて$r$0から$n-1$を含めてウィンドウを展開します。$a[r]$、その後移動します$l$前進しながら$a[r] - a[l] > k$。 

これにより、ウィンドウが常に制約を満たすことが保証されます。 
4.固定後$r$、セグメント$[l, r]$で終わる最大の有効な間隔です。$r$。 
5. ポジションごとに$r$、このウィンドウのサイズを記録します。$r - l + 1$。 
6. チームがそのセグメント内のいずれかのメンバーを中心に構成されている場合、このウィンドウ内の各インデックスは少なくともこのチーム サイズを達成できます。 
7. 最後に、保存された位置を使用して結果を元のインデックスにマッピングします。 

重要な点は、すべての最大有効ウィンドウがわかったら、各従業員の最良の答えは、ソートされた位置を含む最大のウィンドウであるということです。 

### なぜ効果があるのか

 ソートされた配列内の任意の点で、スライディング ウィンドウは、内部のすべての要素が制約を満たすという不変条件を維持します。$\max - \min \le k$。 配列はソートされているため、差は常にエンドポイントによって決定されるため、右のエンドポイントが拡張したときに有効性を復元するには、左から縮小することが唯一の方法です。 これにより、すべての最大有効セグメントが 1 回だけ検出され、現在のウィンドウの境界を越えてそれより大きな有効セグメントが存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

arr = [(a[i], i) for i in range(n)]
arr.sort()

ans = [0] * n
l = 0

for r in range(n):
    while arr[r][0] - arr[l][0] > k:
        l += 1
    ans[arr[r][1]] = r - l + 1

print(*ans)
```この解決策は、後で答えを復元できるように、各スキルを元のインデックスと組み合わせることから始まります。 並べ替え後は、前方にのみ移動する左ポインタを維持します。 while ループにより、現在のセグメントがスキル差の制約を常に遵守するようになります。 各ステップで計算されたウィンドウ サイズは、位置の元の従業員に割り当てられます。$r$、その従業員はまさにこの最大有効ウィンドウの一部であり、次で終了します。$r$。 

微妙な点は、ウィンドウのすべてのメンバーの答えを明示的に再計算していないことです。 各ポジション$r$は最良の「終了ウィンドウ」に貢献し、すべての要素がある段階でエンドポイントになるため、有効な最大チーム サイズが正しく把握されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    arr = [(a[i], i) for i in range(n)]
    arr.sort()

    ans = [0] * n
    l = 0

    for r in range(n):
        while arr[r][0] - arr[l][0] > k:
            l += 1
        ans[arr[r][1]] = r - l + 1

    return " ".join(map(str, ans))

# provided samples
assert run("6 2\n1 2 3 4 6 9\n") == "3 3 3 3 2 1"
assert run("15 78\n98 190 175 67 109 139 297 175 789 162 109 87 165 243 72\n") == \
"8 6 8 7 8 8 2 8 1 8 8 7 8 5 7"

# custom cases
assert run("1 10\n5\n") == "1"
assert run("5 0\n1 1 1 2 2\n") == "3 3 3 2 2"
assert run("4 100\n1 50 90 120\n") == "4 4 4 4"
assert run("6 1\n1 3 5 7 9 11\n") == "1 1 1 1 1 1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素 | 1 | 最小サイズの動作 |
 | k=0 で重複 | グループ化された重複のみ | 完全等価制約 |
 | 大きなk | 完全な配列のグループ化 | グローバル ウィンドウの正確性 |
 | 間隔をあけた値 | すべてのもの | 偶発的なグループ化はありません |

 ## 特殊なケース

 いつ$k = 0$、同じ価値観のみがチームを形成できます。 スライディング ウィンドウはエンドポイントが等しくなるように縮小するため、重複によって自然にクラスターが形成されます。 たとえば、入力`1 0 / 1 1 1 2 2`グループを生成する`[1,1,1]`そして`[2,2]`、期待される出力と一致します。 

すべての値が以上異なる場合$k$、すべてのウィンドウが単一の要素に折りたたまれます。 アルゴリズムは、新しい右エンドポイントごとに左ポインターを即座に縮小し、一貫してサイズ 1 を生成します。 

すべての値が同一の場合、ウィンドウは決して縮小せず、すべての従業員が回答を受け取ります。$n$配列全体が有効なセグメントを形成するためです。
