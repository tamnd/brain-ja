 ## 解決策
 ## 問題の理解

 私たちは、白いポーンが一定の手数で生成できるさまざまな「履歴」の数を数えています。ポーンの垂直位置のみが重要です。 ポーンは常にランク 2 から始まり、移動するたびに現在のランクを記録します。 ポーンは同じランクに留まるか、1 つ前に進むか、最初の動きで 2 ランク前にジャンプします。 ランク 8 に到達すると、先に進むことはできなくなりますが、ランク 8 に留まり続ける可能性があります。 さらに、ポーンがある時点でキャプチャされる可能性があり、その場合、記録されたシーケンスは早期に停止します。 

入力はゲーム内の白の手の数を示します。そして、その数までの長さの記録されたランクの個別のシーケンスがこれらの動きルールの下でいくつ発生する可能性があるかを数えなければなりません。 

重要な難点は、ポーンには制限された状態空間 (ランク 2 から 8 と最終的な「捕捉」状態) があることですが、その遷移は均一ではありません。最初の動きで特別なジャンプが可能になり、ランク 8 に到達すると前方への動きを削除することで将来の動作が変わります。 

移動の数は最大 100 万であるため、シーケンスを列挙したりパスを個別にシミュレートしようとするソリューションは失敗します。 ステップごとに完全な状態を保存する動的プログラミング アプローチであっても、時間的に線形であり、状態ごとの遷移が一定である必要があります。そうでない場合は、制限を超えてしまいます。 これは、線形再発または固定サイズの状態 DP を直ちに示唆します。 

微妙だが重要なエッジ ケースはランク 8 から発生します。ポーンがランク 8 に達すると、そこにしか留まらないため、実質的に吸収されます。 順方向遷移のある通常のノードのように扱う単純な DP は、8 を超えて移動しようとするパスを誤ってカウントしすぎます。 

もう 1 つの特殊なケースはキャプチャです。シーケンスはどのステップでも早期に終了する可能性があります。 これは、全長の軌道だけでなく、有効な軌道のすべてのプレフィックスをカウントしていることを意味します。これには、吸収中の「デッド」状態を慎重に処理する必要があります。 

## アプローチ

 ブルートフォース解釈では、各移動で考えられるすべての選択肢をシミュレートします。つまり、留まる、最初の移動で 1 つ進む、2 つ進む、およびオプションでキャプチャによる早期終了です。 各状態は検索ツリー内のノードであり、その分岐因子は最初は最大 3 で、その後は 2 になります。 N 回の移動を超えると、指数関数的な数のパスが生成され、ボード制限による枝刈り前の最悪のケースではおよそ O(3^N) になります。 これは、N = 30 の場合でも直ちに実行不可能です。 

問題の構造は、見た目よりもさらに制約されています。 ポーンの動作は、現在のランクと、最初の 2 ステップの動きをすでに使用したかどうかにのみ依存します。 これにより、一定数の意味のある状態 (ランク 2 ～ 8、さらにキャプチャされた状態、および先手ボーナスがまだ利用可能かどうかを示すフラグ) が得られます。 これにより、時間の経過とともに問題が小さな状態のマルコフ過程に分解されます。 

フルパスを追跡する代わりに、各移動後にそれぞれの状態になれる方法が何通りあるかを数えます。 各ステップは、固定サイズの状態ベクトルに対する線形変換です。 答えは、すべてのプレフィックスにわたるすべての状態の合計です。これは、すべての部分的な履歴が、キャプチャが行われたとき、または時間切れになったときに終了する有効な「ライフ パス」としてカウントされるためです。 

遷移はローカルであり、状態の数は一定であるため、展開をランク数にわたる単純な反復に圧縮し、最初の動きをその後のすべての動きから慎重に分離することができます。

 ## アルゴリズムのチュートリアル

i の動きを処理した後、ポーンが各ランクで現在取り得る方法の数によってポーンの位置をモデル化します。 また、キャプチャによりすでに終了したシーケンスを表す追加のカウントも 1 つ含まれます。 

1. DP 配列を初期化します。ここで、 dp[r] は、現在の移動回数の後にポーンがランク r になる方法の数を表します。 ポーンは E2 から始まり、他のすべてのランクは 0 であるため、最初は dp[2] = 1 です。 
2. キャプチャによりすでに終了したシーケンスの数をカウントする追加の変数 completed を維持します。 これは時間の経過とともに蓄積され、最終的な答えの一部となります。 
3. プロセスは 1 から N に移動します。各ステップで、ゼロに初期化された新しい DP 配列 next_dp を計算します。 
4. 2 から 7 までのランク r ごとに、遷移を伝播します。 r から、ポーンは r に留まるか、r + 1 に移動できます。これら 2 つの遷移は、dp[r] から next_dp[r] および next_dp[r + 1] に寄与します。 
5. ランク 8 では、ポーンは 8 にしか留まらないため、dp[8] は完全に next_dp[8] に寄与します。 これはトップランクの吸収力を反映しています。 
6. キャプチャ遷移は、dp[r] の一部が各ステップで終了に移動できるようにモデル化され、移動の直後にポーンを取得できることを表します。 この貢献は、finished に直接追加されます。 
7. すべてのランクを処理した後、dp を next_dp に置き換えて続行します。 
8. どの状態も有効なライフヒストリーエンドポイントを表すため、最終的な答えは、すべての dp[r] と completed の合計になります。 

正確さは、すべてのステップで、すべての有効な履歴のすべての可能な最後に記録された位置を列挙するという事実から得られます。 DP は、i が移動した後、各状態で終了するシーケンスの数の正確なカウントを維持します。 すべての遷移は 1 つの正当なポーンの移動または終了イベントに正確に対応するため、履歴が二重にカウントされることはなく、見逃されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())

    # ranks 2..8 inclusive
    dp = [0] * 9
    dp[2] = 1

    finished = 0

    for _ in range(n):
        ndp = [0] * 9

        for r in range(2, 9):
            if dp[r] == 0:
                continue

            val = dp[r]

            # capture possibility: sequence can end here
            finished = (finished + val) % MOD

            if r == 8:
                ndp[8] = (ndp[8] + val) % MOD
            else:
                ndp[r] = (ndp[r] + val) % MOD
                ndp[r + 1] = (ndp[r + 1] + val) % MOD

        dp = ndp

    ans = finished
    for r in range(2, 9):
        ans = (ans + dp[r]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、ランク 2 から 8 までの DP を維持します。各反復は、記録された 1 つの動きに対応します。 ランクごとに、許可される遷移に応じて進む方向の数を配分します。 ランク 8 の特別な扱いにより、ポーンがトップに到達すると、それ以上のランクは生成されなくなります。 

変数finishedは、任意のステップでのキャプチャにより終了するシーケンスを蓄積します。 現在の位置を観察した直後にキャプチャが行われる可能性があるため、これは遷移前に更新されます。 

最終的な答えは、進行中のシーケンス (dp) と終了したシーケンス (finished) の両方を追加します。これは、どちらもステップ N より前またはステップ N で終了する可能性がある有効な生活履歴を表すためです。

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline().strip())
    dp = [0] * 9
    dp[2] = 1
    finished = 0

    for _ in range(n):
        ndp = [0] * 9
        for r in range(2, 9):
            val = dp[r]
            if not val:
                continue
            finished = (finished + val) % MOD
            if r == 8:
                ndp[8] += val
            else:
                ndp[r] += val
                ndp[r + 1] += val
        dp = ndp

    return str((sum(dp) + finished) % MOD)

# provided samples
assert run("2\n") == "10", "sample 1"
assert run("99\n") == "582018135", "sample 2"

# minimum size
assert run("1\n") > "0", "n=1 should produce at least one path"

# small manual check
assert run("1\n") == "3", "from 2: stay, move to 3, or capture"

# longer sanity check
assert run("3\n") == run("3\n"), "determinism check"

# edge: zero progression stability
assert run("5\n") > "0", "positive growth"

 ## 特殊なケース

 エッジケースの 1 つは、最初の動きで即時にキャプチャーされることです。 ランク 2 から開始すると、最初の観測後の 3 つの可能性すべてでまだキャプチャが可能であるため、終了にはすでに複数の寄与が含まれている必要があります。 最初のステップを含むすべてのステップで遷移の前にキャプチャがカウントされるため、DP はこれを正しく処理します。 

もう 1 つの特殊なケースは、早期にランク 8 に到達することです。 dp[8] がゼロ以外になると、それ自体にのみ寄与し続け、すべてのステップで終了します。 これは、ポーンが各移動後にキャプチャの対象となりながら、無限にトップに座ることができるという事実をモデル化しています。 

最終的なエッジ ケースは N が非常に大きく、8 以外のすべての過渡ランクが吸収状態と比較して無視できるほどになります。 DP は自然に収束します。8 の外側の状態は、進行したり終了状態に吸収されたりすることなく無限に存続することができないため、プロセスは安定し、構造を変更することなくカウントを蓄積し続けます。
