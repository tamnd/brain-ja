 ## 解決策
 ## 問題の理解

 各テスト ケースは整数の長方形グリッドを示し、各セルは負または正の「美味しさ」値を表します。 このようなグリッドごとに、任意のサイズの正方形のサブグリッドを選択し、含まれるすべてのセルの合計ができるだけ大きいサブグリッドを見つけることがタスクとなります。 答えはその最大合計の値だけであり、平方そのものではありません。 

重要な自由度は、正方形の辺の長さを 1 からグリッドの小さい寸法までの任意の長さにすることができ、境界内に完全に収まる限り、グリッド内のどこにでも配置できることです。 

制約は、複雑さに対する私たちの考え方を変えるような構造になっています。 各グリッドは最大 500 x 500 ですが、テスト ケース全体の高さの合計は最大 500 です。これは、一度に多数の大きなグリッドに直面することは決してないことを意味します。 代わりに、1 つの大きなグリッドまたは複数の小さなグリッドを使用することもできますが、全体として処理される行の総数には上限があります。 

これにより、単一のグリッド次元で立方体であるソリューションは許容範囲内になりますが、大まかなものよりはさらに悪いものになります。$O(500^3)$最悪の場合のグリッドごとに危険です。 すべての正方形の合計を個別に再計算する単純なアプローチでは、作業を頻繁に繰り返すことになります。 

正確性を保つためには、いくつかの特殊なケースが重要です。 

1 つのセルを除いてすべての値が負のグリッド。 1 × 1 の正方形は常に許可されるため、答えはその単一のセルでなければなりません。 たとえば:

 入力:```
1
2 2
-5 -6
-7 10
```出力：```
10
```より大きな正方形のみを考慮したり、より大きな領域がより良いと仮定したりする単純な解決策は、ここでは失敗します。 

もう 1 つのエッジ ケースは、最適な正方形のサイズが最大ではなく、1 行 1 列でもない場合です。次に例を示します。```
2
3 3
1 -2 1
-2 10 -2
1 -2 1
```最適な正方形は完全な 3 × 3 グリッドですが、多くの場合、最適な正方形はより大きな行列内の 2 × 2 になる可能性があります。 どのソリューションでも、すべてのサイズを正確に比較する必要があります。 

## アプローチ

 直接的なアプローチは、グリッド内の可能なすべての正方形を列挙することです。 左上隅ごとに、可能な辺の長さごとに、その正方形の合計を最初から計算します。 各正方形を単純に計算するとコストがかかります$O(k^2)$したがって、すべての位置とサイズにわたって、これはおおよそ次のようになります。$O(n^4)$最悪の場合、グリッドごとに。 と$n = 500$、これはまったく不可能です。 

最初の改善点は、合計を最初から再計算することを避けることです。 2D プレフィックス合計を使用すると、前処理後に一定時間で部分行列の合計を計算できます。 これにより、1 つの正方形を評価するコストが削減されます。$O(1)$。 

この最適化後でも、可能なすべての正方形を考慮する必要があります。 辺の長さが固定の場合$k$をスライドさせます。$k \times k$グリッド上にウィンドウを設定し、それぞれの合計を計算します。$O(1)$。 がある$O(nm)$あたりのポジション$k$、そして最大$O(\min(n, m))$の選択肢$k$。 これにより、$O(nm \cdot \min(n, m))$グリッドごとのソリューション。合計入力サイズの制約を考慮すると、これは許容可能です。 

重要な観察は、セグメント ツリーや Kadane スタイルの 2D 圧縮のような高度な構造は必要ないということです。これは、プレフィックスの合計により、各候補平方評価がすでに定数時間に短縮されており、総行に対するグローバルな制約により候補の総数が管理可能であるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各正方形を再計算) |$O(n^4)$|$O(1)$| 遅すぎる |
 | 接頭辞の合計 + 平方数を列挙する |$O(nm \cdot \min(n,m))$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッドを個別に処理します。 

1. 各エントリが左上隅からそのセルまでの四角形内のすべての値の合計を格納する 2D プレフィックス合計配列を構築します。 これにより、任意のサブ四角形に対する定数時間クエリが可能になります。 
2. 1 からグリッドの最小寸法までの可能なすべての正方形の辺の長さについて繰り返します。 各サイズは、異なる正方形の候補ファミリーを表します。 
3. 辺の長さを固定するには、グリッド内の有効な左上のすべての位置に正方形をスライドさせます。 各位置は一意の正方形を定義します。 
4. 各正方形について、プレフィックス合計テーブルを使用して定数時間でその合計を計算します。 これにより、内和を繰り返し再計算する必要がなくなります。 
5. すべてのサイズのすべての正方形にわたって発生する最大合計を追跡します。 
6. すべての構成を確認した後、最終的な最大値を出力します。 

### なぜ効果があるのか

 プレフィックス合計テーブルは、すべての平方和クエリが正確であり、一定時間で計算されることを保証します。 考えられるすべての正方形がその左上隅と辺の長さを通じて正確に 1 回チェックされるため、候補が見逃されることはありません。 このアルゴリズムは、サイズや位置に関する貪欲な仮定に依存しないため、すべての有効な正方形を網羅的かつ効率的に列挙することによって最大値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        ps = [[0] * (m + 1) for _ in range(n + 1)]

        for i in range(n):
            row_sum = 0
            for j in range(m):
                row_sum += a[i][j]
                ps[i + 1][j + 1] = ps[i][j + 1] + row_sum

        def get_sum(x1, y1, x2, y2):
            return ps[x2][y2] - ps[x1][y2] - ps[x2][y1] + ps[x1][y1]

        ans = -10**18
        limit = min(n, m)

        for k in range(1, limit + 1):
            for i in range(n - k + 1):
                for j in range(m - k + 1):
                    s = get_sum(i, j, i + k, j + k)
                    if s > ans:
                        ans = s

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、標準の 2D プレフィックス合計を構築し、包含と除外を使用して四角形の合計が一定時間内に計算されるようにします。 機能`get_sum`は、ループ内での合計の繰り返しを防止するコアの抽象化です。 

辺の長さ、行の位置、列の位置の三重ループ構造は意図的です。 これらのループを交換しても正確さには影響しませんが、キャッシュの動作にわずかに影響を与える可能性があります。 選択した順序によりロジックが単純になり、インデックス付けの間違いが最小限に抑えられます。 

よくある落とし穴は、プレフィックスのインデックス作成が正しくないことです。 実装では、次のサイズのパディングされたプレフィックス配列が使用されます。$(n+1) \times (m+1)$したがって、すべての四角形クエリは負のインデックスと境界チェックを回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for _ in range(T):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        ps = [[0] * (m + 1) for _ in range(n + 1)]
        for i in range(n):
            row = 0
            for j in range(m):
                row += a[i][j]
                ps[i + 1][j + 1] = ps[i][j + 1] + row

        def get(x1, y1, x2, y2):
            return ps[x2][y2] - ps[x1][y2] - ps[x2][y1] + ps[x1][y1]

        ans = -10**18
        lim = min(n, m)
        for k in range(1, lim + 1):
            for i in range(n - k + 1):
                for j in range(m - k + 1):
                    ans = max(ans, get(i, j, i + k, j + k))

        out.append(str(ans))

    return "\n".join(out)

## 特殊なケース

 1 つのセルを除くすべてが負の値を持つグリッドは、アルゴリズムが 1 行 1 列の正方形を適切に考慮しているかどうかをテストします。 プレフィックス合計アプローチでも k = 1 が評価されるため、最大の単一セルが正しく選択されます。 

最良の答えが行列全体であるグリッドでは、より大きな正方形が無視されなくなります。 アルゴリズムは min(n, m) までのすべての k を反復するため、有効な場合は完全なグリッドが明示的に評価されます。 

符号が混在しているが局所的なピークが強いグリッドは、スライディング ウィンドウが局所的最大値を正しくキャプチャしているかどうかをチェックします。 すべての位置がすべての正方形サイズで評価されるため、領域がスキップされることはなく、プレフィックスの合計によって各候補の評価の正確さが保証されます。
