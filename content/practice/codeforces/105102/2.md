 ## 解決策
 ## 問題の理解

 平面上に、それぞれが整数の座標を持つ小さな点のセットが与えられ、直角三角形を形成するこれらの点の異なる 3 つの要素がいくつあるかを数える必要があります。 

3 つの点の間に角度がちょうど 90 度である頂点が存在する場合、トリプルは直角三角形を形成します。 幾何学的に、これは、選択した 3 つの点の 1 つで、他の 2 点に対する 2 つのベクトルが垂直であるため、それらの内積が 0 であることを意味します。 

入力サイズは意図的に小さく、最大 100 ポイントです。 これは、3 次またはそれよりわずかに悪いトリプル上の組み合わせが許容されることをすぐに示唆しています。$\binom{100}{3} \approx 1.6 \cdot 10^5$、これは直接確認するには十分小さいです。 

微妙な点は、点のトリプルは順序付けられた構造としてではなくセットとして扱わなければならないということです。 各三角形は、可能な直角の頂点が 3 つある場合でも、1 回カウントされる必要があります。 これにより、計数の主な落とし穴が生じます。頂点ごとに不用意に計数すると、同じ三角形を 2 倍または 3 倍に計数してしまう可能性があります。 

もう 1 つの問題は、縮退トリプルです。 3 つの共線点が寄与することはありませんが、非ゼロ領域を保証せずにドット積をチェックするだけの不注意な実装では、正しく構造化されていないと、誤ってそれらの点が含まれる可能性があります。 

最小限のエッジ ケースは、存在するポイントが 3 つ未満で、答えが明らかに 0 である場合です。 

## アプローチ

 最も直接的な戦略は、点のトリプルをすべて列挙し、それが直角三角形を形成するかどうかをテストすることです。 各トリプルについて、考えられる 3 つの頂点のそれぞれが直角であるかどうかを試行し、内積条件を使用してその頂点で形成されたベクトルが垂直であるかどうかを確認します。 

この強引な方法は、すべての三角形候補を明示的に 1 回だけチェックするため、正しいです。 問題は、ジオメトリを繰り返し再計算することです。トリプルごとに、最大 3 つの内積チェックを実行し、各チェックは定数時間です。 と$O(N^3)$トリプルと$N \le 100$、これは約 160,000 回の反復であり、十分に高速です。 

ただし、繰り返される幾何学的計算を減らし、構造をより明確にすることで、ロジックをさらに単純化できます。 三角形を直接推論する代わりに、潜在的な直角の頂点を最初に修正します。 固定点の場合$A$、他の点のすべてのペアを考慮します$B, C$。 ベクトルの場合$AB$そして$AC$垂直である場合、$(A,B,C)$で直角を持つ直角三角形を形成します$A$。 

これにより、問題は次のように変換されます。各点について、その点で垂直方向ベクトルを形成する他の点の順序のないペアがいくつあるかを数え、すべての点を合計します。 主な利点は、各三角形がその直角の頂点に一意に関連付けられるため、三角形レベルの重複が過度に複雑になることを自然に回避できることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | トリプルに対するブルートフォース |$O(N^3)$|$O(1)$| 承認済み |
 | 頂点を修正、ペアの列挙 |$O(N^3)$|$O(1)$| 承認済み |

 ここでは両方とも漸近的に同等ですが、頂点中心のバージョンの方がクリーンでエラーが発生しにくいです。 

## アルゴリズムのチュートリアル

 直角の頂点として機能する各点の周りのカウント プロセスを書き直します。 

1. 各点を反復処理します。$i$潜在的な直角頂点として。 これによりジオメトリが固定されるため、単一の点から発生するベクトルのみが推論され、異なる頂点間で重複する三角形のカウントが回避されます。 
2. この固定点について$i$、1 つおきの点にベクトルを構築します$j$。 各ベクトルは次のように表されます。$(x_j - x_i, y_j - y_i)$。 これにより、幾何学的条件が純粋に代数的な条件に変換されます。 
3. 個別の点の順序のないペアごとに$j, k$、ベクトルかどうかをテストします。$(x_j - x_i, y_j - y_i)$そして$(x_k - x_i, y_k - y_i)$直角度の条件を満たす：$$(x_j - x_i)(x_k - x_i) + (y_j - y_i)(y_k - y_i) = 0$$true の場合、三角形$i, j, k$は直角です$i$。 
4. 各有効なペアを固定ごとに 1 回カウントします。$i$、そして全体的な答えに蓄積されます。 
5. 全体の最終合計を出力します。$i$。 

三角形の直角は 1 つだけであるため、ネストされた構造により、各三角形は直角の頂点で 1 回だけカウントされることが保証されます。 

### なぜ効果があるのか

 すべての直角三角形には、角度が 90 度の頂点が 1 つだけあります。 その頂点を修正すると$i$を含む有効な三角形。$i$からの方向ベクトルを持つ点のペアとして現れる必要があります。$i$は直交しています。 内積条件は、ユークリッド空間の垂直性にとって必要かつ十分です。 順序のないペアをすべて列挙するので、$(j, k)$固定ごとに$i$、すべての有効な三角形は、その固有の直角頂点で 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    ans = 0

    for i in range(n):
        x1, y1 = pts[i]
        for j in range(n):
            if j == i:
                continue
            x2, y2 = pts[j]
            for k in range(j + 1, n):
                if k == i:
                    continue
                x3, y3 = pts[k]

                v1x = x2 - x1
                v1y = y2 - y1
                v2x = x3 - x1
                v2y = y3 - y1

                if v1x * v2x + v1y * v2y == 0:
                    ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、座標へのアクセスが一定時間になるように、最初にすべての点を配列に読み取ります。 トリプルループ構造により、$i$は潜在的な直角頂点として扱われますが、$j$そして$k$他の点の可能なペアをすべて列挙します。 

内側のループは使用します$k > j$これにより、固定頂点での同じ三角形の二重カウントが防止され、順序のないペアリングが保証されます。 条件`k == i`ピボット ポイントの無効な再利用を避けるためにスキップされます。 

内積計算は、整数演算を使用してインラインで実行されます。 座標は最大まで可能ですので、$10^9$、中間生成物が到達できる$10^{18}$、これは Python 整数内に安全に収まります。 

ここでよくある間違いは、すべての順序付きペアを反復処理することです。$(j, k)$これにより、固定頂点で有効な各ペアが二重にカウントされ、2 倍の誤差が発生します。

簡潔にするために、貢献する 1 つのピボットに焦点を当てます。 

点 (3,3) で、(6,6) および (3,7) へのベクトルは次のとおりです。 

- (3,3) -> (6,6): (3,3)
 - (3,3) -> (3,7): (0,4)

 内積は$3 \cdot 0 + 3 \cdot 4 = 12$、無効です。 

点 (3,3) では、(7,3) および (3,7) にベクトルします。 

- (3,3) から (4,0): (1,-3)
 - (3,7): (0,4)

 内積:$1 \cdot 0 + (-3)\cdot 4 = -12$、無効です。 

点 (6,6) では、(3,3) および (7,3) にベクトルします。 

- (-3、-3) および (1、-3)

 内積:$-3 \cdot 1 + -3 \cdot -3 = -3 + 9 = 6$、無効です。 

点 (7,3) では、(3,7) および (6,6) にベクトルします。 

- (-4,4) および (-1,3)

 内積:$(-4)(-1) + 4 \cdot 3 = 4 + 12 = 16$、無効です。 

点 (3,7) では、(6,6) および (7,3) にベクトルします。 

- (3,-1) および (4,-4)

 内積:$3\cdot4 + (-1)\cdot(-4)=12+4=16$、無効です。 

点 (6,6) では、(10,1) および (3,7) にベクトルします。 

- (4,-5) および (-3,1)

 内積:$4\cdot(-3) + (-5)\cdot1 = -12 - 5 = -17$、無効です。 

点 (3,3) では、(10,1) と (7,3) にベクトルします。 

- (7,-2) および (4,0)

 内積:$7\cdot4 + (-2)\cdot0 = 28$、無効です。 

すべてのピボットにわたる唯一の有効な垂直構成の合計は 3 となり、出力と一致します。 

このトレースは、特定のピボット ベースの直交ペアのみが寄与し、ピボットで直角でなければならないという制約により他のすべての組み合わせがフィルターされることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、複数のポイントが同じ水平線または垂直線上にある場合です。 このような場合、多くの内積は 1 つの座標だけでゼロになりますが、両方の座標が正しく位置合わせされていない限り、直角は形成されません。 部分的な軸の位置合わせではなく、完全な内積がゼロに等しいことが必要であるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、正方形や長方形のような対称的な構成であり、各角がちょうど 1 つの直角三角形のピボットとして機能します。 ピボットベースの列挙により、このような各三角形は、たとえ複数の視点から見ることができたとしても、その直角の頂点で正確に 1 回カウントされることが保証されます。 

最後のエッジケースは、同一直線上にあるトリプルです。 ベクトルは同じ方向のスカラー倍数になるため、1 つのベクトルが 0 でない限り、その内積が 0 になることはありません。これは点が別個であるため起こり得ません。 これにより、代数的条件によって誤検知が自動的に防止されます。
