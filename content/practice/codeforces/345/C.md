 ## 解決策
 ## 問題の理解

 コンテストの日程の小さなリストが与えられます。 日付ごとに、その暦日がその月の 13 日であり、金曜日であるかどうかを判断する必要があります。 答えは単純に、両方の条件を満たすコンテスト開催日の数です。 

年の範囲は 1974 年から 2030 年で、日付の数は最大 10 です。これらの制約はわずかです。 すべてのクエリに対してかなりの量のカレンダー計算を実行するアルゴリズムであっても、制限内に問題なく収まります。 本当の課題は効率ではなく、閏年やさまざまな月の長さを含む特定の日付の曜日を正確に判断することです。 

よくある間違いは、日番号が 13 に等しいかどうかのみを確認することです。以下を考慮してください。```
1
2013-09-13
```正しい出力は次のとおりです。```
1
```2013 年 9 月 13 日は金曜日だったからです。 平日を無視すると、金曜日かどうかに関係なく、13 日ごとにカウントされます。 

もう 1 つの簡単な間違いは、閏年の扱いを誤ることです。 考慮する：```
1
2012-02-13
```正しい出力は次のとおりです。```
0
```2012 年がうるう年であることを忘れて平日を計算すると、間違った曜日が生成され、この日付が誤ってカウントされる可能性があります。 

3 番目の微妙なケースは、コンテストの日付が重複していることです。```
3
2012-01-13
2012-01-13
2012-01-13
```正しい出力は次のとおりです。```
3
```各コンテストは個別にカウントする必要があります。 この声明では、同日に複数のコンテストを行うことを明示的に許可しています。 

## アプローチ

 最も直接的な解決策は、指定された日付ごとに曜日を特定し、月の 13 日に金曜日が何日あるかを数えることです。 

平日を決定する強引な方法は、既知の基準日を選択し、目標日に達するまで毎日シミュレーションすることです。 これが機能するのは、平日が 7 日ごとに繰り返されるためです。 基準日が数十年も離れている場合、各クエリには数万日かかる可能性があります。 この問題の最大期間は約 56 年、つまり約 20,000 日です。 クエリが 10 個しかないので、これでもまったく問題ありませんが、必要以上に面倒です。 

重要な観察は、平日の計算にはよく知られた閉じた形式の公式があるということです。 日付範囲は固定されており小さいため、Zeller の合同を使用して特定の日付の曜日を直接計算できます。 この数式は、閏年と閏月の長さを算術的に自動的に処理し、シミュレーションを回避します。 

各入力日付について、最初に日の構成要素が 13 であるかどうかを確認します。そうでない場合、日付は 13 日の金曜日であってはなりません。 13 の場合は、Zeller の合同を使用して曜日を計算します。 この数式は曜日を表すコードを返し、そのコードが金曜日に対応する場合は日付をカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・D) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ここ、$D$参照日とクエリ日の間の日数です。 

## アルゴリズムのチュートリアル

 1. コンテストの日付の数を読み取ります。 
2. 日付文字列ごとに、年、月、日を抽出します。 
3. その日が 13 日ではない場合は、この日付をすぐにスキップします。 

月の日が 13 に等しくない限り、日付を 13 日の金曜日にすることはできません。 
4. ゼラーの合同を使用して曜日を計算します。 

1 月と 2 月の場合は、前年の 13 月と 14 月として扱います。 これは式の定義の一部です。 
5. しましょう$K$今世紀内の年であり、$J$ゼロベースの世紀になります。 
6. Zeller の公式を評価します。$$h = \left( q + \left\lfloor \frac{13(m+1)}{5} \right\rfloor + K + \left\lfloor \frac{K}{4} \right\rfloor + \left\lfloor \frac{J}{4} \right\rfloor + 5J \right) \bmod 7$$どこ$q$月の日です。 
7. ゼラーの番号付けでは、金曜日は次のとおりです。$h = 6$。 
8. もし$h = 6$、答えを増やします。 
9. すべての日付を処理した後、回答を印刷します。 

### なぜ効果があるのか

 ゼラーの合同式は、すべての有効なグレゴリオ暦の日付をその曜日にマッピングする数学的に証明された公式です。 1 月と 2 月を前年の月 13 月と 14 日に変換する機能が導出に組み込まれており、うるう年の正しい処理が保証されます。 

このアルゴリズムは、日付が 13 に等しく、計算された曜日が金曜日に等しいという 2 つの条件が同時に成立する場合にのみ日付をカウントします。 平日の計算は有効な入力日付ごとに正しいため、カウントされる日付はすべて正真正銘の 13 日の金曜日となり、入力内の 13 日ごとの金曜日は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_friday_13(year, month, day):
    if day != 13:
        return False

    if month <= 2:
        month += 12
        year -= 1

    q = day
    K = year % 100
    J = year // 100

    h = (
        q
        + (13 * (month + 1)) // 5
        + K
        + K // 4
        + J // 4
        + 5 * J
    ) % 7

    return h == 6  # Friday in Zeller's congruence

def solve():
    n = int(input())
    ans = 0

    for _ in range(n):
        s = input().strip()
        y, m, d = map(int, s.split('-'))

        if is_friday_13(y, m, d):
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、平日の計算をヘルパー関数に分離します。 最初のチェックは、その日が 13 に等しいかどうかです。これにより、答えに決して寄与しない日付に対する不必要な計算が回避されます。 

見落としがちなのが1月と2月の月調整です。 ゼラーの合同式では、これらを前年の 13 か月と 14 か月として扱います。 この変換を忘れると、年の初め近くの曜日が正しくなくなります。 

すべての算術演算は、標準の Python 整数内に快適に収まります。 この式にはグレゴリオ暦の規則がすでに組み込まれているため、うるう年に対する特別な処理は必要ありません。
