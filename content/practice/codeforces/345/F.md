 ## 解決策
 ## 問題の理解

 入力は、カウントを含む通常の構造化形式では与えられません。 代わりに、国名と迷信のリストを交互に並べた小さなテキスト ファイルです。 

**で始まらない**行`* `は国の名前です。 で始まる行`* `は、最も最近見られた国に属する迷信です。 

国名は一意であることが保証されます。 迷信がまったくない国もあるでしょう。 課題は、どの迷信が最も多くの国で見られるかを見つけることです。 

厄介な点は、名前が正規化された形式で比較されることです。 大文字と小文字は無視する必要があり、単語間の複数のスペースは重要ではありません。 単語に分割した後、大文字と小文字を区別せずに単語シーケンスが同一である場合、2 つの名前は同じシーケンスを表します。 

例えば：```
Friday the   13th
friday   THE 13TH
```は同じ迷信を表しており、1 つのオブジェクトとして扱う必要があります。 

出力には、国の数が最大であるすべての迷信が含まれている必要があります。 名前は小文字で印刷し、一連の単語として辞書順に並べ替える必要があります。 

入力には最大 50 行が含まれ、各行には最大 50 文字が含まれます。 非効率的なソリューションであっても、数千文字しか処理できません。 課題はパフォーマンスではなく、データを正しく解析して正規化することです。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

一貫性のない間隔を考慮してください。```
A
* black   cat
B
* black cat
```正しい出力:```
black cat
```生の文字列を比較するソリューションでは、これらを異なる迷信として誤って扱うことになります。 

大文字の使用を変えることを検討してください。```
A
* Friday The 13th
B
* friday the 13th
```正しい出力:```
friday the 13th
```大文字と小文字を区別して比較すると、2 つの別々の迷信がカウントされます。 

迷信のない国を考えてみましょう。```
A
B
* lucky coin
```正しい出力:```
lucky coin
```パーサーはそれを認識する必要があります`B`新しい国を始めるとしても`A`迷信の項目はありませんでした。 

単語シーケンスの辞書編集的な順序を考慮してください。```
A

B
* apple
```どちらも 1 回発生するため、両方を出力する必要があります。```

zebra
```順序付けは正規化後に適用されます。 

## アプローチ

 ブルートフォース手法では、まずすべての国を解析し、国ごとに一連の迷信を保存します。 次に、すべての明確な迷信について、すべての国をスキャンし、その迷信がそこに存在するかどうかをテストします。 あれば`S`明確な迷信と`C`国々、これには必要です`O(SC)`解析後のメンバーシップチェック。 

実際の制約では、入力全体に最大 50 行が含まれるため、これはすでに簡単に適合します。 それでも、必要のない作業が実行されます。 

重要な観察は、必要な数量は単にそれぞれの迷信を含む国の数であるということです。 迷信の線を読み取って正規化すると、それがどの国に属するかがすでにわかります。 その迷信に対するグローバル カウンタをすぐに増やすことができます。 

問題ステートメントでは、国内のエントリが一意であることが保証されているため、各迷信は国ごとに最大 1 つのカウントに寄与します。 ファイル全体を処理すると、すべての迷信がその国の正確な頻度を示します。 

残りの作業は簡単です。 最大頻度を見つけ、その頻度を持つ迷信をすべて収集し、辞書順に並べ替えて印刷します。 

ここではどちらのアプローチも簡単に十分に高速ですが、カウントするアプローチの方が単純で、計算するよう求められている量に直接一致します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(SC) | O(S + エントリの合計) | 承認済み |
 | 最適 | O(総行数 · 行の長さ) | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力行を読み取ります。 
2. 辞書を管理する`cnt`正規化された迷信名を、それが含まれる国の数にマッピングします。 
3. 各行を順番に処理します。 
4. 行が次で始まる場合`* `、それは迷信を表します。 

先頭を削除して正規化します`* `、単語に分割し、すべての単語を小文字に変換し、単語を 1 つのスペースで結合します。 
5. インクリメント`cnt[normalized_name]`。 

すべての迷信エントリは正確に 1 つの国に属し、国内のエントリは一意であることが保証されているため、これは正しいです。 
6. 行が次で始まらない場合`* `, 国の名前です。 カウントするアクションは必要ありません。 
7. すべての行が処理された後、に格納されている最大値を計算します。`cnt`。 
8. カウントがこの最大値に等しいすべての迷信を収集します。 
9. 収集した名前を辞書順に並べ替えます。 
10. 1 行に 1 つずつ出力します。 

### なぜ効果があるのか

 正規化後は、同じ迷信のすべてのテキスト表現がまったく同じ文字列になります。 各迷信エントリは、正確に 1 つの国に 1 つの出現に寄与しており、国内で重複してエントリすることは声明によって禁止されています。 したがって、に格納されている値は、`cnt[x]`ファイル全体を処理すると、迷信が含まれる国の数が正確に計算されます。`x`。 

このアルゴリズムは、カウントがグローバル最大値 (必要な答えの定義) に等しい迷信を正確に出力します。 正規化された文字列を並べ替えると、必要な辞書編集順序が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize(s: str) -> str:
    return " ".join(s.lower().split())

def solve():
    lines = [line.rstrip("\n") for line in sys.stdin]

    cnt = {}

    for line in lines:
        if line.startswith("* "):
            superstition = normalize(line[2:])
            cnt[superstition] = cnt.get(superstition, 0) + 1

    best = max(cnt.values())

    ans = sorted(
        name for name, value in cnt.items()
        if value == best
    )

    sys.stdout.write("\n".join(ans))

solve()
```の`normalize`機能はソリューションの中心です。 電話をかける`split()`引数なしでは、任意の数の連続したスペースを 1 つの区切り文字にまとめます。 小文字に変換すると、大文字と小文字を区別しない比較が処理されます。 単一のスペースで結合すると、正規表現が作成されます。 

迷信の頻度のみが問題となるため、国名は解析後に無視されます。 この声明は、国名が明確であること、および国内の迷信項目が固有であることを保証するため、追加の簿記は必要ありません。 

よくある間違いは、電話をかけることです。`lower()`ただし、元の間隔は変更しないでください。 それから`"black cat"`そして`"black   cat"`依然として別の文字列として扱われます。 使用する`split()`に続く`" ".join(...)`この問題を回避します。 

もう 1 つの簡単な間違いは、正規化する前に並べ替えることです。 出力には小文字の標準形式が含まれている必要があるため、最初に正規化を実行し、正規化された文字列を辞書に保存する必要があります。
