 ## 解決策
 ## 問題の理解

 私たちには人々のネットワークが与えられており、どのペアの人々も双方向でお互いを知っているか、まったくお互いを知らないかのどちらかです。 この関係は、次のサイズの隣接行列としてエンコードされます。$n \times n$、ここで、`1`2 人が相互にメッセージを転送することを意味します。`0`彼らはそうしないことを意味します。 

メッセージは人物 1 から始まります。誰かが初めてメッセージを受信すると、接続しているすべての人にすぐにそれを転送します。 このプロセスは、友情グラフを塗りつぶすかのように続きます。 重要なルールは、各ユーザーが初めてメッセージを受信したときに、メッセージを 1 回だけ転送するということです。 

私たちは人です$n$、メッセージはそれ以上転送されません。 タスクは、メッセージを合計で何回受信するかを決定することです。これは、この伝播プロセスを通じて何人の異なる人々が私たちに到達できるかを意味します。 

これは基本的にグラフの到達可能性の問題です。 グラフは無向であり、最大 50 個のノードがあるため、比較的高価なグラフ走査手法でも安全です。 出力は、ノードに到達できる個別のノードの数です。$n$ノード1から始まるノードを除くパス経由$n$自体。 

重要な点は、複数の独立したチェーンをシミュレートしたり、パスを数えたりしていないことです。 3 つの異なるルートで最終的に同じ人からメッセージが届いた場合でも、その人からの受信は 1 回だけとしてカウントされます。 重要なのは、多重性ではなく、到達可能性です。 

単純な間違いは、このプロセスを 1 から 2 までのパスを数えるものと解釈することです。$n$。 たとえば、4 つのノードの完全接続グラフでは、1 から 4 までの複数の個別のパスがありますが、送信者ごとに 1 つのコピーしか受信しないため、答えは 3 であり、より大きなパス数ではありません。 

もう 1 つの間違いは、訪問したノードをマークせずに伝播をシミュレートすることです。 訪問したノードを追跡しないと、プロセスは同じ人を繰り返し再処理することになり、概念的な意味で過剰カウントや無限ループにつながる可能性があります。 

制約$n \le 50$両方であることを暗示します$O(n^2)$隣接関係の操作と完全な DFS または BFS は簡単です。 平$O(n^3)$フロイド-ウォーシャルのようなアプローチも機能しますが、不要です。 

## アプローチ

 ブルート フォース解釈では、メッセージの伝播を説明どおりに正確にシミュレートします。 人物 1 から開始してすべての人物を繰り返しスキャンし、接続が存在するたびにメッセージを前進させます。 新しい人がメッセージを受信するたびに、その人のつながりを再度スキャンします。 これは、新しいノードがアクティブ化されなくなるまで繰り返し緩和プロセスとして実装できます。 

これは拡散プロセスを直接模倣するため正しく機能しますが、新しくアクティブ化されたノードごとに隣接行列全体を繰り返し再スキャンすることから非効率になります。 最悪の場合、アクティベーションのたびに次のような事態が引き起こされます。$O(n)$スキャンすると、$O(n)$アクティベーション、与える$O(n^3)$単純な実装では動作が悪化する可能性があり、非効率的に実装された場合はさらに悪化します。 

重要な観察は、転送プロセスがまさにグラフの走査であるということです。 ノードがメッセージを受信すると、そのノードは一度アクティブになり、その近隣ノードをすべて探索します。 これはまさに、深さ優先検索または幅優先検索が行うことです。 ノードに到達できる方法の数ではなく、ノードが到達可能かどうかのみを考慮するため、ルートの多重度は問題になりません。 

したがって、問題は、無向グラフ内のノード 1 から到達可能なすべてのノードを見つけることに帰着します。 到達可能なセットを計算したら、それらのノードのうちの何個がそのノードにも到達できるかを単純に数えます。$n$、これはノードから 2 番目の到達可能性計算を実行することと同等です。$n$、または同等の接続プロパティを確認します。 

より単純で直接的な解釈は対称性です。グラフは無向であるため、ノードが到達できる場合は、$n$伝播では、$n$同じ接続コンポーネント内にあります。 回数$n$メッセージを受信するのは、接続されているコンポーネント内の到達可能なノードの数 1 です。$n$、これは 1 から到達可能で、へのパスを持つノードをカウントすることになります。$n$。 無向グラフでは、これは、1 を含む連結成分と、$n$これは、BFS/DFS ベースの分類に単純化されます。 

実際のクリーンな解決策は、1 から到達可能なすべてのノードを計算し、そのようなノードごとに、到達できるかどうかを確認することです。$n$。 以来$n \le 50$、各候補の BFS/DFS は依然として高速です。

 ## アルゴリズムのチュートリアル

 1. 各ノードの近傍をすばやく反復できるように、入力行列から隣接リストを構築します。 これにより、文字列を繰り返しスキャンすることがなくなります。 
2. ノード 1 から開始して DFS または BFS を実行し、そこから到達可能なすべてのノードを検索します。 これをブール配列に格納します`reach_from_1`。 これにより、メッセージを受信した人が正確に捕捉されます。 
3. 各ノードについて$i$そのような`reach_from_1[i]`true の場合は、次から始まる 2 番目の DFS または BFS を実行します。$i$ノードかどうかを確認します$n$から到達可能です$i$。 そうであれば、ノード$i$答えに 1 を与えます。 
4. そのようなすべてのノードを合計します$i$。 この数は、最終的にあなたに届くメッセージを作成できる個別の送信者の数を表します。 
5. 最終的な合計を出力します。 

2 番目の到達可能性チェックを実行する理由は、1 から到達可能であるだけでは十分ではないためです。 ノードは 1 と同じ接続コンポーネント内にある可能性がありますが、それでも到達できません。$n$「初回転送」の方向性を考慮すると、有効な伝播経路を経由します。 2 番目のトラバーサルにより、有効な伝播チェーン上にあるノードのみがカウントされるようになります。$n$。 

### なぜ効果があるのか

 伝播プロセスは、無向エッジによって引き起こされるが、初回のアクティブ化によって制約される、有向影響関係を定義します。 各ノードはメッセージを 1 回だけ転送します。これは、メッセージが接続コンポーネント内のルート 1 を基点とするスパニング ツリーに沿って広がることを意味します。 ノードがカウントに寄与するのは、ノードがアクティブ化されている (1 から到達可能) 場合と、そのアクティブ化が影響を与える可能性がある場合のみです。$n$。 2 番目の到達可能性条件は、まさにその影響条件をキャプチャします。 グラフが小さく方向性がないため、到達可能性が明確で安定しているため、DFS ベースの特性評価は動的プロセスと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [input().strip() for _ in range(n)]

    adj = [[] for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if g[i][j] == '1':
                adj[i].append(j)

    # DFS from 0 (person 1)
    stack = [0]
    vis1 = [False] * n
    vis1[0] = True

    while stack:
        u = stack.pop()
        for v in adj[u]:
            if not vis1[v]:
                vis1[v] = True
                stack.append(v)

    def can_reach(start):
        stack = [start]
        vis = [False] * n
        vis[start] = True
        while stack:
            u = stack.pop()
            for v in adj[u]:
                if not vis[v]:
                    vis[v] = True
                    stack.append(v)
        return vis[n - 1]

    ans = 0
    for i in range(n):
        if vis1[i]:
            if can_reach(i):
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```隣接リストの構築により、行列が直接隣接反復をサポートする構造に変換されます。 DFS 内の文字列のスキャンを繰り返すと、制約が小さい場合でも不要なオーバーヘッドが追加されるため、これは重要です。 

最初の DFS は、人物 1 からのメッセージを受信したすべてのノードをマークします。2 番目のヘルパー関数は、指定されたノードが依然としてノードに影響を伝播できるかどうかをテストします。$n$、その開始点から同じ転送ルールをシミュレートします。 

最後のループでは、両方の条件を満たすノードを正確にカウントし、到達できるメッセージの有効なソースのみをカウントします。

 ## 特殊なケース

 エッジケースの 1 つは、次のような場合です。$n$完全に孤立している。 この場合、人 1 から多くの人が到達可能であっても、誰も 2 番目の到達可能条件を満たすことができないため、答えはゼロになります。 アルゴリズムはこれを自然に処理します。`can_reach`関数はノードに対して常に失敗します$n$、増分を防ぎます。 

もう 1 つのエッジ ケースは、グラフが完全に接続されている場合です。 そうすれば、1 から到達可能なすべてのノードも到達できます。$n$。 最初の DFS はすべてのノードをマークし、2 番目の DFS が成功するたびに、$n-1$これは、他のすべての人があなたにコピーを送信するという考えと一致します。 

3 番目のエッジ ケースは、1 と$n$切断されています。 最初の DFS は依然としてノードのサブセットに到達する可能性がありますが、それらのノードはいずれも 2 番目の到達可能性テストに合格しないため、結果は再びゼロになります。
