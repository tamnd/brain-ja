 ## 解決策
 ## 問題の理解

 ある期間の 13 日の金曜日を表す文字列が与えられます。 文字列内の各文字は次のようになります。`"0"`普通の日なら、`"1"`特に悪い日、または`"?"`ユーザーが思い出せない日のこと。 これに加えて、確率が与えられます`p`これは、未知の日が起こる可能性を表します。`"?"`実は悪い日だ`"1"`。 

タスクは、すべての金曜日の平均悪さの期待値を計算することです。 言い換えれば、毎日の悪さを表す確率変数の平均が必要です。 既知の日が決定論的な値に寄与します (`0`または`1`)、未知の日はその期待値に寄与します。`p`なぜならそれぞれ`"?"`ベルヌーイ確率変数のように動作します。 

文字列の長さは最大 50 文字ですが、これは非常に小さいため、ここではアルゴリズムの複雑さの制約を受けません。 期待される合計を計算するために文字列を線形に渡すだけでよく、それから文字列の長さで割って平均を取得します。 

文字列にのみが含まれる場合、微妙なエッジ ケースが発生します。`"?"`文字。 たとえば、入力が次の場合`"???"`そして`p = 0.6`、単純な実装では、考えられるすべての組み合わせを生成しようとする可能性があります。`0`そして`1`未知数については、期待値は次のように直接計算できます。`3 * 0.6 / 3 = 0.6`。 もう 1 つのエッジケースは次のような場合です`p`まさに`0`または`1`。 もし`p = 1`、 毎`"?"`として扱われます`1`; もし`p = 0`、 毎`"?"`として扱われます`0`。 不注意に丸めを実装すると、次のような問題が発生する可能性があります。`0.99999`の代わりに`1.00000`気をつけないと。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての置き換えを列挙することです。`"?"`そして各組み合わせの平均悪さを計算します。 のために`n`未知のもの、あります`2^n`組み合わせにはそれぞれ必要な`O(n)`平均的な計算。 これにより、`O(n * 2^n)`時間の複雑さ。 たとえ`n = 50`、これは天文学的に大きくなります（`~10^15`操作）、これは明らかに実行不可能です。 

重要な洞察は、期待の直線性です。 独立確率変数の合計の期待値は、変数間の依存関係に関係なく、それらの期待値の合計です。 既知のそれぞれの日が決定論に寄与します`0`または`1`、そして未知の毎日`"?"`貢献する`p`。 これにより、問題は、これらの値を合計して長さで割るという、文字列を通過する単一の線形パスに軽減されます。 組み合わせ列挙の必要はなく、解決策は正確です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 2^n) | O(n) | 遅すぎる |
 | 期待値 / リニアスキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります`s`そして確率`p`入力から。`s`金曜日の歴史が含まれており、`p`不明な日が悪い可能性があります。 
2. 変数を初期化する`total_badness`に`0`。 これにより、予想される悪影響が一日を通して蓄積されます。 
3. 各文字を反復処理します。`c`で`s`。 もし`c`は`"1"`、 追加`1`に`total_badness`決定的に悪い日だからです。 もし`c`は`"0"`、 追加`0`良い日なので。 もし`c`は`"?"`、 追加`p`なぜなら、確率を伴うベルヌーイ確率変数の期待値は`p`まさに`p`。 
4. ループの後、除算して期待平均を計算します。`total_badness`長さによって`s`。 
5. 結果を小数点以下 5 桁まで正確に出力します。 標準の丸めルールを使用して、最後の桁での 1 つ違いのエラーを回避します。 

機能する理由: 期待値の線形性により、個々の日の期待値を合計すると正確な期待値が得られることが保証されます。 日数で割ると、平均の期待値が維持されます。 治療の精度が損なわれることはありません`"?"`として`p`なぜなら、期待には実際のランダムな結果を生成する必要がないからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
p = float(input().strip())

total_badness = 0.0

for c in s:
    if c == '1':
        total_badness += 1.0
    elif c == '?':
        total_badness += p
    # '0' adds 0, so we do nothing

expected_average = total_badness / len(s)
print(f"{expected_average:.5f}")
```このソリューションは、次を使用して入力を読み取ります。`sys.stdin.readline`高速 I/O を実現します。 ループは、各文字をその意味に従って処理します。 予想される悪さを浮動小数点変数に蓄積し、最後に長さで割ります。 でフォーマットする`:.5f`標準ルールに従って丸められ、小数点以下 5 桁が正確に保証されます。 空のケース`"0"`ゼロを追加しても合計には影響しないため、暗黙的に処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    p = float(input().strip())
    total_badness = 0.0
    for c in s:
        if c == '1':
            total_badness += 1.0
        elif c == '?':
            total_badness += p
    expected_average = total_badness / len(s)
    return f"{expected_average:.5f}"

# Provided samples
assert run("?111?1??1\n1.0\n") == "1.00000", "sample 1"
# Custom tests
assert run("0?0?\n0.25\n") == "0.12500", "mix of known and unknown"
assert run("?????\n0.5\n") == "0.50000", "all unknowns"
assert run("11111\n0.75\n") == "1.00000", "all bad days"
assert run("00000\n0.99\n") == "0.00000", "all good days"
assert run("1?0?1?0?1?\n0.5\n") == "0.50000", "alternating known and unknown"
