 ## 解決策
 ## 問題の理解

 単一の山を使用して 2 人用ゲームを分析するように求められています。`n`石。 プレイヤーはセロザから順番に順番を変えていきます。 各ターンで、プレイヤーは既存の山を 1 つ選択し、それを少なくとも 2 つの山に分割し、連続した差が 1 に等しい厳密に減少するシーケンスを形成します。 たとえば、サイズ 5 の山は次のように分割できます。`[3, 2]`しかしそうではありません`[4, 1]`4 と 1 の差は 3 であるため、プレイヤーが行動できなくなった場合、ゲームは終了し、そのプレイヤーは負けます。 私たちの目標は、セロザが最適なプレイで勝利を保証できるかどうか、そしてそうであれば、勝利を確実にするために最初の動きで最初の山を分割する必要がある最小の山の数はいくらかを判断することです。 勝てない場合、答えは -1 です。 

入力は単一の整数です`n`(1 ≤ n ≤ 10^5)、初期の山のサイズを表します。 n は 100,000 まで大きくなり、制限時間は 2 秒であるため、O(n^2) アルゴリズムは遅すぎる可能性がありますが、O(n log n) または O(n√n) は実行可能です。 考えられるすべてのシーケンスを再帰的に列挙する単純なアプローチは、n が大きい場合には失敗します。 

最初の明白ではないエッジ ケースは、非常に小さな山で発生します。 のために`n = 1`、少なくとも 2 つの連続した減少する山に分割する方法がないため、Serozha はすぐに負けます。 のために`n = 2`、唯一の分割`[1, 1]`厳密に減少しているわけではないので、やはり最初のプレイヤーが負けます。 のために`n = 3`、唯一の有効な分割は`[2, 1]`、最初のプレイヤーが勝ちます。 単純な実装では、減少制約と差制約が正しく適用されなかったり、小さな n の処理に失敗したりすると、これらの計算が誤って行われる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのパイルサイズのグランディ数（または番号）を再帰的に計算します。 特定のサイズの山に対して`x`の場合、考えられるすべての有効な分割を連続する整数の厳密に減少するシーケンスに生成し、結果として得られる各山のセットの数を再帰的に計算し、XOR 演算を適用して現在の山の数を取得します。 数が多ければセロジャが勝ちます`n`はゼロではありません。 このアプローチは数学的には正しいですが、最大 100,000 までのパイル サイズごとにすべての分割を再帰的に生成すると、操作が多すぎます。 たとえば、合計が次になる減少シーケンスの数は、`n`は項の数がほぼ √n ずつ増加するため、再帰呼び出しの総数は最小でも O(n√n) となり、Python では限界ギリギリの速度になります。 

重要な洞察は、有効なシーケンスが厳密に連続する数値を減少させていることに気づくことです。 これにより、分割が大幅に制限されます。 シーケンスに k 個のパイルがある場合、その合計は次のようになります。`k * first - k*(k-1)/2`なぜならシーケンスは`first, first-1, ..., first-(k-1)`。 最初の要素を解くと、`first = (sum + k*(k-1)/2)/k`。 これは整数である必要があり、`first ≥ k`最後の要素が少なくとも 1 であることを確認します。考えられるすべての k を効率的に反復できます。`k*(k+1)/2 ≤ n`。 これにより、問題は、すべてのシーケンスを再帰的に生成することから、実現可能な k 値をテストすることによって候補シーケンスを生成することに軽減されます。 

分割候補が生成されたら、動的プログラミングを使用できます。 させて`dp[x]`プレイヤーがパイルサイズで移動する場合は True になります`x`勝利戦略を持っています。 dp を 1 から n まで繰り返し計算します。 結果として得られるすべてのパイルの dp 値の XOR が False になるような分割が存在する場合、パイルは勝ちです (次のプレーヤーが強制的に負けの位置に置かれます)。 これにより、合計で O(n√n) 個の操作のみが必要になることが保証され、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰 | O(2^n) | O(n) | 遅すぎる |
 | 候補者 k が分割された DP | O(n√n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`dp`サイズの`n+1`偽で。`dp[x]`will indicate whether the first player to move with a pile of size x can force a win.
 2. 反復する`pile`1からnまで。 各杭について、可能な数の杭を反復します`k`2 から始まり、まで`k*(k+1)/2 > pile`。 これにより、最小の有効な減少シーケンスが保証されます。`[k, k-1, ..., 1]`パイルサイズを超えないこと。 
3. 各 k について、計算します。`first = (pile + k*(k-1)//2) // k`。 どうかを確認してください`(pile + k*(k-1)//2) % k == 0`first が整数であることを確認します。 最初の要素が正でない場合は、最初の要素が正でないため、次の要素に進みます。 
4. シーケンスを構築する`[first, first-1, ..., first-(k-1)]`そして、結果として生じるすべてのパイルの dp 値の XOR を計算します。 XOR がゼロの場合は、マークを付けます`dp[pile] = True`そして現在の k を最小勝利スプリットの候補として保存します。 最小限の k だけが必要なので、早めに休憩します。 
5. dp[n] を入力した後、次の場合`dp[n]`が True の場合、見つかった最小の k を出力します。 それ以外の場合は、-1 を出力し、最初のプレイヤーが負けたことを示します。 

機能する理由: DP 配列は 1 から n までのすべての勝ちポジションをキャプチャします。 分割するたびに山が小さな山に縮小されるため、以前に計算された dp 値のみに依存します。 XOR 条件は、Sprague-Grundy の定理と同等です。 k を最小値から最大値まで繰り返すことにより、勝利を保証する最小の最初の手を見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

dp = [False] * (n + 1)
min_k = [-1] * (n + 1)

for pile in range(1, n + 1):
    for k in range(2, pile + 1):
        if k * (k + 1) // 2 > pile:
            break
        s = pile + k * (k - 1) // 2
        if s % k != 0:
            continue
        first = s // k
        if first < k:
            continue
        xor_sum = 0
        for i in range(k):
            xor_sum ^= dp[first - i]
        if not xor_sum:
            dp[pile] = True
            min_k[pile] = k
            break

if dp[n]:
    print(min_k[n])
else:
    print(-1)
```まずパイルのサイズを読み取ります。 の`dp`配列には、パイル サイズが勝っているかどうかが格納されます。 の`min_k`配列には、勝つための最小の最初のスプリットが格納されます。 合計と正の制約を満たす分割のみを考慮して、パイル サイズと可能な k 値を効率的に反復します。 各候補分割の dp 値の XOR を計算します。 次のプレーヤーを負け状態にする最初のスプリットによって、最小の k が決まります。 早めのブレークにより、最小の k を確実に捕捉できます。
