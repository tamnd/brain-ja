 ## 解決策
 ## 問題の理解

 重み付けされたツリーが与えられています。`n`都市と`n - 1`道路。 異なる都市の順序付けられたペアはそれぞれ 1 つの軍事作戦を表すため、次のようになります。`n * (n - 1)`総旅行数。 

市内からのご旅行の場合`u`街へ`v`、軍隊はそれらの間の独特の道に沿って移動します。 その経路上のすべての道路の中で、軍は経路に沿って最大の重みをもつ道路で最も多くの時間を費やします。 そのようなすべての道路には、そのキャンペーンのために 1 本の美しい木が与えられます。 

すべての道路について、順序ペアの数を数えなければなりません`(u, v)`この道路を、パス上の最大重みエッジの 1 つとして扱います。 次に、最大数とそれを達成するすべての道路を出力します。 

グラフはツリーであるため、都市の各ペアには正確に 1 つのパスがあります。 困難は絆から生まれます。 パス上の複数のエッジが最大重みを共有する場合、それらすべてがツリーを受け取ります。 

制約があるため、私たちは慎重に考える必要があります。 と`n ≤ 10^5`、都市ペアの数は約`10^10`したがって、すべてのペアを明示的に反復するアルゴリズムは不可能です。 平`O(n^2)`1 秒の制限には遅すぎます。 に近いものが必要です`O(n log n)`または`O(n α(n))`。 

主な微妙な点は、等しいエッジの重みを正しく処理することです。 よくある間違いは、エッジが一意の最大値であるパスのみをカウントすることです。 これは、複数の最大重みエッジが同じパス上に出現するたびに失敗します。 

次の例を考えてみましょう。```
3
1 2 5
2 3 5
```からのパス`1`に`3`両方のエッジが含まれており、両方とも最大の重みを持ちます`5`, したがって、両方の道路がこのキャンペーンから木を受け取ります。 

正しいカウントは次のとおりです。```
edge 1 -> 4
edge 2 -> 4
```各エッジは以下によって使用されるためです。`(1,2), (2,1), (1,3), (3,1)`エッジ 1 の場合、

 エッジ 2 についても同様です。 

もう 1 つの危険なケースは、同じ重さのエッジによってすでに内部接続されているコンポーネントを、より軽いエッジで接続する場合です。 

例：```
4
1 2 3
2 3 3
3 4 1
```エッジ`(3,4)`頂点を含むパスでは最大値になることはありません`1`または`2`、そのようなパスには重みも含まれるため、`3`。 エッジを個別に処理する不注意な DSU アプローチは、そのようなパスを過剰にカウントする可能性があります。 

正しい答えは次のとおりです。```
4 2
1 2
```最後の厄介なシナリオは、同じ重みを持つ大規模なグループです。 等しい重みのエッジを反復処理しながら DSU コンポーネントをすぐにマージすると、同じ重みグループ内の後続のエッジにはすでに更新されたコンポーネントが表示され、誤ったカウントが生成されます。 

例：```
4
1 2 5
2 3 5
3 4 5
```すべてのエッジは同じカウントを受け取る必要があります。 等しい重みのグループは、結合が完了する前に一緒に処理する必要があります。 

## アプローチ

 ブルートフォースソリューションは概念的には単純です。 注文したペアごとに`(u, v)`、それらの間の一意のパスを見つけ、そのパス上の最大エッジの重みを決定し、その重みを持つすべてのエッジを増分します。 

これは、定義がシミュレーションと直接一致するため機能します。 残念ながら、`n * (n - 1)`順序ペア。各パスには以下が含まれる場合があります。`O(n)`エッジ。 最悪の場合こうなります`O(n^3)`、これは完全に不可能です`n = 10^5`。 

私たちはパスを個別に考えるのをやめる必要があります。 

重要な観察は、エッジの重みがパス上の最大エッジの重みと等しい場合にのみ、エッジがペアに寄与するということです。 DSU を使用して、重みの大きい順にエッジを処理するとします。 

重量加工前`w`、すべての DSU コンポーネントは、厳密に より小さいエッジを使用して接続された頂点を表します。`w`。 

さあ、優位に立とう`(u, v)`体重の`w`。 

もし`u`サイズのコンポーネントに属します`A`そして`v`サイズのコンポーネントに属します`B`、その後、すべてのペア`(a, b)`と`a`最初のコンポーネントと`b`2 番目には、最大エッジ重みが正確に一致するパスがあります。`w`。 

なぜ？ 以前に追加されたエッジはすべて以下よりも小さいため、`w`、現在のエッジは、重みを使用してこれらの領域間に最初に可能な接続を作成します。`w`。 

順序のないペアの数は`A * B`したがって、順序付けされたペアの数は次のようになります。```
2 * A * B
```その値が現在のエッジに寄与します。 

重みが等しいと事態が複雑になります。 ウェイトのエッジを処理するとき`w`コンポーネントをすぐに結合しないでください。すべてのエッジにウェイトが存在するためです。`w`より小さい重みによってのみ形成された DSU 状態を確認する必要があります。 

したがって、各重みグループを 2 つのフェーズで処理します。 

まず、この重みの結合の前に DSU 状態を使用して寄与を計算します。 

次に、このウェイトのすべてのエッジを結合します。 

これにより、等しい重みのエッジが対称的に扱われることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 重量別の最適な DSU | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを読み取り、そのエンドポイント、重み、元のインデックスを保存します。 
2. エッジを重みで降順でない順に並べ替えます。 
3. すべての頂点が独自のコンポーネントで開始される DSU を初期化します。 
4. 等しい重みでグループ化されたエッジを処理します。 
5. あらゆるエッジに`(u, v)`現在の体重グループでは:

 次の DSU ルートを見つけます`u`そして`v`。 

コンポーネントのサイズを次のようにします`A`そして`B`。 

パスが最大の重みを得る順序付けされた都市ペアの数`w`このつながりのおかげで`2 * A * B`。 

この値をエッジの寄与として保存します。 

これが機能するのは、2 つのコンポーネント間のすべてのパスがウェイトのエッジを通過する必要があるためです。`w`、すべての小さなエッジはすでに以前にマージされています。 
6. 重みグループ全体の寄与を計算した後、グループ内のすべてのエッジを結合します。 

労働組合の結成を遅らせることが不可欠だ。 そうしないと、同じグループ内の後のエッジで、部分的にマージされたコンポーネントが誤って観察されてしまいます。 
7. すべてのグループを処理した後、最大の寄与を見つけます。 
8. 最大値、それを達成するエッジの数、およびそれらのインデックスを昇順に出力します。 

### なぜ効果があるのか

 現在重量を処理しています`w`、すべての DSU コンポーネントは、重みが より小さいエッジのみを使用して接続を表します。`w`。 

サイズの異なるコンポーネントを接続するエッジの場合`A`そして`B`、これらのコンポーネントにわたる頂点のすべてのペアには、より小さいエッジのみを使用するパスがありません。 それらの間のパスは少なくとも 1 つのウェイト エッジを使用する必要があります`w`したがって、そのパス上の最大エッジは正確に`w`。 

グラフはツリーであるため、現在のエッジはそのようなパスすべて上にあります。 したがって、このエッジは正確に受信します`2 * A * B`注文したペア。 

等しい重みをまとめて処理すると、重みのエッジがないため正確さが保たれます。`w`同じ重みの別のエッジによって引き起こされる結合から恩恵を受けるはずです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)

        if a == b:
            return

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]

def solve():
    n = int(input())

    edges = []

    for idx in range(1, n):
        u, v, w = map(int, input().split())
        edges.append((w, u, v, idx))

    edges.sort()

    dsu = DSU(n)

    ans = [0] * (n - 1)

    m = len(edges)
    i = 0

    while i < m:
        j = i

        while j < m and edges[j][0] == edges[i][0]:
            j += 1

        # compute contributions
        for k in range(i, j):
            w, u, v, idx = edges[k]

            ru = dsu.find(u)
            rv = dsu.find(v)

            ans[idx - 1] = 2 * dsu.size[ru] * dsu.size[rv]

        # perform unions
        for k in range(i, j):
            w, u, v, idx = edges[k]
            dsu.union(u, v)

        i = j

    best = max(ans)

    result = []

    for i in range(n - 1):
        if ans[i] == best:
            result.append(i + 1)

    print(best, len(result))
    print(*result)

solve()
```この解決策は、より軽い重量のエッジによって形成される接続されたコンポーネントを維持することを中心に展開します。 

DSU は、親とコンポーネントのサイズの両方を保存します。 サイズによるパスの圧縮と結合により、操作時間がほぼ一定に保たれます。 

エッジは重みによってソートされるため、重みを処理するときに`w`、小さい重みはすべてすでにマージされています。 

最もデリケートな部分は、等しい重みのエッジの 2 段階の処理です。 寄与フェーズ中、すべてのエッジは、同じ重みの結合が発生する前に DSU 状態を観察する必要があります。 すべての寄与が計算された後でのみ、コンポーネントをマージします。 

寄与の式では、順序のないペアではなく、順序のあるペアが使用されます。 だからこそ、次のように掛けます。`2`。 

All counts fit in 64-bit integers. Python ではこれは自動的に行われますが、C++ では解決策に次のことが必要になります。`long long`。

 ## 特殊なケース

 もう一度等重チェーンを考えてみましょう。```
3
1 2 5
2 3 5
```最初はすべてのコンポーネントのサイズは 1 です。 

両方のエッジは同じ重みグループに属します。 

結合の前:

 | エッジ | コンポーネントのサイズ | 貢献 |
 | --- | --- | --- |
 | (1,2) | 1 と 1 | 2 |
 | (2,3) | 1 と 1 | 2 |

 最初の結合を処理した後、DSU は次のようになります。`{1,2}`そして`{3}`。 

後で 2 番目のエッジを計算すると、誤って寄与を受け取ることになります。`4`。 

同じ重みをまとめて処理すると、このエラーが回避されます。 

次に、次のことを考えてみましょう。```
4
1 2 3
2 3 3
3 4 1
```加工後重量`1`、頂点`3`そして`4`接続されています。 

エッジ用`(2,3)`体重の`3`、コンポーネントのサイズは次のとおりです。```
{2} -> size 1
{3,4} -> size 2
```したがって、貢献度は`4`。 

これにより、順序付きペアが正しくカウントされます。```
(2,3), (3,2), (2,4), (4,2)
```頂点を含むペア`1`それらのパスには、最大重みが等しい別のエッジが含まれているため、除外されます。 

最後に、厳密に増加するチェーンを考えてみましょう。```
4
1 2 1
2 3 2
3 4 3
```エッジを加工する場合`(3,4)`重さで`3`、DSU はすでにマージされています`{1,2,3}`。 

貢献は次のとおりです。```
2 * 3 * 1 = 6
```順序付きペアに対応:```
(1,4), (4,1),
(2,4), (4,2),
(3,4), (4,3)
```これらのパスにはそれぞれ最大のエッジの重みがあります`3`、そしてエッジ`(3,4)`はその値を持つユニークなエッジです。
