 ## 解決策
 ## 問題の理解

 平面上に 3 つの凸多角形があります。 各多角形から 1 つの点を選択する必要があり、これらの選択された 3 つの点の平均が偶像の位置に等しくなければなりません。 

選択した祭壇ポイントが$A, B, C$、そしてアイドルはポイントです$P$、条件は$$\frac{A+B+C}{3}=P$$これは次のように書き換えることができます$$A+B+C=3P$$すべての丘について、そのような 3 つの点が存在するかどうかを個別に判断する必要があります。 

ポリゴンは凸状であり、最大で$5 \cdot 10^4$それぞれの頂点。 丘の数は最大です$10^5$。 これらの制限により、すべてのポリゴン エッジに対して各クエリを線形時間で処理するものは直ちに除外されます。 平$O(nm)$すでにそこら中にあるだろう$10^{10}$最悪の場合の運用。 

ジオメトリ構造は、生のサイズよりも重要です。 凸多角形はミンコフスキー和の下で非常にうまく動作します。$$A+B+C=3P$$問題を凸多角形内の点のクエリに変換することを強く提案します。 

最初の微妙な点は、祭壇の位置がポリゴンの頂点に制限されていないことです。 境界上を含め、ポリゴン内のどこにでも配置できます。 頂点のみをチェックする解決策は正しくありません。 

考慮する：```
Triangle 1: (0,0) (2,0) (0,2)
Triangle 2: (0,0) (2,0) (0,2)
Triangle 3: (0,0) (2,0) (0,2)
Hill: (1,1)
```ポイント$(1,1)$3 つの祭壇ポイントをすべて選択できるため、これは達成可能です。$(1,1)$、三角形の内側にあります。 頂点に限定すると、誤って「NO」と答えることになります。 

2 番目の微妙な点は、ポリゴンが交差したり、相互に含まれたりする可能性があることです。 分離の仮定は存在しません。 素性を利用したアプローチはすぐに失敗します。 

もう 1 つの簡単な間違いは、境界点が許可されていることを忘れることです。 1 つのポリゴンがエッジ エンドポイントを通じて縮退的に寄与していると仮定します。```
Triangle 1: (0,0) (2,0) (0,2)
Triangle 2: (0,0) (2,0) (0,2)
Triangle 3: (0,0) (2,0) (0,2)
Hill: (0,0)
```3 つの祭壇をすべて選択すると、$(0,0)$は有効なので、正解は YES です。 厳格な内部テストでは誤って拒否される可能性があります。 

最後の危険領域は精度です。 座標の大きさは次のとおりです$5 \cdot 10^8$、ミンコフスキー和は一時的に次のような値を生成する可能性があります。$1.5 \cdot 10^9$。 ここでは浮動小数点ジオメトリは不要であり、境界エラーの危険性があります。 整数の外積は 64 ビット符号付き整数内に安全に収まるため、ソリューション全体は整数のみのままでなければなりません。 

## アプローチ

 ブルートフォース解釈は定義に直接に従います。 各丘のポイントについて$P$、ポイントが存在するかどうかを判断しようとします$A \in S_1$、$B \in S_2$、 そして$C \in S_3$そのような$$A+B+C=3P$$ポリゴンの頂点に限定すれば、頂点のトリプルをすべて列挙することもできますが、それはすでに不可能です。 各ポリゴンには次のものがあります。$5 \cdot 10^4$頂点なので、トリプルの数はおおよそ次のようになります。$$(5 \cdot 10^4)^3 \approx 10^{14}$$有効な祭壇点は頂点に限定されないため、これでも実際の問題は解決されません。 

重要な観察は、方程式がすでにミンコフスキー和を記述していることです。 

定義する$$S = S_1 + S_2 + S_3$$ここで、ミンコフスキー和には次のように表現できるすべての点が含まれます。$$A+B+C$$と$A \in S_1$、$B \in S_2$、$C \in S_3$。 

その場合、クエリは非常に単純になります。$$3P \in S$$したがって、丘ごとに新たな幾何学的存在問題を解決する代わりに、結合された領域を 1 回事前計算することができ、各クエリは凸多角形内の点のテストに帰着します。 

凸多角形はミンコフスキー和の下で閉じられるため、これは美しく機能します。 凸多角形の和もまた凸多角形になります。 さらに良いことに、凸多角形のミンコフスキー和は、エッジ角度マージ手法を使用して線形時間で計算できます。 

3 つのポリゴンに次のものが含まれているとします。$n_1, n_2, n_3$頂点。 彼らのミンコフスキー和は最大でも$$n_1+n_2+n_3$$同一線上の冗長性を削除した後の頂点。 つまり、最終的なポリゴンを線形時間で 1 回構築し、バイナリ検索ポイントの包含を使用して対数時間で各クエリに答えることができます。 

ブルートフォース手法は、クエリごとに幾何学的関係を独立して繰り返し再構築するため、失敗します。 Minkowski-sum の観点では、実行可能領域全体が 1 つの凸多角形に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m \cdot n_1 n_2 n_3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n_1+n_2+n_3+m\log N)$|$O(N)$| 承認済み |

 ここ$N$は、最終的なミンコフスキー和多角形の頂点の数です。 

## アルゴリズムのチュートリアル

 1. 3 つの凸多角形を読み取ります。 

頂点はすでに反時計回りの順序で指定されており、これはまさにミンコフスキー和アルゴリズムが必要とするものです。 
2. 辞書順に最小の頂点が最初に来るように、各多角形を回転します。 

これにより、すべてのポリゴンに正規の開始位置が与えられます。 この回転の後、エッジ ベクトルは、ポリゴンの周囲でソートされた角度順に表示されます。 
3. 各ポリゴンを周期的なエッジ シーケンスに変換します。 

頂点が$p_0, p_1, \dots, p_{n-1}$、エッジは次のようになります。$$p_{i+1}-p_i$$最後にラップアラウンド付き。 
4. エッジ マージを使用して 2 つのポリゴンのミンコフスキー和を計算します。 

2 つの最小頂点の合計から開始します。 次に、エッジ シーケンスを同時に歩きます。 

すべてのステップで、現在のエッジ ベクトルの外積を比較します。 

外積が正の場合、最初の多角形を進めます。 

負の場合は、2 番目のポリゴンを進めます。 

ゼロの場合は両方を進めます。 

これは、並べ替えがエッジ角度によって行われることを除いて、2 つのソートされた配列をマージすることと精神的には同じです。 
5. 3 つのポリゴンを合計します。 

最初の計算$$T=S_1+S_2$$それから計算します$$S=T+S_3$$6. 生成されたポリゴンから、同一線上にある冗長な頂点を削除します。 

連続した同一線上のエッジは形状には影響しませんが、ポイント クエリが複雑になります。 
7. 各丘のポイントについて$P$、それを 3 でスケールします。 

実現可能条件は、$$3P \in S$$そこでポイントを問い合わせます$$Q=(3x,3y)$$8. 対数時間で凸多角形内の点テストを実行します。 

最初の頂点を扇形三角形分割の原点として固定します。 

まず、最初と最後のエッジによって形成される角度範囲外の点を拒否します。 

次に、クエリ点を含む三角形セクターを二分探索します。 

最後に、外積を使用して、点がその三角形の内側にあるかどうかを確認します。 
9. 点がミンコフスキー和多角形の内側または境界上にある場合は YES を出力し、それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 ミンコフスキー和$$S_1+S_2+S_3$$次のように表現できるすべての点が正確に含まれます$$A+B+C$$各ポリゴンから 1 つの点が選択されます。 

アイドルの条件に必要なのは$$A+B+C=3P$$つまり、丘はまさにいつ実現可能であるかということです。$3P$ミンコフスキー和多角形に属します。 

すべてのポリゴンは凸であるため、ミンコフスキー和も凸です。 エッジ角度マージ アルゴリズムは、角度の増加順にサポート エッジをトラバースすることにより、その境界を正しく構築します。 すべての凸多角形は、共通のアンカー頂点を共有する重なり合わない三角形に分割できるため、凸多角形内の点のクエリは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(a, b):
    return a[0] * b[1] - a[1] * b[0]

def sub(a, b):
    return (a[0] - b[0], a[1] - b[1])

def add(a, b):
    return (a[0] + b[0], a[1] + b[1])

def rotate_smallest(poly):
    idx = min(range(len(poly)), key=lambda i: (poly[i][0], poly[i][1]))
    return poly[idx:] + poly[:idx]

def compress(poly):
    res = []
    n = len(poly)

    for p in poly:
        while len(res) >= 2:
            a = res[-2]
            b = res[-1]
            if cross(sub(b, a), sub(p, b)) == 0:
                res.pop()
            else:
                break
        res.append(p)

    while len(res) >= 3:
        a = res[-2]
        b = res[-1]
        c = res[0]
        if cross(sub(b, a), sub(c, b)) == 0:
            res.pop()
        else:
            break

    return res

def minkowski(A, B):
    A = rotate_smallest(A)
    B = rotate_smallest(B)

    n = len(A)
    m = len(B)

    ea = [sub(A[(i + 1) % n], A[i]) for i in range(n)]
    eb = [sub(B[(i + 1) % m], B[i]) for i in range(m)]

    i = j = 0

    cur = add(A[0], B[0])
    res = [cur]

    while i < n or j < m:
        va = ea[i % n] if i < n else None
        vb = eb[j % m] if j < m else None

        if i == n:
            take_a = False
        elif j == m:
            take_a = True
        else:
            cr = cross(va, vb)
            if cr > 0:
                take_a = True
            elif cr < 0:
                take_a = False
            else:
                cur = add(cur, add(va, vb))
                res.append(cur)
                i += 1
                j += 1
                continue

        if take_a:
            cur = add(cur, va)
            i += 1
        else:
            cur = add(cur, vb)
            j += 1

        res.append(cur)

    res.pop()
    return compress(res)

def point_in_convex(poly, p):
    n = len(poly)

    if n == 1:
        return p == poly[0]

    if cross(sub(poly[1], poly[0]), sub(p, poly[0])) < 0:
        return False

    if cross(sub(poly[-1], poly[0]), sub(p, poly[0])) > 0:
        return False

    l = 1
    r = n - 1

    while r - l > 1:
        mid = (l + r) // 2

        if cross(sub(poly[mid], poly[0]), sub(p, poly[0])) >= 0:
            l = mid
        else:
            r = mid

    a = poly[0]
    b = poly[l]
    c = poly[(l + 1) % n]

    return cross(sub(b, a), sub(p, a)) >= 0 and \
           cross(sub(c, b), sub(p, b)) >= 0 and \
           cross(sub(a, c), sub(p, c)) >= 0

def read_poly():
    n = int(input())
    return [tuple(map(int, input().split())) for _ in range(n)]

p1 = read_poly()
input()

p2 = read_poly()
input()

p3 = read_poly()
input()

sum12 = minkowski(p1, p2)
total = minkowski(sum12, p3)

m = int(input())

out = []

for _ in range(m):
    x, y = map(int, input().split())
    q = (3 * x, 3 * y)

    if point_in_convex(total, q):
        out.append("YES")
    else:
        out.append("NO")

print("\n".join(out))
```実装は数学的構造に直接に従います。 

の`rotate_smallest`関数はポリゴン表現を正規化します。 ミンコフスキー エッジのマージは、両方のポリゴンが辞書編集上の最小の頂点から開始する場合にのみきれいに機能します。 

の`minkowski`関数は線形マージを実行します。 各ポリゴンは、角度によってソートされたエッジ ベクトルの循環シーケンスに寄与します。 マージ ロジックは、外積を使用して検出された極角が小さい方のエッジに進みます。 2 つのエッジが平行で同じ方向を向いている場合、両方とも一緒に消費されます。 

結果には不要な同一線上にある頂点が含まれる可能性があります。 の`compress`関数は方向チェックを使用してそれらを削除します。 ポイント クエリは厳密に凸状の扇形構造を想定しているため、これは重要です。 

点包含テストでは整数演算のみが使用されます。 ポリゴンは、次の点をルートとする扇形として扱われます。`poly[0]`。 二分探索により、クエリ点を含む一意の三角形セクターが特定され、次に 3 つの方向テストにより、その点が境界の内側にあるか境界上にあるかが判断されます。 

微妙な点の 1 つは、非厳密な不等式の使用です。 ステートメントによれば境界点は有効であるため、すべての封じ込めテストではゼロクロス積を受け入れる必要があります。 

もう 1 つの微妙な点は、オーバーフローの安全性です。 Python の整数は任意の精度ですが、C++ でも、座標の大きさがおよそ以下にとどまるため、すべての計算は符号付き 64 ビット整数に収まります。$10^{18}$外積内の乗算後。

 ## 特殊なケース

 境界包含の場合を考えてみましょう。```
3
0 0
1 0
0 1

3
0 0
1 0
0 1

3
0 0
1 0
0 1

1
0 0
```スケーリングされたクエリ ポイントはそのままです$(0,0)$。 この点は、ミンコフスキー和多角形の頂点に正確に位置します。 すべての方向チェックで使用されるため、ポリゴン内ポイント テストはこれを受け入れます。`>= 0`の代わりに`> 0`。 アルゴリズムは正しく YES を出力します。 

ここで、内部点のみが機能する例を考えてみましょう。```
3
0 0
2 0
0 2

3
0 0
2 0
0 2

3
0 0
2 0
0 2

1
1 1
```スケーリングされたクエリは次のようになります$(3,3)$。 頂点の合計が 3 倍になることはありません$(3,3)$したがって、頂点のみのアプローチは失敗します。 ただし、ミンコフスキー和には、頂点の和だけでなく、すべての凸の組み合わせが含まれます。 以来$(1,1)$各三角形の内側にあり、そこにある 3 つの祭壇点をすべて選択すると、$$(1,1)+(1,1)+(1,1)=(3,3)$$アルゴリズムは正しく YES を出力します。 

最後に、交差するポリゴンについて考えてみましょう。```
3
0 0
2 0
0 2

3
1 0
3 0
1 2

3
0 1
2 1
0 3

1
1 1
```ポリゴンが重なり合っています。 このアルゴリズムは、どこにも素性には依存しません。 ミンコフスキー和は任意の凸集合に対して有効なままであるため、同じ構築とクエリ ロジックは変更されずに機能します。
