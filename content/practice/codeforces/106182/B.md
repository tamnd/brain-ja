 ## 問題の理解

 この問題はカードのコレクションを与えます。 各カードには 2 つの値があり、`a`そして`b`。 正確に選択しなければなりません`k`カードを選択し、選択したすべての合計の積を最大化します`a`値と選択されたすべての合計`b`価値観。 このデッキには特別なバランス特性があります。どのカードでも、その 2 つの値のうち少なくとも 1 つは最大 100 です。 

入力には複数のテスト ケースが含まれています。 ケースごとに、カードの枚数とプレイする必要があるカードの数が分かり、その後、各カードの 2 つの値がわかります。 出力は、すべての有効な選択肢の中で可能な最高のスコアです。`k`カード。 

制約が鍵です。 すべてのテスト ケースにわたるカードの合計数は最大で`100000`、 そして`k`せいぜい`5`。 通常のサブセット検索では、大まかに試行します。`n^k`可能性があり、値が小さい場合でも不可能になります。`k`いつ`n`到達する`100000`。 解決策は線形に近いか、カード制限に隠された小さな値を使用する必要があります。 

よくある間違いは、カードの片面だけを基準にして並べ替えることです。 たとえば、最大のカードを 5 枚選択すると、`a`価値観を破壊する可能性があります`b`和。 考慮する：```
1
3 2
1000 1
999 100
1 100
```による貪欲な選択`a`最初の 2 枚のカードにスコアを与えます`(1999) * (101) = 201899`。 より良い選択はスコアのある最後の 2 枚のカードです`(1000) * (200) = 200000`なので、この例では壊れません。 ただし、最後のカードを次のように変更すると、`(500, 100)`、ベストセットはまた変わります。 重要なのは、両方の合計が相互作用するため、一方の側を独立して最大化することは目的を表さないということです。 

もう 1 つの特殊なケースは、すべてのカードの小さい側が小さい場合です。 例えば：```
1
4 2
1000000000 1
2 1000000000
100 100
100 100
```答えは 2 つの合計のバランスをとることで得られます。 大きな値のみを追跡する方法では、小さな寄与が積を大幅に大きくする可能性を見逃してしまう可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべてのグループを直接試します。`k`カード。 グループごとに 2 つの合計を計算し、答えを更新します。 すべての有効なハンドがチェックされるため、これは正しいです。 問題はグループ数です。 と`n`カードと`k`に近い`5`、選択肢の数は約`n^5`これは、通常のコンテストの制限時間に収まる制限をはるかに超えています。 

有益な観察はバランス状態から得られます。 すべてのカードについて、定義します`small = min(a, b)`そして`large = max(a, b)`。 選択したカードには次のような特徴があります。```
sum(a) * sum(b)
```それは正確には:```
(sum of small values) * (sum of large values)
```なぜなら、カードの 2 つの値を交換しても、乗算される 2 つの合計は変わらないからです。 

選択されたすべての小さな値の合計が超えることはできません`5 * 100 = 500`。 これは、この小さな次元に対して動的プログラミングを使用できることを意味します。 カードをスキャンしている間、選択したカードの数ごとに可能な最大の高額額と、可能なすべての少額額を保持します。 

カードを処理するときは、カードをスキップすることも、カードを取得することもできます。 取ると、選んだカードの枚数が1枚増え、小額が1枚増えます。`small`、そして保存された大額は によって増加します`large`。 すべてを処理した後の答えは、`small_sum * large_sum`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | お(1) | 遅すぎる |
 | 最適 | O(n * k * 500) | O(k * 500) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのカードについて、小さい値と大きい値を計算します。 DP 状態の合計範囲は限られているため、DP 状態の小さい値のみを考慮します。 
2. 動的プログラミング テーブルを作成します。`dp[j][s]`正確に選択することで取得できる大きな値の最大合計を格納します。`j`小さな値が合計されるカード`s`。 
3.初期化`dp[0][0] = 0`, つまり、カードを選択しないと大きな合計がゼロになります。 
4. 各カードを 1 枚ずつ処理します。 現在のカードについて、すでに選択されている数が少ないすべての州にカードを追加してみてください。`k`カード。 新しい状態では、選択されたカウントと少額の合計が現在のカードの値によって増加します。 
5. すべてのカードが処理された後、すべての可能な少額の金額を正確に調べます。`k`カードが選ばれました。 小さな合計に保存されている大きな合計を掛けて、最大値を維持します。 

なぜ効果があるのか:

 選択されたすべてのハンドには、より小さい値とより大きい値の固定セットがあります。 DP は、選択されたカードの可能なすべての枚数と、可能なすべての小さい値の合計を列挙します。 合計が大きくなると最終製品が改善されるだけであるため、そのような状況ごとに、可能な限り最大の値の合計が維持されます。 考えられるすべてのハンドが 1 つの DP 状態にマップされ、すべての状態に最良の継続が格納されるため、最終的な最大値は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    INF = -10**30

    for _ in range(t):
        n, k = map(int, input().split())

        cards = []
        for _ in range(n):
            a, b = map(int, input().split())
            if a <= b:
                cards.append((a, b))
            else:
                cards.append((b, a))

        dp = [[INF] * 501 for _ in range(k + 1)]
        dp[0][0] = 0

        for small, large in cards:
            for cnt in range(k - 1, -1, -1):
                for sm in range(501 - small):
                    if dp[cnt][sm] != INF:
                        dp[cnt + 1][sm + small] = max(
                            dp[cnt + 1][sm + small],
                            dp[cnt][sm] + large
                        )

        ans = 0
        for sm in range(501):
            if dp[k][sm] != INF:
                ans = max(ans, sm * dp[k][sm])

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```入力は通常、次のように読み取られます。`sys.stdin.readline`カードの合計枚数が上限に達するため、`100000`。 DP テーブルは次のみを使用します。`k + 1`遷移は常に、選択された小さい数から大きい数に移行するためです。 

ループが終わる`cnt`後ろに行く。 これにより、現在のカードが同じ反復で複数回使用されることが防止されます。 順方向にループすると、新しく更新された状態によって、同じカードがすぐに再び消費される可能性があります。 

少額の合計次元は次のように固定されます。`500`選ばれたカードは最大でも 5 枚までしか寄与しないため、`100`それぞれ小さめに。 Python では整数の精度は任意であるため、最後の乗算は安全です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * k * 500) | 各カードは、選択されたすべてのカウントと少額の状態を更新します。 
| スペース | O(k * 500) | 現在の DP テーブルのみが保存されます。

## テストケース```python
import sys
import io

def solve_io(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    t = int(sys.stdin.readline())
    res = []
    INF = -10**30

    for _ in range(t):
        n, k = map(int, sys.stdin.readline().split())
        dp = [[INF] * 501 for _ in range(k + 1)]
        dp[0][0] = 0

        for _ in range(n):
            a, b = map(int, sys.stdin.readline().split())
            small = min(a, b)
            large = max(a, b)

            for cnt in range(k - 1, -1, -1):
                for sm in range(501 - small):
                    if dp[cnt][sm] != INF:
                        dp[cnt + 1][sm + small] = max(
                            dp[cnt + 1][sm + small],
                            dp[cnt][sm] + large
                        )

        ans = 0
        for sm in range(501):
            ans = max(ans, sm * dp[k][sm])
        res.append(str(ans))

    sys.stdin = old
    return "\n".join(res)

 ## 特殊なケース

 いつ`k = 1`、選択された 1 枚のカードを持つ状態のみが考慮されるため、DP は引き続き機能します。 入力の場合:```
1
1 1
7 9
```小さい方の合計は`7`そして大きい方の合計は`9`、与える`63`。 

すべてのカードが同じ値を持つ場合、多くの異なる選択が同じ DP 状態に達します。 その状態の最大の大きな金額が重要であり、最良の値のみを保持することが安全です。 

一方の面が非常に大きく、もう一方の面が小さいカードの場合、大きい面による貪欲な選択は失敗します。 DP は少額の寄与を状態の一部として保持するため、同様の少額の合計が大きく異なる組み合わせを比較できます。
