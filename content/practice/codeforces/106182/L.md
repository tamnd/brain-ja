 ## 解決策
 ## 問題の理解

 部屋は木としてモデル化されており、そこではすべての人が頂点であり、シラミが 1 日のトレーニングで 2 人の間を直接移動できれば 2 人がつながります。 トレーニング後は、`d`シラミは、木の距離が最大でも 2 つの頂点の間を飛び越えることができます。`d`。 目標は、必要なジャンプ距離を最小限に抑えながら、開始者とすべての人を正確に 1 回訪問する順序を選択することです。 

入力により、いくつかの独立したツリーが得られます。 各ツリーについて、次の最小値が必要です。`d`これにより、このような訪問命令が可能になります。 出力は、すべてのテスト ケースの最小トレーニング時間です。 

すべてのテスト ケースにわたる頂点の合計数が最大で次であるという制約`10^6`これは、解が線形に近い必要があることを意味します。 多くの可能なパス、順列、またはグラフ検索の繰り返しを試みるアプローチでは、時間がかかりすぎます。 木の構造特性を抽出し、エッジを数回通過するだけで答えを決定する必要があります。 

主なエッジケースは、短いトラバースの存在と通常の深さ優先の検索順序を混同することから生じます。 DFS 順序では、別の順序が機能する場合でも、長い分岐の終端から別の遠く離れた分岐へのジャンプが強制される場合があります。 

たとえば、スターツリーの場合は次のようになります。```
3
1 2
1 3
```正しい出力は次のとおりです。```
2
```不注意な解決策では、すべての頂点が接続されているため、エッジのみを使用してすべてのツリーを歩くことができると考える可能性があります。 ただし、一枚の葉を訪れて中心部を通って戻ると、再び中心部を訪れることはできません。 2 番目のリーフには、距離 2 のジャンプで到達する必要があります。 

パス ツリーは異なります。```
4
1 2
2 3
3 4
```正しい出力は次のとおりです。```
1
```頂点は次の順序でアクセスできます。`1 -> 2 -> 3 -> 4`、既存のエッジのみを使用します。 常に 2 を出力するソリューションでは、パスが特別であることを見逃してしまいます。 

もう 1 つのよくある間違いは、直径だけを確認することです。 シラミは直径に従う必要がないため、直径が大きい木でも答え 2 が得られます。 必要なのは、距離が 2 以下の頂点のすべてのペアが接続されているグラフ内のハミルトニアン パスだけです。 

## アプローチ

 直接的なアプローチでは、可能なすべてのジャンプ距離に対して訪問順序を構築しようとします。 固定距離の場合、その長さのジャンプを許可することによって形成されたグラフを検索し、ハミルトニアン パスが含まれているかどうかを確認できます。 問題はそのような経路を正確に求めているため、これは正しいですが、ハミルトニアン経路探索は一般に指数関数的です。 たとえ木の上であっても、考えられるすべての順序を推論しようとするのはすぐに不可能になります。 

重要な観察は、木には非常に強い特性があるということです。つまり、すべての木の二乗はハミルトニアンです。 木の正方形は、すべての頂点が最大 2 の距離ですべての頂点に接続されているグラフです。これは、2 日間のトレーニングですべての木を訪問できることを意味します。 

今では1日で十分なケースだけが残っています。 1 日のトレーニングでは、すべてのジャンプは元の木の端に従わなければなりません。 ツリー自体が単純なパスである場合にのみ、ツリーは独自のエッジを使用してすべての頂点を訪れるパスを持つことができます。 ツリーでは、これはまさにすべての頂点の次数が 2 以下の場合に発生します。 

ブルート フォースは訪問命令を主なオブジェクトとして扱うため、失敗します。 構造観察により、問題全体がツリーの最大次数のチェックに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、すべての頂点の次数を計算します。 必要な情報は、頂点が 3 方向以上に分岐しているかどうかだけです。 
2. すべての頂点の最大次数を見つけます。 すべての次数が最大 2 の場合、木は道であるため、端に沿って歩くことが可能であり、答えは 1 になります。 
3. 頂点の次数が 3 以上の場合、そのツリーはパスではありません。 1 日のジャンプではすべての頂点を訪問することはできませんが、木の正方形には常にハミルトニアン パスがあるため、2 日のジャンプで常に十分です。 答えは 2 です。 

なぜ効果があるのか:

 最大次数が 2 以下のツリーは分岐できないため、まさに頂点の連鎖になります。 チェーンをたどると、距離 1 のジャンプですべての頂点にアクセスします。 

最大次数が 2 より大きい場合、ツリーには分岐点が含まれます。 木の端のみを使用するパスは、分岐点を再度訪問しないと複数の分岐に入ることができないため、距離 1 は不可能です。 距離 2 を許可すると、すべての頂点がその親、子、兄弟に接続されます。これは、すべての頂点を 1 つの有効な訪問シーケンスに配置するのに十分です。 

アルゴリズムの背後にある不変条件は、可能な答えは 1 と 2 だけであるということです。次数チェックでは、より小さい値を達成するツリーが正確に区別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    t = data[0]
    idx = 1
    ans = []

    for _ in range(t):
        n = data[idx]
        idx += 1

        deg = [0] * n

        for _ in range(n - 1):
            u = data[idx] - 1
            v = data[idx + 1] - 1
            idx += 2
            deg[u] += 1
            deg[v] += 1

        if max(deg) <= 2:
            ans.append("1")
        else:
            ans.append("2")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```入力パーサーは使用します`sys.stdin.buffer.read()`頂点の総数が 100 万に達する可能性があり、入力全体を一度に読み取ることで、多くの小さなエラーによるオーバーヘッドが回避されるためです。`input()`呼び出します。 

各テスト ケースについて、コードは次数配列のみを保存します。 すべてのエッジで 2 つのエンドポイントの次数が増加するため、隣接リストを構築する必要はありません。 

条件`max(deg) <= 2`決定ステップ全体です。 ツリーにはサイクルを含めることはできないため、すべての頂点次数が最大 2 であると、ツリーは単一のパスになります。 他のすべてのツリーの場合、答えは正確に 2 です。 

距離の計算やトラバースがないため、不必要な作業が回避されます。 値は通常の Python 整数としては十分小さいので、可能な最大次数は次のとおりです。`n - 1`。

## 特殊なケース

 パス状のツリーの場合:```
5
1 2
2 3
3 4

```度数は`[1, 2, 2, 2, 1]`。 最大次数は 2 であるため、アルゴリズムは 1 を返します。訪問順序は単純にチェーンを一方の端からもう一方の端までたどることができます。 

分岐ツリーの場合:```
5
1 2
1 3
1 4
1 5
```度数は`[4, 1, 1, 1, 1]`。 センターのレベルは4なので、日帰りの散歩は不可能です。 アルゴリズムは 2 を返します。これは、距離 2 のジャンプを介して他のリーフからリーフに到達できるという事実と一致します。 

バランスの取れた大規模なツリーの場合、多くの頂点の次数は 3 ですが、アルゴリズムはジャンプをシミュレートする必要はありません。 分岐頂点の存在のみをチェックし、すぐに 2 を返します。ツリー スクエアのハミルトニアン プロパティは、そのようなケースをすべて処理します。
