 ## 解決策
 ## 問題の理解

 各ノードが時点を表し、各ノードが負ではないダメージ値を保持するツリーが与えられます。 ノードのサブセットは特別としてマークされており、ノード 1 から開始して、最終的にはこれらすべての特別なノードを任意の順序で訪問する必要があります。 

2 つのノード間を移動するときは常に、その移動のコストは、それらを接続する固有のパスに沿った最大ダメージ値によって定義されます。 パスを通過すると、そのパス上のすべてのノードのダメージ値は永続的にゼロに減らされるため、将来の通過では、たとえそれらが後のパス上にあったとしても、それらのノードに再び支払いが発生することはありません。 

タスクは、この「初回のみ」の最大オンパス ルールに基づいて、累積移動コストの合計を最小化する特別なノードを訪問する順序を選択することです。 

制約は最大 20 万ノードにまで及ぶため、パスの最大値を再計算したり、各移動を直接シミュレートしたりするアプローチは即座に除外されます。 単一の全ペア パス クエリでも遅すぎます。 繰り返される走査を圧縮し、パス情報を最初から再計算することを避ける構造が必要です。 

特別なノードを訪問することについて貪欲に考えると、微妙な困難が現れます。 2 つのノード間を移動するコストは、そのパス上の最大ノードの重みによって異なりますが、ノードが一度使用されると、その後のすべてのパスには無関係になります。 これは、エッジの重みが固定されているという通常の仮定を打ち破ります。 移動のたびにコストが変化するため、単純な最短パスやシュタイナー ツリーのアプローチは直接適用されません。 

素朴な考えを打ち破るエッジ ケースには、2 つの特別なノード間の最適なパスが他のペアと高重みのノードを共有する状況が含まれます。 間違った順序でアクセスすると、より適切な順序で早くノードを「消費」できたとしても、そのハイノードに対して複数回支払うことになる可能性があります。 たとえば、非常に大きなダメージを負った単一のノードが特別なノード間の多くのパス上にある場合、そのノードの通過を遅らせる順序でペアを訪問すると、たとえ正しい戦略によって最大 1 回の支払いが確実に行われるとしても、単純なシミュレーションでは大きなコストが繰り返し発生することになります。 

## アプローチ

 直接シミュレーションでは、訪問する特別なノードのすべての順列が試行されます。 移動ごとに、LCA または DFS 前処理を使用してパスに沿った最大ノード値を計算します。 各クエリのコストは O(log N) で、移動が M 回あるため、各置換のコストは O(M log N) ですが、M 個の階乗置換ではこれは不可能になります。 

順序を修正してパス クエリを最適化したとしても、トラバース後にノード値が変化するという基本的な問題に依然として直面するため、再計算が必要になるか、残りのアクティブなノードの動的構造を維持する必要があります。 

重要な観察は、各ノードのダメージが最大 1 回支払われ、それを最大値として必要とするパスが最初に通過したときに正確に支払われるということです。 特別なノード間のパスの観点から考える代わりに、視点を逆にすることができます。つまり、各ノードはその重みを最大 1 回だけ提供し、それが必要な接続で最大になるかどうかを判断する必要があります。 

これは当然、ダメージの大きい順にノードを処理することを示唆しています。 値 D を持つノードを考えるとき、このノードは、以前に処理された上位ノードを介してまだ「接続」されていない特別なノード間で実現する必要がある接続上に存在するか? 「はい」の場合、このノードは 1 回支払う必要があります。これは、これらのコンポーネントを最初に接続した時点で、そのパス上に残っている最大の重みになるからです。

これは、ツリー上の DSU (素集合結合) を使用してモデル化できます。 ダメージの降順にノードをアクティブにします。 最初は特別なノードのみが「必須エンドポイント」としてマークされ、損傷しきい値が下がるにつれて徐々にノードを接続します。 ノードを処理するときは、そのノードをすでにアクティブ化されている隣接ノードと結合します。 これにより、両方に特別なノードを含む 2 つのコンポーネントがマージされる場合、現在のノードがその接続を可能にするボトルネックとなり、そのマージに対してそのダメージが 1 回追加されます。 

この問題は、ノードの重みが「アクティブ化時間」として機能するツリー上のクラスカルのようなプロセスに帰着し、特殊なノードのフォレストを効果的に構築しています。 2 つの特別なコンポーネントがマージされるたびに、現在のノード値を 1 回支払います。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列 + パス クエリに対するブルート フォース | O(M! · M log N) | O(N) | 遅すぎる |
 | 重みでソートされたノード上の DSU | O(N α(N)) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのノードをダメージ値の降順に並べ替えます。 これは、ダメージの大きいノードが最初にパス コストを支配するノードであるため、最もリスクの高いノードから最もリスクの低いノードへと段階的にノードを「アクティブ化」すると解釈します。 
2. 各ノードが最初に独自のセットを形成する DSU 構造を維持します。 また、各セットに現在少なくとも 1 つの特別なノードが含まれているかどうかも維持します。 2 つの特別な含有コンポーネントが結合する場合のみを考慮するため、これは不可欠です。 
3. ノードがアクティブ化されているかどうかを追跡する配列を維持します。 ソートされた順序でノードを処理し、ノードが処理されると、そのノードをアクティブとしてマークし、ツリー内ですでにアクティブになっているすべての隣接ノードと結合しようとします。 これにより、現在のしきい値の下で実行可能なパスに正確に沿って接続が構築されます。 
4. 2 つのコンポーネント間でユニオンを実行する場合、両方のコンポーネントに少なくとも 1 つの特別なノードが既に含まれているかどうかを確認します。 両方がそうである場合、それらを接続することは最終的な訪問計画にとって意味があり、現在のノードのダメージ値を一度答えに追加します。 その後、コンポーネントをマージし、どちらかの側が特別なノードを含む場合には、マージされたコンポーネントに特別なノードが含まれるという事実を伝達します。 
5. すべてのノードが処理されるまで続行します。 累計したものが最終的な答えとなります。 

2 つの特別なコンポーネントがマージする場合にのみ値を追加する理由は、この瞬間が、これらの領域を接続する利用可能な最高の重みとしてこのノードを介してパスが初めて「強制」されることに対応するためです。 それ以降の走査は、すでにアクティブ化されているため、すでに考慮されている、より低いまたは等しい重みのノードのみを通過します。 

なぜ効果があるのか

 降順スイープのどの時点でも、アクティブ ノードは、最大ノード重みが少なくとも現在のしきい値であるパスによって接続されたコンポーネントのフォレストを形成します。 特別なノードを含む 2 つのコンポーネントが最初に接続されるとき、それらの特別なノード間のすべてのパスは現在のノードまたは同等以上の重みを持つ別のノードを通過する必要がありますが、そのようなノードはまだ、代替の安価な接続を可能にする方法で完全にアクティブ化されていません。 したがって、現在のノードは、これらのコンポーネント間の接続を可能にする最小限のボトルネックであり、最終コストに 1 回だけ寄与します。 これにより、必要な接続パスの最大値として最初に必要になったときに、すべてのノードが正確に充電されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n
        self.has_special = [False] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False, False

        if self.sz[a] < self.sz[b]:
            a, b = b, a

        self.p[b] = a
        self.sz[a] += self.sz[b]

        before = self.has_special[a] and self.has_special[b]
        self.has_special[a] = self.has_special[a] or self.has_special[b]

        return before, a

def main():
    n, m = map(int, input().split())
    special = set(map(lambda x: int(x) - 1, input().split()))
    d = list(map(int, input().split()))

    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    order = sorted(range(n), key=lambda x: -d[x])
    active = [False] * n
    dsu = DSU(n)

    for x in special:
        dsu.has_special[x] = True

    ans = 0

    for x in order:
        active[x] = True
        for y in adj[x]:
            if active[y]:
                merged_before, root = dsu.union(x, y)
                if merged_before:
                    ans += d[x]

    print(ans)

if __name__ == "__main__":
    main()
```DSU は、すでにアクティブ化されているノードを介してのみ接続を維持します。これにより、最大ノード値が少なくとも処理中の現在のノードであるパスのみが考慮されることが保証されます。 の`has_special`flag は、コンポーネントに必要なノードが含まれているかどうかを追跡するため、2 つの意味のあるコンポーネントがマージされた場合にのみ料金が発生します。 

実装の重要な詳細は、アクティブ化の瞬間ではなく結合の瞬間にノード値を追加することです。これは、アクティブ化だけでは接続要件が満たされることが保証されないためです。

 ## 特殊なケース

 重要なエッジ ケースは、高重みノードがアクティブ化された後、複数の特別なノードが同じ初期コンポーネント内に存在する場合です。 アルゴリズムは二重カウントを回避する必要があります。 中心が最も高い重みを持ち、すべての葉が特別なノードである星型ツリーでは、中心は 1 回だけ寄与する必要があります。 ノードが最高位から最低位にアクティブ化されると、各リーフは特殊対特殊のマージをトリガーせずに中心に接続します。 2 番目のリーフが接続される場合にのみ、2 つの特殊なコンポーネント間のマージが発生し、中央のウェイトが 1 回追加されます。 

もう 1 つのケースは、特殊なノードが元のツリー内ですでに隣接している場合です。 接続パスに重みの高いノードが含まれていない場合でも、DSU はそれらを早期にマージしますが、最初の結合の時点ではどちらのコンポーネント ペアも同時に「特殊完全」ではないため、コストが誤って追加されることはありません。 コストは、両側に独立してすでに特別なノードが含まれている場合にのみ表示されます。これは、シングルエッジ接続では早期に発生することはありません。
