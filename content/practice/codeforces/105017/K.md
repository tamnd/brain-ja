 ## 解決策
 ## 問題の理解

 高さのある単位正方形で形成されたグリッドが与えられます。$N$と幅$M$。 このグリッド内で、考えられるすべてのサイズを考慮して、軸に沿った正方形がいくつ存在するかを数えたいとします。 正方形の辺$k$内に完全に収まる場合は有効です。$N \times M$ボードを作成し、そのような正方形を配置できるすべての個別の位置を数えます。 

したがって、タスクは、最大の正方形を見つけたり、存在を確認したりすることではなく、考えられるすべての正方形のサイズとすべての有効な配置を合計することです。 

入力サイズの制約により、$N, M \le 10^6$。 これにより、正方形を明示的に列挙しようとするメソッドは即座に除外されます。 すべてのグリッド セルを 1 回反復するだけでも問題ありませんが、すべての正方形を個別に考慮しようとすると、爆発的に約$O(N^2 M^2)$最悪の場合、それは実現可能な限界をはるかに超えています。 

ここでの一般的な失敗モードは、各正方形サイズを独立して処理しながらも、すべての位置を単純に反復処理することです。 たとえば、それぞれについて$k$、すべてを反復します$(i, j)$有効性をチェックすると、$O(NM \cdot \min(N,M))$、両方の次元が大きい場合、すでに大きすぎます。 

もう 1 つの微妙な問題はオーバーフローです。 正方形の数は、寸法に応じて立方体的に増加し、およそ次のようになります。$N^3$したがって、中間計算では 64 ビット整数を使用する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です: 正方形のサイズを固定します$k$をスライドさせてから、$k \times k$グリッド上のウィンドウを表示し、すべての有効な位置をカウントします。 固定の場合$k$、 がある$(N-k+1)(M-k+1)$配置。 以上をまとめると$k$から$1$に$\min(N, M)$は正しい答えを出します。 これは概念的には単純で、すでに最終的な式に近いものです。 

ただし、これをネストされたループとして直接計算すると、$k$、$i$、 そして$j$3 つのネストされたループに縮退します。 総作業量は、$$\sum_{k=1}^{\min(N,M)} (N-k+1)(M-k+1),$$これは数学的には問題ありませんが、単純な方法で反復的に評価すると高価になります。 

重要な観察は、各正方形サイズのカウントが独立しており、閉じた形式に従っていることです。 すべての配置を繰り返す代わりに、サイズごとに存在する位置の数を直接計算し、それらを合計します。 これにより、内側のループが完全に削除され、問題は可能な辺の長さにわたる単一の直線パスに軽減されます。 

そして、答え全体が単なる合計であることがわかります。$k$で計算できます。$O(\min(N,M))$時間。

 | 最適 |$O(\min(N,M))$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 限界寸法を特定する$L = \min(N, M)$。 これは、正方形の最大の辺の長さです。 これより大きな正方形は、少なくとも 1 つの次元に沿ってグリッドに収まることはできません。 
2. 考えられる正方形サイズごとに$k$から$1$に$L$、有効な配置の数を計算します。 正方形の大きさ$k$からの任意の行から開始できます$1$に$N-k+1$および任意の列$1$に$M-k+1$、したがって、位置の数は$(N-k+1)(M-k+1)$。 
3. この値を応答変数に累積します。 各項は、そのサイズの個別の正方形の数に寄与します。 
4.すべての処理が完了したら$k$、累積合計を出力します。 

この直接加算が効率的に機能する理由は、各正方形がその左上隅と辺の長さによって一意に識別されるため、反復間での重複や二重カウントが発生しないためです。 

### なぜ効果があるのか

 グリッド内のすべての有効な正方形は、次の 2 つの選択肢によって一意に決定されます: その辺の長さ$k$、およびその左上の座標$(i, j)$。 固定の場合$k$、 有効$i$有効範囲とは独立した範囲$j$、両方の範囲は連続しており、グリッドの境界によって完全に決定されます。 アルゴリズムはすべての有効なペアを列挙します$(k, i, j)$因数分解されたカウントを通じて正確に 1 回実行されるため、設定が失われることはなく、二重にカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, M = map(int, input().split())

L = min(N, M)

ans = 0
for k in range(1, L + 1):
    ans += (N - k + 1) * (M - k + 1)

print(ans)
```実装は、派生したカウント式に直接従います。 ループ変数`k`正方形の辺の長さを表します。 それぞれについて`k`、`(N - k + 1)`正方形が取れる垂直位置の数を数えます。`(M - k + 1)`水平位置をカウントします。 彼らの製品は配置数を示します。 

微妙だが重要な詳細は、ループが次の位置で停止する必要があるということです。`min(N, M)`。 それを超えて継続すると、マイナスの寄与が生成されますが、これは無意味であり、合計が破損します。 

すべての算術演算は Python 整数を使用して行われ、オーバーフローを心配することなく大きな値を自然に処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N, M = map(int, input().split())
    L = min(N, M)
    ans = 0
    for k in range(1, L + 1):
        ans += (N - k + 1) * (M - k + 1)
    return str(ans)

# provided samples
assert run("2 3\n") == "8"
assert run("4 4\n") == "30"

# custom cases
assert run("1 1\n") == "1", "single cell grid"
assert run("1 5\n") == "5", "only 1x1 squares possible"
assert run("2 2\n") == "5", "small symmetric grid"
assert run("3 5\n") == str(sum((3-k+1)*(5-k+1) for k in range(1,4))), "formula consistency"

 ## 特殊なケース

 主なエッジ ケースは、1 つの次元が 1 の場合です。入力の場合`1 5`、サイズ 1 の正方形のみが存在します。 The algorithm sets$L = 1$、だからそれだけ$k = 1$加工され、生産されます$(1-1+1)(5-1+1) = 5$これは、すべてのセルが有効な 1×1 正方形であるという事実と一致します。 

もう 1 つのエッジ ケースは、可能な限り最小のグリッドです。`1 1`。 ここ$L = 1$、単一の貢献は$(1)(1) = 1$。 より大きな反復は発生しないため、無効な負の値は考慮されません。 

次のような正方形グリッドの場合`4 4`、1 から 4 までのすべての辺の長さは、徐々に小さいカウントに寄与します。 アルゴリズムは、特別なケースを使用せずにこれを自然に処理します。$(N-k+1)(M-k+1)$範囲全体にわたって有効です。
