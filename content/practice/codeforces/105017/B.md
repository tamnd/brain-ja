 ## 解決策
 ## 問題の理解

 何度も繰り返される非常に単純なランダムプロセスをシミュレートしています。 サイズの配列から始めます$n$、最初はすべてゼロです。 それから私たちはパフォーマンスします$m$独立した操作があり、各操作は次のいずれかを選択します。$n$均一にランダムに配置し、1 ずつ増分します。 すべての操作の後、ランダムな分布で終了します。$m$配列全体で増分します。 

重要なのは正確な最終的な配列ではなく、少なくとも 1 つの位置が指定されたしきい値以上の値に達するというイベントです。$K$。 つまり、投げた後、$m$同一の「単位増分」$n$ビンを一様にランダムに配置する場合、一部のビンに少なくとも次のものが含まれる確率が必要です。$K$増加します。 

制約は十分に小さいため、カウントを含む状態に対する多項式時間動的計画法ソリューションが実現可能です。 両方$n$そして$m$最大でも 300 なので、解決策は何でもよい$O(nm^2)$または$O(nmK)$制限時間内で快適に通過します。 これにより、すべての指数関数的な列挙が即座に排除されます。$n^m$これは、考えられるあらゆる選択肢のシーケンスを直接シミュレートすることに相当します。 

微妙なエッジケースが現れるのは、$K = 0$。 その場合、すべての要素は自動的に少なくとも$0$したがって、答えは常に 1 です。もう 1 つのエッジケースは次のとおりです。$K > m$。単一の位置はこれ以上の値を受け取ることができないため、どの要素も到達することは不可能です。$m$増加します。 この場合、答えは 0 です。これらのケースは、純粋に組み合わせによる定式化では見落とされがちですが、プロセスに関する推論から自然に抜け落ちます。 

## アプローチ

 直接的なアプローチでは、すべてをシミュレートします。$m$ステップを計算し、有効な最終構成を生成する一連の選択の数をカウントします。 各ステップには、$n$選択肢があるので、$n^m$合計シーケンス。 たとえ$n = 300$そして$m = 300$、これは天文学的に大きいため、直接列挙することは不可能です。 

重要な変化は、一連の操作について考えるのをやめ、代わりに各インデックスが何回選択されるかを考えることです。 すべての結果はベクトルに対応します$(a_1, a_2, \dots, a_n)$合計が$m$、そしてそれぞれ$a_i$は回数インデックスです$i$が選ばれました。 このような構成の確率は、多項係数のみに依存します。 

私たちが望むイベントは、「すべて」を補完するものです。$a_i \le K-1$したがって、構成を直接カウントする代わりに、$a_i \ge K$、すべてが含まれる構成を数える方が簡単です。$a_i \le K-1$、1から減算します。 

有効な構成をカウントするには、ビンに対する動的プログラミングを使用します。 インデックスを 1 つずつ処理し、これまでに配布された増分数を維持します。 各ビンについて、0 から 0 までのすべての可能な値を試します。$K-1$、多項係数から得られる階乗項によって重み付けされた寄与を蓄積します。 これにより、問題は 300 × 300 の州にわたる境界のあるナップザック スタイルの DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのシーケンスを列挙する |$O(n^m)$|$O(1)$| 遅すぎる |
 | 制限されたカウントを持つビン上の DP |$O(n \cdot m \cdot K)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 補数イベントの確率を計算します。すべての要素は最大でも受け取ります。$K-1$増加します。 させて$dp[i][j]$最初の値を使用して有効な分布の加重合計を表します。$i$まさにそのようなインデックス$j$これまでに増分が割り当てられており、各構成は次の係数に寄与します。$1 / (a_1! a_2! \dots a_i!)$。 

1. すべての値がゼロになるテーブルを初期化し、$dp[0][0] = 1$。 これは、ビンを割り当てる前に、ゼロ増分を割り当てる空の方法が 1 つだけ存在することを表します。 
2. 各インデックスを反復処理します。$i$1から$n$。 各ステップで増分数を決定します$t$インデックスに入る$i$、 しかし$t$範囲に制限されています$0 \le t \le \min(K-1, m - j)$。 これにより、グローバル合計とビンごとの制限の両方が確実に尊重されます。 
3. それぞれの可能な合計について$j$0から$m$、以前の状態からの寄与を追加して DP を更新します。$$dp[i][j] += \frac{dp[i-1][j-t]}{t!}$$この除算は$t!$代入の内部順列を説明します。$t$ラベル付き操作を同じビンに追加します。 
4. すべてのビンを処理した後、$dp[n][m]$すべての有効な数量分布の合計が含まれます$1 / (a_1! \dots a_n!)$。 
5. この値を乗算します。$m!$有効な操作シーケンスの数を回復します。 考えられるすべてのシーケンスの合計数は次のとおりです。$n^m$、それぞれの$m$操作は独立して次のいずれかを選択します$n$インデックス。 
6. 最終的な確率は次のとおりです。$$\text{answer} = 1 - \frac{\text{valid sequences}}{n^m}$$この正しさは、すべての演算シーケンスが多項カウント ベクトルに一意に対応しており、DP は、座標が次の値を超えないという制約の下でそのようなベクトルをすべて列挙するという事実から生まれます。$K-1$同時に、同一の割り当ての順列の数を正確に考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, K = map(int, input().split())

    if K == 0:
        print(1.0)
        return
    if K > m:
        print(0.0)
        return

    # factorials up to m
    fact = [1.0] * (m + 1)
    for i in range(1, m + 1):
        fact[i] = fact[i - 1] * i

    dp = [[0.0] * (m + 1) for _ in range(n + 1)]
    dp[0][0] = 1.0

    for i in range(1, n + 1):
        for j in range(m + 1):
            if dp[i - 1][j] == 0:
                continue
            max_add = min(K - 1, m - j)
            base = dp[i - 1][j]
            for t in range(max_add + 1):
                dp[i][j + t] += base / fact[t]

    good = fact[m] * dp[n][m]
    total = float(n) ** m
    ans = 1.0 - good / total
    print(ans)

if __name__ == "__main__":
    solve()
```コードは DP 解釈に直接従います。 階乗配列は、繰り返しの計算を避けるために事前に計算されます。$t!$内側のトランジション。 DP テーブルは、次の形式の貢献を蓄積します。$1 / (a_i!)$、そして最後の乗算$m!$真の多項カウントを再構築します。 

ここでよくある間違いは、階乗がなぜ現れるのかを忘れてしまうことです。 これらは任意の重みではなく、「区別できないカウントの分布」を「ラベル付けされた一連の操作のカウント」に変換する正確な補正係数です。 

もう 1 つの微妙な点は、数値の安定性です。 DP は最終スケーリング ステップの前に正規化された階乗分数を累積するため、値は倍精度にとって十分小さいままです。 

## 実用的な例

 小さな例を考えてみましょう。$n = 2$、$m = 3$、$K = 2$。 少なくとも 1 つのビンに少なくとも 2 つの増分がある確率が必要です。 補足として、両方のビンの増分は最大 1 です。 

DP 状態を 2 つのビンにわたる分布として追跡します。 

| i (使用されたビン) | j (割り当てられた合計) | dp 値の概念的な説明 |
 | --- | --- | --- |
 | 0 | 0 | 1 |

 最初のビンを処理した後、0 または 1 個のアイテムを取得できるようにします。 

| 私 | j | トランジション |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 1 | 1 | 1 |

 2 番目のビンを処理した後、残りのアイテムを同じ制約の下で配布します。 

| 私 | j | DP |
 | --- | --- | --- |
 | 2 | 0 | 1 |
 | 2 | 1 | 2 |
 | 2 | 2 | 1 |
 | 2 | 3 | 0 |

 それで$dp[2][3] = 0$これは、ビンが容量 1 を超えずに 3 つの増分を分配する方法がないことを意味します。 したがって、確率は 1 であり、これは 3 つのボールと 2 つのビンの場合、一部のビンは少なくとも 2 を受け取る必要があるという事実と一致します。 

このトレースは、ラベル付き操作のすべての分布を考慮しながら、DP がどのようにビンごとの上限を強制するかを示しています。

 ## 特殊なケース

 いつ$K = 0$の場合、「少なくとも 1 つの要素 ≥ K」という条件は常に true です。 アルゴリズムはこれを DP の直前に処理し、状態計算を行わずに 1 を返します。 

いつ$K > m$、インデックスは十分な増分を蓄積できません。$m$トータルオペレーション。 早期リターンにより不必要な計算が回避され、正しく 0 が出力されます。 

いつ$n = 1$、すべての増分は単一の位置に入る必要があるため、結果は次のいずれかであるかどうかの決定的なチェックになります。$m \ge K$。 DP は 1 つのパスに折りたたまれ、最終的な乗算は次のようになります。$m!$正確に 1 つの有効なシーケンスを正確に再構築します。 

いつ$m = 0$の場合、配列はすべて 0 のままであるため、答えは次のとおりであるかどうかによってのみ決まります。$K \le 0$。 DP は当然これを基本状態のみで表します。$dp[0][0]$ただし、初期のケースでは処理が簡素化され、階乗論理におけるゼロ除算スタイルの混乱が防止されます。
