 ## 解決策
 ## 問題の理解

 この問題は、候補者のグループと候補者間の友情について説明しています。 選択された 2 人の候補者が友人にならないように、考えられるグループ サイズごとに候補者のグループが何グループ選択できるかをカウントする必要があります。 グラフの用語では、各候補は頂点であり、各友情はエッジであるため、サイズごとにグループ化された独立したセットをカウントしています。 出力には、0 から 0 までのサイズごとに 1 つの値が含まれます。`n`ここで、値は、正確にその数の頂点を含む独立セットの数です。 

候補者の数は 40 に達する可能性があります。これが重要な制限です。 すべてのサブセットを直接カウントするには、最大のチェックが必要となるため、通常のグラフ走査や頂点に対する動的プログラミングだけでは十分ではありません。`2^40`可能性としては、約 1 兆の州があります。 非常に高速な実装であっても、数秒以内にこれを処理することはできません。 この制限は、問題をより小さな部分に分割することを強く示唆しています。`2^20`わずか約 100 万であり、管理可能です。 

見落としやすいケースもございます。 友情がない場合、すべてのサブセットが有効です。 例えば：```
3 0
```答えは次のとおりです。```
1 3 3 1
```ペアをカウントするだけのソリューションや、候補を貪欲に選択しようとするソリューションは、考えられるすべてのグループが機能するため失敗します。 

もう 1 つのケースは、グラフが完成したときです。```
3 3
1 2
1 3
2 3
```答えは次のとおりです。```
1 3 0 0
```空のグループと単一の候補者のみが許可されます。 異なる半分の頂点間の競合をチェックするのを忘れた不注意な実装により、無効なグループがカウントされる可能性があります。 

3 番目のエッジ ケースは、接続されていないグラフです。```
4 2
1 2
3 4
```答えは次のとおりです。```
1 4 4 0 0
```ペア`(1,3)`、`(1,4)`、`(2,3)`、 そして`(2,4)`は有効ですが、サイズ 3 のグループは存在しません。 サイズを正しく組み合わせずに 2 つの連結コンポーネントを個別に処理すると、誤ったカウントが得られる可能性があります。 

## アプローチ

 直接的なアプローチは、候補者のすべてのサブセットを調べて、そこに友情の要素が含まれているかどうかを確認することです。 それぞれについて、`2^n`サブセットの場合、選択した候補をスキャンし、選択した 2 つの頂点が接続されていないことを確認します。 この方法は正しいです。考えられるすべてのグループが 1 回だけ考慮されるからです。 問題は、`n = 40`、サブセットの数は約`1,099,511,627,776`したがって、操作数は時間内に実行できる数をはるかに超えています。 

有益な観察は、グラフが完全に列挙するには大きすぎるが、分割するには十分小さいということです。 頂点をそれぞれ最大 20 個の頂点からなる 2 つの半分に分割すると、各半分には最大 20 個の頂点が含まれます。`2^20`サブセット。 半分のすべてのサブセットを列挙し、どれが内部的に有効であるかを判断し、それらを残りの半分と組み合わせるのに役立つ情報を保存できます。 

左半分のサブセットの場合、重要な情報はそのサイズだけでなく、それとともに選択できない右半分の頂点も重要です。 左側の各頂点には、右側に隣接する頂点のビットマスクがあります。 選択した左側の頂点に対してこれらのマスクの OR を計算することで、禁止されている右側の頂点がわかります。 残りの右側の頂点は使用可能です。 

右半分は動的プログラミング配列で前処理できます。 右頂点のすべてのマスクについて、そのマスク内に含まれる有効な独立したサブセットの数をサイズごとに分けて保存します。 次に、すべての有効な左サブセットは、許可されたマスクを確認することによって、互換性のある右サブセットを選択する方法の数をクエリできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | お(1) | 遅すぎる |
 | 最適 | O(2^(n/2) * n) | O(2^(n/2) * n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点を 2 つのグループに分割します。 最初のグループに次のものを含めます`a`頂点と 2 番目のグループには以下が含まれます`b`両方の値が最大 20 である頂点。これにより、指数部分が次の値から減少します。`2^40`くらいまで`2^20`。 
2. 2 番目のグループのすべてのサブセットを列挙し、それが独立したセットであるかどうかを判断します。 有効なサブセットごとに、そのサイズを保存します。 保存された情報は、後で「この利用可能なセット内に各サイズの有効な右側のグループがいくつ収まるか?」という答えを返します。 
3. 2 番目のグループに対してサブセット動的プログラミング テーブルを構築します。 正確なマスクの値から始めて、より大きなマスクに情報を伝播します。 この後、マスクのクエリにより、マスク内に各サイズの独立したサブセットがいくつ含まれているかがわかります。 
4. 最初のグループのすべてのサブセットを列挙します。 最初のグループ内で独立しているかどうかを確認します。 そうでない場合は、残りの半分から頂点を追加しても内部の友情を修復できないため、それを破棄します。 
5. 有効な左側のサブセットごとに、その友情によってブロックされている右側の頂点のビットマスクを計算します。 このマスクを反転して、引き続き使用できる右側の頂点を取得します。 
6. 使用可能な右側マスクの保存されたカウントを答えに追加します。 最終的なグループのサイズは、左側のサブセット サイズに選択した右側のサブセット サイズを加えたものになります。 

これが機能する理由: 元のグラフ内のすべての独立集合は、左半分に属する部分と右半分に属する部分に一意に分割できます。 左側の部分は内部競合がないかチェックされ、右側の部分は左側の友情によって禁止されていない頂点の中でのみカウントされます。 右側の前処理では、許可されたマスク内のすべての有効なサブセットが正確にカウントされるため、考えられるすべての独立セットが 1 回カウントされ、無効なセットは含まれません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    left = n // 2
    right = n - left

    g_left = [0] * left
    g_right = [0] * right
    cross = [0] * left

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        if a < left and b < left:
            g_left[a] |= 1 << b
            g_left[b] |= 1 << a
        elif a >= left and b >= left:
            x = a - left
            y = b - left
            g_right[x] |= 1 << y
            g_right[y] |= 1 << x
        else:
            if a < left:
                cross[a] |= 1 << (b - left)
            else:
                cross[b] |= 1 << (a - left)

    total_right = 1 << right
    dp = [[0] * (right + 1) for _ in range(total_right)]
    dp[0][0] = 1

    for mask in range(total_right):
        if mask == 0:
            continue
        bit = mask & -mask
        idx = bit.bit_length() - 1
        prev = mask ^ bit

        for k in range(right + 1):
            dp[mask][k] = dp[prev][k]

        if prev & g_right[idx] == 0:
            size = prev.bit_count()
            dp[mask][size + 1] += 1

    for bit in range(right):
        for mask in range(total_right):
            if mask & (1 << bit):
                for k in range(right + 1):
                    dp[mask][k] += dp[mask ^ (1 << bit)][k]

    ans = [0] * (n + 1)
    total_left = 1 << left

    for mask in range(total_left):
        ok = True
        blocked = 0

        for i in range(left):
            if mask & (1 << i):
                if g_left[i] & mask:
                    ok = False
                    break
                blocked |= cross[i]

        if not ok:
            continue

        available = (1 << right) - 1
        available ^= blocked

        size_left = mask.bit_count()
        for k in range(right + 1):
            ans[size_left + k] += dp[available][k]

    print(*ans)

if __name__ == "__main__":
    solve()
```各半分には最大 20 個の頂点があるため、グラフはビットマスクとして保存されます。 単一の整数で隣接する頂点を表すことができるため、競合チェックを一定時間行うことができます。 

右側の前処理では、サブセット動的プログラミングを使用します。 トランジションは、選択した 1 つの頂点を削除し、それを追加することで競合が発生するかどうかを確認します。 第 2 伝播フェーズの後、`dp[mask][k]`サイズの独立したサブセットの数を表します`k`中に含まれているもの`mask`、正確なマスク自体だけではありません。 

左側の列挙中に、条件は`g_left[i] & mask`選択した左側のサブセット内ですべての友情を完全に捕捉します。 の`blocked`マスクは、現在の左側の選択肢と一緒に表示できない右側の頂点をすべて収集します。 残りの頂点を使用すると、交差エッジが確実に尊重されます。 

この実装は、20 ビット マスクを簡単に保持できる Python 整数に依存しています。 Python の整数は自動的に増加するため、オーバーフローのリスクはありません。

1 5 7 2 0 0
```この例は、半分を結合する前に内部競合が削除されることを示しています。

3 4

 ## 特殊なケース

 空のグラフの場合:```
3 0
```右側の前処理では、すべてのサブセットが独立しているとマークされます。 左の列挙中、頂点が何もブロックしないため、左のすべての選択肢が右のすべての選択肢と結合します。 答えは二項カウントになります`1 3 3 1`。 

完全なグラフの場合:```
3 3
1 2
1 3
2 3
```隣接マスクが選択したマスクと交差するため、2 つの頂点を含む左側のサブセットはすぐに拒否されます。 生き残る選択肢は空のセットと単一の頂点だけなので、出力は次のようになります。`1 3 0 0`。 

切断された場合:```
4 2
1 2
3 4
```友情関係は完全に別のコンポーネント内にあるため、頂点 1 を選択しても頂点 3 または 4 はブロックされません。 このアルゴリズムは、クロスハーフ ブロッキング マスクを空のままにし、互換性のあるすべての右サブセットを許可します。 これにより、4 つの有効なペアが正しくカウントされ、トリプルの作成が回避されます。
