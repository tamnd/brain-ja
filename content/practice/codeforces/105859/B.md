 ## 問題の理解

 3 つの未知の正の整数を含む非常に特殊な構造から得られた 4 つの整数が与えられています。$a$、$b$、 そして$c$。 ボード上の数字は、まさに 3 つのペアごとの合計です。$a+b$、$a+c$、$b+c$、および合計$a+b+c$、しかし、彼らの順序は完全にシャッフルされています。 

私たちの仕事は、有効なトリプルを回復することです$(a, b, c)$それがこのマルチセットを生成した可能性があります。 

これについて考えるのに便利な方法は、4 つの数値のうちの 1 つが最大でなければならず、その最大の数値は強制的に次の値になるということです。$a+b+c$なぜなら、次の場合、すべてのペアごとの合計は完全な合計よりも厳密に小さいからです。$a, b, c$ポジティブです。 それが特定されると、残りの 3 つの数値はそれぞれ「合計から 1 つの変数を引いたもの」に対応するため、それぞれが次の 1 つを隠します。$a$、$b$、 または$c$。 

制約は非常に小さく、数値が 4 つだけであるため、継続的な作業以外の解決策はすでに不要です。 4 つのポジション間の割り当てを単純に列挙した場合でも、一定の係数によって制限されます。 これは、本当の課題は効率ではなく、正しい不変条件を特定することであることを意味します。 

よくある失敗例は、一貫性をチェックせずに最大値が常に合計であると想定している場合に発生します。 たとえば、入力が次の場合、`40 40 40 60`、正しい解釈は$a=b=c=20$。 誤って最大値以外の要素を合計として解釈しようとすると、再構築は即座に中断されます。 

もう 1 つの微妙なケースは、値が繰り返される場合です。 例えば、`3 6 5 4`値の一意性ではなく、ロジックによる以外に一意の順序付けのヒントはありません。 ここでは、区別性に依存するアプローチは失敗します。 

## アプローチ

 ブルートフォース解釈では、4 つの数値のそれぞれを合計候補として割り当ててから、再構築を試みます。$a, b, c$残りの3つから。 合計の各選択肢について$S$、計算します$S-x_i$他の各値について、これらの 3 つの再構成された数値が、ペアごとの合計の元のマルチセットの生成と一致しているかどうかを確認します。 選択肢が4つしかないので、$S$、これは継続的な作業です。 

これが機能するのは、構造が厳格であるためです。合計が固定されると、残りの各数値が 1 つの変数に直接マッピングされ、順列を除いて曖昧さは残りません。 

ただし、より強力なプロパティを観察することで、これをさらに単純化できます。 正しい合計は、マルチセット内の最大の要素である必要があります。 それを受け入れると、再構成は決定論的になります。合計から他の 3 つの数値をそれぞれ減算すると、すぐに復元されます。$a, b, c$。 

ブルートフォースアプローチは、数値の考えられる役割をすべて試すため機能します。 ポジティブによって厳密な順序付けの制約が課せられ、検索空間が 4 つの候補から 1 つに集約されることがわかれば、その必要はなくなります。

 ## アルゴリズムのチュートリアル

 1. 4 つの数字をリストに読み取ります。 
2. 最大の要素が最後に配置されるようにリストを並べ替えます。 
3. 最大値を合計として扱う$S = a + b + c$。 
4. 他の 3 つの値のそれぞれについて$x$、計算する$S - x$。 これらの結果は非表示の値に対応します$a, b, c$ある順序で。 
5. 3 つの再構成された値を出力します。 

ステップ 4 が有効である理由は、小さい数値のそれぞれが次のようにペアごとの合計を表すためです。$a+b$。 合計からそれを減算すると、そのペアに含まれる 2 つの変数が正確にキャンセルされ、3 番目の変数が残ります。 

### なぜ効果があるのか

 各入力数値は、ペアごとの合計または全合計のいずれかです。 すべての変数が正であるため、完全な合計はペアごとの合計よりも厳密に大きくなります。 最大値が次のように固定されると、$a+b+c$、1 つおきの数字$x$等しい必要があります$S - v$正確に 1 つの変数に対して$v$。 これにより、残りの 3 つの数値と元の変数の間に 1 対 1 のマッピングが確立され、順列までの正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    nums = list(map(int, input().split()))
    nums.sort()
    
    S = nums[3]
    
    a = S - nums[0]
    b = S - nums[1]
    c = S - nums[2]
    
    print(a, b, c)

if __name__ == "__main__":
    solve()
```ソートのステップは、合計を正しく特定することを保証するため、重要です。 並べ替えを行わない場合、合計候補として任意の要素を選択するには、検証ロジックが必要になります。 

各減算ステップは、未知の変数の 1 つを分離することに直接対応します。 出力の順序は重要ではないため、どの値がどの元の変数に対応するかを追跡する必要はありません。 

よくある間違いは、小さい数値を直接次のように割り当てようとすることです。$a, b, c$, ただし、これは減算による変換後にのみ機能します。 入力値は変数そのものではなく、それらのペアごとの集計です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    nums = list(map(int, sys.stdin.readline().split()))
    nums.sort()
    S = nums[3]
    res = [S - nums[i] for i in range(3)]
    return " ".join(map(str, res))

# provided samples

 ## 特殊なケース

 次のような値が繰り返されるシナリオ`40 40 40 60`アルゴリズムが一意性に依存していないことを示しています。 合計として最大値を選択した後も、各減算では同じ値が得られます。これは、正確に正しい再構成となります。$a=b=c$。 

次のような入力がすでに均一に近い場合`2 2 2 6`、小さい値を選択すると負の値または一貫性のない値が生成されるため、合計がどの数値であるかについての誤った仮定は、最大値が使用された場合にのみ正しく解決されます。 分類ステップにより、この障害モードが発生しないことが保証されます。 

もう 1 つの微妙なケースは、値が緊密にクラスター化されている場合です。`1 2 3 6`。 ここでは、すべての数値が合計のように見える可能性がありますが、`6`合計として機能するのに十分な大きさです。 引き算のステップにより、役割についての直感が弱い場合でも、構造がきれいに分離されます。
