 ## 解決策
 ## 問題の理解

 この問題は、生徒がクラブの会合に出席することを選択することを記述しています。 各クラブにはミーティング時間が設けられており、一定数のピザが提供されます。 ミーティングが重なっているため、同じ時間に 2 つのクラブに両方に参加することはできません。 学生には、満腹になるまでに食べられるスライスの最大数もあります。 目標は、ピザの総数を制限内に保ちながら、参加クラブ数を最大化するクラブのセットを選択することです。 

入力により、クラブの数、ピザの収容人数、そして会議時間とピザの量を含む 1 つのレコードがクラブごとに提供されます。 出力は、選択できるクラブの最大数です。 

クラブの数は 1000 に達する可能性があります。クラブのすべてのサブセットを試すソリューションでは、最大で 1000 までのチェックが必要になります。$2^{1000}$可能性はありますが、それは完全に不可能です。 ただし、時間数はわずか 24 なので、時間の次元は非常に小さいです。 これは、州が個々のクラブではなく時間に基づいて判断されるべきであることを強く示唆しています。 動的プログラミング ソリューションは大まかに言うと、$24 \times c$ピザの収容能力が最大の場合に実行可能です。$10^6$、操作数は数千万回程度にとどまるためです。 

簡単な間違いがいくつかあります。 1 つは重複ルールを忘れていることです。 例えば：```
3 10
5 2
5 3
6 5
```正しい出力は次のとおりです。```
2
```一番安いピザを最初に選ぶという貪欲なアプローチでは、5 時間目に両方のクラブが参加し、2 つの選択肢としてカウントされる可能性がありますが、5 時間目のミーティングには 1 つしか参加できないため、これは無効です。 

もう一つの問題は、ピザがゼロのクラブの扱いが間違っていることだ。 考慮する：```
2 0
1 0
2 1
```正しい出力は次のとおりです。```
1
```2 番目のクラブは生徒の定員が残っていないため参加できませんが、最初のクラブは無料なのでカウントする必要があります。 

最後のエッジケースは、複数のクラブが 1 時間を共有し、最も小さなピザを提供するクラブが最も優れたクラブではない場合です。 例えば：```
3 5
7 5
7 1
8 4
```正しい出力は次のとおりです。```
2
```7 時間目にワンスライスクラブを選択すると、8 時間目にも参加できます。 クラブを個別に処理する方法では、この相互作用が見逃される可能性があります。 

## アプローチ

 最も直接的なアイデアは、考えられるすべてのクラブのコレクションを試してみることです。 すべてのサブセットについて、選択した 2 つのクラブが同じ時間を共有していないかどうか、およびピザの合計が制限内にあるかどうかを確認します。 有効な場合、選択したクラブの最大数が維持されます。 考えられるすべての答えがサブセットの中に現れるため、これは正しいです。 問題は、$2^n$サブセットは、数十のクラブでも不可能になりますが、ここでは$n$1000にすることもできます。 

重要な観察は、重複する会議の制限は、可能な 24 時間のみに依存するということです。 時間ごとに、どのクラブを選択するかを決めるだけで済みます。 処理時間の順序は重要ではありません。ある時間にクラブを選択しても、消費されたピザの合計を除いて、別の時間に利用可能な選択肢に影響を与えることはありません。 

これにより、問題がナップザック スタイルの動的プログラムに変換されます。 時間ごとに処理します。 この状態は、時間の接頭辞を考慮した後でピザがどのくらい使用されたかを表し、その量で達成可能なクラブの最大数を保存します。 1 時間ごとに、その時間をスキップするか、その時間中に開催されるクラブの 1 つを選択します。 

クラブの総数は 1000 ですが、クラブのグループは 24 しかありません。 時間ごとに、その時間のすべてのクラブとすべての可能なピザの量を試し、実際的な制限を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適なDP |$O(24 \times n \times c)$最悪の場合 |$O(c)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのクラブを会合時間ごとにグループ化します。 各時間には、選択できるクラブのリストが表示されます。 
2. 動的プログラミング配列を作成します。`dp[x]`正確に使用して参加できるクラブの最大数を保存します`x`数時間加工した後のピザのスライス。 最初はピザの使用量が 0 個しかありませんので、`dp[0] = 0`。 
3. 24 時間を 1 つずつ処理します。 現在の時間について、前の状態として開始する新しい配列を作成します。 これは、この時間にクラブに参加しないという選択を表します。 
4. 現在の時間にすべてのクラブを試してください。 以前のピザの量ごとに`x`、このクラブのピザを追加しても容量を超えない場合は、参加クラブが 1 つ増えて新しい状態を更新します。 
5. 古い状態を新しい状態に置き換え、次の 1 時間に進みます。 
6. すべての時間が処理された後、学生には最終的にピザが残っている可能性があるため、DP 配列内の任意の場所に保存されている最大値が答えとなります。 

これが機能する理由は、数時間の処理の後、過去に関して必要な情報は、消費されたピザの量と取得したクラブの最大数だけであるためです。 その状態を作り出した正確な選択はもはや重要ではありません。 すべての有効なスケジュールは、時間の移行を通る 1 つのパスに対応し、すべての移行では、各時間から 1 つのクラブのみを選択できるというルールが尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())

    hours = [[] for _ in range(24)]

    for _ in range(n):
        t, p = map(int, input().split())
        if p <= c:
            hours[t].append(p)

    dp = [-10**9] * (c + 1)
    dp[0] = 0

    for clubs in hours:
        ndp = dp[:]

        for pizza in clubs:
            for used in range(c - pizza + 1):
                if dp[used] != -10**9:
                    ndp[used + pizza] = max(
                        ndp[used + pizza],
                        dp[used] + 1
                    )

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```入力は時間ごとにすぐにグループ化されます。 総収容人数を超えるピザがあるクラブは、有効な回答には決して含まれないため、無視されます。 

DP 配列は、到達不可能な状態に対して、ありえない負の値を使用します。 これにより、存在できない状態を誤って拡張することが回避されます。 

1 時間ごとに、`ndp`必要です。 更新が直接行われた場合`dp`、クラブを選択すると、同じ時間内のその後の選択に影響を与える可能性があり、1 時間の複数のクラブをカウントできるようになります。 別の配列は、1 時間ごとに 0 か 1 つのクラブが貢献するというルールを表します。 

ループオーバー`used`に止まります`c - pizza`これにより、容量を超えるインデックス作成が防止されます。 最大容量は大きくても時間数が固定されているため、メモリ使用量は管理しやすくなっています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().strip().split()
    sys.stdin = old

    if not data:
        return ""

    it = iter(data)
    n = int(next(it))
    c = int(next(it))

    hours = [[] for _ in range(24)]

    for _ in range(n):
        t = int(next(it))
        p = int(next(it))
        if p <= c:
            hours[t].append(p)

    dp = [-10**9] * (c + 1)
    dp[0] = 0

    for clubs in hours:
        ndp = dp[:]
        for pizza in clubs:
            for used in range(c - pizza + 1):
                if dp[used] >= 0:
                    ndp[used + pizza] = max(ndp[used + pizza], dp[used] + 1)
        dp = ndp

    return str(max(dp))

 ## 特殊なケース

 時間が重なる場合:```
3 10
5 2
5 3
6 5
```アルゴリズムは、5 時間目に 2 つの可能な選択肢を含む 1 つのグループを作成します。 5 時間を処理する場合、両方の選択肢が考慮されますが、次の 1 時間は変更されていない前の状態から始まるため、次の 1 時間まで存続できる遷移は 1 つだけです。 最終的な最良の状態は、5 時間目から 1 つのクラブを取得し、6 時間目から 1 つのクラブを取得して 2 つを生成します。 

ピザがゼロの場合:```
2 0
1 0
2 1
```1スライスのクラブは入らないのでDP前に外します。 ゼロ スライス クラブは、ピザ 0 から参加クラブが 1 つ増えたピザ 0 への移行を維持するため、答えは 1 になります。 

一番安いピザだけでは物足りない場合:```
3 5
7 5
7 1
8 4
```処理時間 7 では、5 スライスまたは 1 スライスのいずれかを取得する状態が作成されます。 後の時間は 1 スライスの状態とのみ組み合わせることができ、合計 5 つのスライスと 2 つのクラブが得られます。 これはまさに、DP が維持するように設計された決定です。
