 ## 解決策
 ## 問題の理解

 数字のみで構成され、長さが最大 100 の単一の文字列が与えられます。タスクは、この文字列が非常に具体的な対称条件を満たすかどうかを判断し、単純な「はい」または「いいえ」の判定を出力することです。 

私たちが探している構造は、純粋に、左から右に読まれた文字と右から左に読まれた文字をどのように比較するかに関するものです。 数字の算術解釈はなく、数値を解析したり変換を実行したりする必要はありません。 問題全体は、静的オブジェクトとしての文字のシーケンスに関する推論に帰着します。 

最大長はわずか 100 であるため、文字を直接検査するソリューションはすでに十分に効率的です。 文字列を繰り返しスキャンするアプローチでも、一般的な競技プログラミングの制限に比べて一定の時間で実行されます。 これにより、パフォーマンスの最適化に関する懸念が即座に排除され、正確さと境界ケースの処理に完全に焦点が移ります。 

主な微妙な点は、非常に小さな入力でのエッジの動作を認識することにあります。 単一の文字列は対称性が自明になるため、複数の文字列とは異なる動作をしますが、2 文字の文字列は両端が一致するかどうかによって必要な条件を満たす場合と満たさない場合があります。 

ここでの単純な間違いは、完全な構造を検証せずに最初と最後の文字だけをチェックするなど、部分的な観察に基づいてプロパティを仮定することです。 たとえば、入力`343`最初から最後のチェックに誤って合格する可能性がありますが、完全な対称性を確保するには完全な検証が必要です。 

## アプローチ

 簡単なアプローチは、文字列が前方と後方で同じように読み取られるかどうかを確認することです。 これは、対称の位置を比較することを意味します。最初の文字と最後の文字、2 番目の文字と最後から 2 番目の文字など、中央に到達するまで続きます。 

これを考える強引な方法は、文字列を逆にして元の文字列と比較することです。 これが機能するのは、反転によってすべての対称制約が 1 つのオブジェクト比較にエンコードされるためです。 反転文字列の構築と比較には O(n) 時間がかかるため、コストは文字列の長さに対して線形です。 

長さは最大 100 という制約があるため、繰り返しの比較や単純なスキャンであっても無視できます。 ただし、この考えを一般化すると、重要な構造的洞察は、回文チェックでは反転された文字列全体を保存する必要がないということです。 代わりに、ミラーリングされたインデックスを直接比較できるため、余分な割り当てが回避され、ロジックがより明確になります。 

ブルート フォースが機能するのは、逆の表現を明示的に構築し、等価性をチェックするためです。 比較がペアごとに独立していることが分かると、不必要なオーバーヘッドが発生し、不一致が見つかるとすぐに早期終了できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 逆にして比較 | O(n) | O(n) | 承認済み |
 | 2 点チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題の構造を最も直接的に表す 2 ポインタ法に焦点を当てます。 

1. 2 つのインデックスから始めます。1 つは文字列の先頭に、もう 1 つは文字列の末尾にあります。 これらは、文字列の対称性を保つために一致する必要がある文字を表します。 どこかの点でも異なると、対称性はすぐに破れます。 
2. 2 つのインデックスの文字を比較します。 それらが等しくない場合は、停止して文字列が対称ではないと結論付けることができます。 単一の不一致がグローバル条件に違反するため、この早期終了は有効です。 
3. 一致する場合は、両方のポインタを内側に移動し、左のインデックスを前方に、右のインデックスを後方に進めます。 これにより、すべてのミラーリングされた位置を繰り返しなく段階的に検証できるようになります。 
4. ポインタが交差するか交わるまで、このプロセスを繰り返します。 不一致が見つからずにすべての比較が完了すると、文字列は対称性の要件を満たします。 

このプロセスの背後にある理由は、すべての有効な対称文字列がすべてのミラー位置で同時に等価性を満たさなければならないということです。 各比較でグローバル構造の 1 つの必要な条件が強制されるため、それらを個別にチェックすることで完全性が保証されます。 

### なぜ効果があるのか

 このアルゴリズムは、現在のポインター範囲外のすべての文字ペアが一致することがすでに検証されているという不変条件を維持します。 各ステップにより、正確さを維持しながら文字列の未検証部分が削減されます。 どこかに不一致が存在する場合、それはミラーリングされたペアで発生するはずで、そのペアは最終的には直接チェックされます。 したがって、アルゴリズムは違反を見逃すことができず、違反が見つからずに終了した場合、文字列は対称である必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

i, j = 0, len(s) - 1
ok = True

while i < j:
    if s[i] != s[j]:
        ok = False
        break
    i += 1
    j -= 1

print("YES" if ok else "NO")
```コードは入力文字列を読み取り、その両端で 2 つのポインターを初期化します。 このループは、前述したミラーリングされた比較ロジックを強制します。 不一致が見つかった時点で、それ以上のチェックでは対称性を修復できないため、早期に終了します。 

微妙な実装の詳細は、`strip()`末尾の改行がインデックス作成を妨げないようにします。 もう 1 つの重要な点は、文字列の長さが 1 である場合の処理​​です。この場合、ループは実行されず、結果は正しくデフォルトで返されます。`YES`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    s = input().strip()
    i, j = 0, len(s) - 1
    ok = True
    while i < j:
        if s[i] != s[j]:
            ok = False
            break
        i += 1
        j -= 1
    return "YES" if ok else "NO"

# provided samples
assert run("5\n") == "YES"
assert run("43\n") == "NO"
assert run("76\n") == "NO"

# custom cases
assert run("1\n") == "YES"
assert run("11\n") == "YES"
assert run("12321\n") == "YES"
assert run("12345\n") == "NO"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | はい | 単一文字の対称性 |
 | 11 | はい | 偶数長の回文 |
 | 12321 | はい | より長い奇数長の回文 |
 | 12345 | いいえ | 明らかに非対称なシーケンス |

 ## 特殊なケース

 次のような 1 桁の入力`7`は最も単純なシナリオです。 アルゴリズムセット`i = 0`そして`j = 0`, そのため、ループは実行されません。 結果は残る`YES`これは正しいです。単一の文字列は定義上対称であるためです。 

次のような 2 文字の不一致の場合、`90`、最初の比較`s[0]`対`s[1]`すぐに失敗します。 アルゴリズムは正しく出力します`NO`不必要なチェックなしで。 

のような長い対称入力の場合`1221`、比較は次のように進行します。`(1,1)`そして`(2,2)`鏡のような位置にあります。 すべてのチェックが成功し、アルゴリズムがローカルな等価性をグローバルな対称性に正しく集約していることが確認されます。
