 ## 解決策
 ## 問題の理解

 私たちには根の生えた木が与えられています。 各ノードには「アクティビティの種類」を表すラベルがあります。 任意の 2 つのノードの場合$u$そして$v$、それらの最下位の共通祖先を調べます。$w$。 2 つの量を考慮します。それは、からのパス上の異なるアクティビティ タイプの数です。$u$まで$w$、およびからのパス上の個別のアクティビティ タイプの数$v$まで$w$。 ペアのスコアは、これら 2 つのカウントの積です。 

タスクは、すべてのペアに対してこの積を最大化するノードのペアを選択することです。 

ツリーはテスト ケース全体で大きくなり、最大で$3 \cdot 10^5$合計でノードが 2 つあるため、二次関数はすべて$n$テストケースごとには不可能です。 平$O(n \log n)$隠れ定数が極端に小さい場合を除き、ノードあたりの値は境界線に達します。 これにより、ノードのペアごとにパス情報を明示的に計算したり、候補ペアごとに DFS を介して個別のカウントを繰り返し再計算しようとするソリューションは直ちに除外されます。 

微妙だが重要なエッジケースは、長いチェーンに沿って繰り返される値から生じます。 「距離」または「深さ」を個別のカウントの代用として扱うという素朴な考えがあるかもしれませんが、アクティビティ ラベルが繰り返されると、その考えは完全に崩れてしまいます。 もう 1 つの障害モードは、最適なペアには常にリーフが含まれるか、常に深さの高いノードが含まれると想定していることです。 この積は、構造的な深さだけではなく、2 つの独立した上向きパス上のラベルの多様性に依存します。 

## アプローチ

 ブルート フォース ソリューションでは、ノードのすべてのペアが列挙されます。 各ペアについて、LCA を計算し、訪問したアクティビティ タイプのセットを維持しながら、両方のパスを上向きにトラバースして、個別の値をカウントします。 これは正しいですが、遅すぎます。 それぞれのパスのトラバースは、$O(n)$最悪の場合、$O(n^2)$ペア、与える$O(n^3)$行動。 

パスセットを繰り返し再計算するのではなく、サブツリー全体で情報を再利用する必要があります。 重要な構造的観察は、すべての有効なペアが$(u, v)$LCAによって決定されます。 ノードを修正すると$x$LCA として、問題は次のようになります。上向きのパスに寄与するサブツリー内の 1 つのノードを選択します。$u$に$x$、およびそこから上向きのパスに寄与するサブツリー内の別のノード$v$に$x$、これら 2 つの上向きパス上の個別のラベル数の積を最大化します。 

これは、ツリー上のボトムアップ DP を示唆しており、各ノードはその子孫から上に向かうパスが「どれだけリッチ」であるかについての情報を保持しますが、完全なセットを保存することは不可能です。 重要な単純化は、個別のカウントのみを考慮し、それらのカウントはパス セグメントに沿って現れる新しい色の数によって決定されることです。 

これは、古典的なリルートとマージのアイデアにつながります。つまり、各ノードは子からの情報を集約しますが、正確なセットを追跡する代わりに、上向きパスの圧縮された「最良の多様性プロファイル」を追跡し、それらを組み合わせて潜在的な LCA として各ノードで製品の候補を形成します。 

2 番目の洞察は、固定 LCA の場合、最適なペアは常に 2 つの異なる子サブツリーから、または異なるブランチを介した同じサブツリーから得られるということです。 したがって、各ノードでは、個別の子ブランチからの上位の寄与を結合することのみを考慮する必要があります。 

これにより、問題は、各ノードに対して、各サブツリーからの最良の上向きダイバーシティ値の小さなセットを維持し、それらを貪欲に組み合わせるというものに軽減されます。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、サブツリー内のノードからそのノードに至るパスの可能な限り最良の「ダイバーシティ寄与度」をノードごとに計算し、各ノードを潜在的な LCA として使用して、2 つのそのような寄与度を結合することです。 

ボトムアップで進めていきます。 

1. ノードでツリーをルート化します$1$。 これにより親子方向が固定され、LCA へのすべてのパスをサブツリー内で上向きのセグメントに分割できるようになります。 
2. 各ノードについて、そのノードで終わる上向きのパスを表す構造を計算します。 各ノードについて$u$、サブツリー内のノードから次のノードに至るまでのパス上にいくつの異なる色が現れるかを説明する候補値のリストを維持します。$u$。 これは子をマージすることで構築できます。 

主な理由は、子サブツリー内のノードからノードへのパスはすべて、$u$はその子を通過する必要があるため、追加することで子の寄与を拡張できます。$a_u$まだカウントされていない場合。 
3. 子を親にマージする際、最良の少数の貢献のみを保持します。 これが機能する理由は、製品を最大化するためには、大きな多様性値のみが重要であり、支配的な小さな値は最適な製品に決して関与しないためです。 
4. ノードの上向き寄与を計算した後$x$、 扱う$x$潜在的な LCA として。 ここで、次の異なる子サブツリーからの貢献を組み合わせることを検討します。$x$。 各子サブツリーは、次で終わる上向きダイバーシティ値のマルチセットを提供します。$x$。 
5. 2 つの異なる子ブランチからの 2 つの最大の有効な寄与を取得し、それらの積を計算します。 ノードにおけるそのようなすべての組み合わせの最大値$x$は回答候補です。$x$それがLCAです。 

2 つのノードに LCA がある場合、この手順は正しいです。$x$、への道$x$の異なる子サブツリーに存在します$x$、したがって、彼らの貢献はさまざまなブランチから来ています。 
6. すべてのノードの最大値を取得します。 

### なぜ効果があるのか

 ノードの各ペアには固有の LCA があります。 その LCA では、ノードへの 2 つのパスは、LCA 自体を除いて互いに素であり、異なる子サブツリーに存在します。 各側からの寄与は、そのサブツリーの上向きパスの多様性にのみ依存します。 すべてのサブツリーの寄与を計算し、異なる子間でのみ結合することにより、構造分解の観点からすべての有効なペアを 1 回だけ正確に使い果たします。 DP は、最適な組み合わせに必要な可能な限り最良の上向きダイバーシティ情報をすべてのノードに対して確実に保存するため、圧縮中に最適なペアが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parent = [0] * n
        g = [[] for _ in range(n)]

        arr = [0] * n

        p = list(map(int, input().split()))
        for i in range(1, n):
            parent[i] = p[i-1] - 1
            g[parent[i]].append(i)

        arr = list(map(int, input().split()))

        # compress colors
        # keep as is; values are up to n, fine

        ans = 0

        # each node returns a list of best upward distinct counts
        def dfs(u):
            nonlocal ans

            # store best contributions from each child
            child_lists = []

            for v in g[u]:
                child_lists.append(dfs(v))

            # build upward contributions from u
            # start with path consisting of u only
            cur = {arr[u]: 1}

            for lst in child_lists:
                new_cur = dict(cur)
                for c, val in lst.items():
                    # extend path to u
                    if c == arr[u]:
                        new_val = val
                    else:
                        new_val = val + 1
                    if c not in new_cur or new_val > new_cur[c]:
                        new_cur[c] = new_val
                cur = new_cur

            # combine children contributions for LCA = u
            best = []

            for lst in child_lists:
                best.append(max(lst.values()) if lst else 1)

            best.sort(reverse=True)

            if len(best) >= 2:
                ans = max(ans, best[0] * best[1])

            return cur

        dfs(0)
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、DFS を実行し、各ノードを潜在的な LCA としてチェックしながら、ダイバーシティ値を上方に伝播しようとします。 結合ステップにより、候補製品を計算するときに、異なるサブツリーから延びるパスが確実に考慮されます。 ディクショナリの使用は、カラー エンドポイントの状態ごとに最適な値を追跡することを目的としており、パスを拡張することで色がすでに表示されているかどうかを正しく考慮できるようになります。 

微妙な点は、最適なペアは LCA の 2 つの異なる子ブランチから得られる必要があるため、LCA 計算にはノードごとに最適な 2 つの寄与だけが必要であるということです。 これらの寄与をソートすると、そのノードに最適な製品候補が得られます。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードが同じラベルを持つ場合です。 この状況では、すべてのパスの個別のカウントが 1 であるため、ツリーの形状に関係なく、答えは 1 になる必要があります。 すべての上向きの寄与は 1 に崩壊し、すべての積は 1 のままであるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、ルートのすべての子が異なるラベルを持つ星型ツリーです。 ここで、最適なペアは常に 2 つのリーフであり、LCA はルートです。 このアルゴリズムは、ルートにあるすべての子の寄与を正しく考慮し、2 つの最大値を乗算します。 

最後のエッジケースは深いチェーンです。 すべてのペアの LCA は上位ノードと等しいため、異なるブランチの組み合わせは存在せず、答えは完全にローカル サブツリーの多様性によって決まります。これは DFS 伝播によって捕捉されます。
