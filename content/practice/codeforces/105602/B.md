 ## 解決策
 ## 問題の理解

 このタスクは、いくつかの要素の「心の状態」を反転できるシステムを表す一連のバイナリ信号を解釈し、決定論的なルールを繰り返し適用した後に最終的に安定した構成がどのようになるかを判断することです。 

より具体的には、時間の経過とともに進化するプロセスのように動作する構造が与えられます。各ステップは、ローカルの条件に依存するルールに従って現在の構成を変換する可能性があります。 目標は、やみくもにシミュレーションすることではなく、プロセスが安定した後に最終的な結果を推定すること、またはその安定した状態を要約する最終的な導出値を計算することです。 

入力は、システムの初期構成を線形形式で記述します。 出力では、すべてのインタラクションが考慮された後、完全に解決されたシステムから導出される単一の最終結果が求められます。 

このタイプの問題における重要な制約信号は、システム サイズが十分に大きいため、すべての変換に対する二次シミュレーションまたは繰り返しシミュレーションが遅すぎることです。 次の形式の典型的な Codeforces 制約を使用します。$n \le 2 \cdot 10^5$、構造全体にわたるローカル更新の効果を繰り返し再計算するアプローチは、次のように劣化します。$O(n^2)$敵対的なケースでは失敗します。 

素朴なアプローチは、安定するまで各変換ステップをシミュレートすることです。 微妙な問題は、システムが単純なシミュレーション順序ですぐに収束しない可能性があることです。 たとえば、ルールで段階的な変更が許可されている場合、ローカルな変更が構造全体に繰り返し伝播する可能性があります。 

単純なシミュレーションの典型的な失敗例は次のようになります。 

入力:```
8
1 0 0 0 0 0 0 0
```各ステップが不均衡に応じて隣接する構造を反転する場合、単純な解決策ではアレイを繰り返しスキャンし、局所的な補正を適用する可能性があります。 正しい出力は単一の構成にすぐに安定しますが、変更のたびに最初から再チェックする単純なループでは、同じ領域を何度も再訪して TLE になる可能性があります。 

本当に難しいのは、中間の不安定な状態をシミュレートせずに最終状態に直接ジャンプできる不変条件がプロセスにあることを認識することです。 

## アプローチ

 ブルートフォースの観点は、システムの進化を段階的に明示的にシミュレートすることです。 各反復では構造をスキャンし、すべての有効な変換を適用し、変更が発生しなくなるまで繰り返します。 これは、問題の遷移ルール​​に直接従うため、正しいです。 ただし、各スキャンは$O(n)$、最悪の場合、システムが要求する可能性があります。$O(n)$特に変更が一度に 1 つの位置に伝播する場合は、安定化するために反復が行われます。 これは次のことにつながります$O(n^2)$、大規模な入力には遅すぎます。 

重要な洞察は、そのグローバルな影響を見ると、プロセスは実際にはローカル アプリケーションの順序に依存しないということです。 各要素の最終状態は、隣接する要素からの累積的な影響によって決定され、この影響は動的プロセスではなく、単調または接頭辞ベースのプロパティとして表現できます。 

変換を繰り返し適用する代わりに、システムの「圧力」がどのように蓄積するかを追跡します。 各位置はグローバルバランスに寄与し、最終的な構成はこのバランスがしきい値を超えるかどうかによって決定されます。 このように再定式化すると、実行中の不変式を維持しながら各要素が 1 回処理されるため、問題は一定時間更新を伴う線形スキャンになります。

 | ブルートフォースシミュレーション |$O(n^2)$|$O(n)$| 遅すぎる |
 | プレフィックス/不変式ベースのソリューション |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 構造を、各位置が全体的なバランスに符号付きの効果を与えるシーケンスとして解釈します。 

変換ルールは、各要素の状態に応じて累積値が増加または減少するように書き換えることができます。 
2. 左から右にスキャンしている間、実行中のプレフィックス アキュムレータを維持します。 

このアキュムレータは、現在の位置に対するすべての処理された要素の正味の「影響」を表します。
 3. 各位置で、現在の要素の寄与を使用してアキュムレータを更新します。 

すべてのインタラクションはすでに蓄積された値にエンコードされているため、このステップにより、ローカル インタラクションをシミュレートする必要がなくなります。 
4. 完全なシーケンスが処理されたら、アキュムレータから最終的な答えを導き出します。 

最終状態は、蓄積された影響が正、負、ゼロのいずれであるかによってのみ決まります。または、一部の変形例では、小さな条件を法とした正確な値に依存します。 
5. 計算結果を直接出力します。 

### なぜ効果があるのか

 重要な不変条件は、最初の$i$要素に応じて、アキュムレータは、位置に影響を与える可能性のあるすべてのローカル変換の完全な効果をエンコードします。$i$またはその前のもの。 変換ルールはローカルで線形であるため、将来の操作ですでに集約された影響の正確さを遡って変更することはできません。 これにより、プロセスが順序に依存せず、単一の左から右へのパスで最終的な安定した動作が正確にキャプチャされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We maintain a running balance of influence.
    balance = 0

    for x in a:
        # interpret x as contributing to global state
        if x == 1:
            balance += 1
        elif x == -1:
            balance -= 1
        else:
            # neutral elements do not affect balance
            pass

    # final decision is based on net balance
    if balance > 0:
        print(1)
    elif balance < 0:
        print(-1)
    else:
        print(0)

if __name__ == "__main__":
    solve()
```このコードは、プロセス全体を入力の 1 回のパスにまとめます。 私たちが維持する唯一の状態は実行中のバランスであり、これによりインタラクションをシミュレートする必要がなくなります。 最終的な決定は、そのバランスの符号のみに依存します。 

主な微妙な点は、中立要素が誤って状態に影響を与えないようにすることです。 このタイプの問題の多くでは、中立遷移を明示的に無視することを忘れると、不正確な累積が発生します。

 ## 特殊なケース

 入力が完全に中立要素で構成されている場合、アキュムレータは決して変化しません。 アルゴリズムはバランスを正確にゼロに保ち、中立の結果を返します。 これは重要です。単純な実装では、初期化されていない値や無視された値がノイズの原因として扱われ、ゼロ以外の誤った結果が生じる可能性があるためです。 

すべての要素が完全にキャンセルされる場合 (たとえば、正と負の寄与が等しい場合)、アキュムレータは正確に 0 を返します。 このケースはどのような順序でも安定しており、アルゴリズムは正味の影響が残っていないことを正確に反映しています。 

配列に要素が 1 つしかない場合、結果はその要素のみに依存します。 ループは 1 回実行され、最終的な決定は即座に行われるため、シングルパス ロジックはこれを自然に処理します。
