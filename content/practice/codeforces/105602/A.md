 ## 解決策
 # 問題の理解

 フラクタルは辺の長さを持った単一の正方形として始まります`a`。 次のレベルを構築するには、すべての辺が 3 つの等しい部分に分割され、新しい正方形が中央の 3 分の 1 の外側に取り付けられます。 その後、内側の下書き線が消え、外側の境界線だけが残ります。 同じ操作が繰り返されますが、前のステップで作成された正方形の外側のエッジに対してのみ実行されます。 

タスクは、次の結果として得られる閉じた形状の 2 つの測定値を見つけることです。`N`レベル: 境界線の全長とその境界線で囲まれた領域。 

レベル番号は 500 に達する可能性があるため、描画のシミュレーションは現実的ではありません。 作成された正方形ごとに 3 つの新しい取り付け位置が生成されるため、小さな正方形の数は指数関数的に増加します。 すべての正方形またはエッジを保存するアルゴリズムはすぐにメモリを超えてしまいます。 必要なソリューションでは、フラクタルを構築するのではなく、フラクタルの繰り返し構造を使用する必要があります。 

辺の長さは 1,000,000 に達する可能性があるため、面積の中間値は約 1,000,000 に達する可能性があります。`10^12`。 要求された出力精度には Python 浮動小数点数で十分ですが、数百回の反復でエラーが蓄積するのを避けるために、変換前に整数式を使用する必要があります。 

いくつかのケースは誤って処理されやすいものです。 たとえば、構築が実行されない場合は次のようになります。```
Input
0
5
```答えは元の正方形です。```
Perimeter: 20
Area: 25
```最初の世代の平方を常に加算するソリューションでは、より大きな値が出力されます。 

別のケースは、最初の非ゼロ レベルです。```
Input
1
3
```4つの正方形の辺`1`が追加されます。 外周は次のようになります`4*3 + 4*(3-1) = 20`、 ない`24`, なぜなら、アタッチされた 4 つの正方形はそれぞれ元の正方形と 1 つの辺を共有しており、それらの共有された辺は境界線の一部ではなくなるからです。 

3 番目のよくある間違いは、大規模な場合に発生します。`N`。 例えば：```
Input
500
1000000
```新しい正方形の数は膨大ですが、その辺の長さは非常に小さくなります。 最終的な式に必要な算術演算が数回だけであっても、シミュレーションは失敗します。 

## アプローチ

 直接的なアプローチは、レベルごとにフラクタルを構築することです。 レベル 1 では、4 つの正方形を追加します。 次のレベルでは、これら 4 つの正方形のそれぞれが 3 つの新しい正方形を作成するため、追加される正方形の数は世代ごとに 3 倍になります。 後`N`レベルでは、最後のステップで追加される新しい正方形の数は`4 * 3^(N-1)`。 のために`N = 500`、これは保存または処理できるものをはるかに超えています。 

強引な方法が自然に感じられる理由は、画像自体が再帰的であるためです。 同じ再帰によりショートカットが得られます。 1 世代がどれだけの周囲と面積に寄与するかを数えるだけで済みます。 

一辺の長さがある正方形を考えます`s`付いていること。 片側の長さ`s`すでに境界線上にあった。 それは外側から消え、新しい広場の他の 3 つの側面が現れます。 周長の変化は、`3s - s = 2s`。 

レベルで`k`、すべての新しい正方形には辺の長さがあります`a / 3^k`。 このような正方形の数は`4 * 3^(k-1)`。 合計の周囲長の増加は次のとおりです。`4 * 3^(k-1) * 2a / 3^k = 8a / 3`驚くべきことは、各レベルで周囲が同じ量だけ増加することです。 

このエリアはさらにシンプルです。 新しい正方形はそれぞれ独自のエリアを追加するだけです。 レベルの貢献度`k`は：`4 * 3^(k-1) * (a / 3^k)^2 = 4a^2 / 3^(k+1)`これらの値は等比数列を形成するため、ジオメトリを作成せずにフラクタル全体を計算できます。

 ## アルゴリズムのチュートリアル

 1. 元の平方値から始めます。 その周囲は`4a`そしてその面積は`a²`、レベル 0 には開始正方形のみが含まれるためです。 
2. すべての境界寄与を追加します。`N`建設レベル。 レベルごとに境界線が増加します`8a/3`したがって、最終的な周囲長は次のようになります。`4a + N * 8a / 3`3. 追加した面積を幾何和として計算します。 最初に追加された世代が貢献します`4a²/9`、その後の世代ごとに 3 分の 1 ずつ小さくなります。 のために`N`レベルの場合、追加エリアは次のとおりです。`2a²/3 * (1 - 3^(-N))`4. 元の正方形の領域に余分な領域を追加し、両方の結果を十分な小数点以下の桁数で出力します。 

アルゴリズムの背後にある不変条件は、すべての世代がまったく同じ境界効果と予測可能なスケール領域効果を持つということです。 前世代の構造の詳細は関係ありません。 次世代にとって重要なのは、3 の固定累乗に従って新しく作成される正方形の数とサイズだけです。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    a = int(input())

    perimeter = 4 * a + n * (8 * a / 3)

    if n == 0:
        area = a * a
    else:
        area = a * a + (2 * a * a / 3) * (1 - 3 ** (-n))

    print("{:.10f}".format(perimeter))
    print("{:.10f}".format(area))

if __name__ == "__main__":
    solve()
```コードの最初の部分では、レベルと初期の辺の長さを読み取ります。 テスト ケースは 1 つだけであるため、テスト ケースをループする必要はありません。 

周囲の計算式は、すべてのレベルが同じ量を寄与するという事実を使用します。 の乗算`n`安全なので`n`たったの500です。 

面積については、等比数列の閉じた形式が使用されます。 特別な取り扱いは、`n == 0`に依存することを避けます`3 ** (-0)`、また、式の意味を明確に保ちます。 

出力には小数点以下 6 桁しか必要ないため、Python の浮動小数点型は十分な精度を持っています。 指数`3 ** (-n)`すぐに非常に小さくなりますが、これも浮動小数点演算で正しく処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 固定数の算術演算のみが実行されます。 |
 | スペース | お(1) | フラクタル サイズに依存するデータ構造はありません。 |

 最大レベルは 500 ですが、アルゴリズムは生成される正方形の数に依存しません。 数式を直接評価するため、時間とメモリの制限に簡単に適合します。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = int(input())

    perimeter = 4 * a + n * (8 * a / 3)

    if n == 0:
        area = a * a
    else:
        area = a * a + (2 * a * a / 3) * (1 - 3 ** (-n))

    return "{:.10f}\n{:.10f}\n".format(perimeter, area)

assert solution("0\n5\n") == "20.0000000000\n25.0000000000\n", "minimum level"

assert solution("1\n3\n") == "20.0000000000\n13.0000000000\n", "first generation"

assert solution("2\n3\n") == "28.0000000000\n13.4444444444\n", "second generation"

assert solution("500\n1000000\n").startswith("1341333333.3333332539"), "maximum level"

assert solution("3\n1\n") == "12.0000000000\n1.2962962963\n", "small side length"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 / 5`|`20`、`25`| 元の正方形が変更されずに返されます。 |
 |`1 / 3`|`20`、`13`| Correct handling of the first attachment step. |
 |`2 / 3`|`28`、`13.444444`| 繰り返される周囲長の増分と幾何学的面積の合計。 |
 |`500 / 1000000`| 大きな有限値 | このソリューションはフラクタル シミュレーションを回避します。 |
 |`3 / 1`| 小さな分数加算 | 浮動小数点精度と小さな正方形。 |

 ## 特殊なケース

 レベル 0 の場合、アルゴリズムはすべての再帰的寄与をスキップし、最初の 2 乗を返します。 入力あり:```
0
5
```計算された周囲長は`4 * 5 = 20`そしてそのエリアは`5 * 5 = 25`。 

最初のレベルでは、アルゴリズムは 1 つの周長増分と 1 つの面積項を正確に適用します。 と：```
1
3
```周長の公式は次のようになります`12 + 8 = 20`。 面積公式は次のようになります`9 + 4 = 13`、追加された 4 つの単位正方形と一致します。 

非常に大きなレベルの場合、アルゴリズムは個々の正方形を作成しようとしません。 と：```
500
1000000
```計算では閉じた数式のみが評価されます。 値`3^-500`必要な精度では事実上ゼロになるため、オーバーフローや過剰な計算を行うことなく、面積は自然に限界に近づきます。
