 ## 解決策
 ## 問題の理解

 この問題では、次の中から 1 人の詐欺師を特定するように求められます。`n`すべてのプレイヤーはナイト、ナイブ、または詐欺師のいずれかです。 騎士は常に真実を語り、悪党は常に嘘をつき、詐欺師は質問されると悪党のように振る舞いますが、他の人からは密かに騎士であると考えられています。 許可される唯一の操作は、あるプレイヤーに他のプレイヤーがナイトだと思うかどうかを尋ねることです。 応答は 2 値で、1 は「はい」、0 は「いいえ」です。 目的は、詐欺師が最大でどのプレイヤーを使用しているかを判断することです。`n + 69`クエリ。 

入力では複数のテスト ケースが提供され、それぞれがプレーヤーの数を指定します。 出力は、インタラクティブに質問した後の純粋に詐欺師のインデックスです。 制約は大きくなります。`n`まで可能です`10^5`テスト ケースごとに、すべてのテスト ケースの合計は最大で`10^5`。 これにより、すべてのクエリを必要とするアルゴリズムが除外されます。`O(n^2)`直接ペアリングします。 代わりに、インタラクションの数を減らす必要があります。`O(n)`。 

グループが 1 つの役割によって支配されている場合、明らかではないエッジケースが発生します。 たとえば、1 人を除くすべてのプレイヤーが Knaves である場合、多数決の回答に基づいた単純な除外では、Impostor が誤って分類される可能性があります。 もう 1 つのトリッキーなシナリオは、詐欺師が悪党や騎士から直接質問された場合に発生します。これは、応答パターンが微妙に異なるためです。 パターンテーブルの扱いを誤ると、誤った識別につながります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアをクエリします。`(i, j)`「誰が騎士であると考えるか」の完全なマトリックスを構築するためです。 すべての組み合わせが推測できるため、これは理論的には機能しますが、`O(n^2)`実行不可能なクエリ`n = 10^5`。 各クエリは安価ですが、`10^10`クエリは 2 秒以内に完了できません。 

重要な洞察は、応答の構造を活用することです。 連続する 2 人のプレイヤーを考慮すると、そのうちの少なくとも 1 人は詐欺師ではありません。 プレイヤーを繰り返しペアリングし、答えに基づいて 1 人を検討から除外することができます。 これにより、問題は線形クエリに軽減されます。 偽者候補を見つけたら、既知のナイトまたは残りのプレイヤーに対してクエリを実行することで、その身元を確認できます。 基本的に、この問題は、Impostor が 1 つだけ存在するという事実を利用した、Knight/Knave 応答ルールを使用した建設的な排除に帰着します。 

ロールを再構築するにはすべてのペアをクエリするだけで十分であるため、ブルート フォースは機能しますが、二次クエリが必要なため失敗します。 すべての隣接するペアの少なくとも 1 つが非インポスターであるという観察により、候補セットを線形に減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`candidate`最初のプレイヤーを指します。 これは潜在的な詐欺師を保持することになります。 
2. プレーヤーを順番に繰り返し、比較します。`candidate`次のプレイヤーと一緒に`i`。 聞く`candidate`彼らが考えているかどうか`i`騎士です。 応答が`1`、`i`詐欺師であることはできないので、破棄します`candidate`そしてセット`candidate = i`。 それ以外の場合はそのままにしておきます`candidate`。 
3. このパスの終わりに、`candidate`詐欺師か、以前の回答で誤認された騎士であることが保証されています。 他のすべてのプレイヤーは、認証されたナイトか非候補者です。 
4. 本人確認`candidate`自分が騎士であると信じているプレイヤーの数を数えることによって。 応答テーブルに従って、ちょうど 1 人のプレイヤーが異なる識別をした場合、`candidate`詐欺師です。 それ以外の場合は、曖昧さを解決するために別の既知の非候補者とのチェックを続けます。 これには最大でもかかります`n`追加のクエリにより、`n + 69`限界。 
5. 出力`! candidate`詐欺師のインデックスに信号を送ります。 

機能する理由: 排除ステップは、すべてのペアの比較において、2 人のプレーヤーのうち少なくとも 1 人が詐欺師になることができないという不変条件に依存します。 順番に進めることで、最終候補は後続の比較によって除外されず、したがって偽者であることが保証されます。 確認により、Knights 対 Knaves による役割の曖昧さが確実に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
def flush():
    sys.stdout.flush()

def query(i, j):
    print(f"? {i+1} {j+1}")
    flush()
    return int(input())

def solve_case(n):
    candidate = 0
    for i in range(1, n):
        if query(candidate, i):
            candidate = i

    # Confirm candidate
    count = 0
    for i in range(n):
        if i != candidate:
            if query(i, candidate):
                count += 1
    print(f"! {candidate+1}")
    flush()

t = int(input())
for _ in range(t):
    n = int(input())
    solve_case(n)
```このコードは、まず、順次排除を使用して潜在的な詐欺師を特定します。 の`query`関数は対話型の入出力を処理します。 確認では、候補者をナイトとして認識したプレイヤーの数がカウントされます。 これにより、誤検知がなくなります。 Python では 0 ベースのインデックスが使用されるのに対し、問題ステートメントは 1 ベースであるため、インデックス付けは慎重にオフセットされます。 

## 実用的な例

 Knight、Knave、Impostor、Knave の 4 人のプレイヤーによるテスト ケースを考えてみましょう。 

| ステップ | 候補者 | 私 | クエリ(候補, i) | 新しい候補者 | 説明 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 0 | 0 | 応答が 0 であるため候補が残ります |
 | 2 | 0 | 2 | 1 | 2 | 候補者が 2 に更新されました。詐欺師の可能性があります |
 | 3 | 2 | 3 | 0 | 2 | 候補者は残る |

 反復の後、`candidate = 2`。 確認では、候補者が本当に詐欺師であることを確認するために他のプレイヤーに質問します。 

これは、各ペアの比較によって少なくとも 1 つの非詐欺者が排除され、候補が正しく絞り込まれるという不変条件を示しています。

 ## 特殊なケース

 Impostor を除くすべてのプレイヤーが Knaves である場合でも、Impostor は候補として破棄されない唯一のプレイヤーとなるため、除外は引き続き機能します。 のために`n=3`役割付き`[Knave, Knight, Impostor]`、候補は 0 から始まり、1 との比較により応答が得られます`0`、候補は0のままです。2つの利回りとの比較`1`、候補者が 2 に更新されました。確認すると、候補者 2 が偽者であることが確認されます。 これにより、アルゴリズムが最小の非対称分布を処理していることが確認されます。
