 ## 解決策
 ## 問題の理解

 各テスト ケースは、複数の車種を扱うディーラーを記述します。`i`もっている`a_i`同一の車はすべて販売しなければなりません。 顧客が納得して購入できるのは、`x`ただし、選択したすべての車が異なるモデルの場合に限ります。つまり、1 人の顧客が同じタイプの 2 台の車を利用することはできません。 

各顧客が最大で選択できるように顧客をスケジュールしたいと考えています。`x`異なるモデルを選択し、選択した各モデルから 1 台の車を削除します。 目標は全部減らすこと`a_i`顧客数を最小限に抑えながらゼロにします。 

制約`x ≤ 10`モデル数は少ないですが、`n`まで大きくすることができます`5 · 10^5`そのため、顧客を 1 人ずつシミュレートしたり、顧客ごとにすべてのモデルを繰り返しスキャンしたりするソリューションは遅すぎます。 の合計`n`テスト全体でも到達します`5 · 10^5`、テストごとに本質的に線形または線形に近い動作を強制します。 

1 つのモデルが他のすべてのモデルを支配する場合、微妙なエッジケースが発生します。 たとえば、`a_i`は非常に大きいですが、他のものは小さいため、制限要因は車の総数ではなく、顧客ごとにいくつの異なるモデルを組み合わせることができるかです。 もう 1 つの注意が必要な状況は、カウントが非常にバランスが取れており、常に最大のものを選択するような貪欲な直感が働く場合です。`x`グループは正しく形式化されていないと失敗する可能性があります。 

## アプローチ

 単純なアプローチでは、顧客を明示的にシミュレートします。 毎回、私たちは迎えに行きました`x`残りの車両があるモデルを作成し、それらを減らします。 これはルールに正確に従っているため概念的には機能しますが、各顧客は最大で次のものを選択する必要があります。`x`までのモデル`n`、少なくとも`O(n)`顧客ごとの作業。 顧客の数も最大オーダーになる可能性があるため、`a_i`、このアプローチは実行不可能になります。 

重要な観察は、このプロセスが配布と同等であるということです。`sum(a_i)`ユニットを最大でも同じサイズのグループに分割`x`、どのグループもラウンドごとに各インデックスから複数のユニットを取得することはできません。 本当のボトルネックは、合計ではなく、モデルを何回提供する必要があるかです。 モデルが持っている場合`a_i`車には少なくとも表示される必要があります`a_i`顧客は異なりますが、各顧客がカバーできるのは最大でも`x`モデル。 これにより、梱包上の制約が生じます。各顧客が最大で削減できるのは、`x`さまざまなインデックスにわたる残りの単位の合計。 

プロセスを確認する便利な方法は、最大で何回の除去を繰り返し行う場合に、何層の除去が必要になるかを考慮することです。`x`レイヤーごとに異なるアクティブなモデル。 各層は最大でも減少します`x`残りの車両の合計なので、下限は`ceil(sum(a_i) / x)`。 ただし、これでは十分ではありません。単一のモデルが集中しすぎると、合計への寄与が示唆するよりも多くのレイヤーが強制される可能性があるからです。 正しい考えは、常に少なくとも次のものが必要であるということです。`max(a_i)`各レイヤーがそのモデルに最大 1 回、少なくとも 1 回は接触できるレイヤー`ceil(sum(a_i) / x)`容量の関係でレイヤーが入ります。 

したがって、最適な答えは、これら 2 つの制約の最大値になります。

 ## アルゴリズムのチュートリアル

 1. すべてのモデルの車両の合計数を計算します。 これにより、処理する必要がある全体的なワークロードが取得されます。 
2. すべての中から最大値を見つけます`a_i`。 これは、顧客ごとに 1 回しか提供できないため、最も要求の厳しい単一モデルをキャプチャします。 
3. 合計容量から下限を次のように計算します。`(sum(a_i) + x - 1) // x`。 これは、各顧客が最大で削除できることを反映しています。`x`分布に関係なく、車両の合計。 
4. 2 つの境界の最大値を取ります。 これにより、グローバル容量とモデルごとの制約の両方が確実に満たされます。 
5. この値をテスト ケースごとに出力します。 

### なぜ効果があるのか

 各顧客は、どのモデルからでも最大 1 台の車を削除します。`a_i`車には少なくとも必要なもの`a_i`異なる顧客。 これにより、答えがこれより小さくならないという制約が与えられます。`max(a_i)`。 同時に、すべての顧客が削除するのは最大でも`x`車の合計なので削除`S = sum(a_i)`車には少なくとも必要なもの`ceil(S / x)`顧客。 

この限界を達成するスケジュールが存在するのは、いつでも車をバッチで貪欲に割り当てることができるためです。各ステップで、`x`残りの車両を含むモデルを作成し、それぞれから 1 台を削除します。 残りの車両の合計または残りの最大列高さのいずれかが依然として正であるため、2 つの制約のうち少なくとも 1 つがまだ満たされていない限り、このプロセスがスタックすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        s = sum(a)
        mx = max(a)
        
        ans = max(mx, (s + x - 1) // x)
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に処理します。 配列を読み取り、単一パスで合計と最大値を計算し、派生した数式を適用します。 

唯一の微妙な実装の詳細は、整数の上限除算を使用することです。`sum(a_i) / x`、として実装されます`(s + x - 1) // x`。 これにより、浮動小数点エラーが回避され、大きな値の正確性が保証されます。
