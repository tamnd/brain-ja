 ## 解決策
 ## 問題の理解

 ちょうど 2 行からなる投票グリッドが与えられ、`n`各セルには「A」または「J」のラベルが付けられ、その議院の投票方法を表します。 グリッドは、正確に 3 つのセルのグループに分割する必要があり、各グループはグリッドの隣接関係を介して接続されなければならないという追加の制約があります。 各グループは単一の多数決を生成するため、グループ内に少なくとも 2 回出現する文字に応じて、グループはアルバロに 1 ポイント、またはホセに 1 ポイントのいずれかを寄付します。 

タスクは、「A」で勝ったグループの数が最大になるように、すべてのセルをそのような接続されたトリプルに分割することです。 

以来`n`まで可能です$10^5$各テスト ケースは独立しているため、どのソリューションもテスト ケースごとに直線的な時間で実行する必要があります。 これにより、考えられるすべてのグループを列挙したり、パーティションに対するグローバル検索を試みたりすることが直ちに除外されます。 グリッドの構造は、2×n グリッドの接続性によりトリプルの形成方法が厳しく制限されるため、列をスキャンしながら最適な決定をローカルで行うことができることを強く示唆しています。 

重要な点は、グループが単一の列に制限されていないことです。 トリプルは水平に曲がることができるため、隣接する列をまたぐ L 字型のような構成が重要になります。 これにより、選択が将来の列にどのような影響を与えるかを考慮しないと、貪欲なローカル決定が失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、2×n グリッドの考えられるすべての分割を、接続されたトリプルに考慮しようとします。 単一の列であっても、部分的な形状を拡張する方法の数は指数関数的であり、列間の接続を追跡すると、組み合わせ的に増大する状態空間が作成されます。 これは非常に小規模な場合でもすぐに実行不可能になります`n`。 

重要な観察点は、グリッドには 2 行しかないということです。これは、接続されたすべてのトリプルが非常に限られた形状のセットに適合する必要があることを意味します。 対称性までは、有効な構成はいくつかしかありません。1 つのセルによって拡張された垂直ドミノ、または 2 つの隣接する列にまたがる L 字型のブロックです。 この制限により、一部のセルが部分的に形成された地区によってすでに「予約」されているかどうかを示す少量の状態のみを保持しながら、グリッドを列ごとに処理することができます。 

すべての接続の可能性を解決するには最大でも 2 つの列が必要であることが認識されると、問題を列にわたる動的なプロセスとして扱うことができ、ローカル パターンに基づいて地区を完成させる方法を貪欲に決定し、最小限の残された情報を引き継ぐことができます。

 ## アルゴリズムのチュートリアル

 グリッドを左から右にスキャンし、現在、次の列にまたがる「オープン」部分地区があるかどうかを示す小さな状態を維持します。 重要な考え方は、新しい列を処理するたびに、できるだけ多くの有益な 3 セル グループを即座に完成させようとするということです。 

1. 各列を 4 つの値に前処理します。`(top, bottom)`これにより、文字列のインデックスを繰り返し作成することなく、ローカル構成を推論できるようになります。 
2. 列上の実行ポインタと、前の列から部分的に構築された L 字型グループを現在継続しているかどうかを表す小さな状態変数を維持します。 この状態が必要なのは、地区が柱の境界を越えることができる唯一の方法が L 字型であるためです。 
3. 各列で、両方のセルが十分に A-heavy である場合に、最初に垂直トリプルのような寄与を形成しようとします。 実際には、これは、現在の列に 2 つの A が含まれているかどうか、または以前に開いた構造を完了できるかどうかをチェックすることに相当します。 
4. アクティブな継続がない場合は、現在の列と場合によっては次の列を使用して、新しい最適な構造を開始することを検討します。 ここで L 字型が作成されます。現在の列の 1 つのセルと次の列の 2 つのセルを組み合わせたり、その逆を組み合わせたりします。 
5. 私たちは、将来の分割の実現可能性を維持しながら、多数派 A グループの当面の利益を最大化するオプションを貪欲に選択します。 すべての決定で消費される対話の列は最大 2 列であるため、この貪欲な選択によって全体的に最適な構築が妨げられることはありません。 
6. クロスカラム地区が使用されたかどうかに応じて、カラムポインタを 1 ステップまたは 2 ステップ進めます。 

### なぜ効果があるのか

 正しさは、2×n グリッドでは、接続されたすべてのトリプルが最大 2 つの隣接する列内に含まれるか、その範囲を超えて相互作用することなくそのようなローカル パターンの組み合わせに分解できるかのいずれかであるという構造的事実に依存します。 このローカルで限定された相互作用により、列での決定が確実に行われます。`i`カラムを超えて最適な実現可能性に影響を与えることはありません`i+2`これにより、貪欲な選択が安全かつグローバルに一貫したものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        top = input().strip()
        bot = input().strip()

        ans = 0
        i = 0

        while i < n:
            if i == n - 1:
                i += 1
                continue

            # count A's in current column
            cur = (top[i] == 'A') + (bot[i] == 'A')
            nxt = (top[i+1] == 'A') + (bot[i+1] == 'A')

            # if both columns are strong, we can form 2 A-wins in a 2-column structure
            if cur + nxt >= 3:
                ans += 1
                i += 2
            else:
                # otherwise take best local column pairing
                if cur >= 2:
                    ans += 1
                i += 1

        print(ans)

if __name__ == "__main__":
    solve()
```### 実装の説明

 このソリューションでは、各列を A の数に圧縮します。多数決のみが重要であるため、これで十分です。 ポインタ`i`は左から右に移動し、各ステップで、それらを組み合わせることで確実な勝利地区が得られるかどうかに応じて、1 つまたは 2 つの列を消費します。 

重要な設計上の選択は、隣接する 2 つの列を唯一の意味のある対話ウィンドウとして扱うことです。 これにより、有効な接続されたトリプルをすべてキャプチャしながら、グローバル DP 状態の必要性が回避されます。 

アクセスしないように注意する必要があります`i+1`境界を超えているため、ループは最後の列を明示的に個別に処理します。

これは、隣接する列を結合することでマルチセル地区がどのように正しくキャプチャされるかを示しています。

 このアルゴリズムは、有益な場合にのみローカル ペアを形成します。 A が散在していると大規模なマージが防止され、結果として合計は小さくなりますが最適になります。

 ## 特殊なケース

 重要なエッジ ケースは、列が 1 つだけ残っている場合に発生します。 このような状況では、アルゴリズムはペアリングを明示的にスキップし、範囲外のアクセスがないことを保証し、不完全なグループを正しく無視します。 

もう 1 つのエッジケースは、次のような列を交互に配置することです。`AJ / JA`、2 列の組み合わせでは安定多数を生み出すことはできません。 貪欲なロジックは、利益が保証されない限りマージを回避するため、自然に単一列の決定に戻り、正確さを維持します。
