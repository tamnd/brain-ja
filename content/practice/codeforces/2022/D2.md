 ## 解決策
 ## 問題の理解

 任務は、その中から 1 人の詐欺師を見つけることです。$n$インタラクティブ ゲームのプレイヤーは、各プレイヤーがナイト、悪党、詐欺師の 3 つの役割のいずれかを担当します。 騎士は常に真実を語り、悪党は常に嘘をつき、詐欺師は他のすべての人の観点からは悪党のように振る舞います。 「プレイヤーはどうですか？」という形式で質問することができます。$i$考えるプレイヤー$j$目標は、偽者を正しく識別しながら質問の数を最小限に抑えることです。 

入力により各テスト ケースのプレーヤーの数が提供され、対話はクエリを通じて実行されます。 以来$n$まで可能です$10^5$と合計$n$すべてのテストケースにわたって$10^5$、すべてのペアを直接クエリするアルゴリズムでは、$O(n^2)$動作が遅すぎます。 これにより、ブルートフォース列挙が排除されます。 したがって、課題は正確さだけではなく、効率性です。 

単純なアプローチでは、各プレーヤーに他のすべてのプレーヤーについてクエリを実行して、プレーヤーを個別に分類する可能性がありますが、許可されるクエリの最大数は、$n^2$。 エッジ ケースには、Knight が 1 つだけ、または Knave が 1 つだけある構成が含まれます。この場合、単純なペアごとのクエリによって Impostor が誤って識別される可能性があります。 たとえば、プレイヤーが 3 人の場合、プレイヤー 1 と 2 が Knaves、プレイヤー 3 が Impostor の場合、不用意なクエリによって他のディストリビューションと区別できない答えが得られる可能性があるため、戦略的な質問の選択が必要です。 

## アプローチ

 強引なアプローチは、すべてのプレイヤーに他のすべてのプレイヤーについて質問し、完全な応答マトリックスを使用して役割を推測することです。 原理的には正しいですが、これには時間がかかります$O(n^2)$クエリ、これは実行不可能です$n$まで$10^5$。 

クエリを減らすための重要な洞察は、回答の一貫性を明らかにできる単一のナイトまたはプレーヤーのペアを特定するだけでよいという観察から得られます。 ナイトが見つかると、そのプレイヤーは他の全員についてクエリを実行して、他の全員を効率的に分類できます。 したがって、最小限の戦略には、プレイヤーのペアを繰り返し比較し、ナイトが孤立するまで詐欺師の候補を排除し、その後、このナイトで線形スイープを実行して詐欺師を見つけることが含まれます。 

これにより、クエリの数が減少します。$O(n)$なぜなら、各クエリは候補を除外するか、最終的な分類を提供するからです。 詐欺師が 1 人だけ存在し、ナイツの答えが信頼できるという問題の構造により、この削減が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下のプレイヤーの完全なリストから始めます。$1$に$n$。 詐欺師である可能性のある候補インデックスを維持します。 
2. 連続するプレーヤーのペアを比較する$(i, i+1)$尋ねることによって$i$について$i+1$。 答えが「はい」の場合は 1 つの候補を保持し、そうでない場合はもう 1 つの候補を保持します。 比較するたびに、1 人の潜在的な詐欺師が排除されるか、ナイトに関する情報が提供されます。 
3. 線形スイープの後、1 つの候補が残ります。 この候補者に他のすべてのプレイヤーについて質問します。 応答がプレイヤーがナイトであることを示している場合は、それに応じてマークを付けます。 
4. これらの結果から確定したナイトを特定します。 確認されたナイトは参照として使用されます。残りの未知のプレイヤー全員について問い合わせます。 
5. 確認されたナイトが「いいえ」と答えたプレイヤーが詐欺師です。 そのプレイヤーを詐欺師として出力します。 

このアプローチが機能するのは、候補者を排除することで少なくとも 1 人のナイトが線形スイープで生き残ることが保証され、ナイツの回答が信頼できるためです。 ナイトが確認されると、その回答によって残りのすべてのプレイヤーが最終的に分類され、詐欺師を特定できるようになります。$2n$クエリ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
def flush():
    sys.stdout.flush()

def query(i, j):
    print(f"? {i} {j}")
    flush()
    return int(input())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        candidate = 1
        # Step 1: find a candidate
        for i in range(2, n+1):
            res = query(candidate, i)
            if res == 0:
                candidate = i
        # Step 2: find a confirmed Knight
        knight = None
        for i in range(1, n+1):
            if i == candidate:
                continue
            res = query(i, candidate)
            if res == 1:
                knight = i
                break
        # Step 3: identify Impostor
        for i in range(1, n+1):
            if i == knight:
                continue
            res = query(knight, i)
            if res == 0:
                print(f"! {i}")
                flush()
                break

if __name__ == "__main__":
    solve()
```最初のループでは、各ステップで 1 人のプレイヤーを排除することで、詐欺師の候補者を特定します。 2 番目のループでは、候補者に関する他のすべてのクエリを実行して、Knight を見つけます。 ナイトが判明すると、その応答の信頼性が保証され、残りの未知のすべてについてクエリを実行します。 ナイトが「いいえ」と答えたプレイヤーが詐欺師です。 

## 実用的な例

 のために`n=4`プレイヤーの役割を使って`[Knight, Knave, Impostor, Knave]`、アルゴリズムは候補を順番に比較します。 候補者がプレーヤー 1 から開始すると仮定します。 

| 候補者 | 次へ | 応答 | 新規候補者 |
 | --- | --- | --- | --- |
 | 1 | 2 | 0 | 2 |
 | 2 | 3 | 0 | 3 |
 | 3 | 4 | 1 | 3 |

 候補 3 が生き残ります。 ナイトを見つけるために他の人に問い合わせます。 プレイヤー 1 が 3 について「はい」と言う → プレイヤー 1 はナイトです。 すべてについてのクエリナイト 1: 候補 3 のみが「いいえ」を取得するため、詐欺師は 3 になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各プレイヤーは最大 2 回クエリを受けます。1 回は候補者スイープで 1 回、もう 1 回は承認されたナイト |
 | スペース | お(1) | 定数変数とインデックスのみが保存されます。 

この直線的な複雑さにより、実現可能性が保証されます。$n$まで$10^5$2 秒の制限に適合します。

 ## 特殊なケース

 最小限のケースの場合`n=3`役割付き`[Knight, Knave, Impostor]`、候補者を排除すると、偽者がすぐに特定されます。 ナイトが最後に質問された場合でも、その答えによって詐欺師が正確に特定されることが保証されます。 最大のケースの場合、`n=10^5`、アルゴリズムはプレイヤーの数に比例してスケールし、クエリ戦略により、詐欺師を分類する前にナイトが常に見つかるようになり、一貫性のない回答による誤認を防ぎます。
