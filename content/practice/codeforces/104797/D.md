 ## 解決策
 ## 問題の理解

 スピーカーのラインが与えられ、各スピーカーには初期音量と、音量を 1 単位変化させるのに必要なエネルギー量を示すコスト係数があります。 この線の連続するセグメントに対して 2 種類の操作が実行されます。 

最初の操作では、範囲内のすべてのスピーカーに均一な調整を適用し、現在の音量をある値だけ増減させます。 これは、基礎となるボリューム アレイが範囲追加の更新によって時間の経過とともに変更されていることを意味します。 

2 番目の操作では、さまざまなスピーカーを取得し、それらを単一の共通ボリュームに「正規化」する必要があります。 ただし、この正規化は任意ではありません。 必要な総エネルギーを最小限に抑える目標音量を選択する必要があります。スピーカー i を 1 単位変更すると Bi エネルギーがかかります。 複数のターゲット ボリュームが同じ最小エネルギーを与える場合、最小のそのようなボリュームを選択する必要があります。 タイプ 2 の各クエリの出力は、エネルギーそのものではなく、まさにこの選択されたターゲット ボリュームです。 

主な問題は、値とクエリの両方が動的であることです。 配列は範囲にわたって繰り返しシフトされるため、サブ配列に対する最適な重み付きアライメントのクエリに答える必要があります。 

制約は大きく、最大 200,000 のスピーカーと 200,000 の操作があります。 クエリごとにセグメントを再計算するソリューションでは、クエリごとの線形スキャンでも最悪の場合約 4e10 の操作が発生するため、遅すぎます。 これにより、単純なセグメントごとの再計算が即座に排除され、範囲更新と高速集計クエリの両方をサポートするデータ構造に向かって進みます。 

微妙な点は、タイプ 2 のクエリは、何度も範囲を更新した後の現在の値に依存することです。 2 番目の微妙な問題はタイブレークです。最適な値が複数存在する場合、最も小さい値を選択する必要があり、これは加重中央値の処理方法に影響します。 

エッジ ケースは、すべての Bi が等しい場合、つまり答えが値の単純な中央値になる場合、および 1 つを除くすべての Bi がゼロの場合、つまり 1 人の話者が最適な選択を支配する場合に発生します。 もう 1 つの注意が必要な状況は、繰り返しの範囲更新によって大きな負または正のシフトが生じる場合です。ただし、重要なのは相対的な順序のみであるため、正確性は絶対的な再計算ではなく、一貫したプレフィックス効果を維持することに依存します。 

## アプローチ

 直接的なアプローチは簡単です。配列を明示的に維持し、範囲を反復してすべての値を調整することによってタイプ 1 の各更新を適用し、現在のセグメント値を抽出して値で並べ替え、Bi に関する加重中央値を計算することによってタイプ 2 のクエリに応答します。 重み付き中央値は、総重みの半分に達するまで Bi を累積することによって見つけることができます。 

これが機能するのは、コスト関数が Bi の [l, r] の i の合計に Ai と選択したターゲット間の絶対差を乗算したものであるためです。 この式の最小化子は、重み Bi を備えた Ai の重み付き中央値です。 ただし、クエリごとにこれを最初から再計算するには、最悪の場合、クエリごとに O(n) 要素をスキャンし、O(n log n) を並べ替える必要があります。 最大 2e5 のクエリでは、これでは遅すぎます。 

重要な観察は、コスト関数が Ai 値と累積重み Bi の順序のみに依存するということです。 タイプ 1 の範囲更新は、セグメント上で Ai 値を均一にシフトするだけです。 これは、固定クエリ セグメント内で、すべての Ai 値が、影響を受ける更新の数に応じて定数を追加することによって変換されることを意味します。 重み付き中央値構造は均一なシフトの下で保存されます。つまり、セット内のすべての Ai が x 増加すると、最適な答えも x 増加します。

したがって、絶対値を再計算する代わりに、重み Bi の静的構造と、範囲の追加による進化する値 Ai の 2 つのことを維持することに問題を分割できます。 これは、遅延伝播を備えたセグメント ツリーを使用することを提案しています。各ノードは、Bi のプレフィックス合計とともに Ai 値のソートされた構造を保存し、重み付き中央値クエリを可能にし、遅延タグは範囲シフトを維持します。 

ノードをクエリする場合、Bi 値と調整された Ai 値のプレフィックス合計を使用して候補中央値を評価できます。 セグメント ツリーを使用すると、子からの結果を対数時間でマージでき、遅延伝播により範囲更新の効率性が維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q・N log N) | O(N) | 遅すぎる |
 | 遅延 + 加重中央値を使用したセグメント ツリー | O(Q log² N) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 話者のインデックスに基づいてセグメント ツリーを構築します。 各ノードは範囲を表し、そのセグメント内の要素の基本値ごとにソートされたリストと、加重累積のための Bi のプレフィックス合計を格納します。 

また、そのセグメント内のすべての Ai 値に適用される保留中の均一シフトを表す遅延伝播値も維持します。 

### ステップ

 1. 各リーフ ノードが話者インデックス i に対応し、ペア (Ai、Bi) を格納するセグメント ツリーを構築します。 

各内部ノードは、Ai でソートし、Bi のプレフィックス合計を維持することによって子をマージします。 

この構造により、任意のセグメント内の加重中央値を計算できます。 
2. 各ノードに、そのノードの間隔内のすべての Ai 値への保留中の加算シフトを表す遅延値を格納します。 

これにより、範囲タイプ 1 の操作中にすべての要素を明示的に更新することが回避されます。 
3. タイプ 1 の操作 (l、r、x) の場合、セグメント ツリーを走査します。 

ノードが [l, r] で完全にカバーされるたびに、個々の要素に触れる代わりに、その遅延値に x を追加します。 

これが機能するのは、そのノード内のすべての Ai が均一にシフトし、ノード内の順序が維持されるためです。 
4. タイプ 2 操作 (l、r) の場合、セグメント ツリーをクエリし、範囲をカバーするすべてのノードを収集します。 

結果をマージするときに、Ai 値が正しく解釈されるように保留中の遅延シフトを適用します。 
5. クエリ範囲の結合された並べ替え構造が得られたら、加重中央値を計算します。 

Bi を Ai の順に総重量の半分以上になるまで蓄積します。 

対応する Ai が答えです。 
6. タイプ 2 クエリごとにその値を出力します。 

### なぜ効果があるのか

 ターゲット v を選択するためのコスト関数は、Bi と |Ai − v| の合計です。 クエリ範囲を超えています。 これは、重み Bi を使用した Ai の加重中央値で正確に最小化されます。 範囲タイプ 1 の更新では、セグメント内のすべての Ai に定数が追加され、相対的な順序や重みを変更せずにコスト関数全体が水平方向にシフトされます。 したがって、重み付けされた中央値は同じ量だけシフトし、最適性が維持されます。 セグメント ツリーにより、クエリ範囲ごとに正しい複数の値セットが常に計算されるようになり、遅延伝播により、それらの値が以前のすべての更新を反映することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("a", "b", "lazy")
    def __init__(self):
        self.a = []
        self.b = []
        self.lazy = 0

def merge(left, right):
    res = Node()
    i = j = 0
    a = []
    b = []
    la, lb = left.a, left.b
    ra, rb = right.a, right.b

    while i < len(la) and j < len(ra):
        if la[i] < ra[j]:
            a.append(la[i])
            b.append(lb[i])
            i += 1
        else:
            a.append(ra[j])
            b.append(rb[j])
            j += 1

    while i < len(la):
        a.append(la[i])
        b.append(lb[i])
        i += 1

    while j < len(ra):
        a.append(ra[j])
        b.append(rb[j])
        j += 1

    res.a = a
    res.b = b
    res.lazy = 0
    return res

class SegTree:
    def __init__(self, n, A, B):
        self.n = n
        self.tree = [Node() for _ in range(4 * n)]
        self.build(1, 0, n - 1, A, B)

    def build(self, idx, l, r, A, B):
        if l == r:
            self.tree[idx].a = [A[l]]
            self.tree[idx].b = [B[l]]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid, A, B)
        self.build(idx * 2 + 1, mid + 1, r, A, B)
        self.tree[idx] = merge(self.tree[idx * 2], self.tree[idx * 2 + 1])

    def apply(self, idx, val):
        self.tree[idx].lazy += val
        for i in range(len(self.tree[idx].a)):
            self.tree[idx].a[i] += val

    def push(self, idx):
        if self.tree[idx].lazy != 0:
            v = self.tree[idx].lazy
            self.apply(idx * 2, v)
            self.apply(idx * 2 + 1, v)
            self.tree[idx].lazy = 0

    def update(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(idx, val)
            return
        self.push(idx)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, val)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, val)

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[idx]
        self.push(idx)
        mid = (l + r) // 2
        if qr <= mid:
            return self.query(idx * 2, l, mid, ql, qr)
        if ql > mid:
            return self.query(idx * 2 + 1, mid + 1, r, ql, qr)
        left = self.query(idx * 2, l, mid, ql, qr)
        right = self.query(idx * 2 + 1, mid + 1, r, ql, qr)
        return merge(left, right)

def solve():
    n, q = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    st = SegTree(n, A, B)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "1":
            l, r, x = map(int, tmp[1:])
            st.update(1, 0, n - 1, l - 1, r - 1, x)
        else:
            l, r = map(int, tmp[1:])
            res = st.query(1, 0, n - 1, l - 1, r - 1)

            total = sum(res.b)
            cur = 0
            for i in range(len(res.a)):
                cur += res.b[i]
                if cur * 2 >= total:
                    print(res.a[i])
                    break

if __name__ == "__main__":
    solve()
```セグメント ツリーは、各ノードを重みとペアになった値の並べ替えられたマルチセットとして保存します。これにより、マージされた構造の 1 回の線形スキャンで重み付き中央値を計算できます。 遅延伝播は保存された値に直接適用されるため、再構築することなく各ノードの一貫性が維持されます。 

重要な点は、遅延タグを適用するときに、ノード内に格納されている Ai 値を物理的に更新することです。 これにより、マージ中の再計算は回避されますが、タッチされたノードごとの更新コストが増加します。 この設計では、実際にはセグメント ツリーのカバレッジが対数更新を維持することを前提としています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、スピーカーが 1 つだけ含まれる範囲です。 この状況では、代替候補がないため、Bi に関係なく、加重中央値がその話者の値になることは自明です。 セグメント ツリーは単一要素ノードを返し、累積ループはその要素の合計重みの半分をすぐに超えます。 

もう 1 つのエッジ ケースは、Bi 値が 1 を除くすべて 0 である場合です。 他のスピーカーの値が大きく異なる場合でも、コストに寄与するのは 1 つのゼロ以外の重みだけです。 累積重みが並べ替えられた順序でその要素のしきい値にすぐに達し、その要素が強制的に選択されるため、アルゴリズムは引き続き機能します。 

3 番目のケースは、全範囲更新が繰り返される場合です。 何度も更新した後でも、遅延伝播により、シフトは均一な変換を超えてノード内の順序に影響を与えないため、構造を再計算する必要がなく、すべてのノードが正しいシフト値を維持します。
