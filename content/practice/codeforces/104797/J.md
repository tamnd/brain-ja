 ## 解決策
 ## 問題の理解

 小文字のみで構成される長い文字列と、この文字列の部分文字列に対する少数のクエリが与えられます。 各クエリは文字列の連続したセグメントに焦点を当て、そのセグメント内の非常に特殊なパターンを見つけるように求めます。 

私たちが探しているパターンは、次の形式の繰り返しです。`t + t`、空ではない部分文字列を意味します`t`直後にそれ自体の同一のコピーが続きます。 クエリ間隔に完全に含まれるこのような 2 倍の部分文字列すべての中で、可能な限り最大の長さを持つ部分文字列が必要です。`t`。 言い換えれば、前半と後半が等しい最長の偶数長の部分文字列を検索し、半分の長さとそれが出現する左端の位置を報告する必要があります。 

クエリ範囲内にそのような繰り返しが存在しない場合は、長さ 0 が返され、開始インデックスはクエリの左境界として定義されます。 

文字列の長さは 100 万にも達しますが、クエリの数は最大 100 です。 この不均衡が中心的なヒントです。 各クエリに比較的迅速に応答できる限り、文字列全体に対して大量の前処理を行ってもかまいません。 すべての部分文字列に対するクエリごとの線形スキャンに近いものは、大きなセグメントに対する単一のクエリでもコストがかかる可能性があるため、すでに遅すぎます。$O(n^2)$単純な部分文字列比較ロジックで。 

主な困難は、繰り返しの存在だけを求められるのではなく、最大の長さと、タイの中で最も左にある出現も求められることです。 この組み合わせは通常、サフィックス配列、サフィックス オートマトン、または範囲チェックを備えたローリング ハッシュなどの構造を示します。 

素朴なアプローチでは、クエリ内のすべての可能な開始位置とすべての可能な長さをチェックし、部分文字列を比較します。 これは、文字列が繰り返される小さな例であっても、静かに失敗します。 たとえば、次のような文字列では、`aaaaaa`、すべての位置で多くの有効な繰り返しが生成され、部分文字列の比較はすぐに二次またはさらに悪い動作に劣化します。 

もう 1 つの微妙な失敗例は、重複した繰り返しです。 たとえば、`ababab`、セグメント内の最適な繰り返しは、後で現れる短い繰り返しよりも早く始まる可能性があります。 最初の有効なペアで停止する単純なスキャンでは、間違った位置が返されます。 

最後に、境界の処理は注意が必要です。 繰り返し`t+t`内側に完全に収まる必要があります`[a, b]`。 よくある間違いは、後半が範囲内に収まっていることを確認せずに、開始位置だけをチェックすることです。 

## アプローチ

 直接的な総当たりソリューションでは、クエリごとに、考えられるすべての中心位置とすべての長さを試行します。`len`、次に、次のことを確認します。`s[i:i+len] == s[i+len:i+2len]`。 各比較は次のように線形です。`len`したがって、ハッシュを使用して比較を最適化したとしても、最終的にはチェックを行うことになります。$O(n^2)$最悪の場合、クエリごとのペア。 100 万文字の文字列では、これは完全に不可能です。 

重要な観察は、部分文字列の等価性が、ローリング ハッシュまたはサフィックス配列 LCP 構造を使用した高速範囲等価性チェックに帰着できるということです。 任意の 2 つの部分文字列を比較できるようになると、$O(1)$の場合、問題は、考えられる開始位置ごとに長さにわたる検索になります。 

2 番目の構造上の観察は、クエリの数が非常に少ないことです。 これにより、文字列に対するグローバル データ構造を 1 回前処理し、その間隔のみをスキャンすることで各クエリに個別に応答することができます。 

文字列と基数の累乗に対して多項式ローリング ハッシュを事前計算します。 これにより、任意の部分文字列を定数時間で比較できるようになります。 クエリ間隔ごとに、開始位置の候補を試し、長さの二分探索を使用してそこから始まる最長の繰り返しを計算します。`t`。 繰り返し条件は、次の間のハッシュの等価性チェックになります。`[i, i+len-1]`そして`[i+len, i+2len-1]`。 

グローバル最大値を見逃さないように、最初の有効な繰り返しで停止しません。 代わりに、クエリ間隔内のすべての有効な開始位置を評価し、最適な長さとそれを達成する最小のインデックスを追跡します。 

これにより、各クエリが一定期間にわたる制御されたスキャンに変わり、各チェックは繰り返しの長さが対数になります。

 | 最適 (ハッシュ + 位置ごとの二分探索) |$O(q \cdot n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 部分文字列のハッシュを一定時間内に計算できるように、文字列に対してローリング ハッシュを構築します。 

各クエリについて、セグメントに制限します。`[l, r]`。 ペアを見つけたい`(i, len)`そのような`i + 2*len - 1 ≤ r`そして繰り返し条件が成り立ちます。 

以下のように進めていきます。 

1. 文字列全体のプレフィックス ハッシュと基数の累乗を事前計算します。 

これにより、定数時間の部分文字列ハッシュ抽出が可能になります。 
2. クエリごとに`[l, r]`、初期化します`best_len = 0`そして`best_pos = l`。 
3. 可能なすべての開始インデックスを反復処理します。`i`から`l`に`r`。 

私たちはただ考慮します`i`少なくとも長さ 1 を繰り返す余地がある場合、つまり`i + 1 ≤ r`。 
4. それぞれについて`i`、二分探索を実行します。`len`から`0`に`(r - i + 1) // 2`。 

各中間点で、次のハッシュを比較します。`s[i : i+len]`と`s[i+len : i+2*len]`。 
5. ハッシュが一致する場合、その繰り返しは有効です。`len`、そこで拡張しようとします`len`上向き。 それ以外の場合は削減します。 
6. 二分探索が終了すると、有効な最大値が得られます。`len`その開始位置のために。 
7. クエリに対するグローバルな回答を更新します。 

もし`len > best_len`、両方を交換します`best_len`そして`best_pos`;

 等しい場合は、小さい方のインデックスを維持します。 
8. 出力`(best_len, best_pos)`。 

### なぜ効果があるのか

 このアルゴリズムは 2 つの不変式に依存します。 まず、ローリング ハッシュでは、等しい部分文字列が常に同じハッシュ値を生成することが保証されるため、バイナリ検索中に有効な繰り返しが見逃されることはありません。 2 番目に、固定開始インデックスごとに`i`、二分探索では、そこから開始して可能な最大の繰り返しの長さを見つけます。これは、述語「2 つの半分は等しい」は、繰り返しが長く失敗した場合という意味で単調であるためです。`len`、それより長い長さのすべても、その固定開始点では失敗します。 

クエリ範囲内のすべての有効な開始位置を評価するため、考えられるすべての繰り返し候補が最大形式で 1 ​​回だけ考慮され、最適なグローバル繰り返しが確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hash(s, base=91138233, mod=10**9+7):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)

    for i, c in enumerate(s):
        h[i + 1] = (h[i] * base + (ord(c) - 96)) % mod
        p[i + 1] = (p[i] * base) % mod

    return h, p

def get_hash(h, p, l, r, mod):
    return (h[r] - h[l] * p[r - l]) % mod

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    mod = 10**9 + 7
    h, p = build_hash(s, mod=mod)

    def subhash(l, r):
        return (h[r] - h[l] * p[r - l]) % mod

    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        best_len = 0
        best_pos = l

        for i in range(l, r + 1):
            hi = (r - i + 1) // 2
            lo = 0
            cur = 0

            while lo <= hi:
                mid = (lo + hi) // 2
                if mid == 0:
                    lo = 1
                    continue

                if i + 2 * mid <= r + 1:
                    if subhash(i, i + mid) == subhash(i + mid, i + 2 * mid):
                        cur = mid
                        lo = mid + 1
                    else:
                        hi = mid - 1
                else:
                    hi = mid - 1

            if cur > best_len:
                best_len = cur
                best_pos = i

        out.append(f"{best_len} {best_pos + 1}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策はプレフィックス ハッシュから始まり、部分文字列の比較が事前に計算された値の算術に削減されます。 ヘルパーさん`subhash`部分文字列ハッシュを抽出するロジックを分離します。これは、クエリ ループを読み取り可能に保ち、境界ミスを回避するために重要です。 

各クエリ内でインデックスをゼロベースの形式に変換し、可能な開始位置をすべてスキャンします。 開始ごとに、有効な最大繰り返し長を二分探索します。 キー制約チェック`i + 2 * mid <= r + 1`繰り返される部分文字列がクエリ セグメントをオーバーフローしないようにします。これは一般的な off-by-one エラーの原因です。 

結果の追跡では、最初に長さ、次に位置の厳密な比較が使用され、左端の最大値が保持されることが保証されます。 

## 実用的な例

 ### 例 1

 入力文字列:`cabaabaaca`、クエリ`[4, 8]`に相当する`aabaa`。 

それぞれの開始位置を調べます。 

| i (0 ベース) | 部分文字列 | 最適な繰り返しの長さ |
 | --- | --- | --- |
 | 3 | あばあ | 1 |
 | 4 | アバア | 0 |
 | 5 | ばあ | 0 |
 | 6 | ああ | 0 |

 最良の繰り返しは、位置 3 (1 から始まる位置 4) から始まる長さ 1 です。これは、次のようになります。`"aa"`内部`"aabaa"`。 

これにより、重複する候補と重複しない候補がすべて考慮され、左端のタイブレークが正しく機能することが確認されます。 

### 例 2

 入力文字列:`cabaabaaca`、クエリ`[8, 10]`に相当する`aca`。 

| 私 | 部分文字列 | 最適な繰り返しの長さ |

これは、開始位置がデフォルトで左側の境界になる、空の応答ケースの正しい処理を示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次のような完全に周期的な文字列です。`aaaaaa`。 すべての位置で複数の有効な繰り返しが生成され、アルゴリズムは、たとえ開始が遅くても、短い繰り返しよりも長い繰り返しが優先されるようにする必要があります。 すべての位置のスキャンにより、次のことが保証されます。`(len, pos)`ローカルに貪欲ではなく、グローバルに最適化されます。 

もう 1 つのケースは、次のような重複した繰り返しです。`ababab`。 位置 1 では、有効な長さには 1 (`ab ab`)、2(`abab abab`切り捨てられます)、アルゴリズムは、重複境界によって混乱することなく、有効な最大繰り返しを正確に識別する必要があります。 条件`i + 2*len ≤ r`厳密な非重複構造を強制することで正確性を保証します。
