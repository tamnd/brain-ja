 ## 解決策
 ## 問題の理解

 すでにツリーになっている無向グラフが与えられています。これは、正確に n 個のノードと n−1 個のエッジがあり、任意の 2 つのノード間には単純なパスが 1 つだけ存在することを意味します。 2 つのノード間の距離は、この一意のパス上のエッジの数です。 

ここで、いくつかの仮想的な追加エッジを評価するように求められます。 各クエリ エッジ (x、y) について、それをツリーに追加して単一のサイクルを作成することを想像します。 この新しいエッジにより、ノードのペア (s、t) によっては、元のツリー パスに沿って進むのではなく、追加されたエッジを通ってショートカットできるため、以前よりも厳密に短いパスが見つかる可能性があります。 

クエリごとに、エッジを追加した後に最短距離が短縮された、s < t の順序なしペア (s, t) がいくつあるかをカウントする必要があります。 

ツリー構造は非常に大きく、最大 100 万のノードがあり、最大 10 万のクエリがあります。 これにより、クエリごとの距離の再計算や、複数ソースの最短パス シミュレーションの実行が即座に排除されます。 n² は天文学的に大きいため、ノードのすべてのペアに触れることさえ不可能です。 

重要な微妙な点は、元のパスが x から y へのツリー パスの一部のセグメントを使用しているペアのみが改善できる可能性があることです。 s と t の間のパスが x-y パスと意味のある方法で「相互作用」しない場合、ショートカットを追加してもそれを減らすことはできません。 

典型的な単純な間違いは、クエリごとに x と y から BFS を再実行して、影響を受けるノードをカウントできると想定することです。 各 BFS が O(n) であるため、これは失敗し、O(nq) が大きすぎます。 

もう 1 つのよくある落とし穴は、最短パスが x または y を通過するペアのみが影響を受けると想定することです。 これでも十分ではありません。ショートカットによって x-y パスの両側にある大きなサブツリーのルートを変更できるからです。 

## アプローチ

 最初の総当たり攻撃のアイデアは単純です。クエリ (x, y) ごとに、変更されたグラフ内のすべてのペアの最短パスを計算するか、少なくともすべてのノードから BFS を使用して最初から距離を再計算します。 これにより、各ペア (s, t) が改善されたかどうかが正しく識別されますが、コストはクエリあたり O(n²)、またはクエリあたりよくても O(n) BFS であり、最悪の場合は 10¹¹ または 10¹⁰ の操作が発生します。 これは不可能です。 

重要な構造的洞察は、ツリー内で新しいエッジが実際に何を行うかを理解することで得られます。 (x, y) を追加すると、単一サイクル、つまり x と y の間の一意のツリー パスが導入されます。 最短パスを改善するには、この新しいエッジを使用する必要があります。そうしないと、ツリーにはすでに最適なパスが存在するためです。 

したがって、問題は、x と y の間のツリー パスに沿って、元のパスではなくショートカットを通過することを好むノードのペアが何組あるかを数えるということになります。 影響を受けるすべてのペアは、元のパスが迂回を短くする方法で x-y パスと交差するエンドポイントに対応します。 

これを形式化する標準的な方法は、ツリーをルート化し、LCA 構造を事前計算して、O(1) で距離を測定できるようにすることです。 次に、クエリ (x, y) について、ツリー内のそれらの間のパスを考慮します。 そのパスはツリーを領域に分割し、ノードはさまざまな点でこのパスに「接続」されます。 各ノードは、パスへの最短ルートが入る X-Y パス上の最も近い点に関連付けることができます。 

すべてのノードが x-y パス上に投影されると、各ノードはセグメント上にあるかのように動作し、改善条件はそのパスに沿った位置にわたる 1 次元の不等式になります。 これにより、問題は、ショートカットの長さによって引き起こされる距離短縮制約を満たす線上の点のペアを数えることに変換されます。

最後のステップは、すべてのノードが X-Y パス上の投影間隔に寄与しており、ペアの投影が互換性のある位置にある場合に正確に影響を受け、ショートカットがツリー パスよりも短くなることを理解することです。 注意深く前処理を行うことで、これらの寄与は、パス上のプレフィックス合計と、実装スタイルに応じてパスへの距離変換や重心ベースのカウントと組み合わせた重光分解などのサブツリー集約手法を使用してカウントできます。 

核心的な削減は、各クエリが x-y パスに沿って順序付けられたノードに対するカウント問題になり、すべての距離が固定長の dist(x, y) との比較に削減されることです。

 ## アルゴリズムのチュートリアル

 ツリーが任意にルート化されていると仮定し、最小共通祖先と距離を前処理します。 

1. すべてのノードの深さ、親ポインター、およびルートからの距離を事前計算します。 これにより、LCA を使用して O(1) 内の任意の 2 つのノード間の距離を計算できるようになります。 これが必要なのは、すべてのクエリが元の木の距離と新しいショートカットの比較に依存しているためです。 
2. 各クエリ (x, y) について、ツリー距離 d(x, y) を計算します。 これは、エッジを追加することによって形成されるサイクルの長さです。 この値により、ペアが新しいエッジを使用することでメリットが得られるかどうかが決まります。 
3. ツリー内の x から y への一意のパス P を考えます。 概念的には、ツリー内のすべてのノードは、パスへのパスが最初に交差するこのパス上の最も近い点に割り当てることができます。 この「投影点」は、ツリーを P のエッジに接続された領域に分割します。 
4. 各ノード s について、P 上のその接続位置を、s からパスに向かって移動するときに遭遇する x-y パス上の最初のノードとして定義します。 これは、LCA ロジックとバイナリ リフティングを使用して計算できます。 これが機能する理由は、s から P 上の任意のノードへの最短パスは一意の境界頂点で P に入らなければならないためです。 
5. すべてのノードが P に沿った位置にマッピングされたら、パスに沿ったこの位置インデックスによってノードを並べ替えます。 各ノードは、長さ d(x, y) の線分上の点のように動作します。 
6. 2 つのノード s と t の場合、それらの距離が減少する唯一の方法は、それらの間の元のパスが、ショートカットを使用して P に沿って s からその投影に進み、t に戻るパスよりも長い場合です。 この条件は、それらの投影位置とd(x,y)を含む比較となる。 
7. P に沿った位置で線形不等式が成り立つように、クエリをカウント ペア (i, j) に減らします。これは、位置がわかったら、2 ポインター スイープまたはプレフィックス頻度カウントを使用して計算できます。 
8. パスに沿ったすべての有効なペアにわたる寄与を合計し、クエリの結果を出力します。 

### なぜ効果があるのか

 ツリー内のすべての最短パスは一意に決定され、エッジを 1 つ追加すると、既存のパスを超えることができる代替ルートが 1 つだけ作成されます。 その代替ルートは常に 3 つのセグメントで構成されます。s からサイクルに移動し、ショートカット エッジを使用してサイクルの一部を横断し、次にサイクルから t に移動します。 サイクルは正確に x-y パスに新しいエッジを加えたものであるため、すべての改善は、元のツリー パスと、x-y パスの連続セグメントを迂回するパスとの比較として表現できる必要があります。 これにより、2 次元のツリー構造がそのパスに沿った 1 次元の順序に折りたたまれ、その順序でカウントすることが必要かつ十分になります。

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(u, p):
    parent[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(1, 0)

for k in range(1, LOG):
    for v in range(1, n + 1):
        parent[k][v] = parent[k - 1][parent[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for k in range(LOG):
        if diff >> k & 1:
            a = parent[k][a]
    if a == b:
        return a
    for k in reversed(range(LOG)):
        if parent[k][a] != parent[k][b]:
            a = parent[k][a]
            b = parent[k][b]
    return parent[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

 ## 特殊なケース

 重大なエッジ ケースは、x と y がすでに隣接している場合です。 その場合、追加されたエッジは既存の接続を複製するため、最短パスを変更しません。 アルゴリズムでは、計算された距離 d(x, y) が 1 に等しく、すべての比較で影響を受けるペアが正しく生成されないことを確認する必要があります。 

もう 1 つのエッジ ケースは、x と y が長い直径のようなパスの終点である場合です。 この場合、サイクルはツリーの大部分に及び、影響を受けるペアの数は最大になります。 投影ベースのメソッドは、パス自体上のノードだけでなく、パスに接続されているすべてのサブツリーからの寄与を正確にカウントすることを保証する必要があります。
