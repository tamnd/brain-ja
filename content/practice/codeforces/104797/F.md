 ## 解決策
 ## 問題の理解

 小文字と空のセルを含む長方形のグリッドが与えられます。 時間の経過とともに、重力はこのグリッドに作用しますが、その方向は固定されません。 代わりに、グリッドは一連の重力方向の下で繰り返し「定着」され、各フェーズですべての文字が境界または別の文字によってブロックされるまで、現在の方向に可能な限り完全に移動します。 

単一フェーズは物理シミュレーションのように動作します。すべての文字は独立して指定された方向にスライドしますが、文字は相互に通過できないため、その方向に沿った相対的な順序が維持されます。 すべての文字が静止した後、おそらく異なる重力方向で次のフェーズが始まります。 

最後のタスクは、K 個の重力フェーズをすべて適用した後の構成を計算することです。 

制約は小さく、N と M は最大 100、K は最大 100 です。これは、O(KNM) または O(KN M log N) 程度の複雑さを持つ解であれば問題ない可能性が高いことをすぐに示唆しています。 ただし、ステップごとに一度に 1 つのセルの動きをシミュレートするソリューションは、グリッドが小さいため、依然として安全です。 

主な微妙な点は、単純な意味では動きが細胞ごとに独立していないことです。 文字を 1 つずつ誤って移動すると、以前の移動が同じフェーズ内の後の移動に影響を与える可能性があります。 たとえば、下降局面では次のようになります。```
a
b
.
```移動したら`a`まず、誤って通過する可能性があります`b`実装順序に応じて。 正しい解釈は、列内のすべての文字が全体として再配置されたスタックのように動作するということです。 

もう 1 つの微妙なエッジ ケースは、空のグリッドまたは文字のないグリッドです。 出力は変更されず、圧縮ロジックは空のシーケンスを正しく処理する必要があります。 

最後に、K = 0 は動きがまったく発生しないことを意味するため、元のグリッドは指定されたとおりに正確に印刷される必要があります。 

## アプローチ

 直接的な総当たりシミュレーションでは、各フェーズを物理ステップとして扱い、移動が不可能になるまで重力方向に各文字を一度に 1 セルずつ繰り返し移動します。 フェーズごとに、グリッドをスキャンし、文字を移動し、安定するまで繰り返すなどのことを試みます。 最悪の場合、1 つの文字がフェーズごとに O(max(N, M)) ステップを移動する可能性があり、相互作用を解決するために多くのパスが必要になる可能性があり、非効率な実装では O(KN²M²) にまで低下する可能性のある複雑さになります。 各行または列内の最終位置は並べ替えまたは圧縮によって完全に決定されるため、これは不要です。 

重要な観察は、重力は線に沿った順序以上の複雑な相互作用を生み出さないということです。 固定方向では、グリッドは独立した線、つまり垂直重力の列と水平重力の行に分解されます。 各行内では、相対的な順序を維持しながら、文字が片側に向かって単に「詰め込まれ」ます。 これは、行からすべての文字を抽出し、ターゲット側から順番に書き戻し、残りのセルをドットで埋めることに相当します。 

したがって、各フェーズは O(NM) で処理できます。文字を収集して書き換えることによって、すべての行または列を独立して再構築します。 

K は最大 100 であるため、この手順を K 回繰り返すだけで十分に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ステップ シミュレーション | O(K · N² · M²) 最悪の場合 | O(1) おまけ | 遅すぎる |
 | フェーズごとのライン圧縮 | O(K・N・M) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 各重力フェーズを繰り返しシミュレートしますが、文字を徐々に移動させるのではなく、方向に応じて構造化された方法でグリッドを再構築します。 

### 段階的な手順

 1. グリッドを、リストのリストなどの変更可能な構造に読み取ります。 
2. シーケンス内の重力方向ごとに、グリッド全体を 1 回のパスで処理します。 
3. 方向が垂直 (下) の場合:

 各列を個別に処理します。 各列を上から下にスキャンし、すべての文字を順番に集めてから、下から上に書き戻します。 これは、順序を維持しながら文字を下に引っ張る重力をシミュレートします。 
4. 方向が上である場合:

 再度各列を処理します。 文字を上から下に収集し、行 0 から始めて上から下に書き戻します。これにより、文字が上向きにパックされます。 
5. 方向が正しい場合:

 各行を個別に処理します。 文字を左から右に集めて、最後の列から右から左に書き戻します。 
6. 方向が左の場合:

 各行を個別に処理します。 文字を左から右に集めて、一番左の位置から書き直します。 
7. フェーズのすべての行または列を処理した後、グリッドが更新され、次のフェーズへの入力になります。 

### なぜ効果があるのか

 文字が互いに交差することがないため、各フェーズでは、動きに直交する軸に沿った文字の相対的な順序が維持されます。 重力の唯一の影響は、すべての文字が 1 つの境界に向かって線に沿って圧縮されることです。 したがって、各行または列は、要素が再配置されるものの、内部的には並べ替えられない、安定した順序付けられたコンテナーのように動作します。 この不変条件により、文字の抽出と再挿入による各行の再構築が物理プロセスと正確に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply_down(grid, n, m):
    for col in range(m):
        stack = []
        for row in range(n):
            if grid[row][col] != '.':
                stack.append(grid[row][col])
        for row in range(n - 1, -1, -1):
            grid[row][col] = stack.pop() if stack else '.'

def apply_up(grid, n, m):
    for col in range(m):
        stack = []
        for row in range(n):
            if grid[row][col] != '.':
                stack.append(grid[row][col])
        for row in range(n):
            grid[row][col] = stack.pop(0) if stack else '.'

def apply_right(grid, n, m):
    for row in range(n):
        stack = []
        for col in range(m):
            if grid[row][col] != '.':
                stack.append(grid[row][col])
        for col in range(m - 1, -1, -1):
            grid[row][col] = stack.pop() if stack else '.'

def apply_left(grid, n, m):
    for row in range(n):
        stack = []
        for col in range(m):
            if grid[row][col] != '.':
                stack.append(grid[row][col])
        for col in range(m):
            grid[row][col] = stack.pop(0) if stack else '.'

def main():
    n, m, k = map(int, input().split())
    dirs = input().strip()
    grid = [list(input().strip()) for _ in range(n)]

    for d in dirs:
        if d == 'D':
            apply_down(grid, n, m)
        elif d == 'U':
            apply_up(grid, n, m)
        elif d == 'R':
            apply_right(grid, n, m)
        else:
            apply_left(grid, n, m)

    for row in grid:
        print(''.join(row))

if __name__ == "__main__":
    main()
```このソリューションは、グリッドを変更可能な 2D リストとして維持します。 各フェーズでは、方向に応じて行または列のいずれかを再構築します。 

下向きおよび上向きの重力の場合、各列は文字の線形リストに抽出されます。 下向き重力の場合は、文字が最も低い利用可能なセルに蓄積されるように、下から補充します。 上向きの重力のために、上から補充します。 

水平重力の場合、行は同様に処理され、右重力は右端から充填され、左重力は左端から充填されます。 

微妙な点は、抽出中に順序を維持する必要があることです。 これがコンシをスキャンする理由です
