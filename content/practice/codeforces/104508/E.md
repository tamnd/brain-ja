 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられます。 各点について、そこから上に伸びる 2 つの領域 (左上方向に向かって 1 つと右上方向に向かって 1 つ) を描くことを想像します。 固定点の場合、これら 2 つの上向きの円錐内に厳密に存在する他の点がいくつあるかに興味があります。 最終的な答えは、すべての点にわたるこの量の合計です。 

より具体的には、各ポイントごとに$(x_i, y_i)$、左側で 1 回、右側で 1 回ずつ、それに対して特定の優勢関係を満たす他のポイントがいくつあるかを数え、すべてのポイントにわたってすべてを累積する必要があります。 

制約は次のとおりです$N = 3 \cdot 10^5$これにより、ペア間の二次比較が即座に除外されます。 すべての点のペアを明示的にチェックするソリューションは、約$10^{10}$2 秒の制限をはるかに超えた最悪のケースでの操作が可能になります。 ターゲットは近くにいるはずだ$O(N \log N)$または$O(N \log^2 N)$。 

主な問題は、各ポイントが 2 つの異なる方向性優位クエリに同時に寄与するため、二重カウントや高価なカウントの再計算を避けなければならないことです。 

多くの点が同じ座標を共有する場合、微妙なエッジケースが発生します。 複数の点が同じ位置にある場合、単純な厳密な不等式チェックでは、順序によっては誤ってそれらを数えてしまう可能性があります。 もう 1 つのエッジ ケースは、ポイントが単調なチェーンを形成する場合です。たとえば、両方のポイントですべてが増加します。$x$そして$y$慎重に扱わないと、単純な座標圧縮の仮定が壊れてしまいます。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべてのポイントについて、他のすべてのポイントを反復処理し、それらのポイントが必要な左上または右上の領域にあるかどうかをテストします。 これは問題の定義に直接従うため、正しいです。 ただし、これには確認が必要です$N-1$それぞれのポイント$N$ポイント、結果として$O(N^2)$操作。 と$N = 3 \cdot 10^5$、これは完全に不可能になります。 

重要な観察は、左上条件と右上条件の両方が、並べ替えと座標圧縮後に優勢クエリに変換できることです。 ジオメトリについて考える代わりに、より大きな点がいくつあるかを数えるという問題として再解釈します。$y$特定の制約の下での値$x$。 

ポイントを並べ替えると$x$、各点について、その左または右にあるすべての候補がその順序で連続します。 次に、問題をプレフィックスとサフィックスのカウントに落とし込みます。$y$-軸。 フェンウィック ツリー (または BIT) を使用すると、特定の条件で何ポイントかを維持できます。$y$はすでに処理されており、対数時間でしきい値を上回るか下回るものがいくつあるかをクエリできます。 

ポイントを 2 つのスイープで処理します。1 つは左から右へのスイープで右上の関係を処理し、もう 1 つは右から左へのスイープで左上の関係を処理します。 各掃引では、周波数構造を維持します。$y$-コーディネート。 

ブルート フォースはすべてのペアを明示的に比較するため機能しますが、順序付けを利用していないため失敗します。 両方の条件が相対的な順序にのみ依存するという観察$x$そして$y$これにより、ペアワイズ チェックを動的順序構造に対するプレフィックス クエリに置き換えることができます。

 ## アルゴリズムのチュートリアル

 まずすべてを圧縮します$y$フェンウィック ツリーには制限付きのインデックス スペースが必要なため、-座標を指定します。 圧縮後、それぞれ$y_i$の整数になります$[1, N]$。 

次にポイントを並べ替えます$x$そして、元の順序を使用するか、同等のグループを作成することによって、慎重に関係を解消します。$x$-値、厳密な不等式が重要であるため。 

1. すべてのポイントを昇順に並べ替えます$x$。 これにより、「左」と「右」の関係を配列内の接頭辞と接尾辞として扱うことができます。 
2. それぞれのポイントの数を追跡するフェンウィック ツリーを初期化します。$y$-値が見られました。 
3. 左から右にスイープします。 各ポイントで、以前に確認されたポイントのうち、より大きい値を持つポイントがいくつあるかをクエリします。$y$-価値。 これらの点は図の左側にあるため、これにより「右上」条件の寄与が得られます。$x$しかし上では$y$。 
4. 現在のポイントを挿入します。$y$-value をフェンウィック ツリーに追加します。 
5. フェンウィック ツリーをクリアし、右から左へ 2 回目のスイープを繰り返します。 次に、右側の点がどれだけ大きいかを対称的に数えます。$y$-value、「左上」条件に対応します。 
6. 両方のスイープからの寄与を加算して、最終的な答えを取得します。 

重要な点は、平等は厳密に扱われなければならないということです。 同じ点のグループを処理する場合$x$-座標、フェンウィック ツリーにクエリを挿入する前に、まずグループのすべてのクエリを計算する必要があります。そうでない場合は、等しいポイントを持ちます。$x$誤って相互に貢献してしまいます。 

### なぜ効果があるのか

 スイープのどの時点でも、フェンウィック ツリーは厳密に片側にある点のセットを正確に表します。$x$。 各クエリは、それらの点のうちのいくつが次の厳密な不等式を満たすかを数えます。$y$。 これは、左上または右上の領域にあるという幾何学的条件と正確に一致します。 各ポイントを方向ごとに 1 回だけ処理し、均等に分離することで厳密な順序を維持しているためです。$x$-座標、無効なペアはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    ys = sorted({y for _, y in pts})
    comp = {v: i + 1 for i, v in enumerate(ys)}

    pts = [(x, comp[y]) for x, y in pts]
    pts.sort()

    def sweep(order):
        bit = BIT(len(ys))
        res = 0
        i = 0
        while i < n:
            j = i
            while j < n and pts[j][0] == pts[i][0]:
                j += 1

            for k in range(i, j):
                _, y = pts[k]
                if order == 1:
                    res += bit.sum(len(ys)) - bit.sum(y)
                else:
                    res += bit.sum(len(ys)) - bit.sum(y)

            for k in range(i, j):
                _, y = pts[k]
                bit.add(y, 1)

            i = j
        return res

    pts.sort(key=lambda p: (p[0], p[1]))
    left_to_right = sweep(1)

    pts.sort(key=lambda p: (-p[0], p[1]))
    right_to_left = sweep(-1)

    print(left_to_right + right_to_left)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、圧縮されたプレフィックス合計にのみ使用されます。$y$-コーディネート。 スイープ機能は同等の処理を行います。$x$の厳密な不平等を保証するブロック$x$。 それぞれの方向が独立して寄与し、それらの合計が最終的な答えとなります。 

一般的な実装の落とし穴は、同じ BIT 内でクエリを実行する前に BIT に挿入することです。$x$-ブロック。 これでは、同一のペアが誤ってカウントされてしまいます。$x$、厳格な「内部」条件に違反します。

 ## 特殊なケース

 すべての点が同じ座標を共有する場合、条件は厳密に領域内にあるため、すべてのペアを除外する必要があります。 等しいため、アルゴリズムはこれを正しく処理します。$x$ポイントはグループ化され、クエリの後にのみ挿入されるため、グループ内での自己カウントや相互カウントが防止されます。 

のような単一点入力の場合$(0,0)$の場合、フェンウィック ツリー全体が空であり、貢献できる他のポイントが存在しないため、両方のスイープはゼロを返します。 

次のような単調増加シーケンスの場合$(1,1), (2,2), (3,3)$、左から右へのスイープでは、すべての反転がカウントされます。$y$、右から左へのスイープはそれを反映します。 各スイープでは一貫したプレフィックスベースのカウントが生成され、方向の対称性が保たれていることを確認します。 

2 つの点が同じ場合$x$でも違う$y$、 例えば$(1,1), (1,2)$、どちらも厳密には他方の左右にないため、依然として寄与はゼロです。$x$、幾何学的条件に正確に一致します。
