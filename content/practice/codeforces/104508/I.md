 ## 解決策
 ## アルゴリズムのチュートリアル

 有効なパスがその行で占有することができる列位置の範囲を維持しながら、行を上から下に処理します。 

1. 先頭には開始位置が 1 つしかないため、到達可能な間隔を L = 1 および R = 1 として初期化します。 
2. 1 から n までの各行 i について、移動を反映するように間隔を更新します。 どの位置からでも、同じ列に留まるか、右に 1 ステップ移動することができるため、新しい間隔は [L, R + 1] になります。 これにより、もう 1 つのステップ後に到達可能なすべての列がキャプチャされます。 
3. 間隔を更新した後、赤色の位置 ai が [L, R] 内にあるかどうかを確認します。 そうであれば、パスが行 i の赤いセルを通過する一連の移動を選択できるため、答えを 1 つ増やします。これは、パスを指定された制約に「位置合わせ」する瞬間です。 
4. 将来の柔軟性を維持するために、有用な位置から離れすぎないように強制して間隔を縮小します。 この構造では、間隔は到達可能なすべての状態をすでに表しているため、それ以上の枝刈りは必要ありません。 
5. 最後の行まで継続し、累積されたカウントを返します。 

重要な設計上の選択は、実行可能なすべてのパス状態を個別に列挙するのではなく、常に間隔としてコンパクトに表現することです。 

正確さは、行 i の処理後、区間 [L, R] に、開始からの有効な左/右移動シーケンスによって到達できるすべての列インデックスが正確に含まれるという不変条件から得られます。 各状態は同じ列または次の列に独立して遷移するため、すべての更新ステップでこれが維持されます。 遷移は線形であり、位置を超えた履歴に依存しないため、到達可能な状態のセットは常に連続した間隔であり、有効な状態が除外されたり、誤って追加されたりすることはありません。 これにより、ai が区間内にあるときは常に、それを実現する有効なパスが存在し、貪欲なカウントによって達成可能な一致が見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    L = 1
    R = 1
    ans = 0

    for i in range(n):
        # expand reachable interval
        R += 1

        # check if red position is reachable at this row
        if L <= a[i] <= R:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、進化する到達可能な間隔のみが保持されます。 唯一の微妙な点は、区間の拡張が非対称であることを覚えておくことです。各行では、その位置に留まるか右に移動することができ、上限が増加するだけです。 

条件`L <= a[i] <= R`直接、その行の赤いセルを通過するパスを構築できるかどうかに対応します。

 ## 特殊なケース

 最小の入力 n = 1 の場合、間隔は唯一の位置で開始および終了するため、赤セルは常に到達可能であり、1 回カウントされます。 このアルゴリズムは L = R = 1 を正しく初期化し、a1 が 1 に等しい場合はすぐに一致をカウントします。 

1、2、3、... のような単調増加ターゲットの場合、間隔はすべての AI を内部に保持するのに十分な速さで正確に拡大します。 拡張ステップ R += 1 により、行 i で到達可能な最大列が i となり、ai = i と正確に一致することが保証されます。 

すべての i に対して一定のターゲット ai = 1 の場合、L が増加することはないため、到達可能な間隔には常に 1 が含まれます。 R が大きくなっても、左側の境界は固定されたままであるため、すべての行がカウントされます。 

1、2、1、2 のような交互パターンの場合、間隔は無制限に拡大するため、各ステップで両方の可能な列が引き続き実行可能です。 すべての ai がプロセス全体を通じて間隔内に留まるため、アルゴリズムはすべての行を正しくカウントします。
