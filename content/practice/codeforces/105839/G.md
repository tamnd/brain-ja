 ## 解決策
 ## 問題の理解

 数字を含む有効な算術式があります。`+`、`-`、および括弧。 一部の括弧を削除することもできますが、結果として得られるテキストは依然として有効な式である必要があります。 考えられるすべての削除の中で、最大値とそれを達成する 1 つの式が必要です。 

この式は小さく、最大でも 100 個の数値と 100 個のかっこを含むため、かっこのすべてのサブセットに対する指数関数的な総当たり攻撃は実行できません。 約 100 個の独立したペアが存在する可能性があり、最大で`2^100`選択肢。 削除を列挙するのではなく、算術式の構造を利用する必要があります。 

よくある間違いは、括弧を削除するとグループ化が削除されるだけであると想定することです。 例えば、`1-(2-3)`なることができる`1-2-3`、値を から変更します。`2`に`-4`。 括弧が消えると、内側のマイナスはグループ全体の減算として保存されません。 

もう 1 つの特殊なケースは、入れ子になった括弧です。 のために`1-(2-(3-4))`、最も外側のペアのみを削除すると、`1-2-(3-4)`内側の括弧が残っている場合のみ。 効果は正確にどのペアが生き残るかによって異なります。 

## アプローチ

 ブルートフォースのアイデアは、削除するかっこのすべての可能なサブセットを試し、結果の式が有効かどうかを確認し、それを評価することです。 考えられるすべての答えが考慮されるため、これは正しいです。 ただし、括弧が約 100 個あると、可能性の数が多すぎます。 

重要な点は、括弧で囲まれた式には 2 つの役割があるということです。 グループ化したままにすることもでき、その場合、その値は個別に最適化されます。 または、周囲の式に開くこともできます。この場合、その前の符号はその中の最初の数値に影響し、内部の演算子は外側の式の一部になります。 

これは、符号パラメータを使用した動的プログラミングを示唆しています。 すべての式セグメントについて、先頭に次の文字が付いている場合に最良の結果を計算します。`+`そしてその前にあるとき`-`。 考えられる外部の影響はこれら 2 つの記号のみであるため、状態空間は小さいままです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^p) | O(p) | 遅すぎる |
 | 符号付き DP 状態 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 式を式と括弧で囲まれた部分に再帰的に解析します。 各式について、2 つの状態を保持します。この式が正符号の後に付加された場合の最良の値と、負符号の後に付加された場合の最良の値です。 
2. 数字を処理する場合、その寄与は単純に数字に受信符号を乗算したものになります。 
3. 演算子で区切られた一連の用語を処理する場合は、左から右に用語を結合します。 次の項は、現在の演算子によって生成された符号を受け取ります。 
4. 括弧内の部分を処理する場合は、2 つの選択肢を考慮します。 括弧を保持するということは、内部を通常どおり評価し、その結果に入力符号を乗算することを意味します。 括弧を削除すると、内部の式が現在の式とマージされるため、同じ受信符号を持つ内部の式の状態が使用されます。 
5. より大きな値を与える選択肢を保存します。その選択肢が再構築に必要な選択肢であるためです。 

機能する理由: 括弧を削除すると、囲まれた式が単一の項として評価されるか、周囲のシーケンスの一部になるかが変わるだけです。 DP は、すべての括弧のペアについてこれら 2 つの可能性を正確に考慮します。 各部分式は、考えられる両方の受信符号に対して最適に解決されるため、そこから構築されたすべてのより大きな式も最適な結果になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

sys.setrecursionlimit(10000)

def parse_expr(pos):
    items = []
    ops = []
    cur = None

    while pos < n and s[pos] != ')':
        if s[pos].isdigit():
            items.append((int(s[pos]), None))
            pos += 1
        else:
            if s[pos] == '(':
                val, st, pos = parse_expr(pos + 1)
                items.append((val, st))
            else:
                ops.append(s[pos])
                pos += 1

    return build(items, ops), None, pos + 1

def build(items, ops):
    m = len(items)

    memo = {}

    def solve(i, sign):
        if (i, sign) in memo:
            return memo[(i, sign)]

        if i == m:
            return 0, ""

        value, inside = items[i]

        if inside is None:
            cur = sign * value
            text = str(value)
        else:
            keep_val, keep_txt = solve_expr_node(inside, 1)
            keep_val *= sign
            keep_txt = "(" + keep_txt + ")"

            rem_val, rem_txt = solve_expr_node(inside, sign)

            if rem_val > keep_val:
                cur, text = rem_val, rem_txt
            else:
                cur, text = keep_val, keep_txt

        if i + 1 == m:
            memo[(i, sign)] = (cur, text)
            return cur, text

        op = ops[i]
        nxt_sign = 1 if op == '+' else -1
        nxt_val, nxt_txt = solve(i + 1, nxt_sign)

        memo[(i, sign)] = (cur + nxt_val, text + op + nxt_txt)
        return memo[(i, sign)]

    return solve

def solve_expr_node(node, sign):
    return node(0, sign)

root, _, _ = parse_expr(0)

ans_val, ans_str = solve_expr_node(root, 1)

print(ans_val)
print(ans_str)
```パーサーは再帰的な式オブジェクトを作成します。 各式オブジェクトには、2 つの DP 状態に応答できる関数があります。 

重要な実装の詳細は、括弧で囲まれたブロックが常に個別に評価される必要はないということです。 括弧を削除した場合は、内部の式が周囲の式の一部になるため、現在の符号を使用して内部 DP を呼び出します。 

Python の整数が使用されるのは、多くの加算と減算を行うと式の値が通常の 32 ビット範囲よりも大きくなる可能性があるためです。 

## 実用的な例

 のために`1-(2-3)`最初の決定は維持するかどうかです`(2-3)`。 

| パート | かっこはそのままにしておきます | かっこを削除 |
 | --- | --- | --- |
 |`(2-3)`| 価値`-1`次に乗算します`-1`与える`1`| になる`2-3`外側のマイナスの後に、`-1`|

 保存されているバージョンの方が優れているため、答えは次のとおりです。`1-(2-3)`価値のあるもの`2`。 

のために`1+(2)-(3-(4-5))`、最後の括弧で囲まれた部分は部分的に開くと便利です。 

| 式部分 | ベストアクション |
 | --- | --- |
 |`(2)`| どちらの形式でも得られる`2`|
 |`(3-(4-5))`| 外側の括弧を削除し、内側の括弧はそのままにしておきます。 

結果は次のようになります`1+(2)-(3-4-5)`価値のあるもの`9`。

 ## 特殊なケース

 単一の数字には選択肢がありません。 アルゴリズムはすぐに数字のケースに到達し、数字を返します。 

すべての括弧が 1 つの値を囲む場合、次のようになります。`((9))`、すべての削除により式は有効に保たれます。 DP は保持と削除を比較し、同じ最大値を選択します。 

次のようなネストされた減算の場合`1-(2-(3-4))`、「すべての括弧を削除する」などの貪欲なルールは、内部符号が相互作用するため失敗します。 ネストされた各式は親から正しい受信符号を受け取るため、DP はこれを処理します。
