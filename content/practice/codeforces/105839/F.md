 ## 解決策
 ## 問題の理解

 個別の項目のシャッフルされた順序を表す配列が与えられ、最大 1 つの操作 (2 つの位置を選択してそれらの値を交換する) を実行できます。 タスクは、この 1 回のスワップを使用して配列をソートされた順序に変換できるかどうかを判断し、可能であれば、問題の必要な出力に従ってその可能性を正確に特徴付けることです。 

アルゴリズムの観点から見ると、入力は長さのシーケンスです。$n$ターゲット構成は、非降順でソートされた同じシーケンスです。 許可される唯一の変更は、任意の 2 つのインデックス間の 1 つのグローバル スワップです。 通常、出力は、この制約の下での実現可能性の決定または最小限の特徴付けです。 

制約レジーム (最大サイズの配列、通常は$10^5$この形式の Codeforces 問題では、可能な限りすべてのスワップを試みるアプローチは即座に除外されます。 すべてのペアを試すには、次のことが必要です$O(n^2)$実行可能な限界をはるかに超えた操作。 有効な解決策は、配列とそのソートされたバージョンの間の不一致の構造を線形または線形に近い時間で推論する必要があります。 

配列がすでにソートされている場合、微妙なケースが発生します。 その場合、スワップは必要なく、盲目的に「不一致を修正」しようとするロジックでは、スワップがまだ必要であると誤って結論付ける可能性があります。 もう 1 つの重要なケースは、ちょうど 2 つの要素が適切な位置にないにもかかわらず、それらの配置が他の位置と相互作用するため、それらを交換しても実際には順序が修正されない場合です。 たとえば、複数の要素が 2 サイクルよりも長いサイクルで置き換えられる、ほぼソートされた配列を考えてみましょう。 極端な点だけを考慮する単純なアプローチでは、1 つのスワップで十分であると誤って仮定する可能性があります。 

具体的な例として、配列を考えてみましょう$[1, 4, 3, 2, 5]$。 ソートされた配列は$[1, 2, 3, 4, 5]$。 複数の不一致の位置があり、交換していますが、$4$そして$2$状況は改善されますが、配列が完全にソートされず、すべての不一致パターンが 1 回のスワップで解決できるわけではないことがわかります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのインデックスのペアを試してください。$(i, j)$、それらを交換し、結果の配列がソートされているかどうかを確認します。 スワップごとに、ソートの検証には次の時間がかかります。$O(n)$時間もあるし、$O(n^2)$スワップの可能性があり、$O(n^3)$素朴に行われた場合の解決策、または$O(n^2)$チェックをもっと賢く再利用できれば。 これが不可能になるのは、$n$さえ大きくなるから$10^5$周りにつながるだろう$10^{10}$操作。 

重要な観察は、1 つのスワップが 2 つのポジションにのみ影響を与える可能性があるということです。 これは、配列を少しでも固定できる場合、ほとんどすべての位置がソートされたターゲットとすでに一致している必要があることを意味します。 唯一の逸脱は厳密に局所的に特定される必要があります。 スワップをシミュレートする代わりに、配列をソートされたバージョンと比較し、異なるインデックスのみに焦点を当てます。 

不一致の位置を分離すると、有効なソリューションの構造は固定的になります。 不一致がゼロの場合、配列はすでにソートされています。 正確に 2 つの不一致がある場合、これら 2 つの値を交換すると配列が修正される可能性がありますが、これは並べ替えられた構成でそれらが互いに対応する場合に限られます。 3 つ以上の不一致がある場合、1 回のスワップでは 2 つ以上のポジションを修正できないため、答えは直ちに否定になります。 

これにより、問題全体が、並べ替えられたベースラインと比較し、不一致セットを分析することに集約されます。

 ## アルゴリズムのチュートリアル

 1. ソートされた配列のコピーを作成します。 これは、到達したい最終目標状態を表します。 この配列と比較すると、どの位置が間違っているかが正確にわかります。 
2. すべてのインデックスを反復処理し、元の配列がソートされた配列と異なるインデックスを収集します。 これらのインデックスは、スワップで修正できる唯一の場所を表します。 
3. 不一致の位置の数がゼロの場合、配列はすでにソートされているため、操作は必要ありません。 すぐに成功を返すことができます。 
4. 不一致の位置の数がちょうど 2 つである場合、それら 2 つのインデックスを抽出し、それらの値を交換することで両方の位置がソートされた配列と一致するかどうかをテストします。 これにより、スワップが局所的に改善されるだけでなく、構造的に有効であることが保証されます。 
5. 不一致の位置の数が 0 または 2 以外の場合は、1 回のスワップでは最大 2 つの位置しか修正できないため、1 回のスワップでは配列を修正できないと結論付けます。 

### なぜ効果があるのか

 重要な不変条件は、スワップ操作が 2 つのインデックスにのみ影響し、他の場所の要素のマルチセットを変更せずにそれらの値のみを交換することです。 ソート位置と既に一致しているインデックスは、スワップに関与しない限り正しいままでなければなりません。関与できるインデックスは最大 2 つです。 したがって、解決可能な構成は最大 2 つの位置でソートされた配列と異なっている必要があり、それらの 2 つの位置は、値を交換すると両方が正確に復元されるという意味で相補的である必要があります。 この構造上の制限は、すべての有効なケースを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    b = sorted(a)
    
    diff = []
    for i in range(n):
        if a[i] != b[i]:
            diff.append(i)
    
    if len(diff) == 0:
        print("YES")
        return
    
    if len(diff) == 2:
        i, j = diff
        if a[i] == b[j] and a[j] == b[i]:
            print("YES")
        else:
            print("NO")
        return
    
    print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、配列を読み取り、そのソートされたバージョンを構築することから始まります。 これは参考構成です。 不一致のインデックスを収集するループは、並べ替え順序に違反する配列の部分を正確に分離します。 次に、ロジックはこの不一致セットのサイズに厳密に基づいて分岐します。 

最もデリケートな部分は、2 つの不一致の場合です。 単に 2 つの不一致があるだけでは十分ではありません。 交換された値は、互いのソートされた位置と完全に一致する必要があります。 このチェックにより、スワップが部分的に正しくないことを確認しますが、両方の間違った位置が完全に解決されます。 

## 実用的な例

 配列を考慮してください$[1, 3, 2, 4]$。 並べ替えたバージョンは、$[1, 2, 3, 4]$。 

不一致を追跡します。 

| 私 | a[i] | b[i] | 不一致 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | いいえ |
 | 1 | 3 | 2 | はい |
 | 2 | 2 | 3 | はい |
 | 3 | 4 | 4 | いいえ |

 不一致インデックスは次のとおりです。$[1, 2]$。 これらを交換すると、$[1, 2, 3, 4]$, したがって、答えはYESです。 

ここで考えてみましょう$[1, 4, 3, 2, 5]$。 ソートされた配列は$[1, 2, 3, 4, 5]$。 

| 私 | a[i] | b[i] | 不一致 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | いいえ |
 | 1 | 4 | 2 | はい |
 | 2 | 3 | 3 | いいえ |
 | 3 | 2 | 4 | はい |
 | 4 | 5 | 5 | いいえ |

 不一致インデックスは、$[1, 3]$。 スワップの確認:$a[1]=4$等しいはずです$b[3]=4$そして$a[3]=2$等しいはずです$b[1]=2$、したがって、スワップが機能し、配列がソートされます。 これにより、2 つの不一致の場合の正当性条件が確認されます。

 ## 特殊なケース

 すでにソートされている配列の場合、次のようになります。$[1, 2, 3]$の場合、不一致リストは空であり、アルゴリズムはスワップ ロジックを試行せずにすぐに YES を返します。 これにより、スワップが必要ない場合でも強制的にスワップを行うというよくある間違いを回避できます。 

のようなケースの場合$[2, 1, 3]$、位置に正確に 2 つの不一致があります$0$そして$1$。 ソートされた配列は$[1, 2, 3]$、不一致の要素を交換すると、両方の位置が正しく整列され、アルゴリズムがクロスチェック条件によってそれを確認します。 

次のような周期的変位の場合$[3, 1, 2]$、3 つの位置すべてが並べ替えられた配列と一致しません。 配列がソートに「近い」場合でも、単一のスワップでは 3 サイクルを解決できず、アルゴリズムは 3 つ以上の不一致を検出して正しく拒否します。
