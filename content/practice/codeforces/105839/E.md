 ## 解決策
 ## 問題の理解

 英語の大文字のみで構成される文字列のエンコードとデコードの両方のスキームを設計するように求められます。 文字列を送信するシステムは信頼できません。送信中に、エンコードされた文字列の最大 1 文字が他の大文字に置き換えられる可能性があります。 

エンコードするときは、元のメッセージをより長い文字列に変換する必要があります。 デコード時に、破損している可能性のあるエンコードされた文字列が与えられるため、変更された文字が 1 つだけであると仮定して、元のメッセージを一意に復元する必要があります。 

重要な制約は、エンコードされた文字列が元の文字列よりわずかに長くてもよく、最大 10 文字だけであることです。 アルファベットは 26 個の大文字に固定されているため、すべての記号は基数 26 の数字になります。 

重要な点は、破損を検出することではなく、リカバリを独自のものにすることです。 エンコードされた文字列内の任意の単一の置換は、位置と置換文字の両方が不明であっても、曖昧さなく修正可能でなければなりません。 

長さの制約は、すべての文字を何度も繰り返すような大きな冗長性を許容できないことを意味します。 エンコードされたメッセージの長さは最大約 1010 であるため、線形または線形に近い時間ですべての位置をスキャンまたはテストするソリューションは許容されますが、長さが 2 次のものは遅すぎます。 

単純なアプローチは、単純なチェックサム (文字コードの合計など) を追加することです。 これにより、エラーが発生したことは検出できますが、どこでエラーが発生したかを特定することはできません。 2 つの異なる 1 文字の変更により、同じチェックサムの違いが生じる可能性があるため、デコードがあいまいになります。 

位置ハッシュのみを保存しようとすると、さらに微妙な失敗例が発生します。 たとえば、値によって重み付けされた文字のインデックスの合計を保存する場合、2 つの異なる位置を変更しても、チェックサムに対して同じ集計効果が生じる可能性があります。 これにより、デコードの一意性が損なわれます。 

中心的な課題は、制限された数の追加シンボルのみを使用して、破損した文字の位置と値の両方を回復するのに十分な情報をエンコードする冗長性を構築することです。 

## アプローチ

 強引な考え方は、デコードを「あらゆる可能性を試す」ものとして扱うことです。 多くても 1 つの位置が破損していると想定します。 受信した文字列の各位置について、26 文字のそれぞれに置き換えてみて、結果の文字列が元のメッセージの有効なエンコードと一致しているかどうかを確認します。 厳密なエンコード ルールがあれば、すべてのチェックを再計算することで一貫性を検証できます。 

これはエラー モデルが単純であるため概念的には機能しますが、有効性をチェックするために複数のグローバル制約を繰り返し再計算する必要がある場合は遅すぎます。 最悪の場合、約 1010 の位置 x 26 の置換を実行し、それぞれに対して文字列全体に対していくつかのハッシュのような制約を再計算する可能性があります。 単純に実装すると、厳密な 1 秒制限ではコストが高くなりすぎます。 

重要な観察は、「方程式を直接解く」必要がないということです。 代わりに、検証が少数の決定論的チェックに減り、デコードが単一の破損した位置に対する制御されたブルートフォースになるようにエンコードを設計できます。 

このアイデアは、文字列の複数の独立した線形要約をエンコードする固定数のチェックサム文字を追加することです。 各チェックサムは、位置の異なる重み付けを使用して計算されるため、単一の破損した文字によって、すべてのチェックにわたる変更の明確なシグネチャが生成されます。 十分な独立したチェックを行うことで、位置と置換文字の両方を一意に識別できます。

冗長性として 10 個の余分な文字を使用します。 これらの各文字には、異なる重み付けスキームを使用して、メッセージ全体にわたる 1 つの集計されたチェックサムが保存されます。 デコード中に、これらのチェックを再計算し、受信したチェックと比較します。 破損がなければすべて一致します。 破損が 1 つだけある場合、不一致は 1 つの位置と 1 つの置換文字によって説明できます。 次に、すべての候補ポジションとすべての文字を試し、10 個のチェックすべてが同時に一致するかどうかを検証します。 

メッセージ長は最大でも約 1000 であるため、この二重ループは十分小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース一貫性チェック | O(n² · 26) | O(n) | 遅すぎる |
 | ブルート再構築によるチェックサムベースのエンコーディング | O(n · 26 · 10) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションをエンコードとデコードのフェーズに分けます。 

### エンコードフェーズ

 1. 元の文字列を読み取り、各文字を 0 ～ 25 の範囲の整数に変換します。これにより、文字の算術演算が可能になります。 
2. 文字列に対して 10 個の異なるチェックサム値を計算します。 各チェックサムは、位置と文字値の異なる決定論的重み付け関数を使用します。 目的は、エラーの場所が異なると、これらのチェック全体で異なる複合効果が生じることを確認することです。 
3. 各チェックサム値を 26 を法として、単一の大文字に変換します。これらの 10 文字が冗長ブロックを形成します。 
4. 10 個のチェックサム文字を元の文字列に追加し、結果を出力します。 

1 つではなく複数のチェックを使用する理由は、単一の集計値では異なるエラー位置を区別できない一方で、複数の独立した投影により曖昧さが軽減され、一意の解決策を分離できるためです。 

### デコードフェーズ

 1. 受信した文字列をメイン部分と、保存されているチェックサム ブロックを表す最後の 10 文字に分割します。 
2. 受信したメイン文字列から 10 個のチェックサム値を再計算します。 
3. 計算されたチェックを保存されたチェックと比較します。 それらが一致する場合、メッセージはすでに正しいので、チェックサム ブロックを削除して元のメッセージを返すことができます。 
4. 不一致がある場合は、完全なエンコード文字列のちょうど 1 つの位置が破損していると想定します。 
5. エンコードされた文字列内の各位置を、A から Z までの可能な文字に置き換えてみます。 
6. 変更候補ごとに、チェックサム値を再計算し、保存されているチェックサム ブロックと比較します。 
7. すべてのチェックを一致させる一意の候補が正しい再構成です。 対応する元のメッセージを (チェックサム ブロックなしで) 出力します。 

### なぜ効果があるのか

 このアルゴリズムは、単一の置換がすべてのチェックサム方程式に予測可能な線形的な影響を与えるという事実に基づいています。 各チェックサムは、文字列全体を 26 を法とする単一のスカラー値に射影したものとして機能します。エラーが 1 つ発生すると、エラーの位置と置換文字という 2 つの未知数を含む 10 個の方程式系が生成されます。 

未知の自由度よりも多くの独立した制約があるため、正しい解決策は一意に識別可能になります。 位置と文字に対する総当り検索により、この小さな制約のあるシステムが効果的に解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ALPH = 26
K = 10

def ch_to_i(c):
    return ord(c) - ord('A')

def i_to_ch(x):
    return chr(x + ord('A'))

def compute_checks(s):
    n = len(s)
    a = [ch_to_i(c) for c in s]
    checks = [0] * K

    for k in range(K):
        acc = 0
        for i, v in enumerate(a):
            acc += (i + 1) ** k * v
        checks[k] = acc % ALPH

    return checks

def encode(s):
    checks = compute_checks(s)
    return s + ''.join(i_to_ch(x) for x in checks)

def decode(s):
    main = s[:-K]
    given = s[-K:]

    base_checks = compute_checks(main)
    given_checks = [ch_to_i(c) for c in given]

    if base_checks == given_checks:
        return main

    n = len(main)
    a = [ch_to_i(c) for c in main]

    for i in range(n):
        original = a[i]
        for nv in range(ALPH):
            if nv == original:
                continue
            a[i] = nv

            checks = [0] * K
            for k in range(K):
                acc = 0
                for j, v in enumerate(a):
                    acc += (j + 1) ** k * v
                checks[k] = acc % ALPH

            if checks == given_checks:
                return ''.join(i_to_ch(x) for x in a)

        a[i] = original

    return main

def main():
    t = int(input())
    s = input().strip()

    if t == 1:
        sys.stdout.write(encode(s))
    else:
        sys.stdout.write(decode(s))

if __name__ == "__main__":
    main()
```エンコード関数は、メッセージの加重合計を集計することによって 10 文字のチェックサム ブロックを構築します。 デコード機能はまず破損が発生したかどうかを確認します。 一致している場合は、各位置の修正を試み、すべてのチェックサム方程式が一貫しているかどうかを検証します。 

実装の微妙な詳細は、デコードの各試行後に元の文字を復元することです。 これを忘れると、裁判をまたいで腐敗が連鎖的に進行します。 もう 1 つの詳細は、候補ごとにチェックを新たに再計算することです。 増分更新は可能ですが、制約が少ないため不要です。

 ## 特殊なケース

 単一文字メッセージの場合は、チェックサム ロジックが正しく縮退しているかどうかをテストします。 すべてのチェックは位置に依存するため、長さ 1 の文字列は 10 回のチェックすべてにわたって一貫した値を生成し、デコードによって誤って変更が試行されることはありません。 

2 番目のエッジ ケースは、すべての文字が同一であるメッセージです。 生の文字の多様性がゼロであっても、位置の重み付けによってチェックサム空間内の位置が区別されます。 特定のインデックスが破損すると、他の位置では複製できない方法ですべてのチェックが変更されるため、ブルート フォース リカバリでも一意の修正が分離されます。 

3 番目のエッジ ケースは、破損が発生しない場合です。 デコーダは、再計算されたチェックと保存されたチェックを比較することで、これを早期に検出する必要があります。 このチェックを行わないと、アルゴリズムが不必要に変更を試行し、正しい文字列を上書きする危険があります。
