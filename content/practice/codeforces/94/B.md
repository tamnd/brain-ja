 ## 解決策
 ## 問題の理解

 ちょうど5人います。 いくつかの人々はお互いを知っており、入力にはそのような知人関係がすべてリストされます。 

タスクは、次のいずれかが存在するかどうかを判断することです。 

1. どのペアもお互いを知っている 3 人。 
2. お互いを知らない3人。 

これは当然グラフの問題です。 一人ひとりが頂点であり、知人関係は無向の辺である。 次のいずれかを探しています。 

1. グラフ内の三角形。 
2. 補数グラフ内の三角形。 

これらの構造の少なくとも 1 つが存在する場合、次のように出力します。`"WIN"`。 それ以外の場合は印刷します`"FAIL"`。 

制約は非常に小さいです。 5 つの頂点上の無向グラフは`5 * 4 / 2 = 10`可能なペア。 すべてのトリプルを総当たり検索しても、ほんのわずかです。 トリプルの合計数は`C(5, 3) = 10`。 

主な困難はパフォーマンスではなく、条件を正しく実装することです。 

簡単な間違いの 1 つは、友情のトライアングルだけをチェックし、独立したトリプルを忘れることです。 次の入力を考えてみましょう。```
2
1 2
3 4
```正しい答えは次のとおりです。```
WIN
```人々`1, 3, 5`ペアでは面識がありません。 友情の三角形のみを検索するソリューションでは、誤って出力されます。`"FAIL"`。 

もう 1 つのよくあるバグは、グラフを指示どおりに処理することです。 この関係は対称であるため、次の場合`(1, 3)`が表示されると、`3`も知っています`1`。 隣接構造が不注意であると、これを忘れて有効なトリプルを見逃す可能性があります。 

例えば：```
3
1 2
2 3
1 3
```正しい答えは次のとおりです。```
WIN
```これは友情の三角関係です。 実装が各エッジの一方向のみを保存する場合、チェックは失敗する可能性があります。 

より微妙なエッジ ケースは、空のグラフです。```
0
```正しい答えは次のとおりです。```
WIN
```任意の 3 人が、ペアごとの見知らぬ人のトリプルを形成します。 少なくとも 1 つのエッジが存在することを前提としたソリューションは、ここでは誤った動作をする可能性があります。 

## アプローチ

 最も直接的な解決策は、3 人組の人々すべてに対して総当たり攻撃を行うことです。 

5人しかいないのであらゆる組み合わせを列挙できる`(a, b, c)`どこ`a < b < c`。 各トリプルについて、2 つの条件をチェックします。 

1. 3 つのペアはすべてエッジです。 
2. 3 つのペアはいずれもエッジではありません。 

いずれかのトリプルに対していずれかの条件が true の場合、すぐに戻ります。`"WIN"``。 

この強引なアプローチはすでに十分に高速です。 トリプルは 10 個しかなく、各チェックでは 3 つのペアが検査されるため、合計の作業量は一定です。 

これが非常に自然に機能する理由は、私たちが関心を持っているプロパティがトリプルに対して完全にローカルであるためです。 より大きなグラフ構造、最短パス、接続されたコンポーネント、またはグローバルなものは一切必要ありません。 

ブルート フォースのより素朴なバージョンでは、人々のすべてのサブセットを明示的に構築し、サイズ 3 のすべてのサブセットをテストします。 グラフが小さいためこれでも機能しますが、不必要なオーバーヘッドが発生します。 

重要な観察は、問題が正確にすべてのトリプルを 1 回チェックすることに帰着するということです。 グラフのサイズは 5 に固定されているため、これは最適化の問題ではなく、コンパクトな実装の問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 一般的なサブセット ブルート フォース | O(2^5) | お(1) | 承認済み |
 | トリプル列挙 | O(C(5,3)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.`5 x 5`で初期化された隣接行列`False`。 

マトリックスを使用すると、2 人がお互いを知っているかどうかを一定時間内に確認できます。 
2. 各知人ペアを読む`(a, b)`。 

インデックスをゼロベースのインデックスに変換し、両方を設定します`adj[a][b]`そして`adj[b][a]`に`True`。 

グラフは無向であるため、両方向を保存する必要があります。 
3. 異なる人々のトリプルをすべて列挙する`(i, j, k)`と`i < j < k`。 

順序付きトリプルを使用すると、重複が回避され、3 人のグループがすべて 1 回だけチェックされることが保証されます。 
4. 現在のトリプルについて、3 つのペアすべてが接続されているかどうかを計算します。 

必要なエッジは次のとおりです。`i-j`、`i-k`、 そして`j-k`。 
5. 3 つのペアがすべて存在しないかどうかを計算します。 

これは、3 つのエッジがいずれも存在しないことを意味します。 
6. いずれかの条件が true の場合、出力します。`"WIN"`そしてやめてください。 

有効なトリプルが 1 つだけ必要です。 
7. すべてのトリプルがチェックされ、条件を満たすものがない場合は、出力します。`"FAIL"`。 

### なぜ効果があるのか

 すべての有効な答えは、3 人のグループにのみ依存します。 このアルゴリズムは、考えられるすべてのトリプルを 1 回だけ検査します。 各トリプルについて、問題から両方の定義をチェックします。 

1. ペアの知り合い。 
2. ペアごとに面識がない。 

このようなトリプルがグラフ内のどこかに存在する場合、列挙は最終的にそれに到達して戻ります。`"WIN"`。 アルゴリズムが見つからずに終了した場合は、条件を満たすトリプルが存在しないことになります。`"FAIL"`は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# solution

def solve():
    m = int(input())

    adj = [[False] * 5 for _ in range(5)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1

        adj[a][b] = True
        adj[b][a] = True

    for i in range(5):
        for j in range(i + 1, 5):
            for k in range(j + 1, 5):

                ab = adj[i][j]
                ac = adj[i][k]
                bc = adj[j][k]

                all_friends = ab and ac and bc
                all_strangers = (not ab) and (not ac) and (not bc)

                if all_friends or all_strangers:
                    print("WIN")
                    return

    print("FAIL")

solve()
```グラフが小さく、「エッジはありますか」という形式の質問が頻繁に発生するため、ここでは隣接行列が最も単純な表現です。`(u, v)`各検索は単一の配列アクセスになります。 

ループは使用します`i < j < k`したがって、すべてのトリプルは 1 回だけ表示されます。 これにより、重複した作業が回避され、同じ人物が複数回登場するという偶発的なケースが防止されます。 

変数`ab`、`ac`、 そして`bc`ロジックが読みやすくなり、インデックス作成操作の繰り返しが減ります。 トリプルごとに関連するエッジは 3 つだけであるため、明示的に名前を付けることで条件を明確に保つことができます。 

実装では、両方の必要なパターンを個別にチェックします。```
all_friends = ab and ac and bc
all_strangers = (not ab) and (not ac) and (not bc)
```これらの条件を 1 つの式に混在させると、特に否定の場合に論理的な間違いが生じることがよくあります。 

答えを決定するには 1 人の証人で十分であるため、プログラムは有効なトリプルを見つけるとすぐに終了します。

        m = int(input())

        adj = [[False] * 5 for _ in range(5)]

            b -= 1

0

all_friends = False
all_strangers = True
```したがって、正しく出力されます。```
WIN
```これは、アルゴリズムがエッジのないグラフを処理していることを確認します。 

次に、5 サイクルの反例を考えてみましょう。```
5
1 2
2 3
3 4
4 5
5 1
```すべてのトリプルには、正確に 1 つのエッジまたは正確に 2 つのエッジが含まれます。 エッジが 0 つまたは 3 つ含まれるものはありません。 このアルゴリズムは 10 個のトリプルすべてを体系的にチェックしますが、有効なトリプルが見つからないため、次のように出力します。```
FAIL
```これは、ステートメントが 5 人にとって普遍的に真実ではないことを証明するため、正しさが決定的に重要なケースです。

2 3

```アルゴリズムが 3 倍に達すると`(1,2,3)`、必要な 3 つのエッジがすべて存在します。```

```それで`all_friends`になる`True`とすると、アルゴリズムはすぐに次のように出力します。```
