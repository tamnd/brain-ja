 ## 解決策
 ## 問題の理解

 タスクは、値が追加される間、シーケンスを維持することです。 各追加操作の後、一部のクエリは、現在のシーケンスの任意のサブシーケンスを取得し、選択した要素を XOR 演算することで取得できる k 番目の最小の個別の値を要求します。 空のサブシーケンスは許可されるため、常にゼロが可能な答えの 1 つになります。 存在する異なる XOR 結果が k 個未満の場合、クエリは -1 を返します。 これは、シーケンスの XOR スパンを維持するクエリ バージョンです。 

シーケンスの長さは 200000 まで拡張でき、すべての値は 60 ビットに収まります。 サブシーケンスの数は指数関数的に増加するため、サブシーケンスを生成しようとするソリューションは直ちに不可能になります。 到達可能なすべての XOR 値を格納するソリューションであっても、最終的には最大 2^60 の可能な値を処理する必要があり、メモリに収まりません。 有益な観察は、XOR がビットに対する線形代数のように動作するということです。 ビット数は60固定なのでビット数に比例した演算が可能です。 

いくつかの特殊なケースは見落とされがちです。 繰り返される値のみを含むシーケンスを考えてみましょう。```
Input
3
1 5
1 5
2 3
```2 回の挿入の後、可能な XOR 値は 0 と 5 のみです。答えは -1 であり、別の値が生成されるわけではありません。 独立した XOR 方向ではなく、挿入された要素をカウントするソリューションは、ここでは失敗します。 

もう 1 つのケースは、以前の値から値を形成できる場合です。```
Input
4
1 1
1 2
1 3
2 4
```到達可能な値は 0、1、2、3 です。異なる値は 4 つしかないため、答えは -1 です。 不注意な実装では、3 つの数値が 8 つのサブシーケンスを作成すると考え、8 つの異なる XOR 結果があるかのように応答する可能性があります。 

境界ケースは最初のクエリです。```
Input
2
2 1
2 2
```挿入前に可能な唯一の XOR は、空のサブシーケンスからの 0 です。 最初のクエリは 0 を返し、2 番目のクエリは -1 を返します。 数値が挿入されていない場合でも、基底は空の XOR 値をサポートする必要があります。 

## アプローチ

 簡単なアプローチは、作成できるすべての XOR 値のセットを保持することです。 新しい数値が到着すると、既存の値はすべて変更されないままになるか、新しい数値と XOR 演算されます。 これが機能するのは、すべての古いサブシーケンスが新しい要素をスキップするか、新しい要素を取得するためです。 ただし、多くの操作を行うと、セットは最大 2^60 の完全な XOR 空間サイズに近づく可能性があります。 これほど多くの値を更新して保存することは不可能です。 

ブルート フォースがこれほど急速に増大する理由は、多くの異なるサブシーケンスが実際には冗長であるためです。 XOR の場合、すべての数値はビットのベクトルであり、XOR をとることは、2 を法として加算が行われるベクトルの加算と同等です。独立したベクトルのセットは、考えられるすべての XOR 結果を記述するのに十分です。 この構造は線形基底と呼ばれます。 

考えられる最高の設定ビットごとに 1 つの基底ベクトルを維持します。 数値を挿入するときは、既存の基底ベクトルを使用してその最上位ビットを削除しようとします。 数値がゼロになった場合、その数値はすでに表現可能です。 基底ベクトルが所有していない最上位ビットがまだある場合は、それをそこに保存します。 60 ビットしかないため、すべての挿入は高速です。 

k 番目に小さいクエリに答える場合、基底は正確に 2^ ランクの異なる値を持つ空間を表します。 基底ベクトルは二分決定として扱うことができます。 最上位ビットから始めて、ビットが 0 に等しい値がいくつあるかを確認することで、答えにそのビットを設定する必要があるかどうかを決定します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 更新ごとに O(2^n) | O(2^60) | 遅すぎる |
 | 最適 | 操作ごとに O(60) | お(60) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を維持する`basis`サイズ60の。`basis[i]`最上位の設定ビットが`i`、そのようなベクトルが存在しない場合はゼロ。 

数値が挿入されると、上位ビットから下位ビットに減算されます。 2 つの基底ベクトルは同じ最上位ビットを共有できないため、最上位ビットが最も重要な部分になります。 

1. 挿入の場合、59 から 0 までのビットをスキャンします。数値の現在のビットが 0 の場合、リダクションには影響しません。 このビットに基底ベクトルがすでに存在する場合は、それを XOR します。 それ以外の場合は、現在の数値を新しい基底ベクトルとして保存します。 

これにより、数値をその XOR によって別の到達可能な数値に置き換えても、形成できる内容は変わらないため、到達可能な XOR 値の同じセットが保存されます。 

1. 現在のランク (非ゼロ基底ベクトルの数) を維持します。 個別の XOR 値の数は次のとおりです。`2^rank`。 

クエリでこの量より大きい k が要求された場合、答えはありません。 

1. k 番目に小さい値を見つけるには、基底を最上位ビットから下方向に処理します。 最上位ビットが小さいベクトルは、より大きいビットに対して既に行われた決定を変更できません。 

ビットの基底ベクトルの場合`i`、残りのすべての組み合わせのちょうど半分にビットがあります。`i`ゼロに等しい、半分は 1 に等しい。 もし`k`はゼロ グループ内にあるため、ベクトルをスキップします。 それ以外の場合は、ベクトルを取得し、からゼロ グループのサイズを減算します。`k`。 

1. 構築された値を返します。 

機能する理由: 基底ベクトルは独立しているため、到達可能なすべての XOR 値は基底ベクトルのサブセットとして 1 つの表現を持ちます。 2 つの表現間で最も異なるビットによって、どちらの値が大きいかが決まります。つまり、上位ビットから下位ビットへの検索は、すべての可能な値の並べ替え順序と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    basis = [0] * 60
    rank = 0
    ans = []

    def insert(x):
        nonlocal rank
        for b in range(59, -1, -1):
            if ((x >> b) & 1) == 0:
                continue
            if basis[b]:
                x ^= basis[b]
            else:
                basis[b] = x
                rank += 1
                return

    def kth_smallest(k):
        if k > (1 << rank):
            return -1

        res = 0
        remaining = rank

        for b in range(59, -1, -1):
            if basis[b]:
                remaining -= 1
                cnt_zero = 1 << remaining
                if k > cnt_zero:
                    k -= cnt_zero
                    res ^= basis[b]

        return res

    for _ in range(q):
        t, x = map(int, input().split())
        if t == 1:
            insert(x)
        else:
            ans.append(str(kth_smallest(x)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`insert`関数は、バイナリ ベクトルに対するガウス消去ステップです。 入力値が 2^60 より小さいため、ループはビット 59 から開始され、59 より上のビット位置は表示されません。 

クエリ関数は、まず、要求された位置が存在するかどうかを確認します。 表現`1 << rank`すべての独立した基底ベクトルが可能な XOR 値の数を 2 倍にするため、この関数は機能します。 

変数`remaining`現在のビットの後、まだ決定されていない基底選択肢の数をカウントします。 これにより、現在のビットが 0 であるブロックのサイズが得られます。 からの引き算`k`これは、ブロック全体をスキップして現在のビットを 1 つとして選択した場合にのみ発生します。 

XOR 値の大きな配列は作成されないため、実装はメモリ制限内に留まります。

import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    data = sys.stdin.readline
    q = int(data())
    basis = [0] * 60
    rank = 0
    out = []

    def insert(x):
        nonlocal rank
        for b in range(59, -1, -1):
            if (x >> b) & 1:
                if basis[b]:
                    x ^= basis[b]
                else:
                    basis[b] = x
                    rank += 1
                    return

    def kth(k):
        if k > (1 << rank):
            return -1
        res = 0
        rem = rank
        for b in range(59, -1, -1):
            if basis[b]:
                rem -= 1
                if k > (1 << rem):
                    k -= 1 << rem
                    res ^= basis[b]
        return res

    for _ in range(q):
        t, x = map(int, data().split())
        if t == 1:
            insert(x)
        else:
            out.append(str(kth(x)))

    sys.stdin = old
    return "\n".join(out)

 ## 特殊なケース

 繰り返される値の場合、次のようになります。```
3
1 5
1 5
2 3
```最初の挿入では 1 つの基底ベクトルが作成されます。 2 番目の挿入は既存の方向と同じであるため、ゼロになります。 ランクは 1 のままであるため、0 と 5 の 2 つの値のみが存在します。3 番目に小さい値は存在しません。 

結合して別の値になる値の場合:```
4
1 1
1 2
1 3
2 4
```3 回目の挿入ではランクは上がりません。`1 XOR 2 = 3`。 この基底には依然として 2 つの独立したベクトルしかなく、4 つの可能な XOR 結果が得られます。 アルゴリズムは正しく -1 を返します。 

空のシーケンスの場合:```
2
2 1
2 2
```ランクは 0 であるため、到達可能な値の数は次のとおりです。`2^0 = 1`。 唯一の値はゼロです。これは、何も選択しない場合に得られます。 最初のクエリはゼロを返し、2 番目のクエリには応答できません。
