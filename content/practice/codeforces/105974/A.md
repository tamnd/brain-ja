 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、順序を維持しながら要素のサブセットを選択することによって形成されるすべての可能なサブシーケンスを考慮します。 選択したサブシーケンスごとに、そのすべての要素のビットごとの XOR を計算します。 タスクは、すべてのサブシーケンスにわたって個別の XOR 値をいくつ生成できるかを決定することです。 

サブシーケンスは順序を保持しますが、XOR 演算自体は順序を無視するため、重要なのは、要素がどこに表示されるかではなく、どの要素が選択されるかです。 2 つの異なるサブシーケンスでも同じ XOR 値が生成される可能性があり、可能な一意の結果がいくつあるかを数えるように求められます。 

配列の長さが約 10^5 までの場合、部分列を直接列挙するアプローチは不可能です。 部分列の数は 2^n であり、n がある程度大きくなると、すでに実行可能な計算を超えます。 これにより、あらゆる指数列挙戦略が即座に除外され、すべてのサブセット XOR のセットを圧縮形式で表現する方向に進みます。 

一般的な失敗例は、セット内の「すべての XOR を段階的に追跡」しようとすることから発生します。 たとえば、配列が [1, 2, 3] の場合、要素の追加と到達可能な XOR のセットの更新をシミュレートできます。 これは n が小さい場合には機能しますが、最悪の場合、各ステップで状態空間が 2 倍になります。 n = 30 では、これはすでに境界線になっており、n = 10^5 では不可能です。 

もう 1 つの微妙な問題は、要素の重複です。 たとえば、[5, 5] はサブシーケンス XOR {0, 5} を生成します。 構造を持たずにオカレンスを独立して処理する単純な実装では、XOR 代数を明示的に正しく処理しない限り、カウントしすぎたりキャンセルを見逃したりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのサブシーケンスを生成し、その XOR を計算して、それをセットに挿入します。 これは問題の定義に直接従うため、正しいです。 ただし、サブシーケンスの数は 2^n であり、各 XOR 計算のコストは最大 O(n) であるため、合計作業量は O(n · 2^n) 程度になります。 これは、n が 25 程度になるとすでに実行不可能になります。 

重要な観察は、サブセットに対する XOR がバイナリ フィールドに対して線形構造を形成するということです。 各数値はビットのベクトルとして解釈でき、XOR はベクトル加算 mod 2 に対応します。すべてのサブセット XOR のセットは、まさに指定されたベクトルの線形スパンです。 組み合わせを列挙する代わりに、このスパンの次元を理解するだけで済みます。 

これは、線形基底 (XOR 基底とも呼ばれます) の概念につながります。 任意の配列要素をいくつかの基底要素の XOR として表現できるように、独立したベクトルのセットを維持します。 新しい数値を挿入するたびに、以前に保存された基底ベクトルを使用して数値を削減しようとします。 ゼロにできない場合は、新たな独立した方向となります。 

最終基底のサイズが k の場合、各サブセットの XOR は、各基底ベクトルを含めるかどうかを独立して選択することに対応します。 これにより、正確に 2^k 個の異なる XOR 値が生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · 2^n) | O(2^n) | 遅すぎる |
 | 線形基準 | O(n log A) | O(1) から O(log A) | 承認済み |

 ここで、A は配列内の最大値です。 

## アルゴリズムのチュートリアル

1. 各位置が上位から下位のビットに対応する空の XOR 基底構造を初期化します。 この構造体は、ビット位置ごとに最大 1 つのベクトルを保存します。 
2. 配列内の各数値を反復処理します。 現在の数値については、既存の基準を使用して削減を試みます。 最上位から最下位までの各ビットについて、そのビットが設定されており、そのビットの基底ベクトルがすでにある場合は、数値とその基底ベクトルを XOR して先頭ビットを削除します。 このステップでは、スパン内での表現可能性を維持しながら、数値を段階的に単純化します。 
3. 縮小後、数値がゼロになった場合は、すでに既存の基底要素から形成できることを意味するため、空間の次元数は増加しません。 
4. 数値がゼロでない場合は、その最上位の設定ビットを見つけて、それを基底のその位置に挿入します。 これにより、独立したベクトルのセットが拡張されます。 
5. すべての数値を処理した後、挿入された基底ベクトルの数を数えます。 この数をkとします。 
6. 答えは 2^k で、独立した方向のすべての可能な XOR の組み合わせを表します。 

### なぜ効果があるのか

 この基礎は、線形に独立した XOR ベクトルのセットを維持します。 挿入されたすべてのベクトルは、既存のベクトルの範囲内に存在するか、次元が 1 だけ増加します。 XOR は GF(2) 上のベクトル空間での加算であるため、すべてのサブセット XOR は基底ベクトルの選択に一意に対応します。 したがって、到達可能な XOR 値の数は、スパン内の要素の数をその次元に 2 乗したものと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    B = [0] * 60  # basis for bits up to 2^59
    rank = 0

    for x in arr:
        v = x
        for b in range(59, -1, -1):
            if (v >> b) & 1:
                if B[b]:
                    v ^= B[b]
                else:
                    B[b] = v
                    rank += 1
                    break

    # number of distinct XOR subsets
    print(1 << rank)

if __name__ == "__main__":
    solve()
```このソリューションは固定サイズの配列を維持します`B`ここで、各エントリは、最上位ビットがその位置にある代表ベクトルを格納します。 これにより、すべての新しい挿入がそれ自体を打ち消すか、新しい独立した方向が導入されることが保証されます。 変数`rank`このような独立した方向がいくつ発見されたかを追跡します。 

最後のシフト操作`1 << rank`2^rank を効率的に計算します。 標準の 64 ビット整数のランクは最大 60 であるため、これは安全です。

 | 1 | 1 | 1 | 1を追加 | 1 |

 ## 特殊なケース

 [0] などの単一のゼロ要素入力は、完全に 1 つの異なる XOR 値を生成する必要があります。これは、サブシーケンスが空と [0] のみであり、どちらもゼロを生成するためです。 このアルゴリズムはゼロを即時約分可能として扱い、ランクを増加させないため、結果は 2^0 = 1 になります。 

すべての要素が同一である配列 ([9, 9, 9] など) も、ゼロと値自体の 2 つの異なる XOR のみを生成します。 最初の挿入により 1 つの基底ベクトルが確立され、その後のすべての同一の値はその基底に基づいて 0 に減少し、ランク 1 が維持され、2^1 = 2 が生成されます。 

[1, 2, 4, 8] のようなフルランク構造では、すべての数値が独立した基底ベクトルになることが保証されます。 挿入ごとにランクが 1 ずつ増加し、最終結果 2^4 = 16 は、すべてのサブセット XOR が異なるという事実と一致します。
