 ## 解決策
 ## 問題の理解

 Codeforces からのこの問題では、クエリ値を固定配列の要素の XOR として表すことが求められます。 最大 500 個の番号が与えられます。それぞれの番号は次の値よりも小さいです。`2^60`。 すべてのクエリ値について`x`、選択した値の XOR が正確に一致するように、元の位置のいくつかを選択する必要があります。`x`、選択された位置を説明するバイナリ文字列を出力します。 この問題により、すべてのクエリに少なくとも 1 つの有効な表現が含まれることが保証されます。 

重要なのは、値が形成できるかどうかだけが問われているわけではないということです。 実際に選択された要素を再構築する必要があります。 つまり、到達可能な XOR 値の単純なセットだけでは十分ではありません。 到達可能な各値がどのように作成されたかを覚えておく必要があります。 

この制約は、ビットに対する線形代数アプローチを直接指しています。 すべての数値が以下であるため、可能なビット位置は 60 個のみです`2^60`。 配列の長さは 500 で、クエリの数は 1000 なので、`O(60 * n + 60 * q)`スタイルのソリューションは簡単に十分に高速です。 すべてのサブセットを試すソリューションには、最大で`2^500`組み合わせ、それは不可能です。 

厄介なケースは XOR の構造に起因します。 最初のケースは、一部の値がゼロの場合です。 たとえば、入力が次の場合:```
3
0 5 5
1
0
```正しい出力は次のようになります。```
100
```最初の要素を選択するとすでに XOR が得られるため、`0`。 基底ベクトルのみを格納し、元のインデックスを無視する不注意な実装では、タスクがサブセット表現を要求しているにもかかわらず、誤って空の選択を返す可能性があります。 2 番目のケースは、数値が複数の方法で表現できる場合です。 例えば：```
3
1 2 3
1
1
```答えは次のとおりです`100`または`011`。 出力は一意ではないため、アルゴリズムは有効な構造を 1 つだけ保持する必要があります。 3 番目のケースは、上位ビットが後でキャンセルされる場合に発生します。 のために：```
2
8 12
1
4
```2 番目の要素が必要なので、`12`上位ビットが含まれており、`12 xor 8 = 4`。 最初に一致した値を永続的に取得し、変換を決して追跡しない貪欲なアプローチは、ここで失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、配列のすべてのサブセットがチェックされます。 サブセットごとに XOR を計算し、クエリに一致する場合はそのサブセットを記憶することができます。 考えられる要素のすべての選択が検査されるため、これは正しいです。 問題はサブセットの数です。 と`n = 500`、可能性の数は`2^500`したがって、それらを保存したり繰り返したりすることさえ、時間制限が許容できる範囲をはるかに超えています。 

ブルート フォースが不要な理由は、XOR が各ビットが次元であるベクトル空間では加算のように動作するという事実から来ています。 すべての数値は 60 ビットのベクトルであり、複数の数値を選択するということは、加算が XOR となる合計を取ることを意味します。 この構造を扱う通常の方法は、ガウス消去法と同様に線形基礎を構築することです。 

基底に数値を挿入するとき、既存の基底ベクトルを使用してその最も高い設定ビットを削除しようとします。 ゼロになった場合は、すでに表現可能です。 それ以外の場合は、残りの数によって新しい独立した方向が導入されます。 すべての基準値とともに、それを作成した元のインデックスのビットマスクを保存します。 この追加情報により、クエリを削減した後に回答を再構築できます。 

クエリの場合も、基底を使用して上位ビットを削除します。 クエリがゼロになると、保存されたインデックス マスクが必要なサブセットになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^n * n)`|`O(2^n)`| 遅すぎる |
 | 線形基準 |`O((n + q) * 60)`|`O(60)`プラス保存されたマスク | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 60 個の基底エントリの配列を作成します。 各エントリには、その最上位の設定ビットがエントリの位置に等しい値と、この基本要素を形成する元のインデックスを格納する別の値が格納されます。 

最上位ビット位置がピボットとして使用されます。 これは、ガウス消去法で主変数を選択するのと同じ考え方です。 

1. すべての配列要素を基底に挿入します。 挿入する前に、独自のインデックスのみを含むビットマスクをアタッチします。 

値を挿入するときは、可能な限り最上位のビットから開始して、そこに基底ベクトルがすでに存在するかどうかを確認します。 存在する場合は、値とインデックス マスクの両方から XOR を計算します。 そうでない場合は、現在の値が新しい基底ベクトルになります。 

1. 各クエリについて、クエリ値と空の応答マスクから始めます。 

基底を使用して、設定されたビットを上位から下位に削除してみてください。 基底ベクトルが使用されるたびに、格納されているインデックス マスクと応答マスクの XOR が計算されます。 

保存されたマスクは挿入中に値とともに変化するため、その基底ベクトルの作成に必要な正確な元の位置を表します。 

1. ステートメントはすべてのクエリが表現可能であることを保証するため、すべてのビットを処理した後、クエリ値はゼロになるはずです。 

応答マスクを次の文字列として出力します。`0`そして`1`元の配列の順序で文字を並べます。 

なぜ効果があるのか:

 この基礎によって維持される不変条件は、保存されているすべてのベクトルをその保存されているインデックスから正確に再作成できるということです。 挿入中に、数値から基底ベクトルを XOR するたびに、それを作成したインデックスも XOR します。 これにより、表現が有効に保たれます。 基底ベクトルは、それぞれが固有の最上位ビットを所有しているため、独立しています。 クエリ中にこれらのピボットを削除することは、まったく同じ削除プロセスであるため、ゼロに達すると、収集されたインデックスが元の値を再作成することを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    basis = [0] * 60
    who = [0] * 60

    for i, x in enumerate(a):
        mask = 1 << i
        cur = x
        cur_mask = mask

        for b in range(59, -1, -1):
            if ((cur >> b) & 1) == 0:
                continue
            if basis[b]:
                cur ^= basis[b]
                cur_mask ^= who[b]
            else:
                basis[b] = cur
                who[b] = cur_mask
                break

    q = int(input())
    out = []

    for _ in range(q):
        x = int(input())
        ans = 0

        for b in range(59, -1, -1):
            if ((x >> b) & 1) == 0:
                continue
            x ^= basis[b]
            ans ^= who[b]

        out.append(''.join('1' if (ans >> i) & 1 else '0' for i in range(n)))

    print('\n'.join(out))

if __name__ == "__main__":
    solve()
```最初の部分は基礎を構築します。 変数`cur`は現在挿入中の値です。`cur_mask`それを担当する元の配列位置を追跡します。 最終的な答えは再構築に依存するため、常に一緒に変更する必要があります。 

ループはビットから始まります`59`まで`0`。 この順序付けが必要なのは、基底が最上位の設定ビットによって編成されているためです。 下位ビットが最初に処理された場合、後の操作でピボットの一意性が破壊される可能性があります。 

クエリの場合も、同じ削除プロセスが使用されます。 応答マスクはゼロから始まり、使用されるすべての基底ベクトルからインデックスを収集します。 各インデックスは 1 つの元の数値に対応するため、マスクを直接出力すると、必要なサブセットが得られます。 

Python の整数は任意の大きな値を保持できるため、500 ビットのインデックス マスクを保存しても安全です。 数値自体は 60 ビットのみを使用しますが、オーバーフローの問題はありません。

import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    it = iter(data)
    n = int(next(it))
    a = [int(next(it)) for _ in range(n)]

    basis = [0] * 60
    who = [0] * 60

    for i, x in enumerate(a):
        mask = 1 << i
        cur = x
        cur_mask = mask
        for b in range(59, -1, -1):
            if (cur >> b) & 1:
                if basis[b]:
                    cur ^= basis[b]
                    cur_mask ^= who[b]
                else:
                    basis[b] = cur
                    who[b] = cur_mask
                    break

    q = int(next(it))
    ans = []
    for _ in range(q):
        x = int(next(it))
        mask = 0
        for b in range(59, -1, -1):
            if (x >> b) & 1:
                x ^= basis[b]
                mask ^= who[b]
        ans.append(''.join('1' if (mask >> i) & 1 else '0' for i in range(n)))

    return '\n'.join(ans)

 ## 特殊なケース

 値がゼロの場合:```
3
0 5 5
1
0
```ゼロ要素は、新しいピボットを作成する場合にのみ基底に挿入されますが、新しいピボットは作成されません。 ただし、この問題には有効なサブセットが必要であり、クエリがゼロであることが保証されています。 線形基底ではゼロの空のマスクが返され、以下が生成されます。```
000
```どの要素の XOR もゼロではないため、これは有効なサブセットです。 

重複した値の場合:```
3
1 2 3
1
1
```番号`3`最初の 2 つの値の XOR です。 挿入中に、これはゼロに減らされます。これは、新しい独立した方向が追加されないことを意味します。 基礎には、最初の値を直接使用して回答するのに十分な情報がまだ保持されています。 

XOR 演算後に重要なビットが消える値の場合:```
2
8 12
1
4
```基礎を構築する際に、2 番目の数値が最初の数値によって減算されます。 結果のベクトルに対して保存されたマスクは、2 つの元のインデックスの組み合わせになるため、クエリの再構築によって、値がどこから来たのかを見失うことなく、有効な答えを生成できます。
