 ## 解決策
 ## 問題の理解

 合計で配布するように求められています`k`釣り込む`n`魚の水槽。各水槽には正の整数の魚が含まれている必要があります。 この分布を修正した後、水槽の空ではないすべてのサブセットを調べ、それについて構造的な質問をします。サブセット自体を、合計の魚数が等しい 2 つの素のグループに分割できるかどうかです。 

このような分割が存在する場合、サブセットは「不良」とみなされます。 この要件は非常に厳しく、空ではないタンクのサブセットが不良であることは許可されません。 言い換えれば、すべてのサブセットは、その要素を合計が同じになる 2 つの部分に分割することが不可能であるという意味で、本質的に「アンバランス」でなければなりません。 

出力は、魚数の有効な割り当て、またはそのような割り当てが存在しないという宣言のいずれかです。 

制約は小さく、両方とも`n`そして`k`最大でも 200 です。これは、サブセットに対する複雑な動的プログラミングや、値に対する指数関数的な検索を扱っていないことを示しています。 むしろ、条件の構造が主な困難です。 

微妙なエッジケースはフルセットそのものです。 より小さいサブセットには機能するが、配列全体を等しい合計の半分に分割できる配置を選択した場合、それはすでに条件に違反しています。 たとえば、次のような対称構成`[1, 1, 2]`フルセットは次のように分割できるため、失敗します。`{1,1}`そして`{2}`。 

もう 1 つの重要なエッジ ケースは、単一の正の整数を 2 つの空でないグループに分割できないため、サイズ 1 のサブセットが常に自動的に有効になることです。 正しい構築では、サイズが少なくとも 2 のサブセットについてのみ考慮する必要があります。 

## アプローチ

 強引な解釈では、可能なすべての割り当てを試みます。`n`正の整数の合計`k`、各割り当てについてすべてを列挙します`2^n - 1`次に、サブセットごとに、すべてのパーティションを 2 つのグループに分割するか、内部のサブセット合計が等しいかどうかを同等に確認します。 これは中程度の人でもすぐに実行不可能になります`n`なぜなら、整数構成の構成の数はすでに膨大であり、各構成はサブセットに対する指数関数的なチェックを必要とするからです。 

重要な構造の単純化は、条件を書き直すことで実現します。 固定サブセットの場合`S`、2 つの等和グループに分割できると言うのは、サブサブセットが存在すると言うのと同じです。`T ⊂ S`そのような`sum(T) = sum(S) / 2`。 したがって、実際にはパーティションを直接扱うのではなく、すべてのサブセット内のサブセット合計構造を扱います。 

これは、サブセットの合計が非常に制御された方法で動作するように数値を設計する必要があることを直ちに示唆しています。 サブセットの合計を制御する最も強力な既知の方法は、各要素が以前のすべての要素の合計より厳密に大きくなる超増加シーケンスを使用することです。 

確保できれば`a[i] > a[1] + ... + a[i-1]`、その後、何か強力なことが起こります。 任意のサブセットを取得します`S`そしてその最大の要素に注目してください`x`。 その要素は、プレフィックス全体の他のすべての要素の合計よりも厳密に大きいため、サブセット内の他のすべての要素の合計よりも大きくなります。 これにより、内部での等和パーティションが防止されます。`S`、どちらの側に含まれるかに関係なく、`x`すぐに相手を圧倒します。 

これにより、問題全体が超増加する長さのシーケンスを構築することに帰着します。`n`それは正確に次のようになります`k`。 

ただし、超増加シーケンスは最小形式では少なくとも指数関数的に増加します。そのようなシーケンスの最小のものは次のとおりです。`1, 2, 4, ..., 2^{n-1}`、その合計は`2^n - 1`。 これは直ちに実現可能性を制限します。`k ≤ 200`までしかサポートできません。`n = 7`。 

実現可能性が確立されると、構築は簡単になります。`n-1`2 のべき乗を計算し、残りの合計を吸収する最後の値を割り当てます。

 ## アルゴリズムのチュートリアル

 1. かどうかを確認します。`n`が大きすぎるため、合計制限内で超増加シーケンスをサポートできません。 長さの最小和なので`n`は`2^n - 1`、 もし`n ≥ 8`、出力`No`。 この限界は、有効な構造の指数関数的な増加から直接得られます。 
2. 最初の値を計算します`n-1`2 のべき乗としての値:`a[0] = 1`、`a[1] = 2`、などまで`2^{n-2}`。 これにより、プレフィックスがすでに超増加していることが保証され、サブセットの合計を厳密に制御できます。 
3. Compute the sum of these first`n-1`価値観。 電話してください`S`。 
4. 最後の要素を次のように設定します。`k - S`。 これにより、合計が要件と正確に一致するようになります。 
5. 構築された配列を出力します。 

唯一明らかではない部分は、このように最後の値を代入してもプロパティが壊れない理由です。 その理由は、構造が有効であるときは必ずプレフィックスの合計がすでに厳密に最後の値よりも小さくなり、配列全体にわたって超増加条件が維持されるためです。 

### なぜ効果があるのか

 任意のサブセットについて、`x`がその最大の要素になります。 超増加シーケンスでは、`x`は、プレフィックス全体の他のすべての要素の合計よりも厳密に大きいため、そのサブセット内の他のすべての要素の合計よりも大きくなります。 サブセットを合計が等しい 2 つのグループに分割すると仮定すると、どちらのグループにも`x`の合計は他のグループよりも厳密に大きくなりますが、これは不可能です。 したがって、等しい分割を許可するサブセットはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k, n = map(int, input().split())

    # minimal sum for superincreasing sequence of length n is 2^n - 1
    if n >= 8:
        print("No")
        return

    # build powers of two
    a = []
    for i in range(n - 1):
        a.append(1 << i)

    s = sum(a)
    last = k - s

    # must keep positivity and superincreasing property
    if last <= s:
        print("No")
        return

    a.append(last)

    if sum(a) != k:
        print("No")
        return

    print("Yes")
    print(*a)

if __name__ == "__main__":
    solve()
```この構造では、最初にサブセット合計の制御を保証する厳格なプレフィックスを修正し、次に最後の要素をバランス項として使用して正確な合計を達成します。`k`。 実現可能性に関するチェックにより、超増加構造を誤って壊すことがないことが保証されます。 

微妙な実装の詳細は、`last <= s`チェック。 これがないと、最後の要素が正しさの議論の最終ステップに必要な優性プロパティに違反する可能性があります。 たとえ理論上の限界があるとしても、`n ≥ 8`すでに不可能なケースのほとんどが排除されており、このガードにより境界値に対して建設が安全に保たれます。

 ## 特殊なケース

 のために`n = 1`の場合、アルゴリズムはすぐに次の値に等しい単一の正の整数を出力します。`k`。 1 を超えるサイズの空でないサブセットは存在しないため、違反するパーティション条件がないため、正の値はすべて有効です。 

のために`n ≥ 8`の場合、最小の超増加シーケンスですらすでに許容合計限界を超えているため、構築は不可能です。 アルゴリズムはこれらのケースを事前に拒否し、有効な構造の指数関数的な下限と一致します。 

境界例の場合、`k`まさに最小合計です`2^n - 1`、この構造により、正規の 2 の累乗シーケンスが生成されます。 超増加特性がすべてのレベルで厳密に保持され、サブセットが均等に分割されないことが保証されるため、すべてのサブセットは依然として安全です。
