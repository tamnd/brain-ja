 ## 解決策
 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$ここで、各セルは 0 または 1 です。このグリッドから、グリッド線に沿って配置されたすべての可能なサブ長方形を検討します。 各四角形は、上の行、下の行、左の列、右の列を選択することによって定義され、少なくとも 1 つのセルが含まれている必要があります。 

長方形を上下反転しても内容が変わらない場合、その長方形は垂直対称と呼ばれます。 具体的に行を比較すると$i$行のある長方形の上から$i$下から順に、長方形内のすべての列で同一である必要があります。 

タスクは、このような垂直対称の長方形がグリッド内にいくつ存在するかを数えることです。 

制約$n \cdot m \le 10^6$重要な構造上のヒントです。 両方の次元で同時に 2 次となる解は除外されます。 すべての四角形に対する単純な列挙にはすでにコストがかかります$O(n^2 m^2)$、これは実現可能な限界をはるかに超えています。 2 つの側面を修正し、残りを単純にスキャンしても、問題がきれいに分解されない限り、依然として爆発します。 

対称性が構造全体ではなく境界行のみでチェックされると、微妙な故障モードが現れます。 たとえば、上部と下部の行は一致しているが、中央の行が対称を破っている長方形について考えてみましょう。 外側の行のみを比較する単純なアプローチでは、誤って受け入れられてしまいます。 

もう 1 つのよくある落とし穴は、行間の対称性が列間の相互作用に依存すると仮定することです。 実際には、各列は行構造が回文であるかどうかに独立して影響し、これが問題を軽減する鍵となります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての四角形が試行されます。 によって定義された各候補について、$(top, bottom, left, right)$、行かどうかをチェックします$top+k$行に一致します$bottom-k$すべて有効な$k$、およびこれが間隔内のすべての列に当てはまるかどうか。 これにはすでに費用がかかります$O(n^2 m^2)$長方形、各チェックは$O(nm)$最悪の場合、これは中程度の入力であっても完全に実行不可能です。 

重要な簡素化は、行条件と列条件を分離することによって実現されます。 長方形は、その内部のすべての列について、行に沿った値のシーケンスが回文を形成する場合に限り、垂直方向に対称になります。 これは、問題が列ごとに分解されることを意味します。つまり、すべての列で同時に有効な回文部分配列である場合に、長方形は正確に有効になります。 

完全な長方形を追跡する代わりに、遠近法を反転します。 列を修正し、それを長さのバイナリ文字列として見る$n$。 垂直対称のすべての長方形は、この列の回文である行の連続セグメントに寄与します。 この四角形は、選択したすべての列で同じ行間隔が回文である場合にのみ有効です。これにより、各列が行全体にわたって回文部分文字列を個別にカウントし、最終的な答えが列全体の合計になることがわかります。 

これにより、列ごとにバイナリ文字列内の回文部分文字列の数を計算する問題が軽減されます。 これは、Manacher のアルゴリズムまたは同等の中心拡張テクニックを使用して列ごとに線形時間で実行でき、全体の複雑さを最小限に抑えます。$O(nm)$。

 ## アルゴリズムのチュートリアル

 グリッドを列ごとに処理し、各列を行全体にわたる独立したバイナリ文字列として扱います。 

1. 1 つの列を文字列として抽出します$s$長さの$n$。 これは、その固定列の行に沿って値がどのように変化するかを表します。 
2. すべての回文部分文字列を計算します。$s$。 これは、Manacher のアルゴリズムなどの線形時間回文展開方法を使用して行われます。 各回文は、この列の有効な垂直対称間隔に対応します。 
3. この列に存在する回文部分文字列の数を数えます。 この数は、この特定の列の対称性を満たす行間隔の数を表します。 
4. このカウントをグローバル回答に追加します。 
5. すべての列に対して繰り返し、合計を出力します。 

微妙な点は、明示的に長方形を構築しているわけではないということです。 代わりに、列内の各回文は行間隔の候補に対応し、すべての列が同じ回文行構造に一致する場合に長方形が正確に有効となるため、列の合計によりすべての有効な長方形が集約されます。 

### なぜ効果があるのか

 任意の長方形を修正します。 垂直対称条件は、その内部のすべての列について、選択した行に沿った値のシーケンスが回文である必要があることを意味します。 したがって、すべての有効な四角形は、各列の回文である行間隔に対応します。 逆に、列内の回文である行間隔は、その列内の 1 つの有効な構造に寄与します。 

これにより、行間隔条件が列ごとに独立してテストされ、累積されるため、カウントを列全体で完全に分離できます。 この列ごとの制約を超えると、列間の相互作用が有効性に影響を与えることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def manacher_count(s):
    # counts palindromic substrings in s
    # transform implicitly by using odd/even radii
    n = len(s)
    d1 = [0] * n  # odd
    l, r = 0, -1
    for i in range(n):
        k = 1 if i > r else min(d1[l + r - i], r - i + 1)
        while i - k >= 0 and i + k < n and s[i - k] == s[i + k]:
            k += 1
        d1[i] = k
        k -= 1
        if i + k > r:
            l, r = i - k, i + k

    d2 = [0] * n  # even
    l, r = 0, -1
    for i in range(n):
        k = 0 if i > r else min(d2[l + r - i + 1], r - i + 1)
        while i - k - 1 >= 0 and i + k < n and s[i - k - 1] == s[i + k]:
            k += 1
        d2[i] = k
        k -= 1
        if i + k > r:
            l, r = i - k - 1, i + k

    return sum(d1) + sum(d2)

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ans = 0
    for col in range(m):
        s = [grid[row][col] for row in range(n)]
        ans += manacher_count(s)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、グリッドを行ごとに読み取り、各列を一時文字列として構築します。 各列について、Manacher のアルゴリズムを使用して回文部分文字列を計算します。 配列$d1$そして$d2$奇数回文と偶数回文の半径をそれぞれ保存し、それらの合計から直接回文部分文字列の数が得られます。 

よくある実装上の間違いは、抽出時に行と列のインデックスを混合することです。$s$。 各列は垂直スライスとして独立して構築する必要があります。そうしないと、回文構造が間違った次元で計算されます。

 ## 特殊なケース

 単一セルグリッドのような`1 1 / 0`有効な四角形が 1 つだけ生成されます。 各列文字列の長さが 1 であり、Manacher が単一の回文を正しく返すため、アルゴリズムはこれを処理します。 

各列が次のように交互に配置されたグリッド`010101...`単一セル回文のみが存在することが保証されます。 拡張はすぐに失敗するため、アルゴリズムは長さ 1 の寄与のみを正しく合計します。 

all one などの完全に均一なグリッドでは、列ごとに最大数の回文部分文字列が生成されます。 各列は独立して生成されます$n(n+1)/2$、列の合計は次のように線形にスケールされます。$m$、アルゴリズムは変更せずに処理します。
