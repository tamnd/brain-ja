 ## 解決策
 ## 問題の理解

 2 つの隠れた順列が与えられ、どちらも 1 から n までの数値を 1 回だけ含みます。 一方の順列は他方の順列の循環回転ですが、どちらもわかりませんし、回転量 k もわかりません。 形式的には、すべての位置 i が a[i] = b[(i + k) mod n] を満たすような未知のシフト k が存在します。 

情報を取得する唯一の方法は、2 つのインデックス x と y を受け取り、max(a[x], b[y]) を返すクエリ操作を行うことです。 各クエリは単一の整数を与えるので、最大 2n 個のそのようなクエリを使用してシフト k を推定する必要があります。 

n ≤ 200 という制約は十分に小さいので、線形のクエリ数を許容しながら、すべての位置について明示的に推論することができます。 すべてのペアを比較しようとするソリューションは理論的には問題ありませんが、クエリ バジェットが O(n²) になるため、クエリ バジェットを超えてしまいます。 これは、順列の構造と最大値の特別な役割を利用する必要があることを直ちに示唆しています。 

k = 0 の場合、微妙なエッジ ケースが現れます。その場合、両方の配列が同一であるため、任意の位置 i は a[i] = b[i] を満たし、正しく 0 を出力するはずです。もう 1 つの重要なエッジ ケースは、ゼロ シフトにより最大値 n が両方の置換で同じインデックスに現れる場合です。 その場合、「2 つの異なる最大値の位置」に関する素朴な推論は崩れるので、慎重に扱う必要があります。 

## アプローチ

 強引なアイデアは、両方の順列を完全に再構築することです。 すべての a[i] と b[i] を決定できれば、シーケンスが整列する場所を見つけることで単純にシフトを計算できます。 ただし、各クエリは max(a[x], b[y]) のみを与えるため、いずれかの値が十分に大きいことがすでにわかっている場合を除き、どちらの値も直接明らかになりません。 すべての値を回復しようとすると、O(n²) 個の推論と潜在的に多くのクエリが必要となり、2n の制限を大幅に超えます。 

重要な観察は、完全な順列は必要ないということです。 制御された方法で両方の構造に存在する単一のアンカー要素を識別するだけで済みます。 最大値 n は番兵のように動作するため、理想的です。 クエリが n を返す場合、a[x] = n または b[y] = n のいずれかがわかります。 n は各順列で 1 回だけ出現するため、O(n) クエリのみを使用して両方の配列内の n の位置を特定できます。 

n が a に現れるインデックスと n が b に現れるインデックスを特定すると、回転はこれらの位置間の直接的な算術差になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再構築 | O(n²) クエリ | O(n) | 遅すぎる |
 | 最大値のローカリゼーション | O(n) クエリ | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

1. 0 から n − 1 までのすべてのインデックス i について、ペア (i, i) をクエリし、結果を保存します。 目的は、2 つの配列の少なくとも 1 つが値 n を持つ位置を検出することです。 n は最大の結果として現れることができる唯一の値であるため、n を返すクエリは、a または b のいずれかの n の位置に触れている必要があります。 
2. query(i, i) が n を返すように、すべてのインデックス i を収集します。 このセットには 1 つまたは 2 つのインデックスが含まれます。 インデックスが 1 つだけ含まれている場合、両方の順列の同じ位置に n があり、これは回転が 0 であることを意味し、すぐに k = 0 を出力できます。 
3. 2 つのインデックス i と j がある場合、そのうちの 1 つは a の n の位置であり、もう 1 つは b の n の位置であることがわかりますが、どちらがどちらであるかはまだわかりません。 
4. 方向を解決するには、1 つのクロスクエリ query(i, j) を実行します。 結果が n の場合、a[i] は n でなければなりません。そうしないと、a[i] も b[j] も n を生成できないからです。 これは、i が a 内の n の位置であり、j が b 内の n の位置であることを意味します。 それ以外の場合、結果が n より小さい場合は、役割が逆になります。つまり、i は b 内の n の位置、j は a 内の n の位置になります。 
5. posA と posB がわかったら、シフトを k = (posB − posA) mod n として計算します。 

### なぜ効果があるのか

 正確さは、n が両方の置換において一意であり、max クエリ内の他のすべての値を支配するという事実に左右されます。 n を返すクエリは、クエリされたインデックスに直接の論理制約を与えます。 対角クエリは、どちらかの構造内で n が存在する場所を正確に分離します。 クロス クエリでは、n が最大値で表示されるのは正しい位置合わせのみであるため、あいまいさが解決されます。 巡回シフトの定義により、単一の値の位置が揃うと、回転オフセット全体が固定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x, y):
    print(f"? {x} {y}")
    sys.stdout.flush()
    return int(input())

def main():
    n = int(input())

    candidates = []

    for i in range(n):
        res = ask(i, i)
        if res == n:
            candidates.append(i)

    if len(candidates) == 1:
        print(f"! 0")
        sys.stdout.flush()
        return

    i, j = candidates[0], candidates[1]
    res = ask(i, j)

    if res == n:
        posA = i
        posB = j
    else:
        posA = j
        posB = i

    k = (posB - posA) % n
    print(f"! {k}")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```この実装は、インタラクティブなクエリを実行し、出力を即座にフラッシュする単一のヘルパー関数を中心に展開します。これは、フラッシュを忘れるとジャッジとの同期が壊れてしまうためです。 

すべてのインデックスのループではちょうど n 個のクエリが使用され、それぞれのクエリで対角位置が最大値を隠しているかどうかがチェックされます。 その後、方向を明確にするために最大 1 つの追加クエリが必要になります。 モジュロ計算により、回転が [0, n − 1] の範囲に正しく正規化されることが保証されます。 

よくある落とし穴は、検出された 2 つのインデックスが常に異なる役割に対応していると想定していることです。 k = 0 の場合を早期に処理することで、不必要なクエリが防止され、同一位置の誤解が回避されます。 

## 実用的な例

 n = 4、隠し配列が a = [2, 3, 1, 4] および b = [4, 2, 3, 1] である小さな概念的な例を考えてみましょう。 正しいシフトは k = 1 です。 

対角クエリをシミュレートします。 

| 私 | クエリ(i, i) | 解釈 |
 | --- | --- | --- |
 | 0 | 最大(2, 4) = 4 | 候補者 |
 | 1 | 最大(3, 2) = 3 | いいえ |
 | 2 | 最大(1, 3) = 3 | いいえ |
 | 3 | 最大(4, 1) = 4 | 候補者 |

 候補 {0, 3} を取得します。 次に、(0, 3) をクエリします。 結果は max(a[0], b[3]) = max(2, 1) = 2 で、4 ではないため、役割が逆になります。インデックス 3 は a の n の位置、インデックス 0 は b の n の位置です。 

したがって、posA = 3、posB = 0、k = (0 − 3) mod 4 = 1 となります。 

このトレースは、いずれの置換も再構築せずに、巡回シフトを完全に決定するには単一の値 (最大値) で十分であることを示しています。 

## 複雑さの分析

 ## 特殊なケース

 k = 0 の場合、両方の配列は同一であるため、すべての対角クエリは同じ値を返します。 この状況では、インデックスが 1 つだけ候補として収集され、アルゴリズムは追加のクエリを実行せずにすぐに 0 を出力します。 

n の 2 つの位置がインデックス空間で一致する場合、候補リストのサイズは 1 になります。これは、最大値が両方の配列の同じ位置に現れることを正しく反映しています。 この場合、アルゴリズムはあいまいさを回避するため、クロスクエリを試行しません。 

n が異なる位置に出現する場合、ロールの 1 つの割り当てだけでクエリ対象のペアに最大値を出現させることができるため、クロス クエリでは方向が明確に区別されます。 これにより、誤ったシフト方向の反転を防止することができる。
