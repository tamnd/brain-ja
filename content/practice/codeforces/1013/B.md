 ## 解決策
 ## 問題の理解

 整数のリストと特殊な整数が与えられます。`x`。 許可される唯一の変換は、インデックスを選択し、その要素をそのビット単位の AND で置き換えることです。`x`。 AND は 1 ビットを 0 に変えることしかできないため、この演算ではビットを減らすことしかできません。`x`。 

目標は、配列をグローバルな意味でソートまたは最適化することではありません。 唯一の要件ははるかに単純です。操作を何度でも適用した後、少なくとも 1 つの値が少なくとも 2 つの異なる位置に表示されるようにする必要があります。 このような複製を強制するか、複製が不可能であると判断するために必要な操作の数は最小限に抑えたいと考えています。 

制約`n ≤ 100000`あらゆる解を線形に近づけるように強制します。 すべての値と中間状態に対する二次ペアリング戦略は遅すぎます。 値の範囲は最大です`100000`これは、状態空間が正確な値を追跡できるほど十分に小さいため、周波数配列またはハッシュ マップを安全に使用できることを意味します。 

単純な間違いは、インデックスのすべてのサブセットに対する操作をシミュレートする必要があると考えることから生じます。 たとえば、すべてのペアを試してみると、`(i, j)`また、一連の AND 演算によってそれらを等しくできるかどうかを確認すると、各要素は多くても 1 つの有用な方法で個別に変換できるため、すぐに爆発的に処理されます。 

2 番目の微妙な問題は、繰り返しの操作が要素ごとに 1 つのアプリケーションを超えて役立つ可能性があると想定していることです。 これは真実ではありません: 適用する`a & x`2 回適用することは 1 回適用することと同じであるため、各要素には元の状態と変換された状態の 2 つのみの状態しかありません。 

最後のエッジケースは、値を変更できない場合に発生します。 たとえば、次の場合`a[i] & x == a[i]`みんなのために`i`の場合、どの操作を行っても何も変わりません。 最初に配列に重複がない場合、答えはすぐに返されます。`-1`。 

## アプローチ

 ブルート フォースの観点では、インデックスのすべてのサブセットを考慮して演算を適用し、値が 2 回出現するかどうかを確認します。 サブセットごとに、配列を再計算して頻度をカウントします。 これは指数関数的です`n`、あるので`2^n`操作ごとにグローバルな衝突構造が変化するため、枝刈りさえもあまり役に立ちません。 失敗する理由は、操作が要素ごとに独立しているため、グローバル検索が不要であるためです。 

重要な観察は、各要素には正確に 2 つの意味のある状態があるということです。元の値です。`a[i]`、およびその変換された値`a[i] & x`。 必要なのは重複する値だけであるため、要素ごとに最大 1 つの変換を使用して、ある値を少なくとも 2 回出現させることができるかどうかだけを考慮します。 

これにより、問題は 3 つの状況を確認することになります。 まず、値がすでに少なくとも 2 回出現している場合、操作は必要ありません。 次に、変換された値が既存の元の値と一致する場合、1 つの操作を使用して複製を作成できます。 3 番目に、2 つの異なる要素を両方とも同じ値に変換できる場合、2 つの操作が必要になります。 

すべての元の値とすべての変換された値を評価し、周波数を追跡します。 答えは、組み合わせたシステムで周波数 ≥ 2 を達成するために必要な最小操作数になりますが、すでに等しい要素を二重にカウントしないように注意してください。

 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^n · n) | O(n) | 遅すぎる |
 | 周波数+変換チェック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ハッシュ マップまたは配列内のすべての元の値の頻度をカウントします。 いずれかの値がすでに頻度が少なくとも 2 である場合、答えは 0 です。これは、操作を実行せずに直接目標を満たします。 
2. 変換された値の 2 番目の頻度マップを構築します。`b[i] = a[i] & x`。 配列は変更しません。 これらの仮定の結果を計算するだけです。 
3. 各インデックスについて、変換によって元の周波数マップにすでに存在する値が作成されるかどうかを検討します。 「はい」の場合、この 1 回の操作ですぐに重複が作成されるため、回答候補 1 を記録できます。 
4. 次に、すべてのインデックスにわたる変換された値の頻度を数えます。 変換された値が少なくとも 2 回出現する場合、それらのインデックスのうち 2 つに対して操作を実行すると重複した値が作成されるため、2 回の操作で目標を達成できます。 
5. 答えは、達成可能な場合は 0、1、または 2 のうちの最小値です。そうでない場合は、0、1、または 2 のうちの最小値になります。`-1`。 

### なぜ効果があるのか

 各要素は最大 2 つの可能な値を提供し、各操作は 1 つの要素のみを元の値から変換された値に移動します。 したがって、どのソリューションも、インデックスのサブセットを選択して変換を「アクティブ化」することと同じです。 重複を作成する唯一の方法は、2 つの要素をこれら 2 つの状態間で同じ値に揃えることです。 これ以上の遷移はないため、問題全体はこれら 2 つの値セット間の重複をカウントすることに帰着し、最適な解決策は特定された 3 つのケースのいずれかに該当する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1
    
    # already has duplicate
    for v in freq:
        if freq[v] >= 2:
            print(0)
            return
    
    # try one operation case
    seen_after = {}
    for v in a:
        nv = v & x
        if nv in freq:
            print(1)
            return
        seen_after[nv] = seen_after.get(nv, 0) + 1
    
    # check two operations case
    for v in seen_after:
        if seen_after[v] >= 2:
            print(2)
            return
    
    print(-1)

if __name__ == "__main__":
    solve()
```最初のパスでは、元の値の頻度テーブルを構築します。これにより、配列がすでに条件を満たしているかどうかをすぐに検出できます。 2 番目のパスでは、考えられる変換された値をそれぞれ計算し、それが既存の値と衝突する可能性があるかどうかをチェックします。これは、単一の操作で十分であることに対応します。 

3 番目のチェックでは、変換された周波数を集計して、2 つの異なるインデックスが変換後に同じ値に収束するかどうかを確認します。 これは、元の重複が存在せず、既存の値と一致する単一の変換がない場合に重複を強制する唯一の方法です。 

操作の数を最小限に抑えたいため、順序は重要です。`0`前に`1`、 そして`1`検討する前に`2`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1

    for v in freq:
        if freq[v] >= 2:
            return "0"

    seen_after = {}
    for v in a:
        nv = v & x
        if nv in freq:
            return "1"
        seen_after[nv] = seen_after.get(nv, 0) + 1

    for v in seen_after:
        if seen_after[v] >= 2:
            return "2"

    return "-1"

# provided sample
assert run("4 3\n1 2 3 7\n") == "1"

# all equal
assert run("5 7\n4 4 4 4 4\n") == "0"

# no change possible
assert run("3 0\n1 2 3\n") == "-1"

# two elements converge after AND
assert run("3 1\n5 7 3\n") == "2"

# already duplicate
assert run("4 10\n1 2 2 3\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい配列 | 0 | ゼロオペレーションの場合 |
 | x = 0 変化なし | -1 | 変換が機能しない場合は不可能です。 
| AND | 後の完全な収束 2 | ツーオペレーション衝突事件 |
 | 既存の重複 | 0 | 早期終了の正確性 |

 ## 特殊なケース

 最初に重複が存在せず、すべての変換で同じ値が生成される配列を考えてみましょう。 例えば、`a = [5, 7, 3]`そして`x = 1`。 変換された値はすべて次のようになります。`1`。 アルゴリズムが構築される`seen_after = {1: 3}`、周波数 ≥ 2 を検出し、返します`2`。 同等にするには少なくとも 2 つのインデックスを変換する必要があるため、これは要件に一致します。 

もう 1 つのエッジ ケースは、変換が何も行われない場合です。 もし`x = 0`、 それから`a[i] & x = 0`みんなのために`i`。 元の配列に重複が含まれていない場合、有効な方法で元の値と一致する変換された値は存在しません。`seen_after`既存の価値観との衝突を避けられません。 アルゴリズムは正しく返します`-1`単一操作チェックと 2 操作チェックの両方に失敗した後。
