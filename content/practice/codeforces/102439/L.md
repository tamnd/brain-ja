 ## 解決策
 ## 問題の理解

 私たちは持っています`2n`番号が付けられた個別のカード`1`を通して`2n`。 それらはランダムに分けられます`n`ペアで、各ペアに 1 人のゲストが参加します。 ゲストのスコアは、ペアの 2 枚のカードの合計です。 ちょうど 1 人のゲストが最大スコアを持つ確率が必要です。 

入力はゲストの数です。`n`。 あるので`2n`カードの場合、すべてのランダムな結果はカードのペアとして完全に一致します。 出力は、モジュロで表された一意の最大スコアを持つ確率です。`10^9 + 7`。 

制約`n <= 10^5`ペアリングを列挙したり、可能なペアリングの数に比例する作業を実行したりすることさえ除外されます。 完全一致の数`2n`カードは`(2n-1)!!`、非常に早く成長します。 ランダムなマッチングを一定サイズのイベントに縮小して、`O(1)`読んだ後の解決策`n`。 

一番小さいケースは、`n = 1`。 ゲストは 1 人だけなので、そのゲストが自動的に勝者となりますが、複数の勝者が存在する可能性はありません。 正しい確率は`1`、 ない`0`。 「固有の最大値」を 2 つの異なるゲストの比較が必要であると解釈する不注意な解決策は、このケースを誤って拒否することになります。 

のために`n = 2`、カードの組み合わせは 3 つあります。`1,2,3,4`。 彼らです`{1,2},{3,4}`、`{1,3},{2,4}`、 そして`{1,4},{2,3}`。 最初の 2 つは一意の最大値を持ち、最後の 2 つは合計を持ちます。`5`そして`5`したがって、正しい確率は次のようになります。`2/3`。 カードがあるかどうかだけをチェックするソリューション`3`そして`4`異なるゲストに属している場合は、これを誤解します。最初のペアリングでもゲストが分離されますが、決定的な比較はパートナー間であるためです。 

## アプローチ

 直接的なアプローチでは、考えられるすべての組み合わせが生成されます。`2n`カード、すべてを計算します`n`ペアの合計を計算し、最大値が 1 回だけ発生するペアを数えます。 これは、考えられるすべてのランダムな結果を検査し、定義を直接適用するため、正しいです。 ただしペアリング数は`(2n-1)!!`。 たとえ`n = 10`、これはもう`19!! = 654729075`したがって、網羅的な列挙は不可能です。 で`n = 10^5`、検索空間は天文学的に大きくなります。 

有益な観察は、2 つの最大のカードを見ることで得られます。`2n`そして`2n-1`。 カードをペアリングさせます`2n`なれ`x`、とペアになっているカード`2n-1`なれ`y`。 最初のペアのスコアは`2n + x`、2番目のペアにはスコアがあります`2n-1 + y`。 

他のペアは最大でもカードのみで構成されます`2n-2`、したがって、その合計は最大でも`4n-5`。 より直接的には、以下を含まないすべてのペアの間で、`2n`、出現できる最大のカードは`2n-1`。 したがって、以下を含むペアは`2n-1`を含まないすべてのペアの中で最大のスコアを持ちます。`2n`。 

したがって、以下を含むペアは、`2n`ユニークな勝者はまさにそのときです`2n + x > 2n - 1 + y`、

 これは以下と同等です`x > y`。 

これにより、問題全体が 2 つの最大のカードのパートナーを比較することに帰着します。 

特殊なケースが 1 つあります。 もし`2n`そして`2n-1`ペアになっている場合、それらは明らかに同じゲストを形成しており、そのパートナーは 2 枚の別個のカードではありません。 あのゲストはお金を持っています`4n-1`これは、他のすべての可能なペアの合計よりも厳密に大きいため、この結果は実際には一意の勝者を与えます。 したがって、2 つの最大のカードの組み合わせは有利です。 

それらがペアになっていない場合、対称性は、次のパートナーであることを示します。`2n`のパートナーよりも大きいか小さい可能性が同等です。`2n-1`。 2 人のパートナーは異なるため、3 番目の可能性はありません。 したがって、一意の勝者の条件付き確率は次のようになります。`1/2`最大のカードが分離されたとき。 

特定の 2 枚のカードが一様にランダムに完全に一致してペアになる確率は次のとおりです。`1/(2n-1)`のパートナーを修正した後だからです。`2n`、他のすべて`2n-1`カードの可能性も同様です。 

したがって`P = 1/(2n-1) + (1 - 1/(2n-1)) * 1/2`これを単純化すると`P = n/(2n-1)`。 

この式はまた、`1`のために`n = 1`、必要に応じて正確に。

 ## アルゴリズムのチュートリアル

 1.読む`n`。 がある`2n`カードなので、最大の 2 枚のカードは`2n`そして`2n-1`。 
2. これら 2 枚のカードがペアになった場合を考えてみましょう。 その確率は`1/(2n-1)`、カードなので`2n`まさに`2n-1`可能性のあるパートナーはすべて同じ可能性があります。 
3. 最大のカード 2 枚がペアになっている場合、ゲストは合計を獲得します。`4n-1`、可能な絶対最大のペアの合計。 そのゲストは自動的にユニークな勝者となります。 
4. それ以外の場合は、`x`～のパートナーになる`2n`そして`y`のパートナー`2n-1`。 を含むペア`2n`を含むペアに勝つ`2n-1`まさにいつ`x > y`。 
5. 最大のカードが分離されていることを条件として、2 つのパートナーは対称になります。 のアイデンティティを交換する`2n`そして`2n-1`イベントを交換します`x > y`そして`x < y`なので、それぞれに確率があります`1/2`。 
6. 2 つのケースを結合します。 確率は`1/(2n-1) + (2n-2)/(2n-1) * 1/2 = n/(2n-1)`。 
7. この分数モジュロを計算します`10^9 + 7`乗算して`n`モジュラー逆関数により`2n-1`。 

これが機能する理由: 考えられるすべての一致は、2 つのケースのうちの 1 つに正確に当てはまります。2 つの最大のカードがペアになっているか、分離されているかのいずれかです。 最初のケースでは、すぐに唯一の勝者が存在します。 2 番目のケースでは、次のペアが含まれます。`2n-1`を含むペアに対する最強の競合相手です`2n`したがって、勝者は、パートナーが次の場合にのみユニークになります。`2n`～のパートナーより大きい`2n-1`。 対称性により、2 つの可能な順序が同等の可能性を持ち、確率が得られます。`1/2`。 これらのケースはすべての一致をカバーするため、結果として得られる確率は正確です。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())

    numerator = n
    denominator = 2 * n - 1

    answer = numerator * pow(denominator, MOD - 2, MOD) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```コードは導出に直接続きます。`numerator`は`n`、 そして`denominator`は`2n-1`、したがって、望ましい確率は次のように表されます。`n / (2n-1)`。 

パイソンの`pow(a, MOD - 2, MOD)`の逆モジュールを計算します`a`高速累乗を使用します。 これが機能する理由は、`MOD = 10^9 + 7`プライムであり、`2n-1`よりも小さいです`MOD`与えられた制約に対するものであるため、係数では割り切れません。 

乗算は、最後の剰余を求める前に実行されます。 Python の整数はオーバーフローしませんが、モジュラー リダクションによって値が小さく保たれ、意図したモジュラー演算に従います。 

特別な支店はありません`n = 1`。 この式は自然に与えます`1 / 1 = 1`したがって、境界ケースは別個のロジックなしで処理されます。 

## 実用的な例

 提供されたステートメントには目に見えるサンプル入力または出力が含まれていないため、2 つの小さな有効な入力をトレースできます。 

### 例 1

 のために`n = 1`、カードがあります`1`そして`2`、そしてそれらは唯一のペアを形成する必要があります。 

| n | 2n | 2n-1 | 確率 |
 | --- | --- | --- | --- |
 | 1 | 2 | 1 |`1 / 1`|

 2 つの最大のカードは必ずペアになります。 唯一のゲストが最大スコアを持っているため、一意の勝者の確率は次のようになります。`1`。 アルゴリズムの出力`1`。 

### 例 2

 のために`n = 2`、カードは`1,2,3,4`。 式は次のようになります`2/3`。 

| n | 2n | 2n-1 | ペアになる確率が最大のカード | 分離された確率 | 最終確率 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 4 | 3 |`1/3`|`2/3`|`1/3 + (2/3)(1/2) = 2/3`|

 可能な3つの組み合わせのうち、`{3,4}`一緒にユニークな勝者をもたらします。`{1,2},{3,4}`ユニークな勝者もいますが、`{1,4},{2,3}`実は3番目の組み合わせで、これまたユニークな勝者がいる。 待ってください。この直接列挙は、3 つの組み合わせすべてに一意の勝者がいることを示しているため、正しい確率は次のようになります。`1`、 ない`2/3`。 

これは、前の対称性の計算を慎重に処理する必要がある理由を明らかにします。 いつ`2n`そして`2n-1`が分離されており、次のペアが含まれます。`2n`スコアがある`2n+x`、を含むペア`2n-1`スコアがある`2n-1+y`。 不平等は確かにある`x > y`、しかし、`n=2`、別居後、残ったパートナーは`1`そして`2`、各マッチングで 1 つの順序付けが発生します。 で`{1,4},{2,3}`、 我々は持っています`x=1,y=2`、つまり、以下を含むペア`4`合計があります`5`、を含むペア`3`合計があります`5`。 これはネクタイです。 もう一方の分離されたマッチング`{2,4},{1,3}`もっている`x=2,y=1`、合計を生成します`6`そして`4`。 

したがって、3 つのマッチングのうち 2 つだけが固有の勝者を持ち、正しい確率は次のようになります。`2/3`。 トレースは、パートナーの比較が決定的なイベントであることを確認します。

import io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

# Small boundary case.

 ## 特殊なケース

 のために`n = 1`、入力は`1`。 カードはちょうど2枚ありますが、`1`そして`2`、そしてそれらは必然的に同じゲストに行きます。 確率は`1`。 式は次のようになります`1/(2-1) = 1`したがって、特別なケースは必要ありません。 

のために`n = 2`、入力は`2`。 最大の2枚のカードは、`4`そして`3`。 ペアになっている場合、スコアは次のようになります。`7`、これは一意に最大です。 分離した場合、残ったカードは`1`そして`2`。 ペアリング`4`と`2`スコアを与える`6`そして`4`、つまり、ペアリング中に勝者は一意になります。`4`と`1`の 2 つのスコアを与える`5`、ネクタイを生成します。 3 つのマッチングのうちちょうど 2 つが成功するため、確率が得られます。`2/3`。 

分母`2n-1`誤って置き換えてはなりません`2n`。 カード`2n`まさに`2n-1`可能性のあるパートナーではなく、`2n`、それ自体とペアリングできないためです。 のために`n = 2`を使用して`2n`最大の 2 枚のカードが確率でペアになっていると誤って主張します。`1/4`、一方、正しい確率は`1/3`。 

最大の 2 枚のカードが一緒になった場合も成功としてカウントされます。 彼らの合計スコアは`4n-1`、これは他のすべてのペアの合計よりも大きくなります。 このケースを省略すると、イベントが誤って引き分けまたは無関係として扱われ、イベント全体が失われます。`1/(2n-1)`答えへの貢献。 

最後に、モジュラー出力を通常の分数と混同しないでください。 のために`n = 2`、数学的な答えは次のとおりです。`2/3`ですが、必要な出力は次のとおりです。`2 * 3^{-1} mod (10^9+7) = 666666672`。 このコードは、浮動小数点除算を試行するのではなく、このモジュラー表現を正確に計算します。
