 ## 解決策
 ## 問題の理解

 電球は (n) 個あるため、クラブの構成は長さ (n) のバイナリ ベクトルになります。 スイッチも別のバイナリ ベクトルです。 スイッチを押すということは、対応するビットが 1 であるすべての電球が切り替わるため、そのベクトルと現在の設定の XOR を計算することを意味します。 

各スイッチは、連続した日間隔でのみ使用できます。 Dima は毎日、空のサブセットを含む、その日に利用可能なスイッチのサブセットを使用できます。 毎日の問題は、いくつの異なる電球構成を作成できるかです。 

代数上の重要な観察は、スイッチを押す順序は重要ではないということです。 特定の日に使用可能なスイッチがベクトル (v_1,v_2,\ldots,v_k) の場合、到達可能なすべての構成は次の形式になります。 

[
 c_1v_1\oplus c_2v_2\oplus\cdots\oplus c_kv_k,
 ]

 ここで、すべての (c_i) は 0 または 1 です。 したがって、到達可能な構成は、フィールド GF(2) 上の利用可能なベクトルの線形スパンと正確に一致します。 

ベクトルのランクが (r) である場合、そのスパンには正確に (2^r) 個の異なるベクトルが含まれます。 したがって、元の問題は、毎日のアクティブなスイッチ ベクトルのセットのランクを計算することに相当します。 

境界により、私たちはガウス基底を毎日独立して再構築することから遠ざけられます。 (d=q=500,000) になる可能性があり、毎日すべてのスイッチを 1 回通過するだけでも、すでに (2.5\cdot10^{11}) 回のスイッチ検査が必要になります。 二次関数または (O(nq d)) アプローチは完全に不可能です。 

入力形式には便利な制約も隠されています。 すべてのスイッチの説明には正確に (n) ビットが含まれており、そのようなすべての文字列の合計長は最大でも (500,000) です。 したがって、

 [
 nq\le500,000。 
]

 これがガウスベースのソリューションを実用的なものにします。 (n) 自体は (500,000) であっても、その場合はスイッチは 1 つしかありません。 逆に、(500,000) 個のスイッチがある場合は、(n=1) になります。 

単純な実装では誤って処理される可能性のあるエッジケースがいくつかあります。 

ゼロスイッチを考えてみましょう。```
1 1 1
1 1 0
```スイッチだけでは何も変わりません。 したがって、スパンのランクは 0 なので、答えは次のようになります。`1`、 ない`2`。 独立したベクトルの代わりにスイッチをカウントする不注意な実装では、誤った結果が得られます。 

重複したスイッチは別の罠です。```
2 2 1
1 1 10
1 1 10
```どちらのスイッチも使用できますが、同じベクトルを表します。 ランクは1なので、答えは`2`。 利用可能なすべてのスイッチを独立したバイナリの選択肢として扱うと、誤って生成されます。`4`。 

間隔エンドポイントも包括的である必要があります。 例えば：```
2 2 2
1 2 10
2 2 01
```初日には最初のベクトルのみが利用可能となり、`2`構成。 2 日目には、両方の独立したベクトルが利用可能になり、次のようになります。`4`。 正しい出力は次のとおりです`2 4`。 適切なエンドポイントを排他的であると解釈する実装では、2 日目に 2 番目のスイッチが失われます。 

## アプローチ

 直接的なアプローチは、毎日を独立して処理することです。 固定日の場合、間隔にその日が含まれるすべてのスイッチを収集し、そのベクトルを GF(2) のガウス基底に挿入します。 結果の基底がランク (r) を持つ場合、(2^r) を出力します。 

ガウス消去法により、利用可能なスイッチが提供する独立した方向の数が正確にわかるため、これは正しいです。 ただし、最悪の場合、(500,00) 日、(500,00) 回の切り替えが発生する可能性があります。 毎日すべてのスイッチを処理するには、削除のコストを考慮する前に、(250,000,000,000) 回のスイッチ チェックが必要になる可能性があります。 

私たちを救ってくれる構造は、すべてのスイッチが 1 つの間隔でアクティブになることです。 毎日どのスイッチがアクティブであるかを尋ねる代わりに、そのスイッチがアクティブである日を正確にカバーするセグメント ツリーにスイッチを保存できます。 

間隔は (O(\log d)) 個のセグメント ツリー ノードで表すことができます。 ツリーの深さ優先トラバーサル中、ノードに格納されているすべてのスイッチが、そのノードの下のすべてのリーフに対してアクティブになります。 このようなベクトルをすべて 1 つの線形基底に挿入し、子を再帰的にアクセスし、ノードから戻るときに挿入を元に戻すことができます。 

通常の消去では情報が破壊されるため、ガウス消去を元に戻すのは難しそうに思えます。 解決策は、挿入が成功するたびに新しいピボットが 1 つだけ作成されるという基準を使用することです。 どのピボットが作成されたかを記憶しており、ロールバック時にそのピボットを単純にクリアします。 再帰処理は逆の​​挿入順序でロールバックされるため、後のベクトルはすでに削除された基底エントリに依存できません。 

バイナリ ベクトルを 1 つの Python 整数として表すと、実装が特に便利になります。 ビットごとの XOR は GF(2) に対してベクトル加算を実行し、`bit_length()`は、基底で使用されるピボットである最高の設定ビットを与えます。 

セグメント ツリーは時間間隔を処理し、ロールバック ベースはスイッチ間の線形依存関係を処理します。 すべての再帰ノードは、そのノードに格納されているすべてのベクトルが同時に利用できる日の範囲を表すため、これら 2 つの部分は適合します。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(ndq)) 単純な実装 | (O(nq)) | 遅すぎる |
 | 最適 | (O(nq\log d)) 最悪の場合 | (O(q\log d+n)) | 承認済み |

 限界 (nq\le500,000) により最適な時間はおよそ (O(500,000\log 500,000)) になりますが、実際の定数は必要なガウスベースの削減の数によって異なります。 

## アルゴリズムのチュートリアル

 1. すべてのスイッチを読み取り、そのバイナリ文字列を整数に変換します。 ビット (i) は、電球 (i) がトグルされているかどうかを表します。 整数表現を使用すると、通常の XOR を使用してベクトル加算を実行できます。 
2. (1) から (d) までの日数にわたって暗黙的なセグメント ツリーを構築します。 ([l,r]) で使用可能なスイッチの場合、その間隔を、範囲が正確に ([l,r]) に等しい正規のセグメント ツリー ノードに分解します。 このようなすべてのノードにスイッチ ベクトルを格納します。 
3. 各基底ベクトルの最上位の設定ビットによってインデックス付けされた線形基底を維持します。 ベクトル (x) を挿入するには、その最上位の設定ビットを繰り返し調べます。 対応するピボットがすでに存在する場合は、(x) から既存の基底ベクトルを XOR します。 ピボットが空の場合は、そこに (x) を入力し、ランクを 1 つ増やします。 
4. 挿入によって新しいピボットが作成されるたびに、そのピボットをロールバック スタックに記録します。 ベクトルがゼロに減少した場合、それは現在の基底に線形に依存しているため、何も記録する必要はありません。 
5. セグメント ツリーを再帰的に走査します。 ノードで、現在のロールバック スタック サイズを記憶し、そのノードに格納されているすべてのベクトルを挿入します。 これらのベクトルはすべて、ノード範囲全体にわたってアクティブであるため、すべての子孫日のベースに属します。 
6. ノードが日 (i) を表すリーフである場合、現在のベースには、その日に利用可能な独立したスイッチが正確に含まれます。 ランクが (r) の場合、(2^r\bmod(10^9+7)) を (i) 日の答えとして記述します。 
7. 内部ノードの場合、両方の子を再帰的に処理します。 基礎は 2 つの子の間で共有されますが、各子はその範囲全体でアクティブなベクトルとその祖先から継承したベクトルを正確に受け取ります。 
8. ノードの処理後、保存されたチェックポイントに到達するまでロールバック スタックを繰り返しポップします。 削除されたピボットごとに、その基準エントリをクリアし、ランクを下げます。 これにより、基底はノードに入ったときの状態に正確に復元されます。 

### なぜ効果があるのか

 すべてのセグメント ツリー ノードにおいて、不変条件は、線形基底にスイッチが正確に含まれており、その間隔はルートからそのノードまでのパスを完全にカバーします。 リーフに到達すると、そのパスは 1 日に対応するため、ベースにはその日にアクティブなすべてのスイッチが正確に含まれます。 ガウス消去では、依存ベクトルを削除しながらスパンを保持します。これは、そのランクが到達可能な構成空間の次元と正確に一致することを意味します。 GF(2) 上の次元 (r) のベクトル空間には、正確に (2^r) 個のベクトルが含まれるため、各リーフで生成される値は、到達可能なライト構成の数と正確に一致します。 

挿入は逆の順序で元に戻されるため、ロールバックは正しいです。 挿入が成功すると、以前は空だったピボットが占有され、その後に行われた挿入はすべて、後で最初に削除されます。 したがって、記録されたピボットをクリアすると、古い基底ベクトルに影響を与えることなく、以前の基底が復元されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, q, d = map(int, input().split())

    # Use a power-of-two segment tree.
    size = 1
    while size < d:
        size <<= 1

    # events[v] contains vector integers assigned to segment-tree node v.
    # None avoids creating millions of empty Python lists.
    events = [None] * (2 * size)

    for _ in range(q):
        l, r, s = input().split()
        l = int(l) - 1
        r = int(r)

        # One object is shared by all segment-tree copies of this switch.
        vec = int(s, 2)

        l += size
        r += size

        while l < r:
            if l & 1:
                if events[l] is None:
                    events[l] = [vec]
                else:
                    events[l].append(vec)
                l += 1

            if r & 1:
                r -= 1
                if events[r] is None:
                    events[r] = [vec]
                else:
                    events[r].append(vec)

            l >>= 1
            r >>= 1

    # basis[p] is the vector whose highest set bit is p.
    basis = [0] * n
    changes = []
    rank = 0

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    ans = [0] * d

    def add_vector(x):
        nonlocal rank

        while x:
            p = x.bit_length() - 1
            b = basis[p]

            if b:
                x ^= b
            else:
                basis[p] = x
                changes.append(p)
                rank += 1
                return

    def rollback(checkpoint):
        nonlocal rank

        while len(changes) > checkpoint:
            p = changes.pop()
            basis[p] = 0
            rank -= 1

    sys.setrecursionlimit(1_000_000)

    def dfs(v, left, right):
        checkpoint = len(changes)

        ev = events[v]
        if ev is not None:
            for x in ev:
                add_vector(x)

        if right - left == 1:
            if left < d:
                ans[left] = pow2[rank]
        else:
            mid = (left + right) >> 1
            dfs(v << 1, left, mid)
            dfs(v << 1 | 1, mid, right)

        rollback(checkpoint)

    dfs(1, 0, size)

    sys.stdout.write(" ".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```入力変換`int(s, 2)`中心的な表現トリックです。 左端の文字が上位ビットになりますが、XOR と線形依存性は一貫して座標の名前を変更することによって影響を受けないため、正確な方向は問題になりません。 

インターバル変換は半開レンジを使用します。`[l, r)`。 入力間隔`[l,r]`まず、から 1 を減算して、ゼロベースの座標に変更されます。`l`、一方、右端点は変化しません。 したがって、スイッチは入力日にアクティブになります`1..3`半開範囲になります`[0,3)`。 これは、反復的なセグメント ツリー分解におけるエンドポイントの間違いを回避する便利な方法です。 

の`events`配列にはサイズがあります`2 * size`、 どこ`size`少なくとも 2 の最小の累乗です`d`。 空のノードは次のように表されます。`None`。 Python では、数百万の空のリストを作成すると、必要以上に多くのメモリが消費されるため、これは重要です。 

基底には、考えられるピボット ビットごとに 1 つのベクトルが格納されます。 ベクトルが最上位ビットを持つ場合`p`、既存の`basis[p]`そのビットを取り除くことができます。 最終的には、ベクトルがゼロになって依存関係が証明されるか、未使用のピボットに到達して新しい独立した基底ベクトルになります。 

ロールバック スタックには、基底全体のコピーではなく、ピボット インデックスのみが含まれます。 挿入によりピボットが作成されると仮定します。`p`。 その瞬間`basis[p]`ゼロだった。 それ以降の挿入はすべて、この挿入の前に元に戻されるため、クリア`basis[p]`正確に以前の状態を復元します。 

答えは次のように事前計算されます。`pow2[r]`。 ランクが超えることはありません`n`、だからそれだけ`n+1`力が必要です。 Python の整数はオーバーフローしませんが、累乗剰余 (10^9+7) を減らすと、格納される答えが小さく保たれます。 

トラバースでは、次の場合でも完全な 2 のべき乗ツリーが使用されます。`d`自体は 2 の累乗ではありません。 少なくともインデックスのある葉`d`無視されます。 間隔分解では実際の日数のみが挿入されるため、これらの人工的な葉は有効な答えに影響を与えることはありません。 

## 実用的な例

 ### サンプル 1

 入力は次のとおりです。```
3 3 3
1 3 011
3 3 101
3 3 001
```ベクトルは次のとおりです。`011`、`101`、 そして`001`。 

| 日 | アクティブなベクトル | 独立したピボット | ランク | 答え |
 | --- | --- | --- | --- | --- |
 | 1 |`011`|`011`| 1 | 2 |
 | 2 |`011`|`011`| 1 | 2 |
 | 3 |`011`、`101`、`001`| 3 つの独立したベクトル | 3 | 8 |

 1 日目と 2 日目には、ゼロ以外の方向が 1 つだけ使用できるため、到達可能な構成は 2 つあります。スイッチを使用するか使用しません。 

3 日目には、3 つのベクトルは独立しています。 特に、それらのいずれも他の 2 つの XOR として生成できないため、スパンは次元 3 を持ち、すべての (2^3=8) 個の可能なバルブ構成が含まれます。 

### サンプル 2

 入力は次のとおりです。```
4 3 4
2 4 1010
2 4 0101
3 4 1101
```最初の 2 つのスイッチは 2 日目に使用可能になり、3 番目のスイッチは 3 日目に開始されます。 

| 日 | アクティブなベクトル | ランク | 答え |
 | --- | --- | --- | --- |
 | 1 | なし | 0 | 1 |
 | 2 |`1010`、`0101`| 2 | 4 |
 | 3 |`1010`、`0101`、`1101`| 3 | 8 |
 | 4 |`1010`、`0101`、`1101`| 3 | 8 |

 初日にはスイッチはありませんが、Dima は空のサブセットを使用する可能性があるため、オールオフ構成に到達できます。 つまり (2^0=1) になります。 

2 日目には、2 つのベクトルは独立しています。 3 日目、3 番目のベクトルにより別の独立した方向が追加され、ランクが 2 から 3 に増加します。 4 日目も同じ 3 つのスイッチが利用できるため、答えは 8 のままです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(nq\log d)) 最悪の場合 | 各スイッチは (O(\log d)) 個のセグメント ツリー ノードに格納され、各基底挿入では最大で (O(n)) 個のピボット除去が実行されます。 
| スペース | (O(q\log d+n+d)) | セグメント ツリー間隔のコピー、ベース、ロールバック スタック、回答、およびツリー メタデータ |

 すべてのスイッチ文字列の合計の長さが最大 ​​(500,000) であるという特別な制約により、(nq\le500,000) が与えられます。 したがって、最悪の場合の除去作業は、(nq d) ではなく、おおよそ (500,000\log 500,000) によって制限されます。 ロールバック基底には常に最大 (n) 個のベクトルが含まれ、再帰の深さは (O(\log d)) のみです。 

元のコンテスト ソリューションは、(2) 秒、(256) MB の制限に合わせて設計されており、受け入れられた C++ 実装では、間隔分解と線形基底維持の同じ基本的な組み合わせが使用されています。

 ## 特殊なケース

 ゼロベクトルは基底によって自然に処理されます。 のために```
1 1 1
1 1 0
```整数表現はゼロなので、`add_vector(0)`ピボットを作成せずにすぐに戻ります。 ランクはゼロのままで、リーフは`2^0 = 1`。 スイッチは存在しますが、それを押してもライトの構成を変更することはできません。 

重複ベクトルも、カウント スイッチではなくガウス消去法によって処理されます。 のために```
2 2 1
1 1 10
1 1 10
```最初`10`1 つのピボットを作成します。 2番目`10`は既存の基底ベクトルと XOR 演算され、ゼロになります。 ピボットは 1 つだけ残っているので、答えは次のようになります。`2`。 

包括的な右エンドポイントは、次の変換によって処理されます。`[l,r]`ゼロベースのハーフオープンレンジに`[l-1,r)`。 のために```
2 2 2
1 2 10
2 2 01
```最初のスイッチは両方のリーフを占有しますが、2 番目のスイッチは 2 番目のリーフのみを占有します。 したがって、最初の葉はランク 1 を持ち、`2`、一方、2 番目の葉には 2 つの独立したベクトルがあり、`4`。 

空きスイッチがない日も有効です。 スイッチの空のサブセットは常に存在するため、アクティブ セットが空の場合でもオールオフ構成に到達できます。 この場合、基底のランクは 0 になり、答えは正確に 1 になります。 

最後に、ベクトルは機械語よりもはるかに長くなる可能性があります。 (500,000) ビットのベクトルが直接表現され、内部ですべてのマシンワードに対して XOR が演算されるため、Python の任意精度の整数がここで役に立ちます。 入力保証により、(nq\le500,000) 以降、この大きなベクトルのケースが多数のスイッチと一致することが防止されます。
