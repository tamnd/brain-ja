 ## 問題の理解

 文字列で表される数字ブロックのバッグがあります。`s`。 2 つの 10 進整数を構築するには、すべてのブロックを 1 回だけ使用する必要があります。 2 つの整数は等しい場合があり、ゼロも許可されますが、どちらの数値も先頭にゼロを含めることはできません。 どちらの数値も最大 (10^{18}) でなければなりません。 

必要なペアは、小さい値から順に並べられます。 すべての有効な構造のうち、まず小さい数を最小化します。 その数値が固定されたら、他の数値を最小化します。 すべての数字ブロックの有効なパーティションが存在しない場合は、次のように出力します。`-1 -1`。 

50 という長さの限界は、桁ごとに一定量の作業を実行するアルゴリズムには十分小さいですが、サブセットの列挙には大きすぎます。 最初の数字に属するブロックを選択する方法は、最大 (2^{50})、おおよそ (1.13 \times 10^{15}) 通りあります。 わずか数十回の操作ですべてのパーティションをチェックできたとしても、これは 1 秒の制限をはるかに超えています。 (10^{18}) の上限は重要な構造上の制限です。すべての有効な数値は最大 19 桁であり、(10^{18}) を超えない 19 桁の数値は正確に一致する必要があります。`1000000000000000000`。 

いくつかのエッジケースでは、直接的な貪欲な実装を欺くことができます。 

のために`0`、ブロックが 1 つしかないため、空でない 2 つの数値を構成することはできません。 答えは、`-1 -1`。 不用意に実装すると、欠落している 2 番目の数値がゼロとして扱われる可能性があります。 

のために`00`、正解は`0 0`。 数値の最初の桁にゼロを含めることはできないというルールは、このケースを誤って拒否することになります。 単一のゼロはゼロの有効な表現ですが、`00`は無効になります。 

のために`000`、答えは`-1 -1`。 分割すると`0`そして`00`機能しないので`00`先頭にゼロが付きます。 これは、ブロック数だけをチェックするだけでは不十分な理由を示しています。 

のために`1000000000000000000`19 桁の場合、答えは次のとおりです。`0 100000000000000000`。 最小の数値には 1 つのゼロを使用でき、2 番目の数値には 18 ブロックが残ります。 この数字パターンを見たときに常に (10^{18}) を作成しようとする不用意な実装は、最初の数値を最小化することが優先されるという事実を見落とすことになります。 

のみを含む 20 桁の文字列の場合`2`、 のような`22222222222222222222`の場合、有効な 19 桁の数値 (10^{18}) を作成する方法はありません。そのような数値はすべて正確に (10^{18}) でなければならないからです。 それでも、インスタンスはまだ次のように解決できます`22 222222222222222222`。 これが、入力が 19 桁を超える場合に単純に (10^{18}) ブロックを要求できない決定的な理由です。 小さい数に対して可能な限りの長さを試さなければなりません。 

## アプローチ

 ブルート フォース ソリューションでは、最初の数字の数字ブロックの任意のサブセットを選択し、2 番目の数字の補数を使用し、選択した数字を関連するすべての順序で配置し、最適な有効なペアを保持できます。 考えられるすべてのパーティションがサブセット内に表示されるため、これは正しいです。 問題はパーティションの数です。 50 桁の場合、(2^{50})、約 (1.13 \times 10^{15}) 個のサブセットの選択肢があります。 各選択肢を (O(50)) 時間で処理する場合でも、最悪の場合、約 (5.6 \times 10^{16}) 回の初等数字演算が必要になりますが、これは到底実現可能ではありません。 

有益な観察は、値が (10^{18}) によって制限されているため、各数値には最大 19 桁が含まれるということです。 まず、小さい方の数の長さ (k) を決定します。 もう一方の数値の長さが (n-k) である場合、両方の長さは最大 19 である必要があります。(k<n-k) 常に小さい数値の桁数が少ないため、すべての有効な (k) 桁の正の数はすべての有効な ((n-k)) 桁の数値よりも自動的に小さくなります。 したがって、小さい方の数の実現可能な最小の長さが、常に検討に値する最初の長さになります。 

可能な長さは最大 19 です。 固定長 (k) の場合、使用可能な桁から最小の (k) 桁の数値を構築します。 これを左から右に実行します。 すべての位置で、昇順に数字を試し、一時的に 1 つのコピーを取得します。 唯一の問題は、残りの桁が必要な長さの他の数値を形成できるかどうかです。 

実現可能性のチェックは非常に簡単です。 他の数値が最大 18 桁の場合、その長さが 1 であるか、より長い表現の場合は少なくとも 1 つの非ゼロ桁が含まれていれば有効です。 19 桁の場合、正確に (10^{18}) でなければならないため、残りのマルチセットには 1 つが含まれている必要があります。`1`そして18`0`数字。 

小さい方の数値が決定されると、残りの桁を昇順に並べることによって 2 番目の数値が最小化されます。ただし、複数桁の数値は、使用可能な最小のゼロ以外の桁で開始する必要があります。 これは、複数の桁セットからの標準的な最小数の構成です。 

すべてのパーティションが明示的に考慮されるため、ブルート フォースは機能しますが、パーティションが指数関数的に多いため失敗します。 各数値が最大 19 桁であるという観察により、検索は最大 19 個の候補長に減り、各候補は一定サイズの桁空間で貪欲に解決できます。

 ## アルゴリズムのチュートリアル

 1. すべての数字の出現を数えて、`n = len(s)`。 有効なペアには両方の数値が空でない必要があります。`n < 2`私たちはすぐに戻ります`-1 -1`。 また、もし`n > 38`, それぞれ最大 19 桁なので、2 つの数字は収まりません。 
2. 可能な長さを検討する`k`より小さい数のうちの`max(1, n - 19)`を通して`floor(n / 2)`。 下限は、他の数値には 19 桁を超える数字を含めることができないという事実に基づいています。 これらの長さは昇順で処理されます。これは、有効な小さい数値が長い正の数値よりも常に優れているためです。 
3.固定の場合`k`、 セット`L = n - k`、他の数値の必要な長さ。 完全な桁数の配列から始めて、左から右に最初の数値を構築します。 
4. 各位置で、以下のすべての数字を試します。`0`を通して`9`昇順で。 最初の位置では、次の場合にのみゼロが許可されます。`k == 1`、単一の文字なので、`0`はゼロの有効な表現です。 複数桁の数値の場合、最初の桁はゼロ以外でなければなりません。 
5. 候補の数字を一時的に削除し、残りの数字が有効な数字を正確に形成できるかどうかを尋ねます。`L`数字。 できない場合は、桁を復元し、次の候補を試してください。 可能であれば、その候補者を永久に保持し、次のポジションで続行します。 
6. 実現可能性テストは、次の場合に残りのすべてのマルチセットを受け入れます。`L == 1`、任意の 1 桁が有効な数値であるためです。 のために`2 <= L <= 18`、残りの少なくとも 1 つの桁はゼロ以外でなければなりません。 のために`L == 19`、受け入れられる唯一のマルチセットは 1 つだけです`1`そして18`0`数字なので、`1000000000000000000`(10^{18}) を超えない唯一の 19 桁の整数です。 
7. 結局のところ`k`数字が選択されている場合は、残りの数字を可能な限り小さい 2 番目の数字に配置します。 1 桁のみの場合は、直接返します。 それ以外の場合は、ゼロ以外の最小の数字が最初に配置され、その後にすべてのゼロが続き、その後に残りの数字がソート順に配置されます。 
8. 最初に見つかった実行可能なペアを返します。 もし`k < L`、最初の数値は桁数が少なく、必然的に小さい値になります。 もし`k == L`、貪欲な構造では、すべての実行可能なパーティションの中で可能な限り小さい最初の数値が得られるため、結果として得られる 2 つの数値を順序付けした後でも、そのペアは依然として最適です。 

機能する理由: すべての候補の長さに対して、この構築では、これまでに選択されたプレフィックスが有効なペアに完成できる辞書編集上の最小のプレフィックスであるという不変条件が維持されます。 各位置で、小さい数字がすべて最初にテストされ、残りのブロックが必要な 2 番目の数字を形成できない場合にのみ、数字が拒否されます。 したがって、最初に受け入れられる数字は常にその位置に最適です。 位置を左から右に処理すると、その長さの実現可能な最小数が得られます。 長さは最小値から最大値の順に処理されるため、最初の実行可能な長さは、グローバルに可能な最小の小さい数値を与えます。 最後に、未使用の数字を最小の有効な表現にソートすると、その固定された最初の数値に対して可能な最小の 2 番目の数値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def can_make_other(cnt, length):
    if sum(cnt) != length:
        return False

    if length == 1:
        return True

    if length == 19:
        return cnt[0] == 18 and cnt[1] == 1 and sum(cnt[2:]) == 0

    return any(cnt[d] > 0 for d in range(1, 10))

def build_smallest(cnt):
    length = sum(cnt)

    if length == 1:
        for d in range(10):
            if cnt[d]:
                return str(d)

    first = -1
    for d in range(1, 10):
        if cnt[d]:
            first = d
            break

    if first == -1:
        return None

    cnt[first] -= 1
    result = [str(first)]

    result.extend("0" for _ in range(cnt[0]))

    for d in range(1, 10):
        result.extend(str(d) for _ in range(cnt[d]))

    return "".join(result)

def solve(s):
    n = len(s)

    if n < 2 or n > 38:
        return "-1 -1"

    original = [0] * 10
    for ch in s:
        original[ord(ch) - ord('0')] += 1

    min_k = max(1, n - 19)
    max_k = n // 2

    for k in range(min_k, max_k + 1):
        other_len = n - k
        cnt = original[:]
        first_digits = []

        possible = True

        for pos in range(k):
            chosen = -1

            for d in range(10):
                if cnt[d] == 0:
                    continue

                if pos == 0 and k > 1 and d == 0:
                    continue

                cnt[d] -= 1

                if can_make_other(cnt, other_len):
                    chosen = d
                    break

                cnt[d] += 1

            if chosen == -1:
                possible = False
                break

            first_digits.append(str(chosen))

        if not possible:
            continue

        first = "".join(first_digits)
        second = build_smallest(cnt)

        if second is None:
            continue

        if len(second) > 19:
            continue

        if len(second) == 19 and second != "1000000000000000000":
            continue

        if k == other_len and first > second:
            first, second = second, first

        return first + " " + second

    return "-1 -1"

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()

構築ループは貪欲な部分です。 各位置で、昇順に数字が試行されます。 電話をかける前に数字が一時的に削除されます`can_make_other`なぜなら、その関数は候補にコミットした後に残るブロックを正確に検査する必要があるからです。 

最初の位置の特別な処理により、次のような表現が防止されます。`04`。 条件により許可されます`0`いつ`k == 1`、1 文字の表現であるため、`0`有効です。`can_make_other`Python の任意精度の整数変換に依存せずに上限を処理します。 19 桁の有効な数値は正確に (10^{18}) である必要があるため、その桁数をチェックする方が、無効な可能性のある文字列を作成して変換するよりも簡単かつ安全です。`build_smallest`二次最小化を実行します。 複数桁の数値の場合、ゼロ以外の最小の桁が最初に選択されます。これは、そこにゼロを置くと先行ゼロが作成されるためです。 すべてのゼロをその直後に配置し、その後に残りの数字を昇順に配置できます。 

最終的な長さ 19 のチェックは、2 番目の数値にのみ必要です。 貪欲な実現可能性テストによってこの条件はすでに保証されていますが、明示的な検証を維持することで境界条件が明確になり、将来の偶発的な変更が (10^{18}) 制限に違反するのを防ぎます。 

Python の整数はオーバーフローしませんが、ソリューションでは構築された文字列を整数に変換する必要はありません。 すべての比較は長さによって処理され、唯一関連する 19 桁の場合については、(10^{18}) の正確な文字列表現との直接比較によって処理されます。

 ## 特殊なケース

 ワンブロック入力の場合`7`、長さループは 2 つの空でない数値を生成できません。`n < 2`すぐに拒否されます。 出力は`-1 -1`。 これにより、実装で 1 つの数値が誤って空として扱われることが防止されます。 

のために`00`の場合、最初の候補の長さは 1 です。 貪欲な構築の試み`0`、それを削除し、もう 1 つの数値には 0 を残します。 他の長さも1本なので、`can_make_other`それを受け入れます。 結果は`0 0`。 特別な 1 桁のルールにより、この有効な表現と、次のような無効な複数桁の文字列が区別されます。`00`。 

のために`000`、同じ最初の試行で選択します`0`ただし、2 番目の数値には 2 つのゼロが残ります。 必要な長さは 2 であり、`can_make_other`1 より大きいすべての長さに対してすべてゼロのマルチセットを拒否します。 ゼロ以外の候補がないため、アルゴリズムは次のように報告します。`-1 -1`。 

のために`1000000000000000000`、アルゴリズムは次から始まります`k = 1`。 それは試みます`0`前に`1`、ゼロを 1 つ削除すると 18 桁が残り、有効な数値が形成されます。`100000000000000000`。 したがって、小さい方の数はすぐにゼロになります。 結果は`0 100000000000000000`を使用するよりも優れています。`1`小さい方の数字として。 

のために`22222222222222222222`、最初の候補の長さは 1 で、もう 1 つの数値には 19 桁が残ります。 19 桁の有効な数値は正確に (10^{18}) でなければならないため、実現可能性テストではこれら 19 個の 2 が拒否されます。 次にアルゴリズムは次のことを試みます`k = 2`。 もう一方の数値は 18 桁で、2 で構成される 18 桁の数値は (10^{18}) より下になります。`22`は最小の 2 桁の数値として受け入れられます。 結果は`22 222222222222222222`。 

実現可能な最大長の場合、入力は 2 つの要素で構成されます。`1`ブロックと 36 個のゼロブロック。 有効な 19 桁の数値は (10^{18}) のみであり、2 つのコピーを作成するのにちょうど十分なブロックがあります。 アルゴリズムが到達する`k = 19`、2 番目の数値の正確な桁マルチセットを検証し、両側に同じ値を構築します。 

長さ 50 の入力の場合、アルゴリズムは構築を試行する前に拒否します。 各数値には最大 19 桁を含めることができるため、2 つの数値で最大 38 ブロックを消費できます。 数値制限を遵守しながら 50 ブロックすべてを使用できるパーティションはありません。`-1 -1`避けられない。
