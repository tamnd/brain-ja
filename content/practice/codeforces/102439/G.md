 ## 問題の理解

 文字列から始めます`1`。 次の各項は、前の項を左から右に読み、等しい連続する数字をグループ化し、すべてのグループを 2 つの数字 (その長さの後に数字自体が続く) で置き換えることによって取得されます。 例えば、`13112221`グループで構成されています`1`、`3`、`11`、`222`、`1`、になる`11`、`13`、`21`、`32`、`11`。 

入力には以下が含まれます`n`、必要な用語のインデックス、および`m`、右端から保持する必要がある桁数。 用語が次の数より少ない場合は、完全な用語を出力する必要があります。`m`数字、それ以外の場合は最後の数字のみ`m`数字。 公式の制約により、`n`到達する`10^18`その間`m`せいぜい`1000`。 

の莫大な価値`n`用語を 1 つずつ構築することを排除します。 配列の長ささえも指数関数的に増加し、通常のルックアンドセイ成長係数はコンウェイ定数に近づきます。`1.303577`。 直接シミュレーションはずっと前に天文学的な文字列に到達するでしょう`n`遠くから近くなった`10^18`。 

サフィックスベースのソリューションでは慎重に処理する必要がある境界ケースがいくつかあります。 入力あり`1 2`、最初の項には 1 桁しか含まれていないため、答えは次のようになります。`1`、 ない`01`。 入力あり`4 2`、第4期は`1211`、最後の 2 桁は`11`、したがって、答えは次のとおりです`11`。 常に正確にフォーマットする不用意な実装`m`数字が生成します`01`最初のケースでは、文字列の間違った側を取得する実装は 2 番目のケースで失敗します。 

要求されたサフィックスに現在の用語全体が含まれている場合、別の微妙なケースが発生します。 たとえば、入力`3 10`3番目の項を求めます。`21`、したがって、答えは次のとおりです`21`。 ゼロを埋め込んだり、存在しない数字をでっち上げたりしてはなりません。 

シーケンスには、サフィックスを管理しやすくする追加の構造があります。 から始まる`1`、数字のみ`1`、`2`、 そして`3`発生すると、すべての用語が元の数字で終わります`1`、連続した等しい数字が長さ 4 以上のランを形成することはありません。 最後のプロパティは、すべての実行を 1 つの 10 進数で表すことができることを意味します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 現在の文字列全体を保存し、左から右にスキャンしてランを形成し、次の文字列を構築します。 後`n-1`繰り返し、最後のものを取得します`m`文字。 これはシーケンスの定義に正確に従っているため、正しいです。 

問題は中間文字列のサイズです。 現在の長さが次の場合`L`、1 回の移行にはすでに費用がかかります`O(L)`時間を計算して、およその長さの文字列を作成します。`1.3L`。 したがって、最初の数十の用語を構築するだけでも、数千または数百万の文字を処理する必要があります。`n`多分`10^18`。 ブルート フォース シミュレーションは、すべての項の長さの合計程度で実行されます。これは指数関数的です。`n`, したがって、それは完全に不可能です。 

重要な点は、用語全体が必要ないということです。 必要なのはサフィックスのみであり、変換は実行に関してローカルです。 

用語を個々の数字ではなくラン単位で表します。 実行は次のように保存されます`(digit, count)`。 1 回の入力実行でちょうど 2 つの出力文字が生成されます。`count`そして`digit`。 最後について考えてみましょう`K`学期の終わり。 これらのランが変換されるとき、それらのエンコードされたペアには常に少なくとも次のものが含まれます。`K`出力が実行されます。 The reason is simple: the last digit of each encoded pair is the digit of the corresponding input run, and consecutive input runs have different digits. Thus every input run contributes at least one distinct output run.

 その結果、最後は`K`次の学期の実行は最後の学期のみに依存します`K`今期の運用状況。 破棄された実行との相互作用は、変換されたサフィックスの先頭でのみ発生しますが、最後の場合は、`K`出力実行は、保持されているものによってすでに決定されています`K`入力が実行されます。 

私たちは今、選択できるようになりました`K = m`。 最後`m`10 進数には最大でも次の値が含まれます`m`実行されるので、最後に`m`run は、要求されたサフィックスを再構築するのに十分です。 さらに重要なことは、これにより決定論的な有限状態が得られるということです。つまり、状態は単に最後の状態です。`m`走る。 

ある状態が繰り返されると、後続のすべての状態が同じ周期で繰り返されます。 から始まるルックアンドセイシーケンスについては、`1`、これらの接尾辞の状態は、右端の見慣れた周期的な動作にすぐに落ち着きます。 安定化は右から左に伝播するため、次のようなサフィックスの場合、`m`実行のみ`O(m)`状態がサイクルに入る前に遷移が必要です。 実際には、サイクルは非常に短いですが、その期間をハードコーディングする必要はありません。 辞書を使用してサイクルを直接検出できます。 

結果として得られるアプローチはプロセスのみを処理します`O(m)`生成された状態ごとに実行され、`O(m)`サフィックスサイクルに達する前の状態。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`、設定します`K = m`。 run を使用するのは、すべての run が少なくとも 1 桁を占めるためです。`m`数字にはそれ以上を含めることはできません`m`走る。 
2. 最初の学期から始めます。`1`、単一の実行として表されます`(1, 1)`。 また、最初は今期インデックスも保持します。`1`。 
3. 現在の期間が次の期間より少ない場合`K`実行すると、完全な実行リストが通常どおり変換されます。 この段階では用語全体が表現されているため、切り捨ての問題はありません。 
4. 用語が少なくとも`K`実行され、最後のものだけが保持されます`K`走る。 置き換えることでそれらの実行を変換します`(digit, count)`二人のキャラクターと一緒に`count`そして`digit`、結果の文字シーケンスをランレングス エンコードします。 保持された各入力実行は少なくとも 1 つの出力実行に寄与するため、最後の`K`元の用語の接頭辞が破棄されていても、出力実行は正確です。 
5. 移行するたびに、結果の実行リストを最後まで切り詰めます。`K`走る。 状態は現在、最大で以下を含むタプルになっています。`K` `(digit, count)`ペア。 
6. 最初の状態から開始`K`実行すると、各状態が最初に出現した用語インデックスとともに保存されます。 状態が再び現れる場合、2 つの指標の差がサイクル長になります。 
7. しましょう`remaining`任期に達するまでにまだ必要な移行の回数`n`。 もし`remaining`がサイクル長より大きい場合は、サイクル長を法として減少させます。 これは潜在的に置き換えられます`10^18`最大 1 サイクル分の遷移で遷移します。 
8. 最後のものを再構築する`m`ランを右から左に読んで、最終ランリストの桁を取得します。 ランニング`(digit, count)`貢献する`count`のコピー`digit`; 少なくともすぐにやめてください`m`数字が集まりました。 用語全体に含まれる内容が以下の場合`m`数字の場合は、代わりに完全な用語を返します。 

### なぜ効果があるのか

 不変条件は、保存された状態に次のものが含まれる場合は常に、`K`走ります、まさに最後です`K`実数列項の実行。 これが今期にも当てはまると仮定します。 保存された各入力ランは、最後の桁がその入力ランの桁と等しいペアにエンコードされます。 連続する入力実行の桁が異なるため、各入力実行は少なくとも 1 つの出力実行に寄与するため、最後の入力実行は`K`出力実行は、保持されたサフィックスより前の入力実行に依存することはできません。 したがって、変換により正確に最後のものが生成されます。`K`次の実質期の実行。 不変式はすべての遷移後に保持されます。 

同じ状態が 2 回発生すると、決定論により、両方の発生から同じ後続状態が得られます。 したがって、未来全体は周期的になります。 完全な期間をスキップすると状態は変更されないため、期間に到達した状態になります。`n`正確に保存されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize(runs, k):
    """
    Apply one look-and-say operation to the supplied suffix of runs.

    When k runs are supplied from the end of a real term, the last k
    output runs are determined completely by these runs.
    """
    chars = []

    for digit, count in runs:
        chars.append(str(count))
        chars.append(digit)

    out = []

    for ch in chars:
        if out and out[-1][0] == ch:
            out[-1] = (ch, out[-1][1] + 1)
        else:
            out.append((ch, 1))

    if len(out) > k:
        out = out[-k:]

    return tuple(out)

def suffix_from_runs(runs, m):
    parts = []
    need = m

    for digit, count in reversed(runs):
        take = min(count, need)
        parts.append(digit * take)
        need -= take
        if need == 0:
            break

    return ''.join(reversed(parts))

def solve():
    n, m = map(int, input().split())

    if n == 1:
        print("1")
        return

    k = m

    # The complete first term.
    state = (("1", 1),)
    index = 1

    # States are only needed once the suffix contains k runs.
    seen = {}
    history = []

    while index < n:
        if len(state) < k:
            new_state = normalize(state, k)
        else:
            if state not in seen:
                seen[state] = index
                history.append(state)

            new_state = normalize(state, k)

        index += 1
        state = new_state

        if index >= n:
            break

        if len(state) == k:
            if state in seen:
                cycle_start = seen[state]
                cycle_len = index - cycle_start

                remaining = n - index
                if remaining >= cycle_len:
                    skip = remaining // cycle_len
                    index += skip * cycle_len

                if index >= n:
                    break

            else:
                seen[state] = index
                history.append(state)

    print(suffix_from_runs(state, m))

if __name__ == "__main__":
    solve()
```状態は次のように保存されます`(digit, count)`文字列としてではなくペアとして。 から生成されたシーケンスなので、`1`3 桁を超えるランが含まれることはありません。すべてのカウントは 1 桁の 10 進数であり、変換ルールと正確に一致します。`normalize`まず、保持されたランからエンコードされた文字ストリームを作成します。 次に、その短いストリームに対して通常のランレングス エンコーディングを実行します。 最後だけ`k`以前の実行は要求されたサフィックスに影響を与えることができないため、結果の実行は保持されます。 

サイクル辞書は、最後の数桁だけではなく、完全な実行状態によってキー設定されます。 これは、2 つの文字列が異なる実行境界を持ちながらも同じテキスト接尾辞を持つ可能性があり、それらの境界が次の変換に影響するため重要です。 

ソリューションのどこにも整数変換はありません。 答えには以下が含まれる場合があります`1000`数字であるため、これを Python 整数として扱う必要はなく、問題の別のバージョンで要求されたサフィックスがゼロで始まる場合、主要な情報が失われる可能性もあります。 ここで、最も安全な表現は常に文字列です。 

遷移カウントは、ゼロベースのオフセットではなく、用語インデックスに基づいています。 学期`1`状態です`1`、そして 1 つの変換が項に移動します`2`。 この規則を一貫して維持することで、サイクル スキップで最も一般的なオフバイ 1 エラーを回避できます。

import sys
import io

def solve_string(inp: str) -> str:
    data = inp.strip().split()
    n = int(data[0])
    m = int(data[1])

    if n == 1:
        return "1"

    def normalize(runs, k):
        chars = []
        for digit, count in runs:
            chars.append(str(count))
            chars.append(digit)

        out = []
        for ch in chars:
            if out and out[-1][0] == ch:
                out[-1] = (ch, out[-1][1] + 1)
            else:
                out.append((ch, 1))

        return tuple(out[-k:])

    def get_suffix(runs, k):
        parts = []
        need = k

        for digit, count in reversed(runs):
            take = min(count, need)
            parts.append(digit * take)
            need -= take
            if need == 0:
                break

        return ''.join(reversed(parts))

    state = (("1", 1),)
    index = 1
    seen = {}

    while index < n:
        state = normalize(state, m)
        index += 1

        if len(state) == m:
            if state in seen:
                cycle_start = seen[state]
                cycle_len = index - cycle_start

                remaining = n - index
                if remaining >= cycle_len:
                    index += (remaining // cycle_len) * cycle_len

                if index >= n:
                    break
            else:
                seen[state] = index

    return get_suffix(state, m)

 ## 特殊なケース

 入力用`1 2`、アルゴリズムはすぐに戻ります`1`。 現在の実行リストには、`(1,1)`、全長は以下より小さい`m`。 ゼロ埋め込みは導入されません。これは、要求された接尾辞より短い場合に用語自体を出力するという要件に一致します。 

入力用`4 2`、生成された用語は次のとおりです。`1`、`11`、`21`、 そして`1211`。 4期も走り終わりました`(1,1)`、`(2,1)`、`(1,2)`。 右から読むと最終滑走が貢献`11`、したがって、要求されたサフィックスは正確に`11`。 アルゴリズムにより実行カウントが混乱することはありません`2`実行は構造的に次のように表現されるため、2 つの別々の出力桁が使用されます。`(digit='1', count=2)`。 

入力用`3 100`、要求されたサフィックスは用語全体よりも長いです。 3期目は`21`で表される`(2,1), (1,1)`。 サフィックスの再構築は両方の実行を消費し、完全な用語が回復されたため停止します。 出力は残ります`21`人為的なゼロ埋め込みはありません。 

入力用`1000000000000000000 1`、アルゴリズムは実行を試みません`10^18`変化。 と`m = 1`、保存された状態には右端の実行のみが含まれます。 短い過渡状態の後、その状態は周期的となり、サイクル計算では必要な用語インデックスの圧倒的大部分がスキップされます。 最後の桁は常に`1`したがって、出力は次のようになります`1`。 

実装上の主な危険は、実行単位ではなく数字単位で切り捨てられることです。 実行の途中でサフィックスがカットされた場合、その完全なカウントが失われ、次の用語が変更される可能性があります。 完全な実行を保存すると、その問題が完全に回避されます。 もう 1 つの危険は、テキストの接尾辞のみからサイクルを検出することです。 次の変換では個々の文字ではなくグループを読み取るため、実行境界は状態の一部です。 最後に保存することで、`m`実行が完了すると、アルゴリズムは将来のサフィックス遷移に必要な情報を正確に保存します。
