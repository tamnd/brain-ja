 ## 解決策
 ## 問題の理解

 連続したセグメントごとに`[L, R]`、評価方法は2つあります。 から開始`L`、次の配列要素によって剰余を繰り返し取得します。`a[L] % a[L+1] % ... % a[R]`。 

から開始`R`、同じことを逆方向に実行します。`a[R] % a[R-1] % ... % a[L]`。 

両方向で同じ最終値を生成するセグメントがいくつあるかをカウントする必要があります。 両方の式には同じ要素のみが含まれるため、長さ 1 のセグメントが常に適格となります。 

配列には最大で次のものが含まれます`10^5`要素、すべての値は最大でも`3 * 10^5`。 二次アルゴリズムはすでに`10^10`したがって、セグメントごとの定数処理であっても遅すぎます。 より現実的には、モジュロチェーン自体を評価すると、セグメント長の線形時間がかかるため、直接的な解決策は 3 次時間になります。 この有用な構造は、モジュロ演算がその引数をすぐに減少させるという事実から来ているに違いありません。 

誤って対処しやすい特殊なケースがいくつかあります。 のために`n = 1`、唯一のセグメントをカウントする必要があるため、入力```
1
7
```答えがあります`1`。 少なくとも 2 つ以上の長さのセグメントのみを考慮するソリューションでは、この問題を見逃してしまいます。 

値が等しいと、モジュロ演算でゼロが生成されることがあります。 のために```
2
5 5
```2 つのシングルトンが適格であり、`[1,2]`両方の方向が次のように評価されるため、これも適格です`5 % 5 = 0`、したがって、答えは次のとおりです`3`。 現在の値が変更されていないかのように等しい値を扱うと、誤って返されます。`2`。 これは公式の最初のサンプルでもあります。 

セグメントが適格であるためにエンドポイントが等しい必要はなく、エンドポイントが等しいこと自体は何も保証しません。 のために```
2
6 3
```2 つのシングルトンは適格ですが、`[1,2]`そうでない: 左から右の結果は次のようになります。`6 % 3 = 0`一方、右から左への結果は次のようになります。`3 % 6 = 3`。 正しい答えは、`2`。 

最後に、答えは 32 ビットの符号付き整数を超える可能性があります。 もしすべてなら`100000`要素はすべて等しい、`n(n+1)/2 = 5000050000`セグメントが対象となります。 Python の整数はこれを自然に処理しますが、C++ 実装では次のことが必要になります。`long long`。 

## アプローチ

 直接的なアプローチは簡単です。 すべてのペアについて`(L,R)`、モジュロチェーンを左から評価し、再度右から評価します。 2 つの結果が一致する場合は、答えをインクリメントします。 

これは、有効なセグメントの定義を正確にテストするため、正しいです。 問題は仕事量です。 がある`n(n+1)/2`すべてのセグメントの合計の長さは、`n(n+1)(n+2)/6`。 

のために`n = 100000`、それは約です`1.67 * 10^14`一方向および約の要素の訪問`3.33 * 10^14`両方向用。 このアプローチは制限の 1.5 秒には遠く及ばない。 

重要な観察は、モジュロチェーンは実際にはすべての位置で変化しないということです。 現在の値が`x`そして次の配列値は`y`。 もし`y > x`、 それから`x % y = x`, したがって、結果はまったく変わりません。 したがって、結果を変更できる最初の位置は、値が最大でも次の位置になります。`x`。 

そのような位置が見つかると、新しい値は次のようになります。`x % y`。 もし`y <= x`、この新しい値は厳密に次の値より小さいです。`x/2`。 これを見るには、`y <= x/2`、余りは以下より小さい`y`、したがって、より小さい`x/2`。 もし`y > x/2`の場合、商はちょうど 1 となり、剰余は次のようになります。`x-y`、これもまたより小さいです`x/2`。 

したがって、実際に変更を加えると、現在の値が少なくとも半分になります。 すべての配列値は最大でも`3 * 10^5`、固定開始位置には次のものしか含めることができません。`O(log a[L])`したがって、最大でも約 20 の異なる州が存在します。 

固定左端点の場合`L`、結果として、左から右への結果のシーケンス全体を少数の間隔として表すことができます。 各間隔は、結果が何らかの固定値であることを示します`v`すべての適切なエンドポイントに対して`[p,q]`。 同じ構造を右側から適用すると、固定された右側の端点ごとに少数の間隔が得られます。 

これが中心的な削​​減です。 あらゆることを考慮するのではなく、`(L,R)`別途、取得のみ`O(n log A)`水平方向と垂直方向の間隔、ここで`A = max(a_i)`。 有効なセグメントは、まさに同じ値を持つ左状態の間隔と右状態の間隔の交差点です。 

残りのタスクは幾何学的カウントです。 1 つの値について`v`、左状態区間は次の形式になります。`L = fixed, R in [p,q]`、

 一方、正しい状態の区間は次の形式になります。`R = fixed, L in [p,q]`。 

それらの交差は 1 つの有効なペアです`(L,R)`まさに、固定座標が対応する間隔内にあるときです。 

掃引線を使用して、一度に 1 つの値を処理します。`R`。 すべての左状態の間隔が座標のアクティブなポイントになります`L`右端の範囲がアクティブである間。 正しい状態の間隔ごとに、アクティブなポイントがいくつあるかを尋ねます。`L`その間隔の中で。 フェンウィック ツリーは、これらのポイントの更新と範囲のクエリを処理します。 

同じ考え方が、問題の意図したスキャンライン定式化にも現れています。モジュロ状態は形式のみを表します。`O(n log A)`その後、それらの交差は 2 次元のオフライン クエリ問題としてカウントされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントの最小配列値を格納するセグメント ツリーを構築します。 開始位置が与えられた場合、1 つの操作を繰り返して行う必要があります。`p`そして現在値`x`、以降の最初の位置を検索します。`p`その配列値は最大でも`x`。 最小セグメント ツリーはこれに直接答えることができます。`O(log n)`最小値が次より大きいノードをスキップすることによって`x`。 
2. 左側のエンドポイントを修正します`L`そしてから始めます`x = a[L]`。 現在の右のエンドポイントは`L`。 最初の位置を見つける`p > L`と`a[p] <= x`。 現在の右エンドポイントから`p-1`値を次の値のままにします`x`、それらのすべての値がより大きいため、`x`。 これらの右端点を表す 1 つの水平間隔を保存します。 
3. このような立場の場合`p`存在する、置き換える`x`と`x % a[p]`そして続きから`p`。 そのような位置が存在しない場合、現在の値は配列の終わりまで変更されないため、この左の端点の状態は終了します。 
4. 左側のエンドポイントごとにこれを繰り返します。 すべての状態は、その値に属するバケットに保存されます。 左側の状態レコードには、右側のエンドポイント間隔が含まれます`[p,q]`とその固定左端点`L`。 
5. 配列を逆にして、まったく同じ手順を実行します。 反転された配列の状態は、元の配列の固定右端点に対応します。 反転した間隔を元の座標に変換し、固定値を含む垂直レコードとして保存します。`R`そして許容範囲は`L`。 
6. 各モジュロ値について`v`、すべてのレコードをスイープ座標で並べ替えます。 水平レコードは、許容される最小値でアクティブになり始めます。`R`。 固定して保管する`L`フェンウィックツリー内とその有効期限位置はミニヒープ内にあります。 
7. 右端固定の垂直レコードの場合`R`に達した場合は、まず、最大許容値に達しているすべてのアクティブな水平レコードを削除します。`R`よりも小さいです`R`。 残りのフェンウィック ツリーには、間隔にこれが含まれる水平状態が正確に含まれています。`R`。 
8. 垂直レコードの許容範囲に対してフェンウィック ツリーをクエリします。`[L1,L2]`。 見つかったすべての点が 1 つのペアを表します`(L,R)`両方向が同じ値を持つもの`v`なので、その数を答えに追加します。 
9. すべての値バケットを処理し、蓄積された回答を出力します。 シングルトン セグメントは両方の状態表現にすでに存在しているため、個別の特殊なケースは必要ありません。 

### なぜ効果があるのか

 固定ごとに`L`、保存された水平間隔は、すべての可能な右端点のパーティションを形成します。 このような 1 つの間隔内では、遭遇する除数が最大でも現在の値ではないため、左から右へのモジュロ値は一定です。 間隔が終了すると、次の除数によって値が変更され、新しい値は古い値の半分より厳密に小さくなります。 したがって、保存された間隔には、考えられるすべての左から右への状態が正確に含まれます。 

逆の構造により、右から左の状態に対して同様の正確な分割が行われます。 あらゆるセグメントを検討してください`[L,R]`。 値を持つ 1 つの水平状態にのみ属します`v`そして、何らかの値を持つ正確に 1 つの垂直状態`w`。 セグメントは正確に次の場合に有効になります。`v = w`。 For a fixed value, the sweep line counts exactly those intersections where the horizontal state's right interval contains`R`そして垂直状態の左側の間隔には次のものが含まれます`L`。 したがって、すべての有効なセグメントは 1 回カウントされ、無効なセグメントはカウントされません。 

半分にするプロパティは、各開始位置から生成される状態の数を制限します。 現在の値が変化するたびに、前の値の半分より小さくなり、すべての配列値が正であるため、一度ゼロに達すると再び変化することはありません。 これにより、`O(log A)`エンドポイントごとの状態。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**9
SHIFT = 17
MASK = (1 << SHIFT) - 1

def build_min_tree(a):
    n = len(a)
    size = 1 << (n - 1).bit_length()
    tree = [INF] * (2 * size)
    tree[size:size + n] = a

    for i in range(size - 1, 0, -1):
        left = tree[i << 1]
        right = tree[i << 1 | 1]
        tree[i] = left if left <= right else right

    return tree, size

def first_leq(tree, size, n, start, x):
    """First index >= start with a[index] <= x, or n if none exists."""
    if start >= n:
        return n

    p = start + size

    while p:
        if p & 1:
            if tree[p] <= x:
                while p < size:
                    left = p << 1
                    if tree[left] <= x:
                        p = left
                    else:
                        p = left | 1
                pos = p - size
                return pos if pos < n else n
            p += 1
        p >>= 1

    return n

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    max_a = max(a)

    # buckets[v] contains packed horizontal and vertical records
    # having modulo-state value v.
    buckets = [[] for _ in range(max_a + 1)]

    # ------------------------------------------------------------
    # Left-to-right states.
    #
    # Record:
    #   type = 0
    #   coord = first R for which the state is active
    #   field1 = last R for which the state is active
    #   field2 = fixed L
    #
    # Packed as:
    #   coord << 35 | field1 << 17 | field2
    # ------------------------------------------------------------
    tree, size = build_min_tree(a)

    for L in range(n):
        now = a[L]
        j = L

        while True:
            p = first_leq(tree, size, n, j + 1, now)

            if p == n:
                end = n - 1
                buckets[now].append((j << 35) | (end << SHIFT) | L)
                break

            end = p - 1
            buckets[now].append((j << 35) | (end << SHIFT) | L)

            now %= a[p]
            j = p

    # ------------------------------------------------------------
    # Right-to-left states.
    #
    # Generate them as left-to-right states on the reversed array.
    #
    # Record:
    #   type = 1
    #   coord = fixed R
    #   field1 = smallest allowed L
    #   field2 = largest allowed L
    #
    # The type bit is bit 34.
    # ------------------------------------------------------------
    rev = a[::-1]
    tree, size = build_min_tree(rev)

    for s in range(n):
        now = rev[s]
        j = s
        original_r = n - 1 - s

        while True:
            p = first_leq(tree, size, n, j + 1, now)

            if p == n:
                end = n - 1
                lo = n - 1 - end
                hi = n - 1 - j

                record = (
                    (original_r << 35)
                    | (1 << 34)
                    | (lo << SHIFT)
                    | hi
                )
                buckets[now].append(record)
                break

            end = p - 1
            lo = n - 1 - end
            hi = n - 1 - j

            record = (
                (original_r << 35)
                | (1 << 34)
                | (lo << SHIFT)
                | hi
            )
            buckets[now].append(record)

            now %= rev[p]
            j = p

    # ------------------------------------------------------------
    # For each value, count intersections between horizontal
    # and vertical state rectangles.
    # ------------------------------------------------------------
    bit = [0] * (n + 1)
    tag = [0] * (n + 1)
    stamp = 0
    answer = 0

    for bucket in buckets:
        if not bucket:
            continue

        bucket.sort()
        stamp += 1

        heap = []

        for rec in bucket:
            typ = (rec >> 34) & 1
            coord = rec >> 35
            x1 = (rec >> SHIFT) & MASK
            x2 = rec & MASK

            if typ == 0:
                # Horizontal state:
                # active for R in [coord, x1],
                # fixed L = x2.
                end = x1
                point = x2

                idx = point + 1
                while idx <= n:
                    if tag[idx] != stamp:
                        tag[idx] = stamp
                        bit[idx] = 1
                    else:
                        bit[idx] += 1
                    idx += idx & -idx

                heapq.heappush(heap, (end << SHIFT) | point)

            else:
                # Vertical state:
                # fixed R = coord,
                # allowed L in [x1, x2].
                while heap and (heap[0] >> SHIFT) < coord:
                    item = heapq.heappop(heap)
                    point = item & MASK

                    idx = point + 1
                    while idx <= n:
                        bit[idx] -= 1
                        idx += idx & -idx

                # Fenwick range sum [x1, x2].
                idx = x2 + 1
                right_sum = 0
                while idx:
                    if tag[idx] == stamp:
                        right_sum += bit[idx]
                    idx -= idx & -idx

                idx = x1
                left_sum = 0
                while idx:
                    if tag[idx] == stamp:
                        left_sum += bit[idx]
                    idx -= idx & -idx

                answer += right_sum - left_sum

        bucket.clear()

    print(answer)

if __name__ == "__main__":
    solve()
```セグメント ツリーには、実際のモジュロ結果ではなく最小値が格納されます。 現在の値を変更できる次の位置なので、これで十分です。`x`は、配列値が最大である最初の位置です。`x`。 の`first_leq`ルーチンはサフィックスを直接検索し、RMQ クエリの前後の個別のバイナリ検索を回避します。 

左から右へのループレコード`[j,end]`その間隔内のすべての右のエンドポイントでまったく同じ累積値が表示されるためです。 状態は次の時点でのみ変化します。`p`、 どこ`a[p] <= now`、モジュロ演算は次の処理を続行する前に実行されます。`p`。 

逆パスは座標に細心の注意を払う必要があります。 逆引きインデックス`q`元のインデックスに対応します`n-1-q`。 したがって、逆の間隔`[j,end]`元の左端点間隔になります`[n-1-end,n-1-j]`、元の右端点は に固定されます。`n-1-s`。 

パックされた整数は、Python タプルの代わりに使用されます。`O(n log A)`記録。 フィールドをパックすると、メモリ消費が大幅に削減され、スイープ座標とレコード タイプによる自然な並べ替え順序がレコードに与えられます。 タイプ`0`水平方向のレコードとタイプに使用されます`1`垂直レコードの場合、同じ座標で始まる水平レコードは、その座標での垂直クエリの前に処理されます。 

フェンウィック ツリーは、アクティブな固定左エンドポイントごとに 1 つのカウントを保存します。 ヒープは、これらの水平間隔がアクティブでなくなる時期を追跡します。 垂直クエリを処理する前に、`R`、すべての水平間隔はその前で終了します`R`が削除されます。 正確に終了する間隔`R`これは必須の包含境界条件です。 

タイムスタンプ配列により、すべての値を処理した後にフェンウィック ツリー全体をクリアすることができなくなります。 現在値バケット中にタッチされた位置のみが初期化されたとみなされます。 これは重要です。`3 * 10^5`可能なモジュロ値が異なります。 

Python の任意精度の整数を使用すると、応答のオーバーフローの問題も解決されます。 考えられる最大の答えは、`5000050000`。

 |`2`|`[1,3]`|

 したがって、答えは次のとおりです`4`。 

トリプル`[1,3]`興味深いケースです。 その値は左から、`8 % 3 % 5 = 2`、一方、右からは`5 % 3 % 8 = 2`。 走査線はそれを水平状態の交点として検出します。`L=1, R in [2,3]`垂直状態で`R=3, L in [1,2]`。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n log A log n)`| 各エンドポイントには、`O(log A)`各州ではセグメント ツリー検索が使用され、すべての州レコードは並べ替えとフェンウィック操作で処理されます。 
| スペース |`O(n log A + A)`| がある`O(n log A)`パックされた状態レコードと`O(A)`値バケット |

 ここ`A = max(a_i) <= 3 * 10^5`したがって、各エンドポイントは少数の状態のみを作成します。 と`n = 10^5`、モジュロ リダクションからの対数係数は約 20 です。 オフライン スイープはセグメントの二次列挙を回避し、意図した条件に適合します。`O(n log n log A)`この問題に対して説明されているアプローチ。 

## テストケース

 次のハーネスは、送信されたソリューションが次のように保存されることを前提としています。`solution.py`そして暴露します`solve()`上記のソリューションの関数。```python
# Test harness for solution.py
import sys
import io

from solution import solve

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

assert run("3\n8 3 5\n") == "4", "sample 2"

# Minimum-size input
assert run("1\n7\n") == "1", "single element"

# All values equal.
# Every segment evaluates to 5 for a singleton and 0 for length >= 2.
# Both directions are identical for every segment.
assert run("3\n5 5 5\n") == "6", "all equal"

# Equal modulo can produce zero, and the boundaries are inclusive.
assert run("4\n4 2 3 2\n") == "6", "zero and boundary handling"

# A length-two segment can fail even when one direction becomes zero.
assert run("2\n6 3\n") == "2", "different two-element results"

# Maximum n and maximum answer.

 ## 特殊なケース

 単一要素の場合`1 / 7`1 つの左の状態と 1 つの右の状態を生成し、どちらも値を持ちます`7`そして両方とも所定の位置に固定されています`1`。 スイープはそれらを 1 回交差し、答えを返します`1`。 

のために`2 / 5 5`、最初の左側の状態は値です`5`でのみ`R=1`。 で`R=2`、除数は現在の値に等しいため、状態はゼロに変化します。 右から左への構造は対称的に動作します。 値`5`両方のシングルトンセグメントに貢献しますが、値は`0`貢献する`[1,2]`、与える`3`。 

のために`2 / 6 3`、左の状態`L=1`からの変更`6`に`0`2番目の要素で。 適切な状態`R=2`残っている`3`考えられる両方の左側の端点にわたって`3 % 6 = 3`。 長さ 2 のセグメントでは状態値が決して一致しないため、2 つのシングルトン交差だけが残り、次のようになります。`2`。 

のために`4 / 4 2 3 2`、セグメント`[2,4]`間隔の境界をテストする場合に特に役立ちます。 その左の結果は`2 % 3 % 2 = 0`、その正しい結果は`2 % 3 % 2 = 0`, したがって、カウントする必要があります。 アルゴリズムは左の結果を表します`0`で終了する間隔として`R=4`そして正しい結果`0`から始まる間隔として`L=2`。 両方の走査線の境界が包括的であるため、それらの交差部分は保持されます。 

完全に構成される最大入力の場合`300000`、すべてのペア`(L,R)`両方向で同等の結果が得られます。 がある`100000 * 100001 / 2 = 5000050000`そんなペアたち。 ここでは、状態圧縮が特に効果的です。最初の等しい値はすぐに累積値を 0 に変更し、その後は 0 のままであるため、各エンドポイントには少数の状態しかありません。
