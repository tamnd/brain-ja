 ## 解決策
 ## 問題の理解

 位置 0 から位置 (x_n) の大学まで直線道路があります。 カメラ (i) は位置 (x_i) にあり、車がその点を通過するときの速度は最大 (v_i) でなければなりません。 車は速度ゼロでスタートします。 最大 (a) の加速度で加速し、最大 (b) の減速度でブレーキをかけ、一定速度を維持します。 

入力により、カメラの位置とその速度制限が 2 つの加速度パラメーターとともに提供されます。 必要な出力は、位置 0 から最後のカメラ (大学でもある) までの可能な最小移動時間です。 

主な問題は、カメラが 1 つの位置でのみ速度を制限することです。 カメラ間では、車は一時的にどちらのエンドポイントの速度よりもはるかに速く進む場合があります。 たとえば、連続する 2 台のカメラの速度が 1 と 1 の場合、最も速い動きは必ずしも速度 1 にとどまるとは限りません。車は 1 を超えて加速し、2 番目のカメラの前でブレーキをかけて 1 に戻る可能性があります。 

(n) が (10^5) までの場合、(O(n^2)) アルゴリズムは約

 [
 \frac{10^5(10^5-1)}2 \約 5\cdot 10^9
 ]

 最悪の場合はペアごとにチェックします。 これは 1 秒の制限で処理できる範囲をはるかに超えています。 ソリューションでは、すべてのカメラを一定回数処理する必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 たとえば、唯一のカメラの速度制限がゼロの場合、```
1 1 1
1 0
```正解は(2)です。 車はゼロからスタートし、1 ユニット移動した後にゼロに戻る必要があるため、速度 1 まで加速してからゼロにブレーキをかけます。 単純に (x/v) を使用するソリューションは、エンドポイントの速度がゼロであるため中断します。 

中間カメラによって車を強制的に停止させることもできます。 のために```
2 1 1
1 0
2 1
```正解は約 (3.4494897428) です。 最初のユニットでは加速とブレーキをゼロに戻す必要があり、その後初めて車は再び加速を開始できます。 すべてのセグメントを独立した一定速度の動きとして扱うと、ここでは大きく失敗します。 

カメラの制限が等しい場合も微妙なケースです。 考慮する```
2 1 1
1 1
2 1
```答えはおよそ (1.8989794856) です。 2 番目のセグメントでは、車は速度 1 を超えて加速し、その後ブレーキで速度 1 に戻ります。単純に両方のセグメントを速度 1 で走行すると、答えは遅くなります。 

最後に、最後のカメラが目的地であるため、その速度制限はエンドポイントの制約であり、さらに先に進むための単なる制限ではありません。 制限がゼロの場合、車は速度ゼロで終了しなければなりません。 バックワードパスはその制約を自然に処理します。 

## アプローチ

 直接的なアプローチは、すべてのカメラについて、他の各カメラがその速度をどの程度強く制限するかを決定することです。 (x_i) のカメラの場合、後続のすべてのカメラ (j) が制動条件を与えます。 

[
 u_i^2 \le v_j^2 + 2b(x_j-x_i)。 
]

 ブルートフォース実装では、後続のすべてのカメラを (i) ごとに検査し、許容される最小速度を取得し、最初から加速のための同様の作業を行うことができます。 これは、将来の可能性のあるすべてのカメラが明示的にチェックされるため、正しいのですが、(n=10^5) の場合、(O(n^2)) の操作を実行し、約 (5\cdot10^9) 個のチェックを実行します。 

有益な観察は、これらの制約には局所的な再発があるということです。 カメラ (i+1) で合法的に使用できる最大速度がすでにわかっているとします。 この場合、カメラ (i) での最大速度は、距離 (x_{i+1}-x_i) が経過してもその速度まで減速できます。 

[
 \sqrt{v_{i+1}^2+2b(x_{i+1}-x_i)}。 
]

 以前のカメラは、(i+1) に格納された値によってすでに要約されています。 これは、完全な制動制限を 1 回の後方パスで計算できることを意味します。 

最初から同じ考え方が機能します。 カメラ (i-1) で到達可能な最大速度が (u) である場合、最大加速度 (a) で距離 (d) を移動した後、到達可能な最大速度は次のようになります。 

[
 \sqrt{u^2+2ad}。 
]

 これをカメラ自体の制限と組み合わせると、左側のすべての制約によって許容される最大速度が得られます。 

開始点とその前のカメラのみを考慮したカメラ (i) での最大速度を (F_i) とします。 (B_i) を、その後のカメラと制動限界のみを考慮したカメラ (i) での最大速度とします。 この場合、両方向に同時に対応できる最大速度は次のようになります。 

[
 s_i=\min(F_i,B_i)。 
]

 これらの速度は、まさに必要なエンドポイントの速度です。 2 つの連続する終点速度が固定されると、それらの間の最速の動作は非常に単純な形になります。つまり、レート (a) でピーク速度 (p) まで加速し、その後、レート (b) でブレーキをかけて次の終点速度まで下がります。 

速度 (u) で開始し、速度 (v) で終了する長さ (d) のセグメントの場合、加速時と制動時の移動距離は次のようになります。 

[
 d=\frac{p^2-u^2}{2a}+\frac{p^2-v^2}{2b}。 
]

 (p^2) を解くと、

 [
 p^2=
 \frac{2abd+bu^2+av^2}{a+b}。 
]

 このセグメントの時間は次のとおりです。 

[
 \frac{p-u}{a}+\frac{p-v}{b}。 
]

 2 つのパスによって生成されるエンドポイント速度は相互に到達可能であるため、結果の (p) は常に少なくとも両方のエンドポイント速度になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのカメラ位置 (x_i) と限界値 (v_i) を読み取ります。 位置 0 を、速度が 0 に固定されている追加点として扱います。 
2. 前進速度制限 (F_i) を計算します。 位置 0 の速度 0 から開始します。各カメラについて、加速度 (a) を使用して前の前進速度から到達可能な最大速度を計算し、(v_i) で上限を設定します。 

[
 F_i=\min\left(v_i,\sqrt{F_{i-1}^2+2a(x_i-x_{i-1})}\right)。 
]

 これにより、最初からのすべての制限と以前のすべてのカメラがキャプチャされます。 

1. 後進速度制限 (B_i) を計算します。 (B_n=v_n) を使用して最後のカメラから開始します。 後方に移動し、(B_{i+1}) までブレーキをかけたまま、前のカメラで車がどれくらいの速度を出すことができるかを計算します。 

[
 B_i=\min\left(v_i,\sqrt{B_{i+1}^2+2b(x_{i+1}-x_i)}\right)。 
]

 これにより、将来のすべての制動制約がカメラごとに 1 つの値に圧縮されます。 

1. 各カメラの実際のエンドポイント速度を次のように定義します。 

[
 s_i=\min(F_i,B_i)。 
]

前方値は、前のカメラを尊重しながら、車がスタートから (s_i) に到達できることを保証します。 逆方向の値は、将来のカメラを尊重しながら (s_i) から目的地まで続行できることを保証します。 

1. 位置 0 に速度を加算します (s_0=0)。 連続する位置のペアごとに、距離を (d=x_i-x_{i-1})、開始速度を (u=s_{i-1})、終了速度を (v=s_i) とします。 
2. 以下から最適なピーク速度を見つけます。 

[
 p^2=
 \frac{2abd+bu^2+av^2}{a+b}。 
]

 車は (u) から (p) まで加速し、(p) から (v) までブレーキをかけます。 セグメントタイムは

 [
 t_i=\frac{p-u}{a}+\frac{p-v}{b}。 
]

 1. すべてのセグメント時間を合計し、十分な精度で結果を出力します。 

### なぜ効果があるのか

 順方向パスでは、(F_i) がカメラ (i) で達成可能な最大速度であるという不変条件が維持され、開始から (i) まですべてのカメラが満たされます。 再帰は (v^2=u^2+2ad) から直接得られます。 

後方パスは、(B_i) がカメラ (i) で許可される最大速度であるという対称不変条件を維持しながら、(i) から目的地までのすべてのカメラを満たすことができます。 その再発は制動関係 (u^2=v^2+2bd) から導き出されます。 

したがって、(s_i=\min(F_i,B_i)) は、すべてのカメラで両方向で実現可能な最大速度になります。 より大きな終点速度を使用すると、以前の加速制約または将来の制動制約のいずれかに違反します。 より小さいエンドポイント速度を使用しても移動時間を改善することはできません。固定位置間の最速セグメントには、より大きな実現可能なエンドポイント速度を許可することで減少しない利点があるためです。 

2 つの固定終点速度の場合、(a) を下回る加速または (b) を下回る制動に費やされた時間は、終点条件に違反することなく、より速い加速または制動に置き換えることができます。 したがって、最適なセグメントは、最大加速とそれに続く最大制動で構成されます。 距離の方程式を解くとその固有のピーク速度が得られるため、セグメントの式から可能な最小時間が得られます。 これらの最適セグメントを合計すると、全体的な最適値が生成されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())

    x = [0] * n
    v = [0] * n

    for i in range(n):
        x[i], v[i] = map(int, input().split())

    # Maximum speed reachable from the start while
    # respecting all cameras seen so far.
    forward = [0.0] * n
    cur = 0.0
    prev_x = 0

    for i in range(n):
        d = x[i] - prev_x
        reachable = math.sqrt(cur * cur + 2.0 * a * d)
        cur = min(float(v[i]), reachable)
        forward[i] = cur
        prev_x = x[i]

    # Maximum speed allowed when looking from the destination backwards.
    backward = [0.0] * n
    backward[-1] = float(v[-1])

    for i in range(n - 2, -1, -1):
        d = x[i + 1] - x[i]
        reachable = math.sqrt(
            backward[i + 1] * backward[i + 1] + 2.0 * b * d
        )
        backward[i] = min(float(v[i]), reachable)

    # The actual feasible maximum speed at each camera.
    speed = [min(forward[i], backward[i]) for i in range(n)]

    ans = 0.0
    prev_speed = 0.0
    prev_x = 0.0

    for i in range(n):
        d = x[i] - prev_x
        cur_speed = speed[i]

        # During the optimal segment:
        #
        # d = (p^2 - u^2)/(2a) + (p^2 - v^2)/(2b)
        #
        # so:
        # p^2 = (2abd + bu^2 + av^2) / (a+b)
        p2 = (
            2.0 * a * b * d
            + b * prev_speed * prev_speed
            + a * cur_speed * cur_speed
        ) / (a + b)

        # Protect against a tiny negative value caused by floating point
        # rounding in cases where the exact value is zero.
        p = math.sqrt(max(0.0, p2))

        ans += (p - prev_speed) / a
        ans += (p - cur_speed) / b

        prev_speed = cur_speed
        prev_x = x[i]

    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```最初のパスでは、`cur`現在到達可能な最高速度として最初から。 表現`cur * cur + 2.0 * a * d`は標準的な一定加速度の関係であり、カメラの制限で最小値を取ると、新しい制限がすぐに組み込まれます。 

後方パスは、最終カメラの実際の速度制限から始まります。 目的地は正確に最後のカメラであるため、その後に後の位置はないため、その後方値は単純に次のようになります。`v[-1]`。 以前のすべてのカメラは、次のカメラまでに利用できる制動距離によって制限されます。 

3 番目のステージでは、2 つのアレイを結合します。 カメラは左側からは到達可能ですが、右側に向かって安全に離れることは不可能であり、その逆も同様です。 最小値を取得すると、両方の条件を同時に処理できます。 

セグメントの計算は最もデリケートな部分です。 ピーク速度は、必ずしもどちらのエンドポイント速度にも等しいとは限りません。 2 台のカメラが両方とも速度 1 を必要とする場合でも、車はそれらの間で 1 よりも高速になる可能性があります。 の二次式`p2`まさにその可能性を説明しています。 

Python では整数オーバーフローの問題はありません。 最大の中間値は、浮動小数点に変換する前に Python 整数によって快適に処理され、対応する値も倍精度浮動小数点数の有効範囲内に十分収まります。 の`max(0.0, p2)`ガードは、丸めによって引き起こされる微視的な負の値からのみ保護します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) | 2 つの線形パスで前方制限と後方制限が計算され、その後にセグメント時間の 1 つの線形パスが計算されます。 |
 | スペース | (O(n)) | カメラ データと前進速度、後進速度、最終速度の配列が保存されます。 |

 このアルゴリズムはカメラごとに一定数の演算のみを実行するため、(10^5) カメラでは数十万回の算術演算のみが必要になります。 メモリ使用量も直線的で、簡単に 256 MB 以内に収まります。 

## テストケース```python
import sys
import io
import math

def solve_io(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n, a, b = map(int, sys.stdin.readline().split())

    x = [0] * n
    v = [0] * n

    for i in range(n):
        x[i], v[i] = map(int, sys.stdin.readline().split())

    forward = [0.0] * n
    cur = 0.0
    prev_x = 0

    for i in range(n):
        d = x[i] - prev_x
        cur = min(float(v[i]), math.sqrt(cur * cur + 2.0 * a * d))
        forward[i] = cur
        prev_x = x[i]

    backward = [0.0] * n
    backward[-1] = float(v[-1])

    for i in range(n - 2, -1, -1):
        d = x[i + 1] - x[i]
        backward[i] = min(
            float(v[i]),
            math.sqrt(
                backward[i + 1] * backward[i + 1]
                + 2.0 * b * d
            )
        )

    speed = [min(forward[i], backward[i]) for i in range(n)]

    ans = 0.0
    prev_speed = 0.0
    prev_x = 0.0

    for i in range(n):
        d = x[i] - prev_x
        cur_speed = speed[i]

        p2 = (
            2.0 * a * b * d
            + b * prev_speed * prev_speed
            + a * cur_speed * cur_speed
        ) / (a + b)

        p = math.sqrt(max(0.0, p2))

        ans += (p - prev_speed) / a
        ans += (p - cur_speed) / b

        prev_speed = cur_speed
        prev_x = x[i]

    sys.stdin = old_stdin
    return f"{ans:.10f}"

def assert_close(inp: str, expected: float, eps: float = 1e-8):
    actual = float(solve_io(inp))
    assert abs(actual - expected) <= eps, (actual, expected)

# Provided sample 1
assert_close(
    """\
2 1 1
1 1
2 2
""",
    2.1815405,
    1e-7,
)

# Provided sample 2
assert_close(
    """\
4 1 5
2 3
4 5
7 3
9 5
""",
    4.3598594,
    1e-7,
)

# Minimum-size input, endpoint speed is zero.
assert_close(
    """\
1 1 1
1 0
""",
    2.0,
)

# One camera, endpoint speed is nonzero.
expected = 2.0 * math.sqrt(1.5) - 1.0
assert_close(
    """\
1 1 1
1 1
""",
    expected,
)

# All camera limits are equal.
p = math.sqrt(1.5)
expected = (2.0 * p - 1.0) + 2.0 * (p - 1.0)
assert_close(
    """\
3 1 1
1 1
2 1
3 1
""",
    expected,
)

# Intermediate camera forces a full stop.
expected = 2.0 + (2.0 * math.sqrt(1.5) - 1.0)
assert_close(
    """\
2 1 1
1 0
2 1
""",
    expected,
)

# Maximum-size input with a very simple exact answer.
# Every camera forces speed zero, so every unit segment takes exactly 2 time units.
n = 100000
parts = [f"{n} 1 1"]
parts.extend(f"{i} 0" for i in range(1, n + 1))
max_input = "\n".join(parts) + "\n"

 ## 特殊なケース

 速度制限がゼロの最終的なカメラについては、次のことを考慮してください。```
1 1 1
1 0
```カメラは正のエンドポイント速度を禁止しているため、前進速度はゼロです。 ここが目的地なので後進速度もゼロです。 したがって、選択されたエンドポイント速度はゼロになります。 単一セグメントの場合、

 [
 p^2=\frac{2\cdot1\cdot1\cdot1}{2}=1、
 ]

 したがって (p=1)。 加速には 1 つの時間単位がかかり、制動には別の時間単位がかかり、正確に (2) が得られます。 

中間のゼロ速度カメラの場合、```
2 1 1
1 0
2 1
```どちらのパスも最初のカメラで速度 0 を選択します。 最初のセグメントのピーク速度は 1 で、2 単位の時間がかかります。 2 番目のセグメントはゼロから始まり速度 1 で終わり、ピーク速度 (\sqrt{1.5}) と時間 (2\sqrt{1.5}-1) が得られます。 合計は約 (3.4494897428) です。 バックワード パスは、アルゴリズムが最初のカメラを通過して不正な正の速度を伝達するのを防ぎます。 

カメラの制限を同等にするには、```
2 1 1
1 1
2 1
```両方のカメラ速度は 1 として選択されます。最初のセグメントのピークは (\sqrt{1.5}) であるため、時間は (2\sqrt{1.5}-1) になります。 2 番目のセグメントでは同じピークが使用されますが、両方のエンドポイントはすでに速度 1 を持っており、時間は (2(\sqrt{1.5}-1)) になります。 合計は約 (1.8989794856) です。 これは、セグメント計算で車両がカメラ間で両方のカメラ速度を超えることを許可する必要がある理由を示しています。 

速度制限が高いが、以前の制限カメラが設置されている目的地の場合、前方通行がアクティブな制約になる可能性があります。 サンプル 1 では、2 番目のカメラは速度 2 を許可しますが、最初のカメラから速度 1 で到達可能な距離は (\sqrt3) のみです。 最終的に選択された速度は、結果的に 2 ではなく (\sqrt3) になります。前方パスにより、アルゴリズムは、すべてのカメラに設定された制限が独立して達成可能であると想定するのを防ぎます。
