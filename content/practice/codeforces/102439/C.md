 ## 解決策
 ## 問題の理解

 私たちは持っています`n`ゴキブリ、そしてそれぞれのゴキブリは`m`裏面に数字が書かれています。 いくつかの数字はわかっていますが、すべての数字は`?`以下の任意の数字に独立して置き換えることができます。`0`に`9`。 先頭のゼロは許可されます。 

すべての疑問符を置き換えた後、結果の数値は次の条件を満たす必要があります。 

[
 x_1 < x_2 < \dots < x_n。 
】

 タスクは、そのようなシーケンスを 1 つ構築することではありません。 有効な修復物をすべて考慮し、すべての値を加算する必要があります。`n`その復元に登場する数字。 最終的な答えは、この合計モジュロ (10^9+7) です。 公式の制約は (n,m\le 50) で、制限時間は 1.5 秒です。 

すべての数値は同じ長さであるため、2 つの数値を数値的に比較することは、それらの数字列を辞書編集的に比較することとまったく同じです。 2 つの数値が異なる最初の位置によって順序が決まります。 

50 という境界は、ゴキブリの間隔にわたる動的プログラミングには十分小さいですが、どちらの場合も指数関数的にするには小さすぎます。`n`または`m`。 もしすべてなら`n*m`位置は疑問符であり、(10^{nm}) 個の修復があります。 最大サイズでは (10^{2500}) 個の可能性があります。 (O(nm)) 時間で 1 つの復元をチェックするだけでも、およそ (2450\cdot10^{2500}) 桁の比較が行われるため、総当たりは完全に不可能です。 

サイレント エラーを引き起こす傾向にある 3 つの特殊なケースがあります。 

まず、次数は厳密に増加しており、減少していません。 のために```
2 1
?
?
```有効なペアは 45 のペア (0<1,0<2,\ldots,8<9) とその組み合わせです。 各数字は正確に 9 つの有効なペアで表示されるため、答えは (9(0+1+\dots+9)=405) となります。 治療中`<=`as valid では、誤って等しいペアが含まれ、495 が生成されます。 

次に、先頭のゼロは実数であるため、破棄してはなりません。 のために```
2 2
0?
10
```最初の数字は次のとおりです`00`を通して`09`、2番目の数字は`10`。 10 件の修復はすべて有効であり、その合計は

 [
 (0+1+\dots+9)+10\cdot10=145。 
】

 解釈する実装`0?`無効な表現では、それらすべてが誤って拒否されるためです。 

第三に、最初の桁が等しいからといって、2 つの数値が等しいという意味ではありません。 のために```
2 2
??
??
```2 つの数値の最初の桁が同じであっても、2 番目の桁が厳密に増加している場合には有効なペアを形成することがあります。 プレフィックスが等しい場合は、すぐに拒否されるのではなく、次の桁まで継続する必要があります。 

## アプローチ

 直接的なアプローチは、すべての疑問符を個別に置き換え、結果として得られるすべての数値を構築し、シーケンスが厳密に増加しているかどうかをテストすることです。 これは、考えられるすべての修復を明示的に検査しているため、正しいです。 問題は検索スペースです。 と`q`疑問符は (10^q) の代入を考慮し、最悪の場合 (q=nm=2500) を考慮します。 要求された合計を計算するコストを考慮する前でも、(10^{2500}) 個の候補が得られるため、ブルート フォースは使用できません。 

有益な観察は、一度に 1 桁の位置を検査すると、増加するシーケンスが非常に特殊な構造を持つということです。 

現在、ゴキブリの連続した間隔に同じプレフィックスが付いていると仮定します。 次の桁では、選択した桁が減少していなければなりません。 2 つの連続するゴキブリの間で数字が厳密に増加する場合は常に、それらの 2 つの側はすでに永遠に順序付けされているため、間隔は 2 つの独立したグループに分割されます。 同じ数字を受け取るゴキブリは同じグループに残り、残りの接尾辞によって順序付けする必要があります。 

たとえば、現在 4 匹のゴキブリが同じプレフィックスを共有しており、その次の数字が

 [
 2、2、5、8、
 】

 その後、シーケンスがグループに分割されます`[1,2]`、`[3,3]`、 そして`[4,4]`。 最初のグループでは接尾辞を増やす必要がありますが、他の 2 つのグループにはそれぞれ 1 匹のゴキブリが含まれており、それ以上の順序付けは必要ありません。 

これにより、指数関数的な比較状態セットが区間動的プログラムに変わります。 定義する`cnt[l][r]`ゴキブリが侵入したときに残りの接尾辞を埋める有効な方法の数として`l`を通して`r`現在、同じプレフィックスが付いています。 また定義します`sum[l][r]`残りのサフィックスのみを考慮した、これらの方法のすべての数値の合計として計算されます。 

1 桁で、間隔が連続したブロックに分割されます。 すべてのブロックは 1 桁を受け取り、ブロック桁は厳密に増加し、異なるブロックのサフィックスは独立しています。 ブロック`[k,r]`数字の受信が許可されています`d`まさにそのときからのすべてのパターン`k`を通して`r`受け入れる`d`この位置で。 

最後のブロックとそれに割り当てられた数字を列挙できます。 前のブロックでは、より小さい数字を使用する必要があります。 可能な桁は 10 桁しかないため、最後の桁には別の小さな DP 次元を保持します。 これにより、(O(10mn^3)) 時間が得られます。これは、次の場合に実用的です。`n,m <= 50`。 

同じ DP はカウントだけでなく合計も保持できます。 2 つの独立したブロックが結合されると、それらのカウントは増加します。 それらの合計は次のようになります

 [
 S = S_1C_2+C_1S_2。 
】

 現在の桁は、その値に適切な 10 のべき乗を乗じた値を、間隔全体のゴキブリごとに 1 回ずつ与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm\cdot10^{nm})) | (O(nm)) | 遅すぎる |
 | インターバルDP | (O(10mn^3)) | (O(n^2+mn)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのパターン位置を 10 ビットのマスクに変換します。 少し`d`桁の場合に設定されます`d`その位置に置くことができます。 これにより、間隔全体で 1 桁を受信できるかどうかのチェックが整数ビット演算になります。 
2. 桁位置を右から左に処理します。 最初は残りの桁はありません。 したがって、1 匹のゴキブリを含む区間には有効な空の接尾辞が 1 つありますが、等しい完全数は許可されないため、少なくとも 2 匹のゴキブリが含まれる区間には有効な接尾辞が 0 個あります。 
3. 現在の桁位置については、間隔を考慮します。`[l,r]`その前の接頭辞は、その中のすべてのゴキブリで同一です。 選択した現在の桁は減少しないものでなければなりません。 同じ数字が 1 つのブロックを形成しますが、厳密に増加すると 2 つの独立したブロックが分離されます。 
4. 桁を修正する`d`最後のブロックの`[k,r]`。 ブロックは、次のすべてのパターンが存在する場合にのみ有効です。`k`を通して`r`受け入れる`d`。 位置と桁ごとに、間隔が次で終わる最初のインデックスを事前計算します。`r`完全にその数字を受け入れるパターンで構成することができます。 これにより、トランジション内のすべての文字を個別にチェックする必要がなくなります。 
5.その部分`[l,k-1]`空でない場合は、以下の数字で終わる必要があります。`d`。 あらゆる可能性に対して`k`、プレフィックス DP は、ウェイの数と、そのような以前のブロックすべてのサフィックスの合計を示します。 ブロック`[k,r]`すでに計算されたものを提供します`cnt[k][r]`そして`sum[k][r]`。 
6. 前の部分と最後のブロックを結合します。 彼らの数が`C1`そして`C2`、結合された数は`C1*C2`。 それらの合計が`S1`そして`S2`、接尾辞の合計は次のようになります。`S1*C2 + C1*S2`なぜなら、最初のパートのすべての割り当ては、2 番目のパートのすべての割り当てと組み合わせることができるからです。 
7. 現在の桁の DP を計算した後、現在の桁自体を合計に加算します。 間隔に次のものが含まれる場合`r-l+1`ゴキブリと現在位置には位の値 (10^{m-1-p}) があり、数字を割り当てます`d`貢献する

 [
 d\cdot(r-l+1)\cdot10^{m-1-p}
 】

 その状態によってカウントされるすべての割り当てに適用されます。 

1. すべてのポジションが処理された後、`cnt[0][n-1]`有効な完全なシーケンスをすべてカウントし、`sum[0][n-1]`まさに要求された合計です。 

### なぜ効果があるのか

 不変条件とは、`cnt[l][r]`そして`sum[l][r]`ゴキブリに対する有効な接尾辞の割り当てをすべて正確に記述します`l..r`すでに処理されたプレフィックスが等しいという前提の下で。 現在の桁では、すべての有効な割り当ては、現在の桁が等しい最大連続ブロックへの一意のパーティションを持ちます。 これらのブロックの桁数は厳密に増加しており、異なるブロックを独立して完了できます。 遷移では、可能なすべての最後のブロックとそのブロックの可能なすべての桁が列挙されるため、有効な割り当てはすべて 1 回だけカウントされます。 逆に、すべての遷移では、減少しない現在の数字と再帰的に有効なサフィックスが作成されるため、厳密に増加するシーケンスが作成されます。 同じ分解を通じてカウントと合計の両方を実行すると、個々の割り当てを列挙することなく、要求された合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n, m = map(int, input().split())
    patterns = [input().strip() for _ in range(n)]

    # allowed[pos][i] is a bit mask of digits allowed for cockroach i.
    allowed = [[0] * n for _ in range(m)]

    for i in range(n):
        s = patterns[i]
        for p, ch in enumerate(s):
            if ch == '?':
                allowed[p][i] = (1 << 10) - 1
            else:
                allowed[p][i] = 1 << (ord(ch) - ord('0'))

    # next_cnt[l][r], next_sum[l][r]:
    # valid completions for positions p+1 ... m-1,
    # assuming positions before p are equal for l..r.
    next_cnt = [[0] * n for _ in range(n)]
    next_sum = [[0] * n for _ in range(n)]

    for i in range(n):
        next_cnt[i][i] = 1

    pow10 = [1] * m
    for i in range(1, m):
        pow10[i] = pow10[i - 1] * 10 % MOD

    for p in range(m - 1, -1, -1):
        # start[d][r] is the first k such that every pattern k..r
        # accepts digit d at position p.
        start = [[0] * n for _ in range(10)]
        last_bad = [-1] * 10

        for r in range(n):
            mask = allowed[p][r]
            for d in range(10):
                if not (mask >> d) & 1:
                    last_bad[d] = r
                start[d][r] = last_bad[d] + 1

        cur_cnt = [[0] * n for _ in range(n)]
        cur_sum = [[0] * n for _ in range(n)]

        for l in range(n):
            # fcnt[r][d]:
            # ways for [l,r] where the last current-digit block uses d.
            #
            # fsum[r][d]:
            # corresponding sum, including positions p+1..m-1,
            # but not yet the current digit at p.
            fcnt = [[0] * 10 for _ in range(n)]
            fsum = [[0] * 10 for _ in range(n)]

            # Prefix sums over the possible last digit.
            pref_cnt = [[0] * 10 for _ in range(n)]
            pref_sum = [[0] * 10 for _ in range(n)]

            weight = pow10[m - 1 - p]

            for r in range(l, n):
                row_sum = 0

                for d in range(10):
                    lo = max(l, start[d][r])
                    if lo > r:
                        continue

                    ways = 0
                    total = 0

                    for k in range(lo, r + 1):
                        block_cnt = next_cnt[k][r]
                        if block_cnt == 0:
                            continue

                        block_sum = next_sum[k][r]

                        if k == l:
                            prev_cnt = 1
                            prev_sum = 0
                        elif d == 0:
                            continue
                        else:
                            prev_cnt = pref_cnt[k - 1][d - 1]
                            prev_sum = pref_sum[k - 1][d - 1]

                        ways += prev_cnt * block_cnt
                        total += prev_sum * block_cnt + prev_cnt * block_sum

                    fcnt[r][d] = ways % MOD
                    fsum[r][d] = total % MOD

                    row_sum += fsum[r][d]

                # Build prefix sums for this r.
                pc = 0
                ps = 0
                for d in range(10):
                    pc += fcnt[r][d]
                    ps += fsum[r][d]
                    pref_cnt[r][d] = pc % MOD
                    pref_sum[r][d] = ps % MOD

                total_cnt = pc % MOD

                # Add the current digit to every cockroach in [l,r].
                size = r - l + 1
                digit_contribution = 0

                for d in range(10):
                    digit_contribution += (
                        d * size * weight * fcnt[r][d]
                    )

                cur_cnt[l][r] = total_cnt
                cur_sum[l][r] = (
                    row_sum + digit_contribution
                ) % MOD

        next_cnt = cur_cnt
        next_sum = cur_sum

    print(next_sum[0][n - 1] % MOD)

if __name__ == "__main__":
    solve()
```実装の最初の部分では、すべてのパターン位置を数字マスクに変換します。 あ`?`は 10 ビットすべてを取得しますが、固定数字は 1 ビットだけを取得します。 DP は元のキャラクターを再度検査する必要はありません。`next_cnt`そして`next_sum`現在位置を削除した後の状態を表します。 1 匹のゴキブリには常に空の接尾辞が 1 つだけあるため、対角要素は 1 に初期化されます。 等しい完全な数は厳密な順序付けを満たすことができないため、少なくとも 2 の長さの区間はゼロから始まります。 

それぞれのポジションごとに、`start[d][r]`で終わるブロックがどこまで残っているかを記録します`r`数字を許可したまま拡張できる`d`。 パターンの場合`r`拒否する`d`、そのようなブロックは存在しません。 それ以外の場合、境界は最新のパターンを拒否することによって決定されます。`d`。 これは、遷移で使用される間隔の有効性条件です。 

固定の開始点の場合`l`、`fcnt[r][d]`そして`fsum[r][d]`～のすべてのパーティションを説明する`[l,r]`最後のブロックが数字を受け取る`d`。 トランジションが始まりを選ぶ`k`最後のブロックの。 前の部分は小さい数字で終わる必要があるため、`pref_cnt[k-1][d-1]`そして`pref_sum[k-1][d-1]`が使用されています。 

の`k == l`case は、最後のブロックの前にある空のプレフィックスを表します。 そのカウントは 1 で、合計は 0 です。 この境界ケースは、最初のブロックが区間全体を占める区間に必要です。 

2 つのブロックは現在の桁が異なると独立するため、合計遷移ではカウントの乗算が使用されます。 対応する合計は次のようになります。`prev_sum * block_cnt + prev_cnt * block_sum`これは、一方の側の各割り当てをもう一方の側のすべての割り当てと組み合わせることができるという事実を説明しています。 

ついに、`digit_contribution`現在の数字を間隔内のすべてのゴキブリに追加します。 の乗算`pow10[m-1-p]`は、数字を実際の数値に変換するものです。 Python の整数はオーバーフローしませんが、すべての DP 値はモジュロ (10^9+7) で削減されるため、効率的な算術演算のために中間値は十分に小さいままになります。

            for d in range(10):
                if not ((mask >> d) & 1):
                    last_bad[d] = r
                start[d][r] = last_bad[d] + 1

        cur_cnt = [[0] * n for _ in range(n)]
        cur_sum = [[0] * n for _ in range(n)]

        weight = pow10[m - 1 - p]

        for l in range(n):
            fcnt = [[0] * 10 for _ in range(n)]
            fsum = [[0] * 10 for _ in range(n)]
            pref_cnt = [[0] * 10 for _ in range(n)]
            pref_sum = [[0] * 10 for _ in range(n)]

            for r in range(l, n):
                row_sum = 0

                for d in range(10):
                    lo = max(l, start[d][r])
                    if lo > r:
                        continue

                    ways = 0
                    total = 0

                    for k in range(lo, r + 1):
                        block_cnt = next_cnt[k][r]
                        if block_cnt == 0:
                            continue

                        block_sum = next_sum[k][r]

                        if k == l:
                            prev_cnt = 1
                            prev_sum = 0
                        elif d == 0:
                            continue
                        else:
                            prev_cnt = pref_cnt[k - 1][d - 1]
                            prev_sum = pref_sum[k - 1][d - 1]

                        ways += prev_cnt * block_cnt
                        total += prev_sum * block_cnt
                        total += prev_cnt * block_sum

                    fcnt[r][d] = ways % MOD
                    fsum[r][d] = total % MOD
                    row_sum += fsum[r][d]

                pc = 0
                ps = 0

                for d in range(10):
                    pc += fcnt[r][d]
                    ps += fsum[r][d]
                    pref_cnt[r][d] = pc % MOD
                    pref_sum[r][d] = ps % MOD

                size = r - l + 1
                digit_sum = 0

                for d in range(10):
                    digit_sum += d * size * weight * fcnt[r][d]

                cur_cnt[l][r] = pc % MOD
                cur_sum[l][r] = (row_sum + digit_sum) % MOD

        next_cnt = cur_cnt
        next_sum = cur_sum

    print(next_sum[0][n - 1] % MOD)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 厳密な不等式の場合```
2 1
?
?
```2 つの単一要素間隔の基本状態から始まります。 唯一の数字の位置では、2 つの要素が 2 つの異なるブロックを形成し、最初のブロックの数字が 2 番目のブロックの数字より小さくなければなりません。 このような数字のペアは 45 個あります。 すべてのペアの 2 桁の合計は 405 であるため、DP は正確に返します。`405`。 最後の桁の位置にはそれらを区切る接尾辞が残っていないため、等しい桁が遷移に入ることはありません。 

先行ゼロの場合、```
2 2
0?
10
```最初のパターンは 10 個の値を表します`00,01,...,09`、一方、2番目は`10`。 最初の数値は常に小さいため、有効なシーケンスは 10 個あります。 それらの合計は 145 です。DP の扱いは`0`通常の許可された数字として使用され、途中でパターンを整数に変換することはありません。そのため、先頭のゼロによって特別なケースが発生することはありません。 

等しいプレフィックスの場合、```
2 2
??
??
```最初の桁は両方のゴキブリで同じである可能性があります。 その状況では、間隔は単一ブロックのままで、DP は次の桁の状態を使用します。 2 桁目では、厳密に増加するペアのみが生き残ります。 まさにこれが、すべての隣接するペアの明示的な比較状態を保存せずに、再帰が等しいプレフィックスを処理できる理由です。 

不可能なシーケンスの場合、```
3 1
7
7
7
```基本状態には、1 を超える長さの有効な間隔は含まれません。 すべてのパターンは次の数字のみを受け入れるため、唯一の数字を処理しても 3 匹のゴキブリを異なる数字に分割することはできません。`7`。 結果のカウントと合計は両方ともゼロになります。 

最大サイズのオールゼロ入力の場合、2 匹以上のゴキブリを含むすべての間隔は、すべての位置で依然として不可能です。 DP は引き続き完全なデータを処理します。`50 x 50`ただし、シングルトン以外のすべての状態はゼロのままです。 結果的に答えは`0`、メモリ使用量は二次関数のままです。`n`。
