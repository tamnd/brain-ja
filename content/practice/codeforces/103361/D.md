 ## 問題の理解

 一桁から始めます`x`。 この数字から、現在の数字に 3 を掛け、その結果の最後の 10 進数字を取り出し、それをボードに書かれた数字の右側に追加することによって、新しい数字を繰り返し生成します。 後`n`ステップは、`n`-この決定論的な方法で形成された桁数。 

タスクは、この数値を明示的に構築することではなく、最終的な数値が正しいかどうかを判断することです。`n`-桁の数値は 3 で割り切れます。 

この制約により、プロセスを直接シミュレートしようとする試みは即座に排除されます。 以来`n`と同じ大きさにすることができます`10^9`、生成さえも`n`桁は無理です。 どのソリューションも、入力を読み取った後、一定時間内に機能する必要があります。 

素朴だが自然なアプローチは、実際に数字の生成をシミュレートし、3 を法とする数字の合計を計算することです。これは小規模な場合に機能します。`n`、ただし、大規模な場合は実行不可能になります`n`。 

プロセス自体にはトリッキーな構造分岐がないため、潜在的な落とし穴は、実際に 3 で割り切れる要素を誤解していることだけです。重要な微妙な点は、乗算と切り捨てが繰り返されるため、桁が非線形に変化するため、桁の合計が単純な構造であるかどうかがすぐには分からないことです。 

## アプローチ

 単純な総当たりソリューションでプロセスをシミュレートします。 から始めます`a1 = x`、その後繰り返し計算します`ai = (3 * a(i-1)) % 10`そして各数字を追加します。 全部建て終わったら`n`数字がある場合は、それらの合計を計算し、それが 3 で割り切れるかどうかを確認します。 

3 で割り切れるかどうかは桁の合計にのみ依存するため、これは正しいです。 ただし、この方法では、`n`反復回数、最大`10^9`。 10 億の単純な算術演算でも、Python や C++ の 2 秒の制限をはるかに超えています。 

重要な観察結果は、モジュロ 10 ではなくモジュロ 3 での桁生成を分析することで得られます。再発は次のとおりです。`ai = (3 * a(i-1)) % 10`。 このモジュロ 3 を減算すると、次のようになります。`ai ≡ (3 * a(i-1) mod 10) mod 3`。 以来`10 ≡ 1 (mod 3)`、モジュロ 10 を取得しても、モジュロ 3 の値には影響しません。これにより、切り捨てがなかったかのように推論することができます。 

したがって`ai mod 3 ≡ (3 * a(i-1)) mod 3 ≡ 0`みんなのために`i ≥ 2`。 これは、最初の桁以降のすべての桁が 3 を法とする桁の合計に何も寄与しないことを意味します。割り算条件全体が最初の桁のみに崩壊します。`x`。 

したがって、プロセスは動的に見えますが、完全に静的なモジュール構造になっています。

 ## アルゴリズムのチュートリアル

 このソリューションでは、生成された数値を構築するのではなく、モジュール プロパティに変換します。 

1. 値を読み取る`x`そして`n`。 値`n`生成される桁数を制御するだけですが、後で使用するモジュールの動作には影響しません。 
2. 3 で割り切れるかどうかは、3 を法とする桁の合計に依存することに注目してください。これにより、完全な数値構造を無視して、桁の寄与のみに焦点を当てることができます。 
3. 最初の桁が正確であることに注意してください。`x`, したがって、合計への寄与は固定されます。 
4. 次の数字ごとに、繰り返しを観察します。`ai = (3 * a(i-1)) % 10`。 モジュロ 3 とみなされると、そのような各桁は 0 になります。これは、切り捨てが 10 の倍数にのみ影響し、モジュロ 3 が保持される前に、3 を乗算すると値が 3 で割り切れるようになるためです。 
5. 最初の桁を除くすべての桁は、3 を法とする合計に影響を与えないと結論付けます。 
6.次のことを確認します。`x % 3 == 0`。 「はい」の場合、その整数は 3 で割り切れますが、そうでない場合は割り切れません。 

### なぜ効果があるのか

 このアルゴリズムは、最初の数字以降に生成されるすべての数字が 3 を法として 0 に一致するという不変式に依存します。3 で割り切れるかどうかは 3 を法とする数字の合計にのみ依存し、プロセスでは最初のステップの後に非ゼロの寄与がまったく導入されないため、最終的な答えは最初の数字によって完全に決定されます。 どんなに大きくても`n`となり、反復の構造により、後の桁がモジュロ 3 の合計に影響を与えることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, n = map(int, input().split())
    if x % 3 == 0:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```このコードは、最初の数字のみが重要であるという観察を直接適用しています。 の値`n`読み取られますが、割り算には影響しないため、入力解析を超えて使用されることはありません。 

実装上の重要な決定は、シミュレーション ループを完全に回避することです。 これは、次のような場合でもソリューションの時間を一定に保つためのものです。`n`非常に大きいです。
