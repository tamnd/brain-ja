 ## 問題の理解

 セルのストリップを表すバイナリ文字列が与えられます。 一部のセルにはすでに十字が含まれており、次のようにマークされています。`X`、残りは空で、次のようにマークされています。`.`。 重要な制約は、2 つの十字を隣接させることはできないということです。つまり、`XX`隣り合った位置にある。 

ミシャはすでに有効なクロスを配置しています。 次に、別の人、Lёsha が、2 つの十字架が隣接しないというルールを尊重しながら、さらに十字架を追加します。 最後に、Katya が構成が最大であることを確認したと言われます。これは、Misha と Lёsha の両方が十字架を配置した後、隣接ルールを破らずに追加の十字架を配置できる空のセルが存在しないことを意味します。 

タスクは、初期構成を考慮して、Lёsha が最大でいくつの十字架を追加できるかを判断することです。 

入力サイズは小さく、n は最大 1000 です。これは、原理的には O(n²) アプローチが受け入れられることをすぐに示唆していますが、構造が非常に局所的であるため、線形の貪欲なソリューションを期待する必要があります。 

微妙だが重要な制約は、Misha の設定がすでに有効であるため、隣接する設定が存在しないことです。`X`最初はキャラクター。 これにより、検証や修復ロジックの必要性がなくなり、純粋に拡張に集中できるようになります。 

主なエッジ ケースは、既存のクロスと境界の間の短いギャップから発生します。 

文字列が`"..."`の場合、すべての位置は自由になりますが、それでも十字を互いに隣接して配置することはできないため、最大配置は 1 つおきのセルになります。 

文字列が`"X.X"`の場合、追加のクロスを追加することはできません。 

文字列が`"..X.."`の場合、追加の十字はパリティに応じて左または右に 1 つだけ配置できます。 

単純な間違いは、新しく占有された隣接セルをマークせずに貪欲に配置しようとしたり、配置された十字が両方の隣接セルをブロックすることを忘れたりすることです。 

## アプローチ

 ブルートフォース戦略では、空のポジションのすべてのサブセットを試し、そこにクロスを配置することが隣接制約に違反するかどうかを確認します。 各候補サブセットについて、文字列全体を O(n) で検証すると、O(2ⁿ · n) の複雑さになりますが、これは n = 1000 の場合でも完全に実行不可能です。 

もう少し合理的な総当たり攻撃は、ポジションを反復処理し、クロスを置くかどうかを再帰的に決定することです。 枝刈りを行っても、空の各セルは隣接するセルとローカルでのみ相互作用するため、分岐係数は高いままであり、依然として指数関数的な構成を探索することになります。 

重要な観察は、制約が純粋にローカルであるということです。つまり、十字を配置すると、そのすぐ隣のものだけが禁止されます。 これは、後戻りする必要がないことを意味します。 代わりに、左から右にスキャンして、両方の隣が空になるたびに貪欲に十字を配置できます。 

すでに存在しているものも尊重しなければなりません`X`強制占有セルとして機能する位置。 すでに隣接セルによって占有されているかブロックされているセルを見つけたら、単純にそれをスキップします。 それ以外の場合、すぐに十字を配置することは、残りのサフィックスにできるだけ多くの十字を配置する機能を保持するため、常に安全で局所的に最適です。 

これにより、問題は単一の直線パスに縮小されます。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`added = 0`Lёshaが何回交差したかを追跡します。 既存のプレースメントではなく、新しいプレースメントのみをカウントします。 
2. 文字列を変更可能な配列に変換して、新しく配置された十字をマークできるようにします。 新しく配置された十字も隣接するセルをブロックするため、これは重要です。 
3. インデックスを使用して文字列を左から右にトラバースします。`i`。 
4. 各ポジションについて`i`、空かどうかを確認します。 すでにある場合`X`、すでに占有されているためスキップします。 
5. 位置の場合`i`が空の場合、ここにクロスを配置できるかどうかを確認します。 これには、左隣 (存在する場合) が存在しないことが必要です。`X`、右隣 (存在する場合) は存在しません。`X`。 新しく配置されたクロスも同様にブロックとして扱います。 
6. 隣人が両方とも安全であれば、所定の位置に十字架を置きます`i`、増分`added`、マーク`i`として`X`配列に含まれるため、将来の決定に影響します。 
7. 文字列の終わりまでスキャンを続けます。 

スキャンが完了したら、`added`Lёshaが追加できるクロスの最大数です。 

### なぜ効果があるのか

 核となる不変条件は、スキャンの各ステップでプレフィックスが`[0..i-1]`はすでに、以前の位置をさらに変更しても、隣接性制約に違反することなく答えを改善できない状態にあります。 有効な解決策はどれも、クロスの数を減らすことなく、プレフィックス上のこの貪欲な配置に一致するものに変換できます。`i`のみに依存する`i-1`そして`i+1`。 ポジションを通過したら`i`、私たちはそれを再考することはありません、そして、代替の選択は同じかそれ以上の右側のポジションをブロックすることになります。 したがって、可能な限りクロスを配置することが、局所的には最適であり、世界的には安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = list(input().strip())

    added = 0

    for i in range(n):
        if s[i] == 'X':
            continue

        left_ok = (i == 0 or s[i - 1] == '.')
        right_ok = (i == n - 1 or s[i + 1] == '.')

        if left_ok and right_ok:
            s[i] = 'X'
            added += 1

    print(added)

if __name__ == "__main__":
    solve()
```このソリューションは文字列をリストに読み取るため、更新が効率的に行われ、新しく配置されたクロスがすぐに反映されます。 左右の隣接要素のチェックには境界処理が含まれており、エッジは外側で自動的に安全なものとして扱われます。 

重要な実装の詳細は、元の文字列ではなく、配列の現在の状態をチェックして、新しく追加された十字が後続の配置を正しくブロックするようにすることです。
