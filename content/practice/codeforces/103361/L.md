 ## 問題の理解

 文字列の 2 つのコレクションが与えられ、1 つは配列と呼ばれます。`a`もう1つは配列と呼ばれる`b`。 タスクは空ではない単一の文字列を選択することです。`s`2つの条件を同時に満たすもの。 

初め、`s`のすべての文字列の部分文字列として出現する必要があります。`a`。 これは、から任意の文字列を取得すると、`a`、その中のどこかで見つけることができます`s`連続したセグメントとして。 

次に、最初の条件を満たすすべての文字列のうち、`s`最小限の文字列の部分文字列として現れる`b`できるだけ。 この数を最小限に抑えた後、同じ最小値を達成する候補が複数ある場合は、長さが最も短い候補が選択されます。 

出力は 2 つの数値のみです: 内の文字列の最小数`b`選択した部分文字列とその部分文字列の長さを含むもの。 有効な部分文字列がまったく存在しない場合は、次のように出力します。`-1 -1`。 

文字列の数という点では制約が大きく見えますが、重要な隠れた構造は、各テストにわたるすべての文字列の合計の長さがわずか 50,000 であることです。 これにより、複雑さの状況が完全に変わります。 最大 50,000 個の文字列が存在する場合でも、それらを合計すると短いため、文字列ごとに 2 次的な解法は依然として実行可能です。 

素朴な解釈では、すべての文字列のすべての部分文字列を反復処理することを提案します。`a`そしてそれぞれをすべての文字列と比較してチェックします`b`。 これは、文字列ごとに部分文字列の数が二次関数的に増加し、メンバーシップを繰り返し確認するとコストが倍増するため、すぐに失敗します。 

候補者を 1 人ずつテストしようとすると、さらに微妙な問題が発生します。 たとえば、次の最初の文字列から部分文字列を選択します。`a`また、他のすべての文字列に対してそれらを検証すると、依然として爆発につながる可能性があります。これは、候補部分文字列の数が文字列あたり約 125,000 に達する可能性があり、多くの文字列に対してそれぞれをチェックするのが遅すぎるためです。 

一般的に単純なアプローチを破るエッジケースには、次のような状況が含まれます。 

すべての文字列が入っている場合`a`単一文字の部分文字列のみを共有する場合、どのソリューションでもその最小限の共有部分文字列を正しく検出する必要があります。 例えば：```
a = ["abc", "bca", "cab"]
```一般的な部分文字列は 1 文字のみであり、すべての文字列にわたって部分文字列が正しく交差しないと、候補が不正確になります。 

もう 1 つのエッジケースは、すべての文字列にわたって部分文字列が共有されていない場合です。`a`、 例えば：```
a = ["ab", "cd"]
```正しい答えは、`-1 -1`、少なくとも 1 つの共通文字を前提とするアルゴリズムは、何かを誤って出力する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべての文字列のすべての部分文字列を生成することから始まります。`a`、次に各部分文字列が他のすべての文字列に出現するかどうかを確認します。`a`。 存在する場合、次に含まれる文字列の数を計算します。`b`それを含んでください。 これは概念的には正しいですが、運用上は悲惨です。 長さ 500 の 1 つの文字列にはすでに約 125,000 の部分文字列が含まれており、最大 50,000 の文字列にわたってメンバーシップ チェックを実行すると、この値は許容範囲をはるかに超えて増加します。 

重要な観察は、実際には候補ごとに部分文字列を追跡する必要がないということです。 代わりに、視点を反転することができます。 すべての文字列に現れる部分文字列が必要です。`a`したがって、各文字列を個別に処理し、その個別の部分文字列をすべて抽出し、各部分文字列が含まれる文字列の数をカウントできます。 これにより、「グローバル交差」問題がセット全体の頻度カウント問題に変わります。 

各部分文字列の頻度がわかったら、`a`、有効な候補は、頻度が文字列の数と正確に等しいものです。`a`。 同じ種類の周波数を同時に計算できます。`b`文字列を使用することで、2 番目の最適化基準を効率的に評価できるようになります。 

これが機能するのは、入力の合計長に対する制約により、各文字列内の部分文字列の重複を排除する限り、すべての文字列にわたるすべての部分文字列の列挙が確実に実行可能であるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N · L³) | O(N · L²) | 遅すぎる |
 | ハッシュを使用した部分文字列の頻度 | O(合計 L²) | O(合計 L²) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 部分文字列を比較可能な形式で表現します

 各部分文字列をコンパクトなキーとして保存できるように、部分文字列のローリング ハッシュを計算します。 これにより、生の文字列を繰り返し保存することが回避され、比較の効率が維持されます。 

### 2. の各文字列を処理します。`a`の各文字列に対して`a`、すべての部分文字列を列挙しますが、同じ文字列内の重複によってカウントが膨らまないよう、それらをセットに保存します。 1 つの文字列を処理した後、グローバル マップを更新します`cntA[sub]`これは、この部分文字列が出現する異なる文字列の数を追跡します。 

条件は「全体で何度も出現する」ではなく「すべての文字列に出現する」であるため、このステップは必須です。 

### 3. 同じプロセスを繰り返します。`b`再度、文字列ごとに部分文字列を列挙します。`b`、各文字列内で重複を排除し、維持します。`cntB[sub]`の文字列の数を数えます。`b`部分文字列が表示されます。 

### 4. 有効な候補者をフィルタリングする

 にあるすべての部分文字列を反復処理します。`cntA`。 部分文字列は次の場合にのみ有効です。`cntA[sub] == n`、すべての文字列に出現することを意味します。`a`。 

### 5. 最も有効な部分文字列を選択する

 有効な部分文字列の中から、最小化するものを選択します。`cntB[sub]`。 同点の場合は、最小の部分文字列長が選択されます。 

### なぜ効果があるのか

 このアルゴリズムは直接等価性に依存しています。つまり、部分文字列がすべての文字列に出現します。`a`文字列ごとの部分文字列セット全体で文字列ごとに 1 回カウントされる場合に限ります。 各文字列内で重複を排除することで、頻度の解釈の正確さが保証されます。 すべての候補は集計後に 1 回だけ評価されるため、正確性を維持しながら、コストのかかるチェックを繰り返すことを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_counts(strings):
    MOD1 = 10**9 + 7
    MOD2 = 10**9 + 9
    BASE = 91138233

    cnt = {}

    for s in strings:
        seen = set()
        n = len(s)

        for i in range(n):
            h1 = 0
            h2 = 0
            for j in range(i, n):
                c = ord(s[j])
                h1 = (h1 * BASE + c) % MOD1
                h2 = (h2 * BASE + c) % MOD2
                seen.add((h1, h2, j - i + 1))

        for key in seen:
            cnt[key] = cnt.get(key, 0) + 1

    return cnt

def build_b_counts(strings):
    MOD1 = 10**9 + 7
    MOD2 = 10**9 + 9
    BASE = 91138233

    cnt = {}

    for s in strings:
        seen = set()
        n = len(s)

        for i in range(n):
            h1 = 0
            h2 = 0
            for j in range(i, n):
                c = ord(s[j])
                h1 = (h1 * BASE + c) % MOD1
                h2 = (h2 * BASE + c) % MOD2
                seen.add((h1, h2, j - i + 1))

        for key in seen:
            cnt[key] = cnt.get(key, 0) + 1

    return cnt

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = [input().strip() for _ in range(n)]
        m = int(input())
        b = [input().strip() for _ in range(m)]

        cntA = build_counts(a)
        cntB = build_b_counts(b)

        best_b = None
        best_len = None

        for (h1, h2, ln), c in cntA.items():
            if c == n:
                cb = cntB.get((h1, h2, ln), 0)
                if best_b is None or cb < best_b or (cb == best_b and ln < best_len):
                    best_b = cb
                    best_len = ln

        if best_b is None:
            print("-1 -1")
        else:
            print(best_b, best_len)

if __name__ == "__main__":
    solve()
```この実装は、2 つの対称前処理関数を中心に構造化されています。`a`そして1つは`b`。 各関数は文字列ごとに部分文字列を列挙しますが、重要なのは文字列ごとの`seen`同じ文字列内で繰り返し出現しても頻度カウントが歪められないように設定します。 

各部分文字列は、二重ローリング ハッシュとその長さで表されます。 この長さは、縮退の場合にハッシュ ペアを共有する可能性がある異なる部分文字列間の偶発的な衝突を避けるために含まれます。 

前処理の後、ソルバーは、次のすべての文字列にわたって有効な部分文字列のみをスキャンします。`a`から事前に計算されたカウントを使用してそれらを評価します。`b`。

 ## 特殊なケース

 重大なエッジ ケースの 1 つは、すべての文字列にわたって部分文字列が共有されていない場合です。`a`。 キーが入力されていないため、アルゴリズムはこれを自然に処理します。`cntA`周波数に達する`n`、出発`best_b`設定を解除して正しく戻す`-1 -1`。 

もう 1 つのケースは、単一文字の部分文字列のみが有効な場合です。 各文字列は独自の重複排除された部分文字列セットに寄与するため、アルゴリズムは依然として文字列ごとの出現回数を正確にカウントし、頻度の等価性が共有文字を正確にキャプチャすることを保証します。 

最後に、複数の部分文字列が同じ最良のカウントに達すると、`b`、最後の比較では頻度とともに長さを明示的に追跡するため、長さによるタイブレークにより最小の部分文字列の決定論的な選択が保証されます。
