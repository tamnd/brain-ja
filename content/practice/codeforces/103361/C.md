 ## 解決策
 ## 問題の理解

 辺の長さが整数の長方形のボードが与えられます。 タスクは、グリッド線に沿って切断して、この長方形を小さな正方形に分割することです。 各カットでは、1 つの既存の長方形が 2 つの小さな長方形に分割され、最終的な目標は、元の長方形を正方形に完全に分解することです。 目的は、最終的な分解での正方形の数を最小限に抑えることです。 

このプロセスは、すべての部分が正方形になるまで、現在の長方形を繰り返し選択し、水平方向または垂直方向に切断して 2 つの小さな長方形を作成すると考えることができます。 出力は、最終的に得られる正方形の最小数です。 

このタイプの問題の制約では、通常、辺の長さは数百または数千程度まで許容されます。 長方形を再帰的に分割する方法の数は非常に急速に増加するため、すべての切断シーケンスの指数関数的な列挙は即座に除外されます。 各四角形は最大 O(n + m) 通りに分割でき、この分岐はすべてのサブ四角形で繰り返されるため、考えられるすべてのカット オーダーを試行する単純な強引な方法では、組み合わせが爆発的に増加します。 

長方形がすでに正方形である場合、微妙なエッジケースが表示されます。 たとえば、入力が 5 x 5 の場合、正解は 1 です。常に少なくとも 1 つのカットを実行する戦略では、誤ってより大きな値が返されます。 もう 1 つの重要なケースは、1 x n などの非常に歪んだ長方形です。 このような場合、有効な分解は 1 x 1 の正方形のみであり、単純で貪欲な水平または垂直分割戦略では、分割方法に応じて過大評価または過小評価する可能性があるため、最適な答えは正確に n になります。 

## アプローチ

 ブルートフォースアプローチでは、問題を直接モデル化します。 サイズ a × b の長方形の場合、位置 i で可能なすべての垂直方向のカットを試みて、長方形 i × b および (a − i) × b を生成し、位置 j ですべての水平方向のカットを試みて、a × j および a × (b − j) を生成します。 結果のペアごとに、正方形の最小数を再帰的に計算し、結果を結合します。 長方形の答えは、すべての選択肢の最小値になります。 

このアプローチは、考えられるカットのシーケンスをすべて探索するので正しいですが、各四角形が O(a + b) の遷移を生成し、それぞれがさらなる再帰につながるため、失敗します。 メモ化しても状態空間は O(a・b) ですが、各状態では依然として O(a + b) 個の遷移をスキャンする必要があるため、O(a・b・(a + b)) 周りの複雑さが生じます。 a = b = 500 の場合、これはすでに 500 回の演算のオーダーに達しており、一般的な制限には遅すぎます。 

重要な観察は、問題には最適な部分構造があるということです。最初のカットを修正すると、結果として得られる 2 つの長方形は独立した部分問題になります。 これは、動的プログラミングで十分であり、各四角形サイズに対する最適な答えを保存するだけでよいことを意味します。 再計算する代わりに、dp[a][b] を a × b の長方形をタイル状に並べるのに必要な最小正方形数として定義します。 すべてのトランジションでは、1 つのカットに沿った分割とサブ結果の結合のみが考慮されます。 

また、dp[a][b] が dp[b][a] に等しいため、対称性によって状態空間を縮小し、a ≤ b のみを計算できるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰 | O(n・m・(n + m)) | O(n・m) | 遅すぎる |
 | 長方形上の DP | O(n・m・(n + m)) 枝刈り/対称あり | O(n・m) | 承認済み |

 本当の利点は、遷移の漸近的な改善ではなく、対称性による反復的な再計算と枝刈りの排除であり、これにより状態空間が管理可能になります。 

## アルゴリズムのチュートリアル

 dp[a][b] に a × b の長方形をタイル状に並べるのに必要な最小数の正方形が格納されるテーブル dp を定義します。

1. dp[a][b] をすべての a、b に対して大きな値に初期化します。 これは、その四角形サイズの解をまだ計算していないことを表します。 
2. すべての長方形について、まずそれがすでに正方形であるかどうかを確認します。 a が b と等しい場合は、dp[a][b] を 1 に設定します。カットは必要ないため、これが基本ケースです。 
3. 正方形ではない長方形ごとに、考えられるすべての垂直方向のカットを試します。 位置 i でのカットの場合、長方形は i × b と (a − i) × b に分割されます。 この分割のコストは dp[i][b] + dp[a − i][b] です。 このようなすべての分割の最小値で dp[a][b] を更新します。 
4. 同様に、位置 j ですべての水平カットを試します。 これは、a by j と a by (b − j) に分割され、dp[a][j] + dp[a][b − j] に寄与します。 再び最小値を取ります。 
5. dp 値にアクセスするときは、常に以前に計算された状態または対称状態に依存するようにします。そのため、通常は a を 1 から n まで、b を 1 から m まで昇順に反復することにより、小さな四角形が大きな四角形よりも先に解決されます。 

テーブルを昇順に埋めることができる理由は、カットによって少なくとも 1 つの次元が厳密に削減されるため、部分問題は常に、すでに計算されたより小さいか等しい次元を参照するためです。 

### なぜ効果があるのか

 正確さは、長方形の最適なタイリングは最初のカットから開始する必要があるという事実に基づいています (すでに正方形である場合を除く)。 まず、問題を 2 つの独立した長方形に分割します。 最適なソリューションでは、可能な限り最良の最初のカットを選択し、結果として得られる各長方形を最適に解決する必要があります。 dp は、考えられるすべての最初のカットを列挙し、部分長方形に最適な部分構造を使用するため、より良い分解を見逃すことはできません。 このテーブルは、大規模な計算で使用される前にすべての部分問題が最適に解決されることを保証し、最適ではない部分解の伝播を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    
    for a in range(1, n + 1):
        for b in range(1, m + 1):
            if a == b:
                dp[a][b] = 1
                continue
            
            best = float('inf')
            
            for i in range(1, a // 2 + 1):
                best = min(best, dp[i][b] + dp[a - i][b])
            
            for j in range(1, b // 2 + 1):
                best = min(best, dp[a][j] + dp[a][b - j])
            
            dp[a][b] = best
    
    print(dp[n][m])

if __name__ == "__main__":
    solve()
```この実装では、小さな四角形から大きな四角形まで 2 次元の DP テーブルを構築します。 i および a − i での分割は a − i および i での分割と対称であるため、ループは次元の半分までしか進みません。そのため、冗長な計算が回避されます。 正方形のセルを初期化すると、正しい塩基伝播が保証されます。 最終的な答えは dp[n][m] です。 

ここでよくある間違いは、半分ではなく全範囲にわたってカットを繰り返すことです。これにより、正確さを変えることなく作業が 2 倍になります。 もう 1 つの微妙な点は、より小さい次元がすべて利用可能になった後にのみ dp[a][b] が計算されるようにすることです。これは、ループの次数を増やすことで保証されます。 

## 実用的な例

 2 x 3 の長方形を考えてみましょう。 dp を昇順に計算します。 

| 長方形 (a, b) | タイプ | 検討中の削減 | dp値 |
 | --- | --- | --- | --- |
 | (1,1) | 正方形 | なし | 1 |
 | (1,2) | 非正方形 | 縦方向のみ | 2 |
 | (2,2) | 正方形 | なし | 1 |
 | (1,3) | 非正方形 | 縦方向のみ | 3 |
 | (2,3) | 非正方形 | 縦+横 | 3 |

 (2,3) の場合、垂直方向のカットでは (1,3)+(1,3)=6 が得られ、1 での水平方向のカットでは (2,1)+(2,2)=2+1=3 が得られるため、dp[2][3]=3 となります。 

このトレースは、DP がどのように単純な分割を回避し、均等な分割ではなく最適な部分構造に合わせた分解を正しく選択するかを示しています。 

次に、3 × 3 の長方形について考えてみましょう。 すでに正方形であるため、カットの考慮に関係なく、直ちに dp[3][3] = 1 になります。 これは、基本ケースが不要な再帰をオーバーライドすることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・m・(n + m)) | 各長方形について、最大 n 個の水平分割と m 個の垂直分割を試み、各 O(1) 遷移 |
 | スペース | O(n・m) | DP テーブルには、長方形のサイズごとに 1 つの値が格納されます。 

この複雑さは、n と m が数百までの中程度の制約では許容されます。 対称性の削減により定数係数が効果的に半分になり、反復構造により再帰オーバーヘッドがなくなりました。

 ## 特殊なケース

 1 × n の長方形の場合、アルゴリズムは垂直方向の分割のみを繰り返し考慮します。 正方形を形成する唯一の方法は 1 x 1 の部分に分割することであるため、各 dp[1][k] は k に解決されます。 すべての分割がより小さな 1 x x 状態に減少し、最終的には 1 x 1 の基本ケースに到達するため、DP テーブルはこれを正しく累積します。 

7 x 7 などの正方形の入力の場合、アルゴリズムはカットが考慮される前に直ちに dp[7][7] = 1 を割り当てます。 技術的にはループでカットを評価できますが、ガード条件により基本ケースの上書きが防止され、誤った分解が導入されないことが保証されます。
