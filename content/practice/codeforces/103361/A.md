 ## 解決策
 ## 問題の理解

 私たちには、2 つの瞬間と 2 つの期間を含む 1 日のスケジュールが与えられています。 まず、旅行者がいつ家を出発するかを時間と分で表します。 その瞬間から、ナビゲーション システムは空港までの移動時間が固定の分数であると表示します。 それとは別に、飛行機の出発時刻と、チェックインデスクが出発の何分前に閉まるかがわかります。 乗客はチェックイン終了時間までに必ず到着する必要があります。つまり、締め切り時間ちょうどに到着しても失敗とみなされます。 

このタスクは、出発時間と移動時間を加算して計算した到着時間が、フライトの出発時間からチェックインのリードタイムを引いて計算した許容可能な最終チェックイン時刻よりも厳密に早いかどうかを判断することです。 

重要な点は、すべての時間が 1 日以内に存在し、分単位で一貫して比較する必要があることです。 これは複数日にわたるシミュレーションではなく、すべてを均一な単位に変換した後の単一の線形比較です。 

制約は小さく、時間はおよそ 9 時から 21 時までの間に制限され、継続時間は最大 60 分です。 これにより、時間を変換し、定数時間の演算を実行するソリューションであればどれでも十分であることがすぐにわかります。 検索、並べ替え、または重要なデータ構造は必要ありません。 強引な分ごとのシミュレーションでも許容されますが、その必要はありません。 

よくある失敗例は、厳密な不等式条件の誤解から生じます。 

たとえば、旅行者がチェックイン期限ぴったりに到着したとします。 

入力:

 9 0 10 9 10 10

 出発は9:00、所要時間は10分なので到着は9:10です。 フライトは 9:10 で、チェックインは 10 分前、つまり 9:00 に終了します。 到着は締切後なので、答えは「CHANGE TICKET」です。 

もう一つの微妙なケース:

 入力:

 10 0 50 15 30 45

 到着は10時50分です。 フライトは15:30、チェックインは14:45に終了します。 到着が早いので、答えは「OK」です。 ここでの罠は、時間の境界を超えて分を正しく減算することです。 

最もよくある間違いは、正規化を行わずに時間を時と分の別々の計算として扱うことであり、減算が時間の境界を越えると中断されてしまいます。 

## アプローチ

 ブルートフォース解釈では、出発時刻から 1 分ごとにシミュレーションし、移動時間を追加し、チェックイン終了までのカウントダウンを個別にシミュレートします。 両方の瞬間を細かい配列に変換し、エンドポイントに到達するまで増分することができます。 これは時間範囲が狭いため機能しますが、不必要なオーバーヘッドになります。 最悪の場合でも、処理できるのは数千分だけなので、これは正しいですが、洗練されていません。 

より良いアプローチは、すべての時間を午前 0 時からの絶対分に正規化することです。 すべてが 1 つの線形スケールに収まると、問題は 1 つの比較に集約されます。 

次のように計算します。 

- 到着時刻 = (h1 * 60 + m1) + t1
 - last_checkin_time = (h2 * 60 + m2) - t2

 残る唯一の条件は厳密な不等式です。 

到着時刻 < 最終チェックイン時刻

 これにより、すべての複雑さが取り除かれ、問題が定数時間の演算に簡素化されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(T) ただし、T ≤ 1440 | お(1) | 受け入れられるが不要 |
 | 時間の正規化 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. h1 * 60 + m1 を計算して、出発時刻を午前 0 時からの合計分数に変換します。 これにより、旅行者が出発するときの単一のスカラー値が得られます。 
2. 移動時間 t1 を追加して、空港への到着時間を分単位で計算します。 これは、時間の境界を扱うことなく、連続的な時間の進行をモデル化します。 
3. h2 * 60 + m2 を使用して、フライトの出発時間を午前 0 時からの合計分数に変換します。 これは航空会社のスケジュールの基準点となります。 
4. フライトの出発時刻から、必要なチェックイン リード タイム t2 を減算します。 これにより、乗客がチェックインを完了できる最後の有効な時間が得られます。 
5. 厳密な不等式を使用して、delivery_time と last_checkin_time を比較します。 到着時刻が厳密に小さい場合は、「OK」を出力します。 それ以外の場合は「CHANGE TICKET」を出力します。 

### なぜ効果があるのか

 両方の計算値は、午前 0 時からの分単位で測定された同じ直線軸上の絶対時間位置を表します。 変換はクロック時間から整数への厳密に単調なマッピングであるため、順序が維持されます。 要件は、あるイベントが別のイベントの前に厳密に発生するかどうかだけであるため、追加の構造は必要ありません。 正しい答えはこの順序のみに依存する必要があるため、問題を整数比較に縮小するだけで必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

h1, m1, t1, h2, m2, t2 = map(int, input().split())

arrival = h1 * 60 + m1 + t1
deadline = h2 * 60 + m2 - t2

if arrival < deadline:
    print("OK")
else:
    print("CHANGE TICKET")
```実装はアルゴリズムに直接に従います。 唯一重要な点は、演算を行う前に一貫して分数に変換することです。 これにより、時間の境界を越えて分が手動で運ばれることによるエラーが回避されます。 

厳密な不等式は必要に応じて正確に実装されます。正確な終了時刻に到達しても登録を完了できないため、等号は失敗として扱われます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    h1, m1, t1, h2, m2, t2 = map(int, input().split())

    arrival = h1 * 60 + m1 + t1
    deadline = h2 * 60 + m2 - t2

    return "OK\n" if arrival < deadline else "CHANGE TICKET\n"
