 ## 解決策
 ## 問題の理解

 頂点が湖、端が湖から湖へ流れる川である有向グラフが与えられます。 この構造は非常に制約があり、各湖には流入する川が最大 1 つ、流出する川が最大 2 つあり、方向性のあるサイクルがないため、水は常に一定の方向に下り坂に移動します。 

ラフティングの旅は、川が流れ込んでいない湖から始まります。 そこから、複数の川が流れ出ている湖にラフトが到達するたびに、利用可能な選択肢の中から次の川が均一にランダムに選択されます。 このプロセスは、いかだが流れ出る川のない湖に到着するまで続き、そこが最終目的地となります。 

タスクは、一様にランダムなソース湖から開始し、説明されたランダムな選択に従う場合に、どの終端湖が最終停止点になる可能性が最も高いかを判断することです。 複数の末端湖が同じ最大確率を共有する場合、インデックスが最小のものを出力する必要があります。 

この制約は、最大 200,000 のノードとエッジを含むグラフを暗黙的に示しているため、どのソリューションも基本的にグラフのサイズが線形である必要があります。 パスを明示的にシミュレートしたり、開始ノードごとに独立して確率を再計算しようとするアルゴリズムは、制限内では存続できません。 構造も重要です。入次数が最大 1 ということは、すべてのノードが 1 つのツリー状コンポーネントに属することを意味するため、グラフは下向きの有向ツリーのフォレストになります。 

いくつかの特殊なケースについては、明示する価値があります。 

川がまったく存在しない場合、すべての湖は同時に出発湖であると同時に終着湖でもあります。 たとえば、n = 3 および m = 0 の場合、3 つの湖はすべて有効な開始点であり、それぞれが停止点でもあるため、それぞれが選択される確率は 1/3 になります。 

グラフが 1 → 2 → 3 → 4 のような連鎖を形成している場合、ソース (1) とシンク (4) は 1 つだけであるため、答えは自明に 4 になります。 

1 → 2、1 → 3 などの分岐が発生し、2 と 3 の両方が異なるシンクにつながる場合、確率は分割され、異なるパスに沿って蓄積されます。 共有プレフィックス確率を正しく伝播せずにパスを独立して扱う単純なアプローチでは、寄与が過大評価または過少評価されます。 

## アプローチ

 プロセスの直接シミュレーションでは、開始レイクを繰り返し選択し、シンクに到達するまでランダムな遷移をシミュレートします。 最悪の場合、単一のシミュレーションでも O(n) がかかる可能性があり、確率を正確に推定するには非常に多くの実行回数が必要になります。 これは、n が 2 · 10^5 までの範囲をはるかに超えています。 

より構造化されたブルート フォース アプローチは、すべての分岐点で確率を均等に分割する DFS または BFS を実行することにより、ソースごとにシンク全体の完全な確率分布を計算することです。 これはランダム ウォークを正しくモデル化しますが、すべてのソースに対してこれを繰り返すと、大規模な共有サブツリーが再計算されます。 グラフが単一のツリー状構造である最悪のケースでは、これは O(n^2) になります。 

重要な観察は、プロセスが非常に単純な方法で線形かつマルコフ的であるということです。 ノードに到達する確率がわかれば、過去を振り返ることなく、その確率をその子に分配することができます。 各ノードには親が 1 つだけあるため、確率フローは異なる親からマージされることはなく、下方向にのみ分割されます。 これにより、すべてのソースから同時に開始されるシングルパス伝播が可能になります。 

すべてのソース ノードに等しい初期確率を割り当て、その後、確率をエッジに沿って前進させ、発信エッジ間で均等に分割します。 各シンクは、そこに到達する確率質量の合計を単純に蓄積します。 最良のシンクは、最大の蓄積質量を持つシンクです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ソースごとの総当たり攻撃 | O(n^2) | O(n) | 遅すぎる |
 | 順方向確率伝播 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 確率をソース ノードから始まりグラフ内を下に移動するフローとして扱います。 

1. 入力エッジがゼロのすべてのノードを特定します。 これらは可能な開始湖です。 それらを k と数えます。 このような各ノードに 1/k の初期確率を割り当てます。 これは、開始点の一様ランダムな選択を反映しています。 
2. 流出河川の隣接リストを構築し、源を検出するための次数を計算します。 これにより、シングルパス伝播のための構造が準備されます。 
3. 配列 p を初期化します。ここで、p[v] はいかだが v 湖に到着する確率を表します。すべてのソースに対して p[source] = 1/k を設定し、他のすべてのノードに対して 0 を設定します。 
4. トポロジ順にノードを処理します。 各ノードには最大でも 1 つの入力エッジがあるため、子の前に親を尊重する任意の順序で単純に反復処理することもできます。これは、ソースからの BFS/キューによって自然に実現されます。 
5. 各ノード u について、その確率質量をその出力エッジ間で均等に分配します。 u に d 個の出力エッジがある場合、各子 v は p[v] += p[u] / d を受け取ります。 これは、各分岐における一様なランダムな選択をモデル化します。 
6. u に出力エッジがない場合、それはシンクであるため、そこからさらに伝播しません。 
7. 伝播が完了したら、すべてのノードをスキャンし、発信エッジがないノードを見つけます。 その中で、p 値が最大のノードを選択します。 同点の場合は、最小のインデックスを選択します。 

### なぜ効果があるのか

 すべてのノードには 1 つのソースからの一意のパスがあるため、このプロセスは線形です。そのため、ノードに到着する確率は、そのソースの初期質量とパスに沿った分割の順序によって完全に決まります。 確率は分割するだけで結合することはないため、独立した情報源からの寄与を合計することは有効です。 伝播ルールはすべてのステップで確率質量の合計を保存し、ソースに注入されたすべての確率が損失や重複なく最終的にシンクに到達することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
g = [[] for _ in range(n)]
indeg = [0] * n
outdeg = [0] * n

for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    indeg[v] += 1
    outdeg[u] += 1

sources = [i for i in range(n) if indeg[i] == 0]
k = len(sources)

p = [0.0] * n
if k > 0:
    init = 1.0 / k
    for s in sources:
        p[s] = init

from collections import deque
q = deque(sources)

while q:
    u = q.popleft()
    if outdeg[u] == 0:
        continue
    share = p[u] / outdeg[u]
    for v in g[u]:
        p[v] += share
        q.append(v)

best = -1
best_p = -1.0

for i in range(n):
    if outdeg[i] == 0:
        if p[i] > best_p or (abs(p[i] - best_p) < 1e-15 and i < best):
            best_p = p[i]
            best = i

print(best + 1)
```この解決策は、隣接リストを構築し、すべての有効な開始レイクを識別するための度数を計算することから始まります。 確率配列は、それぞれが等しい質量を受信するソース上でのみ初期化されます。 キューはトポロジカル トラバーサルと同様の順方向伝播を駆動し、各ノードの確率が出力エッジを通じて正確に 1 回分散されるようにします。 

実装の微妙な点は、単純な BFS スタイルのプッシュではノードが複数回キューに入れられる可能性があることですが、正確性については処理順序には依存しておらず、最終的な完全な伝播のみに依存しているため、正確性は損なわれません。 各更新は追加的であるため、エンキューを繰り返すと、累積された確率が配布され続けるだけです。 これにより、厳密なトポロジのソートが不要になります。 

確率には制限があり、最終値のみを比較するため、ここでは浮動小数点演算で十分です。 タイブレーク ルールは、イプシロン比較を使用して明示的に処理されます。 

## 実用的な例

 小さなグラフを考えてみましょう。 

入力:```
4 3
1 2
1 3
2 4
```ここで、ノード 1 のみが次数 0 であるため、ソースは {1} です。p(1) = 1 から始めます。 

伝播を追跡します。 

| ステップ | ノード | p[ノード] | アクション |
 | --- | --- | --- | --- |
 | 初期化 | 1 | 1.0 | ソースから開始 |
 | 1 | 1 | 1.0 | 2 と 3 に分割 |
 | 2 | 2 | 0.5 | 半分を受け取る |
 | 3 | 3 | 0.5 | 半分を受け取る |
 | 4 | 2→4 | 0.5 | 2 を 4 に分割 |
 | 最終 | 4 | 0.5 | シンク確率 |

 ノード 3 は確率 0.5 のシンクであり、ノード 4 も確率 0.5 のシンクです。 同点であるため、インデックスが小さい方が勝つため、3 が選択されます。 

このトレースは、確率が分岐ノードでどのように分割され、シンクで蓄積されるかを示しています。 

次に、複数のソースを持つチェーンを考えてみましょう。 

入力:```
3 1
1 3
```ソースは {1, 2} であるため、それぞれの確率は 1/2 になります。 ノード 2 自体はシンクであるため、すぐに 1/2 に寄与します。 ノード 1 はその 1/2 をノード 3 に渡すため、ノード 3 も 1/2 を取得します。 

両方のシンクの確率は同じであり、そのうちの小さいインデックスが選択されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各エッジは伝播中に確率を 1 回処理します。 
| スペース | O(n + m) | 隣接リストと確率と次数の配列 |

 このアルゴリズムは、各ノードとエッジを一定の回数だけ処理します。これは、n、m の制限内に快適に収まり、最大 2 · 10^5 になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n
    outdeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        indeg[v] += 1
        outdeg[u] += 1

    sources = [i for i in range(n) if indeg[i] == 0]
    k = len(sources)

    p = [0.0] * n
    if k > 0:
        init = 1.0 / k
        for s in sources:
            p[s] = init

    from collections import deque
    q = deque(sources)

    while q:
        u = q.popleft()
        if outdeg[u] == 0:
            continue
        share = p[u] / outdeg[u]
        for v in g[u]:
            p[v] += share
            q.append(v)

    best = -1
    best_p = -1.0
    for i in range(n):
        if outdeg[i] == 0:
            if p[i] > best_p or (abs(p[i] - best_p) < 1e-15 and i < best):
                best_p = p[i]
                best = i

    return str(best + 1)

## 特殊なケース

 エッジがない場合、すべてのノードは同時にソースでもありシンクでもあります。 この場合、初期化によって確率 1/n がすべてのノードに割り当てられ、伝播が起こらないため、すべてのノードは等しい確率を保ちます。 アルゴリズムは最小のインデックスを正しく選択します。 

グラフが純粋なチェーンの場合、最後のノードを除く各ノードには出力エッジが 1 つだけあるため、分割は発生しません。 確率はランダム開始分布から一意のシンクまで完全に流れ、総質量が維持され、単一の答えが生成されます。 

1 → 2 や 1 → 3 などの分岐がソースで発生すると、アルゴリズムは確率を即座に分割し、両方の分岐を独立して追跡します。 次数制約のためマージは不可能であるため、累積された値は互いに素で加算されたままとなり、正しいシンク確率が保証されます。
