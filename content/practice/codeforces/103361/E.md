 ## 解決策
 ## 問題の理解

 この問題は、繰り返し行われる数値の割り算を中心に構築された 2 人用ゲームについて説明しています。 複数の整数セットから開始し、プレイヤーは順番に数値を選択し、ゲームの固定ルールに従って適切な約数の 1 つに置き換えます。 数字が選択されると、動きの構造は決定的になるため、ゲーム全体は、与えられた構成から有効な手がどれだけ存在するか、そしてすべてが分割できなくなるまで分割の連鎖をどのくらい長く強制できるかを理解することに帰着します。 

各テスト ケースは、値の初期コレクションを提供します。 このコレクションから、移動は、1 より大きい要素を 1 つ選択し、それを厳密に小さい正の除数に置き換えることで構成されます。 これ以上要素を減らすことができない場合、つまりすべての要素が 1 つになるか、ルール内に収める法的約数がなくなるとゲームは終了します。 

出力は、入力内のすべての数値にわたるこれらの分割チェーンの構造の評価に依存します。 各整数は、何回分解できるかという点で独立して寄与しますが、グローバルな相互作用は、これらの寄与が遊びのルールの下でどのように組み合わされるかによって生じます。 

制約 (約数の問題に典型的な最大の値、多くの場合最大 10^7 以上、および多くのテスト ケース) により、手ごとに約数を列挙したり、ゲームプレイを段階的にシミュレートしたりすることは実行不可能であることがすぐにわかります。 単純なシミュレーションでは、繰り返し数値を因数分解したり、約数を検索したりするため、すべての状態の除算の合計数に比例する最悪のケースの動作が発生し、二次次またはさらに悪化する可能性があります。 

いくつかの特殊なケースで構造が明らかになります。 

配列に 1 つだけが含まれる場合、たとえば入力`n = 3, [1, 1, 1]`、動きはないので、答えは自明のことながらゼロです。 ここでも単純なシミュレーションは機能しますが、不必要なループに堕してしまいます。 

配列に次のような素数が含まれている場合、`[7]`、7 は 1 にしかならないため、可能なリダクション ステップは 1 つだけです。複数の約数を仮定したり、任意の係数を介して貪欲にリダクションしようとする間違ったアプローチでは、カウントがオーバーカウントされる可能性があります。 

配列に次のような繰り返しの複合が含まれている場合、`[8, 8, 8]`単純なステップごとのシミュレーションでは、たとえ構造の反復性が高く、再利用する必要がある場合でも、除数構造が繰り返し再計算され、時間の爆発につながる可能性があります。 

重要な問題は、同じ数字が繰り返され、その約数の深さが固定されており、ゲームの順序とは無関係であるため、構造を動的に再計算するソリューションは過剰であるということです。 

## アプローチ

 ブルートフォース解釈では、ゲームを文字通りに扱います。 各ステップで、配列をスキャンし、すべての有効な要素を選択し、すべての約数を計算し、すべての可能な遷移をシミュレートします。 どの合成数が選択されたかに応じて、各合成数が複数の次の状態を生成する可能性があるため、これは大きく分岐します。 ゲームの状態を調査する代わりに手を数えることに限定したとしても、数値を繰り返し因数分解する必要があります。 

単一の数値 x の場合、試行除算による因数分解には O(√x) のコストがかかります。 これをすべての動きとすべての数値に対して実行し、最悪の場合、各数値が何度も減らされると、総作業量は √x のすべての状態の合計に比例し、大きな入力では許容範囲をはるかに超えます。 

重要な観察は、ゲームは分岐の意味で各ステップでどの除数が選択されるかに依存しないということです。 代わりに、各数値には固定の「分割の深さ」があり、最適なプレイまたは強制的なプレイの下で 1 に達するまでに減らすことができる回数です。 その深さは素因数分解のみに依存します。 

数字が次のように書かれている場合

 x = p1^a1 · p2^a2 · ... · pk^ak,

 この場合、各移動は、何らかの分解スキームで 1 つの指数を 1 単位ずつ効果的に削減します。 可能な削減の合計数は、指数の合計に関連付けられます。 これにより、問題は動的なゲームから素数累乗をめぐる静的な計数問題に変換されます。 

動きをシミュレートする代わりに、各数値の指数の合計を事前計算します。これは、すべての要素にわたって素数を何回「分割」できるかを数えるのと同じです。 これが計算されると、ゲームは配列全体の寄与を合計することになります。 

したがって、私たちは手ごとのシミュレーションから数字ごとの因子分析に移行し、ゲームプレイの分岐から決定論的な算術構造に移行します。

 ## アルゴリズムのチュートリアル

 各数値を素因数表現に再定式化し、その数値に多重度で含まれる素因数の数を数えます。 

1. 入力内の各数値 x を素因数分解します。 これは、√x までの除算を試行するか、制約が許す場合は事前に計算された最小素因数ふるいを使用して行います。 このステップが必要なのは、すべての有効な移動が、ある数値から素数べき乗の 1 単位を削除することに相当するためです。 
2. すべての要素にわたる素因数の数を累積する累計を維持します。 12 = 2^2 · 3^1 のような数値の場合、素数単位が 3 つ含まれるため、寄与は 3 になります。 
3. すべての数値に対するこれらの寄与を合計します。 各演算はマルチセット全体で 1 つの素指数を正確に削減するため、この合計はシステム全体で可能な有効な削減演算の数を表します。 
4. この合計を最終的な答えとして返します。 

唯一の微妙な点は、因数分解で多重度が正しくカウントされるようにすることです。 たとえば、2 による除算を繰り返す場合は、8 を単一の要因イベントとして扱うのではなく、複数回カウントする必要があります。 

これが機能する理由: 有効な各移動は、正確に 1 つの要素から 1 つの素因数の出現を削除することに対応します。 新しい素因数を作成したり、多重度の削減をスキップしたりする移動はありません。そのため、すべてのシーケンスにわたって可能な移動の総数は固定されており、マルチセット内の素因数の総数に等しくなります。 この不変式は、演算の順序に関係なく安定しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factor_count(x: int) -> int:
    cnt = 0
    d = 2
    while d * d <= x:
        while x % d == 0:
            cnt += 1
            x //= d
        d += 1
    if x > 1:
        cnt += 1
    return cnt

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    ans = 0
    for x in arr:
        if x > 1:
            ans += factor_count(x)
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、ロジックが透過的な状態を維持できるように、因子カウントをヘルパー関数に分離します。 内側のループは同じ素数を繰り返し分割します。これは、2^k などの多重度を正しく処理するために必要です。 外側のループは、要素間の相互作用を行わずに結果を集約し、寄与の独立性を反映します。 

よくある落とし穴は、最初の約数が見つかった後に停止することです。 これにより、12 のような数値が 3 つの因数ではなく 2 つの因数のみとして誤って処理されてしまいます。 もう 1 つの問題は、残りの処理を忘れることです。`x > 1`ループ後のケースで、大きなプライムレムナントをキャプチャします。

import sys, io

    sys.stdin = io.StringIO(inp)
    import builtins

        cnt = 0
        d = 2
        while d * d <= x:

                cnt += 1

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が 1 である場合です。その場合、因子カウント ループは寄与せず、結果は 0 のままになります。 因数関数はループに入らずに x = 1 に対してすぐに 0 を返すため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、999983 などの大きな素数です。ループは、d * d が x を超えるまで実行され、約数が見つからず、最後に残った x を単一の素因数としてカウントします。 これにより、1 の正しい寄与が保証されます。 

3 番目のケースは、2^20 のような反復累乗です。 内側の while ループは x を 2 で繰り返し除算し、そのたびにカウントをインクリメントするため、寄与は 1 ではなく 20 になり、繰り返しのリダクションの意図した解釈と一致します。
