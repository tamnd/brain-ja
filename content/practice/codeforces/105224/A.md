 ## 解決策
 ## 問題の理解

 1 から n までの位置からなる 1 次元のボードが与えられます。 各位置 i にはジャンプ長 t[i] が含まれます。 ボールが位置 i にドロップされると、ボールは決定論的なジャンプを繰り返し実行します。つまり、i から i + t[i] に移動し、次にその新しい位置 j から j + t[j] に移動するというように、位置が n を超えるまで繰り返されます。 その瞬間、ボールはボードから出たものとみなされます。 

興味深いのは、配列が静的ではないことです。 2 つの操作をサポートする必要があります。 1 回の操作で 1 つのインデックスでのジャンプ長が変更されます。 もう 1 つは、指定されたインデックスから開始してジャンプ プロセス全体をシミュレートし、ボールがボードから離れる前にまだボード内にあった最後の位置と、ボードから出るまでに行われたジャンプの数という 2 つの値を報告するように求めます。 

制約 n と q は両方とも最大 100000 で、各ジャンプは配列に応じて遠くまで移動することも、小さくとどまる可能性もあります。 単一のクエリが多くの位置を横断する可能性があり、そのようなクエリが多数存在する可能性があるため、構造が敵対的である場合、クエリごとの直接シミュレーションは容易に二次動作に低下する可能性があります。 

単純な予想では、各クエリ タイプ 1 は最悪の場合 O(n) を要し、合計作業量は O(nq) になると考えられます。 100,000 回の操作では、これは実現可能な限界をはるかに超えています。 

微妙なエッジ ケースは、ジャンプが常に小さな領域内に留まる場合です。たとえば、すべての i に対して t[i] = 1 です。 位置 1 から開始して、n まで順番にすべての位置を訪問し、クエリごとに n ステップを生成します。 クエリが多数ある場合、これはすぐに遅くなりすぎます。 もう 1 つのエッジ ケースは、単一の値をシフトしてパスを完全に変更する頻繁な更新であり、慎重に構造化されていない限り、クエリ全体のメモ化の信頼性が低くなります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 i で始まるクエリの場合、範囲を出るまで現在の配列を使用して繰り返しジャンプします。 歩数をカウントし、最後に有効な位置を記憶します。 各更新では 1 つの値が変更されるだけです。 

これは文字通りプロセスの定義をシミュレートするため、正しく機能します。 問題は、最悪の場合、単一のクエリが O(n) 個の位置を通過する可能性があることです。 q が 100000 までの場合、最悪の場合の合計は O(nq) となり、大きすぎます。 

重要な観察は、各位置が遠くの位置にジャンプするか、小さなジャンプが繰り返されて予測どおりに動作する領域に留まるかのいずれかであるということです。 すべての中間ステップを個別にシミュレートすることは避けたいと考えています。 更新時にこのような「次のポインター ジャンプ」プロセスを加速する標準的な方法は、制御されたブロック構造内に留まる次の位置を位置ごとに維持し、その次の位置に到達するまでに必要なステップ数も維持することです。 

このためのよく知られた手法は、インデックスの sqrt 分解です。 配列を約 sqrt(n) のサイズのブロックに分割します。 各インデックスについて、現在のブロックを終了する場所と、終了するまでに必要なステップ数を事前計算します。 クエリを処理するときは、ステップごとではなくブロックごとに繰り返しジャンプします。 更新が発生すると、影響を受けるブロックのみが再計算されます。 

ブロック内ではジャンプが明示的にシミュレートされますが、各ブロックの走査はクエリ中に 1 つのジャンプに圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n)、更新 O(1) | O(n) | 遅すぎる |
 | ブロック分解 | クエリごとに O(√n)、更新は O(√n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックス 1 ～ n をサイズ B のブロック (通常は sqrt(n) 程度) に分割します。 各位置 i について、2 つの値を維持します。nxt[i]、ジャンプ規則に従って i のブロックを出た後の次の位置、および cnt[i]、nxt[i] に到達するかブロックを出るために必要なジャンプの数です。

1. ブロックを構築し、nxt と cnt を右から左に初期化します。 i を計算するときに、i + t[i] の結果が同じブロック内にあるか、ブロック外にあるかがすでにわかるようにインデックスを処理します。 
2. 各インデックス i について、j = i + t[i] を計算します。 j > n の場合、nxt[i] は配列の外にあり、cnt[i] は 1 です。これは、終了につながる 1 つのジャンプを表します。 
3. j が i と同じブロック内にある場合、nxt[i] と cnt[i] は j から継承されます。 nxt[i] = nxt[j] および cnt[i] = cnt[j] + 1 を設定します。これにより、複数の内部ジャンプが 1 つの要約に圧縮されます。 
4. j が別のブロック内にあるものの、まだ配列内にある場合は、nxt[i] = j および cnt[i] = 1 を設定します。これは、次の圧縮ホップが直ちにブロックから出ることを意味します。 
5. i で始まるクエリの場合、これらのブロック ジャンプを繰り返し適用します。 合計カウントを蓄積し、最後の有効な位置を追跡します。 i から nxt[i] にジャンプするたびに、最後の位置はジャンプ前の i になり、i は nxt[i] に更新されます。 
6. i が n を超えるとプロセスが停止し、最後の有効な位置と合計ステップが出力されます。 
7. 位置 i での更新の場合、t[i] を変更し、i のブロック内のすべての nxt および cnt 値を再計算します。これは、そのブロックの内部構造のみが変更されている可能性があるためです。 

これが機能する主な理由は、ブロック内では、再計算後にすべてのチェーンが局所的に一貫しており、ブロック間をジャンプすることでパスの長さが大幅に短縮されるためです。 各ブロックの走査は一度に多くの位置をスキップするため、各クエリは最大でも O(√n) ブロックを横断します。 

### なぜ効果があるのか

 nxt と cnt によって維持される構造は、ジャンプ規則によって引き起こされる関数グラフの圧縮表現として機能します。 ブロック内では、すべてのパスが最終的にブロックまたは配列から抜け出し、その出口がどこで発生するかを正確に事前計算します。 更新は 1 つのブロックにのみ影響し、再計算はローカルで正確さを復元するため、すべてのジャンプは有効な事前計算されたチェーンに従うか、新しいブロック境界に遷移します。 これにより、圧縮プロセスのシミュレートされたすべてのステップが元のジャンプのシーケンスに正確に対応し、最終位置とステップ数の両方が保持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
t = list(map(int, input().split()))

B = int(n ** 0.5) + 1

nxt = [0] * n
cnt = [0] * n

def rebuild(block):
    l = block * B
    r = min(n, (block + 1) * B)
    for i in range(r - 1, l - 1, -1):
        j = i + t[i]
        if j >= n:
            nxt[i] = n
            cnt[i] = 1
        else:
            if j // B == i // B:
                nxt[i] = nxt[j]
                cnt[i] = cnt[j] + 1
            else:
                nxt[i] = j
                cnt[i] = 1

for b in range((n + B - 1) // B):
    rebuild(b)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '0':
        i = int(tmp[1]) - 1
        x = int(tmp[2])
        t[i] = x
        rebuild(i // B)
    else:
        i = int(tmp[1]) - 1
        pos = i
        steps = 0
        last = i

        while pos < n:
            last = pos
            steps += cnt[pos]
            pos = nxt[pos]

        print(last + 1, steps)
```実装の中核となるのは、`rebuild`1 つのブロックの圧縮されたジャンプ情報を再計算する関数。 インデックスを右から左に処理するので、使用するたびに`nxt[j]`そして`cnt[j]`、それらはすでに有効です。 

クエリ中に、一度に 1 つのインデックスをステップ実行するのではなく、次を使用して繰り返しジャンプします。`nxt[pos]`、ブロック内のチェーン全体をスキップします。 最後の有効な位置は常に、配列を出る最後のジャンプの開始位置です。 

更新操作は 1 つのブロックのみに触れるため、再計算はローカルに留まります。 最も微妙な点は、インデックス付けを一貫して処理することです。格納された構造体は内部で 0 から始まるインデックスを使用しますが、出力には 1 から始まる位置が必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    t = list(map(int, input().split()))

    B = int(n ** 0.5) + 1
    nxt = [0] * n
    cnt = [0] * n

    def rebuild(block):
        l = block * B
        r = min(n, (block + 1) * B)
        for i in range(r - 1, l - 1, -1):
            j = i + t[i]
            if j >= n:
                nxt[i] = n
                cnt[i] = 1
            else:
                if j // B == i // B:
                    nxt[i] = nxt[j]
                    cnt[i] = cnt[j] + 1
                else:
                    nxt[i] = j
                    cnt[i] = 1

    for b in range((n + B - 1) // B):
        rebuild(b)

    out = []
    for _ in range(q):
        tmp = sys.stdin.readline().split()
        if tmp[0] == '0':
            i = int(tmp[1]) - 1
            x = int(tmp[2])
            t[i] = x
            rebuild(i // B)
        else:
            i = int(tmp[1]) - 1
            pos = i
            steps = 0
            last = i
            while pos < n:
                last = pos
                steps += cnt[pos]
                pos = nxt[pos]
            out.append(f"{last+1} {steps}")

    return "\n".join(out)

 ## 特殊なケース

 重大なエッジ ケースは、すべてのジャンプが 1 つのブロック内に留まる場合であり、通常はステップバイステップのトラバースが強制されます。 内部チェーンが事前に計算され、nxt ポインターに折りたたまれているため、ブロック分解によってこれが処理されます。 たとえ最後のステップまでブロックを離れなかったとしても、cnt は内部パス全体の長さを蓄積します。 

もう 1 つのエッジ ケースは、1 回の更新でブロック境界近くの値が変更される場合です。 ブロック全体を再計算しないと、後続のクエリが古い nxt ポインターに従う可能性があります。 ブロック全体を再構築すると、すべての内部依存関係が再び一貫したものになります。 

最後に、t[i] が配列からすぐに抜け出すのに十分な大きさである場合、nxt[i] は n に設定され、cnt[i] は 1 になります。これにより、チェーン圧縮中の境界を超えた偶発的な逆参照が防止され、そのようなジャンプが複数連続して発生した場合でもクエリが正常に終了することが保証されます。
