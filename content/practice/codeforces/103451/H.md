 ## 解決策
 ## 問題の理解

 単一の整数 n が与えられ、2 人のプレイヤーがそれに対して交互に動きます。 移動するたびに、プレイヤーは現在の数字を見て、それを 1 つ減らすか、フロア分割で半分にします。 問題は、「1 を引く」操作は数値が奇数の場合にのみ許可されるのに対し、2 で割る操作は数値が正である限り常に許可されることです。 

数字が0になるとゲーム終了となり、動けなくなったプレイヤーの負けとなります。 両方のプレイヤーが最適にプレイするため、タスクは n の各開始値でどちらが勝つかを決定することです。 

このプロセスは基本的に、0 から n までの状態に対する決定論的なゲームであり、各状態はより小さな状態に遷移します。 すべての動きが厳密に数値を減少させるため、ゲームは有限の有向非循環構造を形成し、整数に対する動的プログラミングの解釈を即座に示唆します。 

この制約により、n は最大 10^18、最大 10^3 のクエリが許可されるため、段階的に遷移をシミュレートするソリューションは不可能です。 クエリごとの O(n) ですら実現可能をはるかに超えており、単純な再帰では依然として奇数を繰り返し分割する危険があるため、ステップごとの対数シミュレーションであっても細心の注意を払う必要があります。 

奇数の場合、微妙なケースが発生します。 たとえば、3 からは 1 または 1 に進むことができますが、2 からは 1 にしか進むことができません。これは、多くの状態が同じ結果に崩壊することを意味し、ゲームが単純な半分のプロセスのように動作すると誤って想定する可能性があります。 この仮定は、連続する奇数のシーケンスでは当てはまりません。1 を減算すると、2 のべき乗への降下が遅れる可能性があります。 

「できれば常に2で割る」といった素朴な欲張りな考えは間違いです。 たとえば、3 を除算すると 1 になりますが、最初に減算してから除算すると、最適なプレイに重要な異なるパリティ パスが生じる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、各整数をゲームの状態として扱い、すべての有効な手をチェックすることで勝っているかどうかを再帰的に計算することです。 負けている状態への移行が存在する場合、状態 n は勝利しています。 これは、n → n/2 および n → n−1 (n が奇数の場合) にわたる再帰を直接定義します。 

これは値が小さい場合は正しく機能しますが、大きな n と組み合わせた分岐の深さが問題になります。 各ステップで n が減少したとしても、最悪の場合でも 1 つのクエリで Θ(n) 状態を探索できますが、n が 10^18 までの場合、これは完全に不可能です。 

重要な観察は、遷移の構造がパリティと 2 の累乗に関して非常に規則的であるということです。 すべての偶数はすぐに n/2 に崩壊します。これは、すべての偶数状態が半分の大きさの対応するもののように動作することを意味します。 実際の分岐の複雑さは奇数に集中しているだけですが、そこでさえ、減算 1 の動きによって偶数の状態に変換され、再びすぐに減少します。 

これは、ゲームが効果的に、因数 2 を何回取り除くことができるか、およびパリティの変更がこのプロセスとどのように相互作用するかに依存することを意味します。 偶数状態を繰り返し圧縮すると、問題は、遷移が n で対数になる圧縮された状態空間に沿った動作の追跡に帰着します。 再帰の深さは O(log n) になり、各状態はメモ化または直接パリティ削減を使用してクエリごとに最大 1 回評価されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての状態に対するブルート フォース再帰 | クエリごとに O(n) | O(n) | 遅すぎる |
 | パリティ圧縮再帰 / メモ化リダクション | クエリあたり O(log n) | O(1) または O(log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のプレイヤーが x から始まる勝利戦略を持っているかどうかを判断する関数 win(x) を定義します。

1. x が 0 の場合、手が存在しないため、局面は負けています。 
2. x が偶数の場合、問題をすぐに win(x / 2) に削減します。 これは、2 による除算が常に許可されており、半分にする前に最初にパリティを操作する間接シーケンスを厳密に支配するため、有効です。 
3. x が奇数の場合、可能な 2 つの手を検討します。 1 つの手は x − 1 であり、これは偶数になるため、すぐに win((x − 1) / 2) に減ります。 もう 1 つの手は x / 2 (床分割) で、これも厳密に小さい状態につながります。 
4. 少なくとも 1 つの手が負け状態につながる場合、x の勝利を宣言します。 そうでなければ、x は負けます。 
5. 評価の繰り返しを避けるために、遷移を圧縮した後、x の昇順で結果をメモ化または反復計算します。 

重要な圧縮ステップは、すべての偶数の x が即座に x/2 に折りたたまれるため、偶数の長いチェーンを明示的にモデル化する必要がありません。 それぞれの奇数は、最大で 2 つの小さな大きさへの遷移を生成し、それらは両方ともすぐにさらに減少します。 

これが機能する理由は、構造的不変式に由来します。すべての位置は、2 の因数を繰り返し除算することによって得られる小さい代表と同等であり、唯一の決定点は、奇数が圧縮形式の勝ち負けの結果を変えるパリティ シフトを強制するかどうかです。 それぞれの移動によって圧縮状態が厳密に削減されるため、再帰によって十分な根拠のある順序付けが定義され、循環依存関係は存在しません。 これにより、勝敗分類の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

@lru_cache(None)
def win(x: int) -> int:
    if x == 0:
        return 0

    if x % 2 == 0:
        return win(x // 2)

    move1 = win(x // 2)          # subtract 1 then halve
    move2 = win(x // 2)          # divide directly

    return 1 if (move1 == 0 or move2 == 0) else 0

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        print(win(n))

if __name__ == "__main__":
    solve()
```実装は再帰定義に直接に従います。 メモ化により、それぞれの個別の状態が 1 回評価されることが保証されます。 重要な点は、両方の奇数遷移が最初の操作後に同じ縮小状態に崩壊するため、分岐要素によって実際には複雑さが増加しないことです。 

偶数リダクションは即座に適用され、繰り返し除算の長いチェーンが再帰の深さを増大させるのを防ぎます。 これにより、有効な状態空間が最大 10^3 のクエリに十分な大きさに保たれます。 

## 実用的な例

 ### 例 1: n = 1

 | × | タイプ | 遷移 | 結果 |
 | --- | --- | --- | --- |
 | 1 | 奇数 | 0 または 0 | 負け状態が存在します |

 1 から 0 に到達するのは 1 つだけであるため、現在のプレイヤーは常に即座に勝ちます。 これは、奇数の最小ステートが相手のターンに直接終了を強制するため勝っていることを裏付けています。 

### 例 2: n = 4

 | × | タイプ | 遷移 | 結果 |
 | --- | --- | --- | --- |
 | 4 | 偶数 | 2 | 依存します |
 | 2 | 偶数 | 1 | 依存します |
 | 1 | 奇数 | 0 | 次は負け |

 1は勝ちなので、2は1しか行かないので負けとなり、4は相手の負けている2に手を押し付けることができるので勝ちとなります。 

このトレースは、パリティ圧縮が勝敗構造をどのように上方に伝播するかを示しています。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

 ## 特殊なケース

 x = 1 の場合、ゲームは直ちに終了します。 唯一利用可能な手は相手を 0 にするため、その位置は簡単に勝ちます。 アルゴリズムはこれを基本ケースで直接処理し、1 を返します。 

x = 2^k のような 2 の累乗の場合、均等な縮小を繰り返すと、状態は 1 まで崩壊します。1 が勝っているため、崩壊チェーンのパリティが結果を決定します。 偶数の各リダクションが奇数のコアに到達するまで均一に適用されるため、再帰ではこれが正しく維持されます。 

x = 10^18 − 1 などの大きな奇数の場合、最初の動きは常に偶数状態を生成し、すぐに減少します。 このアルゴリズムは、同じ圧縮状態を通じて両方の分岐を正しく評価し、奇数ノードでの見かけの選択にもかかわらず指数関数的な分岐が発生しないことを保証します。
