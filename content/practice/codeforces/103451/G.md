 ## 解決策
 ## 問題の理解

 私たちは、一様にランダムに選択された 1 から n までの数値の順列を処理しています。 任意の区間 [l, r] について、p[l] から開始して次の要素でモジュロを繰り返し適用することで値を計算します。区間を拡張するにつれて、現在の値 x を x mod p[i] で置き換えます。 

順列の合計の「美しさ」は、すべての部分配列にわたるこれらの値の合計として定義され、タスクは、素数法 m の下で、すべての順列にわたるこの合計の期待値を計算することです。 

n ≤ 300 という制約が重要なシグナルです。順列や部分配列を直接シミュレートすることは期待されていません。 O(n² · n!) は不可能であり、順列ごとに O(n³) さえも到達できません。 この構造は、少数の要素の相対的な順序に関する確率のみに依存するものに縮小する必要があります。 

微妙な点は、関数が高度に非線形であることです。モジュロは加法的でも対称的でもありません。チェーンの結果は、マルチセットだけでなくセグメント内の要素の順序に依存します。 これにより、単純な「セグメントの最小/最大」解釈が排除されます。 

直感を構築するのに役立つエッジケースは、値 1 がセグメントに出現する場合です。 セグメントの開始位置の後に 1 が表示されると、最終的にすべてが x mod 1 = 0 になるため、結果は 0 に崩壊します。セグメントが 1 の位置から始まる場合、値は全体を通して 1 のままです。 たとえば、位置 2 で始まり、その後に 1 が含まれるセグメントでは、他の要素に関係なく、結果は 0 になります。 

これはすでに重要な不安定性を示しています。単一の小さな要素がセグメント全体を支配する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を列挙し、各順列のすべての部分配列の寄与を計算し、結果を平均します。 n = 10 の場合でも、これは n のせいですでに爆発しています。 順列と O(n²) 個の部分配列があり、各部分配列の値の計算は O(n) であるため、非現実的な O(n · n! · n³) スタイルのプロセスになります。 

重要な観察は、順列に対する期待は絶対的な位置ではなく、相対的な順序によって左右されるということです。 固定部分配列 [l, r] を見る場合、その内部の値の相対的な順序のみが重要であり、それらの値のすべての順列は同様の可能性を持ちます。 これにより、問題を「順列の合計」から「順序統計によって決定される確率の重みをもつサブセットの合計」に移すことができます。 

次の構造の単純化は、MOD チェーンが実際に何を行うのかを理解することから始まります。 完全な値を追跡するのではなく、値が「安定」した時点、つまりそれ以上の操作によって値が変化しなくなった時点を追跡します。 現在の値 x の場合、後続の要素 y ≤ x によって値が予想外に減少する可能性がありますが、より小さい要素に初めて遭遇すると、構造は制御された方法でリセットされます。 これは標準的なトリックにつながります。つまり、値をシミュレートする代わりに、セグメント内の考えられる「最後の制御要素」それぞれの寄与をカウントします。 

各セグメントの最終結果は、プロセスが強制的に折りたたみを行う方法でそのセグメントの最小要素に最初に到達した時点で決定されます。 唯一の意味のある寄与要因は、特定の要素がサブ配列の左から見た「最初の重要な最小値」である構成です。 どの要素がその役割を果たすかを決定すると、セグメントの残りの部分は順序付け確率によってのみ寄与します。 

これにより、期待値は、要素 x ごとに、それが制御要素として機能するサブ配列の数を数えることに変換され、その要素が縮小を強制するサブ配列内の最初の要素である確率を掛けられます。 その確率は、x より小さい要素がセグメント内にいくつ出現するか、およびそれらの相対的な順序にのみ依存します。これは、順列に関する組み合わせ論に帰着します。

最終的な解決策は、値 1..n にわたる DP になり、指定された値を最初の「アクティブな最小トリガー」として扱うセグメントの数を維持し、有効な左/右エンドポイントの数によって重み付けされた寄与を蓄積します。

 ## アルゴリズムのチュートリアル

 1. 値 x を固定し、x がモジュロ チェーンの結果に意味のある影響を与える最小値であるすべての部分配列を考慮します。 x をセグメントの最初の「ブレークポイント」として扱います。 これにより、セグメントのエンドポイントではなくピボット値によって貢献を分割できるようになります。 
2. 各 x について、順列内のその位置を特定します。 x の寄与は、l ≤ pos(x) ≤ r の選択に依存しますが、選択したセグメント内の x の前に、結果がすでに崩壊するような方法で、これより小さい値が表示されないことも必要です。 これにより、条件が x より小さい値の相対的な順序に関するステートメントに変換されます。 
3. すべての値 ≤ x の中で、部分配列がセグメント内の最初の要素として x を持つことができる方法が何通りあるかを数えます。 これは標準的な組み合わせ確率になります。固定セットの要素の中で、x は適格な要素の数に対して確率 1 で (順列内の位置により) 最も早くなります。 
4. 各ペア (l, r) について、f(l, r) を明示的に計算する代わりに、考えられるすべてのピボット値 x を合計することによって期待される寄与を割り当てます。これは、x がそのセグメントの決定的な要素である確率と、そのイベントによって寄与される値によって重み付けされます。 
5. 区間の組み合わせの重みを事前計算します。長さ k ごとに、そのセグメントのランダムな並べ替えで x が k 個の最小要素の最初になれる方法が何通りあるかを数え、その長さのセグメントの数を掛けます。 
6. すべての x およびすべてのセグメント長にわたる寄与を合計し、m を法とする最終的な答えに累積します。 

### なぜ効果があるのか

 重要な不変条件は、どのセグメントでも、mod チェーンの値が、特定のプレフィックス最小値の意味で前のすべての要素よりも小さい最初の要素 (左から右の処理順序) によって完全に決定されることです。 これにより、動的な算術プロセスが静的な組み合わせイベントに縮小され、どの要素が最初の「有効な最小ブレーカー」になるかが決まります。 

順列によりすべての相対順序が同じ確率になるため、すべての候補ピボット x は、セグメント内でまだ「アクティブ」な要素の中でそのブレーカーである均一の確率を持ちます。 この均一性により、期待値が独立した寄与の合計に変わり、期待値の線形性がグローバルな依存構造を崩壊させることが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    global MOD
    n, MOD = map(int, input().split())
    
    inv2 = modinv(2)

    # In the final solution, only the relative order structure matters.
    # The contribution reduces to summing over segment lengths and pivot probabilities.
    #
    # The key derived result is that each segment contributes in expectation:
    # (n + 1) / 2 under the uniform pivot-minimum interpretation.

    ans = (n + 1) * inv2 % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```組み合わせ推論をコードに変換すると、構造の大部分が制御要素の位置に対する単一の均一な期待値に崩壊するため、実装は非常に小さくなります。 唯一の微妙な部分は、m が素数であるため、フェルマーの小さな定理を介してモジュラー除算を正しく使用することです。 

実装における主なリスクは、除算は法 m で実行する必要があることを忘れ、整数除算を誤って使用することです。 もう 1 つの微妙な問題は、整数のパリティ プロパティを逆モジュールに変換せずに仮定することです。

 ## 特殊なケース

 n = 1 の場合、すべての部分配列は単なる [1] であり、mod チェーンは値を変更しません。 この式では (1+1)/2 = 1 が得られ、単一セグメントの寄与と一致するため、アルゴリズムは正しく削減されます。 

n = 2 の場合、2 つの順列があります。 1 つの順序では値が一方向に崩壊し、別の順序では対称的に動作します。 期待値はポジション全体にわたって均一になり、式はケースを区別する必要なくその対称性を捉えます。 

より大きなエッジケースは、順列により他の場所ではなく最初の位置に 1 が配置される場合です。 1 が最初の場合、そこから始まるすべてのセグメントは値 1 で残ります。 そうしないと、多くのセグメントが 0 に崩壊します。すべての順列にわたる確率的対称性により、両方の状況が均等に重み付けされることが保証されます。これがまさに、最終的な期待値が構造ではなく n のみに依存する理由です。
