 ## 解決策
 ## 問題の理解

 負でない整数の配列と、それを新しい値に繰り返し「拡張」する再帰操作が与えられます。 

基本レベルでは、レベルがゼロの場合、値は単に配列内のすべての要素の合計になります。 

より高いレベルでは、すべての連続したサブ配列を調べます。 各部分配列について、その部分配列の前のレベルで同じ関数を計算し、それらの結果をすべて合計します。 これを k 回繰り返すと、非常に急速に増加する 1 つの数値が生成されます。 

したがって、タスクは元の配列を取得し、この部分配列の前の値の合計演算を k 回適用し、1e9+7 を法とする最終値を出力することです。 

入力サイズでは最大 200,000 個の要素、k は最大 200,000 個まで許容されます。 これにより、サブ配列が O(n^2) 個あるため、サブ配列を 1 回でも明示的に列挙するアプローチは即座に除外されます。 k = 1 であっても、すでにすべての部分配列にわたる集計が必要ですが、k > 1 になると、この爆発がさらに悪化します。 どのソリューションでも、サブ配列を明示的に反復することは避けなければなりません。 

k = 0 の場合、微妙なエッジ ケースが発生します。その場合、再帰は決して開始されず、答えは単なる配列の合計になります。 もう 1 つのエッジ ケースは、n = 1 の場合です。すべての部分配列は単なる 1 つの要素であるため、答えはすべての k に対して同じ値になります。これは、派生式の健全性チェックに役立ちます。 

## アプローチ

 直接シミュレーションでは、すべてのペア (l, r) を反復し、各部分配列を合計し、結果として得られる k 層の構造に対してこれを繰り返すことによって f(A, 1) を計算します。 これはすでに O(n^2) であり、これを k 回実行すると、事実上 O(k n^2) になります。これは、実行可能な制限をはるかに超えています。 

重要な観察は、すべての要素が最終的な答えに独立して寄与するという意味で、プロセス全体が線形であるということです。 再帰では、元の各要素がカウントされる回数のみが変更され、要素が相互に作用する方法は変更されません。 したがって、部分配列を追跡する代わりに、すべてのレベルを通じて単一の固定位置の寄与を追跡します。 

レベル 0 では、各要素 a[i] は合計に 1 だけ寄与します。 

レベル 1 では、インデックス i を含むサブ配列の数を数えます。 つまり、左端点には i 個の選択肢があり、右端点には (n - i + 1) 個の選択肢があるため、係数は i(n - i + 1) になります。 

より高いレベルでは、同じ構造が繰り返されますが、選択された各サブ配列内で要素の位置が移動します。 これはプロダクト構造につながります。つまり、各深さで左側の境界と右側の境界を選択する方法の数がきれいに分離されます。 2 つのレベルを処理すると、二項係数が自然に現れるパターンが現れます。 

これにより、k 回の操作後の a[i] の係数の閉じた形式が得られます。これは、その位置と n にのみ依存します。

 | 組み合わせ寄与公式 | O(n + k) | O(n + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. プロセスを線形寄与問題として再解釈する

 最終的な答えは、元の要素の加重和として記述できると仮定します。ここで、各 a[i] は、そのインデックスと k にのみ依存する係数を持ちます。 これは、すべてのステップが部分配列の合計であり、入力値が線形であるため有効です。 

### 2. 基本係数を計算する

 k = 0 の場合、すべての要素は 1 回だけ寄与するため、すべての i に対して係数は 1 になります。 

k = 1 の場合、各要素 i は左境界の i 個の選択肢と右境界の (n - i + 1) 個の選択肢に出現し、係数 i(n - i + 1) が与えられます。 

これは、係数が位置をカバーするサブアレイの数にのみ依存することを確認します。 

### 3. k = 2 の構造を観察します。 

2 番目のレベルでは、すべてのサブ配列を再度合計しますが、各サブ配列は独自の内部重み付けに寄与します。

元の配列の要素 i を固定する場合、それを含む部分配列 [l, r] を選択します。 そのサブ配列内では、その局所的な寄与はその位置 (i - l + 1) と残りの長さ (r - i + 1) にのみ依存します。 すべての有効な l と r を合計すると、左側と右側の 2 つの独立した和に分離され、三角和の積が生成されます。 

これにより、以下が生成されます。 

i(i + 1)/2 倍 (n - i + 1)(n - i + 2)/2

 ### 4. k レベルに一般化する

 レベルを追加するたびに、組み合わせの「三角形」の両辺が 1 ずつ増加します。これにより、次の二項係数が得られます。 

a[i] の係数 =

 C(i + k - 1, k) × C(n - i + k, k)

 ### 5. 最終的な答えを計算する

 n + k までの階乗および逆階乗を事前計算します。 次に、インデックスごとに、上記の係数を乗算した a[i] を合計します。 

### なぜ効果があるのか

 すべてのレベルで、操作は左右の境界のみを個別に選択します。 これらの選択は、再帰レベル全体にわたって乗算的に蓄積されます。 部分配列内の要素の位置は、左側の境界が要素をどれだけシフトさせるかによってのみ決まるため、カウントは 2 つの独立した組み合わせの選択肢 (左側から 1 つと右側から 1 つ) に分解されます。 この独立性はまさに、入れ子になった部分配列の合計を二項係数の積に変換するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    return fact, invfact

def C(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    maxv = n + k + 5
    fact, invfact = build_fact(maxv)

    ans = 0
    for i in range(n):
        left = C(i + k, k, fact, invfact)
        right = C(n - i - 1 + k, k, fact, invfact)
        ans = (ans + a[i] * left % MOD * right) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```両方の二項項がインデックスを最大 k までシフトするため、階乗テーブルは n + k まで構築されます。 各係数は、事前計算された階乗を使用して一定時間で計算されます。 

主要な実装の詳細はインデックス付けです。式では 0 から始まる i が使用されるため、左項は C(i + k, k) になり、右項は C(n - i - 1 + k, k) になります。 よくある間違いは、1 ベースの導出と 0 ベースの実装を混合することです。これにより、すべての係数が誤ってシフトされます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + k) | 階乗前処理と配列の 1 回のパス |
 | スペース | O(n + k) | 階乗表と逆階乗表 |

 この制約では、n と k の両方で最大 2e5 が許可されるため、n + k までの階乗の事前計算が快適に適合し、最終的なループは n で線形になります。 

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    maxv = n + k + 5
    fact = [1] * (maxv + 1)
    invfact = [1] * (maxv + 1)

    for i in range(1, maxv + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[maxv] = pow(fact[maxv], MOD - 2, MOD)
    for i in range(maxv, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    ans = 0
    for i in range(n):
        ans += a[i] * C(i + k, k) * C(n - i - 1 + k, k)
        ans %= MOD

    return str(ans)

# provided samples
assert solve("5 0\n1 2 3 4 5\n") == "15"
assert solve("5 1\n1 2 3 4 5\n") == "105"
assert solve("3 2\n1 2 3\n") == "42"

# custom cases
assert solve("1 0\n7\n") == "7"
assert solve("1 5\n7\n") == "7"
assert solve("2 1\n1 1\n") == "4"
assert solve("4 2\n1 2 3 4\n") == solve("4 2\n1 2 3 4\n"), "consistency"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 k = 0 の場合、両方の二項項が 1 に評価されるため、アルゴリズムは a[i] を合計することになります。すべての有効な x に対して C(x, 0) = 1 であるため、数式はこれをきれいに処理します。 

n = 1 の場合、左項は C(k, k) = 1 になり、右項も C(k, k) = 1 になるため、どのレベルでも値は変更されません。 これは、各ステージにサブ配列が 1 つだけ存在するため、組み合わせ爆発は起こらないという直観と一致します。 

k が大きい場合、係数は急速に増加しますが、階乗事前計算により、制限されたモジュロ MOD のままになります。 逆モジュラーを使用すると、二項値が大きい場合でも、要素ごとに一定時間で計算できることが保証されます。
