 ## 解決策
 ## 問題の理解

 私たちは、ボブとキャロルの 2 人が同じセルから出発し、マンハッタン距離の最短経路を使用して各自の目的地まで移動する必要があるグリッドに取り組んでいます。 最短経路とは、各ステップがターゲットまでのマンハッタン距離をちょうど 1 だけ減らすことを意味するため、方向の組み合わせによっては移動が常に単調になります。 

両方の旅行者は、旅の一部を共有することができます。つまり、散歩の一部のプレフィックスで同じセルに立つことができます。 目標は、両方が可能な限り最短のルートを使用してそれぞれの目的地に到着しながら、同一のセルに留まる時間を最大化することです。 

各テストでは、グリッド上に共通の出発点、ボブの目的地、キャロルの目的地という 3 つのポイントが与えられます。 出力は、両方の最短パスに同時に属することができるセルの最大数です。 

制約は最大 10^4 のテスト ケースに適用され、最大 10^8 の調整が行われます。 これにより、パスのシミュレーションが直ちに除外されます。 テストごとに O(n) でも遅すぎてパスの列挙が不可能になるため、各答えはテスト ケースごとに一定時間で計算する必要があります。 

よくある間違いは、両方のパスが宛先間のセグメントの中間点まで常に重なる可能性があると想定することです。 これは、ジオメトリが早期に発散を強制する場合、たとえば、ボブのターゲットが最初からキャロルの最適な方向とすぐに矛盾する方向にある場合に失敗します。 

## アプローチ

 強引なアイデアでは、最初からボブとキャロルまでの最短パスをすべて列挙し、任意のペアの最長の共通プレフィックスを計算しようとします。 グリッド内の最短パスの数は、距離に応じて組み合わせ的に増加し、おおよそマンハッタン距離の二項係数のオーダーで増加します。 中距離の場合でも、これは実行不可能になり、パスのペアを比較する必要があるため、アプローチは指数関数的になります。 

重要な観察は、マンハッタン ジオメトリの最短パスは単調であるということです。各ステップで、x または y に独立して近づくだけです。 これにより、問題は離散的なパスではなく幾何学的領域に関する推論に変わります。 

個々のパスについて考える代わりに、A から B への最短パスと A から C への最短パスの両方に属することができるすべてのセルのセットについて考えます。セルは、マンハッタン距離が可能な最小距離を超えて増加しない場合に限り、ターゲットへの最短パスで使用できます。 これにより、問題はグリッド内で重なり合う単調な長方形を理解することに変換されます。 

セルが両方の目的地の最短経路制約に適合している限り、両方の旅行者が一緒に移動すると、最適なオーバーラップが発生します。 ある方向が矛盾した瞬間に、道は分岐しなければなりません。 

これにより、点間のマンハッタン距離に基づいた直接的な幾何学的公式が得られます。

 ## アルゴリズムのチュートリアル

 1. 関連するすべての点のペア間のマンハッタン距離 (A から B、A から C、B から C) を計算します。これらの距離は、グリッド内の最短パス ジオメトリを完全に記述します。 
2. 両方の旅行者ができるだけ長く同じ道を共有する場合、A から事実上一緒に移動し、一緒に行動を続けると少なくとも 1 人が最短ではない迂回を余儀なくされる点まで移動することを観察します。 この乖離は、B と C が A に対してどれだけ離れているかによって完全に決まります。 
3. 最大の共有セグメントは、A から B と C への最短経路が重なる領域に向かって歩くことに対応します。 この重なりは、最短経路のコリドーがどの程度交差するかによって決まります。 
4. 最終結果は数量の半分に単純化されます。$$d(A,B) + d(A,C) - d(B,C)$$グリッド セルのカウントを処理する整数除算を使用して 1 を加えます。 この式は、分離が不可避になる前にどの程度のパスを位置合わせできるかを測定します。 
5. 各テスト ケースの計算値を返します。 

重要な推論ステップは、B と C が A から個別にカバーする必要がある合計距離から、B と C の間の直接の距離を差し引くことによって重複が決定されるということです。残っているのは、まさにそれらの単調なルートの共有部分です。 

機能する理由: マンハッタン ジオメトリの最短パスは単調なチェーンのように動作します。 共有セグメントは、それ自体が両方の宛先への最短パス プレフィックスである必要があります。 完全な共有を妨げる唯一の障害は、2 つのターゲット方向間の幾何学的な発散であり、この発散は距離間の三角不等式のギャップによって完全に捕らえられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def manhattan(x1, y1, x2, y2):
    return abs(x1 - x2) + abs(y1 - y2)

def solve():
    t = int(input())
    for _ in range(t):
        ax, ay = map(int, input().split())
        bx, by = map(int, input().split())
        cx, cy = map(int, input().split())

        d_ab = manhattan(ax, ay, bx, by)
        d_ac = manhattan(ax, ay, cx, cy)
        d_bc = manhattan(bx, by, cx, cy)

        # maximum overlap of shortest paths
        ans = (d_ab + d_ac - d_bc) // 2 + 1
        print(ans)

if __name__ == "__main__":
    solve()
```コードはペアごとのマンハッタン距離を計算し、導出された式を直接適用します。 この幾何学的設定では式は常に整数に評価されるため、整数除算は安全です。 決勝戦`+1`共有パス セグメント内のエッジではなくセルをカウントします。 

実装でよくある落とし穴は、答えがステップではなくセルをカウントすることを忘れていることです。 そのため、距離だけが直接返されないのです。 共有頂点数に変換する必要があります。 

## 実用的な例

 最初のサンプルを考えてみましょう。 

A = (3,1)、B = (1,3)、C = (6,4)

 次のように計算します。 

| 数量 | 値 |
 | --- | --- |
 | d(A,B) | 4 |
 | d(A,C) | 6 |
 | d(B,C) | 6 |

 式を適用すると次のようになります。 

(4 + 6 - 6) // 2 + 1 = 3

 これは、両方の旅行者が方向が分かれる前に、短い接頭辞のために一緒に移動できるという考えと一致します。 

次に、2 番目の構成を考えてみましょう。 

A = (5,2)、B = (2,2)、C = (7,2)

 ここではすべてが同じ水平線上にあります。 

| 数量 | 値 |
 | --- | --- |
 | d(A,B) | 3 |
 | d(A,C) | 2 |
 | d(B,C) | 5 |

 結果:

 (3 + 2 - 5) // 2 + 1 = 1

 これらは、ラインに沿って反対方向に移動する前に、開始セルを共有するだけです。 

これらの例は、B と C が A からの互換性のある指向性コーン内にある場合にのみ完全なオーバーラップが発生することを示しています。

 ## 特殊なケース

 B と C が A を通る同じ直線上にある場合、最適な共有パスは単に A からの方向の重なりです。d(B,C) は A からの反対方向の距離の合計に等しいため、式は正しく崩壊し、共有開始セグメントのみが残ります。 

B と C が A から垂直方向に配置されている場合、一方に近づくとすぐに他方への距離が増加します。 この式は、共有セグメントをちょうど 1 つのセルに縮小し、開始点のみを表します。 

3 つの点すべてが近い場合 (座標が 1 単位だけ異なる場合など)、マンハッタン距離により、数式が無効な負の重複を生成しないことが保証され、共有パスは A のすぐ近くに制限されます。
