[CF 1389C - 良好な文字列](https://codeforces.com/problemset/problem/1389/C)

 **評価:** 1500
 **タグ:** ブルート フォース、DP、貪欲、ツー ポインター
 **解決時間:** 5 分 10 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 数字の文字列が与えられ、残りの文字の順序を維持したまま、好きな場所で文字を削除できます。 目標は、文字列を「good」と呼ばれる特別な形式に変換することです。 

左巡回シフトを適用すると、右巡回シフトを適用した場合と同じ文字列が生成される場合、その文字列は良好であるとみなされます。 循環シフトは、最初の文字を最後に移動するか (左シフト)、最後の文字を前に移動します (右シフト)。良好な文字列では、どちらの操作も同じ結果を生成します。 

重要なのは、適切な文字列を直接構築することではなく、残りの部分シーケンスが適切なものになるように、できるだけ少ない文字を削除することです。 

したがって、出力は必要な削除の最小数になります。これは、適切なサブシーケンスの長さを最大化するのと同じです。 

テスト ケース全体にわたる全長の制約は、最大 2 · 10^5 です。 これにより、テスト ケースごとの二次関数は即座に排除され、テストごとに線形または線形に近い解、または小さな固定状態空間を反復する解へと私たちは近づきます。 

単純なアプローチでは、すべてのサブシーケンスまたはすべての削除を試行しますが、単一のサブシーケンスの有効性をチェックするだけでも線形時間が必要です。 サブシーケンスが指数関数的に多い場合、これは不可能です。 

文字列がすでに非常に規則的であるように見えても、完全に交互になっていない場合、微妙なエッジケースが発生します。 たとえば、`100120013`、最適な構造に到達するためにどの文字を削除すればよいかは明らかではありません。 全体的なパターンを理解せずに「見栄えの悪い」文字を貪欲に削除すると、最適な部分シーケンスを簡単に見逃す可能性があります。 

もう 1 つの失敗モードは、結果として得られる適切な文字列がすべて同一の文字を持っている必要があると仮定することです。 これは最適な答えには当てはまりますが、中間推論では必ずしも必要というわけではありません。 

## アプローチ

 「善」が実際に構造的に何を強制するのかを理解することから始めましょう。 巡回シフトを直接シミュレートする代わりに、2 つのシフトされたバージョンを位置ごとに比較します。 

文字列を次のようにします`t1 t2 ... tn`。 

左シフトすると`t2 t3 ... tn t1`。 

右シフトすると`tn t1 t2 ... t_{n-1}`。 

For these to be identical, corresponding positions must match. これにより、等式系が作成されます。`t2 = tn`、`t3 = t1`、`t4 = t2`、 等々。 

これらの制約に従うと、周期 2 の繰り返しパターンがわかります。2 文字ごとに一致する必要があります。これは、すべての奇数位置がそれらの間で同一であり、すべての偶数位置がそれらの間で同一であることを意味します。 

したがって、適切な文字列は 2 つの固定数字の間で交互に配置する必要があります。たとえば、`a b a b a b ...`または`b a b a b a ...`、以下のような退化したケースを含む`a = b`、定数文字列が生成されます。 

したがって、問題は次のようになります。元の文字列から必要な数の文字を削除し、残りの部分シーケンスが選択した 2 つの数字の間で交互になるようにします。 

ブルートフォースアプローチでは、すべてのサブシーケンスを試行するか、さらに合理的に、削除する文字のすべてのサブセットを試行し、残りが良好かどうかを確認します。 これにより、文字列の長さが指数関数的に動作し、小さな入力を超えると実行不可能になります。 

重要な観察点は、有効な文字列の構造は、順序付けられた数字のペアの選択のみに依存するということです。`(a, b)`。 このペアが修正されると、可能な限り最良のサブシーケンスを貪欲に構築できます。左から右にスキャンし、予想される代替パターンに一致する場合にのみ文字を保持します。 100 個の可能な数字のペアすべてを効率的に評価できます。

 ## アルゴリズムのチュートリアル

 このタスクを、2 つの固定数字の間で交互に現れる最長のサブシーケンスを見つけることに変換します。 

1. 順序付けられた数字のペアを修正する`(a, b)`。 

このペアは、最終文字列の意図された交互パターンを表します。 100の可能性をすべて試してみます。 
2. 期待値から始まる最長の部分列を計算します`a`。 

文字列を左から右にスキャンします。 期待される文字を見つけると、それを受け取り、期待を他の桁に切り替えます。 

これが機能するのは、以前の有効な一致を取得すると、常に将来の一致に対する柔軟性が高まるためです。 
3. 期待値から始まる最長の部分列を計算します`b`。 

最適な交互サブシーケンスはいずれかの桁で始まる可能性があるため、これにより代替パリティの開始がキャプチャされます。 
4. このペアの 2 つの開始選択肢から最大の結果を取得します。`(a, b)`。 
5. すべての数字のペアに対してこれを繰り返し、グローバルな最大サブシーケンス長を追跡します。 
6. 答えは次のとおりです。`n - best_subsequence_length`。 

これで十分な理由: すべての有効な適切な文字列は 2 桁の間で交互に配置される必要があり、交互に配置されるすべてのサブシーケンスは、次のいずれかの選択に正確に対応します。`(a, b)`プラススタートポジション。 貪欲スキャンは、スキップされた有効な一致は遅延するか、将来必要な一致をブロックするだけであるため、固定構成ごとに最適なサブシーケンスを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def best_for_pair(s, a, b):
    # try starting with a
    need = a
    cnt1 = 0
    for ch in s:
        if ch == need:
            cnt1 += 1
            need = b if need == a else a

    # try starting with b
    need = b
    cnt2 = 0
    for ch in s:
        if ch == need:
            cnt2 += 1
            need = a if need == b else b

    return max(cnt1, cnt2)

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        best = 1
        for i in range(10):
            for j in range(10):
                best = max(best, best_for_pair(s, str(i), str(j)))

        print(n - best)

if __name__ == "__main__":
    solve()
```この実装における中心的なアイデアは、交互サブシーケンス チェックを固定桁ペアのヘルパー関数に分離することです。 数字上の二重ループのサイズは一定であるため、複雑さは文字列長において線形のままです。 

微妙な実装の詳細がこのケースを処理しています`a == b`。 その場合、交互プロセスは単一の数字のすべての出現を選択するように退化しますが、期待値は決して変わらないため、同じ貪欲なロジックが依然として正しく機能します。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    def best_for_pair(s, a, b):
        need = a
        c1 = 0
        for ch in s:
            if ch == need:
                c1 += 1
                need = b if need == a else a

        need = b
        c2 = 0
        for ch in s:
            if ch == need:
                c2 += 1
                need = a if need == b else b

        return max(c1, c2)

    for _ in range(t):
        s = input().strip()
        n = len(s)
        best = 1
        for i in range(10):
            for j in range(10):
                best = max(best, best_for_pair(s, str(i), str(j)))
        print(n - best)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 一般的なエッジケースは、すべての文字が同一である場合です。`777777`。 アルゴリズムはペアを評価します`(7,7)`また、切り替えが必要ないため、文字列全体が有効な交互サブシーケンスとして正しくカウントされます。 

もう 1 つのケースは、最適なパターンが元の文字列内で遠く離れた 2 つの異なる数字を使用する場合です。`95831`。 貪欲スキャンでは、隣接関係には依存せず、順序の保存のみに依存するため、正しいサブシーケンスが見つかります。 

さらなるケースは、交互が頻度の低い数字から始まる場合です。 たとえば、`100120013`、最適なサブシーケンスは、文字列の後半に現れる数字で始まる可能性があります。 アルゴリズムは、各桁ペアの両方の開始状態を明示的に試行することでこれを処理し、構成が欠落していないことを保証します。
