[CF 1389G - エッジのディレクティング](https://codeforces.com/problemset/problem/1389/G)

 **評価:** 2800
 **タグ:** dfs および類似の、dp、グラフ、ツリー
 **解決時間:** 2 分 35 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 無向接続グラフが与えられ、各エッジを選択した一方向エッジに変えることも、双方向エッジとして維持することもできます。 双方向に保つと、そのようなエッジがすべてその重みをコストに反映させるため、コストがかかります。 有向エッジは自由ですが、選択した方向でのみ使用可能ですが、無向エッジは両方向に横断できます。 

特別な頂点と呼ばれる頂点のサブセットがあります。 方向を選択した後、結果として得られる混合グラフ内で許可された動きを使用してすべての特別な頂点がその頂点に到達できる場合、その頂点は良好であると呼ばれます。 良好な頂点ごとに、その頂点に割り当てられた特定の値に等しい利益を受け取ります。 合計スコアは、すべての良好な頂点からの利益から、方向付けされていないエッジの合計コストを差し引いたものです。 

タスクは、必須の良好な頂点とみなされるすべての頂点について、可能な最大スコアを計算することです。 

重要な問題は、到達可能性の構造がエッジの向きに全体的に依存しており、1 つのエッジを変更すると、多くの頂点ペア間の到達可能性に同時に影響を与える可能性があることです。 これにより、頂点を独立して扱うアプローチは即座に除外されます。 

制約は大きく、最大 30 万の頂点とエッジがあります。 到達可能性を再計算したり、単純な方法でルートごとに方向を最適化したりするソリューションは拡張できません。 各頂点に対して繰り返される線形または線形に近いグラフの走査でさえ、遅すぎます。 

グラフのさまざまな部分からの方向要件が矛盾するサイクルがグラフに含まれている場合、微妙なエッジ ケースが発生します。 ローカルでエッジの向きを貪欲に設定すると、たとえ別のグローバルな向きであれば可能であっても、一部の特別な頂点が選択したルートに到達できなくなる状況が簡単に発生する可能性があります。 たとえば、特別な頂点が異なる角にある三角形では、パスがどのように相互作用するかを無視すると、局所的に一貫した方向が依然としてグローバルな到達可能性を損なう可能性があります。 

## アプローチ

 強引な観点では、考えられるエッジの向きをすべて試してみることになります。 方向ごとに、すべての特別な頂点からどの頂点に到達できるかを計算し、それらの値を合計して、無向エッジのコストを差し引きます。 向きの指数関数的な数を無視しても、到達可能性の計算だけではグラフ サイズが線形であるため、これは完全に実行不可能です。 

より構造化されたブルート フォースは、ルート頂点 i を固定し、すべての特別な頂点が i に到達できるという制約の下でスコアを最大化する最適な方向を構築しようとするものです。 それでも、エッジの方向を貪欲に決定したり、接続性を繰り返し再計算したりすると、ルートごとに少なくとも O(m) の作業が発生する可能性があり、これは 3⋅10^5 までの n にとっては遅すぎます。 

重要な観察は、すべての特別な頂点からの到達可能性が、高度に接続された領域内の個々のエッジの方向に影響されないことです。 方向の選択が重要になるのはブリッジだけです。これは、2 つのエッジで接続されたコンポーネント内でいつでもパスを再ルーティングできるためです。 これは、各ノードが二重接続コンポーネントであり、各エッジがブリッジであるブリッジ ツリーにグラフを圧縮することを示唆しています。 

このツリーでは、すべてのブリッジが二分決定点のように動作します。 それを一方向に向けると、それを横切る到達可能性は一方向になります。 コストを支払えば、双方向に横断することができます。 全体の問題は、特別な頂点がどのように分散されているかに応じて、ブリッジごとに双方向トラバーサルが必要かどうかを決定することに帰着します。

この観点から、ルート i を固定することは意味のあるものになります。すべての特別な頂点は、ブリッジ ツリー内の i を含むコンポーネントに到達できなければなりません。 各ブリッジはいつでも i の方向に向けることができ、これによりコストを支払うことなくすべての頂点が i に到達できるようになります。 ただし、これは目的に隠された 2 番目の制約を無視します。つまり、到達可能性を確保するだけでなく、単一の一貫した方向の選択の下ですべてのスペシャルから同時に到達可能な頂点のセットを最大化します。 異なる到達可能性要件間のトレードオフにより、最適な構成では特定のブリッジが双方向になることが強制され、ここでコストが発生します。 

グラフをブリッジ ツリーに縮小した後、問題はルート選択に関するツリー DP になり、各ブリッジは特別な頂点によって引き起こされる競合するフローをサポートする必要があるかどうかに応じてコストに寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース オリエンテーション + ケースごとの BFS | 指数 / O(nm) | O(n + m) | 遅すぎる |
 | ツリー構造上のブリッジツリー + DP | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを二重接続コンポーネントに分解し、ブリッジ ツリーを構築します。 各ノードは 2 エッジ接続されたコンポーネントを表し、各エッジは特定のコストを持つブリッジに対応します。 

このステップでは、コンポーネント内で必要な接続を制約なしで実現できるため、無関係な内部構造がすべて削除されます。 
2. すべての元の頂点をブリッジ ツリー内のコンポーネントにマッピングし、どのコンポーネントに特別な頂点が含まれているかを特定します。 

この変換後、すべての制約は、特別なコンポーネントがツリー全体にどのように分散されるかのみに依存します。 
3. ブリッジ ツリーを任意にルート化し、サブツリー情報、具体的には各ノードの各サブツリーに特別な頂点がいくつあるかを計算します。 

これにより、あらゆる橋について、その橋の両側に特別な頂点が存在するかどうかを判断できます。 
4. 各ブリッジについて、特定のルート選択の下でブリッジが「強制」されるかどうかを判断します。 特別な頂点が橋の両側に表示される場合、橋は強制的に適用されます。これは、情報または到達可能性の要件が構造の異なる部分にわたって両方向に橋を通過する必要があり、単一の方向付けでは満たすことができないためです。 

橋を強制的に建設する場合、橋は両方向に使用できる必要があるため、そのコストを支払う必要があります。 
5. 考えられるルート コンポーネントごとに、すべての強制ブリッジによる合計コストを計算します。 これは、ブリッジ ツリー上の再ルート DP を使用して O(n) で実行できます。エッジを越えてルートを移動すると、強制されたとみなされるブリッジのセットが更新されます。 
6. ルートの利益は、選択された方向の下ですべての特別な頂点から同時に到達可能なコンポーネント内のすべての頂点の値の合計から、計算された強制ブリッジ コストを差し引いたものです。 

コンポーネント内の到達可能性は常に達成可能であるため、決定は完全に制約をブリッジすることになります。 
7. コンポーネントの応答を元の頂点にマッピングして、すべての頂点の計算値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、二重接続されたコンポーネント内では、エッジの方向に関係なく頂点間の到達可能性が常に維持されるため、すべてのグローバル制約がブリッジ ツリーに集約されるということです。 このツリーでは、すべての特別なコンポーネントが頂点に到達できる場合に限り、頂点は飽和ルートとして有効であり、この条件に対する障害は、ブリッジの除去によって特別な頂点が異なる側面に分離されることによってのみ発生します。 このようなブリッジでは、ルートが選択されると避けられない双方向要件が生じ、これらの要件がコストを完全に決定します。 すべての設定はブリッジ ツリー上の方向の割り当てに対応し、すべての有効な割り当ては双方向性に対してどのブリッジに支払いを行うかを選択することで表すことができるため、リルート上の DP はすべての最適な設定を漏れなくキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m, k = map(int, input().split())
    special = set(map(int, input().split()))
    c = list(map(int, input().split()))
    w = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))

    tin = [-1] * n
    low = [-1] * n
    timer = 0
    is_bridge = [False] * m

    def dfs(v, pe):
        nonlocal timer
        timer += 1
        tin[v] = low[v] = timer
        for to, ei in g[v]:
            if ei == pe:
                continue
            if tin[to] != -1:
                low[v] = min(low[v], tin[to])
            else:
                dfs(to, ei)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[ei] = True

    dfs(0, -1)

    comp = [-1] * n
    cid = 0

    stack = []

    comp_g = []

    def dfs_comp(v, cid):
        stack = [v]
        comp[v] = cid
        has_special = special.__contains__(v + 1)
        while stack:
            x = stack.pop()
            for to, ei in g[x]:
                if comp[to] == -1 and not is_bridge[ei]:
                    comp[to] = cid
                    stack.append(to)

    for i in range(n):
        if comp[i] == -1:
            dfs_comp(i, cid)
            cid += 1

    comp_special = [0] * cid
    comp_weight = [0] * cid

    for v in range(n):
        if (v + 1) in special:
            comp_special[comp[v]] = 1
        comp_weight[comp[v]] += c[v]

    tree = [[] for _ in range(cid)]

    for i, (u, v) in enumerate(edges):
        cu, cv = comp[u], comp[v]
        if cu != cv:
            tree[cu].append((cv, w[i]))
            tree[cv].append((cu, w[i]))

    sz = [0] * cid
    dp = [0] * cid

    total_special = sum(comp_special)

    def dfs1(v, p):
        sz[v] = comp_special[v]
        for to, wt in tree[v]:
            if to == p:
                continue
            dfs1(to, v)
            sz[v] += sz[to]

    dfs1(0, -1)

    def dfs2(v, p):
        for to, wt in tree[v]:
            if to == p:
                continue
            dp[to] = dp[v]
            if sz[to] > 0 and total_special - sz[to] > 0:
                dp[to] += wt
            dfs2(to, v)

    dfs2(0, -1)

    ans_comp = [comp_weight[i] - dp[i] for i in range(cid)]

    for v in range(n):
        print(ans_comp[comp[v]], end=" ")

if __name__ == "__main__":
    solve()
```実装は、標準の DFS ローリンク手順を使用してすべてのブリッジを検索することから始まります。 削除によって接続コンポーネントの数が増加するエッジは、ブリッジとしてマークされます。 

次に、すべての非ブリッジ エッジを通過することにより、頂点が 2 つのエッジで接続されたコンポーネントに圧縮されます。 各コンポーネントは、その頂点の合計値と、少なくとも 1 つの特別な頂点が含まれているかどうかを示すフラグを蓄積します。 

圧縮後、エッジが元のグラフのブリッジに正確に対応するツリーが構築され、各エッジは元の重みを保持します。 

最初の DFS は、コンポーネントごとに、サブツリー内に特別な頂点がいくつあるかを計算します。 ブリッジは各側の少なくとも 1 つの特別な頂点を分離する場合にのみ関連するため、これは不可欠です。 

2 番目の DFS はツリーを再ルートし、現在のルート位置に関して「切断」されたブリッジによって寄与されるコストを累積します。 ルートをエッジを越えて移動するとき、そのエッジが特別な頂点を両側に分割するかどうかを更新し、分割する場合はコストを追加します。 

最後に、各コンポーネントの答えは、頂点の合計値から累積コストを引いたもので、この値はそのコンポーネント内のすべての頂点に対して出力されます。

```ブリッジ分解後はすべてのエッジがブリッジになるため、各頂点は独自のコンポーネントを形成します。 特別な頂点は 1 と 3 です。 

| ステップ | コンポーネントの特別なカウント | ブリッジコストを計算 | ルートコンポーネント | 結果 |
 | --- | --- | --- | --- | --- |

 これは、中間の頂点によってブリッジ コストが 1 つの構成で使用されるようになり、エンドポイントと比較して利益が減少する様子を示しています。 

### 例 2

 すべての頂点が特別なサイクルを考えてみましょう。 ブリッジがないため、ルートの選択に関係なく、エッジがコストに寄与することはありません。 

| ステップ | 橋の構造 | 特別配布 | コスト | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 橋がない | すべてのコンポーネントが特別 | 0 | 合計 c[i] |

 これは、高度に接続されたグラフでは、エッジ コストを支払うことなくすべての頂点が飽和していることを示しています。

 ## 特殊なケース

 ブリッジのないグラフが最もきれいなケースです。 すべての頂点は単一のコンポーネントに属しているため、DP によってブリッジ コストが蓄積されることはありません。 このアルゴリズムはグラフ全体を 1 つのノードに圧縮し、すべての頂点が同じ合計値を受け取ります。これは、エッジ コストを支払うことなくすべての頂点間の到達可能性を維持できるという事実と一致します。 

木はその対極にあり、すべての端が橋になっています。 この場合、特別な頂点がエッジ全体にどのように分割されるかに応じて、すべてのエッジがコストに寄与する可能性があります。 DFS 累積では、特別な頂点をツリーの異なる部分に分割するときに、各ブリッジが 1 回だけ正確にカウントされ、問題の最悪の場合の感度が一致します。 

すべての特別な頂点が 1 つのコンポーネント内にある構成は、ブリッジが強制されないことを示しています。 特殊な頂点のサブツリー数により、特殊なノードを区切るエッジがないため、すべてのブリッジの寄与がゼロになることが保証されるため、答えは純粋に頂点の値になります。
