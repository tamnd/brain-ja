 ## 解決策
 ## 問題の理解

 私たちは時間が 3 つの層で構成されている架空の暦体系を与えられています。 一年は`m`月、各月には正確に含まれます`d`日ごとに週が繰り返されます`w`日々。 年の最初の日は平日インデックス 1 から始まり、それ以降のすべての平日が周期的に続きます。`w`。 

このシステム内の各日は、月内での位置とグローバルな曜日ラベルの 2 つの異なる方法で識別できます。 月は均一であるため、平日の計算で重要なのは、年間の線形日インデックスだけです。 

タスクは、異なる月のすべてのペアを考慮することです`(x, y)`と`x < y`、それらの間の対称条件を確認します。 ペアをカウントするには、「y 月 x 日」の曜日が「x 月 y 日」の曜日と一致する必要があります。 この対称性を満たすペアがいくつあるかを数えなければなりません。 

このステートメントはカレンダー用語で表現されていますが、すべては 1 次元のタイムライン上の算術に帰着します。毎日にはグローバルなインデックスがあり、平日はそのインデックスの法にのみ依存します。`w`。 

制約は非常に大きく、それぞれの制約は`m`、`d`、 そして`w`まで`10^9`そして最大まで`1000`テストケース。 月のペアを直接調べるアプローチ。`m`、無理です。 線形依存性さえも`m`最悪の場合、テスト ケースごとのサイズが大きすぎます。 

単純な試みでは、すべてのペアをチェックしようとするでしょう`(x, y)`モジュラー演算を使用して曜日の差を計算します。 それは次のことにつながります`O(m^2)`テストごとの操作。これは次の場合にはまったく実行不可能です。`m`大きいです。 

微妙な失敗例は、平日を月ごとにシミュレートしようとした場合に発生します。 毎月のシフトは単純ですが、複数のオフセットを蓄積すると、`m`数か月経ってもすべてのペアをチェックすると、依然として 2 次作業や制約を破る大量の事前計算が発生します。 

## アプローチ

 最大の問題は、「y 月の x 日」と「x 月 y 日」の両方が同じ線形カレンダーに依存しているため、同じ等差数列から構築されているが、交換されたインデックスで評価された 2 つの式を比較していることです。 

毎月割り当ててみましょう`i`その年の開始オフセット。 毎月あるので、`d`日、月の初め`i`は`(i-1) * d`。 したがって、その日のグローバルインデックスは、`k`月に`i`は：`A(i, k) = (i-1) * d + k`この日の平日は、`A(i, k) mod w`。 

ペアの条件は`(x, y)`は次のようになります:`A(y, x) ≡ A(x, y) (mod w)`両側を展開すると：`(y-1)d + x ≡ (x-1)d + y (mod w)`並べ替え:`(y-x)d + x - y ≡ 0 (mod w)`要素：`(y-x)(d - 1) ≡ 0 (mod w)`これで構造が明確になります。条件は違いのみに依存します。`t = y - x`、絶対的な位置ではありません。 すべての有効なペアは、月間のギャップによってのみ決定されます。 

したがって、それぞれについて`t > 0`、ペアの数を数える必要があります`(x, x+t)`存在する、つまり`m - t`を確認し、次のことを確認します。`t * (d - 1) ≡ 0 (mod w)`したがって、問題は有効な差異を数えることに帰着します。`t`生成されるペアの数によって重み付けされます。 

ブルートフォースはすべてを反復します`t`から`1`に`m-1`すでに設定されている状態を確認します`O(m)`テストケースごとに、それでも大きすぎる場合`m`は`10^9`。 

重要な洞察は、すべてを分類することです`t`モジュールの可分性条件を満たします。 必要なものは次のとおりです。`w | t * (d - 1)`させて`g = gcd(w, d - 1)`。 この場合、条件は次のように単純化されます。`(w / g) | t`とても有効です`t`まさに次の倍数です`k = w / gcd(w, d - 1)`。 

ここで、問題は純粋に算術になります。次のすべての倍数を数えます。`k`まで`m-1`、そしてそのようなそれぞれについて`t`、 追加`m - t`。 

これにより、計算全体が次の倍数にわたる等差数列の合計に減ります。`k`。

 ## アルゴリズムのチュートリアル

 ここで、算術リダクションを直接計算に変換します。 

1. コンピューティング`a = d - 1`。 これが導出された合同式に現れるシフトです。 もし`a = 0`の場合、すべての月ごとのオフセットが式内で消えるため、平日の条件が大幅に簡素化されます。 
2. コンピューティング`g = gcd(w, a)`。 これにより、週の長さと月のシフトの間の共通の可分性構造が抽出されます。 
3. 定義する`k = w // g`。 これは、すべての有効な差分が一致する最小ステップ サイズです。`t`の倍数でなければなりません`k`。 
4. もし`k > m - 1`、有効な違いはありません。 戻る`0`。 有効な最小値は次のとおりです。`t`すでに月のギャップの可能性の範囲を超えています。 
5. それ以外の場合は、すべての倍数を考慮します`t = k, 2k, 3k, ... ≤ m-1`。 そのような最大の倍数を次のようにします`q = (m-1) // k`。 
6. それぞれについて`i`から`1`に`q`、`t = i * k`貢献する`(m - t)`有効なペア。 これらの貢献を合計します。 
7. 等差級数を使用して合計を計算します。 

答えは次のようになります。`sum_{i=1..q} (m - i*k) = q*m - k * (q*(q+1)//2)`。 
8. テスト ケースに対してこの値を出力します。 

### なぜ効果があるのか

 変換全体は、元の合同を次の可算条件に還元することに依存します。`t`。 一旦次のように書き換えると`w | t(d-1)`、元のカレンダーのすべての構造は、間の gcd 相互作用を除いて消えます。`w`そして`d-1`。 これにより、すべての有効なペアが一意の違いによって正確に 1 回カウントされることが保証されます。`t`、その差がモジュラー制約を満たさないため、無効なペアはすべて除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        m, d, w = map(int, input().split())
        a = d - 1
        g = gcd(w, a)
        k = w // g

        if k > m - 1:
            out.append("0")
            continue

        q = (m - 1) // k
        ans = q * m - k * (q * (q + 1) // 2)
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は代数的縮約を直接反映しています。 唯一の重要な変換は、モジュラー条件を gcd ベースのステップ サイズに置き換えることです。`k`。 それが計算されると、残りはすべての有効な差分からの寄与の閉じた形式の合計になります。 

注意が必要です`m - 1`月の差がその制限を超えることはできないためです。 もう 1 つの微妙な点は、全体を通して整数演算を使用していることです。 Python の big integer を使用する場合、すべての中間値は 64 ビット整数に快適に収まりますが、他の言語ではオーバーフロー管理が不可欠です。

from math import gcd

    import sys as _sys

            out.append("0")
        else:
            q = (m - 1) // k

    return "\n".join(out)

## 特殊なケース

 主なエッジケースは次の場合に発生します。`d = 1`。 それから`d - 1 = 0`なので、毎期`t(d-1)`はゼロであり、モジュラー条件は常に成り立ちます。 アルゴリズムはこれを処理します。`g = gcd(w, 0) = w`、 それで`k = 1`。 すべての違いは有効であり、式はすべてのペアをカウントすることになります。`(x, y)`、つまり`m(m-1)/2`。 

もう 1 つのエッジケースは次のような場合です`w = 1`。 週は 1 日だけなので、平日はすべて同じです。 また`k = 1`、アルゴリズムはすべてのペアを正しくカウントします。 

いつ`m = 1`、有効なペアがありません。 式は次のようになります。`(m-1) = 0`、 それで`q = 0`そして結果は`0`。 

最後に、いつ`k > m - 1`、有効な違いは存在しません。 これは、最小の月差でも条件を満たせない非常に制限的なモジュール構造に相当します。 早期にリターンすることで、無効な合計を試行することがなくなります。
