 ## 解決策
 ## 問題の理解

 最初の要素から開始して、正の整数の配列に沿ったウォークをシミュレートするように求められます。 各移動は、右に 1 ステップ移動できます (最後の要素にいない場合は常に許可されます)。または、左に 1 ステップ移動できます (最初の要素にいない場合、および前の移動が左移動でない場合にのみ実行できます)。 各ステップでは、到達した配列要素の値だけ実行スコアが増加します。 合計移動数は指定された数と等しくなければなりません$k$、残りの移動の合計数は次を超えることはできません。$z$。 タスクは、正確にスコアを最大化することです。$k$動く。 

入力サイズは次のように大きくできます。$n = 10^5$テスト ケースごとに、最大で$10^4$テスト ケースの合計$n$すべてのテストケースにわたって、$3 \cdot 10^5$。 これにより、テスト ケースごとの複雑さが線形よりも悪いソリューションは除外されます。$O(n^2)$または$O(nk)$結果として$10^{9}$またはそれ以上の操作。これは 2 秒の制限時間をはるかに超えています。 

見落としやすいエッジケースには、次のような配列が含まれます。$z = 0$、すべての移動を強制的に右に移動するか、左に移動する配列は 1 回か 2 回しか役に立たない可能性があります。過度の左移動は禁止されており、2 回連続の左移動は許可されていません。 たとえば、配列の場合`[1, 100, 1]`、$k = 2$、 そして$z = 1$、最適なシーケンスは右、左であり、スコアは 1 + 100 + 1 = 102 になります。常に最初に右に移動する素朴な貪欲なアプローチでは、1 + 100 = 101 しか得られず、最適な解が見つかりません。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべてのシーケンスが生成されます。$k$左移動制約を尊重し、対応するスコアを合計します。 シーケンスの数は次のように指数関数的に増加します。$k$、指定された境界ではこれは完全に不可能になります。 

重要な洞察は、左に移動することによる唯一の利点は、左の移動とその直前の右の移動を組み合わせることによって得られ、効果的に最大で反復できる「左右のペア」を形成することであるということです。$z$回。 すべての左の動きの直前に右の動きを行う必要があるため、できるだけ右に動きながら、そのようなペアを何回実行できるかを考慮するだけで済みます。 さらに、合計が最も大きいペアのみ$a[i] + a[i+1]$最大の隣接ペアを繰り返し使用すると、左の移動によるゲインが最大化されるため、これは重要です。 

この観察により、最適な戦略は、0 から 0 までのあらゆる数の左移動を試行することになります。$z$。 左の移動の候補数ごとに、その後に利用可能な右の移動の数を計算し、到達可能な最も遠いインデックスを決定します。 次に、許可される左の最大移動数と総移動数を考慮して、最初のプレフィックスと繰り返された左右のペアからの寄与の合計として合計スコアを計算します。$k$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k) | O(k) | 遅すぎる |
 | 最適 | O(n * z) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のプレフィックスの合計を事前計算します。 これにより、左に移動せずに任意の位置まで移動した場合の合計スコアをすばやく計算できます。 プレフィックス合計は、このタイプの累積和問題の標準であり、加算の繰り返しを減らします。$O(n)$に$O(1)$。 
2. すべての隣接するペアを識別する$a[i] + a[i+1]$インデックスに到達した後に左に移動するため$i+1$このペアの合計を繰り返し求めることができます。 すべてのインデックスまでに観察された最大ペア合計を追跡します。 
3. 左の移動回数を繰り返します。$lz$0から$z$。 左に移動するたびに合計 2 つの移動が消費されます。1 つは新しいインデックスに到達するための右への移動、もう 1 つは左に移動して戻ります。 したがって、到達できる最も遠いインデックスは、$lz$左の動きは$k - 2 * lz$。 たとえば、次の場合$k = 7$そして$lz = 2$、最初に到達できる右端の位置はインデックスです。$7 - 4 = 3$。 
4. それぞれについて$lz$、右の動きだけで到達可能な最も遠いインデックスまでの要素の合計と、左右のペアによる合計の合計としてスコアを計算します。 左の動きによる貢献度の合計は次のとおりです。$lz * \text{maximum pair sum among visited positions}$。 
5. すべての選択肢の最大スコアを追跡します。$lz$。 これがそのテストケースの答えです。 

機能する理由: すべての左移動は、訪問した位置の中で利用可能な最大の隣接ペアから利益を得るために厳密に使用されます。 0 から 0 までの左の動きのすべてのカウントを試します。$z$制約に違反することなく、すべての実行可能な戦略を検討することが保証されます。 プレフィックスの合計は、すべての右のみの移動を効率的に処理します。 これにより、考えられるすべてのシーケンスを生成することなく、すべての最適な組み合わせが徹底的に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, z = map(int, input().split())
        a = list(map(int, input().split()))
        prefix = [0] * n
        prefix[0] = a[0]
        for i in range(1, n):
            prefix[i] = prefix[i-1] + a[i]
        max_score = 0
        max_pair = 0
        for i in range(k + 1):
            if i < n - 1:
                max_pair = max(max_pair, a[i] + a[i+1])
            left_moves = min(z, i // 2)
            right_index = i - 2 * left_moves
            if right_index < 0:
                continue
            score = prefix[right_index] + left_moves * max_pair
            max_score = max(max_score, score)
        print(max_score)

if __name__ == "__main__":
    solve()
```コードは最初にプレフィックスの合計を計算します。これは、厳密に右に移動するスコアを決定するために使用されます。 変数`max_pair`潜在的な左移動に対する最良の隣接合計を追跡します。 到達可能な各位置について`i`移動すると、左に何回移動できるかを計算します (`left_moves`) を計算し、合計スコアを計算します。 スコアは、最も右のインデックスまでのプレフィックスの合計と、左の移動からの寄与を組み合わせたものです。 最後に、すべての実行可能な左移動カウントの最大値が出力されます。
