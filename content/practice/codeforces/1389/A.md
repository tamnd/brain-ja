 ## 解決策
 ## 問題の理解

 整数の独立した範囲が多数与えられます。 それぞれの範囲について$[l, r]$、2 つの異なる整数を選択する必要があります$x$そして$y$この間隔内では、それらの最小公倍数も同じ間隔内になります。 

したがって、タスクは和や差のようなものを最適化することではなく、LCM 演算の下で「安定した」ペアを見つけることです。つまり、両方の入力が範囲内にあり、LCM が範囲から逃れることはありません。 

出力は、そのようなペアか、有効なペアが存在しないという宣言のいずれかです。 複数の有効な解決策が存在する場合は、自由に印刷できます。 

ここでの制約は非常に重要です。 最大で$10^4$テスト ケース、および各範囲エンドポイントは次のような大きさにすることができます。$10^9$。 これにより、範囲内のすべてのペアまたはすべての候補を試行するソリューションは除外されます。 最悪の場合の範囲がテスト ケース全体に及ぶ場合、テスト ケースごとに 1 つの大きな間隔を反復することさえ不可能です。$10^9$規模。 

単純なペアチェックでは、すべてが検査されます。$(x, y)$で$[l, r]$、毎回 LCM を計算します。 これは間隔のサイズが 2 次であり、直ちに実行不可能です。 

間隔が狭すぎる場合、微妙なエッジケースが表示されます。 たとえば、次の場合$r = l + 1$、可能なペアは 1 つだけです$(l, l+1)$。 これはうまくいく場合もあれば、失敗する場合もあります。 たとえば、$[88, 89]$、唯一のペアは 88 と 89 であり、それらは互いに素であるため、その最小公倍数は次のようになります。$88 \cdot 89$、これは範囲をはるかに超えているため、答えは次のようになります。$-1, -1$。 

もう 1 つのエッジ ケースは、間隔は小さいが、約数の関係を持つ数値が含まれる場合です。$[2, 4]$。 ここで選択します$x=2, y=4$機能するので$\mathrm{LCM}(2,4)=4$、区間内に留まります。 

最も難しいのは、候補を列挙せずに、そのような「LCM の下で閉じられた」ペアがいつ存在するかを判断することです。 

## アプローチ

 すべてのペアを総当り攻撃で試す$(x, y)$範囲内で$[l, r]$かどうかを確認します$\mathrm{LCM}(x, y)$同じ範囲内にあります。 これは問題の条件に直接従うため、正解です。 ただし、間隔にサイズがある場合は、$k$、これには必要です$O(k^2)$各チェックには LCM の計算が含まれます。 最悪の場合$k$サイズが大きくなる可能性があるため、このアプローチは不可能になります。 

重要な観察は、実際には間隔内を検索する必要がないということです。 問題の構造は、唯一有用な候補ペアが非常に単純なものであることを強く示唆しています。 のような成功例を見てみると、$(2,4)$または$(6,7)$、数字が連続しているか、一方が他方の倍数であるかのいずれかのパターンに気づきます。 

ペアを試してみると$(l, 2l)$、面白くなります。 の最小公倍数$l$そして$2l$いつもです$2l$、 以来$2l$はすでに次の倍数です$l$。 これにより、LCM が大きい要素と等しいことが直ちに保証されます。 したがって、条件は次のことを確認することになります。$2l \le r$。 

これにより、問題全体がテスト ケースごとに 1 回の構築試行に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((r-l)^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(1)$テストケースごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 値を読み取る$l$そして$r$。 これらは、数値と LCM の両方の許容範囲を定義します。 
2. 範囲内の最小の数値を使用して候補ペアの構築を試みます。 設定しました$x = l$なぜなら、有効な解は可能な限り実現可能性を失わずに下方にシフトでき、最小値から開始することで最小公倍数を区間内に維持する最良のチャンスが得られるからです。 
3.セット$y = 2l$。 この選択により、一方の数値が他方の数値を除算するため、クリーンな LCM 構造が保証されます。 gcd や LCM を明示的に計算することは避けます。 
4. かどうかを確認します。$y \le r$。 これが当てはまる場合、両方の数値が範囲内にあり、それらの最小公倍数は正確に一致します。$y$、これも範囲内にあります。 
5. 条件が失敗した場合、出力$-1, -1$、このタイプの構造は区間内に収まらないためです。 

### なぜ効果があるのか

 正確かどうかは、有効なペアがいずれか 1 つの数値をもう 1 つの数値で割るか、区間サイズを超えて増大する LCM を生成する必要があるという事実に依存します。 建設$(l, 2l)$は、可能性のある最小の非自明な多重関係です。 この最小の倍加さえ超えれば$r$、次に関係する他のペア$l$それ以上の値を指定すると、さらに大きな LCM が生成されるだけです。 したがって、有効なペアは存在できません。 逆に言うと、$2l \le r$、ペア$(l, 2l)$割り算が保証されているため、常に有効です$\mathrm{LCM}(l, 2l)=2l$、範囲内に留まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    l, r = map(int, input().split())
    
    if 2 * l <= r:
        out.append(f"{l} {2*l}")
    else:
        out.append("-1 -1")

print("\n".join(out))
```この解決策はもっぱら、意味のある唯一の候補は次のとおりであるという観察によって導かれています。$(l, 2l)$。 このコードでは、割り算構造が明示的に構築されているため、gcd または LCM の計算が回避されます。 

唯一の微妙な点は、整数の乗算が一般的な範囲をオーバーフローしないようにすることですが、Python は大きな整数を安全に処理します。 小切手$2*l \le r$は完全な決定ロジックです。

```施工テストを行っております$x = 1$、$y = 2$。

 | 構築 | 1 | 2 | - |
 | チェック | 1 | 2 | 2 ≤ 1337 |

 条件が成り立つので出力します$1, 2$。 LCM は 2 であり、範囲内にあります。 

これは、間隔が十分に大きいため、最小要素の 2 倍が有効な場合を示しています。 

### 例 2

 入力:```

```私たちは建設します$x = 88$、$y = 176$。 

| ステップ | × | y | 状態 |

 条件が満たされないので、出力します。$-1, -1$。 使用可能な唯一のペアが存在しないか、範囲をはるかに外れた LCM を生成するため、他のペアは不可能です。 

これは、間隔が狭い障害のケースを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    res = []
    for _ in range(t):
        l, r = map(int, input().split())
        if 2 * l <= r:
            res.append(f"{l} {2*l}")
        else:
            res.append("-1 -1")
    return "\n".join(res)

# provided samples
assert run("""4
1 1337
13 69
2 4
88 89
""") == """1 2
13 26
2 4
-1 -1"""

# minimum size interval
assert run("""1
1 2
""") == "1 2"

# tight impossible interval
assert run("""1
5 6
""") == "-1 -1"

# large exact boundary
assert run("""1
10 20
""") == "10 20"

# large range where l is big
assert run("""1
1000000000 1000000000
""") == "-1 -1"

 ## 特殊なケース

 次のように、間隔に連続する数字が 2 つだけ含まれる場合、$[88, 89]$、建設が生み出す$y = 2l = 176$、すぐに範囲を超えます。 アルゴリズムはこのケースを正しく拒否します。$2l \le r$失敗したため出力されます$-1, -1$。 88 で制限された LCM を形成できる範囲内に 2 番目の整数が存在しないため、代替ペアは不可能です。 

間隔がぴったりの場合$[l, l+1]$、唯一の可能なペアが強制され、アルゴリズムは 2 倍化ルールを通じてそのペアを暗黙的にテストします。 以来$2l > l+1$みんなのために$l \ge 1$、そのようなすべての間隔は、次のような特別な分割可能な構造に退化しない限り、正しく拒否されます。$[2,4]$、 どこ$2l = 4 \le r$、有効な解決策が生成されます。
