 ## 問題の理解

 サイズのグリッドとして表される長方形の箔シートが与えられます。$n \times m$。 一部のセルには、次のようにマークされた欠陥が含まれています。`X`、他のものはきれいです。 このシートから、インゴットとして適格な長方形の金属片を抽出したいと考えています。 

インゴットは幾何学的制約を満たす必要があります。つまり、その辺の 1 つが正確​​な長さでなければなりません。$k$。 もう一方の側は可変長と呼びますが、自由に選択できます。 ただし、品質の制約があります。インゴットに含まれるのは最大でも次のとおりです。$x$不完全さ。 

タスクは、少なくとも 1 つの有効な辺の長さが存在するように、この可変辺の長さの可能な最大値を決定することです。$k \times L$または$L \times k$以下を含むサブ長方形$x$ `X`細胞。 

入力サイズの制約$n \cdot m \le 10^5$グリッドが十分にまばらであることを意味します$O(nm)$前処理は許容されますが、すべての部分四角形を個別にチェックしようとすると遅すぎます。 すべての単純な列挙$O(n^2 m^2)$長方形は不可能であり、前処理なしの 3 次元スライディング ウィンドウですら限界を超えてしまいます。 

重要なエッジケースは、固定寸法がグリッド境界とどのように相互作用するかによって生じます。 もし$k$が 1 の場合、問題はストリップの選択にまで発展します。$k$に近いです$\max(n,m)$、有効な方向はごくわずかです。 もう 1 つの微妙なケースは、最適な長方形がグリッドの高さまたは幅全体にまたがる場合です。これは、多くの単純なスライディング ウィンドウ アプローチでは、両方の寸法が対称的に変化する可能性があると誤って想定しているためです。 

小さな例として、すべての欠陥が 1 つの列に集中しているグリッドがあります。 もし$k$が行数である場合、すべての候補四角形にはその列が含まれ、答えは純粋に垂直方向の累積に依存します。 プレフィックス構造を使用せずに四角形ごとのカウントを再計算する単純なアプローチでは、同じ列の寄与を繰り返しカウントするのが誤ったり、遅すぎたりします。

 ## アルゴリズムのチュートリアル

 この問題を 2 つの方向で解決します: 高さの水平ストリップを固定する$k$、および幅の垂直ストリップを固定します$k$。 両方を考慮して最良の回答を採用します。 

1. グリッド上に 2D プレフィックス構造を構築して、その数をクエリできるようにします。`X`セルは列の任意の垂直セグメントに一定時間存在します。 これは、各列の行に沿ってプレフィックスの合計を個別に計算することによって行われます。 
2. 考えられる最上位行ごとに$r$、行間の各列の不完全性の数を計算します。$r$そして$r + k - 1$。 これにより、各エントリがその列をその列に含めるコストを表す 1D 配列が生成されます。$k$-行から始まる背の高いストリップ$r$。 この手順が必要な理由は、高さが固定されると、列が合計数に独立して寄与するようになるためです。 
3. この 1D 配列では、2 つのポインターを持つスライディング ウィンドウを使用します。 欠陥の総数が以下の範囲内で右ポインタを展開します。$x$。 制約に違反した場合は、制約が再び満たされるまで左ポインタを前に動かします。 各ステップで、ウィンドウの最大長を記録します。 これが機能するのは、すべての値が負ではないため、ウィンドウを拡大しても合計が増加または維持されるだけです。 
4. グリッドを転置した後、同じ手順を繰り返します。これにより、長さの固定側が異なる場合が処理されます。$k$垂直ではなく水平です。 この問題ではどちらの次元も正確に一致できるため、この対称性は不可欠です。$k$。 
5. 両方の方向から得られた最大長を返します。 

### なぜ効果があるのか

 一回$k$- ストリップの高さは固定されており、実行可能なすべてのインゴットは柱の連続セグメントに正確に対応します。 どのセグメントのコストも列に対して加算され、すべての寄与は負ではありません。 これにより、単調な構造が作成されます。セグメントを拡張しても不完全性の数は決して減少しません。 したがって、スライディング ウィンドウは、現在のセグメントが常に右ポインタで終わる最長の有効なセグメントであるという不変条件を維持し、すべての有効なセグメントは右ポインタが移動するたびに 1 回だけ考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_orientation(grid, n, m, k, x):
    # prefix sums per column
    pref = [[0] * m for _ in range(n + 1)]
    for i in range(n):
        row = grid[i]
        for j in range(m):
            pref[i + 1][j] = pref[i][j] + (1 if row[j] == 'X' else 0)

    best = 0

    for top in range(n - k + 1):
        col_cost = [0] * m
        bottom = top + k
        for j in range(m):
            col_cost[j] = pref[bottom][j] - pref[top][j]

        # sliding window over columns
        l = 0
        s = 0
        for r in range(m):
            s += col_cost[r]
            while s > x:
                s -= col_cost[l]
                l += 1
            best = max(best, r - l + 1)

    return best

def solve():
    n, m, k, x = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ans1 = solve_orientation(grid, n, m, k, x)

    transposed = [''.join(grid[i][j] for i in range(n)) for j in range(m)]
    ans2 = solve_orientation(transposed, m, n, k, x)

    print(max(ans1, ans2))

if __name__ == "__main__":
    solve()
```この実装では、最初に列ごとにプレフィックスの合計を構築し、垂直セグメントを列ごとに一定時間で評価できるようにします。 機能`solve_orientation`次に、すべての可能な開始行を反復処理します。$k$-高さウィンドウを作成し、そのウィンドウをコストの 1D 配列に圧縮します。 列上のスライディング ウィンドウにより、有効なセグメントを常に維持できるようになります。$x$不完全さ、貪欲に拡大し、必要な場合にのみ縮小します。 

実装の微妙な詳細は、プレフィックスの合計が次のようにインデックス付けされることです。`pref[i+1][j] - pref[i][j]`、高さのウィンドウを抽出する際の 1 つずつずれた間違いを回避します。$k$。 もう 1 つの重要な詳細は転置です。水平方向と垂直方向の場合に個別のロジックを記述するのではなく、回転したグリッド上で同じ関数を再利用します。これにより、重複したロジック エラーが防止されます。

 ## 特殊なケース

 重要なエッジ ケースは、最適な長方形が可能な幅全体に広がっているにもかかわらず、少数の不完全さによってのみ制約される場合です。 その状況では、スライディング ウィンドウは特定の点以降は決して縮小せず、答えはグリッドの全幅になります。 合計が以下に留まる間、右ポインタは拡大し続けるため、アルゴリズムはこれを自然に処理します。$x$、人為的な停止条件は導入されません。
