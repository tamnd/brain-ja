 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバランスのとれた括弧文字列が与えられます。 どちらの文字列も通常の括弧シーケンスであることが保証されています。つまり、すべての接頭辞には少なくとも閉じ括弧と同じ数の開始括弧があり、合計数は一致します。 

それ自体が有効な通常の括弧シーケンスである 2 つの互いに素な部分文字列を繰り返し取得し、文字列内でそれらの位置を交換することができます。 この操作では、選択された各ブロックの内部構造が保存されますが、バランスの取れた「チャンク」全体の順序を変更できます。 

タスクは、そのようなスワップを任意の数だけ使用して、ある有効なブラケット シーケンスを別のブラケット シーケンスに変換できるかどうかを判断することです。 

重要な制約は、最大 5×10^5 までのすべてのテスト ケースにわたる合計の長さです。 これにより、テスト ケースごとに O(n) または O(n log n) の解が強制されます。 バランスの取れた括弧シーケンス内の有効な部分文字列の数は 2 次になる可能性があるため、部分文字列のスワップをシミュレートしたり、部分文字列を検索したりする試みは直ちに実行できなくなります。 

シーケンスが全体的なバランスでは類似しているように見えても、還元不可能なバランスの取れたコンポーネントへの分解が異なる場合、微妙なエッジ ケースが発生します。 たとえば、「()()()」と「((()))」はカウントは同じですが、構造分解が異なります。 「(」と「)」のカウントのみをチェックする単純なアプローチでは、すべての入力が同じカウントを共有するため、誤ってすべてに対して「YES」と判定されてしまいます。 

もう 1 つの失敗例は、プリミティブ コンポーネントの任意の置換が可能であると想定している場合です。 これは、操作によって実際に何が保存されるかを特徴づけない限り真実ではありません。 

## アプローチ

 この操作により、2 つの互いに素なバランスの取れた部分文字列を交換できます。 これは、シーケンスを原子のバランスの取れたコンポーネントに分解するという観点から考えることをすぐに示唆します。 

自然な総当たりアプローチは、すべての有効な部分文字列をノードとして扱い、有効なブロックのスワップによって到達可能なすべての文字列に対して BFS または DFS を試みることです。 各スワップでは O(n^2) 個のブロックの選択肢が生成され、各状態は文字列であるため、状態空間は指数関数的に拡大します。 近傍の生成でさえ、状態ごとにすでに Θ(n^2) であるため、これはまったく使用できなくなります。 

重要な観察は、すべての通常のブラケット シーケンスがプリミティブ RBS ブロックへの一意の分解を持ち、各ブロックがバランスをゼロに戻す最小の有効なプレフィックスであるということです。 これらのプリミティブ ブロックは、操作中は分割できない単位のように動作します。 

スワップ操作では、このようなプリミティブ ブロックの任意の 2 つを交換できますが、ブロック内の再配置やブロックをより小さな部分に分割することはできません。 これは、プリミティブ ブロックのマルチセットが不変であることを意味し、問題は 2 つのシーケンスがプリミティブ RBS コンポーネントの同じマルチセットを共有するかどうかを確認することに帰着します。 

次に、問題をプリミティブ ブロックの正規シグネチャの計算とその頻度の比較に縮小します。

 | --- | --- | --- | --- |
 | ブルートフォース状態検索 | 指数 | 指数 | 遅すぎる |
 | プリミティブ ブロック マルチセット マッチング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 「(」が +1 に寄与し、「)」が -1 に寄与するバランス カウンターを維持しながら、文字列を左から右にスキャンします。 

カウンタがゼロに達した瞬間に、原始的な RBS ブロックが発見されました。 これは、この位置で終わる最小のプレフィックスであり、それ自体が有効な RBS です。 
2. 両方の文字列のこのようなすべてのプリミティブ ブロックを抽出します。 

有効な RBS では、プリミティブ コンポーネントのブロック境界でのみバランスがゼロに戻るため、この分解は独特です。 
3. 各プリミティブ ブロックに対して、正規表現を計算します。

これは、ブロックが連続しており、すべてのテスト ケースの合計サイズが O(n) であるため、完全な部分文字列を記録するか、同様にブロックを直接ハッシュすることによって行われます。 
4. 両方の文字列について、各プリミティブ ブロック表現の出現をカウントします。 
5. 2 つのマルチセットを比較します。 完全に一致する場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 不変条件は、この操作ではバランスのとれた部分文字列全体のみを交換することです。 通常の括弧シーケンス内の有効な部分文字列は、プリミティブ RBS ブロックの連結に分解できます。 2 つの有効な部分文字列を交換すると、これらのプリミティブ ブロックのグループが効果的に交換されますが、境界を越えて分割またはマージされることはありません。 

したがって、プリミティブ ブロックのマルチセットは、任意の数の操作の下で保存されます。 逆に、2 つの文字列に同一のプリミティブ ブロックのマルチセットがある場合、有効性を損なうことなく一連の素なスワップを通じて任意の 2 つのブロックを所定の位置に配置できるため、スワップを繰り返すことでそれらのブロックを任意に並べ替えることができます。 これにより、到達可能な状態間の等価性とブロック マルチセットの等価性が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_blocks(s: str):
    bal = 0
    start = 0
    blocks = []
    for i, ch in enumerate(s):
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        if bal == 0:
            blocks.append(s[start:i + 1])
            start = i + 1
    return blocks

def solve():
    s = input().strip()
    t = input().strip()

    bs = get_blocks(s)
    bt = get_blocks(t)

    if len(bs) != len(bt):
        return "NO"

    from collections import Counter
    return "YES" if Counter(bs) == Counter(bt) else "NO"

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        tt = input().strip()
        out.append(solve_for_case(s, tt))
    print("\n".join(out))

def solve_for_case(s, t):
    from collections import Counter
    return "YES" if Counter(get_blocks(s)) == Counter(get_blocks(t)) else "NO"

if __name__ == "__main__":
    main()
```実装ではまず、バランスを追跡し、ゼロに戻るたびにカットすることにより、各文字列をプリミティブのバランスの取れたセグメントに分解します。 プリミティブ ブロック内ではバランスがゼロに到達できないため、これは通常の括弧シーケンス内で構造的に意味のある唯一のパーティションです。 

各ブロックは部分文字列として保存されます。 すべてのテスト ケースにわたるすべてのブロックの合計長は O(n) であるため、それらを直接保存しても安全です。 

次に、ハッシュ テーブルを使用してブロックの周波数マップを比較します。 両方の文字列にプリミティブ コンポーネントの同一のコレクションが含まれている場合、変換が可能です。 

一般的な実装の落とし穴は、プレフィックスでバランスの取れたセグメントと任意のバランスのとれた部分文字列を混同することです。 許可された操作では、プレフィックス最小バランス セグメントのみがアトミック ユニットに対応します。

 ## 特殊なケース

 重要なエッジ ケースは、両方の文字列の合計カウントが同じであるが、プリミティブ セグメンテーションが異なる場合です。 たとえば、「(()())」は 1 つのプリミティブ ブロックですが、「()()()」は 3 つのプリミティブです。 バランスが異なる位置でゼロに達するため、アルゴリズムは異なるマルチセットを正しく生成します。 

もう 1 つのケースは、ブロックが同一であるが、異なる順序で表示される場合です。 たとえば、「(())()()」と「()()(())」は同じブロックのマルチセットを生成し、カウンタの比較では順序が正しく無視され、スワップによってブロック全体の順序が任意に変更される可能性があるという事実と一致します。 

最後のエッジケースは最小入力「()」であり、分解により単一のブロックが生成されます。 すべての変換ではこのシングルトン構造を保持する必要があるため、同一の文字列のみが受け入れられます。
