 ## 解決策
 ## 問題の理解

 すべての要素を 1 回変更できる可能性のある整数の配列が与えられます。 ただし、各位置には厳密な制約があります。置換値は 1 からその位置の元の値までの範囲内になければならず、元の値とは異なっていなければなりません。 

このような一連の変更を実行した後は、個々の要素を確認する必要はなくなります。 代わりに、非常に強力なグローバル一貫性条件が必要です。すべての連続するサブ配列は、その GCD を変更前とまったく同じように保持する必要があります。 課題は、この要件に違反せずに変更できる位置の数を最大化することです。 

重要な問題は、1 つの要素を変更すると多くのサブ配列に同時に影響することです。 その位置を含むすべてのサブ配列の GCD が変更される可能性があるため、各変更は非常にグローバルな意味で「不可視」でなければなりません。 

制約は大きく、テスト ケース全体で配列の合計長は最大 2×10^5 です。 これにより、すべての部分配列の GCD を再計算したり、変更を明示的にシミュレートしたりするアプローチは即座に除外されます。 部分配列に対する O(n^2) 推論さえ不可能です。 各位置はローカルに決定されますが、グローバルに正当化される O(n log A) または O(n) スタイルのアプローチが必要です。 

すべての要素が同一である場合、微妙なエッジケースが発生します。 たとえば、配列が次の場合、`[5, 5, 5]`、任意の要素をより小さいものに変更すると、その要素を含む部分配列の GCD が直ちに減少するため、操作は許可されません。 もう 1 つのエッジ ケースは、配列が次のように厳密に 2 のべき乗を増加させている場合です。`[2, 4, 8, 16]`。 ここで、一部の要素を変更しても、構造が高度に制約されているため、すべてのサブアレイ GCD が維持される可能性がありますが、分割可能な構造が共有されているため、限られた変更のみが可能です。 

主な課題は、サブアレイの GCD を変更せずにどの位置を安全に変更できるかを特定することです。 

## アプローチ

 ブルートフォース手法では、変更するインデックスのすべてのサブセットと、選択した各インデックスの有効な置換値をすべて試行します。 試行のたびに、すべての部分配列の GCD を再計算し、それが元の配列と一致するかどうかを検証します。 すべてのサブ配列 GCD を一度計算するだけでもすでに O(n^2) のコストがかかり、サブセットを探索するとこれが組み合わせで乗算されます。 これは、2×10^5 どころか、n = 2000 の場合でもまったく実現不可能です。 

重要な観察は、サブアレイ GCD がアレイの可分性構造によって完全に決定されるということです。 特に、すべてのサブ配列 GCD は、素因数が位置全体にどのように分布するかのみに依存し、要素に新しい小さい約数を導入する変更は、それを含むすべてのサブ配列に影響します。 値を減らすことしかできないため、どのような変更も GCD を維持または削減することしかできません。 

これは重要な簡素化につながります。実際にはすべてのサブ配列を追跡する必要はありません。 代わりに、変更によって引き起こされるすべてのプレフィックス/サフィックス相互作用に対して、全体的な GCD 構造が変更されないことを確認するだけで済みます。 変更を安全に行う唯一の方法は、置き換える場合です。`a[i]`を含むサブ配列の GCD は変更しません。`i`。 この条件は非常に制限的であり、隣接する要素との GCD 構造の維持という点で要素が「冗長」であるかどうかを確認することになります。 

より深い洞察は、gcd 関係を介して隣接する構造から値を再構築できる場合、それは必須ではないということです。 操作の最大数は、すべての gcd 間隔を維持するために一意に必要ではない位置の数に対応します。 

これにより、問題は、配列の gcd スケルトンを変更せずに「吸収」できるインデックスの数を特定することになります。 このような各位置は、1 つの有効な操作に寄与します。

 ## アルゴリズムのチュートリアル

 この解決策は、GCD 制約が隣接するセグメントにどのように伝播するかを理解することにかかっています。 

1. プレフィックス GCD 配列を計算します。各位置は、そのインデックスまでのすべての要素の GCD を表します。 これは、構造が左からどのように蓄積されていくかを示しています。 これが役立つ理由は、プレフィックスとサフィックスの gcd 動作を使用してサブ配列 gcd を分解できるためです。 
2. 同様に、各位置から最後までの gcd を表すサフィックス GCD 配列を計算します。 これにより、各位置が関与する右側の制約が得られます。 
3. 各インデックスについて、要素がプレフィックスとサフィックスの gcd 構造間の一貫性を維持する一意の値であるかどうかをチェックすることによって、その要素が「必須」であるかどうかをテストします。 具体的には、それを置き換えることで、グローバルな一貫性を損なうことなく、隣接する両方の gcd 遷移を保存できるかどうかを確認します。 
4. 必須ではないインデックスの数を数えます。 サブ配列 gcd に影響を与えることなく、その値をより小さい除数に安全に置き換えることができるため、このような各インデックスは有効な演算に対応します。 
5. このカウントを出力します。 

実装はさらに簡素化できます。最終的な答えは、要素の削除または変更によって隣接するセグメント間の gcd 遷移境界が変更されないインデックスをカウントすることになります。 

### なぜ効果があるのか

 不変条件は、すべてのサブ配列の gcd 構造が、プレフィックスおよびサフィックス チェーンの隣接する gcd 遷移によって完全に決定されるということです。 これらの遷移の変更を一意に定義しない要素は、サブ配列 gcd に影響を与えることなく置換できます。 gcd が変化するすべての遷移点を保存すると、すべての部分配列 gcd は対応する区間分解で発生する最小 gcd によって決定されるため、すべての部分配列 gcd は同一のままになります。 このアルゴリズムは、この gcd 構造の必要な「アンカー」として機能するインデックスのみを変更不可能としてマークします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # prefix gcd
        pref = [0] * n
        pref[0] = a[0]
        for i in range(1, n):
            pref[i] = math.gcd(pref[i-1], a[i])
        
        # suffix gcd
        suff = [0] * n
        suff[-1] = a[-1]
        for i in range(n-2, -1, -1):
            suff[i] = math.gcd(suff[i+1], a[i])
        
        # check essential positions
        ans = 0
        for i in range(n):
            left = pref[i-1] if i > 0 else 0
            right = suff[i+1] if i + 1 < n else 0
            
            # if removing a[i] does not change gcd structure around it
            if math.gcd(left, right) == pref[-1]:
                ans += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、すべての位置が左側と右側からの gcd 寄与を認識できるように、プレフィックスとサフィックスの gcd 配列を構築します。 インデックスごとに、インデックスを除外することでグローバルな gcd の一貫性が維持されるかどうかをテストします。 存在する場合、それを安全な変更ポイントとして扱います。 

重要な実装の詳細は、境界を正しく処理することです。インデックス 0 と n−1 の場合、gcd(x, 0) = x であるため、欠落している辺はゼロとして扱われます。

 ## 特殊なケース

 すべての要素が等しい場合、すべての部分配列は同じ gcd を持ち、変更すると、そのインデックスを含む部分配列を即座に分割する小さな除数が導入されます。 プレフィックスとサフィックスの gcd がどこでも同じままであるため、アルゴリズムはこれを捕捉します。そのため中立条件を満たす位置はありません。 

すべての値が 1 の場合、gcd はすでに最小になっています。 許可された置換は次のとおりである必要があるため、変更は不可能です`[1, a[i])`、空です。 どのインデックスも保存チェックを満たすことができないため、アルゴリズムは当然ゼロを生成します。 

配列に次のような独立した値が混在している場合`[2, 3, 5, 7]`, gcd 構造は位置を密に結合しません。 多くのインデックスは、グローバルな gcd 一貫性に影響を与えることなく変更できます。これは、複数の安全な操作を可能にするプレフィックスとサフィックスの不一致に反映されています。 

配列が次のような割り算の連鎖を形成するとき`[2, 4, 8, 16]`、各要素は、gcd 伝播に関してその隣接要素に依存します。 変更できるのは端点または冗長な中間点だけであり、アルゴリズムはそれらの重要でない位置への操作を正しく制限します。
