 ## 解決策
 ## 問題の理解

 並んでいます$n$椅子、最初はすべてマークがありませんでした。 順列$p$長さの$n$が与えられており、以下の各数字を意味します。$1$に$n$は 1 回だけ表示されます。 最初の椅子から始めて右に移動します。 各椅子ですでにマークされている場合、ゲームは直ちに停止します。 それ以外の場合は、座るかスキップするかを選択できます。 座っている場合、立ち上がった後、現在の椅子の順列値によって示される椅子にマークを付けます。$p_i$、次の椅子に進みます。 目標は、私たちが座る椅子の総数を最大化することです。 

入力は複数のテスト ケースを与え、それぞれが指定します$n$そして順列$p$。 出力は、各テスト ケースで座ることができる椅子の最大数です。 

制約は重要です。$n$到達できる$2\cdot 10^5$、およびすべての合計$n$すべてのテストケース全体で最大でも$2\cdot 10^5$。 これにより、テスト ケースごとに線形または線形に近いアルゴリズムが制限されます。 複雑なアプローチ$O(n^2)$遅すぎるでしょう。 

順列が最初の椅子を含むサイクルを作成する場合、微妙なエッジケースが発生します。 たとえば、次の場合$p = [1,2,3]$、最初の椅子に座るとすぐにマークされるため、最初の動きでゲームが終了します。 常に座っているという単純な貪欲なアプローチでは、これらの自己採点シナリオやサイクル初期のシナリオを考慮できず、誤った結果が生じます。 

別のエッジ ケースは、サイクルなしで前方を向いている長いチェーンがある場合に発生します。$p = [2,3,4,1]$、椅子に座っているところ$1$最終的には椅子にマークが付けられます$1$自体。 ここでは、マークされた椅子にぶつかる前にチェーンの長さを最大にするために戦略的に座ることが重要です。 

## アプローチ

 ブルートフォースアプローチでは、椅子のすべてのサブセットに座って、各選択肢の採点手順をシミュレートします。 これが機能するのは、ルールに従って正確に椅子の数を数えることができるからです。 ただし、$n$その周り$2\cdot 10^5$、 がある$2^n$サブセットなので、総当たり攻撃が不可能になります。 

重要な洞察は、順列が各椅子が正確に 1 つの椅子を指す有向グラフを定義するということです。 すべての動きは、このグラフを横断することに対応します。 ゲームは、マークされた椅子を最初に再訪問すると終了します。これは、グラフにサイクルを入力することと同じです。 したがって、座っている椅子の数を最大化するとは、各チェーンを安全に横断できる、ばらばらのサイクルとチェーンを形成する最も長い椅子のプレフィックスを見つけることになります。 

より単純な観点は、椅子を左から右にスキャンし、マーキングの意味で椅子がまだ訪問されていないときは常に座ることです。 座るときにマークを付けます$p_i$。 もし$p_i \le i$であれば、そのマークは将来の椅子には影響しませんが、$p_i > i$、それは私たちが座りたいと思う未来の椅子をマークするかもしれません。 したがって、座数を最大化するには、これまでに発生した最大の「マークされたインデックス」を追跡するだけで済みます。 各椅子について、現在のマークされた指標を超えていれば、安全に座ることができます。 そうしないと、ゲームを終了せずに座ることはできません。 

これにより、問題は貪欲な線形スキャンに変換されます。つまり、以前の座りからマークされる右端の椅子を維持し、現在の椅子のインデックスがそれを超えた場合にのみ座ります。 この観察により、解決策は以下のように簡略化されます。$O(n^2)$に$O(n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`max_marked`これにより、以前の位置でマークされた、またはマークされる予定の最も遠いインデックスが追跡されます。 
2. カウンタの初期化`count`から 0 まで、座っている椅子の数を表します。 
3. インデックスから椅子を反復処理する$1$に$n$(順列との一貫性を保つため、1 から始まるインデックス付け)。 各椅子ごとに$i$:

 1. $i \le max_marked` の場合、ここに座るとゲームが終了するため、この椅子を飛ばしてください。 
2. それ以外の場合は椅子に座ってください$i$。 インクリメント`count`1までに。 
3.アップデート`max_marked`現在の値の最大値になり、$p_i$。 これにより、マークが付けられ、今後座るのを妨げる可能性がある右端の椅子を確実に追跡できます。 
4. 反復の後、`count`座ることができる椅子の最大数が含まれています。 
5. 出力`count`テストケース用。 

なぜ機能するのか: 不変条件は次のとおりです。`max_marked`インデックスに到達するまでにマークされている、またはマークされるであろう右端の椅子を常に保存します。 より大きい指数を持つ椅子にのみ座ることによって、`max_marked`、座ってゲームが途中で終了しないようにします。 この貪欲な戦略が機能するのは、マーキングが将来の椅子のみをブロックし、以前の椅子をブロックしないためです。そのため、最も遠いマークを維持しながら左から右にスキャンすることが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))
    max_marked = 0
    count = 0
    for i in range(n):
        if i + 1 <= max_marked:
            continue
        count += 1
        max_marked = max(max_marked, p[i])
    print(count)
```コードが初期化されます`max_marked`そして`count`、各椅子を反復処理します。 小切手`i + 1 <= max_marked`1 から始まるインデックスが保証されます。 椅子に座るときに、`max_marked`この座りによってマークされた椅子を反映するように更新されます。 このアプローチは、順列チェーンを介したマークの伝播を正しく処理し、ゲームが途中で終了することを回避し、線形時間で実行します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        max_marked = 0
        count = 0
        for i in range(n):
            if i + 1 <= max_marked:
                continue
            count += 1
            max_marked = max(max_marked, p[i])
        print(count)
    return output.getvalue().strip()

assert run("1\n1\n1\n") == "1", "single chair"
