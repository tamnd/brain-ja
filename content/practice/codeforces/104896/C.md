 ## 解決策
 ## 問題の理解

 2 つの整数配列が与えられていますが、これらはシンボルのマルチセットとして考える必要があります。 最初の配列から、任意の順列、つまり同じ要素の任意の順序を形成できます。 2 番目の配列から、固定参照シーケンスを取得します。 

このタスクは、最初の配列の個別の順列が何回発生して、2 番目の配列よりも辞書編集的に小さいシーケンスが生成されるかを数えることです。 ここでの辞書編集的な順序は、辞書の順序とまったく同じように動作します。2 つのシーケンスを左から右に比較し、それらが異なる最初の位置によって順序が決定されます。 一方のシーケンスが他方のシーケンスのプレフィックスである場合、短い方が小さいとみなされます。 

したがって、概念的には、辞書順で特定の文字列より厳密に前にあるマルチセットのアナグラムがいくつあるかを数えています。 

この制約により、両方のシーケンスの長さを最大 200,000 にすることができ、値を頻繁に繰り返すことができます。 これにより、順列の列挙や部分的なプレフィックスの明示的な生成が即座に除外されます。 階乗サイズの検索空間ですら完全に実現不可能です。 どのソリューションでも、順列の反復を避け、代わりに順列を組み合わせて集計してカウントする必要があります。 

構築された順列が全長まではターゲット文字列と一致するが、その後は長くなる場合、微妙なエッジ ケースが発生します。 辞書編集順では、ターゲット文字列が順列の接頭辞である場合、順列はより大きいとみなされ、カウントされません。 もう 1 つの特殊なケースは、繰り返される値が多数の同一の順列を作成する場合です。 順列を個別の値パターンではなく個別のシーケンスとして扱うと、階乗除算が使用されない限り、過大なカウントが発生します。 

## アプローチ

 ブルートフォースのアイデアは単純です。マルチセットのすべての個別の順列を生成し、それぞれをターゲット文字列と比較し、小さいものがいくつあるかを数えます。 これは問題の定義に直接従うため、正しいです。 ただし、順列の数は n のオーダーです。 多重度で割ります。 n が 20 程度であってもこれは膨大となり、n が 200,000 までになると状態空間を表現することさえ不可能になります。 

重要な観察は、辞書編集上の比較は左から右に段階的に決定できるということです。 完全な順列を構築する代わりに、順列がターゲットと異なる最初の位置を決定できます。 各位置では、より小さい値を配置した場合に、有効な補完がいくつ存在するかのみを考慮し、残りのサフィックスが残りのマルチセットから形成できることを確認します。 

これにより、問題は、マルチセットの制約された順列をカウントすることに縮小され、プレフィックスを固定し、階乗比を使用して完了数を計算します。 主な困難は、概念的にプレフィックスを構築する際に、要素を動的に削除してカウントを効率的に維持し、多項係数を計算することになります。 

したがって、ソリューションの構造は次のとおりです。ターゲット文字列内の位置を反復し、残りの頻度を維持し、各ステップで、これまで一致するプレフィックスで始まるが次の位置でより小さい値に分岐する順列の数をカウントします。 これは、まだ周波数が残っている可能なすべての小さいシンボルを合計し、その選択を修正した後、残りのマルチセットの順列数を乗算することによって処理されます。 

これを効率的にサポートするために、階乗とモジュラー逆関数を事前計算し、実行中の多項係数を維持します。 周波数をデクリメントするときの各更新は、事前に計算された逆数を使用して、対数または一定の償却時間で実行できます。

 | 最適 | 組み合わせ更新による O(n · K) | O(K) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 最初の配列内の各値の頻度を数えます。 これは、並べ替えているマルチセットを表します。 
2. モジュラー演算を使用して最大 n までの階乗および逆階乗を事前計算します。 これにより、n! 形式の多項係数を高速に計算できます。 / (c1! c2! ... ck!)。 
3. マルチセット全体の初期の順列数を計算します。 これは直接の答えではありませんが、増分更新の基本状態として機能します。 
4. ターゲット配列の位置を反復処理します。 各位置 i で、順列の i 番目の位置にどの値を配置するかを概念的に決定しようとします。 
5. 現在の位置については、すべての値がこの位置の目標値よりも厳密に小さいことを考慮します。 まだ正の頻度を持つそのような値 v ごとに、そのカウントを一時的に 1 減らして、残りのマルチセットから形成できる順列の数を計算します。 その値を答えに追加します。 これは、現在のプレフィックスに一致するが、正確にこの位置で小さくなるすべての順列をカウントします。 
6. 小さな選択肢をすべて考慮した後、この位置で目標値と一致できるかどうかを確認します。 その頻度がゼロの場合、プレフィックスとの一致を継続できる順列がないため、早期に停止します。 それ以降のすべての置換はすでにカウントされているか無効です。 それ以外の場合は、頻度を減らすことでプレフィックス内のこの値を修正し、続行します。 
7. ターゲット文字列のすべての位置が正常に終了した場合、厳密に小さい順列のみが必要となるため、残りの順列は自動的にカウントされません。 これにより、プレフィックス条件が暗黙的に処理されます。 

### なぜ効果があるのか

 このアルゴリズムは接頭辞の不変性を維持します。各ステップで、現在のインデックスまでターゲット文字列と正確に一致する順列を考慮します。 位置 i でより小さい値に分岐するたびに、その選択のすべての補完は、接尾辞に関係なく、辞書編集的にターゲットよりも小さいことが保証されます。 逆に、目標値との一致を継続する場合は、同等の可能性を保持し、決定を後のポジションに延期します。 これにより、すべての順列がターゲットとより小さい方向に異なる最初の位置で正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())
s = list(map(int, input().split()))
t = list(map(int, input().split()))

maxv = 200000

cnt = [0] * (maxv + 1)
for x in s:
    cnt[x] += 1

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact = [1] * (n + 1)
invfact[n] = modinv(fact[n])
for i in range(n, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def multinom(total):
    res = fact[total]
    for v in cnt_vals:
        res = res * invfact[v] % MOD
    return res

total = n
cnt_vals = cnt[:]
den = 1
for v in cnt_vals:
    den = den * invfact[v] % MOD
ans = 0

for i in range(min(n, m)):
    cur = t[i]

    for v in range(1, cur):
        if cnt_vals[v] == 0:
            continue

        cnt_vals[v] -= 1

        ways = fact[total - 1]
        for x in cnt_vals:
            ways = ways * invfact[x] % MOD

        ans = (ans + ways) % MOD

        cnt_vals[v] += 1

    if cnt_vals[cur] == 0:
        break

    cnt_vals[cur] -= 1
    total -= 1

print(ans)
```コードの中心的な構造は、プレフィックス構築プロセスを反映しています。 の`cnt_vals`配列は、プレフィックスの固定をシミュレートする際の残りのマルチセットを表します。 階乗配列と逆階乗配列は、多項カウントの高速な再計算をサポートします。 各位置で、すべての小さいシンボルを明示的に試し、多項式を使用して完了をカウントします。 

よくある微妙な間違いは、位置 i で小さいシンボルを選択した後、置換を計算する前にマルチセットを一時的に変更する必要があることを忘れていることです。 もう 1 つは、ターゲット プレフィックスが一致しなくなった後、誤って続行されます。 早めの休憩がこれに対応します。 

## 実用的な例

 ### 例 1

 入力:```
s = [1, 2, 2]
t = [2, 1, 2, 1]
```プロセスを追跡します。 

| 私 | t[i] | より小さい値を試してください | 貢献 | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 1 | 先頭に 1 を固定した後の順列 | カウントから 1 を引く |
 | 1 | 1 | なし | 0 | 1 | と一致する必要があります
 | 2 | 2 | なし | 0 | 続ける |
 | 3 | 1 | なし | 0 | 終わり |

 位置 0 で 1 を選択すると、残りの [2,2] のすべての順列が得られるため、1 で始まる順列のみが寄与します。 その後、試合パスが続きます。 

これは、最初の発散のみが寄与するという不変式を裏付けています。 

### 例 2

 入力:```
s = [1,1,1,2]
t = [1,1,2]
```| 私 | t[i] | より小さい値を試してください | 貢献 | 残りのマルチセット |

 | 0 | 1 | なし | 0 | [1,1,2] |
 | 1 | 1 | なし | 0 | [1,2] |

 ここで、3 番目の位置に到達すると、2 の代わりに 1 を配置すると、すぐにすべての補完が有効になり、それ以上の一致は不可能になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ターゲット文字列が構築された順列よりも短い場合です。 その場合、ターゲット全体に一致する順列は余分な長さのために辞書編集的に大きくなるため、カウントしないでください。 アルゴリズムは、ターゲットの長さを使い果たす前に分岐点でのみ寄与を蓄積するため、これを自然に回避します。 

もう 1 つのケースは、マルチセット内のすべての要素が同一である場合です。 この場合、すべての順列は同一であるため、ターゲットがある位置でより小さい値で異なる場合を除き、ターゲットよりも厳密に小さい順列は存在しません。これは「より小さい値を試す」ステップで正しく処理されます。 

最後の微妙なケースは、ターゲットの最初の文字がすでに使用可能なすべての記号よりも小さい場合です。 位置 0 には小さな分岐が存在せず、実現可能性に応じてマッチングが続行または終了するため、アルゴリズムは正しく 0 を提供します。
