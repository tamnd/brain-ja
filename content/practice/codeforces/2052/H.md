 ## 解決策
 ## 問題の理解

 レースはレーベルごとに注文された車両から始まります。$$1,2,3,\dots,n.$$レース中の追い越しは隣接スワップです。 車なら$x$車のすぐ後ろにいます$y$、その後イベント「$x$追い越します$y$」と立場が入れ替わります。 

レースの終わりには最終的な順位だけが分かります$c$。 私たちは、車のペアごとにという 1 つの制限の下で、できるだけ多くの追い越しを含むレースを再構築する必要があります。$(x,y)$、イベント「$x$追い越します$y$" 最大 1 回発生する可能性があり、イベント "$y$追い越します$x$」ということが多くても一度は起こるかもしれません。 

可能な最大追い越し数と、それを達成する一連の追い越しの両方を出力する必要があります。 

制約$n \le 1000$小さいです。 車のペア数は最大で$$\frac{1000\cdot999}{2}=499500.$$答え自体には次の内容を含めることができるため、$O(n^2)$オーバーテイクの場合、受け入れられた解は最悪の場合でも少なくとも 2 次になります。 アン$O(n^2)$施工は完全に安全です。 

微妙な点は、オーバーテイクの数を最大化することは、最終的な順列を最小化または一致させることと同じではないということです。 最終順位での相対順位が変わらない 2 台の車両については、レース中に 2 回順位を入れ替えても、元の順位でフィニッシュすることができます。 最終的な順列を取得するために厳密に必要なオーバーテイクのみを実行するソリューションでは、多くの有効な追加のオーバーテイクが失われます。 

考慮する：```
n = 2
final = [1, 2]
```最終注文はすでに最初の注文になっています。 素朴な解決策では、ゼロのオーバーテイクが出力されます。 

最適な種族は次のとおりです。```
2 overtakes 1
1 overtakes 2
```最後の注文はまた$[1,2]$、しかし今では2回の追い越しがあります。 

見落としやすいもう 1 つのケースは次のとおりです。```
n = 3
final = [3,2,1]
```すべてのペアが逆になります。 逆に終了するには相対的な順序の正味の変更が必要であるため、どのペアも 2 回の追い抜きに貢献することはできません。 最大は、ペアごとに 1 回ずつ、ちょうど 3 回の追い越しです。 

## アプローチ

 ブルートフォースビューは、すべての車のペアを個別に検討することから始まります。 

ペアを取ってください$(x,y)$と$x<y$。 当初は、$x$先です$y$。 

最終順位も上位に入った場合$x$先に$y$の場合、このペアは 2 回のオーバーテイクに貢献できます。```
y overtakes x
x overtakes y
```相対的な順序は変更されずに終了します。 

最終順位が1位になった場合$y$先に$x$の場合、このペアは最大 1 回のオーバーテイクに貢献できます。```
y overtakes x
```両方向を実行すると元の順序が復元されますが、これは許可されていません。 

これによりすぐに上限が決まります。 させて$P$をペアの数とし、$I$は、初期順序に対する最終的な順列の反転数になります。 

すべての非反転ペアは最大 2 回の追い越しに貢献します。 すべての反転ペアは最大でも 1 つだけ貢献します。 

したがって、$$\text{answer} \le 2(P-I)+I = 2P-I.$$興味深いのは、この限界が常に達成可能であることを示していることです。 

重要な観察は、非常に構造化された方法ですべてのペアの最初のオーバーテイクを実現できるということです。 

から開始$$1,2,\dots,n.$$それぞれについて$y=2,3,\dots,n$、 動く$y$隣接する追い越しによって前方までずっと：```
y overtakes y-1
y overtakes y-2
...
y overtakes 1
```すべての車を処理した後、すべてのペア$(x,y)$と$x<y$ちょうど 1 回の追い越しを経験しました。$y$追い越します$x$」となります。$$n,n-1,\dots,1.$$ここで、最終的な相対順序が実際に元の順序と一致する必要があるペアについて考えてみましょう。 このようなペアごとに、反対方向にさらに 1 回の追い越しが必要です。 

逆の順序から始めて、ターゲットの順列に変換します$c$隣接スワップを使用します。 隣接する各スワップは、復元する必要がある 1 つのペアに正確に対応します。 これらのスワップは、すべての非反転ペアに 2 番目のオーバーテイクを提供します。 

総追い抜き回数は、$$P + (P-I)=2P-I,$$これは上限と一致するため、最適です。

 ## アルゴリズムのチュートリアル

 1. 最終的な順列を読み取ります$c$。 
2. 最終的なランキングにおける各車の順位を計算します。 
3. 最初のフェーズを生成します。 

あらゆる人にとって$y$から$2$に$n$、そしてすべての$x$から$y-1$まで$1$、出力:```
y x
```これはつまり "$y$追い越します$x$」。 

これらすべての追い抜きの後、車の順序は次のようになります。$$n,n-1,\dots,1.$$4. 現在の順序を逆順列として初期化します。 
5. 逆順列をターゲット順列に変換します。$c$。 

位置を左から右に処理します。 

車のとき$c[i]$現在その位置にいます$j>i$、所定の位置に達するまで繰り返し左に入れ替えます$i$。 

隣接するすべてのスワップ```
[..., y, x, ...]
->
[..., x, y, ...]
```追い越しに相当します。```
x y
```その追い越しを記録します。 
6. 記録された追い越しの合計数を出力し、その後追い越し自体を出力します。 

### なぜ効果があるのか

 すべてのペアについて$(x,y)$と$x<y$、最初のフェーズでは常に 1 つの追い越しが作成されます。$y$追い越します$x$」。 

最初のフェーズの後、すべてのペアの相対順序は逆になります。 

最終的な順列でもペアを反転する必要がある場合は、それ以上何も必要ありません。 このペアはちょうど 1 回のオーバーテイクに貢献します。 

最終的な順列に元の相対順序が必要な場合は、逆順列から次の順列への変換中に、$c$、ペアは一度交換する必要があります。 そのやりとりはまさに「」$x$追い越します$y$このペアはちょうど2回の追い抜きに貢献した。 

どのペアも同じ方向の追い越しを 2 回行うことはありません。 最初のフェーズでは「」のみを使用します。$y$追い越します$x$"。第 2 段階では " のみを使用します。$x$追い越します$y$」 修復が必要なペアの場合。 

したがって、すべての反転ペアは 1 回のオーバーテイクに寄与し、すべての非反転ペアは 2 回のオーバーテイクに寄与し、合計は証明された上限に等しくなります。$2P-I$。 施工は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))

    events = []

    # Phase 1
    for y in range(2, n + 1):
        for x in range(y - 1, 0, -1):
            events.append((y, x))

    # Phase 2
    arr = list(range(n, 0, -1))
    pos = [0] * (n + 1)

    for i, v in enumerate(arr):
        pos[v] = i

    for i in range(n):
        target = c[i]
        j = pos[target]

        while j > i:
            y = arr[j - 1]
            x = arr[j]

            events.append((x, y))

            arr[j - 1], arr[j] = arr[j], arr[j - 1]
            pos[x] -= 1
            pos[y] += 1

            j -= 1

    out = [str(len(events))]
    out.extend(f"{x} {y}" for x, y in events)
    sys.stdout.write("\n".join(out))

solve()
```最初のフェーズは完全に決定的です。 車$y$番号の小さい車をすべて 1 回ずつ追い越します。 これにより、逆順列が生成され、ペアごとにちょうど 1 回のオーバーテイクが発生します。 

2 番目のフェーズは、標準の隣接スワップ変換です。 配列`arr`現在の注文を保存します。 配列`pos`すべての車の現在位置を保存し、各スワップを一定時間で更新できるようにします。 

動くループ`target`左側は本質的に、ターゲットの順列の挿入ソート形式の再構築です。 隣接するすべてのスワップは、1 つの有効な追い越しイベントに直接対応します。 

Python の整数は任意精度であるため、オーバーフローの心配はありません。 イベントの最大数は 100 万未満であるため、すべてのイベントを保存してもメモリ制限内に収まります。

 ## 特殊なケース

 次のことを考慮してください。```
2
1 2
```最終的なランキングは最初のランキングと同じになります。 最初のフェーズでは以下が実行されます。```
2 overtakes 1
```逆の順序を生み出します。 第 2 フェーズでは、次のようにして元の順序が復元されます。```
1 overtakes 2
```答えは 2 です。このペアは、可能性のある両方の方向の追い越しに寄与するため、これが最適です。 

次に、次のことを考えてみましょう。```
2
2 1
```最初のフェーズでは再び次のことが実行されます。```
2 overtakes 1
```そしてすでに目標の順列に達しています。 第 2 フェーズでは何も実行されません。 答えは 1 です。2 番目の追い抜きを追加しようとすると、元の順位に戻り、必要な最終順位に違反します。 

最後に、次のことを考慮してください。```
3
3 2 1
```すべてのペアが反転されます。 最初のフェーズが終了すると、順序はすでに正しいものになります。 第 2 フェーズのスワップは発生しません。 各ペアは正確に 1 回のオーバーテイクに貢献します。これは、最終的な相対順序が逆転した場合に可能な最大値です。
