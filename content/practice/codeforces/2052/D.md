 ## 解決策
 ## 問題の理解

 false 状態で始まる単一のブール レジスタに適用される一連の操作が与えられます。 各操作は設定または設定解除のいずれかです。 セットは、レジスタが false の場合は true に変更し、その場合は true を返します。それ以外の場合は、レジスタを変更せずにそのままにして false を返します。 unset は、対称的にレジスタが true の場合は false にしようとし、実際に状態を変更した場合にのみ true を返します。 

したがって、すべての操作には、そのタイプと成功を報告したかどうかという 2 つの情報があります。 重要なグローバル制限は、最大 2 回の操作で真の結果が生成されるということです。つまり、実際にレジスタの状態が変更されるのは最大 2 回の瞬間です。 

これに加えて、有向非巡回グラフの形式で演算間に半順序が与えられます。 有効な最終的な配置では、この DAG を線形順序に拡張する必要があります。 タスクは、レジスタをその順序でシミュレートすると、すべての操作が指定されたブール値を正確に生成するような、すべての操作のトポロジカルな順序が存在するかどうかを判断することです。 

この制約により、最大 100,000 の演算と 100,000 のエッジが許可されるため、すべての順列を試行したり、候補の順序ごとにシミュレーションを繰り返したりするアプローチは除外されます。 O(n^2) の構築でも遅すぎます。 私たちは線形または線形に近いグラフ処理方法を強いられており、おそらく追加の枝刈りや状態追跡を伴うトポロジカルな順序付けが必要になります。 

重要な微妙な点は、DAG は相対的な順序を制約しますが、正確性の条件は最大 2 つの遷移によるグローバルな状態の進化に依存することです。 この組み合わせにより、多くの場合、大規模な半順序に埋め込まれた非常に少数の重要なイベントについての推論が導き出されます。 

よくある失敗例は、単純なトポロジカル ソートを試みてからレジスタを貪欲にシミュレートした場合に発生します。 問題は、複数の有効なトポロジー順序が存在し、その一部のみが結果によって暗示される状態遷移と一致することです。 

たとえば、エッジのない 3 つの操作 A、B、C について考えてみましょう。 A と B が両方とも反転に成功したが、タイプが同じである場合、それらを異なるトポロジ順序で交換すると、すべての順序が DAG を満たしていてもレジスタ状態シーケンスが変化するため、実現可能性が変わる可能性があります。 

もう 1 つの失敗例は、false-return 操作が DAG 制約だけでなく現在の状態の一貫性に依然として依存していることを無視していることです。 順序を間違えると、誤った操作と思われる操作によって実際に状態が変更され、そのラベルと矛盾する状況が発生する可能性があります。 

## アプローチ

 ブルート フォースの観点では、DAG の有効なトポロジー順序をすべて列挙し、それぞれのレジスタをシミュレートしようとします。 一般的な DAG ではトポロジー次数の数が階乗的に増加する可能性があるため、これは直ちに実行不可能です。 まばらなグラフでも、これは組み合わせ的に爆発的に発生します。 

もう 1 つの単純なアイデアは、単一の位相順序を計算し、それが機能するかどうかを確認することです。 この問題は位相順序を要求しておらず、非常に特殊な状態の発展と一致する順序を要求しているため、これも失敗します。 DAG だけではレジスタの動作をエンコードしないため、任意のトポロジー ソートでは不十分です。 

重要な観察は、多くても 2 つの操作が true を返すという制約から来ています。 これは、レジスタがシーケンス全体で最大 2 回状態を変更することを意味します。 したがって、有効な実行のタイムラインには、状態が false から true、または true から false に切り替わる非常に少数の「クリティカル ポジション」があります。

これは、レジスタの状態が一定である長い単調セグメントに操作を分割することを示唆しています。 セグメント内では、各操作の結果は、そのタイプと現在の状態と一致するかどうかによって完全に決まります。 ほとんどの操作は状態変更に関して「no-ops」である必要があります。つまり、レジスタを変更しない操作を試行するため false が返されます。 

したがって、問題は、すべての DAG 制約が尊重され、他のすべての操作が結果の状態タイムラインと一貫していることを確認しながら、実際に状態を変更する特別な操作を最大 2 つ配置することに帰着します。 

次に、最初と 2 番目に成功した操作が有効なトポロジー順序でどこで発生するかを特定することによって、実現可能性を強化します。 これらのイベント間およびその前後では、他のすべての操作は固定状態と一致している必要があり、DAG 内での配置が大きく制限されます。 

これを利用する標準的な方法は、トポロジー順序を計算しますが、最大 2 つの重要な遷移の前または後にノードを配置できるかどうかに基づいて、同じレベル内のノードの順序付けに柔軟性を持たせることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのトポロジー次数を列挙する | 指数 | O(n + m) | 遅すぎる |
 | 単一のトポロジーソート + チェック | O(n + m) | O(n + m) | 不正解 |
 | 最大 2 つの状態反転による構造化トポロジカル順序付け | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはトポロジカルな順序付けフレームワークを使用しますが、状態遷移に対する制限を組み込んでいます。 

1. 度数を計算し、DAG の隣接リストを構築します。 これにより、可能なすべての線形拡張の法的構造が得られます。 有効な回答はこれらのいずれかである必要があります。 
2. 種類と報告された結果に基づいて、操作を 4 つのカテゴリに分類します。 構造的に重要な操作は、実際の状態の反転に対応するため、結果が true になる操作のみです。 それらは最大でも 2 つであるため、それらを順序付けの潜在的なアンカーとして扱います。 
3. これらの実際の結果の操作で考えられる役割をタイムラインで列挙します。 状態遷移は 0、1、または 2 つ存在する可能性があります。 ゼロの場合、レジスタは決して変更されないため、すべての操作は初期状態と一致する必要があります。 存在する場合、システムは操作の種類に応じて false から true、または true から false に 1 回変更されます。 2 つある場合は、状態が 2 回切り替わります。 
4. これらの遷移の解釈候補ごとに、時間内のすべての操作に予想される状態 (偽または真) を割り当てます。 これにより、各操作が制約に変わります。その型と期待される状態が与えられると、それが true または false を返さなければならないことがわかり、これは入力と一致する必要があります。 
5. 問題を、DAG を考慮したトポロジカルな順序付けが存在するかどうかを確認すると同時に、「遷移 k の前に存在する必要がある」および「遷移 k の後に存在する必要がある」とラベル付けされたすべてのノードが依存関係に違反することなく分離できるかどうかを確認することに集約します。 これは、遷移の配置によって引き起こされる追加の順序制約を伴う、DAG にわたる一貫性チェックになります。 
6. 修正されたトポロジカルソートを使用して、貪欲に順序を構築します。 各ステップで、すべてのゼロ次数ノードの中から、レジスタ状態の現在のフェーズと一致するノードのみを選択します。 そのようなノードが存在しない場合、遷移の配置に関する現在の仮説は無効です。 
7. すべてのノードの配置に成功したら、順序を出力します。 それ以外の場合は、最大 2 つの true-result 操作の間で遷移配置の次の可能な構成を試してください。 

### なぜ効果があるのか

このアルゴリズムは、レジスタの状態が最大 2 つの変化点で区分的に一定であるという不変条件に依存しているため、すべての操作は最大 3 つのフェーズ (フリップ前、フリップ間、またはフリップ後) のいずれかに正確に属します。 各フェーズ内では、すべての操作はそのタイプに応じて決定論的に動作します。 トポロジカル順序制約は相対的な配置のみを制限し、位相の割り当ては制限しません。 現在のフェーズと互換性のある DAG 利用可能なノードのみを配置するようにすることで、依存関係や状態の一貫性に違反することはありません。 すべての真の結果の操作は実際の状態遷移に対応する必要があるため、それらの位置を列挙することで、実行可能なすべてのグローバル動作が網羅的にカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def try_build(n, ops, adj, indeg, start_state, first_true, second_true):
    indeg2 = indeg[:]
    q = deque()
    for i in range(n):
        if indeg2[i] == 0:
            q.append(i)

    res = []
    state = start_state
    used_first = False
    used_second = False

    # determine transition set
    true_nodes = set([first_true])
    if second_true is not None:
        true_nodes.add(second_true)

    while q:
        chosen = -1

        for _ in range(len(q)):
            v = q.popleft()

            op_type, op_res = ops[v]

            # decide expected result based on state
            expected = (op_type == "set" and state == True) or (op_type == "unset" and state == False)
            expected_result = not expected

            if op_res == "true":
                # must be a flip
                if v == first_true and not used_first:
                    chosen = v
                    used_first = True
                    break
                if v == second_true and not used_second:
                    chosen = v
                    used_second = True
                    break
            else:
                # false result must match expectation
                if op_res == ("true" if expected_result else "false"):
                    chosen = v
                    break

            q.append(v)

        if chosen == -1:
            return None

        # place chosen
        res.append(chosen + 1)
        if ops[chosen][1] == "true":
            state = not state

        for nei in adj[chosen]:
            indeg2[nei] -= 1
            if indeg2[nei] == 0:
                q.append(nei)

    if len(res) != n:
        return None
    return res

def solve():
    n = int(input())
    ops = []
    true_nodes = []
    for i in range(n):
        t, r = input().split()
        ops.append((t, r))
        if r == "true":
            true_nodes.append(i)

    m = int(input())
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append(b)
        indeg[b] += 1

    if len(true_nodes) > 2:
        print(-1)
        return

    candidates = []
    if len(true_nodes) == 0:
        candidates.append((None, None))
    elif len(true_nodes) == 1:
        candidates.append((true_nodes[0], None))
    else:
        candidates.append((true_nodes[0], true_nodes[1]))

    for first, second in candidates:
        order = try_build(n, ops, adj, indeg, False, first, second)
        if order is not None:
            print(*order)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```このソリューションは、DAG を読み取り、標準的なトポロジー プロセスの隣接リストと次数を保存することから始まります。 重要な追加構造は、どのノードが true を返したかを追跡することです。これは、これらのノードが状態遷移の唯一の候補であるためです。 

の`try_build`関数は、どの真のノードが実際の状態の反転に対応するかという仮説に基づいて、有効なトポロジー順序付けを構築しようとします。 利用可能なノードのキューと現在のレジスタ状態を維持します。 各ステップで、DAG が利用可能であり、現在の仮説で予想されるレジスタの動作と一致するノードを選択しようとします。 

微妙な点は、レジスタを反転できるのは true 結果の操作のみであるため、状態の変化をシミュレートするのは true 結果の操作を使用する場合のみであることです。 すべての偽結果操作は、現在の状態に対する一貫性チェックとして扱われます。 

このアルゴリズムは、可能な構成の分岐要素を制限する真のノードが最大 2 つあるという事実に大きく依存しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、真の結果を求める操作がゼロである場合です。 アルゴリズムはこれを、レジスタが決して変更されない単相システムとして扱います。 状態の反転は発生しないため、すべての操作は初期の false 状態と一致している必要があります。 この構築では、状態遷移をトリガーせずに標準的なトポロジー ソートを実行するだけであり、違反があると、一貫性と一致する DAG 有効なノードを選択できないように見えます。 

もう 1 つのエッジ ケースは、2 つの実際の操作が厳密な DAG 順序になっている場合です。 この状況では、それらが 2 つの独立した遷移を表すという仮説は依然として機能しますが、トポロジー プロセスでは、利用可能な場合は常に早い方が最初に選択されるようにする必要があります。 キュー選択ロジックは、使用可能になったときに正しい真のノードを優先することでこれを強制します。 

最後の微妙なケースは、真のノードの配置に応じて、偽の結果の操作が現在の状態と矛盾する場合に発生します。 このアルゴリズムは、DAG 制約と状態の一貫性の両方を満たす利用可能なノードがない場合に早期に仮説全体を拒否することでこれを処理し、無効な部分順序が拡張されないようにします。
