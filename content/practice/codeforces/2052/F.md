 ## 解決策
 ## 問題の理解

 2 行 n 列のグリッドが与えられています。 各セルはすでに壊れている (空白スペースを埋める必要がある) か、無傷で使用できないかのいずれかです。 私たちのタスクは、サイズ 1 × 2 のドミノを使用して、壊れたすべてのセルを 1 回だけカバーすることです。ドミノは、行内に水平に配置することも、同じ列の両方の行を垂直にカバーすることもできます。 ドミノは重なってはならず、無傷のセルを覆うことはできません。 

テスト ケースごとに、すべての壊れたセルのタイリングが不可能なのか、一意に決定されるのか、または複数の有効な構成があるのか​​を判断する必要があります。 

構造は重要です。グリッドの高さは 2 に固定されており、相互作用はローカルな列方向および隣接する列の動作に制限されます。 この問題は基本的に、グリッドから導出された非常に制約された 2 部グラフ内の完全一致をカウントすることに関するものです。 

制約は大きく、すべてのテスト ケースの n の合計は最大 2 × 10^5 になります。 これにより、タイリングやテストごとの O(n^2) 動的プログラミングでさえも指数関数的なバックトラッキングが即座に除外されます。 テストケースごとにリニアスキャンが必要です。 

いくつかの特殊なケースは過小評価されがちです。 

1 つは、列に使用可能なセルが 1 つだけある場合です。 例えば：```
n = 1
..
```どちらかのセルがブロックされたり、後でパリティの不一致が発生したりすると、垂直ドミノを単一列 2 セルのギャップに配置できないため、これは不可能です。 

もう 1 つの微妙なケースは、長い強制チェーンが表示される場合です。```
....
....
```ここでは、垂直方向と水平方向の配置をさまざまな方法で切り替えることができるため、複数のタイリングが存在します。 単純に貪欲な試みは、可能な限り垂直方向の配置を選択し、一意性を誤って結論付ける可能性があります。 

3 番目の厄介なケースは、ローカルで強制された選択が伝播する場合です。 1 つの列に 1 つの強制垂直配置を行うと、隣接する構造が強制される可能性があり、制約の伝播に失敗すると、構成のカウントが不正確になります。 

## アプローチ

 ブルートフォースソリューションでは、ドミノを再帰的に配置しようとします。 空の各セルに、水平ドミノ (右のセルが使用可能な場合) または垂直ドミノ (その列で両方の行が使用可能な場合) のいずれかを配置しようとします。 解を再帰して数え、0、1、または複数の有効なタイリングを区別します。 

これは、有効な一致をすべて調査するため、正しいです。 ただし、各分岐ステップでは複数の再帰呼び出しが発生する可能性があり、最悪の場合、2 x n の完全に空のグリッドのタイリング数は n で指数関数的になります (フィボナッチ型の増加に従います)。 枝刈りを行ったとしても、n が 2 × 10^5 までの場合、最悪の場合の実行時間は実現不可能です。 

重要な点は、グリッドの高さが 2 であるため、任意のタイリングを列ごとに処理でき、各ステップのローカル構造が将来の制約を完全に決定することです。 完全な構成を追跡する代わりに、垂直ドミノが現在「保留中」かどうかを前の列から追跡するだけで済みます。 これにより、問題は列ごとに最大 2 つの状態を含む有限状態プロセスに縮小されます。 

次に、左から右にシミュレーションし、制約を伝播し、選択肢が分岐するかどうかをカウントします。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各列には上部と下部の 2 つのセルがあると解釈します。 前の列で開始された水平ドミノによって行の 1 つがすでに占有されているかどうかを表す状態を維持します。 

また、ソリューション数がまだ一意であるか、すでに複数であるかどうかも維持します。 

### ステップ

 1. 状態を維持しながら列を左から右に処理します`pending`これは、前の列のドミノが現在の列の 1 つのセルを占有しているかどうかを示します。 

これは水平方向のドミノ伝播をキャプチャします。 
2. 各列について、考慮後の使用可能なセルの数によって分類します。`#`ブロックと保留中の占有。 
3. 列に両方のセルが使用できない場合、その列はスキップされます。 列に使用可能なセルが 1 つだけあり、保留中の競合がない場合、強制的に垂直方向に配置するか、既存の水平方向の制約を継続します。 
4. 列に使用可能なセルが 2 つある場合は、ローカルで次の 2 つの決定が考えられます。 

可能であれば、垂直ドミノを 1 つ配置するか、次の列に伸びる 2 つの水平ドミノ半分を配置します。 これが分岐が発生する唯一の状況です。 
5. 垂直方向の配置と水平方向の継続の両方が可能な状況に遭遇した場合は常に、その構成を曖昧なものとしてマークします。 この時点以降、構造が引き続き代替選択肢を許可する場合、答えは「複数」になります。 
6. 保留中の制約と使用可能なセルの間の不一致により、いずれかの時点で必要な配置が不可能な場合は、すぐに「なし」を返します。 
7. 分岐が発生せずにすべての列の処理が完了した場合、答えは「一意」になります。 

### なぜ効果があるのか

 2 x n ボードのすべてのタイリングは、単一の列または隣接する列のペアにローカルな決定に分解できます。 高さは 2 に固定されているため、グローバルな依存関係は、水平ドミノが列の境界を横切るかどうかだけです。 これにより、有界ステート マシンが作成されます。 一意性は、2 つの異なる有効なローカル遷移が同時に利用できる状態が存在しないことに正確に対応します。 このような状態に遭遇すると、後続の列の独立性により、ローカル発散は常に独立して完全なタイリングに拡張できるため、タイリング空間には少なくとも 2 つの異なる補完が含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, g):
    top = g[0]
    bot = g[1]

    # pending[i] = whether a horizontal domino from i-1 occupies cell in column i
    pending_top = False
    pending_bot = False

    multiple = False

    i = 0
    while i < n:
        # apply pending occupancy
        avail_top = (top[i] == '.') and (not pending_top)
        avail_bot = (bot[i] == '.') and (not pending_bot)

        # reset pending after consuming
        pending_top = False
        pending_bot = False

        # count available
        cnt = int(avail_top) + int(avail_bot)

        if cnt == 0:
            i += 1
            continue

        if cnt == 1:
            # forced move: must extend if possible
            if avail_top:
                # must pair top horizontally if possible
                if i + 1 >= n or top[i + 1] != '.':
                    return "None"
                pending_top = True
            else:
                if i + 1 >= n or bot[i + 1] != '.':
                    return "None"
                pending_bot = True
            i += 1
            continue

        # cnt == 2
        # either vertical domino or two horizontals
        # check feasibility of both
        can_vertical = True
        can_horizontal = True

        if i + 1 < n:
            if top[i + 1] != '.':
                can_horizontal = False
            if bot[i + 1] != '.':
                can_horizontal = False
        else:
            can_horizontal = False

        if can_vertical and can_horizontal:
            multiple = True

        if can_vertical:
            # prefer vertical in simulation, but remember ambiguity
            i += 1
            continue

        if can_horizontal:
            pending_top = True
            pending_bot = True
            i += 1
            continue

        return "None"

    return "Multiple" if multiple else "Unique"

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        g = [input().strip(), input().strip()]
        out.append(solve_case(n, g))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、次の列に伸びる水平ドミノを表す 2 つの保留フラグを使用して、列ごとの処理をモデル化します。 各列は、ブロックされたセルを削除した後の可用性によって分類されます。 垂直構造と水平構造の両方が可能な場合、その構成は曖昧であるとマークされます。 

主な微妙な点は、水平方向の伝播を正しく処理することです。水平方向のドミノは常に 2 つの隣接する列を消費するため、次の列を部分的に占有されているものとしてマークする必要があります。 コードは使用します`pending_top`そして`pending_bot`この効果を表すために。 もう 1 つの微妙な点は、単一の分岐点でも複数の完全なタイリングが保証されるため、曖昧さがグローバルに記録されることです。
