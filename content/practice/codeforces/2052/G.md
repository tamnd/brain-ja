 ## 解決策
 ## 問題の理解

 私たちは、カメが飛行機上で実行する描画手順を分析するように求められます。 タートルは一連のコマンドに従って移動および回転します。45 度の倍数で回転したり、痕跡を残してまたは残さずに前進したり、指定された長さのセグメントを描画したりできます。 Ivan が一連のコマンドを実行した後、最小の正の回転角を知りたいと考えます。`b`描画手順全体を次のように回転すると、`b`度を指定すると (オプションで平面上の任意の場所に変換すると)、結果として得られるインク付き点のセットは元のものと同一になります。 

入力サイズ`n`最大 50,000 コマンドですが、実際にインクを残す描画コマンドは最大 2,000 までです。 の大きな値`n`これは、平面内のすべての点を反復する解法は遅すぎることを意味します。 回転が 45 度の倍数であるという事実は重要です。これにより、カメが向くことができる方向が 8 つのコンパス点に制限され、幾何学的な推論が簡素化されます。 エッジ ケースには、単一の描画コマンド、対称形状 (正方形や線など) を形成するシーケンス、および描画が水平または垂直セグメントとは異なる回転対称性を持つ単一の対角線セグメントである場合が含まれます。 

たとえば、入力が次の場合:```
1
draw 10
```次に、タートルは単一のセグメントを描画します。 180 度回転すると同じ画像が生成されるため、答えは 180 になります。すべての回転を細かい増分で考慮する単純なアプローチでは、この個別の対称性が失われ、非効率になります。 

## アプローチ

 この強引なアイデアは、タートルの経路をシミュレートし、インクで覆われたすべてのポイントのセットを生成することです。 次に、考えられるすべての回転角度について`b`1 から 360 まで、セット全体を回転し、元の値と一致するかどうかを確認します。 これは正しいですが、最大 360 回回転して、最大で 1 つまでの大きなポイントのセットを比較する必要があるため、非常に時間がかかります。`2*10^9`単位が長い。 すべての点を座標として表すことさえ、セグメントの長さが非常に長いため現実的ではありません。 

重要な点は、すべての個々の点を表す必要はないということです。 描画されたすべてのセグメントは、コンパスの 8 つの方向のいずれかに沿っています。 図面全体を回転させると、`b`度は、各描画セグメントに対応するベクトルのセットを保存します。 したがって、問題を、360 度を法として考慮した、描画されたセグメントのすべての方向の最大公約数 (GCD) を見つけることに帰着できます。 各描画セグメントは方向に寄与し、回転下でも一連の方向を不変に保つ正の最小角度は、360 を 45 度単位で測定したこれらの方向の GCD で割った値です。 これにより、問題は座標を直接操作するのではなく、小さな配列 (最大 2,000 の描画コマンド) に対する単純な算術演算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(360 * セグメント長の合計) | O(合計ポイント) | 遅すぎる |
 | 最適 | O(m) ここで、m = 描画コマンドの数 | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. タートルの向きの角度を 0 度に初期化します。 描画セグメントの方向を保存する空のリストを作成します。 
2. コマンド シーケンスを繰り返します。 

- コマンドが「rotate a」の場合、追加します`a`現在の対面角度、モジュロ 360 に換算します。 
- コマンドが「draw d」の場合、現在の対面角度を法 360 で指示リストに保存します。 
- コマンドが「move d」の場合、対称計算は無視されます。 
3. 各角度を 45 で割ることにより、保存されているすべての方向を 45 度の倍数に変換します。これにより、8 つのコンパス方向の 1 つを表す 0 ～ 7 の整数が得られます。 
4. このモジュラー 8 システムで連続する方向間の差を計算します。 一連の差分により、セグメント間の相対角度が取得されます。 
5. これらすべての差の GCD を計算します。 回転対称角`b`度単位では`360 / GCD`。 画像が毎回繰り返されるため、これは機能します。`GCD * 45`度。 
6. 結果を出力します。 

機能する理由: 描画されたすべてのセグメントには固定方向があります。 画像を保存する回転では、各セグメントを同じ方向のセグメントにマッピングする必要があります。 方向をモジュロ 45 で削減し、角度差の GCD を計算すると、シーケンスをそれ自体にマッピングする最小の回転が捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd
from functools import reduce

def main():
    n = int(input())
    angle = 0
    draw_dirs = []

    for _ in range(n):
        cmd = input().split()
        if cmd[0] == 'rotate':
            angle = (angle + int(cmd[1])) % 360
        elif cmd[0] == 'draw':
            draw_dirs.append(angle)
        # 'move' is ignored for symmetry

    # Convert angles to multiples of 45 degrees
    draw_dirs_mod = [d // 45 for d in draw_dirs]

    if len(draw_dirs_mod) == 1:
        print(180)
        return

    diffs = [(draw_dirs_mod[i+1] - draw_dirs_mod[i]) % 8 for i in range(len(draw_dirs_mod)-1)]

    g = reduce(gcd, diffs)
    result = 360 // g
    print(result)

if __name__ == "__main__":
    main()
```コードはタートルの絶対的な向きの角度を追跡し、描画コマンドのみを記録します。 モジュロ 45 変換により、可能な 8 つの方向のみが確実にキャプチャされます。 対称性は常に 180 度であるため、単一描画セグメントのエッジ ケースを明示的に処理します。 差の GCD を計算すると、描画されたすべてのセグメントの相対的な方向を維持した最小の回転が見つかることが保証されます。

 ## 特殊なケース

 セグメントを 180 度回転すると同じ点のセットが得られるため、単一の描画セグメントは常に 180 を生成します。 コードはこれを明示的にチェックします。 

2 つの垂直セグメントが L 字型を作成します。 モジュロ 8 の違いは次のとおりです。`[2]`、GCD は 2、回転は`360 / 2 = 180`、最小角度を正確に識別します。 

複数の対角線セグメント (例: 45 度回転)、結果の差異`[1]`。 GCD は 1 なので、`360 / 1 = 360`つまり、完全に回転した場合のみ図面が保持されます。 

この社説は、対称性とモジュラー演算というレンズを通して問題を提示し、不必要な幾何学的シミュレーションを回避しています。
