 ## 解決策
 ## 問題の理解

 順列、つまり 1 から n までのすべての整数を 1 回だけ含む配列が与えられます。 このプロセスでは、決定論的な「ストレンジ バブル パス」操作が繰り返し適用されますが、一工夫が施されています。奇数番号のラウンドはインデックス 1、3、5 から開始して隣接するペアを比較し、偶数番号のラウンドはインデックス 2、4、6 から開始します。 

各比較では、順序が間違っている場合にのみペアを交換します。 フルラウンドは、選択されたパリティのすべての有効なペアを順番にスイープすることで構成されます。 

ここでのタスクは、配列が初めて完全に昇順にソートされるまでに、何回のラウンドが必要かを判断することです。 最初にすでにソートされている場合、答えはゼロです。 

制約は十分に小さいため、直接シミュレーションも実行可能です。 すべてのテスト ケースにわたる n の合計は最大 999 で、各シミュレーション ステップはラウンドごとに最大 n 回の比較を実行します。 これにより、単純なソリューションは全体で約 10^6 の演算に制限され、Python では十分に高速になります。 

配列がすでにソートされているか、ソートに近い場合、微妙なエッジ ケースが発生します。 ラウンドの完了後にのみチェックする単純な実装では、反復が開始される前に「ソート済み」の条件を見逃さないようにする必要があります。 もう 1 つの潜在的な落とし穴は、完全な反復がカウントの単位として定義されているため、完全な反復の完了後ではなく、ラウンド中にソート状態を検出した後に停止することです。 

## アプローチ

 単純な考えは、説明されているプロセスを直接シミュレートすることです。 各反復では、パリティに応じて適切なインデックスをループし、条件付きスワップを実行します。 完全な反復を行うたびに、配列がソートされているかどうかを確認します。 整理されるまで繰り返します。 

これが機能するのは、操作が順列の展開を正確に定義しており、ソート順に初めて到達するかどうかを尋ねられるため、シミュレーションが忠実であるためです。 

非効率性の問題は、フルパスを繰り返すのにコストがかかりすぎるかどうかです。 各パスは O(n) であり、最悪の場合は O(n) 回のパスが必要になる可能性がありますが、ここでは n ≤ 999 で合計が小さいため、テスト ケースごとの最悪の場合の O(n²) は依然として許容されます。 

重要な観察は、このプロセスは明示的に制限されており、ソート順に向かって単調であるため、高度なデータ構造やソート理論は必要ないということです。 各ラウンドは決定的であり、構造化された方法で反転を減らすため、直接シミュレーションで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 定義どおりにプロセスを正確にシミュレートし、ラウンドをカウントします。 

1. 順列を読み取り、すでにソートされているかどうかを確認します。 「はい」の場合は、すぐに 0 を出力します。 これにより、答えが自明な場合に不必要なシミュレーションが回避されます。 
2. 実行された反復回数のカウンターを初期化します。 
3. 配列がソートされるまで繰り返します。 

1. 現在の反復数が奇数の場合、インデックス 1、3、5、...、n−2 をスキャンし、必要に応じて隣接する要素を交換します。 
2. 反復数が偶数の場合、インデックス 2、4、6、...、n−1 をスキャンし、必要に応じて隣接する要素を交換します。 

各フル スキャンはプロセスの 1 回の反復を表し、スキャン内の部分的な進行状況は同じ反復の一部です。 
4. 完全に反復するたびに、カウンターを増加させ、配列がソートされたかどうかを確認します。 
5. ソートされたら、完了した反復回数を返します。

これが機能する理由は、アルゴリズムが順列における決定的な状態遷移を定義しているためです。 各反復は完全な変換ステップであり、問​​題では、システムが固定点 (並べ替えられた順序) に到達するときの最初の時間ステップが求められます。 状態空間は有限であり、収束するまで各ステップで厳密に無秩序が低減されるため、シミュレーションは常に終了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_sorted(a):
    for i in range(len(a) - 1):
        if a[i] > a[i + 1]:
            return False
    return True

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if is_sorted(a):
            out.append("0")
            continue
        
        steps = 0
        
        while True:
            steps += 1
            
            if steps % 2 == 1:
                start = 0
            else:
                start = 1
            
            for i in range(start, n - 1, 2):
                if a[i] > a[i + 1]:
                    a[i], a[i + 1] = a[i + 1], a[i]
            
            if is_sorted(a):
                out.append(str(steps))
                break
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はプロセス定義に直接続きます。 反復のパリティによって、比較をインデックス 0 で開始するか 1 で開始するかが決まります。ループを 2 ずつステップ実行することで、正しいペアにのみスワップを適用できるようになります。 

並べ替えられたチェックは各完全な反復の後に配置され、ラウンド内の部分的な進行ではなく、完全なラウンドをカウントするという要件に一致します。 シミュレーション前の早期チェックにより、ゼロケースが効率的に処理されます。

 ### 例 1

 入力:```

 ## 特殊なケース

 次のような完全にソートされた配列`[1, 2, 3, 4, 5]`反復が開始される前に初期チェックで反転が検出されないため、すぐに 0 を返します。 

次のような逆順列`[3, 2, 1]`は、小さい n に対する最大の仕事量を示します。 最初のパスではローカルの反転は修正されますが、配列はグローバルに並べ替えられないため、固定点に到達するまでに完全な反復を複数回行う必要があります。 

のような交互パターン`[2, 1, 4, 3, 5]`は、独立したローカル反転がどのように並行して解決されるかを示しています。 奇数パスと偶数パスはそれぞれ異なる隣接セットを解決し、少数の完全な反復後に配列が安定し、収束がグローバルな再構築ではなくローカルな修正によって推進されることが確認されます。
