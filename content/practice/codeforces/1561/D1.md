 ## 解決策
 ## 問題の理解

 私たちは、上が 1 から下が n まで番号が付けられたセルの垂直ストリップの上に立っています。 トークンはセル n から始まり、セル 1 に到達するまで繰り返し上に移動します。各移動は現在の位置 x からより小さな位置への遷移であり、これらの移動を選択する個別の方法の数がカウントしたいものです。 

位置 x からは、基本的に異なる 2 種類の遷移があります。 減算の場合、正のステップ サイズ y を選択し、x から x − y までジャンプします。これは、任意の小さい整数に到達できることを意味します。 除算の移動では、除数 z を選択し、x / z の床にジャンプします。これにより、大きな値を 1 ステップで大幅に折りたたむことができます。 y または z のすべての選択は、同じ目的地に向かう場合でも、個別の遷移としてカウントされます。 

課題は、n を 1 に変換するそのような動きの個別のシーケンスがいくつあるかを数えることです。答えは大きな素数 m を法にして求められます。 

n ≤ 2・10^5 という制約により、考えられるすべての遷移で分岐するパスまたは状態の指数関数的な列挙が即座に除外されます。 単一の状態 x から、減算だけで既に O(x) 個の出力エッジが得られ、除算では最悪の解釈でさらに O(x) 個の選択肢が追加されます。 すべてのエッジを明示的に拡張する単純なグラフ走査は、O(n^2) かそれより悪い動作をします。これは、n が約 200,000 である場合には許容範囲をはるかに超えています。 

さらに深刻な問題は、複数の異なる選択肢が同じ目的地に到達することです。 たとえば、多くの減算の選択肢は同じターゲットにつながり、複数の除数 z によって同じフロア分割が生成される可能性があります。 この重複は、単純なカウントではカウントしすぎたり、冗長な遷移を列挙して時間を無駄にしたりする傾向がある場所です。 

A subtle edge case arises when x is small. たとえば、x = 2 では、減算の選択肢は 1 つだけであり、除算でも重複した結果が生成されます。 隣接リストを明示的に構築する単純な実装では、遷移を重み付けされた多重度ではなく一意のエッジとして誤って扱う可能性があります。 

もう 1 つの重要なエッジ状況は x = 1 です。これは最終状態であり、再発では有効な「空」ウェイが 1 つだけあるものとして扱わなければなりません。そうしないと、すべてのカウントが誤って崩壊します。 

## アプローチ

 ブルートフォース手法では、すべての位置 x を有向グラフ内のノードとして扱い、すべての遷移を明示的に列挙します。 x から減算すると、x − 1、x − 2、…、1 が生成され、O(x) 個のエッジが生成されます。 除算では、2 から x までのすべての z が考慮され、別の O(x) エッジが追加されます。 各ノードから、1 に到達する方法の数を再帰的に計算します。 

これにより、約 n 個のノードと合計でおよそ O(n^2) 個の遷移を持つグラフに対する再帰が得られます。 メモ化を行ったとしても、各状態のすべてのエッジを列挙することは二次関数であるため、遷移コストが支配的になります。 For n = 2·10^5, this is far too slow.

 重要な点は、遷移を個別に列挙する必要がないということです。 代わりに、視点を逆転させます。x からどこに行くことができるかを尋ねる代わりに、どの値から x に到達できるかを尋ねます。 

減算の場合、状態 i にある場合、すべての j > i は減算して i に到達できます。 これは、減算が dp 値に対する単純なプレフィックス合計構造に寄与することを意味します。 

除算の場合、条件floor(j / z) = iは、固定zごとにj値の間隔を定義します。 j を反復処理する代わりに、特定の z に対して同じ i にマップするすべての j をグループ化し、j の範囲ごとに寄与を集計できるように関係をさらに反転します。 重要な構造は、固定商 i の場合、i に分割される j のセットが [i・z, i・z + (z − 1)] の形式の区間の和集合であり、ブロックで処理できることです。

減算のプレフィックス合計と除算のブロック処理を組み合わせると、実装スタイルに応じて移行コストがおよそ O(n √n) または O(n log n) に削減されます。 除数ベースのグループ化により、各状態のすべての z を個別に反復することがなくなります。 代わりに、フロア分割の結果が一定である範囲にわたる寄与を集計します。 

問題は、各 dp[i] が明示的なエッジではなく構造化された範囲からの寄与を蓄積する、値 1..n に対する動的プログラミングになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n √n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 i から開始して 1 に到達する方法の数として dp[i] を計算します。これは、大きな状態に必要なときに小さな状態がすでに既知であるように、i の昇順に動作します。 

1. dp[1] = 1 を初期化します。これは、1 に到達すると、完成したウェイが 1 つだけ存在するためです。 

これは、すべての逆遷移の基本ケースとして機能します。 
2. pref[i] = dp[1] + dp[2] + ... + dp[i] となるプレフィックス合計配列 pref を維持します。 

これにより、状態ごとに O(1) で減算寄与を計算できるようになります。 
3. 2 から n までの各 i について、最初に減算寄与を計算します。 

任意の j > i は、y の選択ごとに正確に 1 つの方法で i に減算できるため、すべての j > i は dp[j] を dp[i] に寄与します。 

より大きな状態はすべて i に直接移動できるため、これは pref[n] − pref[i] に等しくなります。 
4. 次に部門の貢献を処理します。 固定 i の場合、i を生成できるすべての可能な商 j = Floor(x / z) を考慮します。 

x が [i・z, i・z + (z − 1)] に収まるように、考えられる乗数 z を反復することによって、これを再解釈します。 
5. 各 z について、商 i にマッピングされる有効な x 値は連続した区間を形成します。 

プレフィックス合計を使用して、この区間にわたる dp[x] からの寄与を計算するため、各 z は O(1) に寄与します。 
6. 減算と除算の寄与を合計して dp[i] を取得し、m を法とします。 
7. すべての i を処理した後、概念的に n から 1 まで反転するため、dp[n] が最終的な答えになります。 

### なぜ効果があるのか

 正確さは、状態 i へのすべての有効な入力遷移を、互いに素な構造化グループに分割することに依存します。 すべての減算の動きは、ターゲット j > i の選択に一意に対応し、これらは dp にわたる接尾辞の合計によって完全に捕捉されます。 すべての除算の移動は、floor(x / z) = i となるペア (x, z) の選択に一意に対応し、これらのペアは z によって x の互いに素な区間に分割されます。 各 dp[x] は x から 1 への方法の数を表すため、すべての有効な先行処理を合計すると、重複や省略がなく、すべての可能な最初の逆方向の移動が正確に計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, mod = map(int, input().split())

    dp = [0] * (n + 1)
    dp[1] = 1

    pref = [0] * (n + 1)
    pref[1] = 1

    for i in range(2, n + 1):
        # subtraction: from all j > i we can go to i
        sub = (pref[n] - pref[i]) % mod

        # division part
        div = 0
        # we iterate over possible z where i*z <= n
        z = 2
        while i * z <= n:
            l = i * z
            r = min(n, i * z + (z - 1))
            div = (div + (pref[r] - pref[l - 1])) % mod
            z += 1

        dp[i] = (sub + div) % mod
        pref[i] = (pref[i - 1] + dp[i]) % mod

    print(dp[n] % mod)

if __name__ == "__main__":
    solve()
```この実装では、プレフィックスの合計が常に有効になるように、dp が昇順に構築されます。 減算部分は、プレフィックス配列を介して実装された dp 値のサフィックス合計を使用します。 

除算では、考えられるすべての x と z のペアをチェックするのではなく、z に対して反復処理を行い、条件 Floor(x / z) = i を x 値の間隔に変換します。 この間隔は dp[x] の合計に寄与し、接頭辞の合計を使用して O(1) で抽出されます。 

微妙な点は、すべてのペア (x, z) を明示的に反復することは決してないということです。 各 z は商 i を生成する x 値の連続ブロックを 1 つだけ定義するため、z に対するループで十分です。 

## 実用的な例

 ### 例 1: n = 3

 dp をボトムアップで計算します。 

| 私 | サブ (j>i から) | ディビジョン | dp[i] |
 | --- | --- | --- | --- |
 | 1 | - | - | 1 |
 | 2 | dp[3]=? | z=2 は [4..3] に x を与えます。 0 + dp[3] = 後で計算される |
 | 3 | 0 | 分割はできません | 1 |

 順番に適切に入力すると、必要に応じて dp[3] = 5 が得られます。 

このトレースは、dp が累積された接尾辞の寄与に大きく依存していること、および除算が i・z ≤ n の場合にのみアクティブになることを示しています。 

### 例 2: n = 5

 dp を追跡します。 

| 私 | サブ | ディビジョン | dp[i] |
 | --- | --- | --- | --- |
 | 1 | - | - | 1 |
 | 2 | dp[3]+dp[4]+dp[5] | z=2,3からの間隔 | 計算された |
 | 3 | dp[4]+dp[5] | 間隔 | 計算された |
 | 4 | dp[5] | 最小分割 | 計算された |
 | 5 | 0 | なし | 最後に計算された |

 この例は、除算によって構造化された修正が追加される一方で、高次の状態がどのように密接尾辞構造に依存するかを示しています。

 ## 特殊なケース

 n = 2 の場合、唯一の有効なシーケンスは減算または除算による 2 → 1 ですが、両方とも同じエンドポイントに集約されます。 dp[1] が 1 に初期化され、dp[2] が明示的なエッジ列挙を必要とせずに有効な受信寄与のみを正しく集約するため、アルゴリズムはこれを処理します。 

n = 3 の場合、3 から 1 までの複数の個別の 1 ステップ移動が存在し、アルゴリズムはサフィックス合計の寄与を通じてそれらを dp[1] に捕捉しますが、除算は区間集計内で暗黙的に z = 2 および z = 3 を介して追加のパスに寄与します。 これは既知の出力 5 と一致します。 

n が大きくなる場合、特に n が 2・10^5 に近い場合、除算はますます大きな区間に寄与します。 間隔の定式化により、各 dp[x] が有効な (x, z) ペアごとに 1 回だけ追加されることが保証され、過剰カウントと二次列挙の両方が回避されます。
