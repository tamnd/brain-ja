 ## 解決策
 ## 問題の理解

 私たちには、一連の洞窟に直面する主人公が与えられています。 各洞窟には多数のモンスターがおり、それぞれに鎧の値があり、主人公は現在の力が厳密にモンスターの鎧よりも大きい場合にのみモンスターを倒すことができます。 モンスターを倒すと主人公の力が1上がります。 主人公は各洞窟に 1 回だけ入り、指定された順序で洞窟内のすべてのモンスターと戦い、無事に抜け出す必要があります。 課題は、主人公がすべての洞窟を順番にクリアできる最小の開始パワーを決定することです。 

入力では複数のテスト ケースが提供され、それぞれが洞窟の数と、各洞窟のモンスターの数とその鎧の値を順番に指定します。 出力は、各テスト ケースの最小開始電力です。 制約により、テスト ケースごとに、すべてのテスト ケース全体で合計最大 100,000 の洞窟と 100,000 のモンスターが許可されます。 これにより、ソリューションを 2 秒で効率的に実行する場合、テスト ケースごとの合計操作は約 10^5 に制限されます。 これにより、n の階乗となる洞窟次数のすべての順列を試みるアルゴリズムが除外されます。 

洞窟にアーマー値が厳密に減少しているモンスターがいる場合、明白ではないエッジケースが発生します。 たとえば、モンスターがいる洞窟`[10, 9, 8]`そしてもう一つは`[12]`慎重な順序が必要です。開始力を最小限に抑えるために、主人公は最初に 1 匹のモンスターで洞窟に取り組む必要があるかもしれません。 常に入力順に洞窟を選択する単純なアプローチでは、必要な初期パワーが過大評価される可能性があります。 同様に、非常に高い装甲を持つモンスターが 1 匹だけいる洞窟では、必要な開始パワーが大きくなる可能性があります。 

## アプローチ

 強引なアプローチは、洞窟の命令をすべて並べ替えて試し、主人公の進行状況をシミュレートすることです。 命令ごとに、ある程度のパワーから開始し、各洞窟を反復処理し、モンスターごとにヒーローの現在のパワーがモンスターの鎧を超えているかどうかを確認し、戦闘が成功するとパワーを増やします。 主人公がモンスターに勝てない場合は、その初期パワーを捨てて、より高い値を試します。 このアプローチは原理的には正しいですが、順列の階乗増加により、中程度の n の場合でも完全に実行不可能になります。 

重要な洞察は、各洞窟内で、主人公に必要な最小限の開始パワーは、最初のモンスターの鎧と、順番に戦わなければならないモンスターの数に依存するということです。 より正確に言うと、洞窟内のモンスターが鎧を着ている場合`[a_1, a_2, ..., a_k]`、この洞窟を単独で生き残るための最小の初期パワーは、`max(a_j - (j - 1)) + 1`、 どこ`j`モンスターを順番にインデックスします。 これは、各戦闘後のパワーの増加を説明します。 各洞窟のこの要件を計算すると、問題は最大の実行要件を最小限に抑える洞窟の順序を選択することになります。 

最適な戦略は、必要最小限の初期パワーで洞窟を分類し、その順序で主人公が洞窟を通過することをシミュレートすることです。 現在のパワーを追跡し、洞窟内のモンスターの数に応じて増加させ、必要な開始パワーを動的に調整して、ヒーローが決して失敗しないようにします。 これにより、すべての順列の試行が回避され、並べ替えによりテスト ケースごとの線形計算時間の計算量が実現されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(K log n) | O(n) | 承認済み |

 ここ、`K`すべての洞窟にいるモンスターの総数です。 

## アルゴリズムのチュートリアル

 1. 洞窟ごとに、その洞窟を単独でクリアするために必要な最小限の開始パワーを計算します。 必要なパワーを維持しながら、モンスターを順番に繰り返します。`max(required, monster_armor - position_index + 1)`。 洞窟を処理した後、洞窟内のモンスターの数とともにこの値を保存します。 
2. 計算された最小必要開始電力に基づいて洞窟を並べ替えます。 これにより、開始ヒーローパワーが低くてもクリアしやすい洞窟が優先され、すべての洞窟で必要な最大開始パワーが最小限に抑えられます。 
3.初期化`current_power`0として、そして`answer`0 として。ソートされた洞窟を反復処理します。 洞窟ごとに更新します`answer`として`max(answer, minimal_required_power - current_power)`主人公が洞窟に入ることができるようにするためです。 次にインクリメントします`current_power`洞窟内のモンスターの数によって、その洞窟内のすべてのモンスターを倒した後の累積パワー増加を反映します。 
4.すべての洞窟を処理した後、`answer`主人公がすべての洞窟を最適な順序で生き残るために開始する必要がある最小限の初期パワーが含まれています。 

機能する理由: アルゴリズムは、各洞窟の開始時に不変条件を維持します。`current_power + answer`少なくとも洞窟の最小要件と同じ大きさです。 最小の洞窟要件によって並べ替えると、ヒーローのパワーの最小増分が最初に発生し、全体の開始パワーが最小限に抑えられることが保証されます。 他の順序では、より高い始動電力が必要になるか、同じ結果が得られ、正確であることが確認されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def minimal_start_power(caves):
    cave_info = []
    for monsters in caves:
        k = len(monsters)
        req = 0
        for i, armor in enumerate(monsters):
            req = max(req, armor - i + 1)
        cave_info.append((req, k))
    
    cave_info.sort()
    answer = 0
    current_power = 0
    for req, k in cave_info:
        answer = max(answer, req - current_power)
        current_power += k
    return answer

def main():
    t = int(input())
    results = []
    for _ in range(t):
        n = int(input())
        caves = []
        for _ in range(n):
            data = list(map(int, input().split()))
            k = data[0]
            monsters = data[1:]
            caves.append(monsters)
        results.append(str(minimal_start_power(caves)))
    print("\n".join(results))

if __name__ == "__main__":
    main()
```このソリューションでは、各洞窟の計算を前処理ステップに分割して、必要な最小限の開始電力を計算します。 ソートにより、主人公が必要とする初期パワーを最小限に抑える順序で洞窟に取り組むことができます。 の`answer`変数は、現在の累積パワーが次の洞窟に不十分な場合にのみ更新され、オーバーシュートを防ぎます。 使用する`current_power += k`各洞窟後の累積ゲインを反映し、Python の任意サイズの整数によりオーバーフローの問題が回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K log n) | 洞窟ごとの最小必要パワーを O(K) で事前計算し、n 個の洞窟を O(n log n) でソート |
 | スペース | O(K + n) | 洞窟ごとにモンスターと最小限の電力を保管する |

 K ≤ 10^5 および n ≤ 10^5 の場合、アルゴリズムは 2 秒以内および 512 MB のメモリ制限内に快適に適合します。
