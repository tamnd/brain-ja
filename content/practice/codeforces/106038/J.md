 ## 解決策
 ## 問題の理解

 アイテムのコレクションが与えられ、各アイテムには 2 つの値が関連付けられています。 1 つの値は「どれだけ学ぶか」として解釈されるメリットを表し、もう 1 つは「どれだけの痛みを伴うか」として解釈されるコストまたは苦痛を表します。 

これらの項目から、すべてまたは 1 つだけを含む任意のサブセットを選択できます。 選択されたサブセットのスコアは、選択された項目の学習値の合計から、選択された項目の最大の痛みの値を引いたものとして定義されます。 このタスクは、入力項目のすべての接頭辞について、その接頭辞から任意のサブセットを選択することで取得できる最大スコアを計算することです。 

したがって、各プレフィックスについて、すべてのサブセットにわたる最適化問題、つまり総ゲインを最大にしてサブセット内の最悪 (最大) コストを差し引くという最適化問題を解決することになります。 

制約が大きいため、サブセットを列挙することは不可能です。 強引なアプローチでは、プレフィックスごとにすべての 2^n のサブセットを検査することになりますが、これは、n が約 40 であっても直ちに実行できません。n が 200000 までであっても、O(n log n) または O(n) に近い解が必要になります。 

微妙なエッジケースは、空のサブセットを選択する可能性から生じます。 項目を何も取らない場合、学習の合計はゼロになり、最大の痛みの値は存在しません。 この問題のほとんどの解釈では、これはゼロに寄与するため、最終的な回答ではベースラインとして考慮する必要があります。 もう 1 つの注意が必要なケースは、すべての学習値が負の場合です。 最適なサブセットには最大の痛みのペナルティを制御するために必要な項目が含まれている可能性があるため、すべての項目がネガティブな場合、常にポジティブな学習を伴う項目を含む素朴な貪欲戦略は失敗します。 

## アプローチ

 直接的なアプローチでは、プレフィックスのすべてのサブセットが試行されます。 各サブセットについて、学習値の合計を計算し、そのサブセット内の最大の痛みの値を差し引きます。 これは定義と正確に一致するため、正しいです。 ただし、サイズ n の各プレフィックスには 2^n 個のサブセットがあり、各サブセットのスコアの計算には O(n) のコストがかかり、制限時間内に実行できない指数関数的な爆発が発生します。 

重要な観察は、要素間の唯一の非線形相互作用が最大ペイン項であるということです。 学習値の合計は加算的で独立していますが、最大の痛みは、選択されたサブセット内の単一の最悪の要素にのみ依存します。 これは、どの要素がその最大値の原因であるかを条件付けする必要があることを示唆しています。 

項目 j を、選択したサブセット内で最大のペイン値を持つ要素に修正します。 これが修正されると、選択された他のすべてのアイテムの痛みは j の痛み以下でなければなりません。 また、j はサブセットに含まれている必要があります。 この条件下では、目的は、j が含まれていることを確認しながら、最大 bj の痛みを伴うアイテムのサブセットを選択し、学習値の合計を最大化し、最後に bj を 1 回減算することになります。 

痛み ≤ bj の制限された項目セット内では、最後の減算を除き、選択肢間に結合はありません。 したがって、すべての項目について、合計が改善される場合にのみ含めます。 つまり、正の学習値を持つすべての項目を含めます。また、最大の痛みを定義するために j が必要であるため、符号に関係なく常に j を含めます。 

これにより、項目を苦痛に基づいてソートし、プレフィックスを介して実行される構造を維持するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 項目を痛みの値の昇順に処理することで、各ステップで、特定の最大痛みのしきい値の下でどの項目を一緒に含めることが許可されているかを正確に知ることができます。

1. すべてのアイテムを痛みの値で降順でない順に並べ替えます。 これにより、特定の項目を最大の痛みの候補として検討する場合、そのサブセット内のすべての以前の項目が有効な選択肢となることが保証されます。 
2. ランニングバリューを維持する`pos_sum`、これまでに処理された項目間のすべての正の学習値の合計が保存されます。 必要とされない限り、ネガティブな学習項目は決して有益ではないため、これは制約なしで自由に摂取できる最善の貢献を表します。 
3. 並べ替えられた項目を繰り返し処理します。 各アイテム j について、そのペイン値 bj を候補サブセットの最大ペインとして扱います。 
4. この項目については、以下から開始して候補スコアを計算します。`pos_sum`次に、学習値が負であっても項目 j を含める必要があるという事実を修正します。 これは追加することで処理されます`min(a_j, 0)`。 
5. 最大ペインは、j が定義要素であるサブセットに対して 1 回だけ支払われるため、結果から bj を減算します。 
6. すべての項目の最大値を追跡し、空のサブセットを有効な回答として許可するためにゼロと比較します。 

### なぜ効果があるのか

 どの時点でも、最大痛みが bj であるすべてのサブセットは、定義する最大痛み要素として j を持たなければなりません。つまり、より高い痛みを持つアイテムは出現できず、正確に痛みが bj であるアイテムが少なくとも 1 つ存在する必要があります。 このようなすべてのサブセットの中で、正の学習値を持つすべての項目 (ペナルティに影響を与えることなくスコアが増加するため) を含め、必要な要素 j を除くすべての負の項目を除外することによって、合計が最大化されます。 目標の構造では、この制約を超えて含まれる項目間の相互作用がないことが保証されているため、最大ペイン アンカーに対するこの貪欲な分解はロスレスです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    items = []
    for _ in range(n):
        a, b = map(int, input().split())
        items.append((b, a))  # sort by pain

    items.sort()

    pos_sum = 0
    ans = 0

    i = 0
    while i < n:
        j = i
        # process all with same b together
        while j < n and items[j][0] == items[i][0]:
            j += 1

        # compute answers for this group using current prefix
        for k in range(i, j):
            b, a = items[k]
            cur = pos_sum + (a if a < 0 else 0) - b
            if cur > ans:
                ans = cur

        # update prefix after evaluating this group
        for k in range(i, j):
            b, a = items[k]
            if a > 0:
                pos_sum += a

        i = j

    print(max(ans, 0))

if __name__ == "__main__":
    solve()
```ソートのステップにより、現在のアンカーよりも痛みの高い項目が誤って含まれることがなくなります。 負の学習値は強制されない限り決して全体的に有益ではないため、接頭辞の合計は正の学習値のみを蓄積します。また、強制された包含は各項目を最大ペイン アンカーとして評価するときに明示的に処理されます。 

正しい痛みの値をグループ化することは厳密には必要ありませんが、特定の痛みのレベルのすべての候補が評価された後にのみプレフィックスの寄与が適用されるようにすることで、ロジックをクリーンに保ちます。 

## 実用的な例

 3 つの項目 (学習、痛み) が (5, 4)、(2, 1)、および (3, 3) に等しい入力を考えます。 

痛みごとに並べ替えると、(2,1)、(3,3)、(5,4) になります。 から始めます`pos_sum = 0`。 

最初の項目 (2,1) で、候補を 0 + 0 - 1 = -1 として計算し、更新します。`pos_sum`サブセットが空であるため、答えは 0 のままです。 

2番目の項目(3,3)では、候補は2 + 0 - 3 = -1となり、`pos_sum`5になります。 

3 番目の項目 (5,4) では、候補は 5 + 0 - 4 = 1 になります。これにより、答えは 1 に改善され、すべての項目を選択して最大の苦痛 4 を支払うことに相当します。 

このトレースは、アルゴリズムがどのようにネガティブ項目へのコミットメントを遅らせ、それらを必要なアンカーとしてのみ評価するかを示しています。

 ## 特殊なケース

 すべての学習値が負の場合でも、アルゴリズムは各項目を潜在的な最大痛みアンカーとして評価しますが、その恩恵を受けることはありません。`pos_sum`。 最良の結果は、何も選択しないことによってゼロになるか、他のものよりも悪くない強制的な包含のいずれかになります。 

たとえば、入力 (-2, 1)、(-1, 3) の場合、ソートされた順序により、候補 -1 と -3 が与えられますが、どちらもゼロ未満であるため、アルゴリズムは正しくゼロを出力します。 

複数のアイテムが同じペイン値を共有する場合、プレフィックスが更新される前に、各アイテムがアンカー候補として評価されます。 これにより、異なる項目が最大のペインとして機能するサブセットが誤ってマージされることがなくなり、結合された制約の正確性が維持されます。
