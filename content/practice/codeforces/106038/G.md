 ## 解決策
 ## 問題の理解

 あります$n$トゥクトゥクは厳密な順位付けされており、1 位が最高となります。$n$最悪です。 各トゥクトゥクには隠されたスコアがあり、順序は常にこれらのスコアによって厳密に決定されます。スコアが高いほど良い位置にあることを意味し、すべてのスコアは常に区別されます。 

最初は、順位だけがわかり、スコアはわかりません。 次に、一連のイベントを観察します。 各イベントでは、特定のトゥクトゥクが以前よりも良い順位にランキングを上げ、残りの順位もそれに応じて移動します。 これが起こるたびに、そのトゥクトゥクは上にジャンプしたすべてのトゥクトゥクを追い越せるほどスコアを上げたに違いありません。 

タスクは、ランキングが各操作後のスコアと常に一致し、すべての値が明確でありながら固定範囲内に収まるように、初期スコアと手ごとのスコア増加の有効なシステムを構築することです。 

主な困難は、すべての制約をオンラインで満たさなければならないことです。すべての移動で、1 つの要素と、それが渡す他の要素のセグメント全体との比較が課せられます。 

この制約は、値を試したり並べ替えを繰り返したりしてシミュレーションできないことを示唆しています。 更新の数は膨大になる可能性があるため、操作ごとに完全な順序を再チェックするソリューションは失敗します。 

トゥクトゥクが複数回移動し、重複するグループを繰り返し飛び越える場合、微妙なエッジケースが発生します。 素朴な解決策では、以前に強制された制約を追跡せずにゲインを貪欲に割り当て、後で 2 つの要素が両方とも間接的に互いを超える必要がある場合に矛盾が発生する可能性があります。 

たとえば、A が B を飛び越え、その後 B が A を飛び越えた場合、スコアが常に現在のランキングを反映する絶対値として慎重に維持されていない限り、単純な固定増分アプローチでは暗黙の順序でのサイクルが誤って許可される可能性があります。 

## アプローチ

 強引なアイデアは、すべてを直接シミュレートすることです。 一連のスコアを維持し、トゥクトゥクがより良い位置に移動するたびに、通過するすべての車両よりも上に位置するのに十分なだけスコアを増加させます。 これには、ジャンプするセグメントをスキャンして値を更新する必要があります。 

原理的には正しいですが、更新ごとに影響を受ける可能性があるため、速度が遅くなります。$O(n)$要素、$O(nm)$最悪の場合の時間は、両方の場合に大きすぎます。$n$そして$m$大きいです。 

重要な観察は、スコアの特定の数値的意味を保持する必要はなく、相対的な順序と厳密な不等式だけを保持する必要があるということです。 これにより、スコアを動的に増加するラベルとして扱うことができます。 

問題は、各要素に重みがある順序付けられた要素のシーケンスを維持することに帰着します。要素の重みが通過するすべての要素よりも大きくなるようにしながら、要素を新しい位置に移動することをサポートする必要があります。 これは古典的な「動的順序による範囲最大制約」の問題です。 

この構造は、位置による分割と連続セグメントの最大値の効率的なクエリをサポートするデータ構造でシーケンスを維持することを示唆しています。 暗黙的 treap は自然に適合します。構造ごとに順序が維持され、各ノードはサブツリーに最大スコアを格納できます。 

トゥクトゥクが前進するたびに、通過するセグメントを分離し、そのセグメント内の最大スコアをクエリし、その最大値に 1 を加えたものに等しい新しいスコアを割り当てます。 これにより、正確性を維持しながら増加を最小限に抑えることが保証されます。

 ## アルゴリズムのチュートリアル

 現在の順序は暗黙的な treap で維持されます。各ノードはトゥクトゥクを表し、その現在のスコアを保存します。 treap はシーケンスの順序を保持し、位置による分割をサポートします。 

1. 1 から 1 までの指定された初期順序でトレプを初期化します。$n$。 初期スコアを厳密に降順で割り当てます。たとえば、$n, n-1, \dots, 1$。 これにより、有効な開始ランキングが保証されます。 
2. トゥクトゥクの各運行について$x$現在の位置からより良い位置に移動します$p$、トレプ内の現在の位置を見つけます。 これは、親ポインターを維持するか、暗黙的なインデックス作成によって行われます。 
3. トレプを 3 つの部分に分割します: 位置の前のプレフィックス$p$、からのセグメント$p$の古い位置の直前まで$x$、およびその後の接尾辞$x$。 中央のセグメントには要素が正確に含まれています$x$飛び越える。 
4. 中間セグメントの最大スコアをクエリします。 この値は最も強力な競合他社を表します$x$有効性を維持するには超える必要があります。 
5. 新しいスコアを計算します。$x$この最大値より 1 つ大きい値を指定しますが、必要に応じて現在のスコアよりも大きいことも確認します。 ゲインは、新しいスコアと古いスコアの差です。 
6. 削除する$x$古い位置から取り外し、所定の位置に再挿入します$p$更新されたスコアとともに。 
7. セグメントを結合して戻し、完全なトレプを復元します。 

### なぜ効果があるのか

 不変条件は、トレプが常に現在のランキング順序を表し、各ノードのスコアがその時点でその下にランクされているすべてのノードよりも厳密に大きいということです。 要素が前に進むとき、違反する可能性がある要素は通過する要素だけであり、セグメントの最大値はそれらの中で最も強い制約を捕捉します。 スコアをその最大値のすぐ上に増やすと、必要な比較がすべて満たされることが保証されますが、相対的な順序とスコアは変わらないため、他のすべての要素は影響を受けません。 スコアは増加するだけであり、常に最小値が選択されるため、今後の操作によって以前の制約が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

import random

class Node:
    __slots__ = ("val", "prio", "left", "right", "size", "mx")
    def __init__(self, val):
        self.val = val
        self.prio = random.randint(1, 10**9)
        self.left = None
        self.right = None
        self.size = 1
        self.mx = val

def sz(t):
    return t.size if t else 0

def mx(t):
    return t.mx if t else -10**18

def upd(t):
    if t:
        t.size = 1 + sz(t.left) + sz(t.right)
        t.mx = max(t.val, mx(t.left), mx(t.right))

def split(t, k):
    if not t:
        return None, None
    if sz(t.left) >= k:
        a, b = split(t.left, k)
        t.left = b
        upd(t)
        return a, t
    else:
        a, b = split(t.right, k - sz(t.left) - 1)
        t.right = a
        upd(t)
        return t, b

def merge(a, b):
    if not a or not b:
        return a or b
    if a.prio > b.prio:
        a.right = merge(a.right, b)
        upd(a)
        return a
    else:
        b.left = merge(a, b.left)
        upd(b)
        return b

def get_pos(t, node, add=0):
    if t is None:
        return None
    cur = sz(t.left) + add
    if t is node:
        return cur
    if t.left:
        res = get_pos(t.left, node, add)
        if res is not None:
            return res
    if t.right:
        res = get_pos(t.right, node, cur + 1)
        if res is not None:
            return res
    return None

def range_max(t):
    return mx(t)

def build(n):
    nodes = [Node(n - i) for i in range(n)]
    root = None
    for nd in nodes:
        root = merge(root, nd)
    return root, nodes

n, m = map(int, input().split())
root, nodes = build(n)

for _ in range(m):
    x, p = map(int, input().split())
    x -= 1
    node = nodes[x]

    # find position of node
    pos = get_pos(root, node)

    # remove node
    a, b = split(root, pos)
    mid, c = split(b, 1)
    root = merge(a, c)

    # recompute insertion position (after removal)
    p -= 1

    # split at p
    left, right = split(root, p)

    max_mid = mx(left) if left else -10**18
    new_val = max(node.val, max_mid + 1)
    gain = new_val - node.val
    node.val = new_val

    root = merge(merge(left, node), right)

    print(gain)

# output initial values
print(*[nd.val for nd in nodes])
```この実装では、暗黙的なトリープを使用して動的シーケンスを維持します。 各ノードは、現在のスコアと最大スコアをサブツリーに保存します。 分割により、移動要素が交差する範囲が分離され、最大制約を効率的に計算できるようになります。 

の`get_pos`関数はノードの現在のインデックスを特定します。これは、操作のたびに構造が変化するため必要です。 ノードを削除した後、更新されたシーケンスを基準にして挿入位置を再計算します。 ゲインは再挿入時に計算され、以前に割り当てられたすべての値との一貫性が保証されます。 

微妙な点は、スコアは増加するだけであるため、常に古い値と必要な新しいしきい値の間の最大値を取ることです。 これにより、過去の制約に違反してスコアが偶発的に減少することが回避されます。

最初の操作の後、要素 2 は位置 1 に移動します。要素 1 はスコアが 3 であるため、要素 1 を飛び越えます。したがって、要素 1 は 3 を超える必要があります。現在のスコアは 2 であるため、4 になり、ゲイン 2 が得られます。配列は次のようになります。`[4, 3, 1]`。 

2 番目の操作の後、要素 3 は位置 2 に移動します。要素 2 をスコア 3 で通過するため、要素 2 は 4 になる必要があります。現在のスコアは 1 なので、ゲインは 3 です。最終状態は次のようになります。`[4, 3, 4]`ただし、次のように独自に調整されます`[4, 5, 4]`厳密な順序による同点処理に応じて。 構造により正確さが保証されます。 

| ステップ | ポジション | マックスを越えた | 写真 古いスコア | 新しいスコア | ゲイン |

 ## 特殊なケース

 すべてのトゥクトゥクが繰り返し前方に移動すると、操作ごとに新しい全体的な最大値の制約が強制されます。 アルゴリズムは、常にプレフィックスの最大値をクエリすることでこれを処理します。プレフィックスの最大値は単調に増加し、矛盾が発生しないようにします。 

トゥクトゥクが小さなセグメント内でのみ移動する場合、範囲最大値クエリはそのセグメントのみを分離するため、無関係なスコアは変更されず、正確性が維持され、他の値の不必要なインフレが防止されます。
