 ## 解決策
 ## 問題の理解

 時系列でソートされた個別の整数のリストが与えられます。各整数は、ベルナルドがジムに行った日を表します。 目標は、このリスト内に存在する連続暦日の最長連続日数を決定することです。 ストリークは、日が 1 つだけ異なる場合に形成されます (5、6、7 が長さ 3 のストリークを形成するなど)。このような連続シーケンスすべてにわたって最大長が必要です。 

入力サイズは記録された訪問数に線形であるため、配列を繰り返しスキャンしたり、すべての開始点から間隔を拡張しようとするソリューションであっても、1 秒以内に最大約 200,000 個の要素を処理できる十分な効率性が必要です。 すでにソート済みのデータに対するネストされたスキャンは、最悪の場合、10^10 の演算のオーダーを容易に超えるため、これにより二次的な動作が除外されます。 

一般的な失敗モードは、すべてのペアを考慮する必要があるか、インデックスごとにストリークの長さを個別に再計算する必要があるかのように問題を扱うことから発生します。 たとえば、与えられた入力`1 2 3 4 10 11`単純なアプローチでは、各インデックスから開始して前方チェックを繰り返し、重複するセグメントを複数回再計算する可能性があり、冗長で遅くなります。 

もう 1 つの微妙なエッジ ケースは、連続する要素がまったくない場合です。 たとえば、入力`5 10 20`毎日が長さ 1 の連続として独立しているため、1 を返す必要があります。 少なくとも 1 つの連続したペアが存在すると仮定し、答えを誤って初期化するソリューションは、ここで失敗する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。配列内の各位置をストリークの開始点として扱い、次の値が現在の値よりちょうど 1 大きい間、前方に拡張します。 これにより、各インデックスから始まる最長のストリークが正しく計算され、すべての開始点の最大値を取ることで正しい答えが得られます。 

ただし、このアプローチでは、重複するセグメントが繰り返しスキャンされます。 最悪の場合、配列自体が単一の長く連続したシーケンスである場合、次のようになります。`1 2 3 4 ... n`、最初のインデックスは n 個の要素をスキャンし、2 番目のインデックスは n-1 をスキャンするというように、約 n²/2 個の比較が行われます。 n が大きい場合、これは遅くなりすぎます。 

重要な点は、配列がすでにソートされているため、連続するシーケンスが連続したブロックとして表示されることです。 すべてのインデックスでスキャンを再開するのではなく、左から右に 1 回スイープするときに現在のストリークの長さを追跡するだけで済みます。 連続する要素間の差がちょうど 1 の場合、ストリークを延長します。 それ以外の場合はリセットします。 これにより、冗長な再計算がすべて削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在の連続ストリークの長さとこれまでに確認された最良の答えを維持しながら、配列を 1 回のパスで処理します。 

1. 変数を初期化する`best`単一要素は長さ 1 の有効なストリークを形成するため、1 となります。 これは、連続するペアがない場合に対処します。 
2.初期化`cur`1 は、最初の要素で終わる現在のストリークの長さを表します。 
3. 2 番目の要素から配列の最後まで繰り返します。 各インデックスで`i`、 比較する`a[i]`と`a[i-1]`。 
4. もし`a[i] == a[i-1] + 1`、増分`cur`連続記録が途切れることなく続くため、1 ずつ増えます。 これは、連続する日数の定義を直接エンコードします。 
5. それ以外の場合はリセットします`cur`ストリークが途切れ、その位置から新しいストリークが始まるため、1 に`i`。 
6. アップデート後`cur`、 アップデート`best`として`max(best, cur)`アレイ内の任意の場所で見られる最大のストリークを追跡します。 
7. ループ終了後、出力`best`。 

正確さは、すべてのインデックスで次の不変条件を維持することで得られます。`i`、`cur`正確に終了する最長連続ストリークの長さに等しい`i`。 すべてのストリークは何らかの位置で終了する必要があるため、そのようなエンドポイントをすべて追跡することで、グローバル最大値を確実に捕捉できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    if not data:
        return

    n = data[0]
    arr = data[1:]

    # In some inputs n may not be needed explicitly if all values are present
    # but we trust format: first number is n, followed by n values.
    if len(arr) < n:
        arr += list(map(int, input().split()))

    if n == 0:
        print(0)
        return

    best = 1
    cur = 1

    for i in range(1, n):
        if arr[i] == arr[i - 1] + 1:
            cur += 1
        else:
            cur = 1
        if cur > best:
            best = cur

    print(best)

if __name__ == "__main__":
    solve()
```コードは 1 回のリニア スキャンを実行します。 保持される唯一の状態は、現在のストリークの長さとこれまでの最良の結果です。 比較`arr[i] == arr[i-1] + 1`が意思決定メカニズム全体であり、それ以外はすべて簿記です。 

よくある実装上の間違いは、シーケンスが途切れたときに現在のストリークをリセットするのを忘れることです。これにより、ギャップ全体の値が誤って蓄積されてしまいます。 もう一つは初期化中です`best`配列に少なくとも 1 つの要素があるが、連続するペアがない場合は失敗します。

 ## 特殊なケース

 重要なエッジケースは、配列のサイズが 1 の場合です。 アルゴリズムは両方を初期化します`cur`そして`best`を 1 に設定するため、ループ反復に入らずに直接 1 を出力します。 入力用`7`、状態は変化せず、答えは正しく 1 です。 

もう 1 つのケースは、シーケンス全体が厳密に増加しているが連続的ではない場合です。`1 3 4 6`。 アルゴリズムがリセットされる`cur`ブレークごとに、無効なマージが発生しないようにします。 決勝戦`best`ペアにより 2 になります`3 4`、これは正しい最長の連続セグメントです。 

最後の微妙なケースは、最長の連続が最初または最後にある場合です。 以来`best`休憩時だけでなく、各ステップの後に更新されます。`1 2 3 4`または`10 11 12 13`特別な後処理を必要とせずに完全にキャプチャされます。
