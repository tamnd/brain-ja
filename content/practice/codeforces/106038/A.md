 ## 解決策
 ## 問題の理解

 私たちは、カメのラファエル、レオナルド、ドナテロ、ミケランジェロという 4 人の固定候補者の間での投票を追跡しています。 各候補者はすでにある程度の票を持っており、まだ投じられていない残りの票がプールされています。 残りの投票はすべて 4 人の候補者のうちの 1 人に与えられることになりますが、どのように配分されるかはわかりません。 

候補者が勝利するのは、残りのすべての票がその候補者にとって最も有利な方法で割り当てられた後、最終的に総得票数の半分を厳密に超える場合のみです。 課題は、どのタートルが唯一の多数派勝者になる理論的な道をまだ持っているかを判断することです。 

常に 4 つの候補があるため、入力サイズは構造上一定です。 唯一変化するのは残りの投票数であり、これは大きくなる可能性があります。 これにより、複雑なデータ構造や投票に関するシミュレーションの必要性が即座に排除されます。 残りの投票の分布を列挙しようとする解決策は本質的に指数関数的であり、残りの投票のそれぞれが独立して 4 つの候補者のうち 1 つを選択するため、中程度の値であっても不可能です。 

現在明らかなリードを持っている候補者がいないにもかかわらず、残りの票が誰かの過半数を形成するには不十分である場合、微妙なエッジケースが発生します。 たとえば、すべての投票がすでに投じられており、半数を超える人がいない場合、勝者はあり得ません。 もう 1 つの特殊なケースは、1 人の候補者がすでに強力なリードを持っているが、残りの票を最適に再配分できればまだ追い抜かれる可能性がある場合です。 

次のシナリオを考えてみましょう。現在の投票数は 10 0 0 0 で、残りの投票数は 5 です。 合計は 15 になるため、過半数には少なくとも 8 票が必要です。 ラファエルはすでに 10 を持っているので、条件を簡単に満たしていますが、他のものを注意深く確認する必要があります。 レオナルド、ドナテロ、ミケランジェロの場合は、残りの5票すべてに加えて追加の赤字回復が必要となるが、これは不可能である。 

別のシナリオ: 1 1 1 1、残り 4 票。 合計は 8 になり、過半数のしきい値は 5 になります。各候補者は残りの 4 票をすべて受け取ることができ、最終的には 5 票になるため、全員が依然として勝者の可能性があります。 現在の指導者だけが重要であるという素朴な解釈は、ここでは正しくありません。 

## アプローチ

 強引なアイデアは、残りの各票を 4 人の候補者に分配し、考えられるすべての結果をシミュレーションすることです。 各投票には 4 つの選択肢があるため、次のようになります。$4^r$可能性はどこにあるのか$r$残りの投票数です。 たとえ$r = 20$、これはすでに構成の数が 10 億を超えており、実行不可能になっています。 

重要な観察は、分布をシミュレートする必要がないということです。 固定された候補者については、最終的な合計の半分を超えることを可能にする残りの票の割り当てが存在するかどうかだけを知る必要があります。 候補者にとって考えられる最良のシナリオは、残りの票がすべて自分に与えられることです。他の人に票を与えると、その候補者の仕事がさらに難しくなるだけだからです。 これにより、問題は候補ごとの直接的な実現可能性チェックに集約されます。 

最終的な総投票数は、現在のすべての投票と残りの投票の合計として計算されます。 勝利の基準は厳密にこの合計の半分以上です。 各候補者について、現在の投票と残りのすべての投票が厳密にこのしきい値より大きいかどうかを確認します。 「はい」の場合、彼らはまだ勝つことができます。 それ以外の場合は削除されます。

 ## アルゴリズムのチュートリアル

 私たちは問題を各候補の単純な不等式を評価することに落とし込みます。 

1. 現在の 4 つの投票数と残りの投票数を読み取ります。 また、すべての投票が終了した後、4 つの現在の値を合計し、残りの投票を加算することで、総投票数を計算します。 
2. 各候補者について、残りのすべての票を獲得すると仮定して、可能な限り最高の最終スコアを計算します。 これはその候補者にとって最も有利なケースであり、達成可能な結果に上限が与えられます。 
3. 過半数のしきい値を最終投票総数の半分として計算し、この値よりも厳密に大きいことが必要です。 同点では勝者は生まれないため、この厳格さが重要です。 
4. 各候補者について、最良の場合のスコアが過半数のしきい値を超えているかどうかを確認します。 そうであれば、彼らにはまだ勝つチャンスがあるとマークされます。 
5. このようなすべての候補をアルファベット順に出力します。 該当する者がいない場合は、勝者がいないことを示す文字列を出力します。 

### なぜ効果があるのか

 どの候補者にとっても、残りの票を分散しても最終的な総票数は減るだけですが、総票数は配分に関係なく固定されます。 勝利条件は固定しきい値に対する最終合計のみに依存するため、候補者に残りのすべての票を与えることによって候補者にとって最良の結果が得られます。 この最大シナリオでも過半数のしきい値を超えられない場合、代替の割り当てはしきい値を変更せずに厳密にスコアを下げるため、他の分布は役に立ちません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    r, l, d, m, rem = map(int, input().split())
    names = [("Donatello", d), ("Leonardo", l), ("Michelangelo", m), ("Rafael", r)]

    total = r + l + d + m + rem
    threshold = total // 2  # must be strictly greater

    res = []

    for name, cur in names:
        if cur + rem > threshold:
            res.append(name)

    if not res:
        print("sem vencedores")
    else:
        res.sort()
        for x in res:
            print(x)

if __name__ == "__main__":
    main()
```解決策は、5 つの整数を読み取り、候補者を現在の投票数でグループ化することから始まります。 最終的な投票の合計数は、残りの投票がどのように配分されるかには依存しないため、一度計算されます。 しきい値は整数の除算を使用して導出され、実現可能性をチェックする際には厳密な不等式に依存します。 

各候補者は、現在の投票数に残りのすべての票を加算することによって独立して評価されます。 これは、最良の場合の推論を直接実装します。 入力内の候補の順序が必要な出力順序と一致することが保証されないため、ソートにより出力が確実にアルファベット順になります。 

よくある落とし穴は、`>=`の代わりに`>`。 この問題では厳密に半分以上が必要であるため、平等であることは勝利とはみなされません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import isclose

    r, l, d, m, rem = map(int, _sys.stdin.readline().split())
    names = [("Donatello", d), ("Leonardo", l), ("Michelangelo", m), ("Rafael", r)]
    total = r + l + d + m + rem
    threshold = total // 2

    res = [name for name, cur in names if cur + rem > threshold]

    if not res:
        return "sem vencedores"
    res.sort()
    return "\n".join(res)

 ## 特殊なケース

 重要なエッジケースの 1 つは、投票が残っていない場合です。 たとえば、入力`5 4 3 3 0`結果は固定され、スコアを変更することはできません。 アルゴリズムは合計を 15 として計算し、しきい値を 7 として計算します。現在のスコアはすべてこのしきい値以下であるため、厳密な条件を通過する候補者はいません。 このチェックでは、各候補が次のように正しく評価されます。`cur + 0 > threshold`、勝者は生まれません。 

もう 1 つのエッジ ケースは、すべての候補者が同等で、過半数を形成するのに十分な票が残っている場合です。 のために`1 1 1 1 4`、合計は 8 になり、しきい値は 4 になります。各候補には最良のケース 5 があり、しきい値を超えているため、すべてが出力されます。 アルゴリズムは、現在のランキングが重要であると想定せずに各候補を個別に評価するため、これを自然に処理します。
