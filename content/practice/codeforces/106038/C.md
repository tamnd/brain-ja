 ## 解決策
 ## 問題の理解

 丸括弧の配置が与えられています。 文字列には次のみが含まれます`'('`そして`')'`、開き括弧と閉じ括弧の合計数は同じです。 文字列の接頭辞を取得して末尾に移動し、文字列を効果的に回転させることができます。 タスクは、結果のシーケンスを有効な括弧文字列にする回転を選択し、先頭から何文字移動する必要があるかを出力することです。 

ここでの有効な括弧シーケンスとは、左から右にスキャンした場合、どの接頭辞でも閉じ括弧が開き括弧よりも多く表示されず、最後にカウントが一致することを意味します。これは入力によってすでに保証されています。 

重要な制約は、文字列の長さが一般的な Codeforce の制限までであることです (暗黙的に長いため、線形または線形に近い解決策が期待されます)。 すべてのローテーションを試して妥当性を最初からチェックする 2 次アプローチでは、各チェックが O(n) であり、全体で O(n²) になるため、時間がかかりすぎます。 

複数の回転によって有効なシーケンスが生成される場合、微妙なエッジ ケースが発生します。 例えば、`"()()"`はすでに有効なので、0 で回転するのは正しいですが、2 で回転することもできます。 この問題では有効な答えが許可されているため、正しい回転は 1 つだけ必要です。 

もう 1 つのエッジ ケースは、弦のバランスが完全に逆になっている場合です。`"))((()"`。 グローバル カウントだけでなく中間プレフィックスも重要であるため、総カウントのみを単純にチェックすると失敗します。 

## アプローチ

 ブルートフォース戦略では、あらゆるローテーションを試みます。 各回転インデックス i について、回転された文字列を構築し、左から右にスキャンしてバランスを追跡することによって、それが有効かどうかを確認します。 各妥当性チェックには O(n) のコストがかかり、n 回のローテーションがあるため、O(n²) 時間がかかります。 これは、n が大きい場合には遅すぎます。 

問題の構造は、妥当性を最初から再計算することは避けるべきであることを示唆しています。 重要な観察は、括弧シーケンスの有効性はプレフィックスのバランスのみに依存し、ローテーションは同じ巡回シーケンスの読み取りを開始する位置からシフトするだけであるということです。 したがって、文字列を再構築する代わりに、二重ビューまたは循環ビューにわたるプレフィックスの合計の観点から考えることができます。 

残高を +1 として定義します。`'('`および -1`')'`。 位置 i から始まる回転の場合、セグメント内のすべてのプレフィックスの合計が必要です`[i, i+n-1]`（循環的に）ネガティブでない状態を維持すること。 

重要なアイデアは、トラバーサルを開始するときに、負のプレフィックス合計を回避する可能性が最も高い位置を見つけることです。 これは、元の配列で最小プレフィックス バランスを追跡し、累積バランス曲線の最低点の直後から開始するローテーションを選択することで特定できます。 これにより、再中心化されたときにパスがゼロを下回ることはなくなります。 

これにより、プレフィックスのバランスを計算し、最小プレフィックス合計のインデックスを特定する単一の線形スキャンにタスクが削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 (プレフィックス最小ローテーション) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を括弧に応じて +1 値と -1 値の配列に変換します。 これにより、問題は文字列構造ではなく累積合計の追跡に変わり、回転効果の推論が容易になります。 
2. 文字列を左から右にスキャンしながらプレフィックスの合計を計算します。 それぞれの時点の合計を記録してください`'('`合計が増加し、それぞれ`')'`それを減らします。 これは、シーケンスが各ポイントで有効性しきい値をどれだけ上回るか下回るかを表します。 
3. プレフィックスの合計が最小値に達するインデックスを追跡します。 このポイントは、シーケンス全体にわたるバランスの最も深い落ち込みに対応します。 直観的には、これが循環構造の最も弱い点であると考えられます。 
4. この最小点が新しい文字列の開始直前になるように回転を選択します。 具体的には、最小プレフィックスがインデックス i にある場合、i+1 位置ずつ回転します。 
5. この回転インデックスを出力します。 複数の有効な選択肢が存在する場合、そのようなローテーションはすべて負のプレフィックス合計を回避するため、最小到達位置は機能します。 

### なぜ効果があるのか

 プレフィックス和曲線は、ゼロで始まりゼロで終わるウォークを表します。 有効な括弧のシーケンスは、まさにゼロを下回らないウォークです。 シーケンスを回転すると、この循環ウォークの新しい開始点を効果的に選択することになります。 最適な開始点はグローバル最小値の直後です。これにより、曲線全体が上方にシフトし、最低点が負ではなくゼロになるためです。 他のすべてのプレフィックスはこの最小値以上であるため、ローテーションされたバージョンのプレフィックスは負になることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

min_prefix = 0
min_idx = -1

pref = 0

for i, ch in enumerate(s):
    if ch == '(':
        pref += 1
    else:
        pref -= 1

    if pref < min_prefix:
        min_prefix = pref
        min_idx = i

# rotate so that min prefix position moves to end of prefix
print(min_idx + 1)
```このコードは、最低値が発生する場所を追跡しながら、単一パスで累積残高を計算します。 変数`min_idx`プレフィックスの合計が最小となる最後の位置を格納します。 このインデックスの後に回転すると、バランスが全体的に負でないポイントからシーケンスが開始されることが保証されます。 

一般的な微妙な点は、off-by-one の処理です。`min_idx + 1`、 ない`min_idx`これは、新しい文字列を最も低い接頭辞ポイントの直後から開始する必要があるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    n = len(s)

    min_prefix = 0
    min_idx = -1
    pref = 0

    for i, ch in enumerate(s):
        pref += 1 if ch == '(' else -1
        if pref < min_prefix:
            min_prefix = pref
            min_idx = i

    return str(min_idx + 1)

# provided samples
assert run("))((()\n") == "2"
assert run("()\n") == "0"
assert run("))((\n") == "2"

# custom cases
assert run("()") == "0", "already valid"
assert run(")(()") == "1", "single correction via rotation"
assert run("((()))") == "0", "fully nested already valid"
assert run(")))(((") == "3", "large imbalance symmetric"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`()`|`0`| すでに有効なので、回転する必要はありません |
 |`)(()`|`1`| 初期の負の接頭辞を修正するにはローテーションが必要です。 
|`)))(((`|`3`| 最悪の場合の不均衡、正しい最小インデックス処理をチェックします。 

## 特殊なケース

 エッジ ケースの 1 つは、文字列がすでに有効であり、ゼロを下回らない場合です。 この場合、最小プレフィックスはすべてのポイントでゼロであるため、`min_idx`残る`-1`、出力は次のようになります`0`。 アルゴリズムは、回転が必要ないことを正確に識別します。 

もう 1 つのエッジ ケースは、最小プレフィックスが最後の文字にある場合です。 のような文字列で`"((()))"`またはすでにバランスのとれた有効な形式であっても、これは依然として次のような問題につながります。`min_idx = -1`したがって、結果は安定しており、回転を誤って示唆することはありません。 

より微妙なケースは、複数の位置が同じ最小プレフィックス値を共有する場合です。 アルゴリズムは最後の出現を保存しますが、最も深いディップの後にシフトすると非負の再中心ウォークが生成されるため、どの出現でも有効な回転が生成されます。
