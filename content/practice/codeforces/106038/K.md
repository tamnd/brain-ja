 ## 解決策
 ## 問題の理解

 長さ不明のバイナリ文字列を再構築しようとしています$N$裁判官との対話によって。 候補文字列を提出するたびに、審査員はそれを隠しパスワードと比較し、2 つの文字列が最初から一致する長さを返します。 

クリーンな世界では、これは単に最長の共通プレフィックスの長さになります。 問題は、判定が完全に信頼できるわけではないということです。一定の確率で、戻り値が破損する可能性があります。 この破損は、私たちが悪用できる構造化された方法で恣意的に行われるわけではないため、唯一の安定した信号は、反復的な相互作用と集約から得られます。 

私たちのタスクは、限られた試行回数内で、ノイズの多いプレフィックス長クエリのみを使用して、正確な隠蔽されたバイナリ文字列を回復することです。 

主な問題は、単一のクエリを信頼できないことです。 正確な答えが許可されている場合、問題は文字列を貪欲に構築することに帰着します。$O(N)$クエリ。 ここでは、ノイズにより、各クエリを事実ではなく測定値として扱わざるを得なくなります。 

クエリの制約は、すべての文字列に対してブルート フォースを実行したり、すべてを過度に繰り返しリサンプリングしたりすることはできないことを意味します。 あらゆる可能性を試したり、ビットごとに再構築を最初からやり直したりするアプローチは、特に次の場合にすぐに制限を超えてしまいます。$N$大きいです。 

ノイズが一貫して一方向に偏る場合、微妙なエッジ ケースが発生します。 たとえば、2 つの候補プレフィックスが非常に近い真の LCP 値を生成する場合、ノイズのある 1 つの観測によって決定が誤って反転される可能性があります。 このため、基礎となる構造が単純であっても、決定論的なワンショットの貪欲な構築の信頼性が低くなります。 

## アプローチ

 ノイズがなければ、問題は簡単です。 答えを左から右に組み立てることができます。 位置で$i$、プレフィックスを設定して、返された LCP を観察します。 それが増加した場合、ビットを保持します。 それ以外の場合は裏返します。 各クエリは正確なフィードバックを提供し、最終的には$O(N)$クエリ。 

このアイデアをノイズの下で強引に拡張すると、単一のクエリを使用して各ビットを決定することができます。 問題は差し迫ったものです。ノイズにより、報告されるプレフィックス長が短縮または増大する可能性があります。これは、単一の決定が間違っている可能性があり、そのエラーがその後のすべての位置に伝播することを意味します。 最悪の場合、再建全体が崩壊してしまいます。 

重要な観察は、ノイズが多い場合でも、各クエリが役に立たないということです。 これにはまだ偏った信号が含まれています。つまり、正しいプレフィックスは、間違ったプレフィックスよりも体系的に大きな LCP 値を生成する傾向があります。 これにより、戻り値を、真のプレフィックス一致長を中心としたランダム変数として扱うことができます。 これを受け入れると、問題は正確なクエリではなく、統計的な意思決定の問題になります。 

単一の測定値を信頼するのではなく、各候補クエリを数回繰り返し、集計された結果を比較します。 位置ごとに、考えられる両方のビットをテストし、予想されるプレフィックス スコアが高い方を選択します。 正しくないプレフィックスはより早く分解されるため、ノイズの多い測定であっても、平均すると高い確率で順序付け情報が保存されます。

 ## アルゴリズムのチュートリアル

 応答文字列を一度に 1 文字ずつ構築し、隠しパスワードと一致すると思われるプレフィックスを増加させ続けます。 

1. 空の文字列を初期化する$s$。 これが再構築されたパスワードになります。 
2. ポジションごとに$i$から$0$に$N-1$、次の文字が`'0'`または`'1'`。 
3. 候補ビットをテストするには、すでに固定されているプレフィックスから構成される完全なクエリ文字列を形成します。$s$、その後に候補ビット、そして任意のフィラーが続きます（位置の決定にはプレフィックスの正確さのみが重要であるため、ゼロで埋め込むことができます）$i$）。 
4. このクエリを複数回送信して、返された LCP 値を収集します。 単一の結果が破損する可能性があるため、この繰り返しが必要ですが、繰り返されるサンプルは実際のプレフィックス長の周囲に集中します。 
5. 候補者の平均応答を計算します`'0'`そして候補者`'1'`。 正しいビットは、より長いプレフィックスの非表示文字列と一致する可能性が高いため、期待される LCP が高くなります。 
6. より良いビットを追加します$s$、最終的な答えの一部としてそれをロックします。 
7. すべての位置が決定したら、再構成された文字列を出力して終了します。 

これが機能する主な構造的理由は、LCP 関数が正しいプレフィックスに関して単調であるためです。 正しいプレフィックスを拡張すると、常に一致境界が右にシフトしますが、不正なビットは即時ドロップを引き起こします。 ノイズは値を混乱させますが、十分なサンプルが取得されていれば期待通りの順序を変更しません。 

### なぜ効果があるのか

 どの位置でも$i$、プレフィックスを仮定します$s[0..i-1]$はすでに正しいです。 隠し文字列の位置には固定ビットがあります$i$。 正しいビットをテストすると、予想される LCP は次の値を超えて増加します。$i$不一致が遅れるため、間違ったビットをテストする場合よりも確率が高くなります。 個々のクエリにノイズが多い場合でも、平均化によりこの分離が維持されます。 したがって、各決定ステップでは、統計的に優勢な真の文字列の継続が選択され、以前の正しいプレフィックスが破棄されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import random

def ask(s: str) -> int:
    print(s, flush=True)
    return int(input().strip())

def decide(prefix: str, n: int, bit: str, samples: int = 5) -> float:
    # build candidate string and average noisy LCP responses
    # we pad to full length; suffix does not matter for LCP beyond mismatch
    best_score = 0
    total = 0
    for _ in range(samples):
        res = ask(prefix + bit + "0" * (n - len(prefix) - 1))
        total += res
    return total / samples

def main():
    n = int(input().strip())
    s = ""

    for i in range(n):
        score0 = decide(s, n, "0")
        score1 = decide(s, n, "1")

        if score1 > score0:
            s += "1"
        else:
            s += "0"

    # final verification (optional)
    print(s, flush=True)
    verdict = input().strip()
    if verdict == "1":
        return

if __name__ == "__main__":
    main()
```実装の中心的な考え方は、単一の裁判官の反応に決して依存しないということです。 すべてのビットの決定は複数のサンプルによって裏付けられており、生の出力ではなく集計された LCP 値を比較します。 パディングにより、すべてのクエリが有効な長さに保たれるようになります。$N$文字列。 

ここでよくある間違いは、最初の不一致が発生すると、接頭辞の比較には接尾辞が重要ではないことを忘れることです。 これにより、決定信号に影響を与えることなく、安全にゼロをパディングすることができます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N \cdot k)$| それぞれの$N$ポジションが実行する$k$ノイズを減らすためのクエリ |
 | スペース |$O(N)$| 再構築された文字列 | を保存します。 

クエリの数は線形です$N$サンプリングによって決定される定数係数まで。 これは、典型的なインタラクティブな制約内に収まります。$N$までです$10^5$そして$k$少ない (約 5 ～ 20) ため、クエリの総数は管理可能に保たれます。

 ## 特殊なケース

 サイズの最小限の入力$N = 1$は最も単純なストレスケースです。 アルゴリズムは次の間で 1 つの決定を行います。`'0'`そして`'1'`。 ノイズがある場合でも、サンプリングを繰り返すことで、正しいビットが不正確なビットよりも高い期待一致を生成するため、アルゴリズムは正しく収束します。 

次のような完全に均一な文字列`000...0`も重要なケースです。 ここで、両方の候補決定は、最初の不一致点でのみ異なる動作をします。 誤った候補は常にプレフィックスを早く終了させ、ノイズによって時折値が膨らむ場合でも、一貫してより小さい予想される LCP を生成するため、アルゴリズムは引き続き機能します。 

のように高度に交互に配置される文字列`1010...`多くのステップにわたって正しさが伝播されることを強調します。 次の決定が意味を持ち続けるためには、それぞれの正しいプレフィックスを維持する必要があります。 アルゴリズムは過去の決定を決して改訂しないため、正確さは各ステップの統計的安定性に依存し、サンプリングを繰り返すことで維持されます。
