 ## 解決策
 ## 問題の理解

 アイテムにはいくつかの独立したグループがあり、各グループがコンテストを表します。 各競技ごとに$i$, Fmota は当初所有しています$a_i$シャツ。 時間は 0 年から 1 年までの年単位で測定されます。$k$。 毎年、各競技会でちょうど 1 枚追加のシャツが追加されます。$t$、 競争$i$含まれています$a_i + t$シャツ。 

Fmota の着用プロセスは厳密に構造化されています。 彼は競技を混ぜることはしません。 代わりに、決まった順序で競技を 1 つずつ処理します。 各競技会で、彼は次の競技会に移る前に、その競技会のすべてのシャツを自分が選んだ順序で 1 回ずつ着用します。 これは、各競技内でその配置が可能性の階乗数に寄与し、競技全体ではブロックが独立しているため選択肢が増えることを意味します。 

タスクは毎年計算することです$t$0から$k$、異なる完全装着スケジュールがいくつ存在するか、大きな素数を法として (暗黙的に$10^9 + 7$）。 

主要な入力構造は初期のシャツ数のリストであり、出力は各値が均一な増加後の異なる年に対応するシーケンスです。 

制約は明確な形式で明示的に記述されていませんが、大きなメモリ制限と複数年の存在は、コンテストの数と$k$大きくてもよく、最大約$2 \cdot 10^5$。 これにより、階乗を毎年ゼロから再計算したり、年ごとに再計算したりすることが直ちに除外されます。$O(n)$競技ごとに大量の演算を伴う再計算。 

競技ごと、毎年独立して階乗を再計算する単純なアプローチでは、大規模な階乗計算を繰り返すことになります。$k \times n$が遅すぎるでしょう。 

微妙な特殊なケースの 1 つは、成長の法則から生じます。 ソルバーが最終年のみが重要であると誤って仮定した場合、または各年の値を独立して出力する必要があることを忘れた場合、年の単一の積を計算する可能性があります。$k$のみ。 もう 1 つのよくある間違いは、キャッシュせずに階乗を再計算することです。$O(n)$ループ内で動作します。 

## アプローチ

 問題の直接的な解釈は簡単です。 固定年度の場合$t$、 競争$i$貢献する$(a_i + t)!$可能な順列。 競合は独立して処理され、固定された順序で連結されるため、構成の総数は単にこれらの階乗値のすべての競合の積になります。 

それで、それぞれの年ごとに$t$、答えは次のとおりです。$$\prod_{i=1}^{n} (a_i + t)!$$ブルートフォースソリューションでは、すべてのペアの階乗を最初から計算します。$(i, t)$。 毎年、すべての階乗を個別に再計算し、次のコストを計算します。$O(n \cdot (a_i + t))$素朴に行われた場合、または少なくとも$O(n \cdot \max a_i)$年ごとに。 年間を通じて、これは完全に不可能になります。 

重要な観察は、連続する数値の階乗が単純な乗法遷移によって関連付けられていることです。$$(x+1)! = (x+1) \cdot x!$$これは、単一の線形パスですべての年にわたって可能な最大値まで階乗を事前計算できることを意味します。 階乗が事前に計算されると、各年の答えは単なる積になります。$n$事前に計算された値、合計を与える$O(nk)$乗算コスト。 乗算は安価であり、通常、制約により最大数十万回の演算が許可されるため、これは許容できます。 

本当の最適化は、階乗の再計算を回避することではなく、階乗がネストされたループ内で繰り返し計算されるのではなく、グローバルに 1 回計算されるようにすることにあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k \cdot n \cdot V)$|$O(1)$| 遅すぎる |
 | 最適 |$O(V + k \cdot n)$|$O(V)$| 承認済み |

 ここ$V = \max(a_i + k)$。 

## アルゴリズムのチュートリアル

 まず、階乗が必要となる最大値を特定します。これは、最大の初期シャツ数にプラスした値です。$k$。 これにより、前処理の限界が決まります。 

次に階乗モジュロを事前計算します$10^9 + 7$単一の線形反復を使用してその最大値まで。 これにより、あらゆるものへの定時間アクセスが可能になります。$(a_i + t)!$。 

毎年、すべての競技会の対応する階乗値の積を計算します。 

### ステップ

 1.読む$n$そして$k$、配列を読み取ります$a$。 

これにより、1 年間に増加する独立要因寄与の数が決まります。 
2. コンピューティング$MAX = \max(a_i) + k$。 

これは、すべての年にわたって出現する可能性のあるすべての階乗値を制限します。 
3. 階乗配列を事前計算する`fact`0から$MAX$モジュロ$10^9+7$。 

各値は、次を使用して前の値から導出されます。$fact[x] = fact[x-1] \cdot x$。 これにより、繰り返しの再計算が回避されます。 
4. 各年度ごと$t$0から$k$、答えを次のように計算します。$$\prod_{i=1}^{n} fact[a_i + t]$$5. すべての計算値を出力します。 

### なぜ効果があるのか

 正しさは 2 つの独立した構造的事実に基づいています。 まず、各競技内では、すべてのシャツはポジションによってのみ区別されるため、有効な着用順序をカウントすることは、順序を正確にカウントすることになり、これは階乗になります。 第 2 に、競技は固定ブロックで処理されるため、あるブロックでの選択が別のブロックに干渉することがなく、競技全体で合計カウントが倍増します。 year パラメーターはすべての階乗入力を均一にシフトするだけであるため、階乗を一度事前計算すると、すべての年に対して正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    max_val = max(a) + k

    fact = [1] * (max_val + 1)
    for i in range(1, max_val + 1):
        fact[i] = fact[i - 1] * i % MOD

    for t in range(k + 1):
        res = 1
        for x in a:
            res = res * fact[x + t] % MOD
        print(res, end=" ")

if __name__ == "__main__":
    solve()
```階乗前処理は年次計算から分離されているため、各クエリ年はテーブルの直接検索のみを実行します。 内部の乗算ループは年間の主な作業であり、各競技が独自に貢献しているため、これは避けられません。 

よくある落とし穴は、階乗の積み上げ中に法を忘れることです。これにより、最終的な乗算段階のかなり前にオーバーフローが発生します。 もう 1 つは、年次ループ内で階乗を再計算することで、線形の解を値の範囲内で 2 次の解に変換します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k = 0$、初期設定のみが重要であることを意味します。 このアルゴリズムは階乗を計算するため、引き続き機能します。$\max a_i$そして単一の製品を出力します。 

入力の場合:```
2 0
3 3
```アルゴリズムは以下を計算します。$$3! \times 3! = 36$$長年にわたるループは 1 回だけ実行されるため、特別な処理は必要ありません。 

もう 1 つの特殊なケースは、すべてが$a_i$等しいです。 のために：```
3 2
2 2 2
```毎年次のことを単純に評価します。$$((2+t)!)^3$$このアルゴリズムは、同一の階乗検索を 3 回正しく適用し、剰余乗算ではオーバーフローや順序付けの問題が発生することなく正確性が維持されます。
