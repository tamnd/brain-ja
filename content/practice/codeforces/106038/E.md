 ## 解決策
 ## 問題の理解

 コインを一行で表す最大 15 文字の短い文字列が与えられます。 各コインは次のいずれかです`H`(頭) または`T`（尾）。 移動は、コインが存在する任意の位置を選択することで構成されます。`H`、そのコインを投げて、`T`、そしてオプションでコインのサブセットを厳密に左側に反転します。 選択した位置の右側にあるコインは、その移動中に変更されることはありません。 

このプロセスは新しい構成から繰り返されます。 すべてのコインがなくなった場合にのみ、ゲームは終了します。`T`, その場合、有効な手は残っていないからです。 

2 つの結果が考えられます。 状態を循環させることでゲームを永遠に続けるか、一連の合法的な動きが最終的にすべてに到達するかのどちらかです。`T`構成。 ゲームが無限にできるなら、出力しなければなりません`-1`。 それ以外の場合は、初期構成から始まり最後までの可能な限り最長の有効な状態シーケンスを出力する必要があります。`T`、連続する各ペアは 1 つの有効な手によって異なります。 

文字列の長さが最大 ​​15 であるため、状態空間は非常に小さくなります。したがって、可能な構成の総数は最大でも 2^15、つまり約 32000 になります。これは、状態をグラフとして問題をモデル化し、到達可能性とサイクルについて推論できることをすぐに示唆しています。 

微妙な点は、移動ルールがローカルではないことです。 位置の選択はすべてのプレフィックスに任意に影響するため、遷移は非常に非決定的になります。 貪欲に動きを選択する単純なシミュレーションでは、長いシーケンスを簡単に見逃したり、サイクルの検出に失敗したりする可能性があります。 

もう 1 つの注意が必要な状況は、まったく同じ移動シーケンスを再訪する必要はないが、状態を再訪するサイクルがある場合です。 状態の繰り返しは無限の再生可能性を意味するため、状態グラフ内の到達可能なサイクルを検出することが不可欠です。 

## アプローチ

 ブルートフォース手法では、各構成をグラフ内のノードとして扱い、そこから可能なすべての手を生成します。 それぞれについて`H`位置が決まったら、そのコインを投げてから、コインのすべてのサブセットを左に投げることを検討します。 インデックスのコインの場合`i`、 がある`2^i`左反転の可能なサブセットであるため、状態からの出力遷移の合計は、位置全体の 2 のべき乗の合計程度になる可能性があり、最悪の場合は指数関数的になります。 

各状態から、到達可能なすべての状態に対して DFS を試行し、現在の再帰スタックで訪問した状態を追跡してサイクルを検出できます。 現在のパスの状態を再訪すると、ゲームが無限に広がる可能性があることがわかります。 サイクルが見つからない場合は、有向グラフ内の最長パスを効率的に検索することになります。 

重要な観察は、遷移ルール​​は複雑であるにもかかわらず、状態の数が少ないということです。 すべての 2^n 状態にわたる完全な有向グラフを明示的に構築し、それを分析できます。 グラフが構築されると、問題は、初期状態から到達可能なサイクルがあるかどうかを検出することになり、ない場合は、すべてのビットが 0 (すべてゼロ) の最終状態への最長パスを計算することになります。`T`）。 

グラフにはサイクルが含まれる可能性があるため、グラフが DAG である場合、最初から到達可能な状態に制限し、サイクルを除外した後でのみ、最長パスが明確に定義されます。 いずれかのサイクルが到達可能であれば、出力します。`-1`。 それ以外の場合は、メモ化またはトポロジカル順序を使用して状態に対する DP を使用して、最長距離を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フル拡張のブルート フォース DFS | O(2^n * 2^n) 最悪の場合 | O(2^n) | 遅すぎる |
 | 明示的なグラフ + サイクル検出 + DP | O(2^n * n * 2^n) 単純な生成ですが、枝刈りにより n ≤ 15 については管理可能 | O(2^n) | 承認済み |

 実際には、n ≤ 15 であるため、状態ごとにすべての遷移を生成し、標準のグラフ アルゴリズムを実行することができます。 

## アルゴリズムのチュートリアル

 各コインの構成をビットマスクとして扱います。`1`に対応する`H`そして`0`に対応する`T`。 

1. 入力文字列を整数マスクに変換します。 これにより、状態がコンパクトに表現され、ビット演算による遷移の計算が容易になります。 
2. すべての状態について、考えられるすべての遷移を事前計算します。 状態ごとに、すべての位置を反復処理します。`i`そんなことはちょっと`i`は`1`。 そのような選択ごとに、ビットを反転します`i`次に、厳密に以下のビットのサブセットをすべて列挙します。`i`、これらの反転を適用して次の状態を生成します。 これにより、状態グラフの完全な隣接リストが構築されます。 
3. ノードごとに 3 つの状態 (未訪問、訪問中、および完了) で DFS を実行します。 Visiting とマークされたノードに入ると、開始状態から到達可能なサイクルが見つかりました。 その場合、答えは無限であるとすぐに結論付けて出力できます。`-1`。 これが機能するのは、反復可能な状態には任意の長さのループが含まれるためです。 
4. サイクルが検出されない場合は、初期状態から最終状態 (すべて 0) までの最長パスを計算します。 メモ化された DFS を使用します。`dp[state]`は、その状態から始まり終端で終わる有効なシーケンスで状態の最大数を格納します。 
5. 最適な dp 値につながる遷移を常に選択して、パスを再構築します。 初期状態から開始して、すべてがゼロになるまで貪欲に最良の後継者を追います。 
6. シーケンスの長さを出力し、次に各状態を順番に出力し、ビットマスクを次のように変換します。`H`そして`T`。 

なぜ効果があるのか

 状態グラフはすべての正当な手を完全にキャプチャするため、有効なゲームプレイはすべてこのグラフ内のパスに正確に対応します。 サイクル検出により、到達可能な状態に制限されたグラフが非周期である場合にのみ続行することが保証され、最長パスが明確に定義されることが保証されます。 DP は DAG 内の最長パスを計算し、最適なパスのすべてのサフィックス自体が最適である必要があるため、再構成は最適な部分構造に従います。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_mask(s):
    m = 0
    n = len(s)
    for i, c in enumerate(s):
        if c == 'H':
            m |= (1 << i)
    return m

def to_str(mask, n):
    return ''.join('H' if (mask >> i) & 1 else 'T' for i in range(n))

def generate_transitions(n):
    size = 1 << n
    adj = [[] for _ in range(size)]

    for mask in range(size):
        # try choosing any H position
        for i in range(n):
            if not (mask & (1 << i)):
                continue

            base = mask & ~(1 << i)  # flip chosen coin to T

            # enumerate all subsets of left bits [0..i-1]
            left = i
            sub = base
            while True:
                adj[mask].append(sub)
                if left == 0:
                    break
                sub = (sub - 1) & ((1 << left) - 1)
                sub = base ^ sub
    return adj

def solve():
    s = input().strip()
    n = len(s)
    start = to_mask(s)
    target = 0

    adj = generate_transitions(n)

    sys.setrecursionlimit(1000000)

    state = [0] * (1 << n)  # 0 unvisited, 1 visiting, 2 done
    bad_cycle = False

    def dfs_cycle(v):
        nonlocal bad_cycle
        state[v] = 1
        for to in adj[v]:
            if state[to] == 0:
                dfs_cycle(to)
                if bad_cycle:
                    return
            elif state[to] == 1:
                bad_cycle = True
                return
        state[v] = 2

    dfs_cycle(start)

    if bad_cycle:
        print(-1)
        return

    dp = [-1] * (1 << n)

    def dfs_dp(v):
        if v == target:
            dp[v] = 1
            return 1
        if dp[v] != -1:
            return dp[v]
        best = 1
        for to in adj[v]:
            best = max(best, 1 + dfs_dp(to))
        dp[v] = best
        return best

    dfs_dp(start)

    path = []
    cur = start
    while True:
        path.append(cur)
        if cur == target:
            break
        best = -1
        nxt = None
        for to in adj[cur]:
            if dp[to] > best:
                best = dp[to]
                nxt = to
        cur = nxt

    print(len(path))
    for x in path:
        print(to_str(x, n))

def main():
    solve()

if __name__ == "__main__":
    main()
```このソリューションでは、完全な状態グラフを明示的に構築します。 各状態が反復され、考えられる動きごとに、ビット操作を使用してプレフィックスのすべてのサブセットを列挙します。 サイクル検出は、標準の DFS カラーリング スキームを使用して実行されます。 到達可能なサイクルがないことを確認したら、メモ化再帰を使用して最長パスを計算し、常に最良の dp 値を持つ近傍をたどることで最適なシーケンスを再構築します。 

重要な実装の詳細はサブセットの列挙です。 表現`(sub - 1) & ((1 << left) - 1)`ビットマスクのすべてのサブセットを効率的に生成し、XOR を実行します。`base`それらを反転として適用します。 これにより、再帰による明示的な 2^i サブセットの反復が回避されます。

 ## 特殊なケース

 シングル`H`input は、アルゴリズムが最小の非終端状態を正しく処理するかどうかをテストします。 唯一の動きはそれを反転します`T`したがって、シーケンスの長さは正確に 2 である必要があります。状態グラフには正確に 2 つのノードと 1 つのエッジが含まれるため、サイクル検出が誤ってトリガーされてはなりません。 

完全に`T`string は終了状態をテストします。 遷移が存在しないため、DP 基本ケースは長さ 1 のシーケンスを直ちに返す必要があります。この状態から遷移を生成しようとすると、誤った再帰を引き起こすことなく空の隣接リストが生成される必要があります。
