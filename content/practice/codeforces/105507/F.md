 ## 問題の理解

 ボールの三角形の配置が与えられます。1 列には 1 個のボールがあり、2 列には 2 個のボールがあり、以下同様に n 列まで続きます。 ボールには、上から下へ、各行内で左から右へ、行ごとに連続した番号が付けられます。 これは、すべてのボールが概念的な三角形内で固定位置を持っていることを意味しますが、その線形インデックス x によってアドレス指定されます。 

手球がボール x に当たると、そのボールがアクティブになります。 最後の行にない場合は、次の行のすぐ下の 2 つのボールにモーションを分割します。 その後、それらはそれぞれ同じように動作し、その下の 2 つのボールに分割され、最後の行に到達するまで下向きのバイナリ伝播を形成します。 このプロセスは決定的です。アクティブ化された各ボールは、次の行にある 2 つの子を正確にアクティブ化します (存在する場合)。 

このタスクは、n 行の三角形内で、x から開始してアクティブになる個別のボールの数を計算することです。 

制約は非常に大きく、n は最大 10^9、x は最大 10^18 にすることができ、テスト ケースは最大 1000 個あります。 これにより、単一の開始位置でも最悪の場合には O(n^2) 個のノードがアクティブになる可能性があり、これは実行可能な限界をはるかに超えているため、伝播のシミュレーションは直ちに除外されます。 n 自体が 10 億になる可能性があるため、テストごとに O(n) さえも不可能です。 

微妙だが重要なエッジ ケースは、x が最後の行にある場合です。 その場合、伝播はまったく起こらず、答えは正確に 1 になります。もう 1 つのエッジ ケースは、x が三角形の頂点近くにある場合で、伝播は最大に拡大し、到達可能なすべてのレベルに触れます。 

## アプローチ

 直接シミュレーションでは、構造を x をルートとするツリーとして扱い、レベルごとに拡張します。 各ノードは、下の行に最大 2 つの子を生成します。 この問題は決定論的な分岐プロセスを明示的に定義しているため、これは原理的には正しいです。 ただし、アクティブ化されたノードの数は深さとともに指数関数的に増加します。深さ d では、最大 2^d のノードが存在します。 x が上部に近い場合、深さは n となり、このアプローチは時間制限をはるかに超えて爆発的に増加します。 

重要な観察は、実際には個々のボールを追跡する必要がないということです。 活性化領域が各行で水平方向にどれだけ広がるかを理解することだけが必要です。 

個々のノードの観点から考えるのではなく、構造を幾何学的に再解釈します。 各行には、連続した間隔のインデックスが含まれます。 行 r の位置 j にあるボールがアクティブになると、行 r+1 の位置 j と j+1 がアクティブになります。 したがって、各行のアクティブ セットは常に連続したセグメントになります。 これは重要な圧縮です。指数関数的分岐は区間拡張に崩壊します。 

したがって、プロセスは一連の間隔になります。 行 r0 の単一インデックスから開始して、各行のアクティブな位置の左境界と右境界を維持します。 各ステップは、間隔 [L, R] を次の行の [L, R+1] に変換し、行幅でクリップします。 n 行目まで到達したら停止します。 答えは、影響を受けるすべての行の間隔の長さの合計です。 

これにより、問題は、指数関数的に多くのノードを追跡することから、最大 n ステップにわたって線形に変化する間隔境界のみを追跡することに軽減されます。 ただし、n は直接反復するにはまだ大きすぎるため、間隔の増加が単調で行境界に対してすぐに飽和することを観察することで、プロセスをさらに圧縮します。 間隔が行全体をカバーすると、その間隔は下位の行すべてに対していっぱいのままになります。 

これにより、完全に覆われた列の長距離を一定時間内に飛び越えることができます。

 ## アルゴリズムのチュートリアル

1. 線形インデックス x を三角番号付けシステムの行 r と列 c に変換します。 r(r+1)/2 < x となる最大の r を見つけて、行内のオフセットを計算します。 伝播はグローバル インデックスではなく行構造に依存するため、これが必要です。 
2. 行 r のアクティブな間隔を [c, c] として初期化し、単一のヒット位置を表します。 この間隔は、現在の行で現在アクティブなすべてのボールを表します。 
3. アクティブなボールの総数を累積するために変数を維持します。 
4. r から n までの各行について、現在の間隔 [L, R] を処理します。 これらのボールはすべてこの行でアクティブになるため、(R - L + 1) を ans に追加します。 
5. すでに行 n にいる場合は、伝播する次の行がないため停止します。 
6. 次の行の間隔を [L, R+1] として計算します。これは、各位置が 2 つの子に広がり、右に最大 1 つシフトされた連続セグメントにマージされるためです。 
7. この間隔を次の行の有効範囲 (長さ row_index + 1) にクリップします。間隔が無効になるか空になる場合は、停止します。 
8. 任意の時点で間隔が [1, row_length] になった場合、残りの行がすべて完全にカバーされ、予測可能な算術合計に寄与するため、直接最下位にジャンプできます。 

重要な決定点は、アクティブな間隔がいつ行を飽和させるかを認識することです。 行全体がアクティブ化されると、後続の行もすべて完全にアクティブ化されるため、それ以上の構造追跡は必要ありません。 

### なぜ効果があるのか

 不変条件は、行 i の処理後、その行のアクティブ ノードのセットが常に 1 つの連続した間隔を形成し、行 i のすべてのアクティブ ノードがその 2 つの子を行 i+1 (存在する場合) に正確に提供することです。 隣接するノードの子はターゲット インデックスで重複するため、区間のすべての子の和集合は、最大 1 回の境界拡張によってシフトされた連続した区間のままになります。 これにより、状態全体を記述するために 3 つ以上のエンドポイントが必要になることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def row_of(x):
    lo, hi = 1, 2 * 10**9
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * (mid + 1) // 2 >= x:
            hi = mid - 1
        else:
            lo = mid + 1
    return lo

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())

        r = row_of(x)
        prev_total = r * (r - 1) // 2
        c = x - prev_total

        L = R = c
        ans = 0

        cur_row = r
        width = r

        while cur_row <= n:
            ans += (R - L + 1)

            if cur_row == n:
                break

            next_width = width + 1

            L2 = L
            R2 = R + 1

            if L2 < 1:
                L2 = 1
            if R2 > next_width:
                R2 = next_width

            L, R = L2, R2
            cur_row += 1
            width = next_width

            if L == 1 and R == width:
                ans += (n - cur_row + 1) * width
                break

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、線形インデックスを三角座標系に変換します。これは、伝播が開始される場所を理解するために必要です。 二分探索`row_of`O(log n) 時間で正しい行を見つけます。 

次に、2 つの整数 L と R を使用して、行ごとのアクティブなインターバルのみを追跡します。各反復では、現在の行のアクティブなボールをカウントし、各ポジションが下の 2 つのポジションに広がるというルールに従ってインターバルを拡張します。 

飽和チェック`if L == 1 and R == width`これは、アクティブ領域が行全体をカバーするようにすでに拡張されている場合に、残りのすべての行を反復しないようにする最適化です。 この時点で、以下の各行がその全幅に寄与するため、残りの三角和を 1 ステップで加算します。 

## 実用的な例

 n = 4、x が 3 番目のボールである小さな三角形を考えてみましょう。 

まず三角形内の x を見つけます。 2 行目の 2 番目の位置にあります。 

| 行 | 間隔 [L, R] | 幅 | 貢献 |
 | --- | --- | --- | --- |
 | 2 | [2, 2] | 2 | 1 |
 | 3 | [2、3] | 3 | 2 |
 | 4 | [2、4] | 4 | 3 |

 合計は 1 + 2 + 3 = 6 となります。 

このトレースは、単一のアクティベーションが個別のノードに分岐するのではなく、成長する間隔にどのように拡張されるかを示しています。 アクティブ セットが連続したままであるという不変条件が各行に表示されます。 

次に、n = 3 で、最上部、行 1 の位置 1 に x があるとします。 

| 行 | 間隔 [L, R] | 幅 | 貢献 |
 | --- | --- | --- | --- |
 | 1 | [1, 1] | 1 | 1 |
 | 2 | [1、2] | 2 | 2 |
 | 3 | [1、3] | 3 | 3 |

 結果は 6 で、すべてのボールがアクティブになることを意味します。 これは飽和動作を示しており、間隔が最終的に行全体を埋めて、いっぱいのままになります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t log n) | 行の二分探索 + テストごとに最大でも線形伝播ですが、早期の飽和により効果的に制限されます。 
| スペース | お(1) | 少数の変数のみが維持されます。 

アルゴリズムは、間隔が飽和すると各テストですべての行の完全な走査が回避され、二分探索がコストの大半を占めるため、制限内で快適に実行されます。

def run(inp: str) -> str:

    import sys

    def solve():
        input = sys.stdin.readline
        t = int(input())
        out = []
        for _ in range(t):
            n, x = map(int, input().split())

            def row_of(x):
                lo, hi = 1, 2 * 10**9
                while lo <= hi:
                    mid = (lo + hi) // 2
                    if mid * (mid + 1) // 2 >= x:
                        hi = mid - 1

            c = x - prev

 ## 特殊なケース

 x が最後の行にある場合、伝播は決して拡張されません。 たとえば、n = 4 で、x が行 4 のインデックスである場合、間隔は 1 つの行で開始および終了し、拡張は行われません。 アルゴリズムは行ごとに 1 つを即座に蓄積し、最初の反復で停止し、1 を正しく生成します。 

x がピラミッドの最初のボールである場合、間隔は最大限に拡大し、すぐにいっぱいになります。 その場合、いくつかのステップの後、条件 L == 1 および R == width がトリガーされ、残りの行が完全な算術継続として追加されます。 実行では各行を個別に操作することはありませんが、すべてのボールを 1 回だけ計算します。 

x が行の右側の境界に近い場合、最初の拡張ステップで間隔が生成され、一時的に行幅を超える可能性があります。 クリッピングステップにより、間隔が有効なままとなり、三角形の外側での過剰なカウントが防止されます。
