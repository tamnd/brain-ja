 ## アルゴリズムのチュートリアル

 しましょう$a$長さの文字列としての入力数値になります$n$。 

### 1. 次と同じ長さの repdigits を試してください。$a$数値を構築しようとします$c$長さの$n$すべての数字が何らかの値に等しい場合$d$9 から 1 の間。このような最大の値が必要です。$c$それは厳密に以下よりも小さいです$a$。 

繰り返します$d$9 から 1 まで下げて文字列を比較します$d$繰り返された$n$との回$a$。 最初の小さいものがこの長さの最良の候補となります。これは、桁が大きいほど、辞書編集的にも数値的にも大きな数値が生成されるためです。 

このステップが機能するのは、等しい長さの 10 進数の間では、辞書編集上の順序が数値の順序と一致するためです。 

### 2. 最適な短い repdigit を構築する

 長さの再桁も考慮します$n-1$。 可能な限り最善の選択は常に$999\ldots9$というのは、任意の桁を増やしても、同じ長さの範囲内で数値が大きくなるだけだからです。 

すべて 9 より小さい値は厳密には悪いので、この長さに対して他の桁を試す必要はありません。 

### 3. 両方の候補を比較します

 現在、有効な候補者は最大 2 人です$c$。 大きい方を選択します。$c$より小さいことを意味します$b = a - c$。 

どちらの同じ長さの候補も機能しない場合、答えは短い方から得られる必要があります。 

### なぜ効果があるのか

 重要な特性は、repdigital が数直線上で非常にまばらな集合を形成し、その大きさは桁の選択ではなく長さによって支配されるということです。 最大でも長さのある候補者$n-2$せいぜい$9 \cdot (10^{n-2} - 1)/9$より小さい$10^{n-1} - 1$、つまり、常にどのものよりも小さいことを意味します。$n-1$-桁の再桁。 これにより、上位 2 つの長さのみが重要になることが保証されます。 

固定長内では、すべての有効な数値が桁の選択によって単調に順序付けされるため、桁の検索で十分であり、中間構造を考慮する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def repdigit(d, k):
    return str(d) * k

def less(a, b):
    if len(a) != len(b):
        return len(a) < len(b)
    return a < b

def main():
    a = input().strip()
    n = len(a)

    best_c = "0"

    # case 1: same length
    for d in range(9, 0, -1):
        c = str(d) * n
        if c < a:
            best_c = c
            break

    # case 2: length n-1
    if n > 1:
        c2 = "9" * (n - 1)
        if less(best_c, c2):
            best_c = c2

    # compute b = a - best_c (big integer subtraction)
    a_digits = list(map(int, a[::-1]))
    c_digits = list(map(int, best_c[::-1]))

    b = []
    carry = 0
    for i in range(n):
        ai = a_digits[i]
        ci = c_digits[i] if i < len(c_digits) else 0
        val = ai - ci - carry
        if val < 0:
            val += 10
            carry = 1
        else:
            carry = 0
        b.append(str(val))

    while len(b) > 1 and b[-1] == '0':
        b.pop()

    print("".join(b[::-1]))

if __name__ == "__main__":
    main()
```候補の構築は 2 つの厳密に制限された検索に分割されます。 数字 9 から 1 までの最初のループは、実際には定数時間であり、同じ長さの文字列比較のみを実行します。これは線形です。$n$。 2 番目の候補は、9 の文字列として直接構築されます。 

減算は、標準的な桁ごとのアプローチを逆の順序で使用して、最後に 1 回実行されます。 必要な減算は 1 回だけなので、実行時間に影響を与えることはありません。
