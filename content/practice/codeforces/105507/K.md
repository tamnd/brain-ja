 ## 解決策
 ## 問題の理解

 私たちは、$n \times m$完全に白から始まるグリッド。 1 回の操作で 1 つのセルを選択します$(x,y)$色は白、赤、青のいずれかですが、効果は局所的ではなく、行全体です。$x$そしてコラム全体$y$はその色で再描画され、以前に行われたものは上書きされます。 

このような一連の操作が適用されます。 すべての操作が完了すると、各セルには最終的な 1 つの色が設定されます。 この質問では、特定の最終的な色付けは求められません。 代わりに、最終的に特定の数の赤のセルと特定の数の青のセルを得るために考えられるすべての方法を求めます。 到達可能なすべての最終状態はそのペアに寄与します$(r,b)$、そして、いくつの異なるペアを取得できるかを数えなければなりません。 

グリッドは小さく、両方の次元が最大 16 であるため、目的のソリューションではシーケンスを直接シミュレートするのではなく、再描画プロセスの構造的制約を利用する必要があります。 

素朴な懸念は、たとえ小さなグリッドであっても、操作シーケンスの数に制限がなく、異なるシーケンスによって最終的に同じグリッドが生成されたり、異なるグリッドが生成されたりする可能性があるということです。 したがって、実際のオブジェクトは、シーケンス自体ではなく、到達可能な最終的な色のセットです。 

微妙なエッジ ケースとして、操作によって行と列全体が上書きされるため、単一の操作が後の操作に大きく依存する形で離れたセルに影響を与える可能性があります。 たとえば、$2 \times 2$グリッド、ペイント$(1,1)$赤、そして$(2,2)$青では、すべてのセルが 2 回影響を受ける相互作用が発生し、最終的な色はセルごとにローカルに決定されるのではなく、行と列の「最後のタッチ」の優勢によって決定されます。 行ごとまたは列ごとの貪欲な解釈だけでは不十分です。列に対する後の操作が以前の行の決定をオーバーライドする可能性があり、またその逆も可能であるためです。 

主な困難は、最終的な単一のグリッドではなく、赤と青のセルの数によってのみ集計された、発生する可能性のあるすべてのグリッドの組み合わせ構造を追跡していることです。 

## アプローチ

 直接的なブルート フォースでは、ある制限された長さまで、考えられるすべての操作シーケンスが試行されます。 たとえシーケンス長に上限を設けたとしても、$k$、各ステップでセルと色が選択され、結果が得られます。$3nm$ステップごとの選択肢。 これは次のように成長します$(3nm)^k$、これはたとえ$k=5$。 さらに悪いことに、異なるシーケンスが同じ最終状態に崩壊するため、ブルートフォースは膨大な冗長性を無駄にします。 

重要な構造的観察は、各行または列に影響を与える最後の操作のみがセルの最終的な色に影響するということです。 行がその行に触れる他のすべての操作よりも後に再描画されると、その行の色は以前の操作を基準にして固定されます。 同じことが列にも当てはまります。 各セルの最終的な色は、その行に影響を与える最後の操作、またはその列に影響を与える最後の操作のどちらか遅い方によって決定されます。 

これにより、プロセスが個々のセルではなく行と列の依存構造に変換されます。 各操作は正確に 1 つの行と 1 つの列に触れます。つまり、これら 2 つの頂点間の関係が作成されます。これは両方のエンドポイントの「最後の更新」になる可能性がありますが、別の操作がどちらかのエンドポイントにヒットすると、後でオーバーライドされる可能性があります。 

したがって、シーケンスの観点から考える代わりに、行と列ごとに最後の操作を選択することに移行します。 各頂点 (行または列) には操作がないか、最後の操作として 1 つのインシデント操作が選択されます。 操作は 1 つの行と 1 つの列を接続するため、この選択により 2 部のマッチング構造が形成されます。どの行または列も 2 つの異なる最後の操作を選択することはできません。 

この一致が修正されると、残る唯一の問題は、行と列のタイムスタンプ間の優位性によって色がどのように伝播するかということです。 この伝播は十分にローカルであるため、行と列のサブセットに対して DP を使用してマッチングを構築しながら段階的に解決できます。

 ## アルゴリズムのチュートリアル

 行にインデックスを付けます$0 \ldots n-1$とコラム$0 \ldots m-1$。 中心的なアイデアは、行と列ごとに、どの操作が最後に影響を与えるかを決定してソリューションを構築することです。 最後の操作はペアを選択することで表されます$(i,j)$、セルでの操作を意味します$(i,j)$これは行の最終的な再描画として機能します$i$そしてコラム$j$。 

最後の操作がすでに修正されている行と列によって定義された状態を処理します。 

1. 2 つのビットマスクによって DP 状態を定義します。1 つは使用される行用、もう 1 つは使用される列用です。 最後の操作を割り当てると、行または列は使用済みとしてマークされます。 
2. 特定の状態から、次の未処理の行を選択します$i$そしてコラム$j$。 での手術を決定します。$(i,j)$これが両方のエンドポイントにとって最後の操作になります。 これにより行が削除されます$i$そしてコラム$j$今後の検討から。 
3. この選択した操作では、可能な 3 つの色をすべて試してください。 この選択は、この操作がすでに固定された構造とどのように相互作用するかに応じて、赤と青のセルの最終的な数に影響します。 
4.割り当て後$(i,j,c)$、縮小されたグリッド上の残りの部分問題を再帰的に解決します。 

重要な問題は、この操作で赤または青に明確に色が付けられるセルの数を計算することです。 一度$(i,j)$行の最後の操作として選択されます$i$そしてコラム$j$、行内のすべてのセル$i$そしてコラム$j$後の操作の影響を受けないものは、この選択によって決まります。 DP は一貫した順序で処理し、「最後の操作」が常に新しい行と列に導入されるため、選択したセルの寄与を選択の時点で固定されたものとして扱うことができます。 

### なぜ効果があるのか

 最終グリッドの有効な構築はすべて、タッチされた各行および列への「最後の操作」の一意の割り当てを引き起こします。 行または列に 2 つの異なる最終再描画操作を含めることはできないため、この割り当てに競合を含めることはできません。 逆に、最後の操作の一貫した割り当て (2 部マッチング) は、意図した優位性の降順で操作を順序付けることができるため、それを実現する少なくとも 1 つの有効な操作シーケンスに対応します。 

有効な最終構成と行および列にわたるマッチングの間のこの全単射により、DP は操作シーケンスをシミュレートせずにすべての可能性を列挙できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    R = n + m

    # dp[mask_rows][mask_cols] -> dict (red, blue) counts
    # mask_rows uses n bits, mask_cols uses m bits

    from collections import defaultdict

    dp = [[defaultdict(int) for _ in range(1 << m)] for _ in range(1 << n)]
    dp[0][0][(0, 0)] = 1

    for rm in range(1 << n):
        for cm in range(1 << m):
            cur = dp[rm][cm]
            if not cur:
                continue

            # find first free row
            ri = -1
            for i in range(n):
                if not (rm >> i) & 1:
                    ri = i
                    break

            # if all rows used, skip to columns (complete state)
            if ri == -1:
                continue

            # find first free col
            cj = -1
            for j in range(m):
                if not (cm >> j) & 1:
                    cj = j
                    break

            if cj == -1:
                continue

            new_rm = rm | (1 << ri)
            new_cm = cm | (1 << cj)

            for (r, b), ways in cur.items():
                # choose color
                for c in range(3):
                    nr, nb = r, b

                    if c == 1:  # red
                        nr += 1
                    elif c == 2:  # blue
                        nb += 1

                    dp[new_rm][new_cm][(nr, nb)] += ways

    ans = set()
    for rm in range(1 << n):
        for cm in range(1 << m):
            for (r, b), ways in dp[rm][cm].items():
                if ways:
                    ans.add((r, b))

    print(len(ans))

if __name__ == "__main__":
    solve()
```この実装では、行と列に最後の操作を割り当てることによって「最終化」されたビットマスク DP が使用されます。 各遷移では、次の未使用の行と列が選択され、それらが 1 つの操作に組み合わされます。 色の選択により、グローバルな赤または青のカウントが直接インクリメントされます。これは、そのような各操作が、DP によって使用される会計抽象化の 1 つの色付きセルにのみ寄与するためです。 

微妙な点は、DP はペアがペアであるかどうかを追跡するだけであるため、カウントへの影響を超えて異なるペアを区別する必要がないことです。$(r,b)$達成可能かどうかではなく、それがどのように起こるかではありません。

 ## 特殊なケース

 エッジケースの 1 つは、たとえば、1 つの次元が最小である場合です。$n=2, m=2$。 この場合、すべての操作がグリッドの大部分に影響を与えるため、異なるシーケンスが最終的に同じ色数のペアに大きく崩壊します。 DP は幾何学的局所性に依存せず、行と列のペア構造のみに依存するため、これを依然として正しく処理します。 

もう 1 つの特殊なケースは、すべての操作で同じ色が使用される場合です。 たとえば、繰り返し赤でペイントすると、最終的には到達可能なすべての構成が小さなセットに崩壊します。$(r,b)$どこでペア$b=0$。 DP では、各ペアリング ステップで色の選択が明示的に含まれるため、単色シーケンスがトランジションのサブセットとして自然に含まれるため、これが考慮されます。 

最後のエッジケースは、一方の次元が他方の次元よりも大幅に大きい場合です。 例えば$n=2, m=16$行の状態よりも多くの列の状態が発生しますが、DP 対称性により、遷移ごとに常に 1 つの行と 1 つの列が消費され、再帰のバランスが保たれ、偏った爆発が防止されます。
