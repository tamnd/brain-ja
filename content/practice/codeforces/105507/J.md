 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 各操作は、非常に特殊な方法でこの配列を変更します。つまり、2 つの特別な位置を見つけます。1 つは最大値を含み、もう 1 つは最小値を含みます。 最大値はすべての最大値の中で最も左にあるものとして選択され、最小値はすべての最小値の中で最も右にあるものとして選択されます。 これら 2 つの位置が特定されたら、それらの値の平均を計算し、切り捨てて、この値を両方の位置に割り当てます。 

このプロセスを正確に k 回繰り返した後、結果の配列を出力する必要があります。 

この制約により、配列サイズを 200,000 まで、演算数を n までにすることができます。 これは、各スキャンのコストが O(n) であり、最悪の場合は O(nk) になり、O(n^2) に縮退するため、各操作の最大値と最小値を最初から再計算するのは遅すぎることがすぐにわかります。 それは大きすぎます。 

重要な微妙な点は、極値の位置が安定していないことです。 2 つの要素を更新すると、次の最大値または最小値が発生する場所が変わる可能性があるため、ポイント更新でのグローバル クエリの繰り返しをサポートする構造が必要です。 

エッジケースはタイブレークルールから発生します。 最大値は左端の出現である必要があり、最小値は右端の出現である必要があります。 タイブレークを無視した単純なアプローチは失敗します。 

たとえば、[5, 1, 5] を考えてみましょう。 最大値は 5 で、正しい選択はインデックス 0 です。最小値はインデックス 1 の 1 です。1 回の操作の後、両方とも 3 になり、[3, 3, 5] が生成されます。 プログラムが右端の最大値を誤って選択すると、代わりにインデックス 2 が選択され、誤った要素が変更され、将来の状態の誤ったシーケンスが生成されます。 

もう 1 つの微妙なケースは、更新後に最大値と最小値が値または位置で一致する場合です。 アルゴリズムは、変換後に同じインデックスを指すことになる場合でも、正しいタイブレークを使用してそれらを 2 つの独立した選択として扱う必要があります。 

## アプローチ

 直接シミュレーションは簡単です。k 個の操作のそれぞれについて、配列をスキャンして必要な最大インデックスと最小インデックスを見つけ、平均を計算し、両方の位置を更新します。 これは正しいですが、各スキャンのコストは O(n) となり、O(nk) になります。 n が 200,000 までになると、これは不可能になります。 

重要な点は、値が変化しても、操作ごとに 2 つの位置だけが更新されるということです。 配列の残りの部分は変更されません。 これは、グローバル最大値と最小値アンダーポイント更新を効率的に追跡できるデータ構造を維持すれば十分であることを示唆しています。 

セグメント ツリーは自然に適合します。 各ノードは、最小インデックスによるタイブレークで最大値を格納し、最大インデックスによるタイブレークで最小値を格納します。 2 つの位置を更新するたびに、セグメント ツリーを O(log n) で更新し、両方の極値をクエリすると、ルートに格納されている場合は O(1) になります。 

したがって、各操作は O(log n) になり、全体の複雑さは O(k log n) となり、十分に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | O(n) | 遅すぎる |
 | セグメントツリー | O(k log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードが 2 つの情報を保存するセグメント ツリーを維持します。セグメント内の最大値とその左端の出現のインデックス、およびセグメント内の最小値とその右端の出現のインデックスです。

1. 初期配列にセグメント ツリーを構築します。 各リーフはその値とインデックスを保存し、内部ノードはタイブレーク ルールに従って正しい最大値と最小値を選択することで子をマージします。 これにより、ルートから常に正しいグローバル極値を取得できるようになります。 
2. 以下のプロセスを k 回繰り返します。 各反復で、ルート ノードから最大値を読み取ります。 これにより、左端の最大値の値とインデックスの両方が得られます。 
3. 同様に、ルート ノードから最小値を読み取ります。これにより、右端の最小値の値とインデックスが得られます。 
4. これら 2 つの値の平均の下限として新しい値を計算します。 この値は、選択した両方の位置を置き換えます。 
5. 選択した両方のインデックスが同じ場合、更新は 1 回だけ実行されます。 それ以外の場合は、配列内の両方の位置を更新し、これらの変更をセグメント ツリーに伝播します。 
6. k 回の反復後、最終的な配列を出力します。 

ルートを繰り返しクエリできる決定的な理由は、すべての更新が 2 つの位置にのみ影響し、セグメント ツリーは各変更後に正しい集計情報を維持するためです。 

### なぜ効果があるのか

 すべてのステップで、セグメント ツリーは現在の配列を正確に表します。 ルート ノードは常に、正しいタイブレークを使用して真のグローバル最大値を保存し、タイブレーク ルールを使用して真のグローバル最小値を保存します。 各操作で変更されるのは 2 つの位置だけであり、セグメント ツリーの更新ではすべての祖先の正確さが維持されるため、この不変条件はすべての k ステップを通じて有効のままです。 したがって、選択されたすべてのインデックスのペアは、問題定義で必要とされるものとまったく同じであり、シミュレーションが意図したプロセスと一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("mx", "mx_i", "mn", "mn_i")
    def __init__(self, mx=0, mx_i=0, mn=0, mn_i=0):
        self.mx = mx
        self.mx_i = mx_i
        self.mn = mn
        self.mn_i = mn_i

def merge(a, b):
    res = Node()

    if a.mx > b.mx:
        res.mx, res.mx_i = a.mx, a.mx_i
    elif a.mx < b.mx:
        res.mx, res.mx_i = b.mx, b.mx_i
    else:
        res.mx = a.mx
        res.mx_i = min(a.mx_i, b.mx_i)

    if a.mn < b.mn:
        res.mn, res.mn_i = a.mn, a.mn_i
    elif a.mn > b.mn:
        res.mn, res.mn_i = b.mn, b.mn_i
    else:
        res.mn = a.mn
        res.mn_i = max(a.mn_i, b.mn_i)

    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.t = [Node(-10**18, 0, 10**18, 0) for _ in range(2 * self.size)]

        for i in range(self.n):
            v = arr[i]
            self.t[self.size + i] = Node(v, i, v, i)

        for i in range(self.size - 1, 0, -1):
            self.t[i] = merge(self.t[2 * i], self.t[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.t[i] = Node(val, idx, val, idx)
        i //= 2
        while i:
            self.t[i] = merge(self.t[2 * i], self.t[2 * i + 1])
            i //= 2

    def root(self):
        return self.t[1]

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    st = SegTree(a)

    for _ in range(k):
        r = st.root()

        mx_val, mx_i = r.mx, r.mx_i
        mn_val, mn_i = r.mn, r.mn_i

        new_val = (mx_val + mn_val) // 2

        if mx_i == mn_i:
            st.update(mx_i, new_val)
        else:
            st.update(mx_i, new_val)
            st.update(mn_i, new_val)

    print(*[st.t[st.size + i].mx for i in range(n)])

if __name__ == "__main__":
    solve()
```このソリューションは、両方の極値を同時に維持するセグメント ツリーを中心に構造化されています。 各ノードは、必要なタイブレーク インデックスを使用して最大値と最小値を追跡します。 マージ関数は、両方の統計の正確さを独立して強制します。 

更新操作では、リーフからルートまでのパスが再構築され、各変更後の一貫性が確保されます。 k 個の操作のみが実行されるため、更新の総数は O(k log n) によって制限されます。 

細かいことですが重要な点は、最大インデックスと最小インデックスが一致する場合、更新は 1 回だけ実行されるということです。 このチェックがないと、同じ変換を誤って二重適用してしまい、正確さが損なわれてしまいます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最大値と最小値が同じインデックスで発生する場合です。 たとえば、[5] のような配列では、n ≥ 2 であるためこのようなことは起こりませんが、更新後にすべての要素が等しくなる可能性があります。 その場合、両方の極値は同じインデックスを指します。 アルゴリズムはこれを明示的にチェックし、単一の更新を実行して、正確性を維持し、冗長な書き込みを回避します。 

もう 1 つの微妙な状況は、複数の最大値または最小値が存在する場合です。 タイブレーク ルールはすべてのステップで厳密に適用される必要があります。 セグメント ツリーにはインデックス情報が格納されるため、更新後でもクエリの一貫性が保たれます。 たとえば、[1, 5, 5] では、インデックス 2 ではなくインデックス 1 で最大値が選択され、この選択は将来の操作に正しく反映されます。
