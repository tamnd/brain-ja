 ## 解決策
 ## 問題の理解

 この問題では、パネルと呼ばれる独立した数値のグループがいくつか与えられます。 各パネルには、一連の短い正の整数が含まれています。 各パネルから最大 1 つの要素を削除することができ、その後、残った要素の最大公約数を取得します。 その値はパネルの「本質」とみなされます。 

すべてのパネルがそのエッセンスを生成したら、これらすべての値で構成される新しいリストを作成します。 このリストから最小公倍数を計算します。 最終的な LCM をできるだけ小さくすることを目的として、LCM を取得する前にこのリストから 1 つの値をオプションで削除することができます。 

つまり、構造は 2 レベルの最適化になっています。 まず、各パネルは最大 1 つの要素を削除した後、可能な限り最適な GCD を介して単一の数値に圧縮されます。 次に、これらの結果の数値は LCM を介して結合されますが、最大 1 つの削除が許可されます。 

入力サイズは、パネルの数とパネル全体の要素の合計という点では大きくなりますが、パネル内の各値は小さくなります。 これは、パネルごとの線形処理は許容されるが、パネルごとの二次アプローチは許容できないことを強く示唆しています。 

素朴なアプローチでは、各パネル内のすべての削除を試行し、毎回 GCD を再計算してから、LCM を繰り返し再計算しながら最終リスト内のすべての削除を試行します。 各パネル内の GCD 再計算はパネル サイズで 2 次になり、最大 10^5 要素にわたって LCM 再計算を繰り返すとコストも高くなるため、これはすぐに遅くなりすぎます。 

より微妙な問題は、「1 つの要素を削除すると GCD が向上する」という点の正しさです。 たとえば、次のようなパネルでは、`[6, 10, 15]`、完全な GCD は 1 ですが、`10`与える`[6, 15]`GCD 3 を使用します。完全な GCD のみを使用するソリューションでは、この改善が見逃されます。 

第 2 段階でも同様の落とし穴が存在します。LCM リストから大きな数値を 1 つ削除すると、結果が大幅に減少する可能性があります。 例えば、`[8, 9, 10]`LCM 360 はありますが、削除されています`9`LCM 40 が得られ、はるかに小さくなります。 

## アプローチ

 ブルート フォース戦略は各パネルで独立して開始されます。 単一パネルの場合、考えられるすべての要素を削除し、残りの配列の GCD を計算して、最大の結果を取得します。 除去ごとに GCD を最初から計算するには O(A) 時間がかかるため、パネルのコストは O(A²) になります。 すべてのパネルで、要素の合計数が 2×10^5 に達すると、これは実行できなくなります。 

重要な観察は、GCD が接頭辞と接尾辞の分解の下で適切に動作するということです。 プレフィックス GCD とサフィックス GCD を事前計算すると、位置 i の要素を削除した後の GCD は O(1) で計算できます。 これにより、各パネルが線形時間に短縮されます。 

この縮小の後、サイズ N のリスト B が得られます。ここで、各 B[i] はパネル i からの可能な限り最良の GCD です。 

第 2 フェーズでは、すべての B[i] の LCM を最小化し、オプションで 1 つの要素を削除します。 単純なアプローチでは、考えられるすべての除去に対して LCM を再計算し、O(N²) 個の乗算とオーバーフローが発生しやすい中間値を与えます。 

代わりに、配列全体の LCM を 1 回計算してから、各 i について、B[i] を除くすべての要素の LCM を計算します。 これは、プレフィックスとサフィックスの LCM 値を維持することで実現できます。これは GCD トリックと精神的には似ていますが、LCM の使用には注意が必要です。 

これが機能するのは、要素を 1 つだけ削除すると、すべての回答候補が完全な LCM か、単一の位置を除外して形成された N 個の LCM の 1 つになるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パネル削除 + LCM 再計算) | O(∑A² + N²) | お(1) | 遅すぎる |
 | パネルごとの接頭辞/接尾辞 GCD + 結果に対する接頭辞/接尾辞 LCM | O(∑A + N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 各パネルの最適な GCD を計算します。 

パネルごとに、GCD のプレフィックス配列とサフィックス配列を構築します。 これにより、単一の要素を一定時間で除去した後、パネル全体の GCD を計算できます。 

### 2. パネル値を抽出する

 パネル内のインデックス i ごとに、i の削除をシミュレートして計算します。`gcd(prefix[i-1], suffix[i+1])`。 すべての除去の最大値を追跡し、パネル全体の GCD とも比較します。 

### 3. 一連のエッセンスを構築する

 各パネルから最適な値をサイズ N の配列 B に収集します。 

### 4. グローバル LCM 構造を計算する

 以下のプレフィックス配列とサフィックス配列を構築します。`pref[i] = lcm(B[0..i])`

`suf[i] = lcm(B[i..N-1])`これにより、1 つのインデックスを除くすべての要素の LCM の O(1) 計算が可能になります。 

### 5. 最終回答を評価する

 計算:

 1. B のすべての要素の最小公倍数
 2. 各 i について、プレフィックス配列とサフィックス配列を使用した B[i] を除くすべての要素の LCM

 これらの値の最小値を取得します。 

### なぜ効果があるのか

 最初のフェーズは正しいです。パネル内の最適な削除は GCD に局所的にのみ影響し、要素が 1 つ欠落しているセットの GCD はその要素で割り切れる寄与の削除にのみ依存するためです。 プレフィックス/サフィックス GCD は、各要素が共有約数にどのように寄与するかを正確にキャプチャします。 

第 2 フェーズは、LCM が結合性であるため機能します。そのため、1 つを除くすべての要素の LCM は、互いに素なセグメント間で相互作用することなく、接頭辞部分と接尾辞部分にきれいに分解できます。 有効な最終選択はすべて、すべての要素を保持するか 1 つの位置を除外するかのどちらかに正確に対応し、両方のケースが列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def lcm(a, b):
    return a // gcd(a, b) * b

def best_gcd_after_one_removal(arr):
    n = len(arr)
    if n == 1:
        return arr[0]

    pref = [0] * n
    suf = [0] * n

    pref[0] = arr[0]
    for i in range(1, n):
        pref[i] = gcd(pref[i - 1], arr[i])

    suf[n - 1] = arr[n - 1]
    for i in range(n - 2, -1, -1):
        suf[i] = gcd(suf[i + 1], arr[i])

    best = pref[n - 1]

    for i in range(n):
        left = pref[i - 1] if i > 0 else 0
        right = suf[i + 1] if i + 1 < n else 0
        best = max(best, gcd(left, right))

    return best

def solve():
    n = int(input())
    B = []

    for _ in range(n):
        tmp = list(map(int, input().split()))
        a = tmp[0]
        arr = tmp[1:]

        B.append(best_gcd_after_one_removal(arr))

    if n == 1:
        print(B[0])
        return

    pref = [0] * n
    suf = [0] * n

    pref[0] = B[0]
    for i in range(1, n):
        pref[i] = lcm(pref[i - 1], B[i])

    suf[n - 1] = B[n - 1]
    for i in range(n - 2, -1, -1):
        suf[i] = lcm(suf[i + 1], B[i])

    ans = pref[n - 1]

    for i in range(n):
        left = pref[i - 1] if i > 0 else 1
        right = suf[i + 1] if i + 1 < n else 1
        ans = min(ans, lcm(left, right))

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、プレフィックスとサフィックスの GCD 配列を使用して、各パネルを最適な GCD に圧縮します。 次に、これらの圧縮された値に対してプレフィックスとサフィックスの LCM 配列を構築します。 最後のループでは、接頭辞と接尾辞の LCM の乗法的再結合を使用して、すべての値を保持することと、考えられる単一の値をそれぞれ削除することの両方をチェックします。 第 2 段階の「1 つの要素を削除」ルールは複数の値が存在する場合にのみ適用されるため、単一パネルなどのエッジ ケースは個別に処理されます。

 ## 特殊なケース

 単一の要素を含むパネルは、GCD を最大化する意味のある方法で削除することができないため、簡単です。 完全な GCD と「削除」ケースの両方が崩壊するため、アルゴリズムは要素自体を返します。 

みたいなパネル`[6, 10, 15]`これは、完全な GCD が 1 であるものの、`10`収量`[6, 15]`GCD 3 では、中央の要素の寄与がきれいに除外され、両側から再結合されるため、プレフィックスとサフィックスの GCD 配列はこれを正確に捕捉します。 

第 2 段階では、次のような構成になります`B = [1, 5, 12, 1]`は、中間要素を削除すると LCM が大幅に削減されることを示しています。 プレフィックス/サフィックス LCM 再構築により、このような単一の削除はすべて、最初から再計算することなく、正確に 1 回評価されることが保証されます。
