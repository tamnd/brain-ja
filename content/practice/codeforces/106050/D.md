 ## 解決策
 ## 問題の理解

 映画の企画セッションに参加する一組の人々と、選択または選択できない映画のコレクションが与えられます。 各人は映画に関して正確に 2 つの制約を表明しており、その要件は、すべての人にとって、映画の最終選択によって 2 つの制約のうち少なくとも 1 つが満たされなければならないということです。 

制約は 1 つのムービーに関係する単純な構造になっています。 映画は望ましいか、望ましくないかのどちらかだと言えます。 その映画が選択されたセットに含まれている場合、望ましいステートメントは満たされます。 その映画が選択されたセットに含まれていない場合、望ましくないステートメントが満たされます。 各人は、2 つのステートメントのうち少なくとも 1 つが最終選択に当てはまれば満足します。 

課題は、すべての人々を同時に満足させる映画のサブセットを構築するか、そのようなサブセットが存在しないと判断することです。 

入力サイズは最大 10 万人の人物と 10 万本の映画に達します。 このスケールでは、映画のすべてのサブセットを理由づけるアプローチは直ちに削除されます。 映画の組み合わせを探ろうとする方法は、たとえ部分的であっても指数関数的な動作をする危険があり、実行可能ではありません。 各ムービーが局所的な制約に基づいて決定される、または制約が線形または線形に近い時間で効率的に伝播できる定式化が必要です。 

微妙な失敗例は、貪欲なローカルの決定がグローバルに矛盾する場合に発生します。 たとえば、ある人が「映画 1 を含める必要があるか、映画 2 を除外する必要がある」と要求し、別の人が「映画 2 を含める必要がある、または映画 1 を除外する必要がある」と要求した場合、人ごとの単純な貪欲な満足度が変動する可能性があります。 2 人の人物と 2 本の映画のような小さな例では、すでに選択肢全体に一貫性を強制できます。 

入力:```
2 2
S 1 N 2
N 1 S 2
```ここで、ムービーを含めるか除外するかの割り当ては両方の制約を同時に満たす必要がありますが、両方のムービーは逆の方法で結びついています。 各人を独立して満足させる素朴なアプローチは、制約が相互に関連していることを認識しない限り、簡単に矛盾に終わる可能性があります。 

主な困難は、各人が 2 つのブール変数 (映画が含まれるかどうか) に対して論理条件を課しており、そのような条件はすべて一度に満たされなければならないことです。 

## アプローチ

 ブルートフォース解釈では、各ムービーをバイナリ変数として扱い、すべてのムービーを試します。$2^M$サブセットを使用して、すべての人の 2 つの制約が満たされているかどうかを確認します。 各小切手にかかる費用$O(N)$、これは完全に不可能になります。$M$できる$10^5$。 

サブセットを選択するという観点から考えるのをやめ、代わりに各人の要件を、2 つのステートメントによって形成される 4 つの可能性のうち 1 つの構成だけを禁止する制約として解釈すると、この構造は管理可能になります。 それぞれの人は基本的に、「これら 2 つの条件のうち少なくとも 1 つは真でなければならない」と言います。 これは論理的には 2 つのリテラルにわたる句と同等です。 

重要な観察は、映画の各決定が 2 値であり、各制約が 2 つのリテラルの論理和であるということです。 これは古典的な 2 充足可能性構造ですが、この問題には建設的な近道があるため、ここでは完全な SCC 機構は必要ありません。すべての制約には、映画ごとに 1 つの肯定的な条件と 1 つの否定的な条件が含まれており、強制的な決定を伝播することで割り当てを貪欲に方向付けることができます。 

一般的な含意グラフを構築する代わりに、一貫した方法で制約を処理し、値を割り当てることができます。 ムービーがさまざまな制約によって強制的に含められるか除外される場合、不可能であることが検出されます。 それ以外の場合は、現在満たされていない制約に基づいて未決定の映画を繰り返し修正することで、有効な割り当てを構築できます。 

重要な簡略化は、各人が 1 つの条項のみを提供し、条項を満たすということは、少なくとも 1 つのリテラルが true でなければならないことを意味します。 各節をローカル チェックとして扱い、値を遅延的に割り当てることができます。節の両方のオプションが現在 false の場合、それを満たすためにムービーの 1 つを反転する必要があります。 各映画は 1 人当たり最大でも一定数の制約に参加するため、伝播は線形のままです。

 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース |$O(2^M \cdot N)$|$O(1)$| 遅すぎる |
 | 制約の伝播 (2-SAT スタイルの構築) |$O(N + M)$|$O(N + M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各人は 2 つのリテラルからなる節を提供します。 リテラルは、「映画 i が含まれる」または「映画 i が除外される」のいずれかです。 

1. すべてのステートメントをムービーのブール条件に変換します。包含は true に対応し、除外は false に対応します。 これにより、すべての制約が同じ形式に標準化されます。 
2. ムービーの割り当て配列を維持します。最初はすべて割り当てられていません。 これは、各映画が現在選択されているか、選択されていないか、またはまだ決定されていないかを表します。 
3. 現在の割り当てで一部の句が満たされていない間、すべての句を繰り返し処理します。 句がすでに満たされている場合、それ以上の制限は課されないため、その句は無視されます。 
4. 両方のリテラルが現在 false である句に遭遇した場合、そのリテラルの 1 つを true に代入して満足を強制する必要があります。 関連する 2 つのムービーのうち 1 つを選択し、それに応じてその値を設定します。 
5. ムービーを割り当てた後、満足度ステータスが変更されている可能性があるため、このムービーを含むすべての条項を再評価して、その効果を広めます。 以前の仮定によって満たされなくなった条項は、さらなる割り当てをトリガーする必要があります。 
6. どこかの時点でムービーが矛盾した状態 (真と偽の両方) に強制された場合は、終了して出力不可能になります。 
7. すべての伝播が安定した後、残りの未割り当てのムービーに任意の値を割り当てます。これは、それらのムービーが満たされていない条項によって制約されないためです。 

### なぜ効果があるのか

 各節は、最終的な代入に保持する必要があるローカル論理和を強制します。 伝播プロセスは、句が違反された場合にのみ機能します。つまり、その句の両方のリテラルが現在 false であることを意味します。 1 つのリテラルを修正すると、直接的な矛盾が生じない限り、すでに満たされている節を無効にすることなく有効性が回復されます (矛盾はすぐに検出されます)。 すべての代入は現在違反している節によってのみトリガーされるため、満たされた節は再処理されずに破られることはなく、プロセスはすべての節が満たされる固定点に収束します。 矛盾が現れない場合、不動点はグローバルに一貫した割り当てを表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    # assignment: None = unassigned, 1 = selected, 0 = not selected
    val = [None] * (m + 1)

    # clauses: each person contributes two literals
    clauses = []

    for _ in range(n):
        s1, i1, s2, i2 = input().split()
        i1 = int(i1)
        i2 = int(i2)

        lit1 = (i1, s1 == 'S')  # True means must be included
        lit2 = (i2, s2 == 'S')
        clauses.append((lit1, lit2))

    changed = True

    def lit_ok(lit):
        idx, must_be_true = lit
        if val[idx] is None:
            return False
        return val[idx] == must_be_true

    while changed:
        changed = False
        for lit1, lit2 in clauses:
            if lit_ok(lit1) or lit_ok(lit2):
                continue

            # both false -> must fix one
            i1, b1 = lit1
            i2, b2 = lit2

            # try assign first literal
            if val[i1] is None:
                val[i1] = 1 if b1 else 0
                changed = True
            elif val[i2] is None:
                val[i2] = 1 if b2 else 0
                changed = True
            else:
                # both assigned but clause not satisfied
                print("IMPOSSIVEL")
                return

    for i in range(1, m + 1):
        if val[i] is None:
            val[i] = 0

    print(" ".join("S" if val[i] == 1 else "N" for i in range(1, m + 1)))

if __name__ == "__main__":
    solve()
```実装では、各句をリテラルのペアとして保存し、満たされていない句がなくなるまで繰り返しスキャンします。 割り当て配列は、各ムービーが含まれているかどうかを追跡します。 唯一の微妙な部分は、未割り当ての変数を正しく処理することです。句は、現在の割り当てで少なくとも 1 つのリテラルがすでに true である場合にのみ満たされているとみなされ、その場合にのみ、そのリテラルに触れることを避けます。 

最後のスイープでは、残りの未決定の映画をすべて「含まない」に割り当てます。これらの変数は、強制的に強制するアクティブな制約に関与しないため、これは安全です。

 ## 特殊なケース

 重要なエッジケースは、映画でさまざまな人物が相反する役柄で登場する場合です。 例えば：```
2 1
S 1 N 1
N 1 S 1
```最初はすべての変数が割り当てられていないため、両方の句が満たされていません。 アルゴリズムは、最初の違反条項を満たすためにムービー 1 を割り当てます。 この代入の後、2 番目の節は、最初は矛盾しているように見えても、1 つのリテラルが成立するため満たされます。 伝播ステップでは、新しい代入によって条件が破られない限り、条件が満たされた句を再検討することはありません。そのため、プロセスは正しく安定します。 

もう 1 つのケースは、すべての変数が制約を受けない場合です。 その状況では、アルゴリズムは最後のスイープまでそれらを未割り当てのままにし、その後安全にそれらを含めないように設定します。 どの句もそれらに依存しないため、不必要な伝播を引き起こすことなく有効な出力が生成されます。
