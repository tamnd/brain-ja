 ## 解決策
 ## 問題の理解

 初めは空で、時間の経過とともに成長するグラフが与えられています。 各クエリは、2 つの頂点間に赤または青の新しいエッジを 1 つ追加します。 追加するたびに、仮説的な質問が行われます。削除される赤いエッジの数が削除される青いエッジの数と等しくなければならないという追加の制約付きで、すべての頂点間の接続を変更せずに、現在のグラフからエッジをいくつ削除できるかということです。 

接続性は、色を無視して、標準的な無指向性の意味で測定されます。 したがって、削除前に 2 つの頂点が接続されていた場合、削除後も接続されたままでなければなりません。 これにより、残りのエッジには、現在のグラフのすべての接続されたコンポーネントのスパニング フォレストが引き続き含まれるようになります。 

制約は大きく、最大数十万のクエリがあるため、挿入のたびに接続を再計算したり、すべてのサイクルを最初から再計算したりすることは現実的ではありません。 スパニング フォレストを再構築したり、クエリごとに完全な DFS を実行しようとするソリューションは、最悪の場合、実質的に 2 次の動作につながるため、遅すぎます。 

微妙な点は、特定の削除戦略の出力を求められるのではなく、削除可能なエッジの最大数のみを出力するように求められることです。 これは、明示的な構造ではなく構造の観点から推論できることを意味します。 

単純なアプローチでは、各状態を独立して扱い、すべてのブリッジまたはスパニング フォレストを計算してから、「余分な」エッジの数を数えようとします。 難しいのは、色ごとに削除のバランスを取る必要があるという追加の要件です。 この制約により、独立して削除できるエッジが結合されます。 

よくある落とし穴は、この結合を無視して非ツリー エッジの数のみを計算することです。 たとえば、1 つの青いサイクル エッジを除いてすべてのエッジが赤の場合、グラフには多くの冗長なエッジがある可能性がありますが、赤と青の削除の等価性が崩れる場合は、それらをすべて削除することはできません。 

別の失敗例は、グラフがすでに接続されているが、すべての冗長エッジが 1 色である場合に発生します。 たとえば、グラフに 1 つの青いエッジを除いて完全に赤いエッジで構成される 1 つのサイクルがあるとします。 構造的により多くのエッジが冗長である場合でも、最大で 1 つの赤いエッジと 1 つの青いエッジを同量削除できます。 

## アプローチ

 重要な分離は、接続に構造的に必要なエッジとそうでないエッジの間です。 どのようなグラフでも、連結成分を修正すると、正確に$n - c$エッジは各コンポーネント内の接続を維持するために必要です。$c$接続成分の数です。 それ以降はすべてサイクルに属し、削除できる可能性があります。 

したがって、最初の観察は、「構造的に冗長な」エッジの数が$$\text{cycle\_edges} = m - (n - c)$$どこ$m$現在のグラフのエッジの数です。 

色の制約がない場合、接続を切断することなくツリー以外のエッジをすべて削除できるため、答えは単純にこのサイクル数になります。 

色の制約により、全体的なバランス条件が導入されます。 させて$R$そして$B$は、サイクル内にある赤と青のエッジの数になります。 サイクル エッジのセットを削除する場合、削除は次の条件を満たす必要があります。$$\text{deleted red} = \text{deleted blue}$$すべてのサイクルエッジのうち、すべてを削除しようとすると、アンバランスは$|R - B|$。 すべての削除はいずれかの側に寄与するため、サイクル エッジだけを使用してこの不均衡を取り除くことはできません。 

したがって、最善の戦略は、最終的な削除数のバランスを保ちながら、できるだけ多くのサイクル エッジを削除することです。 これは、少なくとも「置き去り」を強いられることを意味します。$|R - B|$さもなければ削除可能なサイクルエッジ。 

これにより、最適なカウントが得られます。$$\text{answer} = \text{cycle\_edges} - |R - B|$$直感的には、1 つの色が余るたびに、サイクル エッジ間で形成できる対称的な欠失ペアの数が減少します。 

ブルート フォース アプローチでは、各クエリの後に接続を明示的にシミュレートし、サイクル構造を再計算し、コストを計算します。$O(q(n + m))$が遅すぎます。 

最適化されたアプローチでは、グローバルな集計、つまり接続されたコンポーネントと、赤と青のサイクル エッジ間の差異のみが維持されます。 エッジがサイクルを作成するかコンポーネントをマージするかどうかだけを知る必要があるため、各挿入は Union-find を使用してほぼ一定時間で処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに再計算 (DFS / スパニング フォレスト) |$O(q(n + m))$|$O(n + m)$| 遅すぎる |
 | DSU + サイクルカウント |$O((n + q)\alpha(n))$|$O(n + q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 接続のために DSU (Disjoint Set Union) を維持しながら、クエリをオンラインで処理します。 

1. 独自のコンポーネント内の各頂点と、赤と青のサイクル エッジのカウンターを使用して DSU を初期化します。 
2. クエリごとにエッジを追加する$(u, v)$指定された色の、$u$そして$v$はすでに同じ DSU コンポーネント内にあります。 
3. 異なるコンポーネントにある場合は、DSU にマージします。 このエッジはスパニング フォレストの一部になり、サイクル エッジではないため、削除可能なエッジには影響しません。 
4. それらがすでに同じコンポーネント内にある場合、このエッジはサイクルを形成します。 色に応じて、赤サイクル カウンタまたは青サイクル カウンタのいずれかをインクリメントします。 
5. エッジを処理した後、次を計算します。 

- 赤と青のサイクル カウンターの合計としての合計サイクル エッジ
 - アンバランスとして$|\text{red\_cycle} - \text{blue\_cycle}|$6. 出力:$$(\text{cycle edges}) - |\text{red cycle} - \text{blue cycle}|$$重要なアイデアは、DSU が接続の変更を分離し、サイクル エッジが独立して蓄積されるということです。 色の分類を超えてサイクルを形成する正確なエッジを明示的に追跡する必要はありません。 

### なぜ効果があるのか

 すべてのグラフは、スパニング フォレストと一連のサイクル エッジに分解できます。 スパン フォレストは選択に応じて一意に決定されますが、常に正確に含まれます。$n - c$エッジ。 このフォレストの外側にあるエッジは、接続に影響を与えることなく削除できます。 

残りの唯一の制限は、削除は色によってバランスをとらなければならないことです。 サイクル エッジのみが削除可能であるため、問題は赤と青のカウントが等しいサイクル エッジの最大マルチセットを選択することになります。 最適解では、可能なすべてのペアが削除され、絶対的な不均衡は避けられないままになります。 DSU では、すべての非サイクル エッジが接続にコミットされ、削除プールに入らないことが保証されるため、この不変条件は維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    n, q = map(int, input().split())
    dsu = DSU(n)

    red_cycle = 0
    blue_cycle = 0

    for _ in range(q):
        t, u, v = map(int, input().split())
        u -= 1
        v -= 1

        merged = dsu.union(u, v)
        if not merged:
            if t == 1:
                red_cycle += 1
            else:
                blue_cycle += 1

        cycle_edges = red_cycle + blue_cycle
        ans = cycle_edges - abs(red_cycle - blue_cycle)
        print(ans)

if __name__ == "__main__":
    solve()
```DSU は、エッジが接続に関して冗長であるかどうかを検出するためにのみ使用されます。 結合が成功した場合、エッジはスパニング フォレストの一部となり、答えに直接寄与することはありません。 

サイクル カウンタは、赤と青の冗長性を分離します。 最後の式は、避けられない不均衡を除去することによって生のサイクル数を修正します。 

実装の微妙な点は、エッジを保存したりグラフを再構築したりする必要がないことです。 すべては、クエリごとの一定時間の分類に帰着します。

 ## 特殊なケース

 すべてのサイクル エッジが単一の色に属している場合、重大なエッジ ケースが発生します。 この状況でも、DSU はすべての冗長エッジを正しく識別しますが、不均衡項はサイクル エッジの数と等しくなります。 等価な赤と青のペアは不可能であるため、公式では削除可能なエッジがゼロになるように答えが強制されます。 

もう 1 つのケースは、サイクルが早い段階で出現するが、後のエッジが以前は別個だったコンポーネントをマージする場合です。 DSU ではコンポーネント内のエッジのみが冗長とみなされ、挿入順序に関係なく正確さが維持されるため、これらの後のマージはサイクル カウンターに影響を与えません。
