 ## 問題の理解

 各テスト ケースには 2 つの文字列が与えられ、もともと文字ブロックから作成された単語と、いくつかのいたずらな変更の後に表示される別の単語を表します。 変更ルールは非常に具体的です。いつでも、誰かが文字列内の位置を選択して、同じ文字の 2 つの同一のコピーを隣り合わせに挿入できます。 このペアは、先頭、末尾、または 2 つの既存の文字の間に挿入できます。 この操作は何度でも繰り返すことができます。 

タスクは、これらの「二重文字の挿入」のみを使用して最初の文字列から 2 番目の文字列を取得できたかどうかを判断することです。 

重要な制約の意味は、テスト ケースの数が最大 50 万と非常に多く、すべての文字列の合計の長さが 100 万に制限されることです。 これにより、結合された入力サイズに対して本質的に線形の解が強制されます。 テスト ケースごとに 2 次的なものはすべて、繰り返しの削除やシミュレーションのような単純なものであっても、すぐに制限を超えてしまいます。 

微妙な点は、挿入は常に同一の文字のペアで行われることです。 つまり、文字が出現する回数のパリティは、これらのペアが元の文字列とどのようにインターリーブされるかによって厳密に制御されます。 ただし、挿入はどこにでも発生する可能性があるため、文字の順序は厳密には保持されません。そのため、通常の意味でのサブシーケンスの問題を扱っているわけではありません。 

単純な推論を打ち破るエッジケースは、元の文字列に繰り返し文字がすでに存在する場合に発生します。 たとえば、オリジナルが次のような場合`ab`そしてターゲットは`aabb`、素朴な考えは、次のように誤って仮定する可能性があります。`aa`そして`bb`ブロック内で明確に適用される個別の挿入操作に対応する必要があります。 ただし、有効な変換では挿入をインターリーブできます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 2 つのポインターを使用して、両方の文字列を左から右にスキャンします。`i`のために`s1`そして`j`のために`s2`。 目標は、すべての文字を一致させることです。`s1`中で順番に`s2`、余分に挿入された文字をスキップする可能性があります。 
2. 位置で`j`で`s2`、 もし`s2[j]`等しい`s1[i]`、両方のポインタを進めます。 これは、元の単語の文字を消費することを表します。 
3. 一致しない場合は、次のように解釈します。`s2[j]`挿入されたブロックの一部として。 この不一致を、次から始まる連続する同一文字にグループ化します。`j`、長さのことを言う`k`。 
4. この実行では、挿入によって完全に説明できるかどうかを確認します。 挿入では常にペアが追加されるため、一致する文字を超える余分な文字は存在しません。`s1`must come in even counts. 私たちは前進します`j`による`k`動かずに`i`、しかし、概念的にはこれらの文字を「消費されたノイズ」として説明します。 
5. いずれかのポインタが最後に到達するまで続行します。 最後に、変換は、次のすべての文字が一致した場合にのみ有効になります。`s1`正確に、および残りの接尾辞`s2`有効なリムーバブル実行のみで構成されます。

### なぜ効果があるのか

 すべての操作で 2 つの同一の文字が隣接して挿入されるため、余分な文字が表示される唯一の方法です。`s2`実行の一部として、余剰の発生をペアにすることができます。 からの文字の相対的な順序`s1`は決して邪魔されないので、サブシーケンスとして現れる必要があります。 貪欲なマッチングにより、必要な文字をスキップすることがなくなります。`s1`、実行ベースのスキップにより、有効な挿入によって生成された可能性のある構造内の文字のみが破棄されます。 これにより、プロセスが成功した場合、以下を構築する一連の挿入が存在することが保証されます。`s2`から`s1`、そしてそれが失敗した場合、そのような構造は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(s1, s2):
    n, m = len(s1), len(s2)
    i = j = 0

    while j < m:
        if i < n and s1[i] == s2[j]:
            i += 1
            j += 1
        else:
            # process a run of identical characters in s2
            k = j
            while k < m and s2[k] == s2[j]:
                k += 1
            # we skip this whole block in s2
            j = k

    return i == n

t = int(input())
out = []
for _ in range(t):
    s1 = input().strip()
    s2 = input().strip()
    out.append("YES" if possible(s1, s2) else "NO")

print("\n".join(out))
```この実装では、厳密なリニア スキャンが維持されます。`s2`。 広がる内側のループ`k`前に進むだけなので、どのキャラクターも最大 1 回訪問されます。 ポインタ`i`確実に一致します`s1`順番に、サブシーケンス構造を強制します。 

よくある落とし穴は、ペアを明示的に削除しようとしたり、削除のスタックを維持しようとしたりすることです。 これは、二次関数の動作や重複する実行の誤った処理につながります。 線形実行拡張では、各ブロックを 1 回だけ処理することで両方の問題を回避します。
