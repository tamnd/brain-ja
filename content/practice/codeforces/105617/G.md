 ## 解決策
 ## 問題の理解

 直線上に座標の昇順に配置された一連の点が与えられます。 各ポイントはガソリンスタンドまたは休憩所です。 最大許容距離も与えられています`d`。 

We need to count ordered triples of points`(i, j, k)`そのような`i < j < k`指定された順序で、外側の 2 つの点はガソリン スタンド、中央の点は休憩エリアで、2 つのガソリン スタンド間の距離は以下を超えません。`d`。 

入力では座標が厳密に増加しているため、インデックスの順序はすでにライン上の左から右の順序と一致しています。 したがって、「i < j < k」は、「i は j の左側、is は k の左側」と同等です。 

したがって、条件は幾何学的に単純です。長さが最大で 2 つのガソリン スタンドを区間の終点として選択します。`d`、厳密にそれらの間に休憩エリアがいくつあるかを数えます。 

制約は次のとおりです`5 × 10^5`これにより、トリプルまたは点のすべてのペアに対する二次列挙が即座に除外されます。 すべてのガソリン スタンドのペアに対する単純な O(n²) スキャンでは、ポイントの半分がガソリン スタンドである最悪のケースではすでに遅すぎます。 

2 つのガソリン スタンドを修正し、その間をスキャンして中間点を数えようとすると、より微妙な問題が発生します。 各スキャンが線形であっても、重複する範囲にわたって繰り返しスキャンすると、密な場合には立体的な動作が発生します。 

一般に単純な推論を破るエッジ ケースには、すべてのポイントがガソリン スタンドである場合、すべてのポイントが休憩エリアである場合、またはガソリン スタンドが密集してほぼすべてのペアが距離制約を満たすような状況が含まれます。 特に、すべてのポイントがガソリン スタンドである場合、距離に関係なく、答えはゼロでなければなりません。 逆に、有効なガスペアの間に多くの休止領域がある場合、そのような休止領域はそれぞれ独立して寄与するため、構造が注意深く編成されていない場合、簡単に二重にカウントされる可能性があります。 

## アプローチ

 ブルートフォース戦略は簡単です。すべてのトリプルを反復処理します。`(i, j, k)`、タイプと座標制約を確認し、有効なものを数えます。 これは定義に直接従っているので正しいですが、最悪の場合には O(n³) 個のトリプルをチェックする必要があります。 ガソリンスタンドに限定しても、高密度構成では O(g² r) に減少しますが、これは依然として限界をはるかに超えています。`n = 5 × 10^5`。 

重要な観察は、端点を固定すると中間点が独立しているということです。 ガソリン スタンドの固定ペアの場合`(i, k)`と`x_k - x_i ≤ d`、それらの間のすべての残りの領域は、そのペアを持つ有効なトリプルを 1 つだけ提供します。 したがって、問題は、有効なガスのペアごとに、その間隔内に休止点がいくつあるかを数えることになります。 

これは、構造をタイプごとに分離し、プレフィックスの合計を使用することを提案しています。 ポイントが座標によって順序付けされると、休止領域の実行カウントを維持し、「2 つのインデックスの間にある休止ポイントの数」をプレフィックス値の差に変換できます。 残りの課題は、距離制約を満たすガソリン スタンドのペアのみを効率的に反復することです。 これは、ガソリン スタンド上の 2 ポインタ ウィンドウによって処理されます。 

ガソリン スタンドを越えて適切なエンドポイントをスイープします。 右端の各エンドポイントについて、左端のガソリン スタンドを依然として距離内に維持します。`d`。 このウィンドウ内のすべてのガソリン スタンドは、現在の右のエンドポイントと有効なペアを形成します。 それらを個別に列挙するのではなく、プレフィックス値の累計を使用してそれらの寄与を集計します。

 | --- | --- | --- | --- |
 | ブルートフォーストリプル | O(n3) | お(1) | 遅すぎる |
 | ガスペア + プレフィックス + 2 つのポインター | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 行の任意のプレフィックスに残りの領域がいくつ存在するかをすばやくクエリできるように、配列を前処理します。 

1. アレイを構築する`pref_rest`、 どこ`pref_rest[i]`ポイント間の休憩エリアの数です`1`を通して`i`。 This allows constant-time counting of rest points in any segment.
 2. Extract the indices of all gas stations into a list`gas`。 メイン ロジックについては、これらの点のみを繰り返します。 
3. ツーポインタウィンドウを使用して、`gas`リスト。 正しいポインタを置いてみましょう`r`ガソリンスタンドの上を左から右に移動します。 
4. 左ポインタを維持する`l`距離制約はウィンドウ内のすべてのガソリン スタンドに適用されます。つまり、`x[gas[r]] - x[gas[l]] ≤ d`。 これに違反した場合は移動します`l`フォワード。 これにより、すべてのガソリンスタンドで`[l, r]`は有効な左エンドポイントです`gas[r]`。 
5. 固定右エンドポイントの処理中`r`、すべての左側のエンドポイントの寄与を合計したい`i`窓の中。 各ペアごとに`(i, r)`、有効な中間点の数は`pref_rest[r_idx - 1] - pref_rest[i_idx]`、 どこ`i_idx`そして`r_idx`は配列内の元の位置です。 
6. 合計を全体に分割します`i`窓の中:

 - 用語`pref_rest[r_idx - 1]`固定の場合は一定です`r`、貢献します`(window_size) * pref_rest[r_idx - 1]`。 
- 用語`-pref_rest[i_idx]`の合計を維持する必要があります`pref_rest[i_idx]`現在ウィンドウ内にあるすべてのガソリンスタンドを対象にします。 
7. 現在の合計を維持する`sum_pref`の`pref_rest[i_idx]`現在のウィンドウ内のガソリン スタンドの場合、ウィンドウがスライドするにつれて更新されます。 
8. それぞれについて`r`、 追加：`window_size * pref_rest[r_idx - 1] - sum_pref`答えに。 

### なぜ効果があるのか

 正確さは 2 つの結合された不変条件に依存します。 まず、スライディング ウィンドウは、距離制約の下で現在の正しいエンドポイントと合法的にペアリングできるガソリン スタンドのセットを常に正確に表します。 第 2 に、そのようなペアごとに、有効な中間点の数はプレフィックス数のみに依存し、左側の端点にわたって線形に分解されます。 

有効な各トリプルは、適切なガソリン スタンドの選択によって一意に表されるため、`k`、ガソリンスタンドを出ました`i`、およびそれらの間に休憩所があり、各ペアの貢献度は、次の場合に 1 回だけカウントされるためです。`k`処理されるため、過大カウントまたは過少カウントは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
x = []
t = []

for _ in range(n):
    xi, ti = map(int, input().split())
    x.append(xi)
    t.append(ti)

pref_rest = [0] * (n + 1)
for i in range(n):
    pref_rest[i + 1] = pref_rest[i] + (1 if t[i] == 0 else 0)

gas = [i for i in range(n) if t[i] == 1]

ans = 0
l = 0
sum_pref = 0

for r in range(len(gas)):
    ri = gas[r]

    while l < r and x[ri] - x[gas[l]] > d:
        sum_pref -= pref_rest[gas[l] + 1]
        l += 1

    # add current right endpoint contribution
    window_size = r - l
    if window_size > 0:
        ans += window_size * pref_rest[ri] - sum_pref

    sum_pref += pref_rest[ri + 1]

print(ans)
```コードの中心構造は、ガソリン スタンドのスライディング ウィンドウに正確に従っています。 プレフィックス配列は 1 回のパスで構築されます。 2 ポインタ ループにより、各ガソリン スタンドがウィンドウに出入りするのは最大 1 回だけになります。 

微妙な実装の詳細は、プレフィックス値が次のように取得されることです。`pref_rest[i+1]`ガスインデックス用`i`、 なぜなら`pref_rest`は、元の配列インデックスを 1 だけシフトして定義されます。 ここで 0 ベースのインデックスと 1 ベースのインデックスを混在させると、off-by-one エラーの最も一般的な原因になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, d = map(int, input().split())
    x = []
    t = []
    for _ in range(n):
        xi, ti = map(int, input().split())
        x.append(xi)
        t.append(ti)

    pref_rest = [0] * (n + 1)
    for i in range(n):
        pref_rest[i + 1] = pref_rest[i] + (1 if t[i] == 0 else 0)

    gas = [i for i in range(n) if t[i] == 1]

    ans = 0
    l = 0
    sum_pref = 0

    for r in range(len(gas)):
        ri = gas[r]

        while l < r and x[ri] - x[gas[l]] > d:
            sum_pref -= pref_rest[gas[l] + 1]
            l += 1

        if r - l > 0:
            ans += (r - l) * pref_rest[ri] - sum_pref

        sum_pref += pref_rest[ri + 1]

    return str(ans)

 ## 特殊なケース

 すべてのポイントがガソリン スタンドの場合でも、プレフィックス構造は正しく構築されますが、ガソリン リストは完全なインデックス セットになります。 スライディング ウィンドウには多くのペアが含まれる可能性がありますが、すべての寄与はゼロと評価されます。`pref_rest`is always zero at gas positions. このアルゴリズムでは、特別な処理を行わなくても、自然にゼロが累積されます。 

すべてのポイントが休憩エリアの場合、ガスリストは空になります。 ガソリン スタンドを経由するループは決して実行されないため、寄付は追加されず、答えはゼロのままです。 これにより、空の構造物に対して防御する必要がなくなります。 

ガソリン スタンドが座標空間内で非常に近い場合、ウィンドウは多くの左側の端点を含むように拡張されます。 各左エンドポイントは維持されたプレフィックス合計を通じて独立して寄与し、右エンドポイント上の厳密な単一パスにより二重にカウントされるペアはないため、アルゴリズムは引き続き正しく動作します。
