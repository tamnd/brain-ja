 ## 解決策
 ## 問題の理解

 ツリーベースの暗号化スキームが与えられます。公開キーは、ツリー内の頂点の数とツリー内の長さ 2 のパスの数という 2 つの数値で構成されます。 長さ 2 のパスは、u が v に接続され、v が w に接続され、u と w が異なる、順序付けられた頂点 (u、v、w) のトリプルです。 簡単に言うと、すべての頂点は、その次数に応じて、そのようないくつかのパスの「中心」として寄与します。 

タスクは逆構築です。 指定されたツリーからそのようなパスの数を計算する代わりに、頂点の数とこれらの長さ 2 のパスの必要な数だけが与えられるため、この仕様に一致するツリーが存在するかどうかを判断する必要があります。 存在する場合は、有効なツリーを 1 つ出力する必要もあります。 それ以外の場合は不可能であると報告します。 

この制約では、頂点の数は最大 1000、必要なパスの数は最大 10^9 に設定されます。 テストごとに 10^6 の演算を処理できるため、テスト ケースごとの 3 次または 2 次の構築は原則として許容されますが、すべてのツリーを列挙したり、任意のグラフに対して構造検索を試みたりするアプローチは直ちに実行不可能になります。 本当の制約は n ではなく、可能なツリーの組み合わせ爆発であり、問​​題を直接的な構造的特徴付けに還元する必要があります。 

n が小さい場合、微妙なエッジケースが現れます。 n が 1 の場合、エッジは存在しないため、長さ 2 のパスは存在しません。 n が 2 の場合、エッジは 1 つありますが、長さ 2 のパスはまだありません。 これらの場合、正のターゲット p は不可能です。 必要な p が非常に大きい場合、別の特殊なケースが発生します。 p は最大 10^9 まで可能ですが、サイズ n のツリー内の長さ 2 のパスの最大可能数は次数分布によって制限され、星型ツリーではすでに最大数に達しています。 この最大値を超える値は、構築を試みても直ちに不可能になります。 

## アプローチ

 強引なアイデアは、n 個の頂点上にすべてのツリーを生成し、それぞれの長さ 2 のパスの数を計算することです。 たとえ賢く、ラベルのないツリーのみを生成しようとしても、ツリー形状の数は n とともに指数関数的に増加し、各候補は依然として次数を計算し、組み合わせを合計する必要があります。 ラベル付きツリーの数は n^(n-2) であるため、このアプローチは n が 15 程度の場合でも完全に実行不可能になります。 

重要な観察は、長さ 2 のパスの数が頂点の次数のみに依存し、隣接を超えた詳細な構造には依存しないということです。 すべての頂点 v は正確に deg(v) に寄与します。隣接する頂点の各ペアが v を通過する長さ 2 の一意のパスを定義するため、そのようなパスを 2 つ選択します。したがって、合計値は次のようになります。$$p = \sum_{v=1}^{n} \binom{deg(v)}{2}.$$ここで、問題は純粋にツリーの次数シーケンスの構築問題になります。 合計が 2(n−1) (ツリー プロパティ) になり、上記の 2 次式に代入すると正確に p が得られる次数が必要です。 

この再定式化により、必要な構造、つまり凸和を制御するために頂点間で次数を分配する構造が明らかになります。 関数 binom(x,2) は x 内で二次関数的に増加します。これは、より少ない頂点への集中度が p を増加させるのに対し、拡散度は均一に減少することを意味します。 この単調な構造により、貪欲な構築が可能になります。スター (可能な最大の p) から開始し、ターゲットに到達するか、到達不可能であると判断されるまで、徐々にエッジを再配分して p を減らします。 

n 個の頂点を持つスター ツリーには次数 n−1 の中心が 1 つあるため、p_max = binom(n−1,2) となります。 パス状のツリーは式を最小化し、可能な限り最小の p を生成します。 エッジの中間再分布ごとに p が予測可能な離散ステップで調整されるため、p の変化を追跡しながら、次数を高次のノードから低次のノードに反復的に移動できます。

 ## アルゴリズムのチュートリアル

 星から開始して次数を調整することにより、有効なツリーを構築します。 

1. 頂点 1 をルートとするスターを初期化します。他のすべての頂点を 1 に直接接続します。これにより、他のすべての頂点に対して度 deg(1)=n−1 および deg(i)=1 が与えられます。 初期値 p を binom(n−1,2) として計算します。 
2. p がターゲットと等しい場合、完了です。 スターはすでに有効な解決策です。 
3. p がターゲットより小さい場合、スターがすでに式を最大化しているため、要件を満たす木は存在しないため、「いいえ」を出力します。 
4. p がターゲットより大きい場合、1 つのリーフを中心から別の頂点に繰り返し「シフト」します。 具体的には、次数が少なくとも 2 の頂点 (最初は中心) を選択し、それに直接接続されていない新しい近傍をアタッチします。これにより、高次数のノードの寄与が効果的に減少し、低次数のノードの寄与が増加します。 
5. このような各操作により、影響を受ける頂点の binom(deg,2) の変化に等しい制御された量だけ合計値 p が減少します。 このデルタを明示的に計算し、ツリーの有効性に違反することなくターゲットに近づける場合は変更を適用します。 
6. p がターゲットに一致するか、可能なすべての再配布が完了するまで、再配布を続けます。 

### なぜ効果があるのか

 値 p は、次数の凸関数の合計です。 どのツリーも固定次数合計 2(n−1) を持っているため、この問題は頂点全体に固定量の「次数質量」を分配することに相当します。 binom(x,2) は x 内で凸であるため、均一性からの偏差があると合計が増加します。 星印は最も偏った分布を表し、したがって最大値を表します。 すべての再分配操作は、次数の 1 単位を高次のノードから低次のノードに転送することに相当し、予測可能な方法で凸和を厳密に減少させます。 ツリーのすべての有効な次数シーケンスはこのような転送を介して接続されるため、このプロセスは中間合計をスキップすることなく、任意の達成可能な値に到達できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def comb(x):
    return x * (x - 1) // 2

def solve():
    n, p = map(int, input().split())

    if n <= 2:
        print("Yes" if p == 0 else "No")
        return

    # start with star
    deg = [0] * (n + 1)
    deg[1] = n - 1
    for i in range(2, n + 1):
        deg[i] = 1

    current = comb(n - 1)

    if current < p:
        print("No")
        return

    edges = [[1, i] for i in range(2, n + 1)]

    # we try to reduce current down to p
    # we repeatedly move a leaf from center to another node
    for i in range(2, n + 1):
        if current == p:
            break
        if deg[1] <= 1:
            break

        # try reattaching i from 1 to make structure less star-like
        # remove edge (1, i), add (i, j) for some j != 1
        for j in range(2, n + 1):
            if i == j:
                continue
            # simulate move
            old = comb(deg[1]) + comb(deg[i]) + comb(deg[j])
            deg[1] -= 1
            deg[i] = 1
            deg[j] += 1
            new = comb(deg[1]) + comb(deg[i]) + comb(deg[j])

            if current - (old - new) >= p:
                current -= (old - new)
                edges.remove([1, i])
                edges.append([i, j])
                break
            else:
                # revert
                deg[1] += 1
                deg[i] = 1
                deg[j] -= 1

    if current != p:
        print("No")
        return

    print("Yes")
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```構築は、既知の最大ベースラインを与えるため、スターを明示的に構築することから始まります。 次数配列は寄与を計算するために必要な唯一の状態として使用され、隣接関係を超えたグラフ構造を検査する必要性を回避します。 

内側のループは、1 つの接続を中心から離れたところに再配布しようとします。 重要な実装の詳細は、全体の合計を最初から再計算しないことです。 代わりに、局所的な次数の変化を使用してデルタを追跡します。 これにより、O(n^2) ループ内での O(n) 回の再計算が回避され、n が 1000 までの場合に十分な効率が保たれます。 

度数を更新するときは注意が必要です。目標に向かって進まない場合は、一時的な変更はすべて元に戻さなければなりません。 これを忘れると、ツリーに対応しなくなる無効な次数シーケンスが発生します。 

## 実用的な例

 n = 7、p = 11 とします。最初の星の度数は [6,1,1,1,1,1,1] で、p = binom(6,2)=15 となります。 

| ステップ | センター学位 | p | アクション |
 | --- | --- | --- | --- |
 | 0 | 6 | 15 | スタートスター |
 | 1 | 5 | 10 | リーフ アタッチメントを 1 つ移動する |

 中心次数を一度下げた後、注意しないと 11 をわずかに下回ってオーバーシュートしてしまうため、寄与の一部のみを調整する別の再配分を選択します。 これは、ローカルの貪欲な動きを盲目的に適用するのではなく段階的にテストする必要がある理由を示しています。 

ここで、より小さいケース n = 5、p = 3 を考えてみましょう。星型は p = 6 を与えます。3 ずつ減らす必要があります。2 つの葉を中心から遠ざけ、それらを連鎖させると、寄与が段階的に減少し、パスのような構造など、次数がよりバランスが取れた構成に到達し、正確に p = 3 が得られます。 

これらのトレースは、各操作が次数集中の制御された変化に対応し、アルゴリズムが基本的に次数分布の空間をナビゲートすることを示しています。

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは p = 0 の場合にのみ成功を即座に返します。エッジがないため、長さ 2 のパスは存在せず、ゼロ以外のターゲットは構築が開始される前に拒否されます。 

n = 2 の場合、最初のスターは単一のエッジに縮退します。 両方の頂点の次数が 1 であるため、二項寄与の合計はゼロになります。 次数 2 以上の頂点がないため、アルゴリズムは再分布の試行を正しく回避し、p > 0 は拒否されます。 

binom(n−1,2) に近い非常に大きな p の場合、最初の星はすでに要件を満たしているか、最小限の調整で済みます。 現在とターゲットの差が小さいため、アルゴリズムはすぐに終了し、収束するまでに数度の移行のみが必要になります。
