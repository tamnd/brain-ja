 ## 解決策
 ## 問題の理解

 この問題では、任意のステージをクリアする可能性が 50% のプレイヤーがゲーム全体で正確に予想される試行回数を獲得できるように、一連のゲーム ステージとチェックポイントを設計するように求められます。 すべてのステージにはチェックポイントがある場合とない場合があり、最初のステージには常にチェックポイントがあります。 プレイヤーがステージに失敗すると、最後にアクティブ化されたチェックポイントに戻されます。 目標は、予想される合計試行回数が指定された整数と一致するように、一連のステージとチェックポイントを選択することです。$k$、2000 ステージ以下を使用します。 

制約は異常です。 各ステージの予想試行回数は成功確率と幾何学的になります。$p = 1/2$つまり、後のチェックポイントのない各ステージでは、期待される貢献度が 2 倍になります。 最初のステージには常にチェックポイントがあり、予想される試行回数が少なくとも 2 であることが保証されます。$k$まで高くすることができます$10^{18}$したがって、すべてのステージの試行を明示的にシミュレートすることはできません。 代わりに、数学的な構築が必要です。 

エッジケースはどこにあるのか$k = 1$または小さな値。 たとえば、次の場合$k = 1$の場合、成功確率 1/2 のステージの予想試行回数は少なくとも 2 回であるため、有効な順序が存在しないため、これは不可能です。 もう一つの微妙なケースは次のような場合です。$k$とても大きいです、近くにあります$10^{18}$これには、2000 ステージ未満に抑えながらターゲットの期待値に到達するために、ステージの長いブロックを含むシーケンスを考慮する必要があります。 

## アプローチ

 素朴なアプローチは、チェックポイントのすべてのシーケンスを試行し、構成ごとに予想される試行回数を計算することです。 チェックポイントで終了するステージ セグメントの予想試行数は再帰的に計算できます。チェックポイントが存在する場合、セグメントの予想試行数は 2 倍になります。 たとえ長さのあるすべてのバイナリ シーケンスを考慮したとしても$n$、シーケンスの数は指数関数的に増加します ($2^n$）、これは明らかに不可能です$n = 2000$。 

重要な洞察は、予想される試行は 2 のべき乗に従うということです。 チェックポイントの後に始まりチェックポイントで終わるステージのセグメントが寄与します。$2^L$期待されるステージごとの試行数、ここで$L$最後のチェックポイント後のステージ数です。 したがって、次のように構築することが考えられます。$k$2 の累乗の合計として。 例えば、$k = 12$に分解できます$8 + 4$、予想される試行 8 と 4 を生成する長さのセグメントに対応します。これにより、問題は 2 倍の予想される試行の合計が以下になる一連のセグメント長を構築することになります。$k$、合計ステージが 2000 を超えないようにします。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 建設的 (2 の累乗) | O(log k) | お(2000) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. チェックポイントのある最初のステージから始めて、チェックポイントの配置を保存するリストを初期化します。 これは、常にアクティブな最初のチェックポイントに対応します。 
2.対象物を分解する$k$バイナリに変換します。 各ビットは、予想される試行が 2 のべき乗に対応するセグメントが必要かどうかを表します。 たとえば、ビット位置 3 は試行が予想されるセグメントに対応します。$2^3 = 8$。 
3. 2 の最大累乗から最小の累乗まで繰り返します。 設定されているビットごとに、チェックポイントで終わる一連のステージを追加して、予想される寄与の合計が対応する 2 のべき乗と一致するようにします。 セグメントを構築するには、次のチェックポイントを配置する前に、中間チェックポイントを含まない十分なステージを挿入します。 チェックポイントまでの各ステージで予期される試行が 2 倍になるため、セグメント長はビット位置に 1 を加えたものになります。 
4. すべてのビットを処理した後、合計ステージ数をカウントします。 2000 を超える場合、答えは -1 になります。 それ以外の場合は、ステージ数とチェックポイントを表すバイナリ リストを出力します。 
5. 設定を出力します。 各ステージは 0 (チェックポイントなし) または 1 (チェックポイント) で表され、最初のステージは常に 1 になります。 

機能する理由: チェックポイント間の各セグメントは、合計が 2 の累乗に等しい等比級数に寄与します。 のバイナリ表現をマッピングすることにより、$k$これらのセグメントに対して、予想される試行の合計は正確に等しくなります$k$。 この構造により、次の条件を満たす限り、合計ステージ数が制限内に収まることが保証されます。$k$は 2000 ステージとしては大きすぎず、アルゴリズムは必要な寄与に一致するチェックポイントを体系的に配置します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        stages = []
        # Build the stages backwards from binary representation
        powers = []
        remaining = k
        for i in range(60, -1, -1):
            if remaining >= (1 << i):
                remaining -= (1 << i)
                powers.append(i)
        if remaining != 0 or len(powers) > 2000:
            print(-1)
            continue
        n = 0
        checkpoints = []
        for p in powers:
            # Each segment of length p+1: first p stages no checkpoint, last stage has checkpoint
            for _ in range(p):
                checkpoints.append(0)
                n += 1
            checkpoints.append(1)
            n += 1
        if n > 2000:
            print(-1)
        else:
            print(n)
            print(" ".join(map(str, checkpoints)))

solve()
```このソリューションは複数のテスト ケースを読み取り、それぞれを処理します。$k$これを 2 の累乗に分解し、チェックポイントで終わるステージのセグメントを構築します。 セグメントは、チェックポイントを表すリストに追加されます。 合計ステージが 2000 を超えているかどうかを確認し、それに応じて出力を出力します。 バイナリ分解により、期待される試行回数が次と等しくなることが保証されます。$k$、ゼロの後に 1 を追加すると、正しい間隔でチェックポイントが配置されます。

| ステージ | チェックポイント |

のために$k = 12$、バイナリ$1100_2$、累乗 3 と 2 があります。長さ 3 (試行回数 8 が予想される) と長さ 2 のセグメント (試行回数 4 が予想される) を作成します。 チェックポイント リストは次のようになります。 

| ステージ | チェックポイント |
 | --- | --- |

 予想される試行の合計は 12 で、要件を満たしています。

 ## 特殊なケース

 のために$k = 1$の場合、アルゴリズムは、チェックポイントのある最初のステージであっても、少なくとも 2 回の予想試行に寄与すると計算します。 構築は失敗し、-1 が出力されますが、これは正しいです。 のために$k = 2$の場合、アルゴリズムはチェックポイントを持つ 1 つのステージを作成し、予想される試行回数をちょうど 2 回生成します。 非常に大きい場合$k$、分解により、2 つの一致のべき乗の合計が保証されます。$k$セグメント数は最大 60 であるため、2000 ステージを超えずに有効なステージ シーケンスを構築します。$k \le 10^{18}$。
