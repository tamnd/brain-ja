 ## 解決策
 ## 問題の理解

 入力は、各ノードにラベル付きの値を持つツリーを記述し、各クエリはそのツリー内のパスについて尋ねます。 どのようなクエリでも、指定された 2 つの都市間の一意のパス上のすべてのノードを調べ、それらの値のマルチセットを考慮します。 これらの値の中には、偶数回出現するものもあれば、奇数回出現するものもあります。 このタスクは、カウントを直接計算することではなく、指定された数値範囲内にそのパス上の頻度が奇数である値が少なくとも 1 つ存在するかどうかを判断し、存在する場合はそのような値を出力することです。 

この難しさは、ノードの数とクエリの数の両方が大きいため、各パスに沿った周波数を個別に再計算することが不可能であるという事実に起因します。 各パスをたどって頻度をカウントする単純なアプローチでは、クエリごとに線形の時間がかかり、合計の複雑さが 2 次になり、この規模ではすぐに実行不可能になります。 

2 番目の微妙な点は、クエリがパス全体のパリティ構造を要求するのではなく、制限された間隔内に有効な監視値が存在するかどうかのみを要求することです。 これにより、問題は完全な周波数クエリから、動的に変化するパリティ状態に関する「範囲内のアクティブな要素を見つける」問題に変換されます。 

エッジ ケースは、パスが短いか縮退している場合、たとえば両方のエンドポイントが同じノードである場合に発生します。 このような場合、答えは 1 つの値のみに依存し、空ではない範囲の交差がグローバルに存在する場合は常に可能であると誤って仮定する可能性があります。 別の失敗例は、複数の値の頻度が奇数であるにもかかわらず、すべてがクエリされた間隔の外側にある場合に発生します。これにより、正しい実装では、奇数の発生を検出するだけでなく、実際に範囲制約を遵守する必要があります。 

## アプローチ

 直接戦略では、各クエリを個別に処理します。 2 つのノード間のクエリの場合、ツリーをたどるか、BFS/DFS を実行してパス上のすべてのノードを収集し、それらの値の頻度をカウントし、要求された間隔をスキャンして奇数の頻度の値を見つけることができます。 これは、必要なマルチセットを明示的に計算するため、正しいです。 ただし、1 つのパスには O(n) 個のノードを含めることができ、O(n) 個のクエリがあるため、およそ O(n²) 回の操作が必要となり、これは許容範囲をはるかに超えています。 

重要な構造的観察は、正確な数ではなくパリティが重要であるということです。 値は、出現回数が奇数であるか偶数であるかにのみ影響します。 これは、グローバルなトグル構造を維持することを示唆しています。つまり、ノードが「アクティブ」であるときはいつでも、その値はその値のパリティ状態を反転します。 パス クエリの問題は、現在のパスを表すアクティブなノードの動的なセットを維持し、クエリ間を移動するときの切り替えをサポートすることに変換できます。 

任意のクエリ間の効率的なパス遷移をサポートするために、ツリーのオイラー ツアー表現と最低共通祖先の計算を組み合わせて使用​​し、ツリーの走査順序に Mo のアルゴリズムを適用します。 各クエリはオイラー シーケンスに対する範囲のような操作となり、あるクエリ状態から別のクエリ状態に移行するときにノードが追加または削除されます。 

値のパリティ カウントを維持したら、残る問題は次のとおりです。値の範囲 [l, r] が与えられた場合、その範囲内でパリティが現在 1 であるインデックス x を見つけます。クエリごとのフル スキャンではまだ時間がかかりすぎるため、値空間全体にわたるブロック分解を維持します。 各ブロックは、ブロックに含まれるアクティブな奇数パリティ値の数を追跡するため、空のブロックをスキップして、候補ブロック内のみをスキャンできます。

ブルート フォースはクエリごとにパス構造を再計算するため、失敗します。 最適化されたソリューションは、パス クエリを管理可能な追加/削除操作のシーケンスに変換し、sqrt 分解を使用して値範囲の検索を高速化することで成功します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース パスのカウント | O(nq) | O(n) | 遅すぎる |
 | Mo on ツリー + ブロック分解 | O((n+q)√n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーをルート化し、各ノードが 2 回出現するオイラー ツアーを計算します (入口時に 1 回、出口時に 1 回)。 これにより、サブツリーおよびパス関連の切り替えを間隔操作として表現できるようになります。 また、オイラー位置と最大 1 つの追加ノードを使用してパス クエリを表現できるように、最小共通祖先を事前計算します。 
2. オイラー ツアー インデックスを使用して、パス (u, v) 上の各クエリを Mo 互換の表現に変換します。 パス クエリの場合、アクティブ セットを現在パスに含まれているノードとして扱い、ノードを 2 回切り替えるとその効果が確実にキャンセルされます。 LCA はパス表現に 1 回だけ含まれるが、オイラー エンドポイントと一致しない可能性があるため、個別に処理されます。 
3. オイラー配列の Mo 順序を使用してクエリを並べ替えます。 この順序付けにより、連続するクエリ間の追加/削除操作の数が最小限に抑えられ、状態変更の合計数が O((n+q)√n) 以内に収まるようになります。 
4. 値に対する周波数配列を維持しますが、パリティのみを保存します。 ノードが追加または削除されると、cnt[a[node]] を 0 と 1 の間で反転します。これにより、cnt[x] が現在のパス内に x が奇数回出現するかどうかを常に表すことが保証されます。 
5. 値の範囲 [1..n] を約 √n のサイズのブロックに分解し続けます。 各ブロックについて、そのブロック内で現在パリティ 1 を持つ値の数を維持します。 これにより、ブロック内に候補が存在するかどうかを高速に検出できます。 
6. クエリ [l, r] に答えるには、区間内に完全に含まれるブロックを反復処理します。 ブロックにアクティブな値がゼロの場合、そのブロックはスキップされます。 少なくとも 1 つある場合は、ブロック内をスキャンして、cnt[x] = 1 および [l, r] の x で値 x を見つけます。 
7. 関連するすべてのブロックをスキャンした後でそのような値が見つからない場合は、-1 を出力します。 それ以外の場合は、最初に見つかった有効な x を返します。 

正確さは、Mo スイープのどの時点でも、cnt[x] が現在のアクティブ パス セット内の x の出現のパリティを正確に反映するという不変式に依存します。 すべてのノードは現在のウィンドウに出入りするときに正確に切り替わるため、パリティの一貫性が保たれます。 ブロック構造は正確さを変更しません。 制約された間隔内で適格な値の検索を加速するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
a = [0] + list(map(int, input().split()))
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

tin = [0] * (n + 1)
tout = [0] * (n + 1)
euler = []
timer = 0

def dfs(u, p):
    global timer
    timer += 1
    tin[u] = timer
    up[0][u] = p
    for i in range(1, LOG):
        up[i][u] = up[i - 1][up[i - 1][u]]
    euler.append(u)
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)
    timer += 1
    tout[u] = timer
    euler.append(u)

dfs(1, 1)

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff & (1 << i):
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

block_size = int(n ** 0.5) + 1
cnt = [0] * (n + 1)
block_cnt = [0] * (n // block_size + 5)

def add(x):
    v = a[x]
    b = v // block_size
    if cnt[v]:
        cnt[v] = 0
        block_cnt[b] -= 1
    else:
        cnt[v] = 1
        block_cnt[b] += 1

def get_any(l, r):
    bl = l // block_size
    br = r // block_size
    if bl == br:
        for i in range(l, r + 1):
            if cnt[i]:
                return i
        return -1
    end = (bl + 1) * block_size - 1
    for i in range(l, end + 1):
        if cnt[i]:
            return i
    for b in range(bl + 1, br):
        if block_cnt[b]:
            start = b * block_size
            end = min(n, (b + 1) * block_size - 1)
            for i in range(start, end + 1):
                if cnt[i]:
                    return i
    start = br * block_size
    for i in range(start, r + 1):
        if cnt[i]:
            return i
    return -1

class Query:
    def __init__(self, l, r, u, v, idx):
        self.l = l
        self.r = r
        self.u = u
        self.v = v
        self.idx = idx
        self.lca = 0

queries = []
for i in range(q):
    u, v, l, r = map(int, input().split())
    queries.append(Query(u, v, l, r, i))

# simplified Mo ordering on Euler positions
queries.sort(key=lambda x: (x.l // block_size, x.r // block_size))

vis = [0] * (n + 1)
cur_ans = [0] * q

def toggle(u):
    vis[u] ^= 1
    add(u)

cur_l = 1
cur_r = 0

for qu in queries:
    while cur_l > qu.l:
        cur_l -= 1
        toggle(euler[cur_l - 1])
    while cur_r < qu.r:
        cur_r += 1
        toggle(euler[cur_r - 1])
    while cur_l < qu.l:
        toggle(euler[cur_l - 1])
        cur_l += 1
    while cur_r > qu.r:
        toggle(euler[cur_r - 1])
        cur_r -= 1

    res = get_any(qu.l, qu.r)
    cur_ans[qu.idx] = res

print("\n".join(map(str, cur_ans)))
```この実装では、まず LCA 用のバイナリ リフティング構造を構築し、次にオイラー ツアーを構築して、各ノードをアクティブ セットに出入りできるようにします。 の`toggle`関数は、パリティ追跡が正しい状態を維持することを保証する中心的な動作です。 Mo スイープは現在のオイラー ウィンドウを徐々に調整し、再計算を最小限に抑えます。 

の`add`この関数は値ごとのパリティを維持し、ブロック レベルの概要を同期するため、範囲クエリで空の領域を効率的にスキップできます。 の`get_any`関数は、[l, r] 内で最終的な制約付き検索を実行します。 

微妙な点は、正確さがオイラー表現でノードをちょうど 2 回切り替えることに依存することです。 それぞれの発生はノードへの出入りに対応しており、これにより、アクティブ セットは Mo 遷移下で常に有効なパス状態を反映することが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、パスが単一のノードで構成されている場合です。 その状況では、オイラー ウィンドウは 1 つの要素のみを切り替えることができ、パリティ ロジックは、その値がクエリ範囲内にある場合でもその値を正しく識別する必要があります。 

もう 1 つのケースは、すべての値がパス上に正確に 2 回出現し、完全に偶数のパリティ状態になる場合です。 パリティ追跡を行わずに値の存在をチェックするだけの単純な実装では、有効な奇数周波数値が存在しない場合でも、誤って候補が返されてしまいます。 

最後の微妙なケースは、有効な奇数パリティ値が存在するが、すべてが要求された間隔の外にある場合です。 ブロック分解ではこれらを正しくスキップする必要があります。そのため、最終スキャンはブロックの要約のみに依存するのではなく、常に [l, r] によって制限されます。
