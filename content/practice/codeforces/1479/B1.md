 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、各要素を黒または白でペイントできます。 ペイント後、配列を 2 つのサブ配列に分割します。1 つはすべて白の要素を含み、もう 1 つはすべて黒の要素を含みます。 各サブ配列内では、連続する同一の番号が 1 つのセグメントとみなされます。 私たちの目標は、両方のサブ配列にわたるセグメントの合計数を最大化することです。 

入力は単純で、配列の長さです。$n$（まで$10^5$) と配列自体。要素は次のように区切られます。$1$そして$n$。 出力は単一の整数、つまり達成可能なセグメントの最大合計数です。 

この制約は、解が線形または線形に近いものでなければならないことを意味します。$n$。 考えられるすべてのペイント割り当てを調査するアルゴリズム。$2^n$、全く実現不可能です。 二次関数にも近づきます$n$おそらくタイムアウトになるでしょう$n = 10^5$。 

微妙なエッジ ケースには、すべての要素が同一である配列が含まれます。最適な解決策には、単一の繰り返しの数値を両方の色に分離することが含まれる場合や、交互のパターンを持つ配列が含まれます。これにより、色を交互にすることでセグメントを最大化できます。 たとえば、配列の場合、$[1,1,2,2,1,1]$1 つの数値をすべて同じ色でペイントする単純なアプローチでは、インターリーブ割り当てよりも少ないセグメントが生成されます。 

## アプローチ

 ブルートフォースアプローチは、すべてを試すことです$2^n$配列を描画し、セグメントの総数をカウントする方法。 これは正しいですが、まったく実用的ではありません。$n$到達できる$10^5$。 すべての可能性を保存したり、インデックスのサブセットを反復処理したりしても、メモリまたは時間の制限を超えてしまいます。 

最適なソリューションを実現するための重要な洞察は、各サブ配列内のセグメントの数は、連続する数値がどこで変化するか、および 2 つの色間で同じ数値をどのように分割するかによってのみ依存することを認識することです。 連続する同一の番号は、各サブ配列に最大 1 つのセグメントを与えることができ、異なる番号の実行ごとに、交互に割り当ててセグメントを増やす機会が与えられます。 

この観察により、問題を配列の個別の数値に対する動的プログラミングに帰着させることができます。 個別の値ごとに、前の出現を黒または白でペイントした場合の最大セグメントを追跡します。 遷移は、現在のオカレンスが前のセグメントを継続するか、どちらかのサブ配列で新しいセグメントを開始するかによって異なります。 このアプローチは、配列の長さと個別の数値の数において線形です。

 ## アルゴリズムのチュートリアル

 1. 配列を連続する同一の番号のランに圧縮します。 各実行は、その値と長さによって表されます。 これにより、実行内の内部繰り返しが 1 つのセグメントに集約されるため、セグメントの計算が簡素化されます。 
2. 各値を 2 つのカウンターにマッピングする辞書を維持します。`max_white`そして`max_black`。 これらは、最後の出現が白または黒に割り当てられている場合に、その値で終わるセグメントの最大合計を追跡します。 
3. 実行を順番に繰り返します。 一連の値ごとに`v`、 アップデート`max_white[v]`最大として`(previous max_black[v] + 1)`そして`(global max segments so far if last of other value was white)`。 同様にアップデート`max_black[v]`対称的に。 これは、同じ色のセグメントを継続するか、色を切り替えることでより多くのセグメントが得られるかをキャプチャします。 
4. これまでに確認された最良の合計セグメントを知るために、すべての値にわたるグローバル最大値を維持します。 
5. すべての実行を処理した後、グローバル最大値が答えとなります。 

なぜ機能するのか: アルゴリズムは次の不変条件を保持します。`max_white[v]`そして`max_black[v]`value で終わるシーケンスの最適な合計セグメントを常に反映します。`v`白か黒で。 各実行は 1 回だけ処理され、遷移ではすべての有効な以前のシーケンスが考慮されます。 組み合わせが見逃されることはなく、セグメントを二重にカウントすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    # compress consecutive duplicates
    runs = [a[0]]
    for i in range(1, n):
        if a[i] != a[i-1]:
            runs.append(a[i])
    
    max_white = dict()
    max_black = dict()
    global_max = 0
    
    for val in runs:
        mw = max_black.get(val, 0) + 1
        mb = max_white.get(val, 0) + 1
        
        max_white[val] = max(max_white.get(val, 0), mw)
        max_black[val] = max(max_black.get(val, 0), mb)
        
        global_max = max(global_max, max_white[val], max_black[val])
    
    print(global_max)

if __name__ == "__main__":
    main()
```圧縮ステップにより、連続する値の間の変更のみを処理できるようになり、これが新しいセグメントを開始できる唯一のポイントになります。`max_white`そして`max_black`目に見えない値の場合は 0 に初期化されます。 で更新しています`max(...)`以前に計算された最適値が決して減少しないようにします。 の`global_max`最後にすべての値の最大値を取得します。

 ## 特殊なケース

 単一要素配列の場合`[42]`、アルゴリズムは次のように圧縮します。`[42]`、セット`max_white[42]=1`、`max_black[42]=1`、そして戻ります`1`。 これは期待と一致します。 

のために`[5,5,5,5,5]`、圧縮すると次のように減少します。`[5]`、最適にペイントされた場合は 2 つのセグメント (1 つは白、もう 1 つは黒) が可能になります。 アルゴリズムは計算します`max_white[5]=2`、`max_black[5]=2`、降伏`2`希望どおりに。 

交互配列の場合、アルゴリズムは更新をインターリーブします。`max_white`そして`max_black`各ステップで最大セグメントを正確に取得し、グローバル最大値がすべての実行にわたって正しく累積されるようにします。
