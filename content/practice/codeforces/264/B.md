 ## 解決策
 ## 問題の理解

 厳密に増加する正の整数のリストが与えられます。 このリストから、やはり厳密に増加している部分列を選択したいと思いますが、隣接性に関する追加の制約があります。つまり、選択された 2 つの連続した数値が部分列内で隣り合って現れる場合は常に、少なくとも 1 つの共通の素因数を共有する必要があります。 

タスクは、そのようなサブシーケンスの可能な最大長を見つけることです。 

入力はすでにソートされているため、並べ替えについて心配する必要はなく、要素をスキップすることだけを考慮する必要があります。 唯一の本当の困難は、gcd が 1 より大きいことに基づいて、どの要素をどの要素に続けることができるかを決定することです。 

n が 100000 まで、値が 100000 までという制約は、すべてのペアをチェックしたり、すべての遷移の gcd を計算したりするソリューションは遅すぎることを意味します。 すべてのペアに対する単純な動的プログラミングには O(n^2) の遷移が必要ですが、これは最悪の場合でも約 10^10 の演算に相当し、合格することはできません。 

数値が複数の素因数を共有する場合、より微妙な問題が発生します。 12 のような数値は、2 または 3 を介して独立してチェーンを接続できます。数値ごとに 1 つの「以前の最良値」のみを追跡する間違ったソリューションでは、有効な遷移が失われます。 

別の失敗例は、複数の要素が小さな素因数を共有しているものの、インデックスが大きく離れている場合に発生します。 たとえば、3 の倍数とインターリーブされた 2 の倍数の多くでは、グローバル ベストだけでなく、素数ごとに複数の競合する状態を繰り越す必要があります。 

## アプローチ

 強引なアイデアは、これを有向非巡回グラフの最長パスとして扱うことです。各インデックス i は、i < j および gcd(a[i], a[j]) > 1 の場合に j に遷移できます。dp[j] を、すべての有効な i に対する最良の dp[i] + 1 として計算します。 これは定義と直接一致しており、正しいですが、すべてのペアをチェックして毎回 gcd を計算すると、二次時間になります。 

重要な観察は、gcd(a[i], a[j]) > 1 は、それらが少なくとも 1 つの素因数を共有することを意味するということです。 ペアごとの gcd チェックについて考える代わりに、素因数の観点から考えることができます。つまり、すべての数値が複数の「素数チャネル」に属します。 x から y へのシーケンス ステップは、両方が p で割り切れるような素数 p が存在する場合に有効です。 

これにより、問題は、素数 p ごとに、p で割り切れる数で終わる最適な部分列を維持することに変換されます。 数値 a[i] を処理するときは、それを因数分解し、そのすべての素数を調べます。 a[i] で終わる最良のシーケンスは、1 にその素数に関連付けられたすべての dp 状態の最大値を加えたものです。 dp[i] を計算した後、これらの素数状態をすべて更新します。 

これが機能するのは、すべての有効な遷移が少なくとも 1 つの共有プライムを通過する必要があるためです。そのため、プライムごとのベストを集計することで接続を見逃すことはありません。

 ## アルゴリズムのチュートリアル

 辞書または配列 best[p] を維持します。best[p] には、素数 p で割り切れる処理済みの数値の最大 dp 値が格納されます。 

また、a[i] で終わる最適なサブシーケンス長である dp[i] も計算します。 

### ステップ

 1. max(a[i]) までのすべての数値の最小素因数を事前計算します。 これにより、各要素の素早い因数分解が可能になります。 これは素数を繰り返し再計算することを避けるために必要です。 
2. 100000 までのすべての素数 p に対して配列 best[p] = 0 を初期化します。これにより、p で割り切れる数値で終わる最良の部分列が追跡されます。 
3. サブシーケンスは順序を尊重する必要があるため、配列を左から右に繰り返します。 
4. 現在の数値 x = a[i] について、それを別個の素数 p1、p2、...、pk に因数分解します。 このステップでは、この番号が接続できるすべての「チャネル」を特定します。 
5. dp[i] = 1 + max(best[p1], best[p2], ..., best[pk]) を計算します。 x に有用な接続がない場合、dp[i] = 1。 
6. すべての best[pk] = max(best[pk], dp[i]) を更新して、将来の数値がこの数値から拡張できるようにします。 

### なぜ効果があるのか

処理の任意の時点で、best[p] は、すでに処理された要素のうち、p で割り切れる数値で終わる最長の有効なシーケンスを表します。 新しい数値を処理するとき、有効な先行演算子はその数値と少なくとも 1 つの素因数を共有する必要があるため、これらの best[p] 状態のいずれかで出現する必要があります。 すべての素数の最大値を取得することで、考えられるすべての有効な遷移を確実に考慮することができ、一方、最適値を更新することで、将来の要素に対して最適な部分構造を確実に保存することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 100000

# smallest prime factor sieve
spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    primes = []
    while x > 1:
        p = spf[x]
        primes.append(p)
        while x % p == 0:
            x //= p
    return primes

n = int(input())
a = list(map(int, input().split()))

best = [0] * (MAXV + 1)
ans = 0

for x in a:
    primes = factorize(x)
    cur = 1
    for p in primes:
        cur = max(cur, best[p] + 1)
    for p in primes:
        best[p] = max(best[p], cur)
    ans = max(ans, cur)

print(ans)
```ふるいは最小の素因数を構築するので、各数値はその値に対して対数時間で因数分解できます。 処理中に、各要素は個別の素数に分解されます。 すべての素数ベースの状態をクエリすることで、その数値で終わる最適なチェーンを計算し、dp を計算した後にそれらの状態を更新します。 

微妙な詳細は、因数分解中の素数の重複排除です。 重複を削除しないと、12 分の 2 のような素因数が繰り返されると、遷移が人為的に膨らみます。 SPF ベースの圧縮により、各素数が数値ごとに 1 回考慮されることが保証されます。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての数値自体が素数である場合です。 例えば`2 3 5 7 11`。 各数値は他の数値と共有する素因数を持たないため、正解は常に 1 になります。各 best[p] は 0 から始まり、数値全体で素数が再利用されないため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、12 = 2 × 2 × 3 のような単一の数値内で素数が繰り返される場合です。重複が削除されない場合、アルゴリズムは同じ素数を通る遷移を誤って二重にカウントします。 SPF ベースの因数分解により、各素数が数値ごとに 1 回使用されることが保証されるため、dp は正確なままになります。 

最後のエッジケースは、次のような要素が密に重なり合うことです。`6 10 15`。 ここでは、複数の素数が異なる方向に接続されています。 素数ごとのベスト配列は、dp の計算後に各数値がすべての素数を同時に更新し、時期尚早な上書きを防ぐため、これらのパスを正しくマージします。
