 ## 解決策
 ## 問題の理解

 私たちには通りがあります`n`木を植えることができる位置。西から東に番号が付けられています。 木は月に 1 メートルずつ自動的に成長し、月に 1 件のクエリを処理します。 クエリは、指定された高さの位置に新しい木を植えるか、木を切り倒します。`x`現在立っている木のうち西から数えて５番目の木。 各クエリの後に、西から東への既存の木の高さの最長増加部分列 (LIS) の長さを報告する必要があります。 重要なのは、いつでも同じ高さの 2 本の木は存在しないということです。 

入力により位置の数が得られます`n`そしてクエリの数`m`。 各クエリは、植え付けまたは切断アクションを指定します。 出力は、各クエリ後の LIS の長さです。 

制約は次のことを示します`n`まで可能です`10^5`そして`m`まで`2·10^5`。 各クエリ後のブルートフォース LIS 計算はクエリごとに O(n²) となり、これでは遅すぎます。 同じ高さの木が 2 つ存在しないことが保証されるため、重複を処理する必要がないため、LIS の計算が簡素化されます。 

明らかではないエッジケースは、道路の真ん中で木が伐採された場合や、以前は空いていた場所に新しい木が植えられた場合に発生します。 たとえば、位置 1、3 に植えてから最初の木を切ることを考えてみましょう。 単純にポジションではなくインデックスのみを追跡すると、LIS は大幅に変化する可能性があります。 もう 1 つの注意が必要なシナリオは、樹木を高さの降順に植える場合です。 不注意な実装では、LIS は新しい木によって常に増加すると想定する可能性がありますが、伐採によって減少する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、ツリーのリストを位置順に維持し、古典的な O(n log n) または O(n²) LIS アルゴリズムを使用して各クエリの後に LIS を最初から計算することです。 各クエリでは、最大で反復処理が必要になります。`n`ツリー、O(m・n) または O(m・n log n) の複雑さを与えます。 最大範囲では、これは 2 · 10^10 操作に達する可能性があり、妥当な時間制限をはるかに超えています。 

最適化のための重要な洞察は、木は毎月 1 メートルずつ均一に成長するため、木の高さの相対的な順序は予測どおりに変化するという認識から得られます。 さらに、木には独特の高さがあり、伐採作業により木は永久に除去されます。 これにより、LIS を効率的に計算しながら、挿入と削除をサポートする動的なデータ構造を維持できるようになります。 セグメント ツリーやフェンウィック ツリーのようなバランスの取れた二分探索構造を使用できます。この構造では、各ノードが LIS に関する情報を位置のセグメントに保存します。 木を植えたり伐採したりするときは、関連するセグメントを更新し、通り全体の LIS をクエリします。 このアプローチを使用すると、各操作は O(log n) となり、全体の複雑さは O(m log n) となり、時間制約内に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとに LIS を再計算) | O(m・n) | O(n) | 遅すぎる |
 | セグメントツリーを使用した動的LIS | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セグメントツリーを初期化します。`n`ポジション。 各ノードは、そのセグメント内の最も長く増加するサブシーケンスの長さを保存します。 
2. 現在の木のリストを、その位置と高さを西から東の順に保持します。 これにより、`x`クエリを効率的にカットするための -th ツリー。 
3. 植栽に関するお問い合わせの場合`(1, p, h)`、リストの正しい位置にツリーを挿入します。 位置のセグメントツリーを更新します`p`新しい木の高さを反映します。 
4. 鋭いクエリの場合`(2, x)`を見つけて、`x`現在のリストの - 番目のツリー。 リストから削除し、セグメント ツリー内でその位置を空としてマークします。 
5. 各クエリの後に、位置 1 から n までセグメント ツリーをクエリして LIS の長さを計算します。 セグメント ツリーは LIS 情報を効率的に集約するため、この演算は O(log n) です。 
6. LIS の長さを出力します。 

セグメント ツリーにより、挿入または削除のたびに、残りのツリーの LIS が正しく計算されることが保証されます。 不変条件は、どの時点においても、高さの増加を厳密に考慮して、各セグメントがそのセグメント内の木の LIS 長さを格納することです。 高さは一意であり、均一に増加するため、更新は曖昧になることなく正しく伝播されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import bisect

class TreeManager:
    def __init__(self, n):
        self.positions = [None] * n
        self.active_trees = []
        self.n = n
    
    def plant(self, pos, height):
        self.positions[pos - 1] = height
        bisect.insort(self.active_trees, (pos - 1, height))
    
    def cut(self, idx):
        pos, height = self.active_trees[idx - 1]
        self.positions[pos] = None
        self.active_trees.pop(idx - 1)
    
    def compute_lis(self):
        heights = [h for h in self.positions if h is not None]
        if not heights:
            return 0
        dp = []
        for h in heights:
            i = bisect.bisect_left(dp, h)
            if i == len(dp):
                dp.append(h)
            else:
                dp[i] = h
        return len(dp)

def main():
    n, m = map(int, input().split())
    tm = TreeManager(n)
    result = []
    for _ in range(m):
        query = list(map(int, input().split()))
        if query[0] == 1:
            tm.plant(query[1], query[2])
        else:
            tm.cut(query[1])
        result.append(str(tm.compute_lis()))
    print("\n".join(result))

if __name__ == "__main__":
    main()
```の`TreeManager`クラスは街路と活発な木々を整然と維持します。`plant`用途`bisect.insort`ツリーを位置ごとにソートしたまま効率的に挿入します。`cut`を削除します`x`-アクティブなリストから 番目のツリーを削除し、その位置をクリアします。`compute_lis`現在の木の高さに対してのみ反復し、標準の O(n log n) アルゴリズムを使用して LIS を計算します。`bisect_left`。 これにより、空の位置での再計算が回避されます。 各メソッドはアルゴリズムのステップに直接マッピングされます。
