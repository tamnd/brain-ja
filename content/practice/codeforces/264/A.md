 ## 解決策
 ## 問題の理解

 次の文字で構成される文字列が与えられます。`l`そして`r`。 文字は、石が一つずつ落ちてくるときにリスがどのように動くかを説明します。 

石`i`石の後に落ちる`1...i-1`すでに配置されています。 対応する文字が`l`、リスは現在の間隔の左半分に移動します。 そうであれば`r`、彼女は右半分に移動します。 すべての手が処理された後、石は最終的に直線上に配置されます。 石の番号を左端から右端に出力する必要があります。 

幾何学的な説明は複雑に聞こえますが、実際の作業は、石のインデックスの最終的な左から右への順序を決定することです。 

文字列の長さは 100 万に達する場合があります。 配列の中央に繰り返し挿入したり、位置を明示的にシミュレートしたりするアルゴリズムは、非常に遅すぎます。 と$n = 10^6$、 平$O(n^2)$動作には大まかに必要になります$10^{12}$まったく実行不可能な操作です。 線形時間ソリューションが必要です。 

微妙な点は、順序が石の物理的な座標によって決定されないことです。 ジオメトリは相対的な順序付けのルールのみを意味します。 

次の入力を考えてみましょう。```
r
```石は 1 つだけなので、出力は次のようになります。```
1
```あらゆることを想定したソリューション`r`他の何かがこの最小のケースを誤って処理する可能性がある後に配置する必要があります。 

もう 1 つの興味深いケースは次のとおりです。```
lll
```正しい出力は次のとおりです。```
3
2
1
```すべての新しい石は、以前に処理されたすべての石の左側に配置されます。 文字列を読み取るときにインデックスを追加するだけの不注意な実装では、`1 2 3`、これは間違いです。 

同様に:```
rrr
```生成する```
1
2
3
```これで、すべての石が以前のすべての石の右側に表示されます。 

混合ケース```
llrlr
```与える```
3
5
4
2
1
```これは、答えを逆にすることも、元の順序を維持することも十分ではないことを示しています。 

## アプローチ

 直接シミュレーションが可能です。 現在の左から右の石の順序を維持できます。 石のとき`i`到着したら、既存の石との相対的な位置を決定し、それに応じて挿入します。 

問題は、動的配列の先頭または中間への挿入に直線的な時間がかかることです。 最悪の場合は実行します$n$挿入、それぞれの費用$O(n)$、につながる$O(n^2)$複雑。 石が100万個あると絶望的に遅い。 

重要な観察は、ジオメトリが非常に単純な順序付けルールを誘導するということです。 

石を順番に加工していくとします。 石のとき`i`に対応する`l`、リスは左に逃げます。 これは、その間隔内の将来のすべての位置が石の左側にあることを意味します`i`。 最終的な配置では、石`i`残っている未処理の石の中でできるだけ早く現れるはずです。 

石のとき`i`に対応する`r`、リスは右に逃げます。 石`i`後で正しい間隔内に配置されるすべての石の後に出現する必要があります。 

これは建設的な解釈につながります。 

あらゆる人にとって`l`、対応する石の番号は最終シーケンスの先頭に属します。 

あらゆる人にとって`r`、対応する石の番号は最後のシーケンスの後ろに属します。 

文字列を左から右に読むと、石の番号を次のように配置できます。`l`フロント部分と石の番号に`r`後ろの部分に。 

出力順序を直接考えると、さらに単純な公式が現れます。 

すべての石にマークが付いています`r`元の順序で印刷する必要があります。 

すべての石にマークが付いています`l`それらの後に逆の順序で印刷する必要があります。 

当然のことながら、deque はこのプロセスを表します。 石材用`i`：

もし`s[i] == 'l'`、 押す`i+1`前へ。 

もし`s[i] == 'r'`、 押す`i+1`後ろへ。 

最後に、deque を前から後ろに読み取ると、正確に希望の順序が得られます。 

デキューの各操作は定数時間であるため、アルゴリズム全体は線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取ります。 
2. 空の両端キューを作成します。 
3. 文字を左から右に処理します。 現在の石の番号を次のようにします。`i + 1`。 
4. 現在のキャラクターが`l`、デクの先頭に石の番号を挿入します。 

これは、左に移動して到達する間隔内に配置されるすべての石の前に、石が表示されなければならないという事実を反映しています。 
5. 現在のキャラクターが`r`、デクの後ろに石の番号を挿入します。 

これは、石は後で適切な間隔で配置される石の後に出現する必要があるという事実を反映しています。 
6. すべての文字を処理した後、デキューを前から後ろに走査し、保存されているすべての石の番号を出力します。 

### なぜ効果があるのか

 最初の処理後の不変条件を維持します。`i`文字、両端キューには石の最終相対順序が正確に含まれています`1...i`。 

キャラクターがいるとき`l`、選択した間隔から生成される将来のすべての石は、最終的な配置では現在の石の右側になければなりません。 現在の石を前面に配置すると、正しい相対順序が維持されます。 

キャラクターがいるとき`r`、選択した間隔から生成される将来の石はすべて、現在の石の左側になければなりません。 現在の石を後ろに配置すると、正しい相対順序が維持されます。 

各挿入では、そのステップで選択された間隔と一致する唯一の位置に新しい石が配置されるため、不変条件は処理全体を通じて真のままです。 最後の石の後に、デックには完全な左から右の順序が含まれます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    s = input().strip()

    dq = deque()

    for i, ch in enumerate(s, start=1):
        if ch == 'l':
            dq.appendleft(i)
        else:
            dq.append(i)

    sys.stdout.write('\n'.join(map(str, dq)))

if __name__ == "__main__":
    solve()
```このソリューションでは両端キューを使用します。これは、定数時間での両端での挿入がサポートされているためです。 

ループは石を自然な順序で処理します。`1`に`n`。 石の番号はループインデックスから直接取得されます。 

のために`l`、私たちは使用します`appendleft`、現在の順序の先頭に石を配置します。 のために`r`、私たちは使用します`append`、最後に置きます。 

座標計算は必要ありません。 幾何学的プロセス全体が崩壊して、正しい相対的順序が維持されます。 

最終出力は、両端キューを 1 回走査し、数値を改行文字で結合することによって生成されます。 これにより、多くの個別の print 呼び出しが回避されます。これは、入力長が 100 万に達する場合に重要です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    s = sys.stdin.readline().strip()
    dq = deque()

    for i, ch in enumerate(s, start=1):
        if ch == 'l':
            dq.appendleft(i)
        else:
            dq.append(i)

    return "\n".join(map(str, dq))

# sample from statement
assert run("llrlr\n") == "4\n2\n1\n3\n5", "sample"

# minimum size
assert run("r\n") == "1", "single stone"

# all left
assert run("lll\n") == "3\n2\n1", "all left moves"

# all right
assert run("rrrr\n") == "1\n2\n3\n4", "all right moves"

# alternating pattern
assert run("lrlr\n") == "4\n2\n1\n3", "mixed ordering"

# boundary style case
assert run("lr\n") == "1\n2", "small mixed case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`r`|`1`| 最小入力サイズ |
 |`lll`|`3 2 1`| 繰り返しの前方挿入 |
 |`rrrr`|`1 2 3 4`| 繰り返されるバック挿入 |
 |`lrlr`|`4 2 1 3`| 交互操作 |
 |`lr`|`1 2`| 境界が小さい場合 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
lll
```処理は次のように進行します。`[1] → [2,1] → [3,2,1]`出力は次のようになります。```
3
2
1
```どの石も前から入れるので、最終的な順番は到着順と全く逆になります。 

次の入力を考えてみましょう。```
rrr
```処理は次のように進行します。`[1] → [1,2] → [1,2,3]`出力は次のとおりです。```
1
2
3
```すべての石は後ろに挿入されますので、最終的な順序は到着順と一致します。 

可能な最小の入力を考えてみましょう。```
l
```デクは次のようになります`[1]`、出力は次のようになります。```
1
```この場合、アルゴリズムでは特別な処理は必要ありません。`appendleft`そして`append`両端キューが空の場合は正しく動作します。 

混合パターンを考えてみましょう。```
lrl
```処理すると以下が得られます。`[1] → [1,2] → [3,1,2]`出力は次のとおりです。```
3
1
2
```これにより、後で`l`確立された他の石の相対的な順序を維持しながら、以前に処理されたすべての石より先に正しくジャンプします。
