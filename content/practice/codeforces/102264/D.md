 ## 解決策
 ## 問題の理解

 (N) 個の異なるグリッド点 ((X_i,Y_i)) があります。 各点はいずれかの座標軸に接続されている必要があります。 ((X_i,Y_i)) から (y) 軸への水平接続には (X_i) のコストがかかり、(x) 軸への垂直接続には (Y_i) のコストがかかります。 

コストは、個々のセグメントの長さの合計ではありません。 すべての水平セグメントの中で最も長い (X_i) だけが重要であり、すべての垂直セグメントの中で最も長い (Y_i) だけが重要です。 横方向の最大長が (h)、縦方向の最大長が (v) の場合、総コストは (h+v) となります。 

使用できる水平セグメントと垂直セグメントの数には上限 (H) と (V) もあります。 難しいのは横断規制です。 ((X_i,Y_i)) に属する水平セグメントは (0\le x\le X_i) を占め、((X_j,Y_j)) に属する垂直セグメントは (0\le y\le Y_j) を占めます。 彼らはまさにそのときに内部で交差します

 [
 X_j<X_i
 】

 そして

 [
 Y_i<Y_j。 
】

 エンドポイントでの交差が明示的に許可されているため、不等式は厳密です。 

座標は 2 次モジュラー再帰によって生成されるため、入力では最初の 2 つの (X) 座標と最初の 2 つの (Y) 座標のみが与えられます。 残りの値は (O(N)) 時間以内に生成される必要があります。 最大の (N) は (800,000) であるため、(N) 内の二次関数はすぐに使用できなくなります。 (N^2) であっても、最大サイズでおよそ (6.4\times10^{11}) 個のペア チェックを意味します。 (O(N\log N)) の解は適切ですが、方向に対する指数関数的な検索は完全に範囲外です。 

いくつかの境界ケースは、静かに解決策を破壊する可能性があります。 (H+V<N) の場合、すべてのポイントを接続するのに十分な許容セグメントがありません。 例えば、```
1
3 1 1
1 2 0 1 0 3
1 2 0 1 0 3
```((1,1),(2,2),(3,3)) を生成します。 3 つの点に対して許可されるセグメントは 2 つだけなので、答えは次のようになります。`Case #1: -1`。 

エンドポイントでの交差が許可されるという事実も重要です。 考慮する```
1
2 1 1
1 2 0 0 0 10
1 2 0 0 0 10
```点は ((1,1)) と ((2,2)) です。 1つ目を水平に接続し、2つ目を垂直に接続します。 それらの交差は ((2,1)) にあり、これは水平セグメントの終点であるため、許可されます。 答えは`Case #1: 3`。 非厳密な不等式を使用した不用意な実装は、この有効な構成を拒否する可能性があります。 

等しい座標にも同じ注意が必要です。 のために```
1
3 1 2
2 2 0 0 1 2
1 2 0 1 0 3
```点は ((2,1),(2,2),(2,3)) です。 1 つの点を水平にし、他の 2 つの点を垂直にすることができます。 すべてのセグメントは同じ垂直線上にあるか、端点で交わっているため、これは有効であり、コストがかかります (2+2=4)。 等しい (X) 座標を交差として扱うと、間違った答えが得られます。 

最後に、ゼロは意味のあるしきい値です。 すべての点が垂直に接続されている場合、水平セグメントは存在せず、そのコストはゼロになります。 同様に、すべての点が水平の場合、垂直コストはゼロになります。 両方の方向が使用されることを常に前提とするソリューションでは、最初のサンプルのような最適な答えが得られません。 

## アプローチ

 直接的なアプローチは、すべての点が水平であるか垂直であるかを個別に決定することです。 (2^N) 個の可能な割り当てがあります。 割り当てごとに、すべての水平ペアと垂直ペアの交差をチェックし、各タイプのセグメントが何個使用されているかをカウントできます。 単純な交差チェックでは、(O(N^2)) 個のペアを検査し、(O(N^2 2^N)) 個の時間を与えます。 たとえ交差チェックが最適化されたとしても、(2^N) 代入によりこの方法は絶望的になります。 (N=30) では、すでに 10 億を超える割り当てが存在します。 

有益な観察は、コストは 2 つの数値のみに依存するということです。 (h) を水平点の最大値 (X_i) とし、(v) を垂直点の最大値 (Y_i) とします。 (h) と (v) が固定されると、(X_i>h) を持つすべての点は強制的に垂直になり、(Y_i>v) を持つすべての点は強制的に水平になります。 

これらのしきい値の下では、交差条件がはるかに単純になります。 (X_i>h) の場合、点 (i) は垂直でなければなりません。 (Y_j>v) の場合、点 (j) は水平でなければなりません。 両方の条件を満たす点は両方の方向である必要があるため、そのような点ではしきい値が不可能になります。 

重要な構造上の事実は、セグメント数の制限を除けば、これでも十分であるということです。 (X_i>h) と (Y_i>v) の両方を持つ点はないとします。 (Y_i>v) の点は水平に、(X_i>h) の点は垂直にできます。 残りの柔軟なポイントについて、より多くの水平セグメントが必要な場合は、最大の (Y) 座標を持つものを水平として選択し、残りを垂直にします。 

この割り当てでは交差点を作成できません。 すべての強制水平ポイントは、すべての強制垂直ポイントよりも大きい (Y) を持ちます。 すべての強制された垂直点は、すべての可能な水平点よりも大きい (X) を持ちます。 柔軟な点の中で、すべての柔軟な垂直点と少なくとも同じ大きさの a (Y) を持つ水平点が選択されました。 したがって、考えられる 3 つのタイプの水平垂直ペアはすべて安全です。 

したがって、問題は、セグメント数の要件を満たす最も安価なしきい値のペア (h,v) を見つけて、右上の長方形 (X>h,Y>v) 内の点を回避することに帰着します。 

垂直制限で必要な最小値 (h) は、((V+1)) 番目に大きい (X) ですが、(V=N) の場合はゼロになります。 同様に、水平方向の制限で必要な最小値 (v) は、(H=N) を除き、((H+1)) 番目に大きい (Y) です。(H=N) の場合、ゼロにすることができます。 

ここで (h) を修正します。 (X>h) を持つすべての点は強制的に垂直になるため、交差を防ぐために次の点を選択する必要があります。 

[
 v\ge \max_{X_i>h}Y_i。 
】

 (v) 水平カウント要件を満たす必要もあります。 したがって、この (h) に対する考えられる最も安価な垂直しきい値は次のようになります。 

[
 v=\max\left(y_{\text{req}},\max_{X_i>h}Y_i\right)。 
】

 これは、個別の (X) 座標ごとに評価できます。 (X) を減らしてポイントを並べ替えると、厳密に大きい (X) を持つポイント間で最大値 (Y) を維持できます。 この厳密さは、まさにエンドポイント交差ルールが要求するものです。 

2 つのアプローチを次のように比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2 2^N)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 2 つの反復シーケンスからすべて (N) 個の点を生成します。 Python の整数が直接使用されるため、再帰内の積は 32 ビットの範囲を超えても安全です。 
2. (H+V<N) の場合は、すぐに (-1) を返します。 すべてのポイントには 1 つのセグメントが必要なので、2 つのセグメント制限に十分な合計容量が必要です。 
3. ポイントの生成中に、最大値 (X) と最大値 (Y) を記録します。 (V=N) の場合、すべての点を垂直に接続することが許可され、コストは正確に最大値 (Y) になります。 これを最初の答えとして使用してください。 (H=N) の場合、すべての点を水平方向に接続すると、候補の最大値 (X) が得られます。 
4. すべての (Y) 座標を降順に並べ替えます。 (H<N)、ゼロから始まるインデックス (H) の値が ((H+1)) 番目に大きい (Y) である場合、それを (y_{\text{req}}) と呼びます。 最大 (H) 個の水平セグメントを持つ有効なソリューションには、(v\ge y_{\text{req}}) が必要です。 (H=N) の場合は、(y_{\text{req}}=0) を使用します。 
5. ポイントを降順 (X) で並べ替えます。 (V<N) の場合、ゼロから始まるインデックス (V) の点が ((V+1)) 番目に大きい (X) を持ち、これを (x_{\text{req}}) と呼びます。 最大 (V) 個の垂直セグメントを含む有効なソリューションには、(h\ge x_{\text{req}}) が必要です。 (V=N) の場合、(x_{\text{req}}=0) を使用します。 
6. ソートされたポイントを等しい (X) のグループごとにスイープします。 座標 (x) を持つグループを処理する前に、`greater_y`、(X) 座標が厳密に (x) より大きい点の中で最大の (Y)。 (x) で終わる水平セグメントが、同様に終点が (x) である垂直セグメントに接触する可能性があるため、この厳密なグループ化が必要です。 
7. (x\ge x_{\text{req}}) を持つグループごとに、(h=x) を選択します。 (X>h) の点は強制的に垂直になるため、すべての垂直しきい値が (v\ge\text{greater_y}) を満たす必要があります。 これをセグメント数の要件と組み合わせると、次のようになります。 

[
 v=\max(y_{\text{req}},\text{greater_y})。 
】

 候補コストは (h+v) です。 

1. 最小限の候補で回答を更新します。 グループを評価した後、その (Y) 座標を`greater_y`次に小さい (X) に移動する前に。 

### なぜ効果があるのか

 有効な図面について、(h) をその最長の水平方向の長さ、(v) をその最長の垂直方向の長さとします。 (X>h) のすべての点は垂直でなければならず、(Y>v) のすべての点は水平でなければなりません。 したがって、(h) は (V) 限界を満たさなければならず、(v) は (H) 限界を満たさなければなりません。 また、(X>h) を持つ点は (Y>v) を持つことはできません。そのような点は両方の方向を使用することを強制されるためです。 したがって、固定 (h) の場合、すべての有効な解には少なくとも (h+\max(y_{\text{req}},\max_{X_i>h}Y_i)) のコストがかかります。 

スイープは、可能なすべての (h) についてこの下限を正確に評価します。 逆に、評価されたすべての (h) について、その最小値 (v) を選択すると、強制された水平セットと垂直セットが素になり、十分な容量が得られます。 残りの水平ポイントを降順 (Y) 順に割り当てると、フレキシブル ポイント間の交差が防止されます。 したがって、スイープによって評価されたすべての候補は有効な描画に対応し、最小の候補がまさに最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, H, V, xdata, ydata):
    x1, x2, ax, bx, cx, dx = xdata
    y1, y2, ay, by, cy, dy = ydata

    if H + V < n:
        return -1

    points = [(x1, y1), (x2, y2)]
    ys = [y1, y2]

    max_x = max(x1, x2)
    max_y = max(y1, y2)

    px2, px1 = x1, x2
    py2, py1 = y1, y2

    for _ in range(2, n):
        nx = ((ax * px2 + bx * px1 + cx) % dx) + 1
        ny = ((ay * py2 + by * py1 + cy) % dy) + 1

        points.append((nx, ny))
        ys.append(ny)

        if nx > max_x:
            max_x = nx
        if ny > max_y:
            max_y = ny

        px2, px1 = px1, nx
        py2, py1 = py1, ny

    ans = 10**30

    # Using no horizontal segments.
    if V >= n:
        ans = min(ans, max_y)

    # Using no vertical segments.
    if H >= n:
        ans = min(ans, max_x)

    # If no horizontal segment is allowed, the all-vertical
    # candidate above is the only possible orientation.
    if H == 0:
        return ans

    ys.sort(reverse=True)
    y_req = ys[H] if H < n else 0

    points.sort(key=lambda p: p[0], reverse=True)
    x_req = points[V][0] if V < n else 0

    greater_y = 0
    i = 0

    while i < n:
        x = points[i][0]
        j = i
        group_y = 0

        while j < n and points[j][0] == x:
            if points[j][1] > group_y:
                group_y = points[j][1]
            j += 1

        if x >= x_req:
            v_cost = max(y_req, greater_y)
            candidate = x + v_cost
            if candidate < ans:
                ans = candidate

        if group_y > greater_y:
            greater_y = group_y

        i = j

    return ans

def main():
    T = int(input())
    out = []

    for case_id in range(1, T + 1):
        n, H, V = map(int, input().split())
        xdata = list(map(int, input().split()))
        ydata = list(map(int, input().split()))

        ans = solve_case(n, H, V, xdata, ydata)
        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```繰り返しは 3 番目のポイントから始まるため、最初の 2 つのポイントは直接挿入されます。 変数`px2`そして`px1`次の値を生成する前に常に (X_{i-1}) と (X_i) を表し、同じ不変式が (Y) シーケンスに対して維持されます。 

反復では、指定どおりにモジュロの前に乗算が使用されます。 Python の任意精度の整数は、固定幅の 32 ビット実装で発生するオーバーフローを回避します。 

初期の`ans`1 つの方向が使用されない場合を処理します。 これは、両方の制限が正の場合でも重要です。 最初のサンプルでは、​​すべての点が垂直になる可能性があるため、最適な水平コストはゼロです。 

(Y) 配列は降順にソートされるため、`ys[H]`は ((H+1)) 番目に大きい値です。 (H=N) の場合、そのような要素は存在せず、すべての点が水平である可能性があるため、ゼロが正しいしきい値になります。 

ポイントは降順 (X) でソートされます。 スイープ中は、現在の等しい (X) グループは挿入されません。`greater_y`候補者が評価されるまで。 その結果、`greater_y`(X_i\ge x) ではなく、(X_i>x) を満たす点が正確に含まれています。 これは実装において最もデリケートな境界条件です。 

## 実用的な例

 ### サンプル 1

 最初のサンプルには (N=2)、(H=2)、および (V=2) があり、点は ((6,2)) および ((3,4)) です。 

(V=N) であるため、全垂直解はコスト (4) の候補になります。 (H=N) であるため、全水平ソリューションのコストは (6) になります。 

混合スイープの場合、(x_{\text{req}}=0) および (y_{\text{req}}=0)。 

| 現在 (x) | この点 (x) |`greater_y`グループの前 | (v=\max(y_{\text{req}},greater_y)) | 候補者 |
 | --- | --- | --- | --- | --- |
 | 6 | ((6,2)) | 0 | 0 | 6 |
 | 3 | ((3,4)) | 2 | 2 | 5 |

 最初の全縦候補はすでに (4) なので、最終的な答えは次のようになります。`Case #1: 4`。 

このスイープは、ゼロコスト志向を個別に考慮する必要がある理由を示しています。 しきい値 (h=0) は水平セグメントを使用しないことを表し、そのしきい値は任意の点の (X) 座標ではありません。 

### サンプル 2

 2 番目のサンプルには (N=2)、(H=2)、(V=1) があり、やはり点 ((6,2)) と ((3,4)) があります。 

ここでは (H=N)、つまり (y_{\text{req}}=0) となります。 許可される垂直セグメントは 1 つだけであるため、(x_{\text{req}}) は 2 番目に大きい (X)、つまり (3) になります。 

全水平候補のコストは (6) です。 

| 現在 (x) | この点 (x) |`greater_y`グループの前 | (v) | 候補者 |
 | --- | --- | --- | --- | --- |
 | 6 | ((6,2)) | 0 | 0 | 6 |
 | 3 | ((3,4)) | 2 | 2 | 5 |

 (h=3) では、(X=6) の点が強制的に垂直になります。 その (Y) 座標は (2) であるため、垂直コストは少なくとも (2) でなければなりません。 もう 1 つの点は長さ (3) で水平であり、合計コスト (3+2=5) が得られます。 

結果は`Case #2: 5`。 このトレースは、スイープが厳密に大きい (X) の点を使用する理由も示しています。(X=3) の点自体は、`greater_y`。

 ## 特殊なケース

 (H+V<N) の場合、アルゴリズムは座標を生成する前に (-1) を返します。 入力用```
1
3 1 1
1 2 0 1 0 3
1 2 0 1 0 3
```生成される点は ((1,1),(2,2),(3,3)) です。 許可されるセグメントは 2 つだけですが、3 つが必要です。 いかなる幾何学的議論もその容量制限を克服することはできません。 

すべての垂直セグメントが許可される場合、水平しきい値をゼロにすることができます。 (V=N=2) の最初のサンプルでは、​​アルゴリズムは初期化します。`ans`最大値 (Y) は (4) です。 後のスイープではコスト (6) と (5) のみが検出されるため、答えは (4) のままです。 これは、そうでなければ欠落している (h=0) 候補を処理します。 

座標が等しい場合、スイープは更新する前に等しい (X) グループ全体を処理します。`greater_y`。 点 ((2,1)、(2,2)、(2,3)) の場合、(X=2) の点はあっても、(h=2) の候補には (X>2) の点が表示されません。 これは正しいです。共有 (X) 座標での交差はエンドポイントの交差であり、許可されているためです。 

点 ((1,1)) と ((2,2)) を持つ終点の場合、水平方向に最初の点を選択し、垂直方向に 2 番目の点を選択すると、水平セグメントの終点である ((2,1)) で交点が生成されます。 交差条件には (X_{\text{vertical}}<X_{\text{horizo​​ntal}}) と (Y_{\text{horizo​​ntal}}<Y_{\text{vertical}}) の両方が必要で、最初の不等式は false です。 したがって、アルゴリズムは構成を受け入れ、コスト (1+2=3) を取得します。 

最大サイズの再発検定の場合、(1\le i\le800000) に対して (X_i=Y_i=i)。 (H=V=400000) の場合、必要なしきい値は両方とも (400000) です。 (h=400000) を選択すると、残りの (400000) ポイントが強制的に垂直になり、その最大 (Y) が (800000) となり、コスト (1,200,000) が与えられますが、スイープが右上のポイントを考慮するバランスのとれたしきい値を選択すると、最適な値 (800000) が得られます。 このテストでは、再帰、厳格なしきい値処理、等価自由ソート、および上限制約での整数サイズが実行されます。
