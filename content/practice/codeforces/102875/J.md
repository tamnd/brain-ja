 ## 解決策
 ## 問題の理解

 この問題の関数はモジュラー逆行列を計算する再帰的な方法ですが、要求された値は逆行列そのものではありません。 この質問では、関数が次のすべての可能な開始値で開始された場合の関数呼び出しの平均数を尋ねます。`1`に`p - 1`、 どこ`p`は素数です。 

再帰関数は、引数が次のようになるとすぐに停止します。`1`。 それ以外の場合は、現在の値から移動します`x`に`p mod x`そしてもう一度電話をかけます。 呼び出しの数のみが重要であるため、逆関数を構築するために使用される乗算とモジュロ演算はここでは無関係です。 たとえば、次のようなとき`p = 7`、のためのチェーン`x = 5`は`5 -> 2 -> 1`、貢献します`3`平均を求めます。 

入力には最大 100 個の素数値が含まれており、すべての素数は最大 100 個です。`10^6`。 この境界がアルゴリズム上の主要な手がかりとなります。 すべての再帰チェーンを独立して追跡しようとする解決策は、同じ部分問題を何度も繰り返す可能性があり、すべてのチェーンの直接シミュレーションは二次の動作に近づきます。 およその値の場合`10^6`、二次方程式の方法では約`10^12`これは通常の制限時間をはるかに超えています。 私たちは、すべての状態がより小さな剰余にのみ依存しているという事実を利用する必要があります。 

微妙なケースはほとんどが境界付近にあります。 いつ`p = 2`、可能な開始値は 1 つだけです。`x = 1`。 答えは`1`、およびループに常に からの値が含まれると想定する実装。`2`に`p - 1`開始値の数は次のとおりであるため、誤ってゼロで除算する可能性があります。`p - 1`。 

入力の場合:```
1
2
```正しい出力は次のとおりです。```
1.0000000000
```唯一の呼び出しであるため、再帰的な遷移はありません。`F(1, 2)`。 

もう 1 つの簡単な間違いは、返されたモジュール値を答えとして扱うことです。 たとえば、`p = 7`そして`x = 5`の場合、関数はモジュラー逆数値を返しますが、寄与するのは呼び出しの数です。```
F(5, 7) -> F(2, 7) -> F(1, 7)
```貢献度は、`3`の逆ではありません`5`モジュロ`7`。 

## アプローチ

 簡単なアプローチは、考えられるすべての開始値に対して再帰関数をシミュレートすることです。 それぞれについて`x`から`1`に`p - 1`、私たちは繰り返し交換します`x`と`p mod x`到達するまで`1`、呼び出しの数を数えます。 再帰は測定する必要があるプロセスを正確に記述しているため、これにより正しい結果が得られます。 

問題は、多くの異なる開始値が同じ中間値に到達することです。 すべてのチェーンを個別に計算すると、同じ剰余を何度でも評価できます。 最悪の場合、これをすべての開始値に対して個別に実行すると、二次関数になる可能性があります。 と`p`に近い`10^6`、それは約 1 兆回の遷移を意味します。 

重要な観察は、依存関係グラフがすでに順序付けされていることです。 どれについても`x > 1`、次の値は`p mod x`、この値は常に以下よりも小さくなります。`x`。 つまり、答えを昇順に計算すると、`x`、すべての遷移に対する答えはすでにわかっています。 

させて`dp[x]`から始まる関数による呼び出しの数になります。`x`。 基本的なケースは`dp[1] = 1`。 他のすべての値については、次のようになります。$$dp[x] = 1 + dp[p \bmod x]$$余分な`1`は現在の呼び出しを表し、残りの呼び出しはまさに再帰的な子からの呼び出しです。 

最終的な答えはすべての平均です`dp[x]`からの値`1`に`p - 1`。

 | ブルートフォース | O(p²) | お(1) | 遅すぎる |
 | 最適 | O(p) | O(p) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`dp`どこ`dp[x]`関数の開始時に必要な呼び出しの数を格納します。`x`。 セット`dp[1] = 1`この状態では関数がすぐに戻るためです。 これにより、唯一の停止条件が直接得られます。 
2. 反復処理`x`から`2`に`p - 1`。 値ごとに、次の再帰状態を計算します。`p mod x`。 この値はより小さいため、`x`、その答えはすでに計算されています。 
3.セット`dp[x] = 1 + dp[p mod x]`。 現在の呼び出しは 1 つを提供し、チェーンの残りはすでに動的プログラミング テーブルに格納されています。 
4. すべてを追加します`dp[x]`値を計算し、合計をで割ります。`p - 1`。 からのすべての開始値`1`に`p - 1`確率は等しいため、必要な期待値は算術平均になります。 

なぜ機能するのか: 重要な不変条件は、すべての値を処理した後、`x`、`dp[i]`どれも正しいです`i <= x`。 からの再帰的遷移`x`は常に小さい数値に移動するため、必要な部分問題はすでに不変式によってカバーされています。 考えられるすべての開始値が最終合計に 1 回だけ含まれるため、計算された平均は予想される呼び出し数と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(p):
    if p == 2:
        return 1.0

    dp = [0] * p
    dp[1] = 1

    total = 1
    for x in range(2, p):
        dp[x] = 1 + dp[p % x]
        total += dp[x]

    return total / (p - 1)

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        p = int(input())
        ans.append(f"{solve_case(p):.10f}")
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```特別な場合`p = 2`無効な平均計算の作成を回避します。 可能な開始値は 1 つだけであるため、答えは次のようになります。`1`。 

より大きな素数の場合、`dp`サイズがあります`p`考えられるすべての開始値が以下より小さいため、`p`。 ループ順序の増加が実装の中心的な詳細です。 計算するとき`dp[x]`、インデックス`p % x`よりも小さいことが保証されます`x`したがって、再帰や追加の順序付けは必要ありません。 

変数`total`合計を計算する間、 は整数として保持されます。 浮動小数点への変換は最後の除算中にのみ行われるため、累積中の不必要な精度の損失が回避されます。

 ## 特殊なケース

 のために`p = 2`、アルゴリズムはすぐに戻ります`1.0`。 からのループ`2`に`p - 1`は空ですが、唯一の開始点は であるため、これは正しいです。`x = 1`。 

入力の場合:```
1
2
```実行は次のとおりです。 

| ステップ | 状態 |
 | --- | --- |
 | 開始 | 唯一の価値は、`x = 1`|
 | 関数呼び出し | ワンコール |
 | 平均 |`1 / 1 = 1`|

 開始値が別の計算された状態に到達する場合、DP 順序付けはそれを自然に処理します。 と`p = 7`、計算するとき`dp[5]`、遷移は次のとおりです。```
5 -> 2
```値`dp[2]`はすでに知られています:```
dp[2] = 1 + dp[1] = 2
```それで：```
dp[5] = 1 + dp[2] = 3
```アルゴリズムはチェーンを再計算しません`2 -> 1`これが、線形ソリューションが機能する主な理由です。
