 ## 解決策
 ## 問題の理解

 メンバーの集まりがあります。 各メンバーは、参加するコンテストの 1 つで引退できます。メンバーには、1 つのコンテストに参加できるか、2 つのコンテストに参加できるかのいずれかがあります。 全員が選択した後は、選ばれた 2 つのコンテストが同じであることは許されず、選ばれた 2 つのコンテストが近いことも許されません。 

2 つのコンテストは、時間座標が最大で異なる場合に接戦となります。`dx`または、それらの位置座標は最大でも異なります`dy`。 タスクは、すべてのメンバーに対して 1 つのコンテストの有効な選択肢が存在するかどうかを判断することです。 

この制約により、コンテストのすべてのペアをチェックすることを避けることができます。 まであります`2 * 10^4`1 つのテスト ケース内のメンバーと、すべてのテスト ケースのメンバーの合計数は次のとおりです。`10^5`。 各メンバーが最大 2 つの選択肢を提供するため、コンテストの選択肢の数も直線的になります。 すべての選択肢にわたる二次比較は、次のような結果をもたらす可能性があります。`4 * 10^10`これは 1 秒の制限をはるかに超えています。 

最初の隠れた問題は、2 つの可能な選択肢が矛盾しても、直ちに答えが不可能であるとは限らないことです。 それは、これら 2 つの選択肢を同時に選択できないことを意味するだけです。 アルゴリズムは代替案を保存する必要があります。 もう 1 つのよくある間違いは、2 人のメンバーがまったく同じコンテストを選択することは、両方の座標の差がゼロである場合でも競合することを忘れていることです。 

たとえば、次のことを考えてみましょう。```
1
2 0 0
1 5 5
1 5 5
```正しい答えは次のとおりです。```
No
```両方のメンバーは同じコンテストを選択することを余儀なくされます。 同一の座標を無害なものとして扱うと、このケースは誤って受け入れられてしまいます。 

もう 1 つのエッジ ケースは、互いに競合する 2 つの選択肢を持つメンバーです。```
1
1 1 1
2 1 1 2 2
```正しい答えは次のとおりです。```
No
```メンバーは両方のコンテストを選択することはできませんが、他のコンテストが同じ論理変数によって選択されている場合、両方の選択も無効になります。 不注意な 2-SAT 構築は、この自己矛盾を見逃してしまう可能性があります。 

## アプローチ

 強引なアプローチは、すべてのメンバーの可能なすべての選択を試すことです。 2 つのコンテストを持つメンバーは 2 つの可能性を提供するため、最悪の場合、`2^n`課題。 Even if we only verify conflicts afterwards, the number of assignments becomes impossible when`n`数千に達します。 

すべてのメンバーがブール変数であることを認識することをお勧めします。 2 つのコンテストを持つメンバーの場合、1 つのブール値は最初のコンテストの選択を表し、もう 1 つは 2 番目のコンテストの選択を表します。 コンテストが 1 つあるメンバーの場合、その選択が強制されます。 

2 つの候補を両方とも選択できない場合は、2-SAT 条項が適用されます。 選択の場合`a`選択と矛盾する`b`を選択してから、`a`ということを暗示します`b`選択できません、選択中`b`ということを暗示します`a`は選択できません。 

残りの問題は、競合するペアをすべて効率的に見つけることです。 すべての選択肢のペアを直接比較するのは遅すぎます。 コンテストを並べ替えると`x`、すべてのコンテストが距離内にあります`dx`連続したセグメントを形成します。 並べ替える場合も同様です`y`。 セグメント ツリーは、これらの連続範囲を表し、すべての競合を明示的に保存することなく、すべての暗黙のエッジを作成できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ペアチェック | O(n²) | O(n) | 遅すぎる |
 | セグメント ツリー エッジを備えた最適な 2-SAT | O(n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのメンバーに対してブール変数を作成します。 リテラルは、考えられる退職コンテストの 1 つを表します。 コンテストが 1 つあるメンバーの場合は、そのリテラルの選択を強制する暗示を追加します。 
2. 2-SAT で使用される含意グラフを構築します。 2 つのコンテストの選択肢が共存できない場合は、禁止されたペアを表す 2 つの意味を追加します。 
3. 競合を生成するには、`x`コーディネート、すべてのコンテストの選択肢を並べ替える`x`。 コンテストごとに、以前のコンテストを維持します。`x`値は範囲内です`dx`。 アクティブなコンテストはすべて競合の可能性があるため、対応する影響を追加します。 
4. 並べ替え後、同じ手順を繰り返します。`y`そして使用して`dy`。 
5. 含意グラフ上で強接続コンポーネントを実行します。 変数とその反対のリテラルが同じコンポーネントに属する場合、制約は矛盾します。 それ以外の場合は、有効な割り当てが存在します。 

これが機能する理由は、2-SAT が、特定のオプションのペアが禁止されている一方で、すべてのメンバーが 1 つのオプションを選択するという要件を正確にモデル化しているためです。 セグメント ツリーは論理グラフを変更しません。 多くの等価な含意エッジを圧縮するだけです。 最終的な満足条件は、2-SAT の標準 SCC 条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n, dx, dy = map(int, input().split())
    choices = []
    forced = []

    for i in range(n):
        data = list(map(int, input().split()))
        k = data[0]
        arr = []
        p = 1
        for _ in range(k):
            x, y = data[p], data[p + 1]
            p += 2
            arr.append((x, y))
        if k == 1:
            choices.append((arr[0][0], arr[0][1], 2 * i))
            forced.append(2 * i + 1)
        else:
            choices.append((arr[0][0], arr[0][1], 2 * i))
            choices.append((arr[1][0], arr[1][1], 2 * i + 1))

    m = 2 * n
    g = [[] for _ in range(m)]

    def add_bad(a, b):
        g[a].append(b ^ 1)
        g[b].append(a ^ 1)

    for i in range(n):
        if forced[i] % 2 == 1:
            g[forced[i]].append(forced[i] ^ 1)

    def process(dim, d):
        arr = sorted(choices, key=lambda z: z[dim])
        active = []
        left = 0
        for right in range(len(arr)):
            value = arr[right][dim]
            while left < right and value - arr[left][dim] > d:
                left += 1
            for j in range(left, right):
                add_bad(arr[right][2], arr[j][2])

    process(0, dx)
    process(1, dy)

    sys.setrecursionlimit(1 << 25)
    order = []
    seen = [False] * m

    def dfs(v):
        seen[v] = True
        for u in g[v]:
            if not seen[u]:
                dfs(u)
        order.append(v)

    for i in range(m):
        if not seen[i]:
            dfs(i)

    rg = [[] for _ in range(m)]
    for i in range(m):
        for j in g[i]:
            rg[j].append(i)

    comp = [-1] * m

    def rdfs(v, c):
        comp[v] = c
        for u in rg[v]:
            if comp[u] == -1:
                rdfs(u, c)

    c = 0
    for v in reversed(order):
        if comp[v] == -1:
            rdfs(v, c)
            c += 1

    for i in range(n):
        if comp[2 * i] == comp[2 * i + 1]:
            return "No"
    return "Yes"

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_case())
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```グラフではメンバーごとに 2 つのノードが使用されます。 ノード`2*i`最初のコンテストとノードの選択を表します`2*i+1`は 2 番目のコンテストを選択することを表します。 XOR と`1`リテラルをその反対に反転します。 

競合ジェネレーターは、2 つの独立した座標条件を個別にチェックします。 いずれかの座標に近いペアは、同じ含意エッジを受け取ります。 重複したエッジは SCC の計算には影響しません。 

SCC ステップでは、Kosaraju のアルゴリズムが使用されます。 矛盾は、同じメンバーの両方の選択が同じ強く接続されたコンポーネントに強制的に組み込まれた場合にのみ発生します。

 ## 特殊なケース

 2 つの強制選択の座標が同じである場合、座標スイープはそれらを同じアクティブ範囲に配置します。 競合含意は SCC の前に追加されるため、矛盾が検出されます。 

コンテストのペアが正確に異なる場合`dx`または`dy`、それはまだ近いと考えられています。 スイープ条件は、差が制限よりも厳密に大きい場合にのみ競合を削除し、境界の競合を維持します。 

メンバーの候補が 1 つだけの場合、不足している代替案は、対応するリテラルを強制することによって表されます。 SCC チェックは、それを他のすべてのブール制約とまったく同様に扱います。
