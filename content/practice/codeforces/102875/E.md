 ## 解決策
 ## 問題の理解

 最大 16 ノードの無向ネットワークがあります。 すべてのノードが感染し始めます。 各秒の初めに、ウイルス対策ソフトウェアは現在感染しているノードの一部を駆除する可能性がありますが、駆除できるのはせいぜい`k`1 回の操作でノードを構築できます。 駆除後、残った感染ノードはすべての近隣ノードにウイルスを拡散し、その後自ら消滅します。 目標は、最終的にネットワーク全体をウイルスから守る一連のクリーニング操作を出力するか、そのようなシーケンスが存在しないと判断することです。 

状況を表現する便利な方法は、ビットマスクを使用することです。 少し`i`ノードのときに設定されます`i`現在感染しています。 感染したノードをいくつか選択して削除すると、駆除されていないノードのみが拡散する可能性があります。 次の状態は、まさに残りのノードの隣接ノードの結合です。 

の小さな値`n`は重要な制限です。 しかないので、`2^n`考えられる感染状態と`n <= 16`、州の数は最大で 65536 です。 状態の数を多項式とする解法が可能です。 一方、状態圧縮を使用せずにグラフを直接シミュレートすると、繰り返される構成を効率的に取得できません。 

主なエッジケースは、「今すぐクリーン」と「永久にクリーン」を混同することに起因します。 1 回のラウンドで駆除されたノードでも、隣接する感染したノードが広がると、再び感染する可能性があります。 例えば：```
2 1 1
1 2
```答えは、1 回の操作で両方のノードをクリーニングするというものではありません。`k=1`。 ノード 1 をクリーニングすると、まずノード 2 が感染したままになり、ノード 1 に感染が広がります。有効な答えは次のとおりです。```
2
1
1
```もう 1 つの重要なケースは、現在感染しているすべてのノードを駆除できる場合です。 もし`k=n`、初期状態はすべてのノードを 1 回クリーニングすることですぐに解決できます。 クリーニング後に常にスプレッドを強制するシミュレーションでは、このケースは誤って拒否されます。 

## アプローチ

 強引なアイデアは、考えられるあらゆる戦略を試すことです。 現在の感染セットについては、感染ノードのすべてのサブセットを列挙して駆除し、1 つの拡散をシミュレートし、再帰的に続行できます。 考えられるすべての有効な戦略が考慮されているため、これは正しいです。 問題は選択肢の多さです。 すべての状態にわたって、考えられるすべてのクリーンアップされたサブセットを列挙すると、おおよその結果が得られます。`3^n`すべてのノードが、感染していない、感染しているが駆除されている、または感染しているが駆除されていないという 3 つのカテゴリのいずれかになる可能性があるためです。 のために`n=16`、繰り返しの作業を考慮して検索ツリーを保存する前に、これはすでに約 4,300 万の可能性があります。 

有益な観察は、現在の感染パターンが将来を完全に描写しているということです。 以前の操作を思い出す必要はありません。 これにより、問題は状態グラフ上の最短経路探索に変わります。 すべてのマスクは頂点であり、有向エッジは、1 つのウイルスの拡散に続く 1 つの可能な駆除操作を表します。 

すべての操作のコストは等しいため、幅優先検索で十分です。 残りの最適化では、トランジションを慎重に生成します。 クリーニングされたノードを直接選択するのではなく、クリーニング後に生き残って拡散した感染したノードを選択します。 現在のマスクが`S`生き残った感染ノードは`T`、 それから`T`のサブセットでなければなりません`S`、クリーンアップされたノードの数は`popcount(S)-popcount(T)`。 この値が最大であるサブセットのみを考慮します`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(2^n) | 一般的なケースでは遅すぎる |
 | 最適 | 定数が小さい場合の O(3^n) 最悪のケース | O(2^n) | 承認済み |

 最悪の場合の遷移数は依然としてサブセットの列挙に基づいていますが、状態グラフには 65536 個の頂点しかなく、実装では整数ビット演算が使用されます。 と`n=16`、これは快適にフィットします。 

## アルゴリズムのチュートリアル

 1. すべての感染状態を整数マスクとしてエンコードします。 初期状態は`(1 << n) - 1`、目標状態は`0`。 
2. すべてのマスクについて、1 つのウイルスの拡散の結果を事前計算します。 マスクがクリーニング後に生き残った感染ノードを表す場合、その次の状態は、設定されているすべてのビットの隣接マスクの OR です。 
3. 初期マスクから開始して BFS を実行します。 以前の状態と、検出されたすべての状態に到達するために使用したクリーニング操作を保存します。 
4. ステート処理時`S`、すべてのサブセットを列挙します`T`の`S`。 扱う`T`クリーニング後も感染したままのノードとして。 もし`S`ビット数が多すぎます`T`、クリーニング操作は超過します`k`なので飛ばしてください。 
5. クリーンアップされたノードは次のとおりです。`S ^ T`。 次の状態は、事前計算された拡散結果です。`T`。 この状態にアクセスしたことがない場合は、その親と使用された操作を記録します。 
6. 状態がいつ`0`に到達したら、親ポインターを逆方向にたどって答えを再構築します。 

機能する理由: BFS は、操作数が増加する中で、到達可能なすべての感染状態を調査します。 すべての州について、すべての法的清掃の選択肢が考慮されるため、考えられるすべての戦略がこの検索グラフのパスに対応します。 リーチマスク`0`ウイルスが消滅したことを意味し、ウイルスに到達できないということは有効な戦略が存在しないことを意味します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    adj = [0] * n
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u] |= 1 << v
        adj[v] |= 1 << u

    total = 1 << n

    spread = [0] * total
    for mask in range(total):
        x = mask
        res = 0
        while x:
            b = x & -x
            i = b.bit_length() - 1
            res |= adj[i]
            x -= b
        spread[mask] = res

    parent = [-1] * total
    move = [0] * total

    start = total - 1
    parent[start] = start

    q = deque([start])

    while q:
        cur = q.popleft()
        if cur == 0:
            break

        bits = cur
        while True:
            remain = bits
            cleaned = cur ^ remain
            if cleaned.bit_count() <= k:
                nxt = spread[remain]
                if parent[nxt] == -1:
                    parent[nxt] = cur
                    move[nxt] = cleaned
                    q.append(nxt)

            if bits == 0:
                break
            bits = (bits - 1) & cur

    if parent[0] == -1:
        print(-1)
        return

    ans = []
    cur = 0
    while cur != start:
        mask = move[cur]
        s = ""
        for i in range(n):
            if mask >> i & 1:
                s += chr(ord('a') + i)
        ans.append(s)
        cur = parent[cur]

    ans.reverse()
    print(len(ans))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```各ノードの隣接ノードが単一の整数として格納されるため、隣接マスクにより拡散が非常に高速になります。 の`spread`配列により、BFS 中に同じグラフ操作が再計算されることが回避されます。 

サブセット ループは、標準のサブマスク反復を使用します。```
bits = (bits - 1) & cur
```のすべてのサブセットを訪問します`cur`まさに一度。 変数`remain`は、クリーニング後に生き残った感染ノードを表すため、クリーニングされたセットは次のようになります。`cur ^ remain`。 これにより、ウイルス対策ソフトが既にクリーンなノードを誤ってクリーンアップしてしまうことを防ぎます。 

BFS アレイが使用するのは、`-1`未訪問のマーカーとして。 BFS はプロセスの最初からターゲットを自然に検出するため、親ポインターは逆の順序でシーケンスを再構築します。

 ## 特殊なケース

 1 つのクリーニング スロットを持つ 2 ノード グラフの場合:```
2 1 1
1 2
```BFS はマスクから始まります`11`。 1 つのノードのクリーニングを試行し、マスクに到達します`01`または`10`そして、残りのノードのクリーニングが完了することを発見します。`00`。 すべての遷移には常に拡散ステップが適用されるため、このアルゴリズムでは、クリーン化されたノードがクリーンなままであるとは想定されていません。 

グラフの場合、`k=n`、初期状態には、すべてクリーンアップできるノードが正確に含まれています。 BFS は、生き残ったセットを持つ遷移を見つけます。`0`、そのスプレッド結果も`0`。 これにより、完全なクリーンアップ後に不要なラウンドを強制するというよくある間違いを防ぐことができます。

2 3
3 4
4 5
5 1
```貪欲なアプローチでは、再び感染したノードを繰り返し駆除する可能性があります。 BFS は、完全な状態を検討し、状態がすでに探索されているかどうかのみを考慮するため、これを回避します。
