 ## 解決策
 ## 問題の理解

 この問題は、モールスに似た小さな暗号を記述しています。 暗号書には複数の文字が含まれており、それぞれに最大 5 文字の長さの一意のバイナリ文字列が割り当てられています。 メッセージは別のバイナリ文字列であり、メッセージを指定された文字コードに何通りに分割できるかを決定する必要があります。 その数値に応じて、答えは 3 つの状態のいずれかになります。解釈が存在しない、解釈が 1 つだけ存在する、または複数の解釈が存在します。 複数の場合、解釈の数は 128 を法として出力する必要があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、エンコードされたメッセージの長さ、使用可能な文字の数、文字からバイナリ文字列へのマッピングの辞書、およびデコードが必要な最終的なバイナリ文字列が示されます。 出力には、実際にデコードされたテキストは必要ありません。 可能なデコードの数だけを尋ねます。 

重要な制約がソリューションを形成します。 メッセージの長さは次のとおりです$10^5$、辞書には最大 26 個のコードが含まれており、すべてのコードの長さは最大 5 です。すべての位置がカット ポイントである場合とそうでない場合があるため、考えられるすべての分割を試行するソリューションは指数関数的に増加します。 すべてのコードをすべての位置で比較する動的プログラムであっても、$26 \times 5 \times n$簡単に実現可能な操作です。 

厄介な点は、複数解の場合にのみ、回答数が 128 を法として計算されることです。 よくある間違いは、128 を法とするカウントのみを保存し、それを使用して解が 1 つ存在するかどうかを判断することです。 たとえば、実際のデコード数が 128 の場合、保存される値は 0 ですが、答えはやはり「nonono」ではなく「puppymousecat」になります。 

文字列の解釈が 1 つだけである場合、別の特殊なケースが発生します。 入力の場合:```
1
1 1
A 0
0
```正しい出力は次のとおりです。```
happymorsecode
```モジュロを取得した後にカウントがゼロ以外であるかどうかのみをチェックする不用意な実装は、多くの解釈が 128 を法としてゼロに崩壊する場合に失敗します。 

2 番目のエッジ ケースは、まったく分割できないメッセージです。 入力の場合:```
1
1 1
A 0
1
```正しい出力は次のとおりです。```
nonono
```有効な方法の 1 つとして空のプレフィックスを初期化することを忘れた遷移ベースの DP は、到達可能な状態がないと誤って報告します。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての次の文字を再帰的に試すことです。 すべての位置ですべての辞書エントリを調べ、コードが残りのサフィックスと一致するたびに続行します。 これは正しいです。すべての有効なデコードが、この再帰における 1 つの選択シーケンスに正確に対応するからです。 ただし、可能な分割位置の数は指数関数的に増加する可能性があります。 長さの文字列$n$まで持つことができます$2^{n-1}$辞書を考慮する前に区切り文字を配置する方法が異なるため、このアプローチはすぐに不可能になります。 

ブルートフォース手法は、同じサフィックスの問題を繰り返し解決するため、失敗します。 最初の数文字が異なる方法でデコードされても、両方が同じ残りの位置に到達する場合、残りの作業は同一です。 重要な点は、文字列内の現在位置のみが重要であるということです。 過去の選択は将来の可能性に影響を与えないため、この問題は接頭辞動的プログラムの構造を持っています。 

状態がプレフィックスのすべてのデコードを表すようにします。 到達可能なすべての位置について、すべてのコードワードを試し、次の文字が一致する場合はプレフィックスを拡張します。 コードワードは非常に短いため、各ポジションの作業量は一定です。 

2 番目の観察は、数を数えるということです。 2 つの情報が必要です。128 を法とするカウントと、実際のカウントが少なくとも 2 に達しているかどうかです。 モジュロ値のみを保持すると、128、256、およびその他の多くのカウントがすべてゼロになるため、情報が失われます。 これら 2 つのプロパティを個別に維持するだけで、必要な 3 つの出力を区別できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(26 * 5 * n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 暗号本からすべてのモールス信号文字列を保存します。 出力は選択された文字ではなく、考えられる解釈の数に依存するため、コード自体が必要になるだけです。 
2. プレフィックスの動的プログラミング配列を作成します。 すべての位置について、その位置に到達する方法の数を 128 を法にして格納し、その位置に到達する実際の方法の数が少なくとも 2 つであるかどうかを示すブール値を保存します。 
3. 空のプレフィックスを 1 つの有効なデコードとして初期化します。 空の文字列は、文字が選択される前の開始点を表します。 
4. すべての位置を左から右に処理します。 位置が到達可能な場合は、辞書内のすべてのコードを試してください。 コードがこの位置から始まる部分文字列に一致する場合、現在位置のウェイを目的の位置に追加します。 
5. 宛先を更新する場合、モジュロカウントは通常通り更新しますが、複数フラグは独立して更新します。 multiple フラグは、目的地にすでにウェイがあり、新しいウェイが到着する場合、またはソースの位置がすでに複数のウェイを表している場合に true になります。 
6. 文字列全体を処理した後、最終位置を検査します。 方法がない場合は印刷してください`nonono`。 方法が 1 つしかない場合は、印刷します`happymorsecode`。 それ以外の場合は印刷します`puppymousecat`128 を法とするウェイの数。 

これが機能する理由: プレフィックスのすべてのデコードは正確に 1 つの位置で終了し、有効な次の文字ごとに後のプレフィックスへの遷移が 1 つだけ作成されます。 DP は考えられるすべての遷移を考慮し、以前の有効な分割を表す状態のみを結合します。 不変条件は、処理後の位置です。$i$、で終わるすべてのプレフィックスの保存情報$i$は、そのプレフィックスの可能なすべてのデコードを正確に表します。 最終位置には文字列全体の完全なデコードがすべて含まれるため、最終状態によって必要な分類が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    n, m = map(int, input().split())
    codes = []
    for _ in range(m):
        _, t = input().split()
        codes.append(t)
    s = input().strip()

    mod = [0] * (n + 1)
    many = [False] * (n + 1)

    mod[0] = 1

    def positive(i):
        return mod[i] != 0 or many[i]

    for i in range(n):
        if not positive(i):
            continue
        for c in codes:
            j = i + len(c)
            if j <= n and s.startswith(c, i):
                if positive(j):
                    if positive(i):
                        many[j] = True
                if many[i]:
                    many[j] = True
                mod[j] = (mod[j] + mod[i]) % 128

    if not positive(n):
        return "nonono"
    if not many[n] and mod[n] == 1:
        return "happymorsecode"
    return f"puppymousecat {mod[n]}"

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        ans.append(solve_case())
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```コードは 2 つの並行した情報を保持します。 の`mod`配列には、必要なモジュロ演算を適用した後のカウントが格納されます。 の`many`配列には、モジュロカウントからは回復できない情報、つまり、真のカウントがすでに少なくとも 2 であるかどうかが格納されます。 

ヘルパー関数`positive`状態が少なくとも 1 つのデコードを表しているかどうかをチェックします。 州は次のことを行う可能性があります`mod[i] == 0`ただし、実際の数は 128 または 128 の倍数である可能性があるため、到達可能です。この区別により、最も一般的な誤った答えが防止されます。 

移行では、`startswith`既知の短いコード長を持つ。 すべてのコードの長さは最大 5 であるため、このチェックは一定時間行われます。 文字列境界をチェックする前に宛先インデックスが計算されるため、無効なアクセスが防止されます。 

初期化`mod[0] = 1`文字を読み取る前の単一の空のデコードを表します。 それがなければ、他の状態に到達することはできません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26 * 5 * n) | 各位置は最大 26 個のコードをチェックし、各コードの長さは最大 5 です。 
| スペース | O(n) | 長さ n + 1 の 2 つの配列にプレフィックスの状態が格納されます。 |

 すべてのテスト ケースの合計メッセージ長は次のとおりです。$10^5$したがって、線形動的計画法のアプローチは簡単に制限内に収まります。 このアルゴリズムは再帰の深さの問題を回避し、可能な解釈の数に依存しません。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        out = io.StringIO()
        sys.stdout = out

        t = int(input())
        ans = []

        for _ in range(t):
            n, m = map(int, input().split())
            codes = []
            for _ in range(m):
                _, x = input().split()
                codes.append(x)
            s = input().strip()

            mod = [0] * (n + 1)
            many = [False] * (n + 1)
            mod[0] = 1

            def positive(i):
                return mod[i] != 0 or many[i]

            for i in range(n):
                if not positive(i):
                    continue
                for c in codes:
                    j = i + len(c)
                    if j <= n and s.startswith(c, i):
                        if positive(j) and positive(i):
                            many[j] = True
                        if many[i]:
                            many[j] = True
                        mod[j] = (mod[j] + mod[i]) % 128

            if not positive(n):
                ans.append("nonono")
            elif not many[n] and mod[n] == 1:
                ans.append("happymorsecode")
            else:
                ans.append(f"puppymousecat {mod[n]}")

        return "\n".join(ans)
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 カウントが 128 の倍数の場合、アルゴリズムは引き続き機能します。`many`flag は、モジュロ値とは別に情報を格納します。 メッセージは次で終わる場合があります`mod[n] = 0`、しかし、もし`many[n]`確かに、依然として複数の解釈があるものとして正しく分類されています。 

可能な分割が 1 つだけのメッセージの場合、すべての遷移は 2 番目の解釈を引き起こすことなく同じパスに寄与します。 最終状態は維持されます`many[n]`偽と`mod[n]`1 に等しいため、`happymorsecode`。 

不可能なメッセージの場合、最終位置に到達する遷移はありません。 最初の空のプレフィックスが到達可能な唯一の状態であるため、最終状態は空のままで、アルゴリズムは次のように出力します。`nonono`。 

重複するコードの場合`0`そして`00`、異なる前の位置から同じ終了位置に到達することができます。 更新ルールは、別の解釈が到着したときに、宛先にすでに 1 つの解釈があることを検出し、それを複数としてマークします。 これは、個別の一意性追跡が必要な状況です。
