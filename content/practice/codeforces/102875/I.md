 ## 解決策
 # 問題の理解

 都市は長方形の格子状の交差点です。 すべての交差点には独自の信号パターンがあり、反復サイクルの一部では行に沿った移動が可能で、残りの部分では列に沿った移動が可能です。 道路に沿って移動するにも一定時間がかかります。 時刻 0 の 1 つの交差点から開始して、別の交差点にできるだけ早く到着する時間が必要です。 入力は、グリッドの寸法、開始位置と目標位置、すべての交差点のタイミング パラメーター、およびすべての水平および垂直道路の長さを記述します。 出力は最小到着時間です。 

グリッドには最大 500 × 500 の交差を含めることができるため、頂点は 250,000 個存在する可能性があります。 多くの可能な待機選択肢を検討したり、時間を繰り返しシミュレーションしたりするソリューションは、すぐに不可能になってしまいます。 数十万のノードと 1 秒の制限があるため、交差点の数は線形演算に近いものが必要です。 道路の数は交差点の数の約 2 倍しかないため、効率的な優先キューを備えたダイクストラなどの通常のグラフ アルゴリズムが適切です。 

主なトラップは、時間依存の移動ルールから発生します。 現在時刻は交差点に到着するときではなく、交差点を出るときに重要になります。 たとえば、最初の 5 秒間は水平方向の移動が許可され、次の 5 秒間は垂直方向の移動が許可され、道路の所要時間は 3 秒である 1 つの交差点について考えてみましょう。```
a = 5, b = 5
current time = 6
```不注意な実装では、交差状態を 1 回しかチェックしないため、すぐに水平方向に移動しようとする可能性があります。 正しい動作は、時間 10 まで待機し、その後水平に移動して時間 13 に到着することです。 

別の間違いは、現在時刻がちょうど位相の境界にある場合に発生します。 水平間隔が`[0,5)`そして垂直間隔は`[5,10)`の場合、時間 5 は水平方向の動きではなく、垂直方向の動きに属します。 区間の両端が閉じているものとして扱うと、誤った答えが生じます。 

最後のエッジ ケースは、ターゲットまたは孤立したタイミング境界で待機しています。 最善の経路には、道路がすぐに存在する場合でも、意図的に待つことが含まれる場合があります。 たとえば、垂直フェーズが終了する 1 秒前に垂直交差点に到達すると、後でさらに完全なサイクルが強制される場合、別のエッジに入る前に待機すると、最適な状態が得られます。 

## アプローチ

 直接的なアプローチは、グリッドをグラフとして扱い、到達したすべての交差点から可能なすべてのアクションをシミュレートしようとすることです。 状態ごとに現在時刻を保存し、移動するか待機するかを繰り返し選択できます。 これは実際のルールに従っているため正しいですが、可能な待機時間の数には制限がありません。 サイクル値が大きいと、このアプローチで膨大な数の不必要な状態を探索する可能性があります。 

有益な観察は、待機をアクションとして表す必要がないということです。 交差点に最も早く到着する時刻がわかれば、隣接するすべての道路の最も早い出発時刻を数学的に計算できます。 各交差点には、同じ長さの繰り返しサイクルがあります。`a + b`。 そのサイクル内の現在時間の残りによって、すぐに出発できるかどうか、またはどれくらい待つ必要があるかがわかります。 

この問題は、時間依存のエッジ重みをもつグラフ上の最短経路問題になります。 ダイクストラは依然として機能します。なぜなら、後で出発することは、利用可能な最も早い時間に出発することよりも同じエッジを通って早く到着することを決して生み出さないからです。 ノードが優先キューから抽出されると、通常のダイクストラとまったく同様に、その格納された距離が最終的なものとなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 待機状態が繰り返されるため無制限 | 大 | 遅すぎる |
 | 最適 | O(nm log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての交差点の既知の最も早い到着時刻を保存します。 最初は、時間ゼロの開始交差点を除き、すべての値が無限大です。 スタートを優先キューにプッシュします。 
2. 既知の到着時間が最小の交差点を繰り返し削除します。 この時間が保存された距離よりも古い場合は、より適切なパスがすでに見つかっているため、無視してください。 
3. 隣接するすべての交差点について、その道路に沿って歩き始めることができる最も早い時間を計算します。 水平方向の移動には現在の交差点が水平フェーズにある必要があり、垂直方向の移動には垂直フェーズが必要です。 
4. 出発時刻に道路の長さを加算します。 この新しい到着時間がネイバーの最良の既知の値を改善する場合は、それを更新し、ネイバーを優先キューにプッシュします。 
5. ターゲット交差点が優先キューから削除されるまで続行します。 その時点では飛距離は伸びない、それが答えだ。 

機能する理由: ダイクストラは、最初にノードを永続的に選択すると、その後のパスによってそのノードが改善されないという事実に依存しています。 ここで、すべてのエッジは、現在の到着時間のみに基づいて決定的な最も早い到着時間を持ちます。 同じエッジを取る前に長く待っても、最も早い有効な瞬間にエッジを取ることに比べれば、決して役に立ちません。 したがって、すべての遷移は通常の非負の重み付きエッジのように動作し、標準のダイクストラの正当性の議論が適用されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, xs, ys, xt, yt = map(int, input().split())
    xs -= 1
    ys -= 1
    xt -= 1
    yt -= 1

    a = [list(map(int, input().split())) for _ in range(n)]
    b = [list(map(int, input().split())) for _ in range(n)]

    c = [list(map(int, input().split())) for _ in range(n)]
    w = [list(map(int, input().split())) for _ in range(n - 1)]

    total = n * m
    inf = 10**30
    dist = [inf] * total

    def node_id(x, y):
        return x * m + y

    start = node_id(xs, ys)
    target = node_id(xt, yt)

    dist[start] = 0
    pq = [(0, xs, ys)]

    while pq:
        t, x, y = heapq.heappop(pq)

        if t != dist[node_id(x, y)]:
            continue

        if x == xt and y == yt:
            print(t)
            return

        cycle = a[x][y] + b[x][y]
        rem = t % cycle

        if y > 0:
            depart = t if rem < a[x][y] else t + cycle - rem
            nt = depart + c[x][y]
            idx = node_id(x, y - 1)
            if nt < dist[idx]:
                dist[idx] = nt
                heapq.heappush(pq, (nt, x, y - 1))

        if y + 1 < m:
            depart = t if rem < a[x][y] else t + cycle - rem
            nt = depart + c[x][y]
            idx = node_id(x, y + 1)
            if nt < dist[idx]:
                dist[idx] = nt
                heapq.heappush(pq, (nt, x, y + 1))

        if x > 0:
            depart = t if rem >= a[x][y] else t + a[x][y] - rem
            nt = depart + w[x - 1][y]
            idx = node_id(x - 1, y)
            if nt < dist[idx]:
                dist[idx] = nt
                heapq.heappush(pq, (nt, x - 1, y))

        if x + 1 < n:
            depart = t if rem >= a[x][y] else t + a[x][y] - rem
            nt = depart + w[x][y]
            idx = node_id(x + 1, y)
            if nt < dist[idx]:
                dist[idx] = nt
                heapq.heappush(pq, (nt, x + 1, y))

if __name__ == "__main__":
    solve()
```配列`a`そして`b`各交差点のサイクルの 2 つのフェーズを保存します。 水平方向の道路と垂直方向の道路は形状が異なるため、道路配列は別々に保存されます。 

の`depart`計算はソリューションの核心です。 水平移動の場合、有効な間隔は各サイクルの開始時に始まり、継続します。`a[x][y]`単位。 残りがすでにこの間隔内にある場合は、すぐに出発します。 それ以外の場合、アルゴリズムは次のサイクルが開始されるまで待機します。 垂直方向の移動には補完的な間隔が使用されます。 

優先キューには到着候補が格納されます。 古いエントリのチェックが必要なのは、Python のヒープがキーの減少をサポートしていないため、改善後も古い値が残るためです。 すべての時間は Python 整数として保存されるため、入力値が大きくてもオーバーフローが回避されます。

 ## 特殊なケース

 現在時刻がまさに垂直フェーズの開始時である場合、水平移動は次のサイクルまで待機する必要があります。 アルゴリズムは次のことをチェックするため、これを処理します。`rem < a`水平移動の場合は、半開区間の定義に一致します。 

スタートとターゲットが待機を必要とするパスで接続されている場合、アルゴリズムは人為的な待機状態を作成しません。 代わりに、待ち時間はエッジ緩和式に直接含まれるため、優先キューには意味のある到着時間のみが含まれます。 

多くの交差点を含むパスを通ってターゲットに到達する場合でも、すべての交差点は、考えられるすべての短い到着時間がすでに処理された後にのみ確定されるため、アルゴリズムは依然として正しく動作します。 道路の時間依存の性質により、緩和公式は変化しますが、最短経路の不変式は変化しません。
