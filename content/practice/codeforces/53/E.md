 ## 解決策
 ## 問題の理解

 ジャンクション間の道路を表す無向接続グラフが与えられます。 市長は、残りのグラフがツリーになるように、いくつかの道路を削除したいと考えています。つまり、グラフは接続されたままで、正確な内容が含まれます。`n - 1`エッジ。 このようなすべてのスパニング ツリーの中で、正確に含まれるスパニング ツリーのみを考慮します。`k`葉。 リーフは、ツリー内の次数が次と等しい頂点です。`1`。 

タスクは、元のグラフのスパニング ツリーの数を正確に数えることです。`k`葉。 

グラフは非常に小さく、最大で`10`頂点。 これは、サブセットに対する指数関数的アルゴリズムが可能であることを直ちに示唆しています。 周囲の状態空間`2^10 = 1024`小さいです。 平`3^10`または`10 * 2^10 * 2^10`スタイルの動的プログラミングは快適にフィットします。 

問題は接続チェック自体ではありません。 本当の課題は、リーフの数が最終的な次数の分布に依存するため、同時に頂点次数を追跡しながらスパニング ツリーをカウントすることです。 

単純な解決策では、次のすべてのサブセットを列挙します。`n - 1`エッジを確認し、正確にスパニング ツリーを形成しているかどうかを確認します。`k`葉。 問題は、グラフに次のものが含まれる可能性があることです。`45`エッジ。 サブセットの数は次のようになります。$$\binom{45}{9} \approx 8.8 \times 10^8$$制限時間内では絶対に無理です。 

不注意な解決策を破る微妙なケースがいくつかあります。 

グラフ自体がすでにツリーになっていると仮定します。```
4 3 3
1 2
2 3
2 4
```スパニング ツリーは 1 つだけ (グラフ自体) あり、ちょうど 3 つの葉があります。 正しい答えは、`1`。 すべての頂点がリーフとして開始され、後でエッジが追加されるときにリーフが削除されると想定するバグのある実装では、中心頂点のカウントを簡単に間違える可能性があります。 

もう一つの危険なケースは自転車です。```
4 4 2
1 2
2 3
3 4
4 1
```サイクルのすべてのスパニング ツリーはパスであり、4 つの頂点上のすべてのパスにはちょうど 2 つの葉があります。 正しい答えは、`4`なぜなら、いずれかのエッジを削除すると有効なツリーが得られるからです。 接続の処理が間違っていると、切断されたフォレストがカウントされやすくなります。 

3 番目の落とし穴は、ツリーを段階的に構築するときに発生します。 考慮する：```
5 6 2
1 2
1 3
1 4
1 5
2 3
4 5
```スパニング ツリーには構築中に一時的に多くの葉が含まれることがありますが、将来エッジが追加されると、それらの葉の一部が消えます。 貪欲にリーフ数を修正するのが早すぎる DP は失敗します。 

中心的な問題は、次数情報が最終的なのはツリー全体が構築された後でしかないということです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 サイズのエッジのすべてのサブセットを試します`n - 1`。 サブセットごとに、接続されたグラフを形成しているかどうかを確認します。 接続されたグラフなので、`n - 1`エッジは自動的にツリーになります。次に、次数を持つ頂点の数を数えます。`1`。 そのカウントが等しい場合`k`、答えに1を追加します。 

これが機能するのは、スパニング ツリーの定義の検証が簡単であるためです。 問題はサブセットの数です。 最悪の場合に私たちが選択するのは、`9`端から出ている`45`これは、接続チェックを実行する前に、ほぼ 10 億の組み合わせになります。 

の小さな値`n`エッジではなく頂点が状態表現の中心であるべきであることを示唆しています。 ツリーには非常に便利な特性があります。ツリーをどこかにルートして頂点を 1 つずつ表示すると、新しく追加された頂点はすべて 1 つのエッジを介してすでに構築された部分に接続されます。 

この観察により、問題はサブセット DP に変換されます。 

接続された誘導構造を段階的に構築します。 私たちは常に次のことを維持します。 

- 現在の接続コンポーネント内に既に存在する頂点、
 - 現在葉であるという点で奇妙なステータスを持っている頂点はどれですか、
 - すでに内部頂点になっている頂点の数。 

重要なトリックは、ツリーを一度に 1 エッジずつ成長させながら、ビットマスクを使用して次数パリティをエンコードすることです。 新しい頂点をアタッチするたびに`v`既存の頂点に`u`:

 -`v`学位から始まります`1`、葉になるので、
 -`u`追加の学位を 1 つ獲得するため、そのリーフ/内部ステータスが変更される可能性があります。 

このローカル更新はまさに動的プログラミングを可能にするものです。 

同じツリーを何度もカウントすることを避ける標準的な方法は、すべてのツリーを最小番号の頂点にルートし、より大きな頂点を追加する遷移のみを許可することです。 この正規の順序付けにより、重複が自動的に削除されます。 

結果の DP はおおよそ次のようになります。$$2^n \times 2^n$$州としては小さいですが、`n ≤ 10`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O\left(\binom{m}{n-1} \cdot (n+m)\right)$|$O(n+m)$| 遅すぎる |
 | 最適 |$O(3^n \cdot n^2)$|$O(2^n \cdot n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 根を張った木を成長させる古典的な接続されたサブセット DP を使用します。 

させて`dp[mask][leafMask]`頂点セットが次のような異なる木の数を示します。`mask`、現在の葉はまさに内部の頂点です`leafMask`。 

頂点が属する`leafMask`現在の学位が等しい場合`1`。 

### 1. 考えられるすべてのルートから開始します

 頂点ごとに`r`、初期化します:```
dp[1 << r][0] = 1
```単一の孤立した頂点には次数があります`0`、程度ではありません`1`, つまり、まだ葉ではありません。 

私たちもそれを強制します`r`は、最終的なツリーの最小の頂点です。 後のトランジションでは、より大きい頂点のみが追加されます。`r`。 これにより、異なるルートから同じツリーを複数回カウントすることがなくなります。 

### 2. 接続されたサブセットを展開する

 現在のサブセットごとに`mask`、新しい頂点を追加してみてください`v`中にはいない`mask`。 

新しい頂点は何らかのエッジを介して接続する必要があります`(u, v)`どこ`u`すでに所属している`mask`。 

これにより、接続が自動的に維持されます。 

### 3. リーフセットを更新する

 取り付けるとき`v`に`u`:

 -`v`学位を取得する`1`、葉になるので、
 -`u`によって次数が増加します`1`。 

への影響`u`古い学位カテゴリによって異なります。 

もし`u`以前は葉ではありませんでしたが、エッジを 1 つ追加した後でも葉ではありません。 

もし`u`以前は葉でしたが、その次数は次のように変化します。`1`に`2`、それで葉ではなくなります。 

この更新はすべてビット演算で表現できます。 

### 4. 新しい状態への移行

 構築:```
newMask = mask | (1 << v)
```次に変更します`leafMask`:

 - トグル`u`以前は葉っぱだった場合、
 - 追加`v`葉として。 

DP 値を新しい状態に追加します。 

### 5. フルマスクで終了

 すべてのサブセットを処理した後、すべてのスパニング ツリーが 1 回だけ表示されます。 

すべての州について:```
mask == (1 << n) - 1
```次の場合にカウントします。```
popcount(leafMask) == k
```そのようなすべての状態の合計が答えになります。 

### なぜ効果があるのか

 遷移ごとに、新しい頂点を 1 つだけ追加し、それを既存の接続コンポーネントに接続する新しいエッジを 1 つだけ追加します。 単一の頂点から開始してこのプロセスを繰り返すと、常にツリーが生成されます。 

逆に、最大の非ルート頂点を繰り返し削除することで、すべてのルート ツリーを一意に再構築できます。 つまり、すべての有効なスパニング ツリーが 1 つの DP 遷移シーケンスに正確に対応します。 

遷移中に変更される頂点次数は親のみであるため、リーフ マスクは正しいままです。`u`そして新しくアタッチされた頂点`v`。 他のすべての頂点は同じ次数を維持します。 更新ルールは、ツリー次数の進化方法と正確に一致します。 

すべてのスパニング ツリーは一度だけ生成され、正確に一致するものだけをカウントするため、`k`葉、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    adj = [[False] * n for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u][v] = True
        adj[v][u] = True

    FULL = (1 << n) - 1

    ans = 0

    for root in range(n):
        dp = [[0] * (1 << n) for _ in range(1 << n)]

        dp[1 << root][0] = 1

        for mask in range(1 << n):
            if not (mask & (1 << root)):
                continue

            for leaf_mask in range(1 << n):
                cur = dp[mask][leaf_mask]

                if cur == 0:
                    continue

                for v in range(root + 1, n):
                    if mask & (1 << v):
                        continue

                    for u in range(n):
                        if not (mask & (1 << u)):
                            continue

                        if not adj[u][v]:
                            continue

                        new_mask = mask | (1 << v)

                        new_leaf = leaf_mask

                        if leaf_mask & (1 << u):
                            new_leaf ^= (1 << u)

                        new_leaf |= (1 << v)

                        dp[new_mask][new_leaf] += cur

        for leaf_mask in range(1 << n):
            if leaf_mask.bit_count() == k:
                ans += dp[FULL][leaf_mask]

    print(ans)

solve()
```隣接行列により、エッジの存在チェックが一定時間行われます。 以来`n`だけです`10`、これは、この DP の隣接リストよりも単純で高速です。 

外側のループはツリーの最小頂点を固定します。 これが重要な重複削除のトリックです。 ルート処理時`r`より大きいインデックスを持つ頂点のみを追加します。`r`。 すべてのスパニング ツリーには最小の頂点が 1 つだけあるため、すべてのツリーは 1 回だけカウントされます。 

DP 状態には、現在の頂点セットと正確な葉のセットの両方が保存されます。 よくある間違いは、リーフの数だけを保存しようとすることです。 これは、頂点が後で別のエッジを受け取ると、リーフではなくなる可能性があるため、失敗します。 アルゴリズムは、現在どの頂点に次数があるかを正確に知る必要があります。`1`。 

移行ロジックは微妙です。 新しく追加された頂点は次数が正確であるため、常にリーフになります。`1`。 以前に次数を持っていた場合、親頂点はリーフ ステータスを失う可能性があります`1`。 XOR を使用して削除する`u`リーフセットからは、次の場合にのみ実行するため便利です。`u`すでにリーフマスクの中にあります。 

次の理由により、メモリ使用量は少ないままです。$$2^{10} \times 2^{10} = 1,048,576$$これは Python のメモリに簡単に収まります。
