 ## 解決策
 ## 問題の理解

 私たちは持っています`n`直線上の位置に置かれた塚`1, 2, ..., n`。 カエルはすべての塚を 1 回だけ訪問したいと考えているため、これらの位置の順列を出力する必要があります。 

興味深い制限はジャンプにあります。 カエルが順番に塚を訪れるなら`p1, p2, ..., pn`の場合、ジャンプの長さは次のようになります。$$|p_1 - p_2|,\ |p_2 - p_3|,\ \dots,\ |p_{n-1} - p_n|$$これらの距離はすべて異なる必要があります。 

入力には整数が 1 つだけ含まれています。`n`有効な訪問順序を作成する必要があります。 

制約は非常に小さいです。 たとえ`O(n^2)`検証ステップは簡単に制限内に収まります。`n ≤ 10^4`。 重要なのは、常に機能する建設的なパターンを見つけることです。 順列の徹底的な検索は完全に不可能です。`n!`爆発的に成長します。 たとえ`n = 12`、すでに何億もの順列が存在します。 

難しい部分は、一部のジャンプ長が後で繰り返されるため、ローカルではルートが有効であるように見えても、グローバルでは失敗する可能性があることです。 

たとえば、次のことを考えてみましょう。```
1 3 2 4
```ジャンプの長さは次のとおりです。```
2, 1, 2
```距離`2`が 2 回表示されるため、このルートは無効です。 

もう 1 つの簡単な間違いは、距離を連続的に増加させると自動的に機能すると仮定することです。 のために`n = 5`、シーケンス:```
1 5 2 4 3
```ジャンプを生成します:```
4, 3, 2, 1
```これは有効ですが、小さな変更を加えるとすぐに壊れてしまいます。 例えば：```
1 4 2 5 3
```与える:```
3, 2, 3, 2
```2 つの距離が繰り返し表示されます。 

最小値にも注目する必要があります。 

のために`n = 1`、ジャンプがまったくないので、単一のマウンドが機能します。 

のために`n = 2`、ジャンプは 1 つだけあり、自動的に一意になります。 

建設的なアルゴリズムは、特別なハックをせずに、これらの境界ケースを自然に処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、次の順列が生成されます。`1..n`すべてのジャンプの長さが異なるかどうかをテストします。 

正しさは明らかです。 最終的に、連続する絶対差がすべて異なる順列を見つけた場合、問題は直接満たされます。 

問題は検索スペースです。 がある`n!`順列。 たとえ 1 つの順列をチェックするだけで済むとしても、`O(n)`、全体の複雑さは次のようになります。$$O(n \cdot n!)$$これはすぐに使用できなくなります。 のために`n = 15`、順列の数はすでに 1 兆を超えています。 

重要な観察は、ジャンプの長さはすべて異なる必要があり、正確に`n - 1`ジャンプします。 唯一可能な個別のジャンプ長は次のとおりです。$$1, 2, 3, \dots, n-1$$したがって、有効な構築では、可能なすべての距離を 1 回だけ使用する必要があります。 

これは、ジャンプが制御された方法で減少するようにシーケンスを構築することを強く示唆しています。$$n-1,\ n-2,\ n-3,\ \dots,\ 1$$これを達成するための非常に自然な方法は、最小の未使用ポジションと最大の未使用ポジションを交互に使用することです。 

たとえば、`n = 7`:```
1 7 2 6 3 5 4
```ジャンプの長さは次のようになります。```
6, 5, 4, 3, 2, 1
```すべての距離は 1 回だけ表示されます。 

なぜこの交互パターンが機能するのでしょうか? 残りの間隔の一方の端からもう一方の端に移動するたびに、間隔が 1 つずつ縮むからです。 最初のジャンプはほぼ​​配列全体に広がり、次のジャンプは 1 つ少ない範囲に広がります。 

これにより、問題が不可能な順列検索から直接的な建設的な解決策に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot n!)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインターから始めます。`left = 1`そして`right = n`。 

これらは、最小および最大の未使用マウンド位置を表します。 
2. 空の応答配列を作成します。 
3. その間`left <= right`、位置を交互に追加します。 

最初の追加`left`、その後増加します`left`。 

その後、まだ未使用のポジションがある場合は追加します。`right`、その後減少します`right`。 
4. すべての位置が 1 回だけ使用されるまで続けます。 

たとえば、次のようなとき`n = 6`:

 1.追加`1`2.追加`6`3.追加`2`4.追加`5`5.追加`3`6.追加`4`シーケンスは次のようになります。```
1 6 2 5 3 4
```ジャンプの長さは次のとおりです。```
5, 4, 3, 2, 1
```各ジャンプは前のジャンプより 1 つ小さくなります。 

### なぜ効果があるのか

 各ステップで、シーケンスは残りの未使用間隔の両端間をジャンプします。 

残りの間隔が`[L, R]`。 

When we move from one side to the other, the jump length is:$$R - L$$1 つのエンドポイントを使用すると、間隔が 1 つ縮小するため、次のジャンプは次のようになります。$$(R - L) - 1$$これは間隔が崩れるまで続きます。 

生成されるジャンプの長さは正確に次のとおりです。$$n-1,\ n-2,\ \dots,\ 1$$すべては個別であり、各ポジションは追加直後に考慮から削除されるため、すべてのマウンドは 1 回だけ使用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

left = 1
right = n

ans = []

while left <= right:
    ans.append(left)
    left += 1

    if left <= right:
        ans.append(right)
        right -= 1

print(*ans)
```実装は構築の後に直接続きます。`left`未使用の最小のマウンドを追跡し、`right`未使用の最大の塚を追跡します。 各反復では、左側から 1 つの値、右側から 1 つの値が追加されます。 

条件`if left <= right`重要なとき`n`奇数です。 これがないと、中央の要素が 2 回追加されてしまいます。 

たとえば、`n = 5`、挿入後:```
1 5 2 4
```両方のポインタは次のようになります`3`。 追加する必要があります`3`まさに一度。 

構造が設計により正確性を保証しているため、アルゴリズムはジャンプ長を明示的に計算する必要はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())

    left = 1
    right = n

    ans = []

    while left <= right:
        ans.append(left)
        left += 1

        if left <= right:
            ans.append(right)
            right -= 1

    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("2\n") == "1 2\n", "sample 1"

# minimum size
assert run("1\n") == "1\n", "n = 1"

# odd n
assert run("5\n") == "1 5 2 4 3\n", "odd length construction"

# even n
assert run("6\n") == "1 6 2 5 3 4\n", "even length construction"

# larger case
out = run("10\n").strip().split()
arr = list(map(int, out))

assert sorted(arr) == list(range(1, 11)), "must be a permutation"

diffs = [abs(arr[i] - arr[i + 1]) for i in range(9)]
assert len(set(diffs)) == 9, "all jump lengths must be unique"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`1`| 空のジャンプ セットを正しく処理します。 
|`5`|`1 5 2 4 3`| 異形のサイズの建設 |
 |`6`|`1 6 2 5 3 4`| 均等なサイズの構造 |
 |`10`| 任意の有効な置換 | 一般的な正確性と固有の距離 |

 ## 特殊なケース

 のために`n = 1`、入力は次のとおりです。```
1
```アルゴリズムは次から始まります`left = right = 1`。 

追加します`1`、増分`left`に`2`、そして停止します。`left > right`。 

出力は次のとおりです。```
1
```ジャンプがないため、一意性条件は空虚に満たされます。 

のために`n = 2`、アルゴリズムは次を生成します。```
1 2
```唯一のジャンプの長さは次のとおりです。```
|1 - 2| = 1
```ジャンプは 1 つだけであるため、重複はできません。 

次のような奇数の値の場合`n = 5`、真ん中の位置が危険な部分です。 

この構造により次のことが得られます。```
1 5 2 4 3
```ジャンプは次のとおりです。```
4, 3, 2, 1
```中心値`3`次の条件により、 は 1 回だけ表示されます。```
if left <= right:
```この条件がないと、中央の要素が 2 回挿入され、置換要件が破られてしまいます。 

より大きな偶数値の場合、`n = 8`、アルゴリズムは次のように出力します。```
1 8 2 7 3 6 4 5
```ジャンプは次のとおりです。```
7, 6, 5, 4, 3, 2, 1
```これは、すべての新しいジャンプがちょうど 1 だけ減少するという不変条件を裏付けます。
