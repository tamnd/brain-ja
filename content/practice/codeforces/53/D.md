 ## 解決策
 ## 問題の理解

 一列に並んだ生徒の順序を表す 2 つの配列があります。 配列`a`は目的の配置であり、配列です`b`が現在の配置です。 1 回の操作で、隣り合う 2 人の生徒を交換することができます。 変換する隣接するスワップのシーケンスを出力する必要があります。`b`の中へ`a`。 

難しいのは、高さが必ずしも一意ではないということです。 2 人の生徒の身長が同じである可能性があるため、どの出現がどの位置に対応するかを考えずに単純に値を一致させることはできません。 

制約は二次アルゴリズムを許可するのに十分小さいものです。 以来`n ≤ 300`、たとえ`O(n^2)`または`O(n^3)`ソリューションは制限内に簡単に収まります。 ある順列を別の順列に変換するために必要な隣接するスワップの最大数は、`n(n-1)/2`、これは`n = 300`等しい`44850`、許容値をはるかに下回ります`10^6`操作。 

不用意に実装すると、重複した値が存在すると失敗する可能性があります。 考慮する：```
a = [1, 2, 1]
b = [1, 1, 2]
```貪欲に最初に合わせると`1`で`a`最初のものと`1`で`b`、それでいいです。 しかし、後で検索を誤ると、間違った箇所が移動して、すでに固定されていた位置が壊れてしまう可能性があります。 

もう 1 つの微妙なケースは、目的の値が配列の前の方にすでに存在している場合に発生します。```
a = [2, 1, 2]
b = [2, 2, 1]
```位置を固定する場合`2`、固定されていないサフィックス内でのみ検索する必要があります。 そうしないと、すでに正しい最初の位置を誤って乱してしまう可能性があります。 

最小のケースも重要です。```
n = 1
a = [5]
b = [5]
```答えにはスワップが含まれていない必要があります。 一部の実装では、これを処理することを忘れて、無効な隣接操作を試行します。 

## アプローチ

 最も直接的なアイデアは総当たりシミュレーションです。 あらゆるポジションについて`i`、私たちは配置しようとします`a[i]`配列内のその位置に`b`。 最初に出現するものを検索します`a[i]`右のどこかに移動し、所定の位置に到達するまで繰り返し左に入れ替えます`i`。 

これが機能するのは、隣接するスワップによって要素を段階的に移動できるためです。 1回の位置`i`正しい値が含まれているため、二度と触れることはありません。 

最悪の場合のスワップの総数は 2 次です。 たとえば、個別の値の配列を反転するには、約`n^2 / 2`交換します。 と`n = 300`、これは完全に安全です。 

より素朴な総当たりアプローチでは、アレイ全体を繰り返しスキャンして不一致を探し、ランダムなローカル修正を実行します。 すべての修正でもう一度完全なスキャンが必要になる可能性があるため、3 次の複雑さまで低下する可能性があります。 と`n = 300`、それでもまだ合格するかもしれませんが、不必要に乱雑であり、推論するのがはるかに困難です。 

重要な観察は、隣接するスワップが自然に左から右への固定プロセスをサポートするということです。 位置に正しい値を配置したら`i`、後の操作は右側でのみ発生します。`i`, そのため、プレフィックスは永続的に正しいままになります。 

これにより、クリーンな貪欲アルゴリズムが得られます。 

1. 位置を左から右に処理します。 
2. サフィックスのどこかで必要な値を見つけます。 
3. 隣接するスワップを使用して左にバブルします。 

すべての操作で固定プレフィックスが厳密に改善されるため、アルゴリズムは常に終了します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ランダムな総当たり修正 | O(n3) | お(1) | 不必要に遅い |
 | 貪欲な隣接バブル | O(n²) | O(1) 回答ストレージを除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の位置から開始して、配列内を左から右に移動します。 
2. ポジションについて`i`、どうかを確認してください`b[i]`すでに等しい`a[i]`。 
3. 値がすでに正しい場合は、次の位置に進みます。 
4. それ以外の場合は、最初のインデックスを検索します`j ≥ i`そのような`b[j] == a[i]`。 

より前に位置するため、サフィックスのみで検索します。`i`はすでに修正されており、再度変更することはできません。 
5. 要素を位置に移動します`j`向かって`i`隣接スワップを使用します。 

あらゆるポジションについて`k`から`j-1`まで`i`:

 - スワップ`b[k]`そして`b[k+1]`- 操作を記録する`(k+1, k+2)`1 から始まるインデックス付け
 6. これらの交換の後、位置を変更します。`i`今は含まれています`a[i]`。 
7. すべての位置が固定されるまで続けます。 

### なぜ効果があるのか

 加工後の位置`i`、接頭辞`b[0..i]`と同一になる`a[0..i]`。 

今後のスワップは現在のインデックス以上の位置内でのみ発生するため、アルゴリズムがこのプレフィックスに再び触れることはありません。 配列には同じ値の複数セットが含まれているため、各ステップに必要な値は残りのサフィックスのどこかに存在する必要があります。 

帰納法により、最終的にはすべての位置が正しくなり、最終的な配列は次のようになります。`a`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ops = []

    for i in range(n):
        if b[i] == a[i]:
            continue

        j = i
        while b[j] != a[i]:
            j += 1

        while j > i:
            b[j], b[j - 1] = b[j - 1], b[j]
            ops.append((j, j + 1))
            j -= 1

    print(len(ops))
    for x, y in ops:
        print(x, y)

solve()
```外側のループは、左から右に位置を固定します。 反復の開始時`i`、それ以前の位置はすべてすでに正しいです。 

検索ループは、最初に出現したものを見つけます。`a[i]`未固定のサフィックスで。 等しい値は交換可能であるため、最初に出現したものを使用するだけで十分です。 1 つの正しいコピーが所定の位置に到達することだけを考慮します`i`。 

バブリング ループは、隣接するスワップを 1 つずつ実行します。 この問題では隣接するスワップが明示的に求められているため、各動きを個別にシミュレートして保存する必要があります。 

Codeforces は出力で 1 から始まるインデックスを使用するため、操作インデックスは 1 から始まる形式で保存されます。 ここは、1 つずつ間違いを犯しやすい場所です。 配列内では 0 から始まるインデックスを使用しますが、位置間の交換は`j-1`そして`j`出力に対応する`(j, j+1)`。 

スワップ数が超過することはありません`n(n-1)/2`なので、操作を保存するためのメモリ使用量は少ないままです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    ops = []

    for i in range(n):
        if b[i] == a[i]:
            continue

        j = i
        while b[j] != a[i]:
            j += 1

        while j > i:
            b[j], b[j - 1] = b[j - 1], b[j]
            ops.append((j, j + 1))
            j -= 1

    out = [str(len(ops))]
    for x, y in ops:
        out.append(f"{x} {y}")

    return "\n".join(out)

# provided sample
res = solve_io(
    "4\n1 2 3 2\n3 2 1 2\n"
)
assert res.startswith("4"), "sample 1"

# minimum size
assert solve_io(
    "1\n5\n5\n"
) == "0", "single element"

# already sorted
assert solve_io(
    "3\n1 2 3\n1 2 3\n"
) == "0", "already correct"

# duplicates
res = solve_io(
    "3\n2 1 2\n2 2 1\n"
)
assert res.splitlines()[0] == "1", "duplicate handling"

# reverse order
res = solve_io(
    "4\n1 2 3 4\n4 3 2 1\n"
)
assert int(res.splitlines()[0]) == 6, "maximum inversions for n=4"

 ## 特殊なケース

 値が重複する場合を考えてみましょう。```
a = [1, 2, 1]
b = [1, 1, 2]
```位置で`0`、値はすでに正しいです。 位置で`1`、必要です`2`。 アルゴリズムはサフィックスのみを検索し、`2`インデックスで`2`。 1 つの隣接するスワップにより、以下が生成されます。```
[1, 2, 1]
```すでに正しい最初の位置は決して変更されません。 

次に、次のことを考えてみましょう。```
a = [2, 1, 2]
b = [2, 2, 1]
```最初の位置はすぐに固定されます。 位置処理時`1`、アルゴリズムはインデックスから検索します`1`先に進んで見つけます`1`インデックスで`2`。 ポジションを交換する`2`そして`3`正しい配置を与えます。 

以前の位置の検索を許可していたら、固定プレフィックスを誤って移動し、正確性が損なわれる可能性があります。 

最後に、可能な最小の入力:```
n = 1
a = [7]
b = [7]
```外側のループは 1 回実行されます。 値はすでに一致しているため、操作は追加されません。 アルゴリズムは正しく印刷します`0`。
