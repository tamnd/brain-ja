 ## 解決策
 ## 問題の理解

 一辺の長さが次のような正方形のグリッドが与えられます。$2n$。 このグリッド内には、問題の前の部分 (迷宫 I) で説明した固定手順があり、これにより、特定のローカル ルールに従ってセル間にエッジを追加できます。 この手順を繰り返し適用することで、同じグラフ上で異なる最終グラフを作成できます。$2n \times 2n$ボード。 

タスクは、この方法で取得できる個別の最終エッジ構成の数を数えることです。 一方の構成には存在するが、もう一方の構成には存在しない隣接エッジが少なくとも 1 つ存在する場合、2 つの構成は異なるものとみなされます。 この数は非常に急速に増加するため、答えはモジュロで報告する必要があります。$m$。 

各テスト ケースはペアを提供します$(n, m)$であり、目標は、そのサイズ パラメーターで到達可能な構成の数を計算することです。 

制約により、最大で次のことが許可されます。$10^4$テストケース、$n$そして$m$と同じくらい大きい$10^9$。 これにより、グリッドの反復、構築のシミュレーション、または動的プログラミングの使用に依存するソリューションは即座に排除されます。$n$。 平$O(n)$テストケースごとに実行することは不可能です。$n$それ自体は可能です$10^9$。 

入力の構造は、答えが次のもののみに依存することを示唆しています。$n$、グリッドのコンテンツや個々のクエリではありません。 各テスト ケースは独立しているため、前処理はクエリごとに一定時間または対数時間で実行する必要があります。 

このタイプの問題でよくある失敗モードは、構築ルールをローカルでシミュレートしようとすることです。 それぞれの操作は単純に見えても、可能な操作シーケンスの数は通常、次のように指数関数的に爆発的に増加します。$n$、シミュレーションが不可能になります。 

もう一つの微妙なエッジケースは次のような場合です。$n = 1$。 その場合、グリッドはただ$2 \times 2$、可能な構成の数は非常に少ないです。 どの式も、漸近近似に依存せずに、この基本ケースを正しく処理する必要があります。 

## アプローチ

 プロセスについて直接考えてみると、すべての構成は、許可された接続操作を繰り返し適用することから生まれます。$2n \times 2n$グリッド。 ブルートフォース手法では、考えられるすべての操作シーケンスを列挙し、その都度結果として得られるグラフを構築し、それをセットに挿入します。 

これはプロセスの完全な状態空間を探索するため、概念的には正しいです。 ただし、可能な操作シーケンスの数は、グリッドのサイズに応じて指数関数的に増加します。 中程度の場合でも$n$、状態の数は計算の限界をはるかに超えます。 ボトルネックは、構築あたりの時間だけではなく、調査する必要がある個別の構築の数が膨大であることです。 

重要な構造観察は、構造が全体にわたって独立して分解するということです。$n$グリッドのレイヤー。 各層は独立した二者決定、つまり他の層を制約しない局所的な構造の選択に寄与します。 この分解が認識されると、次のようにしてグローバル構成が完全に決定されます。$n$独立した選択肢。それぞれに 2 つの可能性があります。 

これにより、複雑な組み合わせオブジェクトの探索から、ある長さのバイナリ文字列の数を数える問題までが軽減されます。$n$。 各構成はそのような文字列に一意に対応するため、構成の総数は次のようになります。$2^n$。 

モジュロ$m$次に、要件によりタスクがべき乗剰余演算に変わります。

 ## アルゴリズムのチュートリアル

 解決策はコンピューティングに依存します$2^n \bmod m$各テストケースを効率的に実行します。 

1.読む$n$そして$m$。 The modulus$m$is specific to each query, so computations cannot be reused across test cases in a straightforward way.
 2. もし$m = 1$、すぐに 0 を返します。1 を法とする数値はすべて 0 であるため、それ以上の計算は不要です。 
3. コンピューティング$2^n \bmod m$2進累乗を使用します。 これは、モジュロを適用しながら、底を二乗し、各ステップで指数を半分に減らすことを繰り返すことで機能します。$m$乗算ごとに。 
4. 結果を出力します。 

重要な点は、指数が$n$と同じ大きさにすることができます$10^9$なので、線形乗算は不可能です。 2 進累乗では、次のことのみが保証されます。$O(\log n)$乗算が必要です。 

### なぜ効果があるのか

 正確さは、構成空間を次のように分解することで得られます。$n$独立した二者決定。 グリッドの各層は、正確に 2 つの可能な構造状態に寄与し、層間の選択は相互作用しません。 これにより、構成と長さのバイナリ文字列の間に 1 対 1 のマッピングが作成されます。$n$。 したがって、構成のカウントは、まさにそのような文字列のカウントに帰着します。$2^n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1 % mod
    a %= mod
    while e > 0:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    if m == 1:
        print(0)
        continue
    print(mod_pow(2, n, m))
```このコードは、べき乗剰余演算をヘルパー関数に分離します。 反復的な 2 進累乗により、再帰の深さの問題が回避され、メモリ使用量が一定に保たれます。 

実装の微妙な詳細は初期化です。`res = 1 % mod`、次のような場合でも正確性が保証されます。`mod`は 1 ですが、このケースはすでに明示的に処理されています。 ベース`a`剰余を減算したもの`m`中間の乗算で不必要に増大するのを防ぐために、最初に 1 回実行します。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def mod_pow(a, e, mod):
        res = 1 % mod
        a %= mod
        while e > 0:
            if e & 1:
                res = (res * a) % mod
            a = (a * a) % mod
            e >>= 1
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        if m == 1:
            out.append("0")
        else:
            out.append(str(mod_pow(2, n, m)))
    return "\n".join(out)

def run(inp: str) -> str:
    return solve(inp)

assert run("1\n3 10\n") == "8"

assert run("1\n10 1\n") == "0", "mod 1 case"
assert run("1\n5 6\n") == "2", "mod wrap case"
assert run("2\n1 2\n2 2\n") == "0\n0", "small modulus consistency"

 ## 特殊なケース

 いつ$n = 0$、グリッドは、構成が 1 つだけの空の構造に縮退します。 アルゴリズムは戻ります$2^0 = 1$、ループは実行されず、結果は 1 のままであるため、累乗ロジックから直接続きます。 

いつ$m = 1$、すべての整数は 1 を法として等価であるため、すべての中間値は無関係になります。 早期のリターンにより、不必要な計算が回避され、たとえ 2 進累乗が最終的に 0 を生成するとしても、正確さが保証されます。 

いつ$n$など大きいです$10^9$、乗算を繰り返すと制限時間をオーバーしてしまいます。 2 進累乗は、同一性を維持することで正確さを維持します。$a^{2k} = (a^k)^2$、大きさに関係なく計算を対数のままにすることができます。
