 ## 問題の理解

 私たちに与えられているのは、$2^n \times 2^n$格子点のグリッド。 各セルには、ヒルベルト曲線インデックス付けを使用して一意の順序が割り当てられます。これは、最小インデックスから最大インデックスまですべてのグリッド セルの順列を生成する再帰的な空間充填トラバーサルです。 

この順序を修正した後、グリッド上にランダムな構造を構築します。 ヒルベルト順序の昇順にセルを処理します。 セルを処理するとき$(x, y)$、その 4 つの隣接グリッドを調べますが、ヒルベルト次数が現在のセルより小さいもののみを保持します。 これらの適格な隣接セルの中から一様にランダムに 1 つを選択し、現在のセルをそれに接続します。 ヒルベルト順序の最初のセルが開始点であり、他のすべてのセルは最終的に前のセルに結合するため、この構築により根のあるツリーが生成されます。 

タスクは、開始セルからの予想される最短パス距離を計算することです。$(0,0)$目的の細胞に$(2^n - 1, 0)$結果として得られるランダム ツリー内で、距離は頂点間の一意のパス上の頂点の数です。 

グリッドのサイズは次のように大きくなります$2^n \le 1024$したがって、ノードの数は最大で約 100 万個になります。 各ノードは最大 4 方向に分岐でき、可能なツリーの数はノードの数に比例して増加するため、すべてのランダム性を単純にシミュレーションすることは不可能です。 木の完全な確率分布を保存することすら不可能です。 

微妙な点は、構造はランダムですが、グラフは常に最初のヒルベルト セルをルートとするツリーであることです。 つまり、ルートから任意のノードまでの距離が、まさにこのルート付きツリーの深さになります。 したがって、実際の問題は、ターゲット ノードの予想される深さを求めることです。 

よくある間違いは、予想されるグラフ内の最短パスを計算しようとしたり、複数のランダムな実現の距離を直接平均しようとしたりすることです。 これにより、タイムアウトするか正確ではない指数関数的アプローチやモンテカルロ アプローチが発生します。 

## アプローチ

 強引な解釈では、構築を何度も明示的にシミュレートすることになります。 ヒルベルト次数の各セルについて、適格な近傍の中から親をランダムに選択し、ルートから BFS または DFS を実行してターゲットまでの距離を計算します。 各シミュレーションの費用$O(N)$そしてこれを十分な回数繰り返して期待を安定させることは、たとえ$N \approx 10^6$。 

重要な点は、ツリー全体が必要ではなく、単一ノードの予想される深さだけが必要であるということです。 この構造は、各ノードがすでに処理された隣接ノードの中から 1 つの親を正確に選択するルート付きツリーです。 これにより、深さは単純な再帰を満たすようになります。つまり、ノードの深さは常に、選択した親の深さに 1 を加えたものになります。 親は既知の候補の中から一様に選択されるため、期待値は線形に分布します。 

これにより、問題は、増加するヒルベルト次数での予想深度の計算に軽減されます。 すべてのセルのヒルベルト指数がわかったら、その順序でノードを処理し、期待される深さを維持します。 各ノードは以前の隣接ノードのみに依存するため、計算はシングルパスの動的プログラムになります。

 ## アルゴリズムのチュートリアル

 ### 1. すべてのセルのヒルベルト次数を計算します。 

ヒルベルト曲線によって引き起こされるすべての格子点の全体的な順序付けが必要です。 細胞ごとに$(x, y)$、曲線の標準的な再帰的定義を使用して、そのヒルベルト指数を計算します。 これにより、ソート用の同等の整数キーが得られます。 

重要な特性は、近隣ノードを親として選択できる場合、それがこの順序付けの最初に現れる必要があるということです。 

### 2. すべてのグリッド セルをヒルベルト指数で並べ替えます。 

グリッドを次のリストに平坦化します。$(H(x,y), x, y)$そしてそれを並べ替えます。 これにより、ランダム ツリーが構築される正確な処理順序が生成されます。 

この順序により、ノードを処理するときに、すべての潜在的な親がすでに処理されることが保証されます。 

### 3. 予想される深さの配列を初期化する

 私たちは定義します`dp[x][y]`ノードの予想される深さとして$(x,y)$最後のツリーで。 ヒルベルト順序の最初のノードはルートであるため、その深さは 1 です。 

### 4. ヒルベルトの昇順でノードを処理します。 

各ノードについて$(x,y)$ソートされた順序で、その 4 つの隣接グリッドを検査します。 境界内にあり、より小さいヒルベルト指数を持つ近傍のみを保持します。 

あれば$k$このような近隣ノードの場合、ノードは親として一様にランダムに 1 つを選択します。$$dp[x][y] = 1 + \frac{1}{k} \sum dp[\text{neighbor}]$$そのようなネイバーが存在しない場合は、それがルートである必要があります。 

親は利用可能な候補の中から独立して均一に選択されるため、反復は有効です。 

### 5. ターゲットセルの値を返します。 

答えは単純です`dp[2^n - 1][0]`。 

### なぜ効果があるのか

 構築のどの段階でも、すべてのノードには、以前に処理されたノードから選択された 1 つの親があります。 これにより、構造が根のあるツリーになります。 ルートのあるツリーでは、ルートからノードまでの距離がまさにその深さになります。 

各ノードの深さはランダムに選択された親の深さにのみ依存するため、期待値の線形性により、ランダム性をシミュレートせずに期待される深さを計算できます。 重要な不変条件は、ノードを処理するときに、すべての親の深さの候補がすでに固定された期待値であるため、再帰は期待値内に正確に保持され、ヒルベルト次数を通じて正しく伝播されるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# compute Hilbert order for (x, y)
def hilbert(n, x, y):
    res = 0
    s = 1 << (n - 1)
    for i in range(n - 1, -1, -1):
        rx = (x >> i) & 1
        ry = (y >> i) & 1
        seg = (rx << 1) | ry
        # rotate depending on segment
        if seg == 0:
            x, y = y, x
        elif seg == 1:
            y -= s
            res += 1 * (1 << (2 * i))
        elif seg == 2:
            x -= s
            y -= s
            res += 2 * (1 << (2 * i))
        else:
            x, y = s - 1 - y, s - 1 - x
            res += 3 * (1 << (2 * i))
        s >>= 1
    return res

n = int(input())
m = 1 << n

cells = []
for x in range(m):
    for y in range(m):
        cells.append((hilbert(n, x, y), x, y))

cells.sort()

dp = [[0.0] * m for _ in range(m)]

start_x, start_y = 0, 0
dp[start_x][start_y] = 1.0

pos = {(0, 0)}

for _, x, y in cells:
    if x == 0 and y == 0:
        continue

    candidates = []
    for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        nx, ny = x + dx, y + dy
        if 0 <= nx < m and 0 <= ny < m:
            if dp[nx][ny] > 0:
                candidates.append(dp[nx][ny])

    dp[x][y] = 1.0 + sum(candidates) / len(candidates)

tx, ty = m - 1, 0
print(dp[tx][ty])
```この実装では、まずヒルベルト指数を計算して処理順序を回復します。 並べ替え後、単一の動的プログラミング パスを実行します。 各セルについて、すでに処理された隣接セルをチェックし、それらの予想される深さを平均します。 

微妙な点は、ツリー構造の確率を明示的に保存しないことです。 すべてのランダム性は期待値の式に吸収されるため、状態はセルごとに単一のスカラーのままになります。 

## 実用的な例

 意味のある最小のケースは$n = 1$、グリッドは$2 \times 2$。 ヒルベルト順序は固定シーケンスでセルを処理し、各ノードはすでに処理された隣接ノードの 1 つに接続します。 

### トレース対象$n = 1$| セル | 近隣住民が利用可能 | |から一律に選択されます。 予想される深さ |
 | --- | --- | --- | --- |
 | (0,0) | なし | ルート | 1 |
 | (0,1) | (0,0) | (0,0) | 2 |
 | (1,1) | (0,1),(1,0) | 両方 | 1 + 平均 |
 | (1,0) | (0,0) | (0,0) | 2 |

 ターゲットは (1,0) なので、答えは 2 です。 

これは、ノードが以前に計算された期待値のみに依存し、グローバル ツリー構造を必要としないことを示しています。 

### もう少し大きなグリッドのトレース

 のために$n = 2$、ノードは、すでに処理された隣接ノードからの深度値を徐々に蓄積します。 原点に近いセルは、ヒルベルト次数が近く、分岐の選択肢が少ないため、期待される深さが小さくなる傾向がありますが、遠方のセルは、より多くの可能な親を平均します。 

これは、DP がローカルなランダム性をグローバルな予想される構造に正しく伝播することを確認します。

 ## 特殊なケース

 最小のグリッド$n = 1$各ノードには有効な親が 1 つしかないため、これは重要です。 この場合、再発は決定論的な結合に変質し、DP は単純な鎖状構造と一致するはずです。 候補リストのサイズは常に 1 であるため、アルゴリズムはこれを自然に処理し、期待値の更新は直接割り当てになります。 

もう 1 つのエッジ ケースは、ノードに適格な隣接ノードが複数ある場合です。 たとえば、より大きなグリッドの内部セルでは、ノードには前に処理された隣接セルが 2 つまたは 3 つある場合があります。 アルゴリズムはそれらの深さを正しく平均します。 ノードが処理されるときに、それらの近傍はすべてすでに確定されているため、期待値は一貫したままであり、ヒルベルト ソートを超える処理順序には依存しません。 

最後に、角などの境界セル (開始点以外) には隣接するセルが 1 つだけであることが多く、分割の曖昧さがなくなります。 候補リストのサイズは平均化を通じて常に暗黙的にチェックされるため、実装では特別なケースを使用せずにこれを自然に処理します。
