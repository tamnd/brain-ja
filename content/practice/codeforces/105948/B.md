 ## 解決策
 ## 問題の理解

 ここでは、TAP と BREAK の 2 つのノート タイプのみが関連する単純化されたリズム ゲームのスコアリング システムをシミュレートしています。 すべての音符はいくつかの演奏カテゴリーのいずれかに審査され、各カテゴリーは最終スコアに異なる影響を与えます。 

入力により 2 つのヒストグラムが得られます。 1 つ目は各判定タイプごとに TAP ノートの数を記述し、2 つ目は判定タイプごとに BREAK ノートの数を記述します。 これらのカウントから、最終スコアの 2 つのコンポーネントを再構築する必要があります。 

最終スコアは 2 つの部分から構成されます。 1 つ目は基本スコアで、TAP ノートと BREAK ノートの両方に依存し、最大値が 100 になるように調整されます。2 つ目は、BREAK ノートのみに依存し、最大 1 ポイントに寄与するボーナス スコアです。 最終的な答えは、これら 2 つの値の合計であり、小数点第 4 位まで切り捨てられます。 

最大の難点は、スケーリング係数は分母にノートの合計数を使用するため、単一ノートの寄与がそのタイプや判断だけでなく、TAP ノートや BREAK ノートの合計数などの全体的な量にも依存することです。 これは、最初に全体的な合計を計算せずに、各カテゴリを独立して扱うことができないことを意味します。 

制約は十分小さいため、13 個の入力整数に対する単一の線形パスで十分です。 慎重な浮動小数点計算以外の最適化は必要ありません。 

微妙な失敗例は、精度と順序から発生します。 小数点以下 4 桁で切り捨てが必要なため、暗黙的に丸めが発生してはなりません。 たとえば、99.99999 のような値は、100.0000 ではなく 99.9999 になる必要があります。 もう 1 つの落とし穴は、BREAK ノートが基本スコアとボーナス スコアの両方に寄与しますが、その係数は異なるということを忘れていることです。 

## アプローチ

 単純な解釈では、スケーリング係数を慎重に分離せずにノート タイプごとの寄与を計算しようとする可能性があります。 各カテゴリのカウントにその係数を直接乗算し、個別に除算しようとする人もいるかもしれませんが、TAP と BREAK の寄与は、TAP と BREAK ノートの合計数から導出される正規化定数を共有するため、これはうまくいきません。 

正しいブルートフォース手法では、各ノートを個別にシミュレートします。 すべての TAP カウントと BREAK カウントを明示的なリストに拡張し、寄与を 1 つずつ計算できます。 これは正しいですが、不要です。 最悪の場合、TAP エントリは最大 1000 個、BREAK エントリは 800 個あるため、これは小さいままですが、概念的には扱いにくく、スケーリングを適用するときに誤って実装されやすくなります。 

重要な観察は、すべての貢献がカテゴリごとのノート数において線形であるということです。 TAP ノートと BREAK ノートの合計数が必要になるのは 1 回だけで、その後はカテゴリごとに固定乗数を適用します。 これにより、問題は一定量の演算に削減されます。 

TAP 合計 T と BREAK 合計 B を計算します。次に、x = 100 / (T + 5B) および y = 1 / B を事前計算します。すべての TAP カテゴリは、そのカウントと係数の積に x を掛けた値に寄与します。 すべての BREAK カテゴリは同様に基本スコアに寄与し、個別にボーナス スコアに寄与します。 

ノートごとの推論からカテゴリごとの集計への変換により、解決策が即座に得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース拡張 | O(T + B) | O(T + B) | 受け入れられるが不要 |
 | 集計式 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ

1. すべての TAP カテゴリ カウントを読み取り、合計 TAP ノートを計算します。 T. すべての BREAK カテゴリ カウントを読み取り、合計 BREAK ノートを計算します。 B. これらの合計は、両方のスコア コンポーネントの正規化を定義します。 
2. 基本スコア正規化では BREAK ノートが 5 倍重み付けされるため、基本スケーリング分母 T + 5B を計算します。 
3. 5 つの TAP 判定カテゴリに対応する TAP 基本係数を 1、1、1、0.8、0.5 として定義します。 
4. 基本スコア寄与度の 8 つの BREAK 判定カテゴリに対応する BREAK 基本係数を 5、5、5、4、3、2.5、2、0 として定義します。 
5. x = 100 / (T + 5B) を計算します。 これにより、加重カウントがパーセンテージの基本スコアに変換されます。 
6. 各 TAP カウントとその係数の x 倍、および各 BREAK カウントとその係数の x 倍を合計して、基本スコアを累積します。 
7. ボーナス スケーリング y = 1 / B を計算します。 
8. BREAK 判定のみを使用してボーナス スコアを計算します。C.Perfect は 1 に寄与し、Perfect1 は 0.75 に寄与し、Perfect2 は 0.5 に寄与し、Great カテゴリは 0.4 に寄与しますが、その他のカテゴリーは 0 に寄与します。 
9. ボーナス合計に y を乗算して、[0, 1] の値に正規化します。 
10. 基本スコアとボーナス スコアを加算し、結果を小数点第 4 位まで切り捨てます。 

### なぜ効果があるのか

 システム内のすべての寄与はノート数において線形であり、カテゴリー間の唯一の結合は、共有正規化定数 T + 5B および B から生じます。これらの合計が固定されると、各カテゴリーは独立して寄与します。 このアルゴリズムは、正規化を累積から分離することで正確な重み付けを維持し、カテゴリ間の相互作用が失われたり二重にカウントされたりしないようにします。 最後の切り捨てにより、中間計算に浮動小数点の丸め誤差を導入することなく、スコアリング形式への準拠が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = list(map(int, input().split()))
b = list(map(int, input().split()))

T = sum(a)
B = sum(b)

# base score coefficients
tap_coef = [1.0, 1.0, 1.0, 0.8, 0.5]
break_base_coef = [5.0, 5.0, 5.0, 4.0, 3.0, 2.5, 2.0, 0.0]

# bonus coefficients
break_bonus_coef = [1.0, 0.75, 0.5, 0.4, 0.4, 0.4, 0.0, 0.0]

x = 100.0 / (T + 5 * B)
y = 1.0 / B

base = 0.0
for i in range(5):
    base += a[i] * tap_coef[i] * x

for i in range(8):
    base += b[i] * break_base_coef[i] * x

bonus = 0.0
for i in range(8):
    bonus += b[i] * break_bonus_coef[i]

bonus *= y

ans = base + bonus

# truncate to 4 decimals
ans = int(ans * 10000) / 10000.0

print(f"{ans:.4f}")
```このソリューションでは、正規化係数を分離した後、スコア計算式を直接エンコードします。 TAP 配列と BREAK 配列は固定係数テーブルを使用して独立して処理されるため、判定タイプを乗算器にマッピングする際の間違いを防ぎます。 

切り捨てステップは、10000 によるスケーリング後に整数フロアリングを使用して明示的に実行されます。これにより、浮動小数点の丸めの問題が回避され、値が正しいカットオフをわずかに超えてしまう可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ミス以外に BREAK ノートがない場合です。この場合でも B はプラスになりますが、ボーナスとベースへの寄与が異なります。 y = 1 / B が明確に定義されたままであり、MISS のすべての係数がゼロであり、偶発的なインフレが発生しないため、式は引き続き正しく動作します。 

もう 1 つの特殊なケースは、T が小さく、B が大きい場合です。 BREAK ノートは分母に 5 の重みがかかるため、基本スコアが大幅に縮小します。 スケーリング係数 x がすでにこの不均衡をエンコードしているため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは切り捨てです。 計算された値が次に表現可能な 4 桁の 10 進数に非常に近い場合、明示的に切り捨てられないと、浮動小数点演算が誤って切り上げられる可能性があります。 整数スケーリング ステップにより、浮動小数点表現に関係なく決定的なフロアリングが保証されます。
