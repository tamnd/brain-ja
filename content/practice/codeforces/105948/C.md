 ## 解決策
 ## 問題の理解

 スタミナ値が設定された馬と重量が設定されたカートの 2 つのコレクションが与えられました。 各馬には 1 台のカートを割り当てる必要があり、各カートは最大 1 回しか使用できません。 スタミナのある馬なら$E_i$重みのある荷車を引く$W_j$、その移動貢献度は$\max(E_i - W_j, 0)$。 

各馬に個別のカートを割り当てた後、各馬は移動値を生成します。 私たちはすべての馬の最小の動きを重視しており、割り当てを賢明に選択することで、この最小値をできるだけ大きくしたいと考えています。 

つまり、ペアリングしているのです$n$馬と$n$から選択したカート$m$, そして組み合わせ後の最低成績の馬を最大化したいと考えています。 

制約により、最大で次のことが許可されます。$10^4$馬と荷車、最大値$10^9$。 全単射の数は階乗であるため、すべての代入を試行する解決策は不可能です。$n$、これは実行可能な計算をはるかに超えて増加します。 

エッジの動作に関する重要な観察は、動きは決してネガティブではないということです。 馬にスタミナより重いカートが割り当てられた場合、貢献はゼロになります。 これにより特殊なケースが発生します。正の最小値の答えを目指す場合は、割り当てられたすべてのペアが満足することを確認する必要があります。$E_i > W_j$。 

重いカートが多すぎると、単純に誤解を招くシナリオが発生します。 

例：```
n = 2, m = 3
E = [5, 6]
W = [10, 1, 2]
```貪欲に最小の重みを恣意的に割り当てた場合でも、馬に重いカートを与えることを強いられる可能性があり、その結果、その馬の動きがゼロになり、正の最小目標が破壊されます。 ここでの正しい出力は、特定のしきい値以下で重いカートを回避できるかどうかによって完全に決まります。 

これは、割り当てを直接最適化しているのではなく、ターゲットの最小値の実現可能性をチェックしていることをすでに示唆しています。 

## アプローチ

 強引なアイデアは、選択するすべての方法を列挙することです。$n$からのカート$m$、選択ごとに、最小値を最大化する馬と荷車の間の最良のマッチングを計算します。 選択を修正したとしても、すべての組み合わせを試す必要があります。$O(n!)$。 すべてのサブセットにわたって、これは組み合わせ爆発的となり、非常に小さいものであっても通過できません。$n$。 

構造的な変化は、目的を逆転させることから生まれます。 最良の割り当てを直接構築する代わりに、すべての馬が少なくとも動きを達成することを要求するかどうかという決定の質問をします。$x$、有効な割り当てを作成できますか?

 固定の場合$x$、条件$$\max(E_i - W_j, 0) \ge x$$手段$E_i - W_j \ge x$、または同等の$W_j \le E_i - x$。 各馬にはしきい値があり、そのしきい値以下の重さの荷車のみを受け入れることができます。 問題は、これらの制約の下で馬と荷車の間の二者マッチングの実現可能性チェックになります。 

両方の配列をソートすると、貪欲なスキャンが可能になります。つまり、動作する最も軽い利用可能なカートを使用して、常に最も制限された馬を最初に満たそうとします。 

実現可能性は単調なので、$x$、二分探索が適用されます。 値の場合$x$可能であれば、より小さい値もすべて可能であり、それが不可能な場合は、より大きな値も不可能のままです。

 | 二分探索 + 貪欲マッチング | O((n+m)\log 1e9) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 馬をスタミナごとに、馬車を重量ごとに分類します。 ソートは、後戻りすることなく常に最も制限的な要件を最初に一致させるために必要です。 
2. 関数を定義する`check(x)`すべての馬が少なくとも動きを達成できるかどうかを決定します$x$。 この関数が扱うのは、$x$最適化の目標ではなく、要件として。 
3. 各馬のスタミナの増加順に、必要な最大カート重量を計算します。$limit = E_i - x$。 これにより、移動制約が単純な容量制約に変換されます。 
4. 重量別に分類されたカートの上にポインタを置き続けます。 各馬について、制限を満たす最も軽い未使用のカートが見つかるまでポインターを進めます。 
5. 馬に対応する有効なカートが存在しない場合は、false を返します。 これは、最も柔軟な割り当てでもしきい値を満たすことができないことを意味します。$x$。 
6. すべての馬が正常に割り当てられた場合は、true を返します。 
7. 二分探索$x$0 から大きな上限 (最大スタミナ差) まで、を使用して`check(x)`検索をガイドします。 

二分探索では実行可能な最大値が返されます$x$、これが答えです。 

### なぜ効果があるのか

 貪欲チェックが機能するのは、馬がスタミナの増加順に処理されるためです。つまり、早い馬ほど制約が厳しくなります。 最初にそれらを割り当てると、後でより厳格な馬に必要になる小さなカートを無駄にすることがなくなります。 実行可能な割り当てが存在する場合、有効なマッチングは実行可能性を損なうことなくこの貪欲な選択と一致するものに変換できるため、この順序付けによって有効な解決策がブロックされることはありません。 実現可能性の単調な性質$x$二分探索が正しい境界に確実に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, E, W):
    j = 0
    n = len(E)
    m = len(W)

    for i in range(n):
        limit = E[i] - x
        while j < m and W[j] <= limit:
            j += 1
        if j == 0:
            return False
        j -= 1
        if W[j] > limit:
            return False
        # use this cart
    return True

def check(x, E, W):
    j = 0
    n = len(E)
    m = len(W)
    used = [False] * m
    ptr = 0

    for i in range(n):
        limit = E[i] - x
        while ptr < m and W[ptr] <= limit:
            ptr += 1
        if ptr == 0:
            return False
        # assign largest valid available by stepping back
        ptr -= 1
        if W[ptr] > limit:
            return False
        ptr -= 1
    return True

def feasible(x, E, W):
    j = 0
    m = len(W)
    for e in E:
        limit = e - x
        while j < m and W[j] <= limit:
            j += 1
        if j == 0:
            return False
        j -= 1
        if W[j] > limit:
            return False
        # consume it
    return True

def solve():
    n, m = map(int, input().split())
    E = list(map(int, input().split()))
    W = list(map(int, input().split()))

    E.sort()
    W.sort()

    lo, hi = 0, 10**9
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(mid, E, W):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は両方の配列のソートに依存しているため、実現可能性はリニア スキャンの問題になります。 機能`feasible`コアの貪欲チェックです。馬を調べてカート配列内のポインターを維持し、常に現在の制限内で可能な最大の有効なカートを割り当てようとします。 

微妙な点は、セットを介してどのカートが使用されているかを明示的に追跡することがないことです。 代わりに、ポインターの移動と単調な消費に依存しており、各カートが最大 1 回使用されることが保証されます。 

二分探索範囲は、答えが馬と荷車の間で可能な最大差を超えることができないため安全であり、実行不可能な値は拒否されるため、大きな上限を設定しても正確さに影響しません。 

## 実用的な例

 ### 例 1```
n = 3, m = 4
E = [2, 3, 2]
W = [1, 3, 2, 1]
```並べ替え後:

 E = [2, 2, 3]

 W = [1、1、2、3]

 x = 1 の実現可能性をテストします。 

| 馬 | 馬 リミット (E-x) | カートポインター | アクション |
 | --- | --- | --- | --- |
 | 2 | 1 | 0→1 | 1を割り当てる |
 | 2 | 1 | 1→2 | 1を割り当てる |
 | 3 | 2 | 2→3 | 2を割り当てる |

 すべての馬が一致したため、x = 1 が可能です。 

x = 2 を試してみます。 

限界は [0, 0, 1] になります。 最後の馬は、利用可能なカートが制限に対して重すぎるため、有効なカートを見つけることができず、失敗が発生します。 

これは二分探索境界の動作を示しています。実現可能性は true から false に急激に変化します。

n = 2, m = 3
E = [5, 6]
W = [1, 2, 10]
```並べ替え:

 | 馬 | 馬 制限 | カートポインター | アクション |

 | 5 | 2 | 0→2 | 2番目を選択 |

これは、実現可能性はローカルな満足度だけではなく、グローバルな可用性によって左右されることを示しています。

 ## 特殊なケース

 重大なエッジケースは、すべてのカートが多くの馬よりも重く、移動値がゼロになる場合です。 例えば：```
E = [1, 2]
W = [100, 200]
```どれについても$x > 0$、条件$E_i - W_j \ge x$は不可能であるため、カートが満たされない場合、最初のチェックで実行可能性が直ちに失敗するため、アルゴリズムは正しく 0 に収束します。$W_j \le E_i - x$。 

もう一つのケースは次のような場合です。$m = n$つまり、選択に柔軟性がありません。 貪欲スキャンはソート後に厳密な 1 対 1 ペアリングに縮退するため、このアルゴリズムは引き続き機能します。 実行不可能な順序付けは実行可能性チェック中に不一致として表示され、二分探索では自然に達成可能な最良のしきい値に落ち着きます。 

微妙な失敗モードは、世界的な消費量の追跡を行わずに、馬ごとに独立して最小の有効なカートを割り当てようとすることです。 これでは、推論の際にカートが何度も再利用され、人為的に楽観的な答えが生成されてしまいます。 ポインターベースの消費では、各カートが利用可能から 1 回だけ削除されるようにすることで、これを防ぎます。
