 ## 解決策
 ## 問題の理解

 この問題により、文字列「a」と「b」が得られます。これは、連結された 3 つのカピバラの名前を表します。 私たちのタスクは、文字列を 3 つの空ではない部分文字列に分割することです。$a$、$b$、 そして$c$中央の文字列のどちらかが$b$辞書編集上、両方の隣接値よりも小さくありません ($a \le b$そして$c \le b$） または$b$辞書編集上、隣り合うものよりも大きくない ($b \le a$そして$b \le c$）。 出力は 1 つの有効なトリプレット、または分割できない場合は「:(」である必要があります。

 入力制約は重要です。 各文字列の長さは最大 200,000 文字で、テスト ケースは最大 10,000 個まで可能ですが、合計の長さは 400,000 に制限されます。 これは、すべての分割位置を反復するには大まかに必要となるため、考えられるすべての分割を強引に列挙することはできないことを意味します。$O(n^2)$文字列ごとの演算は非常に遅すぎます。 

エッジ ケースは、文字列が複数回繰り返される 1 つの文字のみで構成されている場合、または文字列の長さが最小限である場合に発生します。 たとえば、「aaa」は単純に「a a a」として分割する必要があり、これは両方の条件を自明に満たします。 もう 1 つの注意が必要なケースは、「aba」または「bab」です。この場合、辞書編集上の順序により、ルールを満たすために特定の分割が強制される可能性があります。 

## アプローチ

 素朴なアプローチは、考えられる分割点のすべてのペアを試し、結果の 3 つ組を辞書編集条件と照合してチェックし、最初の有効な 1 つを出力することです。 これには、$O(n^2)$文字列ごとの操作、最大値では実行不可能$n = 2 \cdot 10^5$。 

重要な観察は、辞書編集上の条件は、次の最初の文字を選択することで満たされるということです。$a$、の最後の文字$c$、残りの部分文字列を$b$。 これが機能するのは、最初と最後の文字が最小限の方法で順序制約を決定するためです。$a$そして$c$単一の文字、$b$文字列の残りの部分を吸収し、必要に応じて支配したり、支配されたりすることができます。 これは貪欲な解決策につながります。$a$最初の文字、$c$最後の文字と、$b$その間のすべて。 文字列の長さがちょうど 3 の場合、各文字列は 1 文字になります。 長い文字列の場合は、$b$合計の長さが少なくとも 3 であるため、空でないことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 貪欲 (最初-中-最後) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、文字列を読み取ります。$s$。 
2.長さの場合$s$ちょうど 3 です。代入します$a$、$b$、 そして$c$それぞれのキャラクターに。 これは、空ではない要件を自明に満たします。 
3. それ以外の場合は、割り当てます$a$の最初の文字に$s$、$c$最後の文字まで、そして$b$それらの間の部分文字列に。 これにより、両方のことが保証されます。$a$そして$c$空ではない、そして$b$文字列には少なくとも 3 文字があるため、空ではありません。 
4. 3 連符を印刷します。$a$、$b$、$c$。 辞書編集条件は、次のいずれかの理由により常に満たされます。$b$は中央のチャンクであり、それが長いか一致する場合は隣接するチャンクを支配します。あるいは、単一文字の場合はその逆が自明に当てはまります。$a$そして$c$。 

なぜそれが機能するのか: 不変条件は、$a$そして$c$残りの文字を入れます$b$、私たちは空ではないことを維持し、$b$辞書編集的により大きくなる$a$そして$c$(すべての文字が「b」の場合) 以下 (すべての文字が「a」の場合)。 これ以上複雑な分割は不要であり、この問題では複数の正しい出力が許可されるため、この貪欲な割り当てにより常に有効な答えが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        if len(s) == 3:
            print(s[0], s[1], s[2])
        else:
            a = s[0]
            b = s[1:-1]
            c = s[-1]
            print(a, b, c)

if __name__ == "__main__":
    solve()
```このコードは、高速 I/O を使用して複数のテスト ケースを効率的に処理します。 設計により空でない分割が保証され、不必要なループが回避され、トリプレットが直接出力されます。 スライスを使用すると、手動による反復が回避され、最大長の文字列であっても正確さが保証されます。 

## 実用的な例

 トレース 1: s = "bbba"

 | ステップ | | b | c |
 | --- | --- | --- | --- |
 | 割り当て | 'b' | 'bb' | 'a' |

 出力「b bb a」は次の条件を満たします。$a \le b$そして$c \le b$「b」≤「bb」および「a」≤「bb」であるためです。 

トレース 2: s = "aba"

 | ステップ | | b | c |
 | --- | --- | --- | --- |
 | 割り当て | 'a' | 'b' | 'a' |

 出力「a b a」は次の両方を満たします。$a \le b$そして$b \le a$同時に、それは許可されています。 トリプレットは有効です。 

これらのトレースは、貪欲なアプローチが最小限の文字列とわずかに長い文字列の両方を正しく処理し、常に有効な分割を生成することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 | スペース | O(n) | 各分割では、最大 3 つの新しい文字列が作成されます。 スライスでは n を超えるコピーは作成されないため、合計メモリ使用量は文字列の長さに比例します。 |

 このソリューションは、1 秒の制限と 256 MB のメモリ制約内に簡単に収まります。

 ## 特殊なケース

 このアルゴリズムは、長さ 3 の最小の有効な文字列を正しく処理し、各文字の有効な分割を生成します。 3 より長い文字列の場合、中央の部分文字列が残りの文字をすべて吸収し、$b$は空ではありません。 「aaa」や「bbb」などの文字列は、すべての文字が同一であるため、辞書編集上の制約を自動的に満たします。 「aba」のような文字列の場合、アルゴリズムは次の条件を満たす「a b a」を生成します。$b$は隣接する文字より小さくも大きくもなく、交互の文字に対する柔軟性を示しています。 長さが 3 未満の文字列は無効な入力です。 このような場合には、「:(」を返すようにコードを変更できます。
