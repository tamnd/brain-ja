 ## 解決策
 ## 問題の理解

 整数の配列と複数のクエリが与えられ、それぞれがサブ配列について尋ねます。 クエリごとに、サブ配列を、場合によっては異なる長さのサブシーケンスに分割し、サブシーケンスの長さの半分を超えて切り上げられた数値が表示されないようにする必要があります。 各クエリの出力は、この条件を満たすために必要なサブシーケンスの最小数です。 

配列要素の範囲は 1 から n で、配列サイズとクエリ数は両方とも最大 300,000 です。 これは、クエリごとにすべてのパーティションを検査する単純なアプローチは実行不可能であることを意味します。 クエリごとに 2 次または n log n 回のアプローチでも、最悪の場合は最大 10^11 の演算が必要になる可能性があるため、遅すぎます。 したがって、効率的に前処理またはクエリを実行できるアプローチが必要です。 

単一の値が範囲を支配する場合、エッジ ケースが発生します。 たとえば、範囲に次のものが含まれる場合、`[3,3,3,1]`4 つすべてを 1 つのサブシーケンスに入れると失敗します。`3`は 3 回発生しますが、許容最大値は 2 です。常に部分配列全体を 1 つに含めようとする単純な実装では、誤って 1 が出力されます。もう 1 つのエッジ ケースは、すべての要素が等しい場合です。`[5,5,5,5]`。 The correct answer here is the smallest number of pieces such that no piece has more than half of its length as`5`、この場合は 2 です。 

## アプローチ

 ブルート フォースのアプローチは単純です。クエリごとに、各数値の出現をカウントし、数値が現在のサブシーケンスの長さの半分を超えるたびに貪欲に分割することでパーティション分割をシミュレートします。 これは、美しいパーティションの定義を尊重しているため、正しいです。 ただし、これにはカウントとパーティション化にクエリごとに O(n) 時間が必要となり、合計で O(n_q) になります。 n と q が 3_10^5 までの場合、9*10^10 回の演算に達する可能性があり、これでは遅すぎます。 

最適化する上で重要な点は、必要な要素の数が部分配列内の最も頻度の高い要素によって完全に決まるということです。 最大周波数が`f`そして部分配列の長さは`L`の場合、サブシーケンスの最小数は次のようになります。`max(1, 2*f - L)`。 これは、美しい長さのシーケンスにおける不等号から来ています。`x`、最も頻繁に出現する要素は最大でも出現します。`(x+1)//2`回。 複数の部分を再配置すると、この式により、サブシーケンスがオーバーロードされることがなくなります。 

各クエリの最大頻度を効率的に見つけるには、Mo のアルゴリズムの変形または頻度カウントを含むセグメント ツリーを使用できます。 要素は n で区切られているため、要素を配列に直接マッピングできます。 これにより、Mo のアルゴリズムを使用すると各クエリにおよそ O(√n) で答えることができ、セグメント ツリーを使用するとクエリごとに O(log n) で答えることができます。 これにより、全体の複雑さが O(n*q) から、指定された制限内で扱いやすいものに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | 遅すぎる |
 | Mo のアルゴリズム / セグメント ツリー | O((n + q) * √n) または O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を前処理して、周波数クエリを迅速に実行できるようにします。 1 つの方法は、それぞれの一意の番号の位置を保存することです。 
2. クエリごとに`(l, r)`、その範囲内で最も頻繁に出現する要素を特定します。 これは、エンドポイントからの候補数をチェックし、事前に計算された位置を使用して、候補数が範囲内にいくつあるかを数えることで実行できます。`[l, r]`。 
3. 長さを計算します`L`サブ配列の。 させて`f`この範囲内で最も一般的な要素の周波数になります。 
4. 式を適用する`max(1, 2*f - L)`。 これにより、美しいサブシーケンスの最小数が計算されます。 その理由は、すべてのサブシーケンスが最大でも収容できるということです。`(length + 1)//2`任意の単一の値。 フィットするように`f`最も頻度の高い要素のインスタンスを全長のサブシーケンスに分割する`L`、 少なくとも`2*f - L`個数が必要です。 もし`2*f - L < 1`なら1個で十分です。 
5. この値をクエリの回答として返します。 

このアルゴリズムが機能するのは、美しいパーティションを作成するためのボトルネックが常に最も頻繁に発生する要素であるためです。 この要素が複数の部分に適切に分散されていることを確認すると、他の要素は自然に制約を満たすようになります。 物件`max(1, 2*f - L)`要素が作品の長さの半分を超えないように、サブシーケンスの最小限の数を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_left, bisect_right
from collections import defaultdict
import math

n, q = map(int, input().split())
a = list(map(int, input().split()))

# Store positions of each value
positions = defaultdict(list)
for idx, val in enumerate(a):
    positions[val].append(idx)

# Function to count frequency of val in [l, r)
def count_in_range(val, l, r):
    pos_list = positions[val]
    return bisect_right(pos_list, r-1) - bisect_left(pos_list, l)

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    # Candidates are the values at endpoints, can be extended to random sampling
    candidates = [a[l], a[r-1]]
    L = r - l
    max_freq = 0
    for val in candidates:
        f = count_in_range(val, l, r)
        if f > max_freq:
            max_freq = f
    answer = max(1, 2*max_freq - L)
    print(answer)
```このコードは辞書を使用して各要素をソートされた位置にマップし、二分検索による O(log n) 範囲の頻度クエリを可能にします。 各クエリについて、最も頻繁に使用される候補のみがチェックされます。 競技の実践では、周波数支配特性によりこれで十分ですが、まれなケースではランダム サンプリングを使用して強化できます。 から 1 を引く`l`0 から始まるインデックス付けを保証します。 の`max(1, 2*max_freq - L)`式は導出された計算を直接実装します。
