 ## 解決策
 ## 問題の理解

 洞窟とトンネルの有向グラフが与えられます。 洞窟から始まります`1`バックパックに石が入っていないので洞窟に行きたい`n`。 

トンネルが追加される`a`入ると岩ができて、それから取り除く`b`私たちがそれを離れると岩が揺れます。 以下の場合は、`b`岩があれば、トンネルはすべてを取り除きます。 現在の石の数が`r`、トンネルを通過した後の新しい金額は次のようになります。```
max(0, r + a - b)
```定義すると便利です```
w = a - b
```したがって、すべてのトンネルが適用されます```
r -> max(0, r + w)
```課題は、最初に洞窟に到着したときに存在できる岩の最小数を見つけることです。`n`。 洞窟なら`n`到達不可能です、答えは`-1`。 

グラフには最大 300 個の頂点がありますが、非常に密になる可能性があります。`n(n-1)`有向エッジ。 トンネルパラメータは次の条件を満たします`0 ≤ a, b ≤ 10`したがって、フロアアットゼロ操作が適用される前に、すべてのエッジで岩の数が最大 10 ずつ変化します。 

エッジの重みが小さいことが重要な観察点です。 単純なパスには最大でも次のものが含まれます`n - 1`したがって、単純なパスに沿った合計の減少は最大でも```
10 * (n - 1) ≤ 2990
```これは、岩石数の制限された範囲のみを明示的に表現する必要があることを直ちに示唆しています。 

サイクルが存在する場合、微妙なエッジケースが発生します。 

例：```
1 -> 2 : +10
2 -> 3 : -9
3 -> 2 : 0
```最短パス スタイルのソリューションは失敗します。頂点を再訪すると岩の数が変わり、最終的な答えが改善される可能性があるためです。 

もう 1 つの重要なケースは、後でそれらを減らす前に、パスに一時的に多くの岩を蓄積する必要がある場合です。 

例：```
1 -> 2 : +10
2 -> 2 : +10
2 -> n : -10
```最適な散歩では、出発前に正のサイクルを数回使用する場合があります。 単純なパスのみを考慮するソリューションでは、そのようなウォークが見逃されます。 

最後に、グラフには任意の大きな岩石数を許容する到達可能な正のサイクルが含まれる場合があります。 すべての可能な値を明示的に保存することはできないため、状態空間は慎重に圧縮する必要があります。 

## アプローチ

 ブルートフォース検索では状態が次のように扱われます。`(vertex, rocks)`到達可能なすべての状態を探索します。 

遷移は決定的であるため、これは正しいです。```
r -> max(0, r + w)
```問題は、岩石の数が理論上無制限であることです。 到達可能な正のサイクルでは、岩石の数が永遠に増加し、無限に多くの状態が生成されます。 

重要な観察は、エッジの重みが 10 で制限されており、グラフには 300 個の頂点しか含まれていないことです。 

させて```
B = 10 * (n - 1)
```この問題については、```
B ≤ 2990
```現在、以上のものがあるとします。`B`岩。 単純なパスではカウントをこれ以上減らすことはできません`B`、すべてのエッジが少なくとも寄与するため、`-10`。 

つまり、カウントが十分に大きくなると、正確な値は重要ではなくなります。 固定しきい値を超えるすべての値は同様に動作します。 すべてのカウントを制限まで明示的に保存し、それより大きいものをすべて 1 つの特別な状態にマージできます。 

便利な選択肢としては、```
LIMIT = B + 10 = 3000
```3000 個を超える岩がある場合、エッジを横断した後でも 2990 個を超える岩が残っていることになります。 私たちがこの領域に留まっている間は、ゼロ下限運用が意味を持つことはあり得ません。 

これにより、無限の状態空間が有限の状態空間に変換されます。```
(vertex, 0..3000)
```さらに、頂点ごとに 1 つの追加の「ラージ」ステートが追加されます。 

残りの課題は効率性です。 到達可能なカウントを個別に保存するのではなく、ビットセットとして保存します。 長さ 3001 のビットセットは Python 整数に無理なく収まり、すべてのエッジ変換は数ビットの操作になります。 

結果として得られるアルゴリズムは、有限グラフ上の単調な到達可能性の伝播であり、到達可能な状態の完全なセットに収束します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 正確な岩の数に対するブルートフォース | 無制限 | 無制限 | 遅すぎる |
 | 圧縮された大きな状態でのビットセットの到達可能性 | 実際には O(m · LIMIT / word_size) | O(n・LIMIT) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのトンネルのコンピューティングについて```
w = a - b
```遷移はこの値のみに依存するためです。 
2. しましょう```
LIMIT = 3000
```カウント`0..3000`明示的に表現されています。 
3. すべての頂点について以下を維持します。```
bits[v]
```どこビット`k`岩の数の場合に設定されます`k`頂点で到達可能です`v`。 

メンテナンスも行います```
big[v]
```これは、3000 を超えるカウントが頂点で到達可能であることを意味します`v`。 
4.初期化```
bits[1] = {0}
```なぜなら、洞窟 1 では岩がゼロからスタートするからです。 
5. 発信エッジに沿って情報を繰り返し伝播します。 

負でない重みの場合`w`:```
k -> k + w
```カウントが 3000 を超えると、`big`州。 
6. 負の重みの場合`-d`:```
k -> max(0, k - d)
```これは、ビットセットを右シフトし、さらに以下のカウントがある場合はビット 0 を設定することで実装されます。`d`到達可能でした。 
7. もし`big[u]`それは真実であり、エッジがあります`u -> v`、 それから`big[v]`も真になります。 

3000 を超えるカウントは 1 回の遷移後も 2990 を超えるため、正確な値は無関係です。 
8. キューを使用します。 頂点が新しい到達可能な状態を受け取るたびに、その頂点をキューにプッシュして、その発信エッジが再度処理されるようにします。 
9. 固定点に到達したら、頂点のビットセットを検査します。`n`。 

設定された最小ビットは、到達可能な最小の岩の数です。 
10. ビットセットも大きな状態も頂点で到達できない場合`n`、出力`-1`。 

### なぜ効果があるのか

 このアルゴリズムは、到達可能性関係の最小不動点を計算します。 

初期状態から開始してすべての有効な遷移を繰り返し適用するため、到達可能なすべての状態が生成されます。 到達可能な状態は省略されません。 

3000 を超える値は 1 ステップで明示的な範囲に直接戻ることができないため、圧縮は安全です。 1 つのエッジの最大減少は 10 であるため、3000 より大きいカウントは遷移後も常に 2990 より大きいままになります。 この領域に入ると、正確な値は無関係になります。`big`状態はそのような可能性をすべて捉えています。 

有限状態空間が徹底的に探索され、すべての遷移が正確にモデル化されるため、洞窟では到達可能な岩のセットが重要になります。`n`は正しいです。 到達可能な最小のカウントを取得すると、必要な答えが得られます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

LIMIT = 3000
MASK = (1 << (LIMIT + 1)) - 1

def transform(bits, w):
    if bits == 0:
        return 0, False

    if w >= 0:
        shifted = bits << w

        low = shifted & MASK
        high = shifted >> (LIMIT + 1)

        return low, high != 0

    d = -w

    low_part = bits & ((1 << d) - 1) if d <= LIMIT else bits
    res = bits >> d

    if low_part:
        res |= 1

    return res, False

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        x, y, a, b = map(int, input().split())
        g[x - 1].append((y - 1, a - b))

    bits = [0] * n
    big = [False] * n

    bits[0] = 1  # rock count 0

    q = deque([0])
    inq = [False] * n
    inq[0] = True

    while q:
        u = q.popleft()
        inq[u] = False

        cur_bits = bits[u]
        cur_big = big[u]

        for v, w in g[u]:
            add_bits, make_big = transform(cur_bits, w)

            changed = False

            new_bits = bits[v] | add_bits
            if new_bits != bits[v]:
                bits[v] = new_bits
                changed = True

            if cur_big or make_big:
                if not big[v]:
                    big[v] = True
                    changed = True

            if changed and not inq[v]:
                inq[v] = True
                q.append(v)

    target = bits[n - 1]

    if target == 0 and not big[n - 1]:
        print(-1)
        return

    answer = (target & -target).bit_length() - 1
    print(answer)

solve()
```このソリューションでは、到達可能なすべてのカウントを 3000 まで 1 つの Python 整数内に保存します。 少し`k`岩の数に対応します`k`。 

非負のエッジの重みの場合、ビットセットを左にシフトします。 位置 3000 を超えて移動するビットは、明示的な範囲より大きいカウントを示しているため、宛先頂点は`big`フラグ。 

負のエッジの重みの場合は右にシフトします。 負の重みの大きさより小さいカウントは、次の理由によりゼロに崩壊します。`max(0, ...)`手術。 このため、これらの小さなカウントのいずれかに到達した場合は常にビット 0 を追加する必要があります。 

キューベースの伝播は、標準的な単調なデータ フロー プロセスです。 頂点は、到達可能な状態のセットが大きくなった場合にのみ再度処理されます。 

表現```
(target & -target).bit_length() - 1
```最も低い設定ビットのインデックスを返します。これはまさに到達可能な最小の岩の数です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 実際には O(m · LIMIT / word_size) | ビットセット操作は多くの岩石カウントを同時に処理します。 
| スペース | O(n・LIMIT) | 頂点ごとに長さ 3001 の 1 つのビットセット |

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    LIMIT = 3000
    MASK = (1 << (LIMIT + 1)) - 1

    def transform(bits, w):
        if bits == 0:
            return 0, False

        if w >= 0:
            shifted = bits << w
            return shifted & MASK, (shifted >> (LIMIT + 1)) != 0

        d = -w
        low_part = bits & ((1 << d) - 1)
        res = bits >> d
        if low_part:
            res |= 1
        return res, False

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        x, y, a, b = map(int, input().split())
        g[x - 1].append((y - 1, a - b))

    from collections import deque

    bits = [0] * n
    big = [False] * n

    bits[0] = 1

    q = deque([0])
    inq = [False] * n
    inq[0] = True

    while q:
        u = q.popleft()
        inq[u] = False

        for v, w in g[u]:
            add_bits, make_big = transform(bits[u], w)

            changed = False

            nb = bits[v] | add_bits
            if nb != bits[v]:
                bits[v] = nb
                changed = True

            if big[u] or make_big:
                if not big[v]:
                    big[v] = True
                    changed = True

            if changed and not inq[v]:
                inq[v] = True
                q.append(v)

    target = bits[n - 1]

    if target == 0 and not big[n - 1]:
        return "-1\n"

    ans = (target & -target).bit_length() - 1
    return str(ans) + "\n"

 ## 特殊なケース

 次のことを考慮してください。```
3 2
1 2 5 0
2 3 0 10
```5 つの岩から 2 番目のエッジへの移行は次のとおりです。```
max(0, 5 - 10) = 0
```アルゴリズムは、負の重み変換を通じてこれを処理します。 必要な減少を下回るカウントは、宛先ビットセットのビット 0 に寄与します。 

ここで、到達不能な宛先について考えてみましょう。```
3 1
1 2 1 0
```頂点 3 に状態が伝播されることはありません。そのビットセットは空のままであり、`big`フラグは false のままであるため、アルゴリズムは正しく出力します。`-1`。 

最後に、到達可能な正のサイクルについて考えてみましょう。```
3 3
1 2 10 0
2 2 10 0
2 3 0 10
```頂点 2 の自己ループにより、無制限に岩の数を増やすことができます。 カウントが明示的な制限を超えると、アルゴリズムは圧縮されたデータに切り替わります。`big`表現。 無限に多くの値を保存しなくても、到達可能性は正確なままです。
