 ## 解決策
 ## 問題の理解

 各ノードが小文字を持つルート付きツリーが与えられます。 ルートはノード 1 であり、すべてのノードにはルートからの深さが明確に定義されています。 

各クエリは 1 つのノードに焦点を当てます`u`そして目標深度`d`。 2 つの条件を満たすすべてのノードを同時に調べます。それらは、次のサブツリー内にあります。`u`、根元からの深さは正確に`d`。 これらのノードに書かれた文字から、それらすべてを任意の順序で使用して文字列を形成します。 

各クエリの疑問は、結果の文字列がアンチ回文になるように、これらの文字を並べ替えることができるかどうかです。つまり、最初の文字と最後の文字、2 番目の文字と最後から 2 番目の文字などをペアにした場合、どのペアにも同じ文字が含まれないことになります。 

ツリーのサイズとクエリの数は両方とも十分に大きいため、サブツリーのクエリごとの走査が遅すぎます。 各サブツリー内のノードを個別に訪問すると、大まかに次のようになります。$O(nq)$、これは実現可能な限界をはるかに超えています。$2 \cdot 10^5$。 これにより、サブツリーと深さの情報が再編成され、クエリが高速な範囲カウントに削減される前処理アプローチが必要になります。 

クエリ条件に一致するノードがない場合、微妙なエッジ ケースが発生します。 たとえば、サブツリーにノードがない場合、`u`深いところにある`d`、答えは「いいえ」でなければなりません。 もう 1 つの重要なケースは、その層にノードが 1 つだけ存在する場合です。単一の文字列は、中央の位置にある文字列自体と比較されるため、アンチ回文を形成できません。 たとえば、文字を含む単一のノード`"a"`戻らなければなりません`No`。 

## アプローチ

 各クエリに対する直接的なアプローチは、次のサブツリー内のすべてのノードを収集することです。`u`、深さのあるものをフィルタリングします`d`、それらの文字を抽出し、それらをアンチ回文に配置できるかどうかを確認します。 定義を正確に反映しているため、正確さは簡単です。 問題はパフォーマンスです。 密なツリーでは、サブツリーに次のものが含まれる場合があります。$O(n)$すべてのクエリに対してこれを実行すると、$O(nq)$大きすぎる仕事。 

重要な構造上の観察は、「ノードが次のサブツリー内にある」という条件が存在することです。`u`」は当然オイラー巡回区間で表現されますが、「ノードには深さがあります」`d`” はノードを独立したレイヤーに分割します。深さを固定したら`d`、その深度にあるすべてのノードをオイラー ツアーのエントリ時間の昇順でリストできます。 次に、すべてのサブツリー制限は、その並べ替えられたリストに対する連続した間隔のクエリになります。 

これにより、問題は深さごとの静的配列に対する頻度クエリに集約されます。 深さごとに、DFS エントリ時間でソートされたノードのリストを維持し、そのリストの文字のプレフィックス数も維持します。 次に、各クエリは部分配列にわたる度数表を抽出することになり、これは O(26) 時間で実行できます。 

残りのステップは、複数の文字セットがアンチ回文を形成できるかどうかを確認することです。 長さが偶数で、長さの半分を超える文字が表示されない場合に限り、ミラーリングされたペアが一致しないようにマルチセットを再配置できます。 いずれかの文字が半分を超える場合、必然的に 2 つのミラー位置を占有する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース |$O(n)$クエリごと |$O(n)$| 遅すぎる |
 | DFS + 深さリスト + プレフィックス数 |$O((n+q)\log n + 26q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ルートから DFS を実行して、各ノードの 2 つの値 (ノードの深さとオイラー エントリ時間) を計算します。 これにより、サブツリー構造が線形化され、すべてのサブツリーが DFS 順序の間隔になります。 
2. 深度値ごとに`d`、この深さにあるすべてのノードを収集します。 DFS エントリ時刻の昇順に保存します。 これにより、サブツリー制限がこのリスト内の連続セグメントに対応することが保証されます。 
3. すべての深さリストに対して、文字ごとに 1 つずつ、26 個のプレフィックス配列を構築します。 各プレフィックス配列を使用すると、任意のセグメント内の文字の出現を一定時間内にカウントできます。 
4. 各クエリについて`(u, d)`、深さでノードのセグメントを見つけます`d`入場時間が次の範囲にある場合`tin[u]`そして`tout[u]`二分探索を使用します。 
5. プレフィックスの違いを使用して、そのセグメント内の各文字の頻度を計算します。 
6. しましょう`k`このセグメント内のノードの総数になります。 もし`k == 0`、「いいえ」を出力します。 
7. もし`k`が奇数の場合、アンチ回文ではすべての位置を個別のパートナーとペアにする必要があるため、「No」が出力されます。 
8. それ以外の場合は、文字の頻度が次の値を超えているかどうかを確認します。`k / 2`。 そのような文字が存在する場合は「No」を出力し、存在しない場合は「Yes」を出力します。 

### なぜ効果があるのか

 DFS の順序付けにより、サブツリーのメンバーシップが間隔条件になることが保証されます。 深さのグループ化により、各クエリが単一のレイヤーに分離され、その構造はツリーに依存せず、DFS 順序の位置のみに依存します。 固定層内では、プレフィックス合計により、サブツリー スライスの周波数抽出が正確になります。 

反回文条件は、対称的なペアリング位置に帰着します。 すべてのポジションは個別のポジションとペアにする必要があるため、どのキャラクターもスロットの半分以上を独占することはできず、完全なペアには均等な長さが必要です。 これら 2 つの条件は、実現可能性を完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

s = input().strip()

tin = [0] * (n + 1)
tout = [0] * (n + 1)
depth = [0] * (n + 1)
timer = 0

nodes_by_depth = {}

def dfs(u, p):
    global timer
    timer += 1
    tin[u] = timer

    d = depth[u]
    if d not in nodes_by_depth:
        nodes_by_depth[d] = []
    nodes_by_depth[d].append(u)

    for v in g[u]:
        if v == p:
            continue
        depth[v] = d + 1
        dfs(v, u)

    tout[u] = timer

dfs(1, -1)

# build depth structures
depth_data = {}
for d, nodes in nodes_by_depth.items():
    nodes.sort(key=lambda x: tin[x])
    arr = [s[u - 1] for u in nodes]

    pref = [[0] * (len(nodes) + 1) for _ in range(26)]
    for i, ch in enumerate(arr, 1):
        for c in range(26):
            pref[c][i] = pref[c][i - 1]
        pref[ord(ch) - 97][i] += 1

    depth_data[d] = (nodes, pref)

def solve_query(u, d):
    if d not in depth_data:
        return False

    nodes, pref = depth_data[d]

    # find left bound: first tin >= tin[u]
    l, r = 0, len(nodes)
    while l < r:
        m = (l + r) // 2
        if tin[nodes[m]] >= tin[u]:
            r = m
        else:
            l = m + 1
    left = l

    # find right bound: last tin <= tout[u]
    l, r = 0, len(nodes)
    while l < r:
        m = (l + r) // 2
        if tin[nodes[m]] <= tout[u]:
            l = m + 1
        else:
            r = m
    right = l

    k = right - left
    if k == 0:
        return False
    if k % 2 == 1:
        return False

    for c in range(26):
        cnt = pref[c][right] - pref[c][left]
        if cnt > k // 2:
            return False

    return True

out = []
for _ in range(q):
    u, d = map(int, input().split())
    out.append("Yes" if solve_query(u, d) else "No")

print("\n".join(out))
```DFS セクションは、サブツリー クエリが範囲制約となる線形順序を構築します。 深さごとの前処理により、問題が独立した周波数配列に圧縮されます。 

各クエリ内で 2 つのバイナリ検索により、サブツリーとターゲットの深さの両方に属するノードが正確に分離されます。 プレフィックス配列により、セグメントをスキャンせずに正確なカウントが可能になります。 

最終チェックでは、偶数の長さと制限された頻度という、アンチ回文の構造的制約が実装されます。

 ## 特殊なケース

 ターゲットの深さにノードが存在しないサブツリー クエリは、二分探索後に空のセグメントになります。 その場合、計算された長さは`k`がゼロになると、アルゴリズムは直接「No」を返し、有効な再配置が存在しないという要件に一致します。 

単一ノードのセグメントは常に失敗します。`k = 1`、これは奇妙です。 このアルゴリズムは、周波数チェックを行わずに即座にそれを拒否し、セルフペア位置が反回文制約を満たすことができないことを正確に捕捉します。 

1 つの文字が深度スライス全体を支配するケース。`aaaaab`、をトリガーします`cnt > k/2`状態。 セグメントが十分に大きく、偶数の長さであっても、少なくとも 1 つのミラーリングされたペアが一致する必要があるため、拒否が必要であり、周波数境界によって正しく処理されます。
