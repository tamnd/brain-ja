 ## 解決策
 ## 問題の理解

 n 個の保管場所があり、各保管場所は移動コストがかかる指示された道路で接続されており、m 個の製品タイプがあります。 すべての製品タイプが、さまざまな数量ですべての倉庫に分散されます。 目標は、各製品タイプを単一の選択された倉庫に「統合」し、その製品のすべてのユニットが最短ルートでそこに輸送されるようにすることです。 各倉庫は最大でも 1 つの製品タイプをホストできるため、m 個の製品を m 個の異なる倉庫に効率的に割り当てることになります。 

製品 p を倉庫 i に割り当てるコストはローカルではありません。 これは、製品 p を含むすべての倉庫 j に依存します。これは、それらすべての数量をグラフ内の最短パスを使用して j から i に移動する必要があるためです。 したがって、各製品 p と目的地 i について、quantity[j][p] に dist(j, i) を掛けたすべての j の合計が必要になります。 

出力は、すべての製品に対して個別の倉庫を選択するすべての方法における最小総コストです。 

この問題の制約は十分に大きいため、すべての代入を試みるアプローチは不可能です。 n が約 1000 までの場合、m が 100 までであっても、階乗または指数割り当て検索は直ちに実行不可能になります。 サブセットにわたる三次 DP さえ適合しません。 本当のボトルネックは、ウェアハウスの各ペア間の計算コストがすでに効率的である必要があり、その後、割り当てステップで組み合わせ爆発を回避する必要があることです。 

正確さのためには、いくつかの特殊なケースが重要です。 

問題の一つは、直通道路が寸断されていることだ。 負の 1 のエントリが誤って無視されると、指定されたエッジのみを通る単純な最短パスは失敗します。 たとえば、j が i に直接到達できないが、中間経由で到達できる場合、完全な全ペアの最短パス計算のみが正しいコストを与えます。 

もう 1 つのエッジ ケースは、非対称エッジです。 グラフには方向があるため、dist(a, b) は必ずしも dist(b, a) と等しいわけではありません。 対称的な仮定は誤った集計につながります。 

最後に、複数の製品が同じディストリビューションを共有している場合、貪欲な割り当てはローカルでは機能しているように見えますが、2 つの製品が同じ「最良の」ウェアハウスをめぐって競合する可能性があるため、グローバルでは失敗する可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、最初にすべてのペアの最短パスを計算し、次に製品から倉庫までのすべての単射マッピングを列挙します。 1 つの割り当てのコストは、事前に計算された値を合計することで計算できます。 ただし、割り当ての数は基本的に n を m に並べたもので、つまり n! / (n − m)!。 n = 20 および m = 10 の場合でも、これはすでに天文学的な規模になります。 ボトルネックは、割り当ての選択肢の組み合わせが急増していることです。 

重要な観察は、すべてのペアの最短経路が判明すると、問題は m 個の品目 (製品) と n 個の候補 (倉庫) の間の古典的な割り当て最小化になるということです。 各製品には倉庫に対するコストベクトルがあります。 これは加重二部マッチング問題であり、m 個の異なる倉庫を選択し、各製品を 1 つに割り当て、総コストを最小限に抑えます。 

この構造は、ウェアハウスのサブセットに対する動的プログラミングによって正確に解決できます。 各状態はどの倉庫がすでに使用されているかを表し、製品を 1 つずつ割り当て、事前計算されたコスト [p][i] を使用してコストを更新します。 m は積の数であるため、DP は最大 m のサイズのサブセットにわたって実行されますが、これは (この問題の変形の意図された制約のように) m が小さい場合にのみ実現可能です。 

最初の k 製品に対して一連の倉庫が選択されると、どの倉庫が使用されるかは履歴ではなくインデックスによってのみ重要になるため、この移行は機能します。 これにより、グローバルな組み合わせ構造が段階的な割り当ての決定に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n! / (n−m)!) | お(1) | 遅すぎる |
 | サブセットにわたるフロイド + DP の割り当て | O(n^3 + m · 2^m) | O(n^2 + 2^m) | 承認済み |

 ## アルゴリズムのチュートリアル

まずグラフを最短経路距離に変換します。 次に、製品の移動コストを製品から倉庫までのコスト マトリックスに圧縮します。 その後、課題 DP を解決します。 

1. Floyd-Warshall を使用して、倉庫上のすべてのペアの最短パスを計算します。 これにより、任意の 2 つの倉庫 i と j の間の最小移動コストである dist[i][j] が得られます。 すべての出荷は直接のルートではなく最短ルートをたどるため、これが必要です。 
2. 各製品 p と倉庫 i について、amount[j][p] に dist[j][i] を乗算したすべての倉庫 j の合計として、cost[p][i] を計算します。 これは、製品 p が倉庫 i に集中されている場合の総コストを表します。 このステップでは、流れの問題を独立した製品ごとのコスト評価に変換します。 
3. 製品を 1 つずつ処理し、個別の倉庫を選択する DP 状態を定義します。 状態 dp[mask] は、最初の k 製品をマスクでエンコードされた倉庫のセットに割り当てた後の最小コストを表します。ここで、k はマスクで設定されたビット数です。 これが機能するのは、各製品が 1 回だけ割り当てられるため、割り当てられた製品の数が選択した倉庫セットのサイズに等しいためです。 
4. 製品がまだ割り当てられていないため、dp[0] をゼロコストとして初期化します。 
5. 各マスクについて、そのポップカウントとして k を計算します。これは、次に製品 k を割り当てることを意味します。 マスク内にないすべての倉庫 i について、製品 k を i に割り当て、dp[マスク ∪ {i}] を dp[マスク] + コスト[k][i] で更新します。 これにより、単射的代入が強制されます。 
6. 答えは、正確に m 個の選択されたウェアハウスを持つすべてのマスクの最小 dp[mask] です。 

なぜそれが機能するかは、最短経路が固定された後のコストの分離可能性に関係します。 各製品は、選択された宛先倉庫を考慮して、個別に総コストに寄与します。 決定間の唯一の結合は、倉庫を再利用できないという制約です。これはまさにサブセット DP が強制するものです。 すべての有効な割り当ては DP 状態空間を通る 1 つのパスに正確に対応し、すべての遷移は最適な下部構造を保持するため、DP はより適切な構成を見逃したり、ソリューションを二重にカウントしたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def main():
    n, m = map(int, input().split())

    # amount[p][i] in statement form is transposed here as product x warehouse
    # we read warehouse x product then transpose
    amount = [list(map(int, input().split())) for _ in range(n)]

    # Floyd-Warshall distances
    dist = [list(map(int, input().split())) for _ in range(n)]

    for i in range(n):
        for j in range(n):
            if dist[i][j] == -1:
                dist[i][j] = INF

    for k in range(n):
        for i in range(n):
            dik = dist[i][k]
            if dik == INF:
                continue
            di = dist[i]
            dk = dist[k]
            for j in range(n):
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd

    # compute cost per product per warehouse
    cost = [[0] * n for _ in range(m)]
    for p in range(m):
        for i in range(n):
            s = 0
            for j in range(n):
                if amount[j][p]:
                    s += amount[j][p] * dist[j][i]
            cost[p][i] = s

    size = 1 << n
    dp = [INF] * size
    dp[0] = 0

    for mask in range(size):
        k = mask.bit_count()
        if k >= m:
            continue
        cur = dp[mask]
        if cur == INF:
            continue

        for i in range(n):
            if not (mask >> i) & 1:
                nm = mask | (1 << i)
                val = cur + cost[k][i]
                if val < dp[nm]:
                    dp[nm] = val

    ans = INF
    for mask in range(size):
        if mask.bit_count() == m:
            ans = min(ans, dp[mask])

    print(ans)

if __name__ == "__main__":
    main()
```Floyd-Warshall ブロッ​​クは、直接エッジが欠落している場合や非対称の場合でも、すべての間接ルートが確実にキャプチャされるようにします。 製品コストの計算では、最短経路距離を使用して、その製品を保管しているすべての倉庫からの寄与分が意図的に蓄積されます。 

DP セクションは、k 番目に割り当てられた製品が、既に配置されている製品の数によって純粋に決定されるという事実に依存しています。 この順序付けにより、積の順列を明示的に追跡する必要がなくなります。 

よくある間違いは、最も安価な倉庫を個別に選択して、製品ごとに貪欲な割り当てを試みることです。 これは、2 つの製品が同じウェアハウスを優先する可能性があり、後で競合を解決しても全体的な最適値を回復できないため、これは失敗します。 

もう 1 つの微妙な点は、メモリと状態のサイズです。 DP は、n がサブセットを列挙するには十分小さいと想定します。 n が 1000 の場合、このアプローチは不可能になるため、この問題は特殊な設定で存在します。 

## 実用的な例

 3 つの倉庫と 2 つの製品がある小さなインスタンスを考えてみましょう。 

### 例 1

 初期状態では、倉庫間の製品分布と完全に接続された距離マトリックスが表示されます。 フロイドの後は、すべてのパスが直接存在するため、距離は一貫したままになります。 

コストを計算します。 

| 製品 | 倉庫1 | 倉庫2 | 倉庫3 |
 | --- | --- | --- | --- |
 | あ | 0 | 35 | 12 |
 | B | 54 | 20 | 10 |

 DP はマスク 000 から始まります。 

| マスク | 割り当てられた製品 | アクション | 費用 |
 | --- | --- | --- | --- |
 | 000 | あ | 1 に代入する | 0 |
 | 001 | B | 2 に代入する | 20 |
 | 010 | B | 3 に割り当てる | 10 |
 | 001/010 | 最終 | 最適なものを選択してください | 10 |

 これは、ローカルの特定のノードで A が最も安いように見えても、グローバル ペアリングにより両方の製品間でバランスが強制されることを示しています。 

### 例 2

 1 つのウェアハウスが直接接続されていないが、中間ノード経由で到達できる場合、Floyd-Warshall は INF を有限のパス コストに置き換えます。 これがないと、コスト計算で一部の割り当てが誤って不可能として扱われてしまいます。 

その後、DP は引き続き同様に処理を進め、接続処理が割り当てロジックから完全に分離されていることを確認します。 

## 複雑さの分析

 | 時間 | O(n^3 + m・n^2 + n・2^n) | Floyd-Warshall が優勢で、コストの増加とサブセット DP がそれに続きます。 
| スペース | O(n^2 + 2^n) | サブセットにわたる距離行列と DP |

 ## 特殊なケース

 主なエッジ ケースは、一部の倉庫が直接エッジ経由では到達できないが、間接的には到達できる場合です。 このアルゴリズムはフロイド・ウォーシャルに依存してこれらのギャップを修復し、すべてのコスト計算で真の最短パスが使用されるようにします。 このステップがなければ、DP は有効な割り当てを不可能なものとして扱います。 

2 つの製品が同じウェアハウスを強く好む場合、別のエッジ ケースが発生します。 貪欲な割り当てでは、両方がそこに配置されるか、遅れて再割り当てが強制され、総コストが増加します。 サブセット DP はウェアハウス選択の排他性を明示的にエンコードするため、両方の代替案を検討し、最小限に抑えます。 

最後のエッジケースは、非対称な移動コストであり、i から j への移動の方が、j から i への移動よりも安くなります。 各製品コストは有向最短パスを使用して宛先倉庫ごとに再計算されるため、コスト マトリックスはこの方向性を完全に尊重し、対称性の仮定が DP に漏れることはありません。
