 ## 問題の理解

 頂点に負でない重みを持つツリーが与えられます。 実行できる操作はエッジを削除することです。これにより、ツリーがいくつかの接続されたコンポーネントに分割されます。 結果として得られる各コンポーネントは、その頂点の重みを合計することによって評価され、そのような合計はすべて固定間隔内に収まる必要があります。$[L, R]$。 タスクは 1 つの構成を見つけることではなく、構成から削除されたすべての可能な数のエッジを決定することです。$0$まで$K$、結果として得られるすべてのコンポーネントが間隔制約を満たすように、正確にその数のエッジを削除できるかどうか。 

重要なオブジェクトはツリー構造だけではなく、パーティショニングの下で​​頂点の重みがどのように集約されるかです。 削除中$i$エッジは正確に生成します$i+1$したがって、ツリーを次のように分割できるかどうかが問題になります。$i+1$接続されたピースの合計重量は$[L, R]$。 

制約は、ほぼ線形または$O(n \cdot K)$テストアプローチごとに。 と$n \le 1000$そして合計$n$すべてのテスト ケースでも 1000 で制限され、$O(n^2)$テストごとは潜在的に許容されますが、すべてのパーティションを明示的に試行したり、エッジのサブセットを列挙したりすることは不可能です。 バウンド$K \le 50$これは決定的な構造上の制限です。これは、ソリューションが少数のカットを追跡する必要があることを示します。これは、おそらくツリーに対する動的プログラミングによって行われます。 

実現可能性について考えるとき、微妙な点が見えてきます。単純な考えは、サブツリーが超過するたびに貪欲に「カット」することです。$R$」または「到達するまでマージする」$L$” と考えましたが、決定がグローバルであるため、これは失敗します。サブツリーは、局所的に適合する場合でも、兄弟と結合することを強制される可能性があります。早期に切断すると、上位の実現可能性が損なわれる可能性があるためです。別の失敗モードは、サブツリーの独立性を仮定することです。合計が個別に有効である 2 つの子が、合計が違反する親コンポーネントに結合される可能性があります。$R$、完全に異なるカットの配置を強制します。 

たとえば、ノードに 2 つの子があり、各サブツリーの合計が以下の範囲内であると仮定します。$[L, R]$、しかし、それらを合わせると超えます$R$。 貪欲なボトムアップアプローチでは、両方のサブツリーを有効なコンポーネントとして受け入れる可能性がありますが、その上にエッジがカットされていない場合、親コンポーネントは制約に違反することになります。 これは、実現可能性がローカルではなくツリー全体にカットがどのように分散されるかによって決まることを示しています。 

## アプローチ

 ブルートフォース解釈では、エッジのすべてのサブセットを試し、接続コンポーネントを検証し、各コンポーネントの合計を計算し、妥当性をチェックします。 これには、$2^{N-1}$サブセット、およびサブセットごとに成分と合計を再計算します。$O(N)$、指数関数的な時間につながり、たとえ$N=1000$。 

より構造化されたブルート フォースは、ツリーをルート化し、各ノードがそのサブツリー内のカット数ごとにすべての可能な合計を計算する DP を試行することです。 This still explodes if sums are tracked naively because vertex weights go up to$10^{18}$したがって、すべての可能な合計を直接保存することは不可能です。 

重要な点は、合計の実際の数値を詳細に示す必要はないということです。 サブツリーが有効なコンポーネントを形成できるか、それとも上方にマージする必要があるか、およびサブツリー内で使用されるカットの数だけを知る必要があります。 これにより、問題はツリーのナップザックに変換されます。状態は、サブツリーで使用されるカットの数と、現在のサブツリーが「開いている」(まだ切り取られていない) か「閉じている」(すでに完全なコンポーネントを形成している)かを表します。 

これが機能する理由は、すべてのカットがツリーを独立した部分問題に縮小し、コンポーネントの合計に対する制約が子をマージする際の集計追跡のみを必要とするためです。 以来$K$が小さい場合、ノードごとの DP オーバーカット数を維持し、子の DP 状態を慎重に組み合わせることができます。

 ## アルゴリズムのチュートリアル

 便宜上、ノード 1 でツリーを任意にルート化します。各ノードについて$u$、次の DP テーブルを計算します。$dp[u][c]$のサブツリーを処理できるかどうかを説明します。$u$正確に使用して$c$コンポーネントが含むという制約の下で、その内部を切り取ります。$u$（「現在のオープンコンポーネント」）はまだ上向きに最終化されていません。 

各 DP 状態は、オープン コンポーネントの現在の累積重みが有効かどうかを暗黙的に追跡する必要もあります。 正確な合計を保存する代わりに、子をマージする際に実行可能間隔を維持します。 

計算は次のように進みます。 

1. 各ノードから開始します$u$子が含まれない基本状態として。 開成分の合計は最初は$A_u$、ゼロカットが使用されます。 これは次の場合にのみ有効です$A_u \in [L, R]$そうでない場合、ノードは上向きにマージされない限り、スタンドアロン コンポーネントになることはできません。 
2. 子を 1 つずつ処理します。 子を組み合わせる場合$v$の中へ$u$のすべての DP 状態について 2 つの可能性を考慮します。$v$。 エッジを切るか$(u, v)$、カット数を 1 つ増やして処理します。$v$のサブツリーを閉じたコンポーネントとして、またはそれをマージします$u$のオープンコンポーネントに、その重み寄与を追加します。 
3. マージするときは、累積オープンコンポーネントの合計が最大でも次の値にとどまることを確認する必要があります。$R$。 超えた場合$R$、そのマージは無効です。 合計が少なくとも$L$、後で閉鎖できるようになりますが、必ずしも直ちに閉鎖を強制するわけではありません。 私たちは実現可能性を保証するだけです。 
4. すべての子を処理した後、オプションで開いているコンポーネントを次の場所で「ファイナライズ」することができます。$u$その合計が以下にある場合$[L, R]$、または開いたままにして親に上方にマージします。 この柔軟性により、さまざまなカット数を正しく伝達することができます。 
5. DP トランジションは、カット寸法に対するナップザック スタイルの畳み込みを使用して、子全体でマージされます。$K$許可されたカット数を決して超えないようにします。 

ツリー全体を処理した後、ルート DP テーブルを検査します。 それぞれについて$i$から$0$に$K$、正確に使用して有効な構成が存在するかどうかを確認します$i$すべてのコンポーネントが適切に閉じられている (ぶら下がっている開いたコンポーネントが残っていない) 状態でカットします。 

### なぜ効果があるのか

 不変条件は、すべてのノードで$u$、DP は、そのサブツリーを正確に分割するためのすべての実行可能な方法を正確に表します。$c$内部の切断が行われており、切断されていない残りの部分は、接続された単一の接続された開いたコンポーネントです。$u$。 すべての有効なグローバル パーティションは、すべてのサブツリー境界でそのような構造を誘導する必要があります。これは、カットによってツリーが独立したコンポーネントに分割され、接続によってサブツリーごとに境界インターフェイスが 1 つだけ存在することが保証されるためです。 すべての組み合わせは、カット アカウンティングが保持された状態で子に対して探索されるため、実行可能な構成が失われることはなく、すべてのマージが優先されるため、実行不可能な構成も許可されません。$[L, R]$中間成分の合計に対する制約。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, K, L, R = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)

    INF = 10**30

    dp = [None] * n
    sumdp = [None] * n

    for u in reversed(order):
        # dp[u][c] = list of possible open sums or None
        dp[u] = [set() for _ in range(K + 1)]
        dp[u][0].add(a[u])

        for v in children[u]:
            newdp = [set() for _ in range(K + 1)]
            for cu in range(K + 1):
                for cv in range(K + 1 - cu):
                    if not dp[u][cu]:
                        continue
                    if not dp[v][cv]:
                        continue

                    # option 1: cut edge u-v
                    if cu + cv + 1 <= K:
                        newdp[cu + cv + 1].update(dp[u][cu])

                    # option 2: merge v into u
                    for su in dp[u][cu]:
                        for sv in dp[v][cv]:
                            if su + sv <= R:
                                newdp[cu + cv].add(su + sv)

            dp[u] = newdp

        # finalize option: if open sum in [L,R], we can close it (no extra cut)
        # represent closed state by leaving sum as valid marker
        for c in range(K + 1):
            dp[u][c] = set(x for x in dp[u][c] if x <= R)

    res = ['0'] * (K + 1)
    for c in range(K + 1):
        for s in dp[0][c]:
            if L <= s <= R:
                res[c] = '1'
                break

    print(''.join(res))

if __name__ == "__main__":
    solve()
```コードはポストオーダー トラバーサルを中心に構成されているため、すべてのノードはその子が完全に解決された後に処理されます。 各ノードの DP テーブルにはカット数によってインデックスが付けられ、各エントリには可能なオープンコンポーネントの合計が格納されます。 

2 つの遷移は、ツリー パーティションの 2 つの構造的選択に正確に対応します。つまり、子サブツリーが接続エッジを切断して独自のコンポーネントになるか、上向きにマージされて開いたコンポーネントの合計が増加します。 

実装でよくある落とし穴は、2 つの DP 状態をマージすると可能性が倍増するということを忘れていることです。 セットを使用すると重複した合計が回避されますが、依然として重くなる可能性があり、実際には、制約がより厳しい場合は、圧縮された合計よりもセットを積極的にプルーニングするか、ブール値の到達可能な配列に置き換えることになります。 

もう 1 つの微妙な問題は、カット数が次の値を超えないようにすることです。$K$。 すべてのマージ ステップでは慎重にインデックスを制限する必要があります。そうしないと、無効な状態が伝播し、誤検知が発生します。

 ## 特殊なケース

 重要なエッジケースは、すべての頂点の重みがゼロであり、$L=0, R=0$。 この状況では、すべての接続コンポーネントはサイズに関係なく有効であるため、最適な戦略はカットを完全に回避することですが、DP は依然としてすべての接続コンポーネントを正しく許可する必要があります。$K$余分なカットによって有効性が変わることはないため、可能な限り値を設定します。 マージは決して違反しないため、アルゴリズムがこれを処理します。$R$なので、すべての構成にアクセス可能な状態が維持されます。 

別のエッジケースが発生するのは次の場合です。$L$は大きく、単一の頂点のみが有効なコンポーネントを形成できます。 たとえば、すべての重みが 1 で、$L=5$、サイズが 1 より大きいコンポーネントは無効です。 DP では自然にすべてのエッジが強制的にカットされ、正確な結果が得られます。$N-1$カットを実行し、それより小さいカット数をすべて拒否します。 

3 番目のケースは、ノードの重みがすでに超過している場合です。$R$。 その場合、ノードを開いたコンポーネントに保持する状態は無効になります。 DP はそのような状態を即座に削除し、上向きマージに誤ってその状態が含まれないようにします。有効な構成は、このノードが縮退コンポーネントになる構成だけです。これは、状況に応じて可能かどうかが異なります。$L$。
