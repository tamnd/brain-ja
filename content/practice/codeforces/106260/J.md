 ## 解決策
 ## 問題の理解

 一定の長さの文字列を構築しています$n$正確に 4 文字を使用します。$y, u, k, o$。 この制限はローカルです。連続する 5 文字のブロックを見た場合、そのブロックは「yuuko」という単語の文字で形成されたマルチセットの順列であってはなりません。 

「ゆうこ」という文字には次の文字が含まれています$y, u, u, k, o$したがって、禁止されたブロックは正確に長さ 5 のウィンドウであり、そのウィンドウには 1 つのブロックが含まれます。$y$、 二$u$の、1つ$k$、そして1つ$o$、任意の順序で。 タスクは、有効な長さの文字列の数をカウントすることです。$n$この制約の下で存在するモジュロ$998244353$。 

主な問題点は、制限が正確な部分文字列に関するものではなく、スライディング ウィンドウ上の複数セットの条件に関するものであることです。 これにより、位置ごとに一致する固定パターンがないため、単純な部分文字列一致手法は効果がなくなります。 カウントだけが重要です。 

制約$n \le 10^{18}$長さにわたる線形または多項式の DP を即座に除外します。 どのようなソリューションでも、べき乗または別の対数手法を使用して遷移を反復できるように、状態を圧縮する必要があります。 唯一の実行可能な方向は、状態が文字列の制限された履歴のみに依存する有限オートマトンとしてプロセスをモデル化することです。 

複数の重なり合うウィンドウが同時に条件に違反する可能性がある場合、微妙なエッジ ケースが発生します。 たとえば、文字列は次の位置で無効になる可能性があります。$i$ですが、で終わる別の無効なウィンドウも含まれています。$i+1$。 正しい方法では、すべてのウィンドウが遡及的ではなく、形成時に正確にチェックされることを保証する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。$4^n$文字列を調べて、禁止されたウィンドウがないかどうかをそれぞれチェックします。 たとえ$n=20$、これはすでに実行不可能になっており、$n$まで$10^{18}$、それはまったく不可能です。 もう少し優れた総当たり手法では、接頭辞に対して動的プログラミングを使用し、最後の 4 文字を明示的に保存します。 これにより、状態遷移が管理可能なサイズに縮小されますが、依然として次の条件に応じて線形にスケールされます。$n$、これは大きすぎます。 

重要な点は、禁止条件は最後の 5 文字のみに依存するということです。 新しい文字を追加すると、その位置で終わるウィンドウのみが新たに無効になります。 これは、長さ 4 のスライディング ウィンドウを状態として維持することを示唆しています。 次の文字はサイズ 5 のウィンドウを完成させ、そのウィンドウが禁止されたマルチセットに一致するかどうかを直接テストできます。 

これにより、問題は次のような有限状態マシンに縮小されます。$4^4 = 256$可能な状態 (4 文字以上の長さのすべての可能なシーケンス)。 トランジションは、1 文字を追加し、ウィンドウを移動することによって決定されます。 以来$n$は巨大なので、長さの数を計算します-$n$行列のべき乗を使用してこのオートマトン内を歩きます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(4^n)$|$O(n)$| 不可能 |
 | DP オーバープレフィックス長 |$O(n \cdot 4^4)$|$O(4^4)$| 遅すぎる |
 | オートマトン + 行列のべき乗 |$O(256^3 \log n)$|$O(256^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 状態を文字列の最後の最大 4 文字として定義します。 各ポジションには 4 つの選択肢があるため、最大でも$4^4 = 256$州。 各状態を長さ 4 の Base-4 エンコードとして表します。 
2. 各状態および考えられる次の文字ごとに、文字を追加し、前の 4 文字と新しい文字で構成される新しい 5 文字ウィンドウを形成することをシミュレートします。 このウィンドウで文字数を計算します。 
3. これら 5 文字のマルチセットが正確に一致する場合$\{y, u, u, k, o\}$、この遷移を無効としてマークし、破棄します。 それ以外の場合は、現在の状態から左にシフトして新しい文字を追加することによって得られる新しい状態への有向遷移を追加します。 
4. これにより、最大 256 ノードの有向グラフが得られます。各ノードには最大 4 つの出力遷移があります。 これを遷移行列に変換します$T$、 どこ$T[i][j]$状態からの有効な遷移をカウントします$i$述べます$j$。 
5. すべての有効な開始状態を表すベクトルを初期化します。 4 文字より短い文字列は条件に違反できないため、すべての初期状態が許可されます。 
6. 計算する$T^n$高速累乗を使用します。 各乗算は、有効性を維持しながら文字列を拡張する方法の組み合わせに対応します。 
7. 最後に、結果のベクトルのすべてのエントリを合計して、有効な長さの文字列の総数を取得します。$n$。 

正確性は、各 DP 状態が、もう 1 文字の追加によって禁止された 5 長さのウィンドウが作成されるかどうかを判断するために必要なすべての情報を完全に取得するという不変条件に基づいています。 違反は出現した時点で正確に検出されるため、無効な文字列が DP に寄与することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# map characters to indices
mp = {'y': 0, 'u': 1, 'k': 2, 'o': 3}

def encode(s):
    x = 0
    for c in s:
        x = x * 4 + c
    while len(s) < 4:
        x *= 4
        s += [0]
    return x

def decode(x):
    s = []
    for _ in range(4):
        s.append(x % 4)
        x //= 4
    return tuple(reversed(s))

# forbidden multiset: y, u, u, k, o
forbidden = [0, 1, 1, 2, 3]

def is_bad(window):
    cnt = [0] * 4
    for c in window:
        cnt[c] += 1
    return cnt == [1, 2, 1, 1]

# build transitions
N = 256
T = [[0] * N for _ in range(N)]

for s in range(N):
    cur = decode(s)
    for c in range(4):
        window = list(cur) + [c]
        if is_bad(window):
            continue
        ns = tuple(list(cur[1:]) + [c])
        ns_id = 0
        for v in ns:
            ns_id = ns_id * 4 + v
        T[s][ns_id] += 1

def matmul(A, B):
    n = len(A)
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        for k in range(n):
            if Ai[k]:
                Bik = B[k]
                aik = Ai[k]
                for j in range(n):
                    res[i][j] = (res[i][j] + aik * Bik[j]) % MOD
    return res

def matpow(M, e):
    n = len(M)
    res = [[0]*n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1
    while e:
        if e & 1:
            res = matmul(res, M)
        M = matmul(M, M)
        e >>= 1
    return res

# initial vector: all states allowed
# we start from length 4 padding-free states, so treat all as 1
init = [1] * N

def solve(n):
    if n == 0:
        return 1
    if n <= 4:
        return pow(4, n, MOD)

    P = matpow(T, n - 4)

    ans = 0
    for i in range(N):
        for j in range(N):
            ans = (ans + P[i][j] * init[i]) % MOD
    return ans

n = int(input())
print(solve(n))
```このコードは、長さ 4 のすべての履歴にわたって明示的にオートマトンを構築します。 各トランジションでは、新しい文字を追加すると、結果として得られる長さ 5 のウィンドウ内に禁止されたマルチセットが作成されるかどうかがチェックされます。 行列のべき乗では、有効な長さのシーケンスがすべてカウントされます。$n$対数時間で。 

微妙な実装の詳細は次のとおりです。$n \le 4$、長さ 5 のウィンドウはまったく存在しないため、すべての文字列は有効であり、答えは単純です。$4^n$。 

## 実用的な例

 ### 例 1:$n = 5$長さ 4 の状態からの遷移を追跡し、1 文字を追加します。 

| ステップ | 現在の状態 | 追加された文字 | ウィンドウをチェックしました | 有効？ |
 | --- | --- | --- | --- | --- |
 | 1 | 任意の 4 文字の状態 | y | 最後の 5 文字 | 依存します |
 | 2 | 任意の 4 文字の状態 | あなた | 最後の 5 文字 | 依存します |
 | 3 | 任意の 4 文字の状態 | k | 最後の 5 文字 | 依存します |
 | 4 | 任意の 4 文字の状態 | o | 最後の 5 文字 | 依存します |

 この長さでは、オートマトンは、サイズ 5 のウィンドウに禁止されたマルチセットが出現する文字列が、形成された瞬間に 1 回だけ除外されることを保証します。 

これにより、すべての無効な構成が作成直後にフィルタリングされるという不変条件が確認されます。 

### 例 2:$n = 6$これで 2 つの重なり合うウィンドウが存在します: 位置$[1..5]$そして$[2..6]$。 文字列はどちらのウィンドウでも条件に違反する可能性があります。 

| ポジション | 新しい文字 | ウィンドウをチェックしました | アクション |
 | --- | --- | --- | --- |
 | 5 | c₅ | (1..5) | チェック済み |
 | 6 | c₆ | (2..6) | チェック済み |

 いずれかのウィンドウが禁止されたマルチセットに一致する場合、対応する遷移は許可されず、無効なプレフィックスの伝播が防止されます。 

これは、重複する違反が明示的な再チェックなしで自然に処理されることを示しています。
