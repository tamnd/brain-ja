 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、`n`モンスター、それぞれに初期エネルギーレベルがある`a_i`。 それらには次から番号が付けられています`1`に`n`、各モンスターは 1 ラウンドで時計回りの隣のモンスターを同時に攻撃します。 エネルギーを持ったモンスターの場合`x`エネルギーで隣人を攻撃する`y`、隣人の新しいエネルギーは`max(0, y-x)`。 攻撃によって攻撃者のエネルギーは減少しません。 ネネはこの「隣人を攻撃する」呪文を天文学的な回数、効果的に唱えます。`10^100`これにより、プロセスが安定することが保証されます。パターンが繰り返されると、モンスターのエネルギーがさらに減少することはありません。 

課題は、この安定化後もゼロ以外のエネルギーを持つすべてのモンスターを特定することです。 出力には、そのようなモンスターの数とそのインデックスがリストされている必要があります。 

制約は単純なシミュレーションを排除できるほど厳しいものです。 各テスト ケースには最大で次のものを含めることができます。`2*10^5`すべてのテスト ケースの合計は次のようになります。`2*10^5`。 シミュレートするブルートフォースアプローチ`10^100`ラウンドは無理です。 テスト ケースごとに線形時間で機能するアプローチが必要です。 エッジ ケースには、ゼロ エネルギーから始まるすべてのモンスター、ゼロで囲まれた最大エネルギーを持つ単一のモンスター、または円の周りに減少を伝播する均一なエネルギー レベルが含まれます。 

単純なシミュレーションでは、循環インデックスによる off-by-one エラーが発生する危険性もあります。 たとえば、最後のモンスターが最初のモンスターを攻撃するため、攻撃のスキップや二重カウントを避けるために慎重なモジュラー演算が必要です。 

## アプローチ

 ブルートフォースソリューションでは、すべての変更が安定するまで呪文を繰り返し適用します。 各モンスターは 1 回ずつ攻撃するため、各ラウンドには O(n) 時間がかかります。 たとえ安定化が起こったとしても、`O(n)`これにより、テスト ケースあたりの複雑さは O(n^2) になり、上限に対して遅すぎます。`2*10^5`。 

重要な観察は、各モンスターの最終的なエネルギーは、そのモンスター自身のエネルギーとその左隣のモンスターのエネルギーのみに依存するということです。これは、多くのラウンドの後、モンスターのエネルギーは、前任者からの繰り返しの攻撃によって、それ以上減らすことができなくなるまで減少するためです。 具体的にはモンスターの最終エネルギー`i`は`max(0, a[i] - a[i-1])`最弱のモンスターから始まる一定のローテーション。 これは、初期エネルギーが最も小さいモンスターがゼロ以下になることがなく、安定化の「起点」となるためです。 このピボットを選択すると、円の周りの 1 つの直線パスで各最終エネルギーを計算できます。 

線形時間ソリューションが機能するのは、エネルギー削減プロセスが単調であるためです。つまり、各攻撃が隣接するものを削減するか、ゼロのままにするかのいずれかです。 エネルギーは増加しないため、システムはすべてのラウンドをシミュレートしなくても計算できる固定点にすぐに収束します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(n^2) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期エネルギーが最小のモンスターを特定します。 このモンスターはゼロ以下に減ることはなく、安定した開始点として機能するため、そのインデックスが軸となります。 他のモンスターを選択すると、安定した状態に達するまでに追加の回転が必要になる場合があります。 
2. ピボットから開始して、円形の順序でモンスターを移動します。 モンスターごとに`i`、その最終エネルギーを次のように計算します。`max(0, a[i] - a[previous])`、 どこ`previous`は、このトラバースのすぐ反時計回り (左隣) のモンスターです。 これにより、すべての削減が正しい順序で考慮されるようになります。 
3. プラスの最終エネルギーを持つすべてのモンスターを収集します。 出力用にインデックス (1 から始まる) を保存します。 
4. 残りのモンスターの数とそのインデックスを昇順に出力します。 

それが機能する理由: 不変条件は、安定化後、各モンスターのエネルギーは、そのモンスター自身の初期エネルギーとその隣から伝播するエネルギーの最小値だけ減少するということです。 最小エネルギーのモンスターをピボットとして選択することで、モンスターのエネルギーが誤ってゼロ以下に減少しないことが保証され、減少の伝播は自然に循環依存関係を尊重します。 各エネルギーは 1 回だけ計算されるため、正しい最終状態が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        # find index of minimum element
        min_val = min(a)
        pivot = a.index(min_val)
        
        res = [0] * n
        prev = a[pivot]
        # traverse in circular order starting from pivot
        for i in range(1, n+1):
            idx = (pivot + i) % n
            res[idx] = max(0, a[idx] - prev)
            prev = a[idx]
        
        remaining = [i+1 for i, val in enumerate(res) if val > 0]
        print(len(remaining))
        if remaining:
            print(*remaining)

if __name__ == "__main__":
    solve()
```コードでは、まずテスト ケースの数を読み取ります。 テスト ケースごとに、ピボットとして使用するエネルギーが最小のモンスターを見つけます。 次に、単一の円周走査での安定化エネルギーを計算します。 最後に、ゼロ以外のエネルギーを持つモンスターのインデックスを収集します。 モジュロ演算により、off-by-one エラーのない循環アクセスが保証されます。 最終エネルギーのみを保存することで、不必要なスペースと計算を回避します。

 ## 特殊なケース

 すべてのモンスターがゼロ エネルギーから始まる場合、ピボット選択ではゼロが正しく識別され、計算されたすべての最終エネルギーはゼロになります。 入力用`0 0`、トラバースによって生成される`[0, 0]`、 その結果`0`残るモンスターたち。 1 つのモンスターがゼロで囲まれた非常に高いエネルギーを持っている場合、隣のモンスターの攻撃によって生き残ることができます。
