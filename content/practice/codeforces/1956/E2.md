 ## 解決策
 ## 問題の理解

 私たちには、エネルギーレベルを持つモンスターの輪が与えられています。 モンスターは固定された時計回りの順序で隣のモンスターを攻撃します。モンスター 1 がモンスター 2 を攻撃し、モンスター 2 がモンスター 3 を攻撃するというように、最後のモンスターが最初のモンスターを攻撃します。 攻撃は、攻撃者のエネルギーによって隣人のエネルギーを減らしますが、エネルギーがゼロになることはありません。 私たちは、非常に多くの攻撃を行った後でもどのモンスターがまだプラスのエネルギーを持っているかを判断するよう求められています。具体的には、$10^{100}$このプロセスの繰り返し。 

入力は複数のテスト ケースで構成されます。 各テスト ケースではモンスターの数を指定します$n$そして初期エネルギーレベル$a_1, a_2, \dots, a_n$。 攻撃が安定した後、出力には正のエネルギーを持つモンスターがリストされるはずです。 以来$n$まで可能です$2 \cdot 10^5$テスト ケースごとに、すべてのテスト ケースの合計は最大で$2 \cdot 10^5$、テスト ケースごとの複雑さが線形より悪いソリューションは、遅すぎる可能性があります。 シミュレーション中$10^{100}$直接ラウンドすることは不可能です。 反復せずに最終的なエネルギーレベルを予測する方法を見つけなければなりません。 

明らかではないエッジケースには、モンスターのエネルギーが非常に低く、その隣のモンスターのエネルギーが高いシナリオが含まれます。 たとえば、次の場合$a = [1, 10]$、最初のモンスターは最初の攻撃で2番目のモンスターを9未満に減らすことはできませんが、ラウンドを繰り返すと2番目のモンスターのエネルギーはゼロになるまで徐々に減少します。 もう 1 つのエッジ ケースは、すべてのモンスターのエネルギーがゼロである場合です。出力はモンスターがゼロになるはずです。 不用意に実装すると、攻撃の循環的な性質を忘れて、最初または最後のモンスターの計算が間違ってしまう可能性があります。 

## アプローチ

 ブルートフォースのアプローチはシンプルです。各攻撃ラウンドをシミュレートし、隣のモンスターの攻撃に応じてすべてのモンスターのエネルギーを更新します。 各ラウンドの後、エネルギーレベルが変化するかどうかを確認してください。 変化が止まったら、シミュレーションは安定しています。 このアプローチは原理的には正しいですが、特に次のような場合には、必要なラウンド数が膨大になる可能性があるため、実行不可能です。$n$そしてそのエネルギーは大きい。 テスト ケースごとに 100 万ラウンドでも遅すぎます。 

重要な観察は、各モンスターの最終エネルギーは、そのモンスター自身の初期エネルギーと、前のモンスターから受ける最大ダメージのみに依存するということです。 インデックスのモンスターの場合$i$、多くのラウンドの後、そのエネルギーは隣の攻撃後に残っているエネルギーを超えることはできません。 より正式には、モンスターの安定化エネルギー$i$前のモンスターのエネルギーを超えたエネルギーであり、ゼロ以下で区切られます。 つまり、それぞれのモンスターを知っていれば、$a_i$そしてその左隣$a_{i-1}$、無限ラウンド後の可能な最小エネルギーは次のとおりです。$\max(0, a_i - a_{i-1})$、攻撃が最適に伝播すると仮定します。 重要なのは、伝播によって循環依存関係が取り込まれるような開始点を選択することです。 

前のモンスターを考慮した後、最小のエネルギー差を持つモンスターから開始するように円を回転させると、計算は簡単になります。モンスターの最終的なエネルギーは、前のモンスターを超えたものになります。 円を合計すると、テスト ケースごとにどのモンスターが線形時間内に生き残るかを計算できます。

 ## アルゴリズムのチュートリアル

 1. 最小の初期エネルギーを持つモンスターを特定します。これは、循環伝播における安定したアンカーとして機能するためです。 最小限のエネルギーを選択すると、調整が必要なモンスターの数を減らすことができ、循環依存関係が簡素化されます。 
2. この最小のモンスターが概念的な線形配列の「最初」になるように配列を回転します。 この回転は概念的なものです。 物理的には、剰余インデックスを扱うことができます$n$。 
3. 各モンスターの最終エネルギーを、前のモンスターのエネルギーに対するそのエネルギーの超過として計算します。 数式を使用する$\text{final}_i = \max(0, a_i - a_{i-1})$、インデックスを剰余として扱う$n$サークルを守るために。 このステップにより、無限ラウンドの後、モンスターは隣のモンスターの攻撃後に残ったエネルギー以上のエネルギーを保持できないため、前のモンスターの攻撃の効果を正確に捉えることができます。 
4. 最終エネルギーがゼロより大きいすべてのモンスターを収集します。 これらは後に生き残るモンスターです$10^{100}$ラウンドします。 
5. 生き残ったモンスターの数とそのインデックスを昇順に出力します。 

それが機能する理由: 重要な不変条件は、無限ラウンドの後、どのモンスターも前任者の攻撃後に残ったエネルギーを超えるエネルギーを保持できないということです。 最小限のモンスターから開始することで、サークルの周りに伝播する可能性のあるアンダーフローを防ぎます。 max(0, ...) の式は、負のエネルギーがゼロにクランプされることを保証します。 他の回転では同じ結果が生成されるか、エネルギーを過剰にカウントすることになるため、これにより正確さが保証されますが、これは攻撃ルールでは不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        min_a = min(a)
        min_idx = a.index(min_a)
        
        # Rotate array to start from min energy monster
        rotated = a[min_idx:] + a[:min_idx]
        final_energy = [0] * n
        final_energy[0] = rotated[0]
        
        for i in range(1, n):
            final_energy[i] = max(0, rotated[i] - rotated[i-1])
        
        # Recover original indices for output
        result_indices = []
        for i, val in enumerate(final_energy):
            if val > 0:
                result_indices.append((i + min_idx) % n + 1)
        
        print(len(result_indices))
        if result_indices:
            print(' '.join(map(str, sorted(result_indices))))

if __name__ == "__main__":
    solve()
```コードはまずテスト ケースの数を読み取り、それらを反復処理します。 各テスト ケースについて、循環計算を固定するための最小のエネルギーを持つモンスターを特定します。 次に、前のモンスターとの差を使用して最終的なエネルギー値を計算します。 インデックスは元の配列に変換され、生き残ったモンスターが順番に出力されます。 

実装の微妙な選択には、インデックス変換のモジュロ演算と、max(0, ...) によるエネルギーのゼロへのクランプが含まれます。 Off-by-one エラーは、1 から始まるインデックスにマッピングし直すときによく発生します。
