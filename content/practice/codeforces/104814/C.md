 ## 解決策
 ## 問題の理解

 1 から n までの位置のラインが与えられ、各位置は必要な最小輝度を持ちます。 また、複数のランプがあり、各ランプは位置の連続したセグメントをカバーします。 すべてのランプに同じ電力値 x を割り当てると、各ランプはセグメント内のすべての位置に x の明るさを追加します。 したがって、その位置の最終的な明るさは、その位置をカバーするランプの数を x 倍したものになります。 

各位置 i について、ci がそれをカバーするランプの数である場合、その最終的な明るさは x · ci になります。 この値が少なくとも必要なしきい値 ai に達すると、ポジションは「良好」であると見なされます。 タスクは、少なくとも k 個の位置が適切になるように最小の非負の整数 x を選択することです。 そのような x が存在しない場合、答えは -1 になります。 

制約は最大 100,000 個の位置と 100,000 個のランプに達し、単純な方法で各候補 x について個別にカバレッジを再計算したり実現可能性をチェックしたりするソリューションは即座に除外されます。 x の位置と値に対する二次シミュレーションは不可能であり、二分探索ステップごとの線形スキャンでさえ慎重に最適化する必要があります。 

重要な微妙さは、位置がランプで覆われていないときに現れます。 その場合、ci はゼロなので、その明るさは x に関係なく常にゼロになります。 aiがポジティブであれば、そのポジションは決して良くなりません。 ai がゼロの場合、x = 0 であっても常に良好です。ci で除算するか、カバレッジがゼロの場合を無視する不注意な実装は、そのような入力では失敗します。 

もう 1 つの特殊なケースは、グローバルな実現可能性条件から生じます。 x が任意に大きい場合でも、ci > 0 (または ai = 0) の位置のみが満たされます。 このカテゴリに該当する位置が k 未満の場合、答えは -1 でなければなりません。 実現可能性をチェックせずにバイナリ検索のみを行うソリューションでは、誤った値が返されます。 

## アプローチ

 この強引なアイデアは、x の値を増やして、それぞれの値に対して適切な位置がいくつあるかを確認することです。 固定 x について、すべての位置のカバレッジ ci を計算し、x · ci ≥ ai を満たす i がいくつあるかを数えます。 ci は差分配列を使用して 1 回計算でき、評価は n にわたって線形であるため、これにはチェックごとに O(n + q) が必要です。 x が 109 まで上がる可能性がある場合、すべての値を試すことは不可能であり、答えが必ずしも小さいとは限らないため、早期に停止することさえも現実的ではありません。 

重要な観察は、各位置が独立して x のしきい値に寄与しているということです。 ci > 0 の位置の場合、条件 x · ci ≥ ai は x ≥ ceil(ai / ci) になります。 したがって、すべての位置が「アクティブ」になる最小 x を定義します。 ci = 0 および ai = 0 の場合、位置は常にアクティブです。 ci = 0 および ai > 0 の場合、アクティブになることはありません。 

これにより、問題は次のように変換されます。各位置 i には値 ti があり、これらの値の少なくとも k が ti ≤ x を満たすような最小の x が必要です。 これは古典的な単調なカウント条件であるため、すべての ti をソートし、x で二分探索を使用できます (またはプレフィックスを直接ソートしてカウントします)。 

効率的なciは依然として必要です。 ランプは同じ値 x の範囲加算であるため、最初に間隔にわたる差分配列を使用して各位置をカバーするランプの数を計算し、それを ci にプレフィックス合計します。 

すべての ti が計算されたら、それらを並べ替えて、少なくとも k 個の値が x 以下になるように最小の x を二分探索します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | x に対するブルート フォース | O(X・n) | O(n) | 遅すぎる |
 | プレフィックス カバレッジ + しきい値 + ソート + 二分検索 | O((n + q) + n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのランプ間隔にわたる差分配列を使用してカバレージ配列 ci を構築します。 各間隔 [l, r] によって範囲カウンターが増加し、プレフィックスの合計により位置ごとの正確なカバレッジに変換されます。 これが必要なのは、各位置の寄与がその位置に含まれる間隔の数にのみ依存するためです。 
2. すべての位置をスキャンし、実現可能性を確認します。 位置が ci = 0 かつ ai > 0 である場合、満足することは不可能であるとマークします。 潜在的に満たせる位置がいくつあるかを数えます (ci > 0 または ai = 0)。 このカウントが k 未満の場合は、無限の x でも役に立たないため、すぐに -1 を返します。 
3. すべての位置について、必要な起動しきい値 ti を計算します。 ci = 0 の場合、ai = 0 の場合は ti は 0、それ以外の場合は無限大になります。 ci > 0 の場合、ti = ceil(ai / ci) を計算します。 この値は、この位置を適切にする最小の x を表します。 
4. すべての有限 ti 値を配列に収集します。 ti = 0 の位置も常に良好であるため、同様に含まれます。 
5. しきい値の配列を並べ替えます。 並べ替え後、特定の x が機能するかどうかを確認すると、≤ x である値の数をカウントすることになり、これが接頭辞インデックスとなります。 
6. [0, max_t] の範囲で x を二分探索します。ここで、max_t は最大の有限しきい値です。 各候補 x について、upper_bound ロジックを使用して ≤ x である ti がいくつあるかを計算します。 このカウントが少なくとも k であれば、x は実現可能であり、より小さい値を試します。 それ以外の場合は、x を増加します。 
7. 二分探索中に見つかった実行可能な最小の x が答えになります。 

正確さは、「少なくとも k 個のしきい値が ≤ x」という述語の単調構造から得られます。 ある x で位置が良好になると、x は輝度を線形に増加させるだけであるため、それより大きな値すべてにおいて良好な状態が維持されます。 この単調性により、二分探索で遷移を見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    q = int(input())

    diff = [0] * (n + 2)
    for _ in range(q):
        l, r = map(int, input().split())
        diff[l] += 1
        diff[r + 1] -= 1

    c = [0] * n
    cur = 0
    for i in range(n):
        cur += diff[i + 1]
        c[i] = cur

    t = []
    possible = 0

    INF = 10**30

    for i in range(n):
        if c[i] == 0:
            if a[i] == 0:
                t.append(0)
                possible += 1
            else:
                continue
        else:
            possible += 1
            need = (a[i] + c[i] - 1) // c[i]
            t.append(need)

    if possible < k:
        print(-1)
        return

    t.sort()

    def ok(x):
        l, r = 0, len(t)
        while l < r:
            m = (l + r) // 2
            if t[m] <= x:
                l = m + 1
            else:
                r = m
        return l >= k

    lo, hi = 0, max(t) if t else 0
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、各間隔が O(1) 時間で寄与するように、標準の差分配列を使用してカバレッジを構築することから始まります。 プレフィックス再構成ステップは、各セグメントを反復処理せずに範囲更新を位置ごとのカウントに変換するため、非常に重要です。 

しきい値の計算では、カバレッジがゼロのケースが慎重に分離されます。 ci = 0 および ai > 0 の位置はしきい値として無視されますが、それでも実現可能性に影響します。 この分離により、ゼロ除算の論理エラーが防止されます。 

しきい値配列をソートすると、実現可能性チェックがプレフィックス数の問題に変換されます。 ヘルパー関数は手動バイナリ検索を実行して、≤ x であるしきい値の数をカウントし、スキャンの繰り返しを回避します。 

外部二分探索では、実現可能性述語の単調性を利用して、要件を満たす最小の x を見つけます。 

## 実用的な例

 ### 例 1

 カバレッジによってポジション間で異なる感度が生じる小さな例を考えてみましょう。 

最初に ci を計算し、次にしきい値を計算してから、x を検索します。 

| ポジション | ci | あい | ティ |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 0 |
 | 2 | 1 | 5 | 5 |
 | 3 | 1 | 5 | 5 |
 | 4 | 2 | 8 | 4 |
 | 5 | 1 | 3 | 3 |
 | 6 | 1 | 6 | 6 |

 ソートされたしきい値は [0、3、4、5、5、6] になります。 少なくとも k = 3 個の位置が必要です。 

x = 4 をチェックすると、4 つのしきい値 ≤ 4 が得られるため、機能します。 これより小さい x は 3 つの適切な位置に達しないため、答えは 4 になります。 

このトレースは、各位置がどのようにして必要なアクティベーション レベルに独立して変換されるか、またグローバル要件がどのようにプレフィックス カウントの問題になるかを示します。 

### 例 2

 ここで、カバレッジが不十分なために実現可能性が満たされない場合を考えてみましょう。 

| ポジション | ci | あい | ティ |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | インフ |
 | 2 | 0 | 2 | インフ |
 | 3 | 0 | 0 | 0 |
 | 4 | 1 | 10 | 10 |

 常に満たされる位置は 2 つだけです。位置 3 は常に、位置 4 は最終的には満たされます。 k = 3 の場合、x の値は要件を満たすことができません。 

これは、二分探索の前に実行可能性チェックが必要な理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q + n log n) | 差分配列の構築、プレフィックスの合計、ソートしきい値、二分探索 |
 | スペース | O(n) | カバレッジとしきい値を保存する |

 ## 特殊なケース

 位置がランプで決して覆われていないが、正の明るさが必要な場合、アルゴリズムは、その位置を満足可能な位置のプールから明示的に除外します。 実行可能性のチェック中、そのような位置により可能な総数が減少し、k に到達できなくなる場合、アルゴリズムは -1 で早期終了します。

すべての位置が均一にカバーされている場合、ci はすべてのインデックスにわたって一定です。 各しきい値は ai の単純なスケーリング値になり、ソートされた構造により問題は、二分探索で正確に捕捉される、カバレッジで割った k 番目に小さい要件を選択するという問題に軽減されます。
