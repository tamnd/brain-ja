 ## 解決策
 ## 問題の理解

 各テスト ケースに対して、以下と呼ばれる非負の整数の 3 つのリストが与えられます。`A`、`B`、 そして`C`。 次のようなリストの場合`A = [a1, a2, ..., ak]`、そのスコアを次のように定義します

 [
 P(A)=a_1!\cdot a_2!\cdots a_k!。 
】

 タスクは、3 つのリストのどれが最大のスコアを持つかを判断することです。 2 つまたは 3 つのスコアすべてが等しく、最大値で同点の場合、必要な答えは次のとおりです。`TIE`。 

入力はテスト ケースの数から始まります。 各テスト ケースでは 3 つのリスト サイズが示され、その後に 3 つのリストの要素が続きます。 各要素は以下にあります`2501`。 公式声明では、2 つの製品が異なる場合、その相対的な違いは少なくとも以下であることも保証されています。`0.01%`より大きな製品の。 

重要な制約は、`2500`階乗積の大きさではなく、個々の値に基づいて。 平`2500!`通常の整数演算で明示的に構築するには大きすぎます。 技術的には Python の整数で表現できますが、そのような階乗を多く含む積の構築と乗算を繰り返すと、数値が膨大になり、演算コストがますます高くなります。 1 秒の制限により、ソリューションはこれらの製品の実現を回避する必要があります。 入力自体を読み取る必要があるため、効率的なアルゴリズムは基本的にリスト要素の総数が線形である必要があります。 

単純な実装が何も言わずに失敗する可能性があるエッジケースがいくつかあります。 考慮する```
1
1 1 1
0
1
0
```スコアは`0! = 1`、`1! = 1`、 そして`0! = 1`したがって、出力は次のようになります```
Case #1: TIE
```を扱う実装`0!`ゼロは間違った選択をするだろうから`B`。 

もう一つのケースは、```
1
2 1 1
2 2
3
2
```ここ`P(A)=2!*2!=4`、`P(B)=3!=6`、 そして`P(C)=2!=2`、したがって、答えは次のとおりです```
Case #1: B
```各リストの最大の要素のみを比較する不注意な実装では、誤った選択が発生します。`A`なぜならその最大の要素は`2`、しかし積はすべての階乗に依存します。 

3 番目のエッジ ケースは完全に同点です。```
1
1 2 1
3
2 1
3
```両方`A`そして`C`スコアがある`3!`、 その間`B`もっている`2!*1!=2`、結果は次のようになります```
Case #1: TIE
```出力は`TIE`たとえ結合されたリストに同じ要素が含まれていないとしてもです。 比較は、結果として得られた製品間で行う必要があります。 

## アプローチ

 ブルートフォースアプローチは数学的定義に直接従います。 あらゆる価値観に対して`x`、計算します`x!`、対応するリストに対してこれらの階乗を乗算し、結果として得られる 3 つの整数を比較します。 これは、問題で定義された 3 つの量を正確に構成するため、正しいです。 

難点は数字の大きさです。 リストに次のものが含まれる場合`m`価値観、そしてあらゆる価値観は`2500`各階乗を個別に計算すると、おおよその時間がかかります`2500m`掛け算。 3 つのリスト全体で、これは大まかに次のとおりです`7500m`リストのサイズが同等の場合の乗算。 さらに深刻なのは、中間整数自体が数百桁または数千桁の長さであり、そのような値を多数乗算すると、各算術演算のコストが増大するということです。 最終製品の保管も注文だけで済むので手間がかかりません。 

この問題を解決する観察は、対数をとった後に乗算が加算になるということです。 

\log(a_1!)+\log(a_2!)+\cdots+\log(a_k!)。 
】

 対数は厳密に増加しているため、最大の対数スコアを持つリストは、まさに最大の元の積を持つリストです。 事前計算ができる

 [
 L[x]=\log(x!)
 】

 あらゆる人にとって`x`から`0`を通して`2500`。 再発

 [
 L[x]=L[x-1]+\log x
 】

 テーブル全体を線形時間で計算します。 

この場合、各リストでは要素ごとに 1 回の加算のみが必要になります。 階乗や階乗積を構築することはありません。 

さまざまな製品に関する保証があるため、ここでは浮動小数点比較が適切になります。 少なくとも次の相対的な差`0.01%`およその対数差に相当します

 [
 \log(1.0001)\約 10^{-4}。 
】

 合計に蓄積される浮動小数点誤差は、現実的な入力サイズの分離よりもはるかに小さいため、小さな比較許容値で、数学的に等しい積を同点として扱いながら、真に異なる積を区別できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2500S) の算術ステップ、巨大な整数コスト | O(S) プラス巨大な整数 | 遅すぎる |
 | 最適 | O(2500 + S) | O(2500) | 承認済み |

 ここ`S`1 つのテスト ケースの 3 つのリスト内の要素の合計数です。 最適な方法では次のような方法も使用されます。`math.lgamma(x + 1)`別の入手方法として`log(x!)`ただし、累積対数を事前に計算すると、意図した再帰が明確になり、特殊な関数を繰り返し評価する必要がなくなります。 

## アルゴリズムのチュートリアル

 1. 事前計算`log_fact[x]`すべての整数に対して`x`から`0`に`2500`。 から始める`log_fact[0] = 0`、 なぜなら`0! = 1`そして`log(1) = 0`。 あらゆる人にとって`x > 0`、 セット`log_fact[x] = log_fact[x - 1] + log(x)`。 これにより、階乗自体を構築することなく、すべての階乗の対数が得られます。 
2. 3 つのリスト サイズを読み取り、次に 3 つのリストを読み取ります。 サイズは各リストに属する値の数を正確に示すため、リストの値が複数の物理入力行に分割されている場合でも入力を消費できます。 
3. 各リストに次を追加します。`log_fact[x]`あらゆる価値観に対して`x`その中で。 結果として得られる合計は、そのリストの階乗積の対数です。 
4. 3 つの対数スコアの最大値を見つけます。 対数は順序を維持するため、最大スコアは元の積の最大値に対応します。 
5. 小さな許容誤差を使用して、すべてのスコアを最大値と比較します。 最大値の許容範囲内にある 3 つの値がすべて同値であるとみなされる場合は、次のように出力します。`TIE`; それ以外の場合は、一意の最大リストの名前を出力します。 
6. すべてのテスト ケースに対してこれを繰り返し、答えの前に 1 から始まるケース番号を付けます。 

機能する理由: リストを処理した後、その累積値は正確に

 \log\left(\prod_{x\in A}x!\right)。 
】

 したがって、3 つの累積値は、必要な 3 つの積の対数を表します。 対数は厳密に増加しているため、それらの順序は元の積の順序と同じです。 問題の分離保証により、2 つの異なる積が浮動小数点比較で混同されるほど近くにならないようにする一方で、等しい積は等しい数学的対数和を生成し、同点として扱われます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

MAXV = 2500
EPS = 1e-10

# log_fact[x] = log(x!)
log_fact = [0.0] * (MAXV + 1)
for x in range(1, MAXV + 1):
    log_fact[x] = log_fact[x - 1] + math.log(x)

def read_list(n):
    values = []
    while len(values) < n:
        values.extend(map(int, input().split()))
    return values[:n]

def solve():
    t = int(input())
    out = []

    for case_no in range(1, t + 1):
        sizes = []
        while len(sizes) < 3:
            sizes.extend(map(int, input().split()))

        na, nb, nc = sizes[:3]

        A = read_list(na)
        B = read_list(nb)
        C = read_list(nc)

        scores = [
            sum(log_fact[x] for x in A),
            sum(log_fact[x] for x in B),
            sum(log_fact[x] for x in C),
        ]

        mx = max(scores)

        tied = sum(abs(score - mx) <= EPS for score in scores)

        if tied >= 2:
            answer = "TIE"
        elif scores[0] == mx:
            answer = "A"
        elif scores[1] == mx:
            answer = "B"
        else:
            answer = "C"

        out.append(f"Case #{case_no}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```事前計算により、すべてのテスト ケースで使用されるテーブルが作成されます。 最初のエントリはゼロです。なぜなら、`0!`の対数です`1`。 後続の各エントリは追加するもののみを追加します`log(x)`、再発を正確に反映しています`x! = x * (x - 1)!`。 

の`read_list`helper は、ステートメントで各リストが 1 つの入力行を占めるものとして記述されているため注意に値しますが、堅牢な競技プログラミング コードはその書式設定の詳細に依存すべきではありません。 要求された数の値を収集するまで読み取りを続けます。 

3人`sum`式は、積から和への中心的な変換を実装します。 階乗は構築されないため、Python の任意精度の整数機構は、関連する膨大な値を処理する必要がありません。 

比較では、対数の絶対許容誤差が使用されます。 の相対的な違い`0.01%`異なる積間の対数ギャップは、ほぼ次の対数ギャップに相当します。`1e-4`、 一方`1e-10`何桁も小さいです。 したがって、許容差は保証された分離を十分に下回ります。 

の`0!`そして`1!`どちらの場合も、事前計算されたテーブルにすでに正しく表示されているため、特別な分岐は必要ありません。 また、すべての値が に格納されているため、整数オーバーフローの心配もありません。`scores`は階乗積ではなく浮動小数点の対数です。 

## 実用的な例

 公式声明にはリストの例が示されています`A = {2,4,7}`、`B = {0,1,9}`、 そして`C = {2,3,5,5}`。 実際の彼らの製品は、`241920`、`362880`、 そして`172800`、それぞれなので、`B`が一番大きいです。 

トレースの場合、関連する対数状態は次のとおりです。 

| リスト | 値 | 対数スコア | 相対的な結果 |

 | C | 2、3、5、5 |`log(2!) + log(3!) + log(5!) + log(5!)`| について`12.059`|

 最大値は次のスコアです`B`したがって、出力は次のようになります`Case #1: B`。 トレースは、アルゴリズムが直接保存するには厄介な量を比較できる理由を示しています。元の積はすでに数十万であるのに、その対数は小さな浮動小数点数のままです。 

2 番目の例では、厳密な結合を実行します。```
1

4
```州は、

 | リスト | 値 | 階乗積 | 対数スコア |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(2500 + S) | 事前計算は最大値において線形であり、各リスト要素は 1 つのテーブル検索と 1 つの加算に寄与します。 
| スペース | O(2500) | 階乗対数テーブルには、考えられる入力値ごとに 1 つの浮動小数点値が含まれています。
