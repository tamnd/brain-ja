 ## 解決策
 ## 問題の理解

 (0) から (N-1) までの番号が付けられた (N) 個の位置を持つ円形アリーナがあります。 すべての位置は、次のように書かれる岩のいずれかです。`R`、または池、と書かれています。`P`。 カエルはどの岩からでもスタートできます。 

ジャンプの長さ (K) を選択すると、ジャンプするたびにカエルが位置 (i) から位置 (i) に移動します。 

[
 (i+K)\bmod N.
 】

 カエルは開始位置に戻るまで、まさにこのジャンプを繰り返します。 ジャンプの長さは、戻る前に訪れたすべての位置も岩であるような開始岩が少なくとも 1 つ存在する場合に有効です。 (1) から (N-1) までの範囲内で有効な個別の (K) がいくつあるかを数える必要があります。 公式の制約には (3\le N\le10^5) があり、時間制限は 1 秒、メモリ制限は 256 MB です。 

サイズ (N=10^5) は、ジャンプの長さ、開始位置、訪問位置のすべての組み合わせを検査するアルゴリズムを直ちに除外します。 3 次の上限はすでに (10^{15}) 演算程度になります。 同じ (K) モジュロ (N) を繰り返し加算する算術構造を利用する必要があります。 

よくある間違いを明らかにするいくつかの特殊なケースがあります。 たとえばすべての位置が岩だとしたら`RRR`、 (K=1) と (K=2) の両方が機能するため、答えは次のようになります。`2`。 特定の 1 つのジャンプ長だけをチェックするソリューションでは、ゼロ以外の長さはすべて機能するという事実を見逃してしまいます。 

たとえばすべての位置が池の場合`PPP`、答えは`0`。 合法的な開始位置はまったく存在しないため、位置 (0) が有効な開始岩であると仮定するソリューションは、ジャンプを検査する前に失敗する可能性があります。 

開始点は任意の岩にすることができますが、必ずしも位置 (0) である必要はありません。 のために`PRRR`、(K=2) は位置 (1) から開始して機能します。カエルは位置 (1) と (3) (両方の岩) を訪れ、(1) に戻ります。 したがって、正しい答えは、`1`。 常に位置 (0) から開始する実装では、(K=2) が誤って拒否されます。 

最後に、ジャンプの長さ自体は、訪問した個別の位置の数と同じではありません。 のために`RRPR`, (K=2) は位置 (0,2,0,\ldots) を訪問するので有効ですが、(K=1) と (K=3) はすべての位置を訪問し、位置 (2) で池に遭遇します。 正しい答えは、`1`。 違いは、(K) と (N) の最大公約数から生じます。 

## アプローチ

 最も直接的な強引な解決策は、すべての (K) を試し、可能なすべての開始岩を試し、カエルが開始位置に戻るか池に着地するまでジャンプをシミュレートすることです。 各シミュレーションでは最大 (N) 個の位置を検査できるため、リテラル実装には (O(N^3)) の上限があります。 (N=10^5) の場合、最大 (10^{15}) 個の候補位置チェックが行われることになり、利用可能な時間をはるかに超えます。 

この強引な攻撃が機能するのは、それがカエルの行動に正確に従うためですが、本質的に同じ循環構造を何度も繰り返すからです。 重要な観察は、(N) を法として (K) を繰り返し加算しても、位置の任意のサブセットが生成されないということです。 その構造は完全に決定されます

 [
 g=\gcd(K,N)。 
】

 位置 (s) から開始し、ジャンプ後 (t) にカエルがいる位置

 [
 s+tK\pmod N.
 】

 (tK\pmod N) のすべての値は (g) の倍数であり、シーケンスが (s) に戻る前に (g) のすべての倍数が発生します。 その結果、カエルは (s) モジュロ (g) に一致する位置を正確に訪問します。 

これにより問題が大幅に変わります。 すべての (K) を個別にチェックする代わりに、(N) の約数 (g) に岩石だけを含む剰余クラス モジュロ (g) が少なくとも 1 つあるかどうかを尋ねることができます。 そのようなクラスが存在する場合、(N) との最大公約数が (g) であるすべてのジャンプ長が有効になります。 

固定除数 (g) の場合、(g) を法とするどの残基に池が含まれているかを検査するだけで済みます。 池の位置の中で残留物がまったく発生しない場合、その残留物クラスのすべての位置は岩石であるため、そのクラスから任意の岩石を選択すると、有効な開始点が得られます。 

(10^5) までの数の約数は少数しかありません。 (N) の約数を列挙し、それぞれをテストし、最後にすべての (K) を (\gcd(K,N)) によって分類します。 (N) のこの範囲の約数は最大約 128 個であるため、結果として得られる (O(N\tau(N))) スタイルの作業は簡単に管理できます。(\tau(N)) は (N) の約数の数です。

 | 最適 | (O(N\タウ(N)+N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 円形の文字列を読み取り、すべての池の位置のインデックスを記録します。 残基クラスは池が含まれていない場合にのみ有効であるため、池の位置のみが必要です。 
2. (N) のすべての約数 (g) を生成します。 (\gcd(K,N)) として現れるのは除数のみであるため、非除数をテストすると不必要な作業が行われます。 
3. すべての適切な約数 (g<N) について、すべての池の位置を法 (g) で考慮します。 (r\pmod g) と一致する位置に池がある場合は、残差 (r) をマークします。 
4. 少なくとも 1 つの剰余剰余 (g) がマークされていない場合は、(g) が有効であると宣言します。 その残骸には池がまったくないため、その中のすべての位置が岩であり、カエルはそこから始めることができます。 
5. 池の位置が (g) よりも少ない場合は、直ちに (g) が有効であると宣言します。 (g) 残留物クラスはありますが、(g) 池よりも少ないため、池はすべての残留物クラスを占有することはできません。 
6. (1) から (N-1) までのすべてのジャンプ長 (K) について、(g=\gcd(K,N)) を計算します。 (g) が有効とマークされた場合は、回答に 1 を追加します。 

ステップ 6 で十分な理由は、解の中心不変式です。(\gcd(K,N)) の同じ値を持つすべてのジャンプ長は、まったく同じタイプの剰余クラスを訪問します。 (N) を伴う gcd が固定されると、実際の数値は問題になりません。 

### なぜ効果があるのか

 (g=\gcd(K,N)) とし、開始位置を (s) とします。 (t) ジャンプ後、カエルは (s+tK\pmod N) を占めます。 (K=gK') と (N=gN') (K') と (N') は互いに素であるため、シーケンス (tK'\pmod{N'}) は (N') を法とするすべての残基を訪問します。 (g) を掛けることは、カエルが訪れた元の位置が正確であることを意味します。 

[
 s、\ s+g、\ s+2g、\ldots
 】

 円の周り。

したがって、カエルは、少なくとも 1 つの剰余クラス モジュロ (g) が完全に岩で構成されている場合に正確に練習セッションを完了できます。 私たちの除数テストはその条件を正確にチェックし、最後の gcd 計算は可能なすべての (K) を正しいクラスに割り当てます。 したがって、カウントされたすべてのジャンプ長は有効であり、すべての有効なジャンプ長がカウントされます。 

## Python ソリューション```python
import sys
from math import gcd, isqrt

input = sys.stdin.readline

def solve_string(s: str) -> int:
    n = len(s)

    ponds = [i for i, ch in enumerate(s) if ch == 'P']

    # If there are no ponds, every non-zero jump length works.
    if not ponds:
        return n - 1

    # Generate all divisors of n.
    divisors = []
    for d in range(1, isqrt(n) + 1):
        if n % d == 0:
            divisors.append(d)
            if d * d != n:
                divisors.append(n // d)

    can_jump = [False] * (n + 1)
    pond_count = len(ponds)

    for g in divisors:
        # gcd(K, n) can never equal n for 1 <= K < n.
        if g == n:
            continue

        # With fewer ponds than residue classes, some residue is pond-free.
        if pond_count < g:
            can_jump[g] = True
            continue

        seen = bytearray(g)
        covered = 0

        for p in ponds:
            r = p % g
            if not seen[r]:
                seen[r] = 1
                covered += 1

                # Every residue contains a pond, so no all-rock class exists.
                if covered == g:
                    break

        can_jump[g] = covered < g

    answer = 0

    for k in range(1, n):
        if can_jump[gcd(k, n)]:
            answer += 1

    return answer

def main():
    s = input().strip()
    print(solve_string(s))

if __name__ == "__main__":
    main()
```の`ponds`配列には、残差クラスを無効にする可能性のある位置が正確に格納されます。 貯蔵池にその残留物がない場合、残留物モジュロ (g) は良好です。 

除数の生成は (\sqrt N) までのみです。 いつ`d`分割する`n`、 両方`d`そして`n // d`等しい場合を除いて、これらは約数です。 除数 (N) はジェネレータによって保持されますが、必要な範囲の (K) に (\gcd(K,N)=N) がないため、後で無視されます。 

の`pond_count < g`ショートカットは概念的にも実際的にも役立ちます。 残基クラスよりも池の数が少ないため、すべての残基クラスに池を含めることは不可能であるため、少なくとも 1 つのクラスには岩だけが含まれている必要があります。 

の`bytearray`ブール値フラグのコンパクトな配列として使用されます。`seen[r]`池が残留クラス (r) に出現したかどうかを記録します。 すべての (g) 残基が池で覆われるとすぐに、除数は無効であることがわかり、スキャンが停止することがあります。 

最後のループでは、`math.gcd`直接。 Python の整数では、すべての値が最大 (10^5) であるため、オーバーフローの問題は発生しません。 

## 実用的な例

 サンプル 1 の場合、アリーナは次のとおりです。`RRR`。 池がないため、可能なジャンプの長さはすべて即座に有効になります。 

| (K) | (\gcd(K,3)) | 有効？ | 理由 |
 | --- | --- | --- | --- |
 | 1 | 1 | はい | 訪れた場所はすべて岩です。 
| 2 | 1 | はい | 訪れた場所はすべて岩です。 

答えは`2`。 このトレースは、すべて岩のショートカットを示しています。 

サンプル 2 の場合、アリーナは次のとおりです。`RRPR`。 

| (K) | (\gcd(K,4)) | 適切なスタートから訪れた残留物 | 有効？ |
 | --- | --- | --- | --- |
 | 1 | 1 | すべてのポジション | いいえ、位置 2 は`P`|
 | 2 | 2 | 1 剰余クラス モジュロ 2 | はい、位置 0 と 2 は`R`|
 | 3 | 1 | すべてのポジション | いいえ、位置 2 は`P`|

 (g=2) の場合、2 つの剰余クラスは ({0,2}) と ({1,3}) です。 (2)の位置に池があるので第1種は使えませんが、第2種は岩ばかりです。 したがって、(K=2) が機能し、答えは次のようになります。`1`。

 ## 特殊なケース

 のために`PRRR`、正しい出力は次のとおりです。`1`。 唯一有効なジャンプ長は (K=2) です。 (N=4) の gcd は (2) であるため、2 を法とする 2 つの残基クラスのいずれかを参照します。位置 (1) から開始すると、岩石のみを含むサイクル (1\rightarrow3\rightarrow1) が得られます。 位置 (0) は池であるため、位置 (0) から開始すると失敗します。 このアルゴリズムは固定の開始点を選択しないため、適切な残基クラスを正確に検出します。 

のために`PPP`、正しい出力は次のとおりです。`0`。 すべての位置が池であるため、すべての可能な残基クラスには池が含まれます。 すべての適切な約数 (g) について、すべての (g) 残基クラスは池の位置によってマークされます。`can_jump[g]`偽のままです。 ジャンプの長さはカウントされません。 

のために`RRR`、正しい出力は次のとおりです。`2`。 アルゴリズムは、除数処理を実行する前にオールロック ショートカットに到達し、(N-1=2) を返します。 これは、ジャンプがすべてのポジションを訪れる可能性がある場合もカバーします。そのような訪問を違法にする池がないためです。 

のために`RRPR`、正しい出力は次のとおりです。`1`。 除数 (g=1) は、その唯一の残基クラスに位置 (2) の池が含まれるため、無効です。 剰余 (1) には位置 (1) と (3) (両方とも岩) が含まれるため、除数 (g=2) は有効です。 (N=4) では gcd (4) をもつ (K<N) がないため、除数 (g=4) は無視されます。 (K=1,2,3) のうち、(K=2) だけが gcd (2) を持つため、最終的な答えは正確に次のようになります。`1`。
