 ## 解決策
 ## 問題の理解

 私たちにはいくつかの独立したサッカーグループが与えられています。 各グループには、一意の名前が付けられたチームのセットと、すでに行われた試合のコレクションが含まれています。 すべての試合について、私たちは両チームとその最終スコアを把握しています。 

これらの結果から、完全な順位表を作成する必要があります。 すべてのチームについて、総得点、総失点、勝ち数、負け数、引き分け数、累積ポイントが必要です。 各チームに勝利すると 3 ポイント、引き分けでは 1 ポイント、負けると 0 ポイントが与えられます。 

次に、チームは 4 つの基準によって並べ替えられます。 より多くのポイントが優先されます。 勝ち点が等しい場合は、得点差から失点数を差し引いた得点差が大きい方が優先されます。 それも等しい場合は、より多くのゴ​​ールを獲得したチームが優先されます。 すべての数値基準が等しい場合、チーム名のアルファベット順が最終的な順序を決定します。 必要な出力では、グループが入力順に出力され、各グループの後に空の行が残ります。 元の問題では、最大 30 チーム、グループあたり 400 ゲームが指定されており、Codeforces では C++ の時間制限が 1 秒、メモリ制限が 256 MB となっています。 

これらの境界は十分に小さいため、直接シミュレーションとその後の並べ替えよりも高度なものは必要ありません。 すべてのゲームを 1 回処理する場合でも、コストはわずか O(G) であり、最大 30 チームのソートには O(T log T) のコストがかかります。 チーム間の 2 次比較もこれらの範囲では小さいですが、通常の並べ替えがランキング ルールを直接表現する場合、これを使用する理由はありません。 

不注意な実装により、誤って間違ったテーブルが生成されるケースがいくつかあります。 引き分けの場合は、最初にリストされているチームだけでなく、両方のチームが更新される必要があります。 例えば、```
1
2 1
A B
A 0 B 0
```生成する```
Group 1:
A 0 0 0 0 1 1
B 0 0 0 0 1 1
```ゼロゼロの結果を最初のチームの負けとして扱う解決策は、間違った結果と間違ったポイントの両方を与えることになります。 

勝利した場合は、結果カテゴリーとは別にゴールの合計も更新する必要があります。 例えば、```
1
2 1
A B
A 3 B 1
```生成する```
Group 1:
A 3 1 1 0 0 3
B 1 3 0 1 0 0
```ポイントと勝利のみを記録し、ゴールを忘れるソリューションでは、得失点差のタイブレーカーを正しく計算できません。 

最後に、同点だけでは順位を決定するのに十分ではありません。 考慮する```
1
3 2
ALPHA BETA GAMMA
ALPHA 2 BETA 0
GAMMA 1 BETA 0
```正しい順序は、アルファ、ガンマ、ベータです。 ALPHAとGAMMAはともに勝ち点3だが、得失点差はALPHAが+2、GAMMAが+1となっている。 ポイントのみでソートするソリューションでは、任意の順序または入力依存の順序が維持され、必要なランキングに失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチは、すべてのチームの記録を維持し、すべての試合を処理することです。 試合ごとに、両方のチームを検索し、得点と失点を追加し、スコアに応じて勝ち、負け、引き分け、およびポイントを更新します。 すべての試合が処理されたら、すべてのチームのペアを比較し、最も優れた残りのチームを繰り返し選択することでランキングを決定できます。 最終テーブルのすべての統計は個々の試合結果によって独立して決定されるため、これは正しいです。 

最大 30 チームと 400 試合の場合、試合処理でもグループあたりの更新はわずか 400 回です。 すべてのペアを比較する真に単純なランキングのコストは O(T²) で、これはグループあたり最大 900 ペアの比較に相当します。 これらの特定の境界では、それでも問題なく通過します。 ただし、これは不必要な複雑さであり、同じアイデアをより大きな順位の問題に適用すると魅力が薄れます。 

よりクリーンなアプローチは、最終出力と並べ替えルールに必要なすべての統計によって各チームを表し、すべてのゲームを 1 回だけ処理し、その後 1 つの標準並べ替えを使用することです。 重要な観察は、ランキング基準が辞書編集的な順序を形成しているということです。 これらをソートキーとして直接エンコードできます: 得点の降順、得失点差の降順、得点の降順、名前の昇順。 Python のソート機構は、すべての同点のケースを一貫して処理します。 

各試合が独立して 2 つのチームに寄与するため、ブルート フォースは機能しますが、そのペアごとのランキング ステップでは、最終的な順序が固定された比較キーのシーケンスによってすでに記述されているという事実を利用していません。 ランキング ルールが 1 つの辞書編集キーを形成するという観察により、はるかに単純な正当性推論により、最終フェーズが O(T log T) に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(G + T²) | O(T) | 指定された範囲で受け入れられます |
 | 最適 | O(G + T log T) | O(T) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グループの数を読み取り、各グループを個別に処理します。 すべてのグループの統計を別々に保つことで、あるグループの結果が別のグループに影響を与えることを防ぎます。 
2. チーム名を読み、各チームの統計レコードを作成します。 最初は、一致がまだ処理されていないため、すべてのカウントはゼロです。 
3. すべての試合について、2 つのチーム名とそのスコアを読み上げます。 最初のスコアを最初のチームの得点と 2 番目のチームの失点に加算します。 2 番目のチームに対して対称更新を実行します。 どちらが勝ったとしても、これら 4 つの目標の更新が必要です。 
4. 2 つのスコアを比較します。 最初のスコアの方が大きい場合、最初のチームの勝利、2 番目のチームの損失を加算し、最初のチームに 3 ポイントを与えます。 2 番目のスコアの方が大きい場合は、対称更新を実行します。 スコアが同じ場合、両チームの引き分けカウントを増やし、各チームに 1 ポイントを与えます。 
5. すべての試合の処理が完了したら、チームの記録を得点の降順、得失点差の降順、得点の降順、チーム名の昇順に並べ替えます。 最初の 3 つの基準では、値が大きいほど良いため降順を使用しますが、名前には通常のアルファベットの昇順が使用されます。 
6. グループヘッダーを印刷し、その後にチームごとに 1 行をソート順に印刷します。 各行にはチーム名、得点、失点、勝ち、負け、引き分け、得点が含まれます。 グループの後に空白行を 1 行出力します。

重要な不変条件は、試合のプレフィックスを処理した後、各チームの保存された統計が、処理された試合でのパフォーマンスを正確に記述することです。 試合では、参加する 2 チームのみが変更され、勝ち、負け、引き分けなどのあらゆる結果が得点ルールに従って双方に更新されます。 したがって、最終試合後の記録には完全な順位統計が含まれます。 ソートキーはまさに問題の優先順位のランク付けルールであるため、ソートされた順序が必要な最終順位となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    test_cases = int(input())
    output = []

    for group_id in range(1, test_cases + 1):
        team_count, game_count = map(int, input().split())
        names = input().split()

        stats = {}
        for name in names:
            stats[name] = {
                "gf": 0,
                "ga": 0,
                "w": 0,
                "l": 0,
                "d": 0,
                "p": 0,
            }

        for _ in range(game_count):
            team1, score1, team2, score2 = input().split()
            score1 = int(score1)
            score2 = int(score2)

            a = stats[team1]
            b = stats[team2]

            a["gf"] += score1
            a["ga"] += score2
            b["gf"] += score2
            b["ga"] += score1

            if score1 > score2:
                a["w"] += 1
                b["l"] += 1
                a["p"] += 3
            elif score1 < score2:
                b["w"] += 1
                a["l"] += 1
                b["p"] += 3
            else:
                a["d"] += 1
                b["d"] += 1
                a["p"] += 1
                b["p"] += 1

        ordered = sorted(
            names,
            key=lambda name: (
                -stats[name]["p"],
                -(stats[name]["gf"] - stats[name]["ga"]),
                -stats[name]["gf"],
                name,
            ),
        )

        output.append(f"Group {group_id}:")
        for name in ordered:
            s = stats[name]
            output.append(
                f"{name} {s['gf']} {s['ga']} "
                f"{s['w']} {s['l']} {s['d']} {s['p']}"
            )
        output.append("")

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```の`stats`辞書は、各チーム名をその 6 つの可変統計にマップします。 すべての試合で予想される O(1) 時間以内に両方のチームを見つけることができるため、すべての試合のチーム リストを検索するよりも辞書を使用することをお勧めします。 

目標の更新は結果の比較の前に行われます。 これにより、ゴールの統計が勝ち、負け、引き分けのロジックから独立した状態に保たれ、ゴールを更新せずに引き分けが処理されるというよくある間違いが防止されます。 

Python の場合、ソート式では負の数値が使用されます。`sorted`関数はデフォルトで昇順にソートします。 したがって`-points`より大きなポイント合計が最初に配置され、`-goal_difference`そして`-goals_for`次の 2 つの基準についても同じことを行います。 チーム名は変更されず、最後のタイブレーカーのアルファベット順が与えられます。 

出力順序はソートされた順序に基づいて決まります。`names`辞書自体ではなくリストです。 これにより、並べ替えルールが明示的になり、辞書の反復動作に依存することがなくなります。 Python の整数には任意の精度もあるため、ゴールやポイントを蓄積するときに整数オーバーフローの心配はありません。 

## 実用的な例

 最初のサンプルには 2 つのグループが含まれています。 最初のグループでは、KASNIA が LATVERIA に 0-1 で負けました。 第 2 グループでは、6 試合で 4 チームの最終順位が決まります。 

グループ 1 の場合、唯一一致した後の関連する状態は次のとおりです。 

| チーム | GF | GA | W | Ｌ | D | P |
 | --- | --- | --- | --- | --- | --- | --- |
 | カスニア | 0 | 1 | 0 | 1 | 0 | 0 |
 | ラトベリア | 1 | 0 | 1 | 0 | 0 | 3 |

 3 ポイントは 0 より大きいため、ソート キーは LATVERIA を最初に置きます。結果の出力は次のようになります。```
Group 1:
LATVERIA 1 0 1 0 0 3
KASNIA 0 1 0 1 0 0
```実際に提供されたサンプルでは、2 番目のグループは次の最終状態に達します。 

| チーム | GF | GA | W | Ｌ | D | P |
 | --- | --- | --- | --- | --- | --- | --- |
 | アメリカ | 5 | 1 | 1 | 0 | 2 | 5 |
 | イングランド | 5 | 2 | 1 | 0 | 2 | 5 |
 | スロベニア | 4 | 3 | 1 | 1 | 1 | 4 |
 | アルジェリア | 1 | 4 | 0 | 2 | 1 | 1 |

 アメリカとイングランドはともに勝ち点５、得失点差は４。 また、両者とも 5 ゴールを決めたため、最終的な名前の比較では、アルファベット順で ENGLAND が USA よりも前になります。 提供されたサンプル出力では、代わりに USA が ENGLAND の前に配置されており、公開されたステートメントに記載されているアルファベット順のタイブレーカーと一部のミラーによって再現されたサンプルとの間に不一致が明らかになります。 コンテストの公式声明は、提出する際に権威あるものとして扱われる必要があります。 アーカイブされた問題ステートメントには、最終的なタイブレーカーとしてアルファベット順のチーム名が示されています。 

2 番目の有用なトレースは描画です。これは更新の両側を実行するためです。 

| 一致 | チーム | GF | GA | W | Ｌ | D | P |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | A0B0 | あ | 0 | 0 | 0 | 0 | 1 | 1 |
 | A0B0 | B | 0 | 0 | 0 | 0 | 1 | 1 |

 2 つのレコードは対称のままです。 これは、ドロー ブランチが結果を一方のチームだけに割り当てるのではなく、両方のチームを更新する必要がある理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(G + T log T) | すべてのゲームが 1 回処理され、最大で T チームのレコードが並べ替えられます。 
| スペース | O(T) | チームごとに 1 つの統計レコードが保存されます。 

T が最大 30、G が最大 400 の場合、アルゴリズムは、各グループに対して数百回の一致更新と非常に小規模な並べ替えのみを実行します。 1 秒の制限と 256 MB のメモリ制限により、この実装にはかなりの余地が残されています。

 ## 特殊なケース

 ゼロゲームの場合は特別な分岐なしで処理されます。 のために```
1
1 0
SOLO
```統計レコードはすべてのフィールドが 0 に等しい状態で作成され、試合ループは実行されず、単一チームが次のように出力されます。`SOLO 0 0 0 0 0 0`。 重要な特性は、初期化がすでにゲームを行っていないチームを表していることです。 

ドローケースは次を使用します```
1
2 1
A B
A 0 B 0
```目標の更新により、両チームの得点数は 0 得点、反対得点数は 0 となりました。 スコアが等しいため、両方のドロー カウンタが 1 になり、両方のポイント合計が 1 になります。結果のラインは次のようになります。`A 0 0 0 0 1 1`そして`B 0 0 0 0 1 1`。 1 つのチームのみを更新するブランチは、すべての試合が両方の参加者に結果をもたらすという不変条件に違反します。 

などの一方的な勝利```
1
2 1
A B
A 3 B 1
```A を 3 得点、1 得点、1 勝、勝ち点 3 に更新します。 B はミラーリングされたゴール合計、1 敗、0 ポイントを受け取ります。 並べ替えキーは A の 3 点を見て、A を最初に置きます。 ランキングの決定自体はすでにポイントによって決定されている場合でも、ゴールの合計は更新されます。 

最後のタイブレーカーは次のように分離できます。```
1
4 4
A B C D
A 2 B 0
C 2 D 0
