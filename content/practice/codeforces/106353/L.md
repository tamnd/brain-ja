 ## 解決策
 ## 問題の理解

 クリスマス音楽チャートのトップ 10 にランク付けされたものがいくつかあります。 各チャートには、1 位 (最高) から 10 位までの順序で 10 人のアーティスト名が含まれています。同じアーティストが、同じチャート内および異なるチャートに複数回表示される場合があります。 

すべてのチャートを組み合わせて、各アーティストが合計でどのくらいの頻度で登場するかをカウントします。 その合計頻度が主なスコアになります。 複数のアーティストが同じ合計頻度を共有している場合は、すべてのチャートでそのアーティストが 1 位に表示される頻度を調べることで比較を絞り込みます。 それでも同点の場合は、2 位、次に 3 位のカウントを比較し、10 位まで続けます。これらのカウントがすべて 2 人以上のアーティストで同一の場合、単一の勝者は存在せず、出力は「同点」でなければなりません。 

したがって、各アーティストは実質的に 11 の整数のベクトル (合計出演数と 10 の位置カウント) によって表されます。 比較はこのベクトルの辞書順に行われます。 

制約は小さく、それぞれのサイズが 10 のリストが最大 100 個です。つまり、全体でエントリが最大 1000 個になります。 各エントリを 1 回または一定の回数だけ処理するソリューションであれば、簡単に十分です。 すべてのアーティストを繰り返しスキャンしても問題ありませんが、その必要はありません。 

単純な間違いは、合計数のみを使用することから発生します。 たとえば、2 人のアーティストがそれぞれ 3 回登場し、一方のアーティストが常にリストの上位にランクされている場合、答えは同点ではありません。 もう 1 つの微妙な間違いは、合計数と位置数の両方に複数回寄与するため、同じリスト内の繰り返し出現を無視することです。 

エッジケースは簡単ですが、注目に値します。 単一のリストは、位置タイブレークを使用して、そのリスト内で最も頻繁に使用されるアーティストが答えになることを意味します。 もう 1 つのエッジ ケースは、すべてのアーティストが同じ回数出演し、同じ位置分布を持ち、「同点」につながる場合です。 最後に、1 人のアーティストの総出演回数は少ないものの、1 位の回数が多数発生することはありません。これは、総数が常に優先するという厳密な辞書編集ルールにより起こりません。 

## アプローチ

 直接的なアプローチは、すべてのエントリを処理し、アーティストごとの頻度構造を維持することです。 出現ごとに、合計カウントとその位置に対応するカウントの両方が増加します。 処理後、すべてのアーティストを比較して最適なものを見つけます。 

これは正しいです。ルールは純粋に加算的であり、集計されたカウントのみに依存するためです。 ただし、各アーティストのカウントを個別に再計算するなど、より冗長なことを試みたとしても、入力全体を繰り返しスキャンすることになり、個別のアーティストの数に対して不必要な二次関数の動作が発生します。 

重要な観察は、すべてのアーティストはサイズ 11 の固定長ベクトルで完全に記述でき、比較は辞書式であるということです。 これにより、1 回のパスですべてを計算し、単一の比較ルールを使用して最大値を選択することができます。 

したがって、タスクは、アーティスト名からそのベクトルまでの辞書を構築し、次に最大ベクトルを選択して、最大値が一意であるかどうかを追跡することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | アーティストごとのブルート フォース再計算 | O(U * N * 10) | お(う) | 遅すぎる |
 | シングルパス集約 + 最大選択 | O(N * 10) | O(U * 11) | 承認済み |

 ここで、U は個別のアーティストの数、N はリストの数です。 

## アルゴリズムのチュートリアル

 入力に対して 1 回のスイープで頻度情報を構築し、スコア ベクトルの辞書編集的な比較によって最高のアーティストを決定します。

1. リストの数 n を読み取ります。 これにより、処理する 10 エントリのグループの数が決まります。 
2. 各アーティスト名をゼロに初期化された 11 個の整数の配列にマッピングする辞書を作成します。 最初のエントリは出現回数の合計を表し、次の 10 は位置 1 ～ 10 のカウントを表します。 
3. 各リストについて、10 人のアーティスト名を順番に読み上げます。 
4. 0 から 9 までの各位置 j について、合計カウントをインクリメントし、位置 j+1 のカウントもインクリメントすることで、対応するアーティストのベクトルを更新します。 位置インデックスは、タイブレークに必要なランキング情報をエンコードするため重要です。 
5. すべてのリストを処理した後、すべてのアーティストを反復処理し、ベクトルの辞書編集的な比較を使用して最適な候補を計算します。 現在の最良のベクトルと、それが一意であるかどうかを示すフラグの両方を維持します。 
6. 別のアーティストが現在の最良のベクトルと正確に一致する場合、結果があいまいとしてマークされます。 
7. スキャン後、一意の場合はアーティスト名を出力し、一意でない場合は「tie」を出力します。 

### なぜ効果があるのか

 各アーティストは、ランキング ルールで使用されるすべての関連情報の決定的な概要にマッピングされます。 最終スキャンで使用される比較手順は問題の定義と同じです。つまり、合計周波数が優勢であり、位置周波数が厳密な順序で同点を解決します。 すべての出現がベクトルの正しいコンポーネントに正確に 1 回カウントされるため、情報が失われることはありません。 したがって、これらのベクトルに対する辞書編集上の最大値は、まさに、説明した排除手順で勝利するアーティストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    stats = {}

    for _ in range(n):
        arr = input().split()
        for i, name in enumerate(arr):
            if name not in stats:
                stats[name] = [0] * 11
            stats[name][0] += 1
            stats[name][i + 1] += 1

    best_name = None
    best_vec = None
    unique = True

    for name, vec in stats.items():
        if best_vec is None:
            best_vec = vec
            best_name = name
            unique = True
        else:
            if vec > best_vec:
                best_vec = vec
                best_name = name
                unique = True
            elif vec == best_vec:
                unique = False

    if unique:
        print(best_name)
    else:
        print("tie")

if __name__ == "__main__":
    solve()
```このソリューションは、各アーティストが固定サイズのリストを保存する辞書を保持します。 インデックス 0 は合計出現回数を累積し、インデックス 1 ～ 10 は位置固有のカウントを追跡します。 この構造はランキング ルールに直接一致するため、比較は単一の辞書編集ベクトル比較になります。 

選択フェーズは、辞書編集的な順序付けをすでに実行している Python のネイティブ リスト比較に依存します。 等価性の検出は不可欠です。最適なベクトルが見つかった場合でも、それが一意であることを検証する必要があります。

 ## 特殊なケース

 最小限の単一リストのケースでは、位置カウントが正しく適用されているかどうかをテストします。 入力用`a a a a a a a a a a`、同じアーティストがすべてのポジションと合計カウントを蓄積し、アルゴリズムがすぐにそれを最良のものとして選択します。 

完全に等しいケースは、2 人のアーティストが同一の分布ベクトルを持つ場合に発生します。 すべての位置パターンが 2 つの名前間で完全に一致する入力の場合、両方のベクトルが同一になり、比較によって等しいことが検出され、出力は「同点」になります。 一致性が観察されるたびに一意性追跡が更新されるため、スキャンではいず​​れかが早まって選択されることはありません。 

多くの異なるアーティストがいるが、あるアーティストが初期のポジションで優勢であるケースは、辞書編集的な比較によって最初に合計カウントが優先され、次にポジション 1 が優先されるため、自然に処理されます。これにより、低いポジションの利点がより強い優先順位の高い信号を無効にすることができないようになります。
