 ## 解決策
 ## 問題の理解

 各ボスには価値があります`c[i]`。 ボスを倒すと、現在のボーナスをスコアとして獲得し、そのボスによってボーナスが変更されます。`c[i]`。 

リセットがない場合、ボスの順序によってそれぞれの回数が完全に決まります。`c[i]`将来のスコアに貢献します。 正の値は後の多くの報酬を増やすため、通常は早めに適用する必要がありますが、負の値は通常遅らせる必要があります。 

リセット操作は興味深い展開を生み出します。 リセットすると現在のボーナスはゼロに戻りますが、倒されたボスは倒されたままとなり、累積スコアは保持されます。 せいぜいリセットするかもしれないので`k`場合によっては、一連のボス戦のシーケンス全体が効果的に最大で 2 つに分割されます。`k + 1`独立したセグメント。 各セグメント内では、ボーナスが通常通り蓄積されます。 セグメント間ではボーナスはクリアされます。 

すべてのボスを一度だけ倒した後、可能な限り最大の合計スコアが必要です。 

制約は最初の大きな手がかりです。 まであります`5 * 10^5`上司と`5 * 10^5`許可されたリセット。 順列、位置に関する動的プログラミング、さらには`O(n^2)`移行は絶望的です。 50 万個の要素があるため、何か必要になります`O(n log n)`。 

いくつかの特殊なケースは見落とされがちです。 

考慮する```
1 100
-5
```答えは`0`。 

リセットが何枚あってもボスは一人しかいない。 応募前に現在のボーナスを獲得します`-5`, したがってスコアは変わりません。 

考慮する```
3 2
-1 -2 -3
```答えは`0`。 

1 つのボスと戦い、リセットし、別のボスと戦い、リセットして最後のボスと戦います。 すべての戦いにはボーナスが発生します`0`したがって、すべての報酬は`0`。 リセットが正の累積後にのみ有効であると想定するソリューションでは、これが見逃されます。 

考慮する```
4 0
10 -100 10 10
```元の順序のままでは答えは得られません。 順序は完全に私たちの制御下にあり、最適な配置はその自由を活用する必要があります。 

問題全体は実際には、値を配置し、リセットがシーケンスを分割する場所を決定することです。 

## アプローチ

 ブルートフォースの見方は簡単です。 ボスの順序を選択し、リセットが発生する位置を選択し、プロセスをシミュレーションして、最良の答えを維持します。 

これは文字通りすべての有効な戦略を列挙しているため、これは正しいです。 

残念ながら、`n!`リセット場所を検討する前でも可能な順序付けが可能です。 のために`n = 5 * 10^5`、これは天文学的な数字を超えています。 

構造を見つけるために、2 つのリセットの間の固定セグメントに注目してみましょう。 

セグメントに値が含まれているとします。```
a1, a2, ..., am
```この順番で処理すると、`a1`次のボーナスに影響します`m - 1`戦い、`a2`次に影響する`m - 2`喧嘩など。 

セグメントの貢献度は、```
a1(m-1) + a2(m-2) + ... + am(0)
```係数は左から右に減少します。 

これは直ちに交換引数を意味します。 2つの値が満たされる場合`x > y`、配置`x`早い位置ほど係数が大きいため、早いほうが問題になることはありません。 

したがって、すべてのセグメントは非昇順で並べ替える必要があります。 

次に、グローバルに考えてみましょう。 私たちはせいぜい`k + 1`セグメント。 並べ替えると、各セグメントは単に減少するシーケンスになります。 

各セグメントを現在の合計がそのセグメント内の累積ボーナスに等しい山として想像してください。 

新しい値をセグメントに配置すると、その値は現在のパイル合計を正確に答えに反映します。 その後、パイル合計は挿入した値だけ増加します。 

最大の値を最初に割り当てる必要があります。 すべてのボス値をグローバルに降順に並べ替えた後、それらを 1 つずつ処理します。 

いつでも私たちは`k + 1`セグメントの合計。 次の値の直接の寄与を最大化するには、現在の合計が最大であるセグメントにその値を配置する必要があります。 次に、その現在の合計が答えに加算されます。 

これにより、問題が貪欲なプロセスに変わります。`k + 1`セグメントの合計。 

セグメントの合計を最大ヒープに保持します。 最初は全部`k + 1`セグメントには合計があります`0`。 

各値を降順に並べると、次のようになります。 

1. 現在のセグメント合計の最大値を取得します。`s`。 
2.追加`s`答えに。 
3. そのセグメントに値を入力し、その合計を計算します`s + value`。 
4. 更新された合計をヒープに返します。 

これにより、最適なパーティションと順序が正確に構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適な貪欲 + ヒープ | O(n log n) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのボスの増分を読み取ります。 
2. 値を降順に並べ替えます。 

より大きな値は、より大きな係数を持つため、セグメント内では常に小さな値よりも先に現れる必要があります。 
3. 作成する`k + 1`セグメント。 

各セグメントは、現在の累積合計によってのみ表されます。 最初はすべてのセグメントの合計が等しい`0`。 
4. すべてのセグメントの合計を最大ヒープに保存します。 

Python は最小ヒープを提供するため、否定された値を格納します。 
5. ソートされた値を最大値から最小値の順に処理します。 
6. 現在の合計が最も大きいセグメントを抽出します。 

現在の合計が`s`、次の値をこのセグメントに配置すると、正確に寄与します`s`合計スコアに。 
7.追加`s`答えに。 
8. セグメント合計を次のように更新します。`s + value`そしてそれをヒープに押し戻します。 
9. すべての値が処理された後、累積された応答を出力します。 

### なぜ効果があるのか

 セグメント境界を修正した後、前の位置ほど係数が大きくなるため、すべてのセグメントを降順でソートする必要があります。 これにより、値を複数のユーザーに分散させるという問題が軽減されます。`k + 1`セグメント。 

値が最大から最小の順に処理されると、将来のすべての値は現在の値以下になります。 セグメントに関して重要な情報は現在の合計だけです。そのセグメントに値を挿入すると、その合計がすぐに答えに反映されるためです。 

各ステップで、合計が最大のセグメントに現在の値を割り当てると、可能な最大の即時ゲインが得られます。 後の値は現在の値より大きくないため、現在の値を他の場所に移動しても、将来のより良い補償を作成することはできません。 貪欲な選択は常に安全です。 

ヒープ シミュレーションは、この最適な割り当てプロセスを正確に実行し、可能な限り最大のスコアを生成します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    c = list(map(int, input().split()))

    c.sort(reverse=True)

    heap = [0] * (k + 1)
    heapq.heapify(heap)

    ans = 0

    for x in c:
        s = -heapq.heappop(heap)
        ans += s
        heapq.heappush(heap, -(s + x))

    print(ans)

if __name__ == "__main__":
    solve()
```最初のステップは、値を降順に並べ替えることです。 これにより、すべてのセグメント内で最適な順序が適用されます。 

ヒープには現在のセグメントの合計が保存されます。 Python のヒープは最小ヒープであるため、最大のセグメント合計が最初に表示されるようにすべての値を否定します。 

ソートされた値ごとに、最大のセグメント合計を削除します。`s`、 追加`s`答えに対して、そのセグメントを次のように更新します`s + x`、再度挿入します。 

すべての算術演算では Python 整数が使用され、可能な限り最大の答えが安全に処理されます。 と`n = 5 * 10^5`および最大値`10^6`, 64 ビットの算術演算であればすでに十分ですが、Python の任意精度を使用すればその心配はなくなります。 

最も一般的な実装上の間違いは、最大ヒープの代わりに最小ヒープを直接使用することです。 貪欲な選択には、最大の現在のセグメント合計が必要です。

## テストケース```python
import sys
import io
import heapq

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    c = list(map(int, input().split()))

    c.sort(reverse=True)

    heap = [0] * (k + 1)
    heapq.heapify(heap)

    ans = 0

    for x in c:
        s = -heapq.heappop(heap)
        ans += s
        heapq.heappush(heap, -(s + x))

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided samples
assert run("3 0\n1 1 1\n") == "3", "sample 1"
assert run("5 1\n-1 -2 -3 -4 5\n") == "11", "sample 2"

# minimum size
assert run("1 0\n7\n") == "0", "single boss"

# enough resets for every boss
assert run("3 2\n-1 -2 -3\n") == "0", "every fight can start from zero bonus"

# all equal positive values
assert run("4 1\n5 5 5 5\n") == "20", "balanced segments"

# mixed values
assert run("4 0\n10 -100 10 10\n") == "30", "ordering matters"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 0 / 7`|`0`| 単一要素の境界 |
 |`3 2 / -1 -2 -3`|`0`| リセットによりすべての悪影響を排除できます。 
|`4 1 / 5 5 5 5`|`20`| 対称的な正の値 |
 |`4 0 / 10 -100 10 10`|`30`| グローバルな並べ替えは不可欠です |

 ## 特殊なケース

 検討してください```
1 100
-5
```並べ替えると、`[-5]`。 ヒープには以下が含まれます`101`ゼロ。 

抽出します`0`、 追加`0`答えを押してください`-5`。 

最終的な答えは、```
0
```ボスがボーナスを変更する前にスコアが付与されるため、追加のリセットは問題になりません。 

考慮する```
3 2
-1 -2 -3
```ソート順は、```
[-1, -2, -3]
```ヒープは次のように開始されます`[0, 0, 0]`。 

各ステップはゼロ値のセグメントを抽出し、`0`答えに。 すべての負の値は独自のセグメントに分離されます。 

最終的な答えは、```
0
```これにより、スコアが改善されるたびに、アルゴリズムが利用可能なリセットを自然に使用することが確認されます。 

考慮する```
4 0
10 -100 10 10
```ソート順は```
[10, 10, 10, -100]
```セグメント合計は次のように展開されます。```
0 -> 10 -> 20 -> 30 -> -70
```集めたスコアは、```
0 + 10 + 20 + 30 = 60
```待って、各ステップで更新前に現在の合計が加算されます。```
0 + 10 + 20 + 30 = 60
```このアルゴリズムは、大きな正の値を最初に正しく配置し、大きな負の値を最後に延期し、最適な順序と正確に一致します。 これは、入力順序を固定として扱うことが失敗する種類のケースです。
