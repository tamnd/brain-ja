 ## 解決策
 ## 問題の理解

 レベル内のセルを表すバイナリ文字列があります。 あ`1`プラットフォームがすでに存在していることを意味し、`0`セルが空であることを意味します。 

ボールはその位置からバウンドし始めなければなりません`p`、次にポジションを訪問します`p + k`、`p + 2k`、 等々。 これらのポジションには必ずプラットフォームが含まれている必要があります。 お金を払って、空のセルにプラットフォームを追加することが許可されています`x`追加ごとに。 

2 番目の操作があります。レベルの最初のセルを削除します。 最初のセルを削除した後、残りのセルはすべて左に 1 つずつ移動します。 これには費用がかかります`y`取り外しごとに。 この操作を繰り返しても構いませんが、その位置までレベルを下げすぎないようにしてください。`p`消えます。 

目標は、先頭からのいくつかの削除といくつかのプラットフォームの追加の後、バウンス シーケンスが有効になるように、必要な最小総コストを見つけることです。 

の最大値`n`は`10^5`、およびすべての合計`n`テストケース全体でも最大で`10^5`。 これにより、考えられるすべての開始位置を調べて、毎回サフィックス全体を再スキャンするアルゴリズムは即座に除外されます。 アン`O(n²)`ソリューションは次のように実行されます`10^10`最悪の場合の運用。 テスト ケースごとに線形に近い時間が必要です。 

微妙な点は、セルを削除すると位置が変わることです。`p`終わる。 仮定する：```
n = 5
p = 3
k = 2
s = 00100
```先頭から 1 つのセルを削除すると、新しい位置は`p`元のインデックスに対応します`4`、元のインデックスではありません`3`。 削除と追加を独立して処理するソリューションでは、間違った答えが計算されます。 

もう 1 つの簡単な間違いは、次の間隔の位置のみであることを忘れることです。`k`案件。 例えば：```
n = 6
p = 2
k = 3
s = 000100
```必要なセルは位置です`2`そして`5`。 位置`3`そして位置`4`は無関係です。 サフィックス全体を適切なものにしようとする単純な実装は、不必要な追加の代償を払うことになります。 

3 番目のエッジケースは文字列の終わり近くで発生します。```
n = 5
p = 5
k = 2
s = 00000
```ポジションのみ`5`が必要です。 答えは単純に一つ足すだけです。 不注意なコードは、次のような遷移を計算するときに配列の末尾を超えてアクセスすることがよくあります。`i + k`。 

## アプローチ

 最も直接的な解決策は、可能な限り前方の削除を試してみることです。 

削除したら`d`セルを配置してから、`p`新しい文字列の位置は に対応します`p + d`元の文字列で。 その位置から開始して、インデックスを順に見ていきます。```
p + d,
p + d + k,
p + d + 2k,
...
```現在含まれているものがいくつあるか数えます`0`。 このようなセルごとに、プラットフォームを 1 つ追加する必要があります。 総コストは次のようになります。```
d * y + additions * x
```すべての有効な値を試してみます`d`簡単です。 問題はカウントの段階です。 削除数ごとにバウンス位置を再スキャンすると、`O(n)`候補者ごとに作業します。 あるので`O(n)`候補者の合計は`O(n²)`。 

重要な観察は、すべての候補開始位置が同じ質問をしていることです。 

> このインデックスから開始してジャンプする等差数列に現れるゼロの数`k`?

 これらの答えは重なり合っています。 位置の答えがすでにわかっている場合`i + k`、次に位置を決めます`i`セルかどうかだけが異なります`i`それ自体はゼロです。 

定義する：```
dp[i] = number of additions needed
        if bouncing starts at i
```0 から始まるインデックスを使用すると、```
dp[i] = (s[i] == '0') + dp[i + k]
```いつ`i + k`存在します。 さもないと、```
dp[i] = (s[i] == '0')
```この繰り返しにより、次から始まる必要なバウンス パスに沿って欠落しているプラ​​ットフォームの数が正確に計算されます。`i`。 

一度すべて`dp[i]`値が既知であれば、すべての削除数を一定時間で評価できます。```
cost = deletions * y + dp[start] * x
```どこ`start`位置となる元の位置です`p`削除後。 

これにより、問題は線形スキャンに変換されます。

 ## アルゴリズムのチュートリアル

 1.変換`p`0 ベースのインデックスに変更します。 
2. 配列を作成する`dp`長さの`n`。 
3. 位置を右から左に処理します。 
4. ポジションごとに`i`、次を計算します。```
need = 1 if s[i] == '0' else 0
```5. もし`i + k < n`、 追加`dp[i + k]`:```
dp[i] = need + dp[i + k]
```さもないと：```
dp[i] = need
```これにより、バウンスが開始される場合に追加する必要があるプラットフォームの数がわかります。`i`。 
6. 可能な限りの削除数を検討します。 

削除したら`d`セルの場合、元の文字列内の必要な開始位置は次のようになります。```
start = p + d
```7. 有効なそれぞれについて`start`、次を計算します。```
cost = (start - p) * y + dp[start] * x
```最初の項は削除コスト、第 2 項はバウンス パス上に存在しないすべてのプラットフォームを追加するコストです。 
8. すべての候補者から最小値を取得します。 

### なぜ効果があるのか

 あらゆるインデックスに対して`i`、バウンスパスは正確に次のもので構成されます。```
i, i + k, i + 2k, ...
```再発```
dp[i] = missing_at_i + dp[i + k]
```そのパス上のゼロの数を数えます。 ゼロごとにプラットフォームを 1 つ追加する必要があり、すべてがすでに要件を満たしています。 

削除後`d`セル、位置`p`新しいレベルでは位置に対応します`p + d`オリジナルレベルでは。 必要な追加は正確に`dp[p + d]`。 削除と追加は独立して総コストに寄与するため、評価```
d * y + dp[p + d] * x
```有効なすべての`d`実行可能なすべての最終構成を調べます。 これらの値の最小値が最適な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, p, k = map(int, input().split())
        s = input().strip()
        x, y = map(int, input().split())

        p -= 1

        dp = [0] * n

        for i in range(n - 1, -1, -1):
            dp[i] = (s[i] == '0')
            if i + k < n:
                dp[i] += dp[i + k]

        best = 10**18

        for start in range(p, n):
            deletions = start - p
            cost = deletions * y + dp[start] * x
            best = min(best, cost)

        ans.append(str(best))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```すべての状態は以下に依存するため、動的プログラミング配列は右から左に埋められます。`i + k`、右側にあります。 

表現```
(s[i] == '0')
```と評価される`True`または`False`、Python は自動的に次のように扱います。`1`または`0`算術式で。 これにより、現在のセルで必要な加算の数が得られます。 

ループオーバー`start`考えられるすべての削除数を表します。 もし`start = p`、細胞は削除されません。 もし`start = p + 1`、1 つのセルが削除される、などです。 

最も一般的な実装上の間違いは、1 から始まるインデックスと 0 から始まるインデックスを混合することです。 入力位置`p`は 1 ベースですが、配列へのアクセスはすべて 0 ベースなので、すぐに次のようにします。```
p -= 1
```もう 1 つのよくあるバグは、サイズのジャンプを繰り返した場合にのみ到達可能な位置であることを忘れることです。`k`案件。 回帰では、当然のことながら、まさにそれらの位置が捉えられます。

def run(inp: str) -> str:

    t = int(input())
    out = []

 ## 特殊なケース

 次のことを考慮してください。```
1
5 3 2
00100
1 1
```削除がなければ、バウンスパスは次の位置から始まります。`3`そして訪問位置`5`。 どちらも`1`そして`0`, したがって、1 つの追加が必要です。 

1つのセルを削除すると、位置が`p`元の位置に対応するようになりました`4`。 道が全く変わります。 アルゴリズムは次のように評価するため、これを処理します。`dp[2]`、`dp[3]`、 そして`dp[4]`別に。 バウンスパスが固定されているとは決して想定しません。 

ここで次のことを考えてみましょう。```
1
6 2 3
000100
5 1
```該当するポジションは、`2`そして`5`。 細胞`3`、`4`、 そして`6`関係ありません。 サイズのジャンプに続いて再発が発生する`k`したがって、これらの無関係なセルは計算されたコストに影響を与えることはありません。 

最後に、次のことを考慮してください。```
1
5 5 2
00000
3 1
```バウンス パスには最後のセルのみが含まれます。 DP建設中に、`i + k`は配列の外にあるため、繰り返しは正しく停止します。```
dp[4] = 1
```答えはちょうど 1 つの足し算になります。`3`。 境界外アクセスは発生せず、余分なセルはカウントされません。
