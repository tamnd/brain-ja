 ## 解決策
 ## アプローチ

 強引なアイデアは、現在ダンスにあるすべての文字列の明示的なセットを維持し、各クエリですべての文字列を反復処理し、クエリがそれらのいずれかのプレフィックスであるかどうかを確認することです。 タイプ 3 の操作では、セット内のすべての文字列を物理的に反転します。 これは問題ステートメントを直接シミュレートするため正しいですが、そのコストは完全な反転の繰り返しとプレフィックス スキャンの繰り返しによって支配されます。 各反転は O (すべての文字列の合計長) であり、そのような操作は最大 10^5 回存在する可能性があり、最悪の場合は約 10^10 文字操作になります。 

重要な観察は、世界的な逆転が均一であるということです。 すべての文字列は、これまでに確認されたタイプ 3 の操作の数のパリティのみに応じて、通常の形式または逆形式で格納されます。 保存された文字列を変更する代わりに、2 つの試行を維持します。1 つは文字列を元の向きで保存し、もう 1 つは反転した文字列を保存します。 また、ブール反転状態も維持します。 文字列が挿入されると、それを両方のトライに挿入しますが、現在の反転状態に応じてどちらのトライがアクティブであるかを論理的に解釈します。 クエリが到着すると、現在反転しているかどうかに応じて、順方向トライまたは逆方向トライでクエリを検索します。 反転操作はブール値 (O(1)) を切り替えるだけになります。 

これにより、問題は、償却定数時間のグローバル変換を使用した、トライにおける標準的なプレフィックス存在クエリに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q * 全長) と完全な反転の繰り返し | O(全長) | 遅すぎる |
 | 怠惰な逆転でツートライ | O(全長 + Q * | クエリ | ) |

 ## アルゴリズムのチュートリアル

 1. 2 つのトライ構造を維持します。1 つは挿入された文字列を表し、もう 1 つはその反転された形式を表します。 この分離により、既存のデータを変更することなく、どちらの方向でもプレフィックス クエリに応答できることが保証されます。 
2. グローバル反転が奇数回適用されたか偶数回適用されたかを示すブール変数を保持します。 この変数は、保存された文字列の現在アクティブな解釈であるトライを決定します。 
3. 挿入操作ごとに、両方の試行に文字列を挿入します。 これが必要なのは、将来のクエリによって、将来の反転に応じて同じ文字列がどちらかの方向に解釈される可能性があり、両方の表現を事前計算することで再計算が回避されるためです。 
4. 各クエリ操作について、指定されたクエリ文字列を使用して、現在の反転状態に対応するトライをトラバースします。 すべての文字で有効なノードに到達した場合は、そのパスが存在するかどうかを確認します。つまり、保存されている少なくとも 1 つの文字列にプレフィックスとしてクエリが含まれているかどうかが確認されます。 
5. 各反転操作では、保存されているデータを変更する代わりに、単にブール フラグを切り替えるだけです。 これは、すべての文字列の向きが同時に変わることを反映しています。 

これが機能する理由は、システムの状態はいつでも、反転の位置ではなく、反転のパリティのみに依存するためです。 すべての文字列は同じ変換シーケンスを受けるため、両方の方向を事前に表すことで、将来の可能性がすべて保存されます。 トライにより、プレフィックス クエリはクエリの長​​さにのみ比例して時間内に応答されることが保証され、格納された文字列を物理的に更新する必要がないため、グローバル構造の一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.next = {}
        self.cnt = 0

    def insert(self, s):
        node = self
        node.cnt += 1
        for ch in s:
            if ch not in node.next:
                node.next[ch] = Trie()
            node = node.next[ch]
            node.cnt += 1

    def query(self, s):
        node = self
        for ch in s:
            if ch not in node.next:
                return False
            node = node.next[ch]
        return True

def main():
    q = int(input())
    forward = Trie()
    backward = Trie()
    flipped = False

    for _ in range(q):
        parts = input().split()
        t = parts[0]

        if t == "1":
            s = parts[1]
            forward.insert(s)
            backward.insert(s[::-1])

        elif t == "3":
            flipped = not flipped

        else:
            s = parts[1]
            if flipped:
                print(1 if backward.query(s) else 0)
            else:
                print(1 if forward.query(s) else 0)

if __name__ == "__main__":
    main()
```挿入ステップでは両方の向きを意図的に保存するため、グローバル反転での反転を再計算する必要がありません。 反転されたフラグは、どのトライをクエリするかを制御し、クエリ ロジックを履歴の長さに依存しないようにします。 

実装の微妙な詳細は、完全な文字列メンバーシップの数を維持しようとせず、プレフィックスの存在のみを維持しようとすることです。 有効なパスは少なくとも 1 つの格納された文字列がそのプレフィックスを通過していることを示すため、トライ ノードには終了フラグが必要ありません。 

## 実用的な例

 「alice」を挿入し、「alice」をクエリし、反転してから「ali」と「ecil」をクエリするシーケンスを考えてみましょう。 

| ステップ | 操作 | 反転 | 使用したトライ | クエリ | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | アリスを挿入 | 偽 | 前方+後方 | - | - |
 | 2 | クエリアリス | 偽 | 前へ | アリス | 1 |
 | 3 | フリップ | 本当 | - | - | - |
 | 4 | クエリアリ | 本当 | 後ろ向き | アリ | 0 |
 | 5 | クエリecil | 本当 | 後ろ向き | エシル | 1 |

 このトレースは、構造を変更せずに、格納された同じ文字列が方向に応じて異なるクエリをどのように満たすことができるかを示しています。 

ここで、「abc」と「xyz」を挿入し、間にクエリを挟んで 2 回反転することを考えてみましょう。 

| ステップ | 操作 | 反転 | クエリ | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | abcを挿入 | 偽 | - | - |
 | 2 | xyzを挿入 | 偽 | - | - |
 | 3 | フリップ | 本当 | - | - |
 | 4 | クエリ「ab」 | 本当 | 0 | |
 | 5 | フリップ | 偽 | - | - |
 | 6 | クエリ「xy」 | 偽 | 1 | |

 これは、フリップ パリティが解釈を完全に決定し、繰り返されるフリップが一貫して動作することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(挿入された文字列の合計長 + クエリの合計長) | 各文字は、トライ操作で一定の回数だけ処理されます。 
| スペース | O(挿入された文字列の合計の長さ) | 各文字列は両方の試行でノードに寄与し、合計入力サイズは線形です。 

この制約では合計 10^5 文字までが許可されるため、操作ごとの完全な文字列の反転を回避しながら、線形時間トライの構築と走査は十分に制限内に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import contextlib

    output = []
    def fake_print(x):
        output.append(str(x))

    global print
    old_print = print
    print = fake_print
    try:
        # inline solution
        class Trie:
            def __init__(self):
                self.next = {}

            def insert(self, s):
                node = self
                for ch in s:
                    if ch not in node.next:
                        node.next[ch] = Trie()
                    node = node.next[ch]

            def query(self, s):
                node = self
                for ch in s:
                    if ch not in node.next:
                        return False
                    node = node.next[ch]
                return True

        data = inp.strip().split()
        q = int(data[0])
        idx = 1
        f = Trie()
        b = Trie()
        flipped = False

        for _ in range(q):
            t = data[idx]
            idx += 1
            if t == "1":
                s = data[idx]
                idx += 1
                f.insert(s)
                b.insert(s[::-1])
            elif t == "3":
                flipped = not flipped
            else:
                s = data[idx]
                idx += 1
                print(1 if (b.query(s) if flipped else f.query(s)) else 0)
    finally:
        print = old_print

    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースは、間に挿入が行われずに多くのフリップが発生する場合です。 フリップはブール値を切り替えるだけでトライ状態を変更しないため、アルゴリズムはこれを安全に処理します。そのため、フリップを繰り返してもコストが蓄積されません。 

もう 1 つのエッジ ケースは、長く保存された文字列に対して空のプレフィックスまたは非常に短いプレフィックスをクエリすることです。 このトライにより、複数の文字列がプレフィックスを共有している場合でも、クエリ パスを超えた継続によって有効な一致が確認されるため、存在チェックが正しく行われることが保証されます。 

最後に、一連のフリップの後に文字列を挿入しても機能します。これは、各挿入が両方の方向で即座に記録され、将来の状態の変更が過去のデータに無関係になるためです。
