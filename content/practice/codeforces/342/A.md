 ## 解決策
 ## 問題の理解

 すべて 1 から 7 までの正の整数のシーケンスが与えられ、シーケンスの長さは 3 で割り切れます。 Xenia は、このシーケンスを 3 つの数値のグループに分割し、各グループ内で数値が厳密に増加し、各数値が次の数値を分割するようにしたいと考えています。 出力は、これらのトリプレットのリストか、そのようなパーティションが存在しない場合は -1 になります。 

この制約は、n が 99999 まで大きくなり得ることを示しています。これにより、シーケンス内のすべての可能な 3 つの要素を試すアルゴリズムは除外されます。これは、n 個の要素の組み合わせを一度に 3 つずつ選択し、割り算をチェックする必要があり、およそ n3 個の演算が行われることになるからです。 n が 10⁵ に近い場合、n3 は 10¹⁵ 程度であるため、これは完全に不可能です。 線形または最大でも O(n) のアプローチが必要です。 

1 から 7 までのすべての数値が有効な 3 つの組み合わせに共存できるわけではないため、明らかではないエッジ ケースが発生します。 たとえば、1,1,1 は厳密には増加していないため、3 つの 1 は三重項を形成できません。 同様に、1 ～ 7 の数字だけを使用して 5 で終わる a 割る b 割る c という形式のシーケンスは存在しないため、5 のような数字はどの三重項にも出現できません。 もう 1 つの注意が必要なケースは、カウントの不一致です。1 よりも 2 の方が多い場合、すべての 2 に対して 3 つ組 1,2,x を形成することはできません。 

具体的な失敗例は次のとおりです。`6\n1 1 1 2 2 2`。 1 と 2 を組み合わせて厳密な増加条件と割り算条件を満たすことはできないため、正しい出力は -1 になります。 

## アプローチ

 ブルートフォースアプローチは、3 つの要素のすべての組み合わせを生成し、a<b<c、および a が b を割って c が割れるという条件が成立するかどうかを確認することです。 有効なトリプレットごとに、要素を使用済みとしてマークし、すべての要素がグループ化されるまで続行します。 このアプローチは原理的には正しいですが、n 個の要素の組み合わせを一度に 3 つ選択する必要があり、これは O(n3) となり、10⁵ までの n には遅すぎます。 

重要な点は、数値が 1 ～ 7 の範囲に制限されていることです。 そのため、個別の数値の総数は非常に少なくなります。 各数値の出現を数えてから、有効なシーケンスのみからトリプレットを組み立ててみます。 制約 (1,2,4)、(1,2,6)、(1,3,6) を満たすすべての可能なトリプレットをリストすると、これらの組み合わせのみが出現できることがわかります。 いずれかの数値のカウントが、これらのトリプレット全体で必要なカウントと一致しない場合、解決は不可能です。 

したがって、最適なアプローチは貪欲なカウント方法です。つまり、1 から 7 の出現をカウントし、そのカウントによって必要な 3 つ組を形成できるかどうかを確認し、そのカウントを使用して 3 つ組を出力します。 これにより、カウントするためにリストを 1 回トラバースするだけで済み、トリプレットを出力するだけで済むため、複雑さが O(n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 数えること + 貪欲 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 から 7 までの各整数がシーケンス内に何回出現するかを数えます。 これを配列に格納します`cnt`どこ`cnt[i]`は番号 i のカウントを表します。 
2. 不可能な数値がないか確認します。 5 や 7 など、有効な 3 つの要素の一部ではない数値が表示された場合は、すぐに -1 を返すことができます。 
3. 実行可能なトリプレットに対してカウントを検証します。 有効な 3 つ組は (1,2,4)、(1,2,6)、および (1,3,6) のみです。 1 のカウントの合計は n/3 に等しくなければならず、各 1 は 1 回だけ使用する必要があります。 同様に、2、3、4、および 6 の数は、3 つ組によって暗示される関係を満たす必要があります。 

- 各 2 は (1,2,4) または (1,2,6) の一部です。 
- 各 3 は 6 インチ (1、3、6) と組み合わせる必要があります。 
- 4 と 6 というカウントは、すべての 3 連符をカバーするのに十分でなければなりません。 
- 5と7は無効です。 
4. 貪欲なアプローチを使用してトリプレットを構築します。 まず、次を使用してできるだけ多くの (1,2,4) 三つ組を形成します。`min(cnt[1], cnt[2], cnt[4])`、残りの 1、2、6 で (1,2,6) の 3 つ組を形成し、次に残りの 1、3、6 で (1,3,6) の 3 つ組を形成します。 
5. トリプレットを形成した後、カウントがゼロ以外のままの場合は、-1 を返します。 それ以外の場合は、すべてのトリプレットを出力します。 

不変条件は、すべてのステップで、使用可能な数値で有効なトリプレットのみを形成し、各数値が 1 回だけ使用されることを保証することです。 カウントによってパーティションが存在するかどうかが完全に判断されるため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

cnt = [0] * 8
for x in a:
    cnt[x] += 1

# impossible numbers
if cnt[5] > 0 or cnt[7] > 0:
    print(-1)
    sys.exit()

triplets = []

# form (1,2,4) as much as possible
k = min(cnt[1], cnt[2], cnt[4])
for _ in range(k):
    triplets.append((1,2,4))
    cnt[1] -= 1
    cnt[2] -= 1
    cnt[4] -= 1

# form (1,2,6)
k = min(cnt[1], cnt[2], cnt[6])
for _ in range(k):
    triplets.append((1,2,6))
    cnt[1] -= 1
    cnt[2] -= 1
    cnt[6] -= 1

# form (1,3,6)
k = min(cnt[1], cnt[3], cnt[6])
for _ in range(k):
    triplets.append((1,3,6))
    cnt[1] -= 1
    cnt[3] -= 1
    cnt[6] -= 1

# if any leftover numbers, impossible
if sum(cnt) != 0:
    print(-1)
else:
    for t in triplets:
        print(*t)
```最初の部分では出現回数をカウントし、無効な数値を即座に拒否します。 貪欲なステップにより、残り物を残さずに有効なシーケンスでトリプレットを形成することが保証されます。 残りのカウントの合計をチェックすると、割り当てられていない番号がないことが確認されます。
