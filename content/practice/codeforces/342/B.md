 ## 解決策
 ## 問題の理解

 メモはインデックスに配置された 1 人のスパイから始まります`s`一列に並んで`n`スパイ。 そのメモは最終的にはその位置にいる別のスパイに届くはずだ`f`。 時間は個別のステップで進み、各ステップで、現在メモを保持しているスパイは、メモを 1 位置左に移動するか、1 位置右に移動するか、またはその位置に保持することができます。 

問題は、各ステップに禁止された間隔があることです。`[l_i, r_i]`。 そのステップの間、その期間内のすべてのスパイは監視下にあります。 監視下にあるスパイは完全に非アクティブであるため、その間隔内でメモが現在スパイ上にある場合、それを遠ざけたり、隣人から受け取ったりすることはできません。 この場合に許可される唯一のアクションは、同じスパイにメモを保管することです。 

移動シーケンスは、各ステップで音符が静止しているか、左右に 1 つの位置を移動し、監視されているスパイから移動したり到着したりしない場合に有効です。 目標は達成することです`f`から`s`最小限のステップ数で実行し、一連のアクションを時間の経過とともに出力します。 

この制約により、リニア スキャン ソリューションが求められます。 最大 100,000 ステップがあるため、時間や位置を超えた二次探索は不可能です。 状態空間は 1 次元ですが、時間に依存する制限により動的になります。 ステップごとに到達可能性を最初から再計算しようとするソリューションは遅すぎます。 

微妙なエッジケースは、完全な遮断間隔から発生します。 ある段階でライン全体が監視下に置かれた場合、`[1, n]`、その場合、そのステップ中は移動が不可能になり、戦略に関係なく位置が固定されます。 もう 1 つの特殊なケースは、ターゲットの方向が時間の経過とともに変化し、直接貪欲に移動するのではなく、迂回または待機期間を余儀なくされる場合です。 

## アプローチ

 素朴な見方では、これを時間展開グラフの最短経路として扱います。 それぞれの状態は、`(position, time)`、各状態から、隣接する位置に移動するか、その時点で目的地とソースがブロックされていない場合はその場に留まることができます。 これはプロセスを正しくモデル化していますが、グラフには次のような特徴があります。`n * m`州およびそれまで`3`状態ごとの遷移、約`3 * 10^10`限界をはるかに超えた最悪の場合には移行します。 

任意のパスの観点から考えるのをやめ、代わりにステップごとの実現可能性に焦点を当てると、構造が簡素化されます。 各時間ステップにおいて、意味のある唯一の質問は、目的地に一歩近づくことができるかどうか、それとも待たなければならないかどうかです。 監視間隔は、現在位置をブロックするかブロックしないかのいずれかであり、同様に、隣接する遷移が許可されるかどうかに影響します。 

重要な観察は、ターゲットから遠ざかっても決して利益を得られないということです。 ターゲットが右側にある場合、ブロックによって強制的に留まらない限り、最適な戦略は決して左側に移動しません。 したがって、問題は、貪欲に距離を縮めようとすることになります。`f`可能な限り、それ以外の場合はその場に留まります。 

1 から 2 までの時間をシミュレーションします。`m`。 現在の地位を維持します。 各ステップで、次の目標に向かって進むことができるかどうかを決定します。`f`。 現在の位置が安全で、次の位置もそのステップで安全である場合は、移動します。 そうでなければ、私たちは残ります。 

これにより、問題は、間隔比較を使用してステップごとに一定時間チェックを行う線形スキャンに変わります。

 ## アルゴリズムのチュートリアル

 一般性を失うことなく、次のような場合に動きが右方向であると仮定します。`s < f`、それ以外の場合は左方向です。 私たちは問題を、常に一定の方向に進もうとすることに変換します。 

1. すべての間隔を読み取り、時間順に処理します。 ノートの現在の位置を維持します。 
2. 各ステップごとに`i`、ブロックされた間隔を抽出します`[l_i, r_i]`。 
3. 現在位置がブロック区間内にあるかどうかを確認します。 そうであれば、移動は禁止され、出力する必要があります。`X`。 
4. 移動が許可されている場合は、次の方向に進むかどうかを決定します。`f`1ポジションずつ可能です。 これには、このステップで宛先セルもブロックされていないことが必要です。 
5.移動可能であれば位置を更新して出力`L`または`R`方向によっては。 
6. それ以外の場合は出力`X`そして同じ位置に留まります。 

重要な設計上の選択は、ターゲットから離れることを決して考慮しないことです。 一時的に許可されても、ゴールまでのタイムは決して向上しません。 

### なぜ効果があるのか

 どのタイムステップでも、ターゲットまでの残り距離を減らすことができる唯一のアクションは、ユニットが目標に向かって移動することです。`f`。 遠ざかる動きは厳密に距離を増加させるため、ターゲットに向かう動きがブロックされない限り、最適なシーケンスの一部となることはできません。 動きがブロックされている場合、とにかくその場に留まることが唯一の合法的な選択肢です。 

したがって、このプロセスでは、各ステップの後に、その位置が到達可能な最も遠い位置であるという不変条件が維持されます。`f`それまでの制約を考えると。 距離は可能な場合にのみ減少し、決して増加しないため、初めて到達したとき`f`が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s, f = map(int, input().split())
    
    # store events
    events = []
    for _ in range(m):
        t, l, r = map(int, input().split())
        events.append((t, l, r))
    
    pos = s
    direction = 1 if f > s else -1
    
    ans = []
    
    for i in range(m):
        t, l, r = events[i]
        
        # if current position is blocked, must stay
        if l <= pos <= r:
            ans.append('X')
            continue
        
        nxt = pos + direction
        
        # check if we can move
        if 1 <= nxt <= n and not (l <= nxt <= r):
            pos = nxt
            ans.append('R' if direction == 1 else 'L')
        else:
            ans.append('X')
    
    print("".join(ans))

if __name__ == "__main__":
    solve()
```このソリューションは現在位置のみを保持し、各時間ステップを 1 回ずつ処理します。 方向は開始と終了の相対的な順序に基づいて固定されます。 各間隔は一定時間でチェックされます。 

微妙な点は、次のことを明示的にチェックしないことです。`pos == f`プロセスを早期に終了します。 それ以上の移動は不要になるため、アルゴリズムは自然に安定しますが、留まることが常に有効です。

このトレースは、現在のポジションと次のポジションの両方が安全な場合にのみアルゴリズムが移動することを示しています。

 ## 特殊なケース

 重要な状況の 1 つは、現在位置が多数の連続ステップのすべての間隔内にある場合です。 その場合、アルゴリズムは繰り返し出力します。`X`そしてその立場は決して変わりません。 これは正しいです。なぜなら、これらのステップでは法的な動きは存在せず、強制的に移動させようとする試みは監視規則に違反することになるからです。 

もう 1 つのエッジ ケースは、ターゲットがすぐ隣にあるものの、断続的にブロックされている場合に発生します。 このアルゴリズムは、現在の位置と次の位置の両方が安全な場合にのみ移動するため、不正な遷移を試みるのではなく、安全なステップを自然に待ちます。 

最後のエッジケースは、目的地に早く到着した場合です。 一度`pos == f`、その後のすべてのアクションは引き続き有効です`X`、アルゴリズムは明示的な終了ロジックを必要とせずに、正当な最小限のシーケンスを生成し続けます。
