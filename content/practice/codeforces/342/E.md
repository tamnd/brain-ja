 ## 解決策
 ## 問題の理解

 私たちは、すべてのノードが接続された非巡回グラフ内の点を表すツリーを操作しています。 最初はノード 1 のみが赤に色付けされ、他のすべてのノードは青から始まります。 時間の経過とともに、2 種類の操作が実行されます。 1 回の操作で、選択した青色のノードが永続的に赤色に変わり、赤色のノードのセットが増加します。 もう 1 つの演算では、指定されたノードについて、木の距離の観点から最も近い赤いノードにどれだけ近いかを尋ねます。 

各クエリはオンラインであるため、レッド セットが進化するにつれて、タイプ 2 のクエリに直ちに回答する必要があります。 主な問題は、赤いノードが時間の経過とともに蓄積され、距離がツリー上で測定されるため、クエリごとに最短パスを最初から再計算すると時間がかかりすぎることです。 

この制約により、クエリごとに線形または対数に近いソリューションが求められます。 最大 100,000 のノードと 100,000 のクエリでは、クエリごとに BFS または DFS を再計算するものは、最悪の場合、すぐに約 10¹⁰ の操作に縮退し、実行不可能になります。 クエリごとにすべての赤いノードからの距離を再計算することさえ明らかに不可能です。 

新しい赤いノードが追加される前に、多くの連続したタイプ 2 クエリが発行されると、微妙なエッジ ケースが発生します。 その場合、単純なアプローチでは、答えが変わらない場合でも、最初から距離を繰り返し再計算する可能性があります。 もう 1 つのコーナーは、赤いノードがツリーの小さな領域に密集する場合です。これにより、単一のソースを前提としたソリューションや、1 つの「最良の」赤いノードのみを維持しようとするソリューションが破綻します。 

## アプローチ

 直接的なソリューションでは、一連の赤いノードを維持し、距離を求めるクエリごとに、すべての赤いノードから開始してマルチソース BFS を実行します。 ツリー上の BFS では正確な距離が得られるため、これは正しいです。 ただし、そのような各クエリのコストは O(n) となり、クエリが O(n) の場合、これは O(n²) となり、遅すぎます。 

重要な観察点は、ツリー構造により、セントロイド分解を使用して更新をクエリから分離できるということです。 「任意の赤いノードまでの距離」に直接答えようとする代わりに、すべてのノードについて、重心分解ツリーを通るパスに関する情報を維持することによって問題を再構成します。 

各ノードは O(log n) 個の重心コンポーネントに属します。 この分解の各重心について、その重心からそのコンポーネントのサブツリー内の任意の赤いノードまでの最小距離を維持します。 ノードが赤になると、そのすべての祖先の重心が更新されます。 ノードをクエリするときは、これらの保存された値を重心パス全体で結合し、赤色のノードまでの最小距離を回復します。 

これが機能するのは、2 つのノード間のすべてのパスが明確に定義された重心の先祖のセットを通過し、距離がそれらの先祖に沿ってきれいに分解されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(nm) | O(n) | 遅すぎる |
 | 重心分解 | O(n log n + m log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーの重心分解を構築し、重心ごとに、その重心から現在赤いノードまでの最小距離を表す値を維持します。

1. まず、重心分解を根付けします。 各段階で、サブツリーのサイズを計算し、現在のコンポーネントをバランスの取れた部分に分割する重心を選択します。 これにより、再帰の深さが対数的になります。 
2. 元のツリー内のすべてのノードについて、重心パス上の各重心までの距離を事前に計算します。 これは、各重心から BFS または DFS を使用して分解中に行われます。 
3. すべての重心値を無限大に初期化し、ノード 1 を赤に設定します。 ノード 1 については、それらの重心からノード 1 までの最小距離を取得することにより、パス上のすべての重心を更新します。 
4. タイプ 1 クエリの場合、ノードが赤になると、その重心パスを上に進みます。 各重心の祖先について、その重心からノードまでの事前計算された距離を使用して、保存されている最小値を更新します。 
5. タイプ 2 クエリの場合、クエリ対象のノードの重心パスを再度たどります。 各重心祖先について、保存された重心値とその重心からクエリ ノードまでの距離を組み合わせます。 このようなすべての組み合わせの最小値が答えです。 

重要な考え方は、クエリ ノードから任意の赤いノードまでのすべてのパスが、両方の距離が正しく計算されている少なくとも 1 つの重心祖先を通過する必要があるということです。 

### なぜ効果があるのか

 いつでも、各重心は、その重心を介して測定された距離に関して最も近い赤いノードをそのコンポーネントに保存します。 任意のクエリ ノード v と任意の赤色ノード r について、パス距離 dist(v, r) が dist(v, c) + dist(c, r) に等しくなるように、v と r の両方の分解パス上に重心 c が存在します。 すべての赤いノードにわたって可能な最小の dist(c, r) を保存しているため、v のパス上のすべての重心をチェックすることで、任意の赤いノードまでの真の最小距離を確実に取得できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    g[a].append(b)
    g[b].append(a)

parent_centroid = [-1] * n
sub_size = [0] * n
blocked = [False] * n

centroid_tree = [[] for _ in range(n)]
dist_to_centroid = [[] for _ in range(n)]
centroids_on_path = [[] for _ in range(n)]

INF = 10**18
best = [INF] * n

def dfs_size(v, p):
    sub_size[v] = 1
    for to in g[v]:
        if to != p and not blocked[to]:
            dfs_size(to, v)
            sub_size[v] += sub_size[to]

def dfs_centroid(v, p, total):
    for to in g[v]:
        if to != p and not blocked[to]:
            if sub_size[to] > total // 2:
                return dfs_centroid(to, v, total)
    return v

def add_dist(v, p, c, d):
    dist_to_centroid[v].append(d)
    centroids_on_path[v].append(c)
    for to in g[v]:
        if to != p and not blocked[to]:
            add_dist(to, v, c, d + 1)

def build(c_parent, entry):
    dfs_size(entry, -1)
    c = dfs_centroid(entry, -1, sub_size[entry])
    blocked[c] = True

    parent_centroid[c] = c_parent

    add_dist(c, -1, c, 0)

    for to in g[c]:
        if not blocked[to]:
            build(c, to)

def update(v):
    for i in range(len(centroids_on_path[v])):
        c = centroids_on_path[v][i]
        d = dist_to_centroid[v][i]
        best[c] = min(best[c], d)

def query(v):
    ans = INF
    for i in range(len(centroids_on_path[v])):
        c = centroids_on_path[v][i]
        d = dist_to_centroid[v][i]
        ans = min(ans, best[c] + d)
    return ans

build(-1, 0)

update(0)

for _ in range(q):
    t, v = map(int, input().split())
    v -= 1
    if t == 1:
        update(v)
    else:
        print(query(v))
```分解は、再帰的な重心分割を使用して一度構築されます。 構築中、各ノードはそのパス上の重心のリストとそこまでの距離を保存します。 これにより、元のツリーをたどることなく、更新とクエリの両方を実行できるようになります。 

の`best`配列はコア構造です。`best[c]`常に重心からの最小距離を表します`c`任意の赤いノードに接続します。 ノードを更新するには、深さが対数である重心パスを歩くだけで済みます。 

微妙な点は、セントロイド分解では、選択されたノードをブロック済みとしてマークする必要があることです。そうしないと、再帰によってすでに分解されたコンポーネントが再訪され、サイズ保証が破られてしまいます。

 ## 特殊なケース

 厄介な状況は、更新が 1 つのサブツリーの奥深くにクラスタ化されている場合です。 単純な重心アプローチでは、すべての重心祖先に更新を伝播するのを忘れると、そのサブツリーの外側のノードの距離が不正確になります。 重心パス構造は、すべてのノードがその領域を横切るすべてのパスと少なくとも 1 つの重心を共有するため、これを防ぎます。 

もう 1 つのエッジ ケースは、クエリ ノード自体が赤になる場合です。 その場合、セントロイドの更新により、それ自身のセントロイド エントリがゼロ距離ソースになることが保証されるため、クエリを正しく実行すると、特別なケースを使用せずにゼロが返されます。 

パス グラフの場合、重心分解はバランスのとれた分割シーケンスに退化しますが、各ノードは依然として O(log n) 個の重心エントリを維持し、最悪の場合の線形構造でもクエリの効率性を維持します。
