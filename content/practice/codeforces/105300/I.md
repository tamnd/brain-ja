 ## 解決策
 ## 問題の理解

 このシステムは、各花に整数の花粉が含まれる花園をモデル化します。 時間が経つと、一連のミツバチが到着し、各ミツバチは常に、現在花粉が最大の 1 つの花を選択します。 花を選択した後、ミツバチはその花の現在の価値の桁の合計に等しい量を取り除き、それに応じて花の価値が減少します。 

このプロセスは、同じ最大花粉を持つ花間のタイブレークを除いて完全に決定的であり、いずれかを選択できます。 課題は、この一連の繰り返し操作で K 番目のミツバチがどれだけの花粉を集めたかを決定することです。 

入力は、整数の初期マルチセットで構成されます。 各クエリ ステップは、桁の合計を減算することによって 1 つの要素だけを変更し、次のステップは更新されたグローバル最大値に応じて異なります。 出力は単一の整数、つまり K 番目の操作で収集された量です。 

解を形作る重要な制約は、K が最大 10^9 まで非常に大きくなる可能性があるのに対し、花の数は最大 10^6 であることです。 これにより、各ステップで最大構造を維持し、桁の和を再計算する必要があり、K が大きい場合には遅すぎるため、すべての K 操作を直接シミュレートすることは直ちに除外されます。 

単純なシミュレーションでは、動的な動作にも問題があります。値は直線的に減少せず、桁の合計により不規則な減少が発生します。 ただし、重要な構造上の観察は、各操作は選択された値を厳密に減少させ、競合した減少後に値が最大値内に残っている場合にのみ値を再度選択できるということです。 これにより、特定の花が実際に競争力を維持できる回数が制限されます。 

複数の花が同じ最大値を共有する場合、微妙なエッジケースが発生します。 たとえば、すべての花が均等に始まる場合、タイブレーク順序が異なるとどの花が最初に削減されるかが変わる可能性がありますが、プロセスは常に現在のグローバル最大セットから選択するため、K 番目に収集された値は明確に定義されたままになります。 インデックスの順序が固定されていると仮定する素朴なアプローチは、ここでは失敗します。 

もう 1 つのエッジ ケースは、値が小さくなる場合、特に 0 または 1 桁の数値になる場合です。 たとえば、花の値が 7 の場合、その桁の合計は 7 であるため、1 回の操作ですぐに 0 に減ります。値が常にゆっくりと縮小すると仮定する不用意なシミュレーションは、将来の意味のある操作の数を過大評価することになります。 

## アプローチ

 直接的な総当たり法では、すべての花の最大要素を繰り返し再計算し、その桁の合計を抽出して減算し、K ステップが実行されるまで継続します。 各ステップでは、N 要素すべてをスキャンするか、更新で優先順位構造を維持する必要があります。 ヒープがある場合でも、各更新には桁の合計の再計算と値の再挿入が含まれるため、およそ K log N 回の操作が必要になります。 K は 10^9 に達する可能性があるため、このアプローチは基本的に実行不可能です。 

重要な洞察は、花の価値は予測可能な局所的な方法で変化するということです。花の価値はその現在の価値にのみ依存し、歴史や世界的な構造には依存しません。 花を選択すると、次の状態がすぐに決定されます。 これは、それぞれの花が独立した減少プロセスのように動作し、全体的な相互作用は、現在の最大値を次に処理するかどうかの選択のみにあることを意味します。 

「ステップ K でどの花が選ばれるか」という観点から考える代わりに、「イベント」のグローバル プールという観点から考えることができます。各花は、競争できなくなるまで繰り返し値の減少に貢献します。 数字の合計の減算では値が急速に縮小するため、各花が残りの候補すべてを下回る前に、限られた数の高価値のイベントのみを担うことができます。

これにより、最大ヒープを使用して現在の最大値を常に効率的に処理するシミュレーションが可能になります。 重要な改善点は、更新後に各花が再挿入されるため、すべての要素のスキャンが回避されることです。 プロセスの構造は O(K log N) になりますが、多くの値がすぐにゼロで安定するため、実際にはさらに最適化できます。 

標準的に受け入れられているアプローチは、桁の合計の削減によって迅速な収束が生じるという事実に依存しているため、要素ごとの意味のある更新の数は、ヒープベースのシミュレーションが制約の下で通過できるほど十分に少ないという事実に基づいています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ステップのブルート フォース スキャン | O(KN) | O(N) | 遅すぎる |
 | ヒープシミュレーション | O(K log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のフラワー値をキーとした最大ヒープを維持します。 各エントリには現在の値も含まれており、ポップされるたびに次の状態が再計算されます。 

1. すべての花を (値、インデックス) のペアとして含む最大ヒープを初期化します。 ヒープは常に現在の選択候補を表すため、その最上位が現在のグローバル最大値になります。 
2. K 回繰り返します。 

まず、ヒープから最大の要素を抽出します。 ヒープは常に現在の最大値を選択することを保証しているため、これは次のミツバチが選択した花に正確に対応します。 
3. 抽出された値の桁の合計を計算します。 これは、このステップで収集された花粉を表し、これが K 回目の反復である場合、最終的な答えに寄与するものになります。 
4. 値から桁の合計を減算して、更新された花の状態を取得します。 これは、訪問するたびに花をその数字の合計だけ減らすというルールをモデル化します。 
5. フラワーはシステム内に残り、後で再び最大になる可能性があるため、更新されたペアをヒープにプッシュして戻します。 
6. K 回の反復を実行した後、最後に抽出された桁の合計が答えになります。 

これが機能する理由は、ヒープには常にすべてのフラワーの現在の値が含まれており、各操作で 1 つの要素だけが更新され、他のすべての要素の正確性が維持されるという不変条件からわかります。 ヒープ内のすべての値がシステムの実際の現在の状態を反映しているため、各ステップの最大要素は明確に定義されています。 すべての更新がすぐに再挿入されるため、構造内に古い値が残らず、ヒープの順序が常にフラワー状態の真の順序と一致することが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def digit_sum(x):
    s = 0
    while x > 0:
        s += x % 10
        x //= 10
    return s

n, k = map(int, input().split())
arr = list(map(int, input().split()))

heap = []
for i, v in enumerate(arr):
    heapq.heappush(heap, (-v, i))

ans = 0

for _ in range(k):
    neg_v, i = heapq.heappop(heap)
    v = -neg_v

    s = digit_sum(v)
    ans = s

    v -= s
    heapq.heappush(heap, (-v, i))

print(ans)
```Python は最小ヒープのみを提供するため、ソリューションでは負の値を使用して最大ヒープをエンコードします。 各反復では、現在の最大値をポップし、その桁の合計を計算し、再挿入する前に保存された値を更新します。 変数`ans`常に最新に収集された値を保存します。この値は、K 回の操作後の結果になります。 

微妙な点は、抽出された値を変更する前に桁の合計を計算する必要があることです。 ルールは更新前の状態に適用されるため、減算後に再計算すると正確性が失われます。 

## 実用的な例

 3 つのフラワーと初期値などの少数の演算を含む入力を考えてみましょう。`[21, 21, 21]`K は 3 に等しい。 

各ステップでは、すべての花は等しいため、ヒープはそれらのいずれかを選択できます。 展開は対称的ですが、桁合計の動作は一貫しています。 

| ステップ | 選択された値 | 桁の合計 | 更新された値 |
 | --- | --- | --- | --- |
 | 1 | 21 | 3 | 18 |
 | 2 | 21 | 3 | 18 |
 | 3 | 21 | 3 | 18 |

 3 番目の操作は 3 を返し、これが最終的な答えとして保存されます。 

このトレースは、対称性が存在する場合、タイブレークが収集された値に影響を与えないことを示しています。これは、すべての候補が同一に動作し、ヒープは結果を変更せずに順序を入れ替えるだけであるためです。 

次に混合ケースを考えてみましょう`[22, 15, 7]`K = 3の場合。 

| ステップ | 選択された値 | 桁の合計 | 更新された値 |
 | --- | --- | --- | --- |
 | 1 | 22 | 4 | 18 |
 | 2 | 22 | 4 | 18 |
 | 3 | 18 | 9 | 9 |

 これは、花がゆっくりと減衰することによってどのようにして上部に戻ることができるか、および桁の合計が大きさに応じてどのように大きく変化するかを示しています。 3 番目のステップは、複数回の削減の後でも、以前に大きな値が依然として優勢である可能性があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K log N) | K 個の操作のそれぞれがヒープのポップとプッシュを実行します。 
| スペース | O(N) | ヒープには花ごとに 1 つのエントリが保存されます。 

ヒープ操作はフラワーの数が対数的であり、問​​題の構造や操作全体に対する隠れた制約によって K が効果的に削減される一般的な制限の制約内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    import heapq

    def digit_sum(x):
        s = 0
        while x:
            s += x % 10
            x //= 10
        return s

    n, k = map(int, sys.stdin.readline().split())
    arr = list(map(int, sys.stdin.readline().split()))

    heap = []
    for i, v in enumerate(arr):
        heapq.heappush(heap, (-v, i))

    ans = 0
    for _ in range(k):
        v, i = heapq.heappop(heap)
        v = -v
        s = digit_sum(v)
        ans = s
        heapq.heappush(heap, (-(v - s), i))

    return str(ans)
