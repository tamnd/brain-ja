 ## 解決策
 ## 問題の理解

 バイナリ文字列の「偏執的な」部分文字列を数えるように求められます。 パラノイド文字列とは、次の 2 つの操作を繰り返し適用することで 1 文字に減らすことができる文字列です。`01`と`1`または`10`と`0`。 これは、事実上、隣接するそれぞれの`01`に解決します`1`そしてそれぞれ`10`に解決します`0`。 よく考えてみると、連続した同一ビットのシーケンスはすべて安全です。簡単に単一ビットに崩壊する可能性があります。 唯一の潜在的な問題は、両方を含む部分文字列で発生します。`0`と`1`操作では完全に減少できない特定の交互パターンにあります。 

入力は複数のテスト ケースで構成されます。 各テストケースには長さがあります`n`とバイナリ文字列`S`。 各テスト ケースのパラノイド部分文字列の合計数を出力する必要があります。 と`n`まで`2*10^5`そして最大まで`1000`テストケース、すべてをチェックするブルートフォースアプローチ`O(n^2)`部分文字列は直ちに除外されます。 の合計`n`すべてのテスト ケースの上限は次のとおりです。`2*10^5`つまり、テスト ケースごとに線形または線形算術の解を得ることができますが、すべての部分文字列ペアに対する入れ子ループは遅すぎることになります。 

すべての文字が同一である場合、微妙なエッジケースが発生します。 例えば、`S = 1111`。 この文字列の部分文字列はどれもパラノイドであるため、合計数は次のようになります。`n*(n+1)/2`。 操作を機械的に適用しようとする不注意な実装では、これらの均一な部分文字列が誤って分類される可能性があります。 もう 1 つのトリッキーなシナリオは、同じビットで始まり同じビットで終わる部分文字列ですが、内部に奇数の反転が含まれる場合です。`010`または`101`。 どの部分文字列が本質的に偏執的であるかを理解することは、カウントにおける組み合わせ爆発を回避するために重要です。 

## アプローチ

 ブルートフォースアプローチを説明するのは簡単です。 部分文字列ごとに、単一の文字に到達するか、操作が不可能になるまで、段階的に操作をシミュレートできます。 これは正確性を保つために機能しますが、次のことが必要です`O(n^3)`各部分文字列には最大で`n`操作があり、`O(n^2)`部分文字列。 と`n`と同じくらい大きい`2*10^5`、これは不可能です。 

最適なソリューションを導き出す重要な観察は、`01 -> 1`そして`10 -> 0`部分文字列の **最初と最後の文字** のみに注意してください。 偏執的な部分文字列は、最初と最後の文字が同じかどうかによって完全に決定されます。 最初と最後の文字が等しい場合、部分文字列は偏執的になります。これは、交互のリダクションによって常にその文字に折りたたまれる可能性があるためです。 最初と最後の文字が異なる場合、部分文字列が短いか、操作で完全に短縮できるように交互になっている場合も偏執的です。 バイナリ文字列の場合、**長さ 1 のすべての部分文字列はパラノイド**、**最初と最後の文字が同じであるすべての部分文字列はパラノイド**という最も単純なルールが現れます。 同一文字の連続ブロックをカウントすることで、偏執的な部分文字列の総数を効率的に計算できます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右に繰り返し、連続する同一文字の数を維持します。 文字が変更されるか、文字列が終了するたびに、次の式を使用して、この連続ブロック内の部分文字列の数を計算します。`length * (length + 1) // 2`。 これを現在の合計に追加します。 これは、完全に均一なすべての部分文字列をカウントします。 
2. 異なる文字で始まり、終わる部分文字列については、より単純な観察が必要です。 ビットが異なる長さ 2 のすべての部分文字列 (`01`または`10`) も、1 回の操作で 1 文字に減るため、偏執的です。 したがって、均一なブロックに加えて、異なる値を持つ連続する文字のペアごとに 1 つの偏執的な部分文字列が追加されます。 繰り返しながらこれらを数えることができます。 
3. 一様な部分文字列と連続する異なるペアの合計により、偏執的な部分文字列の総数が得られます。 

このアルゴリズムが機能するのは、同一の文字の各ブロックがすべての内部部分文字列を自動的に生成し、交互に`01`または`10`部分文字列は 1 回の操作で削減されます。 長い部分文字列には均一なブロックが含まれるか、最初と最後の文字がパラノイアを決定する重複するブロックに分解できるため、より複雑なシーケンスをシミュレートする必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_paranoid_substrings(S):
    n = len(S)
    total = 0
    i = 0
    while i < n:
        j = i
        while j < n and S[j] == S[i]:
            j += 1
        length = j - i
        total += length * (length + 1) // 2
        i = j
    total += sum(1 for k in range(n - 1) if S[k] != S[k + 1])
    return total

t = int(input())
for _ in range(t):
    n = int(input())
    S = input().strip()
    print(count_paranoid_substrings(S))
```最初の while ループは、同一ビットの連続ブロックを識別します。 次を使用して各ブロック内の部分文字列の数を数えます。`length * (length + 1) // 2`、すべての均一な部分文字列が含まれていることを確認します。 リスト内包表記では、隣接する異なるペアをカウントします (`01`または`10`)、これは長さ 2 の追加の偏執的な部分文字列です。`strip()`末尾の改行が文字列処理に干渉しないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        S = input().strip()
        total = 0
        i = 0
        while i < n:
            j = i
            while j < n and S[j] == S[i]:
                j += 1
            length = j - i
            total += length * (length + 1) // 2
            i = j
        total += sum(1 for k in range(n - 1) if S[k] != S[k + 1])
        output.append(str(total))
    return "\n".join(output)

 ## 特殊なケース

 単一文字列の場合、`S = 0`、アルゴリズムは長さ 1 の均一ブロックを 1 つカウントし、合計を生成します。`1`。 隣接する異なるペアがないため、結果は正しいです。
