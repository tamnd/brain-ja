 ## 解決策
 ## 問題の理解

 ラベルが付いたコインが 3 枚あります`A`、`B`、 そして`C`。 すべてのコインのペアは天秤を使用してすでに一度比較されており、比較するたびにどちらのコインが重いかがわかります。 

のような行`A>B`コインを意味します`A`コインより重いです`B`。 重いコインほど額面が大きいと想定されるため、実際のタスクは、3 つのコインの最も軽いものから最も重いものへの完全な順序を回復することです。 

入力には常に、3 つのコインの各ペアに 1 つずつ、合計 3 つの比較が含まれています。 出力は、最小重量から最大重量までのコインを表す長さ 3 の文字列である必要があります。 比較が互いに矛盾し、有効な順序が存在しない場合は、次のように出力します。`Impossible`。 

コインが 3 枚しかないため、制約はわずかです。 合理的なアルゴリズムであれば、制限内に簡単に収まります。 考えられるすべての順序をチェックする場合でも、事実上一定時間です。`3! = 6`順列。 課題はパフォーマンスではなく、矛盾を正確に検出することです。 

難しいのは、一部の比較セットがサイクルを形成することです。 例えば：```
A>B
B>C
C>A
```これは言う`A`よりも重いです`B`、`B`よりも重いです`C`、 そして`C`よりも重いです`A`。 3 つの条件をすべて同時に満たす順序はありません。 勝ち負けだけをカウントする不注意な実装では、矛盾を検出せずに誤って無効な注文が生成される可能性があります。 

もう 1 つの微妙なケースは、比較がすでに混合方向で行われている場合です。```
A<B
C<B
A<C
```正しい順序は`ACB`。 完全な順序を考慮せずに直接的な関係のみを追跡すると、誤って配置される可能性があります。`B`比較の両側に現れるため、時期尚早です。 

3 番目のエッジ ケースは、2 つのコインが均等に制約されているように見える場合です。```
A>B
A>C
B<C
```正しい順序は`BCA`。 最も強いコインを特定するのは簡単ですが、残りの 2 つは依然として慎重に注文する必要があります。 ここでは「勝利数」のみによる並べ替えが機能しますが、これはグラフが非循環であるためです。 矛盾チェックがなければ、同じロジックが周期的な入力で壊れます。 

## アプローチ

 最も直接的な総当たりの解決策は、3 つのコインの 6 つの可能な順序をすべて生成し、それぞれを比較してテストすることです。 

順列を試してみるとします`CAB`。 これはつまり`C < A < B`。 すべての入力関係について、順列内の位置と一致するかどうかを検証します。 3 つの比較がすべて一致すれば、答えが見つかったことになります。 

有効な合計順序はすべて 6 つの順列の中に出現する必要があるため、このアプローチは正しいです。 このアルゴリズムは、すべての条件を満たすまですべての候補をチェックするだけです。 

たった 6 つの順列により、実行時間は事実上一定になります。 ここではブルートフォースが完全に許容されますが、なぜそれが機能するのかを考えることは役に立ちます。 順序を段階的に推論するのではなく、グローバルな一貫性を直接検証しています。 

よりクリーンな観察ベースのソリューションもあります。 

それぞれの比較により、コイン間の 1 つの有向関係が得られます。 各コインが他のコインより何回重いかを数えると、比較に一貫性があると仮定すると、最も軽いコインの勝ちは 0 回、真ん中のコインの勝ちは 1 回、最も重いコインの勝ちは 2 回になります。 

例えば：```
A>B
C<B
A>C
```コイン`A`２回優勝して、`C`一度勝てば、`B`勝ちはゼロ回。 勝利数で並べ替えると、`BCA`, しかし、それは勝利という観点から見ると最弱から最強までです。 勝利はより重いコインに対応するため、解釈を逆にして次のようになります。`CBA`重量の増加順として。 

有益な洞察は、正確に 3 つの異なる要素があれば、有効な順序付けが厳密なチェーンを形成するということです。 矛盾が存在しない限り、外次数によってすべてのコインの位置が一意に決定されます。 

矛盾事例は自然に現れる。 次のようなサイクルで:```
A>B
B>C
C>A
```すべてのコインには 1 回の勝利しかありません。 すべてのカウントが同一であるため、一意の順序は存在しません。 重複したカウントを検出すると、不一致がすぐに明らかになります。

 ## アルゴリズムのチュートリアル

 1. 各コインの勝利数を格納する辞書を作成します。`A`、`B`、 そして`C`。 
2. 3 つの比較を 1 つずつ読みます。 
3. 各比較について:

 関係がある場合`X>Y`、勝利数を増加させます`X`。 

関係がある場合`X<Y`、勝利数を増加させます`Y`。 

重いコインは軽いコインを支配するため、1 回の勝利を獲得します。 
4. すべての比較を処理した後、3 つの勝利数を調べます。 
5. 有効な順序では、カウントは正確に一致する必要があります。`0`、`1`、 そして`2`ある順序で。 

2 つのコインが同じ枚数を共有する場合、その関係は矛盾するため、次のように出力します。`Impossible`。 
6. それ以外の場合は、勝利数の増加順にコインを並べ替えます。 

勝利数が少ないコインは、他のコインよりも重かったため、軽くなります。 
7. ソートされたシーケンスを文字列として出力します。 

### なぜ効果があるのか

 3 つの異なるコインの有効な順序はすべて、厳密なランキングを形成します。 最も軽いコインは誰よりも重いので、`0`勝ちます。 真ん中のコインはちょうど 1 枚のコインよりも重いので、`1`勝つ。 最も重いコインは他のコインよりも重いため、`2`勝ちます。 

矛盾によりサイクルが発生し、これらのカウントが一意にならなくなります。 サイクルにおいて、コインがランキング内で常に独自の位置を占めることはできません。 アルゴリズムは個別のパターンのみを受け入れるため、`0,1,2`、すべての矛盾する構成を拒否します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

wins = {'A': 0, 'B': 0, 'C': 0}

for _ in range(3):
    s = input().strip()

    if s[1] == '>':
        wins[s[0]] += 1
    else:
        wins[s[2]] += 1

values = list(wins.values())

if len(set(values)) < 3:
    print("Impossible")
else:
    order = sorted(wins.keys(), key=lambda x: wins[x])
    print(''.join(order))
```辞書`wins`各コインが重いコインとして出現した回数を保存します。 

各比較の長さは 3 なので、`s[0]`そして`s[2]`はコインのラベルですが、`s[1]`どちらかです`<`または`>`。 

関係があるとき`A>B`、コイン`A`重いので1勝します。 関係があるとき`A<B`、コイン`B`代わりに1勝を得る。 

すべての比較が処理された後、ソリューションはすべてのカウントが異なるかどうかをチェックします。 3 つの要素の有効なチェーンはカウントを生成する必要があります`{0,1,2}`。 値が繰り返される場合は、循環または矛盾を示します。 

仕分けの手順は微妙です。 勝利が少ないほど重みが軽くなるため、勝利の昇順に並べ替えます。 誤って降順で並べ替えると、出力は必要な軽いものから重いものではなく、重いものから軽いものになってしまいます。 

ノードが 3 つしかなく、出次数によって順序が完全に決まるため、追加のグラフ構造は必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    wins = {'A': 0, 'B': 0, 'C': 0}

    for _ in range(3):
        s = input().strip()

        if s[1] == '>':
            wins[s[0]] += 1
        else:
            wins[s[2]] += 1

    if len(set(wins.values())) < 3:
        print("Impossible")
    else:
        order = sorted(wins.keys(), key=lambda x: wins[x])
        print(''.join(order))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("A>B\nC<B\nA>C\n") == "CBA", "sample 1"

# cyclic contradiction
assert run("A>B\nB>C\nC>A\n") == "Impossible", "cycle detection"

# already increasing
assert run("A<B\nB<C\nA<C\n") == "ABC", "simple sorted order"

# reverse order
assert run("A>B\nA>C\nB>C\n") == "CBA", "fully descending"

# mixed relations
assert run("A<C\nB>A\nB<C\n") == "ABC", "mixed direction comparisons"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`A>B, B>C, C>A`|`Impossible`| 周期的な矛盾を検出 |
 |`A<B, B<C, A<C`|`ABC`| すでにソートされた順序を処理します。 
|`A>B, A>C, B>C`|`CBA`| 完全に逆転したランキングを処理します |
 |`A<C, B>A, B<C`|`ABC`| 混合比較方向を検証します。 

## 特殊なケース

 矛盾するサイクルを考えてみましょう。```
A>B
B>C
C>A
```アルゴリズムは勝利をカウントします。```
A = 1
B = 1
C = 1
```カウントは一意ではないため、アルゴリズムはすぐに出力します。`Impossible`。 これにより、不可能な順序付けが正しく拒否されます。 

ここで、比較が混合方向で記述される場合を考えてみましょう。```
A<B
C<B
A<C
```比較を処理すると次のようになります。```
A = 0
C = 1
B = 2
```勝利結果による並べ替え`ACB`、これは実際の軽いものから重いものへの順序に一致します。 アルゴリズムは常に重いコインをインクリメントするため、入力方向を考慮しません。 

最後に、次のことを考慮してください。```
A>B
A>C
B<C
```勝利数は次のようになります。```
C = 0
B = 1
A = 2
```出力は`CBA`。 このケースでは、最初から最も強いコインが明らかな場合でも、中央のコインが正しく決定されることが確認されています。
