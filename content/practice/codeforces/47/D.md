 ## 解決策
 ## 問題の理解

 長さの隠されたバイナリ文字列を再構築しようとしています`n`。 Vasya が行ったすべての推測は、同じ長さの別のバイナリ文字列と、実際のコードと正確に一致した位置の数を示す数値です。 

たとえば、隠しコードが次の場合、`101011`そして推測は`111001`、答えは次のようになります`3`文字列が 3 つの位置で一致するためです。 

そのような推測は最大 10 個まで与えられます。 すべての答えはせいぜい`5`、これが決定的な制限であることがわかります。 タスクは、すべての回答と一致するバイナリ文字列の数を同時にカウントすることです。 

最も直接的な解釈は次のとおりです。`2^n`バイナリ文字列、いくつ満たすか$$\text{matches}(x, s_i) = c_i$$あらゆる試みに対して`i`。 

この制約により、考えられるすべてのコードを列挙することが完全に排除されます。 以来`n`到達できる`35`、検索スペースには以下が含まれます$$2^{35} \approx 3.4 \times 10^{10}$$文字列。 1 秒あたり 10 億の文字列をチェックしても、それでも遅すぎます。 

試行回数は少なく、最大でもわずかです`10`。 これは、ソリューションがすべての候補を総当たり攻撃するのではなく、推測間の関係を利用する必要があることを示唆しています。 

異常な制限`c_i ≤ 5`本当のオープニングです。 それぞれの推測は少なくとも次の点で真の答えと異なります`n - 5`ポジション。 つまり、隠されたコードは特定のすべての文字列からかなり離れており、1 つの推測に対して必要な修正の数はごくわずかです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

2 つの推測は同一ですが、異なる一致数が要求されるとします。```
6 2
000000 2
000000 3
```両方の条件を満たすバイナリ文字列はないため、正しい答えは次のとおりです。`0`。 制約を個別に処理する不注意な実装では、不可能な状態を誤ってカウントする可能性があります。 

制約がゼロ一致を要求する場合には、別の微妙なケースが発生します。```
6 1
000000 0
```唯一の有効なコードは、`111111`。 「数ビットの変更」を考慮した実装では、必要に応じてすべての位置を反転できるようにする必要があります。 

多くの異なる修正によって最終的に同じ文字列が生成される場合もあります。 例えば：```
6 2
000000 1
111111 5
```どちらの制約も、まったく同じ文字列のセット、つまりゼロが 1 つだけ含まれるすべての文字列を記述します。 単純な再帰検索では、パスではなく完全な割り当てを保存しない限り、二重にカウントされる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 長さのすべてのバイナリ文字列を列挙します`n`、すべてと比較してください`m`推測し、すべての一致数を満たすものがいくつあるかを数えます。 

1 つの候補のコストを確認する`O(mn)`なぜなら、すべての推測に対して文字ごとに比較するからです。 全体の複雑さは次のようになります。$$O(2^n \cdot m \cdot n)$$それは絶望的だ`n = 35`。 

制約の構造は、別の観点を示唆しています。 参照文字列として推測を 1 つ選択します。たとえば、最初の文字列です。 必要な一致数は次のとおりです。`c`。 

隠し文字列は正確にあるため、`c`このリファレンスと位置を一致させますが、正確には異なります$$n - c$$ポジション。 

最初はこれでもまだ大きく見えます。`n - c`周りにいるかも知れません`30`。 しかし、視点を反転すると役に立ちます。 

非表示文字列を直接構築する代わりに、どの位置が参照文字列と等しく残るかを検討してください。 以来`c ≤ 5`、そのようなポジションは最大で 5 つあります。 

これにより、検索空間が劇的に変化します。 最初の推測と比較して変化しない位置を最大 5 つ選択するだけで済みます。 1 つおきの位置が自動的に反対のビットになります。 

そのようなサブセットの数は$$\sum_{k=0}^{5} \binom{35}{k}$$下にあるのは`400000`。 サブセットごとに、候補文字列を 1 つだけ再構築し、すべての制約を検証できます。 

これが機能するのは、バイナリ文字列の各位置に取り得る値が 2 つだけであるためです。 位置が参照文字列と一致するかどうかを判断すると、その値は固定されます。 

すべての有効なコードを個別にチェックできるため、総当たり攻撃は成功します。 最初の制約によって候補空間が圧縮されるため、最適化されたソリューションは成功します。`2^35`サイズが最大 5 のすべてのサブセットまでダウンします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot m \cdot n)$|$O(1)$| 遅すぎる |
 | 最適 |$O\left(mn \sum_{k=0}^{5}\binom{n}{k}\right)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての推測とその必要な一致数を読み取ります。 
2. 最初の推測を参照文字列として選択します。 
3. 最初の推測に一致数があると仮定します。`c`。 隠しコードはこの文字列と正確に異なっていなければなりません`n - c`ポジション。 
4. 異なる位置を選択する代わりに、参照文字列と同じままの位置を選択します。 彼らの数は正確に`c`、そしてそれ以来`c ≤ 5`、可能性の数は少ないです。 
5. サイズの位置のすべてのサブセットを列挙します。`c`。 

これらの位置は、最初の推測と等しいと宣言されます。 他のすべての位置が反転されます。 
6. このサブセットによって暗示される候補文字列を構築します。 

すべてのインデックスについて:

 - インデックスが選択したサブセットに属している場合、参照ビットをコピーします
 - それ以外の場合は、それを反転します

 アルファベットはバイナリであるため、これによって文字列全体が一意に決まります。 
7. あらゆる推測に対して候補者をチェックします。 

一致する位置の数を数えます。 すべてのカウントが必要な値と等しい場合、候補は有効です。 
8. 有効な候補をすべて数えて、合計を出力します。 

### なぜ効果があるのか

 最初の制約は、すべての位置を 2 つのグループ (非表示文字列が参照推測と等しい位置とそれが異なる位置) に分割します。 

文字列はバイナリであるため、「異なる」とは、任意の 3 番目の値ではなく、反対のビットを意味します。 等しい位置が選択されると、隠し文字列が完全に決定されます。 

すべての有効な非表示文字列は、サイズが等しい位置の 1 つのサブセットに正確に対応します。`c`、そのようなすべてのサブセットは、正確に 1 つの候補文字列を生成します。 アルゴリズムはこれらすべてのサブセットを列挙し、他の制約に違反するサブセットを除外するため、有効なソリューションはすべて 1 回だけカウントされます。 

## Python ソリューション```python
import sys
from itertools import combinations

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    strings = []
    counts = []

    for _ in range(m):
        s, c = input().split()
        strings.append(s)
        counts.append(int(c))

    base = strings[0]
    keep = counts[0]

    ans = 0
    positions = list(range(n))

    for same_positions in combinations(positions, keep):
        same_set = set(same_positions)

        candidate = []

        for i in range(n):
            if i in same_set:
                candidate.append(base[i])
            else:
                candidate.append('1' if base[i] == '0' else '0')

        candidate = ''.join(candidate)

        ok = True

        for s, need in zip(strings, counts):
            match = 0

            for a, b in zip(candidate, s):
                if a == b:
                    match += 1

            if match != need:
                ok = False
                break

        if ok:
            ans += 1

    print(ans)

solve()
```実装は数学的削減に直接従うものです。 

最初の重要な観察は次の行に表示されます。```
base = strings[0]
keep = counts[0]
```最初の推測を参照文字列として使用します。 有効な回答はすべて正確に一致する必要があります`keep`ポジション。 

ループ```
for same_positions in combinations(positions, keep):
```隠しコードが参照文字列と等しい位置の可能なすべてのセットを列挙します。 以来`keep ≤ 5`、この列挙は十分小さいままです。 

候補の構造は微妙です。 選択したサブセットの外側の位置については、ビットを反転する必要があります。```
'1' if base[i] == '0' else '0'
```これは、アルファベットがバイナリであるためにのみ機能します。 より大きなアルファベットでは、基準と異なっていても値が一意に決定されません。 

検証ステップでは、候補をすべての推測と比較し、完全に一致するものをカウントします。 矛盾が見つかったらループはすぐに終了するため、不要な作業が回避されます。 

よくある間違いは、サブセットを反復しながら参照文字列を段階的に変更しようとすることです。 候補を最初から再構築する方が簡単で、古い状態のバグを回避できます。 

もう 1 つの微妙な点は独自性です。 参照に等しい位置は一意に決定されるため、サブセットが異なれば常に異なる候補文字列が生成されます。

def run(inp: str) -> str:
