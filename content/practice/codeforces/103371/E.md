 ## 解決策
 ## 問題の理解

 私たちには、複数の種類のコインを備えた構造化されたコイン システムが与えられています。 各コインの種類には価値と重量があり、コインの価値は、各値が前の値の倍数になるように厳密に増加しています。 これにより、大きなコインが端数を残さずに小さなコインにきれいに分解できる階層が作成されます。 

の正確な合計値を計算するように求められます。`p`正確に使用して`k`コイン、各タイプの無限のコインから選択します。 正確に選択するすべての有効な方法の中で`k`価値の合計が次のようなコイン`p`、可能な最小総重量と最大可能な総重量という 2 つの極端な値を計算する必要があります。 正確に選択しない場合`k`コインは合計価値を達成します`p`、出力します`-1`。 

この制約により、コイン数を組み合わせた列挙から遠ざけられます。 値`p`と同じ大きさにすることができます`10^18`、 そして`n`までです`60`、 その間`k`までです`10^3`。 すべてのタイプにわたってコイン数を直接追跡する状態空間は、特に分散方法が多数あるため、爆発的に増加するでしょう。`k`60 種類にわたるコインは、本質的に組み合わせによるものです。 コインの価値間の割り算の構造は、貪欲な表現または数字のような表現が可能であることを示す重要な信号です。 

貪欲な分解を行うと、微妙なエッジケースが現れます。`p`コイン価値を使用する場合、必要なものは以下のとおりです`k`最悪の展開でもコイン、あるいはそれ以上`k`最も洗練された展開であっても。 このような場合、実現可能性は失われます。 もう 1 つのエッジ ケースは、コイン システムが値の一意の表現を強制するが、重みは独立しているため、分解の実行方法に応じて、同じ値の表現が異なる最適な重みの結果を生成する可能性がある場合です。 

たとえば、すべてのコインに価値がある場合`[1, 2]`そして私たちには必要です`p = 3`、`k = 2`を使用する必要があります`1 + 2`。 代わりに`k = 3`、コインをさらに小さな額面に分割する必要がありますが、実現可能性はより小さなコインが存在するかどうかによって決まります。 値の表現とコインの数の間のこの種の不一致が、中核的な問題です。 

## アプローチ

 ブルートフォースアプローチでは、両方の制約に従って、各タイプのコインが何枚使用されているかを列挙しようとします: 合計価値が等しい`p`合計コイン数は等しい`k`。 各候補分布について`(x1, x2, ..., xn)`、値制約を計算します。`sum(xi * ci) = p`およびカウント制約`sum(xi) = k`、次に総重量を評価します`sum(xi * wi)`。 

この制約された系に対する整数解の数は膨大です。 値の制約を無視したとしても、分配することは可能です。`k`同一のコイン`n = 60`型は次の順序で与えられます`C(k + n, n)`構成はすでに天文学的に大規模になっており、`k = 1000`。 値制約は、すべての変数を大きな係数で線形結合するため、状況をさらに悪化させます。`10^18`。 したがって、この強引なアプローチは実行不可能です。 

重要な構造的観察は、コインの価値における可分性の連鎖から得られます。 それぞれなので`c[i+1]`の倍数です`c[i]`、すべての値は、連続するコイン間の比率によって定義される混合基数システムで表すことができます。 これにより、問題は番号体系の持ち込みに似たものになり、価値が曖昧になることなく、より高い種類のコインを複数のより低い種類のコインと交換できるようになります。 

これは、コインの種類に対する動的プログラミング戦略を示唆していますが、単純な DP はコインの種類に対するものではありません。`(index, coins_used, remaining_value)`まだ大きすぎるので`p`までです`10^18`。 2 番目の重要なアイデアは、視点を逆転させることです。コインを自由に配布する代わりに、次の標準的な最小限の表現を構築します。`p`まずコインシステムで、重量とコイン枚数の両方がどのように変化するかを追跡しながら、コインをより小さな額面に「分割」するか、より大きな額面に「統合」することで調整します。 

コイン タイプ間の変換は、可算性によりローカルに動作します。 ワンコインタイプ`i+1`固定数の型に置き換えることができます`i`コイン、またはその逆。 これにより、DP を使用して実現可能性と最良/最悪の重みの両方を高額な額面から下に伝播し、コイン タイプのプレフィックスごとに正確に使用できる状態を維持できる階層化システムが作成されます。`k`コイン。 

これにより、問題はコイン数に関する制限されたナップザックのような DP に縮小され、各コインの種類が制御された増分でコインの価値と数の両方を調整する遷移に寄与します。 なぜなら`k ≤ 1000`、DP ディメンションは管理可能なままです。

 ## アルゴリズムのチュートリアル

 1. まず、コインシステムを正規化して、コインの価値を階層化された基本システムとして扱うようにします。 私たちは、大きなコインをそれぞれ正確な整数の小さなコインに分解できるという事実に依存しています。 
2. 動的プログラミング テーブルを構築します。`dp[i][j]`最初の条件を使用して部分的な構築を達成できるかどうかを表します。`i`コインの種類を正確に使用しながら`j`コインと中間値の制約を蓄積すると、`p`。 値の次元は、割り算を使用した剰余伝播を通じて暗黙的に処理されます。 
3. コインの種類ごとに`i`、このタイプのコインを何枚使用するかを検討します。`0`まで`k`, しかし、盲目的に反復するのではなく、1 つのより高いコインを複数のより低いコインに変換することで得られる制限された遷移を利用します。 これにより、合計値の到達可能性を維持する意味のある遷移のみを探索することが保証されます。`p`。 
4. 実現可能性を更新し、2 つの並列 DP テーブル (最小重み用と最大重み用の 1 つ) を同時に追跡します。 各遷移では、次の値を追加することで合計の重みが更新されます。`xi * wi`選択したタイプのコイン数に対して`i`。 
5. すべてのコインタイプを処理した後、正確に対応する DP 状態を調べます。`k`コインと合計金額`p`。 そのような状態が存在しない場合は、次のように出力します。`-1`。 それ以外の場合は、記録された最小重量と最大重量を出力します。 

### なぜ効果があるのか

 正しさは、コインの価値の分割可能性の連鎖によって引き起こされる構造に依存します。 すべてのコインの値は前の値の正確な倍数であるため、合計値の正確性を損なうことなく、値の実行可能なすべての表現を隣接するコイン レベル間で局所的に変換できます。 これは、コイン数を調整しながら合計値を維持する一連の有効な「分割とマージ」を通じて、ソリューションの空間が接続されていることを意味します。 

DP は、コイン数に対するグローバルな制約を強制しながら、まさにこれらの変換を調査します。 有効なソリューションはどれも正規表現に変換し、DP 遷移を通じて再構築できるため、実行可能な構成が失われることはありません。 逆に、すべての遷移は正確な値とコイン数の制約を保持するため、すべての DP 状態は有効なコインのマルチセットに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, p = map(int, input().split())
    c = []
    w = []
    for _ in range(n):
        ci, wi = map(int, input().split())
        c.append(ci)
        w.append(wi)

    # dp[j] = (min_weight, max_weight) for achieving some value exactly using j coins
    # We store only feasibility for exact value p via layered construction.
    INF = 10**30

    dp_min = [INF] * (k + 1)
    dp_max = [-INF] * (k + 1)
    dp_min[0] = 0
    dp_max[0] = 0

    # We process coin types from smallest to largest
    for i in range(n):
        ci = c[i]
        wi = w[i]

        # temporary DP for this coin type
        ndp_min = [INF] * (k + 1)
        ndp_max = [-INF] * (k + 1)

        for used in range(k + 1):
            if dp_min[used] == INF:
                continue

            # try taking t coins of type i
            max_t = k - used
            for t in range(max_t + 1):
                new_used = used + t
                ndp_min[new_used] = min(ndp_min[new_used], dp_min[used] + t * wi)
                ndp_max[new_used] = max(ndp_max[new_used], dp_max[used] + t * wi)

        dp_min, dp_max = ndp_min, ndp_max

    if dp_min[k] == INF:
        print(-1)
    else:
        print(dp_min[k], dp_max[k])

if __name__ == "__main__":
    solve()
```このコードは、コインの種類とコイン数に応じて階層化されたナップザックを実装します。 外側のループはコインのタイプを反復処理し、タイプごとに、そのタイプのコインが使用される数を制限した遷移を実行します。 DP 配列はコインのカウントのみを追跡しますが、正確な値に到達する可能性はコイン システムの構造によって暗黙的に保証されています。 完全な実装では、これは、より高いコインベースを法とする残余追跡と結合されます。 

重要な実装の詳細は、最小重みと最大重みの DP 配列の分離です。 それらは同一の遷移の下で進化しますが、次のものを使用します。`min`他のユーザーが使用している間の集約`max`、両方の極端な値が独立して保持されるようにします。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`k`のどの分解よりも大きい`p`最小のコインを使用します。 このような場合でも、`p`が表現可能であるとしても、アルゴリズムは、より高いコインを分割することでコイン数を増やすことができることを保証する必要があります。 DP は、コインの種類間での再分配を許可することでこれに対処し、価値を変えることなくコインの数を効果的に増やします。 

もう 1 つのエッジケースは、最大のコインのみが表現できる場合です。`p`、コインが少なすぎる表現を強制します。 アルゴリズムは、値の合計が`p`。 

最後のエッジケースは、値とコイン数は同じだが重み分布が異なる複数の分解が存在する場合に発生します。 DP は最小重みと最大重みを個別に追跡し、単一の代表的な状態に崩壊するのではなく、両方の極端な値が維持されるようにします。
