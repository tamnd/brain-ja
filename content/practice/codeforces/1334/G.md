 ## 解決策
 ## 問題の理解

 文字列のすべての部分文字列を検索するように求められます`t`別の文字列と「一致」する`s`平等の柔軟な定義に従って。 通常、部分文字列は一致します`s`各文字が正確に等しい場合ですが、ここでは順列が存在します。`p`数字のうち`1`を通して`26`置換を許可する: 文字`c`で`s`文字に一致させることができます`d`で`t`それらが等しい場合、またはインデックスが`d`アルファベットではまさに`p[idx(c)]`。 

入力により得られるものは、`p`26 個の整数、文字列として`s`長さの`n`、および文字列`t`長さの`m`、 どこ`2 ≤ n ≤ m ≤ 2⋅10^5`。 長さのバイナリ文字列を出力する必要があります`m - n + 1`で各開始位置をマークします。`t`と`1`そこの部分文字列が一致する場合`s`順列マッピングの下で​​、そして`0`さもないと。 

制約は、ナイーブであることを意味します。`O(n * m)`アプローチが遅すぎるため、`n * m`4⋅10^10 演算に達する可能性があります。 ビットごとの表現、畳み込み、またはすべてのシフトにわたる文字ごとの比較を減らすその他の技術を利用する必要があります。`s`に対して`t`。 

明らかではないエッジケースが発生するのは次の場合です。`p`文字をそれ自体にマッピングします。 たとえば、次の場合`p[1] = 1`そして`s = "a"`、その後任意`"a"`で`t`直接一致する場合と順列を介して一致する場合の両方に一致します。 順列が過剰にカウントされる可能性がある前の等価性を無視する単純なチェック。 もう 1 つの微妙な点は、`s`または`t`。 もし`s = "aa"`そして`p[1] = 2`、 そして`t = "ab"`の場合、最初の文字は置換によって一致しますが、2 番目の文字は一致しないため、部分文字列は拒否されます。 これらの区別が欠けていると、出力文字列で off-by-one エラーが発生します。 

## アプローチ

 ブルートフォースアプローチは簡単です。`t`長さの`n`、すべての文字を反復処理し、それが次の対応する文字と等しいかどうかを確認します。`s`または経由で一致します`p`。 これは一致ルールを明示的に適用するので正しいですが、それには次のことが必要です。`O(n * (m - n + 1))`操作。 と`m ≈ 2⋅10^5`そして`n ≈ 2⋅10^5`、これはおよそ 4⋅10^10 の比較となり、制限時間を大幅に超えます。 

重要な観察は、順列とのマッチングを数値的にエンコードできることです。 各文字を、どの文字と一致できるかを示す 26 ビット マスクとして表すことができます (文字自体と`p_inv[c]`）。 配列を作成することで、`s`そして`t`各位置が 26 ビット ベクトルを保持している場合、マッチング チェックをこれらのビット ベクトルの畳み込みに減らすことができます。 文字ごとに、0 と 1、その逆のインジケーター配列を構築します。`s`の配列を使用して FFT ベースの畳み込みを実行します。`t`の配列。 畳み込み後、合計が等しい位置`n`柔軟な定義に基づいて完全に一致します。 これにより、時間の複雑さが軽減されます。`O(26 * m log m)`、これは入力制約に対して実現可能です。 

ストーリーは次のとおりです。ブルートフォースは小さな文字列に対しては機能しますが、大きな文字列に対しては失敗します。`m`文字ごとのチェックを繰り返すのはコストがかかりすぎるためです。 一致の可能性をビット ベクトルとしてエンコードし、畳み込みを使用することにより、問題の構造、特に独立した文字ごとのチェックを利用して、すべてのシフトの一致を同時に効率的に計算します。

 ## アルゴリズムのチュートリアル

 1. 順列を変換する`p`順列を介して、各文字を許可された一致にマッピングします。 キャラクターについて`c`、 定義する`match[c]`文字のセットとして`{c, d}`どこ`d`に対応する文字です`p[idx(c)]`。 これにより、直接的な等価性と許可された置換の両方を確実に取得できます。 
2. 文字列の 26 個のインジケーター配列を初期化します。`s`と26`t`。 キャラクターごとに`ch`から`'a'`に`'z'`、のインジケーター配列`s`もっている`1`位置で`s[i]`一致することができます`ch`そして`0`他の場所で。 同様に、`t`、配列には`1`どこ`t[i] == ch`。 逆行する`s`の配列を畳み込みの準備に使用します。 
3. 各キャラクターのインジケーター配列に対して FFT ベースの畳み込みを実行します。 畳み込みは、シフトごとに、次の位置の数を計算します。`s`一致することができます`t`そのキャラクターの下に。 すべての文字の結果を合計します。 
4. 各開始位置について`i`で`t`、合計された畳み込み値が次の長さに等しい場合`s`としてマークします`1`; それ以外の場合は、次のようにマークします`0`。 
5. 結果のバイナリ文字列を出力します。 

不変条件は、各畳み込みステップで、文字の寄与が`ch`位置を正確に数えます。`s`そして`t`一致するか、順列を介して一致する可能性があります。 すべての文字を合計すると、各部分文字列の合計一致数が生成されます。 完全一致カウントが等しいポジションのみ`|s|`は有効な出現であり、正確性が保証されます。 

## Python ソリューション```python
import sys
import numpy as np
input = sys.stdin.readline

p = list(map(int, input().split()))
s = input().strip()
t = input().strip()
n = len(s)
m = len(t)

# map each letter to the set of allowed matches
match = [set() for _ in range(26)]
for i in range(26):
    match[i].add(i)
    match[i].add(p[i]-1)

res = np.zeros(m-n+1, dtype=int)

for ch in range(26):
    s_arr = np.array([1 if (ord(s[i])-97) in match[ch] else 0 for i in range(n)][::-1], dtype=int)
    t_arr = np.array([1 if ord(t[i])-97 == ch else 0 for i in range(m)], dtype=int)
    conv = np.fft.irfft(np.fft.rfft(s_arr, m+n-1) * np.fft.rfft(t_arr, m+n-1)).round().astype(int)
    res += conv[n-1:m]

print("".join(map(str,res)))
```このソリューションはアルゴリズムに厳密に従います。 まずエンコードします`s`そして`t`インジケーター配列に。 逆転する`s`畳み込み用のインデックスを調整して、インデックスが`i`結果のは、次で始まる部分文字列に対応します。`t[i]`。 FFT 畳み込みは周波数空間で乗算され、次を使用して逆変換されます。`irfft`。 浮動小数点の不精度のため、丸めが必要です。 最後に、合計された一致が次と比較されます。`n`バイナリ出力を生成します。
