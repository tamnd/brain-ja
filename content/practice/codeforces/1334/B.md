 ## 問題の理解

 私たちには人々のグループが与えられ、それぞれがある程度のお金を持っています。 「裕福な」人は、最終的な金額が少なくとも閾値である人として定義されます$x$。 

手術は何度でも可能です。 各操作では、人々のサブセットを選択し、そのサブセットからすべての資金を取り出し、同じ選ばれた人々の間で均等に再分配します。 再分配後、サブセット内の合計は同じままですが、選択されたすべての人々が同じ値になります。 

課題は、少なくとも最終的に到達できる最大人数を決定することです。$x$このような一連の操作を実行した後。 

制約は以下を意味します$10^5$すべてのテストケースに人が参加するため、$O(n \log n)$または$O(n)$テストケースごとのソリューション。 サブセットの数は指数関数的であるため、操作をシミュレートしたり、サブセットを直接考慮したりするアプローチは実行不可能です。 

重要な微妙な点は、お金は端数を含めて、選択されたグループ内で完全に転送可能であるということです。 これは、均等化操作を介してのみ、選択されたグループ間で総富を恣意的に再分配することが事実上許可されていることを意味します。 

素朴な直感は、物事のバランスをとるために裕福な人々と貧しい人々を繰り返しグループ化することを示唆するかもしれませんが、そのアプローチは総和のグローバルな保存と、選択されたすべてのメンバーが平等になるという制約を無視しているため、簡単に破綻します。 

いくつかの特殊なケースがその難しさを浮き彫りにしています。 

すべての値が以下の場合$x$、しかし合計平均はまだ下回っています$x$、そうするとどんな操作をしても富裕層を生み出すことはできません。 たとえば:

 入力:```
3 10
3 3 3
```全員をグループ化しても平均は 3 なので、答えは 0 になります。 

非常に大きな値が 1 つ存在する場合、それを集中させるのではなく、多くの人に分散させるのが最適な場合があります。 

これらの例は、平均を上回る可能性のあるサブセットを選択することが重要な課題であることを示唆しています。$x$できるだけ多くの人のために。 

## アプローチ

 強引なアイデアは、考えられるすべての人々のサブセットを試し、操作のダイナミクスをシミュレートすることです。 サブセットごとに、お金を再分配し、少なくとも何人の人にリーチできるかを確認することを想像できます。$x$。 ただし、これはサブセットの数が指数関数的であり、各シミュレーションは線形であるため、不可能な結果が生じます。$O(2^n \cdot n)$複雑。 

重要な観察は、操作が常に選択したサブセットをその平均値で置き換えることです。 したがって、重要な値は選択されたグループの平均だけであり、最終的な構成は、値がグループ平均と等しいグループに人々を分割することと同等です。 

ここで、私たちが望むことを考えてみましょう。最終的な価値が少なくとも以下である人の数を最大化します。$x$。 グループが少なくとも価値のあるものになった場合$x$の場合、その合計は少なくともグループ サイズ倍でなければなりません$x$。 これは、価値の高い人材は他者からの余剰分をプールすることで形成される可能性があることを示唆しています。 

これを考える標準的な方法は、配列を降順に並べ替えることです。 仮にトップだと決めたとします。$k$人々は豊かになるでしょう。 これをサポートするために、私たちは利用可能な最大の値を使用してそれらに「資金を提供」しようとします。 最良の戦略は貪欲です。最初に最大値を取得し、その累積合計が少なくとも維持するのに十分であるかどうかを確認します。$k \cdot x$。 

これにより、問題は、ソートされた値の接頭辞ごとに、その接頭辞をすべて少なくとも 1 つ以上にすることが可能かどうかをチェックすることに変わります。$x$。 値が大きいほど要件を満たすのに役立つため、並べ替えにより常に最も有益な候補が最初に考慮されます。 

プレフィックスの合計を最大から最小まで計算し、最大のものを見つけます。$k$最大の合計が$k$要素は少なくとも$k \cdot x$。 それ$k$が答えです。

 ## アルゴリズムのチュートリアル

 1. 貯蓄額が最も高い人を優先するため、配列を降順に並べ替えます。 これにより、常に最も有望な候補を最初にテストすることが保証されます。 
2. ソートされた配列に対して実行中のプレフィックスの合計を計算します。 ステップで$k$, この合計は、上位層が利用できる富の合計を表します。$k$最も裕福な人々。 
3. それぞれについて$k$1から$n$、条件が満たされているかどうかを確認します$$\text{prefixSum}(k) \ge k \cdot x$$が成立する。 これは、すべてをもたらすのに十分な総富を再分配できるかどうかをチェックします。$k$少なくとも以下までの選ばれた人々$x$。 
4. 最大のものを追跡する$k$条件を満たすものです。 この値は、達成可能な富裕層の最大数です。 

### なぜ効果があるのか

 重要な不変条件は、最終的な構成が$k$裕福な人はそれらの分野で完全な富を持っている必要があります$k$少なくとも$k \cdot x$。 操作は合計を保持するため、いかなる変換も、選択されたグループ内で利用可能な富を増やすことはできません。 

並べ替えにより、そのようなグループを形成するための最も有力な候補が常に選択されるようになります。 上位さえあれば$k$最も裕福な人は条件を満たすことができず、その場合、他のサイズのサブセットは満たされない$k$選択した要素をより小さい要素に置き換えても、合計が減少するだけであるため、可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort(reverse=True)
        
        total = 0
        ans = 0
        
        for i in range(n):
            total += a[i]
            k = i + 1
            if total >= k * x:
                ans = k
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列を降順に並べ替えて、最も強い候補を最初に評価します。 プレフィックスの合計`total`現在のトップセグメントの蓄積された富を追跡します。 各ステップで、必要なしきい値と比較します。$k \cdot x$。 変数`ans`見つかった最適な有効なプレフィックス長を維持します。 

微妙な点は、再配布を明示的にシミュレートする必要がないことです。 操作は、合計を保持し、プレフィックス合計条件によって完全に捕捉される、選択されたグループ内での任意の再分配を許可する場合にのみ重要です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    out = []
    for _ in range(t):
        n, x = map(int, sys.stdin.readline().split())

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 独身者向け$a_1 \ge x$の場合、プレフィックスの合計が要件と等しいため、アルゴリズムは直ちにそれを有効としてカウントします。 

すべての値が以下の入力の場合$x$、プレフィックス条件はすべての場合に失敗します。$k$合計金額に達しないため、$k \cdot x$。 並べ替えてもこの結果は変わりません。 

1 つの大きな値と多数の小さな値のような非常に偏った入力の場合、プレフィックス テストはサポートできる人数を正確に制限します。これは、人が追加されるたびに必要なしきい値が線形に増加し、わずかな限界合計のみが寄与するためです。
