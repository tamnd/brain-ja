 ## 解決策
 ## 問題の理解

 ラヴレンティには、生地の量が決まっていて、詰め物の種類も数種類あります。 各詰め物の種類には数量が限られており、バンズを作るには一定量の生地が必要であり、バンズごとに利益が得られます。 さらに、彼は何も詰めずにプレーンなパンを作ることができ、これも生地を消費し、一定の利益をもたらします。 目標は、総利益を最大化するために、プレーン バンズを含む各種類のバンズを何個焼くかを選択することです。 

入力は簡単です: 生地の総グラム数`n`、詰め物の種類の数`m`、プレーンバンズの生地と利益`c0`そして`d0`。 次に、詰め物ごとに利用可能なグラムが与えられます。`ai`, パン1個あたりに必要なグラム数`bi`、パンごとの生地`ci`、利益`di`。 

制約が意味するのは、`n`詰め物の種類の数は最大 1000 です`m`は小さく、最大でも 10 です。各リソースの量も小さく、最大 100 です。これは、生地の使用量に基づく動的プログラミング ソリューションが実現可能であることを示唆しています。 小さいもの`m`グローバル ソリューションに統合する前に、各スタッフィングを個別に処理できます。 

明白ではないエッジケースとしては、最適なソリューションでは詰め物が存在するにもかかわらずプレーンバンのみを使用する場合や、一部の詰め物の種類では利益に比べて生地のコストが高すぎる場合などがあります。 たとえば、次の場合`n=5`、`m=1`、`c0=1`、`d0=1`、そして詰め物には必要があります`ai=3`、`bi=1`、`ci=5`、`di=10`の場合、最適な解決策は、1 つの詰めパンでは生地の必要量が多すぎるため、合計利益 5 のプレーン バンズを 5 つ作ることです。 

## アプローチ

 強引なアプローチでは、詰め物の種類ごとに作るバンズの数とプレーンなバンズのあらゆる組み合わせを試します。 詰め物の種類ごとに`i`、0 から 0 までのどこでもベイクできます。`ai // bi`十分な生地がある限り、バンズを作ります。 すべての可能性を掛け合わせると、指数関数的な数の組み合わせが得られます。`O(prod(ai//bi + 1))`操作。 これは明らかに小規模であっても実行不可能です`m`なぜなら`ai`最大 100 まで可能です。 

重要な洞察は、プレーンのバンズを含む各タイプのバンズは、詰め物の量と生地の両方によって制限されるということです。 この構造は、「重量」が消費される生地、「価値」が利益である、有界ナップザック問題に完全に適合します。 バイナリ分解トリックを使用して、各スタッフィング タイプを一連のアイテムに変換できます。`ai // bi`2 の累乗の項目を含むバンズ。項目の総数は最大で 2 になります。`log2(maxBuns)`詰め物ごとに。 これにより、生地上で 1 次元動的プログラミング配列を使用できるようになります。 

これは問題を古典的なナップザックに変換します。つまり、限られた生地の総量を考慮して利益を最大化します。ここで、各「アイテム」は一緒に焼くことができるバンズの束を表します。 プレーン バンズは実質的に制限がないため、標準の制限なしナップザック更新で個別に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(prod(ai//bi + 1)) | O(n) | 遅すぎる |
 | オプティマル (境界付きナップザック) | O(n * m * log(maxBuns)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP 配列を初期化する`dp`サイズの`n + 1`すべてゼロで。`dp[x]`を使用して達成可能な最大利益を正確に表します`x`生地のグラム数。 
2. 詰め物の種類ごとに`i`、可能なパンの最大数を計算します。`maxBuns = ai // bi`。 バイナリ分解を適用します`maxBuns`複数の「バンドルアイテム」を作成します。 たとえば、次の場合`maxBuns = 13`、に分解します`1, 2, 4, 6`バンズ。 各バンドルは重量のあるアイテムになります`bundle_size * ci`そして価値観`bundle_size * di`。 
3. すべてのスタッフィング タイプのバンドルされたアイテムごとに、DP 配列を逆に更新します (`n`まで`weight`）同じバンズを複数回使用しないようにします。 それぞれについて`dp[j]`、 考慮する`dp[j - weight] + value`。 
4. プレーンバンズは綴じられていないため、別々に扱ってください。 反復する`j`から`c0`に`n`、更新します`dp[j] = max(dp[j], dp[j - c0] + d0)`。 これは、生地を超えずに任意の数のプレーン バンズを追加することをシミュレートします。 
5. 答えは次の最大値です。`dp`、または同等の`dp[n]`すべてのアップデートの後。 

これが機能する理由は、各ステップで、`dp[x]`常に正確に使用して可能な最大の利益を保存します`x`生地のグラム数。 項目を 2 の累乗でバンドルすると、大量の DP 更新を作成することなく、制限までのあらゆるバンズの数が確実に考慮されます。また、逆反復により、制限されたナップザック動作が保証されます。 境界のないプレーン バンズは、前方反復で安全に追加されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, c0, d0 = map(int, input().split())
stuffings = [tuple(map(int, input().split())) for _ in range(m)]

dp = [0] * (n + 1)

for ai, bi, ci, di in stuffings:
    maxBuns = ai // bi
    k = 1
    bundles = []
    while maxBuns > 0:
        take = min(k, maxBuns)
        bundles.append((take * ci, take * di))
        maxBuns -= take
        k <<= 1
    for weight, value in bundles:
        for j in range(n, weight - 1, -1):
            dp[j] = max(dp[j], dp[j - weight] + value)

for j in range(c0, n + 1):
    dp[j] = max(dp[j], dp[j - c0] + d0)

print(dp[n])
```最初のセクションは入力を読み取り、すべてのスタッフィング情報を保存します。 次に、生地の DP 配列を初期化します。 詰め物の種類ごとに、作成できるバンズの最大数を計算し、2 の累乗を使用してバンドルに分解します。 これらのバンドルに対して DP 配列を逆に反復して、各スタッフィング タイプの制限された性質を尊重します。 最後に、プレーン バンズは境界がないため、前方の順序で追加されます。 最後の行には、達成可能な最大利益が表示されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m * log(maxBuns)) | 各スタッフィングは log(maxBuns) 項目に分解され、それぞれがサイズ n | の DP を更新します。 
| スペース | O(n) | 生地上の DP 配列のみが必要です。 

n ≤ 1000、m ≤ 10、および maxBuns ≤ 100 の場合、合計操作は 10^5 を余裕で下回っており、2 秒の制限時間内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, c0, d0 = map(int, input().split())
    stuffings = [tuple(map(int, input().split())) for _ in range(m)]
    dp = [0] * (n + 1)
    for ai, bi, ci, di in stuffings:
        maxBuns = ai // bi
        k = 1
        bundles = []
        while maxBuns > 0:
            take = min(k, maxBuns)
            bundles.append((take * ci, take * di))
            maxBuns -= take
            k <<= 1
        for weight, value in bundles:
            for j in range(n, weight - 1, -1):
                dp[j] = max(dp[j], dp[j - weight] + value)
    for j in range(c0, n + 1):
        dp[j] = max(dp[j], dp[j - c0] + d0)
    return str(dp[n])

assert run("10 2 2 1\n7 3 2 100\n12 3 1 10\n") == "241", "sample 1"
assert run("10 1 3 1\n2 2 5 10\n") == "4", "sample 2"
assert run("1 1 1 1\n1 1 1 1\n") == "1", "minimum input"
assert run("1000 10 1 1\n100 1 1 100\n"*10) == "100000", "max input, many high profit"
```
