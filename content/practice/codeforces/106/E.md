 ## 解決策
 ## 問題の理解

 私たちは、宇宙救助ステーションから指定された惑星までの最大距離が最小限になるように、三次元空間に宇宙救助ステーションを配置するように求められます。 各惑星はその座標で表されます$(x, y, z)$。 入力は整数で構成されます$n$惑星の数を表し、その後に$n$座標の線。 出力は点である必要があります$(x_0, y_0, z_0)$これにより、惑星までの最遠距離が最小化されます。 距離が最適値と最大で異なる場合、答えは受け入れられます。$10^{-6}$。 

制約は小さいです。$n \le 100$座標は範囲内にあります$[-10^4, 10^4]$。 惑星の数が少ないため、惑星に対して 3 次または 4 次の反復を行うアルゴリズムを使用する余裕がありますが、空間の連続的な性質により、純粋に離散的なブルート フォースを実行することはできません。 単純なアプローチでは、グリッド上のすべての可能な点を試行することになりますが、精度の要件によりそれは不可能になります。 

明白ではないエッジケースには、惑星が整列または対称である構成が含まれます。 たとえば、惑星が次の位置にある場合、$(1, 0, 0)$そして$(-1, 0, 0)$、最適なポイントは$(0, 0, 0)$。 惑星自体を候補点としてのみ考慮する不注意なアルゴリズムにより、中心ではなく惑星の 1 つが誤って選択される可能性があります。 

## アプローチ

 この強引なアイデアは、3D 境界ボックス内のすべてのポイントをチェックし、惑星までの最大距離を計算することです。 一定のサイズのグリッドの場合$M^3$、各チェックには次のことが必要です$O(n)$距離の計算。 と$M = 20000$(すべての整数座標をカバー) および$n = 100$、これには必要になります$20000^3 \cdot 100$明らかに実行不可能な操作。 

重要な観察は、最大距離関数が$f(x, y, z) = \max_i \text{dist}((x, y, z), (x_i, y_i, z_i))$3Dでは凸です。 直感的には、候補点を最も遠い惑星の中心に近づけるにつれて、最大距離は減少します。 Convexity を使用すると、三分探索や勾配降下法などの反復幾何最適化手法を使用できます。 以来$n$が小さい場合は、候補点を最も遠い惑星に向かって移動するランダム化された山登り法が効率的に機能します。 

アイデアは、任意の点 (たとえば、最初の惑星) から開始し、現在の点から最も遠い惑星を特定し、そこに向かって少し移動することです。 これを繰り返すことで徐々に最小包囲球中心に収束していきます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグリッド | O(M^3 * n) | O(n) | 遅すぎる |
 | 反復ヒルクライム / 三項探索 | O(n * 反復) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の惑星、たとえば最初の惑星で候補点を初期化します。 最適な点は通常、惑星の凸包の内側のどこかにあるため、これは合理的です。 
2. 初期ステップ サイズを 2 つの惑星間の最大距離の半分に設定します。 これにより、最初の移動でかなりのスペースをカバーできるようになります。 
3. ステップ サイズが非常に小さくなるまで繰り返します。 

1. 現在の候補点からすべての惑星までの距離を計算します。 
2. 現在の候補点から最も遠い惑星を特定します。 
3. 候補点を最も遠い惑星に向かってステップ サイズの分数だけ移動します。 
4. ステップ サイズをわずかに小さくし、たとえば 0.99 倍して、より細かく調整できるようにします。 
4. 十分な反復の後、現在の候補点を出力します。 このプロセスは、惑星までの最大距離を最小化する点に収束します。 

これが機能する理由: 各ステップで、最も遠い惑星に向かって移動することで最大距離を短縮します。 最大距離関数の凸性により、極小値がプロセスをトラップしないことが保証されます。 ステップ サイズを徐々に小さくすることで、任意の精度で位置を微調整することができます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def distance(p1, p2):
    return math.sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2 + (p1[2]-p2[2])**2)

def main():
    n = int(input())
    planets = [tuple(map(int, input().split())) for _ in range(n)]
    
    # Initialize at the first planet
    x, y, z = planets[0]
    
    # Step size: half the max distance between any two planets
    step = 0.0
    for i in range(n):
        for j in range(i+1, n):
            step = max(step, distance(planets[i], planets[j]))
    step /= 2
    
    # Iterative hill climb
    for _ in range(10000):
        farthest = max(planets, key=lambda p: distance((x, y, z), p))
        dx, dy, dz = farthest[0]-x, farthest[1]-y, farthest[2]-z
        d = math.sqrt(dx*dx + dy*dy + dz*dz)
        if d == 0:
            break
        x += dx/d * step
        y += dy/d * step
        z += dz/d * step
        step *= 0.995
    
    print(f"{x:.10f} {y:.10f} {z:.10f}")

if __name__ == "__main__":
    main()
```解決策は惑星から開始して、候補点が惑星の凸包の内側にあることを確認します。 ペアごとの最大距離を計算すると、適切な初期ステップ サイズが得られます。 各反復では、最も遠い惑星に向かってステップ サイズの一部だけ移動し、徐々にステップ サイズを小さくして精度を高めます。 ゼロによる除算を防ぐために、距離がゼロのケースを処理します。 反復回数は、必要な結果を達成するのに十分な数が選択されます。$10^{-6}$精度。 

## 実用的な例

 サンプル 1 の場合:

 | 反復 | 候補 (x,y,z) | 最果ての惑星 | 最大距離 |
 | --- | --- | --- | --- |
 | 0 | 5,0,0 | (-5,0,0) | 10 |
 | 1 | 0,0,0 | (-5,0,0) | 5 |
 | ... | ... | ... | ... |
 | 最終 | 0,0,0 | 任意の惑星 | 5 |

 トレースは、各ステップで最も遠い惑星に向かって移動すると、その点が惑星間の中心に素早く配置され、最大距離が最小化されることを示しています。 

構築された入力:```
2
1 0 0
-1 0 0
```出力：`0.0 0.0 0.0`。 アルゴリズムは、最初の惑星から 2 番目の惑星に向かって移動し、中間点で停止します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | スペース | O(n) | n 個の惑星のみを格納します |

 と$n \le 100$反復回数が固定されている場合、アルゴリズムは 2 秒以内に快適に実行されます。
