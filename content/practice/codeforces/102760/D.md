 ## 解決策
 ## 問題の理解

 インストールは完全なグラフです。ノードの各ペア間にはワイヤーがあります。 唯一欠けている情報は、どのタグ値がどのワイヤに属しているかということです。 すべてのタグ値を受け取り、これらの値の 2 つの異なる割り当てを決定する必要があります。 

最初の割り当てでは、最小スパニング ツリーを可能な限り安価にする必要があります。 2 番目の割り当てでは、最小スパニング ツリーのコストを可能な限り高くする必要があります。 どちらの場合も、出力は MST コストです。 

ノード数は最大 100 なので、ワイヤの数は最大 100 に達します。$$\frac{100 \cdot 99}{2}=4950$$これは、すべてのタグを並べ替えてリニア スキャンを実行できるほど十分に小さいです。 ワイヤーへのタグの割り当てをすべて試みるソリューションは、4950 個であっても不可能です。 割り当てが存在します。 意図したアプローチでは、個々のワイヤーを調査するのではなく、完全なグラフの構造を使用する必要があります。 

主な厄介なケースは、値が等しいことやグラフが非常に小さいことが原因で発生します。 等しいタグは、交換しても何も変わらないため、個別の選択肢として扱うことはできません。 の小さな値`N`頂点のグループに基づく式は、MST エッジが 1 つまたは 2 つしか存在しない場合でも機能する必要があるため、これらも重要です。 

たとえば、ノードが 2 つある場合、ワイヤは 1 つだけです。```
Input
2
10

Output
10 10
```複数の MST エッジがあることを前提とした不注意な実装により、存在しない位置にアクセスする可能性があります。 

もう 1 つのケースは、すべてのタグが同一である場合です。```
Input
4
7 7 7 7 7 7

Output
21 21
```可能なすべての割り当てにより、同じ MST コストが発生します。 最小と最大の異なる選択を強制しようとするアプローチでは、間違った答えが生成されます。 

3 番目のエッジ ケースは、最大の割り当てを取得しても最大の割り当てが得られない、小さな完全なグラフです。`N - 1`タグ。```
Input
4
3 5 5 8 8 9

Output
13 16
```最大の 3 つのタグの合計は 25 になりますが、これを MST に強制的に組み込むことはできません。 小さいタグはすでに接続されているグループ内に隠すことができ、可能な最大の MST はソート順の特定の位置のタグを使用します。 

## アプローチ

 直接的な解決策では、すべてのタグをすべての可能なワイヤに配置し、その結果の MST を計算しようとします。 MST の計算自体は Kruskal のアルゴリズムを使用すると簡単ですが、割り当ての数はワイヤの数に影響します。 たとえ`N = 10`、すでに 45 本のワイヤがあるため、このアプローチは完全に使用できなくなります。 

最初の観察は、グラフが完成していることです。 ノードのすべてのペアにワイヤがあるため、最も安価な MST 割り当ては簡単です。 最小のものを配置できます`N - 1`木の端にあるタグ。 これらのエッジはすでにすべての頂点を接続しているため、Kruskal はそれらのエッジを正確に選択します。 残りのエッジはすべて、MST に影響を与えることなく、より大きな値を受け取ることができます。 最小の答えは最初の値の合計です`N - 1`ソート後の値。 

最大の場合には、別のビューが必要になります。 Kruskal はエッジを最小から最大まで処理します。 最初はすべてのノードが分離されているため、最初のエッジは常に MST に入ります。 そのエッジが 2 つのノードを接続した後、両方のエンドポイントがすでに同じコンポーネント内にあるため、これら 2 つのノード間のエッジに小さな値を割り当てることで、そのエッジを無効にすることができます。 

後の MST の選択を遅らせるために、成長する 1 つの接続コンポーネントを作成したいと考えています。 選択後`i - 1`MST エッジ、このコンポーネントには`i`頂点。 その中には、$$\frac{i(i-1)}{2}$$エッジはすべて、選択されずに次の有用なエッジの前に表示されます。 これが意味するのは、`i`番目の MST エッジは の位置に配置できます$$\frac{i(i-1)}{2}+1$$1 つのベースのインデックスを使用して、ソートされたタグのリストに含めます。 

たとえば、頂点が 4 つある場合、最大 MST は位置を使用します。```
i = 1: position 1
i = 2: position 2
i = 3: position 4
```サンプル値について`3 5 5 8 8 9`、これは与えます`3 + 5 + 8 = 16`。 

2 つの戦略は次のように要約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(M! * M log M) | お(お) | 遅すぎる |
 | 最適 | O(M log M) | お(お) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのタグ値を降順でない順序で並べ替えます。 MST は相対的なエッジの重みに依存するため、必要な情報はタグの順序だけです。 
2. 最初の値を加算して最小 MST コストを計算します。`N - 1`ソートされた値。 これらの値は常にスパニング ツリーに配置でき、Kruskal にそれらの値を選択させることができます。 
3. 最初の MST コストを反復して最大 MST コストを計算します。`N - 1`MSTエッジ。 のために`i`選択したエッジ、インデックスに値を追加します`i * (i - 1) / 2`ゼロベースのインデックス付け。 
4. 2 つの累積合計を出力します。 

最大限の建設作業が行われるため、`i - 1`選択したエッジの場合、最適な配置には次のコンポーネントが 1 つ含まれます。`i`頂点。 そのコンポーネント内のすべてのエッジは、より小さいタグで埋められ、Kruskal によって無視されます。 このコンポーネントを新しい頂点に接続する次のエッジは、すべての内部エッジが処理された直後に表示されます。 

なぜ効果があるのか:

 最小の答えとして、MST にこれより少ない値を含めることはできません。`N - 1`エッジを使用し、その多くのタグの可能な最小の合計は、最小のタグを使用することで達成されます。`N - 1`タグ。 

最大の答えを得るには、Kruskal が選択した時点で、すべての MST エッジが 2 つの異なるコンポーネントを接続する必要があります。 最初の有用なエッジは内部エッジが 0 個の後にのみ表示され、2 番目は 1 つの内部エッジの後に、3 番目は 3 つの内部エッジの後にのみ表示されます。 単一コンポーネントを拡張すると、各 MST エッジの前に非表示にできるエッジの数が最大になります。 この式によって生成されるポジションは、正確に可能な最新のポジションであるため、結果の合計が達成可能な最大の MST コストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    c.sort()

    mn = sum(c[:n - 1])

    mx = 0
    for i in range(1, n):
        idx = i * (i - 1) // 2
        mx += c[idx]

    print(mn, mx)

if __name__ == "__main__":
    solve()
```入力にはテスト ケースが 1 つだけ含まれているため、ソリューションに必要な実行パスは 1 つだけです。 

ソート後、最小計算には最初の値が使用されます。`n - 1`エントリ。 木が付いているのでスライスも安全です`n`頂点には常に正確な値があります`n - 1`エッジ。 

最大値の計算では、ループ変数`i`次の MST エッジを追加する前に、成長コンポーネント内に既に存在する頂点の数を表します。 ゼロベースのインデックス`i * (i - 1) // 2`1 つのベースの位置と同じです`i * (i - 1) / 2 + 1`。 

Python の整数はオーバーフローしません。これは重要です。なぜなら、タグ値は最大で`2 * 10^9`MST には 99 個のエッジを含めることができます。

import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    import sys
    input = sys.stdin.readline

    n = int(input())

    c.sort()

    mn = sum(c[:n - 1])

 ## 特殊なケース

 2 つのノードの場合、ワイヤは 1 本だけであるため、最も安い MST コストも最も高価な MST コストも同じです。```
Input
2
10
```ソートされた配列は`[10]`。 最小値は値のみを使用します。 最大ループも 1 回実行され、インデックス 0 が選択されます。 出力は次のとおりです。```
10 10
```すべてのタグが等しい場合、可能なすべての割り当ては同じ MST を与えます。```
Input
4
7 7 7 7 7 7
```最小値では 3 つの 7 が使用されます。 最大値でも 3 つの位置が選択されますが、すべての位置には 7 つが含まれます。 両方の結果は次のとおりです。```
21 21
```最大の場合には、`N - 1`タグは最大 MST を形成できません:```
Input
4
3 5 5 8 8 9
```ソート後の最大位置がインデックスになります`0`、`1`、 そして`3`。 アルゴリズムが選択するのは、`3`、`5`、 そして`8`。 価値観`8`そして`9`大きなエッジが多すぎると、小さなエッジを隠すことができなくなるため、両方を MST に強制的に組み込むことはできません。 結果は次のとおりです。```
13 16
```これはまさに、コンポーネントの増加に関する議論が重要となる状況です。 このアルゴリズムは、単に大きな値を選択するわけではありません。 クラスカルが選択したエッジとして実際に表示される値が選択されます。
