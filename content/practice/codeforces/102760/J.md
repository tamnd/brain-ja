 ## 解決策
 ## 問題の理解

 グリッドはセルを除いて無限です。`(0,0)`壁が含まれています。 リモコンには、1 つの固定された一連の動作が含まれています。 壁以外のセルに配置された車はそのシーケンスに従いますが、移動が壁に進入する場合は常に、その 1 つの移動は無視され、車は残りのコマンドを続行します。 

すべての開始座標について、ボタンを 1 回押した後の最終座標を見つける必要があります。 

コマンドシーケンスの長さは最大です。`300000`、また、最大で`300000`クエリ。 すべてのクエリのパス全体のシミュレーションには、最大で`9 * 10^10`最悪の場合、2 秒の制限をはるかに超えて操作が可能になります。 コマンド シーケンスを 1 回前処理し、一定時間内に各クエリに応答する必要があります。 

重要な問題は、壁が衝突する可能性のある開始位置にのみ影響を与えることです。 ほとんどの開始位置は、壁が存在しないかのようにコマンド シーケンスに従うだけです。 

不注意に実装すると、コマンド パス内の繰り返し位置で失敗する可能性があります。 たとえば、パスが同じ変位を複数回訪問する場合、車がそこで壁に衝突し、シミュレーションの残りの部分が変更されるため、最初の訪問が重要になります。 

コマンドの場合:```
2
RL
```接頭辞の変位は`(0,0)`、`(1,0)`、`(0,0)`。 からのスタート`(0,-0)`は壁であるため無効ですが、近くのケースでも同じ位置の繰り返しの問題が発生します。 プレフィックス位置の最初の出現ではなく最後の出現を保存すると、計算された衝突点が間違ってしまいます。 

もう 1 つのエッジ ケースは、同じ変位に決して戻らないコマンド パスです。 のために：```
1
R
```で始まるクエリ`(5,5)`出力する必要があります`(6,5)`。 変位観測を使用する代わりに、パス付近のすべてのポイントを処理しようとするソリューションでは、時間が無駄になります。 

## アプローチ

 直接的なアプローチは、すべてのクエリのコマンドをシミュレートすることです。 お問い合わせの場合`(x,y)`、現在の位置を保持し、コマンドのすべての文字を適用します。 次のセルが表示されるたびに、`(0,0)`、その動きはスキップします。 これは車の規則に正確に従っているため、明らかに正しいですが、時間がかかります。`O(N)`クエリあたりの時間。 両方とも`N`そして`Q`に等しい`300000`、これは次のようになります`O(NQ)`、それは不可能です。 

重要な観察は、壁が問題となるのは、変換されたコマンド パスが原点に到達した場合のみであるということです。 させて`P[i]`最初の後の車の排気量になります`i`から開始するときのコマンド`(0,0)`。 壁がなければ、車は`(x,y)`で終了します:```
(x + P[N].x, y + P[N].y)
```壁に遭遇するのは次の場合のみです。```
(x,y) + P[i] = (0,0)
```つまり:```
(x,y) = -P[i]
```したがって、特別な処理が必要なのは、接頭辞位置のマイナスである開始位置のみです。 

これらの位置では、パスが初めて壁に到達したときが、その接頭辞の変位の最初の発生になります。 ブロックされた移動の後、パスの残りのサフィックスは通常どおり実行されます。 コマンドを 1 回スキャンする間に、危険な開始位置ごとに答えを前処理できます。 

ブルート フォースは正確なシミュレーションに従うため機能しますが、多くのクエリに対して同じ作業を繰り返すため失敗します。 プリフィックスの変位のみが衝突を引き起こす可能性があるという観察により、問題は例外状態のセットの前処理に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | お(1) | 遅すぎる |
 | 最適 | O(N + Q) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コマンド シーケンス全体の合計変位を計算します。 開始位置が壁に到達しないクエリは、この変位を追加することで答えることができます。 
2. コマンド シーケンスをスキャンし、すべてのプレフィックス ディスプレイスメントを保存します。 各変位について、最初の出現インデックスのみを保持します。 最初の発生は、対応する開始位置で車が壁に衝突する可能性のある最初の時間です。 
3. プレフィックス位置が最初に出現するたびに`P[i]`、危険な開始点のエントリを作成します`-P[i]`。 
4. 危険な開始点の最終位置を計算するには、次のようにします。`i`パスがそのプレフィックス変位に初めて到達したときです。 衝突前に、車は次の位置に到達します。`P[i-1] - P[i]`。 時のコマンド`i`がブロックされ、残りのコマンドが変位に寄与します`P[N] - P[i]`。 

したがって、最終的な位置は次のようになります。```
P[i-1] - P[i] + P[N] - P[i]
```または：```
P[N] + P[i-1] - 2 * P[i]
```1. 各クエリについて、その座標が事前計算された危険位置マップに存在するかどうかを確認します。 存在する場合は、保存されている回答を出力します。 それ以外の場合は、通常の変換された位置を出力します。 

これが機能する理由: 壁とのすべての可能なインタラクションは、コマンド パスのプレフィックス ディスプレイスメントに正確に対応します。 開始位置がプレフィックス変位の負の値でない場合、壁に到達することはなく、最終位置は合計変位だけ離れたところにあります。 それが危険な位置である場合、そのプレフィックス変位の最初の発生によって、最初にブロックされた動きが決定されます。 その時点以降、車の動作は残りの接尾辞によって完全に決定されます。これはまさに数式が計算するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    dx = [0] * (n + 1)
    dy = [0] * (n + 1)

    x = y = 0
    for i, c in enumerate(s, 1):
        if c == 'L':
            x -= 1
        elif c == 'R':
            x += 1
        elif c == 'U':
            y += 1
        else:
            y -= 1
        dx[i] = x
        dy[i] = y

    total_x, total_y = x, y

    first = {}
    for i in range(n + 1):
        pos = (dx[i], dy[i])
        if pos not in first:
            first[pos] = i

    special = {}
    for (px, py), i in first.items():
        if px == 0 and py == 0:
            continue
        prev_x = dx[i - 1]
        prev_y = dy[i - 1]
        ans_x = total_x + prev_x - 2 * px
        ans_y = total_y + prev_y - 2 * py
        special[(-px, -py)] = (ans_x, ans_y)

    q = int(input())
    out = []
    for _ in range(q):
        x, y = map(int, input().split())
        if (x, y) in special:
            ax, ay = special[(x, y)]
            out.append(f"{ax} {ay}")
        else:
            out.append(f"{x + total_x} {y + total_y}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```配列`dx`そして`dy`原点から始まるコマンドパスを保存します。 すべての接頭辞を保持すると、クエリに応答するときに座標を再計算する必要がなくなります。 

の`first`辞書は前処理の重要な部分です。 同じ変位が複数回出現する場合、最初の衝突が発生する場所であるため、最も古いインデックスのみが保存されます。 最後の出現を使用すると、すでに壁を通過した車をシミュレートすることになりますが、これは不可能です。 

の`special`ディクショナリには壁以外の開始座標のみが保存されます。 車がそこからスタートすることはできないため、原点は除外されます。 通常のクエリはすべて、この辞書検索を回避し、総変位を直接使用します。 

すべての計算では Python 整数が使用されるため、オーバーフローの心配はありません。 によるインデックス作成`i - 1`最初に保存された出現は安全であるため、`(0,0)`インデックスです`0`、その場合はスキップされます。

危険なクエリの場合:

 | 値 | 意味 |
 | --- | --- |
 | 出発点 | (-2、-1) |
 | 負のプレフィックス位置 | (2,1) |
 | 最初の出現インデックス | 7 |
 | 前のプレフィックス | (3,1) |
 | 総変位 | (1,1) |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + Q) | コマンド パスは 1 回スキャンされ、すべてのクエリは辞書検索によって応答されます。 |
 | スペース | O(N) | プレフィックスの変位と危険な開始位置を保存します。 |

 パスの長さとクエリの数の両方が制限されるため、この制約により線形前処理が可能になります。`300000`。 このアルゴリズムは、コマンドごとおよびクエリごとに一定量の作業のみを実行します。

 ## 特殊なケース

 繰り返されるプレフィックス位置には、最初に出現したものを使用する必要があります。 コマンド パスが同じ変位に数回到達するとします。 その排気量のマイナスから始まる車は最初の訪問時に衝突するため、その後の訪問は関係ありません。 前処理では最も古いインデックスが保持され、正しいサフィックス シミュレーションが生成されます。 

決して壁に到達しないクエリは、特殊ケースのロジックに入ってはなりません。 たとえば、次のようになります。```
1
R
1
5 5
```総変位は`(1,0)`。 以来`(-5,-5)`は接頭辞の位置ではありません。答えは単純です。`(6,5)`。 

位置をすぐに返すか繰り返すパスは、同じルールによって処理されます。 ディクショナリには各変位が最初に現れた時間のみが含まれているため、シミュレーションでは常に最初にブロックされた動きが使用され、車が壁を通過できるとは決して想定されません。
