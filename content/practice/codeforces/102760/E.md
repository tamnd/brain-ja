 ## 解決策
 ## 問題の理解

 無向グラフがあります。 すべての頂点は一意のラベルで始まり、ラベルの値は次の番号の順列になります。`1`に`n`。 プロセスの各ラウンドで、すべての頂点は隣接する頂点を調べ、その頂点の中で現在存在する最小値を保持します。 最初のラウンドでは元のラベルが使用され、その後の各ラウンドでは前のラウンドで生成された値が使用されます。 

ラウンド後`k`、まったく同じ値を持つ異なる頂点のペアが何組あるかを数えます。 タスクは、すべての正のラウンドにわたってこのカウントの可能な最大値を見つけることです。 

制約は大きく、最大で`100000`頂点と`250000`エッジ。 すべての頂点を繰り返し更新するシミュレーションでは、必要なラウンド数を理解する必要があり、1 ラウンドでもすでにコストがかかります。`O(n + m)`。 グラフは大きくなる可能性があり、答えは多くのラウンド後の動作に依存するため、直接シミュレーションではなく構造観察が必要です。 

ラベルは一意であり、便利なプロパティです。 一定回数のラウンド後に 2 つの頂点が同じ値を持つ場合、それらは両方とも、到達可能な頂点のセットから同じ最小ラベルの頂点を選択しています。 繰り返される最小操作は新しい値を作成するのではなく、既存のラベルを選択するだけです。 

いくつかのケースでは、簡単に誤って処理されてしまいます。 単一のエッジを持つグラフを考えてみましょう。```
2 1
1 2
1 2
```最初のラウンドの後、両方の頂点が他の頂点のラベルを受け取るため、値は次のようになります。`[2, 1]`そして答えは`0`。 元のラベルをラウンドの候補として誤って含めたソリューションはペアをカウントすることになりますが、これは許可されません。`k`から始まります`1`。 

もう 1 つのトリッキーなケースはスターです。```
4 3
1 2 3 4
1 2
1 3
1 4
```1 ラウンド後、すべての葉にラベルが付けられます`1`、与える`C(3, 2) = 3`等しいペア。 中心には最小の葉ラベルが付けられます。 重要な詳細は、グラフが 2 部構成であり、ウォークのパリティが重要であるため、中心と葉が永遠に 1 つのグループになるわけではないということです。 

最後のケースは奇数サイクルです。```
3 3
1 2 3
1 2
2 3
3 1
```十分なラウンドの後、すべての頂点は、必要な長さのウォークで他のすべての頂点に到達できます。 最終的にはすべての頂点にラベルが付けられます`1`、生産`C(3, 2) = 3`。 すべてのコンポーネントを 2 部グラフのように扱うと、奇数サイクルではパリティの制限がなくなるため、これを見逃してしまいます。 

## アプローチ

 直接的なアプローチは、プロセスをシミュレートすることです。 ラウンドごとに、すべてのエッジをスキャンし、両方のエンドポイントの最小近傍値を計算します。 新しいラベルを取得した後、度数表を使用して等しい値を数えます。 これは定義に正確に従っているため、正しいです。 

問題は、どれくらいの時間をシミュレーションする必要があるかを決定することです。 グラフには長いパスが含まれる可能性があり、ステートメントのラウンド数に有用な小さな制限はありません。 繰り返し`O(n + m)`多くのラウンドにわたる作業はコストがかかりすぎます。 最悪の場合、何も変化がなくなるまでシミュレーションしようとすると、可能な時間をはるかに超えて時間がかかる可能性があります。`n = 100000`。 

重要な観察は、値を見るのをやめて、代わりにどの元の頂点が後の頂点に影響を与える可能性があるかを調べることです。`k`ラウンドします。 1 ラウンド後、頂点には距離 1 の頂点の中で最小のラベルが格納されます。 2 ラウンド後、長さ 2 の歩行で到達可能な頂点の中で最小のラベルが保存されます。 一般的に、`h^(k)`正確な長さの歩行で到達可能なすべての頂点の最小ラベルです`k`。 

接続された非二部コンポーネントの場合、十分なステップを経た後、必要な長さのウォークを使用してすべての頂点に到達できます。 コンポーネント内の最小のラベルはどこにでも広がるため、コンポーネント全体が 1 つのグループになります。 

接続された 2 部コンポーネントの場合、各ウォークは両側を交互に行います。 十分なステップを踏むと、頂点はウォーク長のパリティによって決まる辺のすべての頂点に到達できます。 各辺の最小ラベルは、ラウンド パリティに応じて反対側または同じ側に広がります。 実際のラベルは等しいペアの数には影響せず、2 つのカラー クラスのサイズのみが問題になります。 

したがって、最大値はすべてのコンポーネントの安定状態から得られます。 接続されている異なるコンポーネントの頂点が互いに影響を与えることはできないため、コンポーネントの寄与は独立して追加できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | ラウンド数に依存しすぎるため、各ラウンドは`O(n + m)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n + m)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを 2 色で色付けしながら、DFS または BFS を使用してすべての接続コンポーネントを走査します。 色分けにより、コンポーネントが 2 部構成であるかどうかがわかり、各辺のサイズもわかります。 サイド情報はまさに、多くのラウンド後の到達可能性を制御するものです。 
2. コンポーネントのトラバース中に、競合が発生するかどうか、つまりエッジが同じ色の 2 つの頂点を接続するかどうかを保存します。 このような競合は、コンポーネントが二部構成ではないことを証明します。 非 2 部コンポーネントの場合、すべての頂点は最終的にコンポーネントの最小ラベルを受け取ります。 
3. サイズが 2 部構成でない場合`s`、 追加`s * (s - 1) / 2`答えに。 このコンポーネント内のすべてのペアは、最終的には同じ値になります。 
4. カラークラスサイズを持つ 2 部コンポーネントの場合`a`そして`b`、 追加`a * (a - 1) / 2 + b * (b - 1) / 2`。 十分なラウンドの後、2 つのカラー クラスは、各グループ内の値が等しい 2 つの独立したグループになります。 
5. すべてのコンポーネントの寄与の合計を出力します。 コンポーネントを見つけるプロセスはすでにグラフ全体をカバーしているため、ハッシュ ラウンドのシミュレーションは必要ありません。 

なぜ効果があるのか:

 後の頂点の値`k`ラウンドは、一定の長さの歩行で到達可能な頂点のうちの最小の元のラベルによって決定されます。`k`。 接続された非二部グラフでは、十分に長いウォークで任意の 2 つの頂点を接続できるため、コンポーネント全体の最小ラベルがすべての頂点に到達します。 接続された 2 部グラフでは、ウォークによってサイド パリティが維持されるため、同じ色クラスの頂点のみが同じ最終的に到達可能なセットを共有できます。 各到達可能なセット内で選択されたラベルは一意ですが、同じ到達可能なセットを持つすべての頂点に対して同一であるため、最終グループは正確に 2 部コンポーネントのカラー クラスと、非 2 部コンポーネントのコンポーネント全体です。 各ラウンドは、安定した到達可能なセットに到達する前に到達可能な頂点を制限するだけであるため、以前のラウンドでより大きなグループを作成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    labels = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    color = [-1] * n
    ans = 0

    for start in range(n):
        if color[start] != -1:
            continue

        stack = [start]
        color[start] = 0
        cnt = [1, 0]
        bipartite = True

        while stack:
            v = stack.pop()
            for u in graph[v]:
                if color[u] == -1:
                    color[u] = color[v] ^ 1
                    cnt[color[u]] += 1
                    stack.append(u)
                elif color[u] == color[v]:
                    bipartite = False

        if bipartite:
            ans += cnt[0] * (cnt[0] - 1) // 2
            ans += cnt[1] * (cnt[1] - 1) // 2
        else:
            s = cnt[0] + cnt[1]
            ans += s * (s - 1) // 2

    print(ans)

if __name__ == "__main__":
    solve()
```実装にはグラフの走査のみが必要です。 ラベルは元の定義に属しているため読み取られますが、最終的な等しいペアの数はコンポーネントの構造のみに依存し、ラベルの実際の値には依存しません。 

の`color`array は 2 部チェックを実行します。 新しいコンポーネントは色から始まります`0`、すべてのエッジは、もう一方の端点が反対の色を持つ必要があります。 同じ色の間にエッジが見つかった場合、そのコンポーネントには奇数のサイクルが含まれています。 

カウント`cnt[0]`そして`cnt[1]`は、2 部構成要素の 2 つの側面のサイズです。 サイズのグループ内の等しいペアの数`x`は`x * (x - 1) // 2`そのため、最終的なハッシュ値を構築する代わりに、式が直接使用されます。 

Python の整数はオーバーフローしませんが、答えは次のように大きくなる可能性があります。`C(100000, 2)`したがって、固定幅の整数を使用する言語には 64 ビット型が必要になります。

 ## 特殊なケース

 片エッジグラフの場合:```
2 1
1 2
1 2
```DFS は、カラー サイズを持つ 1 つの 2 部コンポーネントを検出します。`1`そして`1`。 貢献度は、`0 + 0 = 0`。 これは、各頂点が常に他の頂点のラベルを受け取るため、2 つの頂点が値を共有することがないため、プロセスと一致します。 

星形グラフの場合:```
4 3
1 2 3 4
1 2
1 3
1 4
```色にはサイズがあります`1`そして`3`。 アルゴリズムは追加します`C(1,2) + C(3,2) = 3`。 3 つの葉は最終的に同じ到達可能な側を持ちますが、中心は他のグループに残ります。 

奇数サイクルの場合:```
3 3
1 2 3
1 2
2 3
3 1
```DFS は、隣接する頂点のどこかに同じ色が必要になるため、グラフを 2 色で色付けできないことを検出します。 コンポーネント全体のサイズは 3 なので、`C(3,2) = 3`。 

接続されていないグラフの場合、各コンポーネントは個別に処理されます。 1 つのコンポーネントの頂点が別のコンポーネントのラベルを参照することはできないため、独立したコンポーネントの寄与を追加すると、正しいグローバル最大値が得られます。
