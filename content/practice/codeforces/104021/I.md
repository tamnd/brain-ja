 ## 解決策
 ## 問題の理解

 基数のある任意の位置記数法で書かれた数字が与えられます。$x$ここで、数字は 0 ～ 9 に限定されず、大文字と小文字を合わせて合計 62 個の異なる記号まで拡張されます。 私たちのタスクは、この文字列を整数値として解釈し、別の基数で表された同じ整数を出力することです。$y$、同じ 62 文字のアルファベットを使用します。 

より具体的に言えば、入力により、ソース ベース、ターゲット ベース、およびソース ベース内の数値の文字列エンコードが得られます。 まずその文字列を真の整数値にデコードし、次にその整数をターゲットのベースに再エンコードする必要があります。 

この制約は、任意精度の算術ライブラリを必要とするほど大きくはありませんが、最大 62 の基数と潜在的に長い入力文字列が存在するため、組み込みの基数変換関数に依存することはできません。 整数演算または手動の数値処理を使用して、変換を慎重にシミュレートする必要があります。 

主な微妙な点は、入力数値がベースの文字列として提供されることです。$x$したがって、先頭のゼロと文字マッピングが重要になります。 不注意な実装は、文字を意図した数値にマッピングせずに生の ASCII 値として扱うため、失敗することがよくあります。 

いくつかの特殊なケースについては、明示する価値があります。 

入力番号が`"0"`基数に関係なく、正しい出力は次のとおりです。`"0"`あらゆるターゲットベースで。 ゼロを個別に処理しない単純な変換ループでは、空の文字列が出力される可能性があります。 

入力に文字のみが使用されている場合、次のようになります。`"FB"`基数 16 では、誤ってマッピングされやすい`'F'`15 ではなく ASCII 値に変更します。たとえば、次のように解釈します。`'F' - '0'`意味のない値を与え、変換を中断します。 

Base 62 の長い文字列など、数値が非常に大きい場合、単純な累乗による直接整数解析はオーバーフローや過剰な計算の危険性がありますが、桁ごとの累算は安全です。 

## アプローチ

 ブルートフォース解釈では、累乗を繰り返し使用して入力文字列を整数に変換しようとします。各位置について、次の計算を行います。$digit \times x^{power}$そしてそれらを合計します。 これは数学的には正しいですが、コンピューティング能力により、不必要な繰り返し作業が繰り返し発生します。 一定の長さの文字列の場合$n$、桁ごとの単純な累乗により複雑さが増します$O(n^2)$、各電力計算には最大で次のコストがかかるため、$O(n)$反復的に行われる場合。 

より効率的で標準的な観察は、位置番号には明示的なべき乗が必要ないということです。 代わりに、左から右に値を段階的に構築できます。 新しい数字ごとに、現在の値が係数でシフトされます。$x$、次に数字を追加します。 これにより、変換が線形スキャンに変換されます。 

整数値を取得したら、それを基数に変換します$y$対称です。 で割ることを繰り返します$y$、新しい基本表現の数字に直接対応する剰余を収集します。 これは、位置システムにおける整数の標準的な貪欲な分解です。 

重要な構造上の考え方は、両方の変換方向が同じアイデンティティの繰り返し適用に帰着するということです。つまり、基数表現は、単に基数による乗算と数字の加算のシーケンスに過ぎません。

 | 線形解析 + 繰り返し除算 | O(n + log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 プロセスを 2 つのフェーズに分けます。入力文字列を整数値にデコードし、次にその整数値をターゲット ベースにエンコードします。 

### 1. 数字マッピングの準備

 文字から値へのマッピングを定義します。`'0'-'9'`0 ～ 9 にマップし、`'A'-'Z'`10-35 にマップし、`'a'-'z'`36-61にマップします。 これにより、各桁の定数時間の解釈が可能になります。 

表現が ASCII ベースの算術演算ではなくカスタム アルファベットであるため、このマッピングは不可欠です。 

### 2. 基数 x の数値を整数にデコードします。 

アキュムレータを初期化します`value = 0`。 キャラクターごとに`c`入力文字列では、それを数値に変換します`d`を更新し、次のように更新します。$$value = value \cdot x + d$$各ステップでは、現在の数値を基数から 1 桁左にシフトします。$x$そして新しい数字を挿入します。 

これが機能するのは、位置表記が数値を次のように定義しているためです。$$(((d_1 \cdot x + d_2)\cdot x + d_3)\cdots)$$したがって、再帰により意図した値が正確に再構築されます。 

### 3. ゼロを明示的に処理する

 入力が`"0"`(または計算値がゼロの場合)、すぐに出力します。`"0"`。 これにより、変換中に空の出力が生成されることが回避されます。 

### 4. 整数を基数 y 表現に変換する

 剰余を繰り返し求めます$y$基数の最下位桁を抽出するには$y$。 各剰余は、数字マッピングの逆を使用して文字にマッピングされます。 

モジュロ抽出では最下位桁が最初に生成されるため、逆の順序で桁を収集します。 

ループの後、収集された文字を反転して、最終的な表現を取得します。 

### なぜ効果があるのか

 正確さは 2 つの不変条件に依存します。 デコード中、最初のデータを処理した後、$i$キャラクター、`value`長さの接頭辞で表される整数と等しい$i$基地内で$x$。 エンコード中、各ステップで残りの数が`value`は、すでに出力された下位桁を削除した後の商とまったく同じなので、各モジュロ演算により基数内の正しい次の桁が抽出されます。$y$。 これらのプロパティにより、両方のフェーズで曖昧さなく同じ整数が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def char_to_val(c):
    if '0' <= c <= '9':
        return ord(c) - ord('0')
    if 'A' <= c <= 'Z':
        return ord(c) - ord('A') + 10
    return ord(c) - ord('a') + 36

def val_to_char(v):
    if v < 10:
        return chr(ord('0') + v)
    if v < 36:
        return chr(ord('A') + v - 10)
    return chr(ord('a') + v - 36)

x, y, z = input().split()
x = int(x)
y = int(y)

value = 0
for c in z.strip():
    value = value * x + char_to_val(c)

if value == 0:
    print("0")
    sys.exit()

res = []
while value > 0:
    res.append(val_to_char(value % y))
    value //= y

print("".join(reversed(res)))
```デコード ループはソリューションの中核です。 累乗を完全に回避し、ベース内の解析されたプレフィックスを常に表すローリング値を維持します。$x$。 エンコード ループは長い除算を反映しています。各反復で最も重要でない基底が削除されます。$y$桁。 

よくある間違いは、入力文字列から改行文字を削除するのを忘れることで、数字の解析が中断されてしまいます。 もう 1 つはゼロを誤って処理しており、そうでない場合は空になります。`res`リストと間違った出力。
