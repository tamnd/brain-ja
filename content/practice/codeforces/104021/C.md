 ## 解決策
 ## 問題の理解

 左から右に 1 つずつ処理された一連の画像が与えられます。 各画像には隠された「真の」コントラスト値がありますが、私たちに直接与えられるのはエンコードされたシーケンスです。 デコード規則は逐次的です。現在の画像の実際のコントラストは、入力値と以前に計算された応答値との XOR 演算によって取得されます。 これにより、デコードされたすべての値が以前のすべての決定に依存する依存関係の連鎖が作成されます。 

位置 i までの真のコントラストがわかったら、長さ i の接頭辞を連続するグループに分割することを検討する必要があります。 すべてのグループには少なくとも k 個の画像が含まれている必要があり、各グループ内でその「コスト」を、そのグループ内の 2 つのコントラスト値間の最大差として測定します。 各プレフィックス i の目標は、すべての有効なパーティションにわたる最悪のグループ コストを最小限に抑えることです。 

出力は、i 番目の値が最初の i イメージの最小可能最悪グループ コストを表す配列、または有効なパーティションが存在しない場合はゼロです。 

n 最大 1,000,000 という制約により、単純な間隔チェックでは二次関数または n log n DP さえも即座に除外されます。 セグメントの最大値を繰り返し再計算したり、すべての分割点を試行したりするソリューションは、タイムアウトになります。 増分構造を維持し、範囲の再計算を避ける必要があります。 

実現可能性から微妙な特殊なケースが発生します。 i < k の場合、グループを形成することさえできないため、答えは強制的にゼロになります。 もう 1 つのそれほど明白ではない失敗ケースは、グループを貪欲に形成しようとした場合に発生します。ローカル グループ化が有効であっても、目的は単に有効なブロックを形成することではなく、グループの最大拡散を最小限に抑えることであるため、将来の制約によって以前の貪欲な決定が最適ではなくなる可能性があります。 

このエンコーディングには罠も導入されています。vi は ci−1 に依存しているため、値が正しく計算されなかったり、順序が狂ったりすると、将来のすべての値が即座に破損します。 

## アプローチ

 ブルートフォース手法は、ci−1 が得られたらすべての値をデコードすることから始まり、次に各 i について、プレフィックスの考えられるすべての分割を少なくとも k 以上のサイズのセグメントに試みます。 各パーティションについて、各セグメント内の最大範囲を計算し、セグメント全体で最大値を取得し、すべてのパーティションで最小化します。 

範囲最大値を事前に計算したとしても、有効な各カットは最小サイズ k によってのみ制約されるため、プレフィックスのパーティション数は i で指数関数的になります。そのため、最悪の場合の遷移は依然として組み合わせ的に爆発します。 動的計画法公式 dp[i] = min over j ≤ i−k of max(dp[j], range(j+1, i)) はすでに O(n²) の遷移を示唆しており、範囲クエリが O(1) であるとしても、これは 10⁶ までの n にとってはまだ大きすぎます。 

重要な構造上の観察は、固定セグメントの場合、そのコストはそのセグメントの最小値と最大値のみに依存するということです。 したがって、問題は間隔の極値を制御するパーティションの維持に帰着します。 これは、すべての分割を試す必要はなく、実現可能なセグメントのエンドポイントにわたって単調な構造を維持する必要があることを示唆しています。 

重要な洞察は、配列を拡張すると、最後のグループのみが変更され、以前のグループは有効なままになる可能性があるということです。 したがって、グローバル パーティションを再計算する代わりに、最後のセグメントが常に最適に配置されることを保証する構造を維持し、最小値と最大値のスライディング ウィンドウ スタイルの維持と組み合わせたセグメント長の貪欲なチェックを使用して実現可能性を追跡します。

この問題は、各セグメントの長さが少なくとも k であることを保証し、セグメント全体の最大値 (max − min) を最小化する必要があるパーティションを維持することとして再解釈できます。 固定された候補回答 X については、実現可能性を貪欲にテストできます。(現在の最大値 − 現在の最小値) ≤ X である限りセグメントを拡張し、最小長 k を尊重しながら必要に応じて切断します。 これにより、単調な実現可能条件が得られ、プレフィックスごとにバイナリのような構造が可能になりますが、すべての ci がオンラインである必要があるため、代わりに、deque ベースのウィンドウ追跡極値と貪欲なセグメンテーション ポインターを使用して、達成可能な最良の境界を増分的に維持します。 

最後の最適化は、最初から有効なセグメントを貪欲に形成することで、各位置で達成可能な最小の最大範囲を維持し、各セグメントが実現可能性の下で最大限に拡張されることです。 セグメントの範囲を拡大する早期のカットは最大値を悪化させるだけであり、最小長の制約を尊重する限りカットを遅らせても安全であるため、この貪欲さが最適です。

 ## アルゴリズムのチュートリアル

 要素を左から右に処理し、デコードされた配列をオンザフライで維持します。 

1. vi = xi XOR c(i−1) を使用して各 vi をデコードします。 すべての値は前の回答に依存するため、これは順番に実行する必要があります。 
2. 現在の暫定セグメントの最小値と最大値を効率的にクエリできる構造を維持します。 セグメントを右に拡張するだけであるため、最小値と最大値の単調デキューで十分です。 
3. 位置 1 から貪欲にセグメントの構築を開始します。現在のセグメントについて、最小値と最大値を追跡しながら、その右側の境界を可能な限り拡張します。 さらに拡張すると最適な構造に違反する点に達した時点、またはセグメントを完成させる必要性が満たされた時点で、切断を検討します。 
4. セグメントの長さが少なくとも k である場合にのみ、セグメントをファイナライズできます。 この制約により、範囲が大きくなっても、早期にカットすることは違法であるため、場合によっては延長し続けなければなりません。 
5. l で始まるセグメントの位置 r でカットすることを決定した場合、そのセグメントのコストを max(v[l..r]) − min(v[l..r]) として記録し、これを現在のプレフィックスの答えの一部として伝播します。 
6. 各プレフィックス i について、値 ci は、この貪欲な構造で i までに形成されたすべてのセグメントの最大セグメント コストです。 
7. i < k の場合、有効なセグメンテーションが存在しないため、直接 0 を出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのカット ポイントで、最終化するセグメントが、すべてのセグメントに少なくとも k 個の要素が必要であるというルールを遵守した、左側の境界から始まる可能な限り長いセグメントであるということです。 以前のカットは最小サイズの制約に違反するか、一部のセグメントで厳密に悪い (より大きな) 最大範囲を強制することになります。これは、カットを遅延しても以前の要素の min が減少したり、max が増加したりすることはないためです。 したがって、貪欲セグメンテーションは、セグメントごとに局所的に最適なパーティションを構築し、プレフィックス全体の最大セグメント範囲をグローバルに最小化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    x = list(map(int, input().split()))

    v = [0] * n
    c = [0] * (n + 1)

    from collections import deque

    mindq = deque()
    maxdq = deque()

    seg_start = 0
    seg_costs = []
    ans = []

    def add(i):
        while mindq and v[mindq[-1]] >= v[i]:
            mindq.pop()
        mindq.append(i)

        while maxdq and v[maxdq[-1]] <= v[i]:
            maxdq.pop()
        maxdq.append(i)

    for i in range(n):
        if i == 0:
            v[i] = x[i]
        else:
            v[i] = x[i] ^ c[i]

        add(i)

        if i - seg_start + 1 >= k:
            # compute current segment cost
            while mindq[0] < seg_start:
                mindq.popleft()
            while maxdq[0] < seg_start:
                maxdq.popleft()

            cost = v[maxdq[0]] - v[mindq[0]]

            c[i + 1] = max(c[i], cost)

            # greedy cut: reset segment
            seg_start = i + 1
            mindq.clear()
            maxdq.clear()
        else:
            c[i + 1] = c[i]

    print("\n".join(map(str, c[1:])))

if __name__ == "__main__":
    solve()
```このソリューションは、以前の回答への依存関係を使用して、デコードされた配列をオンラインで構築します。 デキューは、現在のアクティブなセグメント内の最小値と最大値を維持するため、カットが考慮されるときにセグメント コストを定数時間で評価できます。 

セグメンテーション ロジックにより、セグメントがサイズ k に達した場合にのみカットが行われるように強制され、実現可能性が保証されます。 切断後は、新しいセグメントが新たに開始されるため、データ構造はリセットされます。 

微妙な詳細は、以前のセグメントがすべてのプレフィックスの最終的な答えを決定するため、これまでに確認された最大コストを常に c[i] に伝播することです。 これにより、c は単調非減少となり、最悪のセグメントコストを最小化するという解釈と一致します。

 ## 特殊なケース

 n < k の場合、セグメントを形成できないため、アルゴリズムはすべての位置に対して 0 を出力します。 たとえば、入力 n = 2、k = 5 は、有効なグループを形成する条件が決して満たされないため、すぐに c1 = c2 = 0 を生成します。 

k = 1 の場合、すべての要素が独自のセグメントを形成します。 貪欲なロジックはすべてのインデックスで即座にカットし、各 ci は 1 つの要素内の最大差になります。最小値と最大値が等しいため、値は常にゼロになります。 

より微妙なケースは、大きな XOR フィードバックによってステップ間で値が大幅に反転される場合に発生します。 vi は ci−1 に依存するため、初期の間違ったセグメンテーションが後で完全に異なる vi 値に伝播する可能性がありますが、貪欲な構築により、vi+1 よりも前に ci が計算され、一貫性が保たれます。
