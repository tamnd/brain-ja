 ## 問題の理解

 私たちは、すべてのノードが整数値を格納するルート付きツリーを操作しています。 任意のノードに対して$x$では、ツリーの制限された領域、つまりすべての子孫を調べます。$x$その深さから$x$せいぜい$k$。 これらのノードから値をマルチセットに収集します。$p(x, k)$。 マルチセットであるため、繰り返される値が重要です。2 つの異なるノードが同じ値を持つ場合、両方のコピーは別々に表示されます。 

各ノードについて$x$、要素の順序付けされていないすべてのペアに対して定義されたスコアを計算する必要があります。$p(x, k)$、同一の要素のペアが含まれます。 値のペアの場合$u, v$、私たちは取る$u \oplus v$、それを二乗し、これをすべてのペアで合計します。 ペアは多重度を持って取得されるため、これは順序付けられたすべてのペアを合計することと同等です。$(u, v)$含む$u = v$。 

ツリーのサイズは次のように大きくできます。$10^5$、各ノードはその位置に応じて多くのクエリに寄与します。 これにより、それぞれの再計算が即座に排除されます。$p(x, k)$BFS または DFS とは独立して、ノードごとの線形再計算でも$O(n^2)$連鎖など最悪の場合の挙動。 

微妙な点は、スコアでは異なるノード間のペアではなく、同じマルチセット内のペアがカウントされることです。 単純なソリューションが誤って値の重複を排除したり、異なるペアのみをカウントしたりすると、不正確な結果が生成されます。 たとえば、次の場合$p(x, k) = \{1, 1\}$、正しい貢献には以下が含まれます$(1 \oplus 1)^2$いずれにせよゼロですが、大きな場合には重複が重要になります。 

もう 1 つの特殊なケースは、深さのカットオフです。 チェーン ツリーでは、上部近くのノードにはほとんどすべての子孫が含まれますが、下部近くのノードにはほとんど子孫が含まれません。 均一なサブツリー サイズを前提とするソリューションは、歪んだツリーでは失敗します。 

## アプローチ

 直接的なアプローチは計算することです$p(x, k)$深さに制限された BFS または DFS を使用するノードごとに個別に$k$。 各ノードについて$x$、すべての有効なノードを収集し、そのセット内のすべてのペアを計算します。 設定サイズの場合$s_x$、スコアの計算に必要な$O(s_x^2)$XOR評価とセットコストの構築$O(s_x)$。 最悪の場合の連鎖では、ルートは$s_x = n$、与える$O(n^2)$ノードが 1 つだけの場合、全体の複雑さは次のようになります。$O(n^3)$すべてのノードにわたって。 

主な問題点は、これらのセットの多くが重なり合っていることです。 ノードとその親はツリーの 1 レベルだけ異なります。これは、ノードの寄与の大部分が共有されることを意味します。 これは、再ルート化または DSU-on-tree スタイルの計算の再利用を示唆しています。 

スコア自体は、明示的なペアの列挙ではなく、頻度カウントの集計を可能にする方法で書き換えることができます。 アクティブなウィンドウ内の値の頻度を維持すると、ビット位置ごとのビット単位の寄与を使用してペアの合計を表現できます。 XOR の場合、各ビットが独立して寄与するため、ビット全体で問題を分解し、明示的にペアを列挙することを回避できます。 

これにより、アクティブなノード セットごとにビットごとの値のカウントを維持するという解決策が得られます。 値を挿入または削除すると、コントリビューションが段階的に更新されます。 各ノードのアクティブな領域が深さのスライディング サブツリー ウィンドウに対応することを保証するツリー トラバーサルと組み合わせる$k$、計算を効率的に再利用できます。 

「最大距離」を強制する標準的な方法$k$」制約は、深さごとにアクティブなノードのマルチセットを持つ DFS を維持するか、DFS スタック上でスライディング ウィンドウを維持し、深さを超えるノードを削除することです。$k$。 トラバーサル中、各ノードの答えは現在アクティブなマルチセットから計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$最悪の場合 |$O(n)$| 遅すぎる |

 ここ$A$は最大値です（最大$10^9$）。 

## アルゴリズムのチュートリアル

 ルートからの深さ優先のトラバースでツリーを処理し、現在最大の距離内にあるすべてのノードを表す構造を維持します。$k$現在のノードから。 

DFS 内のどの時点でも、深さが次の範囲内にあるノードのウィンドウを維持します。$[depth[x] - k, depth[x]]$。 これは、深さによってインデックス付けされたスタックを使用して強制できます。各深さレベルには、現在アクティブなノードの値が格納されます。 

各値について、アクティブ セット全体のビットごとのカウントも維持します。 これにより、ペアを列挙せずに XOR ペアの合計を計算できます。 

アクティブ セット内のすべてのペアの現在のグローバル コントリビューションを維持します。 値を挿入すると、その値が既存の要素と形成する新しいペアの数が更新されます。 取り外しの際も同様のことが起こります。 

## ステップ

 1. ノード 1 でツリーをルートし、DFS トラバーサル中にすべてのノードの深さを計算します。 この深さは、純粋に先祖伝来の方法で距離制約を強制するために使用されます。 重要な観察は、すべてのノードが距離内にあることです。$k$DFS 内のノードからのは、深度ウィンドウ内のノードに対応します。 
2. 配列を維持する`freq`サイズ 31 (以来$a_i \le 10^9$) ここで、各エントリには、そのビットが設定されているアクティブな番号の数が格納されます。 これにより、XOR 寄与をビットごとに計算できるようになります。 
3. グローバル変数を維持する`current_score`のアクティブな値のすべての順序付きペアの合計を表します。$(u \oplus v)^2$。 最初から再計算するのではなく、段階的に更新します。 
4. 値を挿入する場合$v$、ビットごとの分解を使用して、現在のアクティブ セットに対する寄与を計算します。 以前にアクティブだった各値について、XOR 二乗はビットの合計として表すことができます。 

の$b$-番目のビットが寄与する$2^{2b}$ビットが異なる場合。 使用する`freq`、ビットを持つ既存の番号の数を決定します$b$設定または設定解除し、それに応じてスコアを更新します。 投稿を処理した後、更新します`freq`。 

これが機能する理由は、1 つの要素を挿入するときに、すべてのペアを再計算するのではなく、既存の要素とのペアを考慮するだけでよいためです。 
5. 値を削除するときは、同じ寄与ロジックを逆にします。つまり、そのペアの寄与をグローバル スコアから減算し、デクリメントします。`freq`。 
6. DFS 中に、ノードを探索する前に、その値をアクティブな構造に挿入します。 挿入後、深度ウィンドウが有効な場合は、`current_score`そのノードの答えとして。 
7. DFS から戻る前に、ウィンドウから外れたノードを削除し、アクティブ セットが常に距離内のノードを正確に反映するようにします。$k$。 

## なぜ機能するのか

 すべての DFS 状態で、アクティブなマルチセットは、現在のノードとの深さの差が最大で 1 つであるノードのセットです。$k$。 スコアはこのマルチセットのみに依存し、内部のペアごとの XOR 相互作用によって完全に決定されます。 

XOR 二乗は独立したビット位置に分解されるため、ペアの寄与は、情報を失うことなく頻度カウントを使用して段階的に更新できます。 挿入または削除のたびに、変更された要素に関係するペアのセットが正確に更新されるため、相互作用が二重にカウントされたり見逃されたりすることはありません。 

DFS ウィンドウのメンテナンスにより、有効な近傍が一度だけ完全に表現される状態ですべてのノードが評価されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 31

def add(x, freq, bitcnt):
    # update contribution of x against existing set
    add_score = 0
    for b in range(MAXB):
        xb = (x >> b) & 1
        if xb:
            add_score += (1 << (2 * b)) * (len(freq) - bitcnt[b])
        else:
            add_score += (1 << (2 * b)) * bitcnt[b]

    # update bit counts
    for b in range(MAXB):
        if (x >> b) & 1:
            bitcnt[b] += 1

    freq.append(x)
    return add_score

def remove(x, freq, bitcnt):
    rem_score = 0
    for b in range(MAXB):
        xb = (x >> b) & 1
        if xb:
            rem_score += (1 << (2 * b)) * (len(freq) - bitcnt[b])
        else:
            rem_score += (1 << (2 * b)) * bitcnt[b]

    freq.pop()
    for b in range(MAXB):
        if (x >> b) & 1:
            bitcnt[b] -= 1

    return rem_score

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    g = [[] for _ in range(n + 1)]
    parent = list(map(int, input().split()))

    for i, p in enumerate(parent, start=2):
        g[p].append(i)

    depth = [0] * (n + 1)
    ans = [0] * (n + 1)

    freq = []
    bitcnt = [0] * MAXB
    current_score = 0

    stack = []

    def dfs(u):
        nonlocal current_score
        stack.append((u, depth[u]))

        # remove nodes too far in depth
        while stack and depth[u] - stack[0][1] > k:
            v, _ = stack.pop(0)
            current_score -= remove(a[v], freq, bitcnt)

        # add current
        current_score += add(a[u], freq, bitcnt)

        ans[u] = current_score

        for v in g[u]:
            depth[v] = depth[u] + 1
            dfs(v)

        # rollback
        current_score -= remove(a[u], freq, bitcnt)
        stack.pop()

    dfs(1)

    print("\n".join(str(x % (1 << 64)) for x in ans[1:]))

if __name__ == "__main__":
    solve()
```この実装では、アクティブ ノードの DFS スタックが維持され、ビット位置にわたる周波数構造が維持されます。 挿入および削除ロジックにより、現在の要素に関係する相互作用のみが更新されるようになり、完全なペア行列の再計算が防止されます。 

微妙な点は、このソリューションでは順序付きペアのカウントを前提としているため、既存のすべての要素との相互作用を考慮することで、各挿入が暗黙的に両方向を考慮していることです。
