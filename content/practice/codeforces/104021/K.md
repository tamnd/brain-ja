 ## 解決策
 ## 問題の理解

 次のサイズの 2 つの正方形グリッドが与えられます。$n \times m$、各セルにはそのグリッド内の一意の整数が含まれます。 単一の行列内の値が繰り返されることはありませんが、2 つの行列にまたがって値が両方に出現する可能性があります。 

部分行列は、行と列の連続する長方形のブロックを選択することによって定義されます。 両方の行列に同じ構造で現れる部分行列の可能な最大の領域を見つけたいと考えています。これは、値のパターンが 2 番目の行列の長方形と正確に一致する長方形が最初の行列に存在することを意味します。 

各行列のすべての値は個別であるため、すべての値はその位置の一意の識別子のように機能します。 これは重要な構造の単純化です。生の値を比較する代わりに、2 つの行列間で一致する値の位置を推論できます。 

制約により許可されるのは、$n, m \le 1000$したがって、グリッドには最大$10^6$細胞。 より近いソリューションはどれか$O(n^2 m^2)$次のオーダーが必要になるため、すぐには不可能です$10^{12}$比較。 平$O(n^2 m)$理想的には行ごとまたは列ごとに線形またはほぼ線形のスキャンを使用して、慎重に構築する必要があります。 

単純な誤解は、値の一意性を使用せずに、これを 2 次元の最長の共通部分文字列として扱うことから生じることがよくあります。 これにより、すべての部分行列をハッシュしたり、すべての四角形を直接比較したりすることになりますが、これは実行不可能になります。 

一貫した相対位置を強制せずに、純粋に値の同一性によって部分行列を一致させようとすると、微妙な失敗のケースが発生します。 たとえば、長方形内のすべての値が他の行列のどこかに出現することだけをチェックすると、長方形以外の配置を誤って受け入れてしまうことになります。 

正しく定式化するには、行方向と列方向の両方で隣接関係を同時に維持する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、最初のグリッドで考えられるすべての部分行列を列挙し、2 番目のグリッドで同一の部分行列を見つけようとします。 ハッシュまたは直接比較を使用してチェックを最適化したとしても、部分行列の数は$O(n^2 m^2)$、そしてそれぞれを検証するにはエリア内で少なくとも直線的な時間がかかり、全体の作業は完全に実行不可能になります。 

重要な観察は、各行列内の値の一意性から得られます。 各数値は行列ごとに 1 回だけ出現するため、すべての値が一意の座標を定義します。 これにより、問題を値の四角形の比較から座標の差の四角形の比較に変換することができます。 

行列 A のすべての値をその位置にマッピングし、行列 B に対して同じことを行うと、任意の値が参照アンカーとして機能します。 部分行列が両方のグリッドに存在する場合、その左上の要素を選択すると、その部分行列内の他のすべての要素に一貫したオフセット パターンが与えられます。 これは、一致するアンカー セルのペアを固定すると、共通部分行列の存在が、位置の一貫性を維持しながら 2 方向に拡張するという問題になることを意味します。 

これにより、この問題は、位置合わせされた座標にわたる 2D の最長共通展開問題に変換され、事前に計算された一致位置を使用して行ごとにチェックできます。 

タスクを、値から位置へのマッピングによって引き起こされる同一の水平方向の配置パターンが連続する行に保存される最大の長方形を見つけるという作業に効果的に削減します。

 ## アルゴリズムのチュートリアル

 まず両方の行列の逆引き検索を構築し、すべての値についてその行列内の座標を把握します。 これにより、一方の行列の値からもう一方の行列の位置への定時間変換が可能になります。 

次に、2 つの行列間の構造的位置合わせをエンコードするヘルパー グリッドを構築します。 ポジションごとに$(i, j)$行列 A 内で、その値が行列 B 内で出現する場所を特定し、座標を与えます。$(x, y)$。 この座標のペアにより、A の隣接セルが B でも隣接性を維持しているかどうかを推論できます。 

次に、問題を、有効な位置合わせの最大の長方形を見つけることに変換します。 隣接する列のペアに対して、水平方向の隣接関係が両方の行列で同時に保存されるかどうかという 2 値条件を定義します。 各行について、この水平方向の一貫性が右にどれだけ広がっているかを表すヒストグラムのような構造を計算します。 

次に、各行をヒストグラムのベースとして扱い、行をスイープします。 各列について、上にある連続する行の数を維持し、水平方向の一貫性も維持します。 これにより、各行のヒストグラム内の最大の四角形を計算するという問題が軽減されます。 

このプロセス中に見つかった最大の長方形の領域が答えになります。 

### なぜ効果があるのか

 有効な共通部分行列は、水平方向と垂直方向の両方で隣接関係を保持する必要があります。 水平方向の隣接性により、すべてのセルの右隣が他の行列内の対応するセルの右隣と一致することが保証されます。 垂直スタッキングにより、この一貫性が複数の行にわたって確実に拡張されます。 

すべての値は一意であるため、隣接関係の一貫性によって部分行列が両方の行列にわたって同一であるかどうかが完全に決まります。 これにより、2D パターン マッチングの問題が、行にわたる 1D ヒストグラム展開に縮小されます。正確性は、すべての制約がローカル隣接チェックに分解されるという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]
    B = [list(map(int, input().split())) for _ in range(n)]

    posB = {}
    for i in range(n):
        for j in range(m):
            posB[B[i][j]] = (i, j)

    match_row = [[0] * m for _ in range(n)]
    match_col = [[0] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            x, y = posB[A[i][j]]
            match_row[i][j] = (y == posB[A[i][j+1]][1] if j + 1 < m else 0)
            match_col[i][j] = (x == posB[A[i+1][j]][0] if i + 1 < n else 0)

    # height array for histogram of valid rows
    height = [[0] * m for _ in range(n)]

    for j in range(m):
        height[0][j] = 1

    for i in range(1, n):
        for j in range(m):
            if match_col[i-1][j]:
                height[i][j] = height[i-1][j] + 1
            else:
                height[i][j] = 1

    ans = 1

    # for each row, compute largest rectangle using horizontal validity
    for i in range(n):
        stack = []
        for j in range(m + 1):
            cur = match_row[i][j] if j < m else 0
            while stack and match_row[i][stack[-1]] >= cur:
                idx = stack.pop()
                h = height[i][idx]
                width = j if not stack else j - stack[-1] - 1
                ans = max(ans, h * width)
            stack.append(j)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、各値を瞬時にその座標に解決できるように、まず行列 B の位置マップを構築します。 これは、スキャンせずに隣接関係を比較できるようにする構造的なバックボーンです。 

の`match_row`テーブルは、A の右方向の移動が B の右方向の移動に対応するかどうかをチェックします。この条件が当てはまる場合、そのセルでの水平構造は一貫しています。 同様に、垂直方向の一貫性は、`height`配列。各列で垂直方向の配置を維持する連続行の数をカウントします。 

最後のステップは、行ごとの標準的な単調スタック ヒストグラムの計算です。幅は水平方向の一貫性から得られ、高さは垂直方向の連続性から得られます。 

よくある実装の落とし穴は、水平制約と垂直制約が独立して相互作用することを忘れていることです。 これらを 1 つの DP 状態に混在させると、多くの場合、過剰なカウントや誤った四角形の拡張が発生します。

```マトリックス B:```

 最大の長方形は行 1 ～ 2、列 0 ～ 1 で形成される 2x2 で、エリア 4 になります。 

### 例 2

 最小限のケース:```

1 2
3 4

B:
1 2
3 4
```すべての水平方向および垂直方向の一致はどこでも当てはまります。 

| 行 | コラム | マッチ行 | 身長 |

これらのトレースは、垂直方向の累積が水平方向の実現可能性とは無関係であり、長方形を形成するには両方が整列する必要があることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、行列が値を共有しているものの、空間配置が完全に異なる場合です。 このような場合、隣接性が維持されないため、値の平等だけでは誤解を招きます。 アルゴリズムは、水平方向と垂直方向の両方の一貫性を強制することでこれを回避します。`match_row`そして`height`。 

もう 1 つのケースは、単一セルの一致のみが存在する場合です。 たとえば、隣接関係の保持の観点からすべての値が分離されている場合でも、アルゴリズムはどこでも高さ 1 と幅 1 を生成し、無効な拡張を試行することなく正しく答え 1 を生成します。 

最後に、1×m や n×1 などの縮退グリッドも自然に処理されます。 水平または垂直の遷移は崩壊しますが、境界はゼロ遷移として扱われるため、ヒストグラム構造は依然として正しく計算されます。
