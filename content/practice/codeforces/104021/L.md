 ## 解決策
 ## 問題の理解

 最大 7 × 7 の小さなグリッドが与えられます。このグリッドには、「オブジェクト」を含むセルと空のセルがあります。 各オブジェクトは長さ 5 以内の短い文字列で記述され、文字列内の各位置が属性を表します。 軸に沿って最大 1 回回転するポリライン パスを使用してグリッド位置を接続できれば、2 つのオブジェクトをペアとして削除できます。このパスは他のオブジェクトを通過してはなりません。 

有効なペアを削除すると、それらの属性文字列がどれだけ似ているかにのみ依存するスコアが得られます。 具体的には、2 つの文字列が正確に p 位置で一致する場合、スコア s[p] を受け取ります。 このタスクは、すべてのオブジェクトが 1 回だけ使用され、合計スコアが最大になるように、素のペアにあるすべてのオブジェクトを削除することです。 

重要な構造は、グリッドはペアを許可するかどうかの幾何学的制約にすぎず、スコアリングは文字列の類似性のみに依存するということです。 オブジェクトの数は最大 18 ですが、ペアリングの状態を直接列挙できるほど十分に小さいです。 

この制約により、グリッド内の削除シーケンスをシミュレートしようとしたり、マッチング中にパスを動的に検索したりするアプローチは直ちに除外されます。 グリッド内で削除命令に応じて分岐しようとするソリューションは、要因によって爆発してしまいます。 その代わりに、問題は、エッジが「幾何学的に有効」であり、類似性によって重み付けされている、最大 18 ノードのグラフ上で完全に一致するものを選択することに帰着します。 

微妙なエッジ ケースは、2 つのオブジェクト間のパスがグリッドの壁だけでなく中間オブジェクトによってブロックされているという事実から生じます。 これは、行または列に並んでいる 2 つのオブジェクトが間に別のオブジェクトがある場合、接続できない可能性があることを意味します。 

たとえば、3 つのオブジェクトが同じ行に並んでいる場合、隣接するオブジェクトのみが接続できます。 ブロッキングをチェックせずにジオメトリのみを比較する単純なチェックでは、エンドポイントが誤って接続し、スコアを過大評価する可能性があります。 

もう 1 つのエッジケースは、幾何学的に多くのペアが有効に見えても、唯一の有効なペアリング構造がブロッキングにより非自明なペアリングを強制する場合です。 

## アプローチ

 グリッド制約を無視すると、問題は最大 18 ノードでの古典的な最大重みの完全一致になります。 これでも、サブセットに対するビットマスク動的プログラミングがすでに示唆されています。 

複雑なのは、どのペアが許可されるかを決定することです。 任意の 2 つのオブジェクトについて、それらのグリッド位置の間に他のすべてのオブジェクトを回避する L 字型のパスが存在するかどうかを確認する必要があります。 グリッドは 7 × 7 しかないため、このチェックは、最大 2 つの可能な L 字型を試し、中間のセルがすべて空であることを確認することで直接実行できます。 

どのペアが有効であるかが分かると、問題は純粋に組み合わせの問題になります。つまり、すべてのノードをカバーする互いに素なペアを選択して、合計の重みを最大化します。 この強引なアイデアは、考えられるすべてのペアを再帰的に列挙することです。 各ステップで、未使用のオブジェクトを 1 つ選択し、それを他のすべての未使用のオブジェクトとペアにしてみます。 これにより、すべての完全な一致が調査されます。 

n 個の項目をペアにする方法の数はおよそ (n-1)!! で、n = 18 の場合、すでに 10^7 通り以上の可能性があり、各ステップには遷移が含まれるため境界線に達しますが、それでもオーバーヘッドと組み合わせると Python では遅すぎます。 

主な改善点は、状態を未使用オブジェクトのビットマスクとして扱い、メモ化された再帰または DP を適用することです。 各状態は、最初の未使用オブジェクト i を選択し、それを同じく未使用で有効な接続を持つ任意の j > i とペアにすることによって遷移します。 これにより、各ペアリング構造が重複することなく 1 回だけ考慮されることが保証されます。 

これにより、問題は O(2^n * n^2) 個の遷移に軽減され、n ≤ 18 の場合は簡単に管理できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペアリングの列挙 | O((n-1)!! · n) | O(n) | 遅すぎる |
 | ペアリング上のビットマスク DP | O(2^n · n^2) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずすべてのオブジェクトのリストを作成し、それらに 0 から n−1 までのインデックスを割り当てます。 それらのグリッド位置と属性文字列が保存されます。 

次に、文字列内の一致する位置の数を数えることにより、オブジェクトの各ペアのスコア テーブルを事前計算します。 これにより、ペアリングに対する報酬が得られます。 

また、各ペアが L 字型制約の下で接続できるかどうかも事前計算します。 セルのペアごとに、考えられる 2 つのコーナー ポイントをテストします。1 つは水平に続いて垂直に進み、もう 1 つは垂直に続いて水平に進みます。 各候補パスについて、すべての中間セルが空であるか、エンドポイントの 1 つであることを確認します。 

前処理の後、ビットマスク DP を実行します。 

1. 状態 dp[mask] を、mask で表されるオブジェクトのセットを正確に使用して達成可能な最大スコアとして定義します。ここで、mask = 1 は、オブジェクトがまだ使用されていないことを意味します。 
2. マスクが空の場合、オブジェクトが残っていないため、スコアは 0 になります。 
3. それ以外の場合は、マスク内にまだ存在する最小のインデックス付きオブジェクト i を選択します。 最初の選択肢を固定すると、同等のペアの対称的な再計算ができなくなります。 
4. j もマスク内にあり、ペアが幾何学的に有効であるように、i と他のすべての j > i のペアを試行します。 有効なペアごとに、dp[i と j を含まないマスク] にペアリング スコアを加えたものに移行します。 
5. このようなすべての選択肢の最大値を取得し、それを dp[mask] として保存します。 

再帰はメモ化されるため、各マスクは 1 回計算されます。 

### なぜ効果があるのか

 すべての有効なソリューションは、オブジェクトのセット上で完全に一致します。 DP は、常に利用可能な最小のインデックスを最初に選択することによってマッチングを構築します。これにより、各マッチングが正確に 1 つの正規順序で生成されることが保証されます。 すべての遷移では正確に 2 つの要素が削除され、選択されたピボットのすべての有効なパートナーが考慮されるため、有効なペアがスキップされることはなく、異なる順序でペアが 2 回カウントされることもありません。 

ペアが選択されると、残りの問題は以前の決定とは関係なく、残りのマスクにのみ依存するため、最適な部分構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def can_link(a, b, pos, occ, n, m):
    (x1, y1) = pos[a]
    (x2, y2) = pos[b]

    def clear_path(cells):
        for x, y in cells:
            if (x, y) in occ and (x, y) != (x1, y1) and (x, y) != (x2, y2):
                return False
        return True

    # L shape 1: (x1, y1) -> (x1, y2) -> (x2, y2)
    path1 = []
    y = y1
    step = 1 if y2 >= y1 else -1
    for yy in range(y1, y2 + step, step):
        path1.append((x1, yy))
    x = x2
    step = 1 if x2 >= x1 else -1
    for xx in range(x1, x2 + step, step):
        path1.append((xx, y2))

    # L shape 2: (x1, y1) -> (x2, y1) -> (x2, y2)
    path2 = []
    step = 1 if x2 >= x1 else -1
    for xx in range(x1, x2 + step, step):
        path2.append((xx, y1))
    step = 1 if y2 >= y1 else -1
    for yy in range(y1, y2 + step, step):
        path2.append((x2, yy))

    return clear_path(path1) or clear_path(path2)

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        grid = []
        pos = []
        occ = set()

        for i in range(n):
            row = input().split()
            grid.append(row)
            for j, s in enumerate(row):
                if s != "-" * k:
                    pos.append((i, j))
                    occ.add((i, j))

        sz = len(pos)

        s = list(map(int, input().split()))

        # precompute weights
        w = [[0] * sz for _ in range(sz)]
        for i in range(sz):
            for j in range(sz):
                if i == j:
                    continue
                a = grid[pos[i][0]][pos[i][1]]
                b = grid[pos[j][0]][pos[j][1]]
                cnt = 0
                for t in range(k):
                    if a[t] == b[t]:
                        cnt += 1
                w[i][j] = s[cnt]

        # precompute connectivity
        occ_set = set(pos)
        can = [[False] * sz for _ in range(sz)]

        for i in range(sz):
            for j in range(sz):
                if i != j:
                    can[i][j] = can_link(i, j, pos, occ_set, n, m)

        from functools import lru_cache

        @lru_cache(None)
        def dp(mask):
            if mask == 0:
                return 0

            i = 0
            while not (mask & (1 << i)):
                i += 1

            best = 0
            rest_i = mask ^ (1 << i)

            j = i + 1
            while j < sz:
                if mask & (1 << j) and can[i][j]:
                    best = max(best, w[i][j] + dp(rest_i ^ (1 << j)))
                j += 1

            return best

        full = (1 << sz) - 1
        print(dp(full))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず空のセルを無視して、すべてのオブジェクトの位置を抽出します。 次に、属性文字列の直接文字比較を使用してペアごとのスコアを計算し、各一致カウントを提供されたスコア配列にマッピングします。 

接続チェックは最もデリケートな部分です。 各ペアについて、可能な 2 つの L 字型ルートを明示的に構築し、中間セルに別のオブジェクトが含まれていないことを確認します。 占有セットにより、ブロッキングが正しく処理されることが保証されます。これは正確性にとって重要です。 

DP はビットマスクを使用して、どのオブジェクトが残っているかを表します。 残りの最小のインデックスを選択すると、同等のペアの対称探索が防止され、再帰によりすべての有効な一致が 1 回だけ考慮されることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つのオブジェクトが一直線に並んでいるように見えても、別のオブジェクトが L パスの中央をブロックしている場合です。 その場合、単純な幾何学的チェックでは誤ってペアリングが許可されてしまいますが、パスが無効であるため、DP はペアリングを拒否する必要があります。 前処理では、中間セルの占有を明示的にチェックし、直線構成であっても、ブロッカーが存在する場合には隣接するオブジェクトのみが接続できるようにします。 

もう 1 つのケースは、複数のペアのスコアは同じだが、実現可能性が異なる場合です。 DP は接続性の推移性を想定していないため、グリッドに基づいて各ペアを独立して評価し、対称性の仮定による過大なカウントを防ぎます。
