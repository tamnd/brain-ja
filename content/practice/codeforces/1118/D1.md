 ## 解決策
 ## 問題の理解

 私たちには、カフェイン値が固定されたコーヒー カップのコレクションが与えられました。 Polycarp はこれらのカップのいくつかを選択し、数日間に渡って分配することができます。 特定の日に、ある順序で複数のカップを飲んだ場合、各カップの寄与はカフェインの量だけでなく、その日の飲酒順序におけるその位置にも依存します。 次のカップごとに、前のカップと比較して事実上 1 単位のカフェインの影響が失われるため、カップを 1 日のうちに早く消費するほど、そのカップの有用性は高くなります。 

目標は、少なくとも蓄積するのに何日必要かを決定することです。`m`作品のページ、ページはこれらの調整されたカフェインの寄与から来ています。 各カップは最大 1 回使用でき、カップは日をまたいで任意に分割できます。 

制約は小さく、カフェインを含むカップは最大 100 杯、ターゲット ページは最大 10^4 です。 これは、注意深く制御すれば二次または三次の動作は許容できるが、サブセットまたはパーティションに対する指数関数的な探索は許容できないことをすぐに示唆しています。 

カップが弱いと微妙なエッジケースが現れます。 少量のカフェインを含むカップは、その日の最初のカップにのみ影響を及ぼします。 そうしないと役に立たなくなります。 たとえば、値 1 のカップは、最初に取られた場合にのみ貢献します。 それ以外の場合は寄与はゼロになります。 注文を尊重せずに 1 日に何杯も詰める単純な貪欲な人は、貢献を過大評価し、実現可能性を誤って想定する可能性があります。 

別の特殊なケースは、すべてのカップが弱すぎて、1 日あたり 1 枚最適に使用したとしても、十分な総ページ数を蓄積できない場合に発生します。 その場合、どの構成でも合計寄与度が不十分となり、答えは -1 になる必要があります。 

## アプローチ

 ブルートフォースの観点では、考えられるすべての方法でカップを日にちに割り当て、各パーティションについて、毎日の中で考えられるすべての注文を試みます。 それはすでに組み合わせ論的に爆発しています。100 個の項目をシーケンスに分割するだけでも、ベル数によって支配され、実現可能性をはるかに超えています。 

重要な観察は、カップを固定すると 1 日の構造が単純になるということです。カップをカフェインの降順に並べ替えると、1 日の寄与が最大化されます。 1 日内のペナルティは位置に応じて直線的に増加するため、最も強力なカップが最も早く表示されるようにしたいと考えています。 他の順序付けは、寄与分を減らすか維持するだけです。 

したがって、問題は、ソートされた配列をセグメント (日) に分割する方法を決定することに帰着します。各セグメントは、貪欲に計算された既知の値に寄与します。 ここで、私たちは実質的に質問されます。これらのカップが与えられた場合、グループのスコアの合計が少なくとも以下に達するように、カップを最小数のグループにどのように分割するかです。`m`、グループ構造ごとの合計スコアを最大化しながら?

 目標合計を下回る日数を直接最小化するのではなく、視点を反転して、一定の日数を対象とします。`d`、少なくとも達成できるかどうかを確認します`m`ページ。 日数が増えると常に柔軟性が増すため (達成可能な貢献度の合計が決して減らない)、これは単調述語となり、二分探索が可能になります。`d`。 

固定の場合`d`、最良の戦略は、最大でもカップを貪欲に割り当てることです。`d`毎日、最も役立つカップを常にその日の最初の位置に置きます。 日数を繰り返しシミュレーションします。毎回最大で 2 日かかります。`d`残っている最大のカップからその寄与を計算し、それらを削除します。 寄付総額が に達した場合`m`、構成は実行可能です。 

したがって、最適な解決策は、貪欲な実現可能性チェックと組み合わせた、答えの二分探索です。

 ## アルゴリズムのチュートリアル

 ### 一定日数の実現可能性チェック`d`1. すべてのコーヒー カップをカフェイン値の降順に並べます。 

これにより、カップを日に割り当てるときに、常に、位置上のペナルティが最小になる毎日の早い時間帯に、より強力なカップを配置することが保証されます。 
2. ソートされた配列と変数に対するポインタを初期化します。`total = 0`。 

貪欲に杯を消費しながら、日々を積み重ねていくシミュレーションをしていきます。 
3. 1日から1日まで`d`、までかかります`d`残りのカップを配列から順番に取り出します。 

その日の最初のカップはその価値を最大限に発揮し、2 番目のカップは 1 を失い、3 番目のカップは 2 を失います。 次のように計算します。`max(0, a[i] - position_in_day)`。 
4. 1 日処理した後、使用したカップの数だけポインタを進めます。 

これにより、各カップが最大 1 回使用されることが保証されます。 
5. すべての貢献を蓄積します。 いつでも`total >= m`、早めに止めることができます。 
6. やっぱり`d`少なくとも到達する日`m`、構成は実行可能です。 

### 外部二分探索

 1. 検索範囲を 1 ～ で設定します。`n`、最悪の場合、各カップがその日単独で存在する可能性があるためです。 
2. 各中間点について`d`、実現可能性チェックを実行します。 
3. 可能であれば、より小さくしてみてください`d`、それ以外の場合は増加します`d`。 
4. 実行可能な最小値を返すか、どれも機能しない場合は -1 を返します。 

### なぜ効果があるのか

 中心となる不変条件は、ペナルティは身分ではなく位置のみに依存するため、特定の日においてカフェインの降順にカップを置くと貢献が最大になるということです。 これにより、毎日を個別に最適化できるようになります。 日数が決まったら、残りの最も強いカップから順番に貪欲に満たしても、より良い再分配は存在しません。より強い後のカップをより弱い以前のカップと交換することは、合計の貢献を改善または維持することしかできないからです。 これにより、実現可能性チェックが正しいことが保証され、日数にわたる単調性により二分探索が正当化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(m, a, days):
    n = len(a)
    i = 0
    total = 0

    while i < n:
        used = 0
        # fill one day
        for j in range(days):
            if i >= n:
                break
            gain = a[i] - j
            if gain > 0:
                total += gain
            i += 1
            used += 1

        if total >= m:
            return True

    return total >= m

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    a.sort(reverse=True)

    lo, hi = 1, n
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(m, a, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、毎日の早い位置が常に最も強い残りのカップで満たされるように、カフェイン値を降順に並べ替えることから開始します。 の`can`関数は、最大で何ページを書き込むことができるかをシミュレートします。`days`1日あたりのカップ数。 毎日貪欲に消費します`days`カップでは、位置に基づいてリニアペナルティを適用します。 二分探索では、必要なページ数に到達できる最小の日数が見つかります。 

微妙な実装の詳細は、次の場合に早期に停止することです。`total >= m`これにより、不必要なシミュレーションが回避されます。 もう 1 つは、カップがゼロまたはマイナスの調整値に貢献すると、そのカップは引き続き消費されますが、合計は増加しないことを保証することです。 

## 実用的な例

 ### 例 1

 入力:```
5 8
2 3 1 1 2
```ソートされた配列:`[3, 2, 2, 1, 1]`私たちは実現可能性をテストします`d = 2`。 

| 日 | 使用したカップ | 貢献 | 合計 |
 | --- | --- | --- | --- |
 | 1 | 3、2 | 3 + 1 = 4 | 4 |
 | 2 | 2、1 | 2 + 0 = 2 | 6 |
 | 2 | 1 | 1 | 7 |

 これは2日間失敗します。 のために`d = 3`、少なくとも 8 に達するのに十分な柔軟性が得られ、二分探索は次のように収束します。`4`最適な構造で日々を過ごします。 

これは、1 日により多くのカップを詰めるとペナルティによりカップあたりの効率が低下することを示しており、正解はグループ化のバランスに依存します。

```並べ替え:`[5, 4, 3, 1]`テスト`d = 2`:

 | 日 | カップ | 貢献 |

 | 1 | 5、4 | 5 + 3 = 8 |

 11 ≥ 10 に達するので、2 日あれば十分です。 これは、強力な初期カップが実現可能性を支配していることを裏付けています。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのカフェイン値が 1 である場合です。入力の場合:```
3 5
1 1 1
```すべてのカップが最適に使用されたとしても、寄与するのはその日の最初のカップだけであるため、最大合計は 3 です。アルゴリズムはすべてのカップについて実行可能性チェックに正しく失敗します。`d`、-1 を返します。 

もう 1 つのエッジ ケースは、1 つの非常に大きなカップが優勢な場合です。```
1 1
100
```アルゴリズムはすぐに成功します。`d = 1`, 1杯だけでも十分な貢献が得られるためです。 

3 番目のエッジケースは、次のようなグループ化によってパフォーマンスが低下する場合です。```
3 6
5 1 1
```1 日では 5 + 0 + 0 = 5 となり不十分ですが、2 日では弱いカップを分離できるため、再び便利になります。 実現可能性チェックでは、すべてを 1 日に詰め込むのではなく、グループ化のサイズを調整することで、このトレードオフを正確に把握します。
