 ## 解決策
 ## 問題の理解

 各インデックスがキャンディーを表す重みの配列が与えられます。 Tanya はキャンディーを 1 つだけ取り除き、残りのキャンディーを厳密にインデックス順に、1 日目から 1 日あたり 1 つずつ消費します。工夫としては、取り除いた後、食べたキャンディーを日数に基づいて奇数日と偶数日に分割し、奇数日に食べた重量の合計と偶数日の合計を比較します。 

タスクは、これら 2 つの合計が等しくなる、削除されたインデックスの選択肢がいくつあるかを数えることです。 

重要な点は、Tanya が常に残りのキャンディーをインデックスの昇順で食べるため、キャンディーを削除すると消費順序が変わることです。 したがって、要素を削除すると、その要素が削除されるだけでなく、奇数日に配置される要素と偶数日に配置される要素も変更されます。 

最大 200,000 個の要素という制約は、インデックスごとに削除をシミュレートし、パリティ合計を最初から再計算するソリューションでは遅すぎることを意味します。 削除するたびに配列やスキャンを再構築する単純な O(n^2) アプローチでは、最悪の場合で 400 億回の操作が必要となるため、大規模すぎます。 

n が小さい場合、特に n = 1 または n = 2 の場合、微妙なエッジケースが発生します。 n = 1 の場合、唯一のキャンディーを削除した後、食べたキャンディーはなく、両方の合計がゼロになるため、答えは 1 になります。 n = 2 の場合、どちらかの要素を削除するとキャンディーが 1 つ残り、常に 1 日目 (奇数) になるため、合計は 0 になります。 残りの構造がパリティのバランスをとる場合のみ機能し、多くの単純な実装では、パリティのシフトが削除されたインデックスに対する相対的な位置に依存することを忘れています。 

## アプローチ

 ブルートフォースソリューションでは、各インデックスを削除されたキャンディーとして試します。 選択ごとに、残りのシーケンスを再構築し、奇数日と偶数日の合計を累積して日々の消費量をシミュレートします。 これはプロセス定義に直接従うため正しいですが、そのコストがボトルネックになります。 

各シミュレーションのコストは O(n) で、それを n 回繰り返すと、時間は O(n^2) になります。 n が 2 × 10^5 までの場合、これは実行不可能です。 

重要な観察は、要素を削除すると位置のパリティが反転することです。 固定削除インデックス i の場合、i より前のすべての要素は相対的な順序とパリティの配置を維持します。 i 以降のすべての要素は 1 位置分左にシフトし、日のパリティが反転します。 これは、プレフィックスとサフィックスからの寄与を事前計算し、インデックスごとに O(1) で結合できることを意味します。 

元の配列の偶数位置と奇数位置の寄与について個別にプレフィックスの合計を事前計算します。 次に、各除去インデックスについて次のように計算します。 

i より前の要素のパリティは同じままです。 

i 以降の要素ではパリティが反転するため、元の奇数が偶数になり、その逆も同様です。 

これにより、インデックスごとに両方の合計を一定時間で計算できます。

 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのプレフィックス配列を事前計算します。1 つは奇数のインデックスの値の累積和を格納し、もう 1 つは偶数のインデックスを格納します。 これにより、元のパリティで分割された高速範囲合計クエリが可能になります。 
2. 配列全体の奇数インデックスと偶数インデックスの値の合計を計算します。 これらは、削除前のベースライン寄与を表します。 
3. 各候補インデックス i について、配列をプレフィックス [1..i-1] とサフィックス [i+1..n] に分割することとして削除を解釈します。 
4. プレフィックスの場合、相対的な順序が変化しないため、寄与は変化しません。 
5. サフィックスの場合、削除後にすべてのインデックスが 1 つ左にシフトするため、パリティが反転します。 したがって、元の偶数ポジションは奇数日の寄与になり、元の奇数ポジションは偶数日の寄与になります。 
6. プレフィックスと変換されたサフィックスの合計を結合して、最終的な奇数日と偶数日の合計を計算します。 
7. 2 つの合計が等しい場合、このインデックスは有効なものとしてカウントされます。 

### なぜ効果があるのか

正確性は、削除時の安定したパリティ変換に依存します。 単一の要素を削除しても、残りの要素の順序は変更されません。削除された位置の後のインデックスが 1 つだけシフトされるだけです。 これにより、サフィックスの決定論的なパリティ 反転が引き起こされ、プレフィックスのパリティが維持されます。 すべての要素の寄与は、その最終位置が奇数か偶数かによってのみ決まり、このパリティ変換は削除されたインデックスとの関係によって完全に決定されるため、再計算せずにプレフィックス/サフィックス集約を使用してすべての結果を計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # 1-indexed thinking: use 0-indexed but treat parity carefully
    # prefix odd/even sums based on original index parity
    pref_odd = [0] * (n + 1)
    pref_even = [0] * (n + 1)

    for i in range(n):
        pref_odd[i + 1] = pref_odd[i]
        pref_even[i + 1] = pref_even[i]
        if i % 2 == 0:
            pref_odd[i + 1] += a[i]
        else:
            pref_even[i + 1] += a[i]

    total_odd = pref_odd[n]
    total_even = pref_even[n]

    ans = 0

    for i in range(n):
        left_odd = pref_odd[i]
        left_even = pref_even[i]

        right_odd = total_odd - pref_odd[i + 1]
        right_even = total_even - pref_even[i + 1]

        # after removal, suffix parity flips
        odd_sum = left_odd + right_even
        even_sum = left_even + right_odd

        if odd_sum == even_sum:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、インデックス パリティによって分割されたプレフィックス合計が構築されるため、セグメントを迅速に分離できます。 削除位置 i ごとに、配列を左部分と右部分に分割します。 左側の部分は元のパリティ アライメントを維持します。 右側の部分は、削除後にインデックスがシフトするため、奇数と偶数の寄与を交換することによって調整されます。 これは、アレイの再構築を回避する中心的な変換です。 

よくある落とし穴は、パリティが元のインデックスではなく、削除後の日数によって定義されることを忘れていることです。 もう 1 つの間違いは、プレフィックス スライスにおける off-by-one エラーです。特に、削除された要素自体が両方の合計から確実に除外されることです。

    from collections import deque

 ## 特殊なケース

 n = 1 の場合、唯一の要素を削除すると食べたキャンディーが残らないため、奇数と偶数の合計は両方ともゼロになります。 プレフィックスとサフィックスの合計がゼロであり、等価条件が常に成り立つため、アルゴリズムはこれを正しく処理します。 

インデックス 0 または n − 1 での削除の場合、プレフィックスまたはサフィックスのいずれかが空になります。 特別な処理を行わなくても、プレフィックスとサフィックスの合計はデフォルトで 0 になるため、この実装は引き続き機能します。 

すべての値が同一である配列の場合、対称性により、多くの削除によってバランスが保たれます。 接頭辞と接尾辞の分解は、値の同一性ではなく純粋にカウントとパリティ反転に基づいて動作するため、これを依然として正確に捕捉します。
