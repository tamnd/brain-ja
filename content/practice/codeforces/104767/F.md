 ## 解決策
 ## 問題の理解

 最大 100,000 台のロボットのマルチセットが与えられ、各ロボットには 1 ～ 20 の高さでラベルが付けられています。このマルチセットから、すべてのロボットの単一の線形順序付けを構築する必要があります。また、キャプテンと呼ばれるこの順序の最初の要素となる 1 台のロボットも選択します。 

列が形成されると、キャプテンを除くすべてのロボットは、その直前のロボットを見て、その前任者の身長と自分の身長の gcd を提供します。 キャプテンはこれらすべての貢献を受け取り、その合計がアレンジメントのスコアとなります。 すべてのロボットを自由に並べ替えて開始点を選択できます。タスクは、結果の合計を最大化することです。 

構造上の重要な点は、最終的な順序付けでは隣接するペアのみが重要であるということです。 すべての配置は、マルチセットの順列を選択し、連続するペアの gcd を合計することと同じです。 

この制約は、ロボットを別個の長いシーケンスとして扱うことができないことを直ちに示唆しています。 N は 100000 に達する可能性があるため、N 階乗順列や N 上の二次 DP に依存するアプローチは不可能です。 唯一の強力な構造上のヒントは、値が 1 ～ 20 の範囲に制限されていることです。これは、多重度が大きくても、個別の「タイプ」の有効な数が少ないことを意味します。 

単純な実装は、いくつかの微妙な点で失敗します。 一例として、高さの降順による並べ替えが常に最適であると仮定します。 たとえば、値の場合`[2, 3, 4]`、降順で並べ替えると、`4, 3, 2`、gcd 合計を生成します`gcd(4,3)+gcd(3,2)=1+1=2`。 ただし、注文すると、`3, 2, 4`収量`gcd(3,2)+gcd(2,4)=1+2=3`どちらの方が優れているため、純粋に単調な順序付けは失敗します。 

もう 1 つの障害モードは、各値を独立して処理し、最良のローカル近傍を貪欲に接続することです。 値を中央に配置すると、その左と右の両方の寄与に影響するため、ローカルの決定を独立して修正することはできません。 

3 番目の微妙な問題は、すべての値が同じ場合に発生します。 どの順序付けも構造的には同等ですが、遷移を過剰に最適化する単純なアルゴリズムは、対称性の仮定を誤って破り、最適な内部寄与を失う可能性があります。`(cnt - 1) * v`。 

## アプローチ

 最初の観点は、各ロボットが頂点であり、2 台のロボット間のエッジの重みが`gcd(a[i], a[j])`。 すべての頂点を 1 回だけ訪問し、連続するエッジの重みの合計を最大化するパスが必要です。 キャプテンは単にこの道の出発点にすぎません。 

ブルート フォース ソリューションでは、N 個の要素のすべての順列を試し、それぞれのパスの重みを計算し、最大値を取得します。 これは探索します`N!`実現可能な限界をはるかに超えた取り決め。 

重要な単純化は、エッジがアイデンティティではなく値のみに依存することに気づくことから生まれます。 同じ高さのロボットはすべて互換性があります。 したがって、状態を 1 から 20 までの各値のカウントに圧縮できます。同一の値のブロック内での最適な配置は自明です。同一の値を連続して配置すると、常に寄与が得られます。`value`各内部エッジに対して、各値クラスが寄与する`(cnt[v] - 1) * v`グローバルな順序に関係なく。 

残っているのは、個別の値グループが表示される順序を決定することです。 各グループはノード (最大 20 ノード) であり、次の合計を最大化する順列を選択する必要があります。`gcd(value[i], value[j])`連続するグループに沿って。 これは最大 20 ノードにわたる最長パスの問題であり、ビットマスク動的プログラミングで解決できます。 

解決策を、固定グループ内寄与と 20 ノードにわたるグループ間順序付け問題に分けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | お(ん!) | O(N) | 遅すぎる |
 | 値圧縮 + ビットマスク DP | O(2^20 · 20^2) | O(2^20・20) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各値の頻度を 1 から 20 までカウントします。これにより、入力が最大 20 個の重み付きノードに減ります。これは、すべての同一の値がそのカウントを除いて対称的に動作するためです。 
2. 各値グループの内部寄与を次のように計算します。`(cnt[v] - 1) * v`。 これは、同じ値がブロック内に連続して配置されたときに形成されるエッジを表します。 
3. 20 × 20 の行列を構築する`w[i][j] = gcd(i, j)`、値を配置することによるゲインを表します`i`値の隣`j`。 
4. 各値を扱います`v`と`cnt[v] > 0`グラフ内のノードとして。 タスクは、重みを使用してこれらのノード上の最大重みハミルトニアン パスを見つけることになります。`w`。 
5. サブセットに対して動的プログラミングを使用します。 定義する`dp[mask][i]`の値のセットを正確に訪問することによって得られる最大スコアとして`mask`そして値で終わる`i`。 
6.初期化`dp[1 << i][i] = 0`マルチセットに存在するすべての値に対して。 これは、選択した任意のキャプテン値でパスを開始することに対応します。 
7. 新しい値を追加して遷移する`j`現在のマスクにはありません。 アップデート`dp[mask | (1 << j)][j]`考慮することで`dp[mask][i] + w[i][j]`。 
8. すべての状態を満たした後、すべての終了状態の最大値を取得します。`dp[full_mask][i]`、次にステップ 2 の内部寄与を追加します。 

### なぜ効果があるのか

 有効な配置はすべて、ブロックに圧縮されるときに個別の値の順序が 1 つだけ誘導され、各ブロック内ではブロック間の寄与を変更することなくすべての同一の値を再配置できます。 DP は、考えられるすべてのブロックの順序を反復せずに列挙し、各遷移は gcd を介した隣接するブロック間の相互作用のみを正確に考慮します。 すべての有効な置換は 1 つの DP パスに正確に対応し、その逆も同様であり、内部ブロックの寄与は順序とは無関係であるため、最大 DP 値と内部合計により最適な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    cnt = [0] * 21
    for x in a:
        cnt[x] += 1

    values = [v for v in range(1, 21) if cnt[v] > 0]
    k = len(values)

    # map value -> index
    idx = {v: i for i, v in enumerate(values)}

    # internal contribution
    ans = 0
    for v in values:
        ans += (cnt[v] - 1) * v

    # gcd table
    w = [[0] * k for _ in range(k)]
    for i in range(k):
        for j in range(k):
            import math
            w[i][j] = math.gcd(values[i], values[j])

    # dp[mask][i]
    size = 1 << k
    dp = [[-1] * k for _ in range(size)]

    for i in range(k):
        dp[1 << i][i] = 0

    for mask in range(size):
        for i in range(k):
            if dp[mask][i] < 0:
                continue
            for j in range(k):
                if mask & (1 << j):
                    continue
                nm = mask | (1 << j)
                val = dp[mask][i] + w[i][j]
                if val > dp[nm][j]:
                    dp[nm][j] = val

    best = 0
    full = size - 1
    for i in range(k):
        best = max(best, dp[full][i])

    print(ans + best)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずマルチセットを周波数バケットに圧縮し、N への依存を取り除きます。その後、動的プログラミングは純粋に個別の値のセットに対して機能します。 重要な微妙な点は、DP はグループ間のエッジのみを考慮し、グループ内のすべての寄与は個別に処理されることです。 

すべてのシングルトン マスクが開始点として有効であるため、DP 状態の初期化では、任意の値をキャプテンとして機能させることができます。 遷移構造により、各値がグループの順序付けで 1 回だけ使用されることが保証されます。 

## 実用的な例

 サンプル入力を考えてみましょう。 

入力：```
7
2 3 12 4 6 4 3
```カウントを圧縮します。 

- 2:1、3:2、4:2、6:1、12:1

 内部貢献は次のとおりです。 

- 3 件の貢献`(2-1)*3 = 3`- 4 件の貢献`(2-1)*4 = 4`内部合計 = 7

 ここで、値 {2,3,4,6,12} の順序を選択します。 DP はすべての順列を調査し、最適な順序の 1 つは次のとおりです。`3 → 6 → 12 → 4 → 2`| ステップ | 選ばれた | エッジが追加されました | 累計額 |
 | --- | --- | --- | --- |
 | 1 | 3 | - | 0 |
 | 2 | 6 | gcd(3,6)=3 | 3 |
 | 3 | 12 | gcd(6,12)=6 | 9 |
 | 4 | 4 | gcd(12,4)=4 | 13 |
 | 5 | 2 | gcd(4,2)=2 | 15 |

 グループ間の最高スコアは 15 で、内部 7 を加えると 22 になります。 

これは、同一の値を個別にグループ化し、個別の値のみを最適化することで完全な構造を取得する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^K · K^2) ここで、K ≤ 20 | ペア間の遷移を伴う個別の値のサブセットに対する DP |
 | スペース | O(2^K・K) | 各サブセット終了状態の最適値を格納する DP テーブル |

 K が最大 20 の場合、DP サイズは約 100 万の状態とおよそ数千万の遷移になります。これは、gcd 計算と単純な整数演算の小さい定数係数を考慮すると、制限内に問題なく収まります。

        for x in a:
            cnt[x] += 1

 ## 特殊なケース

 次のような均一な配列`5 5 5 5`ブロック内ロジックを分離します。 アルゴリズムが生成するのは、`(4 * 5) = 20`すべての隣接するペアが gcd(5,5)=5 に寄与し、圧縮グラフにはノードが 1 つしかないため、DP 遷移は必要ありません。 

次のような厳密に減少するシーケンス`20 10 5 1`DP が単純な並べ替えの仮定を正しく回避するかどうかをテストします。 最適な配置は、大きさによる隣接関係ではなく gcd 相互作用を最大化することに依存し、DP は値ノードのすべての順列を探索し、貪欲な順序付けではなく最適なシーケンスが選択されるようにします。 

次のような小さな混合ケース`2 3 4`ローカルの貪欲さがなぜ失敗するのかを浮き彫りにします。 DP は 3 つの可能な順序をすべて評価し、それを捕捉します。`3 → 2 → 4`ソート順よりも優れています。これは、最後に強い遷移が得られるためです。
