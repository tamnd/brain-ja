 ## 解決策
 ## 問題の理解

 各生徒は学校に対して 2 つのランク付けされた好みを持って到着します。 学生はすでにグローバルな品質順に並べ替えられているため、常に高得点の学生を最初に処理します。 どの学校も、最大でも以下の限られたリストを維持しています。`C`学生を対象に、世界ランキングからより優れた候補者を引き抜き、リストを改善しようと繰り返し試みています。 

このプロセスは、単純な 1 パスの割り当てではありません。 代わりに、学校は更新イベントを周期的に繰り返し実行します。 更新中、学校はグローバルな順序で最も悪い生徒から上に向かってスキャンし、いくつかの制約の下でまだ資格があり、学校の現在のリストを改善する生徒を見つけようとします。生徒はこの学校を好む必要があり、すでに他の場所にしっかりと割り当てられていてはならず、現在割り当てられていない、または第二希望の学校に割り当てられている必要があります。 学校に空きがある場合、または生徒が現在の最悪の状況よりも優れている場合、その生徒は入学でき、誰かが置き換えられる可能性があります。 

これにより、学校間の競争の動的なシステムが作成され、生徒を複数回移動させることができますが、それは各学校のリストの単調な改善を保証する構造化されたルールの下でのみ可能です。 

出力では、最終的に第 1 希望の学校と第 2 希望の学校に合格した生徒の数のみがカウントされます。 

学生数と学校数の制限はそれぞれ最大 100,000 人までと大きいですが、`C`は非常に小さく、最大でも 100 です。この非対称性が重要な構造上のヒントです。 学校運営のたびに完全な生徒リストを繰り返しスキャンしようとするソリューションでは、サイクルの単純なシミュレーションが何倍にも増えるため、時間がかかりすぎます。`N`による`M`。 

単純なアプローチでは、度重なる移転にも苦労するでしょう。 学生は第 2 希望から第 1 希望に移る可能性があり、最初に配置された後に課題が最終的なものであるという誤った仮定が誤った答えにつながります。 たとえば、学生が早い段階で第 2 希望に選ばれたものの、後に第 1 希望に合格する資格が得られた場合、以前の決定を再検討しない単純な貪欲な課題では、結果が誤ってカウントされます。 

学校が満員で、世界秩序の後半にわずかに優れた候補者しか存在しない場合、別の微妙な特殊なケースが発生します。 毎回最初から再起動する単純なスキャンでは、意図した「最悪から上へ」の動作が失われ、間違った候補が選択され、置換ルールに違反する可能性があります。 

## アプローチ

 ブルート フォース シミュレーションでは、文字通り、説明されたプロセスが実行されます。 各学校は、成績の悪い生徒から順にグローバル リストを繰り返しスキャンし、資格条件を確認し、入れ替えを実行します。 各更新イベントは、最大で次の範囲まで移動する可能性があります。`N`学生もいるし、`M`学校、複数のサイクルにわたって繰り返されます。 挿入/削除のたびに学校全体で段階的な変更が引き起こされる可能性があるため、チェックの総数は爆発的に増加する可能性があります。`O(N * M * C)`あるいはさらに悪いことに。 と`N`そして`M`100,000 では、これはまったく不可能です。 

重要な洞察は、システムが強力な単調な構造を持っているということです。各学校は常に最高の状態を維持するだけです。`C`一貫した世界的な順序に従って有効な候補者を絞り込み、より優れた学校に拒否された生徒は、第 2 希望に「下がる」だけです。 なぜなら`C`規模は小さく、各学校の州は小規模で安定した規模であり、すべての更新はローカル交換との限定された優先順位構造を維持するかのように効果的に動作します。 

グローバル スキャンをシミュレートする代わりに、視点を逆転させます。 各学生には最大で 2 つの目的地が考えられます。 スコアの降順に貪欲に学生を割り当てようとしますが、置換の連鎖を許可する必要があります。 これは、各学校が最大でも小さい順序セットのサイズを維持する、マルチソースの制約付きマッチングになります。`C`。 新しい候補が到着すると、有効であれば挿入し、必要に応じて最悪の候補を削除できます。 立ち退かせられた場合、彼らは 2 番目の希望を 1 回だけ試します。 これにより、プロセスが制御された伝播システムに変わり、各生徒が最大 2 回移動し、各学校の運営が行われます。`O(C)`。 

なぜなら`C ≤ 100`、各学校構造内でリニアスキャンを行う余裕があります。 全体の複雑さは次のように線形になります。`N * C`、これは許容範囲です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N² · M) 最悪の場合 | O(N + M) | 遅すぎる |
 | 有界セットを使用した最適化されたローカル シミュレーション | O(N・C) | O(N+M・C) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは各学校ごとに最大でも次のリストを維持しています。`C`現在割り当てられている生徒は、常にスコア順 (または、入力順序がすでにスコア順をエンコードしているため、インデックス順) で並べ替えられます。 また、生徒が現在どの学校に割り当てられているかどうかも追跡します。 

1. 入力によってすでにこの順序が与えられているため、生徒をスコアの降順に処理します。 これにより、学生が検討されるたびに、より優れたすべての学生がすでに処理され、最適に配置されることが保証されます。 
2. 各生徒は、まず第一志望校への配属を試みます。 学校の定員が以下の場合`C`生徒、すぐに挿入してください。 満員の場合は、現在その学校にいる最も悪い生徒と比較します。 新入生の方が優れている場合は、最悪の生徒を置き換えます。 
3. 補充が発生すると、退学させられた生徒は割り当てが解除され、すぐに第 2 希望の学校に再検討されます。 これは、非優先課題から追放された学生が、依然として他の選択肢に移動できるというルールをモデル化しています。 
4. 生徒が第一希望の学校に入学できない場合は、第二希望の学校についても同じ手順を試みます。ただし、その生徒が現在割り当てられていない、または第二希望の学校から入学したという規則に基づいて資格がある場合に限ります。 
5. 各学校は常に最大で次の値を維持します。`C`学生であるため、挿入または削除はすべて制限された作業となります。 各生徒は最大 2 回挿入できるため、操作の合計数は線形のままです。`N`。 

中心的な考え方は、より優れた学生が常に優先され、どの学校もそれ以上の決定を下すことは決してないため、あらゆる地域の決定が世界的な実現可能性を維持するというものです。`C`候補者たち。 

### なぜ効果があるのか

 不変条件は、どの時点においても、各学校のリストには最大でも可能な限り最良の規模のサブセットが含まれていることです。`C`現在、避難規則に基づいてその学校に入学する資格のあるすべての生徒の中に含まれます。 学生はスコアの降順で処理されるため、後の学生が以前の学生よりも全体的に優れていることはありません。そのため、新しい学生を挿入しても、現在の最悪の要素を置き換えることによってのみ学校のリストを改善できます。 移動は常に学生を厳密に悪い、または二番目の位置に送るため、配置転換のサイクルが無制限に増加することはありません。 これにより、最終的な配置の終了と正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c = map(int, input().split())
    a = [None] * n

    for i in range(n):
        a[i] = tuple(map(int, input().split()))

    # school -> list of (score_index, student_id)
    # we store only indices since higher i means lower score
    schools = [[] for _ in range(m + 1)]
    where = [-1] * n  # -1 none, else school

    first_ok = 0
    second_ok = 0

    def try_insert(student, school):
        nonlocal first_ok, second_ok

        lst = schools[school]

        # check if already there
        if where[student] == school:
            return None

        # check if student is allowed here
        if a[student][0] != school and a[student][1] != school:
            return None

        # capacity not full
        if len(lst) < c:
            lst.append(student)
            where[student] = school
            return None

        # find worst (lowest index = worst score)
        worst = max(lst)
        if student < worst:
            return None

        # replace worst
        lst.remove(worst)
        lst.append(student)
        where[student] = school
        return worst

    for i in range(n):
        s1, s2 = a[i]

        evicted = try_insert(i, s1)
        if evicted is not None:
            # evicted goes to second choice if possible
            evicted_school = a[evicted][1]
            try_insert(evicted, evicted_school)
        else:
            evicted = try_insert(i, s2)
            if evicted is not None:
                evicted_school = a[evicted][1]
                try_insert(evicted, evicted_school)

    # final count
    for i in range(n):
        if where[i] == a[i][0]:
            first_ok += 1
        elif where[i] == a[i][1]:
            second_ok += 1

    print(first_ok, second_ok)

if __name__ == "__main__":
    solve()
```このソリューションは、各学校の受験者リストを明示的に保持し、定員を確保します。`C`。 の`try_insert`関数はコア ルールをカプセル化します。挿入は、学生に資格があり、空きがある場合、または現在の最悪の候補者よりも優れている場合にのみ可能です。 補欠が発生した場合、退学させられた学生は返還され、二次配置を試みることができます。 

セカンドチャンスの挿入のロジックは、退去直後に処理されます。これは、避難した生徒が参加し続けるという SAP ルールを反映しています。 

最後の集計フェーズでは、各生徒の最終課題と希望を単純に比較します。

 ## 特殊なケース

 エッジ ケースの 1 つは、定員が 1 の場合です。新しい有効な学生はすぐに前の学生と置き換えられ、第 2 希望への退学という長い連鎖が強制されます。 すべてのエビクションが即座に再ルーティングされるため、アルゴリズムはこれを正しく処理し、候補者の損失を防ぎます。 

もう 1 つの特殊なケースは、多くの生徒にとって両方の学校が同一である場合に発生します。 その場合、1校が第2志望オーバーフローの受け皿となる。 各学校が独自に最高の成績を維持しているため、不変条件は依然として維持されています。`C`立ち退き移転以外の干渉を受けることなく候補者を支援します。 

最後のエッジケースは、生徒の第 2 希望の学校が、より優秀な生徒ですでに満員である場合です。 この状況では、立ち退きチェーンは単に停止し、学生は割り当てられていないままになります。これは、学生に対する有効な更新イベントがもう存在しないため、ルールと一致します。
