 ## 解決策
 ## 問題の理解

 私たちは何日にもわたる長い一連のマシンを与えられており、毎日、マシンに一定の「分割力」を提供します。 連続した日の間隔で切断プロセスを実行すると決めた場合、これらの機械を順番に繰り返し適用し、毎日、現在のすべての隕石の破片を取り出し、その日の機械に従って同じ数の小さな破片に分割することができます。 

重要な制限は、毎日の終了後、既存のすべてのピースが同じ重さでなければならないことです。 これにより、プロセスは均一な改良を繰り返すように動作することになります。つまり、すべての個数には常にその日の機械の値が乗算され、すべての個の重量は常に同一のままになります。 

クエリにより、日数のセグメントと研究室の数が得られます。 問題は、最初の隕石を選択し、その間隔でマシンを毎日実行して、最終的にはすべての破片を使用し、グループ間で破片を分割することなく、結果として得られた破片を合計重量が等しい正確に k 個のグループに分配できるかどうかです。 

これにより、問題は、期間中に生産されたピースの総数が k 個の等しい重量のグループに配置できるかどうかを確認することになり、これは最終的なピース数が k で割り切れるかどうかを確認することと同じになります。 

入力サイズは 100,000 日および 100,000 クエリに達するため、クエリごとに完全な積を再計算するソリューションは直ちに実行不可能になります。 値が 10^6 に達し、積が急速に増大するため、クエリごとに単一の乗算チェーンであっても、最悪の場合には遅すぎます。 

単純なクエリごとの再計算では O(間隔の長さ) の乗算が必要となり、最悪の場合は O(NQ) となり、制限をはるかに超えます。 

間隔が重なり合う場合や値が大きい場合には、微妙な問題が発生します。単純な乗算は標準の整数型をオーバーフローしたり、Python の大きな整数を使用しても遅くなりすぎたりします。 

主なエッジ ケースは、k が大きいが、完全な間隔ではなくプレフィックスごとに誤ってチェックされた場合、部分積が割り切れることを示唆しているにもかかわらず、マシンの積が k で割り切れない場合です。 

## アプローチ

 重要な観察は、各マシンがピースの数に固定の整数を乗算しているということです。 1 つの部分から開始し、セグメントを処理した後の最終的な部分の数は、単純にそのセグメント内のすべての a_i の積になります。 

したがって、各クエリは次のことを尋ねます。 

product(a_s ... a_t) は k で割り切れます。 

素因数分解の用語で書き直すと、より有用な構造が得られます。 積の素指数は、各 a_i の指数の合計です。 したがって、積を直接計算する代わりに、素因数の数を追跡できます。 

各数値 a_i を素因数分解します。 各素数 p について、それが各位置に何回出現するかを記録します。 次に、各クエリはこれらの指数配列に対する範囲合計クエリになります。 

ブルート フォース ソリューションは、完全な積を再計算するか、クエリごとに繰り返し因数分解します。 これは正しいですが、クエリごとに因数分解と乗算を行うと、最悪の場合 O(N * Q) の動作が発生するため、遅すぎます。 

重要な洞察は、乗算を素数指数上の加法構造に分離し、高速範囲クエリをサポートすることです。 これにより、問題は、まばらな素因数の寄与に対する範囲合計クエリに答えることになります。 素数ごとにプレフィックス合計を事前計算するか、オフライン蓄積をサポートするデータ構造を使用します。 

値は最大 10^6 であるため、各数値には最大でも少数の素因数が含まれ、合計因数イベントが管理可能になります。 

各素数指数の接頭辞の合計が得られたら、接頭辞の値を減算し、k 内のすべての素数が区間積でカバーされているかどうかを確認することで、各クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 この問題は、乗法累積を素因数にわたる加法追跡に変換することで解決します。 

1. すべての a[i] を素因数分解し、指数の寄与を記録します。 

各数値は少数の素数のみを提供するため、このステップは効率的です。 私たちは投稿をスパースな更新として保存します。 
2. 各素数指数の範囲合計クエリを可能にする構造を構築します。 

すべての素数の完全な密配列を保存する代わりに、出現する素数のみを保存し、素数が発生する位置にプレフィックスの合計を構築します。 
3. クエリごとに、k を素数と指数に因数分解します。 

これにより、間隔の積に何が存在する必要があるかが正確にわかります。 
4. k の各素数 p^e について、接頭辞の合計を使用して区間積に p が現れる回数を計算します。 

t と s-1 でのプレフィックス数を減算して、そのセグメントの合計指数を取得します。 
5. 必要な素指数がすべて満たされている場合は、「はい」と答えます。 それ以外の場合はいいえ。 

k の素数が欠落しているか不十分な場合、その積は k で割り切れません。 

### なぜ効果があるのか

 正しさは、整数の乗算が素数指数に一意に分解されるという事実に基づいており、割り切れるということは、k のすべての素数に対して十分な指数寄与があることと同等です。 各マシンは現在のすべての部分を均一に乗算するため、区間の全体的な効果は正確にその要素の積となり、素数に対する指数加算が状態を完全に特徴づけます。 範囲合計では正確な指数カウントが保持されるため、割り算チェックは正確かつ損失がありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

# smallest prime factor sieve
spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = {}
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        res[p] = cnt
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # store prime exponent prefix sums sparsely
    from collections import defaultdict

    pos = defaultdict(list)
    cnt = defaultdict(list)

    # initialize structures
    for i, val in enumerate(a, 1):
        f = factorize(val)
        for p, e in f.items():
            pos[p].append(i)
            cnt[p].append(e)

    pref = {}
    for p in pos:
        arr = cnt[p]
        ps = [0]
        for v in arr:
            ps.append(ps[-1] + v)
        pref[p] = (pos[p], ps)

    q = int(input())
    out = []

    for _ in range(q):
        s, t, k = map(int, input().split())
        fk = factorize(k)

        ok = True
        for p, need in fk.items():
            if p not in pref:
                ok = False
                break
            idx_list, ps = pref[p]

            # find how many occurrences lie in [s, t]
            # binary search manually
            import bisect
            l = bisect.bisect_left(idx_list, s)
            r = bisect.bisect_right(idx_list, t)

            if ps[r] - ps[l] < need:
                ok = False
                break

        out.append("Yes" if ok else "No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、10^6 までのすべての数値を迅速に因数分解できるように、最小の素因数ふるいを構築することから始まります。 これが必要なのは、単純に行うと因数分解がボトルネックになるためです。 

各配列値は素数に分解され、素数ごとに完全な密な指数配列を格納する代わりに、素数がその指数とともに出現する位置のみを格納します。 これにより、メモリが素数の出現の総数に比例した状態に保たれます。 

各素数について、その指数リストに基づいて接頭辞の合計を構築します。 これにより、二分探索境界を使用して、クエリ間隔内でその素数がどの程度寄与するかを高速に計算できます。 

各クエリは k を因数分解し、区間に必要な素数ごとに十分な指数質量が含まれているかどうかをチェックします。 要件が満たされない場合、答えは直ちに否定になります。 

## 実用的な例

 サンプル入力を使用してメカニズムを説明します。 

### 例 1

 クエリ: 間隔 [2, 4]、k = 72

 | ステップ | アクション | 状態 |
 | --- | --- | --- |
 | ファクター k | 72 = 2^3 * 3^2 | 必要: 2→3、3→2 |
 | プライム2 | [2,4] のカウント = 2 | 不十分？ 依存します |
 | プライム3 | [2,4] のカウント = 1 | 不十分です |

 間隔には十分な係数 3 が含まれていないため、位置ごとにカウントが間違っている場合、結果は「いいえ」になりますが、正しいプレフィックス構造では正確なカウントが示され、正しいインデックス付け全体での完全な係数の累積によりサンプルでは「はい」につながります。 

### 例 2

 クエリ: 間隔 [1, 4]、k = 16

 | ステップ | アクション | 状態 |
 | --- | --- | --- |
 | ファクター k | 2^4 | ツーが 4 つ必要 |
 | 2秒を数える | 1 位から 4 位まで | 十分な蓄積 |
 | 決定 | 指数の合計を比較する | 要件を満たします |

 これにより、正確性は個々の値ではなく、指数の合計に完全に依存することが確認されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、k に区間内に決して出現しない素数が含まれる場合です。 アルゴリズムは、プレフィックス辞書内の欠落キー チェックを通じてこれを即座に処理し、正しく No を返します。 

もう 1 つのエッジ ケースは、多くの位置で a_i = 1 の場合です。 1 は素数を提供しないため、どの構造にも現れず、そのような範囲にわたるクエリは非単位要素のみに正しく依存します。 

さらにエッジ ケースは、k = 1 の場合です。1 には素因数がないため、クエリは常に Yes を返します。fk が空でチェックが実行されないため、アルゴリズムはこれを自然に処理します。
