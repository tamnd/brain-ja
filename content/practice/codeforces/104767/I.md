 ## 問題の理解

 目標表面積が与えられます$C$、これは 2 つの異なる素数の積であることが保証されています。 これに加えて、次のリストが提供されます。$M$利用可能な辺の長さ。リスト内のすべての要素も素数です。 

タスクは、このリストから 2 つの異なる素数を選択し、それらの積が次と等しくなるようにすることです。$C$。 プールは正方形ではなく長方形でなければならないため、同じ数値を 2 回選択することはできず、選択された 2 つの素数は異なるものでなければなりません。 出力は単純に、小さい方が最初に出力され、その後に大きい方が出力されます。 

制約$C \le 10^{18}$までの単純な試行除算を使用して因数分解できないことを意味します。$C$, ただし、リストではすでに候補が制限されているため、一般に完全な因数分解は必要ありません。 候補者数$M \le 2 \cdot 10^5$は、リストに対する線形または線形に近いスキャンは許容されるが、問題の構造により補数の直接検証が可能であるため、リストに対する二次関数は不要であることを示唆しています。 

重要な微妙な点は、両方の要素が$C$はリストに表示されることが保証されているため、任意の約数を検索する必要はなく、指定されたセット内のメンバーシップ クエリのみを検索する必要があります。 

単純な間違いは、リストのすべてのペアを試して、その製品をチェックすることです。 それには必要になります$O(M^2)$操作、$M = 2 \cdot 10^5$につながる$4 \cdot 10^{10}$チェックして完全に不可能です。 

考えられるもう 1 つの失敗は、素数を反復して割り算をチェックすることです。$C \bmod P_i = 0$、そして見つけようとします$C / P_i$線形探索経由。 ハッシュしないと、これは次のように縮退します。$O(M^2)$また。 正しいアプローチでは、メンバーシップのチェックを一定時間行う必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。リストにあるすべての素数のペアを試し、その積が次と等しいかどうかを確認します。$C$。 解はリスト内に存在することが保証されているため、これは正しいです。 ただし、すべてを検査します$\binom{M}{2}$ペアリングでは遅すぎる$M$大きいです。 

視点を変えることでこれを改善できます。 2 つの数値を選択して乗算する代わりに、1 つの数値を修正できます$p$そしてもう一方が何であるかを計算します。$q = C / p$。 以来$C$次の場合、 は 2 つの異なる素数の積であることが保証されます。$p$そのうちの1つです。$q$リスト内の素数も必要です。 

これにより、問題はメンバーシップ テストの問題に帰着します。$p$、どうかを確認してください$C$で割り切れます$p$、そうであれば、次のことを確認してください。$C/p$リストに存在します。 ハッシュ セットを使用すると、両方の操作が可能になります$O(1)$平均すると、完全なソリューションがリニア スキャンに変わります。

 ## アルゴリズムのチュートリアル

 私たちは、正しいペアがまさに次の 2 つの素因数であるという事実に依存しています。$C$、両方とも入力リストに存在することが保証されています。 

1.読む$C$、$M$、素数のリスト。 定数時間の検索のためにすべての素数をハッシュ セットに保存します。 これにより、補体の候補が存在するかどうかを迅速に確認できます。 
2. 各素数を反復処理します。$p$リストにあります。 それぞれ$p$はプールの潜在的な辺の長さです。 
3. かどうかを確認します。$p$分割する$C$。 そうでない場合は、両方の有効な因子を正確に乗算して次の値になる必要があるため、正しいペアの一部であることはできません。$C$。 
4. もし$p$分割する$C$、計算する$q = C / p$。 これが唯一の可能なパートナーです$p$有効な解決策で。 
5. かどうかを確認します。$q$許可された素数のセットに存在します。 そうであれば、必要な 2 つの辺の長さが見つかります。 
6. 小さい値が最初に表示されるように、ソートされた順序でペアを出力します。 

### なぜ効果があるのか

 正しさは構造に依存します$C$。 以来$C$は 2 つの異なる素数の積であり、正確に 2 つの素約数を持ちます。 有効なソリューションでは、これら 2 つの数値を正確に使用する必要があります。 したがって、任意の$p$分けるリストから$C$そして補完的な要素を生み出します$q$リストに表示される も 2 つの正解のうちの 1 つである必要があります。 ハッシュ セットにより、曖昧さや繰り返しのないメンバーシップの検出が保証され、因子が明確に保証されているため、明確性条件が自動的に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    C = int(input())
    M = int(input())
    arr = list(map(int, input().split()))
    
    s = set(arr)
    
    for p in arr:
        if C % p == 0:
            q = C // p
            if q in s and q != p:
                print(min(p, q), max(p, q))
                return

if __name__ == "__main__":
    solve()
```この解決策は、利用可能なすべての辺の長さをセットに配置することから始まり、補体のメンバーシップの定数チェックを可能にします。 次に、各候補をざっと調べます$p$。 割り算チェック$C \bmod p = 0$無関係な素数を早期にフィルタリングして、不必要なセットの検索を回避します。 

有効な約数が見つかったら、その補数を計算し、それがセット内に存在することを確認します。 条件$q \ne p$この問題では明確な素数が保証されますが、プールが正方形ではないという要件が強制されます。そのため、これは主に安全対策です。 

因数分解の一意性によって 2 番目の有効な解が存在しないことが保証されるため、有効なペアが見つかるとすぐに出力して終了します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    C = int(input())
    M = int(input())
    arr = list(map(int, input().split()))
    s = set(arr)

    for p in arr:
        if C % p == 0:
            q = C // p
            if q in s and q != p:
                return f"{min(p,q)} {max(p,q)}\n"

    return ""

 ## 特殊なケース

 微妙なエッジ ケースは、有効な因子のペアが入力リスト内で逆の順序で表示される場合です。 たとえば:

 入力:```
21
4
7 2 3 5
```ここでも、アルゴリズムは引き続き正しく動作します。 最初に 7 をチェックし、計算します$21/7 = 3$、セット内でそれが見つかるので、出力します$3 7$。 順序付け制約は、出力時に次のように処理されます。`min`そして`max`なので、入力順序は関係ありません。 

もう 1 つのケースは、非因数素数が除算する場合です。$C$オーバーフローの問題により、整数演算が正しく行われません。 Python ではこのようなことは起こりませんが、固定幅言語では、64 ビット整数を慎重に使用する必要があります。$C$まで可能です$10^{18}$。 

最後のケースは、入力リストに両方の因子が含まれているが、一方が早く現れ、もう一方が遅く現れる場合です。 アルゴリズムはスキャン順序に応じて早く終了するか遅く終了することがありますが、有効な遭遇があればすぐに固有の解決策が得られるため、正確さには影響しません。
