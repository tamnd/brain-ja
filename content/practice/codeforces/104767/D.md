 ## 解決策
 ## 問題の理解

 演算子が組み込まれた一連の整数で構成される固定算術式が与えられます。演算子は加算、減算、乗算です。 式は常に標準の優先順位ルールを使用して評価されるため、加算と減算の前に乗算が適用され、グループ化を変更するためのかっこはありません。 

初期式が評価された後、一連の更新を受け取ります。 更新するたびに、式内の数値の 1 つが変更されます。 更新前を含め、このような変更が行われるたびに、式全体が偶数整数と奇数整数のどちらに評価されるかを報告する必要があります。 

重要な点は、式の完全な数値は必要なく、そのパリティのみが必要であるということです。 これにより、問題はすぐにモジュロ 2 算術の推論に帰着します。 

この制約により、最大 100,000 個の数値と 100,000 回の更新が許可されます。 各更新後に式全体を再計算すると、クエリごとに O(N) のコストがかかり、O(NM) となり、あまりにも大きすぎます。 更新ごとに 1 回の完全な再計算を行うだけでも、最悪の場合、10¹⁰ の操作が必要になりますが、これは実行不可能です。 

微妙だが重要な点は、乗算は 2 を法とするゼロの存在によってのみ非線形にパリティと相互作用するということです。ただし、法 2 の算術演算では、乗算と加算は両方とも明確に定義されており結合的ですが、減算はパリティで XOR であるため、減算は加算と同じになります。 

エッジケースは演算子の優先順位から発生します。 単純に左から右に評価したり、すべての操作を同等に扱ったりすると、誤った結果が得られます。 

たとえば、次のように考えてみましょう`2 + 1 * 1`。 正しい評価は`2 + (1 * 1) = 3`、これは奇妙です。 素朴な左から右への評価は次のようになります。`(2 + 1) * 1 = 3`、ここではまだ正しいですが、一般的に信頼できません。 別の例`1 + 2 * 2`: 正しいのは`1 + 4 = 5 (odd)`ただし、不注意にグループ化すると、更新時の中間構造を誤って評価する可能性があります。 

本当に難しいのは、演算子の優先順位を尊重しながら、更新時の正確性を効率的に維持することです。 

## アプローチ

 ブルート フォース ソリューションでは、更新のたびに式全体が評価されます。 式を解析し、最初に乗算を適用するか、スタックベースの評価器を使用して、最終値を計算します。 各評価は O(N) で、これを M 回の更新に対して実行すると O(NM) になりますが、これは 105 回の操作には遅すぎます。 

重要な洞察は、パリティのみを考慮しているということです。 これにより、問題をモジュロ 2 算術上の線形構造の追跡に変換することができます。 

- 加算は XOR になります
 - 減算は XOR になります
 - 乗算は AND になります

 したがって、すべての演算子は単純なブール演算になります。 ただし、優先順位が依然として重要であるため、すべてを単一の実行 XOR 式に単純に折りたたむことはできません。 

優先順位を維持する正しい方法は、+ または - で区切られたセグメント内で乗算チェーンが独立して動作することを観察することです。 連続した乗算の各セグメントは 1 つのパリティ値に分解され、式は XOR によって結合された一連のセグメント寄与になります (+ と - は同一の mod 2 であるため)。 

したがって、私たちは次のことを維持します。 

- 単一の値として * で接続された数値の各最大ブロック (積 mod 2)
 - 更新をサポートするこれらのブロックにわたるセグメント ツリーまたはバランスの取れた構造

 パリティでは乗算は AND であるため、ブロック内の要素が偶数でない限り、ブロックは 1 になります。 

したがって、各ブロックは「ブロック内に偶数があるかどうか」ということになります。 

各数値のパリティを追跡する元の配列に対してセグメント ツリーを維持します。 次に、演算子ごとに、乗算ブロックが「すべて奇数」であるかどうかを事前計算します。 乗算チェーンは、すべての値が奇数の場合は 1、それ以外の場合は 0 になります。 

これで、式は XOR と結合されたブロック値のシーケンスになり、ブロック全体にわたる 2 番目のセグメント ツリーで維持できます。 ただし、更新は 1 つの位置にのみ影響するため、影響を受けるブロック積を O(log N) で再計算し、グローバル XOR 和を維持できます。 

したがって、各更新は対数的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM) | O(N) | 遅すぎる |
 | 最適 | O((N+M) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてをパリティの観点から処理し、各数値を偶数の場合は 0、奇数の場合は 1 に変換します。 

1. すべての入力数値をパリティ値に変換します。 これにより、すべての算術演算がブール演算に簡素化されます。 これが機能する理由は、モジュラー リダクションでパリティが維持されるためです。 
2. 乗算チェーンの開始位置と終了位置を事前計算します。 演算子が連続したシーケンスを形成するたびに、`*`、それらの位置をブロックにグループ化します。 これが必要なのは、乗算が加算や減算よりも優先されるためです。 
3. 各ブロックについて、その値をそのブロック内のすべてのパリティ値の AND として定義します。 ブロックは、その中のすべての数値が奇数の場合にのみ 1 と評価されます。 これは正しいです。なぜなら、偶数であれば積は均等になるからです。 
4. AND のポイント更新と範囲クエリをサポートする、元のパリティ配列に対するセグメント ツリーを維持します。 これにより、変更後にブロックを効率的に再計算できます。 
5. 最終的な式が評価されるブロック全体で別の構造 (または再計算された集計) を維持します。 + と - はパリティにおいて同等であるため、最終的な組み合わせはブロック値に対する XOR になります。 
6. 更新ごとに、更新されたインデックスでパリティを反転し、セグメント ツリーを使用して影響を受ける乗算ブロックを再計算し、それに応じてグローバル XOR 寄与を更新します。 
7. 各更新後に、すべてのブロック値の現在の XOR を出力します。 

### なぜ効果があるのか

 パリティは式をブール代数システムに変換し、加算と減算は XOR に変換され、乗算は AND になります。 演算子の優先順位は、XOR を適用する前に乗算チェーンをグループ化することによって保持されます。 各ブロックは独立しており、偶数が含まれているかどうかによって完全に決定されるため、更新は O(log N) 構造のみに影響し、グローバル XOR はすべてのブロックの寄与を正しく集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [1] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = self.t[v * 2] & self.t[v * 2 + 1]

    def update(self, v, l, r, i, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i, val)
        else:
            self.update(v * 2 + 1, m + 1, r, i, val)
        self.t[v] = self.t[v * 2] & self.t[v * 2 + 1]

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        if r < ql or l > qr:
            return 1
        m = (l + r) // 2
        return self.query(v * 2, l, m, ql, qr) & self.query(v * 2 + 1, m + 1, r, ql, qr)

def solve():
    n, m = map(int, input().split())
    nums = list(map(int, input().split()))

    # parity array
    a = [x & 1 for x in nums]

    # read operators
    ops = input().split()

    # build segment tree for AND queries
    st = SegTree(a)

    # compute block boundaries based on '*'
    # block i belongs to current multiplication chain
    block_id = [0] * n
    blocks = []
    b = 0

    i = 0
    while i < n:
        j = i
        while j < n - 1 and ops[j] == '*':
            j += 1
        blocks.append((i, j))
        for k in range(i, j + 1):
            block_id[k] = b
        b += 1
        i = j + 1

    block_val = [0] * b
    for idx, (l, r) in enumerate(blocks):
        block_val[idx] = st.query(1, 0, n - 1, l, r)

    # XOR over blocks gives result
    total = 0
    for v in block_val:
        total ^= v

    def recompute_block(bid):
        l, r = blocks[bid]
        block_val[bid] = st.query(1, 0, n - 1, l, r)

    print("odd" if total else "even")

    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1

        st.update(1, 0, n - 1, x, y & 1)

        bid = block_id[x]
        old = block_val[bid]
        recompute_block(bid)
        total ^= old ^ block_val[bid]

        print("odd" if total else "even")

if __name__ == "__main__":
    solve()
```この実装では、すべての数値をパリティに換算し、範囲 AND クエリをサポートするセグメント ツリーを使用して乗算セグメントを効率的に評価します。 各乗算セグメントは、内部の要素が変更されると再計算されます。 グローバル式はセグメント値の XOR として維持され、パリティのもとで加算と減算を正確にモデル化します。 

実装の微妙な詳細は、モジュロ 2 の算術演算では両方とも減算が行われるため、減算を個別に処理する必要がないことです。`+`そして`-`XORになります。 これが、評価段階で減算を明示的に保存したり区別したりしない理由です。 

## 実用的な例

 ### トレースの例

 入力:```
6 4
11 + 22 * 33 - 44 * 55 * 66
1 2
2 3
4 5
3 5
```パリティを追跡します。 

初期配列:`[1,0,1,0,1,0]`オペレーター:`+ * - * *`形成されたブロック:

 - ブロック 0: インデックス 0 (単一)
 - ブロック 1: インデックス 1 ～ 2 (* による)
 - ブロック 2: インデックス 3
 - ブロック 3: インデックス 4 ～ 5 (** による)

 ブロック値:

 | ブロック | インデックス | パリティ値 | AND の結果 |
 | --- | --- | --- | --- |
 | 0 | [0] | [1] | 1 |
 | 1 | [1,2] | [0,1] | 0 |
 | 2 | [3] | [0] | 0 |
 | 3 | [4,5] | [1,0] | 0 |

 合計 XOR = 1 → 奇数

 更新後は、影響を受けるブロックのみが再計算されます。 たとえば、インデックス 1 を 0 から 1 に変更すると、ブロック 1 が 0 から 1 に変更され、それに応じてグローバル XOR が反転します。 

このトレースは、ローカルでは乗算チェーンのみが重要であり、グローバルな結果は単純な XOR 集計であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + M) log N) | 各更新により、ポイントの更新とセグメントの再計算がトリガーされます。 
| スペース | O(N) | セグメント ツリーとブロック メタデータ |

 2 × 10⁵ log 10⁵ 演算は一般的な制約内に十分収まるため、これは制限内に問題なく収まります。

 ## 特殊なケース

 重大なエッジ ケースは、乗算チェーンがほぼ配列全体に広がり、1 回の更新でそのパリティが反転される場合です。 たとえば:

 入力:```
5 1
1 * 1 * 1 * 1 * 1
3 2
```最初はブロックはすべて奇数であるため、1 と評価されます。 中央の要素を偶数に更新すると、ブロック全体が 0 になります。アルゴリズムは、セグメント ツリーを介してブロックを再計算し、XOR 寄与を 1 つだけ反転することでこれを処理し、式の無関係な部分に触れることなく正確さを確保します。 

もう 1 つのエッジ ケースは、乗算演算子がまったくない場合です。 各数値は独自のブロックになり、答えはすべてのパリティ値の XOR に縮退しますが、アルゴリズムは特別なケースを使用せずに均一に処理します。
