 ## 解決策
 ## 問題の理解

 入力は、バランスの取れた括弧のシーケンスとしてエンコードされたツリー状構造内のウォークを記述します。 すべての開始括弧は、新しく発見された部屋への移動、またはトラバースのより深い部分から部屋を再訪問することに対応し、すべての閉じ括弧は、部屋からトラバース履歴で以前に見た祖先に戻ることに対応します。 ウォークは常にルートで始まりルートで終わるため、括弧は有効なバランスの取れたシーケンスを形成します。 

変換ルールは、この走査レコードを算術式に変換します。 最終的な式内の隣接するシンボルのペアはすべて、シーケンス内の 2 つの連続する括弧に依存します。 重要な考え方は、文字列内の各位置は独立しておらず、寄与は隣接する括弧の局所的な関係に依存するということです。 タスクは、これらのローカル置換ルールを適用した後に結果の式を評価することです。 

シーケンスの長さは最大でも 100 であるため、2 次またはそれよりわずかに悪い解でもすでに十分です。 これにより、漸近最適化に関する懸念がなくなり、ブラケット シーケンス内の構造的関係を算術寄与に正しく変換することに完全に焦点が移ります。 

複数の同一の連続括弧が出現すると、微妙な失敗のケースが発生します。 たとえば、「)))」のような接頭辞では、ルールにより、連続する閉じ括弧の各ペアの間に特別な「+1」が導入されます。 隣接関係を処理せずにペアのマッチングまたはスタックのマッチングのみを考慮する単純なアプローチでは、これらの寄与を完全に見逃してしまいます。 同様に、「(()())」のようなシーケンスには、入れ子構造と隣接効果が混在しているため、これを括弧の均衡評価のみとして扱うと、誤った結果が生成されます。 

## アプローチ

 問題を直接解釈するには、式がどのように構築されるかをシミュレートすることです。 まず、隣接するペアをスキャンし、ルールに従ってシンボルを挿入することによって式を明示的に構築し、次にスタックベースのパーサーまたは再帰降下を使用して結果の算術式を評価できます。 これは正しいです。変換ルールは純粋にローカルであり、最終式は整数と乗算に対する有効な算術式であるためです。 

ただし、完全な式を構築する必要はありません。 ルールの構造により、括弧文字列の 1 回のスキャン中に寄与度を直接計算できます。 隣接する各ペアは、ペアのタイプに応じて 3 つの可能な値のうちの 1 つを正確に提供します。 これにより、問題は完全な式ツリーを構築するのではなく、局所的な寄与の合計を評価することに変わります。 

ブルート フォース アプローチは、大きなサイズに拡張した場合、または明示的な文字列拡張と解析を使用して実装した場合にのみ効率性が低下しますが、さらに重要なことに、不必要な複雑さと解析ミスの余地が生じます。 最適化された解釈では、式の構築が完全に回避され、隣接する関係からの数値結果が直接蓄積されます。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、括弧のシーケンスを調べて、隣接する各ペアを最終的な合計に寄与するルールとして解釈することです。

1. 文字列を左から右にスキャンして、連続する文字のペアをすべて調べます。 各ペアは構築された式への 1 つの挿入を表すため、それぞれを 1 回だけ評価する必要があります。 
2. ペアが「()」の場合、これは値 1 を与える一致したステップに対応します。これは最も単純な構造単位であり、同じネスト レベルで前方への移動の直後に後方への戻りが続くことを表します。 
3. ペアが ")(" の場合、これは 2 つの別個の部分構造間を反対方向に移動することに対応し、1 の乗算に寄与するため、累積値は変わりません。
 4. ペアが "))" の場合、これはトラバーサルでの連続リターンを表し、ルールに従ってそれらの間に "+1" が寄与するため、結果に 1 を加算します。 
5. ペアが「((」の場合、より深い構造への連続した前方展開を表しますが、これは値に直接寄与しないため無視できます。
 6. すべての隣接するペアからのすべての寄与を合計して、最終的な答えを取得します。 

唯一の重要な推論ステップは、各ローカル パターンが独立して寄与を決定し、グローバルな解析やマッチングが必要ないことを認識することです。 

### なぜ効果があるのか

 トラバーサル エンコーディングにより、最終的な式に影響を与えるすべての構造的相互作用が隣接関係によってキャプチャされることが保証されます。 ネストされた構造は、どのペアがどのように寄与するかではなく、どのペアが表示されるかにのみ影響します。 各ルールは連続する 2 文字のみに依存するため、式は独立したローカル寄与に分解されます。 これにより、不変条件が作成されます。最初の i 個のペアを処理した後、累積された合計は、最初の i 個のローカル置換によって部分的に構築された式の値に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    
    ans = 0
    
    for i in range(n - 1):
        a, b = s[i], s[i + 1]
        
        if a == '(' and b == ')':
            ans += 1
        elif a == ')' and b == ')':
            ans += 1
        elif a == ')' and b == '(':
            ans += 0
        else:
            pass
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、隣接するペアを 1 回スキャンすることに完全に依存しています。 重要な点は、ゼロ以外の値を与えるパターンは「()」と「))」の 2 つだけであるということです。 他の 2 つのパターンは、中立的な乗算または価値を付加しない構造的な遷​​移に対応します。 これにより、スタック処理やストーリーで説明されている式の明示的な構築が不要になります。

 ## 特殊なケース

 エッジ ケースの 1 つは、「)))))」などの連続する閉じ括弧によって支配されるシーケンスです。 この場合、隣接するすべてのペアが 1 を寄与するため、アルゴリズムは正確に N-1 の寄与を蓄積します。 各「))」は構造的な一致を必要とせずに増分をトリガーするため、スキャンはこれを自然に処理します。 

もう 1 つのエッジ ケースは、「(((())))」のような完全にネストされたシーケンスです。 ここでは、特定の遷移のみが寄与し、アルゴリズムは依然として各隣接ペアを独立して処理します。 結果は、より深いネストとリターンの間の境界からのみ得られ、スキャンは深さを明示的に追跡する必要がなく、これらのポイントを正確にキャプチャします。
