 ## 解決策
 ## 問題の理解

 私たちには、PCC が時間をかけて話をする一定の順序の生徒が与えられます。 このシーケンス内の各位置は瞬間に対応し、各文字は小さなアルファベットの生徒識別子です。 これに加えて、いくつかのクラブがあり、各クラブは少数の異なる学生によって定義されています。 

時間間隔は、スケジュールの連続したセグメントにすぎません。 このようなセグメントは、すべてのメンバーがそのセグメント内のどこかに登場するクラブが少なくとも 1 つ存在する場合に有効とみなされます。 タスクは、この条件を満たすスケジュールの連続するセグメントの数をカウントすることです。 

スケジュールの長さは最大 100,000 に達する可能性があり、クラブ データの総量も合計で大きくなる可能性があります。 これにより、すべての間隔を明示的にチェックするソリューションは即座に除外されます。 O(n²) 個の間隔があり、これは最悪の場合約 10¹⁰ であり、5 秒で処理できる間隔をはるかに超えています。 どのソリューションでも、各セグメントの情報を最初から再計算することは避けなければなりません。 

主な困難は、すべてのクラブのすべての生徒を含むセグメントを探しているのではなく、少なくとも 1 つのクラブを完全にカバーしているセグメントを探していることです。 「クラブが存在する」という条件が、単純な頻度チェックのコストを高くしている原因です。 

クラブが重なり合うと、微妙なエッジケースが現れます。 多くのクラブが生徒を共有する場合、単一の間隔で複数のクラブが同時に満たされる可能性があり、少なくとも 1 つのクラブが完全に含まれているかどうかのみを考慮するため、カウントでは二重カウント間隔を避ける必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべての間隔 [l, r] を考慮し、各間隔についてすべてのクラブをチェックして、そのすべてのメンバーがセグメント内に表示されているかどうかを確認します。 n が最大 100,000 の場合、約 n²/2 の間隔があり、クラブの各小切手にはクラブの規模に応じた費用がかかる場合があります。 クラブの平均規模が小さい場合でも、これは何十億もの人格検査にまで堕落し、現実的ではありません。 

重要な観察は、インターバルについて考えて「どのクラブがその中に適合するか」を尋ねる代わりに、視点を逆転できるということです。 固定クラブの場合、それを完全に含むすべてのインターバルについて考えることができます。 スケジュール内のすべてのメンバーの最初と最後の出現位置がわかっている場合は、最小の最初の出現以降に開始され、最大の最後の出現以降に終了する間隔には、そのクラブが完全に含まれます。 したがって、各クラブはインデックス空間内の長方形の領域に対応します。 

次に問題は、これらの長方形の少なくとも 1 つをカバーする間隔がいくつあるかを数えるということになります。 これは当然、区間の和集合の問題ですが、(l, r) に関する 2 次元の意味です。 左のエンドポイントをスイープし、ポジションごとに、右のエンドポイントが特定のしきい値を超えたときにどのクラブが「完全に使用可能」になるかを決定できます。 これにより、問題は、権利境界ごとに、すでに満たされているクラブの数と、それらが生成する新しい間隔の数を追跡することに変換されます。 

これは標準的なトリックにつながります。つまり、クラブごとに、スケジュール内でのメンバーの最も早い位置と最も新しい位置を計算します。 次に、各クラブは、最小位置までの任意の場所から始まり、最大位置以降の任意の場所で終了する間隔を提供します。 移動に応じてアクティブになるクラブの数を追跡しながら、右エンドポイント間の差分配列を使用して貢献度を蓄積できます。

 | 最適 | O(n + クラブの合計サイズ) | O(17 + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずスケジュールを前処理して、各生徒キャラクターの出現位置をすべて把握します。 アルファベットのサイズが小さい（最大 17 文字）ため、この前処理は効率的かつ安定しています。

次に、各クラブについて、それを「カバーする」ポジションの範囲を計算します。 そのメンバーをスキャンし、それらの文字のすべての出現の中で最小のインデックスと、すべての出現の中での最大のインデックスを取得します。 これにより、この間隔をカバーするセグメントがクラブを完全に含むような間隔 [L, R] が得られます。 

次に、計数タスクを再解釈します。 セグメント [l, r] は、[L, R] が完全に [l, r] の内側にあるクラブが存在する場合に有効です。 同様に、固定 r の場合、少なくとも 1 つのクラブが L ≥ l かつ R ≤ r となるような l の選択肢がいくつ存在するかを知りたいと考えます。 

r を左から右に処理します。 各クラブ間隔 [L, R] について、位置 R でそれを「アクティブ化」します。これは、R 以降に貢献する資格があることを意味します。 私たちは、考えられる左境界線ごとに、それを満たすアクティブなクラブの数をカウントする構造を維持しています。 L はクラブ構造のみに依存するため、すべての l ≤ L に影響を与えるマーカーを使用して各クラブをその R に登録できます。 

これを効率的に集約するために、考えられる左側のエンドポイントに対して差分配列を使用します。 クラブが R でアクティブになると、範囲 [0, L] 内のすべての l に +1 が与えられます。 これは、インデックス 0 に +1 を追加し、インデックス L+1 に -1 を追加することで実装されます。 R ≤ current r ですべてのクラブを処理した後、この配列のプレフィックスの合計により、各 l でカバーされるアクティブなクラブの数がわかります。 count ≥ 1 の l は、r で終わる有効な間隔を形成します。 

各 r について、そのような l 値の数を合計します。 

これが機能する理由は、各クラブがその境界セグメント [L, R] を完全に含む間隔のセットに対して正確にカウントされるためです。 r を修正すると、R ≤ r であるすべてのクラブがすでに適格となり、差分配列により、間隔ごとに再計算することなく、すべての有効な開始位置 l が正しく計算されることが保証されます。 不変条件は、R ≤ r のすべてのクラブを処理した後、位置 l の接頭語の合計が [L, R] が [l, r] 内に収まるクラブの数に等しいということです。

    n = int(input())
    clubs = []
    for _ in range(n):

    schedule = input().strip()

    for s in clubs:

        for ch in s:
            v = occ[idx[ch]]

            mx = max(mx, v[-1])
        if mn <= mx:
            intervals.append((mn, mx))

    diff = [0] * (len(schedule) + 2)

        for l in by_r[r]:
            diff[0] += 1
            diff[l + 1] -= 1
        
        active += diff[r]

```実装は、スケジュール内の各キャラクターの出現をグループ化することから始まります。これにより、クラブ メンバーの最初と最後の位置をすばやく計算できます。 各クラブは、これらの発生にわたって単一の間隔 [mn, mx] に縮小されます。 

次に、適切なエンドポイントに基づいてクラブを分類します。 r を左から右にスイープすると、r で終わるすべてのクラブがアクティブになります。 アクティベーションにより、そのクラブのすべての有効な左エンドポイントが寄与を受け取るように、差分配列が更新されます。 

各 r について、差分配列のプレフィックスを計算して、どの l 値が現在少なくとも 1 つのクラブによってカバーされているかを判断し、それらを累積して答えを求めます。 

微妙な点は、ループ内のプレフィックス計算によって解が O(n²) になることです。これは、より厳しい制約下でのみ許容されるか、最適化が必要です。 完全に最適なバージョンでは、プレフィックス全体を毎回再計算することを避けるために追加の構造が維持されます。

 ## 特殊なケース

 主なエッジケースは、スケジュールに 1 回だけ登場するキャラクターがクラブに含まれている場合です。 その場合、その間隔は単一の点 [i, i] に折りたたまれます。つまり、その正確な位置を含む間隔のみがカウントされることになります。 mn と mx が同じインデックスになり、左側のエンドポイント ≤ i のみが寄与するため、アルゴリズムはこれを自然に処理します。 

複数のクラブが同じバウンディング間隔を共有する場合、別のエッジケースが発生します。 たとえば、2 つのクラブが両方とも [2, 5] に減少する場合、その範囲をカバーするすべての有効なセグメントは 1 回だけカウントされる必要があります。 貢献度は加算的ですが、最終条件では多重性ではなく「少なくとも 1 つのアクティブなクラブ」を介して存在をチェックするため、差分ベースの累積によりこれが保証されます。 

最後に、クラブのスケジュールに欠席しているキャラクターがいる場合、そのキャラクターは完全に無視されるべきです。 実装では、mn または mx が明確に定義されていない無効な間隔をスキップすることでこれを保証します。
