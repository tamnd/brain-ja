 ## 解決策
 ## 問題の理解

 コンテストのスケジュール案は 2 つあります。 フィリベルトのスケジュールは配列 (d) であり、アブラハムのスケジュールは配列 (x) です。 どちらのスケジュールからも問題を削除できますが、保持されたすべての問題は元の相対的な位置に留まる必要があります。 

2 つのスケジュールは同じ数の問題を引き起こす必要があります。 1 つのスケジュールから選択した問題は、別のスケジュールで同じ難易度の選択した問題と組み合わせることができます。 最終的なコンテストの順序は難易度に応じて厳密に増加する必要があるため、選択された難易度は厳密に増加する順序を形成します。 両方の提案の元の順序を保持する必要があるため、同じ増加シーケンスが両方の配列のサブシーケンスとして発生する必要があります。 

したがって、このタスクはまさに​​ **最長共通増加サブシーケンス** (LCIS) です。 必要なのはその長さだけです。 

配列の長さは最大 (10^4) ですが、難易度は (10^9) まで大きくなる可能性があります。 難易度境界では、難易度によって直接インデックス付けされた DP が除外されるため、アルゴリズムは数値範囲ではなく配列要素の数に依存する必要があります。 (10^4) の長さの制限により、サブシーケンスの指数関数的な列挙も除外されます。 二次アルゴリズムには、最大の場合でも (10^8) 個の状態遷移があり、最適化された C++ ではすでに限界に近づいているため、実装では DP を 1 次元に保ち、(n\times) のテーブルを格納することを避ける必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 両方の配列に異なる難易度が 1 つだけ含まれている場合、答えは出現回数ではなく (1) になります。 例えば、```
2 3
5 5
5 5 5
```答えがあります`1`, 最終難易度は厳密に増加する必要があるため、難易度 (5) を 2 つ両方選択することはできません。 

2 番目の罠は、解答内で同じ難易度を連続させることができないことです。 例えば、```
3 3
1 1 2
1 1 2
```答えがあります`2`で表される`[1, 2]`。 不注意な LCS 実装は、次のような結果を招く可能性があります。`3`選択することで`[1, 1, 2]`, しかし、それは厳密な増加に違反します。 

3 番目の罠は、順序制約が両方の配列で独立して重要になることです。 のために```
3 3
1 2 3
1 3 2
```答えは`2`。 シーケンス`[1, 3]`は有効ですが、`[1, 2, 3]`はエイブラハムの配列の部分列ではありません。 最初に値を並べ替えると、問題が保持するように求めている情報が正確に破壊されてしまいます。 

## アプローチ

 最も直接的なアプローチは、考えられる共通の部分列を列挙し、厳密に困難が増加している部分列のみを保持することです。 すべての正当な解はそのような部分列であるため、これは正しいですが、長さ (10^4) の配列には指数関数的に多くの部分列が含まれる可能性があるため、列挙は直ちに不可能になります。 

標準の動的プログラミングの定式化ははるかに優れています。 Filiberto の配列を左から右に処理します。 アブラハム配列のすべての位置 (j) について、(x_j) で終わる最良の増加する共通部分列の長さを維持します。 新しい値 (d_i) を処理する場合、(x_k<d_i) の時点で、一致する位置 (j) を前の位置 (k<j) から拡張できます。 エイブラハム配列を左から右にスキャンしながら、単一の変数を使用して、そのようなすべての (k) の中で最良の DP 値を維持できます。 

重要な詳細は更新の順序です。 (d_i) の処理中、実行最大値にはエイブラハム配列の以前の位置からの状態のみが含まれている必要があり、現在の (d_i) を使用して作成された状態を同じ反復中に再度使用してはなりません。 これにより、(d_i) の 1 つの出現が複数回使用されるのを防ぐことができます。 

その結果生じる再発は、

 [
 dp[j] =
 \begin{ケース}
 dp[j], & d_i\ne x_j,\
 best+1、& d_i=x_j、
 \end{件}
 】

 どこで`best`が最大です`dp[k]`これまでは (k<j) と (x_k<d_i) で見られました。 

したがって、ブルートフォース DP には (O(nm)) 時間必要ですが、最初の次元をロールアウトした後に必要なメモリは (O(m)) のみです。 元のコンテストが意図したソリューションは、この古典的な LCIS DP です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブシーケンスを列挙する | (O(2^{\min(n,m)})) | (O(\min(n,m))) | 遅すぎる |
 | フル二次元DP | (O(nm)) | (O(nm)) | メモリが多すぎる |
 | ローリングLCIS DP | (O(nm)) | (O(m)) | 最適化された実装で受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 両方の配列を読み取り、エイブラハムの配列を DP 次元として選択します。 必要に応じて、2 番目の配列が短くなるように配列を交換します。 これにより、メモリ フットプリントが削減され、内部ループの反復回数も削減されます。 
2.作成`dp[j]`、 どこ`dp[j]`位置で終了する厳密に増加する共通部分列の最適な長さです`j`2 番目の配列の。 値 0 は、有効なサブシーケンスがまだそこで終了していないことを意味します。 
3. すべての値を処理する`a`最初の配列の左から右へ。 この反復の開始時に、次のように設定します。`best = 0`。 この変数は、現在の値に先行できる最適なサブシーケンスを表します。 
4. 2 番目のアレイを左から右にスキャンします。 いつでも`b[j] < a`、 アップデート`best = max(best, dp[j])`。 このような立場は法的に優先される可能性があります`a`理由は、難易度が低く、2 番目の配列内の位置がすでに現在の位置よりも前であるためです。 
5. もし`b[j] == a`、 セット`dp[j] = max(dp[j], best + 1)`。 で表される部分列`best`現在の難易度で延長可能。 の`max`同じ値がもう 1 つ出現すると、この位置で終わる同等以上の良好な状態が既に生成されている可能性があるため、この値が必要となります。 
6. もし`b[j] > a`、何もしません。 このような値を以前の値にすることはできません。`a`、最後の難易度シーケンスが増加しているはずだからです。 
7. すべての要素が処理された後、次の最大値が表示されます。`dp`が答えです。 すべての正の DP 状態は法的共通増加サブシーケンスを表し、すべての法的サブシーケンスはその要素が処理されるときに考慮されます。 

### なぜ効果があるのか

 不変条件は、最初の配列の最初の (i) 要素を処理した後、`dp[j]`最初の配列の最初の (i) 要素のみを使用した、最後に選択された要素が (x_j) である正当な共通増加サブシーケンスの最大長です。 

いつ`d_i`よりも小さいです`x_j`、`x_j`によって拡張されたサブシーケンスのエンドポイントにすることはできません`d_i`。 いつ`d_i`等しい`x_j`、唯一の可能な先行要素は 2 番目の配列の前に出現し、厳密に難易度が低くなければなりません。 実行中の変数`best`は、まさにこれら 2 つの条件を満たす最大 DP 値です。 したがって`best + 1`以前のソリューションを拡張するためのあらゆる有効な方法を検討します。 

現在の反復では、新しく作成された状態が別の拡張機能に参加することはありません。`best`の場合にのみ更新されます`x_j < d_i`。 新しく作成された状態には正確な値があるため、`d_i`、後の同じスキャンではその厳密な不等式を満たすことができません。 これは、厳密な増加を自動的に強制する部分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # Keep the DP dimension as small as possible.
    if len(a) < len(b):
        a, b = b, a

    dp = [0] * len(b)
    answer = 0

    for x in a:
        best = 0

        for j, y in enumerate(b):
            if y < x:
                if dp[j] > best:
                    best = dp[j]
            elif y == x:
                value = best + 1
                if value > dp[j]:
                    dp[j] = value
                    if value > answer:
                        answer = value

    print(answer)

if __name__ == "__main__":
    solve()
```最初の部分は 2 つのスケジュールを読み取り、必要に応じてそれらを交換します。 DP 次元は 2 番目の配列であるため、そこで短い配列を選択すると、メモリと内部ループの反復回数の両方が最小限に抑えられます。 

の`dp`配列には長さのみが含まれ、実際のサブシーケンスは含まれません。 この問題では、選択された問題の最大数のみが要求されるため、先行問題を保存するとメモリが追加され、結果が改善されずに作業が行われてしまいます。 

それぞれの値について`x`最初の配列から、`best`ゼロから始まります。 2 番目の配列をスキャンしている間、難易度が低いすべての位置が先行者として適格となります。 そのDP値は`best`。 

等価ブランチは、小なりブランチから意図的に分離されています。 いつ`y == x`、現在のものを使用します`best`ただし挿入しないでください`dp[j]`の中へ`best`。 これにより、同じ困難が連鎖するのを防ぎます。 また、1 回のパス中に 1 回の発生が誤って 2 回発生する可能性がある、オフバイワンのミスも回避します。 

Python では整数オーバーフローの問題はありません。 答えは最大でも (\min(n,m)) なので、固定幅の 32 ビット整数でも十分です。 

この実装では、DP 配列を 1 次元に保ちます。 2 次元テーブルには最大 (10^8) の整数が含まれるため、Python のメモリ制限を大幅に超えてしまいます。

 | 時間 | (O(nm)) | 最初の配列のすべての要素は、2 番目の配列のすべての要素を 1 回スキャンします。 |
 | スペース | (O(\min(n,m))) | 1 次元 DP 配列のみが保存されます。 |

 ## 特殊なケース

 すべてが等しい場合は、実行最大値の厳密な比較によって処理されます。 のために```
2 3
5 5
5 5 5
```どの要素にも難しさがある`5`、 それで`y < x`は決して真実ではありません。 最初に一致した位置が受け取ります`dp = 1`ただし、その後の等しい位置は、等価分岐が更新されないため、それを拡張することはできません。`best`。 結果は`1`。 

より大きな値を組み合わせて同じ難易度を繰り返す場合、```
3 3
1 1 2
1 1 2
```最初`1`長さの状態を作成します`1`。 2番目`1`等しい値が除外されるため、その状態を拡張できません。`best`。 いつ`2`処理されると、既存の`1`状態が先行して長さを生成します`2`。 結果は`2`、に対応`[1,2]`。 

逆順の場合は、```
3 3
1 2 3
1 3 2
```値`1`長さを作成します`1`、 そして`2`後で長さを作成します`2`。 いつ`3`処理されると拡張できます`1`、ただし、長さ 3 のシーケンスを生成することはできません。`2`後に発生します`3`アブラハムの配列で。 最終的な答えは、`2`。 

最後に、(10^9) までの値は、この実装では特別な座標圧縮を必要としません。 難易度は次のような比較でのみ使用されます。`y < x`そして`y == x`したがって、数値の大きさは正確性やメモリ使用量に影響を与えません。
