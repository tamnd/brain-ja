 ## 解決策
 ## 問題の理解

 コンテストのスケジュール案は 2 つあります。 フィリベルトのスケジュールは長さ (n) の配列 (d) であり、アブラハムのスケジュールは長さ (m) の配列 (x) です。 各エントリは 1 つの問題の難易度であり、どちらのスケジュールも組み替えることはできないため、エントリの位置は固定されています。 

難易度 (v) を選択する場合、各配列から難易度 (v) の問題を 1 つ選択する必要があります。 選択された 2 つの問題は、最終コンテスト セットでペアを形成します。 選択した難易度の値は、あるペアから次のペアへと厳密に増加する必要がありますが、選択した位置は両方の元の配列内で増加したままでなければなりません。 

したがって、選択した難易度が

 [
 v_1 < v_2 < \dots < v_k、
 ]

 それならポジションがあるはずだ

 [
 i_1 < i_2 < \dots < i_k
 ]

 最初の配列と

 [
 j_1 < j_2 < \dots < j_k
 ]

 2番目の配列では次のようになります

 [
 d_{i_t}=x_{j_t}=v_t。 
]

 選択した各難易度は、各提案から 1 つずつ、合計 2 つの実際の問題に影響します。 可能な最長のシーケンスに (k) 個の困難が含まれる場合、必要な出力は (2k) です。 

これは、答えが最終的に 2 倍される必要があることを除けば、まさに最長共通増加部分列の問題です。 

配列の長さはどちらも (10^4) に達する可能性があるため、(10^8) 個の位置のペアが存在する可能性があります。 すべてのペアを明示的に列挙するアルゴリズムは C++ ではすでに大規模であり、指数関数的な検索は完全に不可能です。 標準的な動的計画法では、(O(nm)) 時間と (O(\min(n,m))) メモリを使用します。これは、この問題に対する実際的な 2 次解法です。 難易度の値は (10^9) まで大きくすることができますが、必要なのは等価性と比較のみであるため、その大きさは DP には影響しません。 

いくつかの特殊なケースでは、誤った答えが簡単に発生する可能性があります。 まず、同じ困難を繰り返してもすべてを数えることはできません。 例えば、```
1 1
5
5
```答えがあります`2`, 各配列から難易度 5 の問題が 1 つ選択されるためです。 繰り返されるペアを 2 つの困難の増加シーケンスとして扱うと、誤って生成されます。`4`。 

第二に、共通の困難がたくさんあるだけでは十分ではありません。 それらの位置は両方の配列で一致する必要があります。 例えば、```
2 2
1 2
2 1
```答えがあります`2`。 難易度 1 と難易度 2 は両方の配列に存在しますが、難易度を上げて選択するには両方の配列で 2 の前に 1 を指定する必要があり、これは不可能です。 

第三に、2 つの配列には同じ難易度が何度も含まれる可能性があり、最良の出現はその前に選択された内容によって異なります。 例えば、```
4 4
2 3 1 4
1 2 3 4
```答えがあります`6`、難易度（2、3、4）を使用します。 現在利用可能な最小の難易度を常に選択する欲張りな戦略では、最初に 1 を選択し、取得できる難易度は 1 と 4 の 2 つだけになります。 

最後に、配列に共通の難易度がまったくない場合、答えはゼロになります。 のために```
2 2
1 2
3 4
```何もペアリングできないため、正しい出力は次のようになります。`0`。 

## アプローチ

 直接的な総当たりアプローチでは、最初の配列のすべてのサブシーケンスと 2 番目の配列のすべてのサブシーケンスを生成し、どのペアが同じ厳密に増加するシーケンスを形成するかをチェックします。 一方の配列には (2^n) 個の部分列があり、もう一方の配列には (2^m) 個の部分列があるため、候補部分列のペアを考慮するだけでも、(\Theta(2^{n+m})) 個の可能性が得られます。 最大サイズでは (2^{20000}) となり、実行可能なサイズをはるかに超えます。 

有益な観察は、選択したシーケンス全体を記憶する必要がないということです。 最初の配列を左から右に処理するとします。 2 番目の配列のすべての位置 (j) について、正確に (x_j) で終わる共通の増加シーケンスの最適な長さを格納できます。 現在の値 (d_i) を考慮すると、(x_j<d_i) であるすべての以前の (x_j) が有効な先行値になります。 このようなすべての位置の中で、最大の DP 値のみが必要です。 (d_i=x_j) の場合、(d_i) をその最良の前任者に追加できます。 

微妙な部分は、2 番目の配列を左から右に処理することです。 変数を維持します`best`、すでに訪問した位置の中で、その値が現在の値 (d_i) よりも厳密に小さい最大の DP 値を表します。 (d_i=x_j) の場合、新しい候補は`best + 1`。 (x_j<d_i)の場合、`dp[j]`先行者としての資格が得られ、更新できるようになります`best`。 (x_j>d_i) の場合、結果として生じる難易度シーケンスは厳密には増加しないため、先行することはできません。 

DP は 2 番目の配列のスキャン中に更新されるため、その配列内の位置が自動的に考慮されます。 外側のループは最初の配列をスキャンするため、その位置も考慮されます。 同じ値が含まれることはありません`best`、非減少順序ではなく厳密な増加を与えます。 

結果として得られるアルゴリズムは、古典的な 1 次元 LCIS 動的プログラミング手法です。 実際の難易度シーケンスではなく長さのみが必要なので、(n\times) テーブル全体を 1 つの配列に圧縮できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^{n+m})) またはそれ以上 | 指数 | 遅すぎる |
 | 最適 | (O(nm)) | (O(\min(n,m))) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの難易度配列を保存します。 DP 配列には 2 番目の配列の要素ごとに 1 つのエントリがあるため、オプションで最初の配列を短くすることができます。 これによって正確性は変わりませんが、入力サイズが異なる場合でもメモリが削減されます。 
2.作成`dp[j]`、 どこ`dp[j]`最後に選択された難易度が である、一般的な厳密に増加するシーケンスの最大長です。`b[j]`。 ゼロは、現在そこで終了する有効なシーケンスがないことを意味します。 
3. すべての値を処理する`a[i]`左から右へ。 2 番目のアレイをスキャンする前に、次のように設定します。`best = 0`。 この変数には、難易度が`a[i]`。 
4.スキャン`b`左から右へ。 もし`b[j] < a[i]`、 それから`b[j]`先行できる`a[i]`ので、更新します`best`と`dp[j]`。 
5. もし`b[j] == a[i]`の場合、現在の 2 つの要素を一致させることができます。 この値で終わる最適なシーケンスの長さは次のとおりです。`best + 1`ので、更新します`dp[j]`その値で。 
6. もし`b[j] > a[i]`、何も変わりません。 そのような値を前に置くことはできません`a[i]`厳密に増加する順序で。 
7. 最初の配列のすべての要素が処理された後、次の最大値が`dp`LCIS の長さ (k) です。 選択した各難易度は、各配列から選択した 1 つの問題に対応するため、次のように出力します。`2 * k`。 

重要な不変条件は、外側のループのすべての点で、`dp[j]`は、最初の配列の処理されたプレフィックスと 2 番目の配列の位置 (j) に関連する処理されたプレフィックスから取得可能な最良の有効なシーケンスを表します。 1行スキャン中に、`best`正確に最大値が含まれています`dp[j]`現在の最初の配列の値よりも難易度が低いポジションの間で。 したがって、すべての遷移では有効な先行処理が正確に考慮され、無効な先行処理は考慮されません。 考えられるすべての LCIS は、最終的に一致したペアによって表示できるため、DP は最終的に最適な最終ペアを考慮し、最大保存長は選択された難易度の最適な数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # Keep the DP array on the shorter sequence.
    if len(b) > len(a):
        a, b = b, a

    dp = [0] * len(b)
    answer = 0

    for x in a:
        best = 0

        for j, y in enumerate(b):
            if y < x:
                if dp[j] > best:
                    best = dp[j]
            elif y == x:
                candidate = best + 1
                if candidate > dp[j]:
                    dp[j] = candidate
                    if candidate > answer:
                        answer = candidate

    print(answer * 2)

if __name__ == "__main__":
    solve()
```最初の部分では、2 つのスケジュール案を説明します。 問題は対称であるため、必要に応じて配列を交換しても安全です。共通の増加サブシーケンスは、どちらが最初の配列と呼ばれるかに関係なく、両方の配列を尊重する必要があります。 

の`dp`配列には、短い配列の各位置に 1 つの値が格納されます。 外側のループは他の配列の問題を修正し、内側のループは 2 番目の配列内の一致する可能性のある位置を調べます。 

内側のループ内の 2 つの条件の順序は重要です。 のために`y < x`、`dp[j]`の候補となる`best`。 のために`y == x`、現在の値は、`best`厳密に小さい値から累積されます。 なぜなら`best`はより小さい値に対してのみ更新されるため、等しい値が別の等しい値を拡張することはできません。 それはまさに、厳密な増加条件が要求するものです。 

更新しません`best`等しい値を処理した後。 これを行うと、同じスキャン中に同じ値が再度出現するときの先行値として現在の値が使用される可能性があり、厳密な不等式が非厳密な不等式に誤って変換されてしまいます。 

アップデート`dp[j] = max(dp[j], best + 1)`2 番目の配列の同じ位置には、最初の配列の異なるプレフィックスからアクセスできるため、これも必要です。 私たちは最も強い可能性を保持しています。 

最終的な答えは 2 倍になります。`dp`は選択した難易度の値をカウントし、問題は選択した問題の合計数を尋ねます。 共通の増加シーケンスにおけるすべての困難は、各提案からのちょうど 1 つの問題に寄与します。 

Python の整数はこれらの値ではオーバーフローせず、DP 値は最大 (10^4) です。

7
7
```DP はすべてゼロで始まります。 最初で唯一の値が一致する場合、`best`はゼロなので、一致する位置は`dp = 1`。 LCIS には 1 つの困難が含まれており、アルゴリズムは (1\cdot2=2) を出力します。 

両方のアレイに問題が発生しない場合、```
2 2
1 2
3 4
```等価分岐に到達することはありません。 毎`dp`エントリはゼロのままであるため、LCIS の最大長はゼロとなり、最終的な答えは次のようになります。`0`。

3 4
7 7 7
7 7 7 7
```最初`7`長さ 1 のシーケンスを作成します。 後ほど`7`条件により、厳密にこれより小さい値は見出されません。`y < x`他の人にとっては偽です`7`。 したがって、どのトランジションも長さ 2 を作成できません。 最終的な LCIS の長さは 1 で、答えは次のようになります。`2`。 

順序の問題が表示されるのは、```
4 4
2 3 1 1000000000
1 2 3 1000000000
```一般的な増加シーケンス (2,3,10^9) が有効です。 最初の配列は位置 (1,2,4) を使用し、2 番目の配列は位置 (2,3,4) を使用します。 値`1`これも一般的ですが、最初に選択すると、最初の配列の位置 3 にその出現箇所が配置され、後のものになります。`2`そして`3`利用できません。 民進党は貪欲にコミットしない`1`; 関連するすべての状態を保持し、長さ 3 を見つけて、`6`。 

同じメカニズムで、最大サイズの繰り返し値の場合も処理されます。 10,000部`5`各配列で、最初に一致する出現は長さを 1 にしますが、その後のすべての等しい出現は長さを拡張できません。`best`厳密に小さな困難のみが組み込まれています。 結果は残る`2`、同じ難易度のコピーが何枚存在するかに関係なく。
