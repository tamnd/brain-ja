 ## 解決策
 ## 問題の理解

 ネットワークは、一度に 1 台のコンピュータが成長するツリーです。 コンピュータ 1 は最初から存在します。 すべての新しいコンピュータは次の未使用の ID を受け取ります。`curr`コンピュータ、新しいコンピュータは ID を取得します`curr + 1`。 片方の端で既存のコンピュータに接続されます。 

タイプ 1 のクエリは、新しいコンピュータの親を間接的に指定します。 タイプ 2 のクエリは、2 つの既存のコンピューター間の最短パスを要求します。 答えはエッジではなくコンピューターをカウントするため、次のパスが含まれます。`k`エッジには答えがある`k + 1`。 

入力は、前の回答を使用して意図的にエンコードされます。 もし`last`が最新の回答であり、`curr`既存のコンピュータ、タイプ 1 の値`p'`親を表します

 [
 p=(p'+last)\bmod curr+1。 
】

 タイプ 2 の場合、2 つのエンドポイントはまったく同じ方法でデコードされます。 これは、クエリが厳密にオンラインで処理される必要があることを意味します。 次のクエリをデコードするために必要な値は現在のクエリによって生成されるため、最初にすべてのクエリをデコードしてから最終ツリーを前処理することはできません。 

最大 (2\cdot10^5) 個の操作が可能であるため、最終的なツリーにも最大で (2\cdot10^5+1) 台のコンピュータが含まれます。 すべてのクエリに対してルートからノードへのパス全体をたどるソリューションでは、(O(Q^2)) 時間がかかる可能性があります。 (Q=2\cdot10^5) の場合、これはおよそ (4\cdot10^{10}) 回の親走査に達する可能性があり、2 秒の制限が許容する範囲をはるかに超えています。 操作ごとに対数仕事が必要です。 

ツリー構造は、特に便利な特性を提供します。つまり、新しく作成された頂点はすべて葉であり、その親はすでに存在します。 したがって、新しい頂点に関するすべての情報は、その親からすぐに計算できます。 挿入後に既存のツリーを再構築したり走査したりする必要はありません。 

実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 1 つ目は、同じコンピュータに 2 回クエリを実行することです。 例えば、```
1
2 0 0
```コンピューター 1 しかないため、デコードされたエンドポイントは両方とも 1 で、正しい出力は次のようになります。`1`。 エッジの距離はゼロですが、問題はコンピューターの数を求めているため、答えは 1 です。 最終を忘れた実装`+1`ゼロを出力します。 

2 番目のエッジ ケースは、親が現在有効な最大の ID を持つ新しく追加されたコンピューターです。 考慮する```
4
1 0
1 1
2 0 0
2 0 1
```最初の挿入により、コンピューター 1 の下にコンピューター 2 が作成され、出力されます。`2`。 2 番目の挿入には、`last=2`、つまり、その親は`(1+2)%2+1=2`、コンピュータ 2 の下にコンピュータ 3 を作成して出力します。`3`。 3 番目のクエリは次のようにデコードされます。`(1,1)`そして出力`1`。 最終的なクエリは次のようにデコードされます。`(2,3)`、そのパスは`2-3`したがって、出力は次のようになります`2`。 正しい出力は次のとおりです```
2
3
1
2
```一般的な off-by-one エラーは、次の値を使用することです。`curr`親をデコードするときにそれをインクリメントした後。 新しい頂点を挿入する前に、コンピューターの数を使用して親をデコードする必要があります。 

3 番目のエッジケースは、`last`タイプ 2 クエリを含むすべてのクエリの後に変更されます。 例えば、```
3
1 0
2 0 0
2 0 0
```挿入後は、`last=2`。 次のクエリは両方のエンドポイントを 1 としてデコードし、次を出力します。`1`、 それで`last`したがって、現在のコンピュータ数とエンコードされた値がその結果を生成する場合に限り、最終的なクエリでは両方のエンドポイントが 2 に等しくなります。 古いものを再利用する`last`value は後続のクエリを正しくデコードしない可能性があります。 エンコードは、単なる入力の前処理ではなく、アルゴリズムの状態の一部です。 

## アプローチ

 直接的な解決策は、すべてのコンピュータの親を保存し、コンピュータ間のクエリを実行することです。`u`そして`v`、パスが交わるまで両方の頂点から上に向かって歩きます。 これは正しいです。ネットワークは常にツリーであるため、2 台のコンピュータ間にはパスが 1 つだけ存在します。 それらの最小共通祖先を見つけることができた場合、パス上のエッジの数は次のようになります。 

[
 深さ[u]+深さ[v]-2\cdot深さ[lca]。 
】

 1 つ追加すると、必要な数のコンピュータが得られます。 

問題は走行時間です。 1 本の長い鎖だけからなる木を考えてみましょう。 最も深いコンピューターに関係するクエリには、(O(n)) 個の親ステップが必要になる場合があります。 ツリーに (2\cdot10^5) 個の頂点があり、そのようなクエリを (2\cdot10^5) 回作成した場合、合計は約 (4\cdot10^{10}) 回の操作になります。 強引な方法は正しいですが、根本的に遅すぎます。 

問題を変える観察は、挿入は葉を追加するだけであるということです。 新しいコンピュータのとき`x`既存の親にアタッチされます`p`、その祖先チェーン全体をすぐに要約できます。 店`up[k][x]`の祖先`x`エッジを上方向 (2^k) に移動することによって取得されます。 以来`p`すでに知られているが、再発は

 [
 アップ[0][x]=p
 】

 そして

 [
 アップ[k][x]=アップ[k-1][アップ[k-1][x]]。 
】

 次の場合、既存の頂点は変更されません。`x`が挿入されるため、以前に計算されたすべてのバイナリリフティング情報は永久に有効なままになります。 

これはまさにバイナリ リフティングが適切に機能する設定です。 最初に両方の頂点の深さが同じになるまで深い頂点を上に移動し、次に両方の頂点を大きなジャンプから小さなジャンプに一緒に持ち上げることにより、(O(\log n)) 時間で LCA を見つけることができます。 新しい頂点の祖先を 2 の累乗すべてで計算するため、挿入自体にも (O(\log n)) がかかります。 

エンコードされた入力によってデータ構造は変更されません。 必要なのは、クエリを処理する前にデコードし、その答えを計算し、その答えをすぐに保存することだけです。`last`次のクエリのために。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(Q^2)) 最悪の場合 | (O(Q)) | 遅すぎる |
 | 最適 | (O(Q\log Q)) | (O(Q\log Q)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピュータ 1 をルートとして初期化します。 その深さをゼロに設定し、すべてのバイナリリフティングの祖先をゼロに初期化します。 ルートには実際の親がないため、ゼロは便利な番兵です。 
2.キープ`curr`現在存在するコンピュータの数に等しく、`last`前の回答と同じです。 最初は両方とも必要な値を持っていますが、`curr=1`そして`last=0`。 
3. タイプ 1 クエリの場合、次を使用して親をデコードします。`(p_prime + last) % curr + 1`変更する前に`curr`。 新しいコンピュータには ID があります`curr + 1`, id が連続して割り当てられるためです。 
4. 新しいコンピュータの深さを次のように設定します。`depth[parent] + 1`そしてその直接の親に`parent`。 次に、すべての上位祖先を次のように計算します。`up[k][new] = up[k-1][up[k-1][new]]`。 これは、右側で参照されているすべての頂点が挿入前にすでに存在しているため機能します。 
5. 新しいコンピュータのコンピュータ 1 へのパスには次のものが含まれます。`depth[new] + 1`コンピューター。 この値を次のように設定します`last`そしてそれを出力します。 ルートの深さはゼロなので、頂点は深さになります。`d`まさに`d+1`ルートへのパス上の頂点。 
6. タイプ 2 クエリの場合、現在のクエリを使用して両方のエンドポイントをデコードします。`last`そして`curr`。 モジュロは現在の頂点数によって取得されるため、両方のエンドポイントが既存のコンピューターを参照することが保証されます。 
7. デコードされたエンドポイントの LCA を見つけます。 まず、深さが一致するまで、より深いエンドポイントを持ち上げます。 次に、バイナリ リフティング レベルを最大から最小まで検査し、対応する祖先が異なるたびに両方のエンドポイントをリフトします。 このプロセスの後、それらの直接の親は LCA になります。 
8. エンドポイント間のエッジの数を次のように計算します。`depth[u] + depth[v] - 2 * depth[lca]`。 両方のエンドポイントがカウントされるため 1 を追加し、結果を次の場所に保存します。`last`を入力して出力します。 

### なぜ効果があるのか

 重要な不変条件は、既存のすべてのコンピュータに対して`v`、`depth[v]`はコンピュータ 1 からのエッジの正確な距離です、そして`up[k][v]`はその正確な (2^k) 番目の祖先です。 新しいリーフが挿入されると、その親はすでに有効になっているため、古い値を変更することなく、再帰によってすべての新しい祖先の値が正しく計算されます。 次に、バイナリ リフティングによって真の LCA が見つかります。これは、深さを等化すると両方の頂点が同じレベルになり、その後の最大値から最小値へのジャンプによって、LCA を越えることなく頂点が上方に移動するためです。 したがって、標準のツリー距離の式ではエッジの正確な数が得られ、1 を追加するとパス上のコンピュータの正確な数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX_Q = 200000
MAX_N = MAX_Q + 1
LOG = MAX_N.bit_length()

def solve():
    q = int(input())

    depth = [0] * (MAX_N + 1)
    up = [[0] * (MAX_N + 1) for _ in range(LOG)]

    curr = 1
    last = 0

    out = []

    for _ in range(q):
        parts = input().split()
        t = int(parts[0])

        if t == 1:
            p_prime = int(parts[1])

            # Decode using the number of computers before insertion.
            parent = (p_prime + last) % curr + 1

            new_node = curr + 1
            depth[new_node] = depth[parent] + 1
            up[0][new_node] = parent

            for k in range(1, LOG):
                mid = up[k - 1][new_node]
                up[k][new_node] = up[k - 1][mid]

            curr += 1

            last = depth[new_node] + 1
            out.append(str(last))

        else:
            u_prime = int(parts[1])
            v_prime = int(parts[2])

            u = (u_prime + last) % curr + 1
            v = (v_prime + last) % curr + 1

            if depth[u] < depth[v]:
                u, v = v, u

            # Bring u to the same depth as v.
            diff = depth[u] - depth[v]
            bit = 0
            while diff:
                if diff & 1:
                    u = up[bit][u]
                diff >>= 1
                bit += 1

            if u == v:
                lca = u
            else:
                for k in range(LOG - 1, -1, -1):
                    if up[k][u] != up[k][v]:
                        u = up[k][u]
                        v = up[k][v]

                lca = up[0][u]

            last = depth[u] + depth[v] - 2 * depth[lca] + 1
            out.append(str(last))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`depth`配列はゼロベースのツリーの深さを使用するため、コンピューター 1 の深さはゼロになります。 これにより、標準距離の式が特に明確になります。 要求された答えは、エッジ距離に 1 を加えたものになります。`up[0][v]`直接の親を保存しますが、`up[k][v]`上の祖先 (2^k) エッジを保存します`v`。 レベル数は`MAX_N.bit_length()`。 せいぜい`200001`コンピュータでは、これにより、考えられるすべての深さの違いと、考えられるすべての LCA ジャンプを表すのに十分なレベルが得られます。 

挿入の場合は、`curr`親がデコードされている間も、古いコンピュータの数を表します。 新しいコンピュータのすべての情報が計算された後でのみ、増加します。`curr`。 この順序はエンコード式で必要となります。 

タイプ 2 クエリの場合、LCA が機能する前にエンドポイントがデコードされます。 次に、深さの差の設定ビットに従って、より深いエンドポイントが持ち上げられます。 頂点が等しくなった場合、その頂点はすでに LCA です。 それ以外の場合、ループは最大から最小へのジャンプを考慮します。 いつ`up[k][u]`そして`up[k][v]`異なる場合でも、LCA が依然としてこれら 2 つの異なる祖先より上にあるため、両方の頂点は安全に (2^k) 上方に移動できます。 最終的に、彼らは LCA の子になります。 

Python の整数は、ここで使用される値ではオーバーフローしません。 解読式の最大中間値はわずか数十万であり、その距離はせいぜいコンピュータの数です。

 ## 特殊なケース

 単一コンピューターの場合は、ルートの深さが 0 であり、そのすべてのクエリのエッジが距離 0 であるため、処理されます。 この実装では、距離をコンピュータの数に変換するときに 1 が加算されます。 のために```
1
2 0 0
```両方のエンドポイントは 1 にデコードされます。`lca=1`、そして答えは`0+0-2*0+1=1`。 

自己クエリの場合は、特別なデータ構造操作は必要ありません。 いつ`u == v`、深さの等化によりそれらは直ちに等しくなるため、LCA は同じ頂点になります。 距離の式は次のようになります。`depth[u] + depth[u] - 2*depth[u] + 1`、それは 1 つです。 したがって```
4
2 0 0
2 0 0
2 0 0
2 0 0
```を含む 4 行が生成されます。`1`、 それでも`last`各クエリの後に変更されます。 

親境界ケースはモジュロ式によって制御されます。 で```
4
1 0
1 1
2 0 0
2 0 1
```最初の挿入では親 1 が使用されます。その答えは 2 なので、2 番目の挿入では親が次のようにデコードされます。`(1+2)%2+1=2`。 したがって、新しいコンピュータは深さ 2 と応答 3 を持ちます。次のクエリの後、`last`は 1 になり、最終的にエンコードされたエンドポイントは 2 と 3 になります。それらのパスには、ちょうど 2 台のコンピューターが含まれます。 アルゴリズムは、完全なパスをたどることなく、これらの結果を取得します。 

の注文`curr`これも微妙な境界条件です。 挿入前に 2 台のコンピュータがあったとします。 現在 ID 1 と 2 のみが存在するため、親はモジュロ 2 でデコードする必要があります。 インクリメント`curr`1 つ目は、数式でまだ作成されていないコンピューターを誤って選択することを許可します。 3. 実装は計算を行います。`parent`まず、構築します`new_node`、その後のみ増加します`curr`。 

最後に、エンコードされた入力をオンラインで処理する必要があります。 クエリは変更される可能性があります`last`、その値によって、後続のエンコードされたすべての数値の意味が変わります。 たとえば、サンプル 1 では、最初の挿入により次のものが生成されます。`last=2`; 2 番目の挿入の生の親値は次のとおりです。`2`ですが、実際の親は`(2+2)%2+1=1`。 すべての操作をデコードする実装`last=0`、または前の答えの代わりに最終的な答えを使用すると、異なるツリーが構築され、その結果、異なる結果が得られます。
