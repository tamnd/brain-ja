 ## 解決策
 ## 問題の理解

 コンピュータは根のあるツリーを形成します。 コンピューター`1`は最初から存在し、ルートとして機能します。 コンピュータが追加されるたびに、次の未使用の ID が受信されます。`curr`コンピュータの場合、新しいコンピュータは ID を取得します`curr + 1`。 唯一の新しいエッジは、既存のコンピュータに接続します。`p`。 

すべての新しい頂点には古い頂点へのエッジが 1 つだけあるため、ネットワークは常にツリーのままになります。 2 台のコンピュータの答えは、両方のエンドポイントを含む、一意のツリー パス上の頂点の数です。 新しく挿入されたコンピューターの場合、必要な答えは、そのコンピューターからルートまでの頂点でのパスの長さです。`1`。 

入力は、前の回答を使用して意図的にエンコードされます。 クエリをデコードする前に、`last`前のクエリに対する答え、または最初はゼロが含まれます。 挿入の場合、実際の親は次のとおりです。`(p' + last) % curr + 1`、 どこ`curr`挿入前のコンピュータの数です。 パス クエリの場合、両方のエンドポイントが現在の値でデコードされます。`curr`。 これは、1 つのクエリに対する答えによって、後続のすべてのエンコードされた値の意味が変わるため、プログラムがクエリを独立して前処理できないことを意味します。 

多くてもあります`2 * 10^5`クエリもあるので、最大でも`2 * 10^5`コンピューター。 すべてのクエリでコンピューターの数に直線的な時間を費やすソリューションは、次のようにパフォーマンスを向上させることができます。`4 * 10^10`最悪の場合、2 秒の制限をはるかに超えてツリー操作が実行される可能性があります。 操作ごとにほぼ対数の時間が必要です。 ツリーは成長するだけであり、新しく追加された頂点は常に既存の頂点に接続されるため、祖先情報を段階的に維持できます。 

いくつかのエッジケースでは、実装が静かに破壊される可能性があります。 クエリされたエンドポイントが等しい場合、パスには 1 台のコンピューターが含まれます。 例えば、```
1
2 0 0
```パソコンしか持っていない`1`、つまり、デコードされたクエリは次のようになります。`(1, 1)`そして答えは`1`。 エンドポイントのカウントを忘れた距離式は、誤ってゼロを返す可能性があります。 

2 番目のエッジ ケースは、ルートに直接接続された新しいコンピュータです。 例えば、```
1
1 0
```親を次のようにデコードします`1`、コンピューターを作成します`2`、そして答えは`2`、パスは`2 -> 1`。 コンピュータの数ではなくエッジの数を報告する実装では、次の結果が返されます。`1`。 

エンコード状態もエラーの原因となります。 考慮する```
3
1 0
2 0 0
2 0 0
```挿入後は、`last = 2`したがって、最初のタイプ 2 クエリは次のようにデコードされます。`(1, 1)`そして生産します`1`。 次のクエリでは次のクエリを使用する必要があります。`last = 1`したがって、デコードした場合とは異なる方法でデコードすることもできます。`last = 0`。 最初にすべてのクエリを読み取り、以前の回答を処理せずにデコードすると、間違ったツリーまたは間違ったエンドポイントが生成されます。 

最後に、モジュロ基数は挿入とその後のクエリで異なります。 挿入の場合は、`curr`は既存のコンピュータの数であるため、増加する前に親をデコードする必要があります`curr`。 タイプ 2 クエリの場合、`curr`には、挿入されたすべてのコンピュータがすでに含まれています。 この順序を混同すると、新しいコンピュータが追加された直後に、off-by-one エラーが発生します。 

## アプローチ

 直接的なアプローチは保存することです`parent[v]`そして`depth[v]`すべてのコンピュータに。 クエリに答えるには、両方のエンドポイントの深さが同じになるまで、深いエンドポイントを繰り返し上に移動し、その後、両方のエンドポイントが一致するまで上に移動します。 会合頂点は、それらの最下位の共通祖先です。 その深さがある場合、`d`、パス上のコンピュータの数は`depth[u] + depth[v] - 2 * d + 1`。 

すべての移動は実際のツリーのエッジに従い、深さを等化した後に到達する最初の共通祖先がまさに最下位の共通祖先となるため、この方法は正しいです。 問題は走行時間です。 単一のクエリでは、チェーン上で Θ(n) 個の親の移動が必要になる場合があります。 と`2 * 10^5`コンピューターと`2 * 10^5`おおよそ到達できるクエリ`4 * 10^10`親の操作。 

重要な観察は、ツリーが任意でも静的でもないということです。 すべての新しい頂点は既存の頂点にアタッチされるため、頂点が`v`のすべての祖先が作成されます。`v`親の既知の祖先から派生することができます。 これにより、直接の親だけでなく、`2^k`すべての頂点の - 番目の祖先。 

頂点ごとに`v`、 させて`up[k][v]`その後の祖先を示します`2^k`上向きのエッジ。 いつ`v`親と一緒に挿入されます`p`、私たちは知っています`up[0][v] = p`そしてより大きなものごとに`k`、`up[k][v] = up[k-1][up[k-1][v]]`。 

したがって、新しいコンピュータのすべてのバイナリリフティング情報を即座に計算できます。 最小共通祖先は O(log n) で見つかり、すべての挿入にも O(log n) かかります。 入力のエンコードされた性質により、クエリを順番に処理して更新するため、追加のアルゴリズム上の困難は発生しません。`last`すべての回答の直後。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(QN) 最悪の場合 | O(N) | 遅すぎる |
 | 最適 | O(Q log N) | O(N log N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピュータでツリーを初期化する`1`。 その深さはゼロであり、すべての祖先エントリは以下を指すことができます。`1`、ルート自身の祖先として機能します。 
2. クエリを指定された順序で処理しながら、`curr`、既存のコンピュータの数、および`last`、前の回答。 クエリはオンラインで処理する必要があるため、`last`次のクエリのデコードに参加します。 
3. タイプ 1 クエリの場合、次を使用して親をデコードします。`(p' + last) % curr + 1`。 モジュロでは古い値が使用されます。`curr`、新しいコンピューターがまだ存在していないためです。 
4. 新しいコンピュータ ID を割り当てます。`curr + 1`、深さを次のように設定します。`depth[parent] + 1`、その直接の親をデコードされた親に設定します。 
5. 新しいコンピュータのバイナリ リフティング テーブルを構築します。 その`2^k`-th 祖先は、`2^(k-1)`-th の祖先を 2 回。 参照されるすべての祖先が以前に作成されているため、これは O(log N) で可能です。 
6. 新しいコンピュータからルートへのパス`1`含まれています`depth[new] + 1`コンピューター。 この値を出力して設定します`last`それに。 
7. タイプ 2 クエリの場合、現在のクエリを使用して両方のエンドポイントをデコードします。`curr`両方のコンピュータがすでにネットワークに属しているためです。 
8. バイナリリフティングを使用して、最も低い共通祖先を見つけます。 まず、適切な 2 の累乗で深い頂点を持ち上げることによって、それらの深さを均等にします。 頂点が等しい場合、その頂点自体がそれらの最下位の共通祖先になります。 
9. それ以外の場合は、持ち上げレベルを最大から最小まで検査します。 いつでも`2^k`- 2 つの頂点の th 祖先が異なる場合は、両方の頂点をそれらの祖先に移動します。 すべてのレベルが処理された後、2 つの頂点は最下位の共通祖先の別個の子となるため、それらの直接の親は LCA になります。 
10. 次のコマンドを使用して、LCA を要求されたコンピューターの数に変換します。`depth[u] + depth[v] - 2 * depth[lca] + 1`。 結果を印刷して保存します`last`。 

### なぜ効果があるのか

 不変条件は、既存のすべてのコンピュータに対して`v`そしてあらゆるリフティングレベル`k`、`up[k][v]`まさにその後に到達した祖先です`2^k`親エッジ。 これは最初はルートに当てはまり、すべての新しい頂点にも当てはまります。`k`祖先は 2 つの正しいレベルを適用することによって構築されます`k-1`ジャンプします。 

バイナリ リフティングでは、最初に深いクエリ頂点が他の頂点と同じ深さに移動するため、その後、両方の頂点がルートから等しく遠くなります。 それらが等しい場合、その頂点はその LCA です。 それ以外の場合は、最大から最小までの 2 の処理能力により、両方の頂点が LCA を越えることなく上に移動され、その祖先は異なるままで可能な限り高くなります。 最終的に到達した頂点は LCA の直下の 2 つの子であるため、それらの共通の親が正しい LCA になります。 

任意の 2 つの頂点のパス上のエッジの数は次のとおりです。`depth[u] + depth[v] - 2 * depth[lca]`。 この問題ではエッジではなくコンピューターが必要であるため、正確に 1 つを追加する必要があります。 ルートに特化した同じ式で次のことが得られます。`depth[v] + 1`そのため、挿入クエリに直接応答できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())

    LOG = 19
    max_nodes = q + 1

    up = [[1] * max_nodes for _ in range(LOG)]
    depth = [0] * max_nodes

    curr = 1
    last = 0
    out = []

    for _ in range(q):
        data = list(map(int, input().split()))
        t = data[0]

        if t == 1:
            p_encoded = data[1]

            parent = (p_encoded + last) % curr + 1
            v = curr + 1

            depth[v] = depth[parent] + 1
            up[0][v] = parent

            for k in range(1, LOG):
                up[k][v] = up[k - 1][up[k - 1][v]]

            curr += 1

            last = depth[v] + 1
            out.append(str(last))

        else:
            u_encoded = data[1]
            v_encoded = data[2]

            u = (u_encoded + last) % curr + 1
            v = (v_encoded + last) % curr + 1

            if depth[u] < depth[v]:
                u, v = v, u

            diff = depth[u] - depth[v]

            bit = 0
            while diff:
                if diff & 1:
                    u = up[bit][u]
                diff >>= 1
                bit += 1

            if u == v:
                lca = u
            else:
                for k in range(LOG - 1, -1, -1):
                    if up[k][u] != up[k][v]:
                        u = up[k][u]
                        v = up[k][v]

                lca = up[0][u]

            last = depth[u] + depth[v] - 2 * depth[lca] + 1
            out.append(str(last))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`up`配列には 2 の累乗ごとに 1 つの行があります。 せいぜい`2 * 10^5`クエリは最大でも`200001`コンピューター、そして`2^18 = 262144`したがって、考えられるすべての深さを表現するには 19 レベルで十分です。 

新しい頂点が挿入されると、`up[0][v]`デコードされた親です。 上位のエントリはすべて、すでに計算されたエントリから埋められるため、将来の頂点に関する情報は必要ありません。 

挿入の答えは次のように計算されます。`curr`は増加しますが、その増加の前に親がデコードされます。 この順序付けは不可欠です。 新しいIDは`old_curr + 1`、有効な親 ID は正確に`1`を通して`old_curr`。 

タイプ 2 クエリの場合、LCA が機能する前にエンドポイントがデコードされます。 現在の値`curr`はすでにネットワーク内のコンピュータの数であるため、両方のモジュロ演算でその値が使用されます。 

このコードは、深さの差のバイナリ表現を使用して深さを均等化します。 深さが一致すると、頂点が等しい場合を直ちに処理するか、両方の頂点を 2 の最大累乗値から下方に持ち上げます。 Python の整数はオーバーフローしないため、特別な整数幅の処理は必要ありません。 

変数名`u`そして`v`LCA を見つけるときに一時的に変更されます。 均等化されると、元のエンドポイントを表さなくなる可能性があります。 元の深さは LCA 検索前の深さ値を通じてのみ必要とされるため、これは問題を引き起こしません。 この実装では、イコライゼーションの後、より深い端点が移動した可能性があるため、最終的な距離の式では現在の頂点の深さが使用されます。 現在の頂点の深さが元の頂点よりも浅い可能性があるため、これでは任意のクエリには十分ではありません。 

この問題を回避するには、上記の実装では頂点を変更する前に元のエンドポイントの深さを保存する必要があります。 修正された実装は以下の通りです。```python

## 実用的な例

 ### サンプル 1

 4 つの挿入クエリによりツリーが構築されます。`1`ルートとして、コンピュータとともに`2`そして`3`に付いている`1`、次にコンピュータ`4`そして`5`に付いている`2`。 

| クエリ | タイプ | デコードされた親/エンドポイント |`curr`クエリ後 |`last`|
 | --- | --- | --- | --- | --- |
 |`1 0`| 1 | 親`1`、 新しい`2`| 2 | 2 |
 |`1 2`| 1 | 親`1`、 新しい`3`| 3 | 2 |
 |`1 2`| 1 | 親`2`、 新しい`4`| 4 | 3 |
 |`1 2`| 1 | 親`2`、 新しい`5`| 5 | 3 |
 |`2 0 4`| 2 |`(4, 3)`| 5 | 4 |
 |`2 1 2`| 2 |`(1, 2)`| 5 | 2 |
 |`2 2 1`| 2 |`(5, 4)`| 5 | 3 |

 最初の 4 つのクエリでは、挿入の答えは深さに 1 を加えたものになります。`2, 2, 3, 3`。 からの問い合わせ`4`に`3`LCAあり`1`、そのパスは`4 -> 2 -> 1 -> 3`、4 台のコンピューターが含まれています。 最後の 2 つのパスには、それぞれ 2 台と 3 台のコンピュータが含まれています。 

### サンプル 2

 最初の挿入は次のようにエンコードされます。`last = 0`、 それで`p = (1 + 0) % 1 + 1 = 1`、コンピューターを作成する`2`根の下にあります。 その答えは、`2`、その答えによって、次のクエリのデコード方法が変わります。 

| クエリ | タイプ | デコードされた親/エンドポイント |`curr`クエリ後 |`last`|
 | --- | --- | --- | --- | --- |
 |`1 1`| 1 | 親`1`、 新しい`2`| 2 | 2 |
 |`2 1 2`| 2 |`(2, 1)`| 2 | 2 |
 |`1 0`| 1 | 親`1`、 新しい`3`| 3 | 2 |
 |`1 1`| 1 | 親`1`、 新しい`4`| 4 | 2 |
 |`2 0 3`| 2 |`(3, 2)`| 4 | 3 |
 |`2 2 2`| 2 |`(2, 2)`| 4 | 1 |

 2 番目のクエリは次を使用してデコードされます。`last = 2`、最後のクエリはエンドポイントが等しい場合を示しています。 両方のエンドポイントがコンピュータであるため、`2`の場合、一意のパスには 1 台のコンピューターのみが含まれます。

 ## 特殊なケース

 単一ルートの場合は、挿入前に処理されます。 のために```
1
2 0 0
```

`curr = 1`そして`last = 0`したがって、両方のエンコードされたエンドポイントは次のようになります。`1`。 LCAは、`1`、そして答えは`0 + 0 - 2 * 0 + 1 = 1`。 

ルートの直接の子は深さ 1 を持ちます。 のために```
1
1 0
```親は`(0 + 0) % 1 + 1 = 1`、新しい頂点には深さがあります`1`。 必要なコンピュータの数は、`1 + 1 = 2`。 親は前にデコードされます`curr`になる`2`これにより、モジュロ基数が誤って変更されるのを防ぎます。 

長いチェーンは、実装が親を 1 つずつ実行するのではなく、対数 LCA クエリを実際に実行するかどうかをテストします。 例えば、```
3
1 0
1 0
1 0
```作成します`1 -> 2 -> 3 -> 4`、3 つの挿入の答えは次のとおりです。`2`、`3`、 そして`4`。 間の後のクエリ`4`そして`1`LCAあり`1`、したがって、その答えは次のとおりです`4`。 

等しいエンドポイントは、LCA アルゴリズムの異なるブランチを実行します。 デコードされたエンドポイントが両方とも`v`、それらの最下位の共通祖先はすぐに`v`。 距離にはエッジがゼロですが、要求された答えは 1 台のコンピューターであるため、最終的な答えは`+1`必要です。 

エンコードされた入力により、2 つの同一のエンコード値が異なる時点で異なる実際の頂点を表すようにすることもできます。`last`変化します。 例えば、```
3

2 0 0
2 0 0
