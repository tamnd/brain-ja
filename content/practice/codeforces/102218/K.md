 ## 解決策
 ## 問題の理解

 2 つの正の整数 (A) と (B) が与えられ、それぞれに最大 100 万桁の 10 進数が含まれる可能性があります。 積は 10 進数の文字列 (P) として書かれますが、ちょうど 1 桁が`*`。 課題は、失われた数字を回復することです。 欠落している桁はゼロ以外であることが保証されます。 

最初の行は、(A)、(B)、(P) の長さを示します。 次の 2 行には (A) と (B) が含まれ、最後の行には (A \times B) の部分的に既知の 10 進表現が含まれています。 答えは、置き換える必要がある 10 進数です。`*`。 

重要な制約は整数の数値ではなく桁数です。 (A) と (B) はそれぞれ (10^6) 桁を持つことができるため、通常の機械演算でいずれかの整数を構築することは不可能です。 小学生の掛け算でも、(10^{12}) 桁の演算が必要になります。 欠落している可能性のある 9 桁すべてを試して結果の結果をチェックすると、そのコストは 9 倍になります。 

入力自体には最大約 200 万桁を含めることができるため、文字列を一定の回数スキャンするアルゴリズムが適切です。 乗算、組み込み整数型への変換、または数字列の二次演算を必要とするアルゴリズムは適していません。 Python の任意精度の整数でもこの結論は変わりません。入力整数は実際のネイティブ表現よりもはるかに大きくなる可能性があり、100 万桁の 10 進数文字列の変換自体が不必要な作業であるためです。 

一般的に間違いを引き起こす特殊なケースが 2 つあります。 まず、欠落している桁は (9) である可能性があります。 例えば、```
1 1 2
9
1
1*
```(A \times B = 9) が得られるので、答えは次のようになります。`9`。 結果のモジュロ (9) のみを計算し、剰余を直接返すメソッドは、次の値を返します。`0`、これは禁止されていますが、数学的にはモジュロ (9) と同等です。 欠落している数字がゼロ以外であるという保証により、剰余 (0) を数字 (9) として解釈するように指示されます。 

2 番目のエッジ ケースは、製品の両端に数字が欠落していることです。 例えば、```
2 2 3
10
10
*00
```製品があります`100`、したがって、不足している桁は`1`。 隣接する文字のみを使用して数字を推測しようとしたり、星を内部数字として扱ったりする方法は、ここで失敗する可能性があります。 モジュラー引数は星の位置に依存しないため、最初、最後、または中間の位置についても同じ計算が機能します。 

## アプローチ

 直接的なアプローチは、(1) から (9) までのゼロ以外の可能なすべての数字を試し、置き換えることです。`*`その数字を使用して、結果の文字列が (A \times B) に等しいかどうかをテストします。 これは正しいです。欠落している桁がこれら 9 つの値のいずれかであることが保証されているため、すべての可能性をテストして答えを見つける必要があります。 

問題は乗算です。 (A) と (B) の両方に最大 (10^6) 桁があるため、通常の長い乗算では、1 つの候補に対して (O(10^{12})) 桁の演算が必要になります。 9 つの候補をテストしても、最悪の場合でもおおよそ (9 \times 10^{12}) 個の演算が残ります。 より洗練された大きな整数の乗算を使用すると、この問題を漸近的に減らすことができますが、この問題には乗算を完全に回避するはるかに単純な性質があります。 

重要な観察は、10 進数は、その桁を合計するときに (9) を法とする値を保持することです。 任意の 10 進数 (X) について、

 [
 X \equiv \sum \text{桁}(X) \pmod 9.
 】

 (P = A \times B) なので、次のように計算できます。 

[
 P \bmod 9 = (A \bmod 9)(B \bmod 9) \bmod 9.
 】

 (A \bmod 9) と (B \bmod 9) は、膨大な整数を構築することなく、その桁をスキャンすることで計算できます。 また、未知の桁 (x) だけを残して、(P) のすべての既知の桁の寄与を計算することもできます。 

(P) の既知の数字の合計が (S) であると仮定します。 それから

 [
 x + S \equiv A \times B \pmod 9.
 】

 したがって、

 [
 x \equiv (A \times B - S) \pmod 9.
 】

 これにより、(0) から (8) までの剰余が得られます。 (1) ～ (8) の場合、それはまさに不足している桁です。 (0) の場合、問題では (0) が明示的に除外されるため、欠落している数字は (9) でなければなりません。 

この総当り方式は、すべての候補を正確な積と照合してチェックできるため機能しますが、オペランドに数百万桁が含まれている場合は失敗します。 10 進数の合計が (9) を法として値を保持するという観察により、膨大な乗算を 3 つの線形スキャンに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(AB)) 小学生の掛け算、最大 9 回繰り返す | (O(A+B+P)) | 遅すぎる |
 | 最適 | (O(A+B+P)) | (O(1)) 入力文字列のほか | 承認済み |

 ここで、複素数式の (A)、(B)、(P) は整数の数値ではなく、桁数を示します。 

## アルゴリズムのチュートリアル

 1. 3 つの長さと、(A)、(B)、および部分的に既知の積 (P) を表す文字列を読み取ります。 長さは数学には必要ありませんが、入力形式に従って読み取ります。 
2. (A) のすべての桁をスキャンし、繰り返し適用して (A \bmod 9) を計算します。`remainder = (remainder + digit) % 9`。 (B) についても同様の計算を行います。 これが機能するのは、小数点の値が (10^k) および (10 \equiv 1 \pmod 9) であるため、(10) のすべてのべき乗も (1) と合同です。 
3. (9) を法とした 2 つの剰余を乗算します。 結果は、完全な積 (P) が持つ必要がある残りです。 
4. スキャン (P)、無視しながら既知のすべての数字をモジュロ (9) で加算します。`*`。 結果の値を呼び出します`known`。 
5. 欠落している数字の剰余を次のように計算します。`(product_mod - known) % 9`。 モジュロ演算は、減算が負の場合を処理します。 
6. 結果の剰余がゼロの場合、出力`9`; それ以外の場合は、剰余自体を出力します。 剰余ゼロは両方の数字に対応します`0`と数字`9`、そしてステートメントは除外します`0`。 

### なぜ効果があるのか

 不変条件は、処理されたすべての 10 進数文字列が、その処理された数字の合計と同じ剰余モジュロ (9) を持つということです。 (A) と (B) をスキャンした後、(9) を法とする正確な剰余がわかるため、剰余乗算からその積剰余がわかります。 (P) の既知の数字をスキャンした後、その数字の合計から欠落している唯一の寄与は未知の数字 (x) です。 したがって、(x + S) は積の剰余 (9) を正確に持たなければなりません。 (0) と (9) だけが剰余 0 を共有し、(0) は禁止されているため、計算された剰余は、許可された数字 (1,\ldots,9) の中で (x) を一意に識別します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_mod_9(s):
    remainder = 0
    for ch in s:
        if ch != '\n':
            remainder = (remainder + ord(ch) - ord('0')) % 9
    return remainder

def solve():
    a_len, b_len, p_len = map(int, input().split())

    A = input().strip()
    B = input().strip()
    P = input().strip()

    a_mod = digit_mod_9(A)
    b_mod = digit_mod_9(B)

    product_mod = (a_mod * b_mod) % 9

    known_mod = 0
    for ch in P:
        if ch != '*':
            known_mod = (known_mod + ord(ch) - ord('0')) % 9

    missing = (product_mod - known_mod) % 9

    if missing == 0:
        missing = 9

    print(missing)

if __name__ == "__main__":
    solve()
```の`digit_mod_9`関数は、アルゴリズムの最初の部分で説明した桁の合計の計算を実行します。 (9) を法として換算した余りを維持することは、変数が 1 桁を超えて大きくならないことを意味します。 

二人はこう呼びかける`A`そして`B`オペランドの剰余を指定します。 これらの剰余を乗算すると、その積を構築せずに実際の積の剰余が得られます。 

最後のスキャンでは、`*`そして、すべての既知の積の桁の剰余を累積します。 これを積の剰余から減算すると、不足している桁のモジュロ (9) が分離されます。 

の`% 9`Python はモジュロを求める前に負の中間結果を生成する可能性があるため、減算後の演算が必要です。 からの最終的な変換`0`に`9`も不可欠です。 実際に欠落している桁が (9) である場合、剰余を直接返すことは失敗します。 

整数の変換や大きな数の乗算はありません。 Python の任意精度の算術演算は (9^2) 未満の小さな値にのみ使用されるため、整数のオーバーフローは問題になりません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve_io():
    input = sys.stdin.readline

    a_len, b_len, p_len = map(int, input().split())
    A = input().strip()
    B = input().strip()
    P = input().strip()

    a_mod = 0
    for ch in A:
        a_mod = (a_mod + ord(ch) - ord('0')) % 9

    b_mod = 0
    for ch in B:
        b_mod = (b_mod + ord(ch) - ord('0')) % 9

    product_mod = (a_mod * b_mod) % 9

    known_mod = 0
    for ch in P:
        if ch != '*':
            known_mod = (known_mod + ord(ch) - ord('0')) % 9

    answer = (product_mod - known_mod) % 9
    if answer == 0:
        answer = 9

    print(answer)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve_io()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

 ## 特殊なケース

 (9) に等しい桁の欠落は、最も微妙なケースです。 考慮する：```
1 1 1
1
9
*
```製品は`9`、その剰​​余モジュロ (9) はゼロです。 既知の積の桁がないため、既知の桁の寄与もゼロになります。 アルゴリズムは計算します`missing = 0`、その剰​​余を次のように変換します。`9`。 これは正しいです。なぜなら、`0`入力保証により禁止されています。 

製品の先頭にある星は、特別な位置処理を必要としません。 のために：```
2 1 2
12
8
*6
```製品は`96`。 (12 \equiv 3 \pmod 9) と (8 \equiv 8 \pmod 9) があり、生成物剰余 (3 \times 8 \equiv 6) が得られます。 既知の数字は`6`, したがって、欠落している数字には剰余 (6-6\equiv0) があります。 その剰余を持つ唯一許可される数字は次のとおりです`9`、正しい製品を提供します`96`。 

最後のスターも同様に動作します。 のために：```
1 1 2
3
8
2*
```積剰余は (6) ですが、既知の数字は`2`(2) に貢献します。 欠落している桁は (4) であるため、アルゴリズムは次のように出力します。`4`。 

大きなオペランドは乗算せずに処理されます。 (A) に 100 万桁が含まれ、(B) に 100 万桁が含まれる場合、アルゴリズムは入力のスキャン中に (0) ～ (8) の範囲内の 2 つの残基のみを維持します。 同じ理由が、200 万近くの桁を含む積文字列にも当てはまります。 これはまさに、モジュール方式のアプローチが成功し、明示的な乗算が失敗するスケールです。
