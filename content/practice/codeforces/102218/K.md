 ## 問題の理解

 2 つの非常に大きな 10 進整数があります。`A`そして`B`、および 10 進数の文字列`P`それは彼らの製品に等しいはずです。 ちょうど 1 桁`P`に置き換えられました`*`。 欠落している数字は次のものであることが保証されています`1`を通して`9`、したがって、タスクはその数字を回復することです。 

最初の 3 つの数字は、`a`、`b`、 そして`p`、は次の桁数です。`A`、`B`、 そして`P`。 これらは整数値ではありません。 2 つの入力整数にはそれぞれ約 100 万桁を含めることができ、積には約 200 万桁を含めることができます。 元の問題には、0.5 秒の時間制限と 32 MB のメモリ制限があります。 

これらの境界は直ちに治療を除外します`A`そして`B`通常のマシン整数として。 100 万桁の値を格納または乗算する場合でも、定数時間の算術演算よりも大幅に多くの作業が必要になります。 意図したソリューションでは、10 進数文字列を直接処理し、入力桁ごとに一定量の作業のみを行う必要があり、合計入力サイズが線形的に複雑になります。 

不注意な解決策が失敗する可能性があるケースがいくつかあります。 欠落している文字が最初の桁の場合でも、算術演算に含める必要があります。 例えば、```

## アプローチ

 直接的なアプローチは、考えられる欠落している数字をすべて試してみることです。`1`を通して`9`、 交換する`*`その数字を使用して、結果の数値が正確であるかどうかを確認します`A * B`。 このメソッドは正しいです。9 つの置換のうちの 1 つが実際の積であり、ステートメントは欠落している桁がゼロ以外であることを保証しているからです。 

問題は数字の大きさです。 最も大きなケースでは、`A`そして`B`それぞれ最大で`999999`数字と`P`はほぼ 200 万桁あります。 2 つの巨大な整数を構築して乗算することは、通常の固定幅の演算をはるかに超えています。 すでに製品を持っていたとしても、製品をスキャンして 9 つの候補すべてをチェックするには、最大で 2 時間の時間がかかります。`9p`、これは最大の入力でほぼ 1,800 万文字のチェックです。 乗算自体は、単純に実装した場合よりもはるかに高価になります。 

重要な観察は、10 進数は桁の合計を通じて 9 を法とする値を保持するということです。 すべての 10 進整数に対して`X`、

 [
 X \equiv \text{の桁の合計 }X \pmod 9.
 】

 以来

 [
 P=A\cdot B、
 】

 その結果、私たちは

 [

 】

 目に見えるすべての数字`P`既知の量がその桁の合計に寄与します。 欠落している桁が`x`、その後

 (\text{数字の合計 }A\bmod9)
 (\text{数字の合計 }B\bmod9)\bmod9。

 したがって、文字列を読み取るときに 3 つの小さな残基を計算するだけで済みます。 大きな整数の乗算はまったく必要ありません。 

欠落している数字は以下に限定されます`1`を通して`9`。 これらの 9 桁には 9 を法とする 9 つの異なる剰余があるため、必要な剰余によって答えが一意に識別されます。 特に残留物`0`数字に対応する`9`。 

9 桁しか使用できないため、強引なアイデアは機能しますが、それでも巨大な積を構築または繰り返しチェックする必要がある数値として扱います。 乗算と 10 進数の合計が 9 を法としてきれいに相互作用するという観察により、大きな数の演算が完全に削除されます。

 ## アルゴリズムのチュートリアル

 1. 桁数と 3 つの文字列を読み取ります。 文字列自体がどの桁を処理する必要があるかを正確に示すため、計算にはカウントは必要ありません。 
2. 次の桁の合計を計算します。`A`最終的な方程式も 9 を法とするので、必要なのは剰余だけです。 
3. 次の桁の合計を計算します。`B`同じ理由でモジュロ 9 も同様です。 
4.スキャン`P`以外のすべての文字を追加します`*`スターは未知の値に寄与するため、ここでは省略します。 
5. 必要な生成物残差を計算します。 

[
 r=(A\bmod9)(B\bmod9)\bmod9。 
】

 1.解決する

 [
 (\text{visibleSum}+x)\bmod9=r。 
】

 候補者`x`からの一意の数字です`1`を通して`9`コードでは、これは次のように記述できます。 

[
 x=(r-\text{visibleSum})\bmod9,
 】

 続いて変更`0`に`9`。 

1. 印刷`x`。 許容される数字の中で剰余が一意であるということは、積を構築したり複数の候補をテストしたりする必要がないことを意味します。 

### なぜ効果があるのか

 不変条件は、処理されたすべての 10 進数文字列が、その文字列で表される整数とまったく同じ剰余である 9 を法とする数字の合計によってのみ表されるということです。 のために`A`そして`B`、それらの剰余を乗算して、その積の剰余を得ることができます。 のために`P`、すべての目に見える数字は既知の剰余を与え、欠落している数字は正確に寄与します。`x`。 の計算値`x`2 つの剰余が等しくなります。また、数字があるため、`1`を通して`9`9 を法とするすべての剰余を 1 回だけ表現します。`x`欠落の可能性がある唯一の桁です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum_mod9(s):
    total = 0
    for c in s:
        if c != '\n':
            total += ord(c) - ord('0')
    return total % 9

def solve():
    a, b, p = map(int, input().split())
    A = input().strip()
    B = input().strip()
    P = input().strip()

    ra = digit_sum_mod9(A)
    rb = digit_sum_mod9(B)

    visible = 0
    for c in P:
        if c != '*':
            visible += ord(c) - ord('0')
    visible %= 9

    required = (ra * rb) % 9
    answer = (required - visible) % 9

    if answer == 0:
        answer = 9

    print(answer)

if __name__ == "__main__":
    solve()
```ヘルパーさん`digit_sum_mod9`10 進数の文字列を整数に変換するのではなく、文字ごとに処理します。 これが必要なのは、入力整数には通常のマシン整数サイズをはるかに超える約 100 万桁が含まれる可能性があるためです。 

のために`P`、コードはスキップするだけです`*`。 実際のすべての桁は、表示される桁の合計に含まれます。 の使用`ord(c) - ord('0')`変換を繰り返すことで一時的な整数オブジェクトが作成されることを回避し、計算を単純に保ちます。 

表現`(required - visible) % 9`からの値を与えます`0`を通して`8`。 それが与えられるなら`1`を通して`8`、その値はすでに対応する欠落桁です。 それが与えられるなら`0`、欠落している数字は次のとおりである必要があります。`9`、 なぜなら`0`問題によって明示的に除外されます。 

すべての実行合計は、完全な文字列ごとに 9 を法として減算されるため、整数オーバーフローの問題は発生しません。`visible`総額はせいぜい1800万程度。 さらに重要なのは、コードは決して構築されないということです。`A * B`。

import sys
import io

def solve():
    input = sys.stdin.readline

    a, b, p = map(int, input().split())
    A = input().strip()
    B = input().strip()
    P = input().strip()

    for c in A:
        ra = (ra + ord(c) - 48) % 9

    rb = 0
    for c in B:

    for c in P:

        solve()
        return sys.stdout.getvalue().strip()
    finally:

        sys.stdout = old_stdout
