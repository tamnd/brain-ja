 ## 解決策
 ## 問題の理解

 英語の小文字の文字列が与えられており、その文字を任意の順序で並べ替えることができます。 アランは辞書編集上の最小の文字列から最大の文字列に向かって辞書を検索するため、最良の贈り物は、その順序のできるだけ早くに表示される並べ替えです。 

辞書編集的に最小の並べ替えは、単純にすべての文字をアルファベットの昇順に配置した文字列です。 たとえば、のキャラクター`mac`次のような文字列にのみ再配置できます。`mac`、`mca`、`amc`、などなど、`acm`辞書順ではそれらの最初のものです。 

長さは (10^7) に達する可能性があり、これは、約 1 秒の制限時間内で高価なアルゴリズムが快適に使用できるサイズよりもはるかに大きくなります。 (O(N^2)) アルゴリズムは上限で約 (10^{14}) 回の演算を必要とし、(O(N!)) 列挙はそれをはるかに超えます。 比較ベースの (O(N\log N)) 並べ替えでも、(N=10^7) の場合、数億回のオーダーで実行されます。 重要な追加情報は、すべての文字が 26 個の小文字のみからなるアルファベットに属しているということです。 

最初のエッジ ケースは 1 文字の文字列です。 入力用`1`に続く`z`、答えはまだです`z`。 再配置するものは何もなく、少なくとも 2 文字を想定する実装では不要な境界エラーが発生する可能性があります。 

2 番目の特殊なケースは、文字が繰り返されることです。 入力用`5`に続く`aaaaa`、答えは`aaaaa`。 等しい文字を個別のオブジェクトとして扱う不注意な実装では、結果にはまったく同じ 5 つのコピーが含まれている必要があるにもかかわらず、冗長な作業が実行される可能性があります。 

3 番目のエッジ ケースは、最小の文字が複数回出現する混合です。 入力用`6`に続く`zzabca`、答えは`aabcz z`、 または`aabczz`スペースなしで。 二人`a`両方の文字は、すべての大きな文字の前に来る必要があります。 最小の文字を 1 回だけ移動する実装では、間違った順序が生成されます。 

## アプローチ

 直接的な総当たりアプローチでは、文字列の可能なすべての再配置が生成され、それらが比較され、辞書編集上最も小さいものが保持されます。 すべての文字が異なる場合、(N!) 個の順列が存在します。 2 つの文字列を比較すると、最大 (N) 文字まで検査できるため、最悪の場合の作業は (O(N\cdot N!)) になります。 (N=10^7) では、これらの順列の最初の小さな部分を書き留めることさえ不可能です。 文字が繰り返されると個別の順列の数が減りますが、最悪の場合でも原理的にはすべての文字が異なるため、入力アルファベットの制限によって大きい (N) 場合の順列の列挙が救済されません。 

より賢明な汎用アプローチは、比較ソートです。 文字を昇順に並べ替えると、結果はまさに辞書編集上最小の並べ替えになります。 標準の比較並べ替えでは (O(N\log N)) 回の比較が行われます。 それは正しいのですが、制約 (N\le 10^7) により、特に元の問題で使用されている 1.25 秒の制限の下では、余分な対数係数が不必要に高価になります。 

重要な観察は、使用可能な文字が 26 個しかないということです。 アルファベット順はすでにわかっているため、何百万もの個々の文字の相対的な順序を発見する必要はありません。 何個数えるだけでいいのです`a`キャラクターは存在しますが、何人いますか`b`キャラクターが存在するなど`z`。 これら 26 個の周波数がわかったら、数えた回数だけ各文字をアルファベット順に書くことで答えが得られます。 

これは、最も単純な形式でのカウントソートです。 順序がすでにわかっている文字を比較するために (O(N\log N)) を支払う代わりに、入力を 1 回スキャンし、26 個のカウンターの固定配列を使用します。 答えの構築にも (O(N)) がかかるため、アルゴリズム全体は線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての再配置を列挙する | (O(N\cdot N!)) | (O(N)) | 遅すぎる |
 | 比較ソート | (O(N\log N)) | (O(N)) | 不必要に高価 |
 | 文字数を数える | (O(N)) | (O(N)) 入出力、(O(26)) 補助 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (N) と文字列 (S) を読み取ります。 (N) の値は予想される文字数を示しますが、実際の文字列には再配置する必要がある文字が含まれています。 
2. 小文字ごとに 1 つずつ、計 26 個のカウンターを作成します。 (S) の文字ごとに、そのアルファベットの位置に対応するカウンタをインクリメントします。 可能な位置は 26 個しかないため、各文字は一定時間内に分類できます。 
3. 26 個のカウンターを通過します。`a`を通して`z`。 頻度 (f) の文字の場合、その文字を結果に正確に (f) 回追加します。 辞書編集上最小限の文字列では、小さい文字のすべてのコピーが、大きい文字のすべてのコピーの前に置かれなければなりません。 
4. 結果の文字列を書き込みます。 すべての入力文字は 1 回だけカウントされ、その後 1 回だけ出力されるため、出力は元の文字列を再配置したものになります。 

### なぜ効果があるのか

 カウント後、アルゴリズムは入力内に各文字のコピーが何回出現するかを正確に把握します。 結果の文字列には、小さな文字の前に大きな文字があったとします。 これら 2 つの位置を交換すると、すべての文字の頻度を維持しながら、文字列が辞書編集的に小さくなります。 したがって、このような反転は辞書編集上の最小の並べ替えでは発生しません。 このような逆転のない唯一の配置は、すべてが`a`文字が最初に来て、その後にすべての文字が来ます`b`キャラクターなどを通じて`z`。 アルゴリズムはまさにその配置を構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    count = [0] * 26

    for ch in s:
        count[ord(ch) - ord('a')] += 1

    result = []
    for i, freq in enumerate(count):
        if freq:
            result.append(chr(ord('a') + i) * freq)

    sys.stdout.write(''.join(result))

if __name__ == "__main__":
    solve()
```最初の行は宣言された長さを読み取りますが、入力が読み取られた後、アルゴリズムはそれを使用する必要はありません。 値を保持すると、入力形式と一致させるのに役立ちますが、実際の文字列を反復処理することで、ステートメントの保証を超える行境界についての仮定を回避できます。 

表現`ord(ch) - ord('a')`小文字を 0 ～ 25 のインデックスに変換します。たとえば、次のようになります。`a`0になり、`b`が 1 になり、`z`したがって、文字列に 10 文字が含まれるか、1000 万文字が含まれるかに関係なく、カウンター配列には 26 エントリだけが必要です。 

結果は次のようなブロックから構築されます。`a * 3`または`m * 2`。 文字列の連結を繰り返すと不必要なコピーが作成される可能性があるため、これは一度に 1 文字ずつ繰り返し連結するよりも望ましい方法です。 リストには最大 26 個の文字列が含まれており、`''.join(result)`それらを最終出力に一度結合します。 

Python では整数がオーバーフローできません。 最大のカウンターは (10^7) のみで、これは Python 整数で簡単に表現できます。 

の`.strip()`呼び出しは、によって生成された改行を削除します`readline()`。 入力には小文字のみが含まれるため、保持する必要がある意味のあるスペースはありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N)) | 入力は 1 回スキャンされ、26 個のカウンターが一定のアルファベット サイズで出力されます。 |
 | スペース | (O(N)) | 入力文字列とその結果の出力は線形空間を占有しますが、周波数配列は 26 個のカウンターのみを使用します。 |

 (N) が (10^7) と同じくらい大きい場合、線形処理が適切なターゲットになります。 このアルゴリズムは、入力文字ごとに一定量の作業を実行し、可能な順列の数に比例したデータ構造を割り当てることはありません。 補助カウント状態は 26 エントリに固定されたままであり、元の 64 MB のメモリ制限に特に適しています。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    count = [0] * 26

    for ch in s:
        count[ord(ch) - ord('a')] += 1

    result = []
    for i, freq in enumerate(count):
        if freq:
            result.append(chr(ord('a') + i) * freq)

    sys.stdout.write(''.join(result))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("3\nmac\n") == "acm", "sample 1"
assert run("4\ngeso\n") == "egos", "sample 2"

# Minimum-size input
assert run("1\nz\n") == "z", "single character"

# All characters are equal
assert run("7\naaaaaaa\n") == "aaaaaaa", "all equal"

# Boundary alphabet characters and repeated letters
assert run("8\nzzzzaaaa\n") == "aaaazzzz", "alphabet boundaries"

# Maximum-size input
s = "a" * 10_000_000
assert run(f"{len(s)}\n{s}\n") == s, "maximum size"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`/`z`|`z`| 最小サイズと再配置なしのケース |
 |`7`/`aaaaaaa`|`aaaaaaa`| 繰り返される文字と頻度のカウント |
 |`8`/`zzzzaaaa`|`aaaazzzz`| アルファベットの最小文字と最大文字 (繰り返しブロックを含む) |
 |`10000000`/千万`a`キャラクター | 同じ1000万でも`a`キャラクター | 最大入力サイズと線形処理 |

 最大サイズのアサーションは、文字通り 1,000 万文字の行として記述されるのではなく、意図的に構築されます。 実際のコンテストの提出では、そのデータを含める必要があるのは審査員の入力のみであり、テストでは同じ境界条件がプログラムで表現されます。 

## 特殊なケース

 1 文字の場合は次を考慮してください。```
1
z
```のカウンター`z`は 1 になり、他のすべてのカウンタは 0 のままになります。 放出フェーズでは空の文字がスキップされ、1 つの文字が出力されます。`z`。 2 番目の文字のインデックスは作成されないため、(N=1) の境界は自然に処理されます。 

文字が繰り返される場合は、次の点を考慮してください。```
5
aaaaa
```すべての反復で同じカウンターがインクリメントされ、残りは`count['a'] = 5`。 出力位相が放射します`a * 5`、生産`aaaaa`。 周波数表現はすでに答えに関連する状態全体を捉えているため、個別の置換ロジックは必要ありません。 

最小文字と大きな文字が混在して繰り返される場合は、次の点を考慮してください。```
6
zzabca
```カウンターは、`a:2`、`b:1`、`c:1`、 そして`z:2`。 放出順序は`aa`、 それから`b`、 それから`c`、 それから`zz`、生産:```
aabczz
```たったひとつから始まる並べ替え`a`、 のような`abaczz`、別の理由により最適化することはできません`a`が存在し、最初の直後に配置します`a`文字列を小さくします。 

アルファベットの境界の場合については、次のことを考慮してください。```
4
zaba
```周波数は次のとおりです。`a:2`、`b:1`、 そして`z:1`。 アルゴリズムは、`a`最初にブロックしてから`b`、 それから`z`、生産:```
aabz
```これは、アルゴリズムが入力順序に依存せず、小文字のアルファベットの両端を正しく処理することを確認します。 

最大サイズの場合もまったく同じロジックに従います。 すべての (10^7) 文字が`a`、スキャンは (10^7) 定数時間カウンタの増分を実行し、出力フェーズは (10^7) 文字の 1 ブロックを出力します。 並べ替えの手順や配置を列挙する試みがないため、実行時間は実際の入力サイズに比例して増加します。
