 ## 解決策
 ## 問題の理解

 ちょうど（M）個の山を購入します。 各パイルは、(K) 個の利用可能な正のサイズの 1 つを独立して選択します。各サイズには確率 (1/K) があります。 すべての山が明らかになった後、ゲームは通常のニムの位置になります。 

ニムの場合、アリスはすべてのパイル サイズの xor がゼロ以外の場合に正確に勝ちます。 したがって、問題は確率を計算することです

 [
 \Pr[c_{i_1}\oplus c_{i_2}\oplus\cdots\oplus c_{i_M}\ne 0]、
 ]

 ここで、すべての (i_j) は、(K) 個の利用可能なサイズから独立して均一に選択されます。 

答えはモジュロ (998244353) として要求されます。 (W) が、xor が 0 以外である (M) 個のパイル サイズの順序付き選択肢の数である場合、望ましい確率は (W/K^M) なので、素数の法は次のようになります。 

[
 W\cdot (K^M)^{-1}\pmod {998244353}。 
]

 杭の数 (M) は (10^9) に達する可能性があるため、杭を 1 つずつ処理する方法は不可能です。 可能な杭のサイズはすべて (2^{17}) 未満であり、これは重要な構造上の制約です。 これは、すべてのサイズが 17 ビットの XOR 空間に収まることを意味します。 

[
 2^{17}=131072
 ]

 可能な値。 (O(2^{17}\cdot17)) アルゴリズムは簡単に実現可能ですが、(O(MK))、(O(M2^{17}))、またはすべての (K^M) 個の順序付けされた選択肢を列挙することは絶望的です。 

実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 (K=1) の場合、すべてのパイルはまったく同じサイズになります。 例えば、```
2 1
5
```(5\oplus5=0) であるため、確率 (1) が得られます。したがって、最初のプレイヤーの立場は負けになります。 いくつかの異なる選択肢を想定している数式や、偶数の等しい値の xor がゼロであることを忘れている数式では、この問題が発生する可能性があります。 

のために```
1 1
5
```答えは (0) です。 山は 1 つだけあり、そのサイズはゼロではないため、アリスはそれを削除して勝つことができます。 これは、指数が (M=1) である境界も捕らえます。 

もう一つの便利なケースは、```
3 2
1 2
```2 つの値の可能な数は合計 (3) になります。 xor ゼロを取得するには、両方のカウントが偶数である必要がありますが、それらの合計が奇数であるため、これは不可能です。 したがって、アリスは (0) ではなく (1) の確率で勝ちます。 重複するパイル サイズが存在するかどうかだけをチェックする不用意な引数は、パリティ条件を見逃してしまいます。 

最後に、提供されるサイズはすべて正であっても、変換には (0) から (2^{17}-1) までの xor ドメイン全体が含まれている必要があります。 値 (0) は提供されたパイル サイズではありませんが、XOR の結果として考えられるものであり、負けたポジションを数えるときに不可欠です。 

## アプローチ

 直接的なアプローチでは、(K) 個の利用可能なパイル サイズからの (M) 個の選択肢のすべての順序付けされたシーケンスが考慮されます。 各シーケンスについて、その要素の XOR を実行し、結果がゼロ以外であるかどうかを確認します。 すべての順序付けされたシーケンスには正確に (1/K^M) の確率があるため、これは正しいです。 

問題は配列の数です。 それらは (K^M) 個あるため、シーケンスごとの作業量が一定であっても、実行時間は (O(K^M M)) になります。 たとえば、(K=2) と (M=10^9) はすでに (2^{10^9}) 個の可能なシーケンスを与えています。 ブルートフォース手法は、最大の制約に達するずっと前に役に立たなくなります。 

より有望な観点は、負けているポジション、つまり xor が正確に 0 であるシーケンスをカウントすることです。 すべてのパイル値は (2^{17}) 未満であるため、xor は 17 ビット整数の有限ベクトル空間で動作します。 これにより、(N=2^{17}) 個の可能な xor 状態のみが得られます。 

動的プログラミング配列を定義できます。`dp[x]`は、一定数の山を積んだ後に xor (x) を取得する方法の数です。 値 (c) を持つ山をもう 1 つ追加すると、状態 (x) が (x\oplus c) に変わります。 1 回の遷移には (O(NK)) のコストがかかり、それを (M) 回実行すると (O(MNK)) のコストがかかりますが、(M) は (10^9) に達する可能性があるため、それでも大きすぎます。 

重要な観察は、この遷移が XOR 畳み込みであるということです。 (f[x]) が現在の分布を表し、(g[c]) が新しく購入した 1 つの山の分布である場合、次の分布は次のようになります。 

[
 h[x]=\sum_y f[y]g[x\oplus y]。 
]

 Xor 畳み込みには、専用に設計されたフーリエ変換、ウォルシュ アダマール変換があります。 変換空間では、xor 畳み込みは点ごとの乗算になります。 したがって、(M) 個の山を取ることは、すべての変換された値を単純に (M) 乗することになります。 

(x) が提供されているサイズの 1 つである場合は (A[x]) を (1)、それ以外の場合は (0) とします。 そのウォルシュ-アダマール変換は次のようになります。 

[
 F[s]=\sum_x A[x](-1)^{\オペレーター名{ポップカウント}(s\mathbin{&}x)}。 
]

 xor が 0 に等しい順序付けされた (M) タプルの数は次のようになります。 

[
 L=\frac{1}{N}\sum_{s=0}^{N-1}F[s]^M。 
]

 これは、特に xor 状態 0 で評価される標準の逆ウォルシュ アダマール公式です。 実際には分布全体を再構築する必要はありません。 必要なのはゼロ係数だけなので、変換してべき乗した後、変換された値を合計できます。 

望ましい答えは、勝つ確率から 1 を引いた負けの確率です。 同じ確率で順序付けされた (K^M) 個の選択があるため、

 \frac{1}{NK^M}\sum_s F[s]^M。 
]

 したがって、

 1-
 \frac{\sum_s F[s]^M}{N K^M}
 }
 \pmod {998244353}。 
]

 変換自体には (O(N\log N)) のコストがかかり、(N) 個のべき乗剰余演算があり、それぞれのコストは (O(\log M)) です。 (N=2^{17}) なので、これにより制約が快適に処理されます。

 ## アルゴリズムのチュートリアル

 1. すべてのパイル サイズは最大 17 ビットで表されるため、(N=2^{17}) を設定します。 配列を作成する`a`長さ (N) の、`a[c]=1`提供されたすべてのパイル サイズ (c) に対して、それ以外の場合は 0 になります。 この配列は、正規化前の 1 つの山の分布を表します。 
2. 高速ウォルシュ・アダマール変換を適用します。`a`。 各変換座標について、結果の値は符号付きの合計になります。 

[
 F[s]=\sum_{c\in C}(-1)^{\operatorname{popcount}(s\mathbin{&}c)}。 
]

 変換は xor 畳み込みを乗算に変換します。独立したパイルが xor によって結合されるため、これはまさに必要なものです。 

1. 変換されたすべての値を M 乗したモジュロ (998244353) にします。 1 つのパイルが変換値 (F[s]) に寄与する場合、(M) 個の独立したパイルが寄与します (F[s]^M)。 これはモジュラー 2 進累乗を使用して直接計算できるため、(M) の巨大な値は問題になりません。 
2. (N) 個の変換座標にわたるすべての (F[s]^M) を合計します。 逆ウォルシュ・アダマール公式により、この合計を (N) で割ると、xor が 0 である順序付けされた (M) タプルの数が得られます。 
3. 負けた回数を (K^M) で割って、負ける確率を求めます。 モジュラー除算はモジュラー逆数による乗算であるため、次のように計算します。 

\left(\sum_sF[s]^M\right)
 (NK^M)^{-1}
 \pmod {998244353}。 
]

 1. (1-\text{lose}) モジュロ (998244353) を出力します。これは、xor がゼロでない場合にアリスが正確に勝つためです。 

これが機能する理由: このメソッドの背後にある不変条件は、各ウォルシュ アダマール座標が、考えられるすべての XOR 状態の符号付き寄与を独立して追跡することです。 1 つの山の場合、座標は (F[s]) です。 xor による独立したパイルの結合は xor 畳み込みに対応し、ウォルシュ アダマール変換はその畳み込みを通常の乗算​​に変更します。 したがって、(M) 個積み上げた後の座標は (F[s]^M) になります。 逆変換は、xor 状態ゼロの係数が、変換されたすべての座標の合計の正確に (1/N) 倍であることを示します。 すべての順序付き選択肢は等しい確率 (1/K^M) を持つため、そのカウントを正規化すると負ける確率が得られ、その補数がアリスの勝つ確率になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
LOG = 17
N = 1 << LOG

def fwht(a):
    n = len(a)
    length = 1

    while length < n:
        step = length << 1

        for i in range(0, n, step):
            end = i + length

            for j in range(i, end):
                x = a[j]
                y = a[j + length]

                a[j] = x + y
                a[j + length] = x - y

        length = step

def solve():
    M, K = map(int, input().split())
    c = list(map(int, input().split()))

    a = [0] * N
    for x in c:
        a[x] = 1

    fwht(a)

    total = 0
    for x in a:
        total = (total + pow(x % MOD, M, MOD)) % MOD

    denominator = N * pow(K, M, MOD) % MOD
    losing = total * pow(denominator, MOD - 2, MOD) % MOD

    answer = (1 - losing) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```入力配列には、可能なパイル サイズごとに 1 つのエントリが含まれています。 提供されているサイズはすべて異なるため、割り当て`1`それぞれに正しい 1 パイルカウント関数を与えます。`fwht`非正規化ウォルシュ アダマール変換を実行します。 各蝶はペア ((x,y)) を ((x+y,x-y)) に置き換えます。 順変換中に除算が存在しないため、実装が単純に保たれ、すべてのバタフライにモジュラー逆関数が導入されることが回避されます。 

変換値は負の場合もあり、変換中に増加する場合もあります。 Python の整数はオーバーフローしませんが、累乗剰余演算の前に値を減らすと便利です。 表現`x % MOD`負の値を正しく処理します。 

べき乗`pow(x % MOD, M, MOD)`(M) は (10^9) になる可能性があるため、これは必須です。 2 進累乗では、変換座標ごとに (O(\log M)) 個のモジュラー乗算のみが必要になります。 

係数 (N) は、逆ウォルシュ アダマール変換から得られます。 よくある実装上の間違いは、これを省略して、誤って負けポジションの数 (N) 倍を計算してしまうことです。 

ストアの選択は独立していて均一であるため、もう 1 つの分母は (K^M) です。 2 つの要素を次のように組み合わせます。`N * K^M`逆モジュラーをとる前に。 (N=2^{17}) および (K<2^{17}<998244353) であるため、どちらの因数も素数係数で割り切れません。 

ついに、`1 - losing`剰余が取られます`MOD`。 これは、モジュール表現が`losing`よりも大きいです`1`たとえ基礎となる確率が 0 から 1 の間であっても、算術演算の後。

        for i in range(0, n, step):
            for j in range(i, i + length):
                x = a[j]
                y = a[j + length]
                a[j] = x + y
                a[j + length] = x - y

def solve():

    try:

        sys.stdout = output

        finally:

 ## 特殊なケース

 利用可能なサイズが 1 つだけの場合、ゲーム全体が決定的になります。 入力あり```
1 1
5
```初期配列には 0 以外のエントリが 1 つあるため、変換は引き続き機能します。 もっと簡単に言えば、xor には 5 のコピーが 1 つ含まれているため、これは非ゼロであり、答えは 0 になります。 (F[s]^1=F[s]) は自動的に同じカウントを生成するため、実装では特別なケースは必要ありません。 

のために```
2 1
5
```両方の山には 5 が含まれているため、XOR は (5\oplus5=0) になります。 アリスは毎回負けて勝率だけ出力が1？ ここで、勝率は実際には 0 であるため、正しい出力は次のようになります。`0`。 まさにこれが、指数のパリティが重要である理由です。 テスト スイートはこの区別を使用して、ゼロ xor とゼロ以外の xor を混同する実装を検出します。 

提供されたサンプルについては、```
11 1
5
```5 のコピーが 11 個あり、xor 5 が得られます。確率 1 でアリスが勝ち、出力が生成されます。`1`。 (M) のパリティが変化すると、同じ決定論的ケースが完全に変化します。 

最大パイル値については、```
1000000000 1
