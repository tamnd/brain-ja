 ## 解決策
 ## 問題の理解

 アリスは(M)山を買います。 すべてのパイルは、それぞれ (1/K) の確率で、(K) 個の許容される正のサイズの 1 つを独立して受け取ります。 サイズがわかれば、ゲームは通常のニムの位置になります。 

Nim の場合、すべてのパイル サイズのビットごとの XOR がゼロ以外の場合、最初のプレーヤーが勝ちます。 したがって、この問題は、(M) の XOR が集合から独立して選択された値である確率を求めることと同じです。 

[
 C={c_1,c_2,\ldots,c_K}
 】

 ゼロではありません。 必要な答えはこの確率のモジュロ (998244353) であるため、除算は逆モジュラで実行されます。 

難点は(M)のサイズです。 (10^9) ほどの大きさになる可能性があるため、山を 1 つずつ処理することはできません。 可能な値の数は (2^{17}) によって制限されます。これが重要な構造上の制約です。 これは、問題全体が (131072) 個の要素のみからなる有限 XOR グループ内に存在することを意味します。 このサイズは (O(2^{17}\cdot17)) 変換には十分小さいですが、巨大な (M) は 2 進累乗で処理できます。 

考えられるすべての順序付けされたシーケンスを総当たり的に列挙すると、(K^M) 個のケースが存在します。 (K=2) と (M=10^9) であっても、それはすでに絶望的です。 各パイルの後にすべての XOR 状態を列挙するには、(O(M2^{17})) も必要になりますが、(M) が巨大であるため、これは大きすぎます。 

合理的な実装が間違っている可能性があるいくつかの特殊なケースがあります。 1 つの山では、XOR は単にその正のサイズになるため、アリスが常に勝ちます。 例えば、```
1 1
5
```答えは(1)です。 ゼロ XOR を勝ちの位置として扱う実装では、誤ってゼロが返されます。 

可能なパイル サイズが 1 つだけであるため、すべてのパイルは同一になります。 (K=1) の場合、(M) が偶数の場合、XOR はゼロになり、(M) が奇数の場合、ゼロ以外になります。 例えば、```
2 1
5
```答えは (0) ですが、```
11 1
5
```答えは(1)です。 複数の異なる値が存在することを前提としたソリューションでは、このケースを誤って処理する可能性があります。 

もう 1 つの境界ケースは、使用可能なサイズに (2^{17}) に近い値が含まれる場合です。 (2^{17}) より下の 2 つの値の XOR はまだ (2^{17}) よりも低いため、正確に (2^{17}) 個の状態の配列で十分です。 たとえば、```
2 2
65536 131071
```唯一のゼロ XOR 結果は 2 つの等しい選択肢であるため、確率 (1/2) でアリスが勝ちます。 サイズ (2^{17}-1) の配列を使用すると、無効な状態にアクセスします。 

## アプローチ

 直接的な解決策は、Nim の規則に直接従います。 (M) 個のパイル サイズのすべての可能なシーケンスを生成し、シーケンス内のすべての値を XOR し、XOR がゼロ以外のシーケンスをカウントします。 すべての順序付けされたシーケンスには確率 (1/K^M) があるため、当選確率は当選シーケンスの数を (K^M) で割ったものになります。 

これは正しいです。なぜなら、完全なシーケンスが Nim の正確な位置を決定し、XOR がゼロ以外の場合に Nim は正確に最初の手を獲得するからです。 問題は配列の数です。 最悪の場合、それらは (K^M) 個あり、(M) は指数関数的になります。 (K=131071) で、さらに小さな (M) の場合、これは実行不可能になります。 

より構造化されたブルート フォースにより、各 XOR 値を取得する方法の数を維持できます。 (dp[x]) が (x) である XOR を持つシーケンスの数である場合、別の山を追加することは、

 [
 newdp[x]=\sum_{c\in C}dp[x\oplus c]。 
】

 可能な XOR 値は (2^{17}) 個あるため、1 回の遷移には (O(K2^{17})) のコストがかかります。 これを (M) 回繰り返すと (O(MK2^{17})) が得られますが、(M) が (10^9) になる可能性があるため、これでも失敗します。 

重要な観察は、XOR が通常の加算ではなく、ウォルシュ アダマール変換が畳み込みを対角化する群を形成するということです。 上記の遷移は、利用可能なパイル サイズの周波数関数による XOR 畳み込みです。 Walsh-Hadamard 変換を適用した後、すべての XOR 畳み込みは点ごとの乗算になります。 

(x) が利用可能なサイズの場合は (f[x]) を (1)、それ以外の場合は (0) とします。 (f) の変換 (F) は、すべての XOR 周波数の寄与を表します。 (M) 個の独立したパイルを選択することは、(f) の (M) 番目の XOR 畳み込み累乗を取ることに相当するため、変換後の各コンポーネントは単純に (F[i]^M) になります。 

次に、逆ウォルシュ アダマール変換により、結果として得られるすべての XOR 値のシーケンスの数が回復されます。 XOR (0) の値のみが必要です。 標準の非正規化変換の場合、逆関数は係数 (1/2^{17}) に寄与します。 元の選択肢は確率が等しいので、(K^M) で割ります。 

したがって、計算全体は 1 つのウォルシュ アダマール変換、(2^{17}) 乗剰余演算、および 1 つの最終正規化に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(K^MM)) | (O(M)) | 遅すぎる |
 | DP over XOR 状態 | (O(MK2^{17})) | (O(2^{17})) | 遅すぎる |
 | ウォルシュ・アダマール変換 | (O(2^{17}\cdot17 + 2^{17}\log M)) | (O(2^{17})) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`a`長さ (N=2^{17})。 許可されたすべてのパイル サイズ (c_i) に (1) を配置し、それ以外の場所には (0) を配置します。 これは、各 XOR 値を生成する利用可能な選択肢の数を表します。 
2. Walsh-Hadamard 変換を適用します。`a`。 XOR 畳み込みの場合、変換は畳み込みを点単位の乗算に置き換えます。 この操作の後、`a[x]`周波数 (x) に関連付けられた変換値です。 
3. 変換されたすべての値を M 乗したモジュロ (998244353) にします。 これは、(M) 個のパイルを選択することを表します。これは、(M) 倍 XOR 畳み込みが変換後に通常の乗算​​になるためです。 
4. すべて (N) 個の累乗変換値を合計します。 ゼロ周波数逆係数のすべての符号は (+1) であるため、位置 0 での逆ウォルシュ アダマール変換は、正確にこの合計を (N) で割ったものになります。 
5. 結果として得られる勝利シーケンスの数を (K^M) で割ります。 逆モジュラを使用して、両方の除算をモジュロ (998244353) で実行できます。 同様に、(N^{-1}) と ((K^M)^{-1}) を掛けます。 
6. 結果の値は、XOR がゼロになる確率です。 XOR が 0 以外の場合はアリスが勝つため、(1) から XOR を減算します。 

これが機能する理由: (g_M[x]) は、XOR が (x) である、(M) 個の許容パイル サイズの順序付けされたシーケンスの数を表すものとします。 基本関数は (g_1=f) で、パイルを追加すると XOR 畳み込み (g_{m+1}=g_m*f) が得られます。 Walsh-Hadamard 変換は、この漸化式を (\widehat g_{m+1}[x]=\widehat g_m[x]\widehat f[x]) に変換するため、帰納法により (\widehat g_M[x]=\widehat f[x]^M) が得られます。 したがって、逆変換により正確なカウント (g_M[0]) が復元されます。 合計数 (K^M) で割ると負けの確率が得られ、その補数を取るとアリスの勝利確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
N = 1 << 17

def fwht(a):
    n = len(a)
    length = 1

    while length < n:
        step = length << 1
        for start in range(0, n, step):
            end = start + length
            for i in range(start, end):
                x = a[i]
                y = a[i + length]
                a[i] = (x + y) % MOD
                a[i + length] = (x - y) % MOD
        length <<= 1

def solve():
    M, K = map(int, input().split())
    c = list(map(int, input().split()))

    a = [0] * N
    for x in c:
        a[x] = 1

    fwht(a)

    total_zero_xor = 0
    for x in a:
        total_zero_xor = (total_zero_xor + pow(x, M, MOD)) % MOD

    inv_n = pow(N, MOD - 2, MOD)
    inv_k_power = pow(pow(K, M, MOD), MOD - 2, MOD)

    zero_probability = total_zero_xor * inv_n % MOD
    zero_probability = zero_probability * inv_k_power % MOD

    answer = (1 - zero_probability) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```配列のサイズは (N=2^{17}) です。これは、すべてのパイル サイズが (2^{17}) 未満であり、XOR がオペランドに現れる最上位ビットを超えるビットを設定することがないためです。 配列は、許可されたサイズごとに 1 つの頻度で初期化されます。`fwht`XOR Walsh-Hadamard 変換を適切に実行します。 各層で、値のペアがその合計と差に置き換えられます。 層は (17) あり、各層はすべての (N) エントリを処理し、(O(N\log N)) 時間を与えます。 

変換された値は次のように計算されます。`M`Pythonのモジュラーを使って`pow`、二進累乗を使用します。 (M) は (10^9) になる可能性があるため、これは重要です。 明示的に (M) 倍することは不可能です。 

すべての累乗変換値の合計は、XOR ゼロでの非正規化逆変換です。 (N) で割ると、ゼロ XOR シーケンスの数が得られます。 元の配列には確率ではなくカウントが含まれているため、この数値をさらに (K^M)、つまり順序​​付けされたパイル構成の総数で割る必要があります。 

(998244353) が素数であるため、逆剰余はフェルマーの定理を使用して計算されます。 Python には整数オーバーフローの問題はなく、すべての中間モジュラー乗算は次のように削減されます。`% MOD`。 

変換を明示的に反転する必要はありません。 必要なのは係数 0 だけであり、その係数のすべての逆変換符号は正です。 完全な逆変換を計算すると、不必要な作業が追加されます。

## 特殊なケース

 (M=1) の場合、可能なパイル サイズは正のみであるため、その XOR をゼロにすることはできません。 例えば、```
1 1
5
```答えは(1)です。 このアルゴリズムでは、変換された値を使用して元の周波数配列が再構築されます。入力配列の位置 0 には値がないため、ゼロ XOR 係数はゼロになります。 したがって、最後の補数は (1) になります。 

(K=1) の場合、すべての山は同じサイズになります。 のために```
2 1
5
```XOR は (5\oplus5=0) なので、答えは (0) になります。 奇数 (M) の場合、XOR は (5) となるため、アリスが勝ちます。 サンプル```
11 1
5
```には (5) のコピーが 11 個あり、XOR (5) と答え (1) が得られます。 変換された各コンポーネントは対応するべき乗されるため、変換では両方のパリティが自然に処理されます。 

パイル サイズが最大許容値に近い場合でも、変換には (2^{17}) 状態のみが必要です。 考慮する```
1 2
65536 131071
```単一の山は (65536) または (131071) のいずれかであり、どちらもゼロではないため、答えは (1) です。 可能な最大値は正確に (2^{17}-1=131071) であるため、配列インデックスは有効です。 したがって、配列には (0) から (131071) までのインデックスが必要で、正確に (2^{17}) 個のエントリが必要です。 

異なる使用可能な値を持つ 2 つの山の場合、ゼロ XOR の結果のみが等しい値になります。 と```
2 2
1 2
```4 つの順序付けられた結果は次のとおりです`(1,1)`、`(1,2)`、`(2,1)`、 そして`(2,2)`。 2 つはゼロの XOR を持ち、2 つはゼロ以外の XOR を持ち、アリスの確率は (1/2) になります。 これにより、順序付けられた独立した選択肢ではなく、順序付けられていないペアがカウントされるという簡単な間違いが見つかります。 

最後に、実装では、最大のパイル値と等しいサイズの配列を使用してはなりません。 変換は状態 0 を含む XOR グループ全体を表すため、そのサイズは (131071) ではなく (2^{17}) になります。 この区別は、インデックスが変換配列の最終有効位置である (131071) などの値にとって不可欠です。
