 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、`n`～のラベルが付いたカード`1`に`n`。 最初はすべてのカードは黒です。 私たちは一連の操作を実行することが許可されており、各操作では 1 枚の黒いカードが永続的に赤く塗られます。 目標は正確にペイントすることです`n − 1`カードは赤で、最後に黒いカードが 1 枚残ります。 

カード`i`別のカードが存在する場合にのみ赤く塗ることができます`j`そこはまだ黒い、そしてそこからの円形の歩道にある`i`に`j`どちらの方向にも、他の 2 枚のカードを通過するパスが 1 つだけあります。`i`そして`j`。 円で言えば、この条件は次のように言うのと同じです。`i`そして`j`はサイクルに沿って距離 3 にあります。これは、それらの間にちょうど 2 つの中間位置があることを意味します。 

したがって、それぞれの動きは、円に沿って 3 つのステップで区切られた黒のペアの存在によって制約され、そのような有効なペアのどちらかの端点を削除することができます。 

削除するたびに黒のカードのセットが減り、今後の有効な動きがどのような構造が残っているかによって決まるため、このプロセスは動的です。 実現可能性に加えて、削除されたインデックスの辞書編集上最小のシーケンスも出力する必要があります。 

制約により、最大で次のことが許可されます。`10^5`テストケースと合計`n`まで`5 × 10^5`。 これにより、強制的に`O(n)`または`O(n log n)`テストごとに二次関数を作成すると、すぐに制限時間を超えてしまいます。 

微妙な失敗例が小さな周期で現れます。 のために`n = 4`、最初に有効なペアは次のとおりです。`(1, 4)`ただし、1 つの端点を削除すると、残りの 3 つのノードが三角形を形成し、円周距離 3 に 2 つのノードが存在しなくなるため、それ以上の操作はできなくなります。 したがって、私たちは到達することができません`n − 1`撤去。 

のために`n = 5`、最初は有効なペアが存在しますが、数回削除すると構造が急速に崩壊し、単一の黒いノードに到達する前に再び行き詰まります。 

のために`n = 6`、サンプルでは不可能であると明示的に述べられています。 これは、プロセス全体を通じて「距離 3 の監視」状態を維持するにはサイクルが小さすぎる重要な移行点です。 

のために`n = 7`、完全に有効なシーケンスが存在し、サンプルはそのような順序の 1 つを示しています。 

したがって、重要な現象は、非常に小さなサイクルでは必要な構造的不変性を維持できないが、十分に大きなサイクルでは制御された剥離プロセスを維持できるということです。 

## アプローチ

 ブルートフォース戦略では、プロセスをシミュレートします。 各ステップで、すべての黒いノードをスキャンします。`i`、それぞれについて、距離 3 に黒いノードが存在するかどうかを確認します。 その場合は、削除してみます`i`1 つのノードが残るか、行き詰まるまで再帰的に続行します。 辞書編集的に最小限の出力を得るには、常に最小の有効な出力を選択します。`i`各ステップで。 

このシミュレーションの正しさは簡単ですが、各ステップで残りのすべてのノードをスキャンする必要があり、有効性をチェックするために円をスキャンすることも必要な場合があります。 これは次のことにつながります`O(n^2)`最悪の場合のテスト ケースごとに、制約をはるかに超えています。`n`到達する`10^5`。 

重要な観察は、唯一の構造要件は、距離 3 にアクティブなノードのペアが少なくとも 1 つ存在することであるということです。 この条件は、グローバル接続や長距離構造ではなく、そのようなペアの両方のエンドポイントがまだ黒であるかどうかによってのみ決まります。 円を固定配列として再解釈すると、少なくとも 1 つの有効な距離 3 ペアに現在参加している最小のインデックスを常に削除するという貪欲な戦略を維持できます。 

これが機能するのは、有効なペアのエンドポイントを削除すると、残っている構造が十分に保持されるためです。`n ≥ 7`。 直観的には、このサイクルは十分に大きいため、1 つの頂点を削除しても、考えられるすべての距離 3 関係がグローバルに削除されることはありません。

 ## アルゴリズムのチュートリアル

 ブール配列を維持します`alive[i]`カードがまだ黒いかどうかを示します。 また、ノードが`i`距離 3 の隣接する 2 つのうちの少なくとも 1 つが現在削除可能である`(i+3)`または`(i−3)`(モジュロ`n`）はまだ生きています。 

### アルゴリズムのステップ

 1. すべてのノードを初期化します`1..n`生きているように。 

また、候補インデックスを昇順にすばやく与えることができるデータ構造 (キューまたはセット) も用意します。 
2. 各ノードについて`i`、距離 3 に現在生存している有効なパートナーがいるかどうかを確認します。 その場合はマークを付けてください`i`最初は取り外し可能です。 
3. 最小のインデックスを繰り返し抽出する`i`それは現在取り外し可能です。 
4.追加`i`答えに対してデッドとしてマークします。 
5.取り外し後`i`、ノードのステータスを更新します`i−3`そして`i+3`(それらが存在し、まだ生きている場合)、有効なペアを形成する能力が変化している可能性があるためです。 
6. 1 つのノードだけが存続するまで続行します。 
7. いずれかの時点で取り外し可能なノードが見つからないが、複数のノードがまだ生きている場合は、次のように出力します。`NO`。 

微妙な部分は、「削除可能」状態の正確さを段階的に維持することです。 各削除は、距離 3 の近傍を含むペアにのみ影響するため、ステップごとに一定数のノードのみを更新する必要があります。 

### なぜ効果があるのか

 不変条件は、すべてのリムーバブル ノードが既存の距離 3 の黒のペアに対応するということです。 このようなペアの 1 つのエンドポイントを削除しても、各ノードには固定オフセットで 2 つの潜在的なパートナーが存在するため、十分な大きさのサイクルで将来の可能性をすべて破壊することはできません。 のために`n ≥ 7`、ノードが 1 つだけ残るまで、円は常に少なくとも 1 つのアクティブな距離と 3 のペアを保持します。 貪欲な選択により、不変式を満たす最小のインデックスが常に選択されるため、辞書編集上の最小性が保証されます。また、スキップしても以前のインデックスのロックが解除されずに削除が遅れるだけであるため、今後の選択によってそのインデックスをスキップすることを強制することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        
        if n <= 6:
            print("NO")
            continue
        
        alive = [True] * (n + 1)
        remaining = n
        
        # candidate set: indices that can be removed
        import heapq
        heap = []
        
        def valid(i):
            if not alive[i]:
                return False
            j1 = i + 3
            j2 = i - 3
            if j1 <= n and alive[j1]:
                return True
            if j2 >= 1 and alive[j2]:
                return True
            return False
        
        for i in range(1, n + 1):
            if valid(i):
                heap.append(i)
        heapq.heapify(heap)
        
        ans = []
        
        while remaining > 1:
            while heap and (not valid(heap[0])):
                heapq.heappop(heap)
            
            if not heap:
                break
            
            i = heapq.heappop(heap)
            if not valid(i):
                continue
            
            ans.append(i)
            alive[i] = False
            remaining -= 1
            
            for d in (-3, 3):
                j = i + d
                if 1 <= j <= n and alive[j]:
                    heapq.heappush(heap, j)
        
        if remaining != 1:
            print("NO")
        else:
            print("YES")
            print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、生きているノードを追跡し、最小ヒープを使用して、現在有効な最小のリムーバブル インデックスを常に抽出します。 の`valid`関数は距離 3 条件を直接エンコードします。 削除するたびに、距離 3 にある影響を受ける 2 つの近隣のみが再検討され、ローカルで効率的な更新が維持されます。 

重要な実装の詳細は、ヒープ内の遅延削除パターンです。古い候補を保存する可能性があるため、それらを使用する前に有効性を再チェックします。 これにより、ヒープの中央からのコストのかかる削除が回避されます。

 ## 特殊なケース

 のために`n = 4`、アルゴリズムは、最初の削除後、有効な距離 3 のパートナーを維持できるノードがないことをすぐに検出するため、次のように出力します。`NO`ループに入らずに。 制約が厳しすぎるため、一貫したステップを 1 つも維持できません。 

のために`n = 5`、初期の有効なペアが存在する場合でも、削除を繰り返すと対称性がすぐに崩れ、ノードが 1 つだけ残る前にヒープが空になり、`NO`。 

のために`n = 6`、失敗は偶然ではなく構造的なものです。 このサイクルでは、残りのノード間の十分な分離が維持されないため、すべての候補が最終的にパートナーを失い、プロセスが途中で停止します。 

のために`n ≥ 7`の場合、ピーリング プロセス全体を通じて距離 3 の隣接関係が維持される可能性があるため、貪欲プロセスは最終ステップまで常に少なくとも 1 つの取り外し可能なノードを見つけます。
