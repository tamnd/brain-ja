 ## 解決策
 ## 問題の理解

 グループ チャットでは、メッセージの時系列のログが提供されます。 各メッセージには送信者とタイムスタンプがあります。 特定の参加者の 1 人であるアスワドは、固定された反応ルールに従います。つまり、メッセージが表示されるたびに、長さ k 分の待機タイマーを開始します。 タイマーが終了する前に他のメッセージが表示されない場合、応答は 1 つだけ送信されます。 タイマーが完了する前に別のメッセージが表示された場合、保留中の反応を破棄し、その新しいメッセージから待機タイマーを再開します。 

このタスクは、すべてのメッセージのタイムスタンプを順番に指定して、Aswad が各テスト ケースに対して最終的に送信する応答の数を決定することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、k、待機期間、およびメッセージ タイムスタンプのシーケンスを提供します。 Aswad はメッセージの送信者ではなく時間の経過に反応するため、送信者 ID はロジックには無関係です。 出力はテスト ケースごとに 1 つの整数、つまり Aswad が完全な中断のない待機期間を正常に完了した回数です。 

制約は十分小さいため、テスト ケースごとに直接リニア スキャンを行うだけで十分です。 すべてのメッセージを処理し、現在追跡されている期限と比較しても、総作業量は問題なく制限内に収まります。 重要な観察は、各メッセージが 1 回処理され、各決定が一定時間で行われることです。 

待機期間が終了するまさにその瞬間に到着するメッセージの周囲には、微妙なエッジケースが現れます。 最後のメッセージが時刻 t に開始されたとき、メッセージが時刻 t + k に到着した場合、待機は中断されずに完了したとみなされます。 したがって、等価性はリセットではなく成功応答をトリガーする必要があります。 

もう 1 つの重要な例外ケースは、メッセージが急速に送信される場合です。 たとえば、メッセージが毎分到着し続け、k が大きい場合、Aswad は決して応答しません。 逆に、メッセージの後に長いアイドルギャップがある場合、Aswad はそのギャップに対して 1 回だけ応答します。 

## アプローチ

 ブルートフォース解釈では、アスワドの動作をメッセージごとにシミュレートし、保留中の「待機ウィンドウ」のキューを明示的に維持します。 各メッセージについて、時間を前方にスキャンして、k 分が経過する前に後のメッセージが表示されるかどうかを確認し、現在のメッセージが応答につながるかどうかを判断できます。 これにより、配列のサフィックスを繰り返しスキャンすることになり、メッセージが密集している最悪の場合、各メッセージで将来の多くのイベントをチェックする必要が生じる可能性があります。 これにより、テスト ケースごとの複雑さが O(m²) に近づきますが、m が完全な入力サイズに到達できることを考えると、これは不要です。 

この改善は、プロセスで複数のステップを先読みする必要がないことに気づいたことから生まれます。 現在「回答を待っている」単一のアクティブな候補者メッセージを追跡する必要があるだけです。 新しいメッセージが到着すると、現在の候補が無効になるか、完了が許可されます。 これにより、問題はシングルパスの貪欲なシミュレーションに変わります。待機期間を開始した最後のメッセージのタイムスタンプを維持し、その待機期間がいつ終了するかを維持します。 

「現在のアクティブ開始時刻」と「有効期限」という観点で問題を表現すると、すべてのメッセージがアクティブ状態を延長するか、完了した応答をトリガーします。 これにより、ネストされたスキャンの必要性がすべてなくなります。

 ## アルゴリズムのチュートリアル

 まず、すべてのタイムスタンプを比較可能な数値形式、具体的には午前 0 時からの分数に変換します。 これにより、k 分間の比較の直接演算が可能になります。 

次に、現在の保留中のメッセージのタイムスタンプと、中断されなかった場合にその応答がトリガーされる時刻という 2 つの変数を維持しながら、メッセージを時系列で処理します。

1. Aswad の応答のカウンターをゼロに初期化します。 また、アクティブな保留中のメッセージも初期化されません。 
2. 差分が単純な整数の減算になるように、60 * HH + MM を使用して各タイムスタンプ HH:MM を合計分に変換します。 これにより、時間境界を明示的に扱うことがなくなります。 
3. 最初のメッセージについては、それをアクティブな保留中のメッセージとして設定し、その有効期限をタイムスタンプに k 分を加えた値に設定します。 これは、何も中断されなかった場合にアスワドが応答する最も早い瞬間を表します。 
4. 次の各メッセージについて、そのタイムスタンプと現在の有効期限を比較します。 新しいメッセージが有効期限よりも前に到着した場合、以前の待機プロセスは中断されて破棄されるため、アクティブなメッセージを新しいメッセージに置き換えて、その有効期限を再計算します。 
5. 新しいメッセージが有効期限時刻以降に到着した場合、前の待機期間は中断される前に正常に完了しました。 保留中のメッセージが応答を生成したため、応答カウンターをインクリメントします。 次に、現在のメッセージを新たな開始点として扱い、新しい有効期限を割り当てます。 
6. すべてのメッセージを処理した後、最後の保留中のメッセージには、中断されない有効な待機期間がまだ残っている場合があります。 今後メッセージによってキャンセルされることはないため、応答としてカウントされます。 

重要な決定点は常に、次のタイムスタンプと現在の有効期限との比較です。 

### なぜ効果があるのか

 すべてのステップで、応答を生成できるアクティブな「候補メッセージ」が最大 1 つ存在します。 有効期限が切れる前に到着したメッセージは完全に無効になり、以前のメッセージは常にすでにキャンセルされているか、すでに完了しているため、再び関連することはありません。 これは、アルゴリズムが、アクティブな候補が常に中断されていない最新のメッセージであるという不変条件を維持し、その有効期限が応答が発生する可能性のある最も早い時間を正確に表すことを意味します。 すべてのメッセージは 1 回処理され、遷移は最終的なものとなるため、完了した有効期限の数は Aswad の応答と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_minutes(t):
    h, m = map(int, t.split(":"))
    return h * 60 + m

t = int(input())
for _ in range(t):
    n, k, m = map(int, input().split())

    times = []
    for _ in range(m):
        _, ts = input().split()
        times.append(to_minutes(ts))

    ans = 0
    start = times[0]
    expiry = start + k

    for i in range(1, m):
        cur = times[i]
        if cur < expiry:
            start = cur
            expiry = cur + k
        else:
            ans += 1
            start = cur
            expiry = cur + k

    ans += 1
    print(ans)
```この実装では、アクティブなメッセージの実行「開始」時間と計算された有効期限が維持されます。 比較`cur < expiry`待機ウィンドウ内の割り込みを厳密に捕捉します。 等しいことは完了として扱われるため、状態を切り替える前に応答がカウントされます。 

決勝戦`ans += 1`最後のアクティブなウィンドウは、後で明示的に無効にしない限り常に完了し、その後のメッセージがないためカウントする必要があるため、これが必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def to_minutes(t):
        h, m = map(int, t.split(":"))
        return h * 60 + m

    t = int(input())
    out = []
    for _ in range(t):
        n, k, m = map(int, input().split())
        times = []
        for _ in range(m):
            _, ts = input().split()
            times.append(to_minutes(ts))

        ans = 0
        start = times[0]
        expiry = start + k

        for i in range(1, m):
            cur = times[i]
            if cur < expiry:
                start = cur
                expiry = cur + k
            else:
                ans += 1
                start = cur
                expiry = cur + k

        ans += 1
        out.append(str(ans))

    return "\n".join(out)

1 00:00

1 00:10
""") == "1"

# all spaced far apart

""") == "3"

""") == "0"

""") == "1"

 | 密な流れ | 0 | 連続割り込みはすべてをブロックします。 
| 正確な k 境界 | 1 | 等しい場合は完了としてカウントされます |

 ## 特殊なケース

 重要なエッジ ケースは、メッセージが正確に k 分間隔で到着する場合です。 この場合、待機期間は次のメッセージが到着した瞬間に完了するため、前の応答は引き続きカウントされます。 たとえば、k = 5 でメッセージが 00:00 と 00:05 にある場合、最初のメッセージが応答を生成し、2 番目のメッセージで新しいサイクルが開始されます。 アルゴリズムは厳密なアルゴリズムを使用するため、これを処理します。`< expiry`中断の条件であるため、等しいことが完了として扱われます。 

もう 1 つのエッジ ケースは、すべてのメッセージが k 分が経過する前に到着する、完全に密なメッセージ シーケンスです。 このような状況では、待機期間が終了することは決して許可されません。 シミュレーションではアクティブなメッセージが継続的にリセットされ、最後に強制的に完了するまでカウンターは増加しません。 これは、中断のない間隔のみが応答を生成するというルールと一致します。 

最後のエッジケースは単一のメッセージです。 タイムスタンプが 1 つだけの場合、中断の可能性はないため、Aswad は常に 1 つの応答を生成します。 最初の保留ウィンドウは常に最後にカウントされるため、アルゴリズムはこれを自然に処理します。
