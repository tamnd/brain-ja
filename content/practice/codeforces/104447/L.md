 ## 解決策
 ## 問題の理解

 一連の独立したテスト ケースが与えられます。 各テスト ケースには、生徒の元のスコアを 0 から 10 のスケールで表す 1 つの整数が含まれています。 このタスクは、合格またはゼロ以外の提出物を満点にアップグレードするが、完全に空白の提出物についてはアップグレードを拒否する教師をモデル化した単純なルール セットに従ってこのスコアを変換することです。 

各テスト ケースで、元のスコアが厳密に 0 より大きい場合、出力は 10 になります。スコアが正確に 0 の場合、出力は 0 のままです。 

制約は非常に小さいです。 テスト ケースは最大 11 個あり、各スコアは 0 ～ 10 の範囲にあります。これにより、複雑なデータ構造や最適化の必要性が即座に排除されます。 各テスト ケースを一定時間で処理するソリューションであればどれでも十分です。 

唯一の微妙なエッジ ケースは、ゼロと正の値の間の境界です。 素朴な間違いは、ゼロをアップグレードに有効なものとして扱うか、値に関係なくすべての入力が 10 にマップされるべきであると誤って仮定することです。 たとえば、入力`0`残らなければなりません`0`、入力中に`1`にならなければなりません`10`。 もう 1 つの考えられる間違いは、ルールを複雑にしすぎて、チェックなどの off-by-one ロジックを誤って導入してしまうことです。`n >= 0`これにより、ゼロも誤ってアップグレードされてしまいます。 

## アプローチ

 問題を強引に解釈すると、複数の条件分岐を使用して採点ロジックを明示的にシミュレートしたり、0 から 10 までのすべての可能な値のマッピング テーブルを保存したりしようとする可能性があります。入力ドメインが小さいため、これは正しく機能し、可能なスコアごとに出力を簡単に事前定義できます。 

ただし、そのようなアプローチは不要です。 問題の構造から、値がゼロかどうかという 1 つの条件だけが重要であることがわかります。 ブルート フォース アプローチでは各値が独立して処理されますが、非ゼロのケースはすべて同じように動作するため、すべてのケースを 1 つの結果に圧縮できます。 この観察により、問題は 1 つの条件チェックに集約されます。 

重要な洞察は、変換全体が 2 値分類であるということです。0 は 0 にマッピングされ、それ以外はすべて 10 にマッピングされます。 これが認識されると、解はテスト ケースごとに定数時間になります。

 | ブルート フォース マッピング テーブル | ケースごとに O(1) | お(1) | 承認済み |
 | 最適な条件チェック | ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 これにより、適用する必要がある独立した変換の数が決まります。 
2. 各テスト ケースについて、整数スコアを読み取ります。 
3. スコアがゼロに等しいかどうかを確認します。 すべての正の値は同じように動作するため、これが唯一の意味のある決定点です。 
4. スコアがゼロの場合は、ゼロを出力します。 それ以外の場合は、10 を出力します。 

各決定はそのテスト ケースに対してローカルであるため、反復間で状態を引き継ぐ必要はありません。 

### なぜ効果があるのか

 正確さは、変換が入力ドメインの 2 要素パーティションのメンバーシップ (ゼロを含むシングルトン セットと範囲内のすべての正の整数のセット) にのみ依存するという事実に基づいています。 すべての非ゼロ入力は同じ出力にマッピングされるため、それらを区別する必要はありません。 したがって、アルゴリズムは、ルール自体が許容する範囲を超えた近似や集計を行わずに、正確なルール定義を適用することで正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n > 0:
            print(10)
        else:
            print(0)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 ここでの制約では必須ではありませんが、競技プログラミングでは標準的な手法であるため、入力は高速 I/O を使用して処理されます。 

条件付き`if n > 0`ソリューションの核心です。 意図的に書き込みを避けている`if n != 0`または`if n >= 0`後者は 0 から 10 までを誤ってマッピングしてしまうためです。 2 つの出力の分離は明示的であり、間違いを引き起こす可能性のある隠れた算術トリックを回避します。

 ## 特殊なケース

 唯一意味のあるエッジ ケースは、値 0 自体です。 入力用`0`、アルゴリズムは条件を評価します`n > 0`false と正しく出力される`0`。 正しいトレースは次のとおりです。 

| ステップ | n | 条件 (n > 0) | 出力 |
 | --- | --- | --- | --- |
 | 読む | 0 | - | - |
 | 評価 | 0 | 偽 | 0 |

 これにより、ゼロが決してアップグレードされないことが確認されます。 

次のような最小の正の値の場合、`1`、条件は true と評価され、`10`、この動作は、大きさに関係なく、すべての正の入力にわたって一貫しています。
