 ## 解決策
 ## 問題の理解

 n 個の頂点を持つツリーが与えられます。 各頂点にはその色と呼ばれるラベルがあり、グラフはツリーであるため、各エッジは 2 つの頂点を独自の方法で接続します。 

任意の 2 つの頂点 u と v について、それらの間には一意の単純なパスが存在します。 頂点のペアは、2 つの条件が当てはまる場合に有効であると呼ばれます。つまり、最初の頂点のインデックスが 2 番目の頂点より小さく、その色の gcd が正確に 1 です。有効なペアは 1 つの「美しいパス」を提供します。これは、ツリー内の 2 つの頂点間のパスにすぎません。 

タスクは、すべての美しいパスをグローバルにカウントすることではなく、エッジごとに、そのエッジを通過する一意のパスを持つ有効なペアの数をカウントすることです。 

n が 5 × 10^4 までの制約により、頂点のすべてのペアを明示的に考慮する解法から遠ざけられます。 単純なペアの O(n^2) 列挙はすでに大きすぎます。n 個のエッジがあるため、エッジあたり O(n log n) でさえも不可能です。 エッジを削除するとツリーが 2 つのコンポーネントに分割され、そのエッジを使用するパスは一方のコンポーネントで開始し、もう一方のコンポーネントで終了する必要があるため、ツリーの構造が役に立ちます。 

最も難しいのは gcd 条件です。 これを無視すると、各エッジは、u < v の順序になるように調整された、単純にその 2 つの辺間の交差ペアの数に寄与することになります。gcd 制約は、コンポーネント間の値を結合し、数理論的な変換を強制します。 

u < v 制約について推論するときに、微妙な落とし穴が現れます。 カット全体で順序のないペアを数えるだけでは十分ではありません。 たとえば、小さいインデックスのノードが右側のコンポーネントにあり、大きいインデックスのノードが左側のコンポーネントにある場合、サイドを交換すると、ペアがカウントされるかどうかが変わります。 インデックスを考慮せずにカットを対称として扱うソリューションでは、オーバーカウントが行われます。 

## アプローチ

 直接的なアプローチでは、頂点 u と v のすべてのペアを考慮し、そのパスが指定されたエッジと交差するかどうかをチェックし、gcd(cu, cv) = 1 を検証します。パス チェックが O(1) の LCA ロジックに縮小されたとしても、これは依然として O(n^2) ペアの処理につながり、これは限界をはるかに超えています。 

より構造化された観察は、エッジによってツリーが 2 つのコンポーネントに分割されるということです。 固定エッジの場合、u と v が異なる側にあるペア (u, v) のみを考慮します。 gcd を一時的に無視すると、問題は成分間カウントの問題になります。 順序付け条件 u < v は非対称性をもたらしますが、インデックスベースのプレフィックス構造の観点からカウントを表現すれば、まだ管理可能です。 

gcd 条件が本当の障害です。 多くのペアにわたる gcd 制約を処理する標準的な方法は、メビウス反転です。 gcd(cu, cv) = 1 を直接強制する代わりに、両方の色が d で割り切れるペアをカウントし、結果をメビウス係数 μ(d) と組み合わせます。 これにより、問題は、割り算によってグループ化された値の頻度カウントを維持することに変換されます。 

除数 d を修正すると、問題は、u < v を考慮しながら、色が d で割り切れるノード間のコンポーネント間のペアをカウントするようになります。これは、純粋にインデックスをカウントする問題になり、オイラーまたはフェンウィック ツリーと組み合わせたインデックス順序のプレフィックス合計を使用して処理できます。 

最終的なソリューションは、エッジごとのツリー分割、色に対するメビウス反転、インデックスに対するフェンウィックベースのプレフィックスカウントの 3 つのアイデアを組み合わせたもので、アクティブなサブツリーとグローバル補数を慎重に処理します。

 | メビウス + ツリーパーティション + フェンウィック | O(n log n √C) | O(n √C) | 承認済み |

 ## アルゴリズムのチュートリアル

頂点 1 でツリーをルートします。次に、このルート構造内のすべてのエッジが親と子を接続し、エッジを削除するとサブツリーがツリーの残りの部分から分離されます。 各エッジについて、子のサブツリーを一方の側として扱い、その他すべてをもう一方の側として扱います。 

また、すべての約数のメビウス寄与を最大カラー値まで事前計算します。 これにより、gcd 制約を除数ベースのカウントに変換できるようになります。 

各約数 d について、現在 d で割り切れる色を持つ頂点の数を格納する頂点インデックス上のフェンウィック ツリーを維持します。 この構造は、u < v 条件を処理するために必要なプレフィックス クエリをサポートします。 

DFS を使用してツリーを処理し、頂点の「アクティブな」セットを表す動的構造を維持します。これが、評価している現在のサブツリーです。 与えられたノード c について、そのサブツリーを 1 つのコンポーネントとして扱い、残りのノードを補完物として扱います。 

次に、固定約数 d を考えます。 サブツリー内の頂点 u について、補数内の頂点 v が 2 つの条件を満たす数を数えたいとします。それらの色は d で割り切れる、およびインデックスは u より大きいです。 これにより、この約数に対する u の寄与が得られます。 

これを効率的に計算するには、プレフィックス合計を使用します。 total_d を d で割り切れるツリー全体のノードの数とし、active_d を現在のサブツリーの数とします。 pref_d(x) を、指定されたセット内で割り切れる色のインデックス ≤ x を持つノードの数とします。 

サブツリー内の頂点 u の場合、v > u の補数内の有効な v の数は、グローバル プレフィックス数からサブツリー プレフィックス数を引いた組み合わせとして書き換えることができます。 これにより、問題はグローバルおよびサブツリー構造に対するフェンウィック クエリに変換されます。 

概念的には、除数ごとに 2 つのフェンウィック構造を維持します。1 つはツリー全体用、もう 1 つは現在アクティブなサブツリー用です。 サブツリー構造は移動中に動的に維持されますが、グローバル構造は固定されています。 

親 p から子 c までの各エッジについて、c のサブツリーが完全にアクティブになると、そのサブツリー内のすべての頂点 u を反復してその寄与を計算します。 各 u について、cu のすべての約数を反復し、メビウス反転を適用してエッジの答えへの寄与を蓄積します。 

処理後、DFS で上向きに戻る前にサブツリーを削除します。 

### なぜ効果があるのか

 すべての有効なペア (u、v) は、正確に 1 つのエッジ、つまりカットの低インデックス側から高インデックス側に移動するときの u から v へのパス上の最初のエッジに一意に割り当てられます。 サブツリー分解により、エッジを処理するときに、パスがそのエッジと交差するペアを正確に考慮することが保証されます。 メビウス反転では、ペアごとの gcd を明示的にチェックすることなく、gcd(cu, cv) = 1 が強制されます。 フェンウィック ベースのカウントでは、プレフィックスの違いを使用して u < v 制約が一貫して適用されることが保証されるため、ペアが二重にカウントされたり見逃されたりすることはありません。

def build_mobius(n):
    mu = list(range(n + 1))
    prime = []
    is_comp = [False] * (n + 1)
    for i in range(2, n + 1):
        if not is_comp[i]:
            prime.append(i)
            mu[i] = -1
        j = 0
        while j < len(prime) and i * prime[j] <= n:
            is_comp[i * prime[j]] = True
            if i % prime[j] == 0:
                mu[i * prime[j]] = 0
                break
            else:
                mu[i * prime[j]] = -mu[i]
            j += 1
    mu[1] = 1
    return mu

        self.n = n
        self.bit = [0] * (n + 1)

        while i <= self.n:
            self.bit[i] += v
            i += i & -i

        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - self.sum(l - 1)

 ## 特殊なケース

 重要なエッジ ケースは、すべての色が 1 より大きい共通因数を共有する場合です。その状況では、gcd(cu, cv) が 1 にならないため、どのペアも寄与すべきではありません。アルゴリズムはメビウス反転を通じてこれを処理します。つまり、すべての約数の寄与が相殺され、すべてのエッジの合計寄与がゼロになります。 

別のエッジ ケースは、チェーンなどの非常にアンバランスなツリーで発生します。 ここで、各エッジはプレフィックスとサフィックスの分割に対応します。 すべてのサブツリーはオイラー順序で連続したセグメントであるため、サブツリー メカニズムは引き続き機能し、Fenwick プレフィックス クエリは有効なままになります。 

最後の微妙なケースは、ツリーの奥深くにある高インデックスのノードとルート近くの低インデックス ノードなど、頂点インデックスがツリー構造に対して逆転している場合です。 u < v 条件により、1 つの方向のみが寄与することが保証され、プレフィックスベースの計算により、ツリーの深さに関係なく方向が正しく識別されます。
