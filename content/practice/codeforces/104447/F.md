 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースには文字列の配列があり、各文字列には値が含まれます。 また、文字編集の予算も限られており、1 回の編集で文字列内の 1 文字が他の文字に変更されます。 

配列から文字列の連続ブロックを選択することに興味があります。 そのブロックから、選択したブロック内のすべての文字列にわたって最大で合計 k 回の文字編集を使用して、すべての文字列を回文にしたいと考えています。 それが達成できれば、ブロックは有効であるとみなされます。 ブロックのスコアはその文字列の値の合計であり、目的は、すべての有効な連続ブロックの中で可能な最大スコアを見つけることです。 

重要な隠された構造は、単一の文字列を回文に変換するコストが他の文字列から独立していることです。 文字列の場合、ペアの一方の文字が他方の文字と一致するように変更される可能性があるため、一致しない対称文字ペアごとに 1 回の編集が強制されます。 これは、各文字列にはローカルで計算できる固定の「回文コスト」があることを意味します。 

問題は、スコアの合計を最大化しながら、総コストが k を超えない連続セグメントを選択することになります。 

この制約により、テスト ケースごとに線形または線形に近い解決策が強く求められます。 すべてのテストにわたるすべての文字列の合計の長さは最大でも 5 × 10^5 であるため、一定の回数を超えて文字を処理するソリューションであればどれでも受け入れられます。 ただし、部分文字列に対する二次アプローチやセグメントに対する繰り返しの再計算は不可能です。 

スコアがマイナスの場合、微妙な問題が発生します。 貪欲に拡張するだけの単純なスライディング ウィンドウは失敗する可能性があります。ウィンドウを拡張すると常にコストが増加しますが、スコアの増加が保証されるわけではないからです。 

もう 1 つの特殊なケースは空のサブ配列であり、これは明示的に許可されています。 これは、常に何も選択できないため、答えが決して否定的ではないことを意味します。 

## アプローチ

 ブルート フォース ソリューションでは、すべての文字列の回文コストを計算し、すべての O(n^2) 部分配列を列挙します。 各サブ配列について、スコアとコストの両方を合計し、妥当性をチェックします。 これには O(n^2) 個のサブ配列が必要で、プレフィックスの使用状況に応じてサブ配列ごとに O(1) または O(n) が動作するため、全体として O(n^2) かそれ以上の結果となり、n が 10^5 に達すると制限をはるかに超えます。 

重要な観察は、各文字列が 2 つの数値 (スコアと回文変換コスト) に還元できることです。 この問題は、古典的な制約付きサブアレイ最適化になります。コストの合計が最大でも k であることを条件として、スコアの合計を最大化します。 

これはプレフィックスベースの最適化問題です。 prefixScore[i] と prefixCost[i] を累積値とします。 l から r までの部分配列は、prefixCost[r] − prefixCost[l − 1] ≤ k であり、そのスコアが prefixScore[r] − prefixScore[l − 1] である場合に有効です。 r を固定して、prefixCost[l − 1] ≥ prefixCost[r] − k を満たしながら prefixScore[l − 1] を最小化する最適な l を見つけたいとします。 

これにより、問題はプレフィックス インデックスにわたるスライディング有効性ウィンドウに変換されますが、ダイナミック レンジ内で最小プレフィックス スコアを維持する必要が追加されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのサブ配列に対するブルート フォース | O(n^2) | お(1) | 遅すぎる |
 | プレフィックス + 2 つのポインター + デキューの最小値 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

## アルゴリズムのチュートリアル

1. 各文字列について、両端の対称文字を比較し、不一致のペアをカウントすることによって回文コストを計算します。 これは、その文字列が回文になるために必要な編集の最小回数です。 
2. 文字列リストに対して 2 つの配列を構築します。1 つはスコア用、もう 1 つはコスト用です。 
3. プレフィックス配列 prefixScore および prefixCost を構築します。ここで、コストは常に負ではないため、prefixCost は減少しません。 
4. 部分配列の右端点 r を昇順に繰り返します。 
5. 各 r について、プレフィックス空間で許容される最小の左境界を決定します。 prefixCost[l − 1] ≥ prefixCost[r] − k が必要です。 prefixCost はインデックスによってソートされるため、これは二分探索または単調前進によって取得される単一の移動ポインタ l0 に変換されます。 
6. 次に、prefixScore[l − 1] が最小化されるように、範囲 [l0, r − 1] 内の l − 1 を選択する必要があります。 これは、時間の経過とともに右にのみ移動するスライディング ウィンドウにわたる範囲最小クエリです。 
7. プレフィックス位置のインデックスの両端キューを維持します。 deque には l − 1 の候補が格納され、先頭が常に最小の prefixScore になるように prefixScore の昇順に保持されます。 
8. r が増加するにつれて、インデックス r − 1 を両端キューに挿入し、l0 を下回るインデックスを削除します。 また、より悪い候補を後方から削除することで単調性を維持します。 
9. 各 r について、r で終わる最も有効なサブ配列の値は、prefixScore[r] から有効な両端キュー内の最小 prefixScore を引いた値になります。 グローバルな回答を更新します。 

### なぜ効果があるのか

 すべての r で、r で終わるすべての有効な部分配列は、接尾辞範囲 [l0, r − 1] 内の接頭辞インデックス j の選択に正確に対応します。 deque は、まさにこの範囲にわたって最小 prefixScore を維持します。 すべての候補 j は有効な左境界を表し、そのようなすべての候補が考慮されるため、最適な選択が見逃されることはありません。 l0 の単調な動きにより、以前は無効だったインデックスが再度有効になることがないため、構造の一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def pal_cost(s: str) -> int:
    i, j = 0, len(s) - 1
    c = 0
    while i < j:
        if s[i] != s[j]:
            c += 1
        i += 1
        j -= 1
    return c

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        w = [input().strip() for _ in range(n)]
        s = list(map(int, input().split()))
        
        cost = [pal_cost(x) for x in w]

        prefS = [0] * (n + 1)
        prefC = [0] * (n + 1)

        for i in range(n):
            prefS[i + 1] = prefS[i] + s[i]
            prefC[i + 1] = prefC[i] + cost[i]

        dq = deque()
        dq.append(0)

        ans = 0
        l0 = 0

        for r in range(1, n + 1):
            limit = prefC[r] - k

            while l0 < r and prefC[l0] < limit:
                l0 += 1

            j = r - 1
            while dq and prefS[dq[-1]] >= prefS[j]:
                dq.pop()
            dq.append(j)

            while dq and dq[0] < l0:
                dq.popleft()

            if dq:
                ans = max(ans, prefS[r] - prefS[dq[0]])

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、各文字列をコストに変換することから始まります。コストは、文字レベルの構造に依存する唯一の部分です。 プレフィックス合計により、すべてのサブ配列計算が定数時間範囲クエリに削減されます。 deque は、現在の正しいエンドポイントのすべての有効なプレフィックス境界の中で、常に最高のスコアを与えるプレフィックス境界を取得することを強制します。 

実装の微妙な詳細は、ループ内の順序付けです。最初に有効性境界 l0 を調整し、次に新しいプレフィックス インデックスを挿入し、その後で古いインデックスを破棄します。 これにより、両端キューが常に有効なプレフィックス範囲を正確に反映することが保証されます。 

## 実用的な例

 コスト フィルタリングとスコアの最大化を同時に確認できる、小規模な構築されたケースを考えてみましょう。 

入力:

 n = 5、k = 2

 文字列 = ["ab"、"aa"、"cd"、"ee"、"ff"]

 スコア = [5、-2、4、3、6]

 費用は次のとおりです。 

「ab」→1、「aa」→0、「cd」→1、「ee」→0、「ff」→0

 プレフィックスコストは次のようになります。 

0、1、1、2、2、2

 r を段階的に追跡します。 

| r | 制限 = prefC[r]-k | l0 | ベスト j (プレフィックス インデックス) | スコア |
 | --- | --- | --- | --- | --- |
 | 1 | -2 | 0 | 0 | 5 |
 | 2 | -1 | 0 | 1 | 3 |
 | 3 | -1 | 0 | 1 | 7 |
 | 4 | 0 | 0 | 1 | 10 |
 | 5 | 0 | 0 | 1 | 16 |

 これは、prefixScore の最小化によって負の寄与がスキップされることを優先するため、負の寄与がどのように自然に回避されるかを示しています。 

トレースは、アルゴリズムがウィンドウをやみくもに拡大するのではなく、最適な開始プレフィックスを継続的に再評価することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(n) | プレフィックス配列とデキューは、インデックスの線形数を格納します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    def pal_cost(s: str) -> int:
        i, j = 0, len(s) - 1
        c = 0
        while i < j:
            if s[i] != s[j]:
                c += 1
            i += 1
            j -= 1
        return c

    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        w = [input().strip() for _ in range(n)]
        s = list(map(int, input().split()))
        cost = [pal_cost(x) for x in w]

        prefS = [0]*(n+1)
        prefC = [0]*(n+1)
        for i in range(n):
            prefS[i+1] = prefS[i] + s[i]
            prefC[i+1] = prefC[i] + cost[i]

        dq = deque([0])
        l0 = 0
        ans = 0

        for r in range(1, n+1):
            limit = prefC[r] - k
            while l0 < r and prefC[l0] < limit:
                l0 += 1

            j = r-1
            while dq and prefS[dq[-1]] >= prefS[j]:
                dq.pop()
            dq.append(j)

            while dq and dq[0] < l0:
                dq.popleft()

            ans = max(ans, prefS[r] - prefS[dq[0]])

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、k が 0 の場合です。 その場合、既に回文になっている文字列 (コスト 0) のみを含めることができます。 ゼロコストのプレフィックス位置のみが残るまで l0 が進み、deque が自然に候補を制限するため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、すべてのスコアがマイナスの場合です。 空の部分配列は常に有効であり、プレフィックス差分ロジックにより、空の選択が優勢になる可能性のある j = r − 1 の候補を常に考慮するため、ゼロよりも負の和が好まれることはありません。 

最後の微妙なケースは、長さが 1 の文字列で、回文コストが常に 0 です。 これらは常に有効なウィンドウ内に残り、アルゴリズムは効果的に標準の最大サブ配列合計問題にまで縮小しますが、この問題はプレフィックス最小選択によって引き続き正しく処理されます。
