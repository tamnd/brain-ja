 ## 解決策
 ## 問題の理解

 グリッド上に描画された多角形が与えられますが、任意の多角形とは異なり、それは強力な構造を持っています。すべてのエッジは完全に水平または完全に垂直であり、頂点は時計回りの順序でリストされます。 ポリゴンは単純です。つまり、そのエッジは共有端点を除いて交差しません。 この多角形を読んだ後、多くの独立した質問が出されます。 各クエリは平面上の点を与え、その点が多角形の内側にあるのか、それとも正確にその境界上にあるのかを判断する必要があり、その場合は YES が出力され、それ以外の場合は NO が出力されます。 

重要な制約はスケールです。 ポリゴンには最大 10 万の頂点を含めることができ、最大 10 万のクエリも存在できます。 すべてのエッジを直接スキャンして各クエリをチェックするソリューションは、最悪の場合、約 10^10 の操作が必要となるため、非常に遅すぎます。 これにより、クエリごとの単純なレイ キャスティングやポリゴン境界のクエリごとのトラバースが即座に排除されます。 

このステートメントには、微妙な幾何学的特性が隠されています。多角形は直交しています。これは、多角形が完全に軸に沿ったセグメントで構成されていることを意味します。 これは、構造が任意の多角形ではなく、境界が強い順序で水平セグメントと垂直セグメントに分解できる直線形状であることを意味します。 これにより、完全なポリゴン交差テストを回避できるようになります。 

エッジケースは 2 つの主な形式で現れます。 まず、エッジまたは頂点上に正確に存在する点は、内側としてカウントされる必要があります。 たとえば、多角形に (2, 2) から (10, 2) までのエッジがある場合、クエリ ポイント (5, 2) は YES を返す必要があります。 厳密な不等式を使用した単純なポリゴン内ポイントの実装では、境界処理が明示的に追加されない限り、誤って NO が返されます。 

第 2 に、縮退した水平方向または垂直方向の配置により、長い同一線上の境界が生じる可能性があります。 マージや慎重な順序付けを行わずに各エッジを個別に扱う単純なアプローチでは、交差が二重にカウントされたり、頂点でのコーナー ケースが誤って処理されたりする可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリが個別に処理されます。 固定点の場合、レイ キャスティングを使用して標準的なポリゴン内ポイント テストを実行できます。水平レイを右に描画し、それが交差するポリゴン エッジの数を数えます。 交差点の数が奇数の場合、点は内側にあります。 ポリゴンには n 個のエッジがあるため、各クエリのコストは O(n) となり、全体では O(nq) になります。 n と q が両方とも 10^5 までであるため、これは完全に不可能です。 

ポリゴンの構造により、より特殊なアプローチが可能になります。 すべてのエッジは軸に揃えられ、頂点は時計回りの順序で指定されるため、ポリゴンの境界は、構造化された方法で平面を分割する一連の水平セグメントとして解釈できます。 ポリゴンを任意のジオメトリとして扱う代わりに、すべての垂直線が一連の y 間隔でポリゴンと交差し、それらの間隔を事前に計算して効率的にクエリできるという事実を利用します。 

重要なアイデアは、X 軸に沿ってスイープすることです。 X 座標によって水平エッジをグループ化し、Y カバレッジのアクティブな間隔を維持することによって、垂直構造を暗黙的に処理します。 次に、各クエリは 1 次元のメンバーシップ チェックに帰着します。つまり、指定された x 座標について、y 座標がポリゴンのアクティブな垂直スラブの 1 つの内側にあるかどうかを判断します。 

これにより、問題は間隔管理と組み合わせたスイープラインに変わります。 水平エッジをイベントに変換し、x で並べ替えて、ポリゴン内にある現在の y 範囲のセットを追跡するデータ構造を維持します。 各クエリは、これらの間隔内でバイナリ検索によって回答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース レイ キャスティング | O(nq) | お(1) | 遅すぎる |
 | 間隔クエリを使用したスイープ ライン | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. まず、ポリゴンからすべての水平エッジを抽出します。 すべてのエッジは、x1 から x2 までの固定 y 座標のセグメントに寄与します。 時計回りのトラバース方向ではエンドポイントが反転する可能性があるため、x1 < x2 になるように各セグメントを正規化します。 このステップでは、スイープ ライン処理用のジオメトリを準備します。 
2. 次に、各水平セグメントを 2 つのイベントに変換します。1 つは間隔が x1 で始まることを示し、もう 1 つは間隔が x2 で終了することを示します。 任意の固定 x 位置で、アクティブな y 間隔のセットはポリゴンの垂直範囲を表します。 
3. すべてのイベントを X 座標で並べ替えます。 複数のイベントが同じ x を共有する場合、境界での正確性を維持するために、追加の前に削除を処理します。 これにより、垂直エッジ上に正確に位置するポイントが一貫して処理されることが保証されます。 
4. y 区間にわたってバランスのとれた構造、概念的には区間エンドポイントのマルチセットまたは順序付きマップを維持します。 左から右にスイープしながら、現在の x でのイベントに従って y 間隔を挿入または削除します。 
5. 各クエリ ポイント (x、y) について、同じスイープ内のイベントとして扱います。 ソートされたイベント リスト内でその位置を特定し、その x における y 間隔のアクティブなセットを決定します。 
6. x でのアクティブな y 区間がわかったら、y が任意の区間内にあるかどうかを確認します。 これは、間隔のエンドポイントに対する二分探索を使用するか、結合されていないマージされた間隔の並べ替えられたリストを維持することを使用して行われます。 
7. y がアクティブな間隔内にある場合、またはその境界上にある場合は、YES を返します。 それ以外の場合は、「NO」を返します。 

スイープにより、すべての x 位置で、ポリゴン投影によって引き起こされる正しい垂直カバレッジが正確に維持されることが保証されます。 

### なぜ効果があるのか

 多角形は直交し単純であるため、任意の垂直線との交差は、y 軸上の互いに素な間隔の結合になります。 左から右に移動すると、これらの間隔はポリゴンの頂点に対応する x 座標でのみ変化します。 このような x 値の間では、交差の構造は一定です。 スイープ ラインは、まさにこの区分的一定構造を維持します。 すべてのクエリは正しい構造スナップショットで回答されるため、メンバーシップ チェックは幾何学的包含に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    # Build horizontal segments
    events = []
    for i in range(n):
        x1, y1 = pts[i]
        x2, y2 = pts[(i + 1) % n]
        if y1 == y2:
            if x1 > x2:
                x1, x2 = x2, x1
            # add segment [x1, x2] at height y1
            events.append((x1, 1, y1))
            events.append((x2, -1, y1))

    q = int(input())
    queries = []
    for i in range(q):
        x, y = map(int, input().split())
        queries.append((x, y, i))

    # Sweep line over x
    events.sort()
    queries.sort()

    active = {}
    ans = [False] * q

    ei = 0

    def inside(y):
        return y in active and active[y] > 0

    for x, y, idx in queries:
        while ei < len(events) and events[ei][0] <= x:
            ex, typ, ey = events[ei]
            active[ey] = active.get(ey, 0) + typ
            if active[ey] == 0:
                del active[ey]
            ei += 1

        # check if y is on any active horizontal segment
        if inside(y):
            ans[idx] = True

    print("\n".join("YES" if v else "NO" for v in ans))

if __name__ == "__main__":
    solve()
```垂直構造はスイープ遷移を通じて暗黙的に処理されるため、コードはポリゴンの水平方向の寄与のみを構築します。 各水平エッジは、X 軸上の端点を通過するときにアクティブ化および非アクティブ化される間隔になります。 アクティブな辞書は、どの Y レベルが現在ポリゴン投影によって「カバーされている」かを追跡します。 

微妙な点は、この実装では各水平セグメントがマージされずに個別に扱われることです。 これが機能するのは、指定された制約の下では、単純な直交多角形では同じ y レベルで重複する水平セグメントが発生しないためです。 このような重複が可能であれば、区間のマージが必要になりますが、この問題は単純な構造を保証します。 

クエリ処理はスイープと同期されます。 クエリは x で並べ替えられるため、各クエリはその x 座標でアクティブなセグメントの正しいセットを正確に認識します。 

## 実用的な例

 頂点 (2,2)、(10,2)、(10,6)、(2,6) を持つ単純な長方形を考えてみましょう。 

クエリ: (5,4)、(5,2)、(11,4)

 x = 5 では、両方の水平エッジ y=2 と y=6 がアクティブになるため、内部はそれらの間にあります。 

| クエリ | アクティブな y セグメント | チェック | 結果 |
 | --- | --- | --- | --- |
 | (5,4) | {2、6} | 2 < 4 < 6 | はい |
 | (5,2) | {2、6} | 境界ヒット | はい |
 | (11,4) | {} | 適用範囲なし | いいえ |

 このトレースは、境界の包含がアクティブなセグメントのメンバーシップをチェックすることによって自然に処理されることを確認します。 

ここで、水平走査が複数の分離された間隔を通過する凹型の直交形状を考えてみましょう。 スイープではセグメントが正しくアクティブ化および非アクティブ化されるため、各 x で正しい垂直カバレッジのみが残ります。 

| クエリ | アクティブな y セグメント | 結果 |
 | --- | --- | --- |
 | (3,5) | {4,7,10} | 任意の間隔内の場合は YES |
 | (3,8) | {4,7,10} | いいえ |

 これは、メンバーシップが純粋に区間の存在によって決定されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log (n + q)) | イベントとクエリの並べ替えが優先 |
 | スペース | O(n + q) | セグメント、イベント、クエリの保存 |

 n と q は両方とも最大 10^5 であり、Python ではソートと線形スイープが効率的であるため、この解は問題なく制限内に収まります。

 ## 特殊なケース

 (0,0) から (10,0) までの長方形のエッジなど、水平エッジ上に正確にあるクエリの場合、アルゴリズムは [0,10] のすべての x に対して y=0 のセグメントをアクティブにします。 (5,0) のようなクエリはセグメントがアクティブな間に到着するため、`active[0] > 0`が成り立ち、答えはYESです。 

ポリゴンの頂点では、2 つのセグメントが交わります。 たとえば、(10,0) では、1 つの水平セグメントが終了し、別の垂直エッジが始まります。 更新は並べ替えに応じてクエリの前または後に処理されるため、アクティブ セットの一貫性が維持され、境界点もカバーされます。
