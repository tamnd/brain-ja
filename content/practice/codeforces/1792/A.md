 ## 解決策
 ## 問題の理解

 私たちは、Monocarp がそれぞれ特定の健康値を持つ一連のモンスターを倒すために必要な呪文のキャストの最小数を決定するように求められています。 Monocarp には 2 つの呪文があります。1 つは 2 匹の異なるモンスターの体力を同時に 1 減らすもので、もう 1 つは 1 匹のモンスターを即座に殺すものです。 目標は、できるだけ少ない詠唱ですべてのモンスターを倒す方法でこれらの呪文を順番に並べることです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースに対して、モンスターの数と、それに続く健康値のリストが与えられます。 各テスト ケースの出力は単一の整数、つまり必要な呪文の最小数です。 

制約は比較的小さく、1 つのテスト ケース内のモンスターの数は最大 100 で、すべてのテスト ケースにわたるモンスターの合計は最大 20,000 です。 これにより、テスト ケースあたり最大約 O(n^2) までのアルゴリズムは快適に実行できますが、O(n^3) に近づくと非効率になり始める可能性があります。 各モンスターの健康状態は最大でも 100 であり、これは、並べ替え、貪欲な選択、または基本的な算術操作に応じた解決策が効率的に実行されることを示唆しています。 

モンスターの体力が著しくアンバランスである場合、単純なアプローチは失敗する可能性があります。 たとえば、体力のあるモンスターが 3 匹いるとします。`[1, 1, 100]`, 2 モンスターの呪文の最初の 2 つを貪欲にペアにするのは効率的ですが、最大の体力を考慮せずにモンスターのペアを繰り返し試行すると、単一モンスターの呪文を何度も使用することになり、合計数が最適ではない結果になる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、可能なすべての呪文発動シーケンスを試します。つまり、生きているモンスターのペアごとに 2 モンスターの呪文を適用し、単一のモンスターに対して 1 モンスターの呪文を適用できます。 これにより膨大な数の状態が生成され、各モンスターの健康状態は最大 100 であるため、潜在的な状態の数は最悪の場合でも 100^100 のオーダーになります。 これは明らかに手に負えないものです。 

重要な洞察は、2 モンスターの呪文が適用できる場合には常により効率的であることを理解することです。 各詠唱は 2 匹のモンスターの体力を合わせて 2 減らしますが、単一モンスターの呪文では 1 つしか減りません。 したがって、最適な戦略は常に 2 体のモンスターの呪文を最大限に活用しようとすることになります。 総合的な健康という観点から考えると、`H`すべてのモンスターの体力の合計を次のようにします。`M`個人の健康を最大限に高めること。 呪文の最小数は 2 つの事実によって制約されます。すべての呪文は最大 2 ヘルス ポイント (モンスター 2 体呪文の場合) を減少させるため、少なくとも必要です。`ceil(H/2)`呪文; また、モンスターはそれ以下の時間で倒すことはできません。`M`最悪の場合、キャストごとに体力を 1 より早く減らすことはできないためです。 したがって、キャストの最小総数は次のようになります。`max(ceil(H/2), M)`。 

この洞察は、テスト ケースごとの O(n) 解にすぐにつながります。つまり、ヘルス値と最大ヘルスの合計を計算し、合計の半分 (切り上げ) と最大ヘルスの最大値を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * H) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 これにより、複数のシナリオにわたるループが設定されます。 
2. 各テストケースについて、モンスターの数を読み取ります。`n`。 
3. モンスターの体力値のリストを読みます。 
4. 合計を計算します`total_health`あらゆる健康上の価値観。 これは必要な「ダメージ」の合計を表します。 
5. 最大の健康状態を見つける`max_health`すべてのモンスターの中で。 これにより、単一のモンスターの体力が呪文のキャスト数を超えることがなくなります。 
6. コンピューティング`ceil(total_health / 2)`これは、2 モンスターの呪文がキャストごとに 2 ヘルス ポイントを減らすという事実を考慮したものです。 整数演算では、これは次のようになります。`(total_health + 1) // 2`。 
7. 結果は次のとおりです。`max(max_health, (total_health + 1) // 2)`。 これにより、両方の制約が満たされることが保証されます。つまり、総体力を減らすのに十分なキャストと、最強のモンスターを排除するのに十分なキャストが得られます。 
8. 結果を印刷します。 

機能する理由: 2 つの制約 (全体的な健全性と最大の健全性) がシステムのボトルネックを捉えます。 どのアルゴリズムも、これらの制限よりも少ないキャスト数を使用することはできません。2 匹のモンスターの呪文は、キャストごとに 2 ポイントより早く合計を減らすことができず、唯一残っている強力なモンスターの場合、キャストごとに 1 ヘルスより早く死ぬモンスターは存在しないからです。 1 体だけが残るまで常に 2 体のモンスターの呪文を適用するという貪欲な選択は、最大値の公式に暗黙的にエンコードされています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    h = list(map(int, input().split()))
    total_health = sum(h)
    max_health = max(h)
    result = max(max_health, (total_health + 1) // 2)
    print(result)
```このソリューションは、テスト ケースの数を読み取り、それぞれを反復処理し、正常性値の合計と最大値を計算して、結果を計算します。 使用する`(total_health + 1) // 2`奇数の合計を正しく丸めることができます。 このソリューションでは、ヘルス配列の保存以外に O(1) 個の追加スペースが使用されます。

 このアルゴリズムは、すべてのテスト ケースにわたる合計 20,000 のモンスターの制約を容易に処理し、合計/最大あたり約 20,000 の操作を実行します。これは 2 秒の制限を大幅に下回ります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))
        total_health = sum(h)
        max_health = max(h)
        result = max(max_health, (total_health + 1) // 2)
        output.append(str(result))
    return "\n".join(output)

# provided samples
assert run("3\n4\n1 2 1 2\n3\n2 4 2\n5\n1 2 3 4 5\n") == "3\n4\n5", "sample 1-3"

# custom cases
assert run("1\n1\n100\n") == "100", "single monster max health"
assert run("1\n2\n1 1\n") == "1", "smallest total health even"
assert run("1\n2\n1 2\n") == "2", "smallest total health odd"
assert run("1\n5\n5 5 5 5 5\n") == "13", "all equal large health"
assert run("1\n3\n1 100 1\n") == "100", "dominant monster"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\n1\n100\n`| 100 | 単一のモンスター、最大体力は合計に等しい |
 |`1\n2\n1 1\n`| 1 | 最小の総健康状態、偶数 |
 |`1\n2\n1 2\n`| 2 | 最小合計健康状態、奇数 |

## 特殊なケース

 モンスターが 1 匹の場合、答えはその体力と同じになります。 例えば、`[100]`生成する`100`。 アルゴリズムは計算します`max(100, ceil(100/2)) = 100`。 

すべてのモンスターの体力が等しい場合、たとえば`[5, 5, 5, 5, 5]`、合計は 25、`ceil(25/2) = 13`、最大値は 5 で、出力は 13 です。これは、モンスターを 2 匹の呪文で効率的にペアリングすることを正しく説明しています。 

1 つのモンスターが全体を支配している場合、`[1, 100, 1]`、合計は 102、`ceil(102/2) = 51`ですが、最大値は 100 です。100 回のキャストよりも早く最強のモンスターを倒すことはできないため、アルゴリズムは正しく 100 を出力します。
