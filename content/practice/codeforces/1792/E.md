 ## 解決策
 ## 問題の理解

 私たちは、$n \times n$各セルが配置される九九$(i, j)$値が含まれています$i \cdot j$。 このテーブルは明示的に構築されません。 代わりに、その中にどの数字が含まれているかを推論します。 

各テストケースには番号が与えられます$m = m_1 \cdot m_2$。 すべての約数を考慮します$m$。 各約数について$d$かどうかを尋ねます。$d$九九のどこかに表示され、指数が存在するかどうかを意味します$i, j$そのような$1 \le i, j \le n$そして$i \cdot j = d$。 表示される場合は、可能な限り小さい行インデックスも考慮します。$i$このような因数分解が存在します。 

最終的な出力は、回答の完全なリストではありません。 代わりに、テーブルに現れる約数の数と、すべての約数に対する対応する最小行インデックスの XOR だけが必要です。 

重要な難点は、$n$と同じ大きさにすることができます$10^9$したがって、テーブルを反復処理したり、すべての候補因数分解を素朴な方法で反復したりすることはできません。 すべての約数を反復しても、$m$これは、除数の生成を注意深く制御する場合にのみ実現可能です。$m$最大約まで持つことができます$10^4$最悪の場合は約数。 

素朴なアプローチでは、すべての約数を試してしまうでしょう$d$、次に考えられるすべての因子のペアをスキャンします$(i, j)$が必要となるため、これは不可能です。$O(n)$または$O(n^2)$テストケースごとに作業します。 

さらに微妙な失敗は、因数分解を 1 つだけチェックした場合に発生します。 たとえば、次の場合$d = 12$そして$n = 6$、有効なペアには以下が含まれます$(2, 6)$、$(3, 4)$、$(4, 3)$、 そして$(6, 2)$。 最小行は$2$、 ない$3$または$4$。 すべての因子ペアにわたって行を明示的に最小化しない解決策は間違っています。 

もう 1 つのエッジ ケースは、すべての約数が超過した場合です。$n$。 その場合、たとえカウントと XOR の両方の答えがゼロでなければなりません。$m$大きくて高度に複合的なものになる可能性があります。 

## アプローチ

 直接的なアプローチは、次のすべての約数を生成することから始まります。$m$。 因数分解するだけなので、これはすでに管理可能です$m_1$そして$m_2$そして、それらの約数を結合するか、同等の因数分解を行います。$m$直接。 約数リストを取得したら、各約数について$d$、因子のペアを見つけようとします$(i, j)$そのような$i \cdot j = d$、 両方$i, j \le n$、 そして$i$最小化されます。 

すべてのペアを試してみると、次の結果が得られます。$O(\sqrt{d})$約数あたり、約$O(\sum \sqrt{d})$、潜在的に遅すぎる場合$m$大きくて高度に複合的です。 

重要な観察は、固定除数の場合です。$d$、私たちが選択するなら$i$、 それから$j = d / i$。 両方ともそうである必要があります$\le n$、つまり$i \le n$そして$d / i \le n$、 それで$i \ge \lceil d / n \rceil$。 したがって、有効な$i$値は制限された間隔内にあります。$$\lceil d/n \rceil \le i \le \min(n, \lfloor \sqrt{d} \rfloor)$$この範囲内の候補者のみをテストする必要があります。 すべての約数にわたって平均すると範囲が小さく、各約数が独立しているため、これは効率的になります。 

また、構造化された因子生成を通じてすべての約数を事前計算することで、すべての約数を盲目的にスキャンすることも避けます。 

最終的な解決策は、約数を列挙し、それぞれの行インデックスの候補の小さなセットをスキャンすることになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.因数分解$m = m_1 \cdot m_2$素因数に変換します。 これを行うには、両方の数値を別々に因数分解し、指数を結合します。 これは積のすべての約数が必要なため必要です。 
2. 素因数分解から、次のすべての約数を生成します。$m$。 これは、各素数から指数の寄与を選択することによって再帰的に行われます。 これにより、完全にソートされた除数リストが生成されます。 
3. 各約数について$d$、最小の行インデックスを見つけようとします。$i$列が存在するように$j = d/i$両方とも$i \le n$そして$j \le n$。 これは、$n \times n$制約。 
4. 最小有効行を効率的に計算するには、反復のみを行います。$i$から始まる$\lceil d/n \rceil$まで$\min(n, \lfloor \sqrt{d} \rfloor)$。 下限により列制約が満たされることが保証され、上限により冗長な対称チェックが回避されます。 
5. 有効なものが見つかった場合$i$、この約数の答えを最小値として更新します。$i$。 存在しない場合は記録します$0$。 
6. ゼロ以外の答えを持つすべての約数の数を維持し、そのようなすべての最小行インデックスの XOR を計算します。 

### なぜ効果があるのか

 有効な表現の場合$d = i \cdot j$と$i, j \le n$、少なくとも 1 つ$i, j$は$\le \sqrt{d}$。 したがって、最小の行インデックスは常に次の領域に存在する必要があります。$\sqrt{d}$、そしてより大きな候補者を考慮する必要はありません。 制約$i \ge \lceil d/n \rceil$列インデックスが強制的に超過する行を選択しないようにします$n$。 この制限は実現可能性を完全に特徴付けるものであるため、すべての有効なペアは制御された範囲内で 1 回だけ考慮され、最小行が存在する場合は常に検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import isqrt

def factorize(x):
    res = {}
    d = 2
    while d * d <= x:
        while x % d == 0:
            res[d] = res.get(d, 0) + 1
            x //= d
        d += 1
    if x > 1:
        res[x] = res.get(x, 0) + 1
    return res

def gen_divisors(primes):
    divs = [1]
    for p, e in primes.items():
        cur = []
        pe = 1
        for _ in range(e + 1):
            for d in divs:
                cur.append(d * pe)
            pe *= p
        divs = cur
    divs.sort()
    return divs

t = int(input())
for _ in range(t):
    n, m1, m2 = map(int, input().split())
    m = m1 * m2

    primes = factorize(m)
    divs = gen_divisors(primes)

    ans = []
    cnt = 0
    xr = 0

    for d in divs:
        best = 0

        if d <= n * n:
            start = (d + n - 1) // n
            limit = min(n, isqrt(d))

            i = start
            while i <= limit:
                if d % i == 0:
                    j = d // i
                    if j <= n:
                        best = i
                        break
                i += 1

        if best:
            cnt += 1
            xr ^= best

    print(cnt, xr)
```因数分解のステップでは素数と指数の辞書を構築し、すべての約数を系統的に再構築できるようにします。 除数ジェネレータは組み合わせを段階的に拡張し、フルセットを管理しやすく保ちます。 

各約数について、可能な行値の狭い有効な間隔を計算します。 最初の有効な要素が見つかると、ループは直ちに停止します。実行可能な最小の候補から上向きに反復するため、この要素は最小の行であることが保証されます。 

小切手`d <= n * n`因子のペアがテーブル内に収まらない可能性がある場合に、不必要な作業を防止します。

 ## 特殊なケース

 いつ$n = 1$、テーブルには値のみが含まれます$1$。 約数のみ$1$は寄与する必要があり、他のすべてはたとえ割ってもゼロになる必要があります$m$。 アルゴリズムはこれを正しく適用します。$d > 1$条件に失敗します$d \le n^2$、すぐに破棄します。 

いつ$m$は素数、約数はのみ$1$そして$m$。 もし$m > n$、 のみ$1$貢献します。 ループは引き続き両方の約数を生成しますが、実現可能性チェックにより除外されます。$m$したがって、XOR には有効なエントリのみが含まれます。 

いつ$m$大きいですが$n$は小さい、ほとんどの約数は超過$n^2$。 このチェックにより、不必要な因子スキャンが防止され、実行時間が総除数数ではなく実際の実行可能な除数に主に依存することが保証されます。
