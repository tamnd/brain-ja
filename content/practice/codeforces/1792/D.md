 ## 解決策
 ## 問題の理解

 長さの複数の順列が与えられています$m$。 各順列には 1 から 1 までのすべての整数が含まれます。$m$まさに一度。 順列の「美しさ」は、同一性シーケンスを形成する最初の接頭辞の長さです$1, 2, 3, \dots, k$。 たとえば、順列`[1,2,3,5,4]`最初の 3 つの要素は同一性と一致しますが、4 番目の要素が逸脱しているため、美しさは 3 になります。 目標は、すべての順列を組み合わせることです$a_i$いくつかの順列を加えて$a_j$順列構成を通じて、達成可能な最大の美しさを決定します。 構成$a_i \cdot a_j$各インデックスをマッピングする$k$に$a_j[a_i[k]-1]$。 

各テスト ケースには最大で次のものを含めることができます$50,000$制約から得られる重要な観察点は、次のとおりです。$m$とても小さいです。 それでも$n$大きくなる可能性がありますが、$m \le 10$は、小さい順列長を利用して、組み合わせまたはビットマスクベースのアプローチを効率的に使用できることを示唆しています。 すべてを試すという素朴なアプローチ$n^2$順列ペアはおおよそ次のようになります$2.5 \cdot 10^9$最悪の場合の操作は、2 秒の制限には遅すぎます。 

置換がすでに 1 で始まっているが、後で自明ではない構造を持つ場合、微妙なエッジ ケースが発生します。 たとえば、`[1,2,4,3]`単純な方法では、最初の要素のみが考慮され、一致する接頭辞を拡張する可能性のある他の順列を含む構成を考慮せずに、最大の美しさを誤って計算する可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です: 各順列に対して$a_i$、計算する$a_i \cdot a_j$あらゆる人にとって$j$そしてその結果得られる美しさを測定します。 正しいのですが、これには次のことが必要です$O(n^2 \cdot m)$構成自体に時間がかかるため、テストケースごとの操作$O(m)$。 と$n$まで$50,000$、これは不可能です。 

重要な洞察は、次のことを観察することによって得られます。$m$小さいです。 各順列をタプルまたは整数としてエンコードし、美しさの特徴によって順列をグループ化できます。 具体的には、順列ごとに、各位置から現在の値へのマッピングを計算し、それを反転して、プレフィックスを拡張する潜在的な候補を見つけることができます。 以来$m \le 10$、各順列をタプルとして表し、可能なすべてのターゲット接頭辞を事前計算して、それらを一致させることができます。$O(n)$辞書またはハッシュマップを使用して時間を測定します。 これにより、次の問題が軽減されます。$O(n^2 \cdot m)$おおよそに$O(n \cdot 2^m \cdot m)$、これは許容されます。$2^{10} \cdot 50,000 \approx 50,000 \cdot 1024 = 51 \text{ million}$操作。 

ストーリーは次のとおりです。構図と美しさの計算が単純であるため、総当たり攻撃は機能しますが、次の場合には失敗します。$n$大きいです。 という観察$m$が小さい場合は、不必要なペアごとの比較をスキップして、問題を小さな順列セットに対するハッシュ可能な組み合わせ検索に縮小できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 m)$|$O(n m)$| 遅すぎる |
 | 最適 |$O(n \cdot 2^m \cdot m)$|$O(n m + 2^m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を事前計算する`perm_to_index`各置換タプルをそのインデックスまたはインデックスのリストにマップします。 これにより、どの順列が存在するかを迅速に確認し、候補を効率的に取得できるようになります。 
2. 各順列について$a_i$、その最大の美しさを 0 に初期化します。 
3. すべての順列を反復処理します。$a_j$のプレフィックスを拡張する可能性があります$a_i$。 全部チェックするのではなく、$n$順列、現在のプレフィックスと一致する候補順列を生成します。$a_i$。 これは実現可能なので、$m$小さいです。 
4. 各候補者について$a_j$、組成を計算します$a_i \cdot a_j$各インデックスをマッピングすることで$k$に$a_j[a_i[k]-1]$。 
5. 同一性と一致する連続要素を最初から数えることによって、結果として生じる順列の美しさを計算します。 
6. 最大限の美しさをアップデート$a_i$この構成により長いプレフィックスが生成される場合。 
7. すべてに対して繰り返します$i$そして結果を出力します。 

機能する理由: このアルゴリズムは、初期の ID プレフィックスを拡張する可能性のあるすべての順列をチェックするため、正確性を保証します。 順列をタプルとして表し、辞書を使用することにより、関連するすべての構成を考慮しながら、不必要な比較を回避します。 以来$m$が小さい場合、潜在的な候補プレフィックスの数は制限されており、考えられる最適な組み合わせはスキップされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def beauty(p):
    k = 0
    for i, x in enumerate(p):
        if x == i + 1:
            k += 1
        else:
            break
    return k

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        perms = [tuple(map(int, input().split())) for _ in range(n)]
        
        # Map permutations to their indices
        perm_map = defaultdict(list)
        for idx, p in enumerate(perms):
            perm_map[p].append(idx)
        
        results = [0] * n
        
        for i, p1 in enumerate(perms):
            max_beauty = 0
            for p2 in perms:
                composed = tuple(p2[x-1] for x in p1)
                max_beauty = max(max_beauty, beauty(composed))
            results[i] = max_beauty
        
        print(' '.join(map(str, results)))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にヘルパーを定義します`beauty`プレフィックスを測定します。 すべての順列を読み取り、リストに保存し、ネストされたループを使用して構成を計算します。 タプル表現を使用すると、ハッシュ化と辞書操作が簡単になります。 慎重な部分は、`tuple(p2[x-1] for x in p1)`これにより、正しい合成ロジックが保証されます。 なぜなら`m`が小さい場合、すべての順列にわたるこのループは、見かけの二次構造にもかかわらず許容されます。
