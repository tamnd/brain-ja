 ## 解決策
 ## 問題の理解

 私たちには都市の木が与えられています。 2 人が 2 つの異なるノードから開始します。1 人は警察、もう 1 人はあなたです。 毎秒、二人は同時に隣接する都市に移動するか、その場に留まり、両方ともその木について完全な知識を持っています。 いつでも同じ都市を占領したり、同じ秒間に同じ端を反対方向に横断したりすると、すぐに捕らえられます。 

クエリごとに、双方が最適に行動すると仮定して、どれくらいの時間捕獲を回避できるかを計算する必要があります。警察はあなたを捕まえる時間を最小限に抑えようとするのに対し、あなたはそれを最大にしようとします。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは、n 個のノードと q 個のクエリを含むツリーを与え、各クエリは警察とプレイヤーの開始位置を与えます。 出力はクエリごとに 1 つの整数であり、最適なプレイでの生存時間を秒単位で表します。 

この制約により、合計で最大 200,000 個のノードと 200,000 個のクエリが許可されるため、ツリー全体を走査して各クエリを処理するソリューションは即座に除外されます。 各ステップには両方のプレイヤーの分岐選択肢が含まれ、木の高さは線形になる可能性があるため、動きの単純なシミュレーションも不可能です。 

主要な構造特性は、グラフがツリーであるため、2 つのノード間には単純なパスが 1 つだけ存在するということです。 これは、ゲームツリーのシミュレーションではなく、距離とツリーの形状が答えを制御する必要があることを強く示唆しています。 

微妙なエッジケースは、一方のプレイヤーが他方のプレイヤーのサブツリーから開始する場合です。 たとえば、あなたとあなたが移動するディープノードとの間の経路上にすでに警察がいる場合、たとえ距離が遠かったとしても、即座に衝突することを余儀なくされる可能性があります。 もう 1 つのエッジ ケースは、両方が隣接して開始する場合です。距離が 1 であっても、エッジを越えて同時に移動するため、キャプチャは 1 秒以内に発生する可能性があります。 

よくある間違いは、答えが単にノード間の距離の半分であると仮定すること、または両方のプレイヤーが最短経路で互いに向かって移動しているだけであると仮定することです。 これが失敗するのは、最適なプレイが非対称であるためです。警察はあなたの正確な位置を追跡する必要はなく、あなたが通る可能性のあるルートを傍受するだけで済みます。 

## アプローチ

 ブルートフォース解釈では、これをツリー上での 2 人プレイの最短パス ゲームとして扱います。 (自分の位置、警察の位置) によって定義される各状態から、両方のプレイヤーが同時に動きを選択します。 各状態の次数が両方のノードの次数にほぼ比例するゲーム グラフを探索します。 初期状態からの BFS またはミニマックス検索は、すべての可能性をシミュレートし、最も早い強制衝突を計算します。 

ゲーム グラフは時間的に有限で非循環的であるため、これは原理的に機能し、拡張された状態空間内の最短経路が答えを与えます。 ただし、状態空間のサイズは O(n^2) であり、各状態は O(deg(u) * deg(v)) の可能性で遷移します。 注意深く枝刈りしたとしても、これは n が 200,000 までの場合には大きすぎます。 

重要な観察は、木の上で重要なのは、警察が逃げ道に沿って阻止する頂点を占領して、プレーヤーを木の残りの部分からどれだけ早く「引き離す」ことができるかということだけだということです。 すべての位置を追跡する代わりに、私たちは問題を両プレーヤーから、それらの間の一意の経路上で戦略的に選択された合流地点までの距離の比較に落とし込みます。 

ツリーをルート化し、バイナリのリフティングと深さを事前計算すると、O(1) で LCA と距離を計算できます。 最適な生存時間は、プレイヤーが到達する前に、またはプレイヤーが到達すると同時に、警察がプレイヤーからのパス上の頂点に到達できるかどうかによってのみ決まります。 これにより、問題は、動きをシミュレートするのではなく、木のパス上のいくつかの距離の比較を評価することに変換されます。

最終的な結論は、答えは、両方が最短経路に沿って最適に移動するという制約の下で、プレーヤーが到着時間において厳密に警察より先に留まることができる 2 つのノード間の経路に沿った最長点に依存するということです。

 | --- | --- | --- | --- |
 | ブルート フォース ゲーム BFS | O(n²) | O(n²) | 遅すぎる |
 | ツリー + LCA 距離推論 | O((n + q) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意のノード (通常は 1) でツリーをルートし、LCA クエリの深さとバイナリ リフティング テーブルを計算します。 これにより、深さと LCA を使用して、任意の 2 つのノード間の距離を定数で計算できます。 
2. 各クエリ (a, b) について、LCA(a, b) を使用してそれらの間の一意のパスを暗黙的に計算します。 このパスの構造は、警察とプレイヤーの間のすべての最適な対話を制限するものです。 
3. 距離 d = dist(a, b) を計算します。 警察とプレイヤーがすでに同じノードにいる場合、答えは 0 です。警察とプレイヤーが隣接している場合、同時に移動すると即座に会うため、答えは 1 になります。 
4. パスの中間点の構造を考慮します。 警察は、プレイヤーが経路に沿って厳密に先頭を維持しようとする一方で、プレイヤーの脱出フロンティア上のノードに到達する時間を最小限に抑えることを目指しています。 クリティカル値は、b から外側へのパスに沿ったノード上でプレイヤーが持つ最大時間的優位性です。 
5. a と b の間の固有のパスに沿って、プレーヤーはパスの 2 つの方向のいずれかに沿って警察から離れることを効果的に選択できることに注目してください。 警察はいつでも迎撃距離を最小にする方向を選択できます。 これにより、ゲームはツリーに埋め込まれた長さ d の線分上のレースに縮小されます。 
6. 線分上で、最適なプレーは既知の結果をもたらします。両方が同じ速度で最適に動いた場合、集合時間はfloor((d + 1) / 2)です。 これは、衝突または交差が発生するまで、残りの距離が 1 秒ごとに最大 2 ずつ減少するという事実から来ています。 
7. したがって、答えは d / 2 の上限であり、(d + 1) // 2 と書くことができます。 

### なぜ効果があるのか

 不変条件は、t 秒後、警察は常に、少なくともプレイヤーがそのルートに到達する限り、プレイヤーから可能なすべての逃走ルートの近くに留まらなければならないということです。 ツリー上では、すべてのエスケープ ルートは 2 つの開始ノード間の一意のパス上の頂点を通過します。 両方のプレーヤーは単位速度で移動するため、このパスに沿った相対的な進行は、直線上で互いに向かって移動する 2 つのポインターのように動作します。 いかなる迂回路も固有のボトルネック パスに沿った効果的な分離を減少させるだけであるため、分岐を選択しても、極限パスに留まることで達成される生存時間よりも長い生存時間を生み出すことはできません。 これにより、インタラクションは一次元の追跡に強制的に崩壊し、集合時間は純粋に最初の距離の同等性と同時の移動によって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    LOG = (n).bit_length()
    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    # iterative DFS
    stack = [1]
    parent = [0] * (n + 1)
    parent[1] = 1

    order = []
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)

    for i in range(1, n + 1):
        up[0][i] = parent[i]

    for k in range(1, LOG):
        for i in range(1, n + 1):
            up[k][i] = up[k - 1][up[k - 1][i]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for k in reversed(range(LOG)):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]
        return up[0][a]

    def dist(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    q = int(input())
    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        d = dist(a, b)
        out.append(str((d + 1) // 2))

    print("\n".join(out))

t = int(input())
for _ in range(t):
    solve()
```実装は、ツリーの隣接リストを構築し、バイナリ リフティングを使用して祖先を前処理することから始まります。 DFS は深さと直接の親を確立し、それらは完全なスパース テーブルに持ち上げられます。 

LCA 関数はまず深さを均等化し、次に祖先が一致するまで両方のノードを 2 の最高乗から下方に持ち上げます。 LCA が利用可能になると、標準の深さの計算式を使用して距離が計算されます。 

各クエリは、2 つの開始ノード間のツリー距離を計算し、導出された閉じた形式 (d + 1) // 2 を使用してその距離を生存時間に変換することに要約されます。 

一般的な実装の落とし穴は、LCA の深さ調整ステップ、特にビット反復順序の混合を誤って処理することです。 もう 1 つの微妙な問題は、リフティング中のインデックス 0 ジャンプを避けるために、parent[1] をそれ自体に初期化する必要があることを忘れていることです。

このトレースは、ツリー内の分岐が、一意のパスによって課せられる根底にある 1 次元の制約からどちらの側も逃れるのに役立つわけではないことを確認します。

 ## 特殊なケース

 チェーン内の a = 1、b = 2 のような直接隣接の場合は、両方が同時に移動し、1 秒後に出会うため、距離が 1 であっても答えが 0 になることはないことがわかります。 (1 + 1) // 2 は 1 に等しく、強制衝突と一致するため、アルゴリズムはこれを処理します。 

a が一方の終点、b がもう一方の終点である長い直鎖は、分岐が無関係であることを示しています。 ツリーに多くのサブツリーが含まれる場合でも、固有のパスを離れることによって最適なプレイが得られることは決してないため、距離に基づく削減は引き続き有効です。
