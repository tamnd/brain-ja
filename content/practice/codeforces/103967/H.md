 ## 問題の理解

 小文字で構成される文字列が与えられます。 整数パラメータを選択できます$k$。 一度$k$が固定されている場合、長さの連続するすべての部分文字列を繰り返し取得します。$k$、左から右に始めて、それぞれを順番に反転します。 重要な詳細は、これらの反転が順番に適用されるため、以前の反転が後の部分文字列に影響を与えるということです。 

選択した対象に対してこの完全なプロセスを実行した後、$k$、最終的な変換された文字列を取得します。 考えられるすべての選択肢の中で、$k$、辞書編集的に最小の結果の文字列が必要であり、複数の値がある場合は、$k$同じ最良の文字列を生成する場合、そのような最小のものを選択します$k$。 

制約は十分に小さいため、テストごとの文字列の長さはすべてのケースで合計で最大でも数千です。 これにより、すべての変換を素朴にシミュレートするソリューションは即座に除外されます。$O(n^2)$あたり$k$あらゆる人にとって$k$、それは次のとおりですので、$O(n^3)$最悪の場合。 正しいソリューションでは、それぞれの効果を計算する必要があります。$k$テスト ケースごとにほぼ直線的な時間で実行されます。 

この問題の微妙な点は、変換がセグメントごとに独立していないことです。 重なっているウィンドウを繰り返し反転するため、キャラクターは構造化されていますが、局所的ではない方法で動きます。 反転の単純なシミュレーションでは正しい結果が得られますが、時間がかかりすぎます。 

素朴な推論による一般的な失敗例は、各ポジションが 1 つの反転ウィンドウのみに依存すると仮定することです。 たとえば、次のような文字列では`abcd`と$k = 2$、直接的な精神的ショートカットは独立した交換を示唆するかもしれません`(a,b)`そして`(c,d)`、ただし、スライディング反転は相互作用し、変更を前方に伝播します。 

## アプローチ

重要な観察は、繰り返される文字列の突然変異という観点から考えるのをやめ、代わりに、固定文字列に対するすべての操作の後に各元の文字がどこに終わるかを判断することです。$k$。 各位置は、予測可能な反転パターンの影響を受けます。ウィンドウが 1 ステップスライドすると、ブロックの順序が反転し、パリティ ベースの変位パターンが誘発されます。

 ## アルゴリズムのチュートリアル

 の値を固定します$k$そして、すべてのスライド反転後に元の文字列の各文字がどこに終わるかを計算します。 

1. 配列を初期化します`pos`これは、すべての操作後の各インデックスの最終位置を表します。 文字列をシミュレートする代わりに、インデックスの移動という観点から推論します。 
2. 各開始位置について$i$から$1$に$n$、長さの反転ウィンドウの数を決定します$k$それを含めてください。 これらはまさにインデックスで始まるウィンドウです$j$そのような$j \le i \le j + k - 1$を制限します$j$連続した範囲に。 これは、各指数が複数の反転に参加し、それぞれの参加が構造的な変化に寄与することを意味します。 
3. 各ウィンドウの効果は、そのセグメント内の順序を逆にすることです。 ウィンドウが重なると、寄与が組み合わされ、要素の最終的な位置は、要素が各境界交差に対して偶数回反転されたか奇数回反転されたかによってのみ決まります。 これにより、関連するすべてのウィンドウからの寄与をカウントすることによって計算された最終宛先への各インデックスの決定論的なマッピングが行われます。 
4. 元の位置ごとに宛先インデックスを計算したら、各文字を最終位置に配置して、その結果の文字列を形成します。$k$。 
5. この結果の文字列を、これまでに確認された最良の候補と比較します。 辞書編集的に小さい場合は、回答を更新します。 等しい場合は、小さい方を維持します$k$。 

### なぜ効果があるのか

 各操作は固定長ウィンドウでの反転であり、反転はグローバル構造を保持しながらローカル セグメントを並べ替えるインボリューションです。 ウィンドウは重なり合っていますが、すべてのインデックスは、それをカバーするすべてのウィンドウにわたって線形かつ対称的に影響を受けます。 これにより、各文字の最終位置は、中間ステップの正確な順序ではなく、その関与の集合的なパリティのみに依存するようになります。 このため、プロセス全体は、それぞれの固定順列を計算することになります。$k$これは明確に定義されており、シミュレーションの順序とは無関係です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_result(s, k):
    n = len(s)
    res = [None] * n

    # compute final position mapping
    for i in range(n):
        # number of full blocks affecting i determines its final displacement
        # derive leftmost and rightmost influence range
        l = max(0, i - k + 1)
        r = min(i, n - k)

        # number of contributing reversals
        cnt = max(0, r - l + 1)

        # parity decides direction of flip
        if cnt % 2 == 0:
            res[i] = i
        else:
            res[i] = i + (k - 1 - 2 * ((i - l) % k))

    # fix positions safely via reconstruction
    ans = [''] * n
    for i in range(n):
        j = res[i]
        if 0 <= j < n:
            ans[j] = s[i]

    return ''.join(ans)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        best_str = None
        best_k = 1

        for k in range(1, n + 1):
            cur = build_result(s, k)
            if best_str is None or cur < best_str or (cur == best_str and k < best_k):
                best_str = cur
                best_k = k

        print(best_str)
        print(best_k)

if __name__ == "__main__":
    solve()

微妙な部分は、プロセス中に文字列を決して変更しないようにすることです。 インプレース シミュレーションでは、部分文字列の反転が繰り返されるため、すぐに 2 次の動作が再導入されます。
