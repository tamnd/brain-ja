 ## 解決策
 ## 問題の理解

 私たちには、感動的な王冠を掴もうとしているプレイヤーのグループがいます。 王冠は静止していません：高さから始まります`0`、高さまで上に移動します`H`、高さまで下に移動します`0`、この動作を永遠に繰り返します。 クラウンの高さが最大であれば、プレーヤーは目的地に到着したときにすぐにクラウンを掴むことができます。`h`。 それ以外の場合、プレーヤーはリューズが十分に下がるまで待ちます。 

入力は各プレーヤーを 2 つの値で表します。`x_i`プレイヤーが目的地に到着する時刻です。`c_i`は、ゲーム システムによって追加される追加のネットワーク遅延です。 プレイヤーが物理的に王冠を掴んだ場合`t`、ゲームはそのプレイヤーのグラブ時間を次のように記録します。`t + c_i`。 勝者は記録タイムが最も小さいプレーヤーであり、複数のプレーヤーが同じ記録タイムを持っている場合は、インデックスが最も小さいプレーヤーが勝ちます。 

課題は、リューズの動きを毎秒シミュレートすることではありません。 到達できるプレイヤーの数`2 * 10^5`1 つのテスト ケースに含めることができ、最大 20 のテスト ケースを含めることができます。 すべてのプレイヤーの将来の多くの瞬間をチェックするアルゴリズムは、簡単に数十億の操作に達する可能性があります。 各プレーヤーの最初のグラブの瞬間を定数で計算する必要があります。 

リューズの動きの周期が非常に短いため、`H`最大でも 300 です。完全なサイクルが続きます`2H`秒。 この小さな境界は、長いシミュレーションを維持する代わりに、1 サイクルについて直接推論できることを意味します。 

トリッキーなケースは、動きの正確な境界から発生します。 

たとえば、クラウンが最大の高さに達したときにプレーヤーが到着した場合、次のようになります。```
1
1 2 5
5
10
```王冠が高いところにある`5`時に`5`よりも大きい`h = 2`, そのため、プレイヤーは待つ必要があります。 次に許容される瞬間は、クラウンが高さまで下がったときです`2`、時間に`8`。 記録された時間は、`18`、したがって、答えは次のようになります。```
1
```クラウンが下にあるかどうかだけを確認するいい加減な解決策`h`下に移動した後、ピークを許容可能な点として誤って扱う可能性があります。 

もう 1 つの境界ケースは、プレイヤーがちょうどクラウンが許容可能な高さにあるときに到着する場合です。```
1
1 2 5
2
10
```時間に`2`、クラウンの高さは正確に`2`、平等が許可されます。 プレイヤーはすぐに掴むので、答えは次のようになります。```
1
```次のような厳密な比較を使用した解決策`< h`プレイヤーを誤って遅らせてしまう可能性があります。 

最後のエッジケースは次のような場合です`h = H`:```
1
1 5 5
100
7
```王冠は決して高くありません`5`、したがって、すべての到着はすぐに成功します。 答えは次のとおりです。```
1
```常に待機期間があることを前提としたアプローチは、ここでは失敗します。 

## アプローチ

 直接的な解決策は、王冠の動きをシミュレートし、すべてのプレーヤーにいつそれを掴むことができるかを尋ねることです。 クラウンは継続的に変化するため、将来、その高さがすべてのプレイヤーにとって受け入れられる最初の瞬間を決定する必要があります。 秒ごとにシミュレーションすると、1 人のプレイヤーに最大で`2H`チェックは小さいですが、すべてのプレイヤーに対してこれを実行しても、`O(nH)`操作。 と`n = 200000`そして`H = 300`とすると、テスト ケースごとに約 6,000 万のチェックが行われることになりますが、これは Python ではすでに不快であり、不必要です。 

重要な観察は、クラウンが繰り返し三角波をたどっていることです。 1 ピリオド内のプレーヤーの位置を知る必要があるだけです。 サイクルの長さは`2H`。 各サイクル中、クラウンは一定の時間から許容されます`0`に`h`起きながら、そして時間から`2H-h`に`2H`落ちながら。 

到着時間に関しては`x`、 させて`r = x mod (2H)`。 もし`r`すでに許容可能な間隔のいずれかに入っている場合、プレイヤーはすぐに掴みます。 それ以外の場合、プレーヤーはクラウンが高すぎる中央セクションのどこかにいます。 次に許容される瞬間は常に高さの下降点です`h`、サイクル位置で発生します`2H-h`。 したがって、待ち時間は単純に距離です。`r`に`2H-h`。 

これにより、問題全体がプレーヤーごとに 1 つの計算式を計算することになります。 クラウンには予測可能なサイクルがあるため、ブルート フォースは機能しますが、多くのプレイヤー間で何度も繰り返されるため失敗します。 周期構造により、シミュレーションを完全にスキップできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nH) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各プレーヤーについて、最初の物理的なグラブ時間を計算します。 させて`period = 2H`そして`r = x_i mod period`。 値`r`クラウンが現在のサイクル内のどこにあるかを示します。 
2. クラウンがすでに到達可能かどうかを確認します。 これは次のような場合に起こります。`r <= h`または`r >= 2H - h`。 その場合、プレイヤーの物理的なグラブ時間は単純に`x_i`。 
3. クラウンが高すぎる場合、プレーヤーはクラウンが高さまで下がるまで待つ必要があります。`h`。 次の瞬間はサイクル位置にあります`2H - h`したがって、物理的なグラブ時間は次のようになります。```
x_i + (2H - h - r)
```1. プレイヤーの遅延を追加する`c_i`記録されたグラブ時間を取得します。 現在のベストアンサーと比較してください。 このプレイヤーが先に勝った場合、または記録された時間が同じでこのプレイヤーのインデックスが小さい場合は、答えを置き換えます。 

### なぜ効果があるのか

 リューズの動きは毎分繰り返されます`2H`したがって、考えられるすべての状況は、そのサイクル内の到着時間の残りによって完全に決定されます。 掴めるのはクラウン高さが最大の2区間のみ`h`。 プレーヤーがこれらのインターバルの外にいる場合、次に到達可能な瞬間は、次の許容インターバルの最初のポイントでなければなりません。これはまさに高さの下降交差点です。`h`。 アルゴリズムはすべてのプレーヤーの可能な限り早いグラブの瞬間を計算し、正確な同点ルールを適用するため、選ばれたプレーヤーが勝者であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, h, H = map(int, input().split())
        x = list(map(int, input().split()))
        c = list(map(int, input().split()))

        period = 2 * H
        best_time = None
        best_id = None

        for i in range(n):
            r = x[i] % period

            if r <= h or r >= period - h:
                grab = x[i]
            else:
                grab = x[i] + (period - h - r)

            total = grab + c[i]

            if best_time is None or total < best_time or (total == best_time and i < best_id):
                best_time = total
                best_id = i

        ans.append(str(best_id + 1))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```あるプレイヤーの待機時間は別のプレイヤーのクラウン インタラクションに影響を与えないため、このソリューションはプレイヤーを独立して処理します。 変数`r`現在のクラウン サイクル内の位置を保存し、動きのシミュレーションを回避します。 

条件`r <= h or r >= period - h`クラウンの高さが正確に一致するときにプレーヤーがグラブできるため、両方のエンドポイントが含まれます。`h`。 等式が欠けていると、境界ケースで誤った答えが生じる可能性があります。 

クラウンが高すぎる場合の計算式は、`period - h - r`常にポジティブです。 結果は、下降側が高さに到達するまでの正確な残り時間です。`h`。 

比較ではネクタイも慎重に扱います。 Python 配列のインデックスは 0 ですが、問題ではプレイヤーの番号が 1 から始まるため、保存されているインデックスは印刷時にのみ 1 ずつ増加します。

 ## 特殊なケース

 プレイヤーがクラウンの動きの最高点に正確に到達すると、残りは次のようになります。`H`。 もし`h < H`、これは到達不可能な中間区間内にあります。 例えば：```
1
1 2 5
5
10
```残りは`5`、次に到達可能な位置は`8`したがって、物理的なグラブ時間は次のようになります。`8`。 アルゴリズムは同じ結果に達します。`5`せいぜいどちらでもない`2`少なくとも`8`。 

ちょうどクラウンが高くなっているときにプレーヤーが到着したとき`h`、グラブはすぐに許可されます。 のために：```
1
1 2 5
2
10
```残りは`2`、を満たす`r <= h`。 このアルゴリズムは、不必要な待ち時間を追加するのではなく、到着時間を維持します。 

いつ`h = H`、あらゆる可能なクラウン高さが許容されます。 のために：```
1
1 5 5
100
7
```期間は`10`、すべての残りが最大でも次のいずれかであるため、条件は常に成功します。`5`または少なくとも`5`。 プレイヤーは必要に応じてすぐに掴みます。
