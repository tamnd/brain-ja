 ## 解決策
 # 問題の理解

 この問題は、燃えているグリッドの中を移動するランナーを表しています。 ランナーは左上のセルから開始し、右下のセルに到達する必要があります。 各セルには一定量の新鮮な空気が含まれています。 陽性細胞は吸い込むことができますが、非陽性細胞には煙が含まれており、ランナーが息を止めていない限り入ることはできません。 

移動は常に下、右、または右斜め下に進むため、パスはグリッドを通る有向非循環パスになります。 息止めセッションを開始するには費用がかかります`U`空気を通し、煙を通過できるのは最長でも`K`動く。 目標は単に脱出することではなく、出口に到達した後に残る空気の量を最大化することです。 

グリッドの寸法は両方に達することができます`1000`、すべてのテスト ケースのすべてのグリッド セルの合計は次の値に達します。`7 * 10^6`。 パスの数は指数関数的に増加するため、すべての可能なパスを探索するアルゴリズムは不可能です。 すべての位置について、可能なすべての前のセルをチェックする動的プログラムさえも存在するでしょう。`O(N^2M^2)`最悪の場合、限界をはるかに超えてしまいます。 セル数が線形に近い解決策が必要です。 

主なエッジケースは、通常の動きと呼吸のジャンプの間の相互作用から生じます。 パスは煙に入る前に息を止め始める必要がある場合があり、以前の最良の位置は、煙の中のはるか遠くにある場合があります。`K`による`K`隣接する 3 つのセルの 1 つではなく、長方形になります。 

例えば：```
1 3 2 5
10 0 10
```答えは`15`。 隣接する陽性セルのみを考慮する不注意な解決策は、ランナーが中央の煙セルを横切るために空気を費やす必要があるため、失敗します。 

もう一つのケースは次のような場合です。`K`グリッド サイズより大きいです:```
2 2 10 3
5 0
0 7
```答えは`9`。 呼吸の継続時間が正確であると仮定するソリューション`K`移動により、先に停止する有効なパスが拒否される場合があります。 

## アプローチ

 直接動的プログラミング ソリューションは簡単に定義できます。 させて`dp[i][j]`セルに到達した後に残っている空気の最大値である`(i,j)`。 現在のセルに空気が含まれている場合は、通常の 3 つの先行セルから到達できます。 また、以前に到達可能なセルから息を止め始めることもできます。`K`行と`K`列、支払い`U`現在のセルの空気を追加します。 

再発は正しいですが、呼吸の移行にはコストがかかります。 すべてのセルについて、最大でスキャンします`K*K`可能な開始位置。 以来`K`と同じ大きさにすることができます`10^9`、これは実質的に前のグリッド全体のスキャンであり、遅すぎます。 

重要な観察は、呼吸の移行には最大限の効果のみが必要であるということです。`dp`スライドする長方形内の値。 行ごとにスキャンしている間、この長方形は常に一度に 1 ステップずつ移動します。 単調キューを使用すると最大値を維持できます。 

すべての列について、最後からの有用な開始位置を含む両端キューを保持します。`K`行。 デックは次のように減少しています`dp`値なので、その前がその列の最良の候補になります。 次に、現在の行全体で別の両端キューを維持して、最後の列の中から最適な列を取得します。`K`列。 これら 2 つの構造を組み合わせることで、最大限の効果が得られます。`dp`全体の価値`K`による`K`一定の償却時間でのウィンドウ。 

すべての有効な呼吸開始がチェックされるため、ブルート フォースは機能しますが、グリッドが大きくなると失敗します。 遷移がスライディング最大値であるという観察により、何百万回も繰り返される比較を 2 つの単調なキューに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM * K²) | O(NM) | 遅すぎる |
 | 最適 | O(NM) | お(お) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを上から下、左から右に処理します。 セルのすべての先行処理がすでに処理されているため、この順序は移動ルールと一致します。 
2. すべての陽性セルについて、まず息を止めずに遷移を計算します。 考えられる 3 つの前のセルは、上のセル、左側のセル、および対角のセルです。 到達可能な最大値を取得した後、現在のセルの空気を追加します。 
3. 呼吸セッションを開始できる以前のセルを含む列デキューを維持します。 以上のエントリを削除します。`K`何列も離れています。 デックは最大値を維持します`dp`なぜなら、弱い候補者は後で役に立たないからです。 
4. アクティブな列からの最適な候補を含む行デックを維持します。 以上の列を削除します。`K`列が離れています。 この両端キューの先頭は、現在のセルで終了するブレス セッションの最良の開始点です。 
5. 現在のセルが正であり、有効な呼吸開始が存在する場合、更新します。`dp[i][j]`その開始からの値をマイナスしたもの`U`、次に現在のセルの空気を追加します。 
6. 計算後`dp[i][j]`、空気が少なくとも残っている場合にのみ、列デクに挿入します。`U`。 値が小さいとコストを支払うことができないため、呼吸セッションを開始できません。 

これが機能する理由: 不変条件は、すべての両端キューに、現在のスライディング ウィンドウ内にある有用な到達可能なセルが正確に含まれており、最適な候補が常に先頭になるように順序付けされていることです。 古いエントリを削除すると距離の制限が保持され、支配的なエントリを削除すると最大値が保持されます。これは、有効期限が遅い場合の悪い値は、同じまたは早い有効期限のより大きな値に勝つことができないためです。 考えられるすべての遷移が表現されるため、計算された`dp`値は常に可能な限り最良の空気量です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve_case(n, m, k, u, grid):
    cols = [deque() for _ in range(m)]
    dp_prev = [-1] * m
    ans = -1

    for i in range(n):
        row_best = deque()
        dp_cur = [-1] * m

        for j in range(m):
            while cols[j] and cols[j][0][0] < i - k:
                cols[j].popleft()

            while row_best and row_best[0][1] < j - k:
                row_best.popleft()

            if grid[i][j] > 0:
                best = -1

                if i == 0 and j == 0:
                    best = 0

                if i > 0 and dp_prev[j] >= 0:
                    best = max(best, dp_prev[j])

                if j > 0 and dp_cur[j - 1] >= 0:
                    best = max(best, dp_cur[j - 1])

                if i > 0 and j > 0 and dp_prev[j - 1] >= 0:
                    best = max(best, dp_prev[j - 1])

                if row_best:
                    best = max(best, row_best[0][0] - u)

                if best >= 0:
                    dp_cur[j] = best + grid[i][j]

            if dp_cur[j] >= u:
                while cols[j] and cols[j][-1][1] <= dp_cur[j]:
                    cols[j].pop()
                cols[j].append((i, dp_cur[j]))

            if cols[j]:
                value = cols[j][0][1]
                while row_best and row_best[-1][0] <= value:
                    row_best.pop()
                row_best.append((value, j))

            if i == n - 1 and j == m - 1:
                ans = dp_cur[j]

        dp_prev = dp_cur

    return ans

def main():
    out = []
    data = sys.stdin.buffer.read().split()
    ptr = 0

    while ptr < len(data):
        n = int(data[ptr])
        m = int(data[ptr + 1])
        k = int(data[ptr + 2])
        u = int(data[ptr + 3])
        ptr += 4

        grid = []
        for _ in range(n):
            row = list(map(int, data[ptr:ptr + m]))
            ptr += m
            grid.append(row)

        out.append(str(solve_case(n, m, k, u, grid)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```実装では、前の行のみが保存されます。`dp`なぜなら、通常の遷移では真上または斜め上のセルのみが必要だからです。 列デキューには行インデックスが格納されるため、距離が より大きくなったときに期限切れの状態を削除できます。`K`。 

挿入順序は重要です。 セルは、それ自体の値が計算された後にのみ呼吸開始点として使用する必要があるため、現在のセルのすべての遷移が終了した後にキューに追加されます。 これにより、長さゼロのブレス動作を誤って許可してしまうことを防ぎます。 

可能な最大残留空気は 32 ビット制限を超える可能性があるため、すべての値は Python 整数として保存されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | すべてのセルは、各単調キューに 1 回ずつ出入りします。 |
 | スペース | お(お) | DP の 1 行と列キューのみが保存されます。 |

 このアルゴリズムは、各グリッド セルに一定回数タッチします。これは、数百万セルの合計制限に適合します。 メモリ使用量は、グリッド全体ではなく列の数に依存します。

import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    idx = 0
    ans = []

    while idx < len(data):
        n, m, k, u = map(int, data[idx:idx + 4])
        idx += 4
        grid = []
        for _ in range(n):
            grid.append(list(map(int, data[idx:idx + m])))
            idx += m

        ans.append(str(solve_case(n, m, k, u, grid)))

    return "\n".join(ans)

 ## 特殊なケース

 開始セルから息を止めて始まるパスが処理されます。`(1,1)`は通常どおり DP プロセスに挿入されます。 ケース```
1 3 2 5
10 0 10
```最初のセルから最後のセルへのブレストランジションを作成します。 デキュー ウィンドウには、開始状態、減算が含まれます。`U`、そして最後の空気を加えます。 

呼吸セッションがより早く終了する`K`移動は有効です。 で```
2 2 10 3
5 0
0 7
```ランナーは 10 分間すべてを費やす必要はありません。 スライディング ウィンドウは最大距離を制限するだけなので、安全なセルに到達した後の通常の移行は引き続き利用可能です。 

残りの空気が少ないセルは、その値が少なくとも`U`。 これにより、ランナーが十分な空気がない状態で息を止めてスタートしようとするような不可能なトランジションが発生するのを防ぎます。
