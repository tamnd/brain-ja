 ## 問題の理解

 この問題は、ベクトルかどうかを尋ねます。`B`初期ベクトルから取得できる`A`2 つの許可された移動を繰り返し適用します。現在のベクトルを時計回りに 90 度回転するか、固定ベクトルを追加します。`C`現在のベクトルに。 回転と加算は任意の順序で組み合わせることができ、何度でも使用できます。 タスクは、そのような一連の操作が存在するかどうかを判断することです。 

すべてのベクトルの座標は次のように大きくなります。`10^8`絶対値で言うと。 これにより、必要な加算数が非常に多くなる可能性があり、シーケンスの長さに上限がないため、演算数に基づくシミュレーションが除外されます。 解決策は演算の代数構造を使用し、一定時間内に完了する必要があります。 

隠れた主な問題は、回転操作によって将来の追加の方向が変わることです。 かどうかを確認するだけのシンプルなアプローチ`B - A`の倍数です`C`回転によって新しい方向の移動が可能になるケースを見逃します。 

最初のエッジケースは次のような場合です。`C`はゼロベクトルです。 例えば：```
Input
0 0
1 1
0 0
```答えは次のとおりです。```
NO
```どれだけ回転を実行しても、ゼロ ベクトルはゼロのままであるため、到達可能なベクトルは 4 回転のみです。`A`。 長さで割る方法です。`C`有効な除数がないため、ここでは失敗します。 

もう 1 つのエッジ ケースは、ターゲットで何かを追加する前に開始ベクトルの回転が必要になる場合があります。 例えば：```
Input
1 0
0 -1
0 0
```答えは次のとおりです。```
YES
```回転中`(1, 0)`時計回りに与える`(0, -1)`。 元の位置からの追加のみをチェックするメソッドでは、これが誤って拒否されてしまいます。 

3 番目のエッジ ケースは、必要な動きが回転されたコピーによってのみ可能になる場合です。`C`キャンセルまたは結合します。 例えば：```
Input
0 0
1 0
0 1
```答えは次のとおりです。```
YES
```ベクトル`(1,0)`を追加することで取得できます`(0,1)`座標系を時計回りに 3 回回転すると、回転加算によってすべての垂直方向が作成されるため、効果が得られます。 オリジナルの倍数のみをチェックする`C`失敗するだろう。 

## アプローチ

 直接的な総当りの解決策では、回転と加算の可能なすべてのシーケンスが試行されます。 このアイデアの問題は、意味のある停止点がないことです。 シーケンスには任意の数の加算を含めることができ、考えられるすべての演算順序の検索は指数関数的に増加します。 検索を固定操作数に制限することさえ正当化できません。 

有益な観察は、回転が周期的であるということです。 時計回りに 4 回回転すると、ベクトルは元の方向に戻ります。 すべての演算が完了すると、初期ベクトルが`A`可能な最終形式は 4 つだけです。```
A
R(A)
R^2(A)
R^3(A)
```どこ`R`時計回りに90度回転します。 

追加もローテーションを考慮すると理解しやすくなります。 すべて追加されました`C`後でローテーションされる可能性があるため、すべての加算の寄与合計は次の整数の組み合わせとなります。```
C
R(C)
R^2(C)
R^3(C)
```最後の 2 つは最初の 2 つのマイナスであるため、これは次によって生成された格子と同じです。`C`そして`R(C)`。 

考えられる最終的な向きごとに、`A`の違いがあるかどうかを確認するだけで済みます。`B`そしてその方向はこの格子に属します。 

させて：```
C = (x, y)
R(C) = (y, -x)
```ベクトル`(u, v)`整数が存在する場合、この格子内にあります`p`そして`q`次のような:```
p * (x, y) + q * (y, -x) = (u, v)
```このシステムの行列は、その二乗がスカラー行列であるため特別です。```
[x  y] [x  y]   [x²+y²  0]
[y -x] [y -x] = [0      x²+y²]
```これにより係数が得られます。```
p = (x*u + y*v) / (x² + y²)
q = (y*u - x*v) / (x² + y²)
```残っている唯一のことは、両方の分子が次で割り切れるかどうかを確認することです。`x² + y²`。

 ## アルゴリズムのチュートリアル

 1. 3 つのベクトルを読み取る`A`、`B`、 そして`C`。 すべての計算は浮動小数点演算を行わずに正確に実行できるため、座標を整数として保存します。 
2. もし`C`は`(0, 0)`、可能な 4 つの回転を確認します。`A`。 加算では何も行われないため、回転のみが可能です。 
3. コンピューティング`x² + y²`のために`C = (x, y)`。 この値は、2 つの格子基底ベクトルの決定的な大きさです。 これは、整数係数を回復するために使用される分母でもあります。 
4. 可能な 4 つの最終回転をすべて試してください。`A`。 それぞれについて、差分ベクトルを計算します。`D = B - rotated_A`。 
5. かどうかを確認します。`D`の整数の組み合わせとして書くことができます`C`そしてその時計回りの回転。 必要な 2 つの割り算チェックは次のとおりです。```
x*D.x + y*D.y
y*D.x - x*D.y
```両方とも割り切れる必要があります`x² + y²`。 

1. いずれかの回転が格子テストに合格した場合、出力します。`YES`。 4 つすべてが失敗した場合は、印刷します`NO`。 

それが機能する理由: すべての有効な操作シーケンスは、概念的に最後のローテーションに再配置できます。`A`の回転バージョンの合計を加えたもの`C`。 回転には 4 つの可能な状態しかなく、回転された状態の可能な合計はありません。`C`ベクトルは、によって生成された整数格子を正確に形成します。`C`そして`R(C)`。 このアルゴリズムは、考えられるすべての回転状態をチェックし、その格子の正確なメンバーシップ条件を使用するため、到達可能なすべてのベクトルを受け入れ、到達できないすべてのベクトルを拒否します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rotate(v):
    x, y = v
    return (y, -x)

def possible(a, b, c):
    cx, cy = c

    if cx == 0 and cy == 0:
        cur = a
        for _ in range(4):
            if cur == b:
                return True
            cur = rotate(cur)
        return False

    den = cx * cx + cy * cy

    cur = a
    for _ in range(4):
        dx = b[0] - cur[0]
        dy = b[1] - cur[1]

        p_num = cx * dx + cy * dy
        q_num = cy * dx - cx * dy

        if p_num % den == 0 and q_num % den == 0:
            return True

        cur = rotate(cur)

    return False

def solve():
    a = tuple(map(int, input().split()))
    b = tuple(map(int, input().split()))
    c = tuple(map(int, input().split()))

    print("YES" if possible(a, b, c) else "NO")

if __name__ == "__main__":
    solve()
```の`rotate`関数は時計回りの 4 分の 1 回転を直接実装します。 これを 4 回適用すると元のベクトルに戻るため、メイン ループの反復は 4 回だけで済みます。 

ベクトルがゼロの場合は、格子の分母がゼロになるため、別個に処理されます。 いつ`C`がゼロの場合、使用できる操作は回転のみであるため、4 つの方向を確認するだけで十分です。 

ゼロ以外の場合`C`、変数`den`常にポジティブです。 Python 整数には任意の精度があるため、割り算チェックは浮動小数点精度の問題を回避し、大きな座標でも正しく機能します。 

二つの表現`p_num`そして`q_num`2 by 2 線形システムを解くことから得られます。 各格子方向が使用される回数は整数でなければならないため、両方を均等に分割する必要があります。

 ## 特殊なケース

 いつ`C`がゼロの場合、アルゴリズムは格子計算に入りません。 のために：```
0 0
1 1
0 0
```の4回転`(0,0)`すべてです`(0,0)`、 それで`(1,1)`到達できず、アルゴリズムが戻ります`NO`。 

の回転時`A`が必要な場合は、4 つの状態チェックによって直接処理されます。 のために：```
1 0
0 -1
0 0
```最初のチェックはベクトルが異なるため失敗しますが、2 番目の回転により次の結果が得られます。`(0,-1)`、一致します`B`。 

答えが回転加算の組み合わせに依存する場合、格子テストはそれを捕捉します。 のために：```
0 0
1 0
0 1
```生成された方向は`(0,1)`そして`(1,0)`ネガは追加の回転によって利用可能になります。 必要な動きは格子内にあるため、アルゴリズムは次の値を返します。`YES`。
