 ## 解決策
 ## 問題の理解

 この問題では、2 値空間の重要な点を表す一連の個別の整数が得られます。 選択した 2 つの点間の距離は、バイナリ表現が異なるビット位置の数、つまり XOR のポップカウントです。 この距離をエッジの重みとして使用して、これらの点に最小スパニング ツリーを構築し、合計の重みとツリー構造を必要な順序で出力する必要があります。 

値は以下の値で制限されています$2^{18}$, したがって、すべての数値は 18 ビットのみを使用して表現できます。 付与できるポイント数は$2 \times 10^5$これにより、すべてのペアごとのエッジの構築が除外されます。 完全なグラフには大まかに次の内容が含まれます。$n^2$エッジ、約$4 \times 10^{10}$最悪の場合の比較。 このソリューションでは、多数のポイントではなく、小さなビット次元を利用する必要があります。 主要な制約と意図されたアプローチは、元の問題の制限に基づいています。$n \le 2 \times 10^5$そして$a_i < 2^{18}$。 

いくつかの特殊なケースでは、直接実装が中断される可能性があります。 2 つの数値が 1 ビットだけ異なる場合、それらの距離は 1 であり、このエッジは可能のままでなければなりません。 たとえば、入力ポイントが次の場合、`1`そして`3`、バイナリ形式は次のとおりです。`01`そして`11`、したがって、距離は`1`。 より大きな差異のみをチェックする方法では、最も安価な接続を見逃してしまいます。 

中間値が元の点の 1 つではない場合、別の問題が発生します。 元の点が次のとおりであるとします。`0`そして`7`。 それらの直線距離は 3 であるため、`000`そして`111`どこでも異なります。 値`1`は入力ポイントではありませんが、接続されます`0`そして`7`ハイパーキューブ構造を通して。 元の点をグラフ ノードとしてのみ考慮するソリューションでは、この有用な構造を発見できません。 

すべての値がビット空間内で近い場合も重要です。 入力に ​​1 ビット異なる数値が多数含まれている場合でも、有用な候補エッジの数は少ないままでなければなりません。 すべてのペアを生成すると、小規模なテストは静かに合格しますが、大規模で密なケースでは失敗します。 

## アプローチ

 自然な最初の試みは、元の点のすべてのペアをエッジとして扱うことです。 各ペアについて、XOR のポップカウントを計算し、それをエッジの重みとして追加します。 クラスカルのアルゴリズムは、最小スパニング ツリーを見つけることができます。 これが機能するのは、完全なグラフには考えられるすべての接続が含まれており、MST が存在することが保証されているためです。 

問題は辺の数です。 と$n$ポイント、グラフには次のものが含まれます$n(n-1)/2$エッジ。 のために$n=200000$、このあたりです$2 \times 10^{10}$エッジは保存や処理が不可能です。 

有益な観察は、数値が 18 次元のバイナリ超立方体内に存在するということです。 すべての値には、1 ビットだけ異なる隣接する値が 18 個だけあります。 すべての元の点間のグラフを作成する代わりに、すべての点を考慮することができます。$2^{18}$ハイパーキューブの頂点として可能なビット パターン。 

元の点は、この超立方体内の特別な頂点です。 すべての元の点から開始するマルチソース BFS は、すべてのハイパーキューブの頂点をその最も近い元の点に割り当てます。 2 つの領域がハイパーキューブ エッジを横切って接する場合、それらの領域を所有する 2 つの元の点の間に MST エッジの可能性があることがわかりました。 このような候補エッジの数は、超立方体のサイズにのみ比例します。$2^{18}$、各頂点には 18 個のトランジションがあります。 

ブルート フォースは、考えられるすべての接続を探索するため機能しますが、完全なグラフが大きすぎるために失敗します。 ハイパーキューブ観察により、MST を維持しながら、多くの等価パスを小さな候補エッジのセットに圧縮できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 \log n)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O((2^{18} \cdot 18 + n)\log(2^{18}))$|$O(2^{18}+n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.全体のグラフを作成する$2^{18}$可能なビットマスク。 1 つのビットを正確に反転することで一方をもう一方に変換できる場合、2 つのマスクは接続されます。 これらはバイナリ超立方体のエッジです。 
2. すべての入力番号からマルチソース BFS を開始します。 ハイパーキューブの各頂点について、最初に到達した元の点のインデックスを保存します。 
3. BFS 中に、既に異なる元の点に属している 2 つの頂点をエッジが接続する場合は常に、それらの 2 つの元の点の間に候補エッジを作成します。 その重みは、2 つの元の値間のハミング距離です。 
4. すべての候補エッジに対して Kruskal のアルゴリズムを実行します。 エッジが 2 つの異なるコンポーネントを接続する場合は、必ずそれを最終ツリーに追加します。 
5. 選択されたエッジが最小スパニング ツリーを形成します。 結果のツリーをトラバースして、必要な親の順序を生成します。 

BFS 圧縮が有効である理由は、バイナリ値間のあらゆる可能な移動がハイパーキューブによって表現されるためです。 2 つの元の点が中間のハイパーキューブ頂点を介して接続する必要がある場合、その領域に割り当てられた最も近い元の点で接続を表すのに十分です。 2 つの BFS 領域間の境界は、常に、それらの領域の所有者間の可能な MST エッジに対応します。 

これが機能する理由: 不変条件は、すべてのハイパーキューブ頂点が、BFS 中に検出された最も近い元の点に属することです。 最適なスパニング ツリーが何らかの中間値を介した接続を使用する場合、所有されている 2 つの領域が最初に交わる場所で、それより大きな重みを持たないエッジが提供されます。 元の接続をこの境界エッジに置き換えると、ツリーの接続が維持され、コストが増加することはありません。 Kruskal は、そのような必要な境界すべての中で最も安価なエッジを選択するため、結果として得られるツリーは最適になります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        self.parent[a] = b
        return True

def solve():
    t = int(input())
    out = []

    LIMIT = 1 << 18

    while t:
        t -= 1
        n = int(input())
        a = list(map(int, input().split()))

        owner = [-1] * LIMIT
        q = deque()

        for i, x in enumerate(a):
            owner[x] = i
            q.append(x)

        edges = []

        while q:
            u = q.popleft()
            for b in range(18):
                v = u ^ (1 << b)
                if owner[v] == -1:
                    owner[v] = owner[u]
                    q.append(v)
                elif owner[v] != owner[u]:
                    x = owner[u]
                    y = owner[v]
                    w = (a[x] ^ a[y]).bit_count()
                    edges.append((w, x, y))

        edges.sort()

        dsu = DSU(n)
        tree = [[] for _ in range(n)]
        total = 0

        for w, u, v in edges:
            if dsu.union(u, v):
                total += w
                tree[u].append(v)
                tree[v].append(u)

        parent = []
        order = []

        def dfs(u, p):
            order.append(u)
            parent.append(p)
            for v in tree[u]:
                if v != p:
                    dfs(v, u)

        dfs(0, -1)

        out.append(str(total))
        out.append(" ".join(str(x + 1) for x in order))
        out.append(" ".join(str(x + 1 if x != -1 else 1) for x in parent))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`owner`配列には、ハイパーキューブの各頂点を担当する元の点が格納されます。 値は常に 18 ビットに収まるため、そのサイズは固定されており、完全な領域を安全に割り当てることができます。 

BFS は、すべての元の値で一度に開始されます。 これにより、割り当ては単一のソースからの距離ではなく、最も近い元の点を表すようになります。 

隣接する 2 つのハイパーキューブ頂点の所有者が異なる場合、アルゴリズムはそれらの所有者間の接続の可能性を追加します。 Kruskal は不要なエッジを破棄するため、重複したエッジは無害です。 

DSU 実装ではパス圧縮を使用するため、クラスカル フェーズはほぼ線形のままです。 最終的な DFS は、選択された無向 MST エッジをルート付きツリー表現に変換します。 ルートの親は次のように置き換えられます。`1`出力形式には有効な頂点インデックスが必要なためです。 

Python の整数は、XOR またはポップカウントの計算中にオーバーフローしません。 注意すべき唯一のインデックス作成境界はハイパーキューブのサイズです。これは正確に`1 << 18`。

## 複雑さの分析

## 特殊なケース

 2 つの値の場合`0`そして`1`、BFS はそれらの間のハイパーキューブ エッジをすぐに認識します。 このアルゴリズムは重み 1 の候補エッジを作成し、Kruskal がそれを選択して、唯一可能なスパニング ツリーを生成します。 

次のような値の場合、`0`そして`7`、直接ペアワイズ ビューでは距離 3 が表示されます。 超立方体には次のような中間状態が含まれます。`1`、`3`、 そして`7`、BFS は 2 つの領域間の境界を検出します。 結果として得られる候補エッジには正しいハミング距離があり、MST 構築で圧縮されたグラフを推論できるようになります。 

多くのポイントが存在する場合、アルゴリズムはすべてのペアを作成することはありません。 固定されたハイパーキューブ近傍のみを検査するため、互いに近い値が繰り返されても、それに比例してメモリが増加することはありません。$n^2$。 これにより、高密度入力でのタイムアウトという一般的な障害モードが防止されます。
