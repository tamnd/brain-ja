 ## 解決策
 # 問題の理解

 この問題は、道路で接続された一連の教室について説明しています。 どの教室のペアにも同じコストの可能な直接道路がありますが、最初はこれらの道路はどれも点灯していません。 道路の照明には 1 ドルかかります。 与えられた行列は、信号を灯す道路を選択した後、教室の各ペア間に存在する必要がある最短移動距離を示します。 

タスクは、結果として得られる道路網が指定された行列とまったく同じ最短経路距離を持つように、点灯する必要がある道路の最小数を見つけることです。 答えは、道路の全長ではなく、必要なエッジの最小数です。 

入力には、ファイルの終わりまでいくつかのテスト ケースが含まれています。 各テスト ケースは教室の数から始まり、その後に`N x N`マトリックス。 この行列は有効な距離システムを記述することが保証されています。つまり、最短経路距離がそれに一致するグラフが常に存在します。 制約により許可されるのは、`N`到達する`1000`、およびすべての合計`N`テスト ケース全体の値は最大でも`5000`。 すべてのテスト ケースに対して 3 次作業を実行するソリューションでは、最悪のケースでは約`10^9`操作。 行列自体の読み取りにはすでに必要があるため、二次時間に近いものが必要です。`O(N^2)`操作。 

主な罠は、指定された完全なグラフと構築する必要があるグラフを混同することから発生します。 マトリックス内ではすべてのペアに距離がありますが、すべての直線道路を維持する必要はありません。 

例えば：```
Input:
3
0 1 2
1 0 1
2 1 0
```正しい出力は次のとおりです。```
2
```教室には 3 つのペアがあるため、不用意にアプローチすると、考えられる 3 つの道路すべてがカウントされる可能性があります。 ただし、第 2 教室を通る通路はすでに長さがあるため、第 1 教室と第 3 教室の間の直通道路は不要です。`1 + 1 = 2`。 

もう 1 つのエッジ ケースは、複数の異なる最小ネットワークが可能である場合です。 目標は照らされた道路の数のみであるため、実際のエッジの選択は重要ではありません。```
Input:
4
0 5 10 15
5 0 5 10
10 5 0 5
15 10 5 0
```正しい出力は次のとおりです。```
3
```元の行列にエッジが現れるかどうかだけをチェックするソリューションでは、冗長なエッジが保持され、より大きな答えが得られる可能性があります。 必要な接続のみを維持することで、最短のパスを維持できます。 

# アプローチ

 直接的な強引なアイデアは、行列で表される完全なグラフを考慮し、最短経路距離が変わらないかどうかを確認しながら道路を 1 つずつ削除することです。 これは正しいです。なぜなら、答えは同じ距離行列を持つエッジの最小のサブセットを求めているからです。 ただし、`N(N-1)/2`可能性のある道路があるため、サブセットの試行は指数関数的になります。 考えられるすべての削除をチェックすることさえ、ずっと前に不可能になる`N=1000`。 

有益な観察は、必要なネットワークがまさに完全なグラフの最小スパニング ツリーであり、すべてのエッジの重みが 2 つの教室間の指定された距離であるということです。 その理由は少し特殊です。行列には、任意のエッジの重みではなく、最短経路距離がすでに含まれています。 

この完全なグラフの最小スパニング ツリーは次のようになります。`N-1`エッジ。 指定された距離は三角形のプロパティを満たすため、最小スパニング ツリーによって選択されたすべてのエッジは必要な接続であり、ツリーは元の距離を保存します。 追加のエッジは、その長さがすでにツリー内の端点間のパス以上であるため、冗長になります。 

したがって、問題はスパニング ツリーの最小サイズを見つけることになります。 接続されているすべてのグラフのスパニング ツリーは正確に`N-1`エッジの場合、距離行列が有効で接続されているかどうかだけを知る必要があります。 このステートメントは有効性を保証しているため、答えは単純に頂点の数から 1 を引いたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(N²) | 遅すぎる |
 | 最適 | O(1) 入力読み取り後 | お(1) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 値を読み取る`N`そして消費する`N x N`距離行列。 最終的な計算には値が必要ない場合でも、行列は入力形式の一部であるため、読み取る必要があります。 
2. 指定された距離は有効な接続グラフから得られることが保証されているため、接続に必要なエッジの最小数は`N`教室はスパニングツリーほどの大きさです。 
3. 出力`N - 1`、すべてのスパニング ツリー上にあるため、`N`頂点には、頂点よりもちょうど 1 つ少ないエッジが含まれます。 

なぜ効果があるのか:

 元のグラフには多くの可能な道路が含まれている可能性がありますが、接続されたグラフはいつでも頂点を切断することなくスパニング ツリーに縮小できます。 スパニングツリーには正確に`N - 1`エッジ。 入力によって距離行列が実現可能であることが保証されるため、すべての最短距離を保存するツリーが存在するため、以下の距離を含む解は存在しません。`N - 1`エッジが存在する可能性があります。 下限と構造が一致しているため、`N - 1`最低限の答え。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    ans = []
    while True:
        line = input()
        if not line:
            break
        line = line.strip()
        if not line:
            continue

        n = int(line)

        for _ in range(n):
            input()

        ans.append(str(n - 1))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```プログラムは回答リストを保存するだけです。 有効性が保証されているため、最短パスの計算は必要ないため、行列行は読み取られた直後に破棄されます。 

問題には先頭のテスト数のない複数のテスト ケースが含まれているため、入力ループは EOF まで継続します。 行列の各行は、次のケースに向けて入力ストリームを調整するために引き続き消費されます。 

出力される最大値は次のとおりであるため、整数オーバーフローの懸念はありません。`N - 1`、 そして`N`せいぜい`1000`。

# 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N²) | 距離行列の読み取りが作業を支配します。 
| スペース | お(1) | カウンタと出力ストレージのみが維持されます。 

入力自体に次のものが含まれるため、二次読み取りコストは避けられません。`N²`数字。 合計から`N`テスト ケース全体が制限されている場合、ソリューションはその制限内に簡単に収まります。 

# テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    data = []
    input = sys.stdin.readline

    while True:
        line = input()
        if not line:
            break
        line = line.strip()
        if not line:
            continue
        n = int(line)
        for _ in range(n):
            input()
        data.append(str(n - 1))

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.getvalue()

0 1 2
1 0 1
2 1 0
""") == "2", "sample"

assert run("""1

""") == "0", "single classroom"

assert run("""4

1 0 1 2
2 1 0 1
3 2 1 0
""") == "3", "chain distances"

10 5 0 5 10 15
