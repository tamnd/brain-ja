 ## 解決策
 ## 問題の理解

 この問題は、正の整数に対する変換を定義します。 数字の場合`x`、その 10 進表現のすべての接尾辞を取得し、それらの接尾辞の値をすべて乗算し、積の剰余を減らします。`x + 1`。 この結果は、`f(x)`。 あとは繰り返し申請していきます`f`、タスクは最初のを追加することです`m`このプロセスによって生成される値。 

たとえば、現在値が`1023`、接尾辞は次のとおりです。`3`、`23`、`23`、 そして`1023`したがって、次の値はこれらの数値の積を法としたものになります。`1024`。 

入力値が大きいため、開始番号と反復回数の両方が最大になる可能性があります。`10^9`。 直接シミュレーション`m`1 つのテスト ケースで 10 億回の関数評価が必要になる可能性があるため、このようなステップは不可能です。 ソリューションは、関数のサイズではなく関数のプロパティを利用する必要があります。`m`。 

重要な観察結果は、`f(x)`常に範囲内にあります`[0, x]`、剰余モジュロであるため`x + 1`。 値が変化しない場合、シーケンスは固定点に達しています。 それ以外の場合は厳密に減少します。 非負の整数の厳密に減少するシーケンスを永久に続けることはできないため、すべての開始値は最終的に固定点に到達します。 

不注意に実装すると、場合によっては失敗する可能性があります。 もし`x`は 1 桁で、接尾辞は数字自体だけなので、結果は次のようになります。`x % (x + 1) = x`。 入力の場合:```
3 4
```シーケンスは`3, 3, 3, 3`、したがって、答えは次のとおりです`12`。 永久に数を減らそうとし続ける実装は決して終了しません。 

ゼロで終わる値も間違いやすいです。 例えば：```
10 3
```接尾辞は次のとおりです。`0`そして`10`、したがって積はゼロであり、`f(10)=0`。 順序は`0, 0, 0`、答えを与える`0`。 ゼロ接尾辞を無視するコードは、不正なゼロ以外の値を生成する可能性があります。 

3 番目のケースは、数回のリダクション後に開始値がすでに固定点になっている場合です。 たとえば、2 番目のサンプルは最終的に安定した値に達します。 アルゴリズムは、不必要な反復を実行する代わりに、シミュレーションを停止し、残りのカウントにその固定値を乗算する必要があります。 

## アプローチ

 ブルートフォース ソリューションは文字通り定義に従います。 それぞれについて、`m`要求された用語に対して、小数点の接尾辞を計算し、それらを乗算し、モジュロ演算を適用して、次の値に移動します。 これは正確に再発に従っているので正しいです。 

ただし、このアプローチは以下に依存します。`m`、 そして`m`できる`10^9`。 一つの評価でも`f`は非常に小さいため、テスト ケースあたり 10 億の評価は許容時間をはるかに超えています。 

便利な特性は、生成されたシーケンスが単調であることです。 あらゆるアプリケーションの`f`間の数値を返します`0`そして現在値。 値が減少しない唯一の方法は、値がすでに固定点である場合です。 これにより問題は完全に変わります。 すべてを実行するのではなく、`m`トランジションについては、シーケンスが安定するまでシミュレートするだけで済みます。 その時点以降、残りの項はすべて同一であるため、残りの答えは乗算で加算できます。 

繰り返しは評価しやすいため総当たり法は機能しますが、反復回数が大きい場合は失敗します。 シーケンスが永久に減少することはできないという観察により、無制限のシミュレーションを短い収束プロセスに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * d) | お(1) | 遅すぎる |
 | 最適 | O(k * d) | お(1) | 承認済み |

 ここ`d`は現在の値の桁数であり、`k`固定点に到達するまでに減少するステップ数です。 

## アルゴリズムのチュートリアル

 1. 現在値を計算する`f(current)`新しい値を答えに追加します。 最初に生成された用語は、`f(n)`、オリジナルではありません`n`したがって、追加する前に変換を行う必要があります。 
2. 値が変化し、要求された項がまだ残っている間、関数の適用を続けます。 成功したすべての変更は厳密に小さい整数に移行するため、プロセスは最終的に停止する必要があります。 
3. 固定小数点が見つかると、残りの生成値はすべて同じ数値になります。 その値に残りの項の数を掛けて加算します。 
4. 累計を出力します。 

なぜ効果があるのか:

 生成される値のシーケンスは次のとおりです。`a1=f(n), a2=f(a1), ...`。 あらゆるポジティブなことに対して`x`、`f(x)`モジュロです`x+1`結果、だから`0 <= f(x) <= x`。 もし`f(x) != x`、 それから`f(x) < x`。 したがって、シーケンスはある値まで減少します。`p`満足する`f(p)=p`。 その瞬間から応募すると、`f`値は決して変更されません。 このアルゴリズムは、減少する接頭辞を正確に計算してから、定数接尾辞をカウントするため、必要な合計内のすべての項が 1 回含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply_f(x):
    if x == 0:
        return 0

    mod = x + 1
    prod = 1
    p = 10

    while p <= x * 10:
        prod = (prod * (x % p)) % mod
        p *= 10

    return prod

def solve_case(n, m):
    ans = 0
    cur = n

    while m > 0:
        nxt = apply_f(cur)
        ans += nxt
        m -= 1
        cur = nxt

        if cur == apply_f(cur):
            ans += cur * m
            break

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(solve_case(n, m)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```の`apply_f`関数は定義を直接実装します。 このループは 10 のべき乗を生成し、剰余演算を使用して接尾辞を抽出します。 乗算は剰余で縮小されます`x + 1`残りだけが重要であり、これにより中間値が小さく保たれるため、各ステップの後に実行されます。 

メインループは使用しません`m`反復回数として。 固定点が現れるまでシーケンスをたどるだけです。 次の値が同一であることを検出した後、残りのコピーをすべて一度に追加します。 

境界の場合`x = 0`元の定義は正の整数で始まるため、個別に処理されますが、反復ではゼロに達する可能性があります。 ゼロに戻すことで即座に無駄な電力の発生を防ぎます。 

Python の整数はオーバーフローしないため、場合によっては最終的な合計が 64 ビットの符号付き範囲よりも大きくなる可能性があるため、これは便利です。

 ## 特殊なケース

 1 桁の数字の場合は次のようになります。```
3 4
```サフィックスリストには次のものだけが含まれます`3`。 製品は`3`、モジュロは`3 % 4`、それはまだです`3`。 アルゴリズムは、次の値が現在の値と等しいことを検出し、残りの項をすぐに追加します。 

ゼロで終わる数字の場合:```
10 3
```接尾辞は`0`そして`10`。 その積はゼロなので、最初に生成される値は次のようになります。`0`。 関数はゼロを受け取るため、以降のアプリケーションもすべてゼロを返します。 ゼロの特別な処理により、このケースは正しく終了します。 

反復回数が大きい場合、アルゴリズムはすべてを実行しようとすることはありません。`m`操作。 固定点に到達すると、残りの寄与分が乗算として計算されます。 これは、不可能な限界に依存する解決策との違いです。`10^9`反復と、短い減少チェーンのみをたどる反復です。
