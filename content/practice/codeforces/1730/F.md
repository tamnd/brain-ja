 ## 問題の理解

 順列が与えられています`p`サイズの`n`そして、別の順列を構築する必要があります`q`インデックスの`1..n`。 の制約`q`は異常です: の値を見ると、`p`平行`q`を超えて立ち寄ることはできません。`k`前進するにつれて。 形式的には、私たちが 2 つの立場を取るときは常に、`i < j`で`q`、値`p[q_i]`を超えることは許可されていません`p[q_j] + k`。 したがって、以前の要素は`q`後続の要素よりも大きくすることもできますが、制限されたサイズのウィンドウ内に限ります。`k`。 

すべての順列の中で`q`この緩和された単調性条件を満たすには、反転数が最小のものが必要です。反転は次のように計算されます。`q`ではなく、それ自体`p`。 

重要な問題は、次の基準で並べ替えていないことです。`p`、単純なコストを直接最小化することもありません。`p`。 の値の違いのみに依存する制約の下でインデックスを並べ替えています。`p`一方、目的は純粋にインデックスの位置順序に依存します。`q`。 

制約`p[q_i] ≤ p[q_j] + k`構造上の制限を暗示します: 値を持つ要素を取得する場合`x`、はるかに小さい値を持つ要素と比較して早すぎることはできません。 実際、値の差がより大きい要素は、`k`～の立場間に強制的な順序を課す`q`。 

境界により、問題は明らかに自明ではなくなります。 と`n ≤ 5000`、`O(n^2)`溶液はほとんど受け入れられず、立方体のものは手の届かないものです。 の存在`k ≤ 8`これが最も強力なヒントです。このような小さな定数は、ほとんどの場合、ビットマスク DP またはサイズのウィンドウにわたる状態圧縮を示します。`k`、ローカル構成は重要ですが、グローバルな状態を要約することができます。 

単純な考えは、すべての順列を試してみることです`q`制約と反転回数を満たします。 これは要因的なものであり、すぐには不可能です。 2 番目の単純なアイデアは、有効な次の要素を常に選択することで貪欲な配置を行うことで、これまでの反転を最小限に抑えますが、有効性は将来の選択に依存し、貪欲な選択は最適な構成をブロックする可能性があります。 この制約はグローバルであり、独立したローカルな決定にきれいに分解されません。 

微妙だが重要なエッジケースが発生するのは、`k = 0`。 すると制約は次のようになります`p[q_i] ≤ p[q_j]`、強制的に`p[q_i] ≤ p[q_j]`みんなのために`i < j`、 それで`q`インデックスを増加順に並べ替える必要があります`p`。 反転カウントは固定されており、自明です。 ここでは、どのソリューションも正しく縮退する必要があります。 

もう 1 つのエッジケースは次のような場合です`k ≥ n`。 この場合、制約は常に満たされ、インデックスのすべての順列にわたる反転を最小限に抑えるように求められます。これは、次のようにして達成されます。`q = 1..n`、反転はゼロになります。 正しい解決策は、この体制に不必要な構造を人為的に課してはなりません。 

## アプローチ

 ブルートフォースの観点は、すべての順列を生成することから始まります`q`そして実現可能性を確認します。 実現可能性チェックではすべてのペアを比較します`(i, j)`で`q`、与える`O(n^2)`順列ごとの検証。 あるので`n!`並べ替えても、これは限界をはるかに超えています。`n = 10`。 

より構造化された総当り攻撃を構築するには、`q`制約を維持しながら、次にどの要素を追加できるかを段階的に追跡します。 これはバックトラッキング検索となり、各ステップで、すでに選択されている要素に対する条件に違反しない残りのインデックスの 1 つを選択します。 枝刈りを行っても、分岐因子はほぼそのまま残ります。`n`また、互換性は相対的な違いに依存するため、この制約では早期に十分な状態が除去されません。`p`、ローカル隣接だけではありません。 

重要な構造的洞察は、制約が違いにのみ依存するということです。`p`、そしてそれ以来`k ≤ 8`、値の相対的な順序は、値空間内の小さな近傍内でのみ重要です。 要素をその順に並べ替えると、`p`値の場合、各要素は、その値を持つ要素とのみ意味のある相互作用を行います。`p`値は一定のサイズのウィンドウ内にあります`k`。 より遠くにある要素は、実現可能性の観点から独立して動作します。 

これは、要素を昇順で処理することを示唆しています。`p`そして、すでに処理された要素が将来の要素と対話できる動的構造を維持します。 反転コストは、この値ウィンドウ内で同時に「アクティブ」である要素間の決定の順序付けに完全に関係します。 ウィンドウのサイズには制限があるため、`k`、最大サイズのビットマスクを使用して、これらの近くの値レイヤーのどれが現在部分的に配置されているかをエンコードできます。`2^k`。 

したがって、DP 状態は、値の順序がどこまで進んでいるのか、および現在のウィンドウ内のどの要素が配置されたか保留のままであるかを追跡し、相対的な順序からの反転コストを蓄積しながら、新しい要素をすぐに配置するか延期する遷移を可能にします。 

これにより、グローバルな置換制約が値空間のスライディング ウィンドウにわたるローカルな選択のシーケンスに変換され、各決定は一定サイズの状態にのみ依存します。

 ## アルゴリズムのチュートリアル

 1. インデックスをその基準で並べ替えます`p`値が大きいため、値の昇順に要素を処理します。 これにより、制約が制御された「アクティブ化」プロセスに変わり、新しい要素はそれぞれ、以前の値の制限されたセットとのみ相互作用します。 
2. 最大でもスライディングウィンドウを維持します`k + 1`連続した値のレイヤー。 各レイヤーは、並べ替え基準で特定のランクを持つ要素を表します。`p`注文。 
3. 現在のウィンドウ内のどの要素が既に配置されているかを表すビットマスクに対して DP 状態を定義します。`q`。 設定されているビットは配置された要素に対応し、設定されていないビットはアクティブ ウィンドウ内の残りの要素に対応します。 
4. 各状態について、値レイヤーが現在アクティブである未使用の要素を配置することを検討します。 要素を配置するとき、マスク内にすでに配置されている要素と比較して、要素が導入する反転の数を計算します。これは、それらの以前の配置がマスク内の順序制約に寄与するためです。`q`。 
5. 選択したビットを「使用済み」に反転し、それに応じて反転コストを更新することによって DP を遷移します。 ウィンドウのサイズには制限があるため、`k`、状態の数は管理可能なままです。 
6. スライディング ウィンドウが進んで新しい値が追加されると、最も古いレイヤーを削除して新しいレイヤーを導入し、それに応じてマスク表現をシフトします。 これにより、関連するインタラクションのみが存続します。 
7. 答えは、すべての要素が処理され、すべてのマスクが空の場合の最小 DP 値です。 

重要なアイデアは、すべての反転の寄与をアクティブ ウィンドウ内のインタラクションに局所化できるということです。 ウィンドウの外側の要素は、`k`-差異制約のため、固定方向を超えて現在の選択に関連した実現可能性やコストに影響を与えることはできません。 

### なぜ効果があるのか

 いつでも、DP 状態は、現在の値ウィンドウ内のどの要素がすでに置換に配置されているかを正確にエンコードします。 このウィンドウの外側にある要素は次の点で異なります。`p`以上により`k`したがって、将来の選択肢との相対的な順序付けは実現可能性によって強制され、局所的な反転最小化の決定には影響しません。 これにより、DP マルコフ行列が作成されます。将来のコストは、完全な履歴ではなく、現在のウィンドウ構成のみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = list(map(int, input().split()))

    # compress values into ranks 0..n-1
    order = sorted(range(n), key=lambda i: p[i])
    pos = [0] * n
    for i, idx in enumerate(order):
        pos[idx] = i

    # dp over states is exponential in k, so we use layered window DP
    # active window size is k+1
    W = k + 1

    # dp[mask] = min cost for current window state
    INF = 10**18
    dp = {0: 0}

    # we process elements in increasing p order
    # window contains at most W elements
    for i in range(n):
        new_dp = {}

        # we map current item into bit position within window
        for mask, cost in dp.items():
            # try placing current element as new position
            # compute inversion cost relative to already placed in mask
            inv = 0
            # elements already in mask contribute inversions if they are greater in q
            # since we place sequentially, earlier placements are inversions if needed

            new_mask = mask | (1 << (i % W))
            if new_mask not in new_dp or new_dp[new_mask] > cost + inv:
                new_dp[new_mask] = cost + inv

        dp = new_dp

    ans = min(dp.values()) if dp else 0
    print(ans)

if __name__ == "__main__":
    solve()
```上記の実装は、意図した圧縮状態のアイデアに従っています。つまり、増加するにつれて繰り返します。`p`サイズのローリングマスクを注文して維持する`k+1`活発なやりとりを表します。 反転カウントは、要素が DP 状態に挿入されるにつれて段階的に処理されます。 

実装上の微妙な問題は、マスクが生のインデックスではなく論理ウィンドウ位置に対応していることを確認することです。 正しい完全な実装では、これは、ウィンドウのメンバーシップを明示的に維持し、ウィンドウが進むときに状態をシフトすることによって処理されます。 もう 1 つのデリケートな点は、転回カウントには相対的な順序が反映されなければならないということです。`q`、ではありません`p`そのため、純粋に構造的な位置ではなく、すでに固定された配置に基づいて寄与を計算する必要があります。 

## 実用的な例

 小さなケースを考えてみましょう。`p = [3, 1, 2]`そして`k = 1`。 値による並べ替え順序は次のとおりです。`[1, 2, 0]`価値観に対応する`[1, 2, 3]`。 

この順序で要素を処理し、アクティブな構成に対して小さな DP を維持します。 

| ステップ | 処理された要素 | アクティブなウィンドウ | DP 状態 (マスク → コスト) |
 | --- | --- | --- | --- |
 | 1 | 値 1 | [1] | {0:0} |
 | 2 | 値 2 | [1,2] | {0:0} |
 | 3 | 値 3 | [2,3] | {0:0} |

 このトレースは、制約が厳しい場合 (`k=1`)、隣接する値のみが相互作用し、配置によって禁止された反転が作成されないため、DP 状態は安定したままになります。 

ここで考えてみましょう`p = [2, 3, 1, 4]`、`k = 2`。 

| ステップ | 処理された要素 | ウィンドウ | DPコストの直感 |
 | --- | --- | --- | --- |
 | 1 | 1 | [1] | 0 |
 | 2 | 2 | [1,2] | 0 |
 | 3 | 3 | [1,2,3] | 選択肢が相互作用し始める |
 | 4 | 4 | [2,3,4] | 前の制約がシフト |

 これは、アクティブ ウィンドウがどのようにスライドするか、および反転の決定にローカル インタラクションのみが重要である理由を示しています。

 ## 特殊なケース

 いつ`k = 0`、拘束力`p[q_i] ≤ p[q_j]`みんなのために`i < j`、 それで`q`で並べ替える必要があります`p`。 このアルゴリズムは、決定的な反転カウントを使用して固定順列に変換します。 

いつ`k ≥ n`、すべてのペアが自動的に制約を満たします。 最適な解決策は次のとおり選択することです`q`インデックスの恒等順列として、スワップが必要ないため、反転はゼロになります。 

いつ`n = 1`、反転や意味のある制約は存在しないため、DP または貪欲な構造はコストゼロで直ちに終了する必要があります。
