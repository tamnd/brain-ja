 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには複数の整数セットがあり、各整数は惑星の軌道ラベルを表します。 同じ値を共有する惑星は同じ軌道に属します。 

惑星を破壊するには2つの方法があります。 1 つのオプションは、コスト 1 で単一の惑星を削除します。もう 1 つのオプションは、その軌道にある惑星の数に関係なく、選択した軌道に属するすべての惑星を 1 回の操作でコスト c で削除します。 

課題は、総コストを最小限に抑えながらすべての惑星を除去する、これら 2 つのアクションの組み合わせを選択することです。 

入力の構造は、位置ではなく、個別の軌道値の周波数のみが重要であることを意味します。 配列をどのように並べ替えても答えは変わらないため、問題は各値の出現を数えるということになります。 

制約は小さく、n はテスト ケースごとに最大 100、最大 100 のテスト ケースです。 これは、テスト ケースごとに O(n²) で実行されるソリューションはすでに安全であることを意味しますが、この構造により、さらに単純な線形カウント アプローチが可能になります。 

よくある失敗例は、周波数集約を無視したことに起因します。 たとえば、すべての惑星が個別の軌道上にあり、c が大きい場合、2 番目のマシンを使用するのは無駄ですが、単純で貪欲なアプローチにより、惑星ごとに 1 回適用する可能性があります。 逆に、多くの惑星が同じ軌道を共有し、c が小さい場合、それらをグループ化することに失敗すると、最初のマシンを繰り返し使用することになり、過剰な支払いにつながります。 

小さな例:

 入力:```
1
5 3
1 1 1 2 3
```個別に撃破するとコスト5、2号機を軌道1で使うとコスト3+2=5、全軌道で使うとコスト3+3+3=9とさらに悪くなる。 正しい戦略は、生のカウントだけではなく、軌道ごとの節約量を比較することに依存します。 

## アプローチ

 ブルートフォースの観点では、軌道のサブセットごとに 2 番目のマシンを使用するかどうかを決定しようとします。 k 個の異なる軌道があると仮定します。 各軌道について、その軌道のサイズを支払うか (最初のマシンを繰り返し使用する)、または c を 1 回支払うか (2 番目のマシンを使用する) を選択します。 これにより、2^k 通りの選択肢が得られます。 各選択肢の計算には O(n) のコストがかかるため、合計は O(2^k n) となり、これは中程度の k の場合でも実行不可能です。 

重要な観察は、軌道が独立しているということです。 周波数 f の個別の軌道値ごとに、2 つのコストのみを比較します。個別に破壊する場合はコスト f、2 番目のマシンを使用する場合はコスト c です。 2 番目のマシンは軌道を部分的に破壊できないため、異なる軌道間に相互作用はありません。 

したがって、最適な決定は局所的です。各軌道について、f と c の最小値をとります。 これらの選択を合計すると、全体的な最適値が得られます。 

これにより、問題は組み合わせ選択から単純な周波数集約問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 軌道サブセットに対するブルート フォース | O(2^k · n) | O(k) | 遅すぎる |
 | 軌道ごとの周波数貪欲 | O(n) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 軌道値の配列を読み取り、各軌道に属する惑星の数を数えます。 カウントのみが重要であるため、このステップでは問題を独立したグループに圧縮します。 
2. 個別の軌道ごとに、その周波数 f を計算します。 これは、最初のマシンのみを使用してその軌道上のすべての惑星を破壊するコストを表します。 
3. その軌道について、f と c の間で安価なオプションを計算します。 2 番目のマシンは、その軌道上のすべての惑星を個別に破壊するよりもコストが低い場合にのみ役立ちます。 
4. すべての軌道にわたるこれらの最小値を合計して、総コストを取得します。 
5. テストケースの結果を出力します。 

各軌道を個別に評価する理由は、軌道全体で共通の利点がないためです。2 番目のマシンは一度に複数の軌道に影響を与えることはありません。 

### なぜ効果があるのか

 各軌道は独立した決定単位を形成します。 最適なソリューションは、コストの最適性を変えることなく、軌道ごとに 2 番目のマシンを 1 回完全に適用するか、最初のマシンのみを繰り返し使用するように変換できます。 単一軌道内で戦略を混合することは不可能であり、軌道をまたがる結合もないため、軌道ごとの最適コストを合計すると、全体的に最適なソリューションが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        ans = 0
        for f in freq.values():
            ans += min(f, c)
        
        print(ans)

if __name__ == "__main__":
    solve()
```解決策は、辞書を使用して惑星を軌道ごとにグループ化することから始まります。 これにより、問題の正しい抽象化である周波数のみについて推論することが保証されます。 次に、各周波数がコスト c に対して独立して比較されます。 

微妙な点は、2台目のマシンの部分的な使用はまったく考慮されていないことです。 軌道に選択されると、常にその軌道のすべての惑星が削除されるため、使用を分割することは無意味です。 これが、min(f, c) 比較が決定空間を完全に捉える理由です。 

## 実用的な例

 ### 例 1

a = [1, 1, 1, 2, 3]
```| 軌道 | 周波数 f | min(f, c) | 累計額 |

 | 1 | 3 | 3 | 3 |

 | 3 | 1 | 1 | 5 |

 最終出力は 5 です。 

このトレースは、2 番目のマシンが密な軌道に役立つ場合でも、疎な軌道は個別に処理する方がコストがかからないため、当然のことながら軌道ごとに決定が分かれることを示しています。 

### 例 2

n = 4, c = 2

```| 軌道 | 周波数 f | min(f, c) | 累計額 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 配列を 1 回スキャンしてから、個別の軌道を反復処理します。 
| スペース | O(k) | 個別の軌道の周波数を保存します。 

n ≤ 100 および t ≤ 100 であるため、制約によりこれが容易に可能になり、全体で最大 10,000 回の操作が可能となり、十分に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        ans = sum(min(f, c) for f in freq.values())
        output.append(str(ans))
    
    return "\n".join(output)

# provided samples
assert run("""4
10 1
2 1 4 5 2 4 5 5 1 2
5 2
3 2 1 2 2
2 2
1 1
2 2
1 2
""") == """4
4
2
2"""

# all equal values
assert run("""1
5 10
7 7 7 7 7
""") == "5"

# all distinct, cheap c
assert run("""1
4 2
1 2 3 4
""") == "4"

# all distinct, expensive c
assert run("""1
4 10
1 2 3 4
""") == "4"

# mixed case
assert run("""1
6 3
1 1 2 2 2 3
""") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい値 | 5 | 2 台目のマシンと繰り返し使用の比較 |
 | すべてが独特で、安い c | 4 | c ≥ 1 | の場合、2 番目のマシンは有益ではないことを示しています。 
| すべて個別で高価な c | 4 | 個別の削除へのフォールバックを確認します |
 | 混合ケース | 5 | 軌道ごとの独立した決定を検証します。 

## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての惑星が 1 つの軌道に属し、c が非常に小さい場合です。 

入力：```
1
6 2
5 5 5 5 5 5
```アルゴリズムは周波数 f = 6 を計算し、min(6, 2) を比較して 2 を与えます。2 番目のマシンが優先されます。これは、個別に削除するよりも安価であるためです。 

もう 1 つの特殊なケースは、すべての軌道が一意である場合です。 

入力：```
1
4 10
1 2 3 4
```各周波数は 1 であるため、各軌道では min(1, 10) = 1 となります。 合計は 4 になり、2 番目のマシンは完全に無視されます。 

混合分布は独立性の原則を裏付けます。 

入力:```
1
6 3
1 1 2 2 2 3
```周波数は 2、3、1 です。コストは min(2,3)=2、min(3,3)=3、min(1,3)=1 となり、合計 6 になります。各軌道は独立して処理され、決定プロセスでは軌道間の結合は現れず、分解が正しいことが確認されます。
