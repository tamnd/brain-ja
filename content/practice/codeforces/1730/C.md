 ## 問題の理解

 10 進数の文字列が与えられます。 任意の数字について、現在の位置からその数字を削除し、その値を 1 つ増やし (上限は 9)、結果の数字を文字列の任意の場所に挿入します。 

この操作は何度でも繰り返すことができます。 挿入には制限がないため、最終的な桁の順序は主に制御下にあります。 課題は、結果として得られる文字列が辞書編集的にできるだけ小さくなるように、どの桁を増加および移動するか、どの桁を変更しないかを決定することです。 

すべてのテスト ケースの合計の長さは最大でも$2 \cdot 10^5$。 これにより、一連の操作を検討するアプローチは即座に排除されます。 たとえ$O(n^2)$単一のテスト ケースに次の要素が含まれる可能性があるため、アルゴリズムは危険です。$2 \cdot 10^5$数字。 テスト ケースごとに線形に近い時間が必要です。 

難しいのは、いつ数字を変更する必要があるかを理解することです。 単純な考えは、後で移動すると効果があるため、大きな桁をすべて増やすことです。 それは必ずしも正しいとは限りません。 

考慮する：```
s = 01
```答えは次のとおりです。```
01
```桁を増やすと`0`、になります。`1`、より悪い文字列が生成されます。 

別の微妙なケースは次のとおりです。```
s = 21
```答えは次のとおりです。```
13
```数字`2`小さい数字の前に表示されます`1`。 保管`2`in place は、最後の文字列の最初の文字を少なくとも`2`。 それを増やすことで、`3`後で移動することも可能です`1`最初に来ること。 

3 番目の重要なケースは次のとおりです。```
s = 999
```答えはまだ残っています:```
999
```演算を繰り返し適用する場合でも、桁数の上限は次のとおりです。`9`。 それらを移動しても、既存の複数の数字セットより小さいものは作成できません。 

重要な観察は、その数字が問題になるのは、その右側のどこかに小さな数字が存在する場合のみであるということです。 

## アプローチ

 ブルートフォースビューとは、すべての桁を独立して考えることです。 位置ごとに、数字を保持するか演算を適用するかを決定し、考えられるすべての挿入位置を試します。 これにより、最終的には到達可能なすべての文字列が生成され、辞書順に最小の文字列が答えになります。 

難しいのは、可能性の数が爆発的に増えることです。 各桁の保持または変更を決定するだけでも、すでに$2^n$可能性と挿入位置により、別の組み合わせ要素が追加されます。 それはずっと前から不可能になる$n$数十文字にも達します。 

何かをより速く見つけるには、操作によって実際に何が変わるのかを理解する必要があります。 

数字を仮定します$s[i]$右側のどこかに小さな数字があります。 そうすれば、後で何をしても、$s[i]$その小さい数字の前にあると、辞書編集上の順序が損なわれます。 操作により削除できるため、$s[i]$、それを 1 つ増やし、後で任意の場所に配置します。まさにそれを行う必要があります。 数字を増やすことで数字をわずかに犠牲にしますが、より小さい数字を早く表示できるようにします。 

ここで、すでにその右側のすべての数字以下になっている数字について考えてみましょう。 このような数字は、それより小さい値をブロックしません。 そのままにしておくのは、増やすのと少なくとも同じくらい良いことです。 

これにより、明確な基準が得られます。 

すべての位置について、その右側に表示される最小の桁を確認します。 厳密に小さい桁が存在する場合は、現在の桁を 1 つ増やします (9 が上限)。 それ以外の場合は、変更しないでください。 

これらの決定を行った後は、正確な位置は重要ではなくなります。 保持されたすべての数字は、元の値で使用可能なままになります。 変更されたすべての数字は、その値の増加に寄与します。 移動された数字は任意に並べ替えることができるため、辞書編集的に最小の最終文字列は、結果として得られるすべての数字を並べ替えることによって簡単に取得されます。 

全体の問題は、接尾辞の最小値を計算し、変換された数字のマルチセットを構築することに帰着します。

 ## アルゴリズムのチュートリアル

 1.文字列の場合$s$、すべての接尾辞に現れる最小の桁を計算します。 
2. 文字列を左から右にトラバースします。 
3. ポジションについて$i$、 比較する$s[i]$最小桁がその右側のどこかに表示されます。 
4. 右側に小さい数字がある場合は、置き換えます。$s[i]$による$\min(s[i]+1, 9)$。 
5. それ以外の場合はそのままにしておきます$s[i]$変わらない。 
6. 結果の数字をリストに保存します。 
7. すべての位置を処理した後、結果の数字のリストを並べ替えます。 
8. ソートされた数字を連結し、結果を出力します。 

なぜ並べ替えが有効なのでしょうか? 移動する必要があるすべての数字が、その増加バージョンに変換されました。 このような決定がすべて修正されると、操作により、変更された数字をどこにでも挿入できるようになります。 複数の数字セットの辞書編集上の最小の配置は、単にそのソート順です。 

### なぜ効果があるのか

 数字は、その数字がその後のすべての数字よりも大きくなっていない場合にのみ、変更されないままにする必要があります。 このような数字は、より小さい数字が先に現れることを妨げることは決してないので、それを変更しても最終的な文字列のプレフィックスを改善することはできません。 

より小さい数字が右側のどこかに存在する場合、その前に現在の数字を保持すると、最終的な文字列が必要以上に大きな値で始まることになります。 数字を遠ざけることは常に有益であり、この操作では、増加単位を 1 単位 (上限は 9) だけ支払う必要があります。 

したがって、すべての位置には、より小さい接尾辞が存在するかどうかだけによって決定される最適なローカル決定があります。 必須の増加をすべて適用した後、残りのタスクは、結果として得られる桁のマルチセットを配置することです。 辞書編集上最小限の配列では、数字を非降順でソートする必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        s = input().strip()
        n = len(s)

        suf_min = [''] * n
        suf_min[-1] = s[-1]

        for i in range(n - 2, -1, -1):
            suf_min[i] = min(s[i], suf_min[i + 1])

        res = []

        for i in range(n):
            if i + 1 < n and suf_min[i + 1] < s[i]:
                d = min(int(s[i]) + 1, 9)
                res.append(str(d))
            else:
                res.append(s[i])

        res.sort()
        print("".join(res))

solve()
```最初の部分は接尾辞の最小値を計算します。 すべての位置について、より小さい数字が後で表示されるかどうかを知りたいと考えます。 で始まるサフィックスの最小値`i + 1`まさにその質問に答えます。 

2 番目のパスでは貪欲ルールが適用されます。 将来の最小の桁が現在の桁よりも厳密に小さい場合、現在の桁を 1 つ増やし、その桁を移動可能としてマークします。 それ以外の場合は保管します。 

すべての変換が決定された後は、結果として得られる数字のマルチセットのみが重要になります。 それらを並べ替えると、可能な限り最小の辞書式配列が得られます。 

最も一般的な実装上の間違いは、現在の位置を含むサフィックスの最小値と比較することです。 特に必要なのは`suf_min[i + 1]`なぜなら、問題は右側に小さい数字が存在するかどうかだからです。 使用する`suf_min[i]`等しい数字が、より小さい数字が存在する証拠として誤って扱われてしまいます。 

もう一つの簡単な間違いは、キャップを忘れることです。`9`。 現在の桁が`9`、増加してもまだ残ります`9`。

def solve():
