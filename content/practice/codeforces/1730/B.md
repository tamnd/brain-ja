 ## 解決策
 ## 問題の理解

 さまざまな座標に立つ人々の列が与えられます。 各人には固定の位置があり、動き始めるまでの個人的な準備時間もあります。 集合場所を選択すると、準備時間と集合場所まで歩く必要のある距離の合計が到着時間になります。 

目標は、合計到着時間の点で最も遅い人ができるだけ早く到着するように、回線上の 1 つの座標を選択することです。 つまり、i さんの到着時刻を次のように定義すると、`t_i + |x_i - x_0|`、選びたい`x_0`すべての人々におけるこれらの値の最大値を最小化します。 

制約は、すべてのテスト ケースで合計最大 200,000 人を示します。 回答空間は連続的であり、最大 10^8 まで大きいため、考えられるすべての会議位置を試す単純なアプローチは不可能です。 候補位置ごとに関数を評価するだけでも遅すぎます。 

微妙な点は、目的が固定インデックスにわたる単純な線形ではなく、凸関数の最大値であることです。 これは、最小化している関数自体は凸状ですが、どこでも滑らかではないことを意味します。 

素朴な直感によるよくある失敗例は、ミーティングポイントがポジションの中央値または何らかの加重平均であるべきだと仮定することです。 準備時間が異なるとすぐに壊れてしまいます。 たとえば、同じ位置にいる異なる 2 人の人がいるとします。`t_i`コストは純粋に幾何学的なものではないため、値によって最適なミーティング ポイントがその位置から完全にずれる可能性があります。 

もう 1 つの落とし穴は、動きをシミュレートしたり、位置だけで並べ替えたりしようとすることです。 準備時間は各「V 字型」機能の垂直方向のシフトのように機能し、どの人が最大値を支配するかを変更します。 

## アプローチ

 候補者集合位置を確定したら`x_0`、各人の時間を計算するのは簡単です。`t_i + |x_i - x_0|`そして最大値を取る。 これにより、正しいが高価な総当たりのアイデアが得られます。つまり、候補位置の密集したセットをスキャンし、それぞれの最大コストを評価します。 

問題は、最適な点がどの入力座標にもあることが保証されておらず、探索空間が連続していることです。 0 から 10^8 までのすべての整数を試すことは不可能であり、ポイントごとに関数を評価することさえ遅すぎます。 

重要な観察は、最小化している関数が凸関数であるということです。`x_0`。 各学期`t_i + |x_i - x_0|`は V 字型の凸関数であり、凸関数の最大値は依然として凸です。 直線上の凸関数には一意のグローバル最小値があり、三分探索を使用するか、導関数の符号をチェックすることで見つけることができます。 

ただし、関数を直接評価しても O(n) であるため、各チェックのコストは O(n) です。 広い範囲にわたる三分探索では、十分な精度に収束するまでに約 60 回の反復のみが必要であり、解を実現可能にします。 

別の視点としては、勾配の観点から考えることです。 移動中`x_0`右に行くと、一部の人の貢献が増加する一方、他の人は減少します。 最適な点は、「最も厳しい制約」が左側の貢献者による支配から右側の貢献者に切り替わる点です。 このバランス ポイントは、まさにこれらの V 字型の最大値が最小化される場所です。

 ## アルゴリズムのチュートリアル

 1. 関数を定義する`f(x)`すべての人がポイントに到達するまでに必要な最大時間を計算します`x`。 これは、すべての人々をスキャンし、コンピューティングすることによって行われます。`t_i + |x_i - x|`。 この関数は、選択した場合の最悪の到着時間を表します。`x`。 
2. それを観察してください`f(x)`は実数に対して凸です。 これにより、三項検索を使用して最小値を見つけることができます。 
3. 検索間隔を設定する`[L, R]`最初はすべての考えられる意味のある位置をカバー`[0, 1e8]`。 
4. 間隔がまだ十分広いうちに、内部の 2 点を選択します。`m1`そして`m2`、通常はセグメントを 3 つに分割します。 コンピューティング`f(m1)`そして`f(m2)`。 
5. もし`f(m1) > f(m2)`、最小値は右側にあるため、シフトします`L`に`m1`。 それ以外の場合はシフトします`R`に`m2`。 これが機能するのは、凸関数が減少してから増加するためです。そのため、2 つの内部点を比較すると、どちらの側に最小値が含まれているかがわかります。 
6. 十分な反復の後、残りの間隔の中点を答えとして取得します。 

これが機能する理由は、凸性によって単一のグローバル最小値が存在することが保証され、2 つの点を比較するたびに、それを含むことができない領域が排除されるためです。 このプロセスでは、最適な点を破棄することなく、探索間隔を着実に短縮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        x = list(map(int, input().split()))
        tvals = list(map(int, input().split()))
        
        def f(pos):
            mx = 0
            for i in range(n):
                d = abs(x[i] - pos)
                val = tvals[i] + d
                if val > mx:
                    mx = val
            return mx
        
        l, r = 0.0, 100000000.0
        
        for _ in range(80):
            m1 = l + (r - l) / 3.0
            m2 = r - (r - l) / 3.0
            if f(m1) > f(m2):
                l = m1
            else:
                r = m2
        
        ans = (l + r) / 2.0
        print(ans)

if __name__ == "__main__":
    solve()
```機能`f(pos)`候補点への最大到着時間を明示的に評価します。 これは、三項検索で使用される中心的な評価です。 最適な点は入力位置の凸包内にあるため、検索間隔は、考えられるすべての答えをカバーするのに十分な幅に固定されています。 

80 回の反復のループは、間隔を必要な精度以下にするには十分です。 各反復では残りの範囲の約 3 分の 1 が破棄されるため、高精度の要件でも高速に収束します。 

実装の微妙な詳細は、整数 3 項検索を試行するのではなく、浮動小数点演算を直接使用することです。 要求される精度は次のとおりですので、`1e-6`倍精度で十分です。

def run(inp: str) -> str:

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 主なエッジケースは、すべてのポジションが同じであるが、準備時間が異なる場合です。 たとえば、すべてが`x_i = 5`しかし`t_i`状況は変わりますが、最適な集合場所は変わりません`5`, なぜなら、遠方に移動しても準備コンポーネントは減らずに移動時間が増えるだけだからです。 5 からの偏差はすべての値を増加させるため、アルゴリズムはこれを正しく評価します。`|x_i - x|`同様に。 

もう 1 つの微妙なケースは、準備に時間がかかる左側と右側の 2 つの対立するグループが存在する場合です。 最適な点は、入力座標ではなく、厳密にそれらの間にある可能性があります。 三分探索では、離散的な候補に依存しないため、この内部点が自然に見つかります。 

最後に、人が 1 人だけの場合、関数はその人の位置で正確に最小化されます。 評価関数は、次の点を中心とする単一の V 字型に縮小されます。`x_i`、最小値は自明です`x_i`、アルゴリズムは不安定になることなく返します。
