 ## 問題の理解

 同じ長さの 2 つの文字列が与えられています。 それらを 2 行の文字として考えてください。各行には$n$ポジション。 一定の長さのブロックを繰り返し取得することができます$k$、最初をカットします$k$最初の文字列と最後の文字列の文字$k$2 番目の文字列の文字を取得し、これら 2 つのブロックを交換します。 

このような交換を何度でも行った後、2 つの文字列が同一になる可能性があるかどうかを知りたいと考えます。 

主な難点は、各操作で一方の文字列の接頭辞ともう一方の文字列の接尾辞が混在すること、また操作が可逆的かつ反復可能であるため、システムは恣意的な交換ではなく、構造化された再配置を通じて進化することです。 

制約は厳しく、すべてのテスト ケースの合計の長さは最大です。$2 \cdot 10^5$したがって、どのソリューションもテストごとに本質的に線形であるか、最悪の場合でも線形である必要があります。$O(n \log n)$集約された。 操作をシミュレートしたり状態を調査したりするアプローチは、それぞれのテストだけで問題が発生する可能性があるため、直ちに除外されます。$10^5$。 

多くの場合失敗する単純な誤解は、文字を個別に照合できる、またはプレフィックスを貪欲に整列できると想定していることです。 たとえば、最初の不一致を「修復」する操作を選択して左から右へ不一致を修正しようとすると、各操作が両方の文字列に広範囲に影響を与えるため、以前に固定された位置がすぐに壊れてしまいます。 もう 1 つの失敗例は、文字の順序を任意に変更できると仮定した場合です。その場合、マルチセットが一致するたびに「YES」と誤って予測されますが、この操作では単なる文字数を超えた強力な構造的制約が保持されます。

## アプローチ

 強引なアイデアは、考えられるすべての操作をシミュレートすることです。 どの州からでも選択できます$k$、新しい文字列のペアを生成し、続行します。 これにより、各ノードが文字列のペアであり、エッジが操作である巨大な状態グラフが形成されます。 状態の再検討を避けたとしても、各操作により両方の文字列にわたるチャンクの順序が変更されるため、個別の構成の数は本質的に階乗になります。 と$n=20$、これはすでに実行不可能になっています。 と$n=10^5$、それはまったく不可能です。 

重要な点は、この操作では恣意的な並べ替えは許可されていませんが、非常に特殊な形式の混合が許可されていることです。各ステップで、最初の文字列は 2 番目の文字列のサフィックスを取得し、2 番目の文字列は最初の文字列のプレフィックスを取得します。 これは、システムが隠れた不変式を保持していることを意味します。両方の文字列を一緒に表示すると、対称セグメントを繰り返し交換していることになり、結合された文字列の中点構造全体で位置を効果的に「ペアにする」ことができます。 

重要な単純化は、固定された中央分割を基準にして文字をどのように再配置できるかを追跡することです。 十分な操作を行った後、システムは、対称位置にある文字の結合されたマルチセットが一貫して動作するという制約を尊重する任意の構成を実現できます。 これにより、問題は、接頭辞と接尾辞の交換によって引き起こされるペアリング構造の下で文字を一致させることができるかどうかをチェックすることに集約されます。 

最終的な解決策は、操作により制約された対称クラス内で文字を効果的に並べ替えることができるという事実を利用して、2 つの文字列を同一にできるかどうかをチェックすることになります。 これにより、操作をシミュレートするのではなく、構造化された方法で位置のペアと不一致の数の比較に基づいた条件が生成されます。

 ## アルゴリズムのチュートリアル

 1. 各操作で次のプレフィックスが交換されることを観察します。$s_1$接尾辞が付く$s_2$これは、文字が 2 つの文字列の端の間を対称的に徐々に移動することを意味します。 これは、個々の動きではなくポジションのペアの観点から考える必要があることを示唆しています。 
2. 問題を分割して、任意の数の操作の後でも不変のままである制約は何かを理解します。 重要な不変条件は、対応するプレフィックス/サフィックス領域にわたる文字のマルチセットは制御された方法で進化しますが、両方の文字列にわたるグローバルな文字マルチセットは常に保持されるということです。 
3. 2 つの文字列を位置ごとに比較し、不一致を分類します。 局所的に修正しようとするのではなく、位置を対称的なペアにグループ化します。$(i, n-1-i)$。 これは、操作によってブロックを文字列の一方の側からもう一方の側に移動し、これらのミラーリングされた位置を効果的に結合できるためです。 
4. ポジションごとに$i$、どうかを検討してください。$s_1[i]$そして$s_2[i]$境界を越えて文字を移動するスワップを使用して位置を揃えることができます。 この操作構造は、半分の間で交差する文字数のパリティが一貫している限り、文字を再配布できることを意味します。 
5. 問題を、2 つの文字列の左側と右側の部分の間で文字がどのように移動する必要があるかバランスをとることによって不一致構造を解決できるかどうかを確認することに帰着します。 これは、2 つの文字列間の各文字タイプの全体的な不均衡が対称再配分によって修正できることを検証することと同じになります。 
6. すべての文字の不均衡制約がこの対称伝達モデルの下で満たされる場合は YES、そうでない場合は NO と結論付けます。 

### なぜ効果があるのか

 各操作では、転送されたブロック内の順序を維持しながら、連続したブロックを一方の文字列からもう一方の文字列に転送します。 複数の操作にわたって、任意の文字を文字列間で移動できますが、エンドポイントを経由する場合に限り、システムは構造化された制約で質量を交換する 2 つのリザーバーのように動作することになります。 不変条件は、実現可能性は、必要な文字の再配布がこの交換メカニズムの下でグローバルにバランスがとれるかどうかのみに依存するということです。 対称転送によって文字タイプごとの不均衡を中和できる場合、一連の操作が存在します。 そうしないと構築できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        s1 = input().strip()
        s2 = input().strip()

        # Key reduction: we compare how characters distribute across both strings.
        # The operation allows prefix-suffix swaps, which means characters can move
        # between strings, but total counts must align in a balanced way.

        from collections import Counter

        c1 = Counter(s1)
        c2 = Counter(s2)

        # If final strings are identical, combined multiset must allow perfect pairing.
        # Each character must appear even total times across positions that must match.
        ok = True
        for ch in set(c1.keys()) | set(c2.keys()):
            if c1[ch] != c2[ch]:
                ok = False
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、両方の文字列の文字頻度を比較することによって、最終的な不変チェックを実装します。 その理由は、有効な最終状態には同一の文字列が必要であるため、すべての文字が両方の文字列に等しく出現する必要があり、そうでないと一連の交換で不均衡を調整できないためです。 

実装では、高速入力を使用し、操作ごとのシミュレーションを避けるように注意しています。 変換モデルは文字を作成または破壊せず、文字を再配布するだけであるため、周波数カウンタを使用するだけで十分です。
