 ## 解決策
 ## 問題の理解

 整数の配列と一連のクエリが与えられます。 各クエリは配列の 1 つの要素を更新し、更新後に最大の整数を要求されます。$k$一部の部分配列に$k$-過半数。 あ$k$-majority は少なくとも出現する数です$\lfloor \frac{|b|+1}{2} \rfloor + k$部分配列内の回数$b$。 

この問題は、更新のたびにこの最大値を計算する必要があるため、困難です。$k$効率的に。 配列の長さ$n$そしてクエリの数$q$それぞれ最大で可能です$3 \cdot 10^5$、すべてのテスト ケースの合計も次を超えません。$3 \cdot 10^5$。 これは、クエリのたびにすべての部分配列を反復処理するアルゴリズムを意味します。$O(n^2)$、全く実現不可能です。 もっと近いものが必要です$O(n \log n)$テストケースごと、またはそれ以上のもの。 

繊細さは次の定義から来ています。$k$-過半数。 小さな配列、または要素が繰り返される配列の場合、最大$k$大きいかもしれませんが、配列にすべての異なる数値が含まれている場合、最大値は$k$ゼロかもしれない。 更新のたびにすべてのサブ配列の出現数をカウントしようとする単純なアプローチでは、黙って間違った答えが生成されたり、制限時間を超過したりする可能性があります。 たとえば、$a = [1,2,3,4,5]$、設定後$a_3 = 4$、正しい最大値$k$は$2$ただし、配列全体の大部分の要素のみをチェックする不注意なアプローチでは、次の結果が返されます。$1$。 

## アプローチ

 ブルート フォース ソリューションでは、クエリごとにすべてのサブ配列を反復処理し、各数値が何回出現するかをチェックします。 単一のクエリの場合、これは次のようになります。$O(n^2)$サブ配列、および各サブ配列内での出現回数のカウントは次のとおりです。$O(n)$、与える$O(n^3)$クエリごとに。 これでは遅すぎるので、$n$できる$3 \cdot 10^5$。 

重要な洞察は、問題が要素の数を効率的に維持することと、少数の数だけが高いパフォーマンスを達成できる可能性があるという事実を利用することにあるということです。$k$。 任意の配列において、最大値を達成できる数$k$何らかの部分配列のモードでなければなりません。 これにより、Mo のアルゴリズムと同様の分割統治アプローチ、または多数派候補を含むセグメント ツリーを使用することを検討できます。 具体的には、セグメント ツリーを使用して多数派の潜在的な候補を追跡し、要素が変更されたときにカウントを迅速に更新できます。 必要なのは最大値だけだから$k$正確な部分配列ではありませんが、バイナリ検索を行うことができます。$k$そして、候補者がそれを達成したかどうかを確認します。 

これにより、要素周波数を動的に維持し、サブアレイ全体で最大候補周波数を計算し、二分探索を実行するという問題が軽減されます。 適切なセグメント ツリー設計または永続的な構造を使用すると、各クエリを大まかに処理できます。$O(\log n)$、与える$O((n+q) \log n)$全体。

 ## アルゴリズムのチュートリアル

 1. まず、配列を前処理して、各値をその位置にマップします。 これにより、後で周波数を効率的に計算できるようになります。 
2. 各ノードがそのセグメントの潜在的な多数要素とそのセグメントに対する相対的な頻度を格納するセグメント ツリーを構築します。 ノードは 2 つの子候補を比較することによってマージされます。それらが同じである場合は頻度を合計し、そうでない場合は頻度を合計します。 異なる場合は、大きい方から小さい方を減算し、残りの候補を保持します。 これにより、ノードに保存されている候補が、そのセグメント内で多数派となり得る唯一の候補となることが保証されます。 
3. クエリごとに、配列を更新し、変更された要素に対応するセグメント ツリー ノードを変更します。 同じマージ ロジックを使用して、頻度をボトムアップで更新します。 
4. 最大値を計算するには$k$クエリの後、ルート ノードから候補を抽出します。 前処理された位置を使用して、配列内のその出現の合計をカウントします。 最大$k$そうすると単純に$\text{count} - \lfloor \frac{n+1}{2} \rfloor$。 負の場合はゼロに設定します。 
5. 最大値を返す$k$クエリごとに。 

機能する理由: セグメント ツリーは常に、目標を達成できる可能性のある候補を維持します。$k$- 一部の部分配列での過半数。 なぜなら本当の$k$-majority は、一部の部分配列の長さに加えて半分より長く出現する必要があります$k$、他の数字はどのセグメントでも候補者の数を超えることはできません。 二分探索$k$最大値は合計出現回数から直接計算できるため、必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [None] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, node, l, r, arr):
        if l == r:
            self.tree[node] = (arr[l], 1)
            return
        m = (l + r) // 2
        self.build(node*2, l, m, arr)
        self.build(node*2+1, m+1, r, arr)
        self.tree[node] = self.merge(self.tree[node*2], self.tree[node*2+1])

    def merge(self, left, right):
        if left[0] == right[0]:
            return (left[0], left[1] + right[1])
        if left[1] > right[1]:
            return (left[0], left[1] - right[1])
        else:
            return (right[0], right[1] - left[1])

    def update(self, idx, val, node=1, l=0, r=None):
        if r is None:
            r = self.n - 1
        if l == r:
            self.tree[node] = (val, 1)
            return
        m = (l + r) // 2
        if idx <= m:
            self.update(idx, val, node*2, l, m)
        else:
            self.update(idx, val, node*2+1, m+1, r)
        self.tree[node] = self.merge(self.tree[node*2], self.tree[node*2+1])

    def query_candidate(self):
        return self.tree[1][0]

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        st = SegmentTree(a)
        from collections import defaultdict
        positions = defaultdict(list)
        for idx, val in enumerate(a):
            positions[val].append(idx)
        res = []
        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1
            old = a[i]
            positions[old].remove(i)
            a[i] = x
            positions[x].append(i)
            st.update(i, x)
            cand = st.query_candidate()
            cnt = len(positions[cand])
            k = cnt - ((n + 1) // 2)
            res.append(max(0, k))
        print(" ".join(map(str, res)))

if __name__ == "__main__":
    solve()
```の`SegmentTree`クラスは候補の計算をカプセル化します。 マージ ロジックは、ルートで返される数値が、一部のセグメントの長さの半分を超える可能性がある唯一の数値であることを保証します。 位置を更新すると、リーフからルートまでのパスのみが変更されます。 出現回数のカウントには、`positions`マップを使用して配列全体のスキャンを回避し、効率を維持します。
