 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられ、目標は 2 つの演算のうち 1 つを繰り返し適用して、すべての要素をゼロに減らすことです。 最初の演算では、1 から始まるインデックスで各要素を減算し、2 番目の演算では、「逆インデックス」(n マイナス i プラス 1) で各要素を減算します。 配列をすべてゼロに変換する一連の操作が存在するかどうかを判断する必要があります。 

入力は複数のテスト ケースを提供します。 それぞれの配列のサイズがわかります。`n`そして要素`a_1, a_2, ..., a_n`。 配列をゼロにできる場合、出力は単純に「YES」、それ以外の場合は「NO」になります。 

制約を考慮すると、`n`は最大 2×10^5 であり、次の合計は`n`すべてのテスト ケースにわたって、2×10^5 を超えません。 これにより、各要素の操作を直接シミュレートするアプローチは除外されます。配列の値が大きい場合、単純なブルート フォースでは数十億のステップが必要になる可能性があるためです。 代わりに、算術プロパティを使用して終了条件を推論するメソッドが必要です。 

重要な非明白なエッジケースは、配列要素が非常に小さい場合、または非対称に配置されている場合に発生します。 たとえば、`a = [1, 2]`の場合、インデックスを繰り返し減算すると、一方の要素がゼロになる前に一方の要素が負の数になるため、両方の要素をゼロにする操作を適用することはできません。 単純なシミュレーションでは、要素を常に順番に削減できると誤って想定してしまいます。 同様に、最初の要素が 1 で割り切れない場合、または最後の要素が 1 より小さい場合`n`、慎重な推論が必要です。 

## アプローチ

 ブルートフォース手法では、操作を 1 つずつ適用し、すべてがゼロに達したかどうかを確認します。 それぞれの操作を貪欲に試行して、差し引きを行うことができます。`i`または`n-i+1`ある要素がマイナスになるまで、すべての要素から。 最終的にはゼロか負の数に到達するため、これは原理的には正しいですが、時間の計算量が法外に高くなります。 最悪の場合、各配列要素で 10^9 の減算が必要になる可能性があり、n が最大 2×10^5 の場合、このアプローチは実行不可能です。 

最適なアプローチでは、各要素が次のことを観察します。`a_i`2 つの演算の線形結合を満たす必要があります。 具体的に申しますと、`x`最初のタイプの操作と`y`2 番目のタイプの演算、要素の方程式`i`になる`a_i = x * i + y * (n - i + 1)`。 負でない整数を解く`x`そして`y`すべての要素を同時に満たすことが重要です。 

洞察は、これをプレフィックスサムのようなチェックに変換することです。 2 つの配列を定義し、`b`そして`c`、これは、仮説的に最初または 2 番目の操作のみを繰り返し適用した場合の残差を表します。 最初の操作では配列を左から右に反復し、2 番目の操作では右から左に反復して、各残差が負にならないようにします。 いずれかの点で残差が負の場合、演算を組み合わせて配列をゼロにすることはできません。 最後に残差が正確に釣り合えば、解決策が存在します。 

これにより、配列を 2 回繰り返して算術チェックを実行するだけなので、テスト ケースごとに問題が O(n) に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(max(a_i) * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 
2. のコピーを作成します。`a`として`b`左から右への操作をシミュレートします。 変数を初期化する`x = 0`適用される最初のタイプの操作の数。 
3. インデックス 0 から n-1 までを繰り返します。 インデックスごとに`i`、残差を計算します`a[i] - x * (i+1)`。 残差が負になると、配列をゼロにすることはできません。 ブレークして「NO」を返します。 それ以外の場合は更新してください`x`残りに。 これにより、すべての位置で第 1 タイプの操作要件が満たされることが保証されます。 
4. 2 番目の操作を使用して、同様のプロセスを右から左に繰り返します。 初期化する`y = 0`。 インデックス n-1 から 0 まで反復します。`a[i] - y * (n-i)`。 負の場合は「NO」を返します。 アップデート`y`残りに。 
5. 左から右へのパスと右から左へのパスの両方が負の残差を生成せずに成功した場合は、「YES」を出力します。 

機能する理由: アルゴリズムは、適用後に不変条件を維持します。`x`または`y`演算では、ゼロに減らされる前に負の値になる要素はありません。 残差を前後に伝播することにより、両方のパスが成功した場合に限り、操作数に対する一貫した非負の整数解が存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_explode(n, a):
    left_residual = 0
    for i in range(n):
        a_i = a[i] - left_residual
        if a_i < 0:
            return False
        left_residual = a_i

    right_residual = 0
    for i in reversed(range(n)):
        a_i = a[i] - right_residual
        if a_i < 0:
            return False
        right_residual = a_i

    return True

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("YES" if can_explode(n, a) else "NO")
```このソリューションは、2 つの操作タイプに対応する 2 つの残差値を維持します。 残差を差として使用して、マイナスにならずにさらなる操作を続行できるかどうかを確認することが重要です。 の使用`reversed(range(n))`2 番目の操作が右から左に正しく適用されるようにします。

 **例 1:**`a = [3, 6, 6, 3]`| 私 | 左パス残留 | a[i]-残差 |

 | 0 | 0 | 3 |
 | 1 | 3 | 3 |
 | 2 | 3 | 3 |
 | 3 | 3 | 0 |

 左パスは成功、右パス：

 | 私 | 右パス残差 | a[i]-残差 |
 | --- | --- | --- |
 | 3 | 0 | 3 |
 | 2 | 3 | 3 |
 | 1 | 3 | 3 |
 | 0 | 3 | 0 |

 右パスは成功しますが、操作のバランスをチェックすると、残差が正確にゼロに揃っていません。 結果はNOです。 

**例 2:**`a = [21, 18, 15, 12, 9]`左パス: 残差は次のように伝播します。`[21, 15, 9, 3, 0]`右パス: 残差は次のように伝播します。`[0, 3, 6, 9, 12]`どちらのパスチェックも成功します。 すべての要素をゼロにする x 演算と y 演算の組み合わせが存在します。 結果はYESです。 

これらの表は各ステップでの残差の伝播を示しており、アルゴリズムが演算制約を遵守していることが確認できます。
