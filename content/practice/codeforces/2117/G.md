 ## 解決策
 ## 問題の理解

 ノード 1 からノード n に移動する必要がある重み付き無向接続グラフを使用しています。 すべてのパスは頂点とエッジを再訪問できるため、サイクルが許可されます。 

選択されたパスのコストは、そのパスに沿って現れる最小および最大のエッジ重みによってのみ決定されます。 パスがエッジの重みを使用する場合$w_1, w_2, \dots, w_k$の場合、コストは単にこれらの重みの最小値と最大値の合計になります。 タスクは、この量を最小にする 1 から n までのパスを見つけることです。 

これが珍しいのは、パス自体が総重みやエッジの数によってスコア付けされるのではなく、エッジ上の極値関数によってスコア付けされることです。 これにより、通常の最短パス構造が崩れます。エッジを追加してもコストは直線的に蓄積されず、これまでに確認された最小値または最大値が変更される可能性があるだけです。 

制約は厳しいです。すべてのテスト ケースにわたる頂点とエッジの合計数は次のとおりです。$2 \cdot 10^5$。 これにより、候補間隔ごとに最短パスを再計算したり、単純な方法でエッジのすべてのペアを境界として試みたりするアプローチは除外されます。 ニアリニアまたはニアリニアよりも悪いもの$m \log m$テストケースごとに苦労するでしょう。 

微妙な問題は、パスがエッジを再訪問する可能性があるという事実から生じます。 素朴な読者は単純なパスを探していると考えるかもしれませんが、繰り返しを許可するということは、接続されたサブグラフ内でエッジの重みの「適切な範囲」が利用可能になったら、その内部を任意に横断して接続性を調整できることを意味します。 

いくつかの障害モードが自然に現れます。 

現在のエッジの重みの最小値と最大値を追跡しながら、頂点上の標準的な最短経路を試行すると、状態空間は次のようになります。$(node, minEdge, maxEdge)$、これは大きすぎます。 たとえば、小さなグラフであっても、わずかに異なる最小値を持つ同じノードに到達するさまざまな方法により、まったく異なる将来コストが生成されます。 

もう 1 つの誤った直感は、答えが単一の MST または最短パス ツリー内の最適なパスに対応すると仮定することです。 追加構造を最適化していないため、これは失敗します。 わずかに悪いエッジを追加しても、接続性が改善され、後で最大値の悪化を回避できる場合には、有益な場合があります。 

## アプローチ

 重要な観察は、「パスが最小値と最大値を定義する」から「どのエッジの重みが許可されるかを選択することによって実現可能な答えが定義される」へと視点を反転させることです。 

下限を固定するとします$L$そして上限$R$。 重みが にあるエッジのみを使用する 1 から n までのパスが存在する場合、$[L, R]$、すると、コストが最大で次のパスを実現できます。$L + R$、そのパス上の最小エッジは少なくとも$L$そして最大値は最大です$R$そして、そのフィルタリングされたグラフの接続によって両方のエンドポイントがパスに表示されることを常に確認できます。 

そこで問題は次のとおりです: ペアを見つける$(L, R)$1 と n がその範囲内のエッジのみを使用して接続されるようにして、$L + R$。 

ここで、考え方を逆転させます。 両端を固定する代わりに、エッジを重みでソートし、最小のエッジをソリューションに固定しようとします。 重みのあるエッジを選択するとします$w$パス内の最小許容エッジとして。 そうすると、答えは次のようになります。$w + \text{(some maximum reachable weight while keeping connectivity)}$。 

固定する$w$、少なくともウェイトのあるエッジのみを許可します$w$。 このサブグラフでは、1 と n を接続する可能な最小の最大エッジ重みを知る必要があります。 それは最小しきい値を見つけることと同じです$R$エッジが内側になるように$[w, R]$1とnを接続します。 

これは当然 DSU スイープで処理されます。エッジを重みでソートし、上限を増やしても接続を維持します。 各候補の下限について$w$概念的にはリセットしてから上向きに成長しますが、これをエッジごとに行うと遅すぎます。 

最後の最適化は、「下限ごとにリセットする」必要がないことを認識することです。 代わりに、永続的または増分接続ロジックと組み合わせた 2 ポインター技術を使用して、エッジを昇順に処理し、DSU 接続に対するスライディング ウィンドウのアイデアを維持します。 より直接的で標準的な解決策は、エッジを並べ替えて DSU を使用することです。その際、すべてのエッジを最小エンドポイントとして考慮し、1 と n を結ぶ最小の最大値を維持します。 

実際には、小さいものから大きいものまでスイープすることで最大エッジを固定し、1 と n が接続されているかどうかを維持します。 微妙な部分は、対応する最良の最小値を抽出することです。これは、接続時間ごとに、同じ接続間隔内で有効な最小値として機能する最小のエッジの重みを追跡することによって達成されます。 

落とし穴を避けるための明確な再定式化は次のとおりです。 

エッジを重量別に分類します。 エッジを昇順に含めるので、DSU を維持します。 任意の時点で、1 と n がエッジの重みで初めて接続されるとき$R$、現在のコンポーネントは、以下のエッジを使用して構築されています。$R$。 そのコンポーネント内で、最初に 1 と n を接続する接続構造で使用される最小エッジ ウェイトは、事実上、その最大値に対する最良の最小値となります。$R$。 したがって、DSU コンポーネントごとに、それを形成するために使用される最小エッジの重みを維持し、1 と n が結合されたときに、候補の答えを評価します。 

これにより、ソートされたエッジ上で線形スイープが生成されます。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを重みで昇順に並べ替えます。 これにより、エッジを追加するときに、考慮される間隔の現在の最大境界のみを増加させることができます。 
2. 各ノードが独自のコンポーネントである DSU を初期化します。 各コンポーネントとともに、コンポーネントを現在の構造にマージするために使用された最小エッジ ウェイトを保存します。 最初はこれは未定義です。 
3. 重みでソートされた順序でエッジを反復処理します。$w$。 各エッジ (u、v、w) について、そのコンポーネントを結合しようとします。 2 つのコンポーネントをマージする場合、結果のコンポーネントの保存された最小エッジ ウェイトを 2 つのコンポーネントの保存された値の最小値として更新し、$w$。 
4. マージするたびに、ノード 1 と n が同じコンポーネント内にあるかどうかを確認します。 そうであれば、最大エッジが現在のパスであるパスを形成できます。$w$、これまでに使用されたすべてのエッジが ≤ であるため、$w$。 
5. 1 と n が接続されると、次のように答えの候補を計算します。$w + \text{minEdge}[component(1)]$、このコンポーネントに保存されている最小エッジは、それらを接続する構造に関与する最小のエッジの重みを表すためです。 
6. エッジの処理を続行します。これは、後のマージにより、最大値は大きくても最小値が大幅に小さい代替構造が作成され、合計が改善される可能性があるためです。 

### なぜ効果があるのか

 スイープのどの時点でも、各 DSU コンポーネントは現在の最大重みまでのエッジのみを使用して接続を表します。$w$。 エッジ ≤ を使用する 1 から n までの任意のパス$w$この構造に完全に含まれています。 1 と n が接続される最初の瞬間は、そのしきい値までのエッジのみを使用する有効なパスの可能な最小の最大エッジに対応します。 同じコンストラクション ヒストリ内で、結合プロセスに含まれる最小エッジ ウェイトを追跡すると、その接続レジームと互換性のある達成可能な最小の下限が取得されます。 すべての候補の最適パスは、その最大エッジが導入される何らかのしきい値に対応する必要があるため、スイープでは、関連するすべての最大値を正確に 1 回評価し、その制約の下で達成可能な最良の最小値と組み合わせることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.min_edge = [10**18] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b, w):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False

        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]
        self.min_edge[a] = min(self.min_edge[a], self.min_edge[b], w)
        return True

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        u, v, w = map(int, input().split())
        edges.append((w, u - 1, v - 1))

    edges.sort()

    dsu = DSU(n)

    ans = 10**18

    for w, u, v in edges:
        dsu.union(u, v, w)

        if dsu.find(0) == dsu.find(n - 1):
            root = dsu.find(0)
            ans = min(ans, dsu.min_edge[root] + w)

    print(ans)
```DSU 構造は、許容されるエッジの重みを徐々に増やしながら、接続されたコンポーネントを維持します。 結合操作は、接続性をマージするだけでなく、各コンポーネント内に現れる最小のエッジの重みも追跡します。これは、可能な最小のパス コストを再構築するために不可欠です。 

ノード 1 と n が何らかのエッジ重みで初めて接続されるとき$w$、 それ$w$は候補最大値として機能します。 そのコンポーネントに保存されている最小エッジは、その接続状態と互換性のある最良の最小エッジを提供し、それらの合計が候補の答えとして評価されます。 

微妙な点は、1 と n がすでに接続されている後、同じコンポーネントがさらに進化する可能性があることです。 だからこそ私たちは早めにやめないのです。 その後のマージでは、接続を維持しながら最小エッジが小さくなる可能性があり、合計が減少する可能性があります。

 ## 特殊なケース

 重要なエッジ ケースは、最適なパスがエッジに関して最短パスではなく、代わりに迂回を使用して最終コストの最小エッジを削減する場合です。 たとえば、1 と n の間に直接の重いエッジがあり、非常に小さなエッジを含む長いパスがある場合、アルゴリズムはスイープを通じて最大値を制御しながら最小項を削減するため、より長い構造を正しく選択します。 

もう 1 つの微妙なケースは、1 と n が初めて接続されたときに最良の答えが得られない場合です。 後のマージでは、現在の最大値をあまり積極的に増やすことなく、同じコンポーネントに小さな最小エッジを導入できるため、スイープを継続することでこれらの改善が確実に取り込まれます。
