 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ一連のドアを与えられています。 各ドアは開いているか閉じています。 ユセフは最初のドアの前からスタートし、厳密にドア 1 からドア n まで順番に移動する必要があります。 開いたドアを通過するには時間がかかりますが、閉じたドアは特別な能力を使用しない限り完全に移動をブロックします。 

特別な能力は、一定期間継続する 1 回のアクティベーションです。`x`。 そのウィンドウの間、すべての閉じたドアは開いたドアと同じように動作し、通行が可能になります。 その窓の外では、閉まったドアは依然として通行できません。 

問題は、ユセフが立ち往生することなくすべてのドアを左から右に通過できるように、この能力をアクティブにする瞬間を選択する方法が存在するかどうかです。 

入力サイズは非常に小さいため、`n ≤ 10`そして`x ≤ 10`, そのため、テスト ケースごとに複数の可能性を試す方法でも実行可能です。 ただし、1 回限りのアクティベーションが存在すると、グローバルな制約が作成されます。つまり、能力が使用されると、そのタイミングは閉じたドアの連続した領域に合わせなければならず、そうしないと進行が妨げられてしまいます。 

重要なエッジ状況は、閉じられたドアが複数の別々のグループに分割されるときに発生します。 たとえば、閉じたドアがシーケンスの最初と最後に出現し、その間に長い開いたギャップがある場合、短いアクティブ化ウィンドウでは両方のグループを一度にカバーできない可能性があります。 

もう 1 つの重要なケースは、すべての閉じたドアがしっかりと詰め込まれているが、そのスパンが長さよりも長い場合です。`x`。 たとえば、次の場合`x = 2`4 連続して閉ざされたドアがある場合、最適なタイミングでもすべてをカバーすることはできません。 

最後に、最初または最後のドアが閉まっているのは誤解を招く可能性があります。 単純なアプローチでは、最初に閉じられたドアでボタンを開始すると常に機能すると想定する可能性がありますが、その後に閉じられたドアがアクティブ化ウィンドウの外側に表示される場合、トラバーサルは失敗します。 

## アプローチ

 ブルートフォースアプローチでは、ボタンをアクティブにするあらゆる瞬間をシミュレートし、ドアを一歩ずつ通過することをシミュレートします。 アクティブ化の開始位置ごとに、閉じたドアを選択した間隔内でのみ開いたものとして扱うことで、Yousef がすべてのドアを通過できるかどうかを確認します。 

せいぜいあるので`n`アクティベーションの可能な開始点と各シミュレーションのコスト`O(n)`、これにより、`O(n^2)`テストケースごとの解決策。すでに与えられた自明なもの`n ≤ 10`。 ただし、完全なシミュレーションを避けることでさらに簡素化できます。 

重要な観察は、ボタンが閉じたドアの連続したブロックでのみ重要であるということです。 ユセフは、起動ウィンドウの外で閉まったドアに遭遇すると、すぐに停止します。 したがって、重要なのは閉ざされたドアの最も長く連続するセグメントだけです。そのセグメントが、すべてのブロックされた位置を連続して通過するのに必要な最小時間枠を決定するからです。 

連続した実行の最大長を特定したら、`1`つまり、問題は、この実行がアクティベーション ウィンドウ内に収まるかどうかを確認することになります。`x`。 そのような最長のセグメントが次の値より長い場合、`x`の場合、どのボタンを配置しても完全にカバーできなくなり、トラバースが不可能になります。 それ以外の場合は、パスの残りの部分を歩きながら、そのセグメントを完全にカバーするようにアクティブ化ウィンドウを常に位置合わせできます。

 ## アルゴリズムのチュートリアル

 1. 現在連続している閉じたドアのブロックの長さを追跡しながら、配列を左から右にスキャンします。 

私たちが見るたびに、`1`、現在のブロックを拡張します。 私たちが見るとき、`0`、ブロック長をゼロにリセットします。 
2. 変数を維持する`best`これまでに検出された最大ブロック長を格納します。 

この値は、ユセフが連続した 1 回の区間で克服しなければならない最も困難な連続障害物を表します。 
3. 配列全体を処理した後、比較します。`best`と`x`。 

もし`best`より大きい`x`、その場合、可能な限り最適なアクティベーションウィンドウでも完全なブロックをカバーすることはできません。 
4. もし`best`以下である`x`の場合は「YES」を出力し、それ以外の場合は「NO」を出力します。 

連続したブロックのみを追跡する理由は、分離された閉じたドアは、時間的に単一の連続セグメント内にない限り、単一のアクティブ化ウィンドウの下では相互作用しないためです。 Yousef は 1 秒あたり 1 つのドアを決定的に前進させるため、時間的な順序はインデックスの順序と直接一致します。 

### なぜ効果があるのか

 このアルゴリズムは、ボタンの持続時間を超えて通過できない場合は、閉じたドアの連続セグメント内で発生するという不変条件に依存しています。 Yousef は厳密に左から右に移動し、ドアごとに正確に 1 単位の時間を費やすため、アクティブ化ウィンドウはインデックスの連続セグメントにも対応します。 したがって、重要な唯一の制約は、連続したセグメントが存在するかどうかです。`1`よりも長い`x`。 何も存在しない場合は、他の場所での進行を見逃すことなく、必要なすべてのブロックされた位置をカバーするようにアクティベーションを常に調整できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    a = list(map(int, input().split()))
    
    best = 0
    cur = 0
    
    for v in a:
        if v == 1:
            cur += 1
            best = max(best, cur)
        else:
            cur = 0
    
    print("YES" if best <= x else "NO")
```実装では 2 つの変数のみが保持されます。`cur`そして`best`。 の`cur`カウンタは閉じたドアの現在のストリークを測定し、開いたドアがストリークを破るたびにリセットします。 の`best`変数には、観察された最大のストリークが格納されます。 

微妙な点は、Yousef の動きや起動のタイミングを明示的にシミュレートする必要がないことです。 動きの線形構造により、実行可能な戦略は連続したブロックのみに依存することが保証されるため、問題を 1 回のスキャンに減らすだけで十分です。

## 特殊なケース

 のような最小限のケース`n = 1`単一の閉じたドアを使用すると、アルゴリズムが単一の要素を有効な連続ブロックとして正しく扱うかどうかをテストします。 スキャンによって生成されるのは、`best = 1`、との比較`x`正しく動作します。 

次のような完全にブロックされた配列`1 1 1 1 1`アルゴリズムがセグメントを早期にリセットしたり、セグメントを誤って分割したりしないことをチェックします。 カウンタは継続的に増加し、正しい最大セグメント長が生成されます。 

のような混合パターン`0 1 1 0 1 1`開いたドアでのリセットが適切に処理されるようにします。 このアルゴリズムは 2 つの個別のブロックを記録し、アクティブ化に対する真の制約を反映する最大値のみを保持します。
