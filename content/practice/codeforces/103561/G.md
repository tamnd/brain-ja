 ## 解決策
 ## 問題の理解

 サイズ V の根付きツリーから始めます。このツリーはバイナリ形式の構造ですが、形式的には単なる根付きツリーです。 このツリーの各リーフは、同じツリーの反映されたコピー内の対応するリーフとペアになります。 この反射の後、追加のエッジが対応する葉の間に導入され、2 つの同一のツリーが境界の葉に沿って効果的にマージされます。 

これにより、ツリーではなくなった新しい無向グラフが生成されます。 オリジナルとミラーリングされたコピーの間のリーフ接続のため、グラフにはサイクルが含まれます。 タスクは、この構築されたグラフ内にいくつの異なる単純サイクルが存在するかを数えることです。 

重要な解釈の変更は、一般的なグラフで 2 つのツリーを明示的に構築してサイクルをカウントしていないことです。 代わりに、すべてのサイクルは、元のツリー内の 2 つの異なるルートから葉へのパスを取得し、ミラー化された構造を通じて「それらを閉じる」ことによって形成されます。 したがって、サイクルは、任意のグラフ走査ループではなく、リーフ パスの構造的な組み合わせに対応します。 

入力サイズ V は最大 10^6 であるため、サイクルを列挙しようとしたり、ミラーリングされたグラフを明示的に構築しようとしたりするソリューションは、直ちに実行不可能になります。 二重構造上の線形グラフの走査でも、定数とメモリ レイアウトには細心の注意を払う必要があります。 これにより、最終グラフで DFS を使用してサイクルを検出しようとするアプローチはすでに除外されています。ミラーリング後のエッジの数は依然として線形である可能性がありますが、サイクル構造は組み合わせ的に密であるためです。 

素朴な解釈では、ミラーリングされたツリーを明示的に構築し、対応するリーフを接続してから、サイクル列挙アルゴリズムを実行することになります。 単一の DFS ベースのバックエッジ列挙であっても、追加された各リーフ エッジが共有ツリー パスを介して複数の重複するサイクルを作成するため、指数関数的な動作に低下します。 

ツリーがチェーンに退化すると、微妙な特殊なケースが発生します。 この場合、リーフは 2 つだけであり、すべてのサイクルが 1 つの大きな外側サイクルに崩壊します。 各リーフ接続が独立したサイクルを形成すると仮定する間違ったアプローチでは、カウントが過剰になります。 

もう 1 つのエッジ ケースは、単項分岐の大きなチェーンにノードの子が 1 つだけある場合です。 問題は「バイナリ ツリー型」と説明されていますが、入力は完全なバイナリ ツリーを厳密に保証するものではないため、完全なバイナリ構造を仮定すると、誤ったカウント ロジックが発生します。 

## アプローチ

 ブルートフォース解釈により、完全なミラー構造が明示的に構築されます。 ツリーを複製し、対応するリーフを接続し、DFS またはサイクルベースの抽出方法を使用してすべての単純なサイクルをカウントしようとします。 結果として得られるグラフでは、すべてのサイクルが単純な閉じたウォークであるため、これは原理的には正しいです。 

ただし、L 個のリーフ接続を持つグラフ内の単純なサイクルの数は急速に増加します。 各リーフ接続には基本的なサイクルが導入され、その内部構造はルートからリーフへのパスの共有プレフィックスに依存します。 多くのリーフが長い共通の祖先を共有する最悪のケースでは、DFS ベースの列挙では共有サブツリーが繰り返し再検討され、同じ構造サイクルが複数回カウントされます。 これにより、重複するサイクル分解で指数関数的な爆発が発生します。 

重要な洞察は、最終的なグラフは依然として基本的にツリーと L 個の追加エッジであり、各追加エッジが 2 つの葉を接続し、そのパスが固有の最下位共通祖先を共有するということです。 このような各エッジは、グラフのサイクル空間内の 1 つの基本サイクルに正確に寄与します。 したがって、問題は、リーフペアリングによって引き起こされるこれらの独立したサイクルの数をカウントすることに帰着します。

サイクルを明示的に構築する代わりに、リーフペアがいくつ存在するか、およびそれらが LCA 集計を通じて暗示する明確な構造的接続がいくつあるかを計算します。 ミラーリングされた構造により、すべてのリーフが効果的に 1 つのペアリングに参加することが保証されるため、サイクル カウントはツリーに伝播されるサブツリー リーフ カウントの関数になります。 

これにより、問題は、各サブツリーが上向きに伝播する「オープン リーフ接続」の数に寄与し、そのような 2 つの寄与が一致するたびにサイクルが生成される、事後探索に帰着します。

 | リーフペア伝播におけるツリー DP | O(V) | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、ポストオーダー DFS を使用して処理します。 私たちが維持する中心的な目的は、各サブツリー内のリーフの数と、ミラー接続を考慮した場合にこれらのリーフがサイクル形成にどのように寄与するかです。 

1. ルートから DFS を実行し、各ノードのサブツリー内のリーフ ノードの数を計算します。 ノードに子がない場合、ノードはリーフになります。 
2. 各ノードについて、その子のサブツリーを 1 つずつ検討します。 各子サブツリーは、後でミラー構造を通じてペアになる特定の数のリーフを提供します。 
3. ノードで子サブツリーを結合するとき、これまでに確認されたリーフ寄与の累計を維持します。 k 個の葉を提供する新しい子サブツリーごとに、k * (現在累積された葉) 個の新しいサイクルを形成します。 これは、ミラー誘導接続を介して、異なるブランチにわたるリーフのペアを表します。 
4. ノードのすべての子を処理した後、このサブツリー内のリーフの総数をその親に返します。 
5. すべてのノードでのサイクル寄与をグローバルな応答に累積します。 

重要な考え方は、異なるサブツリーの 2 つのリーフがミラーリングされたリーフ識別を通じて接続されるたびにサイクルが形成されるということです。 パスが分岐する最下点はまさにサイクルがカウントされる場所であるため、各ペアは LCA で正確に 1 回カウントされます。 

### なぜ効果があるのか

 最終的なグラフ内のすべてのサイクルは、元のツリー内のパスが何らかの最下位共通祖先で分岐するリーフのペアに一意に対応します。 ミラー構造により、これら 2 つのリーフが、反射構造を介してサイクルを閉じる方法で接続されることが保証されます。 2 つの異なるリーフを選択せず​​にサイクルを形成することはできず、そのようなペアはすべて、結果として得られるグラフ内で 1 つの単純なサイクルを正確に定義します。 

DFS は各ノードを異なる子サブツリーからのリーフ ペアの一意の LCA として処理するため、各サイクルは最高分岐点で 1 回だけカウントされます。 これにより二重カウントが防止され、完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)

    ans = 0

    def dfs(u):
        nonlocal ans
        leaf_count = 0

        for v in g[u]:
            sub = dfs(v)

            ans += leaf_count * sub
            leaf_count += sub

        if leaf_count == 0:
            return 1
        return leaf_count

    dfs(1)
    print(ans)

if __name__ == "__main__":
    solve()
```DFS は、各サブツリーのリーフの数を返します。 ノードを処理するとき、子を順番に集約します。 新しいサブツリーを組み込むたびに、そのリーフをさまざまなサブツリーで以前に確認されたすべてのリーフとペアにします。これは、ミラーリングされた構造全体にわたるリーフ接続によって形成されるサイクルをカウントすることに正確に対応します。 

微妙な実装の詳細は、子のないノードを 1 を返すリーフとして扱うことです。これが、サイクル形成を上向きに伝播させるシードです。 

蓄積の順序は重要です。実行中のリーフ数を更新する前に寄与分を追加する必要があります。そうしないと、単一のサブツリー内の自己ペアリングが誤ってカウントされてしまいます。 

## 実用的な例

 ルート 1 に 2 つの子 2 と 3 があり、2 と 3 の両方が葉である小さなツリーを考えてみましょう。 

ノード 1 の場合:

 | ステップ | 子を処理中 | 葉っぱの寄稿 | 実行中のリーフカウント | 新しいサイクルが追加されました |
 | --- | --- | --- | --- | --- |
 | 1 | 子供2 | 1 | 0→1 | 0 |
 | 2 | 子供3 | 1 | 1→2 | 1 |

 結果は、リーフ 2 とリーフ 3 のペアによって形成される 1 サイクルになります。 

これは、異なるサブツリーをマージする場合にのみサイクルがカウントされることを示しています。 

次に、ノード 3 のみがリーフであるチェーン 1 → 2 → 3 を考えます。 

ノード 3 では 1 を返します。ノード 2 では子が 1 つだけであるため、ペアリングは発生しません。 ノード 1 では、やはり 1 つのサブツリーのみが寄与するため、サイクルは形成されません。 最終的な答えは 0 で、明確な葉のペアが存在しないという事実と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V) | 各エッジは DFS で 1 回訪問され、各ノードは子に対して定数時間の集約を実行します。 
| スペース | O(V) | 隣接リストと再帰スタック |

 このソリューションは、ペアごとの列挙を回避し、すべてのサイクル カウントを線形ツリー集約に削減するため、最大 10^6 ノードの制約内に快適に適合します。

def run(inp: str) -> str:

    from collections import deque

    # embedded solution
    sys.setrecursionlimit(10**7)

    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)

    ans = 0

        leaf_count = 0

            ans += leaf_count * sub
            leaf_count += sub

        return leaf_count

    return str(ans)

 ## 特殊なケース

 純粋なチェーンでは、すべてのノードに子が 1 つだけあるため、DFS が結合する 2 つの独立したリーフ グループに遭遇することはありません。 リーフ カウントは項間乗算をトリガーすることなく上方に伝播するため、累積サイクル カウントはゼロのままです。 

完全な星では、すべての葉が根に直接接続されています。 根元では、新しい葉のそれぞれが、以前に見られた葉の数に等しいサイクルに寄与し、三角形の数のペアを生成します。 すべてのリーフがルート レベルで個別のサブツリーの寄与として扱われるため、DFS はこれを正しく累積します。 

ツリーが非常にアンバランスであるにもかかわらず、上部近くで分岐している場合でも、サイクル数は分岐点でのみ決定されます。 DFS は、リーフの各ペアがその寄与が最初に一致する一意の最小共通祖先を持っているため、ペアが 2 回カウントされることを保証します。
