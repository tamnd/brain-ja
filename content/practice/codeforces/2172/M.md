 ## 解決策
 ## 問題の理解

 We have a network of cities connected by roads, where each road is exactly one kilometer long. 各都市は 1 種類の農産物を生産しており、都市 1 は中心港です。 目標は、製品の種類ごとに、その製品を生産している都市が港に到達するまでに移動しなければならない最悪の場合の距離を見つけることです。 つまり、製品タイプに関しては、$i$を生産するすべての都市からの最短距離のうちの最大値が必要です。$i$都市1へ。 

入力により都市の数が得られます$n$、道路$m$、製品タイプ$k$、その後に長さのリストが続きます$n$各都市の産物を示します。 次は$m$線は双方向エッジを表します。 グラフは接続されていることが保証されているため、すべての都市が都市 1 に到達できます。出力は次の 1 行です。$k$整数$i$-番目の整数は製品の最大距離です$i$。 

制約は、最大で次のものを持つことができることを示しています。$2 \times 10^5$都市と端。 各都市から港までの最短経路を個別に計算する単純なアプローチでは、次の時間がかかります。$O(n + m)$都市ごとに、結果として$O(n(n + m))$が遅すぎます。 これは、距離を効率的に計算するにはグラフを 1 回通過する必要があることを意味します。 すべてのエッジの長さが等しいため、線形時間で重み付けされていないグラフの最短パスを生成する幅優先探索 (BFS) が理想的です。 

複数の都市が同じ製品を生産する場合、特にそのうちの 1 つが都市 1 である場合、微妙なエッジ ケースが発生します。たとえば、都市 1 が製品 3 を生産する場合、他の都市もその製品を生産している場合でも、その製品の最大距離は 0 である必要があります。 別の特殊なケースは、ある製品タイプが 1 つの都市のみで生産されている場合に発生します。 私たちのアルゴリズムは依然としてその距離を正しく計算する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、BFS またはダイクストラを使用して、製品を生産する各都市から都市 1 までの最短パスを計算します。 次に、各製品の最大距離を取得します。 これが機能するのは、BFS が重み付けされていないグラフ内の最短パスを保証しているためです。 ただし、最悪の場合、すべてが$n$都市が同じ製品を生産している場合、私たちは実行します$n$BFS トラバーサル、それぞれの処理$O(n + m)$、につながる$O(n(n + m))$、これは許容限界をはるかに超えています。$n = 2 \times 10^5$。 

最適なアプローチは、重み付けされていないグラフ内の最短パスの対称性を利用します。 すべての都市から BFS を開始する代わりに、港湾都市 1 から単一の BFS を開始します。BFS は、都市 1 から他のすべての都市までの最短距離を計算します。$O(n + m)$。 この後、すべての都市を単純に反復し、製品タイプごとに、その製品を生産している都市間の最大距離を追跡できます。 これにより、次の作業が軽減されます。$O(n(n + m))$シングルに$O(n + m)$BFS と都市全体のリニア スキャンにより、時間の制約内に快適に収まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n + m)) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m + k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析して都市の数を読み取る$n$、道路$m$、製品タイプ$k$。 各都市が生産する製品のリストもお読みください。 
2. 道路情報を使用してグラフの隣接リストを作成します。 この表現により、BFS 中に近隣ノードを効率的に走査できます。 
3. サイズの距離配列を初期化します。$n + 1$センチネル値を使用して (例:$-1$) 未訪問の都市を示します。 都市の距離を 1 から 0 に設定します。 
4. 都市 1 から開始して BFS を実行します。キューを使用して都市をレイヤーごとに処理します。 デキューされた都市ごとに、近隣都市をすべてチェックします。 近隣都市が訪問されていない場合は、その距離を現在の都市の距離に 1 を加えた値に設定し、キューに追加します。 
5. BFS 後、距離配列には都市 1 から他のすべての都市までの最短距離が含まれます。 
6. サイズの結果配列を初期化します。$k + 1$ゼロ付き。 すべての都市を反復処理します。 都市の製品タイプについては、対応する結果エントリを現在の値と都市の距離の最大値に更新します。 
7. 製品タイプの結果を印刷します。$1$に$k$。 

機能する理由: BFS は、ある都市を初めて訪問するときに、開始都市からその都市への最短経路が見つかったことを保証します。 各製品タイプの最大距離を追跡すると、その製品を生産している最も遠い都市が正確に特定されます。 すべてのエッジの重みが等しいため、BFS は最短距離を正しく計算し、結果が正確であることを保証します。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

n, m, k = map(int, input().split())
products = list(map(int, input().split()))

# Build adjacency list
graph = [[] for _ in range(n + 1)]
for _ in range(m):
    u, v = map(int, input().split())
    graph[u].append(v)
    graph[v].append(u)

# BFS from city 1
dist = [-1] * (n + 1)
dist[1] = 0
queue = deque([1])

while queue:
    u = queue.popleft()
    for v in graph[u]:
        if dist[v] == -1:
            dist[v] = dist[u] + 1
            queue.append(v)

# Track maximum distances per product type
res = [0] * (k + 1)
for i in range(n):
    p = products[i]
    res[p] = max(res[p], dist[i + 1])

print(" ".join(str(res[i]) for i in range(1, k + 1)))
```隣接リストにより許可されるのは、$O(1)$隣人の検索。 BFS はキューを使用して、港からの距離が遠い順に都市を訪問することを保証します。 最後のループでは、都市をその製品タイプに正しくマッピングし、表示される最大距離を更新します。 の`i + 1`インデックス付けにより、0 から始まる配列の位置が 1 から始まる都市番号に変換されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | BFS は各都市を 1 回訪問し、各エッジを 1 回反復します。 都市を巡る最終ループは O(n) です。 |
 | スペース | O(n + m + k) | 隣接リストには O(n + m) がかかります。 距離配列 O(n)。 結果配列 O(k)。 キューは最大でも O(n) です。 |

 と$n, m \le 2 \times 10^5$、これは快適に 1 秒未満の実行時間であり、使用するメモリは 256 MB 未満です。
