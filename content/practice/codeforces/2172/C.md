 ## 解決策
 ## 問題の理解

 一連の円を中心の 1 つの直線上に配置し、それらがどのように重なり合ったり、相互に入れ子になったりするかを制御する必要があります。 各円の半径は固定されており、半径は増加しない順序で指定されます。 

ジオメトリが平面内にあるとしても、すべての中心は 1 つの線上になければならないため、すべてが 1 次元の配置問題に陥ります。 2 つの円間の距離は、それらの中心と半径によって決まります。2 つの円が近すぎる場合、それらの内部は交差します。 それらが十分に離れている場合、それらは互いに素であり、一方がはるかに大きい場合は、もう一方が含まれる可能性があります。 

いくつかの構造ルールを尊重した有効な構成を構築する必要があります。 まず、中心は直線上にあり、k を超えて離れている 2 つはありません。 次に、円は交差してはなりません。つまり、中心間の距離が半径に比べて十分に大きくなければなりません。 第三に、ネストは一貫した構造を形成する必要があります。円に他の 2 つが含まれる場合、それら 2 つは封じ込めの観点から無関係ではありえないため、封じ込めは局所的にチェーンのような階層のように動作します。 最後に、囲まれるかどうかは最初の ℓ 円のみがオプションであり、ℓ 以降のすべての円は少なくとも 1 つの大きな円の内側になければなりません。 

すべての有効な構成の中で、異なる円に属する任意の 2 点間の最小距離を最大化します。 直感的には、これは円の境界間の最も狭い「ギャップ」であり、実現可能な範囲で構成をできるだけ分離したいと考えています。 

制約はすでに構造を示唆しています。 n が 100000 までの場合、円間の二次相互作用は不可能です。 小さなパラメーター ℓ (最大 200) が鍵です。これは、最初のいくつかの円だけが組み合わせによる決定を必要とし、残りは決定論的な貪欲パターンに従う必要があることを強く示唆しています。 

よくある失敗例は、隣接する円のみが重要であると想定した場合に発生します。 たとえば、局所的な半径の差のみを使用して円を左から右に貪欲に配置すると、ℓ を超えるインデックスの囲い要件に違反する可能性があります。 もう 1 つの微妙な問題は、コンテインメントが円ごとに独立して動作すると仮定しているのに対し、条件 4 ではネストのグローバルな一貫性が強制されるため、ペアごとのジオメトリが機能する場合でも、任意の重複チェーンは無効になります。 

## アプローチ

 直接的な総当り的なアプローチでは、線上のすべての中心に位置を割り当て、すべての幾何学的制約をチェックして、結果として得られる円の境界間の最小距離を計算します。 位置を離散化したり、バックトラッキングを試みたりした場合でも、各円の配置は前のすべての円の配置に依存し、包含により組み合わせ構造が導入されます。 これにより、指数関数または階乗探索空間が生じますが、10^5 までの n では明らかに不可能です。 

重要な観察は、実現可能性は答えにおいて単調であるということです。任意の 2 つの円の間で特定の最小距離 d を達成できれば、構成をわずかに圧縮することで、より小さな値も達成可能です。 これにより、答えの二分探索が可能になります。 

候補 d を固定すると、問題は次のようになります。境界間の少なくとも距離 d を維持し、すべてのネスト制約を満たしながら、円を順番に配置できるか? 半径はソートされているため、インデックス ℓ の後の円が何らかの囲み構造に強制的に組み込まれるようにしながら、各円を新しい囲みセグメントの開始または前のセグメント内に収まるように貪欲に割り当てることができます。

2 番目の構造的洞察は、最初の ℓ 円のみがグローバルなネスティングの柔軟性に影響を与えることができるということです。 その後、すべての円を「カバー」する必要があります。これは、円を有効な囲み間隔に割り当てる必要があることを意味します。 これにより、制御された DP のようなエンベロープまたは貪欲なエンベロープ内の最初の ℓ 円の配置を事前計算またはシミュレートし、残りの円に対して決定論的に拡張することができます。 

固定 d の実現可能性チェックの内部では、最後に使用された中心位置を維持し、新しい円がそれぞれ新しいセグメントを開始するか、有効な囲み円の内側に配置されることを確認します。 中心が距離 k 以内にあるという制約により、全体の広がりが制限されるため、グローバルな間隔制約も適用します。 

解決策は、半径順序付けと最初の ℓ 要素の制限された組み合わせ自由度によって駆動される貪欲な実行可能性チェックと組み合わせた d の二分探索に帰着します。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 二分探索 + 貪欲な実現可能性 | O(n log R) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 異なる円に属する任意の 2 点間の最小許容距離として扱い、答え d を二分探索します。 

1. 円を半径の非増加順に並べ替えます。これは入力によってすでに保証されています。 これにより、円に別の円を含めることができるときは常に、その半径が常に大きいか等しいことが保証され、包含ロジックが簡素化されます。 
2. 固定 d の実現可能性チェックを定義します。 中心線上に左から右に円を配置することをシミュレートします。 
3. 各円 i について、前の円からの最小許容距離を計算します。 これは、重なりを防止し、境界距離を少なくとも d 確保することから導かれます。 円 i が位置 x に配置され、円 i-1 が x_prev に配置された場合、x ≥ x_prev + (r_{i-1} + r_i + d) が強制されます。 これにより、内部の分離と必要な分離の両方が保証されます。 
4. また、包含構造も維持します。インデックス ℓ の後の円は、それより前の円の内側になければなりません。 私たちは、「利用可能なコンテナ」のアクティブなセットを維持します。これは、半径が十分に大きく、その空間スパンに新しい円を含めることができる円です。 円 i > ℓ を配置する場合、距離 k の制約の下でもまだ容量がある、最も近い有効な囲み円に円を割り当てます。 
5. いずれかの点で円に有効な位置またはコンテナを割り当てることができない場合、この d の実現可能性は失敗します。 
6. また、最大中心距離が k を超えないというグローバル制約も保証するため、最終位置から最初の位置を引いた値は k 以内に留まらなければなりません。 
7. 実現可能性があれば、d を大きくしてみます。 それ以外の場合は小さくなります。 

重要な不変条件は、すべてのステップで、部分的な配置が有効なネスト フォレストを維持し、すべての幾何学的間隔制約を尊重することです。 私たちは常に最も早い有効な位置に円を貪欲に配置するため、後でより大きな間隔を許可できる可能性のある構成を見逃すことはありません。遅延は利用可能なスペースを減らすだけであり、半径の順序付けは再順序付けの利点を妨げます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(d, n, k, l, r):
    # positions of centers
    x = [0] * n
    
    # last position
    x[0] = 0
    
    # active containers stack: (radius, rightmost_bound)
    stack = [(r[0], 0)]
    
    # container assignment for circles > l
    parent = [-1] * n
    
    for i in range(1, n):
        # place i as far left as possible
        x[i] = x[i - 1] + r[i - 1] + r[i] + d
        
        # pop containers that cannot contain i
        while stack and stack[-1][0] <= r[i]:
            stack.pop()
        
        if i >= l:
            if not stack:
                return False
            parent[i] = stack[-1][1]
        
        stack.append((r[i], i))
    
    if x[-1] - x[0] > k:
        return False
    
    # check enclosure requirement
    for i in range(l, n):
        if parent[i] == -1:
            return False
    
    return True

def solve():
    k, n, l = map(int, input().split())
    r = list(map(int, input().split()))
    
    lo, hi = 0, k + max(r) * 2
    
    ans = 0
    
    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid, n, k, l, r):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、実現可能性のチェックが二分探索から分離されます。 機能`check`候補ギャップと一致する最小限の可能な位置を使用して中心の左から右への配置を構築する ｄ． この貪欲な配置は重要です。 d に有効な構成が存在する場合、有効な解は有効性を低下させることなく右にシフトできるため、貪欲な構成によって人為的に実現可能性が損なわれることはありません。そのため、左揃えの構築は安全です。 

スタックは、囲む円の候補を維持します。 半径はソートされているため、円に小さい円を含めることができなくなると、有効性が回復することはないため、ポップは安全です。 ℓ の後の円については、コンテナを割り当てる必要があります。 それ以外の場合、構成はエンクロージャの条件に違反します。 

最後の距離制約により、許容される広がり k を超えないことが保証されます。

 ## 特殊なケース

 1 つのエッジ ケースは、ℓ が n に等しい場合に発生します。 その状況では、強制的に囲まれる円は存在しないため、アルゴリズムはコンテナが割り当てられていない構成を拒否してはなりません。 親条件は i ≥ ℓ の場合にのみ適用されるため、実現可能性チェックでこれが処理されます。 

すべての半径が等しい場合、別のエッジ ケースが発生します。 その場合、ジオメトリによる厳密なネストを除いて封じ込めは不可能であるため、最初の ℓ を超えるすべての円は純粋に空間配置に依存する必要があります。 貪欲な間隔 x[i] = x[i-1] + 2r + d はこれを直接捉えており、実現可能性は k にのみ依存します。 

最後のケースは、k が非常に大きい場合です。 その場合、答えは幾何学的広がりではなく純粋にネスト制約によって制限され、二分探索は i ≥ ℓ について包含スタックが空になるまで d をプッシュします。 これは、入力分布に応じて制限要因がジオメトリから階層に切り替わる可能性があることを示しています。
