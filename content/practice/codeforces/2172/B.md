 ## 解決策
 ## 問題の理解

 すべてのバスは同じ速度で道路に沿って移動します`x`。 バス`i`位置から始まります`s_i`時に`0`、右に移動し、到達すると消えます`t_i`。 

人は位置から始まります`p`。 彼らは速く歩くことができます`y`、 どこ`y < x`。 人とバスが同時に同じ位置を占めると、その人は即座にそのバスに乗り込むことができます。 バスに乗っている間、彼らは高速で移動します`x`、いつでもバスから降りる可能性があります。 

すべての開始位置について`p_i`、位置で道路の終点に到達するために必要な最小時間を計算する必要があります。`ℓ`。 

最初の観察は、すべての移動が 1 つの路線上で行われ、すべてのバスの速度が同じであるということです。 制約は大きく、最大で`2 · 10^5`バスと`2 · 10^5`クエリ。 Any algorithm that examines all buses for every person would require roughly`4 · 10^10`まったく実行不可能な操作です。 に近いものが必要です`O((n+m) log n)`。 

この問題の最も欺瞞的な部分は、実際にどのようなバス移動が可能であるかを理解することです。 

2 つのバスを考えてみましょう。```
bus A: 0 -> 10
bus B: 5 -> 20
```どちらも同じ速度で動きます。 バス A に乗っている場合、バス B の距離は永遠に一定なので、後でバス B にジャンプすることはできません。 速度が等しいということは、バスがお互いに追いつくことがないということです。 

もう一つの微妙なケースは、後ろから発車したバスに乗ろうとしている人です。```
x = 4, y = 1
bus: 0 -> 100
person: 10
```バスは人より速いです。 人の後ろからスタートしたので、最終的には追いつくことができます。 集合位置は相対速度によって決定されるため、正しく計算する必要があります。 かどうかだけを確認するいい加減な解決策`s_i ≥ p`この有効な搭乗機会を逃すことになります。 

3 番目の罠は、バスに乗ることが常に有益であると仮定していることです。```
ℓ = 100
x = 10
y = 9

bus: 0 -> 1
person: 0
```バスは人を乗せるのは1メートルだけで、その後消えてしまいます。 直接歩いてもほぼ同じ速さです。 最適な答えは、バスに乗らないことも含め、あらゆる可能性を比較する必要があります。 

これらの観察は、問題が実際には転送のシーケンスではなく、独立したバスの機会を評価することにあることを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、各個人が個別に処理されます。 

特定の開始位置に対して`p`、すべてのバスを調べることができます。 バスごとに、バスが消える前にその人に会えるかどうかを判断します。 会議が可能であれば、その結果の位置への到着時間を計算します`ℓ`。 答えは、すべてのバスと純粋な徒歩の中での最小値です。 

これは正しいです。実行可能な戦略はすべて、永遠に歩くか、最初のバスに乗ることから始まるからです。 残念ながら、それは必要です`O(n)`クエリごとに動作するため、`O(nm)`全体的な複雑さ。 両方の値が到達すると、`2 · 10^5`、これは約になります`4 · 10^10`小切手。 

改善するには、単一のバスの形状を理解する必要があります。 

ある人が の位置から開始するとします。`p`そしてバスに乗ります`(s,t)`。 

もし彼らが時間通りに会えば`τ`、 それから```
p + yτ = s + xτ
```それは与える```
τ = (p - s)/(x - y)
```会議は次の場合にのみ可能です`p ≥ s`, そうしないと、バスはすでに前方にいて、人よりも早く遠ざかってしまうからです。 

バスはその後目的地に到着します```
T = (t - s)/x
```分。 

したがって、次の場合には搭乗が可能です```
(p - s)/(x - y) ≤ (t - s)/x
```再配置後:```
x p ≤ y s + (x - y) t
```これが重要な単純化です。 

定義する```
R = y s + (x - y) t
```立場の人にとっては`p`、バス`(s,t)`正確にいつ到達できるか```
R ≥ x p
```条件は 1 つの値のみに依存します`R`。 

次に、そのバスを使用した場合の合計移動時間を計算します。 

集合時間：```
τ = (p - s)/(x - y)
```乗車後は、バスが消えるまで車内に留まることが常に最適です。 バスは徒歩よりも早いので、早めに出発しても残りの所要時間は増えるだけです。 

到着時間は、```
τ + (t - meeting_position)/x + (ℓ - t)/y
```ミーティングポジションの代替とイールドの簡素化```
ℓ / y - p / (x - y)
    + s * x / (y(x-y))
    - t / y
```固定クエリ位置の場合`p`、最初の 2 つの項は定数です。 バスのみが貢献します```
value(bus) =
s * x / (y(x-y))
- t / y
```したがって、各クエリは次のことを尋ねます。 

すべてのバスの中で```
R ≥ x p
```最小バス値を見つけます。 

これは一次元のオフライン問題になります。 バスを並べ替える`R`。 クエリをしきい値で並べ替える`x p`。 すべてのバスの最小値を維持しながら、大きなしきい値から小さなしきい値までスイープします。`R`十分な大きさです。 

それぞれの質問に対する答えは、```
min(
    walking_time,
    base(p) + best_bus_value
)
```どこ```
walking_time = (ℓ - p)/y
base(p) = ℓ/y - p/(x-y)
```### Complexity Comparison

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O((n+m) log n) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. バスごとに`(s,t)`、計算する```
R = ys + (x-y)t
```そして```
V = sx/(y(x-y)) - t/y
```2. すべてのバスを次の基準で並べ替えます。`R`降順で。 
3. クエリ位置ごとに`p`、そのしきい値を計算します```
need = xp
```店`(need, index, p)`。 
4. すべてのクエリを次の基準で並べ替えます。`need`降順で。 
5. 最大のしきい値から最小のしきい値までクエリをスイープします。 
6. ソートされたバスリストへのポインタと変数を維持します。`best`、最小`V`すでに挿入されているすべてのバスの中で。 
7. 現在のクエリに対して、次のすべてのバスを挿入します。```
R ≥ need
```まさにそれらのバスがその位置から到達できるからです`p`。 
8. 歩行のみの時間を計算する```
walk = (ℓ-p)/y
```9. 少なくとも 1 つの到達可能なバスが存在する場合、計算します。```
bus_answer =
ℓ/y - p/(x-y) + best
```10. クエリの答えは、徒歩時間とバス利用時間の最小値です。 
11. 回答を元のクエリ順序に戻して印刷します。 

### なぜ効果があるのか

 重要な特性は、バス速度が等しいと、有用な転送がすべて排除されるということです。 2 台のバスが動き始めると、それらの相対位置は決して変わりません。 乗客は、最適な移動中に最大 1 台のバスに乗車できます。 

固定バスの場合、到達可能性条件は次のように単純化されます。```
R ≥ xp
```結果として得られる移動時間は、クエリに依存する一定の期間とバスに依存する一定の期間に単純化されます。 したがって、すべてのクエリは、最小のバス依存値を持つ到達可能なバスを選択することになります。 

スイープはバスを減少させて処理します`R`。 閾値を扱う場合`xp`、維持されたセットには、次の条件を満たすバスが正確に含まれています。`R ≥ xp`。 変数`best`はそのセット内の最小バス値であるため、最適なバス支援の旅が生成されます。 直接歩くことで最低限のことを行えば、バスが役に立たない可能性もカバーできます。 したがって、すべての答えは最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, L, x, y = map(int, input().split())

    buses = []
    d = x - y

    for _ in range(n):
        s, t = map(int, input().split())

        R = y * s + d * t
        V = s * x / (y * d) - t / y

        buses.append((R, V))

    queries = []
    for i in range(m):
        p = int(input())
        queries.append((x * p, i, p))

    buses.sort(reverse=True)
    queries.sort(reverse=True)

    ans = [0.0] * m

    ptr = 0
    best = float('inf')

    for need, idx, p in queries:
        while ptr < n and buses[ptr][0] >= need:
            best = min(best, buses[ptr][1])
            ptr += 1

        walk = (L - p) / y
        res = walk

        if best < float('inf'):
            bus_res = L / y - p / d + best
            res = min(res, bus_res)

        ans[idx] = res

    sys.stdout.write("\n".join(f"{v:.10f}" for v in ans))

if __name__ == "__main__":
    solve()
```最初の部分では、すべてのバスを 2 つの派生量に変換します。`R`到達可能性を決定しますが、`V`最終的な移動時間に対するそのバスの寄与全体を取得します。 

クエリはしきい値に変換されます`xp`。 バスとクエリを降順に並べ替えると、標準のスイープ ラインが可能になります。 しきい値が減少すると、より多くのバスが到達可能になるため、バスは 1 回だけ挿入されます。 

変数`best`最低限のものを収納する`V`現在到達可能なすべてのバスの中で。 すべてのクエリ依存の用語は選択されたバスから独立しているため、これで十分です。 

微妙なディテールが 1 つあります。`>=`バスを挿入するとき。 導出された条件はまさに`R ≥ xp`なので、次のように変更します`>`バスが目的地に到着した瞬間に開催される会議を誤って拒否してしまうことがあります。 

もう 1 つの詳細は、すべての計算が浮動小数点値を使用して実行されることです。 必要な精度はただ`10^-6`、数式には割り算が含まれているため、倍精度で十分です。

 ## 特殊なケース

 目的地で正確に到着できなくなったバスを考えてみましょう。```
1 1 10 4 1
0 4
3
```ここ```
R = 12
xp = 12
```バスが位置に到着したときにその人がバスに出会う`4`。 導出された条件は、`R ≥ xp`、 ない`R > xp`。 等価性が許可されるため、スイープではこのバスが挿入されます。 厳密に比較すると、誤って破棄されてしまいます。 

すでに目的地にいる人を考えてみましょう。```
1 1 100 10 1
0 50
100
```歩行時間はゼロです。 アルゴリズムは計算します```
walk = (100 - 100)/1 = 0
```バスベースのオプションで最小値を取得した直後にゼロを返します。 

人より先に出発するバスを考えてみましょう。```
1 1 100 10 1
50 90
0
```バスはすでに前にいて、より速く進みます。 導出された不等式は失敗します。```
xp > R
```スイープ中にバスがアクティブ セットに入ることはありません。 答えは純粋な歩行時間となり、正解です。 

到達可能な複数のバスを考慮します。```
2 1 100 10 2
0 50
20 90
10
```どちらのバスも到達可能条件を満たしています。 スイープでは、すべてのアクティブなバスの中で最小のバス値が維持されます。 どのバスが選択されるかに関係なく、すべてのクエリ依存項は同一であるため、格納されている最小値を選択することは、到達可能なすべてのバスを個別に評価して最良の結果を取得することとまったく同じです。
