 ## 解決策
 ## 問題の理解

 私たちは、各生徒が番号の付いたカードのサブセットから開始し、追加のカードが 1 枚ずつ公開される確率的カード ゲームをモデル化するように求められました。 ゲームの仕組みは割り算に基づいています。公開されたカードごとに、各生徒は自分の手札からカードを 1 枚選択し、公開された数字で割り切れる最小のカードがどの生徒がそのカードを獲得するかを決定します。 割り切れるカードがない場合、公開されたカードは捨てられます。 生徒たちは常に固定された決定論的な方法で最適にプレイします。割り切れるカードが使用できる場合は、そのような最小のカードを選びます。 それ以外の場合は、持っている最小のカードを選択します。 

入力は次のもので構成されます`n`までの値を持つカード$10^{18}$そして`m`学生の場合、各カードは最初は学生が所有しているか、または配られていません。 すべての未配カードが公開された後、各生徒が最終的に手にするカードの予想枚数を、確率のモジュラー逆数を使用して 998244353 を法として計算する必要があります。 

制約が教えてくれる`n`そして`m`両方とも最大 600 です。これは、より悪い解決策があることを意味します。$O(n^3)$遅すぎる可能性がありますので、$600^3$はおよそ 2×10^8 の演算であり、Python の境界線となる可能性があります。 カードの値は大きいですが、割り算チェック以外の算術演算を行う必要はありません。 

明らかではないエッジケースは、公開されたカードで割り切れるカードを生徒が持っていない場合に発生します。 この場合、生徒は自分の最小のカードを選択しますが、それは他の人の選択と微妙な方法で相互作用する可能性があります。 たとえば、すべての生徒の最小カードが公開されたカードより大きい場合、そのカードは破棄されます。 単純なシミュレーションは、各生徒の選択ルールを適切にモデル化していない場合、または捨てられたカードを正しく処理していない場合に失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、公開された未配カードのすべての可能な並べ替えをシミュレートすることです。 順列ごとに、各生徒の決定論的な選択ルールに従い、所有権を更新します。 すべての順列を考慮した後、各生徒の最終的な数を平均します。 このアプローチは正しいですが、非現実的です。未配カードが最大 600 枚存在する可能性があり、$k!$順列。 k = 10, 10 の場合でも! = 360 万、k = 20 の場合、次のようになります。$2.4 \times 10^{18}$、明らかに実行不可能です。 

最適なアプローチでは、各生徒の最終的なカード数の期待値が、期待の線形性を使用して未配カードごとに独立して計算できることが認識されています。 すべての順列を列挙する必要はありません。 公開されたカードについて`c`、手札にある最小の割り切れるカードを考慮し、それを他の生徒と比較することで、各生徒がそれを獲得する確率を計算できます。 分割可能なカードを持っている生徒がいない場合、そのカードは破棄されます。 各生徒には決定的な選択があり、公開されたカードを獲得するまでカードが手札から離れることはないため、どの生徒が各未配カードを獲得するかを事前に計算し、期待される貢献度を次のように計算できます。$1/k$未処理のカードごとに。 すべての未配カードを合計し、最初のカード数を加算すると、予想される最終的なカード数が得られます。 除算には逆モジュラーが使用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k! * n) | O(n) | 遅すぎる |
 | 期待値の線形化 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての未配カードを特定します。 させて`U`をそれらのインデックスとし、`k = |U|`。 入っている各カード`U`として期待されるカウントに独立して寄与します$1/k$教師が一様にランダムに選択するからです。 
2. 各生徒が、潜在的な約数ごとに最小のカードを手札に保管します。 各生徒に対して、潜在的に明らかになったカードの値から、その値で割り切れる生徒の最小のカードまでのマップを事前計算します。 そのようなカードが存在しない場合は、所有する最小のカードを保管します。 これにより、公開された各カードを高速に検索できます。 
3. 未配カードごとに`c`、すべての生徒を調べ、事前に計算されたルールに従って選択したカードを選択します。 生徒が選んだどのカードが次の数で割り切れるかを確認します。`c`。 その中で、一番小さいカードを持った生徒が勝ちです。 割り切れるカードがない場合、そのカードは捨てられます。 
4. 勝者の予想される生徒数を次のように増やします。$1/k$。 998244353 を法として処理するため、増分ごとに k の逆剰余を乗算します。 
5. すべての未配カードを処理した後、各生徒のカードの初期枚数を予想枚数に追加します。 結果をモジュロ 998244353 で出力します。 

機能する理由: 期待値の線形性により、各未配カードの期待値を個別に合計することができます。 事前計算により、決定論的な選択戦略が正しく適用されることが保証されます。 カードを並べ替えることで、「分割可能な最小のカード」の選択が正しいことが保証されます。 モジュラー演算により、整数演算が一貫して維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

owned = [[] for _ in range(m)]
undealt = []

for idx, owner in enumerate(b):
    if owner == 0:
        undealt.append(idx)
    else:
        owned[owner-1].append(a[idx])

min_card = [min(cards) if cards else 0 for cards in owned]

k = len(undealt)
inv_k = modinv(k)
expected = [len(cards) for cards in owned]

for idx in undealt:
    c = a[idx]
    winner = -1
    best = 0
    for i in range(m):
        sel = None
        for card in owned[i]:
            if card % c == 0:
                sel = card
                break
        if sel is None:
            sel = min_card[i]
        if sel % c == 0:
            if winner == -1 or sel < best:
                winner = i
                best = sel
    if winner != -1:
        expected[winner] = (expected[winner] + inv_k) % MOD

print(" ".join(str(x % MOD) for x in expected))
```最初のセクションは入力を読み取り、カードを所有しているカードと未取引のカードに分けます。`min_card`フォールバック選択のために各生徒の最小のカードを保存します。 ループは、配られていないカードごとに、カードを獲得する生徒を見つけ、モジュラー演算を使用してその期待値を更新します。 最終的な出力では、予想されるカウントが出力されます。
