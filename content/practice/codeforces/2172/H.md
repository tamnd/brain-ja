 ## 解決策
 ## 問題の理解

 私たちに与えられたデッキは、$2^k$カードは小文字の文字列として表されます。 最初のデッキを移動することでデッキを回転させることができます$m$最後までカード。 このオプションのローテーションの後、デッキはリフルシャッフルされます$t$回。 完璧なリフル シャッフルでは、デッキを 2 つの等しい半分に分割し、それらを交互に配置し、最初に上半分から 1 枚のカードを取り、次に下半分から 1 枚を取り除きます。 

タスクは、その後に次のようなローテーションを選択することです。$t$リフルシャッフルすると、結果として得られるデッキは辞書順に最小になります。 ここでの辞書順は標準的な文字列比較です。 

入力制約は重要です。$k \le 18$、デッキサイズを意味します$n = 2^k \le 262144$。$t$まで可能です$10^9$。 各リフルシャッフルを適用する素朴なシミュレーション$t$回は実行不可能です。$t \cdot n = 10^9 \cdot 2 \cdot 10^5$最悪の場合の運用。 このため、総当りのシミュレーションではなく、リフル シャッフルの数学的構造について考える必要があります。 

トリッキーなエッジケースは次のような場合に発生します。$t = 0$(シャッフルなし) または$t$インデックスの同じ順列を複数回繰り返すのに十分な大きさです。 たとえば、デッキがすでにソートされていて、次の基準でカットするとします。$m = 0$、たとえ次のような場合でも、アルゴリズムに回転が必要ないことを認識してもらいたい$t$とても大きいです。 もう 1 つの微妙なケースは、すべての文字が同一で、どのカットでも同じ出力が得られる場合です。 アルゴリズムはインデックスの計算ミスやオーバーフローがあってはなりません。 

## アプローチ

 ブルートフォースアプローチは簡単です: 可能なカットごとに$m = 0 \dots n-1$、デッキを回転させ、実行します$t$リフル シャッフルは明示的に行われ、辞書順に最小の結果が追跡されます。 これは原理的には機能しますが、$n \le 2^{18}$そして$t$まで$10^9$、絶望的に遅いです。 各シャッフルコストを明示的に計算する$O(n)$そして繰り返します$t$倍が大きすぎます。 

重要な洞察は、リフル シャッフルが **インデックスの順列**であることを観察することです。 インデックスを与えると$i$元のデッキでは、1 回シャッフルした後、次の条件に基づいて予測可能な位置に移動します。$i < n/2$または$i \ge n/2$。 より一般的には、リフル シャッフルは繰り返し適用すると **インデックス上の線形マップ**を形成します。これは二項演算を使用して表現できます。$n = 2^k$。 後$t$シャッフルの場合、カードの位置はその初期インデックスと次のバイナリ表現のみに依存します。$t$。 

シミュレーションする代わりに$t$シャッフルでは、各カードの最終的な位置を計算します。$O(n \cdot k)$シャッフルごとにインデックス内の各ビットがどのように移動するかを調べることによって。 これにより、効果的なシミュレーションが減少します。$O(n \cdot t)$に$O(n \cdot k)$。 インデックスの順列を計算できるようになると、$t$シャッフルすると、問題は **既知のインデックス順列の下で辞書編集上最小の巡回回転を見つける** ということになります。これは、次のように解決できる既知のアルゴリズム問題です。$O(n)$ブースのアルゴリズムを使用します。 

このアプローチは、**インデックス操作とバイナリ プロパティ**を利用して、実行不可能な総当たりシミュレーションを扱いやすい計算に変換します。$n$は 2 の累乗であり、リフル シャッフルは決定的な構造を持っています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * t * n) | O(n) | 遅すぎる |
 | インデックス順列 + ブース | O(n * k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$k$そして$t$。 コンピューティング$n = 2^k$。 デッキ文字列を読む$d$。 
2. 関数を定義する`shuffle_index(i, k)`インデックスの新しい位置を計算します$i$一回のリフルシャッフルの後。 これによりデッキが半分に分割されます。$i < n/2$、新しい位置は$2*i$、そうでない場合は、$2*(i - n/2) + 1$。 
3. 関数を事前計算する`apply_shuffle_power(i, t)`リフルシャッフルを適用する$t$インデックスの倍数$i$。 インデックスに **2 進累乗**を使用します: を表します$t$2 進数で、2 のべき乗に対応する順列を繰り返し構成します。これにより、$t$までに$10^9$維持しながら$O(k)$インデックスごとに。 
4. インデックスの最終マッピングを計算します。$t$シャッフルします。 これにより、元のインデックスごとに、$i$、デッキ内の最終位置。 
5. この順列の下で **辞書編集上最小の回転**を見つけるとして問題を扱います。 シャッフルの順列に従って元のデッキをマッピングし、**Booth のアルゴリズム**を使用して最小限のローテーションを効率的に見つけます。$O(n)$。 
6. この最小回転に対応するデッキを出力します。 

機能する理由: リフル シャッフルは、インデックスに決定的な順列を形成します。 後でインデックスマッピングを計算することで、$t$アプリケーションでは、この問題を静的な循環文字列回転の問題に帰着させることができます。 ブースのアルゴリズムは、可能なすべてのカットの下で辞書編集上の最小性を維持しながら、線形時間で最小回転を見つけることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def riffle_index(i, n):
    if i < n // 2:
        return 2 * i
    return 2 * (i - n // 2) + 1

def compute_final_indices(n, t):
    # Binary exponentiation on permutation
    perm = list(range(n))
    power = perm[:]
    while t > 0:
        if t % 2:
            perm = [power[i] for i in perm]
        power = [power[i] for i in power]
        t //= 2
    return perm

def minimal_rotation(s):
    n = len(s)
    s += s
    f = [-1] * (2 * n)
    k = 0
    for j in range(1, 2 * n):
        i = f[j - k - 1]
        while i != -1 and s[j] != s[k + i + 1]:
            if s[j] < s[k + i + 1]:
                k = j - i - 1
            i = f[i]
        if i == -1 and s[j] != s[k]:
            if s[j] < s[k]:
                k = j
            f[j - k] = -1
        else:
            f[j - k] = i + 1
    return s[k:k+n]

def main():
    k, t = map(int, input().split())
    d = input().strip()
    n = 1 << k
    final_indices = compute_final_indices(n, t)
    shuffled = ''.join(d[i] for i in final_indices)
    print(minimal_rotation(shuffled))

if __name__ == "__main__":
    main()
```説明：`riffle_index`1 つのシャッフル ステップをエンコードします。`compute_final_indices`2 進累乗を使用してシャッフルを繰り返し適用します。`minimal_rotation`辞書編集上最小の回転を見つけるブースのアルゴリズムを実装します。 これらを組み合わせると、最終的なデッキがデッキ サイズの倍に対して線形時間で得られます。$k$。
