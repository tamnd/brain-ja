 ## 解決策
 ## 問題の理解

 私たちには、基数の桁から構築された非常に小さな「数値世界」が与えられています。 基数は常に、2 桁の数値、3 桁の数値、または 4 桁の数値の 3 つの可能性のうちの 1 つです。 その数字から、すべての個別の順列を生成し、これらの順列を数値の昇順に並べ替えます。 

次に、各テスト ケースに 2 つのインデックスが与えられ、この並べ替えられたリストから対応する 2 つの順列が選択されます。 タスクは、牛と牛に似たスコアリング システムを使用して、選択した 2 つの数字を比較することです。数字は、値と位置の両方が一致する場合は A に寄与し、値は一致するが位置が異なる場合は B に寄与します。 

出力は、xAyB 形式のカウントのペアだけです。 

構造的に制約が極めて少ない。 最大のケースには 4 桁しかないため、最大 24 個の順列が存在します。 テスト ケースごとにすべてを再計算したとしても、数十の文字列に制限された継続的な作業を行っていることになります。 これにより、最適化のトリックや漸近的な懸念が必要なくなります。 テスト ケースごとに順列を列挙するソリューションは、最大 1000 クエリの制限時間内に簡単に収まります。 

主な微妙な点は、カウント ロジックの正確さです。 単純な実装は、数字が繰り返される場合、または B が A の一致にすでに使用されている数字を二重にカウントする場合に失敗することがよくあります。 入力サイズが小さい場合でも、一致ルールの処理が間違っていると、エッジ ケースで間違った答えが生成されます。 

典型的な落とし穴は、多重度を注意深く追跡せずに、B を「共通桁の数から A を引いたもの」として扱うことです。 これは、数字が繰り返される場合、または同じ数字が異なる位置に複数回出現する場合に中断されます。 

障害シナリオの例:

 入力: 122 1 2

 順列: 122、212、221

 122 と 221 を比較すると、3A0B やカウントミスではなく、0A3B が得られるはずです。 位置ごとに使用された桁を追跡しない不注意なアプローチでは、一致が過剰にカウントされます。 

## アプローチ

 ブルートフォース手法では、基数の桁のすべての順列を明示的に生成し、それらを並べ替えてから、j 番目と k 番目の順列を直接フェッチします。 順列の最大数は 4 なので、 = 24、これは簡単です。 2 つの文字列を取得した後、一致する A について位置ごとに比較し、頻度表を使用して一致する A を注意深く減算し、一致する B をカウントします。 

これはすでに簡単に成功していますが、さらに明確な観察があります。順列セットは非常に小さく、入力サイズによって固定されているため、すべての順列をテスト ケースごとに 1 回事前計算し、すぐに再利用できます。 実際の作業は、一定サイズのリストをソートし、そのリストにインデックスを作成することになります。 

唯一重要な部分は、xA yB を正しく計算することです。 正しい方法は、まず位置をスキャンして A を計算することです。 次に、両方の文字列から一致しない数字の頻度カウントを構築し、最小の重複の合計として B を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース置換 + 直接比較 | テストごとに O(1) | お(1) | 承認済み |
 | 事前計算 + 周波数マッチング | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 基数の桁をリストに抽出します。 数字はすべての順列の唯一のソースであるため、すべてはこのマルチセットに依存します。 
2. 数字リストのすべての順列を生成します。 リストのサイズは最大 4 であるため、最大 24 個の文字列が生成されます。 
3. すべての順列を整数に変換された文字列として数値的に並べ替えます。 これは、インデックス作成で使用されるグローバルな順序付けを定義します。 
4. j 番目と k 番目の順列 (1 から始まる) を選択します。 これらは比較する 2 つのコードになります。 
5. 両方の文字列を位置ごとにスキャンし、完全に一致するものを数えることによって A を計算します。 これにより、正しく配置された数字がキャプチャされます。 
6. 最初に両方の文字列の桁の頻度カウントを構築し、次に A ですでにカウントされている寄与を減算して B を計算します。最後の B は、両方の文字列の残りの最小頻度の桁の合計です。 
7. 結果を必要な形式で出力します。 

機能する理由: すべての数字の一致は、位置がすでに固定されているか (A)、または位置がずれているもの (B) の 2 つのカテゴリのいずれかに正確に分類されます。 頻度をカウントする前に一致する A を削除することで、二重カウントを防ぎます。 順列では同じ複数の桁セットが保存されるため、頻度比較ではすべての有効な B 一致が完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

def score(a, b):
    A = 0
    fa = [0] * 10
    fb = [0] * 10

    for x, y in zip(a, b):
        if x == y:
            A += 1
        else:
            fa[int(x)] += 1
            fb[int(y)] += 1

    B = 0
    for d in range(10):
        B += min(fa[d], fb[d])

    return A, B

def solve():
    t = int(input())
    for _ in range(t):
        n, j, k = input().split()
        j = int(j)
        k = int(k)

        digits = list(n)
        perms = sorted(set(permutations(digits)))

        perms = [''.join(p) for p in perms]

        a = perms[j - 1]
        b = perms[k - 1]

        A, B = score(a, b)
        print(f"{A}A{B}B")

if __name__ == "__main__":
    solve()
```この解決策は、数字リストのすべての順列を列挙することから始まります。 セットを使用すると、基数に繰り返しの数字が含まれる場合に重複が削除されます。そうしないと、重複した順列がインデックス付けをシフトし、j 番目の選択が壊れる可能性があるため、これは重要です。 

ソート後、比較を容易にするためにタプルを文字列に変換します。 問題は 1 から始まるため、インデックス付けは簡単です。 

スコアリング関数は明確に分割されています。完全に一致するものが最初に処理され、一致しない数字は頻度配列に累積されます。 B を計算するときに A の一致を再利用してはいけないため、この分離は非常に重要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストごとに O(1) | 最大 24 の順列と 4 桁の比較 |
 | スペース | お(1) | 固定サイズの順列リストと頻度配列 |

 この制約では桁の長さが 4 に制限されているため、テスト ケースごとの完全な列挙であっても無視できます。 最大 1000 のテスト ケースでは、総作業量はわずかに制限内に収まります。 

## テストケース```python
import sys, io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    out = []

    def score(a, b):
        A = 0
        fa = [0] * 10
        fb = [0] * 10
        for x, y in zip(a, b):
            if x == y:
                A += 1
            else:
                fa[int(x)] += 1
                fb[int(y)] += 1
        B = sum(min(fa[i], fb[i]) for i in range(10))
        return f"{A}A{B}B"

    t = int(input())
    for _ in range(t):
        n, j, k = input().split()
        j = int(j); k = int(k)

        perms = sorted(set(permutations(n)))
        perms = [''.join(p) for p in perms]

        a = perms[j - 1]
        b = perms[k - 1]
        out.append(score(a, b))

    return "\n".join(out)

# provided samples
assert run("3\n12 1 2\n123 1 2\n123 2 5\n") == "0A2B\n1A2B\n1A2B"

# custom cases
assert run("1\n12 1 1\n") == "2A0B", "same permutation"
assert run("1\n1234 1 24\n") != "", "max size sanity"
assert run("1\n122 1 3\n") == "1A2B", "repeated digits case"
assert run("1\n123 6 1\n") == "0A3B", "reverse extremes"

| 122 1 3 | 1A2B | 繰り返される数字の正確さ |

 ## 特殊なケース

 基数に 122 や 212 などの繰り返しの数字が含まれる場合、微妙なエッジ ケースが発生します。このような場合、生の順列ジェネレーターは重複排除しない限り重複を生成し、インデックス付けがシフトされる可能性があります。 たとえば、セットがない場合、122 は複数の同一の文字列を生成し、j と k が誤った順列を参照する可能性があります。 

このアルゴリズムは、並べ替えの前に順列をセットに変換することでこれを処理します。 入力 122 1 3 の場合、順列は {122, 212, 221} になります。 ソート結果 [122、212、221]。 インデックス 1 と 3 を選択すると、122 と 221 が得られます。スコアリングにより、正しく 1A2B が生成されます。 

もう 1 つのエッジ ケースは、j が k と等しい場合です。 A が文字列の全長になり、一致しない数字が残らないため B がゼロになるため、アルゴリズムは引き続き機能します。
