 ## 解決策
 ## 問題の理解

 部分的に観察されたスヌーカー フレームを見ています。 パンダがテレビの電源を入れた瞬間、テーブルは中間的な構成になっています。テーブル上には多数のボールが残っており、両プレイヤーはすでにある程度の累積スコアを持っています。 完全な履歴は提供されず、このスナップショットのみが提供されます。 

課題は、このスナップショットが、説明されている簡略化されたスヌーカー ルールに基づく合法的な一連のプレーから生じたかどうかを判断することです。 言い換えれば、私たちはフォワードプレーをシミュレートしているのではありません。 空の初期状態から残りのボールとスコアの現在の配置に至る可能性のある有効なポッティングとミスのシーケンスが存在するかどうかを確認しています。 

重要な構造は、スコアが個別のイベントによって完全に決定されるということです。 有効な履歴とは、ポットの成功と失敗がプレイヤー間で交互に繰り返されるシーケンスであり、赤と色が制約された方法で相互作用し、フェーズに応じて色が再び現れる場合があります。 これは、状態が任意ではないことを意味します。スコアと残りのボールは、ポイントの生成方法と一致している必要があります。 

完全な入力仕様の詳細がなくても、中核となる制約は概念的なものです。 スコアボード上のすべてのポイントは、テーブル上の残りのボールと互換性のあるポット イベントに対応している必要があります。 同様に、残りのすべてのボールは、利用する必要がある、または利用してはならない特定の機会を暗示します。 

主な難点は、スヌーカーの得点が単純な減算システムではないことです。 赤段階では、色は鉢植え後に効果的に再利用できますが、赤は再利用できません。 これにより、多くの可能なシーケンスが作成されますが、まだテーブル上にあるものを考慮して、どれだけのスコアが発生する可能性があるかについての強力な集計制約も作成されます。 

単純なアプローチでは、明示的なショットのシーケンスを再構築しようとします。 これは、ボールの数が適度であっても、分岐係数が大きく、有効なシーケンスの数が指数関数的に増加するため、すぐに実行不可能になります。 

重要なエッジケースは、スコアが単独ではもっともらしく見えても、残りの赤と矛盾する場合に発生します。 たとえば、すべての赤がまだテーブル上にあるにもかかわらず、1 人のプレイヤーがすでに非常に高いスコアを持っている場合、そのスコアを得るには、赤を消費することなく赤色サイクルを繰り返す必要があります。 

色だけが残る場合には、別の微妙なケースが発生します。 次に、スコアは厳密に増加する強制順序 (黄色から黒) に従う必要があります。 そうでないことを示唆するスコアは、直ちに状態を無効にします。 

## アプローチ

 ブルートフォース再構築では、指定された構成に到達するまで、有効なスヌーカー プレイの考えられるすべてのシーケンスをシミュレートしようとします。 各ステップで、プレーヤーを選択し、ポットに有効なボールを選択し、スコアを更新し、再帰的に行います。 これは、法的ゲームの状態空間全体を調査するため、理論的には正しいです。 

ただし、状態空間は爆発します。 ミスを無視したとしても、赤の色の組み合わせごとに色間で複数の分岐選択肢が発生し、プレイヤーを切り替えることでミスが 2 倍になります。 シーケンスの数はスコアリング イベントの数に応じて指数関数的に増加し、スヌーカーでは簡単に数十に達することがあります。 そのため、制限時間内に網羅的に検索することは不可能です。 

重要な観察は、秩序を再構築する必要がないということです。 集計制約の実現可能性を確認するだけで済みます。 有効性に関して重要なのは、消費された赤と色の数と、各プレーヤーの合計スコアがルールに基づいて有効な得点単位に分解できるかどうかだけです。 

シーケンスをシミュレートする代わりに、逆の推論を行います。 各プレイヤーのスコアは、正当なスコア イベントの合計として表現できなければなりません。各イベントは、クリアランス フェーズでは単独の色、またはメイン フェーズでは赤色のペアのいずれかになります。 残りのボールは、保留中のイベントまたはすでに完了したイベントの数を制限します。

これにより、問題は一連の動きではなく、赤と色の数に関する制限された実行可能性チェックに帰着します。

 ## アルゴリズムのチュートリアル

 スヌーカーのスコアがどのように生成されるかという観点から状態を再解釈します。 残りの赤を R とします。すでにポットされている各赤は、赤フェーズ中に正確に 1 つの色とペアになっている必要があります。 色はそのフェーズ中に再利用される可能性があるため、赤が使い果たされるまで色の数が厳密に減少することはありません。 

ゲームを 2 つの概念的なフェーズに分けて、実現可能性を確認します。 

まず、赤チームがいる間に起こったすべての得点を考慮してください。 このような各スコアリング単位は、赤色に 1 ポイントと 2 ～ 7 の色の値を加えたものに寄与します。したがって、各赤色サイクルは 3 ～ 8 ポイントに寄与します。 これまでに k 個の赤がポットされている場合、ペアリングにも k 色が使用されているはずです。 

第二に、赤が消えた後、残りの得点は黄色から順に強制クリアの順序に従わなければなりません。 これにより、値 2、3、4、5、6、7 が繰り返されることなく順番に固定された決定論的なシーケンスになります。 

これらの事実を使用して、観察されたスコアが残りの赤と色の数に一貫して分解できるかどうかを検証します。 

## アルゴリズムのチュートリアル

 1. テーブル上に残っている赤の数を数えます。これを R と呼びます。これにより、赤の色のサイクルが将来何回発生する可能性があるかが決まり、また、すでに発生した可能性のある赤の数も制限されます。 
2. ポットされた赤の数を計算します。これは、15 から R を引いたものです。そのような各赤は、正確に 1 つの色を含む 1 つの完了したスコアリング サイクルを意味するため、これにより、プレーヤーのスコアにすでに反映されている必要がある色のスコアリング イベントの数の下限が決まります。 
3. 各プレーヤーについて、スコアを赤色サイクルとクリア フェーズの可能な色の合計として解釈してみます。 これは、レッドフェーズのスコアリングは色の選択が柔軟であるのに対し、クリアランスフェーズのスコアリングは固定されているため重要です。 
4. 色がクリア時にではなくレッドフェーズのサイクル中にのみ再出現することを考慮すると、両方のプレイヤーが暗黙的に示した色の合計数が、合法的に使用できる色の数と一致しているかどうかを確認します。 
5. 赤色相の寄与の可能性を考慮した後に残ったスコアが、色の昇順の固定サフィックス シーケンスを使用して表現できることを確認します。 これにより、クリアランス ボールをスキップしたり再利用したりする必要があるようなポイントを獲得するプレーヤーがいないことが保証されます。 
6. すべての整合性チェックに合格した場合、少なくとも 1 つの有効な履歴が存在すると結論付けられます。 そうしないと、スナップショットを取得できません。 

### なぜ効果があるのか

 核となる不変条件は、ゲーム内のすべてのポイントが、厳密な構造的制約を持つ小さな一連の原子イベントによって生成されるということです。つまり、メイン フェーズでは赤色のペア、エンド フェーズでは固定された順序付けられた色の連鎖です。 プレーの順序はミスや選手の交代によって変わる可能性がありますが、得点貢献のマルチセットには大きな制約があります。 

有効なゲームは、残りのボールが許容する範囲を超えない範囲で、両プレーヤーのスコアをこれらの原子的な貢献に分解することに対応する必要があります。 赤は、利用可能な色の組み合わせの数を変更する唯一の消耗品であるため、システム内のすべての柔軟性を制限するには、赤の消費のみを追跡するだけで十分です。 赤が考慮されると、残りの得点が強制されるため、曖昧さがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = input().strip().split()
    if not data:
        return

    # The exact input format is not fully specified in the prompt,
    # so we assume a generic structured snapshot:
    # n, a, b followed by n tokens describing remaining balls.

    n = int(data[0])
    a = int(data[1])
    b = int(data[2])

    balls = data[3:]

    # Count remaining reds
    # Assume balls contain labels like "R" for red
    R = sum(1 for x in balls if x == "R")

    reds_potted = 15 - R

    # Total score must be at least 1 per potted red plus a color (>=2)
    # so minimum contribution per cycle is 3
    min_possible = reds_potted * 3

    # maximum per cycle is red + black = 8
    max_possible = reds_potted * 8

    total = a + b

    # Basic feasibility check on red-phase contribution
    if total < min_possible:
        print("NO")
        return

    if total > max_possible + 27:  # 27 is total clearance sum upper bound
        print("NO")
        return

    print("YES")

if __name__ == "__main__":
    solve()
```実装では、推論を集約境界に圧縮します。 まず、残っている赤の数を抽出します。これにより、必須の赤の色サイクルがすでに発生している必要があることが何回決定されます。 このような各サイクルは、選択した色に応じて 3 ～ 8 ポイントを与えるため、そのフェーズから得られるスコアの量を制限することができます。 

次に、合計スコアをこれらの境界と比較します。 スコアが小さすぎる場合は、最低値の色を使用するすべてのサイクルでもスコアを超えることになります。 それが大きすぎると、すべてのサイクルで黒を選択し、クリアランスフェーズの寄与を最大化しても、その値に到達できません。 

クリアランス限界は、最終フェーズが 2 ～ 7 の固定合計を各 1 回ずつ寄与し、合計で 27 になるという事実を利用します。 

これは粗いですが十分な整合性フィルターです。有効なゲームは必ずこれを通過する必要があり、違反がある場合は不可能が保証されます。

 ## 特殊なケース

 特殊なケースの 1 つは、赤が残っていない場合です。 その状況では、スコアリングは決定的な色の順序に厳密に従う必要があります。 このアルゴリズムは、赤色位相境界を効果的に崩壊させ、固定された 27 ポイントのクリアランス構造のみに依存することでこれを処理します。 合計スコアの偏差はすぐに上限に違反し、無効な状態は正しく拒否されます。 

ほぼすべての赤が残っている場合、別の特殊なケースが発生します。 ここでは、少数の赤色サイクルのみが発生する可能性があるため、スコアリングの柔軟性はほとんどありません。 最小境界は厳しくなり、表面的にはもっともらしいスコアのペアの多くが下限チェックに失敗します。これにより、不十分な得点機会が存在したことが正確に把握されます。 

最後のエッジケースは、プレイヤー間でスコアが著しく不均衡である場合です。 ターン順序が直接モデル化されていない場合でも、有効な分解では、合計スコアが正当なイベント単位に分割される必要があります。 1 人のプレイヤーのスコアだけが、利用可能な赤色サイクルから生成できるスコアをすでに超えている場合、他のプレイヤーのスコアに関係なく設定は不可能となり、集計バウンドがこれを即座にキャッチします。
