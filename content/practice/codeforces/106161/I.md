 ## 解決策
 ## 問題の理解

 各テスト ケースには一連の論文が含まれており、各論文は少数の査読者グループによって評価されます。 すべての査読者は -3 から 3 までの整数のスコアを割り当て、論文の合計スコアはこれらの値の合計にすぎません。 論文は、合計スコアが少なくともしきい値に達した場合に受理されたとみなされます。$k$。 

最初の評価の後、反論と呼ばれるオプションのアクションが 1 つあります。 パンダが選択できるのは最大でも$b$異なる論文を作成し、この反論操作をそれらの論文に適用します。 この操作により、その論文のすべての査読者のスコアが非常に構造化された方法で変更されます。肯定的なスコアは 1 つ減少し、非肯定的なスコアは 1 つ増加します。 これは、高いスコアがわずかに減少し、低いスコアがわずかに改善されることを意味しますが、合計の影響という点では変化は対称的ではありません。 

目標は、すべての変更を行った後に受け入れられる論文の数が最大になるように、どの論文に反論を適用するかを決定することです。 

主要な制約構造は、各論文の査読者は最大 10 名であり、すべてのテスト ケースで最大 200,000 の論文が存在するということです。 これにより、選択した論文の組み合わせをシミュレートしたり、グローバルな状態を繰り返し再計算しようとするアプローチは即座に排除されます。 どのようなソリューションでも、各紙をほぼ独立して処理し、線形または線形に近い時間で問題をソートまたは貪欲な選択に減らす必要があります。 

微妙なエッジケースは、論文が既に受理されたものの、反論の後に却下された場合に発生します。 たとえば、論文が最初はしきい値をほとんど超えていなくても、ほとんどの査読者が肯定的なスコアを与えた場合、この操作を適用すると、合計が十分に減少してしきい値を下回る可能性があります。$k$。 「役立つかもしれないものすべてに反論する」という素朴な戦略は、ここでは失敗するでしょう。 

もう 1 つのエッジケースは、論文が最初は拒否されたが、反論の後に受け入れられる場合です。 これは、操作の適用が役立つ唯一の状況であり、これがいつ発生するかを正確に特定することが問題の核心です。 

## アプローチ

 直接的な総当たり戦略では、最大でもすべてのサブセットが試行されます。$b$論文を作成し、反論を適用した場合の影響をシミュレートします。 サブセットごとに、すべての論文スコアを再計算し、しきい値を満たす数を数えます。 これには評価が必要です$\sum_{i=0}^{b} \binom{n}{i}$可能性は小さくても天文学的に大きい$b$、各評価には次のことが必要になります$O(nm)$work to recompute totals. このアプローチは、小さな入力を超えるとすぐに失敗します。 

重要な観察は、単一の論文に対する反論の影響は、他のすべての論文から完全に独立しているということです。 最大でも$b$papers can be selected. これにより、問題は組み合わせによる全体的な最適化から項目ごとのゲイン選択問題に縮小されます。 

各論文について、現在の受理ステータスと固定変換を適用した後のステータスの 2 つの状態を比較するだけで済みます。 反論を適用することで論文が却下から受理に変わる場合、それは有益です。 受け入れられたものから拒否されたものに変更されると有害です。 決定が変わらないのであれば、それは無関係です。 

この論文ごとの利益を計算すると、全体的な問題は、最大でも次のいずれかを選択することになります。$b$プラスのゲインを持つ項目。 各論文は目的の改善に 0 または 1 の貢献をするため (またはマイナス、決して選択しません)、最適な戦略は単純に、許可される限り多くの有益な論文を採用することです。$b$。

 ## アルゴリズムのチュートリアル

 各論文に反論を適用した場合の効果を個別に計算し、最良の候補を貪欲に選択します。 

1. 各論文について、すべての査読者の値を合計して初期合計スコアを計算します。 これにより、現在受け入れられるかどうかが決まります。 
2. 同じ論文について、反論によってスコアがどのように変化するかを計算します。 各査読者は、スコア ≤ 0 の場合は +1 を貢献し、スコア ≥ 1 の場合は -1 を貢献します。これらの貢献を合計すると、その論文のスコアの合計変化が得られます。 
3. 元のスコアと変更を組み合わせて反論後の最終スコアを取得し、その状態で論文が受理されるかどうかを判断します。 
4. 反論前後の受理状況を比較する。 論文がリジェクトからアクセプトに変わった場合は、ゲイン +1 で有益であるとマークします。 合格から不合格に変わった場合は、-1 とマークしますが、そのような論文は決して選ばれません。 同じままであればゲインは0です。 
5. ゲイン +1 を獲得した論文の数を数えます。 各選択は独立しており、唯一の制約は最大でも選択することであるため、$b$用紙、最大まで選択します$b$これらの有益な論文の一部をご覧ください。 
6. 最終的な答えは、最初に受理された論文の数に、選択された有益な論文の数を加えたものです。 

### なぜ効果があるのか

 各紙は、1 回の操作でのみ価値が向上、悪化、または変化しないバイナリ項目のように動作します。 この目的は論文間で純粋に加算的であり、操作数はグローバルに制限されていますが相互作用しないため、有益な論文を別の論文よりも優先することにはメリットがありません。 すべての有用な論文は、最終的なカウントにおいて正確に 1 単位の改善に貢献するため、最大のサイズのサブセットはすべて$b$その中では同等です。 これにより、貪欲な選択が最適化され、選択肢間の隠れた依存関係が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m, k, b = map(int, input().split())
        
        base_accepted = 0
        good = 0
        
        for _ in range(n):
            arr = list(map(int, input().split()))
            
            s = sum(arr)
            base_ok = (s >= k)
            
            delta = 0
            for x in arr:
                if x >= 1:
                    delta -= 1
                else:
                    delta += 1
            
            new_ok = (s + delta >= k)
            
            if base_ok:
                base_accepted += 1
            
            if (not base_ok) and new_ok:
                good += 1
        
        out.append(str(base_accepted + min(b, good)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```The implementation follows the algorithm directly. For each paper, we compute both the original sum and the net change induced by the rebuttal. レビュー担当者のループは小さいため、$m \le 10$したがって、このステップは事実上、紙ごとに一定の時間になります。 

主要な実装の詳細は、論文を暗黙的に 3 つのカテゴリ (すでに受理されたもの、反論後に新たに受理されたもの、その他すべて) に分類することです。 拒否から承認への移行のみが、最終的な改善カウントに寄与します。 正のゲインの数のみが重要であるため、ゲインを明示的に保存することはありません。 

## 実用的な例

 3 つの論文からなる小さなシナリオを考えてみましょう。 

論文 A はすでにスコアの合計がしきい値を超えているため、最初は受け入れられます。 反論を適用した後、そのスコアがしきい値を下回ったとします。 紙 A は有益なプールに何も貢献しません。 

紙 B は最初は拒否されますが、変換後に受け入れられます。 紙 C はどちらの場合も拒否されたままです。 

分類を追跡します。 

| 紙 | 初期合計額 | 初期OK | デルタ | 新しい合計 | 新規OK | ゲイン |
 | --- | --- | --- | --- | --- | --- | --- |
 | あ | 高い | 1 | −2 | 下 | 0 | −1 |
 | B | 中 | 0 | +3 | 高い | 1 | +1 |
 | C | 低い | 0 | +1 | まだ低い | 0 | 0 |

 もし$b = 1$では、用紙 B のみを選択し、追加の承認を 1 つ与えます。 もし$b = 2$、プラスのゲインがあるのは 1 つの用紙だけであるため、さらに選択しても役に立ちません。 

これは、決定が完全に、拒否された論文をどれだけ多くの論文から受け入れられるかを数えることに帰着することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    input = sys.stdin.readline
    t = int(input())
    res = []
    
    for _ in range(t):
        n, m, k, b = map(int, input().split())
        base = 0
        good = 0
        
        for _ in range(n):
            arr = list(map(int, input().split()))
            s = sum(arr)
            ok = s >= k
            
            delta = sum(1 if x <= 0 else -1 for x in arr)
            new_ok = (s + delta >= k)
            
            if ok:
                base += 1
            if (not ok) and new_ok:
                good += 1
        
        res.append(str(base + min(b, good)))
    
    return "\n".join(res)

# minimal case
assert run("""1
1 1 0 1
0
""") == "1"

# simple flip case
assert run("""1
1 1 1 1
0
""") == "1"

# no benefit case
assert run("""1
2 1 5 1
3
3
""") == "0"

# mixed case
assert run("""1
3 2 1 2
1 1
-3 -3
2 -1
""") == "2"

 ## 特殊なケース

 微妙なエッジケースは、論文がすでに受理されているが、反論を適用した後に拒否される場合です。 この状況では、ゲインは負であり、拒否から受け入れへの遷移のみをカウントするため、アルゴリズムは当然それを無視します。 たとえば、紙の合計が次とまったく同じである場合、$k$ほとんどのレビュー担当者が肯定的なスコアを付けた場合、デルタによってしきい値を下回る可能性がありますが、有益なプールには決して表示されないため、選択されることはありません。 

Another edge case occurs when no paper improves after the operation. In that case, the count of beneficial papers is zero, and the answer correctly reduces to the number of initially accepted papers.
