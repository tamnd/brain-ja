 ## 問題の理解

 ルート付きツリーが与えられ、すべてのノードが 2 つの値 (1 つは配列からの値) を保持します。`a`配列からの 1 つ`b`。 両方の配列の一部のエントリはゼロである可能性があり、ゼロは任意のものに一致するワイルドカードとして機能します。 値`x`と互換性があると考えられます`y`それらが等しいか、少なくとも 1 つがゼロの場合。 

すべてのノードについて`i`、をルートとするサブツリーのみを調べます。`i`。 そのサブツリー内では自由に交換できます`a`任意のペアごとのスワップを使用して、何らかの方法でノード間で値を取り込むことができますが、サブツリーの外部から値を取り込むことはできません。 問題は、それを並べ替えることができるかどうかです。`a`そのサブツリー内の値により、並べ替え後にすべてのノードが`k`そのサブツリーでは満たされます`a[k]`マッチ`b[k]`ワイルドカード等価ルールの下で。 

各ノードは独立したクエリを定義します。つまり、概念的には配列をリセットします。`a`すべてのクエリについて、そのサブツリー内のスワップのみを考慮します。 

制約により、最大で`2 * 10^5`これにより、サブツリーごとに何かを個別に再計算することが即座に排除されます。 スワップをシミュレートしたり、マッチングの実現可能性をノードごとに最初から再計算しようとするソリューションでは、おおよその結果が得られます。`O(n^2)`チェーン状のツリー内での動作が遅すぎます。 テスト ケースごとに 1 つの線形パスまたは線形に近いパスが必要です。 

微妙ですが重要な詳細は、ワイルドカードがマッチングとどのように相互作用するかです。 ゼロイン`b`特定の値を要求せず、ゼロを入力します。`a`あらゆる要求を満たすことができます。 This makes the problem fundamentally about multiset matching with flexible capacities rather than strict equality.

 値ごとに一致を個別にチェックできると仮定すると、単純な間違いが発生します。 たとえば、値を含むサブツリーでは`[1, 2]`で`a`そして`[2, 1]`で`b`、答えは明らかに「はい」です。 ただし、ワイルドカードが存在する場合、カウントではゼロを汎用フィラーとして扱う必要があります。そうしないと、システムが誤って過剰に制約される可能性があります。 

もう 1 つの微妙な失敗例は、サブツリーの独立性を無視したことに起因します。 A node’s answer depends only on its subtree, not on the global tree, so any approach that aggregates only once globally without subtree aggregation will miss constraints for deeper nodes.

 ## アプローチ

 重要な観察は、サブツリー内のスワップは再配置できることを意味するということです。`a`そのサブツリー内で任意に。 This turns each subtree into a multiset problem: we are checking whether the multiset of`a`サブツリー内の値は、次によって課されるマルチセット制約を満たすように再配置できます。`b`。 

ワイルドカードがない場合、条件は単純になります。各値について、その頻度は次のようになります。`a`少なくともその要件である必要があります`b`。 ただし、ワイルドカードを使用すると柔軟な一致が可能になるため、これが複雑になります。 ゼロイン`a`欠落している必要な値とゼロを補うことができます。`b`特定の値を消費しません。 

単一のサブツリーに対する強引なアイデアは、そのサブツリー内のすべての値を収集し、貪欲に一致させることです。`b`要件を使用して`a`値、ゼロをユニバーサル スラックとして扱います。 これはサブツリーごとに線形時間で機能しますが、すべてのノードに対して実行すると、`O(n^2)`各サブツリーにはほぼすべてのノードが含まれるため、チェーンのような最悪のケースでは総作業量が増加します。 

重要な洞察は、視点を逆転させることです。 各サブツリーを再計算する代わりに、ツリー全体にわたる DP スタイルのバランスを計算します。 各ノードについて、各ラベルにどれだけの「余剰」または「不足」値が存在するかについて、その子からの集約情報を維持します。 ワイルドカードは、不一致を吸収できるグローバル バッファーとして機能します。 サブツリーの有効性の条件は、利用可能な完全一致とワイルドカードの柔軟性を使用して欠落を完全にカバーできるかどうかのチェックになります。 

これにより、サブツリーごとに、各値がいくつ使用可能か、またいくつ必要かが計算される事後探索が行われます。 私たちはサブツリーごとに 2 つの主要なカウンターを維持します。正確に一致しない要件がいくつ存在するか、および不一致を解決するために利用できるワイルドカード ユニットがいくつあるかです。 すべての要件がサブツリーの集約プール内でローカルに満たされる場合、サブツリーは有効です。

 ## アルゴリズムのチュートリアル

 ノードをルートとする DFS を使用してツリーを処理します`1`。 各ノードについて、そのサブツリーの情報を計算し、子からの結果を再利用します。 

1. すべてのサブツリーに対して、各タイプの値がいくつ利用可能であるかを追跡するバランス構造を定義します。`a`、何個必要ですか`b`、およびワイルドカード トークンがいくつ存在するか。 この構造は、DFS 中に子から親にマージされます。 
2. ノードの場合`u`、独自のコントリビューションを使用してそのコントリビューションを初期化することから始めます。`a[u]`そして`b[u]`。 もし`a[u]`がゼロの場合、1 つのワイルドカード供給に寄与します。 もし`b[u]`ゼロの場合は何も要求しません。 さもないと、`b[u]`その特定の値に対する要件が作成されます。 
3. 各子をマージします`v`の中へ`u`残高を追加することによって。 これにより、ルートとなるサブツリーのすべてのマルチセット情報が効果的に結合されます。`u`。 この正しさは、スワップではサブツリー内での任意の置換が可能であるため、重要なのはカウントのみであるという事実から来ています。 
4. 子を結合した後、利用可能な供給物を使用してすべての要求を解決しようとします。 各値の完全一致が最初にペアになります。 残りの需要は、ワイルドカード供給を使用して満たすことができます。 同じく残り物`a`値がゼロであるか未使用のままの場合、ワイルドカードの供給に寄与します。 
5. 解決後も要求が満たされない場合、サブツリーは`u`は無効であるため、記録します`0`このノードの場合。 それ以外の場合は有効であり、記録されます`1`。 
6. DFS は、親の計算の一貫性を維持できるように、集計されたバランス構造を上方に戻します。 

### なぜ効果があるのか

 不変条件は、すべてのノードについて`u`、そのサブツリーの処理後に計算された構造は、そのサブツリー内で内部的に一致する必要がある値の正味の余剰と不足を正確にエンコードします。 スワップでは任意の再配置が可能であるため、位置的な制約は存在せず、マルチセットの数のみが問題となります。 ワイルドカードは、すべての正確なペアが使い果たされた後に割り当てることができる無制限のユニットとして機能します。 サブツリーが解決可能な場合、すべての欠損を完全一致またはワイルドカードの供給と組み合わせることができます。 そうでない場合は、完全な再配布後でも必要な頻度がサブツリーが提供できる頻度を超える値が少なくとも 1 つ存在し、一連のスワップでは修正できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    # We use dictionaries to store frequency deltas per subtree.
    # cntA: available values from a
    # cntB: required values from b
    # zerosA: wildcard supply from a
    # ok[u]: answer for subtree u

    ok = [1] * n

    def dfs(u, p):
        cntA = {}
        cntB = {}
        zeros = 0

        # process node u
        if a[u] == 0:
            zeros += 1
        else:
            cntA[a[u]] = cntA.get(a[u], 0) + 1

        if b[u] == 0:
            pass
        else:
            cntB[b[u]] = cntB.get(b[u], 0) + 1

        for v in g[u]:
            if v == p:
                continue
            cA, cB, cz, valid = dfs(v, u)

            if not valid:
                ok[u] = 0

            # merge small into large
            if len(cA) > len(cntA):
                cntA, cA = cA, cntA
            for k, val in cA.items():
                cntA[k] = cntA.get(k, 0) + val

            if len(cB) > len(cntB):
                cntB, cB = cB, cntB
            for k, val in cB.items():
                cntB[k] = cntB.get(k, 0) + val

            zeros += cz

        # resolve matches
        keys = list(set(cntA.keys()) | set(cntB.keys()))
        for k in keys:
            m = min(cntA.get(k, 0), cntB.get(k, 0))
            cntA[k] = cntA.get(k, 0) - m
            cntB[k] = cntB.get(k, 0) - m

        # use wildcards to cover remaining demand
        remaining_demand = sum(cntB.values())
        if zeros >= remaining_demand:
            zeros -= remaining_demand
            for k in cntB:
                cntB[k] = 0
        else:
            ok[u] = 0

        return cntA, cntB, zeros, ok[u]

    dfs(0, -1)
    print("".join(map(str, ok)))

t = int(input())
for _ in range(t):
    solve()
```この実装は DFS のアイデアに直接準拠しています。 各サブツリーは、使用可能な値と必要な値の頻度マップを蓄積し、ワイルドカードの供給もカウントします。 子をマージした後、完全一致は柔軟性を消費しない必須のペアリングであるため、最初にキャンセルされます。 残りの需要はワイルドカード供給と照合されます。 

実装上の微妙な問題は、サブツリーのマージを効率的に維持することです。 このコードは、必要に応じて辞書を交換することで小規模から大規模へのマージ戦略を試み、全体の複雑さをほぼ線形に保ちます。 もう 1 つの重要な詳細は、ワイルドカードの処理は完全にキャンセルされた後にのみ行われなければならないということです。そうしないと、一致可能なペアでワイルドカードが無駄になる可能性があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、サブツリーにワイルドカードのみが含まれている場合に発生します。`a`価値観は厳しいが`b`要件。 その場合、ワイルドカードの供給はすべての要求をカバーするのに十分である必要があります。 それ以外の場合、サブツリーは無効になります。 アルゴリズムは、ゼロを個別にカウントし、正確に一致した後に需要を減算することでこれを処理します。 

もう 1 つの特殊なケースは、完全に一致するものが存在するものの、子全体に分散している場合です。 集計のマージはキャンセル前にカウントされるため、すべての潜在的な一致が親レベルで表示され、時期尚早な不一致の決定が防止されます。 

最後の微妙なケースは、ノード自体は無効だが、より大きな有効なサブツリー内にある場合です。 このアルゴリズムは無効性を盲目的に上方に伝播しません。 代わりに、完全な集計数に基づいて各親での実現可能性を再計算します。これにより、中間サブツリーがローカルでは不可能でもグローバルには修正可能である場合でも正確さが保証されます。
