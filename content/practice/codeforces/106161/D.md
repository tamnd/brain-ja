 ## 解決策
 ## 問題の理解

 簡略化されたスヌーカーのようなスコアリング システムのターゲット状態が与えられます。 常に 2 人のプレーヤーがおり、そのうちの 1 人が現在テーブルにいます。 私たちはプレーヤー A とプレーヤー B の現在のスコアを知っており、テーブルにボールが何個残っているか、そして誰の番であるかを知っています。 

私たちの仕事はスコアを計算することではなく、フレームの開始からこの正確な状態に至る可能性のあるイベントのシーケンスを再構築することです。 各イベントは、1 から 7 までの既知のポイント値を持つボールのポットの成功、またはミスショットのいずれかであり、スコアは変更されずにターンが切り替わります。 

したがって、出力は、アクションの有効な時系列履歴を説明する文字列になります。 最終スコア、残りのボール数、誰の順番と一致している限り、有効なシーケンスを出力することができます。 そのようなシーケンスが存在しない場合は、NA を出力します。 

状態空間の点では制約は小さいです。 スコアと残りのボールはすべて最大 200 で、テスト ケースの数は最大 2000 です。これは、長い分岐履歴をシミュレートしたり、指数関数的な処理を行うことは期待されていないことをすぐに示唆しています。 代わりに、私たちは、スコアの増分と残りのボールの数の間の一貫性が重要な困難である、制約付きの実現可能性再構成問題を扱っています。 

素朴な推論で最も一般的な失敗例は、これを単純な分割問題として扱うことです。つまり、スコアの差を複数セットのポット値と一致させることです。 これでは 2 つの重要な制約が無視されます。 まず、ミス時に交互にターンを行うため、シーケンスは現在のプレイヤーを尊重する必要があります。 第 2 に、ポットごとに利用可能なプールが減少するため、ボールの残りの数によって成功するポットの数が制限されます。 

スコアがゼロではないがボールが残っていない場合、微妙なエッジケースが発生します。 その場合、すべての得点はもっと早くに行われている必要があり、使用可能なボールを超えてポットを生成しようとする試みは直ちに無効になります。 もう 1 つのエッジ ケースは、両方のスコアが 0 であるが、方向指示器が有効な開始動作シーケンスと一致しない場合であり、特に強制ミスが必要であるが、ボールが残っていないために配置できない場合です。 

## アプローチ

 ブルートフォースの観点は、ある限界までの長さの考えられるすべてのシーケンスを生成し、ポットとミスをシミュレートし、スコアの変化と残りのボールを追跡し、目標の状態に到達したかどうかを確認することを想像することです。 すべての有効なゲーム履歴が検索スペースに含まれるため、これは概念的には正しいです。 

ただし、楽観的な限界があっても、分岐係数は大きくなります。 各ステップで、プレーヤーは 7 種類のボールのいずれかをミスまたはポットすることができ、状態ごとに少なくとも 8 つのトランジションが可能になります。 深さが 30 であっても、すでに天文学的な数のシーケンスが生成されます。 最終的なシーケンスの長さが最大 ​​100 であるという制約も、探索空間ではなく答えを制限するだけであるため、ブルート フォースには役に立ちません。 

重要な構造観察は、状態が極度に圧縮されていることです。 得点、残玉、手番の整合性以上に順位は気にしません。 これは、得点アクションが何回発生したか、および最終プレーヤーを調整するために必要なミスの数にのみ焦点を当てて、ソリューションをリバース エンジニアリングできることを意味します。 

順序の自由を無視すると、問題は、各得点アクションが 1 つのボールを消費し、残りのボールの制約が合計得点アクションの上限を与えることを考慮しながら、得点差を正確に合計する得点アクションのマルチセットを構築することに帰着します。 その後、ミスは最後のプレイヤーに合わせてターンを反転するために使用される単なるパディングです。 

本質的な単純化は、スコアリング イベントとミスが切り離されているということです。スコアリングはスコアの実現可能性を決定し、ミスはパリティとターンの整合性を決定します。

 ## アルゴリズムのチュートリアル

 スコア差を Δ = a + b として表しますが、グローバルではなく現在のプレーヤーによるアクションのみを制御するため、A と B を別々に扱う必要があります。 代わりに、ゲームを交互のターンのシーケンスとして解釈し、各動きがスコア値を追加するかターンを終了します。 

### 1. 基本的な実現可能範囲を検証する

 まず、必要なスコアリング アクションの総数が最大でも n + k であることを確認します。ここで、k はゲーム構造によって暗黙的に制限されます。 成功した各ポットはボールを消費するため、ポットの合計数は、最初のボールの数に暗黙的な補充を加えたもの (ここには存在しません) を超えることはできません。 したがって、n とルールによって暗示される、a + b ≤ 初期有効得点能力を確保する必要があります。 これに違反した場合は、直ちに NA を返します。 

このステップが存在する理由は、スコアだけでは十分ではないためです。 そのスコアを生み出すのに十分なボールを持っていたことは物理的に可能でなければなりません。 

### 2. スコアをボールの値に分解する

 利用可能な値 {1,2,3,4,5,6,7} を使用して、a と b の表現を独立して構築します。 必要なのは解だけであるため、貪欲な分解が機能します。残りのスコアを超えない範囲で可能な最大値を繰り返し減算します。 

これが機能するのは、コイン システムが制限されていて小さいためであり、実現可能性を超えて最小長を最適化していないためです。 

### 3. ボールの消費量が残りのテーブルと一致することを確認します。 

成功した各ポットはボールを 1 つ消費します。 したがって、得点アクションの総数は S であり、状態に到達する前に S ≤ 初期ボールが利用可能でなければなりません。 残りのボールとして n が与えられるため、消費されるボールの総数は固定されているため、暗黙の初期ボール数から S を引いた値が n と一致することを確認することで一貫性を確保します。 

不一致が発生した場合、有効な履歴は存在しません。 

### 4. 交互シーケンスを構築する

 ここで、最初のプレイヤー p = 0 または 1 から始まるタイムラインに得点アクションを配置します。順方向のターンをシミュレートします。 

現在のプレイヤーに割り当てるスコアがまだ残っている場合は常に、ポット アクションを追加します。 それ以外の場合は、ミスアクション「/」を挿入してターンを切り替えます。 

これにより、ターン交代を考慮した有効なシーケンスが構築され、すべてのスコアが正しく割り当てられるようになります。 

重要な考え方は、ミスは自由な構造ツールであるということです。ミスはスコアやボール数には影響せず、同等性にのみ影響します。 

### 5. 最終的なプレーヤーの配置を修正する

 シーケンスを構築した後、それを再生した後にどのプレイヤーがテーブルにいるかを計算します。 p と一致しない場合は、ミスを 1 つ追加するか、最小数のミスを先頭に挿入して調整します。 ミスはトグルターンのみであるため、不可能なスコア分解による制約がない限り、パリティ調整は常に可能です。 

### なぜ効果があるのか

 このアルゴリズムは、スコアリング アクションが数値状態遷移を完全に決定し、制御パリティのみをミスするという不変条件に依存します。 スコア以外のアクションはスコアに影響せず、スコアは帰属を超えてターン履歴に依存しないため、実現可能性に影響を与えることなく、ミスを任意に並べ替えることができます。 したがって、スコアを許容値に有効に分解し、十分なパリティ補正と組み合わせると、数値制約が満たされる場合に限り、有効なゲーム履歴が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

vals = [7, 6, 5, 4, 3, 2, 1]

def decompose(x):
    res = []
    for v in vals:
        while x >= v:
            res.append(v)
            x -= v
    if x != 0:
        return None
    return res

def solve_case(a, b, n, p):
    A = decompose(a)
    B = decompose(b)
    if A is None or B is None:
        return "NA"

    total_scores = len(A) + len(B)

    if total_scores > n + 21:
        return "NA"

    # build actions: we interleave greedily
    i = j = 0
    turn = 0
    res = []

    while i < len(A) or j < len(B):
        if turn == 0:
            if i < len(A):
                res.append(str(A[i]))
                i += 1
            elif j < len(B):
                res.append("/")
            else:
                break
        else:
            if j < len(B):
                res.append(str(B[j]))
                j += 1
            elif i < len(A):
                res.append("/")
            else:
                break
        if res[-1] == "/":
            turn ^= 1

    cur = 0
    for ch in res:
        if ch == "/":
            cur ^= 1

    if cur != p:
        res.append("/")

    if len(res) > 100:
        return "NA"

    return "".join(res)

def main():
    T = int(input())
    out = []
    for _ in range(T):
        a, b, n, p = map(int, input().split())
        out.append(solve_case(a, b, n, p))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```分解ステップでは、7 から 1 までの固定スコア値に対する貪欲な減算が使用されます。最小限のショット数は必要なく、実行可能性のみが必要であり、残りの失敗は直ちに不可能であることが証明されるため、これは安全です。 

構築フェーズでは A と B を独立して扱い、ターンの変更を考慮しながらそれらをインターリーブします。 現在のプレイヤーが行動できない、または行動すべきではない場合には必ずミスが挿入され、そのミスによりターンが反転します。 

最後に、最大 1 つの追加ミスでパリティを調整します。 1 回の切り替えで、計算されたスターティング プレーヤー パリティと必要なスターティング プレーヤー パリティの不一致を修正できるため、これで十分です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方のスコアが 0 であるが、必要なプレーヤーが B である場合です。アルゴリズムは空のシーケンスを生成し、ターンを反転するために 1 つのミスを追加します。 これは、スコアリングの制約が存在しないため有効であり、パリティが唯一の要件です。 

もう 1 つのエッジ ケースは、スコアが小さいものの、貪欲な減算ではきれいに分解できない場合に発生します (たとえば、1 より高い値のみが誤って想定された場合)。 私たちのシステムでは、1 が常に利用可能なため、このようなことは起こりませんが、1 を削除するバリアントは、剰余チェックによる実現可能性の検出を直ちに中断します。 

最後のエッジ ケースは、構築された長さの合計が 100 を超える場合です。このような場合、有効な分解が存在する場合でも、出力制約を満たすことができないため、拒否する必要があります。 アルゴリズムはこれを明示的にチェックして NA を返し、問題の書式制限への準拠を保証します。
