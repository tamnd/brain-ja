 ## 解決策
 ## 問題の理解

 私たちにはアイテムのコレクションが与えられています。 各項目には重みと値がありますが、一部の項目ではこれら 2 つの数値のうちの 1 つが欠落しているため、10 億を超えない正の整数として当社が割り当てる必要があります。 

完成したデータセットに対して 2 つの貪欲なプロシージャが後で実行されます。 アリスは、重量を増やしてアイテムを分類し、次のアイテムがナップザックの容量をオーバーフローするまで、その順序でアイテムを取り出します。その時点で完全に停止します。 ボブは、値の降順でアイテムを並べ替え、その順序でスキャンし、残りの容量に収まるたびにアイテムを取得します。 

私たちの仕事は、両方のプロシージャが最終的にまったく同じ項目セットを選択するように、欠落している重みと値を割り当てることです。 

主な困難は、割り当てが並べ替え順序とナップザックの実現可能性の両方に影響を与えるため、単一の容量制約の下で順序付けと累積合計を同時に制御することです。 

制約が十分に小さいため、テスト ケースごとの 2 次推論、さらにはわずかに超 3 次推論がすべてのケースで受け入れられるわけではありません。 項目は合計で最大 3000 個ありますが、本当の難しさは生の計算ではなく、順序と容量から来る混合制約の下で一貫した割り当てを構築することです。 

アリスとボブを別々に扱おうとすると、すぐに微妙な失敗モードが現れます。 アリスの選択は重みの順序とプレフィックスの合計のみに依存しますが、ボブの選択は値の順序と増分の実現可能性に依存します。 2 番目の手順は最終的な合計だけでなく、中間の残りの容量に敏感であるため、最初に 1 つの順序を修正する単純な試みでは、他の貪欲な手順が発散することがよくあります。 

## アプローチ

 ブルートフォースの観点では、すべての欠損値を割り当てて、両方の戦略をシミュレートしようとします。 それぞれの未知の値は最大 10 億の値を取り、指数関数的または無限の検索空間が与えられるため、これは明らかに不可能です。 

より構造化された観察は、アリスの手順が実際に何を生み出すかを理解することで得られます。 重みが固定されると、アリスは恣意的に選択するのではなく、常に重み順にソートされたプレフィックスを取得し、適合しない最初の項目で停止します。 これは、アリスが選択したセットがその順序付けのしきい値によって完全に決定されることを意味します。 

ボブの手順は、選択順序に関してはより柔軟ですが、アイテムが値でソートされたら、可能であればそれらをパックしようとするという意味では依然として貪欲です。 

重要なアイデアは、どちらの順序でも、アリスが取得したアイテムとボブが取得しなかったアイテムが交互に配置されるような相互作用を回避する必要があるということです。 両方のソート基準の下で安定した項目の共通の「受け入れ領域」について両方のプロシージャを強制的に一致させることができれば、両方の貪欲なプロセスは同じように動作します。 

同一の動作を保証する最も簡単な方法は、両方のアルゴリズムですべての項目を効果的に選択させることです。これにより、容量や順序の競合によって拒否されることなく、両方の貪欲なプロシージャがすべての項目を受け入れるようにするという問題が軽減されます。 

これを行うために、すべての項目が適合し、すべての項目が拒否が発生しない一貫した順序で処理されるように、不足している重みと値をすべて割り当てます。 

重量の合計が最大 W であることを保証し、値の注文によって包含が妨げられないことを保証します。 すべての項目が適合すると、接頭語ステップがオーバーフローすることがないため、Alice はすべてを受け取ります。また、遭遇したときにすべての項目が適合するため、Bob はすべてを受け取ります。 

唯一の障害は、一部のウェイトが固定されており、減らすことができないことです。 ただし、未知の重みを割り当てることが許可されているため、固定重みがすでに容量を超えていない限り、合計制約が満たされるように、いつでも十分小さな重みを選択できます。

これは直接の実現可能性チェックにつながります。すでに固定されている重みの合計が W より大きい場合、それらの重みは不変であるため、どの割り当てもアリスの手順を救うことはできません。 それ以外の場合は、不明な重みをすべて 1 として割り当て、合計重みが容量内に収まるようにすることができます。 値には任意の正の値を割り当てることができます (たとえば、すべて等しい)。これにより、ボブの順序はタイブレークまで無関係になります。 

これにより、両方の欲張りプロシージャがすべての項目を受け入れるようになります。

 | ブルートフォース割り当て検索 | 指数 | O(n) | 遅すぎる |
 | すべて選択されたソリューションを構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 アリスとボブの両方がすべての項目を選択するソリューションを構築します。 

1. すでに固定されているすべての指定された重み (ゼロ以外のエントリ) の合計を計算します。 これらの重量は変更できないため、ナップザックの合計使用量に厳しい下限が形成されます。 
2. この固定合計がすでに W を超えている場合は、未知の重みを追加する前であっても、アリスがすべての項目を取得しようとすると容量を超えるため、割り当ては不可能になります。 この場合、タスクは不可能であるとすぐに出力します。 
3. それ以外の場合は、すべての未知の重みに値 1 を割り当てます。これにより、重みは正の整数でなければならないという要件を尊重しながら、合計の重みが可能な限り小さく保たれます。 
4. 次に、アリスのプロセスを考えてみましょう。 すべての重みが正であり、その合計が W を超えないため、重みでソートされた順序のすべての接頭辞が引き続き実行可能であるため、アリスはナップザックから溢れるアイテムに遭遇することはありません。 したがって、彼女はあらゆるアイテムを選択します。 
5. 不明な値もすべて 1 に代入します。 これにより、すべての値が同一になるため、Bob の並べ替えは安定し、元のインデックスのみに依存するようになります。 
6. ボブはすべての項目をある順序で処理しますが、すべての項目が残りの容量に収まるため (総重量が W 以内であるため)、容量のためにスキップすることはありません。 したがって、ボブもすべてのアイテムを選択します。 

### なぜ効果があるのか

 この構造により、両方の貪欲なプロセスが、容量の制約によって拒否が引き起こされることのない自明な体制に縮小されます。 総重量が W によって制限されるため、アリスの停止条件は決してアクティブになりません。ボブのスキップ条件は、考慮された時点ですべての項目が個別に適合するため、決してアクティブになりません。 どちらのプロシージャにもすべての項目が含まれるため、選択されたセットは同一です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, W = map(int, input().split())
        w = list(map(int, input().split()))
        r = list(map(int, input().split()))
        
        fixed_sum = 0
        for x in w:
            if x != 0:
                fixed_sum += x
        
        if fixed_sum > W:
            print("No")
            continue
        
        print("Yes")
        
        # assign weights
        res_w = []
        for x in w:
            if x == 0:
                res_w.append(1)
            else:
                res_w.append(x)
        
        # assign values
        res_r = []
        for x in r:
            if x == 0:
                res_r.append(1)
            else:
                res_r.append(x)
        
        print(*res_w)
        print(*res_r)

if __name__ == "__main__":
    solve()
```実装は構築の後に直接続きます。 唯一の重要なステップは、固定重みの合計を計算し、W に対する実現可能性を検証することです。それ以外はすべて、欠落しているエントリに 1 を直接割り当てることです。 

微妙な点の 1 つは、指定された値を決して変更しないことです。 この問題により、アイテムごとに重量または値の最大 1 つが欠落していることが保証され、上書き時に競合が発生しないため、これは重要です。 

## 実用的な例

 ### 例 1

 容量 W = 10 の 3 つのアイテムを考えてみましょう。 

重みが`[3, 0, 2]`そして値は`[0, 5, 0]`。 

固定重量の合計は`3 + 2 = 5`、容量内です。 

欠落している重みと値を 1 として割り当てます。 

| ステップ | 重み | 値 | 定額 | 有効 |
 | --- | --- | --- | --- | --- |
 | イニシャル | 3、0、2 | 0、5、0 | 5 | はい |
 | 塗りつぶし後 | 3、1、2 | 1、5、1 | 5 | はい |

 アリスは重量の増加順にアイテムを処理し、最大で 6 個、合計 10 個以下になるため、すべてのアイテムを受け取ります。 ボブは値の降順に項目を処理し、すべての項目が適合するため、すべての項目も取得します。 

これにより、同一の選択が行われることが確認されます。 

### 例 2

 W = 6 と仮定し、重みを付けます`[2, 0, 5]`、値`[0, 3, 0]`。 

固定重量の合計は`2 + 5 = 7`、すでに容量を超えています。 

| ステップ | 定額 | 決定 |
 | --- | --- | --- |
 | イニシャル | 7 | 不可能 |

 不変の重みですら容量を超えるため、アリスは割り当ての前に強制的に失敗することになり、解決策は存在しません。 

これは唯一の障害を示しています。固定重みだけでは実現可能性を侵害する可能性があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    T = int(sys.stdin.readline())
    out = []
    for _ in range(T):
        n, W = map(int, sys.stdin.readline().split())
        w = list(map(int, sys.stdin.readline().split()))

            r2 = [x if x != 0 else 1 for x in r]
            out.append(" ".join(map(str, w2)))
            out.append(" ".join(map(str, r2)))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースは、固定ウェイトがすでに容量を超えている場合です。 たとえば、項目の重みが 10^9 で W が小さい場合、割り当てを行っても重みを減らすことはできません。 アルゴリズムは、代入を試行せずに即座に正しく拒否します。 

もう 1 つのエッジ ケースは、すべての値が欠落しているが重みが固定されている場合です。 その場合でも、アリスの実現可能性が満たされると、選択は完全に重みによって決定されるため、値の割り当ては無関係です。 

最後の微妙なケースは、多数のゼロが存在する場合です。 常に 1 を割り当てるため、正確さを維持しながら総重量の増加を最小限に抑え、構築されたソリューションの容量を誤って超えることはありません。
