 ## 解決策
 ## 問題の理解

 私たちには最大 6 人のキャラクターからなる小さなパーティーが与えられ、長い一連のラウンドにわたって繰り返し戦います。 各ラウンドは固定のエネルギープールから始まり、各キャラクターはスキルを 1 回使用するか、アイドル状態のままにすることができます。 スキルを使用するとラウンドのエネルギーの一部が消費され、ラウンド内の合計消費量が利用可能なプールを超えることはできません。 

各キャラクターには基本コストと固定ダメージ値があります。 面白いのは、コストはラウンド間で静的ではないということです。キャラクターがラウンドでスキルを使用すると、次のラウンドではコストが一時的に高くなり、毎ラウンド使用し続ける限り、その高いレベルに留まります。 ラウンドをスキップすると、コストはすぐに元の値にリセットされます。 

私たちは、ラウンドごとの総エネルギー制限が尊重され、全ラウンドにわたるダメージの合計が最大化されるように、ラウンドごと、キャラクターごとに行動するかどうかを選択したいと考えています。 ラウンド数が非常に多くなる可能性があるため、ラウンドごとにシミュレーションすることはできません。 

制約によってソリューションの構造が決まります。 キャラクターの数は最大でも 6 つであり、これは、「このラウンドでどのキャラクターのサブセットがアクティブであるか」を説明する状態は列挙するには十分に小さいことを強く示唆しています。 困難はサブセットの選択自体ではなく、コストの増加とリセットによって引き起こされるラウンド間の依存関係です。 

ラウンド数は最大 10 億に達する可能性があります。 これにより、ラウンドごとの動的プログラミングやシミュレーションが即座に除外されます。 有効なソリューションは、プロセスを繰り返しを検出できる形式、または安定したサイクルに到達できる形式に圧縮する必要があります。 

コストの増加を避けるためにキャラクターが交互に使用される場合、微妙なエッジケースが発生します。 たとえば、キャラクターを 1 ラウンドおきに使用して、ダメージを与えながら基本コストを維持することができます。 各ラウンドで常に最もダメージ効率の高いサブセットを個別に選択する単純な貪欲なアプローチは、長期的なコストの進化を無視しているため、ここでは失敗します。 

もう 1 つの失敗モードは、キャラクターが一度「高価」になったら、有用な意味で高価なままであると仮定することです。 実際には、1 ラウンドでもスキップするとコストが完全にリセットされるため、最適な戦略により、高価なキャラクターを意図的に「冷却」して、後で効率的に再利用することができます。 

## アプローチ

 ブルートフォース解釈では、すべてのラウンドが状態遷移の問題として扱われます。 各ラウンドで、各キャラクターが前のラウンドで使用されたかどうかがわかり、それによって現在のコストが決まります。 これは、どの文字が前のラウンドで使用されたかを表すサイズ n のバイナリ ベクトルで構成される状態を示唆しています。 このような状態から、現在のラウンドで使用するキャラクターのすべてのサブセットを試し、エネルギー制限の下での実現可能性を確認し、ダメージを計算して、新しい状態に移行します。 

これはルールを直接シミュレートするため、これは正しいです。コストは以前の使用状況のみに依存し、決定は現在の状態にのみ依存します。 ただし、各状態には最大 2^n 個の可能性があり、各遷移では別の 2^n 個のサブセットが試行されます。 つまり、ラウンド状態レイヤーごとに 2^(2n) 回の遷移になります。 n が小さい場合でも、ラウンド数 R は最大 10^9 になるため、ラウンドごとに反復することは不可能です。 

重要な観察は、システムが最大 2^n 個の状態を持つ有限状態マシンであり、遷移は前の状態にのみ依存するということです。 これは、ノードが状態、エッジが 1 ラウンドのプレイを表す有向重み付きグラフを扱っていることを意味します。 各エッジには、その状態を考慮して 1 ラウンドで達成可能な最大ダメージに等しい重みがあります。 問題は、このグラフの R ステップにわたる最大合計重みを見つけることになります。これは、古典的な最大プラス行列累乗問題です。

状態 a (どのキャラクターが現在「コストブースト モード」にあるかを決定します) で開始し、状態 b (このラウンドで選択されたセット) で終了する場合、エントリ T[a][b] が 1 ラウンドで達成可能な最高のダメージとなる遷移行列を構築します。 次に、R ステップを効率的に計算するために、max-plus 乗算の下でこの行列の高速累乗を実行します。 

n は最大 6 であるため、状態空間は最大 64 となり、64 × 64 の行列が管理可能になります。 S = 64 であるため、O(S^3 log R) での行列のべき乗は実行可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(R・2^n・2^n) | O(2^n) | 遅すぎる |
 | Max-Plus Matrix Exponentiation | O(2^{3n} log R) | O(2^{2n}) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態を長さ n のビットマスクとしてエンコードします。ビット i は、キャラクター i が前のラウンドでスキルを使用したかどうかを示します。 このビットマスクは、各キャラクターの現在のコストを完全に決定します。 

状態ごとに、各キャラクターの実効コストを計算します。前のラウンドで使用された場合、コストは ci + k、それ以外の場合は ci になります。 

すべての状態について、その状態から開始した場合に 1 ラウンドで得られる最大の合計ダメージを事前計算します。 

### 1. Enumerate all states

 0 から 2^n - 1 までのすべてのマスクを反復処理します。各マスクは、現在どのキャラクターが「コスト上昇」状態にあるかを表します。 

未来はこのバイナリメモリのみに依存し、他の歴史は重要ではないため、これが必要です。 

### 2. Compute effective costs per state

 固定状態マスクの場合、ビットが設定されているかどうかに応じて、各文字に ci または ci + k を割り当てます。 これにより、問題は 1 ラウンドの標準的なナップザックのような制約に変換されます。 

重要な点は、1 ラウンド内で状態が判明するとコストが固定されるということです。 

### 3. ラウンドの文字のすべてのサブセットを列挙します。 

州ごとに、キャラクターのすべてのサブセットを試して、このラウンドで誰が行動するかを決定します。 総コストと総ダメージを計算し、コストが m を超えるサブセットを破棄します。 

このステップは、n が小さいため有効であり、すべての 2^n サブセットが列挙可能です。 

### 4. Build transition matrix

 現在のラウンドで使用されたキャラクターのみが次のラウンドでブーストされるため、各開始状態 a と選択された各サブセット S について、S に等しい次の状態 b を計算します。 更新します:

 T[a][b] = max(T[a][b], damage(S, a))

 これにより、考えられる 1 ラウンドのトランジションがすべてキャプチャされます。 

### 5. 遷移行列の高速累乗

 ここで、T を最大プラス隣接行列として解釈します。 行列の乗算はラウンドの合成に対応し、加算はダメージの合計に置き換えられ、比較は最大値の取得に置き換えられます。 

2 進累乗を使用して T を R 乗します。 ダメージを受けずに同じ状態に留まることがゼロである恒等行列から始めます。 

累乗後、すべての開始状態で最大のエントリを取得し、R ラウンドで達成可能な最高の合計ダメージを取得します。 

### なぜ効果があるのか

 重要な不変条件は、k ラウンド後、行列パワー T^k が正確に k ラウンドにわたって状態のペア間を遷移するときに達成可能な最良の合計ダメージを正しく格納することです。 各乗算ステップは最適な部分構造を構成します。k ラウンドを i と k-i に分割することで、最適なシーケンスが最適なプレフィックスとサフィックスに分解されます。 状態はコストの進化を完全に捉えるため、隠された履歴が失われることはなく、すべての有効な戦略がこの状態グラフのパスに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**30

def mat_mul(A, B, n):
    C = [[NEG] * n for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        for k in range(n):
            if Ai[k] == NEG:
                continue
            Bik = B[k]
            aik = Ai[k]
            for j in range(n):
                if Bik[j] == NEG:
                    continue
                val = aik + Bik[j]
                if val > C[i][j]:
                    C[i][j] = val
    return C

def mat_pow(mat, exp, n):
    res = [[NEG] * n for _ in range(n)]
    for i in range(n):
        res[i][i] = 0
    base = mat
    while exp:
        if exp & 1:
            res = mat_mul(res, base, n)
        base = mat_mul(base, base, n)
        exp >>= 1
    return res

def solve():
    n, m, k, R = map(int, input().split())
    a = []
    c = []
    for _ in range(n):
        ai, ci = map(int, input().split())
        a.append(ai)
        c.append(ci)

    S = 1 << n
    trans = [[NEG] * S for _ in range(S)]

    for mask in range(S):
        cost = [0] * n
        for i in range(n):
            cost[i] = c[i] + (k if (mask >> i) & 1 else 0)

        best = [-1] * S
        for sub in range(S):
            total_cost = 0
            total_dmg = 0
            for i in range(n):
                if (sub >> i) & 1:
                    total_cost += cost[i]
                    total_dmg += a[i]
            if total_cost <= m:
                best[sub] = total_dmg

        for sub in range(S):
            if best[sub] >= 0:
                trans[mask][sub] = max(trans[mask][sub], best[sub])

    res = mat_pow(trans, R, S)

    ans = 0
    for i in range(S):
        for j in range(S):
            ans = max(ans, res[i][j])

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず各状態をエンコードし、状態ごとに実行可能なすべてのサブセットを計算します。 遷移マトリックスには、状態間の 1 ラウンドの遷移で達成可能な最良のダメージが格納されます。 次に、行列累乗によって多数のラウンドが対数ステップに圧縮され、最終的な答えは、考えられるすべての開始状態と終了状態にわたる最良の値になります。 

微妙な点は、固定開始状態を強制していないことです。 任意の初期設定が許可されているため、最終的な答えは単一の開始行ではなく、すべての行列エントリの最大値を取得します。 

## 実用的な例

 2 文字の小さなケースを考えてみましょう。 キャラクター 1 はコスト 2 で 10 ダメージを与え、キャラクター 2 はコスト 3 で 6 ダメージを与えます (m = 5、k = 2)。 

### 状態遷移トレース

 | マスク (前に使用) | コスト (c または c+k) | 最良のサブセット | コスト | ダメージ |
 | --- | --- | --- | --- | --- |
 | 00 | (2, 3) | {1,2} | 5 | 16 |
 | 01 | (2, 5) | {1} | 2 | 10 |
 | 10 | (4,3) | {2} | 3 | 6 |
 | 11 | (4,5) | { } | 0 | 0 |

 これは、以前の使用法が次のラウンドの実現可能性にどのように直接影響するかを示しています。 高価な州は特定の組み合わせを削減します。 

ここで、R = 2 と仮定します。1 ラウンドの後、選択されたサブセットに応じて状態が遷移し、行列のべき乗によりこれらの選択が 2 つのステップで構成されます。 最初のラウンドで両方のキャラクターを選択すると、高コストの 2 ラウンド目が強制され、総利益が減少する可能性があるため、最良のシーケンスはラウンドごとに欲張らないことがよくあります。 

このトレースは、状態依存性が不可欠であることを示しており、各ラウンドを独立して処理できない理由を正当化します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^{3n} log R) | 2^n 個の状態、2^n 個のサブセットにわたる各遷移、log R 上の行列累乗 |
 | スペース | O(2^{2n}) | 遷移行列と作業行列 |

 n ≤ 6 の場合、状態は最大 64 個であるため、3 次係数は乗算ごとに約 262k の演算になります。 log R が最大 30 なので、制限時間内に余裕で収まります。

 ## 特殊なケース

 重要なエッジケースは、すべてのキャラクターがブースト状態では高価であるが、基本状態では安価である場合です。 たとえば、m = 2 で ci = 1 および k = 1000 の文字です。最適な戦略は、それを 1 ラウンドおきに使用し、使用可能な状態と使用できない状態を交互に繰り返すことです。 状態遷移が文字が使用されたかどうかを明示的にエンコードし、行列が交互のパターンを自然に表現できるようにするため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、R = 1 の場合です。この場合、べき乗は 1 ラウンドのサブセットにわたる単一層の最大化に崩壊し、行列はすべての有効なサブセットの直接列挙に正しく還元されます。 

3 番目のエッジ ケースは、ある状態で実行可能なサブセットが存在しない場合です。 この状態には、有限の重みを持つ発信遷移がないため、事実上デッド ノードになります。 マトリックスは NEG 値を介してこれを自然に処理し、そのようなパスが最大値に寄与しないことを保証します。
