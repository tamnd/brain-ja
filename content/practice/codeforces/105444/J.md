 ## 解決策
 ## 問題の理解

 少数のチョコレートの蛇口が与えられ、各蛇口は一定の温度でチョコレートを生産しますが、流量は一定の間隔に制限されて制御可能です。 各蛇口の流量を選択すると、システムはすべての個別の流れの合計に等しい結合流量を生成し、結果として得られる温度は、これらの流量を重みとして使用した蛇口温度の加重平均になります。 

各クエリは、合計流量が目標値と等しく、結果として得られる加重平均温度が別の目標値と等しくなるように、すべての蛇口を同時に調整できるかどうかを尋ねます。 

問題を幾何学的に再構成することは役立ちます。各蛇口はベクトルのような選択に寄与し、流れは大きさであり、温度は重み付けされた組み合わせの方向に影響します。 制約は連続区間であるため、離散状態ではなく、境界内の実際の値を選択します。 

重要な制約は、k が最大 10 であるということです。これは、サブセットに対する指数関数的な探索や凸幾何学推論が実行できるほど十分に小さいです。 クエリの数は 100,000 に達する可能性があるため、前処理後に各クエリはほぼ一定時間または対数時間で応答する必要があります。 

素朴な解釈では、すべての可能なフロー割り当てをシミュレートまたは検索しようとしますが、空間は連続的かつ高次元であるため、直接列挙することは不可能です。 

合計流量がゼロの場合、微妙なエッジケースが現れますが、それぞれの ai と bi が負ではなく、少なくとも 1 つのレシピが φ ≥ 1 を必要とするため、これは不可能です。それでも、分母がゼロになると温度が定義されなくなるため、ゼロに近い流量構成が重要になるため、正しい定式化ではゼロによる除算を回避する必要があります。 

もう 1 つの重要なエッジ状況は、すべての蛇口の温度が同じである場合です。 次に、実行可能な流量の割り当ては分布に関係なく同じ温度を生成し、問題を総流量の単純な間隔チェックにまとめます。 

## アプローチ

 強引なアイデアは、各蛇口の流れを細かいステップに離散化し、すべての組み合わせを試すことです。 適度な離散化、たとえば蛇口ごとに 100 ステップを使用した場合でも、状態の数は 100^10 になり、天文学的に大きくなり、使用できなくなります。 

もう 1 つの大胆なアイデアは、これをクエリごとの連続最適化問題として扱い、線形制約と非線形比率制約の下で変数 x_i を解決することです。 クエリごとに直接解くには、不等式と有理方程式を含むシステムを解く必要があり、100,000 クエリには遅すぎます。 

重要な観察は、制約が 2D 投影空間内の凸領域 (合計流量 F と合計加重温度分子 S = Σ x_i t_i) を定義していることです。 すべてのフォーセットは、(F, S) 寄与空間内の線分に寄与します。x_i を選択すると、(x_i, x_i * t_i) に寄与します。ここで、x_i ∈ [a_i, b_i]。 したがって、各蛇口は、この平面内の 2 点間のセグメントを定義します。 

全体の実現可能な領域は、2D の k 個の線分のミンコフスキー和であり、凸多角形です。 k ≤ 10 であるため、この多角形には最大 2^k 個の頂点があります。 a_i または b_i の各フォーセットを考慮することですべての極点を計算し、すべてのサブセットの組み合わせを得ることができます。 これにより、(F, S) 空間の凸包が得られます。 

各クエリ (φ, τ) は、点 (φ, φ・τ) がこの凸多角形の内側にあるかどうかをチェックすることになります。 ポリゴンは前処理後に固定されるため、事前計算されたハルで方向チェックを使用して O(log V) のメンバーシップをテストできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 離散化 / ブルートサーチ | O(M^k) | O(M^k) | 遅すぎる |
 | 2^k コーナー + ポリゴン内ポイント クエリ上の凸包 | O(2^k log 2^k + r log 2^k) | O(2^k) | 承認済み |

 ## アルゴリズムのチュートリアル

各蛇口の選択を 2D 空間内の点として書き換えます。 蛇口 i がフロー x_i を使用する場合、それは (x_i, x_i t_i) に寄与します。 複数の蛇口を合計すると、合計点 (F、S) が生成されます。ここで、F は合計流量、S は合計加重温度分子です。 

私たちは、蛇口ごとに最小流量に寄与するか最大流量に寄与するかを決定することにより、考えられるすべての極端な構成を事前計算します。 これにより、(F, S) 空間内のすべての 2^k コーナー点が得られます。 

次に、これらの点の凸包を反時計回りの順序で計算します。 

クエリごとに、希望の条件を点 (φ、φ・τ) に変換します。 問題は、この点が凸多角形の内側にあるのか、それとも凸多角形の境界上にあるのかということになります。 

ハルが凸状で順序付けされているという利点を活かし、方位チェックに基づく標準の凸多角形ポイント テストを使用してメンバーシップのクエリに答えます。 

### なぜ効果があるのか

 実現可能な領域は、2D 線形マッピングにおける k 個の線分のミンコフスキー和です。 線分のミンコフスキー和は、各線分の端点を選択することで頂点が得られる凸多角形です。 任意の内部点は、頂点間を線形補間する x_i の中間値の選択に対応します。 したがって、達成可能な (F, S) ペアの完全なセットは、まさに 2^k の極値構成の凸包であり、実現可能性のチェックは凸多角形のメンバーシップに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def build_hull(points):
    points = sorted(set(points))
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def point_in_convex_polygon(poly, p):
    if len(poly) <= 2:
        return False

    def orient(a, b, c):
        return cross(a, b, c)

    n = len(poly)

    if orient(poly[0], poly[1], p) < 0 or orient(poly[0], poly[-1], p) > 0:
        return False

    lo, hi = 1, n - 1
    while hi - lo > 1:
        mid = (lo + hi) // 2
        if orient(poly[0], poly[mid], p) >= 0:
            lo = mid
        else:
            hi = mid

    return orient(poly[lo], poly[(lo + 1) % n], p) >= 0

def solve():
    k = int(input())
    taps = [tuple(map(int, input().split())) for _ in range(k)]

    points = []
    for mask in range(1 << k):
        F = 0
        S = 0
        for i in range(k):
            ti, ai, bi = taps[i]
            xi = bi if (mask >> i) & 1 else ai
            F += xi
            S += xi * ti
        points.append((F, S))

    hull = build_hull(points)

    r = int(input())
    out = []
    for _ in range(r):
        phi, tau = map(int, input().split())
        p = (phi, phi * tau)
        out.append("yes" if point_in_convex_polygon(hull, p) else "no")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各蛇口構成をポイント (F、S) にエンコードすることから始まります。 各マスクは、各蛇口の下限または上限のいずれかの流量境界の選択を表します。これは、実行可能な領域のすべての極端な頂点を捕捉するのに十分です。 

凸包の構築では単調連鎖アルゴリズムを使用し、到達可能な領域の境界点のみを確実に保持します。 内部の組み合わせは補間フローに対応するため、内部の点は無関係であり、実現可能性が船体を超えて拡張されることはありません。 

各クエリは温度と流れを線形制約点に変換し、凸性を利用した二分探索ベースの方法でポリゴンの包含をチェックします。 

よくある間違いは、温度制約は総流量を乗算すると線形になることを忘れていることです。そのため、比率を直接使用するのではなく、(F, S) 空間で作業します。 

## 実用的な例

 2 つの蛇口を備えた簡素化されたセットアップを考えてみましょう。 

| ステップ | マスク | ふ | S | 解釈 |
 | --- | --- | --- | --- | --- |
 | 00 | 0 | a1 + a2 | a1 t1 + a2 t2 | 少なくとも両方 |
 | 01 | 1 | b1 + a2 | b1 t1 + a2 t2 | 最初の最大値 |
 | 10 | 2 | a1 + b2 | a1 t1 + b2 t2 | 秒最大 |
 | 11 | 3 | b1 + b2 | b1 t1 + b2 t2 | 両方の最大 |

 これら 4 つの点の外殻は、パラメーターの配置に応じて、凸状の四角形または三角形を形成します。 

クエリ（φ、τ）は点（φ、φτ）となる。 これが船体の内側にある場合、レシピは実行可能です。 

これは、実現可能性がエンドポイント構成の線形結合によって完全に決定され、中間のフロー値がポリゴン内の凸補間に対応することを示しています。

 ## 特殊なケース

 すべての蛇口の温度が同じである場合、すべての構成で同じ比率が生成されるため、実現可能性は必要な流量が間隔の合計内にあるかどうかによってのみ決まります。 (F, S) 空間では、すべての点が 1 つの直線上にあり、ハルはセグメントに縮退しますが、凸包の構築により正しく縮小されるため、アルゴリズムは引き続きセグメントを処理します。 

各フォーセットが ai = bi である場合、システムはまさに 1 つの可能な状態を持ちます。 ハルは単一の点になり、クエリはその点と正確に等しい場合にのみ一致します。これは、ポリゴン内ポイント チェックによって正しく捕捉され、等しい場合にのみ true を返します。 

k = 1 の場合、多角形は区間の端点を表す 2 つの点に減ります。 船体はセグメントであり、実現可能性は (φ, φτ) がそのセグメント上にあるかどうかを確認することになります。これは、単一の制御可能な蛇口の物理的解釈と一致します。
