 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各セルには、そこで話されている 3 つの未知の言語のうちのいくつが話されているかについての部分的な情報のみが含まれています。 すべてのセルには 1 または 2 のマークが付いています。1 はそのセルで 1 つの言語が話されていることを意味し、2 はそのセルで少なくとも 2 つの言語が話されていることを意味します。 

この隠れた構造の背後では、3 つの言語のそれぞれがグリッドの接続された領域を占有する必要があり、すべてのセルは少なくとも 1 つの言語領域に属します。 セルは複数の言語に属することができるため、重複は許可されます。 観察できる唯一の制約は、セルが 1 つの言語地域にのみ存在するか、少なくとも 2 つの言語地域に存在するかということです。 

タスクは、これらの数と接続要件と一致するグリッド セルへの 3 つの言語の有効な割り当てを構築するか、そのような割り当てが存在しないと判断することです。 

主要な構造上の制約は、各言語の地域の接続性です。 これにより、ローカルの「オーバーラップ カウント」パターンを照合しながら、すべてのセルを共同でカバーする 3 つの接続されたセットを構築するという問題が直ちに発生します。 

グリッドのサイズは最大です$200 \times 200$、これは、$O(nm)$または$O(nm \log nm)$解決。 セルごとに 3 つのラベルの割り当てに対する指数関数的な検索を伴うものは実行不可能です。$3^{40000}$最悪の場合。 

貪欲に言語を個別に割り当てようとすると、微妙な失敗モードが発生します。 たとえば、最初に A に対して接続されたリージョンを構築し、次に B と C に対して独立して構築した場合、「1」とマークされたセル (1 つの言語のみ) を誤って複数のリージョンに所属させたり、後で重複制約を満たすときにリージョンを切断したりする可能性があります。 1/2 制約による 3 つのセット間の結合は、ローカルではなくグローバルです。 

2 番目の微妙な点は、1 とマークされたセルは複数の言語に属することができないため、「排他的領域」のように動作するのに対し、2 とマークされたセルは少なくとも 2 つの言語に属している必要があり、強制オーバーラップアンカーとして機能することです。 どのソリューションでも、各言語の接続を個別に維持しながら、この分割を尊重する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、各セルに次のサブセットを割り当てようとします。$\{A,B,C\}$ラベルと一致していること (1 セルの場合は 1 つのサブセット、2 セルの場合はサイズ 2 または 3 の 1 つ)、各言語が連結成分を誘発するかどうかを確認します。 可能性を制限したとしても、1 マス目では 3 つの選択肢があり、2 マス目では 4 つの選択肢があり、おおよその選択肢が得られます。$3^{k} \cdot 4^{(nm-k)}$可能性。 最大 40,000 個のセルでは、これは完全に不可能です。 

構造的なブレークスルーは、視点を反転することから生まれます。言語を直接割り当てる代わりに、まずグリッド内に 2 つのスパニング ツリー (言語 A 用と言語 B 用に 1 つ) を構築し、共用体制約によって強制される C を暗黙的に定義します。 

重要な点は、最小限の構造ではなく、接続性を確保することだけが必要であるということです。 接続性は、隣接関係をエッジとして扱い、グリッド セル上にスパニング ツリーを構築することによって保証できます。 A と B がそれぞれ 1/2 ラベルを尊重する接続されたスパニング構造を形成していることを確認できれば、C を選択して、オーバーラップの一貫性を通じてカバレッジと接続性を自動的に維持できます。 

重要な簡素化は、BFS スタイルの構造を使用してグリッドを 2 つのフェーズに分割することです。 まず、必要なすべての重複セル (2 とマークされたセル) に接触するグリッドを通るバックボーン パスを特定します。 次に、各言語が接続されたセットを取得するように、スパン トラバーサルに沿って制御された交互パターンで言語を割り当てます。トラバーサル構造により、すべての 2 セルが自然に複数のセットに含まれます。 

これにより、グリッド グラフの 1 つの走査を構築し、その走査におけるパリティと役割に基づいて慎重にラベルを割り当てるという問題が軽減され、グローバル接続を中断することなく、ローカルで重複要件が確実に満たされるようになります。

 ## アルゴリズムのチュートリアル

 各セルがその 4 つの隣接セルに接続されたノードであるグラフとしてグリッドをモデル化します。 このアイデアは、接続性とオーバーラップ制約の両方を強制する構造化されたトラバーサルを埋め込むことによって、3 つの接続されたコンポーネントを構築することです。 

1. グリッド内でスパニング トラバーサルの開始点として機能するセルを見つけます。 すべてのセル上に DFS または BFS ツリーを構築します。 これにより、グリッド全体をカバーする単一の接続された構造が確保されます。 
2. BFS を使用してグリッドのスパニング ツリーを構築します。 このツリーは、セル間の親子関係を定義します。 ツリーを使用する理由は、循環がなくなり、矛盾のない一貫したラベルを簡単に割り当てることができるためです。 
3. 言語 A のバックボーンとして BFS ツリー内の 1 つのパスを選択し、そのパスに 2 つのセルによって暗示されるすべての接続領域から少なくとも 1 つのセルが含まれていることを確認します。 これにより、A が接続され、十分に拡散されることが保証されます。 
4. BFS ツリー内の均等な深さのすべてのセルに言語 A を割り当てます。 これにより、すべてのノードがツリー エッジを介して接続され、パリティによって隣接構造が破壊されないため、接続が確保されます。 
5. BFS ツリー内の奇数の深さにあるすべてのセルに言語 B を割り当てます。 これは、エッジが適切に交互になる場合、奇数の深さのノードもツリー内の接続された部分構造を形成するため、B の同じ接続性保証を反映しています。 
6. 1/2 制約によってまだ一意に決定されていないすべてのセルに言語 C を割り当てます。これにより、すべてのセルが少なくとも 1 つの言語を持ち、すべての 2 セルがパリティ分割による重複を持つことが効果的に保証されます。 
7. 1 とマークされたセルについては、パリティに応じて A または B のどちらか一方に割り当てられるようにし、両方には割り当てないようにします。 2 とマークされたセルについては、必要に応じて A と B の両方の割り当てを受信するようにし、完全なカバレッジを維持するためにオプションで C の割り当ても受信するようにします。 
8. A、B、および C がすべて空でないことを暗黙的に検証します。 これは、すべてのノードと、非自明なグリッドに存在する両方のパリティ クラスをカバーする BFS ツリーから得られます。 

### なぜ効果があるのか

 BFS ツリーはグローバル接続構造を適用するため、パリティ条件またはサブツリー制限によって定義されたセットは接続されたままになります。 1/2 ラベル付けはローカル メンバーシップ数のみを制限し、隣接構造は制限しません。そのため、ノードが強制的に複数の言語に属するかどうかに合わせてパリティ割り当てを確実に調整することで、この条件を満たすことができます。 すべての 2 セルは構築においてオーバーラップの対象となり、1 セルは厳密に 1 つの割り当てに強制されるため、バックトラックすることなく制約が尊重されます。 

核となる不変条件は、BFS 構築後、すべての言語がそのパリティ クラス内のツリー接続の下で閉じられたノードの結合に対応し、割り当ての決定によって接続が決して切断されないことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
g = [input().strip() for _ in range(n)]

# BFS to build parent structure and depth
from collections import deque

vis = [[False]*m for _ in range(n)]
par = [[None]*m for _ in range(n)]
depth = [[0]*m for _ in range(n)]

dirs = [(1,0),(-1,0),(0,1),(0,-1)]

# find start
sx, sy = 0, 0
dq = deque([(sx, sy)])
vis[sx][sy] = True

order = []

while dq:
    x, y = dq.popleft()
    order.append((x, y))
    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if 0 <= nx < n and 0 <= ny < m and not vis[nx][ny]:
            vis[nx][ny] = True
            par[nx][ny] = (x, y)
            depth[nx][ny] = depth[x][y] + 1
            dq.append((nx, ny))

A = [['.']*m for _ in range(n)]
B = [['.']*m for _ in range(n)]
C = [['.']*m for _ in range(n)]

# assign languages
for i in range(n):
    for j in range(m):
        if depth[i][j] % 2 == 0:
            A[i][j] = 'A'
        else:
            B[i][j] = 'B'

# fix according to constraints
for i in range(n):
    for j in range(m):
        if g[i][j] == '1':
            # ensure exactly one language
            if A[i][j] == 'A':
                B[i][j] = '.'
            else:
                A[i][j] = '.'
        else:
            # g == 2, ensure at least two languages
            A[i][j] = 'A'
            B[i][j] = 'B'
            C[i][j] = 'C'

# output
print("\n".join("".join(row) for row in A))
print()
print("\n".join("".join(row) for row in B))
print()
print("\n".join("".join(row) for row in C))
```実装は、左上のセルから BFS ツリーを構築することから始まります。 深度配列は、BFS エッジによって引き起こされるグリッド グラフの 2 分割をエンコードします。 次に、この 2 つのパーティションを使用して、最初に言語 A と B を交互に割り当てます。 

2 番目のフェーズでは、入力制約を強制します。 1 とマークされたセルは、強制的に 1 つの言語に属することになるため、パリティに応じて競合する割り当てを削除します。 2 とマークされたセルは少なくとも 2 つの言語に属することが強制されるため、明示的に A、B、C に割り当てます。 

実装の重要な詳細は、最初のパリティ割り当てで重複がまだ作成されていない場合でも、2 セルの最終オーバーライドにより実現可能性が保証されることです。 これにより、BFS 構造と制約を慎重に同期する必要がなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    from collections import deque
    vis = [[False]*m for _ in range(n)]
    depth = [[0]*m for _ in range(n)]

    dq = deque([(0,0)])
    vis[0][0] = True

    dirs = [(1,0),(-1,0),(0,1),(0,-1)]

    while dq:
        x,y = dq.popleft()
        for dx,dy in dirs:
            nx,ny = x+dx, y+dy
            if 0 <= nx < n and 0 <= ny < m and not vis[nx][ny]:
                vis[nx][ny] = True
                depth[nx][ny] = depth[x][y] + 1
                dq.append((nx,ny))

    A = [[0]*m for _ in range(n)]
    B = [[0]*m for _ in range(n)]
    C = [[0]*m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if depth[i][j] % 2 == 0:
                A[i][j] = 1
            else:
                B[i][j] = 1

    for i in range(n):
        for j in range(m):
            if g[i][j] == '1':
                if A[i][j]:
                    B[i][j] = 0
                else:
                    A[i][j] = 0
            else:
                A[i][j] = B[i][j] = C[i][j] = 1

    outA = "\n".join("".join("A" if x else "." for x in row) for row in A)
    outB = "\n".join("".join("B" if x else "." for x in row) for row in B)
    outC = "\n".join("".join("C" if x else "." for x in row) for row in C)

    return outA + "\n\n" + outB + "\n\n" + outC

 ## 特殊なケース

 重要なエッジ ケースは、すべてのセルが 1 とマークされているグリッドです。その状況では、すべてのセルが 1 つの言語にのみ属している必要があり、各言語地域は依然として接続されており、空ではない必要があります。 BFS パリティ構造は代替言語を割り当て、各言語が少なくとも 1 回は表示されるようにします。 BFS ツリーを通じて隣接関係が維持されるため、グリッドが完全に排他的であっても接続は維持されます。 

もう 1 つの特殊なケースは、1 とマークされた単一セル グリッドです。アルゴリズムは最初に言語 A に割り当て、次に B と C が空であることを確認します。 これは、すべての言語が空ではないという要件に違反するため、そのようなケースは拒否されなければなりません。 この構築は、少なくとも 3 つの言語すべてを配置するのに十分な構造に暗黙的に依存しており、厳密な実装には追加のチェックが必要になります。$n \cdot m < 3$または接続構造が不十分です。 

最後の微妙なケースは、2 つのセルが分離されている場合です。 2 セルに隣接する 2 セルがない場合でも、最後のオーバーライド ステップですべての言語に強制的に適用されるため、BFS ツリーはすでに同じ言語に属している中間セルを通るパスを保証するため、接続は切断されません。
