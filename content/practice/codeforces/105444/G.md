 ## 解決策
 ## 問題の理解

 私たちは書かれた順に一連の曲を与えられます。 各曲にはラベルがあり、ラベルは 1、2、または 3 のいずれかです。有効な「セットリスト」を形成するこれらの曲の連続した部分の数を数えたいと考えています。 

有効なセットリストは、元のリストから順に取得されたサブシーケンスであり、3 つの構造上の制約があります。 最初に選択した曲にはラベル 1 が必要で、最後に選択した曲にはラベル 3 が必要で、その間のすべての曲にはラベル 2 が必要です。セットリストには少なくとも 3 つの曲が含まれている必要があります。したがって、その間に少なくとも 1 つの 1、少なくとも 1 つの 3、および少なくとも 1 つの 2 が含まれている必要があります。 

これはすべてのサブ配列にわたるカウントの問題ですが、構造は非常に厳格です。すべての有効なセットリストは、1 を含む開始位置と 3 を含む終了位置を選択することによって完全に決定されます。ただし、それらの間のすべてが 2 のみであるという要件があります。 

n が 10^6 までの制約により、エンドポイントのペアの O(n^2) または O(n^2) の列挙が直ちに除外されます。 O(n log n) 個の解であっても許容されますが、不要です。 この構造は、リニア スキャン ソリューションが可能であることを示唆しています。 

すべてのペア (l, r) を試してセグメントが有効かどうかをチェックする単純なアプローチでは、内部チェックが繰り返し再計算され、n = 10^6 で壊滅的に失敗します。 

内部を効率的に検証せずに 1 と 3 のエンドポイントのペアのみをチェックしようとすると、さらに微妙な失敗ケースが発生します。 たとえば、入力では

 1 2 3 1 3

 ペア (1, 3) は中央が 2 であるため有効ですが、(1, 4) は中央に 3 が含まれているため無効です。内部検証を無視する単純なエンドポイント ペアリング アプローチではオーバーカウントになります。 

## アプローチ

 ブルートフォースの考え方は簡単です。考えられるすべてのインデックスのペア (l、r) を考慮し、l から r まで有効なセットリストを形成できるかどうかを確認します。 これには、a[l] = 1、a[r] = 3 であり、それらの間のすべての要素が 2 であることを検証する必要があります。内部チェックがプレフィックス情報で最適化されている場合でも、すべてのペアを反復処理すると、最悪の場合でも O(n^2) のコストがかかります。 n = 10^6 では、これは完全に不可能です。 

重要な観察は、有効なセグメントの構造により、すべての内部要素が 2 になるように強制されるということです。これは、有効なセグメントは、ブロックの直前に 1 があり、ブロックの直後に 3 がある、2 の最大連続ブロック内にのみ存在できることを意味します。 したがって、任意の部分配列について考える代わりに、問題を 1 + (1 つ以上の 2) + 3 の形式のパターンを数えることに縮小します。ここで、2 は元の配列で連続領域を形成します。 

このように配列を表示すると、1 回スキャンして、連続する 2 のストレッチを追跡し、そのようなストレッチごとに、その直前に 1 がいくつ出現するか、その直後に 3 がいくつ出現するかをカウントできます。 (1、2 ブロックの開始、2 ブロックの終了、3) の各選択は、正確に 1 つの有効なセットリストに寄与し、これらの寄与を効率的に集約できます。 

これにより、問題が線形カウントのオーバーランに変わり、内部セグメントの繰り返しスキャンが回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 実行ベースのカウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を 1 回スキャンし、概念的に同じ値の連続に圧縮しますが、それらを明示的に保存する必要はありません。

1. 値 2 の最大の連続セグメントを特定しながら、配列を反復処理します。そのような各セグメントは、有効なセットリストの「中間領域」の候補です。 これが重要なのは、有効なセットリストはすべての内部要素が 2 に等しい必要があり、2 以外の境界を越えることができないためです。 
2. 2 の連続ブロックごとに、開始 1 に有効な選択肢がいくつ存在するかを数えます。これは、このブロックのすぐ左側にある連続する 1 の数です。有効なセグメントの開始は、元の順序では 2 ブロックの直前に位置する 1 でなければならないためです。 1 をさらに遠ざけると、セグメント内に 2 以外の値が強制されます。 
3. 同様に、終わりの 3 に有効な選択肢がいくつあるかを数えます。終わりの 3 は 2 ブロックの直後になければならないため、これは 2 ブロックのすぐ右にある連続する 3 の数です。 
4. 特定の 2 ブロックによって提供される有効なセットリストの数は、これら 2 つのカウントの積です。これは、左側の選択肢 1 がそれ​​ぞれ右側の選択肢 3 と独立してペアになり、すべての組み合わせで必要な構造が維持されるためです。 
5. この積を 2 ブロックすべてにわたって累積し、結果のモジュロ 10^9 + 7 を取得します。 

### なぜ効果があるのか

 有効なセットリストは、すべての内部要素が 2 である構造を持っている必要があります。これにより、選択したセグメントの内部全体が、配列内の 2 の連続する 1 つの範囲内に収まるようになります。 そのランが修正されると、その直前に連続する 1 がいくつ出現するか、およびその直後に連続する 3 がいくつ出現するかによってエンドポイントが決定されます。 ギャップや不一致を導入すると、内部に 2 のみが表示されるという制約が破られるため、他の位置は有効な境界を形成できません。 これにより、各 2 回の実行からの独立した寄与への分解が完全かつ重複しなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # Precompute prefix counts of consecutive 1s ending at i
    left_ones = [0] * n
    if a[0] == 1:
        left_ones[0] = 1
    for i in range(1, n):
        if a[i] == 1:
            left_ones[i] = left_ones[i - 1] + 1
    
    # Precompute suffix counts of consecutive 3s starting at i
    right_threes = [0] * n
    if a[-1] == 3:
        right_threes[-1] = 1
    for i in range(n - 2, -1, -1):
        if a[i] == 3:
            right_threes[i] = right_threes[i + 1] + 1
    
    ans = 0
    
    i = 0
    while i < n:
        if a[i] != 2:
            i += 1
            continue
        
        j = i
        while j < n and a[j] == 2:
            j += 1
        
        left_count = left_ones[i - 1] if i > 0 else 0
        right_count = right_threes[j] if j < n else 0
        
        if left_count and right_count:
            ans = (ans + left_count * right_count) % MOD
        
        i = j
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、各位置で 1 の連続がどのくらいの長さで終了するか、および各位置で 3 の連続がどのくらいの長さで始まるかをキャプチャする 2 つのヘルパー配列を構築します。 これらにより、任意の 2 ブロックの周囲に有効な開始および終了の選択肢がいくつ存在するかに定時アクセスできます。 

次に、配列全体をスキャンし、2 の連続したセグメントを飛び越えます。 このようなセグメントごとに、すぐに左右を調べて、有効な 1-start と 3-end がいくつ存在するかを判断します。 これらのカウントを乗算すると、そのブロックの寄与が求められます。 

よくある落とし穴は、隣接しない 1 または 3 の参加を誤って許可してしまうことです。 連続した実行カウントを使用すると、境界に隣接する値のみが考慮されるようになります。 

## 実用的な例

 ### 例 1

 入力:```
1 1 1 2 2 2 3 3 3
```各インデックスで終わる連続 1 と各インデックスで始まる連続 3 を計算します。 

唯一の 2 ブロックはインデックス 3 から 5 までです。 

| ステップ | 2 ブロック (i, j) | left_count (1 秒前) | right_count (3 秒後) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | (3, 5) | 3 | 3 | 9 |

 2 のブロックは 3 つの 1 と 3 つの 3 で囲まれているため、3 × 3 = 9 個の有効なセットリストが得られます。 

これにより、最初の 3 つの位置から開始 1 を選択し、最後の 3 つの位置から終了 3 を選択するすべての組み合わせで、2 ブロック全体にわたる有効なセグメントが生成されることが確認されます。 

### 例 2

 入力:```
1 2 1 2 3 1 2 3
```インデックス 1、インデックス 3、およびインデックス 6 の 2 つの 2 ブロックを特定します。 

| ステップ | 2ブロック | 左数 | 右数 | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | (1, 1) | 1 | 0 | 0 |
 | 2 | (3, 3) | 1 | 1 | 1 |
 | 3 | (6, 6) | 1 | 1 | 1 |

 少なくとも左側の 1 つと右側の 1 つ 3 で適切に囲まれたブロックのみが寄与します。 合計は2です。 

これは、孤立した 2 または不適切に配置された 2 は、正しく括弧内に収まらない限り、何も寄与しないことを示しています。

 ## 特殊なケース

 主なエッジ ケースは、2 ブロックが配列の境界にある場合です。 のような入力の場合```
2 2 2 1 3 3
```2 ブロックの直前には有効な 1 がないため、left_count はゼロになり、寄与は追加されません。 アルゴリズムは範囲外のインデックス i - 1 から left_count を計算するため、このブロックを正しく無視します。 

もう 1 つのケースは、複数の 2 ブロックが存在するが、一部のみが適切に括弧で囲まれている場合です。```
1 2 3 2 2 3
```最初の 2 ブロックは 1 × 1 に寄与し、2 番目のブロックも 1 × 1 に寄与します。 スキャンは 2 以外の境界ごとにリセットされ、二重カウントやブロック間混合が発生しないようにするため、それぞれが独立して処理されます。
