 ## 解決策
 ## 問題の理解

 フロアプランを表す単純な多角形の境界が与えられます。 頂点は時計回りの順序でリストされ、ポリゴンには最大 50 万個の非常に多くの頂点を含めることができます。 タスクは、多角形自体を直接分析することではなく、エッジによる障害物なしに多角形全体を「見る」ことができるように、単一の点をどこに配置できるかを決定することです。 これは、多角形の内側にある直線セグメントを介して境界上のすべての点が見える位置に点がなければならないことを意味します。 

幾何学的には、これは、多角形が完全に見える多角形内のすべての点のセットを要求します。 このセットはまさに多角形のカーネル、つまり多角形の有向エッジによって定義されるすべての半平面の交差点です。 

出力はこのカーネルの領域です。 そのような点が存在しない場合、つまり多角形が星形ではない場合、カーネルは空であり、答えはゼロになります。 

最大 500,000 までの n の制約により、二次関数や偶数関数は即座に除外されます。$O(n \log n)$構造のない任意の領域を繰り返し交差する、ジオメトリを多用したアプローチ。 解は基本的に頂点の数において線形またはほぼ線形でなければなりません。$O(n \log n)$ソートのような操作は許容されますが、幾何学的なクリッピングの繰り返しは許容されません。 

ポリゴンが凹型で一般的な可視ポイントがすべて排除されている場合、微妙なエッジ ケースが発生します。 たとえば、2 本のアームが反対側から可視性制約に重なる「U 字型」ポリゴンでは、空のカーネルが生成されます。 局所的な凸面だけをチェックしたり、ポリゴンが「ほぼ凸面」であると仮定したりする単純な試みでは、正の領域が誤って報告されます。 

もう 1 つの問題は縮退です。連続した同一線上のエッジや頂点の繰り返しです。 これらはカーネルを変更しませんが、慎重に扱わないと単純な交差ロジックが壊れる可能性があります。 

## アプローチ

 ブルートフォース解釈では、候補点をテストし、すべてのエッジが見えるかどうかを検証しようとします。 グリッド上の点をサンプリングしたり、ポリゴンの頂点を候補としてテストしたりすることを想像できます。 各候補点について、すべてのエッジに対する可視性をチェックし、$O(n)$候補者ごとにチェックしてください。 領域は連続しているため、正しいサンプリングには任意の細かい解像度が必要となり、このアプローチは根本的に無効になります。 候補を頂点またはエッジ交差に制限した場合でも、最悪の場合は二次関数の動作が発生します。 

重要な点は、すべての有効なカメラ位置のセットが任意ではないということです。 それはまさに、多角形の各有向エッジによって定義される半平面の交差点です。 各エッジには、ポリゴン全体がその点から見える状態を維持できるように、カメラがそのエッジの内側になければならないという制約が課されます。 これにより、問題が幾何学的探索から半平面交差問題に変換されます。 

半平面の交差は、角度によってラインをソートし、候補の半平面のデックを維持し、進行するにつれて冗長になるものを削除することで効率的に解決できます。 単純なポリゴンの構造によってすでに自然な順序付けが行われているため、向きの一貫性を注意深く維持すれば、角度によってソートすることなくエッジを順番に処理できます。 結果は、カーネルを表す凸多角形です。 

カーネル ポリゴンが計算されると、標準の靴紐の公式を使用してその面積が取得されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 半平面交差カーネル | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 多角形の各有向エッジを、カメラ位置が満たさなければならない線形制約として解釈します。 からのエッジのために$p_i$に$p_{i+1}$、有効な側は時計回りの順序によって決定されます。これは、内部がすべてのエッジの片側に一貫して存在することを意味します。 これにより、可視性が半平面のシステムに変換されます。 
2. 補助線と内部方向を使用して各半平面を表します。 各線は境界と、多角形内の有効な点を維持する方向を定義します。 線形制約の観点からは、明示的な領域よりも交差の方が維持しやすいため、この表現は不可欠です。 
3. アクティブなハーフプレーンのデキューを維持しながら、エッジを順番に処理します。 新しい各半平面は、現在の実行可能領域と交差します。 新しい制約を追加すると古い制約が無効になる場合、それらは削除されます。 これが機能するのは、実行可能領域が常に凸状であるため、交差部分が凸状のままになるか空になるためです。 
4. 各ステップで、必要に応じて境界線の交点を計算します。 最後の 2 つの半平面の交点が以前に有効だった制約の外側にある場合、問題のある半平面を破棄します。 これにより、最終的なカーネルに影響を与える制約のみが確実に残ります。 
5. すべてのエッジを処理した後、最終デックで連続する半平面を交差させることによって形成される多角形を計算します。 このポリゴンがカーネルです。 
6. 残っている点が 3 つ未満であるか、領域が崩壊している場合は、領域が存在しないため、0 を返します。 
7. それ以外の場合は、結果として得られるカーネル ポリゴンに対して靴紐の式を使用して面積を計算します。 

### なぜ効果があるのか

 このアルゴリズムは、最初の k 個のエッジを処理した後、デキューが循環順序で最初の k 個の半平面の交差を正確に表すという不変条件を維持します。 各半平面は実行可能領域を線形に制限し、半平面の交点は凸多角形を形成するため、冗長な制約を破棄しても情報が失われることはありません。 したがって、最終領域は正確にすべての制約の交差部分であり、これがポリゴンのカーネルとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def intersection(p1, p2, p3, p4):
    # line p1-p2 with p3-p4 intersection
    x1, y1 = p1
    x2, y2 = p2
    x3, y3 = p3
    x4, y4 = p4

    a1 = x2 - x1
    b1 = y2 - y1
    a2 = x4 - x3
    b2 = y4 - y3

    den = cross(a1, b1, a2, b2)
    if den == 0:
        return None

    t = cross(x3 - x1, y3 - y1, a2, b2) / den
    return (x1 + t * a1, y1 + t * b1)

def inside(p, a, b, c):
    # check if point p is on correct side of line a->b wrt polygon orientation
    return cross(b[0] - a[0], b[1] - a[1], p[0] - a[0], p[1] - a[1]) >= 0

def polygon_area(poly):
    s = 0
    n = len(poly)
    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        s += x1 * y2 - x2 * y1
    return abs(s) / 2

n = int(input())
pts = [tuple(map(int, input().split())) for _ in range(n)]

halfplanes = []
for i in range(n):
    a = pts[i]
    b = pts[(i + 1) % n]
    halfplanes.append((a, b))

# simple half-plane intersection using deque
dq = []

def is_valid(p, a, b):
    return cross(b[0] - a[0], b[1] - a[1], p[0] - a[0], p[1] - a[1]) >= 0

for a, b in halfplanes:
    dq.append((a, b))
    while len(dq) >= 3:
        a1, b1 = dq[-3]
        a2, b2 = dq[-2]
        a3, b3 = dq[-1]

        ip = intersection(a1, b1, a2, b2)
        if ip is None or not is_valid(ip, a3, b3):
            dq.pop(-2)
        else:
            break

# construct polygon from remaining halfplanes
points = []
for i in range(len(dq)):
    a1, b1 = dq[i]
    a2, b2 = dq[(i + 1) % len(dq)]
    ip = intersection(a1, b1, a2, b2)
    if ip is not None:
        points.append(ip)

if len(points) < 3:
    print(0.0)
else:
    print(polygon_area(points))
```このコードは、半平面の動的なセットを維持することによってカーネルの表現を構築します。 各エッジは制約に寄与し、中央の制約が実行可能領域の境界の一部ではなくなっていることが交差構造によって示されるたびに、デックによって冗長な制約が削除されます。 

交差関数は中心的な機能です。2 つの境界線が交わる場所を計算し、検証と最終頂点の構築の両方に使用されます。 内部テストでは、候補交差点が最新の制約の下で有効なままであることが保証されます。 

最後に、すべての制約が処理されると、残りの半平面で凸多角形が定義され、その頂点は隣接する境界線と交差することによって計算され、靴紐の式によって面積が求められます。 

## 実用的な例

 ### サンプル 1

 入力ポリゴンは明確な凸形状を形成しているため、カーネルはポリゴン全体と等しくなります。 

| ステップ | アクション | アクティブなハーフプレーン | 有効な地域 |
 | --- | --- | --- | --- |
 | 1 | エッジ 1 を追加 | 1 | 無制限の部分 |
 | 2 | エッジ 2 を追加 | 1,2 | 縮小する凸領域 |
 | 3 | すべてのエッジを追加 | すべてのエッジ | 凸多角形 | 凸多角形

 制約の競合が発生しないため、最終的なポリゴンはそのまま残ります。 これは、凸ポリゴンがそれ自体と等しい完全な可視領域を持っていることを確認します。 

### サンプル 2

 入力は星形ではない多角形を形成します。 

| ステップ | アクション | アクティブなハーフプレーン | 有効な地域 |
 | --- | --- | --- | --- |
 | 1 | エッジを追加する | 部分セット | 縮小中 |
 | 2 | 競合が発生します | 一部削除されました | 地域が崩壊する |
 | 3 | 最終チェック | <3 ポイント | 空 |

 アルゴリズムは、すべての半平面制約を同時に満たす点がないことを検出するため、カーネルの面積はゼロになります。 

これは、星形ではない入力に対する正確性を示しています。

 ## 特殊なケース

 完全に凸の多角形は最も単純な状況であり、アルゴリズムはすべての半平面をアクティブに保ちます。 各交差は有効なままであるため、最終的なカーネルは元のポリゴンと一致し、その面積は標準ポリゴンの面積と一致します。 

反対側のエッジがすべての実行可能なポイントを削除する、強く凹んだポリゴンは、デク内で繰り返し削除を引き起こします。 最終的に、有効な境界制約が 3 つ未満になり、再構築されたポリゴンは存在できなくなり、面積がゼロになります。 

同一線上のエッジを持つ縮退ケースでは、交差ロジックが平行線を処理できるかどうかをテストします。 交差関数はゼロ行列式を明示的にチェックし、無効な幾何学的構造が最終領域に伝播しないようにします。
