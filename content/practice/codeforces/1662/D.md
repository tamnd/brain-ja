 ## 解決策
 ## 問題の理解

 アルファベットの上に 2 つの DNA 文字列が与えられています`{A, B, C}`。 目的は、一連の操作を使用して最初の文字列を 2 番目の文字列に変換できるかどうかを判断することです。 各操作では部分文字列が挿入または削除されます。これらの編集で許可される部分文字列は次のとおりです。`AA`、`BB`、`CC`、`ABAB`、 そして`BCBC`。 

重要な解釈は、これらの操作が文字列の等価関係を定義するということです。文字列内の任意の場所でこれらの固定パターンを繰り返し追加または削除することによって一方を他方に変えることができる場合、2 つの文字列は等価です。 タスクは、指定された 2 つの文字列が同じ同値クラスに属しているかどうかを確認することです。 

制約は小さく、各文字列の長さは最大 200、テスト ケースの数は最大 100 です。 これにより、すべての変異配列に対する指数関数的な検索が即座に排除されます。 操作ごとにすべての部分文字列に対する三次シミュレーションでさえ、すでに限界に近づいており、変換のシーケンスを直接調査することは実行不可能です。 

難しいのは、演算を適用することではなく、その演算の下でどのような構造が不変のままであるかを理解することです。 

最初の微妙なエッジ ケースは、文字列が「ローカル」と思われる再配置によってのみ異なる場合です。たとえば、`ABAB`なる`A`あるいは完全に消滅する。 素朴な解釈では、順序が保持されるか、ローカルなキャンセルのみが発生すると想定するかもしれませんが、次のような操作は行われません。`ABAB`2 つのタイプにまたがる 4 つの文字を削除でき、その直感を打ち破ることができます。 

もう 1 つの重要なケースは、文字列が空になる可能性があることです。 例えば、`AA`削除できるので、`AA`は空と同等です。 長さのパリティや文字数だけで実現可能性が決まると仮定する不用意なアプローチは、次のような場合に失敗します。`ABAB`、消えることもあります。 

最後に、次のような操作に注意してください。`ABAB`そして`BCBC`文字を混ぜます。 これは、各文字が独立して進化するという素朴な考えを破壊します。 

## アプローチ

 ブルートフォース解釈では、許可されたパターンの挿入と削除を適用することによって、到達可能なすべての文字列に対するグラフ検索として問題を扱います。 各状態は文字列であり、遷移は任意の部分文字列を変更します。 

単一の長さの文字列から`n`、 がある`O(n)`位置と最大 5 つのパターン タイプを挿入または削除でき、各操作により多くの重複する結果が生成される可能性があります。 分岐要素は急速に増大し、到達可能な文字列の数は指数関数的に増加します。 メモ化しても、状態空間はすべて 3 文字で長さ 200 までの文字列であり、これは天文学的に大きくなります。 

重要な観察は、許可されたすべての操作が可逆的かつローカルであること、そしてさらに重要なことに、それらの操作は隠された正規化構造を保持していることです。 各パターンは、同一の文字のペアを削除するか、サイクル内の 2 つの隣接する文字を含む交互のブロックを削除します。`A-B-C`。 これは、このシステムが、特定の隣接するパターンのみが重要となる、縮小された形式のキャンセル ルールに関連していることを示唆しています。 

重要な単純化は、このプロセスが、ローカル隣接制約によって制御されるスタックのようなキャンセルを使用して文字列を繰り返し削減することと同等であることを認識することです。 完全な縮小後、各文字列は正規表現にマップされ、縮小された形式が一致する場合に限り、2 つの文字列は同等になります。 

これにより、問題はグラフの到達可能性から文字列の正規化に変わります。

 ## アルゴリズムのチュートリアル

 各文字列を個別に処理し、スタックを使用して正規の縮小形式に変換します。 

1. 現在の文字列の空のスタックを初期化します。 スタックは、現在の縮小されたプレフィックスを表します。 
2. 文字を左から右にスキャンします。 
3. 現在の文字をスタックにプッシュします。 
4. プッシュするたびに、スタックの最上部が、許可された操作によって誘発された近くの構造と除去可能なパターンを形成しているかどうかを繰り返し確認します。 
5. キーリダクションは、パターンに対応する隣接する等しい文字または交互の構造によってトリガーされます。`ABAB`そして`BCBC`。 
6. スタックの最上位で有効なパターンが検出されると、それを削除し、新しい最上位から再度チェックを続けます。 
7. 文字列全体を処理した後のスタックは標準形式になります。 
8. 両方の文字列の正規形式を比較します。 同一の場合はYESを出力し、同一の場合はNOを出力します。 

重要な部分はステップ 4 と 5 で、ここでは隣接する重複だけでなく交互のペアも削減されます。 スタック メカニズムにより、削除後に新たに公開されたパターンも確実にチェックされるため、有効な削減が見逃されることはありません。 

### なぜ効果があるのか

 許可される操作は、グローバル構造に依存しないローカル等価性を定義します。 各削除パターンでは、最小限の還元可能なフラグメントが削除されます。 操作のシーケンスは、縮小された境界位置にパターンが現れるとすぐに削除が行われるように順序を変更できます。 これにより、演算の順序に関係なく、最終的な既約形式が固有になります。 スタック シミュレーションでは、まさにこの貪欲な正規化が強制され、すべての削減可能な構成が削除され、不変の構造のみが残ることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reduce_string(s: str) -> str:
    st = []
    
    def bad():
        if len(st) < 2:
            return False
        a, b = st[-2], st[-1]
        return a == b

    def bad2():
        if len(st) < 4:
            return False
        a, b, c, d = st[-4], st[-3], st[-2], st[-1]
        return a == c and b == d and a != b

    for ch in s:
        st.append(ch)
        changed = True
        while changed:
            changed = False
            if len(st) >= 2 and st[-1] == st[-2]:
                st.pop()
                st.pop()
                changed = True
                continue
            if len(st) >= 4 and st[-4] == st[-2] and st[-3] == st[-1]:
                st.pop()
                st.pop()
                st.pop()
                st.pop()
                changed = True

    return "".join(st)

def solve():
    t = int(input())
    for _ in range(t):
        u = input().strip()
        v = input().strip()
        if reduce_string(u) == reduce_string(v):
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装はスタックを維持します`st`現在の縮小された文字列を表します。 新しい文字がそれぞれ追加され、削除可能なパターンがないか繰り返しチェックされます。 

最初の条件は削除します`AA`、`BB`、 または`CC`隣接する等しい文字を検出することによって。 2 番目の条件は、次の形式の長さ 4 のブロックを交互に削除します。`ABAB`または`BCBC`または`CACA`適切に制限されている場合。 状態`st[-4] == st[-2] and st[-3] == st[-1]`この交互構造を捉えています。 

このループは、各挿入後に削減ができなくなるまで継続し、カスケード削除が正しく処理されるようにします。 

最後に、両方の文字列が正規化されて比較されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline

    def reduce_string(s: str) -> str:
        st = []
        for ch in s:
            st.append(ch)
            changed = True
            while changed:
                changed = False
                if len(st) >= 2 and st[-1] == st[-2]:
                    st.pop()
                    st.pop()
                    changed = True
                    continue
                if len(st) >= 4 and st[-4] == st[-2] and st[-3] == st[-1]:
                    st.pop(); st.pop(); st.pop(); st.pop()
                    changed = True
        return "".join(st)

    t = int(input())
    out = []
    for _ in range(t):
        u = input().strip()
        v = input().strip()
        out.append("YES" if reduce_string(u) == reduce_string(v) else "NO")
    return "\n".join(out)

 ## 特殊なケース

 のような文字列`AA`即時キャンセルを示します。 スタックがプッシュする`A`、それからもう一つ`A`、ペア削除ルールをトリガーし、空のスタックを残します。これは、次の考えと一致します。`AA`何もしないのと同じです。 

のために`ABAB`、スタックは次のように進化します。`A → AB → ABA → ABAB`の場合、交互ルールによって完全な 4 文字パターンが検出され、完全に削除されます。 最終結果は空であるため、他の完全に縮小可能な文字列と一致します。 

で`AABBCC`、削減はローカルで発生します。`AA`まず消えて、それから`BB`、 それから`CC`。 スタックはグローバルな推論を必要とせず、各キャンセルによって次のキャンセルが公開され、操作の局所性が文字列を完全に正規化するのに十分であることが確認されます。
