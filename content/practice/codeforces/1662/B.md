 ## 解決策
 ## 問題の理解

 それぞれが名前を表す 3 つの文字列が与えられます。 各文字列を、再構築する必要がある複数の文字セットとして考えてください。 

弊社では「シート」の製作をさせていただいており、シートの両面に2文字ずつ書かれております。 名前を綴るときに、各シートの片面を選択し、選択したすべての文字を任意の順序で配置するという意味で、シートは再利用可能です。 ただし、3 つの名前すべてに同じ物理シートを使用する必要があります。名前ごとに異なる場合があるのは、シートごとの面の選択のみです。 

したがって、各シートには名前ごとに 1 文字が含まれており、両面から名前ごとに独立して選択されます。 (X, Y) というラベルの付いたシートがある場合、3 つの単語のいずれかについて、そのシートはどちらの側を選択するかに応じて X または Y のいずれかに寄与します。 

タスクは、シートの数を最小限に抑え、シートごとに 1 つの文字を選択することで 3 つのターゲット単語のそれぞれを形成できるように、シートへの文字の割り当てを構築することです。 

制約 |t|、|o|、|r| ≤ 1000 は、サポートする必要がある文字の合計数が最大 3000 であることを意味します。これにより、超指数関数的なものや、三次的な動作を伴う大規模な構造間のマッチングが含まれるものは直ちに排除されます。 周波数カウントに基づく線形または線形に近い構造で十分です。 

微妙な点は、1 つのシートが 3 つの単語すべてに同時に寄与しますが、単語ごとに独立していることです。 これにより、問題は各シートに文字のペアを割り当てることと同等になり、すべてのシートにわたって各文字列の文字マルチセットが正確にカバーされるようになります。 

よくある失敗例は、グローバルな周波数の調整を無視して文字を貪欲に一致させようとした場合に発生します。 

たとえば、文字列間で文字をペアごとにのみ一致させる場合、再利用を過小評価する可能性があります。 

入力:

 t = "AA"、o = "AB"、r = "AC"

 単純なアプローチでは、不一致ごとに個別のシートが必要だと考えるかもしれませんが、実際には、慎重に設計された 1 つのシート セットですべての要件を同時にカバーできます。 

もう 1 つの特殊なケースは、すべての文字列が同一である場合です。 理想的には、すべてのシートの両面に同じ文字が含まれている必要があります。そうでないと、柔軟性が無駄になります。 

## アプローチ

 この問題を考える強引な方法は、各シートを個別に検討し、考えられるすべての文字のペアを試し、3 つの文字列すべてを満たすことができるかどうかをシミュレートすることです。 各シートには 26×26 の可能性があり、最大 1000 枚のシートが必要になる可能性があるため、天文学的に大きな検索スペースが必要となり、これは完全に不可能になります。 

重要な洞察は、文字ごとの需要の観点から問題を再解釈することです。 各シートは、その両側から選択された各文字列に 1 つの文字を提供します。 つまり、各シートは 3 つの文字列にわたる文字のパーティションを定義することになります。文字列ごとに、2 つの文字のうち 1 つを選択します。 

シートごとに考えるのではなく、文字ごとに考えます。 各文字について、すべてのシートにわたって、各文字列に対してこの文字を選択できる十分な「スロット」があることを確認する必要があります。 各シートは文字列ごとに 1 つの選択肢を提供するため、自然な貪欲な構造により、各シートが 2 文字を担当し、すべてのシートが文字列間の不一致を満たすのに役立ちます。 

最適な構築は、文字列全体で貪欲に文字をペアにすることで実現します。可能な限り同じ位置に文字を配置します。 3 つの文字列すべてを同時に走査する場合、文字が一致するたびに同じシートを再利用しようとします。 それ以外の場合は、一方の側が 1 つの文字列を満たし、もう一方の側が別の文字列を満たすように、異なる文字を接続するシートを導入します。 

これにより、オーバーラップを最大化しながらすべての位置をカバーするペアのセットを構築するという問題が軽減されます。

## アルゴリズムのチュートリアル

 文字列を位置的に処理し、シートを段階的に構築します。 

1. 3 つの文字列をインデックスで整列し、各位置の文字を比較します。 3 つの文字がすべて同じである場合は、両面がその文字に等しいシートを作成します。 これは、必要のない柔軟性を導入することなく、1 つのシートですべての単語の位置を完全に満たすため、最適です。 
2. 正確に 2 つの文字が一致し、1 つが異なる場合は、共通の文字と奇数の文字を組み合わせたシートを作成します。 共通の文字が一方の側に配置され、異なる文字がもう一方の側に配置されます。 これにより、シートは奇数文字側を選択することで異なる文字列を提供し、共通側を選択することで他の文字列を提供することができます。 
3. 3 つの文字がすべて異なる場合は、このポジションの要件をカバーするために 2 つのシートを作成する必要があります。 1 枚のシートで 2 人のキャラクターが接続され、2 番目のシートでそのうちの 1 人が 3 番目のキャラクターと接続されます。 これにより、シートあたり 2 文字の制約を維持しながら、各文字列が必要な文字を個別に選択できるようになります。 
4. 3 つの文字列の最大長になるまで、すべての位置に対してこのプロセスを続けます。 文字列が短い場合、欠落している位置は無関係なものとして扱われ、それらの位置に対する制約には影響しません。 

これが機能する理由は、各インデックスを処理した後、構築されたシートを使用してその位置のすべての要件がローカルで満たされるという不変条件に基づいています。 各シートはすべての単語に独立して寄与し、文字間の直接的な接続を導入することによってすべての不一致が解決されるため、全体的な競合が蓄積することはありません。 すべての構築ステップでは、文字列ごとに有効なサイド選択を割り当てる機能が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    o = input().strip()
    r = input().strip()

    n = max(len(t), len(o), len(r))

    sheets = []

    for i in range(n):
        a = t[i] if i < len(t) else None
        b = o[i] if i < len(o) else None
        c = r[i] if i < len(r) else None

        letters = [x for x in [a, b, c] if x is not None]

        if len(letters) == 0:
            continue

        if len(set(letters)) == 1:
            ch = letters[0]
            sheets.append(ch + ch)

        elif len(set(letters)) == 2:
            # find majority and minority
            from collections import Counter
            cnt = Counter(letters)
            common = max(cnt, key=cnt.get)
            for ch in cnt:
                if ch != common:
                    diff = ch
            sheets.append(common + diff)

        else:
            # all three different
            sheets.append(letters[0] + letters[1])
            sheets.append(letters[0] + letters[2])

    print(len(sheets))
    for s in sheets:
        print(s)

if __name__ == "__main__":
    solve()
```このソリューションは各インデックスを反復処理し、文字のトリプルを分類します。 すべてが同一の場合、簡単なセルフペアシートが作成されます。 2 つが一致すると、多数派の文字と少数派の文字がペアになり、少数派の文字列が必要な文字を選択できるようになります。 すべてが異なる場合、競合は 2 つのペアごとの制約に分解されます。 

主要な実装の詳細は、欠落している位置を空文字ではなく欠落として扱うことで、さまざまな文字列長を安全に処理することです。 もう 1 つの微妙な点は、「2 つの異なる文字」の場合に少数文字が正しく抽出されるようにすることです。これは、誤った多数派の選択によって無効なカバレッジが生じるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from contextlib import redirect_stdout
    out = io.StringIO()

    def solve():
        t = sys.stdin.readline().strip()
        o = sys.stdin.readline().strip()
        r = sys.stdin.readline().strip()

        n = max(len(t), len(o), len(r))
        sheets = []

        for i in range(n):
            a = t[i] if i < len(t) else None
            b = o[i] if i < len(o) else None
            c = r[i] if i < len(r) else None
            letters = [x for x in [a, b, c] if x is not None]
            if not letters:
                continue
            if len(set(letters)) == 1:
                sheets.append(letters[0] * 2)
            elif len(set(letters)) == 2:
                from collections import Counter
                cnt = Counter(letters)
                common = max(cnt, key=cnt.get)
                diff = [x for x in cnt if x != common][0]
                sheets.append(common + diff)
            else:
                sheets.append(letters[0] + letters[1])
                sheets.append(letters[0] + letters[2])

        print(len(sheets))
        for s in sheets:
            print(s)

    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

 ## 特殊なケース

 特殊なケースの 1 つは、すべての文字がある位置で異なる場合です。 アルゴリズムはこれを 2 つのシートに分割し、各文字列が引き続き有効な選択を取得できるようにします。 A、B、C のような入力の場合、AB と AC が生成されます。 次に、A は 1 つの文字列の両方のシートで利用可能であり、B と C は直接カバーされているため、各文字列は必要な文字を個別に選択できます。 

もう 1 つのケースは、A、A、B のように、2 つの異なる文字のみが表示されるが不均等に分布している場合です。多数決ベースの構造によりシート AB が確保され、B 文字列が B を選択し、他の文字列が A を選択することができます。 

すべての文字が同一の場合、構造は繰り返しの AA シートに縮退します。これは、柔軟性が必要なく、すべてのシートを競合することなくすべての文字列にわたって完全に再利用できるため、最適です。
