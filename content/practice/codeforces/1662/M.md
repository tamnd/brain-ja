 ## 解決策
 ## 問題の理解

 の列を構築する必要があります`n`ワインボトル。 各ボトルは赤（`R`) または白 (`W`）。 

すべての批評家は、内容が要求されたペアと一致するボトルの連続したセグメントを見つけたいと考えています。`(r, w)`、 どこ`r`は赤いボトルの数、そして`w`はそのセグメント内の白いボトルの数です。 批評家が異なれば、選択するセグメントも異なる可能性があります。 私たちのタスクは、要求されたすべてのペアが少なくとも 1 つの連続した間隔のカラー カウントとして表示されるようにする単一の配置を構築することです。 

長さの調整が無い場合`n`すべてのリクエストを同時に満たすことができるため、印刷する必要があります`IMPOSSIBLE`。 

制約は小さいです。 両方`n`そして`m`せいぜい`100`。 これは、すべての可能な長さまたはすべての可能な色数にわたる高価な列挙が実行可能であることを直ちに示唆しています。 残っているのは、構築を容易にするのに十分な探索スペースを削減する構造観察を見つけることです。 

微妙な点は、批評家が音程の位置を指定していないことです。 一定の間隔内に赤と白のボトルが何本出現するかを指定するだけです。 間隔が存在する限り、後で自由に間隔を選択できます。 

リクエストを検討してください`(3, 2)`。 批評家は長さ 5 の特定のセグメントを求めているわけではありません。 ちょうど 3 つの赤いボトルと 2 つの白いボトルが含まれる間隔は許容されます。 

もう 1 つの簡単な間違いは、間隔の長さがリクエストによって固定されていることを忘れていることです。 お願い`(r, w)`一定の長さの間隔が必要です`r + w`。 もし`r + w > n`、要求は決して満たされません。 

例えば：```
n = 4
request = (3, 2)
```必要な間隔の長さは次のとおりです。`5`、しかし、全体の配置には4つのボトルしか含まれていません。 正しい答えは、`IMPOSSIBLE`。 

2 番目の自明ではないケースは、リクエストが 1 つの色だけを要求する場合に発生します。```
n = 3
requests:
(0, 2)
(0, 3)
```アレンジメント`WWW`長さ 2 と 3 の間隔には、必要な数の白いボトルが正確に含まれているため、機能します。 

すべての有効な間隔に両方の色が含まれている必要があると主張する不用意な解決策は、このケースを誤って拒否することになります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての長さの文字列が生成されます。`n`そして、すべてのリクエストがその間隔内に出現するかどうかを確認します。 あるので`2^n`可能な文字列の場合、中程度の値であってもこれは不可能になります。`n`。 

重要な観察は、リクエストに実際にどのような情報が含まれているかを調べることから得られます。 

お願い`(r, w)`次の 2 つの数量のみを考慮します。 

1. インターバルの長さ`L = r + w`。 
2. その間隔内の赤いボトルの数。 

いくつかの赤いボトルの後にいくつかの白いボトルが続く文字列を構築するとします。```
RRRR...RWWWW...W
```赤いボトルの総数を`R`。 

任意の間隔の長さを考慮する`L`。 

長さのスライディングウィンドウとして`L`が左端から右端に移動すると、ウィンドウ内の赤いボトルの数が徐々に変化します。 から始まります`min(R, L)`そしてで終わります`max(0, L - (n - R))`。 

さらに、その範囲内のすべての整数値が表示されます。 

したがって、赤いボトルの合計数が一定である場合、`R`、リクエスト`(r, w)`次の場合にのみ実現可能です。```
L = r + w <= n
```そして```
max(0, L - (n - R)) <= r <= min(R, L)
```これが重要な単純化です。 

任意の配置を構築する代わりに、値を選択するだけで済みます。`R`間`0`そして`n`。 一度`R`決まった、アレンジメント```
R repeated R times
W repeated (n - R) times
```は、すべての間隔の長さで達成可能なすべての赤カウントをすでに実現しています。 

あるのは`n + 1`可能な選択肢`R`、最大でも`101`。 

各候補値を単純にテストできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | すべての文字列を列挙する | O(2^n · n²) | O(n) | 遅すぎる |
 | すべての赤の合計カウントを試してください | O(nm) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 可能な数の赤いボトルごとに`R`から`0`に`n`、からなる配置を考えてください。`R`赤いボトルに続いて`n - R`白いボトル。 

2. リクエストごとに`(r, w)`、必要な間隔の長さを計算します。```
   L = r + w
   ```3. もし`L > n`、このリクエストはアレンジメント内に収まりません。 この値を拒否します`R`。 

4. 任意の長さの区間における赤いボトルの最小可能数を計算します。`L`:```
   low = max(0, L - (n - R))
   ```これは、間隔が白い領域にできるだけ押し込まれると発生します。 

5. 任意の長さの区間における赤いボトルの最大可能数を計算します。`L`:```
   high = min(R, L)
   ```これは、間隔が赤い領域にできるだけ押し込まれると発生します。 

6. 要求された赤数が以下を満たしているかどうかを確認します。```
   low <= r <= high
   ```そうでない場合は、この値を拒否します`R`。 

7. すべてのリクエストが成功すると、次のように出力されます。```
   "R" * R + "W" * (n - R)
   ```8. の値がない場合は、`R`作品、出力`IMPOSSIBLE`。 

### なぜ効果があるのか

 赤いボトルの 1 つのブロックとそれに続く白いボトルの 1 つのブロックで構成される文字列では、固定長のすべての間隔が連続部分で赤いブロックと交差します。 

間隔がスライドするにつれて、赤いボトルの数は各ステップで最大 1 つずつ変化します。 したがって、考えられる赤のカウントは、達成可能な最小値から達成可能な最大値までの完全な整数間隔を形成します。 

の公式`low`そして`high`それらの極端さを正確に説明します。 

要求は、要求される赤のカウントがその間隔内にある場合に正確に満たされます。 両端の間のすべての整数が発生するため、追加の条件は必要ありません。 

すべての値をテストする`R`赤いブロックのあらゆるサイズを調べます。 この特別な形式の有効な配置が存在する場合、アルゴリズムはそれを見つけます。 建設的な観察は、解決策が存在する場合には常にそのような取り決めが存在することを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, m = map(int, input().split())
        req = [tuple(map(int, input().split())) for _ in range(m)]

        found = None

        for R in range(n + 1):
            ok = True

            for r, w in req:
                L = r + w

                if L > n:
                    ok = False
                    break

                low = max(0, L - (n - R))
                high = min(R, L)

                if not (low <= r <= high):
                    ok = False
                    break

            if ok:
                found = "R" * R + "W" * (n - R)
                break

        if found is None:
            answers.append("IMPOSSIBLE")
        else:
            answers.append(found)

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```実装は数学的特徴付けに直接続きます。 

外側のループでは、可能な数の赤いボトルをすべて試します。 内部ループは、その選択に対してすべての批評家のリクエストを検証します。 

の公式`low`そして`high`自明ではない唯一の部分です。 これらは、長さの間隔によって取得可能な最小および最大の赤カウントをエンコードします。`L`次の形式の文字列内:```
RRR...RWWW...W
```間隔の列挙は必要ありません。 

構造自体は、単純に赤いボトルの接頭辞とそれに続く白いボトルの接尾辞です。
