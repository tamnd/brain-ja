 ## 解決策
 ## 問題の理解

 私たちはサッカーの試合でキックが行われる一連の瞬間を与えられており、各キックはタッチラインに沿った決まった時間と決まった位置で行われます。 時間ゼロでは、位置ゼロから開始し、その後、制限された速度でラインに沿って継続的に移動することができます。 それぞれのキックが行われるとき、私たちはそれを注意深く観察できる位置にいる場合とそうでない場合があります。つまり、その時点で、動きの制約の下で到達可能なすべての位置の中で、私たちの位置がキックの位置にできるだけ近い場合にのみ成功します。 

課題は、時系列で「カバー」するキックのサブセットを選択し、この最適な意味で観察できるキックの数を最大化することです。 選択した 2 つのキックの間の動作は、最大速度を考慮して物理的に実行可能でなければなりません。 

重要な問題は、観察条件によって、選択されたキックの瞬間に正確に最適になることが強制されることです。これは、事実上、選択された各キックの時点で、そのキックの座標に正確に位置していなければならないことを意味します。これは、到達可能な場合、いかなる偏差も厳密に近い位置を許容するためです。 

入力サイズは最大 200,000 イベントです。 すべてのキックのペアにわたる二次またはわずかに超線形の動的計画法は遅すぎます。 どの解も線形または n log n に近いものでなければなりません。 

貪欲な戦略がローカルで到達可能なすべてのキックを選択すると、微妙な失敗のケースが発生します。 たとえば、キックにかろうじて到達できるが、それによって将来の多くのキックがブロックされる場合、貪欲は失敗する可能性があります。これは、先に到着するか遅く到着することで将来の到達可能性がさらに高まる可能性があることを無視するためです。 

大きな時間差により長時間の移動が可能になる場合、別の特殊なケースが発生します。 単純な実装では、時間差によるスケーリングを行わずに位置の差だけを比較し、ステップごとの動きが一定であると誤って仮定する可能性があります。 

## アプローチ

 ブルートフォース手法では、キックごとに、以前に選択されたキックの後にそのキックで終了できるかどうかを計算しようとします。 i < j のキック i と j のすべてのペアについて、時間 t_j - t_i 内に a_i から a_j に移動できるかどうかを確認します。 可能であれば、i で終わる最適なチェーンを j に拡張しようとします。 これにより、すべてのペアにわたる動的プログラミング遷移が発生します。これは O(n^2) であり、200,000 イベントでは通過しません。 

重要な観察は、2 つのキック間の実行可能性の条件は時間差と位置差のみに依存し、単調な到達可能性制約を形成するということです。 考えられるすべての以前の選択を追跡する代わりに、各位置について、その時点でその位置に到達するための最適な方法を維持できます。 ただし、連続した位置にわたって完全な状態を保存することはできません。 

代わりに、到達可能性制約の下で最長のチェーンとして問題を再定式化します。つまり、連続して選択された各ペアが速度制約を満たすようなキックのサブシーケンスが必要です。 これは構造的に、 |a_i - a_j| の場合にのみエッジが存在する DAG 内の最長パスに似ています。 ≤ v · (t_j - t_i)。 直接グラフは高密度ですが、時間の順序付けにより、実行可能なフロンティアをスライドさせて動的プログラミングを行うことができます。 

重要な単純化は、各キック j について、j に到達できる以前に選択されたキック i が存在するかどうかを知る必要があるだけであり、その中でチェーンの長さを最大にするキック i が必要であることです。 これは、時間の経過とともに到達可能な間隔を貪欲に伝播し、状態を単一の最良候補フロンティアに縮小することによって維持できます。 

基本的に、選択した各キックの後に可能な限り最良の「カバレッジ状態」を維持し、その状態から到達可能かどうかに基づいて次のキックを含めるかどうかを決定します。 到達可能な場合は更新します。 それ以外の場合はスキップして続行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのペアに対するブルート フォース DP | O(n^2) | O(n) | 遅すぎる |
 | 最適な貪欲な到達可能性 DP | O(n) | お(1) | 承認済み |

## アルゴリズムのチュートリアル

 時間の増加順にキックを処理します。 

1. 最後に選択されたキック インデックスとこれまでに選択されたキックの数からなる現在の最良の状態を維持します。 最初はキックが選択されていないため、時間 0 での最後の位置は 0 になります。 
2. 時系列順の各キック i について、現在の状態から到達可能かどうかをテストします。 これは、t_i - current_time の時間内に現在位置から a_i に移動できるかどうかを確認することを意味します。 
3. 到達可能であれば、このキックを行うことにします。 現在の状態を更新して、時刻 t_i に位置 a_i にいることを反映し、答えをインクリメントします。 
4. 到達できない場合は、このキックをスキップし、現在の状態を変更しないようにします。 
5. すべてのキックが処理されるまで続けます。 

微妙な部分は、将来の到達可能性を最大化するという観点から、現在の状態が常に最良の位置であるため、「現在の状態から到達可能」で十分であるということです。 より柔軟な代替パスは、より早く到着するか、より近い位置に到着する必要があり、それがすでに維持された状態を支配することになります。 

### なぜ効果があるのか

 アルゴリズムは常に、将来の到達可能性にとって最適な、選択された最新のキック時間での実行可能な位置を表す単一のフロンティア状態を維持します。 動作の制約は時間的に線形であり、距離において対称であるため、より早く終了する、または異なる位置で終了するその他の実行可能なシーケンスは、まずこのフロンティアを改善することができなければ、将来の選択肢を厳密に改善することはできません。 したがって、貪欲な受け入れ基準は、後で厳密に大きなカウントにつながる可能性のあるシーケンスを決して破棄しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, v = map(int, input().split())
    t = list(map(int, input().split()))
    a = list(map(int, input().split()))

    # current state: time, position, count
    cur_t = 0
    cur_x = 0
    ans = 0

    for i in range(n):
        dt = t[i] - cur_t
        dist = abs(a[i] - cur_x)

        if dist <= v * dt:
            ans += 1
            cur_t = t[i]
            cur_x = a[i]

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、単一の進化可能な実行可能な状態を維持します。 変数`cur_t`最後に受け入れられたキックの時間を追跡し、`cur_x`キック後に私たちが立っている位置を追跡します。 受信イベントごとに、最後に受け入れられたイベント以降に移動できた距離を計算し、それを必要な変位と比較します。 

よくある実装の落とし穴は、キックが行われたときだけ時間を更新するのを忘れることです。 最後に受け入れられた時刻の代わりにグローバル時刻を使用すると、スキップされた間隔での移動が誤って許可されるため、実行可能性チェックが中断されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各キックは定数時間演算で 1 回処理されます。 
| スペース | お(1) | 現在の時刻、位置、カウンターのみが保存されます。 

このソリューションは、200,000 のイベントが単一の線形パスで処理され、補助的なデータ構造が存在しないため、制約内に簡単に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, v = map(int, sys.stdin.readline().split())

 ## 特殊なケース

 エッジ ケースの 1 つは、時間ギャップが十分に大きく、複数の位置リセットが可能な場合です。 たとえば、キックがスキップされた場合、アルゴリズムはそのスキップされた間隔からの動きを誤って蓄積してはなりません。 状態は受け入れられたキックでのみ更新されるため、スキップされた間隔は、位置に影響を与えることなく、次の実行可能性チェックに自然に時間に寄与します。 

もう 1 つのエッジ ケースは、ポジションが左端と右端が交互になる場合です。 条件`abs(a[i] - cur_x) <= v * (t[i] - cur_t)`必要な距離は時間とともに直線的に増加し、サイドの切り替えには十分な累積時間を必要とするため、不可能な発振を正確に防止します。 

最後の微妙なケースは、複数のキックのタイミングが非常に近い場合です。 アルゴリズムはこれを正しく処理します。`dt`が小さくなり、制限された速度の物理的制約に一致する位置も近い場合を除き、ほとんどのトランジションが実行不可能になります。
