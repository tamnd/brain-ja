 ## 解決策
 ## 問題の理解

 私たちは持っています`n`丸いテーブルに座っている人々、番号が付けられている`1`に`n`。 最初の着席は自然な順序です`[1, 2, 3, …, n]`テーブルの周りを時計回りに。 希望の座席順序を順列形式で与えられます`p`。 私たちのタスクは、許可されるスワップの最小数を使用してこの順列に到達することです。 交換は隣り合って座っている 2 人の間でのみ発生します。ただし、人物を交換することはできないという制限があります。`x`と`x+1`のために`1 ≤ x ≤ n-1`。 「禁止された隣接関係」を越える唯一のスワップは個人間のものです`n`そして人`1`テーブルが円形だから。 

入力では複数のテスト ケースを指定します。 それぞれについて、私たちは受け取ります`n`そして長さの順列`n`。 出力は、目的の循環順序に到達するための最小スワップ数です。 

制約が教えてくれるのは`n`最大 200,000 までの値になる場合があります。`n`すべてのテスト ケースの上限は 200,000 です。 これにより、テスト ケースごとに O(n) よりも複雑なソリューションが効果的に排除されます。 各人を個別に移動するには O(n²) 回の操作が必要になる可能性があるため、スワップの単純なシミュレーションは実行できません。 エッジ ケースは、目的の順列が恒等順列の回転バージョンである場合、または数値が降順である場合に発生します。 不注意なシミュレーションでは、テーブルの循環的な性質や禁止されたスワップを無視して、スワップを誤ってカウントする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、スワップを直接シミュレートすることです。 から始まる`[1, 2, …, n]`、許可されたスワップのみを使用して、各人をターゲットの位置にバブリングしようとします。 スワップは可逆的であり、間の循環スワップにより任意の順列に到達できるため、この方法は正しいです。`1`そして`n`。 ただし、最悪の場合、要素を個別に移動するには O(n²) 操作が必要となり、これでは遅すぎます。`n`200,000まで。 

最適な解決策を見つけるための重要な洞察は、テーブルを順列サイクルの問題として見ることです。 させて`pos[i]`人の現在のインデックスになります`i`。 人は誰しも、前任者と比べて相対的な立場にありたいと考えています。 交換はできないので`x`そして`x+1`、ターゲットの順列内のすべての増加する連続シーケンスはすでに「交換できない」ルールを遵守しており、内部の並べ替えは必要ありません。 したがって、問題は、最長の連続した増加サブシーケンス (ラップアラウンドあり) を特定し、それに対して順序が狂っている要素の数を計算することに帰着します。 この順序にない各人物は、許可されたラップアラウンド スワップのみを使用して移動する必要があります。ラップアラウンド スワップは、シミュレーションではなく算術的にカウントできます。 

この観察により、明示的なスワップ シミュレーションを回避することで、複雑さが O(n²) から O(n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列について`p`、配列を構築します`pos`どこ`pos[i]`人のインデックスです`i`で`p`。 これにより、ターゲットの順列内の任意の 2 人の人物の相対位置をすばやく確認できます。 
2. すべての人々を横断します。`1`に`n-1`そして、最長の連続増加シーケンスの長さを計算します。`p`これは元の番号付けを尊重します。 具体的には、`i`2から`n`、 もし`pos[i] > pos[i-1]`、次に人`i`の後に正しく配置されます`i-1`順列の中で。 そうでない場合は、連続したシーケンスが終了します。 維持する`max_len`最長のシーケンスを保存します。 
3. 必要なスワップの最小数は次のとおりです。`n - max_len`。 これは、最長連続増加サブシーケンスでは内部でのスワップが不要であり、残りの各人は許可されたスワップを使用して所定の位置に移動する必要があるためです。 
4. 各テストケースの結果を出力します。 

これが機能する理由は、各交換では一度に 1 人しか正しいシーケンスに移動できないためです。 最大の既に順序付けされたシーケンスを特定することにより、必要なスワップの数を最小限に抑えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        pos = [0] * (n + 1)
        for i, x in enumerate(p):
            pos[x] = i
        max_len = 1
        cur_len = 1
        for i in range(2, n + 1):
            if pos[i] > pos[i - 1]:
                cur_len += 1
                max_len = max(max_len, cur_len)
            else:
                cur_len = 1
        print(n - max_len)

if __name__ == "__main__":
    solve()
```ソリューションは最初に構築されます`pos`、各人をその位置にマッピングします。 これは、連続する数値をチェックする際の定数検索にとって重要です。 それから追跡します`cur_len`インデックスの増加、更新`max_len`必要に応じて。 最後の引き算`n - max_len`最小スワップ数が直接得られます。 Off-by-one エラーはインデックス作成によって回避されます`pos`1 から始まり、すべての算術演算では整数インデックスが使用されるため、オーバーフローの心配はありません。

 ## 特殊なケース

 完全に逆の順列の場合`[n, n-1, ..., 1]`、アルゴリズムは正しく検出します`max_len = 1`そして出力`n - 1`交換します。 すでにソートされている順列の場合`[1, 2, ..., n]`、`max_len = n`そして出力は`0`。 次のようなローテーションの場合`[3, 1, 2]`、最長の連続増加シーケンスは、位置に応じて長さ 1 または 2 として正しく識別され、出力は最小スワップ数と一致します。 このアルゴリズムは、置換インデックス内ですでに昇順になっている要素のみをカウントするため、本質的に禁止された隣接関係を考慮します。
