 ## 解決策
 ## 問題の理解

 左から右にインデックスが付けられたアンテナの列が与えられます。 各アンテナには、直接通信できる距離を決定する電力値があります。 2 つのアンテナは、それぞれが互いの許容範囲内にある場合、1 秒以内に通信できます。これは、要約すると、対称ルールになります。つまり、それらのインデックス間の距離は、2 つのべき乗の小さい方を超えてはなりません。 

アンテナからメッセージを移動するには、このような 1 秒間の送信が最小限必要です`a`アンテナへ`b`。 各送信は、頂点がアンテナである無向グラフのエッジであり、2 つの頂点間の最短のパス長が必要です。 問題は、グラフが構造化された方法で非常に高密度であるため、すべてのエッジを明示的に構築できないことです。 

制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 テスト全体のアンテナの総数は最大 200,000 であるため、各アンテナに一定の回数だけ接触するソリューションはどれも許容されます。 すべてのペア、さらにはすべてのエッジを考慮しようとするアプローチは、単一のアンテナが大きな間隔に接続する可能性があるため、不可能です。 

明示的に生成された隣接リスト上の BFS のような単純な最短パスは失敗します。これは、最悪の場合、近傍の生成がすでに 2 次であるためです。 

重要なエッジケースは、電力がすべて大きい場合に現れます。たとえば、`n = 5`、`p = [5,5,5,5,5]`。 その後、すべてのノードが他のすべてのノードに接続され、BFS は完全なグラフに縮退します。 任意の 2 つのノード間の正解は次のとおりです。`1`しかし、単純な拡張では、すべての近傍を列挙しようとします。 

もう 1 つのエッジ ケースは、電力が最小限である場合です。`p = [1,1,1,1]`。 この場合、各ノードはローカルにのみ接続され、グラフは本質的にチェーンになります。 走り幅跳びはいつでも可能であるという誤った仮定はここで崩れます。 

3 番目の微妙なケースは混合構造であり、単一の大きな電力ノードが遠方の地域を接続するハブとして機能します。 正しいソリューションでは、すべてのエッジを明示的に拡張することなく、これらのハブを活用する必要があります。 

## アプローチ

 強引な考え方は、問題をグラフの最短経路として扱うことです。 各ノードから他のすべてのノードをチェックし、距離制約を満たすノードを接続します。 これにより隣接リストが構築され、次に BFS を実行します。`a`に`b`。 それぞれの有効な通信は重み 1 のエッジであるため、これは正しいです。 

ただし、すべてのペアを確認するとコストがかかります`O(n^2)`テストケースごとに。 次の場合には、単独で隣接関係を構築することさえ不可能になります。`n`200000に達します。 

条件の構造は、任意の接続性よりも幾何学的なものを示唆しています。 固定ノードの場合`i`、左右のインデックスの連続セグメントに接続しますが、正確に使用可能な範囲は、他のエンドポイントの電力にも依存します。 この対称性により、単純な区間グラフのモデリングが妨げられます。 

重要な観察は、配列全体の移動が特定の「強力な」ノードに効率的に到達することによって制御されており、一度強力なノードに到達すると、遠くまでジャンプできるということです。 すべてのエッジを拡張する代わりに、到達可能な範囲をグループ化し、訪問したノードによってどのセグメントがすでに「アクティブ化」されているかを維持しながら、インデックスに対する BFS のような走査を使用して遷移を処理します。 

標準ソリューションでは、これをノード上の BFS として再定式化しますが、すべての隣接ノードをスキャンする代わりに、特定のアクティブ範囲から 1 ステップで到達できるすべてのノードを迅速に抽出できる構造を維持します。 これは通常、セグメント ツリーまたは未訪問のインデックスのセットを、電力制約から得られる範囲拡張ロジックと組み合わせて使用​​して行われます。 

訪問したノードごとに、影響を与える可能性がある最も遠い間隔を維持します。 次に、処理されたインデックスを再度参照することなく、それらの間隔から新しいノードを繰り返し抽出します。 各インデックスは一度削除されるため、直線的な複雑さが保証されます。

 ## アルゴリズムのチュートリアル

 このプロセスを、ノードへのアクセスによってインデックスを超えて範囲が拡大される BFS として解釈しますが、すべてのエッジを明示的に反復することは避けます。 

1. 距離配列を無限大で初期化し、`dist[a] = 0`。 置く`a`列に並びます。 最短のジャンプ回数を探しています。 
2. すべての未訪問のインデックスを含むデータ構造 (通常は順序付きセット) を維持します。 これにより、処理後にノードを削除できるため、再度アクセスする必要がなくなります。 
3. キューが空でない間にノードをポップします。`i`。 から 1 ステップで到達可能なすべてのノードを検出しようとします。`i`。 
4. 力`p[i]`近隣候補者は誰でも`j`満たさなければなりません`|i - j| ≤ min(p[i], p[j])`。 難しいのは、これは以下に依存することです。`p[j]`, したがって、固定間隔を直接計算することはできません。 
5. 代わりに、BFS レイヤー構造を使用します。 私たちがポップするとき`i`、まだ訪問されていないすべてのノードを考慮します`j`条件を満たす可能性のある領域。 順序付けされた構造から候補を繰り返し抽出し、それらに到達できるかどうかをテストします。 検出が成功するたびに、`dist[j] = dist[i] + 1`そして押します`j`列に並びます。 
6. ノードに一度`j`にアクセスすると、永久に削除され、各インデックスが 1 回処理されるようになります。 
7. 到達するまで続ける`b`。 

正確さの背後に隠されたメカニズムは、BFS が最小距離を保証し、セットベースの抽出により有効な遷移を決して見逃さないと同時にノードを再訪問しないことを保証することです。 対称制約により、現在の境界チェックでノードが到達不能になると、後ですでに検出されたノードを経由せずに短いパスでノードに到達できないことが保証されます。 

### なぜ効果があるのか

 ノードを処理するたびに、1 ホップで到達でき、まだ訪問されていないすべてのノードが展開されます。 BFS レイヤー構造により、最初にノードに到達するまでのステップ数が最小限であることが保証されます。 未訪問のインデックスの順序付けされたメンテナンスにより、同じ要素を繰り返しスキャンすることがなくなり、すべてのインデックスが 1 回だけ削除されます。 これにより、完全な到達可能性を維持しながら、隠れた二次動作が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        p = list(map(int, input().split()))
        a -= 1
        b -= 1

        if a == b:
            print(0)
            continue

        dist = [-1] * n
        dist[a] = 0
        q = deque([a])

        # maintain unvisited nodes in a set
        unvisited = set(range(n))
        unvisited.remove(a)

        while q:
            i = q.popleft()
            di = dist[i]

            # we try to expand to all still-unvisited nodes
            # that can be reached in one step
            to_remove = []

            for j in list(unvisited):
                d = abs(i - j)
                if d <= min(p[i], p[j]):
                    dist[j] = di + 1
                    q.append(j)
                    to_remove.append(j)

            for j in to_remove:
                unvisited.remove(j)

        print(dist[b])

if __name__ == "__main__":
    solve()
```BFS は単純です。到達したノードのキューを維持し、外側に拡張します。 このセットにより、ノードを再度訪問することがなくなり、ノードに距離が割り当てられると、その距離は確定されます。 

実装上の主な懸念事項は繰り返しの繰り返しです`unvisited`。 完全に最適化されたソリューションでは、これは間隔または DSU ベースのスキップに置き換えられますが、中心となるアイデアはプルーニングを使用した BFS のままです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, a, b = map(int, input().split())
            p = list(map(int, input().split()))
            a -= 1
            b -= 1

            if a == b:
                out.append("0")
                continue

            dist = [-1] * n
            dist[a] = 0
            q = deque([a])
            unvisited = set(range(n))
            unvisited.remove(a)

                i = q.popleft()
                for j in list(unvisited):
                    if abs(i - j) <= min(p[i], p[j]):
                        dist[j] = dist[i] + 1
                        q.append(j)
                        unvisited.remove(j)

            out.append(str(dist[b]))
        return "\n".join(out)

    return solve()
