 ## 解決策
 ## 問題の理解

 以下のみで構成されるバイナリ文字列が与えられます。`'a'`そして`'b'`。 すべての部分文字列について、連続する等しい文字を単一の文字に繰り返しマージします。 例えば：

-`"aaaa"`になる`"a"`-`"aabbaa"`になる`"aba"`-`"abbba"`になる`"aba"`これらのマージ後に得られた圧縮文字列が回文である場合、部分文字列は良好であると呼ばれます。 

タスクは部分文字列をリストすることではありません。 偶数の長さの適切な部分文字列がいくつあるか、奇数の長さの部分文字列がいくつあるかを数えるだけで済みます。 

文字列の長さは次のとおりです$10^5$。 部分文字列の数はすでに$O(n^2)$したがって、すべての部分文字列を個別にチェックすることは不可能です。 部分文字列ごとの線形スキャンでも、おおよその結果が得られます。$10^{10}$最悪の場合、2 秒の制限時間をはるかに超えて操作が行われる可能性があります。 ソリューションは、何らかの隠れた構造を利用し、線形時間に近い速度で実行する必要があります。 

問題の最も微妙な部分は、圧縮操作によって実際に何が変わるのかを理解することです。 

部分文字列を考慮してください`"abba"`。 

圧縮後:$$"abba" \rightarrow "aba"$$これは回文なので、部分文字列は適切です。 

ここで考えてみましょう`"abab"`。 

圧縮しても何も変わりません。$$"abab" \rightarrow "abab"$$そしてこれは回文ではありません。 

よくある間違いは、圧縮文字列全体を部分文字列ごとに計算する必要があると考えることです。 重要な観察は、バイナリ アルファベットの場合、回文条件がはるかに単純になるということです。 

1 つの繰り返し文字で構成される部分文字列を使用すると、別の簡単なトラップが発生します。 例えば：```
aaaa
```すべての部分文字列は次のように圧縮されます`"a"`、これは回文です。 圧縮文字列の形状のみに基づく解決策でも、すべての長さを正しくカウントする必要があります。 

最後のエッジケースは、次のような文字列を交互に使用することです。```
ababab
```圧縮は何も行わないため、圧縮の良さは完全に元の部分文字列に依存します。 このような場合、等しい文字の連続についての誤った仮定が露呈します。 

## アプローチ

 ブルートフォースソリューションでは、すべての部分文字列を列挙し、それを圧縮し、圧縮された結果が回文であるかどうかをテストします。 

がある$O(n^2)$部分文字列。 1 回の圧縮にかかる時間$O(n)$時間、与えること$O(n^3)$全体的な複雑さ。 いくらかの最適化を行ったとしても、すべての部分文字列を個別にチェックすることは少なくとも残ります。$O(n^2)$が遅すぎます。$n=10^5$。 

画期的な進歩は、適切な部分文字列がバイナリ アルファベットでどのように見えるかを理解することから生まれます。 

任意の部分文字列を取得します。 連続する等しい文字を圧縮すると、隣接する等しい文字がマージされてしまうため、結果は交互のシーケンスになります。 

以来`'a'`そして`'b'`存在する場合、すべての圧縮文字列は次のいずれかのようになっている必要があります。$$a,\quad b,\quad ab,\quad ba,\quad aba,\quad bab,\quad abab,\ldots$$交互のバイナリ文字列は、その長さが奇数の場合、まさに回文になります。 

例えば：$$aba,\ bab,\ ababa$$は回文ですが、$$ab,\ ba,\ abab$$そうではありません。 

次に部分文字列を見てみましょう$s[l..r]$。 

その圧縮形式は次で始まります。$s[l]$そして次で終わります$s[r]$。 

圧縮文字列は交互になるため、最初と最後の文字が等しい場合にのみ回文になります。 

つまり:

 部分文字列は、最初と最後の文字が等しい場合にのみ有効です。 

これにより、圧縮の必要性が完全になくなります。 

問題は、端点に同じ文字が含まれる部分文字列を偶数と奇数の長さに分けて数えることになります。 

位置を左から右に処理するとします。 

終了位置を固定する場合$i$、で終わるすべての適切な部分文字列$i$より早い位置から開始する必要がある$j$と：$$s[j] = s[i]$$部分文字列の長さのパリティは次のとおりです。$$(i-j+1)$$奇数の長さが発生するのは次の場合です。$i$そして$j$同じインデックスパリティを持ちます。 

偶数の長さが発生するのは、$i$そして$j$逆パリティを持ちます。 

したがって、各文字について知る必要があるだけです (`a`または`b`)、偶数の位置に出現した以前の出現の数と、奇数の位置に出現した出現の数。 

これにより、$O(n)$解決。

 | ブルートフォース |$O(n^3)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンターを 4 つ維持します。`a_even`、`a_odd`、`b_even`、 そして`b_odd`各文字と各インデックス パリティを含む処理された位置の数を格納します。 
2. 文字列を左から右にスキャンします。 

ゼロベースのインデックスを使用します。 
3. 現在のポジションについて$i$かどうかを判断します。$i$偶数または奇数です。 
4. で終わる奇数長の適切な部分文字列を数えます。$i$。 

開始位置には同じ文字が含まれ、同じパリティを持つ必要があります。$i$。 

現在のキャラクターが`'a'`そして$i$偶数である場合は追加します`a_even`。 

現在のキャラクターが`'a'`そして$i$奇数です、追加します`a_odd`。 

同じ考え方が当てはまります`'b'`。 
5. で終わる偶数長の適切な部分文字列を数えます。$i$。 

開始位置には同じ文字が含まれ、反対のパリティがなければなりません。 

現在のキャラクターが`'a'`そして$i$偶数である場合は追加します`a_odd`。 

現在のキャラクターが`'a'`そして$i$奇数です、追加します`a_even`。 

同じ考え方が当てはまります`'b'`。 
6. 単一文字の部分文字列をカウントします。 

長さ 1 のすべての部分文字列は適切であり、長さが奇数であるため、奇数の答えに 1 を追加します。 
7. 現在位置を対応するカウンターに挿入します。 

将来の部分文字列はここから始まる可能性があります。 
8. 文字列全体が処理されるまで続行します。 

### なぜ効果があるのか

 圧縮されたバイナリ文字列は常に次のように切り替わります。`'a'`そして`'b'`。 このような文字列は、最初と最後の文字が等しい場合に回文になります。 圧縮文字列の最初と最後の文字は、正確に元の部分文字列の最初と最後の文字です。 したがって、部分文字列は、その端点が等しい場合にのみ有効です。 

問題をエンドポイントの等価性に落とし込んだ後は、パリティだけで部分文字列の長さが奇数か偶数かを決定します。 同じパリティを持つ 2 つのインデックスは奇数長の部分文字列を生成し、反対のパリティは偶数長の部分文字列を生成します。 維持されるカウンターは、有効な開始点として機能する以前の位置を正確にカウントするため、すべての適切な部分文字列は、その右のエンドポイントが処理されるときに 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

even_good = 0
odd_good = 0

a_even = a_odd = 0
b_even = b_odd = 0

for i, ch in enumerate(s):
    if ch == 'a':
        if i % 2 == 0:
            odd_good += a_even
            even_good += a_odd
            a_even += 1
        else:
            odd_good += a_odd
            even_good += a_even
            a_odd += 1
    else:
        if i % 2 == 0:
            odd_good += b_even
            even_good += b_odd
            b_even += 1
        else:
            odd_good += b_odd
            even_good += b_even
            b_odd += 1

    odd_good += 1

print(even_good, odd_good)
```アルゴリズムはすべての位置を 1 回だけ処理します。 

4 つのカウンタは、インデックス パリティによって分割された各文字の以前に発生したすべての発生を表します。 位置決め時`i`に到達し、すべての適切な部分文字列は次で終わります。`i`前に出現した同じ文字から開始する必要があります。 

開始位置と終了位置が同じパリティを持つ場合、部分文字列の長さは奇数になります。 パリティが異なる場合、部分文字列の長さは偶数になります。 これにより、両方の回答を一定時間で更新できます。 

位置の 1 文字の部分文字列`i`いつも良いので、`odd_good`文字ごとに 1 回増加します。 

操作の順序が重要です。 現在のポジションをカウンターに挿入する前に、以前のポジションからの貢献を追加する必要があります。 そうしないと、現在位置自体が長さ 0 の部分文字列を誤って形成してしまいます。 

Python の整数は、およそ以下の値を自動的に処理します。$n^2$、答えは約に達する可能性があるため、これは必要です$5 \times 10^9$。

def solve():

    even_good = 0

    b_even = b_odd = 0

    for i, ch in enumerate(s):
        if ch == 'a':
            if i % 2 == 0:
                odd_good += a_even
                even_good += a_odd
                a_even += 1
            else:
                odd_good += a_odd
                even_good += a_even
                a_odd += 1
        else:
            if i % 2 == 0:
                odd_good += b_even
                even_good += b_odd
                b_even += 1
            else:
                odd_good += b_odd
                even_good += b_even
                b_odd += 1

        odd_good += 1

    print(even_good, odd_good)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    global input
    input = sys.stdin.readline

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = old_stdout
    return out.getvalue().strip()

 ## 特殊なケース

 次の入力を考えてみましょう。```
aaaa
```すべての部分文字列は次のように圧縮されます`"a"`したがって、すべての部分文字列は適切です。 このアルゴリズムは、純粋にエンドポイントの等価性を通じて部分文字列をカウントします。 すべてのエンドポイント ペアには次のものが含まれるため、`'a'`、すべての部分文字列がカウントされます。 結果は次のとおりです。```
4 6
```これは、長さ 4 の文字列の合計 10 個の部分文字列と一致します。 

ここで次のことを考えてみましょう。```
abab
```圧縮しても何も変わりません。 適切な部分文字列とは、最初と最後の文字が正確に一致する部分文字列です。 このような部分文字列は、4 つの単一文字と 2 つの長さ 3 の部分文字列だけです。 アルゴリズムは以下に到達します。```
0 6
```一致するエンドポイントを持つ偶数長の部分文字列がないためです。 

最後に次のことを考慮してください。```
abba
```文字列全体は次のように圧縮されます。`"aba"`、これは回文です。 元の文字列のみを考慮した単純な実装では、これが見逃される可能性があります。 エンドポイントの特性評価はこれを即座に処理します。最初と最後の文字は両方とも`'a'`, したがって、部分文字列は適切です。 アルゴリズムはマッチングを通じてそれをカウントします`'a'`位置での発生$0$そして$3$、偶数長の適切な部分文字列を 1 つ追加します。
