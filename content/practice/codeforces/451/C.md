 ## 解決策
 ## 問題の理解

 私たちは3つのチームが参加するサッカートーナメントを持っています。 すべてのゲームで 1 人の勝者が誕生するため、プレイされた各ゲームはいずれかのチームに 1 つの勝利をもたらします。 

後`k`試合はすでに行われているため、3 チームの正確な勝利数はわかりません。 私たちが知っている絶対的な違いは 2 つだけです。 

- チーム 1 とチーム 2 の勝利の差は`d1`。 
- チーム 2 とチーム 3 の勝利の差は`d2`。 

トーナメントには最終的に次のものが含まれます`n`合計ゲーム数。 私たちはトーナメントを完走できるかどうか知りたいのですが、結局のところ、`n`ゲームが終了すると、どのチームもまったく同じ勝利数を獲得します。 

すべてのゲームで 1 つの勝利が得られるため、全チームの最終的な勝利数は正確に次のようになります。`n`。 3 チームすべてが同点で終了しなければならない場合、各チームは次のように終了する必要があります。`n / 3`勝ちます。 これはすぐに次のことを意味します`n`3で割り切れる必要があります。 

制約は、数学的解決策が必要であることを示す最初の手がかりです。 テストケースの数が到達しました`10^5`、 そして`n`と同じ大きさにすることができます`10^12`。 ゲームをシミュレートしたり、勝ちの分布を検索したりするアプローチは不可能です。 比例する仕事をしても`k`失敗するだろう。 テストケースごとに一定時間のチェックが必要です。 

難しいのは、その差が絶対値であるということです。 知ること`|a - b| = d1`そして`|b - c| = d2`現在の勝利数を一意に決定するものではありません。 いくつかの標識構成が可能です。 

よくある間違いは、次のような単一の順序を想定することです。`a ≥ b ≥ c`。 考慮する：```
n = 6
k = 4
d1 = 1
d2 = 0
```有効な分布の 1 つは、`(2,1,1)`、有効な決勝トーナメントにつながります。 順番を確認するだけなら`a ≥ b ≥ c`、それは見つかりますが、他の場合には、唯一の有効な配置が別の順序を使用する可能性があります。 

現在最も強いチームがすでに勝利を重ねすぎている場合、別の微妙なケースが発生します。 例えば：```
n = 6
k = 3
d1 = 3
d2 = 0
```唯一可能な分布は`(3,0,0)`。 各チームは次で終了する必要があるため、`2`勝った場合、チーム 1 はすでに最終目標を超えています。 答えは`"no"`。 

3 番目のエッジケースは、可算性です。 考慮する：```
n = 4
k = 0
d1 = 0
d2 = 0
```現状は完全にバランスが取れているとはいえ、合計4勝を3チームで均等に分けることはできない。 答えは次のとおりです。`"no"`。 

## アプローチ

 ブルートフォースアプローチでは、最初の試合後の 3 チームの勝利数を再構築しようとします。`k`一致します。 それらのカウントを次のようにします`(a,b,c)`。 

次の条件を満たす必要があります。```
a + b + c = k
|a - b| = d1
|b - c| = d2
```可能な値を列挙することができます。`a`、`b`、 そして`c`、制約を確認し、残りの制約がないかどうかを確認します。`n-k`ゲームではすべてのチームのバランスをとることができます。 

すべての有効な現在の状態を直接テストできるため、これは概念的に機能します。 問題は規模だ。 以来`k`と同じ大きさにすることができます`10^12`1 つの変数の可能な値を反復処理することさえ完全に不可能です。 

重要な観察は、2 つの絶対的な差に符号を割り当てる明確な方法は 4 つしかないということです。 

チーム 2 の勝利を価値あるものにしましょう`x`。 

その場合、チーム 1 は次のいずれかでなければなりません`x+d1`または`x-d1`。 

同様に、チーム 3 は次のいずれかである必要があります。`x+d2`または`x-d2`。 

これにより、候補パターンは 4 つだけ作成されます。```
(x+d1, x, x+d2)
(x+d1, x, x-d2)
(x-d1, x, x+d2)
(x-d1, x, x-d2)
```各パターンについて、方程式は次のようになります。```
a + b + c = k
```決定する`x`ユニークに。 

取得後`(a,b,c)`、次のことを確認するだけで済みます。 

1. すべてのカウントは負ではない整数です。 
2. すでに最終目標を超えているチームはない`n/3`。 
3. 残りの試合はすべてのチームをレベルを上げるのに十分です`n/3`。 

3 番目の条件は、必要な追加勝利の合計が残りのゲーム数と正確に等しいことを確認することと同等であることがわかります。 

構成が 4 つしかないため、すべてのテスト ケースを一定時間内に解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) 以上 | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. かどうかを確認します。`n`は 3 で割り切れます。そうでない場合、最終スコアが等しいことは不可能なので、戻り値を返します。`"no"`。 
2. チームごとの最終目標勝利数を次のようにします。```
target = n / 3
```3. 4 つのサイン構成を列挙します。```
(+d1, +d2)
(+d1, -d2)
(-d1, +d2)
(-d1, -d2)
```4. 選択した構成について、次のように記述します。```
a = x + s1*d1
b = x
c = x + s2*d2
```どこ`s1`そして`s2`どちらかです`+1`または`-1`。 
5. 条件を使用する`a+b+c=k`計算する`x`。```
3x + s1*d1 + s2*d2 = k
```したがって、```
x = (k - s1*d1 - s2*d2) / 3
```6. 分子が 3 で割り切れない場合、この構成は有効な勝利数を表すことができません。 スキップしてください。 
7. 構築する`(a,b,c)`すべての値が負でないことを確認します。 
8. しましょう```
mx = max(a,b,c)
```もし`mx > target`の場合、一部のチームはすでに最終的に許可された合計を超える勝利数を獲得しています。 この設定はスキップしてください。 
9. すべてのチームを目標に到達させるために必要な勝利数を計算します。```
need = (target-a) + (target-b) + (target-c)
```10. もし`need == n-k`の場合、残りのゲームでそれらの勝利を正確に提供できるため、戻ります。`"yes"`。 
11. 4 つの構成のいずれも機能しない場合は、戻ります。`"no"`。 

### なぜ効果があるのか

 現在の順位における唯一の不確実性は、2 つの絶対的な差の方向から来ています。 すべての有効なトリプル`(a,b,c)`4 つの符号割り当てのいずれかに対応する必要があります。 

固定割り当ての場合、方程式は次のようになります。`a+b+c=k`順位を独自に決定します。 有効な配布が見逃されることはありません。 

チームがすでに最終目標を超えている場合`n/3`、後で勝利を削除する方法がないため、その構成は不可能です。 すべてのチームが最大でも目標を達成している場合、達成するために必要な正確な勝利数`(target,target,target)`は```
(target-a)+(target-b)+(target-c).
```今後の各ゲームは 1 回の追加勝利に貢献するため、この必要な合計が残りのゲーム数と等しい場合に、この構成が正確に実行可能になります。`n-k`。 

考えられるすべてのサイン割り当てが検査され、それぞれがトーナメントの制約に対して正確にチェックされるため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(n, k, d1, d2):
    if n % 3 != 0:
        return False

    target = n // 3

    for s1 in (1, -1):
        for s2 in (1, -1):
            rem = k - s1 * d1 - s2 * d2

            if rem % 3 != 0:
                continue

            x = rem // 3

            a = x + s1 * d1
            b = x
            c = x + s2 * d2

            if min(a, b, c) < 0:
                continue

            if max(a, b, c) > target:
                continue

            need = (target - a) + (target - b) + (target - c)

            if need == n - k:
                return True

    return False

def main():
    t = int(input())

    ans = []
    for _ in range(t):
        n, k, d1, d2 = map(int, input().split())
        ans.append("yes" if possible(n, k, d1, d2) else "no")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```最初のチェックでは、避けられない割り算の要件が処理されます。 もし`n`は 3 の倍数ではないため、等しい最終スコアは存在できません。 

ネストされたループは、絶対差の 4 つの可能な解釈を列挙します。 それぞれについて、合計制約によって中間値が決定されます。`x`。 結果の値が整数でない場合、その構成は実際の勝利数に対応できません。 

非ネガティブチェックにより、不可能な順位が削除されます。 後でチームから勝利を奪うことはできないため、最大値のチェックは不可欠です。 

最後の平等```
need == n - k
```残りの試合がすべてのチームを共通の目標に引き上げるのに正確に十分であるかどうかを把握します。 

すべての算術演算では整数が使用されるため、次の場合でもオーバーフローの心配はありません。`n`到達する`10^12`Python の整数には制限がないためです。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    def possible(n, k, d1, d2):
        if n % 3 != 0:
            return False

        target = n // 3

        for s1 in (1, -1):
            for s2 in (1, -1):
                rem = k - s1 * d1 - s2 * d2

                if rem % 3 != 0:
                    continue

                x = rem // 3

                a = x + s1 * d1
                b = x
                c = x + s2 * d2

                if min(a, b, c) < 0:
                    continue

                if max(a, b, c) > target:
                    continue

                need = (target - a) + (target - b) + (target - c)

                if need == n - k:
                    return True

        return False

    t = int(input())
    out = []

    for _ in range(t):
        n, k, d1, d2 = map(int, input().split())
        out.append("yes" if possible(n, k, d1, d2) else "no")

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# provided samples
assert run(
"""5
3 0 0 0
3 3 0 0
6 4 1 0
6 3 3 0
3 3 3 2
"""
) == "yes\nyes\nyes\nno\nno"

# minimum case
assert run(
"""1
3 0 0 0
"""
) == "yes"

# n not divisible by 3
assert run(
"""1
4 0 0 0
"""
) == "no"

# already perfectly balanced
assert run(

"""
) == "yes"

# large values
assert run(

999999999999 0 0 0
"""
) == "yes"

## 特殊なケース

 次のことを考慮してください。```
1
4 0 0 0
```アルゴリズムはすぐにチェックします`n % 3`。 以来`4 % 3 = 1`, 最終スコアが同じになることは不可能です。 出力は`"no"`。 現在の順位だけを推論する解決策は、このケースを誤って受け入れることになります。 

考慮する：```
1
6 3 3 0
```有効な符号割り当てを使用すると、次のようになります。```
(a,b,c) = (3,0,0)
```ターゲットは`2`。 以来`max(a,b,c)=3`、1 つのチームは、最終的な均衡状態ですでに許可されている以上の勝利を獲得しています。 アルゴリズムは構成を拒否し、出力します。`"no"`。 

考慮する：```
1
3 3 3 2
```4 つの符号割り当てすべてが検査されます。 負の勝利数を生み出すものもあれば、割り算の要件を満たさないものもあります。 現在の勝利数の有効な分布はまったく存在しません。 アルゴリズムは正しく出力します`"no"`なぜなら、報告されている違いは3試合後には発生しないからです。 

考慮する：```
1
6 4 1 0
```1 つの構成では次の結果が得られます。```
(a,b,c) = (2,1,1)
```目標を超えるチームはない`2`、ちょうど 2 つの勝利が配布されるまでに残っています。 必要な追加勝利数も`2`したがって、アルゴリズムは次のように出力します。`"yes"`。 これにより、リーダーが最終目標をまだ超えていない限り、現在のリーダーが許容されることが確認されます。
