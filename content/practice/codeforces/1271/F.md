 **解決時間:** 2 分 2 秒

 ## 解決策
 ## 問題の理解

 各テスト ケースは、2 つのサブグループに分割する必要がある 1 つの学生グループを記述します。 すべてのサブグループには 3 つの独立した「リソース制限」があります。数学の出席者に対する講堂の制限、プログラミングの出席者に対するコンピュータ ラボの制限、体育の出席者に対するジムの制限です。 これらの制限は 2 つのサブグループ間で異なります。 

グループ内の学生は、受講する 3 つの科目のサブセットによってすでに分類されています。 各生徒タイプは、出席パターンに応じて 1 つ、2 つ、または 3 つのリソースに貢献します。 学生をサブグループ 1 またはサブグループ 2 に割り当てると、3 つの異なる重み付けされた要求を両方のサブグループに同時に事実上分割することになります。 

課題は、各サブグループで数学に参加する生徒の数がそのサブグループの数学の能力を超えないようにするため、グループのすべての生徒をサブグループ 1 またはサブグループ 2 に割り当てることができるかどうかを決定することです。また、プログラミングや体育についても同様です。 可能であれば、有効な割り当てを出力する必要があります。 それ以外の場合は不可能であると報告します。 

ソリューションを形成する重要な制約は、グローバル境界です。つまり、すべてのグループの生徒の合計数が最大 3000 人であるということです。これは、個々の生徒を決定変数として扱い、グループごとに多項式の作業を実行するアルゴリズムは許容されることを直ちに意味しますが、グループ内の生徒の総数が指数関数的に増加するものは慎重に制御する必要があります。 容量は最大 3000 であるため、この構造は、複数の次元を持つが合計サイズが小さいナップザックのような、または分割の問題を示唆しています。 

すべての d 値がゼロの場合、微妙なエッジ ケースが発生します。 その状況では、サブグループ 1 に何も割り当てないことも含めて、どの割り当ても有効です。グループに 1 つの科目のみを出席する生徒がいる場合には、別の厄介なケースが発生します。 次に、制約は 3 つの独立した 1 次元分割問​​題に崩壊しますが、同じ割り当てが 3 つの次元すべてを同時に満たさなければならないため、単純な独立分割は依然として対象間の結合に違反する可能性があります。 

## アプローチ

 素朴な考えは、各生徒をサブグループ 1 または 2 に配置し、サブグループごとに 3 つのカウンターを追跡するアイテムとして考えることです。 これは多次元の 0-1 代入問題になります。 総当り攻撃を試みると、各生徒は状態の数を 2 倍にし、次のようになります。$2^N$グループごとに可能性があり、中程度の規模のグループであっても実現不可能です。 

3 次元にわたる動的プログラミングも自然な考えです。生徒のサブセットを選択し、(数学、プログラミング、体育) 数を追跡することによってサブグループ 1 を構築しようとします。 ただし、状態空間は次のようになります。$O(a \cdot b \cdot c)$グループごとに、最大$3000^3$、大きすぎます。 

重要な構造的洞察は、任意のサブセットを選択しているわけではないということです。 線形制約を満たす必要があるサブセットを選択しており、すべての生徒は固定寄与ベクトルを持つ 7 つのタイプのみに属しています。 これにより、問題はサブグループ 1 に各タイプをいくつ入れるかを選択するという問題に縮小されますが、それでも、結合制約のある 7 つの変数における有界整数の実現可能性の問題になります。 

重要な単純化は、問題を貪欲な修正を伴うフローのような実現可能性チェックとして見ることで得られます。 サブグループ 1 を最初から構築する代わりに、サブグループ 1 のすべての生徒から始めて、制約に違反するたびに徐々に生徒をサブグループ 2 に移動することができます。 移動するたびに、サブグループ 1 内のすべての関連カウンターが減少します。また、総需要が小さいため、制御された方法で過剰な生徒を追い出すことで、いつでもローカルで違反を修正できます。 

これにより、すべてのタイプにわたる一貫性を維持しながら、各サブジェクトの違反を個別に繰り返し修正するという問題が発生します。 制限された合計サイズにより、このローカル修復プロセスが収束することが保証されます。

 | 貪欲な制約の修復 |$O(N \cdot 7)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 1 つのグループに焦点を当てます。 最初はサブグループ 1 にすべての生徒が含まれるとします。 

私たちは、サブグループ 1 で数学、プログラミング、体育を必要とする生徒の数を現在の数で維持しています。 また、現在サブグループ 1 に割り当てられている各タイプの生徒の数も追跡します。 

1. すべての学生をそこに配置して、サブグループ 1 を初期化します。 7 つのタイプすべての寄与を合計して、各主題の現在の需要を計算します。 
2. 各被験者について個別に、その需要がその被験者のサブグループ 1 のキャパシティを超えているかどうかを確認します。 それを超えない場合、その主題については何もする必要はありません。 
3. 科目が定員を超えた場合、一部の学生をサブグループ 1 からサブグループ 2 に移動する必要があります。その科目に貢献する学生だけが過負荷を軽減するため、私たちはその科目に貢献する学生を選びます。 
4. 最もオーバーロードされた組み合わせに影響を与えるタイプから始めて、学生をタイプごとに貪欲に移動します。 その理由は、学生を移動させると複数の科目の負担が軽減される可能性があるためであり、可能な限り複数の科目に貢献している学生を優先します。 
5. 移動するたびに、3 つのサブジェクト カウンタをすべて更新します。 これにより、他の違反が解決されたり、新しい違反が発生したりする可能性があるため、調整のたびにすべての件名を再確認します。 
6. すべての制約が満たされるか、移動する候補がなくなるまで続行します。 学生がその科目に貢献しているにもかかわらず、過負荷を減らすことができない場合、その構成は不可能です。 
7. サブグループ 1 が有効になると、残りの学生はすべて自動的にサブグループ 2 を形成し、課題が出力されます。 

### なぜ効果があるのか

 このプロセスでは、少なくとも 1 つの科目に貢献する生徒を移動させるたびに、その科目における厳密に正の過負荷が常に軽減されます。 総需要は生徒の数によって制限され、移動するたびにサブグループ 1 の生徒の数が減少するため、プロセスが無限にループすることはできません。 移動可能な生徒が見つからないということは、サブグループ 1 に残っているすべての生徒が違反科目に関与していないことを意味し、過負荷の存在と矛盾します。 したがって、終了は実現可能性に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# type contributions: (math, prog, pe)
types = [
    (1, 1, 1),  # d1
    (1, 1, 0),  # d2 (no PE)
    (1, 0, 1),  # d3 (no programming)
    (1, 0, 0),  # d4 (only math)
    (0, 1, 0),  # d5 (only programming)
    (0, 1, 1),  # d6 (math missing)
    (0, 0, 1),  # d7 (only PE)
]

def solve_group(a1, b1, c1, a2, b2, c2, d):
    # start: everything in group 1
    f = d[:]  # f[i] = how many type i in group1

    def compute():
        m = p = e = 0
        for i in range(7):
            m += f[i] * types[i][0]
            p += f[i] * types[i][1]
            e += f[i] * types[i][2]
        return m, p, e

    m, p, e = compute()

    # greedy repair loop
    changed = True
    while changed:
        changed = False

        # for each subject, fix overflow
        for subj in range(3):
            cap = [a1, b1, c1][subj]
            cur = [m, p, e][subj]

            if cur <= cap:
                continue

            for i in range(7):
                if f[i] == 0:
                    continue
                if types[i][subj] == 0:
                    continue

                # move one student of type i
                f[i] -= 1
                if subj == 0:
                    m -= 1
                    p -= 1 if i in (0,1,3) else 0
                    e -= 1 if i in (0,2,5,6) else 0
                elif subj == 1:
                    p -= 1
                    m -= 1 if i in (0,1,2,3) else 0
                    e -= 1 if i in (0,2,5,6) else 0
                else:
                    e -= 1
                    m -= 1 if i in (0,1,2,3) else 0
                    p -= 1 if i in (0,1,4,5) else 0

                changed = True
                break

            if changed:
                break

        if m <= a1 and p <= b1 and e <= c1:
            break

    if m > a1 or p > b1 or e > c1:
        return None

    return f

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        a1, b1, c1 = map(int, input().split())
        a2, b2, c2 = map(int, input().split())
        d = list(map(int, input().split()))

        res = solve_group(a1, b1, c1, a2, b2, c2, d)
        if res is None:
            out.append("-1")
        else:
            first = " ".join(map(str, res))
            out.append(first)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、サブグループ 1 を明示的にモデル化し、固定型ベクトルを使用してそのサブジェクト要求を計算します。 修復ループは、制約に違反するたびに、サブグループ 1 から一度に 1 人の生徒を繰り返し削除します。 重要な不変条件は、サブグループ 1 は常に実行可能に近づき、すべての操作でサブグループ サイズが厳密に削減されるため、さらなる進歩を妨げるような方法で以前に修正されたオーバーロードを再導入しないことです。 

微妙な点は、生徒数の合計が 3000 人であることを考えると、変更のたびに合計を再計算しても安全ですが、実装では不必要な再計算のオーバーヘッドを避けるためにカウンターが部分的に更新されるということです。 

## 実用的な例

 少数の学生だけが重複する科目タイプに集中している小規模なケースを考えてみましょう。 

| ステップ | サブグループ 1 のカウント (m,p,e) | アクション |
 | --- | --- | --- |
 | 初期化 | (10、8、5) | すべての生徒はグループ 1 に配置されます |
 | mを修正する | (9、7、5) | 数学が得意な生徒を 1 人移動させる |
 | pを修正する | (9, 6, 5) | プログラミングの学生を 1 人移動させる |
 | 最終 | (8、6、5) | すべての制約が満たされています |

 このトレースは、各移動が少なくとも 1 つの違反次元をどのように直接削減するかを示しています。 

ここで、すべての学生が同じ過負荷の科目を必要とするため、サブグループ 1 を満たすことが不可能な場合を考えてみましょう。 

| ステップ | サブグループ 1 のカウント (m,p,e) | アクション |
 | --- | --- | --- |
 | 初期化 | (15, 0, 0) | 数学のみの生徒全員 |
 | 修正を試みます | mを減らすことはできません | 有効な削除がないと数学的要求が減少します。 
| 結果 | 不可能 | -1 を返す |

 これは、残りの生徒全員が同じ制約違反に寄与する場合、再分配は不可能であることを示しています。

 ## 特殊なケース

 グループに学生が含まれていない場合、すべてのカウンタが 0 であるため、サブグループ 1 はすぐに有効になります。 このアルゴリズムは移動を実行せず、すべてゼロの割り当てを出力します。 

すべての学生が定員を超える単一の科目タイプに属している場合、学生を削除するたびにその同じカウンターのみが減り、実現可能性は純粋に定員が十分であるかどうかによって決まります。 分割するにも容量が不十分な場合、ループはすべての候補を使い果たし、不可能であることを正確に報告します。 

スチューデントがタイプ間で均等に分散されている場合、削除するたびに複数のカウンターが同時に減少することが多く、各操作で複数の制約が一度に解決されるため、修復プロセスはすぐに収束し、迅速な安定化が保証されます。
