 ## 解決策
 ## 問題の理解

 食堂で数日間にわたる飲み物の販売を計画するように求められます。 毎日、複数の種類のドリンクがあり、それぞれの予想利益がプラスまたはマイナスになる可能性があります。 どの日でも、販売する飲み物の種類の連続したセグメントを選択する必要があります。 初日は、このセグメントは何でも構いません。 翌日のセグメントは、少なくとも 1 つのドリンク タイプで前日のセグメントと重複する必要がありますが、前日に販売されていない新しいタイプを少なくとも 1 つ含む必要があります。 目的は、一日を通しての総利益を最大化することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは日数が指定されます$n$そしてドリンクの種類$m$、続いて$n \times m$利益マトリックス。 出力はテスト ケースごとに 1 つの整数、つまりルールに基づいて達成可能な最大合計利益です。 

制約が意味するのは、$n \cdot m \le 2 \cdot 10^5$すべてのテストケースにわたって。 これは、1 日あたりの複雑さが線形より悪いアルゴリズムはすべて、$m$遅すぎるでしょう。 毎日の可能なすべての連続セグメントを考慮する単純なアプローチでは、大まかに次のことが必要になります。$O(n \cdot m^2)$セグメントを列挙するだけの操作は実行不可能です。$m$まで$2 \cdot 10^5$。 

明白ではないエッジケースには、利益がすべてマイナスになる日が含まれます。この場合、最長のセグメントを貪欲に取得すると不必要な損失が発生する可能性があり、エッジのセグメントで重複条件が満たされない可能性があります。 たとえば、初日にタイプ 2 ～ 3 が販売され、タイプ 2 を除くすべての利益がマイナスの場合、最適な選択はタイプ 2 のみを販売することですが、不注意なアルゴリズムがタイプ 3 に拡張されて全体の利益が減少する可能性があります。 

## アプローチ

 強引な解決策は、最初の日に可能なすべての連続セグメントを列挙し、その後、その後の日についてすべての有効な重複セグメントを再帰的に探索し、それらの利益を合計することです。 これにより、許可されたすべての組み合わせが試行されるため、正確性が保証されますが、複雑さは次のとおりです。$O(n \cdot m^3)$最悪の場合、すべてのセグメントの開始と終了の組み合わせをカウントし、重複をチェックします。 これは、最大の入力に対しては遅すぎます。 

重要な観察は、問題を動的プログラミング タスクとしてモデル化できるということです。 今日までの最大利益を表す DP 状態を定義しましょう$i$特定の列で終わるセグメントを選択した場合。 トランジションでは、前のセグメントの外側に少なくとも 1 つの列が重なって広がる新しいセグメントを選択する必要があります。 1 日あたりの利益のプレフィックス合計を事前計算することで、任意のセグメント合計を計算できます。$O(1)$。 残りの課題は、前日から最も重複するセグメントを効率的に見つけることです。 オーバーラップには少なくとも 1 つの共有要素のみが必要なため、セグメントを左端と右端のインデックスで表し、スライディング ウィンドウまたは 2 ポインター手法を使用して最適なトランジションを計算できます。$O(m)$1日あたり。 

ブルート フォース アプローチと最適化されたアプローチを次のように比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m^3) | O(n * m) | 遅すぎる |
 | 最適 | O(n * m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。$n$そして$m$そして$n \times m$利益マトリックス。 
2. 毎日、利益のプレフィックス合計を計算して、O(1) セグメント合計の計算を可能にします。 
3. 初日の DP アレイを初期化します。 考えられる各セグメントについて$[l, r]$、その合計を計算し、セグメント境界によってインデックス付けされた DP テーブルに格納します。 
4. 以降の日のために、2 つの配列を維持します。1 つは列またはその列より前で終了するセグメントの最大 DP 値を保存します。$j$、列以降で始まるセグメントに 1 つ$j$。 これらの配列を使用すると、すべての新しいセグメントの最適な遷移を効率的に計算できます。 
5. 当日の考えられるすべてのセグメントを繰り返します。 各セグメントについて、事前に計算された最大値を使用して、重複条件と新規列条件を満たす前日のセグメントを選択します。 現在のセグメントと選択した前日の DP 値の合計で現在の DP 状態を更新します。 
6. 全日を処理した後、テスト ケースの答えは、最終日のすべての DP 状態の最大値になります。 

不変条件は、毎日の後、重複ルールを尊重して、その日に終了する各セグメントの達成可能な最大利益を DP テーブルに保存することです。 考えられるすべてのセグメントを効率的に検討するため、最終的な最大値を超えることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        A = [list(map(int, input().split())) for _ in range(n)]

        # Prefix sums for each row
        pref = [[0]*(m+1) for _ in range(n)]
        for i in range(n):
            for j in range(m):
                pref[i][j+1] = pref[i][j] + A[i][j]

        # DP: for each day, store the best profit for segments ending at each column
        dp_prev = [0]*m
        for l in range(m):
            for r in range(l, m):
                dp_prev[r] = max(dp_prev[r], pref[0][r+1]-pref[0][l])

        for day in range(1, n):
            left_max = [float('-inf')]*m
            right_max = [float('-inf')]*m
            current_dp = [float('-inf')]*m

            left_max[0] = dp_prev[0]
            for j in range(1, m):
                left_max[j] = max(left_max[j-1], dp_prev[j])

            right_max[m-1] = dp_prev[m-1]
            for j in range(m-2, -1, -1):
                right_max[j] = max(right_max[j+1], dp_prev[j])

            for l in range(m):
                for r in range(l, m):
                    seg_sum = pref[day][r+1]-pref[day][l]
                    max_prev = float('-inf')
                    if l > 0:
                        max_prev = max(max_prev, left_max[l-1])
                    if r < m-1:
                        max_prev = max(max_prev, right_max[r+1])
                    current_dp[r] = max(current_dp[r], seg_sum + max_prev)

            dp_prev = current_dp

        print(max(dp_prev))

if __name__ == "__main__":
    solve()
```このソリューションでは、まずプレフィックスの合計を計算して、定数時間のセグメント合計の計算を可能にします。 DP テーブルには、セグメントの終了位置ごとに達成可能な最高の利益が格納されます。 新しい日ごとに、考えられる左側と右側の遷移の最大値を事前計算し、セグメントが重複ルールを遵守するようにします。 DP テーブルの更新には、現在のセグメントの利益と前日の最も有効なセグメントの組み合わせが含まれます。
