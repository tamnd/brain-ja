 ## 解決策
 ## 問題の理解

 初期の人物ラインナップが与えられ、各人物が 1 回だけ登場します。 一連のプレゼンテーションは固定された順序で実行する必要があり、各プレゼンテーションは特定の人に割り当てられます。 

各ステップで、現在列の先頭にいる人が次のスライドを渡します。 配信直後に、同じ人を取り出して列の後ろの任意の場所に挿入することができ、他のすべての人の相対的な順序は変更されません。 これがラインナップを進化させる唯一の方法です。 

問題は、各スライドに必要な人物が必要なときに正確に先頭に現れるように、これらの動きをスケジュールできるかどうかです。 

したがって、プロセスには制約があります。私たちは常に先頭の人を「消費」し、その同じ人の位置を変更できるのは、その人が話した後でのみです。 私たちは恣意的な人物を前に出させることはできません。 今話した人をリサイクルすることしかできません。 

最大の難点は、最前線での行動により、最初の順序とスピーカーのリサイクル方法によって決定される一連の暴露を強制されることです。 

制約は大きく、テスト ケース全体で n と m の合計は最大 2⋅10^5 になります。 これにより、ステップごとにリストを繰り返しスキャンまたは再構築するシミュレーションが除外されます。 O(nm) さえも超える解決策は不可能であり、O(m log n) さえも慎重に実装された場合にのみ許容されます。 意図したソリューションは線形または線形に近いものでなければなりません。 

他の人を前に循環させることで、必要な人をいつでも「待つ」ことができると仮定すると、微妙な失敗例が現れます。 たとえば、必要なシーケンスが、順序付けの制約に違反せずに到達できない方法ですでに通過した人物を要求する場合、単純な貪欲ポインタ シミュレーションでは誤って受け入れられる可能性があります。 

重要な問題は、現在のポインタに対して最初の順序で人が「追い越される」と、その人がいつ最前線に再び現れることができるかを説明する一貫した方法が必要であることを認識することです。 

## アプローチ

 ブルート フォース シミュレーションでは、人の列が明示的に維持されます。 各ステップでは、フロントを取り、必要なスピーカーと一致するかどうかを確認し、その人に対して可能なすべての挿入位置を試します。 選択を貪欲にシミュレートしたとしても、サイズ n のリストを最大 m 回更新することになり、最悪のケースでは O(nm) の動作が発生します。 

重要な点は、実際には完全なリストをシミュレートする必要がないということです。 必要なシーケンスを最初の順列と一致する方法で「消費」できるかどうかだけを知る必要があります。 

最初の順序を左から右にスキャンすることを考えてください。 このプロセスは、初期配列 a を使用して必要なシーケンス b と一致しようとしていると解釈できますが、特別なルールがあります。 a 内の位置を渡すと、以前の一致の構造が再配置による「リセット」効果を許可しない限り、その位置に戻ることはできません。 

これにより、最初の並べ替えで貪欲なマッチング プロセスが行われます。 最も古い未使用の要素を表すポインタを に保持します。 b 内の必須要素ごとに、そのポインターから開始して要素を検索します。 見つけたら先に進みます。 残りのサフィックスでそれが見つからない場合、それが表示される唯一の方法は、リサイクル可能なセグメントですでに使用されている場合であり、再起動条件が強制されます。 簡単なバージョンでは、これはさらに単純化されます。セグメントごとに複数のラップアラウンドが必要ない、繰り返される巡回スキャンのサブシーケンスとして b をシミュレートできる場合、シーケンスは有効です。 

より具体的には、a を順番に繰り返しスキャンするシミュレーションを行いますが、最初からスキャンを再開すると、少なくとも 1 つの完全なパス境界がすでに消費されているためであることを確認します。 必要な要素が現在のポインターの前にあり、まだ完全なラップを行っていない場合は、それは不可能です。

これは、要素の位置を追跡し、位置のシーケンスが減少していないことを確認することになりますが、論理的にサイクルを完了するときに、端から開始までに 1 回だけリセットが許可される点が異なります。 

したがって、各値の位置を a に保存します。 b を反復する際に、位置が厳密に増加する必要があることを強制します。 そうでない場合は、サイクル カウンタを増やして続行しますが、許可されたサイクルを超えた場合は拒否します。 

このバージョンでは、q = 0 であるため、評価は 1 回だけです。

 ## アルゴリズムのチュートリアル

 1. 辞書を作成する`pos`どこ`pos[x]`価値の指標です`x`初期配列内で`a`。 これにより、要素の検索が O(1) 操作に変換されます。 
2. 変数を初期化する`cur`から 0 まで、最小許容位置を表します。`a`次に必要なスピーカーのために。 
3. 変数を初期化する`cycles`これは、配列の末尾を超えて「折り返す」ことを強制された回数をカウントします。 
4. 必要なスピーカーごとに反復処理します。`x`で`b`：

- させて`p = pos[x]`。 
- もし`p >= cur`、この発生を現在のスキャンで使用できるため、次のように設定します。`cur = p + 1`。 
- そうしないと、スキャンを最初からやり直す必要があります。`a`, したがって、インクリメントします`cycles`そしてセット`cur = p + 1`。 
5. いつでも`cycles > 1`、すぐに「TIDAK」を出力します。 
6. サイクル制約に違反せずにループが終了した場合は、“YA”を出力します。 

重要なアイデアは、ラップアラウンドするたびに、順列の構造を最初から再度使用することを約束することになり、これはプロセスの制約の下で一貫して 1 回だけ発生する可能性があるということです。 

### なぜ効果があるのか

 不変条件というのは、`cur`多くても 1 回のリセットが発生したと仮定すると、常に、すでに一致した話者のシーケンスと一致する初期順列の最も早い位置を表します。 置換順序を後方に移動するたびに、残りのプロセスをラインナップの新しいパスの開始として再解釈する必要があります。 許可された移動の構造では、フロント要素のリサイクル以外に任意の並べ替えが作成されることはないため、複数の完全なリセットを一貫して解決することはできません。 したがって、シーケンスは、各セグメント内の昇順の位置順序を維持しながら、そのようなリセットを 1 つだけ使用してシミュレートできる場合に正確に有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i
    
    cur = 0
    cycles = 0
    
    for x in b:
        p = pos[x]
        if p >= cur:
            cur = p + 1
        else:
            cycles += 1
            cur = p + 1
            if cycles > 1:
                print("TIDAK")
                break
    else:
        print("YA")

if __name__ == "__main__":
    solve()
```実装は、各値を初期順序の位置にマッピングすることから始まり、これにより、必要な各話者が元々座っていた場所への定時間アクセスが可能になります。 

変数`cur`順列による単調な進行を強制します。 次に必要な位置がこの単調性に違反する場合、配列の先頭からのスキャンの再開が必要であると解釈します。`cycles`。 

早期退場時`cycles > 1`シーケンスを実現できないことがわかったら、不要な処理を防ぎます。

 ## 特殊なケース

 シーケンスが順列順序で後方ジャンプを繰り返し強制する場合、重大なエッジ ケースが発生します。 たとえば、必要なシーケンスが初期配列の両端に位置する要素間で交互に行われる場合、すべてのステップでリセットが強制される可能性があります。 2 回目のリセットが必要になると、アルゴリズムはこれを正しく拒否します。`cycles`1を超えます。 

もう 1 つのエッジケースは次のような場合です`b`はすでに次のサブシーケンスです`a`。 その場合、`cur`は前進するだけでサイクルは発生しないため、答えはすぐに受け入れられます。 

ミニマルなケース付き`n = 1`関係なく常に成功します`m`順序の競合がないため、`pos[x]`は常にゼロであり、単調性を破ることはありません。
