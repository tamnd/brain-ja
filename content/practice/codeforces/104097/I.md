 ## 解決策
 ## 問題の理解

 ビットマスクによってインデックスが付けられた配列が与えられます。 それぞれの位置は、あるサイズの宇宙のサブセットを表します。$k$、あります。$2^k$合計値。 タスクは、すべてのサブセットについて、包含によってそれに関連する他のサブセットの集計を計算することです。 「サブセット間のサブセット合計」と呼ばれるバージョンでは、マスクの値は通常、マスクがその中に含まれるすべての値の合計になります。ただし、同じフレームワークが逆に表示され、代わりにスーパーセットが集約されます。 

出力は同じサイズの別の配列で、各位置が対応するマスクに対するこの集計クエリに応答します。 

主要な問題は、各クエリが他の多くのマスクに指数関数的に依存していることです。 直接解釈すると、重複するセット間で作業を繰り返すことになりますが、これはまさに問題が明らかにするように設計されているものです。 

制約は暗黙的に次のように形作られます。$2^k$。 もし$k$が約 20 または 22 の場合、配列全体のサイズは約 100 万から数百万のエントリになります。 これにより、マスクごとにサブセットを個別に列挙しようとするアプローチは即座に除外されます。これは、次のような結果につながるからです。$O(4^k)$、これは実現可能な限界をはるかに超えています。 目的のソリューションでは、部分的な計算を再利用し、ビットマスク全体で構造を活用する必要があります。 

一般的なエッジケースは次のような場合に発生します。$k = 0$。 この場合、サブセットは空のマスクだけであり、答えは入力と単純に一致する必要があります。 もう 1 つの微妙なケースは、1 つの位置を除いてすべての値がゼロである場合です。 単純なサブセット列挙では、ビット遷移が正しく処理されない場合、特に実装でサブセットとスーパーセットの方向が混在している場合、寄与を簡単に過大評価したり見逃したりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。マスクごとに、すべてのサブマスクを反復処理し、それらの値を合計します。 これは、必要な集計の定義に直接従うため、正しいです。 ただし、マスクのサブマスクの数は$2^{\text{popcount}(mask)}$これをすべてのマスクについて合計すると、およそ$3^k$操作。 のために$k = 20$、これはもうあります$3^{20} \approx 3.4 \times 10^9$が遅すぎます。 

重要な観察は、計算が大きく重複していることです。 あるマスクから別のマスクに移動すると、サブマスク構造の大部分が共有されます。 最初から再計算するのではなく、徐々により多くのビットが参加できるようにすることで、段階的に答えを構築できます。 

これはまさに SOS DP の設定である「Sum Over Subsets Dynamic Programming」です。 このアイデアは、ビットを 1 つずつ処理し、変更が許可されるビットの制約を段階的に緩和することです。 処理した後、$i$-番目のビット、下位のみを考慮すると正しい答えがわかります$i$自由のビット、これを拡張してビットを含めます$i$すべての小さなビットの正確性を維持しながら。 

ブルート フォースはすべてのサブマスクを明示的に列挙するため機能します。 この列挙はマスクごとに独立して繰り返されるため、失敗します。 SOS DP はこれを次のように削減します。$k \cdot 2^k$各サブセット関係がビット レベルごとに 1 回だけ考慮されることを保証することにより、遷移が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(3^k)$|$O(2^k)$| 遅すぎる |
 | SOS DP |$O(k \cdot 2^k)$|$O(2^k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 DP 配列を維持します。`dp[mask]`最初はそのサブセットに指定された値を格納します。 目標は、それぞれが`dp[mask]`すべてのサブマスクからの寄与を蓄積します。 

1.初期化`dp[mask]`すべてのマスクの入力値を使用します。 これは、まだ集計が適用されていない基本的なケースを表しています。 
2. 0 から 0 までの各ビット位置を反復します。$k-1$。 各反復により、情報はそのビットによって定義されたサブセット格子の 1 つの次元に沿って流れることができます。 
3. 各マスクについて、現在のビットが設定されているかどうかを確認します。 設定されていない場合は、このマスクを、このビットのみが異なる関連マスクからの情報を組み合わせるための基本状態として安全に使用できます。 
4. トランジションを実行します`dp[mask] += dp[mask with bit set]`サブセット合計バリアントの場合。 このステップは、現在の構造体とこの追加ビットを含むすべてのサブセットが現在のマスクの答えに寄与していることを事実上示しています。 
5. すべてのビットに対してこのプロセスを繰り返し、考えられるすべてのビットの組み合わせに寄与が伝播されるようにします。 

反復順序は、次の次元に進む前に各次元が完全に処理されることを保証するという点でのみ重要です。 すべてのビットを終了した後、各マスクには、有効な変換パスごとに 1 回だけ、関連するすべての関連マスクからの寄与が蓄積されます。 

### なぜ効果があるのか

 最初の処理後の DP の状態$i$bits は、それらのビットのみを考慮したすべてのサブセットにわたる正しい集計を表します。 不変条件は、マスクのペアが以下より大きいビットのみ異なるということです。$i$彼らの貢献はすでに正しくマージされています。 

ビット処理時$i$、そのビットのみが異なる状態をマージし、ブール格子のより小さなサブキューブからより大きなサブキューブまで正確性を拡張します。 すべてのサブセット関係はビット 反転のシーケンスに分解できるため、各寄与は正確に 1 つの有効なチェーンを通じて伝播され、重複や省略が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    dp = list(map(int, input().split()))
    
    k = n.bit_length() - 1 if n & (n - 1) == 0 else n.bit_length()
    
    # If input size is 2^k, we infer k from n
    # but more safely, treat k as bit width of indices
    # (common CF format gives n = 2^k directly)
    
    k = (n - 1).bit_length()
    
    for i in range(k):
        for mask in range(n):
            if mask & (1 << i):
                dp[mask] += dp[mask ^ (1 << i)]
    
    print(*dp)

if __name__ == "__main__":
    solve()
```このコードは、配列のサイズ (フルパワーセットであると想定) を読み取ることから始まり、続いて各サブセットに関連付けられた値を読み取ります。 DP 配列は入力から直接初期化されます。 

メインループは各ビットを独立して処理します。 現在のビットを含むすべてのマスクについて、そのビットを削除した同じマスクからの寄与を追加します。 この方向により、サブマスクからスーパーセットへの累積が確実に行われ、意図したサブセット合計の累積と一致します。 

の計算`k`すべてのマスクを表すのに必要なビット数を導出します。 配列のサイズは$2^k$、回復します$k$ビット長ロジックを使用します。 よくある落とし穴は、次のことを想定していることです。$n$すでに$k$、インデックス作成が完全に壊れてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(k \cdot 2^k)$| 各ビットはすべてのマスクを 1 回処理します。 
| スペース |$O(2^k)$| すべてのサブセットにわたる DP 配列 |

 複雑さは状態空間の自然なサイズと一致します。 と$2^k$約100万、そして$k$20 年頃の合計操作は約 2,000 万回の更新であり、効率的なループを使用する Python の一般的な時間制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import log2
    
    data = inp.strip().split()
    n = int(data[0])
    arr = list(map(int, data[1:]))
    
    dp = arr[:]
    k = (n - 1).bit_length()
    
    for i in range(k):
        for mask in range(n):
            if mask & (1 << i):
                dp[mask] += dp[mask ^ (1 << i)]
    
    return " ".join(map(str, dp))

# small base case
assert run("1\n5") == "5"

# k=2 case
assert run("4\n1 2 3 4") == "1 3 4 10"

# all zeros except one
assert run("4\n0 0 0 7") == "0 0 0 7"

# alternating pattern
assert run("4\n1 0 1 0") == "1 1 2 1"

# maximum small sanity
assert run("2\n1 2") == "1 3"

 ## 特殊なケース

 のために$k = 0$、マスクは 1 つだけ、つまり空のセットだけです。 このアルゴリズムはビットに対してゼロ反復を実行するため、元の値が変更されずに出力されます。 たとえば、入力`1\n5`返品`5`、空の宇宙の唯一のサブセットはそれ自体であるため、これは定義と一致します。 

すべてのマスクにわたって 1 ビットのみが設定されている場合、伝播はその次元に沿ってのみ発生します。 未設定の次元に沿って遷移が存在しないため、DP は他のビットからの干渉なしに値を正しく累積します。 

厄介なケースは、値がスパースであるものの、より高いインデックスのマスクに配置されている場合です。 各ビットは独立して処理され、上位ビットはそれらを明示的に含む状態にのみ影響を与えるため、アルゴリズムは依然として正しく伝播します。
