 ## 解決策
 ## 問題の理解

 一連の頂点と辺によって記述される無向グラフが与えられます。 課題は、このグラフが「クトゥルフ」と呼ばれる非常に特殊な構造パターンと一致するかどうかを判断することです。 

私たちが探している構造は、おそらくその頂点のいくつかに木が取り付けられた、中央の単純なサイクルとして説明できます。 すべての頂点は、その単一のサイクル、またはそれにぶら下がっている木のいずれかに属します。 サイクル自体は単純である必要があります。つまり、各頂点を 1 回だけ訪問し、縮退しないように少なくとも 3 つの頂点が含まれている必要があります。 

グラフ理論の観点から見ると、これはグラフが接続され、正確に 1 つのサイクルを含む必要があることを意味します。 他のすべてのエッジは、追加のサイクルを導入することなく、サイクルに接続されたツリー状の枝を形成する必要があります。 

入力は頂点とエッジの数を提供し、その後にエッジ リストが続きます。 出力は、グラフがそのような「ツリーが付加されたサイクル」構造として解釈できるかどうかの二者択一です。 

制約は十分小さいため、線形または線形に近いグラフの走査で十分です。 頂点が約 100 個までであれば、O(n + m) 個の DFS または BFS でさえもわずかに高速ですが、二次関数であればそれでも通過できます。 ただし、構造の状態は微妙です。接続性をチェックするだけでは十分ではなく、エッジの数だけをチェックするだけでも十分ではありません。 

接続性を検証せずに「エッジと頂点が等しい」だけで十分だと考えるのは単純な間違いです。 たとえば、それぞれがツリーを含む 2 つの切断されたサイクルで構成されるグラフは正しいエッジ数を持つ可能性がありますが、その構造が単一の統一されたサイクルベースのコンポーネントではないため無効です。 

もう 1 つの失敗例は、切断されたツリーに起因します。 たとえば、ツリーを形成する 4 つの頂点と 3 つのエッジと、他の場所にある孤立したサイクル コンポーネントを持つグラフを考えてみましょう。 ローカルではエッジカウントを満たしますが、グローバルでは失敗します。 

2 番目の微妙なエッジ ケースは、グラフに正確に n 個のエッジがあるが、複数のサイクルが含まれる場合です。 たとえば、パスで接続された 2 つの別々のサイクルでもエッジ数を n に近づけることはできますが、「グラフ全体でちょうど 1 つのサイクル」という要件に違反します。 

## アプローチ

 ブルートフォースのアイデアは、サイクルを明示的に検出し、各頂点からのグラフ走査をシミュレートし、エッジを単一のサイクルとツリーに分割できるかどうかを確認することによって完全な構造制約を検証することです。 サイクルを列挙し、サイクル バックボーンを再構築し、残りのすべてのエッジがそれに接続されたツリーに属していることを確認することを試みることができます。 添付ファイルの検証と組み合わせた任意のグラフでの再構成を伴うサイクル検出には慎重な記録管理が必要であり、最悪の場合、各エッジが複数回再検討される可能性があり、単純な実装では指数関数的または高多項式の動作が発生する可能性があるため、これはすぐに複雑になります。 

重要な単純化は構造的な観察から来ています。 接続された無向グラフでは、ちょうど n 個の頂点と n 個のエッジがある場合、ちょうど 1 つのサイクルが存在します。 これは標準的な不変条件です。ツリーには n − 1 個のエッジがあり、追加のエッジごとに 1 つのサイクルが導入されます。 したがって、グラフが接続されていて n 個のエッジがある場合、グラフには 1 つのサイクルが含まれている必要があり、他のすべてのエッジはその周囲にツリー接続を形成します。 

これは、グラフが縮退していないことを保証する限り、必要な構造と正確に一致します。 中心サイクルには少なくとも 3 つの頂点が必要であるため、n ≥ 3 であることを確認する必要があります。これらの条件があれば、それ以上の構造検証は必要ありません。接続性によって単一コンポーネントが保証され、エッジ数によって正確に 1 つのサイクルが保証されます。 

したがって、問題は 2 つのチェックに集約されます。グラフは接続されている必要があり、エッジの数は頂点の数と等しくなければならず、有効性のために最小サイズの制約があります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (明示的なサイクル再構築) | O(n²) から O(n³) | O(n + m) | 遅すぎる/不必要 |
 | 最適 (接続性 + エッジ数) | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフをその基本的な構造特性に還元し、それらを直接検証します。 

1. グラフを読み取り、隣接リスト表現を構築します。 これにより、接続の効率的な横断が可能になります。 
2. 頂点の数が少なくとも 3 つであるかどうかを確認します。有効な中心サイクルは頂点が 3 つ未満では存在できないため、それより小さいグラフは直ちに無効になります。 
3. m と n を比較して、エッジ数の条件を検証します。 グラフに頂点とまったく同じ数のエッジがない場合、グラフに正確に 1 つのサイクルを含めることはできないため、すぐに失敗します。 
4. 少なくとも 1 つのエッジを持つ頂点から開始してグラフの走査を実行します。 DFS または BFS を使用して、到達可能なすべての頂点をマークします。 
5. トラバース後、グラフに表示されるすべての頂点が訪問されていることを確認します。 いずれかの頂点に到達できない場合、グラフは切断されます。これは、構造がツリーが接続された単一サイクルであるという要件に違反します。 
6. すべてのチェックに合格すると、グラフは必要な構造と一致します。 

### なぜ効果があるのか

 n 個の頂点と n 個の辺をもつ接続された無向グラフは循環番号 1 を持ちます。これは、独立したサイクルが 1 つだけ存在することを意味します。 追加のサイクルには n を超える追加のエッジが少なくとも 1 つ必要になるため、残りのすべてのエッジはそのサイクルに関連付けられたツリー状構造に強制的に組み込まれます。 接続性により、追加のサイクルや切断された構造を隠す可能性のある孤立したコンポーネントが存在しないことが保証されます。 サイズ制約により、サイクルが縮退構造ではなく単純なサイクルとして有効であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    if n < 3 or m != n:
        print("NO")
        return

    vis = [False] * (n + 1)

    # find a start node with at least one edge
    start = 1
    while start <= n and len(adj[start]) == 0:
        start += 1

    if start > n:
        print("NO")
        return

    stack = [start]
    vis[start] = True

    while stack:
        u = stack.pop()
        for v in adj[u]:
            if not vis[v]:
                vis[v] = True
                stack.append(v)

    for i in range(1, n + 1):
        if len(adj[i]) > 0 and not vis[i]:
            print("NO")
            return

    print("FHTAGN!")

if __name__ == "__main__":
    solve()
```隣接リストには、トラバーサルに適した形式でグラフが保存されます。 初期のチェックでは、検索の前に構造上の不可能性が処理されます。 DFS は、グラフに参加しているすべての頂点が単一の接続コンポーネントの一部であることを保証します。 微妙な点は、次数 0 の孤立した頂点はサイクルやエッジ構造に関与していないため、接続性をチェックする際に無視されることです。また、問題は意味のある構造がエッジによって引き起こされる接続コンポーネントにあると暗黙的に想定しています。 

条件 m == n は、明示的なサイクル検出に代わる決定的な構造的ショートカットです。 これがなければ、一意のサイクルを明示的に識別して検証する必要がありますが、ここではエッジ数がすでにその制約をエンコードしています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各頂点とエッジは、DFS と構築中に 1 回処理されます。 
| スペース | O(n + m) | 隣接リストと訪問先配列 |

 制約は十分に小さいため、この線形横断は容易に制限内に収まります。 最大入力サイズであっても、操作の数は無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    stdout.flush = lambda: None

    n, m = map(int, inp.splitlines()[0].split())
    adj = [[] for _ in range(n + 1)]
    edges = inp.splitlines()[1:1+m]
    for e in edges:
        u, v = map(int, e.split())
        adj[u].append(v)
        adj[v].append(u)

    if n < 3 or m != n:
        return "NO"

    vis = [False] * (n + 1)

    start = 1
    while start <= n and len(adj[start]) == 0:
        start += 1
    if start > n:
        return "NO"

    stack = [start]
    vis[start] = True
    while stack:
        u = stack.pop()
        for v in adj[u]:
            if not vis[v]:
                vis[v] = True
                stack.append(v)

    for i in range(1, n + 1):
        if len(adj[i]) > 0 and not vis[i]:
            return "NO"

    return "FHTAGN!"

 ## 特殊なケース

 一般的なエッジ ケースは、正しい数のエッジがあるにもかかわらず接続されていないグラフです。 このような場合、DFS は 1 つのコンポーネントのみをカバーし、他の頂点は訪問されないままになり、最終チェックで正しく拒否されます。 

もう 1 つの微妙なケースは、孤立した頂点がある場合です。 これらはどのエッジにも参加しないため、接続性をチェックするときに無視されますが、構造に寄与せずに頂点数に含まれている場合、グラフが m == n 条件を満たさない原因になります。 

最後のエッジ ケースは、有効な最小サイクル サイズです。 n が 3 未満の場合、m == n であっても単純なサイクルは存在できず、早期の拒否によって縮退構造を誤って受け入れることがなくなります。
