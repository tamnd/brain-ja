 ## 解決策
 ## 問題の理解

 単一の製品に対して、毎月の一連の値上げが与えられています。 最初の値は初値を表し、その後の各値はその月の名目上昇額を表します。 その月までの累積価格に対するその月の上昇率の比率として計算される月次インフレ率が、所定のしきい値を超えないようにすることが求められます。$k$パーセント。 これを達成するには、初回価格や前月の価格を引き上げることができますが、追加される合計金額を最小限に抑えながら引き上げたいと考えています。 

各テスト ケースには月数が示されています$n$、最大許容インフレ率$k$、そして価格の上昇の配列$p$。 出力はテスト ケースごとに 1 つの整数であり、インフレ制約が毎月維持されるように配列に追加する必要がある最小合計値です。 

制約は中程度です。$n$最大でも 100 であり、$t$最大 1000、つまりソリューションは次の範囲で効率的に機能する必要があります。$O(n)$テストケースごとに。 個々の価格の値上げは最大で$10^9$これにより、考えられるすべての追加価格を単純に力ずくで列挙することに依存するアプローチが排除されます。 明らかではないエッジケースは、非常に低い初値の後に大幅な値上がりが続く場合に発生します。つまり、調整がなければ、インフレ係数は次の値を超えることになります。$k$大差で。 たとえば、$p = [1, 100]$そして$k = 1$, 2か月目の値上がり額は初値の100倍となり、上限の1％を大きく上回ります。 次の場合のみチェックする単純なソリューション$p_i \le k$完全に失敗します。 

## アプローチ

 ブルートフォースアプローチでは、各月の累積合計に対するすべての可能な増分を考慮し、どの組み合わせがインフレの上限を満たすかを確認します。 このアプローチは正しいですが、現実的ではありません。月ごとに、潜在的に$O(10^9)$考慮すべき要素が増えるため、操作数が天文学的に増加します。 

重要な洞察は、問題は左から右へ貪欲に解決できるということです。 月のインフレ係数$i$は次のように定義されます$p_i / S$、 どこ$S$調整後の以前のすべての値の合計です。 確実にするために$p_i / S \le k / 100$、必要な最小累積和を求めることができます。$S$として$S \ge \lceil (p_i \cdot 100) / k \rceil$。 現在の累積合計がこれより小さい場合は、その差を累計に加算します。 月を順番に処理することで、制約を満たすために合計増分を常に最小限に調整し、過剰補償が発生しないようにします。 これは線形です$n$そして与えられた範囲内で動作します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((max p_i)^n) | O(n) | 遅すぎる |
 | 貪欲なシーケンシャル | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`total_add`すべての加算の合計を追跡するにはゼロに設定し、`cumulative`初月の料金に。 
2. 2 か月目から最後の月まで、数か月にわたって繰り返します。 
3. 月ごとに$i$、必要な最小累積合計を次のように計算します。`(p[i] * 100 + k - 1) // k`。 この式により、最も近い整数に切り上げられます。 
4. 現在の累積和が`cumulative`が必要な最小値より小さい場合は、その差を計算して次の値に加算します。`total_add`。 アップデート`cumulative`この差を加えれば。 
5. 当月の料金を追加します`p[i]`に`cumulative`、その後の月の合計に今月が含まれるようになったことが反映されています。 
6. すべての月を処理した後、出力します`total_add`。 

不変条件は、処理後の月です。$i$、累積合計は、すべての月のインフレを最大に維持するのに常に十分です。$i$下に$k$パーセント。 この不変条件を維持することにより、インフレ制約が決して違反されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        p = list(map(int, input().split()))
        total_add = 0
        cumulative = p[0]
        for i in range(1, n):
            required = (p[i] * 100 + k - 1) // k
            if cumulative < required:
                add = required - cumulative
                total_add += add
                cumulative += add
            cumulative += p[i]
        print(total_add)

if __name__ == "__main__":
    solve()
```コードは、テスト ケースの数を読み取り、各テスト ケースを個別に処理することから始まります。 初期化する`total_add`ゼロにして設定する`cumulative`開始価格を反映して、最初の月の価格に変わります。 このループは、整数の丸めを処理するために天井除算を使用して必要な累積合計を計算します。 現在の累計額が不足する場合は、必要な金額を追加します。`total_add`そして更新します`cumulative`。 最後に、当月の価格を追加します。`cumulative`今後のチェックのために。 全体を通して整数演算を使用すると、浮動小数点エラーが回避されます。

## 特殊なケース

 入力用`2 1\n1 100`、累積は 1 から始まります。月 1 には次のことが必要です`100 * 100 / 1 = 10000`, そこで追加します`10000 - 1 = 9999`アルゴリズムは天井分割を正しく適用し、累積を順次更新します。 のために`4 10\n10 1 1 100`、アルゴリズムは 10% の上限を満たすために先月の前に 90 を追加し、後続の月に連続した更新が正しく蓄積されることを示しています。
