 ## 解決策
 ## 問題の理解

 0 から 0 までの番号が付けられた都市のチェーンが与えられています。$n$、によって線形に接続されます。$n$道路。 各道路には方向があり、左（都市から）のどちらかです。$i$に$i-1$) または右 (から$i-1$に$i$）。 旅行者は、ある都市から出発して、できるだけ多くの異なる都市を訪れたいと考えています。 旅行者は道路に沿って現在の方向にのみ移動でき、移動するたびにすべての道路の方向が反転します。 このタスクは、旅行者がそこから出発した場合に到達できる個別の都市の最大数を都市ごとに計算することです。 

入力は複数のテスト ケースで構成されます。 それぞれのケースについて、長さが与えられます。$n$と長さの文字列$n$道路の最初の方向を表します。 アウトプットしなければなりません$n+1$各都市に 1 つずつ、その都市から開始して到達可能な個別の都市の最大数を示す整数。 

制約は強力です。$n$まで可能です$3 \cdot 10^5$、との合計$n$すべてのテストケースで次を超えない$3 \cdot 10^5$。 これは、総当たりのシミュレーションには時間がかかるため、都市ごとに考えられるすべての移動を明示的に反復するソリューションは実行不可能であることを意味します。$O(n^2)$テスト ケースごとに複数の操作。 必要なのは$O(n)$テストケースごとのソリューション。 

微妙なエッジケースは、交互に配置される道路ストリングです。たとえば、`LRL`。 都市 1 から開始して、旅行者は都市 2 に右に移動し、その後方向が反転して都市 1 に戻ることができます。実装を不用意に行うと、反転により「往復」移動が可能であることを忘れ、到達可能な都市を過小評価する可能性があります。 

もう一つの境界は最小の場合です。$n = 1$。 一本道が右を向いているなら`R`, 都市0から開始すると都市1に移動できますが、都市1から開始すると移動できません。 正しい出力は次のようになります`[2,1]`。 インデックスがオフの場合、チェーンの開始または終了でのエッジの処理は間違いやすくなります。 

## アプローチ

 強引なアプローチでは、各都市から始まる各移動をシミュレートします。 あらゆるステップで、現在の都市の近隣都市をチェックし、有効なエッジに沿って移動し、その後すべての方向を反転します。 これは正しいですが、時間がかかります$O(n^2)$最悪の場合の運用。 と$n = 3 \cdot 10^5$、これはおおよそ次のようになります$10^{10}$操作が遅すぎる。 

重要な洞察は、1 回移動すると道路の方向が逆転するという観察から得られます。`R`または`L`予測可能なパターンでの移動が可能になります。 シミュレーションする代わりに、中断することなく各方向にどこまで移動できるかを事前に計算できます。 2 つの配列を定義します。`left`そして`right`。`left[i]`都市から左に連続して移動できる回数です`i`交互フリップの下で。 同様に、`right[i]`は右への連続移動の数です。 

これにより、問題は文字列を左から右に 1 回、右から左に 1 回スキャンして、連続した到達可能な都市を計算するという問題に軽減されます。 各都市の最大移動距離は、`left[i] + 1 + right[i]`。 これにより線形が得られます$O(n)$解決。

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化する`left`そして`right`サイズの`n+1`ゼロ付き。 これらには、各都市から左右に到達可能な最大連続都市が格納されます。 
2. を計算します。`right`左から右にスキャンして配列します。 インデックスごとに$i$0から$n-1$、の場合$i$- 番目の道は右を向いています`R`、 セット`right[i+1] = right[i] + 1`。 それ以外の場合はリセット`right[i+1] = 0`。 これは都市からの移動を考慮したものです$i$に$i+1$。 
3. を計算します。`left`右から左にスキャンして配列します。 インデックスごとに$i$から$n$1 まで下げます。$i-1$- 番目の道路が左を指します`L`、 セット`left[i-1] = left[i] + 1`。 それ以外の場合はリセット`left[i-1] = 0`。 これは都市からの移動をキャプチャします$i$に$i-1$。 
4. 都市ごとに$i$0から$n$、到達可能な個別の都市の最大数は次のとおりです。`left[i] + 1 + right[i]`。 の`+1`開始都市そのものを表します。 
5. 各テスト ケースの計算値を出力します。 

なぜ効果があるのか​​:`left`そして`right`配列は各方向で最大の連続シーケンスをキャプチャします。 移動するたびに道路が反転するため、交互のパターンによって連続した同一の移動が保証されるため、中断されないシーケンスを数えることで、到達可能な個別の都市の正確な数が得られます。 合計する`left`、`right`、開始都市により、訪問したすべての都市が正確に 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        left = [0] * (n+1)
        right = [0] * (n+1)

        for i in range(n):
            if s[i] == 'R':
                right[i+1] = right[i] + 1
            else:
                right[i+1] = 0

        for i in range(n-1, -1, -1):
            if s[i] == 'L':
                left[i] = left[i+1] + 1
            else:
                left[i] = 0

        result = [str(left[i] + 1 + right[i]) for i in range(n+1)]
        print(" ".join(result))

if __name__ == "__main__":
    solve()
```このソリューションは、まずテスト ケースの数を読み取ります。 それぞれの場合において、配列を初期化して、左右の最大リーチを事前計算します。 スキャンは、off-by-one エラーを避けるために、適切なインデックスを使用して慎重に行われます。 最後に、結果は文字列としてフォーマットされて出力されます。 高速 I/O を使用すると、大規模な入力に対するソリューションが時間制限内で確実に実行されます。
