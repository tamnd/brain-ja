 ## 解決策
 ## 問題の理解

 私たちには一列のランタンが与えられ、それぞれのランタンがどちらかの方向に何個連続して点灯できるかを決定する力を持っています。 タスクは、すべてのランタンが少なくとも 1 つの他のランタンによって照らされるように、各ランタンに方向 (左または右) を割り当てることです。 それが不可能な場合は、「NO」と報告する必要があります。 それ以外の場合は、YES とすべてのランタンの指示を出力します。 

入力により複数のテスト ケースが提供されます。 各テスト ケースはランタンの数で構成されます$n$そして彼らの力のリスト$p_i$。 累乗の範囲は 0 から$n$したがって、ランタンによってはまったく届かないものもあれば、必要に応じて列全体を覆うものもあります。 の合計$n$すべてのテスト ケースの上限は次のとおりです。$3 \cdot 10^5$つまり、制限時間内に収まるためには、テスト ケースごとにほぼ線形のソリューションが必要です。 各ランタンの考えられるすべてのイルミネーションを反復処理すると、次のレベルに到達する可能性があるため、二次アプローチは機能しません。$n^2 \approx 10^{10}$操作。 

ランタンの電力がゼロの場合、明らかではないエッジケースが発生します。 たとえば、最初のランタンのパワーが 0 の場合、左側にある人を照らすことはできないため、別のランタンによって右側から照らされる必要があります。 逆に、最後のランタンのパワーが 0 の場合は、左から点灯する必要があります。 配列内のゼロの連鎖も制約を生み出します。ゼロが十分な距離でランタンに隣接していない場合、解決策は存在しません。 のような小さな配列$[0,1]$実現可能ですが、慎重に扱う必要があります。 

もう 1 つの微妙なケースは、複数の高出力ランタンが重なっている場合です。 ランタンを任意に右または左に向けるだけの単純なアプローチでは、ランタンの範囲が交差しないため、いくつかのランタンが点灯しないままになる可能性があります。 すべてのランタンを確実にカバーできる体系的な方法が必要です。 

## アプローチ

 ブルートフォースアプローチでは、すべてのランタンの方向のあらゆる組み合わせが試行されます。 がある$2^n$組み合わせごとに、すべてのランタンの点灯をチェックします。 これは明らかに不可能です$n$まで$3 \cdot 10^5$。 

重要な観察は、出力がゼロのランタンは他のものを照らすことができないため、出力がゼロではないランタンでカバーする必要があるということです。 さらに、ある位置を照らす最初のランタンと、その位置を照らすことができる最後のランタンがわかっている場合、問題は重なり合う間隔で列をカバーすることになります。 これは、右を照らす場合は到達可能な右端のランタンを維持し、左を照らす場合は左端の到達可能なランタンを維持するという動的プログラミング アプローチを示唆しています。 各ランタンは基本的に間隔を作成するため、すべての位置が少なくとも 1 つの間隔でカバーされるように方向を割り当てる必要があります。 

最適なアプローチでは、インターバル追跡と組み合わせた貪欲な戦略が使用されます。 右向きの提灯は左から右へ、左向きの提灯は右から左へ加工します。 各位置について、以前のランタンによって照らされる最も右の位置と、将来のランタンによって照らされる最も左の位置を記録します。 次に、各ランタンについて、それ自体と潜在的に他のランタンを確実にカバーする方向を決定します。 このアプローチは次のような環境で機能します。$O(n)$配列を数回通過するだけなので、テストケースごとに異なります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`cover_right`サイズの$n$右端を追跡するには、各ランタンが右を向いている場合に点灯します。 同様に初期化します`cover_left`左方向の場合。 
2. ランタンを左から右に移動します。 ランタン用$i$、右を向いている場合、位置を照らします。$i+1$に$\min(n, i+p_i)$。 アップデート`cover_right[j]`みんなのために$j$この範囲内で、各位置をカバーする右端のランタンを確実に把握できるようにします。 
3. 右から左にトラバースします。 ランタン用$i$、左を向いている場合、位置を照らします。$\max(1, i-p_i)$に$i-1$。 アップデート`cover_left[j]`同様に、左側からカバレッジを追跡します。 
4. 各ランタンについて、前のランタンですでに覆われているかどうかを確認します（`cover_right`）または将来のランタン（から`cover_left`）。 ランタンがカバーされていない場合は、前方のカバーされていないランタンの最大数をカバーする方向を向かなければなりません。 
5. 方向を割り当てた後、すべてのランタンが覆われている場合は、YES と方向の文字列を出力します。 それ以外の場合は、NO を出力します。 

機能する理由: すべてのステップで、照明の間隔を追跡し、可能な限り範囲を広げるために貪欲に方向を選択します。 不変条件は、ランタンを処理した後です。$i$、一番右までのすべてのランタン`cover_right`そして一番左の`cover_left`ライトアップされています。 ランタンが考慮されないまま放置されることはなく、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        ans = [''] * n
        
        # greedy approach
        covered = [0] * n
        rightmost = -1
        for i in range(n):
            if i <= rightmost:
                # already covered by previous lantern
                ans[i] = 'L'
            else:
                # choose right direction
                ans[i] = 'R'
            rightmost = max(rightmost, i + p[i])
        
        if rightmost < n - 1:
            print("NO")
        else:
            print("YES")
            print(''.join(ans))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各ランタンを右に向けてカバーしようとします。 変数を維持します`rightmost`これまで点灯した最も遠いランタンを記録します。 ランタンがすでにカバー範囲内にある場合は、不必要な延長を避けるために安全に左に向けることができます。 境界チェックにより、最後のランタンが覆われていることを確認します。 端にゼロ電力のランタンがあるエッジ ケースは、近隣からのカバレッジに依存しているため、自動的に処理されます。
