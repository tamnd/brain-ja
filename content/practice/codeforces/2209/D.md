 ## 解決策
 ## 問題の理解

 この問題では、赤、緑、青の 3 色で一連のゴーストファイアを構築するように求められます。 OtterZ では、各色の数に限りがあります。$r$、$g$、 そして$b$。 目標は、2 つの制約を回避しながら、できるだけ多くのゴーストファイアを連続して配置することです。 まず、隣接する 2 つのゴーストファイアが同じ色を持つことはできません。 第二に、位置が 3 つ離れている (つまり、他の 2 つのゴーストファイアによって隔てられている) 2 つのゴーストファイアは同じ色を持つことはできません。 基本的に、シーケンスは距離 1 と距離 3 での繰り返しを避ける必要があります。 

各テスト ケースは 3 色の数を指定し、複数のテスト ケースが 1 回の実行で処理されます。 すべてのテストケースにわたるゴーストファイアの合計が以下を超えないため、$10^6$、テスト ケースごとのゴーストファイアの数に関してアルゴリズムがほぼ線形時間で実行されることを確認する必要があります。 これにより、すべての順列を列挙しようとしたり、考えられるすべての配置を単純にチェックしようとしたり、ゴーストファイアの数の階乗に時間がかかる可能性があるアプローチが妨げられます。 

エッジ ケースは、1 つ以上の色がゼロの場合に発生します。 たとえば、次の場合$r = 0, g = 3, b = 0$、緑のゴーストファイアのみを配置できます。 2 つの隣接する緑は隣接ルールに違反するため、正しいシーケンスは「G」です。 同様に、カウントが等しい場合、複数のインターリーブ シーケンスが可能であり、アルゴリズムは制約に違反することなく 1 つを選択する必要があります。 距離 3 のルールを無視すると、3 よりも長いシーケンスで微妙なエラーが発生します。 

## アプローチ

 ブルートフォースアプローチは、ゴーストファイアのすべての順列を試し、結果のシーケンスが両方の制約を満たすかどうかをテストすることです。 テストケースの場合$n = r + g + b$、 がある$O(n!)$順列。 これは、たとえ小さな値であっても明らかに実行不可能です。$n$、 とすれば$n$まで可能です$10^6$すべてのテストケースにわたって。 

貪欲な戦略が機能するのは、問題が反復的で局所的な構造を持っているためです。制約となるのは 1 ステップと 3 ステップ離れた位置に関係するだけです。 各ステップで、アルゴリズムは、隣接性と距離 3 の制約に違反しない残りの数が最大の色を選択できます。 重要な洞察は、各ステップで正しい選択をするには、最後に配置された 3 つのゴーストファイアの単純な履歴を維持するだけで十分であるということです。 色が使用されると、その数が減少します。 ある位置で有効な色がない場合、シーケンスは終了し、最大長のシーケンスが構築されることが保証されます。 

この貪欲なアプローチは、制約にローカルな相互作用のみが含まれるため機能します。 最後の 3 つの位置を超えるグローバルな依存関係はないため、シーケンスを継続する可能性が最大化されるため、残りの数量が最も多い色を選択するのが安全です。

 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | お(ん!) | O(n) | 遅すぎる |
 | 過去 3 件の追跡に貪欲 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、色をその数にマッピングする辞書を作成します。`{'R': r, 'G': g, 'B': b}`。 これにより、簡単にアクセスして更新できるようになります。 
2. 空のリストを初期化する`s`一連のゴーストファイアを保存します。 
3. 少なくとも 1 つの色が残っている間に、次の操作を行います。 

1. すべての色を残りの数で降順に並べ替えて調べます。 
2. この順序で各色について、その色を追加すると最後に配置された制約に違反するかどうかを確認します。`s[-1]`そして`s[-3]`。 もし`s`要素が 3 つ未満の場合は、関連する比較のみが実行されます。 
3. 色がこれらのチェックに合格した場合は、その色を`s`、そのカウントをデクリメントし、色選択ループから抜け出します。 
4. 制約に違反せずに色を追加できない場合は、このテスト ケースのシーケンスを終了します。 
4.変換`s`文字列に変換して保存または印刷します。 

機能する理由: アルゴリズムは、直接隣接性または距離 3 の制約に違反しない、使用可能な最大数の色を常に選択することで、ルールに違反することなくシーケンスをさらに拡張できないようにします。 不変条件は、すべてのステップで、`s`は有効であり、色の選択により将来の柔軟性が最大化されます。 大きい数の色が利用可能なときに小さい数の色を選択すると、色が早期に不足し、潜在的な最大長が減少する危険性があるため、どの選択肢を組み合わせてもシーケンスが長くなる可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        r, g, b = map(int, input().split())
        counts = {'R': r, 'G': g, 'B': b}
        s = []
        while any(counts[c] > 0 for c in counts):
            placed = False
            for color in sorted(counts, key=lambda x: -counts[x]):
                if counts[color] == 0:
                    continue
                if len(s) >= 1 and s[-1] == color:
                    continue
                if len(s) >= 3 and s[-3] == color:
                    continue
                s.append(color)
                counts[color] -= 1
                placed = True
                break
            if not placed:
                break
        print(''.join(s))

if __name__ == "__main__":
    solve()
```このコードは、カウントに単純な辞書を使用し、シーケンスのリストを保持します。`s`。 残りの数によって色を分類することで、貪欲な選択が保証されます。 隣接性と距離 3 のチェックにより、無効な配置が防止されます。 の`while`ループは、色が残っていない場合、または制約に違反せずに色を配置できない場合に終了します。
