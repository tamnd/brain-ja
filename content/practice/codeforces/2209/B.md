 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、各要素について、その右側にある要素が特定の意味で「支配」できる要素の数を決定する必要があります。 要素の場合`a[i]`、インデックスの最大数をカウントしたい`j > i`何らかの整数が存在するように`k`絶対的な差は`|a[i] - k|`厳密には次より大きいです`|a[j] - k|`。 鍵となるのは、`k`それぞれ独立して選択できます`i`、そしてカウントを最大にする必要があります。 

これは、要素ごとに次のことを尋ねることと同じです。`a[i]`、後の要素の数`a[j]`厳密にその間にあります`a[i]`そして選ばれた人もいる`k`? 直感的に選ぶと、`k`非常に大きいか非常に小さい場合でも許可されます`a[i]`すべての要素をそれ自体より小さいか大きいかのいずれかで支配すること。 最適な`k`カウントを最大化するには、常に 2 つの要素の範囲のすぐ外にあります。 

この制約は、すべてのテスト ケースにわたって配列に合計で最大 5000 個の要素を含めることができることを示しています。 すべてのペアを検査する素朴なアプローチ`(i, j)`あらゆる可能性のために`k`n ≤ 5000 なので O(n²) の操作が必要ですが、ブルートフォース反復ではなく数値のプロパティを使用したより簡単な方法があるかもしれません。`k`。 

エッジ ケースには、サイズ 1 の配列、要素が繰り返される配列、最大または最小の要素が先頭または末尾に現れる配列が含まれます。 たとえば、配列`[5, 5, 5]`生産しなければならない`[0, 0, 0]`、なぜなら、どの選択をしても`k`、厳密に「近い」要素はありません。`k`値が等しい場合は、他のものよりも高くなります。 

## アプローチ

 ブルートフォースアプローチでは、各要素を反復処理します。`a[i]`、それぞれについて`i`、すべての要素を確認してください`a[j]`のために`j > i`。 各ペアごとに`(i, j)`、整数を見つけようとします`k`そのような`|a[i] - k| > |a[j] - k|`。 この不等式は単純なチェックに帰着します。`k`間の間隔の外にある必要があります`a[i]`そして`a[j]`。 具体的にはどちらか`k < min(a[i], a[j])`または`k > max(a[i], a[j])`。 そのようなので`k`何に対しても常に存在する`i ≠ j`、状態はチェックに減ります`a[i] ≠ a[j]`。 単純な複雑さはテスト ケースごとに O(n²) ですが、制約を考慮すると許容範囲です。 

最適なアプローチは、どのような場合でも次のような観察を利用します。`a[i]`、支配的な要素の最大数は、次の選択によって達成されます。`k`左端または右端にあるため、`a[i]`からはさらに遠い`k`よりも`a[j]`もし`a[j]`間にあります`a[i]`そして`k`。 これにより、問題は右側の要素の数を数えるということになります。`i`よりも厳密に小さいか、厳密に大きい`a[i]`、これら 2 つのカウントの最大値を取得します。 もう計算したり反復したりする必要はありません`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | n ≤ 5000 で許容 |
 | 最適化された貪欲さ | O(n²) | お(1) | 受け入れられた、より単純なロジック |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。`a`長さの`n`。 
2. 結果配列を初期化する`res`長さの`n`ゼロ付き。 
3. 各インデックスを反復処理します。`i`から`0`に`n-1`。 
4. のために`i`、2つのカウンターを初期化します`count_less`そして`count_greater`ゼロに。 
5. 各インデックスを反復処理します。`j`から`i+1`に`n-1`。 もし`a[j] < a[i]`、増分`count_less`。 もし`a[j] > a[i]`、増分`count_greater`。 
6.セット`res[i]`最大まで`count_less`そして`count_greater`。 
7. すべてのインデックスを処理した後、テスト ケースの結果配列を出力します。 

効果がある理由: それぞれ`i`、支配できる要素の数は、の相対値にのみ依存します。`a[i]`そして`a[j]`。 選択する`k`左端の要素がすべての小さな要素を支配し、`k`一番右にあるものは、より大きな要素すべてを支配します。 最大値が必要なため、これら 2 つのカウントのうち大きい方を取ると正しい答えが得られます。 支配は各要素ごとに独立しているため、要素が二重にカウントされることはありません。`i`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        res = [0] * n
        for i in range(n):
            count_less = 0
            count_greater = 0
            for j in range(i + 1, n):
                if a[j] < a[i]:
                    count_less += 1
                elif a[j] > a[i]:
                    count_greater += 1
            res[i] = max(count_less, count_greater)
        print(" ".join(map(str, res)))
```コードはアルゴリズムのステップを直接実装します。 それぞれ`i`それ以降のインデックスとのみ比較されます。 使用する`max(count_less, count_greater)`最適なものを確実に選択します`k`暗黙的に。 このアプローチにより、実際のデータの不必要な計算が回避されます。`k`相対的な順序のみに依存する値。
