 ## 解決策
 ## 問題の理解

 それぞれの強さの値を持つ一連のモンスターが与えられます。 こちらも初期戦闘力からスタートします。 いつでも、現在のパワーが少なくともモンスターの強さであればモンスターを倒すことができます。または、限られた数の特別なアイテムを使用して、使用ごとにモンスターの強さを 1 ずつ増やすことができます。 

モンスターを倒すと、モンスターの現在の強さだけ戦闘力が増加し、モンスターが除去されるため有利です。 面白いのは、戦うかどうかを決定する前に、最大 k 個のモンスターの強さを段階的に増加させて「形成」できることですが、増加ごとに 1 つのフリップ フロップが消費されます。 

目標は、強化と殺害の最適な順序を選択した後、最終的な戦闘力を最大化することです。 

重要な相互作用は、モンスターをブーストするとすぐに殺すのが難しくなりますが、強くなった後はより有益になる可能性があるということです。 同時に、早く倒すことで力が増し、より強力なモンスターにアクセスできるようになります。 

制約は n の点では小さく、テスト ケースごとに最大 100 ですが、強度と初期検出力の値は最大 10^9 になり、k は非常に大きくなる可能性があります。 これにより、フリップフロップの分布に対する状態空間検索が即座に除外されます。 k が巨大であるため、モンスターと残りの k に対する単純な DP さえ不可能です。 

この構造は、私たちがグローバルに増分の恣意的な割り当てを選択しているのではなく、モンスターが現在使用可能であるか、それともわずかに調整する必要があるかについてローカルな決定を行っていることを示唆しています。 

素朴な貪欲な思考による微妙な失敗例は、モンスターがぎりぎり強すぎるときに発生します。 

入力:```
c = 10, k = 1
a = [12, 11]
```単純な戦略では、12 のフリップ フロップを使って 13 にする可能性がありますが、これはさらに悪いことです。 正しい行動は、それを 11 に費やして 12 にし、11 が 12 より早く殺せるようにして、将来の成長順序を改善することです。 

すべてのフリップフロップの使用が早すぎると、後で有益なキルに到達できない場合、別のエッジケースが発生します。 

主な難しさは、最良のキル順序を維持しながら、複数のモンスターにわたって k 増分を使用する方法を決定することです。 

## アプローチ

 ブルートフォースアプローチでは、モンスター全体に最大 k 個の増分を割り当てるあらゆる方法と、殺害順序のすべての順列を試みます。 各構成について、現在の実現可能性の順にキルをシミュレートします。 これはすぐに爆発します。なぜなら、k の増分をどのように分配するかを決定することすら、およそ (k+n が n を選択する) 可能性との組み合わせによるものであり、k = 10^9 の場合でも実行不可能だからです。 

重要な観察は、フリップフロップの唯一の意味のある効果は、モンスターが早く殺せるか遅く殺せるかを変えることであるということです。 各増分によってモンスターが正確に 1 変更されるため、現在のパワー c でモンスターを倒せるようにするためのコストは決定的です: max(0, a_i - c)。 モンスターを c を超えて増やす必要はありません。そうしても倒すのが遅れるだけだからです。 

したがって、各モンスターには「アクティベーション コスト」が関連付けられています。つまり、現在のパワー レベルでモンスターを倒すことができるまでに何回のフリップ フロップが必要かということです。 モンスターが殺せるようになったら、すぐに殺すことが常に最適です。それは c を増加させ、その後の殺害を容易にするだけだからです。 

これにより、調整コストが残りの k と現在の c の範囲内に収まるモンスターを繰り返し選択するという問題が軽減され、パワーの成長が進むモンスターが常に優先されます。 n が小さいため、スキャンを繰り返して実行可能な最適なモンスターを選択し、c を更新することができます。 

貪欲な構造が現れます。各ステップで、現在到達可能なモンスターを殺すか、新しいモンスターのロックを解除するために必要な最も安価な調整にフリップフロップを費やします。

 ## アルゴリズムのチュートリアル

 現在の戦闘力と残りのフリップフロップを使用して成長の過程をシミュレーションします。 

1. 現在の戦闘力 c とすべてのモンスターが生存している状態で開始します。 残りの k 個のフリップフロップも追跡します。 重要な考え方は、いつでも、a_i ≤ c を持つモンスターのみがすぐに使用できるということです。 
2. まだモンスターが残っている間、まずビーチサンダルを消費せずに直接倒すことができるモンスターを見つけようとします。 そのようなモンスターが存在する場合、それを除去し、その値だけ c を増加します。 これは、リソースを消費せずにすぐに成長できるため、常に最適です。 
3. 現在殺せるモンスターがいない場合は、どのモンスターを殺せるのが最も安価であるかを検討します。 生きているモンスターごとに、必要なコスト max(0, a_i - c) を計算します。 このようなコストは最小のものを選択します。 これは、次の成長の機会を引き出す最も効率的な方法です。 
4. 最も安い必要コストが k より大きい場合、それ以上進むことはできないため、終了します。 その時点で、残りのモンスターは強力すぎて決して起動できず、kを節約しても将来の利益がないため、停止するのが最適です。 
5. そうでない場合は、そのコストを選択したモンスターに費やし、kを減らし、その実効強度をcに合わせて増加します。 その調整後、モンスターは次のステップで殺せるようになります。 
6. 再びループし、フリーキルと最小限のロック解除操作を交互に実行し、常に最も成長効率の高い方法でリソースを使用するようにします。 

### なぜ効果があるのか

このアルゴリズムは、少なくとも 1 つの即時キルを有効にしない限り、フリップ フロップを決して消費しないという不変条件を維持します。 即時キルにつながらないフリップフロップの割り当ては、将来の実現可能性に影響を与えることなく延期できます。キルによって c を増やすと、将来のしきい値が満たされやすくなるだけだからです。 したがって、すべての支出は次のパワー獲得のロックを解除することに合わせて調整され、必要最小限の調整を貪欲に選択することで、時間の経過とともに到達可能なキル数を最大化することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c, k = map(int, input().split())
        a = list(map(int, input().split()))
        alive = [True] * n

        while True:
            changed = False

            # try free kills
            for i in range(n):
                if alive[i] and a[i] <= c:
                    c += a[i]
                    alive[i] = False
                    changed = True

            if changed:
                continue

            # find cheapest activation
            best_i = -1
            best_cost = 10**30

            for i in range(n):
                if alive[i]:
                    cost = max(0, a[i] - c)
                    if cost < best_cost:
                        best_cost = cost
                        best_i = i

            if best_i == -1:
                break

            if best_cost > k:
                break

            k -= best_cost
            a[best_i] = c  # now killable immediately

        # final clean-up: kill everything possible
        for i in range(n):
            if alive[i] and a[i] <= c:
                c += a[i]
                alive[i] = False

        print(c)

if __name__ == "__main__":
    solve()
```このソリューションは、現在利用可能なすべてのモンスターを無料で消費し、将来の最も安価なモンスターを対象にロック解除するという 2 つの操作を繰り返し適用することを中心に構成されています。 ブール配列はどのモンスターがアクティブなままかを追跡し、メイン ループにより、すぐに成長できない場合にのみフリップ フロップを費やすことが保証されます。 

実装の微妙な詳細は、最後のクリーンアップ ループです。 フリップフロップが使い果たされるか、それ以上のアクティベーションが不可能になった後も、残りの到達可能なモンスターをすべて消費する必要があります。これは、以前のロック解除により追加コストなしで追加のモンスターが対象となる可能性があるためです。 

課題`a[best_i] = c`これは、追加の調整なしでモンスターを正確に殺せるものとしてマークし、次のフリーフェーズで消費されることを保証するコンパクトな方法です。

 ## 特殊なケース

 重要なエッジケースは、すべてのモンスターが最初は c より強く、k が 0 である場合です。 アルゴリズムはただちにアクティベーション検索に入り、正のコストを見つけて、進行できないため正しく停止します。 たとえば:

 入力:```
n = 2, c = 1, k = 0, a = [5, 6]
```すべてのコストが k を超えるため、調整は許可されず、答えは 1 のままになります。 

もう 1 つのケースは、k が c より小さいモンスターを減らすのに十分な大きさで、カスケードのロックを解除する場合です。 たとえば:

 入力:```
n = 2, c = 3, k = 2, a = [6, 4]
```このアルゴリズムは 4 に 1 を費やし、すぐにキルを有効にし、その結果の成長を利用して残りのロックを解除します。 すべての支出の直後に少なくとも 1 つのキルが続き、フリップ フロップが無駄にならないため、不変条件が成り立ちます。 

3 番目のケースは、1 回の殺害後に複数のモンスターが同時に殺害可能になる場合です。 フリーキル ループにより、そのようなモンスターはそれ以上消費される前にすべて消費され、最適な順序が維持されます。
