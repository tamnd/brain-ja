 ## 解決策
 ## 問題の理解

 長さの隠し配列内のゼロの位置を見つけるように求められます。$2n$, ここで、各整数は$1$に$n$は 1 回だけ発生し、残りの位置はすべて 0 になります。 配列を明示的に知ることはできませんが、任意の 2 つのインデックスをクエリして、それらのインデックスに等しい値が含まれているかどうかを確認することができます。 インタラクターは適応的です。つまり、応答が一貫している限り、クエリ全体で非ゼロ要素を再配置できます。 私たちの目標は、最大でも次の値を使用してゼロを見つけることです。$n+1$クエリ。 

入力により提供されるのは、$n$、配列のサイズを定義します$2n$、複数のテスト ケースが存在する場合があります。 出力は、ゼロが発生する各テスト ケースの単一のインデックスです。 主な問題は、単純なクエリがクエリ制限を超える可能性があり、適応型インタラクターにより配列が静的であると想定できないことです。 

とすれば$n$到達できる$10^4$まであります$10^3$テストケース、$O(n^2)$すべてのペアを比較するブルートフォース手法では、最大で次のパフォーマンスが得られます。$10^8$操作は 2 秒の制限には遅すぎます。 線形または線形に近い戦略が必要です。 すべてのゼロが一緒にクラスター化すると、微妙なエッジ ケースが発生します。ゼロではない 2 つの位置をクエリすると、ゼロが含まれるまで一貫してゼロが返される可能性があり、単純なスキャンが誤解を招く可能性があります。 たとえば、次の場合$a=[0,0,1,2]$、インデックス 3 と 4 を繰り返し比較すると、0 が返されますが、これはゼロを示しません。 

## アプローチ

 最も単純な総当たりアプローチは、ゼロが見つかるまですべてのインデックスを他のすべてのインデックスと比較することです。 これが機能するのは、ゼロが存在することが保証されており、ゼロを含む不等ペアは 0 を返すためです。問題は、これには最大で 0 が必要なことです。$O(n^2)$大規模なクエリの制限を超えるクエリ$n$。 

より効率的なアプローチは、正確に存在するという事実を活用します。$n$ゼロ以外の数値と$n$ゼロ。 構造化された方法で配列をクエリできます。連続する要素をペアにします。$(1,2),(3,4),\dots$そしてどのインデックスが一致するかを追跡します。 等しい値を返すペアは、両方ともゼロであるか、両方とも同じゼロ以外の数値である必要があります。 重要なのは、ゼロ以外の数値はそれぞれ 1 回だけ出現するため、等しい値を返すペアはゼロでなければなりません。 

問題を最大で解決できる観察$n+1$クエリでは、要素を順番にペアにすると、一致するペアの中ですぐにゼロが見つかるか、最後にペアになっていないゼロが残るかのどちらかになります。 これにより、インタラクターの適応性に関係なく、線形数のクエリで常に 1 つのゼロを見つけることができることが保証されます。 このアプローチは決定論的であり、ゼロ以外の数値の正確な位置を知ることに依存しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスポインタを初期化する`i = 1`。 2 ステップで配列を反復処理し、連続するペアをクエリします。`(i, i+1)`。 これにより、隣接するすべての要素を効率的にカバーできるようになります。 
2. 各クエリに対して、インタラクターが 1 を返した場合、これはペアに等しい数値が含まれていることを示します。 ゼロ以外の数値はそれぞれ 1 回出現するため、唯一の可能性は両方の要素がゼロであることです。 このペアのインデックスの 1 つをただちにゼロとして報告します。 
3. インタラクターが 0 を返した場合、ペアには 2 つの異なる非ゼロ数値、またはゼロと非ゼロ数値のいずれかが含まれていることを意味します。 次のペアに移動します。 
4. すべてのペアが 0 を返す場合、まだペアになっていない残りの要素の中に 0 が 1 つだけ存在します。 最後のペアになっていないインデックスを報告します。 

機能する理由: 連続する要素をペアにすることで、配列には正確な値が含まれるため、一致するペア内で直接、または枯渇によってゼロが見つかることが保証されます。$n$ゼロ。 不変条件は、各クエリでは要素の 1 つのペアが考慮から除外され、一致するペアはすべて 0 でなければならないということです。 適応型インタラクターは、以前のクエリ応答と矛盾しない限り、ゼロの検出を防ぐことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        found = False
        for i in range(1, 2*n, 2):
            print(f"? {i} {i+1}")
            sys.stdout.flush()
            res = int(input())
            if res == 1:
                print(f"! {i}")
                sys.stdout.flush()
                found = True
                break
        if not found:
            print(f"! {2*n}")
            sys.stdout.flush()

solve()
```このソリューションはテスト ケースの数を読み取り、各配列を個別に処理します。 各配列について、一致が見つかるまで連続するペアをクエリし、一致するペアの最初のインデックスを報告します。 一致するペアがない場合、最後の要素はゼロであることが保証されます。 適切な対話を維持するために、各クエリの後に出力をフラッシュします。 2 のステップを使用すると、最大でも$n$配列ごとのクエリ数 (範囲内)$n+1$限界。 微妙なのは、最後の要素が唯一のゼロである場合の処理​​です。 ペアリングでそれをスキップしても、正確性は保証されます。 

## 実用的な例

 サンプル 1:`a=[0,1,0,2]`と`n=2`| 私 | クエリ (i,i+1) | 応答 | アクション |

 | 1 | (1,2) | 0 | 次のペアに移動 |

これは、アルゴリズムが正確な非ゼロ位置の把握に依存せずにゼロを識別していることを示しています。 

サンプル 2:`a=[0,0,1,2,3,4]`と`n=3`| 私 | クエリ (i,i+1) | 応答 | アクション |
 | --- | --- | --- | --- |
 | 1 | (1,2) | 1 | レポートインデックス 1 |

 最初のペア自体にはゼロが含まれています。 アルゴリズムは直ちに停止し、連続する要素の一致するペアが 0 であるという不変条件を確認します。

 ## 特殊なケース

 すべてのゼロが最後にグループ化されるシナリオの場合、たとえば、`a=[1,2,3,0,0,0]`、アルゴリズムは連続するペアをクエリします。`(1,2),(3,4),(5,6)`。 最後のペアのみが一致し、応答 1 が生成されます。アルゴリズムは、そのペアの最初のインデックスを報告し、ゼロを正確に識別します。 適応型インタラクターは、以前のクエリ応答を維持する必要があるため、検出を防ぐためにゼロを並べ替えることはできません。 このソリューションは、ゼロがクラスター化されているか、分散されているか、孤立しているかに関係なく、あらゆる配置に対して堅牢です。
