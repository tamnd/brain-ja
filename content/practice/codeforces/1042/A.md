 ## 問題の理解

 私たちにはいくつかのベンチが与えられましたが、それぞれのベンチにはすでに何人かの人々が座っていました。 それから新しい人々のグループが到着し、それぞれがベンチを選んでそこに座らなければなりません。 全員が着席した後、すべてのベンチの中で 1 つのベンチの人数が最も多くなり、その値を と呼びます。$k$。 

タスクは、この最終最大荷重の 2 つの極端値を計算することです。 まず、可能な限り小さい値が必要です。$k$, 単一のベンチに過負荷がかかるのを避けるために、新人をできるだけ均等に分配すると仮定します。 次に、可能な限り最大の値が必要です。$k$, 意図的に人を集中させて、1つのベンチをできるだけ混雑させると仮定します。 

制約は十分に小さいので、どのような解決策もおおよそ$O(n \log(\max a_i + m))$あるいは$O(n \cdot m)$通るかも知れません、なぜなら$n \le 100$そして$m \le 10000$。 これは、パフォーマンスの問題を心配することなく、貪欲なシミュレーションまたは応答空間に対する二分探索のいずれかを実行できることを意味します。 

将来の結果について理由を考えずに貪欲に人々を分配しようとすると、微妙な失敗例が現れます。 たとえば、新人を常に現在最も負荷の低いベンチに置くことは合理的であるように見えますが、それを容量の問題として形式化しない限り、最適性が直接保証されるわけではありません。 もう 1 つのエッジ ケースは、すべてのベンチが同一である場合です。この場合、最小値と最大値の両方の答えが同じ値に崩れ、慎重に処理しないと、単純な不均等分布の考え方によって誤った推論が生じる可能性があります。 

## アプローチ

 可能な最大値は、$k$は簡単です。 1 つのベンチをできるだけ大きくしたいので、すでに最も多くの人がいるベンチを選択し、全員を割り当てます。$m$そこの新人たち。 人々を他の場所に分散しても、ターゲットベンチに追加される数が減るだけであるため、他の分散では最大値をさらに増やすことはできません。 したがって、最大の場合は完全に初期最大値によって決まります。 

可能な最小値は、$k$より構造化されています。 配布しようとしています$m$ベンチが大きくなりすぎないように。 これは最小の数値を求めるのと同じです$k$すべてのベンチの高さに「キャップ」を付けることができるように$k$新人を適切に配置することによって。 

候補値を固定すると$k$、各ベンチ$i$せいぜい受け入れられる$k - a_i$到着する前にさらに人が増える$k$。 この収容人数をすべてのベンチで合計すると、超過することなく収容できる合計人数が得られます。$k$。 この合計が少なくとも$m$とすると、最大値を維持したまま全員に配布することが可能になります。$k$。 そうでなければ不可能です。 

これにより、問題は単調条件に変換されます。$k$, これは自然に二分探索につながります。

 ## アルゴリズムのチュートリアル

 計算を最大値と最小値の 2 つの独立した部分に分割します。 

### 最大値$k$1. すべてのベンチの最大初期占有率を計算します。 
2. すべて追加$m$同じベンチの新人たち。 
3. 結果の値を返します。 

これが機能するのは、すべての加算を 1 つのベンチに集中させるとグローバル最大値のみが増加し、他の配置がこの構造を超えることができないためです。 

### 最小値$k$1. 検索範囲を設定します。$k$から$\max(a_i)$に$\max(a_i) + m$。 既存の負荷を減らすことはできないため、下限は現在の最大値です。 上限は新人全員が一つのベンチに入るとき。 
2. 候補者が確定した場合$k$、各ベンチが超過することなく追加で何人の人を受け入れることができるかを計算します。$k$、つまり$\max(0, k - a_i)$。 
3. すべてのベンチのこれらの容量を合計します。 
4. 合計容量が少なくとも$m$を超えずにすべての新規ユーザーを配布できることを意味します。$k$、 それで$k$実現可能です。 
5. それ以外の場合は、$k$小さすぎます。 
6. 二分探索を使用して、実行可能な最小値を見つけます$k$。 

### なぜ効果があるのか

 重要な不変条件は、実現可能性が単調であるということです。$k$。 ある場合$k$すべてを許可します$m$配置する人、その後、任意の大きな値$k$また、各ベンチの容量が増えるだけなので、配置も可能になります。 この単調性により、エッジ ケースを見逃すことなく、二分探索が最小の有効なしきい値に収束することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, a, m):
    total = 0
    for x in a:
        if k > x:
            total += k - x
    return total >= m

n = int(input())
m = int(input())
a = [int(input()) for _ in range(n)]

mx = max(a)

# maximum k
max_k = mx + m

# minimum k via binary search
lo, hi = mx, mx + m
while lo < hi:
    mid = (lo + hi) // 2
    if can(mid, a, m):
        hi = mid
    else:
        lo = mid + 1

min_k = lo

print(min_k, max_k)
```このコードは、問題を 2 つの独立した計算にきれいに分割します。 ヘルパー関数`can(k, a, m)`以前に導出された実現可能性条件をエンコードします。 二分検索はインデックスではなく回答空間に対して実行されます。これは、条件が単調であるため安全です。$k$。 

よくある間違いは、`max(0, k - a_i)`ロジックを使用し、代わりに生の差分を合計すると、すでにオーバーフルのベンチからのマイナスの寄与が誤って許可されてしまいます。

 ## 特殊なケース

 主なエッジケースは、ベンチが 1 つしかない場合です。 その場合、すべての新人はそこに行かなければならないため、最小結果と最大結果の両方が同じ値に崩壊します。 容量関数は単一の項に縮小され、二分探索はすぐに次のように収束するため、アルゴリズムはこれを自然に処理します。$a_1 + m$。 

もう 1 つのエッジ ケースは、すべてのベンチにすでに大きな値があり、$m$小さいです。 二分探索は依然として機能します。実現可能性は、わずかに増加したしきい値でもすべての新規参入者を吸収できるかどうかのみに依存し、探索範囲は現在の最大値から始まり、無効な下限推測が考慮されないことが保証されます。 

最後に、すべてのベンチが等しい場合、分布の対称性は、最大値を最小化するために拡散が常に最適であることを意味します。 実現可能性チェックでは、すべてのベンチを同一の容量に寄与するものとして扱うことでこれを自動的に取得するため、検索はバランスの取れたしきい値で正確に収束します。
