 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、1 つの値だけが残るまでそれを繰り返し削減します。 各リダクション ステップでは、2 つの位置の値を乗算してその結果を位置の 1 つに格納することによって 2 つの位置をマージするか、単一の要素を完全に削除しますが、その削除操作は最大 1 回しか使用できません。 

ポジションのインデックス付けは決して変更されません。つまり、一部のポジションが論理的に削除された場合でも、常に元のインデックスを参照します。 ポジションを削除すると、そのポジションは永久に使用できなくなります。 まさにその後$n-1$操作では、値を含む配列セルは 1 つだけなので、最終的な値をできるだけ大きくする必要があります。 

重要な制約は、最終値そのものを出力するように求められるのではなく、可能な最大の結果を達成する有効な一連の操作を出力するように求められるということです。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$これにより、考えられるすべてのマージ順序を試行する戦略は即座に除外されます。 さまざまなエリミネーション ツリーをシミュレートしたり、バックトラッキングを使用して貪欲な決定を試みたりするアプローチは、バイナリ マージ構造だけでも指数関数的に増加するため、遅すぎます。 直線または直線に近い構造が必要です。 

この問題の微妙な点は、単一のオプションの削除操作です。 これは、値を最終積に乗算せずに破棄する唯一の方法です。 これは、ある要素 (通常は最も有害な要素) を乗算に使用するのではなく、削除する必要があることを直ちに示唆します。 

重要なエッジケース:

 常にすべてを掛け合わせる単純な貪欲さは、マイナスがある場合に失敗します。 たとえば、奇数の負の値を指定すると、積が減少します。 1 つのゼロと多数の負の値がある場合、ゼロを削除するか 1 つの負の値を削除するかを選択することで、結果が完全に変わります。 たとえば、$[-5, -4, 0]$、盲目的にすべてを乗算するとゼロになりますが、ゼロを削除すると正の積が得られます。$20$。 

もう 1 つの失敗ケースは、1 つの非ゼロ要素を除いてすべての数値がゼロである場合です。 どのマージ順序でも機能しますが、削除操作を使用すると不必要な乗算を簡素化または回避でき、不注意なロジックにより無駄になったり、置き忘れたりする可能性があります。 

最後に、正の値と負の値の両方を持つ配列では、負のパリティに応じて、最小の絶対値の負を削除するか、潜在的にゼロを削除するかを決定する必要があります。 

## アプローチ

 ブルートフォース解釈では、削除する要素 (または削除しない要素) を選択するすべての可能な方法を検討し、その後、残りの要素をマージするすべての可能な順序を検討します。 各マージは、配列に対するバイナリ ツリーの構築に対応します。 そのような木の数はカタルーニャ語に似た成長をしており、おおよそ指数関数的です。$n$、$n = 40$、ましてや$2 \cdot 10^5$。 

最終的な値が、おそらく 1 つの要素を削除した後に残ったすべての数値の積であることがわかれば、問題の構造は単純化されます。 各マージ操作ではマルチセット積は変更されません。 ステップ間で乗算を再分配するだけです。 したがって、実際に決定するのはどの要素を削除するかということだけです。他のすべての要素を最終結果に乗算する必要があるためです。 

これにより、タスクは、最大 1 つの削除された要素を除くすべての数値の積を最大化することになります。 最適な選択は常に、総積の符号と大きさを最も改善する単一の要素を削除することです。 具体的には、負の値の数が均等になるようにすることを目指します。 すでに偶数である場合は、ゼロ (存在する場合) を削除すると、積がゼロになるのを防ぐことができるため、有益です。 負の数が奇数の場合、符号を反転することに最も寄与しないため、絶対値が最も小さい負の値を削除します。 

削除の選択肢が決まったら、現在の累積値を次に残っている要素に繰り返し乗算することで一連の操作を構築できます。

 ## アルゴリズムのチュートリアル

 1. 配列をスキャンしてインデックスを正、負、ゼロに分類し、絶対値が最小の負も追跡します。 
2. マイナスがいくつ存在するかを数えます。 この数が奇数の場合は、1 つの負の値 (絶対値が最も小さいもの) を削除対象としてマークします。 この選択により、パリティを固定しながら振幅の損失が最小限に抑えられるため、最終的な積が最大になります。 
3. 負の数が偶数の場合は、ゼロが存在するかどうかを確認します。 「はい」の場合は、削除するゼロを 1 つだけマークします。 これにより、最終製品が不必要にゼロになるのを防ぎます。 
4. どちらの条件も当てはまらない場合、削除は行われません。 アレイはすでに最適な構造を持っています。 
5. 削除後に残ったインデックスのリストを作成します。 
6. 最初に残ったインデックスをアキュムレータとして選択します。 このインデックスは、乗算演算を通じて他のインデックスを徐々に吸収していきます。 
7. 残りのインデックスごとに、その値をアキュムレータに乗算してソース インデックスを削除する演算を出力します。 
8. 削除を選択した場合は、乗算演算の前に出力します。削除は、ある時点で実行する必要があり、早めに実行すると、後のマージの妨げにならないからです。 

この構造により、アキュムレータを除くすべての要素が正確に 1 回消費され、アキュムレータが最終製品に成長することが保証されます。 

### なぜ効果があるのか

 すべての操作後の最終値は、常に明示的に削除されなかったすべての要素の積になります。 結合性により、乗算の順序によって結果は変わりません。 したがって、唯一の自由度は、どの単一要素 (存在する場合) を削除するかを選択することです。 負のパリティとゼロの存在に関する貪欲なルールにより、積の符号と大きさが直接最大化されるため、構築されたシーケンスは最適な値を達成する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

neg_indices = []
zero_indices = []
pos_indices = []

min_neg_idx = -1
min_neg_abs = 10**30

for i, v in enumerate(a):
    if v < 0:
        neg_indices.append(i)
        if abs(v) < min_neg_abs:
            min_neg_abs = abs(v)
            min_neg_idx = i
    elif v == 0:
        zero_indices.append(i)
    else:
        pos_indices.append(i)

delete_idx = -1

# if odd negatives, delete the smallest abs negative
if len(neg_indices) % 2 == 1:
    delete_idx = min_neg_idx
else:
    # if even negatives, prefer deleting a zero
    if zero_indices:
        delete_idx = zero_indices[0]

ops = []

# perform deletion first if chosen
if delete_idx != -1:
    ops.append((2, delete_idx + 1))

# build remaining list
alive = []
for i in range(n):
    if i != delete_idx:
        alive.append(i)

# if only one element remains
if len(alive) == 1:
    for op in ops:
        print(op[0], op[1])
    exit()

root = alive[0]

for i in alive[1:]:
    ops.append((1, root + 1, i + 1))

for op in ops:
    print(*op)
```このコードは、どの要素を削除するかを迅速に決定するために、インデックスを 3 つのグループに分割します。 削除の決定はマージ チェーンを構築する前に計算され、最終的な製品構造の正確性が保証されます。 

残りの要素は単純なチェーンに接続され、最初の生きたインデックスが他のすべてのインデックスを吸収します。 これにより、この問題がマージの形状に制約を与えないため、複雑なツリーを構築する必要がなくなります。 

一般的に微妙な点は、操作が 1 ベースであるのに対し、内部ストレージは 0 ベースであるため、インデックス付けを正しく処理することです。 もう 1 つの微妙な点は、削除が最大 1 回だけ行われるようにすることです。これは、単一の`delete_idx`。 

## 実用的な例

 ### 例 1

 入力:```
5
5 -2 0 1 -3
```We classify elements and decide deletion.

 | ステップ | ネガティブ | ゼロ | 選択肢を削除 | アライブセット |
 | --- | --- | --- | --- | --- |
 | イニシャル | 2 | 1 | まだありません | すべて |
 | 決定 | 偶数のマイナス | ゼロが存在します | ゼロを 1 つ削除 | 0 のインデックスを削除 |

 After deletion, we connect remaining elements:

 | 操作 | アクション |
 | --- | --- |
 | 2 3 | ゼロを削除する |
 | 1 1 2 | 5 は -2 を吸収 |
 | 1 2 4 | intermediate product absorbs 1 |
 | 1 4 5 | 最終吸収 |

 This produces a positive maximum product of 30.

 トレースは、ゼロを削除すると積の崩壊が回避され、ゼロ以外のすべての値が寄与できることがわかります。 

### 例 2

 入力:```
3
-1 -2 4
```マイナスが 2 つあるため、パリティはすでに均等です。 削除する必要はありません。 

| ステップ | ネガティブ | 選択肢を削除 | アライブセット |
 | --- | --- | --- | --- |
 | イニシャル | 2 | なし | すべて |

 次に、順番にマージします。 

| 操作 | 状態変化 |
 | --- | --- |
 | 1 1 2 | -1 は -2 を吸収し 2 になります |
 | 1 1 3 | 2 が 4 を吸収して 8 になります |

 最終結果は 8 ですが、すべての値が使用されるため、これが最適です。 

これは、負のパリティがすでにバランスされている場合、すべての要素を維持すると最良の製品が得られることを確認します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列に 0 以外の要素が 1 つだけ含まれ、多数の 0 が含まれる場合です。 アルゴリズムは、ゼロを削除し、非ゼロ要素をアキュムレータとして残すことを選択します。 入力用`[5, 0, 0]`、削除するとゼロが削除され、マージではゼロを乗算せずに最終値として 5 が単純に伝播されます。 

もう 1 つのケースは、ゼロがなく、負の値が 1 つだけある場合です。 のために`[3, -2, 4]`、アルゴリズムは削除します`-2`それは唯一のマイナスであり、それを除去すると製品がプラスになるからです。 残りの乗算チェーンは次のようになります。`12`。 

最後の微妙なケースは、すべての数値がゼロの場合です。 で`[0, 0, 0, 0]`、意味のある負のパリティの決定はありません。 このアルゴリズムは 1 つのゼロを削除し、残りを連鎖させて、正確に 1 つの値が残り、ゼロのままであることを保証します。
