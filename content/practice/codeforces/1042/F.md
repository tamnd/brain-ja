 ## 問題の理解

 いくつかの頂点だけが重要な木が与えられています。つまり、次数がちょうど 1 の頂点、つまり葉と呼ばれるものです。 このタスクはすべての頂点をグループ化することではなく、これらの葉をグループ化することだけを目的としています。 

各グループは、ツリー メトリック内の幾何学的制約を満たす必要があります。 同じグループ内の任意の 2 つの葉を取得する場合、木に沿った葉の間の距離は最大でも$k$。 この制約の下ですべてのグループが有効になるように、すべてのリーフを素のグループに分割する必要があり、使用するグループの数を最小限に抑えたいと考えています。 

入力サイズは最大です$10^6$これにより、直ちに線形または線形に近い解が強制されます。 リーフ間のペアワイズ距離を計算しようとするアプローチは、間接的であっても失敗します。これは、リーフの数が線形になる可能性があるためです。$n$、ペアワイズ推論は二次的な動作につながります。 同様に、距離を繰り返し再計算したり、各リーフから BFS を実行したりするソリューションは実行不可能です。 

微妙な点は、ツリー構造自体は大きいですが、グループ化に関連するのは葉だけであることです。 ただし、内部頂点はリーフ間の距離を決定するため、依然として重要です。 

グローバル構造を考慮せずにローカルでリーフを貪欲にグループ化しようとすると、単純な失敗モードが発生します。 たとえば、すべての葉が中心に接続されている星形の木では、葉のすべてのペアの距離は 2 になります。$k = 1$2 つのリーフをグループ化することはできませんが、隣接性によってリーフをグループ化する貪欲なアプローチでは、中心を介してリーフが誤ってマージされてしまいます。 逆に、もし$k$が大きい場合でも、異なる枝からの葉が直径制約に違反すると、サブツリーの近接性によるグループ化が失敗する可能性があります。 

長い連鎖の中で別の失敗ケースが発生します。 リーフは端点にのみ存在し、サブツリーの境界に基づく単純なクラスタリングでは、チェーンに沿って蓄積される距離を簡単に過小評価する可能性があります。 

## アプローチ

 直接的な強引なアイデアは、リーフ間のすべてのペアごとの距離を計算し、各セットの直径が最大になる最小数のセットにそれらを分割しようとすることです。$k$。 これは、エッジの重みがツリー内の距離である、リーフの完全なグラフ上のグラフ分割問題になります。 距離行列コストの計算さえも$O(L^2)$どこ$L$は葉の数です。$O(n)$、これは二次関数となり不可能になります。 

距離が利用可能な場合でも、分割ステップは、最小数の直径境界クラスターで計量空間内の点をカバーすることと同等であり、これは一般的な計量では NP 困難です。 したがって、ブルート フォースは遅すぎるだけでなく、構造的にツリー メトリックと一致していません。 

重要な観察は、ツリー メトリックがどのパス構造に沿っても 1 次元であり、葉から葉までの距離が最も低い共通の祖先によって決定されるということです。 すべてのペアについて直接推論する代わりに、問題を DFS 順序に沿ったリーフのペアリング プロセスに変換できます。 

木を根付かせると、すべての葉には明確に定義された深さがあります。 葉から上に向かって歩き、ツリー内の各グループの「スパン」が範囲内に収まるように葉をグループに一致させることを検討してください。$k$。 すべてのペアごとの距離を明示的に維持する代わりに、グループとの互換性を保ちながらリーフが「上向きに到達」できる距離を維持します。 

より構造的な再定式化は、DFS トラバーサルでリーフを貪欲にペアリングするという観点から考えることです。サブツリーの処理が完了すると、一致しないリーフに関する情報が上方に運ばれます。 このような 2 つの部分構造を組み合わせるたびに、それらの距離が 2 を超えるかどうかに応じて、それらを 1 つの有効なグループにマージできるか、それとも分離したままにしておく必要があるかを決定します。$k$。 

これにより、問題はツリー上のローカル結合問題に変わり、各エッジが距離の累積に寄与します。 重要なアイデアは、最適なソリューションでは、同じグループ内のリーフがペアごとのパスの観点から接続された領域を形成し、サブツリーごとに制限された数の「アクティブなリーフ」のみを追跡しながら、このボトムアップ処理ができるということです。

 ## アルゴリズムのチュートリアル

 任意の頂点 (通常は 1) でツリーをルート化し、DFS を実行します。 

各サブツリーは、サブツリー内の完全なグループに完全に割り当てられていないという意味で、まだ「未解決」のリーフに関する情報を返します。 

1. DFS をルートから実行し、各ノードをその子からの結果を結合したものとして扱います。 葉のグループは木の何らかの接続された領域にある葉によって形成されるため、これは自然なことです。 
2. 各ノードについて、その子からのすべての候補「アクティブ リーフ パス」を収集します。 このような各値は、そのサブツリー内のリーフと、そのリーフから現在のノードまでの距離を表します。 この抽象化により、以下のすべての内部構造が単一の距離値に圧縮されます。 
3. 異なる子からのこれらの候補リストをマージします。 マージ中は、距離が遠いほど最初に制約に違反するリスクがあるため、常に最も離れたリーフを貪欲にペアリングしようとします。 これは、候補を深さによってソートし、極端なものを一致させようとすることと同じです。 
4. 距離のある 2 つの候補葉を検討するときはいつでも$a$そして$b$このノードを介してペアになっている場合、現在のノードからのツリー内の距離は次のようになります。$a + b$。 この値が最大でも$k$、それらは同じグループに属することができ、それらをペアとして削除します。 
5. 合計額を超える場合$k$、それらをマージすることはできず、より深いものは上に渡される未解決の候補として残らなければなりません。 もう一方も、どこかでマージする可能性がまだある場合には保持されますが、実際には、貪欲な構造により、最小限の代表セットのみを上に運ぶことが保証されます。 
6. ノードのすべての子を処理した後、上に移動することを考慮して深さを 1 つ増やして、一致しない残りの候補を返します。 
7. 最後に、ルートで、残りのすべての候補は、制約内でペアにすることができないグループのエンドポイントを表します。 グループの数は、そのようなエンドポイントが残っている数から導出され、DFS 中に正常に形成されたペアの数によって調整されます。 

### なぜ効果があるのか

 重要な不変条件は、サブツリーから返されたすべての候補が、そのサブツリー全体の内部の完全な有効なグループにまだ割り当てられていないリーフを表しており、その格納値が現在の部分ペア構造の最深点までの正確な距離であることです。 

ツリー内の有効なグループはすべて、最下位の共通祖先を介して接続されている必要があるため、実行可能なすべてのペアは、LCA でマージ候補として表現できなければなりません。 貪欲な戦略では、常に最も制限の厳しいペアを最初に解決しようとし、最適なソリューションでペアリングが可能であれば、以前の決定によってブロックされないようにします。 ツリー構造では、特定のノードで 2 つのリーフが離れすぎると、その後の祖先がその距離を縮めることができないことが保証されるため、ローカルでペアリングしなくても安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    INF = 10**18
    ans = 0

    def dfs(u, p):
        nonlocal ans
        cur = []

        for v in g[u]:
            if v == p:
                continue
            child = dfs(v, u)
            for d in child:
                nd = d + 1
                if nd <= k:
                    cur.append(nd)

        cur.sort()

        i, j = 0, len(cur) - 1
        while i < j:
            if cur[i] + cur[j] <= k:
                i += 1
                j -= 1
                ans += 1
            else:
                j -= 1

        res = []
        while i <= j:
            res.append(cur[i])
            i += 1

        return res

    dfs(1, -1)
    print(ans)

if __name__ == "__main__":
    solve()
```DFS は、各サブツリーの葉の深さの候補のリストを返します。 各深さは、リーフが現在のノードからどれだけ離れているかを表します。 上に移動するときに子の深さを 1 つ増やします。これにより、実際のツリーの距離が維持されます。 

ソートにより、残っている最小の候補と最大の候補を貪欲に一致させることができます。これは、最小の候補が最大の候補とペアにできない場合、それより大きな候補とペアにすることもできないため、最適です。 

ペアリングが成功するたびに、現在のノードをルートとするサブツリー内で直径制約が満たされる 1 つの完全なグループが形成されるため、答えが増加します。 

返されたリストには、ペアになっていない候補 (ツリーの上位で解決されるグループの潜在的なエンドポイント) のみが保持されます。 

ツリーは長さのチェーンになる可能性があるため、再帰制限が増加します。$10^6$そうでないと、Python のデフォルトの再帰スタックがオーバーフローしてしまいます。

 ## 特殊なケース

 純粋なパス グラフでは、すべてのリーフが長いチェーンの終点になります。 このアルゴリズムは、単一の候補距離を運びながら、下から上に向かって処理します。 各ステップでは、ルートに到達するまでペアリングはできません。ルートで最終的なペアリングの決定が行われ、正しい最小限のグループ化が生成されます。 

星型グラフでは、すべての葉が根元で交わるので、すべての距離は正確に 2 になります。$k \ge 2$、根はすぐに貪欲な方法で葉を組み合わせます。 もし$k < 2$、ペアリングは発生せず、すべてのリーフが独自のグループになります。 DFS は、LCA が最小になるノードでペアリングが常にチェックされるため、両方の結果が一貫して処理されることを保証します。
