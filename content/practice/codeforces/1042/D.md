 ## 解決策

 ## 問題の理解

 行に配置された一連の整数が与えられており、この行の連続する断片に興味があります。 考えられるすべてのフラグメントについて、その合計を計算し、合計が指定されたしきい値よりも厳密に小さいフラグメントがいくつあるかを数える必要があります。 

直接の解釈は簡単です。開始位置と終了位置のすべての選択が 1 つのセグメントを定義し、それらのセグメントのうちのいくつが制限を下回る合計を生成するかを知りたいと考えます。 

入力サイズによっては、より慎重なアプローチが必要になります。 要素数が最大 200,000 個の場合、セグメント数は n² のオーダーとなり、最悪の場合でもすでに約 200 億に達します。 すべてのセグメントを明示的に検査するメソッドは、Python や最適化された C++ でさえ 2 秒で処理できる速度をはるかに超えています。 これにより、線形または線形に近い戦略、通常は 2 ポインター手法やプレフィックス合計ベースのカウント方法のような戦略が採用されます。 

負の数の存在が重要な問題です。 すべての数値が負でない場合、スライディング ウィンドウは単調に動作し、単一の拡大および縮小ウィンドウを維持できます。 ここで、負の値は単調性を壊すため、合計の増加に依存する単純な 2 ポインタ アプローチを直接適用することはできません。 

しきい値が非常に大きいか非常に小さい場合、微妙なエッジ ケースが発生します。 t が非常に大きい場合は、すべてのセグメントが有効であり、正しい解は依然として n(n+1)/2 を効率的にカウントする必要があります。 t が非常に小さいか負の場合、少数のセグメントまたは単一の要素だけが適格となる可能性があり、負の和を正しく処理しないと、簡単に過大カウントまたは過少カウントが発生する可能性があります。 

素朴な直感が失敗する小さな例は次のとおりです。 

入力:```
3 1
2 -5 3
```正しいセグメントは次のとおりです。`[1,2] = -3`、`[2,2] = -5`、`[2,3] = -2`、`[3,3] = 3`は無効なので、答えは 3 です。合計が大きすぎる場合にのみ右に移動する素朴な拡張ウィンドウは失敗します。これは、合計が負の値から減少するのは単調ではないためです。 

## アプローチ

 ブルート フォース手法では、エンドポイントのすべてのペア (l、r) が考慮され、そのセグメントの合計が計算され、それが t より小さいかどうかがチェックされます。 これは問題の定義と直接一致するため、正しいです。 ただし、各セグメントの合計を単純に計算すると O(n) のコストがかかり、合計時間は O(n³) になり、プレフィックスの合計を使用する場合は O(n²) になります。 O(n²) でさえ 200,000 要素には大きすぎます。 

重要な観察は、プレフィックスの合計の観点から問題を再構成できるということです。 S[i] を最初の i 要素の合計として定義すると、セグメント [l, r] の合計は S[r] − S[l−1] となります。 条件は S[l−1] > S[r] − t になります。 固定 r ごとに、以前のプレフィックスの合計が S[r] から導出されたしきい値を超える回数を数えたいとします。 

これにより、問題は、位置ごとに、特定の境界を超えた以前の値がいくつあるかを数えるという問題に変換されます。 これまでに見られたプレフィックス合計のソートされた構造を維持すると、このカウントを効率的にクエリできます。 プレフィックスの合計を順番に処理するため、バイナリ インデックス付きツリーまたは順序統計構造を使用できます。 ただし、動的挿入クエリを使用せずにそのようなペアを O(n log n) でカウントする、より直接的で最適な分割統治手法があります。 

このタスクを、i < j および S[j] − S[i] < t であるペア (i, j) を数えるように縮小します。これは、S[i] > S[j] − t と同等です。 これは、プレフィックス合計に関する古典的な反転カウントのバリアントであり、マージ中にクロスペアをカウントする修正されたマージ ソートを使用して解決できます。 

ブルート フォース アプローチはシンプルですが二次的ですが、プレフィックスサム + 分割統治アプローチは問題をカウントによるソートに軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(1) または O(n) | 遅すぎる |
 | プレフィックス + マージ ソート カウント | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題をプレフィックスの合計に変換し、分割統治を使用してペアを数えます。 

1. プレフィックス合計 S の配列を構築します。ここで、S[0] = 0、S[i] は最初の i 要素の合計です。 これにより、セグメントの合計が 2 つのプレフィックス値の差に変換されます。 
2. 条件を再定式化します。 S[r] − S[l−1] < t の場合、セグメント [l, r] の合計は t となり、S[l−1] > S[r] − t に再配置されます。 ここで、この不等式を満たすプレフィックス インデックスのペアを数えます。 
3. プレフィックス合計配列に対して変更されたマージ ソートを実行します。 目的は、ソートするだけでなく、左半分と右半分の間で交差する有効なペアの数をカウントすることです。 
4. マージ ステップ中に、右半分の各要素について、S[左] > S[右] − t を満たす左半分の要素の数を決定します。 両方の半分がソートされているため、要素ごとにやり直すことなく、左半分にポインタを移動できます。 
5. すべてのマージ ステップにわたってこれらのカウントを累積します。 有効な各ペアは、その 2 つのエンドポイントが再帰的分割で分割されるときに 1 回だけカウントされます。 
6. より高いレベルの再帰でも境界を越えたペアを正しくカウントできるように、ソートされた半分のマージを続けます。 

### なぜ効果があるのか

 正しさは 2 つの事実から得られます。 まず、すべてのセグメントがプレフィックス インデックスのペアに一意に対応するため、プレフィックス ペア以外で有効な答えが失われたり重複したりすることはありません。 第 2 に、各マージ ステップ内で、並べ替えられた順序により、すべての組み合わせをスキャンすることなく、すべての有効なクロス ペアを効率的にカウントできます。 各ペアは再帰レベルで 1 回だけ考慮され、2 つのインデックスが異なる半分に分離されるため、完全性が保証され、二重カウントが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, t = map(int, input().split())
    a = list(map(int, input().split()))

    prefix = [0]
    for x in a:
        prefix.append(prefix[-1] + x)

    def sort_count(arr):
        if len(arr) <= 1:
            return arr, 0

        mid = len(arr) // 2
        left, cnt_left = sort_count(arr[:mid])
        right, cnt_right = sort_count(arr[mid:])

        cnt = cnt_left + cnt_right

        j = 0
        for r in right:
            while j < len(left) and left[j] <= r - t:
                j += 1
            cnt += len(left) - j

        merged = []
        i = j = 0
        while i < len(left) and j < len(right):
            if left[i] < right[j]:
                merged.append(left[i])
                i += 1
            else:
                merged.append(right[j])
                j += 1

        merged.extend(left[i:])
        merged.extend(right[j:])
        return merged, cnt

    _, ans = sort_count(prefix)
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、すべてのセグメントの合計が 2 つのプレフィックス値の差になるようにプレフィックスの合計を構築することから始まります。 再帰関数は、プレフィックス部分配列のソートされたバージョンとその中の有効なペアの数の両方を返します。 

重要な部分は、マージ中のカウント ループです。 右半分の各値について、左半分にポインタを移動して、不等式を満たす値の数を見つけます。 これが機能するのは、両方の半分がソートされているため、ポインタは前方にのみ移動します。 

マージ ステップでは、並べ替えられた順序が保持されます。これは、より高い再帰レベルでの正確性のために必要です。 よくある間違いは、不等号の方向を混同することです。 ここでは、プレフィックスの違いに一致するように条件を慎重に変換します。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
5 4
5 -1 3 4 -1
```プレフィックスの合計は次のとおりです。```
[0, 5, 4, 7, 11, 10]
```マージカウントを高レベルで追跡します。 

| ステップ | 左半分 | 右半分 | ポインタ j の位置 | 新しいペアのカウント |
 | --- | --- | --- | --- | --- |
 | マージ | [0,4,5] | [7,10,11] | 左に移動 | スプリット全体で有効なペアをカウントします |

 各右側の要素は、prefix[i] > prefix[j] − 4 を満たす左側の要素のカウントをトリガーします。たとえば、プレフィックス値 7 の場合、しきい値は 3 で、3 より大きい有効な左側の値がカウントされます。 

これにより、パーティション境界を越えるすべての条件を満たすセグメントが 1 回だけ含まれることが確認されます。 

次に、小さなカスタム例を考えてみましょう。```
3 1
2 -5 3
```プレフィックス:```
[0, 2, -3, 0]
```アルゴリズムは有効なペアを識別します。 

- (0,1)、(1,2)、(1,3) 不等号チェックに応じて

 マージ ステップでは、負の値であっても順序が保持され、すべての比較が有効なままであることが保証されます。

 ## 特殊なケース

 サイズ 1 の最小配列は、アルゴリズムが単一のプレフィックス ペアを正しく処理するかどうかを明らかにします。 入力用`n = 1`、`t = 0`、`a = [5]`、プレフィックスは`[0, 5]`。 唯一のセグメントは、`[5]`これはゼロ以上なので、答えは 0 です。厳密な不等式の解釈では 5 > 0 − 0 は false であるため、マージベースのカウントでは有効なペアが生成されず、正しく 0 が返されます。 

完全にネガティブな配列は、すべてのセグメントが有効であるか、ほとんどすべてが有効である場合に正確さを強調します。 のために`[-1, -2, -3]`と`t = 1`、すべてのプレフィックスの合計が減少しており、2 つのインデックス間のすべての差が負であるため、6 つのセグメントすべてが該当します。 分割統治のカウントにはプレフィックス インデックスのすべてのペアが含まれており、順序が厳密に減少している場合でも不等式の処理が引き続き有効であることが確認されます。 

次のような混合符号配列`[2, -5, 3]`アルゴリズムが単調なプレフィックス動作に依存しないようにします。 プレフィックス配列は変動しますが、比較は元のインデックスの順序ではなく値の順序のみに基づいているため、マージ ソート内のソートされた構造により正しいカウントが保証されます。
