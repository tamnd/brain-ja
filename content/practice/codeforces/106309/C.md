 ## 解決策
 ## 問題の理解

 限られた量の生地と数種類のパンが与えられます。 各バンズのタイプは一定量の生地を消費します。また、フレーバーバンズの場合は、限られた量の特定のフィリングも消費します。 各パンは一定の利益をもたらします。 さらに、生地のみを使用し、無制限に供給できる「プレーン」バンズ タイプが 1 つ追加されていますが、各フレーバー タイプはさらに、利用可能なフィリングの量によって制限されます。 

課題は、生地を超えず、各フィリングの利用可能な量を超えずに、総利益を最大化するために、各種類のパンを何個焼くかを決定することです。 

難しいのは、すべての選択肢が単一の共有リソースである生地を通じて相互作用する一方で、各フレーバーの種類には独自の独立したキャップがあることです。 

制約は小さく、生地は最大でも約 1000、フレーバーの数は最大でも 10 です。これにより、フレーバーごとの正確な量を求める指数関数的な検索は即座に排除されます。これは、中程度の分岐係数でも爆発的に増加するためです。 純粋に貪欲なアプローチも安全ではありません。なぜなら、餡1グラムあたりの利益が高いバンズは、生地を消費しすぎて、より高い総利益をもたらす他のバンズの組み合わせを妨げる可能性があるからです。 

微妙な失敗例は、パンごとの利益による強欲なランキングが誤解を招く場合に現れます。 

たとえば、あるパンは利益は高いが生地の消費が多すぎるとします。一方、別のパンは利益はわずかに低いものの、生地の使用効率がはるかに高いとします。 常に目先の利益が最も高いものを選択する貪欲な戦略は、生地を早期に使い果たしてしまい、より良い全体的な組み合わせを逃す可能性があります。 

もう 1 つのよくある落とし穴は、各パンを個別に扱い、種類ごとにできるだけ多く摂取することです。 これは、あらゆる種類のパンをもう 1 つ摂取すると、他のすべてのパンの全体的な容量が減少するということを無視しています。 

## アプローチ

 重要な観察は、フレーバーの種類の数が非常に少ないため、それらを各種類のバンズの数を決定する層として扱うことができ、残りの生地に関する一次元の最適化に他のすべてが崩壊するということです。 

強引なアイデアとしては、各フレーバーのバンズの数をすべて組み合わせて試してみるというものです。 各フレーバー i について、0 から min(ai, n / ci) 個のバンズを取得できます。 これを直接試みると、状態の数はフレーバーごとに最大 100 個の選択肢のおおよその積となり、これは天文学的に大きくなります。 

私たちを救ってくれる構造は、各種類の味付きバンズの数を決めてしまえば、残りの問題は取るに足らないものになるということです。残りの生地はすべてプレーンバンズに費やす必要があります。 これにより、問題全体が、最大 10 個の項目にわたって制限されたナップザックの選択肢を選択することになり、各項目には制限された多重度および生地の線形コストが設定されます。 

すべての組み合わせを列挙するのではなく、標準の有界ナップザック分解トリックを使用して、各フレーバーを個別に最適化します。 各フレーバーパンは一定の利益をもたらし、一定量の生地を消費しますが、ai/bi アイテムを超えることはできません。 これにより、各フレーバーが制限された項目セットに変換され、問題全体が容量 n を超えるナップザックになります。 

プレーンパンは単に無限に供給されるアイテムなので、自然に DP の余剰容量を埋めます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのフレーバー数の完全な列挙 | m と ai の指数 | O(1) おまけ | 遅すぎる |
 | 分解されたアイテムの上に縛られたナップザック | 写真 O(n · 分解された項目の合計) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各フレーバーパンは、最大 ai / bi 回使用できるアイテムとして解釈します。 これにより、「充填に関するリソース制約」が、各項目を何回取得できるかという単純な上限に変換されます。 
2. 最大数のバイナリ分割を使用して、各フレーバーを複数の 0 ～ 1 アイテムに変換します。 これにより、すべてのカウントを繰り返すことなく、大きな制限を効率的に処理できるようになります。 
3. 動的プログラミング配列 dp を作成します。ここで、dp[x] は、正確に x グラムの生地を使用して達成可能な最大利益を表します。 dp[0] = 0 を除くすべての状態を到達不能として初期化します。 
4. 変換されたすべてのアイテムを反復処理し、生地の使用量の降順で DP を更新します。 これにより、1 回の遷移で同じ項目が複数回再利用されることがなくなり、0-1 動作の正確さが維持されます。 
5. 全ての味付きバンズを加工した後、プレーンバンズを最終の綴じられていない商品として扱います。 プレーン バンズのコストと利益を繰り返し追加する遷移を許可することで dp を緩和します。または、同様に、残りの生地の使用量をすべて試してプレーン バンズを充填することで、可能な限り最良の組み合わせを事前計算します。 
6. 最終的な答えは、残った生地がいつでもプレーンなバンズに変換できることを考慮した後の、すべての dp 状態にわたる最大値です。 

DP を通じて不変なのは、dp[x] が常に、アイテムのプレフィックスを処理した後に正確に x 単位の生地を使用して達成可能な最高の利益を表すということです。 利用可能なフレーバーバンズの多様性を決して超えず、生地の合計を超えることもないため、各移行は実現可能性を維持します。 

正確さは、すべての有効なベーキング プランが、境界のあるフレーバー アイテムのマルチセットといくつかのプレーン バンズの選択に対応するという事実にかかっており、この表現はナップサックの状態によって完全にキャプチャされています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())

    items = []

    for _ in range(m):
        a, b, c, d = map(int, input().split())
        max_cnt = min(a // b, n // c)
        k = 1
        while max_cnt > 0:
            take = min(k, max_cnt)
            items.append((take * c, take * d))
            max_cnt -= take
            k <<= 1

    dp = [-10**18] * (n + 1)
    dp[0] = 0

    for cost, val in items:
        for j in range(n, cost - 1, -1):
            if dp[j - cost] != -10**18:
                dp[j] = max(dp[j], dp[j - cost] + val)

    best = 0
    for used in range(n + 1):
        if dp[used] < 0:
            continue
        remaining = n - used
        best = max(best, dp[used] + (remaining // c0) * d0)

    print(best)

if __name__ == "__main__":
    solve()
```DP 配列はバンズの数ではなく生地の使用量によってインデックス付けされるため、異なるバンズの種類間の相互作用が明確になります。 各フレーバー型はバイナリ分割を使用して展開されるため、フレーバーが何度も使用される場合でも内部ループの効率が維持されます。 

最後のループは重要です。DP はフレーバー付きバンズのみを考慮するため、残りの生地をプレーン バンズに明示的に変換します。 dp[n] だけが必ずしも最適であるとは限らないため、このステップを忘れると誤った答えが発生する原因になります。 

## 実用的な例

 ### 例 1

 入力:```
10 2 2 1
7 3 2 100
12 3 1 10
```最初のフレーバーを処理します。これにより、最大 2 個のバンズが許可されます (7/3 = 2 であるため)。 1号パン、2号パンに対応したアイテムを作成します。 2 番目のフレーバーについても、同様にその限界を分解します。 

DP の後、最良の状態を追跡します。 

| 使用済み生地 | 最高の利益 |
 | --- | --- |
 | 0 | 0 |
 | 2 | 100 |
 | 4 | 200 |
 | 5 | 210 |
 | 6 | 220 |
 | 8 | 230 |

 次に、コスト 2、利益 1 のプレーン バンズを追加します。 

各状態ごとに、残りの生地が変換されます。 

たとえば、使用済み = 8、残り = 2 の場合、利益が 1 つ追加され、231 となります。すべての状態で最高の値は 241 となり、味付きバンズとプレーン バンズの最適な組み合わせと一致します。 

このトレースは、フレーバー付きの決定だけでは不十分であり、残りの変換が最適性を最終的に決定するものであることを示しています。 

### 例 2

 入力:```
100 1 25 50
15 5 20 10
```味付きタイプは1種類のみです。 フレーバーバンズは最大3個です。 

| 使用済み生地 | 利益 |
 | --- | --- |
 | 0 | 0 |
 | 20 | 10 |
 | 40 | 20 |
 | 60 | 30 |

 次に、残りの生地にプレーンなバンズを詰めます。 

使用済み = 60、残り = 40 でプレーン パン 1 個が得られます。 

合計は、基本構造に追加される 40 + 30 = 70 相当のゲインになりますが、代わりに最適な解決策では、フレーバー付きバンズを完全にスキップし、プレーン バンズのみを使用することを選択し、200 を生成します。 

これは、味付きパンが入手可能であっても、自動的に有益になるわけではないことを示しています。

| スペース | O(n) | 生地容量に対する DP 配列 |

 ## 特殊なケース

 特殊なケースの 1 つは、フレーバー付きバンズがプレーンなバンズよりも厳密に劣る場合です。 入力```
5 1 1 10
5 1 1 1
```これにより、DP はフレーバー付きオプションを検討しますが、最後の変換ステップでは、それを完全にスキップすることが最適であることが保証され、より小さい混合値ではなく 50 が生成されます。 

もう 1 つのケースは、味付きバンズをまったく使用しない場合の最良の解決策です。 DP は、フレーバー付きの使用に対して 0 を正しく返し、プレーン バンズへの完全な変換を許可する必要があります。 最後のループで「used = 0」状態を考慮しないと、ソリューションはオールプレーンの最適な構成を誤って見逃してしまいます。 

3 番目のケースは、風味豊かなバンズが生地を正確に満たし、残りが残らない場合に発生します。 最終的な変換項がゼロになるため、アルゴリズムは引き続き機能し、干渉なしに DP のみが結果を決定します。
