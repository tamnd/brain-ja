 ## 問題の理解

 長さのシーケンスを構築しています`n`を使用して`m`から番号が付けられた個別のラベル`0`に`m-1`ただし、シーケンス内でラベルが繰り返されないという制限があります。 したがって、それぞれの有効なシーケンスは本質的に、順序付けられた選択です。`n`～からの異なる要素`m`、つまりサイズの順列`n`から引き出された`m`。 

このようなシーケンスごとに、すべてのプレフィックスを調べます。 プレフィックスの場合、そのプレフィックスに現れない最小の非負の整数である mex を計算します。 次に、これらの mex 値をすべてのプレフィックス長にわたって合計します。`1`に`n`、これをシーケンスのスコアと呼びます。 タスクは、すべての有効なシーケンスのスコアの合計を計算することです。 

制約は大きいです:`n`100万まで上がるし、`m`10億まで上がります。 これにより、順列を反復したり、値に比例する値を処理したりするアプローチは即座に除外されます。`m`。 解決策は以下にのみ依存する必要があります`n`全範囲に触れないようにしてください`[0, m)`明示的に。 二次関数の何か`n`も安全ではないため、代数的単純化の後、最終的な式は線形または線形に近い計算に帰着する必要があります。 

一般的な失敗例は、順列全体で mex を直接シミュレートしようとした場合に発生します。 などの小さな例でも、`n = 3, m = 5`、ブルート世代はすでに生成しています`P(5,3) = 60`シーケンス、プレフィックスごとの mex の計算は、おもちゃの入力に対してのみ管理可能です。 このアイデアを拡張することはすぐに失敗します。 

もう 1 つの微妙なエッジ ケースは、ラベルが次のものであるという誤解です。`0`に`m-1`。 いくつかの素朴な解釈では、`0..n-1`ただし、ここでは未使用の大きな値が重要です。これは、並べ替えの初期に小さな数値が出現する頻度に影響し、mex の増加に直接影響するためです。 

## アプローチ

 ブルートフォース手法では、長さの有効な順列がすべて生成されます。`n`から`m`要素。 各順列について、次からスキャンしてすべてのプレフィックスの mex を計算します。`0`欠損値が見つかるまで上向きに続けます。 ハッシュ セットを使用してプレフィックスごとの mex が最適化されたとしても、少なくとも少なくとも料金を支払います`O(n)`順列ごとに、`P(m, n)`順列。 これは小規模であっても天文学的に増加します`n`, したがって、このアプローチは実行不可能です。 

重要な構造上の観察は、mex はプレフィックスに出現する小さな値のみに依存し、存在を超えた順序には依存しないということです。 プレフィックスの mex は少なくとも`k`まさにすべての値が`0..k-1`はそのプレフィックスに存在します。 これにより、mex をインジケーター イベントの合計として言い換えることができます。 

mex を直接計算する代わりに、各しきい値が何回あるかをカウントするようにプレフィックスの寄与を書き換えます。`k`すべての順列にわたってプレフィックス内で「完全に満たされる」。 これは、非線形関数を単純な組み合わせ条件の合計に変換します。

 ## アルゴリズムのチュートリアル

 mex 合計をしきい値からの寄与に変換します`k`、 どこ`k`すべての値が一致するイベントを表します`0..k-1`プレフィックスにすでに存在します。 

1. プレフィックスの mex を、次の指標の合計として表現します。`k`、ここで、`k`-th インジケーターは、プレフィックスにすべての数字が含まれている場合に true になります。`0..k-1`。 これにより、合計の答えが次の合計に変換されます。`k`その条件を満たすプレフィックス構成の数。 
2. 固定の場合`k`、長さのプレフィックスが何通りあるかを数えます`i`すべての要素が含まれています`0..k-1`、完全なシーケンスは長さの有効な順列のままです。`n`。 
3. プレフィックス内のどの位置にこれらが含まれるかを選択します。`k`特殊な要素を追加し、残りのプレフィックスとサフィックスを残りの任意の要素で埋めます。 これにより、階乗スタイルの項の積が得られます。 
4. 組み合わせ論を単純化した後、アルファベットのサイズへの依存性`m`は、整数の連続セグメントの積のみを含む因子にきれいに分離されますが、組み合わせプレフィックス構造は二項係数のみに依存します。 
5. 次に、既知の恒等式を使用してすべてのプレフィックス長を暗黙的に合計します。対角線に沿った二項係数の合計は単一の二項係数に集約され、合計の 1 次元が削除されます。 
6. 最終的な式は単一の合計になります。`k`から`1`に`n`ここで、各項は 3 つの部分の積です。`k`、のみに依存する二項係数`n`、およびそれに応じた接頭辞と積の比率`m`そして`n`。 
7. 階乗と逆階乗を最大で事前計算します。`n+1`二項係数の場合、範囲を表すシフトされた配列に対して前置積を事前計算します。`[m-n+1, m]`項ごとに O(1) で大数の積比を評価します。 

### なぜ効果があるのか

 正しさは 2 つの不変条件から得られます。 まず、mex 分解により、すべてのプレフィックスがしきい値ごとに 1 回だけ寄与することが保証されます。`k`これは完全に満たされるため、過剰カウントは発生しません。 次に、組み合わせカウントでは、最初のすべての配置が処理されます。`k`順列全体で対称的に数値を計算し、各有効な順列構成が関連するプレフィックス長ごとに 1 回だけカウントされるようにします。 代数的リダクションにより、置換構造への明示的な依存を排除​​しながら、これらのカウントが保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

n, m = map(int, input().split())

# factorials for binomial coefficients up to n+1
fact = [1] * (n + 3)
invfact = [1] * (n + 3)

for i in range(1, n + 3):
    fact[i] = fact[i - 1] * i % MOD

invfact[n + 2] = modinv(fact[n + 2])
for i in range(n + 2, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C(a, b):
    if b < 0 or b > a:
        return 0
    return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

# build product over [m-n+1 .. m]
start = m - n + 1
prod = [1] * (n + 1)

for i in range(n):
    prod[i + 1] = prod[i] * (start + i) % MOD

def range_prod_inv(l, r):
    # product of A[l..r]
    val = prod[r + 1] * modinv(prod[l]) % MOD
    return modinv(val)

ans = 0

for k in range(1, n + 1):
    comb = C(n + 1, k + 1)
    coeff = fact[k]
    
    # product over (m-n+1 .. m-k)
    l = 0
    r = n - k - 1
    if l <= r:
        ratio = range_prod_inv(l, r)
    else:
        ratio = 1
    
    ans = (ans + coeff * comb % MOD * ratio) % MOD

print(ans)
```この実装では、ソリューションが 3 つの独立したコンポーネントに分割されます。 階乗表は二項項にのみ必要です`C(n+1, k+1)`。 大きな値`m`は単一の連続した製品範囲内にのみ表示されるため、この間隔にわたってプレフィックス製品配列を構築します。`[m-n+1, m]`。 これにより、次のような反復処理が回避されます。`m`、それは不可能でしょう。 

機能`range_prod_inv`プレフィックス積とモジュール逆関数を使用して、サブセグメント積の逆関数を返します。 導出された式では連続する整数の積による除算が必要なため、これが必要になります。 

メインループは繰り返します`k`、各寄与を独立して累積します。これは、代数的単純化後に各項がすでに完全に分離されているため安全です。

 ## 特殊なケース

 いつ`n = 1`、すべてのシーケンスは単一の要素で構成され、mex は常に`0`または`1`要素が`0`。 アルゴリズムはこれを正しく処理します。`k = 1`用語が存在し、単一の接頭辞に対する単純な組み合わせの数にきれいに減少します。 

いつ`n = m`、すべての要素が 1 回だけ使用されます。 この場合、製品範囲は次のとおりです`[m-n+1, m]`で始まる完全な連続ブロックになります`1`、ゼロによる除算が発生しないため、接頭辞と積の反転は引き続き機能します。 すべての順列はセットの完全な順列であるため、組み合わせ項は有効なままです。 

いつ`m`よりもはるかに大きいです`n`、への依存`m`短い製品セグメントに分割されますが、アルゴリズムは依然として線形時間で実行されます。`n`大きな値に明示的に触れることなく、最大の制約下での安定性を確保します。
