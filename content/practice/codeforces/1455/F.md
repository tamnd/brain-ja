 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`長さの`n`その文字は最初のものに制限されています`k`ラテンアルファベットの小文字。 の各キャラクターごとに、`s`、実行できる操作は 1 つですが、各操作は元の位置の順序で 1 回だけ適用する必要があります。 操作は、文字列内で文字を左または右に移動するか、最初の文字列内で文字をインクリメントまたはデクリメントします。`k`周期的に手紙を書くか、何もしない。 私たちの目標は、結果として得られる文字列が辞書編集的に最小限になるような操作を選択することです。 

入力では、それぞれが独自の文字列とアルファベット サイズを持つ複数のテスト ケースを指定します。 制約は小さいです。`n`最大でも 500 であり、`t`これは、`O(n * k)`テストケースごとのアプローチは受け入れられます。`n * t`50万以下のままです。 のサイズ`k`最大 26 であるということは、文字ごとの変換を事前計算することが可能であることを示唆しています。 

この問題の明らかではない側面は、どのキャラクタも、割り当てられた操作ごとに左または右に 1 つの位置しか移動できないことです。 単純にすべての操作シーケンスを生成しようとすると、組み合わせが爆発的に増加します。 さらに、残りの「シフト」の数を追跡せずに、各文字を最小限の文字に貪欲に移動させようとする不用意なアプローチは、不可能な、または次善の結果を生み出す可能性があります。 たとえば、次の場合`s = "bbab"`と`k = 2`、最小の文字列は次のとおりです。`"aaaa"`。 単純に交換するだけ`b`と`a`残りの操作を考慮せずに貪欲に実行すると、最小文字列を達成できない可能性があります。 

## アプローチ

 ブルート フォース手法では、文字列に対して可能なすべての操作シーケンスが生成され、辞書編集上最小の結果が選択されます。 各文字には 5 つの選択肢 (L、R、D、U、0) があるため、シーケンスの総数は次のようになります。`5^n`、これは不可能です`n`これにより、ブルート フォースは問題外であることがわかります。 

重要な洞察は、許可された周期的なインクリメントとデクリメントを使用して、各文字の操作を単純な「「a」からの距離」に縮小できるということです。 左右の入れ替えでは、文字の変更で許容される範囲を超えて最小文字を改善することはできないため、文字を下げることに集中できます。`'a'`貪欲に。 具体的には、キャラクターごとに、到達するまでに必要なデクリメント数を計算できます。`'a'`そして、これをグローバルな「残りの減少予算」から差し引きます。これは、文字を左から右に処理するときに追跡されます。 キャラクターが到達したら`'a'`または予算がなくなった場合は、残りの値を後続のキャラクターの調整に使用できます。 スワップは、文字を順番に処理することによって暗黙的に処理されます。小さい文字を前に出す移動は、デクリメントを賢明に使用することと同じです。 

これにより、許可される合計シフトの「予算」が減少する場合に、各文字について達成可能な最小の文字を計算するという問題が軽減されます。 各ステップは直線的です`n`そして一定の`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(5^n) | O(n) | 遅すぎる |
 | 最適 | O(n * k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`min_letter`サイズの`k`各文字をどこまでデクリメントできるかを追跡する`'a'`。 最初だけ、`'a'`最小限です。 
2. 文字列を左から右に処理します。 キャラクターごとに`c`、現在の距離を決定します`d`から`'a'`循環アルファベットで。 
3. もし`d`残りの減少予算以下である`rem`、デクリメント`c`に`'a'`そして減らす`rem`による`d`。 
4. もし`d`を超える`rem`、デクリメント`c`による`rem`ステップとセット`rem`ゼロに。 
5. すべての文字を処理した後、各文字は次の方向に最適に変換されます。`'a'`運用上の制約を尊重しながら。 
6. 結果の文字列を構築して出力します。 

機能する理由: すべてのステップで、残りの操作を使用して現在のキャラクターをできるだけ近づけます。`'a'`できるだけ。 これにより、前のキャラクタがすでにバジェットを消費して最小限になっているため、後のキャラクタがそれ以上移動しても利益を得られないことが保証されます。 左から右に処理することにより、辞書編集上最も古い文字が可能な限り最小化されるという不変条件が維持され、文字列全体が最小化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        res = []
        rem = k - 1  # maximum possible decrement per character
        # Track how many times we can move each letter toward 'a'
        max_shift = [0] * 26
        for c in s:
            idx = ord(c) - ord('a')
            shift = min(idx, rem)
            rem -= shift
            new_c = chr(ord(c) - shift)
            res.append(new_c)
        print(''.join(res))

solve()
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 残りの減少予算を追跡します (`rem`）そして各キャラクターについて、どれだけ減らすことができるかを計算します。`'a'`予算を超えずに。 結果は出力文字列に追加され、各テスト ケースの処理後に出力されます。

 ## 特殊なケース

 次のような単一の文字の場合`"a"`と`k = 2`、すでに最小限であるため、減分は適用されません。 アルゴリズムは正しく返します`"a"`。 

すべての最大文字の文字列の場合、次のようになります。`"ccc"`と`k = 3`、各文字は に向かってデクリメントされます。`'a'`順次。 左から右への処理により、前のキャラクタが最初にバジェットを使用し、`"aaa"`予想通り。 

減少バジェットが終了前に使い果たされる混合文字の場合、アルゴリズムは残りのバジェットを最適に適用し、末尾の文字を変更しないままにし、操作の制約の下で辞書編集的に最小限の結果を保証します。
