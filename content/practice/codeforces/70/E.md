 ## 解決策
 ## 問題の理解

 私たちは、道路網がツリーを形成するように道路で接続された都市を持つ国を与えられています。つまり、どの 2 つの都市の間にも 1 つの単純な道が存在します。 エッジの数を数えると、各道路の長さは同じになります。 政府は情報を効率的に広めるため、一部の都市に地域センターを設立したいと考えている。 地域センターの維持には、年間固定金額 _k_ の費用がかかります。 地域の中心地ではない都市の場合、情報を提供し続けるためのコストは、距離依存のコスト リストを使用して、最寄りの地域の中心地からの距離に比例します。`d[i]`。 

入力は都市の数を提供します`n`、地域センターの費用`k`、リスト`d`距離単位あたりのコストを表す (`d[i] <= d[i+1]`）、 そして`n-1`ツリーを定義するエッジ。 目標は、地域センターをいくつかの都市に割り当て、中心以外の各都市を地域センターに割り当てて総メンテナンスコストを最小限に抑え、最小コストとセンターの割り当ての両方を出力することです。 

の小さな値`n`(最大 180) を使用すると、センターの配置が指数関数的に選択される可能性がある場合でも、ツリーを介した動的プログラミングを検討できます。 都市の考えられるすべてのサブセットを中心として試す単純なアプローチは 2^180 となり、明らかに実行不可能です。 ツリー構造を利用したソリューションが必要です。 

明らかではないエッジ ケースには、中心となる都市が 1 つだけあるツリーや、`d[i]`値の増加が非常に遅いか、ゼロのままです。 たとえば、`n=1`そして`k=10`、唯一の都市が中心である必要があり、総コストは次のとおりです。`10`。 もしすべてなら`d[i]=0`、追加のセンターの作成を完全に回避し、ゼロ距離コストを支払う方が安くなる可能性があります。 

## アプローチ

 強引なアプローチでは、都市のすべてのサブセットを地域の中心として列挙し、中心ではない各都市から最も近い中心までの距離を計算し、コストを合計し、総コストが最小となるサブセットを選択します。 これは原理的には正しいですが、2^n 個の可能性をチェックし、それぞれの距離を計算する必要があるため、実行不可能です。 

重要な点は、ツリー構造によりボトムアップの動的プログラミング アプローチが可能になるということです。 ツリーを任意にルート化すると、地域センターがルートに配置された場合と子のセンターに依存した場合の最小コストをサブツリーごとに計算できます。 各ノードは DP テーブルを維持します`dp[u][i]`をルートとするサブツリーをカバーするための最小コストを表す`u`からのパス内の最も近い中心を想定します`u`距離がある`i`。 テーブルは、以下の距離の場合にのみ必要です。`n-1`、およびの単調性`d[i]`子サブツリーをマージするときにコストを効率的に伝播できるようになります。 これにより、複雑さが O(n^3) 以上に軽減され、n ≤ 180 では許容されます。 

総当たりのアプローチは、サブセットの指数関数的な数が管理できないため失敗します。 DP アプローチが機能するのは、ツリーがサイクルを保証しないためです。そのため、サブツリーを個別にカバーし、潜在的な中心までの距離を考慮しながら結果をマージするだけで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | DP オン ツリー | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーのルートを任意のノード (ノード 1 など) に設定します。これにより、問題を階層的に処理し、葉からルートまでのコストを計算できるようになります。 
2. 定義する`dp[u][i]`をルートとするサブツリーをカバーするための最小コストとして`u`、サブツリーの外側の最も近い中心が距離にあると仮定します。`i`。 ここ、`i`範囲は0から`n`(0の意味`u`それ自体がセンターです）。 
3. リーフ ノードの場合、DP は単純です。 リーフがセンターの場合、コストは`k`。 それ以外の場合のコストは、`d[i]`最も近い外部中心が離れたところにある場合`i`。 
4. 内部ノードの場合`u`、すべての子の DP を再帰的に計算します。 2 つのケースを考えます。`u`（その場合、外部距離は0になります）または中心を置かない`u`。 子を結合するときに距離を調整します`i`からのエッジを考慮して 1 ずつ増分します。`u`子供に。 
5. 最終的な答えは、次の最小値です。`dp[root][n]`、 どこ`n`は、他の中心が存在しない場合に、ルート自体が中心を必要とする可能性がある状況を表します。 
6. センターの割り当てを再構築するために、DP マージ中に別の配列で決定を追跡します。つまり、ノードがセンターとして選択されるかどうか、およびどの子が最小のカバレッジ コストを提供するかどうかです。 DP の完了後、ツリーを再び走査し、これらの決定に従って各ノードを最も近い選択された中心に割り当てます。 

機能する理由: 各ノードで、`dp[u][i]`をルートとするサブツリーをカバーするためのすべての可能性を正しくエンコードします。`u`最も近い外部中心までの固定距離が与えられます。 子を結合すると、すべてのパスと距離が確実に考慮されます。 再帰的なボトムアップ伝播により、より適切な構成が見逃されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1000)

n, k = map(int, input().split())
d = [0] + list(map(int, input().split()))  # 1-based indexing
edges = [[] for _ in range(n+1)]
for _ in range(n-1):
    u, v = map(int, input().split())
    edges[u].append(v)
    edges[v].append(u)

dp = [[0]*(n+2) for _ in range(n+1)]
choice = [[-1]*(n+2) for _ in range(n+1)]

def dfs(u, parent):
    for v in edges[u]:
        if v == parent:
            continue
        dfs(v, u)

    for dist in range(n+1):
        # Case 1: place center at u
        cost_with_center = k
        for v in edges[u]:
            if v == parent:
                continue
            cost_with_center += dp[v][1]
        dp[u][dist] = cost_with_center
        choice[u][dist] = 0

        # Case 2: do not place center at u
        cost_without_center = d[dist]
        for v in edges[u]:
            if v == parent:
                continue
            cost_without_center += dp[v][dist+1]
        if cost_without_center < dp[u][dist]:
            dp[u][dist] = cost_without_center
            choice[u][dist] = 1

dfs(1, 0)

res = dp[1][n]
assignment = [0]*(n+1)

def assign(u, parent, dist, center):
    if choice[u][dist] == 0:
        center = u
    assignment[u] = center
    for v in edges[u]:
        if v == parent:
            continue
        assign(v, u, dist+1 if choice[u][dist]==1 else 1, center)

assign(1, 0, n, 1)
print(res)
print(' '.join(map(str, assignment[1:])))
```このソリューションでは、最初にツリーを構築し、DP テーブルを設定し、再帰的 DFS を使用して最小コストを計算します。 の`choice`配列は、各距離シナリオのノードに中心を置くかどうかを追跡します。 の`assign`関数は、最適な DP の決定に従って、各都市がどの地域中心部に属するかを再構築します。 私たちが使用するのは`dist+1`ノードが最も近い中心までの距離を増加させる中心を配置しない場合、および`1`中心が現在のノードに配置されるとき。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3) | 各ノードは距離を最大 n まで反復し、すべての子のコストをマージして、およそ n * n * n | を求めます。
