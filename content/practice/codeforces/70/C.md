 ## 解決策
 ## 問題の理解

 各チケットは 2 つの正の整数で記述されます。 最初はシリーズ番号です`a`、2 番目はそのシリーズ内のチケット番号です。`b`。 チケットは次の場合に幸運と呼ばれます$a \cdot b = \operatorname{rev}(a) \cdot \operatorname{rev}(b)$機能`rev(x)`10 進数を反転し、反転後に先頭のゼロを削除します。 例えば、`rev(1200) = 21`。 

印刷するシリーズの数と各シリーズに含まれるチケットの数を選択できます。 私たちが選ぶなら`x`シリーズと`y`シリーズごとのチケット、その後すべてのペアのチケット`(a, b)`と`1 ≤ a ≤ x`そして`1 ≤ b ≤ y`存在する。 それらのペアの中では少なくとも、`w`幸運に違いない。 印刷されたチケットの総数を最小限に抑えたいと考えています。`x * y`。 

この制約により、すべてのペアに対するブルート フォースが即座に排除されます。 両方`maxx`そして`maxy`到達できる`10^5`したがって、完全なグリッドには最大で次のものが含まれます。`10^10`ペア。 すべてのペアの単一の算術条件をチェックすることさえ 2 秒以内には不可能です。 

ラッキーチケットの目標枚数は次のとおりです。`10^7`、つまり、疎な構造にも依存できないということです。 解決策は方程式自体の構造を利用する必要があります。 

難しいのは、どのような数値が条件を満たすかを理解することです。 不注意な実装では、反転が乗算的に動作すると想定する可能性がありますが、それは誤りです。 例えば：```
a = 12, b = 21
12 * 21 = 252
rev(12) * rev(21) = 21 * 12 = 252
```どちらの数字も回文ではありませんが、このペアは幸運です。 

もう 1 つの簡単な間違いは、反転すると先頭のゼロが削除されることを忘れることです。 考慮する：```
a = 10, b = 1
10 * 1 = 10
rev(10) * rev(1) = 1 * 1 = 1
```チケットは幸運ではありません。 治療中`rev(10)`として`01 = 10`黙って不正確な答えを生み出すでしょう。 

3 番目の微妙な問題は、有効な答えが存在しない場合に発生します。 仮定する：```
1 1 2
```チケットは1枚しかありませんが、`(1,1)`、そしてそれは幸運です。 幸運のチケットが 2 枚必要なので、正しい出力は次のようになります。`-1`。 実現可能性をチェックせずに、十分な大きさの長方形だけを検索するソリューションは、ここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのペアについて`(a, b)`選択した長方形内で両方の積を計算し、条件を満たす数を数えます。 次に、考えられるすべての値を試します`x`そして`y`少なくとも到達する最小の領域を選択します`w`幸運のチケット。 

ラッキー チケットの定義は 1 つのペアに対して完全にローカルであるため、これは論理的に機能します。 問題はスケールです。 まであります`10^10`すべての四角形を列挙する場合でも、すでに別の係数がかかります。`10^10`。 総操作数は実用的なものをはるかに超えて爆発的に増加します。 

これを改善するには、方程式自体を理解する必要があります。 

から開始$a \cdot b = \operatorname{rev}(a) \cdot \operatorname{rev}(b)$並べ替えると$\frac{a}{\operatorname{rev}(a)} = \frac{\operatorname{rev}(b)}{b}$これは、次の比率を意味します。`a`に関連付けられた逆比と正確に一致する必要があります`b`。 

正規表現を定義します。 

f(x)=\frac{x}{\オペレータ名{rev}(x)}}

 2 つの数字は、その約分数が等しい場合に正確に幸運のペアを形成します。 

それは問題を完全に変えます。 すべてのペアを個別に調べる代わりに、数値を小数部分でグループ化できます。`x / rev(x)`。 

特定の分数が現れたとします。`cx`数字の倍`1..x`、同じ分数が表示されます`cy`数字の倍`1..y`。 そして、それらのグループ間のすべての組み合わせが幸運のチケットを形成します。 寄付総額は、$cx \cdot cy$ここで、タスクは約分数の頻度を数えることになります。 

整数の数は`10^5`, したがって、すべての値を 1 回前処理できます。 各数値について、その逆の値を計算し、gcd を使用して端数を減らし、正規化されたペアを保存します。`(p, q)`。 

前処理後、考えられる長方形のサイズを効率的にスイープできます。 重要な観察は、片側を 1 ずつ増やすと、単一の新しい数値の寄与のみが変化するということです。 これにより、すべてを最初から再計算するのではなく、2 ポインター スタイルのプロセスが可能になります。

 | 最適 | O(maxx + maxy) 前処理 + O(maxx + maxy) スイープ | O(maxx + maxy) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下のすべての整数に対して`1`に`max(maxx, maxy)`、その反転値を計算します。 
2. 端数を減らす`x / rev(x)`両辺を gcd で割ることによって。 正規化されたペアを保存する`(p, q)`。 

削減ステップは重要です。 数値が異なると同等の比率が生成される場合があります。 例えば：```
12 / 21 = 4 / 7
24 / 42 = 4 / 7
```両方が同じグループに属している必要があります。 

1. 2 つのアレイを構築します。`typeX[i]`系列インデックスとして使用できる数値の場合、`typeY[i]`チケットのインデックスとして使用できる番号。 

各エントリには、その数値の正規化された小数が格納されます。 

1. スライディング ウィンドウ スタイルのプロセスを使用します。`x`。 

頻度表を維持する`cnt`現在存在するすべての正規化された分数について`1..y`。 

また、次のことも維持します。$good = \sum_t cntX_t \cdot cntY_t$どこ`cntX_t`そして`cntY_t`分数型のカウントです`t`両側にあります。 

1. から始める`y = 0`。 それぞれについて`x`から`1`に`maxx`から新しい分数型を追加します。`x`。 
2. その間`good < w`そして`y < maxy`、 伸ばす`y`1つずつ。 

新しい番号を追加するときは、`y`側で、そのタイプが次であると仮定します。`t`。 上の既存のすべての番号`x`同じタイプの側は新しい幸運のペアを形成するため、次のようになります。```
good += cntX[t]
cntY[t] += 1
```1. 1回`good ≥ w`、長方形`(x, y)`実現可能です。 

その面積をこれまでに確認された最良の回答と比較します。 

1.すべて終わるまで続けます`x`処理されます。 
2. 実行可能な長方形が見つからなかった場合は、印刷します。`-1`。 

### なぜ効果があるのか

 不変条件は、正規化された分数型を一致させることによって、すべての幸運なペアが正確にカウントされるということです。 

どのペアでも`(a,b)`:$a \cdot b = \operatorname{rev}(a) \cdot \operatorname{rev}(b)$次の場合にのみ成立します$\frac{a}{\operatorname{rev}(a)} = \frac{\operatorname{rev}(b)}{b}$分数を削減した後、等価性は正規化されたペアの等価性になります。 すべてのラッキー チケットは 1 つの分数クラスに属し、同じクラス内のすべての組み合わせがラッキーです。 

スライディング ウィンドウは、両側に出現する各クラスの数値の正確な数を維持します。 すべての更新では 1 つの周波数のみが変更されるため、`good`は常に、現在の四角形内のラッキー チケットの実際の数と等しくなります。 

なぜなら`y`前方にのみ移動するため、ポインタの移動の総数は直線的です。 

## Python ソリューション```python
import sys
from math import gcd
from collections import defaultdict

input = sys.stdin.readline

def rev(x):
    return int(str(x)[::-1])

def solve():
    maxx, maxy, w = map(int, input().split())

    limit = max(maxx, maxy)

    typ = [None] * (limit + 1)

    for i in range(1, limit + 1):
        r = rev(i)
        g = gcd(i, r)
        typ[i] = (i // g, r // g)

    cnt_x = defaultdict(int)
    cnt_y = defaultdict(int)

    good = 0
    y = 0

    best_area = None
    best_ans = None

    for x in range(1, maxx + 1):
        t = typ[x]

        good += cnt_y[t]
        cnt_x[t] += 1

        while y < maxy and good < w:
            y += 1
            ty = typ[y]

            good += cnt_x[ty]
            cnt_y[ty] += 1

        if good >= w:
            area = x * y

            if best_area is None or area < best_area:
                best_area = area
                best_ans = (x, y)

    if best_ans is None:
        print(-1)
    else:
        print(best_ans[0], best_ans[1])

solve()
```最初のセクションでは、すべての数値の正準分数型を計算します。 gcd による縮小は、等価比を同じキーに折りたたむものです。 正規化を行わないと、次のような値になります。`(12,21)`そして`(24,42)`誤って異なって表示されてしまいます。 

辞書`cnt_x`そして`cnt_y`現在のプレフィックスに各分数型が何回出現するかを保存します。 変数`good`は常に現在の四角形内に幸運のペアの数を保存します。 

新しい値を追加すると、`x`新しいラッキー チケットの数は、すでに存在する一致するタイプの数と同じです。`y`側。 そのため、更新順序は次のようになります。```
good += cnt_y[t]
cnt_x[t] += 1
```順序を逆にすると、新しい要素がそれ自体に対して余分にカウントされます。 

展開中にも同じロジックが適用されます`y`。 

2 ポインター構造は効率的です。`y`決して減りません。 アルゴリズム全体にわたって、増加するのは最大でも`maxy`回。 

このソリューションでは、タプルをハッシュ キーとして使用します。 Python はこれを効率的に処理し、個別の換算された分数の合計数は次のように管理できます。`10^5`数字。

 ## 特殊なケース

 不可能な構成を考えてみましょう。```
1 1 2
```前処理ステージでは、次の 1 つのタイプが作成されます。```
1 -> (1,1)
```スイープは次のように続行されます。 

| × | y | 良い |
 | --- | --- | --- |
 | 1 | 1 | 1 |

 アルゴリズムは可能な最大の長方形に達しましたが、まだラッキー チケットは 1 枚だけです。 以来`good < w`、回答は記録されず、最終出力は次のようになります。`-1`。 

次に、先行ゼロの動作を考えてみましょう。```
10 1 1
```番号`10`は次のようになります:```
rev(10) = 1
```その縮小型は、`(10,1)`のタイプですが、`1`は`(1,1)`。 

アルゴリズムは決して重要ではない`(10,1)`種類が違うのでラッキーです。 これにより、反転後の先頭のゼロの消失が正しく処理されます。 

最後に、当量比を考慮します。```
24 42 1
```得られるものは次のとおりです。 

| 番号 | 回転 | 縮小型 |
 | --- | --- | --- |
 | 12 | 21 | (4,7) |
 | 24 | 42 | (4,7) |

 gcd 削減後、両方の数値は同じクラスに属します。 非還元分数を直接比較するソリューションでは、この等価性が失われます。 正規化ステップにより、それらが正しく一致することが保証されます。
