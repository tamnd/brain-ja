 ## 解決策
 ## 問題の理解

 単一の SMS メッセージと、スペースで区切られた文で構成される 1 つの完全なテキストの最大長が与えられています。 文は常に次のいずれかで終わります。`.`、`?`、 または`!`。 単語には文字だけが含まれます。 

The task is to split the text into the minimum possible number of messages such that no sentence is broken across messages. A message may contain several consecutive sentences if they fit within the length limit. When two consecutive sentences are placed into different messages, the separating space disappears because Fangy simply does not type it.

 This detail about spaces is the entire trick of the problem. Inside one message, the original spaces must stay. Between two different messages, the separating space can be omitted.

 テキストの長さは最大でも`10^4`、これは線形または二次処理には十分小さいです。 メッセージ制限があるので`n`せいぜい`255`, 文の長さをチェックするのは簡単です。 部分文字列の再構築や長さの再計算を繰り返し行うと、演算数が数千万、数億に達する可能性があるため、3 次解はすでに危険です。 クリーンなグリーディ プログラミング ソリューションまたは動的プログラミング ソリューションの方が適切です。 

最初の重要なエッジケースは、単一の文がすでにメッセージ制限を超えている場合です。 

入力：```
5
Hello!
```文`"Hello!"`長さがある`6`したがって、有効な分割は存在しません。 

正しい出力:```
Impossible
```不注意な実装では、結合されたメッセージの長さだけをチェックし、個々の文の検証を忘れる可能性があります。 

もう 1 つの微妙なケースは、メッセージ間のスペースが消えることです。 

入力：```
7
Hi. Bye.
```文章全体に長さがある`8`ですが、それでも次の 2 つのメッセージで送信できます。`"Hi."`そして`"Bye."`正しい出力:```
2
```文間のスペースを常にカウントする実装では、これは不可能であると誤って認識される可能性があります。 

もう 1 つの注意が必要な状況は、複数の短い文を合わせてちょうど 1 つのスペースで制限を超える場合に発生します。 

入力：```
10
Hi. Hello.
```

`"Hi. Hello."`長さがある`10`, したがって、1 つのメッセージに収まります。 

もし限界があったとしたら`9`、両方の文が一緒にある場合、内部スペースが残る必要があるため、2 つのメッセージが必要になります。 

正しい出力`n = 9`:```
2
```内部スペースと削除された境界スペースの間のこの区別は、多くのオフバイワンバグが発生する場所です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 まずテキストを文に分割します。 次に、連続した文をメッセージにグループ化できるすべてのことを試し、動的プログラミングを使用してメッセージの最小数を計算します。 

あると仮定します`k`文章。 素朴な DP は次のように定義できます。`dp[i]`最初に必要なメッセージの最小数として`i`文章。 あらゆる人にとって`i`、以前のすべての位置を試します`j`文かどうかを確認してください`j...i-1`一つのメッセージに収まります。 

コストがかかる部分は、グループの長さを繰り返し計算することです。 毎回部分文字列を再構築したり、スペースを再カウントしたりすると、各遷移にコストがかかる可能性があります`O(k)`を生成し、`O(k^3)`解決。 周りと`10^4`文字数が多くなると、文の数も多くなり、遅くなりすぎる可能性があります。 

重要な観察は、実際に必要なのは文の長さだけであるということです。 テキストが文の長さに解析されると、複数の連続する文が互いに適合するかどうかをチェックすることが簡単な算術式になります。 

文の長さが次のようになると仮定します。```
len[0], len[1], ..., len[k-1]
```文章を並べると`l...r`1 つのメッセージにまとめると、合計の長さは次のようになります。```
sum(len[l...r]) + (r - l)
```余分な`(r - l)`同じメッセージ内の連続した文の間のスペースから来ています。 異なるメッセージ間のスペースは消え、カウントされません。 

問題ははるかに単純になります。 各グループの合計の長さが次の値を超えないように、シーケンスを最小限のグループに分割するだけで済みます。`n`。 

この時点で、貪欲になるのが自然になります。 現在の文から始めて、できるだけ多くの連続した文を現在のメッセージに詰め込む必要があります。 未使用のスペースを残しておくことは、将来のすべての文をどこかに配置する必要があるため、後で役に立ちません。 有効なプレフィックスを最大限に取得すると、グループの数が最小限に抑えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k3) | O(k) | 遅すぎる |
 | 最適 | O( | テキスト | ) |

 ## アルゴリズムのチュートリアル

 1. テキストを解析し、すべての文の長さを抽出します。 

文字列を 1 文字ずつスキャンします。 私たちが出会うたびに`.`、`?`、 または`!`で一文を終わります。 文の長さには、文の先頭から句読点までのすべての文字が含まれます。 
2. 個々の文の長さが超過していないか確認します。`n`。 

1 つの文でも大きすぎる場合は、文を複数のメッセージに分割することができないため、有効な配置が存在しません。 
3. 貪欲にメッセージを構築し始めます。 

現在のメッセージの長さと、これまでに使用されたメッセージの数を維持します。 
4. 最初の文を現在のメッセージに挿入します。 

すべての文が個別に適合することはすでに検証済みなので、これはいつでも可能です。 
5. 次の各文について、現在のメッセージに追加できるかどうかを判断します。 

現在のメッセージにすでに何かが含まれている場合、別の文を追加するには追加のスペースが 1 つ必要です。 したがって、追加コストは次のようになります。```
1 + next_sentence_length
```6. 新しい合計が以下の場合`n`、現在のメッセージに文を追加します。 

これにより、現在のメッセージの使用量を最大化しながら、メッセージの数は変更されません。 
7. それ以外の場合は、この文で新しいメッセージを開始します。 

文が別のメッセージになったため、区切りスペースは消えます。 
8. すべての文を処理した後、使用されたメッセージの数を出力します。 

### なぜ効果があるのか

 メッセージには連続した文のみが含まれるため、貪欲な選択が最適です。 現在のメッセージがまだ別の文に適合すると仮定します。 その文を追加せずに先に分割しても、利用可能なスペースが無駄になるだけであり、将来の追加の機会を生み出すことはできません。 以降のすべての文は現在の文の後に出現する必要があるため、分割を遅らせても必要なメッセージ数が増加することはありません。 

このアルゴリズムは、現在のメッセージに制限内に収まる最大可能数の連続した文が含まれるという不変条件を維持します。 各メッセージは最大限にパックされるため、メッセージの総数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    text = input().rstrip()

    sentences = []

    start = 0

    for i, ch in enumerate(text):
        if ch in ".?!":
            sentences.append(i - start + 1)

            if i + 1 < len(text):
                start = i + 2

    for length in sentences:
        if length > n:
            print("Impossible")
            return

    messages = 1
    current = sentences[0]

    for length in sentences[1:]:
        if current + 1 + length <= n:
            current += 1 + length
        else:
            messages += 1
            current = length

    print(messages)

solve()
```最初の部分ではテキストをスキャンし、文の長さを抽出します。 変数`start`現在の文が始まるインデックスを保存します。 句読点が見つかると、文の長さは単純に次のようになります。```
i - start + 1
```文法により、連続する文の間には必ず 1 つのスペースが必要であることが保証されているため、文が終了すると、次の文は 2 つ遅れて始まります。 

2 番目のループでは実現可能性をチェックします。 単一の文が大きすぎるとタスクがすぐに不可能になるため、これは貪欲なパッキング段階の前に行う必要があります。 

貪欲な構造では、現在のメッセージの長さのみが保持されます。 別の文を追加するときは、内部スペースに 1 文字追加します。```
current + 1 + length
```このスペースは、同じメッセージ内に 2 つの文が含まれている場合にのみカウントされます。 新しいメッセージを開始すると、長さが新しい文のみにリセットされます。 

微妙な境界条件の 1 つは初期化です。```
messages = 1
current = sentences[0]
```テキストには少なくとも 1 つの文が含まれることが保証されているため、常に安全です。

```これは制限を超えているため、新しいメッセージが開始されます。 メッセージ間の区切りスペースはカウントされなくなり、正確に 2 つの有効なメッセージが生成されます。 

最後に、境界条件を調べます。```
10
Hi. Hello.
```長さは`[3, 6]`。 

2 番目の文を追加すると、次のようになります。```
3 + 1 + 6 = 10
```等価性が許可されているため、両方の文が 1 つのメッセージにまとめられます。 これにより、アルゴリズムがオフバイワンの間違いなく正確な適合を正しく処理することが確認されます。
