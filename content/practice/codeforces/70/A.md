 ## 解決策
 ## 問題の理解

 サイズの正方形の箱があります`2^n × 2^n`。 この箱の中に、特製の三角クッキーを繰り返し入れています。 

サイズのクッキー`k`の上三角部分を占めます。`k × k`主対角線を含む正方形。 そのエリアは次のとおりです。$$1 + 2 + 3 + \dots + k = \frac{k(k+1)}{2}$$Cookie は回転できないため、すべての Cookie は常に同じ方向を指します。 

梱包プロセスは貪欲です。 すべてのステップで、残りの空きスペースのどこかにまだ収まる最大の Cookie を選択し、それを配置し、少なくともそのサイズの Cookie がなくなるまで続行します。`2`もう置くことができます。 大きさのクッキー`1`存在しません。 

タスクは、このプロセスが終了した後に空のままになる単位セルの数を計算することです。 数値は急速に増加するため、答えを剰余として出力する必要があります`10^6 + 3`。 

制約が小さいので、`n ≤ 1000`ですが、実際の基板サイズは`2^n × 2^n`、天文学的な大きさになります。 たとえば、次のようなとき`n = 1000`、辺の長さ自体の 10 進数は 300 桁を超えます。 ボードを明示的に構築しようとするアプローチは不可能です。 1 行を保存することさえすでに不可能です。 

これは、数学的パターンを特定することから解決策が得られるはずであることをすぐに示します。 

微妙なエッジケースが現れる`n = 0`。 基板サイズは、`1 × 1`、しかしサイズのクッキー`1`存在しません。 箱は完全に空のままです。 

入力：```
0
```正しい出力:```
1
```すべてのボードが少なくとも 1 つの Cookie に適合すると想定する不注意な実装では、誤って印刷されます。`0`。 

もう 1 つの簡単な間違いは、貪欲なプロセスを誤解することです。 梱包は任意ではありません。 可能な限り最大の Cookie が常に最初に選択されます。 たとえば、`n = 1`、ボードは`2 × 2`。 サイズ 2 のクッキーは 1 回だけ収まり、3 つのセルをカバーし、1 つの空のセルを残します。 

入力：```
1
```正しい出力:```
1
```後で小さい Cookie も使用できると誤って推測した場合、残りのセルを存在しないサイズ 1 の Cookie で埋めようとする可能性があります。 

最後のトラップは、固定幅の整数を使用する言語における整数オーバーフローです。 ボード領域は次のとおりです。$$(2^n)^2 = 4^n$$のために`n = 1000`、この数は膨大です。 モジュロは、完全な値を構築した後ではなく、べき乗中に適用する必要があります。 

## アプローチ

 最も直接的なアプローチは、グリッド自体でパッキング プロセスをシミュレートすることです。 私たちが代表できるのは、`2^n × 2^n`ボードに収まる最大のクッキーを繰り返し検索し、配置し、配置がなくなるまで続けます。 

これは、次の小さな値に対して機能します。`n`。 たとえば、次のようなとき`n = 3`、ボードはのみです`8 × 8`、そのため、強引な攻撃も管理可能です。 問題は、辺の長さが増加するたびに2倍になることです。`n`。 で`n = 20`、ボードにはすでに 1 兆を超えるセルが含まれています。 グリッドを一度反復することさえ不可能になります。 

実際のプロセスは非常に厳格な再帰構造を持っていますが、ボードを任意のジオメトリとして扱うため、総当り的なアイデアは失敗します。 

重要な観察は、貪欲なパッキングによって完全な再帰的分解が作成されるということです。 

から始めてください`2^n × 2^n`ボード。 ぴったり合う最大のクッキー`2^n`。 そのクッキーはボードの上三角形全体を占めます。 

覆われていないのは、右下半分にある別の三角形の領域です。 座標をシフトした後、残りの領域はサイズに関して元の問題とまったく同じ形状になります。`2^{n-1}`。 

これは、空のセルの数が繰り返しに続くことを意味します。 

させて`f(n)`あるサイズのボードのカバーされていないセルの数になります。`2^n × 2^n`。 

最大の Cookie は以下をカバーします。$$\frac{2^n(2^n+1)}{2}$$総基板面積は次のとおりです。$$4^n$$最大のクッキーを配置した後のカバーされていない領域は、パラメータに関する同じ問題の別のインスタンスになります。`n-1`。 

小さな値を試してみると、次のことがわかります。$$f(0)=1$$

$$f(1)=1$$

$$f(2)=3$$

$$f(3)=9$$これは等比数列です。$$f(n)=3^{n-1} \quad \text{for } n \ge 1$$反復は形式的に導出することもできます。$$f(n)=3f(n-1)$$各再帰的細分化により、以前のカバーされていないパターンのコピーが 3 つ作成されます。 

パターンが特定されると、問題は累乗剰余計算に帰着します。

2. 特殊なケースに対処する`n = 0`。 

ボードは`1 × 1`、最小 Cookie サイズが次のとおりであるため、Cookie を配置できません。`2`。 単一セルは空のままなので、答えは次のようになります。`1`。 
3. のために`n ≥ 1`、導出された式を使用します。$$f(n)=3^{n-1}$$これは、最大の Cookie を配置するたびに、カバーされない領域の再帰的な構造から導き出されます。 

1. 電力モジュロを計算します。`10^6 + 3`。

### なぜ効果があるのか

 貪欲なプロセスでは、常に可能な限り最大の Cookie が最初に配置されます。これは、次のサイズの Cookie です。`2^n`。 配置後、残りの覆われていない領域は、元の問題と同じ幾何学的構造を再現する小さな領域に分割されます。 

各再帰レベルは、以前のカバーされていない構成の独立したコピーを 3 つだけ生成します。 基本ケースにはカバーされていないセルが 1 つ含まれているため、カバーされていないセルの数はレベルごとに 3 倍になります。$$f(n)=3f(n-1)$$この繰り返しを解くと次のようになります。$$f(n)=3^{n-1}$$みんなのために`n ≥ 1`。 

## Python ソリューション```python

if n == 0:
    print(1)
else:
    print(pow(3, n - 1, MOD))
```問題の難しい部分は再発を発見することであり、コーディングではないため、実装は意図的に短くされています。 

最初のブランチは唯一の例外的なケースを処理します。 いつ`n = 0`、ボードは小さすぎてクッキーを配置できないため、答えはちょうど 1 つの空のセルです。 

すべての大きな値に対して、解決策は閉じた形式の漸化式を使用します。$$f(n)=3^{n-1}$$内蔵されている`pow`3 つの引数を持つ関数は、二乗を繰り返して累乗剰余を効率的に計算します。 これにより、次のような膨大な中間数の構築が回避されます。`3^999`。 

1 つ違いの簡単な間違いは、`3^n`の代わりに`3^{n-1}`。 小さな値をチェックすると、すぐに問題が明らかになります。 

のために`n = 1`、答えは次のようになります。`1`、 ない`3`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

MOD = 10**6 + 3

def solve():
    input = sys.stdin.readline

    n = int(input())

    if n == 0:
        print(1)
    else:
        print(pow(3, n - 1, MOD))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("3\n") == "9\n", "sample 1"

# minimum size
assert run("0\n") == "1\n", "n = 0"

# smallest non-trivial board
assert run("1\n") == "1\n", "single size-2 cookie"

# small recursive case
assert run("2\n") == "3\n", "tripling starts"

# larger value
assert run("5\n") == "81\n", "3^(5-1)"

# maximum boundary style test
expected = str(pow(3, 999, MOD)) + "\n"
assert run("1000\n") == expected, "large exponent modulo"
