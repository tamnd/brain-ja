 ## 解決策
 ## 問題の理解

 1 から N までのラベルが付けられた同じ頂点セット上に 2 つの異なる構造が与えられています。1 つの構造はツリーであるため、任意の 2 つの頂点間には 1 つの単純なパスが存在します。 もう 1 つの構造は、任意の無向の単純なグラフです。 

順序付けられた頂点のペア (u, v) について、ツリー内の u と v を接続する一意のパスを調べます。 次に、この正確な頂点のシーケンスもグラフ内の有効なパスとして通過できるかどうかを尋ねます。 「はい」の場合、そのペアは良好であると呼ばれます。 u から u へのパスにはエッジがないため、すべての頂点はそれ自体で問題なく動作します。 

タスクは、どれだけの順序ペアが良好であるかを数えることです。 

制約により、N と M は最大 200,000 になります。 これにより、ペアを個別にチェックしたり、クエリごとにパスをシミュレートしたりするソリューションは即座に除外されます。 O(N^2) または O(NM) に近いアプローチは遅すぎます。 線形時間または線形算術時間に近い時間 (おそらく O(N + M) または O((N + M) log N) が予想されるはずです。

 微妙な点は、「G のパス」が何を意味するかです。 必要なのは一意性ではなく、存在することだけです。 したがって、ツリー パスが u → a → b → v の場合、G に存在する必要があるのはこれらのエッジ (u, a)、(a, b)、(b, v) だけです。 G 内の余分なエッジは、このシーケンスの存在を無効にしない限り問題ありません。 

よくある間違いは、G 内の最短パスを一致させる必要がある、または代替ルートが存在しないようにする必要があると考えることです。 それは必須ではありません。 

明確にする価値のあるエッジケースの 1 つは、G がツリーと同一である場合です。 したがって、どのペアも良好であるため、答えは N² になります。 もう 1 つの極端な場合は、G が木の端と重ならない場合です。 この場合、(u, u) ペアのみが有効となり、N が与えられます。 

## アプローチ

 ブルートフォースのアイデアは定義から始まります。 順序付きペア (u, v) ごとに、ツリー内の一意のパスを計算し、そのパス上の各エッジが G に存在するかどうかを確認します。パスの長さが k の場合、ペアごとに O(k) かかります。 チェーン状ツリーではほとんどのペアでツリー パスが長くなる可能性があるため、すべてのペアを合計すると、最悪の場合、これは O(N^2) になります。 ハッシュを使用してエッジの存在チェックを高速化したとしても、ペアの数自体は 2 次のままであり、限界をはるかに超えています。 

重要な観察は、実際には任意のペアを個別に推論する必要がないということです。 ペア (u, v) は、それらの間のツリー パス上のすべてのエッジが G に存在する場合に正確に適切です。これにより、問題はペアに関するパス チェックの問題からツリー上のエッジ フィルタリングの問題に変換されます。 

各木のエッジが G にも表示されるかどうかに応じて、「使用可能」または「壊れた」のいずれかに分類できます。ツリー内に使用可能なエッジのみを保持すると、森が得られます。 このフォレスト内では、元のツリー パスが使用可能なエッジのみを使用していた場合に限り、任意の 2 つの頂点が接続されます。 その状態は、ペアが良好であることとまったく同じです。 

したがって、問題は、このフィルタリングされたツリー内で接続されたコンポーネントを見つけて、各コンポーネント内の順序付きペアの数を合計することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | O(N) | 遅すぎる |
 | ツリー エッジ + コンポーネントをフィルタリングする | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 G のエッジの高速メンバーシップ構造を構築し、それに応じてツリーをフィルタリングします。

1. G のすべてのエッジを、順序付きペア (min(x, y)、max(x, y)) をキーとするハッシュ セットまたは辞書に格納します。 これにより、G に木のエッジが存在するかどうかを定数時間でチェックできます。 
2. N 個の頂点すべてに対して Disjoint Set Union (DSU) 構造を初期化します。最初は各頂点がそれ自体のコンポーネントです。 この DSU は、「良好な」ツリー エッジのみを使用して接続を表します。 
3. ツリー内の各エッジ (a、b) について、ハッシュ セットを使用して、それが G に存在するかどうかを確認します。 存在する場合は、DSU で a と b をマージします。 そうでない場合は、完全に無視し、壊れているものとして扱います。 
4. すべてのツリー エッジを処理した後、各 DSU コンポーネントは、使用可能なエッジによって形成される接続コンポーネントに正確に対応します。 
5. 各 DSU コンポーネントについて、そのサイズ s を計算します。 (u, u) を含め、コンポーネント内のすべての順序ペア (u, v) は良好であるため、s × s に寄与します。 
6. すべての成分について s × s を合計し、結果を出力します。 

唯一の微妙な点は、新しいグラフを明示的に構築していないことです。 DSU は、隣接リストを必要とせずに、フィルタリングされたツリー内の接続を直接シミュレートします。 

### なぜ効果があるのか

 ツリーは、任意の 2 つの頂点間の一意の単純なパスを保証します。 そのパスは木のエッジの順序によって完全に決定されます。 ペア (u, v) は、その一意のパス上のすべてのエッジが G に存在する場合に正確に有効です。これは、パス上のすべてのエッジが使用可能としてマークされていると言うのと同じです。 

パス上のすべてのエッジが使用可能な場合、それらのエッジを正確に結合するため、DSU 接続により u と v が同じコンポーネントになることが保証されます。 逆に、それらが同じ DSU コンポーネント内にある場合、ツリーには代替ルートがないため、使用可能なエッジのみで構成されるパスが存在します。これは、一意のツリー パスと一致する必要があります。 この 1 対 1 の対応により、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

def main():
    n, m = map(int, input().split())

    tree_edges = []
    for _ in range(n - 1):
        a, b = map(int, input().split())
        tree_edges.append((a, b))

    g_edges = set()
    for _ in range(m):
        x, y = map(int, input().split())
        if x > y:
            x, y = y, x
        g_edges.add((x, y))

    dsu = DSU(n)

    for a, b in tree_edges:
        x, y = (a, b) if a < b else (b, a)
        if (x, y) in g_edges:
            dsu.union(a, b)

    comp_size = {}
    for i in range(1, n + 1):
        root = dsu.find(i)
        comp_size[root] = comp_size.get(root, 0) + 1

    ans = 0
    for s in comp_size.values():
        ans += s * s

    print(ans)

if __name__ == "__main__":
    main()
```コードはまず、エッジ ルックアップが定数時間になるように、G のすべてのエッジを正規化された順序でセットに格納します。 次に、ツリーのエッジを反復処理し、そのエッジが G に存在する場合にのみ端点を結合します。DSU の構築後、すべての頂点をルートに圧縮し、カウントを累積することでコンポーネントのサイズを計算します。 

よくある実装の落とし穴は、ツリーとグラフの間でエッジを一貫して正規化することを忘れることです。 もう 1 つは、最終的なパス圧縮を行わずに DSU の親を反復処理することで、コンポーネント サイズのカウントを誤る可能性があります。 最後のループでは、すべてのノードで find を明示的に呼び出して、正確さを保証します。 

## 実用的な例

 ライン ツリーに 4 つのノードと G に 3 つのエッジがあるサンプル構造を考えてみましょう。ツリーのエッジは (1,2)、(2,3)、(3,4) です。 グラフの端では (1,2) を除くすべてが許可されます。 

フィルタリング後、エッジ (2,3) と (3,4) のみが使用可能になります。 DSU コンポーネントは {1}、{2,3,4} になります。 貢献度は 1² + 3² = 1 + 9 = 10 です。 

ここで、ツリーが 1 を中心とし、エッジ (1,2)、(1,3)、(1,4) を持つスターであり、G には (1,2) と (1,3) のみが含まれる 2 番目の例を考えてみましょう。 

フィルタリング後、1、2、3 は 1 つの成分を形成し、4 は分離されます。 

以下の表は、DSU ユニオンを追跡します。 

| エッジ加工 | Gで| DSU の状態 |
 | --- | --- | --- |
 | (1,2) | はい | {1,2}、{3}、{4} |
 | (1,3) | はい | {1,2,3}、{4} |
 | (1,4) | いいえ | 変更なし |

 最終的なサイズは 3 と 1 で、3² + 1² = 10 となります。 

これらの例は、保存されたツリーのエッジのみが重要であり、すべての推論はフィルタリングされた構造内の接続に帰着することを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、G にツリー エッジが存在しない場合です。その状況では、すべての頂点が DSU 内で孤立したままになります。 このアルゴリズムは、サイズ 1 の N 個のコンポーネントを生成し、それぞれが 1 を寄与するため、答えは N になります。これは、(u, u) ペアのみが有効であるという事実と一致します。 

別のケースは、G にすべてのツリー エッジと追加のエッジが含まれる場合です。 ツリー エッジのみが処理されるため、余分なエッジは DSU 結合には影響しません。 ツリー全体が 1 つのコンポーネントになり、N² の順序ペアが生成されます。すべてのツリー パスが G に存在するため、これは正しいことです。 

最後の微妙なケースは、G がツリーと一致しない方法で切断されている場合です。 DSU は非ツリー エッジを完全に無視するため、そのようなエッジがコンポーネントを誤ってマージすることはできません。 G によって制限されるツリー接続のみが重要であり、これはまさに良好なペアを定義する条件です。
