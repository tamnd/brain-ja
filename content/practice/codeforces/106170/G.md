 ## 解決策
 ## 問題の理解

 小文字で構成されるいくつかの短い文字列が与えられ、各文字列について、同じセット内で特定の距離の尺度で「最も近い」別の文字列を見つけたいとします。 この距離は、置換を伴う通常の編集距離ではなく、挿入と削除のみです。 したがって、ある文字列を別の文字列に変換するには、置換を許可せずに、一方の文字列から削除してもう一方の文字列に挿入する必要がある正確な数の文字が必要になります。 

この距離はもっと簡単に解釈できます。`lcs(a, b)`最長の共通部分列の長さ、次にそれらの間の距離`a`そして`b`は`|a| + |b| - 2 * lcs(a, b)`。 このアイデンティティは、問題を文字列編集から最長共通部分列の最大化の問題に変えるため、非常に重要です。 

文字列ごとに`si`、別の文字列を選択する必要があります`sj`この距離を最小化し、複数の候補が同じ最小値に達する場合は、それらの中から辞書編集的に最小の文字列を選択する必要があります。 

文字列の数という点では制約が厳しく、テスト ケースあたり最大 20,000 個ですが、各文字列は非常に短く、長さは最大 8 です。この組み合わせは、高価な文字列比較ロジックを使用した場合、すべてのペアに対するブルート フォースが大きすぎることをすぐに示唆していますが、小さなアルファベットの長さを利用するアプローチは実行可能です。 

単純な解決策では、すべてのペアを比較し、各ペアの LCS を計算します。 長さが 8 であるため各 LCS は安価ですが、最悪の場合でもテスト ケースあたり約 20000 平方ペアであり、これは大きすぎます。 

さらに微妙な問題はタイブレークです。 複数の文字列の距離が同じ場合、最初に見つかった最小値をそのまま維持することはできません。 辞書編集上の順序を明示的に比較する必要がありますが、距離だけを保存すると誤って処理される可能性があります。 

エッジケースには次のようなものがあります。 

状況の 1 つは、多くの同じ接頭辞が異なるが、語尾が異なる場合です。たとえば、`["aaaaaa", "aaaaba", "aaabaa"]`。 単純なアプローチでは、同一のプレフィックスが優勢であると誤って想定し、任意の一致を選択する可能性がありますが、LCS の違いはサフィックスの位置において依然として重要です。 

もう 1 つのケースは、複数の文字列の最小距離が同じである場合です。たとえば、`["abc", "abd", "aac"]`のために`"abc"`どちらも`"abd"`そして`"aac"`LCS ベースの距離で結ばれる場合があります。 正解は、最小距離だけではなく、辞書編集上最小の文字列インデックスを選択する必要があります。 

最後に、長さ 1 のような非常に小さな文字列は、等しいかどうかに応じて距離が 0 または 2 になるため、慎重に扱う必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。 すべての文字列について`si`、それを他のすべての文字列と比較します`sj`。 LCS を計算し、距離を導き出し、最小値を追跡します。 各文字列の長さは最大 8 であるため、DP を介した LCS の計算は実際には定数時間であり、1 ペアあたり約 64 回の演算になります。 ただし、文字列が 20,000 個ある場合、最悪の場合、テスト ケースごとに約 4e8 回の比較が行われることになり、遅すぎます。 

重要な観察は、文字列が非常に短いため、LCS 構造が小さな組み合わせパターンによって決定されるということです。 各文字列には最大 2^8 = 256 個のサブシーケンスがあります。 文字列を直接比較する代わりに、各文字列をそのすべてのサブシーケンスで表し、ハッシュまたはビットマスク署名を使用できます。 

各文字列のすべてのサブシーケンスを事前計算してマッピングできます。 2 つの文字列間の LCS が最大長です`k`共通の長さの部分列を共有するように`k`。 これは、サブシーケンス署名によってグループ化された文字列を処理すると、重複を最大化する候補を検索できることを示唆しています。 

より直接的で効率的なアプローチは、8 から 0 までの可能な LCS 長を反復処理することです。文字列ごとに、長さが減少するすべてのサブシーケンスを生成し、サブシーケンスから候補文字列まで事前に計算されたマップでそれらを検索します。 最初の空でない一致により、最適な LCS が得られ、したがって最小距離が得られます。 

各文字列は 256 個のサブシーケンスしか生成しないため、前処理の合計は約 500 万回の操作となり、これは容易に実現可能です。

 ## アルゴリズムのチュートリアル

 すべての文字列をそのすべてのサブシーケンスのコンパクトな表現に変換し、それらの表現を使用して最適な一致を効率的に推測することで、この問題を解決します。 

1. 文字列ごとに、その文字のビットマスクを使用してすべてのサブシーケンスを生成します。 各サブシーケンスは、サブシーケンス文字列または圧縮ハッシュをキーとする辞書に保存されます。 各キーとともに、それを含む文字列のすべてのインデックスを保存します。 このステップでは、サブシーケンスから候補文字列への逆インデックスを構築します。 
2. 文字列ごとに`si`、長さから開始して、長さの降順にサブシーケンスを検討して、最も一致するものを見つけようとします。`|si| - 1`この順序の理由は、共通のサブシーケンスが長くなると距離が小さくなるためです。 
3. 固定サブシーケンス長の場合`k`のすべての部分列を列挙します。`si`長さの`k`。 各サブシーケンスについて、事前計算されたマップを使用して、どの文字列にそれが含まれているかを検索します。 
4. 候補者が見つかったら`sj`それは違います`i`を使用して距離を計算します。`|si| + |sj| - 2k`。 これまでに見つかった最良の距離を維持し、より小さい値または辞書順に小さい文字列と等しい値が見つかった場合は、答えを更新します。 
5. 指定された場所で有効な候補者を見つけたら、早期に終了します`k`、それより小さくないので`k`答えを改善することができます。 

なぜ効果があるのか

 正確さは、LCS では距離が単調であるという事実から得られます。 LCS が大きいほど、常に小さいか等しい距離が生成されます。 サブシーケンスの長さを長いものから短いものまで検索することにより、初めて共通のサブシーケンスが見つかると、セット内の一部の文字列で可能な最大の LCS が保証されます。 考えられるすべてのサブシーケンスが列挙されるため、LCS を達成する候補を見逃すことはありません。 タイブレークは候補の評価中に明示的に処理され、等距離の中から辞書順に最小の選択が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gen_subseqs(s):
    n = len(s)
    res = []
    for mask in range(1 << n):
        t = []
        for i in range(n):
            if mask & (1 << i):
                t.append(s[i])
        res.append("".join(t))
    return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = [input().strip() for _ in range(n)]

        # map subsequence -> list of indices
        mp = {}

        subs = []
        for i, st in enumerate(s):
            all_subs = gen_subseqs(st)
            subs.append(all_subs)
            for sub in all_subs:
                if sub not in mp:
                    mp[sub] = []
                mp[sub].append(i)

        ans_idx = [-1] * n
        ans_dist = [10**9] * n

        for i in range(n):
            best_d = 10**9
            best_j = -1

            # try subsequences by decreasing length
            # group by length
            by_len = {}
            for sub in subs[i]:
                by_len.setdefault(len(sub), []).append(sub)

            for k in range(len(s[i]) - 1, -1, -1):
                if k not in by_len:
                    continue
                found = False
                for sub in by_len[k]:
                    for j in mp.get(sub, []):
                        if j == i:
                            continue
                        d = len(s[i]) + len(s[j]) - 2 * k
                        if d < best_d or (d == best_d and s[j] < s[best_j] if best_j != -1 else True):
                            best_d = d
                            best_j = j
                if best_j != -1:
                    break

            ans_idx[i] = best_j + 1
            ans_dist[i] = best_d

        print(*ans_idx)
        print(*ans_dist)

if __name__ == "__main__":
    solve()
```この解決策は、すべての文字列のすべての部分列を列挙することから始まります。 長さが最大 ​​8 であるため、これは安全です。つまり、文字列あたり 256 個のサブシーケンスは定数スケールで動作します。 これらのサブシーケンスは逆インデックスに保存され、指定されたサブシーケンスがどの文字列に含まれているかを簡単に検索できます。 

各文字列について、そのサブシーケンスを長さ別に再編成して、最初に長い一致を試行できるようにします。 検索中に、指定されたサブシーケンスの長さに対して有効な一致が見つかったら、それより短い共通サブシーケンスでは距離を改善できないため、検索は停止します。 

辞書編集上のタイブレークは、距離が等しい場合に文字列値を比較することによって、候補の更新中に処理されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、多くの文字列が同一のサブシーケンスを共有しているが、最後の文字が異なる場合です。 例えば、`"aaaaaa"`、`"aaaaab"`、 そして`"aaaaba"`。 このアルゴリズムは同一の長さのサブシーケンスを生成しますが、タイブレークにより、`"aaaaba"`選ばれます`"aaaaab"`等しい距離が得られ、辞書順に小さい場合。 

文字列の長さが 1 の場合、別のエッジ ケースが発生します。ここでは、サブシーケンスは`""`共通の文字が存在しない場合、アルゴリズムは正しく長さ 0 LCS に戻ります。 

最後のエッジ ケースは、複数の文字列が、異なるサブシーケンス長にわたって同等に最適な候補である場合です。 このアルゴリズムは、最初に見つかった一致の一意性を決して想定せず、同じ LCS レベル内で比較を継続し、重度のタイ条件下でも正確性を保証します。
