 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは音楽ジャンルのコレクションを記述します。i 番目のジャンルには ci の個別の曲が含まれます。 このプールから合計で正確に m 曲を選択する必要がありますが、各ジャンルで利用可能な曲を超えない限り、任意のサブセットを選択できます。 

選択は整数 ki で表されます。ここで、ki はジャンル i から選択する曲の数です。 これらの値は 0 ≤ ki ≤ ci を満たす必要があり、それらの合計は正確に m でなければなりません。 ジャンル間で m 個のセレクションを配布する有効な方法の中で、私たちは配布が可能な限りバランスがとれるようにしたいと考えています。 不均衡の尺度は、すべてのジャンルの中で最も使用されているジャンルと最も使用されていないジャンルの差、つまり最大 ki から最小 ki を引いたものです。 

重要な微妙な点は、まったく使用していないジャンルでも最小限の貢献をしているということです。 したがって、一部の ki がゼロに等しい構成は、すべてのジャンルが少なくとも 1 回使用されない限り、目標をすぐに引き上げます。 これは、容量 ci を尊重しなければならないという制約と強く相互作用します。 

この制約は、すべてのテスト ケースにわたるジャンルの合計数が最大 2 · 10^5 と大きく、ci が 10^9 まで大きくなる可能性があることを意味します。 これにより、すべての分布を試行したり、割り当てのユニットごとのシミュレーションを実行したりするソリューションは除外されます。 テスト ケースごとに n の二次関数であっても合格しません。 

現在最も小さい ki に曲を段階的に配布しようとする単純な貪欲な方法も、微妙に失敗する可能性があります。これは、初期のローカル バランシングによって後で ci 違反が強制される可能性があり、最適な解決策はグローバル レベリングしきい値に依存するためです。 

一般的なエッジケースは、m が n に比べて小さい場合に発生します。 たとえば、n = 5、m = 2、およびすべての ci が大きい場合、1 つの曲を 2 つのジャンルに割り当て、残りに 0 を割り当てるのが最善で、最小値は 0、最大値は 1 となるため、答えは 1 になります。常にすべてのジャンルに均等に分散しようとする貪欲な人は、実現可能性をチェックする前に誤ってすべてのジャンルに 1 を与えようとする可能性があります。 

もう 1 つの特殊なケースは、容量が大幅に異なる場合です。 たとえば、あるジャンルの ci = 100 と他のジャンルの ci = 1 があり、m が大きい場合、制限されたジャンルにより達成可能な最小レベルが強制され、これはジャンルごとではなく全体的に考慮する必要があります。 

## アプローチ

 主な困難は、m 個の同一ユニットを n 個の境界付きビンに分散しており、最も多く充填されているビンと最も充填されていないビンの間の広がりを最小限に抑えたいことです。 これは、最終的な構成が可能な限り「平坦」であるべきであることを示唆しています。これは、ほとんどの ki が、R − L が最小化された小さな間隔 [L, R] の周囲に集まる必要があることを意味します。 

強引なアプローチでは、容量を考慮して、m 曲のジャンルへの可能なすべての割り当てが試行されます。 たとえ順列ではなく数だけを考慮したとしても、これは、m を n 個の部分に組み合わせるオーダーの複雑さを伴う有界整数合成問題と同等であり、指数関数的に増加します。 m は大きくなり、n は 2 · 10^5 までであるため、(i、残りの m、現在の最小値、現在の最大値) を超える DP でさえも大きすぎます。 

重要な洞察は、視点を逆転させることです。ki を構築する代わりに、候補の差 D = max ki − min ki を固定し、それを達成する有効な割り当てが存在するかどうかを尋ねます。 これにより、問題は構造化された範囲制約に関する実現可能性のチェックに変換されます。 

最小レベル L を固定する場合、容量制限のために強制的にそれ以下に留まらなければならないジャンルを除き、すべてのジャンルは少なくとも L を取る必要があります。 L が選択されると、各ジャンルにかかる時間は最大でも min(ci, L + D) になります。 これにより、問題は、すべての ki を許可された間隔内に保ちながら、これらの範囲内で少なくとも m ユニット、最大でも m ユニットを割り当てることができるかどうかを確認することに変わります。

単調性は重要な構造です。上限を緩和すると柔軟性が高まるだけなので、特定の差 D が実現可能であれば、より大きな D も実現可能です。 これにより、D に対する二分探索が可能になります。D ごとに、選択したベースライン L から導出された制約の下で達成可能な最大値と最小値の合計を計算し、m が達成できるかどうかを確認します。 

L 自体は最終構成ではグローバルに固定されていないため、代わりに最適解では、最小 ki が ci のソートによって生じる ci 制限値またはしきい値制限値の 1 つになることが観察されます。 これは、容量を並べ替えて、意味のある各ブレークポイントに最小値を固定しようとする標準的なトリックにつながります。 

ci をソートし、候補の最小レベル L を検討します。固定 L の場合、ジャンルは、すべての ci を取り、固定和を寄与する必要がある ci < L のジャンルと、L と ci の間の値を取ることができる ci ≥ L のジャンルに分割されます。 次に、m を達成する実現可能性をテストし、制限された間隔の下で可能な限り最良の最大値を計算し、結果の広がりを導き出します。

 | ソート + 候補の最小レベルに対する実現可能性 | テストあたり O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列 c を非降順でソートします。 L より下のすべてのジャンルは均一に動作するため、ソートにより候補の最小レベル L を構造化された方法で推論することができます。 
2. c のプレフィックス合計を事前計算します。 これにより、すべての ci < L が完全に取得される必要があるため、しきい値 L を設定した場合に「強制」される曲の数をすばやく計算できます。 
3. ci を潜在的な最小レベル L = ci として扱い、可能な各位置 i に対して繰り返します。 これが機能するのは、最適なソリューションでは割り当てられた最小値が容量によって引き起こされる境界と一致するためです。 
4. 固定 L について、L 以下にあるジャンルの数を計算します。これらのジャンルについては、L に到達できないため、その寄与は ci に固定されます。これにより、基本合計が定義されます。 
5. ci ≥ L のジャンルでは、それぞれが L と ci の間で貢献できます。 合計のスラック キャパシティを計算し、L を超える追加ユニットを分配することで合計 m に正確に到達できるかどうかを判断します。 
6. 可能であれば、残りのスラックを貪欲に埋めることにより、この L の下で最大のジャンルで可能な最大割り当て値を計算し、ci 境界を確実に尊重します。 
7. すべての候補 L にわたって、max ki − min ki の最小可能値を追跡します。 

### なぜ効果があるのか

 最適な割り当てでは、ki の中でゼロ以外の最小値またはゼロの値が、容量の境界に達するか、最小値をさらに上げると合計が m を超える均一な平準化点に達するしきい値に対応する必要があります。 どちらの制約も線形で単調であるため、解空間は、sorted ci によって定義されたチェック ブレークポイントに崩壊します。 L が固定されると、すべての有効な構成は合計割り当てに関して凸状の間隔を形成するため、実現可能性は計算可能な範囲に対して m を比較することになります。 これにより、候補 L 値の間で最適な解が失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        c = list(map(int, input().split()))
        c.sort()
        
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + c[i]
        
        ans = float('inf')
        
        for i in range(n):
            L = c[i]
            
            # genres < i are below L, all fully taken
            base = pref[i]
            
            # remaining genres
            k = n - i
            
            # we try to distribute remaining m - base among k genres
            rem = m - base
            
            if rem < 0:
                continue
            
            # each of these k genres can take at least L, so subtract baseline L*k
            if rem < L * k:
                continue
            
            rem -= L * k
            
            # extra capacity above L
            cap = 0
            for j in range(i, n):
                cap += c[j] - L
            
            if rem > cap:
                continue
            
            # compute max ki among large side
            # worst-case spread: smallest is L, largest is L + distributed extras
            mx = L + min(c[n - 1] - L, rem)
            ans = min(ans, mx - L)
        
        out.append(str(ans if ans != float('inf') else 0))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、すべての候補最小レベルを意味のある境界でテストできるように、容量を並べ替えることから始まります。 プレフィックスの合計は、選択したしきい値 L に到達できないジャンルからの強制選択を迅速に計算するために使用されます。L ごとに、残りのすべてのジャンルを均一に扱い、下限 (アクティブなジャンルごとに少なくとも L) と上限 (ジャンルごとの ci) の両方を尊重しながら、残りの必要な曲を割り当てることができるかどうかを確認します。 割り当てが可能な場合は、その構成で最小 L と達成可能な最大値の間にどの程度の不均衡が残っているかを計算します。 

実装の微妙な詳細は、実行可能性チェックで、必要な最小割り当てと L を超える総容量の両方を確実に考慮することです。どちらかの条件が欠けていると、不可能な分散が受け入れられるか、有効な分散が拒否されます。

 ## 特殊なケース

 1 つのエッジ ケースは、m が n より小さい場合に発生し、多くの ki がゼロになります。 たとえば、n = 5、m = 2、c はすべて大きいです。 1、1、0、0、0 を割り当てることができるため、正解は 1 です。すべてのジャンルを使用する必要があると想定する方法は、ここでは失敗します。 このアルゴリズムは、L = 0 でない限り rem が負になる実現可能性チェックを通じてこれを処理し、無効な一様な仮定を防ぎます。 

あるジャンルの容量が非常に大きく、他のジャンルの容量が小さい場合には、別の特殊なケースが発生します。 たとえば、c = [1, 1, 1, 100]、m = 5 です。最適な値は [1, 1, 1, 2] で、差は 1 になります。アルゴリズムは、ci − L までの余剰割り当てのみを許可することでこれを捉え、最小境界構造に影響を与えることなく大きなビンがすべての余剰を吸収するのを防ぎます。
