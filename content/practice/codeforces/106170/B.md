 ## 解決策
 ## 問題の理解

 私たちにはハブと呼ばれる場所のシステムが与えられています。 どのハブからでも、毎日の移動は 2 つの独立した選択肢で構成されます。まず、何らかの方法論の「出発フォーム」を使用して現在のハブを離れ、次に、何らかの (おそらく異なる) 方法論の「オンボーディング フォーム」を使用して目的地のハブに入ります。 方法 j を使用してハブ i から出る方法の数は ci,j であり、同じ方法 j を使用してハブ i に入る方法の数も ci,j です。 

したがって、ハブ i からハブ v への移動は、単なるグラフのエッジではなく、重み付けされた遷移になります。 方法論の固定ペア (j は退出、t は進入) の場合、i → v の移動を実行する方法の数は ci,j · cv,t ですが、これは j ≠ t の場合に限ります。 有効な方法論のペアをすべて合計すると、1 日に i から v に移動する方法の合計数が得られます。 

ハブ 1 から開始し、このプロセスをちょうど d 日間繰り返します。 毎日、選択した遷移に応じて乗算係数が寄与するため、ハブ上の完全な有向グラフ上で長さ d の加重ウォークを効果的にカウントします。エッジの重みは、方法論による構造化因数分解から得られます。 

制約は構造を必要とするものです。 ハブの数は最大 10^4 であるため、ステップごとに O(m^2) の遷移を行うことは不可能です。 方法論の数は最大 40 であり、これは、k 次元表現を使用してハブ間の動作を圧縮する必要があることを強く示唆しています。 日数は最大 10^6 に達する可能性があり、状態の進化を累乗または閉じた形式に折りたたむことができるものに還元できない限り、日ごとの遷移を明示的にシミュレートすることは即座に除外されます。 

単純なアプローチでは、ハブ上のベクトル dp を維持し、毎日高密度の遷移を適用しようとします。 それには O(m^2 d) のコストがかかりますが、これは実現不可能です。 

より微妙なエッジ ケースは、自己遷移から発生します。 同じハブに滞在することは許可されていますが、出発と到着には依然として独立したフォーム カウントが含まれており、制限 j ≠ t により一部の組み合わせが削除されるため、これは簡単な ID の移動ではありません。 独立性を前提としたり、平等な方法論の排除を無視した不注意な解決策は、過大な評価を招くことになります。 別の失敗例は、メソッド間の相互作用を考慮せずに、遷移をハブごとに分離可能として扱うことです。 これにより、「異なる方法論」ルールによって導入された制約結合が破壊されます。 

## アプローチ

 ブルートフォースの観点では、プロセスを m 個のハブにわたるマルコフのようなシステムとして解釈し、各ステップですべてのハブ i からすべてのハブ v に進む方法の数を再計算します。固定ペア (i, v) の場合、方法論 j と t のすべてのペア (j ≠ t) を考慮し、ci,j · cv,t を合計する必要があります。 1 つの遷移の計算には O(k^2) かかるため、完全な m × m 遷移行列の構築には O(m^2 k^2) かかります。 これを d 日間繰り返すことはまったく不可能です。 

重要な観察は、ハブへの依存がほぼ完全に因数分解されていることです。 式 ci,j · cv,t は、i と j のみに依存する項と v と t のみに依存する項の積に分離されます。 これは、すべての遷移をハブ間の相互作用を通じて直接表現するのではなく、ハブごとの小さな k 次元の要約を通じて表現できることを意味します。 

各ハブ i に対して、k 次元ベクトル ci を定義します。 移動の寄与は、これらのベクトルの双一次結合、特に ci,j cv,t の j ≠ t にわたる合計にのみ依存します。 これは、対角項 j = t を減算する必要があることを除いて、j と t のほぼ完全な内積です。 これにより、遷移の重みが 2 つの構造化された量の差、つまり合計の全積から座標方向の積の積を引いたものに変換されます。

遷移カーネルがこの低次元形式で書き直されると、システムの進化は m 次元ではなく k 次元の集合状態で表現できるようになります。 これにより、日々の変換が固定次元空間での線形再帰となるため、問題は 1 日あたりの少数の集計値の追跡と、数日間にわたる高速累乗の適用に軽減されます。 

ブルート フォースは、ハブ全体で冗長構造を繰り返し再計算するため失敗します。一方、最適解では、すべてのハブの相互作用が固定の k × k 相互作用構造に圧縮され、時間の経過とともにその構造が進化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d · m^2 · k^2) | O(m^2) | 遅すぎる |
 | 最適 | O(mk + k^3 log d) | O(m + k^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各ハブ i を長さ k のベクトル ci として再解釈します。 1 日にハブ i からハブ v に移動する方法が何通りあるかを理解したいと考えています。 

すべての j、t の合計を書き込み、禁止された対角線の場合を減算することによって、制約 j ≠ t を拡張します。 

固定 i と v の場合、遷移の重みの合計は次のようになります。 

∑j ∑t ci,j cv,t − ∑j ci,j cv,j

 最初の項は (∑j ci,j)(∑t cv,t) として因数分解され、ハブごとに 2 つのスカラー要約のみに依存します。 第 2 項は、ci と cv の内積です。 

これは、すべてのハブが 2 種類の量を通じてのみ寄与していることを示しています。方法論にわたる総和と、内積の k 次元ベクトルそのものです。 

ここで、d 日目の状態表現を導入します。ハブごとに、その現在の寄与を追跡しますが、すべてのハブに伝播するのではなく、これらの要約を使用してハブ全体を集計します。 重要なのは、考えられるすべての宛先ハブを合計した後、ハブへの寄与は合計のグローバルな集計とコンポーネントごとの合計にのみ依存するということです。 

現在のハブ全体の重みの配分に関して、重みの合計と方法論コンポーネントの加重合計という 2 つのグローバル構造を維持しています。 

毎日の更新では、ci,j 値で構成される行列 C から導出された固定 k × k 線形変換を介してこれらの集計が変換されます。 

d 日を適用するには、k × k 行列の 2 進累乗を使用してこの変換を累乗します。 

1. 各ハブ i について合計 Si = ∑j ci,j を事前計算します。 
2. M[a][b] が方法論の相互作用に対応する寄与を蓄積する k × k 行列 M を構築します。具体的には、a ≠ b 制約を強制した後に、出発方法 a と到着方法 b の選択がどのように寄与するかを捕捉します。 
3. システムの発展を、k^2 次元または k 次元の圧縮状態での固定線形演算子による乗算として解釈します。 
4. 高速累乗を使用して、この演算子を d 回適用した場合の効果を計算します。 
5. 結果の変換を初期状態ベクトルに適用します。初期状態ベクトルはハブ 1 に集中し始めます。 

重要な単純化は、ハブ構造が凝集後に消失することです。 方法論の相互作用のみが残り、それらは一定サイズの線形システムを形成します。 

### なぜ効果があるのか

 ハブをめぐる進化は、1 日後に各ハブに到達する方法の数が、以前のハブからの独立した寄与の合計であるという意味で線形です。 すべての遷移の重みは、k 次元の相互作用項のみを使用して ci および cv の関数に因数分解されるため、システム全体は固定の有限次元ベクトル空間の下で閉じられます。 これにより、d が増加しても新しい自由度が出現しないことが保証されるため、繰り返し適用することは固定線形変換を累乗することと同じになります。 これにより、完全な状態をシミュレートするのではなく、問題を行列のべき乗に還元する正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mat_mul(A, B):
    n = len(A)
    m = len(B[0])
    p = len(B)
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        Ai = A[i]
        for k in range(p):
            if Ai[k] == 0:
                continue
            aik = Ai[k]
            Bk = B[k]
            for j in range(m):
                res[i][j] = (res[i][j] + aik * Bk[j]) % MOD
    return res

def mat_pow(M, e):
    n = len(M)
    res = [[0]*n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1
    base = M
    while e:
        if e & 1:
            res = mat_mul(res, base)
        base = mat_mul(base, base)
        e >>= 1
    return res

def main():
    m, k, d = map(int, input().split())
    C = [list(map(int, input().split())) for _ in range(m)]

    S = [sum(row) for row in C]

    M = [[0]*k for _ in range(k)]

    for i in range(m):
        for a in range(k):
            for b in range(k):
                if a == b:
                    continue
                M[a][b] = (M[a][b] + C[i][a] * C[i][b]) % MOD

    P = mat_pow(M, d)

    v = [0]*k
    v = C[0][:]

    ans = 0
    for i in range(k):
        for j in range(k):
            ans = (ans + P[i][j] * v[j]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```この実装では、まずハブ方法論マトリックスを読み取り、ハブごとの単純な要約を計算します。 次に、ハブを通過するときに方法論のペアがどのように相互作用するかを捕捉する k × k 遷移行列を構築し、対角線の寄与を除外することで出発方法と到着方法が異なるという制約を強制します。 

行列のべき乗ステップでは、この変換を d 日間にわたって適用します。 k は最大 40 であるため、k × k 行列は O(k^3 log d) べき乗を行うのに十分な大きさのままです。 

最後に、ハブ 1 の方法論プロファイルから初期状態が導出されます。ハブ 1 では、考えられるすべての出発フォームから開始するためです。 べき乗された遷移行列を乗算すると、有効なシーケンスの累積数が得られます。 

実装の微妙な詳細は、行列の乗算全体でモジュラー演算を保証することです。 もう 1 つは、M を構築するときに a = b の場合を正しく除外することです。 これを忘れると、無効な毎日の遷移が組織的に過剰にカウントされることになります。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    m, k, d = map(int, input().split())
    C = [list(map(int, input().split())) for _ in range(m)]

    S = [sum(row) for row in C]

    M = [[0]*k for _ in range(k)]
    for i in range(m):
        for a in range(k):
            for b in range(k):
                if a != b:
                    M[a][b] = (M[a][b] + C[i][a] * C[i][b]) % MOD

    def mat_mul(A, B):
        n = len(A)
        res = [[0]*n for _ in range(n)]
        for i in range(n):
            for k in range(n):
                if A[i][k]:
                    for j in range(n):
                        res[i][j] = (res[i][j] + A[i][k]*B[k][j]) % MOD
        return res

    def mat_pow(A, e):
        n = len(A)
        R = [[1 if i==j else 0 for j in range(n)] for i in range(n)]
        B = A
        while e:
            if e & 1:
                R = mat_mul(R, B)
            B = mat_mul(B, B)
            e >>= 1
        return R

    P = mat_pow(M, d)

    v = C[0]
    ans = 0
    for i in range(k):
        for j in range(k):
            ans = (ans + P[i][j] * v[j]) % MOD

    return str(ans % MOD)

 ## 特殊なケース

 最初のエッジ ケースは、k = 1 の場合です。方法論は 1 つだけであるため、j ≠ t という制約により、毎日の移動は不可能になります。 アルゴリズムはこれを処理します。これは、遷移行列 M がすべて 0 になり、累乗ではその構造が維持され、d ≥ 1 の場合は 0 シーケンスが得られるためです。 

もう 1 つのエッジ ケースは、ハブ全体で一部の ci,j 値が 0 である場合です。 その場合、M の特定の行または列が消えます。 行列の構築では積 ci,a · ci,b が累積されるだけであるため、ゼロのエントリは単純に何も貢献せず、これは有効な形式が存在しないことを正しく反映しています。 

3 番目のケースは d = 0 で、遷移は行われません。 べき乗は単位行列を返すため、結果は初期ハブ状態になります。 アルゴリズムはハブ 1 のベクトルを状態にシードするため、恒等乗算によって無効な遷移が発生することなく状態が保持されます。
