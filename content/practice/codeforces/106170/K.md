 ## 問題の理解

 一連の GPU が与えられ、それぞれが固定負荷で開始されます。 整数調整を追加することで各 GPU を個別に変更できますが、各調整の大きさは共通の値によって制限されます。$k$。 同時に、変更後もすべての GPU には少なくとも 1 の負荷が必要です。 

これに加えて、いくつかの会社があります。 各企業は GPU の連続セグメントを所有しており、そのセグメント全体の最終負荷の合計に制約を課しています。つまり、その間隔にわたる合計が、指定された下限と上限内に収まらなければなりません。 間隔は重複する可能性があるため、各 GPU は複数の制約に同時に影響します。 

タスクは、有効な構成を構築することではなく、可能な限り最小の構成を見つけることです。$k$そのため、すべての間隔合計制約と安全条件を満たす、許可された GPU ごとの調整のセットが存在します。 

主要な構造は、各制約がライン上のプレフィックスの合計にのみ依存し、各変数が独立して制限されるということです。 この組み合わせは、任意の線形方程式ではなく、チェーンにわたる線形制約のシステムを示唆しています。 

制約$n, m \le 1000$ことを示します$O(n^2)$あるいは$O(nm)$特に対数検索と組み合わせた場合、実現可能性チェックは許容されます。$k$。 各 GPU は大きな整数範囲にわたって変化する可能性があるため、すべての構成を直接列挙しようとするソリューションは不可能です。$10^9$。 

素朴なアプローチでは、値を貪欲に、または間隔ごとに独立して割り当てようとしますが、重複によりローカルな決定が安全でなくなります。 もう少し良い試みとしては、間隔を順番に満たそうとする可能性がありますが、先に選択すると、共有 GPU により後で矛盾が生じる可能性があります。 

いくつかの微妙なエッジ ケースにより、ローカル推論が失敗する理由が明らかになります。 重なりが大きいものの、合計範囲に互換性がない 2 つの区間を考えてみましょう。 各間隔が個別に満たされる場合でも、共有領域により不可能な割り当てが強制される可能性があります。 

もう 1 つのエッジケースは次のような場合です$a_i = 1$。 次に、より低い安全制約力が適用されます。$\Delta_i \ge 0$、負荷を軽減する機能を削除します。 下方調整に依存する解決策は、間隔の合計が有効であることを示している場合でも、無効になります。 

最後のエッジ ケースは、間隔の境界が非常に狭い場合です。たとえば、単一の間隔ですべての GPU がカバーされる場合です。 次に、問題は、固定配列の有界摂動が特定の合計範囲に達するかどうかを確認することに帰着します。これは、局所的な調整の問題ではなく、全体的な実現可能性の制約です。 

## アプローチ

 ブルートフォースアプローチでは、それぞれに直接割り当てを試みます。$\Delta_i$内で$[-k, k]$、強制する$\Delta_i \ge 1 - a_i$、すべての間隔の合計を確認します。 固定の場合$k$、各変数には小さな整数範囲があるため、すべての代入を検索するか、バックトラックを使用することを想像するかもしれません。 

これはすぐに失敗します。$n = 1000$、割り当ての数は指数関数的です。 制約はプレフィックス構造全体にわたってグローバルに相互作用するため、部分和に基づく枝刈りでも、重複する間隔を効率的に処理することはできません。 

重要な観察は、個々の GPU 値についての考え方からプレフィックスの合計についての考え方に移行することです。 定義すると$S[i]$調整された負荷のプレフィックス合計として、各間隔制約は 2 つのプレフィックス値の間の単純な差分制約になります。 一方、要素ごとの境界も、連続するプレフィックス値間の制約になります。 

これにより、問題は次の形式の不等式系に変換されます。$S[v] \le S[u] + w$そして$S[v] \ge S[u] + w$、これはまさに差分制約システムです。 このようなシステムは、グラフ上の最短経路アルゴリズムを使用して実現可能性をチェックできます。 

以来$k$与えられた場合、単調です$k$作品、それより大きいもの$k$も機能します。 これにより、バイナリ検索が可能になります$k$、各実現可能性チェックは、グラフの整合性テストの実行に帰着します。

 ## アルゴリズムのチュートリアル

 の候補値を固定します$k$すべての制約を満たすことが可能かどうかをテストします。 

まず、各 GPU 制約を調整の境界に変換します。 以来$|\Delta_i| \le k$そして$a_i + \Delta_i \ge 1$、下限を取得します$\Delta_i \ge 1 - a_i$そして上限$\Delta_i \le k$したがって、有効な範囲はこれらの制約の交差部分になります。 

次に、プレフィックスの合計を定義します。$S[i]$指数までの調整値の合計として$i$。 位置に関する各調整制約$i$間の制約になります$S[i]$そして$S[i-1]$、 以来$\Delta_i = S[i] - S[i-1] - a_i$一定のシフトまで。 これにより、連続するプレフィックス値間の差を境界付ける直接不等式が得られます。 

第三に、各社間隔$[L, R]$必要な合計限度額あり$[A, B]$は、プレフィックス合計の制約に変換されます。 区間の合計は次と等しいため、$S[R] - S[L-1]$、上限と下限の両方を 2 つのプレフィックス ノード間の線形不等式として書き換えます。 

4 番目に、各不等式が次のような有向グラフを構築します。$S[v] \le S[u] + w$有向辺になる$u \to v$重さで$w$。 

5 番目に、重みゼロのエッジを持つすべてのプレフィックス ノードに接続されたスーパー ソースを導入します。 これにより、すべての変数にアクセスできるようになり、システム内のどこでも不整合を検出できるようになります。 

6 番目に、ベルマン・フォード スタイルの緩和を使用して最短経路の実現可能性チェックを実行します。 その後も距離を伸ばすことができる場合$n+1$繰り返しでは、負のサイクルが存在します。これは、制約システムがこの問題に対して一貫性がないことを意味します。$k$。 

7番目に、二分探索を行います$k$。 各実現可能性チェックでは、すべての制約が満たされるかどうかが確認されるか、不可能であることが証明され、単調性によって検索の正確さが保証されます。 

正確さは、プレフィックス値がエッジ不等式としてエンコードされたすべてのアクティブな制約によって制限されたままであるという不変条件に基づいています。 負の合計重みを持つサイクルが存在する場合、それは必要な不等式の矛盾を表しており、接頭辞の合計の割り当てがすべての条件を同時に満たすことができないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def feasible(n, a, segs, k):
    # nodes: 0..n, S[0]=0..S[n]
    N = n + 1

    edges = []

    # S[i] - S[i-1] in [Li, Ui]
    for i in range(1, n + 1):
        lo = max(1 - a[i-1], -k)
        hi = k

        # S[i] <= S[i-1] + hi
        edges.append((i-1, i, hi))
        # S[i-1] <= S[i] - lo  => S[i-1] <= S[i] + (-lo)
        edges.append((i, i-1, -lo))

    # segment constraints
    pref = [0]
    for x in a:
        pref.append(pref[-1] + x)

    for l, r, A, B in segs:
        base = pref[r] - pref[l-1]

        lo = A - base
        hi = B - base

        # S[r] - S[l-1] <= hi
        edges.append((l-1, r, hi))
        # S[l-1] - S[r] <= -lo
        edges.append((r, l-1, -lo))

    # add super source 0 connected to all with 0
    # we use Bellman-Ford from 0
    dist = [0] * N

    for i in range(N):
        edges.append((0, i, 0))

    # Bellman-Ford
    for _ in range(N):
        changed = False
        for u, v, w in edges:
            if dist[v] > dist[u] + w:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            return True

    # one more pass => negative cycle
    for u, v, w in edges:
        if dist[v] > dist[u] + w:
            return False

    return True

def main():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    segs = []
    for _ in range(m):
        l, r, A, B = map(int, input().split())
        segs.append((l, r, A, B))

    if any(a[i] < 1 for i in range(n)):
        return print(-1)

    lo, hi = 0, 10**9

    # quick feasibility check at large k
    if not feasible(n, a, segs, hi):
        print(-1)
        return

    ans = hi
    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(n, a, segs, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    main()

実現可能性チェックでは、ベルマン フォード スタイルの緩和が使用されます。 スーパー ソースは、制約によって直接接続されていない場合でも、すべてのプレフィックス変数が緩和プロセスに確実に含まれるようにします。 その後のさらなる改善の検出$n$反復は、制約グラフ内の不一致サイクルの検出に対応します。

 ## 特殊なケース

 重要なエッジケースが 1 つ発生します。$a_i = 1$。 この場合、制約は$\Delta_i \ge 1 - a_i$すべての調整を強制的に負以外の値にします。 対称を前提としたソリューション$[-k, k]$自由度が誤って削減を許可し、実現可能性モデルの間隔制約を誤って満たす可能性があります。 下限がゼロになり、制約グラフ内のすべての負のエッジが除去されるため、アルゴリズムはこれを正しく防止します。 

単一の間隔が配列全体をカバーする場合、別のエッジ ケースが発生します。 制約は、グローバル プレフィックスの差に関する単一の不等式になります。$S[n] - S[0]$。 アルゴリズムはこれをグラフ内の 1 つのエッジとしてきれいに処理し、実現可能性は、総調整能力が合計を必要な範囲にシフトできるかどうかを確認することになります。 

最後のエッジケースは、非常に大きな条件であっても制約が一貫していない場合です。$k$。 その場合、制約のない調整でも矛盾する区間限界を満たすことができないため、二分探索では事前チェックによって実行不可能性が早期に検出されます。
