 ## 解決策
 ## 問題の理解

 グリッド上にいくつかの点が与えられ、それぞれが卵を表します。 農場の「コンパクトさ」はいつでも、順序付けされていないすべての卵のペアにわたるマンハッタン距離の合計です。 言い換えれば、すべての卵のペアは、それらの間の水平距離と垂直距離を加えたものであり、これをすべてのペアにわたって集計します。 

時間が数日に分けられます。 当日$i$、 がある$s_i$そして各秒間、卵を 1 個ずつ 4 方向のいずれかに 1 単位ずつ動かすことも、何もしないことを選択することもできます。 毎日の終了後に、現在の構成のコンパクトさを評価します。 目的は、これらの毎日のコンパクト性の値の合計を最小限に抑えることです。 

主な問題点は、移動の量が自由ではなく、移動が数日にわたって分散され、コスト関数がすべてのペアごとのマンハッタン距離に依存し、ポイント間で高度に結合していることです。 

制約$n, d \le 2 \cdot 10^5$動きをシミュレートしたり、ペアごとの距離を毎日最初から再計算したりするアプローチは除外します。 すべてのペアごとの距離を動的に維持するだけでもコストがかかりすぎます。$O(n^2)$ペア。 有効なソリューションでは、システムを集約された統計に還元する必要があります。 

すべての卵が固まり始めたとき、または数日の卵の量が非常に多かったとき、微妙なエッジケースが発生します。$s_i$。 単純な戦略では、毎日個別に卵を貪欲に「圧縮」しようとするかもしれませんが、コストは個々の距離ではなく全体的なペア構造に依存するため、これは失敗します。 

たとえば、卵 2 個があるとします。$(0,0)$そして$(100,0)$。 1 つの卵をもう 1 つの卵に向かって移動すると、コストは直線的に削減されますが、移動が数日に分散されている場合は、早期に部分的に移動しても、その後のすべての日のコストが削減されます。 将来の貢献を無視した貪欲な 1 日あたりの最適化は、このトレードオフを誤って評価します。 

別の失敗例は、卵が 1 つの軸に沿って整列している場合に発生します。 水平方向と垂直方向の寄与は独立して動作しますが、多くの単純な実装ではそれらが誤って結合され、誤った更新につながります。 

## アプローチ

 主な障害は、目標が毎日の後のコンパクトネスを合計し、コンパクトネス自体がすべてのペアごとのマンハッタン距離に依存することです。 ペアごとの距離を直接追跡することは不可能です。 

最初の観察は、マンハッタン距離が独立した x 成分と y 成分に分離されるということです。 総コストは、x 座標のペアごとの絶対差の合計に、y 座標の絶対差を加えたものです。 これにより、x と y を独立して処理し、結果を最後に追加することができます。 

ここでは 1 つの次元だけに焦点を当てます。 x 座標のみを考慮するとします。 コンパクトさはすべてのペアの合計になります$|x_i - x_j|$これは、ソート順序をプレフィックス合計の一次関数として使用して書き換えることができます。 これにより、状態が次のように減少します。$O(n^2)$との相互作用$O(n)$秩序ある構造。 

2 番目の重要な洞察は一時的なものであり、すべての動きは将来のすべての日に影響を与えます。 卵を 1 単位だけ左に移動すると、将来のすべてのコンパクトネス値が、その卵が参加するペアの数だけ減少します。したがって、各単位の移動には、残りの日数にわたって永続的な利点があります。 

位置をシミュレートする代わりに、各卵の動きがわずかな改善に寄与していると解釈します。 各軸に沿って卵を分類し、その軸のスプレッドをどれだけ削減することで総コストが削減されるかを検討できます。 最大のギャップを減らすと、ペアごとの距離の合計で最大の限界利得が得られるため、最適な戦略は常に「最初に極値を内側に引っ張る」ことになります。 

これにより、動きの各単位が特定の順序統計ギャップの寄与を低減する構造が得られます。 問題は、固定の総移動数 (すべての移動の合計) を分配することになります。$s_i$) 日をまたがる場合、毎日のコストは残りの「削減されていない」スプレッドに依存します。 

プレフィックスの合計を使用して、最初の x コンパクト性と y コンパクト性の合計を計算します。 次に、1 日に適用できる「効果的な縮小操作」の数をシミュレートし、最大の寄与を最初に貪欲に削減します。 各ユニットの縮小は将来の日に影響を与えるため、貢献度の継続的な減少シーケンスを維持します。

 ## アルゴリズムのチュートリアル

 x 座標と y 座標について個別に問題を削減し、結果を合計します。 

1. X 座標を並べ替えます。 絶対的な差分をプレフィックス合計を使用して書き換えることができるようにソートが必要です。これにより、ペアごとの距離が隣接する順序構造にわたる線形計算に変換されます。 
2. プレフィックス合計を使用して初期の x コンパクト性を計算します。 各位置について、累積合計を使用して、前のすべてのポイントと後のすべてのポイントまでの距離としてその寄与を計算します。 
3. y 座標についても同じことを行います。 
4. 利用可能な操作の合計を計算する$S = \sum s_i$。 これは、全日にわたるユニット移動の合計数です。 
5. 各ユニットの移動により、x または y 次元のいずれかでコンパクトさが 1 減少する可能性がありますが、利点はそれが適用される場所によって異なります。 最善の使用法は、常に最大の残りの限界寄与を減らすことです。 
6. 各「スプレッド単位」が総コストにどれだけ寄与するかを表す寄与構造を維持します。 移動を適用するたびに、残りの最大の寄与分が減ります。 これは、ソートされた座標の現在の最大ギャップを常にターゲットにすることと同じです。 
7. 適用の効果をシミュレーションします$S$削減。 縮小するたびに、現在の最大の限界寄与分だけ全体のコンパクト性が減少し、その寄与度は繰り返し減少するにつれて縮小します。 
8. 最終的な答えは、初期のコンパクトさから全体に適用される合計削減量を引いたものです。$S$モジュロで計算された移動$998244353$。 

### なぜ効果があるのか

 重要な不変条件は、いかなる瞬間においても、1 次元のコンパクトさは、連続するソートされた座標間のギャップのマルチセットによって完全に決定されるということです。 各ユニットの移動は、これらのギャップの 1 つから 1 つのユニットを削減するものと見なすことができ、より大きなギャップを削減すると、常に、より小さいギャップを削減する場合よりもペアごとの合計の合計が大きくまたは同等の減少をもたらします。 これらのギャップではコスト関数が線形であるため、常に利用可能な最大の限界削減を選択することで、時間の経過とともに最適な割り当てが生成されます。 この貪欲な優位性により、移動の再配置がなく、数日間の合計がより少なくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, d = map(int, input().split())
    xs = []
    ys = []
    for _ in range(n):
        x, y = map(int, input().split())
        xs.append(x)
        ys.append(y)

    s = list(map(int, input().split()))
    S = sum(s)

    xs.sort()
    ys.sort()

    def initial_cost(arr):
        pref = 0
        res = 0
        for i, v in enumerate(arr):
            res += v * i - pref
            pref += v
        return res

    base_x = initial_cost(xs)
    base_y = initial_cost(ys)
    base = base_x + base_y

    # collect gaps between consecutive points
    gaps = []
    for arr in (xs, ys):
        for i in range(1, len(arr)):
            gaps.append(arr[i] - arr[i - 1])

    gaps.sort(reverse=True)

    # each move reduces largest remaining gap contribution by 1
    # each gap contributes linearly, so we just subtract S from largest gaps greedily
    i = 0
    reduction = 0

    for _ in range(S):
        if i >= len(gaps):
            break
        reduction += gaps[i]
        gaps[i] -= 1
        if gaps[i] == 0:
            i += 1
        else:
            j = i
            while j + 1 < len(gaps) and gaps[j] < gaps[j + 1]:
                gaps[j], gaps[j + 1] = gaps[j + 1], gaps[j]
                j += 1

    answer = (base - reduction) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```マンハッタン距離は 2 つの独立した 1D 問題にきれいに分割されるため、コードは座標を x リストと y リストに分割することから始まります。 次に、プレフィックス累積を使用して各次元の初期ペアワイズ距離合計を計算します。これにより、二次ペアリングが回避されます。 

次に、ソートされた順序で連続するギャップのリストを作成します。 これらのギャップは、構成を圧縮することで最大の限界利益が得られる場所をエンコードします。 

シミュレーション ループは、各ユニットの移動を現在最大のギャップに適用し、ギャップを減らして順序を維持します。 この貪欲なプロセスは、最も有益な圧縮操作を繰り返し適用することをモデル化します。 

最後に、合計の削減量が初期のコンパクトさから減算されます。 

実装の微妙な詳細は、各デクリメント後のギャップのソート順序を維持することです。 単純なヒープの方がクリーンですが、現在の構造ではローカル スワップが使用されています。 正確さは、更新のたびに順序不変条件を常に復元するかどうかに依存します。

 ## 特殊なケース

 エッジケースの 1 つは、すべての卵が同じ位置を共有する場合です。 その場合、すべてのギャップはゼロになるため、削減は不可能です。 このアルゴリズムは即座にゼロのコンパクト性を計算し、リダクション ループに入ることはなく、正確にゼロを生成します。 

もう 1 つの特殊なケースは、卵が 1 個しかない場合です。 ペアごとの合計は空であるため、初期コンパクト性はゼロです。 たとえ手数が多くても、縮める隙がないので、答えはゼロのままです。 

3 番目のエッジ ケースは、すべての移動予算がギャップに比べて非常に大きい場合です。 これ以上の削減はコストを改善しないため、貪欲な削減は最初にすべての正のギャップを使い尽くしてから停止します。 これは、すべての座標が等しくなると、追加の移動によってペア間の距離をさらに縮めることはできないという事実と一致します。
