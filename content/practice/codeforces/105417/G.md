 ## 解決策
 ## 問題の理解

 ニワトリをシミュレートしているか卵をシミュレートしているかに応じて、各エッジに沿った移動に異なる時間がかかる有向グラフが与えられています。 実験を開始できる指定された入口ノードがいくつかあり、成功状態を表す出口ノードがいくつかあります。 

どのような開始入口でも、ニワトリ (または卵) は最適に動作し、常に可能な限り最速のルートをたどって出口に到達すると想定されます。 開始から終了までのパスが存在しない場合、その実行は終了しません。 

実験は確率的に 2 回繰り返されます。 まず、鶏が入口ノードの 1 つに均一にランダムに配置され、出口に到達するまでの移動時間が記録されます。 次に、卵が独立して均一にランダムに入口ノードに配置され、その移動時間が記録されます。 結果はどちらが早く出口に到達するかによって決まり、時間が一致する場合、または両方が出口に到達できない場合は同点が許可されます。 

出力は、鶏が卵よりも早く終了する確率とその逆の確率を比較することによって決定されます。 

この制約では、最大 200,000 のノードとエッジが許可されます。 これにより、入り口ごとに最短経路を個別に計算するアプローチは即座に除外されます。これは、同じ構造に対してグラフ アルゴリズムを繰り返し実行することになるためです。 ソリューションは計算を再利用し、少数のグローバル最短パスの実行に依存する必要があります。 

一部の入口がどの出口にも到達できない場合、微妙なエッジケースが発生します。 その場合、それらの距離は事実上無限になります。 両方の種が到達不可能なスタートを切った場合、それらのケースは勝利ではなく引き分けに貢献します。 到達不能なノードを単純に無視する単純なアプローチでは、確率が歪められてしまいます。 

もう 1 つの重要な特殊ケースは、すべての入り口に到達できない場合に発生します。 そうすれば、鶏と卵は常に引き分けとなり、答えは「引き分け」になるはずです。 

## アプローチ

 直接シミュレーションでは、鶏と卵の順序付けされたすべての入り口のペアが考慮され、それらの最短経路時間が計算され、それらが比較されます。 最短パスが事前に計算されている場合でも、サイズ a のすべてのペアを比較する必要があり、2次の O(a²) 比較ステップが必要になりますが、これは最大 200,000 には遅すぎます。 

重要な観察は、すべてのノードについて、ニワトリと卵の出口に到達するまでの最小時間を個別に計算すると、各入口が単一の数値ペアになるということです。 次に、問題は、サイズ a の固定マルチセットから均一に抽出された 2 つの独立した確率変数を比較することに帰着します。 

すべての順序付きペアにわたって、リストの 1 つの値が同じリストの別の値よりも小さい頻度を計算することが実質的に求められます。 これは、明示的なペアの列挙ではなく、ソートされた配列の計数問題に変換できます。 

各入口 i について、ペア (tc[i], te[i]) がわかります。 チキンが勝つ頻度を計算するには、tc[i] < te[j] となる i の数をすべての j で合計します。 tc をソートすると、二分探索で各クエリ te[j] に答えることができます。 同じ構造が卵の勝ちにも対称的に適用されます。 

ボトルネックは、グラフの走査から、重みの種類ごとに 1 回の最短パスの計算に移行し、その後、十分に効率的なソートとバイナリ検索に移行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペアの比較 | O(a² + m log n) | O(n) | 遅すぎる |
 | ダイクストラ + ソート + カウント | O(m log n + a log a) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グラフの方向を反転し、出口をソースとして扱います。 これにより、問題は「入口で開始して出口に行く」という問題から、標準的な複数ソースの最短経路問題に変換されます。 すべての出口からダイクストラを一度に実行すると、すべてのノードの出口までの最短距離が得られます。 
2. ダイクストラを 2 回実行します。1 回目は鶏のエッジの重みを使用し、もう 1 回は卵のエッジの重みを使用します。 これにより、2 つの配列 tc と te が生成されます。ここで、tc[v] は v から任意の出口までの最小チキン移動時間であり、te[v] についても同様です。 
3. 入口ノードに対応する値のみを抽出し、サイズ a の 2 つのリストを形成しますが、両方の種が同じ入口セットを使用するため、インデックスによってペアになります。 
4. 到達不可能な距離を、無限を表す大きなセンチネル値に置き換えます。 到達不可能な状態が正しく比較されるように、これは両方の種にわたって一貫している必要があります。 
5. チキンタイムリスト tc を入口ごとにソートします。 
6. 各入口 j について、tc の二分探索を使用して、厳密に te[j] より小さいチキンタイムがいくつあるかを計算します。 これらの値を合計すると、チキン勝利の合計が得られます。 
7. 順序ペアの合計を a² として計算します。 tc と te の役割を交換することで、egg の勝利を対称的に計算します。 
8. 同点は合計ペアから勝利を減算することで得られ、最終的な答えは勝利数を比較することによって決定されます。 

正しさは、順序付けされたすべての入口ペアがニワトリの勝ち、卵の勝ち、または引き分けのうちの 1 つの結果カテゴリに正確に寄与するという事実に基づいており、これらのカテゴリは 2 つのスカラー最短パス値を比較することによって完全に決定されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

INF = 10**30

def dijkstra(n, adj, sources):
    dist = [INF] * (n + 1)
    h = []
    for s in sources:
        dist[s] = 0
        heapq.heappush(h, (0, s))

    while h:
        d, u = heapq.heappop(h)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(h, (nd, v))
    return dist

def solve():
    n, m, a, b = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    radj = [[] for _ in range(n + 1)]

    edges = []
    for _ in range(m):
        u, v, c, e = map(int, input().split())
        adj[u].append((v, (c, e)))
        radj[v].append(u)

    starts = list(map(int, input().split()))
    exits = list(map(int, input().split()))

    radj_ch = [[] for _ in range(n + 1)]
    radj_eg = [[] for _ in range(n + 1)]

    for u in range(1, n + 1):
        for v, (c, e) in adj[u]:
            radj_ch[v].append((u, c))
            radj_eg[v].append((u, e))

    tc_all = dijkstra(n, radj_ch, exits)
    te_all = dijkstra(n, radj_eg, exits)

    tc = [tc_all[s] for s in starts]
    te = [te_all[s] for s in starts]

    def count_wins(a_list, b_list):
        a_sorted = sorted(a_list)

        from bisect import bisect_left
        res = 0
        for x in b_list:
            res += bisect_left(a_sorted, x)
        return res

    chicken_wins = count_wins(tc, te)
    egg_wins = count_wins(te, tc)

    total = a * a
    ties = total - chicken_wins - egg_wins

    if chicken_wins > egg_wins:
        print("chicken")
    elif egg_wins > chicken_wins:
        print("egg")
    else:
        print("tie")

if __name__ == "__main__":
    solve()
```実装は、両方の重量システムの逆グラフを構築することから始まります。 ダイクストラではエッジごとに単一のスカラー重みが必要であり、ニワトリと卵のダイナミクスは独立した最短経路問題であるため、この分離が必要です。 

の`dijkstra`関数はマルチソースであり、距離ゼロですべての出口を初期化します。 これにより、入口ごとにアルゴリズムを 1 回実行することがなくなり、すべての開始状態が 1 回の実行に圧縮されます。 

最短経路を計算した後、入口ノードのみを抽出する。 これにより、問題は配列上の純粋な比較問題に縮小されます。 

の`count_wins`関数は、コアの削減をエンコードします。つまり、1 つの配列をソートし、二分探索を使用して、他の配列の各クエリよりも小さい要素の数を数えます。 これは、明示的に列挙することなく、順序付きペアの優位性を直接計算します。 

最後に、勝利数を比較することで答えが決まります。 

## 実用的な例

 3 つの入口とその計算された時間を含む単純化されたシナリオを考えてみましょう。 

チキンタイム: [2、5、INF]

 卵の時間: [3, 1, INF]

 ニワトリの勝利は、各卵の時間をすべてのニワトリの時間と比較することによってカウントされます。 

卵の時間 3 の場合、3 未満の鶏の値は [2] で、寄与は 1 です。 

エッグタイム 1 の場合、それより小さいものはなく、寄与率は 0 です。 

INF の場合、すべての有限チキン値は小さくなり、2 に寄与します。 

チキンは合計3勝。 

| ステップ | b値 | | を並べ替えました 勝利が追加されました |
 | --- | --- | --- | --- |
 | 1 | 3 | [2,5,INF] | 1 |
 | 2 | 1 | [2,5,INF] | 0 |
 | 3 | INF | [2,5,INF] | 2 |

 これは、ドミナンス カウントがペアごとの比較をプレフィックス カウントに変換する方法を示しています。 

ここで対称性について考えてみましょう。役割を交換すると、同様に卵の勝ちが生成され、順序付けされたすべてのペアがどちらかの側または同点に 1 回だけ貢献することが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log n + a log a) | 2 つのダイクストラ実行がヒープ操作に加えて、入口に対するソートとバイナリ検索を支配します。 
| スペース | O(n + m) | 両方の重量システムのグラフ ストレージと距離配列 |

 グラフが 2 回だけ処理され、入口の比較がソートベースのカウントに削減されるため、この構造は制限内に問題なく収まります。

 ## 特殊なケース

 すべての入口がどの出口にも到達できない場合、 tc 配列と te 配列は両方とも完全に INF 値で構成されます。 任意のペア間の比較はすべて等しいため、すべての a² ペアは同点になります。 同一にソートされた INF リストに対する二分探索では双方に勝利が得られず、引き分けの判定につながるため、アルゴリズムはこれを自然に処理します。 

一方の種が出口に到達できるのに、もう一方の種が出口に到達できない場合、すべての有限値が INF 比較を支配します。 その場合、すべてのペアは一貫して到達可能な種を優先し、ソートベースのカウントにより特別なケースを使用せずに完全な優位性が得られます。 

複数の入口が同一の最短パス時間を共有する場合、厳密な不平等が勝利数に寄与しないため、アルゴリズムは暗黙的に同点を正確にカウントします。
