 ## 解決策
 ## 問題の理解

 私たちは整数と剰余算術を扱っていますが、無限数直線が周期規則によって色分けされていると考えると、構造がより明確になります。 

任意の整数の場合$x$、2 つの値を計算します。最初に次の値を取ります。$x \bmod a$、その結果を剰余として削減します$b$。 並行して計算も行います$x \bmod b$モジュロが続く$a$。 これら 2 つの最終結果が異なる場合は、次のようにカウントします。$x$。 

Each query gives a segment$[l, r]$, そして、その範囲内でこの不等式条件を満たす整数がいくつあるかを数えなければなりません。 

重要な難点は、$l$そして$r$と同じ大きさにすることができます$10^{18}$, そのため、各数値を個別に評価することはできません。 構造は剰余剰余のみに依存します$a$そして$b$、どちらも小さい (最大 200) ため、あるサイクルにわたる周期性が強く示唆されます。$a$そして$b$。 

強引なアイデアでは、各クエリ範囲内のすべての数値をテストします。 これは、クエリ間隔が長いとすぐに壊れてしまいます。 たとえば、次の場合$l = 1$そして$r = 10^{18}$、反復は不可能です。 

さらに微妙な問題は、プレフィックスの値を事前計算したとしても、等価性のパターンは両方の mod に依存することです。$a$そしてモッド$b$したがって、単純なプレフィックス シミュレーションではなく、構造化された繰り返し引数が必要です。 

エッジケースは次の場合に発生します。$a = b$。 その場合、両方の式はすべて同じです$x$したがって、答えは常にゼロになります。 これをチェックせずに周期的な動作を想定する不注意な実装も機能しますが、計算が無駄になったり、分割エッジの混乱が発生したりする可能性があります。 

もう 1 つのエッジ ケースは、次のいずれかの場合です。$a$または$b$次に、モジュロ チェーンの 1 つがゼロに崩壊し、式が大幅に単純化されます。 実装では、これを一般的な式の中できれいに処理する必要があります。 

## アプローチ

 ブルート フォース方式では、クエリ間隔ごとにすべての整数の条件が評価されます。 各評価には一定の時間がかかるため、1 つのクエリにコストがかかります$O(r - l + 1)$、そして最悪の場合、これは$10^{18}$。 これは直ちに実行不可能です。 

中心的な観察は、条件は次のもののみに依存するということです。$x \bmod a$そして$x \bmod b$。 これら 2 つの残基はピリオドで繰り返されます$a$そして$b$、したがって、ペアは一緒にピリオドで繰り返されます$\mathrm{lcm}(a, b)$。 以来$a, b \le 200$、この期間は最大 40000 であり、事前計算するには十分な小ささです。 

したがって、1 つの完全なサイクルの長さを計算できます。$L = \mathrm{lcm}(a, b)$、条件を満たす値がいくつあるか。 次に、最大のプレフィックス$x$は次のように表現できます。 

全サイクルと残りのセグメント。 

したがって、1 つの期間にわたってプレフィックス配列を構築し、2 つのプレフィックス評価を使用して各クエリに答えます。 

これにより、前処理後の各クエリが一定時間に短縮されます。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$L = \mathrm{lcm}(a, b)$。 これは、両方のモジュロ パターンがこの長さの後に同時に繰り返されるため、関連するすべての残基ペアの繰り返し周期を定義します。 
2. アレイを構築する`bad[i]`のために$i \in [1, L]$、 どこ`bad[i] = 1`もし$((i \bmod a) \bmod b) \ne ((i \bmod b) \bmod a)$これは、各位置が答えに寄与するかどうかを直接エンコードします。 
3. プレフィックス合計配列を構築する`pref`、 どこ`pref[i]`有効な値がいくつあるかを格納します$[1, i]$。 これにより、期間内の一定時間範囲のカウントが可能になります。 
4. 事前計算`total = pref[L]`、1 つの完全なサイクル内の有効な値の数。 これにより、大きな範囲を完全なサイクルと残りに分割することで処理できるようになります。 
5. 質問に答えるため$[l, r]$、次を計算します。 

有効な値の数$[1, r]$の数値を引いたもの$[1, l-1]$。 これらはそれぞれ、完全なサイクルを使用して計算されます。$$f(x) = (x // L) \cdot total + pref[x \bmod L]$$取り扱いには注意してください$x \bmod L = 0$。 

### なぜ効果があるのか

 式の値はペアにのみ依存します。$(x \bmod a, x \bmod b)$。 両方の残基がピリオドで独立して繰り返されるため、$a$そして$b$、結合された状態は毎回繰り返されます。$\mathrm{lcm}(a, b)$。 これにより、インジケーター関数が周期的になるため、広い範囲にわたるカウントは、全サイクルに加えて固定プレフィックスをカウントすることになり、整数間隔ごとに正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lcm(a, b):
    import math
    return a // math.gcd(a, b) * b

t = int(input())
for _ in range(t):
    a, b, q = map(int, input().split())
    L = lcm(a, b)

    bad = [0] * (L + 1)
    pref = [0] * (L + 1)

    for i in range(1, L + 1):
        x = i % a
        y = i % b
        if (x % b) != (y % a):
            bad[i] = 1
        pref[i] = pref[i - 1] + bad[i]

    total = pref[L]

    def calc(x):
        if x <= 0:
            return 0
        cycles = x // L
        rem = x % L
        return cycles * total + pref[rem]

    out = []
    for _q in range(q):
        l, r = map(int, input().split())
        out.append(str(calc(r) - calc(l - 1)))

    print(" ".join(out))
```この実装は、関数の 1 つの完全な期間を明示的に構築し、プレフィックス合計を使用して範囲クエリを定数時間演算に変換することに依存しています。 

主な点は、インデックス作成を正しく処理することです。 配列は 1 から始まるため、剰余のプレフィックスの合計には次の値が使用されます。`pref[rem]`直接、全サイクルに次の乗算が行われます。`pref[L]`。 もう 1 つの重要な詳細は、`l - 1`安全に屋内で`calc`、正でない値はゼロを返す必要があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    def solve():
        t = int(input())
        for _ in range(t):
            a, b, q = map(int, input().split())
            L = a * b // math.gcd(a, b)

            bad = [0] * (L + 1)
            pref = [0] * (L + 1)

            for i in range(1, L + 1):
                x = i % a
                y = i % b
                bad[i] = 1 if (x % b) != (y % a) else 0
                pref[i] = pref[i - 1] + bad[i]

            total = pref[L]

            def calc(x):
                if x <= 0:
                    return 0
                return (x // L) * total + pref[x % L]

            out = []
            for _ in range(q):
                l, r = map(int, input().split())
                out.append(str(calc(r) - calc(l - 1)))
            print(" ".join(out))

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    res = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return res.strip()

 ## 特殊なケース

 いつ$a = b$、両方の式が同じ計算に帰着するため、すべての項は同一に評価され、アルゴリズムのマーキング配列は完全にゼロになります。 プレフィックスの合計は一定のままで、すべてのクエリはゼロを返し、予想される数学的単純化と一致します。 

いつ$a = 1$または$b = 1$、式の一方の側はすべてゼロに折りたたまれます。$x$。 モジュロ演算が定数剰余を正しく生成し、周期構造が他のパラメータと等しい長さの自明なサイクルに縮退するため、この実装は引き続き機能します。 

いつ$l$そして$r$複数の完全なサイクルと部分的な末尾にまたがる、`calc`関数は範囲をきれいに分割します`(x // L)`完全な繰り返しと残りのセグメント。 これにより、クエリ境界とサイクル境界の位置合わせへの依存が回避され、任意の間隔の正確性が保証されます。
