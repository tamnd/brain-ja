 ## 解決策

 ## 問題の理解

 正確に配置しています$n$ルーク$n \times n$ただし、古典的な「行と列ごとに 1 つ」の設定とは異なり、複数のルークが 1 つの行または列を共有する場合があります。 構成は 2 つのグローバル条件によって制約されます。 

まず、すべての空のセルは、その行と列を見ると、その行または列のどこかに少なくとも 1 つのルークが表示されるという意味で、「カバー」されている必要があります。 したがって、空のセルを含む行と列の間には、完全に孤立した行や完全に孤立した列は存在しません。 ルークの配置はグリッド全体を支配する必要があります。 

次に、ルーク間の相互作用をカウントします。 2 つのルークが同じ行または同じ列にあり、その行または列の間にルークの間に他のルークがない場合、2 つのルークはペアになります。 これは事実上、各行 (または列) 内でルークの位置を並べ替えると、隣接するルークのみが攻撃ペアを形成することを意味します。 すべての行と列にわたるこのような隣接するペアの合計数は、正確に次のとおりである必要があります。$k$。 

出力では、有効な配置数を法的に求めます。$998244353$。 

制約$n \le 2 \cdot 10^5$あらゆるものを即座に除外します$O(n^2)$グリッド状態に対する建設または DP。 平$O(n \sqrt{n})$線形または線形に近いものが必要なので、すでに危険です$n \log n$。 タグ内の畳み込みの存在は、構造が「セグメントの数」または同様の分解に対するグローバルな畳み込みを使用して、独立した行の寄与の合計に還元されることを強く示唆しています。 

「すべての空のセルがカバーされる」という制約を強制せずに、独立した行または列の観点から考えると、微妙な障害モードが発生します。 たとえば、すべてのルークが 1 つの行に配置されている場合、ほとんどの列は空であり、カバレッジに違反します。 もう 1 つの微妙な点は、「攻撃ペア」は連続するすべてのペアではなく、隣接するペアのみであるため、行を次のように扱うことです。$t$貢献するルークス$\binom{t}{2}$ペアは正しくありません。 

## アプローチ

 直接的な試みは、次のすべての配置を考慮することです。$n$次に、ルークのカバレッジを確認し、隣接ペアをカウントします。 状態空間は次のとおりであるため、これは絶望的です。$\binom{n^2}{n}$、行と列ごとに複数のルークが許可されるため、行と列の順列に制限しても構造は捕捉されません。 

主要な構造の簡素化は、構成を行と列を「アクティブ セグメント」に分割したものとして解釈することで実現します。 各行にはある程度の数のルークが含まれており、隣接条件はその行内の順序にのみ依存します。 列についても同様です。 カバレッジ条件により、すべての行と列に少なくとも 1 つのルークが含まれる必要があります。そうでない場合、空の行または列では、直交方向のセルがカバーされないままになります。 

複数の行占有セットを修正したら、たとえば row$i$もっている$a_i$ルーク、および同様に列数$b_j$、配置の合計数は、行と列のペアへのルークの組み合わせ割り当てになります。 行内の隣接関係の寄与$a_i$ルークは、その行内でルークがどのように順序付けられるかによって異なります。$a_i$連続した点が作成する$a_i - 1$隣接するペアを線形順序として考える場合、そうではありません。$\binom{a_i}{2}$。 これは問題を次の構成を数える問題に変換します。$n$行の寄与に変換し、列構造を一貫して照合します。 

重要な観察は、構造が分割方法を数えることに帰着するということです。$n$ルークは、行と列に沿って接続されたコンポーネントを調べます。各コンポーネントはチェーンのように動作します。 隣接ペアの数は、これらのチェーン内のエッジの合計数と正確に一致します。$n - \text{number of chains}$。 したがって、修正$k$これはチェーンの数を固定することと同等であり、問​​題は分割方法を数えるという問題に減ります。$n$オブジェクトを、固定数のコンポーネントを持つ 2 部構造に変換します。 これらの分割を選択する組み合わせ論により、チェーン サイズの分布に対する畳み込みが発生します。これが、目的のソリューションに FFT または NTT が登場する理由です。 

最後に、カウントは、存在する行セグメントと列セグメントの数を選択し、分散します。$n$それらの間でルークを選択し、畳み込みを介して独立した選択肢を組み合わせます。

 ## アルゴリズムのチュートリアル

 行と列の隣接性によってルークをチェーンに分割するという観点から構成を再定式化します。 

1. 各行を一連のルーク ブロックとして再解釈します。各ブロックは、その行内の最大の連続セグメントに対応します。 このような各セグメントは、その長さから 1 を引いた値に等しい固定数の隣接ペアに寄与します。 これにより、行の寄与が位置ではなくセグメント数の関数に変わります。 
2. グローバルパラメータを定義します$c$、ルークの隣接関係を行と列のエッジとして表示したときに形成される接続されたチェーンの数。 各チェーンは、ルークが水平または垂直に隣接して接続される最大の構造です。 一定の長さのチェーンの内側$t$、まさにあります$t-1$隣接ペアなので、ペアの合計数は次のようになります。$n - c$。 
3. 制約は「正確に」$k$ペアズ」となります。$c = n - k$。 これにより、計数の問題全体が、正確な構成を計数することに軽減されます。$c$鎖。 
4. 分割方法を数えてみます$n$ラベル付きルーク$c$鎖。 各チェーンは行制約と列制約を交互に行いますが、重要な単純化は、各チェーンを行セグメントと列セグメントの交互シーケンスとして表すことができ、これらの選択はサイズの畳み込みまで独立していることです。 
5. 係数が特定のサイズのチェーンを形成する方法の数を表す生成関数を導入します。 行の寄与と列の寄与は 2 つの独立したシーケンスになり、それらを結合するには、合計サイズのすべての分割を合計する必要があります。$n$。 これはまさに 2 つのシーケンスの畳み込みです。 
6. 行構造 DP と列構造 DP を計算し、それぞれインデックスが次の配列を生成します。$i$構造を形成する方法を数えます$i$セグメント。 次に、畳み込みを実行してそれらを結合し、に対応する係数を抽出します。$c$。 
7. 最後に、階乗正規化を適用して、ルークのラベル付けとセグメント内の順列を考慮します。 

### なぜ効果があるのか

 不変条件は、すべての有効な構成が交互の行チェーンと列チェーンのセットに一意に分解され、各隣接ペアが正確に 1 つのチェーンの内部エッジに対応することです。 これは、構成をカウントすることを意味します。$k$隣接ペアは、分解をカウントすることと同じです。$n-k$鎖。 チェーンは合計サイズを除いて相互作用しないため、生成関数は乗算され、畳み込みは二重にカウントすることなくすべての分割を正しく集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    
    c = n - k
    if c <= 0:
        print(0)
        return

    # factorials for combinatorics
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    
    invfact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def ncr(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    # dp_row[i] = ways to form i segments in rows
    dp_row = [0] * (n + 1)
    dp_row[0] = 1

    for i in range(1, n + 1):
        ndp = [0] * (n + 1)
        for j in range(n + 1):
            if dp_row[j]:
                for add in range(1, n - j + 1):
                    ndp[j + add] = (ndp[j + add] + dp_row[j] * ncr(n, add)) % MOD
        dp_row = ndp

    # symmetric for columns
    dp_col = dp_row[:]

    # convolution
    ans = 0
    for i in range(c + 1):
        ans = (ans + dp_row[i] * dp_col[c - i]) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```階乗事前計算は、ルークをセグメントに分割する際に使用される二項係数をサポートします。 動的プログラミング配列は、セグメント数の分布を表します。 最後のループは、必要な数のチェーンの可能な分割に対して畳み込みを実行します。$c$。 

重要な点は、チェーンの数がルークの配置から直接ではなく、隣接ペアから導出されるということです。 削減$c = n - k$これにより、最終的なカウントが扱いやすくなります。

 ## 特殊なケース

 のために$n = 1$の場合、グリッドには単一のセルが含まれており、隣接ペアは存在しません。 この条件により、唯一の有効な構成が強制され、チェーンの分解は単一の自明なコンポーネントに崩壊します。 アルゴリズムは正しく処理します$c = 1 - 0 = 1$、正確に 1 つの構造が得られます。 

のために$k = 0$、すべてのルークは隣接性の観点から分離する必要があります。つまり、すべてのルークが独自のチェーンを形成します。 これは以下に対応します$c = n$、そして畳み込みは完全に独立したシングルトン構造を選択するように退化します。 DP は、完全に切断された構成のみを正しくカウントします。 

のために$k = \frac{n(n-1)}{2}$、すべてのルークは最大の隣接関係を形成する必要がありますが、単一のチェーンであるため、チェーンの解釈の下ではこれは不可能です。$n$ルークのみが貢献する$n-1$ペア。 アルゴリズムが強制するのは、$c < 0$または、矛盾した状態がゼロとなり、組み合わせ不可能性と一致します。
