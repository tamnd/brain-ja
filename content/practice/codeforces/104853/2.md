 ## 解決策
 ## 問題の理解

 それぞれが 0 から 9 までの数字のみで構成される文字列のコレクションが与えられます。インデックスの順序付きペアの場合$(i, j)$と$i < j$、2つの文字列を連結します$s_i$そして$s_j$。 タスクは、そのような連結によって減少しない数字シーケンスが生成される回数を数えることです。つまり、すべての数字が次の数字以下であることを意味します。 

キーオブジェクトは連結された文字列です$s_i + s_j$。 この条件では、各文字列を個別に並べ替える必要はありません。 代わりに、次の境界が存在するかどうかを尋ねます。$s_i$そして$s_j$、および両方の内部構造により、マージされた文字列全体にわたって単調性が維持されます。 

制約は大きく、最大 100,000 個の文字列と合計の長さ 100,000 です。 これにより、すべてのペアを直接チェックすることが直ちに除外されます。$O(n^2)$、これは実現不可能です。 単純に連結の有効性をチェックする場合でも、文字列を繰り返しスキャンする必要があり、時間がかかりすぎます。 

微妙な問題が連結境界に現れます。 たとえ両方とも$s_i$そして$s_j$個別に非減少であるため、最後の桁が一致しない場合、それらの連結は失敗する可能性があります。$s_i$の最初の桁より大きいです$s_j$。 逆に、1 つの文字列が内部的にソートされていない場合でも、制約のあるペアリングでは機能する可能性がありますが、内部構造が大幅に減少することがわかります。 

小さな失敗例:

 入力:```
2
21
123
```ペアのみです$(1,2)$。 連結とは、`21123`、境界では 2 > 1 であるため、非減少ではありません。 したがって、答えは 0 です。 

単純に最後から最初の互換性だけをチェックしたとしても、次のような内部違反を見逃してしまいます。`132`単一の文字列内にありますが、それらはその文字列を含む連結をすでに無効にしているため、構造が重要です。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアに対して反復処理が行われます。$(i, j)$、文字列を連結し、結果の文字列が減少していないかどうかを確認します。 全長が$m$、その後、各小切手にコストがかかります$O(|s_i| + |s_j|)$、そして、あります$O(n^2)$ペア。 これは最悪の事態につながります$O(n^2 \cdot \text{avg length})$、これは完全に不可能です$n = 10^5$。 

重要な観察は、非減少であるという条件が連結境界において非常に厳格であるということです。 2 つの文字列を修正すると、境界を越える可能性のある唯一の違反は、最初の文字列の最後の桁が 2 番目の文字列の最初の桁より大きいかどうかです。 ただし、これは両方の文字列自体が内部的に非減少である場合にのみ意味があります。 そうしないと、内部違反によりすでに失格となります。 

したがって、すべての有効な文字列は、まず内部的に非減少でなければなりません。 隣接するペアが減少する文字列は、有効な連結の一部になることはできません。これは、その違反が最終連結に変更されずに残るためです。 

これで、各文字列は最初の桁と最後の桁の 2 つの値だけで要約できるようになりました。 この削減が機能するのは、各文字列内では桁が減らないため、互換性の目的で構造全体がエンドポイントで決定されるためです。 

文字列を最初の桁で分類するようになりました。$f$そして最後の数字$l$。 ペア用$(i, j)$、連結は次の場合にのみ有効です。 

1.$s_i$内部的には減少していません
 2.$s_j$内部的には減少していません
 3.$l_i \le f_j$これにより、単純な順序制約を使用して、問題が小さなアルファベット (数字 0 ～ 9) のペアを数えるという問題に軽減されます。 

各ペアを持つ有効な文字列の数を事前に計算します。$(f, l)$。 次に、カテゴリのすべてのペアを集計します。 桁が小さいため、最初の桁または最後の桁のプレフィックスの合計を効率的に計算し、互換性のあるペアをカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

| Optimized classification | $O(n + 100)$|$O(100)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各文字列について、左から右に減少していないかどうかを確認します。 そうでない場合は、破棄してください。 これが必要なのは、内部で減少するとすべての連結が無効になるためです。 
2. 有効な文字列ごとに、その最初の数字を抽出します。$f$そして最後の数字$l$、頻度テーブルをインクリメントします`cnt[f][l]`。 
3. 最初の数字の上に、考えられる最後の数字ごとにプレフィックス構造を構築します。$l$、最初の桁が指定されたしきい値以上または最大でもいくつの文字列に高速にアクセスしたいと考えています。 代わりに、最初の桁の集計カウントを準備します。 
4. 数字カテゴリのすべてのペアを反復処理します。$(f_i, l_i)$そして$(f_j, l_j)$。 各ペアについて、$l_i \le f_j$の場合、これらのグループ間のすべての組み合わせが寄与します。$cnt[f_i][l_i] \cdot cnt[f_j][l_j]$。 
5. すべての有効な寄与を合計します。以下の組み合わせに注意してください。$i = j$グループ間の乗算とその順序付けを通じてのみ正しく処理されます。$i < j$順序付けされたペアではなく組み合わせをカウントすることによって強制されます。 

正確さは、内部の単調性が保証された後に各文字列を安定した境界署名に還元するかどうかにかかっています。 

### なぜ効果があるのか

 文字列が内部的に非減少になると、その内部数字間のすべての比較は文字列間の有効性とは無関係になります。 連結で考えられる唯一の障害点は、2 つの文字列間の単一の境界です。 各文字列内では桁が減らないため、境界条件は$l_i \le f_j$必要かつ十分です。 これにより、問題は、エンドポイントによってのみ定義された部分的に順序付けされたセット内の互換性のあるペアをカウントすることに変わります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_good(s):
    for i in range(1, len(s)):
        if s[i] < s[i - 1]:
            return False
    return True

def main():
    n = int(input())
    
    cnt = [[0] * 10 for _ in range(10)]
    valid = []

    for _ in range(n):
        s = input().strip()
        if is_good(s):
            f = int(s[0])
            l = int(s[-1])
            cnt[f][l] += 1
            valid.append((f, l))

    # prefix sums over first digit
    pref = [[0] * 10 for _ in range(11)]
    for f in range(10):
        for l in range(10):
            pref[f + 1][l] = pref[f][l] + cnt[f][l]

    ans = 0

    # count ordered pairs i < j via aggregation
    for f1 in range(10):
        for l1 in range(10):
            c1 = cnt[f1][l1]
            if c1 == 0:
                continue
            for f2 in range(10):
                for l2 in range(10):
                    c2 = cnt[f2][l2]
                    if c2 == 0:
                        continue
                    if l1 <= f2:
                        if (f1, l1) == (f2, l2):
                            ans += c1 * (c1 - 1) // 2
                        else:
                            ans += c1 * c2

    print(ans)

if __name__ == "__main__":
    main()
```このソリューションでは、まず内部で単調性に違反するすべての文字列をフィルターで除外します。 そうしないとエンドポイント圧縮が無効になるため、この手順は必須です。 残りの各文字列は、他の文字列との相互作用を表す 1 対の数字に変換されます。 

アルファベットのサイズは 10 のみなので、合計 100 の状態になるため、数字のペアに対する二重ループは安全です。 唯一の微妙な点は、セルフペアを正しく処理することです。両方の文字列が同じバケットからのものである場合、組み合わせをカウントする必要があります。$c(c-1)/2$の代わりに$c^2$、インデックスは次の条件を満たす必要があるため、$i < j$。

 ## 特殊なケース

 重大なエッジケースは、同一の文字列が多数存在する場合です。 たとえば、すべての文字列が`111`、すべてのペアが有効です。 アルゴリズムはそれらを 1 つのバケット (1,1) にグループ化し、正しくカウントします。$c(c-1)/2$、ペアの数に一致します。 

もう 1 つのエッジ ケースは、内部的には無効であるが、エンドポイントによって互換性があるように見える文字列です。 例えば、`132`そして`123`。 どちらもエンドポイントを共有しているため、互換性があることが示唆されますが、`132`内部の単調性に違反するため、早期に破棄されます。 これにより、エンドポイントのみのロジックによって発生する誤ったカウントが防止されます。
