 ## 解決策
 ## 問題の理解

 私たちにはいくつかの石の山が与えられました。 各山には、そこから取り出せる石の数の固定された許容範囲があります。 山から$i$、整数を選択する必要があります$x_i$そのような$l_i \le x_i \le r_i$。 すべての山から選択した後、選択したすべての値の合計は正確に一致する必要があります。$s$。 

ここで注意すべき点は、有効な選択のグローバルな数を 1 つも要求されないことです。 代わりに、各山ごとに$i$、値の数を知りたいです$x$許容範囲内であれば「安全」です。つまり、修正すれば$x_i = x$、その後、合計が正確になるように他のすべての山の値を選択することは可能です。$s$。 

したがって、すべてのパイルについて、そのローカルな選択肢の数が少なくとも 1 つのグローバルな補完と互換性があるかどうかを効率的に数えています。 

この制約により、すべての組み合わせを列挙しようとするアプローチは直ちに除外されます。 と$n$まで$10^5$までの範囲$10^9$、考えられるすべての合計を保存することすら不可能です。 合計額$s$と同じ大きさにすることができます$10^{18}$したがって、合計によってインデックス付けされた DP も不可能です。 

素朴な考えは次のようになります: 各山と各候補値について$x$、残りの山が合計を形成できるかどうかを確認します$s-x$。 しかし、これは同じ実現可能性チェックを繰り返すことになります$O(n \cdot m)$が遅すぎます。 

微妙なエッジケースは、たとえば山の範囲が非常に狭い場合に現れます。$l_i = r_i$。 その場合、その固定値は、残りが必要な残差和を形成できるかどうかに応じて、常に有効であるか、まったく無効になりません。 不用意な解決策は杭間の独立性を誤って仮定する可能性がありますが、実現可能性はグローバルです。 

## アプローチ

 重要な観察は、問題は実際には独立した区間にわたる合計の実現可能性に関するものであるということです。 各パイルは間隔からの選択に貢献します$[l_i, r_i]$。 割り当てはカウントしていません。 部分的な割り当てを延長できるかどうかをテストしています。 

根本的に何が起こっているのかを定義しましょう。 パイルを取り除くと$i$、残りの山は一定の間隔で任意の合計を形成できます$[L_i, R_i]$、 どこ：$$L_i = \sum_{j \ne i} l_j, \quad R_i = \sum_{j \ne i} r_j$$これは、各パイルがその最小値と最大値の間で独立して寄与するため、合計範囲は加算されるためです。 

今パイルを修正します$i$そして、値を選択するとします$x$。 残りの山は合計を形成する必要があります$s - x$。 これは次の場合にのみ可能です。$$L_i \le s - x \le R_i$$並べ替え:$$s - R_i \le x \le s - L_i$$それでパイルについては$i$、の有効な値$x$は、まさに 2 つの区間の交点です。$$[l_i, r_i] \cap [s - R_i, s - L_i]$$これにより、グローバル合計を事前に計算した後、各クエリが区間交差に縮小されます。 

唯一高価な部分はコンピューティングです$L_i, R_i$あらゆる人にとって$i$。 これは合計を使用して行うことができます。$$\text{sumL} = \sum l_i, \quad \text{sumR} = \sum r_i$$それから：$$L_i = \text{sumL} - l_i, \quad R_i = \text{sumR} - r_i$$それぞれの答えは単純な算術積集合になります。$O(1)$。

 ## アルゴリズムのチュートリアル

 1. 2 つのグローバル合計を計算します: 最小合計合計`sumL`と合計最大額`sumR`。 これにより、すべての杭が空いている場合に達成可能な範囲全体がキャプチャされます。 これが機能する理由は、杭の寄与が独立しており、加算されるためです。 
2. 山ごとに$i$、その寄与を差し引いて、残りの杭の達成可能な範囲を計算します。$L_i = sumL - l_i$、$R_i = sumR - r_i$。 

このステップではパイルを分離します$i$そして残りを単一の間隔システムとして扱います。 
3. 要件「残杭合計」を換算します。$s - x$” を制約に組み込む$x$:$s - R_i \le x \le s - L_i$。 

これは、実現可能性を定義する不等式を逆転させることから生まれます。 
4. この導出した区間をローカル制約と交差させます。$[l_i, r_i]$。 有効な値は、$x$は：$$[\max(l_i, s - R_i), \min(r_i, s - L_i)]$$5. パイルの答え$i$この交差が空でない場合はそのサイズ、それ以外の場合はゼロです。 

### なぜ効果があるのか

 建設全体は、残りの部分が$n-1$パイルは隙間のない連続した合計間隔を形成します。 各パイルは固定範囲内で独立して寄与するため、すべての組み合わせは最小合計と最大合計の間の全範囲を満たします。 これにより、実現可能性は範囲内の離散構造ではなく、区間の重なりのみに依存することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())
    l = [0] * n
    r = [0] * n

    sumL = 0
    sumR = 0

    for i in range(n):
        l[i], r[i] = map(int, input().split())
        sumL += l[i]
        sumR += r[i]

    out = []

    for i in range(n):
        L = sumL - l[i]
        R = sumR - r[i]

        low = max(l[i], s - R)
        high = min(r[i], s - L)

        if high < low:
            out.append("0")
        else:
            out.append(str(high - low + 1))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```この実装は、事前に計算された合計に完全に依存しています。 重要な詳細は、残りの範囲を計算するときに現在のパイルの寄与を正しく差し引くことです。 よくある間違いは、下限と上限の両方の合計が一貫して同じ山を除外する必要があることを忘れていることです。 

通常、交差ステップでは、off-by-one エラーが発生します。 式`high - low + 1`包含区間内の整数点を正しくカウントします。

| ステップ | 値 |

 | ステップ | 値 |

 ## 特殊なケース

 微妙なケースとしては、交差後に実行可能区間が空になる場合があります。 たとえば、グローバル要件により杭の許容範囲外の値が強制される場合です。 

入力：```
2 10
0 3
0 3
```ここで:

 sumL = 0、sumR = 6。どちらの山でも、必要な寄与間隔は [7,10] になり、[0,3] と交差しないため、両方の答えはゼロになります。 アルゴリズムはこれを正しく検出します。`high < low`。 

もう 1 つのケースは、実行可能な間隔に杭の範囲が完全に含まれている場合です。 したがって、すべての値は有効であり、答えは単純です。`r_i - l_i + 1`、これは特別な場合を必要とせずに自然に交差式から外れます。
