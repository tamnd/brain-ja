## Problem Understanding

We start with two very large integers, call them $a$そして$b$。 出演させていただくのはせいぜい$k$操作。各操作は独立して次のいずれかを増加します。$a$1つずつ、または$b$1つずつ。 以下の金額を費やした後、$k$合計が増加したら、立ち止まって、結果として得られる数値のペアを確認します。 目標は、2 つの数値の最終積ができるだけ大きくなるように、これらの増分を分配する方法を選択することです。 

出力は製品そのものではなく、最終的な値です$c$そして$d$、更新されたものに対応$a$そして$b$、使用されるインクリメントの合計数が最大で次であるという制約があります。$k$。 

制約は次のとおりです$10^{18}$これにより、シミュレーションや段階的な割り当てが即座に排除されます。 どのソリューションも、テスト ケースごとに一定時間または対数時間で機能する必要があります。 これは、目的関数の構造が単純で滑らかであるため、離散探索ではなく分析的に最適化できることも示唆しています。 

単純な試みでは、増分を 1 つずつ割り当て、積がより多くなる側に常に次の増分を与えようとします。 これは、ステップごとに限界ゲインが変化するため、微妙な方法で失敗します。そのため、局所的に最適な選択が全体的な最適値から逸脱する可能性があります。 

たとえば、次のように仮定します。$a = 1$、$b = 100$、$k = 2$。 貪欲な戦略はすぐに増加する可能性があります$a$バランスは改善されますが、正確な順序によっては、別の方法で割り当てるよりも悪い結果になる可能性があるためです。 重要な問題は、その決定は目先の利益だけではなく、将来の分配に依存するということです。 

別の失敗例が現れるのは、$k = 0$。 少なくとも 1 つの移動を想定するアルゴリズム、または分割によって正規化するアルゴリズム$k$明示的にゼロ増分を許可し、元のペアを返さない限り、壊れます。 

## アプローチ

 ブルートフォース手法では、配布するすべての方法が列挙されます。$k$2 つの変数間の増分。 割り当てれば$x$に増分します$a$、 それから$k-x$に行く$b$、すべてを評価します$k+1$ possibilities. This is correct because every valid sequence of operations corresponds exactly to one such split. However, this approach is linear in $k$までです$10^{18}$、完全に実行不可能になります。 

最終的な値を次のように書き直すと、問題の構造がより明確になります。$c = a + x$そして$d = b + (k - x)$。 目的は単一変数関数を最大化することになります。$$f(x) = (a + x)(b + k - x)$$これを展開すると、次の二次関数がわかります。$x$、具体的には凹型放物線です。 凹面は、最大値が任意の点ではなく頂点付近で達成されることを意味します。 これにより、問題は、巨大な離散空間にわたる検索から、頂点の周囲の一定数の候補のみを評価することに変換されます。 

放物線の頂点は実数値の最適値を与え、整数の最適値はその頂点に非常に近くなければなりません。 したがって、最良の整数解を保証するには、頂点の周囲の小さな近傍をチェックするだけで十分です。

 ## アルゴリズムのチュートリアル

 問題は増分の数を選択することになります。$x$に行く$a$、残りの$k-x$に適用される$b$。 

1. 最終状態を次のように解釈します。$c = a + x$そして$d = b + k - x$、 どこ$x$からの範囲$0$に$k$。 この再パラメータ化により、すべての有効な操作シーケンスがキャプチャされます。 
2. 目的関数を定義する$f(x) = (a + x)(b + k - x)$。 これにより、2 次元の決定が単一変数の最適化問題に変わります。 
3. 式を展開してその構造を確認します。$$f(x) = -x^2 + x(a - b - k) + a(b + k)$$の負の係数$x^2$は、関数が凹面であることを示しています。これは、実数直線上にグローバル最大値が 1 つだけ存在することを意味します。 
4. 放物線の実数値の頂点を計算します。$$x^* = \frac{(b + k) - a}{2}$$これは、どちらかの側の増加による限界利益が釣り合う点です。 
5.以来$x$整数であり、その範囲内にある必要があります$[0, k]$、頂点の周囲の候補値に注意を限定します。 唯一意味のある候補は、$x = \lfloor x^* \rfloor$そして$x = \lceil x^* \rceil$有効範囲にクランプした後。 
6. 両方の候補について製品を評価し、より大きな値を生成する方を選択します。 
7. 対応する出力$c = a + x$そして$d = b + (k - x)$。 

### なぜ効果があるのか

 機能$f(x)$は連続領域上の凹二次方程式であるため、極大値も大域的になります。 整数に制限する場合、最適値は実際の頂点に最も近い整数になければなりません。 凹二次関数は単調方向を 1 回だけ変更するため、頂点近傍からより良い解を隠す可能性のある二次ピークはありません。 これにより、最適な分割を見つけるには最大 2 つの整数をチェックするだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = int(input().strip())
    b = int(input().strip())
    k = int(input().strip())

    def value(x):
        return (a + x) * (b + (k - x))

    # vertex of concave quadratic
    # x* = ( (b+k) - a ) / 2
    x_star = ((b + k) - a) / 2

    candidates = set()

    for x in [int(x_star), int(x_star) + 1]:
        if 0 <= x <= k:
            candidates.add(x)

    # also clamp boundaries (important for extreme cases)
    candidates.add(0)
    candidates.add(k)

    best_x = 0
    best_val = -1

    for x in candidates:
        v = value(x)
        if v > best_val:
            best_val = v
            best_x = x

    c = a + best_x
    d = b + (k - best_x)
    print(c, d)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず 3 つの整数を読み取ります。 次に、決定を選択として再構成します。$x$、に割り当てられた増分数$a$。 ヘルパー関数は、指定された分割に対して結果の積を直接計算します。 

中心となるアイデアは、閉じた形式の式を使用した放物線の頂点の計算です。 浮動小数点の丸めでは境界ケースを見逃す可能性があるため、実装では頂点の床と天井の両方をチェックし、さらに端点も含めます。$0$そして$k$これは、頂点が有効な間隔の外側にあるすべての縮退ケースを安全にカバーします。 

最後に、最適な分割が必要な出力値に変換されます。

 ## 特殊なケース

 いつ$k = 0$、候補セットには依然として次のものが含まれている必要があります。$x = 0$。 アルゴリズムは両方の境界を明示的に挿入するため、すぐに戻ります。$(a, b)$頂点計算に依存せずに。 

頂点が外側にある場合$[0, k]$、たとえば次のようなとき$a$よりもはるかに大きいです$b + k$、計算された$x^*$マイナスになる。 このような場合には、どちらも$int(x^*)$そして$int(x^*) + 1$有効性チェックでは無視され、境界候補のみが残ります。 したがって、アルゴリズムはすべての演算を小さい側に正しくシフトします。 

値が非常に大きい場合、中間積は Python 整数に収まるため、オーバーフローは心配ありません。 固定幅言語では、安全のために 64 ビット乗算が必要ですが、ロジックは変わりません。
