 ## 解決策
 ## 問題の理解

 私たちに与えられた通りは、$2n$連続した家。各家は、その間に特定のサイズのケーキ段を 1 つだけ販売します。$1$そして$n$。 どのサイズも正確に 2 回表示されます。 

二人は家からスタート$1$。 それぞれが独立して、複数の層からなる完全なケーキを作りたいと考えています$1$を通して$n$、サイズの小さい順に層を購入する必要があります。 各層は特定の家から選択する必要があるため、通りに沿って物理的に歩いて必要な家を順番に収集します。 

タスクは、各サイズの 2 つの利用可能な出来事を 2 人の間でどのように割り当てるか、また、2 人の合計歩行距離が最小になるように、それらを訪問する順序を決定することです。 

主要な出力は、両方の個人が歩いた距離の最小合計です。 

制約$n \le 10^5$入力サイズが最大であることを意味します$2 \cdot 10^5$。 二次関数の動作を伴う任意の解でも、$O(n^2)$、それは最大の作業を伴うため、遅すぎます。$10^{10}$操作。 通常、線形または線形に近い戦略が必要です。$O(n \log n)$または$O(n)$。 

各値の最も近い値を個別に割り当てようとすると、微妙な落とし穴が発生します。 これは失敗します。以前の層を選択すると将来の可用性が制限され、バックトラッキング距離が大きくなる可能性があるためです。 

たとえば、最も近いサイズを取得する状況を考えてみましょう。$1$両方のサイズの優れたオプションをブロックします$2$、長い後進移動を強いられます。 単純に貪欲なアプローチでは、そのようなやり取りは予測できません。 

## アプローチ

 ブルートフォース戦略では、あらゆるサイズの 2 つの出現のそれぞれをサーシャまたはディマのいずれかに割り当てるすべての可能な方法をシミュレートし、同時に両方の移動順序も決定します。 これは基本的に、各サイズでの分岐プロセスを調査します。$i$、その 2 つのポジションのどちらがどの人に割り当てられるかを選択します。 各サイズには 2 つの選択肢があり、$n$サイズ、あります$2^n$割り当てを行い、それぞれの割り当てについても歩行コストをシミュレーションします。 枝刈りを行ったとしても、これは指数関数的であり、小規模を超えると不可能になります$n$。 

重要な構造的洞察は、移動はライン上の位置のみに依存し、次に必要な層は常に前の層よりも大きいということです。 これは、各人のパスはサイズのシーケンスでは単調ですが、位置では必ずしも単調ではないことを意味します。 

サイズを割り当てる代わりに、位置の配列を 2 つの増加するインデックスのサブシーケンス (各人に 1 つずつ) に分割するという観点から考えることができます。 各人は、サイズの大きい順に自分に割り当てられたポジションを訪問します。コストは、ポジションから開始して、連続して訪問したインデックス間の絶対差の単純な合計です。$1$。 

ここで重要な簡略化: サイズごとに$i$、ちょうど 2 つのポジションがあります$p_i$そして$q_i$。 そのうちの1つはサーシャに、もう1つはディマに送られます。 総移動距離が最小になるように割り当てを決めたいと思います。 

重要な観察は、サイズごとに、2 人のうち 1 人がその値の推移を「吸収」し、各人が最後に訪問した位置を維持すれば、コストの寄与を増分的に計算できるということです。 

これは貪欲な動的プロセスにつながります。つまり、サイズを次から処理します。$1$に$n$そしてサイズごとに、現在のポジションに追加される当面の移動コストを最小限に抑える方法で、どの人物がどのオカレンスを取るかを決定します。 各ステップは両方の人の最後の位置にのみ依存するため、ローカルの貪欲な選択で十分です。 

当社は常に、2 つの利用可能なポジションのうち近い方を、移動コストがより小さい人に割り当て、それに応じて現在のポジションを更新します。

 ## アルゴリズムのチュートリアル

 まず各層サイズの位置を前処理して、各値が現れる 2 つのインデックスを把握します。 

1. 値ごとに保存する$i$配列内の 2 つの位置。 これにより、候補の動きに常時アクセスできるようになります。 
2. サーシャとディマの現在の位置を表す 2 つのポインターを維持します。 どちらもインデックスから始まります$1$、最初の家から始まるので。 
3. からの値を処理します。$1$に$n$両方の担当者がサイズの増加する階層を収集する必要があるため、将来の決定が過去の可用性に影響を与える可能性がないため、昇順で行われます。 
4. 各値について$i$、2つのポジションがあります。 1 つのポジションをサーシャに割り当て、もう 1 つのポジションをディマに割り当てるコストを、考えられる両方の方法で検討します。 

最初のペアリング$(p_i \to S, q_i \to D)$、2番目のペアリング$(p_i \to D, q_i \to S)$。 
5. 両方の人の現在の位置を使用して、各ペアの増分コストを計算します。 総移動コストが小さい割り当てを選択してください。 
6. 選択した割り当てを反映するために両方の現在のポジションを更新し、コストを追加します。 

両方の割り当てを評価する理由は、決定が個人ごとにローカルではなく共同で行われるためです。エンドポイントを交換すると、将来の移動が大幅に削減される可能性があります。 

### なぜ効果があるのか

 どの段階でも、両方の人々が「最後に訪問した位置」を固定しており、将来の移動はこれら 2 つの状態にのみ依存します。 各値は各人が一度だけ収集する必要があるため、自由度は 2 つの発生をどのように分割するかだけです。 

このアルゴリズムは、すべての層で当面の移動コストの合計を最小化する分割を選択し、結果として得られるポジションを超えて、「どの人がどの特定の出来事を取得したか」に将来の層が依存しないため、最適です。 したがって、システムには最適な下部構造があり、各層で最適なローカル ペアリングを決定することによって、最適なグローバル割り当てを構築できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    pos = [[] for _ in range(n + 1)]
    for i, v in enumerate(arr, 1):
        pos[v].append(i)

    # starting positions
    s = 1
    d = 1
    ans = 0

    for i in range(1, n + 1):
        a, b = pos[i]

        # option 1: a->S, b->D
        cost1 = abs(s - a) + abs(d - b)

        # option 2: a->D, b->S
        cost2 = abs(s - b) + abs(d - a)

        if cost1 <= cost2:
            ans += cost1
            s, d = a, b
        else:
            ans += cost2
            s, d = b, a

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、各値に一定時間でアクセスできるように、各層の位置をグループ化することから始まります。 変数`s`そして`d`は、それぞれサーシャとディマの最後に訪問した家のインデックスを表します。 各層で、その 2 つの出現の両方の可能な割り当てを評価し、現在の位置から移動コストを計算します。 スワップの決定により、両方のエンドポイントが常に安価な構成で割り当てられるようになります。 

微妙な点は、決定のたびに両方のポジションを同時に更新することです。 将来の動きは両方の州に共同で依存するため、これは不可欠です。 1 つだけを更新すると、正確さが失われます。

 ## 特殊なケース

 重要なエッジ ケースは、値の両方の出現が隣接している場合です。 たとえば、値の場合$i$、ポジション$(k, k+1)$、間違った割り当てを選択すると、当面は同様のコストがかかりますが、将来の到達可能性に影響する可能性があります。 両方のペアリング オプションが対称的に評価され、現在の状態が常に一貫して更新されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つの重要なケースは、次のような発生が最大限に離れている場合です。$1$そして$2n$。 ここで、貪欲な割り当ては直観に反しているように見えるかもしれませんが、両者は常に値の順序で前進するため、エンドポイントを貪欲に割り当てても最適な分割が生成されます。 状態の更新により、ロングジャンプが即座に考慮され、後で隠れたコストが蓄積されるのを防ぎます。
