 ## 解決策
 ## 問題の理解

 正の数、負の数、そして場合によってはゼロを含む配列が与えられます。 ゼロ以外の整数を選択する必要があります$d$すべての要素を次のように分割した後、$d$、配列要素の少なくとも半分は正です。 より正確には、除算後の正の値の数は少なくとも$\lceil n/2 \rceil$。 

除算後の実際の大きさは関係ありません。 記号だけが重要です。 次のような値$2.5$まだポジティブですが、$0$プラスにもマイナスにもなりません。 

制約は非常に小さいです。 配列には最大 100 個の要素が含まれており、すべての値は要素間にあります。$-1000$そして$1000$。 数値が 100 個しかないため、配列を総当たり的に検査することさえ簡単です。 

重要な観察は、割り算が記号にどのように影響するかに由来します。 正の数で割ると、すべての符号は変更されません。 負の数で除算すると、すべての正の数が負の数に反転され、すべての負の数が正の数に反転されます。 どちらの場合でもゼロはゼロのままです。 

いくつかの特殊なケースでは、簡単に間違いが発生する可能性があります。 

考慮する：```
3
0 0 5
```正の数で割った場合、配列の符号は残ります。$(0,0,+)$したがって、正の値は 1 つだけです。 以来$\lceil 3/2 \rceil = 2$、これでは不十分です。 ゼロを無視する不用意な解決策は、正の値が多数派であると誤って結論付ける可能性があります。 

考慮する：```
5
-1 -2 -3 0 0
```負の除数を使用すると、3 つの負が正に反転され、3 つの正の値が得られます。 正しい答えは、$-1$。 正の約数のみをチェックするソリューションでは、誤って 0 が出力されます。 

次のことを考慮してください。```
4
1 -1 0 0
```ポジティブなものとネガティブなものが 1 つあります。 正の約数は 1 つの正の数を生成します。 負の約数も 1 つの正の数を生成します。 少なくとも 2 つの正の値が必要なので、正解は 0 です。 

除数に関係なくゼロは決して正にはならないため、多くのゼロが存在することが主な微妙な点です。 

## アプローチ

 ブルートフォースアプローチでは、有効な約数をすべて試します。$-1000$に$1000$、ゼロを除きます。 各約数について、すべての配列要素を分割し、正の結果がいくつあるかを数えます。 

検索スペースが小さいため、これが機能します。 可能な約数は 2000 個のみで、配列要素は最大 100 個です。 最悪の場合の仕事は、$2000 \times 100 = 200{,}000$制限内に簡単に収まる操作。 

興味深いのは、除数の正確な値が無関係であることに注目することです。 その符号のみが重要です。 

もし$d > 0$、すべてのプラスの要素はプラスのままであり、すべてのマイナスの要素はマイナスのままです。 

もし$d < 0$、すべてのポジティブな要素はネガティブになり、すべてのネガティブな要素はポジティブになります。 

つまり、確認すべき状況は次の 2 つだけです。 

まず、正の除数を使用します。 正の値の数は、元の配列内の正の要素の数と等しくなります。 

2 番目に、負の除数を使用します。 正の値の数は、元の配列内の負の要素の数と等しくなります。 

させて：

-$pos$正の要素の数になります。 
-$neg$負の要素の数になります。 
-$need = \lceil n/2 \rceil$。 

もし$pos \ge need$、たとえば 1 など、任意の正の約数を出力できます。 

それ以外の場合は、$neg \ge need$、-1 などの負の除数を出力できます。 

それ以外の場合は、どちらの符号を選択しても十分な正の値を生成できないため、0 を出力します。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、正の要素の数を数えます。 このカウントを次の場所に保存します`pos`。 
2. 負の要素の数を数えます。 このカウントを次の場所に保存します`neg`。 
3. 必要な正の値の数を計算します。$$need = \left\lceil \frac{n}{2} \right\rceil$$整数演算ではこれは`(n + 1) // 2`。 
4. もし`pos >= need`、印刷`1`。 

正の除数はすべての符号を保持するため、除算後の正の値の数は正確に次のようになります。`pos`。 
5. それ以外の場合、`neg >= need`、印刷`-1`。 

負の約数は符号を反転するため、すべての負の要素が正になります。 正の値の数は正確になります`neg`。 
6. それ以外の場合は印刷します`0`。 

どちらの符号を選択​​しても、十分な正の値を生成できません。 

### なぜ効果があるのか

 ゼロ以外のすべての商の符号は、被除数の符号と除数の符号にのみ依存します。 除数の大きさは、結果が正であるかどうかには影響しません。 

正の除数を使用すると、元の符号分布が保存され、正確に生成されます。`pos`正の値。 負の除数を使用すると、正と負のカウントが交換され、正確に生成されます。`neg`正の値。 考えられる結果はこれら 2 つだけであるため、どちらかのカウントが以下に達するかどうかを確認します。$\lceil n/2 \rceil$すべての有効な回答を完全に特徴づけます。 どちらのカウントも十分に大きくない場合、どの除数も要件を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

pos = sum(1 for x in a if x > 0)
neg = sum(1 for x in a if x < 0)

need = (n + 1) // 2

if pos >= need:
    print(1)
elif neg >= need:
    print(-1)
else:
    print(0)
```最初の部分では、正の要素と負の要素を別々にカウントします。 ゼロは、除算後の正の値の数に決して寄与しないため、無視されます。 

変数`need`店舗$\lceil n/2 \rceil$。 使用する`(n + 1) // 2`の偶数と奇数の両方の値を正しく処理します`n`。 

チェックの順序は、両方のカウントが要件を満たしている場合に、どの有効な回答を出力するかを選択する場合にのみ重要です。 この問題では有効な約数が許容されるため、次のように出力します。`1`最初は完全に許容されます。 

実際の除算は実行されません。 この解決策は、記号の動作に完全に依存しており、これが重要な簡素化です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = sum(1 for x in a if x > 0)
    neg = sum(1 for x in a if x < 0)

    need = (n + 1) // 2

    if pos >= need:
        print(1)
    elif neg >= need:
        print(-1)
    else:
        print(0)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    result = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# sample-style case
assert run("5\n10 0 -7 2 6\n") == "1"

# minimum size, positive
assert run("1\n5\n") == "1"

# minimum size, negative
assert run("1\n-5\n") == "-1"

# impossible because zeros dominate
assert run("4\n1 -1 0 0\n") == "0"

# all negatives
assert run("5\n-1 -2 -3 -4 -5\n") == "-1"

# all positives
assert run("6\n1 1 1 1 1 1\n") == "1"

# boundary count exactly equal to need
assert run("5\n1 2 3 0 -1\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 5`|`1`| 最小サイズの正の配列 |
 |`1 / -5`|`-1`| 最小サイズの負の配列 |
 |`4 / 1 -1 0 0`|`0`| 過半数を防ぐゼロ |
 |`5 / all negatives`|`-1`| 負の除数による符号反転 |
 |`6 / all positives`|`1`| 正の除数の場合 |
 |`5 / 1 2 3 0 -1`|`1`| 正確なしきい値の等しい |
