 ## 解決策
 ## 問題の理解

 一連の長方形の木製ブロックが与えられます。 i 番目のブロックは常に高さ 1 を持ち、その長さは ⌈i/2⌉ 規則に従って i とともにゆっくりと増加します。 したがって、ブロックは同じ幅のペアになります。インデックス 1 と 2 は両方とも幅 1、インデックス 3 と 4 は両方とも幅 2、インデックス 5 と 6 は両方とも幅 3 などとなります。 

これらのブロックのサブセットを選択して、回転せずに配置することができます。 各ブロックは、高さ 1 と固定幅の水平ストリップに寄与します。 目標は、これらのストリップを、可能な最大の整数 s でサイズ s × s の正方形に組み立てることです。 

主な制限は、ブロックを回転できないため、各ブロックは正確に 1 行 w 列の長方形となることです。 

入力サイズは大きく、n は最大 10^9 であり、最大 10^4 のテスト ケースがあります。 これにより、すべてのブロックを反復したり、構築をシミュレートしたりするアプローチは即座に除外されます。 すべての解決策は n のみに依存し、閉じた形式の推論を使用する必要があります。 

n が小さい場合、微妙なエッジケースが現れます。 n = 1 または n = 2 の場合、すべてのブロックの幅は 1 なので、1 × 1 の正方形のみが可能です。 幅の増加が 2 からすぐに始まると仮定する単純なアプローチでは、答えが誤って過大評価されてしまいます。 もう 1 つの落とし穴は、すべてのブロックを使用する必要があると想定しているにもかかわらず、実際には正方形パッキング制約に適合するサブセットのみを選択していることです。 

## アプローチ

 直接構築アプローチを試みる場合は、広場の列を構築することをシミュレートすることになります。 各行には幅 s が必要で、幅の合計が少なくとも s になる利用可能なブロックを貪欲に選択します。 候補ごとに、すべてのブロックをスキャンするか、複数セットの幅を維持する必要があります。 

単一の s をチェックするだけでも O(n) のコストがかかり、s はおよそ √n まで大きくなる可能性があるため、テスト ケースごとに約 O(n√n) かそれより悪い結果になり、10^9 までの n では不可能です。 

重要な観察は、ブロック幅が非常に構造化されていることです。 すべての整数幅 w は正確に 2 回出現し、すべての幅 ≤ k はブロックのプレフィックス内に正確に 2k 回出現します。 

したがって、個々のブロックの観点から考えるのではなく、幅によって集計します。 与えられた n に対して、全幅グループがいくつあるかを計算できます。 k = ⌊in/2⌋ の場合、1 から k までの幅が完全に含まれ、それぞれが 2 つのブロックに寄与します。 n が奇数の場合、幅 k+1 のブロックがさらに 1 つあります。 

これにより、問題は純粋な計数の問題に変換されます。各幅 w が最大 2 回 (おそらく最後の 1 つを部分的に除く) 出現するマルチセットを使用して、どのくらいの大きさの正方形を形成できるでしょうか?

 次の洞察は幾何学的なものです。辺 s の正方形を構築するには、合計の高さが少なくとも s であるストリップを選択する必要があります (最大でも s 行を選択できるため、常に true)。さらに重要なのは、各行を長さ s にパックする必要があることです。 これは、幅レベルごとに割り当てることができる水平方向の「ユニット高さストリップ」の合計数を確認することになります。 

これを確認するためのより簡単な方法は、視点を逆にすることです。正方形を組み立てる代わりに、s 行のそれぞれに少なくとも s の合計幅を割り当てることができるように、可能な最大の s を考慮します。 すべての行の要件が同一であるため、幅から得られる利用可能な「面積寄与率」の合計が s × s をサポートできるかどうかを実際に尋ねます。 

すべてのブロックが占める合計面積は次のとおりです。 

sum_{i=1..n} ⌈i/2⌉。 

この合計は、インデックスをペアにすることで閉じた形式で計算できます。 各 k について、おそらく最後の不完全なペアまで、合計 2k の領域に寄与する幅 k の 2 つのブロックが得られます。 

したがって:

 n = 2m の場合、総面積 = 2(1 + 2 + ... + m) = m(m+1)

 n = 2m + 1 の場合、総面積 = m(m+1) + (m+1) = (m+1)^2

 したがって、総面積は m(m+1) または (m+1)^2 になります。 面積に収まる最大の正方形 s × s が必要なので、s はおおよそ √(面積) であると考えられます。 ただし、構造上梱包が制限される可能性があるため、これだけでは十分ではありません。

重要な最終的な観察は、この構造が緊密であるということです。幅は減少しておらず、実行可能なパッキングは総面積のみに依存するほど十分にバランスが取れており、最適な正方形の辺は正確に次のようになります。 

s = ⌊√(最初の n 個の幅の合計)⌋。 

これを計算すると、問題全体がテスト ケースごとの定数時間の算術式に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース構築 | O(n√n) | O(n) | 遅すぎる |
 | 接頭辞の合計 + 平方根の式 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 最初の n ブロックが寄与する幅の合計を計算し、s² ≤ sum となる最大の整数 s を取得します。 

### ステップ

 1. m = n // 2 を計算して、n をインデックスのペアに分割します。 

これは、同じ幅を共有する各ペアのブロック (1,2)、(3,4)、... をグループ化します。 
2. 完全なペアからの合計寄与度を計算します: m(m+1)。 

各幅 k が 2 回出現するため、これは 2(1 + 2 + ... + m) から得られます。 
3. n が奇数の場合、幅 m+1 を持つ最後のブロックの寄与を加算します。 
4. total を計算された合計とします。 
5. 答えは、s² ≤ total となる最大の整数 s、つまり、floor(sqrt(total)) です。 

### なぜ効果があるのか

 構造は幅が単調です。つまり、大きな幅は小さな幅の後にのみ表示され、常に十分な多重度で表示されます。 これにより、領域は存在するが正方形に配置できない場合の病的なパッキング制限が回避されます。 すべての幅レベルが完全な 1-高さのストリップに寄与するため、制限要因は純粋に利用可能な合計領域となり、追加の組み合わせ制約が実現可能性を低下させることはありません。 したがって、最大正方形の辺は領域境界によって正確に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

t = int(input())
for _ in range(t):
    n = int(input())
    m = n // 2
    total = m * (m + 1)
    if n % 2 == 1:
        total += (m + 1)
    print(int(math.isqrt(total)))
```実装は派生した式に直接続きます。 整数の平方根は、浮動小数点の精度の問題を回避するために使用されます。 合計の計算は等差級数の公式を使用して O(1) で行われます。 

中間乗算 m(m+1) は大きくなる可能性があるため、ここでは Python の任意精度整数が適切であることに注意する必要があります。 

## 実用的な例

 ### 例 1: n = 5

 | ステップ | mの値 | ペアの貢献 | 追加ブロック | 合計 |
 | --- | --- | --- | --- | --- |
 | コンピューティング | 2 | 2(1+2)=6 | 幅3 | 9 |

 ここで、s = ⌊√9⌋ = 3 を計算します。 

これは、幅 1、1、2、2、3 のブロックが 3 × 3 の正方形を形成できる構造と一致します。 

### 例 2: n = 2

 | ステップ | mの値 | ペアの貢献 | 追加ブロック | 合計 |
 | --- | --- | --- | --- | --- |
 | コンピューティング | 1 | 2(1)=2 | なし | 2 |

 これで s = ⌊√2⌋ = 1 となります。 

利用可能な幅の合計が不十分であるため、2 × 2 の正方形を形成できないため、結果は 1 になります。 

これらの例は、正方形の辺が個々のブロックの配置ではなく、集約された幅の合計によって完全に支配されることを示しています。

## テストケース```python
import sys, io, math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        m = n // 2
        total = m * (m + 1)
        if n % 2 == 1:
            total += (m + 1)
        out.append(str(math.isqrt(total)))
    return "\n".join(out)

# provided samples
assert solve("3\n2\n5\n197654321\n") == "1\n3\n98827161"

# custom cases
assert solve("1\n1\n") == "1", "minimum n"
assert solve("1\n2\n") == "1", "small even case"
assert solve("1\n6\n") == str(math.isqrt(3*4)), "even structured case"
assert solve("1\n7\n") == str(math.isqrt(16)), "odd boundary case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n = 1 | 1 | 最小限のエッジケース |
 | n = 2 | 1 | 最小偶数の場合 |
 | n = 6 | sqrt ベースの値 | ペアリング式の一貫性 |
 | n = 7 | sqrt ベースの値 | 奇数長の処理 |

 ## 特殊なケース

 n = 1 の場合、幅 1 のブロックは 1 つだけあります。式では m = 0、合計 = 1 となり、答えは 1 になります。奇数ケースの加算が 1 つのブロックに寄与するため、アルゴリズムはこれを正しく処理します。 

n = 2 の場合、両方のブロックの幅は 1 です。m = 1、合計 = 2 となり、平方根は 1 になります。ブロックが 2 つ存在しても、合計面積が不十分であるため、辺 2 を形成することはできません。 

大きな奇数 n (たとえば n = 10^9) の場合、アルゴリズムは m = 5×10^8 を計算し、Python 整数の二次式を安全に評価します。 モノトーン構造により、オーバーフローや構造的なパッキング不良が発生せず、平方根が正確なままになります。
