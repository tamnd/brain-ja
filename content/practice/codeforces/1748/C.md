 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、そのプレフィックスの合計がゼロに達する頻度を気にします。 位置のプレフィックス合計`i`最初の合計です`i`これらのプレフィックスの合計が正確にゼロであるものがいくつあるかを数えることによって配列をスコア付けします。 

工夫としては、一部の要素は最初はゼロであり、そのような各位置は柔軟です。必要な整数に置き換えることができ、ゼロの位置ごとに異なる値を使用することもできます。 目標は、ゼロのプレフィックス合計の数ができるだけ多くなるように置換を選択することです。 

制約の観点から見ると、すべてのテスト ケースにわたる合計入力サイズは最大で`2 · 10^5`。 これにより、多くの候補変更のプレフィックス合計を繰り返し再計算する二次戦略は即座に除外されます。 許容できるものは基本的に、テスト ケースごとに各要素を一定の回数処理する必要があります。 

すべての値がゼロ以外の場合、微妙なエッジ ケースが発生します。 この状況では、操作はまったく許可されないため、答えは元のプレフィックス構造によって決まります。 演算を使用して常にプレフィックスの合計を「修正」できると想定する単純なアプローチでは、スコアが誤って過大評価されてしまいます。 もう 1 つの特殊なケースは、ゼロが頻繁に現れる場合です。 不用意に貪欲なアプローチでは、すべてのゼロが独立してプレフィックス合計をゼロに強制できると想定する可能性がありますが、任意の値を選択できる機能は、プレフィックス合計がグローバルにどのように進化するかを理解している場合にのみ役に立ちます。 

## アプローチ

 この問題を直接考える方法は、ゼロ エントリを置き換えるために考えられるすべての選択肢をシミュレートすることです。 ゼロの位置ごとに、将来のゼロのプレフィックスの合計を作成するのに役立つ可能性のあるすべての整数を試し、後でプレフィックスの合計を再計算することができます。 これは原理的には正しいですが、完全に実行不可能です。値を小さなセットに制限しても、構成の数はゼロの数で指数関数的に増加し、各構成ではプレフィックスの合計を計算するためにフル スキャンが必要になり、最悪の場合は指数関数的に時間がかかります。 

重要な観察は、スコアはプレフィックスの合計にのみ依存し、プレフィックスの合計は線形に変化するということです。 ゼロに遭遇した場合、その時点での累計をどの程度調整するかを完全に制御できます。 これは、各ゼロが「リセットの機会」のように機能することを意味します。以前の履歴に関係なく、その位置のプレフィックスの合計が正確にゼロになるように値を選択できます。 ただし、その自由を誤って使用すると、1 つの位置を変更するとその後のすべてのプレフィックス合計に影響を与えるため、将来の機会が失われる可能性があります。 

正しい観点は、現在のプレフィックスの合計を追跡しながら、配列を左から右に処理することです。 元の値がゼロである位置に到達すると、それを使用してその正確な位置でプレフィックス合計をゼロにするかどうかを決定できます。 そうする場合、事実上、累計がゼロにリセットされます。 これは、現在のプレフィックス合計がまだゼロでない場合に常に有益です。これにより、その後一貫して継続する能力を失うことなく、追加のカウント ゼロを作成できるからです。 

これにより、問題は、リセットが強制されるたびにゼロから累積を再開するという制約のもとで、ゼロのプレフィックス合計を何回強制できるかを貪欲にカウントするというものに軽減されます。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、配列を 1 回スキャンします。 

1. 実行中のプレフィックス合計を初期化します。`s = 0`そしてカウンター`ans = 0`。 
2. 配列を左から右に繰り返します。 ポジションごとに`i`、 追加`a[i]`に`s`。 これは、この位置で特別なことを何も行わなかった場合のプレフィックスの合計をシミュレートします。 
3. 現在のプレフィックスの合計が`s`ゼロになる、増加する`ans`有効なゼロプレフィックスを取得したためです。 
4. もし`a[i] == 0`, この位置を交代ポイントとして使用することを検討します。 現在のプレフィックス合計がゼロでない場合、次のように設定します。`ans += 1`そしてリセット`s = 0`。 その理由は、現在のプレフィックスの合計を正確にキャンセルする値をこのゼロに割り当て、位置に新しいゼロのプレフィックスを作成できるためです。`i`して蓄積を再開します。 
5. 配列の最後まで続けます。 

重要な決定は、すべてのゼロ値の位置を無視できるか、プレフィックス リセットを強制するために使用できるかのいずれかであるということです。 これを使用すると、ゼロ プレフィックスの数が増加する場合にのみ役立ちます。これは、累計がまだゼロではない場合に発生します。 

### なぜ効果があるのか

 現在のプレフィックスの合計によって、プレフィックスがスコアに寄与するかどうかが完全に決まります。 ゼロ位置での変更は、現在までの合計を通じて将来のすべてのプレフィックス合計に均一に影響します。 したがって、各ゼロは、システムをクリーンな状態にリセットできる潜在的な「カットポイント」として機能します。 

不変条件は、インデックスを処理した後のものです。`i`、アルゴリズムは、最初のプレフィックス サムの中から最適な選択を使用して、達成可能なゼロ プレフィックス サムの最大可能数を維持します。`i`現在のシミュレートされたプレフィックス合計と選択された決定との一貫性を維持しながら、要素を追加します。 プレフィックスの合計がゼロ以外の場合にゼロにリセットしない代替戦略では、後の柔軟性が低下することなく、その位置でのスコアを増やすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        s = 0
        ans = 0
        
        for x in a:
            s += x
            
            if s == 0:
                ans += 1
            
            if x == 0:
                if s != 0:
                    ans += 1
                    s = 0
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、左から右へのシミュレーションに直接従います。 プレフィックスの合計`s`選択した変更を適用した後の現在の累積値を表します。 小切手`s == 0`は、変更を加えずに自然なゼロプレフィックスの出現を考慮します。 2 番目の条件は、リセットを強制する値を積極的に選択するゼロ位置を処理します。 

リセットする`s`現在の合計をキャンセルするためにゼロの位置を使用すると、将来のプレフィックス合計はその新しいベースラインを基準にして計算される必要があるため、ゼロへの設定は不可欠です。 このリセットがないと、後の計算で過去の寄与が誤って蓄積されてしまいます。

 ## 特殊なケース

 単一のゼロを含む最小限の入力は、リセット動作を直接示します。 と`a = [0]`、プレフィックスの合計は最初はゼロであり、アルゴリズムはそれを 1 回カウントし、その後ゼロの位置をリセットの機会としても認識しますが、合計はすでにゼロであるため、誤って二重カウントすることを回避し、それでも戻ります`1`。 

のために`a = [1, 2, 3]`、操作するゼロはなく、プレフィックスの合計がゼロに達することもないため、答えは変わりません。`0`。 このアルゴリズムはリセット分岐をトリガーせず、単純にゼロ以外のプレフィックスを蓄積します。 

すべて 0 のシーケンスの場合、すべての位置を使用してリセットを強制できます。 各ステップで新しいゼロのプレフィックスが生成されるため、結果は次のようになります。`n`、貪欲なリセット ルールは、次の要素を処理する前に合計がゼロ以外のすべての位置でリセットすることで、これを正しく実現します。
