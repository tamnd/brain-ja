 ## 解決策
 ## 問題の理解

 隠れた長さの順列を再構築するように求められます`n`以下のすべての整数を含む`1`に`n`インタラクティブなクエリメカニズムを使用します。 クエリごとに、2 つの異なるインデックスを選択します`i`そして`j`、タイプ`t`(1 または 2)、およびしきい値`x`。 Nastia は、次の順列要素に基づいて計算された値で応答します。`i`そして`j`そして`x`、タイプ 1 は最小値の最大値を返し、タイプ 2 は最大値の最小値を返します。という 2 つのルールに従います。 

入力は複数のテスト ケースで構成されます。 それぞれに長さが与えられます`n`、そして、最大でも大まかに使用して隠れた順列を決定する必要があります。`1.5 * n + 30`クエリ。 出力は、各テスト ケースの完全な順列です。 

制約が意味するのは、`n`最大 10,000 件に達する可能性があり、すべてのテスト ケースの合計の上限は 20,000 件です。 これにより、おおよそのことが可能になります`O(n)`テスト ケースごとの操作ですが、二次アプローチは除外されます。 あらゆるインデックスのペアを可能な限り試みる単純な総当たり戦略`x`すぐにクエリの予算を超えてしまう可能性があります。 

エッジケースには、最大値が次のような順列が含まれます。`n`極端な位置にある、例えば、`p = [1, 2, 3, ..., n]`または`p = [n, 1, 2, ..., n-1]`。 不注意なアプローチでは、インデックス間の対称性を前提としたり、隣接する要素のみの比較に依存したりする可能性があり、最大または最小の要素が最初または最後の位置にある場合は失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのペアをクエリすることです。`(i, j)`可能な限り`x`それぞれを決定する`p_i`。 これは、タイプ 1 をさまざまな値でクエリすることで機能するため、`x`、隔離できる`p_i`に対して`p_j`。 ただし、クエリの数は増加するにつれて、`O(n^2)`、これは多すぎます。`n = 10^4`、時間とクエリの両方の制限を超えています。 

最適なアプローチは、順列内の最大要素を効率的に識別できることに気づくことから生まれます。 タイプ 2 クエリ`x = n-1`最小値を返す`max(x, p_i)`そして`max(x+1, p_j)`; 以来`x+1 = n`、クエリの 1 つが返されます。`n`どちらかであれば`p_i`または`p_j`等しい`n`。 ペアを系統的に比較することで、次の指標を見つけることができます。`n`を使用して`n-1`クエリ。 最大の要素の位置がわかったら、次のようにタイプ 1 をクエリすることで残りの要素を決定できます。`x`最大の要素から 1 を引いた値に設定され、最大の要素のインデックスを他のインデックスと比較します。 これにより、正確な結果が保証されます。`2n - 2`制限内であれば安全にクエリを実行できます。 

重要な洞察は、相互作用が最小-最大操作を中心に構造化されており、最大の要素を「ピボット」し、それに関連する他のすべての値を推定できるということです。 これにより、問題が 2 次の複雑さから 1 次の複雑さに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`p`サイズの`n`順列を保存します。 
2. 最大の要素のインデックスを見つける`n`。 最初のインデックスを候補として開始し、インデックスを反復処理します。`1..n-1`。 インデックスごとに`i`、タイプ 2 クエリを実行します。`x = n-1`候補者を比較し、`i`。 応答が`n`、候補インデックスを現在のインデックスに更新します。 すべての反復の後、候補インデックスは保持されます。`n`。 
3. インデックスがわかったら、`n`、他のすべてのインデックスを反復処理して残りの要素を埋めます。 インデックスごとに`i != max_index`、タイプ 1 クエリを実行します。`x = n-1`比較する`i`と`max_index`。 戻り値は`p[i]`なぜなら`max_index`は最大の要素であり、最小-最大評価を支配します。 
4. 配列を出力する`p`。 

機能する理由: タイプ 2 クエリ`x = n-1`クエリに含まれる 2 つのインデックスのうちの 1 つが返されることを保証します。`n`最大値が含まれている場合。 これにより、リニアスキャンで以下を見つけることができます。`n`。 一度`n`が知られている場合、タイプ 1 クエリはその優位性を利用して、他の要素を独立して決定します。 各クエリは、正確に 1 つの要素を明らかにするか、最大値の候補を更新し、それを超えることはありません。`2n - 2`クエリ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(t, i, j, x):
    print(f"? {t} {i+1} {j+1} {x}")
    sys.stdout.flush()
    return int(input())

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = [0] * n
        
        max_idx = 0
        for i in range(1, n):
            res = ask(2, max_idx, i, n-1)
            if res == n:
                max_idx = i
        
        p[max_idx] = n
        for i in range(n):
            if i == max_idx:
                continue
            p[i] = ask(1, i, max_idx, n-1)
        
        print("! " + " ".join(map(str, p)))
        sys.stdout.flush()

solve()
```まずヘルパー関数を定義します`ask`クエリの送信と応答の受信用。 次に、すべてのインデックスをスキャンして最大値を見つけます。 タイプ 2 クエリにより、確実に検出されます。`n`。 その後、次を使用してクエリ 1 を入力します。`n-1`残りのすべての値を効率的に提供します。 インタラクションにおける 1 から始まるインデックス付けには注意が必要です。 対話性の問題を回避するために、各クエリはすぐにフラッシュされます。
