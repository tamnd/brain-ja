 ## 解決策
 ## 問題の理解

 ツリー、つまり接続されたグラフから始めます。$n$頂点と正確に$n-1$エッジ。 移動するたびに、既存のエッジを 1 つ削除し、任意の 2 つの頂点の間に新しいエッジを挿入できます。 プロセス中に構造が切断されることは許容されますが、すべての操作の後、最終的にはすべての頂点の次数が最大 2 であるツリー状の構造になる必要があります。 このような構造は単純なパス構造であり、竹と呼ばれることがよくあります。 

タスクは、最初のツリーをすべての頂点にわたるパスに変換するために必要なエッジ置換の最小数を決定することです。 各操作では 1 つのエッジが削除され、1 つのエッジが追加されるため、エッジの数は常に残ります。$n-1$したがって、最終的なグラフはまだツリーです。 唯一の制約は次数限界です。 

制約により、最大で$10^4$テストケースと合計$n$まで$2 \cdot 10^5$。 したがって、大きなツリーに対する二次処理は制限を超えるため、すべてのソリューションは平均してテスト ケースごとに線形である必要があります。 これは、任意のエッジ再配線をシミュレートしたり、候補パスを明示的に列挙したりすることはできないことを直ちに示唆しています。 

重要なエッジ ケースは、ツリーがすでにパスである場合に発生します。 たとえば、チェーン$1-2-3-4$すでに次数制約を満たしているため、操作は必要ありません。 局所的な次数の不均衡に基づいて盲目的に再配線を実行するアルゴリズムでは、不必要な演算が誤って導入されてしまいます。 

もう 1 つの重要なケースは、1 つの頂点を中心とする星です。 たとえば、頂点の場合、$1$が他のすべてに接続されている場合、中心の次数を徐々に最大 2 まで減らす必要があり、体系的な再配線が必要になるため、答えは大きくなります。 貪欲なローカル修正は、グローバル構造を考慮していない場合、必要なエッジ置換の数を簡単に過小評価する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、有効な操作のすべてのシーケンスをシミュレートし、高次数の頂点の優先構造を維持し、次数を減らすためにエッジを繰り返し再配線しようとします。 正しさを議論するのは難しくありませんが、各操作には次のような特徴があるため、分岐要素は膨大です。$\Theta(n^2)$新しいエッジの可能な選択肢。 すべての中間ツリー構成が将来の選択に影響を与えるため、注意を「有用な」エッジに限定しても、依然として組み合わせによる可能性の爆発が残ります。 

重要な点は、最終的な構造は常にパスであるということです。したがって、重要なのは、元の構造にできるだけ「近い」元のツリー内のスパニング パスを選択し、置き換える必要があるエッジの数を最小限に抑えることです。 エッジの編集という観点から考えるのではなく、視点を変えます。元のツリーに一貫した順序で既に存在する最終パスのエッジの数を最大化したいと考えます。 

これはツリー DP の視点につながります。ツリーをルート化し、最終的な竹では各頂点の次数が最大 2 であること、つまりチェーンの一部のように動作することを考慮します。 変換は、頂点が分離されたチェーンのコレクションを選択し、それらをマージするものとして扱うことができます。構造に互換性がない場合、マージごとに 1 回の操作が必要になります。 最適な戦略は、中央構造の周囲でブランチを最適にペアリングすることであり、切断して再配線する必要がある「余分なブランチ」の数を効果的に最小限に抑えます。 

この問題のよく知られた単純化は、答えは、ツリーを単一のパスに変換する際にどれだけ多くの「良好な」隣接関係を保持できるかによって決まるということです。これは、チェーンのエンドポイントを追跡する貪欲な DP でサブツリーをルート化して照合することによって計算できます。

 ## アルゴリズムのチュートリアル

 任意の頂点でツリーを根付けします。 各ノードについて、次数制約に違反することなく、このノードを通過する単一のチェーンに子サブツリーをマージできる数を計算します。 

親を処理する前に各サブツリーがすでに要約されるように、ノードをポストオーダーで処理します。 各子サブツリーは、利用可能なエンドポイントが既に存在するかどうかに応じて、上方に拡張できるチェーン、または切断する必要がある構造のいずれかを構成します。 

各ノードで、子からのすべての「利用可能なチェーン エンドポイント」を収集します。 パス内のノードは最大 2 つの隣接ノードに接続できるため、上向きに続行するにはそのようなチェーンを最大 2 つ選択する必要があり、他のすべては切断して再配線する必要があります。 

子チェーンを破棄するたびに、概念的には 1 つの操作を実行します。つまり、そのサブツリーを現在のノードに接続しているエッジを削除し、後でそれを別の場所に再接続して、最終パスの接続を維持します。 このような破棄された接続の数は、答えに直接影響します。 

すべてのノードを処理した後、破棄された子アタッチメントの合計数によって、必要な操作の最小数が決まります。 

構築フェーズはこの DP から派生します。子が保持されているチェーンの一部として選択されない場合は常に、その削除されたエッジを別のチェーンの適切なエンドポイントに接続する新しいエッジと組み合わせて、単一の進化する構造を常に維持するようにします。 

### なぜ効果があるのか

 不変条件は、ノードの処理後、そのサブツリー内のすべての頂点が一連の互いに素なパス フラグメントに配置され、これらのフラグメントのうち最大 2 つが親を介して拡張できる状態に残ることです。 最終的な構造の頂点は最大 2 つの入射エッジを持つことができるため、これは竹の次数制約と正確に一致します。 余分なフラグメントは現在の接続ポイントから切断する必要があり、そのような切断はそれぞれ 1 回の必要な操作に対応します。 すべての有効な最終的な竹は、チェーン セグメントごとに 1 つの親子アタッチメントを正確に誘導するため、この DP が許可する以上のアタッチメントを保存できるソリューションはなく、最小性が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            g[a].append(b)
            g[b].append(a)

        parent = [0] * (n + 1)
        order = []
        stack = [1]
        parent[1] = -1

        while stack:
            v = stack.pop()
            order.append(v)
            for u in g[v]:
                if u == parent[v]:
                    continue
                parent[u] = v
                stack.append(u)

        children = [[] for _ in range(n + 1)]
        for v in range(2, n + 1):
            children[parent[v]].append(v)

        dp_keep = [0] * (n + 1)
        ans = 0

        for v in reversed(order):
            gains = []
            for u in children[v]:
                gains.append(dp_keep[u])
            gains.sort(reverse=True)

            if len(gains) <= 2:
                dp_keep[v] = sum(gains)
            else:
                dp_keep[v] = gains[0] + gains[1]
                ans += sum(gains[2:]) + (len(gains) - 2)

        print(ans)

if __name__ == "__main__":
    solve()
```コードは最初にツリーを構築し、それをノードにルートします。$1$。 DFS 順序付けは、再帰の深さの問題を回避するために反復的に生成され、サブツリー処理がボトムアップになるように子リストが明示的に構築されます。 

各ノードについて、各サブツリーが保持できるチェーン接続の数を表す子からの寄与を収集します。 パス ノードは 3 つを超えるアクティブな方向をサポートできないため、これらの寄与を並べ替えることで、最も有用な 2 つの継続を保持することができます。 残りのすべての貢献は必要な削減としてカウントされ、答えに直接追加されます。 ノードごとに保存される DP 値は、そのノードを通じて上向きに維持できる接続の数を表します。 

最終的な答えは、必要なエッジ置換の最小数に相当する、すべての破棄されたアタッチメントを蓄積します。 

## 実用的な例

 深さ 2 の星のような形をした最初のサンプル ツリーについて考えてみましょう。 葉から上に向かって寄与を計算します。 葉はすでに自明なチェーンを形成しているため、寄与はゼロです。 センターでは、多くの子供たちが、最大 2 つの保存された接続をめぐって競い合います。 

| ノード | 子どもの寄付 | 保管 | 削除されました | DP値 |
 | --- | --- | --- | --- | --- |
 | 中央 | 多くのゼロ | 2 | その他すべて | 0 |

 削除の数は子の数から 2 を引いたものに等しく、パス構造内に残ることができるスポークは 2 つだけであるという直観と一致します。 

2 番目のサンプルでは、​​ツリーはすでにパスになっています。 すべてのノードにはルート表現内に最大 2 つの子があるため、どのステップでも削除は発生しません。 DP は過剰な枝刈りを引き起こすことはありません。 

これは、次数制約に違反するノードがないため、アルゴリズムが不必要な変更を導入することなく既存のパス構造を保存することを示しています。
