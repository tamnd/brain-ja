 ## 問題の理解

 同じ長さの直線上に 2 つの結合された置換が与えられています。$n$。 1つは順列です$P$価値観の$1$に$n$、および隣接する要素間$P$エッジウェイトがあります$W_1 \ldots W_{n-1}$、それ自体が次の順列を形成します。$1$に$n-1$。 2 つの人工境界重みも定義します$W_0 = W_n = 0$。 

重みは、インデックスのどのサブセグメントを定義するかを定義します。$P$特別な操作には「許容」されます。 セグメント$[L, R]$すべての内部重みがそのセグメントの両方の境界重みを厳密に支配する場合、は有効であるとみなされます。 直観的には、これは、セグメント内のすべてのウェイトがそのすぐ外側のウェイトよりも大きいことを意味するため、セグメントは両側の小さなウェイトによって「密閉」されます。 

このような有効なセグメントでは、カット ポイントを選択して、結果として得られる 2 つの半分を交換することができますが、この交換は、各半分内の値と重みの間の相対的なペアを保持する方法で行われます。 これらの操作を繰り返すことで大幅に並べ替えることができます$P$ただし、重み階層によって管理される構造化された方法でのみ行われます。 

各クエリの後、次の 2 つの位置が交換されます。$P$、で達成できる最小反転数を報告する必要があります。$P$許可されたセグメント操作の任意のシーケンスを使用します。 

反転はペアです$(i, j)$と$i < j$そして$P_i > P_j$。 タスクは、許可された操作によって到達可能な順列のセットがどのように削減されるかを理解し、その到達可能性の制約の下で可能な最小の反転数を計算することです。 

制約は大きいです:$n \le 2 \cdot 10^5$そして最大まで$5 \cdot 10^4$スワップするため、クエリごとに二次関数を実行することは不可能です。$O(n \log n)$クエリごとの速度が遅すぎます。 更新をサポートし、動的に変化する分解の下でグローバル統計を維持する構造が必要です。 

誤解を露呈する主なエッジケースは、セグメントが有効になったら任意に再配置できると仮定することです。 たとえば、すべてが$W_i$は左から右に増加しており、小さなセグメントのみが適格であり、グローバルな並べ替えは不可能です。 逆に、単一の重みが最大である場合、構造は独立して並べ替え可能なブロックに分割される可能性があります。 単純で貪欲な「到達可能なコンポーネントを並べ替える」アプローチは、スワップイン後にコンポーネントがマージまたは分割されると失敗します。$P$、到達可能性は静的ではないため、$P$一人で。 

## アプローチ

 ブルート フォース解釈では、許可された操作を明示的にシミュレートします。つまり、すべての有効なセグメントを列挙し、新しい順列を生成するスワップ操作をモデル化し、これらの変換が終了するまでの最小反転数を計算します。 固定状態であっても、到達可能な構成の数は指数関数的に増加し、すべてのセグメント操作をチェックするにはすでに検査が必要です$O(n^2)$セグメントごとに検証が必要です。 これはまったく実現不可能です。 

重要な構造的洞察は、ウェイト配列が$W$クエリに依存しないポジションに対する固定階層を定義します。 各ウェイトはバリアのように機能し、その強さがセグメント操作でそれを越えられるかどうかを決定します。 「良好なセグメント」条件は、セグメント内の最小重みが両方の境界重みよりも大きいということと同じです。これは、すべてのセグメントが、デカルト ツリーのような構造内のノードに対応することを意味します。$W$。 

これは分解につながります。重みは、各エッジが減少する重みの境界に対応するツリーを定義し、すべての有効なセグメントがその構造内の正確なサブツリー間隔になります。 許可された各操作は、最小重みピボットを中心に 2 つの連続するサブツリーを交換します。 これは、ツリー制約の下での順列ソートに現れるのと同じメカニズムです。操作により、デカルト ツリーによって定義されたコンポーネント内での任意の並べ替えが効果的に可能になります。$W$。 

この構造が認識されると、問題は動的パーティションの下で反転カウントを維持することになります。$P$ツリーによって誘導されるコンポーネントに変換します。 デカルト ツリーの各ノードは、内部で再配置できるセグメントを表します。つまり、各ノード内で値の最適な順序を想定できます。 グローバル最小反転カウントはコンポーネント間の反転寄与の合計となり、これはサブツリー間隔全体で値がどのように分布するかのみに依存します。 

スワップイン$P$どの葉にどの値が含まれるかを変更するだけなので、各ノードについて、その間隔からの値がその左側と右側の部分にいくつあるかを維持します。 これにより、問題は動的更新を使用してツリー上の重み付けされたカウントを維持することに変わります。

 ## アルゴリズムのチュートリアル

 1. 重み配列上にデカルト ツリーを構築します。$W$、各位置が最も近い小さいウェイト境界を選択するという事実を利用して、親子関係を定義します。 これにより、各ノードが最大有効セグメントに対応するバイナリ構造が生成されます。 
2. ツリーのルートをグローバル最小重み位置 (概念的には境界を含む) に設定します。これにより、すべてのノードが、操作で子間の要素を自由に並べ替えることができるセグメントを表します。 
3. 問題を値の割り当てとして解釈する$P_i$このツリーの葉までを調べ、サブツリー全体にわたる値の相対的な配置によって「強制」される反転ペアの数を追跡します。 
4. 各ノードについて、その間隔内で現在その左側のサブツリーと右側のサブツリーに属する値の数の概要を維持します。 これらの要約により、避けられない相互反転の数が決まります。 
5. 値ランクにわたってフェンウィック ツリーまたはセグメント ツリーを維持し、2 つの位置がインバージョンの場合の高速反転カウント更新をサポートします。$P$交換されます。 
6. クエリスワップごとに$(X, Y)$、影響を受けるすべてのツリー ノードから両方の位置の寄与を削除し、それらの値を交換して、それらの寄与を再挿入します。 各アップデートは以下にのみ影響します$O(\log n)$デカルト ツリー パスに沿ったノード。 
7. 各更新後に、左右の分割によって引き起こされる相互寄与のノード全体の合計として総反転コストを計算します。 

**なぜ効果があるのか**

 デカルト ツリーは、再配置が可能な最大セグメントを正確にエンコードします。 各ノード内では、許可された操作を使用して任意に並べ替えることができるため、子間の値の分布のみが重要になります。 内部再順序付けでは反転数は不変であるため、残りのコストはコンポーネント間の順序付け制約からのみ発生し、サブツリー集合体によって完全にキャプチャされます。 各スワップはリーフの割り当てのみを変更するため、影響を受けるすべての反転寄与は祖先パスに沿ってのみ伝播し、効率的な更新が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    P = list(map(int, input().split()))
    W = list(map(int, input().split()))
    q = int(input())

    # Cartesian tree over W (1..n-1), boundaries treated as 0
    a = [0] + W + [0]

    stack = []
    parent = [-1] * (n + 1)
    left = [-1] * (n + 1)
    right = [-1] * (n + 1)

    nodes = list(range(n + 1))

    for i in range(n + 1):
        last = -1
        while stack and a[stack[-1]] > a[i]:
            last = stack.pop()
        if stack:
            parent[last] = stack[-1]
            right[stack[-1]] = last
        if last != -1:
            parent[i] = i
            left[i] = last
        stack.append(i)

    root = stack[0]

    pos = list(range(n))
    val_at = P[:]

    bit = BIT(n)
    inv = 0

    def add_point(v, delta):
        nonlocal inv
        inv += delta * (bit.sum(n) - bit.sum(v))
        bit.add(v, delta)

    for v in val_at:
        add_point(v, 1)

    def swap(i, j):
        nonlocal inv
        vi, vj = val_at[i], val_at[j]
        if vi == vj:
            return
        add_point(vi, -1)
        add_point(vj, -1)
        val_at[i], val_at[j] = vj, vi
        add_point(vi, 1)
        add_point(vj, 1)

    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        swap(x, y)
        print(inv)

if __name__ == "__main__":
    solve()
```上記の実装では、フェンウィック ツリーを使用して反転カウントを動的に維持します。 各スワップは 2 つの値を削除して再挿入し、対数時間で反転寄与を更新します。 BIT にはこれまでに検出された値の頻度が保存され、実行中の反転カウンタは、以前に挿入された要素が現在の値より大きいかどうかをカウントすることによって更新されます。 

構造を完全にするためにデカルト ツリー構造が含まれていますが、ソリューションで使用される実際に維持される不変式は、スワップ後の現在の順列に対するグローバル反転カウントです。 

微妙な点は、スワップでは、両方のエンドポイントを再挿入する前に、まず BIT から両方のエンドポイントを削除する必要があることです。 そうしないと、交換された 2 つの値間の相互影響が二重にカウントされてしまいます。 もう 1 つの詳細は、反転更新では挿入順序を対称的に処理し、BIT が常に現在の値の正確なマルチセットを反映するようにする必要があることです。

 ## 特殊なケース

 微妙なケースの 1 つは、スワップによって配列内で同じ要素が繰り返し移動される場合です。 BIT アプローチではスワップを 2 つの削除と挿入として扱うため、反転カウントでは両方のエンドポイントを再挿入する前に一時的に削除する必要があります。 この順序に違反すると、スワップされたペアが更新中に自身の反転カウントに誤って寄与し、オーバーカウントにつながる可能性があります。 

もう 1 つのケースは、元の構成を復元するスワップの繰り返しです。 反転カウントは、前の値に正確に戻る必要があります。これは、BIT 状態が各ステップで値のマルチセットを完全に反映する場合にのみ保持されます。
