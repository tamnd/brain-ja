 ## 解決策
 ## 問題の理解

 無向グラフが与えられました。 各頂点はブログを表し、すべてのブログには目的のトピック番号があります。`t[i]`。 

ジョニーはブログを一つ一つ書きます。 彼がブログを書くとき、彼はすでに書かれた隣人だけを見ます。 彼はトピックの中で、出現しない最小の正の整数を見つけて、そのトピックを現在のブログに正確に割り当てます。 

希望するトピックはすでに決まっています。 私たちの仕事は、ジョニーのルールがすべての頂点に対して指定されたトピックを正確に生成するようなブログを書く順序を見つけることです。 そのような順序が存在しない場合は、出力する必要があります`-1`。 

グラフには以下が含まれます`5 * 10^5`頂点と`5 * 10^5`エッジ。 これらの制限により、二次関数は即座に除外されます。 平`O(n√n)`不快だろう。 グラフ自体にはのみが含まれているため、`O(n + m)`データに基づいて、受け入れられたソリューションは線形または`O((n + m) log n)`。 

難しいのは、目的のトピックが任意のラベルではないことです。 それらはジョニーが使用するメキシコ風のルールに一致する必要があります。 トピックを持つ頂点`k`からのすべてのトピックをすでに参照している必要があります`1`を通して`k - 1`以前に書き込まれた隣接するものの間であり、トピックを参照してはなりません`k`。 

いくつかのエッジケースでは、単純な構造が簡単に壊れてしまう可能性があります。 

同じトピックを持つ 2 つの隣接する頂点を考えます。```
2 1
1 2
1 1
```どちらか一方が最初に書かれた場合、もう一方はすでにトピックを参照しています`1`、そのためトピックも受信できません`1`。 正しい答えは、`-1`。 

トピックが次のような頂点があるとします。`3`、ただし、トピックのみの隣人がいます。`1`そして`4`:```
3 2
1 2
1 3
3 1 4
```トピック`2`近所から行方不明になっている。 ジョニーにトピックを割り当てる命令はありません`3`その頂点へ。 正しい答えは、`-1`。 

もう 1 つの微妙なケースは、必要な小さなトピックがすべて存在するが、隣接するトピックが同じトピックを持っている場合です。```
3 3
1 2
2 3
1 3
2 1 2
```頂点`1`話題があります`2`。 話題でお隣さんを見る`1`、それは良いことですが、話題のある隣人もいます`2`。 トピック 2 の近隣トピックがより早く処理されると、トピック`2`はすでに書き込まれた近隣の中に存在しており、mex が存在することを妨げています。`2`。 インスタンスは不可能です。 

ソリューションでは、これらすべての条件を効率的に検証する必要があります。 

## アプローチ

 強引なアイデアは、順序を構築してジョニーのルールを繰り返しシミュレーションしてみることです。 すべての頂点について、すでに処理された近傍を調べ、欠落しているトピックの最小値を計算し、それが目的の値と等しいかどうかを確認できます。 

問題は、次にどの頂点が来るかを決定することです。 可能な注文の探索は指数関数的に行われます。 何らかの方法で順序を修正したとしても、頂点ごとに mex を最初から再計算するには、多くの近傍を繰り返しスキャンする必要があり、その結果、大まかに`O(nm)`密集した状況での作業。 

重要な観察は、有効な注文が存在する場合に何が起こるかを調べることから得られます。 

頂点に目的のトピックがあるとします。`t`。 

ジョニーにトピックを割り当てる`t`、あらゆるトピック`1, 2, ..., t-1`以前に書き込まれた近隣の中にすでに存在している必要があります。 これらのトピックはこの頂点が書き込まれる前にすでに存在している必要があるため、トピック番号が小さいすべての頂点が先に処理される必要があります。 

これは、唯一の意味のある順序、つまり、目的のトピックの昇順で頂点を処理することを直ちに示唆します。 同じトピックを共有する頂点は、任意の相対順序で表示できます。 

次に頂点を考えます`v`話題付き`t[v]`。 

すべての小さなトピックの頂点がすでに処理されている場合、一連のトピックが`v`の近傍は、メキシコを同等にするのに正確に十分でなければなりません`t[v]`。 

つまり:

 1. 隣人は話題を持ってはいけません`t[v]`。 
2. からのすべてのトピック`1`に`t[v]-1`隣接するトピックの中に出現する必要があります。 

これらの条件がすべての頂点に当てはまる場合、頂点をトピックごとに並べ替えるだけで、すでに有効な書き込み順序が得られます。 より小さいトピックを持つすべての隣接トピックはより早く処理され、同じトピックの隣接トピックはすべて存在せず、必要なすべてのより小さいトピックが存在します。 

これにより、問題は複雑な順序の構築から頂点ごとの局所的な条件の検証に変換されます。

 ## アルゴリズムのチュートリアル

 1. グラフと各頂点の目的のトピックを読み取ります。 
2. トピック値を増やして頂点の順序を作成します。 

有効な解決策が存在する場合、より小さなトピックを持つすべての頂点を、より大きなトピックを持つすべての頂点より前に処理する必要があります。 
3. この並べ替えられた順序で頂点を移動します。 
4. 現在の頂点の場合`v`、すべての近隣に出現するトピック値のセットを収集します。 

必要なのはトピック ラベル自体だけであり、近隣 ID は必要ありません。 
5. トピックの場合`t[v]`隣接するトピックの中に が表示されている場合、回答は不可能です。 

ジョニーはトピックを受信できません`t[v]`そのトピックがすでに隣人の間に存在する場合。 
6. 隣接トピックの数が次の値より小さいかどうかを確認します。`t[v]`等しい`t[v] - 1`。 

トピックは正の整数であるため、これはすべてのトピックを意味します`1, 2, ..., t[v]-1`必要なとおりに存在します。 

セットを使用するので重複は問題ありません。 
7. いずれかのチェックが失敗した場合、出力`-1`。 
8. すべての頂点が合格した場合、トピックの昇順で頂点を出力します。 

### なぜ効果があるのか

 頂点を考えてみましょう`v`希望の話題で`t`。 

有効な書き込み順序が存在する場合、以下のすべてのトピックが`1`を通して`t-1`以前に書き込まれた隣接するものの中にすでに存在している必要があります`v`。 その結果、`v`それらすべてのトピック値を保持する近隣ノードが必要です。 また、トピックス`t`それ自体は隣接するトピック間で出現することはできません。そうでない場合、欠落している最小のトピックはそれよりも大きくなります。`t`。 

これらは必要な条件です。 

それらも十分です。 トピックを増やして頂点を並べ替えた後は、トピックが小さいすべての近傍がより早く処理されることが保証されます。 どの話題もそうなので、`1..t-1`近所や話題に存在する`t`そうではありません。すでに書かれている近隣トピックの中で欠落しているトピックの中で最も小さいものは、まさに次のとおりです。`t`。 したがって、ジョニーは希望のトピックを割り当てます。 

すべての頂点が独立してこの引数を満たすため、ソートされた順序はグラフ全体に対して有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    t = list(map(int, input().split()))

    order = sorted(range(n), key=lambda x: t[x])

    for v in order:
        cur = t[v]

        seen = set()

        for to in g[v]:
            topic = t[to]

            if topic == cur:
                print(-1)
                return

            if topic < cur:
                seen.add(topic)

        if len(seen) != cur - 1:
            print(-1)
            return

    print(*[v + 1 for v in order])

if __name__ == "__main__":
    solve()
```グラフは隣接リストとして保存されます。`n`そして`m`到達できる`5 * 10^5`。 

ソートステップでは、候補の書き込み順序が作成されます。 これはソリューションの中心的な観察です。有効な順序はトピック値の増加を考慮する必要があります。 

各頂点については、隣接するトピックのみが重要です。 セット`seen`現在のトピックより小さい個別のトピックを保存します。 重複は自動的に無視されます。 

条件```
len(seen) == cur - 1
```すべてのトピックがポジティブであるため、機能します。 正確にあるなら`cur - 1`明確に小さなトピックがあり、それらはすべて以下です`cur`、それらは正確にセットでなければなりません`{1, 2, ..., cur - 1}`。 

同じ話題を持つ隣人をチェックすることが不可欠です。 このテストを行わないと、隣接する 2 つの頂点の両方にラベルが付けられる場合など、`1`誤って合格してしまいます。 

すべての値が Python 整数に快適に収まるため、整数オーバーフローの懸念はありません。

import sys
import io

def run(inp: str) -> str:

    input = sys.stdin.readline

    n, m = map(int, input().split())

    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

            if topic < cur:
                seen.add(topic)

        if len(seen) != cur - 1:
            return "-1\n"

    return " ".join(str(v + 1) for v in order) + "\n"
