 ## 解決策
 ## 問題の理解

 私たちは、順序付けられた一連の映画を含む棚を与えられ、各映画には「タイプ」または終了ラベルが付いています。`1`に`m`。 この初期シーケンスは固定されており、インデックスが付けられます。`1`に`n`。 

毎月、現在の棚と追加のフィルムを組み合わせて、特定のパラメーターに対して新しいフィルムのマルチセットが形成されます。`k`、 その通り`k`すべての終了タイプのコピーが追加されます。 この拡張の後、概念的にランダムな実験を実行します。つまり、均一に選択します。`n`この拡大されたマルチセットからフィルムを置き換えずに選択し、選択したフィルムをランダムな順序で配置して、長さの新しい棚を形成します`n`。 

この質問は、このプロセスを直接シミュレートするものではありません。 代わりに、クエリごとに、位置の特定のセグメントが一致する確率を計算するように求められます。`[l, r]`新しい棚は元の棚と正確に一致します。 回答はフォームで必須です`P × A`、 どこ`A`選択する方法の合計数です`n`保管庫から取り出したフィルム。 これは、セグメント制約が成立するようにフィルムを選択および配置するための有利な方法の数を効果的に計算していることを意味します。 

主な難点は、各クエリが変化することです`k`、したがって、マルチセットのサイズが変化しますが、確率の構造は、対称性が高いが大きなマルチセットからの組み合わせサンプリングに依存します。 

この制約により、直接の組み合わせ列挙から遠ざけられます。 と`n, q ≤ 10^5`、 平`O(n)`クエリごとの速度はすでに境界線に達しており、クエリごとのカラーごとのスキャンを伴うものは遅すぎます。 異なる値が最大 100 個存在するという追加の制約`k`これは、クエリをグループ化して効率的に処理する必要があるという主な構造上のヒントです。`k`。 

いくつかの微妙な特殊なケースがすぐに現れます。 いつ`k = 0`、マルチセットは元のシェルフにすぎないため、答えは決定的であり、確率は固定マルチセットのランダムな置換の下でセグメントを保存できるかどうかに対応しますが、これにはすでに正しい組み合わせ処理が必要です。 もう 1 つの例外的なケースは次のような場合です。`l = r`ここで、答えは単一位置の確率に帰着し、一般式と正確に一致する必要があります。 最後に、シェルフ内で繰り返される値は重要です。位置を独立したものとして扱うと、同一の末尾が下降階乗法で乗算的に寄与するため、誤った過大カウントにつながります。 

## アプローチ

 直接的なアプローチでは、ランダムなプロセスがシミュレートされます。 考えられるすべてのサイズを生成するという観点から考えることもできます。`n`拡大されたマルチセットから選択し、どの選択がセグメントを保持しているかを確認します。 そのような選択の数は天文学的に膨大です。`n`おおよそから`n + m·k`要素は二項スケールの爆発につながります。 このアプローチは、単一のクエリであってもすぐに実行不可能になります。 

より構造化されたビューは、最終的な配置が、ランダムに選択されたマルチセットのサブセットをランダムに並べ替えることと同等であることを認識することで得られます。 対称性があるため、サイズの固定マルチセットから置き換えることなく、プロセスを順次描画として再解釈できます。`n + m·k`ここで、各有効なシーケンスは、多項係数の積に比例する確率を持ちます。 

重要な単純化は、条件が「セグメント」であることです。`[l, r]`「変更されない」は、セグメントの外側の正確な配置には依存しません。代わりに、セグメント内で各色が何回、どのような順序で表示されるかを制限するだけです。これにより、問題は 2 つの独立した要素の積に変換されます。分子はセグメントが各色のコピーをどのように消費するかに依存し、分母はグローバル サンプリング プロセスのみに依存します。 

ブルートフォースシーケンシャル確率の観点から積の形が得られます。各位置で、残りの数に比例する確率で必要な色を選択します。 の位置だけを分離すると、`[l, r]`、拘束されていない位置の効果は、マルチセットから既に削除されている要素の数を除いて相殺されます。 これにより、きれいな因数分解が行われます。各色は、セグメント内での出現回数に基づいて下降階乗項に寄与しますが、分母は描画の合計数とマルチセットのサイズのみに依存します。 

したがって、問題は、任意の範囲内の色の頻度情報を維持し、動的に変化するパラメータの下で下降階乗の積を評価することに帰着します。`k`。 の異なる値は最大 100 個しかないため、`k`、クエリをグループ化して処理します。`k`。 

高速範囲クエリをサポートするために、Mo のアルゴリズムを使用します。 クエリ ウィンドウをスキャンしている間、各色が表示される回数を維持し、それに応じて実行中の製品を更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | O(n) | 遅すぎる |
 | クエリごとのカウント | O(nq) | O(n) | 遅すぎる |
 | Grouped + Mo のアルゴリズム | O((n+q)√n · 100) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 の値を固定します`k`そしてそれを共有するすべてのクエリを処理します。 

1. このために`k`、計算する`A_c = cnt_initial[c] + k`、ストレージ内の各色の利用可能なコピーの合計。 計算もする`B = n + k·m`、サンプリング前のマルチセットの合計サイズ。 これにより、このグループのクエリのすべての確率が完全に決定されます。 
2. 答えを 2 つの独立した部分に書き直します。セグメントの構成のみに依存する分子と、セグメントの構成のみに依存する分母です。`(l, r, k)`。 この分離により、クエリごとにグローバルな組み合わせを再計算することを回避できます。 
3. 各クエリセグメントについて`[l, r]`、セグメント内の各色の数が必要です。 最初から再計算するのではなく、Mo のアルゴリズムを使用してクエリを処理し、セグメントが一度に 1 位置ずつ移動します。 
4. 実行周波数配列を維持する`freq[c]`現在のウィンドウの色について。 それと並行して、実行中の製品を保守します。$$\text{num} = \prod_c (A_c)(A_c-1)\cdots(A_c - freq[c] + 1)$$これは、追加/削除操作ごとに O(1) で更新できます。 
5.色付きの位置を追加する場合`c`、更新します`freq[c]`そして分子に次の値を掛けます`A_c - freq[c] + 1`。 削除するときは次のように割ります。`A_c - freq[c]`。 
6. 分母は色の分布とは独立しており、間隔の長さのみに依存します。 それは次のとおりです。$$\prod_{i=l}^{r} (B - i + 1)$$これは、それぞれのプレフィックス積を使用して事前に計算できます。`k`。 
7. クエリごとに、分母の逆モジュラーを使用して分子と分母を結合します。 

### なぜ効果があるのか

 核となる不変条件は、Mo のスイープ中のどの時点でも、維持される積が現在のセグメント内の色のマルチセットの下降階乗寄与に正確に等しいということです。 各更新は、多項係数に単一の出現を追加または削除する真の組み合わせ効果を反映します。 最終的な確率は色ごとの独立した寄与とグローバル サンプリング項に分解されるため、これら 2 つの部分を個別に維持することで、すべてのクエリの正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def add(x, y):
    return x + y

def mul(x, y):
    return (x * y) % MOD

def solve():
    n, m, q = map(int, input().split())
    arr = list(map(int, input().split()))

    queries_by_k = defaultdict(list)
    ks = []

    for i in range(q):
        l, r, k = map(int, input().split())
        queries_by_k[k].append((l - 1, r - 1, i))
        ks.append(k)

    max_k = max(ks) if ks else 0

    # positions are 0-indexed
    pos_by_color = defaultdict(list)
    for i, c in enumerate(arr):
        pos_by_color[c].append(i)

    ans = [0] * q

    # precompute prefix occurrence arrays per color is impossible, we use Mo per k
    import math

    def process_group(k, queries):
        A = {}
        for c in range(1, m + 1):
            A[c] = 1  # avoid missing key cost
        # we only override used colors
        # better: build A only for present colors
        for c in pos_by_color:
            A[c] = len(pos_by_color[c]) + k

        B = n + k * m

        # denominator prefix
        pref = [1] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] * (B - i) % MOD

        def denom(l, r):
            return pref[r + 1] * modinv(pref[l]) % MOD

        # Mo's algorithm
        block = int(n ** 0.5) + 1
        queries_sorted = sorted(queries, key=lambda x: (x[0] // block, x[1]))

        freq = defaultdict(int)
        cur_l, cur_r = 0, -1
        cur_num = 1

        def apply(idx, delta):
            nonlocal cur_num
            c = arr[idx]
            old = freq[c]
            if delta == 1:
                freq[c] += 1
                new = freq[c]
                cur_num = cur_num * (A[c] - new + 1) % MOD
            else:
                new = freq[c]
                cur_num = cur_num * modinv(A[c] - new + 1) % MOD
                freq[c] -= 1

        for l, r, qi in queries_sorted:
            while cur_r < r:
                cur_r += 1
                apply(cur_r, 1)
            while cur_r > r:
                apply(cur_r, -1)
                cur_r -= 1
            while cur_l < l:
                apply(cur_l, -1)
                cur_l += 1
            while cur_l > l:
                cur_l -= 1
                apply(cur_l, 1)

            ans[qi] = cur_num * modinv(denom(l, r)) % MOD

    for k, qs in queries_by_k.items():
        process_group(k, qs)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```実装はそれぞれを分離します`k`グループ化し、それに依存するすべての量を再計算します。 Mo の構造は、配列全体にわたってスライディング ウィンドウを維持し、各挿入または削除によって単一の色の周波数のみが更新され、それに応じて下降階乗積が調整されるようにします。 分母はプレフィックス積を使用して独立して処理されるため、各クエリは前処理後に一定時間内に応答されます。 

更新ロジックには注意が必要です。乗算係数は、挿入後の新しい頻度と削除前の以前の頻度に依存します。 よくある間違いは、除去時に補正項を計算する前に頻度を更新することです。これにより、逆関係が崩れます。

これは、独立した確率による単純な乗算が失敗する、重複が存在する場合の正しさを示しています。

 ## 特殊なケース

 いつ`k = 0`、追加のフィルムは追加されないため、すべてのカウントは純粋に最初の棚からのものです。 アルゴリズムは引き続き計算します`A_c = cnt[c]`、そして下降階乗は既存のコピーの順列に正しく還元されます。 アップデートは依存しないため、Mo メンテナンスは引き続き有効です。`k`ポジティブであること。 

セグメントが同じ色にまたがる場合、次のようになります。`[1,1,1]`、分子は次のように発展します。`A·(A−1)·(A−2)`、アルゴリズムは利用可能なカウントを段階的に正しく減らします。 単純な確率アプローチでは、各位置が独立したものとして誤って扱われてしまいます。 

いつ`l = r`、セグメントには単一の位置が含まれており、答えは次のようになります。`A_{e[l]} / B`、アルゴリズムは 1 つの乗算と 1 つの分母因数を介して再現し、一般式との一貫性を確認します。
