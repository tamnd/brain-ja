 ## 問題の理解

 すべて同じ固定長のバイナリ文字列のコレクションが与えられます。$n \le 12$。 このコレクション内の各文字列は多重度を持って出現するため、重複は重要です。 これに加えて、あらゆるポジションで$i$負ではない重みを持っています$w_i$。 

2 つのバイナリ文字列を比較する場合$s$そして$t$, 文字が一致する位置からのみ重みを蓄積します。 もし$s_i = t_i$、追加します$w_i$それ以外の場合は何も追加しません。 これは、2 つの文字列間の「類似性スコア」を定義します。これは、単に一致する位置の重みの合計です。 

クエリごとにバイナリ文字列が与えられます。$t$そして閾値$k$、マルチセット内の類似性スコアを持つ文字列の数をカウントする必要があります。$t$せいぜい$k$、重複を個別にカウントします。 

制約は重要なシグナルです。 長さ$n$は最大 12 であるため、各文字列は実質的に最大 12 位置のビットマスクになります。 ただし、弦の数は、$m$そしてクエリ$q$まで行く$5 \cdot 10^5$したがって、各クエリをすべての文字列と比較するソリューションは遅すぎます。 ナイーブ$O(mq)$比較ごとに最大 12 の演算を行う場合でも、約$6 \cdot 10^{10}$操作、それは不可能です。 

微妙な点は、重みが 100 までは任意であるため、ハミング距離のような均一な構造に依存できないことです。 代わりに、重み付けされた合意をエンコードする必要があります。 

よくある落とし穴は、文字列のペアごとに類似性を事前計算しようとすることです。 それには必要になります$O(m^2)$前処理も実行不可能です。 

もう 1 つの失敗例は、多重度を忘れることです。 文字列は繰り返されるため、カウントを慎重に集計する必要があります。 入力をマルチセットではなくセットとして扱うと、重複が存在する場合は常に不正確な答えが生成されます。 

## アプローチ

 ブルート フォースのアプローチは簡単です。クエリ文字列ごとに$t$、保存されているすべての文字列を反復処理します。$s$、重み付けされた一致スコアを計算します$O(n)$、スコアのあるものをカウントします$\le k$。 これは定義に直接従っているため、正しいです。 問題は速度です。各クエリにはコストがかかります$O(mn)$したがって、全体の複雑さは次のようになります。$O(mqn)$、それは限界をはるかに超えています。 

重要な観察は、次の小さな制約から来ています。$n$。 各文字列は、長さのビットマスクとして表現できます。$n$。 固定クエリ文字列の場合$t$との相対的な各位置の一致または不一致の重み寄与を事前に計算できます。$t$。 

文字列を直接比較する代わりに、保存されているすべての文字列を互換性構造を表す数値に変換します。 次に、すべての頻度を集計します。$2^n$マスク。 各マスクの数を取得したら、各クエリは位置のすべてのサブセットにわたる問題になります。しきい値内のスコアを生成するマスクの数を決定する必要があります。 

重要な洞察は、クエリに対する位置ごとの寄与を事前に計算することです。 マスクごとに$s$、対スコア$t$ビットが一致する位置のみに依存します。 つまり、すべてのマスクについて、固定されたマスクに対するその寄与を事前計算できるということです。$t$不一致または一致のサブマスクを反復処理することで実現可能です。$2^{12} = 4096$。 

各文字列マスクの頻度を事前に計算し、すべてのマスクを列挙し、スコア制約を使用してそれらを合計することで各クエリに答えます。 4096 は小さいので、$q \cdot 2^n$についてです$2 \cdot 10^9$最悪の場合は境界線に達するため、高速サブセット DP または重みの中間点を使用してさらに改善します。 

よりクリーンな方法は、ビットマスクに対する重み付き変換を使用して、マスクごとに、考えられるすべてのクエリ パターンに対する合計スコア寄与を事前計算し、基本的に各位置を独立して扱い、サブセットに対する DP を構築することです。

 ## アルゴリズムのチュートリアル

 各バイナリ文字列を次のサイズの整数マスクに圧縮します。$n$、どこビット$i$文字が「1」かどうかを示します。 各マスクが出現する回数もカウントします。 

1. すべての入力文字列を整数マスクに変換し、周波数配列を構築します。`cnt[mask]`。 このステップにより、個々の文字列について考えるのをやめ、代わりに固定サイズの世界に取り組むことが保証されます。$2^n$。 
2. 各クエリ文字列について$t$、マスクにも変換します`tm`。 保存されたマスクとの類似性スコア`s`はビットが等しい位置に依存するため、ビット単位の演算によって一致する構造を解釈します。 
3. ポジションのサブセットごとに重みの合計を事前計算します。 クエリごとに最初から再計算するのではなく、ビット位置ごとに寄与を分離し、最大 12 ビットにわたるサブセット列挙を使用して一致の決定を評価できるようにします。 
4. クエリごとに、すべてのマスクを反復処理します。`s`で`[0, 2^n)`、重み付き一致スコアを次のように計算します。`tm`事前に計算された位置寄与を使用して累積します`cnt[s]`スコアが範囲内であれば`k`。 
5. 累積カウントを出力します。 

これが高速になる主な理由は、状態の世界がわずか 4096 であるためです。慎重に構造化すれば、この空間に対するネストされた反復も引き続き実行可能です。 

### なぜ効果があるのか

 各文字列は位置のサブセットに一意に対応します。 2 つの文字列間の類似性スコアは、独立した座標にわたって分解される関数です。各位置は次のいずれかに寄与します。$w_i$または$0$、その位置での平等にのみ依存します。 この分離性により、位置ごとの独立した寄与を合計することでグローバル スコアを計算できるため、文字列ペアを直接列挙するのではなく、ビットマスク全体でカウントを集計することが有効になります。 単純な等価性を超える位置間の相互作用は存在しないため、ビットマスク表現は問題の構造を完全に捉えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    w = list(map(int, input().split()))

    size = 1 << n
    cnt = [0] * size

    # encode strings
    for _ in range(m):
        s = input().strip()
        mask = 0
        for i, ch in enumerate(s):
            if ch == '1':
                mask |= 1 << i
        cnt[mask] += 1

    # precompute for each mask: score against any t via bit structure
    # we will precompute contribution of equality using bit DP
    # dp[mask] will store sum of weights where bits are 1 in mask
    weight_sum = [0] * size
    for mask in range(size):
        s = 0
        for i in range(n):
            if mask & (1 << i):
                s += w[i]
        weight_sum[mask] = s

    # answer queries
    for _ in range(q):
        t = input().strip().split()
        s = t[0]
        k = int(t[1])

        tmask = 0
        for i, ch in enumerate(s):
            if ch == '1':
                tmask |= 1 << i

        ans = 0

        # compare against all masks
        for mask in range(size):
            # positions where equal:
            # equal bits = positions where both have 1 or both have 0
            # compute match mask: ~(mask ^ tmask)
            match = ~(mask ^ tmask) & (size - 1)
            score = weight_sum[match]
            if score <= k:
                ans += cnt[mask]

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、すべての文字列をビットマスクに圧縮し、以下を使用して同一の文字列を集約します。`cnt`。 配列`weight_sum`は位置のサブセットを重みの合計に変換するため、2 つの文字列間でどの位置が一致するかがわかれば、一定時間で類似性スコアを計算できます。 

クエリごとに、クエリ マスクと保存されたマスクの間の XOR を計算して、不一致の位置を見つけます。 固定内でこれを否定する$n$-bit 境界は、一致する位置を正確に示します。 そのマスクはインデックス付けに使用されます。`weight_sum`。 

重要な実装の詳細は、ビット単位の NOT をマスクすることです。`(size - 1)`Python の整数には制限がなく、そうでない場合は偽の上位ビットが導入されるためです。

 ## 特殊なケース

 すべての文字列が同一である場合、重要なエッジ ケースが発生します。 その場合、`cnt`ゼロ以外のエントリが 1 つあり、しきい値で許可されている場合、すべてのクエリはすべての重複を正しく集計する必要があります。 蓄積は次の方法で行われるため、アルゴリズムはこれを自然に処理します。`cnt[mask]`インスタンスごとの反復ではなく。 

もう 1 つのエッジ ケースは、重みがゼロの場合です。 その後、一致する構造に関係なく、すべての類似性スコアがゼロになり、すべてのクエリが$k \ge 0$戻らなければなりません$m$。 アルゴリズムはまだ機能します。`weight_sum`どのマスクでもゼロであるため、すべての文字列がカウントされます。 

最後の微妙なケースは、クエリのすべての位置で異なる文字列です。 この場合、一致マスクはすべて 0 であるため、スコアは 0 になり、正確さはビット単位の NOT を正しくマスクするかどうかに依存します。 表現`(~(mask ^ tmask) & (size - 1))`最低限のものだけを保証します$n$ビットが考慮され、上位ビットが誤って含まれるのを防ぎます。
