 ## 解決策
 ## 問題の理解

 私たちには番号が与えられています$n$からの整数の順列を構築する必要があります。$1$に$n$。 このようなすべての順列の中で、その順列で定義された量を最小化することが求められます。 

この量は、2 つの古典的なサブシーケンス メジャーの合計です。 1 つは、増加する最長のサブシーケンスの長さです。これは、インデックスの順序を尊重しながら値が厳密に増加する位置の最長のシーケンスを意味します。 もう 1 つは、最も長く減少するサブシーケンスの長さで、同様に定義されますが、値は厳密に減少します。 

タスクは、特定の順列に対してこれらの値を計算することではなく、それらの合計が可能な限り小さくなる順列を構築することです。 

制約により許可されるのは、$n$まで$10^5$これにより、すべての順列に対して LIS と LDS を評価しようとするアプローチが即座に除外されます。 単一の LIS 計算でも、$O(n \log n)$、順列の数は階乗であるため、網羅的な検索は不可能です。 どのような解でも、線形時間またはそれに近い時間で直接順列を構築する必要があります。 

微妙な落とし穴は、LIS を最小限に抑えると自動的に LDS に役立つ、またはその逆であると想定していることです。 たとえば、恒等順列$[1, 2, 3, \dots, n]$LISあり$n$とLDS$1$、反対側にはLISがあります$1$とLDS$n$。 どちらも多額の利益が得られる$n+1$したがって、極端な順序付けは最適ではありません。 

より小さな例では、問題がより明確に示されています。 のために$n = 4$、順列$[1,2,3,4]$合計を与える$5$、ただし、次のような再配置された構造$[3,4,1,2]$LISを与える$2$とLDS$2$、合計$4$。 これは、一方向の最適化よりも構造のバランスを取ることが重要であることを示しています。 

## アプローチ

 ブルートフォースのアイデアでは、すべての順列を列挙し、それぞれの LIS と LDS を計算します。 それぞれの評価にかかる費用$O(n \log n)$、そして、あります$n!$順列なので、これは完全に不可能です$n = 10$。 

もう少し情報に基づいた総当りアプローチでは、ランダムな置換を試行して最良の結果を維持できる可能性がありますが、最適性の保証はなく、検索スペースは膨大なままです。 

重要な観察は、順列が長い単調構造を持つ場合、LIS と LDS の両方が大きくなるということです。 配列を厳密に増加させると LIS が最大化され、配列を厳密に減少させると LDS が最大化されます。 目標は、どちらの方向にも長い単調なセグメントを避けることです。 

最適な構築は、サブシーケンスの増加と減少の両方を同時に制限するブロック構造に順列を強制することで得られます。 配列を 2 つの半分に分割し、後半を最初に、前半を 2 番目に配置すると、値がローカルに順序付けされているものの、長い単調チェーンの形成を防ぐのに十分なほどグローバルに「混合」されるパターンが作成されます。 

より一般的には、要素を高低ブロックに交互に配置すると、増加するサブシーケンスが各ブロックから最大 1 つの要素を選択できるようになり、同じ制限が減少するサブシーケンスにも対称的に適用されます。 これにより、LIS と LDS の両方の境界がおよそ決まります。$\lceil n/2 \rceil$、これは丸め効果までは最小限です。 

これにより、単純な貪欲な構造が得られます。つまり、最初に大きい数値を昇順に配置し、次に小さい数値を昇順に配置します。 これにより、LIS と LDS の両方が厳密に制約され、バランスがとれた順列が得られます。

 ## アルゴリズムのチュートリアル

 1. 数値を分割します。$1$に$n$2 つの連続した半分に分けます。 

目的は、値を分離して、単調なサブシーケンス内で大きなジャンプが強制されるようにすることです。 
2. 後半のすべての要素を昇順に出力します。 

これにより、より小さい値が順列の後半に出現し、長い増加チェーンが切断されます。 
3. 次に前半のすべての要素を昇順に出力します。 

これにより、内部順序は維持されますが、以前の増加構造を拡張することはできなくなります。 
4. 結果のシーケンスを順列として返します。 

重要な考え方は、各半分内の順序は単調ですが、半分間の全体的な移行により値の範囲に不連続性が生じるということです。 増加するサブシーケンスは、値のギャップにより増加を強制的にリセットされる前に、最大 1 つの連続した値のブロックを取ることができます。 

### なぜ効果があるのか

 この構造では、値の分離が強制されます。つまり、後半のすべての要素は前半のすべての要素よりも大きくなりますが、シーケンスの前半に表示されます。 この値の順序と位置の順序の逆転により、長い単調サブシーケンスが両方の半分にまたがることが防止されます。 結果として、LIS と LDS は両方とも、ほぼ半分のサイズに制限されます。これは、単一の分割構造で達成可能な最小スケールです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

left = list(range(1, n // 2 + 1))
right = list(range(n // 2 + 1, n + 1))

# print right half first, then left half
res = right + left

print(*res)
```このコードは、上で説明した構造を直接実装します。 分岐点は、$n // 2$、両方の半分は昇順に保たれます。 右半分が最初に出力されるのは、より大きな値が順列の早い段階で現れるようにするためです。これは、単調サブシーケンスを制限する重要な構造反転です。 

困難は計算ではなく、LIS と LDS の両方を同時に最小化するには 1 つの分割で十分であることを認識することにあるため、構築は意図的に単純になっています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    left = list(range(1, n // 2 + 1))
    right = list(range(n // 2 + 1, n + 1))
    res = right + left
    return " ".join(map(str, res)).strip()

# provided samples
assert run("4\n") in ["3 4 1 2", "2 1 3 4"]  # both valid constructions exist

# custom cases
assert run("1\n") == "1"
assert run("2\n") == "2 1"
assert run("3\n") in ["2 3 1", "3 1 2"]
assert run("5\n") == "3 4 5 1 2"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 のために$n = 1$の場合、この構造は単一要素の順列を生成するため、LIS と LDS は両方とも 1 になり、合計は自明に最小になります。 

のために$n = 2$、分割すると左 = [1]、右 = [2] となり、[2,1] が生成されます。 順番に増加するペアが存在しないため、LIS は 1 になりますが、シーケンス全体が減少しているため、LDS は 2 になります。 どの順列も合計が 3 でなければならないため、これが最適です。 

小さな奇数の場合$n$、分割により不均等な半分が作成されますが、同じ原理が当てはまります。 のために$n = 3$の場合、[2,3,1] が得られます。ここで、LIS は 2、LDS は 2 です。構造上の破損によって全長の単調サブシーケンスが妨げられるため、不均衡は正確さに影響しません。 

大型の場合$n$、同じ推論がスケールします。増加するサブシーケンスを境界を越えて拡張しようとする試みは失敗します。これは、後半の値が先に配置され、単調増加のリセットが強制されるためです。
