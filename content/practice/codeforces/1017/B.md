 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられています。 最初の文字列内の任意の 2 つの位置を選択して、それらのビットを交換することができます。 2番目の文字列は固定されたままになります。 各スワップの後、2 つの文字列のビット単位の OR を位置ごとに再計算し、元の結果と比較して異なる OR 結果が得られたスワップの数をカウントしたいと考えています。 

キー オブジェクトは OR 文字列で、位置的に両方の入力に依存します。 各インデックスでは、2 つのビットの少なくとも 1 つが 1 であれば OR は 1 になり、それ以外の場合は 0 になります。最初の文字列のみが変更されるため、OR が変更される唯一の方法は、スワップ後に何らかの位置が 0 または 1 に寄与するかどうかが反転する場合です。 

制約 n は 100000 まで大きくすることができ、位置のすべてのペアを明示的にチェックするソリューションは除外されます。 すべてのスワップにわたる 2 次スキャンには、最悪の場合でも約 10^10 の操作が必要になりますが、これは 2 秒で実行可能な量をはるかに超えています。 これにより、スワップをシミュレートするのではなく、パターンをカウントすることに問題を縮小する必要があります。 

ローカルで考えると微妙な問題が見えてきます。 スワップは正確に 2 つの位置に影響しますが、OR は両方の文字列に依存するため、2 番目の文字列によってすでに OR が 1 に強制されている場合、1 つの位置での変更は無関係になる可能性があります。 これにより、ビットの交換によって最初の文字列が変更されたように見えても、実際には OR が変更されないケースが発生します。 

小さな特殊なケースがこれを示しています。 ある位置 b に 1 があるとします。その場合、a で何が起こっているかに関係なく、その位置の OR は常に 1 になります。 したがって、b が 1 である位置内でビットを移動しても、たとえ a が大幅に変化したとしても、OR にはまったく影響しない可能性があります。 変更によってそのようなスワップが誤ってカウントされるかどうかを確認するだけの単純な解決策です。 

もう 1 つのエッジ ケースは、a 内の同一ビットを交換することです。 位置が変わっても文字列は変わらないので、OR は同一のままです。 これらのスワップはカウントしてはなりません。 

## アプローチ

 ブルートフォース手法では、インデックス i と j のすべてのペアを試し、文字列のコピーで交換を実行し、OR 文字列を再計算して、元の文字列と比較します。 各 OR の再計算には O(n) がかかるため、合計の複雑さは O(n^3) になります。 ローカルで再計算を最適化しても依然として O(n^2) が残り、これは 10^5 には遅すぎます。 

重要な観察は、スワップは 2 つのポジションにのみ影響するため、これら 2 つのポジションが OR 寄与を変更するかどうかだけを理解する必要があるということです。 各インデックス i での OR は、a[i] と b[i] に依存します。 b[i] が 1 の場合、OR は a[i] に関係なく永続的に 1 になります。 これは、そのような位置が a の変化の影響を受けないことを意味します。 

b[i] が 0 の場合、その位置の OR は a[i] と正確に等しくなります。 これらは、a 内のビットの交換によって OR の結果が変更される唯一の位置です。 

したがって、問題は、a のビットを交換することにより、b[i] = 0 の少なくとも 1 つの位置の値が反転するインデックスのペアをカウントすることに帰着します。 単純化すると、これは、a 内に全体で 0 と 1 がいくつ存在するか、および b が 1 である位置にそれらの 0 と 1 がいくつ存在するかのみに基づく組み合わせ計数問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) 以上 | O(n) | 遅すぎる |
 | 最適な計数 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 番目の文字列に基づいてインデックスを 2 つのカテゴリに分類します。 b[i] = 1 の位置は、a に何が含まれているかに関係なく、OR 値が常に 1 に固定されるため、特別です。 b[i] = 0 となる位置は a に完全に依存します。

1. a の 0 と 1 の合計数を数えます。 これらは、ビットの配置を変更できるスワップの数を決定します。 
2. 位置を 2 つのグループに分割します。b[i] = 1 のグループと b[i] = 0 のグループです。最初のグループでは、a の変更は OR の結果にまったく影響しません。 2 番目のグループでは、ビットを反転すると、その位置の OR が直接変更されます。 
3. a 内の異なるビットを持つインデックスのすべてのペアを考慮します。 これらのスワップのみが、a のビットのマルチセットを実際に変更します。 このようなペアの数は、a 内の 0 の数と 1 の数を掛けたものです。 
4. b[i] = 1 グループ内に完全に含まれるペアを減算します。これは、そのグループ内で交換しても OR 値が変更されることがないためです。 これらの位置のうち、等しいビットを交換しても何も起こらないため、減算の対象となるのは 0 と 1 の間の交換のみです。 
5. 最終的な答えは、a 内のゼロ-1 ペアの合計から、b[i] = 1 の位置の完全に内側にあるゼロ-1 ペアを差し引いたものになります。 

結果は、位置やシミュレーションではなく、単純なカウントのみに依存します。 

### なぜ効果があるのか

 すべてのスワップでは、正確に 2 つの位置のビットが保持または反転されます。 OR 文字列は、b[i] = 0 である少なくとも 1 つの位置が対応する a ビットを変更する場合にのみ、元の文字列と異なることができます。 b[i] = 1 の位置は、常に 1 を出力するシンクとして機能するため、正確さに影響を与えることはできません。 これにより、問題は、0/1 の差を少なくとも 1 つの敏感な位置に移動するスワップの回数を数えるということになります。 減算により、影響を受けない位置に限定されているスワップが正確に削除され、カウントされた各スワップが真に OR を変更することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().strip()
    b = input().strip()

    total_zeros = a.count('0')
    total_ones = n - total_zeros

    z1 = o1 = 0

    for i in range(n):
        if b[i] == '1':
            if a[i] == '0':
                z1 += 1
            else:
                o1 += 1

    ans = total_zeros * total_ones - z1 * o1
    print(ans)

if __name__ == "__main__":
    solve()
```異なるビット間の交換のみが重要であるため、このソリューションでは、まず最初の文字列にいくつの 0 と 1 が存在するかを計算します。 次に、2 番目の文字列によって OR が常に 1 になるように強制されるインデックスのサブセットに焦点を当てます。そのサブセット内で、a に 0 と 1 がいくつ存在するかをカウントします。これは、それらの間の交換によって OR が変更されることがないためです。 

この減算により、完全に安全領域に含まれるスワップが正確に削除され、少なくとも 1 つの意味のある OR 変更を引き起こすスワップのみが残ります。 

## 実用的な例

 ### 例 1

 入力:```

01011
11001
```合計を計算します。 a には 0 = 2 と 1 = 3 があるため、異なるペアの合計は 6 になります。 

次に、b = 1 の位置に注目します。それらの中で、a に z1 = 1 個のゼロと、o1 = 2 個の 1 があるとします。 これらの内部スワップにより、2 つの無効なペアが発生します。 

| ステップ | 合計ゼロ | 総数 | z1 | o1 | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | イニシャル | 2 | 3 | - | - | - |

 これは予想される出力と一致します。 トレースは、少なくとも 1 つの b=0 位置を含むスワップ、または安全領域外で不均衡を生じさせるスワップのみが問題であることを示しています。

| ステップ | 合計ゼロ | 総数 | z1 | o1 | 結果 |

 ## 特殊なケース

 b のすべての位置が 1 の場合、OR は a での交換に関係なく、常にすべて 1 の文字列になります。 このアルゴリズムは配列全体で z1 と o1 をカウントします。すべてのスワップは安全領域内で発生するため、減算によって合計の 0-1 ペアがキャンセルされ、正しく 0 が生成されます。 

b のすべての位置が 0 の場合、すべての位置が敏感であるため、z1 と o1 は両方とも 0 になります。 この式は、a 内の合計 0-1 ペアに帰着します。これにより、配置を変更し、したがって OR を変更するすべてのスワップが正しくカウントされます。 

a にすべて同一のビットが含まれている場合、合計 0 または合計 1 は 0 なので、スワップによって a を変更することはできません。 積項はゼロになり、b に関係なく答えは正しくゼロになります。
