 ## 解決策
 ## 問題の理解

 私たちは、頂点 1 がルートであり、すべてのノードが最初は白に着色されているルート付きツリーを操作しています。 時間の経過とともに、色を反転する、ツリーの一部をリセットする、またはノードの現在の色を尋ねる 3 種類の操作を適用します。 

最初の操作は最も珍しいものです。頂点を黒に着色しようとすると、頂点が現在白である場合にのみ成功します。 すでに黒になっている場合は、停止したり失敗を報告したりしません。 代わりに、同じ操作をそのすべての子にリダイレクトし、そこで同じルールを繰り返します。 これにより、白いノードが見つかるまで作業を下方向に押し出すカスケード動作が作成されます。 

2 番目の操作はより簡単です。 これにより、サブツリー全体が強制的に白になり、サブツリー内の以前の黒いマーキングがすべて消去されます。 

3 番目の操作は、指定された頂点が現在黒であるか白であるかを尋ねるポイント クエリです。 

主な難点は、操作が 1 つのノードから多くの再帰的試行に拡張される可能性があり、この拡張は、リセットや以前の操作によって動的に変化するツリーの現在の状態に依存することです。 

この制約により、最大 100,000 個のノードと 100,000 個のクエリが許可されます。 これにより、最悪の場合、各操作のツリーを 1 つずつ明示的にたどるソリューションは即座に排除されます。 動作中に繰り返されるリダイレクトの単一チェーンは、ほぼすべてのノードに接触するようになり、クエリ間で繰り返されるため、二次関数になります。 

単純な DFS ベースのシミュレーションも失敗します。これは、サブツリーのリセットが再計算を無効にする形で以前の色の状態と相互作用するためです。 

すでに完全に黒になっているサブツリーに対して操作 1 が繰り返し呼び出される場合、微妙なエッジ ケースが発生します。 たとえば、チェーン 1 → 2 → 3 があり、すべてが黒の場合、ノード 1 で操作 1 を適用すると、リーフに到達するか子がなくなるまで操作が押し下げられ続けます。 単純な実装では、停止が早すぎるか、ノードを誤って再訪問する可能性があります。 

サブツリーが頻繁にリセットされると、別の特殊なケースが発生します。 サブツリーをリセットし、すぐにそのサブツリーにカスケード操作を適用する場合は、補助構造に保存されている古い「黒」状態に依存しないようにする必要があります。 

## アプローチ

 直接シミュレーションでは、すべてのノードの色が維持され、ツリーを走査することによって各操作が実行されます。 操作 2 は、サブツリーを介して DFS によって実行できます。 操作 1 は、ノードを繰り返しチェックし、必要に応じて子に降りることで実行できます。 

これは正しく動作しますが、問題はコストです。 最悪の場合、単一の操作 1 が長いチェーンまたは多くの分岐を横断する可能性があり、操作 2 が大きなサブツリー内のすべてのノードに触れる可能性があります。 クエリが 100,000 件になると、制限をはるかに超える 10¹⁰ オペレーション程度の最悪の動作が発生します。 

重要な観察は、2 つのアイデアを効率的にサポートする構造が必要であるということです。 まず、「ノードをアクティブ化するか、すでにアクティブな場合はアクティブ化を下方にプッシュする」をサポートする必要があります。 次に、以前のアクティブ化を迅速に無効にするサブツリーのリセットをサポートする必要があります。 

この組み合わせは、範囲割り当てとポイント クエリをサポートするデータ構造と組み合わせたツリーのオイラー ツアー表現を強く示唆しています。 ただし、操作 1 は現在の状態に基づいて条件付きで降下するため、標準の更新ではありません。 

重要な洞察は、黒いノードを動的なセットとして扱い、ノードごとに、アクティブ化しようとしたときにサブツリー パス内の次の白いノードをすぐに見つけられる機能を維持することです。 これは、ノードが現在白か黒かを追跡するオイラー順序によるセグメント ツリーを使用して自然に処理され、白への範囲割り当てと黒へのポイント更新がサポートされます。

「子へのプッシュ」動作を効率的に処理するために、すべての子を明示的に走査する必要がないことがわかります。 代わりに、黒いノードをアクティブにしようとするときに、サブツリー内の最初の白いノードを繰り返し見つけます。 これは、ノードが白かどうかを格納するセグメント ツリーを維持し、範囲内で値 1 を持つノードの検索をサポートすることでサポートできます。 

したがって、操作 1 は、「サブツリーで次の白いノードを見つけて黒にマークする」の繰り返しとなり、関連するパスに何も存在しない場合は停止します。 

これにより、カスケード DFS が対数クエリの繰り返しに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース DFS シミュレーション | O(nq) 最悪の場合 | O(n) | 遅すぎる |
 | 次の白のクエリを使用したオイラー ツアー + セグメント ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをルート化し、各サブツリーが連続したセグメントに対応するようにオイラー ツアーを計算します。 

次に、このオイラー配列に対してセグメント ツリーを構築します。ここで、各位置には、対応するノードが現在白であるかどうかが格納されます。 

また、オイラー インデックスをノード ラベルにマッピングする配列も維持します。 

### ステップ

 1. ルートから DFS を実行してエントリ時間を計算します`tin[v]`そして退出時間`tout[v]`。 

これにより、すべてのサブツリーが連続したセグメントになります。`[tin[v], tout[v]]`。 
2. セグメントツリーを構築します`[1, n]`すべて 1 に初期化され、すべてのノードが白になります。 
3. 操作タイプ 3 (クエリ) を処理するには、位置の現在値を確認するだけです。`tin[v]`。 1 の場合、ノードは白、それ以外の場合は黒です。 
4. 操作タイプ 2 (サブツリーを白でペイント) を処理するには、1 オーバーの範囲割り当てを適用します。`[tin[v], tout[v]]`。 

これにより、サブツリー内のすべてのノードが対数時間で白色に復元されます。 
5. 操作タイプ 1 を処理するには、次の操作を繰り返し実行します。 

をルートとするサブツリー内の白いノードを検索します。`v`。 存在しない場合は停止します。 

それ以外の場合は、そのノードを黒としてマークし、繰り返します。 

子を歩く代わりに白いノードを検索する理由は、「黒の場合は子に行く」というルールが事実上、すでにアクティブ化されたノードをスキップし、有効な候補が見つかるまでさらに深く進むことを意味するためです。 
6. オイラー指数で白いノードを見つけるたびに`i`、黒に設定してプロセスを続行します。 検索は常にサブツリー間隔に制限され、正確性が保証されます。 

### なぜ効果があるのか

 重要な不変条件は、セグメント ツリーが常にノードの正確な現在のカラーリングをオイラー順に反映することです。 すべてのサブツリー操作は連続セグメントの更新に対応し、すべてのクエリは直接検索に対応します。 

操作 1 では、セグメント ツリーは常に正しい存在クエリを返すため、サブツリー間隔内の有効な白いノードをスキップすることはありません。 ノードが黒にマークされると、サブツリーがリセットされて白に戻されるまで、そのノードは再び戻されることはありません。 これは、反復降下のセマンティクスと正確に一致します。各黒いノードは永続的にバイパスされ、処理時にまだ白いノードのみに落ち着きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.tree = [0] * (2 * self.size)

    def build(self):
        for i in range(self.size):
            self.tree[self.size + i] = 1
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = self.tree[2*i] + self.tree[2*i+1]

    def point_set(self, i, val):
        i += self.size
        self.tree[i] = val
        i //= 2
        while i:
            self.tree[i] = self.tree[2*i] + self.tree[2*i+1]
            i //= 2

    def range_set(self, l, r):
        # set all to 1 in range via naive segment tree recursion
        self._range_set(1, 0, self.size - 1, l, r)

    def _range_set(self, v, tl, tr, l, r):
        if l > r:
            return
        if l == tl and r == tr:
            self.tree[v] = (tr - tl + 1)
            return
        tm = (tl + tr) // 2
        self._range_set(v*2, tl, tm, l, min(r, tm))
        self._range_set(v*2+1, tm+1, tr, max(l, tm+1), r)
        self.tree[v] = self.tree[v*2] + self.tree[v*2+1]

    def find_white(self, l, r):
        return self._find(1, 0, self.size - 1, l, r)

    def _find(self, v, tl, tr, l, r):
        if l > r or self.tree[v] == 0:
            return -1
        if tl == tr:
            return tl
        tm = (tl + tr) // 2
        res = -1
        if l <= tm:
            res = self._find(v*2, tl, tm, l, min(r, tm))
        if res == -1 and r > tm:
            res = self._find(v*2+1, tm+1, tr, max(l, tm+1), r)
        return res

n, q = map(int, input().split())
g = [[] for _ in range(n+1)]
parent = list(map(int, input().split()))
for i, p in enumerate(parent, start=2):
    g[p].append(i)

tin = [0]*(n+1)
tout = [0]*(n+1)
timer = 0

def dfs(v):
    global timer
    tin[v] = timer
    timer += 1
    for to in g[v]:
        dfs(to)
    tout[v] = timer - 1

dfs(1)

st = SegTree(n)
st.build()

for _ in range(q):
    t, v = map(int, input().split())
    if t == 1:
        while True:
            idx = st.find_white(tin[v], tout[v])
            if idx == -1:
                break
            st.point_set(idx, 0)
    elif t == 2:
        st.range_set(tin[v], tout[v])
    else:
        print("black" if st.tree[st.size + tin[v]] == 0 else "white")
```DFS セクションはオイラー順序付けを構築するため、サブツリー クエリは間隔演算になります。 セグメント ツリーはノードごとにバイナリ状態を保存します。1 は白、0 は黒を意味します。 

操作 1 では、サブツリー間隔内の白いノードを繰り返し検索し、それを黒に反転します。 これは、隣接リストを明示的に走査することなく、「黒いノードをスキップして子に移動」ルールを直接シミュレートします。 

操作 2 では、範囲の割り当てを実行して白を復元します。 これは、単純な再帰的なセグメント ツリー更新で実装されます。 

操作 3 では、ノードに対応するリーフ値を読み取ります。 

微妙な点は、ここでのセグメント ツリーは遅延伝播システムではなく、動的な存在構造として使用されていることです。 正確性は、ツリー構造を直接クエリするのではなく、一貫したオイラー インデックスを常にクエリして更新することに依存します。

 ## 特殊なケース

 重要なエッジ ケースは、操作 1 を適用する前にすべてのノードがすでに黒になっている長いチェーンです。 その場合、アルゴリズムはセグメント ツリーに繰り返しクエリを実行しますが、白いノードが見つからないため、ノードをループせずにすぐに終了します。 これにより、不必要なトラバースが防止されます。 

もう 1 つのエッジ ケースは、重複領域でサブツリー リセットが繰り返されることです。 リセットのたびにセグメント ツリーの範囲が上書きされて 1 に戻るため、以前の黒の状態は完全に破棄され、後続のクエリは最新の割り当てのみに依存します。 

3 番目のエッジ ケースは、子を持たないノードで、黒である間に操作 1 が適用されます。 検索はシングルトン間隔ですぐに失敗し、無効な降下は発生せず、「子が存在しないということは停止を意味する」という意図された動作と一致します。
