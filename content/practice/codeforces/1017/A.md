 ## 解決策
 ## 問題の理解

 私たちには学生のクラスが与えられ、各学生は 1 から始まる一意の整数 ID によって識別されます。各学生は、異なる科目に対応する 4 つの試験の得点を持っています。 このタスクは、4 つの科目の合計スコアによってすべての生徒をランク付けすることです。 合計スコアが高いほど、ランクが高くなります。 2 人の生徒の合計スコアが同じ場合、ID が小さい生徒に高いランクを与えることで同点が解消されます。 

必要な出力は、ID 1 の生徒、トーマスのランクです。 ランクは、このソート順における 1 から始まる位置として定義されます。 

制約は小さく、学生数は最大でも 1000 人です。 これは、O(n²) アプローチが完全に適切であり、単純な並べ替えベースの O(n log n) ソリューションでさえやり過ぎではあるものの、クリーンで安全であることがすぐにわかります。 単純な集計と順序付け以外の最適化は必要ありません。 

この問題の主な微妙な点は、タイブレーク ルールです。 合計が等しい場合に小さい ID が勝つことを忘れると、トーマスを同じスコアを持つ誰かの後ろに誤って配置する可能性があります。 もう 1 つの微妙な点は、ランクは、誤って並べ替えた後にのみ厳密に高いスコアを持つ人の数ではなく、最終的に並べ替えられたリスト内の位置に依存することです。 タイを正しく処理せずに、厳密に高い合計のみをカウントする単純な実装は失敗します。 

具体的な失敗例は、トーマスが複数の生徒と同じスコアを持っている場合に発生します。 トーマスと生徒 5 の合計が 400 で、生徒 2 の合計が 401 であるとします。ID が小さいため、正しいランキングでは生徒 2 が最初に配置され、次にトーマスが生徒 5 の前に配置されます。 ID のタイブレークを無視すると、トーマスのランクが 2 ではなく 3 と誤って計算される可能性があります。 

## アプローチ

 この問題を考える最も簡単な方法は、各生徒の合計スコアを計算し、説明されているルールに従ってすべての生徒を並べ替えることです。 分類後、トーマスの位置を特定し、位置を読み取ります。 

強引なアプローチは、すべての生徒を繰り返しスキャンし、まだ選ばれていない次善の候補者を選択することです。 これは選択の並べ替え動作を模倣します。 各選択ステップには O(n) 回のスキャンが必要であり、それを n 回実行するため、O(n²) 回の操作が行われます。 n が最大 1000 の場合、これは約 100 万回の比較となり、それでも許容できますが、不要です。 

より直接的なアプローチは、すべての合計を計算し、ID とともに保存し、Python の組み込みソートを使用してソートすることです。 重要な洞察は、ランキング順序が 1 つのキー、つまり負の合計スコア (降順の場合)、次に ID (昇順の場合) によって完全に決定されるということです。 これにより、問題は標準的な並べ替えタスクに変換されます。 

並べ替えると、トーマスのランクは並べ替えられたリスト内のインデックスに 1 を加えたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースセレクション | O(n²) | O(n) | 承認済み |
 | キーで並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 生徒の数を読み取り、スコアを保存します。 
2. 各生徒について、4 つの科目のスコアの合計を計算します。 これにより、各生徒は単一の比較可能な値に減ります。 
3. 各生徒を負の合計と ID からなるペアとして保存します。 負の値は、昇順で並べ替えるとスコアの降順が生成されるようにするために使用されます。 
4. 学生のリストを並べ替えます。 ID がタプルに含まれているため、ソートでは 2 番目のルールが自動的に適用されます。 
5. ソートされたリストをスキャンして、ID 1 に対応するエントリを見つけます。 
6. 1 からの位置をランクとして出力します。 

これが機能する理由は、タプルによるソートが辞書編集的な順序付けを強制するという事実に基づいています。 タプル (-sum, id) により、大きい合計が最初に来て、等しい合計の中で小さい ID が最初に来るようになります。 すべての生徒が 1 回だけ代表され、順序付けが全体的かつ一貫しているため、ソートされたリストはまさに必要なランキングになります。 したがって、このリストにおけるトーマスの位置は、彼の正しいランクです。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    students = []

    for i in range(1, n + 1):
        a, b, c, d = map(int, input().split())
        total = a + b + c + d
        students.append((-total, i))

    students.sort()

    for idx, (_, sid) in enumerate(students, start=1):
        if sid == 1:
            print(idx)
            return

if __name__ == "__main__":
    main()
```このソリューションは、各タプルが両方のランキング基準をエンコードするタプルのリストを構築します。 並べ替えステップではすべての順序付けロジックが処理されるため、手動による比較ミスが回避されます。 最後のループは ID 1 のみを検索しますが、制約が小さいため安全です。 

よくある間違いは、ソートキーに ID を含めるのを忘れることです。 これがないと、同じスコアが任意の順序で表示され、ランクの定義が崩れる可能性があります。

 ## 特殊なケース

 すべての学生の合計スコアが同じである場合、ランキングは ID の順序に完全に依存します。 たとえば、3 人の学生が全員 40 点の場合、並べ替え順序は ID 1、2、3 でなければなりません。トーマスは常に同等の中で 1 位であるため、彼のランクは 1 になります。ID はタプルの 2 次キーであるため、アルゴリズムはこれを正しく処理します。 

Thomas のスコアが最も低い場合、ソートされたリストの最後に表示されるはずです。 たとえば、トーマスの合計が 10 で、他のメンバーが 20 と 30 の場合、ソート順序は 30、20、10 となり、ランク 3 に配置されます。ソート キーにより、特別な処理を行わなくても自然にこれが保証されます。これは、-10 が -30 および -20 より大きいため、トーマスは順序の後ろに押し出されます。
