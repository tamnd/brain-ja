 ## 問題の理解

 1 から 1 までのすべての整数の数論的な合計を評価するように求められます。$n$ここで、各整数は素因数分解によって定義された値に寄与します。 

数字の場合$x$、素数の積として因数分解します。$x = \prod p_i^{a_i}$。 関数$f$は整数で定義され、この問題では常に 3 次多項式になります。$f(x) = Ax^3 + Bx^2 + Cx + D$。 の貢献$x$の合計です$f(p)$すべての素因数にわたって$p$、多重度でカウントされます。 言い換えれば、素数が出現するたびに、$p$因数分解で$x$追加します$f(p)$の値に$x$。 

このタスクは、1 から 2 までのすべての数値の合計寄与度を計算することです。$n$、モジュロ$2^{32}$。 

問題を再構成する有効な方法は、合計を逆にすることです。 数値を反復して因数分解する代わりに、各素数が範囲全体で何回寄与するかを考えることができます。 素数が出現するたびに$p$数字で$i$貢献する$f(p)$したがって、次の数までのすべての数値の因数分解に各素数が現れる合計回数が必要です。$n$。 

制約$n \le 3 \cdot 10^8$数値ごとの因数分解を除外します。 平$O(n \log n)$大きすぎます。 もっと近いものが必要です$O(\sqrt{n})$またはそれ以上の場合、通常は主要な寄与を合計してカウントすることに依存します。 

微妙なエッジケースは定数項です$D$。 すべての数字以来$x$貢献する$D$素因数が発生するたびに、小さな素因数を多く含む数値は大きな定数寄与を蓄積します。 もう 1 つのエッジ ケースは、素数のべき乗です。寄与は、素数が数値を割るかどうかだけではなく、指数の数に依存します。 

単純な間違いは、各数値を 1 つのみの寄与として扱うことです。$f(p)$多重度ごとではなく、個別の素数ごとに。 例えば、$12 = 2^2 \cdot 3$貢献する$2f(2) + f(3)$、 ない$f(2) + f(3)$。 別の障害モードは、すべての整数を因数分解しようとします。$n$、この規模では実現不可能です。 

## アプローチ

 直接的なアプローチは、すべての整数を反復処理することです。$i \le n$、それを因数分解し、その素分解からの寄与を合計します。 これは概念的には簡単です。因数分解により指数が得られ、累積されます。$a \cdot f(p)$各素数ごとに。 ただし、各数値を個別に因数分解するには、少なくとも$O(\sqrt{i})$単純な実装では数値ごとに計算され、おおよその結果が得られます。$O(n\sqrt{n})$、これは実現不可能です$n = 3 \cdot 10^8$。 

ふるいを使用しても、最大の最小素因数を事前に計算します。$n$制約によりメモリ内に保存することは不可能であり、完全な SPF 配列を保存するだけでも 16 MB の制限を超えます。 

重要な観察は、実際には個々の因数分解が必要ないということです。 それぞれの素数に対して必要なのは、$p$、すべての整数にわたって出現する合計回数。$n$。 その合計は、まさに次の累乗の合計です。$p$: の倍数$p$, の倍数を加えたもの$p^2$、 等々。 

固定素数の場合$p$、すべての数値にわたる指数の寄与は次のとおりです。$$\sum_{k \ge 1} \left\lfloor \frac{n}{p^k} \right\rfloor$$これは標準的な評価計算の恒等式であり、次の値で割り切れるすべての数値です。$p^k$少なくとも貢献する$k$すべてのレベルにわたって発生し、フロアを合計すると多重度が正しく累積されます。 

したがって、合計の答えは次のようになります。$$\sum_{p \le n, p \text{ prime}} f(p) \cdot \sum_{k \ge 1} \left\lfloor \frac{n}{p^k} \right\rfloor$$までの素数がまだ必要です$n$が、保管はしておりません。 代わりに、セグメント化されたふるい、または以下で機能する修正されたプライム列挙を使用します。$O(\sqrt{n})$ふるいにかけるだけで記憶$\sqrt{n}$そしてオンデマンドで候補者をテストします。 

3次多項式$f(p)$素数ごとに直接評価され、すべての算術演算はモジュロで実行されます。$2^{32}$つまり、自然な 32 ビット オーバーフロー演算で十分です。

 ## アルゴリズムのチュートリアル

 1. 以下のすべての素数を事前計算します。$\sqrt{n}$簡単なふるいを使って。 これまでの複合材料であればこれで十分です。$n$を超えない素因数を持つ$\sqrt{n}$、そして、これらの素数は、より大きな数の素数性をテストするためにのみ必要です。 
2. 2 から 2 までのすべての整数を反復処理します。$n$、ただし、それらを完全に因数分解するわけではありません。 代わりに、事前に計算された素数を使用して素数性をテストします。 数値が素数の場合、その数値は寄与プールに追加されます。 
3. 各素数について$p$、以下のすべての数値にわたる合計の指数寄与を計算します。$n$繰り返し除算を使用する: から始める$t = p$を繰り返して蓄積していきます。$\lfloor n / t \rfloor$、次に乗算します$t$による$p$それまで$t > n$。 
4. この指数の合計に次の値を掛けます。$f(p)$、次のように計算されます$A p^3 + B p^2 + C p + D$、そしてそれをグローバル応答モジュロに追加します$2^{32}$。 
5. すべての貢献を蓄積し、最終結果を返します。 

重要な推論ステップは、指数カウントによって乗法分解問題が割り算レベルにわたる合計に変換され、各整数を個別に検査する必要がなくなるということです。 

### なぜ効果があるのか

 素数が出現するたびに$p$までの数値の因数分解で$n$ペアで一意に表現されます$(x, k)$どこ$p^k \mid x$この発生は 1 回に 1 回だけカウントされます。$\lfloor n / p^k \rfloor$。 全体をまとめると$k$より高い累乗は独立したイベントではなく入れ子になった寄与を表すため、過剰カウントすることなくすべての多重度を集計します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, B, C, D = map(int, input().split())

    MOD = 2**32

    if n == 1:
        print(0)
        return

    limit = int(n**0.5) + 1
    is_prime = [True] * (limit + 1)
    is_prime[0] = is_prime[1] = False

    primes = []
    for i in range(2, limit + 1):
        if is_prime[i]:
            primes.append(i)
            for j in range(i * i, limit + 1, i):
                is_prime[j] = False

    # We still need to consider primes > sqrt(n)
    # We'll test them by trial division using small primes

    def is_prime_big(x):
        if x <= limit:
            return is_prime[x]
        for p in primes:
            if p * p > x:
                break
            if x % p == 0:
                return False
        return True

    ans = 0

    # handle small primes
    for p in primes:
        if p > n:
            break

        t = p
        exp_sum = 0
        while t <= n:
            exp_sum += n // t
            t *= p

        fp = (A * p * p * p + B * p * p + C * p + D) % MOD
        ans = (ans + fp * exp_sum) % MOD

    # handle large primes (between sqrt(n) and n)
    for x in range(limit, n + 1):
        if x < 2:
            continue
        if is_prime_big(x):
            p = x
            t = p
            exp_sum = 0
            while t <= n:
                exp_sum += n // t
                t *= p

            fp = (A * p * p * p + B * p * p + C * p + D) % MOD
            ans = (ans + fp * exp_sum) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この解決策は、素数を 2 つのグループに分割します。$\sqrt{n}$、ふるいによって生成される、および上記のもの$\sqrt{n}$、トライアル部門によって検出されました。 各素数について、繰り返し除算を使用してその合計多重度寄与を計算します。これにより、整数の列挙が回避されます。 

微妙な実装ポイントは乗算です。$t *= p$。 これは指数関数的に増加するため、内側のループのみが実行されます。$O(\log_p n)$これにより、計算が管理しやすくなります。 

もう 1 つの重要な詳細は、すべての算術演算がモジュロで計算されることです。$2^{32}$。 Python では、Python の整数は自然にオーバーフローしないため、これを明示的にシミュレートします。

 ## 特殊なケース

 エッジケースの 1 つは、$n = 1$、ここで素数は存在せず、合計はゼロでなければなりません。 プライムループが実行されないため、アルゴリズムは正しく早期に戻ります。 

もう 1 つのエッジ ケースは、次のような大きな素数です。$n$ここで、指数の合計は正確に 1 です。たとえば$n = 10$, 素数 7 は 1 回だけ貢献します。 内側のループはすぐに停止します。$p^2 > n$、過剰カウントがないことを保証します。 

3 番目のエッジ ケースは、次のような小さな素数の高いべき乗です。$p = 2$そして$n = 3 \cdot 10^8$。 ループオーバー$t = p^k$約 28 回の反復後に安全に終了し、各層はオーバーフローや欠落なしに正しいフロア寄与を蓄積します。
