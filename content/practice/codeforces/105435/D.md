 ## 解決策
 ## 問題の理解

 各テスト ケースには文字列が与えられており、特定の複数の文字セットを含む連続した部分文字列を見つける必要があります。 必須の文字は「ハードワーク」という単語に対応しますが、単語自体の通常の頻度パターンには対応しません。 代わりに、部分文字列に h、a、d、w、o、k の各文字が少なくとも 1 つ含まれていること、そして重要なことに r が 2 回出現することを確認する必要があります。 

したがって、このタスクは単語を一致させることではなく、固定頻度要件 (h × 1、a × 1、d × 1、w × 1、o × 1、k × 1、r × 2) を満たす文字列内で最小のウィンドウを見つけることです。 

各テストの出力は、そのような部分文字列の最小長、またはこれらの制約を満たす部分文字列がない場合は -1 です。 

入力サイズは、テストごとに最大 10^5 文字、最大 1000 テストに達します。 これは、すべての部分文字列を明示的にチェックするソリューションは遅すぎることを直ちに意味します。 最悪の場合の入力サイズはテスト全体で 10^8 文字に達する可能性があるため、テストごとの 3 次または 2 次スキャンは許容範囲をはるかに超えます。 

テストごとに線形または線形に近いアプローチが必要です。これは、文字列全体にわたるスライディング ウィンドウ戦略を強く示唆しています。 

覚えておく価値のある微妙な失敗例がいくつかあります。 1 つは、文字列に必要な文字がすべて含まれているものの、r が十分に出現しない場合です。 たとえば、「hardwok」には r が完全に欠落しているため、ほとんどの文字が表示されているにもかかわらず、答えは -1 になります。 もう 1 つのケースは、「harrdwok」など、r が文字列全体に 1 回しか出現しない場合ですが、それでも失敗します。 さらに微妙な問題は、有効なウィンドウが複数存在する可能性があり、アルゴリズムは最初の有効なセグメントで停止するのではなく、重複する有効なセグメント間の最小長を正確に追跡する必要があることです。 

## アプローチ

 ブルートフォース手法では、考えられるすべての部分文字列を考慮し、それが必要な数を満たしているかどうかをチェックします。 長さ n の文字列の場合、O(n²) 個の部分文字列があり、頻度表を維持する場合は各チェックに O(1)、再計算する場合は O(n) のコストがかかります。 最適な設定であっても、テストごとに O(n²) が発生しますが、n = 10^5 ではまったく実行不可能です。 

重要な観察は、この問題は古典的な固定要件の最小ウィンドウの問題であるということです。 パターンを検索しているのではなく、周波数制約を満たす最小の間隔を検索しています。 この構造により、2 ポインタ スライディング ウィンドウが可能になります。ウィンドウが有効になるまで右側の境界を拡張し、有効性を維持しながら左側の境界を縮小して長さを最小限に抑えます。 

重要な洞察は、有効性は展開に関して単調であるということです。ウィンドウに十分な文字が含まれると、さらに文字を追加しても有効性が損なわれることはありません。 この単調性により、各文字を最大 1 回追加および削除する単一パスが可能になります。

 ## アルゴリズムのチュートリアル

 ターゲット文字に必要な頻度マップを修正し、2 つのポインターで文字列をスキャンします。

1. 現在のウィンドウの周波数カウンタと、満たされる必要な条件の数を示すカウンタを初期化します。 また、ターゲット要件も定義します。h、a、d、w、o、k は少なくとも 1 回出現する必要があり、r は少なくとも 2 回出現する必要があります。 
2. 文字列上で右ポインタを移動し、現在の周波数マップに各文字を追加します。 更新ごとに、満たされる要件の数が増加する可能性があります。 たとえば、r の 2 回目の出現は、しきい値 2 に達した場合のみカウントされます。 
3. 展開するたびに、現在のウィンドウがすべての要件を満たしているかどうかを確認します。 頻度を再計算するのではなく満足度を段階的に追跡するため、このチェックは一定時間行われます。 
4. ウィンドウが有効になったら、左側から縮小してみます。 ウィンドウが有効なまま文字を 1 つずつ削除し、より小さい有効なウィンドウが見つかるたびに答えを更新します。 このステップにより、有効なウィンドウを見つけるだけでなく、現在の右ポインタで終わる最小のウィンドウを見つけることができます。 
5. ウィンドウが有効なときはいつでも左からローカルに最小化されるという不変条件を常に維持しながら、文字列の終わりまで右ポインタを展開し続けます。 
6. 有効なウィンドウが見つからない場合は、-1 を返します。 

重要な点は、r の要件を 2 回処理することです。 すべての文字を同等に扱う代わりに、r はその数が少なくとも 2 に達した場合にのみ有効性を持ちますが、他のすべての文字は少なくとも 1 回出現する必要があります。 

### なぜ効果があるのか

 右ポインタのすべての位置で、アルゴリズムはウィンドウが有効になるように可能な限り最小の左境界を維持します。 右ポインタは前方にのみ移動するため、現在の右ポインタまたはその前で開始される将来の有効なウィンドウは、右ポインタが終了位置に到達したときに検出されます。 左ポインタは前方にのみ移動するため、候補ウィンドウはスキップされません。 これにより、すべての有効なウィンドウが最小形式で 1 ​​回だけ考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

REQ = {'h': 1, 'a': 1, 'd': 1, 'w': 1, 'o': 1, 'k': 1, 'r': 2}

def is_valid(cnt):
    return (
        cnt['h'] >= 1 and
        cnt['a'] >= 1 and
        cnt['d'] >= 1 and
        cnt['w'] >= 1 and
        cnt['o'] >= 1 and
        cnt['k'] >= 1 and
        cnt['r'] >= 2
    )

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    cnt = {c: 0 for c in REQ}
    left = 0
    best = float('inf')

    for right in range(n):
        if s[right] in cnt:
            cnt[s[right]] += 1

        while left <= right and is_valid(cnt):
            best = min(best, right - left + 1)
            if s[left] in cnt:
                cnt[s[left]] -= 1
            left += 1

    print(-1 if best == float('inf') else best)
```このコードではダイレクト スライディング ウィンドウを使用しています。 辞書`cnt`有効性にとって重要な文字のみを追跡し、更新を一定時間に保ちます。 機能`is_valid`要件をチェックしますが、アルファベットが小さく固定されているため、チェックごとに O(1) のままです。 

内側の while ループは縮小フェーズです。有効性を維持しながら、左からの文字の破棄を繰り返し試行します。 有効性が切れた瞬間にループは停止し、右ポインタは展開を続けます。 

微妙な点の 1 つは、関連する 7 文字のみを追跡していることです。 他のすべては無視されます。これは、要件が満たされるかどうかには影響せず、ウィンドウの長さのみに影響するためです。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    REQ = {'h': 1, 'a': 1, 'd': 1, 'w': 1, 'o': 1, 'k': 1, 'r': 2}

    def is_valid(cnt):
        return (
            cnt['h'] >= 1 and cnt['a'] >= 1 and cnt['d'] >= 1 and
            cnt['w'] >= 1 and cnt['o'] >= 1 and cnt['k'] >= 1 and cnt['r'] >= 2
        )

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        cnt = {c: 0 for c in REQ}
        left = 0
        best = float('inf')

        for right in range(n):
            if s[right] in cnt:
                cnt[s[right]] += 1

            while left <= right and is_valid(cnt):
                best = min(best, right - left + 1)
                if s[left] in cnt:
                    cnt[s[left]] -= 1
                left += 1

        out.append(str(-1 if best == float('inf') else best))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての文字が表示されるが、2 番目の r が最後まで遅れる場合です。 のような文字列で`hardwokr`、最初の有効なウィンドウは、2 番目の r が現れる最後の位置でのみ可能になります。 アルゴリズムは、縮小が試行される前にその時点まで正しく拡張されるため、時期尚早な決定は行われません。 

もう 1 つのケースは、複数の r 文字が早期にクラスター化される場合です。 で`hharrdwok`の場合、アルゴリズムはすぐに r ≥ 2 を満たしますが、他の必要な文字がすべて出現するまで縮小することはできません。 ウィンドウは複数回拡大および縮小しますが、左は前方に移動するだけであるため、中間の各無効状態は位置を再検討することなく正しく処理されます。 

3 番目のケースは、ほとんどが無関係な文字で構成され、単一の有効なクラスターが埋め込まれた文字列です。 無関係な文字はカウンタでは無視されるため、ウィンドウの長さが大きくなるだけです。 縮小ステップにより、クラスターが完全に含まれると、アルゴリズムによって周囲のノイズが取り除かれ、最小限の有効なセグメントが分離されることが保証されます。
