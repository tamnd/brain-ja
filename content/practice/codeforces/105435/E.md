 ## 解決策
 ## 問題の理解

 一連の個別のエピソードが与えられ、それぞれに整数の楽しみ値が割り当てられます。 2 人のプレーヤーが交互に残りのプールからエピソードを取得します。 ヴィヴェクが最初に動きますが、彼の選択は彼の個人的な経歴によって制限されます。彼はすでに取得したエピソード間で厳密に増加する値のシーケンスを維持しており、移動するたびに、以前に選択した最大値よりも厳密に大きい値を持つエピソードのみを選択できます。 一方、Sagar にはそのような制限はなく、自分のターンで残りのエピソードをすべて受け入れることができます。 

このプロセスは、Vivek に有効な動きが存在しなくなるか、エピソードがなくなるまで続きます。 目標は、Vivek がカウントを最大化しようとし、Sagar がそれを最小化しようとして、両方のプレイヤーが最適に行動したときに、Vivek が何回のエピソードを取ることを強制できるかを決定することです。 

重要なやり取りは、単に大きな値を選択することだけではなく、Sagar の無制限の削除が、Vivek がアクセスできる前に特定の候補をプールから削除することで、Vivek にとって将来の「増加する機会」をどのようにブロックするかについても重要です。 

入力サイズは、グローバルな意味で非常に小さいです。テスト ケース全体のすべての n の合計は最大 15 です。これは、指数関数または階乗状態空間が受け入れられることをすぐに示唆しています。 サブセット、順列、またはゲームの状態を調査するあらゆるソリューションが実行可能です。 

素朴な貪欲な推論による微妙な失敗のケースは、Vivek が常に可能な限り最小の有効な値、または常に最大の可能な値を選択する必要があると仮定することから生じます。 たとえば、配列が次の場合、`[1, 2, 100, 3]`、を選ぶ貪欲な戦略。`1 → 2 → 3`合理的に思えるかもしれないが、Sagar は削除することで介入できる。`3`早い段階で、Vivek ははるかに小さなシーケンスで立ち往生したままになります。 削除の順序は、ローカルの選択よりも重要です。 

別の失敗モードは、問題が敵対的な削除の下で最も長​​く増加する部分列を見つけることに帰着すると仮定することから生じます。 敵対者は単に任意の要素を削除するのではなく、Vivek の成長制約を織り交ぜながら削除を行い、どの要素が依然として有用であるかを変更します。 

## アプローチ

 ゲーム状態の直接シミュレーションが最も簡単な開始点です。 どの時点においても、状態は 3 つの要素によって決まります。どの要素が残っているか、Vivek のシーケンスの現在の最大値は何か、そして誰の順番であるかです。 この状態から、現在のプレイヤーが可能なすべての動きに分岐します。 

この総当り検索が機能するのは、エピソード数が最大 15 であるため、サブセットの総数は 2^15 のみであり、サブセットを含むゲーム状態の数と現在の最大値はメモ化で管理できるためです。 ただし、残りのすべての要素を検査する遷移と 2^15 の状態を組み合わせた場合でも、単純に実行するとすぐに大きくなる分岐要素が発生します。 

重要な観察は、サーガルの役割はヴィヴェクの将来の選択肢に関して純粋に破壊的なものであるということです。 Sagar は値の順序に制約されないため、いつでも彼の最適な行動は、後で増加シーケンスを拡張する Vivek の能力を最も損なう要素を常に削除することです。 これは、私たちが気にする実際の状態は除去の正確な順序ではなく、むしろ最適なブロッキングの下で​​ Vivek が残りのセットからどれだけの「有用な増加ステップ」を抽出できるかであることを示唆しています。 

これにより、問題はサブセットに関するゲームに変わり、各サブセットと現在のしきい値について、Vivek がまだ前進できる最大回数を評価します。 n は小さいため、これをビットマスク上のメモ化された再帰としてエンコードでき、トランジションは両方のプレーヤーを最適にシミュレートします。

 | ゲーム状態を含むビットマスク DP | O(2^n · n) | O(2^n · n) | 承認済み |

 ## アルゴリズムのチュートリアル

 残りのエピソードのビットマスクと現在のしきい値によって各状態を表します。`last`、これは Vivek の次のピックに必要な最小値です。 誰の順番なのかも追跡します。 

関数を定義します`solve(mask, last, turn)`これは、Vivek がこの状態から引き続き取得できるエピソードの最大数を返します。 

1. エピソードが残っていない場合`mask`、それ以上の移動はできないため、0 を返します。 
2. Vivek の番になったら、すべてのインデックスを試します`i`そんなエピソード`i`に存在します`mask`そして`a[i] > last`。 有効な選択肢ごとに、`i`、 アップデート`last`に`a[i]`、Sagar のターンに切り替え、結果に 1 を加えます。 そのようなすべての選択肢から最大値を選択します。 これは、カウントを最大化するという Vivek の目標を反映しています。 
3. Sagar の番になったら、すべてのインデックスを試します`i`そんなエピソード`i`に存在します`mask`。 それぞれの選択肢について、削除します`i`、 保つ`last`変更せず、Vivek のターンに切り替えます。 結果として得られるすべての結果の最小値を取得します。 これは、Vivek の将来の機会を最小限に抑えるという Sagar の目標を反映しています。 
4. それぞれの結果をメモする`(mask, last, turn)`再計算を避けるためにペアにします。 
5. Vivek はどのエピソードからでも開始できるため、Vivek の可能な最初の動きをすべて試してプロセスを初期化します。 答えは、第 1 話のすべての選択肢の最大値です。 

正しさは、両方のプレイヤーを有限状態空間上のゼロサム ゲームで最適にプレイしているものとして扱うかどうかに依存します。 

### なぜ効果があるのか

 重要な不変条件は、すべての状態が`(mask, last, turn)`今後のプレイに関連するすべての情報を完全に取得します。 Vivek の制約はシーケンス全体ではなく、これまでの最大値のみに依存するため、以前に選択した要素の同一性は最大値を超えて問題になりません。 サーガー氏には制約がないため、どの要素が残っているかだけが決定の基準となります。 両方のプレイヤーが常にこれらの十分な統計に基づいて最適化するため、隠された履歴が最適なプレイに影響を与えることはなく、再帰によってゲーム ツリーの可能な継続がすべて状態ごとに 1 回だけ列挙されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from functools import lru_cache

def solve_case(a):
    n = len(a)

    @lru_cache(None)
    def dp(mask, last, turn):
        if mask == 0:
            return 0

        if turn == 0:
            best = 0
            for i in range(n):
                if mask & (1 << i) and a[i] > last:
                    best = max(best, 1 + dp(mask ^ (1 << i), a[i], 1))
            return best

        else:
            best = float('inf')
            moved = False
            for i in range(n):
                if mask & (1 << i):
                    moved = True
                    best = min(best, dp(mask ^ (1 << i), last, 0))
            return 0 if not moved else best

    full = (1 << n) - 1
    ans = 0

    for i in range(n):
        ans = max(ans, 1 + dp(full ^ (1 << i), a[i], 1))

    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(a))
```コードは説明どおりにゲームを正確にエンコードします。 ビットマスク`mask`残りのエピソードを追跡します。 値`last`Vivek の現在の最大制約を保存します。 再帰はターンを交互に行い、Vivek がカウントを最大化し、Sagar がカウントを最小化します。 

微妙な詳細は初期化ステップです。Vivek の最初の動きは強制されないため、最初の選択肢をすべて明示的に試します。 最初のピックの後、ゲームは更新されたしきい値で Sagar のターンに移行します。 

もう 1 つの重要な詳細は、Sagar のブランチが残りの手がない場合にのみ 0 を返すことです。 それ以外の場合は、すべての除去が彼にとって同様に合法であるため、すべての除去が最小限に抑えられます。 

## 実用的な例

 小さな例を考えてみましょう。`a = [3, 1, 4]`。 

考えられるすべての初手を評価します。 

| 最初の選択 | 残りのマスク | 最後 | サーガーの反応 | ヴィヴェクの続き | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 3 | {1,4} | 3 | 1 または 4 を削除 | 4 を取ることができます | 2 |
 | 1 | {3,4} | 1 | 3 または 4 を削除 | 3 と 4 を選択できます | 3 |
 | 4 | {3,1} | 4 | 3 または 1 を削除 | これ以上の動きはありません | 1 |

 1 から開始すると、最適な結果は 3 になります。これは、最初に最大のものを選択するのが最適ではないことを示しています。これは、将来増加するオプションを制限するためです。 

ここで考えてみましょう`a = [2, 5, 1, 3]`。 

| 最初の選択 | 残り | 最後 | サーガルアクション | ヴィヴェク パス | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | {5,1,3} | 2 | ブロック 3 または 5 | ベストは2→3→5 | 3 |
 | 5 | {2,1,3} | 5 | | を削除します。 立ち往生 | 1 |
 | 1 | {2,5,3} | 1 | 5 を削除します | 1→2→3 | 3 |
 | 3 | {2,5,1} | 3 | 5 を削除します | 3→？ | 2 |

 これは、Sagar の選択が増加する連鎖を完了できるかどうかに大きな影響を与えることを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^n · n^2) | 各状態は最大 n 個の遷移を検査し、2 つのターン状態を持つ 2^n 個のマスクがあります。 
| スペース | O(2^n · n) | マスクと状態ごとの最後の値に対するメモ化 |

 n ≤ 15 の場合、2^15 = 32768 となるため、遷移があっても合計作業量は問題なく制限内に収まります。

 ## 特殊なケース

 次のような単一要素の配列`[7]`Vivek がすぐに唯一のエピソードを取得することから始まり、その後は移動が残りません。 初期ループは唯一の有効な開始移動を試行し、終了状態に遷移するため、再帰は正しく 1 を返します。 

次のような厳密に増加する配列`[1, 2, 3, 4]`Vivek は常にシーケンスを拡張できます。 Sagar は要素を削除しますが、削除しても次のステップで使用できる大きな要素が残るため、DP は最終的にすべての要素をカウントします。 

次のような減少する配列`[5, 4, 3, 2]`これは、将来の拡張機能を即座に破棄する Sagar の能力を明らかにします。 最初の選択は、その後に大きな要素が存在しない状況につながるため、Vivek の結果は 1 に崩壊します。
