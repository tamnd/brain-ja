 ## 解決策
 ## 問題の理解

 一連のクエリが与えられ、それぞれが数値間隔を記述します。$[l, r]$。 すべてのクエリについて、その範囲内の整数が、約数の数に関連する特定のプロパティを持っている個数を数えるように求められます。 1 つのタイプのクエリは、除数の数が奇数である整数を要求し、もう 1 つのタイプは、除数の数が偶数である整数を要求します。 

重要な観察は、シミュレーションではなく数理論から得られます。 ほぼすべての整数には、ペアとなる約数があります。$d$分割する$n$、 それから$n/d$も分割します$n$。 この組み合わせは、除数の数が通常は偶数であることを示唆しています。 約数が別のパートナーとペアにならないのは、次の場合のみです。$d = n/d$、 意味$d^2 = n$。 それはまさにそのときに起こります$n$は完全な正方形です。 

これにより問題はすぐに変わります。約数が奇数の数値は完全な平方であり、その他の数はすべて偶数の約数を持ちます。 したがって、各クエリは実際には、範囲内で 2 つのことのうち 1 つを尋ねます。つまり、完全な平方数を数えるか、完全でない平方数を数えるかです。 

この制約により、各クエリ内の数値ごとの処理が行われなくなります。 まで$10^6$最大のクエリと値$10^9$、範囲を反復したり、数値ごとに約数をチェックしたりすることは不可能です。 クエリごとの対数処理でも境界線に達するため、ソリューションでは、何らかの推論や事前計算を行った後、各クエリを定数時間演算に削減する必要があります。 

エッジケースが発生するのは次の場合です$l = r$、間隔に単一の数値が含まれる場合、および間隔が完全な正方形の境界にまたがる場合。 たとえば、$[8, 9]$、9 だけが完全な平方であるため、ちょうど 1 つの数値が奇数の約数を持ちます。 約数を直接チェックする単純なアプローチでも概念的には機能しますが、タイムアウトしてしまいます。 もう 1 つの微妙な問題は、パリティ ルールの誤解です。数値ごとに約数を直接チェックすると、論理的には正しいとしても、時間の制約下では失敗します。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 内のすべての整数に対して$[l, r]$、平方根まで反復し、因数のペアを数えることによって、その除数の数を計算します。 これにより、除数の数が奇数か偶数かを正確に識別できます。 ただし、間隔のサイズは大きくなる可能性があり、最大で$10^6$クエリを実行すると、これは計算上不可能になります。 最悪の場合、広範囲にわたる単一のクエリでもコストがかかります。$O(\sqrt{n})$数値ごとに、おおよその結果が得られます$O((r-l+1)\sqrt{r})$、これは実現可能な限界をはるかに超えています。 

重要な洞察は、約数について明示的に考えるのをやめ、代わりに構造によって数値を分類することです。 対になっていない約数を持つのは完全平方のみであるため、問題全体は範囲内の完全平方を数えるということになります。 これが認識されると、各クエリは単純な算術問題になります。整数がいくつあるかを数えます。$x$満足する$l \le x \le r$そして$x = k^2$。 それは整数を数えるのと同じです$k$そのような$\lceil \sqrt{l} \rceil \le k \le \lfloor \sqrt{r} \rfloor$。 これにより、整数の平方根計算を使用して、すべてのクエリが定数時間に短縮されます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O((r-l+1)\sqrt{r})$クエリごと |$O(1)$| 遅すぎる |
 | 最適 |$O(1)$クエリごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 約数が奇数の数値は正確に完全な平方であることに注目してください。 これにより、除数の計算が構造特性のチェックに置き換えられます。 
2. クエリごとに$(type, l, r)$、区間の整数平方根境界を計算します。 最小の$k$そのような$k^2 \ge l$は$\lceil \sqrt{l} \rceil$、そして最大の$k$そのような$k^2 \le r$は$\lfloor \sqrt{r} \rfloor$。 
3. 区間内の完全正方形の数は次のようになります。$\max(0, \lfloor \sqrt{r} \rfloor - \lceil \sqrt{l} \rceil + 1)$。 これはタイプ 1 のクエリに直接答えます。 
4. タイプ 2 クエリの場合、間隔サイズは次のとおりです。$r - l + 1$、平方数以外のすべての数値は平方数を減算して数えられます。 

各ステップは、組み合わせ計数問題を、元の値ではなく平方のインデックスに関する算術に変換します。 

### なぜ効果があるのか

 すべての正の整数には約数のペア構造があります$d \leftrightarrow n/d$。 これらのペアは別個のものです。$d = n/d$の場合にのみ発生します。$n$は完全な正方形です。 対になっていない 1 つの約数により、合計数が奇数になります。 このような不対の約数は平方数ごとに 1 つだけ存在し、それ以外には存在しないため、奇数の約数を数えるのは平方数を数えるのと同じです。 このアルゴリズムは、「奇数の除数の数」と「区間内の平方数」の間のこの全単射に完全に依存しており、すべての入力の正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        t, l, r = map(int, input().split())
        
        left = math.isqrt(l)
        if left * left < l:
            left += 1
        right = math.isqrt(r)
        
        squares = 0
        if right >= left:
            squares = right - left + 1
        
        total = r - l + 1
        
        if t == 1:
            out.append(str(squares))
        else:
            out.append(str(total - squares))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```解決策は以下にかかっています`math.isqrt`、浮動小数点エラーなしで正確な整数の平方根が得られます。 左側の境界を調整することで、次のようなケースを正しく処理できるようになります。$l$それ自体は完全な正方形です。 そうしないと、範囲が誤ってシフトされてしまいます。 

合計数はクエリごとに計算され、平方数は純粋に整数演算から導出されます。 各クエリは独立しているため、事前計算は必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    def solve():
        q = int(input())
        out = []
        for _ in range(q):
            t, l, r = map(int, input().split())
            left = math.isqrt(l)
            if left * left < l:
                left += 1
            right = math.isqrt(r)
            squares = max(0, right - left + 1)
            total = r - l + 1
            if t == 1:
                out.append(str(squares))
            else:
                out.append(str(total - squares))
        return "\n".join(out)

    return solve()

""") == "3"

""") == "1"

""") == "0"

""") == "7"

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$l$それ自体は完全な正方形です。 例えば、$[9, 9]$。 9 の整数の平方根は 3 なので、$3^2 = 9$コード内の調整ステップにより、誤って除外しないことが保証されます。 

もう 1 つのケースは、次のような間隔に正方形がない場合です。$[8, 8]$。 ここ$\lfloor \sqrt{8} \rfloor = 2$そして$\lceil \sqrt{8} \rceil = 3$、負のカウントが生成されます。 実装では、暗黙的にゼロにクランプすることでこれを防ぎます。`if right >= left`チェック。 

大きな間隔など$[1, 10^9]$整数の平方根境界の正確さを強調します。 このアルゴリズムは依然として問題を 1 から 31622 までの整数をカウントすることに削減しており、大規模な場合でも変換が安定していることを示しています。
