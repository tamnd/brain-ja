 ## 問題の理解

 まず、寸法が次のようなボックス内に単位立方体の長方形の 3D 配置を作成します。$n \times m \times h$。 各ポジション$(i, j)$で$n \times m$グリッドは高さのある立方体の垂直方向の積み重ねを表します$A_{i,j}$。 したがって、最初の構造はフロア プラン上の高さマップです。 

次に、箱が回転して、垂直に積み上げられていたものが別の側から見えるようになります。 回転後、再び目に見える構造をグリッドとして記述します。今度はサイズが決まります。$h \times m$, ここで、各セルは$B_{i,j}$重力が新しい方向に作用した後、その位置に表示される立方体の数を表します。 

重要な点は、立方体が勝手に動かないということです。 これらは回転後の新しい垂直方向に沿って重力の下で落下するため、新しいビューの各列は、その列に「投影」するすべての立方体を回転後の高さ順に積み重ねることによって形成されます。 

これについて考えると便利な方法は、それぞれの元の列$(i,j)$の垂直方向の山に貢献します$A_{i,j}$立方体。 回転後、これらの杭は異なる軸を横切って再配置され、重力によって新しい柱に圧縮されます。 

制約$n, m, h \le 100$どれかであることを示します$O(nmh)$または、小さな定数係数 3D シミュレーションでも許容されます。 除外されるのは、大きな領域を繰り返しスキャンしたり、セルごとに繰り返し再スタックを実行したりする立方体ごとの組み合わせシミュレーションです。 

微妙なエッジ ケースは、多くのスタックがゼロである場合、またはすべてのスタックが最大である場合です。 素朴な「回転して直接割り当てる」アプローチは、単純な転置のようなマッピングを想定する傾向がありますが、重力によって最終的な分布が変化するため失敗します。 たとえば、すべてが$A_{i,j} = 1$、結果は 1 の単純な並べ替えではありません。 代わりに、積み重ねることにより、新しい垂直軸に沿って統合が行われます。 

## アプローチ

 直接シミュレーションでは、各立方体を独立して扱います。 あらゆる細胞に$(i,j)$、生成できます$A_{i,j}$立方体を単位化し、回転後の動きをシミュレートします。 各立方体は座標変換を通じて追跡され、重力下で落ち着くまで落下します。 これは概念的には正しいですが、計算上爆発的になります。 最悪の場合、最大で$n \cdot m \cdot h = 10^6$各キューブは、次のサイズの列をスキャンする必要がある場合があります。$h$、おおよそにつながります$10^8$操作以上。 

重要な観察は、個々の立方体をシミュレートする必要がないということです。 回転後、重要なのは、投影された各列に到達する立方体の数だけです。 位置に寄与する柱の高さの複数セットがわかったら、重力はそれらを順番に積み重ねるだけです。 したがって、問題は、元のグリッドから新しい方向によってインデックス付けされたバケットに値を収集し、バケットごとに安定した垂直パッキングを実行することに帰着します。 

具体的には、元の各列がその高さに寄与します。$A_{i,j}$回転されたグリッド内の位置に移動します。 回転は、最初の座標が新しいシステムの高さになるようにインデックスをマップしますが、2 番目の座標は保持されます。 これにより、固定ごとにグループ化が行われます。$j$、すべて集めます$A_{i,j}$横切って$i$、そしてそれらを に積み重ねるシミュレーションを行います。$h$-背の高い柱。 

重力を物理的にシミュレートする代わりに、各列を個別に解釈するだけです。$j$、リストを扱います$[A_{1,j}, A_{2,j}, \dots, A_{n,j}]$高さのある垂直コンテナにドロップされるブロックのセットとして$h$。 各ブロックは、下から上に向かって占有率に寄与します。 

これにより、問題は充填の問題に軽減されます$m$高さの独立した柱$h$、それぞれは、列内の値の複数セットから構築されます。$A$。

 ## アルゴリズムのチュートリアル

 問題を構築するものとして再解釈します。$m$出力グリッド内の独立した垂直列、それぞれの高さ$h$、入力行列からの寄与を積み重ねることによって形成されます。 

1. 各列インデックスについて$j$、すべての値を収集します$A_{i,j}$のために$i = 1 \ldots n$。 これは、回転したビューで同じ水平位置に整列したすべてのスタックを表します。 列ごとにグループ化する理由は、回転により垂直構造を交換しながら水平方向の配置が維持されるためです。 
2. 列に対応するグループごとに$j$、サイズの配列を埋めながら任意の順序で値を処理することで、新しい方向の重力をシミュレートします。$h$下から上へ。 次に利用可能な高さの位置を示すポインターを維持します。 
3. 各値について$x = A_{i,j}$、置きます$x$単位立方体は、列内で現在利用可能な最も低い位置から始まり、上に向かって移動します。 配置するたびにポインタが増加します。 カラムがいっぱいになると、超過分は無視されます。 
4. 列内のすべての値が得られるまで繰り返します。$j$処理されます。 これにより、出力グリッドの 1 つの完全な列が生成されます。 
5. 結果の列を回答行列に保存します$B$。 

重要な点は、個々の立方体の位置をシミュレートする必要がないことです。 スタッキング後に各列に何個のセルが埋められるかを知る必要があるだけです。 

### なぜ効果があるのか

 正しさは、回転後に各入力スタックが同一の単位立方体の連続した垂直セグメントに寄与するという事実に依存します。 新しい方向の重力は、異なるスタックからのキューブをインターリーブしません。 これらのセグメントは到着順にのみ注文されます。 すべてのキューブは同一であり、その数のみが重要であるため、最終的な構造は、内部順序ではなく、各列に割り当てられたキューブの数のみに依存します。 したがって、各列を独立して処理し、下から上に貪欲に積み重ねることで、完全な物理シミュレーションとまったく同じ占有率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, h = map(int, input().split())
A = [list(map(int, input().split())) for _ in range(n)]

B = [[0] * m for _ in range(h)]

for j in range(m):
    col = []
    for i in range(n):
        if A[i][j] > 0:
            col.append(A[i][j])

    ptr = 0
    for x in col:
        for _ in range(x):
            if ptr < h:
                B[ptr][j] = 1
                ptr += 1

for i in range(h):
    print(*B[i])
```この実装は、アルゴリズムの列中心のビューに直接準拠しています。 各列を個別に構築し、下から上にポインタを入力してスタッキングをシミュレートします。 内側のループは、各高さの値をユニットの寄与度に拡張します。これは、立方体の合計が最大 100 個であるため、制約を考慮すると安全です。$10^6$。 

微妙なポイントはバウンドチェックです`ptr < h`。 これがないと、列がオーバーフローすると、意図した高さを超えて書き込みが行われ、隣接するメモリが論理的に破壊されてしまいます。 余分な立方体は回転後物理的に可視領域の外側にあるため、安全に破棄されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, h = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]

    B = [[0] * m for _ in range(h)]

    for j in range(m):
        col = []
        for i in range(n):
            if A[i][j] > 0:
                col.append(A[i][j])

        ptr = 0
        for x in col:
            for _ in range(x):
                if ptr < h:
                    B[ptr][j] = 1
                    ptr += 1

    return "\n".join(" ".join(map(str, row)) for row in B) + "\n"

 ## 特殊なケース

 主なエッジケースは、単一の列が高さよりも多くの立方体を生成する場合です。$h$。 アルゴリズムは、次の場合に書き込みを停止することでこれを処理します。`ptr == h`。 たとえば、次の場合$h = 3$コラムも寄稿しています$5$立方体では、最初の 3 つだけが配置されます。 残りの立方体は、重力圧縮後に目に見える高さの外側にあるため、無視されます。 

もう 1 つのケースは、列内のすべてのエントリがゼロの場合です。 列リストが空になるため、ポインターは移動せず、出力列は完全にゼロのままになります。 これは、その垂直スライスに立方体が存在しない物理的な解釈と一致します。 

3 番目のケースは、均一な非ゼロ入力です。$A_{i,j} = 1$。 各列が貢献します$n$単一の立方体、および積み重ねは単純に下から上まで充填します。$h$。 このアルゴリズムは、順序に依存せずにすべての要素を正しく圧縮し、入力行の並べ替えが結果に影響を与えないことを確認します。
