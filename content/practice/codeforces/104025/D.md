 ## 解決策
 ## 問題の理解

 重み付き無向グラフとしてモデル化された小さな都市が与えられています。 各交差点はノードであり、各道路には移動時間があります。 さらに、すべてのノードには長さの周期的な制約があります。$T$。 毎回の残量について$t \in [0, T-1]$、ノードは開いているか閉じています。 時間は継続的に進化しますが、許可される侵入パターンは毎回繰り返されます。$T$単位。 

重要なルールは、ノードへの入場は、そのノードが開いているときにのみ許可されるということです。 一度入場したら、好きなだけノード内で待つことができますが、出発時にノードが開いていない限り、退出することはできません。 エッジに沿った移動にはその重みに等しい時間が消費され、移動は継続的であるため、目的地ノードでの実現可能性には到着時間が重要となります。 

タスクは、開始時間の残差ごとに計算することです。$s \in [0, T-1]$、ノードから移動するのに必要な最小時間$1$ノードへ$n$ノードから始めると仮定します$1$時に$s$。 

重要な構造上の制約は、両方とも$n$そして$T$これは、状態空間のサイズに余裕があることを強く示唆しています。$O(nT)$、しかし、そのようなものではありません$O(T \cdot n^2)$コストのかかる作業を繰り返したり、最短パスの実行を繰り返したりします。 

微妙なエッジケースは待機動作にあります。 ノードが閉じているときにノードに到着することは許可されていますが、開始ルールに違反する方法ですぐに離脱したり、トランジションに参加したりすることはできません。 待機の実現可能性を無視した単純な最短パスは失敗します。 

たとえば、ノードが時刻 0 mod でのみ開いている場合、$T$、時間 3 に到着した場合は、次のオープン時間まで待つ必要があります。 時間調整を行わずにエッジを単純な重みとして扱うアプローチでは、不正確な結果が生成されます。 

## アプローチ

 直接的なアプローチは、各ペアを処理することです$(u, t)$状態として、つまりノードにいることを意味します$u$時に$t \bmod T$。 このような状態から、ノードがオープンになるまでその場で待機し、次のノードへの到着時間が一致する場合はエッジを通過できます。 

これは、次のようなグラフを示唆しています。$nT$州。 各状態からすべての隣接ノードに移行する可能性があり、ノードの制約と同期するための待ち時間などのコストがかかります。 すべてのエッジ コストが負ではないため、この拡張グラフに対してダイクストラを実行することは正しいです。 

ただし、移行コストについては慎重に対処する必要があります。 から$(u, t)$、隣に引っ越します$v$重量のエッジを介して$w$出発時間を選択する必要があることを意味します$t' \ge t$そのようなノード$u$にオープンしています$t'$、ノード$v$にオープンしています$t' + w$。 そして到着します$(v, (t' + w) \bmod T)$。 

重要な最適化は、各ノードと時間残差について、周期的なプレフィックス スキャンを使用して次の有効な出発時刻を事前計算できることです。$0/1$弦。 これにより、遷移ごとに直線的に順方向にスキャンすることが回避されます。 

ブルート フォースは、すべての州とすべての近隣諸国について、時間内に前方スキャンを実行します。$T$次の有効な出発時刻を見つけて、$O(nmT^2)$最悪の場合。 改善されたアプローチでは、次回のオープン時間を事前計算し、単一のダイクストラを使用することでこれを削減します。$nT$州。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース時間スキャン |$O(nmT^2)$|$O(nT)$| 遅すぎる |
 | ディクストラを重ね着$nT$状態 |$O((nT + mT)\log(nT))$|$O(nT + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 州を越えて時間拡張された最短パスを構築します$(u, t)$、 どこ$t$現在時刻のモジュロです$T$。 

1. 各ノードについて$u$、配列を前処理します`next_open[u][t]`それが最も早い時間を与える$t' \ge t$そのようなノード$u$にオープンしています$t'$、必要に応じて定期的にラップアラウンドします。 これにより、定数時間の待機計算が可能になります。 
2. 各状態を示すグラフを作成します。$(u, t)$ダイクストラ的な意味でのノードです。 距離配列には、その状態に到達するために必要な最小絶対時間が格納されます。 
3. ノードでのすべての有効な開始状態の距離を初期化します。$1$。 時間通りに始められるので$s$、まず、 以降のノード 1 の最も早いオープン時間に移動します。$s$。 これにより初期状態が得られます$(1, t')$距離を置いて$t' - s$。 
4. これらの初期状態から Dijkstra を実行します。 各状態は最小の現在時刻を抽出することによって処理されます。 
5. 州から$(u, t)$、それぞれの隣人を考慮します$v$。 まず最も早い出発時刻 t_d = \text{next_open}[u][t] を計算します。 これにより、次の場合にのみ離れることができるという制約に従うことが保証されます。$u$開いています。 
6. 到着時間$v$は$t_d + w$。 次に、次のことを確認する必要があります。$v$到着時間にオープンしています。 そうでない場合は、先に進みます$t_d$両方の条件が揃うまでさらに続けます。 以来$T \le 500$、遷移テーブルを事前計算したり、周期的に反復したりできます。$O(T)$ですが、代わりに互換性ジャンプ テーブルを事前計算します。 
7. 状態を緩和する$(v, (t_d + w) \bmod T)$距離を置いて$t_d + w - s$。 
8. アルゴリズムが終了した後、各残差について$t$、すべての状態間の最小距離を取得します。$(n, t)$。 

本質的な構造は、時間は連続的ですが、周期的な制約により、有効な決定点が有限の循環オートマトンに減少するということです。 

### なぜ効果があるのか

 不変条件は、ダイクストラが常に既知の州への最短到着時間を最終決定するということです。$(u, t)$ここで、この状態は信号機サイクルの位置と位相の両方を完全にエンコードします。 元の問題の有効なパスは、この拡張された状態グラフのパスに対応し、その逆も同様です。これは、待機が、実現可能な最も早い出発時刻を考慮した遷移を介して明示的にモデル化されているためです。 すべての遷移は非負の時間増分を尊重し、距離の増加順に状態を探索するため、最初に状態を解決するときに、最適な到着時間が見つかります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m, T = map(int, input().split())
    ok = []
    for _ in range(n):
        ok.append(input().strip())
    
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append((v, w))
        adj[v].append((u, w))

    # preprocess next open time for each node, cyclic
    nxt = [[-1] * T for _ in range(n)]
    for u in range(n):
        for t in range(T):
            if ok[u][t] == '1':
                nxt[u][t] = t
    
        for t in range(T - 2, -1, -1):
            if nxt[u][t] == -1:
                nxt[u][t] = nxt[u][t + 1]
    
        # wrap around
        last = -1
        for t in range(T - 1, -1, -1):
            if ok[u][t] == '1':
                last = t
            if nxt[u][t] == -1:
                nxt[u][t] = last
        nxt[u][T - 1] = nxt[u][T - 1]

    # dist[u][t] = min time to reach u at time mod T = t
    dist = [[INF] * T for _ in range(n)]
    pq = []

    # start from node 1 at any allowed start time s
    for t in range(T):
        if ok[0][t] == '1':
            dist[0][t] = t
            heapq.heappush(pq, (t, 0, t))

    while pq:
        cur, u, t = heapq.heappop(pq)
        if cur != dist[u][t]:
            continue

        # move to neighbors
        for v, w in adj[u]:
            # we must leave u when it's open; already ensured by state
            t_arr = (t + w) % T
            cand_time = cur + w

            # ensure v is open at arrival; if not, wait extra cycles
            # try all possible shifts up to T
            add = 0
            found = False
            for k in range(T):
                tt = (t_arr + k) % T
                if ok[v][tt] == '1':
                    add = k
                    found = True
                    break
            if not found:
                continue

            nt = (t_arr + add) % T
            ncur = cur + w + add

            if ncur < dist[v][nt]:
                dist[v][nt] = ncur
                heapq.heappush(pq, (ncur, v, nt))

    res = []
    for s in range(T):
        res.append(min(dist[n - 1]))

    print(*res)

if __name__ == "__main__":
    solve()
```実装では各ペアを扱います$(u, t)$ダイクストラ状態として。 優先キューには、開始からの距離の剰余ではなく絶対時間が保存されるため、モジュロをラップする際のあいまいさが回避されます。$T$。 

まで検索する内部ループ$T$次の有効な到着のアライメントは安全であるため、$T \le 500$これにより、より複雑なジャンプ テーブルの構築が回避されます。 各緩和により、次の状態に移行する前に、出発制約と到着制約の両方が満たされることが保証されます。 

各開始残基の最終的な答えは、単にノードのすべての終端状態の最小値です。$n$、到着時間のモジュロ以降$T$目的を制約しません。

 ## 特殊なケース

 重大なエッジ ケースは、ノードがサイクル全体にわたって閉じられている場合です。 この問題により到達可能性は保証されますが、中間ノードには依然として長くまばらな開口部が存在する可能性があります。 ダイクストラはサイクル検索内で有効なアライメントが見つかった場合にのみ遷移を緩和するため、アルゴリズムはこれを処理します。 存在しない場合、そのパスは無視されます。 

もう 1 つのケースは、到着が閉店前の許容される最後の瞬間に到着した場合です。 すべての剰余モジュロを明示的にテストするので、$T$、等価性は正しく処理され、待機中の計算でオフバイワンエラーは発生しません。 

最後に、開始時刻がすでにオープン状態と一致している場合、待ち時間は不要です。 これらは優先キュー内で直接初期化され、アルゴリズムが最適な開始を人為的に遅らせないようにします。
