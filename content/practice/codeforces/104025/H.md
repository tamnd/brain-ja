 ## 解決策
 ## 問題の理解

 線に沿った住民の幸福度を表す整数の配列が与えられます。 各テスト ケースについて、下限が指定された整数に等しい平均幸福度を持つ連続する部分配列がいくつあるかを数えなければなりません。$k$。 

部分配列の条件をより操作的な方法で書き直す$[l, r]$、その合計を$S = a_l + a_{l+1} + \dots + a_r$そしてその長さは$L = r - l + 1$。 要件は次のとおりです。$$\left\lfloor \frac{S}{L} \right\rfloor = k$$これは次と同等です。$$k \le \frac{S}{L} < k + 1$$を乗算する$L$、次のようになります。$$kL \le S < (k+1)L$$したがって、すべての有効なセグメントは、その長さに応じてその合計が狭い線形範囲内に収まるセグメントです。 

制約は大きく、最大で$5 \cdot 10^5$テスト ケース全体の要素の合計。 これにより、あらゆることが排除されます$O(n^2)$部分配列の列挙。 たとえ$O(n \log n)$テスト ケースごとのアプローチは慎重に正当化される必要がありますが、実際には線形または線形に近い動作を目指す必要があります。 

微妙な落とし穴は、この条件では合計の等価ではなく、平均の下限が使用されることです。 単純にチェックするだけの間違い$S = kL$、平均がわずかに上回っている有効な間隔を見逃します。$k$しかし、まだ下にあります$k+1$。 もう 1 つの問題は、合計が次の値に達する可能性があるため、オーバーフロー推論です。$10^{14}$ただし、Python はこれを回避しますが、C++ では 64 ビットが必要です。 

小さな例で構造を明確にします。 配列が$[2, 1, 3]$そして$k = 2$、有効な部分配列は次のとおりです。$[2]$、$[1,3]$、 そして$[2,1,3]$。 2 番目の関数は、長さ 2 に対して合計が 4 であるにもかかわらず、平均がちょうど 2 であるため機能します。 

## アプローチ

 直接的なアプローチでは、すべての部分配列を試してその合計を計算し、$\lfloor S/L \rfloor = k$。 これには反復処理が必要です$O(n^2)$間隔と合計の計算は次のように削減できます。$O(1)$プレフィックス合計を使用して間隔ごとに。 それでも全体的な複雑さは残ります$O(n^2)$、これは限界をはるかに超えています。$n$到達する$2 \cdot 10^5$。 

状態の構造は変化を示唆しています。 生の値を扱う代わりに、減算して配列をシフトします。$k$。 定義する：$$b_i = a_i - k$$次に、任意のセグメントに対して次のようにします。$$\sum b_i = S - kL$$条件$kL \le S < (k+1)L$は次のようになります:$$0 \le \sum b_i < L$$したがって、シフトされた合計が負ではないが、厳密にその長さよりも小さいサブ配列を数えます。 

これには依然として長さへの依存が含まれており、見た目が不自然です。 重要な観察は、2 つの不等式を分離することです。 

必要なものは次のとおりです。$$\sum b_i \ge 0 \quad \text{and} \quad \sum b_i \le L - 1$$2 番目の不等式は次のように書き換えることができます。$$\sum b_i - L < 0$$別の変換された配列を定義すると、次のようになります。$$c_i = b_i - 1 = a_i - (k+1)$$それから：$$\sum c_i < 0$$ここで問題は、2 つの独立した接頭辞合計制約を満たす部分配列をカウントすることになります。$$\sum b_i \ge 0 \quad \text{and} \quad \sum c_i < 0$$プレフィックスの合計を次のようにします。$$P_i = \sum_{j \le i} b_j,\quad Q_i = \sum_{j \le i} c_j$$サブアレイの場合$[l, r]$、条件は次のようになります。$$P_r - P_{l-1} \ge 0 \Rightarrow P_r \ge P_{l-1}$$

$$Q_r - Q_{l-1} < 0 \Rightarrow Q_r < Q_{l-1}$$したがって、インデックスのペアが必要です$l-1 < r$次のような:$$P_{l-1} \le P_r \quad \text{and} \quad Q_{l-1} > Q_r$$これは 2D 点の優勢カウント問題です$(P_i, Q_i)$ここで、最初の座標では 1 つの点が超えないが、2 番目の座標では厳密に超えているペアを数えます。 これは、座標圧縮を伴うスイープとフェンウィック ツリーを使用して解決できます。 

アイデアは次のように並べ替えることです$P$、およびそれぞれの固定$P_r$、何個前か数えてください$P$-値は$\le P_r$でフィルタリングしながら$Q$動的に注文する。

 | 最適 (Fenwick + プレフィックス ペアのソート) |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列を 2 つのプレフィックス合計配列に変換し、この条件をプレフィックス ポイントに対するペアごとの優勢カウント問題に落とし込みます。 

1. 変換された値を構築する$b_i = a_i - k$そして$c_i = a_i - (k+1)$。 これにより、元の条件の 2 つの不等式が線形プレフィックス制約にエンコードされます。 
2. プレフィックスの合計を計算する$P_i$のために$b$そして$Q_i$のために$c$、 含む$P_0 = Q_0 = 0$。 各インデックス$i$ポイントになる$(P_i, Q_i)$。 
3. すべてのプレフィックス ポイントを収集し、次の基準で並べ替えます。$P_i$。 これにより、ポイントを処理するときに、すべての有効な先行ポイントが確実に削除されます。$P$順番にアクセス可能です。 
4. 圧縮します。$Q$コーディネート。 これは、以前のポイントが何個あるかをクエリするため必要です。$Q$しきい値より大きいため、フェンウィック ツリーには離散インデックスが必要です。 
5. 昇順にポイントをスイープします。$P$。 圧縮されたキーをキーとして、すでに処理されたポイントの数を保存するフェンウィック ツリーを維持します。$Q$。 
6. 各ポイントについて$i$、以前のポイントの数を数えたい$j$満足する$Q_j > Q_i$。 これは、フェンウィック ツリーに現在のカウントを超える数を問い合わせることによって行われます。$Q_i$。 
7. 処理後に各ポイントの寄与をフェンウィック ツリーに追加し、将来のポイントがそのポイントを先行候補として認識するようにします。 
8. すべてのポイントにわたるすべての寄与を合計して、最終的な答えを取得します。 

スイープにより、$P_j \le P_i$条件は処理順序によって自動的に尊重されますが、フェンウィック ツリーは$Q_j > Q_i$制約。 

### なぜ効果があるのか

 各サブ配列は、プレフィックス インデックスのペアに一意に対応します。$(l-1, r)$。 この変換により、有効性が 2 次元空間内のプレフィックス ポイントの相対的な順序にのみ依存することが保証されます。 掃引線は、有効とみなされるもののみを保証します$P$-順序ペア、フェンウィック構造により厳密な規則が適用されます。$Q$不平等。 すべての有効なペアはその右のエンドポイントで 1 回だけカウントされるため、$r$、過大カウントや漏れは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        P = 0
        Q = 0
        pts = [(0, 0)]

        for x in a:
            P += x - k
            Q += x - (k + 1)
            pts.append((P, Q))

        qs = sorted(set(q for _, q in pts))
        comp = {q: i + 1 for i, q in enumerate(qs)}

        pts.sort()

        fw = Fenwick(len(qs))
        ans = 0

        for p, q in pts:
            idx = comp[q]
            ans += fw.sum(len(qs)) - fw.sum(idx)
            fw.add(idx, 1)

        print(ans)

if __name__ == "__main__":
    solve()
```実装はスイープ ラインの解釈に直接に従います。 各プレフィックス状態はクエリの後に挿入されるため、以前のプレフィックスのみが考慮されます。 フェンウィック ツリーはカウントを圧縮して保存します$Q$、範囲クエリでは、以前のプレフィックスの合計が現在のプレフィックスの合計を超えている回数がカウントされます。$Q$。 

微妙な点は、次の基準で並べ替えることです。$P$恣意的に関係を断つことは平等であるため許容される$P$値は、同じレベルでのペアのカウントの正確性に関する不等号の方向には影響しません。 厳密な不平等$Q$は、Fenwick クエリをサフィックスの合計に分割することで処理されます。

 ## 特殊なケース

 すべての要素が等しい場合に特殊なケースが発生します$k$。 次に、すべての部分配列が正確に平均を持ちます$k$、その答えは部分配列の総数になります。 すべてのプレフィックス ポイントが縮退的な方法で整列するため、アルゴリズムはこれを処理しますが、フェンウィック カウントでは有効なインデックスのペアがすべて正しくカウントされます。 

もう 1 つのエッジ ケースは、条件を満たすサブ配列がない場合です。たとえば、すべての値が よりもはるかに小さい場合です。$k$。 この場合、変換されたプレフィックスの合計は一貫した方向で厳密に負のままであり、すべてのペアで優勢条件が満たされないため、寄与はゼロになります。 

3 番目のケースは、単一要素の配列です。 プレフィックス構築には以下が含まれます$(0,0)$そして変身ポイントが1つ。 Fenwick クエリは、条件が一致する場合に有効なペアを 1 つだけ処理し、特別な大文字と小文字を区別せずに正確さを保証します。
