 ## 解決策
 ## 問題の理解

 (1) から (n) までの数値を順列に配置する必要があります。 位置 (i) は、そこに配置される値も (i) である場合、固定と呼ばれます。 正確に (m) 個の固定位置を持つすべての順列のうち、辞書順で (k) 番目のものを出力する必要があります。 有効な順列が (k) 個未満の場合、答えは (-1) になります。 

(n\le 50) では (n) の制約は小さいですが、順列の数は膨大です。 (n=50) であっても、(50!\about3.04\cdot10^{64}) 個の順列が存在するため、順列を列挙する方法はまったく実行不可能です。 ランク (k) は (10^{18}) に達する可能性があります。これは、入力ランクには通常の 64 ビット整数で十分ですが、中間のカウント値はさらに大きくなる可能性があることを意味します。 (k) 未満のカウントと (k) 以上のカウントを区別するだけでよいため、すべての DP 値は安全に (10^{18}) に制限できます。 

直接構築では誤って処理される可能性のあるいくつかの特殊なケースがあります。 入力用`1 0 1`、唯一の順列は`[1]`ただし、固定点が 1 つあるため、正しい出力は次のようになります。`-1`。 利用可能な唯一の値を単に埋めるだけの構造では、その値が誤って受け入れられます。 

入力用`3 2 1`の場合、必要な固定点の数は 2 です。 2 つの位置が固定されている場合、最後の位置にも独自の値が強制的に含まれるため、正確に 2 つの固定点は不可能です。 正しい出力は次のとおりです`-1`。 残りの配置を考慮せずに固定位置を独立して選択する方法では、この間違いが発生する可能性があります。 

入力用`4 0 3`、すべての固定点は禁止されています。 9 つの混乱があり、辞書編集上 3 番目に小さいものは次のとおりです。`2 4 1 3`。 (i) を (i) の位置に配置することを単に回避する貪欲なルールでは、残りの値を混乱状態に完成できるかどうかがわからないため、後で不可能になるプレフィックスを選択する可能性があります。 

最後のエッジ ケースは (m=n) です。 有効な順列は 1 つだけあり、恒等順列です。 例えば、`4 4 1`生産しなければならない`1 2 3 4`、 その間`4 4 2`生産しなければならない`-1`。 

## アプローチ

 直接的なアプローチは、すべての順列を辞書編集順に生成し、その固定小数点を数え、(k) 番目の有効な順列が見つかったときに停止することです。 生成された順序はまさに必要な順序であるため、これは正しいですが、最悪の場合、すべての (n!) 個の順列を調べ、それぞれの (n) 個の位置を検査します。 最悪の場合の作業は (O(n\cdot n!)) で、(n=50) の場合、位置チェックは約 (50\cdot50!\about1.52\cdot10^{66}) になります。 順列を単独で生成することさえすでに不可能です。 

有益な観察は、将来は残りのすべての値の正確な同一性に依存しないということです。 重要なのは、利用可能な独自の値をまだ持っている残りのポジションがどれだけあるかということです。 

位置と未使用の値が残っていると仮定します。 自身の番号が未使用の値の中にある場合は、位置一致可能と呼び出します。 (a) を一致可能な位置の数とします。 指定された数の固定点で完了をカウントするという目的では、同じ (s)、(a)、および必要な数の固定点を持つすべての状態は同等です。 実際のラベルは関係ありません。 

(dp[s][a][r]) を、(s) 個の位置を使用してそのような状態を完了する方法の数として定義します。ここで、正確に (a) 個の位置には利用可能な独自の値があり、それらの位置のうち正確に (r) 個は固定される必要があります。 

繰り返しを導き出すには、特定の一致可能な位置を 1 つ選択します。 その値は 3 つの方法で割り当てることができます。 独自の値を受け取ることができ、1 つの固定点を作成し、(a) を 1 つ減らします。 対応する位置が残りの位置にない値を受け取ることができます。 このような値は (s-a) 個あり、それらを削除すると (a) が 1 つ減ります。 最後に、別の一致可能な位置に属する値を受け取ることができます。 このような選択肢は (a-1) 通りあり、選択した位置とその値の両方を削除すると (a) が 2 減ります。 

これにより、

 dp[s-1][a-1][r-1]
 +
 (s-a),dp[s-1][a-1][r]
 +
 (a-1)、dp[s-1][a-2][r]。 
]

 (a=0) の場合、残りの位置は固定されないため、(dp[s][0][0]=s!)、一方、(r>0) の場合は (dp[s][0][r]=0) となります。 

同じ DP が辞書編集の構築をガイドできます。 すべての位置で、未使用の値を最小値から最大値まで試します。 各候補について、(a) の新しい値を計算し、有効な補完がいくつ残っているかを DP に尋ねます。 その数が少なくとも (k) であれば、候補は目的の順列に属します。 それ以外の場合、その候補で始まるすべての順列は答えの前にあるため、(k) からカウントを減算して次の候補を試します。 

このブルートフォース手法は、可能なすべての継続を明示的に列挙するため機能しますが、その数が階乗的に多いため失敗します。 完了カウントが (s)、(a)、および (r) にのみ依存するという観察により、これらすべての継続が多項式サイズの DP に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n\cdot n!)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n^3+n^3\log n)) | (O(n^3)) | 承認済み |

 この構築における対数係数は、最大 50 個の未使用の値を繰り返しソートすることで得られます。 これは、順序付けされた構造を維持することで回避することもできますが、この制約サイズでは意味がありません。 

## アルゴリズムのチュートリアル

 1. DP テーブル (dp[s][a][r]) を構築します。 基本状態は (dp[0][0][0]=1) です。 (a=0) のすべての状態に対して、(dp[s][0][0]=s!) を設定します。 (a>0) の場合は、上記の 3 つの場合の反復を使用します。 (k) と比較する目的では、より大きな値は区別できないため、すべてのカウントの上限は (10^{18}) になります。 
2. すべての位置とすべての値を未使用の状態で開始します。 最初は (s=n)、(a=n) です。これは、すべての位置に利用可能な独自の値がまだあるためです。 有効な順列の合計数は (dp[n][n][m]) です。 (k) より小さい場合は、すぐに印刷します。`-1`。 
3. (1) から (n) までの位置を処理します。 位置 (i) では、現在使用されていないすべての値 (x) を昇順に検討します。 この順序付けはまさに辞書編集上のランキングに必要なものです。 
4. (x) を選択すると固定点が作成されるかどうかを判断します。 (x=i) の場合に正確に実行されます。 さらに必要な固定点の数は (m-[x=i]) になります。 
5. 位置 (i) と値 (x) を削除した後、一致可能な位置の新しい数を計算します。 (x=i) の場合、一致可能な位置が 1 つ消えるため、新しいカウントは (a-1) になります。 それ以外の場合、位置 (i) を削除すると、(i) がまだ未使用の値である場合に 1 つの一致可能な位置が正確に削除され、値 (x) を削除すると、位置 (x) がまだ処理されていない場合に正確に 1 つの一致可能な位置が削除されます。 
6. 候補者は (n-i) 人の職を辞任します。 それらの残りの位置、新しく計算された一致可能な数、および必要な固定小数点の残りの数を使用して DP をクエリします。 この数は、プレフィックスが現在のプレフィックスに (x) が続く有効な順列の数と正確に一致します。 
7. そのカウントが (k) より小さい場合、この辞書編集ブロック全体をスキップし、(k) からカウントを減算します。 それ以外の場合は、(x) にコミットし、残りのセットから (i) と (x) を削除し、(a) と (m) を更新して、次の位置に進みます。 
8. すべての位置が処理された後、構築されたシーケンスは (k) 番目の有効な順列になります。 

不変条件は、位置 (i) を処理する前に、(k) は現在のプレフィックスのすべての有効な補完のうちの目的の回答のランクであり、(dp) はすべての候補継続についてそれらの補完を正確にカウントすることです。 候補ブロックがスキップされると、そのブロック全体が答えに先行するため、そのサイズを差し引くと不変式が保持されます。 候補が受け入れられると、答えはそのブロック内にある必要があるため、より小さい状態でも同じ不変式が当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def build_dp(n):
    # dp[s][a][r]:
    # number of completions with s positions left,
    # a matchable positions, and exactly r fixed points.
    dp = [[[0] * (n + 1) for _ in range(n + 1)]
          for _ in range(n + 1)]

    dp[0][0][0] = 1

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = min(LIMIT, fact[i - 1] * i)

    for s in range(1, n + 1):
        dp[s][0][0] = fact[s]

    for s in range(1, n + 1):
        for a in range(1, s + 1):
            for r in range(0, a + 1):
                value = 0

                # The chosen matchable position is fixed.
                if r >= 1:
                    value += dp[s - 1][a - 1][r - 1]

                # It receives a value whose position is not matchable.
                if s - a > 0:
                    value += (s - a) * dp[s - 1][a - 1][r]

                # It receives the value of another matchable position.
                if a >= 2:
                    value += (a - 1) * dp[s - 1][a - 2][r]

                dp[s][a][r] = min(LIMIT, value)

    return dp

def solve_instance(n, m, k):
    dp = build_dp(n)

    if dp[n][n][m] < k:
        return "-1"

    remaining_positions = set(range(1, n + 1))
    remaining_values = set(range(1, n + 1))

    a = n
    answer = []

    for pos in range(1, n + 1):
        s = n - pos + 1

        chosen = False

        for x in sorted(remaining_values):
            fixed = (x == pos)
            remaining_fixed = m - fixed

            if x == pos:
                new_a = a - 1
            else:
                new_a = a
                if pos in remaining_values:
                    new_a -= 1
                if x in remaining_positions:
                    new_a -= 1

            if remaining_fixed < 0:
                count = 0
            else:
                count = dp[s - 1][new_a][remaining_fixed]

            if count < k:
                k -= count
                continue

            answer.append(x)
            remaining_positions.remove(pos)
            remaining_values.remove(x)

            a = new_a
            m = remaining_fixed
            chosen = True
            break

        if not chosen:
            return "-1"

    return " ".join(map(str, answer))

def main():
    n, m, k = map(int, input().split())
    print(solve_instance(n, m, k))

if __name__ == "__main__":
    main()
```の`build_dp`関数はアルゴリズムで記述された状態を実装します。 別個の`a=0`初期化が必要なのは、反復では、その状態には存在しない一致可能な位置が選択されるためです。 階乗値は、将来の固定小数点が不可能な場合のすべての無制限の置換を表します。 

反復内の 3 つの項は、選択された一致可能な位置の 3 つの可能な目的地に直接対応します。 乗算係数は、各カテゴリに属する​​値の数をカウントします。 テーブルには最大 (n) までのインデックスのみが必要なため、その次元は小さくなります。 

の`LIMIT`cap は、Python 整数の不必要な増加を防ぎます。 実際の順列の数は (50!) にもなる可能性がありますが、構築中に尋ねられる唯一の質問は、ブロックに含まれる順列が (k) 個より少ないかどうかです。 (k\le10^{18}) なので、より大きなカウントをすべて (10^{18}) で置き換えると、すべての決定が保存されます。 

工事中は、`remaining_positions`そして`remaining_values`正確な状態を表します。 変数`a`独自の値がまだ使用されていない位置の数を格納します。 の表現`new_a`現在の位置の削除と候補値の削除を別々に考慮します。 いつ`x == pos`、両方の削除は同じ一致可能なペアに関するものであるため、減算する必要があるのは 1 回だけです。 

比較は意図的に行われています`count < k`それよりも`count <= k`。 候補ブロックに正確に (k) 個の有効な補完が含まれている場合、目的の順列はそのブロック内にあり、候補を選択する必要があります。 これは、(k) 番目の辞書編集における最も一般的な off-by-one エラーです。 

Python の整数はオーバーフローしませんが、明示的な上限により DP 値が小さく保たれ、意図された比較セマンティクスが明確になります。 

## 実用的な例

 ### サンプル 1

 入力用`3 1 1`、固定点が 1 つ必要で、最初の有効な順列が必要です。 

| ポジション | 候補者 | 残りのポジション | 一致可能 (a) | 必要な固定点 | 完了 | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 2 | 0 | 1 | |を選択してください
 | 2 | 2 | 1 | 1 | -1 | 0 | スキップ |
 | 2 | 3 | 1 | 0 | 0 | 1 | |を選択してください
 | 3 | 2 | 0 | 0 | 0 | 1 | |を選択してください

 最初は (dp[3][3][1]=3) 個の有効な順列があります。 可能な最小の最初の値は次のとおりです。`1`。 これを選択した場合、残りの 2 つの位置には追加の固定点が含まれていてはならず、唯一の完了は`1 3 2`。 そのブロックには最初に必要な順列が含まれているため、次を選択します。`1`。 

2 番目の位置で、`2`2 番目の固定点が作成されるため、その完了カウントはゼロになります。 選択する`3`唯一可能な完了を残します`2`最後の位置で。 結果は`1 3 2`。 

### サンプル 2

 入力用`3 2 1`、初期状態には 3 つの一致可能な位置があり、正確に 2 つの固定点が必要です。 

| 状態 | (s) | (a) | 必要な固定点 | カウント |
 | --- | --- | --- | --- | --- |
 | イニシャル | 3 | 3 | 2 | 0 |

 3 要素の順列から正確に 2 つの固定点を選択することは不可能であるため、カウントはゼロです。 2 つの位置が固定されると、残りの値が残りの位置に強制的に押し込まれ、3 番目の固定点が作成されます。 

初期カウントはすでに (k=1) より小さいため、アルゴリズムは次のように出力します。`-1`建設を試みることなく。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n^3+n^3\log n)) | DP には (O(n^3)) 個の状態があり、各状態には一定の作業が必要です。 構築では、各 (n) 位置で最大 (n) 個の候補を試行し、毎回最大 (n) 個の値を並べ替えます。 |
 | スペース | (O(n^3)) | DP テーブルには (O(n^3)) 個のエントリがありますが、構築状態では (O(n)) 個の追加スペースが使用されます。 |

 (n\le50) の場合、DP には約 (51^3) 個のエントリしか含まれず、構築では最大でも数千の候補州が検査されます。 これは 1 秒の制限を十分に満たす十分な小ささですが、ブルート フォースは実行可能な範囲から数十桁離れています。

 ## 特殊なケース

 のために`1 0 1`、初期状態は (s=1,a=1,r=0) です。 唯一可能な値は次のとおりです`1`ですが、これを選択すると固定小数点が作成され、必要な固定小数点の数は (-1) のままになります。 完了カウントはゼロであるため、初期状態には有効な順列がなく、アルゴリズムの出力は次のようになります。`-1`。 

のために`3 2 1`、DP は (dp[3][3][2]) から始まります。 正確に 2 つの固定点を持つ 3 つの要素の順列は存在しないため、このエントリはゼロになります。 アルゴリズムは、プレフィックスを構築する前にインスタンス全体を拒否して出力します。`-1`。 

のために`4 4 1`、初期状態は (dp[4][4][4]=1) です。 どのポジションも固定する必要があるので、第一候補は`1`が選択されている場合、`2`、 それから`3`、 それから`4`。 結果は`1 2 3 4`。 入力が代わりに要求した場合`4 4 2`、初期カウントは 1 であり (k=2) より小さいため、アルゴリズムは次のように出力します。`-1`。 

のために`4 3 1`、ターゲットはポジションの数より 1 つ少なくなります。 最初の 3 つの位置が固定されている場合、最終的な未使用の値は必然的に`4`、別の固定点が作成されます。 DP は固定位置を独立して処理するのではなく、この依存関係をキャプチャするため (dp[4][4][3]=0)、アルゴリズムは正しく出力します。`-1`。 

のために`4 0 3`、構築ではあらゆる固定点を回避する必要があります。 第一候補者`1`すぐに固定点が作成されるため、拒否されます。 最初の有効なプレフィックスは次のとおりです。`2`、DP は次に、で始まる有効な補完を比較します。`2`辞書順に。 最初の 3 つは、`2 1 4 3`、`2 3 4 1`、 そして`2 4 1 3`したがって、3 番目の答えは次のようになります。`2 4 1 3`。 これは、候補者自体が固定点を作成しない場合でも、完了をカウントする必要がある理由を示しています。
