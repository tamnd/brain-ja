 ## 解決策
 ## 問題の理解

 平面内には最大 2000 個の点のセットがあり、1 つの線上に 3 つの点はありません。 風車は、回転する線と、現在そのピボットとして機能する 1 つの点で構成されます。 線は時計回りに回転します。 別の点に到達すると、その点が新しいピボットとなり、線は同じ方向を維持して回転を続けます。 360 度完全に回転した後、プロセスは元の状態に戻ります。 

この質問は、特定の開始設定を 1 つ選択するように求めているわけではありません。 任意の初期ピボットと初期方向を選択できます。 このような風車ごとに、各点がピボットになる回数をカウントし、すべての可能な風車にわたる任意の点について可能な最大のカウントを求めます。 

制約は二次作業には十分小さいですが、Python の三次作業には十分ではありません。 (n=2000) の場合、(n^2) は約 400 万となり、実用的になります。 完全な (n^3) 計算は約 80 億回の演算に相当し、10 秒の制限をはるかに超えています。 公式コンテストの仕様では、時間制限は 10 秒、メモリ制限は 256 MB とされています。 

幾何学的入力も意図的に整数値であり、10000 で制限されているため、外積と座標の差は Python 整数に快適に適合します。 その結果、実装では角度によるソートを除いて数値ジオメトリを完全に回避できます。 以下のソリューションでは、角度は各ピボットの周囲に循環順序を確立するためにのみ使用されます。 実際の風車の遷移はその順序によってインデックス付けされるため、どのイベントが最初に来るかを決定するために浮動小数点比較は使用されません。 

最初のエッジ ケースは可能な限り最小のセットです。```
2
0 0
1 0
```点は 2 つだけなので、線はそれらの間で交互に表示されます。 360 度完全に回転する間に、各ポイントは 2 回昇格します。 答えは`2`。 ラインを方向性のないオブジェクトとして扱い、ポイントのペアのみを保存する不注意な実装では、2 つのポイント間の遷移が 1 つしか認識されず、誤った値が返されます。`1`。 

2 番目のエッジ ケースは、同じ幾何学的な線の 2 つの方向の区別です。 のために```
3
-1 0
1 0
0 2
```答えは`2`。 同じ点のペアは、360 度回転中に 2 回、つまり、方向付けされた線の方向ごとに 1 回ずつ出現する可能性があります。 180 度を法とする角度を扱うと、この区別が失われます。 

3 番目のエッジ ケースは、角度次数の円形境界です。 現在の方向が角度 0 に近く、次のイベントが 0 のすぐ下にある場合、そのイベントは (2\pi) に近い角度で表されます。 通常の先行検索では、ソートされた配列の最初のエントリから最後のエントリまでラップする必要があります。 最初のサンプルは、まさにこの状況を実行します。 

最後に、重複した座標やすべてが等しい座標は有効なケースではありません。 入力は一連の点を表し、幾何学的プロセスでは 3 つの同一直線上にない個別の点が想定されます。 したがって、次のような入力に対する意味のある正しい出力はありません。```
3
0 0
0 0
0 0
```コンテストがそれを提供することはないため、ソリューションではそのような無効な入力に対する特別な処理を追加すべきではありません。 

## アプローチ

 最も直接的なシミュレーションは、風車の 1 つの状態から開始され、回転する線が当たる次の点を繰り返し見つけます。 昇格するたびにピボットが変更されるため、1 つおきの点を検査し、新しいピボットの周りの角度位置を計算し、時計回りに回転中に最初に見つかった点を選択できます。 

これは正しいです。風車はラインが別の入力ポイントに到達したときにのみ変化するからです。 このような 2 つのイベントの間には、個別には何も起こりません。 回転方向で最初に遭遇する点を常に選択すると、シミュレーションは問題によって記述された物理プロセスに正確に従います。

### なぜ効果があるのか

 不変条件は、すべての状態が`(a, b, side)`は、回転ラインの現在の方向性とともに、正確に 1 つのプロモーション イベントを表します。 ピボット周り`b`、将来起こり得るすべてのイベントは、有向線が別の点に関連付けられた 2 つの光線の 1 つに到達したときに発生します。 ソートされたレイ リストにはこれらのイベントが角度順に含まれているため、現在のレイの先行のものを取得することは、まさに時計回りに回転中に発生する最初のイベントになります。 

後続関係は決定論的であるため、完全な状態空間は互いに素なサイクルに分解されます。 風車が完全に回転すると、このようなサイクルが 1 回だけ続きます。 そのサイクルの各状態の 2 番目のポイントをカウントすると、その風車中に各ポイントが何回昇格したかが正確にカウントされます。 考えられるすべての開始状態は何らかのサイクルに属しているため、すべてのサイクルを調べると、考えられるすべての風車が考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import atan2, pi
from bisect import bisect_left
from array import array

def solve():
    n = int(input())
    points = [tuple(map(int, input().split())) for _ in range(n)]

    if n == 2:
        print(2)
        return

    TWO_PI = 2.0 * pi

    # State:
    #   (a, b, side)
    # where b is the current pivot and the directed line has angle
    # angle(a -> b) + side * pi.
    #
    # Encode it as:
    #   ((a * n + b) << 1) | side
    #
    # There are 2*n*n slots. States with a == b are unused.
    total_states = 2 * n * n
    nxt = array('I', [0]) * total_states

    for b in range(n):
        bx, by = points[b]

        # Each entry is (angle, point, opposite_flag).
        # opposite_flag = 0 means the ray points toward point.
        # opposite_flag = 1 means the ray points in the opposite direction.
        rays = []

        for q in range(n):
            if q == b:
                continue

            qx, qy = points[q]
            ang = atan2(qy - by, qx - bx)
            if ang < 0.0:
                ang += TWO_PI

            rays.append((ang, q, 0))

            opposite = ang + pi
            if opposite >= TWO_PI:
                opposite -= TWO_PI
            rays.append((opposite, q, 1))

        rays.sort(key=lambda x: x[0])

        m = len(rays)

        # pos0[q] = position of the ray b -> q
        # pos1[q] = position of the opposite ray
        pos0 = [-1] * n
        pos1 = [-1] * n

        for i, (_, q, flag) in enumerate(rays):
            if flag == 0:
                pos0[q] = i
            else:
                pos1[q] = i

        # Fill all states whose current pivot is b.
        for a in range(n):
            if a == b:
                continue

            # side = 0:
            #   current direction is angle(a -> b)
            #   which is the ray opposite to b -> a.
            #
            # side = 1:
            #   current direction is angle(a -> b) + pi
            #   which is exactly b -> a.
            current_pos_side0 = pos1[a]
            current_pos_side1 = pos0[a]

            # side 0
            p = current_pos_side0 - 1
            if p < 0:
                p = m - 1

            _, c, next_side = rays[p]
            state = ((a * n + b) << 1)
            nxt[state] = ((b * n + c) << 1) | next_side

            # side 1
            p = current_pos_side1 - 1
            if p < 0:
                p = m - 1

            _, c, next_side = rays[p]
            state = ((a * n + b) << 1) | 1
            nxt[state] = ((b * n + c) << 1) | next_side

    visited = bytearray(total_states)
    answer = 0

    for a in range(n):
        for b in range(n):
            if a == b:
                continue

            base = (a * n + b) << 1

            for side in range(2):
                start = base | side

                if visited[start]:
                    continue

                counts = [0] * n
                cur = start

                while not visited[cur]:
                    visited[cur] = 1

                    pair = cur >> 1
                    promoted = pair % n
                    counts[promoted] += 1

                    cur = nxt[cur]

                cycle_best = max(counts)
                if cycle_best > answer:
                    answer = cycle_best

    print(answer)

if __name__ == "__main__":
    solve()
```入力は一度に 1 点ずつ読み取られ、遷移テーブルが構築されます。 特別な場合`n == 2`は数学的に必要ではありませんが、小さな遷移構造の構築を回避し、最小の場合を明示的にします。 

の`rays`リストには、1 つおきのポイントに対して 2 つのエントリが含まれます。 1 つ目は、ピボットからその点までの実際の方向です。 2 つ目は、同じ幾何学的な線を反対方向に描いたものです。 これにより、アルゴリズムが 0 度のラインと 180 度のラインを区別できるようになります。 

の`pos0`そして`pos1`配列を使用すると、現在のレイを見つけるときに二分探索が不要になります。 状態はすでにポイントを特定しています`a`、そして 2 つの方向により、どちらが正確であるかがわかります。`a`の 2 つの光線が現在の光線です。 次のイベントは、単に円形配列内の先行イベントです。 

これにより、微妙な浮動小数点の問題も回避されます。 現在の状態の角度を、ソートされた配列内の角度と比較することはありません。 現在のレイの正確な配列位置を直接記憶し、位置を 1 つ後方に移動します。 したがって、事実は、`atan2`方向を並べ替えるために使用された場合、等価境界問題は発生しません。 

遷移テーブルは、Python 整数の Python リストではなく、パックされた符号なし整数配列を使用します。 最大入力サイズでは約 800 万の状態が存在する可能性があるため、通常の Python 整数リストはかなり多くのメモリを消費します。 遷移ごとに 4 バイトなので、テーブルは約 32 MB に保たれ、訪問された配列によって追加されるのは約 8 MB だけです。 

状態エンコーディングでは、`(a * n + b) << 1 | side`。 逆の操作は、`pair = state >> 1`に続く`promoted = pair % n`。 2 番目のコンポーネントはまさにプロモートされるポイントです。そのため、これがサイクル走査中にカウントされる数量になります。 

先行インデックスは次のようにラップされます。```
p = current_pos - 1
if p < 0:
    p = m - 1
```なぜなら角度の順序は円形だからです。 このラップアラウンドを忘れることは、次のイベントが角度ゼロのすぐ下にある構成で失敗する最も簡単な方法の 1 つです。 

すべての相互座標の差は小さく、Python 整数は任意の精度を持ちます。 整数のオーバーフローは発生しません。 唯一の数値演算は、`atan2`、そしてそれは、個別の光線の循環順序を確立するためにのみ使用されます。

 ポイント`E`は 3 回昇格しますので、答えは次のようになります。`3`。 このトレースは、最大値がすべてのポイントで同じである必要がないため便利です。 アルゴリズムは、各サイクル内のポイントごとにプロモーションを個別にカウントする必要があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n^2\log n)) | 各ピボットは (2(n-1)) 個の光線をソートし、すべての状態が 1 回横断されます。 
| スペース | (O(n^2)) | 後続テーブルには (2n^2) 個のエントリがあり、訪問された配列には (2n^2) バイトがあります。 

(n=2000) の場合、州の数は約 800 万です。 コストのかかる操作は、各ピボットの周りで角光線をソートし、およそ (2n) 個の要素をおよそ (n) 種類与えることです。 その後、すべての状態が 1 回だけ処理されます。 これは、ジオメトリによって意図された 2 次スケールの状態空間であり、最大サイズで約 160 億の候補チェックを必要とする 3 次スキャンを回避します。 

コンパクトな遷移表現は、Python で特に役立ちます。これは、数学的 (O(n^2)) 空間のみが制限されているため、Python オブジェクトのオーバーヘッドが考慮されないためです。 使用する`array('I')`そして`bytearray`実装は 256 MB のコンテスト メモリ制限を快適に下回ります。 

## テストケース

 以下のテスト ハーネスは同じものを使用しています`solve`提出されたソリューションとして機能します。 各テストの標準入力をリダイレクトし、標準出力をキャプチャします。 

最大サイズの場合は、素数係数に標準の 2 次構成 (y=x^2\bmod 2003) を使用します。 最初の 2000 点を取得すると、必要な範囲内の座標が得られ、3 つの同一線上の点が回避されます。 このストレス テストでは、このケースの目的は完全な状態空間とメモリ使用量を実行することであるため、アサーションは特定の答えをハードコーディングするのではなく、数学的に有効な範囲をチェックします。 

すべて等しい座標入力は、問題の入力仮定に違反するため、意図的に解に渡されません。```python

## 特殊なケース

 ２点については、```

角度のラップアラウンドについては、サンプル 1 の最初のステップを検討してください。現在の線の角度は (0^\circ) ですが、次の関連する光線の周囲には角度が付いています。`B`角度は約 (296.6^\circ) です。 風車は時計回りに回転するため、(296.6^\circ) はゼロの次に現れる方向です。 ソートされた円形レイ リストでは、これは現在のレイの先行操作であり、先行操作は位置 0 から最終位置までラップします。 コードは明示的にこれを実行します。`if p < 0`支店。

2 番目のサンプルでは、​​内部点は、入力点の数だけでは答えが決定されない理由を示しています。 ポイント`(1,2)`他のポイントは 1 回か 2 回しか昇格しませんが、1 サイクルで 3 回昇格します。 このアルゴリズムは、凸性や深さから式を導出しようとはしません。 これは正確な状態サイクルに従い、内部ポイントの繰り返しのプロモーションを自動的にキャプチャします。 

最大サイズの場合、遷移テーブルには約 800 万の状態が含まれます。 すべての状態は、後続配列の 4 バイトと訪問先配列の 1 バイトで表されます。 レイ リストは一度に 1 つのピボットごとに構築され、そのピボットの遷移が書き込まれた後に破棄されるため、実装ではすべての角度リストを同時に保存することはありません。 これにより、二次空間に Python タプルと浮動小数点数のオーバーヘッドを乗算するのではなく、メモリ使用量が二次状態空間に比例した状態に保たれます。
