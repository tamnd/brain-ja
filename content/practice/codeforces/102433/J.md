 ## 解決策
 ## 問題の理解

 各星は 3 つの値で記述されます。 その最大寄与は (T_i) で、角度ずれのラジアンごとに (s_i) 単位の寄与が失われます。その優先方向は (a_i) です。 宇宙船が角度 (a) で打ち上げられた場合、星 (i) が寄与します。 

[
 f_i(a)=\max(0,T_i-s_i\オペレーター名{距離}(a_i,a))。 
】

 距離関数は円形であるため、角度の差は常に (0) と (\pi) の間にあります。 方向 (a) の総移動距離は、すべての星の寄与の合計です。 可能な発射方向の円全体にわたるこの合計の最大値が必要です。 

(10^5) 個の星が存在する可能性があるため、考えられるすべての候補方向についてすべての星を評価することは現実的ではありません。 入力には小数点以下 6 桁までの実数が含まれますが、答えは (10^{-6}) まで正確である必要があるため、実装では倍精度浮動小数点演算を使用する必要があります。 重要な制約は (N=10^5) です。(O(N^2)) アルゴリズムは、5 秒の制限がサポートできる範囲をはるかに超えて、最大 (10^{10}) 個のスター評価を実行します。 (O(N\log N)) または同様の効率的な解決策が必要です。 

実装を静かに破壊する可能性がある循環境界のケースがいくつかあります。 

1 つ目は影響区間交差角度 (0) です。 例えば、```
1
1 1 0.1
```正の寄与区間は (0.1-1=-0.9) から (0.1+1=1.1) です。 円上では、区間が (0) と交差することを意味し、正解は (1) です。 角度を通常の線として扱い、単に負の終点を破棄すると、ゼロに近い間違った傾きが得られます。 

2つ目は、その影響が逆方向に及ぶ星です。 例えば、```
1
3.141593 1 0
```has (T_i/s_i) slightly larger than (\pi). この星はあらゆる方向にプラスに寄与し、最小の近角 (\pi) で、最大は依然として角度 (0) の (3.141593) です。 すべての星が対蹠方向に到達する前にゼロになると仮定する不注意な実装では、無効な間隔が構築される可能性があります。 

3 番目は (s_i=0) です。 例えば、```
1
100 0 2
```打ち出し角に関係なく、常に (100) に寄与するため、答えは (100) になります。 このケースを処理せずに (T_i) を (s_i) で除算すると、ゼロ除算が発生します。 

最後に、いくつかのイベント角度が同一である場合があります。 例えば、```
2
5 2 1
5 2 1
```答えは(10)です。 両方の星はまったく同じ角度で極大値を示すため、あるイベントが別のイベントを上書きするのではなく、その角度でのすべての傾きの変化を蓄積する必要があります。 

## アプローチ

 直接的なアプローチは、打ち出し角を選択し、すべての星を評価することです。 自然な観察では、最適値はある恒星の優先方向で発生するため、(a_i) ごとに合計の寄与を評価できます。 これは正しいです。なぜなら、個々の寄与は角度において区分的に線形であり、その優先方向でのみ下降勾配の変化が発生するからです。 したがって、これらの方向の 1 つで合計の最大値を取得できます。 

ただし、(a_i) ごとに合計を評価するには、(N) 個の候補のそれぞれについてすべての (N) 個の星を調べる必要があります。 最悪の場合、これは (N^2=10^{10}) 寄与計算を実行します。 ブルートフォース手法は概念的には単純で完全に正しいですが、遅すぎます。 

重要な観察は、すべての星が区分線形関数に寄与しているということです。 星が寄与している間、その優先角度 (a_i) 付近の傾きは (a_i) に向かう途中では (+s_i)、(a_i) を通過した後は (-s_i) になります。 その寄与がゼロに達すると、その傾きはゼロになります。 

仮定してください

 [
 r_i=\min\left(\pi,\frac{T_i}{s_i}\right)
 】

 (s_i>0) の場合。 寄与度は、左端点 (a_i-r_i)、ピーク (a_i)、右端点 (a_i+r_i) の 3 つの関連角度のみで傾きを変更します。 これら 3 つの場所での傾きの変化はそれぞれ

 [
 +s_i,\qquad -2s_i,\qquad +s_i。 
】

 したがって、1 つの星はわずか 3 つの傾き変化イベントで表すことができます。 これは、スイープ ライン ソリューションで使用される中心の縮小です。 この問題の解決策の説明では、まさにこの 3 つのイベント表現を使用し、(0) と (2\pi) を交差する間隔を明示的に処理します。 

すべての候補角度で全体の合計を再計算する代わりに、角度 (0) での合計寄与を計算し、(0) のすぐ右側の合計関数の導関数を計算してから、すべての (O(N)) 個のイベント角度を並べ替えられた順序でスイープします。 

2 つの連続するイベント角度の間では、すべての星は固定された線形の動作をします。 したがって、合計寄与率も一定の傾きを持ちます。 現在の値が (E)、現在の傾きが (D)、次のイベントが角度 (x) にある場合、

 [
 E\leftarrow E+D(x-\text{前の角度})。 
】

 (x) に到達した後、そこで発生するすべての傾きの変化を加算します。 これにより、イベントごとの一定の作業のみを使用して正確な区分線形関数を維持できます。 

円形の境界には追加の詳細が 1 つ必要です。 星の左端点が負の場合、その間隔は (0) と交差するため、その (+s_i) 傾きの変化は角度 (0) の前にすでに発生しています。 (s_i) を初期勾配に追加し、(2\pi) を追加することで左側のイベントを正規化します。 同様に、右端点が (2\pi) を超える場合、右端点はラップアラウンドしているため、(0) のすぐ右側の勾配は既に右端点の (+s_i) イベントの後にあります。 初期傾きから (s_i) を減算し、(2\pi) を減算してそのイベントを正規化します。 

(s_i=0) の星は定数 (T_i) に寄与するため、初期エネルギーに寄与しますが、イベントは生成しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(N)) | 遅すぎる |
 | 最適なスイープ | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての星を読み取り、発射角度 (0) での合計寄与度を計算します。 好ましい角度 (a_i) を持つ星の場合、(0) からの距離は (\min(a_i,2\pi-a_i)) であるため、その初期寄与は直接計算可能です。 
2. (s_i=0) の場合、初期エネルギーに (T_i) を加算し、イベントを作成しません。 その貢献度は打ち出し角によって変わることはありません。 
3. (s_i>0) の場合、有効半径を計算します。 

[
 r_i=\min\left(\pi,\frac{T_i}{s_i}\right)。 
】

 円角距離が (\pi) を超えることはないため、(\pi) のキャップが必要です。 (T_i/s_i\geq\pi) の場合、星は円の周囲で非アクティブになることはありません。

1. スターに対して 3 つのイベントを作成します。 (a_i-r_i) では、傾きは (s_i) だけ増加します。 (a_i) では、傾きは (2s_i) だけ減少します。 (a_i+r_i) では、傾きは (s_i) だけ増加します。 
2. エンドポイントを間隔 ([0,2\pi]) に正規化します。 左の端点が負の場合、(s_i) を初期勾配に追加し、(2\pi) を端点に追加します。 右端点が (2\pi) を超える場合は、初期傾きから (s_i) を減算し、端点から (2\pi) を減算します。 これにより、角度 (0) のすぐ右側の関数を維持しながら、循環間隔が通常の並べ替えられたイベントに変換されます。 
3. すべてのイベントを角度別に並べ替えます。 イベントは最大 (3N) 個なので、コストは (O(N\log N)) になります。 
4. 角度 (0)、以前に計算された初期エネルギー、および初期傾きでスイープを開始します。 各イベント角度 (x) について、まずエネルギーを次のように進めます。 

[
 \text{現在の傾斜}\times(x-\text{前の角度})。 
】

 次に、このエネルギーを最大値候補として記録し、イベントの傾き変更を適用します。 

1. スイープ中に発生した最大のエネルギーを返します。 最適化は円の境界で正確に発生する可能性があるため、角度 (0) での初期エネルギーも考慮されます。 

### なぜ効果があるのか

 1 つの星の場合、その寄与は正であり、発射角は (a_i) に向かって移動しますが、寄与は一定の傾き (+s_i) で変化します。 (a_i) を超えると、傾きは (-s_i) になります。 寄与がゼロに達する点では、傾きはゼロに向かって変化します。 したがって、すべての星は、その初期寄与と 3 つの傾き変化イベントによって完全に表すことができます。 

区分線形関数の合計は、それ自体が区分線形です。 2 つの連続するイベントの間では、その傾きは一定であるため、値は前のイベントからの線形補間によって正確に取得できます。 勾配が変化するすべての点で、スイープは続行する前にその勾配を更新します。 

極大値を生み出すことができる唯一の下向き傾斜ジャンプは、星の優先角度で発生します。 カットオフ点は上向きの傾き変化を生成し、距離関数が対蹠点の周りを囲むと、その傾きも上向きに変化します。 したがって、最大値は常にイベント位置の 1 つ、特に星の優先角度または角度 (0) で見つかります。 スイープはそのようなすべての位置を訪問し、それらの間の正確な値を維持するため、記録される最大値はグローバル最大値になります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

PI = math.pi
TWO_PI = 2.0 * math.pi

def solve():
    n_line = input().strip()
    if not n_line:
        return

    n = int(n_line)

    events = []
    energy = 0.0
    initial_slope = 0.0

    for _ in range(n):
        t, s, a = map(float, input().split())

        # Contribution at angle 0.
        dist0 = min(a, TWO_PI - a)
        energy += max(0.0, t - s * dist0)

        if s == 0.0:
            # Constant contribution, so there are no slope changes.
            continue

        # The circular distance is never larger than pi.
        radius = min(PI, t / s)

        left = a - radius
        right = a + radius

        # The interval may cross angle 0.
        if left < 0.0:
            initial_slope += s
            left += TWO_PI

        # The interval may cross angle 2*pi.
        if right > TWO_PI:
            initial_slope -= s
            right -= TWO_PI

        # Slope changes:
        # left endpoint: 0 -> +s
        # center:        +s -> -s
        # right endpoint: -s -> 0
        events.append((left, s))
        events.append((a, -2.0 * s))
        events.append((right, s))

    events.sort()

    answer = energy
    current_angle = 0.0
    slope = initial_slope

    for angle, delta_slope in events:
        energy += slope * (angle - current_angle)

        if energy > answer:
            answer = energy

        slope += delta_slope
        current_angle = angle

    print(f"{answer:.10f}")

if __name__ == "__main__":
    solve()
```の最初の部分`solve`角度 (0) での関数値を計算します。 これにより、スイープの開始点が得られ、最適値が正確に円形の境界にある場合もカバーされます。 

の`s == 0.0`計算前にチェックを行う必要がある`t / s`。 このような星は常に存在しており、イベントは必要ありません。 

他の星ごとに、`radius = min(PI, t / s)`は、星の線形表現が重要となる角度範囲を表します。 (\pi) でキャップすると、円全体にわたって寄与が正のままである星も処理されます。 

追加された 3 つのイベントは、導関数の変更のみをエンコードします。 左端の導関数は 0 から (+s) に変化するため、イベントは次のようになります。`s`。 優先方向では (+s) から (-s) に変化し、合計で`-2*s`。 右側のエンドポイントでは (-s) からゼロに戻り、イベントが再び発生します。`s`。 

の`initial_slope`調整は実装の微妙な部分です。 区間交差 (0) は、スイープが開始される前にすでに左端点を通過しているため、最初にその正の傾きを含める必要があります。 逆に、右端が (2\pi) を超えてラップしている区間は、角度 (0) よりも前に右端をすでに通過しているため、その寄与はすでに下降しており、最初の微分値から最後の (+s) の傾きの変化を差し引きます。 

同じ角度のイベントを特別にグループ化する必要はありません。 あるイベントから次のイベントに進む場合、それらの角度が等しい場合はコストがゼロになるため、勾配の変更は単純に次々に適用されます。 等角イベントの処理中、関数値は変更されません。 

パイソンの`float`は IEEE-754 double であり、必要な (10^{-6}) 出力許容誤差よりも大幅に高い精度が得られます。 考えられる合計寄与の最大値は最大 (10^8) であるため、整数オーバーフローの問題もありません。

 ## 特殊なケース

 傾きがゼロの場合、次のことを考慮します。```
1
10 0 2
```寄与率は常に (10) であるため、初期エネルギーは (10) となり、イベントは生成されず、スイープには処理するものは何もありません。 答えは (10) のままです。 (s_i=0) の場合、(s_i) による除算をスキップする必要があるのはこのためです。 

区間交差角度 (0) の場合、次を考慮します。```
2
10 1 0.1
10 1 6.2
```最初のスターの有用な間隔は左に (0.1) から (-0.9) まで広がり、2 番目のスターの間隔は (6.2) から右に (2\pi) を超えて広がります。 最初の間隔は角度 (0) の直後に正の傾きをもたらしますが、2 番目の間隔は既に右端点を通過しています。 最初の傾き調整はこれら 2 つの事実を正確に処理し、正規化されたイベントは通常の昇順でスイープされます。 

(\pi) に達する影響半径については、次のように考慮します。```
1
3.141593 1 0
```有効半径の上限は (\pi) です。 左の端点は (0-\pi) で、(\pi) に正規化され、右の端点は (0+\pi) で、これも (\pi) です。 両方のエンドポイント イベントが同じ場所で発生します。 それらを組み合わせた傾き変化は、対蹠点での円周距離の先端を正確に表します。 この関数は角度 (0) で最大となり、(3.141593) が得られます。 

同時発生のイベントについては、次のことを考慮してください。```
2
5 2 1
5 2 1
```両方の星はまったく同じ中心とまったく同じイベント位置を持っています。 スイープでは、同一の座標を持つ複数のイベントが発生します。 等しい座標間で進む距離はゼロであるため、現在のエネルギーを変更せずにすべての勾配の変更が適用されます。 中心のイベントは、2 つの星が必要としているとおりに、傾きを (8) だけ減少させます。角度 (1) では最大値は (10) のままです。 

循環表現は、端点が正確に (0) または (2\pi) である場合も処理します。 角度 (0) のイベントはスイープがゼロから離れる前に処理されるため、すぐ右の傾きは正しいです。 角度 (2\pi) は (0) と同じ物理方向を表し、そのような端点は欠落した最大値候補ではなく極小値であるため、初期角度を超える個別の評価は必要ありません。
