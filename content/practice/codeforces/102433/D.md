 ## 問題の理解

 整数から始めます\(A\)そしてそれを変えたい\(B\)。 いつでも、現在の値を 1 つ増やすか、現在の値が偶数の場合は 2 で割ることができます。 各操作のコストは 1 であるため、タスクは最小操作数を見つけることです。

 の境界\(10^9\)可能なすべての値をシミュレートするアルゴリズムを除外します。\(A\)。 線形探索には約 10 億の状態が必要になる可能性がありますが、これは対数的に多くの除算だけを必要とする効率的なソリューションです。 

不用意に貪欲な実装を行うと失敗する可能性があるエッジケースがいくつかあります。 もし\(A<B\)、 例えば\(3,8\)、答えは簡単です。\(8-3=5\)。 最初に分割するとターゲットから遠ざかるだけなので、可能な限り常に分割しようとする戦略は間違っています。 もし\(A=B\)、 のような\(7,7\)の場合、答えは 0 であり、不要な操作を実行する前にループを停止する必要があります。 もし\(A>B\)そして\(A\)奇数です、例えば\(7,4\), 分割は直ちに合法ではありません。 まず最初にやらなければならないのは、\(7\to8\)、 それから\(8\to4\)、答えは 2 です。最後に、除算によって値が より小さくなるとき、\(B\)、割り算をやめて加算を使用する必要があります。 のために\(103,27\)、最適な順序は次のとおりです。\(103\to104\to52\to26\to27\)したがって、答えは 4 です。26 に達した後も分割を続けるループでは、最適値を逃すことになります。 citeturn1search0

 ## アプローチ

 直接的な総当たりアプローチは、すべての整数をグラフの状態と見なすことです。 偶数値から\(x\)、発信操作は最大 2 つあります。\(x\to x+1\)そして\(x\to x/2\)、奇数の値からのみ\( the current value \(x\)より大きい\(B\)、最終的には分割が必要になります。 すでに上にあるときに 1 つ追加する\(B\)変換を完了することはできないため、最初の分割の前に何が起こるかを検討してください。 もし\(x\)は偶数であり、2 つの加算とその後の除算を実行します。\[
x\to x+1\to x+2\to (x+2)/2,
\]は、最初に除算してから 1 を加算することと同じ値です。\[
x\to x/2\to x/2+1.
\]2 番目のバージョンでは、使用する操作が 1 つ少なくなります。 最初の除算の前にさらに加算する場合も、同様の方法で減らすことができます。 したがって、もし\(x\)が偶数の場合、最適解の最初の演算は除算です。 

もし\(x\)が奇数の場合、最初の除算の前に 1 つの加算が必要です。そうしないと除算が不正になるためです。 この 1 回の加算の後は値が偶数になるため、すぐに除算します。 除算前の追加の加算のペアは、除算後に再び移動することができ、操作が保存されます。 

これにより、決定的な貪欲プロセスが実現します。 その間\(A>B\)、 作る\(A\)必要に応じて 1 つ足しても、それを 2 で割ります。 出来るだけ早く\(A\le B\)、分割はもはや望ましくありません。 その時点で、残りの演算はすべて加算である必要があるため、答えは次のように増加します。\(B-A\)。 

すべての操作は重み付けされていない状態グラフのエッジとして表現できるため、ブルート フォースは機能しますが、グラフには関連する状態が約 10 億個含まれる可能性があるため、失敗します。 最適なパスには正規の順序があり、各除算の前に最大 1 回の加算が行われるという観察により、検索は \(O(\log A)\) ステップに集約されます。

 ## アルゴリズムのチュートリアル

 1. もし\(A\le B\)、 戻る\(B-A\)。 ターゲットはすでに現在の値以上であるため、1 を追加すると直接その値に到達します。 除算を行うと値が下方に移動し、回復するには少なくとも同数の追加の追加が必要になります。 

2. その間\(A>B\)、のパリティを検査します。\(A\)。 もし\(A\)が奇数の場合は、1 を加えて演算回数を増やします。 これが分割を合法化する唯一の方法です。 

3. 分割\(A\)2 つずつ増やして操作回数を増やします。 いつ\(A\)すでに互角だったので、これが最適な最初の動きです。 奇数の場合は前の加算を強制しました。 

4. まで繰り返します。\(A\le B\)。 これが起こった瞬間に、除算の実行を中止してください。 

5.追加\(B-A\)操作回数を計算して返します。 以来\(A\le B\)この時点では、目標を達成するには追加のみが必要です。 

重要な不変条件は、各除算の前に、アルゴリズムが現在の値を 2 で割り切れるようにするために必要な最小限の加算数を使用していることです。 偶数の値の場合、その数値は 0 であり、奇数の値の場合、それはちょうど 1 です。 除算前の余分な追加をその除算の後により安価に移動できるため、最適な解は長さを増やさずに同じ構造を持つ解に変換できます。 値が以下になると\(B\), 除算は最適な継続の一部になることはできないため、最後の直接加算も最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())

    if a <= b:
        print(b - a)
        return

    ans = 0

    while a > b:
        if a & 1:
            a += 1
            ans += 1

        a //= 2
        ans += 1

    ans += b - a
    print(ans)

if __name__ == "__main__":
    solve()
```最初の条件は全体を処理します。\(A\le B\)すぐにケース。 これは単なる最適化ではありません。すでにターゲット以下の値をアルゴリズムが分割するのを防ぎます。 

ループ内では、`a & 1`現在の値が奇数かどうかを確認します。 そうであれば、`a += 1`分割が合法になり、操作が 1 回かかります。 整数の除算`a //= 2`したがって、常に有効になります。 

順序が重要です。 まず奇数の値を偶数にしてから除算する必要があります。 私たちもチェックします`a > b`除算後、新しい値がすでにターゲットを下回っている可能性があるため、別の反復を開始する前に。 その場合、残りの距離は次のように処理されます。`b - a`。 

Python の整数はオーバーフローせず、最大の一時値は\(10^9+1\)したがって、特別な数値処理は必要ありません。

 ## 特殊なケース

 のために\(A=B\)、入力を受け取ります`7 7`。 初期状態\(A\le B\)true であるため、アルゴリズムは次の値を返します。\(7-7=0\)。 操作は必要ありません。 少なくとも 1 つの操作が必要であると想定するループでは、誤った追加のステップが導入される可能性があります。 

のために\(A<B\)、 取る`3 8`。 アルゴリズムはすぐに戻ります\(8-3=5\)。 除算するたびに現在の値はさらに小さくなるため、5 つの直接加算では改善できません。 このため、\(A\le B\)このケースは除算ループの前に処理する必要があります。 

目標を上回る奇数の値については、`7 4`。 7 は奇数であるため、アルゴリズムは次のように実行します。\(7\to8\)、 それから\(8\to4\)、2つの操作を与えます。 7 では除算を直接実行できないため、強制的に増分されます。 結果は除算後に正確に目標に達します。 

目標を下回る部門の場合は、`6 5`。 アルゴリズムが実行するのは、\(6\to3\)、その後停止します。\(3\le5\)を 2 回追加します。\(3\to4\to5\)。 合計は 3 です。値がすでに目標を下回っているため、再度分割すると作業量が増えるだけです。
