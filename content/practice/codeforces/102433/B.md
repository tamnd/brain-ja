 ## 解決策
 ## 問題の理解

 長さ (n) の配列があり、(1) から (k) までのすべての値がその中のどこかに出現します。 元の順序を維持しながらいくつかの要素を削除し、(1) から (k) までのすべての値のコピーを 1 つだけ残す必要があります。 このようなすべての部分列の中で、辞書編集的に最小の部分列が必要です。 

たとえば、配列 (2,1,3) および (k=3) の場合、有効なサブシーケンスは 1 つだけ、つまり (2,1,3) だけです。 配列に繰り返し値が含まれている場合、どの値が特定の値を表すかを選択できます。 その選択が問題を面白くするのです。 (3,2,1,3,2) を使用すると、(3) と (2) の後の出現を使用して、(3) で始まる有効な部分列よりも小さい (1,3,2) が得られます。 

制約 (n\le 200,000) は、アルゴリズムが本質的に線形であるか、または (O(n\log n)) である必要があることを意味します。 (n) と (k) が両方とも大きい場合、(O(nk)) アルゴリズムはすでに約 (4\times10^{10}) の演算を必要とする可能性がありますが、これは 2 秒の競技プログラミング ソリューションが許容できる速度をはるかに超えています。 すべての配列値が (1) と (k) の間にあるという事実により、有用な制限された値の範囲も得られるため、単純な配列で出現情報を維持できます。 

いくつかの特殊なケースでは、一見合理的な貪欲アルゴリズムが正しくなくなる可能性があります。 まず、小さい値が、すでに選択されている大きい値を常に置き換えることはできません。 考慮する```
2 2
2
1
```正しい出力は次のとおりです```
2 1
```(2) は (1) の前にのみ出現するため、(1) を最初に選択すると (2) を含めることができなくなります。 これまでに確認された最小値を常に選択する貪欲なアルゴリズムでは、誤って (1,2) を出力しようとします。 

重複により、別の微妙なケースが発生します。 のために```
3 2
1
1
2
```答えは```
1 2
```最初の (1) を選択した後は、すべての値が 1 回だけ出現する必要があるため、2 番目の (1) は無視する必要があります。 すべての出現を独立して処理すると、無効な答えが生成されます。 

3 番目のケースでは、以前に選択した複数の値を一度に置き換えます。```
5 3
3
2
1
3
2
```正しい答えは、```
1 3 2
```(1) が見つかった場合、前の (2) と前の (3) は両方とも後で表示されるため、破棄できます。 この一連の置換が欠けていると、より大きな接頭辞 (3,2,1) が残り、辞書編集的にはさらに悪くなります。 

最後に、以前に選択した値を削除できるかどうかを決定する前に、出現カウントを更新する必要があります。 のために```
3 2
2
1
2
```答えは```
2 1
```最初の (2) が選択されていますが、2 番目の (2) に到達すると、それはすでに答えに表されています。 その発生は将来の実現可能性の決定に使用できなくなるため、その発生数は依然として減らす必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるサブシーケンスを列挙し、すべての値を含むサブシーケンスを 1 回だけ保持し、辞書編集的に最小の有効なサブシーケンスを選択します。 これは正しいです。考えられるすべての答えが明示的に考慮されますが、長さ (n) の配列には (2^n) 個の部分列があります。 (n=200,000) では (2^{200000}) 個の候補があるため、列挙は完全に不可能です。 

より有用な素朴なアプローチは、左から右に答えを構築することです。 各位置で残りの配列をスキャンして、次に安全に選択できる最小値を見つけて、繰り返します。 実現可能性テストは、まだ選択されていないすべての値が、選択された位置の後にまだ存在するかどうかを確認することによって実行できます。 実現可能性テスト自体は効率的であっても、サフィックスの大部分を繰り返しスキャンすると、(O(nk)) 個の作業が発生する可能性があります。 (n=k=200,000) の場合、これは (4\times10^{10}) 回の演算のオーダーになります。 

重要な点は、各値のどの出現を使用するかを個別に決定する必要がないということです。 配列を左から右にスキャンしながら、答えをスタックとして維持できます。 現在の値が (x) で、最後に選択された値が (x) より大きいとします。 その大きい値を (x) に置き換えると、辞書編集上の順序が改善されますが、それは後で大きい値が再び出現する場合に限られます。 存在する場合は、後で出現するものを代わりに選択できるため、削除しても安全です。 そうでない場合、それを削除すると有効な回答が不可能になります。 

これにより、標準的な単調スタック パターンが得られます。 すべての値について、まだ残っている出現回数を維持します。 (x) を処理するとき、この発生はもはや将来ではないため、残りのカウントを減らします。 (x) がすでに選択されている場合はスキップします。 それ以外の場合、スタックの最上位が (x) より大きく、その最上位の値がまだ後で発生する間は、それを削除します。 次に、(x) を押します。 

ブルートフォースアプローチは、貪欲なメソッドが行う必要がある選択を明示的にチェックするため機能しますが、あまりにも多くの可能性を繰り返し探索するため失敗します。 選択した値は、別の値が残っているときに正確に置き換えられるという観察により、1 回の左から右へのスキャン中にこれらすべての決定を行うことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n)) | 候補者あたり (O(n)) | 遅すぎる |
 | サフィックススキャンの繰り返し | (O(nk)) 最悪の場合 | (O(k)) | 遅すぎる |
 | 単調スタック | (O(n)) | (O(n+k)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (1) から (k) までの各値が配列内に出現する回数を数えます。 これらの数は、現在回答に含まれている値を後で選択できるかどうかを示します。 
2. これまでに構築された答えを表す空のスタックとブール配列を作成します。`used`どの値がすでに選択されているかを知らせます。 
3. アレイを左から右にスキャンします。 現在の値 (x) について、残りの出現回数を直ちに減らします。 この時点から、現在のオカレンスは将来の代替品として利用できなくなります。 
4. もし`used[x]`はすでに true であるため、この発生を無視してください。 答えには (x) のコピーが 1 つだけ存在するため、別のコピーを取得すると、必要な一意性に違反します。 
5. それ以外の場合は、(x) をスタックの最上位の値と比較します。 スタックが空ではありませんが、その最上位が (x) より大きく、その最上位の値が配列の後半に少なくとも 1 つ出現する場合は、最上位の値を削除して未使用のマークを付けます。 

大きい値を削除すると、考えられる 2 つの答えが異なる最初の位置での辞書編集上の順序が改善されます。 後で別のオカレンスが存在するため、削除は安全です。 同じ引数が新しいスタックトップに繰り返し適用されるため、ループでは複数の値が削除される可能性があります。 
6. スタックに (x) を押して、使用済みとしてマークします。 この時点で、現在の接頭辞は、これまでに処理された要素から取得可能な辞書編集上の最小の実現可能な接頭辞です。 
7. スキャンが終了すると、スタックにはすべての値が 1 回だけ含まれます。 順番に出力していきます。 

### なぜ効果があるのか

 不変条件は、入力の接頭辞を処理した後、スタックは、(1) から (k) までのすべての値を含むように拡張できる、個別に選択された値の辞書編集上の最小のシーケンスであるということです。 

新しい値 (x) が到着すると、スタックの最後にあるより大きな値が削除の候補になります。 後でその大きな値が再び発生した場合、それを保持すると、(x) に置き換えるよりも答えが辞書編集的に悪くなるため、削除するのが最適です。 それがその後発生しない場合、それを削除すると完全な回答が不可能になるため、アルゴリズムはそれを保持します。 すでに選択されている値は、必要な 1 つの出現がすでに確保されているため、スキップされます。 したがって、すべての変更は実行可能性を維持しながら、最も早い位置を可能な限り小さくし、辞書編集的に最小の有効な部分列を与えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [int(input()) for _ in range(n)]

    remaining = [0] * (k + 1)
    for x in a:
        remaining[x] += 1

    used = [False] * (k + 1)
    stack = []

    for x in a:
        remaining[x] -= 1

        if used[x]:
            continue

        while stack and stack[-1] > x and remaining[stack[-1]] > 0:
            removed = stack.pop()
            used[removed] = False

        stack.append(x)
        used[x] = True

    print(*stack)

if __name__ == "__main__":
    solve()
```最初のパスは計算します`remaining`なので、いつでも`remaining[v]`まさに value の出現数です`v`現在の位置の右側にまだあります。 現在のオカレンスはすでに消費されているため、カウントは貪欲な決定の前にデクリメントされます。 

の`used`配列は重複した値がスタックに入るのを防ぎます。 すでに選択されている値は、スタック操作によって明示的に削除されない限り、再検討する必要はありません。 

の`while`ループはアルゴリズムの中心です。 比較`stack[-1] > x`辞書編集上の改善を捉えていますが、`remaining[stack[-1]] > 0`その値を削除することが可能かどうかをキャプチャします。 どちらの条件も必要です。 2 番目の条件を省略すると、必要な値の唯一残っているコピーが削除される可能性があります。 

要素がポップされると、その要素は`used`フラグがリセットされます。 これは、後で出現するその値を再度選択する必要がある可能性があるため重要です。 スタックには各値のコピーが最大 1 つ含まれるため、そのサイズは最大 (k) です。 

Python では、インデックス作成のトリックや整数オーバーフローの懸念はありません。 すべての配列には (1) ～ (k) の範囲の値によって直接インデックスが付けられ、入力によってそれらの値が有効であることが保証されます。 

コードにはネストされた`while`ループの合計実行時間は依然として線形です。 最終的な答えが生成される前に、すべての値をスタックにプッシュしたりスタックからポップしたりすることが最大 1 回だけ可能です。 したがって、スタック操作の合計数は (O(n)) になります。

import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    n, k = map(int, sys.stdin.readline().split())
    a = [int(sys.stdin.readline()) for _ in range(n)]

    remaining = [0] * (k + 1)
    for x in a:
        remaining[x] += 1

    used = [False] * (k + 1)
    stack = []

    for x in a:
        remaining[x] -= 1

        if used[x]:
            continue

        while stack and stack[-1] > x and remaining[stack[-1]] > 0:
            removed = stack.pop()
            used[removed] = False

        stack.append(x)
        used[x] = True

    print(*stack)

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

assert solution(
    "6 3\n2\n1\n3\n2\n1\n3\n"
) == "2 1 3\n", "sample 1"

# Provided sample 2

) == "3 2 1 4 5\n", "sample 2"

# Minimum-size input
assert solution(
    "1 1\n1\n"
) == "1\n", "minimum size"

# All values are equal, so k = 1
assert solution(
    "5 1\n1\n1\n1\n1\n1\n"
) == "1\n", "all equal values"

# Boundary condition: the first 2 cannot be replaced by 1

    "3 2\n2\n1\n2\n"
) == "2 1\n", "only safe occurrence of 2"

# Multiple values must be popped

    "5 3\n3\n2\n1\n3\n2\n"

k = 100000

maximum_input += "".join(f"{x}\n" for x in range(1, 100001))

## Edge Cases

The first edge case is when a smaller value appears after the only occurrence of a larger value. For

```テキスト
 2 2
 2
 1```

the algorithm reads (2), decrements its remaining count to zero, and pushes it. When (1) arrives, the top is larger, but `remaining[2]` is zero, so (2) stays. The result is `2 1`, which is the only valid subsequence.

The duplicate case is

```3 2
 1
 1
 2```

After the first (1), the value is marked as used. The second (1) decreases its remaining count but is skipped because it is already represented in the stack. The final (2) is added, producing `1 2`. This prevents the answer from containing duplicate values.

The replacement-chain case is

```5 3
 3
 2
 1
 3
 2```

When (3) is read, another (3) remains. When (2) arrives, the algorithm removes (3), since (2<3) and another (3) is available. When (1) arrives, another (2) remains, so (2) is removed as well. The stack becomes `1`. Later occurrences restore (3) and (2), giving `1 3 2`. This catches implementations that only perform one stack pop instead of continuing while the replacement remains beneficial.

The boundary case involving a repeated value is

```3 2
 2
 1
