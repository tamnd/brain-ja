 ## 解決策
 ## 問題の理解

 都市と道路は重みのあるツリーを形成します。 各都市 (i) には税額 (t_i) があり、都市 (u) から都市 (v) にチケットを送るコストは次のとおりです。 

[
 (t_u+t_v)d(u,v),
 】

 ここで、(d(u,v)) は、2 つの都市間の固有の経路に沿った道路料金の合計です。 

都市 (u) が勝った場合、1 枚のチケットを他のすべての都市に送ります。 すべての (n-1) 枚のチケットの合計コストが必要です。 

\sum_{v\ne u}(t_u+t_v)d(u,v)。 
】

 入力により、都市の数、その税額、および (n-1) 個の重み付けされた道路が得られます。 出力には、優勝する可能性のある都市ごとに 1 つの合計が含まれます。 

キー制約は (n\le 100000) です。 都市のすべてのペアを検査するソリューションは、およそ (10^{10}) 個のペアが存在する可能性があるため、すでに遅すぎます。 (O(n^2)) アルゴリズムでさえ、3 秒の制限時間内では到達できません。 ツリー構造により、以前に計算された答えを一定時間で更新しながら、ある都市から隣の都市に移動する方法が得られます。 

値も十分に大きいため、32 ビット整数は安全ではありません。 パスにはウェイト (1000) のエッジをほぼ (100000) 含めることができ、距離は (10^8) に近くなります。 税額を掛けてすべての都市を合計すると、答えは約 (10^{16}) になります。 Python 整数はこれを自動的に処理しますが、C++ などの言語では 64 ビット整数が必要です。 

導出における間違いを明らかにする小さなケースがいくつかあります。 1つの都市ではチケットはまったくありません。 のために```
1
7
```出力は```
0
```なぜなら、都市から都市自体までの唯一の距離がゼロだからです。 すべての都市に近隣都市があることを前提とした実装は、ここで失敗する可能性があります。 

２つの都市があることで、```
2
2 5
1 2 1000
```距離は (1000) なので、どちらかの勝者のコストは次のようになります。 

[
 (2+5)\cdot1000=7000。 
】

 出力は```
7000
7000
```よくある間違いは、勝者の税金に関係する部分だけを計算し、目的地の税金を忘れることです。 

ツリーのバランスが著しく崩れている場合は、別の問題が発生します。 のために```
3
1 2 3
1 2 1
2 3 1
```距離の合計は (3,2,3) ですが、税金で重み付けされた距離の合計は (8,4,6) です。 したがって、答えは (11,8,15) となります。 再帰的 DFS は、(100,000) 都市を含むチェーンで Python の再帰制限に達する可能性があるため、実装では反復走査を使用する必要があります。 

## アプローチ

 直接的な解決策は、勝利する可能性のあるすべての都市からツリー トラバースを実行することです。 1 回の走査で開始都市からのすべての距離が計算され、その後、((t_u+t_v)d(u,v)) を合計できます。 ツリーの走査には (O(n)) かかり、すべての (n) 都市から走査するには (O(n^2)) かかります。 最悪の場合、これは (n(n-1)) 個のエッジの有向ツリー走査、つまり (100000\cdot99999=9,999,900,000) 個のエッジ訪問を処理することを意味します。 それは利用可能な時間をはるかに超えています。 

有益な観察は、総コストが 2 つの独立した距離の合計に分割できることです。 

[
 \begin{整列}
 \text{答え}_u
 &=\sum_v(t_u+t_v)d(u,v)\
 &=t_u\sum_v d(u,v)+\sum_vt_vd(u,v)。 
\end{整列}
 】

 定義する

 [
 A_u=\sum_v d(u,v)
 】

 そして

 [
 B_u=\sum_v t_vd(u,v)。 
】

 それから

 [
 \text{answer}_u=t_uA_u+B_u。 
】

 したがって、必要なのはすべての (A_u) とすべての (B_u) だけです。 

次に、都市 (1) にツリーをルートします。 (v) が (u) の子であり、重み (w) のエッジによって接続されており、(v) のサブツリーに (s) 個の都市が含まれていると仮定します。 (u) から (v) に移動すると、(v) のサブツリー内のすべての都市は (w) 近くなり、その外側のすべての都市は (w) 遠くなります。 したがって、

 [
 A_v=A_u+w((n-s)-s)
 =A_u+w(n-2s)。 
】

 同じ推論が税加重合計にも当てはまります。 (S) をツリー全体の合計税、(S_v) を (v) のサブツリー内の合計税とします。 サブツリー内の税加重距離は (wS_v) だけ減少しますが、外側の税加重距離は (w(S-S_v)) だけ増加します。 したがって、

 # B_u+w((S-S_v)-S_v)

 B_u+w(S-2S_v)。 
】

 これは、中央ツリーの再ルート手順です。 サブツリーのサイズとサブツリーの税額がわかったら、1 つのエッジを越えて答えを移動するには一定の時間がかかります。 

ルートから 1 回のトラバースで初期値 (A_1) と (B_1) を取得できます。 その走査中に、ルートからすべての都市までの距離が判明するため、両方の合計を累積します。 次に、逆走査によってサブツリーのサイズと税額が計算されます。 最後に、前方走査によって 2 つのルート変更式が適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市 (1) にツリーをルートし、反復 DFS またはスタック走査を実行します。 すべての都市の親、その親エッジの重み、およびルートからの距離を保存します。 走査順序も記録します。 

この順序により、後で再帰せずにツリーを葉から根に向かって処理する便利な方法が得られます。 
2. 各都市を発見しながら (v)、そのルート距離を次のように累積します。 

[
 A_1=\sum_v d(1,v)
 】

 とその税金加重距離

 [
 B_1=\sum_v t_vd(1,v)。 
】

 ルートまでの距離はすでに取得されているため、追加のトラバースは必要ありません。 
3. すべてのサブツリー サイズを (1) に初期化し、すべてのサブツリー税の合計を市独自の税に初期化します。 記録された順序を逆に処理します。 すべての非ルート都市 (v) について、そのサブツリー サイズとサブツリー税額をその親に追加します。 

この通過後、`size[v]`(v) を含む、(v) 以下の都市の数です。`sub_tax[v]`それらの税額の合計です。 これらは、まさにリルート式で必要な量です。 
4. ルートの距離合計と加重距離合計をステップ 2 で計算した値に設定します。その最終的な答えは次のとおりです。 

[
 t_1A_1+B_1。 
】
 5. 元の根から葉の順序で都市を処理します。 すべての非ルート都市 (v) について、(p) をその親とし、(w) をエッジの重みとします。 次を使用して通常の距離の合計を更新します。 

[
 A_v=A_p+w(n-2,\text{size}[v])。 
】

 (n-2,\text{size}[v]) という項は、(p) から (v) へのエッジを横切るときに、遠くに移動する都市の数から、近くに移動する都市の数を差し引いた数をカウントします。 
6. 次を使用して重み付けされた距離の合計を更新します。 

[
 B_v=B_p+w(S-2,\text{sub_tax}[v]),
 】

 ここで、(S) は各都市の税金の合計です。 

同じルート変更の議論が当てはまりますが、各都市が単位負担ではなく税金を負担する点が異なります。 
7. コンピューティング

 [
 \text{答え}_v=t_vA_v+B_v
 】

 すべての都市について実行し、結果を印刷します。 

### なぜ効果があるのか

 すべての都市 (u) について、必要なコストは正確に (t_uA_u+B_u) であるため、これら 2 つの量を計算するだけで十分です。 ルートの初期値は、すべてのルート距離から直接取得されます。 任意の親子エッジ (u)-(v) を考慮します。 (v) のサブツリー内のすべての都市は距離を (-w) だけ変更し、そのサブツリーの外側のすべての都市は (+w) だけ変更します。 これにより、(A_v) の式が得られます。 各都市がその税金で重み付けされている場合、同じパーティションから (B_v) の式が得られます。 サブツリーのサイズと税額は正確であるため、各再ルート手順では、親の正確な値から子の正確な値が生成されます。 したがって、正しいルート値から開始して親から子まですべてのエッジを訪問することで、すべての都市の正しい値が計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    tax = list(map(int, input().split()))

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, w))
        graph[v].append((u, w))

    parent = [-1] * n
    parent[0] = 0
    parent_weight = [0] * n
    dist = [0] * n
    order = []

    stack = [0]

    root_dist_sum = 0
    root_weighted_dist_sum = 0

    while stack:
        u = stack.pop()
        order.append(u)

        root_dist_sum += dist[u]
        root_weighted_dist_sum += tax[u] * dist[u]

        for v, w in graph[u]:
            if v == parent[u]:
                continue

            parent[v] = u
            parent_weight[v] = w
            dist[v] = dist[u] + w
            stack.append(v)

    size = [1] * n
    sub_tax = tax[:]

    for u in reversed(order[1:]):
        p = parent[u]
        size[p] += size[u]
        sub_tax[p] += sub_tax[u]

    total_tax = sub_tax[0]

    distance_sum = [0] * n
    weighted_distance_sum = [0] * n
    answer = [0] * n

    distance_sum[0] = root_dist_sum
    weighted_distance_sum[0] = root_weighted_dist_sum
    answer[0] = tax[0] * distance_sum[0] + weighted_distance_sum[0]

    for v in order[1:]:
        p = parent[v]
        w = parent_weight[v]

        distance_sum[v] = (
            distance_sum[p] + w * (n - 2 * size[v])
        )

        weighted_distance_sum[v] = (
            weighted_distance_sum[p]
            + w * (total_tax - 2 * sub_tax[v])
        )

        answer[v] = (
            tax[v] * distance_sum[v]
            + weighted_distance_sum[v]
        )

    sys.stdout.write("\n".join(map(str, answer)))

if __name__ == "__main__":
    solve()
```最初のトラバースは無向ツリーを通過する必要があるため、隣接リストにはすべての道路の両方向が格納されます。 の`parent`配列は、トラバーサルが使用したばかりのエッジをすぐに横切って戻ってしまうのを防ぎます。 

最初のトラバースビルド`order`、すべての根の距離を計算し、2 つの根の合計を累積します。 ツリーは (100,000) 都市の単一チェーンになる可能性があるため、再帰的ではなく反復的です。 

逆パスの計算`size`そして`sub_tax`。 親より先に子を処理することで、蓄積が正しく行われます。 ルートの値はすでにわかっているため、親の値が計算された後、最後の前方パスですべての子を処理できます。 

表現`n - 2 * size[v]`そして`total_tax - 2 * sub_tax[v]`は符号付きの値です。 子サブツリーに都市の半分以上、または税総額の半分以上が含まれている場合は、負の値になる可能性があります。 コードではそれらを絶対値に置き換えてはなりません。 

ルートの親はそれ自体に設定されるため、最初の走査中に再度アクセスすることはできません。 ルートに関連付けられたエッジの重みは無関係で、ゼロに初期化されます。 

特別なループや除算はなく、Python の任意精度の整数は、潜在的に (10^{16}) スケールの答えを安全に処理します。 C++ では、すべての距離の合計と答えには次のものを使用する必要があります。`long long`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) | ツリーは一定の回数だけ走査され、すべてのエッジが (O(1)) 回処理されます。 |

import sys
import io

def solve(data: str) -> str:
    it = iter(data.split())
    n = int(next(it))
    tax = [int(next(it)) for _ in range(n)]

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        w = int(next(it))
        graph[u].append((v, w))
        graph[v].append((u, w))

    parent = [-1] * n
    parent[0] = 0
    parent_weight = [0] * n
    dist = [0] * n
    order = []

    stack = [0]
    root_dist_sum = 0
    root_weighted_dist_sum = 0

    while stack:
        u = stack.pop()
        order.append(u)

        root_dist_sum += dist[u]
        root_weighted_dist_sum += tax[u] * dist[u]

        for v, w in graph[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            parent_weight[v] = w
            dist[v] = dist[u] + w
            stack.append(v)

    size = [1] * n
    sub_tax = tax[:]

    for u in reversed(order[1:]):
        p = parent[u]
        size[p] += size[u]
        sub_tax[p] += sub_tax[u]

    total_tax = sub_tax[0]

    a = [0] * n
    b = [0] * n
    ans = [0] * n

    a[0] = root_dist_sum
    b[0] = root_weighted_dist_sum
    ans[0] = tax[0] * a[0] + b[0]

    for v in order[1:]:
        p = parent[v]
        w = parent_weight[v]

        a[v] = a[p] + w * (n - 2 * size[v])
        b[v] = b[p] + w * (total_tax - 2 * sub_tax[v])
        ans[v] = tax[v] * a[v] + b[v]

    return "\n".join(map(str, ans))

def run(inp: str) -> str:
    return solve(inp).strip()

parts = [str(n), " ".join(["1"] * n)]
parts.extend(f"{i} {i + 1} 1" for i in range(1, n))
large_input = "\n".join(parts) + "\n"

large_output = run(large_input).splitlines()

assert len(large_output) == n, "maximum-size output length"

for i in range(n):
    left = i * (i + 1) // 2
    right = (n - 1 - i) * (n - i) // 2
    expected = 2 * (left + right)
    assert int(large_output[i]) == expected, f"maximum-size case at city {i + 1}"

 | --- | --- | --- |

 |`2 / 2 5 / 1 2 1000`|`7000 / 7000`| 最大エッジ重みと考えられる両方のルート |

 最大サイズのテストでは、予想されるテキストの埋め込み (100,000) 行ではなく、閉じた形式の距離合計から予想される出力が計算されます。 ゼロベースの位置 (i) の場合、距離の合計は次のようになります。 

[
 \frac{i(i+1)}2+\frac{(n-1-i)(n-i)}2,
 】

 すべての税金は (1) であるため、航空券の費用はその 2 倍になります。 

## 特殊なケース

 単一の都市の場合、```
1
7
```横断では、距離 0 にある 1 つの都市が記録されます。 両方の根の和は 0、サブツリーのサイズは 1、最終的な式は (7\cdot0+0=0) です。 エッジがないため、再ルート手順は実行されません。 出力は正確に`0`。 

2つの都市の場合、```
2
2 5
1 2 1000
```ルートには (A_1=1000) と (B_1=5\cdot1000=5000) があり、(2\cdot1000+5000=7000) になります。 2 番目の都市のサブツリーのサイズは 1、税額は 5 です。 再ルートすると得られるもの

 [
 A_2=1000+1000(2-2)=1000
 】

 そして

 [
 B_2=5000+1000(7-10)=2000。 
】

 したがって、都市 (2) の答えは (5\cdot1000+2000=7000) となります。 これにより、同じ単一エッジの両方向がチェックされます。 

星の値が等しい場合、```
3
1 1 1
1 2 1
1 3 1
```中心には距離の合計 (2) と加重距離の合計 (2) があるため、答えは (4) になります。 葉の距離は (1,0,2) で、その合計は (3) であり、その重み付けされた距離の合計も (3) で、(6) になります。 出力`4 6 6`中心からリーフに移動するときに、サブツリー サイズの項が 1 つの都市が近づく一方、2 つの都市が遠ざかることを正しく説明していることを確認します。 

長いチェーンの場合、ツリーには (100,000) の都市が含まれる可能性があり、再帰的 DFS では (100,000) に近い再帰の深さが必要になります。 実装では代わりに、検出された都市を次の場所に保存します。`order`そして、前後に配列する処理。 ツリーが分岐するかチェーンを形成するかに関係なく、同じ再ルート式が引き続き有効であるため、最大サイズのテストでは Python の再帰に依存せずにアルゴリズムが実行されます。
