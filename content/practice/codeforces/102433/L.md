 ## 解決策
 ## 問題の理解

 この問題の演算は、通常の小数乗算ですが、1 つの重要な変更があります。複数の積が同じ小数位置にある場合は常に、それらの合計は 10 を法として計算されるため、次の位置にキャリーが移動することはありません。 

未知の数の桁が右から左に数えて 0 、a 1 、…である場合、そのキャリーレス正方形の位置 k の桁は次のようになります。 

c k ≡ i=0 ∑ k a i a k−i (mod10)。 

最大 25 桁の N の 10 進数が与えられ、キャリーレス 2 乗がちょうど N になる最小の正の 10 進整数が必要です。そのような整数が存在しない場合は、次のように出力します。`-1`。 

25 桁の制限により、考えられるルートを列挙することができなくなります。 N が 25 桁の場合、そのルートは最大 13 桁になるため、直接検索では最大 9⋅10 12 個の陽性候補を調べることになります。 候補者あたりの非常に安価な小切手であっても、1 秒の制限をはるかに超えます。 

最初の構造上の制限は長さです。 正の m 桁の数値は、ゼロ以外の可能な最大位置が 2m−2 であるキャリーレス平方を持ちます。これは、先頭の桁が 0 でない限り、先頭の桁自体が乗算され、10 を法としてゼロになることができないためであり、これは禁止されています。 したがって、結果は正確に 2m−1 桁になります。 偶数長の N は、正のキャリーレス平方根を持つことはできません。 

例えば、`15`は 2 桁なので、答えは次のようになります。`-1`。 ある数値限界までの候補ルートのみを検索する不用意な実装では、構造的に答えが不可能な場合に検索に時間を浪費する可能性があります。 

最下位桁も 10 を法とする平方でなければなりません。可能な剰余は 0、1、4、5、6、9 です。 したがって`2`すぐには無理です。 最下位位置に任意の数字を選択するだけの検索では、すぐに拒否される可能性のある多くの分岐を探索することになります。 

有効なルートが複数存在することもあるため、任意のルートを見つけるだけでは十分ではありません。 のために`121`、 両方`11`そして`99`キャリーレス平方根です。`99`キャリーが破棄された後の数字は 1、2、1 になります。 必要な答えは、`11`。 数字を昇順に検索すると、後ですべての解を並べ替えることなく最小の根を取得できます。 

最後に、ルートには内部的にゼロ桁が含まれる場合があります。 For example, the 13-digit number`1000000000000`キャリーレススクエアあり`1000000000000000000000000`。 ゼロを数値の桁数が少ないことを意味するものとして扱うと、この有効なケースが誤って拒否されます。 

## アプローチ

 直接的なアプローチは、必要な桁数ですべての可能な正の根を列挙し、そのキャリーレス二乗を計算し、それを N と比較することです。すべての可能な答えが明示的にテストされるため、これは正しいです。 25 桁の N の場合、ルートは 13 桁になり、9⋅10 12 のルートが考えられます。 キャリーレス 2 乗の計算自体は、直接実行すると O(13 2 ) 桁の演算が必要となるため、総当たりのアプローチは絶望的です。 

有益な観察は、結果の数字が右から左に決定されるということです。 a 0 、…、a k−1 がすでにわかっており、 a k を決定したいとします。 位置 k の係数は次のとおりです。 

c k ≡a 0 a k +a 1 a k−1 +⋯+a k−1 a 1 +ak a 0 (mod10)

 k を含む 2 つの用語を除くすべての用語はすでに知られています。 したがって、

 c k ≡S k +2a 0 a k (mod10)、

 ここで、 S k は、以前に選択された数字にのみ依存します。 

より便利なインデックス付けは、最下位側から数字を生成することです。 位置 k では、0 から 9 までのすべての候補数字を、正方形の既知の接頭語に対してテストできます。 未知の数字は 10 を法とする係数 2 の一次式に現れるため、使用できる値は最大 2 つです。 最初の桁には特別な方程式 a 0 2 ≡c 0 (mod10) があり、これも考えられるすべてのターゲット桁に対して最大 2 つの根を持ちます。 

これにより、検索がおよそ 10 13 個の可能性から最大 2 13 = 8192 個の分岐に変更されます。 すべての根の数字がわかったら、正方形の残りの上位の位置を確認します。 これは、ここで再帰的な数字の構築を有効にするプレフィックスの原理と同じです。つまり、キャリーレス平方の最初の k+1 桁は、ルートの最初の k+1 桁にのみ依存します。 

候補はすべての位置で昇順に生成されるため、最初に見つかった完全なルートが最小のルートになります。 あるいは、すべての有効なルートの最小値を維持することもできます。これにより、正しさの引数が走査順序に依存しなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10 n/2 n 2 ) | O(n) | 遅すぎる |
 | 数字のDFS | O(2 n/2 n 2 ) | O(n) | 承認済み |

 ここで、n≤25 は N の桁数です。 

## アルゴリズムのチュートリアル

 1. N を文字列として読み取り、その桁数を n とします。 n が偶数の場合、すぐに出力します`-1`。 m 桁の正の数のキャリーレス 2 乗は常に正確に 2m−1 桁を持つため、偶数長のターゲットは発生しません。 
2. ルートの唯一可能な桁数である m=(n+1)/2 を設定します。 再帰的な構築はその方向に進むため、N の桁を最下位から最上位に格納します。 
3. ルート桁を選択せず​​に深さ優先検索を開始します。 位置 k=0 で、0 から 9 までのすべての数字 x を試し、満足のいくものを維持します。 

x 2 mod10=N 0 .

 これは、未知の数字が畳み込み内で 1 回だけ現れる唯一の位置です。 
4. 以降の位置 k ごとに、0 から 9 までの各桁 x を試します。一時的に a k =x を設定し、計算します。 

( i=0 ∑ k , a i , a k−i )mod10.

 これがターゲット桁 N k と等しい場合にのみ再帰を続行します。 新しくチェックされた結果の数字は、位置 k 以降のルート数字に依存できないため、ここで分岐を拒否しても有効な解が破棄されることはありません。 
5. 位置 m−1 が選択された場合、その桁はゼロ以外である必要があります。 そうしないと、想定されるルートの桁数が m 桁未満になり、ステップ 1 での長さの計算と矛盾します。 
6. すべての m ルート桁が確定したら、位置 m から 2m−2 までの残りのすべての平方桁を計算し、それを N と比較します。これらの位置は、ルートに新しい未知の桁が含まれない最初の位置であるため、下半分の構築中にチェックすることはできません。 
7. すべての完全な有効な数字配列を整数に変換し、最小のものを保持します。 有効な完全な正方形に到達する分岐がない場合は、次のように出力します。`-1`。 

### なぜ効果があるのか

 再帰の深さ k では、k より下のすべてのルート桁が固定されています。 位置 k のキャリーレス平方桁はルート桁 a 0 ,…,a k のみに依存するため、その桁を正確にチェックすることで、現在の部分ルートが依然として解を導き出せるかどうかが決まります。 すべての有効なルートは、これらすべてのチェックに合格した 1 つのブランチに従うため、枝刈りすることはできません。 逆に、m 個すべてのルート桁を通じて受け入れられた分岐は、N のすべての桁に対して完全にチェックされるため、報告されたすべてのルートは真に有効です。 すべての有効な根の最小値を取ると、必要な最小の正の根が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    n = len(s)

    # A carryless square of an m-digit positive number
    # has exactly 2*m-1 digits.
    if n % 2 == 0:
        return "-1"

    m = (n + 1) // 2

    # Target digits, least significant first.
    target = [ord(ch) - ord('0') for ch in reversed(s)]

    # Root digits, least significant first.
    a = [0] * m
    best = None

    def dfs(k):
        nonlocal best

        if k == m:
            # The lower m digits were already checked while constructing
            # the root. Check the remaining digits of the square.
            for pos in range(m, n):
                total = 0
                lo = pos - (m - 1)
                hi = m - 1

                for i in range(max(0, lo), hi + 1):
                    j = pos - i
                    if 0 <= j < m:
                        total += a[i] * a[j]

                if total % 10 != target[pos]:
                    return

            value = 0
            for d in reversed(a):
                value = value * 10 + d

            if best is None or value < best:
                best = value
            return

        start = 0
        end = 10

        # The most significant digit must be nonzero.
        if k == m - 1:
            start = 1

        for x in range(start, end):
            a[k] = x

            total = 0
            for i in range(k + 1):
                total += a[i] * a[k - i]

            if total % 10 == target[k]:
                dfs(k + 1)

    dfs(0)

    return "-1" if best is None else str(best)

def main():
    s = input().strip()
    print(solve_case(s))

if __name__ == "__main__":
    main()
```Python 自体はそのような整数を簡単に処理できますが、ターゲットには 25 桁を含めることができるため、入力は文字列として保持されます。 さらに重要なのは、数字を明示的に保存すると、キャリーレス畳み込みが自然になります。 

配列`target`逆になっているので`target[0]`は単位の桁です。 ルート配列`a`同じ方向を使用するため、係数は次の位置になります。`k`単純に合計`a[i] * a[k-i]`。 

その間`dfs(k)`、位置の係数のみ`k`を確認する必要があります。 すべての用語には最大でもインデックスが含まれます`k`したがって、将来の選択によってこの係数が変更されることはありません。 これは、アルゴリズムからの重要な枝刈り条件です。 

すべての根桁が選択された後の上限チェックは、次の位置から始まります。`m`。 以下のポジション`m`再帰中にすでにチェックされています。 13 桁のルートの場合、正方形には位置があります`0`を通して`24`したがって、ループは位置を正しくチェックします`13`を通して`24`。 

Python の整数には任意の精度があるため、ルートを整数に変換するときにオーバーフローの問題は発生しません。 最大のルートには 13 桁しかありません。 

非ゼロ制限は次の場合にのみ適用されます。`k == m - 1`。 ゼロはすべての下位位置で完全に有効です。 制限を以前に適用すると、次のようなルートが誤って拒否されます。`1000000000000`。

def solve_case(s):
    n = len(s)

    if n % 2 == 0:
        return "-1"

    m = (n + 1) // 2

    a = [0] * m
    best = None

    def dfs(k):
        nonlocal best

        if k == m:
            for pos in range(m, n):
                total = 0
                for i in range(m):
                    j = pos - i
                    if 0 <= j < m:
                        total += a[i] * a[j]

                    return

                value = value * 10 + d

            return

        for x in range(start, 10):
            a[k] = x

            total = 0

                total += a[i] * a[k - i]

    finally:

 ## 特殊なケース

 対象桁数が偶数であることは不可能です。 のために`15`、長さは 2 ですが、正の m 桁のルートは常に 2m−1 桁を生成します。これは奇数です。 アルゴリズムは戻ります`-1`DFS を開始する前に、不必要な検索を回避します。 

最後の桁が 10 を法とする二次剰余でないターゲットも不可能です。 のために`2`、最初の方程式には 0 2 ≡2(mod10) が必要になります。 このような平方剰余を持つ 10 進数は存在しないため、DFS には生き残った分岐がなく、次の結果が返されます。`-1`。 

複数のルートによって任意の回答が返されてはなりません。 のために`121`、ルーツには以下が含まれます`11`そして`99`。 DFS は可能な数字を調べて完全な正方形を検証します。`best`最小の数値ルートを格納します。 結果として得られる答えは、`11`。 

先頭のゼロを短いルートの一部として扱ってはなりません。 のために`1000000000000000000000000`、ターゲットは 25 桁なので、ルートは 13 桁でなければなりません。 根`1000000000000`はまさにその長さを持ち、その唯一の非ゼロ畳み込み項は先頭の桁の 2 乗であり、25 桁のターゲットが生成されます。 この実装では、下位のすべての位置にゼロを許可しますが、最上位桁を表す最後のルート桁がゼロ以外である必要があります。 

1 桁の場合でも、再帰の境界が適用されます。 のために`6`、ルートは 1 桁なので、それより高い係数を検証する必要はありません。 単位方程式だけで有効な根が得られます。`4`そして`6`、最小値は`4`、必要な回答と一致します。
