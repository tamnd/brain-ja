 ## 解決策
 ## 問題の理解

 私たちは (N) 個の異なる単語のコレクションを持っています。 すべての単語はまったく同じ文字のセットを使用しているため、各単語は単に同じ文字の異なる並べ替えにすぎません。 1 つの単語内に文字が 2 回出現することはありません。 

2 つの単語が、正確に 2 つの位置を交換することによって他方から取得できる場合、競合します。 2 つの位置は隣接している必要はありません。 保持されるすべての単語のペアを競合しないようにしながら、できるだけ多くの単語を保持する必要があります。 

問題を考えるのに役立つ方法は、グラフとして考えることです。 各単語は頂点であり、単語が 1 回の交換で異なる場合、2 つの頂点は接続されます。 答えは、このグラフの最大独立集合です。 

制約 (N \le 500) は、実行時間が (O(N^2)) 程度のグラフ アルゴリズムには十分小さいですが、すべてのサブセットを列挙するには大きすぎます。 可能なサブセットは (2^{500}) 個あるため、最大独立集合を直接検索することは完全に不可能です。 単語には小文字のみが含まれており、どの文字も 2 回出現できないため、単語の長さは最大 26 になります。 この短い単語長により、別の有用な限界が得られます。つまり、どの単語からでも、最大 (\binom{26}{2}=325) 個の異なる単一スワップ結果が得られます。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 たとえば (N=1) の場合、入力```
1
a
```答えは 1 です。これに当てはまる言葉は他にありません。`a`衝突する可能性があります。 すべての頂点に反対側の近傍があると仮定したソリューションでは、誤って 0 が返される可能性があります。 

長さ 2 のワードは、隣接する位置の交換が特別な操作ではないことを示しています。 のために```
2
ab
ba
```2 つの単語は 2 つの位置だけを交換することで接続されているため、答えは 1 です。 一部の制限されたスワップ セットのみをチェックするソリューションでは、このエッジを見逃してしまいます。 

もう 1 つの微妙なケースは、多くの単語が存在するが、それらのどれも 1 つずつ交換していない場合です。 例えば、```
3
abc
bca
cab
```答えは 3 です。3 つの順列はすべて同じ順列パリティを持ちますが、1 つのスワップは常にパリティを変更します。 グラフに多くのエッジが含まれている必要があると仮定したソリューションでは、頂点が不必要に削除されてしまいます。 

最後に、すべての単語が一意であるという事実が重要です。 単語から単語自体へのエッジを処理する必要はありません。 すべての文字が異なるため、2 つの異なる位置を交換すると単語が変わります。 

公式のサンプル出力は、サンプル 1 が 3、サンプル 2 が 8、サンプル 3 が 4 です。 

## アプローチ

 最も直接的な総当り攻撃のアイデアは、競合グラフを構築し、単語のすべてのサブセットを試して、そのサブセットに競合するペアが含まれているかどうかを確認することです。 これは正しいです。考えられるすべての回答候補が明示的に考慮されるからです。 (N) 個の頂点のサブセットの場合、すべてのペアのチェックには (O(N^2)) のコストがかかり、(2^N) 個のサブセットが存在するため、最悪の場合でも (O(2^N N^2)) 時間がかかります。 (N=500) では、これはおよそ (2^{500}\cdot250000) ペアのチェックに相当し、これはあまり現実的ではありません。 

単語のすべてのペアを比較してグラフを構築することさえ、すでに (O(N^2L))、ここで (L\le26) になります。 最大の制約では、次のことを意味します

 [
 \binom{500}{2}\cdot26 = 3,243,500
 】

 最悪の場合は文字の比較。 この部分は管理可能ですが、一般的な最大独立集合の問題は依然として指数関数的です。 

重要な観察は、すべてのエッジが置換パリティに対して非常に特殊な影響を与えるということです。 文字の順列が偶数であるか奇数であるかに応じて、すべての単語にパリティを割り当てます。 2 つの位置を交換すると、置換パリティが 1 回だけ変更されるため、すべての競合エッジが偶数ワードと奇数ワードを接続します。 

したがって、競合グラフは 2 部構成になります。 

これにより問題は完全に変わります。 2 部グラフの場合、最大独立セットのサイズは次のとおりです。 

[
 |V|-\text{最小頂点カバー}。 
】

 ケーニッヒの定理により、2 部グラフの最小頂点カバーは最大マッチングと同じサイズになります。 したがって、答えは単純です

 [
 N-\text{最大一致数}。 
】

 もう 1 つの有益な観察は、エッジを見つけるために単語のすべてのペアを比較する必要がないということです。 長さ (L) のワードから、2 つの位置を選択してそれらをスワップすることで、考えられるすべての 1 スワップ近傍を生成できます。 そのような候補は (\binom L2) つだけです。 ハッシュ テーブルは、結果の単語が実際に入力に存在するかどうかを一定の期待時間で教えてくれます。 

すべてのペアをチェックすると正確な競合グラフが得られるため、ブルート フォースは機能しますが、最大独立セットを直接解決しようとすると失敗します。 パリティ観測によりグラフが 2 部グラフに変わり、マッチングによって多項式時間で答えが得られます。 実際のスワップによって近傍を生成すると、不必要な (N^2) ワードの比較も回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^N N^2)) | (O(N^2)) | 遅すぎる |
 | 最適 | (O(NL^2 + E\sqrt N)) | (O(NL^2 + N)) | 承認済み |

 ここで、(L\le26) は語長、(E) は競合エッジの数です。 頂点には最大で (\binom L2\le325) 個の隣接頂点があるため、(E\le O(NL^2)) になります。 

## アルゴリズムのチュートリアル

 1. すべての入力単語を、単語を頂点インデックスにマッピングする辞書に保存します。 これにより、生成された 1 スワップ ワードが入力に属するかどうかを、予想される一定時間内にテストできます。 
2. ソートされた順序で最初の単語の文字を選択し、各文字にランクを割り当てます。 すべての単語を対応するランクのシーケンスに置き換えます。 すべての単語にはまったく同じ異なる文字が含まれているため、すべての単語は同じランクの順序の順列になります。 
3. 反転を数えることにより、各順列のパリティを計算します。 反転数が偶数の単語は 2 部グラフの左側に属し、反転数が奇数の単語は右側に属します。 
4. すべての偶数パリティ ワードについて、すべての位置のペア (i<j) を試します。 これら 2 つの文字を交換し、結果の単語を辞書で調べます。 存在する場合は、対応する頂点を現在の単語の隣接リストに追加します。

任意の 2 つの位置を交換すると、順列パリティが変更されるため、生成された近傍は自動的に反対側になります。 片側からのみエッジを生成するため、2 部マッチングに必要な標準表現が得られます。 
5. この 2 部グラフに対して Hopcroft-Karp を実行します。 すべての左頂点とすべての右頂点の一致を維持します。 幅優先検索は拡張パスの可能性のあるレイヤーを見つけ、深さ優先検索はそれらのレイヤーを介していくつかの拡張パスを送信します。 
6. 結果として得られる一致サイズを (M) とします。 戻ります (N-M)。 ケーニッヒの定理によれば、(M) は最小の頂点カバーのサイズでもあり、そのようなカバーを削除すると、正確に (N-M) 個の頂点の独立したセットが残ります。 

### なぜ効果があるのか

 中心的な不変条件は、すべての競合エッジが反対の置換パリティの単語を結合することです。 1 つの転置によって順列のパリティが変更されるため、競合グラフはパリティを両側とする 2 部構成になります。 

どのグラフでも、頂点カバーの補数は独立したセットであるため、サイズ (C) の最小頂点カバーはサイズ (N-C) の独立したセットを与えます。 逆に、独立セットの補数は頂点カバーであるため、最大の独立セットのサイズは正確に (N-C) になります。ここで (C) は頂点カバーの最小サイズです。 

二部グラフの場合、ケーニッヒの定理は (C=M) を与えます。ここで (M) は最大一致サイズです。 このアルゴリズムは、競合グラフを正確に構築し、その最大一致を見つけて、(N-M) を返します。これは、結果として、スワップのない最大のセットになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    index = {word: i for i, word in enumerate(words)}

    # Every word is a permutation of the same distinct letters.
    base = sorted(words[0])
    rank = {ch: i for i, ch in enumerate(base)}

    parity = [0] * n
    left = []

    for u, word in enumerate(words):
        a = [rank[ch] for ch in word]
        inv_parity = 0

        for i in range(len(a)):
            for j in range(i + 1, len(a)):
                inv_parity ^= (a[i] > a[j])

        parity[u] = inv_parity
        if inv_parity == 0:
            left.append(u)

    # adj[u] contains only vertices on the odd-parity side.
    adj = [[] for _ in range(n)]

    length = len(words[0])

    for u in left:
        s = list(words[u])

        for i in range(length):
            for j in range(i + 1, length):
                s[i], s[j] = s[j], s[i]
                v = index.get(''.join(s))

                if v is not None:
                    adj[u].append(v)

                s[i], s[j] = s[j], s[i]

    # Hopcroft-Karp maximum matching.
    pair_u = [-1] * n
    pair_v = [-1] * n
    dist = [-1] * n

    from collections import deque

    def bfs():
        q = deque()
        found = False

        for u in left:
            if pair_u[u] == -1:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = -1

        while q:
            u = q.popleft()

            for v in adj[u]:
                pu = pair_v[v]

                if pu == -1:
                    found = True
                elif dist[pu] == -1:
                    dist[pu] = dist[u] + 1
                    q.append(pu)

        return found

    sys.setrecursionlimit(2000)

    def dfs(u):
        for v in adj[u]:
            pu = pair_v[v]

            if pu == -1 or (
                dist[pu] == dist[u] + 1 and dfs(pu)
            ):
                pair_u[u] = v
                pair_v[v] = u
                return True

        dist[u] = -1
        return False

    matching = 0

    while bfs():
        for u in left:
            if pair_u[u] == -1 and dfs(u):
                matching += 1

    print(n - matching)

if __name__ == "__main__":
    solve()
```辞書`index`順列生成とグラフ構築の間の橋渡しとなります。 単語内の 2 つの文字を交換した後、`index.get()`その単語が指定されたセットに属しているかどうかをすぐに教えてくれます。 

反転計算では、完全な反転カウントではなく、パリティのみが使用されます。 カウントが奇数であるか偶数であるかのみが重要であるため、XOR 演算で十分です。 語長は最大 26 であるため、単純な 2 次計算は十分に小さくなります。 

一時的なリスト`s`候補スワップごとに適切に変更されます。 文字は辞書検索の直後に元に戻されるため、位置のすべてのペアは元の単語から始まります。 2 番目のスワップバックを忘れると、後の候補が前の候補に依存し、グラフが破損します。 

適切なパリティ側の頂点のみが左側の頂点として反復される場合でも、一致する配列のサイズは (N) になります。 元の頂点インデックスを使用すると、辞書、隣接リスト、および一致する配列の一貫性が維持されます。 

BFS は、現在一致していないすべての左頂点から距離レイヤーを構築します。 DFS はこれらのレイヤーを尊重するエッジのみをたどるため、DFS が成功するたびに、利用可能な最短の拡張パスに沿ってマッチングが拡張されます。 BFS が空き左頂点から到達可能な一致しない右エンドポイントを見つけることができなくなると、拡張パスは残らず、マッチングは最大になります。 

Python では整数がオーバーフローすることはなく、答えは常に 0 ～ 500 の間になります。 

## 実用的な例

 ### サンプル 1

 6 つの単語はすべて次の順列です。`abc`。 それらの反転パリティにより、それらは 2 つのグループに分割されます。

 | --- | --- | --- | --- |
 |`abc`| 偶数 |`acb`、`bac`、`cba`| と一致した`acb`|
 |`acb`| 奇数 |`abc`、`cab`、`bca`| と一致した`abc`|
 |`cab`| 偶数 |`cba`、`abc`、`bca`| と一致した`cba`|
 |`cba`| 奇数 |`cab`、`bac`、`abc`| と一致した`cab`|

### サンプル 2

 11人にとって`alerts`順列の場合、パリティ分割は不均一になります。 マッチング アルゴリズムでは、独立したセットを明示的に見つける必要はありません。 すべての競合を排除するにはいくつの頂点を削除する必要があるかを見つけるだけで済みます。 

| 数量 | 値 |
 | --- | --- |
 | 単語数 | 11 |
 | 最大一致 | 3 |
 | 最小頂点カバー | 3 |
 | スワップフリーの最大セット | 8 |

 マッチングには 3 つの互いに素な競合エッジが含まれています。 3 頂点の最小頂点カバーが削除されると、残りの 8 ワードには競合エッジが含まれなくなります。 したがって、答えは (11-3=8) となり、公式サンプルと一致します。 

この例は、より小さいパリティ クラスを取得するだけでは必ずしも十分ではない理由を示しています。 1 つのパリティの任意のサブセットは常にスワップフリーですが、競合グラフが片側のすべてに一致しない場合、最適なものには両方のパリティ クラスの頂点が含まれる可能性があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(NL^2 + E\sqrt N)) | 各単語は (O(L^2)) スワップを生成し、ホップロフト カープは (O(E\sqrt N)) | を受け取ります。 
| スペース | (O(NL^2 + N)) | 隣接グラフには最大 (O(NL^2)) 個のエッジが保存されます。 

ここでは (N\le500) と (L\le26) です。 頂点には最大 325 個の可能なワン スワップ近傍があるため、グラフには片側表現で最大約 (81{,}250) 個の有向隣接エントリがあります。 これは意図した制限内に簡単に収まりますが、照合フェーズは多項式であり、指数関数 (2^N) 検索が回避されます。

import sys
import io
from itertools import permutations

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]

    index = {word: i for i, word in enumerate(words)}

    base = sorted(words[0])
    rank = {ch: i for i, ch in enumerate(base)}

    parity = [0] * n
    left = []

    for u, word in enumerate(words):
        a = [rank[ch] for ch in word]
        p = 0

        for i in range(len(a)):
            for j in range(i + 1, len(a)):
                p ^= (a[i] > a[j])

        parity[u] = p
        if p == 0:
            left.append(u)

    length = len(words[0])
    adj = [[] for _ in range(n)]

    for u in left:
        s = list(words[u])

        for i in range(length):
            for j in range(i + 1, length):
                s[i], s[j] = s[j], s[i]

                v = index.get(''.join(s))
                if v is not None:
                    adj[u].append(v)

                s[i], s[j] = s[j], s[i]

    from collections import deque

    pair_u = [-1] * n
    pair_v = [-1] * n
    dist = [-1] * n

    def bfs():
        q = deque()
        found = False

        for u in left:
            if pair_u[u] == -1:
                dist[u] = 0
                q.append(u)
            else:
                dist[u] = -1

        while q:
            u = q.popleft()

            for v in adj[u]:
                pu = pair_v[v]

                if pu == -1:
                    found = True
                elif dist[pu] == -1:
                    dist[pu] = dist[u] + 1
                    q.append(pu)

        return found

    def dfs(u):
        for v in adj[u]:
            pu = pair_v[v]

            if pu == -1 or (
                dist[pu] == dist[u] + 1 and dfs(pu)
            ):
                pair_u[u] = v
                pair_v[v] = u
                return True

        dist[u] = -1
        return False

    matching = 0

    while bfs():
        for u in left:
            if pair_u[u] == -1 and dfs(u):
                matching += 1

    print(n - matching)

 |`2 / ab, ba`| 1 | 可能な限り最小の競合グラフと正確な 1 スワップ検出 |
 |`3 / abc, bca, cab`| 3 | すべての頂点が同じパリティを持ち、競合エッジがない |
 | 500 の偶数順列`abcdefgh`| 500 | 最大 (N)、大きなグラフ入力、および同じパリティのワードが常に互換性があるという事実 |

 ## 特殊なケース

 最小サイズのケースは、```
1
a
```このアルゴリズムは、一方のパリティ側に唯一のワードを置き、ワードの長さが 1 であるため有用なスワップを生成せず、サイズ 0 のマッチングを取得します。 戻り値は (1-0=1) です。 

考えられる最小の衝突は、```
2
ab
ba
```言葉`ab`偶数パリティを持ち、`ba`奇数パリティを持っています。 位置 0 と 1 を交換する`ab`生成する`ba`, したがって、グラフには 1 つのエッジが含まれます。 Hopcroft-Karp はこれら 2 つの頂点を照合し、一致するサイズ 1 と答え (2-1=1) を与えます。 

単語が多いが矛盾がないケースは、```
3
abc
bca
cab
```3 つの順列はすべて偶数です。 単一のスワップごとにパリティが変更されるため、これら 3 つの単語のいずれも、1 回のスワップを使用して別のリストされた単語に変換することはできません。 隣接グラフは空で、マッチングのサイズは 0 で、アルゴリズムは 3 を返します。 

最大 (N) の場合は、500 の偶数順列を使用します。`abcdefgh`。 生成されたすべての 1 スワップ ネイバーは奇数ですが、入力には奇数ワードは存在しません。 したがって、隣接グラフは 500 個の頂点があるにもかかわらず空になります。 一致は 0 のままで、答えは 500 です。これにより、大きな入力に競合が含まれているはずだと誤って想定する実装が捕捉されます。 

長さの境界も自然に処理されます。 文字は繰り返すことができず、英小文字のみが使用できるため、単語には最大 26 文字を含めることができます。 このアルゴリズムはすべての (\binom L2) ペアを試行するため、(L=26) の場合、ワードごとに 325 回のスワップ試行のみが実行されます。 両方のループで次の文字が使用されるため、最後の文字に関するオフバイワンの問題は発生しません。`range(length)`そして (i<j) が必要です。
