 ## 解決策
 ## 問題の理解

 頂点に 1 から (N) までの番号が付けられた接続された無向グラフがあります。 アリスは 2 つの色のうち 1 つをすべてのエッジに割り当てます。 色を確認した後、ボブは頂点 1 から頂点 (N) までのルートを選択します。 ルート上の 2 つの連続するエッジの色が異なる場合は、色の変化が 1 回カウントされます。 ボブは変更をできるだけ少なくしたいと考えていますが、アリスは最小限の変更をできるだけ大きくするためにカラーリングを選択します。 

必要な出力は、アリスがすべてのルートで保証できる 1 から (N) までの色の変更の最大数です。 

キーの数量は、ぬりえゲームが示すよりもはるかに単純であることがわかります。 (d) を頂点 1 から頂点 (N) までの通常の最短経路距離とします。 答えはまさに (d-1) です。 2 つの公式サンプルには、それぞれ答え 0 と 3 があります。 

最大 (100,000) 個の頂点と (100,000) 個のエッジがある場合、多くの可能なカラーリングやパスを探索するアルゴリズムは完全に実行不可能です。 (O(N^2)) であっても、すでに最大の入力に対する約 (10^{10}) 回の演算を意味しており、1 秒のコンテスト制限をはるかに超えています。 (O(N+M)) の BFS など、基本的に頂点と辺の数に比例する作業を行うグラフ トラバーサルが必要です。 

最短経路距離との関係が見逃されると、簡単に誤答を引き起こす可能性のあるいくつかのエッジケースがあります。 まず、1 から (N) への直接エッジはすぐに答え 0 を返します。たとえば、次のようになります。```
2 1
1 2
```唯一のルートには 1 つのエッジがあるため、連続するエッジはなく、したがって色の変更は起こりません。 (d) のような数式は誤って 1 を返しますが、正しい答えは 0 です。 

2 番目のケースは、長さが 2 の最短パスを持つグラフです。```
3 2
1 2
2 3
```アリスは、最初のエッジを赤、2 番目のエッジを青に色付けして、1 つの変更を強制できます。 答えは 1 です。変更の数がルート上のエッジの数より 1 少ないことを忘れた不注意な実装では、2 が返されます。 

3 番目のケースは、非常に長いルートの横に短いルートが存在する場合です。```
4 4
1 4
1 2
2 3
3 4
```ボブは直接エッジ (1) ～ (4) を取るだけなので、アリスは色の変更を強制できません。 別のルートに 3 つのエッジが含まれており、2 つの色の変更がある可能性がある場合でも、答えは 0 です。 アリスは、特定のルートの変更を最大化するのではなく、ボブの最良のルートを破らなければなりません。 

## アプローチ

 直接的な総当たりアプローチでは、(M) エッジの考えられるすべての赤と青の色を列挙します。 このようなカラーリングは (2^M) 通りあります。 各カラーリングについて、ボブの最適値は、現在の頂点と前のエッジのカラーを含むように状態を拡張し、同じカラーに沿って継続する場合のコストが 0、カラーの切り替えのコストが 1 である 0-1 最短パス アルゴリズムを使用することによって計算できます。これには、1 つのカラーリングに (O(N+M)) 時間がかかるため、合計は (O(2^M(N+M))) となります。 (M=100000) では、定数係数を考慮する前でさえ、これは事実上不可能です。 

ブルート フォースが機能するのは、アリスが行う可能性のあるすべての決定を明示的に考慮し、ボブの最適化を正確に解決するためです。 色の数が指数関数的であるため、失敗します。 有益な観察は、実際にはアリスの色を構築する必要がないということです。 答えは、頂点 1 と頂点 (N) の間の通常の最短経路距離によってのみ決まります。 

その距離を (d) とします。 アリスがグラフにどのような色を付けても、ボブは正確に (d) のエッジを含む最短パスを選択できます。 (d) 個のエッジのシーケンスには (d-1) 個の隣接するペアしかないため、最大で (d-1) 個の色の変化を含めることができます。 したがって、アリスは (d-1) 以上を強制することはできません。 

興味深いのは、アリスがいつでも (d-1) を達成できることを示していることです。 頂点 1 から BFS を実行し、(dist[v]) を 1 から (v) までの最短距離とします。 (dist[u]) と (dist[v]) の小さい方のパリティに従って、すべてのエッジ ((u,v)) に色を付けます。 言い換えれば、端点が BFS レベル (k) および (k+1) にあるエッジには、(k) のパリティによって決定されるカラーが与えられます。 エンドポイントの BFS 距離が同じエッジは、同じ最小距離ルールを使用して割り当てることもできます。 

1 から (N) までの任意のルートを考えます。 (dist[1]=0) および (dist[N]=d) であるため、ルートは最終的に BFS レベル 1、次にレベル 2、というようにレベル (d) まで到達する必要があります。 ルートが下からレベル (k+1) に到達する最初のエッジはレベル (k) と (k+1) を接続する必要があるため、その色は (k) のパリティによって決まります。 連続する最初に到達するエッジは (k) と (k+1) に対応するため、色が異なります。 したがって、連続するレベルの各ペアの間に少なくとも 1 つの色の変化が発生します。 

レベル 0 の後に通過するレベルは (d) あり、すべての可能なルートで少なくとも (d-1) の変更が行われます。 上限と組み合わせると、最適値は正確に (d-1) になります。 

これにより、ゲーム全体が 1 つの BFS に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^M(N+M))) | (O(N+M)) | 遅すぎる |
 | 最適 | (O(N+M)) | (O(N+M)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 無向グラフの隣接リストを作成します。 ボブはグラフをどちらの方向にも移動できるため、各入力エッジは両方向に保存されます。 
2. 頂点 1 から開始して BFS を実行します。BFS は正しいトラバーサルです。すべてのエッジのコストが等しいため、最初に頂点に到達したときに記録される距離は、頂点 1 からのエッジの最小数になります。 
3. 頂点 (N) に到達するまで BFS を続けます。 結果の距離 (dist[N]) は、1 から (N) までの最短ルートの長さです。 
4. 出力 (dist[N]-1)。 最短ルートには (dist[N]) 個のエッジが含まれるため、色の変化が発生する可能性がある隣接するペアは (dist[N]-1) 個だけになります。 

減算は可能な限り短い距離でも有効です。 グラフは接続されており、(N\neq1) であるため、(dist[N]\ge1) が得られ、答えが負になることはありません。 

### なぜ効果があるのか

 (d=dist[N]) とします。 上限については、ボブは常に (d) エッジを持つ最短ルートを選択できますが、(d) エッジを持つルートには (d-1) を超える色の変更を含めることはできません。 したがって、アリスは (d-1) 以上を強制することはできません。

下限については、BFS 層 (0,1,\ldots,d) を考慮します。ここで、層 (k) には、頂点 1 からの距離 (k) にある頂点が含まれています。アリスは、(k) のパリティに従って、層 (k) と (k+1) を接続するエッジに色を付けることができます。 レイヤ 0 からレイヤ (d) までのすべてのルートは、連続するレイヤ間の各境界を通過する必要があります。 これらの境界の最初の交差に割り当てられる色は交互になるため、連続する境界のすべてのペアが少なくとも 1 つの色の変化に寄与します。 境界のペアは (d-1) 個あるため、すべてのルートには少なくとも (d-1) 個の変更があります。 

上限と下限が一致し、答えが正確に (dist[N]-1) であることが証明されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    dist = [-1] * n
    dist[0] = 0

    q = deque([0])

    while q:
        u = q.popleft()

        if u == n - 1:
            break

        for v in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    print(dist[n - 1] - 1)

if __name__ == "__main__":
    solve()
```隣接リストでは、頂点ごとに 1 つのリストが使用されます。 すべての無向入力エッジ ((a,b)) について、コードは (b) を (a) のリストに挿入し、(a) を (b) のリストに挿入します。 これにより、隣接行列に必要な (O(N^2)) 個のストレージではなく、(O(N+M)) 個のストレージが得られます。 

の`dist`配列は (-1) で始まります。これは、頂点がまだ訪問されていないことを意味します。 頂点 1 には、キューに入れられる前に距離 0 が割り当てられます。 BFS が (u) の未訪問の近傍を発見するたびに、その距離は次のようになります。`dist[u] + 1`。 

BFS は距離が減少しない順序で頂点を処理するため、(N) がキューから削除された場合の早期終了は安全です。 その時点で、(N) の記録された距離はすでに最短経路距離になっています。 

アリスのぬりえを保存する必要はまったくありません。 この証明では、そのようなカラーリングが BFS レベルから構築できるという事実のみを使用しますが、アリスが強制できる値は最短経路距離によって完全に決定されます。 

ここでは Python 整数はオーバーフローせず、最大距離は最大 (N-1) です。 したがって、最終的な減算は 0 から (99999) までになります。 

## 実用的な例

 ### サンプル 1

 グラフには頂点 1 から頂点 3 までの直接エッジが含まれているため、BFS はすぐに目的地に到達します。 

| 現在の頂点 | 距離 | 新たに発見された頂点 | 新しい距離 |
 | --- | --- | --- | --- |
 | 1 | 0 | 3 | 1 |
 | 1 | 0 | 2 | 1 |

 最短距離は (d=1) なので、答えは (d-1=0) となります。 これは、ボブのルートにエッジが 1 つだけあり、色の変化が発生する可能性のある連続したエッジが存在しない境界ケースを示しています。 公式のサンプル出力は 0 です。 

### サンプル 2

 グラフには頂点 4 に到達する 2 つの対称的な方法があり、次に頂点 7 に到達する 2 つの対称的な方法があります。 

| 現在の頂点 | 距離 | 新しく発見された頂点 |
 | --- | --- | --- |
 | 1 | 0 | 2、3 |
 | 2 | 1 | 4 |
 | 3 | 1 | 4 |
 | 4 | 2 | 5、6 |
 | 5 | 3 | 7 |
 | 6 | 3 | 7 |

 BFS は (dist[7]=4) を検出します。 1 から 7 までのすべてのルートには少なくとも 4 つのエッジが必要ですが、Alice はすべてのルートに少なくとも 3 つの変更が含まれるように BFS レイヤーに色を付けることができます。 ボブは最短の 4 エッジ ルートを選択できるため、可能な最大値も 3 になります。 アルゴリズムは (4-1=3) を出力し、公式サンプルと一致します。 

この例では、複数の最短パスの存在が問題にならない理由も示しています。 アリスのレイヤーベースのカラーリングは、これらすべてを同時に処理します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N+M)) | BFS は、すべての頂点を最大 1 回訪問し、すべての無向エッジを一定の回数検査します。 |
 | スペース | (O(N+M)) | 隣接関係リストには (2M) 個の指定された隣接関係エントリが格納され、距離配列とキューは (O(N)) 個の追加スペースを使用します。 |

 (N,M\le100000) を使用すると、アルゴリズムは入力サイズで線形作業のみを実行します。 これは、1 秒のグラフ問題で予想されるスケール内に十分収まりますが、これらの制限では色の指数関数的な列挙は不可能です。

import io
from collections import deque

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    graph = [[] for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    dist[0] = 0
    q = deque([0])

    while q:
        u = q.popleft()

        if u == n - 1:
            break

        for v in graph[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    print(dist[n - 1] - 1)

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

"""

 ## 特殊なケース

 1 から (N) への直接エッジは、最も重要な下限ケースです。 のために```
2 1
1 2
```BFS が割り当てる`dist[1] = 0`そして`dist[2] = 1`。 アルゴリズムは出力します`1 - 1 = 0`。 ボブは単一のエッジを使用し、単一のエッジには色を比較する隣接エッジがないため、アリスは変更を強制できません。 

正確に 2 つのエッジの最短パスの場合、```
3 2
1 2
2 3
```BFS は距離 0、1、および 2 を生成します。アルゴリズムは (2-1=1) を返します。 アリスは (1)-(2) を赤、(2)-(3) を青に着色できるため、ボブは一度色を変更する必要があります。 隣接するエッジのペアは 1 つだけあり、これは 2 つの変更が不可能であることも証明しています。 

短いルートと長いルートの両方を含むグラフの場合、```
4 4
1 4
1 2
2 3
3 4
```BFS は、距離 1 で頂点 4 を直接検出します。グラフにルート (1\rightarrow2\rightarrow3\rightarrow4) が含まれていることも問題ではありません。 ボブは色の変化を最小限に抑えており、常に直接エッジを選択できるため、アリスの保証は 0 です。これがまさに、関連するグラフの数量が最長ルートやグラフ内の頂点の数ではなく、最短距離である理由です。 

純正チェーンの場合、```
5 4
1 2
2 3
3 4
4 5
```固有のルートには 4 つのエッジが含まれます。 BFS は頂点 5 に距離 4 を割り当て、答えは 3 です。アリスは 4 つのエッジに沿って色を交互に変更し、3 つの変更を生成します。 エッジが 4 つ未満のルートはないため、これは上限に達します。 

頂点が (100000) 個ある最大サイズのチェーンの場合、最短距離は (99999) であるため、答えは (99998) になります。 より一般的には、(100000) 個の頂点を持つ接続されたグラフは (99999) より長い最短パスを持つことはできず、BFS 実装はルートやカラーリングを列挙しようとせずにグラフ全体を (O(N+M)) 時間で処理します。
