 ## 解決策
 ## 問題の理解

 2番目の袋には次のものが入っていることがわかります`y`ジャガイモ。 最初のバッグにはもともと何らかの正の数が含まれていました`x`、しかしその価値は失われました。 残っている唯一の情報は、ジャガイモの総数です。`x + y`、で割り切れました`k`を超えませんでした`n`。 

タスクは、可能なすべての値を出力することです。`x`これらの条件を満たすものを昇順に並べます。 

制約は単純な算術解を即座に示します。 値自体は次のように大きくできます。`10^9`したがって、可能な限りすべてを反復します`x`から`1`に`n`一般的な設定では高すぎるでしょう。 同時に状態も`n / k ≤ 10^5`非常に明らかです。 の倍数という意味です`k`まで`n`せいぜい`100000`したがって、有効な合計を直接反復処理することは完全に安全です。 

重要な観察は、実際には任意の数値を検索しているわけではないということです。 で割り切れる合計のみを考慮します`k`。 

見落としやすいエッジケースがいくつかあります。 

合計が既知のバッグを超えることはできないと仮定します。 

入力：```
10 1 10
```合計は以下で割り切れる必要があります`1`、しかしまた満足する必要があります`x + 10 ≤ 10`、強制的に`x ≤ 0`。 以来`x`正の値でなければなりません。正解は次のとおりです。```
-1
```不注意な実装により、誤って次のものが含まれる可能性があります。`0`。 

最初の有効な倍数が次の結果を生成する場合、別の注意が必要なケースが発生します。`x = 0`。 

入力：```
5 5 15
```の倍数`5`まで`15`は`5, 10, 15`。 

合計の場合`5`そして`10`、私たちは得ます`x = 0`そして`x = 5`。 正の値のみが許可されるため、答えは次のようになります。```
5 10
```ゼロを除外するのを忘れると、出力は不正確になります。 

もう 1 つの微妙な状況は、次の値より大きい倍数がない場合です。`y`。 

入力：```
8 10 15
```の唯一の倍数`10`を超えない`15`は`10`、それは与える`x = 2`。 それは正しいので、答えは次のようになります。```
2
```条件は全体に関するものであり、全体に関するものではありません`x`それ自体は次のように割り切れます`k`。 よくある間違いはチェックです`x % k == 0`、このケースは誤って拒否されてしまいます。 

## アプローチ

 ブルートフォースアプローチは簡単です。 私たちはあらゆる可能な値を試します`x`から`1`に`n - y`。 各候補者について、次のことを確認します。`(x + y) % k == 0`。 すべての有効な値が回答に追加されます。 

これが機能するのは、条件を個別に検証するのが簡単であるためです。 問題は規模だ。 最悪の場合、`n`到達できる`10^9`したがって、すべての候補を反復処理するには、現実的なレベルをはるかに超える最大 10 億回のチェックが必要になります。 

可分性条件の構造により、より適切な方向性が得られます。 推測する代わりに`x`, ジャガイモの合計数について考えることができます。 

合計`x + y`の倍数でなければなりません`k`。 つまり、有効な合計は次の形式になります。$x+y=m\cdot k$ある整数に対して`m`。 

したがって、可能な限りすべてを繰り返すのではなく、`x`のすべての倍数を繰り返します。`k`まで`n`。 倍数ごとに`t`、次のように計算します。$x=t-y$もし`x > 0`であれば、それは有効な答えです。 

重要な違いは候補者の数です。 あるのは`n / k`の倍数`k`まで`n`、そして問題はこの量が最大であることを保証します`10^5`。 これにより、最適化されたソリューションが容易に十分に高速になります。

 | ブルートフォース | O(n) | お(1) | 遅すぎる |
 | 最適 | O(n / k) | O(1) 出力を除く | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`y`、`k`、 そして`n`。 
2. すべての倍数を反復処理します。`k`から`k`まで`n`。 
3. 倍数ごとに`t`、計算する`x = t - y`。 
4. かどうかを確認します。`x`はポジティブです。 

この問題では、最初の袋には少なくとも 1 つのジャガイモが含まれている必要があります。`x = 0`は無効です。 
5. もし`x > 0`、回答リストに追加します。 
6. すべての倍数を処理した後、次のようにします。 

回答リストが空の場合は、印刷します`-1`。 それ以外の場合は、収集されたすべての値をスペースで区切って出力します。 

### なぜ効果があるのか

 有効な構成はすべて、次の 2 つの条件を満たす必要があります。$x+y\le n$そして$(x+y)\bmod k=0$アルゴリズムは、次の倍数ごとに列挙します。`k`を超えないもの`n`。 このような各倍数は、ジャガイモの可能な合計数を表します。 引き算`y`の唯一の対応する値を返します`x`。 

有効な合計はすべてそれらの倍数の中に含まれている必要があるため、有効な答えを見逃すことはできません。 肯定的な回答のみを受け入れるため、無効な回答は含めることはできません`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

y, k, n = map(int, input().split())

ans = []

for total in range(k, n + 1, k):
    x = total - y
    if x > 0:
        ans.append(str(x))

if ans:
    print(" ".join(ans))
else:
    print(-1)
```ループは次の倍数を直接反復します。`k`。 これは問題の数学的構造と一致し、無関係な値のチェックを回避します。 

表現`range(k, n + 1, k)`生成します:```
k, 2k, 3k, ...
```まで`n`。 

それぞれの合計について、以下を使用して欠損金額を再構築します。```
x = total - y
```陽性チェックは非常に重要です。 値の場所`x == 0`最初の袋には元々少なくとも 1 つのジャガイモが含まれていたため、これらは無効です。 

このソリューションでは、回答が文字列としてすぐに保存されるため、最終的な印刷ステップがシンプルかつ効率的になります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    y, k, n = map(int, input().split())

    ans = []

    for total in range(k, n + 1, k):
        x = total - y
        if x > 0:
            ans.append(str(x))

    if ans:
        print(" ".join(ans))
    else:
        print(-1)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    return sys.stdout.getvalue().strip()

# provided sample
assert run("10 1 10\n") == "-1", "sample 1"

# custom cases
assert run("5 3 20\n") == "1 4 7 10 13", "basic valid sequence"

assert run("1 1 2\n") == "1", "minimum positive answer"

assert run("5 5 15\n") == "5 10", "exclude x = 0"

assert run("999999999 1000000000 1000000000\n") == "1", "large values"

assert run("8 10 15\n") == "2", "x itself need not be divisible by k"
