 ## 解決策
 ## 問題の理解

 数字で構成される文字列が与えられます。`<`、 そして`>`文字。 すべてのクエリは部分文字列を選択し、それを小さなテープ言語のスタンドアロン プログラムとして扱います。 

インタプリタは 2 つの状態を保持します。 現在の位置は文字列の 1 文字を指し、現在の方向は左または右のいずれかです。 最初は左端の文字から開始して右に移動します。 

数字はカウンターのように動作します。 インタプリタが数字にアクセスすると、現在の値を出力し、その数字を 1 つ減らします。 その数字がすでに`0`、プログラムから完全に消えます。 数字を処理した後、ポインタは現在の方向に 1 ステップ移動します。 

シンボル`<`そして`>`方向を変えるだけ。 方向を更新すると、ポインタが 1 ステップ移動します。 追加のルールが 1 つあります。直後にポインターが別の方向記号に止まった場合、前の方向記号は消えます。 

すべてのクエリについて、次の各桁が何回あるかを数えなければなりません。`0`に`9`完全な実行中に出力されます。 

制約は非常に小さいです。 文字列の長さとクエリの数はどちらも最大です。`100`。 クエリごとにかなり重いシミュレーションであっても許容されます。 解決策`O(n^2)`あるいは`O(n^3)`合計操作量は制限内に簡単に収まります。 

難しい部分はパフォーマンスではなく、説明どおりにインタプリタを実装することです。 いくつかの詳細は誤って扱われやすいものです。 

よくある間違いの 1 つは、数字を印刷する前に更新することです。 考慮する：```
1
```正しい動作は次のとおりです。```
print 1
digit becomes 0
print 0
digit disappears
```出力数は次のとおりです。```
0 -> 1 time
1 -> 1 time
```最初に減少させてから印刷すると、誤って`1`。 

もう 1 つの微妙なケースは、方向記号の削除です。 次のようなプログラムがあるとします。```
><
```から始めます`>`、方向が右になり、次へ進みます`<`。 新しい文字は方向記号でもあるため、前の文字は`>`すぐに消えます。 この削除を忘れると、将来のインデックスが変更され、シミュレーションが中断されます。 

削除後のインデックスのシフトもバグの原因となります。 考慮する：```
0<
```印刷します`0`、それを消去すると、残ったプログラムは`<`。 現在のポインタは、短縮された配列内の正しい次の文字を参照する必要があります。 不注意な実装では、削除を調整する前にポインタをインクリメントし、誤って文字をスキップしてしまうことがよくあります。 

## アプローチ

 最も直接的な解決策は、文字通りインタプリタをシミュレートすることです。 

クエリごとに、部分文字列を抽出し、文字のリストなどの変更可能な構造に格納します。 私たちは現在の位置と方向性を維持します。 すべてのステップで、ステートメントの正確なルールを実行し、文字が消えた場合はプログラムを更新し、印刷された桁を数えます。 

この総当たりシミュレーションはすでに十分に高速です。 数字は、消えるまでに限られた回数しか減少できません。 方向記号も一度だけ消えることがあります。 部分文字列の長さは最大でも`100`、クエリごとのインタプリタ ステップの合計数はごくわずかです。 

大まかな上限は簡単に導き出すことができます。 すべての桁が最大で貢献します`10`消える前に印刷されます。 すべての方向の記号が消えるのは最大でも 1 回だけです。 最悪の場合でも、クエリで実行される操作はわずか数千件です。 

課題は、突然変異下での正しさです。 文字列の長さは動的に変化するため、削除後にインデックスを慎重に更新する必要があります。 重要な点は、制約が十分に小さいため、複雑な最適化を必要としないことです。 忠実なシミュレーションは、状態を圧縮したり遷移を事前計算したりするよりも簡単で安全です。

 ## アルゴリズムのチュートリアル

 1. クエリごとに、部分文字列を抽出し、変更可能な文字リストに変換します。 

実行中に数字や方向記号が消える可能性があるため、可変性が必要です。 
2. 現在位置を初期化する`pos = 0`そして方向`dir = 1`。 

私たちが使用するのは`1`右用と`-1`左用。 
3. 繰り返しながら`0 <= pos < len(program)`。 

ポインタが現在のプログラム境界を離れるとすぐに実行が停止します。 
4. 現在の文字が数字の場合:

 その数字の解答カウンターをインクリメントします。 

数字が`0`、リストから文字を消去します。 それ以外の場合は 1 つ減らします。 

次に、現在の方向に 1 ステップ移動します。 

インタプリタは最初に現在の値を出力するため、削除は出力後に行う必要があります。 
5. 現在のキャラクターが`<`または`>`:

 それに応じて方向を更新します。 

このシンボルが消える可能性があるため、現在のインデックスを保存してください。 

新しい方向へ一歩前進します。 
6. 方向記号から移動した後、新しい位置がまだプログラム内にあるかどうか、および新しい文字も存在するかどうかを確認します。`<`または`>`。 

両方の条件が当てはまる場合は、前の方向記号を消去します。 
7. 現在のポインタの前の文字を削除する場合は、ポインタのインデックスを 1 つ減らします。 

これにより、削除後の配列の左シフトが補正されます。 
8. ポインターがプログラムを終了するまで続行します。 

### なぜ効果があるのか

 シミュレーションでは、インタプリタ定義とまったく同じ状態、つまり現在の可変プログラム、現在のポインタの位置、移動方向が維持されます。 

すべてのインタープリタ ルールはステートメントと同じ順序で適用されます。 数字は修正前に印刷され、方向変更は移動前に発生し、方向記号は別の方向記号に着地した後にのみ削除されます。 

唯一注意が必要な部分は、削除後のインデックスのメンテナンスです。 現在のポインタの前の文字が消えるたびに、後続のすべてのインデックスが 1 つずつ左にシフトします。 ポインタを調整すると、次の不変条件が保持されます。`pos`インタープリターが次にアクセスする必要があるのと同じ論理文字を常に参照します。 

各ループ反復は 1 つのインタープリタ ステップを正確に反映するため、生成される桁数は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(sub):
    s = list(sub)
    ans = [0] * 10

    pos = 0
    direction = 1

    while 0 <= pos < len(s):
        cur = s[pos]

        if cur.isdigit():
            d = int(cur)
            ans[d] += 1

            if d == 0:
                s.pop(pos)

                if direction == -1:
                    pos -= 1
            else:
                s[pos] = str(d - 1)
                pos += direction

        else:
            direction = -1 if cur == '<' else 1

            old_pos = pos
            pos += direction

            if 0 <= pos < len(s) and s[pos] in '<>':
                s.pop(old_pos)

                if old_pos < pos:
                    pos -= 1

    return ans

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    out = []

    for _ in range(q):
        l, r = map(int, input().split())

        res = simulate(s[l - 1:r])
        out.append(' '.join(map(str, res)))

    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    solve()
```このソリューションはインタープリターの規則に直接に従います。 

Python 文字列は不変であるため、各クエリの部分文字列はリストになります。 削除は頻繁に発生するため、リスト操作により実装がよりクリーンになります。 

ポインターが現在の有効範囲を出ると、メイン ループは終了します。 プログラムは動的に縮小するため、常に現在の長さと比較します。 

数字の処理には 2 つの別々の分岐があります。 数字の場合`1`を通して`9`、その場にあるキャラクターを減らして通常どおりに移動します。 のために`0`、文字を完全に消去します。 削除後のポインタの更新は微妙です。 左に移動している場合、配列は現在の論理的な次の位置の前に縮小するため、デクリメントします。`pos`もう一度。 

方向記号は再度慎重に調整する必要があります。 まず、更新された方向に従って移動し、次に目的地が別の方向シンボルであるかどうかを確認します。 その場合は、以前のものを消去します。 削除したインデックスが現在位置より前にある場合、現在位置が 1 つ左に移動するため、次のように補正します。`pos -= 1`。 

これらのインデックス修正は、正しいシミュレーションと、削除後に文字を黙ってスキップするソリューションとの違いになります。

 ## 特殊なケース

 次のプログラムを考えてみましょう。```
0
```実行は数字から始まります`0`。 インタプリタが出力します`0`、それ以上減らすことができないため、文字を削除します。 ポインタが空のプログラムの外側を指すようになったので、実行が停止します。 

アルゴリズムはこれを正しく処理します。`d == 0`ブランチは、印刷をカウントした直後に文字を削除します。 

ここで次のことを考えてみましょう。```
><
```ポインターは次から始まります`>`、右に方向を変え、次へ進みます。`<`。 目的地は方向記号でもあるので、前の`>`消えます。 ポインタが上に置かれるようになりました`<`、それはプログラムのすぐ外に左に送信されます。 

実装では、次を使用してこの動作を再現します。`old_pos`移動後にのみ前のシンボルを削除します。 

最後に、次のことを考慮してください。```
1<
```ポインタが印刷されます`1`、桁を次のように変更します。`0`、そしてすぐに進みます`<`。 の`<`方向を左に変えて元に戻ります`0`。 の`0`が出力されて削除され、その後ポインタは左に抜けます。 

ここで重要なのは、左に移動しながら削除した後のインデックス調整です。 それなし`pos -= 1`削除ブランチでは、配列が縮小された後、シミュレーションが間違った場所から続行されます。
