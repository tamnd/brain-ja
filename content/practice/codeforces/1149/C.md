 ## 解決策
 ## 問題の理解

 オイラー ツアー トラバーサルによってルート付きツリーをエンコードするかっこの文字列が与えられます。 すべての開始括弧は根付きツリーのエッジを下っていくことに対応し、すべての閉じ括弧は同じエッジを上って戻ることに対応します。 ウォークはルートで開始および終了し、各エッジが正確に 2 回横断されるため、文字列は有効なルート付きツリー構造を表すことが保証されます。 

各クエリはツリーを直接変更しません。 代わりに、現在のブラケット シーケンス内の 2 つの位置を交換し、有効なツリー エンコーディングであることが保証された新しいシーケンスを生成します。 結果として得られるシーケンスごとに、それが表すツリーの直径を計算する必要があります。 

木の直径は、任意の 2 つの頂点間の最大距離です。 ルート付きツリーに関しては、ノードのすべてのペアにわたる、それらを接続する一意の単純なパスの長さの最大値です。 

重要な課題は、最大 200,000 までの長さの括弧の長いシーケンスで任意のスワップを繰り返し実行しており、各スワップ後に暗黙のツリーのグローバル構造プロパティを計算する必要があることです。 

制約を直接読み取ると、クエリごとにツリーを再構築するソリューションは直ちに除外されます。 ブラケット シーケンスからツリーを構築するには線形時間がかかり、すべてのペアまたは直径の 2 倍の BFS の再計算も線形になります。 最大 100,000 のクエリで、$O(nq)$アプローチは不可能です。 

より微妙な制約は、スワップが有効性を維持しながらローカル構造を完全に破壊する可能性があることです。 これにより、グローバル バランス構造を注意深く追跡せずに、静的なデカルト ツリーや静的なセグメント解釈などの固定分解の維持に依存するソリューションを回避できます。 

特に危険なエッジケースは、非常に離れた位置でスワップが発生する場合です。 たとえば、最初と最後の文字を交換すると、木の高さと直径に密接に関係しているネストの深さの分布が完全に変わる可能性があります。 ブラケット構造の変化が局所的であることを前提としたアプローチは失敗します。 

## アプローチ

 ブルートフォースの見方は簡単です。 クエリごとに、文字列にスワップを適用し、かっこからルート ツリーを再構築し、すべての深さを計算するか、2 パス DFS を実行して直径を取得し、結果を出力します。 ツリーの再構築は線形です$n$、直径の計算も線形です。 これは次のことにつながります$O(nq)$、で$10^5$スケールは次のものを意味します$10^{10}$実現可能性をはるかに超えた操作。 

構造的な洞察は、この表現の直径を実際に決定するものを認識することから得られます。 括弧の順序は任意ではありません。 それはダイクの言葉です。 有効なルート付きツリーのエンコーディングはバランスの取れた括弧構造に対応し、深さはツリー内のルートからの距離に対応します。 

この方法でエンコードされたツリーの直径は、純粋にプレフィックスの深さの動作の観点から表現できます。 プレフィックスバランス配列を定義すると$d[i]$ここで、各 '(' は +1 に寄与し、各 ')' は -1 に寄与します。この場合、ノードの深さはプレフィックス深さに対応し、ノード間の最大距離はこの深さプロファイルの極値に依存します。 実際、直径は、最も遠いノードの最も低い共通祖先に対応する、慎重に選択されたプレフィックス間の最大の垂直方向の広がりから導き出すことができます。 

スワップ後、シーケンスはグローバルに変更されますが、必要な計算はプレフィックス深さ構造に関する集約情報のみに依存します。 これは、2 つの位置の交換とプレフィックス合計のグローバルな極値プロパティの再計算をサポートする動的構造を配列全体で維持することを示唆しています。 

重要な観察は、直径がプレフィックス合計配列から導出される 4 つのキー値、つまり最小プレフィックス、最大プレフィックス、および潜在的な分割点によって分離されたサブツリー間の距離に対応するプレフィックスの極値の最適な組み合わせによって決定されることです。 これにより、問題は、ポイント更新 (スワップによって引き起こされる) の下で一連のセグメント集合体を維持し、プレフィックス極値のグローバル関数をクエリすることに軽減されます。 

ブラケット シーケンスを +1 と -1 の配列としてモデル化します。 各スワップは 2 ポイントの更新です。 プレフィックスの合計配列はグローバルに変化しますが、セグメント ツリー ノードは合計だけでなく、プレフィックスの最小値、プレフィックスの最大値、サフィックスの最小値、サフィックスの最大値、およびセグメント内の直径寄与の最適な内部候補も維持できます。 2 つのセグメントを結合する場合、これらの集約を使用して、境界を横切るパスが直径にどのように寄与するかを計算できます。 

したがって、問題は、セグメント ツリーがポイント更新をサポートし、セグメントごとに複合「ツリー直径記述子」を維持することに帰着します。 それぞれの交換は、$O(\log n)$、各クエリはルートから回答されます。$O(1)$。

 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 括弧文字列は、「(」が +1、「)」が -1 である配列として解釈されます。 この配列上にセグメント ツリーを構築し、各ノードがそのセグメントに関する情報を保存します。 

1. 入力文字列を整数配列に変換します。$a$ここで、「(」は +1 になり、「)」は -1 になります。 これにより、プレフィックスの合計がルート ツリー エンコーディングの深さを表すようになります。 
2. 各ノードがセグメントを表すセグメント ツリーを構築します。$[l, r]$セグメントの合計を格納します。 連結全体にわたるプレフィックスの合計がそれに依存するため、この合計が必要です。 
3. 各ノードについて、その開始オフセットを基準にして、そのセグメント内の最小プレフィックス合計と最大プレフィックス合計も維持します。 これにより、トラバースがセグメント内でどの程度深くなったのか、浅いのかを追跡できるようになります。 
4. 各セグメント内の全体的な最適直径の候補を維持します。 この値は、セグメント内全体、または分割点を左から右に横断する範囲内で達成可能な最大距離を表します。 
5. 2 つの子セグメントを結合する場合、左側の子の合計を加算して、右側の子のプレフィックス値を調整します。 これにより、連結全体でプレフィックスの深さが正しく調整されます。 
6. マージ中に、左サフィックス極値と右プレフィックス極値を使用して最適なクロスセグメント パスを計算します。 これは、最長のパスが両方の半分のノードを使用するケースをキャプチャしています。 
7. 各スワップ操作により、配列内の 2 つの位置が更新され、セグメント ツリーが更新されます。$O(\log n)$ポジションごとに。 
8. 各スワップの後、ツリー全体の直径がルート ノードの最適値に保存され、直接出力できます。 

重要な不変条件は、すべてのセグメント ツリー ノードが、あたかも独立したブラケット シーケンスであるかのように、その間隔に関するすべての必要な情報を正しく表すことです。 2 つのセグメントがマージされる場合、すべての可能なパスは完全に片側に存在するか、境界を 1 回だけ交差するかのいずれかであり、両方のケースを正確に評価するには、保存された集約で十分です。 

この不変式により、グローバルな再計算が必要ないことが保証されます。 すべてのアップデートは影響のみを及ぼします$O(\log n)$すべてのグローバル直径情報はマージ機能を通じて保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "minp", "maxp", "best")
    def __init__(self, s=0, mn=0, mx=0, best=0):
        self.sum = s
        self.minp = mn
        self.maxp = mx
        self.best = best

def merge(left: Node, right: Node) -> Node:
    res = Node()
    res.sum = left.sum + right.sum

    res.minp = min(left.minp, left.sum + right.minp)
    res.maxp = max(left.maxp, left.sum + right.maxp)

    cross = max(
        right.maxp + left.sum - left.minp,
        left.maxp - (left.sum + right.minp)
    )

    res.best = max(left.best, right.best, cross)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [Node() for _ in range(4 * self.n)]
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            val = self.arr[l]
            self.t[v] = Node(val, min(0, val), max(0, val), 0)
            return
        m = (l + r) // 2
        self.build(v*2, l, m)
        self.build(v*2+1, m+1, r)
        self.t[v] = merge(self.t[v*2], self.t[v*2+1])

    def update(self, v, l, r, i, val):
        if l == r:
            self.arr[i] = val
            self.t[v] = Node(val, min(0, val), max(0, val), 0)
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v*2, l, m, i, val)
        else:
            self.update(v*2+1, m+1, r, i, val)
        self.t[v] = merge(self.t[v*2], self.t[v*2+1])

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    arr = [1 if c == '(' else -1 for c in s]
    st = SegTree(arr)

    def apply(i):
        arr[i] *= -1
        st.update(1, 0, len(arr)-1, i, arr[i])

    out = []
    out.append(str(st.t[1].best))

    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        if a != b:
            apply(a)
            apply(b)
        out.append(str(st.t[1].best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装モデルは、2 つの独立したポイント更新として交換されます。 各更新はセグメント ツリーの上に変更を伝播し、再計算のみを行います。$O(\log n)$ノード。 ルート ノードは常に現在のグローバル直径を維持します。 

マージ機能は重要な部分です。 これは、接頭辞の合計表現を深さの違いに関する幾何学的な推論に変換します。 クロスタームは、あるセグメントで始まり別のセグメントで終わるパスを捕捉します。これは、直径が両方の子を超えることができる唯一のケースです。 

実装の微妙な詳細は、プレフィックスの最小値と最大値がセグメント オフセットを基準にして解釈される必要があることです。 セグメントを結合するときに適用される左サムシフトにより、右セグメントの構造がグローバル座標で正しく位置合わせされることが保証されます。

 ## 特殊なケース

 重大なエッジ ケースは、スワップが完全に深くネストされた領域内で発生する場合です。 このような場合、ローカルサブツリー構造のみが変化しますが、プレフィックス極値はほとんど変化しません。 セグメント ツリーは引き続き影響を受けるリーフのみを更新し、ルートは構造の再構築を必要とせずに一貫して直径を再計算します。 

もう 1 つのケースは、非常に早い '(' と非常に遅い ')' を交換することです。 これにより、プレフィックス合計プロファイル全体を平坦化できます。 マージ ロジックはグローバル プレフィックスの最小値と最大値を再計算するため、これを正しくキャプチャし、更新が伝播した直後に直径が減少します。 

最後のケースは、元の文字列を復元するスワップの繰り返しです。 各更新は対称的であり、保存されたノードには履歴的な依存関係が存在しないため、セグメント ツリーは自然に初期状態に戻ります。
