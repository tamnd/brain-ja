 ## 問題の理解

 タイルの入った袋が与えられ、それぞれに次のいずれかのラベルが付けられています。`1`または`2`。 私たちのタスクは、プレフィックスの合計 (最初の要素の合計、最初の 2 つの要素の合計など) を計算するときに素数となる合計の数が最大になるように、すべてのタイルをシーケンスに配置することです。 出力は、この最大値を達成するタイルの順列です。 

タイルの数、`n`、最大200,000まで上がる可能性があります。 シーケンスは 1 と 2 のみで構成されているため、プレフィックスの合計の最大値は次のようになります。`2 * n`。 すべての順列を試すブルートフォースアプローチは不可能です。`n!`利用可能な操作よりもはるかに速く成長します`n`約20万。 すべてのシーケンスを体系的にチェックすることさえ問題外です。 線形または最悪の場合でも線形演算時間で機能するアプローチが必要です。 

明らかではないエッジ ケースには、数値の 1 つが優勢であるシーケンスが含まれます。 たとえば、入力がすべて 1 の場合、プレフィックスの合計は 1、2、3、... のみになります。`n`。 1 が使用可能な場合に 2 で開始すると、最初のプレフィックスの合計は 2 (素数) になりますが、次は 2 に残りの 1 を加えたものになり、素数の 3 がスキップされる可能性があります。同様に、入力がすべて 2 の場合、最初のプレフィックスの合計は 2 ですが、次は 4 であり、素数ではありません。 プライムを最大化するには、これらの小さな配列を注意深く扱うことが重要です。 

## アプローチ

 単純な総当たりアプローチでは、タイルのすべての順列を列挙し、それぞれの素数プレフィックスの合計の数を計算します。 これは、順列ごとに線形時間でプレフィックスの合計をチェックできるため、原理的には機能しますが、順列の数は階乗になります。`n`。 たとえ`n = 20`、`20!`おおよそです`2.4 * 10^18`、それは完全に不可能です。 ブルート フォースは、すべての順序を試行することが保証されるため機能しますが、大量の入力の場合は計算が爆発的に増加するため失敗します。 

重要な洞察は、任意の順列を考慮する必要がないということです。 タイルには値 1 または 2 しかないため、どのシーケンスが初期の素数プレフィックス合計を生成するかを推論できます。 最小の素数は 2、3、5、7、11、... です。初期の接頭辞の合計で素数を最大化するには、最初の 2 つの要素の合計が 3 (2 の後の最初の奇数素数) になるようにします。 これは、`2`最初に、続いて`1`両方が存在する場合。 を使用したら、`2`そして`1`、残りの 1 をすべて配置し、次に残りの 2 をすべて配置します。 この貪欲な戦略により、プレフィックスの合計が 2、3 に達し、その後も予測可能な方法で増加し続けることが保証されます。

 ## アルゴリズムのチュートリアル

 1. の数を数えます`1`と`2`入力に ​​s が入っています。 させて`count1`そして`count2`これらの数量を保管します。 カウントがわかれば、すべての順列を検索しなくてもシーケンスを直接構築できます。 
2. 空の結果リストを初期化します。 順列を順番に構築していきます。 
3. 両方の場合`count1`そして`count2`が正の場合は、を追加します`2`続いて`1`結果リストに。 減少`count1`そして`count2`それに応じて。 これにより、最初の 2 つのプレフィックスの合計が 2 と 3 (最初の 2 つの素数) になることが保証されます。 
4. 残りをすべて追加します`1`結果リストに移動します。 1 ごとにプレフィックスの合計が 1 ずつ増加し、シーケンス内で可能な限り次の素数にヒットします。 
5. 残りをすべて追加します`2`結果リストに移動します。 1 が使い果たされた後、2 を追加するたびに合計が 2 ずつ増加し、シーケンスを予測可能な状態に保ちます。 
6. 結果リストを出力します。 

効果がある理由: 配置することで`2`それから`1`まず、接頭辞の合計 2 と 3 を確保します。最初に残りの 1 を埋めることで、5、7、11 などの連続する小さな素数にできるだけ早くヒットすることが保証されます。 2 を最後に配置すると、初期の小さな素数を不必要にスキップすることがなくなります。 この貪欲な構築では、素数の構造とタイルの制限された値が尊重され、順列を徹底的にチェックすることなく、素数プレフィックスの合計の最大数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
tiles = list(map(int, input().split()))

count1 = tiles.count(1)
count2 = tiles.count(2)

result = []

if count1 > 0 and count2 > 0:
    result.append(2)
    result.append(1)
    count2 -= 1
    count1 -= 1

result.extend([1] * count1)
result.extend([2] * count2)

print(' '.join(map(str, result)))
```このソリューションでは、最初にタイルをカウントし、次に貪欲戦略を適用します。 最初の文字を配置する前に、1 と 2 の両方が存在することを確認します。`2`そして`1`。 残りのタイルは予測可能な順序で追加され、off-by-one エラーを回避します。 結果はスペースで区切られた文字列として出力されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    tiles = list(map(int, input().split()))
    count1 = tiles.count(1)
    count2 = tiles.count(2)
    result = []
    if count1 > 0 and count2 > 0:
        result.append(2)
        result.append(1)
        count2 -= 1
        count1 -= 1
    result.extend([1] * count1)
    result.extend([2] * count2)
    return ' '.join(map(str, result))

# provided sample
assert run("5\n1 2 1 2 1\n") in ["2 1 1 1 2", "2 1 1 2 1"], "sample 1"

# custom: all 1s
assert run("4\n1 1 1 1\n") == "1 1 1 1", "all 1s"

# custom: all 2s
assert run("3\n2 2 2\n") == "2 2 2", "all 2s"

# custom: single tile
assert run("1\n1\n") == "1", "single 1"
assert run("1\n2\n") == "2", "single 2"

# custom: two tiles
assert run("2\n1 2\n") in ["2 1", "1 2"], "two tiles"
assert run("2\n2 1\n") in ["2 1", "1 2"], "two tiles order"

# custom: large input
assert run("6\n2 2 1 1 2 1\n") in ["2 1 1 1 2 2"], "mixed large"
