 ## 解決策
 ## 問題の理解

 構築する必要があります`n`2 つのプロパティを同時に持つ個別の正の整数。 

まず、すべての数値のペアは、次の値より大きい公約数を共有する必要があります。`1`。 つまり、すべてのペアについて`(ai, aj)`、それらの gcd は等しくありません`1`。 

次に、セット全体の gcd は次と等しくなければなりません。`1`。 単一の素数を使用してすべての数値を割り算することはできません。 

一見すると、これらの条件は矛盾しているように見えます。 ペアごとの gcd は常に自明ではない必要がありますが、グローバルにすべての数値が 1 つの共通因数を共有することはできません。 このタスクは純粋に建設的なものです。必要なのは有効なセットを出力することだけです。または、`-1`そのようなセットが存在しない場合。 

入力には単一の整数が含まれています`n`、友達の数、そして構築しなければならない整数の数。 以来`n ≤ 50`、課題はパフォーマンスではなく、適切な数学的構造を見つけることです。 出力数値には最大 100 桁を含めることができるため、非常に大きな整数も許可されます。 

この問題の最も危険な部分は、ペアワイズ gcd とグローバル gcd の違いを誤解していることです。 

たとえば、次のような数字があります。```
6 10 15
```次の理由により、完璧に動作します。```
gcd(6,10)=2
gcd(6,15)=3
gcd(10,15)=5
gcd(6,10,15)=1
```不注意なアプローチでは、すべての数値を次のような固定値の倍数にしようとする可能性があります。`2`。 これはすべてのペアごとの gcd 条件を満たしますが、配列全体の gcd も少なくとも`2`、これは 2 番目の要件に違反します。 

もう一つの微妙なエッジケースは、`n = 2`。 

2 つの数値を作成しようとするとします`a`そして`b`。 条件`gcd(a,b) ≠ 1`すでに、共通の gcd がより大きい値であることを意味します。`1`。 しかし、2 つの数字の場合は次のようになります。```
gcd(a,b) = gcd(a,b)
```ペアワイズ gcd とグローバル gcd は同じ量です。 したがって、ペアごとの gcd が より大きい場合、`1`、すべての数値の gcd が等しくなることはありません。`1`。 解決策は存在しません。 

単純な実装ではこれが見逃され、次のようなメッセージが出力される可能性があります。```
6
10
```しかしその後：```
gcd(6,10)=2
gcd(6,10)=2
```グローバル gcd は、`1`。 

もう 1 つの簡単な間違いは、重複した番号を作成することです。 不用意に対称構造を使用すると、たとえ gcd 条件が成立していても 2 つの位置が等しくなり、区別性に違反する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。候補配列を生成し、それらがすべての条件を満たすかどうかをテストします。 

各候補セットについて、すべてのペアごとの gcd をチェックし、セット全体の gcd も計算します。 ペアワイズチェックのコスト`O(n²)`gcd の計算。 以来`n`だけです`50`、検証自体は安価です。 

本当の問題は検索スペースです。 までの数字だけ試してみても`10^6`、可能な個別の配列の数は天文学的に多くなります。 制約が反対方向に引っ張られるため、ランダム生成は信頼できません。 ペアごとの gcd を自明ではなくするのは簡単で、合計の gcd を等しくします。`1`は簡単ですが、両方を同時に満たすことは驚くほど制限的です。 

重要な観察は、素数を使用すると gcd 関係を正確に制御できるということです。 

いくつかの異なる素数を取るとします。```
p1, p2, p3, ..., pn
```次に、次のように定義します。```
ai = product of all primes except pi
```たとえば素数の場合`2,3,5`:```
a1 = 3*5 = 15
a2 = 2*5 = 10
a3 = 2*3 = 6
```任意の 2 つの数値は、おそらく 1 つを除いてすべての素数を共有するため、それらの gcd は明らかに よりも大きくなります。`1`。 

同時に、すべての数字に素数が現れることはありません。 プライム`pi`が欠けています`ai`。 すべての素数がどこかに存在しないため、配列全体の gcd は次のようになります。`1`。 

この構造は問題をきれいに解決します。 

唯一残っている問題は、`n = 2`。 

2 つの数字の場合:```
a1 = p2
a2 = p1
```彼らの gcd は次のようになります`1`、ペアワイズ条件に違反します。 もっと根本的に言えば、有効な解決策は存在しません。`n = 2`、前述したように。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. もし`n == 2`、印刷`-1`。 

2 つの数値を同時にペアごとの gcd が次より大きくすることはできません`1`合計 gcd は以下に等しい`1`両方の条件が同じ gcd を参照しているためです。 
3. 最初の生成`n`素数。 

各数値が正確に 1 つの素数を除外できるように、個別の素数が必要です。 
4. 生成されたすべての素数の積を計算します。 

この値を次のようにします。```
P = p1 * p2 * ... * pn
```5. すべてのインデックスについて`i`、次のように構築します。```
ai = P / pi
```各数値には、1 つの固有の欠落素数を除くすべての素数が含まれます。 
6. 構築されたすべての数値を出力します。 

なぜ効果があるのか:

 すべての数字のペアは少なくとも共有します`n - 2`素数。 以来`n ≥ 3`、少なくとも 1 つの共通素数が常に残るため、すべてのペアごとの gcd は次より大きくなります。`1`。 

すべての数値の gcd について、任意の素数を考慮します。`pi`。 番号`ai`含まれていない`pi`、 それで`pi`配列全体の gcd を分割することはできません。 これは、構成内のすべての素数に当てはまります。つまり、すべての数値を割る素数はないということです。 セット全体の gcd は正確に`1`。 

区別性も自動的に続きます。 各数値は異なる素数を省略しているため、2 つの積が等しくなることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate_primes(cnt):
    primes = []
    x = 2

    while len(primes) < cnt:
        ok = True

        for p in primes:
            if p * p > x:
                break
            if x % p == 0:
                ok = False
                break

        if ok:
            primes.append(x)

        x += 1

    return primes

def solve():
    n = int(input())

    if n == 2:
        print(-1)
        return

    primes = generate_primes(n)

    total = 1
    for p in primes:
        total *= p

    for p in primes:
        print(total // p)

solve()
```最初のセクションでは不可能なケースを扱います`n = 2`。 This must be checked before construction because no valid pair exists.

 の`generate_primes`関数は最初のものを生成します`n`試算除算を使用した素数。 以来`n ≤ 50`、これでも十分以上の速度です。 必要な最大の素数は小さいため、単純な実装でも制限内で快適に動作します。 

素数を生成した後、コードは素数を乗算して 1 つの積を生成します。`total`。 

各出力値は次のようになります。```
total // p
```これにより、完全な積からちょうど 1 つの素因数が削除されます。 

構築された値が 64 ビットの制限を超える可能性があるため、ここでは Python 整数を使用すると便利です。 Python は任意の精度を自動的に処理し、この問題では非常に大きな整数が明示的に許可されます。 

操作の順序は多少重要です。 最初に完全な積を 1 回計算し、次に各素数で除算します。 インデックスごとに積を個別に再計算することもできますが、このアプローチの方がクリーンであり、乗算の繰り返しも避けられます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import gcd
from functools import reduce

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def generate_primes(cnt):
        primes = []
        x = 2

        while len(primes) < cnt:
            ok = True

            for p in primes:
                if p * p > x:
                    break
                if x % p == 0:
                    ok = False
                    break

            if ok:
                primes.append(x)

            x += 1

        return primes

    out = io.StringIO()

    n = int(input())

    if n == 2:
        out.write("-1\n")
        return out.getvalue()

    primes = generate_primes(n)

    total = 1
    for p in primes:
        total *= p

    arr = []

    for p in primes:
        arr.append(total // p)

    for x in arr:
        out.write(str(x) + "\n")

    return out.getvalue()

def validate(output: str, n: int):
    if n == 2:
        return output.strip() == "-1"

    arr = list(map(int, output.strip().split()))

    assert len(arr) == n
    assert len(set(arr)) == n

    for i in range(n):
        for j in range(i + 1, n):
            assert gcd(arr[i], arr[j]) != 1

    assert reduce(gcd, arr) == 1

    return True

# provided sample
assert validate(run("3\n"), 3)

# minimum impossible case
assert run("2\n").strip() == "-1", "n=2 impossible"

# small valid case
assert validate(run("4\n"), 4)

# larger case
assert validate(run("10\n"), 10)

# maximum constraint
assert validate(run("50\n"), 50)
