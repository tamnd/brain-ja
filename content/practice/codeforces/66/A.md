 ## 問題の理解

 10 進整数が文字列として与えられます。 この数値は最大 100 桁と非常に大きくなる可能性があるため、多くのプログラミング言語の通常の整数型に適合しない可能性があります。 

タスクは、この値を格納できる最小の Java 整数型を決定することです。 使用可能なタイプは次の順序でチェックされます。`byte`、`short`、`int`、`long`、そして最後に`BigInteger`。 各プリミティブ型には固定の包含範囲があります。 範囲に指定された数値が含まれる最初の型を出力する必要があります。 

主な問題は入力サイズにあります。 100 桁の整数は 64 ビットの符号付き整数よりもはるかに大きいため、固定幅の整数を使用する言語では、入力を通常の数値型に直接変換することは危険です。 不注意に実装すると、比較が行われる前にオーバーフローが発生する可能性があります。 

制約は入力サイズの点で非常に小さいです。 長さが最大 ​​100 の文字列を 1 つだけ処理するため、線形時間の作業でも簡単です。 問題は最適化に関するものではなく、安全な比較と境界値の正確な処理に関するものです。 

いくつかの特殊なケースでは、誤ったソリューションが静かに破壊される可能性があります。 

次の入力を考えてみましょう。```
128
```正しい答えは次のとおりです。```
short
```

`byte`で終わります`127`、境界は包括的です。 厳格な`<`代わりに比較`<=`拒否するだろう`127`間違っているか、受け入れるか`128`間違っています。 

もう一つの危険なケースは次のとおりです。```
9223372036854775808
```正しい答えは次のとおりです。```
BigInteger
```この値は、符号付き 64 ビット整数の最大値よりちょうど 1 大きい値です。 C++ または Java では、これを直接解析して`long long`または`long`溢れてしまうだろう。 より安全なアプローチは、任意精度の算術演算または文字列の直接比較です。 

小さいですが微妙な例は次のとおりです。```
2147483647
```正しい答えは次のとおりです。```
int
```これは正確な上限です`int`したがって、アルゴリズムは制限を包括的なものとして扱う必要があります。 

## アプローチ

 ブルートフォースアプローチでは、数値をますます大きな数値型に解析し、失敗を捕捉しようとします。 Python では、Python の整数は任意の精度であるためこれは機能しますが、固定幅の整数を使用する言語ではこれは危険になります。 100 桁の値を通常の整数型に解析すると、比較する前にオーバーフローが発生する可能性があります。 

もう 1 つのブルート フォース スタイルの解決策は、入力文字列を各範囲内のすべての可能な整数と比較することですが、これは明らかに実行不可能です。 さえ`long`範囲には以上が含まれます$10^{18}$価値観。 

有益な観察は、入力を 4 つの固定境界値と比較するだけでよいということです。 

- 127
 - 32767
 - 2147483647
 - 9223372036854775807

 数値がこれらの制限のいずれか以下の場合、その型はそれを格納できます。 

Python は任意精度の整数を自然にサポートしているため、最も簡単に受け入れられる解決策は、文字列を一度整数に変換し、既知の制限と順番に比較することです。 入力長はわずか 100 桁なので、解析は低コストです。 

アルゴリズムは最小のタイプから順に比較されます。 最初に一致した範囲からすぐに答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返しの解析 / 安全でない固定幅変換 | O(L) | お(1) | 多くの言語で危険 |
 | 制限に対する逐次比較 | O(L) | お(1) | 承認済み |

 ここ、$L$入力の桁数です。 

## アルゴリズムのチュートリアル

 1. 入力された数値を文字列として読み取ります。 
2. 文字列を Python 整数に変換します。 

Python の整数には任意の精度があるため、100 桁の値でも安全に処理されます。 
3. 値を`byte`上限`127`。 

値が最大の場合`127`、印刷`"byte"`そしてやめてください。 
4. それ以外の場合は、`short`上限`32767`。 

値がここに適合する場合は、印刷します`"short"`。 
5. それ以外の場合は、`int`上限`2147483647`。 

値がここに適合する場合は、印刷します`"int"`。 
6. それ以外の場合は、`long`上限`9223372036854775807`。 

値がここに適合する場合は、印刷します`"long"`。 
7. 前の範囲がどれも機能しなかった場合は、次のように出力します。`"BigInteger"`。 

### なぜ効果があるのか

 整数型は、容量が増加する順に並べられます。 数字が中に収まる場合`byte`、それより前の型はすべて小さいため、これが自動的に最小の有効な型になります。 同じロジックが次の場合にも当てはまります`short`、`int`、 そして`long`。 

アルゴリズムは、まさにこの順序で制限をチェックします。 最初に成功した比較によって最小の有効な型が特定されるため、答えは常に正しいものになります。 

## Python ソリューション```python

if n <= 127:
    print("byte")
elif n <= 32767:
    print("short")
elif n <= 2147483647:
    print("int")
elif n <= 9223372036854775807:
    print("long")
else:
    print("BigInteger")
```プログラムはまず入力を読み取り、それを Python 整数に変換します。 Python の整数は大きな値に対してオーバーフローしないため、これは安全です。 

比較は、最小の型から最大のプリミティブ型の順に行われます。 その順序が重要です。 確認してみたら`long`最初に、その後、すべての小さい値も一致します`long`となり、最小の近似型を返すという要件が失われます。 

比較では、`<=`範囲が包括的であるためです。 のような値`127`そして`2147483647`まだ所属している必要があります`byte`そして`int`それぞれ。 

決勝戦`else`最大の符号付き 64 ビット整数より大きいすべての数値を処理します。 それらの値には次のことが必要です`BigInteger`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input().strip())

    if n <= 127:
        print("byte")
    elif n <= 32767:
        print("short")
    elif n <= 2147483647:
        print("int")
    elif n <= 9223372036854775807:
        print("long")
    else:
        print("BigInteger")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

 ## 特殊なケース

 次の入力を考えてみましょう。```
127
```アルゴリズムは以下をチェックします。```
127 <= 127
```これは true なので、次のように出力されます。```
byte
```これにより、境界が包括的であることが確認されます。 厳密な使用法`<`比較すると、この値が誤って拒否されてしまいます。 

次に、次のことを考えてみましょう。```
128
```最初の比較は失敗します。```
128 <= 127
```次の比較は成功します。```
128 <= 32767
```したがって、出力は次のようになります。```
short
```これにより、隣接する整数型間の遷移が検証されます。 

より危険なケースは次のとおりです。```

```比較は、`long`チェック：```
9223372036854775808 <= 9223372036854775807
```これは false であるため、アルゴリズムは最後の分岐に分類され、次のように出力されます。```
BigInteger
```このケースでは、固定幅の整数の解析に依存し、比較する前に誤ってオーバーフローする実装が検出されます。
