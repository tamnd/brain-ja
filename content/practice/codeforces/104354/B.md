 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられます。 選択した整数 k について、配列を長さ k の連続するチャンクに分割します (ただし、最後のチャンクは短い可能性があります)。 次に、各チャンクが非降順で個別に並べ替えられ、最後にすべてのチャンクが同じ順序で連結されて新しい配列が形成されます。 

タスクは、グローバルに非降順でソートされた最終配列を生成する k の値の数をカウントすることです。 

重要な点は、並べ替えはサイズ k の各ブロック内でのみ行われ、異なるブロック間の相対的な順序は維持されるということです。 したがって、最終的な配列のソートが失敗する唯一の原因は、内部ソート後に前のブロックの一部の要素が後のブロックの一部の要素よりも大きくなる場合です。 

n が 10^6 までという制約は、すべての k の変換を直接シミュレートできないことを意味します。 k ごとにブロックを繰り返し再計算または並べ替えるソリューションは、非常に遅すぎます。 O(n√n) のアプローチでもすでに限界に達しているため、O(n log n) または O(n log² n) に近いものを目指す必要があります。 

ブロック内のローカルな順序付けが全体的な無秩序を隠す場合、微妙な失敗例が発生します。 たとえば、次のような配列について考えてみましょう。 

入力:

 3

 3 1 2

 k = 2 の場合、ブロックは [3,1] と [2] になります。 ブロックをソートすると [1,3,2] が得られますが、これは各ブロックがソートされていてもグローバルにソートされていません。 これは、局所的な正しさをチェックするだけでは不十分であることを示しています。 

もう 1 つの失敗パターンは、ブロックの境界要素が不適切に相互作用する場合です。 各ブロックが内部でソートされている場合でも、前のブロックの最大値が次のブロックの最小値を超える可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 k ごとに、配列をブロックに分割し、各ブロックを並べ替えて連結し、結果が並べ替えられているかどうかを確認します。 ブロック内のソートにより各シミュレーションのコストは O(n log k) になり、k の値は n 通りあります。 これはおよそ O(n² log n) になりますが、これは 10^6 までの n ではまったく実現不可能です。 

重要な観察は、各ブロックを並べ替えた後、ブロックに関して重要な情報はその最小値と最大値だけであるということです。 ブロック内ではすべてが順序付けされているため、隣接する 2 つのブロックを比較する場合、最初のブロック全体が値の範囲で 2 番目のブロックを超えてはなりません。 より正確には、ブロックをその最小値と最大値で表す場合、隣接するすべてのブロックのペアについて、左側のブロックの最大値が右側のブロックの最小値以下である場合にのみ、連結がソートされます。 

これにより、問題は範囲クエリの問題に変換されます。 固定 k の場合、各ブロックの最小値と最大値をすばやく計算し、すべてのブロック境界にわたる単純な条件を検証するだけで済みます。 範囲の最小値および最大値のクエリのデータ構造を使用すると、n/k 個のブロックがあるため、各 k を O(n/k) 時間で検証できます。 

すべての k を合計すると、ブロック チェックの総数は次のようになります。 

n/1 + n/2 + n/3 + ... + n/n = O(n log n)

 これは、n = 10^6 の場合には十分効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | k あたりのブルート フォース シミュレーション | O(n² log n) | O(n) | 遅すぎる |
 | RMQ + ブロックチェック | O(n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 一定時間内に任意の間隔で範囲の最小値と最大値のクエリに応答できる構造 (通常はスパース テーブル) を事前計算します。 

その後、1 から n までのすべての可能な k を反復処理し、k が有効かどうかを確認します。

1. 配列全体の最小範囲と最大範囲のスパース テーブルを構築します。 これにより、任意の部分配列の最小値または最大値を O(1) 時間でクエリできるようになります。 
2. 各候補 k について、配列を長さ k の連続セグメントとして解釈します (最後のセグメントはおそらく短い)。 
3. 各セグメントについて、事前に計算された RMQ 構造を使用してその最小値と最大値を計算します。 インデックス l から r にわたるセグメントには、最小値 min(l, r) と最大値 max(l, r) があります。 
4. 連続するセグメントを比較します。セグメント i と i+1 の隣接するすべてのペアについて、max(セグメント i) が min(セグメント i+1) 以下であるかどうかを確認します。 いずれかのペアがこれに違反する場合、この k は直ちに破棄されます。 
5. すべてのセグメント境界が条件を満たす場合、この k を有効なものとしてカウントします。 

### なぜ効果があるのか

 各ブロックを並べ替えた後、ブロック内の要素の内部順序は、その最小要素と最大要素を除いて無関係になります。 ブロック内の要素はすべて、これら 2 つの極端な値の間に位置します。 前のブロックの最大値が後のブロックの最小値より大きい場合、連結後、より大きな要素が小さな要素の前に表示され、並べ替え順序が崩れます。 逆に、ブロックの隣接するすべてのペアが max(left) ≤ min(right) を満たす場合、前のブロックのすべての要素が後のブロックのすべての要素以下であることが保証され、グローバルな並べ替えが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_sparse(arr):
    n = len(arr)
    LOG = (n).bit_length()
    st_min = [arr[:]]
    st_max = [arr[:]]

    j = 1
    while (1 << j) <= n:
        half = 1 << (j - 1)
        prev_min = st_min[-1]
        prev_max = st_max[-1]

        cur_min = [0] * (n - (1 << j) + 1)
        cur_max = [0] * (n - (1 << j) + 1)

        for i in range(len(cur_min)):
            cur_min[i] = min(prev_min[i], prev_min[i + half])
            cur_max[i] = max(prev_max[i], prev_max[i + half])

        st_min.append(cur_min)
        st_max.append(cur_max)
        j += 1

    return st_min, st_max

def query(st, l, r):
    j = (r - l + 1).bit_length() - 1
    return min(st[j][l], st[j][r - (1 << j) + 1])

def query_max(st, l, r):
    j = (r - l + 1).bit_length() - 1
    return max(st[j][l], st[j][r - (1 << j) + 1])

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    st_min, st_max = build_sparse(a)

    def get_min(l, r):
        j = (r - l + 1).bit_length() - 1
        return min(st_min[j][l], st_min[j][r - (1 << j) + 1])

    def get_max(l, r):
        j = (r - l + 1).bit_length() - 1
        return max(st_max[j][l], st_max[j][r - (1 << j) + 1])

    ans = 0

    for k in range(1, n + 1):
        ok = True
        i = 0

        while i < n:
            l1 = i
            r1 = min(n - 1, i + k - 1)
            if i + k >= n:
                break

            l2 = i + k
            r2 = min(n - 1, i + 2 * k - 1)

            max1 = get_max(l1, r1)
            min2 = get_min(l2, r2)

            if max1 > min2:
                ok = False
                break

            i += k

        if ok:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、最初に range-min および range-max のスパース テーブルを構築して、セグメント クエリが O(1) になるようにします。 次に、メイン ループは k ごとに試行し、サイズ k のブロックをスキャンします。 隣接するブロックのペアごとに、左側のブロックの最大値と右側のブロックの最小値が比較されます。 単一の違反が k 全体を無効にするため、早めのブレークが重要です。 

微妙な詳細は、最後の部分ブロックの処理です。 これは、右端のブロックとしてのみ比較に参加します。 次のブロックがないため、それ以降の比較は必要ありません。 

## 実用的な例

 次の配列を考えてみましょう。 

入力:```
5
1 3 2 4 5
```いくつかの k 値を追跡します。 

k = 1 の場合、すべての要素は独自のブロックになります。 すべてのブロックはシングルトンであるため、すべての最大値は最小値と等しくなります。 すべての比較は合格します。 

| k | ブロック | ブロックあたりの最大/最小 | 有効 |
 | --- | --- | --- | --- |
 | 1 | [1][3][2][4][5] | 1,3,2,4,5 | はい |

 k = 2 の場合、ブロックは [1,3]、[2,4]、[5] です。 内部でソートすると、[1,3]、[2,4]、[5] になります。 比較します:

 ブロック 1 の最大値 = 3、ブロック 2 の最小値 = 2、3 > 2 であるため違反が発生します。 

| k | ブロック | 境界チェック | 有効 |
 | --- | --- | --- | --- |
 | 2 | [1,3][2,4][5] | 3 ≤ 2 は失敗します | いいえ |

 k = 5 の場合、配列全体が 1 つのブロックであるため、内部でソートされ、自明に有効になります。 

| k | ブロック | 状態 | 有効 |
 | --- | --- | --- | --- |
 | 5 | [1,3,2,4,5] | 単一ブロック | はい |

 これは、特定のブロック サイズのみがグローバルな順序付け制約を尊重する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各 k は、k を合計した O(n/k) ブロックをチェックします。 
| スペース | O(n log n) | 配列上のRMQのスパーステーブル |

 前処理はメモリ使用量の大半を占めますが、k 単位のチェックは高調波系列の動作により効率的なままです。 これは、最適化された Python または C++ では、n が最大 10^6 の場合、1 秒以内に快適に収まります。

 ## 特殊なケース

 配列がすでにソートされている場合、セグメント化に関係なく、各ブロックの最大値は常に次のブロックの最小値以下であるため、すべての k が合格します。 すべての範囲クエリが一貫した単調値を返すため、アルゴリズムはこれを処理します。したがって、境界比較は決して失敗しません。 

配列が厳密に減少している場合、k = 1 のみが機能します。 k が 1 より大きい場合は、最初の要素が最大値で最後の要素が最小値であるブロックが生成され、隣接するブロックは常に最大-最小条件に直ちに違反します。 アルゴリズムは、最初のブロック比較でこれを検出します。 

k が n/2 より大きい場合、ブロックは最大 2 つであるため、チェックは最初のブロックと 2 番目の (おそらく部分的な) ブロック間の 1 回の比較に減ります。 ループは停止する前に境界チェックを 1 回だけ実行するため、実装はこれを自然に処理します。
