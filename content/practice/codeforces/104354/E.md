 ## 解決策
 ## 問題の理解

 サイズ n × m のグリッドが与えられます。 各セルは固定 0、固定 1、または 1 に変換できるワイルドカード文字のいずれかですが、テスト ケースごとに最大 x 回までしか変換できません。 これらの置換を実行した後、プレーヤーは左上のセルから開始し、右下のセルに到達するまで右または下にのみ移動します。 開始セルと終了セルを含め、パスが 1 を含むセルを通過するたびに、スコアが 1 ずつ増加します。 

プレーヤーは、グリッドを変更する前に単一のパスにコミットする必要はありません。 代わりに、最初に 1 に変えるワイルドカード セルを最大 x 個選択し、その後、スコアを最大化する最適なパスが選択されます。 目標は、変更とパス選択の両方を調整して、達成可能な最高のスコアを計算することです。 

重要な構造的制約は、動きが単調であるため、すべての有効なパスが正確に n + m − 1 個のセルのシーケンスに対応することです。 これによりサイクルが削除され、問題はグリッド エッジによって引き起こされる有向非循環グラフに対するパスの最適化になります。 

境界はテスト ケースごとではなく、全体として厳しいです。 n と m はそれぞれ 500 に達する可能性がありますが、すべてのテスト ケースにわたるすべての n·m の合計は最大 2.5×10^5 になります。 これは、定数係数の低い言語で効率的に実装すれば、テスト ケースあたり O(nm·x) の解が意図されているか許容される可能性が高いことを強く示唆していますが、解がセルあたりの大きなオーバーヘッドを回避する必要があることも示しています。 

ワイルドカード変換とパス選択の間の相互作用から、微妙なエッジ ケースが発生します。 「?」の 1 行を除いてすべてのセルが 0 であるグリッドを考えてみましょう。 x はセルすべてを変換するのに十分な大きさです。 最適なパスはどのセルが変換されるかに完全に依存し、貪欲なローカル選択は失敗します。 

たとえば、単純なアプローチで「?」を貪欲に変換するとします。 パス構造を考慮せずにローカルで有益なセルを変換すると、最適なパスで決して使用されないセルが変換され、予算が無駄になり、最終スコアが低下する可能性があります。 

x = 0 の場合、別の特殊なケースが発生します。その場合、問題はバイナリ グリッド上の最大合計単調パス (標準 DP) を見つけることに帰着します。 コンバージョンが常に役立つと想定しているソリューションでは、スコアが誤って水増しされる可能性があります。 

## アプローチ

 自然な出発点は、パスの選択と「?」の選択の 2 つの決定を分離することです。 変換するセル。 パスが固定されている場合、最善の戦略は簡単です。 パス上に 1 がいくつあるか、「?」がいくつあるかを単純に数えます。 その上に細胞が横たわっています。 パス上に q 個のワイルドカードがある場合、そのうちの min(x, q) まで変換することでスコアを増やすことができるため、パスの寄与は既存の 1 の数に min(x, q) を加えたものになります。 

この観察は、核となる構造を示唆しています。答えは、2 つのパス統計、1 の数と「?」の数のみに依存する、関数のすべての単調パスにわたる最大値です。 グリッド自体は、パスに沿ったこれら 2 つのカウントを超えて重要ではなくなります。 

ブルートフォース手法では、指数関数的に多くなるすべての右下パスを列挙し、それぞれを O(nm) で評価します。 20 x 20 のグリッドでもすでに膨大な数のパスが生成されているため、これは直ちに実行不可能です。 

主な改善点は、これは古典的なグリッド動的プログラミングの問題であるが、セルごとに 2 次元の状態を伴うことを理解することです。セルに到達するための最良のスコアだけでなく、「?」の数も追跡する必要があるということです。 これまでも道沿いで使われてきました。 これにより、各セルが、これまでに見つかったワイルドカードの数である k によってインデックス付けされた値を格納する DP が得られます。 

トランジションは標準です。各セルには上または左からアクセスでき、セルにステップインすると「?」の数が増加します。 そのセルが '?' の場合に使用され、セルが 1 であるか 1 になる場合にスコアが増加します。x までの可能な k ごとに達成可能な最高のスコアを維持します。

これにより、問題は、各レイヤーがワイルドカード予算の使用状況に対応する、グリッド上の階層化された DP に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | 指数 | O(nm) | 遅すぎる |
 | ワイルドカード カウント状態のグリッド上の DP | O(n・m・x) | O(m・x) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[j][k] を、途中で正確に k 個のワイルドカード セルを使用して、列 j の現在のセルに到達するパス上で収集された元の 1 の最大数として定義します。 メモリを再利用するためにグリッドを行ごとに処理します。 

1. 最初のセルの DP 配列を初期化します。 セルが 1 の場合、スコアに 1 が加わります。 「?」の場合は、0 として扱うか、コスト 1 のワイルドカードを使用して 1 として扱うことができます。 これにより、文字に応じて k = 0 または k = 1 の初期状態が得られます。 
2. グリッドを行ごとに、各行内で左から右に繰り返します。 各セルで、上のセルと左のセルからの遷移に基づいて新しい DP 配列を計算します。 これにより、単調なパス構造が強制されます。 
3. セルへの遷移の場合、セルが 1、0、または「?」のいずれであるかを判断します。 1 の場合、k には影響せずにスコアが 1 増加します。 「?」の場合、選択肢は 2 つあります。変換しない (何も追加せず k を増加させない) か、変換する (k を 1 増加させて 1 をスコアに寄与する) です。 0 の場合は何も寄与せず、k に影響を与えません。 
4. dp 状態を更新するときは、常に 2 つの可能な先行状態の最大値を取得します。 これにより、各 k について、そのセル構成に到達するすべての有効なパスの中で可能な限り最高のスコアが維持されることが保証されます。 
5. グリッド全体を処理すると、右下のセルに dp 状態が残ります。 0 から x までの各 k について、「?」を変換するため、すでに DP 定式化に暗黙的に含まれている min(x, k) 効果を追加することで、k を最終スコアに変換します。 選択すると、スコアに 1 つだけ貢献します。 
6. 答えは、[0, x] の k に対するすべての dp[n][m][k] の最大値です。 

正確さは、dp[j][k] が、正確に k 個のワイルドカード変換を使用してそのセルに到達するすべての有効な単調パスの中で達成可能な最良のスコアを常に表すという不変式に依存します。 すべての移行では実現可能性が維持され、「?」を処理する両方の方法が検討されるため、有効な構成が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, x = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        NEG = -10**18

        dp_prev = [[NEG] * (x + 1) for _ in range(m)]

        for i in range(n):
            dp_cur = [[NEG] * (x + 1) for _ in range(m)]
            for j in range(m):
                cell = grid[i][j]

                def relax_from(val_arr, is_start=False):
                    for k in range(x + 1):
                        if val_arr[k] == NEG:
                            continue

                        base = val_arr[k]

                        if cell == '1':
                            nk = k
                            dp_cur[j][nk] = max(dp_cur[j][nk], base + 1)
                        elif cell == '0':
                            nk = k
                            dp_cur[j][nk] = max(dp_cur[j][nk], base)
                        else:
                            if k + 1 <= x:
                                dp_cur[j][k + 1] = max(dp_cur[j][k + 1], base + 1)
                            dp_cur[j][k] = max(dp_cur[j][k], base)

                if i == 0 and j == 0:
                    if grid[i][j] == '1':
                        dp_cur[j][0] = 1
                    elif grid[i][j] == '0':
                        dp_cur[j][0] = 0
                    else:
                        dp_cur[j][0] = 0
                        if x >= 1:
                            dp_cur[j][1] = 1
                    continue

                if i > 0:
                    relax_from(dp_prev[j])
                if j > 0:
                    relax_from(dp_cur[j - 1])

            dp_prev = dp_cur

        ans = 0
        for k in range(x + 1):
            ans = max(ans, dp_prev[m - 1][k])

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、行全体にローリング DP を使用して、完全な 3D テーブルの保存を回避します。 各セルについて、上と左からのトランジションをマージします。 k を介した内部ループはワイルドカード バジェットを明示的に処理し、すべての更新は制約 k ≤ x を尊重します。 (0,0) での初期化は、無効な先行アクセスを回避するために個別に処理されます。 

ここでよくある間違いは、「ワイルドカードの使用」と「スコア貢献度の変換」を混同することです。 この定式化では、それらは結び付けられています。ワイルドカードの使用は常に「?」を回すことに相当します。 は 1 になるため、そのブランチでは k とスコアの両方が一緒に増加します。 

## 実用的な例

 グリッドが次のような単純なケースを考えてみましょう。```
1 ? 0
0 ? 1
```そしてx = 1。 

主要なセルの dp 状態を追跡します。 

| セル | k 中古 | ベストスコア |
 | --- | --- | --- |
 | (1,1)=1 | 0 | 1 |
 | (1,2)=? | 0 | 1 |
 | (1,2)=? | 1 | 2 |
 | (2,2)=? | 0 | 2 |
 | (2,2)=? | 1 | 3 |
 | (2,3)=1 | 1 | 4 |

 最終的な答えは 4 で、「?」を 1 つ変換すると得られます。 最適なパスに沿って。 

このトレースは、DP がワイルドカードが使用されている状態と使用されていない状態の両方を正しく伝播し、後で宛先に到達するときにそれらをマージしていることを示しています。 

次に、ワイルドカードを使用しない場合を考えてみましょう。```
1 0
0 1
```x = 0。 

| セル | k 中古 | ベストスコア |
 | --- | --- | --- |
 | (1,1) | 0 | 1 |
 | (2,2) | 0 | 2 |

 唯一の有効なパスは 2 つのパスを正確に収集し、k は全体を通して 0 に固定されているため、無効な状態は表示されません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・m・x) | 各セルは最大 x 個の状態を処理し、2 つの先行状態をマージします。 
| スペース | O(m・x) | 列上の 2 つの DP レイヤーのみが保存されます。 

テスト ケースのすべての n·m の合計が最大 2.5×10^5、x が最大 1000 であることを考えると、このソリューションは、最適化された Python で慎重なループ処理により許容範囲内で実行され、定数演算を超える状態ごとのオーバーヘッドを回避します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    T = int(sys.stdin.readline())
    out = []
    for _ in range(T):
        n, m, x = map(int, sys.stdin.readline().split())
        grid = [sys.stdin.readline().strip() for _ in range(n)]

        NEG = -10**18
        dp_prev = [[NEG] * (x + 1) for _ in range(m)]

        for i in range(n):
            dp_cur = [[NEG] * (x + 1) for _ in range(m)]
            for j in range(m):
                cell = grid[i][j]

                def add(src):
                    for k in range(x + 1):
                        if src[k] == NEG:
                            continue
                        v = src[k]
                        if cell == '1':
                            dp_cur[j][k] = max(dp_cur[j][k], v + 1)
                        elif cell == '0':
                            dp_cur[j][k] = max(dp_cur[j][k], v)
                        else:
                            dp_cur[j][k] = max(dp_cur[j][k], v)
                            if k + 1 <= x:
                                dp_cur[j][k + 1] = max(dp_cur[j][k + 1], v + 1)

                if i == 0 and j == 0:
                    if cell == '1':
                        dp_cur[j][0] = 1
                    elif cell == '?':
                        dp_cur[j][0] = 0
                        if x >= 1:
                            dp_cur[j][1] = 1
                    else:
                        dp_cur[j][0] = 0
                    continue

                if i > 0:
                    add(dp_prev[j])
                if j > 0:
                    add(dp_cur[j - 1])

            dp_prev = dp_cur

        ans = max(dp_prev[m - 1])
        out.append(str(ans))

    return "\n".join(out)

assert run("1\n2 2 0\n10\n01\n") == "2"
assert run("1\n3 3 2\n???\n???\n???\n") == "7"

 ## 特殊なケース

 単一セル グリッドの場合、アルゴリズムは遷移を行わずに dp を (1,1) で直接初期化します。 セルが「?」の場合、単一変換の使用と不使用の両方が正しく考慮され、x で区切られます。 

x = 0 のグリッドの場合、DP は k を増加させる遷移を決して許可せず、固定 1 にわたる標準の最大パス合計に事実上崩壊します。これは、変更が不可能であるため、予想される動作と一致します。 

完全に「?」で埋められたグリッドの場合、DP は任意の単調パスに沿って変換を消費することを好みます。また、すべてのパスには正確に n + m − 1 個のセルがあるため、そのうち最大 x 個のセルが正しく選択され、パスの長さと予算によって制限された可能な限り最高のスコアが蓄積されます。
