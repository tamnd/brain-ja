 ## 問題の理解

 固定の実数値を分割することができます$n$の中へ$k$非負の実数部。 これを全体の「質量」を分配するものと考えてください。$n$横切って$k$コンテナ。各コンテナは$a_i$間の任意の実際の金額を保持できます$0$そして$n$、すべての合計が以下に戻る限り、$n$。 

分割を選択した後、それぞれ$a_i$標準の四捨五入を使用して、最も近い整数に独立して四捨五入されます: 以下の小数部分を持つ値$0.5$下に行く、少なくとも小数部分を含む値$0.5$上がってください。 目標は、考えられるすべての分割方法にわたって、これらの四捨五入された値の合計を最大化および最小化することです。$n$。 

主な難点は、変数が連続的であることです。 整数分割問題とは異なり、小数部分を調整できます。$a_i$これは、丸め動作のみが本当に重要であることを意味します。 

制約$n, k \le 10^9$そして最大まで$10^5$テスト ケースは、各テスト ケースを次のように削減する必要があることを意味します。$O(1)$時間。 ディストリビューションをシミュレートしたり、構成を検索しようとするソリューション$k$要素は直ちに実行不可能になります。 

微妙なエッジ ケースは、丸めが小数部分が交差するかどうかのみに依存するという事実から生じます。$0.5$、そのため、そのしきい値付近の小さな摂動によって、寄与がちょうど 1 単位だけ反転する可能性があります。 もう一つの重要なコーナーは、$k > n$ほとんどの部分は非常に小さい必要があり、丸めの動作は真上または真下にプッシュされる変数の数によって支配されるためです。$0.5$。 

## アプローチ

 ブルートフォースアプローチでは、すべての分割方法を列挙しようとします。$n$の中へ$k$実際の値を計算し、各構成の丸め合計を計算します。 値を高い精度で離散化したとしても、可能性の空間は事実上連続的で無限です。 唯一意味のある構造は、変数の上または下にいくつの変数があるかです。$0.5$しかし、それさえも総和制約による微妙な結合に依存します。 このため、ブルート フォースは概念的には正しいものの、計算的には無意味になります。 

重要な観察は、丸めは変数ごとに 2 つの情報 (整数部分と小数部分が交差するかどうか) のみに依存するということです。$0.5$。 それぞれ書き換えることができます$a_i$整数部分と小数部分の合計として計算し、これらの寄与がグローバル合計制約とどのように相互作用するかを追跡します。 この構造は、どのくらいの合計分数質量を割り当てるか、および丸めのしきい値を超える変数の数を制御することに崩壊します。 

この観点から見ると、極端な構成はシンプルになります。 最大の合計を得るには、追加の寄与にできるだけ多くの変数が必要です。$+1$端数の合計予算を実現可能に保ちながら、切り上げを防ぎます。 これは、ほとんどすべての質量を 1 つの変数に集中させ、残りを極めて小さくすることで実現されます。 最低限、交差することは避けたいと考えています。$0.5$可能な限りしきい値を大きくし、質量を均等に分散して、丸めによる上向きのバイアスを最小限に抑えます。 

これにより、問題全体が 2 つの閉じた形式の式を評価することになります。

 ## アルゴリズムのチュートリアル

 まず、2 つの閉じた形式を導出します。1 つは丸められた値の最大値合計で、もう 1 つは最小値です。 

### 最大値

 1. ほぼすべてを集中させる$n$単一の変数に$a_1 \approx n$、残りを設定します$k-1$変数を極度に小さな正の値に変換し、合計すると無視できる量になります。 
2. それぞれの小さな変数は次のように丸められます。$0$、その値は以下に留まるため、$0.5$。 
3. 大きい変数は最も近い整数に丸められます。$n$なぜなら、小さな部品からの摂動は任意に小さくできるからです。 
4. これにより、合計は次のようになります。$r(n)$。 

質量をより均等に分割しようとすると、四捨五入のしきい値を超える可能性のある変数の数が増えるだけで、四捨五入の合計が超えることはありません。$r(n)$なぜなら、各部分を個別に丸めることは、総質量集中を超える複数の単位のゲインを生み出すことができないからです。 

したがって、最大値は次のようになります。$$\max \sum r(a_i) = r(n)$$### 最小値

 1. スプリット$n$の中へ$k$等しい部分:$a_i = \frac{n}{k}$。 
2. 各部分は同じ丸め動作に影響します。 
3. 合計は次のようになります。$$k \cdot r\!\left(\frac{n}{k}\right)$$他の分布がこれを改善しない理由を確認するには、平等からの逸脱が不均衡を引き起こすことを観察してください。 1 つの変数を増やすと他の変数が強制的に減少します。また、丸めは整数の周囲で局所的に凸状であり、それ以下では平坦になるためです。$0.5$不均一な分割により、下方へのシフトを十分に補償することなく、一部のコンポーネントに余分な上方丸めが必然的に導入されます。 

したがって、丸めの膨張を最小限に抑える最も安定した構成は、均一な分割です。 

したがって、最小値は次のようになります。$$\min \sum r(a_i) = k \cdot r\!\left(\frac{n}{k}\right)$$## Python ソリューション```python
import sys
input = sys.stdin.readline

def r(x: float) -> int:
    # standard half-up rounding
    frac = x - int(x)
    if frac < 0.5:
        return int(x)
    return int(x) + 1

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())

        max_val = r(n)

        avg = n / k
        min_val = k * r(avg)

        out.append(f"{min_val} {max_val}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、2 つの派生式を直接エンコードします。 丸め関数は、小数部を比較する際の浮動小数点エッジの問題を回避するために明示的に実装されています。 

のみに依存するため、最大値が最初に計算されます。$n$、独立して$k$。 最小値では、対称均一分割引数を使用します。$k$部品は同一です。 

微妙な実装の詳細は、浮動小数点除算を使用することです。$n/k$ここでは分数比較のみなので安全です。$0.5$重要であり、Python の float 精度は制約に対して十分です。 より厳しい環境では、これには注意深く合理的な取り扱いが必要になります。 

## 実用的な例

 ### 例 1

 検討してください$n = 10, k = 3$。 

均一分割により得られる$10/3 \approx 3.333...$、したがって、それぞれは次のように丸められます$3$、最小値を与える$9$。 最大限にするには、すべての質量を集中させます。$r(10) = 10$。 

| ステップ | 構成 | 値 | rの合計 |
 | --- | --- | --- | --- |
 | 分 | 均等分割 | 3.33、3.33、3.33 | 9 |
 | マックス | 集中 | 10、0、0 | 10 |

 これは、拡散によって丸めしきい値を超えることがどのように回避されるかを示しています。 

### 例 2

 検討してください$n = 2, k = 3$。 

均一分割により得られる$0.666...$、それぞれは次のように丸められます。$1$、したがって最小値は$3$。 最大値を得るには、再度質量を集中させます。$r(2) = 2$。 

| ステップ | 構成 | 値 | rの合計 |
 | --- | --- | --- | --- |
 | 分 | 均等分割 | 0.66、0.66、0.66 | 3 |
 | マックス | 集中 | 2、0、0 | 2 |

 この例では、四捨五入により均等な部分が小さく膨らむため、分配効果の点で最小値が最大値を超える可能性があることが強調されています。

## テストケース```python
import sys, io

def r(x):
    return int(x) + (x - int(x) >= 0.5)

def solve():
    input = sys.stdin.readline
    t = int(input())
    res = []
    for _ in range(t):
        n, k = map(int, input().split())
        maxv = r(n)
        avg = n / k
        minv = k * r(avg)
        res.append(f"{minv} {maxv}")
    print("\n".join(res))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        solve()
        return ""
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 いつ$k = 1$、可能な唯一の構成は次のとおりです。$a_1 = n$。 アルゴリズムは最小値と最大値の両方を次のように正しく返します。$r(n)$, 均一分割と集中分割が一致するためです。 

いつ$k > n$, 一律の構成では多くの部品を小さくせざるを得ません。 例えば、$n = 2, k = 5$平均を与える$0.4$したがって、すべての部分は次のように丸められます。$0$、最小限のを生成します$0$、最大値が残っている間、$r(2)$。 このソリューションは、同じ式を通じてこれを自然に処理します。 

いつ$n/k$ちょうど次のような半分の境界にあります$x.5$、丸めが敏感になります。 すべてのパーツが同じように動作し、不均一な分割で発生する非対称の丸め膨張を回避できるため、均一な公式が引き続き一貫して適用されます。
