 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスが与えられます。 このシーケンスから正確に選択する必要があります$k$インデックスの相対的な順序を維持しながら要素を配置します。 これらを選択したら$k$値については、選択した値間のすべてのペアごとの絶対差を調べます。 

重要なのは 2 つの量です。選択したセット内の任意のペア間の最小の差と、選択したセット内の任意のペア間の最大の差です。 これら 2 つの値を乗算し、サイズのサブセットを選択することが目標です。$k$この製品を最小化します。 

選択した値を次のように並べ替えると、$b_1 \le b_2 \le \dots \le b_k$の場合、ペアごとの最大の差は単純に次のようになります。$b_k - b_1$。 ペアごとの最小の差は、次のペア間の最小値です。$|b_{i+1} - b_i|$。 したがって、目的は最小化になります$$(\min_{i} (b_{i+1} - b_i)) \cdot (b_k - b_1).$$入力サイズは最大です$5 \times 10^5$したがって、これより悪い解決策はありません$O(n \log n)$通りません。 平$O(n^2)$選択する方法は無数にあるため、すべてのサブセットにわたる構築は完全に不可能です。$k$要素は組み合わせです。 

微妙な問題は、最適なサブセットが元の配列内で明らかに連続しているわけではなく、ソート後の値の相対的な順序によって完全に支配されることです。 もう 1 つの隠れた落とし穴は、範囲のみが重要であると仮定することです。 範囲が非常に狭いサブセットであっても、非常に小さな内部ギャップが含まれている場合には問題が発生する可能性があり、プロダクトに大きな影響を与えます。 

小さな失敗例としては、値がクラスター化されているものの、非常に緊密なペアが 1 つ含まれており、それ以外の場合は値が分散している場合があります。 貪欲な「最も近い値を取得する」アプローチでは、非常に小さなギャップを選択する可能性がありますが、誤って範囲を拡大してしまい、わずかに広くてもより均一な選択よりも製品が悪くなる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、サイズのすべてのサブセットを列挙します。$k$、並べ替えられた選択された値を計算し、最小隣接差と範囲の両方を評価します。 これは正しいですが、サブセットの数が次のとおりであるため、すぐに失敗します。$\binom{n}{k}$、これは指数関数的であり、中程度の場合でも実行不可能です。$n$。 

重要な構造上の観察は、値がソートされると、最適なサブセットがこのソートされた配列に対してスライディング ウィンドウのように動作するということです。 選択されたすべての要素がソートされた順序で連続したブロック内にある場合、選択されたサブセットの範囲は最小化されます。 サブセットが最小または最大スパン内の要素をスキップする場合、外側の要素を内側のスキップされた要素に置き換えることは、製品に役立つ方法で最小ギャップを悪化させることなく範囲を縮小するだけです。 これにより、連続した長さのセグメントのみを考慮する方向にソリューションが推進されます。$k$ソートされた配列内。 

ウィンドウを修正したら、$k$連続してソートされた要素の場合、範囲はエンドポイント間の差として固定されます。 残りのタスクは、各ウィンドウ内の最小隣接差分を効率的に計算することです。 これは、スライディング ウィンドウ マルチセットまたは隣接するギャップを追跡するバランスの取れた構造によって維持できます。 

したがって、問題をすべてのサイズのウィンドウをスキャンすることに縮小します。$k$並べ替えられた順序で、ウィンドウ範囲と最小隣接ギャップという 2 つの維持された数量に基づいて製品を評価します。

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. 値の配列を降順でない順序で並べ替えます。 ソート後、任意の候補サブセットが選択に対応します。$k$この順序付きリストの要素。 
2. 連続するすべての長さのブロックを考慮します$k$ソートされた配列内。 各ブロックは候補セットを表し、その範囲は単に最後の要素と最初の要素の間の差です。 この制限は、目的を増やすことなく最適解を連続ブロックに変換できるため有効です。 
3. 各ウィンドウについて、範囲を次のように計算します。$a[r] - a[l]$どこ$r = l + k - 1$。 
4. 現在のウィンドウ内の隣接する要素間の差異を追跡する構造を維持します。 で始まるウィンドウの場合$l$、 これらは$a[i+1] - a[i]$みんなのために$i \in [l, r-1]$。 
5. マルチセット (またはバランスの取れた構造) を使用して、これらの隣接するギャップを保存します。 ウィンドウをシフトするたびに、ウィンドウから出るギャップを削除し、ウィンドウに入る新しいギャップを挿入します。 
6. 各ウィンドウについて、最小ギャップはマルチセット内の最小要素であり、範囲は直接知られています。 積を計算して答えを更新します。 

### なぜ効果があるのか

 正確さは、並べ替え後の 2 つのリンクされた単調な動作に依存します。 まず、サブセットがソート順で連続している場合、サブセットの範囲は最小化されます。これは、極端な値の間にスキップされた要素が含まれている場合、その範囲を縮小することしかできないためです。 第二に、固定セットの場合、$k$並べ替えられた要素では、最小隣接差によって完全に最小のペアワイズ ギャップが決まります。 したがって、注意を連続したウィンドウに限定すると、目的を改善できる候補を失うことはなく、有効な構成をすべて 1 回だけ評価します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left
from collections import deque
import heapq

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    if k == 2:
        # special case: min gap = max gap = difference
        ans = float('inf')
        for i in range(n - 1):
            d = a[i+1] - a[i]
            ans = min(ans, d * d)
        print(ans)
        return

    # compute adjacent differences
    diff = [a[i+1] - a[i] for i in range(n - 1)]

    # multiset via heap + lazy deletion
    import collections
    cnt = collections.Counter()

    heap = []

    def add(x):
        cnt[x] += 1
        heapq.heappush(heap, x)

    def remove(x):
        cnt[x] -= 1

    def clean():
        while heap and cnt[heap[0]] == 0:
            heapq.heappop(heap)

    # initial window
    for i in range(k - 1):
        add(diff[i])

    ans = float('inf')

    for l in range(n - k + 1):
        r = l + k - 1

        clean()
        min_gap = heap[0]
        range_val = a[r] - a[l]
        ans = min(ans, min_gap * range_val)

        if r == n - 1:
            break

        # slide window
        remove(diff[l])
        add(diff[r])

    print(ans)

if __name__ == "__main__":
    solve()
```実装ではまず配列を並べ替えます。これにより、すべての候補サブセットが単一の線形構造に整列され、範囲の計算が容易になります。 配列`diff`は、ウィンドウ内の最小ペアごとの差の唯一の候補である隣接ギャップを保存します。 

スライド式の窓が`diff`サイズのスライドに正確に対応します-$k$ソートされた配列をブロックします。 ヒープは最小ギャップを効率的に維持するために使用されますが、ヒープの削除は直接的ではないため、カウンタは遅延削除を実行します。 

特別な場合$k=2$この場合、積は 1 つの差の 2 乗に単純化され、ソートされた配列内の最小の隣接ペアのみが必要になるため、個別に処理されます。

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 すべての隣接する差分がゼロであるため、アルゴリズムはこれを自然に処理します。そのため、すべてのウィンドウで積がゼロになり、答えもゼロになります。 

もう一つのエッジケースは、$k=2$、問題は最小化に崩壊します。$(a_j - a_i)^2$。 コードは、並べ替え後に隣接する差分をスキャンすることでこれを明示的に処理し、グローバルな最小差分が見つかることを保証します。 

最後に、単一の非常に大きな値とクラスター化された小さな値が混在するような極端な外れ値があるケースでは、並べ替えとウィンドウ処理によって外れ値を含めることが有益かどうかを正しく分離できることが確認されます。 このようなウィンドウでは範囲が大きくなり、製品はそれを即座に反映するため、不安定なサブセットが誤って選択されることを防ぎます。
