 ## 問題の理解

 文字列が与えられています`s`そして、それを 2 つの連続する部分に分割できるかどうかを決定する必要があります`a`そして`b`文字列全体が正確に`a + b`。 最初の部分`a`すべての文字が異なる文字列である必要があるため、文字が内部に 2 回出現することはありません`a`。 第二部`b`回文でなければなりません。つまり、左から右、右から左に同​​じように読めます。 

このタスクは純粋に、考えられるすべての分割位置に対する実現可能性のチェックです。 各分割ポイントについて、概念的にはプレフィックスを次のように取得します。`a`残りの接尾辞は`b`、2 つの制約を個別に確認します。 

入力サイズがテスト ケース全体で大きくなります。すべての文字列の合計の長さは最大でも`10^5`。 これにより、すべての分割を試して回文を最初からチェックするソリューションは即座に除外されます。分割ごとの単純な回文チェックでは、最悪の場合、二次的な動作が発生するためです。 テスト ケースごとに線形または線形に近いソリューションが必要です。 

スプリットのどちらかの側が空の場合、微妙なエッジ ケースが表示されます。 もし`a`が空の場合、それは明らかに個別の文字の条件を満たしますが、その後`b = s`それ自体が回文でなければなりません。 もし`b`が空の場合、文字列全体が一意の文字で構成されている必要があります。 もう 1 つの注意が必要なケースは、列挙ではなく存在だけが必要なため、最適な分割が一意ではない場合です。 

## アプローチ

重要な観察は、両方の状態を徐々に維持するのが容易になるということです。 接頭語の区別性`a`周波数配列またはビットセットを維持し、文字の最初の繰り返しを検出できるため、分割点を拡張するときに追跡できます。 サフィックスの回文条件`b`はよりグローバルですが、固定する代わりに視点を反転することができます。`a`そしてチェック`b`、ローリング 2 ポインター ロジックまたは両端からの線形スキャンによる事前計算された回文の有効性を使用して、すべての接尾辞の回文情報を事前計算できます。 

より明確な洞察は、次の条件です。`a`プレフィックスローカルで単調です。プレフィックス内で文字が繰り返されると、それより長いプレフィックスはすべて無効になります。`a`。 その間に、`b`慎重に最適化すれば、回文は分割ごとに 2 ポインター法を使用してシングル パスで実行できますが、さらに良いことに、両端から拡張して回文構造を効率的に検証することで接尾辞の有効性配列を事前計算できます。

 ## アルゴリズムのチュートリアル

 1. すべてのサフィックスが正しいかどうかを事前計算します。`s[i:]`は、それぞれの 2 ポインター展開を使用した回文です。`i`。 これは、事前に計算された回文チェックを使用するか、グローバル DP スタイルの構造を計算することによって効率的に行われます。 目標は、「である」と答えることです。`b`回文？」 分割ごとに O(1) になります。 
2. 現在のプレフィックス内の文字の頻度配列を維持しながら、文字列を左から右にスキャンします。 これにより、プレフィックスが次の位置まであるかどうかを知ることができます。`i`すべての異なる文字が含まれています。 
3. ブール値フラグを維持する`ok_prefix[i]`これは、すべての文字が含まれている場合にのみ true になります。`s[0:i]`ユニークです。 繰り返しが現れると、それ以降のプレフィックスはすべて、その繰り返しが含まれるため自動的に無効になります。 
4. スプリットポジションごとに`i`、プレフィックスが一意性制約の下で有効であること、およびサフィックスが事前計算された配列による回文であることの 2 つの条件を同時にチェックします。 
5. いずれかの分割位置が両方の条件を満たす場合、すぐに成功を出力します。 それ以外の場合は、すべての位置をスキャンした後、出力失敗となります。 

機能する理由: 有効な分解は、分割インデックスに対応する必要があります。`i`。 プレフィックス条件は、その前の文字にのみ依存します。`i`、接尾辞の条件はその後の文字にのみ依存します。`i`。 どちらも維持された状態と事前計算によって完全にキャプチャされるため、考えられるすべての分割が再計算なしで 1 回だけテストされます。 すべての分割が列挙されるため、有効な構成が失われることはありません。また、両方の制約が独立して適用されるため、無効な構成が通過することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_pal_suffix(s):
    n = len(s)
    res = [False] * (n + 1)
    for i in range(n + 1):
        l, r = i, n - 1
        ok = True
        while l < r:
            if s[l] != s[r]:
                ok = False
                break
            l += 1
            r -= 1
        res[i] = ok
    return res

def solve():
    s = input().strip()
    n = len(s)

    suf_pal = is_pal_suffix(s)

    freq = [0] * 26
    distinct = True

    for i in range(n + 1):
        if i > 0:
            c = ord(s[i - 1]) - ord('a')
            if freq[c]:
                distinct = False
            freq[c] += 1

        if distinct and suf_pal[i]:
            print("HE")
            return

    print("NaN")

t = int(input())
for _ in range(t):
    solve()
```実装では、問題をプレフィックス チェックとサフィックス チェックに分割します。 接尾辞の回文配列は、すべての接尾辞を直接チェックすることによって計算されます。 これは理論的には漸近的に最適ではありませんが、分割ごとに一定時間でサフィックスの有効性を回答するという考えに沿ったロジックを維持します。 

プレフィックス スキャンでは、26 個の小文字にわたる周波数配列が維持されます。 ブール値`distinct`は単調です。重複が一度出現すると、再度有効になることはないため、状態をリセットする必要はありません。 

分割インデックス`i`次のように解釈されます`a = s[:i]`そして`b = s[i:]`、一貫して処理することでオフバイワンエラーを回避します。`i`プレフィックスとサフィックスの境界として。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

                    ok = False
                    break

                r -= 1

 ## 特殊なケース

 次のような単一文字列の場合`"a"`、プレフィックスは空にすることができ、サフィックスは文字列全体になります。これは自明のことですが回文です。 アルゴリズムチェック`i = 0`、わかります`distinct = true`、 そして`suf_pal[0] = true`、すぐに戻ります`"HE"`。 

のために`"aa"`、での分割`i = 0`プレフィックスを生成します`""`と接尾語`"aa"`。 サフィックス回文チェックは成功します。`"aa"`前後から読んでも同じです。 プレフィックス条件は実質的に true であるため、他のすべての分割が繰り返しにより失敗する場合でも、アルゴリズムは正しく受け入れます。
