 ## 解決策
 ## 問題の理解

 道路で結ばれた町のグラフが与えられ、各道路には色が付けられています。 グラフには、同じ町のペア間の複数のエッジや自己ループさえも含めることができるため、単純なものではなく一般的なマルチグラフになります。 

選択した町のセットについて、その色の道路だけを見たときに、色ごとにそれらの町が完全に接続されたままであり、選択したセット内でのみ移動できる場合、それを有効と呼びます。 言い換えれば、色を固定する場合、グラフをその色のエッジと選択したセット内の頂点に制限しても、セット内の任意の 2 つの頂点間の移動を許可する必要があります。 

課題は、すべての色についてこの条件を同時に満たす可能な最大の町のセットを見つけることです。 

制約は重要な点で問題を形成します。 町の数は最大でも 500 であり、これはノード上で 2 次または 2 次に近い演算が許容されることを強く示唆しています。 すべてのテスト ケースにわたるエッジの数は最大 200,000 であるため、エッジごとに線形またはほぼ線形の処理を行う余裕はありますが、候補のサブセットごとに接続性を最初から繰り返し再計算する余裕はありません。 

最も危険なエッジケースは、色が複数の色を組み合わせた後でのみ接続される、切断された構造を形成する場合です。 たとえば、2 つの色があり、各色が異なるノードのペアを個別に接続する場合、単純なアプローチではグローバルな接続で十分であると考えるかもしれませんが、要件はグローバルではなく色ごとです。 小さな例でこれを明確にします。 

3 つの町と 2 つの色があるとします。 色 1 は 1-2 を接続し、色 2 は 2-3 を接続します。 グラフ全体は接続されていますが、サイズ 3 のセットは有効ではありません。これは、色 1 ではノード 3 が分離され、色 2 ではノード 1 が分離されているためです。 したがって、構造に応じて答えは 1 または 2 を超えることはできず、グローバル接続は無関係です。 

サブセットへの制限を無視して、各色のグラフがグローバルに接続されていることだけを確認すると、別の失敗ケースが発生します。 グラフ全体では色がつながっている可能性がありますが、ノードを削除すると、サブセット内では切り離されてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、町のすべてのサブセットを試して妥当性をチェックします。 サブセットごと、色ごとに、そのサブセットに制限された BFS または DFS を実行し、接続を確認します。 n が 500 までの場合、サブセットの数は 2^500 になりますが、これはまったく不可能です。 

それほど極端ではない強引な方法は、開始ノードを修正し、有効なセットを貪欲に拡張しようとすることですが、その場合でも、追加するたびにすべての色で接続性を繰り返し検証する必要があります。 各検証には色ごとに O(n + m) のコストがかかる可能性があり、ステップごとにおよそ O(km) かそれ以上のコストがかかりますが、それでも遅すぎます。 

重要な観察は、条件が非常に特殊な点で単調であるということです。セットが有効であれば、サブセットも有効です。 これは、ローカル制約への違反を回避する最大のサブセットを探していることを示唆しています。 

色ごとに条件を再フレーム化します。 固定色の場合、選択したセットでその色の誘導グラフを考慮します。 要件は、この誘導グラフが接続されていることです。 接続エラーは、セット内にその色の下で少なくとも 2 つのコンポーネントに分離するカットが存在する場合に発生します。 

接続性の観点から直接考える代わりに、視点を逆転させます。カラー グラフによって分割されないような頂点のセットが必要です。 同様に、すべての色について、セット内のすべての頂点がその色の単一の連結コンポーネント内に存在する必要があります。 

これは非常に有用な再定式化につながります。 各色について、すべての有効なセットは、その色の 1 つの連結コンポーネント内に完全に含まれている必要があります。 したがって、色ごとに 1 つのコンポーネントを選択する必要があり、最終的なセットは、すべての色にわたってこれらの選択されたコンポーネントの交差部分に存在する必要があります。

ここで問題は、交差サイズが最大化されるように、色ごとに 1 つのコンポーネントを選択することになります。 kは大きいですがエッジは限られているので、実際に現れる成分だけを考えれば良いのです。 

各色の連結成分を個別に計算できます。 各コンポーネントはノード上のビットセットとして表現できます (n ≤ 500 のため)。 その場合、答えは、各色から 1 つのコンポーネントを選択した場合の最大交差になります。 

ただし、色ごとに 1 つのコンポーネントを直接選択すると、k では依然として指数関数的になります。 主要な構造の単純化は、単一のノードを選択すると、各色に使用できる唯一のコンポーネント、つまりそのノードを含むコンポーネントを一意に決定することです。 つまり、有効なセットの場合、すべてのノードは、すべての色にわたって同じコンポーネントの選択を共有するノードのセット内に存在する必要があり、そのセットは、何らかの代表ノードによって決定されるコンポーネントの交差部分と正確に一致する必要があります。 

したがって、最適な解決策は次のようになります。各ノードについて、そのすべての色成分の交差を計算し、そのような最大の交差を取得します。 その交差部分は、まさに、同時にすべての色のルート ノードと同じ接続コンポーネント内にあるノードのセットです。 

各色についてコンポーネントの DSU または BFS ラベル付けを計算し、各ノード u についてすべてのノード v をチェックし、すべての色について u と v が同じコンポーネント内にあることを確認します。 n が小さいため、コンポーネント ID を事前計算してベクトルを比較できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · k · (n + m)) | O(n + m) | 遅すぎる |
 | ノードごとのカラーコンポーネントの交差 | O(km + n^2) | O(nk) または圧縮 | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての色について、その誘導サブグラフを構築し、n 個のノードにわたる連結成分を計算します。 各ノードにその色のコンポーネント識別子を割り当てます。 これは、その色のエッジのみに対して BFS または DSU を使用して行われます。 色で分ける理由は、接続性の制約が交差を除いて色間で相互作用しないためです。 
2. 前処理後、各ノードには、色ごとに 1 つずつ、コンポーネント ラベルのベクトルが含まれます。 k 個のエントリすべてを明示的に保存する代わりに、エッジに現れる色のみを考慮して色を圧縮します。 エッジのない色は、すべてのノードがその色で分離されているため、自明に動作します。したがって、すべてのノードにまたがるエッジなしでそのような色が存在する場合、1 を超えるサイズのセットは有効になりません。 
3. 次に、ノードをペアごとに比較します。 2 つのノード u と v は、すべての色について同じコンポーネントに属している場合、互換性があります。 この互換性関係は推移的です。u が v と互換性があり、v が w と互換性がある場合、u は w とも互換性があります。 
4. ノード上の DSU を使用して、この互換性関係の接続されたコンポーネントを構築します。 すべてのペア (u、v) について、色コンポーネントの識別子を比較することによって互換性をチェックします。 
5. 各 DSU コンポーネントは最大有効セットを表します。その内のすべてのノードが同じ色ごとの接続シグネチャを共有するためです。つまり、セットに制限されている場合、任意の 2 つのノードがすべての色で接続されたままになります。 
6. 最大の DSU コンポーネントを計算し、そのノードを出力します。 

正確かどうかは、有効性がすべての色にわたって同一の接続性シグネチャを持つことと同等であるという事実にかかっています。 

### なぜ効果があるのか

 任意の固定色の場合、2 つのノードがその色の異なる接続コンポーネントにある場合、誘導されたサブグラフがその色ですぐに切断されるため、有効なセットに両方を含めることはできません。 したがって、有効なセットはすべて、色ごとに 1 つのコンポーネント内に完全に存在する必要があります。 これにより、セット内のすべてのノードがすべての色に対して同じコンポーネント ラベルを共有するようになります。 逆に、すべてのノードがすべての色にわたって同一のコンポーネント ラベルを共有する場合、各色についてノードは 1 つの接続されたコンポーネント内に位置するため、誘導されたグラフはその色で接続されたままになります。 これにより、有効なセットと同一のコンポーネント署名の等価クラス間の等価性が確立されます。

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    T = int(input())
    for _ in range(T):
        k, n, m = map(int, input().split())
        
        color_edges = defaultdict(list)
        colors = []
        
        for _ in range(m):
            g, u, v = map(int, input().split())
            u -= 1
            v -= 1
            color_edges[g].append((u, v))
            colors.append(g)
        
        comp = {}
        
        for c, edges in color_edges.items():
            adj = [[] for _ in range(n)]
            for u, v in edges:
                adj[u].append(v)
                adj[v].append(u)
            
            vis = [-1] * n
            cid = 0
            for i in range(n):
                if vis[i] == -1:
                    q = deque([i])
                    vis[i] = cid
                    while q:
                        x = q.popleft()
                        for y in adj[x]:
                            if vis[y] == -1:
                                vis[y] = cid
                                q.append(y)
                    cid += 1
            for i in range(n):
                comp[(i, c)] = vis[i]
        
        # nodes without edges of a color: isolated components
        # implicitly handled by missing adjacency

        def compatible(u, v):
            for c in color_edges.keys():
                if comp[(u, c)] != comp[(v, c)]:
                    return False
            return True
        
        parent = list(range(n))
        
        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x
        
        def union(a, b):
            ra, rb = find(a), find(b)
            if ra != rb:
                parent[rb] = ra
        
        nodes = list(range(n))
        for i in range(n):
            for j in range(i + 1, n):
                if compatible(i, j):
                    union(i, j)
        
        size = defaultdict(int)
        best_root = 0
        best_size = 1
        
        for i in range(n):
            r = find(i)
            size[r] += 1
            if size[r] > best_size:
                best_size = size[r]
                best_root = r
        
        ans = []
        for i in range(n):
            if find(i) == best_root:
                ans.append(i + 1)
        
        print(best_size)
        print(*ans)

if __name__ == "__main__":
    solve()
```この実装では、まず色ごとに隣接リストを構築し、BFS を実行して色ごとに独立して連結成分を計算します。 これらのコンポーネント ラベルは、各ノードの署名を形成します。 

互換性チェックは、純粋に、存在するすべての色のシグネチャを比較することになります。 n が小さいため、ノードのすべてのペアを比較し、一致するものを結合します。 

DSU は、有効なソリューション内で一緒に属する必要があるノードをグループ化します。 最大の DSU セットが返されます。 

細かい点ですが、エッジのない色は隣接マップには決して表示されません。 つまり、どのノードもその色では暗黙的に独自のコンポーネントとなり、その色では接続が不可能なため、ロジックと一致します。 

## 実用的な例

 3 つのノードと 2 つの色を持つ小さなグラフを考えてみましょう。 ノード 1 はカラー 1 の 2 に接続し、ノード 2 はカラー 2 の 3 に接続します。 

| ステップ | ノード 1 の署名 | ノード 2 の署名 | ノード 3 の署名 | 組合活動 |
 | --- | --- | --- | --- | --- |
 | カラー後1 | (1,2) は同じコンポーネント、3 は別々 | 同じ | 別 | まだ何もありません |
 | カラー後2 | 1 は 3 から分離 | ブリッジノードが異なります | (2,3) の同じコンポーネント | なし |

 次に、ペアを比較します。 ノード 1 と 2 はカラー 2 が異なるため、マージされません。 ノード 2 と 3 は色 1 が異なるため、マージされません。 結合は起こらず、答えは 1 です。 

これは、グローバルな接続性は無関係であり、色ごとの一貫性のみが重要であることを示しています。 

次に、すべてのノードが両方の色で接続されている完全に一貫した例を考えてみましょう。 

| ステップ | 署名の等価性 | ユニオンの結果 |
 | --- | --- | --- |
 | すべてのノードは、両方の色で同一のコンポーネント ID を共有します。 すべて等しい | すべてマージされました |

 これは、アルゴリズムが最大有効セットを正しく識別していることを確認します。

 ## 特殊なケース

 重大なエッジ ケースは、色が表示されても孤立した頂点のみを形成する場合に発生します。 その場合、すべてのノードはその色の独自のコンポーネントになります。 アルゴリズムは BFS 経由で個別のコンポーネント ID を割り当てるため、セット サイズが 1 でない限り、互換性は直ちに失敗します。これにより、他の色に基づいてノードを誤ってマージすることが防止されます。 

もう 1 つのエッジ ケースは、エッジがまったくないグラフです。 すべてのノードはすべての色で分離されているため、すべてのシグネチャは色ごとに異なり、最大の有効なセットは 1 です。BFS の初期化では、すべてのノードが独自のコンポーネント内に正しく残され、DSU はどのノードもマージしません。 

最後のエッジ ケースは、複数のエッジと自己ループです。 自己ループは接続構造に影響を与えず、複数のエッジは自然に隣接リストに吸収されます。 BFS コンポーネントの計算では多重度は無視され、到達可能性のみが追跡されるため、冗長エッジの存在によって正確性が変わることはありません。
