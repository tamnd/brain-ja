 ## 問題の理解

 次の形式の数式を変形するように求められます。$x^y$固定サイズの ASCII アートワークに変換します。 各テスト ケースでは、2 つの正の整数の文字列表現が与えられます。$x$そして$y$の値に基づいて何を描画するかを決定する必要があります。$z = x^y$。 

もし$z \le 10^{18}$、完全な表現を描画します$x^y = z$。 それ以外の場合は、結果側全体を文字列に置き換えます。`INF`、生産$x^y = INF$。 

描画は通常の意味でのテキストではなく、事前定義されたグリフを連結することによって決定される高さ 10 と幅のピクセル グリッドです。 各数字と記号は、5×5 のブロックとして描画され、わずかに上に配置される指数桁を除き、7×7 のブロックとして描画されます。 すべての文字は水平方向にちょうど 1 列のドットで区切られており、キャンバスの両側には 1 列のパディングがあります。 

中心となる計算部分はレンダリング自体ではなく、レンダリングするかどうかを決定することです。$x^y$を超える$10^{18}$そうでない場合は、安全な方法で正確な値を計算します。 制約$x, y \le 10^{18}$直接累乗は一般に不可能であることをすぐに暗示します。$2^{60}$すでに超えています$10^{18}$、多くの入力は完全な計算が完了するずっと前にオーバーフローします。 

計算する素朴なアプローチ$x^y$直接的には、時間制限と整数制限の両方がオーバーフローします。 Python の大きな整数でも、10^{18}^{10^{18}} のような場合には大きすぎて、天文学的に実現可能性を超えます。 したがって、実際のタスクは、オーバーフローを早期に判断し、安全に制限された場合にのみ正確な値を計算することになります。 

微妙なエッジケースが現れるのは、$y = 1$。 この場合、値は正確に$x$、次の場合でも印刷する必要があります。$x$大きいですが、まだ範囲内です。 もう一つのエッジケースは、$x = 1$、ここで、結果は常に 1 になります。$y$したがって、べき乗ロジックはすぐに短絡するはずです。 

## アプローチ

ただし、このアプローチは次の場合には実行できなくなります。$y$大きいです。 繰り返し乗算を行うには、$O(y)$演算、および高速累乗であっても、サイズが爆発的に増加する中間値が生成されます。 真のボトルネックは時間だけではなく、メモリと演算の増加にあり、値が実際の限界をすぐに超えてしまいます。

これにより、べき乗が高速パワーの制限付きシミュレーションに変換され、しきい値を超える精度は意図的に破棄されます。 2 進累乗の構造は引き続き適用されますが、飽和算術が適用されます。

 ## アルゴリズムのチュートリアル

 私たちは計算します$x^y$2 進累乗を使用しますが、上限カットオフは次のとおりです。$10^{18} + 1$。 

1. もし$x = 1$または$y = 0$の場合、結果は常に範囲内にあるため、すぐに 1 を返します。 これにより、不必要な計算が回避されます。 
2. 結果を 1 として初期化し、制限値を次のように設定します。$10^{18}$。 
3. その間$y > 0$、最下位ビットを検査します。$y$。 設定されている場合は、現在の結果に次の値を乗算します。$x$ただし、乗算が制限を超える場合は、それをクランプし、結果をオーバーフローとしてマークします。 
4. スクエア$x$各ステップで、必要に応じて再び限界でキャップを付けます。 これにより、中間パワーが私たちが関心を持っている以上に大きくなることはありません。 
5. シフト$y$少しずつ右に移動して続行します。 
6. ループの後、オーバーフローがトリガーされた場合は、次のように出力します。`INF`。 それ以外の場合は、計算された値を出力します。 

値を自然に増加させるのではなく、値に上限を設ける理由は、値がそれを超えると、$10^{18}$出力目的では区別できません。 「有効」と「オーバーフロー」のブール値の区別のみが必要です。 

### なぜ効果があるのか

 2 進累乗では、指数を 2 の累乗に分解し、独立した寄与を乗算することで正確さを保証します。 乗算は正の整数に対して単調であるため、部分積が次の値を超えると、$10^{18}$、さらに乗算してもしきい値を下回ることはありません。 この単調性により、オーバーフローの決定の正確さに影響を与えることなく、安全な早期停止が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def power(x, y):
    result = 1
    overflow = False

    while y > 0:
        if y & 1:
            result *= x
            if result > LIMIT:
                overflow = True
                result = LIMIT + 1
        y //= 2
        if y:
            x *= x
            if x > LIMIT:
                x = LIMIT + 1

    return result, overflow

def solve_case(s):
    base, exp = s.split('^')
    x = int(base)
    y = int(exp)

    if x == 1:
        return "1"
    if y == 1:
        return str(x)

    val, overflow = power(x, y)
    if overflow or val > LIMIT:
        return "INF"
    return str(val)

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append(solve_case(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()

べき乗関数は標準の 2 進累乗ループですが、すべての乗算の後にクランプが続きます。$10^{18} + 1$。 これにより、Python の整数が、意思決定のために考慮する範囲を超えて増大することがなくなります。 

クランプだけでは真の値が制限を超えたかどうかに関する情報が失われるため、オーバーフロー フラグが必要です。 フラグがなければ、まさに次のような値$10^{18} + 5$これは、決して大きくはなかったものの、中間ステップで上限が設定された値と区別がつきません。

 ## 特殊なケース

 入力の場合、$x = 1$の場合、アルゴリズムはべき乗を入力せずにすぐに 1 を返します。 これは正しいです。1 の累乗は 1 のままであり、時間を無駄にする不必要な乗算の連鎖を回避できます。
