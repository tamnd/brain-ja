 ## 解決策
 ## 問題の理解

 整数の配列が与えられており、その配列上でいくつかのセグメントを選択したいと考えています。 選択した各セグメントの合計は負ではない必要があり、選択した 2 つのセグメントが重複することはできません。 選択のスコアは、選択したすべてのセグメントでカバーされるポジションの合計数にすぎず、目標はこのスコアを最大化することです。 

これを理解するもう 1 つの方法は、互いに素な間隔を使用して、できるだけ多くのインデックスをカバーしようとしているということです。つまり、すべての間隔が配列値に関して「非負の総質量」を持ちます。 

制約$n \le 2 \cdot 10^5$セグメントまたはサブセットを明示的に列挙しようとするソリューションは直ちに除外されます。 平$O(n^2)$間隔の構築はすでに境界線に達しています。$O(n^2)$考えられるセグメントを考え、単純に合計をチェックすると、次のようになります。$O(n^3)$。 

小さな負の値が正の値の間に散在している場合、微妙な問題が発生します。 各位置から始まる最も長い非負のセグメントを常に取得する単純な貪欲は失敗する可能性があります。セグメントを拡張すると、セグメントを複数の小さな有効なセグメントに分割することでカバーされる合計長さが向上する場合でも、わずかに正の間隔が負の間隔に変わる可能性があるためです。 

たとえば、次のような配列について考えてみましょう。```
[2, -1, 2, -1, 2]
```配列全体に合計が含まれます$4$, したがって、長さ 5 の単一セグメントとして有効です。ただし、ローカル戦略では、プレフィックスの変動に応じて、代わりに短いセグメントが選択される場合があります。 また、マージをあまりにも積極的に行うと、後でさらにセグメントを配置するための柔軟性が失われる場合もあります。 

主要な問題は、セグメントの決定が独立していないことです。セグメントを選択すると、利用可能なものが変わりますが、将来のセグメントを形成できるかどうかも変わります。 

## アプローチ

 ブルートフォース手法では、可能な限りの素のセグメントのセットを生成し、各セグメントの合計が負でないかどうかを確認しようとします。 有効なセグメントのみに限定したとしても、$O(n^2)$複数の候補があり、それらの中から互いに素なサブセットを選択すると、指数関数的な複雑さが生じます。 これはまったく実現不可能です。 

「セグメントの合計が負ではない」という条件がプレフィックスの合計とうまく相互作用することを認識する必要があります。 プレフィックス合計を定義すると$p[i]$、次に任意のセグメント$[l, r]$の場合は有効です$p[r] \ge p[l-1]$。 これにより、すべての有効なセグメントが、右のエンドポイントが左のエンドポイント以上のプレフィックス値を持つ 2 つのプレフィックス インデックス間の関係に変わります。 

ここで重要な構造的洞察は、各セグメントがその合計ではなく、その長さのみに寄与するということです。 つまり、正しいエンドポイントを修正すると、$r$、そこでセグメントを終了したいので、できるだけ早いものを選択することだけを気にします$l$そのような$p[l-1] \le p[r]$。 より早いものを選択する$l$常に長さが増加しますが、有効性が損なわれることはありません。 

これにより、問題はプレフィックスの位置に関する動的プログラミングに変わります。 それぞれのポジションで$r$でセグメントを終了するかどうかを決定します。$r$、そうする場合は、そこで終了する最長の有効なセグメントが必要です。 最適化は、各プレフィックス値を、それを超えない最小の以前のプレフィックスと繰り返しペアにすることになります。 

これを効率的に維持するために、プレフィックス合計を左から右に処理し、各プレフィックス合計しきい値に対して達成可能な最良の DP 値を格納するデータ構造を維持します。 プレフィックス合計は任意の整数であるため、「これまでで最高のプレフィックス合計」マップのように動作する単調構造を圧縮して使用します。 これにより、単調なスタックのような構造を使用して各状態が償却定数時間で更新される DP が得られます。 

重要な変革は、ポジションでの決定が$i$プレフィックス合計を持つ以前のすべての位置の中で最も到達可能な状態にのみ依存します。$\le p[i]$、この構造は段階的に維持できます。

 | 単調構造のプレフィックス DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックスの合計を計算する$p[i]$、 どこ$p[0] = 0$。 これにより、セグメントの合計がプレフィックス値の差に変換されます。 
2. 以下をサポートする構造を維持します。プレフィックス値が指定された場合$x$、プレフィックスの合計が以下である以前のすべてのプレフィックス位置の中で最良の DP 値を迅速に取得します$\le x$。 これは、現在の位置で終了するセグメントを開始する最良の方法を表します。 
3. 位置を左から右に処理し、プレフィックス インデックス上の DP を維持します。 させて$dp[i]$までの位置を使用してカバーされる最大全長になります。$i$、セグメント境界はプレフィックスポイントで揃えられます。 
4. 各ポジションで$i$、まず先に進めます$dp[i] = dp[i-1]$でセグメントを終了しないことを意味します。$i$。 
5. 次に、セグメントを次の時点で終了することを検討します。$i$。 最良の出発点はどれでもよい$j < i$そのような$p[j] \le p[i]$、ゲインは$(i - j)$プラス最大 DP$j$。 私たちはそのような最高のものを求めます$dp[j] - j$、 なぜなら：$$dp[j] - j + i$$すでに、以前のカバレッジと新しいセグメントの長さが考慮されています。 
6. プレフィックス合計の最大値を格納するデータ構造を維持します。$dp[j] - j$プレフィックス合計のしきい値ごとに。 加工時$i$、現在の状態で更新します。 
7. 最終的な答えは次のとおりです。$dp[n]$。 

### なぜ効果があるのか

 重要な不変条件は、あらゆるプレフィックス値に対して$x$、構造体には達成可能な最高の値が格納されます。$dp[j] - j$すべてのポジションの中で$j$プレフィックスの合計が最大であるもの$x$。 で終わる有効なセグメントであればこれで十分です。$i$いつかから始めなければならない$j$満足のいく$p[j] \le p[i]$そして、そのようなすべての選択肢の中で、最大化するものは$dp[j] - j$トータルゲインを最大化します。 

すべての遷移はプレフィックスの合計と一次式にのみ依存するため、$dp[j] - j$、今後のいかなる決定も、以前に保存された最適な候補を無効にすることはできません。 プレフィックス制約の単調性により、古い状態をより洗練された方法で再検討する必要がなくなりました。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # prefix sums
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    # DP
    dp = [0] * (n + 1)

    # We maintain pairs (prefix_sum, best dp[j] - j up to this prefix constraint)
    # We'll compress prefix sums by sorting unique values
    vals = sorted(set(pref))

    from collections import defaultdict
    import bisect

    # best value for each compressed prefix threshold
    best = [-10**18] * len(vals)

    def get_idx(x):
        return bisect.bisect_right(vals, x) - 1

    def query(x):
        i = get_idx(x)
        return best[i] if i >= 0 else -10**18

    def update(x, val):
        i = get_idx(x)
        if i >= 0:
            best[i] = max(best[i], val)

    # initialize: j = 0
    update(pref[0], dp[0] - 0)

    for i in range(1, n + 1):
        dp[i] = dp[i - 1]

        # try ending segment at i
        best_start = query(pref[i])
        if best_start != -10**18:
            dp[i] = max(dp[i], best_start + i)

        # update structure with j = i
        update(pref[i], dp[i] - i)

    print(dp[n])

if __name__ == "__main__":
    solve()
```コードは、セグメントの有効性が単純な不等式になるように、配列をプレフィックスの合計に変換することから始まります。 DP アレイは、各プレフィックス位置までの最適な合計カバー長を追跡します。 

データ構造は、プレフィックスの合計を圧縮し、プレフィックスしきい値ごとに最適な値を維持することによって実装されます。 各 DP 状態は候補値に寄与します$dp[j] - j$、ポジションの後にセグメントを開始することがどれだけ収益性があるかを表します。$j$。 

各位置で、最初に、ここで終了するセグメントを配置しないオプションを計算します。 次に、現在のインデックスで終了するセグメントの有効な開始点をすべてクエリします。 最後に、現在の状態を構造に挿入して、将来のセグメントの開始点として機能できるようにします。 

最もデリケートな部分は、計算後に構造を常に更新することです。$dp[i]$そうしないと、同じ位置を 2 回使用することが誤って許可されてしまいます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最初のステップの後ですべてのプレフィックスの合計が負になる場合です。 その状況では、後の位置で終了するセグメントはインデックス 0 から開始できず、DP は無効な負の合計セグメントの形成を回避する必要があります。 プレフィックスしきい値を超えるクエリでは有効な開始候補が返されず、「スキップ」遷移のみが残るため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、最適解が 1 つの大きなセグメントではなく、多数の小さなセグメントで構成されている場合です。 次のような入力の場合:```
[2, -1, 2, -1, 2]
```各プレフィックス更新で新しい候補が保存されるため、アルゴリズムは開始位置の複数回のリセットを正しく許可します。$dp[i] - i$により、将来のセグメントを重複せずに異なる最適なポイントから開始できるようになります。 

最後に、プレフィックスの合計が繰り返される場合、圧縮によりそれらが同じしきい値バケットにマッピングされるため、前後の同一のプレフィックス値が一貫して扱われ、「」の正確性が維持されます。$\le$” 有効性チェックで使用される条件。
