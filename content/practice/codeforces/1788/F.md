 ## 解決策
 ## 問題の理解

 私たちには木があります$n$頂点と$n-1$エッジ。 すべてのエッジに負でない整数の重みを割り当てる必要があります。 いくつかの制約は次の形式で与えられます。$(u,v,x)$これは、間の一意のパスに沿ったすべてのエッジの重みの XOR を意味します。$u$そして$v$等しい必要があります$x$。 

最初のタスクは、そのような割り当てがそもそも存在するかどうかを判断することです。 そうであれば、有効な割り当てを 1 つ出力する必要があります。 すべての有効な割り当ての中で、ツリー全体のすべてのエッジの重みの XOR を最小化する必要があります。 

ツリーには以下が含まれます$2.5 \cdot 10^5$頂点があり、最大で$2.5 \cdot 10^5$制約。 パスを明示的に処理するアルゴリズムは、直ちにコストが高くなりすぎます。 単一のパスには以下を含めることができます$O(n)$したがって、すべての制約を素朴にチェックするには、$O(nq)$仕事、それは周りにあります$6 \cdot 10^{10}$最悪の場合の運用。 

サイズ制限は、すべての頂点とすべてのクエリを一定の回数だけ処理する必要があることを強く示唆しています。 周辺のソリューション$O((n+q)\alpha(n))$または$O((n+q)\log n)$許容されます。 

微妙な点は、制約がエッジの重みを直接指定しないことです。 パス上で XOR 値のみを指定します。 異なるエッジ割り当てによって、まったく同じパス XOR のセットが生成されることがあります。 すべてのエッジの重みの XOR を最小限に抑えるという最適化目標により、別の構造層が導入されます。 

単純なチェーンを考えてみましょう。```
1 -- 2 -- 3
```制約が 1 つあります。```
1 3 5
```唯一の要件は次のとおりです。```
a12 XOR a23 = 5
```多くの割り当てはこれを満たします。 例えば：```
0 5
1 4
7 2
```すべて有効です。 エッジ値を一意に決定されたものとして扱う解決策は正しくありません。 

もう 1 つの簡単な間違いは、矛盾する制約を見逃していることです。 仮定する：```
3 2
1 2
2 3
1 3 1
1 3 2
```1 と 2 の両方を XOR するには、同じパスが必要です。解決策は存在しません。 

3 番目のトラップは最適化ターゲットから発生します。 有効な割り当てが必ずしも最適であるとは限りません。 1 つのエッジを持つ木を考えてみましょう。```
1 -- 2
```そして制約はありません。 重み 7 の割り当ては有効ですが、すべてのエッジの XOR は 7 になります。重み 0 の割り当ても有効で、可能な最小の答えが得られます。 

最適化条件は無視できません。 

## アプローチ

 ブルート フォースの観点は、エッジに値を割り当て、すべてのパス制約を検証することです。 各エッジを少数の候補値のみに制限したとしても、検索空間は依然として指数関数的になります。$n$。 まで$250000$エッジ、これは絶望的です。 

重要な観察は、ツリーに対する XOR 制約の標準的なトリックから得られます。 

ツリーを任意に、たとえば頂点 1 にルートします。値を定義します。$p[v]$すべての頂点について:$$p[v] = \text{XOR of edge weights on the path from root to } v$$次に、2 つの頂点間のパス上の XOR は次のようになります。$$p[u] \oplus p[v]$$ルートから LCA までの共通部分が相殺されるためです。 

これにより、ツリーが制約から完全に削除されます。 

すべてのクエリ$$(u,v,x)$$になる$$p[u] \oplus p[v] = x$$これで、各頂点に 1 つの値を割り当てるだけで済みます。 

これは XOR 式のグラフです。 各クエリは、必要な XOR 差を使用して 2 つの頂点を接続します。 このようなシステムは通常、パリティのような情報を備えた DFS、BFS、または DSU で解決されます。 

次の質問は最適化の目標です。 

頂点値が完成したら$p[v]$あらゆる木の端が知られています$(parent,child)$重さがある$$p[parent] \oplus p[child]$$すべてのエッジの重みの XOR は次のとおりです。$$\bigoplus_{(a,b)\in E}(p[a]\oplus p[b])$$ルート以外の各頂点は、その親エッジに 1 回だけ表示されます。 すべての内部頂点は全体で 2 回表示され、キャンセルされます。 ルートには親がないため、その次数よりも 1 回小さく表示されます。 

キャンセル後、すべてのエッジの重みの合計 XOR は次のようになります。$$p[1]\oplus p[2]\oplus\cdots\oplus p[n]$$このアイデンティティが問題の核心です。 

クエリ グラフは XOR の差のみを決定します。 クエリ グラフの 1 つの接続コンポーネント内で、すべてのコンポーネントを XOR することができます。$p[v]$同じ値で$t$、すべての制約は有効のままです。$$(p[u]\oplus t)\oplus(p[v]\oplus t)=p[u]\oplus p[v]$$したがって、各接続コンポーネントは 1 つの自由変数に寄与します。 

すべてのエッジの重みの合計 XOR は、すべてのコンポーネントからの 1 つの値の XOR になります。 少なくとも 2 つのコンポーネントがある場合は常に、これらの自由シフトを選択して、最終的な XOR をゼロにすることができます。 コンポーネントが 1 つだけの場合、合計の XOR は固定されます。 

これは最適な構築に直接つながります。

 ## アルゴリズムのチュートリアル

 ### ステップ 1

 XOR 制約のみを含むグラフを作成します。 

あらゆるクエリに対して$(u,v,x)$、間に無向エッジを追加します。$u$そして$v$とラベルが貼られている$x$。 

このエッジによって表される方程式は次のとおりです。$$p[u]\oplus p[v]=x$$### ステップ 2

 制約グラフの各接続コンポーネントを調べます。 

任意の開始頂点を選択し、その値を設定します$p=0$。 

エッジを横切るたびに$$u \leftrightarrow v$$ラベル付き$x$、私たちは導き出します$$p[v]=p[u]\oplus x$$もし$v$がまだ割り当てられていない場合は、この値を割り当てて続行します。 

もし$v$すでに値がある場合は、方程式が満たされていることを確認してください。 それ以外の場合、システムは一貫性がなくなり、答えは「いいえ」になります。 

これにより、すべての頂点ポテンシャルの 1 つの有効な割り当てが計算されます。 

### ステップ 3

 すべての連結成分について計算します。$$S_i=\bigoplus_{v\in component_i} p[v]$$これらの値は、各コンポーネントが最終的なグローバル XOR にどのように寄与するかを表します。 

### ステップ 4

 コンポーネントを次のようにします$C_1,C_2,\dots,C_k$。 

もし$k=1$、自由は残されていません。 ステップ 2 の割り当てはすでに最適化されています。 

もし$k\ge 2$、最終的な XOR がゼロになるようにシフトを選択します。 

最後のコンポーネントを除くすべてのコンポーネントを変更しないでください。 

させて$$need=S_1\oplus S_2\oplus\cdots\oplus S_k$$最後のコンポーネントのすべての頂点の XOR を計算します。$need$。 

コンポーネントのシフトではすべての制約が保持されますが、そのコンポーネントの XOR は次のように変更されます。$need$。 この変更後、グローバル XOR はゼロになり、これは可能な最小値です。 

### ステップ 5

 エッジの重みを回復します。 

元のツリーを頂点 1 でルートします。 

木の端ごとに$(parent,child)$、$$weight = p[parent]\oplus p[child]$$この値を元の入力順序に対応する位置に格納します。 

### ステップ 6

 復元されたエッジの重みを出力します。 

### なぜ効果があるのか

 クエリ グラフ上の DFS は値を構築します$p[v]$あらゆる方程式を満たす$p[u]\oplus p[v]=x$。 矛盾が検出された場合、頂点ポテンシャルの割り当ては存在せず、したがってエッジの割り当ても存在しません。 

エッジの重みは隣接するポテンシャル間の正確な XOR 差であるため、すべての有効なエッジ割り当ては有効なポテンシャル割り当てに対応し、その逆も同様です。 

クエリ グラフの連結コンポーネント内で、すべてのポテンシャルに同じ定数を追加すると、すべてのペアごとの XOR の差は変更されません。 自由度はこれらのみです。 少なくとも 2 つのコンポーネントが存在する場合、グローバル XOR を完全にキャンセルするために 1 つのコンポーネント シフトを常に選択できます。 XOR 値は負ではない整数であるため、ゼロが可能な最小値です。 したがって、構築されたソリューションは最適です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    tree = [[] for _ in range(n)]
    edges = []

    for i in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        tree[u].append((v, i))
        tree[v].append((u, i))

    cons = [[] for _ in range(n)]

    for _ in range(q):
        u, v, x = map(int, input().split())
        u -= 1
        v -= 1
        cons[u].append((v, x))
        cons[v].append((u, x))

    p = [-1] * n
    comp_id = [-1] * n
    comp_xor = []
    comp_nodes = []

    cid = 0

    for start in range(n):
        if p[start] != -1:
            continue

        p[start] = 0
        comp_id[start] = cid

        dq = deque([start])
        nodes = []
        sx = 0

        while dq:
            u = dq.popleft()
            nodes.append(u)
            sx ^= p[u]

            for v, x in cons[u]:
                want = p[u] ^ x

                if p[v] == -1:
                    p[v] = want
                    comp_id[v] = cid
                    dq.append(v)
                elif p[v] != want:
                    print("No")
                    return

        comp_nodes.append(nodes)
        comp_xor.append(sx)
        cid += 1

    k = cid

    if k >= 2:
        total = 0
        for x in comp_xor:
            total ^= x

        last = k - 1

        if total:
            for v in comp_nodes[last]:
                p[v] ^= total

    parent = [-1] * n
    parent_edge = [-1] * n

    dq = deque([0])
    parent[0] = 0

    while dq:
        u = dq.popleft()

        for v, idx in tree[u]:
            if parent[v] != -1:
                continue

            parent[v] = u
            parent_edge[v] = idx
            dq.append(v)

    ans = [0] * (n - 1)

    for v in range(1, n):
        idx = parent_edge[v]
        ans[idx] = p[v] ^ p[parent[v]]

    print("Yes")
    print(*ans)

solve()
```コードによって構築される最初のグラフは、ツリーではなく制約グラフです。 その目的は、頂点ポテンシャルの XOR 方程式を解くことです。 

BFS は頂点に値を割り当て、同時に一貫性をチェックします。 2 つの異なるパスを介して頂点に到達するときは常に、両方の派生が同じポテンシャルを生成する必要があります。 そうでなければ、連立方程式は不可能です。 

コンポーネントの XOR 値は、グローバル目標に対する各コンポーネントの貢献度を決定するため、保存されます。 すべてのコンポーネントがわかった後でのみ、どのシフトを適用するかを決定できます。 

ツリー上の最後の BFS は、エッジの重みを回復するためだけに存在します。 その時点で、すべての可能性はすでに固定されています。 

よくある実装上の間違いは、すべてのコンポーネントの XOR が判明する前にコンポーネントをシフトしようとすることです。 最適なシフトはすべてのコンポーネントの XOR に依存するため、制約グラフ全体が処理された後に実行する必要があります。 

もう 1 つの簡単な間違いは、孤立した頂点が有効なコンポーネントであることを忘れていることです。 このような頂点は完全に自由なポテンシャルに対応し、まさにグローバル XOR の調整を可能にします。

 ## 特殊なケース

 次のことを考慮してください。```
2 0
1 2
```制約はありません。 制約グラフには 2 つの独立したコンポーネントがあります。 どちらのポテンシャルもゼロから始まります。 このアルゴリズムはすべての値をゼロに保ち、エッジの重みをゼロに戻し、可能な最小の答えを出力します。 

次に、次のことを考えてみましょう。```
3 2
1 2
2 3
1 3 4
1 3 4
```どちらのクエリも同一です。 最初の割り当ては次のとおりです。$$p[3]=4$$2 つ目は同じ方程式をチェックし、成功します。 重複する制約は自然に処理されます。 

最後に次のことを考慮してください。```
4 2
1 2
2 3
3 4
1 2 7
3 4 5
```制約グラフには 2 つの切り離されたコンポーネントがあります。 初期コンポーネントの XOR は 7 と 5 です。それらの XOR は 2 です。アルゴリズムは 1 つのコンポーネントを 2 ずつシフトし、すべてのエッジの重みの最終的な XOR をゼロにします。 コンポーネントの自由度を無視した解決策は、有効ではありますが、最適ではない答えを生成します。
