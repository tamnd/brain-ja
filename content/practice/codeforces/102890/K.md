 ## 解決策
 ## 問題の理解

 私たちは、2 つの別々のプールからサイズ k のチームを編成できる方法が何通りあるのかを効率的に数えています。各プールは組み合わせによって独立して貢献しますが、少なくとも c 人のメンバーが貢献するには 1 つのプールが必要です。 

入力は、2 つのグループのサイズ (グループ A の場合は n、グループ B の場合は m) と、必要なチーム サイズ k およびグループ A からの最小貢献量 c として理解できます。出力は、有効なチームの数を表す単一の整数です。 

制約の直接的な意味は、あらゆるソリューションが多くの組み合わせを評価する際に効率的でなければならないということです。 n と m が最大約 10^5 以上と大きく、k も大きくなる可能性がある場合、サブセットを列挙したり、クエリごとに階乗のような量を繰り返し再計算したりするアプローチは遅すぎます。 2 秒の解の自然な制限は、前処理後の約 O(n + m + k) または O(k) ですが、n または m の二次関数は実行不可能です。 

この設定では、いくつかの微妙な特殊なケースが自然に現れます。 まず、k が n + m より大きい場合、利用可能な人数を超える人数を選択できないため、有効なチームは存在しません。 たとえば、n = 2、m = 2、k = 5、c = 1 の場合、正解は 0 ですが、i を盲目的に反復する不注意な実装では、無効な二項係数を試行する可能性があります。 

第二に、c が 0 の場合、問題は 0 から k までのすべての可能な分割 i の合計に帰着します。 誤って i ≥ 1 を強制する単純な実装では、グループ B からすべての k メンバーを選択するなどの有効な組み合わせが失われます。 

第三に、c が k より大きい場合、グループ A の最小要件を満たしていてもすでにチームの合計サイズを超えているため、答えは直ちにゼロになる必要があります。 

## アプローチ

 ブルートフォースアプローチでは、2 つのグループ間でチームを可能な限り分割しようとします。 0 から k までの各 i について、二項係数を使用して、A から i 人を選択し、B から k − i 人を選択する方法の数を計算します。 次に、i < c の無効な分割を除外します。 

このアプローチは、チームの有効な構成をすべて明示的に列挙するため、正しいです。 問題は計算コストです。 各二項係数の計算は、事前に計算しない限りコストがかかります。また、事前に計算したとしても、k が大きく、テスト ケースが複数ある場合、テスト ケースごとに k 値を反復すると遅くなりすぎます。 最悪のケースでは、k が約 10^5 の場合、テスト ケースごとに 10^5 の加算を実行することになり、多くのテスト ケースが実行される可能性があり、解が限界に近づきます。 

重要な観察は、階乗とモジュラー逆関数を使用して二項係数を一度事前計算できるため、各組み合わせを O(1) で計算できることです。 これにより、問題は高価な再計算から有効な i に対する単純な線形加算に変換されます。 グループ A と B の間の独立した構造により、各分割が C(n, i) * C(m, k − i) を介して乗算的に寄与することが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k · (n + m)) | お(1) | 遅すぎる |
 | 階乗事前計算による組み合わせ論 | O(n + m + k) 前処理、クエリごとに O(k) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 必要な二項係数はこれらの値によって制限されるため、最初に階乗と n + m までの逆階乗を事前計算します。 

1. n + m までのすべての i について階乗 fact[i] を事前計算します。 これにより、nCr 値を高速に構築できます。 
2. 剰余演算における除算が定数時間の乗算になるように、剰余逆行列 invfact[i] を事前計算します。 
3. i のすべての可能な値を繰り返します。ここで、 i はグループ A から何人を選択するかを表します。 
4. 制約に違反する i、具体的には i < c または i > n をスキップします。 
5. 有効な i ごとに、A から i を選択する方法と B から k − i を選択する方法の数を計算します。 
6. この製品を累計に追加します。 
7. 最終的な合計を出力します。

i を反復する理由は、チームの構成を一意に決定するためです。 i が固定されると、残りは強制されるため、素の組み合わせの場合をカウントします。 

### なぜ効果があるのか

 すべての有効なチームは、i の 1 つの値、つまりグループ A から選択された要素の数に対応します。これにより、解空間全体が重複しないケースに分割されます。 それぞれの場合において、A と B からの選択は素のセットであるため、有効な選択の数は独立して乗算されます。 したがって、すべての有効な i の合計は、すべての可能な有効なチームを 1 回だけカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)

    for i in range(2, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    return fact, invfact

def ncr(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    n, m, k, c = map(int, input().split())

    if c > k:
        print(0)
        return

    fact, invfact = build_fact(n + m)

    ans = 0
    for i in range(c, k + 1):
        if i > n:
            break
        j = k - i
        if j > m:
            continue
        ans = (ans + ncr(n, i, fact, invfact) * ncr(m, j, fact, invfact)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```階乗前処理ブロックは、定数時間の二項評価に必要なツールを構築します。 モジュラスが素数であるため、逆モジュラーはフェルマーの定理を使用して計算されます。 

i 上のループがソリューションの中核です。 各反復は、チームの固定パーティションを表します。 境界チェックにより、いずれかのグループで利用可能な人数を超える人を選択するような無効な組み合わせが試行されないことが保証されます。 

実装の微妙な詳細は、i が n を超えた場合の早期終了です。 i が大きすぎると、それ以上の値を加えても増加するだけなので、追加の有効な寄与は存在しません。 

## 実用的な例

 n = 3、m = 3、k = 3、c = 1 の小さな例を考えてみましょう。 

有効な i ごとに寄与度を計算します。 

| 私（Aから） | j (B から) | C(n,i) | C(m,j) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 3 | 3 | 9 |
 | 2 | 1 | 3 | 3 | 9 |
 | 3 | 0 | 1 | 1 | 1 |

 最終的な答えは19です。 

このトレースは、各パーティションがどのように独立して寄与するのか、また制約 c が単に合計から無効な行をどのように削除するのかを示しています。 

ここで、n = 2、m = 4、k = 3、c = 2 について考えてみましょう。 

| 私 | j | 有効 | 貢献 |
 | --- | --- | --- | --- |
 | 0 | 3 | いいえ | 0 |
 | 1 | 2 | いいえ | 0 |
 | 2 | 1 | はい | 2 * 4 = 8 |
 | 3 | 0 | いいえ (i > n) | 0 |

 結果は 8 で、グループ サイズの上限によって無効な構成がどのように排除されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m + k) | 階乗前処理が優先され、i にわたる合計は k | で線形になります。 
| スペース | O(n + m) | 階乗配列と逆階乗配列のストレージ |

 これは、前処理が線形でメイン ループがシングル パスであるため、n と m が最大 10^5 またはわずかに大きい場合の典型的な Codeforces 制約内に快適に適合します。 

## テストケース```python

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys

    def modinv(x):
        return pow(x, MOD - 2, MOD)

    def build_fact(n):
        fact = [1] * (n + 1)
        invfact = [1] * (n + 1)
        for i in range(2, n + 1):
            fact[i] = fact[i - 1] * i % MOD
        invfact[n] = modinv(fact[n])
        for i in range(n, 0, -1):
            invfact[i - 1] = invfact[i] * i % MOD
        return fact, invfact

    def ncr(n, r, fact, invfact):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    def solve():
        n, m, k, c = map(int, _sys.stdin.readline().split())
        if c > k:
            print(0)
            return
        fact, invfact = build_fact(n + m)
        ans = 0
        for i in range(c, k + 1):
            if i > n:
                break
            j = k - i
            if j > m:
                continue
            ans = (ans + ncr(n, i, fact, invfact) * ncr(m, j, fact, invfact)) % MOD
        print(ans)

    solve()
    return sys.stdout.getvalue().strip()

assert run("3 3 3 1") == "19"
assert run("2 4 3 2") == "8"
assert run("2 2 5 1") == "0"
assert run("5 5 3 0") == str((10*10*2) % MOD)
assert run("1 10 2 2") == "0"

 ## 特殊なケース

 グループ A からの必要最小限の選択がチーム サイズを超えると、アルゴリズムは直ちにゼロを返します。 入力用`n=5, m=5, k=3, c=4`、初期条件以降、ループは完全にスキップされます。`c > k`が成立し、不必要に階乗を計算することなく出力 0 が生成されます。 

チームの規模が利用可能な人数の合計を超える場合。`n=2, m=2, k=6, c=1`、すべての候補の分割は最終的にどちらかに違反します。`i <= n`または`k-i <= m`したがって、すべての反復が拒否され、最終的な合計はゼロのままになります。 

制約が最小限の場合、`c=0`、ループは 0 から k まで実行され、すべての有効なパーティションが含まれます。 このアルゴリズムは、2 つの素なセットから k 人を選択するすべての方法を正確にカウントし、二項畳み込みの恒等式を効果的に再現します。
