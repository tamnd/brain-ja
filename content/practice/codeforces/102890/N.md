 ## 解決策
 ## 問題の理解

 私たちは、0 から D までの直線状の位置のコリドーを扱っており、そこに N 個のアンテナのシーケンスを配置する必要があります。 各アンテナには優先位置があり、その位置から離れて配置すると、距離に等しい線形ペナルティが発生します。 

問題は、アンテナが完全に独立していないことです。 アンテナ i を配置するとき、その位置は前のアンテナの位置から最大 f 単位離れた位置に制約されます。 言い換えれば、連続するアンテナは、コリドーに沿って最大ステップ サイズ f で、互いに十分近くに配置する必要があります。 

f を固定値として、連続するアンテナ間の移動制約と個々の配置ペナルティの両方を考慮しながら、すべてのアンテナを配置するための最小の総コストを計算したいと考えます。 次に、この最小コストが予算 B の範囲内であるかどうかを確認します。予算 B の範囲内にある場合、その周波数 f は実行可能です。 

入力構造は、一連の優先位置 p1 から pN、コリドーの長さ D、予算 B として解釈できます。出力は、総コストが最大 B でアンテナを合法的に配置できる最小の f を求めます。 

推論すべき主な制約は、DP 構造自体です。 単純な遷移では、各アンテナ i と位置 j について、考えられるすべての前の位置 j − k (k は最大でも f) が考慮されます。 これにより、N 個のアンテナ、D 個の位置、およびサイズ f のウィンドウにわたる入れ子の依存関係が作成されるため、D が大きい場合、単純なアプローチはすぐに遅くなりすぎます。 

特定の f に対する最適な構成が一意ではない場合、微妙なエッジ ケースが発生します。 配置パスが異なると、最終的な位置は同じになる可能性がありますが、中間コストが異なるため、最小限のみを維持する必要があります。 アンテナごとの貪欲な選択は、後で安価なグローバル構成をブロックする局所的に最適な遷移を選択する可能性があるため、ここでは失敗します。 

0 と D 付近の境界で別の問題が発生します。j − k が負になるか、D を超える場合、それらの遷移は無視する必要があります。 全範囲を想定した不用意な実装は、無効な状態を静かに伝播し、コストを過小評価または過大評価することになります。 

## アプローチ

 効率を無視する場合、連続する位置の差が最大 f であるという制約の下で、すべてのアンテナのあらゆる可能な配置を試すことを考えることができます。 各アンテナについて、[0, D] の位置を選択し、隣接制約を適用します。 これは本質的に、N 層と層ごとに D+1 ノードを持つ層状グラフでのパス検索です。 可能な状態の数は (D+1)^N に応じて増加しますが、これは D と N が中程度の値であっても完全に実行不可能です。 

より構造化されたビューでは、問題は階層化された DAG 上の最短パスであることがわかります。ここで、各層 i はアンテナ i に対応し、各ノードは位置 j です。 ノードのコストは abs(j − pi) で、エッジは制約 |j −Previous_j| を使用して層 i−1 から i を接続します。 ≤ f.

 この構造は自然に動的プログラミングにつながります。 DP[i][j] を、アンテナ i を位置 j に配置するための最小コストとして定義します。 遷移は、前のレイヤーに対するスライディング ウィンドウの最小値であり、距離 f 内の位置に制限されます。 これが最適化の中核です。以前のすべての状態を再計算する代わりに、移動間隔にわたってすでに計算された最小値を再利用します。 

ボトルネックは、すべての DP 状態で効率的に最小範囲を計算することになります。 単純な遷移はアンテナごとに O(D * f) であり、O(N * D * f) になります。 f は D と同じくらい大きくなる可能性があるため、これは O(N * D^2) となり、遅すぎます。 

重要な観察は、実現可能性が f において単調であるということです。 最大ステップ f でアンテナを配置できる場合、より大きなステップ f1 ≥ f を許可しても、有効な遷移のセットが増加するだけです。 これは、f に対して解が存在する場合、それはすべてのより大きな値に対しても存在することを意味します。 この単調性により、f に対する二分探索が可能になります。

各チェックは DP を使用し、各 DP は O(N * D * f) または最適化 O(N * D) で実行されます。 標準的なスライディング ウィンドウの最適化 (遷移にわたる単調なキュー) を使用すると、内部係数を償却して O(1) に削減し、実現可能性チェックごとに O(N * D) を与えます。 D に対する二分探索と組み合わせると、合計の複雑さは O(N * D log D) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((D+1)^N) | O(N) | 遅すぎる |
 | 最適化なしの DP | O(N * D^2) | O(N * D) | 遅すぎる |
 | 最適化された DP + 二分探索 | O(N * D log D) | O(N * D) | 承認済み |

 ## アルゴリズムのチュートリアル

 候補値 f を固定し、予算 B 内にすべてのアンテナを配置できるかどうかを判断します。 

1. DP[i][j] が位置 j で終わる最初の i 個のアンテナを配置する最小コストを表す DP テーブルを構築します。 これは、配置決定と累積ペナルティの両方をエンコードします。 
2. [0, D] のすべての j に対して DP[1][j] = abs(j − p1) を設定して、最初のアンテナを初期化します。 これは、最初のアンテナに先行する制約がないことを反映しています。 
3. 2 から N までの各アンテナ i について、すべての位置 j の DP[i][j] を計算します。 各状態は、|j − k| によって制約されるアンテナ i−1 の有効な位置にのみ依存します。 ≤ f.
 4. DP[i][j] を計算するには、[j−f, j+f] の k にわたる DP[i−1][k] の最小値を取得し、abs(j − pi) を加算します。 これが機能する理由は、j で終わる有効な構成は、許可された移動範囲内の有効な前の位置から取得されなければならないためです。 
5. k にわたるスライディング ウィンドウ構造を使用して範囲を最小値に効率的に維持し、各 DP 層が O(D * f) ではなく O(D) で計算されるようにします。 
6. アンテナ N の DP を埋めた後、[0, D] のすべての j に対して min(DP[N][j]) を取得して答えを抽出します。 これは可能な限り安価な終了位置を表します。 
7. この最小コストを B と比較して、f が実現可能かどうかを判断します。 
8. DP 実現可能性チェックを述語として使用して、[0, D] の f に対して二分探索を実行し、実現可能な最小値を返します。 

### なぜ効果があるのか

 各 DP 状態は、特定の位置で終了するすべての有効な部分配置間の最適コストを表します。 反復では、移動の制約を尊重する遷移のみが考慮されるため、無効な構成が導入されることはありません。 すべての有効な完全な構成には対応する一連の DP 遷移があり、DP は常にそれらの間で最小コストを維持するため、層 N での最終結果はその固定 f に対する全体的な最適値になります。 f における実現可能性の単調性により、f に対する二分探索では最適な境界をスキップできないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def feasible(N, D, B, p, f):
    dp_prev = [INF] * (D + 1)
    for j in range(D + 1):
        dp_prev[j] = abs(j - p[0])

    for i in range(1, N):
        dp_curr = [INF] * (D + 1)

        # sliding window minimum over dp_prev
        from collections import deque
        dq = deque()

        # initialize window for j = 0
        for k in range(0, min(D + 1, f + 1)):
            while dq and dp_prev[dq[-1]] >= dp_prev[k]:
                dq.pop()
            dq.append(k)

        for j in range(D + 1):
            # expand right side of window
            r = j + f
            if r <= D:
                while dq and dp_prev[dq[-1]] >= dp_prev[r]:
                    dq.pop()
                dq.append(r)

            # remove out-of-window elements
            while dq and dq[0] < j - f:
                dq.popleft()

            best_prev = dp_prev[dq[0]]
            dp_curr[j] = best_prev + abs(j - p[i])

        dp_prev = dp_curr

    return min(dp_prev) <= B

def solve():
    N, D, B = map(int, input().split())
    p = list(map(int, input().split()))

    lo, hi = 0, D
    ans = D

    while lo <= hi:
        mid = (lo + hi) // 2
        if feasible(N, D, B, p, mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、実現可能性チェックと二分探索に分かれています。 実現可能性関数は、前のレイヤーと現在のレイヤーのみを保持して DP を行ごとに構築するため、メモリの爆発が回避されます。 

デキューは、スライド間隔 [j − f, j + f] にわたって dp_prev の最小値を維持するために使用されます。 各インデックスは、両端キューに出入りするのは最大 1 回だけであるため、レイヤーごとの線形の複雑さが維持されます。 よくある間違いは、各 j の正しい境界拡張を正しく管理できないことです。 ここでは、すべての候補ポジションが最終的に考慮されるように段階的に処理されます。 

二分探索ではこのチェッカーがラップされます。これは、f を増加しても制約が緩和されるだけであるため、実現可能性が一度 true になると元に戻ることはありません。

 ## 特殊なケース

 アンテナの最適な配置が、許容される移動ウィンドウの境界に正確に位置する場合、クリティカルなエッジ ケースが発生します。 たとえば、dp_prev が位置 0 および f = 2 で最小である場合、j = 2 の場合、遷移には k = 0 が含まれている必要があります。スライディング ウィンドウには両方のエンドポイントが正しく含まれている必要があります。 そうしないと、DP は有効な最適パスを逃し、コストが誤って膨らみます。 

もう 1 つのエッジ ケースは、D = 0 の場合です。すべてのアンテナが 1 つの位置に折りたたまれるため、DP はゼロでの差の絶対値の単純な合計に縮退します。 j 上のすべてのループが単一の状態に減少し、デキュー ロジックが依然としてシングルトン ウィンドウで機能するため、アルゴリズムはこれを処理します。 

3 番目のエッジ ケースは、f = 0 の場合に発生します。この場合、アンテナはすべての層にわたって同じ位置に留まることを強制されます。 DP は遷移を k = j のみに正しく制限します。これは、各アンテナが同じ固定位置で距離コストを個別に支払うことを意味します。
