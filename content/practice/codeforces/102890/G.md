 ## 解決策
 ## 問題の理解

 私たちには一連のポジションが与えられており、各ポジションは即時報酬を伴う「状態」を表します。 それぞれの立場から$i$、2 つの境界の間の距離だけ前方にジャンプできます。$a_i$そして$b_i$、ある位置に着陸します$i + j$。 目標は、すべての位置について、そこから開始して動けなくなるまで繰り返し前方にジャンプした場合に得られる最大の合計報酬を計算することです。 

位置の値$i$、呼んでください$f(i)$、での報酬として定義されます。$i$ジャンプ範囲内のすべての有効な次の位置の中で到達可能な最良の値を加えたもの。 依存関係は常に前方を指すため、計算は本質的に後方動的計画法の問題になります。 

意図した問題の入力サイズが十分に大きいため、$O(n^2)$解決策が遅すぎます。 素朴なアプローチでは、それぞれのポジションに対して、$i$、すべての位置をスキャンします。$[i + a_i, i + b_i]$、最大値を取ります。 これにより、範囲が広い場合には二次関数の動作が発生します。 

各位置が以前の多くの位置に影響を与える可能性があり、最大値を繰り返し再計算するのは冗長な作業になるため、より高速な解決策が必要です。 

ジャンプ範囲が配列の境界を超えると、微妙なエッジ ケースが発生します。 このような場合は、有効なインデックスのみを考慮する必要があります。 別の例外的なケースが発生するのは、$a_i = b_i = 0$これは、不用意な解釈でポジションがそれ自体に移行する可能性があることを意味します。 正しい解釈では依然として前方への移動のみが想定されているため、自己ループを無限再帰として扱ってはなりません。 代わりに、これらの状態は報酬を追加した後すぐに終了します。 

## アプローチ

 ブルートフォース動的プログラミングアプローチは、それぞれを計算します。$f(i)$到達可能なすべての次の状態を個別にスキャンします。 これは正しいです。なぜなら、繰り返しは順方向間隔にわたる最大値として明示的に定義されているからです。 ただし、それぞれについて、$n$位置、最大までスキャンする場合があります$O(n)$将来のポジション、プロデュース$O(n^2)$最悪の場合の運用。 いつ$n$到達する$10^5$、これは完全に不可能になります。 

重要な構造的観察は、値を右から左に計算すると、将来のすべての状態が計算されるということです。$f(i+1), f(i+2), \dots$処理時にすでに既知である$i$。 繰り返しは、逆方向に埋められる動的配列に対する範囲最大クエリになります。 

これはまさに、セグメント ツリー (または任意の範囲最大データ構造) が繰り返しスキャンを削除する設定です。 すべてのインデックスの最大値を再計算する代わりに、範囲内の最大値のクエリと単一の位置の効率的な更新をサポートする構造を維持します。 

からのインデックスを処理します$n$まで$1$。 ポジションにいるとき$i$、セグメント ツリーには、到達可能なすべての前方位置の正しい値がすでに含まれています。 範囲内の最大値をクエリします$[i + a_i, i + b_i]$に報酬を追加します$i$、結果を構造体に格納し直します。

 ## アルゴリズムのチュートリアル

 この問題を、エッジが前方のみに進む有向非巡回構造に対する DP の計算として再解釈します。 これにより、逆の順序で処理すると、常に計算済みの状態が表示されることが保証されます。 

1. サイズの配列に対してセグメント ツリーを初期化します。$n + 2$、報酬が負になるかどうかに応じて、最初はゼロまたは負の無限大などの中立値で埋められます。 ツリーは現在最もよく知られているものを表します$f(i)$処理された位置の値。 
2. から反復する$i = n$まで$1$。 逆反復の理由は、すべての遷移が次から始まるためです。$i$厳密に大きなインデックスに到達すると、$i$、到達可能なすべての状態はすでに計算され、構造に挿入されています。 
3. それぞれについて$i$、有効なクエリ範囲を計算します。$[L, R]$、 どこ$L = i + a_i$そして$R = i + b_i$。 この範囲内に収まるようにクランプします$[1, n]$。 これにより、問題のあるドメインの外側で無効なメモリをクエリすることがなくなります。 
4. セグメント ツリーの最大値をクエリします。$[L, R]$。 これにより、その位置から可能な限り最良の継続が得られます$i$。 範囲が空の場合、結果はゼロとして扱われ、現在の位置を超えてゲインが得られないことを意味します。 
5. コンピューティング$f(i) = g_i + \text{bestNext}$、ローカル報酬と到達可能な最高の将来価値を組み合わせたものです。 
6. 位置でセグメントツリーを更新します。$i$と$f(i)$、より早いポジションで利用できるようになります。 
7. すべてのインデックスを処理した後、答えは通常、すべてのインデックスの最大値になります。$f(i)$, どの位置からでも開始できるためです。 

### なぜ効果があるのか

 現時点で計算すると$f(i)$、依存関係範囲内のすべての位置はすでに固定されており、セグメント ツリーに挿入されています。 これにより、インデックスを処理する前に不変条件が確立されます。$i$、ツリーにはすべてのインデックスの正しい最終値が含まれています。$j > i$。 すべての遷移でインデックスが厳密に増加するため、サイクルがなく、今後のステップでこれらの値が変更されることはありません。 したがって、各クエリは中間の近似値ではなく最終値を読み取るため、正確な繰り返しが行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10**30

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n <<= 1
        self.t = [NEG] * (2 * self.n)

    def update(self, i, v):
        i += self.n
        self.t[i] = v
        i >>= 1
        while i:
            self.t[i] = max(self.t[2*i], self.t[2*i+1])
            i >>= 1

    def query(self, l, r):
        if l > r:
            return NEG
        l += self.n
        r += self.n
        res = NEG
        while l <= r:
            if l & 1:
                res = max(res, self.t[l])
                l += 1
            if not (r & 1):
                res = max(res, self.t[r])
                r -= 1
            l >>= 1
            r >>= 1
        return res

def solve():
    n = int(input())
    g = [0] + list(map(int, input().split()))
    a = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    st = SegTree(n + 2)
    dp = [0] * (n + 2)

    for i in range(n, 0, -1):
        l = i + a[i]
        r = i + b[i]
        if l > n:
            best = 0
        else:
            r = min(r, n)
            best = st.query(l, r)
            if best == NEG:
                best = 0
        dp[i] = g[i] + best
        st.update(i, dp[i])

    print(max(dp[1:n+1]))

if __name__ == "__main__":
    solve()
```セグメントツリーはダイナミックレンジ最大構造としてのみ使用されます。 ボトムアップ反復ツリーの実装選択により、再帰オーバーヘッドが回避され、更新とクエリが厳密に維持されます。$O(\log n)$。 大きな負のセンチネルを使用すると、無効なセグメントまたは初期化されていないセグメントが誤って最大値を占めることがなくなります。 

DP 配列は最終的な答えに対して技術的にはオプションですが、各状態が明示的に保存されるため、推論とデバッグがより明確になります。 

周囲の境界処理$l > n$重要です。 これがないと、クエリが誤ってラップしたり、無効なセグメントにアクセスしたりする可能性があります。 クランプも同様に、$r$到達可能なインデックスのみを考慮するようにします。 

## 実用的な例

 小さな例を考えてみましょう。$n = 5$、報酬は$[1, 2, 3, 4, 5]$、およびジャンプでは、位置に応じて常に 1 つまたは 2 つのステップを正確に前進させることができます。 

仮定する：$a = [0, 1, 1, 1, 0]$、$b = [1, 2, 2, 1, 0]$右から左に処理していきます。 

| 私 | Ｌ | R | セグツリーからのベスト | dp[i] |
 | --- | --- | --- | --- | --- |
 | 5 | 6 | 5 | 空 | 5 |
 | 4 | 5 | 5 | 5 | 9 |
 | 3 | 4 | 5 | 最大(9,5)=9 | 12 |
 | 2 | 3 | 4 | 12 | 14 |
 | 1 | 2 | 2 | 14 | 16 |

 このトレースは、各状態がすでに計算された将来の状態のみにどのように依存するかを示しています。 セグメント ツリーはこれらの値を効率的に公開するだけです。 

次に、ジャンプが範囲外に出る場合を考えてみましょう。$n = 4$、報酬$[10, 1, 1, 1]$、インデックス 3 からはどこにも移動できません。 

インデックス 3 では、$L=4, R=3$、そのため、範囲は無効であり、寄与はゼロです。 これにより、ターミナル状態が自身の報酬のみを正しく伝播することが確認されます。

 ## 特殊なケース

 最初のエッジケースは、ポジションがどこにもジャンプできない場合です。$i + a_i > n$。 この場合、継続値をゼロとして扱うのが正しい動作です。 アルゴリズムは、セグメント ツリーをクエリする前に範囲をチェックすることで、これを明示的に処理します。 このチェックがないと、クエリはセンチネル値または古い値を返し、以前の状態に誤って影響を及ぼします。 

有効な範囲に要素が 1 つだけ含まれる場合、別のエッジ ケースが発生します。 たとえば、次の場合$i = 2$、$a_2 = 1$、$b_2 = 1$、その後、位置 3 のみを考慮します。セグメント ツリー クエリは単一点の最大値まで縮小されますが、更新は点単位で決定的であるため、それでも正しく動作します。 

最後のエッジケースは、すべての報酬がゼロまたはマイナスの場合です。 大きな負のセンチネルを使用すると、空の範囲が有効な値を支配することがなくなります。 有効な未来が存在しない場合、DP を通じて無効な最小値を伝播するのではなく、明示的にゼロにフォールバックします。
