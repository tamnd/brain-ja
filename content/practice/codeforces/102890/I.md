 ## 解決策
 ## 問題の理解

 示されている 3 つの購入金額が与えられています。$t_1, t_2, t_3$。 という機能もあります`discount(x)`これは、名目上の総額で何かを購入した場合に実際にいくら支払うかを示します$x$。 割引関数は何らかの方法でコストを削減する可能性があり、すでに定義されているか、何らかの形式で入力に提供されていると想定されます。 

グループ化すると支払総額が変わるため、目標は、割引を適用する前にこれら 3 つの値をグループ化する方法を決定することです。 割引を適用する前に、アイテムを個別に支払うことも、大きなバンドルにまとめることもできます。 グループ化戦略が異なると最終コストも異なりますので、可能な限り最小のコストを選択する必要があります。 

問題の構造は小さく、形状が固定されています。項目は 3 つだけなので、意味のあるグループ化パターンの数は一定です。 たとえ割引関数自体が任意であっても、それを適用する方法の組み合わせ構造は限られています。 

制約の観点から見ると、入力サイズが増加しないため、任意のサイズのサブセットに対する順列検索や動的プログラミングは直ちに除外されます。 問題は決定の点で一定のサイズであるため、ソリューションはテスト ケースごとに 1 回一定時間で実行する必要があります。`discount`評価が可能です。 

ここでよく見られる素朴な誤解は、再計算を繰り返したり、より深い再帰を行ったりして、3 つの値について考えられるすべてのバイナリ ツリー構造を考慮しようとすることです。 それは論理的には正しいですが、不必要であり、過度に複雑になりやすいです。 

微妙なエッジケースは、割引関数が非線形であるか、あるいは敵対的である場合です。 たとえば、次のように動作する可能性があります。 

-`discount(x) = x`(割引なし)
 - または`discount(x) = 1`正の x の場合 (定額料金)

 どちらの場合も、グループ化の動作によって最適な戦略が大幅に変化するため、単調性や凸性を仮定するのではなく、5 つの構造化オプションすべてを与えられたとおりに正確に評価する必要があります。 

## アプローチ

 強引なアイデアは、問題を文字通りに解釈することです。3 つの要素をグループ化し、各グループのコストを計算し、最小値を取得するためにあらゆる方法を試みます。 3 つの要素の場合、グループ化とは、割引関数を適用する前に、隣接するアイテムをマージするか、すべてをマージするかを決定することを意味します。 

構造を持たずにすべての可能性を拡張すると、セットをサブセットに再帰的に分割することを想像するかもしれませんが、それはすぐに指数関数的なサブセット DP に一般化されます。 より大きな入力の場合、次のようになります。$O(2^n)$、それは不可能です。 

重要な点は、問題が実際に任意のパーティションを要求しているわけではないということです。 このステートメントでは、有効なすべてのグループ化構成がすでに明示的に列挙されており、そのうちの 5 つが正確に存在します。 

割引を 3 つすべてに個別に適用するか、1 つのペアを統合するか、3 つすべてを統合します。 

これにより、問題は組み合わせ検索から 5 つの式の直接評価に分解されます。 割引関数の構造は、呼び出し可能であること以外には重要ではありません。

 | 5 つの固定式を評価する |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を 5 つの候補値を計算し、最小値を取得することに縮小します。 

1. 3 つの値を読み取ります$t_1, t_2, t_3$。 これらは固定され独立しているため、計算全体を通じて定数として扱うことができます。 
2. コンピューティング$s_1 = discount(t_1) + discount(t_2) + discount(t_3)$。 これはアイテムを決してマージしないことに相当します。つまり、各アイテムは割引機能を通じて個別に処理されます。 
3. コンピューティング$s_2 = t_1 + discount(t_2 + t_3)$。 ここでは、割引を適用する前に 2 番目と 3 番目の項目をマージします。 最初の項目は変更されません。 
4. コンピューティング$s_3 = discount(t_1 + t_2) + t_3$。 これにより、最初の 2 つの項目がマージされ、3 番目の項目は分離されたままになります。 
5. コンピューティング$s_4 = discount(t_1 + t_3) + t_2$。 これにより、1 番目と 3 番目の項目がマージされます。 連続していないように見えても、この問題により任意のペアリングが可能になるため、この構成を考慮する必要があります。 
6. コンピューティング$s_5 = discount(t_1 + t_2 + t_3)$。 これにより、すべてが 1 つのバンドルに統合され、割引が 1 回適用されます。 
7. 5 つの計算値の最小値を返します。 

### なぜ効果があるのか

 割引を適用する有効な方法はすべて、3 つの要素をグループに分割する選択に対応します。各グループはサイズ 1、サイズ 2、またはサイズ 3 のいずれかであり、各グループは割引関数を通じて独立して評価されます。 3 つの要素の場合、指定された構造の下で重要な個別のパーティションの数はちょうど 5 つです。 アルゴリズムはそれらをすべて重複または省略することなく列挙するため、最適なソリューションはこれらの計算値のいずれかに一致する必要があります。

演算の順序は、各候補を独立して計算する必要があるという意味でのみ重要です。 中間結果を誤って再利用すると、異なるグループ化の前提が混在する可能性があります。 

## 実用的な例

 割引関数が恒等式である例を考えてみましょう。`discount(x) = x`。 

入力：```
1 2 3
```それぞれの場合を計算します。 

| 式 | 値 |
 | --- | --- |
 | s1 = 1 + 2 + 3 | 6 |
 | s2 = 1 + (2 + 3) | 6 |
 | s3 = (1 + 2) + 3 | 6 |
 | s4 = (1 + 3) + 2 | 6 |
 | s5 = (1 + 2 + 3) | 6 |

 すべての戦略は同等であるため、答えは 6 です。これは、割引関数が線形である場合、グループ化は効果がないことを確認します。 

ここで、一律割引関数を考えてみましょう。`discount(x) = 1`任意の正の x に対して。 

入力：```
1 2 3
```| 式 | 値 |
 | --- | --- |
 | s1 = 1 + 1 + 1 | 3 |
 | s2 = 1 + 1 | 2 |
 | s3 = 1 + 1 | 2 |
 | s4 = 1 + 1 | 2 |
 | s5 = 1 | 1 |

 ここでは、すべてをグループ化することが最適であり、答えは 1 です。これは、5 つの構造すべてをチェックする必要がある理由を示しています。最適な戦略は完全に割引関数の形状に依存します。

 ## 特殊なケース

 すべての値が等しい場合、問題によって対称性が隠れてしまうことがよくあります。 のような入力の場合`t1 = t2 = t3 = x`、どのグループ化も構造的に類似した式を生成します。 このアルゴリズムは 5 つのケースすべてを個別に評価するため、ケースが見逃されることはなく、複数の式が同点であっても最小値が正しく検出されます。 

1 つの値がゼロの場合、グループ化は割引関数によっては予期しない動作をする可能性があります。 たとえば、次の場合`discount(0) = 0`、その場合、ゼロとのマージは、方法に応じて中立または有益になる可能性があります。`discount`より大きな額で行動します。 すべての組み合わせを明示的に評価することで、そのような相互作用が 5 つの候補のうちの少なくとも 1 つで確実に捕捉されます。
