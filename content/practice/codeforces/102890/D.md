 ## 解決策
 ## 問題の理解

 このタスクは、数字が後続の文字の繰り返しカウンターとして機能する圧縮文字列をデコードすることです。 入力は、数字と文字のセグメントが交互に含まれる単一のエンコードされた文字列であり、目的は、その前にある数字に従って各文字を繰り返すことによって、元の展開された文字列を再構築することです。 

この文字列は、カウントが 10 進数として明示的に書き込まれ、複数の桁を含む場合があることを除いて、ランレングス スタイルのエンコーディングと考えることができます。 各数値は次の文字シーケンスに適用され、そのシーケンス内の各文字が出力内でその回数だけ繰り返されます。 

計算の観点から見ると、主な制約は解析だけでなく出力サイズでもあります。 入力が非常に大きな繰り返し係数をエンコードしている場合、デコードされた文字列が非常に大きくなる可能性があります。 これにより、不必要に中間構造を構築したり、不変の文字列を繰り返し連結したりするアプローチは即座に除外されます。 

主な課題は、数字を完全な数字に正しくグループ化し、それらが後続の正しい文字ブロックに適用されるようにすることです。 各桁を個別に処理する単純なスキャンでは、カウントが 9 を超えるケースは壊れます。 

いくつかの特殊なケースでは、典型的な間違いが明らかになります。 問題の 1 つは複数桁の数字です。 たとえば、12a のような入力では aaaaaaaaaaaaa が生成されます。 バグのあるアプローチでは、これを 1 の繰り返し、次に 2 の繰り返し、そして a として扱う可能性がありますが、12 は 1 つの数字であるため、これは正しくありません。 

もう 1 つの問題は、文字グループの繰り返しです。 たとえば、3ab2c は、aabbbc やその他の誤った解釈ではなく、aaabbbc になる必要があります。 位置ずれは通常、数値アキュムレータを正しいタイミングでリセットできないことが原因で発生します。 

最後の微妙なケースは、繰り返し回数が多いことです。 解析が正しい場合でも、ループ内で単純な文字列連結を使用すると、割り当てコストが繰り返されるため、パフォーマンスが低下する可能性があります。 

## アプローチ

 ブルート フォースの解釈は簡単です。文字列を左から右にスキャンし、数字が見つかるたびに、数字以外の文字が現れるまで完全な数値を構築し、それに応じて次の文字またはブロックを繰り返し、結果の文字列に追加します。 これは正しいです。エンコーディングは明示的にシーケンシャルであり、文字は直前の番号を超えるものに依存しないためです。 

ただし、結果文字列が大きくなると非効率が生じます。 ループ内で Python 文字列に繰り返し追加すると、各連結で新しい文字列が作成され、総コストは出力サイズの二次関数に向かって低下する可能性があります。 さらに、繰り返し回数が大きい場合、出力自体が実行時間の大半を占めます。 

重要な観察は、この問題では、単純なストリーミング解釈を超えて中間構造を維持する必要がないということです。 数値が解析されると、効率的な連結戦略を使用して対応する繰り返し文字をすぐに出力したり、チャンクを stdout に直接出力したりできます。 

これにより、タスクが入力上の単一の線形パスに削減され、各文字が 1 回処理され、各数字は数値の構築にのみ寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (文字列連結) | O(合計出力サイズ²) | O(合計出力サイズ) | 遅すぎる |
 | 最適なストリーミング構築 | O(n + 出力サイズ) | O(出力サイズ) または O(1) 追加 | 承認済み |

 ## アルゴリズムのチュートリアル

1. ゼロに初期化された現在の数値アキュムレータを維持しながら、入力文字列を左から右に走査します。 このアキュムレータは、連続した数字を完全な繰り返しカウントに収集します。 
2. 現在の文字が数字の場合、前の数字をシフトし、新しい数字を追加することによってアキュムレータを更新します。 これにより、複数桁の数値が個別に扱われるのではなく、正しく形成されるようになります。 
3. 数字以外の文字が見つかった場合、アキュムレータをその文字の繰り返し回数として解釈します。 現時点では番号は完成しているため、すぐに適用する必要があります。 
4. 文字の繰り返しアキュムレータ回数を出力バッファに追加します。 処理後、アキュムレータをゼロにリセットして、次の数値を独立して形成できるようにします。 
5. 文字列全体が消費されるまでこのプロセスを続けます。 最後に、バッファには完全にデコードされた文字列が含まれます。 

このプロセスの正しさは、エンコード内のすべての数値の直後に、それが適用される文字が続くという事実に依存するため、数値が貪欲に蓄積されると、グループ化に曖昧さがなくなります。 

### なぜ効果があるのか

 このアルゴリズムはローリング不変条件を維持します。つまり、スキャン内のどの位置でも、アキュムレータは最新の連続する数字ブロックの数値を正確に保持し、部分的に処理された数字ブロックが複数の演算に分割されることはありません。 数字以外の文字はすべて直前の数字を使用する必要があるため、各出力は局所的に正しく、将来の入力とは独立しています。 これにより、最終出力が、エンコードされた各セグメントを順番に完全に展開したものと同等であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

res = []
num = 0
in_number = False

for ch in s:
    if ch.isdigit():
        num = num * 10 + (ord(ch) - ord('0'))
        in_number = True
    else:
        if in_number:
            res.append(ch * num)
            num = 0
            in_number = False

sys.stdout.write(''.join(res))
```実装はストリーミングのアイデアに直接準拠しています。 変数`num`基数 10 の構築を使用して、数字を完全な整数に累積します。 旗`in_number`文字の前に完全な数字が読み取られた場合にのみ展開を試みることを保証します。 

繰り返しの割り当てを避けるために、出力は文字列として連結されるのではなく、リストに保存されます。 デコードされた各ブロックは 1 回追加され、最後の結合により効率的に結果が生成されます。 

微妙な詳細の 1 つが両方をリセットします`num`そして`in_number`手紙を消費した後にフラグを立てます。 このリセットがないと、後続の文字が以前のカウントを誤って再利用してしまいます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = sys.stdin.readline().strip()

    res = []
    num = 0
    in_number = False

    for ch in s:
        if ch.isdigit():
            num = num * 10 + (ord(ch) - ord('0'))
            in_number = True
        else:
            res.append(ch * num)
            num = 0
            in_number = False

    return ''.join(res)

 ## 特殊なケース

 エッジケースの 1 つは、複数桁の累積です。 インプットを考慮する`12x`。 アルゴリズムは次のように読み取ります`1`、その後更新します`num`1に設定してから読み取ります`2`そしてアップデート`num`～12.の場合のみ`x`が発生すると、繰り返しブロックが生成されます。 これにより、数値が誤って分割されることが回避され、文字が評価を強制するまでアキュムレータが連続する数字にわたって持続することがトレースによって確認されます。 

もう 1 つの特殊なケースは、数字と文字の間で繰り返される遷移です。 入力用`3a2b1c`、各文字の後に状態がリセットされ、カウントが繰り越されないことが保証されます。 各セグメントは独立してデコードされ、アキュムレータが次のセグメントにリークすることはありません。 

最後の特殊なケースは、反復係数が大きいことです。 100000 のような数値が表示された場合でも、アルゴリズムは最終バッファー追加を超えて中間の繰り返し構造を保存することはありません。これにより、出力サイズが大きい場合でも解析が安定します。
