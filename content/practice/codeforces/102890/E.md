 ## 解決策
 ## 問題の理解

 私たちは循環する人々の列を与えられており、それぞれがパフォーマンスの価値を持っています。 各人のボーナスは、その人のパフォーマンスが左右の隣の人とどのように比較されるかによって決まります。 ある人が一方の側で隣人よりも優れた成績を収めた場合、固定値に隣人のボーナスを加えたものに等しい基本ボーナス寄与分をその側から受け取ります。 それらが両方の隣接するものよりも優れている場合、最終的なボーナスは、可能な 2 つの貢献度の最大値となります。 輪になって座るので、最初と最後の人も隣の人です。 

タスクは、これらの依存関係ルールに基づいてすべての人のボーナスを計算することです。 依存関係は独立していません。各値は隣接する値に依存し、その値自体も他の値に依存し、サイクル全体にわたる制約システムを形成します。 

この構造は、これらの相互依存関係を解決しないと直接評価できないことを意味します。 各位置は両方の隣接位置に依存する可能性があり、依存関係の方向はパフォーマンス値の比較によって動的に決定されます。 

人の数が多い場合 (たとえば最大 200,000 人)、値を繰り返し再計算したり、配列全体に更新を単純に伝播したりするソリューションは、最悪の場合二次関数になります。これは、各更新が円周上で連鎖反応を引き起こす可能性があるためです。 これにより、メモ化を伴わない反復緩和や単純な再帰が即座に除外されます。 

パフォーマンス値が厳密な増加または減少サイクルを形成する場合、微妙なエッジ ケースが発生します。 このような場合、すべての位置は一貫した方向に依存し、単純なローカル伝播では、左から右への寄与と右から左への寄与の間の独立性を誤って仮定する可能性があります。 

たとえば、円の中に価値観を持つ 3 人の人がいるとします。`[1, 2, 3]`。 値 3 を持つ人は両方の隣人よりも優れているため、ボーナスは両方の側に依存します。 単純な左から右へのパスでは部分的な値が割り当てられる可能性がありますが、右から左への影響が正しく伝播されず、一貫性のない結果が生成されます。 

別のエッジ ケースは、すべての値が等しい場合に発生します。`[5, 5, 5, 5]`。 隣人より厳密に優れている人はいないため、すべてのボーナスは基本レベルのままである必要があります。 エッジごとに少なくとも 1 つの厳密な不等式の方向を想定するアルゴリズムでは、更新が誤って伝播されます。 

## アプローチ

 それぞれの有向比較をボーナス貢献の潜在的な「フロー」を作成するものとして解釈すると、依存関係の構造がより明確になります。 隣接するペアの場合、`p[i] > p[j]`、 それから`i`～から得られる寄付金を受け取ることができます`j`。 これにより、隣接するエッジ間に有向エッジが作成されますが、方向はグローバルに固定されず、値の相対的な順序に依存します。 

ブルートフォース手法では、値が変化しなくなるまですべてのボーナスが繰り返し更新されます。 各反復では、すべての位置がその近隣をチェックし、いずれかの近隣がより良い寄与を与える場合はその値を更新します。 各更新は現在の隣接状態に依存するため、値は円の周囲に徐々に伝播します。 

これが機能するのは、システムが単調であるためです。ボーナスは増加するだけです。 ただし、最悪の場合、各更新は円の周りの反復ごとに 1 つのステップのみを伝播する可能性があります。 と`n`要素、これにはかかります`O(n)`反復回数と各反復コスト`O(n)`、生産`O(n^2)`複雑。 入力が大きい場合、これは実現できません。 

重要な観察は、更新ルールには、インデックスではなく値の比較によって引き起こされる方向の非対称性があるということです。 によって引き起こされる順序を修正したら、`p[i]`、「下り坂から上り坂へ」方向に沿った遷移のみを処理できます。 人は厳密に小さいパフォーマンスを持つ隣接者からのみ貢献を受け取ることができ、その貢献自体はさらに小さい隣接者に依存します。 

これにより、問題は、各ノードがより小さい値を持つ隣接ノードのみに接続するグラフ上の最長の重み付きチェーンを計算することに変わります。 各ノードには最大 2 つの隣接ノードがあるため、エッジを小さい値から大きい値に向けると、構造は有向非巡回グラフになります。 この DAG では、メモ化された DFS または反復処理を使用して値を降順で計算できます。`p[i]`。 

パフォーマンスを低下させることによってノードをソートすると、ノードを処理するときに、考えられるすべての寄与因子 (より小さい値を持つ必要がある) がすでに計算されていることが保証されます。

 ## アルゴリズムのチュートリアル

 隣接する値の比較に基づいて循環依存関係を有向関係に変換し、パフォーマンスの降順で DP を計算します。 

1. 降順にソートされたインデックスの配列を構築します。`p[i]`。 これにより、ノードを処理するときに、より小さい値を持つ両方の隣接ノードが有効なコントリビュータである場合、それらがすでに処理されることが保証されます。 順序付けは、依存関係の解決からサイクルを取り除く鍵となります。 
2. 配列を初期化する`f[i] = 0`すべてのポジションに。 これは、最初は貢献が割り当てられていないことを表します。 
3. ソートされた順序でインデックスを反復処理します。 ポジションごとに`i`、循環インデックスを使用してその左右の隣を調べます。 
4. 隣人ごとに`j`、どうかを確認してください`p[i] > p[j]`。 そうであれば、その方向からの候補者の貢献は次のとおりです。`B + f[j]`。 これを計算する理由は、`i`厳密にはより優れています`j`、 それで`j`のすでに計算されたボーナスは、次のように上方に拡張できます。`i`。 
5. 有効な貢献の中で最高の価値を維持します。 両方の近傍が小さい場合は、両方の候補の寄与の最大値を取得します。 1 つだけが有効な場合は、その方が使用されます。 どれも有効でない場合、値はゼロのままです。 
6.割り当て`f[i]`計算された最良の値に。 

降順で処理する理由は、いつでも`p[i] > p[j]`、の値`j`処理する前にすでに完了している必要があります`i`。 これにより、更新の繰り返しが防止され、各状態が 1 回だけ計算されることが保証されます。 

### なぜ効果があるのか

 核となる不変条件は、ノードを処理するときの条件です。`i`、すべての隣人`j`そのような`p[j] < p[i]`すでに最終値を持っています`f[j]`。 寄与分は厳密に小さい値から厳密に大きい値にのみ流れるため、後の操作で変更されることはありません。`f[j]`影響を与える形で`i`。 これにより、依存関係グラフが次の順序で非循環になります。`p`、それぞれのことを保証します。`f[i]`計算された値は割り当て時の最終値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, B = map(int, input().split())
    p = list(map(int, input().split()))
    
    order = sorted(range(n), key=lambda i: p[i], reverse=True)
    f = [0] * n
    
    for i in order:
        best = 0
        
        left = (i - 1) % n
        right = (i + 1) % n
        
        if p[i] > p[left]:
            best = max(best, B + f[left])
        if p[i] > p[right]:
            best = max(best, B + f[right])
        
        f[i] = best
    
    print(*f)

if __name__ == "__main__":
    solve()
```コードは、人数と基本ボーナス値を読み取ることから始まります。 パフォーマンス配列は次の場所に保存されます。`p`。 次に、パフォーマンスの低下に基づいてインデックスを並べ替え、潜在的に寄与するパフォーマンスの低い近隣をすべて計算した後で、パフォーマンスの高い位置が計算されるようにします。 

配列`f`計算されたボーナスを格納します。 ソートされた順序でインデックスごとに、モジュロ演算を使用してその 2 つの循環近傍を計算します。 厳密に小さいパフォーマンスを持つ近隣からの貢献のみを考慮します。 有効な投稿ごとに追加される`B`すでに計算された隣接値を加えます。 有効な貢献の最大値が、そのインデックスの最終ボーナスとなります。 

微妙な点は、循環隣接を強制するためにモジュロ インデックスを使用していることです。 これがないと、最初と最後の要素の境界ケースには特別な処理が必要になり、間違いが発生しやすくなります。 

## 実用的な例

 検討してください`n = 3`、`B = 10`、`p = [1, 2, 3]`。 

順番に処理していきます`[2, 1, 0]`。 

| 私 | p[i] | 左 | 右 | f[左] | f[右] | f[i] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 2 | 3 | 1 | 0 | 0 | 0 | 0 |
 | 1 | 2 | 0 | 2 | 0 | 0 | 10 |
 | 0 | 1 | 2 | 1 | 0 | 10 | 20 |

 インデックス 2 では、両方の近傍は小さくなりますが、`f`値はまだ伝播に役立ちません。 インデックス 1 では、インデックス 0 のみが小さいため、利益が得られます。`B + f[0] = 10`。 インデックス 0 では、値の順序付けコンテキストでは両方の近傍が大きくなりますが、インデックス 1 のみが小さくなります。`10 + 10 = 20`。 

このトレースは、パフォーマンスの上昇順に値がどのように蓄積されるかを示します。 

ここで考えてみましょう`n = 4`、`B = 5`、`p = [4, 1, 3, 2]`。 

| 私 | p[i] | 左 | 右 | 有効な貢献 | f[i] |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 4 | 3 | 1 | 3,1から | max(5+f[3], 5+f[1]) |
 | 2 | 3 | 1 | 3 | 1,3から | max(5+f[1], 5+f[3]) |
 | 3 | 2 | 2 | 0 | 2から | 5+f[2] |
 | 1 | 1 | 0 | 2 | なし | 0 |

 これは、インデックスの順序ではなくローカル比較に応じて、さまざまなノードがどのように寄与を蓄積するかを示しています。

 ## 特殊なケース

 1 人サークルの場合は、次のようにします。`n = 1`、左と右の隣は循環インデックスによるものです。 以来`p[i] > p[i]`false の場合、コントリビューションはトリガーされず、結果は次のようになります。`0`。 両方の近隣チェックが失敗するため、アルゴリズムはこれを自然に処理します。 

のために`p = [5, 5, 5, 5]`、あらゆる比較`p[i] > p[j]`失敗したため、すべてのノードが割り当てを行う`f[i] = 0`。 遷移はアクティブ化されず、DP は全体を通してゼロで安定したままであるため、ソートされた順序は無関係です。 

次のような厳密な単調サイクルの場合`[1, 2, 3, 4, 5]`、各ノードは、その小さな隣接ノードからのみ寄与を受け取ります。 降順で処理すると、ノードを評価するときに、すべての小さなノードがすでに最終的な寄与を持っていることが保証されるため、ノードを再訪することなくチェーンの蓄積がきれいに行われます。
