 ## 解決策
 ## 問題の理解

 すべて同じ長さの文字列のリストが与えられ、回転によって定義された等価関係によってそれらをグループ化するように求められます。 文字を循環的にシフトすることによって一方が他方から取得できる場合、2 つの文字列は同じグループとみなされます。これは、文字列をある位置で切り取り、結果として得られる 2 つの部分を交換することを意味します。 

タスクは、指定されたすべての文字列の中に、基礎となる個別の「ローテーション クラス」がいくつ存在するかをカウントすることです。 各文字列は正確に 1 つのクラスに属しており、異なる文字列が相互にローテーションされている場合には、同じクラスを表す場合もあります。 

問題を解釈する便利な方法は、円の上に書かれた各文字列を想像することです。 円を回転しても、表現しているオブジェクトは変わりません。 すべての入力文字列の中に異なる円がいくつ存在するかを数えたいとします。 

この種の問題によって暗示される制約は通常、文字列のすべてのペアを直接比較するのが遅すぎるほど十分に大きいです。 N 個の文字列があり、それぞれの長さが L である場合、すべてのペア間のすべての回転を単純に比較すると、最悪のケースで O(N² · L²) の動作が発生しますが、N が大きい場合にはこれは実行不可能になります。 

重要な点は、等価性が標準の文字列等価性ではなく循環等価性であることです。 たとえば、「abc」、「bca」、「cab」はすべて同じオブジェクトとして扱う必要があります。 単純な間違いは、文字列を回転を考慮せずに直接比較することだけであり、文字列を別のものとして誤って扱うことになります。 

文字列に繰り返しパターンが含まれる場合、別の特殊なケースが発生します。 たとえば、「aaaa」はそのすべてのローテーションに等しいため、不完全なマッチング ロジックに依存している場合、不注意なローテーション チェックによってカウントが過剰になる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。文字列ごとに、以前に処理されたすべての文字列と比較し、それらが相互に循環回転しているかどうかを確認します。 2 つの文字列が回転しているかどうかをテストするには、一方の文字列の可能なすべてのシフトを試し、それをもう一方の文字列と 1 文字ずつ比較します。 これが機能するのは、回転の等価性がすべての文字を揃えるシフト位置の存在によって定義されるためです。 

ただし、これはすぐに高価になります。 各ペアについて、最大 L 回の回転を試みる可能性があり、各比較のコストは O(L) となり、ペアあたり O(L²) になります。 N 個の文字列の場合、これは O(N²·L²) となり、一般的な制約で使用できる値をはるかに超えます。 

重要な観察は、各ローテーション クラスに固有の正規の代表があるということです。 すべてのペアを比較する代わりに、すべての回転が同じ代表にマッピングされるように、各文字列を単一の決定論的な形式に変換できます。 この代表値を計算すると、問題は個別の値をカウントすることになります。 

これを行う標準的な方法は、各文字列の辞書編集上最小のローテーションを計算することです。 これは、Booth のアルゴリズムを使用すると、文字列あたり O(L) 時間で効率的に実行できます。 すべての文字列を最小限のローテーションに変換した後、これらの正規形式をハッシュ セットに挿入し、出現する一意の値の数をカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²・L²) | O(1) おまけ | 遅すぎる |
 | 正準回転（ブース） | O(N・L) | O(N・L) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 各文字列をローテーション クラスの問題として解釈する

 すべての文字列を円形の配置を表すものとして扱います。 私たちの目標は、同じ円のすべての回転で同一となる一意の識別子を各円に割り当てることです。 この再構成は、ペアごとの等価性問題を正規化問題に変換するため、不可欠です。 

### ステップ 2: 各文字列の辞書編集上最小のローテーションを計算する

各文字列について、すべての巡回シフトの中で辞書順で最小の回転を見つけます。 これが機能するのは、回転等価性によってすべての巡回シフトのセットが保存され、そのセット内の最小要素が各等価性クラスで一意であるためです。 

このステップでは、すべての回転を明示的に生成せずに線形時間でこの最小回転を計算するため、Booth のアルゴリズムが通常使用されます。 

### ステップ 3: 正規形式をセットに挿入する

 各文字列が最小ローテーションに変換されたら、それをハッシュ セットに挿入します。 同一の回転クラスは同一の正規文字列を生成するため、重複は自動的に折りたたまれます。 

### ステップ 4: セットのサイズを出力する

 セット内の個別の要素の数は、個別の回転クラスの数に直接対応します。 

### なぜ効果があるのか

 すべての文字列には、辞書編集上最小のローテーションが 1 つだけあります。 文字列のすべての回転は同じ巡回セットを生成するため、同じ最小要素を共有します。 逆に、互いに回転している 2 つの文字列は、同一の回転セットを持たなければならず、したがって同一の最小値を持たなければなりません。 これにより、ローテーション クラスと正規の代表との間に 1 対 1 のマッピングが確立され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def booth(s: str) -> str:
    s = s + s
    n = len(s)
    f = [-1] * n
    k = 0

    for j in range(1, n):
        i = f[j - k - 1]
        while i != -1 and s[j] != s[k + i + 1]:
            if s[j] < s[k + i + 1]:
                k = j - i - 1
            i = f[i]
        if s[j] != s[k + i + 1]:
            if s[j] < s[k]:
                k = j
            f[j - k] = -1
        else:
            f[j - k] = i + 1

    start = k
    return s[start:start + len(s) // 2]

def solve():
    n = int(input())
    seen = set()

    for _ in range(n):
        s = input().strip()
        seen.add(booth(s))

    print(len(seen))

if __name__ == "__main__":
    solve()
```この実装の中心的な考え方は、すべての文字列が概念的に Booth プロシージャ内で 2 倍になり、すべての回転が連続した部分文字列になるということです。 返されたスライスは、最小回転の開始インデックスに対応します。 

セット`seen`は正規形式のみを保存するため、ローテーション間での重複は自然に崩壊します。 唯一のデリケートな部分は、2 倍の文字列を操作するため、返される部分文字列が元の長さであることを確認することです。

 ## 特殊なケース

 「aaaa」のような 1 文字の繰り返し文字列の場合、すべての回転は同一になります。 アルゴリズムはそれらすべてを同じ正規文字列にマッピングするため、セットには当然 1 つのエントリのみが含まれます。 単純な回転比較でもシフトを反復する可能性がありますが、等価性チェックが正しい限り、何も誤って分類されることはありません。 

長さ 1 の文字列の場合、ブースのアルゴリズムはきれいに縮退します。これは、2 倍になった文字列の長さが 2 であり、有効な回転が 1 つだけ存在するためです。 返される正規形式は文字列そのものであるため、それぞれの個別の文字は 1 つのクラスに正確に寄与します。 

「ababab」のような繰り返しパターンの場合、複数の回転が複数のシフトにわたって同じに見える場合があります。 最小限の回転でも決定論的な開始点が選択され、部分的な比較方法によって発生する可能性のある過剰カウントが防止されます。
