 ## 解決策
 ## 問題の理解

 このタスクは基本的に、単純なトークン化ルールの下で、特定のテキストに出現する「単語」の数を数えるというものです。 テキスト行を表す文字列が与えられ、問題が暗示する定義に従って、その中に存在する個別の単語トークンがいくつあるかを判断する必要があります。 単語は連続したアルファベット文字で構成され、スペース、句読点、数字などは区切り文字として機能します。 出力は、テキストの分割後にそのような単語セグメントがいくつ出現するかを表す単一の整数です。 

入力を表示するもう 1 つの方法は、生の文字ストリームをスキャンし、それを最大の連続するアルファベットの部分文字列にグループ化することです。 非文字から文字に移行するたびに、新しい単語が始まり、文字から非文字に移行するたびに、現在の単語が終了します。 

このような問題の制約は通常、文字列の長さが約 10^5 または 10^6 文字に達するほど十分に大きいです。 これは、スライスを繰り返したり、ループ内で高価な文字列操作を使用したりするなど、二次的なアプローチは失敗することを直ちに意味します。 唯一の実行可能なアプローチは、入力に対して単一の線形スキャンを実行し、各文字を 1 回処理することです。 

単純な間違いは、スペースのみで分割することから生じます。 たとえば、入力が与えられたとすると、`hello,world`、ナイーブな`split()`スペースを指定すると 1 つの単語として扱われますが、正解は 2 つの単語です。`hello`そして`world`。 別の微妙な失敗は、複数のセパレータが連続して出現する場合に発生します。`a---b`。 単純なカウンターは注意しないと空のトークンを誤ってカウントする可能性がありますが、正しい解釈では空のセグメントは無視され、文字シーケンスへの遷移のみがカウントされます。 

## アプローチ

 ブルートフォース手法では、文字列を、文字以外の文字で区切られた一連の部分文字列として扱います。 考えられるすべての開始インデックスを反復し、区切り文字が見つかるまで展開し、部分文字列を記録することができます。 これは概念的には簡単ですが、重複する領域を繰り返しスキャンする危険があります。 すべての文字の文字列などの最悪の場合、各部分文字列の展開は O(n) になり、O(n^2) の動作が発生します。 

重要な点は、部分文字列を実体化する必要がないということです。 「単語の内側」と「単語の外側」の間の境界を検出するだけで済みます。 これにより、左から右へのスキャン中に単一のブール状態を追跡するという問題が軽減されます。 各文字は 1 回だけ処理され、非文字状態から文字セグメントに入る場合にのみ単語数が増加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース部分文字列抽出 | O(n^2) | O(n) | 遅すぎる |
 | シングルパス状態追跡 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 2 つの情報を維持します。単語のカウンターと、現在単語の中にあるかどうかを示すフラグです。 

1. カウンタを初期化する`words = 0`そしてブール値`in_word = False`。 この状態は、最初は単語セグメントの外側にいることを表します。 

2. 文字列内の各文字を左から右に繰り返します。 各文字は文字または区切り文字として分類されます。 

3. 現在の文字が文字であり、`in_word`が False の場合、新しい単語を入力していることを意味します。 インクリメントします`words`1とセットで`in_word = True`。 このステップは、連続する各アルファベット ブロックの最初の文字のみをカウントするようにするため、非常に重要です。 

4. 現在の文字が文字であり、`in_word`が True の場合、同じ単語内で続行し、何もしません。 これにより、複数文字の単語を数えすぎることがなくなります。 

5. 現在の文字が文字ではない場合、次のように設定します。`in_word = False`、後続の文字が新しい単語を開始することを示します。 この移行により、連続する複数のセパレータが正しく処理されるようになります。 

6. すべての文字を処理した後、`words`が答えです。 

正しさは不変式から得られます。`in_word`前の文字が現在アクティブな単語セグメントに属する文字であった場合にのみ True です。 すべての単語は最初の文字で 1 回だけカウントされ、再度カウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip("\n")
    
    words = 0
    in_word = False
    
    for ch in s:
        if ch.isalpha():
            if not in_word:
                words += 1
                in_word = True
        else:
            in_word = False
    
    print(words)

if __name__ == "__main__":
    solve()
```このソリューションは入力行を読み取り、文字ごとに処理します。 の`in_word`flag は、同じ単語内の文字が二重にカウントされることを回避する中心的なメカニズムです。 唯一の微妙な点は、`isalpha()`問題の定義に応じて区切り文字に句読点やその他の文字以外の記号が含まれる場合があるため、スペースのみをチェックするのではなく。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    return sys.stdout.getvalue() if False else capture(inp)

def capture(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = backup
    return out.getvalue().strip()

# minimal cases
assert capture("") == "0"
assert capture("abc") == "1"
assert capture("a b c") == "3"

# punctuation-heavy
assert capture("hello,world") == "2"

# consecutive separators

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字がまったく含まれていない入力です。`"12345!!!"`。 アルゴリズムが初期化されます`in_word = False`そして文字に遭遇することはないので、カウンターはずっとゼロのままです。 出力は正しく行われています`0`。 

もう 1 つのエッジ ケースは、区切り文字で直接始まり、その後に単語が続く文字列です。`"--abc"`。 最初の文字がリセットされる`in_word`ただしカウンターには影響しません。 いつ`'a'`に達すると、新しい単語数が正しくトリガーされ、結果は次のようになります。`1`。 

最後のケースは、次のような区切り文字と 1 つの文字を交互に使用する場合です。`"a-b-c"`。 各文字の前には文字以外の文字が続くため、それぞれが新しい単語を開始します。 アルゴリズムは文字ごとに 1 回だけインクリメントします。`3`、これは意図したセグメンテーション ルールと一致します。
