 ## 解決策
 ## 問題の理解

 私たちは、結合していない 3 つの生徒グループに関する選択問題を扱っています。このグループは、A、B、C というラベルが付いたアイテムの 3 つのバケツと考えることができます。各グループには固定数の生徒がおり、ちょうど K 人の生徒からなるチームを形成したいと考えています。 追加の制約は、K 人の生徒のうちちょうど c 人がグループ C の出身でなければならないということです。 

C から c 人の生徒を受け入れることを約束したら、残りの K − c 人の生徒は、グループ A と B の結合から完全に選択する必要があります。残りの部分内では、合計が K − c である限り、A と B の間の分割は柔軟です。 

したがって、実際の組み合わせ構造は次のとおりです。まず、C からどの c 要素を選択し、次に A と B の組み合わせから K − c 要素を選択します。ここで、A と B の間の分割は任意です。 

出力は、これらの制約を満たす有効なチームの合計数です。 

このステートメントはやや代数的で合計に重点を置いた方法で提示されていますが、重要な隠された構造は、互いに素な集合の組み合わせを数えているということであり、唯一自明ではない部分は、A と B の間で K − c の選択を何通りに分配できるかを数えていることです。 

グループのサイズを a、b、d (それぞれ A、B、C) と表すと、制約により、C から c を選択し、A ∪ B から K − c を選択することが強制されます。 

素朴なアプローチでは、A と B からそれぞれ選択された要素の数を列挙し、すべての有効な分割を合計しようとします。 これにより、二項係数の畳み込みが行われます。 

この問題の一般的なバージョンの制約は、グループ サイズが大きくなり、クエリごとの階乗再計算が不可能になる可能性があることを意味します。そのため、どのような解決策でも、前処理後の計算を O(1) または O(log n) に削減する必要があります。 

単純な実装は、大きな二項係数が繰り返し再計算される場合、特に K が大きい場合に失敗します。 たとえば、a = b = 10^5 および K = 10^5 の場合、0 から K − c までのすべての分割 i を反復すると、テストごとにすでに 10^5 の演算が行われ、これを繰り返すと遅すぎます。 

もう 1 つの微妙な問題は、二重にカウントしたり、同じ合計につながる A と B の異なる分割を 1 回だけ合計する必要があることを忘れたりすることです。 不注意に組み合わせて実装すると、合計ではなく乗算が行われ、誤った過大カウントが発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、制約の分解から直接得られます。 C から c 個の要素を選択した後、A と B から K − c 個の要素を選択する必要があります。これを考える 1 つの方法は、すべての可能な値 i を反復処理することです。ここで、i は B から選択された要素の数です。そのような分割ごとに、B から i 個の要素を選択し、A から K − c − i 個の要素を選択し、すべての有効な i を合計します。 これにより次の式が生成されます

 C(b, i) に C(a, K − c − i) を掛けた i の合計に C(d, c) を掛けます。 

これは、選択範囲を A と B の間で分割する可能なすべての方法を列挙しているため、正しいです。 

ただし、合計は K において線形であり、最悪の場合、K は A と B の合計サイズと同じくらい大きくなる可能性があります。これにより、繰り返した場合や制約が大きい場合、アプローチが遅くなりすぎます。 

重要な観察は、A と B の間の分割の合計が、まさにヴァンデルモンドの恒等として知られる二項畳み込み恒等であるということです。 すべての分布を明示的に合計する代わりに、A と B をサイズ a + b の単一の結合プールとして扱うことができます。 次に、A ∪ B から K − c 要素を選択することは、単一の二項係数 C(a + b, K − c) を使用して直接行うことができます。 C から c 個の要素を選択する残りの部分は独立しており、係数 C(d, c) に寄与します。 

したがって、問題全体は、2 つの二項係数を計算し、それらを乗算することに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (分割列挙) | O(K) | お(1) | 遅すぎる |
 | 最適 (ヴァンデルモンド + 組み合わせ論) | 前処理後の O(1) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 組み合わせ分解と事前計算された階乗を使用して答えを計算します。 

1. 3 つのグループのサイズとパラメータ K および c を読み取ります。 これらは、全体でいくつの要素を選択する必要があるか、およびグループ C から具体的にいくつの要素を選択する必要があるかを定義します。 
2. グループ C から正確に c 人の生徒を選択する方法の数を計算します。そのサイズのサブセットを自由に選択しているため、これは標準の二項係数 C(|C|, c) です。 
3. C から c 個の要素が固定されたら、残りのタスクは A と B の結合から K − c 個の要素を選択することです。選択を分割する代わりに、A と B をサイズ |A| の 1 つのセットとして扱います。 + |B|。 
4. A ∪ B から K − c 個の要素を選択する方法の数を C(|A| + |B|, K − c) として計算します。 これにより、A と B の間の分割の合計全体が置き換えられます。 
5. C からの選択肢と A ∪ B からの選択肢は相互作用しないため、2 つの独立した選択肢を乗算して最終的な答えを求めます。 

### なぜ効果があるのか

 重要な特性は、すべての有効なチームが 2 つの独立した決定によって一意に記述できることです。どの c 要素が C に由来し、どの K − c 要素が A ∪ B に由来するかということです。セットを折りたたむと、A と B の間のこれらの K − c 要素の内部分布は総数を変更しません。これは、このような分割はすべて、和集合内のサイズ K − c の 1 つのサブセットに正確に対応するためです。 これはまさに、分割の合計を結合セットの単一の二項係数と同等にする組み合わせ恒等式です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXN = 200000  # adjust if needed

fact = [1] * (MAXN + 1)
invfact = [1] * (MAXN + 1)

for i in range(1, MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN] = pow(fact[MAXN], MOD - 2, MOD)
for i in range(MAXN, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def ncr(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    a, b, c, K, c_needed = map(int, input().split())
    ans = ncr(c, c_needed) * ncr(a + b, K - c_needed) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```階乗事前計算により、各二項係数を一定時間で計算できます。 機能`ncr`はゼロを返すことで無効な範囲を安全に処理します。これにより、存在する要素よりも多くの要素を要求したり、負の数を要求したりするなど、不可能な選択が自然にカバーされます。 

最後の行では、独立した組み合わせの選択肢を乗算し、「C から選択」と「A ∪ B から選択」への分解を反映しています。 

## 実用的な例

 A に 3 つの要素があり、B に 2 つの要素があり、C に 4 つの要素があり、K が 4 であり、C から c = 2 が必要な例を考えてみましょう。 

| ステップ | C からの値 | A∪Bからの残り | 計算 |
 | --- | --- | --- | --- |
 | C | から選択してください C(4,2) = 6 | | |
 | A∪Bから選択 | | C(5,2) = 10 | |
 | 最終回 | | | 60 |

 これは、C から要素の数を修正すると、残りはマージされたセットからの純粋なサブセット選択になることを示しています。 

ここで、K が c に等しい、つまり C からすべてを取得するという境界ケースを考えてみましょう。 

| ステップ | C からの値 | A∪Bからの残り | 計算 |
 | --- | --- | --- | --- |
 | C | から選択してください C(4,4) = 1 | | |
 | A∪Bから選択 | | C(5,0) = 1 | |
 | 最終回 | | | 1 |

 これにより、A または B から要素が取得されない縮退ケースが数式で正しく処理されることが確認されます。

    import sys

    def ncr(n, r):

    a, b, c, K, c_needed = map(int, input().split())

 ## 特殊なケース

 1 つのエッジ ケースは、C からの必要な数がゼロに等しい場合に発生します。 その状況では、アルゴリズムは A と B からすべてを選択することになります。 a = 3、b = 4、c = 5、K = 3、c_needed = 0 のような入力の場合、計算は C(5,0) と C(7,3) の積となり、35 と評価されます。階乗式では C(n,0) が 1 として定義されているため、アルゴリズムはこれを自然に処理します。 

K − c が a + b を超える場合、別のエッジ ケースが発生します。 たとえば、a = 2、b = 2、c = 10、K = 6、c_needed = 1 の場合、C(a + b, K − c_needed) は C(4,5) になり、正しく 0 と評価されます。これにより、無効な過剰選択が答えに寄与することが防止され、不可能な構成が組み合わせ式によって自動的に破棄されます。
