 ## 解決策
 ## 問題の理解

 エッジごとに成長する無向グラフを維持しています。 すべてのエッジには、0 または 1 のバイナリの重みがあります。各挿入リクエストの後、そのエッジを追加することで特定のグローバル プロパティが有効に保たれるかどうかを決定する必要があります。 

プロパティはサイクルを通じて定義されます。グラフ内の任意の単純なサイクルを取得し、それに沿ったすべてのエッジの重みを XOR します。 グラフは、すべてのサイクルの XOR が 1 に等しい場合にのみ有効とみなされます。新しいエッジが提案されるたびに、それを追加することでこの条件が維持されるかどうかを判断する必要があります。 存在する場合は、永続的に追加します。 そうでない場合は拒否します。 

主な問題点は、新しいエッジがそれぞれサイクルを作成する可能性があり、そのサイクルの XOR がローカル情報だけでなく既存の構造全体に依存することです。 

制約は大きく、最大 300,000 個の頂点と 500,000 個のクエリがあります。 これにより、接続性またはサイクルのプロパティをクエリごとに最初から再計算することが直ちに排除されます。 パスを探索したり、エッジごとに DFS を使用してサイクル XOR を再計算したりするアプローチは、密度が高い場合には実行可能な限界をはるかに超えて二次関数の動作に低下します。 目的のソリューションは、ほぼ一定時間または対数時間で各クエリに応答するのに十分な構造を維持する必要があります。 

複数の異なるパスが既に 2 つの頂点を接続している場合、微妙なエッジ ケースが発生します。 たとえば、u と v の間に 2 つの異なるパスがある場合、新しいエッジを追加すると、それらのパスによって XOR が決定されるサイクルが作成されます。 コンポーネント内の XOR 距離を正しく追跡しないと、エッジが誤って承認または拒否されてしまいます。 拒否されたエッジを無視すると、別の失敗ケースが発生します。エッジが追加されなかったとしても、無効なサイクルが作成されるため、今後の整合性チェックが制約されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 現在のグラフを明示的に維持します。 クエリごとに、エッジを一時的に追加し、u から v まで DFS または BFS を実行して、既存のパスを見つけます。 パスが存在する場合は、それに沿って重みの XOR を計算します。 新しいエッジは、そのパスの XOR に x を加えた XOR となるサイクルを形成します。 これが必要な条件に一致する場合、エッジを維持します。 それ以外の場合は削除します。 

これは正しく動作しますが、遅すぎます。 各接続とパスの XOR クエリには、最悪の場合 O(n) のコストがかかり、これを最大 500,000 回実行する可能性があり、複雑さは O(nq) に達し、これは 10^11 演算のオーダーに相当します。 

重要な観察は、パリティ情報で強化された Disjoint Set Union を使用してグラフ構造を維持できることです。 フルパスを保存する代わりに、ノードごとに、そのノードからそのコンポーネントの代表までの XOR 距離を保存します。 2 つのコンポーネントをマージする場合、新しいエッジが既存のパリティ制約と一致しているかどうかを判断できます。 そうであれば、マージします。 そうでない場合は拒否します。 これにより、パス クエリが潜在的な DSU を使用した定数時間チェックに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n + q) | 遅すぎる |
 | XOR パリティを備えた DSU | O(q α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがその親と値を保存する DSU を維持します。`xor_to_parent`これは、DSU ツリー内のノードからその親までの XOR 距離を表します。 拡張により、任意のノードからそのコンポーネント ルートまでの XOR 距離を計算できます。 

1. 各ノードを XOR 値 0 を使用して独自の親として初期化します。これは、すべての頂点が制約のない孤立したコンポーネントとして開始されることを意味します。 
2. を定義します。`find(u)`パス圧縮の実行中に u のルートを返す関数。 圧縮中に更新します`xor_to_parent[u]`u からルートに XOR を直接保存します。 これにより、今後のクエリが一定時間になることが保証されます。 
3. 関数を実装する`xor_dist(u)`これは、保存された値を使用して u からルートに XOR を返します。 これは、DSU パスに沿って累積されたパリティを表します。 
4. エッジ (u、v、x) を処理するときは、最初にそれらのルート ru と rv を XOR 距離 xu と xv とともに見つけます。 
5. ru が rv に等しい場合、u と v はすでに接続されています。 その場合、このエッジを追加するとサイクルが形成されます。 そのサイクルの XOR は xu XOR xv XOR x です。 すべてのサイクルの XOR は 1 に等しい必要があるため、これが 1 に等しいかどうかを確認します。1 に等しい場合は、エッジを受け入れます。 そうでない場合は拒否します。 
6. ru と rv が異なる場合は、2 つのコンポーネントが接続されていることになります。 いつでも一方のルートをもう一方のルートの下に接続できますが、新しいエッジが一貫性を持つようにパリティを設定する必要があります。 ru の下に rv をマージし、暗黙のパス構造に沿って xu XOR xv XOR x が 1 になるようにルート接続に制約を割り当てます。 これにより、今後のクエリの一貫性が確保されます。 
7. エッジが受け入れられた場合は YES を出力し、結合を実行します。そうでない場合は NO を出力して破棄します。 

### なぜ効果があるのか

 各ノードは、コンポーネント ルートまでの一貫した XOR 距離を維持します。 2 つのノード間のパスは、それらのルート距離の XOR 差として表現できます。 したがって、任意のサイクル XOR は、実際のグラフ走査とは無関係に、これらの保存された値によって完全に決定されます。 DSU の不変条件により、コンポーネントをマージするたびに、単一の一貫したパリティ制約が強制されることが保証されます。 既存のコンポーネントで矛盾が発生した場合、それはエッジが不正な XOR を含むサイクルを作成したときに現れ、それを検出して拒否します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.xr = [0] * (n + 1)

    def find(self, x):
        if self.parent[x] != x:
            p = self.parent[x]
            self.parent[x] = self.find(p)
            self.xr[x] ^= self.xr[p]
        return self.parent[x]

    def get_xor(self, x):
        self.find(x)
        return self.xr[x]

    def union(self, a, b, w):
        ra = self.find(a)
        rb = self.find(b)
        xa = self.get_xor(a)
        xb = self.get_xor(b)

        if ra == rb:
            return (xa ^ xb ^ w) == 1

        self.parent[rb] = ra
        self.xr[rb] = xa ^ xb ^ w ^ 1
        return True

def main():
    n, q = map(int, input().split())
    dsu = DSU(n)
    out = []

    for _ in range(q):
        u, v, x = map(int, input().split())
        if dsu.union(u, v, x):
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```DSU は、構造ポテンシャルと XOR ポテンシャルの両方を同時に維持します。 の`find`関数は、XOR 値を蓄積しながらパス圧縮を実行し、次のことを保証します。`xr[x]`常に x からそのルートまでの XOR を表します。 の`union`この関数は、マージとサイクル検証の両方を 1 ステップで処理します。 

重要な実装の詳細は、コンポーネントをマージするときの割り当てです。 表現`xa ^ xb ^ w ^ 1`新しく形成されたサイクルは XOR が 1 に等しい必要があるという要件をエンコードします。この制約が省略されたり、配置が間違っていた場合、構造は矛盾したパリティ状態を静かに蓄積します。

 ## 特殊なケース

 重要なエッジ ケースは、一連のマージの直後にサイクルが形成され、XOR 制約が累積されたパリティを通じてのみ表示される場合です。 たとえば:

 入力:```
1 2
1 2 0
2 1 1
```最初のエッジの後、ノードは XOR 距離 0 で接続されます。2 番目のエッジは XOR 0 ^ 0 ^ 1 = 1 でサイクルを形成し、条件を満たすため、受け入れられる必要があります。 DSU は、パスを再構築する必要なく、保存されている XOR 距離を使用してこれを正しく評価します。 

もう 1 つのケースは、2 つのノードがすでに同じコンポーネント内に存在するが、ゼロ以外の XOR 差が格納されている場合です。 このアルゴリズムは純粋に DSU 状態からサイクル XOR を正しく計算し、トラバーサルが必要ないことを保証します。
