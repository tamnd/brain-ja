 ## 解決策
 ## 問題の理解

 2 列のコインのグリッドが与えられます。`m`列。 アリスとボブはどちらも左上隅から開始します`(1,1)`そして右下に到達したい`(2,m)`右または下への移動のみを使用します。 アリスが最初に移動し、道に沿ってすべてのコインを集めます。 ボブはその後移動し、アリスが訪れなかった独房のコインだけを集めます。 ボブはコインのコレクションを最大化したいと考えていますが、アリスはコインのコレクションを最小限に抑えたいと考えています。 目標は、両方が最適にプレイした場合のボブのコインの合計を計算することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは列の数を提供します`m`と 2 つのシーケンス`m`上部と下部の行のコインを表す整数。 出力はテスト ケースごとに 1 つの整数で、アリスとボブが最適にプレイした場合にボブが獲得できる最大コインを表します。 

制約が意味するのは、`m`まで到達できます`10^5`, の合計`m`すべてのテストケースにわたって、最大でも`10^5`。 単一グリッドの可能なパスの数は指数関数的であるため、すべてのパスを総当たりで列挙することは不可能です。`m`。 代わりに、テスト ケースごとの線形ソリューションが必要です。 エッジ ケースには、単一列のグリッド、アリスの最善の戦略が自明でないグリッド、およびコインの分布によって最適な選択が自明ではないグリッド (上の行の最後に大きなコインがあり、下の行の最初に大きなコインがある場合など) が含まれます。 

小さいですが注意が必要な例は次のとおりです。```
1
3
1 2 3
3 2 1
```アリスは、上部に沿って右に進み、最後の列で下に進むことを選択でき、ボブが最適に移動した場合、左下隅に 3 枚のコインが残ります。 アリスのターンはボブの最適なカウンターを考慮する必要があるため、常に上部または下部に沿って真っすぐに進むという単純な戦略ではボブの利益を最小限に抑えることができません。 

## アプローチ

 ブルートフォースアプローチでは、アリスが取り得るすべてのパスを考慮し、それぞれに対してボブの最適なカウンターパスを計算します。 がある`m`アリスが上の行から下の行に切り替えることができる列。 そのような選択ごとに、ボブが収集するコインの数を計算します。 のために`m`列ごとに、ボブのパス内のコインを合計する必要があるため、これは最悪の場合 O(m^2) になります。 これでは遅すぎます`m`まで`10^5`。 

重要な洞察は、考えられるすべてのパスを明示的に考慮する必要はないということです。 グリッドには 2 行しかなく、移動は右と下に制限されているため、アリスは正確に`m`意味のあるパス: 彼女は列を選択します`k`彼女は下に移動し、上にあるすべてのコインを集めるまで`k`、次に下に移動して、残りを下に集めます。 次に、ボブは残りのコインを自分のパスに沿って受け取ります。これは、終了後に一番上の行に残っているコインの最大値として計算できます。`k`そして前に一番下の列に集めたコイン`k`。 これにより、行のプレフィックスとサフィックスの合計が事前に計算されるため、問題は O(m) に削減されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(m^2) | O(m) | 遅すぎる |
 | 最適 | O(m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 一番上の行のサフィックスの合計を事前計算します。 させて`top_suffix[j]`列のコインの合計になります`j`に`m`上の行にあります。 これは、アリスが列の後にスイッチを下げた場合に、ボブが一番上の行で収集できるコインを表します。`j-1`。 
2. 一番下の行のプレフィックス合計を事前計算します。 させて`bottom_prefix[j]`列のコインの合計になります`1`に`j-1`一番下の行にあります。 これは、アリスが列のスイッチを下げた場合にボブが一番下の行で収集できるコインを表します。`j`。 
3. 変数を初期化する`min_bob`無限に。 これにより、アリスのすべての選択肢にわたってボブが獲得できる最小最大コインが追跡されます。 
4. 各列を反復処理します。`k`から`1`に`m`。 コンピューティング`bob_coins = max(top_suffix[k+1], bottom_prefix[k-1])`、アリスが列の上から下に切り替わった場合にボブが集めるコインを表します。`k`。 アップデート`min_bob`現在の値と、`bob_coins`。 
5. すべての列を繰り返した後、`min_bob`両方が最適にプレイした場合、 はボブにとって最適なスコアです。 

これが機能する理由は、考えられる切り替えポイントごとに、アリスがボブの残りのコインの最大値を最小化し、ボブが行内の残りのコインの最大値を収集するためです。 ゲームはアリスにとって 1 つの決定点に限定されるため、すべての選択肢を効率的に評価できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        m = int(input())
        top = list(map(int, input().split()))
        bottom = list(map(int, input().split()))
        
        top_suffix = [0] * (m + 2)
        bottom_prefix = [0] * (m + 2)
        
        for i in range(m - 1, -1, -1):
            top_suffix[i + 1] = top_suffix[i + 2] + top[i]
        
        for i in range(1, m + 1):
            bottom_prefix[i] = bottom_prefix[i - 1] + bottom[i - 1]
        
        min_bob = float('inf')
        for k in range(1, m + 1):
            bob_coins = max(top_suffix[k + 1], bottom_prefix[k - 1])
            if bob_coins < min_bob:
                min_bob = bob_coins
        print(min_bob)

if __name__ == "__main__":
    solve()
```コードでは、`top_suffix`列インデックスに揃えるために 1 だけシフトされ、`top_suffix[k+1]`スイッチ列の後の列の合計を厳密に表します。 同様に、`bottom_prefix[k-1]`は、アリスが切り替える前のパスの下にあるコインを表します。 これにより、off-by-one エラーが注意深く回避されます。
