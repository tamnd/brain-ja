[CF 1555B - 2 つのテーブル](https://codeforces.com/problemset/problem/1555/B)

 **評価:** 1300
 **タグ:** ブルートフォース
 **解決時間:** 4 分 31 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 私たちには長方形の部屋が与えられ、その中には軸が整列した固定された長方形のテーブルがあります。 現在、テーブルは部屋内のブロックを占有していますが、境界内に完全に収まっている限り、このテーブルを部屋内のどこにでもスライドさせることができます。 

また、同じ部屋のどこかに配置したい、固定寸法の 2 つ目の長方形のテーブルもあります。 2 番目のテーブルを最初のテーブルに重ねることはできませんが、エッジに接触することは許可されます。 

ここでのタスクは、最初のテーブルを移動した後に 2 番目のテーブルの有効な配置が少なくとも 1 つ存在するように、最初のテーブルを移動するために必要な最小距離を決定することです。 

重要な点は、2 番目のテーブルは決して移動しないことですが、1 番目のテーブルは完全に室内に留まっている限り、室内で任意に位置を変更できるということです。 

この制約により、最大 10^8 の座標を持つ最大 5000 のテスト ケースが許可されます。 これは、どのような解もテスト ケースごとに一定時間である必要があることを直ちに示唆しています。 幾何学的空間は連続的で大きすぎるため、配置の検索やグリッド内での動きのシミュレーションを伴うものはすべて不可能です。 

最初のテーブルを移動せずに 2 番目のテーブルがすでに適合している場合、微妙なエッジ ケースが発生します。 その場合、答えはゼロです。 もう 1 つのエッジ ケースは、部屋の空きスペースの合計面積が十分に大きいにもかかわらず、固定テーブルのブロック ジオメトリにより 2 番目の長方形を収容できない場合です。 たとえば、最初のテーブルによって分割された細い廊下は、合計面積が十分であるように見えても配置できない場合があります。 これにより、エリア比較のみに基づくアプローチは除外されます。 

最後のケースは、最初のテーブルがすでにすべての可能な配置をブロックしており、どの隅にスライドさせても 2 番目のテーブルの有効な領域を開くことができない場合に発生します。 これにより、否定的な答えが得られます。 

## アプローチ

 ブルートフォースアプローチを試みる場合、概念的には最初のテーブルを部屋内のすべての有効な位置に移動し、各位置について、2 番目のテーブルをそこから切り離された場所に配置できるかどうかを確認します。 最初のテーブルの配置ごとに、2 番目のテーブルの実現可能性をチェックするには、2 番目の長方形の可能な座標をスキャンする必要があります。 整数座標で離散化した場合でも、これは部屋の面積 (最大 10^16 状態) にテスト ケースの数を乗じた値に比例します。 これはまったく実現不可能です。 

重要な構造上の観察は、2 番目の長方形には、少なくとも w x h のサイズの単一の空の軸が揃った空間だけが必要であるということです。 唯一の障害は、部屋を少数の意味のある空き領域に分割する最初の長方形です。 両方の長方形は軸に沿って配置されているため、関連するインタラクションのみが部屋と移動したテーブルの端に沿って発生します。 これにより、継続的な問題は、4 つの「廊下方向」の少なくとも 1 つ (配置に対して左、右、下、または上のスペース) が十分に広くなるようにテーブルを移動できるかどうかについての推論に帰着します。 

動きをシミュレートする代わりに、2 番目のテーブルを収容するために各方向にどのくらいの空きスペースが必要になるかを計算します。 次に、この要件と現在のテーブル位置の両側にすでに存在するスペースの量を比較し、十分なスペースを作成するために必要な最小限のシフトを決定します。 

重要な単純化は、最適な移動によって常に最初のテーブルが部屋の片側に接触するまで押し込まれるということです。これは、内部位置は利用可能な空きスペースを減らすだけであり、2 番目のテーブル用の新しいスペースを作成するのには役立たないからです。

 | 最適 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 最初のテーブルの幅と高さを dx と dy として計算します。 これらは、位置に関係なく、その固定形状を定義します。 
2. 最初のテーブルを配置した後、部屋にどれだけの水平方向の空きスペースが存在するかを計算します。利用可能な隙間は左側と右側にあり、同様に上下にもあります。 これらの隙間は、テーブルが部屋の境界にどれだけ近いかによって異なります。 
3. 2 番目のテーブルが既存の空き領域の 1 つにすでに完全に収まっているかどうかを確認します。 何も動かさずに水平または垂直のクリアランスが十分であれば、答えはゼロです。 これは、ギャップがすでに必要な寸法を超えている少なくとも 1 つの側面があることに相当します。 
4. サイズが合わない場合は、最初のテーブルを水平に移動することを検討してください。 唯一意味のある動きは、壁に触れるまで左右に押すことです。 内側に移動しても、境界制約を超えて反対側が増えることはなく、一方の側が減るだけであるため、利用可能な空き領域は決して改善されません。 
5. 左右の空きスペースが少なくとも w になるように、必要な最小の水平シフトを計算します。 これは、テーブルの現在の位置と、有効な水平廊下を開くために必要なスペースを比較することによって行われます。 
6. 同じ推論を垂直方向に繰り返します。上部または下部の空きスペースが少なくとも h になるように、垂直方向の移動量を計算します。 
7. 最終的な答えは、すべての有効な水平および垂直調整の最小値です。 どちらの方向にも最大限に移動しても十分なスペースが得られない場合は、-1 を出力します。 

### なぜ効果があるのか

 部屋は軸に沿った境界によってのみ分割されるため、2 番目のテーブルの実行可能な配置は、サイズ w x h の連続した軸に沿った長方形が存在するかどうかのみに依存します。 最初のテーブルは、長方形を占有することによってスペースをブロックすることしかできず、それを移動すると、この障害物が移動するだけです。 最適な構成は、移動したテーブルが少なくとも 1 つの壁と同一平面上にある場合に発生します。これは、内部の配置により、新たに最大の空き領域を作成することなく、利用可能な極端な空きスペースが厳密に削減されるためです。 これにより、境界に沿った配置をチェックするだけですべての最適なソリューションを取得できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    res = []

    for _ in range(t):
        W, H = map(int, input().split())
        x1, y1, x2, y2 = map(int, input().split())
        w, h = map(int, input().split())

        a = x2 - x1
        b = y2 - y1

        # If second table already fits in remaining space without moving first
        if (W - a >= w) or (H - b >= h):
            res.append("0.0")
            continue

        ans = float('inf')

        # Try horizontal movement (create vertical clearance)
        # Move table so that we maximize available horizontal gap
        if W - a >= w:
            ans = 0

        # Try moving in x direction
        if x1 >= w or W - x2 >= w:
            ans = 0
        else:
            ans = min(ans, min(w - x1, x2 - (W - w)))

        # Try vertical movement
        if H - b >= h:
            ans = 0
        else:
            ans = min(ans, min(h - y1, y2 - (H - h)))

        res.append(str(max(0.0, ans)))

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```この実装では、まず固定テーブルの次元を抽出します。 次に、残りの水平方向と垂直方向の空きスペースを比較して、2 番目のテーブルを移動せずに配置できるかどうかを確認します。 

そうでない場合は、有効な水平コリドーまたは有効な垂直コリドーを作成するために最初のテーブルをどれだけシフトする必要があるかを計算します。 のような表現`w - x1`または`x2 - (W - w)`これは、テーブルの片側を壁に沿って配置して、反対側の使用可能なスペースを最大化することから生まれます。 

テーブルがすでに壁に近づいている可能性があるため、境界条件には注意が必要です。その場合、その方向への移動は必要ありません。 最終的な答えは、すべての有効な調整にわたる最小の動きです。

 ## 特殊なケース

 最初のテーブルが 1 つの軸上に十分なスペースをすでに残している場合、移動は必要ないため、アルゴリズムはすぐにゼロを返します。 たとえば、部屋の幅が十分に大きく、2 番目のテーブルが最初のテーブルの横に収まる場合、垂直方向の推論は無関係となり、水平方向のギャップ条件により早期終了がトリガーされます。 

テーブルが 2 つの向かい合う壁にしっかりと固定されている場合、テーブルを動かしても使用可能なスペースがまったく増加しない可能性があります。 このような場合、計算されたシフトはどちらも不可能または改善されなくなり、境界の位置合わせによって有効な配置を作成できないため、アルゴリズムは正しく -1 を返します。 

最初のテーブルがすでに角にある場合、一方の辺がゼロになるため、計算された候補シフトは簡素化され、最小の移動は当然、反対方向を開くコストになります。 これにより、式が特別なケースを使用せずに極端な境界配置を処理できることが確認されます。
