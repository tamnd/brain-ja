 ## 解決策
 ## 問題の理解

 この問題は、両端から対称的に配置された要素のすべてのペアが十分に近づくように配列を再配置できるかどうかを尋ねます。 配列の順列を選択した後、最初と最後の値の違いは最大でも次のとおりでなければなりません。`d`、2 番目と最後から 2 番目の値は最大でも異なっていなければなりません`d`、 等々。 タスクは、そのような順序が存在するかどうかを判断することだけです。 元の問題は Codeforces Gym 106179 からのものです。 

入力には複数のテスト ケースが含まれています。 各テスト ケースは、配列の長さ、許容される最大差を示します。`d`、および配列内の値。 出力は`YES`何らかの再配置が対称ペアの条件をすべて満たす場合、それ以外の場合は`NO`。 

すべてのテスト ケースにわたる配列要素の合計数は最大 2000 で、個々の配列の長さは 2000 にすることができます。これは、`O(n^2)`解決策は技術的には可能ですが、チェックされる操作は順序付けに基づいているため、より単純な構造を探すことが役立ちます。 値自体は次のように大きくできます。`10^9`したがって、ソリューションでは、小さな範囲や周波数配列についての仮定を避ける必要があります。 

よくある間違いは、最小値と最大値が距離内にあるかどうかだけを確認することです。`d`。 その条件は必要ですが、十分ではありません。 例えば：```
1
4 5
1 4 10 12
```最小値と最大値は次のように異なります。`11`したがって、これはすでに失敗していますが、極端なペアは問題なく、内側のペアが失敗する場合は、別の間違いが発生する可能性があります。 考慮する：```
1
6 5
1 5 6 10 11 12
```最小値と最大値は次のように異なります。`11`, なので、これも明らかに無理です。 より有用なエッジ ケースは、単一の要素です。```
1
1 0
100
```答えは`YES`。 条件に違反するペアは存在せず、中心位置を処理せずにミラーリングされたインデックスを盲目的にチェックする実装は、誤って拒否する可能性があります。 

もう 1 つのエッジケースは次のような場合です`d`はゼロです。 例えば：```
1
4 0
7 7 7 8
```答えは`NO`。 すべてのミラーリングされたペアには、正確に等しい値が含まれている必要があり、単一の`8`一致させることはできません。 並べ替え後に隣接する差異のみをチェックするソリューションでは、配列がほぼ均一であるため、これを見逃す可能性があります。 

## アプローチ

 直接的なアプローチは、可能な再配置を試して、すべての対称ペアが有効かどうかを確認することです。 これは、問題に必要な条件を正確に検査するため、正しいです。 ただし、注文可能数は`n!`、小さな配列でも不可能になります。 

より合理的な総当たり攻撃では、配列をソートして貪欲にペアを構築しようとするか、ペアに対してバックトラッキングを使用します。 問題は、可能なペア割り当ての数が依然として急速に増加することです。 と`n = 2000`、たとえ`O(n^2)`このアプローチにはすでに約 400 万の操作があり、多くのペアの探索を伴うものは限界をはるかに超えています。 

重要な観察は、ペア内の最大距離のみが重要であるということです。 2 つの値が遠く離れている場合は、一緒に配置しないでください。 並べ替えると、最も制限の厳しいペアがすぐにわかります。最大の要素は、配列の下端からの何らかの要素とペアになる必要があります。 最小の要素にも同じ問題があります。 

最適な配置では、最小の残存値と最大の残存値が繰り返しペアになります。 これは単なる便利な構造ではありません。 これにより、アレイをミラーリングされたペアに分割するすべての方法の中で、可能な限り最小の最大ペア差が得られます。 この配置が失敗した場合、他の再配置では極値を適合させることができません。これは、どちらかの極値を内側に移動すると、別の値が代わりに強制的に配置され、同等以上のギャップが生じるためです。 

配列を次のようにソートした後、`b`、必要な唯一のチェックは次のとおりです。`b[n - 1 - i] - b[i] <= d`ミラーリングされたインデックスごとに`i`。

 | ミラーリングされたペアの並べ替えと確認 | O(n log n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 ソートにより、考えられる最も極端なペア、つまり配置が存在できるかどうかを決定するペアが明らかになります。 
2. 最小の要素と最大の要素を比較します。 それらの差がより大きい場合`d`、答えはすぐにわかります`NO`なぜなら、これら 2 つの極端な値を両方とも有効なミラー位置に配置することはできないからです。 
3. 2 番目に小さいものと 2 番目に大きいもの、次に 3 番目に小さいものと 3 番目に大きいものを比較しながら内側に進み、中央に到達します。 すべての比較は、最適な配置で考えられる 1 つのミラーリング ペアを表します。 
4. すべてのミラーリングされたペアが距離制限を満たしている場合、出力`YES`。 ソートされたミラーリングされた配置自体は有効な構造です。 

なぜ効果があるのか:

 並べ替えた後、最大の要素を考慮します。 遠くにいるパートナーが必要です`d`。 残りの可能な最大値の 1 つ以外の値と組み合わせると、パートナーが小さくなり、差が大きくなるだけです。 同じ議論が最小の要素にも当てはまります。 これら 2 つの値を削除すると、より小さい配列でも同じ問題が残るため、極端な値を繰り返しペアにすることで、可能な限り最良の配置が得られます。 この配置にも無効なペアが含まれている場合は、他のすべての配置にも無効なペアが含まれている必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, d = map(int, input().split())
        a = list(map(int, input().split()))

        a.sort()

        ok = True
        for i in range(n // 2):
            if a[n - 1 - i] - a[i] > d:
                ok = False
                break

        ans.append("YES" if ok else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```入力は次を使用して読み取られます`sys.stdin.readline`テストケースがたくさんある可能性があるからです。 このソリューションでは、最初に各配列を並べ替えます。これが順序を変更する唯一の操作です。 

このループは、ソートされた配列の前半のみをチェックします。 各インデックス`i`とペアになっています`n - 1 - i`、これは、ソートされたバージョンでのミラー位置です。 奇数サイズの配列の中央の要素は、パートナーがないため無視されます。 

比較では Python 整数間の減算が使用されるため、最大の大きな値は`10^9`安全に扱われます。 漸近的な複雑さは同じですが、無効なペアを見つけた後の早期終了により、不必要なチェックが回避されます。

 ## 特殊なケース

 単一要素の場合:```
1
1 0
42
```ソートされた配列は`[42]`。 ループは反復をゼロで実行します。`n // 2`はゼロです。 アルゴリズムの出力`YES`、条件に違反するペアが存在しないという事実と一致します。 

距離がゼロの場合:```
1
4 0
7 7 7 8
```ソート後の配列は次のようになります。`[7, 7, 7, 8]`。 最初のミラー比較チェック`8 - 7 = 1`、これはゼロより大きいため、アルゴリズムは停止して出力します。`NO`。 比類のないもの`8`ミラー化されたペアに属している必要があるため、再配置によって非表示にすることはできません。 

グローバルな最小値と最大値をチェックするだけでは不十分な場合、アルゴリズムはすべてのミラー化されたレイヤーをチェックします。 例えば：```

```ソートされた配列は変わりません。 外側のペアは、`9 - 1 = 8`、すでに大きすぎるため、答えは次のようになります。`NO`。 たとえ極値が有効であったとしても、内部の比較が引き続きチェックされるため、部分的な条件が誤って受け入れられることはありません。
