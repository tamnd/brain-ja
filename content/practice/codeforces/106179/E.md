 ## 解決策
 ## 問題の理解

 一連の高さが与えられています`a`長さの`n`、すべての高さが間にあります`0`そして`k`。 少なくとも 2 つの位置を含む間隔を繰り返し選択し、その間隔内のすべての値を 1 ずつ減らすことによって完全に削除できる場合、シーケンスは良好であるとみなされます。 

タスクは、適切な高さのシーケンスがいくつあるかを数えることです。 答えは与えられた素数を法とする必要があります`p`。 

間隔演算はシミュレーションの問題のように見えますが、実際の演算は考慮すべきものではありません。 有益な疑問は、シーケンスのすべての位置でその値がすべて消えるのに十分なサポートがあるかどうかです。 

シーケンスを次のように拡張すると、`a[0] = 0`そして`a[n+1] = 0`、ポジション`i`その値が隣接する 2 つのサポートの合計よりも大きい場合、その値を削除することはできません。$$a_i > a_{i-1} + a_{i+1}$$このようなピークは、すべての操作が接触するため、十分に低減することができません。`i`近隣諸国の 1 つも関与する必要があります。 逆に、そのようなピークが存在しない場合は、間隔短縮を組み合わせることによってシーケンスを削除できます。 

制約があるため、主な課題はチェックではなくカウントすることになります。 値の制限は`k <= n`そして`n <= 3000`, の合計`n^2`すべてのテスト ケースが制限されています。 三次動的計画法のソリューションはすでに遅すぎます。`3000^3`操作は数秒で収まる範囲をはるかに超えています。 に近い方法が必要です`O(n^2)`。 

いくつかの特殊なケースは見落とされがちです。 

大きな孤立値を持つシーケンスは拒否されなければなりません。 例えば：```
Input:
n = 3, k = 5
a = [0, 5, 0]
```中央の値は隣接する値の合計よりも大きいため、正しい寄与はゼロになります。 合計をチェックするだけのソリューションや、間隔を貪欲に削除しようとするソリューションでは、それが誤って受け入れられる可能性があります。 

境界は追加のゼロのように動作します。 例えば：```
Input:
n = 3, k = 1
a = [1, 0, 0]
```最初の位置は条件に違反します。`1 > 0 + 0`, だからダメなんです。 配列の外側に人為的なゼロを忘れると、このケースは誤ってカウントされます。 

シーケンスには多数の等しい値を含めることができ、依然として有効です。```
Input:
n = 3, k = 1
a = [1, 1, 1]
```中央の位置は十分なサポートがあり、両端は隣接する値と外側のゼロによってサポートされます。 答えにはこのシーケンスが含まれます。 

## アプローチ

 直接的なアプローチは、考えられるすべてのシーケンスを生成し、それが適切かどうかをテストすることです。 がある`(k+1)^n`したがって、一定時間チェッカーを使用しても、これはすぐに不可能になります。 たとえば、次のようなとき`n = k = 3000`、検索空間は天文学的に大きいです。 

より合理的な最初の動的プログラミングのアイデアは、前の 2 つの値を記憶しながら左から右にシーケンスを構築することです。 選ぶときは`a[i]`、作成される唯一の新しい条件は、`a[i-1]`、`a[i]`、 そして`a[i+1]`したがって、前の 2 つの値を保持すると、十分な情報が得られます。 この状態は約`n * k^2`各遷移はプレフィックス合計を使用して最適化できます。 簡単なバージョンには十分ですが、値の次元に対して実行する処理が多すぎるため、ハード制約にはまだ大きすぎます。 

重要な点は、無効な位置を隣接させることはできないということです。 2 つの隣接する位置が両方とも無効だったとします。$$a_i > a_{i-1}+a_{i+1}$$そして$$a_{i+1} > a_i+a_{i+2}$$それらを追加すると、次のようになります。$$a_i+a_{i+1} > a_{i-1}+a_i+a_{i+1}+a_{i+2}$$これには負でない値が必要です`a_{i-1}+a_{i+2}`ネガティブになること。 これは不可能です。 

このプロパティにより、包含/除外を使用できるようになります。 前の値を記憶する代わりに、すべてのシーケンスをカウントし、現在位置が最初の無効な位置であるシーケンスを減算します。 無効な位置は互いに接触できないため、前の位置を追跡する必要はありません。 

させて`dp[i][x]`value で終わるプレフィックスの包含/除外加重カウントを表します`x`加工後の位置`i`。 遷移により現在値が修正され、現在位置が条件に違反するケースが排除されます。 無効なケースは 2 桁前の値を使用してカウントできます。`O(nk)`プレフィックス合計による遷移。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((k+1)^n) | O(n) | 遅すぎる |
 | 前の 2 つの値 DP | O(nk²) | O(k²) | ハードバージョンにしては遅すぎる |
 | 包含-除外 DP | O(nk) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のプレフィックスの動的プログラミング状態を初期化します。 配列の前の外側の値はゼロに固定されているため、開始状態は value だけです`0`。 
2. 位置を左から右に処理します。 あらゆる可能な値に対して`j`現在の位置で、まず前の位置で終わるすべての有効なプレフィックスを考慮します。 これにより、新しい違反をフィルタリングする前にすべてのシーケンスが得られます。 
3. 現在位置が無効になる場合を差し引きます。 2 つ前の値が`x`の場合、前の値は、現在の位置が隣接する位置の合計を超えるのに十分な大きさでなければなりません。 以前の値の選択肢の数は、明示的に保存しなくてもカウントできます。 
4. 以前の DP 層のプレフィックス合計を維持します。 これらのプレフィックス合計により、すべての値を反復する代わりに、考えられるすべての前の値の合計寄与を定数時間で見つけることができます。 
5. 値 0 の最終的な人工位置を追加します。 同じ遷移がこの最後の位置を処理し、実際の最後の要素が境界条件を満たすように強制します。 

機能する理由: DP はすべてのシーケンスをカウントし、無効な位置を含むシーケンスを正確に減算します。 唯一の微妙な点は、引き算の際に二重カウントを避けることです。 2 つの無効な位置が隣接することはできないため、すべての無効な位置は左から右へのプロセスで独立して処理できます。 DP に格納された包含/除外重みは、残りの可能性のある無効な選択肢をキャプチャするため、末尾が 0 の最終状態には、正確に適切なシーケンスが含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, mod):
    prev = [0] * (k + 1)
    prev[0] = 1

    pref_prev2 = [0] * (k + 1)
    pref_prev = [0] * (k + 1)

    for i in range(k + 1):
        pref_prev2[i] = 1
        pref_prev[i] = i + 1

    for pos in range(2, n + 2):
        cur = [0] * (k + 1)

        bad = 0
        for j in range(k, -1, -1):
            bad += pref_prev2[k - j - 1] if k - j - 1 >= 0 else 0
            bad %= mod
            cur[j] = (pref_prev[k] - bad) % mod

        pref_cur = [0] * (k + 1)
        pref_cur[0] = cur[0]
        for j in range(1, k + 1):
            pref_cur[j] = (pref_cur[j - 1] + cur[j]) % mod

        pref_prev2 = pref_prev
        pref_prev = pref_cur

    return cur[0] % mod

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n, k, p = map(int, input().split())
        ans.append(str(solve_case(n, k, p)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```配列`pref_prev`そして`pref_prev2`2 つの連続する DP 層のプレフィックスの合計を格納します。 遷移にはこれらの合計のみが必要なので、テーブル全体を保持する必要はありません。 

ループが駆け抜ける`n+1`最後の人工ゼロも処理する必要があるためです。 この最後の遷移は、正しい境界条件を強制するものです。 

減算ステップでは次を使用します。`k - j - 1`気をつけて。 この値が負の場合、削除できる無効な選択肢はありません。 この境界を明示的に処理すると、Python での負のインデックス付けが回避されます。 

All calculations are reduced modulo`p`足し算と引き算の後。 Python の整数はオーバーフローしませんが、値を小さくしておくと、多数の状態に対するパフォーマンスが向上します。

import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    data = sys.stdin.readline
    t = int(data())
    out = []

    def solve_case(n, k, mod):
        prev = [0] * (k + 1)
        prev[0] = 1
        pref2 = [1] * (k + 1)
        pref1 = list(range(1, k + 2))

        for _ in range(2, n + 2):
            cur = [0] * (k + 1)
            bad = 0
            for j in range(k, -1, -1):
                if k - j - 1 >= 0:
                    bad += pref2[k - j - 1]
                    bad %= mod
                cur[j] = (pref1[k] - bad) % mod

            pref = [0] * (k + 1)
            pref[0] = cur[0]
            for j in range(1, k + 1):
                pref[j] = (pref[j - 1] + cur[j]) % mod

            pref2, pref1 = pref1, pref

        return cur[0]

    for _ in range(t):
        n, k, p = map(int, data().split())
        out.append(str(solve_case(n, k, p)))

    sys.stdin = old
    return "\n".join(out)

 ## 特殊なケース

 孤立したピークの場合は、減算項によって処理されます。 シーケンスの場合:```
[0, 5, 0]
```中央の位置は、その隣接位置が値をサポートできないため、無効な選択肢の中に数えられます。`5`。 DP は、最終状態に到達する前にこの寄与を削除します。 

左境界の場合:```
[1, 0, 0]
```追加の開始ゼロが繰り返しにすでに含まれているため、処理されます。 最初の位置が処理されるとき、可能なサポートは次の値と外側のゼロからのみ得られます。 シーケンスは除外されます。 

すべて等しいシーケンスの場合:```
[1, 1, 1]
```中間の値は違反ではありません。`1 <= 1 + 1`、最後の人工ゼロチェックも合格します。`0 <= 1 + 0`。 DP はこのシーケンスを保持し、等しい値が誤って無効として扱われないことを確認します。
