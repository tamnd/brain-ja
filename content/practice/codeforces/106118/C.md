 ## 解決策
 ## 問題の理解

 ガジェットの価格と初期金額のリストが与えられます。 購入ルールは制限的です。ガジェットを購入する前に、現在の金額がそのガジェットの価格の少なくとも 10 倍でなければなりません。 購入後、お金はガジェットの価格によって減額されます。 目標は、購入できるガジェットの数を最大化する購入順序を選択することです。 

実現可能性は項目を取得する順序に依存するため、これは単なるサブセット選択の問題ではありません。 安い商品を早めに購入するとお金が減り、その後の高価な購入を妨げる可能性がありますが、最初に高価な商品を購入すると「購入までに 10 回」という制約に違反する可能性があります。 したがって、タスクは、シーケンスの長さを最大化する有効な購入のシーケンスを見つけることです。 

制約は大きく、最大 200,000 のガジェットと最大 10^15 の初期資金です。 これにより、すべての順列または指数サブセット検索を試みるアプローチは即座に除外されます。 有効な次の項目を求めてリストを繰り返しスキャンする O(n^2) 貪欲シミュレーションでさえ遅すぎます。 各項目を少数回のみ検討し、理想的には O(log n) または O(1) で償却する戦略が必要です。 

小さなアイテムがたくさんある場合、微妙なエッジケースが表示されます。 素朴な直感は、常に最も安い商品を最初に購入することを示唆するかもしれません。 資金を減らすのが早すぎると、まだ対象となる少し大きな商品を購入できなくなる可能性があるため、これは失敗する可能性があります。 たとえば、m = 100 でアイテムが [9, 10, 11] の場合、100 ≥ 90 なので最初に 9 を買うのは合法ですが、お金が 91 に減ります。次に 10 には 100 が必要ですが、91 < 100 なので不可能になります。 ただし、最初の作品を 10 個購入すると、100 ≧ 100 となり、お金は 90 になり、9 と 11 の決定が異なります。 これは、順序が重要であることを示しています。 

もう 1 つのエッジ ケースは、非常に高価なアイテムが最初は技術的に手頃な価格であるが、最初に小さなアイテムを手に入れることでより多くの合計購入のロックが解除されるにもかかわらず、後ですべての小さなアイテムを妨げる場合です。 

## アプローチ

 ブルートフォースアプローチでは、ガジェットのすべての組み合わせを試し、注文ごとに購入プロセスをシミュレートし、ルールに従って購入できるアイテムの数を確認します。 各シミュレーションは O(n) であり、n 個あります。 これは n = 20 の場合でも完全に不可能です。 

より構造化されたブルートフォースの改善は、バックトラッキングを使用することです。各ステップで、現在手頃な価格のアイテムをすべて試してください。 しかし、それでも、多くのアイテムが手頃な価格である最悪のケースでは、分岐係数は大きいままであり、指数関数的な爆発につながります。 

重要な観察は、決定は非常に特殊な方法でローカルに行われるということです。つまり、アイテムを購入できるかどうかは現在のお金にのみ依存し、何かを購入すると決定すると、常にお金が減ります。 したがって、ルールを逆に使用したいと考えます。いつでも、10 倍の制約の下でぎりぎり手頃な価格のアイテムを選択する必要があります。なぜなら、今より安いものを購入しても、より大きなアイテムの実現可能性が向上することはなく、将来の柔軟性が低下するだけだからです。 

これは、価格を並べ替えて、制約を満たす最小の実現可能なアイテムを常に選択しようとすることを示唆しています。 ただし、注意しなければならないのは、制約は固定の手頃な価格だけではなく、現在のお金に依存するということです。 現在どのアイテムが適格であるかを常に追跡し、最適なものを選択する動的な構造が必要です。 

私たちはソートされたリストを維持し、価格が最大でも m/10 のアイテムを段階的に「ロック解除」します。 アイテムが対象となると、購入を検討できます。 対象となる項目の中で最小のものを選択するのが最適です。これは、費用の削減が最小限に抑えられ、将来の資格が維持されるためです。 

これにより、ソートされた配列に対するポインターを使用する貪欲なプロセスに問題が軽減されます。

 ## アルゴリズムのチュートリアル

まず、すべてのガジェットの価格を昇順に並べ替えます。 これにより、資金が減少するにつれて資格を単調に追跡することができます。 

ソートされた配列をスキャンするポインターと、ルールに基づいて現在購入可能なすべてのアイテムを格納する構造を維持します。 

各ステップで、現在の価格が current_money / 10 以下である間にポインタを繰り返し前進させ、それらのアイテムを候補のプールに追加します。 

このプールから、利用可能な最小のアイテムを選択します。これは、金額の削減を最小限に抑え、将来のアイテムが適格なままになる可能性を最大化するためです。 

現在のお金からその価格を引いて、答えを増分します。 プールに項目を追加できなくなり、プール内の項目が選択できなくなるまで、このプロセスを続けます。 

ある時点でプールが空になり、次に小さい項目が高すぎて 10x ルールを満たすことができない場合は、終了します。 

### なぜ効果があるのか

 重要な不変条件は、資金が減少するだけであるため、現在ルールに基づいて適格であるすべての品目は、いつでもすでに候補者プールにあるか、後で適格になることはないかのいずれかであるということです。 したがって、アイテムが適格性のしきい値を超えてスキップされると、再び実現可能になることはありません。 現在適格なアイテムの中で、最小のものを選択することは、将来の適格性の基準値の低下を最小限に抑えるため安全であり、より大きな選択は、将来の制約が厳しくなるだけであり、どのアイテムのアクセシビリティも向上するわけではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    i = 0
    ans = 0
    money = m

    while True:
        # add all newly affordable items
        while i < n and a[i] * 10 <= money:
            i += 1

        # now all items before i are eligible candidates
        # but we need to pick among them those not yet taken
        # since we only move forward, we treat a[0:i] as available pool

        if i == 0:
            break

        # pick the largest index below i that we haven't consumed
        # but since we always consume from left, we simulate by taking a[i-1]
        i -= 1
        money -= a[i]
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは価格を並べ替えて、資格チェックが現在の金額との単純なしきい値の比較になるようにします。 ポインタ`i`10x ルールを満たすすべての項目を含むように展開されます。 これ以上アイテムを追加できない場合は、削減されます`i`1 つずつ増やして、それを最新の対象アイテムとして扱います。 

ここでの微妙な設計上の選択は、明示的に別個のヒープを維持しないことです。 代わりに、ソートされた配列と移動境界を再利用します。 表現`a[i] * 10 <= money`ルールを直接エンコードします。 

微妙な点の 1 つは終了です。 もし`i == 0`、現在このルールに基づいて手頃な価格のアイテムはないため、プロセスを停止する必要があります。 もう 1 つの微妙な点は、アイテムを取得した後、以前に適格だったアイテムが無効になる可能性があるため、ポインタの動きは常に現在のお金を反映する必要があることです。

 ## 特殊なケース

 のような単品の場合`n = 1, m = 10, p = 1`、条件`10 >= 10`購入を許可します。 買うとお金が9になり、それ以上アイテムが存在しないので、答えは1です。 

等価でぎっしり詰まったものについては、`m = 100, p = [10, 10, 10]`、1回購入するとお金が90になり、次の購入には再び少なくとも100が必要になるため、最初の購入のみが可能です。 アルゴリズムは最初の選択後に正しく停止します。 

などの多くの小物に`[1, 1, 1, ..., 1]`、購入ごとに金額がわずかに減少するだけで、資格条件は複数のステップで満たされたままになります。 このアルゴリズムは金額が 10 を下回るまで継続され、その時点でそれ以上のアイテムは検討できなくなります。
