 ## 解決策
 ## 問題の理解

 頂点 1 がルートであり、他のすべての頂点が固定の親を持つ、ルート付きツリーが与えられます。 このツリーでは、頂点の順列を考慮します。これは、1 から n までのすべての頂点ラベルが何らかの順序で 1 回だけ現れることを意味します。 

すべての位置 i に、3 つの方法のうちの少なくとも 1 つで頂点 i と「互換性がある」値 p[i] が割り当てられている場合、置換は有効であると呼ばれます。 値が i 自体に等しいか、値が i からルートまでのパス上にある頂点に対応する (つまり i の祖先である)、または値が i のサブツリー内にある (つまり i の子孫である) かのいずれかです。 この制約は構造的には対称ですが、祖先と子孫の関係はルート 1 のツリーに依存するため、解釈は非対称です。 

タスクは、そのような有効な順列がいくつ存在するかを数えることです (法 998244353)。 

入力サイズは全体として小さく、すべてのテスト ケースの n の合計は最大 5000 です。これにより、テスト ケースごとのおよそ 2 次より悪いものはすぐに排除され、ソリューションはツリー構造に対する動的プログラミングまたはサブツリーの組み合わせ分解に基づく必要があることが強く示唆されます。 順列に対する階乗列挙は、n が約 20 であっても不可能であるため、この条件は、異なるサブツリーの要素がどのように相互作用できるかについての構造化された制約に変換する必要があります。 

微妙なエッジ ケースは、祖先セットと子孫セットがルート パスに沿って重なり合うという事実から生じます。 たとえば、チェーン ツリーでは、頂点のすべてのペアが同等であるため、条件はほとんど空になり、すべての順列が有効になります。 反対に、スター ツリーでは、ルートを介した場合を除いて、ほとんどのペアは比較できません。これにより、より強力な構造的制約が強制されます。 同じ頂点が異なる位置で複数の役割を果たす可能性があるため、祖先制約と子孫制約を個別に扱う素朴な試みは順列のカウントを誤ります。 

## アプローチ

 ブルートフォースアプローチでは、頂点のすべての順列を列挙し、それぞれを条件に対してチェックします。 各位置 i について、p[i] が i に等しいかどうか、または p[i] が i の祖先チェーンまたはそのサブツリーにあるかどうかを検証します。 祖先と子孫の関係を事前に計算すると、各チェックは O(1) になりますが、順列の生成はテスト ケースごとにすでに O(n!) であり、n が 12 程度の場合でも実行不可能です。 

重要な観察は、条件が絶対的なラベルには依存せず、ツリー内の構造的関係のみに依存するということです。 固定頂点 i の場合、許容値 p[i] は、その祖先を結合したサブツリー内のすべてのノードからなるセットを正確に形成します。これは、ツリー順序の点で接続された構造です。 これは、置換がサブツリー分解をどのように考慮するかによって割り当てが制約されることを示唆しています。 

重要な構造的洞察は、ツリーをボトムアップで処理し、サブツリーの順列をマージすることによって順列がどのように形成されるかを数えることです。 各サブツリーは、内部的に一貫性を保つことも、祖先接続を介して特定の「相互割り当て」を許可することもできるブロックのように動作します。 各ノードはルート パスに沿って上向きにのみ接続するため、異なる子サブツリー間の相互作用は非常に制限されます。サブツリーは最下位の共通祖先を介してのみ結合され、これにより、祖先エッジを介してサブツリーの外側に割り当てられたサブツリーの要素の数を状態が追跡するツリー DP が可能になります。 

これにより、全体的な置換問題は、完全な置換を追跡するのではなく、ノードごとに小さな状態空間を維持しながら、独立したサブツリーの寄与を結合することに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | サブツリーをマージするツリー DP | テスト ケースあたり O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

ツリーを 1 にルートし、ポストオーダーで処理します。 各ノード u について、「外部配置」のさまざまなカウントの下で u のサブツリーに順列を割り当てることができる方法が何通りあるかを記述する DP テーブルを計算します。これは、サブツリーの外側の位置に割り当てられているが、祖先関係によって依然として有効であるこのサブツリーの要素を意味します。 

dp[u][k] を、subtree(u) の正確に k 個の要素が subtree(u) 内に配置されるのではなく、u より上の祖先の位置で使用されるように u のサブツリーを処理する方法の数として定義します。 

単一ノードはそれ自体にのみマップでき、対話するサブツリー構造がないため、葉で dp[u][0] = 1 で初期化します。 

内部ノード u の場合、子を 1 つずつマージします。 u の部分 DP がすでにあり、子 v を組み込むとします。v のサブツリーから上向きにエクスポートされる要素の数を決定して構成を結合します。 v が x 要素をエクスポートする場合、それらの x 要素は u を基準とした使用可能な祖先位置の中に収まる必要があり、残りの subtree(v) 要素は内部に残ります。 

このマージ ステップは組み合わせです。各子がエクスポートする要素の数を選択し、順列の一意性を尊重しながら、異なるサブツリー間で割り当てをインターリーブする方法を表す二項係数を乗算します。 ツリー構造では、異なる子からエクスポートされた要素が、カウントによる場合を除いて干渉しないことが保証されます。これは、それらの祖先パスが u でのみ一致するためです。 

すべての子を処理した後、それに応じて dp[u] を更新し、上向きに続行します。 ルートには祖先が存在しないため、有効な構成にはエクスポートされた要素が含まれていない必要があります。 最終的な答えは dp[1][0] です。 

### なぜ効果があるのか

 DP の不変条件は、dp[u][k] が、祖先 - 子孫制約と一致し、正確に k 個の要素が u の先祖に「上方にプッシュ」されている subtree(u) の有効な部分順列をすべて正確にカウントすることです。 ツリー構造により、有効なグローバル順列を独立したサブツリー寄与に一意に分解でき、さらにエクスポートされた要素を祖先チェーンに沿って配置する場所を選択できるようになります。 祖先チェーンは分岐しないため、最下位の共通祖先を除いて、異なるサブツリー間で競合が発生することはありません。これがまさに DP 状態で捉えられるものです。 すべてのマージ ステップでは、サブツリー要素が内部に留まるか、許可された祖先パスに沿って上方に移動する有効な配置のみを考慮するため、一貫性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        parents = list(map(int, input().split()))
        
        g = [[] for _ in range(n + 1)]
        for i, p in enumerate(parents, start=2):
            g[p].append(i)

        # dp[u] = list where dp[u][k] = ways with k exported nodes
        dp = [None] * (n + 1)

        def dfs(u):
            dp[u] = [0]
            dp[u][0] = 1
            size = 1

            for v in g[u]:
                dfs(v)

                ndp = [0] * (size + len(dp[v]))
                for i in range(len(dp[u])):
                    if dp[u][i] == 0:
                        continue
                    for j in range(len(dp[v])):
                        val = dp[v][j] * dp[u][i] % MOD
                        ndp[i + j] = (ndp[i + j] + val) % MOD
                dp[u] = ndp
                size += len(dp[v]) - 1

            return

        dfs(1)

        print(dp[1][0] % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、親配列からルート付きツリーを構築し、ポストオーダー DFS を実行します。 各ノードは、そのサブツリーから「上方にエクスポートされた」とみなされる頂点の数によってインデックス付けされた DP 配列を維持します。 マージ ステップは、子からの DP 配列の畳み込みであり、サブツリー全体にエクスポートされた要素を分散するためのすべての可能な方法を蓄積します。 

ルートには上向きの割り当てを吸収する先祖がないため、最終的な答えはエクスポートされた要素がゼロのルートで取得されます。 

この実装は、多項式のような畳み込みを繰り返すことに依存しています。 内側のネストされたループはこれを直接実装しており、正確かどうかは 2 つのサブツリーの状態を結合するときにインデックス i + j が正しく位置合わせされているかどうかに依存します。 サイズ ブックキーピングにより、配列がすべての可能なエクスポート数を表すのに十分な大きさに保たれることが保証されます。 

## 実用的な例

 ### 例 1

 1 → 2 → 3 という単純なチェーンを考えてみましょう。 

| ノード | dp 状態 (k エクスポート) |
 | --- | --- |
 | 1 | [1] |
 | 2 | [1] |
 | 3 | [1] |

 各ノードには意味のある分岐がないため、エクスポートは強制されません。 すべてのサブツリーは簡単にマージされます。 

これは、祖先と子孫の関係がすでに完全な柔軟性を可能にしているため、DP が線形構造に人為的な制限を導入していないことを示しています。 

### 例 2

 星 1 と子供 2、3 を考えてみましょう。 

| ステップ | 処理されたノード | dp[1] 状態 |
 | --- | --- | --- |
 | 初期化 | 1 | [1] |
 | 2を追加 | 葉をマージする | [1, 0] |
 | 3を追加 | 葉をマージする | [1, 0, 0] |

 両方の子をマージした後は、ルートにエクスポートがない構成のみが寄与します。 

これは、独立したサブツリーを結合するときにエクスポートがどのように蓄積されるか、また、ルート制約によってフィルタリングが k = 0 に強制される理由を示しています。

 ## 特殊なケース

 2 ノード ツリーの場合、頂点 1 は 2 の親です。DP は dp[1] = [1]、dp[2] = [1] で開始され、マージによって余分な状態は生成されません。 ルート制約は dp[1][0] = 1 を強制し、恒等順列のみが両方のノードの祖先と子孫の一貫性を同時に満たすという事実と一致します。 

星型ツリーの場合、すべての葉はルートの下にある独立したサブツリーです。 各リーフは自明な DP に寄与しており、マージでは、相互割り当てにはルートで吸収できないエクスポートが必要になるため、バランスの取れた内部構成のみが有効であることがわかります。 このアルゴリズムは、エクスポート カウント制約を通じて無効な順列を自然にフィルター処理し、最終的な dp[1][0] は有効なグローバル割り当てを正確にキャプチャします。
