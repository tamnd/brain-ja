 ## 解決策
 ## 問題の理解

 私たちは、各点がターゲットの隠れた位置になる可能性がある無限整数グリッドに取り組んでいます。 いくつかの手がかりを受け取ります。各手がかりは中心点と距離で構成されます。 手がかりが信頼できる場合は、隠された点がその手がかりの座標を中心とする指定された半径の円上に正確に存在することを意味します。 手がかりが信頼できない場合、隠された点はその円から厳密に外れている必要があります。 

問題は、どの手がかりが信頼できるかわからないことです。 隠されたポイントを選択し、それが実際の場所であることと一致する手がかりを決定したいと考えています。 固定点の場合、ユークリッド距離の二乗が指定された値と一致するかどうかに応じて、各手がかりは一貫性があるか不一致になります。 

主な目的は、実行可能な点を見つけることだけではなく、唯一の有効な位置を突き止める方法で、同時に信頼できる手がかりの数を最大化することです。 言い換えれば、一致する手がかりのセットができるだけ大きくなるような点が必要ですが、同時に、他の点が同じ一貫したセットを生成できないような点も必要です。 

入力サイズは最大 100,000 個の手がかりに達し、それぞれが円制約を定義します。 候補点をペアごとに比較したり、考えられるすべての交点を列挙したりする単純なアプローチでは、潜在的な円の交点だけで二次スケールに達する可能性があるため、非常に時間がかかりすぎます。 これにより、すべての手がかりペアに対して O(n²) 以上の構造が即座に除外されます。 

複数の点が制約の同じサブセットを満たす場合、微妙な問題が発生します。 たとえば、2 つの円は 2 つの対称点で交差することがよくあります。 この 2 つの手がかりだけを選択すると、曖昧さが生じる可能性があります。 もう 1 つの問題は、複数の異なるサブセットが異なる有効な位置を生成するがサイズは同じである場合で、一意に決定される点につながるサイズ k の一意のサブセットを選択する必要があるという要件に違反します。 

## アプローチ

 直接的なアイデアは、手がかりのすべてのサブセットを考慮し、それらが固有の点を定義しているかどうかを計算し、満たされる制約の数をカウントすることです。 これは原理的には正しいですが、サブセットが 2ⁿ あるため、直ちに実行できません。 サイズ 2 のサブセットに限定しても、既に O(n²) ペアが生成され、各ペアは円の交差を解決する必要があり、これにより最大 2 つの候補点が得られ、すべての手がかりに対するさらなる検証が行われます。 

重要な構造的観察は、有効な解決策は、固定点に対して「現実的な」手がかりのセットによって完全に決定されるということです。 サブセットの観点から考える代わりに、視点を反転することができます。すべての候補点が手がかりのサブセットを定義し、正確に 1 つの点に対応するサブセットのみを考慮します。 

重要な単純化は幾何学によってもたらされます。 各手がかりは円を定義します。 点は、それらの円の一意の交点である場合にのみ、一連の円によって一意に決定されます。 平面内では、2 つの円によってすでに解が最大 2 点に制限されており、通常は 3 番目の非縮退円によって曖昧さが解消されます。 これは、すべての候補解が少数の一定数の制約によって決定されることを意味し、実際には、円のペアの交点を列挙し、それらをすべての制約に対して検証するだけで十分です。 

したがって、戦略は次のようになります。円のペアの交点からすべての候補点を生成し、すべての手がかりに対して各候補を検証し、それが満たす手がかりの数を計算します。 有効な候補の間で、一意性を確保する必要があります。他の点から同じ最大の一貫したセットが得られることはありません。

最後の改良点は、実際にはサブセットを明示的に列挙する必要がないことを理解することです。 各候補点について、それが満たす手がかりの数としてそのスコアを計算します。 答えは、すべての候補点の中での最大のスコアですが、そのスコアが 1 つの候補点に正確に対応する場合に限ります。 複数のポイントが同じ最大値に達する場合、または候補が一意に決定されない場合、その候補は無効となります。 

これにより、O(n²) 個の円のペアを列挙し、それぞれ最大 O(1) 個の交点を生成し、O(n) 内の各候補を検証するという問題が軽減されます。これはまだ大きいですが、候補の中心をハッシュし、距離構造に基づいて早期に枝刈りすることで最適化できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2ⁿ・n) | O(n) | 遅すぎる |
 | ペアワイズ円交差 + 検証 | O(n² log n) | O(n²) 最悪 | プルーニング付きで受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 各手がかりを、(xi, yi) を中心とし、半径 di の 2 乗を持つ円として扱います。 真の点は、これらの円のサブセット上に存在する必要があります。 
2. 手がかりのペアごとに、それらの円の交点を計算します。 各ペアは、最大 2 つの候補整数点を生成します。 これらは、複数の制約が重要な方法で同時に保持できる唯一の可能な場所です。 これは、サブセット検索からペアワイズ構造への幾何学的縮小です。 
3. 各候補点について、二乗距離が di と一致するかどうかをチェックすることにより、すべての手がかりに対して検証します。 これにより、その点の「実際の」手がかりのセットとそのスコア k が生成されます。 
4. 候補点からそのスコアまでのマップを維持します。 複数のペアが同じポイントを生成する場合、そのポイントは 1 回だけ保持します。 
5. すべての候補者の最大スコアを追跡します。 
6. この最大スコアに達した候補者の数を数えます。 受験者が 1 人だけ達成した場合は、そのポイントとスコアを出力します。 それ以外の場合は -1 を出力します。 

明白ではない部分は、なぜペアごとの交差をチェックするだけで十分なのかということです。 少なくとも 2 つの手がかりを満たす有効な点は、それらの円の交点に存在する必要があるため、k ≥ 2 のすべての実行可能な解がこの列挙に表示されます。 k = 1 の解は明らかに最適性が低く、交差が存在しない限り、k ≥ 2 の構成に勝つことはできません。交差が存在しない場合、有効な一意に決定された点は存在しません。 

### なぜ効果があるのか

 有効な解点は、その点が存在する円のサブセットによって完全に特徴付けられます。 そのサブセットのサイズが少なくとも 2 の場合、点はこれらの円のいずれか 2 つの交点に存在する必要があるため、ペアごとの交点の中に表示されます。 したがって、あらゆる最適解の候補が生成されます。 各候補のすべての手がかりを明示的に検証するため、その正確なサブセット サイズを正確に計算します。 一意性は、他の候補が同じ最大サブセット サイズを達成していないことをチェックすることによって強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from collections import defaultdict

def isqrt(x):
    return math.isqrt(x)

def circle_intersections(x0, y0, r0, x1, y1, r1):
    dx = x1 - x0
    dy = y1 - y0
    d2 = dx*dx + dy*dy

    if d2 == 0:
        return []

    r0r0 = r0
    r1r1 = r1

    # using squared radii, but treat as exact distances
    d = math.sqrt(d2)

    # no real circle geometry derivation needed beyond algebraic system
    # we solve using standard intersection formula
    a = (r0r0 - r1r1 + d2) / (2*d)
    h2 = r0r0 - a*a
    if h2 < 0:
        h2 = 0
    h = math.sqrt(h2)

    xm = x0 + a * (dx / d)
    ym = y0 + a * (dy / d)

    rx = -dy * (h / d)
    ry = dx * (h / d)

    p1 = (round(xm + rx), round(ym + ry))
    p2 = (round(xm - rx), round(ym - ry))

    res = []
    if p1 == (int(p1[0]), int(p1[1])):
        res.append(p1)
    if p2 != p1:
        res.append(p2)
    return res

def dist2(x1, y1, x2, y2):
    dx = x1 - x2
    dy = y1 - y2
    return dx*dx + dy*dy

def main():
    n = int(input())
    clues = [tuple(map(int, input().split())) for _ in range(n)]

    best = -1
    best_pts = []

    seen = set()

    for i in range(n):
        x0, y0, d0 = clues[i]
        for j in range(i+1, n):
            x1, y1, d1 = clues[j]
            pts = circle_intersections(x0, y0, d0, x1, y1, d1)
            for px, py in pts:
                if (px, py) in seen:
                    continue
                seen.add((px, py))

                cnt = 0
                for x, y, d in clues:
                    if dist2(px, py, x, y) == d:
                        cnt += 1

                if cnt > best:
                    best = cnt
                    best_pts = [(px, py)]
                elif cnt == best:
                    best_pts.append((px, py))

    if best == -1 or len(best_pts) != 1:
        print(-1)
    else:
        x, y = best_pts[0]
        print(best)
        print(x, y)

if __name__ == "__main__":
    main()
```コードは、すべての円ペアの交点から候補点を構築します。 各候補は直接二乗距離比較によってすべての手がかりに対して検証され、浮動小数点ドリフトが正確性の決定に影響を与えることなく正確性が保証されます。 セットは、異なるペアからの同じ幾何学的点の重複した評価を防ぎます。 

主な微妙な点は、交差の計算を慎重に扱うことです。 実際には、完全に堅牢なソリューションは、正確な整数代数またはハッシュ シンボリック表現を使用することにより、浮動小数点の丸めを回避します。 アルゴリズムの構造は、ペアから候補を生成し、グローバルに検証し、最適な一意のソリューションを追跡するという点で変わりません。 

## 実用的な例

 2 つの円が 2 つの手がかりを満たす 1 つの整数点で交差する小さな構成を考えてみましょう。 すべてのペアを処理します。 これら 2 つの円を定義するペアのみが、完全な検証に合格する候補を生成します。 評価は以下の表のとおりです。 

| ペア | 候補点 | 一致する手がかり | スコア |
 | --- | --- | --- | --- |
 | (1,2) | (18,0) | 1,2 | 2 |
 | その他 | 有効なものはありません | - | - |

 これは、単一の幾何学的交差から最大値がどのように生じるかを示しています。 

ここで、2 つの異なるペアが同じスコアを持つ異なるポイントを生成する対称的なケースを考えてみましょう。 

| ペア | 候補点 | 一致する手がかり | スコア |
 | --- | --- | --- | --- |
 | (1,2) | (0,5) | 1、2、3 | 3 |
 | (4,5) | (20,5) | 4,5,6 | 3 |

 どちらの候補も同じ最大値を達成するため、一意の解決策は存在しません。 アルゴリズムは、最高スコアの一意性をチェックすることにより、これを正しく拒否します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² + n²・n) | すべてのペアの交差と候補ごとの完全な検証 |
 | スペース | O(n²) 最悪 | 候補点の保存と重複排除 |

 二次ペアの生成が優勢であり、各候補の検証は n において線形です。 これは、有効な候補が実際には n² よりはるかに少ない、競合幾何学問題に典型的な強力な幾何学的フィルタリングと枝刈りの仮定の下でのみ実行可能です。

 ## 特殊なケース

 重要なエッジケースは、すべての手がかりが整数点で決して交差しない円に対応する場合です。 この状況では、ペアワイズ生成では候補が生成されず、答えは -1 のままになります。 

複数の交差ペアが同じ幾何学的点を生成する場合、別のエッジ ケースが発生します。 重複排除を行わないと、アルゴリズムは同じ候補を複数回過剰にカウントし、一意性チェックに誤ったバイアスがかかることになります。 セットベースのフィルタリングにより、各ポイントが 1 回だけ評価されることが保証されます。 

最後のエッジケースは、ベストスコアが 1 点以上に達する場合です。 たとえ各点が個別に有効であっても、解が一意に決定されるという要件により、拒否が強制されます。 このアルゴリズムは、出力前に最適な候補セットのカーディナリティを明示的にチェックします。
