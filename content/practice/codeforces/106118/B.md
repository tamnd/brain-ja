 ## 解決策
 ## 問題の理解

 それぞれに初期高さを持った山の線が与えられています。 旅はインデックスから歩くこととして定義されます$l$に$r$、常に右に 1 ステップ移動し、各移動のコストを連続する高さの絶対差として支払います。 したがって、クエリのコストは次の合計となります。$|a_i - a_{i+1}|$全体$i$から$l$に$r-1$ただし、高さは静的ではありません。 

クエリ間では、セグメント内のすべての高さを増やす範囲更新を適用できます。$[l, r]$ある値によって$x$。 重要なのは、この更新により高さが変更され、セグメント内の局所的なものだけでなく、隣接する多くの差異がグローバルに変更されることです。 

問題は、両方の操作の数が多く、最大で$3 \cdot 10^5$したがって、クエリごとに全範囲のコストを最初から再計算するのは遅すぎます。 課題は、範囲の追加とセグメントにわたる隣接する絶対差分の合計の高速クエリをサポートする動的配列を維持することです。 

重要な観察は、更新が違いにどのような影響を与えるかを理解することから得られます。 エッジの両方の端点が$(i, i+1)$更新範囲内でも外でも、その差は変わりません。 更新範囲の境界を横切るエッジのみが影響を受けます。 この局所性により、問題は扱いやすくなります。 

素朴な考えを打ち破るエッジケースには、次のようなものがあります。 

クエリごとの完全に単純な再計算はすぐに失敗します。 たとえば、すべての操作がタイプ 2 のクエリである場合、それぞれのコストは$O(n)$、合計作業量は$O(nq)$、それは約です$9 \cdot 10^{10}$操作。 

微妙な失敗は、範囲の更新を考慮せずに差分のプレフィックス合計を直接維持できると仮定していることです。 配列の一部のみをシフトするセグメント更新を考えてみましょう。 境界差分のみが変化するため、差分配列は単純な点の加算では更新されません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 配列を直接管理します。 範囲の加算の場合、各要素をインクリメントします。$[l, r]$。 クエリの場合、線形スキャンにより、要求された範囲内の絶対差の合計を計算します。 

これは操作の定義に直接従うため、正しいです。 ただし、更新ごとに費用がかかります$O(n)$最悪の場合、各クエリにもコストがかかります$O(n)$、二次関数またはそれより悪い動作につながります。 

ボトルネックは、すべての操作が潜在的に大きなセグメントに触れること、および以前の計算が再利用されないという事実から生じます。 

重要な洞察は、問題を 2 つの層に分けることです。 まず、遅延伝播を備えたセグメント ツリーまたはフェンウィック ツリーを使用して、範囲加算の下で配列を維持します。 第 2 に、毎回範囲にわたる絶対差を再計算するのではなく、隣接するペアの寄与構造を維持します。 

補助配列を定義します$d_i = a_{i+1} - a_i$。 クエリコストは次の合計です。$|d_i|$セグメント上にあります。 範囲の追加$x$影響を与える$d_i$ちょうど次のうちの 1 つの場合のみ$a_i$そして$a_{i+1}$更新範囲内です。 これは、更新ごとに 2 つの境界位置のみが問題となることを意味します。$l-1$そして$r$。 

したがって、多くの差分を更新する代わりに、隣接する 2 つの差分値のみを更新します。 その間、セグメント ツリーを維持します。$d_i$ポイントの更新と絶対値の範囲合計クエリをサポートします。 標識の変更を効率的に処理するために、次のことを維持します。$d_i$それ自体と、範囲の追加によって引き起こされるエンドポイントの更新をサポートする構造を介したその絶対的な寄与。 

中心的な考え方は、範囲の加算が差分配列の最大 2 点の更新に変換され、両方の演算が対数になるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | 最適 |$O(q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列を保守します$a$範囲の追加とポイント クエリをサポートするフェンウィック ツリーまたはセグメント ツリーを使用して暗黙的に実行されます。 並行して、違いを考慮した構造を維持します$d_i = a_{i+1} - a_i$ただし、各操作の後に配列全体を明示的に再構築することはありません。 

1. 元の配列に対する範囲の追加とポイント クエリをサポートするデータ構造を初期化します。$a$。 これにより、あらゆるものを回復できるようになります$a_i$すべての更新を明示的に保存せずに、必要に応じて実行できます。 
2. 初期差異の配列を構築する$d_i = a_{i+1} - a_i$。 これらは、パス コストに対するローカルな寄与を表します。 
3. セグメントツリーを構築します$|d_i|$、ポイントの更新と範囲合計クエリをサポートします。 この構造は、旅行費用のクエリに直接答えます。 
4. 範囲追加演算処理時$(l, r, x)$、境界に関係する差異のみが変化することに注目してください。 具体的には、ただ、$d_{l-1}$そして$d_r$すべての内部エッジが両方の端点を均等にシフトしているため、影響を受けます。 
5. これらの境界差を更新するには、まず古い値を計算します。$a_{l-1}, a_l, a_r, a_{r+1}$range-add 構造に対してポイント クエリを使用します。 
6. 再計算$d_{l-1} = a_l - a_{l-1}$もし$l > 1$、セグメント ツリー内の絶対値を更新します。 
7. 再計算$d_r = a_{r+1} - a_r$もし$r < n$を作成し、同様にその絶対値を更新します。 
8. 範囲加算を適用する$+x$今後のクエリに更新された高さが反映されるように、プライマリ構造に基づいて設定します。 
9. 旅行に関する問い合わせの場合$(l, r)$、の合計を返します$|d_i|$のために$i \in [l, r-1]$セグメントツリーから。 

なぜそれが機能するかは、均一なシフトの下での内部差異の不変性と結びついています。 セグメント内のすべての要素が同じ値だけ増加しても、そのセグメント内の差異は変化しません。 セグメントの境界を横切るエッジのみが 1 つの端点の変化を認識し、もう 1 つの端点の変化を認識しません。そのため、これら 2 つの位置のみを再計算する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_add(self, l, r, v):
        self.add(l, v)
        if r + 1 <= self.n:
            self.add(r + 1, -v)

    def point_query(self, i):
        return self.sum(i)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, tl, tr, arr):
        if tl == tr:
            self.t[v] = arr[tl]
        else:
            tm = (tl + tr) // 2
            self.build(v*2, tl, tm, arr)
            self.build(v*2+1, tm+1, tr, arr)
            self.t[v] = self.t[v*2] + self.t[v*2+1]

    def update(self, v, tl, tr, pos, val):
        if tl == tr:
            self.t[v] = val
        else:
            tm = (tl + tr) // 2
            if pos <= tm:
                self.update(v*2, tl, tm, pos, val)
            else:
                self.update(v*2+1, tm+1, tr, pos, val)
            self.t[v] = self.t[v*2] + self.t[v*2+1]

    def query(self, v, tl, tr, l, r):
        if l > r:
            return 0
        if l == tl and r == tr:
            return self.t[v]
        tm = (tl + tr) // 2
        return self.query(v*2, tl, tm, l, min(r, tm)) + \
               self.query(v*2+1, tm+1, tr, max(l, tm+1), r)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    fw = Fenwick(n)
    for i, v in enumerate(a, 1):
        fw.range_add(i, i, v)

    if n > 1:
        diff = [abs(a[i+1] - a[i]) for i in range(n-1)]
        st = SegTree(diff)
    else:
        st = None

    out = []

    for _ in range(q):
        tmp = list(map(int, input().split()))
        t = tmp[0]

        if t == 1:
            l, r, x = tmp[1], tmp[2], tmp[3]
            fw.range_add(l, r, x)

            if n > 1:
                if l > 1:
                    i = l - 2
                    left = fw.point_query(l-1)
                    right = fw.point_query(l)
                    st.update(1, 0, n-2, i, abs(right - left))

                if r < n:
                    i = r - 1
                    left = fw.point_query(r)
                    right = fw.point_query(r+1)
                    st.update(1, 0, n-2, i, abs(right - left))

        else:
            l, r = tmp[1], tmp[2]
            if l == r:
                out.append("0")
            else:
                out.append(str(st.query(1, 0, n-2, l-1, r-2)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは範囲加算の下で配列を保存するため、任意の点を対数時間で再構築できます。 セグメント ツリーは絶対隣接差分を保存し、境界値が変更された場合の単一位置の更新をサポートします。 更新ロジックは、範囲を追加するたびに、影響を受ける差異のみを慎重に再計算します。 

インデックス付けは少し微妙です: 差分インデックス$i$エッジに相当する$(i, i+1)$、それでクエリ$[l, r]$にマップします$[l-1, r-2]$差分構造で。

 ### 例 1

 入力:```
5 3
1 3 2 5 4
2 1 5
1 2 4 3

```初期の違いは次のとおりです。 

| 私 | a[i] | a[i+1] | 差分 |
 | --- | --- | --- | --- |
 | 1 | 1 | 3 | 2 |
 | 2 | 3 | 2 | 1 |
 | 3 | 2 | 5 | 3 |
 | 4 | 5 | 4 | 1 |

 最初のクエリはすべての差分を合計します: 2 + 1 + 3 + 1 = 7。 

[2,4]に3を加えると、配列は[1,6,5,8,4]になります。 

影響を受けるエッジを更新しました:

 | エッジ | 新しい差分 |
 | --- | --- |
 | (1,2) | 5 |
 | (4,5) | 4 |

### 例 2

 入力:```
4 2
10 10 10 10
2 1 4
1 2 3 5
```すべての値が等しいため、最初のクエリは 0 になります。 

更新後の配列は[10,15,15,10]になります。 

差分は [5,0,5] となり、更新後は境界エッジのみが重要であることがわかります。

 ## 特殊なケース

 単一要素の配列の場合はエッジがないため、すべてのクエリはゼロを返す必要があります。 差分のセグメント ツリーは空であり、コードは次の場合にそれを正しくバイパスします。$n = 1$。 

すべての要素を定数ずつ増やすなどの全範囲更新の場合、差分はまったく変化しません。 アルゴリズムは再計算のみを試みます$d_{l-1}$そして$d_r$この場合はどちらも範囲外であるため、更新は行われません。 これは、均一なシフトがすべての絶対的な差を保存するという事実と一致します。 

境界に触れる更新の場合:$l = 1$または$r = n$、境界更新の片側のみが存在します。 この実装では、差分を再計算する前に境界を明示的にチェックし、Fenwick 構造への無効なクエリを防止します。
