 ## 解決策
 ## 問題の理解

 場所のグラフが与えられます。 ドラえもんの工房を表す 0 というラベルの付いた特別なノードがあり、家を表すノードは他に n 個あります。 各家には良いか悪いかのマークが付いています。 

各家は、非常に特殊な方法で正確に 1 回訪問する必要があります。つまり、サンタは作業場から始まり、ある家に行き、その後作業場に戻ります。 戻ってきたら、次の家でもこれを繰り返します。 各配達のコストは、彼が 0 から家まで往復する道の長さです。 

制約は、元のグラフ内の最短パスだけではありません。 住宅タイプによってはルートが制限されます。 対象の家が良ければ、０からその家までの道はいかなる悪い家も通ることはできません。 対象の家が悪ければ、どんな良い家でも道は通れません。 復路も同じ制限に従う必要があります。 

したがって、各家について、家の色に応じた部分グラフ内の 0 からその家までの最短経路を 2 倍する必要があるのが事実です。 

グラフは、最大 100,000 個のノードと 300,000 個のエッジまで大きくすることができます。 これにより、すべての家に対してダイクストラを最初から実行するようなクエリごとの最短パスの計算が直ちに除外されます。これは、遅すぎるためです。 単純な解決策では、ダイクストラを n 回実行しようとすると、O(n m log n) になりますが、これは現実的ではありません。 

重要な微妙な点は、「悪い家を通過できない」ということは、エッジではなく中間の頂点が制限されていることを意味します。 これは頂点フィルタリングされた最短経路問題です。 

エッジケースは次の場合に発生します。 

家は工房に直結しているが、全ての道が反対の色で塞がれており、迂回を余儀なくされている。 

ノードは、許可された色のサブグラフ内で分離されているため、計算を正しく分離しない限りノードに到達できません。 

同じ物理的なグラフ エッジが両方の部分問題に存在する可能性がありますが、色をまたがって再利用することはできません。 

不注意なアプローチでは、1 つのグローバル最短パス ツリーを計算し、それをすべてのノードに再利用する可能性があり、禁止されたハウス タイプを通るパスが誤って許可されてしまいます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。ハウスごとに、ノード 0 からダイクストラを実行しますが、ターゲット ハウスに応じて、すべて良好またはすべて不良のノードを通過することのみを許可します。 一軒家の場合、これは O(m log n) です。 これをすべての n 軒に対して繰り返すと、O(n m log n) が得られます。これは、最悪の場合、約 10^5 倍の 3×10^5 演算となり、完全に実行不可能です。 

主な観察点は、制限は特定の宛先自体ではなく、宛先のタイプにのみ依存するということです。 タイプを修正すると、たとえば、良い家だけを気にすると、良い家へのすべての有効なパスは、良いノードのみを通過するように制約されます。 つまり、ノード 0 とすべての良好なノードを含む誘導サブグラフ上で、許可された同じタイプのエンドポイントにフィルタリングされたエッジを使用して、単一ソースの最短経路問題を解いていることになります。 悪い家についても同様のことが独立して当てはまります。 

したがって、n 回の最短パス計算の代わりに必要なのは 2 つだけです。1 つは「良好な場合のみ」のグラフで、もう 1 つは「不良な場合のみ」のグラフです。 それぞれはノード 0 の標準ダイクストラですが、同じタイプのノードに限定されます。 距離を計算すると、答えはそれぞれの制限されたグラフの 0 からの距離の 2 倍のすべての住宅の合計になります。 

これにより、多くの最短パスの実行による問題が 2 つに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ハウスごとのディクストラ) | O(n · m log n) | O(n + m) | 遅すぎる |
 | タイプごとに分割 + 2 つのダイクストラ実行 | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 パスではタイプを混在させることができないため、良いハウスと悪いハウスを別々に扱います。 

## アルゴリズムのチュートリアル

1. 2 つの隣接構造を構築します。1 つはワークショップまたは良好なハウスのいずれかのノードのみを含むグラフ、もう 1 つはワークショップまたは不良ハウスのみを含むグラフです。 両方のエンドポイントがそのグラフで許可されているタイプに属している場合にのみ、グラフにエッジを含めます。 これにより、計算されるすべてのパスが自動的に制約を遵守するようになります。 
2. 「良いグラフ」のノード 0 からダイクストラのアルゴリズムを実行して、作業場からすべての良い家までの最短距離を計算します。 この距離は、どら焼きの最適な配送ルートを表しています。 
3. 「悪いグラフ」のノード 0 からダイクストラのアルゴリズムを再度実行して、すべての悪いハウスまでの最短距離を計算します。 これらは、Reflection Mirror の配送に最適なルートを表します。 
4. すべての家について、そのタイプに応じて正しい走行距離から事前に計算された距離を取得し、2 (行きと帰り) を掛けて、最終的な答えに累積します。 
5. 総和を出力します。 

重要な実装の詳細は、すべての旅行がワークショップで開始および終了するため、両方のグラフでノード 0 が許可されることです。 ノードがグラフから除外されると、そのノードはダイクストラ実行からは完全に見えなくなるため、緩和中に特別なロジックを必要とせずに、パスは自動的に禁止ハウスを回避します。 

### なぜ効果があるのか

 「反対色の家を通過できない」という制限により、共有ソース ノード 0 を除き、グラフが 2 つの独立した誘導サブグラフに変わります。良い家の有効なパスは決して悪いノードに入らないため、その最短パスは、良いノードのみを含むサブグラフで計算された最短パスと同じになります。 したがって、そのサブグラフ上のダイクストラは、制約付き最短経路を正確に生成します。 すべてのハウスは独立して処理されますが、タイプごとに単一のマルチターゲット計算から距離が再利用されるため、最適なパスが見逃されたり、誤って許可されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def dijkstra(n, adj, start):
    INF = 10**30
    dist = [INF] * (n + 1)
    dist[start] = 0
    pq = [(0, start)]
    
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

n = int(input().strip())
types = input().strip()

m = int(input().strip())

good_adj = [[] for _ in range(n + 1)]
bad_adj = [[] for _ in range(n + 1)]

def is_good(i):
    return i == 0 or types[i - 1] == 'G'

def is_bad(i):
    return i == 0 or types[i - 1] == 'B'

for _ in range(m):
    u, v, w = map(int, input().split())
    
    if is_good(u) and is_good(v):
        good_adj[u].append((v, w))
        good_adj[v].append((u, w))
    if is_bad(u) and is_bad(v):
        bad_adj[u].append((v, w))
        bad_adj[v].append((u, w))

dist_good = dijkstra(n, good_adj, 0)
dist_bad = dijkstra(n, bad_adj, 0)

ans = 0
for i in range(1, n + 1):
    if types[i - 1] == 'G':
        ans += 2 * dist_good[i]
    else:
        ans += 2 * dist_bad[i]

print(ans)
```このソリューションは 2 つのフィルター処理されたグラフを構築し、ダイクストラを 2 回実行します。 フィルタリングはエッジの構築中に行われるため、最短パスの計算自体は標準であり、ノードの有効性に関する条件チェックは必要ありません。 よくある間違いは、グラフの構築中ではなく緩和中にノードをフィルタリングしようとすることです。 これによりコードが複雑になり、無効なパスを介してノードが誤って再訪問された場合に微妙なバグが発生する傾向があります。 

すべての配信は往復であるため、最後のループでは、ノードごとに正しい距離の 2 倍が単純に累積されます。 

## 実用的な例

 ノード 0 が 2 つの家に接続されており、共有中間ノードがある小さなグラフを考えてみましょう。 

入力：```
3
GBG
0-1 (5)
0-2 (2)
2-1 (1)
1-3 (1)
2-3 (10)
```2 つのグラフを計算します。 

### 良好なグラフ実行 (ノード 0 および良好なハウスのみ: 0、1、3)

 | ステップ | ノード | 距離 | アクション |
 | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 開始 |
 | ポップ | 2 | 無効 | 無視されます (不良ノードが削除されました) |
 | ポップ | 1 | 5 | エッジをリラックス |
 | ポップ | 3 | 6 | 経由 1 |

 つまり、dist_good[1]=5、dist_good[3]=6 となります。 

### 不正なグラフ実行 (ノード 0、2)

 | ステップ | ノード | 距離 | アクション |
 | --- | --- | --- | --- |
 | 初期化 | 0 | 0 | 開始 |
 | ポップ | 2 | 2 | 最終 |

 次に、次のように計算します。 

ハウス 1 (G): 2×5 = 10

 ハウス 2 (B): 2×2 = 4

 ハウス 3 (G): 2×6 = 12

 合計 = 26。 

これは、許可されていないノードを通過するパスが、たとえ元のグラフでは短かったとしても、考慮から完全に除外されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log n) | フィルタリングされたグラフ上で 2 つのダイクストラを実行します。 
| スペース | O(n + m) | 隣接リストと距離配列 |

 この制約により、最大 3×10^5 のエッジが許可されるため、隣接リストを使用した Python では、2 つの優先順位キューの最短パスの計算が容易に十分高速になります。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import heapq

    def dijkstra(n, adj, start):
        INF = 10**30
        dist = [INF] * (n + 1)
        dist[start] = 0
        pq = [(0, start)]
        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            for v, w in adj[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))
        return dist

    n = int(input().strip())
    types = input().strip()
    m = int(input().strip())

    good_adj = [[] for _ in range(n + 1)]
    bad_adj = [[] for _ in range(n + 1)]

    def is_good(i):
        return i == 0 or types[i - 1] == 'G'

    def is_bad(i):
        return i == 0 or types[i - 1] == 'B'

    for _ in range(m):
        u, v, w = map(int, input().split())
        if is_good(u) and is_good(v):
            good_adj[u].append((v, w))
            good_adj[v].append((u, w))
        if is_bad(u) and is_bad(v):
            bad_adj[u].append((v, w))
            bad_adj[v].append((u, w))

    dist_good = dijkstra(n, good_adj, 0)
    dist_bad = dijkstra(n, bad_adj, 0)

    ans = 0
    for i in range(1, n + 1):
        if types[i - 1] == 'G':
            ans += 2 * dist_good[i]
        else:
            ans += 2 * dist_bad[i]

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースは、グラフ全体の最短パスが禁止ノードを通過するが、それを経由しない代替のより長いパスが存在する場合です。 たとえば、良好な家がエッジが非常に短い不良ノードを介してワークショップに接続されている場合、そのルートは完全に無視する必要があります。 フィルターされたグラフの構築では、パス計算の前に不良ノードを削除することでこれを保証するため、アルゴリズムはそのショートカットを考慮することさえありません。 

もう 1 つのエッジ ケースは、家がワークショップに直接接続されているものの、互換性のあるエッジが欠落しているため、許可されたサブグラフ内で孤立している場合です。 そのような状況では、ダイクストラは距離を無限として正しく残しますが、この問題では到達可能性が保証されているため、特別な処理を避けるためにその条件に依存します。 

最後に、反対のタイプ間のエッジは黙って破棄されます。 これは接続を削除するため疑わしいように見えるかもしれませんが、まさに制約を強制するものです。 このようなエッジを横切るパスは直ちにルールに違反するため、ルールを削除すると、正確性が低下するのではなく、正確さが維持されます。
