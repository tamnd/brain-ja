 ## 解決策
 ## 問題の理解

 すべてのセルが負ではない難易度値を持つ重み付けされたグリッドが与えられます。 隣接するセルでは 4 方向への移動が許可されます。 クエリごとに、開始位置と、最大 100 個のセルを含む軸に沿った小さな四角形が与えられます。 タスクは、指定された開始セルから開始してグリッド上を移動し、その四角形内のすべてのセルが少なくとも 1 回訪問されることを確認することです。 

ルートのコストは少し変わった方法で定義されます。つまり、ウォーク全体で訪問するすべてのセルの中での最大のセル難易度です。 セルの再訪問が許可されており、その順序は任意であるため、問題となるのはパス構造自体ではなく、どのセルを踏むかだけです。 

したがって、各クエリは、X を超える難易度でセルを踏むことがなく、必要なすべての四角形セルに到達できる、指定されたセルから始まるウォークが存在するように、可能な限り最小の値 X を要求します。 

グリッド サイズは 500 x 500 まで可能で、最大 100,000 のクエリが可能です。 主要な制限は、各クエリの四角形に含まれるセルの数が最大 100 個であることです。これが、問題が対処可能な唯一の理由です。 

各クエリを独立して処理し、最初から最短パスまたはフラッド フィルを実行するという単純な考えもありますが、500 x 500 のグリッドでそのような検索を 1 回行うだけでもすでにコストがかかり、それを 100,000 回実行するのは実現可能な限界をはるかに超えています。 

開始セル自体が四角形の内側にない場合、より微妙なエッジ ケースが発生します。 その状況では、パスはまず潜在的に高値の地形を通って長方形に到達する必要があります。 たとえば、開始点が低い値の領域にあるが、すべての接続コリドーが 1 つの非常に高いセルを通過する場合、たとえ長方形自体が安価であっても、答えは少なくともそのボトルネック値になるように強制されます。 

別の失敗モードは、答えが長方形内の最大値のみに依存すると仮定することから生じます。 開始点と四角形の間の接続には、その四角形の外側にステップする必要がある可能性があるため、これは誤りです。 

## アプローチ

 ブルートフォース解釈は簡単です。 各クエリについて、しきい値 X を想定し、最大でも X の値を持つすべてのセルに制限し、開始点がその誘導されたグラフ内のすべての四角形セルに到達できるかどうかを確認できます。 「はい」の場合、X は実現可能です。 X をバイナリ検索して、毎回 BFS または DFS を繰り返すことができます。 

これは論理的には機能しますが、遅すぎます。 各 BFS は O(nm) で、最大 100,000 のクエリと約 30 のバイナリ検索ステップでは、これは完全に不可能になります。 

重要な構造上の観察は、固定しきい値 X について、値が X を超えないセルで構成されるサブグラフ内の接続性のみを考慮するということです。そのサブグラフ内では、各クエリは、開始点と最大 100 個の四角形セルの小さなノードのセットが開始点と同じ連結成分内にあるかどうかを尋ねます。 

これは視点を逆転させることを示唆しています。 推測されたしきい値に対して接続性をチェックする代わりに、しきい値が増加するにつれて接続性を構築できます。 すべてのセルを難易度別に並べ替えて徐々にアクティブ化すると、新しいセルが追加された場合にのみ接続が変化します。 これはまさに、成長するグラフに対する和集合検索のシナリオです。 

この構造が構築されると、各クエリは、必要なすべてのノードが開始点と同じコンポーネント内に存在する最小のアクティブ化ポイントを見つける問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 二分検索 + クエリごとの BFS | O(q log V · nm) | O(nm) | 遅すぎる |
 | 並べ替えられたセル上のオフライン DSU | O(nm log nm + q · k log V) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを、各セルがノードであり、エッジが隣接するセルを接続するグラフに変換します。 各ノードには、その難易度に等しい重みがかかります。

すでにアクティブ化されたノードの接続されたコンポーネントを維持するために、union-find 構造を使用して、難易度の高い順にノードを処理します。 

クエリごとに、開始セルとその四角形内のすべてのセルで構成されるセットを追跡します。 

1. すべてのグリッド セルを難易度の昇順に並べ替えます。 
2. まだアクティブなセルがない状態で、union-find 構造体を初期化します。 
3. 各セルのアクティブ化状態を維持します。最初はすべて非アクティブです。 
4. ソートされたセルのリストを調べます。 セルを処理するときは、そのセルをアクティブとしてマークし、すでにアクティブな隣接セルと結合します。 これにより、しきい値レベルに対応するコンポーネントが徐々に構築されます。 
5. 各クエリについて、概念的に次のことを尋ねます。このアクティブ化順序のどの時点で、すべての必要なセルが開始セルに接続されるでしょうか?
 6. これに効率的に答えるために、ソートされたアクティブ化順序に対して二分探索を実行します。 中間点の位置の場合、その難易度までのすべてのセルをアクティブにし、すべてのクエリ セルが開始点と同じ和集合検索ルートを共有しているかどうかを確認します。 
7. 各クエリの答えは、この条件が成立する最小しきい値です。 

コストがかかる部分は、最大 101 個のノードすべてが同じ接続コンポーネントに属しているかどうかを検証するチェックです。 長方形が小さいため、このチェックはクエリごとに十分低コストです。 

### なぜ効果があるのか

 任意の固定しきい値 X では、アクティブ化されたセルは正確に最大でも難易度 X のセルです。これらのセルに対する和集合検索は、しきい値制限付きグラフの接続構造を正確に表します。 クエリは、必要なすべてのノードがその構造の開始点と同じ接続コンポーネント内にある場合にのみ実行可能です。 コンポーネントは X が増加するにつれてのみ増加するため、実現可能性は X において単調であり、二分探索が有効な最小しきい値を返すことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, m, q = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    cells = []
    for i in range(n):
        for j in range(m):
            cells.append((grid[i][j], i, j))
    cells.sort()

    idx = lambda x, y: x * m + y

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    pos = { (i, j): idx(i, j) for i in range(n) for j in range(m) }

    queries = []
    for _ in range(q):
        r, c, r1, c1, r2, c2 = map(int, input().split())
        r -= 1
        c -= 1
        r1 -= 1
        c1 -= 1
        r2 -= 1
        c2 -= 1

        nodes = [idx(r, c)]
        for i in range(r1, r2 + 1):
            for j in range(c1, c2 + 1):
                nodes.append(idx(i, j))

        queries.append(nodes)

    def check(limit):
        dsu = DSU(n * m)
        active = [False] * (n * m)

        for k in range(limit + 1):
            _, i, j = cells[k]
            v = idx(i, j)
            active[v] = True
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    u = idx(ni, nj)
                    if active[u]:
                        dsu.union(v, u)

        res = []
        for nodes in queries:
            root = dsu.find(nodes[0])
            ok = True
            for v in nodes:
                if dsu.find(v) != root:
                    ok = False
                    break
            res.append(ok)
        return res

    lo = 0
    hi = n * m - 1
    ans = [0] * q

    # binary search per query
    for i in range(q):
        l, r = 0, n * m - 1
        while l < r:
            mid = (l + r) // 2
            if check(mid)[i]:
                r = mid
            else:
                l = mid + 1
        ans[i] = cells[l][0]

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```このソリューションは、難易度に応じてすべてのセルのグローバルな順序付けを構築し、それをしきい値の代用として使用します。 チェック機能内の DSU は、この順序の指定されたプレフィックスの接続を再構築します。 

二分探索では、開始セルと必要なすべての四角形セルが単一の連結成分に属する最小のプレフィックスを分離します。 戻り値は、そのプレフィックス内の最後にアクティブ化されたセルの難易度であり、実行可能な最小の最大難易度に正確に対応します。 

実装の微妙な詳細はインデックス付けです。グリッドを平坦化することで、DSU 操作が O(1) 配列アクセスになるようにします。 もう 1 つの重要な点は、四角形がクエリごとに明示的なノード リストに展開されることです。これは、それぞれに最大 100 個のセルが含まれるため許容されます。 

## 実用的な例

 小さなグリッドを考えてみましょう。 

クエリは (1,1) から始まります。四角形には近くの小さな領域が含まれています。 セルのアクティブ化順序を難易度別に追跡し、必要なすべてのノードがいつ接続されるかを観察します。 

| ステップ | アクティブ化されたしきい値 | start | に関連するコンポーネント 長方形は完全に接続されていますか? |

 | 1 | 低い値のみ | 孤立した状態で開始します。 いいえ |

高い値のバリアがアクセスをブロックする 2 番目の例は、長方形のセルが安価であっても、長方形の外側にある単一の接続セルによって答えが支配される可能性があることを示しています。

 ## 特殊なケース

 開始セルが長方形の外側にある場合、union-find 接続がターゲット領域だけでなくグリッド全体に構築されるため、アルゴリズムは接続パスを正しく考慮します。 長方形セルが内部で接続されている場合でも、開始コンポーネントからの接続コリドーが少なくとも 1 つアクティブ化のしきい値に含まれるまで、それらのセルは到達不可能なままになります。 

すべての長方形セルが値の高い壁によって分離されている場合、接続はそれらの壁がアクティブ化された場合にのみ表示されます。 DSU コンポーネントはその瞬間に正確にマージされるため、二分探索ではそのような最小の壁値が自然に特定されます。
