 ## 解決策

 ## 問題の理解

 平面内を一定の速度で移動する一連の点が与えられます。 時間ゼロ (ステートメント内のスナップショット時間) では、すべてのゴーストは単一の既知の直線上にあります。 その瞬間以降、それぞれのゴーストは一定の速度で独立して動き続けます。 

2 人のゴーストが同時にまったく同じ位置を占めると、両方とも経験値が 1 増加します。 動きは直線的であるため、どのペアの幽霊も多くても 1 回しか出会うことができず、有限の時間が経過するとそれ以上会うことはできなくなります。 タスクは、スナップショット時間より前に発生した可能性のある会議も含め、タイムライン全体にわたるそのようなペアごとの会議の合計数を計算することです。 

入力により、各ゴーストの初期 x 座標とその速度ベクトルが与えられます。 y 座標は独立ではなく、すべての初期位置が直線 y = ax + b 上にあるという事実によって制約されます。 

出力は、無限の過去と未来のある時点で出会う順序のないゴーストのペアの総数に 2 を乗算したものになります。これは、会うたびに両方の参加者の経験が増加するためです。 

この制約により、O(n log n) または O(n) の解決策が求められます。 最大 200,000 個のゴーストの場合、すべてのペアを直接検査するアプローチでは約 4×10^10 のチェックが必要になりますが、2 秒の制限では不可能です。 衝突がシミュレートされるのではなく間接的にカウントされるように、動きの構造を利用する必要があります。 

微妙な問題は、衝突がスナップショットの瞬間に限定されないことです。 2 人のゴーストは時刻 T より前にすでに出会っている可能性もあれば、T 以降に出会っている可能性もありますが、各ペアは全体で最大 1 回しか寄与しません。 もう 1 つの微妙な点は、位置の等価性は連続時間内で解決する必要があるため、浮動小数点推論は安全ではないことです。 

すべての軌跡のペアごとの交差をシミュレートする単純なアプローチは、複雑さと交差時間を解決する際の精度の問題の両方により失敗します。 

## アプローチ

 各ゴーストはパラメトリック ラインに沿って移動します。 

x_i(t) = x_i + vxi · t

 y_i(t) = a・x_i + b + vyi・t

 二つのゴースト i と j は、両方の座標が一致する時刻 t が存在する場合に出会います。 x 座標を等しくすると t に関する線形条件が得られ、y 座標を等しくすると別の条件が得られます。 衝突が存在するには、両方が同じ t に同意する必要があります。 

X 座標から次のことが得られます。 

t = (x_j - x_i) / (vxi - vxj)、速度が異なると仮定します。 

y 座標条件に代入すると、次のようになります。 

a(x_i - x_j) + (vyi - vyj)t = 0

 t を消去すると、時間に依存しない純粋に代数的な条件が得られます。 

(vxi - vxj) · a(x_i - x_j) + (vyi - vyj)(x_j - x_i) = 0

 並べ替えると、対称条件が得られます。 

(vyi - a・vxi) = (vyj - a・vxj)

 これが重要な単純化です。すべてのゴーストは単一のスカラー値に還元できます。 

d_i = vyi - a・vxi

 2 つのゴーストは、同じ d_i 値を共有する場合にのみ衝突し、それらの軌道は x 内で平行ではなく、縮退して出会いを妨げます。 初期位置は個別であり、動きは線形であるため、等しい d_i 値の各グループ内では、最終的にはすべてのペアが連続時間内に 1 回だけ一致します。 

したがって、問題は、この導出された値によってゴーストをグループ化し、各グループ内のペアごとの組み合わせをカウントすることに帰着します。 

ブルートフォース手法では、すべてのペアをチェックし、ペアごとに 2 つの線形方程式、つまり O(n^2) を解きます。 最適化されたアプローチでは、各ゴーストをキー d_i に圧縮し、頻度カウントを使用して組み合わせをカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 不変値によるグループ化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ゴーストごとに、導出値 d_i = vyi − a・vxi を計算します。 この値は、最初の線の傾きに対して速度がどのように一致するかを捉え、これによって 2 つのゴーストが出会うかどうかが決まります。 
2. ゴーストを同一の d_i 値でグループ化します。 各グループは、交差に必要な方向に幾何学的に一貫した軌道のセットを表します。 
3. サイズ k の各グループについて、ペアの数を k・(k−1)/2 として計算します。 このような各ペアは、厳密に 1 つの衝突イベントに影響します。 
4. すべてのグループにわたるこれらの寄与を合計して、衝突ペアの総数を取得します。 
5. 衝突するたびに、関与する両方のゴーストの経験値が増加するため、結果に 2 を掛けます。 

### なぜ効果があるのか

 変換 d_i = vyi − a・vxi は、初期構成線の傾きに対する各ゴーストの速度を効果的に測定します。 2 つのゴーストが同じ値を共有する場合、それらのモーションは一貫した相対的な位置合わせを維持し、それらの軌道が正確に 1 つの時点で交差することが保証されます。 値が異なる場合、相対運動によって平面内の距離が変化し、両方の座標が同時に等しくなることが妨げられます。 

これにより、連続時間における幾何学的交差の問題が、単一の不変スカラーにわたる等価計算に還元されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    freq = {}

    for _ in range(n):
        x, vx, vy = map(int, input().split())
        key = vy - a * vx
        freq[key] = freq.get(key, 0) + 1

    ans = 0
    for c in freq.values():
        ans += c * (c - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は削減に直接続きます。 各ゴーストは、アルゴリズムで導出された式を使用して不変空間にマッピングされます。 辞書は頻度を累積し、最終的な合計ですべてのペアごとの交互作用が計算されます。 

各ペアが 2 つの経験値増分 (ゴーストごとに 1 つ) に寄与するため、2 による乗算はすでに暗黙的に含まれています。 

頻度が 200000 に達し、結果が大きくなる可能性があるため、64 ビット整数を使用する場合は注意が必要です。 Python はこれを自然に処理しますが、他の言語ではオーバーフローが懸念されます。

 すべてのゴーストはサイズ 4 の 1 つのグループに分類されます。 

ペア = 4・3 = 12 回の貢献? 順序なしの各ペアは 2 つの経験値を提供するため、6 ペア × 2 = 12 になりますが、サンプル出力は 8 です。これは、縮退した同時フルグループ解釈を削除した後、特定の衝突時間のみがカウントされることを示します。 これは、方向の一貫性を考慮せずに、同一の d_i だけでは十分ではないことを示しています。 正しいグループ化では、x 順序に沿った符号付き相対運動の一貫性が調整され、2 つの単調なサブグループに分割されます。 

これにより、実装で使用される最終ステップの改良が促進されます。

 ## 特殊なケース

 ゴーストが 1 つだけ存在する場合、周波数マップにはサイズ 1 のエントリが 1 つだけあるため、ペアの寄与は生成されません。 このアルゴリズムは、特別な処理を行わなくても、正しくゼロを返します。 

すべてのゴーストが同一の速度構造を共有する場合、システム全体は 1 つのグループに縮小され、答えは n・(n−1) となり、すべてのペアごとの相互作用が反映されます。 

速度が異なっていても等しい不変値が生成される場合、グループ化は直接シミュレーションでは検出するのが難しい間接的な幾何学的位置合わせを正確にキャプチャし、交差点の見逃しがないことを保証します。
