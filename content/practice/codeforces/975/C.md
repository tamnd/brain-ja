 ## 解決策

 ## 問題の理解

 戦士たちの列で繰り返される戦いをシミュレートしています。 各戦士の体力は固定されており、矢は常に最初のまだ生きている戦士に命中してから、次の戦士に進みます。 戦士が体力以上のダメージを蓄積すると、その戦士は死亡したとみなされ、同じ分内に次の戦士に攻撃が続きます。 

面白いのは、その分の間にすべての戦士が死亡した場合、戦闘が 1 分ごとに「リセット」されることです。 その時点で、次の時間が始まる前に、すべての戦士はすぐに完全な健康状態に戻ります。 ただし、一部の戦士が 1 分間の終了後に生き残った場合、減少した体力は次の 1 分まで持続します。 

分ごとに、前の分から引き継がれた部分的なダメージを考慮して、その分の矢を処理した後にまだ生き残っている戦士の数を報告する必要があります。 

入力サイズにより、単純なシミュレーションが不可能になります。 最大 200,000 人の戦士と 200,000 分、矢のカウントが 1 分あたり最大 10^14 であるため、各矢を個別に処理したり、最初から繰り返しスキャンしたりするソリューションでは、遅すぎます。 O(nq) アプローチでも 4e10 操作のリスクがあり、これは実現不可能です。 

わずかなエッジケースは、1 分間の矢ですべての戦士を殺すのに十分で、まだ残っている場合に発生します。 その場合、残った矢は破棄され、すべての戦士が復活します。 不注意に実装すると、誤って次の瞬間にダメージが引き継がれたり、正しくリセットされなかったりする可能性があります。 

もう 1 つの注意が必要なケースは、ダメージによって戦士が部分的にしか死亡しない場合です。 その戦士は次の瞬間に新しい「現在のターゲット」となり、彼の残りの体力は正しく維持されなければなりません。 この永続性が欠けていると、後続のクエリでカウントが不正確になります。 

## アプローチ

 ブルートフォースシミュレーションでは、最初の生存位置から戦士を反復処理し、矢が尽きるかすべての戦士が死ぬまで矢を1本ずつ減算することで毎分処理されます。 戦士の体力がゼロになると、次の戦士に移ります。 このアプローチは正しいですが、最悪の場合、毎分 n 人の戦士すべてを横断する可能性があり、各戦士が数分にわたって何度も訪問され、O(nq) 動作が発生する可能性があります。 200,000 × 200,000 では、これは完全に不可能です。 

重要な観察は、ダメージは左から右にのみ移動し、戦士が完全に殺されると、完全なリセットが発生しない限り、再び関連することは決してないということです。 これは、前の数分後の残りのヘルスのプレフィックス構造を維持し、現在の矢の波がどこまで伝播できるかを迅速に見つけることを示唆しています。 

矢印ごとにシミュレーションする代わりに、ヘルスのプレフィックス合計を維持し、これまでに蓄積された合計ダメージの量を追跡できます。 毎分の矢は全体的なダメージカウンターを増加させます。 まだ生きている最初の戦士インデックスは、プレフィックスの合計が蓄積ダメージを超える最初の位置です。 これにより、問題はプレフィックス合計配列内の境界を繰り返し見つけることになり、二分探索を使用して実行できます。 

ただし、1 分間に入ってくる矢の合計が残りの体力の合計を超えた場合のリセットも処理する必要があります。 その場合、すべての戦士は死亡し、すべてが復活するため、蓄積されたダメージはゼロにリセットされます。 

したがって、問題は、グローバルな「これまでのダメージ」を維持し、ダメージが合計を超えたときに定期的にリセットしながら、それを超えているプレフィックスの合計がいくつあるかを答えることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nq) | O(n) | 遅すぎる |
 | プレフィックス合計 + 二分検索 | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列を構築する`pref`、 どこ`pref[i]`1 から i までの戦士の合計体力です。 これにより、特定のポイントまでに倒すのに必要なダメージがわかります。 
2. 変数を維持する`d`現在の状態に持ち込まれた合計ダメージを表します。 
3. クエリごとに`k_i`、 増加`d`による`k_i`, リセットが発生するまで矢は継続的にダメージを蓄積するためです。 
4. もし`d`以上です`pref[n]`、この1分間にすべての戦士が死亡します。 その場合は出力`n`そしてリセット`d`復活は完全な死の直後に起こるため、ゼロになります。 
5. それ以外の場合は、損傷後に何人の戦士がまだ生きているかを見つける必要があります`d`。 最小のインデックスを見つけます`pos`そのような`pref[pos] > d`二分探索を使用します。 
6. 生き残った戦士の数は`n - pos + 1`、以前のすべての戦士以来`pos`彼らは死んでおり、残りは生きています。 
7. 現在の分のこの値を出力し、続行します。 

二分探索ステップは、動的なプレフィックス損傷プロセスを静的な順序構造クエリに変換するため、非常に重要です。 

### なぜ効果があるのか

 プレフィックス合計配列は、各戦士を倒すのに必要な累積ダメージ量を正確にエンコードします。 ダメージは常に左から右に適用され、後方にスキップすることはありません。`pref[i] <= d`死んだ戦士の特徴を正確に表現しています。 生きているセグメントは常にサフィックスであるため、単一の境界インデックスで状態を完全に記述できます。 すべての戦士が死亡すると、システム状態は初期状態と同じになり、過去のダメージは無関係になるため、リセット条件は正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

pref = [0] * (n + 1)
for i in range(1, n + 1):
    pref[i] = pref[i - 1] + a[i - 1]

total = pref[n]
d = 0

import bisect

for _ in range(q):
    k = int(input())
    d += k

    if d >= total:
        print(n)
        d = 0
        continue

    pos = bisect.bisect_right(pref, d)
    alive = n - (pos - 1)
    print(alive)
```プレフィックス合計配列は、すべての戦士の強さを単調な構造に圧縮し、各プレフィックスが完全な殺害しきい値を表します。 変数`d`完全なワイプが発生するまで、分単位で入ってくる矢印の合計を累積します。完全なワイプが発生すると、システム状態が再起動するため、リセットされます。 

二分探索 (`bisect_right`) は、現在のダメージより厳密に大きい最初のプレフィックスを見つけます。これは、最初に生きている戦士を直接識別します。 減算すると生存者の数が効率的に得られます。 

微妙な点は、二分探索を実行する前にリセットを正しく処理することです。 リセットし忘れたら`d`すべての戦士が死亡すると、今後のクエリでは、すでにリセットされたシステムに加えて誤ってダメージが適用されてしまいます。

## テストケース```python
import sys, io
import bisect

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    total = pref[n]
    d = 0

    out = []
    for _ in range(q):
        k = int(input())
        d += k
        if d >= total:
            out.append(str(n))
            d = 0
        else:
            pos = bisect.bisect_right(pref, d)
            out.append(str(n - (pos - 1)))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、概念的に合計健全性を複数回超えるほどの十分な矢印が 1 つのクエリで提供される場合です。 アルゴリズムは、いつでもすぐにリセットすることでこれを処理します。`d >= total`、サイクル全体にわたって残留損傷が漏れないことを保証します。 たとえば、`a = [1,1,1]`そして`k = 10`、設定しました`d = 0`すべての戦士が生きていることを正しく出力します。 

もう 1 つのエッジ ケースは、ダメージがプレフィックス合計境界に正確に到達する場合です。 私たちが使っているので、`bisect_right`、 もし`d`等しい`pref[i]`、 戦士`i`戦士は死亡したとみなされ、次の戦士が最初に生きた戦士になります。 これは、矢が前進する前に戦士を完全に消耗させるというルールと一致します。
