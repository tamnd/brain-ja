 ## 解決策
 ## 問題の理解

 入力内の各単語はオブジェクトを説明することを目的としていますが、この言語には正規化ルールがあります。つまり、2 つの単語にまったく同じ一連の異なる文字が含まれている場合、2 つの単語は同じオブジェクトを表し、各文字の出現回数や順序は無視されます。 

したがって、単語を文字列として扱うのではなく、実際には単語を固有の文字セットによってグループ化しています。 たとえば、「a」、「aa」、「aaaa」はすべて文字「a」のみを含むため、すべて同じ表現になります。 同様に、「ab」、「baba」、および「aabb」は、それぞれ異なる文字であるため、すべて同じオブジェクトになります。`{a, b}`。 

タスクは、すべての与えられた単語の中にそのような異なる文字セットがいくつ出現するかを数えることです。 

制約は十分に小さいので、各単語を個別に処理して、その文字セットの表現を直接構築することができます。 単語は最大 1000 個あり、各単語の長さは最大 1000 であるため、すべての文字を単純にスキャンすると最大 10^6 文字の操作が行われ、これは Python では快適に高速です。 

生の単語をキーとして使用しようとすると、微妙な問題が発生します。 「ab」と「baab」のような 2 つの単語は異なる文字列ですが、同じオブジェクトを表すため、文字列を直接扱うと過剰にカウントされてしまいます。 もう 1 つの潜在的な間違いは、順列を別のものとして数えることです。 たとえば、「abc」、「cba」、および「bca」は、ルールの下ではすべて同一のオブジェクトです。 

主なエッジケースは、文字が何度も繰り返されることです。 「aaaaaa」のような単語は 1 つの代表者に折りたたむ必要があり、この正規化ステップを怠ると、答えが膨らむことになります。 

## アプローチ

 ブルートフォース解釈では、すべての単語を他のすべての単語と比較し、それらが同じオブジェクトを定義しているかどうかをチェックします。 この比較を行うには、各ペアの文字セットを計算して比較します。 n 個の単語がある場合、各比較のコストは最大 O(26) または O(length) であり、すべてのペアに対してこれを行うと O(n² · k) になります。これは不要ですが、小さい制限では許容できる境界線にあります。 

重要な観察は、オブジェクトの等価性は「文字のセット」の下での等価性であるということです。 これは、各単語の正規形式を構築し、それをハッシュ セットに挿入することを示唆しています。 正規形式は、すべての個別の文字を収集し、それらを並べ替えられた文字列またはビットマスクにエンコードすることによって構築できます。 英語の小文字のサイズは固定 (26) であるため、コンパクトで衝突のない表現を簡単に構築できます。 

これにより、問題は単語ごとに 1 つの署名を計算し、一意の署名がいくつ存在するかを数えるという問題に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアワイズ比較 | O(n² · k) | O(n · k) | 一般的な形式では遅すぎる |
 | 正規セット + ハッシュ | O(n · k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力からすべての単語を読み取ります。 オブジェクトのアイデンティティはその文字自体にのみ依存するため、各単語は独立して処理されます。 
2. 単語ごとに、その単語に含まれる文字セットの表現を構築します。 簡単で信頼できる方法は、単語に含まれる 26 個の小文字のどれをマークすることです。 このステップでは、単語を頻度と順序を無視した構造に圧縮します。 
3. この構造をハッシュ可能な形式に変換します。 実用的なアプローチの 1 つは、アルファベット順に表示されるすべての文字を連結して文字列を構築することです。 これにより、同じセットを持つ 2 つの単語がまったく同じ文字列を生成することが保証されます。 
4. この正規表現をセットに挿入します。 このセットは重複を自動的に削除するため、同じオブジェクトが繰り返し出現しても自然にマージされます。 
5. すべての単語を処理した後、個別のオブジェクトの数に対応するセットのサイズを出力します。 

### なぜ効果があるのか

 核となる不変条件は、すべての単語がその文字セットによってのみ決定される固有の標準形式にマッピングされるということです。 2 つの単語は、まったく同じ文字が含まれている場合にのみ、同じ標準形式にマップされます。 このセットには標準形式のみが格納されるため、すべての等価単語がグループ化され、各等価クラスが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = input().split()

    seen = set()

    for w in words:
        mask = [0] * 26
        for ch in w:
            mask[ord(ch) - 97] = 1

        key = []
        for i in range(26):
            if mask[i]:
                key.append(chr(i + 97))

        seen.add("".join(key))

    print(len(seen))

if __name__ == "__main__":
    solve()
```このソリューションは、1 回のパスですべての単語を読み取り、各単語を 26 個の長さのプレゼンス配列に変換します。 これにより、単語の長さや文字の頻度への依存が回避されます。 アルファベット順の再構成ステップにより、「ab」や「ba」などの順列が同じキーに集約されます。 

よくある実装の落とし穴は、単語の正規化をまったく忘れて、生の文字列をセットに挿入してしまうことです。 これでは、アナグラムが別のものとして誤って扱われてしまいます。 もう 1 つの間違いは、リストをセット内で直接使用することです。これは、リストがハッシュ可能ではないため、Python では無効です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    words = input().split()

    seen = set()

    for w in words:
        mask = [0] * 26
        for ch in w:
            mask[ord(ch) - 97] = 1

        key = []
        for i in range(26):
            if mask[i]:
                key.append(chr(i + 97))

        seen.add("".join(key))

    return str(len(seen))

# provided sample
assert run("5\na aa aaa ab abb") == "2"

# all identical
assert run("3\na aa aaa") == "1"

# all distinct single letters
assert run("3\na b c") == "3"

# permutations
assert run("3\nab ba ab") == "1"

# mixed case
assert run("4\nabc bca aabb cc") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | ああああ | 1 | 繰り返しの崩壊 |
 | a b c | 3 | 独立した一文字オブジェクト |
 | アブ・バ・アブ | 1 | 順列等価性 |

 ## 特殊なケース

 重要な特殊ケースの 1 つは、単語内の極端な繰り返しです。 「aaaaa」のような入力の場合、アルゴリズムはマスク内の 1 文字のみをマークするため、正規キーは「a」になります。 これにより、文字の繰り返しによって表現が膨張することがなくなります。 

もう 1 つの特殊なケースは、多くのアナグラムです。 たとえば、「abc」、「bca」、および「cab」はすべて同じマスクを生成するため、同じキーが生成されます。 すべての順列が同一のソートされた文字表現にマップされるため、このセットはそれらを 1 つのエントリに正しく折りたたみます。 

最後のエッジ ケースは、「a」、「aa」、「aaa」、「aaaa」など、すべての単語の構造は同じだが長さが異なる場合です。 それぞれが同じ正規キー「a」を生成するため、セットには 1 つのエントリだけが残り、正しいカウント 1 が生成されます。
