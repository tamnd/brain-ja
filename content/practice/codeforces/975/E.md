 ## 解決策
 ## 問題の理解

 平面内に固定ジオメトリを持つ厳密に凸状の剛多角形が与えられます。 その頂点には順番にラベルが付けられており、最初はポリゴンはすでに安定した位置に座っています。 頂点のうち 2 つは固定ピンに接続されているため、最初はこれら 2 つの点が平面に固定されています。 

システムは2種類の操作によって進化します。 1 つの操作で頂点からピンを削除し、それを別の頂点に接続しますが、このプロセス中にポリゴンの形状が任意に変更されることはありません。 代わりに、ピンが 1 つだけ残ると、安定した平衡に達するまで、ポリゴンは重力に従ってそのピン留めされた点の周りを自由に回転します。 安定後、別の頂点に新しいピンが取り付けられます。 もう 1 つの操作では、これまでのすべての変換後の特定の頂点の現在の座標を要求します。 

重要な幾何学的効果は、頂点が 1 つだけ固定されている場合は常に、ポリゴンの重心がピボット ポイントの真下に来るまで、そのピボットを中心にポリゴンがしっかりと回転することです。 ポリゴンの密度は均一であるため、質量の中心はその面積重心であり、剛体運動下では変化せず、座標のみが変化します。 

制約は大きく、最大 10,000 個の頂点と 200,000 回の操作があります。 クエリごとにジオメトリを最初から再計算するソリューションは、すぐに失敗します。重心ベースのジオメトリまたは頂点変換を 1 回再計算するだけでも線形時間がかかり、10^9 のオーダーの演算が必要となるためです。 

微妙な問題は、ポリゴンが原点の周りを単純に回転しないことです。 各スタビライゼーションは異なるピボット ポイントを中心に回転し、ポリゴンが変換されるとそのピボット自体がグローバル座標内で移動します。 これは、変換が純粋なグローバル回転ではなく、異なる中心の周りの回転の合成であり、回転と平行移動を組み合わせた一般的な剛体運動のように動作することを意味します。 

回転中心の変更を注意深く考慮しない限り、単一の角度だけを保存する単純なアプローチでは不十分です。 もう 1 つの失敗モードは、変換のたびにグローバル座標でポリゴンの重心を再計算しようとすることで、毎回すべての頂点を変換する必要があります。 

## アプローチ

 ブルートフォースの観点は単純明快です。 すべての頂点座標を明示的に維持します。 ピボットが変更されると、回転をシミュレートします。現在の重心を計算し、ピボットを見つけ、重心がピボットの下に垂直に揃うまでそのピボットを中心にすべての頂点を回転し、すべての座標を更新します。 このような各操作には O(n) のコストがかかり、最大 200,000 回の操作では、2×10^9 座標の更新程度で非常に遅くなります。 

重要な観察は、ポリゴンが決して変形されていないことです。 すべての操作で、形状全体に剛体変換が適用されます。 つまり、各頂点を個別に追跡する必要はありません。 代わりに、元の座標を現在の座標にマッピングする単一のグローバル剛体変換を維持できます。 

平面内の剛体変換は、常に回転とそれに続く平行移動として記述することができます。 すべての原点 x が A x + b になるように回転行列 A と平行移動ベクトル b を維持すると、すべてのクエリに一定時間で答えることができます。 課題は、ピボットの変更後に A と b を効率的に更新することです。 

多角形がピボット p を中心に回転すると、すべての点 x は x' = p + Rδ (x − p) として変換されます。ここで、Rδ は角度 δ による回転です。 これを拡張すると、変換全体が構造化された方法で A と b を更新し、重要なことに、δ を決定するだけでよいことがわかります。

唯一欠けている部分は、δ を迅速に計算する方法です。 安定化条件は、回転後の重心がピボットの垂直下になければならないということです。これは、回転後にピボットから重心へのベクトルの x 成分がゼロになるように強制するのと同じです。 重心とピボットはどちらも現在の変換を使用して表現できるため、頂点を反復することなく、現在の位置からδを直接計算できます。 

これにより、各更新が O(1) に減少しますが、現在のアフィン変換を適用することでクエリも O(1) になります。

 ## アルゴリズムのチュートリアル

 ポリゴンの重心を元の座標系で事前に計算します。 ポリゴンの形状は決して変わらないため、この重心はローカル座標に固定されたままになります。 

回転行列 A と平行移動ベクトル b から構成されるグローバル剛体変換を維持します。 多角形は指定された座標から始まるため、最初は A が単位であり、b はゼロです。 

### 1. 重心を事前計算する

 標準の符号付き面積公式を使用して、多角形の面積重心 C₀ を計算します。 これにより、ポリゴンの固有座標系に固定点が与えられます。 

### 2. 現在の状態をアフィン変換として表現する

 すべての頂点 v が現在の位置 A v + b を持つことを維持します。 これにより、頂点座標を直接保存または変更することが回避されます。 

現在の座標の重心は C = A C₀ + b です。 

### 3. ピボットの変更を処理する

 ピボット頂点が v に変化すると、その現在位置 p = A v + b が計算されます。 これは、ポリゴンが回転する中心となる点です。 

現在の重心位置 C を計算し、ベクトル u = C − p を形成します。 

安定化条件では、p の周りを回転した後、重心が p の真下にあることが必要です。 これは、x 座標が 0 になるまで u を回転させることを意味します。 

u を垂直方向に回転させる角度 δ を計算します。 これは、u 上の atan2 から直接行われます。 

### 4. グローバル変換を更新する

 ピボット p を中心とした回転を使用して前の変換を構成することにより、剛体変換を更新します。 

A ← Rδ A

 b ← p + Rδ (b − p)

 これにより、すべての点がワールド座標のピボットを中心に正しく回転されるようになります。 

### 5. 質問に答える

 クエリ頂点 v の場合、A v + b を返します。 

### なぜ効果があるのか

 いつでも、ポリゴンの状態は、元の構成に適用される剛体モーションによって完全に記述されます。 すべての操作では、この変換ですでに表現されている点の周りの回転が適用されます。 剛体モーションは合成下では閉じられているため、状態は単一の回転と平行移動のペアとして表現可能なままです。 

安定化条件はピボットから重心までの相対ベクトルのみに依存し、変換のアフィン一貫性の下で保存されます。 これにより、現在の変換された位置から δ を計算すると、絶対空間で計算した場合と同じ結果が得られることが保証されます。 したがって、ピボットの繰り返しによって累積誤差やあいまいさが発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def cross(x1, y1, x2, y2):
    return x1 * y2 - y1 * x2

def polygon_centroid(poly):
    # returns area centroid
    area = 0.0
    cx = 0.0
    cy = 0.0
    n = len(poly)
    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        cr = x1 * y2 - x2 * y1
        area += cr
        cx += (x1 + x2) * cr
        cy += (y1 + y2) * cr
    area *= 0.5
    cx /= (6.0 * area)
    cy /= (6.0 * area)
    return cx, cy

n, q = map(int, input().split())
pts = [tuple(map(float, input().split())) for _ in range(n)]

C0 = polygon_centroid(pts)

# affine transform: x -> A x + b
a = 1.0
b = 0.0
c = 0.0
d = 1.0
tx = 0.0
ty = 0.0

def apply(x, y):
    return (a * x + c * y + tx, b * x + d * y + ty)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '2':
        v = int(tmp[1]) - 1
        x, y = apply(pts[v][0], pts[v][1])
        print(f"{x:.10f} {y:.10f}")
    else:
        f = int(tmp[1]) - 1
        t = int(tmp[2]) - 1

        # current pivot is vertex t after removal of f
        px, py = apply(pts[t][0], pts[t][1])
        cx, cy = apply(C0[0], C0[1])

        ux = cx - px
        uy = cy - py

        ang = math.atan2(uy, ux)
        target = math.pi / 2.0

        delta = target - ang

        s = math.sin(delta)
        co = math.cos(delta)

        na = co * a - s * c
        nc = co * c + s * a
        nb = co * b - s * d
        nd = co * d + s * b

        ntx = px + co * (tx - px) - s * (ty - py)
        nty = py + s * (tx - px) + co * (ty - py)

        a, b, c, d, tx, ty = na, nb, nc, nd, ntx, nty
```この実装では、ポリゴン全体が元の座標に保持され、2D 剛体変換のみが操作されます。 線形代数以外の唯一の幾何学的計算は重心であり、これは事前に 1 回計算されます。 

更新ステップでは、既存のアフィン変換を使用して、任意のピボットを中心とした回転を慎重に構成します。 回転は原点の周りではなく、移動するワールド空間の点の周りで行われるため、変換の更新は最も間違いが起こりやすい部分です。

 ## 特殊なケース

 微妙なケースは、重心がピボットの正確に上または下にあるため、回転角度が数値的に 0 または π になる場合です。 その状況では、atan2 は安定した値を返し、δ はアフィン構成を壊さない 0 または π/2 のいずれかの調整になります。 サインとコサインは特別な分岐を行わずにこれらの境界角度を処理するため、変換は引き続き正しく更新されます。 

もう 1 つのケースは、2 つの頂点間でピボット変更が繰り返される場合です。 変換は多くの回転を構成しますが、各更新は現在のアフィン状態と固定された元のジオメトリのみに依存するため、ドリフトや累積エラーが浮動小数点精度の許容誤差を超えて正確さに影響することはありません。 

最後の微妙なケースは、ピボット自体がすでに重心に位置合わせされた点である場合です。 この場合、u にはゼロの x 成分があり、atan2 は垂直方向を返します。 δ はゼロになり、変換は変化せず、すでに安定した構成の物理的挙動と一致します。
