 ## 解決策
 ## 問題の理解

 さまざまな量のベルコーラがすでに入っているマグカップがいくつかあります。 ペットボトルには飲み物も少し残っています。 すべてのマグカップが正確に同じ容量になるように、残りの全量をマグカップに注ぐ必要があります。 

初期金額が`a1, a2, ..., an`そしてボトルの中には`b`、各マグカップに追加の飲み物がどのくらい入るかを決定する必要があります。 添加量は 2 つの条件を同時に満たす必要があります。 まず、追加される合計金額が等しい必要があります`b`。 次に、注いだ後、すべてのマグカップの最終容量が同じでなければなりません。 

制約は非常に小さいです。 マグカップは最大 100 個あり、すべての値は最大 100 です。二次アルゴリズムや三次アルゴリズムでも簡単に制限内に収まります。 課題はパフォーマンスではなく、解決策が存在するかどうかを決定する数学的条件を認識することです。 

重要な観察は、すべてのマグカップが何らかの共通の値で終わる必要があるということです。`x`。 マグカップ用`i`、追加される金額は次のとおりです。$$c_i = x - a_i$$追加される合計金額は次の値に等しくなければなりません`b`、 それで：$$\sum (x - a_i) = b$$これを展開すると次のようになります。$$n \cdot x - \sum a_i = b$$これにより、唯一可能な最終値が即座に決定されます。$$x = \frac{\sum a_i + b}{n}$$一度`x`知られています、あらゆる`c_i`固定されています。 

危険なエッジケースは、マグカップにすでに目標値を超える量が入っている場合です。 その状況では、対応する`c_i`マグカップに飲み物を注ぐことの​​みが許可されており、マグカップを取り出すことはできないため、これは不可能です。 

次の例を考えてみましょう。```
2 1
5 1
```注いだ後の合計金額は、`7`, したがって、ターゲットは次のようになります`3.5`。 最初のマグカップにはすでに入っています`5`よりも大きい`3.5`。 等しいボリュームに達するには、削除する必要があります`1.5`そのマグカップから。 正しい出力は次のとおりです。```
-1
```不用意に実装すると、数式が機械的に計算され、負の値が出力される可能性があります。 

すべてのマグカップがすでに等しい場合、別の微妙なケースが発生します。```
3 6
2 2 2
```ターゲットとなるのは、`4`、したがって、すべてのマグカップは簡単に受け取ります`2`。 出力は次のとおりです。```
2.000000
2.000000
2.000000
```開始値が等しくないことを誤って想定した実装では、この状況が誤って処理される可能性があります。 

3 番目のエッジケースは、ターゲットが部分的になる場合です。```
2 1
1 1
```各マグカップの最終的な量は、`1.5`、各マグカップが受け取ります`0.5`。 ここでは浮動小数点出力が必要です。 

## アプローチ

 ブルートフォース的な考え方では、最終的な共通金額を推測することから始まります。`x`。 すべての候補者に対して`x`、各マグカップに必要な量を計算し、追加された合計量が等しいかどうかを確認できます。`b`。 

すべての値は小さいため、考えられる多くの実数値をある程度の精度で試してみることもできます。 有効なソリューションはいずれも共通の最終ボリュームに対応する必要があるため、このアプローチは論理的に正しいです。 問題は、実数の検索が面倒で不必要なことです。 検索を離散化しても、精度に懸念が生じ、無意味な追加作業が発生します。 

方程式の構造により、より強力なものが得られます。 すべてのマグカップは同じ値で終了する必要があります。つまり、追加されたすべての量は 1 つの変数に直接関連付けられます。`x`。 方程式を合計すると、システム全体が 1 つの式に折りたたまれます。$$x = \frac{\sum a_i + b}{n}$$探す必要はありません。 目標値は総液量保存により一意に決まる。 

わかったら`x`、それぞれの答えは単純に次のとおりです。$$c_i = x - a_i$$残っている唯一の有効性チェックは、`c_i`はマイナスです。 1つでもマイナスの場合は設定できません。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`b`、およびマグカップのボリュームの配列。 
2. 注いだ後に存在する液体の総量を計算します。$$total = \sum a_i + b$$3. 各マグカップの最終的な等容積を計算します。$$x = \frac{total}{n}$$この値は液体の保存によって強制されます。 他のターゲットは条件を満たすことができません。 
4. マグカップごとに、次を計算します。$$c_i = x - a_i$$これはまさに、共通の最終値に到達するために追加する必要がある量です。 
5. ある場合`c_i`ネガです、印刷します`-1`そしてやめてください。 

負の値は、マグカップにすでに目標量を超える量が含まれていることを意味するため、均等化するには液体を除去する必要があります。 
6. それ以外の場合は、次の間隔で印刷します。`c_i`小数点以下少なくとも 6 桁が必要です。 

### なぜ効果があるのか

 このアルゴリズムは保存則に依存しています。 注いだ後の液体の総量は決まっているので、すべてのマグカップが同じ量で終わった場合`x`、その場合、液体の合計は次の値に等しくなければなりません`n * x`。 それは一意に決定されます`x`。 

マグカップごとに追加できる量は次のとおりです。`x - a_i`。 1 つのマグカップの追加量を変更すると、最終的な容量が変更されるため、代替の割り当ては存在しません。`x`。 

すべての計算値が負でない場合、すべてのマグカップを実際に正確な値まで増やすことができます。`x`、追加された合計金額は自動的に等しくなります`b`どうしてかというと`x`導出されました。 いずれかの値が負の場合、注ぐことで液体を減らすことができないため、有効な解決策は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    target = (sum(a) + b) / n

    ans = []

    for value in a:
        add = target - value

        if add < 0:
            print(-1)
            return

        ans.append(add)

    for x in ans:
        print(f"{x:.6f}")

solve()
```最初の部分は入力を読み取り、ターゲットの最終ボリュームを計算します。 この値は、ボトルを空にした後に利用できる液体の総量から直接導出されます。 

このループは、各マグカップにどれだけの量を追加する必要があるかを計算します。 条件`add < 0`実現可能性テスト全体です。 マグカップがすでに目標レベルを超えている場合、液体を追加するだけの操作であるため、状況を修復することはできません。 

回答は保存され、後で印刷されます。 で印刷する`:.6f`出力要件を満たす小数点以下 6 桁以上を保証します。 

微妙な点の 1 つは、ターゲットを計算するときに浮動小数点除算を使用することです。 整数の除算を使用すると、小数点以下の答えが切り捨てられ、次のような場合に不正確な結果が生成されます。`2 1`マグカップ付き`1 1`。

import sys, io

def solve():
    input = sys.stdin.readline

    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    target = (sum(a) + b) / n

    for value in a:
        add = target - value

        if add < 0:
            print(-1)
            return

        ans.append(add)

    for x in ans:
        print(f"{x:.6f}")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue()

 ## 特殊なケース

 不可能な構成を考えてみましょう。```
2 1
5 1
```アルゴリズムは以下を計算します。$$target = (5 + 1 + 1) / 2 = 3.5$$最初のマグカップの場合:$$3.5 - 5 = -1.5$$否定的な結果はすぐにトリガーされます`-1`。 これは正しいです。均一化には最初のマグカップから液体を除去する必要があるからです。 

次に、部分ターゲットを考えてみましょう。```
2 1
1 1
```ターゲットは次のようになります。$$(1 + 1 + 1) / 2 = 1.5$$マグカップは両方とも受け取れます`0.5`。 このアルゴリズムでは浮動小数点除算が使用されるため、整数の切り捨てによって精度が失われることはありません。 

最後に、1 つのマグカップがすでにターゲットと一致している場合を考えてみましょう。```
2 100
0 100
```ターゲットは次のようになります。$$(0 + 100 + 100) / 2 = 100$$追加内容は次のとおりです。$$100 - 0 = 100$$そして$$100 - 100 = 0$$すべてのマグカップに注ぐ必要はなく、ボトル全体を均等な量で分配するだけなので、ゼロが許可されます。
