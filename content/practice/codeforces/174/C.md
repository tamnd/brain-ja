 ## 解決策
 ## 問題の理解

 長さの配列から始めます`n`ゼロで埋められています。 1 回の操作でセグメントを選択します`[l, r]`そして付け加えます`1`そのセグメント内のすべての要素に適用されます。 

最終的な配列が与えられます。 できるだけ少ない操作を使用しながら、正確にその配列を生成する一連の操作を再構築する必要があります。 

重要な詳細は、操作が自由に重複できることです。 1 つのポジションが値で終了した場合`5`の場合、選択した 5 つのセグメントがその位置をカバーする必要があります。 必要な増分が重複する場合、異なるポジションで操作を共有できます。 

制約により、二次関数は直ちに除外されます。 配列の長さが次の値に達しました`10^5`、値も到達します`10^5`。 間隔を繰り返しスキャンしたり、セルごとに増分をシミュレートしたりするソリューションは、簡単に実行できます。`10^10`最悪の場合の運用。 線形または線形に近いものが必要です。 

施工条件もあります。 最小数を要求されるだけでなく、間隔自体を明示的に出力する必要があります。 このステートメントでは、最適な答えには最大でも次のものが含まれることが保証されているため、`10^5`オペレーション、`O(answer)`建設は許容されます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

厳密に増加する配列を考えてみましょう。```
1 2 3 4
```正解は 4 つのセグメントです。```
[1,4]
[2,4]
[3,4]
[4,4]
```新しいインターバルを開かずに古いインターバルを可能な限り延長しようとする不注意な貪欲さは失敗します。`a[i-1]`に`a[i]`追加の間隔を強制的に開始します`i`。 

ここで、値を減らすことを考えてみましょう。```
4 3 2 1
```最適な構築は次のとおりです。```
[1,1]
[1,2]
[1,3]
[1,4]
```ここでは、最初の位置の後に新しい間隔は必要ありません。 代わりに、一部の間隔は単に早く終了します。 すべての間隔を常に最後まで有効に保つ実装では、後の位置がオーバーシュートします。 

もう 1 つの微妙なケースには、配列内にゼロが含まれています。```
2 0 2
```中央のゼロは、左部分と右部分を完全に分離します。 間隔がインデックスを越えることはできません`2`そうでない場合、その位置はプラスになります。 最適解では、4 つの独立した間隔が使用されます。```
[1,1]
[1,1]
[3,3]
[3,3]
```ゼロをまたいで間隔を再利用可能として扱うアプローチでは、無効な配列が生成されます。 

## アプローチ

 強引な視点は、問題の構造を明らかにするのに役立ちます。 

配列を左から右に処理するとします。 位置で`i`、現在アクティブな間隔がどれだけカバーされているかがわかります。 未満の場合`a[i]`インターバルはアクティブです。 から始まる新しいインターバルを開きます。`i`。 アクティブな間隔が多すぎる場合は、到達する前にいくつかの間隔を閉じます。`i`。 

単純な実装では、すべてのアクティブなセグメントを明示的に追跡し、どの間隔を閉じるかを繰り返し検索します。 最悪の場合、これは二次関数になります。 たとえば、次のような交互パターンです。```
1 0 1 0 1 0 ...
```頻繁な間隔の作成と破壊を強制します。 アクティブな間隔でリニア スキャンを繰り返すと、遅すぎて、`10^5`要素。 

重要な観察は、最小演算数が配列の増加によって完全に決定されるということです。 

いつでも：```
a[i] > a[i-1]
```正確に開始する必要があります。```
a[i] - a[i-1]
```位置での新しい間隔`i`。 

これを回避する方法はありません。 既存の間隔はすでに寄与のみを提供します`a[i-1]`ポジションでのカバレッジ`i-1`, したがって、カバレッジをさらに高めるには、`i`、追加の間隔はそこから開始する必要があります。 

逆に、値が減少すると、一部の間隔は現在の位置の前で単純に終了します。 

これにより、問題はインターバル簿記に変換されます。 現在アクティブな間隔はすべて維持されます。 必要な高さが増加すると、新しい間隔が開きます。 減少する場合は、前の位置で十分な間隔を詰めます。 

ここではスタックが完全に機能します。 すべてのアクティブな間隔には、その開始インデックスのみが保存されます。 間隔を終了する必要がある場合は、それをポップして出力します。`[start, current_position - 1]`。 

各間隔は 1 回プッシュされ、1 回ポップされるため、プロセス全体は線形です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のスタックを作成します。 各要素はアクティブな間隔を表し、その開始位置のみを保存します。 
2. 配列を左から右に繰り返します。 
3. 位置で`i`、 比較する`a[i]`アクティブな間隔の数を使用すると、単純に次のようになります。`len(stack)`。 
4. アクティブなインターバルが多すぎる場合は、スタック サイズが小さくなるまでスタックからインターバルを繰り返しポップします。`a[i]`。 

ポップされた各間隔は次のように終了します。`i - 1`、現在の位置に進むことができないためです。 
5. アクティブな間隔が少なすぎる場合は、現在の位置を繰り返し押します`i`スタック サイズが大きくなるまでスタックに追加します。`a[i]`。 

すべての新しい間隔は次から始まります`i`。 
6. すべての位置に対してこのプロセスを続けます。 
7. 配列全体を処理した後、残りのアクティブな間隔はすべて次の位置で終了する必要があります。`n`。 それらをすべてポップし、セグメントを出力します。 

### なぜ効果があるのか

 不変条件は単純です。 

加工後の位置`i`、スタックには位置をカバーする間隔が正確に含まれます`i`。 

したがって、そのサイズは正確に`a[i]`。 

ターゲット値が増加するたびに、現在の位置で初めて追加のカバレッジが表示される必要があるため、新しい間隔は避けられません。 後で開始すると現在のセルをカバーできなくなりますが、早く開始すると前のセルが誤って増加します。 

ターゲット値が減少するたびに、いくつかの間隔が現在の位置の前で停止する必要があります。 アクティブな間隔のサブセットを終了しても同様に機能するため、スタックを使用するだけで十分です。 

新しい間隔は数学的に必要な場合にのみ作成されるため、間隔の総数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []
    ans = []

    for i in range(n):
        pos = i + 1

        while len(stack) > a[i]:
            start = stack.pop()
            ans.append((start, pos - 1))

        while len(stack) < a[i]:
            stack.append(pos)

    while stack:
        start = stack.pop()
        ans.append((start, n))

    print(len(ans))
    print("\n".join(f"{l} {r}" for l, r in ans))

solve()
```スタックには、現在のインデックスを現在カバーしているすべての間隔の開始位置が格納されます。 

必要な高さが低下した場合、間隔は現在の位置より前で終了する必要があります。 すべてのアクティブな間隔は同等であるため、任意の間隔をポップすることができます。 スタックを使用すると、一定時間の挿入と削除が可能になります。 

必要な高さが上昇すると、現在の位置で新しい間隔が開始されます。 各プッシュは 1 つの新しい操作に対応します。 

よくある 1 つ違いの間違いは、インターバルを閉じるときに発生します。 現在の位置にいる場合`i`、削除された間隔は次で終了する必要があります。`i - 1`なぜなら、それらは現在のセルに寄与すべきではないからです。 

もう 1 つの細かい点は、最後のクリーンアップです。 ループ後にアクティブなままのインターバルは、次の位置まで延長する必要があります。`n`。 

このソリューションでは、配列を直接変更することはありません。 各位置でアクティブな間隔の数を維持するだけで、最適な答えを再構築するには十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + k) | 各間隔は 1 回プッシュおよびポップされます。 
| スペース | O(k) | スタックと回答のストレージ |

 ここ`k`最適解の演算数です。 

ステートメントは保証します`k ≤ 10^5`なので、メモリ使用量と実行時間の両方が制限内に快適に収まります。 このアルゴリズムは線形作業のみを実行し、単純なスタック操作を使用します。

import io

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    ans = []

    out = [str(len(ans))]
