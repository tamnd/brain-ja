 ## 解決策
 ## 問題の理解

 次のシーケンスがあります`n`単語はエッセイに登場した順序どおりに書かれています。 単語は、その長さが少なくとも 4 である場合にのみ意味を持ちます。 このようなすべての単語について、最初の出現は許可されますが、その後同じ単語が出現する場合はすべて消去する必要があります。 

出力は、消去する必要がある出現の数と、その後に繰り返される単語が出現する順序で表示されます。 何も消去する必要がない場合、必要な出力は次のとおりです。`SAFO`その代わり。 

重要な違いは、繰り返される単語と繰り返される出来事との違いです。 たとえば、入力に次のものが含まれている場合、`clean clean clean`、その言葉`clean`は 3 回表示されますが、答えに含まれるのは 2 回目と 3 回目のみです。 したがって、出力は次のようになります`2`、続いて 2 つのコピー`clean`。 

この制約により、2 次アプローチは不可能になります。 いくつでもありえます`8 * 10^6`入力単語数、合計文字数も最大です。`8 * 10^6`。 したがって、ソリューションでは、以前のすべての単語を繰り返しスキャンするのではなく、各入力単語を一定の回数だけ処理する必要があります。 合計文字境界は、単語の読み取り、ハッシュ、比較などの操作を、通常のハッシュ コストまでの合計入力サイズに比例させることができるため、特に便利です。 

不注意な実装を黙って破壊してしまう可能性のあるエッジケースがいくつかあります。 まず、4 文字未満の単語は繰り返しルールに参加しません。 例えば、```
3
cat
cat
dog
```問題のルールでは繰り返される単語がないため、出力は次のようになります。```
SAFO
```すべての単語を重複検出構造に挿入するソリューションでは、誤ったレポートが生成されます。`cat`。 

次に、最初に出現した長い単語を出力してはなりません。 のために```
3
clean
bad
clean
```出力は```
1
clean
```最初`clean`は単語が出現したことを確認しますが、2 番目の単語のみを消去する必要があります。 

3 番目に、3 回以上出現する単語は、最初の単語以降に出現するたびに 1 回出力する必要があります。 のために```
4
enough
enough
enough
enough
```出力は```
3
enough
enough
enough
```どの単語が重複しているかを単に記録するだけのソリューションでは、誤って印刷されてしまいます。`enough`一度だけ。 

## アプローチ

 直接的なアプローチは、すべての長い単語をそれ以前のすべての長い単語と比較することです。 処理するときは、`i`-番目のワード、スキャン位置`1`を通して`i-1`同じ単語がすでに出現しているかどうかを確認します。 見つかった場合は、現在の単語を繰り返しとして印刷または記録します。 これは正しいです。入力内のどこかに同じ単語が存在する場合、その単語は正確に繰り返されるからです。 

問題は比較の回数です。 もしすべてなら`n`単語が長くて区別できる場合、アルゴリズムが実行します`0 + 1 + 2 + ... + (n - 1) = n(n - 1)/2`言葉の比較。 と`n = 8 * 10^6`、これについてです`3.2 * 10^13`比較。 たとえ各比較を一定時間として扱ったとしても、それは 2 秒の制限時間をはるかに超えています。 実際の文字列の比較では複数の文字も検査される可能性があり、状況がさらに悪化します。 

より迅速な解決策を明らかにする観察は、以前のどの位置に単語が含まれていたかを知る必要がないということです。 必要な情報は 1 つだけです。この正確な単語が以前に登場したことがありますか? ハッシュ セットはまさにその操作を提供します。 長い単語ごとに、それがすでにセットに含まれているかどうかを確認します。 そうである場合、現在の発生は繰り返し発生しています。 そうでない場合は、それをセットに挿入して、今後の出現が認識されるようにします。 

短い単語は完全に無視してかまいません。 これは単なる最適化ではなく、長さが 4 以上の単語のみが制限の対象となるというルールを直接実装します。 

入力は順番に処理する必要があるため、読み取られた瞬間に繰り返しの発生を検出できます。 最初に繰り返し出現回数を出力する必要があるため、クリーンな実装ではスキャン中に繰り返し単語が記録されます。 入力の合計長は最大でも`8 * 10^6`したがって、繰り返される単語をバイト バッファーに保存することは、すべての個別の単語をセットに保存することに比べてコストがかかりません。 

結果の比較は次のようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 語の比較、文字レベルの比較で最大 O(n²S) | O(nS) | 遅すぎる |
 | ハッシュセット | 予想される合計 O(S) ハッシュおよび入力処理 | 格納された個別のワードと出力バッファの場合は O(S) | 承認済み |

 ここ`S`はすべての入力単語の合計文字数を示します。`S <= 8 * 10^6`。 ハッシュ セット ソリューションの予想される線形境界は、ハッシュ テーブルの通常の平均的な動作を想定しています。 

## アルゴリズムのチュートリアル

 1. 単語の数を読み取り、という空のセットを作成します。`seen`。 このセットには、すでに出現した長い単語が正確に含まれます。 
2.カウンターを作成する`repeated_count`そして出力バイトバッファ。 カウンタは、消去する必要があるオカレンスの数を示しますが、バッファにより、カウンタが判明するまで印刷を延期できます。 
3. 各単語を元の順序で読みます。 行末のみを削除するので、単語自体は変更されません。 
4. 単語が 4 文字未満の場合は、無視してください。 このような単語は何度でも使用でき、決して入力してはなりません`seen`。 
5. 少なくとも 4 つの長さの単語については、それがすでに存在するかどうかを確認します。`seen`。 存在する場合は増分します`repeated_count`そして、この発生を出力バッファに追加します。 最初の重複だけでなく、繰り返されるすべての出現を追加します。 
6. 単語がまだ入っていない場合`seen`、挿入します。 この時点以降、それ以降の等しい単語は繰り返しとして正しく分類されます。 
7. すべての単語が処理されたら、印刷します。`SAFO`もし`repeated_count`はゼロです。 それ以外の場合は、カウントの後にバッファリングされた繰り返し単語を 1 行に 1 つずつ出力します。 

### なぜ効果があるのか

 入力の接頭辞を処理した後、不変条件は次のとおりです。`seen`そのプレフィックスに出現した長さ 4 以上の個別の単語が正確に含まれています。 次の長い単語については、メンバーシップ`seen`したがって、以前の同等の出現があることと同等です。 単語が存在する場合は、現在出現している単語を消去し、回答に追加する必要があります。 存在しない場合は、これが最初の出現であるため、挿入することは正しいことです。 短い単語にはルールが適用されないため、不変条件に影響を与えることはありません。 単語は左から右に処理されるため、報告されるすべての出現は必要な順序で正確に表示され、最初の出現以降のすべての出現は 1 回だけ報告されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    seen = set()
    repeated_count = 0
    repeated = bytearray()

    for _ in range(n):
        word = input().strip()

        if len(word) < 4:
            continue

        if word in seen:
            repeated_count += 1
            repeated.extend(word)
            repeated.append(10)  # '\n'
        else:
            seen.add(word)

    out = sys.stdout.buffer

    if repeated_count == 0:
        out.write(b"SAFO\n")
    else:
        out.write(str(repeated_count).encode())
        out.write(b"\n")
        out.write(repeated)

if __name__ == "__main__":
    solve()
```の`seen`set はアルゴリズムの最初の部分に直接対応します。 Python のセットでは、予期される定数時間のメンバーシップ テストと挿入が行われるため、前の単語をスキャンすることなく、関連するすべての単語を処理できます。 

ソリューションでは、`input = sys.stdin.readline`要求に応じて、より遅い高レベルの入力メカニズムの繰り返し使用を回避します。 単語はセット内の文字列として保持されますが、繰り返された出力は`bytearray`。 バイト バッファーを使用すると、完全な出力用に別の Python 文字列を作成する必要がなくなります。 

操作の順序は重要です。 メンバーシップのチェックは挿入前に行われます。 最初に単語を挿入してからメンバーシップをチェックした場合、すべての長い単語はそれ自体の重複であるように見えます。 正しい順序は、それが見られたかどうかをテストし、見られた場合は報告し、そうでない場合は挿入することです。 

長さチェックには次のものを使用します`< 4`というのは、長さがちょうど 4 の単語が制限を受けるからです。 長さ 3 のワードは無視されます。 

Python には整数オーバーフローの問題はありません。 カウンタは、繰り返し発生の最大可能回数を安全に表すこともできます。 

特別な`SAFO`必要な出力が存在しないため、出力は個別に処理されます。`0`その後に空のリストが続きます。 少なくとも 1 つの繰り返しが存在する場合、最初の行はカウントであり、後続の行には繰り返しが含まれます。

## テストケース```python

import io

def solve():
    n = int(input())

    seen = set()
    repeated_count = 0
    repeated = bytearray()

    for _ in range(n):
        word = input().strip()

        if len(word) < 4:
            continue

        if word in seen:
            repeated_count += 1
            repeated.extend(word.encode())
            repeated.append(10)
        else:
            seen.add(word)

    out = sys.stdout
    if repeated_count == 0:
        out.write("SAFO\n")
    else:
        out.write(str(repeated_count) + "\n")
        out.write(repeated.decode())

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    input = sys.stdin.readline

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = sys.stdin.readline

"""

## 特殊なケース

 短い単語の繰り返しは報告してはなりません。 のために```
3
cat
cat
dog
```両方のコピー`cat`長さは 3 であるため、アルゴリズムは長さのチェックに達し、すぐにそれぞれを無視します。`seen`空のまま、`repeated_count`はゼロのままで、出力は次のようになります。```
SAFO
```これにより、4 文字の制限を適用せずに「繰り返される単語」を解釈するというよくある間違いが見つかります。 

ちょうど 4 文字の単語は、関連する単語として扱われなければなりません。 のために```
2
aaaa
aaaa
```最初`aaaa`に挿入されます`seen`。 2番目のものがそこで見つかり、記録されます。 結果は次のとおりです。```
1
aaaa
```の`< 4`条件により、長さ 3 と長さ 4 の動作が異なります。
