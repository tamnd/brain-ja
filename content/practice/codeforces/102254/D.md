 ## 解決策
 ## 問題の理解

 私たちは持っています`2n`ピザのスライス、スライス`i`サイズがあります`a[i]`。 すべてのスライスを次のように分割する必要があります`n`一人一人に正確に 2 つのスライスを与えます。 一人分の金額は、受け取った 2 つのスライスの合計です。 

目標は、すべての人の金額をできる限り個別に大きくしたり小さくしたりすることではありません。 のセット全体が欲しいです`n`ペアの合計ができるだけ緊密にクラスター化されるようにします。 最小のペアの合計が`L`そして最大のものは`R`、部門の品質は`R - L`。 この差の可能な最小値が必要です。 

制約によって得られるのは最大でも`2 * 10^4`スライスのサイズ、それぞれの大きさ`10^9`。 ペアリングを明示的に調べるアプローチは、分割する方法の数が膨大であるため、完全に実行不可能です。`2n`オブジェクトをペアにすると階乗的に成長します。 スライスの選別は簡単に手頃な価格で行えます。`O(n log n)`したがって、目的のソリューションでは、ペアを列挙するのではなく、スライス サイズの順序を利用する必要があります。 

不注意な実装が失敗する可能性のあるエッジケースがいくつかあります。 と`n = 2`そしてスライス`1 4 3 2`、ソートすると、`1 2 3 4`。 隣接する要素を組み合わせると合計が得られます`3`そして`7`ですが、最適な組み合わせは`1+4`そして`2+3`、答えを与える`0`。 これにより、並べ替えられた隣接する要素がペアになる必要があると仮定したソリューションが捕捉されます。 

重複する値も重要です。 のために`n = 2`そしてスライス`1 1 1 2`、最適なペアリングは次のとおりです。`1+2`そして`1+1`、したがって、答えは次のとおりです`1`。 すべてのスライス サイズが異なることに依存する証明や実装は不必要であり、偶発的に等しい境界を誤って処理する可能性があります。 

最大のスライス値も、縮小せずに整数演算を必要とします。 例えば、`n = 2`そしてスライス`1000000000 1000000000 1 1`ペアの合計を生成する`1000000001`そして`1000000001`、したがって、答えは次のとおりです`0`。 合計額自体は到達可能です`2 * 10^9`、これは Python の整数では安全ですが、固定幅の整数を使用する言語では少なくとも符号付き 32 ビット範囲も必要です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、パーティションを分割するあらゆる可能な方法が列挙されます。`2n`スライスする`n`順序のないペア。 すべての組み合わせについて、すべてを計算できます。`n`ペアの合計を計算し、最大値と最小値の差をとります。 すべての有効な除算が考慮されるため、これは正しいです。 

ペアリング数`2n`明確な立場は

 (2n−1)!!= 2 n n! (2n)! 。 

各ペアリングには次のものが必要です`n`ペアサムの計算なので、総作業量は次のようになります。`O(n(2n-1)!!)`。 のために`n = 10000`、これは 1 秒以内に実行できるものをはるかに超えています。 ペアリングの数も、制約制限に達するずっと前に膨大になります。 

スライスを並べ替えると、有益な観察が得られます。 

a 1 ≤ a 2 ≤⋯≤ a 2n 。 

最小のスライスと最大のスライス、2 番目に小さいスライスと 2 番目に大きいスライスなどを組み合わせる特定の分割について考えてみましょう。 そのペアの合計は

 a 1 +a 2n ,a 2 +a 2n−1 ,…,a n +a n+1 .

 なぜこれが最適である必要があるのでしょうか? キーのプロパティは、このペアが値の「バランスをとっている」と単純に言うよりも強力です。 可能なペアの場合、これらの相補的な合計はすべて、そのペアの最小のペアの合計と最大のペアの合計の間にあります。 

何らかの相補和を仮定します`a_k + a_{2n+1-k}`最大額より大きかった`M`別のペアリングの。 見てください`k`最大のスライス。 それらのどれもが少なくとも価値を持っています`a_{2n+1-k}`。 そのペアの合計は最大で`M`、そのパートナーは厳密に以下より小さくなければなりません`a_k`。 しかし、あるのは`k-1`厳密に小さいスライス`a_k`、一方、`k`最大のスライスが必要`k`異なるパートナー。 それは不可能です。 

同じ議論が反対側からも機能します。 もし`a_k + a_{2n+1-k}`最小合計より小さかった`m`別のペアリングのそれぞれの`k`最小のスライスには、厳密にそれより大きいパートナーが必要です`a_{2n+1-k}`。 のみ`k-1`スライスはその境界値よりも厳密に大きくすることができますが、これも不可能です。 

したがって、すべての相補和は、すべての有効なペアの範囲内に収まります。 したがって、相補的なペアリングの範囲は最小になります。 

ブルート フォースは、考えられるすべてのペアを明示的に考慮するため機能しますが、そのペアの数が非常に多いため失敗します。 順序付け観察により、マッチング問題全体を 1 つのソートと 1 つのスキャンで置き換えることができます。

 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. を読んでください。`2n`スライス サイズを変更し、降順でない順に並べ替えます。 ソートにより、残りの最小スライスと最大スライスに直接アクセスできます。これはまさに最適なペアリングで使用される構造です。 
2.ペアリング`a[i]`と`a[2n - 1 - i]`あらゆる人にとって`i`から`0`を通して`n - 1`。 これらは、ソートされた配列の中心の周りに対称的に配置された 2 つの要素です。 
3. 各ペアについて、その合計を計算します。 これまでに確認された最小のペアの合計と最大のペアの合計を追跡します。 最小値と最大値のみが答えに影響するため、ペアの合計を保存する必要はありません。 
4. 出力`maximum_pair_sum - minimum_pair_sum`。 上記の証明は、これらの対称ペアによって生成される範囲は他の分割の範囲よりも大きくすることはできないため、これが必要最小限であることを示しています。 

なぜそれが機能するのかは不変条件として述べることができます。 並べ替え後、定義します

 c k =ak +a 2n+1−k 。 

ペアの合計が以下にある任意の有効なペアについて`[L,R]`、 毎`c_k`にもあります`[L,R]`。 多少なら`c_k > R`、`k`最大のスライスには必要な`k`より小さい個別のパートナー`a_k`、しかし、ただ`k-1`そのようなスライスが存在します。 多少なら`c_k < L`、`k`最小のスライスに必要なのは`k`～より大きい個別のパートナー`a_{2n+1-k}`、しかし、ただ`k-1`そのようなスライスが存在します。 したがって、対称ペアリングの最小合計と最大合計は両方とも、すべての可能なペアリングの範囲に含まれます。 したがって、その範囲は競合他社の範囲よりも大きくありません。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    a = list(map(int, input().split()))
    a.sort()
    mn = 10**30    mx = -10**30
    for i in range(n):        pair_sum = a[i] + a[2 * n - 1 - i]        mn = min(mn, pair_sum)        mx = max(mx, pair_sum)
    print(mx - mn)

if __name__ == "__main__":    solve()
```入力には正確に次のものが含まれます`2n`整数なので、1 回の呼び出しで配列全体を読み取ることができます。`input()`。 最適なペアリングはスライス サイズの相対的な順序のみに依存するため、配列はソートされます。 

ループはのみ実行されます`n`回。 反復時`i`、`a[i]`です`i`- 番目に小さいスライスと`a[2*n-1-i]`対応するものです`i`- 番目に大きいスライス。 インデックス`2*n-1-i`数学的インデックスと同等のゼロベースの値です`2n+1-(i+1)`。 

変数`mn`そして`mx`ペアごとに更新されます。 ペア合計の可能な範囲をはるかに外れた値で初期化すると、最初の反復での特別な処理が回避されます。 Python の整数には任意の精度があるため、ペアの合計が次の値に達してもオーバーフローのリスクはありません。`2 * 10^9`。 

問題にはテスト ケースが 1 つだけあるため、テスト ケース ループは必要ありません。

 ## 特殊なケース

 最初のエッジケースについては、次のことを考慮してください。```
21 4 3 2
```並べ替えると得られるもの`[1, 2, 3, 4]`。 アルゴリズムのペア`1`と`4`そして`2`と`3`、合計を生成します`5`そして`5`。 したがって`mn = 5`、`mx = 5`、出力は次のようになります`0`。 隣接ペア戦略では、代わりに次の結果が得られます。`3`そして`7`、間違った答えをする`4`。 

重複する値については、次の点を考慮してください。```
21 1 1 2
```ソートされた配列はすでに`[1, 1, 1, 2]`。 対称ペアは和を持ちます`3`そして`2`したがって、アルゴリズムは次のように出力します。`1`。 証明では個別のスライス値ではなく位置を使用するため、等しい値でも特別なインデックス作成の問題は発生しません。 

値が大きい場合は、次のことを考慮してください。```
21 1 1000000000 1000000000
```対称ペアの合計は両方とも`1000000001`。 追跡された最小値と最大値は同一であるため、結果は次のようになります。`0`。 この実装では、すべての算術演算が整数として直接実行され、浮動小数点は使用されません。 

最大入力サイズについては、`n = 10000`そしてすべてを作ります`20000`スライスサイズは以下に等しい`1000000000`。 すべての対称ペアには合計があります`2000000000`、したがって、答えは次のとおりです`0`。 アルゴリズムは配列をソートして実行するだけです。`10000`後でペアチェックを行うため、必要な複雑さの範囲内に快適に収まります。
