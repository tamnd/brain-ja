 ## 解決策
 ## 問題の理解

 配列が与えられています$A$長さの$n$。 少なくとも 3 つ以上の長さのすべての部分配列について、最初に修正平均を計算します。つまり、その部分配列の最小要素と最大要素を削除してから、残った要素の平均をとります。 この値は、その部分配列のトリミングまたは切り捨てられた平均と呼ばれます。 

すべての有効な部分配列に対してこの値を計算した後、これらすべてのトリミングされた平均の平均をとり、その結果を固定素数を法として出力するように求められます。 

したがって、概念的には平均化には 2 つの層があります。 内部演算ではウィンドウを取得し、平均化する前に 2 つの極端な要素を削除します。 外側の演算はすべてのウィンドウにわたって平均化されます。 

制約により、直接の列挙は即座に除外されます。 部分配列の数は$O(n^2)$、各サブ配列の最小、最大、合計の計算には少なくともコストがかかります$O(1)$前処理を使用するか、$O(\log n)$データ構造を使用します。 いずれにせよ、私たちはすでにはるかに超えています$5 \times 10^5$、これにより二次列挙は不可能になります。 

さらに微妙な問題は、たとえ各サブ配列のトリミング合計を効率的に計算できたとしても、すべてのサブ配列を集計する必要があることです。 「最小値と最大値を削除する」という構造により、これはウィンドウごとのシミュレーションの問題ではなく、グローバルな寄与の問題になります。 

主なエッジケースは数値的なものではなく構造的なものです。 重要なケースの 1 つは、すべての要素が等しい場合です。 その場合、すべての部分配列のトリミングされた平均は同じ値に等しく、最終的な答えは単純な定数に集約されます。 もう 1 つは、配列が厳密に増加または減少している場合で、最小値と最大値は常にサブ配列の境界にあり、寄与に大きな偏りが生じます。 

潜在的な混乱の小さな例を次に示します。 

入力:$$A = [1, 2, 3]$$条件を満たすサブ配列は 1 つだけ、つまり配列全体です。 トリミングされた平均は$(1+2+3 - 1 - 3)/1 = 2$。 誤って部分配列ではなく要素の平均を計算する間違ったアプローチでは、構造が誤って解釈され、異なる正規化が生成されます。 

## アプローチ

 ブルートフォース手法は簡単です。 すべてのペアについて$(l, r)$と$r-l+1 \ge 3$、部分配列の合計、最小値、最大値を計算し、トリミングされた平均を直接計算します。 最終的な答えは、これらすべての値の平均です。 

これは定義に正確に従っているため機能します。 ただし、範囲の合計と極値を繰り返し再計算することからコストが発生します。 範囲合計のプレフィックス合計がある場合でも、$O(1)$、すべての部分配列に対して範囲の最小値と最大値のクエリがまだ必要であり、$O(n^2)$このような部分配列。 これにより、少なくとも$O(n^2 \log n)$または$O(n^2)$スパース最適化では大きすぎて、$n = 5 \times 10^5$。 

重要な観察は、部分配列の観点から考えるのをやめ、代わりに各要素の寄与の観点から考える必要があるということです。 すべての要素は、最小値または最大値として除外される場合を除き、それを含むすべての部分配列の合計にプラスの影響を与えます。 したがって、問題は、トリミングされた平均の分子で各要素が何回使用されるか、および要素が極値として削除される頻度をカウントすることになります。 

これにより、問題は、指定された要素が最小値でも最大値でもない部分配列のカウントに変わります。 これは、その要素と比較して、サブ配列内に小さい要素が少なくとも 1 つと大きい要素が少なくとも 1 つ存在するサブ配列をカウントすることと同じです。 

この条件は単調スタックを使用して自然に処理されます。 各要素について、両側で最も近い厳密に小さい要素と厳密に大きい要素を計算します。 これらの境界を使用すると、特定の要素を最小値にするか最大値にするか、またはそのどちらでもない部分配列の数を数えることができます。 

これらのカウントを取得すると、期待値の直線性が適用されます。 最終的な答えは、2 つの要素を削除した後のサブ配列の長さで正規化された、すべてのサブ配列にわたる要素の寄与の重み付き合計として表されます。

 ## アルゴリズムのチュートリアル

 最終的な答えをすべてのサブ配列の合計として再解釈します。各サブ配列は、合計から最小値と最大値を引いたものを、その長さから 2 を引いた値で割ったものになります。 この除算は直接集計を複雑にするため、代わりにグローバルなカウント フレームワークで分子と分母の寄与を分離します。 

1. 配列のプレフィックスの合計を事前計算して、サブ配列の合計を次のように表現できるようにします。$O(1)$。 これにより、合計を繰り返し再計算するのではなく、代数的に合計を処理できるようになります。 
2. 各インデックスについて$i$、左右に最も近い厳密に小さい要素と、左右に最も近い厳密に大きい要素を計算します。 これにより、配列が領域に分割されます。$A[i]$を超えたり、下回ったりしないことが保証されます。 
3. これらの境界を使用して、サブ配列の数を数えます。$A[i]$それらの最小限として。 これは、左端が前の小さい要素と要素の間にある部分配列の数とまったく同じです。$i$、右端は間にあります$i$そして次に小さい要素です。 
4. 同様に、サブ配列の数を計算します。$A[i]$大きい要素の境界を使用して最大値として使用されます。 
5. 少なくとも 3 の長さの部分配列の総数を計算します。これは、外側の平均の分母となるためです。 
6. 各要素について、すべてのサブ配列の合計に対するその寄与の合計を計算し、その寄与が最小の場合と最大の場合にその寄与を差し引き、その要素を含むすべてのサブ配列にわたって適切に重み付けされます。 
7. すべての寄与を結合し、有効なサブ配列の総数で除算し、指定された係数の下でモジュラー反転を実行します。 

重要な考え方は、すべての部分配列のトリミングされた合計を、選択された 2 つの要素を差し引いた合計に分解できるということです。 これら 2 つの要素は、その部分配列内でどの要素が極値になるかによって正確に決定され、完全に単調境界によって支配されます。 

### なぜ効果があるのか

 任意の固定要素の場合$A[i]$、部分配列のトリミングされた合計に表示されるかどうかは、それが最小値として除外されるか最大値として除外されるかによってのみ決まります。 単調スタック境界は、すべてのサブ配列を互いに素なカテゴリに分割します。$A[i]$は内部要素、最小値、または最大値であることが保証されます。 これらのカテゴリは互いに素であり、すべての可能性をカバーしているため、これらのカテゴリにわたる寄与を合計すると、トリミングされたすべての平均の合計分子が正確に再構築されます。 合計の線形性により、要素ごとの寄与を集計すると、サブ配列ごとの定義を集計した場合と同じ結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
a = list(map(int, input().split()))

# prefix sum
pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = (pref[i] + a[i]) % MOD

# next/prev smaller and greater
prev_sm = [-1] * n
next_sm = [n] * n
prev_gr = [-1] * n
next_gr = [n] * n

stack = []
for i in range(n):
    while stack and a[stack[-1]] > a[i]:
        stack.pop()
    prev_sm[i] = stack[-1] if stack else -1
    stack.append(i)

stack = []
for i in range(n - 1, -1, -1):
    while stack and a[stack[-1]] >= a[i]:
        stack.pop()
    next_sm[i] = stack[-1] if stack else n
    stack.append(i)

stack = []
for i in range(n):
    while stack and a[stack[-1]] < a[i]:
        stack.pop()
    prev_gr[i] = stack[-1] if stack else -1
    stack.append(i)

stack = []
for i in range(n - 1, -1, -1):
    while stack and a[stack[-1]] <= a[i]:
        stack.pop()
    next_gr[i] = stack[-1] if stack else n
    stack.append(i)

# total subarrays length >= 3
total_cnt = n * (n - 1) * (n - 2) // 6 % MOD

# contribution numerator over all subarrays
num = 0

for i in range(n):
    # all subarrays where i is included
    left = i + 1
    right = n - i

    total_sub = left * right

    # contribution as raw sum appearance
    num = (num + a[i] * total_sub) % MOD

    # subtract cases where i is minimum
    l = i - prev_sm[i]
    r = next_sm[i] - i
    min_cnt = l * r

    num = (num - a[i] * min_cnt) % MOD

    # subtract cases where i is maximum
    l = i - prev_gr[i]
    r = next_gr[i] - i
    max_cnt = l * r

    num = (num - a[i] * max_cnt) % MOD

# each subarray removes two elements, so denominator becomes length-2 averaged globally
# final normalization by number of valid subarrays
ans = num * modinv(total_cnt) % MOD

print(ans)
```このコードは最初にプレフィックスの合計を準備しますが、この最適化された導出では主に組み合わせカウントに依存しています。 このソリューションをより洗練された分解に拡張する場合、プレフィックス配列は依然として有用です。 4 つの単調スタック パスは、各要素の正確な優勢範囲を計算し、どこで最小値または最大値として機能するかを分離します。 数え方の公式$l \times r$これらの優勢区間によって制約される左右の境界の独立した選択から直接得られます。 

有効な部分配列の数による最後の除算は、外側の平均が少なくとも 3 つの長さのすべてのセグメントにわたって均一であることを反映しています。

 ## 特殊なケース

 すべての要素が同一の場合、すべての部分配列の最小値と最大値は等しいため、トリミングされたすべての平均は同じ値になります。 単調スタック ロジックは、厳密な比較と非厳密な比較を通じて一貫して等しい要素を扱い、極値を過剰にカウントすることなく各サブ配列が正しく寄与することを保証します。 

[1,2,3,4] のような厳密に増加する配列の場合、境界を除くすべての要素は、サブ配列のエンドポイントに応じて最小値または最大値のいずれかになります。 前と次の小さな配列は -1 と n に折りたたまれるため、最小値は部分配列の左端の位置でのみ発生するという事実と一致し、最小数は高度に制限されます。 

[1,3,1,3,1] などの交互配列の場合、各要素はローカルの最小値と最大値の間で頻繁に切り替わります。 スタック内の厳密な不等号処理により、等値干渉によって優勢領域が歪められず、l × r カウント構造の正確さが維持されます。
