 ## 解決策
 ## 問題の理解

 文字 A から Z で構成される「単語」を表す 1 つの大文字の文字列が与えられます。課題は、この単語を一連の化学元素記号に完全に分割できるかどうかを判断することですが、その際に使用するのは制限されたセット (ステートメントで指定されている周期表の最初の 20 個の元素) だけです。 

各元素記号はタイルのように機能します。 一部のタイルは 1 文字の長さです。`B`、`C`、`O`、その他は 2 文字の長さです。`HE`、`NA`、 または`CL`。 目的は、これらの記号を順番に連結することによって、文字を飛ばしたり重複したりすることなく、文字列全体を正確にカバーできるかどうかを確認することです。 

これは文字列に関する古典的なセグメンテーションの問題であり、各セグメントは長さ 1 または 2 の文字列の固定辞書に属している必要があります。 

入力の長さは最大 100 です。これは、DP 遷移ごとに一定量の作業のみを実行するため、位置を越える 2 次動的計画法でも 1 秒の制限内で簡単に十分に高速になるほど十分に小さいです。 

微妙な点は、一部の記号が単一の文字であり、長い記号の接頭辞と重なり合うことです。 例えば、`C`、`CA`、 そして`CL`すべて存在します。 常に 1 つの一致を優先する貪欲なアプローチ (たとえば、常に 1 文字の一致を最初に選択する、または常に 2 文字の一致を優先する) は失敗する可能性があります。 

たとえば、次のような仮想の文字列を考えてみましょう。`CA...`。 貪欲に摂取すれば`C`まず、必要な有効な分解を後でブロックする可能性があります。`CA`その位置で。 これは、ローカルでの選択が安全ではないことを示しています。 

もう 1 つのエッジ ケースは、複数のセグメンテーションが存在するが、有効なフル カバーにつながるのは 1 つだけである場合です。 例えば、`NEON`次のように分割できます`NE O N`または`N E O N`シンボルの可用性によって異なり、一部の選択肢のみが有効です。 

したがって、すべての有効なセグメンテーションを効率的に探索する方法が必要です。 

## アプローチ

 ブルート フォース ソリューションでは、文字列を有効な要素シンボルに分割するためにあらゆる方法が試行されます。 各位置で、1 文字または 2 文字の記号の一致を試み、再帰的に続行します。 これにより、各位置が最大 2 つの選択肢に分岐する再帰ツリーが形成されます。 

最悪の場合、すべてのプレフィックスが有効であるため、再帰パスの数はフィボナッチ スタイルの分岐のように増加し、およそ O(2^n) になります。 n が 100 までの場合、これは完全に不可能です。 

重要な点は、問題の状態は文字列内の現在位置にのみ依存するということです。 インデックス i に到達すると、そこに到達する方法とは関係なく、i 以降のサフィックスを解決できます。 これは標準的な最適な下部構造のプロパティです。 

これは、ポジションに対する動的プログラミングを示唆しています。 dp[i] は、位置 i で始まる部分文字列が、許可された記号を使用して完全にセグメント化できるかどうかを表すものとします。 次に、位置 i からは最大 2 つの遷移のみを試みます。1 文字のシンボル、または有効な場合は 2 文字のシンボルを受け取ります。 各状態は 1 回計算されるため、線形の複雑さが得られます。 

文字列の末尾から dp を逆方向に計算することも、メモ化された再帰を使用することもできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再帰 | O(2^n) | O(n) | 遅すぎる |
 | サフィックス位置上の DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 許可された要素シンボルを前処理して、定数時間のメンバーシップ チェック用のセットにします。 シンボルが 20 個しかないため、オーバーヘッドは無視できます。 

1. dp[i] がインデックス i で始まる部分文字列を完全にセグメント化できるかどうかを示すブール DP 配列を定義します。 また、空のサフィックスは常に有効であるため、 dp[n] = True に設定します。 
2. i を n−1 から 0 まで繰り返します。各位置で、i から始まる有効なシンボルとの一致を試みます。 
3. まず、単一文字の部分文字列 s[i] をチェックします。 許可されたセット内にある場合、dp[i] は dp[i+1] を継承できます。 これは、1 つの要素シンボルを消費することに相当します。 
4. 次に、i+1 < n の場合、2 文字の部分文字列 s[i:i+2] をチェックします。 許可されたセット内にある場合、dp[i] は dp[i+2] を継承できます。 これは、2 文字の要素シンボルを使用することに相当します。 
5. いずれかのオプションが有効な完了につながる場合は、dp[i] = True を設定します。 
6. テーブルに記入すると、答えは dp[0] となり、文字列全体をセグメント化できるかどうかがわかります。 

1 文字と 2 文字のスライスのみをチェックする理由は、問題によりすべてのシンボルの長さが最大 ​​2 に制限されるためです。 

### なぜ効果があるのか

 DP は、i で始まる接尾辞が有効な要素シンボルで完全にカバーできるかどうかを dp[i] が正しく表すという不変条件を維持します。 すべての遷移は、サフィックスの現在のプレフィックスと一致する有効なシンボルを 1 つ選択することに正確に対応し、残りのサフィックスは dp を介して個別にチェックされます。 考えられるすべての有効な最初の選択肢が考慮されるため、有効なセグメンテーションが失われることはなく、有効な辞書一致のみが使用されるため、無効なセグメンテーションが導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

symbols = {
    "H","HE","LI","BE","B","C","N","O","F","NE",
    "NA","MG","AL","SI","P","S","CL","AR","K","CA"
}

def solve():
    s = input().strip()
    n = len(s)

    dp = [False] * (n + 1)
    dp[n] = True

    for i in range(n - 1, -1, -1):
        if s[i:i+1] in symbols and dp[i + 1]:
            dp[i] = True
            continue
        if i + 1 < n and s[i:i+2] in symbols and dp[i + 2]:
            dp[i] = True

    print("YES" if dp[0] else "NO")

if __name__ == "__main__":
    solve()
```コードは DP 定義を直接反映しています。 セット`symbols`許可された要素シンボルの辞書をエンコードします。 DP 配列のサイズが設定されている`n+1`空のサフィックスの基本ケースを自然に処理します。 

チェックの順序は正確さには関係ありませんが、早い段階で`continue`1 文字の一致がすでに成功している場合は、作業がわずかに軽減されます。 両方の遷移は、文字列の末尾での無効なスライスを避けるために、常に境界に対してテストされます。

 | 4 | "" | - | - | 本当 |

### 例 2:`YES`DP を試みます。 

| 私 | s[i:i+2] チェック | dp[i] |
 | --- | --- | --- |
 | 3 | "" | 本当 |
 | 2 | S は記号に含まれておらず、2 文字が一致しません | 偽 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各位置は、最大 2 回の定数時間辞書チェックで 1 回処理されます。 
| スペース | O(n) | サイズ n+1 の DP 配列 |

 制約では長さ 100 までが許可されるため、線形 DP は制限をはるかに下回ります。 より素朴な O(n^2) アプローチでも安全ですが、O(n) はソリューションをクリーンで堅牢に保ちます。

## 特殊なケース

 主なエッジ ケースは、1 文字と 2 文字の両方の記号が同じ位置で有効であるにもかかわらず、正常に完了するのは 1 文字だけである場合です。 たとえば、`CAK`、位置 0 の両方`C`そして`CA`有効です。 選択する`C`につながる`AK`、選択中に失敗します`CA`につながる`K`、成功します。 dp[0] は、貪欲な選択ではなく、dp[1] または dp[2] のいずれかに依存するため、DP は両方の可能性を正しく評価します。 

もう 1 つの特殊なケースは、次のような単一文字の記号だけで構成される文字列です。`BCPC`。 アルゴリズムは 2 文字の一致を必要としないため、これを自然に処理します。 

最後に、有効なプレフィックスで終わるが、一致しないサフィックスが残る文字列。`CLX`、 dp は最終状態 dp[n] = True に到達できないため、最後のステップで失敗します。
