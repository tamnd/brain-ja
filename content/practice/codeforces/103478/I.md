 ## 解決策
 ## 問題の理解

 モジュラー削減による線形漸化によって生成されると主張される整数のシーケンスが与えられます。 シーケンスは既知の値から始まり、固定パラメータを使用して展開します。$a$そして$b$、しかし係数$p$は不明です。 正式には、次の各値は計算によって生成されます。$a \cdot x_{i-1} + b$、剰余を求めます$p$。 

重要なひねりは、$p$直接与えられるものではありません。 代わりに、範囲内のどこかに存在することが知られています。$[1, c]$、タスクは、のどの値を決定することです。$p$観測されたシーケンス全体を生成できた可能性があります。 テスト ケースごとに、そのような値がいくつ存在するかを数え、すべての有効な候補の XOR を計算する必要があります。 

制約は全体として厳しく、テスト ケースにわたるすべてのシーケンスの合計長は最大 100 万です。 これにより、考えられるすべての係数をテストしようとするアプローチが除外されます。$c$、 以来$c$と同じ大きさにすることができます$10^{18}$。 候補モジュラスごとにすべてのシーケンス値を反復処理するだけでも、非常に遅すぎます。 解決策では、検索スペースを、シーケンスの長さではなくシーケンスの長さにのみ依存するものに減らす必要があります。$c$。 

微妙な点は、シーケンス値自体が確実に存在することです。$[0, 10^6]$、 その間$a$そして$b$にも制限されています$10^6$。 これにより、次のような算術式が保証されます。$a x_{i-1} + b$64 ビット整数に快適に適合します。 

1 つの重要なエッジ ケースは、モジュラー リダクションを必要とせずに反復が偶然正確に一致する場合に発生します。 もし$a x_{i-1} + b = x_i$みんなのために$i$の場合、シーケンスは次のように動作します。$p$は「無限」です。これは、十分に大きな係数が機能することを意味します。 たとえば、シーケンスが次の場合、$1, 3, 5$と$a = 1, b = 2$の場合、漸化式は正確に成り立ちます。 その場合、すべての$p > \max x_i$まで$c$有効です。 依然として割り切り条件を強制しようとする単純なアプローチでは、これらのケースが誤って破棄されてしまいます。 

別の失敗例は、遷移のサブセットのみをチェックする場合に発生します。 再発はすべての人に当てはまるはずなので、$i$、トランジションが 1 つでも欠けていると、不正確なモジュライが入り込む可能性があります。 

## アプローチ

 強引なアイデアは、すべてを試してみることです$p \in [1, c]$繰り返しをシミュレートして、シーケンスが再現されるかどうかを確認します。 各シミュレーションの費用$O(n)$、につながる$O(nc)$、次の場合はまったく実行不可能です。$c$到達する$10^{18}$。 

重要な観察は、各遷移がモジュール式制約を課すということです。 から$$x_i \equiv a x_{i-1} + b \pmod p,$$私たちは得ます$$a x_{i-1} + b - x_i \equiv 0 \pmod p.$$これは、すべての有効な係数を意味します$p$フォームのすべての値を除算する必要があります$d_i = a x_{i-1} + b - x_i$。 したがって、すべて有効です$p$すべての最大公約数の約数でなければなりません$d_i$。 

これにより、検索の問題が軽減されます。$c$単一の数の約数を列挙します。 ただし、もう 1 つ制約があります。モジュラー演算には次のものが必要です。$x_i < p$、したがって、私たちも強制する必要があります$p > \max(x_i)$。 gcd のすべての約数を計算した後、この不等式と上限によって単純にフィルターします。$c$。 

gcd が 0 の場合、すべての遷移が満たされることを意味します。$a x_{i-1} + b = x_i$その通り。 この場合、可算性から来る制限はなく、残された唯一の制限は次のとおりです。$p > \max(x_i)$。

 ## アルゴリズムのチュートリアル

 1 つのテスト ケースに焦点を当てます。 

1. シーケンス内の最大値を計算します。 これが必要なのは、有効な係数はすべて、生成されるすべての値より厳密に大きくなければならないためです。 
2. 移行の相違点のリストを作成する$d_i = a x_{i-1} + b - x_i$みんなのために$i \ge 2$。 これらは、モジュール削減を行わない場合、各ステップが正確な一貫性からどの程度離れているかを表します。 
3. コンピューティング$g = \gcd(|d_2|, |d_3|, \dots, |d_n|)$。 これにより、すべての制約が 1 つの分割条件に圧縮されます。 
4. もし$g = 0$、すべてのトランジションが正確に一致する特別なケースとして扱います。 この状況では、すべての整数$p$そのような$\max(x_i) < p \le c$有効です。 この範囲内にある整数の数を数え、プレフィックス XOR 式を使用してそれらの XOR を計算します。 
5. もし$g \ne 0$、の約数をすべて列挙します$g$。 各約数はすべての合同制約を同時に満たすため、係数の候補となります。 
6. 各約数をフィルタリングする$p$チェックすることで$p > \max(x_i)$そして$p \le c$。 これらのみが有効なモジュールです。 
7. すべての有効な値のカウントと XOR の両方を累積します。 

正しさは、すべての有効な係数がすべての遷移の不一致を除算する必要があり、逆に、そのような除数がすべての合同を同時に保持するという事実に依存します。 

### なぜ効果があるのか

 各遷移はモジュラー等式を強制し、これはモジュラスの割り算制約に直接変換されます。 これらすべての制約を交差させると、gcd の約数のセットが正確に得られます。 反復構造により、範囲条件を超えて追加の隠れた制約が存在しないことが保証されます。$x_i < p$。 したがって、範囲条件によって gcd の約数をフィルタリングすると、有効な係数が正確に生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def prefix_xor(n):
    r = n & 3
    if r == 0:
        return n
    if r == 1:
        return 1
    if r == 2:
        return n + 1
    return 0

def range_xor(l, r):
    if l > r:
        return 0
    return prefix_xor(r) ^ prefix_xor(l - 1)

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b, c = map(int, input().split())
        x = list(map(int, input().split()))

        mx = max(x)

        import math
        g = 0

        for i in range(1, n):
            val = a * x[i - 1] + b - x[i]
            g = math.gcd(g, abs(val))

        if g == 0:
            l = mx + 1
            r = c
            if l > r:
                print(0)
                print(0)
                continue
            cnt = r - l + 1
            print(cnt)
            print(range_xor(l, r))
            continue

        divs = set()
        i = 1
        while i * i <= g:
            if g % i == 0:
                divs.add(i)
                divs.add(g // i)
            i += 1

        cnt = 0
        xr = 0

        for d in divs:
            if d > mx and d <= c:
                cnt += 1
                xr ^= d

        print(cnt)
        print(xr)

if __name__ == "__main__":
    solve()
```この実装では、最初にすべての制約が 1 つの gcd 値に圧縮されます。 除数の列挙ステップは唯一の非線形部分ですが、高速なままです。$g$は遷移の差の大きさによって制限されます。 

特別な場合$g = 0$十分に大きな係数はすべて有効であるため、不必要な除数ロジックを回避し、直接区間計算に切り替えます。 

範囲にわたる XOR の処理には注意が必要です。これは、整数の標準プレフィックス XOR パターンを使用して行われます。 

## 実用的な例

 モジュラー効果がなく、反復が完全に一貫しているシーケンスを考えてみましょう。 させて$x = [1, 3, 5]$、$a = 1$、$b = 2$、 そして$c = 10$。 

| 私 | 表現$a x_{i-1} + b$|$x_i$|$d_i$|
 | --- | --- | --- | --- |
 | 2 | 3 | 3 | 0 |
 | 3 | 5 | 5 | 0 |

 ここ$g = 0$、だからすべての$p > 5$最大 10 が有効です。$[6,7,8,9,10]$。 カウントは 5 で、XOR はその間隔で計算されます。 

ここで、自明ではないケースを考えてみましょう$x = [0, 1, 3]$、$a = 2$、$b = 1$。 

| 私 | 式 |$x_i$|$d_i$|
 | --- | --- | --- | --- |
 | 2 | 1 | 1 | 0 |
 | 3 | 3 | 3 | 0 |

 また$g = 0$したがって、十分に大きな係数はすべて有効です。 これは、非線形に見えるシーケンスであっても、同じ制限のないケースに崩壊する可能性があることを示しています。

 ## 特殊なケース

 すべての遷移が満たされるとき$a x_{i-1} + b = x_i$、gcd はゼロに崩壊します。 その場合、アルゴリズムは、最大要素より厳密に大きいすべての整数モジュラスをカウントするように切り替わります。 これにより、未定義となるゼロの約数を列挙しようとすることが回避されます。 

gcd が正であるが小さい場合、すべての約数が明示的に列挙され、上限と比較してチェックされます。$c$。 これにより、非常に大きな$c$値は実行時間には影響しません。 

シーケンスにその最大値が近い値に含まれる場合$c$、有効なセットが空になる可能性があります。 どの除数も上限と同時に最大制約を超えることができないため、アルゴリズムは正しくゼロを返します。
