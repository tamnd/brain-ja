 ## 解決策
 ## 問題の理解

 小文字の英語文字のみを含む空ではない文字列が 1 つ与えられます。 タスクは、より高い頻度を持つ文字が結果の最初に来るように文字を再配置することです。 2 つの文字が同じ頻度で出現する場合は、アルファベット順で小さい文字が最初に来る必要があります。 元の文字列のすべての出現箇所は出力に残る必要があるため、文字の順序のみを変更します。 

たとえば、次の文字列`dcbbdabb`4つ入っています`b`キャラクター、2人`d`キャラクター、1`a`、そして1つ`c`。 したがって、周波数は次のように並べられます。`b`、`d`、 それから`a`そして`c`、 と`a`前に`c`それらの周波数が等しいからです。 必要な結果は次のとおりです`bbbbddac`。 元の問題では入力文字列が小文字 70 文字に制限されており、Codeforces バージョンには 1 秒の時間制限と 256 MB のメモリ制限があります。 

70 という小さい境界は、O(n²) ソリューションでも最大 4900 個の基本文字比較を実行することを意味するため、単純な実装はすでに十分に高速です。 それでも、問題の構造により、固定量の追加作業を伴う O(n) 解が得られます。 重要なのは、使用できる文字は 26 文字のみであるため、任意の値のコレクションを検出したり並べ替えたりする必要がないということです。 

実装で間違った順序が生成される可能性のある特殊なケースがいくつかあります。 次のようにすべての文字が異なる場合`abc`、すべての周波数は 1 つであるため、アルファベット順がすべてを決定し、出力は次のようになります。`abc`。 タイ ブレーカーを適用する代わりに元の順序を保持するソリューションは、次のような入力では失敗します。`cba`、その正しい出力は`abc`。 

アルファベット内で区切られた文字間で同じ頻度が発生することもあります。 のために`programming`、周波数は`g=2`、`m=2`、およびその中のすべての文字`a`、`i`、`n`、`o`、`p`、`r`が一度発生します。 正しい出力は次のとおりです`ggmmainopr`各周波数グループ内で文字が正しく順序付けされている場合に限りますが、実際のサンプル出力は次のようになります。`ggmmrrainop`なぜなら`r`2回も発生します。 したがって、完全な周波数順序は次のようになります。`g`、`m`、`r`、 に続く`a`、`i`、`n`、`o`、`p`、与える`ggmmrrainop`。 一部の出現のみをカウントしたり、タイに元の文字順序を使用したりする不用意な実装は、ここで失敗します。 

もう 1 つの境界ケースは、次のような異なる文字を 1 つだけ含む文字列です。`aaaaa`。 頻度は 5 で、競合するキャラクターがいないため、答えは残ります。`aaaaa`。 実装により、オカレンスごとに 1 つのコピーではなく、個別の文字ごとに 1 つの出力コピーが誤って作成されると、間違った長さが生成されます。 

## アプローチ

 直接的な総当たりソリューションでは、各文字を個別に処理できます。 入力文字列内のすべての位置について、文字列全体をスキャンし、その文字が出現する回数を数えます。 各文字の頻度を取得したら、頻度の降順とアルファベットの昇順で文字を並べ替え、各文字を頻度の数だけ書き込みます。 最終的な順序付けが実行される前に、すべての文字に正確なグローバル頻度が割り当てられるため、これは正しいことです。 

入力の長さが n で、位置ごとにすべての n 位置を個別にスキャンする場合、周波数カウント フェーズは O(n²) 個の文字チェックを実行します。 実際の制約 n ≤ 70 では、最悪の場合でも 70² = 4900 回のチェックしか行われないため、この総当りバージョンは依然として容易に受け入れられます。 公式制約では現実的なパフォーマンスの問題はありません。 ただし、同じ方法を n = 100000 に適用すると、10^10 チェックが必要となり、1 秒のコンテスト プログラムで処理できる量をはるかに超えます。 

より良い解決策をシンプルにする観察は、すべての文字が 26 のみの小文字カテゴリの 1 つに属するということです。 長さ 26 の配列を使用すると、1 回のパスですべての周波数をカウントできます。これらのカウントがわかったら、次はアルファベットを検査するだけで済みます。`a`を通して`z`。 頻度によって主な順序が決定されるため、26 文字を収集し、それらのペアを次の基準で並べ替えることができます。`(-frequency, character)`。 26 は定数であるため、この並べ替えステップには入力長に対して一定の時間がかかります。 

2 つのアプローチの主な違いは、実行される繰り返し作業の量です。 ブルートフォース手法では、保存されている可能性のある周波数を繰り返し再発見しますが、最適手法では各周波数を 1 回記録してから、固定されたアルファベットに作用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(26) | n ≤ 70 の場合は受け入れられます |
 | 最適 | O(n + 26 log 26) = O(n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 単一の入力文字列を読み取り、長さ 26 の周波数配列を作成します。`0`を表します`a`、 索引`1`を表します`b`、などを通じて`z`。 入力アルファベットは事前にわかっているため、固定配列で十分です。 
2. 文字列内のすべての文字をスキャンし、対応する頻度を増加させます。 キャラクターの場合`ch`、その配列位置は`ord(ch) - ord('a')`。 このパスの後、周波数配列には、答えを作成するために必要な完全な情報が含まれます。 
3. 小文字のアルファベットの 26 個の文字と頻度のペアを作成します。 頻度がゼロの文字は、出力に何も寄与しないため、一時的にコレクションに残すことができます。 
4. 頻度を減少させ、頻度が等しい場合には特徴を増加させることによってペアを並べ替えます。 Python では、これはキーを使用して直接表現できます。`(-frequency, character)`。 負の周波数は通常の数値の昇順を逆転させますが、文字は通常のアルファベット順のままです。 
5. 各文字をその頻度に従って繰り返して答えを作成します。 頻度がゼロの文字は当然空の文字列となるため、頻度がゼロのエントリを含めても結果は変わりません。 
6. 結果の文字列をスペースなしで出力します。 元のオカレンスはすべて 1 回だけ出力されるため、出力の長さは入力とまったく同じになります。 

### なぜ効果があるのか

 カウントパスの後、不変条件は次のとおりです。`freq[i]`インデックスで表される文字の正確な出現数に等しい`i`入力で。 頻度を減らすことによって文字と頻度のペアを並べ替えると、すべての文字が頻度の低いすべての文字の前に配置されます。 頻度が等しいペアの場合、二次キーは文字そのものであるため、アルファベット順に表示されます。 最後に、各文字を正確に繰り返します`freq[i]`回は、入力からのすべての出現を保存します。 したがって、結果の文字列は両方の順序付け規則を満たし、元の文字のマルチセットが正確に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    freq = [0] * 26

    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    chars = []
    for i in range(26):
        ch = chr(ord('a') + i)
        chars.append((ch, freq[i]))

    chars.sort(key=lambda item: (-item[1], item[0]))

    ans = []
    for ch, count in chars:
        ans.append(ch * count)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```この問題には複数のテスト ケースではなく 1 つの文字列が含まれているため、最初の部分は 1 行で表示されます。 電話をかける`strip()`入力には小文字のみが含まれるため、有効な入力文字を変更せずに末尾の改行を削除します。 

周波数配列のインデックスは次のとおりです。`ord(ch) - ord('a')`。 例えば、`ord('a') - ord('a')`ゼロであり、`ord('z') - ord('a')`は 25 であるため、考えられるすべての入力文字は有効な配列位置にマップされます。 

ペアのリストには、文字とその数が格納されます。 並べ替えキー`(-item[1], item[0])`両方の必要なルールを 1 つの式で実装します。 最初のコンポーネントは大きい周波数を最初に配置し、2 番目のコンポーネントは同じ周波数の文字をアルファベット順に配置します。 

答えは文字列を繰り返し連結するのではなく、リストに蓄積されます。 次のような各乗算`ch * count`1 つの文字のすべてのコピーを作成し、`''.join(ans)`ピースを一度結合します。 個数も26個しかないので簡単で効率的です。 

Python では整数オーバーフローの懸念はありません。 最大周波数は入力の長さのみであり、元の制約では最大 70 です。

import io

def solve():

    freq = [0] * 26

    for ch in s:

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out

    try:
        solve()
        return out.getvalue()
    finally:

        sys.stdout = old_stdout
        input = old_input

# Boundary-sized input, 70 characters

 ## 特殊なケース

 単一文字の場合`z`は、インデックス 25 で 1 つの出現をカウントすることによって処理されます。他の頻度はすべて 0 であるため、場所を並べ替えます。`z`まず、出力構造は 1 つだけを出力します。`z`。 結果は`z`。 

次のようなすべてが等しい文字列の場合、`aaaaa`、周波数配列には以下が含まれます`freq[a] = 5`それ以外の場所ではゼロです。 ソートされたペアは、`a`まず、唯一の正の周波数があり、構造が放射するためです。`a * 5`、生産`aaaaa`。 文字が失われたり重複したりすることはありません。 

ネクタイケース`cba`二次順序付けルールを適用します。 3 つの文字はすべて頻度 1 を持っているため、頻度によって区別されません。 ソートされたキーは次のとおりです。`(−1, a)`、`(−1, b)`、 そして`(−1, c)`、与える`abc`。 入力順序に依存する実装では、誤って返される可能性があります。`cba`。 

最大サイズのケースには、頻度 35、20、10、および 5 の 70 文字が含まれています。カウント パスではこれら 4 つの頻度が記録され、ソート フェーズで文字が頻度の降順に配置され、再構築によって 70 文字すべてが再度生成されます。 頻度配列のサイズは 26 に固定されているため、入力を 1 文字から最大サイズに増やしても、カウント作業のみが変更され、補助メモリは変更されません。 

マルチプルタイケース`zzzyyxxwwvvvuu`もっている`z=3`、`v=3`、`y=2`、`x=2`、`w=2`、 そして`u=2`。 2 つの頻度 3 文字は次のように順序付けされます。`v`、`z`、頻度 2 の文字は次のように順序付けされます。`u`、`w`、`x`、`y`。 その結果、アルゴリズムは次のように生成します。`vvvzzzuuwwxxyy`。 このケースでは、アルファベット順がすべての周波数グループ内で独立して適用されていることを直接確認します。
