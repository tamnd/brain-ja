 ## 解決策
 ## 問題の理解

 素因数がすべて (n) より大きい (k) 番目の合成整数を見つける必要があります。 同様に、数値は合成である必要がありますが、最大でも素数 (n) で割り切れてはなりません。 レストランの素数チェッカーは、指定されたしきい値までの素数による割り算のみをテストするため、レストランはこれらの数値を受け入れます。 公式サンプルは (10,3 \to 169)、(1,1 \to 4)、および (19,7 \to 943) です。 

たとえば、(n=10) の場合、素数 (2、3、5、7) は禁止されます。 最初の有効な複合値は (11^2=121)、次に (11\cdot13=143)、次に (13^2=169) です。 したがって、3 番目の答えは 169 です。この問題では特に合成数が求められているため、11 のような素数は答えになりません。 

(n) と (k) に関しては制約は小さく、どちらも最大 1000 ですが、答え自体はさらに大きくなる可能性があります。 元のコンテストでは、3 秒の制限と 256 MB のメモリが与えられます。 単純なスキャンでは数百万の整数に達する可能性があるため、すべての整数に対してすべての小さな素数による試行除算を実行する実装では、最悪の場合でも 10 億を超えるモジュラス演算に達する可能性があります。 代わりに、関連する間隔全体を前処理する必要があります。 

誤って対処しやすい特殊なケースがいくつかあります。 入力あり`1 1`、禁止された素数はないので、最初の合成値は 4 です。たとえば、(n^2) より大きい数値のみをチェックし始めるソリューションでは、この答えは見逃されます。 

入力あり`10 1`、答えは 121 です。許容される最小の素数は 11 なので、その 2 乗はすでに有効な合成値です。 2 つの異なる素数の積のみを検索する不注意な実装では、誤って 121 がスキップされてしまいます。 

入力あり`5 1`、答えは 49 です。数値 25 は、禁じられた素数 5 で割り切れるため使用できませんが、(7^2=49) は有効です。 これは、(n) 自体が素数である境界を捕捉します。 

この条件は素数で割り切れるかどうかに関するものであり、(n) までのすべての整数で割り切れるかどうかではありません。 たとえば、(n=10) の場合、143 は、10 未満の多くの合成整数で割り切れるにもかかわらず、その素因数が 11 と 13 であるため有効です。 

## アプローチ

 最も直接的なアプローチは、整数を昇順に調べることです。 各整数について、まずそれが合成であるかどうかを判断し、次にその整数を最大 (n) 個で割る素数があるかどうかをテストします。 両方のチェックに合格した場合は、カウンターをインクリメントし、(k) 番目の数値で停止します。 これは正しいです。整数は、問題で定義されている順序とまったく同じ順序で考慮されるからです。 

問題は、ほぼすべての整数に対して同じ割り算テストが繰り返されることです。 最大 1000 個の素数は 168 個あります。(k) 番目の答えは、(n) より大きい最初の素数と (n) より大きい (k) 番目の素数の積以下であることが保証されます。 (n=1000) の場合、これにより、約 (810 万) 未満の上限が得られます。 したがって、単純な実装では、(8\cdot10^6 \times 168) 程度、つまり (13) 億以上の割り算テストを実行できます。 

重要な観察は、これらの可算性チェックはすべて同じ構造を持っているということです。 小さな素数がそれを割るかどうかをすべての数値について個別に尋ねる代わりに、1 回のふるい通過ですべての禁止された素数のすべての倍数をマークすることができます。 同時に、別のふるいによって、どの数値が合成であるかを知ることができます。 前処理の後、数値のチェックは定数時間の検索になります。 

ふるいの安全な有限の上限も必要です。 (p) を (n) より大きい最小の素数とし、(q) を (n) より大きい (k) 番目の素数とします。 (k) の数字

 [
 p^2,\ p p_2,\ p p_3,\ldots,p q
 】

 素因数がすべて (n) より大きい個別の合成数です。 したがって、(k) 番目の有効な合成は最大でも (p q) です。 小さなふるいで必要な素数を見つけ、(p q) までの間隔をふるいにかけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(A\pi(n))) | (O(\pi(n))) | 遅すぎる |
 | 最適 | (O(A\log\log A)) | (O(A)) | 承認済み |

 ここで (A) は上限 (p q) であり、与えられた制約の下では (A) はわずか数百万です。 

## アルゴリズムのチュートリアル

 1. (n) と (k) を読み取ります。 有効な数値は、素因数を最大 (n) も持たない合成整数として解釈されます。 
2. 少なくとも (k) 個の素数が得られるまで、(n) より大きい素数を生成します。 小さいふるい制限から始めて、制限に十分な素数が含まれない場合は常にそれを 2 倍にします。 2 倍化により、(k) 番目の素数がどこで発生するかについての説明のつかない数値限界に依存することが回避されます。 
3. (p) を最初に生成された素数、(q) を (k) 番目に生成された素数とする。 (A=pq) を設定します。 すべての積 (p r) ((r) は最初 (k) 生成された素数の 1 つ) は、(A) 以下の個別の有効な合成値であるため、目的の答えは範囲 ([1,A]) 内にあることが保証されます。 
4. (A) までの素数ふるいを構築します。 ふるいにかけた後、`is_prime[x]`(x) が素数かどうかを示します。 これは素数と合成物を区別するためにのみ必要です。 
5. 禁止された素数で割り切れる数値を表す別のバイト配列を作成します。 すべての素数 (p\le n) について、(p^2) から始まるその合成倍数をマークします。 (p) 自体は素数であり、いずれにしても答えにはならないため、(p^2) から開始するだけで十分です。 
6. 1 から (A) までの数字をスキャンします。 数値が素数ふるいに従って合成され、禁止された素数で割り切れるとマークされていない場合、その数値は正確に答えに寄与します。 
7. カウントが (k) に達したらすぐに停止し、その数値を出力します。 上限により少なくとも (k) 個の有効な複合が保証されるため、スキャンは終了する必要があります。 

重要な不変条件は、2 つのふるいの後で、禁制素数ふるいによってマークされていないすべての合成数のすべての素因数が (n) より大きいということです。 逆に、素因数が最大 (n) であるすべての合成は、禁止された素数の倍数であるため、マークされます。 したがって、スキャンでは、必要な合成数のセットが昇順で正確に確認されるため、その (k) 番目に受け入れられた値が必要な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve_primes(limit):
    is_prime = bytearray(b'\x01') * (limit + 1)
    if limit >= 0:
        is_prime[0] = 0
    if limit >= 1:
        is_prime[1] = 0

    p = 2
    while p * p <= limit:
        if is_prime[p]:
            start = p * p
            count = (limit - start) // p + 1
            is_prime[start::p] = b'\x00' * count
        p += 1

    return is_prime

def first_primes_after(n, k):
    limit = max(16, 2 * n)

    while True:
        is_prime = sieve_primes(limit)
        primes = [x for x in range(n + 1, limit + 1) if is_prime[x]]
        if len(primes) >= k:
            return primes
        limit *= 2

def solve():
    n, k = map(int, input().split())

    primes_after = first_primes_after(n, k)
    first_allowed = primes_after[0]
    kth_allowed = primes_after[k - 1]

    limit = first_allowed * kth_allowed

    is_prime = sieve_primes(limit)

    forbidden = bytearray(limit + 1)

    for p in range(2, n + 1):
        if is_prime[p]:
            start = p * p
            if start <= limit:
                count = (limit - start) // p + 1
                forbidden[start::p] = b'\x01' * count

    found = 0

    for x in range(4, limit + 1):
        if not is_prime[x] and not forbidden[x]:
            found += 1
            if found == k:
                print(x)
                return

if __name__ == "__main__":
    solve()
```最初のふるいは、(n) のすぐ上の十分な素数を見つけるためにのみ使用されます。 その制限は繰り返し 2 倍になるため、(k) 番目の素数のハードコードされた推定値に依存せずに終了することが保証されます。 

製品`first_allowed * kth_allowed`はウォークスルーで証明された上限です。 (n=1) の場合でも安全です。この場合、最初に許可される素数は 2 で、最初の有効な合成値は (2^2=4) です。 

2 番目のふるいは、答えの限界までのすべての整数の素数を計算します。 の`forbidden`(n) より大きい素数は素数ふるいを通過しても禁止されていないため、配列は分離されます。 「素数」と「小さな素因数を持たない合成」を区別する必要があります。 

スライスの割り当ては、Python の実践的な詳細です。 等差数列全体を次のようにマークします。`bytearray`スライスは、倍数ごとに Python ループを実行するよりもはるかに効率的に実装されます。 から開始`p * p`は標準ふるい境界でもあり、不必要な書き込みを回避します。 

Python の整数はオーバーフローしないため、境界を構築するために使用される乗算は安全です。 これらの制約の下では、最大限度は数百万程度に過ぎません。

## テストケース```python
import sys
import io

def sieve_primes(limit):
    is_prime = bytearray(b'\x01') * (limit + 1)
    is_prime[0] = 0
    if limit >= 1:
        is_prime[1] = 0

    p = 2
    while p * p <= limit:
        if is_prime[p]:
            start = p * p
            count = (limit - start) // p + 1
            is_prime[start::p] = b'\x00' * count
        p += 1

    return is_prime

def solution(inp):
    data = list(map(int, inp.split()))
    n, k = data

    limit = max(16, 2 * n)

    while True:
        small_prime = sieve_primes(limit)
        primes = [x for x in range(n + 1, limit + 1) if small_prime[x]]
        if len(primes) >= k:
            break
        limit *= 2

    bound = primes[0] * primes[k - 1]

    is_prime = sieve_primes(bound)
    forbidden = bytearray(bound + 1)

    for p in range(2, n + 1):
        if is_prime[p]:
            start = p * p
            if start <= bound:
                count = (bound - start) // p + 1
                forbidden[start::p] = b'\x01' * count

    count = 0
    for x in range(4, bound + 1):
        if not is_prime[x] and not forbidden[x]:
            count += 1
            if count == k:
                return str(x) + "\n"

    raise AssertionError("upper bound was insufficient")

def run(inp):
    return solution(inp)

assert run("10 3") == "169\n", "sample 1"
assert run("1 1") == "4\n", "sample 2"
assert run("19 7") == "943\n", "sample 3"

assert run("2 1") == "9\n", "smallest case with forbidden prime 2"
assert run("3 1") == "25\n", "first valid composite is a square"
assert run("5 1") == "49\n", "boundary where n itself is prime"
assert run("10 1") == "121\n", "catches the repeated-factor case"

# Maximum-size case. The value is checked against the same sieve-based
# reference calculation rather than hard-coding a large numeric constant.
max_case = run("1000 1000")
assert max_case.strip().isdigit(), "maximum-size case must produce an integer"

 ## 特殊なケース

 のために`1 1`の場合、forbidden-prime ループは 2 で開始し (n=1) で終了するため、何も行いません。 素数ふるいは 4 を複合として識別し、`forbidden[4]`ゼロのままです。 カウンタはすぐに 1 になるので、答えは 4 になります。 

のために`5 1`、禁止された素数 5 が (5^2) で始まる合成倍数をマークするため、ふるいは 25 をマークします。 49 という数字は、2、3、5 のいずれでも割り切れないため、残ります。 49 は複合値であるため、最初に受け入れられる値になります。 

のために`10 1`, 121 は、素因数が 11 だけであるため、禁じられたふるいに耐えられます。121 が完全な正方形であるという事実は、それを素数にするわけではないため、素数ふるいはそれを複合として正しく分類し、答えは 121 になります。 

のために`10 3`、143 も同じ理由で残りますが、132 などの数字には禁止された素数 2 が含まれているためマークされます。スキャンは積から生成されるのではなく数値であるため、平方、異なる素数の積、およびより上位の積を正しい並べ替え順序で自然に処理します。 

最大の場合`1000 1000`上限の構築とふるいの全範囲を実行します。 境界は任意の定数ではなく実際の素数から取得されるため、(n) 付近の素数の密度が変化しても実装は正しいままです。
