 ## 問題の理解

 ゲームボードは、`n`正方形。 正方形`1`を通して`n - 1`次のような色があります`RED`または、次のようなユニークな特別な正方形`SPECIALCANE`。 四角`n`は仕上げの正方形であり、すべての色を一度に表します。 プレイヤーはスクエアの前から開始します`1`。 

がある`p`プレイヤーとデッキを含む`c`カード。 各ターンで、次のプレイヤーがデッキの一番上から次のカードを受け取ります。 使用後、そのカードは一番下に置かれるため、デッキは循環的に繰り返されます。 プレイヤーの順序も周期的に繰り返されます。 最初に正方形に到達したプレイヤー`n`勝ちます。 公式声明では、ゲームが 10,000 ターン未満で終了することが保証されています。 

A型`1`カードには 1 つの色が含まれています。 プレーヤーは、その色を持つ現在の位置の直後に最初の正方形に移動します。 そのような通常の正方形がない場合は、すべての色が含まれているため、終了正方形に到達します。 

A型`2`カードには 1 つの色が 2 回含まれています。 プレーヤーは、現在の位置の直後にその色の 2 番目の出現位置に移動します。 終了マスはすべての色の出現としてカウントされるため、前方に通常の出現が 1 つしかない場合でも、プレーヤーは勝つことができます。 

A型`3`カードは特別なスクエアに名前を付けます。 プレイヤーは、現在位置の前か後ろかに関係なく、そのマスに直接移動します。 特別なマスはユニークなので、目的地は明確です。 

制約は意図的に小さくなっています。 ボードには最大 200 の正方形があり、デッキには最大 500 枚のカードがあり、ゲームの持続時間は 10,000 ターン未満です。 すべてのカラー カードについてボード全体をスキャンする実装でも、最大で約 2,000,000 平方チェックが実行されます。 これは、3 秒の制限と 256 MB のメモリ制限内で簡単に管理できます。

## アプローチ

 最も直接的な解決策は、説明どおりにゲームをシミュレートすることです。 すべてのプレイヤーに対して 1 つのポジションを保持し、次のカードのインデックスを保持し、誰かが最後のマスに到達するまでターンを処理します。 タイプの場合`1`または入力してください`2`カラー カード、ボードを前方にスキャンし、一致する色を数えます。 タイプの場合`3`カードで、名前付きの特別な正方形を検索し、その位置を直接割り当てます。 

この総当たりシミュレーションはすでに十分に高速です。 最悪の場合、ターンは 10,000 未満であり、各ターンで 199 の通常の正方形すべてが検査される可能性があるため、ボード チェックは 1,990,000 未満になります。 したがって、ブルートフォースアプローチは、指定された制約の下では実際には遅くなりすぎることはありません。 

シミュレーションをよりクリーンにする便利な最適化がまだあります。 各色について、その色を含むボード位置のソート済みリストを前処理します。 最後の正方形を追加します`n`最後の四角形がすべての色を表すため、すべての色のリストに追加されます。 それからタイプ`1`カードはプレーヤーの現在位置より大きい最初に保存された位置を要求しますが、タイプ`2`カードは 2 番目の位置を要求します。 二分探索では、最初の位置が直接検索されます。 

この最適化の背後にある観察は、ボードが決して変更されないということです。 すべてのクエリは同じ静的な質問、つまり、特定の色の出現が特定の位置の後に来るかどうかを尋ねます。 出現リストを事前計算すると、この静的な情報が、プレイヤーの現在位置のみであるゲームの動的な部分から分離されます。 

特別なマスは、名前からボードの位置まで辞書に保存できます。 それらの名前は一意であるため、これにより一定時間の検索が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Tn) | O(n + c + p) | 承認済み |
 | 最適 | O(n + c + T log n) | O(n + c) | 承認済み |

 ここ`T < 10000`ターン数です。 最適なバージョンが望ましいのは、その複雑さが各手が固定ボードに対するクエリであるという事実を直接反映しているためです。 

## アルゴリズムのチュートリアル

 1. ボードを読み、その位置に番号を付けます。`1`を通して`n`。 入力は位置のみを記述します`1`を通して`n - 1`、位置を維持しながら`n`マルチカラー仕上げのスクエアです。 
2. 辞書を作成する`color_positions`。 位置にあるすべての通常の色の正方形に対して`i`、追加`i`その色のリストに。 ボードを読んだ後、追加します`n`すべてのカラーリストへ。 終了正方形はすべての色の出現として機能するため、含める必要があります。 
3. 辞書を作成する`special_positions`掲示板を読みながら。 正方形が次から始まる場合`SPECIAL`、完全な名前とその位置を保存します。 
4. デックを読み取り、各カードをそのタイプとターゲット文字列として保存します。 使用したカードが前から後ろに移動するだけなので、デッキ自体の順序が変わることはありません。 したがって、向きを変える`t`いつもカードを使っている`(t mod c)`。 
5. すべてのプレーヤーの位置を次のように初期化します。`0`。 ターン中のプレイヤー`t`は`(t mod p)`。 どちらのインデックスも内部的には 0 から始まりますが、最後に出力されるプレイヤー番号は 1 から始まります。 
6. タイプの場合`3`カードを使用して、現在のプレーヤーの位置を保存された特別な正方形の位置に置き換えます。 特別なカードは名前付きマスに直接移動するため、前方検索は必要ありません。 
7. タイプの場合`1`カラーカード、使用`bisect_right`色の位置リストで、プレーヤーの現在の位置より厳密に大きい最初の位置を見つけます。 そのポジションをプレーヤーに割り当てます。 
8. タイプについて`2`カラー カードの場合は、同じ二分検索を実行しますが、出現リストの 1 つ後の位置の要素を取得します。 仕上げ四角形はすべてのカラー リストに追加されているため、必要な場合には当然 2 番目に表示されます。 
9. カードを適用した後、プレイヤーの位置が正しいかどうかを確認します。`n`。 そうであれば、そのプレイヤーの 1 から始まる番号をすぐに印刷します。 最初のプレイヤーがフィニッシュに到達した時点でゲームは終了します。 
10. ターンを進めて繰り返します。 ゲームが 10,000 ターン以内に終了するという入力保証は、サイクル検出メカニズムが必要ないことを意味します。 

機能する理由: 各ターンの前に、各プレイヤーが保存した位置が、ゲーム内での実際の位置とまったく同じになります。 特別なカードの場合、辞書はカードによって名付けられた固有のマス目を正確に示します。 カラー カードの場合、出現リストには、最後の多色の正方形を含む、着地できるその色を持つすべての正方形が含まれます。 二分検索では、カード ルールに正確に一致して、現在位置の後に厳密に最初または 2 番目に出現するものが選択されます。 プレイヤーとデッキはゲームと同じ順序で循環的に進められるため、シミュレートされたすべてのターンは実際のゲームと一致します。 最初のシミュレートされた位置は以下に等しい`n`したがって、実際の勝者になります。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())

    color_positions = {}
    special_positions = {}

    for pos in range(1, n):
        cell = input().strip()

        if cell.startswith("SPECIAL"):
            special_positions[cell] = pos
        else:
            color_positions.setdefault(cell, []).append(pos)

    # The final square is an occurrence of every color.
    for positions in color_positions.values():
        positions.append(n)

    c = int(input())
    deck = []

    for _ in range(c):
        typ, target = input().split()
        deck.append((int(typ), target))

    player_pos = [0] * p

    turn = 0

    while True:
        player = turn % p
        typ, target = deck[turn % c]
        current = player_pos[player]

        if typ == 3:
            player_pos[player] = special_positions[target]
        else:
            positions = color_positions[target]
            idx = bisect_right(positions, current)

            if typ == 1:
                player_pos[player] = positions[idx]
            else:
                player_pos[player] = positions[idx + 1]

        if player_pos[player] == n:
            print(player + 1)
            return

        turn += 1

if __name__ == "__main__":
    solve()
```最初の前処理ループは、`SPECIAL`接頭語。 このステートメントでは、どの色にもその部分文字列が含まれていないことが保証されるため、これは安全です。 

カラーリストには、最初は通常のボード位置のみが含まれています。 追加中`n`その後が重要な実装の詳細です。 これにより、「一致する正方形が 1 つだけ残っているため、型が`2`二分探索はそのケースを自然に処理します。`bisect_right(positions, current)`それも意図的です。 カードは常に、現在のマスそのものではなく、プレイヤーの現在のマスの後のマスを要求します。 プレイヤーがすでに要求された色のマス目に立っている場合、そのマス目は移動にカウントされません。 

タイプの場合`1`カード、`positions[idx]`プレーヤーの後に最初に一致する正方形です。 タイプの場合`2`カード、`positions[idx + 1]`2 番目に一致する正方形です。 この問題は、フィニッシュマスが必要な最終出現を提供するため、ゲームルールが要求された手を有効にすることを保証します。 

プレーヤーインデックスは以下を使用します`turn % p`、カードインデックスでは`turn % c`。 これら 2 つのサイクルは独立しています。 ターン終了時にのみデッキインデックスを進めることは、使用したカードをデッキの一番下に移動することと同じです。 

Python の整数には任意の精度があるため、オーバーフローの心配はありません。 最大回転数も少ないのでサイクル加速の必要がありません。
