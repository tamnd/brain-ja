 ## 解決策
 ## 問題の理解

 すべての項がちょうど (D) 有効数字に丸められた後、等比数列の目に見える項が与えられます。 元のシーケンスの形式は次のとおりです。 

[
 a_i=a_0r^i、
 】

 ここで、(a_0>0) は最初の項、(r>0) は公比です。 丸めによって情報が破壊されるため、タスクは正確な元のシーケンスを復元することではありません。 代わりに、(a_0) と (r) の可能な限り厳しい下限と上限が必要です。 必要な出力には、(a_0) の (D+3) 有効桁と (r) の (D+5) 有効桁を含む、これら 4 つの境界が含まれます。 公式の制約では、(1<D<6) が同等の (0<D<6)、(1<N<200) に置き換えられており、観測されたすべての項は厳密に (10^{-8}) と (10^8) の間にあります。 公式声明とサンプルは、これらの制限と必要な出力精度を確認しています。 

中心的な観察は、すべての丸められた値が、考えられる元の値の間隔に対応しているということです。 たとえば、(D=4) の場合、表示される値 (1335) は、(1334.5) から (1335.5) までのすべての数値を表し、上限として解釈されます。 より一般的には、表示される値が (x) で、その最後の有効数字の桁の値が (u) の場合、元の値は (x-u/2) と (x+u/2) の間にあります。 

(N) の値が小さいことが決定的です。 (N<200) であるため、インデックスのペアは (200^2/2=20,000) よりも少なくなります。 (O(N^2)) 解では数万回の浮動小数点演算のみが実行されますが、これはこの問題で規定されている 4 秒の制限内に十分収まります。 (O(N^3)) メソッドは、最悪の場合でもすでに約 800 万回のペア-トリプル演算を実行することになりますが、微細な 2 次元グリッドに対する数値検索ははるかにコストがかかり、精度の制御も困難になります。 

丸められた数値を正確な値として扱うと、誤った結果が生じる特殊なケースがいくつかあります。 (D=1) で可能な最小のシーケンスを考えてみましょう。```
1 2
1 1
```正しい境界はおおよそ次のとおりです。```
0.9500 1.050 0.904762 1.10526
```表示される各 (1) は間隔 ([0.95,1.05)) を表すためです。 単純に (a_0=1) と (r=1) を取る解では、有効な元のシーケンスの範囲全体が失われます。 

2 番目の問題は、大きさの桁が変わるときに発生します。 例えば、```
3 2
999
1000
```値 (999) の丸め単位は (1) ですが、値 (1000) の丸め単位は (10) です。 それらの間隔は ([998.5,999.5)) および ([995,1005))] です。 丸め誤差に常に同じ小数点以下の桁数を使用する不注意な実装では、これらの項の少なくとも 1 つについて間違った間隔が生成されます。 

3 番目のエッジ ケースは、項がすべて等しいシーケンスです。```
2 3
5.0 5.0 5.0
```比率は正確に (1) である必要はありません。 (r) をわずかに増減しても、元の 3 つの項すべてを丸め範囲内に維持できるため、その範囲は約 (0.980198) から (1.020202) になります。 表示された値が等しいため (r=1) と仮定すると、有効な可能性が捨てられます。 

## アプローチ

 真に単純な数値アプローチでは、(a_0) と (r) の候補値を試し、幾何学的シーケンス全体を生成し、生成されたすべての項が対応する丸め間隔内に収まるかどうかを確認します。 これは概念的には正しいです。候補ペアは、生成されたすべての用語が有効である場合にのみ有効となるからです。 問題は、(a_0) と (r) が実数であるため、総当たりグリッドには自然な有限解像度が存在しないことです。 要求された精度を得るには、各軸に沿って 100 万個の候補があったとしても、約 (10^{12}) 回のチェックが必要になり、答えはグリッド点の間にある可能性があります。 

有益な観察は、(a_0) と (r) を直接検索する必要がないということです。 配列位置の各ペアは、(r) に直接の制限を与えます。 

項 (i) が ([L_i,U_i]) にあり、項 (j) (i<j) が ([L_j,U_j]) にあるとします。 以来

 [
 L_i\le a_0r^i\le U_i
 】

 そして

 [
 L_j\le a_0r^j\le U_j,
 】

 後の項の下限と前の項の上限を組み合わせることができます。 

[
 L_j\le a_0r^j\le U_i r^{j-i}。 
】

 したがって、

 [
 r^{j-i}\ge \frac{L_j}{U_i},
 】

 それで

 [
 r\ge\left(\frac{L_j}{U_i}\right)^{1/(j-i)}。 
】

 同様に、後の項の上限と前の項の下限を組み合わせると、次のようになります。 

[
 r\le\left(\frac{U_j}{L_i}\right)^{1/(j-i)}。 
】

 各項のペアは、(r) の下限と上限を 1 つずつ提供します。 すべての下限の最大値とすべての上限の最小値を取得すると、(r) の正確な実行可能な間隔が得られます。 

(r) の 2 つの極値がわかれば、(a_0) は簡単になります。 固定 (r) の場合、各項は次のようになります。 

[
 \frac{L_i}{r^i}\le a_0\le\frac{U_i}{r^i}。 
】

 したがって、

 [
 a_0\ge\max_i\frac{L_i}{r^i}
 】

 そして

 [
 a_0\le\min_i\frac{U_i}{r^i}。 
】

 可能な最小 (a_0) は可能な最大 (r) で発生し、可能な最大 (a_0) は可能な最小 (r) で発生します。 これは、(r) が増加してもすべての式 (L_i/r^i) および (U_i/r^i) が増加しないためです。 

結果として得られるメソッドは、実際の制約 (N<200) に対してすでに十分に最適化されています。 すべてのペアを 1 回チェックし、さらに 1 回の線形スキャンを実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 数値総当たり | グリッドの解像度に応じて、潜在的に (O(G^2N)) | (O(N)) | 遅すぎて精度に敏感 |
 | ペアごとの間隔制約 | (O(N^2)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 丸められたすべての入力値を、可能な元の値の範囲に変換します。 最後の有効数字が位の値 (u) を表す場合、(L_i=x_i-u/2) と (U_i=x_i+u/2) を格納します。 この問題では厳しい境界が求められるため、制限された答えを計算するときにエンドポイント値自体が使用されます。 
2. (r) の下限をゼロに初期化し、上限を無限大に初期化します。 すべてのペア (i<j) について、計算します。 

[
 \left(\frac{L_j}{U_i}\right)^{1/(j-i)}
 】

 それを使用して (r) の下限を強化します。 計算する

 [
 \left(\frac{U_j}{L_i}\right)^{1/(j-i)}
 】

 そしてそれを使って上限を強化します。 

1. すべてのペアが処理された後、結果として得られる値は、実行可能な最小および最大の比率になります。 すべての有効な幾何学的シーケンスは、すべてのペアごとの制限を満たさなければなりませんが、これらの制限の交差部分は、元の間隔をすべて同時に実行可能にするのに十分です。 
2. 最大比率 (r_{\max}) を使用して、可能な最小値 (a_0) を計算します。 すべての用語をスキャンして計算します

 [
 \max_i\frac{L_i}{r_{\max}^i}。 
】

 (r_{\max}) を使用する理由は、(r) を増やすと、(a_0) の要件が低くなるほど減少するためです。 

1. 最小比率 (r_{\min}) を使用して、可能な最大値 (a_0) を計算します。 すべての用語をスキャンして計算します

 [
 \min_i\frac{U_i}{r_{\min}^i}。 
】

その理由は対称的です。(r) を増加しても (a_0) のすべての上限を減少させることしかできないため、最大の上限は (r_{\min}) で発生します。 

1. 2 つの (a_0) 値を (D+3) 有効数字でフォーマットし、2 つの比率値を (D+5) 有効数字でフォーマットします。 科学表記法は許可されていないため、Python が指数を使用する場合、書式設定ヘルパーはそれを通常の 10 進数表記に変換します。 

### なぜ効果があるのか

 不変条件は、インデックス ペアのコレクションを処理した後、(r) に対して維持される間隔には、それらの処理されたペアを満たす可能性のあるすべての比率が正確に含まれるということです。 各ペアは、2 つの対応する丸め間隔から直接、必要な下限と上限を導き出します。 すべてのペアが処理された後、位置のすべてのペアは結果の比率区間と互換性があります。(r) が固定されると、(a_0) のすべての制約は単に同じ実線上の区間になるため、これで十分です。 最終スキャンはこれらの間隔と交差します。 (r) が増加すると (a_0) の下位要件が減少し、(r) が増加すると上位要件も減少するため、最小値 (a_0) は (r_{\max}) で取得され、最大値 (a_0) は (r_{\min}) で取得されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def decimal_exponent(s):
    s = s.strip()
    if '.' in s:
        left, right = s.split('.')
    else:
        left, right = s, ''

    left = left.lstrip('0')

    if left:
        return len(left) - 1

    for i, ch in enumerate(right):
        if ch != '0':
            return -(i + 1)

    return 0

def interval(s, d):
    x = float(s)
    e = decimal_exponent(s)

    # Place value of the D-th significant digit.
    unit = 10.0 ** (e - d + 1)
    half = unit * 0.5

    return x - half, x + half

def fixed_from_scientific(s):
    if 'e' not in s and 'E' not in s:
        return s

    mantissa, exponent = s.lower().split('e')
    exponent = int(exponent)

    sign = ''
    if mantissa.startswith('-'):
        sign = '-'
        mantissa = mantissa[1:]

    if '.' in mantissa:
        whole, frac = mantissa.split('.')
        digits = whole + frac
        decimal_pos = len(whole)
    else:
        digits = mantissa
        decimal_pos = len(mantissa)

    decimal_pos += exponent

    if decimal_pos <= 0:
        result = '0.' + '0' * (-decimal_pos) + digits
    elif decimal_pos >= len(digits):
        result = digits + '0' * (decimal_pos - len(digits))
    else:
        result = digits[:decimal_pos] + '.' + digits[decimal_pos:]

    return sign + result

def format_sig(x, digits):
    # x is always positive in this problem.
    s = format(x, f'.{digits}g')
    return fixed_from_scientific(s)

def solve(data):
    tokens = data.split()
    it = iter(tokens)

    d = int(next(it))
    n = int(next(it))

    low = [0.0] * n
    high = [0.0] * n

    for i in range(n):
        low[i], high[i] = interval(next(it), d)

    r_min = 0.0
    r_max = float('inf')

    # Every pair of terms gives a necessary restriction on r.
    for i in range(n):
        for j in range(i + 1, n):
            dist = j - i

            lower_r = (low[j] / high[i]) ** (1.0 / dist)
            upper_r = (high[j] / low[i]) ** (1.0 / dist)

            if lower_r > r_min:
                r_min = lower_r
            if upper_r < r_max:
                r_max = upper_r

    # Minimum a0 occurs at maximum r.
    rpow = 1.0
    a0_min = 0.0
    for i in range(n):
        if i > 0:
            rpow *= r_max
        candidate = low[i] / rpow
        if candidate > a0_min:
            a0_min = candidate

    # Maximum a0 occurs at minimum r.
    rpow = 1.0
    a0_max = float('inf')
    for i in range(n):
        if i > 0:
            rpow *= r_min
        candidate = high[i] / rpow
        if candidate < a0_max:
            a0_max = candidate

    ans = [
        format_sig(a0_min, d + 3),
        format_sig(a0_max, d + 3),
        format_sig(r_min, d + 5),
        format_sig(r_max, d + 5),
    ]

    return ' '.join(ans)

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data))

if __name__ == "__main__":
    main()
```の`decimal_exponent`関数は、入力文字列から最初の有効数字の大きさを直接決定します。 これにより、`log10`入力がちょうど 10 のべき乗の場合、小さな浮動小数点誤差により間違った丸め単位が選択される可能性があります。 

の`interval`関数は、その指数を使用して最後の有効数字の位の値を見つけます。 たとえば、(D=3) の場合、`999`には指数 (2) があるため、丸め単位は (10^{2-3+1}=1) になります。`1000`指数 (3) があり、単位は (10) になります。 これは、固定 10 進数の実装が誤って処理する可能性がある境界ケースです。 

ネストされたループは、ペアごとの導出を直接実装します。 2 つのシーケンス位置は (r) の (j-i) 乗で区切られており、必ずしも 1 乗ではないため、指数 (1/(j-i)) は必須です。 

2 つの最後のスキャンでは、意図的に異なる比率のエンドポイントが使用されます。 最小値 (a_0) については、`r_max`が使用されます。 最大値 (a_0) については、`r_min`が使用されます。 これら 2 つの選択肢を逆にすることは、不正解の一般的な原因です。 

Python の整数はオーバーフローせず、この問題のすべての数値は非常に狭い浮動小数点範囲内に収まります。 また、このステートメントは、公式解では中間計算で有効桁数が 13 桁以下であることを保証するため、要求された出力精度には倍精度演算で十分です。 

書式設定ヘルパーは、Python の有効数字書式設定を使用し、科学表記を標準 10 進表記に変換します。 これにより、次のような末尾のゼロが保持されます。`180.0500`そして`1.0106650`これが重要なのは、ステートメントでは出力が有効数字の表現規則に従うことが明示的に要求されているためです。

 ## 特殊なケース

 最小サイズの場合```
1 2
1 1
```各項は ([0.95,1.05)) を表します。 唯一のペアが与えるもの

 [
 r_{\min}=\frac{0.95}{1.05}=\frac{19}{21}、
 \qquad
 r_{\max}=\frac{1.05}{0.95}=\frac{21}{19}。 
】

 (r_{\max}) では、最初の項の可能な最小値は (0.95) です。 (r_{\min}) では、考えられる最大の第 1 項は (1.05) です。 その結果、アルゴリズムは次のように生成します。```
0.9500 1.050 0.904762 1.10526
```(N=2) については特別な処理は必要ありません。 

すべてが等しい場合```
2 3
5.0 5.0 5.0
```各項の間隔は ([4.95,5.05)) です。 隣接するペアは次のようになります。 

[
 r_{\min}=\frac{4.95}{5.05}\およそ0.980198、
 \qquad
 r_{\max}=\frac{5.05}{4.95}\約1.020202。 
】

 後の項では、より厳しい制限は生じません。 最大比率では、下位制約は (a_0=4.95) で交差し、最小比率では、上位制約は (a_0=5.05) で交差します。 アルゴリズムは正しく出力します```
4.9500 5.0500 0.9801980 1.020202
```間違って比率を (1) に強制するのではなく、

 マグニチュード境界について```
3 2
999 1000
```最初の項には丸め単位 (1) があり、([998.5,999.5)) になります。 2 番目には丸め単位 (10) があり、([995,1005)) になります。 したがって、このペアは次のようになります。 

[
 r_{\min}=\frac{995}{999.5}\およそ0.99549775
 】

 そして

 [
 r_{\max}=\frac{1005}{998.5}\約1.0065098。 
】

 結果として得られる第 1 項の境界は、正確に (998.5) と (999.5) です。 この場合、実装では文字列ベースの指数計算が実行されます。そのため、コードは小数点以下の桁を繰り返し数えることによって丸め単位を決定しません。 

最大サイズの場合は、199 部コピーします。`1.0000`(D=5) の場合。 すべての項には間隔 ([0.99995,1.00005)] があります。 ペアワイズ ループは (199\cdot198/2=19,701) ペアを処理しますが、これはまだ小さいです。 すべての間隔が同一であるため、最も狭い比率の範囲は隣接する位置から得られます。 

[
 r_{\min}=\frac{0.99995}{1.00005}
 】

 そして

 [
 r_{\max}=\frac{1.00005}{0.99995}。 
】

 2 つの最後のスキャンにより、(a_0) の対応する境界が回復されます。 これにより、アルゴリズムを変更することなく、実装が許容される最大値 (N) に直接拡張されることが確認されます。
