 ## 解決策
 ## 問題の理解

 都市は最大 30 行 30 列の長方形のグリッドです。 ボニーはある独房からスタートし、クライドは別の独房からスタートし、逃走車は 3 番目の独房からスタートします。 一部の細胞がブロックされています。 各人は一度に 1 つのセルを 4 つの基本方向に移動します。 

珍しい制限は、通過可能なすべてのセルを 2 人が一緒に使用できるのは最大 1 回だけであるということです。 ボニーが独房を通り抜けた場合、クライドはその後その独房に入ることができなくなり、その逆も同様です。 彼らの開始セルも他の人には禁止されています。 最終的には両方の人が車に到達する必要があり、目的は移動回数の合計を最小限に抑えることです。 有効なルートのペアが存在しない場合、答えは次のようになります。`-1`。 UCF の公式声明では、これらのグリッドの寸法と単一使用セルのルールが確認されています。 

グリッドには最大 (30 \times 30 = 900) 個のセルが含まれます。 これは、およそ数千のエッジを持つ明示的なグラフを構築するには十分小さいですが、すでに訪問したセルのセットを含む状態としては十分な大きさとは言えません。 両方の人の完全なルートに対する単純な検索には指数関数的に多くの可能性があるため、セルのサブセットや徹底的なパス列挙に基づく解決策は実行できません。 

厄介なケースは、2 つのルート間の相互作用によって引き起こされます。 独立して考慮されたボニーの最短経路とクライドの最短経路は、たとえそのペアが違法であっても、セルを共有することができます。 例えば、```
3 3
B.F
...
.C.
```個々の最短ルートはどちらも中間エリアの使用を希望しているため、通常の BFS 距離を 2 つ加算するだけでは、必ずしも正当なルートのペアが生成されるわけではありません。 

2 番目のエッジ ケースは、他の人が 2 つの開始セルに入ることができない場合です。 例えば、```
2 3
BCF
...
```正しい答えは、`3`：ボニーは直接移動できます`(1,1)`に`(1,3)`クライドは 2 つの動きで`(1,2)`に`(1,3)`一度の動きで。 すべてのセル容量を与えるだけの不注意な頂点非結合パス モデルでも、2 つの開始点への入力エッジが明示的に禁止されていない限り、フローが他のルートに属する開始セルに入ることができます。 

3 番目のエッジケースは、両方の人が車に乗車することを許可されている場合です。 例えば、```
2 2
BF
C.
```答えは`2`。 ボニーには 1 つの移動が必要で、クライドには 1 つの移動が必要で、どちらのパスも同じセルで終わります。 車の容量を与えると、これは不可能であると誤って宣言することになります。 

## アプローチ

 ブルートフォースアプローチは、ボニーから車までの可能な単純なパスと、クライドから車までの可能な単純なパスを列挙することです。 すべてのペアについて、2 つのパスが内部的に素であるかどうかをチェックし、それらの長さの最小合計を維持します。 これは正しいです。なぜなら、すべての法的解決策はまさにそのようなパスのペアであるからです。 

問題は単純なパスの数です。 (V) 個の使用可能なセルを持つグリッドでは、単純なパスの数が (V) で指数関数的に増加する可能性があるため、それらを列挙するには、密集したグリッド領域で (2^{\Theta(V)}) 以上の作業が必要になります。 (V=900) では、これは実際の運用予算をはるかに超えています。 訪問セルを明示的に表す検索でも、最大 (2^{900}) 個の可能な訪問セットが存在します。 

重要な点は、制限は実際には 2 人の移動順序に関するものではないということです。 最後の 2 つのルートは、どちらも車両で終了できることを除いて、セルを共有してはいけないとだけ書かれています。 グラフの用語では、エッジの総数を最小限に抑えるために、2 つの開始頂点から 1 つの共通の目的地までの 2 つの頂点に共通のパスが必要です。 

それはまさに、頂点容量を備えたフロー ネットワークが表すものです。 すべてのグリッド セルを 1 つに分割します。`in`頂点と`out`頂点。 からのエッジ`in`に`out`の容量は 1 です。これは、最大 1 つのルートがセルを使用できることを意味します。 あるセルから隣接するセルへの移動は、最初のセルのエッジになります。`out`2 番目のセルの頂点`in`頂点。 すべての移動には 1 コストがかかるため、すべての移動エッジにコスト 1 を与えます。 

次に、ボニーとクライドに接続されたスーパー ソースを追加します。各エッジに 1 つの容量があり、車に到達するには 2 ユニットの流量が必要です。 二人ともそこでゴールできるため、車の定員は2名です。 最小コスト フローは、まさに最小の合計移動数です。 

すべての法的答えは 2 つのパスで説明できるため、ブルート フォースは機能しますが、そのようなパスが指数関数的に多数あるため失敗します。 セルの使用量が単に容量の制約であるという観察により、実際の検索履歴を忘れて、最小コストのフロー インスタンスとして問題全体を解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (rc) の指数 | 最悪の場合の (rc) の指数 | 遅すぎる |
 | 最適 | (O(VE)) 2 つの SPFA 増強 | (O(V+E)) | 承認済み |

 ここで、(V=O(rc)) および (E=O(rc)) です。 必要な流量値の 2 の係数は一定です。 

## アルゴリズムのチュートリアル

 1. グリッドを読み、ボニー、クライド、車を見つけます。 すべての非`x`セルがグラフの頂点になります。 
2. 使用可能なすべてのセル (v) を 2 つのグラフ頂点に分割します。`vin`そして`vout`。 エッジを追加する`vin -> vout`容量は 1、コストは 0 です。 このエッジはそのセルの使用を表すため、その容量によって使い捨てルールが適用されます。 
3. 隣接する使用可能なセル (u) と (v) のペアごとに、エッジを追加します。`uout -> vin`容量は 1、コストは 1 です。 このエッジの横断は 1 つのグリッドの移動に相当するため、合計フロー コストは正確に合計移動数になります。 
4. ボニーの開始セルまたはクライドの開始セルに入る移動エッジを追加しないでください。 それらのセルに入る唯一の方法は、それら自身のソース エッジです。 これは、どちらの人も相手の開始位置に移動できないというルールを直接モデル化しています。 
5. スーパーソースを追加する`S`それをボニーに接続します`in`頂点とクライドの`in`容量 1、コスト 0 の頂点。 2台のユニットを送信します`S`1 つのユニットを各開始セルから強制的に開始します。 
6. 車を渡す`in -> out`エッジ容量は 2 です。 両方の人が車で終了する必要があるため、これが両方の流れで使用できる唯一の通常のセルです。 
7. 2 つのユニットが車両に到達するか、拡張パスが存在しなくなるまで、最小コスト フローを実行します。 必要なフローは 2 つだけであるため、多くても 2 つの拡張を実行します。 
8. 2 つのフロー単位が送信された場合、その最小合計コストを出力します。 それ以外の場合は印刷します`-1`というのは、2 人のうち少なくとも 1 人をセル共有の制限に違反せずに車に誘導することはできないからです。 

### なぜ効果があるのか

 フローのすべての単位は、1 つの開始セルから車両までのルートに対応します。 容量-1`in -> out`すべての通常のセルのエッジにより、2 つのルートがそのセルを使用できないため、ルートは頂点に共通点がなくなります。 開始セルの端により、どちらのルートも他の人の開始位置に入ることができなくなります。 この車両の定員は 2 名で、両方のルートがそこで終了することができます。 

逆に、ルートのすべての正当なペアは、グリッドのエッジをたどることによって 2 つのフロー単位に変換できます。 ルートは通常のセルを共有しないため、すべての容量制約が尊重されます。 各グリッドの移動は正確に 1 単位のコストに寄与するため、フロー コストは 2 つのルートの長さの合計に等しくなります。 したがって、フロー コストを最小限に抑えることは、まさに元の最適化問題です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

INF = 10**9

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        self.g[u].append([v, cap, cost, len(self.g[v])])
        self.g[v].append([u, 0, -cost, len(self.g[u]) - 1])

    def min_cost_flow(self, s, t, required):
        flow = 0
        cost = 0

        while flow < required:
            dist = [INF] * self.n
            prev_v = [-1] * self.n
            prev_e = [-1] * self.n
            in_queue = [False] * self.n

            dist[s] = 0
            q = deque([s])
            in_queue[s] = True

            while q:
                u = q.popleft()
                in_queue[u] = False

                for ei, edge in enumerate(self.g[u]):
                    v, cap, edge_cost, rev = edge
                    if cap > 0 and dist[v] > dist[u] + edge_cost:
                        dist[v] = dist[u] + edge_cost
                        prev_v[v] = u
                        prev_e[v] = ei

                        if not in_queue[v]:
                            q.append(v)
                            in_queue[v] = True

            if dist[t] == INF:
                break

            add = required - flow
            v = t

            while v != s:
                u = prev_v[v]
                ei = prev_e[v]
                add = min(add, self.g[u][ei][1])
                v = u

            v = t
            while v != s:
                u = prev_v[v]
                ei = prev_e[v]

                edge = self.g[u][ei]
                rev = edge[3]

                edge[1] -= add
                self.g[v][rev][1] += add

                v = u

            flow += add
            cost += add * dist[t]

        return flow, cost

def solve():
    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    cells = []
    pos = {}

    for i in range(r):
        for j in range(c):
            if grid[i][j] != 'x':
                idx = len(cells)
                cells.append((i, j))
                pos[(i, j)] = idx

    n_cells = len(cells)

    source = 2 * n_cells
    sink = 2 * n_cells + 1
    mcmf = MinCostMaxFlow(2 * n_cells + 2)

    start_b = start_c = finish = -1

    for idx, (i, j) in enumerate(cells):
        ch = grid[i][j]

        if ch == 'B':
            start_b = idx
        elif ch == 'C':
            start_c = idx
        elif ch == 'F':
            finish = idx

        capacity = 2 if ch == 'F' else 1
        mcmf.add_edge(2 * idx, 2 * idx + 1, capacity, 0)

    mcmf.add_edge(source, 2 * start_b, 1, 0)
    mcmf.add_edge(source, 2 * start_c, 1, 0)

    directions = ((1, 0), (-1, 0), (0, 1), (0, -1))

    for idx, (i, j) in enumerate(cells):
        # The two starting cells may only be entered from the super-source.
        if idx != start_b and idx != start_c:
            for di, dj in directions:
                ni, nj = i + di, j + dj
                nxt = pos.get((ni, nj))
                if nxt is not None:
                    mcmf.add_edge(2 * idx + 1, 2 * nxt, 1, 1)

    mcmf.add_edge(2 * finish + 1, sink, 2, 0)

    flow, cost = mcmf.min_cost_flow(source, sink, 2)

    if flow < 2:
        print(-1)
    else:
        print(cost)

if __name__ == "__main__":
    solve()
```の`MinCostMaxFlow`クラスは、各残差エッジを、その宛先、残りの容量、コスト、および逆エッジ インデックスを含む 4 要素のリストとして格納します。 残りのエッジには元のコストがマイナスになるため、通常の BFS では最短パスには不十分です。 この実装では SPFA を使用して、最も安価な拡張パスを見つけます。 

グリッド セルには 0 から 2 までの番号が付けられます。`n_cells - 1`。 細胞`idx`グラフの頂点になります`2 * idx`そして`2 * idx + 1`。 グラフの頂点に辞書を使用するのではなく、このマッピング演算を維持することで、ネットワークがコンパクトになります。 

の容量`in -> out`エッジは通常のセル用に 1 つ、車両用に 2 つあります。 車は 2 つのルートが合流できる唯一の場所です。 

移動エッジは、現在のセルが 2 つの開始セルの 1 つではない場合にのみ意図的に追加されます。 これは、単に開始セルの容量を 1 にするよりもわずかに強力です。 これがないと、フローの別の単位がすでに開始されたセルに別のグリッド セルからフローが入る可能性があり、これは法的な移動シーケンスに対応しません。 

すべての動きのエッジのコストは 1 ですが、すべての構造エッジのコストは 0 です。 したがって、(k) 個の動きを含むパスのコストは正確に (k) になります。 

SPFA は、理論上の不利な最悪のケースにもかかわらず、ここでは安全です。グラフには最大 900 個のグリッド セルがあり、必要なフロー単位は 2 つだけであり、グリッドは (O(rc)) 個のエッジのみを生成するためです。
