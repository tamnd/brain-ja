 ## 解決策
 ## 問題の理解

 私たちは、0 から n + 1 までのインデックスが付けられた垂直の「レーン」に分割された直線の通路に沿って移動しています。時間は離散的です。 1 秒ごとに、現在の車線に留まるか、ちょうど 1 つの車線を右に移動します。 常に横軸 y = 0 上にあるため、意味のある状態は現在のレーン インデックスと現在の時間だけです。 

1 から n までの各中間車線 i は、単一の安全な垂直セグメントを除いて交通によってブロックされています。 その安全なセグメントは、最初は [l_i, r_i] の間隔で y に広がりますが、トラフィック パターン全体が 1 秒ごとに 1 単位ずつ下にシフトします。 あなたは常に y = 0 に立っているので、唯一の問題は、あなたがレーン i にいる瞬間に y = 0 が安全なセグメント内にあるかどうかです。 

時間 t で、レーン i の安全セグメントは [l_i − t, r_i − t] にシフトしました。 l_i ≤ t ≤ r_i の場合、位置 y = 0 は正確に安全です。 したがって、各レーン i には時間枠が課されます。つまり、その間隔内の時間 t にレーン i にのみ入ることが許可されます。 

開始レーン 0 と最終レーン n + 1 は常に安全であるため、制限はありません。 

タスクは、レーン 0 から開始してレーン n + 1 に到達するのに必要な最小時間を見つけることです。その際、時間 t ではレーンがその時間有効である必要があり、レーン インデックスは 1 秒あたり最大 1 しか増加できないという事実を尊重します。 

n ≤ 10^5 および l_i、r_i が 10^12 までという制約は、線形または線形に近いスキャンが必要であることを意味します。 時間が大きくなる可能性があり、遷移は 10^12 スケールの値まで連続するため、時間の経過に伴う状態の探索や、時間の値に対する動的プログラミングの直接使用を試みるアプローチは遅すぎます。 

時間の経過に伴う単純なシミュレーションも失敗します。待機により時間が n をはるかに超えて延長される可能性があり、各レーンにグローバル制約ウィンドウが導入されるからです。 

車線の有効間隔が、単に前に歩いて到達できる間隔よりも早い場合、微妙な失敗のケースが発生します。 

たとえば、レーン i が r_i < i である場合、待たずにすぐに到着するだけでもすでに制約に違反しており、パス全体を通過することは不可能になります。 移行後に実現可能性を確認するだけの単純な貪欲な人は、これを見逃すでしょう。 

もう 1 つの注意が必要なケースは、将来のウィンドウに合わせて待機する必要がある場合です。 単純な解法が可能な限り常に移動する場合、有効なウィンドウが遅く開始されるレーンに早く到着しすぎて、より早く待つことが正しかったとしても矛盾が後から強制される可能性があります。 

## アプローチ

 ブルート フォース パースペクティブでは、各状態をペア (位置、時間) として扱います。 各状態から移動または待機することができ、現在のレーンが現時点で有効であるかどうかを確認します。 これにより、時間依存の制約を持つグラフが生成されます。 この暗黙的なグラフ上の BFS または最短パスは、各アクションのコストが 1 秒であるため、概念的には正しいですが、状態空間には時間の制限がありません。 最悪の場合、時間値は 10^12 に達する可能性があり、到達可能な状態の数はそのスケールに比例して増加するため、これは完全に不可能になります。 

重要な観察は、時間を明示的に調べる必要がないということです。 車線インデックス i を修正すると、関連する情報は、そこに到着できる最も早い時刻だけになります。 各レーン i は t が固定間隔 [l_i, r_i] 内にある必要があるため、後で到着すると制約が難しくなるだけで決して簡単になりません。 これにより、問題は単一の実現可能な増加シーケンス t_0、t_1、…、t_{n+1} の計算に変わります。 

レーン i − 1 から i に移動する場合、常に 1 秒が経過するため、t_i は少なくとも t_{i−1} + 1 でなければなりません。さらに、レーン i がその時間枠内で到達可能になる前に到着することはできないため、t_i も少なくとも l_i でなければなりません。 最後に、期限 r_i に違反してはなりません。したがって、t_i ≤ r_i でなければなりません。

これにより、問題は、各ステップで常に可能な限り早い時間を取得する貪欲な前進構造に分解されます。 最も早い実行可能時間が r_i を超える場合、有効なスケジュールは存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 状態空間 BFS (レーン、時間) | O(非常に大きく、最大 10^12 状態) | O(状態) | 遅すぎる |
 | レーンごとの貪欲な時間スケジューリング | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各レーンの到着時間を左から右に構築します。 

1. レーン 0 の時間を 0 として初期化します。これは、時間 0 で位置 0 から開始することを表します。 
2. 1 から n までの各レーン i について、可能な限り最も早い到着時間を計算します。 レーン i − 1 からの移動には少なくとも 1 秒を費やす必要があるため、時間を t_{i−1} + 1 より小さくすることはできません。 
3. レーンには独自の有効期間も課されるため、l_i より前に到着しないようにする必要があります。 したがって、t_{i−1} + 1 と l_i の最大値を候補到着時間として採用します。 
4. この候補が r_i を超える場合、レーンの安全ウィンドウはすでに閉じられているため、有効な移動シーケンスはこのレーンを通過できず、プロセスは失敗して終了します。 
5. それ以外の場合は、t_i をこの候補に設定して続行します。 
6. レーン n を処理した後、制限のないレーン n + 1 に移動します。 移動するにはまだ 1 秒を費やす必要があるため、最終的な答えは t_{n+1} = t_n + 1 となります。 

機能する理由: すべてのレーン i で、有効なスケジュールは時間の進行により t_{i−1} + 1 より早く到着する必要があり、安全上の制約により l_i より早く到着することはできません。 到着が遅くなっても、その後のすべての時間が増加するだけであり、将来の下限を満たすことには役立たないため、実現可能な最小の到着時間を選択することで、全体的に実現可能性が維持されます。 この最小値がすでに r_i に違反している場合は、すべてのスケジュールが少なくとも同じくらい遅れて到着するため、考えられるすべてのスケジュールもそれに違反する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    l = [0] * (n + 2)
    r = [10**30] * (n + 2)

    for i in range(1, n + 1):
        li, ri = map(int, input().split())
        l[i], r[i] = li, ri

    t = 0
    for i in range(1, n + 1):
        t = max(t + 1, l[i])
        if t > r[i]:
            print(-1)
            return

    t = t + 1
    print(t)

if __name__ == "__main__":
    solve()
```各レーンは前のレーンにのみ依存するため、実装では現在の時刻のみが保持されます。 移行`t = max(t + 1, l[i])`必須の時間経過とレーンが使用可能になる最も早い時間の両方をエンコードします。 実現可能性チェック`r[i]`安全な窓が閉まった後は絶対に車線に入らないようにします。 

レーン n の後の最後の増分は、最後の常に安全なレーン n + 1 への移動を考慮します。

 レーン 3 の次はレーン 4 に移動するので、答えは 5 になります。 

このトレースは、待機が暗黙的にどのように処理されるかを示しています。 レーン 2 では、物理的にはもっと早く到着できたにもかかわらず、時間 3 まで待たなければなりません。

 ## 特殊なケース

 エッジ ケースの 1 つは、最初のレーンに時間 1 以降に開始するウィンドウがすでにある場合です。入力の場合`1\n5 10\n`の場合、アルゴリズムは t = max(1, 5) = 5 を設定し、これは有効であり、時間 6 でレーン 2 に移動します。 

もう 1 つのケースは、レーンが閉じるのが早すぎる場合です。 のために`1\n0 0\n`、時間 0 にレーン 1 に到着する必要がありますが、移動には少なくとも時間 1 が必要であるため、計算された時間は 1 になり、これは r_1 = 0 に違反し、正しく不可能を返します。 

最後の構造上のエッジ ケースは、すべての間隔が非常に大きい場合です。`n = 100000`すべて [0, 10^12] です。 このアルゴリズムは、レーンごとに単純に時間を 1 ずつ増分し、制約に到達することなく t = n + 1 を生成します。これは、待ち時間が不要であるという直感と一致します。
