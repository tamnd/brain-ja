 ## 解決策
 ## 問題の理解

 異なる小文字文字列のコレクションが与えられます。 これらの文字列から、空ではないサブセットを選択し、選択した文字列を任意の順序で配置できます。 順序付けされた選択肢ごとに、順序内のすべての文字列の最初の文字を取得して、短い「略語」に連結して新しい文字列を形成します。 

2 つの異なる順序付き選択は同じ略語文字列を生成する可能性があるため、各略語には「スキーム カウント」があり、それはその略語が生成される順序付き選択の数を意味します。 タスクは、考えられるすべての略語文字列にわたるこれらのスキーム数の合計を要求します。 

プロセスを理解するもう 1 つの方法は、すべての有効な構造が、最初に文字列のサブセットを選択し、次にそれを並べ替えることによって決定されるということです。 結果として得られる各順列は合計に 1 つだけ寄与しますが、異なる順列が同じ略語にまとめられる場合があります。 この問題では、個別の略語の数ではなく、すべての略語にわたる合計寄与度が求められます。 

この制約では、最大 100,000 個の文字列と最大 1e6 の合計長が許可されており、実際の文字に依存した解決策や明示的なサブセットの構築が不可能であることがすぐにわかります。 サブセットを列挙すると、すでに 2^n 個の可能性が得られますが、順列に制限するとさらに爆発する可能性があります。 唯一の実現可能な解決策は、問題を閉形式の組み合わせ式または n にわたる線形スキャンに還元するものです。 

微妙な点は、文字列の実際の内容は、各文字列が区別されることを保証する以外に、構造的にカウントに影響を与えないことです。 素朴な読者は、最初の文字がグループ化に重要であると考えるかもしれませんが、出力では、略語の同一性によってグループ化されるのではなく、すべての構造の合計が求められます。 

よくある間違いは、各略語文字列を生成するサブセットの数をシミュレートし、一意の略語を合計しようとすることです。 最悪の場合、個別の略語の数自体が指数関数的に増加するため、このアプローチは失敗します。 もう 1 つの間違いは、最初の文字間の衝突を注意深く追跡する必要があると想定していることです。 たとえば、多くの文字列が同じ文字で始まる場合、文字の頻度によってグループ化しようとするかもしれませんが、個別の略語数は求められず、すべての選択範囲にわたる合計スキーム数のみが求められるため、これは無関係です。 

健全な小さな例として、文字列が 3 つある場合、正解は 15 です。単純な略語によるグループ化方法では、各文字パターンを形成するサブセットの数を追跡するため、これが過度に複雑になる可能性がありますが、正しい解釈は、任意のサイズの可能な順序付けられた選択をすべてカウントすることです。 

## アプローチ

 ブルートフォース解釈は簡単です。 n 個の文字列の空でないすべてのサブセットを検討し、次にそのサブセットのすべての順列を検討します。 各順列は 1 つの有効な構造に寄与します。 サイズ k の固定サブセットの場合、k 個があります。 したがって、サイズ k のすべてのサブセットからの合計寄与は C(n, k) · k! となります。 すべての k を合計すると、最終的な答えが得られます。 これは数学的には正しいですが、項の数が指数関数的に増加するため、これらのオブジェクトを明示的に生成することは不可能です。 

重要な観察は、その構造が文字列内の実際の文字にまったく依存していないことです。 省略操作では最初の文字を除くすべてが破棄されますが、結果の省略形に関係なくすべての順列を合計しているため、順序付けられたすべての選択は同様に有効であり、正確に 1 つとなります。 したがって、問題は、考えられるすべての k について、n からの k 個の異なる項目の順序付けられた選択をすべてカウントすることに帰着します。

固定 k の場合、そのような順序付き選択の数は正確に下降階乗 n · (n − 1) · ... · (n − k + 1) であり、多くの場合 nPk と書かれます。 したがって、答えは単に k = 1 から n までのすべての階乗の合計になります。 これは、現在の積を維持し、各ステップで乗数を減少させることにより、線形時間で増分的に計算できます。

 ## アルゴリズムのチュートリアル

 すべてのサブセット サイズの順列カウントを合計するタスクを再定式化します。 

1. サイズ 1 の順序付けされた選択の数を表す実行値から開始します。n 個の文字列のいずれかを単独で選択できるため、これは単に n です。 
2. サブセット サイズが大きくなるにつれて、どれだけの選択肢が残るかを反映して、減少する乗数を維持します。 k − 1 個の要素を選択した後、次の選択肢には (n − (k − 1)) 個の可能性があります。 
3. 1 から n までの各サブセット サイズ k について、前の値に (n − k + 1) を乗算して、サイズ k の順序付けされた選択の数を計算します。 これにより、最初から再計算することなく、下降階乗シーケンスが構築されます。 
4. 計算された各値をアキュムレータに加算し、最終的な答えのモジュロ 1e9 + 7 を格納します。 
5. すべてのサイズが処理されるまで続行します。 

すべての有効な構造はインデックスの選択と順序付けのみに依存するため、実装では文字列自体を検査する必要はありません。 

### なぜ効果があるのか

 すべての有効な構造は、個別の文字列の順序付けされたシーケンスに一意に対応します。 各 k について、そのようなシーケンスの数は、n 個の異なる要素から抽出された長さ k の順列の数と正確に一致します。 各構成は固有のサイズ k を持ち、合計の対応する項にのみ含まれるため、k を合計すると、すべての可能な構成が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    
    # We only need n, strings are irrelevant
    for _ in range(n):
        input()
    
    ans = 0
    cur = 1  # will build falling factorial incrementally
    
    for k in range(1, n + 1):
        cur = cur * (n - k + 1) % MOD
        ans = (ans + cur) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```重要な実装アイデアは次のとおりです。`cur`は現在の k の nPk を表します。 各反復には、次の減少係数が乗算されます。 これにより、再計算が回避され、解が線形に保たれます。 

入力文字列は組み合わせカウントに影響を与えないため、読み取られてすぐに破棄されます。 重要な状態は n だけです。 

モジュロ演算は、オーバーフローを防止し、値を範囲内に保つために、すべての乗算と加算のステップに適用されます。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    for _ in range(n):
        input()

    ans = 0
    cur = 1
    for k in range(1, n + 1):
        cur = cur * (n - k + 1) % MOD
        ans = (ans + cur) % MOD

    return str(ans)

# provided sample
assert solve("3\naaa\naab\nbba\n") == "15"

# minimum case
assert solve("1\na\n") == "1"

# all equal first letters but irrelevant structure
assert solve("2\naaa\nbbb\n") == "4"

# n = 4 full check
assert solve("4\na\nb\nc\nd\n") == "64"

# larger sanity
assert solve("5\na\nb\nc\nd\ne\n") == str((5 + 20 + 60 + 120 + 120) % MOD)
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 エッジ ケースの 1 つは、n が 1 に等しい場合です。唯一可能な構築は単一の文字列を選択することであるため、答えは 1 でなければなりません。アルゴリズムは k = 1 から始まり、nPk = 1P1 = 1 となり、これは直接一致します。 

もう 1 つのケースは、すべての文字列が同じ最初の文字を共有する場合です。 単純なアプローチでは、その文字でグループ化して貢献度を過大にカウントしたり、誤って結合しようとしたりする可能性があります。 たとえば、2 つの文字列「aaa」と「bbb」の場合でも、アルゴリズムはそれらを別個の項目として扱います。 計算では、すべての順序付けられた選択に対応する 2 + 2 = 4 が生成され、同一のプレフィックスからあいまいさは生じません。 

最後のエッジ ケースは n が大きく、中間階乗のような値が急速に増加します。 各乗算でモジュラー演算を行わないと、オーバーフローや不正な演算が発生します。 この実装では、すべてのステップで係数が適用され、値が一般的な整数の制限を超えた場合でも正確さが保証されます。
