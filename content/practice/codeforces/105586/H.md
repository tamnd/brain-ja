 ## 解決策
 ## 問題の理解

 時間の経過に伴う一連の値が与えられ、各値はマイナス 1、ゼロ、またはプラス 1 のいずれかになります。 それぞれの値は、その日に購入したボトルの本質的な「効果」を表します。 ユーザーは、隣接する要素の間に演算子を挿入することで、任意の方法でシーケンスを連続したグループに分割できます。 各グループは 1 つの「ドリンク イベント」として解釈され、そのイベントの貢献はグループ内のすべての価値観の積となります。 最終的なスコアは、これらのグループ積の合計です。 

同様に、隣接する要素間にプラスまたは乗算を挿入し、通常の算術規則に基づいて式を評価し、結果の値がターゲット x と等しくなるかどうかを尋ねます。 

キー制約構造は重要です。 テストとクエリの合計の長さは最大 10^6 で、値は -1、0、または 1 のみです。これにより、x の n 倍に依存する状態空間や、考えられるすべての合計を単純に追跡する DP が直ちに排除されます。 各テストを本質的に線形の前処理と定数または対数のクエリ応答に削減するものが必要です。 

ゼロの存在が主な構造上の複雑さです。 ゼロを含む積はすべてゼロになるため、ゼロは乗算の観点からシーケンスを分割しますが、乗算を使用してゼロを分離したり、プラス演算を使用して合計に吸収したりすることもできます。 

単純な解釈の間違いは、これがすべての可能なセグメント積と合計の組み合わせを計算する標準パーティション DP であると想定することです。 もう 1 つの微妙な問題は、ゼロが常に分離に有益であると仮定していることです。 実際には、ゼロは何も寄与しないか、乗法構造をリセットする区切り文字として機能するかのどちらかです。 

素朴な推論を打ち破る小さなエッジ ケースは、1、-1、1 のような交互パターンです。(1 + -1 + 1) としてグループ化すると 1 が得られ、(1 * -1 * 1) としてグループ化すると -1 が得られます。 製品内の記号の相互作用により、ローカルの貪欲なグループ化が不正確になります。 

## アプローチ

 直接総当たりアプローチでは、隣接する要素間のプラスまたは乗算のあらゆる配置が考慮されます。 各位置には 2 つの選択肢があり、2^(n-1) 個の式が得られます。 各式の評価には O(n) のコストがかかるため、O(n · 2^n) となり、n が 40 程度であっても不可能です。 

より構造化された DP では、プレフィックスのすべての可能な値を追跡しようとします。 ただし、{-1,0,1} の制約を利用しない場合、値のカウントは組み合わせ的に増加します。 重要な観察は、乗算では {-1,0,1} を超える新しい大きさは作成されず、加算は整数を集計するだけであるということです。 したがって、増加するのは中間生成物の規模ではなく、達成可能な個別の合計の数だけです。 

重要な洞察は、シーケンスを非ゼロ値の最大ブロックに分割することです。 ±1 のブロック内のみで、乗算は基本的に負数のパリティですが、加算ではセグメントのマージが可能です。 このようなブロック内のすべてのセグメント積は常に ±1 です。 したがって、各セグメントに含まれる -1 値が偶数か奇数かに応じて、+1 または -1 のいずれかになります。 

したがって、問題は、配列のパーティションをセグメントに分割する選択に帰着します。各セグメントは、+1、-1、または 0 (ゼロが含まれている場合) のいずれかを与え、ゼロは強制区切り文字または null 寄与子として機能します。 合計は、選択したセグメント符号の合計に、ゼロ セグメントによって生じるオプションのキャンセルを加えたものになります。 

より正確な公式が現れます。区切り文字としてゼロを削除し、ゼロ以外の各ブロックを個別に処理し、形成できる負の積の数と正の寄与をいくつ作成できるかによって決まる最小値と最大値の間のすべての整数として達成可能な合計の範囲を計算します。 各ブロックは ±1 のシーケンスに折りたたまれるため、達成可能な合計セットは連続し、その境界のみが問題になります。

最終的な削減は、テスト ケースごとに、最適に形成できる非ゼロ要素の数と負のプレフィックス セグメントの数を計算することです。 到達可能な合計間隔は対称的であり、マージするセグメントの数を選択することによって決まります。 マージごとに加算と乗算の選択肢が切り替わりますが、乗算では絶対に大きさが増加しないため、完全に分割するか最適にグループ化することで極値が得られます。 

これにより、前処理後のクエリごとのチェックが一定時間行われるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n + q) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 式を列挙するのではなく、配列の構造的特徴を数えることに問題を圧縮します。 

1. まず、配列をスキャンしてゼロ以外の値をすべて抽出します。今のところゼロは無視しますが、個別にカウントします。 ゼロはそれらの間の乗算を防ぐ区切り文字として機能するため、これは重要です。 
2. 非ゼロシーケンスを最大の連続セグメントに分割します。 各セグメントには +1 と -1 のみが含まれます。 完全に乗算されたセグメントの積は、-1 値のパリティによってのみ決定されます。 
3. 各セグメントについて、その総積符号を計算します。 これを完全に乗算すると、+1 または -1 のいずれかになります。 プラス演算子を使用してさらに分割すると、それぞれが ±1 に寄与する単一の要素に分割できます。 
4. 長さ k のセグメント内で、分割によって +1 または -1 の寄与として扱われる要素の数を選択することにより、ステップ サイズ 2 で -k と k の間の任意の合計を実現できることに注目してください。 これは、加算では各要素が個別に ±1 であり、乗算では単一の ±1 に折りたたまれるだけであるという事実から来ています。 
5. すべてのセグメントを結合します。 セグメントは独立しているため、それらの達成可能な範囲は合計されます。 これは、最終的な答えが非ゼロ要素の総数 Nnz とセグメントの総数 S のみに依存することを意味します。 
6. グローバル最小合計は、各セグメントをその最小値に寄与させることによって達成されます。これは、各セグメントを単一の製品に完全にマージし、寄与を最小化する符号を選択することに対応します。 最大合計は、すべてを単一の要素に分割することによって達成されます。 
7. したがって、到達可能な合計は完全な整数間隔 [minSum, maxSum] を形成するため、各クエリ x は minSum ≤ x ≤ maxSum かどうかをチェックすることによって回答されます。 

なぜ効果があるのか

 核となる不変条件は、非ゼロ値のすべてのセグメントを、1 以外の中間の大きさを作成せずに、単一の ±1 寄与率に減らすことも、個々の ±1 寄与率に拡張することもできるということです。ゼロはセグメント間で相互作用することはないため、セグメント化にのみ影響し、セグメント内の算術範囲には影響しません。 すべての演算では整合性が維持され、±1 の範囲外の値が導入されないため、各セグメントの達成可能な合計のセットは連続しています。 独立した連続区間を合計すると、別の連続区間が生成されるため、解空間全体が 1 つの区間 [minSum, maxSum] に折りたたまれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        # extract non-zero structure
        nonzero = []
        for v in a:
            if v != 0:
                nonzero.append(v)

        if not nonzero:
            # only zeros: every segment product is zero, total is always 0
            # queries ask x >= 1, so always No
            for _ in range(q):
                input()
                out.append("NO")
            continue

        # compute min/max achievable
        # max: split everything -> sum of +1 contributions for 1, -1 for -1 optimally
        # best is treating each element individually => sum of abs(v)=len(nonzero)
        max_sum = len(nonzero)

        # min: worst case is pairing to reduce positives; effectively we can make all segments
        # contribute -1 by grouping, so minimum is -len(nonzero)
        min_sum = -len(nonzero)

        for _ in range(q):
            x = int(input())
            if min_sum <= x <= max_sum:
                out.append("YES")
            else:
                out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```ゼロは null 積に寄与するだけであり、絶対和の大きさを増やすのに役立たないため、コードは配列を非ゼロ射影に縮小します。 到達可能な合計間隔は、ゼロを無視した後に存在する ±1 寄与の数に基づいて対称境界として計算されます。 

各クエリは直接間隔チェックによって回答されます。これは、この構造によって達成可能な合計の連続性が保証されているため有効です。 

実装上の微妙な選択は、入力解析の非同期を避けるために、配列が空または些細な場合でもすべてのクエリを読み取ることです。 もう 1 つは、境界の目的で、-1 と +1 は大きさではなく符号のみが異なるため、すべての非ゼロ値を均一に扱うことです。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、a = [1, 1, 0]、クエリ = [2, 3]

 ゼロ以外の値 [1, 1] を抽出します。 要素は2つあります。 

| ステップ | ゼロ以外の配列 | 最小合計 | 最大合計 |
 | --- | --- | --- | --- |
 | 初期化 | [1, 1] | -2 | 2 |

 クエリ x = 2 は [-2, 2] 内にあるため、答えは YES です。 

クエリ x = 3 は外側にあるため、答えは NO です。 

これは、大きさの計算でゼロがどのように無視され、カウントのみが重要になるかを示しています。 

### 例 2

 入力:

 n = 3、a = [1、0、-1]、クエリ = [1]

 ゼロ以外の配列は [1, -1] になり、長さは 2 になります。 

| ステップ | ゼロ以外の配列 | 最小合計 | 最大合計 |
 | --- | --- | --- | --- |
 | 初期化 | [1, -1] | -2 | 2 |

 クエリ x = 1 は区間内にあるため、出力は YES になります。 

これは、配列内の符号の変化は実現可能範囲には影響せず、アクティブな要素の数のみが重要であることを示しています。

 ## 特殊なケース

 [0, 0, 0] のようなゼロのみの配列の場合、アルゴリズムはゼロ以外のリストを空として扱います。 これにより、すべてのセグメント積が強制的にゼロになるため、達成可能な合計は 0 のみになります。クエリには x ≥ 1 が必要なため、すべての答えは NO となり、区間 [-0, 0] に一致します。 

[1, 1, 1, 1] のような完全にゼロでない配列の場合、アルゴリズムはそれを 4 つの独立した ±1 寄与に分解し、境界 [-4, 4] を生成します。 x = 4 のようなクエリは YES ですが、x = 5 は NO です。 これは、大きさを最大化するにはすべての要素を分割することが最適であるという考えと一致します。 

[1, -1, 1] のような交互の符号の場合、間隔は [-3, 3] になります。 乗算によって分散を減らすことができますが、分割機能により中間整数を完全にカバーできるため、符号が変化しても連続性が維持されることが確認されます。
