 ## 問題の理解

 私たちは反復実験を与えられ、各試行は独立して確率で勝利をもたらします。$\frac{p}{q}$そして確率的に損失が発生する$1 - \frac{p}{q}$。 0勝0敗からスタートし、2つの停止条件のいずれかに達するまでプレイを続けます。 を取得すると、プロセスは正常に停止します。$n$蓄積する前に勝ちます$n$損失。 損失が以下に達すると失敗します$n$初め。 

タスクは、この停止ルールに基づいて成功の確率を計算し、それを剰余として出力することです。$10^9 + 7$。 

プロセスを再解釈する便利な方法は、一次元のウォークとして行うことです。 勝利するたびに +1 が移動し、負けるたびに -1 が移動します。 位置 0 から開始します。プロセスは、いずれかに到達すると終了します。$+n$(成功) または$-n$（失敗）。 問題は、バイアスのあるランダム ウォークがヒットする確率はどれくらいかということです。$+n$前に$-n$?

 制約により、最大で$10^4$テストケースと合計$5 \cdot 10^6$全体的に$n$。 これにより、テスト ケースごとのすべての状態にわたるシミュレーションまたは DP が除外されます。 どのようなソリューションでも、各テスト ケースを対数または定数時間のべき乗モジュラに換算する必要があります。 

歩行をシミュレートする単純なアプローチでは、吸収までに指数関数的な時間が必要となり、すぐには不可能になります。 状態を超える動的プログラミング ソリューションでも、$-n$に$n$テストケースごとに次のようになります$O(n^2)$あるいはせいぜい$O(n)$、グローバル制約に対して遅すぎます。 

微妙なエッジケースが現れるのは、$\frac{p}{q} = \frac{1}{2}$。 この対称の場合、ランダム ウォークにはドリフトがなく、対称性は到達する確率を意味します。$+n$前に$-n$まさに$\frac{1}{2}$、独立して$n$。 盲目的に除算する数式ベースの実装$1 - r^{2n}$引き続き動作しますが、慎重に扱わないとモジュールが不安定になる可能性があります。 

## アプローチ

 この強引なアイデアは、現在のネット スコアを表す状態にわたるマルコフ連鎖としてプロセスをモデル化し、動的プログラミングを使用して吸収確率を計算することです。 させて$dp[i]$最終的に到達する確率である$+n$状態から始める$i$。 境界条件を設定します$dp[n] = 1$そして$dp[-n] = 0$、線形漸化式を解きます。 ただし、各状態は 2 つの近傍に依存しており、すべての状態についてこのシステムを解くには、反復緩和または三重対角システムでのガウス消去のいずれかが必要です。 最適化を行ったとしても、テスト ケースごとにこれを個別に実行すると、合計を考慮すると遅すぎます。$n$まで$5 \cdot 10^6$。 

重要な観察は、これが対称的な吸収境界を伴う古典的なギャンブラーの破滅問題であるということです。 このようなプロセスでは、DP グラフの絶対的な構造ではなく、ステップ確率間の比のみに依存する閉形式の解法が可能になります。 システムを比率で表現すると$r = \frac{q-p}{p}$、確率は漸化式を解くことで得られる単純な幾何学的表現に分解されます。 

これにより、各テスト ケースがいくつかのべき乗モジュラーと逆モジュラーの計算に減ります。

 ## アルゴリズムのチュートリアル

 確率モデルを吸収境界を持つバイアスのあるランダム ウォークに変換し、既知の閉じた形式を評価します。 

1. 成功の確率をモジュラー算術形式に変換します。 1ステップで勝つ確率は$\frac{p}{q}$したがって、モジュラー逆関数を使用して以下の分数を表現します。$10^9 + 7$。 
2. 故障確率を次のように定義します。$\frac{q-p}{q}$。 これにより、失敗と成功の比率を使用して歩行の偏りを表すことができます。 
3. ドリフト比を構築する$r = \frac{q-p}{p}$。 この比率は、共通分母とは無関係に、1 つのステップで上方へ移動するよりも下方へ移動する可能性がどの程度高いかを表します。$q$。 
4. コンピューティング$r^n$そして$r^{2n}$モジュラスの下で高速累乗を使用します。 これらの値は、吸収境界に到達するパスの確率重み付けされた寄与に対応します。 
5. もし$r = 1$、次の場合に発生します。$q = 2p$、直接出力$\frac{1}{2}$モジュロ$10^9 + 7$, 歩き方は対称なので。 
6. それ以外の場合は、閉じた形式を使用して最終確率を計算します。$$\frac{1 - r^n}{1 - r^{2n}}$$モジュラー算術では、除算を逆モジュラーによる乗算に置き換えます。 

正確さは、有界バイアスランダムウォークにおける吸収確率の漸化式を解くことから得られます。 確率関数は、係数が一定の 2 次線形漸化式を満たします。 その一般的な解決策は、次のべき乗の線形結合です。$r$、および次の境界条件$-n$そして$+n$係数を一意に決定し、記載された式を正確に生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    T = int(input())
    inv2 = (MOD + 1) // 2

    for _ in range(T):
        n, p, q = map(int, input().split())

        if 2 * p == q:
            print(inv2)
            continue

        # r = (q-p)/p
        r = (q - p) * pow(p, MOD - 2, MOD) % MOD

        rn = mod_pow(r, n)
        r2n = rn * rn % MOD

        numerator = (1 - rn) % MOD
        denominator = (1 - r2n) % MOD

        ans = numerator * pow(denominator, MOD - 2, MOD) % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず確率を共通分母を排除する比率に変換します。$q$。 これは重要です。$q$内部のべき乗は不必要であり、遅くなります。 

高速累乗は次の目的で使用されます。$r^n$なぜなら$n$と同じ大きさにすることができます$10^5$、テストケースはたくさんあります。 逆モジュラーは最後の除算ステップでのみ適用され、逆モジュラーの繰り返しが回避されます。 

対称の場合は、式内でのゼロ除算を避けるために個別に処理されます。$1 - r^{2n}$、それ以外の場合はゼロになります。$r = 1$。 

## 実用的な例

 簡単なケースを考えてみましょう$n = 1, p = 1, q = 2$。 ここ$r = 1$, したがって、すぐに対称分岐に分類されます。 答えは$\frac{1}{2}$。

 これは、成功と失敗の可能性が等しい場合、最初のステップがすべてを決定することを裏付けています。 

ここで考えてみましょう$n = 2, p = 1, q = 3$。 すると成功確率は$1/3$、失敗は$2/3$、 それで$r = 2$。 

| ステップ | r | r^2 | r^4 | 分子 | 分母 |
 | --- | --- | --- | --- | --- | --- |
 | 計算する | 2 | 4 | 16 |$1-4$|$1-16$|

 最終的な確率は次のようになります。$$\frac{-3}{-15} = \frac{1}{5}$$これは、プロセスが失敗する方向に偏っているため、2 回失敗する前に 2 回成功する可能性は比較的低いという直観と一致します。

 ## 特殊なケース

 最もデリケートな状況は次のようなときです$q = 2p$。 この場合の比率は$r = \frac{q-p}{p} = 1$、分母は$1 - r^{2n}$ゼロになる。 単純な実装では、ゼロのモジュラー反転が試行され、クラッシュしたり、ガベージが生成されたりする可能性があります。 明示的な対称処理では、以下を短絡することでこれを完全に回避します。$\frac{1}{2}$。 

もう一つの微妙なケースは次のような場合です。$n = 1$。 プロセスは 1 ステップで終了するため、答えは最初の試行で勝つ確率と正確に一致する必要があります。$\frac{p}{q}$。 式に当てはめると、次のようになります。$$\frac{1 - r}{1 - r^2} = \frac{1}{1 + r} = \frac{p}{q}$$これにより一貫性が確認されます。 

最後に、確率が大きく、逆モジュラーが繰り返し計算される場合、中間値を減らすのを忘れると、オーバーフローや不正確なモジュラー演算が発生する可能性があります。 すべての中間値を剰余として保持する$10^9 + 7$計算全体を通して安定性を確保します。
