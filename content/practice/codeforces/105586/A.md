 ## 解決策
 ## 問題の理解

 文字列として表現された曲の短いプレイリストが与えられます。 各文字列は、元のコンサート スケジュール内の単一のプログラム項目です。 

このタスクは、このスケジュールを上から下に読むときに適用される単純なルールをシミュレートします。 演奏者が正確な文字列を見るたびに`"Tomori"`、彼女はすぐに追加の曲を挿入します`"Haruhikage"`最終出力の直後。 他のすべての文字列は変更されずにコピーされ、元の順序が維持されます。 

したがって、出力は入力リストの単なるコピーではありません。 これは、一部のエントリが値に応じて 2 つの連続するエントリに展開される、変換されたリストです。 

入力サイズは非常に小さく、文字列は最大 100 個、各文字列の長さは最大 20 です。これにより、単純な線形処理を超えたパフォーマンスの最適化に関する懸念がなくなりました。 入力を 1 回通過するだけで十分です。 

唯一の微妙な点は、一致が正確かつ大文字と小文字を区別する必要があることです。 ような文字列`"TOMORI"`または`"tomori"`挿入をトリガーしません。 大文字と小文字を区別しない比較や部分文字列の一致を試みる単純なアプローチでは、誤った出力が自動的に生成されます。 

2 番目の例外的なケースは次のような場合です。`"Tomori"`が連続して現れます。 その状況では、それぞれの出現が独立して挿入をトリガーするため、複数の`"Haruhikage"`行が連続して表示される場合があります。 

## アプローチ

 この問題を考える直接的な方法は、最終的なリストを明示的に作成することです。 すべての文字列を配列に読み取り、それを反復処理して、各文字列を結果リストに追加します。 出会うたびに`"Tomori"`、また追加します`"Haruhikage"`その直後。 

このアプローチはすでに構造的に最適化されています。 ブルートフォース解釈では、配列の途中への挿入など、要素を移動する操作を使用して、拡大するリストに繰り返し再構築または挿入することになります。 これは不必要なオーバーヘッドにつながります。配列ベースの構造体への各挿入には O(n) のコストがかかる可能性があり、最悪の場合、すべての要素が`"Tomori"`の場合、O(n) 回の挿入を実行し、O(n^2) 個の動作が発生します。 

重要な点は、途中の構造を変更する必要がまったくないということです。 ストリーミング形式で出力を発行するだけで済みます。 これにより、問題は、各入力要素が 1 つまたは 2 つの出力要素に寄与する単一の線形スキャンに変わります。 

問題の構造により、要素間の独立性が保証されます。 各行は将来または過去の値を知らなくても処理できるため、複雑なデータ構造は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (配列/リストに繰り返し挿入) | O(n^2) | O(n) | 不要ですが、小さい n の場合は機能します |
 | 最適 (シングルパス追加/出力) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`、これは後に続く文字列の数を示します。 
2. 次のそれぞれについて`n`行、文字列を読み取ります`s`。 
3. 即時出力`s`。 
4. もし`s`と全く同じです`"Tomori"`、追加の行を出力します`"Haruhikage"`その直後。 

即時出力の背後にある理由は、変換は現在の要素のみに依存するということです。 将来の要素には依存しないため、処理を遅延してもメリットはありません。 

### なぜ効果があるのか

 このアルゴリズムは単純な不変条件を維持します。i 番目の入力文字列を処理した後、出力にはルールに従って最初の i 文字列の変換されたバージョンが正確に含まれ、それ以外は何も含まれません。 各文字列は独立して処理され、順序が保持されるため、すべてのローカル変換を連結すると、正しいグローバル結果が生成されます。 変換では相対的な順序は変更されず、特定の一致の後に固定文字列が挿入されるだけであるため、並べ替えやバッファリングは必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

for _ in range(n):
    s = input().strip()
    print(s)
    if s == "Tomori":
        print("Haruhikage")
```実装はアルゴリズムに直接に従います。 入力は高速 I/O を使用して 1 行ずつ処理されます。 正確な比較を保証するために、各文字列の末尾の改行文字が削除されます。 条件付きチェックは直接等価性テストであり、大文字と小文字の区別が強制されます。 

重要な実装の詳細は、結果を保存するのではなく、すぐに出力することです。 リストに保存することもできますが、ストリーミング出力の制約が少なく、単純であることを考えると、その必要はありません。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout

        n = int(sys.stdin.readline().strip())
        for _ in range(n):
            s = sys.stdin.readline().strip()
            print(s)
            if s == "Tomori":
                print("Haruhikage")
    return out.getvalue().strip()

 ## 特殊なケース

 重要なケースの 1 つは、一致する文字列がまったくない場合です。 たとえば、入力が次の場合:```
2
Neko
Rikki
```このアルゴリズムは各行を 1 回出力するだけで、挿入は実行しません。 条件が満たされることはないため、追加の出力は表示されず、出力は入力シーケンスと同一になります。 

別のケースも連続`"Tomori"`エントリ:```
2
Tomori
Tomori
```アルゴリズムは最初のものを処理します`"Tomori"`そしてすぐに印刷します`"Haruhikage"`、次に 2 番目を独立して処理し、同じことを再度実行します。 2 つのステップ間には相互作用がないため、結果には挿入された 2 行が正しく含まれます。 

3 番目のケースは、視覚的にはトリガーに似ていますが、大文字と小文字が異なる文字列です。```
1
TOMORI
```比較は正確であるため、条件は失敗し、追加の出力は生成されません。 これは、等価性チェックが厳密であり、パターン マッチングや正規化に依存していないことを確認します。
