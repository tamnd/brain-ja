 ## 解決策
 ## 問題の理解

 一連の日数が与えられており、毎日、一連の予定された貢献から「追加の作業時間」が何時間蓄積されるかを計算したいと考えています。 

各貢献はある日から始まります$x$そしてその後はすべての日に影響します$x$最後まで$n$。 貢献度はその種類によって異なります。 

タイプ 1 の場合、日から始まる場合$x$、そして当日$x$それは追加します$1$、当日$x+1$それは追加します$2$、当日$x+2$それは追加します$3$、など、その日$i$取得します$i-x+1$に限って$i \ge x$。 

タイプ 2 の場合、日から始まる場合$x$、そして当日$x$それは追加します$1$、当日$x+1$それは追加します$4$、当日$x+2$それは追加します$9$、など、その日$i$取得します$(i-x+1)^2$みんなのために$i \ge x$。 

タスクは、このような多数の更新を処理し、合計累積値の剰余を毎日出力することです。$10^9+7$。 

主な問題点は、すべての更新が配列のサフィックスに影響し、各更新には二次または線形パターンが増加するため、それらを毎日単純に適用するには各範囲を明示的に拡張する必要があり、これでは遅すぎることです。 

制約は非常に重要です。 の合計$n$そして$m$すべてのテスト ケースで最大でも$10^5$、だから$O(nm)$テストケースごとの解決策は不可能です。 平$O(n \sqrt{n})$危険だろう。 意図したソリューションでは、各更新を定数または対数の作業に減らし、最終的な配列を線形時間で再構築する必要があります。 

微妙な問題は、タイプ 2 では寄与が 2 次的に増加することです。多くの誤った解決策は、プレフィックス和を使用してタイプ 1 を正しく処理しますが、特に多項式を次のようにシフトする場合に、同じ考え方を 2 次の増加に拡張できません。$x$。 

もう 1 つの落とし穴は、寄与が複数の更新にわたって蓄積されることを忘れていることです。そのため、最初から再計算するのではなく、多くのシフトされたシーケンスを効率的に結合する必要があります。 

## アプローチ

 直接シミュレーションでは、各操作が独立して処理されます。 あらゆるクエリに対して$(op, x)$から反復します$x$に$n$、毎日の貢献度を計算し、それを配列に追加します。 タイプ 1 の計算$i-x+1$、タイプ 2 の計算$(i-x+1)^2$。 これは正しいですが、約$O(nm)$に達する$10^{10}$最悪の制約分布での操作であり、明らかに実行不可能です。 

両方の式の構造は、重要な観察を示唆しています。両方とも変数内の多項式です。$d = i-x+1$。 それらを拡張すると、$i$そして$x$、次の線形結合が得られます。$i^0, i^1, i^2$、さらに条件に応じて$x$。 これは、すべての更新が次の多項式として表現できることを意味します。$i$、ただし位置からのみアクティブ化されます$x$これからも。 「から」$x$「次へ」の状態が本当の複雑さです。 

これはまさに、差分配列が強力になるタイプの状況です。 すべての位置に値を直接加算する代わりに、多項式の寄与がどのように始まるかをエンコードします。$x$そして前進を続けます。 線形項の場合、1 つの差分配列で十分です。 二次項の場合、係数を追跡するために差分配列の階層が必要です。$i^2$、$i$、および定数部分。 

変換は、すべての寄与を次の二次多項式として書き直すことです。$i$次に、多項式の範囲加算トリックを使用します。3 つの差分配列を維持して、接頭辞の合計後に多項式の係数を回復します。$a i^2 + b i + c$1日あたり。 

すべての更新が位置で係数更新に変換されると、$x$、最終スイープを実行して、毎日の多項式値を再構築します。

 ## アルゴリズムのチュートリアル

 各更新を多項式寄与に変換し、差分配列を使用して適用します。 

### 1. 両方の更新タイプを次の多項式に展開します。$i$させて$d = i - x + 1$。 

タイプ 1 の場合:$$d = i - x + 1 = i + (1 - x)$$したがって、これは線形です$i$。 

タイプ 2 の場合:$$d^2 = (i - x + 1)^2 = i^2 + 2(1-x)i + (1-x)^2$$したがって、これは二次式です$i$。 

これは、すべての更新が次から始まる二次多項式に寄与することを示しています。$x$。 

### 2. 答えを 1 日あたりの二次関数として表します

 アレイを保守します$A[i], B[i], C[i]$最終的な答えは次のようになります。$$A[i] \cdot i^2 + B[i] \cdot i + C[i]$$私たちの目標は、これらの係数配列に範囲の更新を適用することです。 

### 3. 範囲のアクティブ化に差分配列を使用する

 各アップデートの影響が開始されるのは$x$、位置に係数を追加することを意味します$x$差分形式で、プレフィックスを合計した後、効果がすべてに伝播します。$i \ge x$。 

3 つの異なる配列を維持します。$A, B, C$。 更新のたびに、多項式をこれらの配列に拡張して得られた定数がインデックスに追加されます。$x$。 

重要な考え方は、「x から開始」は明示的な反復ではなくプレフィックス伝播によって処理されるということです。 

### 4. すべての更新を処理する

 クエリごとに、多項式の係数を計算し、それらを差分配列の 位置に追加します。$x$。 接尾辞を反復する必要はありません。 

### 5. プレフィックス合計を使用して最終的な配列を構築する

 差分配列に対してプレフィックスの合計を計算して再構築します$A[i], B[i], C[i]$。 次に、1 日あたりの最終的な答えを計算します。 

### なぜ効果があるのか

 すべての寄与は、固定インデックスから始まる多項式です。 差分配列は、「x から開始し、その後のすべてのインデックスに影響する」を x でのローカル更新に変換します。 多項式は加算で閉じられるため、係数空間内の寄与を合計することは、実際の値を毎日合計することと同じです。 プレフィックスの蓄積により、毎日、すべてのアクティブな更新の寄与を正確に受け取ることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def add(diff, i, val):
    if i < len(diff):
        diff[i] = (diff[i] + val) % MOD

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())

        A = [0] * (n + 3)
        B = [0] * (n + 3)
        C = [0] * (n + 3)

        for _ in range(m):
            op, x = map(int, input().split())
            x -= 1  # use 0-based

            if op == 1:
                # (i - x + 1) = i + (1 - x)
                add(A, x, 0)
                add(B, x, 1)
                add(C, x, 1 - x)

            else:
                # (i - x + 1)^2 = i^2 + 2(1-x)i + (1-x)^2
                add(A, x, 1)
                add(B, x, 2 * (1 - x))
                add(C, x, (1 - x) * (1 - x))

        a = b = c = 0
        res = []

        for i in range(n):
            a = (a + A[i]) % MOD
            b = (b + B[i]) % MOD
            c = (c + C[i]) % MOD

            val = (a * i * i + b * i + c) % MOD
            res.append(str(val))

        print(" ".join(res))

if __name__ == "__main__":
    solve()

最もデリケートな点は、周囲を正しく拡張することです。$x$。 使用する$1-x$一貫してオフバイワンエラーを回避します。 もう 1 つの微妙な点は、0 から始まるインデックスを使用していることです。$i$多項式内の値はループ変数に直接一致します。

 ## 特殊なケース

 重大なエッジケースは、複数の更新が同じ位置で開始される場合です。 すべての更新は同じ差分インデックスに適用されるため、それらの貢献は自然に蓄積されます。 たとえば、2 つのタイプ 2 更新が両方とも次から始まる場合、$x=1$、係数配列は 2 倍の 2 次係数を位置 1 で受け取り、プレフィックス伝播により両方が終日アクティブになることが保証されます。 

もう 1 つのエッジケースは次のような場合です$x=n$。 この場合、影響を受けるのは最終日のみです。 プレフィックスの伝播はインデックス以降のインデックスにのみ影響するため、差分更新は引き続き機能します。$x$、そのため、意図しない波及は発生しません。 

最後の微妙なケースは、次のような負の中間係数を処理することです。$1-x$。 すべてが剰余として解釈されるため、これらは安全です$10^9+7$各ステップで、モジュラー演算での正確性を維持しながら、値が範囲内に収まるようにします。
