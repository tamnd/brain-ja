 ## 問題の理解

プレーヤーは初期の正のパワー値から開始します$x$。 プレイヤーが部屋に入るたびに$i$、彼らはそこでモンスターと戦います。 戦いの結果は現在のパワーを変更します$x$モンスターの強さに応じて$a_i$。 現在の電力が少なくとも$a_i$、プレイヤーは簡単にモンスターを倒してその力を獲得し、新しい力は$x + a_i$。 それ以外の場合、プレイヤーはまだそれを倒しますが、苦戦し、力は$2x - a_i$。 どこかの時点でパワーがゼロまたはマイナスになると、実行はただちに失敗します。 

プレーヤーは有効な開始部屋 (DAG 内のソース) を選択し、最終的に部屋に到達するまで有向エッジに従います。$n$、遭遇した各モンスターと正確に 1 回戦います。 目標は、初期電力を最小限に抑えることです$x$有効な開始部屋と部屋へのパスが存在するようなもの$n$これに沿って、プレイヤーは決して死ぬことなく、部屋のモンスターを倒すことに成功します$n$。 

制約により、最大で$10^5$ノードと$2 \cdot 10^5$エッジ。 これは、すべてのパスを明示的にチェックするなどのことは不可能であるため、グラフのサイズが線形または線形に近い解決策であることを強く示唆しています。 DAG 内のパスの数は指数関数的に増加する可能性があるため、すべての単純なパスを動的にプログラミングすることさえ不可能です。 

微妙な困難は、状態遷移が単純な加算的な方法では線形ではないという事実から生じます。 次の力は次のことによって決まります。$x$閾値を越える$a_i$、低レジームでは、変換はアフィンですが、ペナルティが伴います。 これは、エッジに関する貪欲な推論や単純な最短経路の解釈が直接適用されないことを意味します。 

単純な間違いは、ステートメントで部屋のグラフについて言及しているため、すべてのノードを訪問する必要があると想定することです。 たとえば、すべてのノードをトラバースする必要がある場合、問題は DAG にわたるグローバルな順序付けの問題になりますが、実際には 1 つのパスをたどるだけです。

 ## アルゴリズムのチュートリアル

 私たちは定義します$dp[v]$ノードに入るときに必要な最小初期電力として$v$プレイヤーが安全にノードに到達できるように$n$選択した道に沿って必要なモンスターをすべて倒します。 

1. まず、逆のトポロジー順序でノードを処理します。 これにより、計算時に次のことが保証されます。$dp[v]$、 全て$dp[u]$外出する隣人のために$u$はすでに知られています。 
2. ノードで基本ケースを初期化します$n$。 このノードでは、モンスターを倒した後の要件はないため、戦闘自体の生存を確保するだけで済みます。 力を入れて入ったら$x$、結果は$x + a_n$いつ$x \ge a_n$、常に安全です。 それ以外の場合は、$2x - a_n$、これはプラスのままでなければなりません。 したがって、最小の実現可能なエントリー値は、次の 2 つのレジームのうちの最良のものとなります。$x \ge a_n$、与える$x = a_n$、 または$x < a_n$、与える$x > a_n/2$、 それで$x = \lfloor a_n/2 \rfloor + 1$。 設定しました$dp[n]$これら 2 つの値の最小値に設定します。 
3. For each node$v \ne n$、計算します$dp[v]$それぞれの出ていくエッジを考慮して$v \to u$。 最小エントリーパワーを見つけなければなりません$x$で$v$で戦った後のように$v$、結果として得られる電力は少なくとも$dp[u]$。 
4. 固定エッジの場合$v \to u$かどうかに応じて 2 つの体制に分かれます。$x \ge a_v$または$x < a_v$。 
5. もし$x \ge a_v$、戦いの後は$x' = x + a_v$。 条件$x' \ge dp[u]$になる$x \ge dp[u] - a_v$、と組み合わせる$x \ge a_v$。 これにより候補が得られます$x = \max(a_v, dp[u] - a_v)$。 
6. もし$x < a_v$、 それから$x' = 2x - a_v$。 条件$x' \ge dp[u]$になる$2x \ge dp[u] + a_v$、 それで$x \ge \left\lceil \frac{dp[u] + a_v}{2} \right\rceil$、追加の制約付き$x < a_v$。 これにより、範囲内にある場合は 2 番目の候補が得られます。 
7. 各エッジについて、最小の有効な候補を選択し、$dp[v]$はすべての出力エッジにわたる最小値です。 
8. 最後に、任意のソース ノード (入力エッジのないノード) から開始できるため、答えは次のようになります。$\min dp[v]$そのようなノードすべてにわたって。 

正確さは、ソースから$n$これらのローカル制約を満たす必要がある一連の必要なエントリ条件を誘導します。 各移行が既知の有効なサフィックスへの実現可能性を確実に保持することで、グローバルな実現可能性が保証されます。 

重要な不変条件は次のとおりです$dp[v]$は常に、から少なくとも 1 つの有効な継続を許可する真の最小エントリーパワーを表します。$v$に$n$。 すべての出力選択は、その必要な継続に対して正確に評価されるため、無効なパスは実行可能としてカウントされず、実行可能パスは除外されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        indeg[v] += 1

    topo = []
    stack = [i for i in range(1, n + 1) if indeg[i] == 0]

    while stack:
        u = stack.pop()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    dp = [10**30] * (n + 1)

    av = a[n]
    dp_n = min(av, (av // 2) + 1)
    dp[n] = dp_n

    for u in reversed(topo):
        if u == n:
            continue
        if not g[u]:
            continue

        best = 10**30

        for v in g[u]:
            av = a[u]
            need = dp[v]

            cand1 = max(av, need - av)

            cand2 = 10**30
            low = (need + av + 1) // 2
            if low < av:
                cand2 = low

            best = min(best, cand1, cand2)

        dp[u] = best

    ans = 10**30
    for i in range(1, n + 1):
        if indeg[i] == 0:
            ans = min(ans, dp[i])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、次数枝刈りを使用して DAG のトポロジー的順序を構築します。 これにより、計算時にノードを依存関係の逆順で処理することが保証されます。$dp$。 

DP アレイには、各ノードの最小限の安全なエントリ電力が保存されます。 基本ケースは、$n$戦闘公式の 2 つの体制分析を使用して直接計算されます。 

各ノードについて、出力エッジを反復処理し、遷移関数の 2 つの可能な領域から導出された 2 つの候補エントリ要件を計算します。 制約を強制するために注意が必要です$x < a_v$2 番目のケースでは、そうでない場合、導出により無効な遷移が許可されてしまいます。 

最後に、プレーヤーは有効なエントリ ポイントを選択できるため、ソース ノードのみを考慮します。

 ## 特殊なケース

 重要なエッジケースは、ノードを存続させるための唯一の有効な方法が低域レジームに入る場合です。$x < a_i$。 このような場合、誤って制約を無視すると、$x < a_i$実行不可能な候補者を選択することになります。 このアルゴリズムは、低レジームを使用する前にその実現可能性を明示的にチェックし、正確性を保証します。 

別のエッジ ケースが最終ノードで発生し、出力エッジが存在しないことで DP の意味が変化します。 このソリューションは、ノードでの戦闘のみの生存を計算することでこれを個別に処理します。$n$これにより、下流の制約が誤って適用されることがなくなります。 

最後の微妙なケースは、ノードに非常に大きなノードがある場合に発生します。$a_i$そして小さい$dp[u]$、たとえ高レジームの方が単純に見えても、低レジームから最適な移行が行われます。 2 つの候補を比較することで、両方の体制が対称的に評価されることが保証され、1 つの形式の移行への偏りが防止されます。
