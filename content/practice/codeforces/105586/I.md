 ## 解決策
 ## 問題の理解

 配列内に隠された有向構造が与えられます。 各都市には 1 つの発信テレポートがあり、すべてのテレポートは 1 つの都市に属します。 街を眺めるなら$i$をノードとしてエッジを描画します$i \to a_i$、システム全体は、すべてのノードの出次数がちょうど 1 つである関数グラフになります。 

開始都市からテレポートを繰り返したどり、最終的にはサイクルに陥ります。 この問題の要件は、都市に割り当てられたテレポートを交換できるようになった後、グラフが強く接続される必要があることです。 スワップは 2 つのノードの出力エッジを交換します。つまり、配列内の 2 つの値を交換します。$a$。 

目標は、任意のノードから有向パスを介して他のすべてのノードに到達できるように、必要なスワップの最小数を計算することです。 

制約により、最大で$10^5$テスト ケースごとのノード数 (合計)$10^5$テスト全体にわたって。 これにより、すべてのスワップや変換の繰り返しシミュレーションに対する二次推論が除外されます。 どのようなソリューションも、テスト ケースごとに基本的に線形または線形に近いものでなければなりません。 

微妙だが重要なエッジ ケースは、グラフが既に長さの単一の有向サイクルで構成されている場合です。$n$。 この場合、すでに強く結びついているので、答えはゼロになります。 例えば、$n=3$、$a=[2,3,1]$動作します。 この構造を認識せずに「コンポーネントを接続」しようとする単純なアプローチでは、依然として不必要なスワップが実行される可能性があります。 

もう 1 つの特殊なケースは、構造が複数のサイクルとそれらにつながるツリーの素結合である場合です。 グラフには常に出次数 1 がありますが、複数のサイクルがある場合があります。 例えば、$a=[2,1,4,3]$2 つの 2 サイクルに分割されます。 これは強く関連しているわけではなく、スワップがサイクルをどのようにマージできるかを考慮しない限り、サイクルを個別にカウントするだけの単純な推論は失敗します。 

## アプローチ

 配列によって生成されるグラフは、古典的な関数グラフです。 すべての接続されたコンポーネントには、1 つの有向サイクルが含まれており、そこに木がフィードされる可能性があります。 ただし、すべてのノードには出力エッジが 1 つだけあるため、到達可能性はこれらのサイクルの構造によって完全に制御されます。 

強引なアイデアは、スワップをシミュレートすることです。 すべての位置のペアを試し、それらを交換し、グラフを再構築し、すべてのノードから DFS を実行することで強く接続されるかどうかを確認できます。 強い接続性を確認すること自体は、$O(n)$、そして、あります$O(n^2)$スワップ、それにつながる$O(n^3)$テストケースごとに。 これはすぐには不可能です$n=10^5$。 

たとえチェックを減らしたとしても、中心的な問題は残ります。つまり、置換のような構造を変更し、目標のグローバル構造に到達するために最小限のスワップを要求しているということです。 重要な観察は、ターゲット構造がすべてのノードをカバーする単一サイクルでなければならないということです。これは、関数グラフでは、強力な接続性がすべてのノードの次数も正確に 1 であることを意味し、グラフが単一の有向サイクルになることを強制するためです。 

したがって、問題は次のようになります。現在の配列を、長さの 1 サイクルで構成される順列に変換したいのです。$n$、スワップを使用し、各スワップが配列内の 2 つの値を交換します。 これは、配列を単一のサイクル順列に再配置することに相当し、問題は、現在のマッピングがそのようなサイクル構造からどの程度離れているかということになります。 

決定的な洞察は、配列を宛先の順列として解釈することです。 それぞれの値なので、$a_i$が出力エッジ ソースの位置として 1 回だけ使用されると、この構造は出力エッジに関してノードを考慮した後の順列のように動作します。 関数グラフの各サイクルは、この順列分解のサイクルに対応します。 

2 つの値を交換すると、制御された方法でサイクルが結合または分割されます。 既知の結果は、スワップを使用すると、任意の順列を 1 つのサイクルにマージでき、必要なスワップの最小数は存在するサイクルの数によって決まるということです。 2 つのサイクルを 1 つに接続できるため、スワップごとにサイクル数を最大 1 つ減らすことができます。 

グラフに$c$サイクルの場合、少なくとも必要です$c-1$これは、異なるサイクルの要素を常に交換することで貪欲に実現できます。 

したがって、答えは関数グラフ内の有向サイクルの数を数えることに帰着します。

 ## アルゴリズムのチュートリアル

 1. 配列から暗黙的に関数グラフを構築する$a$、各ノード$i$を指す$a_i$。 エッジを直接たどることができるため、この表現はトラバース以降は明示的に必要ありません。 
2. すべてのノードを走査し、標準の訪問状態を使用してサイクルを検出します。 訪問されていない各ノードについて、訪問されたノードに到達するか、現在の再帰パス内のノードに戻るまで、出力エッジに沿って前進を開始します。 現在のパスのノードに再び入った瞬間に、サイクルが識別されたことになります。 
3. 異なるサイクルがいくつ存在するかを数えます。 各ノードは正確に 1 つのサイクルに属するか、そのサイクルにつながるチェーンの一部ですが、すべてのチェーンは最終的には一意のサイクルに入るため、各ノードはトラバース中に曖昧さなく割り当てられます。 
4. サイクル数が$c$、出力$c - 1$。 

このステップが有効である理由は、各スワップが 1 つの発信エッジ接続を 2 つのサイクル間でリダイレクトすることにより、正確に 2 つのサイクルをマージできるためです。 2 つのサイクルがマージされると、到達可能性の観点から 1 つのサイクルとして動作します。 

### なぜ効果があるのか

 関数グラフは、ツリーが結合された独立したサイクルに分解されますが、強力な接続性を実現するには、個別のサイクルへの分岐をすべて排除する必要があります。 有効な最終構造はすべて、すべてのノードにわたる単一の有向サイクルでなければなりません。 各スワップはサイクル数を最大 1 つしか減らすことができません。これは、以前に分離されていた 2 つのサイクルを接続できるものの、一度に 3 つ以上のコンポーネントをマージできないためです。 最初からあるので、$c$少なくともサイクル$c-1$マージが必要であり、2 つの異なるサイクルを繰り返し接続することによって正確にこの境界を達成する建設的なスワップ シーケンスが存在します。 これにより、最適性と実現可能性の両方が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = [0] + list(map(int, input().split()))

        vis = [0] * (n + 1)
        cycles = 0

        for i in range(1, n + 1):
            if vis[i]:
                continue

            cur = i
            stack_index = {}
            path = []

            while True:
                if vis[cur]:
                    break
                if cur in stack_index:
                    cycles += 1
                    break

                stack_index[cur] = len(path)
                path.append(cur)
                cur = a[cur]

            for v in path:
                vis[v] = 1

        print(max(0, cycles - 1))

if __name__ == "__main__":
    solve()
```この実装では、未訪問の各ノードから順方向ウォークが実行されます。 の`stack_index`ディクショナリは、現在のパスへのバックエッジを検出するために使用され、これはサイクル発見を示します。 走査が完了すると、そのウォークで訪問したすべてのノードは処理済みとしてマークされるため、再訪問することはありません。 

微妙な点は、すべてのノードが 1 つのトラバーサルに割り当てられているため、現在のパスを再訪するときに明示的にサイクルを検出するだけであっても、接続されているすべての機能コンポーネントが 1 つのサイクル検出イベントに寄与するため、サイクル カウントは正しいままであるということです。

 ## 特殊なケース

 次のような単一ノードのグラフ$n=1, a=[1]$すぐにサイクルカウント 1 が形成され、答えは 0 になります。 トラバーサルはノード 1 から開始され、自己ループ サイクルを検出し、そのサイクルが訪問したことをマークします。 

次のような完全な巡回置換$a=[2,3,4,1]$は、1 つのサイクル検出イベントを伴う 1 つのトラバースとして処理されます。 パスをマークした後に新しい未訪問の開始点が残らないため、アルゴリズムはパスを誤って分割することはありません。 

次のような素サイクルのケース$a=[2,1,4,3]$この処理は、ノード 1 から開始して 1 つのサイクルを検出し、次にノード 3 から開始して別のサイクルを検出することによって処理されます。 各コンポーネントは正確に 1 つのサイクル検出に寄与し、正しいサイクル カウント 2 と応答 1 を生成します。 

サイクルへの異常に見えるチェーンは、サイクルのエントリのみがバックエッジ条件をトリガーするため、依然として単一の検出されたサイクルに崩壊します。 ツリー ノードは単に訪問済みとしてマークされるだけで、サイクル数が増えることはありません。
