 ## 解決策
 ## 問題の理解

 文字列があります`S`長さの`N`そして、少なくとも 1 つの連続する部分文字列が正確に存在するかどうかを判断する必要があります。`M`文字は左から右に読んでも右から左に読んでも同じです。 

たとえば、次の場合`S = "ajabbaaksj"`そして`M = 4`、部分文字列`"abba"`は回文なので、答えは`Accept`。 部分文字列は特定の位置から始まる必要はなく、多数の候補ウィンドウが存在する可能性があります。 正確な長さの有効な回文が 1 つだけ必要です`M`。 

境界があるため、単純なアプローチは使用できなくなります。 以来`N`到達できる`5 * 10^5`、を調べるアルゴリズム`M`それぞれの大まかな文字`N`開始位置で実行できる可能性があるのは約`N * M`キャラクターの比較。 最悪の場合、`N = M = 5 * 10^5`、それは約です`2.5 * 10^11`1 秒の制限をはるかに超えた比較です。 実行時間が線形または線形に近いソリューションが必要です。`N`。 

誤って処理されやすい境界ケースがいくつかあります。 いつ`M = 1`、個々の文字はすべて回文なので、答えは常に次のようになります。`Accept`。 例えば、`N = 1`、`M = 1`、`S = "a"`与える`Accept`。 2 つの文字の間に中心がある回文のみをチェックするソリューションでは、このケースは誤って拒否されます。 

のパリティ`M`も重要です。 次のような偶数回文`"abba"`2 つの文字の間に中心がありますが、次のような奇妙な回文は`"aba"`キャラクターを中心に据えています。 例えば、`N = 3`、`M = 3`、`S = "aba"`与える`Accept`。 偶数長の中心のみを処理する実装では、これを見逃してしまいます。 

回文は、文字列の境界で正確に開始または終了することもできます。 例えば、`N = 4`、`M = 4`、`S = "abba"`与える`Accept`。 候補中心の両側に文字を必要とするインデックス付けスキームでは、この有効な回文が誤って破棄される可能性があります。 

最後に、より長い回文を作成します。`M`答えるだけで十分です`Accept`なぜなら、適切な長さのすべての接頭辞または接尾辞が必ずしも回文であるとは限りませんが、回文には、その中心付近の長さと同じパリティを持つあらゆる長さの回文部分文字列が含まれているからです。 より直接的には、アルゴリズムは回文が正確かどうかをチェックする必要があります。`M`単に任意の長い回文を見つけるのではなく、存在します。 例えば、`S = "abcba"`と`M = 4`唯一の長さ 5 の回文には長さ 4 の回文が含まれていないため、拒否する必要があります。 これが、要求された長さのパリティを無視できない理由です。 

## アプローチ

 直接的なアプローチは、長さのすべての部分文字列を列挙することです。`M`そしてそれがその逆と等しいかどうかをチェックします。 がある`N - M + 1`そのような部分文字列。 1 つの部分文字列をチェックするには`O(M)`最悪の場合、不一致を発見する前に文字のおよそ半分を比較する必要があるため、合計は次のようになります。`O((N - M + 1)M)`、つまり`O(NM)`最悪の場合。 と`N = M = 5 * 10^5`、これはおよそに達することができます`2.5 * 10^11`キャラクターの比較。 ブルートフォース手法は、考えられるすべての候補を明示的にテストするため正しいですが、繰り返される作業の量が多すぎます。 

有益な観察は、実際には、考えられるすべての部分文字列を個別に考慮しているわけではないということです。 回文は、その中心と半径によって完全に特徴付けられます。 すべての位置について、回文がその中心の周りにどれだけ広がるかを知っていれば、固定長の質問にすぐに答えることができます。 

センターには2種類あります。 奇数長の回文は中心に文字がありますが、偶数長の回文は 2 つの文字の間の隙間が中心になります。 Manacher のアルゴリズムは、線形時間で考えられるすべての中心の最大回文半径を計算します。 これらの半径がわかったら、回文の長さが次のとおりであるかどうかを確認します。`M`存在する場合は単純スキャンになります。 

奇数のために`M`、長さの回文`M`半径があります`(M + 1) // 2`通常の Manacher 表現では、半径は中心の文字自体をカウントします。 偶数の場合`M`、その半分の長さは`M // 2`、対応する偶数中心半径は少なくともその値でなければなりません。 

ブルートフォース手法は、各ウィンドウを個別に検証するため機能します。 隣接するウィンドウがほぼすべての同じ比較を繰り返すため、失敗します。 Manacher のアルゴリズムは、既知の回文間隔に関する情報を再利用することで、この繰り返しを除去します。

 | ブルートフォース |`O(NM)`|`O(1)`| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. すべての文字ペアの間と両端にセパレータを挿入して、変換された文字列を作成します。 例えば、`"abba"`になる`"#a#b#b#a#"`。 これにより、すべての回文に均一な中心表現が与えられるため、奇数と偶数の長さを同じ半径配列で処理できます。 
2. 変換された文字列に対して Manacher のアルゴリズムを実行します。 変形した位置ごとに`i`、 店`p[i]`、対称的に一致できる文字の数`i`。 このアルゴリズムは、現在知られている最も右の回文とその中心を維持します。 新しい位置が回文内にある場合、その初期半径は、現在の右境界によって制限されたミラー位置からコピーできます。 明示的に比較する必要があるのは、その境界を越える文字のみです。 
3. 半径が回文の長さに十分な大きさであるすべての変換された中心をチェックします。`M`。 変換された表現では、元の長さの回文`M`少なくとも次の変換された回文半径に相当します。`M`。 したがって、もしあれば、`p[i] >= M`、答えは`Accept`。 
4. 少なくとも半径を持つ変換された中心がない場合`M`、出力`Reject`。 すべての元の部分文字列回文には、変換された文字列内に対応する中心があるため、候補が見逃されることはありません。 

変換された表現が機能する理由は、元の各文字と各セパレータが交互の位置を占めるためです。 の回文`M`元の文字が正確にまたがる`2M`中心の周りのエッジが変換されるため、変換された半径は`M`このような部分文字列を含めるには正確に十分です。 

### なぜ効果があるのか

 考えられるすべての中心について、`p[i]`は、回文であるその中心の周りの最大の対称領域を表します。 元の文字列内のすべての回文には、長さが奇数であるか偶数であるかに関係なく、これらの変換された中心の 1 つがあります。 長さ-`M`したがって、回文は、少なくとも何らかの中心が半径を変換したときに正確に存在します。`M`。 Manacher はこれらすべての最大半径を正確に計算するため、スキャンで既存の回文を見逃したり、非回文を受け入れたりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    S = input().strip()

    # Transform the string so odd and even palindromes
    # are handled uniformly.
    T = "#" + "#".join(S) + "#"
    n = len(T)

    p = [0] * n
    center = 0
    right = 0

    for i in range(n):
        mirror = 2 * center - i

        if i < right:
            p[i] = min(right - i, p[mirror])

        while (
            i - p[i] - 1 >= 0
            and i + p[i] + 1 < n
            and T[i - p[i] - 1] == T[i + p[i] + 1]
        ):
            p[i] += 1

        if i + p[i] > right:
            center = i
            right = i + p[i]

    for radius in p:
        if radius >= M:
            print("Accept")
            return

    print("Reject")

if __name__ == "__main__":
    solve()
```変換により、元の各文字の間にセパレータが作成されます。 これが次のような回文を作るものです`"aba"`そして次のようなもの`"abba"`Manacher のアルゴリズムと構造的には同一に見えます。 それらの中心は単に異なる変換された位置です。 

の`p`配列には、変換された各位置の周囲の最大半径が格納されます。`center`そして`right`これまでに処理した回文のうち、最も右に到達する回文を記述します。 いつ`i < right`、周りの回文`i`ミラーリングされた位置があります`2 * center - i`。 既知の半径により、有効な開始値が得られます。`p[i]`したがって、すでに他の場所で実行された比較を繰り返すことはありません。 

展開ループは、変換された文字列の両側でガードされます。 これにより、回文が配列のいずれかの端に達したときに、配列の外側の位置にアクセスすることが回避されます。`S`。 Python の整数はオーバーフローしないため、半径やインデックスに特別な処理は必要ありません。 

最終的な条件は、`radius >= M`、 ない`radius == M`。 より大きな回文には、要求された長さに適切なパリティがある場合にのみ、要求された長さの回文が含まれる可能性があるため、これには注意が必要です。 ただし、変換された表現では、半径は`R`からのすべての元の回文の長さを表します。`1`を通して`R`対応する中心構造を持ち、半径は少なくとも`M`これはまさに元の長さの回文の条件です`M`その中心のあたり。

### 構築された例

 次のことを考慮してください。```
5 4
abcba
```文字列の長さは回文です`5`、ただし長さの回文はありません`4`。 変換された文字列は、`#a#b#c#b#a#`。 最大の半径は中心文字で発生します`c`。 

| センター | キャラクター | 半径`p[i]`|`p[i] >= 4`|
 | --- | --- | --- | --- |
 | 1 |`a`| 1 | いいえ |
 | 3 |`b`| 1 | いいえ |
 | 5 |`c`| 5 | はい |

 この表は微妙な点を明らかにしています。 中心には半径があります`5`なので、アルゴリズムは単純です`p[i] >= M`テストは受け入れられるようです`M = 4`。 それはオリジナルの長さの解釈としては正しくありません。 変換された半径`5`元の回文の長さに相当します`5`、同じ中心の次に小さい回文は長さがあります。`3`、 ない`4`。 

このため、実装では次のパリティを区別する必要があります。`M`マナハの変換された半径を解釈するとき。 したがって、上記のコードにはパリティを意識した最終チェックが必要です。 修正された実装を以下に示します。```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    S = input().strip()

    T = "#" + "#".join(S) + "#"
    n = len(T)

    p = [0] * n
    center = 0
    right = 0

    for i in range(n):
        mirror = 2 * center - i

        if i < right:
            p[i] = min(right - i, p[mirror])

        while (
            i - p[i] - 1 >= 0
            and i + p[i] + 1 < n
            and T[i - p[i] - 1] == T[i + p[i] + 1]
        ):
            p[i] += 1

        if i + p[i] > right:
            center = i
            right = i + p[i]

    # In the transformed string:
    # odd original length M has a character at the center,
    # even original length M has a separator at the center.
    if M % 2 == 1:
        needed = M
        for i in range(1, n, 2):
            if p[i] >= needed:
                print("Accept")
                return
    else:
        needed = M
        for i in range(0, n, 2):
            if p[i] >= needed:
                print("Accept")
                return

    print("Reject")

if __name__ == "__main__":
    solve()
```変換された位置は、元の文字と区切り文字の間で交互になります。 文字の中心は奇数のインデックスで発生しますが、セパレータの中心は偶数のインデックスで発生します。 したがって、奇数長の回文は文字の中心でのみチェックする必要があり、偶数長の回文は区切り文字の中心でのみチェックする必要があります。 これにより、次のようなパリティ ミスが解消されます。`"abcba"`と`M = 4`。
