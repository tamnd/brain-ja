 ## 問題の理解

 夜は N 個の位置の配列として見ることができます。 位置 i には、i 番目の時間に Beza が消費した飲み物が格納されます。 バーには M 個のドリンク名があり、それぞれの名前にアルコール量が関連付けられています。 

タイプ 1 クエリは、ある配列位置を別のドリンクに変更します。 タイプ 2 のクエリは、連続した部分配列 [L,R] について質問します。その時間内に消費されたアルコールの総量は二日酔いを引き起こすのに十分ですか?

 間隔に K=R−L+1 時間が含まれると仮定します。 Beza は 60,000 分間飲酒に費やしているため、二日酔いを引き起こさない最大アルコール量はその半分の 30,000 分です。 したがって、答えは次のようになります。`YES`まさにいつ

 i=L ∑ R V i >30(R−L+1)、

 ここで、V i は位置 i での現在の飲み物のアルコール量です。 平等が与えるもの`NO`, 制限額と同じ量であればまだ安全であるためです。 

最初の N 個のドリンク名は初期配列を表します。 次の M 行は、飲み物の名前からアルコールの量までの辞書を形成します。 次に、Q の動的操作があります。 関連する数量はすべて 2⋅10 5 に達する可能性があるため、各クエリの間隔全体をスキャンするには、最悪の場合、およそ NQ=4⋅10 10 の要素の訪問が必要になる可能性があります。 これは 2 秒の制限が許容する時間をはるかに超えています。 更新とクエリごとに対数的な作業が必要です。

## アプローチ

 直接的な解決策は、すべての飲み物の名前をそのアルコール値に変換し、それらの値を配列に格納することです。 タイプ 1 クエリの場合、1 つの配列要素を置き換えます。 タイプ 2 クエリの場合、L から R までループし、すべての値を加算し、結果を 30(R−L+1) と比較します。 これは正しいです。クエリでは、その間隔内の現在の値の合計が正確に求められるからです。 

問題は範囲クエリのコストです。 1 つのクエリで N 個の要素を検査でき、Q 個のクエリでは最悪のケースは O(NQ) になります。 N=Q=200000 の場合、他の操作を考慮する前に、配列アクセスは最大 40,000,000,000 回になります。 2 秒の制限により、このアプローチは除外されます。 

有益な観察は、すべてのタイプ 2 クエリは範囲合計のみを必要とするのに対し、すべてのタイプ 1 クエリは 1 つの値のみを変更するということです。 これはまさにフェンウィックツリーが扱う動作パターンです。 フェンウィック ツリーは部分和を格納するため、ポイントの変更とプレフィックスの合計には両方とも O(logN) 時間がかかります。 プレフィックスの合計が利用可能になると、[L,R] の合計は次のように取得されます。`prefix(R) - prefix(L-1)`。 

重要な簡略化は、二日酔いの状態を 2 つの追加量間の比較として書き直すことです。 分を個別に考える代わりに、アルコール値のみをデータ構造に保存し、しきい値を 30(R−L+1) として直接計算できます。 名前が値に変換された後は、ドリンクに関するその他の情報は必要ありません。 

間隔を直接合計すると必要な量が正確に得られるため、総当り攻撃は機能しますが、長い間隔が多数クエリされると失敗します。 ポイントの変更と範囲の合計のみが必要であるという観察により、繰り返しのスキャンをフェンウィック ツリーに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) 最悪の場合 | O(N+M) | 遅すぎる |
 | 最適 | O((N+M+Q)logN) | O(N+M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のドリンク名と M ドリンク値を読み取ります。 クエリは飲み物を名前で参照するため、各名前からアルコール量へのマッピングを保存します。 
2. 初期スケジュール内のすべての飲み物をアルコール量の数値に変換します。 配列内に数値を保持すると、クエリの処理中に辞書検索が繰り返されることがなくなります。 
3. 結果の配列上にフェンウィック ツリーを構築します。 ツリーはプレフィックスの合計を表しており、2 つのプレフィックスの合計を減算することで任意の間隔の合計を取得できます。 
4. タイプ 1 クエリの場合`1 X Y`、飲み物のアルコール価を調べる`Y`。 位置 X の古い値を次のようにします。`old`そして新しい値は`new`。 違いを適用する`new - old`位置 X のフェンウィック ツリーに追加し、格納されている配列値を次のように置き換えます。`new`。 

位置 X を含むすべてのフェンウィック ノードは、保存されている合計を正確にその量だけ変更するだけでよいため、差による更新で十分です。 
5. タイプ 2 クエリの場合`2 L R`、計算します

 S=合計(L,R)

 フェンウィックツリーを使用。 この間隔には R−L+1 時間が含まれるため、安全なアルコール制限は次のようになります。 

30(R−L+1)。 

印刷する`YES`S>30(R−L+1)の場合、および`NO`さもないと。 
6. すべてのクエリを元の順序で処理します。 更新により現在のスケジュールが変更されるため、それ以降のすべての範囲クエリでは、変更されたフェンウィック ツリーと配列を使用する必要があります。 

不変条件は、処理されたすべての操作の後、フェンウィック ツリーにはすべてのプレフィックスの現在のアルコール値の正確な合計が含まれ、別の配列にはすべての位置の現在の値が含まれるということです。 ポイント更新では両方の表現が同じ量だけ変更されるため、不変式は更新されても存続します。 すべての範囲の合計は 2 つの正しいプレフィックスの合計から取得されるため、タイプ 2 のクエリはすべて、現在のアルコールの正確な合計と 1 時間あたりの正確な 30 リットル制限を比較します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, delta):
        while i <= self.n:
            self.bit[i] += delta
            i += i & -i

    def prefix_sum(self, i):
        result = 0
        while i > 0:
            result += self.bit[i]
            i -= i & -i
        return result

    def range_sum(self, l, r):
        return self.prefix_sum(r) - self.prefix_sum(l - 1)

def solve():
    n, m, q = map(int, input().split())

    drinks = input().split()

    value = {}
    for _ in range(m):
        name, v = input().split()
        value[name] = int(v)

    arr = [value[name] for name in drinks]

    fw = Fenwick(n)

    for i, v in enumerate(arr, 1):
        fw.add(i, v)

    out = []

    for _ in range(q):
        query = input().split()
        t = int(query[0])

        if t == 1:
            x = int(query[1])
            y = query[2]

            new_value = value[y]
            old_value = arr[x - 1]

            fw.add(x, new_value - old_value)
            arr[x - 1] = new_value

        else:
            l = int(query[1])
            r = int(query[2])

            total = fw.range_sum(l, r)
            limit = 30 * (r - l + 1)

            if total > limit:
                out.append("YES")
            else:
                out.append("NO")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```辞書`value`名前からアルコールへの変換を予想される O(1) 時間で実行します。 初期スケジュールは、動的操作が開始される前に 1 回変換されます。 

の`arr`配列には、現在の数値がすべての位置に格納されます。 フェンウィック ツリーは集計合計のみを保存するため、更新時にこれが必要になります。そのため、伝播する必要がある差分を計算するには古い値が必要です。 

フェンウィック ツリーは、すべての配列値を追加することによって初期化されます。 上記の単純な実装では、これには O(NlogN) がかかります。 O(N) 構成も可能ですが、N≤2⋅10 5 であるため、ここでは不要です。 

位置の更新の場合`x`、式`new_value - old_value`正、負、またはゼロにすることができます。 ゼロの差は無害であり、関連するすべての合計は変更されないままになります。 

範囲クエリで使用されるのは、`prefix_sum(r) - prefix_sum(l - 1)`。 の`l - 1`これは、両側の間隔を包含するものです。 入力位置には 1 のインデックスが付けられるため、フェンウィック ツリーも意図的に 1 のインデックスが付けられます。 

Python の整数はオーバーフローしないため、最大の合計は 100⋅200000=20,000,000 にすぎません。 出力はリストに蓄積され、一度書き込まれるため、過度の呼び出しが回避されます。`print`。
