 ## 解決策
 ## 問題の理解

 (N \times M) 個のグリッドがあります。 各セルには、岩石に衝突する前にその場所で掘削できる最大深さが含まれています。 プールを形成するには、正確に (S) 個のセルを選択する必要があります。 選択したセルは共有側を介して接続する必要があり、プールは 1 つの均一な深さになります。 

選択したセルで深さ (7) までのみ掘削が許可されている場合、プール全体を (7) より深くすることはできません。 したがって、接続された (S) セルのセットの場合、達成可能な深さはそれらのセルの中での最小の深さになります。 課題は、その最小値を最大化することです。 

候補の深さ (D) について考える便利な方法は、値が (D) より小さいすべてのセルを破棄することです。 残りのセルはまさに深さ (D) のプールを構築できる場所です。 問題は、これらの残りのセルに少なくとも (S) 個のセルを含む連結成分が含まれているかどうかになります。 

セルの総数は最大でも (10^6) であるため、グリッド全体を繰り返して多数の深さの候補を調べるアルゴリズムはコストがかかりすぎます。 (10^6) 個の異なる深度値が存在する可能性があり、考えられるすべての深度に対して (O(NM)) 個のスキャンを (O((NM)^2)) アルゴリズムにし、最悪の場合、約 (10^{12}) 個のセル検査に達します。 セルの注文コストとは別に、線形に近いものが必要です。 

寸法自体が非常に大きくなる場合もあります。 (N=M=1000) のグリッドには既に (10^6) 個のセルが含まれており、どちらの次元も (10^6) までの大きさにすることができます。 これにより、(N^2)、(M^2)、または繰り返されるフルグリッド走査に依存するアルゴリズムが除外されます。 メモリ制限は、すべてのセルに大きな Python オブジェクトを格納することは可能な限り避けるべきであることも意味します。 

表面的に正しいソリューションが失敗する可能性がある特殊なケースがいくつかあります。 

(S=1) の場合、単一セルを超える接続は必要ありません。 例えば、```
1 1 1
42
```答えは(42)です。 常にセルを隣接セルに接続しようとするソリューションでは、プールが存在しないと誤って結論付けられてしまいます。 

もう 1 つの重要なケースは、高価値のセルが切断された場合です。 考慮する```
2 1 3
10 1 10
```答えは(10)ではなく(1)です。 深さ (10) のセルが 2 つありますが、深さ (1) のセルによって区切られています。 接続性を考慮せずに単に (S) 最大値を取るソリューションでは、間違った結果が返されます。 

逆の状況も重要です。 連結コンポーネントに (S) 個を超えるセルが含まれている場合、ちょうど (S) 個のセルを使用できます。 例えば、```
3 1 5
8 8 8 8 8
```コンポーネントには 5 つのセルが含まれていますが、答えは (8) です。 コンポーネントに正確に (S) セルが必要なソリューションは、コンポーネントを誤って拒否します。 

最後に、(S=N\cdot M) の場合、すべてのセルがプールに属している必要があります。 例えば、```
4 2 2
5 7
8 6
```グリッド全体の最小深さは (5) であるため、答えは (5) です。 大きな値の高い領域を見つけるとすぐに停止するメソッドは、(S) がグリッド サイズ全体と等しい場合、プールにはすべてのセルが含まれている必要があるという事実を見落とす可能性があります。 

## アプローチ

 直接的なアプローチは、考えられるすべてのプールの深さを試してみることです。 候補の深さ (D) の場合、少なくとも (D) の値を持つセルのみを保持し、それらのセルに対してフラッド フィルを実行し、接続されたコンポーネントに少なくとも (S) のセルがあるかどうかを確認します。 これは正しいです。そのようなコンポーネント内のすべてのセルは深さ (D) をサポートでき、少なくとも (S) 個のセルを持つ連結コンポーネントには正確に (S) 個のセルの連結されたサブセットが含まれるためです。 

問題は候補深さの数です。 (NM) 個もの異なる値が存在する可能性があります。 最悪の場合、1 回の塗りつぶしには (O(NM)) 時間がかかるため、すべての個別の深さを確認するには (O((NM)^2)) かかります。 (NM=10^6) の場合、潜在的に (10^{12}) 回のセル訪問になります。 

すべての深さを個別にチェックするのではなく、深さを最大から最小まで処理することで、アイデアを改善できます。 

深さが少なくとも (D) であるすべてのセルを既にアクティブ化していると仮定します。 その瞬間、アクティブなセルは、深さのプール (D) に関連するグラフを正確に形成します。 しきい値を下げると、新しく活性化されたセルがこのグラフに追加されるだけです。 接続性は増大する一方なので、接続されたコンポーネントを最初から再計算する必要はありません。 

これはまさに、Disjoint Set Union 構造が設計された目的です。 アクティブ化された各セルは、独自のコンポーネントとして開始されます。 アクティブ化されたセルにアクティブ化された隣接セルがある場合は常に、それらのコンポーネントをマージします。 DSU はすべてのコンポーネントのサイズを保存するため、セルをアクティブ化した後、そのコンポーネントがサイズ (S) に達したかどうかをすぐに確認できます。 

コンポーネントがサイズ (S) に達する最初の深さが答えです。 降順で処理するということは、以前にアクティブ化されたすべてのセルが少なくとも現在の深さ以上の深さを持っていることを意味します。 その結果、深さ (D) でサイズ (S) に達するコンポーネントは深さ (D) の有効なプールを与えますが、それよりも早く停止しているため、これより大きな深さは (S) 接続されたセルをサポートできません。 

慎重に扱う価値のある Python 固有の実装の詳細が 1 つあります。 グリッドには (10^6) 個のセルを含めることができるため、次のようなタプルを格納します。`(depth, row, column)`かなりのメモリ オーバーヘッドが発生します。 代わりに、各セルは、その深さと平坦化されたセル インデックスの両方を含む 1 つの整数で表されます。 (NM\le10^6<2^{20}) なので、インデックスには下位 20 ビットで十分です。 残りのビットは深さを格納します。 Python の組み込みソートにより、これらのパックされた整数を効率的に順序付けることができます。 

DSU 配列は次を使用して保存されます。`array('i')`これは、Python のはるかに大きな整数ごとのオブジェクト表現の代わりに、エントリごとに 4 バイトを使用します。 アクティブなセルは次の場所に保存されます。`bytearray`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((NM)^2)) | (O(NM)) | 遅すぎる |
 | 最適 | (O(NM\log(NM))) | (O(NM)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 次元グリッドを (0) から (NM-1) までのインデックスに平坦化します。 すべてのセルを、その深さとフラット化されたインデックスを含む 1 つのパックされた整数として格納します。 これらの整数を降順に並べ替えると、最も深いセルから最も浅いセルまでのセルが得られます。 
2. セルごとに最初に 1 つの個別のコンポーネントを含む DSU 構造を作成します。 また、`active`配列。 セルは、下降スイープでセルに到達した後にのみアクティブになります。 
3. 深さの降順でセルを処理します。 セルが見つかったら、それをアクティブ化し、そのコンポーネントのサイズを 1 に等しくします。 
4. セルに隣接する可能性のある 4 つのグリッドを確認します。 すでにアクティブになっているすべてのネイバーについて、2 つの DSU コンポーネントをマージします。 非アクティブなネイバーの深さは現在のしきい値より小さく、現在の深さのプールに属することができないため、アクティブなネイバーのみをマージします。 
5. 新たにアクティブ化されたセルの可能な結合をすべて行った後、その DSU コンポーネントのサイズを検査します。 そのサイズが少なくとも (S) の場合は、現在のセルの深さを返します。 
6. コンポーネントが (S) セルに達するまで続行します。 このようなコンポーネントは、深さが少なくとも報告された値であるセルのみで構成され、接続されています。 少なくとも (S) 個のセルが含まれているため、そこから正確に (S) 個の接続されたセルを選択できます。 

(S) 個を超えるセルを含む連結コンポーネントには、常にちょうど (S) 個のセルの連結サブセットが含まれるのはなぜですか? 任意の頂点から開始して、コンポーネントに属する隣接する頂点を繰り返し追加します。 コンポーネントが接続されているため、このプロセスは正確に (S) 個の頂点が選択されるまで続行できます。 

スイープ全体の背後にある不変条件は、深さ (D) を処理する直前に、すべてのアクティブ セルが少なくとも深さ (D) を持ち、DSU コンポーネントがまさにそれらのアクティブ セルの接続コンポーネントであるということです。 現在のセルがアクティブ化されると、すでにアクティブな隣接セルへのエッジのみを追加する必要があるため、不変条件は true のままになります。 したがって、コンポーネントが最初に (S 個の) セルに到達すると、その深さで実行可能なプールが表されます。 深さは最大から最小の順に処理されるため、最初の深さが最大になります。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

SHIFT = 20
MASK = (1 << SHIFT) - 1

def solve():
    S, N, M = map(int, input().split())
    total = N * M

    # Pack (depth, index) into one integer.
    # The lower 20 bits store the index because total <= 10^6 < 2^20.
    cells = []
    append = cells.append

    idx = 0
    for _ in range(N):
        row = map(int, input().split())
        for depth in row:
            append((depth << SHIFT) | idx)
            idx += 1

    cells.sort(reverse=True)

    parent = array('i', range(total))
    size = array('i', [1]) * total
    active = bytearray(total)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)

        if a == b:
            return a

        if size[a] < size[b]:
            a, b = b, a

        parent[b] = a
        size[a] += size[b]
        return a

    for code in cells:
        depth = code >> SHIFT
        idx = code & MASK

        active[idx] = 1
        root = idx

        row = idx // M
        col = idx - row * M

        if row > 0:
            other = idx - M
            if active[other]:
                root = union(root, other)

        if row + 1 < N:
            other = idx + M
            if active[other]:
                root = union(root, other)

        if col > 0:
            other = idx - 1
            if active[other]:
                root = union(root, other)

        if col + 1 < M:
            other = idx + 1
            if active[other]:
                root = union(root, other)

        root = find(root)

        if size[root] >= S:
            print(depth)
            return

if __name__ == "__main__":
    solve()
```入力は行ごとに読み取られるため、プログラムがすべての入力トークンの巨大なリストを作成することはありません。 各深さは、その平坦化された位置とともに直ちにパックされ、`cells`。 

表現`(depth << SHIFT) | idx`2 つの情報を 1 つの整数に格納します。 可能な最大のセル数は (10^6) であるため、20 ビットで十分です。`idx`。 パックされた値を降順で並べ替えると、主に深さによって並べ替えられます。これは、まさに DSU スイープで必要な順序です。 

の`active`バイト配列は DSU とは別のものです。 すべてのセルには最初から親があるため、DSU の親値だけではセルがすでにアクティブ化されているかどうかを判断できません。 バイト配列を使用すると、近傍が現在のしきい値グラフに属しているかどうかをテストできます。 

グリッドは行ごとに平坦化されます。 インデックス用`idx`、上のセルは`idx - M`、下のセルは`idx + M`、左側のセルは`idx - 1`、右のセルは`idx + 1`。 行と列のチェックにより、エッジの回り込みを防ぎます。 特にチェックするのは、`col > 0`使用する前に`idx - 1`行の最初のセルが前の行に誤って接続されるのを防ぎます。 

DSU は、サイズによる結合とパス圧縮を使用します。 どちらの操作も事実上定数時間で償却され、より正確には (O(\alpha(NM))) となります。ここで (\alpha) は逆アッカーマン関数です。 

このコードは、現在のセルに関係するすべての結合の後でコンポーネントのサイズをチェックします。 この順序は、セルが以前は別々だったいくつかのコンポーネントを接続する可能性があり、最後に結合されたコンポーネントのサイズを (S) と比較する必要があるため、重要です。 

Python の整数はオーバーフローしないため、パックされた表現は安全です。 最大のパック値は (10^8\cdot2^{20}+2^{20}) 未満であり、これは Python の整数範囲内に簡単に収まります。

深さ (9) のセルは、異なるコンポーネントに属しているため、サイズ (2) のプールを作成できません。 これは、単に最大値を取得するだけでは不十分である理由と、接続を明示的に維持する必要がある理由を示しています。

 ## 特殊なケース

 単一セルの場合は、最初のセルがアクティブ化されるとすぐに処理されます。 のために```
1 1 1
42
```セルは深さ (42) を持ち、サイズ (1) のアクティブ コンポーネントになり、(S=1) なので、アルゴリズムは (42) を返します。 隣人は必要ありません。 

切断された高価値セルについては、次のことを考慮してください。```
2 1 3
10 1 10
```2 つの深さ (10) のセルが最初にアクティブ化されますが、どちらにもアクティブな隣接セルがないため、両方のコンポーネントはサイズ (1) のままになります。 次に、深さ (1) の中央のセルがアクティブ化されて両側を結合し、サイズ (3) の 1 つのコンポーネントが生成されます。 この時点でコンポーネントには少なくとも (S=2) のサイズがあるため、答えは (1) になります。 このアルゴリズムは、魅力的だが無効な孤立した深さ (10) のセルのペアを正しく拒否します。 

コンポーネントが (S) より大きい場合、アルゴリズムは意図的にチェックします。`>= S`それよりも`== S`。 のために```
3 1 5
8 8 8 8 8
```最初の 3 つの隣接するセルはすでに正確に 3 つのセルの連結コンポーネントを形成しているため、アルゴリズムは (8) を返します。 チェック前にさらに多くのセルがアクティブ化されていた場合、ちょうど 3 つのセルの接続されたサブセットを取得できるため、サイズ 4 または 5 のコンポーネントは依然として有効です。 

(S=N\cdot M) の場合、すべてのセルがアクティブ化されるまで、しきい値は受け入れられません。 のために```
4 2 2
5 7
8 6
```深さ (8)、(7)、および (6) のセルが最初にアクティブ化されますが、それらのコンポーネントのサイズは 3 つだけです。 最後の深さ (5) セルがそのコンポーネントに結合し、サイズが 4 になります。 次に、アルゴリズムは (5) を返します。これは、グリッド全体の正確な最小深さです。 

グリッド境界チェックも不可欠です。 行優先の表現では、ある行の最後のセルは次の行の最初のセルに数値的に隣接していますが、これらのセルはグリッド内で水平方向に隣接していません。 条件は`col`このような誤った接続を防ぎます。 同様に、`row > 0`そして`row + 1 < N`グリッド外への垂直アクセスを防止します。 

降順により、最初に成功した DSU コンポーネントが最適になります。 深さ (D) では、すべてのアクティブ セルに少なくとも (D) の容量があります。 コンポーネントが (S) に達すると、深さ (D) のプールが存在します。 これより大きな深さは以前に処理され、そのようなコンポーネントの生成に失敗したため、より適切な回答はスキップされました。 

このバージョンは、コンテストのエディトリアルとして使用する準備ができています。 ご希望であれば、DSU の核となる洞察と実装に焦点を当てた、Codeforces スタイルの短いバージョンを作成することもできます。
