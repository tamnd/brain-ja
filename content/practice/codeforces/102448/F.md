 ## 解決策
 ## 問題の理解

 各建物は、同じ水平基線上に立つ、軸に沿った長方形です。 建物は左座標 (L_i)、右座標 (R_i)、高さ (H_i) で表されるため、(L_i) から (R_i) までの区間を占め、高さ (H_i) まで上昇します。 

装飾は都市の目に見える正面全体を覆う必要がありますが、建物の重なり合う部分は一度だけ覆う必要があります。 したがって、水平座標 (x) では、必要な高さは最も高い建物の覆いの高さ (x) になります。 その高さを (f(x)) と呼ぶと、必要な面積は都市全体の (f(x)) の積分になります。 

入力には最大 (10^5) 個の建物が含まれます。 座標は (10^9) に達する可能性があるため、すべての可能な座標でインデックス付けされた配列を作成することはできません。 さらに重要なのは、(O(N^2)) アルゴリズムは、最悪の場合、1 秒の制限がサポートできる範囲をはるかに超えて、約 (10^{10}) 個の演算を実行することになります。 (O(N\log N)) または同様の効率的な解決策が必要です。 

座標は整数ですが、建物は連続した長方形を表します。 これにより、間違いを犯しやすい箇所がいくつか生じます。 

まず、重なり合う建物は最大高さのみを寄与する必要があります。 例えば、```
2
0 4 3
1 2 5
```領域 (3\cdot1+5\cdot1+3\cdot2=16) があります。 重なっている部分が 2 回カウントされるため、2 つの長方形の領域を加算すると (12+5=17) となります。 

第二に、接触している建物は重なりません。 例えば、```
2
0 2 4
2 5 6
```領域 (2\cdot4+3\cdot6=26) があります。 点 (x=2) の幅はゼロであるため、面積には寄与しません。 間隔のエンドポイントを単位幅のセルとして扱うと、余分な影響が生じる可能性があります。 

第三に、複数の建物の最大高さを同じにすることができます。 例えば、```
2
0 3 5
0 3 5
```領域 (3\cdot5=15) があります。 1 つの建物が終了しても、他の建物がまだその間隔をカバーしているため、高さ (5) はアクティブのままでなければなりません。 多重度を追跡せずに単に最大値を削除するデータ構造では、スカイラインが誤って縮小されてしまいます。 

第四に、建物間の隙間は面積をゼロにしなければなりません。 例えば、```
2
0 2 3
5 7 4
```領域 (2\cdot3+2\cdot4=14) があります。 (2) から (5) までの空の間隔にわたって以前の最大値を保持するスイープ実装では、存在しない領域が追加されます。 

## アプローチ

 直接的なアプローチは、スカイラインが建物の端点でのみ変化する可能性があることを観察することから始まります。 左右のすべての座標を収集し、並べ替えて、連続するすべての座標のペアを考慮することができます。 このような 1 つの間隔内では、建物が開始または終了しないため、アクティブな建物のセットは固定され、必要な高さは一定です。 すべての間隔ですべての建物を検査し、その間隔をカバーする建物の中で最大の高さを取得することができます。 

これは正しいです。連続する X 軸全体が、スカイラインが変化しない間隔に分割されているからです。 ただし、ほぼ (2N) 個の異なるエンドポイントが存在する可能性があり、最大 (2N-1) 個の基本間隔が生成されます。 すべて (N) 個の建物をそれぞれ検査するには、最大で 2 時間かかります。 

[
 (2N-1)N

 建物チェック。 (N=10^5) の場合、これは (19,999,900,000)、約 (2\cdot10^{10}) チェックとなり、非常に遅すぎます。 

連続するエンドポイント間のすべての間隔には固定の答えがあるため、ブルート フォースが機能します。 問題は、最大値を最初から繰り返し再計算することです。 重要な観察は、ある端点から次の端点に移動するとき、その座標で始まるまたは終わる建物のみがアクティブ セットを変更するということです。 他のすべての建物を再度検査する理由はありません。 

左から右にスイープできます。 掃除中、現在アクティブな建物の高さをすべて維持し、その最大値をクエリする必要があります。 最大ヒープは、建物が挿入されるときに (O(\log N)) でその操作を正確に提供します。 

残りの困難は削除です。 Python の標準ヒープは、任意の要素を効率的に削除することをサポートしていません。 これは遅延削除で解決できます。 高さごとに、その高さを持つ現在アクティブな建物の数が保存されます。 建物が終了すると、その数は減りますが、ヒープ エントリはそのまま残ります。 ヒープの最上部の高さのカウントが 0 になるたびに、その古いエントリが削除されます。 各ヒープ エントリは 1 回挿入され、多くても 1 回削除されるため、合計作業量は (O(N\log N)) のままになります。 

面積の計算は特に簡単です。 前のイベントの座標が (x_{\text{prev}})、現在の座標が (x)、現在の最大高さが (h) であるとします。 スカイラインは区間 ([x_{\text{prev}},x)) を通じて正確に (h) であるため、その面積の寄与は次のようになります。

 ## アルゴリズムのチュートリアル

1. すべての建物を読み取り、それを 2 つのイベントに変換します。 (L_i) では、高さ (H_i) がアクティブになります。 (R_i) で、高さ (H_i) はアクティブでなくなります。 右側の端点は、建物が (R_i) までの連続区間を占め、単一の端点の面積がゼロであるため、終点として扱われます。 
2. すべて (2N) 個のイベントを X 座標で並べ替えます。 ソート後、スイープはスカイラインが左から右の順序で変化する可能性のあるすべての場所を検出します。 
3. 開始したがまだ終了していない建物の高さを含む最大ヒープを維持します。 Python は最小ヒープを提供するため、高さを負の値として保存し、最小のヒープ要素が実際の最大の高さを表すようにします。 
4. 各高さの現在アクティブな建物の数を含む辞書を維持します。 これにより、2 つ以上のアクティブな建物が同じ高さを持つ場合に必要となる多重度の情報が得られます。 
5. 最初のイベントの x 座標でスイープを開始します。 最初のイベントを処理する前はカバーされるエリアがないため、最初の累積エリアはゼロになります。 
6. 個別のイベント座標 (x) ごとに、まず前の座標と (x) の間の領域を追加します。 アクティブ セットはこの間隔内では変更されていないため、現在の最大高さは一定です。 
7. (x) ですべてのイベントを処理します。 開始イベントは、その高さのカウントをインクリメントし、その高さをヒープにプッシュします。 終了イベントによりカウントが減ります。 右に移動する前に同じ座標ですべてのイベントを処理します。これは、ある点でのイベントの正確な順序がエリアに影響を与えることができない一方で、結合された結果はその座標の直後のアクティブ セットを記述する必要があるためです。 
8. ヒープトップのアクティブカウントがゼロの間に、古いヒープエントリを削除します。 これらのエントリは、すでに終了した建物を表します。 遅延削除により、コストのかかる任意のヒープ削除の必要性が回避されます。 
9. 前の座標を (x) に設定し、すべてのイベントが処理されるまで続行します。 最後の右端点の後にはアクティブな建物がないため、追加のエリアはありません。 

### なぜ効果があるのか

 中心的な不変条件は、座標 (x) ですべてのイベントを処理した直後、ヒープは (x) のすぐ右側のすべての点をカバーする建物の高さを正確に表し、多重度はアクティブ カウント ディクショナリによって考慮されるということです。 

2 つの連続するイベント座標間では、建物が開始または終了しません。 したがって、アクティブなセットは変更されず、最も高いアクティブな建物が区間全体を通じてスカイラインの高さを決定します。 その高さに間隔の幅を掛けると、スカイラインのその部分の面積が正確に計算されます。 X 軸のすべての部分がまさに 1 つのそのような間隔でカバーされるため、すべての寄与の合計は、都市の正面図をカバーするために必要な最小エリアとなります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())

    events = []

    for _ in range(n):
        l, r, h = map(int, input().split())
        events.append((l, 1, h))
        events.append((r, -1, h))

    events.sort()

    heap = []
    count = {}

    area = 0
    prev_x = events[0][0]
    i = 0
    m = len(events)

    while i < m:
        x = events[i][0]

        if heap:
            area += (x - prev_x) * (-heap[0])

        while i < m and events[i][0] == x:
            _, delta, h = events[i]

            if delta == 1:
                count[h] = count.get(h, 0) + 1
                heapq.heappush(heap, -h)
            else:
                count[h] -= 1

            i += 1

        while heap and count.get(-heap[0], 0) == 0:
            heapq.heappop(heap)

        prev_x = x

    print(area)

if __name__ == "__main__":
    solve()
```イベントの構築は、各四角形をアクティブなスカイラインへの 2 つの変更に直接変換することです。 左の端点は高さを追加し、右の端点は高さを削除します。 

ちょうど (2N) 個のイベントがあるため、並べ替えステップには (O(N\log N)) のコストがかかります。 ソートが完了すると、スイープはすべてのイベントを 1 回処理します。 ヒープ挿入コスト (O(\log N)) がかかり、古いエントリが一時的に残る可能性がありますが、すべてのエントリをヒープから削除できるのは 1 回だけです。 したがって、すべてのヒープ操作を合わせると (O(N\log N)) かかります。 

表現`-heap[0]`ヒープには負の高さが格納されるため、現在最も高いアクティブな建物が得られます。 面積は、現在の座標でイベントを処理する前に計算されます。 この順序は意図的なものです。`prev_x`に`x`に達する前に存在していたアクティブ セットを使用します。`x`。 でのイベント`x`その右側の間隔にのみ影響します。 

すべてのイベントを同じ座標でグループ化すると、境界の動作も明確になります。 1 つの建物が終わり、別の建物が同じ x 座標で始まると仮定します。 これら 2 つのイベントの間には領域が存在しないため、これらを一緒に処理でき、その後は結合されたアクティブ セットのみが問題になります。 

ヒープ値は一意の識別子ではないため、辞書が必要です。 3 つのアクティブな建物の高さ (7) がある場合、そのうちの 1 つを削除しても高さ (7) が最大値から消えてはいけません。 このカウントには、まだアクティブなコピーの数が正確に記録されます。 

Python の整数は任意の精度を持っているため、可能な最大領域、おおよそ (10^9\cdot10^6=10^{15}) がオーバーフローせずに処理されます。
