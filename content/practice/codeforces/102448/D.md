 ## 解決策
 ## 問題の理解

 魔法のリングが配置される固定点 ((x,y)) があります。 通常のリングにはそれぞれ中心 ((X_i,Y_i)) と半径 (R_i) があります。 魔法のリングはある程度の半径 (r) で始まり、通常のリングを吸収するたびに、その半径はそのリングの半径だけ増加します。 

現在、魔法のリングの半径が (C) であるとします。 通常のリング (i) は、2 つの円が交差するか接触するときに正確に吸収されます。これは次と同等です。 

[
 \sqrt{(X_i-x)^2+(Y_i-y)^2} \le C+R_i.
 】

 吸収後の現在の半径は(C+R_i)となります。 タスクは、すべてのリングが何らかの順序で吸収されるように、可能な限り小さいイニシャル (r) を選択することです。 

重要な問題は、リングを吸収すると半径が変化するため、リングを単純に独立して扱うことができないことです。 最初は到達不能だったリングでも、いくつかのより容易なリングを吸収すると到達可能になる場合があります。 

最大 (10^5) 個のリングが存在しますが、座標の大きさは (10^9) に近くなる可能性があります。 (10^{10}) の演算は 2 秒の制限をはるかに超えているため、(N) の二次関数は除外されます。 (O(N\log N)) の解決策、または比較的効率的なものが必要です。 座標境界は、距離の二乗がおおよそ (8\cdot10^{18}) に達する可能性があることも意味するため、距離の計算には平方根を求める前に十分な整数精度が必要です。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 まず、必要な初期半径は実際にはゼロになる可能性があります。 例えば、```
1 0 0
0 0 2
```答えがあります`0.0000000000`。 魔法のリングは、中心間の距離がゼロであるため、半径がゼロであってもすでに通常のリングと交差しています。 ゼロを許可せずに最初に必要な半径に対する答えを初期化する実装では、誤って正の値が出力される可能性があります。 

接線も境界ケースの 1 つです。 考慮する```
1 0 0
3 0 2
```中心は正確に距離 (3) 離れており、半径の合計は (3) であるため、リングは接触し、吸収が許可されます。 答えは```
1.0000000000
```厳密な使用法`<`の代わりに`<=`はこの有効な吸収を拒否します。 

吸収の順序も重要です。 考慮する```
2 0 0
100 0 99
3 0 1
```最初のリングの場合、必要な現在の半径は (100-99=1) です。 2 番目の場合は、(3-1=2) となります。 最初のリングは最初に吸収される必要があります。 半径 (1) から始まり、魔法のリングは半径 (99) のリングを吸収して半径 (100) まで成長し、その後 2 番目のリングは簡単です。 正しい答えは、`1.0000000000`。 代わりに中心距離でソートすると、距離 (3) のリングが最初に処理され、半径 (2) が必要であると誤って結論付けられます。 

## アプローチ

 直接的な強引なアプローチは、考えられるすべての吸収順序を考慮することです。 次数が固定されている場合、必要な最小の初期半径は簡単に計算できます。 リング (i) を吸収する前に、以前に吸収されたすべてのリングの半径の合計がわかっているため、そのステップが可能となるために初期半径がどのくらいの大きさでなければならないかを正確に判断できます。 オーダー全体の最大値を取ると、そのオーダーに必要な開始半径が得られます。 

問題は注文数です。 (N!) 個の順列があり、1 つの順列を評価するには (O(N)) 時間がかかり、(O(N\cdot N!)) 個の作業が必要になります。 (N=20) であっても、すでにおよそ (20\cdot20!)、約 (4.9\cdot10^{19}) 個のリング チェックが必要になります。 (N=10^5) では、網羅的な順序付けは完全に不可能です。 

吸収条件を書き換えると構造は非常に単純になります。 しましょう

 [
 d_i=\sqrt{(X_i-x)^2+(Y_i-y)^2}
 】

 は、魔法のリングの中心からリング (i) の中心までの距離になります。 リング (i) は次の場合に吸収可能です

 [
 d_i\le C+R_i、
 】

 または同様に、

 [
 d_i-R_i\le C.
 】

 定義する

 [
 A_i=d_i-R_i。 
】

 ここで、各リングは、現在の魔法の半径がそのしきい値 (A_i) に達すると使用可能になる単なるオブジェクトです。 それを吸収すると、現在の半径に (R_i) が追加されます。 

すべての報酬 (R_i) は正です。 これにより、順序付けの問題が完全に変わります。 2 つのリングにしきい値 (A_i\le A_j) があり、しきい値のあるリング (A_j) が現在使用可能な場合、しきい値のあるリング (A_i) も使用できます。 他のリングが考慮される前に現在の半径が増加するだけであるため、より小さいしきい値のリングを最初に吸収しても問題はありません。 

これは、すべてのリングを (A_i) でソートできることを意味します。 一度並べ替えると、複雑な選択をシミュレーションする必要はありません。 この順序で (i) 番目のリングの前に、現在の半径はすでに前のすべてのリングの半径を獲得しています。 それらの合計半径が (S) の場合、次が必要です。 

[
 r+S\ge A_i、
 】

 それで

 [
 r\ge A_i-S.
 】

 したがって、半径を負にすることはできないため、最小初期半径はこれらの要件の最大値にゼロを加えたものになります。 

完全な順序により、考えられるすべてのシーケンスをテストできるため、ブルート フォースが機能します。 階乗数が多いため失敗します。 リングが到達可能になるまでに必要な半径の量によってリングを順序付けできるという観察により、問題全体がソートと 1 つのプレフィックス合計に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N\cdot N!)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N\log N)) | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての通常のリングについて、固定されたマジックリングの中心からの距離を計算します。 

[
 d_i=\sqrt{(X_i-x)^2+(Y_i-y)^2}。 
】

 次に、必要な現在の半径を計算します。 

[
 A_i=d_i-R_i。 
】

 この値は、リング (i) が即座に吸収されることを可能にする最小のマジック リング半径です。 

1. 各リングをペア ((A_i,R_i)) として保存し、すべてのペアを (A_i) でソートします。 

しきい値が小さいリングは、しきい値が大きいリングよりも吸収されにくいため、ソートされた順序は有効です。 より大きなしきい値リングが使用可能な場合は、より小さなしきい値リングもすべて使用可能になり、より小さなしきい値リングを吸収しても半径が増加するだけです。 

1.セット`added = 0`、すでに吸収されたリングから得られる合計半径を表し、設定されます。`answer = 0`。 

リングを処理する前の、マジック リングの現在の半径は次のとおりです。`answer + added`概念的にのみ。 もっと直接的に言えば、`answer`は、十分にしようとしている初期半径を表します。`added`前回の吸収後に得られた半径を表します。 

1. ソートされた各ペア ((A_i,R_i)) について、計算します。 

[
 あ_い追加しました。 
】

 以前のリングによってすでにマジック リングの半径が 0.5 倍増加しているため、初期半径は少なくともこの値である必要があります。`added`。 現在の最大値とこの要件を使用して回答を更新します。 

1. (R_i) を追加します。`added`そして続けます。 

すべてのリングは、リングに正常に到達した後にのみその半径を提供します。これはまさに実際の吸収プロセスの動作です。 

1. 結果の最大値を十分な小数精度で出力します。 

距離の計算では平方根を求める前に整数の差が使用されるため、距離の二乗自体は Python で正確に計算されます。 

### なぜ効果があるのか

 不変条件は、最初の (i) リングをソートされたしきい値順に処理した後、`added`は正確にそれらの半径の合計であり、`answer`は、すべての処理された吸収を可能にする最小の初期半径です。 

次のリングのしきい値は (A_i) です。 以前のリングはすでに魔法の半径を`added`なので、次の吸収が正確に可能になるのは

 [
 答え+追加\ge A_i。 
】

 したがって、アルゴリズムは (answer\ge A_i-added) を強制する必要があります。 処理されたすべてのリングの最大値を取ると、このようなすべての条件が満たされます。 

残りの疑問は、なぜソートされたしきい値順序で十分なのかということです。 実行可能な吸収順序に、しきい値 (A_j>A_i) を持つ 2 つの連続するリングが含まれており、(j) が (i) より前に吸収されると仮定します。 (j) に到達可能であるため、現在の半径は少なくとも (A_j)、したがって少なくとも (A_i) になります。 それらを交換し、最初に (i) を吸収し、その正の半径を取得しても、(j) を吸収するのに十分な半径を確保できます。 このような反転を繰り返し除去すると、必要な初期半径を増加させることなく、実行可能な順序が非減少しきい値順序に変換されます。 したがって、ソートされた順序には最適な解が含まれます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())

    rings = []

    for _ in range(n):
        X, Y, R = map(int, input().split())

        dx = X - x
        dy = Y - y

        distance = math.hypot(dx, dy)
        need = distance - R

        rings.append((need, R))

    rings.sort()

    answer = 0.0
    added = 0

    for need, radius in rings:
        answer = max(answer, need - added)
        added += radius

    print(f"{answer:.10f}")

if __name__ == "__main__":
    solve()
```入力ループはまず、すべての円を貪欲アルゴリズムにとって重要なペアに変換します。 距離を計算した後は、元の中心座標は必要なくなります。`math.hypot(dx, dy)`(\sqrt{dx^2+dy^2}) を計算します。 座標の差は整数であり、Python の整数には任意の精度があるため、二乗距離が内部で形成されるときに整数のオーバーフローは発生しません。 

引き算`distance - R`ソートの前に意図的に行われます。 並べ替え順`distance`半径が大きい場合、大きなリングは小さなリングよりも吸収されやすいため、単独では不正確です。 関連する数量は常に`distance - radius`。 

ループは維持されます`added`整数として。 これは、最大 (10^5) の半径の合計が最大でも (10^{10}) になるため便利です。これは Python では正確です。 幾何学的しきい値のみに平方根が含まれており、浮動小数点演算が必要です。 

更新は、現在のリングの半径を追加する前に行われます。 この順序は物理プロセスと一致します。つまり、現在のリングは、吸収されるまでその半径に寄与できません。 最初に追加すると、1 ステップずつずれたエラーが発生し、最初は到達不能だったリングが到達可能に見える可能性があります。 

数学的条件での比較は厳密ではありません。 接線リングは吸収できるため、現在の半径が正確に等しい場合にしきい値が満たされます。`need`。 この式は、特別なケースを必要とせずに自然に等価性を処理します。 

ついに、`answer`必要な半径は正でない場合があるため、ゼロから始まります。 すべてのリングが、自身の半径を考慮した後ですでに半径ゼロのマジック リングと交差している場合、正の開始半径は必要ありません。 

## 実用的な例

 サンプル 1 の場合、魔法の中心は ((1,1)) です。 2 つの通常のリングは、半径 (3) の ((1,7)) と半径 (3) の ((5,1)) にあります。 

それらの距離としきい値は次のとおりです。 

| リング | 距離 | 半径 | (A_i=d_i-R_i) |`added`前 | 必要な初期半径 |
 | --- | --- | --- | --- | --- | --- |
 | ((5,1)) | 4 | 3 | 1 | 0 | 1 |
 | ((1,7)) | 6 | 3 | 3 | 3 | 0 |

 しきい値が (1) のみであるため、ソート順序は 2 番目の入力リングから始まります。 半径 (1) から始まり、魔法のリングはそれを吸収し、半径 (4) まで成長します。 もう一方のリングは半径 (3) のみを必要とするため、すぐに吸収されます。 

必要な最大の初期半径は (1) で、サンプル出力が生成されます。 

サンプル 2 の場合、4 つのしきい値はおよそ次のとおりです。 

| リング | 距離 | 半径 | (A_i=d_i-R_i) |`added`前 | 必要な初期半径 |
 | --- | --- | --- | --- | --- | --- |
 | 3 | 160.015625 | 41 | 119.015625 | 0 | 119.015625 |
 | 4 | 245.943083 | 78 | 167.943083 | 41 | 126.943083 |
 | 1 | 836.244584 | 6 | 830.244584 | 119 | 711.244584 |
 | 2 | 1025.353110 | 30 | 995.353110 | 125 | 870.353110 |

 3 番目の入力リングは最も到達しやすいため、最初に吸収され、魔法の半径が (41) だけ増加します。 次に、4 番目のリングが到達可能になり、別のリングが追加されます (78)。 これら 2 つの吸収の後、魔法のリングの半径は (119) 増加します。 

最初のリングは、それら (119) ユニットを考慮した後、わずか約 (711.245) の初期寄与を必要とします。 最後のリングが本当のボトルネックです。 考慮する時点では、半径 (125) がすでに得られていますが、そのしきい値は約 (995.353110) であるため、初期半径は少なくとも

 [
 995.353110-125=870.353110。 
】

 これによりサンプル出力が得られます`870.3531099090`。

import io
import math

def solve(data: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(data)

    input = sys.stdin.readline

    n, x, y = map(int, input().split())
    rings = []

    for _ in range(n):
        X, Y, R = map(int, input().split())

        dx = X - x
        dy = Y - y

        distance = math.hypot(dx, dy)
        need = distance - R

        rings.append((need, R))

    rings.sort()

    answer = 0.0
    added = 0

    for need, radius in rings:
        answer = max(answer, need - added)
        added += radius

    sys.stdin = old_stdin
    return f"{answer:.10f}"

def run(inp: str) -> str:
    return solve(inp)

# Provided sample 1
out = float(run("""\
2 1 1
1 7 3
5 1 3
"""))
assert abs(out - 1.0) < 1e-9, "sample 1"

# Provided sample 2
out = float(run("""\
4 211 -458
335 369 6
-771 -753 30
193 -617 41
-27 -396 78
"""))
assert abs(out - 870.3531099090) < 1e-6, "sample 2"

# Minimum-size input, zero initial radius
out = float(run("""\
1 0 0
0 0 2
"""))
assert abs(out - 0.0) < 1e-9, "zero-radius answer"

# Tangency must be accepted
out = float(run("""\
1 0 0
3 0 2
"""))
assert abs(out - 1.0) < 1e-9, "tangency"

# Sorting must use distance - radius, not distance
out = float(run("""\
2 0 0

"""))

"""))

# Maximum-size input, all equal values

lines = [f"{n} 0 0"]
lines.extend(["0 0 2"] * n)
out = float(run("\n".join(lines) + "\n"))
assert abs(out - 0.0) < 1e-9, "maximum-size equal input"

 ## 特殊なケース

 答えが次から始まるため、半径ゼロのケースが処理されます。`0.0`そしてすべての要件はその値と相対的に考慮されます。 のために```
1 0 0
0 0 2
```距離は (0) なので、しきい値は (0-2=-2) になります。 したがって、必要な初期半径は (-2) ですが、物理的な半径を負にすることはできないため、ゼロを伴う最大値は (0) のままになります。 リングはすぐに吸収され、アルゴリズムが出力します。`0.0000000000`。 

接線の場合は等価性を直接使用します。 のために```
1 0 0
3 0 2
```しきい値は (3-2=1) です。 初期半径がちょうど (1) の場合、2 つの円は中心距離 (3) と結合半径 (1+2=3) を持ち、接触します。 条件は正確に満たされており、答えは次のとおりです。`1.0000000000`。 イプシロン調整や厳密な比較は必要ありません。 

順序付けのエッジ ケースは、しきい値にリング自体の半径が含まれる理由を示しています。 のために```
2 0 0

Python では、大きな座標によって整数オーバーフローが発生することはありません。 たとえば、境界の場合は ((-10^9,10^9)) 付近の中心と ((10^9,-10^9)) 付近のリングを使用します。 座標の差は (2\cdot10^9) に近いため、距離の 2 乗は約 (8\cdot10^{18}) になります。 Python はその整数を直前に正確に計算します。`math.hypot`ジオメトリを浮動小数点に変換します。 結果として生じる浮動小数点誤差は、最終的な答えに必要な許容値 (10^{-6}) をはるかに下回ります。
