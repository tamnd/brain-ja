 ## 解決策
 ## 問題の理解

 私たちには、周期的に機能するプロモーションが与えられています。 一定数のアイスクリームを購入した場合、次のように言います。$X$、会社があなたに与える$Y$追加ユニットは無料です。 このルールは繰り返し適用されます。つまり、別の完全なバッチが蓄積されるたびに、$X$ユニットを支払った場合は、別のユニットを受け取ります$Y$無料のユニット。 

アイスクリームの各ユニットには 3 ドルの固定価格がかかりますが、実際に支払ったユニットのみがコストに影響します。 無料のユニットにより、最終的に入手できるアイスクリームの総数が増加しますが、価格には影響しません。 

各テスト ケースについて、完了したすべてのアイスクリームの景品を含む、受け取られるアイスクリームの総数が得られるように、必要な有料ユニットの最小数を決定したいと考えています。$X$-サイズの購入、少なくとも$N$。 最終的な答えは、有料ユニット数の 3 倍です。 

主な問題点は、無料のユニットが完全なグループの数に依存することです。$X$私たちは買う。 以下よりも少ない量を購入した場合$X$ユニットの場合、ボーナスは得られません。 到着したら$X$、突然追加を獲得します$Y$、そしてこの不連続性は毎回繰り返されます$X$単位。 

制約は十分小さいので、$O(N \log N)$あるいは$O(N^2)$テストケースごとのスタイルチェック。 と$N \le 15000$最大 15 のテスト ケース、ケースごとに数十万の評価であっても安全ですが、購入戦略の考えられるすべての組み合わせを個別に試行するものは、各評価が一定時間である場合にのみ許容されます。 

貪欲な思考が間違って適用されると、微妙な失敗例が現れます。 たとえば、$X = 4$、$Y = 7$、 そして$N = 22$、十分な量の完全なグループを購入することが常に最適であると仮定したくなります。 しかし、部分的な残りは重要です。いくつかの完全なグループを取得した後、追加の有料ユニットをいくつか購入します（別の完全なユニットを完了する必要はありません）$X$) しきい値を効率的に超えるには必要な場合があります。 これを無視すると、答えが過小評価されるセグメント外のエラーが発生します。 

別の特殊なケースが発生する場合$X = 1$。 その後、すべての有料ユニットがすぐに生産します$Y$自由な単位を使用して、問題を単純な線形方程式に変換します。 少なくとも 1 つの完全なブロックが必要であると想定する単純な実装では、このケースが過度に複雑になったり、誤って処理されたりする可能性があります。 

## アプローチ

 最も直接的なアイデアは、購入プロセスをシミュレーションすることです。 有料ユニット数を増やすよう努めます$b$、それぞれについて、受け取る無料ユニットの数を計算します。 もし$b$含まれています$\lfloor b / X \rfloor$フルブロックの場合、空きユニットの数は正確に$Y \cdot \lfloor b / X \rfloor$、アイスクリームの総数は次のようになります。$b + Y \cdot \lfloor b / X \rfloor$。 最小のところで止まります$b$この合計が少なくとも到達するところ$N$。 

考えられるすべての購入戦略が一定数の有料ユニットに対応しているため、この総当たりスキャンは正しいです。$b$、得られる合計は次によって完全に決定されます。$b$。 問題は効率です。最悪の場合、すべてをチェックする可能性があります。$b$0から$N$、各チェックは定数時間であるため、$O(N)$テストケースごとに。 これはこれらの制約に対してすでに許容可能ですが、アイスクリームの総数は単調であるため、二分探索を使用して解をより明確に構築できます。$b$。 

重要な観察は単調性です。 有償ユニット数を増やしても、アイスクリームの総獲得数が減ることはありません。 関数が次の倍数でジャンプする場合でも、$X$、決して減りません。 これにより、最小限の二分探索が可能になります$b$という条件が成り立つように。 

与えられたデータからアイスクリームの合計を計算するチェック関数を定義します。$b$、次に有効な最小値を二分探索します。$b$で$[0, N]$。 上限$N$買うから安心$N$単位は常に少なくとも$N$景品に関係なくアイスクリームの合計。

 ## アルゴリズムのチュートリアル

 私たちはテストケースごとに独立して作業します。 

1. 購入によって得られるアイスクリームの合計を計算する関数を定義します。$b$有料ユニット。 完全なグループの数は$b // X$、各グループが貢献します$Y$無料のユニット。 合計は$b + (b // X) \cdot Y$。 
2. 二分探索範囲を設定します。$b$0から$N$。 下限はコストの観点から自明に実現可能であり、上限は購入できるため安全です。$N$単位は常に少なくとも保証します$N$合計アイスクリーム。 
3. 二分探索を実行します。 中間点に向けて$mid$、ステップ 1 の関数を使用してアイスクリームの合計を計算します。 
4. 合計が少なくとも$N$、答えは次のとおりです$mid$以下なので、右の境界を次の位置に移動します。$mid$。 
5. それ以外の場合は、$mid$では不十分なので、左側の境界を次のように移動します。$mid + 1$。 
6. 収束後、左側の境界は必要な支払い単位の最小数を表します。 

この正しさは、アイスクリームの総数が次の関数であるという事実から得られます。$b$単調非減少です。 の倍数で段階的に増えていくのに、$X$、次の場合は決して減りません。$b$が増加します。 これにより、バイナリ検索が有効な領域を誤って破棄することがなくなり、常に最小の実現可能な領域に収束することが保証されます。$b$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        X, Y, N = map(int, input().split())

        def total(b):
            return b + (b // X) * Y

        lo, hi = 0, N

        while lo < hi:
            mid = (lo + hi) // 2
            if total(mid) >= N:
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```このソリューションでは、ロジックをテストごとのループにラップします。 ヘルパー関数`total(b)`プロモーションの構造を直接捉えています。 二分探索では、答えが常にその中にあるという不変条件が維持されます。`[lo, hi]`。 いつ`total(mid)`要件を満たしている場合、上限を安全に縮小します。`b`これ以上に優れることはできません`mid`。 それ以外の場合は増加します`lo`より小さい値もすべて失敗するためです。 

よくある間違いは、サイズの完全なグループのみを考慮して答えを計算しようとすることです。$X$そして残りは無視します。 二分探索では、すべての候補について正確な式を評価することで、これを完全に回避します。
