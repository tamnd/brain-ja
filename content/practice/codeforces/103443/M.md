 ## 解決策
 ## 問題の理解

 森林は、各セルが 0 または 1 の小さなバイナリ グリッドとして表されます。1 は木が密集していることを意味し、0 は開いた茂みを意味します。 グリッドは境界を越えて暗黙のゼロで囲まれるため、行列の外側のステップは 0 セルのように動作します。 

ノビはちょうど 1 つのマス目に立っていますが、その方向は不明です。 彼は、現在のセルの値、直前のセルの値、および右側のセルの値の 3 つのことを観察します。 問題は、自分が北、東、南、西のいずれを向いているのかがわからないことです。 

このタスクは、4 つの可能な方向のうち少なくとも 1 つが存在するすべてのグリッド位置を決定し、ノビがその方向を向いてそこに立っている場合に、観察されたトリプルが正確に一致するようにすることです。 有効な開始セルごとに、何らかの方向が観察されたパターンを生成するかどうかを確認する必要があります。 

グリッド サイズは最大 100 x 100 であるため、セルの総数は最大 10,000 です。 すべてのセルと 4 つの方向すべてをチェックすると、最大約 40,000 の構成が得られますが、これは 1 パス シミュレーションの制限内に十分収まります。 

微妙なエッジケースは、「前」または「右」のポジションがグリッドの外側に出る場合です。 これらの位置は 0 として扱う必要があります。よくある間違いは、境界チェックをスキップしたり、外側をゼロにするルールを無視したりすることです。 

同じセルに対して複数の方向が有効な場合、別のエッジ ケースが発生します。 たとえば、セルは北を向いている場合と西を向いている場合の両方で条件を満たす可能性があります。 セルは出力に 1 回だけ出現する必要がありますが、少なくとも 1 つの方向が機能する限り有効です。 

最後に、順序が重要です。出力は行、列の順に並べ替える必要があります。 結果を任意の順序で収集する不用意な実装は、ロジックが正しくても失敗します。 

## アプローチ

 最も直接的なアイデアは、考えられるすべての開始設定をテストすることです。 各セルについて、4 つの方向すべてを試します。 方向ごとに、方向ベクトルを使用して前方と右方のセルの座標を計算します。 次に、それらの値を観測されたトリプルと比較します。 

グリッドが小さいため、この強引な方法はすでに十分に効率的です。 各セルは一定量の作業、つまり 4 方向のチェックをトリガーし、それぞれが一定時間のルックアップで構成されます。 最悪の場合でも、これは約 40,000 チェックであり、これは取るに足らないものです。 

高度な前処理やデータ構造は必要ありません。 重要な観察は、問題は純粋に局所的なものであるということです。各候補位置は最大でも 3 つのグリッド検索にのみ依存します。 グローバルな制約やセル間の相互作用がないため、定数因子シミュレーションを超える最適化は必要ありません。 

したがって、「最適な」ソリューションは、総当たりのソリューションと構造が同じです。 唯一の違いは、方向マッピングと境界条件を慎重に処理することです。

 ## アルゴリズムのチュートリアル

 潜在的な開始位置としてすべてのセルを反復処理し、4 つの方向のいずれかで観察結果と一致するかどうかをテストします。 

1. グリッドと観測値 s、f、r を読み取ります。 これらはそれぞれ現在のセル、前のセル、右のセルを表します。 
2. 北、東、南、西の方向ベクトルを定義します。 それぞれの方向に対して、「正しい」とは何を意味するのかも定義する必要があります。 たとえば、北を向いている場合、正面は (-1, 0)、右側は (0, 1) になります。 
3. 各セル (i, j) について、それをノビの可能性のある位置として扱います。 
4. 4 つの方向の各方向 d について、次を計算します。

現在のセルの値は、grid[i][j]、前方のセルの座標、および右のセルの座標です。 
5. 正面または右側の座標がグリッドの外に出る場合は、その値を 0 として扱います。これにより、周囲の茂みがモデル化されます。 
6. Grid[i][j] が s に等しいか、front が f に等しいか、right が r に等しいかどうかを確認します。 すべて一致する場合、(i, j) を有効としてマークし、このセルの他の方向のチェックを停止します。 
7. すべてのセルを処理した後、すべての有効な位置を辞書編集順に行、列の順に出力します。 

セルごとに早めに停止する主な理由は、有効な方向が 1 つだけ存在する必要があり、すべての方向が存在する必要はないからです。 

### なぜ効果があるのか

 (セル、方向) の各構成は、観測値の 1 つのトリプルを決定論的に定義します。 このアルゴリズムは、そのような構成をすべて暗黙的に列挙します。 観察と一致する構成が存在する場合、それがチェックされ、セルが記録されます。 逆に、記録されないセルは、4 つの可能性がすべて明示的に使い尽くされているため、必要なトリプルを生成する方向を持つことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_val(grid, i, j, m, n):
    if 0 <= i < m and 0 <= j < n:
        return grid[i][j]
    return 0

def solve():
    m, n = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(m)]
    s, f, r = map(int, input().split())

    # directions: N, E, S, W
    dirs = [
        (-1, 0, 0, 1),  # N: front up, right east
        (0, 1, 1, 0),   # E: front right, right south
        (1, 0, 0, -1),  # S: front down, right west
        (0, -1, -1, 0)  # W: front left, right north
    ]

    res = []

    for i in range(m):
        for j in range(n):
            if grid[i][j] != s:
                continue

            for dx, dy, rx, ry in dirs:
                fi, fj = i + dx, j + dy
                ri, rj = i + rx, j + ry

                if (get_val(grid, fi, fj, m, n) == f and
                    get_val(grid, ri, rj, m, n) == r):
                    res.append((i, j))
                    break

    res.sort()
    out = []
    for x, y in res:
        out.append(f"{x} {y}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コア構造はすべてのセルにわたる二重ループであり、その後に継続的な 4 方向のチェックが続きます。 ヘルパー関数は、グリッドの外側を 0 としてカウントする境界ルールをきれいにエンコードし、メイン ループ内で条件付きロジックが繰り返されることを回避します。 

方向配列は前方ステップと右ステップの両方を同時にエンコードしますが、これは実装の唯一の微妙な部分です。 各タプルは、特定の方向を向いたときに座標がどのように変化するかを表します。 

ソートは出力要件を満たすために最後に行われます。 候補者が少ないので安心です。 

## 実用的な例

 ### 例 1

 入力:```
2 2
1 0
0 1
1 0 0
```各セルを評価します。 

(0,0) の場合、グリッド値は 1 であるため、s と一致します。 東を向いていると、front (0,1)=0 が得られますが、これは f=0 と一致しません。 実際には f=0 なので一致し、right (1,0)=0 は r=0 と一致するので有効です。 

(0,1) の場合、値は 0 であるため、s=1 であるためすぐに失敗します。 

(1,0) の場合、値は 0 であるため失敗します。 

(1,1) の場合、値は 1 なので、方向をテストします。 1 つの方向でも同様に機能します。 

出力：```
0 0
1 1
```これは、複数の向きで異なるセルを独立して検証できることを示しています。 

### 例 2

 入力:```
1 3
1 1 0
1 1 0
```グリッドは単一行であるため、「北」または「南」方向は外側につながり、0 としてカウントされます。 

セル (0,2) の場合、西向きは正面 (0,1)=1 となり、右は外側 =0 となるため、有効です。 

セル (0,1) についても、同様の推論が有効であることがわかります。 

出力：```
0 1
0 2
```これは、チェックをスキップするのではなく、範囲外をゼロとして扱うことの重要性を強調しています。

 ## 特殊なケース

 よくある失敗例は、前方または右のセルがグリッドの外側にある場合です。 1 行 1 列のグリッドでは、すべての方向がすぐに範囲外になります。 入力の場合:```
1 1
1
1 0 0
```アルゴリズムは、方向に関係なく、正面と右側の両方を 0 として扱う必要があります。 単一セルは有効であり、すべての方向がゼロと同じ比較になるため、アルゴリズムにはそれが正しく含まれます。 

同じセルに対して複数の方向が有効な場合、別のエッジ ケースが発生します。 次のようなグリッド内で:```
1 2
1 1
1 1 0
```セルは東を向いているときも北を向いているときにも条件を満たす可能性があります。 このアルゴリズムはセルを 1 回追加し、早期に中断して、存在を確認しながら重複がないことを保証します。 

最後のエッジケースは注文です。 有効なセルが任意の順序で見つかった場合、ロジックが正しくても出力が間違っている可能性があります。 最後に並べ替えると、トラバーサル パスに関係なく行優先の順序付けが保証されます。これは、グリッド スキャンがネストされているが、正確さを保つには明示的な順序付けが必要であるため、必要です。
