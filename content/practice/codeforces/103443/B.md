 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられています。 初期スコアは、2 つの文字列が既に 1 文字ずつ一致している位置の数にすぎません。 

2 番目の文字列に対して許可される操作は 1 つだけです。セグメントを選択し、その位置で反転します。 この反転の後、最初の文字列と変更された 2 番目の文字列の間で一致する位置の数を再計算します。 目標は、この最終一致数を最大化するセグメントを選択することです。 

テスト ケースごとに 3 つの情報を出力する必要があります。つまり、元の一致数、1 回の反転後に達成可能な最良の数、およびこの最適値を達成するセグメント境界です。 複数のセグメントが同じ最大値に達する場合は、最も短いセグメントが優先され、依然として同点の場合は最小の開始インデックスが優先されます。 

重要な制約は、文字列の長さが最大 ​​1000 であり、テスト ケースが最大 50 であることです。 これにより、慎重に実装されれば、テスト ケースごとにおよそ 2 次より悪いものは即座に排除されます。 すべての部分文字列に対する 3 次解は理論的には定数因数が小さい場合にのみ合格しますが、各候補セグメントの評価は自由ではないため、ここでは正確である必要があります。 

単純なアプローチでは、すべてのセグメントを試し、それらを逆にして、一致を最初から再計算します。 つまり、セグメントあたり O(n)、セグメント数が O(n^2) となり、O(n^3) となり、n = 1000 で約 10^9 回の演算となり、遅すぎます。 

より微妙な障害モードは、エンドポイントのみが独立して重要であると考えることから生じます。 たとえば、一致が増加するたびにセグメントを貪欲に拡張しようとしても機能しません。反転すると位置が対称的に変更されるため、局所的な改善により他の場所でグローバルな位置合わせが破壊される可能性があります。 

もう 1 つの落とし穴は、最適なセグメントには不一致の位置が含まれているに違いないと仮定することです。 それは誤りです。 すでに一致している位置のセグメントを反転すると、非ローカルな方法でセグメント境界の内側または外側の不一致を修正しながら、それらの一致を保持できます。 

## アプローチ

 ブルートフォースの観点は単純です。 各セグメント [l, r] について、s2[l..r] を反転し、s1 との一致をカウントします。 これが機能するのは、問題の定義を直接評価するためです。 ただし、逆転するたびに一致数を再計算すると複雑さが大きくなり、O(n^3) になります。 

重要な観察は、セグメントを反転しても文字がランダムに再シャッフルされるわけではないということです。 セグメント内で対称的に位置のペアを交換するだけです。 セグメントの外側のすべての位置は影響を受けません。 セグメント内では、位置 i が位置 j = l + r − i と交換されます。 これは、スコアの唯一の変化が対称位置のペアごとの寄与によるものであることを意味します。 

これにより、一定の間隔で動的プログラミング状態を定義できるようになります。 文字列全体を再計算するのではなく、セグメントを両端から内側に拡張したときにスコアがどのように変化するかを追跡します。 これにより、各ステップでは位置の 2 つのペアのみを比較するため、状態ごとの再計算が O(n) から O(1) に減ります。 

したがって、s2[l..r] を反転した後の一致数を表す値 dp[l][r] を構築することで、すべてのセグメントの効果を計算できます。 これらの状態は、新しく含まれたペア (l, r) のみを調整して、dp[l][r] を dp[l+1][r−1] に関連付ける漸化式を使用して O(n^2) で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | インターバルDP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、逆転なしのベースライン一致数を計算します。 これは、すべての位置にわたる単純な線形スキャンです。 

次に、部分文字列 s2[l..r] を反転した後の s1 と s2 の間の一致数を dp[l][r] で表す DP テーブルを構築します。

1. dp[i][i] と dp[i][i−1] を基本ケースとして暗黙的に初期化します。 間隔の長さが 1 または空の場合、反転しても何も行われないため、スコアは元の一致数になります。 これにより、再発がわずかな間隔で固定されます。 
2. dp[l][r] を設定して間隔の長さを増やします。 dp[l][r] を計算するときに dp[l+1][r−1] が既知になるように、小さい間隔から大きい間隔に拡張します。 
3. 指定された間隔 [l, r] について、反転すると何が起こるかを考えてみましょう。 反転されたセグメントでは、位置 l は r とペアになり、l+1 は r−1 とペアになります。 内側セグメント [l+1, r−1] のスコアがすでにわかっている場合、l と r を加算すると、寄与を更新する必要がある新しい対称ペアが 1 つだけ導入されます。 
4. トランジションでは、エンドポイントの 2 つの効果を比較します。 追加する前に、位置 l と r は元の場所で一致していました。 反転後、s2[l]はrに移動し、s2[r]はlに移動します。 したがって、これら 2 つのポジションの古い寄与分を差し引き、交換後に新しい寄与分を加算します。 これは、文字比較に基づく直接補正項を使用して行われます。 
5. dp を埋める際に、最良の値とそのセグメントを追跡します。 同点が発生した場合は、最初にセグメントの長さを比較し、次に左側の境界を比較します。 これにより、2 回目のパスを行わずに、必要な答えを再構築できることが保証されます。 

なぜそれが機能するのかは、構造的な不変条件に帰着します。 任意の間隔 [l, r] で、dp[l][r] は、その間隔内のすべての位置の完全な対称交換を実行した後の合計一致スコアを正確に反映します。 各展開ステップでは、新しいスワップされたペアが 1 つだけ導入され、再帰によって、すでに解決されている内部構造に触れることなく、その寄与が分離されます。 すべての反転は独立した対称スワップに分解されるため、すべてのセグメントは dp によって 1 回だけカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input().strip())
        s1 = input().strip()
        s2 = input().strip()

        base = 0
        for i in range(n):
            if s1[i] == s2[i]:
                base += 1

        # dp[l][r] = match count after reversing s2[l:r+1]
        dp = [[0] * n for _ in range(n)]

        best_val = base
        best_l = 0
        best_r = 0

        for i in range(n):
            dp[i][i] = base
            if base > best_val or (base == best_val and (1 < best_r - best_l + 1 or (1 == best_r - best_l + 1 and i < best_l))):
                best_val = base
                best_l = i
                best_r = i

        for length in range(2, n + 1):
            for l in range(0, n - length + 1):
                r = l + length - 1

                inner = dp[l + 1][r - 1] if l + 1 <= r - 1 else base

                # remove old contributions of l and r, add new ones after swap
                old = 0
                if s1[l] == s2[l]:
                    old += 1
                if s1[r] == s2[r]:
                    old += 1

                new = 0
                if s1[l] == s2[r]:
                    new += 1
                if s1[r] == s2[l]:
                    new += 1

                dp[l][r] = inner - old + new

                if dp[l][r] > best_val or (dp[l][r] == best_val and (length < best_r - best_l + 1 or (length == best_r - best_l + 1 and l < best_l))):
                    best_val = dp[l][r]
                    best_l = l
                    best_r = r

        print(base, best_val, best_l + 1, best_r + 1)

if __name__ == "__main__":
    solve()
```コードは最初に、すべての DP 状態の基準値となるベースライン一致数を計算します。 すべての dp[l][r] は既知の値の変更として表現されるため、完全な文字列比較を再計算することはありません。 

DP 遷移は、元の位置にあるエンドポイントの寄与を明示的に削除し、反転後にその寄与を追加します。 すべての内部寄与がすでに dp[l+1][r−1] にキャプチャされているため、これで十分です。 インデックス付けは内部的には慎重に 0 ベースですが、最終出力では 1 ベースに変換されます。 

タイブレーク ロジックは、すべての候補が保存されることを避けるために、DP の更新中に統合されます。 

## 実用的な例

 s1 と s2 が次のような小さな例を考えてみましょう。 

s1 = "アブカ"

 s2 = "アクバ"

 ベースラインの一致は位置 1 と 4 で発生するため、base = 2 となります。 

間隔 [1,3] (0 ベースのインデックス付け [0,2]) を評価します。 

| ステップ | l | r | 内部 dp | 古いマッチ | 新しい試合 | dp[l][r] |
 | --- | --- | --- | --- | --- | --- | --- |
 | 展開する | 0 | 2 | ベース | 1 | 1 | 2 |

 s2の「acb」を反転すると「bca」となり、s2は「bcaa」になります。 一致はポジション 1 と 4 になり、依然として 2 です。これは、すべての逆転でスコアが向上するわけではなく、スワップがキャンセルされたときに DP が中立性を正しく維持することを示しています。 

次に 2 番目の例を考えてみましょう。 

s1 = "abcd"

 s2 = "abdc"

 ベースライン一致 = 2。 

間隔 [2,3] は最後の 2 文字を交換します。 

| ステップ | l | r | 内側 | 古い | 新しい | DP |
 | --- | --- | --- | --- | --- | --- | --- |
 | [2,3] | 1 | 2 | 2 | 1 | 1 | 2 |

 これはスコアを維持するスワップを示しています。 さらに興味深いことに、間隔を大きくすると、複数の位置を同時に整列させることでスコアが増加する可能性があり、DP は対称補正を蓄積することでそれをキャプチャします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとに O(n^2) | 各 dp[l][r] は O(1) で計算され、すべての間隔が列挙されます。 
| スペース | O(n^2) | DP テーブルにはすべての間隔結果が保存されます。 

n が最大 1000、T が最大 50 であるため、最適化された Python では単純な算術演算で 5,000 万回の操作が許容されるため、これは時間制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    import sys as _sys
    input = _sys.stdin.readline

    T = int(input())
    res = []
    for _ in range(T):
        n = int(input())
        s1 = input().strip()
        s2 = input().strip()

        base = 0
        for i in range(n):
            if s1[i] == s2[i]:
                base += 1

        dp = [[0]*n for _ in range(n)]
        best_val = base
        best_l = best_r = 0

        for i in range(n):
            dp[i][i] = base
            if base > best_val:
                best_val = base
                best_l = best_r = i

        for length in range(2, n+1):
            for l in range(n-length+1):
                r = l+length-1
                inner = dp[l+1][r-1] if l+1 <= r-1 else base
                old = (s1[l]==s2[l]) + (s1[r]==s2[r])
                new = (s1[l]==s2[r]) + (s1[r]==s2[l])
                dp[l][r] = inner - old + new
                if dp[l][r] > best_val:
                    best_val = dp[l][r]
                    best_l, best_r = l, r

        res.append(f"{base} {best_val} {best_l+1} {best_r+1}")

    return "\n".join(res)

 ## 特殊なケース

 微妙なケースの 1 つは、最適な操作が何も行われない場合です。 たとえば、同一の文字列は塩基一致と単一文字セグメントを返す必要があります。 すべての dp[i][i] が基本スコアに等しく、タイブレークでは最小のセグメント長と最小のインデックスが優先されるため、DP はこれを自然に処理します。 

もう 1 つのケースは、逆転が不一致の順位にのみ影響を及ぼし、合計の一致は増加しない場合です。 s1 = "ab"、s2 = "ba" と考えてください。 文字列全体を逆にしても、ベースラインを超える改善は復元されません。 DP はシングル スワップとフル インターバル スワップの両方を正しく評価し、オーバーカウントがないことを保証します。 

最後のエッジ ケースは、より大きな間隔内での対称キャンセルです。 2 つのエンドポイント スワップは個別に一致を改善できますが、一緒にすると一致が減少します。 繰り返しでは、エンドポイントの寄与が明示的に削除され、再度追加されるため、二重にカウントすることなく、そのようなインタラクションを正確にキャプチャします。
