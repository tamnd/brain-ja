 ## 解決策
 ## 問題の理解

 0 から n − 1 までの数直線上に配置された動的間隔システムが与えられます。各新規人は間隔 [a, b] で到着し、到着順序に基づいて厳密に増加する識別子が割り当てられます。 その後、サービス リクエストはクエリ間隔 [c, d] として到着します。 各クエリについて、範囲がクエリ範囲と重複する、最後に追加された間隔を見つける必要があります。 クエリでその間隔が使用されると、その間隔は非アクティブとみなされ、二度と使用しないでください。 

そのため、常に増加するアクティブな間隔のセットを維持し、それぞれの間隔には挿入オーダーと同じタイムスタンプが付けられます。 クエリは、クエリ セグメントと交差するすべての間隔の中で最大のタイムスタンプを要求します。 応答後、選択した間隔はアクティブ セットから削除されます。 

主な問題は、挿入と削除の両方がオンラインで行われるため、クエリは常にクエリの時点での最新のアクティブな間隔を反映する必要があることです。 

この制約では、最大 200,000 のイベントと最大 1,000,000 の n が許可されます。 これにより、クエリごとにすべての間隔をチェックするアプローチは即座に除外されます。これは、単純なスキャンでは、最悪の場合、クエリごとに O(n) のコストがかかり、実行可能な制限をはるかに超える O(nm) につながるためです。 

いくつかの特殊なケースから、よくある落とし穴が明らかになります。 まず、複数の間隔が同じクエリに重複する可能性がありますが、それらの中で最新のものだけが重要です。 たとえば、間隔 1 が [0, 10]、間隔 2 が [3, 5]、間隔 3 が [4, 6] の場合、クエリ [4, 4] は間隔 2 または 1 ではなく、間隔 3 を選択する必要があります。 

第 2 に、間隔が使用されると、それ以降のすべての回答からその間隔が消えなければなりません。 適切に削除し忘れると、再度誤って選択される可能性があります。 

第三に、重なり合う構造が重要です。間隔は互いに素ではないため、ラインを素のセグメントに分割することに依存する構造は失敗します。 

## アプローチ

 簡単なアプローチは、すべての間隔をリストに保存し、クエリごとにすべての間隔を反復処理し、それらがクエリ範囲と交差するかどうかを確認し、最大のタイムスタンプを持つ間隔を取得することです。 タイムスタンプは最新性を直接エンコードし、交差チェックは O(1) であるため、これは正しいです。 ただし、最大 200,000 の間隔と 200,000 のクエリでは、最悪の場合、およそ 4 × 10^10 のチェックが必要となり、遅すぎます。 

重要な観察は、これが古典的な「削除のある間隔にわたる範囲の最大値」の問題であるということです。 クエリ範囲と交差するすべてのアクティブな間隔の中で、最も挿入時間が長いものを繰り返し答える必要があります。 

座標軸上のセグメント ツリーは、各間隔が O(log n) ノード、特にセグメント ツリー分解で完全にカバーされるノードにのみ格納されるように間隔を整理する方法を提供します。 各ノードは、そのセグメントを完全にカバーする間隔を追跡します。 各ノードについて、そこに保存されている最新のアクティブな間隔だけを知る必要があります。 

クエリを処理するときは、クエリ範囲内に完全にあるセグメント ツリー ノードをトラバースします。 このような各ノードは、その最良のアクティブ間隔候補に貢献します。 答えはこれらの候補の中で最大のものです。 

削除は遅延処理されます。 間隔が使用されると、その間隔は非アクティブとしてマークされます。 各ノードは間隔 ID のスタックを維持し、最上位にアクセスすると、最上位が再びアクティブになるまで無効な (すでに使用された) 間隔を破棄します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース スキャン | O(n · e) | O(n) | 遅すぎる |
 | 間隔スタックを含むセグメント ツリー | O(e log n) | O(e log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 座標範囲 [0, n − 1] にわたってセグメント ツリーを構築します。 各ノードはセグメントを表し、そのセグメントを完全にカバーする間隔を持つ間隔識別子のスタックを格納します。

また、間隔ごとに、挿入されたセグメント ツリー ノードのリストも維持します。これにより、後で非アクティブとしてマークすることで概念的に削除できます。 

### ステップ

 1. 新しい間隔が到着するたびに、増加する ID を割り当てます。 エンドポイントを保存し、アクティブとしてマークします。 
2. 区間をセグメント ツリーに挿入します。 セグメント ツリー ノードが [a, b] で完全にカバーされるたびに、間隔 ID をそのノードのスタックにプッシュします。 これにより、各間隔が O(log n) ノードに分散されるようになります。 
3. クエリ [c, d] が到着すると、セグメント ツリーをトラバースし、[c, d] に完全に含まれるノードのみを考慮します。 このようなノードごとに、非アクティブなエントリをクリーンアップした後、そのスタックトップを検査します。 
4. クリーニングとは、上部インターバルがアクティブでなくなっている間にスタックから繰り返しポップすることを意味します。 これにより、各ノードが常にその最良の有効な候補を公開するようになります。 
5. クエリに対する答えは、トラバーサル中に収集されたすべての有効なスタック トップの最大 ID です。 
6. 回答として間隔 ID を選択した後、それを非アクティブとしてマークし、今後のクエリで考慮されないようにします。 

### なぜ効果があるのか

 各間隔は、セグメント ツリー分解でそれを完全に表すノードに正確に保存されるため、その範囲内の任意の点は少なくとも 1 つのそのようなノードでカバーされます。 クエリ範囲が処理されるとき、クエリと交差するすべての間隔が、クエリ範囲内に完全に含まれる少なくとも 1 つのノードに表示される必要があります。 これらのノードの最大値を取ることで、候補区間を見逃すことがなくなります。 非アクティブな間隔は常にスタックから削除されるため、削除された間隔が誤って再利用されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, e = map(int, input().split())

# segment tree: each node stores list of interval ids
tree = [[] for _ in range(4 * n + 5)]

interval = [None]  # 1-indexed: (name, l, r)
active = [False]

def add(node, l, r, ql, qr, idx):
    if ql <= l and r <= qr:
        tree[node].append(idx)
        return
    mid = (l + r) // 2
    if ql <= mid:
        add(node * 2, l, mid, ql, qr, idx)
    if qr > mid:
        add(node * 2 + 1, mid + 1, r, ql, qr, idx)

def query(node, l, r, ql, qr):
    if ql <= l and r <= qr:
        while tree[node] and not active[tree[node][-1]]:
            tree[node].pop()
        return tree[node][-1] if tree[node] else 0

    mid = (l + r) // 2
    res = 0
    if ql <= mid:
        res = max(res, query(node * 2, l, mid, ql, qr))
    if qr > mid:
        res = max(res, query(node * 2 + 1, mid + 1, r, ql, qr))
    return res

for _ in range(e):
    tmp = input().split()
    t = tmp[0]

    if t == '1':
        name = tmp[1]
        a = int(tmp[2])
        b = int(tmp[3])
        interval.append((name, a, b))
        active.append(True)
        idx = len(interval) - 1
        add(1, 0, n - 1, a, b, idx)

    else:
        c = int(tmp[1])
        d = int(tmp[2])
        idx = query(1, 0, n - 1, c, d)
        if idx == 0:
            print("> <")
        else:
            print(interval[idx][0])
            active[idx] = False
```セグメント ツリー挿入機能は、各間隔をその範囲が完全にカバーするノードにのみ分配します。 これにより、ポイントごとの冗長な情報の保存が回避されます。 クエリ関数は、関連するセグメント ツリーの分岐のみをたどり、利用可能な最良の間隔 ID を収集します。 

重要な点は遅延削除です。 インターバルが表示されるすべてのノードからインターバルを削除しようとするのではなく、単純にインターバルを非アクティブとしてマークし、ノードのスタックトップで見つかったときに消去します。 これにより、業務の効率が維持されます。 

## 実用的な例

 ### 例 1

 n = 10 の小規模システムを考えてみましょう。 

ID 1 の間隔 A = [2, 6]、ID 2 の間隔 B = [4, 8]、ID 3 の間隔 C = [5, 7] を挿入します。 

ここでクエリ [5, 5] を処理します。 

| ステップ | ノード カバレッジ | スタックトップの検討 | 最高のID |
 | --- | --- | --- | --- |
 | クエリ | 5 をカバーするノード | A=1、B=2、C=3 | 3 |

 重複する間隔の中で最も高い ID を持つため、結果は間隔 C になります。 

出力後、間隔 C は非アクティブとしてマークされます。 別のクエリ [5, 5] が再度発行されると、C が削除されるため、答えは 2 になります。 

### 例 2

 間隔:

 [0, 9] ID 1、[3, 4] ID 2、[6, 8] ID 3。 

クエリ [7, 7]:

 区間 1 と区間 3 のみが交差します。 間隔 3 の方が新しいです。 

| ステップ | アクティブな間隔 | 候補者 | 結果 |
 | --- | --- | --- | --- |
 | クエリ | {1,3} | 1 と 3 | 3 |

 再度クエリ [7, 7] を実行すると、区間 1 だけが残るため、結果は 1 になります。 

これらのトレースは、削除が将来のクエリにどのように直接影響するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(e log n) | 各挿入とクエリは O(log n) ノードに影響します。 
| スペース | O(e log n) | 各間隔は O(log n) 個のセグメント ツリー ノードに保存されます。 

log n が約 20 であるため、境界 n ≤ 10^6 および e ≤ 200,000 はこの複雑さ内に快適に収まり、合計でおよそ数百万の操作が行われることになります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, e = map(int, input().split())

    tree = [[] for _ in range(4 * n + 5)]
    interval = [None]
    active = [False]

    def add(node, l, r, ql, qr, idx):
        if ql <= l and r <= qr:
            tree[node].append(idx)
            return
        mid = (l + r) // 2
        if ql <= mid:
            add(node * 2, l, mid, ql, qr, idx)
        if qr > mid:
            add(node * 2 + 1, mid + 1, r, ql, qr, idx)

    def query(node, l, r, ql, qr):
        if ql <= l and r <= qr:
            while tree[node] and not active[tree[node][-1]]:
                tree[node].pop()
            return tree[node][-1] if tree[node] else 0

        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res = max(res, query(node * 2, l, mid, ql, qr))
        if qr > mid:
            res = max(res, query(node * 2 + 1, mid + 1, r, ql, qr))
        return res

    out = []
    for _ in range(e):
        tmp = input().split()
        if tmp[0] == '1':
            name = tmp[1]
            a, b = map(int, tmp[2:])
            interval.append((name, a, b))
            active.append(True)
            add(1, 0, n - 1, a, b, len(interval) - 1)
        else:
            c, d = map(int, tmp[1:])
            idx = query(1, 0, n - 1, c, d)
            if idx == 0:
                out.append("> <")
            else:
                out.append(interval[idx][0])
                active[idx] = False

    return "\n".join(out)

assert run("5 3\n1 A 0 2\n1 B 1 3\n2 1 1\n") == "B"
assert run("5 4\n1 A 0 4\n1 B 1 2\n2 1 1\n2 1 1\n") == "B\nA"
assert run("10 3\n2 1 5\n1 X 0 9\n2 1 5\n") == "X"

 | --- | --- | --- |
 | 即時クエリで重複する間隔 | B | max-id 選択の正確さ |
 | 削除後に繰り返されたクエリ | B の次に A | 適切な削除動作 |
 | 任意の間隔の前にクエリを実行する | X | 空の状態の処理 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の間隔が同じ領域に重なっており、クエリ後に最新の間隔が削除される場合です。 構造物は誤って再利用してはなりません。 これは、それを非アクティブとしてマークし、最上位に到達した場合にのみスタックから遅延的に削除することで処理されます。 

もう 1 つのエッジ ケースは、アクティブな間隔と交差しないクエリ範囲です。 この場合、訪問したノード間ですべての候補が空のままになり、アルゴリズムは「> <」を出力するセンチネル値を正しく返します。 

最後に、[0, n − 1] などの非常に広い範囲をカバーする間隔は、非常に少数のセグメント ツリー ノードに挿入されますが、多くのクエリに現れます。 各クエリは O(log n) ノードのみに接触するため、セグメント ツリーによって効率的に処理されることが保証されます。
