 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられています。`a`そして`b`。 文字列`a`のあらゆる可能な位置に挿入されます`b`、最初の文字の前と最後の文字の後を含みます。 もし`b`長さがある`m`、これにより生成される`m + 1`異なる文字列。それぞれがカット位置に対応します。`b`。 

次に、これらを並べ替えます`m + 1`辞書順の文字列。 結果として得られる 2 つの文字列が同一である場合、最初に大きい挿入インデックスを優先することによって関係を解消します。 ソート後、元の挿入位置を順番に記録します。 これにより、次のインデックスの順列が得られます。`0`に`m - 1`（そして`m`「最後に追加」の位置は、ステートメントのインデックス付けとの解釈の一貫性に応じて異なります)。 

最後に、この完全な順列を出力する代わりに、ソートされた順序のインデックスがべき乗位置として機能する加重和を計算し、各挿入インデックスに増加する基本べき乗を乗算します。 

主な課題は、テスト ケースの数と文字列の合計の長さが大きいため、挿入されたすべての文字列を明示的に構築して並べ替えるのが遅すぎることです。 

この制約は、テスト ケースごとに慎重な前処理を行って、文字列の全長が線形に近づく必要があることを意味します。 構築する素朴なアプローチ`m + 1`一定の長さの文字列`n + m`それらを大まかに並べ替えるには`O(m^2 log m)`最悪の場合の文字比較。全長が 0.5 に達すると完全に不可能になります。`2 × 10^6`。 

さらに微妙な問題は、タイでの正しさです。 2 つの挿入位置で同一の文字列が生成される場合、問題により、大きいインデックスがソート順で最初に来る必要があります。 文字列を辞書順に比較するだけの不注意なコンパレータは、対称位置への挿入などの場合に失敗します。`a`繰り返されるパターンと一致します`b`。 

タイ動作の最小限の例は、次の場合に発生します。`a = "a"`そして`b = "aa"`。 位置 0、1、2 に挿入すると、次の結果が得られます。`"aaa"`すべての場合において。 正しい順序はインデックスです`[2, 1, 0]`、最初に大きなインデックスによって同順位が明示的に破られるため、任意の安定した順序ではありません。 不安定なソートまたはデフォルトのタプル順序付けに依存するソリューションでは、このルールを明示的にエンコードする必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 挿入位置ごとに`i`、完全な文字列を構築します`S[i]`連結することで`b[0:i] + a + b[i:]`。 次に、すべてを並べ替えます`m + 1`インデックスのタイブレークを使用した標準の辞書編集比較を使用した文字列。 ソート後、必要な加重合計を計算します。 

これは定義に直接従うため、正しいです。 失敗点はパフォーマンスです。 2 つの文字列間の各比較にはコストがかかる場合があります`O(n + m)`最悪の場合、ソート`m`アイテムのニーズ`O(m log m)`比較により、`O(m (n + m) log m)`テストケースごとに。 全長まで`2 × 10^6`、これは実現可能な限界をはるかに超えています。 

重要な点は、実際には完全な文字列が必要ないということです。 各候補文字列は同じ文字列を挿入することによって形成されます`a`のさまざまな場所に`b`。 2 つの候補間の比較は、それらが最初に異なる場所に依存し、その構造は次の部分文字列を比較することに還元できます。`b`プラス 1 つの比較`a`。 

について十分な情報を前処理すると、`a`そして`b`を使用すると、「どの挿入位置でより小さい文字列が得られるか」を定数時間または対数時間で答えることができます。 標準ツールは Z アルゴリズムまたは LCP 前処理で、これにより、次の接尾辞を比較できます。`b`に対して`a`効率的に。 

任意の 2 つの挿入位置をすぐに比較できるようになると、問題はインデックスの並べ替えになります。`0..m`カスタムコンパレータを使用します。 ボトルネックは次のようになります。`O(m log m)`それぞれの比較`O(1)`または`O(log n)`実装に応じて、快適にフィットします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m (n + m) log m) | O(m (n + m)) | 遅すぎる |
 | 最適 | 前処理後の O(m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの挿入位置を扱います`i`仮想文字列として`S[i] = b[0:i] + a + b[i:]`。 目標は、これらの仮想文字列の辞書編集順にインデックスを並べ替え、より大きなインデックスによるタイブレークを行うことです。 

素早く比較する方法が必要です`S[i]`そして`S[j]`。 

まず、次の間の最長のプレフィックス一致を前処理します。`a`そして`b`Z 配列を使用する`a + '#' + b`。 これにより、どの位置でも知ることができます。`b`、一致する文字の数`a`その位置からスタートします。 

次の接尾辞間の比較も必要です。`b`、それは自明のことなので、`b`静的であり、直接インデックスを作成できます。 

1. 結合文字列を構築する`t = a + '#' + b`そしてそれに対して Z 配列を計算します。 これにより、すべての位置に対して、`b`、最長のプレフィックス`a`そこから始まるものと一致します。 これはコストがかかる唯一の前処理ステップであり、直線的です。 
2. 2 つの挿入インデックスのコンパレータを定義します`i`そして`j`。 比較シミュレーションしてみます`S[i]`そして`S[j]`構築せずに。 
3. 両方の文字列がまだ内側にある限り、左から文字を比較します。`b`。 もし`b[i + k] != b[j + k]`、比較はすぐに決まります。 
4. 両方のプレフィックスが内部で一致する場合`b`ある程度の長さを続けると、最終的には挿入ポイントに到達します。`a`。 その境界で比較します。`a`の対応する位置に対して`b`挿入ごとに。 
5. Z 配列を使用して、文字ごとの比較をスキップします。`a`そして`b`挿入境界で。 これにより、どの文字列が最初に分岐するかが決まります。 
6. 両方の文字列が完全なオーバーラップを通じて同一のままである場合は、タイブレーク ルールに戻ります。つまり、大きいインデックスが最初に来ます。 
7. すべてのインデックスを次から並べ替えます`0`に`m`このコンパレータを使用します。 
8. ソート後、累積して最終的な答えを計算します`ans += sorted[i] * (1234567^i mod MOD)`。 

正確かどうかは、挿入された 2 つの文字列間の差異は、共有プレフィックスのいずれかで発生する必要があるという事実に依存します。`b`、挿入された`a`、または接尾辞に`b`。 Z 配列を使用すると、文字ごとにスキャンすることなくこれらの領域間の遷移を検出できるため、効率を維持しながら正確さを維持できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def z_function(s):
    n = len(s)
    z = [0] * n
    l = r = 0
    for i in range(1, n):
        if i <= r:
            z[i] = min(r - i + 1, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] - 1 > r:
            l, r = i, i + z[i] - 1
    return z

def solve():
    a = input().strip()
    b = input().strip()
    n, m = len(a), len(b)

    # Z on a + '#' + b
    combined = a + '#' + b
    z = z_function(combined)

    def match_len_b(pos):
        # longest prefix of a matching b[pos:]
        return z[n + 1 + pos]

    def cmp(i, j):
        # compare S[i] and S[j]
        bi = bj = 0

        # phase 1: compare within b before insertion
        while i + bi < m and j + bj < m and bi == bj:
            if b[i + bi] != b[j + bj]:
                return b[i + bi] < b[j + bj]
            bi += 1
            bj += 1

        # if one reaches end of b earlier
        if i + bi == m or j + bj == m:
            if i + bi == m and j + bj == m:
                return i > j
            return i + bi == m

        # now insertion happens at (i+bi) and (j+bj)
        pi = i + bi
        pj = j + bj

        # compare insertion a vs b at pi/pj using z
        li = match_len_b(pi)
        lj = match_len_b(pj)

        if li != lj:
            return li < lj

        # compare next character after match
        ci = a[li] if li < n else b[pi + li]
        cj = a[lj] if lj < n else b[pj + lj]

        if ci != cj:
            return ci < cj

        return i > j

    arr = list(range(m + 1))
    from functools import cmp_to_key
    arr.sort(key=cmp_to_key(cmp))

    powv = 1
    ans = 0
    for i, v in enumerate(arr):
        ans = (ans + v * powv) % MOD
        powv = powv * 1234567 % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、Z 関数を構築して、`a`そして、のすべての接尾辞`b`。 コンパレータは、挿入された文字列の構築を回避し、各挿入がどこまで一致するかを判断するだけです。`a`その境界で。 タイブレーク ルールは、より大きなインデックスを優先することによって明示的に処理されます。 

微妙な点の 1 つは、2 つの挿入位置で同一の文字列が生成された場合に、コンパレータが必ず次の値を返すようにすることです。`i > j`。 これにより、ソートの安定性に依存せずに、必要な順序付けが強制されます。

 ## 特殊なケース

 重要なエッジケースは挿入時です。`a`複数の位置に同一の文字列を生成します。 このような場合、コンパレータは文字列比較のみに依存してはなりません。 たとえば、次のようなとき`a = "a"`そして`b = "aaa"`、挿入ごとに生成される`"aaaa"`、必要な出力順序は厳密に降順のインデックスです。 コンパレータは明示的に返すことでこれを処理します。`i > j`比較されるすべての文字が等しい場合。 

別の特殊なケースが発生するのは、`a`のサフィックスを持つ長いプレフィックスを共有します`b`。 Z 配列は、比較で一致するセグメント全体をスキップすることを保証し、タイムアウトを防ぎ、境界が一貫して処理されない場合に単純な文字ごとの比較が危険にさらす誤った初期の不一致を回避します。
