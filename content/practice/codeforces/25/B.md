 ## 解決策
 ## 問題の理解

 電話番号を表す数字の文字列が与えられます。 タスクは、この文字列を、各部分の長さが 2 または 3 になるように複数の部分に分割することです。グループは元の順序で出現する必要があり、それらは次のように結合されます。`-`出力内の文字。 

この問題では、考えられるすべてのパーティションが必要というわけではありません。 有効なグループ化はどれでも受け入れられます。 

制約はわずかです。 電話番号の長さは最大 100 であるため、かなり非効率なソリューションでも制限内で快適に実行できます。 これにより、問題の性質が変わります。 課題は最適化ではなく、常に機能するグループを構築し、小さなケースを正しく処理することです。 

難しいのは、欲張って選択すると、誤って最後に 1 桁が残る可能性があることです。 長さ 1 のグループは不正であるため、アルゴリズムはそのような状況の発生を回避する必要があります。 

次の入力を考えてみましょう。```
5
12345
```最初に 3 つのグループを貪欲に取得すると、次のようになります。```
123-45
```これは有効です。 

しかし、別の方法で処理し、最初に 2 つのグループを取得すると、次のようになります。```
12-34
```私たちに残っているのは`5`、有効なグループを形成できません。 

もう 1 つの微妙なケースは、残りの長さが 4 になる場合です。例:```
7
1234567
```すぐに 3 人のグループを選択すると、次のようになります。```
123-456
```私たちに残っているのは`7`、これは無効です。 

正しい戦略は次のとおりです。```
12-34-567
```または```
123-45-67
```最終的に残った長さは常に 2 と 3 に分解できるため、どちらも機能します。 

最小の有効な入力にも注意が必要です。```
2
98
```文字列全体自体がすでに 1 つの有効なグループになっています。 常に最初に 3 桁を抽出しようとする不用意な実装は、すぐに失敗します。 

## アプローチ

 ブルートフォースソリューションでは、あらゆる方法で文字列を分割しようとします。 各位置で 2 桁または 3 桁を取得し、残りを再帰的に計算します。 各ポジションが 2 つの選択肢に分岐するため、可能性の総数は指数関数的に増加します。 

長さが約 100 になると、再帰状態の数が膨大になります。 多くのブランチが早期に消滅しても、このような構造化された問題に対して単純な徹底的な検索は不必要な作業です。 

ブルートフォースが概念的に機能する理由は単純です。 すべての有効なパーティションは、長さ 2 から 3 までの選択肢のシーケンスにすぎません。すべてのシーケンスを探索すると、最終的には有効なパーティションが見つかります。 

重要な点は、検索する必要がないということです。 長さ 2 以上のすべての数値は、長さ 1 を除き、常に 2 と 3 のみを使用して表すことができます。したがって、本当の目標は、ちょうど 1 桁がグループ化されないままになることを避けることだけです。 

それは直接的な建設的な戦略につながります。 4 桁以上残っている間は、安全に 2 つのグループを取得します。なぜ 2 なのか? 繰り返し 2 を減算すると、残りのサフィックスを 2 または 3 のグループで終了する機能が保持されるためです。 

残りの長さが 2、3、または 4 になったら、停止して直接処理します。 

2 桁が残っている場合は、2 つのグループを 1 つ取ります。 

3 桁が残っている場合は、3 つのグループを 1 つ取ります。 

4 桁が残っている場合は、2 つずつ 2 つのグループに分割します。 

これにより、無効なサイズのグループがないことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 概念的には遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 電話番号文字列を読み取ります。 
2. という名前の空のリストを作成します。`groups`結果のチャンクを保存します。 
3. 現在の未読位置を指すインデックスを維持します。 
4. 残りの桁数が 4 桁より大きい場合は、次の 2 桁を取り出して次の桁に追加します。`groups`。 

2 桁を繰り返しても、余りが 1 になることがないため安全です。 
5. ループが終了した後、残りの長さは 2、3、または 4 でなければなりません。 
6. 2 桁が残っている場合は、それらを 1 つの最後のグループとして追加します。 
7. 3 桁が残っている場合は、それらを 1 つの最後のグループとして追加します。 
8. 4 桁が残っている場合は、2 桁ずつ 2 つのグループに分割し、両方を追加します。 

4を分割すると`2 + 2`サイズ 1 の禁止されたグループの生成を回避します。 
9. が参加しているすべてのグループを印刷します。`-`。 

### なぜ効果があるのか

 このアルゴリズムは単純な不変条件を維持します。つまり、各ステップの後でも、サイズ 2 と 3 のグループのみを使用して残りの桁数を表現できます。 

4 を超える有効な残りの長さから 2 を減算すると、残りが有効なままになります。 このプロセスは最終的に、基底長 2、3、または 4 のいずれかに到達します。これらはすべて直接有効な分解を持ちます。 

唯一不可能な剰余は 1 であり、アルゴリズムは特に剰余を作成しないように設計されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

groups = []
i = 0

while n - i > 4:
    groups.append(s[i:i + 2])
    i += 2

remaining = n - i

if remaining == 2:
    groups.append(s[i:i + 2])
elif remaining == 3:
    groups.append(s[i:i + 3])
else:
    groups.append(s[i:i + 2])
    groups.append(s[i + 2:i + 4])

print("-".join(groups))
```解決策は建設的な戦略に直接従うものです。 

変数`i`すでに処理された桁数を追跡します。 長さ 2、3、4 は追加の決定を行わなくても安全に終了できるため、4 桁以上が残っている間はループが継続します。 

長さ 4 の処理は最も重要な境界条件です。 よくある間違いは、3 人のグループを先に取り、1 桁を残すことです。 に分割`2 + 2`その問題を完全に回避します。 

この実装では、元の文字列のスライスを使用します。これは、これらの小さな制約に対してクリーンで効率的です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    groups = []
    i = 0

    while n - i > 4:
        groups.append(s[i:i + 2])
        i += 2

    remaining = n - i

    if remaining == 2:
        groups.append(s[i:i + 2])
    elif remaining == 3:
        groups.append(s[i:i + 3])
    else:
        groups.append(s[i:i + 2])
        groups.append(s[i + 2:i + 4])

    print("-".join(groups))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

# provided sample
assert run("6\n549871\n") == "54-98-71", "sample 1"

# minimum size
assert run("2\n98\n") == "98", "minimum length"

# exactly 3 digits
assert run("3\n123\n") == "123", "single group of 3"

# exactly 4 digits
assert run("4\n1111\n") == "11-11", "split 4 into 2+2"

# odd length
assert run("7\n1234567\n") == "12-34-567", "avoid leftover 1"

# maximum-style repetitive case
assert run("10\n9999999999\n") == "99-99-99-99-99", "many groups of 2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / 98`|`98`| 有効な最小入力値 |
 |`3 / 123`|`123`| 3 人グループ |
 |`4 / 1111`|`11-11`| 剰余 4 の正しい処理 |
 |`7 / 1234567`|`12-34-567`| サイズ残り防止1 |
