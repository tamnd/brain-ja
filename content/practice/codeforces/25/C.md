 ## 解決策
 ## 問題の理解

 ベルランドの _n_ 都市の地図が与えられましたが、すべてのペア間の最短距離はすでにわかっています。 概念的には、これは国が何らかの未知の道路セットを介して完全に接続されており、距離行列がすでにすべてのペアの最短経路の結果であることを意味します。 政府は、_k_ 個の新しい道路を追加することを計画しており、追加するたびに、都市の各ペア間の最短距離の合計を求めています。 

入力は最短距離行列を提供します`d`計画された道路のリストとその終点と長さ。 私たちのタスクは、これらの道路を 1 つずつ追加することをシミュレートし、最短パスの新しい合計を効率的に計算することです。 出力は合計のリストで、道路の追加ごとに 1 つずつ表示されます。 

制約は厳しいですが、対処可能です。 _n_ が最大 300 の場合、Floyd-Warshall を使用した各道路後のすべてのペアの最短経路の素朴な再計算は O(n³ * k) となり、最悪の場合、300³ * 300 = 8.1 × 10^9 の演算となり、遅すぎます。 もっと賢い更新メカニズムが必要です。 

明らかではないエッジケースには、道路を追加しても 2 つの終点間の距離が直接的に短縮されないが、間接的に他の都市間の経路が改善される状況が含まれます。 たとえば、行列が最初に次のようになっている場合、`d[1][2] = 10`そして`d[1][3] = 5`、`d[3][2] = 4`の場合、長さ 7 の 1 から 2 への直線道路を追加しても、直接変化しません。`d[1][2]`10 > 7 なので、他のパスの組み合わせによって他の距離が短縮されるかどうかも確認する必要があります。 直接エンドポイントのみを更新する不注意な実装では、不正確な合計が生成されます。 

## アプローチ

 強引な解決策は、新しい道路をそれぞれ追加し、Floyd-Warshall を実行してすべての最短距離を再計算することです。 フロイド・ウォーシャルの複雑さは O(n³) なので、それを k 個の道路で繰り返すと O(k * n³) になります。 これは正しいですが、n、k ~ 300 の場合は実行できません。行列が再計算されれば、ペアの合計は自明に計算できます。 

重要な観察点は、新しい道路ができるたびに、`(a, b, c)`経由でより短いパスを作成する場合にのみ距離に影響します。`a`または`b`。 具体的には、どのペアでも`(i, j)`、新しい最短距離は次のとおりです。```
d[i][j] = min(d[i][j], d[i][a] + c + d[b][j], d[i][b] + c + d[a][j])
```この式は、新しい道路を通過することで 2 つの都市間の経路が短縮されるかどうかを確認します。 すべてのペアを反復処理します`(i, j)`このアップデートを使用して。 行列は対称であり、順序のないペアのみが必要なので、反復できます。`i`1からnまで、そして`j`から`i+1`を n に増やし、不必要な計算を削減します。 

これにより、道路ごとの更新が O(n²) に削減され、合計複雑度 O(k * n²) が得られます。これは、n、k ≤ 300 (最悪の場合、約 2,700 万回の操作) では許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (道路ごとのフロイド-ウォーシャル) | O(k * n³) | O(n²) | 遅すぎる |
 | 最適 (新しい道路を使用した直接パス更新) | O(k * n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期の最短距離行列を読み取ります。`d`そしてそれを保管します。 入力によりすべてのペアの最短距離がすでに保証されているため、前処理は必要ありません。 
2. 変数を初期化する`sum_pairs`すべての順序なしペアの合計`(i, j)`で`d`。 合計するだけです`i < j`二重カウントを避けるため。 
3. 計画道路ごとに`(a, b, c)`、すべてのペアを反復処理します`(i, j)`そして、この道路を経由するルーティングによってパスが短縮されるかどうかを確認します。 

- コンピューティング`d[i][a] + c + d[b][j]`そして`d[i][b] + c + d[a][j]`。 
- どちらかが現在より小さい場合`d[i][j]`、 アップデート`d[i][j]`最小限に。 
- のために`i < j`、 調整する`sum_pairs`古いものを差し引いて段階的に`d[i][j]`そして新たな価値を加えていく。 
4. 現在の道路を処理した後、追加します`sum_pairs`結果リストへ。 次の道へ進みます。 
5. 最後に結果リストを出力します。 

機能する理由: 更新式により、新しく追加された道路に関係する可能性のあるすべての新しい最短パスが確実に考慮されます。 以来`d`には常に各反復の開始時の最短距離が含まれており、この更新を反復的に適用すると、すべてのペアの正確さが維持されます。 のみの合計`i < j`二重カウントを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
d = [list(map(int, input().split())) for _ in range(n)]

k = int(input())
roads = [tuple(map(int, input().split())) for _ in range(k)]

# Adjust indices to 0-based
d = [[d[i][j] for j in range(n)] for i in range(n)]
sum_pairs = sum(d[i][j] for i in range(n) for j in range(i+1, n))

res = []

for a, b, c in roads:
    a -= 1
    b -= 1
    for i in range(n):
        for j in range(n):
            # Check if a path through the new road improves distance
            new_dist = min(d[i][j], d[i][a] + c + d[b][j], d[i][b] + c + d[a][j])
            if new_dist < d[i][j]:
                if i < j:
                    sum_pairs -= d[i][j]
                    sum_pairs += new_dist
                d[i][j] = new_dist
    res.append(sum_pairs)

print(" ".join(map(str, res)))
```コードの各セクションはアルゴリズムのステップを直接実装します。 インデックスをゼロベースに慎重に調整します。 の増分更新`sum_pairs`各道路の後に合計を最初から再計算することを避けます。 全体を反復処理する`(i, j)`潜在的な新しい短いパスが見逃されないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    d = [list(map(int, input().split())) for _ in range(n)]
    k = int(input())
    roads = [tuple(map(int, input().split())) for _ in range(k)]
    d = [[d[i][j] for j in range(n)] for i in range(n)]
    sum_pairs = sum(d[i][j] for i in range(n) for j in range(i+1, n))
    res = []
    for a, b, c in roads:
        a -= 1
        b -= 1

            for j in range(n):
                new_dist = min(d[i][j], d[i][a]+c+d[b][j], d[i][b]+c+d[a][j])
                if new_dist < d[i][j]:
                    if i < j:
                        sum_pairs -= d[i][j]
                        sum_pairs += new_dist
                    d[i][j] = new_dist
        res.append(sum_pairs)
    return " ".join(map(str, res))
