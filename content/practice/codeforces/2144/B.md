 ## 解決策
 ## 問題の理解

 配列が与えられています`p`長さの`n`ここで、一部の位置には 1 から 2 までの整数が含まれます。`n`その他はゼロです。 正の整数が複数回出現することはありません。 ゼロはプレースホルダーであり、配列が 1 から 1 までの適切な順列になるように欠落している数値で置き換えることができます。`n`。 有効な順列が得られたら、順列全体をソートするためにソートする必要がある最小の連続サブセグメントの長さとして順列のコストを定義します。 

課題は、このコストを最大化することです。 つまり、順列を修正するためにソートする必要があるサブセグメントができるだけ長くなるように、欠落した数値をゼロに配置したいと考えています。 各テスト ケースの出力は単一の整数、つまり達成可能な最大コストです。 

制約は次のことを教えてくれます`n`は 2 * 10^5 まで大きくなり、次の合計は`n`すべてのテスト ケース全体で最大 2 * 10^5 です。 これにより、欠落した数値の順列の数が階乗的に増加するため、あらゆる方法でゼロを埋めようとする強引な解決策が排除されます。 代わりに、次の点に関して線形時間で機能するアプローチが必要です。`n`。 

明らかではないエッジ ケースには、すべての要素が 0 である配列、すでに並べ替えられている配列、または欠落しているすべての数値が一方の端に集まっている配列が含まれます。 たとえば、配列`[0, 0, 0]`配列が次のようになるように数値を配置できるため、最大コストは 3 です。`[3, 1, 2]`そして配列全体をソートする必要があります。 一方で、`[1, 2, 3, 0]`欠落している数値は最後にある 4 だけであり、配列はすでにソートされているため、コストは 0 です。 不注意なアプローチでは、単にゼロを数えたり、既存の数値の位置を無視したりする可能性があり、このような特殊なケースでは誤った答えが生成される可能性があります。 

## アプローチ

 素朴なアプローチでは、ゼロを欠落した数値で埋め、順列を構築し、ソートする最小のセグメントをスキャンしてコストを計算するあらゆる方法を試みます。 特定の順列のセグメント コストの計算は、配列の順序が崩れている左から最初の場所と、順序が乱れている右から最後の場所を見つけることで実行できます。 ただし、これにはゼロの階乗の組み合わせを生成する必要があり、これは完全に不可能です。`n`最大 2 * 10^5。 

重要な観察は、最大コストが最初のゼロで始まり最後のゼロで終わる部分配列に対応するということです。 ゼロセグメントの外側に数値が配置されても、ソートコストは増加しないか、減少します。 したがって、配列内のゼロの最初と最後の位置を識別できます。 次に、考えられる最大のコストは、端にすでに正しく配置されている数字を考慮して調整された、これらの位置間の距離です。 具体的には、このゼロセグメントの外側の番号はすでに適切であり、コストが増加することはありません。 

これにより、問題は、配列内の最初と最後のゼロ位置を見つけて、その差に 1 を加えたものを最大のコストとして取得するという問題に軽減されます。 順列を明示的に構築する必要はありません。 ゼロの位置だけで、強制的にソートを解除できるセグメントの最大長が決まります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`p`。 
2.初期化`first_zero`そして`last_zero`-1まで。 
3. 配列を左から右に繰り返します。 最初のゼロに遭遇したら、そのインデックスを次の場所に保存します。`first_zero`。 
4. 反復と更新を継続する`last_zero`ゼロに遭遇するたびに。 配列の終わりまでに、`last_zero`最後のゼロのインデックスが含まれます。 
5. ゼロがない場合 (`first_zero`-1 のまま)、配列はすでに完全な置換であるため、最大コストは 0 です。 
6. それ以外の場合、最大コストは次のとおりです。`last_zero - first_zero + 1`。 これは、すべてのゼロをカバーする連続セグメントの長さに相当します。これは、欠落している数値を巧みに配置することで強制的に並べ替えることができる最大のサブセグメントです。 
7. テスト ケースのこの最大コストを出力します。 

機能する理由: ゼロの位置は、数字が欠落している連続セグメントを定義します。 欠落している数値を配置して最大の無秩序を作成することで、最初のゼロと最後のゼロの間のセグメント全体をソートする必要があることを確認できます。 このセグメント外の数値は固定されており、仕分けコストの増加には寄与しません。 したがって、セグメントの長さが達成可能な最大コストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))
    
    first_zero = -1
    last_zero = -1
    
    for i in range(n):
        if p[i] == 0:
            if first_zero == -1:
                first_zero = i
            last_zero = i
    
    if first_zero == -1:
        print(0)
    else:
        print(last_zero - first_zero + 1)
```コードは、テスト ケースの数を読み取ることから始まります。 テスト ケースごとに、配列サイズと配列自体を読み取ります。 次に、配列をスキャンして最初と最後のゼロを見つけます。 ゼロが見つからない場合、配列は完全でソートされているため、0 が出力されます。そうでない場合は、すべてのゼロをカバーするセグメントの長さを計算します。 配列の単一パスを使用すると、複雑さは O(n) になり、必要な変数はわずかであるため、スペースの使用量は O(1) になります。 

## 実用的な例

 **例 1:**`p = [1, 0, 4, 0, 5]`| 私 | p[i] | 最初のゼロ | 最後のゼロ |
 | --- | --- | --- | --- |
 | 0 | 1 | -1 | -1 |
 | 1 | 0 | 1 | 1 |
 | 2 | 4 | 1 | 1 |
 | 3 | 0 | 1 | 3 |
 | 4 | 5 | 1 | 3 |

 セグメントの長さ: 3 - 1 + 1 = 3。 

これは、アルゴリズムがセグメントを正しく識別していることを示しています。`[0, 4, 0]`ソートされていない最大のものとして。 

**例 2:**`p = [0, 0, 0]`| 私 | p[i] | 最初のゼロ | 最後のゼロ |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 0 | 0 | 1 |
 | 2 | 0 | 0 | 2 |

 セグメントの長さ: 2 - 0 + 1 = 3。 

すべてゼロで完全な配列を形成し、最大限の無秩序を与えます。

    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        first_zero = -1
        last_zero = -1
        for i in range(n):
            if p[i] == 0:
                if first_zero == -1:
                    first_zero = i
                last_zero = i
        if first_zero == -1:
            print(0)
        else:
            print(last_zero - first_zero + 1)
    return output.getvalue().strip()
