 ## 問題の理解

 いくつかの長括弧文字列が与えられます。それぞれの長さは最大です。$k$そして、すべての文字列を正確に 1 つのグループに割り当てる必要があります。 各グループに対して、正確な長さの単一の「参照」通常括弧シーケンスも構築します。$k$。 グループの規則は、そのグループに割り当てられた文字列がその参照シーケンス内で連続した部分文字列として出現してはいけないということです。 

通常の括弧シーケンスは、バランスのとれた括弧式のように動作します。 幾何学的な観点では、これはゼロを下回ることはなく、最後にゼロに戻るダイク パスに対応します。 部分文字列制約は、そのようなパスのローカル セグメントがどのように見えるかに関する制約に変換されるため、この解釈は重要です。 

出力ではグループの最小数が要求され、グループごとに 1 つの有効な長さを出力する必要があります。$k$通常のシーケンスとそれに割り当てられたインデックス。 

重要な問題は、各グループがグローバル回避条件によって制約されていることです。選択されたシーケンスは、そのグループのすべての禁止された部分文字列を回避する必要があります。 したがって、グループ化は文字列ごとに独立しているわけではなく、グローバルな互換性の問題です。 

制約は小さいです。$n \le 50$、$k \le 50$。 これにより、指数関数的なものはすぐに除外されます$k$グループごとですが、それでも指数関数的な入力が可能です$n$または$2^k$-スタイルのDP。 以来$k$小さいので、長さを構築するという観点から考えることができます-$k$構造を確認し、禁止された部分文字列を直接チェックします。 

微妙なエッジ ケースは、文字列が有効なグループにまったく現れない場合です。 これは、文字列自体が、考えられるすべての長さの通常の括弧シーケンスに出現するという意味で、すでに「大きすぎる」場合に発生します。$k$。 たとえば、文字列が既に完全な Dyck パス プレフィックスになっており、補完のどこかに必ず表示される必要がある場合、それを回避することは不可能になります。 単純なアプローチでは、すべての文字列は慎重に選択されたシーケンスによって常に回避できると想定されるかもしれませんが、これは真実ではありません。 

もう 1 つの失敗ケースは、オーバーラップ相互作用を無視することで発生します。2 つの文字列はシーケンス内で個別に回避可能ですが、それらの禁止位置がすべての可能な構造と重複するため、一緒に矛盾が生じます。 

## アプローチ

 強引なアイデアは、考えられるすべての分割を考慮することです。$n$文字列をグループに分割します。 各グループについて、有効な長さを構築しようとします。$k$そのグループ内のすべての文字列を部分文字列として避ける通常の括弧シーケンス。 構築は、プレフィックス状態を介した DP または長さのすべての Dyck シーケンスのブルート生成を介して実行できます。$k$、次に部分文字列制約をチェックします。 

パーティションの数$n=50$膨大な数（ベル数）、すでに存在しています$10^{47}$なので、パーティションの列挙は不可能です。 多くのグループを修正したとしても、割り当ての実現可能性をチェックすることは依然として組み合わせ爆発的です。 

重要な観察は、個別の禁止文字列の数が少なく、各制約が非常に強い意味でローカルであること、つまり長さの文字列であることです。$L \le k$は、候補シーケンス内で一致する可能性のある一連の位置を禁止します。 パーティションについて推論する代わりに、視点を反転します。まず、候補となる規則的なシーケンスを構築し、次に、そのシーケンスの部分文字列であるかどうかに基づいて文字列を貪欲に割り当てます。 

これは、有効な各グループが慎重に選択された Dyck 単語に対応し、各文字列がそれを回避する Dyck 単語に割り当てられるという構造を示唆しています。 以来$k \le 50$を使用すると、すべての文字列を確実にカバーしながら、Dyck 単語の候補を列挙したり、オンデマンドで単語を構築したりできます。 グループの最小数は、すべての文字列が少なくとも 1 つの選択された単語によって回避され、どの単語がそれを回避するかによってグループ化が誘導されるように、Dyck 単語の最小セットを選択することに対応します。 

これは文字列の世界にわたるセットカバーのような構造となり、各候補の Dyck 単語が回避する文字列のセットを定義します。 なぜなら$k$が小さい場合は、DP を介して Dyck ワードを生成し、ビットマスク DP を使用して貪欲にまたは正確に最小限のカバーを選択できます。$n \le 50$。

## アルゴリズムのチュートリアル

 中心的なアイデアは、長さのすべての通常のブラケット シーケンスを列挙することです。$k$、そしてそのようなシーケンスごとに、どの入力文字列を部分文字列として回避するかを計算します。 次に、「回避されたセット」の和集合がすべての文字列をカバーするシーケンスの最小のサブセットを選択します。 

1. すべての有効な長さの通常の括弧シーケンスを生成します。$k$。 これは、現在のバランスを追跡し、それが決して負にならずゼロで終わることを保証する再帰的 DP を使用して行われます。 これにより、まさにカタルーニャ語ファミリーのサイズが生成されます。$C_{k/2}$。 
2. 生成されたシーケンスごとに、すべての入力文字列をチェックします。$s_i$そして、$s_i$部分文字列として表示されます。 表示されない場合、このシーケンスは有効な「ホスト」です。$s_i$。 
3. 各シーケンスをサイズのビットマスクで表現します。$n$、どこビット$i$の場合は 1$s_i$はそのシーケンスの部分文字列ではありません。 
4. 次に、ビットごとの OR がすべてをカバーするように、これらのマスクの最小数を選択します。$n$文字列。 小宇宙をテーマにしたクラシックなセットカバーです。 
5. 文字列のサブセットに対して DP を実行します。$dp[mask]$は、カバーされる文字列のセットを正確にカバーするために必要なシーケンスの最小数になります。 初期化する$dp[0]=0$。 
6. 各シーケンス マスクに対して、すべての状態に対して遷移を緩和します。$mask$、 アップデート$mask \cup seq\_mask$。 
7. 親ポインタを保存して、どのシーケンスが選択されたかを再構築します。 
8. DP の後、次の場合$dp[(1<<n)-1]$が無限の場合、出力は -1 です。 それ以外の場合は、選択したシーケンスを再構築し、各文字列をそれを回避するシーケンスに割り当てます。 

正確さは、各グループが単一の Dyck 単語で独立して表現できるかどうかにかかっており、グループ化の制約は文字列間の内部相互作用ではなく、回避にのみ依存します。 

これが機能する理由は、グループ化問題の圧縮から来ています。最初にグループを構築する代わりに、考えられるすべてのグループ代表 (有効な Dyck ワード) を列挙し、各代表に実行可能なグループを定義させます。 すべての有効なグループには、その実現可能性を証明する少なくとも 1 つの有効な Dyck シーケンスがあるため、最適なグループ化はこれらの代表の一部に対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

n, k = map(int, input().split())
s = [input().strip() for _ in range(n)]

# generate all regular bracket sequences of length k
res = []

def gen(cur, bal):
    if len(cur) == k:
        if bal == 0:
            res.append(cur)
        return
    if bal < 0 or bal > k - len(cur):
        return
    # add '('
    gen(cur + "(", bal + 1)
    # add ')'
    if bal > 0:
        gen(cur + ")", bal - 1)

gen("", 0)

# precompute substring checks
def contains(a, b):
    return b in a

m = len(res)

mask = [0] * m

for i in range(m):
    for j in range(n):
        if s[j] not in res[i]:
            mask[i] |= (1 << j)

INF = 10**9
dp = [INF] * (1 << n)
par = [-1] * (1 << n)
choice = [-1] * (1 << n)

dp[0] = 0

for i in range(m):
    w = mask[i]
    if w == 0:
        continue
    for st in range((1 << n) - 1, -1, -1):
        if dp[st] == INF:
            continue
        nxt = st | w
        if dp[nxt] > dp[st] + 1:
            dp[nxt] = dp[st] + 1
            par[nxt] = st
            choice[nxt] = i

full = (1 << n) - 1
if dp[full] == INF:
    print(-1)
    sys.exit()

groups = []
cur = full

while cur:
    i = choice[cur]
    prev = par[cur]
    groups.append(i)
    cur = prev

groups.reverse()

assign = [[] for _ in groups]

for idx, gi in enumerate(groups):
    for j in range(n):
        if s[j] not in res[gi]:
            assign[idx].append(j + 1)

print(len(groups))
for gi, members in zip(groups, assign):
    print(res[gi])
    print(len(members))
    print(*members)
```解決策は、長さの有効な Dyck 単語をすべて生成することから始まります。$k$。 生成では、かっこ構造の正確さを強制するバランス変数を使用します。 完成した各シーケンスは、通常のブラケット シーケンスであることが保証されます。 

Dyck 単語ごとに、どの入力文字列を回避するかを示すビットマスクを計算します。 部分文字列チェックは両方とも直接であるため、$k$そして$s_i$小さいです。 

次に、文字列のサブセットに対する DP を使用して、これらのマスクに対する最小セット カバーを解決します。 シーケンスを追加しても適用範囲が増えるだけなので、トランジションは単調です。 親ポインタを使用すると、選択したシーケンスを再構築できます。 

最後に、部分文字列条件を再チェックしてグループを再構築し、選択した適切な Dyck 単語に各文字列を割り当てます。

 ## 特殊なケース

 まれなケースは、文字列自体が非常に制限的である場合に発生します。`"(((("`と$k=4$。 その場合、ほとんどの Dyck 単語にはそれが部分文字列として含まれます。 このような単語はマスク内のその文字列にゼロ ビットを持っているだけであり、DP はカバレッジのためにそれらに依存することを回避するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、特定の文字列を回避する Dyck 単語がない場合です。 そうなると、すべてのマスクのビットが 0 に設定され、完全なカバレッジが不可能になります。 完全なマスクの DP 状態に到達することはなく、アルゴリズムは次のように出力します。`-1`、必要な不可能条件に一致します。 

最後の微妙なケースは、複数の DP パスが同じ最小グループ数を生成する場合です。 親ポインターの再構成により、有効な最小限のカバーが受け入れられるため、タイブレーク ロジックを必要とせずに一貫した選択が保証されます。
