 ## 解決策
 ## 問題の理解

 塔の高さの配列が与えられ、順序を維持しながらいくつかの要素を削除することによって形成されるサブシーケンスを考慮します。 選択したサブシーケンスについて、左から「スキャン」し、以前に確認されたすべての要素よりも厳密に大きいすべての要素を記録します。 これにより、「左から見える」高さのセットが生成されます。 右からも同じことを行い、その方向からこれまでに見えたすべてのものよりも厳密に大きい要素を記録します。 

要件は、元の配列と比較したときに、これらの可視性セットの両方を正確に保持するサブシーケンスの数をカウントすることです。 言い換えれば、配列全体の左右からどの高さが見えるかを計算する場合、誘導された可視性セットがこれら 2 つのセットと正確に一致するサブシーケンスをカウントする必要があります。 

主な問題は、プレフィックスおよびサフィックスのスキャンでどの要素が最大になるかがサブシーケンスによって変わることです。 要素を削除すると、これらの可視性セット内の他の要素が昇格または降格される可能性があるため、位置を独立して扱うことはできません。 

テスト全体の長さの合計が最大 5000 であるという制約が主信号です。 二次またはわずかに超二次の DP は許容されますが、部分列にわたる 3 次または指数関数は不可能です。 すべてのサブシーケンス (2^n) に対する強引な列挙は、直ちに除外されます。 

微妙なエッジケースは、値が繰り返される場合です。 たとえば、[1, 2, 2, 3] のような配列では、可視性を大幅に改善する必要があるため、スキャン中に同じ値が 2 回表示されることはありません。 ただし、サブシーケンスは、可視性セットを変更せずに組み合わせカウントを変更する方法で、重複を含めたり除外したりする場合があります。 もう 1 つの注意が必要な状況は、グローバル最大値が複数回出現する場合です。これは、グローバル最大値が配列全体の両側から常に表示され、すべての有効なサブシーケンスで表示されたままでなければならないためです。 

## アプローチ

 直接的なアプローチは、すべてのサブシーケンスを列挙し、それらの左側に表示されるセットと右側に表示されるセットを計算し、それらを元の配列と比較することです。 これは正しいですが、実行不可能です。 部分列の数は 2^n で、n が 5000 までの場合に評価できる数をはるかに超えています。n = 40 でさえすでに大きすぎます。 

可視性条件の構造は、重要なのは完全なサブシーケンスではなく、それが元の配列のプレフィックス最大値とサフィックス最大値とどのように相互作用するかであることを示唆しています。 左側に表示されるセットはまさにサブシーケンスのプレフィックス最大値のセットであり、右側に表示されるセットはサフィックス最大値のセットです。 これらは単調増加の最大値シーケンスです。 

重要な観察は、すべての有効なサブシーケンスが元の配列とまったく同じ「記録破りの値」を両方向に保持する必要があるということです。 これにより、元の配列のプレフィックス最大値であるすべての要素が、有効なサブシーケンス内で特定の構造的役割に引き続き表示され、サフィックス最大値についても同様になります。 

これにより、問題は、新しいレコード値が出現したり、既存のレコード値が消えたりしないようにしながら、連続するレコード最大値の間に「ブロック」をインターリーブする方法を数えることに減ります。 シーケンスが左から右および右から左の最大構造を中心に圧縮されると、残りの自由は、可視性イベントを変更せずに、どの非クリティカルな要素をオプションで含めることができるかを選択することです。 これは位置に対する組み合わせの DP となり、各要素は無視しても安全かどうか、または可視性の境界を保持することが構造的に必須であるかどうかに基づいて分類されます。

最後の変換は、プレフィックスとサフィックスの両方の制約を同時に考慮して有効なサブシーケンスを構築できる方法を維持しながら、配列をスイープする動的プログラミングの定式化につながります。 遷移は、現在の要素が必須の境界要素であるか、境界間のオプションのフィラーであるかによって異なります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 可視性構造上の DP | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の配列内のプレフィックス最大値のセットを計算します。 これらはまさに、左からスキャンし、厳密に増加する記録的最高値を取得したときに現れる要素です。 構造は発生場所によって異なるため、その位置も保存します。 
2. 右からスキャンして、同じ方法でサフィックス最大値のセットを計算します。 これらは適切な可視性構造を定義します。 
3. 各インデックスを、left-critical (新しいプレフィックスの最大値として表示)、right-critical (新しいサフィックスの最大値として表示)、またはその両方の 3 つのロールのいずれかに属するものとしてマークします。 通常、グローバル最大値は両方です。 
4. 有効なサブシーケンスには、相対的な順序を維持する方法で、左クリティカルと右クリティカルの両方の値がすべて含まれている必要があることに注意してください。 これらは、配列を独立したセグメントに分割するアンカーとして機能します。 
5. 配列を連続するアンカーポイント間のセグメントに分解します。 元の L セットと R セットを保持したい場合、各セグメント内では要素は新しい可視性イベントを作成できないため、オプションのフィラーとして動作します。 
6. 各セグメントについて、両側の最も近いアンカーによって課される実行最大制約に影響を与えることなく、その要素のサブセットを選択できる方法が何通りあるかを計算します。 これは、要素が現在の左右のしきい値を下回っているかどうかに基づいたローカルの組み合わせカウントになります。 
7. アンカー間の順序付けの制約に注意しながら、すべてのセグメントからの寄与を乗算します。 結果は 998244353 を法として累積されます。 

### なぜ効果があるのか

 可視性セットは、両方向からの記録破りの最大値のシーケンスによって完全に決定されます。 これらの最大値は厳格なバックボーンを形成します。新しい最大値を導入したり、既存の最大値を削除したりする変更は、L または R のいずれかを即座に変更します。これらのバックボーン要素が修正されると、他のすべてはこれらのレコードに干渉しないことによってのみ制約されます。 セグメントへの分解は、セグメント内の要素が単調性制約に違反することなくそのセグメントの外側のレコード構造に影響を与えることができないため、機能します。 これにより、セグメントの独立性が保証され、ローカルカウントの積が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # prefix maxima positions
        pref_max = []
        cur = -10**30
        for i, x in enumerate(a):
            if x > cur:
                cur = x
                pref_max.append(i)

        # suffix maxima positions
        suf_max = []
        cur = -10**30
        for i in range(n - 1, -1, -1):
            if a[i] > cur:
                cur = a[i]
                suf_max.append(i)
        suf_max.reverse()

        # mark anchors
        is_anchor = [False] * n
        for i in pref_max:
            is_anchor[i] = True
        for i in suf_max:
            is_anchor[i] = True

        anchors = [i for i in range(n) if is_anchor[i]]

        # if only one anchor, everything must be preserved
        if len(anchors) == 1:
            print(1)
            continue

        ans = 1

        # process segments between anchors
        for k in range(len(anchors) - 1):
            l = anchors[k]
            r = anchors[k + 1]

            # we must include endpoints l and r; everything in between is optional
            # but must not create new visible maxima
            base = 1
            for i in range(l + 1, r):
                base = (base * 2) % MOD
            ans = (ans * base) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、最初にプレフィックスとサフィックスの最大インデックスが抽出されます。これは、可視性構造を維持するサブシーケンスに出現する必要があるすべてのポイントを表します。 次に、これらを固定アンカーとして扱います。 連続するアンカー間では、境界の最大値に影響を与えることなく、すべての要素を含めることも除外することもできるため、それぞれの要素は 2 の係数に寄与します。セグメント間の乗算は、異なる領域での選択の独立性を反映します。 

微妙な点は、エンドポイント自体はオプションではないということです。 可視性セットを削除すると左または右のレコード構造が変更されるため、これらは可視性セットを保持するために必要です。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [4, 2, 4, 8, 3]
```接頭辞の最大値はインデックス 0、3 にあります。接尾辞の最大値はインデックス 3、4 にあります。アンカーは [0、3、4] になります。 

| ステップ | アンカー | セグメント (l, r) | セグメント内のオプション | 実行中の答え |
 | --- | --- | --- | --- | --- |
 | 1 | [0、3、4] | (0, 3) | 要素 [2, 4] → 2^2 = 4 | 4 |
 | 2 | [0、3、4] | (3,4) | 空 → 1 | 4 |

 最終的な答えは 4 です。 

これは、可視性構造を維持するためにアンカーが固定されたままである一方で、各非アンカー領域がどのように独立して寄与するかを示しています。 

### 例 2

 入力:```
n = 1
a = [10]
```プレフィックスとサフィックスの両方が最大である要素は 1 つだけです。 

| ステップ | アンカー | セグメント | 実行中の答え |
 | --- | --- | --- | --- |
 | 1 | [0] | なし | 1 |

 唯一のサブシーケンスは配列自体です。 削除すると可視性セットが破壊され、最小限のケースでは拘束の剛性が確認されます。

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pref = []
        cur = -10**9
        for x in a:
            if x > cur:
                cur = x
                pref.append(x)

        suf = []
        cur = -10**9
        for x in reversed(a):
            if x > cur:
                cur = x
                suf.append(x)
        suf.reverse()

        anchors = set(pref) | set(suf)

        if len(anchors) == 1:
            out.append("1")
            continue

        # simplified model used in editorial code
        ans = 1
        i = 0
        while i < n:
            if a[i] in anchors:
                j = i + 1
                while j < n and a[j] not in anchors:
                    j += 1
                ans = ans * pow(2, j - i - 1, MOD) % MOD
                i = j
            else:
                i += 1

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 [x] のような単一要素の配列の場合、L と R の両方にその要素のみが含まれます。 唯一の要素を削除すると両方の可視性セットが変更されるため、アルゴリズムは 1 つのアンカーを識別し、すぐに 1 を返します。 

厳密に増加する配列の場合、すべての要素はプレフィックスの最大値であり、ミラーリングされた方法でサフィックスの最大値構造にも寄与します。 これによりセグメントが折りたたまれ、オプションの要素が存在しなくなり、有効なサブシーケンスが 1 つだけ、つまり完全な配列になります。 

厳密に減少する配列の場合、接尾辞の最大値が優先されますが、接頭辞の最大値は最初の要素に折りたたまれます。 アンカーが十分に密になるため、再び内部の柔軟性がなくなり、出力は 1 になります。 

[1, 3, 2, 4] などの混合配列の場合、アンカーは配列を複数のセグメントに分割します。 中間の各セグメントは独立した選択肢に寄与しており、プロダクト構造は、新たな記録的最高値を導入することなく可視性セットを維持するすべての有効なサブシーケンスを正確に考慮しています。
