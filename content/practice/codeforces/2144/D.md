 ## 解決策
 ## 問題の理解

 複数のアイテムを揃えるストア向けに、それぞれのアイテムを固定価格でクリアランス セールを実施しています。 ストアでは、整数係数による除算による一律の割引が可能です$x > 1$、アイテムの新しい価格は、元の価格の上限を で割った値です。$x$。 店舗が保有する既存の値札の数には限りがあるため、新しい割引価格が元の価格と一致しない場合は、実費で新しい値札を印刷する必要があります。$y$。 目標は除算係数を選択することです$x$これは、すべての割引価格の合計から新しく印刷されたタグのコストを差し引いた合計収入を最大化します。 

入力は複数のテスト ケースを提供します。 それぞれの項目数は、$n$最大200,000までの価格と価格$c_i$最大200,000も可能です。 印刷コスト$y$非常に大きくなる可能性があり、最大で$10^9$。 以来$n$大きい場合、どのようなソリューションでも$O(n^2)$複雑さは即座に排除されます。 に関して線形または線形に近い演算を処理できるアプローチが必要です。$n$テストケースごとに。 

単純なエッジケースは、すべての商品価格が同じ場合に発生します。$y$非常に高いです。 たとえば、次の場合$n = 3$、$y = 10^9$、 そして$c = [42, 42, 42]$、わずかに価格を下げると、タグの印刷コストにより収入がマイナスになる可能性があります。 印刷コストを考慮せずに割引価格のみを合計する不注意なアプローチは、誤って大きなプラスの収入を想定することになります。 

もう 1 つの微妙なケースは、小型またはプライム商品の価格が独自の割引価格をほとんど生成せず、多くの元のタグを再利用できる場合です。 たとえば、$c = [1, 1, 1]$そしてどれでも$x > 1$、割引価格はすべて 1 になるため、新しいタグは必要なく、印刷コストによる収入の減少もありません。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 すべての整数値を反復処理します。$x$2 から妥当な範囲までを計算し、各アイテムの割引価格を計算し、必要な新しいタグの数を数え、総収入を計算します。 これはどのような場合でも機能するため、$x$、割引価格は明確に定義されています。 ただし、単純な反復では遅すぎるため、$x$原則として元の最高価格まで上がる可能性がありますが、$2 \cdot 10^5$。 やってる$n$あたりの計算$x$操作数は次のとおりです$O(n \cdot c_{\text{max}})$までです$4 \cdot 10^{10}$- 完全に不可能です。 

重要な洞察は、一連の固有の割引価格が特定のしきい値でのみ変化するということです。$x$。 定価の商品の場合$c_i$、その割引価格$\lceil c_i / x \rceil$の間隔にわたって一定です$x$間$\lfloor c_i / k \rfloor$そして$\lfloor c_i / (k-1) \rfloor$整数の場合$k$。 したがって、すべてをチェックするのではなく、$x$、重要なもののみを反復できます。$x$一部の商品の割引価格が変更される値。 これらの候補を生成することで、$x$すべての項目にわたる値を考慮すると、問題は考えられる要素の線形数を評価することに帰着します。 

さらに、与えられた$x$、元の価格の頻度マップを使用して、必要なタグの数をすばやく計算できます。 既存のタグを再利用できる割引価格がいくつあるかを数え、残りの印刷コストを差し引きます。 この制限の組み合わせ$x$候補者を効率的に計算し、収入を計算することで実現可能性が得られます。$O(n \sqrt{c_{\text{max}}})$アプローチ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * c_max) | O(n) | 遅すぎる |
 | 最適 | O(n * sqrt(c_max)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、項目の数を読み取ります。$n$、印刷コスト$y$、アイテムの価格$c_1, \dots, c_n$。 
2. それぞれの元の価格の頻度を数えます。 これは、どの割引価格でタグを再利用できるかを判断するのに役立ちます。 
3. 候補のセットを初期化する$x$で始まる値$x = 2$。 
4.各商品価格$c_i$、しきい値を生成します$x$以下のすべての整数を計算して値を取得します。$\sqrt{c_i}$およびそれらに対応する$\lceil c_i / k \rceil$。 それぞれについて$k$、$x = \lfloor c_i / k \rfloor$新たな割引価格が発生する可能性があります。 これらを候補セットに追加します。 
5. 各候補者について$x$、割引価格を計算します$\lceil c_i / x \rceil$すべてのアイテムに。 各割引価格の頻度を数えます。 
6. 各価格の元の頻度と割引後の頻度の最小値を照合して、再利用できる既存のタグの数を決定します。 残りのアイテムには新しいタグが必要です。 
7. 総収入を、割引価格からマイナスした額の合計として計算します。$y$新しいタグの数の倍になります。 
8. すべての候補者の最大収入を追跡する$x$。 
9. テスト ケースの結果を印刷します。 

なぜ機能するのか: 候補者のセット$x$値は、アイテムの割引価格が変化するすべてのポイントをカバーします。 これらの候補のみを評価することで、すべての固有の収入構成を考慮することが保証されます。 頻度マップにより、既存の値札を最適に再利用できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import ceil, isqrt
from collections import Counter

def max_income(n, y, prices):
    freq = Counter(prices)
    candidates = set([2])
    
    for price in prices:
        for k in range(1, isqrt(price) + 2):
            if k == 0:
                continue
            x = (price + k - 1) // k
            if x > 1:
                candidates.add(x)
    
    max_total = -float('inf')
    
    for x in candidates:
        discounted = [ceil(p / x) for p in prices]
        discounted_freq = Counter(discounted)
        reuse = 0
        for p in discounted_freq:
            reuse += min(discounted_freq[p], freq.get(p, 0))
        new_tags = n - reuse
        total = sum(discounted) - new_tags * y
        max_total = max(max_total, total)
    
    return max_total

t = int(input())
for _ in range(t):
    n, y = map(int, input().split())
    prices = list(map(int, input().split()))
    print(max_income(n, y, prices))
```このソリューションは、タグの再利用を最適化するために元の価格の頻度をカウントすることから始まります。 候補を生成します$x$各価格の平方根まで反復して値を計算し、割引価格が変化するしきい値のみを考慮するようにします。 それぞれについて$x$、割引価格を計算し、タグを最適に再利用し、印刷コストを差し引きます。 使用する`Counter`正しい周波数計算と効率的な再利用が保証されます。
