 ## 解決策

 ## 問題の理解

 Koa は、位置 0 (海岸) から位置 n+1 (島) まで、海のセルのラインを横切って移動する必要があります。 各中間位置 i には固定の底面深さ d[i] がありますが、水位は静的ではありません。 代わりに、潮汐は 2k 秒ごとに循環する時間依存のオフセットを追加します。オフセットは 0 から k まで直線的に増加し、その後 1 に戻ります。 

任意の整数秒 t において、Koa が位置 x に立っている場合、その位置での実効深度は d[x] に時刻 t での潮汐値を加えたものになります。 Koa はその場に留まるか、1 秒ごとに右に 1 歩移動することができ、時間は常に進みます。 実効深さが閾値 l を超えない場合にのみ、船は海上セル上に安全に立つことができます。 独房間を移動する間、彼女は安全であるため、到着時間だけが重要です。 

課題は、彼女が島に到達できる一連の待機と移動が存在するかどうかを判断することです。 

制約は小さく、n、k は最大 100、最大でも 100 のテスト ケースであるため、O(n^3) または O(n^2 k) のアプローチが受け入れられます。 ただし、位置と時間の相互作用により、潮流は位置ではなく時間のみに依存するため、貪欲な推論は危険になります。そのため、同じセルがある瞬間には安全でも、すぐに安全でなくなる可能性があります。 

一般的な微妙な障害のケースは、セルがたまにしか安全でない場合に発生します。 たとえば、潮が下降している段階でのみ位置が安全になる場合、セルが安全になるとすぐに移動する単純な戦略は失敗します。到着時間が安全な段階と一致しない可能性があるためです。 

もう 1 つの注意が必要なケースは、将来の安全なウィンドウと同期するために、以前のセルに長時間滞在する必要がある場合です。 貪欲な「できるだけ早く移動」戦略は、時間調整の制約を無視するため破綻します。 

## アプローチ

 ブルートフォース手法では、問題をペア (位置、時間 mod 2k) の状態グラフとしてモデル化します。 各状態から、次回目的のセルが安全であれば、Koa は留まるか、前進することができます。 これはすべての有効なスケジュールを調査するため正確性を保証しますが、状態空間は n × 2k で、各状態には最大 2 つの遷移があるため、最悪の場合、テストごとに約 40,000 の状態になります。 ここではこれは許容されますが、構造を観察する場合はまだ不要です。 

重要な洞察は、任意の時間発展を考慮する必要がないということです。 各位置での到達可能な最も早い時間のみが重要です。 ある時刻 t に位置 x に到着する場合、潮の位相を前方にシフトするだけであり、実現可能性が低下する可能性があるため、到着時刻が遅れると厳密には悪くなります。 したがって、各位置に到達できる最小時間を追跡します。 

位置 i に到達できる最も早い時刻を計算したら、有効な時刻に i+1 に移動できるようになるまで、i で待機することを貪欲にシミュレートできます。 潮の周期的な性質により、O(k) の各出発時間の実現可能性をテストできるため、全体として効率的に移行できます。 

問題は、複数のポジションを反復し、それぞれのポジションで次のポジションに安全に出発できる最も早い時間を見つけることになります。

 | --- | --- | --- | --- |
 | 状態 BFS オーバー (位置、時間 mod 2k) | O(nk) | O(nk) | 承認済み |
 | ポジションごとの最も早い時間の貪欲 | O(nk) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 与えられた位置 i および時間 t で Koa が安全かどうかをチェックする関数を定義します: d[i] + p[t mod 2k] ≤ l。 

配列 best[i] を維持します。これは、位置 i に安全に到着できる最も早い時間を意味します。 Koa は時刻 0 に海岸からスタートするため、最初は best[0] = 0 になります。 

位置ごとに進み、best[i] から best[i+1] を計算しようとします。

1. Koa は制約なしで時刻 0 に海岸で開始されるため、best[0] = 0 から開始します。 
2. 0 から n までの各位置 i について、i+1 での最も早い有効な到着時刻の計算を試みます。 
3. 位置 i への候補到​​着時刻 t について、Koa が i から出発する可能性があるすべての可能な時刻 t' ≥ t を考慮します。 時間 t' では、Koa は i+1 に移動できるため、位置 i が t' で安全であり、位置 i+1 が t'+1 で安全であることを確認する必要があります。 
4. 最も早い実行可能な t' を見つけるために、best[i] から開始して時間を前方にスキャンします。 時間ステップごとに、次のことを確認します。 

d[i] + p[t mod 2k] ≤ l が成り立つかどうか。 

これは、Koa が待機中も生きていなければならないため、必要です。 
5. 位置 i が t' で安全であるような時刻 t' を見つけると、彼女が i+1 に移動できるかどうかをテストします。これは次のことを意味します。 

d[i+1] + p[(t'+1) mod 2k] ≤ l。 
6. 両方の条件が成立する場合、best[i+1] = t'+1 を設定し、次の位置に進みます。 
7. 妥当な制限範囲内にそのような t' が存在しない場合 (パターンは 2k ごとに繰り返されるため、最大 2k フェーズが必要です)、移動は不可能であると結論付けます。 

### なぜ効果があるのか

 重要な不変条件は、各位置 i について、best[i] が Koa が安全にそこに立つことができる最小時間であるということです。 潮汐状態は時間的に純粋に周期的であるため、到着時間が遅れると、それより悪くなるか同等になるだけであり、遅延によって以前の時間では 1 サイクル内にまだ現れなかった新たな有利な局面が導入されることはありません。 したがって、長さ 2k の 1 つの完全なサイクル内の最も早い到着時刻から前方のみをチェックするだけで、次の位置の到達可能性を判断するのに十分です。 

これにより、無限時間のプロセスが、エッジごとの制限された循環実行可能性チェックに短縮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, l = map(int, input().split())
        d = [0] + list(map(int, input().split()))
        
        # precompute tide pattern
        p = list(range(k)) + list(range(k - 2, 0, -1)) if k > 1 else [0, 1]
        if k == 1:
            p = [0, 1]
        period = len(p)
        
        INF = 10**18
        best = [INF] * (n + 2)
        best[0] = 0
        
        def safe(i, t):
            return d[i] + p[t % period] <= l
        
        ok = True
        
        for i in range(n + 1):
            if best[i] == INF:
                ok = False
                break
            
            tcur = best[i]
            found = False
            
            # search within one cycle window
            for dt in range(period * 2):
                t = tcur + dt
                if not safe(i, t):
                    continue
                if i + 1 <= n:
                    if d[i + 1] + p[(t + 1) % period] <= l:
                        best[i + 1] = min(best[i + 1], t + 1)
                        found = True
                        break
                else:
                    best[i + 1] = t + 1
                    found = True
                    break
            
            if not found and i != n + 1:
                ok = False
                break
        
        print("Yes" if best[n + 1] != INF else "No")

if __name__ == "__main__":
    solve()
```この実装では潮汐サイクルを明示的に構築し、最も早い到着時刻を位置ごとに前方に伝播します。 内側のループは、現在の最良の到着から始まる制限された時間枠をチェックし、潮相の少なくとも 1 回の完全な繰り返しを確実にキャッチします。 の`safe`関数は、固定時刻における制約チェックをカプセル化します。 

微妙な点は、位置 i については時刻 t に、位置 i+1 については時刻 t+1 に常に安全性をチェックすることです。 これは、Koa は整数時間では安全でなければならず、秒間の遷移のみが重要であるというルールと一致します。

 ## 特殊なケース

 A key edge case is when a cell is only occasionally safe. このアルゴリズムは、潮汐サイクル全体にわたって順方向にスキャンすることでこれを処理し、最初の安全な瞬間を逃した場合でも、次の繰り返しが確実に見つかるようにします。 This prevents premature rejection.

 Another case is when Koa must wait at an earlier position to align future phases. best[i] は最も早い到着時間であるため、アルゴリズムは当然、即時の移動を強制するのではなく、スキャンの一部として待機を考慮します。 

A final edge case is when k = 1, where the tide alternates every second. p の構築では、正しい最小サイクル [0, 1] を生成することでこれを明示的に処理し、最小の周期設定でも位相の正確性を保証します。
