 ## 問題の理解

 英小文字のみで構成される文字列が与えられます。 2 つの文字を選択する操作を実行できます`x`そして`y`、次に、出現するすべての文字列を置き換えます。`x`文字列全体で`y`1回の世界的なスイープで。 この操作は何度でも繰り返すことができます。 

目標は、すべての文字が文字になるように文字列全体を変換することです。`'i'`必要な操作の数を最小限に抑えたいと考えています。 

重要な点は、各操作はローカルではなく、選択した文字のすべての出現に同時に影響するということです。 このため、文字が他の文字にどのように徐々に「マージ」され、最終的にすべてが崩壊するかという問題が生じます。`'i'`。 

制約`|s| ≤ 10^4`つまり、操作ごとにキャラクターごとに何かをシミュレートすることは期待されていません。 多くのステップで文字列全体の変換を繰り返しスキャンまたはシミュレートするソリューションは、操作の数が非常に少なく、アルファベット サイズによって制限される場合にのみ合格します。 使用可能な文字は 26 個だけであるため、文字列の長さではなく文字の種類に依存する解決策が期待されるはずです。 

微妙な点は、直接使用することを強制されていないことです。`'i'`操作中の中間シンボルとして。 たとえ`'i'`は最初は文字列に存在しませんが、任意の文字をマッピングすることができます。`'i'`。 

切り分ける価値のあるエッジケースは、小さなアルファベットから来ています。 

文字列が`"i"`、答えは`0`何も変更する必要がないからです。 

文字列が`"abc"`、最適な動作は、それぞれをマップすることです。`a`、`b`、 そして`c`の中へ`'i'`、3つの操作を与えます。 不用意な考えは、最初にすべてを 1 つの文字にマッピングしてから、次の文字にマッピングしようとする可能性があります。`'i'`, しかし、それではカウントが改善されることはありません。 

文字列が`"aii"`、 のみ`a`変更する必要があるので、答えは`1`。 

これらの例は、コストが異なる文字の数にのみ依存することを示しています。`'i'`。 

## アプローチ

 ブルートフォース解釈では、毎回完全な文字列を維持しながら、段階的に操作を適用することを考えます。 各ステップですべてのペアを試すことができます`(x, y)`交換をシミュレートします`x`と`y`次に、すべての文字が一致する状態に到達するまでの最小ステップ数を再帰または検索します。`'i'`。 これは、すべての可能な文字列にわたる最短パスの問題であり、各状態遷移は 1 つのグローバル置換です。 

国家空間は天文学的に大きい。 各文字列の長さは最大ですが、`10^4`、可能な個別の文字列の数は次のとおりです。`26^n`構造を無視して文字の分割だけを考えたとしても、遷移は依然として指数関数的な状態にわたるグラフを形成します。 これにより、ブルートフォースは即座に不可能になります。 

重要な観察点は、この操作は文字の ID にのみ影響し、位置には影響しないということです。 同じ文字を含むすべての位置は、永久に同じように動作します。 したがって、状態は文字列内に現在どの文字が存在するかによって完全に記述されます。 

この観点から、各操作は 1 つの文字記号を削除します`x`それを次のように置き換えます`y`。 これは、次の場合を除き、個別の文字の数を厳密に減らします。`x`そして`y`はすでに同じです。 私たちはすべてがそうなることを望んでいるから、`'i'`、重要な文字は、元の文字列内の異なる文字だけです。`'i'`。 このような各文字は、少なくとも 1 回は「削除」する必要があります。なぜなら、その文字を別のシンボルにマッピングする以外にその文字を消すことはできず、最終的にはすべてが崩壊する必要があるからです。`'i'`。 

非依存性を直接マッピングすることで、これを常に最適に行うことができます。`'i'`への手紙`'i'`一度。 次のような間接的なチェーン`a -> b -> i`操作数は減らないので、`a -> b`そうでない限り、個別の文字の数を減らすのには役立ちません。`b`すでに`'i'`。 

So the answer becomes purely combinational: count how many distinct letters appear in the string, and subtract one if`'i'`その中にはある。

 ## アルゴリズムのチュートリアル

 問題を、文字列内にどの文字が存在するかを追跡することに集約します。 

1. 文字列を 1 回スキャンし、出現する文字を記録します。 

一連の個別の文字のみが操作の数に影響を与えるため、これは重要です。 立場は関係ありません。 
2. 異なる文字が合計で何個存在するかを数えます。 
3. かどうかを確認します。`'i'`この文字の中にあります。 
4. もし`'i'`が存在する場合、答えは`distinct_count - 1`、 以来`'i'`削除したり変形したりする必要はありません。 
5. もし`'i'`は存在しません、答えは`distinct_count`、すべての文字は直接次のように変換する必要があるため、`'i'`。 

ステップ 4 と 5 の決定には、次のことが反映されます。`'i'`文字列の最初のアルファベットの一部であるか、変換によって導入する必要があります。 

### なぜ効果があるのか

 各操作で正確に 1 つのソース文字が削除されます`x`それをターゲット文字にマージすることによって`y`。 このプロセスは、`'i'`残っています。 どの操作でもシステムから複数の異なる文字を削除することはできません。`x`操作ごとに選択されます。 したがって、異なるすべての文字は、`'i'`少なくとも 1 つの操作が必要です。 このような各文字を次のように直接変換すると、`'i'`はこの下限を達成し、最適化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    present = [False] * 26
    for ch in s:
        present[ord(ch) - ord('a')] = True

    distinct_count = sum(present)
    i_idx = ord('i') - ord('a')

    if present[i_idx]:
        print(distinct_count - 1)
    else:
        print(distinct_count)

if __name__ == "__main__":
    solve()
```この実装では文字の存在のみが追跡され、置換のシミュレーションは回避されます。 重要な点は、確実に治療できるようにすることです`'i'`特にそれが存在する場合は、変換して取り除く必要がないためです。
