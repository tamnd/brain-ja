 ## 解決策
 ## 問題の理解

 IPv4 アドレスは 32 ビットの整数として認識され、通常はドットで区切られた 4 つの 10 進数として記述されます。 次のような CIDR ブロック`192.168.88.0/24`はアドレスのセットを説明します。最初の 24 ビットはネットワーク プレフィックスとして固定されていますが、残りの 8 ビットは自由に変更できます。 すべてのクエリでは、指定された IPv4 アドレスがこの固定プレフィックス範囲に属するかどうかが尋ねられます。 

したがって、このタスクは、バイナリ プレフィックス制約によって定義されたセット内のメンバーシップ テストに帰着します。 このようなプレフィックスの説明が 1 つと、最大 1000 個の候補 IP アドレスが与えられます。 各候補について、最初の k ビットがプレフィックスと一致するかどうかを判断する必要があります。k はスラッシュの後に与えられます。 

制約は十分小さいため、クエリごとに直接ビット単位または整数ベースのチェックを行うだけでも十分です。 各 IP を 32 ビット整数に変換し、マスクされたプレフィックスを比較するのは一定時間の作業であるため、すべてのクエリに対する線形スキャンであっても、パフォーマンスの観点からは取るに足らないものです。 

難しい部分は計算的なものではなく、表現的なものです。 よくある落とし穴の 1 つは、完全な 32 ビット構造を正しく再構築せずに、各オクテットを個別に処理することです。 もう 1 つは、CIDR マスクの適用方法の誤解です。比較は IP の完全な同等性に対してではなく、マスク後のプレフィックス部分のみの同等性に対して行われます。 

プレフィックス長が 0 または 32 の場合、微妙なエッジ ケースが発生します。`/0`ネットワークにはすべての IP アドレスが含まれていますが、`/32`ネットワークにはアドレスが 1 つだけ含まれます。 単純な文字列比較は、ビット マスキングを通じて明示的に処理されない限り、ここでは失敗します。 

別の問題は、先頭のゼロやドット付き 10 進数の一貫性のない解析によって発生します。 例えば、`010.0.0.1`依然として 10.0.0.1 として解釈されるはずですが、単純な文字列ベースの比較では異なる方法で処理されます。 

## アプローチ

 ブルート フォース メンタル モデルでは、CIDR ブロックをその範囲内のすべての可能な IP を生成すると解釈し、この生成されたセットに対して各クエリ IP をチェックします。 プレフィックスが`/k`をすべて列挙します。`2^(32-k)`可能なサフィックスを抽出し、完全な IP を構築し、それらをハッシュ セットに保存します。 各クエリはメンバーシップ テストになります。 

これは、サブネットの定義を明示的に構築するため、正しいです。 ただし、効率上の理由から、すぐに失敗します。 みたいなささやかな場合でも、`/24`、可能なアドレスは 1,600 万以上あり、`/16`40億以上あります。 これを構築または保存することは、時間的にもメモリ的にも不可能です。 

重要な観察は、サブネットのメンバーシップが基本的にビットごとの条件であるということです。 すべてのサフィックスを列挙する代わりに、サブネットと各 IP の両方を 32 ビット整数として表し、プレフィックス ビットのみを保持するマスクを適用できます。 2 つのアドレスは、マスクされた値が一致する場合にのみ、同じサブネットに属します。 これにより、列挙が完全に削除され、各クエリが定数時間のビット演算に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (列挙) | O(2^(32-k) + n) | O(2^(32-k)) | 遅すぎる |
 | 最適 (ビット マスキング) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. CIDR 入力をベース IP とプレフィックス長 k の 2 つの部分に解析します。 ベース IP はネットワーク アンカー ポイントを定義します。 
2. ベース IP をドット付き 10 進数から 32 ビット整数に変換します。 各オクテットは 8 ビットをその位置にシフトして提供します。 
3. 上位 k ビットが 1、残りの 32 k ビットが 0 である 32 ビット マスクを構築します。これにより、ネットワーク プレフィックスが分離されます。 
4. マスクをベース IP に適用して、正規のネットワーク代表を取得します。 これにより、入力に存在する可能性のあるホスト ビットのあいまいさがなくなります。 
5. 各クエリ IP について、同じ解析方法を使用して 32 ビット整数に変換します。 
6. 同じマスクをクエリ IP に適用します。 
7. マスクされたクエリ値をマスクされたベース値と比較します。 それらが一致する場合、その IP はサブネットに属します。 それ以外の場合はそうではありません。 
8. それに応じて YES または NO を出力します。 

### なぜ効果があるのか

 マスキングはプレフィックス ビットのみに等価性を適用します。これはまさに CIDR の定義です。 同じサブネット内の 2 つの IP は同一の上位 k ビットを共有し、マスキングにより残りのビットのすべての変動が除去されます。 マスクはサブネット ベースとクエリ IP の両方で同一であるため、マスキング後の同等性は、同じプレフィックス定義の同等性クラスに属することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ip_to_int(s: str) -> int:
    a, b, c, d = map(int, s.strip().split('.'))
    return (a << 24) | (b << 16) | (c << 8) | d

def build_mask(k: int) -> int:
    if k == 0:
        return 0
    return ((1 << k) - 1) << (32 - k)

def solve():
    line = input().strip()
    ip_part, k_part = line.split('/')
    k = int(k_part)

    base = ip_to_int(ip_part)
    mask = build_mask(k)

    base_net = base & mask

    n = int(input())
    out = []

    for _ in range(n):
        ip = ip_to_int(input().strip())
        if (ip & mask) == base_net:
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核は、ドット付き 10 進数を 32 ビット整数に変換することです。 各オクテットは正しい位置にシフトされ、メモリ内に表示されるのとまったく同じバイナリ表現が再構築されます。 

マスクの構造は注目に値する。 k が 0 の場合、サブネットにはすべての IP が含まれるため、マスクは 0 となり、マスク後のすべての IP は 0 にマップされます。 k が 32 の場合、マスクはすべて 1 になり、厳密に等しくなります。 

他のすべては、ビットごとの AND の後の整数比較に帰着します。これは、CIDR セマンティクスの直接の計算変換です。

 ## 特殊なケース

 あ`/0`サブネットは最も許容度の高いケースです。 マスクはゼロになるため、マスクと AND 演算されたすべての IP はゼロになり、ベース ネットワーク値と一致します。 このアルゴリズムは、マスク構築を超えた特別なケースを使用せずに、すべてのクエリに対して当然に YES を返します。 

あ`/32`サブネットは最も厳密なケースです。 マスクはすべて 1 になるため、無視されるビットはありません。 比較により、クエリ IP とベース IP の間の完全な整数の等価性が求められ、定義と正確に一致します。 

のような例`0.0.0.0/0`などのクエリで`8.8.8.8`は同一のマスクされた値 0 を生成するため、正しく YES を返します。 逆に、`192.168.1.1/32`いずれかのビットの違いによってマスクされた値が変更されるため、それ自体とのみ一致します。
