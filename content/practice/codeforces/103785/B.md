 ## 解決策
 ## 問題の理解

 同じレンガがいくつか与えられたので、それらを使って階段を作りたいと思います。 各階段の高さは正の整数であり、階段は 1 つのステップから次のステップへと厳密に増加する必要があります。 目標は、構築できる個別のステップの数を最大化しながら、利用可能なレンガを最大限に使用することです。 

重要な出力は、階段の正確な構成ではなく、段の高さを増やす必要があり、使用されるレンガの総数が指定された制限を超えてはいけないという制約の下で可能な最大段数のみです。 

制約構造は重要です。$n$レンガの場合、単純な構造では任意の増加シーケンスを試行する可能性がありますが、ステップ数を最大化したい場合は、高さを厳密に増加させる必要があるため、直ちに最小コストの構造が強制されます。 

最初の微妙な点は、最適な構築には「隠れた選択肢」がないということです。 建設することに決めたら$k$階段ができるだけ狭い場合、レンガの合計数が最小になります。$1, 2, 3, \ldots, k$。 これから逸脱すると、総コストが増加し、実現可能性が低下します。 

考慮する価値のあるエッジ ケースには、非常に小さな入力や三角数の正確な境界一致が含まれます。 たとえば、次の場合$n = 1$、答えは明らかに 1 です。$n = 3$、構築できます$1 + 2 = 3$2 つのステップを与えますが、$n = 2$, 2 つのステップには 3 つのレンガが必要になるため、1 つのステップしか構築できません。 

素朴な間違いは、増加シーケンスが同じように効率的であると仮定したり、最小構造が強制されていることを認識せずに任意の貪欲な増加を試みたりすることです。 

## アプローチ

 この強引なアイデアは簡単です。使用されたレンガの数を追跡しながら、階段を 1 つずつ建設するシミュレーションを行い、次の階段の高さを常に少なくとも 1 つずつ増やします。 各ステップで次の階段を追加し、それを超えると停止します。$n$。 これは、常に、指定された段数に対して可能な最小限の階段を構築するため、正しいです。 

しかし、これは非効率性を直接的に明らかにします。 最悪の場合、$n$大きいので、最大で反復することができます$k \approx \sqrt{2n}$各ステップは一定の作業であるため、一般的な制約に対してはすでに十分に効率的です。 しかし概念的には、この野蛮なプロセスは主要な構造、つまり最初の要素の合計を隠します。$k$整数。 

観察によると、最適な階段は常に可能な限り最小の増加シーケンスを使用する必要があり、問題は最大の階段を見つけることに帰着します。$k$次のような:$$1 + 2 + 3 + \cdots + k \le n$$これは三角和です。$$\frac{k(k+1)}{2} \le n$$したがって、問題は単純な不等式を解くことになります。 これは、二次公式を使用して数学的に行うことも、制限を超えるまで値を累積することによって反復的に行うこともできます。 反復アプローチはより単純で、浮動小数点精度の問題を回避します。

 ## アルゴリズムのチュートリアル

 1. 可能な限り最小の階段の高さ 1 から始めます。これにより、固定数の階段に対するレンガの総使用量が最小限に抑えられます。 
2. 現在の階段の高さ、これまでに使用されたレンガの総数、建設された階段の数という 3 つの変数を維持します。 
3. 毎回高さを 1 ずつ増やして、次の階段を追加してみます。 これが強制されるのは、これより小さい増加は厳密な順序に違反するためです。 
4. 階段を追加する前に、必要な数のレンガを追加すると制限を超えるかどうかを確認してください。$n$。 そうなった場合は、すぐに中止してください。 
5. それ以外の場合は、階段を含め、使用したレンガの合計を更新し、階段の数を増やして続行します。 
6. 利用可能なレンガを超えずに階段を追加できなくなるまで繰り返します。 

これが機能する理由: この構造は常に、辞書編集上最小の、指定された長さの正の整数の厳密に増加するシーケンスを構築します。 任意の固定数の階段に対して$k$、このシーケンスにより総コストが最小限に抑えられます。 コストは単調増加するため、$k$、の最初の値$k$制約に違反するものは、まさに最大の有効な解が終了する場所です。 これは、貪欲な増分構築が最適化のために必要かつ十分であることを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

cnt = 0
add = 1
total = 0

while total + add <= n:
    total += add
    add += 1
    cnt += 1

print(cnt)
```このソリューションでは、構築プロセスを反映する 3 つの変数が維持されます。 変数`add`次の階段の高さを表します。1 から始まり、反復ごとに 1 ずつ増加します。 変数`total`これまでに使用されたレンガの数を追跡し、予算を決して超過しないようにします`n`。 変数`cnt`正常に建設された階段の数をカウントします。 

ループ条件`total + add <= n`これにより、残りのレンガで完全に支持できる場合にのみ階段をコミットすることが保証されるため、これは重要です。 これによりオーバーシュートが回避され、バックトラッキングの必要がなくなります。 

ここでよくあるオフバイワンのリスクはアップデートです`total`実現可能性を確認する前に。 正しいアプローチは、最初にチェックしてからコミットすることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    cnt = 0
    add = 1
    total = 0
    while total + add <= n:
        total += add
        add += 1
        cnt += 1
    return str(cnt)

# provided samples (conceptual, as not explicitly given)
assert run("1\n") == "1"
assert run("3\n") == "2"

# custom cases
assert run("0\n") == "0", "minimum edge"
assert run("2\n") == "1", "cannot form second stair"
assert run("6\n") == "3", "exact triangular number"
assert run("10\n") == "4", "perfect staircase"

 ## 特殊なケース

 のために$n = 1$、アルゴリズムは次から始まります`add = 1`そして小切手`0 + 1 <= 1`したがって、階段は 1 つだけ作成され、次の追加は 2 つになり、すでに残りの予算を超えているため、その後停止します。 これにより、最小限の入力が正しく処理されることが確認されます。 

のために$n = 2$、最初の階段が追加され、`total = 1`で、次の候補は`add = 2`。 以来`1 + 2 > 2`、ループはすぐに停止し、ちょうど 1 つの階段が生成されます。 これは、アルゴリズムが実現可能性を過大評価していないことを示しています。 

三角形の境界の場合、$n = 6$、シーケンスは正確に構築されます$1 + 2 + 3 = 6$、次の試行は 4 になりますが、これは正しく失敗します。 これは、条件が次を使用しているため、等価性が安全に処理されることを示しています。`<=`、正確なフィットを含めることができます。
