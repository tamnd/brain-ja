 ## 問題の理解

 私たちに与えられた一行は、`N`ホステルの部屋。各部屋には、それに関連する一定の清掃コストまたは重量があります。 管理者は、構造化された方法で掃除人を割り当てることを望んでいます。つまり、部屋を任意に選択するのではなく、周期的なパターンを選択する必要があります。 

有効な割り当ては、サイズのブロックごとに 1 つの位置を正確に選択することによって形成されます。`K`、そして配列全体にわたってこの選択を繰り返します。 具体的には、ポジションからスタートすると決めた場合、`i`、次に部屋を選択します`i, i+K, i+2K, ...`アレイを離れるまで。 このような選択ごとに 1 つのスイーパー候補チームが形成され、その合計コストは、選択されたポジションの値の合計になります。 

重要な制約は、`K`分割する`N`, したがって、配列は完全に次のように分割できます。`K`剰余クラスのモジュロ`K`。 タスクは、各剰余クラスの合計コストを計算し、それらの最小値を返すことです。 

制約の観点から見ると、これは古典的な線形集計の問題です。 たとえ`N`あたりまでです`2 × 10^5`、配列に対して 1 回のパスのみを実行するため、`O(N)`解決策で十分です。 合計の再計算を伴うすべての開始点に対するネストされた反復を伴うものはすべて、次のように劣化します。`O(N^2 / K)`最悪の場合、遅すぎます。`N`大きいです。 

すべての値が等しい場合、または最小クラスが局所的に明らかでない場合、微妙なエッジ ケースが発生します。 たとえば、配列が次の場合、`[5, 1, 5, 1]`そして`K = 2`、剰余クラスは`[5 + 5]`そして`[1 + 1]`、したがって、答えは次のとおりです`2`。 単純な間違いは、単一の最小要素を選択するか、極小値が支配的であると仮定することです。独立した要素を選択するのではなく、構造化された部分列を合計しているため、これは失敗します。 

もう 1 つの失敗例は、グループ化が厳密にインデックス モジュロによって行われることを忘れていることです。`K`。 最小のものをすべて貪欲に選択しようとする試み`K`アライメントを考慮しない -th 要素は、誤ったグループ化を生成します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。`0`に`K - 1`、インデックスの要素の合計を計算します。`i, i + K, i + 2K, ...`。 それぞれの合計を大まかにスキャンする必要があります`N / K`要素があるため、全体の複雑さは次のようになります。`O(K × N / K) = O(N)`。 興味深いことに、正しく実装されていれば単純な定式化であってもすでに線形になっていますが、多くの単純な実装では部分和を繰り返し再計算したり、部分列を明示的に構築したりするため、高水準言語ではオーバーヘッドや隠れた二次関数の動作が発生します。 

重要な観察は、配列が自然に次のように分解されるということです。`K`インデックスモジュロに基づく独立したグループ`K`。 すべてのインデックスは 1 つのグループにのみ属し、各グループは独立して回答候補に貢献します。 したがって、大きなサイズのジャンプを繰り返し歩くのではなく、`K`に直接蓄積できます。`K`1 回のパスでバケットに移動します。 

これにより、問題は単純な分割と合計のタスクに変わります。配列を維持するということです。`bucket[0..K-1]`、 追加`arr[i]`の中へ`bucket[i % K]`、最後に最小バケット合計を取得します。 

それぞれの有効な選択が 1 つの剰余クラスに正確に対応するため、ブルート フォースは機能しますが、繰り返しジャンプとして実装すると非効率または扱いにくくなります。 インデックスが互いに素なモジュロ クラスを形成するという観察により、反復的な走査が単一の累積パスに減ります。

 ## アルゴリズムのチュートリアル

 1.読む`N`そして`K`、配列を読み取ります`arr`。 各インデックスは、次のように決定される剰余クラスに属するものとして扱います。`i % K`。 
2. 配列を作成する`bucket`サイズの`K`、ゼロに初期化されます。 各エントリには、1 つの開始オフセット クラスの合計コストが保存されます。 
3. すべてのインデックスを反復処理します。`i`から`0`に`N - 1`。 
4.追加`arr[i]`に`bucket[i % K]`。 これにより、サブシーケンスを明示的に構築することなく、各要素が正しい周期グループに割り当てられます。 このステップは、反復的な走査を回避する中心的な変換です。 
5. すべての要素を処理した後、すべての要素の最小値を計算します。`bucket[j]`のために`0 ≤ j < K`。 
6. この最小値を答えとして出力します。 

### なぜ効果があるのか

 すべての有効なスイープ構成は、1 つの剰余クラスのモジュロを選択することに正確に対応します。`K`。 バケットの構築により、各要素が正確に 1 つのクラスに寄与し、要素が二重にカウントされないことが保証されます。 各クラスはストライドでステップすることによって選択されたすべての要素の合計を表すため、`K`、バケット値は正確に、考えられるすべての有効なスイープ パターンのコストです。 これらの徹底的でばらばらな構成を最小限に抑えることで、最適なソリューションが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    bucket = [0] * k
    
    for i in range(n):
        bucket[i % k] += arr[i]
    
    print(min(bucket))

if __name__ == "__main__":
    solve()
```実装はバケット分解のアイデアに直接準拠しています。 配列`bucket`各モジュロクラスの累積合計を格納します。 モジュロ演算により、サイズのジャンプを明示的に繰り返すことなく、正しいグループ化が保証されます。`K`。 

よくある間違いは、構築しようとすることです`k`リストを分割してからそれらを合計しますが、これは不必要であり、メモリのオーバーヘッドが増加します。 もう 1 つの微妙な問題は、特に初期化されていない配列にガベージ値が含まれる可能性がある言語で、バケットを適切に初期化することを忘れることです。

## テストケース```python
import sys, io

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    bucket = [0] * k
    for i in range(n):
        bucket[i % k] += arr[i]
    print(min(bucket))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided sample (constructed)
assert run("6 2\n4 1 3 2 6 5\n") == "8"

# all equal
assert run("4 2\n5 5 5 5\n") == "10"

# k = 1 (single group)
assert run("5 1\n1 2 3 4 5\n") == "15"

# k = n (each element isolated)
assert run("4 4\n10 1 2 3\n") == "1"

# alternating pattern
assert run("6 3\n1 100 1 100 1 100\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |

 | k = 1 | 配列の合計 | 単一バケットの折りたたみ |

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`K = 1`。 この場合、すべての要素は同じグループに属しているため、答えは配列全体の合計になる必要があります。 すべてのインデックスが次の条件を満たすため、アルゴリズムはこれを自然に処理します。`i % 1 = 0`したがって、すべての値は 1 つのバケットに蓄積されます。 

もう 1 つのエッジケースは次のような場合です`K = N`。 すべてのインデックスは個別の残基クラスにマップされるため、各要素は独自のグループを形成します。 アルゴリズムはそれぞれを正しく割り当てます。`arr[i]`を別のバケットに追加すると、最小バケットが配列内の最小要素になります。 

3 番目のケースは、次のように値が大きく切り替わる場合です。`[1, 100, 1, 100, ...]`と`K = 2`。 ここで、各バケットはパリティに応じてすべての小さい値またはすべての大きい値を収集し、アルゴリズムはそれらを混合することなく正しく分離し、比較に必要な構造を保持します。
