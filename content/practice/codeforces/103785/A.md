 ## 解決策
 ## 問題の理解

 同一のオブジェクトのコレクションとコンテナーの容量が与えられます。 各コンテナに最大で収容できるのは、$K$オブジェクトをすべて配置したいと考えています$N$オブジェクトをコンテナに入れます。 タスクは、最適に梱包するときに必要なコンテナの最小数を決定することです。 

入力は 2 つの整数で構成されます。 1 つ目は、合計でオブジェクトの数を表します。 2 番目の値は、1 つのコンテナに配置できるオブジェクトの最大数を表します。 出力は、容量を超えずにすべてのオブジェクトを保持するために必要なコンテナーの数を表す単一の整数です。 

制約は十分に小さいため、テスト ケースごとの計算は一定時間でなければなりません。 たとえ$N$大きく、最大で最大である可能性があります$10^9$一般的な競技プログラミング設定では、関係する演算は単純な算術演算であるため、線形または反復パッキング シミュレーションは不要であり、多くのテスト ケースで繰り返すと速度が非常に遅くなる可能性があります。 期待される解決策は、シミュレーションではなく直接的な数学的推論に依存する必要があります。 

オブジェクトの数がコンテナ サイズで正確に割り切れる場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$N = 10$そして$K = 2$、正解は 5 です。除算後に常にコンテナを 1 つ追加する単純なアプローチでは、誤って 6 が返されます。もう 1 つのエッジ ケースは次のような場合です。$K > N$。 例えば、$N = 3$、$K = 10$、正解は 0 ではなく 1 です。純粋な整数の除算です。$N / K$調整しないと、誤ってコンテナが 0 個になる可能性があります。 

## アプローチ

 この問題を考える簡単な方法は、容器を 1 つずつ充填するシミュレーションを行うことです。 最初のコンテナから始めて、最大まで配置します$K$オブジェクト、からそれらを差し引く$N$、オブジェクトがなくなるまで繰り返します。 各反復はコンテナへの充填を表します。 これは制約を直接反映しているため、これは正しいです。 

ただし、このアプローチのパフォーマンスは大まかに$N / K$繰り返し、そして最悪の場合、$K = 1$、に退化します。$N$ステップ。 もし$N$が大きい場合、問題の構造が純粋に一様なパッキングであることを考えると、これは非効率的かつ不必要になります。 

重要な観察は、おそらく最後のコンテナを除いて、すべてのコンテナが完全に満たされていることです。 これは、効果的に分割していることを意味します$N$アイテムをサイズのグループに分ける$K$。 そのようなグループの数はまさに上限に達します$N / K$。 これにより、シミュレーションが完全に不要になり、問題が 1 つの算術式に減ります。

 ## アルゴリズムのチュートリアル

 1. の値を読み取ります。$N$そして$K$。 これらは、配置する必要があるアイテムの数と、各コンテナーに保持できるアイテムの数を定義します。 
2. 整数の除算を計算する$N // K$、形成できる完全なコンテナの数を数えます。 これにより、完璧な梱包を想定したコンテナのベースライン数が得られます。 
3. 割ったときに余りがあるかどうかを確認する$N$による$K$。 もし$N \bmod K \neq 0$の場合、追加のコンテナが必要なアイテムが残ります。 
4. 残りがある場合は、コンテナ数を 1 つ増やします。 これは、部分的に充填された最終コンテナを考慮します。 
5. 最終的なカウントを出力します。 

剰余チェックの背後にある理由は、整数の除算がゼロに向かって切り捨てられ、完全なグループを形成しない残りの部分が破棄されるためです。 この廃棄された部分には、さらに追加のコンテナ内のスペースが必要です。 

### なぜ効果があるのか

 おそらく最後のコンテナを除くすべてのコンテナには、正確に含まれている必要があります$K$アイテムを最適な梱包で。 部分的に充填されたコンテナが複数ある場合、それらをマージしてコンテナの総数を減らし、最適性に反してしまう可能性があります。 したがって、不完全なコンテナは最大でも 1 つ存在する可能性があり、次の場合にのみ存在します。$N$で割り切れない$K$。 これにより、次の上限を計算することが保証されます。$N / K$最適なコンテナ数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

containers = n // k
if n % k != 0:
    containers += 1

print(containers)
```ソリューションは数学的観測を直接エンコードします。 整数の除算によって満杯のコンテナの数が計算され、モジュロ チェックによって追加のコンテナが必要かどうかが判断されます。 ループや追加のデータ構造は必要ないため、実装が最小限に抑えられ、パフォーマンスの問題のリスクが回避されます。 

よくある間違いは、剰余の場合を忘れることです。 書き込みのみ`n // k`失敗したとき$N$で完全に割り切れない$K$、残ったオブジェクトにはまだコンテナが必要なためです。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$N < K$。 入力用`5 10`、アルゴリズムは次のように計算します。$5 // 10 = 0$そして、ゼロ以外の剰余を見つけて、インクリメントをトリガーします。 最終結果は 1 になり、アイテム数が少ない場合でも 1 つのコンテナーが必要であることを正しく表しています。 

別のケースは、次のような正確な可分性です。`12 3`。 計算の結果は、$12 // 3 = 4$そして残りはゼロです。 追加のスペースは必要ないため、答えは 4 のままです。これは、アルゴリズムがコンテナーを過剰にカウントしないことを確認します。 

3 番目のケースは、次のような最小限の入力です。`1 1`。 ここでは、除算の結果は 1 であり、余りが存在しないため、結果は 1 となり、1 つの項目が 1 つのコンテナに正確に収まるという直感的な期待と一致します。
