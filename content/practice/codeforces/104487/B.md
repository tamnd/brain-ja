 ## 解決策
 ## 問題の理解

 ツリーが与えられているため、ノードの各ペアにはノード間の単純なパスが 1 つだけあります。 任意の 2 つのノードの場合$a$そして$b$、セットを定義します$h_{a,b}$間の固有のパス上にあるすべてのノードのコレクションとして$a$そして$b$、エンドポイントを含む。 問題が強制するため、$a < b$、順序のないノードのペアはすべて、そのようなパスの 1 つに正確に対応します。 

次に、2 つの異なるノードのペアを考えます。$(a,b)$そして$(c,d)$。 それらの 2 つのパスセットを見て、次のように定義します。$GCN$両方のパスに現れるノードの数、つまり 2 つのノードセットの交差部分のサイズとして。 タスクは、個別のパスの順序付けされていないすべてのペアにわたるこの交差サイズを合計することです。 

したがって、概念的には、エッジや距離をカウントするのではなく、ツリー内のパスのペアごとに集計された、共有頂点という観点からパスの重なりをカウントします。 

この制約は、ツリーが非常に大きくなり、テスト ケース全体で合計最大 500,000 ノードになる可能性があることを意味します。 すべてのパスを列挙しようとするアプローチは、直ちに不可能です。$\Theta(n^2)$パス。 パスのすべてのペアを比較しても、$\Theta(n^4)$、これは実現可能な限界をはるかに超えています。 これにより、各ノードの寄与がほぼ線形な時間で計算されるソリューションが強制されます。 

木が線である場合、微妙な特殊なケースが発生します。 その場合、ほぼすべてのパスが他の多くのパスと重なり合うため、単純にカウントすると交差を二重にカウントしたり、同一のパスのペアを除外しなければならないという制限を見逃したりする傾向があります。 もう 1 つのエッジ ケースは、ほぼすべてのパスが中心を通過する星型ツリーです。これにより、コンポーネントの分割が誤って処理された場合、中心の寄与が誤って過大評価されやすくなります。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべてのノードペアを列挙します$(a,b)$、パスを構築またはシミュレートし、それを他のすべてのパスと比較します$(c,d)$、共有ノードをカウントします。 これは、次の定義に直接従うため、概念的には正しいです。$GCN$。 ただし、$n$ノードには約があります$n(n-1)/2$パスなので、パスのペアの数はおおよそ次のようになります。$O(n^4)$交差が単純に計算され、前処理を行ったとしても依然として大きすぎる場合の演算。 

重要な点は、合計の順序を逆にすることです。 パスのペアについて考える代わりに、ノードを修正します。$x$パスに含まれるものがいくつあるかを尋ねます。$x$? すべてのノードのその数値がわかっている場合、各ノードは最終的な答えに独立して貢献します。 ノードの場合$x$にある$k_x$パスの場合は貢献します$\binom{k_x}{2}$順序のないパスのペアには次のものが含まれるため、最終的な合計は次のとおりです。$x$合計交差数に 1 つだけ寄与します$x$。 

したがって、問題全体は、ノードごとに、ツリー内の単純なパスが何本通過するかを計算することに帰着します。 

ここで、構造上の洞察は、ノードを削除するとツリーが独立したコンポーネントに分割されるということです。 パスがノードを通過する$x$削除後にそのエンドポイントが両方ともツリーの単一コンポーネント内に含まれていない場合に限ります。$x$。 同様に、次のように計算できます。$$k_x = \binom{n}{2} - \sum_{components\ C \text{ of } x} \binom{|C|}{2}$$これにより、パスの列挙が完全に回避され、サブツリー サイズの計算の問題が軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^4)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、深さ優先探索を使用してサブツリーのサイズを計算します。 これにより、ノードを削除するときに形成されるすべてのコンポーネントを説明するのに十分な構造が得られます。 

1. 任意のノード (通常は 1) でツリーをルート化し、親関係とサブツリーのサイズを計算します。 ノードのサブツリー サイズは、ルート ツリー内でその下にノードがいくつあるかを表します。 
2. 各ノードについて$x$、それを削除するとどうなるかを考えてみましょう。 それぞれの隣人$x$は、結果として得られるフォレスト内の 1 つの接続コンポーネントにのみ対応します。 隣人が子供の場合$x$、コンポーネントのサイズはそのサブツリーのサイズです。 隣人が子供の親である場合$x$、コンポーネントのサイズは$n - \text{subtree}[x]$。 この区別により、二重にカウントすることなくツリー全体を正確に計算できるようになります。 
3. ノードの場合$x$を使用して、各コンポーネント内のノード ペアの合計数を計算します。$\binom{s}{2}$、 どこ$s$コンポーネントのサイズです。 これらをすべてのコンポーネントで合計すると、通過しないパスの数が得られます。$x$。 
4. ペアの総数からこの値を減算します。$\binom{n}{2}$。 結果は、ノードセットに含まれるパスの数です。$x$。 
5. ノードの貢献度を蓄積する$x$最終的な答えとしては$\binom{k_x}{2}$、順序のないパスのペアは両方とも次の内容を含むため、$x$ちょうど 1 回の発生に貢献します$x$グローバル交差和に変換します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのパスのペアが共有ノードごとに 1 回だけカウントされるということです。 ノードを修正する$x$。 両方に含まれる個別のパスの順序付けされていないすべてのペア$x$を通じて、合計の解答にちょうど 1 単位が寄与します。$x$ツリー内の他の場所でパスがどのように動作するかには関係ありません。 さまざまなノードが独立して寄与し、交差サイズはノード間で加算されるため、合計すると$\binom{k_x}{2}$すべてのノードにわたって、必要なグローバル合計を重複や省略なく正確に再構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    parent = [0] * (n + 1)
    order = []
    
    for i in range(2, n + 1):
        p = int(input())
        g[i].append(p)
        g[p].append(i)

    stack = [1]
    parent[1] = -1

    # iterative DFS to avoid recursion depth issues
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            if parent[v] == 0:
                parent[v] = u
                stack.append(v)

    sz = [1] * (n + 1)

    for u in reversed(order):
        for v in g[u]:
            if v == parent[u]:
                continue
            sz[u] += sz[v]

    total_pairs = n * (n - 1) // 2

    ans = 0

    for x in range(1, n + 1):
        sum_bad = 0
        for y in g[x]:
            if parent[y] == x:
                sum_bad += sz[y] * (sz[y] - 1) // 2
            else:
                sum_bad += (n - sz[x]) * (n - sz[x] - 1) // 2 if parent[x] == y else 0

        # simpler correct handling: recompute properly
        sum_bad = 0
        for y in g[x]:
            if parent[y] == x:
                sum_bad += sz[y] * (sz[y] - 1) // 2
            else:
                sum_bad += (n - sz[x]) * (n - sz[x] - 1) // 2

        k = total_pairs - sum_bad
        ans = (ans + k * (k - 1) // 2) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```この実装では、まず親ポインターからツリーを構築し、次に反復 DFS を実行してルート構造を確立します。 サブツリーのサイズは、親の前に子が処理されるように、逆 DFS 順序で計算されます。 

重要な微妙な点は、ノードを削除するときのコンポーネント サイズの処理です。 各子はサブツリー コンポーネントに寄与し、サブツリーの外側にあるものはすべて残りのコンポーネントを形成します。 コードは子のサブツリー サイズを使用し、暗黙的に$n - sz[x]$親側にとっては。 

最後に、ノードごとに、ノードを通過するパスの数を計算し、それをノードを共有するパスのペアの数に変換します。 中間値は 64 ビットの範囲内に収まるため、モジュラー演算は最終累積時にのみ適用されます。 

## 実用的な例

 1-2-3 という 3 つのノードの単純なチェーンを考えてみましょう。 

すべてのパスは (1,2)、(2,3)、(1,3) です。 

ノード 2 の場合、すべてのパスがノード 2 を通過するため、$k_2 = 3$。 ノード 1 と 3 には、$k = 2$。 貢献度は次のようになります。 

| ノード | k (ノードを通るパス) | 貢献$\binom{k}{2}$|
 | --- | --- | --- |
 | 1 | 2 | 1 |
 | 2 | 3 | 3 |
 | 3 | 2 | 1 |

 合計の答えは 5 で、これはほぼすべてのパスのペアが少なくとも 1 つのノードで交差するという事実と一致します。 

次に、中心 1 と葉 2、3、4 を持つ星を考えます。葉の間のパスはすべて中心を通過します。 それで$k_1$は最大ですが、葉の値は小さいです。 これは、中心ノードがどのように寄与を支配するかを示しており、コンポーネントの減算が中心を通過するすべてのパスを正しく捕捉していることを確認します。

 ## 特殊なケース

 2 ノード ツリーにはパスが 1 つだけ存在するため、順序のない個別のパスのペアは存在しません。 アルゴリズムは正しく計算します$k_x$価値観だが最終的には$\binom{k_x}{2}$どこでもゼロになり、出力ゼロが生成されます。 

星型ツリーでは、中心を削除すると、ツリーが多数のシングルトン コンポーネントに分割されます。 の合計$\binom{s}{2}$すべての葉で はゼロになるため、すべてのパスは中心を通過するものとしてカウントされます。 これにより、大きな結果が得られます$k_x$これは、すべての葉から葉へのパスが中心で交差するという事実と一致します。 

線形チェーンでは、ノードを削除した後のコンポーネントのサイズは 2 つの間隔になります。 減算式は、端点が反対側にあるパスのみを正しくカウントし、内部ノードが確実に高くなるようにします。$k_x$パス カバレッジの幾何学的直観と​​一致します。
