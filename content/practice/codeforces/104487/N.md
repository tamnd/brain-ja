 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには n 人の生徒がいます。 各生徒は整数値 ai を持ち、その値は他の生徒との互換性を定義します。2 人の生徒 x と y の間の互換性は、それらの値の最大公約数 gcd(ax, ay) です。 

すべての生徒が接続されて単一のツリーを形成できるように、正確に n − 1 個の接続のネットワークを構築する必要があります。 各接続は、2 つのエンドポイントの gcd に等しい重みを与えます。 木の選び方としては、可能な限り総重量が最大のものを選びたいものです。 

したがって、問題は本質的に、エッジの重みが gcd(ai, aj) として暗黙的に定義される完全なグラフ上の最大スパニング ツリーを求めることになります。 入力制約では、テスト ケース全体で最大 5 · 10^5 の合計ノードと最大 10^6 の値が許可されます。 

このスケールでは、ノードのすべてのペアを明示的に考慮するアプローチは除外されます。 完全なグラフには約 n^2 のエッジが含まれますが、これは n = 10^5 の場合でも不可能です。 すべてのペアごとの gcd 値を保存することすら不可能です。 

さらに微妙な問題は、エッジの重みが任意ではなく、gcd 構造のみに依存することです。 つまり、多くのエッジが同じ重みを共有し、分割可能性の構造だけが重要です。 

単純な間違いは、すべてのペアを gcd 値でソートしようとしたり、すべてのエッジに対して Kruskal を実行しようとしたりすることです。 n = 5000 の場合でも、すでに数千万のエッジが生成されており、すぐに TLE または MLE になります。 

もう 1 つの失敗例は、貪欲なローカル選択に起因します。 たとえば、各ノードを常に最も近い「高 gcd パートナー」に接続すると、サイクルが形成されたり、少し小さい gcd エッジが後で複数の高価値の接続をロック解除する、より優れたグローバル構造を見逃したりする可能性があります。 最適な構造は、ペアごとの最適な選択ではなく、約数によるグローバルなグループ化に依存します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのエッジ (i, j) を構築し、gcd(ai, aj) を計算し、エッジを並べ替えて、最大スパニング ツリー アルゴリズムを実行します。 MST 理論では、エッジが完全にわかったら正確さが保証されるため、これは概念的には正しいです。 ただし、O(n^2) エッジの生成はすでに大きすぎます。 n = 10^5 の場合、これは 10^10 回の演算に相当し、まったく実行不可能です。 

重要な観察は、gcd エッジが約数によって構造化されていることです。 2 つの数値が大きな gcd d を共有する場合、両方の数値は d の倍数になります。 これは、重み d のエッジは、値が d の倍数であるノード間にのみ存在することを意味します。 ペアの観点から考える代わりに、除数バケットの観点から考えることができます。 

考えられる gcd 値を大きい値から小さい値まで処理します。 固定値 d の場合、ai が d で割り切れるすべてのノードを収集します。 これらのノードは、少なくとも d の重みのエッジを使用して接続できる可能性があります。 d を降順で処理すると、より重みの高いエッジが最初に考慮されるようになります。これは、最大スパニング ツリー構築の貪欲な性質と一致します。 

接続を効率的に処理するために、素の集合共用体構造を使用します。 各 d について、バケット内のすべてのノードを取得し、それらをマージしようとします。 マージが成功するたびに、正確に d が答えに寄与します。これは、以前に切り離されていた 2 つのコンポーネント間に重み d のエッジを効果的に追加しているためです。 

また、倍数のすべてのバケットを迅速に構築する方法も必要です。 各数値を因数分解する代わりに、視点を逆にします。各 d について、k・d の倍数を反復し、値が k・d に等しいすべてのインデックスを d のバケットに追加します。 これはおよそ O(m log m) で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのペア + MST) | O(n² log n) | O(n²) | 遅すぎる |
 | 除数バケット + DSU | O(m log m + n α(n)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ai の各値のインデックスのリストを作成します。 特定の値を持つすべてのノードを迅速に取得できるように位置を保存します。 
2. バケットの配列を作成します。ここで、bucket[d] には、値が d で割り切れるすべてのインデックスが含まれます。 これを倍数にわたって反復することによって満たします。1 から m までの各 d に対して、値 2d、3d などのすべてのインデックスを追加します。 
3. すべての n ノードにわたって素セット共用体構造を初期化します。 最初は各ノードが分離されています。 
4. d を m から 1 まで処理します。d ごとに、bucket[d] 内のすべてのノードを反復処理します。 私たちはこのグループの臨時代表者を置いています。 
5. バケット[d]の最初のノードについては、それを基本代表として設定します。 バケット内の他のすべてのノードについて、代表との結合を試みます。 結合が成功した場合は、答えに d を追加します。 
6. すべての d に対してこのプロセスを続けます。 累計が結果となります。 

大きい d から小さい d に処理する理由は、より強力な gcd 接続を最初に優先したいためです。 2 つのノードがより高い値の除数を介して接続されると、DSU によって既に統合されたコンポーネントが再接続されないことが保証されるため、弱いエッジは再度必要なくなります。 

### なぜ効果があるのか

 完全なグラフ内のすべてのエッジの重みは gcd(ai, aj) に等しく、これはまさに ai と aj の両方が d で割り切れる最大の d です。 特定の d を処理するときは、重みが少なくとも d であるすべてのエッジを効果的に考慮することになります。 降順で処理することにより、重みでソートされたすべての暗黙的なエッジに対してクラスカルのアルゴリズムをシミュレートします。 DSU は、異なるコンポーネントを接続するエッジのみを保持することを保証し、レベル d でマージするたびに、それらのコンポーネントを接続できる可能な限り最良の残りのエッジを使用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        a = find(a)
        b = find(b)
        if a == b:
            return False
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]
        return True

    pos = [[] for _ in range(m + 1)]
    for i, v in enumerate(a):
        pos[v].append(i)

    bucket = [[] for _ in range(m + 1)]

    for d in range(1, m + 1):
        for k in range(d, m + 1, d):
            for idx in pos[k]:
                bucket[d].append(idx)

    ans = 0

    for d in range(m, 0, -1):
        if not bucket[d]:
            continue
        rep = bucket[d][0]
        for v in bucket[d]:
            if union(rep, v):
                ans += d

    print(ans)

t = int(input())
for _ in range(t):
    solve()
```このコードは、まずインデックスを正確な値でグループ化し、次に倍数ループを使用して除数バケットを構築します。 これにより、各数値を個別に因数分解することがなくなります。 DSU は標準であり、マージが実際に行われるときにのみコストが追加されます。これはパフォーマンスにとって非常に重要です。 

d を m から 1 までループすると、正しいエッジの順序が暗黙的に適用されるため、明示的にエッジを並べ替える必要はありません。 

## 実用的な例

 ### 例 1

 入力:```
1
3 10
2 6 8
```バケットを構築します。 

| d | バケット[d] |
 | --- | --- |
 | 6 | 6 個のノード |
 | 4 | 8 個のノード |
 | 2 | 2、6、8 のノード |

 高いものから低いものへと処理していきます。 

| d | アクション | DSU のマージ | 答え |
 | --- | --- | --- | --- |
 | 6 | 6グループ接続 | 最初は何もありません | 0 |
 | 4 | 8グループ接続 | まだ何もありません | 0 |
 | 2 | すべて接続する | (2,6)、(2,8) をマージ | 4 |

 合計 6 + 2 になりますか? 実際には、MST は重み 6 と 2 のエッジを選択し、合計すると 8 になります。シミュレーションでは、マージが最初に高いレベルで発生し、次に残りの接続が低いレベルで発生することが反映されています。 

これは、より高い gcd 接続が優先されますが、より低い gcd 接続は依然として残りのコンポーネントに接続していることを示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が等しい場合です。 その状況では、すべてのペアが同じ gcd を持つため、最適なツリーは任意のスパニング ツリーを選択でき、各エッジは同じ値に寄与します。 すべてのノードが関連するすべての除数バケットに表示され、最初に可能な限り高い d で和集合が発生し、その後は何も残らないため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、すべての値がペアごとに互いに素である場合です。 この場合、すべての gcd は 1 になるため、すべてのエッジの重みは事実上 1 になります。アルゴリズムは d = 1 でのみ意味のある結合を実行し、正確に n − 1 個のマージを生成します。これは、予想されるツリー サイズと一致します。 

最後のエッジ ケースは、値がまばらであるものの、1000 の倍数と小​​さな数値が混在するなど、大きな公約数構造を共有する場合です。 降順スイープにより、大きい除数がコンポーネントを最初に接続し、小さい除数はフォールバック接続としてのみ機能するため、最適性が維持されます。
