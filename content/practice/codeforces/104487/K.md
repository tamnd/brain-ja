 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするツリーが与えられています。各ノードには固定の重みがあり、すべての開始ノード間で共有される一連の「日の値」もあります。 あるノードから開始して、固有のパスに沿って上向きにル​​ートに到達する場合、1 日目を開始ノードに割り当て、2 日目をその親に割り当て、というようにルートに到達するまで続けます。 

このウォーク中に、訪問した各ノードが実行スコアに寄与します。 ノードの寄与は 2 つのことに依存します。ツリー内の固定値と、ノードを訪問した日の値です。 具体的には、ノードが k 日目に訪問された場合、そのノードの重みと k 日目の値の積を加算します。 

タスクは、考えられるすべての開始ノードに対して独立してこの合計スコアを計算することです。 

ここでは制約パターンが主な信号です。 すべてのテスト ケースにわたるノードの合計数は最大 3x10^5 であるため、テスト ケースごとにどのような解も線形または線形演算に近いものでなければなりません。 ノードごとに再計算を行って各パスを独立してたどるものは、チェーン形状のツリーで O(n^2) に低下し、すぐに失敗します。 同様に、祖先パスごとに寄与分を繰り返し再計算することは現実的ではありません。 

微妙なエッジ ケースは、開始ノードごとに日インデックスが常に 1 から始まることを理解することから生まれます。 これにより、クエリ ノードごとの重み付けスキームがリセットされます。 単純な間違いは、日をノード間でグローバルなものとして扱うことであり、意味が完全に変わってしまいます。 

もう 1 つの例外的なケースは、歪んだツリー、たとえば 1-2-3-4-…-n のようなチェーンです。 その場合、各回答には、日の重みが増加する完全なプレフィックス合計が含まれます。 ノードごとのトラバーサル手法では、同じサフィックスを何度も繰り返し再計算することになりますが、これはまさに避けなければならないことです。 

## アプローチ

 直接的なアプローチは単純です。各ノードについて、ルートまで上向きに歩き、最初から k 日目の値と深さ k のノードの値を乗算し、それを合計します。 これは問題で説明されているプロセスを文字通りシミュレートしているため、これは正しいです。 ただし、チェーン状のツリーでは O(n) ステップ後に最後のノードのルートに到達するため、これをすべてのノードに対して行うと O(n^2) の作業が必要になります。 

重要な観察点は、ウォークの構造は開始ノードに対する相対的な深さによって完全に決定されるのに対し、ツリー構造は各深度にどのノードが表示されるかにのみ影響するということです。 これは視点を反転することを示唆しています。各ノードから開始して上に進む代わりに、ルートから開始して情報を下に伝播し、考えられるすべての開始パスで各ノードがどのように表示されるかを考慮した方法で寄与を蓄積できます。 

ノード u を修正すると、その寄与がそのサブツリー内にあるすべての開始ノードに表示されます。 そのサブツリー内の開始ノード x については、dist(x, u) に等しい深さで u が訪問されます。 したがって、u は、サブツリー内の各深度に表示されるノードの数にのみ依存する値を乗じた b[u] に寄与します。 

これにより、問題は、サブツリー内のさまざまな深さのすべてのノードにわたる日の値の集計された加重合計をノードごとに維持することに変わります。 課題は、親と子の間を移動するときに深さが変化することです。そのため、これらの深さインデックス付きの寄与を効率的にマージする方法が必要です。 

これは、「シフト畳み込み」動作を備えた古典的なツリー DP です。 各サブツリーには、サブツリー ルートからの距離によってインデックス付けされた寄与を表す構造が含まれています。 子を親にマージする場合、子サブツリー内のすべてのノードが祖先ベースの開始点から 1 ステップ離れているため、すべての子の寄与を深さで +1 シフトする必要があります。 

これを効率的に管理する標準的な方法は、深さごとに集計された値のベクトルのような構造をノードごとに維持し、より小さな構造をより大きな構造にマージし (ツリー上の DSU またはヘビーライト スタイルのマージ)、各要素が O(log n) 回だけシフトおよび追加されるようにすることです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ノードごとの上向きウォーク) | O(n^2) | O(n) | 遅すぎる |
 | 小規模から大規模へのマージを備えたツリー DP | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、サブツリー情報をボトムアップで計算します。 

1. まず、ルートからのすべてのノードの深さを計算します。 これにより、ルートからノードがどのくらい離れているかをインデックスする自然な方法が得られ、サブツリーを結合するときに一貫した相対シフトが可能になります。 
2. 各ノード u について、コンテナ dp[u] を維持します。ここで、dp[u][d] は、u のサブツリー内の、u から距離 d の位置にあるノードの寄与の合計を、それらの b 値で重み付けして表します。 この抽象化により、サブツリー構造がグローバルな相互作用から分離されます。 
3. ツリーをポストオーダーで処理します。 ノード u を訪問するときは、距離 0 にある u 自体の寄与で dp[u] を初期化します。つまり、dp[u][0] = b[u] となります。 
4. u の子 v ごとに、dp[v] を dp[u] にマージします。 すべてのエントリ dp[v][d] は v から距離 d にあるノードに対応しますが、u に対してこれらのノードは距離 d+1 にあるため、マージする前にインデックスを +1 シフトします。 マージにより、dp[v][d] が dp[u][d+1] に追加されます。 
5. マージ中は、常に小さい dp 構造を大きい dp 構造に接続します。 これにより、各値が最大で対数的に多くのマージ間を移動し、全体の複雑さを線形に近く保つことが保証されます。 
6. ノード u の dp が完全に計算されると、その最終的な答えを導き出すことができます。 重要な再解釈は、dp[u][k] が、u から開始したときに深さ k で訪問されるノード間に合計 b 重みがどれだけ存在するかを示すということです。 dp[u][k] に a[k] を乗算し、すべての有効な k を合計します。 

これが機能する理由は、任意の開始ノード u について、そのサブツリー内のすべてのノード v が u からの距離に等しい深さに 1 回だけ訪問され、dp がその距離によってグループ化されたすべてのノードを正確に集約するためです。 

## なぜ機能するのか

 中心となる不変条件は、ノード u を処理した後、dp[u] が u からの距離によってインデックス付けされたサブツリー ノードの重みの完全で正しいヒストグラムをエンコードすることです。 +1 シフトすると、1 レベル上に移動するときのルート参照の変更と正確に一致するため、各マージが正確さを維持します。 すべてのサブツリーは各祖先チェーンに 1 回だけ結合されるため、すべてのペア (開始ノード、訪問ノード) が正しい深さバケット内で 1 回だけカウントされ、最終的な加重合計がプロセスの定義と一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if parent[v] == -1:
                parent[v] = u
                stack.append(v)

    parent[0] = -1

    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)

    dp = [dict() for _ in range(n)]

    for u in reversed(order):
        dp[u][0] = b[u] % MOD
        for v in children[u]:
            if len(dp[v]) > len(dp[u]):
                dp[u], dp[v] = dp[v], dp[u]
            ndp = dp[u]
            for d, val in dp[v].items():
                ndp[d + 1] = (ndp.get(d + 1, 0) + val) % MOD
        dp[u] = ndp

    res = [0] * n
    for u in range(n):
        s = 0
        for d, val in dp[u].items():
            if d < n:
                s = (s + val * a[d]) % MOD
        res[u] = s

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```この実装では、まず明示的な親配列を使用してルート付きツリーを構築し、次にクリーンな事後順序トラバーサル用の子リストを構築します。 dp 構造は、完全な配列は偏った場合に大きすぎるため、疎な深さのストレージを可能にするノードごとの辞書です。 

マージの手順は重要な部分です。子を親にマージする前に、常に小さいマップを大きいマップにマージするようにします。 これにより、二次爆発が防止されます。 1 によるシフトは、キー d+1 に挿入することによって明示的に処理されます。 

最後に、dp[u] が構築されたら、保存されている各深度バケットと対応する日の値 a[d] をペアにして寄与度を評価します。 

## 実用的な例

 a = [1, 2, 3] および b = [1, 2, 3] の小さなチェーン 1-2-3 を考えてみましょう。 

私たちは dp をボトムアップで構築します。 

| ノード | dp 内容 (深さ → 合計 b) |
 | --- | --- |
 | 3 | {0:3} |
 | 2 | {0:2、1:3} |
 | 1 | {0:1、1:2、2:3} |

 ノード 2 の場合、答えは 2・a1 + 3・a2 = 2・1 + 3・2 = 8 として計算されます。これは、2 から開始して 2、次に 1 を訪問することに正確に対応します。 

ノード 1 については、1・a1 + 2・a2 + 3・a3 = 1 + 4 + 9 = 14 を計算し、完全な上向きパスと一致します。 

このトレースは、dp がすべての上向きパスを同時に効果的にエンコードしていることを示しています。 

ここで、ルート 1 に子 2、3、4 があり、すべての葉がある星を考えてみましょう。 

| ノード | dpコンテンツ |
 | --- | --- |
 | 2,3,4 | {0: b[i]} |
 | 1 | {0: b1、1: b2 + b3 + b4} |

 ノード 1 の場合、深さ 0 と 1 のみが存在し、すべてのリーフがちょうど 1 ステップ離れているという事実と一致します。 各リーフは深さ 1 にのみ寄与し、正しいシフト動作を確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各ノードの貢献は小規模から大規模にマージされ、各値が限られたマージ間で移動することが保証されます。 
| スペース | O(n) | 各ノードは、集約された形式で一度に 1 つの dp 構造に寄与します。 

この制約では合計 3×10^5 ノードまでが許可されるため、マージが効率的であれば、対数オーバーヘッドを伴う線形に近いソリューションは、Python 定数因数を使用しても制限内に快適に収まります。

 ## 特殊なケース

 単一ノード ツリーは、dp[1][0] が b[1] に等しくなければならない基本初期化を分離し、答えは b1·a1 になります。 初期化が欠落していると、これは直ちに中断されます。 

深いチェーンでは、マージごとにコントリビューションが繰り返しシフトされます。 アルゴリズムは、各シフトがエッジ トラバーサルごとに 1 回だけ適用されることを保証する必要があります。 シフトが遅れたり重複したりすると、深度インデックスがドリフトし、上位日の乗数が間違ったノードに接続され、明らかに不正確な累積和が生成されます。 

スターでは、すべての子はルートに対して深さ 1 でのみ貢献します。 マージが正しくシフトされない場合、子寄与が誤って深さ 0 に表示され、a2 ではなく a1 でオーバーカウントが発生します。
