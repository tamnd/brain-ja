 ## 解決策
 ## 問題の理解

 いくつかの文字列が与えられますが、すべて同じ固定長です。 同じ長さの新しい文字列を 1 つ作成できます。 目標は、指定された文字列と合計で可能な限り一致するように、この構築された文字列を選択することです。 

試合はポジションごとにカウントされます。 固定位置の場合、構築された文字列のその位置に指定された文字列と同じ文字がある場合、その文字列の類似性が 1 単位得られます。 最終スコアは、すべての文字列とすべての位置にわたるこれらの一致の合計です。 

これをより構造的な方法で再構成すると、最終的な文字列の各位置が独立して合計スコアに寄与します。 位置 i で 1 つの文字を選択します。その選択は同時に、その位置で n 個の文字列のうちのいくつが一致するかに影響します。 

制約は小さく、文字列の数とその長さの両方が 50 で制限されています。これは、テスト ケースごとの 3 次または 2 次の解法でも十分に高速であることがすぐにわかります。 すべての位置のすべての文字のフル スキャンは、テスト ケースごとに最大 2500 セルであり、T が最大 50 であっても、合計の作業量は無視できます。 

各位置が独立して寄与するため、位置間の順序や依存関係に関するトリッキーな特殊なケースはありません。 単純なアプローチでつまずく可能性がある唯一の微妙な問題は、局所周波数の最大化によって各位置が独立して最適に解決されることを認識せずに、貪欲に文字列を構築しようとすることです。 

たとえば、あるポジションで 3 回登場するキャラクターの代わりに 2 回登場するキャラクターを選択した場合、貢献はポジション間で移転されないため、その決定を他の場所で補うことはできません。 もう 1 つの落とし穴は、スコアのみが必要な場合に実際の文字列を不必要に構築しようとすることです。これにより、回避できる複雑さやエラーが発生する可能性があります。 

## アプローチ

 強引なアイデアは、入力によって暗示されるアルファベットに対して長さ m の可能なすべての文字列を試してみることです。 各候補文字列について、すべての m 個の位置を比較することにより、指定された n 個の文字列すべてに対する類似度を計算します。 1 つの候補を評価するコストは O(nm) で、候補の数は m 単位で指数関数的になります。 入力に現れる文字に限定したとしても、分岐係数は依然として大きいため、このアプローチは小さな m を超えると実行不可能になります。 

重要な観察は、ポジション間に相互作用がないということです。 位置 i の寄与は、位置 i で選択した文字にのみ依存し、他のすべての位置には依存しません。 これにより、問題が m 個の個別のサブ問題 (列ごとに 1 つ) に分離されます。 

固定位置 i の場合、その位置に各文字が含まれる文字列の数を知るだけで済みます。 文字 c が位置 i の n 文字列の中で freq[c] 回出現する場合、c を選択すると、その位置から正確に freq[c] の寄与が得られます。 したがって、最適な選択は単にその列で最も頻繁に使用される文字です。 

したがって、文字列全体を検索する代わりに、列ごとの頻度を計算し、最大頻度を合計します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. n と m を読み取り、すべての文字列を読み取ります。 
2. 0 から m-1 までの各位置 i について、n 個の文字列すべてにわたってその列に出現する文字の頻度マップを計算します。 
3. 各列について、そこに出現するすべての文字の最大頻度を見つけます。 
4. この最大値を答えに追加します。 
5. テストケースの累積合計を出力します。 

重要な設計上の選択は、各列を独立して扱うことです。 位置 i の文字を選択すると、位置 i の一致のみに影響し、他の位置には影響しないため、これは有効です。 

### なぜ効果があるのか

合計スコアは、各位置の合計として記述することができます。各項は、その位置で選択された文字にのみ依存します。 位置間に結合がないため、各項を個別に最適化すると、全体的に最適なソリューションが得られます。 各列について、最も頻繁に使用される文字からの逸脱は、他の列を改善することなく、その列の寄与を厳密に減少させるため、トレードオフは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        arr = [input().strip() for _ in range(n)]
        
        ans = 0
        
        for j in range(m):
            freq = {}
            for i in range(n):
                c = arr[i][j]
                freq[c] = freq.get(c, 0) + 1
            ans += max(freq.values())
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは列ごとに反復して、各列の頻度ディクショナリを構築します。 各文字を少なくとも 1 回検査する必要があるため、n 個の文字列にわたる内部ループは避けられません。 ディクショナリはカラムごとにリセットされるため、カラム間の汚染は発生しません。 

よくある間違いは、マトリックス全体にわたってグローバルな頻度を維持しようとすることです。これにより、無関係な位置が混在し、正確さが損なわれてしまいます。 もう 1 つの微妙な問題は、列ごとの頻度マップをリセットするのを忘れることです。これにより、列全体のカウントが誤って累積されてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    return "\n".join(solve() or [])

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        arr = [input().strip() for _ in range(n)]

        for j in range(m):
            freq = {}
            for i in range(n):
                c = arr[i][j]
                freq[c] = freq.get(c, 0) + 1
            ans += max(freq.values())
        out.append(str(ans))
    return out

""") == "4"

 ## 特殊なケース

 文字列が 1 つある最小のケースでは、その文字列が唯一の可能な一致を定義しているため、すべての列が正確に 1 を提供することがわかります。 各列頻度マップには n = 1 に等しい 1 つのエントリがあり、最大値は常に 1 になるため、アルゴリズムはこれを処理します。 

異なる文字を持つ 2 つの文字列など、タイの多い列でも、最大頻度が 1 のままであるため、正しい結果が生成されます。アルゴリズムは、どの文字が選択されるかには依存せず、その文字が出現する回数にのみ依存します。 

完全に均一な行列は最大スコア n × m を生成します。 列ごとの頻度マップには常にカウント n の単一の主要な文字があるため、列全体を合計すると、特殊なケースを使用せずに期待される最大値が得られます。
