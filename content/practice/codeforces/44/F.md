 ## 解決策
 ## 問題の理解

 サイズの長方形のキャンバスがあります`W × H`。 最初はキャンバス全体が白です。 次に、その上にいくつかの黒い線分が描かれます。 その後、一連のフラッドフィル操作が適用されます。 

塗りつぶしはポイントと色を選択します。 現在の同じ色の領域を介して選択したポイントに接続されているすべてのポイントの色が変更されます。 セグメントは壁のように動作し、領域間の移動をブロックする可能性があります。 セグメント自体の面積はゼロですが、コンポーネントを分離するため、依然として重要です。 

最後に、各色が占める合計面積を出力する必要があります。 

難しいのは幾何学的な部分です。 塗りつぶしはピクセルやセルに対しては動作せず、平面内の連続領域に対して動作します。 2 つの点の間にセグメントを横切らず、同じ色の領域内に留まるパスが存在する場合、2 つの点は同じ領域に属します。 

この制約により、あらゆる種類のきめ細かいラスター化が完全に排除されます。 長方形の寸法は最大で`10^4`、したがって、`10^4 × 10^4`グリッドにはすでに含まれています`10^8`細胞。 このようなグリッドを数回フラッドフィルすると、速度が非常に遅くなり、メモリも大量に消費されます。 

セグメントとフィルの数は多くても少なく、`100`それぞれ。 これは、実際の複雑さが長方形のサイズそのものではなく、幾何学的構造に依存していることを強く示唆しています。 だけで`100`セグメントの場合、セグメントによって形成される配置には約`O(n^2)`交差点と地域。 それが私たちが取り組むべき本当のオブジェクトです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

塗りつぶし点がセグメント上に直接あると仮定します。```
5 5
1
1 2 4 2
1
2 2 red
```セグメント自体は赤になりますが、その面積はゼロのままです。 上下の白い部分は白いままです。 正解はまだ`white 25`セグメントは面積に寄与しないためです。 

セグメントを正の厚さを持つものとして扱う単純な実装では、領域が誤って分割されてしまいます。 

セグメントが交差するときに、別の微妙なケースが発生します。```
5 5
2
1 1 4 4
1 4 4 1
1
2 2 blue
```塗りつぶし点はちょうど交点上にあります。 2 つのセグメントのみが青色になり、青色の領域の合計は 0 のままになります。 

交差点でのセグメントの分割に失敗すると、平面グラフが不正確になり、面のトラバースが中断されます。 

ネストされた塗りつぶしもバグの原因となります。```
6 6
1
3 1 3 5
2
1 1 red
5 1 blue
```最初の塗りつぶしは、左半分を赤く着色します。 2 番目の塗りつぶしは、右半分を青色に着色します。 最終エリアは、`18`そして`18`。 

フィルを順次ではなく個別に処理すると、上書き動作が失われます。 

概念的なエッジケースで最も難しいのは、同じ色の切り離された部分です。 2 つの異なる領域が接続されていなくても、両方とも白になることがあります。 塗りつぶしは 1 つの接続コンポーネントのみを再色し、すべての領域を同じ色で再色するわけではありません。 

## アプローチ

 この強引なアイデアは、飛行機を小さなセルに離散化し、塗りつぶしを直接シミュレートすることです。 巨大なグリッド上でセグメントの境界をマークし、塗りつぶし操作ごとに BFS を実行できます。 

フラッド フィルは基本的に接続の問題であるため、これは概念的に機能します。 すべての幾何学的特徴がグリッド セルに整列している場合、BFS はペイント プログラムの動作を正確に再現します。 

問題は規模だ。 座標は次のとおりです`10^4`、セグメントは任意の有理点で交差する可能性があるため、幾何学的精度が重要になります。 セルごとに 1 ユニットの解像度でも、すでに`10^8`細胞。 すべての塗りつぶしがキャンバス全体をスキャンする可能性があります。 これはメモリとランタイムの両方において完全に不可能です。 

重要な観察は、セグメントの数が少ないことです。 平面の実際のトポロジは、セグメントの交差点とセグメントの終点でのみ変更されます。 これらの重要な座標の間では、すべてが均一に動作します。 

これは、ピクセル ビューから平面グラフ ビューに切り替えることを示唆しています。 

描画されたセグメントは、長方形を面に分割します。 各面は固定領域を持つ接続された開いた領域です。 塗りつぶしは、同じ現在の色の境界を介して接続されている 1 つの面または複数の面の色を変更するだけです。 

したがって、問題は次のようになります。 

1. 長方形の境界線とすべてのセグメントによって引き起こされる平面サブディビジョンを構築します。 
2. すべての顔の領域を計算します。 
3. どの面に各塗りつぶし点が含まれているかを決定します。 
4. 面の再着色をシミュレートします。 

のアレンジメント`n`セグメントには唯一のものがあります`O(n^2)`交差点。 交差点でセグメントを分割した後も、平面グラフは管理しやすいままになります。 

顔を抽出する最も確実な方法は、ハーフエッジ トラバースです。 すべての有向エッジはその出射角度を保存します。 周期的な順序で前のエッジを繰り返し取得してウォーキングすると、正確に 1 つの面の境界がトレースされます。 

すべての顔がわかれば、フラッドフィルは簡単になります。 各塗りつぶし点は、面の内部またはセグメントのいずれかに属します。 セグメントの塗りつぶしは領域に影響を与えないため、内部の点のみを考慮します。 再カラーは、接続された 1 つの面にのみ影響します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースラスタライズ | O(W・H・m) | O(W・H) | 遅すぎる |
 | 平面グラフ + 面トラバース | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての幾何学的プリミティブを収集します。 

4 つの長方形の境界線を、入力からのすべての黒いセグメントとともにセグメントとして追加します。 面もキャンバスの端によって境界が定められるため、長方形の境界線が必要です。 
2. すべてのセグメントの交差を計算します。 

セグメントのペアごとに、それらが交差するかどうかを計算します。 存在する場合は、両方のセグメントの交点を保存します。 

元のセグメントはすべて、後ですべての交点で分割されます。 このステップを行わないと、平面グラフには互いに交差するエッジが含まれることになり、面の構築が中断されます。 
3. セグメントを基本エッジに分割します。 

各セグメントに沿ってすべての交点を並べ替えます。 連続した点が 1 つの基本エッジを定義します。 

分割後は、端点を除いて 2 つのエッジが交差しません。 これは、平面グラフ走査の標準要件です。 
4. 幾何学的な点をグラフの頂点に圧縮します。 

浮動小数点座標は辞書キーとしては危険です。 分数を含む正確な有理算術を使用するか、正規化されたタプルを保存します。 

すべての固有の点がグラフの頂点になります。 
5. 有向ハーフエッジを構築します。 

あらゆる無向エッジに対して`(u, v)`、2つの有向エッジを作成します`u → v`そして`v → u`。 

すべての頂点について、出力される有向エッジを極角によって並べ替えます。 
6. 角度トラバースによって面を構築します。 

未使用の有向辺から開始します。 

頂点に到着したとします`v`エッジを通して`u → v`。 すべての発信エッジのうち、`v`、逆エッジを見つけます`v → u`。 周期的な角度順にその直前のエッジを取ります。 

このプロセスを繰り返すことで、1 つの面の境界を歩き回ります。 

このトラバースで使用されるすべての有向エッジをマークします。 
7. すべての面のポリゴン領域を計算します。 

トラバースによりポリゴン境界が生成されます。 靴紐式を使用します。 

1 つの面は外側の面で、負の方向と外側の無限領域に等しい面積を持ちます。 無視してください。 
8. 塗りつぶしポイントを見つけます。 

塗りつぶし操作ごとに、どの境界面にクエリ ポイントが含まれているかを判断します。 

面の数が少ないため、すべての面に対するポイントインポリゴンのテストは十分に高速です。 

点がセグメント上に正確に存在する場合、セグメントの面積はゼロであるため、塗りつぶしは無視してください。 
9. 再着色をシミュレートします。 

最初は、境界のあるすべての面は白です。 

それぞれの塗りつぶし操作により、正確に 1 つの面の色が変更されます。 

マッピングを維持する`face → current color`。 
10. 最終的な面積を蓄積します。 

すべての面の面積を合計して最終的な色を求めます。 

### なぜ効果があるのか

 交差点で分割された後、セグメントは適切な平面埋め込みを形成します。 キャンバスのすべての接続された領域は、この埋め込みの 1 つの境界面に正確に対応します。 

すべての有向エッジは左側の 1 つの面に正確に接するため、ハーフエッジ トラバーサルでは各面を 1 回だけ列挙します。 角度ルールは常に、エッジを交差することなく連続的に境界に従います。 

面内の点の塗りつぶしはセグメントの境界を越えることができないため、その面の色が正確に再設定されます。 面は長方形の内部を分割するため、最終的な色で面の面積を合計すると正しい答えが得られます。 

## Python ソリューション```python
import sys
from fractions import Fraction
from collections import defaultdict

input = sys.stdin.readline

EPS = 1e-9

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def sub(a, b):
    return (a[0] - b[0], a[1] - b[1])

def segment_intersection(a, b, c, d):
    ax, ay = a
    bx, by = b
    cx, cy = c
    dx, dy = d

    r = (bx - ax, by - ay)
    s = (dx - cx, dy - cy)

    den = cross(r[0], r[1], s[0], s[1])

    if den == 0:
        return []

    t = Fraction(cross(cx - ax, cy - ay, s[0], s[1]), den)
    u = Fraction(cross(cx - ax, cy - ay, r[0], r[1]), den)

    if 0 <= t <= 1 and 0 <= u <= 1:
        x = Fraction(ax) + Fraction(r[0]) * t
        y = Fraction(ay) + Fraction(r[1]) * t
        return [(x, y)]

    return []

def point_on_segment(p, a, b):
    px, py = p
    ax, ay = a
    bx, by = b

    c = cross(bx - ax, by - ay, px - ax, py - ay)
    if c != 0:
        return False

    return (
        min(ax, bx) <= px <= max(ax, bx)
        and min(ay, by) <= py <= max(ay, by)
    )

def polygon_area(poly):
    s = Fraction(0)
    n = len(poly)

    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        s += x1 * y2 - x2 * y1

    return s / 2

def point_in_poly(pt, poly):
    x = float(pt[0])
    y = float(pt[1])

    inside = False
    n = len(poly)

    for i in range(n):
        x1 = float(poly[i][0])
        y1 = float(poly[i][1])
        x2 = float(poly[(i + 1) % n][0])
        y2 = float(poly[(i + 1) % n][1])

        if ((y1 > y) != (y2 > y)):
            t = (y - y1) / (y2 - y1)
            xx = x1 + (x2 - x1) * t
            if xx > x:
                inside = not inside

    return inside

def solve():
    W, H = map(int, input().split())

    segments = []

    rect = [
        ((0, 0), (W, 0)),
        ((W, 0), (W, H)),
        ((W, H), (0, H)),
        ((0, H), (0, 0)),
    ]

    for s in rect:
        segments.append(s)

    n = int(input())

    for _ in range(n):
        x1, y1, x2, y2 = map(int, input().split())
        segments.append(((x1, y1), (x2, y2)))

    m = int(input())
    fills = []

    for _ in range(m):
        x, y, c = input().split()
        fills.append((Fraction(int(x)), Fraction(int(y)), c))

    k = len(segments)

    pts_on_seg = []

    for i in range(k):
        a, b = segments[i]
        cur = set()
        cur.add((Fraction(a[0]), Fraction(a[1])))
        cur.add((Fraction(b[0]), Fraction(b[1])))
        pts_on_seg.append(cur)

    for i in range(k):
        for j in range(i + 1, k):
            a, b = segments[i]
            c, d = segments[j]

            inter = segment_intersection(a, b, c, d)

            for p in inter:
                pts_on_seg[i].add(p)
                pts_on_seg[j].add(p)

    edges = set()

    for i in range(k):
        a, b = segments[i]

        pts = list(pts_on_seg[i])

        dx = b[0] - a[0]
        dy = b[1] - a[1]

        pts.sort(
            key=lambda p: (
                Fraction(p[0] - a[0], dx) if dx != 0
                else Fraction(p[1] - a[1], dy)
            )
        )

        for j in range(len(pts) - 1):
            u = pts[j]
            v = pts[j + 1]

            if u != v:
                edges.add((u, v))
                edges.add((v, u))

    graph = defaultdict(list)

    for u, v in edges:
        graph[u].append(v)

    import math

    order = {}

    for u in graph:
        graph[u].sort(
            key=lambda v: math.atan2(
                float(v[1] - u[1]),
                float(v[0] - u[0])
            )
        )

        for i, v in enumerate(graph[u]):
            order[(u, v)] = i

    used = set()
    faces = []

    for u, v in edges:
        if (u, v) in used:
            continue

        face = []

        cu, cv = u, v

        while True:
            used.add((cu, cv))
            face.append(cu)

            arr = graph[cv]
            idx = order[(cv, cu)]

            nxt = arr[(idx - 1) % len(arr)]

            nu, nv = cv, nxt

            cu, cv = nu, nv

            if (cu, cv) == (u, v):
                break

        area = polygon_area(face)

        if area > 0:
            faces.append((face, area))

    face_colors = ["white"] * len(faces)

    all_segments = segments[4:]

    for x, y, col in fills:
        on_seg = False

        for a, b in all_segments:
            aa = (Fraction(a[0]), Fraction(a[1]))
            bb = (Fraction(b[0]), Fraction(b[1]))

            if point_on_segment((x, y), aa, bb):
                on_seg = True
                break

        if on_seg:
            continue

        for i, (poly, area) in enumerate(faces):
            if point_in_poly((x, y), poly):
                face_colors[i] = col
                break

    ans = defaultdict(float)

    for i, (_, area) in enumerate(faces):
        ans[face_colors[i]] += float(area)

    for c in sorted(ans):
        print(c, f"{ans[c]:.8f}")

```最初の部分では幾何学的な配置を構築します。 すべてのセグメントはすべての交点で繰り返し分割されます。 使用する`Fraction`などの合理的な交差点によって引き起こされる正確な災害を回避します。`1/3`。 

ハーフエッジ グラフがソリューションの核心です。 すべての有向エッジは、その左側の 1 つの面にのみ属します。 出ていくエッジを角度ごとに並べ替えることで、境界に沿って一貫して移動できるようになります。 

トラバースステップは微妙です。 1 つのエッジを通って頂点に入った後、循環的な順序で前の出ていくエッジを選択します。 これにより、現在の面が左側に維持され、曖昧さなくその境界がトレースされます。 

この実装では、正の領域の面のみが保存されます。 外側の無限の面は負の向きで表示され、自動的に破棄されます。 

ポイントの位置は、標準のレイ キャスティング テストを使用します。 顔の数が少ないので、すべての顔をチェックするのは十分速いです。 

重要な詳細の 1 つは、セグメントの塗りつぶしの処理です。 これらの塗りつぶしは面積ゼロのジオメトリにのみ影響するため、面積の計算時には無視されます。

 ## 特殊なケース

 セグメント上に正確に塗りつぶし点があると考えてください。```
5 5
1
1 2 4 2
1
2 2 red
```このアルゴリズムは、最初に、正確な共線性と境界ボックス テストを使用して、塗りつぶしポイントがいずれかのセグメントに属しているかどうかをチェックします。 以来`(2,2)`セグメント上にある場合、塗りつぶしは面積の計算では無視されます。 

唯一の面は依然として面積のある長方形全体です`25`したがって、出力は次のようになります。```
white 25.00000000
```次に、交差するセグメントについて考えてみましょう。```
5 5
2
1 1 4 4
1 4 4 1
1
2 2 blue
```前処理中に、2 つのセグメントは次の点で交差します。`(5/2, 5/2)`小さなエッジに分割されます。 塗りつぶしポイントは交差点自体上にあるため、やはり面の色は変更されません。 

分割しないと、グラフに交差するエッジが含まれ、面の走査が有効なポリゴンを生成できなくなります。 

最後に、同じ色を共有する切断された領域について考えます。```
6 6
1
3 0 3 6
3
1 1 red
5 1 red
1 1 blue
```最初の 2 つの塗りつぶしの後、両方の半分が独立して赤くなります。 

フラッドフィルは単なる色の均一性ではなく接続性に依存するため、最後の塗りつぶしは左側の面にのみ影響します。 

最終的な領域は次のようになります。```
blue 18.00000000
red 18.00000000
```カラーはグローバルではなく面ごとに保存されるため、アルゴリズムはこれを自然に処理します。
