 ## 解決策
 ## 問題の理解

 マーシャの電話番号は数字の文字列として与えられます。 この番号から、彼女は別の電話番号を一桁ずつ生成します。 

新しい番号の最初の桁は、次のいずれかの桁になります。`0`に`9`。 その後、次の各桁は、前に選択した桁とマーシャの番号の対応する桁から決定されます。 前に選択した数字が`p`マーシャの番号の現在の桁は`a[i]`の場合、次の数字は次のいずれかに等しい必要があります。$$\left\lfloor \frac{p + a[i]}{2} \right\rfloor \quad \text{or} \quad \left\lceil \frac{p + a[i]}{2} \right\rceil$$いつ`p + a[i]`が偶数の場合、両方の式は同じであり、次の数字が強制されます。 合計が奇数の場合、選択肢は正確に 2 つあります。 

異なる電話番号がいくつ生成できるかを数えなければなりません。 マーシャは、このプロセスで番号を生成できるかどうかに応じて、自分の番号に電話をかける場合もあれば、かけない場合もあります。 このステートメントには、「おそらく彼女自身のものを除いて」と書かれていますが、これは、生成された数値の中にそれが現れた場合にのみそれを減算する必要があることを意味します。 

入力長は最大でも`50`。 これにより、分岐要素が到達する可能性があるため、結果として得られるすべての電話番号を明示的に生成しようとする試みは即座に排除されます。`2`あらゆる位置で。 最悪の場合、有効なシーケンスの数は約`10 * 2^49`、それは天文学的な大きさです。 

長さが短いということは、位置と桁に対する動的プログラミングを強く示唆しています。 どのステップにおいても、重要な情報は、前に選択した数字だけです。 しかないので、`10`可能な桁数の場合、状態空間は小さいです。 

誤って対処しやすい特殊なケースがいくつかあります。 

次の入力を考えてみましょう。```
0
```生成される番号は 1 桁のみで構成され、最初の桁は自由に選択できます。 全て`10`1 桁の数字が有効です。`"0"`自体。 マーシャは自分の電話番号に電話をかけないので、答えは次のようになります。`9`。 

不用意に実装すると、構築可能なときにマーシャの数を引くのを忘れる可能性があります。 

もう 1 つの微妙なケースは、すべての移行が強制される場合です。 

入力：```
2222
```最初の数字から始めると、すべての合計が偶数になるため、次のすべての数字が一意に決定されます。 まさにあります`10`生成された数値。 そのうちの 1 つは、`"2222"`それ自体なので、答えは`9`。 

バグのある解決策では、各位置が常に可能性の数を 2 倍にするという誤った想定が行われる可能性があります。 

パリティトラップもあります。 

入力：```
11
```最初に選択された数字が次であると仮定します。`0`。 2桁目は次のいずれかになります`0`または`1`、 なぜなら`(0 + 1) / 2 = 0.5`。 最初に選択した数字が`1`、2 桁目は強制的に`1`。 前の数字が異なると分岐動作も異なるため、位置ごとに独立して選択肢をカウントすることはできません。 

## アプローチ

 強引なアイデアは文字通りプロセスに従います。 考えられるすべての最初の桁を試し、許可されたすべての継続を再帰的に構築し、生成された個別の電話番号をカウントします。 

これは、遷移ルール​​がローカルであるため機能します。 前の桁がわかったら、1 つまたは 2 つの選択肢によって次の桁が決まります。 再帰ツリーは、すべての有効なシーケンスを正しく列挙します。 

問題は、シーケンスの数が爆発的に増加することです。 奇数の和ごとに 2 つの分岐が作成されます。 最悪の場合、ほぼすべてのポジションが分岐し、おおよそ次のような結果になります。$$10 \cdot 2^{n-1}$$と`n = 50`、これは超えます`5 \times 10^{15}`州。 結果を保存することさえ不可能です。 

重要な観察は、将来はプレフィックス全体ではなく、以前に生成された数字のみに依存するということです。 2 つの異なる構築パスが同じ位置の同じ数字で終わる場合、それらの残りの可能性は同じです。 

その構造はまさに動的プログラミングが利用するものです。 

以下を定義します。$$dp[i][d]$$位置で終わるプレフィックスを生成する方法の数として`i`ここで、生成された数字は次のとおりです`d`。 

州から`(i - 1, prev)`、次の平均化ルールを使用して、許可される次の桁を計算します。`a[i]`。 有効な各遷移は次の DP 層に寄与します。 

しかないので、`50`ポジションと`10`桁数が多いため、状態の総数はごくわずかです。$$50 \cdot 10$$各状態は最大 2 つの遷移を試行するため、ソリューション全体は実用的な目的のために一定時間で実行されます。 

最後に、すべての DP 状態を合計して、生成された電話番号の合計数を取得します。 次に、マーシャの元の数値自体が構成可能な場合は 1 を減算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(2^n)$| 遅すぎる |
 | 最適なDP |$O(n \cdot 10)$|$O(10)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 電話番号を文字列として読み取り、数字の配列に変換します。 
2. サイズの DP 配列を初期化します。`10`。`dp[d]`数字で終わるときに現在のプレフィックスを生成する方法が何通り存在するかを表します`d`。 
3. 最初の位置については、以下のすべての桁が`0`に`9`許可されています。 

セット：```
dp[d] = 1
```すべての桁について`d`。 
4. 残りの位置を左から右に処理します。 
5. 前の数字ごとに`prev`、次を計算します。$$s = prev + a[i]$$6. もし`s`が偶数の場合、次の桁は一意に決定されます。$$nxt = s / 2$$からのすべての方法を追加`prev`の中へ`nxt`。 
7. もし`s`が奇数の場合、可能な丸め値は 2 つあります。$$\lfloor s/2 \rfloor \quad \text{and} \quad \lceil s/2 \rceil$$現在のカウントを次の両方の状態に加算します。 
8. 古い D​​P 配列を新しく計算されたもので置き換えます。 
9. すべての位置を処理した後、すべての DP 値を合計します。 これは、生成された電話番号の合計数です。 
10. マーシャ自身の番号が生成できるかどうかを確認します。 

元の数値そのものを正確に生成しようとすると何が起こるかを観察してください。 位置で`i`、次のことが必要です。$$x_i = a_i$$繰り返しは次のようになります。$$a_i = \frac{x_{i-1} + a_i}{2}$$これは次のことを意味します:$$x_{i-1} = a_i$$これはすべての位置に当てはまらなければならないため、元の数値のすべての桁が等しくなければなりません。 
11. 元の数値のすべての桁が同じ場合は、減算します。`1`答えから。 

### なぜ効果があるのか

 DP の不変式は次のとおりです。$$dp[d]$$数字で終わる有効な生成されたプレフィックスの数と常に等しい`d`現在位置を処理した後。 

各ステップは前の桁と現在の元の桁のみに依存するため、生成された有効な数値はすべて、これらの状態を通過する一連の遷移に正確に対応します。 移行ルールでは、すべての法定の丸められた平均が列挙され、それ以外は何も列挙されません。 

隣接するすべての桁のペアが等しい場合にのみ元の数値を構成できるため、最後の減算は正しいです。 不一致があると、元の数字シーケンスを再現するために必要な平均化方程式に違反します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    a = list(map(int, s))
    n = len(a)

    dp = [1] * 10

    for i in range(1, n):
        ndp = [0] * 10

        for prev in range(10):
            total = prev + a[i]

            if total % 2 == 0:
                nxt = total // 2
                ndp[nxt] += dp[prev]
            else:
                ndp[total // 2] += dp[prev]
                ndp[total // 2 + 1] += dp[prev]

        dp = ndp

    ans = sum(dp)

    same = True
    for i in range(1, n):
        if a[i] != a[0]:
            same = False
            break

    if same:
        ans -= 1

    print(ans)

solve()
```DP 配列には、現在位置のカウントのみが保存されます。 遷移が完了すると古いレイヤーは必要ないため、実装では完全な 2 次元テーブルの代わりにローリング配列が使用されます。 

遷移ロジックは平均化ルールを直接反映します。 合計が偶数の場合、下限と上限が一致するため、次の桁は 1 つだけ存在します。 合計が奇数の場合、隣接する両方の整数が有効になります。 

マーシャ自身の番号の最終チェックは驚くほど簡単です。 元の数値は、プロセス全体を通じてすべての数値が以前に生成された数値と等しい場合にのみ、それ自体を再現できます。 これにより、すべての桁が強制的に同一になります。 

実装の微妙な詳細の 1 つは、合計が偶数の場合に二重カウントを回避することです。 常に下限値と上限値の両方を追加すると、2 つの値が等しいため、誤って遷移が重複してしまいます。 

Python の整数は大きな値を自動的に処理しますが、カウントが指数関数的に増加する可能性があるため、これは重要です。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve():
        s = input().strip()
        a = list(map(int, s))
        n = len(a)

        dp = [1] * 10

        for i in range(1, n):
            ndp = [0] * 10

            for prev in range(10):
                total = prev + a[i]

                if total % 2 == 0:
                    ndp[total // 2] += dp[prev]
                else:

            dp = ndp

        ans = sum(dp)

        if all(x == a[0] for x in a):
            ans -= 1

        return str(ans)

    return solve()

 ## 特殊なケース

 次の入力を考えてみましょう。```
0
```最初はすべての最初の数字が有効であるため、次のようになります。`10`生成された数値。 元の番号から`"0"`それ自体がその中にあるので、1 を引きます。 

アルゴリズムは以下を計算します。 

| ステップ | 値 |
 | --- | --- |
 | 初期合計 | 10 |
 | 自己番号が存在します | はい |
 | 最終的な答え | 9 |

 次に、次のことを考えてみましょう。```
2222
```すべての合計が偶数であるため、すべての遷移は強制的に行われます。 

最初の桁が`2`、シーケンスは正確に残ります`"2222"`。 他の開始桁も、一意の決定的なシーケンスを生成します。 

DP は分岐しないため、合計は残ります`10`。 元の数値は構成可能であるため、1 を引いて次の値が得られます。`9`。 

最後に、以下を調べます。```
11
```前の桁から`0`、平均すると`1`与える`0.5`、どちらかに丸めることができます`0`または`1`。 

前の桁から`1`、平均すると`1`正確に与える`1`。 

アルゴリズムは、合計のパリティをチェックすることで、これらのケースを正しく区別します。 偶数の合計では 1 つの遷移が作成され、奇数の合計では 2 つの遷移が作成されます。
