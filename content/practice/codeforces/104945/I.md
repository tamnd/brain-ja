 ## 解決策
 ## 問題の理解

 各プレイヤーは複数の独立したサイコロを振り、最終的なスコアはサイコロで示されたすべての額面の合計になります。 すべてのサイコロは公平ですが、異なるサイコロは面の数が異なる場合があるため、各サイコロは異なる範囲の均一な整数に寄与します。 

両方の合計の完全な確率分布を単純な方法で計算するように求められるわけではありません。 代わりに、アリスの合計がボブの合計よりも厳密に大きい確率と、ボブの合計がアリスの合計よりも厳密に大きいという 2 つの確率を比較する必要があります。 同点はどちらにも貢献しません。 

入力により、サイコロ サイズの 2 つのマルチセットが得られます。 アリスのサイコロは、各値が 1 つのサイコロの面の数である配列で記述され、ボブのサイコロも同様に記述されます。 課題は、どのプレイヤーがより大きな金額を獲得する可能性が高いかを判断することです。 

この制約により、直接の確率的畳み込みが即座に除外されます。 各プレイヤーは最大 100,000 個のサイコロを持つことができ、各サイコロは最大 10^9 の面を持つことができます。 単一の分布を正確に計算することさえ不可能であり、合計の範囲が膨大で不均一であるため、合計に対する動的計画法さえも実行不可能です。 

さらに微妙な問題は、分布が大きいだけでなく、一様な変数が不規則に混合していることです。 単純なアプローチでは、正規近似または平均比較を想定する可能性がありますが、順序付け確率は期待値だけでなく完全な分布形状に依存するため、それは正しくありません。 

重要なエッジケースは、一方のプレイヤーが他方よりも厳密に多くの最低保証額を持っている場合です。 たとえば、アリスが 8 つの 4 面サイコロを持ち、ボブが 1 つの 6 面サイコロを持っている場合、アリスの最小合計は 8 ですが、ボブの最大合計は 6 となり、答えは決定的になります。 極端な限界を無視する確率的推論は、ここでは失敗します。 

両方のプレーヤーが同じマルチセットを持っている場合、別の失敗ケースが発生します。 両方の分布が同一であるため、確率は正確に等しい必要がありますが、実装が対称的でない場合、単純な並べ替えや非対称処理では依然として偏った結果が生成される可能性があります。 

## アプローチ

 ブルートフォース手法では、サイコロの分布を繰り返し畳み込むことで、各プレイヤーの合計の完全な分布を計算しようとします。 単一のサイコロの場合、分布は側面全体で均一であり、k 個のサイコロを処理した後、すべての可能な合計に対する確率配列を維持します。 しかし、サイコロを少しでも追加すると、可能な合計の数は急速に増加し、多数のサイコロを追加すると、サイコロの数が指数関数的に増加します。 最大 100,000 個のサイコロを使用すると、これは時間的にも記憶力的にも完全に不可能です。 

重要な洞察は、正確な分布の観点から考えるのをやめ、代わりにサイコロの出目のペアごとの比較について推論することです。 2 つの合計を比較すると、それぞれの結果は、アリス側のすべてのダイスから 1 つの面を選択することと、ボブ側のすべてのダイスから 1 つの面を選択することに対応します。 比較は、アリスのサイコロとボブのサイコロの間で考えられるすべてのペアごとの相互作用のマルチセットのみに依存します。 

これは単純化につながります。合計を追跡する代わりに、個々のダイが優位性にどのように寄与するかを考えることができます。 面の数が多いサイコロはより高い値を生成する可能性が高くなりますが、その効果は面の数に比例しません。 ただし、重要な構造上の観察は、結果がサイコロのサイズの相対的な順序にのみ依存し、絶対的な大きさには依存しないということです。 

両方の配列をソートすると、そのプロセスを単調な構造で寄与を比較するものとして解釈できます。つまり、大きい面のサイコロは体系的に確率の質量を上方にシフトします。 この比較は、各プレイヤーが異なるスケールでどれだけの「強い」ダイスを持っているかのバランスに帰着します。 これを捉える正しい方法は、両方のソート済みリストを処理し、しきい値を超えて質量がどのようにシフトするかをシミュレートし、累積的な利点を効果的に追跡することです。

これにより、問題はソートされた配列に対する線形スキャンに変わり、各スケールでアリスとボブのどちらがより「有効な強さ」を持っているかを反映する実行バランスが維持されます。

 ## アルゴリズムのチュートリアル

 1. アリスのサイコロのサイズを降順でない順に並べ替え、ボブにも同じことを行います。 サイコロの貢献度を比較する場合、サイコロ サイズの相対的な順序のみが重要となるため、並べ替えが必要です。 
2. 2 つのポインタを初期化し、1 つはアリスの最大の残りダイス用、もう 1 つはボブの最大の残りダイス用で、バランス変数をゼロに設定します。 このバランスは、現在どちらの側がより強力な残りのハイエンドの貢献を持っているかを表します。 
3. どちらかのプレイヤーにサイコロがまだ残っている間、これを繰り返します。 各ステップで、現在残っている最大のサイコロを比較します。 
4. アリスの現在の最大のサイコロがボブのサイコロよりも大きい場合、これをアリスがこのスケールで有利になったと扱い、アリスのポインタをデクリメントします。 残高を上方更新します。 
5. ボブの現在の最大のサイコロの方が大きい場合、ボブは対応する利点を獲得し、ボブのポインタをデクリメントしてバランスを下方に更新します。 
6. それらが等しい場合、同じスケールで対称的に寄与し、バランスを変更せずに両方のポインタを移動するため、両方が一緒に消費されます。 
7. すべてのサイコロを処理した後、最終残高の符号によって答えが決まります。正はアリスが全体的に有利であることを示し、負はボブが有利であることを示し、ゼロは支配構造が完全に同点であることを示します。 

### なぜ効果があるのか

 合計の比較は、結果の積空間全体で一対の比較において、アリスのサイコロがボブのサイコロをどれだけ上回ることができるかによってのみ決まります。 並べ替えでは、サイコロを強さ別に並べて、最上位レベルでのすべての決定が最も影響力のある残りの比較を反映するようにします。 このプロセスは単調不変条件を維持します。つまり、すべてのステップで、未処理のサイコロはすべて、処理済みのサイコロよりも強くないため、利用可能な最大のサイコロを正しく解決することで、確率質量がシフトする方向が決まります。 これにより、その後のペアリングによって蓄積された優勢サインが覆されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))
    
    A.sort()
    B.sort()
    
    i = m - 1
    j = n - 1
    
    balance = 0
    
    while i >= 0 or j >= 0:
        if j < 0 or (i >= 0 and A[i] > B[j]):
            balance += 1
            i -= 1
        elif i < 0 or (j >= 0 and B[j] > A[i]):
            balance -= 1
            j -= 1
        else:
            i -= 1
            j -= 1
    
    if balance > 0:
        print("ALICE")
    elif balance < 0:
        print("BOB")
    else:
        print("TIED")

if __name__ == "__main__":
    solve()
```この実装は、最大のサイコロが常に最初に比較されるように、両方の配列をソートすることに依存しています。 2 ポインター スキャンにより、より小さいダイスに移動する前に、最も重要な残りの寄与が常に処理されるようになります。 バランス変数は、すべての比較にわたって蓄積された純利益をエンコードし、最終的な符号によ​​って勝者が決まります。 

同じダイスが互いに完全に無力化する必要があるため、大文字と小文字が等しい分岐は重要です。 このケースがないと、マルチセットが重なったときにアルゴリズムが誤って一方の側に偏ってしまいます。

        B.sort()

                balance -= 1
                j -= 1
            else:
                i -= 1
                j -= 1

    return solve()

 ## 特殊なケース

 両方のプレーヤーが同一のダイス マルチセットを持っている場合、アルゴリズムは 2 ポインター スキャン中に同じ要素を繰り返し照合します。 一致するたびに均等分岐がトリガーされ、バランスを変えることなく両方の要素が削除されます。 最終結果はゼロとなり、要求どおりに TIED が生成されます。 

1 人のプレイヤーが相手のすべてのダイスよりも厳密に強い最大ダイスを持っている場合、ループは常に強い側から最初に消費されます。 各反復により、すべてのダイスが使い果たされるまで一方向にバランスが一貫して増加し、決定論的な優位性が一致します。 

配列の分布がわずかに異なっているだけで、順序が異なっていない場合、並べ替えにより、比較の結果が常に最も強いものと最も強いものとが一致することが保証されます。 これにより、意図した支配構造を歪める可能性のある弱い要素と強い要素の偶発的な組み合わせが防止されます。
