 ## 解決策
 ## 問題の理解

 各料理には、味スコアと盛り付けスコアという 2 つの属性があります。 各人には 2 つの好みがあり、同じ 2 つの属性の重みとして機能します。 人は料理の味と盛り付けの値を自分の重みで重み付けして料理を評価します。 課題は、すべての人にとって、どの料理がこの評価を最大化するかを決定することです。 複数のディッシュが同じ最高値を達成する場合、最小のインデックスを持つディッシュを選択する必要があります。 

直接読み取ると、すべての人がすべての料理を潜在的に評価することがわかり、スコア関数は 2 つの変数の単純な線形表現です。 これにより、直ちに問題が幾何学設定に配置されます。各皿は平面内の点であり、各人は最大の内積を取得して、すべての点を投影する方向を定義します。 

制約は大きく、料理数は 500,000 人、人数は 500,000 人までです。 すべての料理と人物のペアを検査するアプローチでは、約 2.5 × 10^11 の評価が必要になりますが、これは実現可能な限界をはるかに超えています。 すべての料理を 1 人ずつリニア スキャンしても遅すぎます。 

重要な点は、料理と人物の両方が同じ 2 次元空間に存在し、評価がドット積であることです。 この構造により、強引な比較ではなく幾何学的最適化が可能になります。 

いくつかの特殊なケースでは注意が必要です。 まず、タイは最小のインデックスによって解決される必要があるため、最大値のみを追跡するソリューションではインデックスの順序も維持する必要があります。 

第二に、退化した方向性が重要です。 人の重みが (0, P) の場合、重要なのはメッキだけです。 (T, 0) についても同様です。 幾何学的変換では、両方の座標が厳密に正であると仮定してはなりません。 

第三に、浮動小数点の傾きに正規化しようとすると、精度の落とし穴が発生します。 比較は整数演算で正確に行う必要があります。 

## アプローチ

 ブルートフォース ソリューションは、すべての人の料理をすべて評価します。 重み (T, P) を持つ人 l の場合、すべての k に対して T・t_k + P・p_k を計算し、最大値を取得します。 これは定義を直接実装しているため、これは正しいです。 ただし、コストは O(NM) で、最悪の場合 2.5 × 10^11 回の乗算と加算となり、使用できなくなります。 

重要な観察は、各料理が点 (t_k, p_k) であり、各人がこれらの点に関する線形関数を定義しているということです。 問題は、2D 点の静的なセットに対する多くの最大内積クエリに答えることに帰着します。 これは古典的な幾何学的クエリの問題であり、点の凸包を前処理することで効率的な最大射影クエリが可能になります。 

重要な洞察は、任意の固定方向 (T、P) について、一連の点にわたる Tt + Pp の最大値が凸包の極点で発生するということです。 内部点は境界点の凸状の組み合わせであるため、最適になることはあり得ません。したがって、どの直線方向においてもハルの頂点によって達成される最大値を超えることはできません。 

したがって、最初にすべての皿点の凸包を計算します。 x 座標でポイントをソートし、上部ハルと下部ハルを構築した後、最適な可能性のあるすべての皿を表す多角形を取得します。 次に、各クエリは、指定された方向ベクトルとの内積を最大化するこの凸多角形の頂点を見つけることに帰着します。 凸多角形の内積は巡回順序で頂点に沿って単峰性であるため、順序に応じて三分探索または回転ポインタ アプローチを使用してクエリを事前計算して答えることができます。 

高速なクエリをサポートするには、凸多角形の頂点に対する三分探索を使用して、O(N log N) でハルを事前計算し、O(log H) で各クエリに答えることができます。ここで、H はハルのサイズです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM) | お(1) | 遅すぎる |
 | 凸包 + クエリ検索 | O(N log N + M log N) | O(N) | 承認済み |

## アルゴリズムのチュートリアル

 ## ステップ 1: 料理を点として表現する

 各皿 k は 2D 空間内の点 (t_k, p_k) として表されます。 これは、評価をクエリ ベクトルとのドット積の計算として再構成します。 

## ステップ 2: 皿点の凸包を計算する

 すべてのポイントを辞書順に並べ替え、単調スタックを使用して下部ハルと上部ハルを構築します。 凸形状の内側にある点は破棄されます。 

このステップは正しいです。なぜなら、線形対物レンズは極点で凸セットを超えて最大値を達成するからです。 内部の点が全方向に優勢になることはありません。 

## ステップ 3: 循環クエリ用にハルを準備する

 ハルの頂点を順番に保存して、凸多角形を形成します。 順序が一貫していることを確認してください (時計回りまたは反時計回り)。 

## ステップ 4: 各人物を方向クエリとして処理する

 重み (T、P) を持つ各人物について、これを方向ベクトルとして解釈します。 T・x + P・y を最大化する船体の頂点を見つけなければなりません。 

## ステップ 5: 凸多角形に対して三項検索を使用する

 凸多角形の内積は頂点に沿って単峰性であるため、ハル インデックスに三分探索を適用します。 各中間点の比較で、内積を評価し、悪い方を破棄します。 

タイブレークは、ドット積が等しい場合にインデックスを比較することによって処理されます。 

## ステップ 6: 結果を出力する

 最適な船体の頂点に対応する皿のインデックスを返します。 

### なぜ効果があるのか

 凸包には、他の点の凸組み合わせとして表現できない点が正確に含まれます。 目的関数は線形であるため、あらゆる内部点は常に、あらゆる方向において何らかの境界点によって支配されます。 凸多角形上の線形関数の最大値は頂点で発生する必要があります。 したがって、探索空間をハルの頂点に制限すると、正確さが保たれます。 ハルの境界に沿った内積の単峰性により、三分探索で局所的最大値を見逃さずに全体的最大値を正しく見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def dot(p, q):
    return p[0] * q[0] + p[1] * q[1]

def convex_hull(points):
    points.sort()
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def best_vertex(hull, v):
    n = len(hull)
    l, r = 0, n - 1

    def f(i):
        return dot(hull[i], v)

    while r - l > 3:
        m1 = l + (r - l) // 3
        m2 = r - (r - l) // 3
        if f(m1) < f(m2):
            l = m1
        else:
            r = m2

    best = l
    for i in range(l, r + 1):
        if f(i) > f(best) or (f(i) == f(best) and hull[i][2] < hull[best][2]):
            best = i
    return hull[best][2]

def main():
    N, M = map(int, input().split())
    points = []
    for i in range(N):
        t, p = map(int, input().split())
        points.append((t, p, i + 1))

    hull = convex_hull(points)

    for _ in range(M):
        T, P = map(int, input().split())
        print(best_vertex(hull, (T, P)))

if __name__ == "__main__":
    main()
```実装は、標準のモノトーン チェーン法を使用して凸包を計算することから始まります。 各ポイントは元のインデックスを保持するため、曖昧さなくタイブレークを処理できます。 

クエリ関数は、ハルに対して三項検索を実行します。 目的関数は、クエリ ベクトルとのドット積として評価されます。 最後のいくつかの候補に対する最終的な線形スキャンにより、三項検索の絞り込みが停止する短い間隔での正確性が保証されます。 

微妙な点はタイブレークルールです。 2 つのディッシュが同じスコアを生成する場合、インデックスが最小のものを選択する必要があるため、実装ではドット積が一致する場合に元のインデックスを比較します。

 ## 特殊なケース

 重要なエッジケースは、すべての皿が平面内の単一の直線上にある場合に発生します。 その状況では、すべての点が凸包の一部となり、アルゴリズムはすべての頂点をスキャンすることになります。 直線に沿ったクエリ方向の場合、複数の点が結ばれる場合があります。 実装では、元のインデックスを追跡し、最小のものを選択することでこの問題を解決し、確定的な出力を保証します。 

もう 1 つのエッジ ケースは、人の重みベクトルが (T, 0) などの 1 つの軸と正確に一致する場合です。 その場合、内積は t_k のみに依存し、最適な料理は単純に最大の味覚スコアを持つ料理になります。 凸包にはすべての候補が含まれており、三分探索では極端な x 値が存在するエンドポイントが正しく評価されます。 

最後のケースには、隣接しないハル頂点間で最適値が重複することが含まれます。 三分探索は、複数の等しい候補を含む短い間隔で停止する場合がありますが、その間隔にわたる最後の線形スキャンにより、すべてがチェックされ、最小のインデックスが選択されることが保証されます。
