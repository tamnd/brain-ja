 ## 解決策
 ## 問題の理解

 各国は 2 つの方法のいずれかで表すことができます。 アリスは、その国の国旗に表示されるすべての色を購入する必要がある完全な国旗の描画を準備するか、その国旗を完全に描くことを避け、その代わりにその国用の 1 つのピンを使用します。 

各色には単価があり、一度色を購入すれば、それを必要とするすべての国で使用できます。 ピンにも単価がありますが、単価は国ごとであるため、国旗をスキップすると、複数の色の購入が 1 つの固定コストに置き換えられます。 

入力により、国ごとに、その国旗を描画するために必要な色のリストが得られます。 ある色は多くの国で販売されている可能性があり、それを購入することを選択すると、すべての国で同時にメリットが得られます。 

課題は、購入する色のサブセットを選択し、それらの色を使用して国旗を描くか、ピンに置き換えるかを決定して総コストを最小限に抑えることです。 

重要な決定はグローバルです。色を選択すると複数の国が同時に役立ちますが、選択した色で完全にカバーされていない国はピンを支払う必要があります。 このように国を超えて結びついていることが、問題を重要なものにしているのです。 

制約は構造に関する明確なヒントを与えます。 色の数 M は最大 100 なので、色のサブセットを推論するアルゴリズムは O(2^M) スタイルまたは O(M * something) で妥当です。 国の数 N は最大 1000 であるため、国ごとに指数関数的な作業を行う余裕はありませんが、州ごとに M または M log M に比例する操作を行う余裕はあります。 

素朴な考えは、色のすべてのサブセットを考慮し、どの国が完全にカバーされているかを計算し、選択した色の数とカバーされていない国の数を加算したコストを計算することです。 これはすでに正しい構造に近づいていますが、最適化を行わないと、コストのかかるチェックを繰り返す危険があります。 

国が単一の色を使用している場合、微妙な特殊なケースが 1 つ発生します。 よく使われる色を欲張って選ぶと、すべての国を安価にカバーできると思いがちですが、実際には、頻繁に使用される色を選択しても、複数の色が必要な国全体をカバーできない可能性があります。 たとえば、ある国が色 {1, 2} を必要とする場合、色 1 だけを購入してもその国には何の役にも立たないため、やはり固定する必要があります。 

もう 1 つの特殊なケースは、すべての国が単一の共通の色を共有する場合です。 単純に貪欲なアプローチでは、不必要に複数の色を購入する可能性がありますが、最適な解決策は、単純にその 1 色を購入し、必要に応じて残りを固定することです。 

## アプローチ

 この決定は次のように言い換えることができます。購入する色のセットを選択します。 この選択されたセット内にすべての色があるすべての国は「描画によってサポートされ」ており、他のすべての国はピンで置き換える必要があります。 

色のサブセット S を修正すると、総コストは |S| になります。 S に完全には含まれていない国の数を加えたものです。 

ブルートフォースアプローチは、色のすべてのサブセットに対して反復されます。 サブセットごとに、すべての国をチェックし、必要な色がすべてサブセットに存在するかどうかを確認します。 各国には最大 M 色が存在する可能性があるため、このチェックは最悪の場合 O(NM) になります。 2^M のサブセットでは、M = 100 の場合、これは完全に不可能になります。 

重要な観察は、構造化されていない方法でサブセットを明示的に列挙する必要がないということです。 代わりに、色を一度に 1 つずつ処理し、州ごとにまだ「違反」している国の数、つまり必要な色が少なくとも 1 つまだ選択されていない国を維持することで、ソリューションを段階的に構築できます。 

これは、色に対する動的プログラミングの定式化を示唆しています。 色ごとに入れるか入れないかを決めております。 国家は、各国ごとに、必要な色がまだ何色不足しているかを把握する必要があります。 ただし、国ごとに完全な数を追跡すると膨大になります。

この単純化は、国は二値的な意味でのみ重要である、つまりすべての色が選択されているかどうかのどちらかであることに気づくことから来ています。 どの国がすでに完全に満足しているかを州ごとに表すことができます。 N は 1000 であるため、依然として完全なビットマスクを国全体に保存することはできません。 代わりに、視点を逆転させます。 

「描く」ことにした場合、各国でまだ不足している色が何色あるかを追跡します。 ある国に k 個の色がある場合、k 個の欠損値から開始し、色を選択するたびに、その色を含むすべての国の欠損数を減らします。 欠落カウントがゼロになると、国は描画可能になります。 

これは単純に行うとまだ大きすぎますが、実際に状態ごとの配列を保存する必要はありません。 代わりに、ビットマスク DP を使用して色のサブセットの状態を処理しますが、事前に計算されたメンバーシップ リストを使用して遷移を圧縮します。 

M ≤ 100 であるため、各色を独立した決定として扱い、増分更新を使用してサブセット全体の DP を暗黙的に維持しながら、コスト寄与をオンザフライで計算できます。 

重要な構造上の洞察は、色のサブセットごとに、選択した色の組み合わせが各国のセットを完全にカバーしているかどうかを確認することによって、サポートされる国の数が完全に決定されるということです。 各国のセットは小さいため、事前に保存し、ビットセットまたはソートされた配列を使用して効率的に包含をチェックできます。 

これにより、国ごとに事前に計算されたビット表現を使用して色のすべてのサブセットを効率的に評価するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全チェックによるサブセットに対するブルート フォース | O(2^M・N・M) | O(NM) | 遅すぎる |
 | ビットマスク DP / ビットセットによるサブセット列挙 | O(2^M · N / ワードサイズ) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各国で必要な色をサイズ M のビットマスクとして表します。これにより、要素ごとのループではなく、高速なビット操作を使用して包含をテストできます。 
2. すべての国のマスクを一度事前計算します。 各マスクは整数 (または Python ビットセット) で、ビット j はその国で色 j が必要であることを示します。 
3. 0 ～ 2^M − 1 の整数を使用して、色のすべてのサブセットを列挙します。各サブセットは、アリスが購入することを選択した色のセットを表します。 
4. 各サブセットについて、そのコストをセット ビット (購入した色) の数として計算します。 
5. 国ごとに、必要なマスクがサブセットに完全に含まれているかどうかを確認します。 これは、(country_mask & subset) == country_mask の場合に当てはまります。 
6. 満足していない国の数を数えてください。 ピンを使用するため、満足していない各国はコスト 1 を負担します。 
7. すべてのサブセットにわたる最小値を追跡します。 

### なぜ効果があるのか

 すべての有効な戦略は、色のサブセット、つまり私たちが購入することを選択する色に一意に対応します。 そのセットが固定されると、すべての色が含まれているかどうかに応じて、各国が描画可能かどうかが個別に決定されます。 コストの計算式は、サブセットのサイズと対象外の国ごとのペナルティという、独立した拠出金の合計にきれいに分解されます。 すべてのサブセットが 1 回だけ評価され、すべての可能な決定セットが表現されるため、すべてのサブセットの最小値が最適な戦略と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def popcount(x):
    return x.bit_count()

def solve():
    n, m = map(int, input().split())
    
    country_masks = []
    
    for _ in range(n):
        k = int(input())
        colors = list(map(int, input().split()))
        mask = 0
        for c in colors:
            mask |= 1 << (c - 1)
        country_masks.append(mask)

    full = (1 << m)

    ans = n  # worst case: pin every country

    for subset in range(full):
        cost_colors = subset.bit_count()
        pins = 0

        for cm in country_masks:
            if (cm & subset) != cm:
                pins += 1

        ans = min(ans, cost_colors + pins)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、各国を M 色のビットマスクとしてエンコードします。 これにより、カラー リストをスキャンする代わりに、サブセットの包含チェックが定数時間のビット操作で行われるようになります。 

メイン ループは、色のすべてのサブセットを反復します。 サブセットごとに、色の購入コストは次のように計算されます。`bit_count()`、その後、単一のビットごとの AND 比較を使用して、各国の完全性がチェックされます。 

最初の答えは N に設定されます。これは、色を購入せず、すべての国に対してピンを使用することに対応します。 

微妙な点は、代表のシフトです。どの国がカバーされているかを追跡する代わりに、条件付きでカバー範囲を直接テストします。 これにより、サブセット間で動的状態を維持することが回避されます。

 ## 特殊なケース

 1 つの国に単一の色が含まれる最小限のケースでは、アルゴリズムが色の購入とピンの使用の両方を正しく評価していることがわかります。 N = 1 で国の色が {2} である入力の場合、サブセット列挙には空のセットと {2} の両方が含まれます。 空集合はコスト 1 (ピン) を与え、{2} はコスト 1 (1 色) を与えるため、答えは 1 です。 

すべての国が共通の色を共有するケースは、サブセットの評価が必要な理由を示しています。 すべての国に色 1 が含まれている場合、サブセット {1} はコスト 1 + 0 ピン = 1 を生成しますが、1 を含まないサブセットは N ピンになります。 このアルゴリズムは、その共有色を含むサブセットを明示的に評価するため、グローバル最小値を正確に見つけます。 

色の重複が存在しない完全に独立した国の場合、解決策はピンを優先することになります。 任意の色をカバーする各サブセットは、せいぜい 1 つの国にしか利益をもたらしません。色を購入しても複数の国で償却されない場合、列挙は最適なものとして N を正しく返します。
