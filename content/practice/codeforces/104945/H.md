 ## 解決策
 ## 問題の理解

 単純な自己交差しない多角形の頂点が順番に与えられます。 これは、質量がその領域全体に均一に分布している硬くて平らなテーブルトップと考えてください。 基本的なジオメトリから、このような形状には明確に定義された重心、つまりポリゴンの内側のどこかに位置するポリゴンの重心があります。 

3 本の脚を配置するには、この多角形の 3 つの異なる頂点を選択する必要があります。 テーブルは、重心がこれらの選択された 3 つの頂点によって形成される三角形の内側に厳密に存在する場合にのみ安定します。 この条件を満たす、順序付けされていない頂点のトリプルがいくつあるかを数えるように求められます。 

したがって、中心的なタスクはポリゴンのエッジに直接関わるものではなくなりました。 多角形は、単一の固定点、つまり重心を定義するためにのみ使用されます。 その後、指定された頂点セットによって形成される三角形の内部にその点が含まれる数を数えます。 

入力サイズは最大 100,000 頂点までです。 すべてのトリプルを直接検査するアプローチでは、次のオーダーが必要になります。$10^{15}$チェックしますが、これは完全に不可能です。 ペアを調べて 3 番目の頂点を推測しようとする 2 次アプローチでも困難を伴うでしょう。$N^2$は$10^{10}$、すでに 1 秒の制限には大きすぎます。 

これにより、三角形の包含クエリを重心の周りの構造化された順序付け問題に還元する幾何学的カウント方法が推進されます。 

重要な点は、重心が頂点ではなく、直接指定されないことです。 ポリゴンから計算する必要があります。 頂点の単純な算術平均を使用するのは間違いです。 正しい重心はポリゴンの符号付き面積に依存するため、標準の靴紐の公式を使用して計算する必要があります。 

素朴な推論による失敗例の 1 つは、「大きく見える」三角形に重心が含まれていると仮定することです。 たとえば、正方形の場合:```
(0,0), (1,0), (1,1), (0,1)
```重心は (0.5, 0.5) です。 3 つの頂点で形成されるすべての三角形には 1 つの角が欠けており、この構成では実際にはそのような三角形の中心が除外され、答えは 0 になります。「ほとんどの三角形には中心が含まれている」などの単純なヒューリスティックは、ここでは失敗します。 

もう 1 つの微妙なケースは、対称性または凸性が必要であると仮定することです。 ポリゴンは非凸であっても構いませんが、重心はポリゴンの内部に残り、ポリゴン構造ではなくポイントの位置のみに依存するため、同じカウント ロジックが引き続き適用されます。 

## アプローチ

 ブルートフォース手法は簡単です。 重心を計算し、頂点のトリプルごとに繰り返し、重心が三角形の内側にあるかどうかをテストします。 標準的な方向テストまたは重心符号チェックは、三角形ごとに一定時間で機能します。 これは正しいですが、検討が必要です$\binom{N}{3}$トリプル、つまり約$1.6 \times 10^{15}$操作時の操作$N = 10^5$。 これは実際的な限界をはるかに超えています。 

重要な観察は、問題は固定点が点のサブセットによって形成される三角形の内側にあるかどうかのみに依存するということです。 これは古典的な幾何学的な縮小です。三角形を直接チェックする代わりに、重心の周りの角度で条件を言い換えることができます。 

重心が原点になるように座標系を移動すると、すべての頂点はその点からのベクトルになります。 3 つの点のすべてが原点を通る閉じた半平面に含まれていない場合に限り、三角形には原点が含まれます。 同様に、原点の周りの極角によって点を並べ替える場合、すべての頂点が最大でも角度の長さの半円内にある場合、三角形は原点を正確に含むことができません。$\pi$。 

これにより、問題は循環順序計算問題に変わります。 2D 面積用語で推論する代わりに、角度の円に基づいて推論し、半円に含まれないトリプルの数を数えます。 これは必要なものの補数なので、合計トリプルを計算し、悪いものを差し引きます。

 ## アルゴリズムのチュートリアル

 1. 標準の符号付き面積公式を使用して、多角形の重心を計算します。 これにより固定点が得られます$C$すべての幾何学的比較の基準として機能する多角形の内部。 
2. すべての頂点を次のように移動します。$C$が原点となります。 各点は重心からのベクトルとして扱われるようになりました。 
3. 各ベクトルを極角に変換します。$[0, 2\pi)$。 これにより、幾何学的包含が循環順序推論に変換されます。 
4. すべてのポイントを角度ごとに並べ替えます。 次に、角度を 1 だけ増やして各点を再度追加して配列を複製します。$2\pi$。 これにより、円形のラップアラウンド間隔を線形セグメントとして処理できるようになります。 
5. 各ポイントについて$i$、最も遠いインデックスを見つけます$j$間の角度差が$i$そして$j$厳密に以下です$\pi$。 これは、次から始まる最大の半円を定義します。$i$。 
6. しましょう$k$この半円内の点の数になります。$i$。 この中から選んだペア$k$ポイントと一緒に$i$原点を含まない三角形を形成します。 
7.合計$\binom{k}{2}$全体$i$。 これは、すべての「悪い」三角形を最小角度の端点に固定することによって、正確に 1 回カウントします。 
8. トリプルの総数から不良トライアングルの数を減算します。$\binom{N}{3}$。 余りは重心を含む三角形の数です。 

これが機能する理由は、すべての頂点が原点を通る開いた半平面に収まる場合にのみ、三角形が原点を含むことができないためです。 このような半平面は、角度の半円に正確に対応します。 すべての不良三角形には、それを覆う固有の最小半円があり、開始点をスイープすることで、そのような各構成が 1 回だけキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def polygon_centroid(points):
    # returns (Cx, Cy)
    area = 0
    cx = 0
    cy = 0
    n = len(points)
    for i in range(n):
        x1, y1 = points[i]
        x2, y2 = points[(i + 1) % n]
        cross = x1 * y2 - x2 * y1
        area += cross
        cx += (x1 + x2) * cross
        cy += (y1 + y2) * cross

    area *= 0.5
    cx /= (6 * area)
    cy /= (6 * area)
    return cx, cy

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    cx, cy = polygon_centroid(pts)

    import math

    ang = []
    for x, y in pts:
        ang.append(math.atan2(y - cy, x - cx))

    ang.sort()

    # duplicate with +2pi shift
    m = len(ang)
    twopi = 2 * math.pi
    ext = ang + [a + twopi for a in ang]

    j = 0
    bad = 0

    for i in range(m):
        if j < i + 1:
            j = i + 1
        while j < i + m and ext[j] - ext[i] < math.pi:
            j += 1
        k = j - i - 1
        if k >= 2:
            bad += k * (k - 1) // 2

    total = n * (n - 1) * (n - 2) // 6
    print(total - bad)

if __name__ == "__main__":
    solve()
```重心の計算では、靴紐メソッドの符号付き面積公式を使用します。これにより、頂点を個別に処理するのではなく、ポリゴン ジオメトリが正しく考慮されます。 座標の直接平均は、不均一な形状では失敗します。 

The angular transformation uses`atan2`これは、符号を含む完全な循環順序を維持するために不可欠です。 これらの角度を並べ替えると、重心の周りの一貫したトラバースが生成されます。 

複製された配列に対する 2 ポインタのスイープでは、半円内の点のウィンドウが維持されます。 不変条件は、各開始インデックスに対するものです。`i`、セグメント`[i+1, j)`以下の範囲内に正確にそれらのポイントが含まれています$\pi$からのラジアン`i`。 これにより、アンカーされているすべての無効なトリプルをカウントできるようになります。`i`インデックスごとの一定の償却時間で。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての点が重心の周りにほぼ均等に位置する場合です。 このような場合、多くの半円ウィンドウにはほぼすべての点が含まれており、角度配列の複製に失敗した単純な実装ではラップアラウンド三角形を見逃してしまいます。 複製角度技術により、ウィンドウが角度を横切ることが保証されます。$2\pi$境界は引き続き連続したセグメントとして表されます。 

もう 1 つの微妙なケースは、角度比較における数値精度です。 違いを比較するので、$\pi$、浮動小数点エラーにより、境界点が誤って分類される可能性があります。 堅牢な実装は、厳密な不平等と一貫性に依存します。`atan2`注文する。 必要に応じてイプシロンを使用すると比較を安定させることができますが、一般的な制約では Python の倍精度で十分です。 

最後のエッジ ケースは、ポリゴンが大きく凹んでいる場合に発生します。 重心はまだ内側にありますが、頂点が小さな角度領域に集中している可能性があります。 スイープ方法は、ポリゴンの隣接性や凸性ではなく、単一の固定点に対する角度のみに依存するため、引き続き機能します。そのため、ポリゴンの構造は正確さに影響しません。
