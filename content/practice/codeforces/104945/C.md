 ## 解決策
 ## 問題の理解

 地下鉄路線のコレクションが与えられており、各路線は最大 18 サイズの固定世界の駅のサブセットとして見ることができます。路線は、どの駅に停車するかによって完全に説明されます。 

1 つの路線が一様にランダムに選択され、タスクは「未知の路線は駅 i に止まりますか?」という形式のはい/いいえの質問をして、その路線を特定することです。 各回答は、残りの候補線を、駅 i を含む線と含まない線に分割します。 

私たちは、常に最終的に行を一意に識別する最適な質問戦略を設計することが求められており、そのようなすべての戦略の中で、行全体に一様に分布した状態で予想される質問の数を最小限に抑えたいと考えています。 

戦略は、二分決定木の構築に相当します。 各内部ノードはステーションをクエリし、各エッジは「はい」または「いいえ」に対応し、可能なラインのセットを制限します。 リーフのコストはその深さであり、すべてのラインにわたる平均リーフの深さを最小限に抑えます。 

制約は非常に特殊な点で厳しいです。 ステーションの数は最大 18 です。これは、すべてのラインを 18 ビット マスクとしてエンコードできることを意味します。 行数は最大 50 であるため、比較的小さなオブジェクトのセットを操作しますが、決定プロセスは指数関数的に分岐する可能性があります。 この組み合わせは、行のサブセットに対する動的プログラミング ソリューションを強く示唆しています。これは、バイナリ機能の小さなセットを使用してアイテムの小さなコレクションを分離するあらゆる方法を最適化しているためです。 

重要な実現可能条件は一意性です。 2 つの路線にまったく同じ一連の駅がある場合、考えられるすべての質問がそれらに対して同じ答えを生成するため、それらを区別することはできません。 その場合、即答は不可能です。 

複数の回線が異なる場合に、効果的にクエリが実行されないステーションのみで、微妙な障害が発生するケースが発生します。 単純な貪欲な分割では、1 つのラインを簡単にすぐに分離できますが、非常に不均衡な残りのセットが残り、次善の期待深さが生成されます。 これが、ローカル分割ヒューリスティックが確実に機能しない理由です。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての決定木を明示的に構築します。 各ノードで、クエリするステーションを選択し、左右のサブツリーを再帰的に構築します。 行の各サブセットはさまざまな方法で分割でき、異なるクエリ シーケンスによって同じサブセットに到達できるため、可能なツリーの数は膨大になります。 わずか 50 行であっても、決定木の数は天文学的に多く、このアプローチはすぐに失敗します。 

重要な観察は、プロセスの状態は、どのようにしてそこに到達したかではなく、残りの候補線のセットによって完全に決定されるということです。 現在、ラインのサブセット S にいる場合、この時点からの最適な予想コストは S にのみ依存します。これにより、ラインのサブセットに対する動的プログラミングの定式化が自然に得られます。 

任意のサブセット S について、次の質問としてすべてのステーション i を試します。 このクエリは、各路線に駅 i が含まれるかどうかに応じて、S を S0 と S1 に分割します。 ステーション i の選択から予想されるコストは、1 つの質問に、結果として得られる 2 つのサブセットの最適コストの加重平均を加えたものです。 この期待を最小限に抑えるステーションを選択します。 

すべての遷移により不確実性が厳密に低減され、サブセットは最終的にサイズ 1 に達し、それ以上の質問は必要なくなるため、再帰は明確に定義されます。 

難しいのは計算です。行のサブセットは最大 2^50 あり、列挙するには大きすぎます。 ただし、再帰では、完全なセットから開始してステーション クエリを分割することによって実際に到達可能なサブセットのみを訪問します。 実際には、このセットははるかに小さく、サブセット マスクをキーとしたメモ化を使用してキャッシュできます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのデシジョン ツリーを列挙する | 木の指数関数 | 指数 | 遅すぎる |
 | メモ化による行のサブセット上の DP | O(到達可能な状態の数 × N × M) | O(状態の数) | 承認済み |

 ## アルゴリズムのチュートリアル

 各路線を長さ N の整数ビットマスクとして表します。ここで、ビット i は路線が駅 i で停止するかどうかを示します。 

次に、再帰関数 dp(S) を定義します。ここで、S は現在でも可能なライン インデックスのサブセットです。 

1. S に 1 行しか含まれていない場合、それを識別するためにそれ以上の質問は必要ないため、コストはゼロです。 これは再帰の基本ケースです。 
2. S が以前に計算されている場合は、保存されている結果を返します。 これにより、異なるクエリ パスを介して到達した同一の状態の再計算が防止されます。 
3. 現在のセット S について、0 から N − 1 までのすべてのステーション i を質問候補として試します。 これは、未知の路線に駅 i が含まれるかどうかを尋ねることを表します。 
4. 固定局 i の場合、S を 2 つのサブセットに分割します。 1 つはステーション i を含む S 内のすべての路線を含み、もう 1 つはステーション i を含まない路線を含みます。 これらは 2 つの可能な答えに対応します。 
5. いずれかのサブセットが空の場合、このクエリは現在の状態を区別するのに役立たないため、無視されます。 
6. それ以外の場合、ステーション i を選択する場合の予想コストを次のように計算します。 

1 つの質問に、S 内のサイズで重み付けされた 2 つのサブセットの最適コストの加重平均を加えたもの。 
7. すべての有効なステーションの最小値を取得し、それを dp(S) として保存します。 

最終的な答えは dp(全行) で、すべての行がインデックスの完全なセットになります。 

### なぜ効果があるのか

 すべての有効な質問戦略は決定木に対応しており、各ノードはこれまでの回答と一致する一連の線によって正確に定義されます。 同じサブセット S につながる 2 つの異なる履歴は、その時点以降は区別できないため、最適な決定はパスではなく S にのみ依存します。 これにより、動的プログラミングに必要な最適な下部構造が確立されます。 

すべてのクエリはセットを厳密に小さい合計サイズの素のサブセットに分割するため、再帰はシングルトンで終了し、基本ケースの伝播の正確さを保証する必要があります。 このアルゴリズムは、すべての状態で考えられるすべての最初の質問を評価するため、最適な分割が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    N = int(input())
    M = int(input())

    masks = []
    for _ in range(M):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        stations = tmp[1:]
        mask = 0
        for s in stations:
            mask |= 1 << s
        masks.append(mask)

    # check distinguishability
    seen = set(masks)
    if len(seen) != M:
        print("not possible")
        return

    from functools import lru_cache

    full = tuple(range(M))

    @lru_cache(None)
    def dp(state):
        if len(state) <= 1:
            return 0.0

        best = float('inf')

        # try each station
        for i in range(N):
            left = []
            right = []
            for idx in state:
                if masks[idx] & (1 << i):
                    left.append(idx)
                else:
                    right.append(idx)

            if not left or not right:
                continue

            left = tuple(left)
            right = tuple(right)

            pL = len(left) / len(state)
            pR = 1 - pL

            cost = 1 + pL * dp(left) + pR * dp(right)
            if cost < best:
                best = cost

        return best

    ans = dp(full)
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各地下鉄路線を駅全体のビットマスクに圧縮します。 これにより、ビット演算を使用して各クエリを 1 行あたり O(1) で評価できるようになります。 

再帰 DP 関数がコアです。 到達可能なライン インデックスの各サブセットを状態として扱い、すべてのステーションを分割クエリとして試行します。 多くの異なるクエリ シーケンスが同じ残りの候補セットにつながる可能性があるため、メモ化は非常に重要です。 

すべてのラインの可能性が等しく、状態の条件付けによって均一性が維持されるため、確率の重みはサブセット サイズから直接計算されます。 

実装の微妙な詳細は、行のサブセットをタプルとして表現することです。 これにより、キャッシュ用にハッシュ可能になりますが、反復処理も簡単になります。 クエリが成功するたびに曖昧さを軽減する必要があるため、再帰の深さは M によって制限されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(状態 × N × M) | 各状態はすべてのステーションを試行し、状態内のすべての回線をスキャンします。 
| スペース | O(州 × M) | メモ化は、到達可能な行の各サブセットを保存します。 

状態の数はデータに依存しますが、ステーション分割を介して到達可能な個別のサブセットの数によって制限されます。 M が最大 50 であれば、これは意図した制約の下で実行可能です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    N = int(sys.stdin.readline())
    M = int(sys.stdin.readline())
    masks = []
    for _ in range(M):
        tmp = list(map(int, sys.stdin.readline().split()))
        k = tmp[0]
        stations = tmp[1:]
        mask = 0
        for s in stations:
            mask |= 1 << s
        masks.append(mask)

    if len(set(masks)) != M:
        return "not possible"

    from functools import lru_cache

    full = tuple(range(M))

    @lru_cache(None)
    def dp(state):
        if len(state) <= 1:
            return 0.0
        best = float('inf')
        for i in range(N):
            left = tuple(idx for idx in state if masks[idx] & (1 << i))
            right = tuple(idx for idx in state if not (masks[idx] & (1 << i)))
            if not left or not right:
                continue
            pL = len(left) / len(state)
            cost = 1 + pL * dp(left) + (1 - pL) * dp(right)
            best = min(best, cost)
        return best

    return dp(full)

# provided samples
assert abs(run("5\n4\n3 0 3 4\n3 0 2 3\n3 2 3 4\n2 1 2\n") - 2.0) < 1e-6
assert abs(run("3\n3\n1 0\n1 1\n1 2\n") - 1.66666666666667) < 1e-6

# custom cases

assert abs(run("2\n2\n1 0\n1 1\n") - 1.0) < 1e-6
assert abs(run("3\n2\n2 0 1\n1 2\n2 1 2\n") < 5.0)

 ## 特殊なケース

 2 つの回線が同一である場合、すべてのステーションのクエリは同一の応答を生成するため、アルゴリズムは DP が開始される前にそのインスタンスを正しく拒否します。 続行しようとすると、両方の行がすべてのサブセットに永久に保持され、終了できなくなります。 

すべてのラインが 1 つのステーション上で異なる場合、最初のクエリは 1 つのラインを即座に分離し、より小さな独立した副問題を残します。 DP は、重み付けされたサブツリーのコストを最小限に抑え、シングルトンを早期に分離するという最適な直感と一致するため、当然これを好みます。 

多くの回線がほとんどのステーションで同一で、小さなサブセットでのみ異なる場合、単純に貪欲な選択を行うと、初期の分割が過剰適合する傾向があります。 DP は、サブツリー全体にわたる重み付けされた予想コストが改善されない場合、そのような分割を適切に遅らせ、全体的な最適性を維持します。
