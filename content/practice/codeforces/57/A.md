 ## 解決策
 ## 問題の理解

 一辺の長さが _n_ の正方形の周囲にある 2 点間の最短距離を見つけるように求められます。 正方形は軸に沿って配置されているため、その角は (0,0)、(n,0)、(0,n)、および (n,n) にあります。 2 つの点は、内部ではなく端にあることが保証されます。 入力により、正方形のサイズと 2 点の座標が得られます。 出力は単一の整数、つまり内部を通るユークリッド距離ではなく、正方形の辺に沿った最小距離です。 

正方形の辺は直線で軸に沿っているため、ある点から別の点へのパスは周囲に沿って移動する必要があり、時計回りまたは反時計回りに移動する可能性があります。 たとえば、点が隣接する辺にある場合、最短パスはそれらを接続する角に沿って直接進む可能性があります。 ポイントが反対側にある場合は、長さの異なる複数の周囲ルートが存在する可能性があります。 

制約 (1 ≤ n ≤ 1000) は小さいです。 すべての境界点に沿って反復する強引なアプローチは機能する可能性がありますが、洗練されていません。 周囲長は最大 4000 単位 (4 * 1000) であるため、エッジを明示的に列挙するソリューションはいずれも快適に実行できます。 エッジ ケースは、ポイントが同じエッジ上、コーナー上、または反対側のエッジ上にある場合に発生します。不注意な距離の計算式は、二重にカウントされたり、より短いルートを見逃したりする可能性があります。 

注意が必要なシナリオは、両方の点が反対側にあるものの、垂直方向または水平方向に揃っていない場合です。 たとえば、n=5、点 (0,1) と (5,3) です。 各軸に沿ったマンハッタン距離の合計を単純に計算すると、パスの長さは 7 であることが示唆されます。しかし、周囲に沿って、時計回りのルートは 1→0 コーナー、次に下端の周囲です。距離は 5 + 3 = 8 です。周囲をループとして明示的に考慮する必要があります。 

## アプローチ

 ブルート フォース手法では、周囲を一連の点として扱います。 4 つのエッジすべてに沿ったすべての点を順番に列挙し、周囲を線形配列に平坦化し、指定された 2 つの点のインデックス間の距離を測定することができます。 これは、周囲が小さい (最大 4*n = 4000 ポイント) ため機能します。 複雑さは O(n) なので合格しますが、やや面倒で不要です。 

重要な観察は、周囲を長さ 4*n の 1D ループとして扱うことができるということです。 各点は、このループに沿った単一の座標にマッピングされます。 たとえば、(0,0) から開始して時計回りに移動すると、左エッジ マップ上のポイントは位置 0 → n、下エッジ n → 2n、右エッジ 2n → 3n、および上エッジ 3n → 4n になります。 両方の点を周囲の位置に変換すると、最短距離は単にループに沿った時計回りと反時計回りの距離の最小値になります。`min(abs(p1 - p2), 4*n - abs(p1 - p2))`。 

この洞察により、明示的な反復が回避され、あらゆる正方形サイズに一般化され、すべてのエッジケースが捕捉されます。 周囲の距離が自然に回り込むという観察により、2D 問題は 1D モジュラー算術問題に還元されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての周囲の点を列挙) | O(n) | O(n) | 受け入れられるが冗長 |
 | 最適 (ポイントを周囲の座標にマップ) | お(1) | お(1) | エレガントで速い |

 ## アルゴリズムのチュートリアル

 1. ポイントからマッピングを定義する`(x, y)`正方形の外周上で、(0,0) から始まり時計回りに移動する、外周に沿った線形座標への変換。 左端の点の場合`(0, y)`にマッピングします`y`。 下端に`(x, 0)`、にマップします`n + x`。 右端に`(n, y)`、にマップします`2*n + (n - y)`。 上端に`(x, n)`、にマップします`3*n + (n - x)`。 
2. このマッピングを両方の入力ポイントに適用します。 これにより 2 つの位置が生成されます`p1`そして`p2`1D 周囲ループに沿って。 
3. 時計回りの距離を計算します`abs(p1 - p2)`。 
4. 反時計回りの距離を次のように計算します。`4*n - abs(p1 - p2)`。 
5. 時計回りと反時計回りの距離の最小値を出力します。 

機能する理由: 周囲マッピングでは、正方形のエッジに沿った相対距離が保存されます。 2 点間の最短パスは、このループに沿って時計回りまたは反時計回りのいずれかの方向にたどる必要があります。 周囲の合計は次のようになりますので、`4*n`、これら 2 つの可能性の最小値が正しい答えになります。 このメソッドは、特別な分岐ロジックを使用せずに、同じエッジ、隣接するエッジ、または反対側のエッジ上の点を含むすべてのエッジ ケースを均一に処理します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def perimeter_distance(n, x1, y1, x2, y2):
    def to_perimeter(x, y):
        if x == 0:
            return y
        elif y == n:
            return 3 * n - x
        elif x == n:
            return 2 * n - y
        else:  # y == 0
            return n + x
    
    p1 = to_perimeter(x1, y1)
    p2 = to_perimeter(x2, y2)
    
    dist = abs(p1 - p2)
    return min(dist, 4 * n - dist)

n, x1, y1, x2, y2 = map(int, input().split())
print(perimeter_distance(n, x1, y1, x2, y2))
```マッピング機能`to_perimeter`2D 座標をループに沿った 1D 位置に明示的に変換します。 左・上・右・下のエッジの状態を入念にチェックします。 ループに沿った絶対距離を計算した後、それを周囲の補足的な距離と比較して、より短いパスを取得します。 すべての計算は整数です。 浮動小数点は必要ありません。

左端 (0,0) → y = 0 → p1 = 0。 

下端 (1,0) → y=0 → n + x = 2 +1 = 3。 

周囲の長さ = 4*n = 8。 

時計回りの距離 = abs(0-3) = 3

 反時計回りの距離 = 8 - 3 = 5

 サンプル出力は 1 です。明らかにマッピングに不一致があります。 エッジを確認してみましょう。 

座標系: 直角 (0,0)、(n,0)、(n,n)、(0,n)。 

(0,0) から開始して時計回りに進むと:

 - 下端 (0,0) → (n,0) = x は 0 → n になります
 - 右端 (n,0) → (n,n) = y は 0 → n になります。 
- 上端 (n,n) → (0,n) = x は n → 0 になります
 - 左端 (0,n) → (0,0) = y は n → 0 になります

    elif x == n:

```現在 (0,0) → x==0、そうでない場合: 4_2 - y = 8 - 0 = 8 → ただし、周囲ループは 0 ベース、モジュロ 4_n → 0。下端 (1,0) → y==0 → x=1 → p2=1。 距離 = abs(0-1)=1 はサンプルと一致します。 

これは、慎重なエッジ マッピングが重要である理由を強調しています。
