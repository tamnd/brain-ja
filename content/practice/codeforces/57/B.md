 ## 解決策
 ## 問題の理解

 各構造は、セルの 1 次元ライン上に配置された階段を表します。 階段は独房から始まります`l`、セルで終わります`r`、等差数列で高さを加算します。 開始高さが次の場合`x`、その場合、追加される石は次のとおりです。`x`で`l`

`x + 1`で`l + 1`

`x + 2`で`l + 2`などまで`x + (r - l)`で`r`。 

いくつかの階段が重なる場合があり、それらの階段の寄与が蓄積されます。 

私たちは道路全体を再建するように求められているわけではありません。 その代わりに、ただ`k`特定の細胞が重要です。 すべての階段が適用された後に、クエリされたセルに存在する石の総数が必要です。 

入力により以下が得られます:

 - セルの数、
 - 階段構造のリスト、
 - 最終的な石の数を合計する必要がある興味深いセルのセット。 

最大値は次のとおりです`10^5`、二次関数は即座に除外されます。 すべての階段の影響を受けるすべてのセルを更新する直接シミュレーションは、次のように実行される可能性があります。`10^10`最悪の場合、2 秒の制限をはるかに超えて操作が可能になります。 

興味深い詳細は、`k ≤ 100`。 少数のセルのみがクエリされます。 それは完全に方向性を変えます。 すべての階段が接触するすべてのセルを更新する代わりに、クエリされた位置のみを処理できます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

階段がクエリされたセルの前で始まり、その後で終わるとします。```
5 1 1
1 5 3
4
```クエリされたセルは`4`。 階段は次のことに貢献します。`3 4 5 6 7`細胞`4`受け取る`6`、 ない`3`そしてそうではありません`7`。 開始値のみを保存する不注意な実装では、階段の開始位置からのオフセットを考慮できなくなります。 

別の微妙なケースは、クエリされたセルが階段間隔の外側にある場合に発生します。```
5 1 2
2 4 1
1 5
```階段はセルにのみ影響します`2,3,4`。 正しい答えは、`0`。 間隔チェックにおけるオフバイワンの間違いには、境界セルが誤って含まれることがよくあります。 

重なり合う階段も重要です。```
5 2 1
1 3 1
2 5 2
3
```最初の階段が貢献します`3`セルへ`3`。 

2番目の階段が貢献しています`3`セルへ`3`。 

最終的な値は`6`。 

蓄積ではなく単純に上書きすると、間違った結果が生じます。 

最後に、答えは 32 ビット整数の範囲を超える可能性があります。 それぞれの階段はせいぜい`1000`、あるかもしれません`10^5`階段。 実装では 64 ビット演算を使用する必要があります。 

## アプローチ

 最も直接的な解決策は、道路全体を明示的に構築します。 

それぞれの階段ごとに`(l, r, x)`、影響を受けるすべてのセルを反復処理し、適切な等差数列の値を追加します。```
cell l     += x
cell l + 1 += x + 1
cell l + 2 += x + 2
...
```すべての階段を処理した後、クエリされたセルを合計します。 

すべての階段の寄与がすべてのカバーされた位置に 1 回だけ適用されるため、これは論理的に機能します。 問題はコストです。 1 つの階段でカバーできる場合があります`10^5`細胞が存在する可能性があります。`10^5`階段。 それはおおよそ次のことにつながります`10^10`最悪の場合はアップデートも。 

重要な観察は、すべてのセルの値が決して必要ないということです。 せいぜいだけ`100`ポジションは重要です。 

階段内のすべてのセルを反復処理する代わりに、クエリされたすべての位置を反復処理して、階段がそれらの位置に影響を与えるかどうかを確認できます。 

クエリされたセルを処理するとします。`p`。 

階段`(l, r, x)`に貢献する`p`次の場合のみ:```
l ≤ p ≤ r
```階段が覆われている場合`p`の場合、付加価値は次のようになります。```
x + (p - l)
```右に 1 ステップごとに高さが 1 ずつ増加するためです。 

合計作業量は次のようになります。```
m × k
```以来`m ≤ 100000`そして`k ≤ 100`、最大値は`10^7`これは Python では完全に許容されます。 

ブルートフォースが機能するのは、追加されたすべての石を文字通りシミュレートするためです。 最適化されたソリューションが機能するのは、クエリ セットが小さいため、関連する位置のみをチェックする方が、道路全体を建設するよりもはるかに安価です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 | O(mk) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリされたすべての位置を読み取り、リストに保存します。 

これらの位置のみが重要であるため、他のセルを追跡する必要はありません。 
2. 配列を作成する`ans`長さの`k`。`ans[i]`に蓄積された石の合計が保存されます。`i-th`質問された位置。 
3.各階段の加工`(l, r, x)`一つ一つ。 

すべての階段は独立しているため、クエリされた関連するすべてのセルにその寄与をすぐに追加できます。 
4. クエリされたすべての位置について`p`:

 かどうかを確認してください`l ≤ p ≤ r`。 

false の場合、この階段は何も貢献しません。`p`。 
5. 階段が覆われている場合`p`、 追加：```
x + (p - l)
```対応する回答エントリに移動します。 

用語`(p - l)`クエリされたセルが階段の開始点から右に何段あるかを表します。 
6. すべての階段が処理された後、次のすべてのエントリを合計します。`ans`。 

これにより、クエリされたすべてのセルにわたる石の合計数が得られます。 

### なぜ効果があるのか

 すべての階段とすべてのクエリされた位置について、アルゴリズムは 2 つの可能性のうちの 1 つを正確に考慮します。 

クエリされたセルが階段間隔の外側にある場合、階段は何も寄与しません。 

クエリされたセルが間隔内にある場合、階段は開始セルからの距離に対応する等差数列値に正確に寄与します。 

すべての階段の寄与は独立して追加され、累積は線形であるため、クエリされた各セルの最終保存値は、そのセル内の石の真の合計数と等しくなります。 これらの値を合計すると、必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    roads = [tuple(map(int, input().split())) for _ in range(m)]
    queries = list(map(int, input().split()))

    ans = [0] * k

    for l, r, x in roads:
        for i in range(k):
            p = queries[i]

            if l <= p <= r:
                ans[i] += x + (p - l)

    print(sum(ans))

solve()
```このソリューションは、サイズの配列を構築するのではなく、クエリされた位置のみを保持します。`n`。 

外側のループは階段を繰り返します。 内側のループは、クエリされたすべてのセルをチェックします。 以来`k`せいぜい`100`、これは、次の場合でも効率的です。`m`到達する`100000`。 

表現:```
x + (p - l)
```ソリューションの核心です。 階段が次から始まる場合`l`高さのある`x`、右に1マス移動すると追加される石が1つ増えます。 問い合わせられた位置`p`まさに`p - l`スタートからあと一歩。 

間隔チェック:```
if l <= p <= r:
```重要です。 どちらかの境界を忘れると、エッジに不正確な寄与が生じます。 

最終的な答えは、個々の値そのものではなく、クエリされたすべてのセル値の合計です。 この問題では、1 つの合計を求めます。 

Python の整数は大きな値を自動的に処理するため、オーバーフローは問題になりません。

 ## 特殊なケース

 階段の内側にあるが、その開始点からは遠いセルでクエリが実行されたとします。```
5 1 1
1 5 3
4
```階段には次のものが追加されます。```
3 4 5 6 7
```クエリを処理するとき`4`、アルゴリズムは次を計算します。```
3 + (4 - 1) = 6
```これは真の貢献と一致します。 これにより、オフセットの式が正しいことが確認されます。 

ここで、すべての階段の完全に外側にあるクエリ対象のセルを考えてみましょう。```
5 1 2
2 4 1
1 5
```問い合わせ用`1`、条件`2 ≤ 1 ≤ 4`失敗します。 

問い合わせ用`5`、条件`2 ≤ 5 ≤ 4`も失敗します。 

寄与は追加されないため、クエリされた両方のセルはゼロのままとなり、最終的な答えは次のようになります。`0`。 

重なり合う階段もバグのよくある原因です。```
5 2 1
1 3 1
2 5 2
3
```最初の階段は次のことに貢献します。```
1 + (3 - 1) = 3
```2 番目の貢献は次のとおりです。```
2 + (3 - 2) = 3
```アルゴリズムは両方の値を同じアキュムレータに加算します。```
3 + 3 = 6
```これは期待される結果と一致します。 

最後に、間隔の境界を考慮します。```
5 1 2
2 4 1
2 4
```クエリ時`2`、貢献度は次のとおりです。```
1 + (2 - 2) = 1
```クエリ時`4`、貢献度は次のとおりです。```
1 + (4 - 2) = 3
```最終的な答えは、`4`。 

これにより、間隔チェックが両端を含むことが確認されます。
