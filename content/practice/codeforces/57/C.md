 ## 解決策
 ## 問題の理解

 長さの配列の数を数えるように求められます`n`1 から 1 までの整数を含む`n`配列が完全に減少しないか、完全に増加しないかのいずれかになります。 言い換えれば、連続するすべての要素は、前の要素より小さくても大きくてもいけません。 結果は 1,000,000,007 を法として出力されるはずです。 

入力は単一の整数です`n`、配列の長さと許可される要素の範囲の両方を決定します。 制約は次のとおりです`10^5`のために`n`、出力は非常に大きな数値になる可能性があるため、単純な列挙は実用的ではありません。 

エッジケースは、特に小さな配列で発生します。`n = 1`そして`n = 2`。 のために`n = 1`、配列`[1]`自明のことですが、非減少と非増加の両方であるため、答えは 1 です。`n = 2`、有効な配列は 4 つあります。`[1,1]`、`[1,2]`、`[2,1]`、`[2,2]`。 繰り返される数字を見逃す単純なアプローチでは、ここで過小評価される可能性があります。 

重要な点は、各配列が厳密に増加または減少するシーケンスに制限されていないことを認識することです。 平等は許される。 これは、繰り返し番号を含む配列が完全に有効であることを意味します。 

## アプローチ

 ブルートフォースソリューションでは、すべてのデータを生成しようとします。`n^n`可能な長さの配列`n`1 から 1 までの値`n`、次に、減少していないものまたは増加していないものをフィルタリングします。 これは理論上は機能しますが、配列の数は指数関数的に増加します。 のために`n = 10^5`、マイクロ秒ごとに 1 つの配列を生成するだけでも、制限時間よりも天文学的に長い時間がかかります。 したがって、ブルートフォースは実行できません。 

重要な洞察は、この問題が繰り返しのある組み合わせを数えることに相当するということです。 長さが減少しない配列`n`選択することとして表すことができます`n`からの要素`1..n`繰り返しは許可されます。 繰り返しを伴う組み合わせの公式は次のとおりです。`C(n + k - 1, k)`、 どこ`k`は配列の長さであり、`n`可能な値の数です。 ここ、`k = n`、したがって、減少しない配列の数は次のようになります。`C(2n - 1, n)`。 

対称性により、増加しない配列は同じカウント ロジックに従います。 ただし、完全に定数である配列は、このアプローチでは 2 回カウントされ、1 回は非減少としてカウントされ、もう 1 回は非増加としてカウントされます。 まさにあります`n`定数配列`[1,1,...,1]`、`[2,2,...,2]`、...、`[n,n,...,n]`。 二重カウントを修正するには、減算します。`n`。 

したがって、最終的な式は次のようになります。`2 * C(2n - 1, n) - n`。 数値が大きいため、モジュラー演算を使用する必要があります。 階乗とモジュラー逆関数を事前計算すると、`O(1)`組み合わせごとに計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^n) | O(n^n) | 遅すぎる |
 | 組み合わせ | O(n) 事前計算、O(1) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗モジュロを事前計算する`10^9 + 7`まで`2n - 1`。 これは組み合わせを効率的に計算するために必要です。 事前計算を行わないと、階乗計算を繰り返すと制限時間を超えてしまいます。 
2. フェルマーの小定理を使用して階乗のモジュラー逆関数を事前計算します。 以来`10^9 + 7`は素数、の逆モジュラー`x`モジュロ`10^9 + 7`は`x^(mod-2) % mod`。 これらの逆数を配列に格納します。 
3. コンピューティング`C(2n - 1, n)`階乗配列と逆階乗配列を使用する:`fact[2n-1] * inv_fact[n] * inv_fact[n-1] % mod`。 
4. 非減少シーケンスと非増加シーケンスを考慮して、組み合わせに 2 を掛けます。 
5. 減算`n`二重にカウントされた定数シーケンスを修正します。 モジュロを適用する`10^9 + 7`潜在的な否定的な結果を処理するために減算後。 
6. 結果を出力します。 

機能する理由: 非減少配列は、繰り返しの組み合わせに直接対応します。 同じロジックが非増加配列にも適用されます。 二重カウントは定数シーケンスでのみ発生しますが、これは正確に修正されます。 このアルゴリズムは、事前計算とモジュラー演算を使用して、時間とメモリの制限内に収まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def modinv(x, mod):
    return pow(x, mod - 2, mod)

def solve():
    n = int(input())
    max_fact = 2 * n
    fact = [1] * (max_fact)
    inv_fact = [1] * (max_fact)
    
    for i in range(1, max_fact):
        fact[i] = fact[i - 1] * i % MOD
    
    inv_fact[max_fact - 1] = modinv(fact[max_fact - 1], MOD)
    
    for i in range(max_fact - 2, -1, -1):
        inv_fact[i] = inv_fact[i + 1] * (i + 1) % MOD
    
    def comb(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * inv_fact[b] % MOD * inv_fact[a - b] % MOD
    
    result = (2 * comb(2 * n - 1, n) - n) % MOD
    print(result)

solve()
```最初の部分では階乗とモジュラー逆関数を事前計算し、`comb(a,b)`一定時間内に組み合わせを計算します。 負の結果を避けるために、モジュロを使用して減算を慎重に処理します。

 ## 特殊なケース

 のために`n = 1`、アルゴリズムは次のように計算します。`2*C(1,1) - 1 = 2*1 - 1 = 1`、単一要素の配列を正しくカウントします。 のために`n = 2`、`2*C(3,2) - 2 = 6 - 2 = 4`、正しく数えます`[1,1],[1,2],[2,1],[2,2]`。 事前計算により、`n`効率的に処理されます。 モジュラー減算では、次のような場合に発生する可能性のあるマイナスの結果を慎重に回避します。`2*comb`未満でした`n`(ここでは当てはまりませんが、一般的な安全策です)。
