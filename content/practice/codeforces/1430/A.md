 ## 解決策
 ## 問題の理解

 この建物は 3 つの固定アパートメント タイプで構成されており、各タイプには固定数の窓が割り当てられていると説明されています。 3 部屋のアパートには 3 つの窓があり、5 部屋には 5 つの窓があり、7 部屋には 7 つの窓があります。各テスト ケースでは、建物内で観測された窓の総数のみが与えられるため、その合計が正確に得られるアパートの数の考えられる組み合わせを再構築する必要があります。 

したがって、このタスクは非負の整数を見つけることと同じです。$a, b, c$次のような:$$3a + 5b + 7c = n$$このような分解が存在する場合、有効なトリプルはどれでも受け入れられます。 分解が存在しない場合は、不可能であると報告します。 

制約は小さいです。$n \le 1000$そして$t \le 1000$。 これにより、テスト ケースごとに 3 次または中程度の 2 次探索でも問題ないことがすぐに分かります。$10^6$全体的にチェックします。 ただし、方程式の構造は、盲目的な検索よりもはるかに優れた処理ができることも示唆しています。 

素朴なアプローチでは、すべてのトリプルを試す可能性があります$(a, b, c)$まで$n$、しかしそれは不必要に大きくなります。 より合理的なブルートフォースでは、2 つの変数を修正して 3 番目の変数を導き出すことになりますが、それでもループは最小限に抑えたいと考えます。 

組み合わせが存在しない場合、特に次のような小さな値の場合、微妙なエッジケースが発生します。$n = 1, 2, 4$。 これらは、有効な構成要素がすべて奇数サイズであるため失敗します。つまり、有効な合計は 3、5、7 の組み合わせと同じパリティを持つ必要があります。すべてが奇数であるため、任意の整数$n \ge 3$は表現できる可能性がありますが、組み合わせに柔軟性がないため、小さな値を表現できないことがよくあります。 

もう 1 つのエッジケースは次のような場合です$n$は、3、5、7 などのコイン タイプの 1 つです。答えは、そのタイプの 1 つのアパートメントとその他のゼロを正しく許可する必要があります。 

## アプローチ

 強引なアイデアは簡単です。3 部屋のアパートの可能な数をすべて試してください。$a$そして5部屋のアパートメント$b$、残りの価値が 7 部屋のアパートで満たせるかどうかを計算します。 各ペアごとに$(a, b)$かどうかを確認します。$n - 3a - 5b$は負ではなく、7 で割り切れます。 

制約が小さいためこれは機能しますが、最悪の場合、約$1000 \times 1000 = 10^6$テスト ケースごとにペアがあり、最大 1000 のテスト ケースでは、これは次のようになります。$10^9$動作が遅すぎます。 

重要な点は、実際には深く検索する必要がないということです。 有効な解だけが必要なので、1 つの変数を修正し、他の変数を貪欲に決定できます。 最も便利な選択は、7 部屋のアパートメントの数を繰り返すことです。$c$。 一度$c$が修正されると、残る問題は次のようになります。$$3a + 5b = n - 7c$$ここで、3 と 5 を使用して表現を見つける必要があるだけです。スペースが小さいため、次のすべての値を試すことができます。$b$これにより、検索時間が大幅に短縮され、迅速な解決が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (a, b) に対するブルート フォース | テストあたり O(n²) | お(1) | 遅すぎる |
 | c を修正し、b を試してください | テストごとに O(n²) のワーストケースだが定数が小さい、または早期終了の場合は O(n) | お(1) | 承認済み |

 より実践的な解釈は、ここでは最も単純な境界付き二重ループでも問題ありませんが、2 つの変数への構造化された削減により、実際にはすぐに終了することが保証されます。 

## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. 7部屋のアパートの数を修正してみる$c$0から$n // 7$。 これにより、7 部屋のアパートメントの合計窓数を超えることがなくなります。 
2. それぞれについて$c$、残りのウィンドウを計算します$rem = n - 7c$。 これにより、問題は表現の問題に縮小されます。$rem$3と5を使用します。 
3. 5 部屋のアパートメントの可能な値を試す$b$0から$rem // 5$。 それぞれの選択肢について計算します$rem - 5b$。 
4. 残った値が 3 で割り切れる場合は、次のように設定します。$a = (rem - 5b) // 3$。 この時点で、有効な分解が得られ、出力できます。$a, b, c$。 
5. すべて出し尽くしても組み合わせが見つからない場合$c$そして$b$、-1を出力します。 

この順序付けが機能する理由は、正確性を維持しながら検索スペースを徐々に縮小するためです。 各ステップでは非負性が自動的に適用されるため、以前に選択した値を後戻りしたり調整したりする必要はありません。 

### なぜ効果があるのか

 アルゴリズムは、実行可能なすべての値を列挙します。$c$そして、そのような選択ごとに、実行可能なすべての値を徹底的にチェックします。$b$。 すべてのペアについて$(b, c)$、の値$a$存在するかどうかは一意に決まります。 すべての有効な解はそのようなペアの 1 つに正確に対応するため、検索空間は完全であり、解をスキップすることはできません。 有界ループは、正確さを維持しながら終了を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        found = False

        for c in range(n // 7 + 1):
            rem = n - 7 * c
            for b in range(rem // 5 + 1):
                rest = rem - 5 * b
                if rest % 3 == 0:
                    a = rest // 3
                    print(a, b, c)
                    found = True
                    break
            if found:
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```このコードは、前述したネストされた検索を直接実装します。 外側のループは 7 部屋のアパートの可能な数を反復し、内側のループは 5 部屋のアパートを使用して残りを完了しようとします。 最終チェックでは、3 で割り切れるよう強制され、3 部屋のアパートメントの数が決まります。 

早期ブレークにより、有効な分解が見つかるとすぐに停止することが保証され、不必要な計算が防止されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())

        found = False
        for c in range(n // 7 + 1):
            rem = n - 7 * c
            for b in range(rem // 5 + 1):
                rest = rem - 5 * b
                if rest % 3 == 0:
                    a = rest // 3
                    out.append(f"{a} {b} {c}")
                    found = True
                    break
            if found:
                break
        if not found:
            out.append("-1")

    return "\n".join(out)

 ## 特殊なケース

 次のような非常に小さな値の場合、$n = 1$、アルゴリズムは正しく反復されます$c = 0$そして$b = 0$1 は 3 で割り切れないため、解は見つからず、-1 が返されます。 

次のような完全一致の場合$n = 7$、ループは次のように考慮します。$c = 1$、剰余 0 が得られます。内側のループはすぐに次の値を見つけます。$b = 0$、 そして$a = 0$、有効な答えが得られます。 

次のような混合ケースの場合$n = 14$、複数の中間の組み合わせがテストされますが、アルゴリズムは正しく識別します$7 + 7$または$3 + 5 + 3 + 3$-style ループ順序に応じた分解。 正しさは、どの解決策が最初に見つかるかには依存せず、その解決策が存在する場合のみ、その解決策が見つかるだけです。
