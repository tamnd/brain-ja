 ## 解決策
 ## 問題の理解

 からの整数から始めます`1`を通して`n`ホワイトボードに書かれています。 1 回の操作で、現在ボード上にある任意の 2 つの数字を選択し、それらを消去して、値を書き戻します。`ceil((a+b)/2)`。 

まさにその後`n-1`操作では 1 つの数字だけが残ります。 私たちの仕事は、最終的な数値をできるだけ小さくするだけでなく、この最小値を達成する一連の操作を出力することでもあります。 

入力には複数のテスト ケースが含まれています。 テスト ケースごとに 1 つの整数が与えられます。`n`、ボードには最初に数字が含まれていることを意味します`1, 2, ..., n`。 出力には、最初に可能な最小の最終値が含まれ、その後に各操作で選択された正確なペアが含まれている必要があります。 

すべての合計の合計が`n`せいぜい`2·10^5`は非常に重要です。 これは、テスト ケースと出力ごとに線形作業を行う余裕があることを意味します。`n-1`操作。 可能なシーケンスの数が爆発的に増加するため、さまざまな操作シーケンスを検索しようとする解決策は不可能です。 平`n = 20`すでに天文学的な数の可能性を秘めています。 

この問題の興味深い部分は、演算が上向きに切り上げられることです。 上方に四捨五入すると、値が通常の平均よりも大きくなる傾向があります。 不用意な戦略は、必要以上に大きな最終結果を残す可能性があります。 

エッジケースの 1 つは、`n = 2`。 

入力：```
1
2
```唯一可能な操作は次のとおりです。```
1 2
```生み出すのは`ceil(3/2)=2`。 答えは`2`。 

もう 1 つのエッジケースは、誰かが最初に最小の数値を繰り返し組み合わせる場合です。 のために`n = 4`:```
1,2,3,4
```組み合わせる`1`そして`2`与える`2`、次に組み合わせます`2`そして`3`与える`3`、次に組み合わせます`3`そして`4`与える`4`。 最終的な答えはこうなります`4`、最適とは程遠い。 

3 番目の微妙なケースは大きい`n`。 出力自体には次のものが含まれるため、操作シーケンスは効率的に生成する必要があります。`n-1`線。 テスト ケースごとに線形よりも遅いソリューションは、避けられない出力コストと比較して時間を無駄にします。 

## アプローチ

 ブルートフォースアプローチでは、すべてのステップですべての可能なペアを探索し、すべての操作シーケンスを再帰的に試行します。 これは、最終的に考えられるすべての結果を検査するため、正しいです。 残念ながら、すぐに役に立たなくなります。 から始まる`n`数字、最初の動きは`n(n-1)/2`選択肢があれば、次の行動は`(n-1)(n-2)/2`選択肢など。 検索スペースは超指数関数的に拡大します。 

重要な観察は、操作が何を行うかを理解することから得られます。 計算してるので$$\left\lceil \frac{a+b}{2} \right\rceil,$$結果は常に間にあります`max(a,b)`そして合計の約半分。 大きな数値を繰り返しマージすると、数値は縮小します。 例えば：$$\left\lceil \frac{8+7}{2} \right\rceil = 8.$$2 つの大きな数は、それより大きくはなく、それに近い数になります。 

常に現在の最大の数値を取得し、それを 2 番目に大きい数値とマージするとします。 から始まる`n`、これにより、最大値が徐々に引き下げられますが、小さな値によって結果が膨らむことはありません。 

たとえば、`n=4`:```
4,3 -> 4
4,2 -> 3
3,1 -> 2
```最終的な答えはこうなります`2`、これが最適です。 

公式ソリューションで証明された注目すべき事実は、この戦略が常に可能な限り最小の最終値を生成するということです。 最後の数字は常に`2`あらゆる人にとって`n ≥ 2`。

 ## アルゴリズムのチュートリアル

 1. 最大の数字から始めます`cur = n`。 
2. あらゆる値について`x`から`n-1`まで`1`、操作を記録します`(cur, x)`。 
3. 交換する`cur`による：$$cur = \left\lceil \frac{cur+x}{2} \right\rceil$$これは、利用可能な 2 つの最大の数値を結合した後に残る値をシミュレートします。 

1. 値が 1 つだけ残るまで続けます。 
2. 最終値と記録されたすべての操作を出力します。 

これが機能する理由は、すべてのステップで、現在の最大値を次に大きい未使用の値とマージするためです。 最終的な答えを大きく保つことができるのは大きな数値だけであるため、最初に積極的に数値を減らします。 

### なぜ効果があるのか

 現在の最大値を次のようにします`M`。 より小さい数値を含む操作はすべて終了します`M`これは、ボードにまだ非常に大きな値が含まれていることを意味します。 最終結果をできるだけ小さくしたい場合は、可能な限り最大値を減らし続ける必要があります。 

操作$$\left\lceil \frac{M+x}{2} \right\rceil$$次に大きいものが利用可能`x`大きな数値の 1 つを消費しながら、最大値を可能な限り強力に削減します。 このプロセスを繰り返すことで、最大値の達成可能な最小の軌道が作成されます。 結果として得られるシーケンスは常に次で終了します。`2`、これは可能な最小の最終値です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        
        ops = []
        cur = n
        
        for x in range(n - 1, 0, -1):
            ops.append((cur, x))
            cur = (cur + x + 1) // 2
        
        print(cur)
        for a, b in ops:
            print(a, b)

solve()
```変数`cur`は、これまでに確認された最大値を処理した後に残る数値を表します。 最初はそうです`n`、ボード上の最大の数。 

各反復では、次の間の操作が記録されます。`cur`次に大きい未使用の値。 表現```
(cur + x + 1) // 2
```の上限を計算します`(cur+x)/2`整数演算を使用します。 

操作の順序が重要です。 以下の値を処理する必要があります。`n-1`まで`1`。 この順序を逆にすると、より大きな最終値が生成されます。 

すべての値が Python の整数範囲内に収まるため、大きな数値に対して特別な処理は必要ありません。

## 複雑さの分析

 | スペース | O(n) | 操作リストを格納します |

 の合計`n`すべてのテストケース全体で最大でも`2·10^5`。 アルゴリズムは線形作業を実行し、正確に出力するため、`n-1`操作を行うと、簡単に制限内に収まります。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    out = []

    t = int(input())

    for _ in range(t):
        n = int(input())

        ops = []
        cur = n

        for x in range(n - 1, 0, -1):
            ops.append((cur, x))
            cur = (cur + x + 1) // 2

        out.append(str(cur))
        for a, b in ops:
            out.append(f"{a} {b}")

    return "\n".join(out)

# sample
res = run("1\n4\n")
assert res.splitlines()[0] == "2"

# minimum n
res = run("1\n2\n")
assert res.splitlines()[0] == "2"

# n = 3
res = run("1\n3\n")
assert res.splitlines()[0] == "2"

# larger value
res = run("1\n10\n")
assert res.splitlines()[0] == "2"

# multiple test cases
res = run("2\n2\n5\n")
assert res.splitlines()[0] == "2"
assert "2" in res

 ## 特殊なケース

 次のことを考慮してください。```
1
2
```ボードには以下のものしか含まれていません`1`そして`2`。 唯一の操作は次のとおりです。```
(1,2) -> 2
```アルゴリズムの出力`2`、代替手段が存在しないため、これが最適です。 

考慮する：```
1
3
```アルゴリズムは以下を実行します。```
(3,2) -> 3
(3,1) -> 2
```そして次で終わります`2`。 合併などの甘い戦略`(1,2)`最初に生成されるもの:```
2,3
```それは次のようになります`3`、さらに悪い結果になります。 

考慮する：```
1
5
```アルゴリズムは最大値を減らし続けます。```
5 -> 5 -> 4 -> 3 -> 2
```不変条件は、すべての操作が現在の最大残存値をターゲットとすることです。 最大値が最終的な答えを制御するため、あらゆる機会に値を減らすことが最適な最終結果につながります。
