 ## 問題の理解

 長さの順列を扱っています$N$したがって、有効な配列はすべて、次の数値を並べ替えたものになります。$1$に$N$。 私たちが気にする唯一の構造特性は、位置が$i$は降下、つまり$P_i > P_{i+1}$。 このような位置は、左から右に読むと順列が落ちる正確な「ブレークポイント」であるため、特別です。 

私たちにはセットが与えられています$S$インデックスの。 この条件は、降下が許可される場所を制限します。$i$降下である場合、$i$に属さなければなりません$S$。 同様に、外側のすべてのポジション$S$強制的に満たさなければならない$P_i < P_{i+1}$, なので歩数を増やしているはずです。 

タスクは、次の順列が何回あるかを数えることです。$[1..N]$指定されたセットに対してこの制約を満たす$S$、複数のテスト ケースにわたるモジュロ$10^9+7$。 

制約は大きいです:$N$まで行くことができます$2 \cdot 10^5$まであります$10^3$テストケースと合計$K$グローバルに制限されています。 これにより、順列を列挙しようとしたり、順列ごとの制約をシミュレートしようとしたりするソリューションは即座に除外されます。 構造はテスト ケースごとの組み合わせ式に帰着する必要があり、理想的には線形または線形に近い形になります。$K$。 

重要な微妙な点は、この状態は局所的であるにもかかわらず、全体的な影響を与えるということです。 許可される降下位置が 1 つだけであると、値の分割方法が変わるため、位置を個別に処理すると失敗します。 

単純な間違いは、各インデックスを次のように考えることです。$S$それが降下であるかどうかを独自に決定します。 それは単純なことを提案します$2^K$-スタイルのカウントまたは階乗分割ですが、これは、下降が増加する実行への順列のセグメント化を定義することを無視しており、それらの実行はグローバルに一貫している必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。すべてを生成します。$N!$順列を調べて、すべての下降位置が次の位置にあるかどうかを確認します。$S$。 順列ごとに 1 回スキャンしてすべてのインデックスを識別します$i$どこ$P_i > P_{i+1}$、ハッシュ セットのメンバーシップを確認します。 これには費用がかかります$O(N \cdot N!)$、これはたとえ$N = 10$。 

重要な観察は、順列の観点から直接考えるのをやめ、代わりに降下によって引き起こされる構造に焦点を当てることです。 すべての順列は、最大増加セグメントに分解できます。 ポジションでの下降$i$まさに 1 つのセグメントが終了し、次のセグメントが始まる場所です。 

この制約は、セグメントの区切りが次の位置でのみ許可されることを示しています。$S$。 これは、次の補数を意味します。$S$休憩を含めてはいけないため、これらの位置では増加するラン内での連続性が強制されます。 言い換えれば、配列を増加するブロックに分割しており、許可される分割ポイントは正確に次のとおりです。$S$。 

ここで問題は、番号を割り当てる方法は何通りあるかということです。$1..N$各ブロック内の昇順を維持しながら、強制的な非ブレーク位置とオプションのブレーク位置によって決定されるブロックに分割します。 

標準的な変換が適用されます。左から右にスキャンして、分割が禁止されている連続セグメントを特定します。 これらの強制拘束により、位置がコンポーネントにマージされます。 マージされると、各コンポーネントは単一の「スロット」として動作し、その中で要素が増加する必要がありますが、コンポーネント間の相対的な順序は自由に変更できます。 これにより問題は、ブロック数の階乗となるブロックの順列を数えることと、固定された内部配置を乗算することに変わります。 

最終的な構造は、強制隣接エッジの下に存在する接続コンポーネントの数に基づいて階乗を計算することを単純化します。

 ## アルゴリズムのチュートリアル

 制約を強制的な隣接関係として再解釈します。 位置の場合$i$入っていない$S$、それでは、次のようにする必要があります$P_i < P_{i+1}$、つまり$i$そして$i+1$同じ増加ブロック内になければなりません。 つまり、すべてのインデックスは$i \notin S$～間の接続を強制する$i$そして$i+1$。 

1. 分類または保管する$S$のハッシュセットで$O(1)$membership checks. これにより、境界が許可されているか禁止されているかを迅速に判断できます。 
2. Traverse indices from$1$に$N-1$。 いつでも$i \notin S$、合併します$i$そして$i+1$同じコンポーネントに入れます。 これにより、降下が許可されない位置の連続したセグメントが構築されます。 
3. 結果として生じる接続コンポーネントの数を数えます。 から始めると$N$孤立した位置を結合し、強制的に隣接する位置を結合すると、結合するたびにコンポーネントの数が 1 つずつ減ります。 
4. コンポーネントの数を次のようにします。$C$。 重要な組み合わせ解釈は、各コンポーネントがコンポーネントの順列における単一の要素のように動作するということです。 
5. 各コンポーネント内では、値は厳密に増加する必要があるため、一連の数値をコンポーネントに割り当てたら、それらを配置する方法は 1 つだけです。 
6. したがって、唯一の自由は、$C$コンポーネント自体が次の要因に寄与します$C!$。 
7. 階乗を計算する$N$一度出力してください$C!$テストケースごとに。 

これが機能する理由は、強制的な非降下が内部順序制約を完全に決定するためです。 強制的に増加するエッジによって形成されるすべての接続コンポーネントは、固定された内部構造を持ち、その内部には追加の自由度は残りません。 すべての変動性は、ブロックが相互に相対的にどのように順序付けられるかによって決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    max_n = 2 * 10**5 + 5

    fact = [1] * (max_n)
    for i in range(1, max_n):
        fact[i] = fact[i - 1] * i % MOD

    for _ in range(T):
        n, k = map(int, input().split())
        s = set(map(int, input().split()))

        components = 1
        for i in range(1, n):
            if i in s:
                components += 1

        print(fact[components])

if __name__ == "__main__":
    solve()

## 実用的な例

 小さなケースを考えてみましょう。$N = 5$そして$S = \{2, 4\}$。 これは、位置 2 と 4 のみが下降できることを意味するため、位置 1 と 3 は境界を増加する必要があります。 

| 私 | S | アクション | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | いいえ | マージ (1,2) | 1 |
 | 2 | はい | 分割可能 | 2 |
 | 3 | いいえ | マージ (3,4) | 2 |
 | 4 | はい | 分割可能 | 3 |

 3 つのコンポーネントで終わるので、答えは次のようになります。$3! = 6$。 これは、禁止された位置がどのように構造を崩壊させるかを示しています。 

ここで考えてみましょう$N = 4$、$S = \{1,2,3\}$。 すべての位置は降下できるため、強制的なマージは行われません。 

| 私 | S | コンポーネント |

 得ます$4$コンポーネントなので、答えは次のとおりです。$4! = 24$これは、どの位置も増加するように制約されていないため、すべての順列が有効であることを意味します。 

これらの例は、制約が単に降下を許可する場合ではなく、隣接を強制する場合にのみ制約によって自由度が低下することを示しています。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline
    T = int(input())
    max_n = 2 * 10**5 + 5
    fact = [1] * max_n
    for i in range(1, max_n):
        fact[i] = fact[i - 1] * i % MOD

    out = []
    for _ in range(T):
        n, k = map(int, input().split())
        s = set(map(int, input().split()))
        comp = 1
        for i in range(1, n):
            if i in s:
                comp += 1
        out.append(str(fact[comp]))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 微妙なケースの 1 つが次のような場合です。$S$は空です。 それはあらゆるポジションを強制する$i$満足させる$P_i < P_{i+1}$したがって、順列は厳密に増加している必要があります。 1 つの順列のみがこれを満たし、アルゴリズムは 1 つのコンポーネントのみを生成します。$1! = 1$、期待される結果と一致します。 

もう一つのコーナーは、$S$からのすべてのインデックスが含まれます$1$に$N-1$。 この場合、隣接関係は強制されないため、すべての置換が有効になります。 アルゴリズムが重要$N$コンポーネント、作成$N!$、完全な順列空間と一致します。 

3 番目のケースは、交互のメンバーシップのような分散された制約です。 欠落している各インデックスは 2 つの位置をマージするため、制約が存在しない場所ではコンポーネントが正確に縮小されます。 マージ プロセスを追跡すると、各強制等化によって自由度がちょうど 1 つの隣接だけ減少し、コンポーネントが最大の強制増加セグメントに対応するという不変条件が維持されることが確認されます。
