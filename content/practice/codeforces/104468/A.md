 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 各位置で値のペアが表示され、選択した位置内の 2 つの値をオプションで交換できます。 いくつかのスワップを実行した後の目標は、結果として得られる両方の配列内に重複する値が含まれないようにすることです。 

操作を表示するもう 1 つの方法は、各インデックスが値のペアに寄与し、そのペアをそのまま保持するか反転するかを決定できることです。 フリップを選択した後、最初のコンポーネントが 1 つの配列を形成し、2 番目のコンポーネントが別の配列を形成し、両方の配列がセットになる必要があります。 

出力は、必要なフリップの最小数、または重複を回避するフリップの選択がない場合は不可能です。 

この制約により、テスト ケース全体で合計最大 100,000 個の要素が許可されます。 これにより、インデックスのすべてのサブセットを試したり、指数関数的な選択をシミュレートしたりするソリューションは即座に除外されます。 テスト ケースごとに線形に近いものが必要です。おそらく、値間の競合に関するカウントと構造的推論に基づいています。 

単純な障害モードは、両方の配列に重複が存在し、単一の値が互換性のない位置に何度も出現する場合に発生します。 たとえば、値が両方の位置で多くのペアに出現するが、選択肢を反転してもすべての出現を分離できない場合、ローカル修正が存在すると誤って仮定する可能性があります。 

もう 1 つの微妙な問題は、値ごとに貪欲に重複を修正することが独立して機能すると仮定していることです。 たとえば、値 5 が複数のペアに出現する場合、フリップは 2 つの値を同時に結合するため、その競合を個別に解決すると、別の値の一意性が失われる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各インデックスをスワップするかスワップしないかの二者択一の決定として扱います。 これにより、2^N 構成が得られます。 構成ごとに、両方の配列にすべての個別の値が含まれているかどうかを確認します。 妥当性のチェックには O(N) のコストがかかるため、合計の複雑さは O(N・2^N) となり、N = 20 の場合でも実行不可能です。 

重要な観察は、構造が任意ではないということです。各インデックスは、最初の配列に 1 つの値を、2 番目の配列に 1 つの値を正確に提供し、交換はペアの割り当てを反転するだけです。 したがって、各インデックスは 2 つのラベルのバイナリ割り当てであり、同じ値が同じ側に 2 回割り当てられた場合にのみ競合が発生します。 

これにより、問題は、各値が各辺に最大 1 回出現する必要があるグラフのような構造上の制約システムに変わります。 割り当てをグローバルに検索する代わりに、値ごとに推論します。各値はいくつかのペアに出現し、各値がサイド配置の選択に影響します。 値が k 回出現する場合、それらの k 個の出現は、最大 1 つが最初の配列に配置され、最大 1 つが 2 番目の配列に配置されるように分散する必要があります。 

これから、すべてのペアにわたって合計で 2 回を超えて出現する値は存在できないという必要条件が導き出されます。 3 回出現する場合、鳩の穴の原則により、入れ替えに関係なく少なくとも 2 つの出現が同じ側に着地する必要があり、この条件は不可能になります。 

実現可能性が保証されたら、一貫した割り当てを強制することでスワップを最小限に抑えます。つまり、値が 2 回出現する場合は必ず、それらの出現を異なる側に分割する必要があります。 これにより、競合を解決するかどうかに応じて、各ポジションがゼロまたは 1 つの強制スワップに寄与する決定的な選択構造が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N・2^N) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

1. 両方の配列に現れるすべての値の頻度マップを作成します。 値が 2 回以上出現した場合、即座に答えは不可能であると判断します。 これは、2 つの配列がそれぞれ値のコピーを 1 つだけホストできるという事実からわかります。 
2. すべての位置について、順序のないペア (a、b) として解釈します。 a が b と等しい場合、この値は決定後に同じ側に 2 回出現する必要がありますが、スワップに関係なく両方のコピーが同じ配列に移動するため、これは不可能です。 したがって、そのような立場は直ちに不可能を強います。 
3. 次に、出現回数に応じて各値を分類します。 正確に 2 回出現する値は、2 つの配列に分割する必要があるため、制約を作成する唯一の値です。 
4. 発生ごとに望ましい方向を割り当てます。 ペア (a, b) については、2 回出現する各値が分割されるように、それを維持するか交換するかを決定します。1 つの出現は 1 番目の配列に寄与し、もう 1 つは 2 番目の配列に寄与します。 
5. インデックスを貪欲に走査し、各値が最初の配列にすでに割り当てられている回数を追跡します。 現在の方向の割り当てがいずれかの値の片側で 1 回の出現を超える場合は、可能であればそれを反転します。 
6. 一意性の侵害を避けるためにペアを反転する必要があるたびに、操作数が増加します。 

貪欲なステップの背後にある理由は、各値はそれぞれの側で独立して 1 つのオカレンスを必要とし、一方の側でクォータがすでに割り当てられていると、今後のオカレンスはもう一方の側に移動する必要があり、現在正しく割り当てられていない場合は強制的に交換する必要があるということです。 

### なぜ効果があるのか

 重要な不変条件は、すべてのステップで、すべての値について、処理されたインデックス間で構築された各配列にその値が最大 1 回出現することを維持することです。 各値はグローバルに最大 2 回出現するため、1 つの出現が片側に固定されると、残りの出現は柔軟性がなく、反対側を占有する必要があります。 これにより、分岐の決定が削除され、強制的な反転まで割り当てが決定的になります。 このアルゴリズムでは、値が一意性制約に違反する場合にのみすべての反転がトリガーされるため、以前は回避できた競合が発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = []
        b = []
        for _ in range(n):
            x, y = map(int, input().split())
            a.append(x)
            b.append(y)

        freq = {}
        for i in range(n):
            freq[a[i]] = freq.get(a[i], 0) + 1
            freq[b[i]] = freq.get(b[i], 0) + 1

        ok = True
        for v in freq:
            if freq[v] > 2:
                ok = False
                break

        if not ok:
            print(-1)
            continue

        # track assignment counts
        cntA = {}
        cntB = {}
        ops = 0

        for i in range(n):
            x, y = a[i], b[i]

            # if same value, impossible (would duplicate in both arrays)
            if x == y:
                ok = False
                break

            # try keep orientation first: x->A, y->B
            ca = cntA.get(x, 0)
            cb = cntB.get(y, 0)

            if ca < 1 and cb < 1:
                cntA[x] = ca + 1
                cntB[y] = cb + 1
            else:
                # must swap
                ops += 1
                cntA[y] = cntA.get(y, 0) + 1
                cntB[x] = cntB.get(x, 0) + 1

        if not ok:
            print(-1)
        else:
            print(ops)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に両方の配列にわたる頻度カウントを使用して実現可能性をチェックします。これは、任意の値の出現が 2 回を超えると、その値を 2 つの異なる配列に一意に割り当てることができなくなるためです。 

次に、ペアごとに貪欲な割り当てをシミュレートします。 各ペアは最初、最初の値を最初の配列に提供し、2 番目の値を 2 番目の配列に提供すると想定されます。 その割り当てが、各側の値ごとに 1 回の出現の許容カウントを超える場合、アルゴリズムはペアを交換し、操作をカウントします。 

微妙な点は、等しいペアが早期に拒否されることです。 ペアが (x, x) の場合、交換は何も行わず、両方の配列のその位置に x が含まれることになり、直ちに区別性に違反します。 

各値の出現回数が合計で最大 2 回であるため、貪欲な決定が機能します。そのため、片側が使用されると、残りの出現が強制されます。 これにより、後の競合によって以前の選択が無効になるのを防ぎます。

2

```値 1 は 2 回表示され、値 2 は 2 回表示されますが、両方のペアが少なくとも片側で強制的に重複する形で重なり合っています。 アルゴリズムは最終的に、片側に 1 または 2 のいずれかが 2 回含まれている必要があることを検出し、実現可能性を拒否または失敗します。 

これは、周波数制約の重要性と、貪欲な割り当てではグローバルな過負荷を回避できないという事実を示しています。

    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())

        b = []

            out.append("-1")

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値がちょうど 2 回出現するが、最初は単純な貪欲な選択によって両方の出現が同じ側に割り当てられる場合です。 その状況では、アルゴリズムはそれらのいずれかでスワップを強制する必要があります。 そうしないと、最終的な配列に重複が含まれることになります。 貪欲ルールにより、これが永続化できないことが保証されます。これは、2 回目の出現により、最初の側がその値に対してすでにいっぱいであることが検出されるためです。 

もう 1 つのエッジ ケースは、(x, x) のような自己ペアです。 スワップによって寄与が変更されず、そのインデックスで両方の配列に重複が発生するため、アルゴリズムはこれをすぐに拒否します。 

3 番目のエッジ ケースは、ペア (1,2)、(2,3)、(3,1) など、複数の値が重複する制約を形成する場合です。 アルゴリズムはこのサイクルを順次割り当てによって解決し、各強制スワップは 1 つのサイクル エッジのブレークに対応し、すべての値がサイドごとの制限を超えることなく正しく分割されるようにします。
