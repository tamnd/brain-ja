 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースでは、整数の配列から開始し、順序を維持し、場合によっては要素をスキップしてサブシーケンスを選択する必要があります。 

その選択されたサブシーケンスから、すべての隣接するペアを調べます。 隣接する各ペアは、元の配列内の位置ではなく、2 つの数値のみに依存する値を与えます。 ペアの貢献$(x, y)$ペアの数を数えることによって定義されます$(i, j)$と一緒に存在する$1 \le i \le x$、$1 \le j \le y$、そのような$i + j$は完全な正方形です。 その量は、間のエッジの重みになります。$x$そして$y$。 

目標は、サブシーケンス内のすべての連続するペアにわたるこれらのエッジの重みの合計を最大化するサブシーケンスを選択することです。 

したがって、この問題は、選択された 2 つの値の間の遷移コストがそれらの数値のみに依存する重み付き最長部分列問題です。 

制約は非常に重要です。 すべてのテスト ケースの合計の長さは最大です。$2 \cdot 10^5$、値は次のようになります。$10^5$。 これにより、インデックスのすべてのペアまたは値のすべてのペアを直接試行するソリューションは除外されます。 配列上の 2 次 DP はすぐに大きすぎます。$4 \cdot 10^{10}$最悪の場合は移行します。 

主な問題は、移行コストが絶対差や一定の重みのような単純な関数ではないことです。 これには、完全な平方条件の下で格子点を数えることが含まれますが、これにより、構造化されているが自明ではない組み合わせ関数が隠蔽されます。 

いくつかのエッジケースは、単純な推論では何が問題になるかを明らかにします。 

配列に単一の要素がある場合、隣接するペアがないため、答えはゼロでなければなりません。 誤って初期化して単一の要素を寄与としてカウントしようとする試みは誤りです。 

すべての要素が等しい場合、次のようにします。$[x, x, x]$、最適なサブシーケンスはすべての要素を使用し、答えは の値の 2 倍になります。$w(x, x)$。 ここでの間違いは、値を繰り返しても追加の利点がないと仮定したり、サブシーケンスに元の位置からの重複が含まれる可能性があることを忘れたりすることです。 

もう 1 つの微妙なケースは、値が大きいにもかかわらず、非常に特定のペアだけが正方形を形成するような間隔で配置されている場合です。 ローカルで最良のペアを常に接続するような貪欲な戦略は失敗します。初期のエッジがわずかに悪くても、後のチェーンははるかに優れている可能性があるためです。 

## アプローチ

 直接的な総当たりアプローチは、すべてのサブシーケンスを考慮し、そのスコアを計算することです。 長さの各部分列に対して$k$、評価します$k-1$移行があり、$2^n$後続。 これは指数関数的に大きく、すぐには不可能です。 

より合理的な総当り攻撃は、インデックスに対する動的プログラミングです。 させて$dp[i]$位置で終了するサブシーケンスの最高スコアであること$i$。 以前のすべてのポジションを試してみます$j < i$、間の移行コストを計算します。$A_j$そして$A_i$、更新します$dp[i]$。 これにより、$O(n^2)$テスト ケースごとの移行が遅くなりすぎます。$n = 2 \cdot 10^5$。 

重要な観察は、移行コストはポジションではなく値のみに依存するということです。 これにより、状態を値でグループ化し、配列を左から右に処理しながら、問題を値の状態に対する DP として扱うことができます。 

残りの課題は、2 つの値の間の遷移関数が繰り返し評価するにはコストが高すぎることです。 ペアごとにゼロから再計算するのではなく、完全二乗の構造を利用して、少数の平方根の合計になるように関数を書き直し、値の間隔で範囲クエリを実行できるようにします。 

これにより、問題は動的プログラミング システムに変換され、新しい要素ごとに、すべての値を反復処理するのではなく、以前の値に対してデータ構造をクエリする必要があります。

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、値に対する DP を維持します。$dp[v]$value で終わる有効なサブシーケンスの最高のスコアです$v$。 

新しい値ごとに$x = A[i]$、既存のサブシーケンスに追加する最適な方法を計算します。 

### 1. トランジションを書き直す

 以前の値の場合$v$、ペアの貢献$(v, x)$正方形に依存する$s^2$。 ペアを数えます$(i, j)$次のような:$$1 \le i \le v,\quad 1 \le j \le x,\quad i + j = s^2$$正方形を固定する$t = s^2$、有効なペアは整数に対応します$i$次のような:$$i \in [1, v], \quad t - i \in [1, x]$$これは区間の交点になります。$$i \in [\max(1, t-x), \min(v, t-1)]$$正の場合、各正方形はこの間隔のサイズに寄与します。 

したがって、遷移はすべての正方形にわたる寄与の合計になります。$t$。 

### 2. DP 遷移構造

 現在の場合$x$、次のように計算します。$$dp_{new}[x] = \max\Big(0, \max_{v} \big(dp[v] + w(v, x)\big)\Big)$$私たちは別れました$w(v, x)$正方形で。 正方形ごとに$t$、 定義する：$$L = \max(1, t-x), \quad R = t-1$$固定の場合$t$、への貢献$w(v, x)$場所によります$v$嘘:

 - もし$v < L$、貢献度は0です
 - もし$L \le v \le R$、貢献度は$v - L + 1$- もし$v > R$、貢献度は一定です$R - L + 1$重要な部分は、中間セグメントでは寄与が線形であることです。$v$。 

### 3. クエリを最大範囲まで削減する

 正方形ごとに$t$、次のものが必要です。$$\max_{v \in [L, R]} (dp[v] + v)$$なぜなら、アクティブ領域内では次のようなことが考えられます。$$dp[v] + (v - L + 1) = (dp[v] + v) + (1 - L)$$したがって、値に対するセグメント ツリーを維持します。$v$、保管$dp[v]$、またクエリも行います$dp[v] + v$効率的に。 

正方形ごとに$t$、私たちは：

 1. 計算間隔$[L, R]$2. クエリの最大値$dp[v] + v$その間隔にわたって
 3. 定数シフトを追加する$1 - L$また、DP にすでに最良の状態が含まれるようにすることで、定常領域を暗黙的に考慮します。 

### 4. Processing each array element

 それぞれの値について$x$:

 1. すべての正方形を列挙する$t \le x + 100000$2. その間隔を計算する$[L, R]$3. セグメント ツリーにクエリを実行して最適な遷移を得る
 4.アップデート$dp[x]$5.挿入$x$セグメントツリーに

 値を使用して新しいサブシーケンスを開始することを常に許可します。$x$、スコアは 0 になります。 

### なぜ効果があるのか

 DP の不変条件は、プレフィックスを処理した後のものです。$1..i$、$dp[v]$value で終わる有効なサブシーケンスの達成可能な最大スコアを格納します$v$。 前の値から新しい値へのすべての遷移は、完全二乗の独立した寄与に分解され、各寄与は前の値​​に対する区分線形関数として表現されます。 この構造により、範囲最大クエリを使用して各正方形の最良の以前の状態を取得できるため、有効な遷移が見逃されたり、無効な組み合わせが導入されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    T = int(input())
    
    # precompute squares up to max possible sum (2e5 + 1e5 margin)
    maxv = 200000 + 5
    squares = []
    k = 1
    while k * k <= maxv:
        squares.append(k * k)
        k += 1

    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        # dp by value
        max_val = max(a)
        dp = [0] * (max_val + 1)

        # segment tree for max(dp[v] + v)
        size = 1
        while size <= max_val:
            size <<= 1
        seg = [-10**18] * (2 * size)

        def seg_update(pos, val):
            pos += size
            seg[pos] = val
            pos >>= 1
            while pos:
                seg[pos] = max(seg[pos << 1], seg[pos << 1 | 1])
                pos >>= 1

        def seg_query(l, r):
            if l > r:
                return -10**18
            l += size
            r += size
            res = -10**18
            while l <= r:
                if l & 1:
                    res = max(res, seg[l])
                    l += 1
                if not (r & 1):
                    res = max(res, seg[r])
                    r -= 1
                l >>= 1
                r >>= 1
            return res

        ans = 0

        for x in a:
            best = 0

            for t in squares:
                if t > x + max_val:
                    break

                L = max(1, t - x)
                R = t - 1
                if L > max_val:
                    continue
                R = min(R, max_val)
                if L > R:
                    continue

                q = seg_query(L, R)
                if q == -10**18:
                    continue

                best = max(best, q + (1 - L))

            dp[x] = max(dp[x], best)
            ans = max(ans, dp[x])

            seg_update(x, dp[x] + x)

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、値に対する DP を維持し、セグメント ツリーを使用して以前の最良のエンドポイントを効率的にクエリします。 重要な点は、セグメント ツリーが$dp[v] + v$、これは遷移の線形部分と一致します。 各四角形はシフトされた範囲最大クエリに寄与し、すべての四角形を組み合わせると、現在の値に最適な遷移が得られます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    T = int(input())
    squares = []
    k = 1
    while k * k <= 200000:
        squares.append(k * k)
        k += 1

    out = []

    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        maxv = max(a)
        dp = [0] * (maxv + 1)

        size = 1
        while size <= maxv:
            size <<= 1
        seg = [-10**18] * (2 * size)

        def upd(p, v):
            p += size
            seg[p] = v
            p >>= 1
            while p:
                seg[p] = max(seg[p<<1], seg[p<<1|1])
                p >>= 1

        def qry(l, r):
            if l > r:
                return -10**18
            l += size
            r += size
            res = -10**18
            while l <= r:
                if l & 1:
                    res = max(res, seg[l]); l += 1
                if not (r & 1):
                    res = max(res, seg[r]); r -= 1
                l >>= 1; r >>= 1
            return res

        ans = 0

        for x in a:
            best = 0
            for t in squares:
                if t > x + maxv:
                    break
                L = max(1, t - x)
                R = min(maxv, t - 1)
                if L > R:
                    continue
                q = qry(L, R)
                if q > -10**17:
                    best = max(best, q + (1 - L))
            dp[x] = best
            ans = max(ans, dp[x])
            upd(x, dp[x] + x)

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 次のような最小の単一要素配列`[5]`隣接するペアは生成されないため、答えはゼロでなければなりません。 DP 遷移がトリガーされないため、アルゴリズムがこれを処理します。 最適な値はゼロに初期化されたままになります。 

のように同じ値が繰り返される場合`[10, 10, 10]`、セグメント ツリーが値からそれ自体への遷移を正しく許可することを保証します。 DP 更新は同じインデックスを介して伝播し、範囲クエリには対角寄与が含まれるため、方形条件が許せば非ゼロ チェーンが生成されます。 

のようなまばらなケース`[1, 100000]`大きな正方形のしきい値が、$t - x$間隔の計算。 実行可能な範囲内の正方形のみが寄与し、セグメント ツリーは間隔を慎重に境界付けることによって無効なクエリを回避します。 

これらのケースは、実装が DP の一貫性を損なうことなく、空の遷移、自己遷移、および大きな値のクリッピングを正しく処理していることを確認します。
