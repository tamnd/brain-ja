 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれに整数の配列があり、これらの値のサブセットを選択できます。 選択された要素のすべてのペアが AND と XOR を含む特定のビット単位の不等式を満たす場合、サブセットは有効であるとみなされます。 

選択した 2 つの数値について、ビットごとの AND の値とビットごとの XOR を通常の整数として比較します。 サブセットは、すべてのペアの AND 結果が XOR 結果以上である場合にのみ受け入れられます。 タスクは、この条件を満たす可能な最大のサブセットを選択し、そのサイズを出力することです。 

テスト ケース全体の合計入力サイズに対する制約は大きく、全体で最大 10^5 の数値になります。 これにより、各テスト ケース内のすべてのペアのチェックが即座に除外されます。これは、二次アプローチでは、最悪の場合、最大約 10^10 の比較が必要となり、これは 1 秒の許容範囲をはるかに超えているためです。 有効な解決策は、テスト ケースごとに問題を線形または線形演算に近いものに削減する必要があります。 

ゼロの場合、微妙なエッジケースが表示されます。 ゼロが正の数値とペアになっている場合、XOR は正の数値と等しくなりますが、AND はゼロとなり、条件に違反します。 これは、ゼロは他のゼロとのみ共存できることを意味します。 

もう 1 つの重要なシナリオは、数値の値が「近い」ように見えても、上位ビットが異なる場合です。 たとえば、5 (101)、6 (110)、および 7 (111) は、5 と 6 のようなペアは複数のビットで異なっていても、サイズ 3 の有効なグループを形成します。 「数値は似ているはずだ」のような単純なヒューリスティックは十分正確ではありません。 正確さは完全に、最も高い設定ビットの構造に依存します。 

## アプローチ

 ブルートフォース戦略は簡単です。すべてのサブセットを試し、その中のすべてのペアの条件を検証します。 サブセットを並べ替えて有効性を段階的にチェックする、少し極端ではないバージョンでも、結局はペアを繰り返しチェックすることになります。 サイズ k のサブセットの場合、検証には O(k^2) のコストがかかり、サブセットの数が指数関数的に多いため、このアプローチは N が 10^5 までの場合はすぐに無効になります。 

重要な観察は、いつ不等式が破綻する可能性があるかを分析することから得られます。 2 つの数字 a と b を考えてみましょう。 両者が異なる最上位ビットでは、XOR には 1 があり、AND には 0 があります。この単一ビットは XOR に 2^k の値を与えるため、比較で支配的になりますが、AND はその位置では何も寄与できません。 AND に 2^k 項がまだ含まれていない場合、下位ビットで補償することは不可能です。 これは、2 つの数値の最高設定ビットが異なる場合は常に、条件が失敗することを意味します。 

ここで、2 つの数値が同じ最上位ビットを共有する場合に何が起こるかを考えてみましょう。 両方ともそのビットが設定されているため、AND にもそのビットが設定されており、少なくとも 2^k に寄与します。 XOR ではそのビットをまったく設定できないため、その値は厳密に 2^k 未満になります。 これにより、そのようなグループ内のすべてのペアに対して不等式が成り立つことが保証されます。 

これにより、問題は、最上位の設定ビットの位置によって数値をグループ化し、最大のグループを選択することになります。 ゼロにはビットが設定されておらず、すべての正の数に対して失敗するため、ゼロは個別に処理する必要があります。

 ## アルゴリズムのチュートリアル

 ### 中心的なアイデア: 最上位ビットによるグループ化

 ## アルゴリズムのチュートリアル

1. 各数値について、その最上位の設定ビットの位置を決定します。 これは、数値の支配的なスケールを定義するため、互換性にとって重要な唯一の機能です。 
2. 値は 2^30 で制限されるため、0 ～ 29 の可能なビット位置ごとに周波数カウンタを維持します。 
3. ゼロはどのビット グループにも属さず、ゼロ以外の値と混合できないため、存在するゼロの数を数えることによってゼロを個別に扱います。 
4. ゼロ以外の数値ごとに、その最上位ビットのカウンターをインクリメントします。 
5. テスト ケースの答えは、すべてのビット カウンタとゼロ カウンタの最大値です。 

この貪欲な選択が正しい理由は、有効なサブセットには同じ最上位セット ビットを共有するすべての要素がなければならず、そうでない場合、少なくとも 1 つのペアが不等式に違反するためです。 この制限が適用されると、同じグループ内のすべての要素は相互に互換性があるため、グループ全体を取得することが常に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        arr = list(map(int, input().split()))

        cnt = [0] * 30
        zero = 0

        for x in arr:
            if x == 0:
                zero += 1
                continue

            msb = x.bit_length() - 1
            cnt[msb] += 1

        print(max(max(cnt), zero))

if __name__ == "__main__":
    solve()
```実装は Python に依存します`bit_length()`数値ごとに O(1) 時間で最高の設定ビットを計算します。 配列`cnt`各ビット グループに分類される数値の数を格納します。 別個の`zero`カウンタは、選択されたすべての要素がゼロになる可能性がある特殊な場合の正確さを保証します。 

最終的な答えは、すべてのグループにわたる最大頻度です。これは、有効なサブセットはそのような 1 つのグループ内に完全に含まれている必要があり、そのグループのすべての要素を取得することが常に安全であるためです。 

## 実用的な例

 ### 例 1

 入力配列:`[6, 8, 2, 7, 2, 5]`| 値 | バイナリ | MSB | グループ数 |
 | --- | --- | --- | --- |
 | 6 | 110 | 2 | 1 |
 | 8 | 1000 | 3 | 1 |
 | 2 | 010 | 1 | 2 |
 | 7 | 111 | 2 | 2 |
 | 5 | 101 | 2 | 3 |

 ここで、最大のグループは MSB = 2 で、3 つの要素: 6、7、および 5 です。これらはすべて、同じ最上位ビットを共有し、すべてのペアが不等式を満たすため、共存できます。 

### 例 2

 入力配列:`[0, 0, 1, 2]`| 値 | グループ |
 | --- | --- |
 | 0 | ゼログループ |
 | 1 | MSB 0 |
 | 2 | MSB 1 |

 ゼロ グループのサイズは 2 ですが、他のグループのサイズはそれぞれ 1 です。 ゼロはゼロ以外の値と混合できないため、最適なサブセットは 2 つのゼロです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import log2

    input = sys.stdin.readline
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        arr = list(map(int, input().split()))
        cnt = [0] * 30
        zero = 0
        for x in arr:
            if x == 0:
                zero += 1
            else:
                cnt[x.bit_length() - 1] += 1
        out.append(str(max(max(cnt), zero)))
    return "\n".join(out)

 ## 特殊なケース

 ゼロヘビー配列は、ビットが設定されていない数値の特別な処理をテストします。 このような場合、すべての要素はゼロ グループに属し、競合するペアが存在しないため、アルゴリズムは完全な数を正しく返します。 

2 番目のエッジ ケースには、密な 2 進数が混在する 2 のべき乗など、複数のビット レベルにまたがる数値が含まれます。 それらの値は数値的に近い場合でも、MSB が異なるため、別のグループに分けられます。 このアルゴリズムは各グループを正しく分離し、無効な組み合わせを回避します。
