 ## 解決策
 ## 問題の理解

 各ノードが値を持つルート付きツリーが与えられます。 パラメータに依存する制約の下でノードのサブセットを構築したいと考えています$K$。 制約はエッジに関するものではなく、祖先に関するものです。つまり、ノードを選択すると、その祖先の数も選択されることに制限されます。 

固定の場合$K$、有効な選択は、選択されたノードごとに次のようなノードのサブセットです。$v$ツリー内のすべての祖先の中で、せいぜい$K-1$そのうちからも選ばれます。 言い換えれば、ルートからノードへのパスに沿って、選択したノードをあまりにも多く密に「スタック」することはできません。 

それぞれについて$K$1から$N$、その制約の下でノード値の可能な最大合計を計算する必要があります。 

制約$N \le 2 \cdot 10^5$すべてのテストケースにわたって、個別にソリューションを再計算するものから私たちを遠ざけます。$K$またはサブセットごとに。 どのソリューションでも、全体にわたって構造を再利用する必要があります。$K$価値観。 素朴な解釈では、DP を試してみることになります。$K$、すぐに次のようになります$O(N^2)$あるいはさらに悪いことに。 

微妙なエッジケースがチェーンに現れます。 ツリーがラインであり、値が高低を交互に繰り返す場合、根から葉までの貪欲な包含は次のように大幅に変化します。$K$が増加します。 各ノードをその祖先選択履歴から独立して扱う解決策は失敗します。実現可能性はローカル構造ではなくグローバル祖先密度に依存するためです。 

## アプローチ

 ブルートフォース戦略では、それぞれの最適なサブセットを計算しようとします。$K$別に。 固定の場合$K$、これは、パス上で選択された祖先の数を追跡する状態を含むツリー DP になります。$O(NK)$あるいは、テストケースごとの複雑さがさらに悪化します。 以来$K$までの範囲$N$、これは次のように退化します。$O(N^2)$、大きすぎます。 

重要な観察は、制約が単調であるということです。$K$。 セットが有効な場合$K$、それより大きな場合にも有効です。$K$。 これはつまり$F(K)$は非減少関数であり、最適解の構造は毎回独立して変化するのではなく、徐々に変化します。$K$。 

さらに深い洞察は、この制約により、ルートからノードへのパス上に表示できる選択されたノードの数が効果的に制限されるということです。 これは、パスに沿った「深さの重複」を制御しながらノードを選択することに相当します。これは、グローバル順序付け引数を介して処理される値と構造制約によってソートされたノードに対する寄与問題に変換できます。 

これにより、各ノードが祖先から「継承」する選択の数を維持しながら、値の降順でノードを選択するという問題を再解釈することができます。 各ノードは、そのパスに沿って選択された祖先の現在のクォータの下でまだ実行可能である場合に貢献します。 

このように考えると、$K$これは、すべてのノードにわたって容量制約を均一に緩和することに相当します。これにより、すべてのノードを計算できるようになります。$F(K)$ツリー構造上の単一のグローバル DP とアクティブな選択のマルチレベルのカウントを 1 つのパスで使用します。

 ## アルゴリズムのチュートリアル

 ツリーのルートをノード 1 に設定します。ノードごとに、その深さを計算し、サブツリー構造を維持します。 

最適な合計ではより高い値を優先する必要があるため、値の降順でノードを処理します。 

ルートへのパスに沿って選択されたノードがいくつ存在するかを追跡する構造を維持します。 すべてのパスを明示的に保存する代わりに、DFS 順序に対するフェンウィックのような蓄積を維持します。 

### ステップ

 1. ツリーをルート化し、DFS の開始時間と終了時間を計算します。 

これにより、各サブツリーが区間に線形化され、祖先関係が範囲関係になるようにします。 
2. ノードを値の降順に並べ替えます。 

最も高い値から順にノードをアクティブ化しようとします。 
3. ノードが現在選択されているかどうかを表す DFS 順序で BIT (フェンウィック ツリー) を維持します。 

ノードは、ルート パス上で選択されたノードの数が以下の場合に実行可能です。$K$。 
4. ソートされた順序で各ノードについて、現在選択されている祖先の数をクエリすることによって、その包含をシミュレートします。 
5. 現在のしきい値の下で有効な場合、そのノードを BIT で選択済みとしてマークします。 
6. すべてを計算するには$F(K)$、各ノードにはクリティカルしきい値があることがわかります。$K_v$: 最小値$K$これにより、より価値の高い選択を指定して含めることができます。 このしきい値はノードをアクティブ化するときに計算します。 
7. 最後に、寄与を集計します。各ノードはその値をすべてのノードに寄与します。$K \ge K_v$。 これは差分配列になります$K$。 

### なぜ効果があるのか

 重要な不変条件は、値の降順でノードを処理する場合、ノードを含めることを決定するたびに、より高い値のノードがすべてすでに固定されていることです。 したがって、ノードに対して選択された祖先の数は、決定時に完全に決定されます。 これにより、その実現可能性は後で変更されないプレフィックス構造のみに依存するため、各ノードのアクティブ化しきい値は明確に定義され、独立しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        tin = [0] * n
        tout = [0] * n
        parent = [-1] * n
        depth = [0] * n
        timer = 0

        stack = [(0, -1, 0)]
        order = []

        while stack:
            v, p, state = stack.pop()
            if state == 0:
                tin[v] = timer
                timer += 1
                parent[v] = p
                order.append(v)
                stack.append((v, p, 1))
                for to in g[v]:
                    if to == p:
                        continue
                    depth[to] = depth[v] + 1
                    stack.append((to, v, 0))
            else:
                tout[v] = timer - 1

        bit = [0] * (n + 5)

        def add(i, v):
            i += 1
            while i <= n:
                bit[i] += v
                i += i & -i

        def sum_(i):
            s = 0
            i += 1
            while i > 0:
                s += bit[i]
                i -= i & -i
            return s

        def path_sum(v):
            return sum_(tin[v])

        nodes = sorted(range(n), key=lambda x: -a[x])

        # each node gets minimum K at which it can be selected
        Kmin = [1] * n

        active = []

        for v in nodes:
            # number of already selected ancestors
            cnt = path_sum(parent[v]) if parent[v] != -1 else 0
            Kmin[v] = cnt + 1
            add(tin[v], 1)

        # difference array over K
        diff = [0] * (n + 3)
        for v in range(n):
            k = Kmin[v]
            diff[k] += a[v]
            diff[n + 1] -= a[v]

        cur = 0
        res = []
        for k in range(1, n + 1):
            cur += diff[k]
            res.append(str(cur))

        print(" ".join(res))

if __name__ == "__main__":
    solve()

 ツリー:```

|

```値:```

```ノードを 3、2、1 の順序で処理します。 

ノード 3 には選択された祖先がありません → Kmin = 1

 ノード 2 には選択された祖先がありません → Kmin = 1

 ノード 1 には選択された祖先がありません → Kmin = 1

 したがって、全員がすぐに貢献します。 

| ノード | 値 | クミン |
 | --- | --- | --- |
 | 3 | 3 | 1 |
 | 2 | 2 | 1 |
 | 1 | 1 | 1 |

 それで:

 - F(1)=6
 - F(2)=6
 - F(3)=6

 これは、制約が十分に緩い場合、すべてのノードが常に最適になることを示しています。

```値:```

 ## 特殊なケース

 主要なエッジケースは、すべての値が減少している深いチェーンです。 そのような状況では、祖先の制約は急速に蓄積され、高くなるだけです。$K$値を指定すると、より深いノードを選択できるようになります。 各ノードの Kmin は DFS 順序で既にアクティブ化されている先祖にのみ依存し、より深いノードが自然に高いしきい値を受け取るようにするため、アルゴリズムはこれを処理します。
