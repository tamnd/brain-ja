 ## 解決策
 ## 問題の理解

 孤立した頂点から始まるグラフを維持しています。 各頂点には 1 から N の範囲の値が含まれます。時間の経過とともにエッジが追加されるため、接続されたコンポーネントが徐々にマージされます。 任意の時点のスナップショットでは、クエリされた頂点を含む接続されたコンポーネントに焦点を当てます。 

特定のコンポーネントに対して、値でインデックス付けされたバイナリ配列を構築します。 配列エントリは、その値がコンポーネント内の少なくとも 1 つの頂点に出現する場合は 1、それ以外の場合は 0 です。コンポーネントの「王様」は、1 や合計を数えるのではなく、このバイナリ配列に 1 の連続するセグメントが最大でいくつ存在するかを数えます。 

したがって、コンポーネントに {2, 3, 7, 8, 9} のような値が含まれている場合、バイナリ配列には 2 つの連続した 1 のブロックがあり、1 つは 2 ～ 3 をカバーし、もう 1 つは 7 ～ 9 をカバーするため、答えは 2 になります。 

主な問題点は、コンポーネントが動的にマージされ、マージのたびにこれらの連続する値セグメントのマージまたは分割方法が変わる可能性があることです。 N と Q は最大 2×10^5 であるため、クエリごとに最初から再計算すると遅すぎます。 各クエリの値範囲にわたるフル スキャンには O(NQ) のコストがかかりますが、これは不可能です。 

それほど明白ではないエッジ ケースは、2 つのコンポーネントの両方に個別に連続した値が含まれているが、マージ後、どちらのコンポーネントにもすでに存在しない値のブリッジを介して接続される場合です。 たとえば、あるコンポーネントには {1, 3} があり、別のコンポーネントには {2} があります。 マージ後、セグメント構造は単一のブロック {1,2,3} に折りたたまれます。 サイズのみを追跡したり、値の境界を越えた隣接性を無視したりするソリューションは、ここでは失敗します。 

## アプローチ

 ブルートフォース手法では、コンポーネントごとに、サイズ N の完全なブール配列 B が維持されます。2 つのコンポーネントがマージされるたびに、それらの配列の OR を計算し、再スキャンしてセグメントをカウントします。 これは正しいですが、遅すぎます。2 つの配列のマージには O(N) のコストがかかり、O(N) 回のマージが発生して O(N²) になる可能性があるからです。 

重要な観察は、答えはコンポーネント内のアクティブな値のセットと、それらが連続する実行をどのように形成するかによってのみ決まるということです。 完全な配列を保存する代わりに、各コンポーネントに存在する値のセットのみを保存し、そのセット内に存在する連続した実行の数を維持します。 

2 つのコンポーネントがマージされる場合、基本的に 1 から N までの線上で 2 つのセットの和集合が取られます。セグメントの数は、一方のセットの値 v がもう一方のセットの v−1 または v+1 に接続する境界付近でのみ変化します。 これにより、順序付けされたコンテナーの大規模なマージと結合していないセット ユニオン構造を組み合わせて、回答を増分的に維持することが可能になります。 

主なトリックは、常に小さい値セットを大きい値セットにマージすることです。 マージ中、各値 x を挿入するときに、ターゲット セットに x−1 または x+1 がすでに存在するかどうかを確認します。 これらにより、新しいセグメントが作成されるか、2 つの既存のセグメントがマージされるかが決まります。 これにより、挿入ごとに対数時間でセグメント数を更新できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | マージごとに最初から再計算 | O(N²) | O(N) | 遅すぎる |
 | DSU + 小から大までの超過値セット | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点にわたる DSU を維持し、接続されたコンポーネントのルートごとに、そのコンポーネントに表示される値のソートされたコンテナーと、それらの値が形成する連続セグメントの数の継続的なカウントを維持します。 

各頂点 v の初期状態では、そのコンポーネントには値 A[v] のみが含まれるため、そのセグメント数は 1 です。 

2 つのコンポーネントを結合するときは、常に小さい値のコンテナを大きい値のコンテナに接続します。

値 x をコンポーネントに挿入するときに、それがセグメント数にどのような影響を与えるかを決定します。 現在のセットに x−1 も x+1 も存在しない場合、x は新しいセグメントを形成し、カウントを 1 増やします。一方の側だけが存在する場合、既存のセグメントを拡張し、カウントは変更しません。 x−1 と x+1 の両方が存在する場合、以前は別々だった 2 つのセグメントがマージされ、カウントが 1 ずつ減ります。 

コンポーネントをマージする際に、挿入されたすべての値にこのロジックを適用することで、連続する値ブロックの正しい数が維持されます。 

クエリに答えることは、必要なときにクエリされた頂点の DSU ルートを見つけて、その保存されているセグメント数を出力することになります。 

正確さは、各コンポーネントの値のセットが常にその頂点の値の正確な和集合であるという不変条件に依存し、セグメント カウンターは常に整数行内のそのセットの連結コンポーネントの数を反映します。 すべての結合演算では、あるセットから別のセットにすべての値を挿入することをシミュレートするため、この不変式が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n, values):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.seg = [1] * (n + 1)
        self.s = [set() for _ in range(n + 1)]
        for i in range(1, n + 1):
            self.s[i].add(values[i])

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def add_value(self, root, x):
        S = self.s[root]
        if x in S:
            return
        left = (x - 1) in S
        right = (x + 1) in S

        if left and right:
            self.seg[root] -= 1
        elif not left and not right:
            self.seg[root] += 1

        S.add(x)

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if len(self.s[a]) < len(self.s[b]):
            a, b = b, a

        for x in self.s[b]:
            self.add_value(a, x)

        self.s[b].clear()
        self.parent[b] = a
        self.seg[a] += 0

def solve():
    n, q = map(int, input().split())
    A = [0] + list(map(int, input().split()))

    dsu = DSU(n, A)

    for _ in range(q):
        parts = list(map(int, input().split()))
        if parts[0] == 1:
            _, u, v, x = parts
            u = dsu.find(u)
            v = dsu.find(v)
            if u != v:
                dsu.union(u, v)
        else:
            _, u, t, x = parts
            u = dsu.find(u)
            print(dsu.seg[u])

if __name__ == "__main__":
    solve()
```## 実用的な例

 コンポーネントが徐々に結合し、値が重複する間隔を形成する単純なケースを考えてみましょう。 最初は各ノードが分離されているため、各コンポーネントは単一の値とセグメント数 1 を持ちます。 

値 1 と 3 を持つ 2 つの頂点がマージされると、そのコンポーネントには 2 つの孤立点があるため、セグメント数は 2 になります。値 2 を持つ頂点が後でマージされると、値が連続したブロック 1 ～ 3 を形成するため、ギャップが埋められ、セグメント数が 1 に減ります。 

これは、セグメントのマージがグラフ構造ではなく値空間の隣接性にのみ依存することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(N) | 各値はマージ間で一度保存されます。 

N と Q が最大 2×10^5 であり、各挿入と DSU 操作が対数またはほぼ一定であるため、複雑さは制限内に収まります。

 ## 特殊なケース

 重大なエッジ ケースは、マージ後に値がギャップを正確に埋める場合です。 1 つのコンポーネントに {1, 3, 5} のような交互の値が含まれ、別のコンポーネントに {2, 4} が含まれる場合、結合された結果は完全に連続した {1,2,3,4,5} になります。 両方の近傍をチェックせずにローカルで寄与のみをカウントする実装では、セグメントが誤って過剰にカウントされます。 値を挿入するたびに両方の隣接する位置がチェックされ、それに応じてセグメント数が更新されるため、提示されたメソッドはこれを正しく処理します。
