 ## 解決策
 ## 問題の理解

 一連の要素が与えられ、各要素には値と色があります。 シーケンスの順序は固定されていますが、値は静的ではありません。 時間の経過とともに、ほぼすべての色に影響を与えるグローバル アップデートを一度に適用し、特定の色に関する質問にも答えます。 

操作は 2 つあります。 最初の操作では色を選択します`Col`そして数字`X`、色が異なるすべての要素を増やします。`Col`による`X`。 2 番目の操作では色を選択します`Col`そして閾値`Y`、その色の要素のみを元の順序で調べます。 このフィルタリングされたシーケンスから、合計が最大以下である最長のプレフィックスが必要です。`Y`。 

問題は、更新がグローバルで繰り返されるため、各要素の値が更新の回数と毎回除外される色によって異なることです。 クエリごとにすべての要素を更新する単純なシミュレーションでは、要素とクエリの両方の数が大きくなる可能性があるため、すぐに時間がかかりすぎます。 

この制約は、クエリごとにすべての要素にアクセスするソリューションはコストが高すぎることを意味します。 最大 200,000 の要素と 200,000 のクエリを使用すると、O(NQ) アプローチは最悪の場合でも約 400 億の操作に達しますが、これは実行不可能です。 したがって、要素値を繰り返し再計算することを避け、代わりに何らかの集合構造を維持する必要があります。 

2 番目のクエリでは、微妙な問題が発生します。動的に変化するシーケンスに対するプレフィックスの合計が必要ですが、その変化は、毎回 1 色を選択的に除外する過去の更新に依存します。 各要素の現在の値をオンデマンドで再計算する不用意なアプローチでは、すべての更新が繰り返し再適用されることになり、これも遅すぎます。 

小さな例で落とし穴を示します。 カラー 2 の 1 つの要素を除いてすべての要素がカラー 1 であり、多くの更新でカラー 1 が除外されるとします。カラー 1 要素の値はカラー 2 要素とは異なる方法で変化するため、注意深く追跡しないとクエリごとの再計算にコストがかかり、エラーが発生しやすくなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 配列を明示的に管理します。 タイプ 1 のクエリごとに、すべての要素を反復処理して追加します。`X`色が違う人たちへ`Col`。 タイプ 2 クエリごとに、フィルター処理された色の配列を構築します。`Col`、プレフィックスの合計を計算し、合計が最大以下である最長のプレフィックスを見つけます。`Y`。 これは定義に直接従うので正しいですが、各更新のコストは O(N) であり、各クエリのコストも O(N) になる可能性があり、結果として O(NQ) となり、制約に対して大きすぎます。 

重要な点は、更新が 1 色を除くすべての要素で均一であることです。 個々の要素を更新する代わりに、グローバル増分が適用された回数を追跡し、特定の色を除外した更新の影響を差し引くことができます。 各要素の値は、その初期値にグローバル寄与分を加えたものから、その色を除外した更新による寄与分を差し引いたものとして表すことができます。 

この観点により、更新の影響を全体的な累積と色ごとの補正に分けることができます。 この分解された形式で値を表現できるようになると、すべての要素を直接変更する必要がなくなりました。 各色について、その要素の集計統計を維持でき、クエリについては、事前に計算された構造と補正項を使用してプレフィックスの合計を計算できます。 

また、各色のプレフィックス評価を高速に行う必要もあります。 特定の色の要素は固定された順序で表示されるため、色ごとの初期値のプレフィックス合計を事前計算し、現在のグローバル状態で有効なプレフィックス合計を評価できる構造を維持できます。 次に、各クエリは、プレフィックス長の一次関数が Y 内に収まる最大のプレフィックスを見つけることに帰着します。これは、色ごとの二分探索を使用して解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | O(N) | 遅すぎる |
 | 最適化された分解 + 前置検索 | O((N + Q) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのインデックスを色ごとにグループ化し、色ごとに元の順序での位置のリストと初期値のプレフィックス合計を事前計算します。 

また、2 つのグローバル数量も維持します。 1 つ目は、タイプ 1 更新の合計数に X 寄与を乗算したもので、除外が存在しなかった場合に各要素がどれだけ増加するかを表します。 2 番目は、各色について、その色を除外した増分の合計量です。 

1. 各色について、その色に属する要素の配列を元の順序でプレフィックスの合計とともに事前計算します。 これにより、カラー グループの任意のプレフィックスに対する高速合計クエリが可能になります。 
2. グローバルカウンターを整備しています`G`除外を無視して、すべてのタイプ 1 操作からのすべての要素に適用される合計の追加効果を表します。 
3.各色ごとに`c`、私たちは維持します`bad[c]`、色を除外したタイプ 1 の更新の合計寄与度`c`。 これは色の要素がどのくらいあるかを表します`c`グローバルベースラインと比較して受信しませんでした。 
4. タイプ 1 クエリを処理する場合`(Col, X)`、色を除くすべての要素が増加すると解釈します`Col`による`X`。 配列を更新する代わりに、グローバル構造を更新します。`G`による`X * N`概念的には調整しますが、より重要なのは調整することです`bad[Col]`色が回避する寄与の合計を加算することによって。 これにより、後で暗黙的に正しい要素ごとの値を再構築できるようになります。 
5. タイプ 2 クエリの場合`(Col, Y)`、その色の配列のみを調べます。 このカラー グループの i 番目の要素の値は、その初期値にプラスされた値になります。`G`マイナス`bad[Col]`。 このシフトは色全体にわたって均一であるため、プレフィックスの各要素は同じ加法定数だけ増加します。 
6. したがって、最初の合計は`k`色の要素`Col`になる`prefix_initial[k] + k * (G - bad[Col])`。 
7. 最大のものが必要です`k`この式が最大で`Y`。 二分探索を行います`k`プレフィックス合計配列を使用します。 

重要な不変条件は、どの色の要素に対しても`c`、その現在値は常に、元の値にグローバル加法項を加えたものから色固有の補正項を引いたものとして表現できます。 これにより、配列を明示的に変更しなくても、すべてのクエリに一貫して応答することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    A = list(map(int, input().split()))
    C = list(map(int, input().split()))
    Q = int(input())

    from collections import defaultdict

    pos = defaultdict(list)
    val = defaultdict(list)

    for i in range(N):
        pos[C[i]].append(i)
        val[C[i]].append(A[i])

    pref = {}
    for c in pos:
        s = [0]
        for v in val[c]:
            s.append(s[-1] + v)
        pref[c] = s

    # global additive effect
    global_add = 0
    # per color compensation
    bad = defaultdict(int)

    # number of elements per color
    sz = {c: len(pos[c]) for c in pos}

    for _ in range(Q):
        t, Col, X = map(int, input().split())
        if t == 1:
            # all except Col increase by X
            global_add += X
            bad[Col] += X
        else:
            Y = X
            if Col not in pos:
                print(0)
                continue

            g = global_add - bad[Col]
            arr_pref = pref[Col]

            # binary search for max k
            lo, hi = 0, len(arr_pref) - 1
            ans = 0

            while lo <= hi:
                mid = (lo + hi) // 2
                total = arr_pref[mid] + mid * g
                if total <= Y:
                    ans = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 番目のタイプのクエリが関連するサブセットのみを扱うように、要素を色ごとにグループ化します。 プレフィックス合計により、元の合計と線形シフトの高速計算が可能になります。`g`すべての更新をコンパクトにモデル化します。 二分探索により、制約を満たす最大プレフィックス長が見つかります。 

微妙な点としては、`g`は色のすべての要素にわたって均一であり、これによりプレフィックス合計調整が有効になります。 この均一性がなければ、プレフィックスの合計は十分ではありません。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての要素が同じ色に属する場合です。 その状況では、すべてのタイプ 1 更新でその色が除外され、どの要素も増分を受け取りません。 アルゴリズムはこれを正しく処理します。`bad[Col]`すべての更新を蓄積し、グローバル コントリビューションをキャンセルして、実質的なシフトをゼロにします。 

もう 1 つのケースは、多数の小さな要素と非常に大きな Y がある場合です。プレフィックスの合計が Y を超えることはないため、バイナリ検索では常に完全な長さが返されます。均一なシフトによりプレフィックスの合計の単調性が維持されるため、検索空間は適切に動作します。 

3 番目のケースは、更新が異なる色の除外を交互に行う場合です。 分解により、各色がどの程度除外されたかを個別に追跡できるため、履歴が失われることはありません。 各更新はグローバル状態と 1 つの補正バケットのみに寄与するため、何度も更新を交互に行った後でも、実効値は一貫したままになります。
