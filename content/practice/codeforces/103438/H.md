 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、ただし、この順列の位置は色によってグループ化されています。 2 種類のアクションを使用して順列を修正できます。固定コストを払って任意の 2 つの要素を交換できます。$S$また、色のクラスを選択し、別のコストを払って、現在その色の位置にあるすべての要素を任意に並べ替えることもできます。$C_i$その色の操作のために。 

重要な点は、色は値ではなく位置に属するということです。 スワップでは、色を変更せずに位置間で値を移動しますが、色の操作では、1 回の有料移動で 1 つのカラー クラス内の値を自由に再配置できます。 目標は、最小の総コストで順列を恒等順列に変換することです。 

制約によって課せられる構造が、ソリューションの重要な推進力となります。 順列サイズは最大で$10^5$ただし、色の数は最大 5 です。これは、色のサブセットごとに状態を追跡しようとするソリューションが実行可能であることをすぐに示唆しています。$2^5 = 32$サブセット。 一方、二次または三次のものはすべて、$n$大幅に最適化するか、テストごとに線形に削減しない限り、遅すぎる可能性があります。 

グリーディ スワップだけで考えると、微妙な問題が生じます。 単純な戦略は、置換サイクル分解を計算して支払うことです。$S$スワップの改善ごとに異なりますが、カラー操作はローカルでサイクルを完全に再構築できます。 これは、サイクルが固定されていないことを意味します。カラー操作は、カラー グループ内の順列グラフを「再形成」する可能性があり、グローバルに必要なスワップ数を変更する方法でサイクルをマージまたは破壊する可能性があります。 

誤解を招きやすいケースとしては、色に複数のサイクルの要素が含まれている場合があります。 カラー操作を使用しない場合、これらのサイクルは独立したままとなり、複数のスワップが強制されます。 単一のカラー操作を使用すると、それらの同じ要素を再配置してより適切に配置できるため、複数の交換操作を 1 回の再構築ステップに減らすことができる可能性があります。 サイクルを不変として扱うソリューションはここで失敗します。 

## アプローチ

 色の操作を無視すると、問題は、任意のスワップを使用して順列を並べ替えるとコストがかかるという古典的な事実に帰着します。$S \cdot (n - \text{cycles})$最適な分解プロセスでは、スワップごとにサイクル数が 1 つ減少するためです。 

色の操作のみを使用する場合、各色はコストを考慮してその位置を個別に並べ替えることができます。$C_i$そして、各色のグループ内で可能な限り多くの順列を「修正」しようとすることができます。 ただし、スワップはグローバルであり、すべてを接続するため、これでも異なる色の相互作用を完全に解決することはできません。 

重要な構造上の観察は、色が 5 つしかないため、高価な「自由順列」操作を適用するかどうかを色ごとに選択できるということです。 色のサブセットが選択されると、問題は次のようになります。選択した色の中で値を任意に再配置できます。 選択されていない色の内側にはできません。 これにより、問題は変更された順列構造の評価と、その派生構造の最小スワップ コストの計算に変わります。 

したがって、解決策はすべてを試すことです$2^k$色のサブセット。 サブセットごとに、選択した色の内部を自由に並べ替えた後に達成可能な最適な配置を計算し、結果の並べ替えを修正するために必要なスワップの数を計算します。 

難しいのは、固定サブセットについて、最適な再配置後に何サイクルが残るかを計算することです。 色の内部の再配置は、位置ごとに独立して任意に行われるわけではありません。 これはそのカラー グループ内の完全な順列であるため、制約されたマッチングの問題ですが、位置とそのターゲット値の間のサイクル形成を最大化することのみを考慮しているため、グループごとに貪欲に解決できます。

 ## アルゴリズムのチュートリアル

 カラー操作でアクティブ化することを決定した色のサブセットを修正します。 

1. 色のすべてのサブセットを反復処理します。 各サブセットは、内部で自由に並べ替えることができる色を表します。 
2. 固定サブセットの場合、各アクティブなカラー グループがその要素を任意に並べ替えられるようにすることで、概念的に順列を変更します。 これは、各アクティブな色の内部で、その位置とその位置に現在存在する値の間の全単射を自由に選択できることを意味します。 
3. 順列の「最適化された」バージョンを再構築します。 各アクティブなカラー グループ内で、すでに正しい目的地を指している位置の数を最大化する方法で、値を位置に貪欲に一致させます。 これは、グループ内でソートし、互換性のあるターゲットをペアにすることによって行われます。 
4. 選択したサブセットに対して可能な限り最良の配置を構築した後、結果として得られる置換グラフのサイクル数を計算します。 
5. この構成のスワップコストは次のとおりです。$S \cdot (n - \text{cycles})$これは、スワップごとにサイクル数がちょうど 1 つ減少するためです。 
6. 選択した色をアクティブにするコストを追加します。これは次の合計です。$C_i$サブセット全体にわたって。 
7. すべてのサブセットの最小値を取得します。 

正確さは、アクティブな色の固定サブセットについて、サイクル構造に影響を与える可能性のある各アクティブな色のグループ内で考えられるすべての再配置を徹底的に考慮するという不変条件から得られます。 最適なソリューションはいずれもサブセットの選択に対応し、そのサブセット内には、計算された最大サイクル カウントを達成する配置が存在します。 

これが機能するのは、スワップがグローバルなサイクル分解にのみ影響するのに対し、カラー操作は内部の再配置の自由度にのみ影響するためです。 サブセットが固定されると、順列構造は各アクティブ グループ内の内部再ラベル付けまで決定的になり、サイクルを最大化することは、そのような再ラベル付けの最適なものを選択することと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_cycles(arr):
    n = len(arr)
    vis = [False] * n
    res = 0
    for i in range(n):
        if not vis[i]:
            res += 1
            j = i
            while not vis[j]:
                vis[j] = True
                j = arr[j]
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        data = list(map(int, input().split()))
        S = data[0]
        C = data[1:]
        
        p = list(map(lambda x: x - 1, input().split()))
        col = list(map(lambda x: x - 1, input().split()))
        
        pos_in_color = [[] for _ in range(k)]
        for i in range(n):
            pos_in_color[col[i]].append(i)
        
        ans = S * (n - 1)
        
        for mask in range(1 << k):
            cost = 0
            for i in range(k):
                if mask & (1 << i):
                    cost += C[i]
            
            arr = p[:]
            
            for c in range(k):
                if mask & (1 << c):
                    idx = pos_in_color[c]
                    vals = [arr[i] for i in idx]
                    vals.sort()
                    for i, v in zip(sorted(idx), vals):
                        arr[i] = v
            
            cycles = count_cycles(arr)
            cost += S * (n - cycles)
            ans = min(ans, cost)
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードはビットマスクを使用してすべての色のサブセットを反復します。 サブセットごとに、順列の作業コピーを作成します。 アクティブ化された色ごとに、その色のインデックスを収集し、現在の値を抽出し、インデックスと値の両方を並べ替えて、それらを貪欲に割り当てます。 これにより、グループ内の整合性を最大化する最適な内部順列が実現されます。 

順列を再構築した後、循環カウント ルーチンは残りのコンポーネントの数を計算します。 スワップ コストはサイクル分解から直接導出され、その後、カラー アクティベーション コストが追加されます。 

微妙な点は、インデックスと値を個別に並べ替えることで、各グループ内で最大限のペアリングが可能になるということです。 これにより、サブセットごとの明示的なマッチング アルゴリズムやグラフ アルゴリズムが必要なくなります。
