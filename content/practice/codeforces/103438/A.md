 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられているとします。`s`そして`t`、どちらも 1 から 1 までのインデックスが付いています。`n`。 位置で始まるすべての部分文字列について`l`そしてその位置で終了します`r`、部分文字列を比較します`s[l..r]`と`t[l..r]`標準の辞書編集順を使用します。 タスクは、次の部分文字列の数を数えることです。`s`辞書編集上、対応する部分文字列よりも厳密に小さい`t`。 

重要な詳細は、比較は常に整列された部分文字列間で行われるということです。つまり、任意の部分文字列を比較することはありません。`s`そして`t`、同じものを共有するもののみ`(l, r)`間隔。 各部分文字列の比較は通常の辞書順序に従います。不一致が見つかるか、1 つの文字列が終わるまで、左から右にスキャンします。 すべての文字が一致する場合、文字列は等しいため、答えには影響しません。 

制約`n ≤ 200000`部分文字列をすべての文字ごとに明示的に比較するソリューションは直ちに除外されます。`(l, r)`ペア。 がある`O(n^2)`部分文字列、さらには単一の文字列でも`O(n)`部分文字列ごとの比較は次のようになります`O(n^3)`、それは完全に不可能です。 

さらに微妙な観察としては、たとえ完全な比較を避けたとしても、各部分文字列を独立して処理するソリューションは、繰り返しの作業が多くなる可能性が高いということです。 この構造は、重複する部分文字列間で比較を再利用する方法が必要であることを示唆しています。 

いくつかの危険な状況については、覚えておく価値があります。 

もし`s`そして`t`が同一である場合、厳密に小さい部分文字列はないため、答えはゼロになる必要があります。 

もし`s`辞書編集的には以下より小さい`t`グローバルでは、後の部分文字列が逆方向に異なる可能性があるため、すべての部分文字列が適格であることを自動的に意味するわけではありません。 

たとえば、次の場合`s = "ba"`そして`t = "aa"`、次に完全な文字列`s[1..2]`より大きい`t[1..2]`、ただし部分文字列`s[2..2] = "a"`等しい`t[2..2]`、何も貢献しません。 

一般的な障害モードは、相違点のプレフィックスまたはサフィックスを比較するだけで十分であると想定していることです。 比較は、各部分文字列内の最初の不一致に応じて異なります。`(l, r)`。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのペアについて`(l, r)`、比較します`s[l..r]`そして`t[l..r]`不一致が見つかるか、一致するまで 1 文字ずつ`r`。 最初の異なる位置にある場合`k`我々は持っています`s[k] < t[k]`、部分文字列を数えます。 

これは正しいですが、高価です。 がある`n(n+1)/2`部分文字列、各比較は最大でスキャンできます`O(n)`文字、につながる`O(n^3)`最悪の場合。 早期に停止した場合でも、繰り返し文字などの敵対的な入力により、長い比較が繰り返し行われます。 

重要な観察は視点を反転することです。すべての部分文字列の比較を再計算するのではなく、正しいエンドポイントごとに理解したいと考えています。`r`、開始点はいくつありますか`l ≤ r`部分文字列を作る`s[l..r]`より小さい`t[l..r]`。 

今すぐ修正してください`r`。 私たちが変化するにつれて`l`、間の比較`s[l..r]`そして`t[l..r]`最初の位置によって決まります`k ≥ l`どこ`s[k] ≠ t[k]`、ただし、`k ≤ r`。 ポジションを定義すると`k`どこ`s[k] < t[k]`、その後任意の部分文字列`[l..r]`含まれている`k`以前の不一致オーバーライドは含まれておらず、右側に最も近い不一致によって分類できます。`l`。 

これは、すべての位置を示す構造を維持しながら、右から左に処理することを示唆しています。`l`、次の位置`k ≥ l`どこ`s[k] != t[k]`。 これは、フェンウィック ツリーまたはユニオン検索のようなスキップで構築された、標準的な次の異なるポインター構造です。 

次の不一致位置がわかったら、各部分文字列が`[l..r]`範囲内の最初の不一致によって決定されます。 そのミスマッチがポジションであれば、`s[k] < t[k]`、その後で始まるすべての部分文字列`l`少なくとも届く`k`そしてで終わります`r ≥ k`貢献する。 

ということで、それぞれのポジションごとに`k`と`s[k] < t[k]`、何個数えますか`(l, r)`満足する`l ≤ k ≤ r`そしてまた`k`内部の最初の不一致です`[l, r]`。 これは、次のことを保証することで強制できます。`l`前の不一致境界の後です。 

DSU スタイルの「次の有効な開始」配列を維持し、ある位置が境界として使用されると、それを飛び越えます。 これにより、重複するセグメントの二重カウントが防止されます。 

最後のアイデアは、問題を不一致位置をスイープし、2D の意味で四角形をカウントすることに還元します。各有効な不一致位置は、その周囲に固定された部分文字列の四角形に寄与します。

 ## アルゴリズムのチュートリアル

 文字列の位置を処理し、処理された境界を効率的に飛び越えるための構造を維持します。 

### ステップ

 1. 配列を事前計算する`nxt[i]`次の位置を表します`j > i`そのような`s[j] != t[j]`。 

これは、右から左にスキャンし、文字の差分状態ごとにスタックまたは最後に表示された配列を使用することによって構築されます。 

目的は、任意のデータから開始するときに、最初の不一致を迅速に特定することです。`l`。 
2. 共用体検索構造を構築する`parent[i]`として初期化される`i`。 

この構造により、位置を「消費済み」としてマークし、今後のクエリでその位置をスキップできるようになります。 

パス圧縮により、ほぼ一定のタイム ジャンプが確実に償却されます。 
3. 正しいエンドポイントを反復処理する`r`1から`n`。 

それぞれについて`r`で終わるすべての部分文字列を概念的に考慮します。`r`。 
4. それぞれについて`l`昇順に検索します`k = nxt[l]`かどうかを確認してください`k ≤ r`。 

内に不一致が存在しない場合`[l, r]`、部分文字列は接頭辞と等しくなります`t`そして貢献もしない。 
5. 不一致の場合`k`存在し、`s[k] < t[k]`の場合はすべて有効です`l`それはこれにマップします`k`連続したセグメントを形成します。 

個別に繰り返すのではなく、そのような開始をすべて一度にカウントします。 
6. 不一致位置の処理後`k`、私たちはそれを結びつけます、そうすれば未来は`l`値はそれをスキップし、各開始間隔が 1 つの最初の不一致に確実に割り当てられるようにします。 
7.全体的に貢献を蓄積する`r`。 

### なぜ効果があるのか

 重要な不変条件は、各開始位置が`l`常に最も近い不一致位置に割り当てられます`k ≥ l`それは Union-find によってスキップされていません。 これ`k`まさに最初の位置です`s`そして`t`で始まる部分文字列内で異なる`l`。 したがって、すべての部分文字列は最初の不一致によって一意に分類され、二重にカウントされることはありません。 

Union-find は処理された不一致アンカーを圧縮するため、不一致位置への開始の割り当てにより、互いに素なセグメントが形成されます。`l`。 各セグメントは、有効なすべてのセグメントに独立して寄与します。`r`効率的にカウントできるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    parent = list(range(n + 2))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    nxt = [n + 1] * n
    last = n + 1

    # build next mismatch position
    for i in range(n - 1, -1, -1):
        if s[i] != t[i]:
            last = i
        nxt[i] = last

    ans = 0

    # process by right endpoint
    for r in range(n):
        i = find(0)
        while i <= r:
            k = nxt[i]
            if k > r:
                break

            # substring [i..r] has first mismatch at k
            if s[k] < t[k]:
                ans += (r - k + 1)

            # skip i so it won't be processed again
            parent[i] = i + 1
            i = find(i)

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、`nxt`各開始位置の最初の不一致を直接示す配列。 Union-find 構造により、各開始インデックスが正しいエンドポイントの進行ごとに最大 1 回アクセスされることが保証されます。 

重要な点はカウントステップです`ans += (r - k + 1)`。 開始インデックスを修正したら`i`最初の不一致は誰ですか`k`、任意ので終わるすべての部分文字列`r' ≥ k`最初の不一致は依然として同じになります`k`、つまり固定用`r`すべての有効なエンディングを 1 ステップでカウントします。 

を削除することで再計算を回避します。`i`処理後、償却効率を確保します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、不一致が存在するものの、常にその方向に不一致がある場合です。`s[k] > t[k]`。 この場合、不一致が頻繁に発生する場合でも、その位置で最初に異なる部分文字列はすべて除外する必要があります。 

例えば：```
s = cba
t = abc
```位置 1 では、`c > a`したがって、最初の不一致が 1 である部分文字列は何も寄与しません。 アルゴリズムの処理`k = 1`ただし、答えへの追加はスキップします。 ユニオン検索はまだ進んでいます`i`再処理が正しく開始されないようにします。 

もう 1 つの特殊なケースは、同じ文字が長く続く場合です。 で：```
s = aaaaa
t = aaaab
```最後の不一致位置以降で終わる部分文字列のみが影響します。 の`nxt`配列は、不一致の前のすべての開始部分を単一のアンカーに正しく折りたたむため、各部分文字列を個別に列挙することなく、すべての拡張子を効率的にカウントできるようになります。 

最後の微妙なケースは、最後の文字で不一致が発生する場合です。 アルゴリズムは引き続き正しくカウントします。`r - k + 1`は 1 になり、正確に終了する部分文字列のみであることを反映します。`k`ミスマッチ寄与を実現できます。
