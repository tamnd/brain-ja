 ## 解決策
 ## 問題の理解

 用紙サイズの階層は以下から与えられます。$A_0$まで$A_N$, ここで、各レベルのサイズは前のレベルのちょうど半分です。 各サイズのシートの初期在庫から始めます。また、達成したい目標在庫もあります。 許可される唯一の操作は、サイズのシートを取得することです$A_i$、2枚の大きさに切ります$A_{i+1}$、このプロセスを再帰的に繰り返します。 

タスクは、初期ストックをすべてのサイズ レベルで少なくとも必要なストックに変換するために必要なそのようなカットの最小数を決定するか、それが不可能であると判断することです。 

各カットは、カウントを 2 倍にしながら、厳密に 1 単位の紙を 1 レベル下に移動します。 これにより、大きいサイズから小さいサイズへの強い方向依存性が生じます。つまり、高いレベルの余剰は常に低いレベルに「精製」できますが、その逆はできません。 

制約$N \le 2 \cdot 10^5$これは、どのような解も線形または線形に近い必要があることを意味します。$O(N \log N)$。 レベル間の再配分の 2 次シミュレーションでは、すべてのインデックスのすべてのレベルに超過を伝播する可能性があり、次の場合には遅すぎます。$N$大きいです。 

重要な微妙な点は、余剰がより高いレベルに存在するが、需要がより低いレベルに存在する場合に現れます。 ローカルな差異のみをチェックする単純な貪欲は、構造化された方法で容量を適切に下方に伝播しない場合に失敗します。 

重要な失敗例の 1 つは、ローカル変換は十分であるように見えても、グローバルな伝播では不十分な場合です。 

入力:```
N = 2
a = [0, 0, 2]
b = [2, 0, 0]
```ここには 2 つあります$A_2$シートですが2枚必要です$A_0$シート。 それぞれの理由で正解は不可能です$A_2$だけを生成します$A_1$、さらにカットが必要ですが、コンバージョン深度を正しく追跡せずに単純な推論を行うと、カウントが誤って一致する可能性があります。 

もう 1 つの微妙なケースは、中間レベルがバッファとして機能する必要がある場合です。 それらを無視すると、必要なカットが過少にカウントされることになります。 

## アプローチ

 ブルートフォースパースペクティブでは、各紙シートが個別に処理されます。 すべての赤字が解消されるまで、余剰があるレベルを選択し、一度に 1 レベルずつ削減することを繰り返しシミュレーションします。 各操作はグローバル カウントを更新し、すべての要求が満たされるか、これ以上有益なカットが存在しない場合に停止します。 

このアプローチは実際のプロセスを正確に反映しているため、正しいです。 ただし、最悪の場合は悲惨な状況になります。 1 枚のシート$A_0$繰り返し削減される可能性があります$N$レベルがあり、$O(N)$このようなシート。 これは次のことにつながります$O(N^2)$最悪の場合の行動、それは不可能です$2 \cdot 10^5$。 

重要な点は、個々のカットをシミュレートする必要がないということです。 レベルの各シート$i$完全に分解された場合、すべての下位レベルに決定論的に寄与します。 個別の操作で考えるのではなく、余剰を下向きの流れとして扱います。 カットの数は、レベルを通過するときにユニットを分割する回数とまったく同じです。 

余った紙をどれだけ下に運べるかを維持しながら、上から下に処理します。 各レベルで、まず利用可能な在庫と入ってくる余剰を使用して需要を満たす。 残った余剰は下に渡され、ユニットが渡されるたびに、そのレベルで 1 カットに貢献します。

 ## アルゴリズムのチュートリアル

 プロセスを次からの流れとして扱います。$A_0$まで$A_N$、余剰容量を下に運びます。 

1. 繰越余剰ゼロから開始します。 これは、上位レベルから現在のレベルに変換されたシートを表します。 
2. レベルごとに$i$0から$N$、このレベルで利用可能な合計を次のように計算します。$a_i + \text{carry}$。 これはすべて、需要を満たすか、さらに分割できる使用可能なシートです。 
3. この合計が以下の場合$b_i$、このレベルでは需要に応えるのは不可能なので、すぐに返品します$-1$。 これは、今後の操作では紙を上方に移動させることができないためです。 
4. それ以外の場合は、$b_i$需要を満たし、残りを余剰として保持するためのシート。 
5. 余ったシートはすべて水平に$i$この水準に留まるか、さらに引き下げられる可能性がある。 削減を最小限に抑えるため、余剰分を下方に流すために必要な分だけを削減します。 各ユニットはレベルから下に移動します$i$1カットを表します。 
6. 残りの余剰をすべてキャリーフォーレベルに追加します$i+1$。 このキャリーは暗黙的にすでにカットされたピースを表すため、通過したユニットの数を数える以外に追加の簿記は必要ありません。 
7. 蓄積されたカット数は、すべてのレベルにわたって下に流れる材料の合計量となります。 

### なぜ効果があるのか

 重要な不変条件は、各レベルで$i$、需要の満足を遅らせることはありません。下に何かを渡す前に、利用可能なマテリアルを常に消費します。 レベルから移動するユニット$i$に$i+1$レベルで 1 回だけ分割されている必要があります$i$、そしてこれは、その段階でそのユニットのカット数に寄与する唯一の瞬間です。 

流れは常に下向きであり、決して可逆的ではないため、剰余の各単位は通過するレベルごとに 1 回だけ計算されます。 これにより、別の戦略では同じ分解を達成するために少なくとも同じ数の分割が必要となるため、下向き転送の総数が最小カット数と等しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    carry = 0
    cuts = 0
    
    for i in range(n + 1):
        available = a[i] + carry
        
        if available < b[i]:
            print(-1)
            return
        
        remaining = available - b[i]
        
        cuts += remaining
        carry = remaining
    
    print(cuts)

if __name__ == "__main__":
    solve()
```この実装では、次の 2 つの変数が維持されます。`carry`、前のレベルから何枚のシートが押し下げられたかを保存します。`cuts`、下向きのスプリットの合計数が累積されます。 

各レベルで、元のストックと入ってくるキャリーを組み合わせます。 これが需要に対して不十分な場合、機能は早期に停止します。 それ以外の場合は、余剰を計算し、それを下方に押し下げます。 さらに進むには分割する必要があるため、剰余の各単位はこのレベルでの削減に対応します。 

微妙な点は、カット数を数えるときにオリジナルのシートと搬送されたシートを区別していないことです。 これは正しいです。レベルに到達すると、どちらも同じユニットを表すからです。

 ## 特殊なケース

 エッジケースの 1 つは、すべての需要がトップレベルに集中している場合です。 その場合、以下の余剰は無関係であり、役に立ちません。 アルゴリズムは、キャリーがまだ存在しないため、需要が利用可能な供給を超える最初のレベルでの障害を即座に検出します。 

別のエッジケースは、高レベルでは大量の余剰があるが、低レベルには適度な需要が広がっている場合に発生します。 アルゴリズムは、余剰を段階的に下方に渡すことでこれを正しく処理し、各ユニットがレベル遷移ごとに正確に 1 つのカットに寄与するようにします。 

最後の微妙なケースは、キャリー単独で直接供給がゼロのレベルで需要を満たす場合です。 このアルゴリズムはキャリーとオリジナルの供給を均一に扱うため、区別する必要はありません。 正確さは、両方がすでにそのレベルに変換されている同一のユニットを表しているという事実から来ます。
