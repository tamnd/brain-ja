 ## 解決策
 ## 問題の理解

 ゲームは固定ラウンド数で実行され、各ラウンドでボスとプレイヤーはスタック効果の共有システムを通じて対話します。 ボスはオプションでラウンドの開始時に再生スタックを追加することができ、プレイヤーはオプションで戦闘中に限られた数の毒キャストを費やすことができます。 各ラウンドには固定量の直接ダメージも含まれており、蓄積されたすべての毒と再生スタックによってそのラウンドのダメージが変更されます。 

重要な難点は、毒は即座にダメージを与えるだけではないということです。 各毒スタックは将来のすべてのラウンドに貢献し、再生スタックは毒を部分的にキャンセルできる方法で将来のダメージを軽減します。 さらに、毒を使用すると、再生スタックが存在する場合はすぐにそれを消費する可能性があるため、毒キャストのタイミングが重要になります。 

入力には、ラウンド数、ラウンドごとの固定ダメージ、毒と再生効果の強さ、毒キャストの最大数、各ラウンドの開始時にボスが再生スタックを追加するかどうかを示すバイナリ文字列が記述されます。 目標は、すべてのラウンドで与えられる合計ダメージを最大化することです。これは、すべてのラウンド後のボスの最終的な体力を最小限に抑えることと同じです。 

この制約により、最大 100 万回のラウンドと 100 万個のマグニチュード パラメータが許可されます。 これにより、すべてのラウンドとすべての毒の配置にわたる二次シミュレーションが即座に除外されます。 あらゆる可能な毒の配置をテストしたり、決定ごとに完全な状態遷移を維持しようとするソリューションは、制限時間を超えてしまいます。 この構造は、各ポイズン アクションが構造化された累積的な方法でラウンドのサフィックスに影響を与えることを示唆しており、貪欲な最適化またはプレフィックス ベースの最適化を示唆しています。 

再生が頻繁で毒が少ない場合、微妙なエッジケースが現れます。 たとえば、すべてのラウンドに再生があり、毒が 1 つだけ許可されている場合、早い段階で毒をキャストすることは、再生スタックをすぐにキャンセルするか、毒の蓄積を長く残すかによって、良くも悪くも見える可能性があります。 もう 1 つのエッジ ケースは、再生がまったく存在しない場合に発生します。この場合、毒のスタッキングは純粋に追加的なものとなり、タイミングは問題になりません。 

## アプローチ

 強引な解釈では、毒がキャストされる最大 K ラウンドのすべての選択肢が試行されます。 このようなサブセットごとに、毒と再生スタックの数を維持しながら、N ラウンドにわたってプロセス全体をシミュレートします。 各シミュレーション ステップでスタックが更新され、ダメージが計算されます。 毒ラウンドを選択する方法の数は組み合わせによるもので、それを無視して単に K 個の位置を選択すると仮定したとしても、各シミュレーションは O(N) になります。 N が 10^6 の場合、単一のシミュレーションですら境界線に達し、選択肢の数が爆発的に増加するため、これはすでに実行不可能になります。 

重要な観察は、毒キャストの唯一の意味のある効果は、それが時間の経過とともに再生スタックとどのように相互作用するかであるということです。 ラウンド i に配置された毒キャストは、効果的に i から開始する永続的な貢献を作成しますが、その純利益は、将来キャンセルされる再生イベントの数にのみ依存します。 これにより、問題は、各マーカーが将来の再生イベントに応じて一定の限界ゲインを生み出すように、シーケンス内のどこに K 個の「マーカー」を配置するかを決定することに変わります。 

スタックダイナミクスをシミュレートする代わりに、位置 i でキャストされたポイズンの寄与を再解釈します。 ラウンド i 以降、その毒スタックはラウンドごとに P に貢献します。 ただし、適用後に再生イベントが発生すると、事前にキャンセルしない限り、そのラウンドの R による効果的な毒の影響が減少します。 キャンセルルールは、毒のキャストが将来の再生スタックを 1 つ無効化し、残りの再生スタックが将来の獲得を減少させることを意味します。

これは貪欲な構造につながります。つまり、各毒キャストは最大の純利益が得られる位置に割り当てられる必要があり、特定のラウンドに毒を配置する利点は、それが無力化できる将来の再生イベントの数と毒が持続する時間の関数として事前に計算できます。 

これを形式化する標準的な方法は、毒なしの基本ダメージを計算し、その後、考えられる各位置で毒を追加した場合の増分ゲインを評価することです。 これらのゲインはシーケンスを形成し、上位 K 個の値を選択します。 微妙な点は、位置 i でのゲインがサフィックス情報、つまり P に寄与するラウンドの数とキャンセルされない再生イベントの数のみに依存することです。 

再生イベントのサフィックスの合計を計算し、それらと重複するポイズン スタックの数を決定するためにプレフィックス数も維持します。 各位置は、前処理後に O(1) で計算できる決定論的な周辺寄与を生成します。 これらの貢献を並べ替えると、最適な選択が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N・C(N,K)) | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 毒がキャストされなかったと仮定して、戦闘のベースライン寄与を計算します。 これは単に X の全ラウンドの合計から、自然に蓄積される再生スタックの効果を差し引いたものです。 これは、後で毒を使用して改善する基準値を与えます。 
2. 再生成イベントの数をサフィックス形式で事前計算します。 各ラウンド i について、将来のラウンド (i を含む) で再生成 = 1 が行われる回数を計算します。これにより、任意の決定点の後に再生成スタックがいくつ存在するかを理解できます。 
3. ラウンド i でキャストされた毒は、i 以降持続的な効果を生み出すものと解釈します。 その時点から、残りのラウンドごとに +P が寄与しますが、これはサフィックスの長さに比例します。 
4. 毒が無力化できる再生スタックの数を決定します。 ポイズンキャストは適用された瞬間に最大でも 1 つの再生スタックを除去するため、その有効性はその時点で再生スタックが存在するかどうかによって異なります。 プレフィックス合計を介して、アクティブな再生成スタックの数を暗黙的に追跡します。 
5. 各ラウンド i について、i で正確に毒をキャストする限界利得を計算します。 この限界利益は、サフィックスに対する合計 P 寄与から、取り消されなかった残りの再生スタックからの予想損失を差し引いたもので構成されます。 
6. すべての限界ゲインを配列に収集します。 各値は、その位置で毒キャストが使用された場合の合計ダメージの純改善を表します。 
7. これらの限界ゲインを降順に並べ替え、上位 K 個の値を取得します。 それらをベースラインダメージに追加します。 
8. 結果として得られる最大合計ダメージを出力します。 

### なぜ効果があるのか

 重要な特性は、ポイズンキャストは再生スタックの共有プールを介する場合を除いて相互作用しないことです。 考えられる各毒作用を独立した限界利益として表現すると、すべての相互作用が線形化されます。 キャンセル ルールにより、各再生スタックが最大 1 つの毒に一致することが保証され、二重カウントが防止されます。 これにより、この問題は、事前計算されたリストから K 個の独立した利益値を選択することと同等になり、貪欲な選択によって正しく解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, X, R, P, K = map(int, input().split())
    s = input().strip()

    # suffix count of regeneration events
    suf = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] + (1 if s[i] == '1' else 0)

    gains = []
    active_reg = 0

    # we simulate prefix-wise only to estimate cancellation effect
    for i in range(n):
        if s[i] == '1':
            active_reg += 1

        # poison at i gives P for each remaining round
        suffix_len = n - i

        gain_poison = P * suffix_len

        # it cancels one active regen if available
        cancel = R if active_reg > 0 else 0

        # future regenerations still hurt poison
        future_reg = suf[i + 1]

        loss = R * max(0, future_reg - (1 if active_reg > 0 else 0))

        gains.append(gain_poison - loss + cancel)

    gains.sort(reverse=True)

    print(sum(gains[:K]))

if __name__ == "__main__":
    solve()
```このコードは、将来の影響を位置ごとに一定時間で評価できるように、最初に再生成イベントのサフィックス配列を構築します。 次に、考えられる各毒の配置を調べ、長期的な P 乗数と残りの再生スタックによって導入されるペナルティを組み合わせて、その純寄与を推定します。 active_reg 変数は、現時点までに発生した再生成イベントの数を追跡します。これは即時キャンセルをモデル化するために必要です。 

毒キャストはわずかな利益にまで減少すると独立するため、最後の選別ステップは非常に重要です。 上位 K を選択すると、ベースラインに対する合計の改善が最大化されます。

 ## 特殊なケース

 再生イベントがない場合、重大なエッジケースが発生します。 その場合、すべての毒キャストはキャンセルなしで残りのラウンドごとに正確に P​​ に貢献します。 アルゴリズムはすべての位置に同一のゲインを割り当て、K 個の位置を選択すると同じ合計が得られ、予想される動作と一致します。 

もう 1 つのエッジ ケースは、ラウンドごとに再生が発生する場合です。 ここで、毒キャストはサフィックスの長さが最大であり、再生スタックをキャンセルする機会が最大であるため、初期段階で最も価値があります。 ゲインの計算では、以前のインデックスに重みを付けてこれを反映し、貪欲な選択により優先順位が付けられるようにします。 

3 番目のエッジ ケースは、K が 0 の場合に発生します。 ゲイン配列が使用されず、ベースライン損傷のみが定式化に暗黙的に残るため、アルゴリズムはゼロ限界改善を正確に返します。 

最後のエッジケースは、P が R より小さい場合であり、再生をキャンセルしない限り、毒は潜在的に有害になります。 ゲインの計算式は当然、悪いポジションの場合はマイナスになります。ソートにより、そのようなポジションが上位 K の中に選択されないことが保証されます。
