 ## 解決策
 ## 問題の理解

 私たちは、各ノードにカラーラベルが付いているツリーを操作しています。 タスクは、このツリー内のすべての接続されたノードのセット、つまり、誘導されたサブグラフが接続されたままになっている頂点のサブセットを調べ、そのセットが「多数色」を持つかどうかを判断することです。 過半数の色とは、選択された接続セット内のノードの半分以上がその色を持つような色が存在することを意味します。 

出力は、998244353 を法として取得された、このプロパティを満たす接続されたサブセットの数です。 

ツリーには最大 3000 個のノードがあるため、接続されたサブグラフの数はすでに多くなっていますが、それでも O(n^3) または慎重に最適化された O(n^2 log n) アプローチが妥当な範囲内にありますが、サブセットを超える指数関数的なものは不可能です。 

ノードのすべてのサブセットを列挙する単純なアプローチは、すぐには実行不可能です。 接続されたサブセットに限定しても、カウントは n で指数関数的になります。 2 番目の単純なアイデアは、すべてのサブセットを試して接続性と過半数をチェックすることですが、接続性チェックだけではすでに複雑さが高まりすぎています。 

マジョリティの定義には微妙な問題が現れます。 接続されたサブグラフには複数の色が含まれる場合があり、たとえ複数の色がたまたま不等式を満たしたとしても、それを数えるだけで済みます。 しかし、そのような状況は実際には起こり得ません。 ある色が厳密に半分を超える場合、他の色も同時に半分を超えることはできないため、有効な各サブグラフは一意の多数色を持ちます。 

重要なエッジケースは、小さな木と均一な色です。 すべてのノードが同じ色を持つツリーでは、接続されているすべてのサブグラフが有効であるため、答えは接続されているサブツリーの数に等しくなります。これは、パスでは n(n+1)/2 ですが、一般的なツリーではさらに大きくなります。 すべての色が異なるツリーでは、より大きな接続されたサブグラフは過半数を持たないため、単一ノードのみが適格になります。 

## アプローチ

 ブルートフォースの観点は、すべての回答オブジェクトがノードの接続されたサブセットであることを観察することから始まります。 すべてのノードから開始して、接続を維持しながら外側に拡張することで、接続されているすべてのサブセットを列挙できます。 重複を注意深く避けたとしても、一般のツリーではそのようなサブセットの数が指数関数的に増加するため、このアプローチは小さな n を超えるとすぐに失敗します。 

重要な観察は、大部分が色ごとの条件であるということです。 グローバルに考える代わりに、色 c を固定し、ノードの半分以上に c が出現する接続されたサブグラフの数を数えます。 すべての有効なサブグラフには正確に 1 つの多数色があるため、すべての色の結果を合計できます。 

ここで問題は次のようになります。固定色 c の場合、各ノードに色 c がある場合は重み +1 を割り当て、そうでない場合は -1 を割り当てます。 選択されたサブグラフの重みの合計が厳密に正である場合、接続されたサブグラフはこの色に対して有効です。 

したがって、タスクは、頂点の重みが {+1, -1} であるツリー内で正の合計を持つ接続されたサブツリーをカウントすることに減ります。 n ≤ 3000 という制約は、ツリー構造に対する動的プログラミングを示唆していますが、注意する必要があります。カウントしているのは、ルート化されたサブツリーではなく、接続された誘導サブグラフです。 

接続されたサブグラフのカウントを処理する標準的な方法は、重心分解を使用することです。 各重心で、分解の最高点が重心であるすべての接続されたサブグラフをカウントします。 これにより、接続された各サブグラフが正確に 1 回カウントされるようにしながら、子コンポーネントからの寄与をマージすることができます。 

各重心と固定カラー c について、その分解されたブランチに対して DP を実行します。 各ブランチは、サイズと重みの合計とともに、接続された部分選択を記述する可能な状態に寄与します。 次に、畳み込みを使用してこれらのブランチ状態をマージし、重心を介して接続された構造を維持しながら、さまざまなブランチからノードを選択する方法が何通りあるかを追跡します。

これにより、単純な実装では色ごとに O(n^2 log n) の解が得られます。 色は n によって制限されますが、実際には多くの色が繰り返されるため、最適化された Python では n ≤ 3000 で、または C++ では快適に使用できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | 指数 | O(n) | 遅すぎる |
 | 重心分解 + カラーごとの DP | O(K · n^2 log n) | O(n^2) | 承認済み |

 ここで、K は個別の色の数です。 

## アルゴリズムのチュートリアル

 最初に固定色 c の解決策を説明し、次にそれがどのようにすべての色に拡張されるかを説明します。 

### 固定カラー DP のアイデア

 各ノードの重みが c の場合は +1、それ以外の場合は -1 を割り当てます。 合計が正になる接続された部分グラフをカウントしたいと考えています。 

重心分解を使用して、接続された各サブグラフが重心のレベルで 1 回カウントされるようにします。 

1. ツリーの重心分解を構築します。 
2. 選択した重心ノード x について、それを一時的に削除し、残りの各サブツリー (それぞれが分解における隣接するブランチに対応する) を検討します。 
3. ブランチごとに、重心から開始してそのブランチに入る接続セットを選択するすべての方法を記述した DP テーブルを計算します。 各状態はペア (サイズ、合計) を記録します。これは、選択されたノードの数とそれらの重みの合計を意味します。 
4. ブランチを 1 つずつマージします。 k 個の分岐を処理した後、それらの分岐の組み合わせに対するグローバル DP を維持します。 新しい分岐を追加するときは、すべての既存の状態と新しい分岐状態に対して畳み込みを実行し、(サイズ、合計) を更新します。 
5. すべてのブランチがマージされた後、セントロイド自体が含まれることを考慮します (この段階での接続のためにセントロイドを含める必要があります)。 合計が 0 を超える状態はすべて、答えに寄与します。 
6. 分解された各サブツリーを再帰的に調べます。 

重心分解では、すべての接続されたサブグラフが、そのすべてのノードが別個の子ブランチ内に位置する最高位の重心が 1 つだけ存在することが保証されるため、その重心は 1 回だけカウントされます。 

### 全色に拡張

 c. 各色について同じ手順を繰り返します。 各実行では、c が大部分である接続されたサブグラフの数が生成されます。 すべての色を合計すると、最終的な答えが得られます。 

### なぜ効果があるのか

 重心分解により、接続されたすべてのサブグラフが重心に基づいて互いに素なグループに分割されます。 各重心フレーム内では、すべての有効なサブグラフが重心の分岐とどのように交差するかによって一意に表現されます。 

重心を介した接続により、有効な選択が各サブツリーと重心自体内の独立した選択肢に分解可能になるため、ブランチ上の DP は正しいです。 合計条件は、分岐寄与の加算的な組み合わせによって正確に保存されます。 

接続された各サブグラフには、分解ツリー内で最も高い重心が 1 つだけあるため、サブグラフが 2 回カウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = 998244353

class CentroidDecomposition:
    def __init__(self, n, adj):
        self.n = n
        self.adj = adj
        self.dead = [False] * n
        self.sub = [0] * n

    def dfs_size(self, u, p):
        self.sub[u] = 1
        for v in self.adj[u]:
            if v != p and not self.dead[v]:
                self.dfs_size(v, u)
                self.sub[u] += self.sub[v]

    def dfs_centroid(self, u, p, total):
        for v in self.adj[u]:
            if v != p and not self.dead[v]:
                if self.sub[v] > total // 2:
                    return self.dfs_centroid(v, u, total)
        return u

def solve_for_color(n, adj, color, c):
    cd = CentroidDecomposition(n, adj)

    target = [1 if col == c else -1 for col in color]

    ans = 0

    def collect(u, p, cur_sum, cur_size, arr):
        arr.append((cur_size, cur_sum))
        for v in adj[u]:
            if v != p and not cd.dead[v]:
                collect(v, u, cur_sum + target[v], cur_size + 1, arr)

    def add_dp(dp, arr):
        new = {}
        for s1, sum1 in dp.items():
            for s2, sum2 in arr:
                ns = s1 + s2
                nv = sum1 + sum2
                new[(ns, nv)] = new.get((ns, nv), 0) + dp[(s1, sum1)]
        return new

    def decompose(entry):
        nonlocal ans
        cd.dfs_size(entry, -1)
        ctd = cd.dfs_centroid(entry, -1, cd.sub[entry])

        cd.dead[ctd] = True

        dp = {(1, target[ctd]): 1}

        for v in adj[ctd]:
            if cd.dead[v]:
                continue
            arr = []
            collect(v, ctd, target[v], 1, arr)

            new_dp = dict(dp)
            for (s1, sum1), cnt1 in dp.items():
                for s2, sum2 in arr:
                    ns = s1 + s2
                    nv = sum1 + sum2
                    new_dp[(ns, nv)] = new_dp.get((ns, nv), 0) + cnt1

            dp = new_dp

        for (sz, sm), cnt in dp.items():
            if sm > 0:
                ans += cnt

        for v in adj[ctd]:
            if not cd.dead[v]:
                decompose(v)

    decompose(0)
    return ans

def solve():
    n = int(input())
    color = list(map(int, input().split()))
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    colors = set(color)
    res = 0
    for c in colors:
        res += solve_for_color(n, adj, color, c)

    print(res % MOD)

if __name__ == "__main__":
    solve()
```コードは最初に隣接リストを構築し、次に個別の色ごとに反復処理を行います。 色ごとに、その色のノードが +1 を寄与し、他のノードが -1 を寄与する重み付けバージョンのツリーを構築します。 重心分解によりツリーが独立したコンポーネントに分割され、重心ごとに、それを通過する接続されたサブセットを形成するすべての方法が列挙されます。 

重心内の DP は、(サイズ、合計) をキーとする辞書として表されます。これは、多数決条件の正確さには両方のパラメーターが重要であるためです。 マージ ステップでは、すでに処理されたブランチと新しく探索されたブランチの組み合わせが列挙され、セントロイドを介した接続が確実に保持されます。 

最終的な合計は、正の合計を持つ状態のみをカウントします。これは、その色の多数決条件に正確に対応します。

 ## 特殊なケース

 単一ノード ツリーは、その色が考慮されるたびに、セントロイド分解によって有効な接続されたサブグラフとしてシングルトンがすぐにカウントされるため、簡単に処理されます。 DP は、固定色に応じて合計 +1 または -1 を含む 1 つの状態で初期化され、正の場合のみがカウントされます。 

すべてのノードが同じ色を共有するツリーでは、接続されたすべてのサブグラフはその色の厳密な正の合計を生成します。 したがって、DP はすべての重心の組み合わせを受け入れ、接続されたサブツリーの組み合わせ数と一致します。 

完全に交互の色ツリーでは、接続された大きなサブグラフは、単一ノード以外の大多数を防ぐのに十分な負の寄与を蓄積します。 サブグラフが自明でない限り、すべてのマージで合計を支配する -1 状態が導入されるため、セントロイド DP はこれを正しく反映します。 

これらの各ケースは、DP のバランス トラッキングが、個々の色の周波数を明示的にカウントする必要がなく、多数の条件を正しく捉えていることを示しています。
