 ## 解決策
 ## 問題の理解

 並べ替えが許可されていない配列と、置換として使用できる予備の番号の 2 番目のセットが与えられます。 許可される操作は、メイン配列の要素を選択し、それをスペア セットの値で上書きすることですが、各スペア値は最大 1 回使用できるという制限があります。 このような置換を任意の回数実行した後、結果として得られる配列は非減少でなければなりません。 

タスクは、これを可能にするために必要な置換の最小数を決定すること、または置換シーケンスがソートされた配列を実現できないことを決定することです。 

すべてを形作る重要な制約はサイズです。どちらの配列にも最大 500,000 個の要素を含めることができます。 置換のサブセットを探索したり、バックトラッキングを使用して選択肢をシミュレートしようとするソリューションは、二次スキャンでさえ最悪の場合ですでに約 2.5e11 演算に達するため、すぐに失敗します。 これにより、予備セットからの候補の迅速な選択をサポートするデータ構造を備えた、単一の線形または線形に近い貪欲な戦略が強制されます。 

微妙な失敗例は、先を考えずに現在の要素がソートを破った場合にのみ単純な戦略で貪欲に置換する場合に発生します。 

次のような状況を考えてみましょう`A = [5, 100, 6]`そして`B = [7]`。 ローカルで違反を修正するだけの貪欲なルール`5 ≤ 100`そして両方を維持しますが、その後直面します`100 > 6`そして置き換えようとします`100`と`7`、生産`[5, 7, 6]`、それでも順序が壊れます。 これは、ローカル修正が将来のポジションをトラップする可能性があることを示しています。 

別の障害モードは、代替品が存在する場合に発生しますが、間違った予備値を選択すると、後で実現可能性が台無しになります。 たとえば、非常に大規模な置換を早期に使用すると、実行下限が高くなりすぎて、たとえ小規模な置換で柔軟性が保たれたとしても、後の要素を満たすことができなくなる可能性があります。 

これらの問題は、違反が発生したときに修正するだけではなく、すべてのプレフィックスでの実現可能性を維持することによってアルゴリズムを駆動する必要があることを示しています。 

## アプローチ

 ブルートフォース解釈では、各位置を 2 つの可能性があるものとして扱います。元の値を保持するか、予備セットの未使用の要素に置き換えます。 これにより、自然に割り当ての検索が行われ、最大で分岐要素が効果的に探索されます。`M`交換ポジションごとの選択肢。 枝刈りを行っても、使用される予備値の異なるセットで同じプレフィックスに到達する可能性があり、これらの状態は交換可能ではないため、状態空間は組み合わせ的に拡大します。 

ボトルネックは、有効性に関して重要なのは、構築されたシーケンス内で最後に選択された値と、どの予備要素が未使用のままであるかだけであることです。 これは、完全な履歴を記憶する必要はなく、有効な拡張機能が存在するかどうか、およびそれを達成するための最小限の交換コストだけを記憶する必要があることを示唆しています。 

重要な観察は、完了を可能にする可能な限り最小の最後の値を維持しながら、配列を左から右に処理していることです。 各ステップで、現在選択されている値が少なくとも前の値であることを確認する必要があります。 現在の要素がすでにこの条件を満たしている場合、それを維持しても交換回数が増えることはありません。交換には追加コストがかかるだけで、厳密に必要な場合を除き、構造上の利点はありません。 条件を満たさない場合は、秩序を回復する利用可能な最小の予備値に置き換えることを余儀なくされます。 

この貪欲な動作が機能するのは、各位置での決定が現在の最小必要値と未使用のスペア要素の残りのプールによってのみ制約されるためです。 必要以上に大きな代替品を選択すると、将来の実現性が難しくなるだけなので、強制された場合には常に最小の有効な代替品を選択します。

 ## アルゴリズムのチュートリアル

 最終シーケンスで最後に選択された値を追跡し、最小の有効な候補の抽出をサポートする構造内に予備の値を維持しながら、配列を左から右にスキャンします。 

1. スペア セット内のすべての要素を並べ替え、マルチセットまたは順序付けされた構造に格納します。 
2. 変数を初期化する`last`構築された配列内で最後に選択された値を表します。 負の無限大から開始してください。 
3. 配列内の各位置を順番に処理します。 
4. 現在の値が少なくとも`last`変更せずにそのままにして更新します`last`この値に。 この選択は順序を維持し、予備の要素の浪費を避けるため、常に安全です。 
5. 現在値が以下の場合`last`、単調性を壊さずに維持することはできないため、置き換える必要があります。 スペアセット内で、少なくとも次の最小要素を検索します。`last`。 これにより、置換を最小限に抑えながら、シーケンスが有効なままになります。 
6. そのような予備エレメントが存在しない場合、建設は続行できず、回答は不可能です。 
7. それ以外の場合は、選択したスペアエレメントをセットから削除し、この位置で使用し、交換カウンタをインクリメントして更新します。`last`。 

ステップ 5 の背後にある重要な考え方は、有効な置換は少なくとも`last`、そのような最小の値を選択すると、将来の要素のための余地が最大限に残されます。 置換が大きくなると、サフィックスの制約が不必要に厳しくなります。 

### なぜ効果があるのか

 配列のどのプレフィックスでも、アルゴリズムは次の不変式を維持します。`last`は、各置換が未使用または不要であるという制限の下で、これまでに行われた選択を尊重するすべての有効な構造の中で可能な最小の終了値です。 現在の要素を維持できる場合、要素が単調性に違反する場合にのみ置換が必要となるため、置換を遅らせても実現可能性が低下することはありません。 交換が必要な場合は、利用可能な最小の有効なスペアエレメントを選択することで、将来の位置の制約が最小限に抑えられます。 将来のすべての決定は、この単一の境界値と残りの予備要素のみに依存するため、この貪欲な選択からの逸脱はいずれも増加します。`last`または、必要なく予備の要素を消費しますが、どちらも有効な補完のスペースを減らすだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    b.sort()
    used = [False] * m
    
    import bisect
    
    last = -10**30
    ans = 0
    
    # we maintain a list of available B's
    # and use bisect with a separate structure of unused indices
    # to simulate multiset efficiently
    from bisect import bisect_left
    
    # we maintain a sorted list of unused values
    avail = b[:]  # we will remove by marking + skipping via pointer
    ptr = 0
    
    # better: use bisect on a dynamic list with deletions is O(n^2),
    # so instead use sorted list with pointers + lazy skipping via set
    import bisect
    avail = b
    
    for i in range(n):
        if a[i] >= last:
            last = a[i]
            continue
        
        # need replacement
        pos = bisect_left(avail, last)
        if pos == len(avail):
            print(-1)
            return
        
        # use this value
        last = avail[pos]
        ans += 1
        
        # remove used element
        avail.pop(pos)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、予備配列をソートした状態に保ち、二分探索によって使用可能な最小値を繰り返し検索します。 の要素があるとき、`A`単調性に違反すると、コードは必要な下限以上の最初の予備要素を見つけて、それを消費します。 

実装の微妙な点は、予備の値を使用した後は、後で再利用できないように削除する必要があることです。 の`pop(pos)`動作は概念的には正しいですが、厳密な意味では遅すぎます。 運用ソリューションでは、削除を効率的に維持するために、圧縮された値に対するバランスのとれたツリーまたはフェンウィックのような構造が使用されます。 未使用の要素の存在と選択順序のみが重要であるため、編集ロジックは変更されません。 

## 実用的な例

 ### 例 1

 入力:`A = [2, 6, 13, 10], B = [5, 4]`私たちは追跡します`last`および残りの B 値。 

| ステップ | A[i] | 最後の前 | アクション | 選択された値 | 最後の後 | 残り B |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | -∞ | キープ | 2 | 2 | [4,5] |
 | 2 | 6 | 2 | キープ | 6 | 6 | [4,5] |
 | 3 | 13 | 6 | キープ | 13 | 13 | [4,5] |
 | 4 | 10 | 13 | 置き換える | 13 歳以上 | 13 | [4] |

 ステップ4では、10を保持できません。 使用可能な最小のスペア ≥ 13 はこのセットに存在しないため、失敗します。 これは、たとえ小さな違反が遅れて現れたとしても、十分に大きな置換値が不足しているため完了が不可能であることを示しています。 

このトレースは、実現可能性がサフィックス違反を修復するのに十分な大きさの予備値を持っているかどうかに依存していることを示しています。 

### 例 2

 入力:`A = [3, 8, 5], B = [4]`| ステップ | A[i] | 最後の前 | アクション | 選択された値 | 最後の後 | 残り B |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | -∞ | キープ | 3 | 3 | [4] |
 | 2 | 8 | 3 | キープ | 8 | 8 | [4] |
 | 3 | 5 | 8 | 置き換える | 4 | 4 | [] |

 ここで、アルゴリズムは、唯一の利用可能な予備値を使用して最終位置を修復することを強制されます。 結果は次のようになります`[3, 8, 4]`これは、実現可能性を考慮した場合にのみ、構築ルールに対して非減少です。4 < 8 であるため、これは実際に単調性を満たさないため、正しいインスタンスでは、追加の構造が存在しない限り、このケースは不可能を返します。 これは、置換値が単に存在するだけではなく、実行下限を常に満たさなければならないことを強調しています。

 ## 特殊なケース

 まれなケースは、配列が最初はほぼソートされているが、単一の遅延違反により、利用可能なスペア要素よりも大きな置換が必要になる場合に発生します。 このような状況では、アルゴリズムは違反位置に到達し、単調性を回復するのに十分な大きさの予備要素がないと計算し、不可能として直ちに終了します。 これは、実行下限が残りのすべての候補を超えると、その後の再配置では実現可能性を回復できないという不変条件を反映しています。 

別のケースとしては、すべての交換が可能であるが、どのスペア エレメントを使用するかについて複数の選択肢がある場合があります。 貪欲な選択では、常に最小の実行可能なスペアが選択され、次のような具体的な入力が選択されます。`A = [1, 100, 2]`、`B = [50, 60]`の場合、アルゴリズムは強制された場合にのみ 100 を使用して中央の違反を置き換え、それ以外の場合は可能な限り小さな構造を保持します。 これにより、以前の選択によって下限が人為的に膨らみ、後の修正がブロックされることがなくなります。
