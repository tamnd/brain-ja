 ## 解決策
 ## 問題の理解

 2n 個のオブジェクトのコレクションが与えられ、各オブジェクトは 2 つの整数 ai と bi で表されます。 エンドポイントの順序は保証されていませんが、各オブジェクトを数直線上のセグメントとして考えることができます。 各オブジェクトについては、その 2 つのエンドポイントのみが重要であり、任意の 2 つのオブジェクト i および j に対して、それらのエンドポイントがどれだけ離れていられるかに応じて接続コストを定義します。 

より正確には、2 つのオブジェクト i と j をペアにする場合、4 つの値すべて ai、bi、aj、bj を調べ、i から 1 つと j から 1 つを取得した値のペア間の最大の絶対差を取得します。 これにより、i と j の間のエッジの重みが生成されます。 次に、2n 個のオブジェクトを n 個の互いに素なペアに分割するすべての可能な方法を検討し、選択したエッジの重みの合計を最大化したいと考えます。 

入力サイズは最大 2n = 200000 エンドポイントの合計オブジェクトに達するため、二次時間よりも近いアプローチが必要です。 すべてのペアワイズ エッジを直接計算するには、すでに約 2n 乗演算が必要になりますが、これは 10^10 のオーダーであり、時間内に実行できる量をはるかに超えています。 グラフ全体を保存することすら実際には不可能です。 

単純な貪欲なアプローチの微妙な失敗例は、エンドポイントがインターリーブされている場合に発生します。 たとえば、オブジェクト (0, 100)、(1, 2)、(98, 99)、(50, 51) がある場合、ローカルに隣接するエンドポイントのペアリングまたは最も近い値によるペアリングでは、極端な値を一緒にペアリングするとより大きな寄与が生成されることを簡単に見逃す可能性があります。 すべてのエンドポイントのグローバル構造を同時に無視する戦略は失敗する傾向があります。これは、各ペアの重みが局所的な近接性ではなく、両方のオブジェクトにわたる極値に依存するためです。 

重要な問題は、各ペアの重みが独立した寄与の合計ではなく、ペア全体の単一のグローバル最大値から単一のグローバル最小値を引いたものによって決定されることです。 

## アプローチ

 ブルート フォース ソリューションでは、2n 個の頂点の可能な完全な一致をすべて列挙し、各一致の合計の重みを計算します。 組み合わせの選択肢に限定しても、完全一致の数はおよそ (2n) です。 / (2^n n!)、超指数関数的に増加します。 n が 100000 までの場合、これは不可能です。 

より構造化されたブルート フォース アプローチは、すべてのエッジの重みを事前計算してから、完全なグラフに対して最大重み一致アルゴリズムを実行することです。 グラフには O(n^2) 個のエッジがあるため、これでもまだ遅すぎます。 

最初の単純化は、エッジの重みを書き直すことから生じます。 各オブジェクトに対して、li = min(ai, bi) および ri = max(ai, bi) を定義します。 任意の 2 つのオブジェクト i および j について、任意のクロス ペア間の最大差は、単純に 4 つの中の最大のエンドポイントと 4 つの中の最小のエンドポイントの差です。 これは、エッジの重みが max(ri, rj) − min(li, lj) になることを意味します。 

この式から、各ペアが 2 つの役割を果たしていることがわかります。 一方のエンドポイントは右側の最大値に寄与し、もう一方のエンドポイントは左側の最小値に寄与します。 すべてのペアにわたって、合計の答えは、r の選択された最大値の合計から l の選択された最小値の合計を引いたものになります。ここで、各オブジェクトは 1 つのペア内で 1 回だけ使用され、各ペア内で 1 つのオブジェクトが max-r を提供し、もう 1 つのオブジェクトが min-l を提供します。 

この再定式化により、問題は要素のペアに変換されます。各ペアの寄与は、一方の要素を「右端のプロバイダー」として選択し、もう一方の要素を「左端のプロバイダー」として選択することだけに依存します。 各オブジェクトが 1 つのペアにのみ参加するという制約を尊重しながら、大きな r 値が最大値として機能し、小さな l 値が最小値として機能するようにしようとすると、最適な構造が現れます。

重要な観察は、オブジェクトを r の降順で処理すると、現在のオブジェクトが当然そのペアの最大 r 寄与者の有力な候補となるということです。 利点を最大化するには、最大パートナーとしてまだ固定されていないオブジェクトの中で、可能な限り小さい l を持つオブジェクトと組み合わせたいと思います。これにより、減算項が最小化されるからです。 

これは、最大の r を持つ残りのオブジェクトを繰り返し取得し、それを最小の l を持つ残りのオブジェクトと照合するという貪欲な戦略につながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースマッチング | 指数 | O(n^2) 以上 | 遅すぎる |
 | 最適な貪欲ペアリング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各入力ペア (ai、bi) を (li、ri) に変換します。ここで、li は小さい方のエンドポイント、ri は大きい方のエンドポイントです。 エッジの重みは順序ではなく極値のみに依存するため、この標準化が必要です。 
2. すべてのインデックスを、最大 ri と最小 li の両方を効率的に繰り返し抽出できる構造に配置します。 一般的な方法は、2 つの順序付けされたビュー、または両方の値をキーとするマルチセットを維持することです。 
3. 最大の ri を持つペアになっていない要素を繰り返し選択します。 この要素が選択されるのは、それが参加するペアの中で「max r」項に最も価値のある寄与を与える可能性があるためです。 
4. この要素をプールから削除し、残っているすべてのペアになっていない要素の中から、li が最も小さい要素を選択します。 この選択により、ペアの「min l」項から生じるペナルティが最小限に抑えられます。 
5. これら 2 つの要素を組み合わせて、max(最初の ri、2 番目の ri) から min(1 番目の li、2 番目の li) を答えに加算します。 最初の要素は残りの候補の中で最大の ri を持つため、常にペアの max-r 寄与が得られます。 
6. 両方の要素を使用済みとしてマークし、すべての要素がペアになるまで続行します。 

正確性は、最大の ri 要素が選択されると、他のペアがその最大値としての現在の最善の役割を超えて寄与を増やすことができないという事実にかかっており、そのため、そのペアの 2 番目のエンドポイントのみを自由に最適化できます。 

### なぜ効果があるのか

 変換により、すべてのペアの寄与が、選択された最大 r 値と選択された最小 l 値の間の差に換算されます。 各要素は 1 回だけ参加するため、問題は各要素を最大寄与因子または最小寄与因子として割り当て、ペアリングによって結合を強制することになります。 

r の降順で要素を処理することにより、要素が最大寄与度として選択されると、その後の決定によって r 寄与度が増加することがなくなります。 その時点で、それを利用可能な最小の l と組み合わせることで、その強制最大値の選択に対する可能な限り最小の減算コストが保証されます。 より大きな l を使用する代替ペアリングは、すでに固定されている最大寄与を改善することなく、減算の合計を増やすだけであるため、合計を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = []
for i in range(2 * n):
    x, y = map(int, input().split())
    l = min(x, y)
    r = max(x, y)
    a.append((l, r, i))

# sort by r descending
a.sort(key=lambda x: x[1], reverse=True)

import heapq

# min-heap by l
heap = []
used = [False] * (2 * n)

for l, r, i in a:
    heapq.heappush(heap, (l, i, r))

ans = 0

# we will maintain a set of available elements in heap,
# but we must lazily remove used ones
for l, r, i in a:
    if used[i]:
        continue

    used[i] = True

    # extract smallest l unused
    while heap and used[heap[0][1]]:
        heapq.heappop(heap)

    l2, j, r2 = heapq.heappop(heap)
    used[j] = True

    ans += max(r, r2) - min(l, l2)

print(ans)
```この実装では、l でソートされたヒープ内のすべての要素が維持されるため、選択されたそれぞれの最大 r 要素について、l 値を最小化する最適なパートナーを迅速に見つけることができます。 r を減少させることによって配列をソートすると、常に最も強い残りの右エンドポイントを最初にペアリングすることが保証されます。 

一般的な注意点は、既に使用されている要素がヒープ内で確実に遅延スキップされるようにすることです。 要素はペアで削除されるため、古いエントリが自然に表示されるため、それらのエントリが見つかった場合は破棄します。 

## 実用的な例

 4 つのオブジェクト (0, 10)、(7, 7)、(9, 4)、(2, 15) がある小さなケースを考えてみましょう。 

まず、(l, r): (0, 10)、(7, 7)、(4, 9)、(2, 15) に正規化します。 r の降順で並べ替えると、(2, 15)、(0, 10)、(4, 9)、(7, 7) になります。 

ペアリングを段階的に追跡します。 

| ステップ | 選択された max-r 要素 | 利用可能な min-l 候補 | 選ばれたパートナー | ペアの貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | (2, 15) | (0,10)、(4,9)、(7,7) | (7,7) | 15 − 7 = 8 |
 | 2 | (0, 10) | (4,9) | (4,9) | 10 − 4 = 6 |

 合計は14です。 

このトレースは、アルゴリズムがどのようにして残りの最大 r を固定最大値として一貫して割り当て、対応する減算項を貪欲に最小化するかを示しています。 

2 番目の例として、(1,100)、(2,3)、(4,5)、(90,91) を考えます。 

正規化: (1,100)、(2,3)、(4,5)、(90,91)。 r でソート: (1,100)、(90,91)、(4,5)、(2,3)。 

| ステップ | マックスアール | ミニプール | パートナー | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,100) | (2,3)、(4,5)、(90,91) | (2,3) | 100 − 2 = 98 |
 | 2 | (90,91) | (4,5) | (4,5) | 91 − 4 = 87 |

 これは、大きな r 値が最大値として保存され、小さな l 値ができるだけ早く消費される様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | r によるソートが優勢であり、ヒープ操作は要素ごとに対数的になります。 
| スペース | O(n) | インターバルとヒープ構造の保存 |

 この制約では最大 2n = 200000 個の要素が許可されるため、O(n log n) の解法は時間制限内に簡単に収まりますが、二次関数のアプローチはすぐに失敗します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    # inline solution
    n = int(input())
    a = []
    for i in range(2 * n):
        x, y = map(int, input().split())
        l = min(x, y)
        r = max(x, y)
        a.append((l, r, i))

    import heapq
    a.sort(key=lambda x: x[1], reverse=True)
    heap = []
    used = [False] * (2 * n)

    for l, r, i in a:
        heapq.heappush(heap, (l, i, r))

    ans = 0

    for l, r, i in a:
        if used[i]:
            continue
        used[i] = True

        while heap and used[heap[0][1]]:
            heapq.heappop(heap)

        l2, j, r2 = heapq.heappop(heap)
        used[j] = True

        ans += max(r, r2) - min(l, l2)

    return str(ans)

# sample-style test

assert run("1\n0 0\n1 1\n") == "1"

 ## 特殊なケース

 すべての ai と bi が同一である最小構成は、アルゴリズムがすべてのペアに対して寄与ゼロを正しく生成することを示しています。 l と r はすべての要素で等しいため、max-r 項と min-l 項の両方が各ペア内で正確にキャンセルされます。 

(1,2)、(3,4)、(5,6) などの多くの小さな間隔とペアになった (0,100) などの密にパックされた構成は、アルゴリズムが一貫して最大の r を最初に優先し、主要な寄与が早期に捕捉され、次善のペアリングに決して失われないことを保証することを示しています。 

最後の微妙なケースには、(1,10)、(2,9)、(3,8)、(4,7) などの混合順序が含まれますが、r でソートされた構造により、小さい要素が最適なパートナーの選択を妨げる前に、大きい r 要素がすべてペアにロックされるため、貪欲なペアリングは依然として正しく動作します。
