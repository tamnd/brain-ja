 ## 解決策
 ## 問題の理解

 整数の配列が与えられており、それを好きなように並べ替えることができます。 注文を選択した後、ポジションのペア$(i,j)$と$i<j$場合は良いと呼ばれます$$\gcd(a_i, 2a_j) > 1.$$課題は、適切なペアの数を最大化することです。 

入力には複数のテスト ケースが含まれています。 テスト ケースごとに 1 つの配列を受け取り、並べ替え後に可能な限り最大数の適切なペアを出力する必要があります。 

最も重要な制約は、すべての配列の合計サイズです。 テスト ケースは最大 1000 件ありますが、すべてのテスト ケースの合計は$n$これにより、複雑さの状況が完全に変わります。 アン$O(n^2)$アルゴリズムは完全に安全です。$$2000^2 = 4 \cdot 10^6,$$これは 2 秒の制限としては小さいです。 高度な数理論や高度なデータ構造は必要ありません。 

微妙な点は、条件には以下が含まれることです。$2a_j$、 ない$a_j$。 これにより、すべての偶数が非常に価値のあるものになります。 たとえば:

 入力:```
1
2
2 3
```配列を次のように配置すると、$[2,3]$、 それから$$\gcd(2, 2\cdot3)=\gcd(2,6)=2,$$だからペアは良いです。 

をチェックする不用意な解決策$\gcd(a_i,a_j)$代わりに、次のように誤って結論付けることになります$$\gcd(2,3)=1.$$もう 1 つの簡単な間違いは、偶数のペアのみが重要であると仮定することです。 

入力：```
1
3
2 3 5
```として注文する$[2,3,5]$与える$$\gcd(2,6)=2,\qquad \gcd(2,10)=2.$$先頭の偶数が関係するペアはどちらも良好です。 

最後のエッジケースは、すべての数値が奇数の場合に発生します。 

入力：```
1
3
1 3 5
```並べ替えによって偶数の最初の要素が作成されることはありません。 答えは完全に、奇数間の gcd 条件を直接チェックすることで得られます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての順列を生成し、条件を満たすペアの数を数え、最大値を維持します。 

これが機能するのは、適切なペアの定義が評価しやすいためです。 残念ながら、順列の数は$n!$。 たとえ$n=15$、それはすでに巨大です。 以来$n$は 2000 に達する可能性がありますが、このアプローチは完全に不可能です。 

重要な観察は状態を観察することから始まります$$\gcd(a_i,2a_j)>1.$$仮定する$a_i$は均等です。 それから$2a_j$も偶数であるため、両方の数値は次で割り切れます。$2$。 したがって$$\gcd(a_i,2a_j)\ge 2.$$つまり、最初の要素が偶数であるすべてのペアは自動的に良好になります。 

これは貪欲な戦略を示唆しています。 できるだけ多くのインデックスに、奇数の前に偶数が含まれるようにしたいと考えています。 すべての偶数が前に移動された場合、最初の要素がそれらの偶数のいずれかであるすべてのペアが自動的に良好になります。 

すべての偶数を最初に配置した後、残りのペアは奇数のペアになります。 これらのペアについては、単に gcd 条件を直接テストします。 

このように配列を並べ替えると、答えを数えるのが簡単になります。 すべてのペアを検査します$(i,j)$そして満足できるものを数えてください$$\gcd(a_i,2a_j)>1.$$以来$n\le 2000$、$O(n^2)$ペアスキャンは完全に許容されます。

 | --- | --- | --- | --- |
 | ブルートフォース順列 |$O(n!\cdot n^2)$|$O(n)$| 遅すぎる |
 | 貪欲な並べ替え + ペアチェック |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を偶数と奇数に分割します。 
2. すべての偶数を最初に配置し、その後にすべての奇数を配置して、新しい順序を作成します。 
3. 答えをゼロに初期化します。 
4. インデックスのペアごとに$(i,j)$と$i<j$、計算する$$\gcd(a_i,2a_j).$$1. gcd が次の値より大きい場合$1$、答えを増やします。 
2. 最終的なカウントを出力します。 

ステップ 2 が最適である理由は、前に配置されたすべての偶数が、後のすべての要素と自動的に良好なペアを作成するためです。 偶数を前に移動すると、そのようなペアの数が増加するだけで、減少することはありません。 

### なぜ効果があるのか

 偶数の値を考慮します$x$。 それ以降の値ごとに$y$、$$\gcd(x,2y)\ge 2.$$したがって、最初の要素が偶数であるすべてのペアは良好であることが保証されます。 

保証された良好なペアの数を最大化するには、すべての偶数をすべての奇数の前に出現させる必要があります。 偶数の前に奇数を残す順序は、潜在的な自動グッドペアを無駄にします。 すべての偶数を前に移動すると、保証される良好なペアの数が最大になります。 

残りの奇数対奇数のペアについては、これ以上構造を単純化することはできません。 gcd 条件を直接評価する必要があります。 したがって、説明した順序付けの後に直接カウントすることで、考えられる最大の答えが得られます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    even = []
    odd = []

    for x in a:
        if x % 2 == 0:
            even.append(x)
        else:
            odd.append(x)

    a = even + odd

    ans = 0

    for i in range(n):
        for j in range(i + 1, n):
            if gcd(a[i], 2 * a[j]) > 1:
                ans += 1

    print(ans)
```最初の部分は偶数値と奇数値を分離します。 これにより、貪欲な順序付けが実装されます。 偶数グループ内と奇数グループ内での相対的な順序は関係ありません。 

並べ替えられた配列を構築した後、ネストされたループはすべてのペアを 1 回だけ検査します。 ステートメントの条件は、Python の組み込みメソッドを使用して文字通りチェックされます。`gcd`。 

オーバーフローの問題は存在しないため、$$a_i \le 10^5,$$それで$$2a_j \le 2\cdot 10^5.$$ネストされたループは、すべてのテスト ケースにわたって最大約 200 万のペア チェックを実行しますが、これは制限内に簡単に収まります。

## テストケース```python
import sys
import io
from math import gcd

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even = [x for x in a if x % 2 == 0]
        odd = [x for x in a if x % 2 == 1]
        a = even + odd

        ans = 0
        for i in range(n):
            for j in range(i + 1, n):
                if gcd(a[i], 2 * a[j]) > 1:
                    ans += 1

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

assert run("3\n4\n3 6 5 3\n2\n1 7\n5\n1 4 2 4 1\n") == "4\n0\n9", "sample"

assert run("1\n2\n2 4\n") == "1", "all even"
assert run("1\n2\n1 1\n") == "0", "all odd"
assert run("1\n3\n2 3 5\n") == "2", "single even in front"
assert run("1\n4\n2 2 2 2\n") == "6", "all pairs good"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 4`|`1`| 最小の非自明な全偶数ケース |
 |`1 1`|`0`| Gcd は 1 を超えることはありません |
 |`2 3 5`|`2`| 偶数優先の貪欲効果 |
 |`2 2 2 2`|`6`| どのペアも良くなります |

 ## 特殊なケース

 完全に偶数で構成される配列を考えてみましょう。```
1
4
2 4 6 8
```すべてのペアの最初の要素が偶数であるため、すべてのペアが条件を満たします。 アルゴリズムはすべての数値を前に配置してからカウントします。$$\binom{4}{2}=6$$良いペア。 

奇数だけで構成される配列を考えてみましょう。```
1
3
1 3 5
```並べ替えられた配列は変更されません。 アルゴリズムはすべてのペアを直接チェックします。$$\gcd(1,6)=1,\quad \gcd(1,10)=1,\quad \gcd(3,10)=1.$$答えは0です。 

偶数が 1 つだけ含まれる混合物を考えます。```
1
3
3 2 5
```アルゴリズムは次のように並べ替えます。```
2 3 5
```ペアは$$(2,3),\ (2,5),\ (3,5).$$最初の 2 つは、先行要素が偶数であるため、良好です。 最後はそうではありません。 答えは 2 で、これが最大値です。
