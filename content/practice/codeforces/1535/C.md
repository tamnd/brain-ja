 ## 問題の理解

 次の文字列が与えられます。`'0'`、`'1'`、 そして`'?'`。 

すべてを置き換えることができる場合、部分文字列は美しいとみなされます。`'?'`どちらとも独立して`0`または`1`そのため、結果の部分文字列は代替バイナリ文字列になります。 言い換えれば、隣接する文字は常に異なっていなければなりません。 

タスクは、このプロパティを持つ連続した部分文字列の数を数えることです。 

すべてのテスト ケースの合計の長さは最大でも`2·10^5`。 これにより、二次関数は即座に除外されます。 すべての部分文字列を検査するソリューションには、大まかに次のものが必要になります。`n²/2`部分文字列、つまり`2·10^10`いつ`n = 2·10^5`。 各部分文字列を定数時間でチェックするだけでも遅すぎます。 テスト ケースごとに線形または線形に近いアルゴリズムが必要です。 

いくつかの特殊なケースにより、問題は見た目よりも複雑になります。 

考慮する：```
???
```必要に応じて交互の値を割り当てることができるため、すべての部分文字列が美しくなります。 答えは次のとおりです。```
6
```特定の 1 つの割り当てにコミットしようとするソリューション`?`文字が有効な部分文字列を誤って拒否する可能性があります。 

考慮する：```
00
```部分文字列`"00"`交互にすることは不可能です。 答えは次のとおりです。```
2
```2 つの長さ 1 の部分文字列のみが機能します。 

考慮する：```
0?0
```中間の文字は次のようになるため、部分文字列全体が美しくなります。`1`、生産`010`。 

隣接する固定文字のみを比較するローカル チェックでは、この可能性が見逃されます。 

考慮する：```
?1??1
```弦全体が美しくない。 位置パリティにより両方が固定される場合`1`■ 矛盾する割り当てが必要な場合、代わりとなるものは存在しません。 正しい解決策では、遠く離れた固定文字によって生じる競合を検出する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての部分文字列を列挙し、その部分文字列を代替文字列に変換できるかどうかを確認します。 

部分文字列は、次の 2 つの交互パターンのいずれかにのみ一致します。```
010101...
```または```
101010...
```部分文字列ごとに両方のパターンをテストし、すべての固定文字がそれらの少なくとも 1 つと互換性があるかどうかを確認できます。 

このアプローチは正しいです。2 つの交互パターンのいずれかがすべての固定位置に適合する場合に、部分文字列が美しくなるからです。 

問題は部分文字列の数です。 長さの文字列`n`もっている`n(n+1)/2`部分文字列。 と`n = 2·10^5`、これはおよそ 200 億の部分文字列に相当します。 部分文字列ごとに O(1) チェックを行うことすら不可能です。 

重要な観察は、交互の文字列がパリティ ルールを課すということです。 

部分文字列が位置から始まると仮定します。`L`。 

そのポジションを決めたら`L`あるべきです`0`、次に、と同じパリティを持つすべての位置`L`もあるはずです`0`、反対のパリティを持つすべてのポジションは次のようにする必要があります。`1`。 

そのポジションを決めたら`L`あるべきです`1`、役割が逆転します。 

固定文字が両方の可能性を強制的に失敗させると、競合が発生します。 

すべての部分文字列を個別に検査する代わりに、文字列を左から右に処理し、現在の位置で終わる最長の有効なサフィックスを維持します。 

便利なトリックは、固定された各文字を再解釈することです。 

ポジションについて`i`:```
expected value = i mod 2
```は 1 つの交互パターンに対応しますが、```
expected value = 1 - (i mod 2)
```他に対応します。 

固定文字が一方のパターンと一致しない場合は常に、もう一方のパターンをサポートします。 各パターンを破る最新のポジションを追跡します。 

次に、終了位置ごとに`r`を使用すると、有効な部分文字列が左からどこまで始まるかを即座に判断できます。 

これにより、問題は線形スキャンに変換されます。

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右に処理します。 
2. 2 つの値を維持します。`last0`= パターンを作成する最新の位置`010101...`不可能。`last1`= パターンを作成する最新の位置`101010...`不可能。 
3. At position`i`、 もし`s[i]`は`'?'`、競合が発生することはないため、どちらの値も変更されません。 
4. もし`s[i]`は`'0'`、両方の交互パターンで予想される文字と比較します。 

パターンの場合`010101...`期待しています`1`ここで、この位置はそのパターンを破るので、更新します`last0 = i`。 

同様にアップデート`last1`2 番目のパターンが崩れた場合。 
5. もし`s[i]`は`'1'`、同じロジックを実行します。 
6. しましょう```
bad = min(last0, last1)
```で終わる任意の部分文字列`i`そしてそれ以前から始まる`bad`両方の交互パターンが失敗します。 
7. したがって、すべての開始位置は```
bad + 1 ... i
```で終わる美しい部分文字列を形成します`i`。 

このような部分文字列の数は次のとおりです。```
i - bad
```8. この量を答えに加えます。 

### なぜ効果があるのか

 すべての位置について、各交互パターンが不可能になった最新の場所を覚えています。 

で終わる部分文字列`i`その部分文字列全体で少なくとも 1 つの交互パターンが実行可能であれば、それは美しいです。 

部分文字列がそれ以前で始まる場合`last0`、次にパターン`010101...`部分文字列内ですでに矛盾しています。 

同様に、それ以前に開始する`last1`パターンを無効にします`101010...`。 

部分文字列は、両方のパターンが無効になった場合にのみ失敗します。 それはまさに開始位置が最大の場合に発生します。```
min(last0, last1).
```それ以降のすべての開始位置は少なくとも 1 つのパターンを保持するため、美しいものになります。 これらの開始位置を終了位置ごとにカウントすると、すべての美しい部分文字列が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        s = input().strip()
        
        last0 = -1
        last1 = -1
        ans = 0
        
        for i, ch in enumerate(s):
            if ch != '?':
                bit = int(ch)
                
                if bit != (i & 1):
                    last0 = i
                
                if bit != (1 ^ (i & 1)):
                    last1 = i
            
            ans += i - min(last0, last1)
        
        print(ans)

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        last0 = -1
        last1 = -1
        ans = 0

        for i, ch in enumerate(s):
            if ch != '?':
                bit = int(ch)

                if bit != (i & 1):
                    last0 = i

                if bit != (1 ^ (i & 1)):
                    last1 = i

            ans += i - min(last0, last1)

        out.append(str(ans))

    return "\n".join(out)

# provided samples
assert run("3\n0?10\n???\n?10??1100\n") == "10\n6\n25"

# minimum size
assert run("1\n?\n") == "1"

# all equal fixed characters
assert run("1\n0000\n") == "4"

# alternating already
assert run("1\n0101\n") == "10"

# off-by-one boundary
assert run("1\n00\n") == "2"

# mixed case
assert run("1\n0?0\n") == "6"

 ## 特殊なケース

 次のことを考慮してください。```
???
```すべての部分文字列を代替文字列に完成させることができます。 スキャン中はどちらも`last0`または`last1`からの変更`-1`。 追加事項は、`1`、`2`、 そして`3`、生産`6`。 このアルゴリズムでは、当然のことながらすべての部分文字列がカウントされます。 

考慮する：```
00
```2 番目の位置では、2 つの固定ゼロにより、長さ 2 の部分文字列に対して矛盾が生じます。 アルゴリズムは競合位置を更新し、2 つの単一文字部分文字列のみをカウントします。`2`。 

考慮する：```
0?0
```真ん中のキャラクターは柔軟なままです。 このアルゴリズムは、文字列全体をブロックする競合を記録することはありません。これは、中間位置を`1`収量`010`。 答えは次のようになります`6`、すべての部分文字列が美しいことを意味します。 

考慮する：```
?1??1
```2 つの固定パターンは、最終的に、より広い範囲にわたって交互パターンの 1 つを無効にします。 の`last0`そして`last1`更新により、矛盾が発生した場所が正確にキャプチャされます。 少なくとも 1 つのパターンを保持している部分文字列は引き続きカウントされますが、不可能なものは自動的に除外されます。
