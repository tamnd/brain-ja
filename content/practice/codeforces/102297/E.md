 ## 解決策
 ## 問題の理解

 中心にある 2 つの図形、つまり辺の長さを持った正方形に共通の領域が必要です。`s`そして半径のある円`r`。 それらの中心は一致しているため、答えは円が正方形の 4 つの辺と角にどのように到達するかによってのみ決まります。 出力はオーバーラップの面積であり、次の式を使用して小数点第 2 位に四捨五入されます。`3.14159265358979`πの場合。 

させて`a = s / 2`。 第 1 象限では、正方形が長方形を占めます。`0 <= x <= a`、`0 <= y <= a`、円には上部境界がありますが、`y = sqrt(r^2 - x^2)`。 

ジオメトリには 3 つの異なる領域があります。 もし`r <= a`、円は正方形の中に完全に収まるので、答えは単純に円の面積になります。 もし`r >= a * sqrt(2)`、円が正方形の角に達するので、正方形全体が覆われます。 これら 2 つのケースの間では、円は正方形の各辺と交差しますが、角には達していないため、円セグメントを計算する必要があります。 

の制約`s`そして`r`は小さく、どちらも最大でも 100 なので、算術演算自体はまったく問題になりません。 さらに重要なことは、このステートメントはシナリオ数に大きな上限を課していないため、望ましいソリューションはシナリオごとに一定の作業のみを実行する必要があるということです。 グリッド上で反復したり、多くのサンプルで数値積分を実行したり、近似を繰り返し改良したりするアプローチでは、単純なジオメトリによって回避できる作業が無駄になります。 

最初のエッジ ケースは、円が正方形を完全に含む場合です。 例えば、```
1
1 1
```の正方形の面積があります`1`、円には半径があります`1`, したがって、円は四隅すべてをはるかに超えて広がります。 正しい答えは、`1.00`。 常に出力する不注意な実装`πr²`おおよその出力になります`3.14`、これは天窓を覆う部分ではなく、ポットの面積です。 

逆のエッジケースは、円が完全に正方形の内側にある場合に発生します。 例えば、```
1
10 5
```半分の側面がある`5`、半径と正確に等しい。 円は 4 つの辺すべてに接しているため、その完全な領域がカバーされ、答えは次のようになります。`78.54`。 円が常に正方形の角と交差すると想定する実装では、部分オーバーラップ式が誤って適用されます。 

純粋に部分的なケースも誤った取り扱いをしやすいです。 のために```
1
8 5
```半分の面は`4`。 半径はより大きいです`4`したがって、円は正方形の辺と交差しますが、`5 < 4sqrt(2)`, そのため、角をカバーしません。 正しい答えは、`62.19`。 全円領域または全正方形領域のいずれかを使用することは間違っています。 

## アプローチ

 直接的な総当りの手法では、正方形を非常に細かいグリッドに分割し、各小さなセル、つまり代表点が円の内側にあるかどうかをチェックすることで、交差点を近似することができます。 これは概念的に機能します。なぜなら、交点はまさに正方形と円の不等式の両方を満たす点のセットであるからです。 問題は、信頼できる小数第 2 位の精度を得るには十分に細かい分割が必要であり、入力の実際の幾何学的複雑さよりも、サンプリングされた位置の数に応じて作業が増大することです。 

For example, scanning a`10000 x 10000`グリッドはすでに意味しています`100,000,000`1つのシナリオに対するポイント評価。 多くのシナリオでは、これはすぐに非現実的になりますが、ポイント サンプリング法には依然として境界誤差があり、慎重に制御する必要があります。 数値積分にも同じ弱点があります。スライスの数を増やすと精度は向上しますが、誤差が明示的に制限されない限り、完全な保証はありません。 

ブルートフォース手法は、幾何学的に明確に定義された領域を近似しようとしているため機能しますが、サンプリング アルゴリズムが使用するよりもはるかに多くの情報がジオメトリから得られるため、失敗します。 重要な観察は、正方形と円が中心を共有しているため、重なりが両方の軸にわたって対称であることです。 1 つの象限内の面積を計算し、4 倍することができます。 

1 つの象限内で、円が水平辺に達するところでのみ興味深い遷移が発生します。`y = a`。 解決中`sqrt(r² - x²) = a`与える`x = sqrt(r² - a²)`。 

この値を呼び出します`x0`。 から`x = 0`を通して`x = x0`、円は正方形の上端よりも上に伸びているため、カバーされる高さは単純に次のようになります。`a`。 から`x0`を通して`x = a`、覆われた高さは円の高さです`sqrt(r² - x²)`。 これにより、問題全体が 1 つの基本積分に変わります。 

円の上限の逆微分は次のようになります。`F(x) = 1/2 * (x * sqrt(r² - x²) + r² * asin(x / r))`。 

したがって、部分的な場合の第 1 象限のオーバーラップは次のようになります。`a * x0 + F(a) - F(x0)`、

 そして最終的な答えはその値の 4 倍になります。

 ## アルゴリズムのチュートリアル

 1. 正方形の辺を読み取ります`s`と円の半径`r`、次に設定します`a = s / 2`。 半分の辺を操作すると、座標系の中心が原点になり、第 1 象限のみを分析できるようになります。 
2. かどうかを確認します。`r <= a`。 この場合、円は接線の場合も含めて完全に正方形の内側にあるため、次を返します。`πr²`。 
3. かどうかを確認します。`r >= a * sqrt(2)`。 正方形の中心から最も遠い点は角であり、その距離は次のとおりです。`a * sqrt(2)`。 円がその距離に達すると、正方形のすべての点が円の内側に位置するため、戻ります。`s²`。 
4. 残りの部分オーバーラップの場合については、次のように計算します。`x0 = sqrt(r² - a²)`。 これは、円が第 1 象限の正方形の上辺と交わる x 座標です。 2 つの境界ケースの間にあるため、`x0`厳密にその間にあります`0`そして`a`。 
5. 逆デリバティブを定義する`F(x) = 0.5 * (x * sqrt(r² - x²) + r² * asin(x / r))`。 

の積分`sqrt(r² - x²)`から`x0`に`a`は`F(a) - F(x0)`、これにより、第 1 象限のオーバーラップの曲線部分が得られます。 
6. から長方形の部分を追加します。`0`に`x0`。 その幅は`x0`そしてその高さは`a`、したがって、その面積は`a * x0`。 したがって、第 1 象限領域は、`a * x0 + F(a) - F(x0)`。 
7. 第 1 象限の領域を 4 倍し、小数点以下 2 桁で出力します。 両方の形状が中心にあり、座標軸に関して対称であるため、4 つの象限は同一の重なり合いを持ちます。 

### なぜ効果があるのか

 このアルゴリズムは、円が正方形の上辺と交差する正確な位置で、第 1 象限のオーバーラップを分割します。 その時点より前は、垂直セグメント全体が`y = 0`に`y = a`は円の内側にあるため、その寄与は長方形になります。 その点以降、円の境界は正方形の最上部よりも下にあるため、寄与は正確に下の領域になります。`sqrt(r² - x²)`。 逆導関数は、その曲線領域を浮動小数点精度まで正確に計算します。 4 つの象限すべてに同じ領域が存在するため、4 を乗算すると、完全な四角形と円の交差が正確に得られます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

PI = 3.14159265358979

def covered_area(s, r):
    a = s / 2.0

    # The circle is completely inside the square.
    if r <= a:
        return PI * r * r

    # The circle contains the entire square.
    if r >= a * math.sqrt(2.0):
        return s * s

    # Partial overlap.
    x0 = math.sqrt(r * r - a * a)

    def F(x):
        y = math.sqrt(max(0.0, r * r - x * x))
        return 0.5 * (x * y + r * r * math.asin(x / r))

    quadrant = a * x0 + F(a) - F(x0)
    return 4.0 * quadrant

def main():
    t = int(input())

    out = []
    for _ in range(t):
        s, r = map(int, input().split())
        area = covered_area(s, r)
        out.append(f"{area:.2f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```定数`PI`を使用するのではなく、明示的に書かれています。`math.pi`なぜなら、この問題では計算に使用する π の正確な値が指定されているからです。 違いはわずかですが、規定の定数を使用すると、丸めに関する曖昧さがなくなります。 

最初の条件では、`r <= a`、だけではありません`r < a`なぜなら、正方形の辺への接線によって円から領域が削除されるわけではないからです。 同様に、2 番目の条件では、`r >= a * sqrt(2)`, 角に触れると、正方形全体がすでに円の内側に入っていることを意味するためです。 

部分的な場合には、`x0`数学的に有効であることが保証されているため、`r² - a²`は非負です。 の`max(0.0, ...)`内部`F`これは、理論的にはゼロであるはずの式を評価する際の浮動小数点の丸めによって引き起こされる小さな負の値に対する防御手段です。 

に対する議論`asin`数学的にも次の間にあります`-1`そして`1`。 ここでは、すべての座標が第 1 象限で取得されるため、負ではありません。 式は次の場合にのみ評価されます。`x <= a < r`部分的なケースでは、`x / r`有効です。 

Python の浮動小数点演算は、要求された小数点以下 2 桁の最大 100 の値には十分です。また、Python では整数オーバーフローの懸念はありませんが、一般的に交差領域は整数ではないため、計算は意図的に浮動小数点に変換されます。

 ## 特殊なケース

 のために`s = 1`そして`r = 1`、半分の辺は`0.5`コーナーの距離は約`0.7071`。 このアルゴリズムは、まず円が正方形の中に収まるかどうかをチェックし (偽)、次に円が角に達しているかどうかをチェックします (真)。 正方形の面積を返します。`1.00`。 これにより、円の面積を返すというよくある間違いを防ぐことができます。 

のために`s = 10`そして`r = 5`、半辺と半径は両方とも`5`。 最初の条件`r <= a`成功したため、アルゴリズムは戻ります`π * 25`、つまり`78.54`必要な値 π を使用します。 円は正方形の側面にのみ接触しているため、円のどの部分も天窓の外側にはありません。 

のために`s = 2`そして`r = 1`、半分の辺は`1`中心から隅々までの距離も`1`。 2 番目の条件は成功します。`r >= a * sqrt(2)`ここでは実際には false になるため、このケースは詳しく調べる必要があります。コーナーの距離は次のとおりです。`sqrt(2)`、 ない`1`。 正しい分類は次のとおりです。`r <= a`、円は 4 つの辺に接しており、面積があることを意味します。`π`、生産`3.14`、 ない`4.00`。 これは、コーナー距離境界の魅力的だが誤った解釈を捉えています。 

対応するコーナータッチの場合の整数値は次のように取得できます。`s = 2`非整数半径`sqrt(2)`、ただし入力が制限されます`r`整数に。 したがって、この正方形の隅の境界に正確に到達する整数半径入力はありません。 実装は依然としてその数学的境界を正しく処理します。`r >= a * sqrt(2)`比較。 

部分的なケースの場合`s = 8`そして`r = 5`、半分の辺は`4`したがって、どちらの封じ込め条件も当てはまりません。 上辺との交点は、`x0 = sqrt(25 - 16) = 3`。 アルゴリズムは全高を割り当てます。`4`間隔を超えて`[0, 3]`、からの円を統合します。`3`に`4`、第 1 象限の結果を 4 で乗算します。 最終的な値は`62.19`、サンプルと一致します。 

チェックする価値のある最後の境界は、円が正方形よりもはるかに小さい場合です。 例えば、```
1
100 1
```半分の側面がある`50`と半径`1`。 円は完全に正方形の内側にあるため、アルゴリズムはすぐに戻ります。`π`、次のようにフォーマットされます`3.14`。 円の一部が正方形の境界と交差する必要があると仮定した数値的または幾何学的実装は、不必要な複雑さをもたらし、存在しない領域を簡単に減算する可能性があります。
