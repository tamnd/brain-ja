 ## 解決策
 ## 問題の理解

 スタンプは、中央のセルとその直角に隣接する 4 つのセルの 5 つのセルで構成される、軸に沿って固定された十字です。 スタンプを押すと、その 5 つの紙セルが黒くなります。 黒インクはスタンプを押しても黒のままであるため、スタンプを重ねることはできますが、白のままであるはずのセルにスタンプが触れることはできません。 

タスクは、その和集合がまさに黒セルのセットとなるような交差配置の最小数を見つけることです。 画像がすでに完全に白い場合、答えはゼロです。 法的なスタンプでカバーできない黒セルがある場合、答えは不可能です。 

各画像には最大 9 行 9 列が含まれます。 現在、Codeforces ページには 2.5 秒の時間制限と 256 MB のメモリ制限が設定されています。 グリッドの絶対サイズは小さいですが、9 x 9 の画像内に最大 49 個のスタンプ中心が存在する可能性があります。 そのため、スタンプ位置のすべてのサブセットを試すと、グリッド幅が指数関数的に増加するだけでなく、スタンプを保持できるセルの数が指数関数的に増加します。 

最初の有益な観察は、4 つのアームすべてが紙の内側に留まらなければならないため、スタンプの中心は内部セルのみになり得るということです。 法務センターには次の要件も備えている必要があります`#`5 つのセルすべてが十字で占められています。 これらの条件が満たされれば、スタンプを押すことは常に安全です。 これにより、問題を、法定スタンプセンターの選択と、その組合がすべての黒マスを確実にカバーするかどうかに分けることができます。 

より単純な実装を無効にするエッジケースがいくつかあります。 1 セルの黒いイメージはスタンプできません。```
1
1 1
#
```正しい出力は次のとおりです`Image #1: impossible`, なぜなら、スタンプは1 by 1の紙には収まらないからです。 

空の画像にはスタンプがまったく必要ありません。```
1
1 1
.
```答えは`Image #1: 0`。 切手を見つけることに固執する検索では、これは不可能であると誤って宣言することになります。 

黒い角もカバーできません。 例えば、```
1
3 3
###
###
###
```不可能です。 3 x 3 の用紙でスタンプの中心となる可能性があるのは中央のセルだけであり、その十字にはどちらのコーナーも含まれません。 選択したすべてのスタンプが安全かどうかだけをチェックする不用意なソリューションでは、すべての黒いセルが覆われていることをチェックせずにこの画像を受け入れる可能性があります。 

法的なスタンプは存在するが、それだけでは十分ではないという微妙なケースもあります。 のために```
1
3 3
.#.
###
.#.
```中央の十字は法的なスタンプであり、すべての黒いセルをカバーするため、答えは正確に 1 です。すべての黒いセルをカバーする必要があるため、法的な中心の存在のみをチェックするだけでは、大きな画像の場合は十分ではありません。 

## アプローチ

 最も直接的な総当たりアプローチは、すべての法定スタンプの位置を特定し、それらの位置のすべてのサブセットを試すことです。 すべてのサブセットについて、結果の黒セルを構築し、それらをターゲットと比較して、最小のサブセットを維持できます。 

これは正しいです。なぜなら、考えられるすべてのスタンピング シーケンスは、スタンプされた位置のセットによって表現できるからです。 2 回目のスタンプではセルが変更されないため、同じ位置を繰り返しても役に立ちません。 ただし、9 × 9 のボードには、7 × 7、つまり 49 個のスタンプ中心が考えられます。 最悪の場合、すべての場所に法的なスタンプが押されてしまう可能性があります。`2^49 = 562,949,953,421,312`サブセット。 1 つのサブセットのチェックに数回の操作しかかからなかったとしても、これは利用可能な時間をはるかに超えています。 

この問題を処理しやすくするキー構造は、すべてのスタンプが 1 つの行とその隣接する 2 つの行のみに影響を与えることです。 それ自体の行内で、連続する 3 つの列に影響します。 つまり、画像を行ごとに処理する場合、現在の行の範囲は、前、現在、次の行でのスタンプの選択のみに依存します。 

列は最大 9 つであるため、ビットマスクによって 1 つの行で選択されたすべてのスタンプの中心を表すことができます。 スタンプの中心は、次のいずれかでのみ発生します。`c - 2`内部の柱なので、最大でも`2^7 = 128`1 行に可能なマスク。 

前の行でマスクが使用されているとします。`prev`、現在の行はマスクを使用しています`cur`、次の行はマスクを使用します`nxt`。 現在の行は垂直方向のカバレッジを受け取ります。`prev`そして`nxt`。 水平方向のカバレッジを受信します。`cur`なぜなら、選択された中心はすべて、そのすぐ左と右のセルにも色を付けるからです。 もし`horizontal[cur]`を示します`cur | (cur << 1) | (cur >> 1)`、

 現在の行の完全なカバレッジは次のようになります。`prev | horizontal[cur] | nxt`。 

これにより、ターゲット行で必要なものが正確にカバーされているかどうかを確認できます。 選択されたすべての中心が有効なスタンプであることがすでにわかっているため、選択されたスタンプはドットに色を付けることができません。 したがって、すべてのターゲットをチェックするだけで済みます。`#`カバーされています。 

これにより、状態が 2 つの連続する行マスクを記憶する動的プログラムが得られます。 次の行マスクを選択すると、最も古い行が完全に決定され、チェックして破棄することができます。 ブルート フォースは、すべてのスタンプ セットを明示的に考慮するため機能しますが、可能性のある中心が多数ある場合は失敗します。 クロスの行ローカルな性質により、49 位置にわたる指数関数的検索を小さなビットマスク動的プログラムに置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(2^((r-2)(c-2)) * rc)`|`O(rc)`| 遅すぎる |
 | 最適 |`O(r * 2^(3(c-2)))`|`O(2^(2(c-2)))`| 承認済み |

 と`c <= 9`、最適な遷移境界はせいぜい大まかです。`9 * 2^21`これは、これらの小さなグリッドには実用的です。 

## アルゴリズムのチュートリアル

 1. グリッドを読み取り、どの内部セルがスタンプの中心として機能できるかを決定します。 センター`(i,j)`中心とその 4 つの近隣がすべて揃っている場合、まさに合法です。`#`。 このようなスタンプは、対象のドットに黒インクが発生することがないため、安全に使用できます。 
2. 行ごとにビットマスクを作成します`allowed[row]`その行にあるすべての法定スタンプセンターが含まれます。 境界行にはスタンプを中央に配置できないため、自動的に空のマスクが設定されます。 
3. すべてのサブマスクを生成します。`allowed[row]`。 各サブマスクは、その行に配置する法的スタンプの 1 つの可能な選択肢を表します。 行内にスタンプを配置しないことが有効な選択であるため、ゼロ マスクが含まれています。 
4. 考えられるすべての行マスクの水平カバレッジを事前計算します。 もし`cur`いくつかのスタンプセンターを選択します。`cur`、`cur << 1`、 そして`cur >> 1`中央のセルとその水平アームを表します。 それらの結合は、まさに現在の行の、その行の中央にあるスタンプで色付けされた部分です。 
5. 2 つの空の行を使用して動的プログラムを初期化します。 概念的には、画像の前の行にはスタンプがなく、最初の画像行にもスタンプの中心となる可能性がないため、初期状態は次のようになります。`(prev, cur) = (0, 0)`コストゼロで。 
6. 画像を上から下に処理します。 現在の行に対してマスクを選択します`nxt`次の行の可能なスタンプ マスクから選択します。 現在の行は完全に決定されます。これは、その垂直カバレッジが次のとおりであるためです。`prev`そして`nxt`、水平方向のカバレッジは次のとおりです。`cur`。 
7. コンピューティング`covered = prev | horizontal[cur] | nxt`。 この遷移は、現在のターゲット行のすべての黒セルが含まれる場合にのみ維持されます。`covered`。 ビットマスク形式では、条件は次のようになります。`(covered & target[row]) == target[row]`。 
8. 動的プログラミング状態を次から移行します。`(prev, cur)`に`(cur, nxt)`選択したスタンプの数を追加します`nxt`コストに。 選択したスタンプの数は単純に`nxt.bit_count()`。 
9. 最後の行では、強制的に`nxt = 0`。 これにより、スタンプが用紙の外側に配置されるのを防ぎ、最終行で完全なカバレッジ チェックが行われます。 
10. 最後の行が処理された後、生き残っているすべての状態の中から最小コストを取得します。 状態が生き残っていなければ、目的の画像は不可能です。 

### なぜ効果があるのか

 不変条件は、DP 状態であることです。`(prev, cur)`は、保存されている最小数のスタンプを正確に使用して、現在の行までのスタンプの可能なすべての選択肢を表し、次の行だけを未決定のままにします。 アルゴリズムが選択するとき`nxt`では、現在の行に影響を与える可能性のあるすべてのスタンプが認識され、前、現在、または次の行の中央に配置されます。 したがって、カバレッジテストは正確です。 トランジションは、現在の行の黒いセルがすべて覆われているときに正確に維持され、選択されたスタンプはそれぞれ個別に有効であるため、ドットは決して色付けされません。 行をチェックした後は、今後のスタンプがその行に到達できないため、前の行を忘れてしまう可能性があります。 すべての有効なスタンピング構成は、DP によって考慮される行マスクの 1 つのシーケンスを生成し、すべての DP シーケンスは正当なスタンプに対応するため、スタンプの累積数を最小限に抑えることで真の最適化が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**9

def solve_case(r, c, grid):
    # A stamp center must be strictly inside the grid.
    # allowed[i] contains the columns where a legal stamp can be centered.
    allowed = [0] * r

    for i in range(1, r - 1):
        mask = 0
        for j in range(1, c - 1):
            if (
                grid[i][j] == '#'
                and grid[i - 1][j] == '#'
                and grid[i + 1][j] == '#'
                and grid[i][j - 1] == '#'
                and grid[i][j + 1] == '#'
            ):
                mask |= 1 << j
        allowed[i] = mask

    # Every possible set of stamp centers in a row.
    choices = []
    for mask in allowed:
        row_choices = []
        sub = mask
        while True:
            row_choices.append(sub)
            if sub == 0:
                break
            sub = (sub - 1) & mask
        choices.append(row_choices)

    # Target row as a bitmask.
    target = []
    for row in grid:
        mask = 0
        for j, ch in enumerate(row):
            if ch == '#':
                mask |= 1 << j
        target.append(mask)

    # Horizontal coverage produced by stamps centered in each row.
    full = (1 << c) - 1
    horizontal = [0] * (1 << c)
    for mask in range(1 << c):
        horizontal[mask] = (
            mask
            | ((mask << 1) & full)
            | (mask >> 1)
        )

    # dp[(prev, cur)] = minimum number of stamps selected so far.
    # Initially both rows contain no stamps.
    dp = {(0, 0): 0}

    for i in range(r):
        ndp = {}

        if i + 1 < r:
            next_choices = choices[i + 1]
        else:
            # Nothing may be centered outside the paper.
            next_choices = [0]

        for (prev, cur), cost in dp.items():
            base = prev | horizontal[cur]

            for nxt in next_choices:
                covered = base | nxt

                # Every '#' in this row must be covered.
                if (covered & target[i]) != target[i]:
                    continue

                new_cost = cost + nxt.bit_count()
                state = (cur, nxt)

                old = ndp.get(state, INF)
                if new_cost < old:
                    ndp[state] = new_cost

        dp = ndp

        if not dp:
            return None

    return min(dp.values()) if dp else None

def solve():
    t = int(input())

    out = []

    for case in range(1, t + 1):
        r, c = map(int, input().split())
        grid = [input().strip() for _ in range(r)]

        answer = solve_case(r, c, grid)

        if answer is None:
            result = "impossible"
        else:
            result = str(answer)

        out.append(f"Image #{case}: {result}")
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

の`allowed`マスクは実際の列番号をビット位置として使用します。 これにより、水平方向のシフトがグリッド列と直接整列するため、圧縮された列インデックスと元の列インデックスの間で変換は行われません。 法務センターは柱にしかないので`1`を通して`c - 2`、マスクを左右にずらすと紙の中に留まります。 

の`choices`構築では、行ごとに法的センターのすべてのサブセットが列挙されます。 これは、すべての列の任意のサブセットを列挙するわけではありません。 最悪の場合、中央の列は 7 つしか考えられないため、1 行には最大 128 の選択肢があります。 

ターゲット行はマスクとしても表されます。 表現`(covered & target[i]) == target[i]`黒セルが 1 回または複数回カバーされたかどうかを気にせずにカバレッジをチェックします。 これは、繰り返しの黒インクが単層と区別できない物理的なスタンピングプロセスと一致します。 

動的プログラミング状態には、ちょうど 2 つの行マスクが含まれています。`prev`現在の行の上の中央にスタンプの下向きアームを供給します。`cur`現在の行の中心と水平アームを提供し、`nxt`スタンプの上向きアームをその下を中心に供給します。 現在の行がチェックされたら、`prev`はもう必要ありません。

最後の遷移では明示的に使用します。`[0]`のために`nxt`。 この境界条件がなければ、DP は概念的に紙の下の中央にあるスタンプを使用して最後の行のセルを覆うことができますが、これはスタンプ全体が紙の中に残るという要件に違反します。

 ## 特殊なケース

 完全に白いイメージの場合、すべてのターゲット行にはマスク 0 が含まれます。 DP は常にゼロ スタンプを選択でき、すべての行がカバレッジ テストに合格します。`(0 & 0) == 0`。 例えば、```
1
1 1
.
```生成する`Image #1: 0`。 スタンプの空のセットは自然にゼロ マスクで表現されるため、実装には特別なケースは必要ありません。 

スタンプより小さい黒い画像の場合、正当な中心位置はありません。 考慮する```
1
1 1
#
```の`allowed`配列にはゼロのみが含まれます。 唯一の DP 状態はカバレッジがゼロですが、ターゲットには黒ビットが 1 つ含まれているため、カバレッジ テストで拒否されます。 最終状態セットは空であり、答えは次のようになります。`impossible`。 

スタンプには斜めのセルがないため、黒い角が十字で覆われることはありません。 で```
1
3 3
###
###
###
```センターは合法ですが、その範囲は```
.#.
###
.#.
```角の部分は残っていない。 DP が最初の行をチェックするとき、選択された中心は中央のビットのみをカバーできるため、ターゲット マスクはカバレッジ マスクに含まれません。 構成は最後の行に到達する前に拒否されます。 

有効な中心には、5 つのスタンプ セルがすべて黒である必要もあります。 例えば、```
1
3 3
...
.#.
...
```の中心は黒ですが、十字を置くと 4 つの点に色が付くため、法的なスタンプはありません。 センターは追加されません`allowed`したがって、DP はそれを使用する方法がなく、正しくレポートします。`impossible`。 

重複するスタンプには特別な処理は必要ありません。 3 x 5 のサンプルでは、```
.#.#.
#####
.#.#.
```2 つの十字を内側の 2 つの黒い柱の中心に置くことができます。 一部のセルは両方のスタンプで覆われていますが、ターゲットはセルが少なくとも 1 回黒かどうかのみを気にします。 DP で使用されるビット単位の共用体では、1 つと複数のカバーリングの区別が自然に削除され、最小値は 2 です。 

最終行の境界は強制的に処理されます。`nxt`ゼロに。 この制限がなければ、トランジションでは紙の下にある仮想の中心を使用し、その上向きのアームが最終行のターゲット セルをカバーする可能性があります。 同じ原則が最初のゼロ状態まで上部ですでに適用されているため、スタンプはどちらの垂直境界をも越えて拡張することはできません。
