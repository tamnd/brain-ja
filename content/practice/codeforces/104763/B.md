 ## 解決策
 ## 問題の理解

 トンネル内には短い一連のライトが与えられ、各ライトはオフ (0) またはオン (1) になります。 目標は、このシーケンスを、隣接するライトが常に異なる完全に交互のパターンに変換することです。 有効なターゲット パターンは 2 つあります。1 つは 0 で始まり 0101... として代替され、もう 1 つは 1 で始まり 1010... として代替されます。 

1 つの操作は、ライトを反転して 0 から 1、または 1 から 0 に変更することで構成されます。指定された構成を 2 つの交互パターンのいずれかに変えるために必要な反転の最小数を決定する必要があります。 

入力サイズは小さく、n は最大 100 です。これは、すべての位置を検査して複数のパターンと比較するソリューションでも、十分に高速であることがすぐにわかります。 候補パターンごとの線形スキャンではすでに最大で数百の演算が行われるため、O(n) または O(n²) であっても安全です。 

主なエッジ ケースは、非常に小さな入力、およびすでに交互またはほぼ交互になっている入力から発生します。 たとえば、入力が「0」の場合、両方のターゲット パターンは「0」または「1」のいずれかになるため、比較に応じて答えは 0 または 1 になります。 文字列がすでに「010101」のように交互になっている場合、答えは 0 である必要があり、開始パターンが 1 つだけであると誤って仮定した解決策は引き続き機能しますが、他の場合には最適な位置合わせを逃す危険があります。 

ターゲット パターンを 1 つだけ考慮すると、微妙な間違いが発生します。 たとえば、入力が「1010」の場合、すでに 1 で始まるパターンと一致しますが、0 で始まるパターンとは完全に異なります。どちらか 1 つだけをチェックすると、一般に間違った答えが得られます。 

## アプローチ

 直接的な総当たりアプローチでは、長さ n の両方のターゲット文字列を明示的に構築し、不一致を数えることによってそれらを入力と比較します。 考えられる開始ビットごとに、完全な交互文字列を生成し、ハミング距離を計算します。 これは正しいです。有効なソリューションはすべて、これら 2 つの固定パターンのいずれかに正確に一致する必要があるからです。 

ブルートフォースのコストはわずかです。長さ n の 2 つの文字列を生成し、それらを比較すると、パターンごとに O(n) のコストがかかるため、O(2n) になります。 n ≤ 100 の場合、これは無視できます。 もっと単純に各位置を繰り返し切り替えて変換をシミュレートしたとしても、制限内にとどまることになりますが、その必要はありません。 

重要な観察は、ターゲットの構造が完全に固定されていることです。 候補者は 2 つだけで、各位置は独立して不一致数に 0 または 1 を与えます。 これにより、シミュレーションや貪欲な決定の必要がなくなります。 1 回スキャンし、両方のパターンに対する不一致を蓄積することで、コストを直接計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース構築 + 比較 | O(n) | O(n) | 承認済み |
 | 単一スキャンの不一致のカウント | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力文字列を読み取り、文字の配列として扱います。 明示的に保存せずに、2 つの概念的な交互パターンと比較します。 
2. 2 つのカウンターを初期化します。1 つは 0 で始まるパターンのマッチングのコスト用で、もう 1 つは 1 で始まるパターンのコスト用です。これらは、各ターゲットに必要なフリップの回数を表します。 
3. 0 から n - 1 までの各インデックス i を繰り返します。各位置で、両方のパターンで正しい文字が何であるかを決定します。 0 で始まるパターンの場合、期待値は i % 2 です。1 で始まるパターンの場合、期待値は 1 - (i % 2) です。 
4. 現在の文字を両方の期待値と比較します。 異なる場合は、対応するカウンタをインクリメントします。 このステップでは、そのパターンを選択した場合に必要なフリップの回数を直接測定します。 
5. すべてのポジションを処理した後、2 つのカウンタの最小値を取得して出力します。 これは可能な限り最良の交互パターンを表します。 

### なぜ効果があるのか

 1 つのライトを反転しても他の位置には影響しないため、文字列内の各位置は最終コストに関して独立しています。 固定ターゲット パターンに必要なフリップの合計数は、入力とそのパターンの間で一致しないインデックスの数と正確に一致します。 有効なパターンは 2 つだけであり、すべての有効な代替構成はそれらの 1 つと正確に一致する必要があるため、これら 2 つの不一致数の最小値が必然的に最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

cost0 = 0  # pattern 0101...
cost1 = 0  # pattern 1010...

for i, ch in enumerate(s):
    bit = ord(ch) - 48  # convert '0'/'1' to int

    expected0 = i % 2
    expected1 = 1 - (i % 2)

    if bit != expected0:
        cost0 += 1
    if bit != expected1:
        cost1 += 1

print(min(cost0, cost1))
```この実装では、ターゲット文字列を構築する代わりに、2 つの実行中の不一致カウントが保持されます。 変換`ord(ch) - 48`繰り返しの文字列比較を回避します。 各インデックスは両方のカウンターに独立して寄与するため、両方のチェックが干渉することなく同じループで実行されます。 

よくある間違いは、最初に見つかった不一致に応じて 1 つのカウンタのみを更新することです。 各パターンは最終構成に関する個別の仮説であるため、両方を評価する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    cost0 = 0
    cost1 = 0

    for i, ch in enumerate(s):
        bit = ord(ch) - 48

        if bit != (i % 2):
            cost0 += 1
        if bit != (1 - i % 2):
            cost1 += 1

    return str(min(cost0, cost1))

assert run("5\n01011\n") == "1", "sample 1"

assert run("1\n0\n") == "0", "already valid single element"

assert run("1\n1\n") == "0", "already valid single element"

assert run("4\n0000\n") == "2", "all equal needs half flips"

assert run("4\n0101\n") == "0", "already alternating start 0"

assert run("4\n1010\n") == "0", "already alternating start 1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1レングスのケース | 0 | 最小境界の正確性 |
 | 0000 | 2 | 最悪の一様不一致動作 |
 | 0101 | 0 | 最初のパターンの正しい認識 |
 | 1010 | 0 | 2 番目のパターンの正しい認識 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、最小入力サイズ n = 1 です。入力「0」の場合、両方の交互パターンが長さ 1 の有効な候補であるため、不一致カウントはそれぞれ 0 と 1 となり、答えは 0 になります。両方のカウンターが独立して計算され、最小値が採用されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、「0000」のような完全に均一な文字列です。 アルゴリズムはそれを両方のパターンと比較します。 0101 に対しては、インデックス 1 と 3 で不一致となり、コスト 2 が与えられます。1010 に対しては、インデックス 0 と 2 で不一致となり、コスト 2 が与えられます。したがって、出力は 2 となり、位置の半分を反転する必要があるという事実と一致します。 

最後のケースは、文字列がすでに 1 つのパターン (「1010」など) に正確に一致している場合です。 そのパターンの不一致カウンターはスキャン全体を通じてゼロのままですが、他のカウンターではエラーが蓄積されます。 最小値を取るので、出力は正しく 0 になります。
