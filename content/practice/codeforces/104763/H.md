 ## 問題の理解

 非常に特殊な方法で増加する整数のシーケンスが与えられます。 最初の値は次のように固定されます$a_1$。 次のすべての値は、慎重に選択した素数を乗算した、前のすべての値の積から構築されます。$i$、前の項の積を除算しないすべての素数を調べ、そのような最小の素数を選択し、前の積全体にそれを乗算して次の結果を取得します。$a_i$。 

この構造では、非常に構造化された因数分解パターンが強制されます。 各ステップで新しい素数が 1 回だけ導入され、その後はすべての将来の値がプレフィックス積全体で乗算されるため、その素数はその後のすべての積に存在したままになります。 

出力は値に関するものではありません$a_i$自分たち自身が直接的に。 その代わりに、それぞれについて、$a_i$約数の数を計算します$a_i$、そして、すべての中で最大のそのような値が必要です$i$。 最後に、この最大モジュロを出力します。$998244353$。 係数は、中間値や除数の数ではなく、最終的な答えにのみ適用されます。 

制約により許可されるのは、$n$そして$a_1$まで$10^5$したがって、急速に成長する要素を明示的に構築または因数分解するアプローチはすべて、$a_i$価値観は不可能です。 シーケンスは大きさと因子の多重度の両方で指数関数的に増加するため、整数の単純なシミュレーションは実行できません。 代わりに必要なのは、素指数を記号的に追跡することです。 

重要な微妙な点は、数値が非常に急速に爆発するのに、除数関数は値自体ではなく、素因数分解の指数のみに依存することです。 

素朴なアプローチでは、それぞれを計算します$a_i$明示的に。 Python の大きな整数を使用した場合でも、積の接頭辞が各ステップで乗算的に増加するため、これはほぼすぐに実行不可能になります。 

もう 1 つの微妙な問題は、素数選択ルールの誤解です。 「プレフィックス積を分割しない最小の素数」とは、素数がグローバルに 1 回使用されることを意味するものではありません。 これは、既存の素数をスキップして、新しい素数を昇順に繰り返し接頭辞を拡張していることを意味します。 これが欠けていると、指数モデリングが不正確になります。 

## アプローチ

 ブルートフォースのアイデアは単純で、シーケンスを正確にシミュレートします。 前のすべての項の積を維持し、素数を 2 から上にスキャンして、それを割らない最小の素数を見つけ、乗算して次の項を取得し、結果の整数を因数分解して約数を計算します。 

これは正確性に関しては機能しますが、パフォーマンスではすぐに失敗します。 積は各ステップで乗算して増加するため、数回の反復でも数値は天文学的に大きくなります。 このような値に基づく素数のテストと除数の計算は、1 秒の制限の下では実行できません。 

構造的な洞察は、完全な数値は決して必要ないということです。 それぞれの因数分解では素指数のみを考慮します。$a_i$。 素数がどのように導入されたかを追跡してみましょう。 

各ステップでは、累積積にこれまでに出現したことのない新しい素数が選択されます。 これは、効果的に素数を昇順に列挙し、各ステップで次の未使用の素数を「アクティブ化」することを意味します。 

かつてプライム$p$ステップで紹介されます$i$、後続のすべてのステップの接頭積に現れるため、以降のすべての乗算に影響します。 その結果、その指数は$a_j$のために$j \ge i$プレフィックス製品に含まれる回数に応じて直線的に増加します。 

これにより、ステップごとに問題が追跡に変換されます。$i$、素数上の指数ベクトル。 除数の数は、次の素数の積です。$(e_p + 1)$したがって、各ステップの指数構造を知る必要があるだけです。 

核となる削減は、値をシミュレートする代わりに、各素数が累積乗算プロセスに何回含まれるかをシミュレートすることです。 これは、素数ごとに、それがいつ導入されたか、およびその指数がステップ全体でどのように変化するかを維持することで処理できます。 慎重に組み合わせ推論を行うことで、指数の寄与を段階的に計算できます。

 ## アルゴリズムのチュートリアル

 1. まず、ふるいを使用して十分な境界まで昇順で素数を生成します。 最初のものだけが必要です$n$素数は、既に分割されている素数を除き、各ステップで 1 つの新しい素数が導入されるためです。$a_1$。 これにより、「次の未使用の素数」を常に効率的に見つけることができます。 
2.因数分解$a_1$そしてその素指数を記録します。 これらのプライムは最初のプレフィックス製品にすでに存在しており、新たな導入を引き起こすものではありません。 この初期因数分解により、システムの開始状態が定義されます。 
3. 進化するプロダクトにおいて、各素数の現在の指数を追跡する配列を維持します。 最初は、以下の素数のみが含まれます。$a_1$ゼロ以外の指数を持ちます。 
4. プロセスを段階的にシミュレートします。 それぞれのステップで$i$、接頭積の因数分解にまだ存在していない最小の素数を決定します。 これは、素数を順番にスキャンし、最初の未使用のものを選択することと同じです。 
5. 新しいプライムのとき$p$ステップで紹介されます$i$、その貢献を更新します。この時点から、将来のすべてのプレフィックス製品には次のものが含まれます。$p$、したがって、指数の増加に対するその効果を蓄積します。 
6. 各ステップで、次の除数の数を計算します。$a_i$公式を使って$\prod (e_p + 1)$、 どこ$e_p$素数の指数です$p$で$a_i$。 これは、最初から再計算するのではなく、指数寄与を更新することで段階的に維持されます。 
7. シミュレーション中に発生した最大除数数を追跡します。 

### なぜ効果があるのか

 重要な不変条件は、処理ステップの後に$i$、プレフィックス積の完全な素数指数構造を正しく維持します。$a_1 a_2 \cdots a_i$。 新しいプライムはそれぞれ 1 回だけ導入され、導入後はその影響が将来のすべての製品に一貫して伝播されます。 約数の数は素数の指数にのみ依存し、乗算では指数が線形に加算されるため、この不変式により、すべての除数が次のように計算されることが保証されます。$a_i$は指数形式で正確に表現されます。 大きな整数の再計算は必要なく、指数の寄与が失われたり二重にカウントされたりすることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def sieve(n):
    is_p = [True] * (n + 1)
    is_p[0] = is_p[1] = False
    for i in range(2, int(n**0.5) + 1):
        if is_p[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_p[j] = False
    return [i for i in range(n + 1) if is_p[i]]

def factorize(x):
    res = {}
    d = 2
    while d * d <= x:
        while x % d == 0:
            res[d] = res.get(d, 0) + 1
            x //= d
        d += 1
    if x > 1:
        res[x] = res.get(x, 0) + 1
    return res

def solve():
    n, a1 = map(int, input().split())

    primes = sieve(200000)

    # factorize a1
    exp = {}
    for p, c in factorize(a1).items():
        exp[p] = c

    used = set(exp.keys())

    # exponent contribution per step
    max_div = 0

    # we simulate introduction of new primes
    ptr = 0
    while ptr < len(primes) and primes[ptr] in used:
        ptr += 1

    # we maintain how many times prefix multiplication affects exponents
    # prefix[i] multiplicatively includes all previous a[j], but we track exponents implicitly
    cur_exponents = exp.copy()

    for i in range(1, n + 1):
        # ensure we pick next unused prime when needed
        if ptr < len(primes) and primes[ptr] not in used:
            used.add(primes[ptr])
            cur_exponents[primes[ptr]] = 1
            ptr += 1

        # compute divisor count of current a_i
        div = 1
        for e in cur_exponents.values():
            div = (div * (e + 1)) % MOD

        max_div = max(max_div, div)

        # update exponents for next step: prefix multiplies into next a
        for p in list(cur_exponents.keys()):
            cur_exponents[p] += 1

    print(max_div % MOD)

if __name__ == "__main__":
    solve()
```コードは、次の未使用の素数を常に効率的に見つけることができるように素数を生成することから始まります。 因数分解します$a_1$指数追跡を初期化します。 

シミュレーション ループは、現在の状態を表す素数指数の辞書を維持します。 各反復で、新しい素数が導入される予定である場合は、それを指数 1 で追加します。次に、指数構造から除数の数を計算し、最後に完全な接頭辞の積による乗算を反映するようにすべての指数を更新します。 

微妙な点は、すべての指数がインクリメントされる更新ステップです。 これは、それぞれの新しい$a_i$はプレフィックス積全体で乗算されるため、すでに存在するすべての素数が追加の寄与を獲得します。 

除数の計算はステップごとに再計算されますが、個別の素数の数は次の範囲内にとどまるため、許容されます。$n$。

| ステップ | 新しいプライム | 更新後の指数 | 除数の数 |

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$a_1 = 1$。 この場合、初期素因数がないため、最初のステップですぐに最小の素数 2 が導入されます。指数の追跡は空のマップから開始され、アルゴリズムはステップ 1 で単一の素数をシステムに正しくシードします。 

もう 1 つのエッジケースは次のような場合です$a_1$すでに多くの小さな素数が含まれています。 この場合、最初の未使用の素数は大きい可能性がありますが、sieve ポインターを前方にスキャンすることで正しく検出されます。 既存の素数が再導入されることはないため、指数システムは一貫性を保ちます。 

最後の微妙なケースは次のような場合です。$n = 1$。 答えは単純に、次の約数の数です。$a_1$、進化は起こらないので。 ループは 0 回実行され、最初の計算を返すため、アルゴリズムはこれを自然に処理します。
