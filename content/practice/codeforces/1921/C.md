 ## 解決策
 ## 問題の理解

 Stepan は、厳密に増加する瞬間に一連のメッセージを送信する必要があります。 彼の携帯電話は有限の充電で始まり、電源が入っている間は単位時間あたり一定量が失われ、電源を切ってから再度電源を入れると固定コストが消費されます。 問題は、バッテリーがゼロになることなくすべてのメッセージをスケジュールできるかどうかです。 

各テスト ケースでは、メッセージの数、初期バッテリー、単位時間あたりの消費量、電源を切り替えるコスト、メッセージを送信する必要がある正確な瞬間が提供されます。 すべてのメッセージの送信を許可する一連のオン/オフ決定が存在する場合は「YES」を出力し、それ以外の場合は「NO」を出力する必要があります。 

制約により、すべてのテスト ケースにわたるメッセージの合計が 200,000 を超えず、所要時間は最大 200,000 になる可能性があります。$10^9$。 これにより、各時間単位を個別に反復するソリューションは除外されます。 メッセージ時間の違いを考慮して推論する必要があります。 エッジケースには、最初のメッセージまでバッテリーがギリギリ残っている状況や、電話機のオンとオフを切り替える方が、オンにしておくよりもコストがかからない状況が含まれます。 

不注意なアプローチでは、すべての単位時間をシミュレートしたり、電話機の電源を入れたままにするか電源を切るかの選択を無視したりする可能性があり、最適な戦略に切り替えが必要な場合に入力で誤った回答が生じる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、電話機の状態が 0 から最後のメッセージまであらゆる瞬間に考慮され、オンのままか、エネルギーを節約するためにオフになります。 単位時間ごとに、バッテリーの低下を計算します。 これは原理的には正しいですが、$10^9$最大メッセージ時間であるため、時間単位で反復することは不可能です。 

重要な洞察は、バッテリーが不連続な瞬間、つまりメッセージの送信時と電話の切り替えの直前または直後にのみ変化するということです。 2 つの連続したメッセージの間では、電話の電源を入れたままにした方が安いか、電源を切ってからもう一度入れた方が安いかを判断するだけで済みます。 長さのギャップに対して$d$、電話をオンにしたままにしておくと、$a \cdot d$単位をオフにしてからオンにすると消費します$b$単位。 したがって、各間隔の最小バッテリーコストは次のようになります。$\min(a \cdot d, b)$。 最初のメッセージからこれらのコストを累積し、バッテリー残量がゼロを下回るかどうかを確認します。 

この観察により、問題は次のように簡略化されます。$O(n)$連続するメッセージの瞬間の間の差異のみを処理するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (時間単位ごとにシミュレート) | O(max(m_i)) | お(1) | 遅すぎる |
 | 最適 (貪欲な間隔) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n, f, a, b$メッセージ時間のリスト$m$。 
3. バッテリー残量を初期化します。$f$。 
4. 最初のメッセージを含め、連続するメッセージ間のギャップを反復処理します。$m_1$0からのギャップとしてギャップの長さを計算します$d = m_i - m_{i-1}$（と$m_0 = 0$）。 
5. 各ギャップについて、最小バッテリーコストを決定します。$\min(a \cdot d, b)$。 これをバッテリー残量から差し引きます。 
6. いずれかの時点でバッテリーが 0 以下になった場合は、このテスト ケースではブレークし、「NO」を出力します。 それ以外の場合は、すべてのメッセージの後に「YES」を出力します。 

機能する理由: アルゴリズムは、電話機の電源を入れたままにするか、ギャップごとに電話機をオフにしてからオンにするかのうち、常に安価なオプションを選択します。 電話機は 2 つの方法でのみバッテリーを失うため (オンの場合は時間的に直線的、または切り替えた場合は固定されます)、この貪欲な選択により、各メッセージまでの消費量を最小限に抑え、正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, f, a, b = map(int, input().split())
    m = list(map(int, input().split()))
    prev = 0
    battery = f
    possible = True
    for time in m:
        gap = time - prev
        cost = min(a * gap, b)
        battery -= cost
        if battery <= 0:
            possible = False
            break
        prev = time
    print("YES" if possible else "NO")
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`複数のテストケースの場合。 メッセージごとに、直前の瞬間からの間隔を計算し、より安価なコストを計算し、バッテリーを更新します。 の`battery <= 0`チェックにより、Stepan がメッセージを送信できないシナリオが即座に検出されることが保証されます。 使用する`min(a * gap, b)`本質的な貪欲な決断を捉えています。

 - コスト: min(1*3, 5) = 3

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各メッセージは 1 回処理されます。 すべてのテスト ケースの n の合計 ≤ 2×10^5 |
 | スペース | O(n) | テストケースごとのメッセージ時間を保存します。 追加の構造はありません |

 このソリューションは、各メッセージを 1 回処理し、追加メモリの使用を最小限に抑えるため、2 秒の制限時間内に十分収まります。

 ## 特殊なケース

 バッテリーが最初の間隔のコストと正確に等しい場合、アルゴリズムは正しく「NO」を出力します。 ギャップが非常に大きい場合は、乗算します。`a * gap`一部の言語ではオーバーフローする可能性がありますが、Python は大きな整数を処理します。`min(a * gap, b)`正しく選択することで、誤ったオーバーフロー結果が防止されます。 貪欲な選択により、各間隔の消費量が最小限に抑えられるため、トグルをスキップする微妙なケースによって間違った答えが生じることはありません。
