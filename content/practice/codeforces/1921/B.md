 ## 解決策
 ## 問題の理解

 タスクは、最小限の操作を使用して、箱内の猫の初期配置を目標の配置に変換することです。 各ボックスには猫が含まれているか空であり、初期状態はバイナリ文字列によって与えられます。`s`、ターゲット状態はバイナリ文字列で与えられます。`f`。 操作は、空のボックスに新しい猫を入れること、満たされたボックスから猫を取り除くこと、または猫をあるボックスから別のボックスに移動することです。 各操作には 1 日かかるため、目標は必要な日数を最小限に抑えることです。 

制約により許可されるのは、`n`までに`10^5`単一のテスト ケースでの合計と、`n`すべてのテストケースにわたって、`10^5`。 これは、どんな解も線形でなければならないことを意味します。`n`テストケースごとに。 箱ごとに移動する猫をシミュレートしようとする二次的なアプローチでは、遅すぎます。 

エッジケースは、最初と最後の配置に同じ数の猫が含まれている場合、すべてのボックスが最初は空または満杯である場合、または移動が削除と追加の両方を直接置き換えることができる場合に発生します。 たとえば、変形する`s = 10010`に`f = 00001`猫を最初のボックスから 5 番目のボックスに移動し、4 番目のボックスで余分な猫を削除する必要があり、2 つの操作が必要になります。 移動を独立した追加と削除として扱う単純なアプローチでは、カウントが過剰になる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、移動する猫や、埋めるか空にする箱を繰り返し見つけ、操作を明示的に追跡することでプロセスをシミュレートします。 これは正しく動作しますが、遅すぎます。`O(n^2)`最悪の場合。 

より良いアプローチは、単純なカウント戦略を使用して問題を処理することです。 位置ごとに、猫を追加する必要があるかどうかを決定します (`f[i] = 1, s[i] = 0`) または削除された (`f[i] = 0, s[i] = 1`）。 させて`add_count`は猫を必要とするポジションの数であり、`remove_count`削除が必要なポジションの数になります。 猫を削除が必要なボックスから追加が必要なボックスに移動できるため、個別の作業が削減されます。 したがって、最小日数は最大日数となります。`add_count`そして`remove_count`、各移動は猫の追加と削除の両方に同時にカウントされるためです。 この観察により、問題は次のように簡略化されます。`O(n)`テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | カウント + 追加と削除の最大値 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタの初期化`add_count`そして`remove_count`ゼロに。 これらはそれぞれ、猫の追加または削除が必要なボックスの数を追跡します。 
2. 各位置を反復処理します。`i`0から`n-1`。 
3. If`s[i] = 0`そして`f[i] = 1`、増分`add_count`。 これは、ここに猫を追加する必要があることを示しています。 
4. もし`s[i] = 1`そして`f[i] = 0`、増分`remove_count`。 これは猫をここから追い出さなければならないことを示しています。 
5. すべてのポジションを処理した後、必要な最小日数は`max(add_count, remove_count)`。 移動は追加と削除の両方を同時に満たすことができるため、最大値は真の最小値となります。 
6. この値を出力します。 

機能する理由: ペアリングできない追加または削除はすべて個別に処理する必要があります。 すべての移動操作で 1 つの追加と 1 つの削除が同時に処理されるため、2 つのカウントの最大値が必要な合計日数を正確に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    f = input().strip()
    add_count = 0
    remove_count = 0
    for i in range(n):
        if s[i] == '0' and f[i] == '1':
            add_count += 1
        elif s[i] == '1' and f[i] == '0':
            remove_count += 1
    print(max(add_count, remove_count))
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`各文字列を 1 回だけ繰り返します。 の使用`max(add_count, remove_count)`追加と削除を同時に実行できる動きを正確に考慮します。これは、不注意な実装では見落とす可能性がある微妙な点です。 

## 実用的な例

 サンプル入力`s = 10010`、`f = 00001`:

 | 私 | s[i] | f[i] | 追加数 | 削除数 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 | 1 |
 | 1 | 0 | 0 | 0 | 1 |
 | 2 | 0 | 0 | 0 | 1 |
 | 3 | 1 | 0 | 0 | 2 |
 | 4 | 0 | 1 | 1 | 2 |`max(add_count, remove_count) = max(1, 2) = 2`、これは予想される出力と一致します。 

のために`s = 000`、`f = 111`:

 | 私 | s[i] | f[i] | 追加数 | 削除数 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 1 | 1 | 0 |
 | 1 | 0 | 1 | 2 | 0 |
 | 2 | 0 | 1 | 3 | 0 |`max(add_count, remove_count) = max(3, 0) = 3`、必要に応じて。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各位置を 1 回反復して、追加と削除をカウントします。 |
 | スペース | お(1) | テスト ケースごとに使用される整数カウンターは 2 つだけであり、追加のデータ構造は必要ありません。 |

 テスト ケースごとの直線的な複雑さにより、最大で`10^5`ボックスを合計すると、プログラムは 2 秒の制限時間内で効率的に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        f = input().strip()
        add_count = 0
        remove_count = 0
        for i in range(n):
            if s[i] == '0' and f[i] == '1':
                add_count += 1
            elif s[i] == '1' and f[i] == '0':
                remove_count += 1
        output.append(str(max(add_count, remove_count)))
    return "\n".join(output)

# provided samples
assert run("6\n5\n10010\n00001\n1\n1\n1\n3\n000\n111\n4\n0101\n1010\n3\n100\n101\n8\n10011001\n11111110\n") == "2\n0\n3\n2\n1\n4"

# custom cases
assert run("2\n1\n0\n1\n1\n1\n0\n") == "1\n1", "single box add/remove"
assert run("2\n3\n111\n111\n3\n000\n000\n") == "0\n0", "no operations needed"
assert run("1\n5\n10101\n01010\n") == "3", "alternating positions"
assert run("1\n4\n0000\n1111\n") == "4", "all additions"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n0\n1 | 1 | 単一のボックス、猫を追加する必要があります |
 | 1\n1\n0 | 1 | 単一ボックス、猫を削除する必要があります |
 | 3\n111\n111 | 0 | 操作は必要ありません |
 | 5\n10101\n01010 | 3 | 交互の動きにはペアの追加と削除が必要です。 
| 4\n0000\n1111 | 4 | すべての追加を実行する必要があります。 

## 特殊なケース

 すべてのボックスが最初にターゲットと一致すると、`add_count = remove_count = 0`、したがって、出力は 0 です。すべてのボックスが空で、すべてを入力する必要がある場合、`remove_count = 0`、そして最大値は単純に`add_count`。 追加と削除の数が等しい場合、移動はそれらを最適に組み合わせることができるため、交互の位置のテスト ケースで示されているように、出力はまさにこの数になります。 これにより、アルゴリズムが極端なケースと混合ケースの両方を正しく処理していることが確認されます。
