 ## 解決策
 ## 問題の理解

 非常に具体的なプロパティを持つ整数の配列を構築するように求められます。増加する部分列の合計数は、指定された整数に等しくなければなりません。$X$。 増加するサブシーケンスは、各要素が前の要素よりも厳密に大きくなるように、配列から順番に取得された要素のシーケンスです。 各サブシーケンスは、値が同じであっても、配列内の異なる位置を使用している場合、異なるものとしてカウントされます。 空のサブシーケンスも同様にカウントされます。 

入力は複数のテスト ケースで構成され、それぞれが単一の整数を提供します$X$、次のように大きくすることができます$10^{18}$。 出力は、正確に実現する長さ 200 以下の配列を与える必要があります。$X$サブシーケンスが増加しているか、不可能であることを示しています。 配列の各要素には、範囲内の任意の整数を指定できます。$[-10^9, 10^9]$。 

大きな上限は$X$サブシーケンスの単純な列挙を即座に除外します。 すべてのサブシーケンスを生成してそれらをカウントしようとすると、たとえ長さが 60 の配列であっても、サブシーケンスの数は次の数に達する可能性があります。$2^{60} \approx 10^{18}$、それは不可能です。 これは、強引なカウントに頼ることはできず、建設的な方法が必要であることを意味します。 

エッジケースには最小のものが含まれます$X = 2$、これは空のサブシーケンスと単一要素の配列に対応します。 同様に非常に大きい$X$近い値$10^{18}$200 要素の長さ制限を超えないよう慎重に設計する必要があります。 要素を線形に増やしたり、ブロックを複製したりする単純なアプローチでは、許可された配列の長さを静かに超えたり、間違った数が生成されたりする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、配列を段階的に生成し、次の値に達するまで増加するすべてのサブシーケンスをカウントしようとする可能性があります。$X$。 たとえば、空の配列から開始し、動的プログラミングを使用してサブシーケンスを計算しながら要素を追加します。 これは小さい場合には正しいです$X$なぜなら、各ステップは予測どおりサブシーケンス数を増加させますが、それはすぐには非現実的です。新しい要素ごとに、それに含まれるサブシーケンスの数が 2 倍になります。$X \sim 10^{18}$に到達するには、長さ約 60 の配列が必要になります。$X$カウントには反復処理が含まれます$2^{60}$組み合わせ。 

重要な洞察は、** のバイナリ分解を使用することです。$X$**、2 の累乗を配列内の繰り返しブロックにマッピングします。 各ブロックがサブシーケンス全体に独立して寄与するように配列を構築すると、ブロックを乗算的に組み合わせることができます。 具体的には、次の形式の配列`[a, a, a, ...]`繰り返された$k$回が貢献する$k + 1$その数で構成されるサブシーケンス (そのブロックの空のサブシーケンスを含む) を増やします。 の 2 進数に対応するブロック サイズを慎重に選択することで、$X$、任意の条件を達成する最大 200 の長さの配列を構築できます。$X \le 10^{18}$。 

貪欲な戦略は、2 の累乗の最大値からできるだけ大きなブロックを割り当てることです。$X$、そして減らします$X$その貢献によって、再帰的に継続されます。 各ブロックに設計された数のサブシーケンスを正確に提供したい場合は、不要なマージや重複を避けるために、各ブロックの配列値を整数として増やすことができます。

 ## アルゴリズムのチュートリアル

 1.変換$X$バイナリ表現に変換します。 それぞれ`1`位置で$k` corresponds to a contribution of $配列内で実現する必要がある 2^k$ 個の部分列。 
2. 空の配列を初期化します。 必要に応じて新しいブロックに厳密に大きな値を設定できるように、現在使用されている最大要素を追跡します。 
3. 2 の累乗ごとに、降順で、その累乗に等しいサイズの繰り返し要素のブロックを追加します。 たとえば、力`2^k`ある長さのブロックで実現できる`k + 1`同じ番号を使用します。 
4. ブロックが干渉しないようにしてください。 ブロック間で値をインクリメントし、新しく増加するサブシーケンスが前のサブシーケンスと重複しないようにし、正確なカウントを維持します。 
5. 2 のべき乗がすべて一致するまで続けます。$X$ブロックに割り当てられています。 合計の長さが 200 を超えていないことを確認し、超えている場合は -1 を出力します。 それ以外の場合は配列を出力します。 

維持される不変条件は、各ブロックが意図した数の増加するサブシーケンスに正確に寄与し、前のブロックからの寄与を変更しないということです。 これにより、サブシーケンスの合計が正確に $X` になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(X):
    # Start with empty array and current value
    array = []
    current = 0
    # Iterate over bits from most significant to least
    for bit in reversed(range(61)):  # 2^60 > 10^18
        if X >= (1 << bit):
            count = bit + 1
            array.extend([current] * count)
            current += 1
            X -= (1 << bit)
    if len(array) > 200:
        return "-1"
    return f"{len(array)}\n{' '.join(map(str, array))}"

def main():
    t = int(input())
    for _ in range(t):
        X = int(input())
        print(solve_case(X))

if __name__ == "__main__":
    main()
```このソリューションでは、まずテスト ケースの数と各テスト ケースの数を読み取ります。$X$。 機能`solve_case`バイナリ分解メソッドを使用して配列を構築します。 最上位ビットから下へのループにより、最大のブロックが最初に使用され、配列の長さが最小限に抑えられます。 各ブロックは同一の番号を使用して、独立した貢献を保証します。`current`値の観点からブロックを区切るために増分します。 長さチェックにより、200 要素制限への準拠が保証されます。
