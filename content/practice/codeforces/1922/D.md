 ## 解決策
 ## 問題の理解

 モンスターの列があり、それぞれに攻撃値があります`a_i`そして防御値`d_i`。 モノカープは凶暴な呪文を唱え、モンスターがラウンドごとに隣接するモンスターを攻撃します。 仕組みは次のとおりです。各生きているモンスターは、左右にある最も近い生きている隣接モンスター (隣接するモンスターが存在する場合) に、その攻撃に等しいダメージを与えます。 ラウンド内のすべての攻撃が同時に適用された後、受けたダメージの合計がその防御力を超えたモンスターは死亡します。 私たちはこの戦いをシミュレートし、ラウンドごとに死亡するモンスターの数を計算するように求められます。 

入力は複数のテスト ケースを提供します。 各テスト ケースには最大で`3 * 10^5`モンスターとその合計`n`すべてのテスト ケースでも次を超えません`3 * 10^5`。 攻撃力と防御力の値は最大で`10^9`。 

すべての生きているモンスターを反復処理して各ラウンドを素朴にシミュレートすると、おおよそ次のようになります。`O(n^2)`テストケースごとに操作を行う必要がありますが、これは実行不可能です。 まで`3 * 10^5`モンスターよ、もっと近い解決策が必要です`O(n)`テストケースごとに。 

一部のモンスターだけがラウンドで生き残る場合、または端にいるモンスターが 1 匹の隣接モンスターのみから攻撃される場合、微妙なエッジケースが発生します。 たとえば、次のようなテスト ケースです。```
n = 3
a = [10, 1, 10]
d = [5, 20, 5]
```近隣住民を注意深く追跡する必要があるでしょう。 単純な実装では、存在しない近傍に誤ってアクセスしようとしたり、死亡数を誤って数えたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、文字通り各ラウンドをシミュレートします。生きているモンスターごとに、隣接するモンスターに与えられるダメージを計算し、死亡数を更新し、すべてのモンスターが死ぬまで繰り返します。 各ラウンドでは、生きているモンスターとその隣人を反復処理する必要があります。 最悪の場合、すべてのラウンドで`O(n)`生きているモンスター、そして最大まで存在する可能性があります`O(n)`ラウンドします。 これにより、`O(n^2)`最大の入力に対してタイムアウトになる時間計算量。 

最適化するための重要な洞察は、各モンスターが死ぬのは 1 回だけであり、隣接するモンスターから受けるダメージは **生きているモンスターの順序** に基づいて完全に予測可能であるということです。 各ラウンドをシミュレートする代わりに、2 パス線形スキャンを使用して **各モンスターがいつ死ぬか** を事前計算できます。 

私たちは、生きている各セグメントとそれが与える累積的な攻撃を追跡する構造を維持しています。 モンスターが死ぬにつれてセグメントを結合し、攻撃を効率的に伝播することで、個々の攻撃をすべてシミュレートすることなく、各ラウンドでの死亡数を計算できます。 概念的には、この問題は、生きているモンスターのセグメントを効率的に管理し、近隣のモンスターからの貢献を合計することに帰着します。 

この洞察により、時間の複雑さが軽減されます。`O(n^2)`に`O(n)`テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、攻撃配列`a`、および防御アレイ`d`。 
3. リストの初期化`alive`0 から 0 までのインデックス`n-1`。 
4. 各モンスターの初期ダメージを、最も近い生きている隣人の攻撃の合計として計算します。 

-`damage[i] = (a[left_neighbor] if left exists else 0) + (a[right_neighbor] if right exists else 0)`。 
5. 最初のラウンドで死亡したモンスターを特定する: すべて`i`と`damage[i] > d[i]`。 
6. 死んだモンスターを`alive`隣接関係をリストして更新します。 

- 死んだモンスターごとに、隣接するモンスターが互いに隣接するようになります。 
- 生き残った隣人が隣人を失ったり獲得したりするため、ダメージを更新します。 
7. このラウンドで死亡した人の数を記録します。 
8. モンスターが死ななくなるまで、手順 4 ～ 7 を繰り返します。 
9. すべてのモンスターが死亡した後のラウンドでは、0 を出力します。 

これが機能する理由は、各モンスターが最大 1 回死亡し、攻撃がすぐ隣のモンスターにのみ向けられるためです。 隣接要素を効率的に更新し、ダメージを計算することで、死んだモンスターを繰り返したり、攻撃を繰り返し加算したりすることなく、ラウンドをシミュレートします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        d = list(map(int, input().split()))
        
        # linked-list style next and prev to track alive neighbors
        next_alive = list(range(1, n)) + [None]
        prev_alive = [None] + list(range(n-1))
        
        deaths_per_round = []
        alive_set = set(range(n))
        
        while True:
            damage = [0] * n
            for i in alive_set:
                if prev_alive[i] is not None:
                    damage[prev_alive[i]] += a[i]
                if next_alive[i] is not None:
                    damage[next_alive[i]] += a[i]
            
            to_die = [i for i in alive_set if damage[i] > d[i]]
            deaths_per_round.append(len(to_die))
            if not to_die:
                break
            
            for i in to_die:
                alive_set.remove(i)
                if prev_alive[i] is not None:
                    next_alive[prev_alive[i]] = next_alive[i]
                if next_alive[i] is not None:
                    prev_alive[next_alive[i]] = prev_alive[i]
        
        # fill remaining rounds with 0 if any alive monsters remain
        remaining_rounds = len(alive_set)
        deaths_per_round.extend([0]*remaining_rounds)
        
        print(" ".join(map(str, deaths_per_round)))

if __name__ == "__main__":
    solve()
```このソリューションは初期化します`next_alive`そして`prev_alive`配列を使用して、モンスターが死亡したときに隣接するインデックスを効率的に追跡します。 死んだモンスターの反復処理を回避し、関連する近隣のみを更新します。 各モンスターのダメージはラウンドごとに 1 回計算され、死亡するたびに最大 2 つの隣接更新がトリガーされるため、線形な時間計算量が保証されます。
