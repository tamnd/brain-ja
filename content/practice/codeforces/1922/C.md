 ## 解決策
 ## 問題の理解

 1 次元の数直線に沿って配置されたいくつかの都市が与えられます。 各都市には座標があり、座標は厳密に増加しています。 各都市には、固有の「最も近い」都市が存在します。これは、その都市に同じように近い都市は 2 つもないことを意味します。 都市間を移動する場合、2 つのオプションがあります。1 つはコインとして距離を支払って他の都市に直接移動するか、1 コインだけを支払って最も近い都市に移動するです。 それぞれ出発地と目的地の都市を指定する一連のクエリでは、旅行に必要な最小コインを計算する必要があります。 

この制約は、すべてのテスト ケースにわたる都市の合計数が 100,000 に達する可能性があり、クエリの合計数も 100,000 に達する可能性があることを示しています。 これにより、すべての可能なパスをシミュレートしたり、クエリごとにその場で距離を計算したりする単純なアプローチが除外されます。 テスト ケースあたりおよそ O(n + m)、または前処理後のクエリあたり O(log n) のソリューションが許容されます。 エッジ ケースには、最寄りの都市のショートカットを経由した旅行が直接旅行するよりも大幅に安くなるような間隔の都市や、出発地と目的地が路線の両端近くにあるクエリが含まれます。 

潜在的な落とし穴を示す例: 都市が位置にある場合`[0, 1, 10]`の場合、1 に最も近い都市は 0 ですが、1 から 10 への移動は、最初に 0 へのショートカットを使用し、次に 10 へ直接移動する方が安くなる可能性があります。どのソリューションでも、単一のジャンプで十分であると仮定するのではなく、最も近い都市へのジャンプのシーケンスを適切に考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、直接ジャンプと最も近い都市へのジャンプを組み合わせて、おそらくサイズ n のグラフでダイクストラのアルゴリズムを使用して、考えられるすべてのパスをシミュレートすることによって各クエリを試行します。 複雑さは少なくとも O(m * n) ですが、これは n と m が 10^5 までの場合には遅すぎます。 

重要な観察は、各都市が最も近い都市にのみ安価 (1 コイン) で接続していることです。これはユニークです。 距離が 1 より大きい場合、直接移動は常に近道よりもコストが高くなります。都市は直線上にあり、最も近い都市は常にすぐ隣 (左または右) であるため、最も近い都市への一連のジャンプは数直線に沿った単純な単調パスを形成します。 これにより、問題は、クエリごとに最大 2 つのパスをシミュレートすることになります。つまり、最も近い都市のリンクに沿って左に移動し、最も近い都市のリンクに沿って右に移動し、必要に応じてオプションで最後の直接ジャンプを実行します。 各都市に対して最も近い都市を事前に計算することにより、次のジャンプを一定時間で決定することができます。 この洞察を使用すると、前処理後、O(1) または O(log n) 時間で各クエリに答えることができます。 

最も近い都市のリンクが単純なチェーンを形成しているという観察は、都市ごとに左右に最も近い都市を事前計算できることを意味します。 これらのチェーンに沿って移動すると、各ステップに 1 コインのコストがかかり、直接ジャンプが必要になるのは最後だけです。 これにより、問題は複雑なグラフの走査から単純な貪欲なパス選択に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * n) | O(n) | 遅すぎる |
 | 最寄りの都市チェーンを経由する貪欲 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市の数を読み取る`n`そして座標配列`a`。 配列は昇順にソートされます。 
2. 各都市について、最も近い都市を決定します。 座標は厳密に増加しているため、都市の最も近い都市`i`どちらかです`i-1`または`i+1`。 距離を比較する`a[i] - a[i-1]`そして`a[i+1] - a[i]`最小限のものを選択します。 これを次のように保存します`closest[i]`。 
3. クエリを読みます。 クエリごとに`(x, y)`、ゼロベースのインデックスに変換します。 
4. もし`x < y`、最寄りの都市のショートカットを使用して右に移動しようとします。 初期化`coins = 0`そして`current = x`。 その間`current != y`:

 - 最寄りの都市の場合`current`の間にあります`current`そして`y`（右方向に単調）、1コインを払ってそこに移動します。 
- それ以外の場合は、直接ジャンプします。`y`、支払い`|a[current] - a[y]|`。 
5. 対称的に、次の場合`x > y`、最寄りの都市のショートカットを使用して左に移動します。 
6. 各クエリの合計コインを出力します。 

機能する理由: 各都市には固有の最も近い都市があり、これらのリンクに沿った貪欲な移動が不必要に都市を再訪問することがないことが保証されます。 ショートカットが目的地を超えてしまう場合にのみ直接ジャンプすることで、最小限のコイン経路を確保します。 不変条件は、各ステップで常に、目的地に向かう最も安価な即時移動が最も近い都市または直接ジャンプする都市にいることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        closest = [0] * n
        for i in range(n):
            if i == 0:
                closest[i] = 1
            elif i == n - 1:
                closest[i] = n - 2
            else:
                if a[i] - a[i-1] <= a[i+1] - a[i]:
                    closest[i] = i - 1
                else:
                    closest[i] = i + 1
        m = int(input())
        for _ in range(m):
            x, y = map(int, input().split())
            x -= 1
            y -= 1
            coins = 0
            current = x
            while current != y:
                next_city = closest[current]
                # If moving to closest goes in direction of y
                if (y > current and next_city > current) or (y < current and next_city < current):
                    coins += 1
                    current = next_city
                else:
                    coins += abs(a[current] - a[y])
                    current = y
            print(coins)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず O(n) 内の各都市に最も近い都市を事前計算します。 各クエリは、最も近い都市のリンクに沿ったパスをシミュレートするか、最終的な直接ジャンプを行うことによって解決されます。 境界条件は、最初と最後の都市に最も近い都市を単一の隣接都市に割り当てることによって処理されます。 ゼロベースのインデックス調整により、1 ずつずれたエラーが防止されます。 目的地に向かって移動するという貪欲な選択により、最も近い都市の独自性を活用して最小限のコインが確保されます。
