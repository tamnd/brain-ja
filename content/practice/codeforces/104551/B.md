 ## 解決策
 ## 問題の理解

 猿は、固定されたキーボードからランダムなキーを繰り返し押して文字を入力しています。 各キーの押下は独立しており、使用可能な文字に対する既知の確率分布に従います。 また、特定のターゲット単語と、サルが行う一定のキーストローク数も与えられます。 

各テスト ケースについて、このランダムな型指定プロセスから得られる 2 つの量について推論する必要があります。 まず、ターゲット単語が結果の文字列内で連続部分文字列として何回出現すると予想されるかです。 2 番目に、上限を計算するときに、入力順序を敵対的に有利に配置できると仮定した場合、ターゲットが可能な限り最良の結果で出現する可能性がある最大回数は何回ですか。 

テスト ケースごとの出力は、これら 2 つの値の差であり、持参する必要があるが、平均して支払わなくても済む「バナナ」の数として解釈されます。 最悪の事態に備える際に、単語のランダム性と重複構造がどの程度避けられない過大評価を引き起こすかを直感的に測定します。 

重要な入力要素は、キーボードの分布、ターゲットの単語、生成される文字列の長さです。 キーボードは文字の確率を決定し、ターゲットは検索するパターンを定義し、長さは存在する可能性のある開始位置の数を制御します。 

この制約は、サルのタイピングをシミュレートできないことを意味します。 10^5 のような中程度の長さの場合でも、状態空間が指数関数的に増大するため、すべての文字列を生成することは不可能です。 代わりに、部分文字列のアライメントよりも確率と組み合わせ論に依存する必要があります。 位置に対する二次シミュレーションや明示的な文字列生成を使用するソリューションは、制限時間内に即座に失敗します。 

いくつかの特殊なケースは見落とされがちです。 

キーボードにターゲットの文字が少なくとも 1 文字含まれていない場合、ターゲットを形成する確率はゼロとなり、予想出現数と最大出現数は両方ともゼロになります。 

ターゲットに「AAA」などの強い自己重複がある場合、単純なカウントでは発生可能な最大数が過小評価されてしまいます。 たとえば、長さ 4 の文字列では、重複により「AAA」が 2 回出現することがあります (「AAAA」)。 

「ABCD」のように、ターゲットがそれ自体とまったくオーバーラップできない場合、出現するたびに長さ L の完全なブロックが消費され、L ずつシフトされます。 

## アプローチ

 ブルートフォースのアイデアは、サルによって生成された長さ S の可能なすべての文字列をシミュレートし、各文字列にターゲットが出現する回数をカウントすることです。 各文字列の確率を計算し、寄与度を合計します。 これは概念的には正しいですが、可能な文字列の数は S で指数関数的になります。具体的には K^S (K はキーボードの文字数) です。 S = 100 の場合でも、これは完全に不可能になります。 

より構造化されたブルートフォースの改善は、すべての位置をスキャンし、部分文字列がターゲットと一致するかどうかを確認することによって、予想される出現を計算することです。 これにより、期待に O(S·L) 時間が与えられますが、それでもオーバーラップ構造は無視されます。 出現回数を最大にするには、単語を貪欲にスライドさせてすべての配置を試すこともできますが、それでも繰り返し一致させる必要があり、S が大きい場合は非効率的になります。 

重要な観察は、期待にはシミュレーションが必要ないということです。 各開始位置は、期待されるカウントに独立して寄与します。 位置は、そこから始まる部分文字列がターゲットと等しい確率に正確に寄与します。 この確率は、キーボードの分布から導出される個々の文字の確率の積にすぎません。 これにより、期待のためのポジション間の依存関係が完全に排除されます。

最大値の場合、構造は純粋に組み合わせです。 重複を許容して、長さ S の文字列内にターゲットのコピーをできるだけ多く配置したいと考えています。 これは、プレフィックスとサフィックスの重複を維持する最小のシフトを見つけることになります。これは、プレフィックス関数 (KMP 失敗配列) によって正確にキャプチャされます。 有効にオーバーラップしながらパターンをどこまでシフトできるかがわかったら、文字列を貪欲に並べて、完全なコピーがいくつ収まるかを数えることができます。

 ## アルゴリズムのチュートリアル

 ### 予想される出来事

 1. キーボードの周波数からサルの入力シーケンスに各文字が出現する確率を計算します。 これにより、アルファベット上の分布が得られます。 
2. 0 から S − L までのすべての位置 i について、i で始まる部分文字列がターゲットと正確に一致する確率を計算します。 

これは、ターゲット内の各文字の確率を乗算することによって行われます。 
3. すべての有効な開始位置についてこれらの確率を合計します。 この合計が予想される出現数です。 

部分文字列が重なっている場合でも期待値は線形であるため、各位置は独立して処理されます。 

### 最大出現回数

 1. プレフィックス関数 (KMP 失敗配列) を使用して、サフィックスでもあるターゲットの最長の適切なプレフィックスを計算します。 この値を b とします。 
2. 連続する重複発生間のシフトをシフト = L − b として計算します。 

これは、オーバーラップの一貫性を保ちながらパターンを移動できる最小のステップです。 
3. ターゲットがそれ自体とまったくオーバーラップできない場合は、b = 0、shift = L になります。 
4. 最大出現数を 1 + (S − L) // シフトとして計算します。 

### 最終的な答え

 1. 結果は、最大発生数から予想される発生数を引いたものになります。 

### なぜ効果があるのか

 期待値の分解は期待値の線形性に依存します。 発生が重複していて独立していない場合でも、各開始位置は他の位置から独立した固定確率に寄与するため、すべての開始位置を合計すると正しい期待値が得られます。 

最大の構築は、ターゲット内の自己オーバーラップの構造に依存します。 プレフィックス関数は、ある出現箇所を次の出現箇所に移動するときに、どの程度の文字列を再利用できるかを正確に識別します。 より密なパッキングはプレフィックスとサフィックスの一貫性に違反するため、このシフトは最適であり、どのような配置でもこのオーバーラップ パターンを繰り返すことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def prefix_function(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
            pi[i] = j
    return pi

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        K, L, S = map(int, input().split())
        keyboard = input().strip()
        target = input().strip()

        freq = {}
        for c in keyboard:
            freq[c] = freq.get(c, 0) + 1

        prob = 1.0
        possible = True
        for c in target:
            if c not in freq:
                possible = False
                break
            prob *= freq[c] / K

        expected = 0.0
        if possible:
            expected = (S - L + 1) * prob if S >= L else 0.0

        pi = prefix_function(target)
        overlap = pi[-1]
        shift = L - overlap

        if S < L:
            maximum = 0
        else:
            maximum = 1 + (S - L) // shift

        print(f"Case #{tc}: {maximum - expected:.10f}")

if __name__ == "__main__":
    solve()
```このソリューションでは、まずキーボード文字の頻度マップを構築します。これは、任意の固定位置にターゲット文字列が生成される確率を計算するために使用されます。 ターゲット文字間の乗算は、キーストロークの独立性を直接反映します。 

prefix 関数は、ターゲット文字列の最長の境界を計算します。 この境界によって、連続する出現の間でどの程度の重複が可能かが決まります。 そこから派生したシフトにより、出現回数を最大化する文字列のタイリングが定義されます。 

最後に、浮動小数点切り捨ての問題を回避するために、最大値と予想値の差が高精度で出力されます。 

## 実用的な例

 ### 例 1

 キーボードのバランスが取れており、ターゲットが短いため、重なりが見えやすい小さなケースを考えてみましょう。 

S = 4、ターゲット = "AA"、キーボード = "AB" とします。

 | --- | --- | --- |

 | 2 | AA | 1/4 |

 各「A」の確率は 1/2 であるため、各「AA」の確率は 1/4 です。 合計すると、期待値 = 3/4 が得られます。 

最大出現回数:

 ターゲット「AA」はシフト 1 でそれ自体とオーバーラップするため、長さ 4 でオカレンスを「AAAA」として配置し、3 つのオカレンスを生成できます。 

差 = 3 − 0.75 = 2.25。 

### 例 2

 S = 5、ターゲット = "ABC"、キーボード = "ABC" とします。 

すべての文字が決定的に一致する有効な文字列は 1 つだけ存在すると予想されるため、期待される出現は 3 つの部分文字列です。「ABCABC」では 2 つの出現が得られますが、S = 5 であるため、実際の文字列は異なります。 期待値は位置に関する確率から得られますが、最大値はシフト 3 によるオーバーラップのないタイリングから得られます。 

これは、期待値は局所的な確率のみに依存し、最大値は構造の重複に依存することを示しています。

 ## 特殊なケース

 ターゲットにキーボードに存在しない文字が含まれている場合、すべての位置がそれに一致する確率はゼロです。 すべての貢献が消滅するため、期待値は即座にゼロになります。 有効なオカレンスがまったく形成できないため、最大値もゼロになります。 

ターゲットに「AAAA」などの最大の自己重複がある場合、プレフィックス関数は大きな境界線を生成します。 これにより、シフトが 1 に減少します。つまり、オカレンスが密にスタックされる可能性があります。 アルゴリズムは、これを文字列全体にわたるほぼ連続した配置として正しくカウントします。 

「ABCDE」のようにターゲットに重なりがない場合、プレフィックス関数はゼロ境界を返し、全長に等しいシフトを与えます。 次に、アルゴリズムは、一致の間で再利用が不可能であるという直感に一致するように、オカレンスを切り離して配置します。
