 ## 解決策
 ## 問題の理解

 与えられた包含区間内のすべての 2 進数のコンパクトな表現を構築するように求められます。$[L, R]$。 これらの数値を直接リストする代わりに、単一のソースと単一のシンクを持つ有向非巡回グラフを構築する必要があります。このグラフでは、ソースからシンクまでのすべての有効なパスがバイナリ文字列を表します。 各エッジは 0 または 1 のビットに寄与し、パスの値は先頭のゼロのない 2 進整数として解釈されます。 

重要な要件は全単射性です。つまり、すべての整数が$[L, R]$は、ソースからシンクへの 1 つのパスにのみ対応する必要があり、他のパスは許可されません。 したがって、グラフは本質的に、区間内のすべての数値のバイナリ表現を正確に生成する圧縮されたオートマトンです。 

出力は数値そのものではなく、この DAG の構造です。 各ノードはその発信エッジをリストし、各エッジには宛先とビット ラベルがあります。 

制約の構造は厳密ですが、サイズは小さいです。 範囲のエンドポイントは最大でも$10^6$したがって、バイナリ表現の長さは最大 20 ビットです。 これは、正しい構造であれば、パスに対する総当たりの列挙ではなく、ビットごとの構造のレベルで推論できることを直ちに示唆しています。 グラフ サイズの制限である 100 ノードも、長さ 20 までのすべてのバイナリ文字列の自然なトライ サイズと比較すると寛大です。これは、最悪の非圧縮ケースでは最大でも約 200 万ノードですが、共有すると大きく崩れます。 

素朴な解釈では、次のすべての数値に対してトライを構築しようとします。$[L, R]$。 これは概念的にはすでに機能していますが、積極的に圧縮しないとノードの制限を超える可能性があります。 もう 1 つの単純な間違いは、各数値を独立して扱い、素のチェーンを作成することです。 これは正確性を自明に満たしますが、ノード数が爆発的に増加します。$O(R-L)$、これは受け入れられません。 

微妙なエッジケースとして、先行ゼロがあります。 たとえば、数字の 1 は、「01」ではなく「1」と表現する必要があります。 すべての数値を同じ長さにパディングする不注意な構成では、誤って無効なパスが導入されてしまいます。 

もう 1 つの特殊なケースは、パスの一意性を確保することです。 2 つの異なる数値がプレフィックスを共有し、継続構造を注意深く処理しないとグラフが誤ってマージされる場合、同じバイナリ文字列を綴る複数の方法を誤って作成したり、範囲にない余分な文字列を導入したりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。次のとおりです。$[L, R]$、そのバイナリ表現を取得してトライに挿入します。 各ノードはプレフィックスに対応し、エッジは追加される 0 または 1 に対応します。すべての数値は独立して挿入され、可能な限りノードはマージされます。 

トライはプレフィックス共有を正確にエンコードするため、このアプローチは正しいです。 ルートからリーフへの各パスは 1 つのバイナリ文字列に対応するため、すべての数値を挿入すると、すべての数値が 1 回表現される構造が保証されます。 障害点はメモリです。範囲が広く、バイナリ文字列が長い場合、トライ ノードの数がそれに近づく可能性があります。$O((R-L+1)\log R)$, これは100をはるかに超えています。 

重要な観察は、個々の数値に対する完全な試行は必要ないということです。 連続した数値間隔内のすべてのバイナリ文字列を表す必要があるだけです。 この間隔構造により、バイナリ ドメインで間隔分解を使用して積極的に圧縮することができます。 

数値ごとのパスを構築する代わりに、数直線上にバイナリ トライを構築しますが、現在のバイナリ プレフィックスが混合区間に対応する場合にのみノードを展開します。 プレフィックスが完全に内側にある場合$[L, R]$、それはターミナル構造になります: すべての補完が有効です。 完全に外側にある場合は破棄されます。 そうでなければ、私たちは別れます。 

これにより、構築がバイナリ プレフィックスでの再帰的な間隔分割に縮小され、同一のサブ範囲の共有ノードを持つ DAG が自然に生成されます。 

重要な構造は、各ノードが固定バイナリ プレフィックスと一致する整数の範囲を表すことです。 プレフィックスから 0 または 1 を追加することは、バイナリの意味で範囲を左半分と右半分に分割することに対応します。 これはバイナリ表現空間上でセグメント ツリーをミラーリングしますが、同一の部分問題がマージされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 数値ごとのトライ |$O((R-L)\log R)$|$O((R-L)\log R)$| 遅すぎる |
 | 間隔圧縮された DAG |$O(\log R)$ノード |$O(\log R)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 問題を、数値が含まれるすべてのバイナリ文字列を正確に生成する構造を構築することに変換します。$[L, R]$、プレフィックスの曖昧さはありません。 これにより、焦点は個々の数値から有効な継続の範囲に移ります。 
2. 状態をペアとして表す関数を定義する$(node, prefix\_value, prefix\_length)$、指定されたバイナリ接頭辞で始まるすべての数値を意味します。 このような各プレフィックスは、そのプレフィックスを共有する整数の間隔に対応します。 
3. 任意のプレフィックス間隔について、その数値範囲を計算します。$[cur\_min, cur\_max]$。 この間隔が完全に外側にある場合$[L, R]$、それを破棄します。 完全に内側にある場合は、すべての補完が有効であるため、ターミナル ノードに直接接続します。 
4. 区間が部分的に重なっている場合$[L, R]$、ビット 0 とビット 1 でプレフィックスを拡張することで分割します。拡張ごとに、左にシフトしてビットを追加することに対応して、間隔が 2 つのサブ間隔に細分化されます。 
5. 同一のサブ問題がノードを再利用できるようにするために、各間隔の状態をメモ化します。 ここで圧縮が行われます。構造内の異なるパスが同じに到達する可能性があります。$(l, r)$-style サブインターバルを作成し、それらを 1 つのノードにマージします。 
6. 有効な開始パスとしてビット 0 を含む空のプレフィックスの展開を禁止することで、先行ゼロが表示されないようにします。 実際には、これはルートが「0」ではなく「1」にのみ拡張されることを意味します。 
7. 最後に、作成されたすべてのノードの隣接リストを出力し、ノード制限を超えていないことを確認します。 

### なぜ効果があるのか

 構造内のすべてのノードは一意のバイナリ プレフィックスに対応し、すべてのプレフィックスは連続する整数の間隔に対応します。 再帰により、ノードの間隔が完全に内側でも外側でもない場合にのみノードが分割されるようになります。$[L, R]$。 これにより、各数値が 1 つのプレフィックス パスに属し、メモ化によってプレフィックスが重複することがないため、すべての有効な数値が 1 回だけ生成されることが保証されます。 DAG プロパティは、エッジが短いプレフィックスから長いプレフィックスにのみ移行し、循環を防ぐため保持されます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(1000000)
input = sys.stdin.readline

L, R = map(int, input().split())

nodes = []
adj = {}
memo = {}

def new_node():
    idx = len(nodes)
    nodes.append(idx)
    adj[idx] = []
    return idx

def interval(prefix, length):
    if length == 0:
        return 0, (1 << 30) - 1
    shift = 30 - length
    base = prefix << shift
    end = base | ((1 << shift) - 1)
    return base, end

def intersect(a, b, c, d):
    return max(a, c) <= min(b, d)

def fully_inside(a, b, c, d):
    return c <= a and b <= d

def build(prefix, length):
    key = (prefix, length)
    if key in memo:
        return memo[key]

    node = new_node()

    a, b = interval(prefix, length)

    if not intersect(a, b, L, R):
        memo[key] = node
        return node

    if fully_inside(a, b, L, R):
        memo[key] = node
        return node

    left_child = build(prefix << 1, length + 1)
    right_child = build((prefix << 1) | 1, length + 1)

    adj[node].append((left_child, 0))
    adj[node].append((right_child, 1))

    memo[key] = node
    return node

root = build(1, 1)

print(len(nodes))
for i in range(len(nodes)):
    print(len(adj[i]), end=' ')
    for v, w in adj[i]:
        print(v + 1, w, end=' ')
    print()
```構築は最初の有効ビットを表すルートから始まり、先頭のゼロを避けるために 1 に固定されます。 各状態は、0 または 1 の追加を表す 2 つの子に展開されます。これは、プレフィックス間隔を 2 倍にして 2 つの半分に分割することに対応します。 

メモ化により、同じプレフィックス長とビット パターンが再検討された場合に、同じノードが再利用されることが保証されます。 これにより、グラフが制限内に保たれます。 

間隔チェックにより、不必要な拡張が防止されます。プレフィックスが完全に有効範囲内に収まると、その調整を停止し、爆発を回避します。

 ## 特殊なケース

 場合について$L = R = 1$、構造全体は、「1」というラベルが付いた単一の有効なパスに縮小される必要があります。 ルート間隔はすぐにターゲット範囲内に完全に収まるため、子は作成されません。 グラフは単一のノードで構成されており、端末圧縮が正しく機能していることが確認できます。 

のような範囲の場合$L = 1, R = 2$, バイナリ表現は「1」と「10」です。 ルート「1」は最小深さの区間 [1,1] に対応し、10 と 1 を分離するのに十分なだけ拡張されます。アルゴリズムは区間が混合する場所のみを分割し、不必要な拡大を防ぎます。 

のために$L = 4, R = 7$、接頭辞「1」は全範囲 [4,7] に正確に対応します。 十分なビットが固定されるまで、より深い表現では間隔が完全に [L,R] の内側に収まらないため、アルゴリズムは依然として拡張します。 これは、間隔表現が値のみではなく深さを考慮する必要がある理由を示しています。
