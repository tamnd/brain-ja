 ## 解決策
 ## 問題の理解

 まず、エッジの長さを表す正の整数のコレクションから始めます。$n$-次元の超長方形。 すべてのエッジの長さの合計とすべてのエッジの長さの積という 2 つの合計値が重要です。 タスクは、このコレクションを正の整数の別の複数セットに変換し、その合計が正確に一致するようにすることです。$S$そしてその製品は正確に$M$。 

2 つの操作が許可されます。 既存のディメンションを削除してその値を完全に削除することも、任意の正の整数の長さを持つ新しいディメンションを導入することもできます。 各操作には 1 ステップのコストがかかります。 このような編集の総数を最小限に抑えたいと考えています。 

構造的な観点から、初期の数値のサブセットを破棄し、新しく構築された数値に置き換えることができます。 固定されたままの点は、保持された要素は合計と積の両方に変化せずに寄与しますが、追加された要素は残りの合計と積の要件を集合的に「説明」する必要があるということです。 

制約が大きいのは、$n$しかし、値のサイズは中程度です。 重要な意味は、初期配列のサブセットを明示的に探索できないことです。 二次関数の動作さえも試みるソリューション$n$失敗します。 重要なのは、次の数値構造です。$M$は非常に制限が厳しいため、因数分解すると、可能な最終構成の空間は実際には小さくなります。 

いくつかのエッジな状況には注意が必要です。 

すでに初期数を超える製品がある場合$M$、積は正の整数でのみ増加するため、1 より大きい要素が保持されると、直ちにターゲットに到達できなくなります。 たとえば、配列に次のものが含まれている場合、$[2,3]$そして$M=2$、合計の調整は可能に見えても、両方を維持することは不可能です。 

もし$M=1$の場合、最終構成のすべての次元は 1 でなければならないため、唯一の問題は、合計に達するように 1 の数を調整できるかどうかになります。$S$。 最初に 1 以外を指定すると、強制的に削除されます。 

もう 1 つの微妙なケースは、和制約と積制約が個別には実現可能だが、一緒には互換性がない場合に発生します。$M=6, S=5$。 因数分解$6 = 2 \cdot 3$は存在しますが、合計制約により、達成不可能な別のグループ化が強制される可能性があります。 

## アプローチ

 直接的なアプローチでは、初期要素のどのサブセットを保持するかを決定し、両方の制約を満たす追加の要素を構築しようとします。 問題は、サブセットの選択が指数関数的に行われることです。$n$また、値が次の値に達するため、値を動的にプログラミングすることさえ不可能です。$10^{10}$。 

重要な観察は、ターゲットの構造はほぼ完全に次の要素によって決定されるということです。$M$。 一度$M$が固定されている場合、有効な最終マルチセットは次の因数分解に対応します。$M$正の整数に変換します。 各要素は最終的な 1 つの次元です。 したがって、本当の自由は、素因数をどのようにグループ化するかにあります。$M$バケツに。 

これにより問題が大幅に軽減されます。 番号$M \le 10^{10}$は、多重度を数える素因数が最大でも約 10 ～ 12 個であるため、可能な因数分解の数は、素数割り当てを遡って列挙できるほど十分に小さいです。 

候補マルチセットを生成したら$B$製品が$M$、その合計が等しいかどうかを確認するだけで済みます。$S$。 有効なものの中で$B$、操作を最小限に抑えたいと考えています。 初期配列は削除以外に変更できないため、最良の戦略は最終構成を選択することです。$B$これにより、すべての共有要素が 1 つの削除と 1 つの追加を節約できるため、最初のマルチセットとの重複が最大化されます。 

したがって、問題は次のようになります。有効な因数分解をすべて列挙します。$M$、正しい合計を持つものをフィルターし、それぞれについて、 の要素数を計算します。$B$初期配列にすでに存在します。 最適な構成が答えを与えます。

 ## アルゴリズムのチュートリアル

 1.因数分解$M$主要な分解に進みます。 もし$M=1$、空の素数セットとして扱います。 

このステップでは、乗法構造を素数の小さなマルチセットに圧縮します。 
2. これらの素因数をグループに分割するすべての方法を生成します。 

各グループは 1 つの最終次元に対応し、その値はそのグループ内の素数の積になります。 

これはバックトラッキングによって行われ、各素数を複数のバケットの 1 つに割り当てます。 
3. すべてのパーティションについて、結果として得られるマルチセットを計算します。$B$価値観の。 

各バケットは、割り当てられた素数の積に等しい 1 つの整数を生成します。 
4. 要素の合計を計算します。$B$。 等しくない場合$S$、このパーティションを破棄します。 

合計制約は、有効な乗算構造に対するフィルターとして機能します。 
5. 要素の数を数えます$B$初期配列に表示されます。 

両方のマルチセットに重複が含まれる可能性があるため、これは周波数マップを使用して行われます。 
6. これにかかるコストを計算します$B$として：$$\text{operations} = n + |B| - 2 \cdot |A \cap B|$$ここで交差点は多重度で取られます。 
7. すべての有効なパーティションの最小コストを返します。 合計に一致するパーティションがない場合は、-1 を出力します。 

### なぜ効果があるのか

 有効な最終構成は、次の方法によって完全に決定されます。$M$の素因数がグループ化されます。 積が次のような整数を構築する他の方法はありません。$M$。 これにより、探索空間が完全になります。考えられるすべての解は、素数の 1 つの分割として表示されます。 

固定パーティションの場合、合計は決定的であり、最初の配列との重複はそのパーティションにどのように到達したかに依存しません。 各操作では要素の削除または挿入のみが行われるため、コスト式は、最初のマルチセットと選択した最終マルチセットの間で異なる要素の数を正確に測定します。 編集を最小限に抑えると、有効な因数分解制約の下で共有要素を最大化することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def factorize(x):
    primes = []
    d = 2
    while d * d <= x:
        while x % d == 0:
            primes.append(d)
            x //= d
        d += 1
    if x > 1:
        primes.append(x)
    return primes

def solve():
    n, S, M = map(int, input().split())
    a = list(map(int, input().split()))
    cntA = Counter(a)

    if M == 1:
        # all ones
        # final product 1 => all elements must be 1
        # sum is number of elements
        k = S
        cnt1 = cntA[1]
        # keep as many ones as possible
        keep = min(cnt1, k)
        if k < 0:
            print(-1)
        else:
            print(n + k - 2 * keep)
        return

    primes = factorize(M)
    m = len(primes)

    best = None

    # backtracking: assign each prime to a bucket
    buckets = []

    def dfs(i):
        nonlocal best
        if i == m:
            prod = []
            for b in buckets:
                val = 1
                for p in b:
                    val *= p
                prod.append(val)
            if sum(prod) != S:
                return
            cntB = Counter(prod)
            inter = sum(min(cntA[x], cntB[x]) for x in cntB)
            k = len(prod)
            score = n + k - 2 * inter
            if best is None or score < best:
                best = score
            return

        p = primes[i]
        used_vals = set()
        for j in range(len(buckets)):
            buckets[j].append(p)
            dfs(i + 1)
            buckets[j].pop()

        buckets.append([p])
        dfs(i + 1)
        buckets.pop()

    dfs(0)

    print(best if best is not None else -1)

if __name__ == "__main__":
    solve()
```解決策は、乗法制約を素数のリストに減らすことから始まります。 バックトラッキング ルーチンは、これらの素数を動的に作成されたバケットに分散します。各バケットは 1 つの最終次元を表します。 完全な割り当てごとに候補マルチセットが生成され、それが必要な合計に対して検証されます。 

頻度比較ステップでは、ハッシュ マップを使用して交差サイズを効率的に計算します。 コスト式は変換を直接反映しています。初期セットと最終セットの両方の要素は保持されますが、その他の要素は削除または挿入が必要です。 

微妙な点は、バケットがすべてのセット パーティションに対して反復されるのではなく、段階的に構築されることです。 これにより、冗長な構築が回避され、各素数が正確に 1 回割り当てられるようになり、正確さが保証されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$M = 1$。 このアルゴリズムにより、すべての値を 1 に調整するという問題が軽減されます。積の制約により、すべての最終要素が 1 になるように強制されるため、有効な構成は 1 の複数セットのみであり、最良の戦略は、単純に既存のものを再利用し、一致するようにカウントを調整することです。$S$。 計算は周波数の比較に完全に縮小されます。 

もう一つのケースは次のような場合です。$M$プライムです。 したがって、すべての有効な最終構成には、以下に等しい要素が 1 つだけ含まれている必要があります。$M$。 アルゴリズムのパーティション生成により、この単一バケット構成が自然に生成され、他のすべての割り当てはサム チェックによって削除されます。 

3 番目のケースには、素数の繰り返しが含まれます。$M$、グループが異なると同じ値が生成されますが、合計は異なります。 バックトラッキングではすべての割り当てが正しく調査され、各素数が独立してバケットに割り当てられるため、有効なグループ化が失われないことが保証されます。
