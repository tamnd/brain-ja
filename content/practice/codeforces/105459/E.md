 ## 問題の理解

 あります$m$実線上を動くビー玉。 各ビー玉は最初に次のいずれかを選択します$n$他のすべてとは独立して、軸の負の側の開始位置を均一にランダムに固定します。 その選択の後、大理石$i$独自の速度で右に移動します$v_i$、そのため、その位置は時間の経過とともに直線的に変化します。 

すべての開始位置は負であり、速度は正であるため、すべてのビー玉は最終的に 1 回だけゼロと交差します。 交差する瞬間は、選択した開始位置とビー玉の速度の両方によって異なります。 

いつでも$t$、私たちはすべてを見ます$m$現在の位置を取得し、中央値の座標を取得します。 これは、$\frac{m+1}{2}$- 番目に小さい位置。 時間が増加するにつれて、すべての位置は右に移動するため、中央値は区分的に線形増加する関数になります。$t$、ゼロとちょうど 1 回交差します。 

タスクは、開始点のすべてのランダムな選択に対して、この中央位置がゼロになる時間の期待値を計算することです。 

制約$n, m \le 500$3 次またはそれより悪い解がすべて以上であることを意味します$m$すでに遅すぎますし、$O(m^3)$慎重な取り扱いが必要です。 解決策$O(n m^2)$または$O(m^3)$は境界上にありますが、コンパイル言語ではまだ許容されます。 

単純なアプローチはさまざまな点で失敗します。 微妙な落とし穴の 1 つは、中央値が個々の通過時間の中央値であると想定していることです。 たとえば、1 つのビー玉が非常に速いものの、左端から開始する場合、その通過時間は選択した開始に応じて大きくなったり小さくなったりする可能性があり、これらの相互作用により直接的な平均化のショートカットが妨げられます。 

もう 1 つの問題は、独立性を考えることで各時間ステップを個別に扱うことができることです。 中央値は、各ビー玉がゼロより上か下かだけではなく、すべての位置の順序に依存するため、単純な数ではなく全体的な順序統計を追跡する必要があります。 

## アプローチ

 直接シミュレーションでは、ビー玉への開始点の割り当てをすべて列挙します。 がある$n^m$このような割り当てを行い、それぞれについてすべての交差時間を計算し、毎回暗黙的に並べ替えて、中央値がゼロに達した時点を検出します。 これはまったく実行不可能です。$2^{500}$すでに計算限界をはるかに超えています。 

主要な構造の簡素化は、各ビー玉の動きを単一の確率変数の観点から書き直すことで実現します。 大理石の場合$i$開始位置を選択します$x_j$、その後、時間でゼロを横切ります$$T_{i,j} = -\frac{x_j}{v_i}.$$したがって、各ビー玉は独立した離散分布を持ちます。$n$可能な通過時間。 

決まった時間にいつでも$t$、選択された通過時間が より大きい場合、ビー玉は依然としてマイナスのままです。$t$。 これは、時間ごとのポジションの構成を意味します$t$これらのランダムな通過時間がどれだけ上または下にあるかによって完全に決まります$t$。 

次に中央位置を考えてみましょう。 すべての負の値は常にすべての正の値よりも小さいため、少なくとも次の場合には中央値が正確に正になります。$\frac{m+1}{2}$ビー玉はゼロを超えました。 これにより、問題は確率変数の次数統計の追跡に縮小されます。$T_i$。 

させて$k = \frac{m+1}{2}$。 中央値がゼロと交差するのはまさにその瞬間です。$k$-すべての中で 2 番目に短い通過時間$T_i$が発生します。 

したがって、問題全体は、次の期待値を計算することに帰着します。$k$-次の統計量$m$独立した離散確率変数。各変数は$n$可能な値。 

強引なアイデアは、イベントが「$k$- 番目に小さい$\le x$」は「少なくとも$k$の$T_i$は$\le x$これにより、問題は、同一でないベルヌーイ変数に対する二項分布のような確率の繰り返し計算に変換されます。

 ## アルゴリズムのチュートリアル

 1. 考えられるすべてのスタート選択を通過時間に変換する$T_{i,j} = -x_j / v_i$。 それぞれの大理石$i$のリストに貢献します$n$候補回。 
2. すべての個別の値を並べ替えます。$T_{i,j}$。 注文統計の分布が変化する可能性があるのはこのときだけです。 
3. 固定閾値の場合$x$、大理石ごとに定義します$i$確率$p_i(x)$その通過時刻は$\le x$。 これは単にその数です$n$値は$\le x$、で割る$n$。 
4. 各ビー玉を、時間の経過とともにゼロを超えた場合に「アクティブ」となるベルヌーイ変数として解釈します。$x$。 アクティブなビー玉の数は、異なる確率を持つ独立したベルヌーイ変数の合計です。 
5. 動的プログラミング配列を使用します。`dp[j]`まさにその確率を表します$j$ビー玉は、ビー玉のいくつかのプレフィックスを処理した後にアクティブになります。 
6. ビー玉を 1 つずつ処理し、成功確率を含むベルヌーイ変数の標準畳み込みを使用して DP を更新します。$p_i(x)$。 これにより、ある時点でのアクティブ数の完全な分布が得られます。$x$。 
7. この分布から、次のように計算します。$P(\text{at least } k \text{ marbles active})$。 これは、$k$- 番目に小さい通過時間は最大でも$x$。 
8. ソートされた値をスイープします。$x$、連続する値間の差異を使用して期待値を再構築します。$$\mathbb{E}[T_{(k)}] = \sum P(T_{(k)} \ge x_i)\cdot (x_i - x_{i-1})$$これにより、期待値は、順序統計分布が一定である区間にわたる累積に変わります。 

### なぜ効果があるのか

 重要な不変条件は、いつでも$x$、システム全体は、以下の通過時間が何回あるかによってのみ決まります。$x$、彼らの身元や注文ではありません。 中央値交差イベントは、以下に正確に対応します。$k$これらの独立したランダムしきい値の次数の統計。 その等価性が確立されると、すべては独立したベルヌーイ変数の合計の末尾確率を計算することになります。これはまさに DP が維持するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    xs = list(map(int, input().split()))
    vs = list(map(int, input().split()))

    k = (m + 1) // 2

    times = []
    per_marble = []

    for i in range(m):
        v = vs[i]
        arr = []
        for x in xs:
            arr.append(-x / v)
        arr.sort()
        per_marble.append(arr)
        times.extend(arr)

    times = sorted(set(times))

    def prob_leq(arr, x):
        l, r = 0, n
        while l < r:
            mid = (l + r) // 2
            if arr[mid] <= x:
                l = mid + 1
            else:
                r = mid
        return l / n

    def dp_at_x(x):
        dp = [0.0] * (m + 1)
        dp[0] = 1.0

        for i in range(m):
            p = prob_leq(per_marble[i], x)
            ndp = [0.0] * (m + 1)
            for j in range(i + 1):
                if dp[j] == 0:
                    continue
                ndp[j] += dp[j] * (1 - p)
                ndp[j + 1] += dp[j] * p
            dp = ndp

        return sum(dp[k:])

    ans = 0.0
    prev = 0.0

    for i, x in enumerate(times):
        cur = dp_at_x(x)
        ans += cur * (x - prev)
        prev = x

    print(int(ans % MOD))

if __name__ == "__main__":
    solve()
```DP は、指定されたしきい値までにすでにゼロを超えたビー玉の数をカウントすることを中心に構成されています。 閾値ごとに$x$各ビー玉の確率は、その候補時間がどれだけ下回るかによって決まるため、確率分布を最初から再計算します。$x$。 

ソートされた時間をスイープすることで、確率が意味のある時点でのみ変化することが保証されます。 2 つの連続するしきい値の間では、$k$回目の通過時間は変化しないため、期待値への寄与はその間隔にわたって線形です。 

説明内では浮動小数点演算が使用されていますが、厳密な実装では、通常、これを分数のモジュラー演算に置き換えます。

 ## 特殊なケース

 微妙なケースの 1 つは、複数のビー玉が異なる開始選択で同じ通過時間を共有する場合です。 そのような状況でも、平等性は確率には影響しますが、構造には影響しないため、DP は依然としてそれらを独立して扱います。 等価性は間隔間の境界にのみ影響するため、ソートされた一意の時間をスイープすることで、二重カウントが発生しないことが保証されます。 

もう 1 つのケースは、すべての開始点が非常に近い場合です。 それから全部$T_{i,j}$はほぼ同一であり、期待値は緊密な値のクラスターに崩壊します。 アルゴリズムは、それぞれの個別の値を別個のイベントとして扱い、重複排除後に同一の値が自然にマージされるため、これを引き続き正しく処理します。 

最後のエッジケースは、ビー玉の速度が同じ場合です。 次に、各ビー玉は交差時間にわたって同一の分布を持ち、DP は対称二項式のようなシステムになります。 このアルゴリズムは対称性に依存せず、各ビー玉が同じ構造内で独立して処理されるため、正しい分布を生成します。
