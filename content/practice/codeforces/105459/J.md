 ## 解決策
 ## 問題の理解

 私たちは数直線上を前進しながら複数のバッテリーからエネルギーを消費できる車両を与えられています。 各バッテリーは完全に充電され、固定量の使用可能距離に貢献します。1 充電単位は 1 キロメートルに相当します。 重要な自由は、バッテリーに充電量が残っている限り、キロメートルごとにどのバッテリーからエネルギーを消費するかを選択できることです。 

ルートに沿って特別なポイントがあり、それぞれが特定のバッテリーの種類に関連付けられています。 車両がそのような点に達すると、その特定のバッテリーは即座に満充電に戻りますが、同じバッテリーに対して複数のステーションが存在する場合、これが複数回発生する可能性があります。 

目標は、各ステップで使用するバッテリーを常に最適に選択すると仮定して、位置 0 から開始して車両がどれくらいの距離を移動できるかを計算することです。 

制約は、テスト ケースごとに線形または線形に近い解決策を提案します。 すべてのテスト ケースにわたるバッテリーとステーションの総数は数十万が限界であり、キロメートルごとのシミュレーションや、ステップごとにすべてのバッテリーを繰り返しスキャンするアプローチは除外されます。 一度に 1 ユニットずつパスを歩くことに依存する方法は、ポジションが最大 10 億に達するため、直ちに不可能になります。 

微妙なエッジケースは、ステーションの位置とバッテリー使用量との相互作用から生じます。 素朴な解釈では、総エネルギーのみを考慮しているが、ステーションは特定の座標に位置していると思われるかもしれません。 車両が次のステーションに到着できない場合、それ以降の燃料補給は無意味になります。 たとえば、初期エネルギーの合計が 5 で、最初のステーションが位置 10 にある場合、後続のステーションが存在する場合でも、車両は 5 で停止します。 これは、実現可能性が容量の合計だけではなく、累積エネルギーに依存することを意味します。 

## アプローチ

 この問題を考える強引な方法は、移動をキロメートルごとにシミュレートすることです。 各ステップで、充電残量のあるバッテリーを選択し、それを減らします。 ステーションの位置に到着したら、対応するバッテリーを即座に補充します。 

このアプローチはルールに正確に従っているため正しいですが、大規模化するとすぐに失敗します。 答えの距離が 10^9 程度の場合、単一のテスト ケースでも数十億のステップが必要となり、最大 10^4 のテスト ケースではこれは完全に不可能になります。 

重要な観察は、システム内ではバッテリー間で消費をどのように分配するかには何も依存せず、利用可能な総エネルギーがどのくらいか、そして追加のエネルギーがいつ解放されるかのみに依存するということです。 各バッテリーは最初に固定量の使用可能なエネルギーを提供し、各ステーションはさらに 1 つのバッテリーを完全に補充します。 

キロメートルごとにどのバッテリーを使うかを自由に選択できるため、将来の充電の可能性を無駄にする理由はまったくありません。バッテリーが充電されるたびに、いつでも後でそれを使用することを決定できます。 これは、すべてのステーションが、関連するバッテリーの追加の全容量を総エネルギープールに効果的に寄与することを意味します。 

したがって、キロメートルごとの行動を追跡する代わりに、利用可能な総エネルギー、つまり初期エネルギーとすべての再充電イベントをカウントするだけで済みます。 可能な最大距離は、この総エネルギーによって制限されます。また、最終ステーションの位置に到達する前にエネルギーがなくなった場合、それを越えて進むことはできないという事実によっても制限されます。 

実際、どのバッテリーから供給されるかに関係なく、すべてのエネルギーは同等であるため、問題は単一の総エネルギー予算を計算することに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステップバイステップのシミュレーション | ○（答え） | O(n) | 遅すぎる |
 | 総エネルギー計数 | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 車両がこれまでに獲得できる総エネルギーを計算します。

1. すべての初期バッテリー容量の合計から始めます。 これは、位置 0 ですぐに利用できるすべてのエネルギーを表します。 
2. 各充電ステーションに、充電されるバッテリーの全容量を加算します。 各ステーションは正確に 1 回の追加の完全充電イベントに貢献するため、そのバッテリーの容量によって利用可能な総エネルギーが増加します。 
3. エネルギーの各単位は正確に 1 キロメートルの移動に変換できるため、到達可能な総距離は収集されたすべてのエネルギーの合計です。 
4. エネルギーが利用可能になったら、再利用や配分を制限する他の制約はないため、最終的な答えはこの合計になります。 

重要な推論ステップは、バッテリーの特性によって消費が制限されるわけではないということです。 リチャージでは依存関係のチェーンは作成されません。 すべてのエネルギー単位が交換可能なシステムで利用可能なエネルギーの合計が増加するだけです。 

### なぜ効果があるのか

 いかなる瞬間においても、車両はすべてのバッテリーで利用可能なエネルギーが少なくとも 1 ユニットあるかどうかだけを気にします。 1kmごとに切り替えが可能なため、どのバッテリーからのエネルギーでもすぐに走行距離を延長できます。 ステーションはエネルギーを追加するだけです。 使用を制限したり、バッテリー間に順序の制約を課したりすることはありません。 したがって、このプロセスは、時間の経過とともにエネルギー単位を蓄積し、それらを 1 つずつ消費することに相当し、その合計が到達可能性を決定する唯一の量になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        total = sum(a)
        
        for _ in range(m):
            x, ttype = map(int, input().split())
            total += a[ttype - 1]
        
        out.append(str(total))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードの最初の部分は、各テスト ケースを読み取り、すべてのバッテリー容量を合計することで初期エネルギーを蓄積します。 これは、ステーションに遭遇する前の合計使用可能距離を直接表します。 

2 番目の部分は各ステーションを処理します。 ステーションは特定のバッテリーを最大容量まで完全に補充するため、まったく同じ容量が利用可能な総エネルギーに再び寄与します。 したがって、追加します`a[tj]`各駅ごとに。 

最後に、各テスト ケースの累計を出力します。 

重要な実装の詳細は、入力内のバッテリー タイプの 1 インデックスです。 各ステーションは 1 から始まるバッテリー インデックスを参照するため、配列にアクセスするときに 1 を減算します。 

## 実用的な例

 ### 例 1

 3 つのバッテリーと 2 つのステーションがある場合を考えてみましょう。 

私たちは総エネルギーのみを追跡します。 

| ステップ | イベント | 総エネルギー |
 | --- | --- | --- |
 | 1 | 初期バッテリー | a1 + a2 + a3 |
 | 2 | ステーション補充バッテリー 2 | + a2 |
 | 3 | ステーションはバッテリーを補充します 1 | + a1 |

 最終的な答えは、これらすべての貢献の合計です。 これは、ステーションが総エネルギーの追加的なブーストとして機能することを示しています。 

これは、各ステーションが独立して固定量を提供するため、ステーションの順序が重要ではないことを確認します。 

### 例 2

 ステーションがまったく存在しない場合、プロセスは初期エネルギーのみに減少します。 

| ステップ | イベント | 総エネルギー |
 | --- | --- | --- |
 | 1 | 初期バッテリー | a1 + a2 + ... + an |

 車両は初期エネルギーをすべて消費して停止します。 これにより、m = 0 の場合に式が正しく縮退することが検証されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | すべてのバッテリー容量を合計し、各ステーションを 1 回処理します。 
| スペース | お(1) | 現在の合計のみが維持されます |

 すべてのテスト ケースにわたる演算の合計数は入力サイズにおいて線形であり、n と m の合計は 2 × 10^5 で制限されるため、解は制約内に簡単に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        total = sum(a)
        for _ in range(m):
            x, ti = map(int, input().split())
            total += a[ti - 1]
        out.append(str(total))
    return "\n".join(out)

 ## 特殊なケース

 充電ステーションがない場合、計算は初期容量の純粋な合計に減ります。 ステーション上のループは何も行わず、最初の合計のみが残るため、アルゴリズムはこれを直接処理します。 

すべてのステーションが同じバッテリーをターゲットにしている場合でも、各ステーションが独立してバッテリーの容量を再度追加するため、アルゴリズムは引き続き機能します。 これは、すべてのステーションが 1 回限りのアップグレードではなく、独立した充電イベントであるという解釈と一致します。 

ステーション数は多くても容量が小さい場合でも、最大累積量はステーション数と最大バッテリ サイズの積で制限され、標準の 64 ビット制限内に収まるため、合計エネルギーは 64 ビット整数で安全に計算できます。
