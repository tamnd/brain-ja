 ## 問題の理解

 単一の整数が与えられます$n$、概念的に関数を評価します$f(n, i)$すべての整数に対して$i$1から$n$。 それぞれの値$f(n, i)$整数を下方向にスキャンするプロシージャによって定義されます。$i$を 2 にして、割り切れるかどうかをチェックします。$n$。 約数が見つかるとすぐに、$n$その範囲では、その除数から導出された削減された値を返します。 何も見つからない場合は戻ります$n$自体。 

したがって、それぞれについて$i$、私たちは事実上、次のことを尋ねています：$n$それはせいぜい$i$、一番大きいものは何ですか？ そのような約数が存在する場合、関数は次を出力します。$n$その約数で割ります。 範囲内に 1 より大きい除数が存在しない場合、出力はそのままになります。$n$。 最終的な答えは、すべての値の合計です。$i$1から$n$。 

制約により、最大で$10^3$テストケースと$n$まで$10^9$。 これにより、ペアごとに関数を独立して評価しようとするアプローチが除外されます。$(n, i)$、そうなるので$O(n)$テストケースごとに、すぐに遅すぎます。 平$O(\sqrt{n} \cdot n)$実現可能性をはるかに超えています。 

単純な実装には、微妙な問題も隠されています。関数は、最大除数を超えない値に依存します。$i$_ 単に約数が存在するかどうかだけではありません。 たとえば、次の場合$n = 12$そして$i = 6$の場合、正しい動作は、6 までの最大の約数が 2、3、4、または 6 のどれであるかによって決まります。「最大」の条件が欠けていると、実装が最適化されている場合でも、不正確な結果が生じます。 

## アプローチ

 直接シミュレーションはすべての要素を反復します。$i$1から$n$、それぞれについて$i$、から下方向にスキャンします。$i$約数が見つかるまで$n$。 最悪の場合、そのときは、$n$は素数であり、すべてのスキャンは失敗する前に 2 に達します。おおよその結果は次のとおりです。$O(n)$テストケースごとに作業します。 いつ$n$高度に複合的であるため、スキャンは依然として多くの整数を繰り返し処理するため、実際には総コストがさらに悪化します。 

重要な観察は、関数がその値を変更するのは次の場合のみであるということです。$i$の約数と交差します$n$。 2 つの連続する約数の間$n$、の最大の約数$n$を超えない$i$は一定のままであるため、その間隔内では出力は変化しません。 これは、すべてを評価する必要がないことを意味します$i$、答えが変わる位置のみ、つまり の約数に相当します。$n$。 

すべての約数がわかって並べ替えられると、連続する約数の各ペアによって範囲が定義されます。$i$答えが一定である値。 これらの範囲を合計すると、問題は除数リスト上の線形パスに変わります。

 ## アルゴリズムのチュートリアル

 1. すべての約数を計算します。$n$、1とを含む$n$を選択し、昇順に並べ替えます。 これにより、関数の動作が変更される可能性がある場所の完全な構造が得られます。 除数リストは範囲の分割として機能します。$[1, n]$。 
2. これらの約数を使用して範囲を暗黙的に繰り返します。 1 より大きい最初の除数の前では、関数は常に次の値を返します。$n$有効な約数がまだ見つかっていないためです。 
3. 各約数について$d_k$の範囲を決定します。$i$値の場所$d_k$はの最大の約数です$n$を超えない$i$。 この範囲は次からです$d_k$に$d_{k+1} - 1$、または$n$もし$d_k$は最後の約数です。 
4. このようなセグメントごとに、寄与度を追加します。$(\text{segment length}) \times (n / d_k)$答えに。 値$n / d_k$セグメント全体で一定のままであるため、$d_k$使用可能な最大除数は残ります。 
5.ハンドル$i = 1$貢献するため、当然最初のセグメントの一部として$n$。 
6. 累計を出力します。 

### なぜ効果があるのか

 固定の場合$i$、関数は戻ります$n$の最大の約数で割った値$n$を超えないもの$i$。 その最大の約数は次の場合にのみ変更されます。$i$の新しい約数に達する$n$。 2 つの連続する約数の間では、適格な約数のセットは同一であるため、最大値も関数値も変わりません。 これにより、関数は除数で定義された区間にわたって区分的に定数になり、アルゴリズムは各定数セグメントを 1 回だけ計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    if n == 1:
        print(1)
        return

    divisors = []
    i = 1
    while i * i <= n:
        if n % i == 0:
            divisors.append(i)
            if i != n // i:
                divisors.append(n // i)
        i += 1

    divisors = sorted(divisors)

    # We will iterate over segments
    ans = 0

    # ensure 1 is included naturally; divisors[0] is 1
    for idx, d in enumerate(divisors):
        left = d
        right = divisors[idx + 1] - 1 if idx + 1 < len(divisors) else n
        
        if right < left:
            continue
        
        length = right - left + 1
        ans += length * (n // d)

    print(ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```実装は、次のすべての約数を抽出することから始まります。$n$で$O(\sqrt{n})$。 連続する約数のペアによって、関数の値が定数となる正確な範囲が定義されるため、並べ替えが必要になります。 

メイン ループは、各約数をブレークポイントとして扱います。 各約数について$d$、それは次のように仮定します$d$すべての現在の最良の約数です$i$そのセグメントで。 寄与度は、それぞれを反復するのではなく、算術を使用して一括で計算されます。$i$これは、ブルートフォースよりも重要な最適化です。 

最後の除数を扱うときは注意が必要です。$n$自体。 その場合、関数の値は次のようになります。$n/n = 1$、セグメントは範囲の終わりまで延長されます。

 ## 特殊なケース

 いつ$n = 1$、除数セットには 1 だけが含まれ、すべての$f(1, i)$は 1 です。アルゴリズムはこれを明示的に処理し、すぐに 1 を返します。 

いつ$n$が素数の場合、約数リストは$[1, n]$。 これにより、正確に 2 つのセグメントが生成されます。答えは次のような長いセグメントです。$n$、その後に 1 になる単一の位置が続きます。セグメンテーション ロジックは、特別な処理を行わずにこれを自然に取得します。 

いつ$n$は完全な正方形です。次のようなものです。$36$、除数の抽出により平方根の重複が回避され、並べ替えられたリストによって範囲が正しく分割されます。 各約数が順番に 1 回だけ出現し、正しいセグメント長が保証されるため、間隔の構築は有効なままです。
