 ## 解決策
 ## 問題の理解

 当社には、一連の個別プラットフォームを備えた製品ラインがあります。 各プラットフォームの長さは固定されています`l`隣のものと一定の距離だけ離れている`m - l`、だからプラットフォーム`k`からのセグメントを占めます`(k-1)*m`に`(k-1)*m + l`。 バッタのボブはこの位置からスタートします`0`そして正確に のステップで前方にジャンプします`d`単位。 彼がプラットフォームに着地した場合、彼は生き残り、再びジャンプすることができます。 すべてのプラットフォームの外に着地すると、落下します。 端に正確に着地すれば安全とみなされます。 課題は、ボブが最初に落ちる位置を見つけることです。 

入力された整数`n, d, m, l`すべて 10^6 まで可能です。 つまり、ポジションを個別に反復するアプローチでは、最悪の場合、最大 100 万回のジャンプが必要になる可能性があります。これは注意すれば実現可能ですが、ラインのすべてのユニットをブルートフォースでスキャンすると遅すぎます。 エッジケースには、ジャンプの長さが異なる状況が含まれます。`d`2 つのプラットフォーム間の距離よりも大きい、または`d`エッジと正確に位置合わせされている、および次の場合`l = 1`そして`m`大きいです。 これらのシナリオでは、単純なチェックを 1 単位ずつ簡単に実行できるため、閉じた間隔での正確な演算が必要です。 

たとえば、次の場合`n = 1, d = 5, m = 10, l = 3`、ボブはにジャンプします`5`最初のジャンプで。 唯一のプラットフォームは、`[0,3]`。 それでも`5 < 10`、彼はホームの外にいるので、答えは次のとおりです。`5`。 不用意に実装すると、内部でのジャンプが誤って想定される可能性があります。`m`ユニットは安全です。`10`、次の (存在しない) プラットフォームの開始、間違った結果。 

## アプローチ

 最も単純なアプローチは、総当たりシミュレーションです。 位置 0 から開始し、増分します`d`ジャンプするたびに、新しい位置ごとにプラットフォーム セグメント内にあるかどうかを確認します。 これはボブの行動を直接モデル化しているため、これは正しいです。 問題は効率です。`n = 10^6`そして`d = 1`、これは最大 100 万回のジャンプを実行する可能性があり、ジャンプごとにプラットフォームのリニア スキャンはコストがかかりすぎます。 さらに悪いことに、毎回すべてのプラットフォームをチェックすると、最悪の場合 O(n^2) となり、タイムアウトになってしまいます。 

重要な観察点は、プラットフォームが等間隔に配置され、長さが同じであることです。 プラットフォーム`k`は`[ (k-1)*m , (k-1)*m + l ]`。 与えられた位置について計算することができます`x`、整数除算によって、どのプラットフォーム上にある (またはその間にある) か: 候補プラットフォームのインデックスは次のとおりです。`x // m + 1`。 次に、次のことを確認するだけです。`x`未満です`(candidate - 1)*m + l`ボブがまだプラットフォーム上にいるかどうかを確認します。 もしそうなら、彼は生き残る。 そうでなければ、彼は倒れます。 これにより、問題はジャンプごとの単純な算術チェックに軽減され、すべてのプラットフォームのスキャンが回避されます。 

ボブのジャンプ距離が固定されていることを認識することで、さらに最適化できます。 彼が落ちる最初のジャンプは次のように表現できます。`x = d * k`ある整数に対して`k`。 最小のものが必要です`k`そのような`x`プラットフォームの右端よりも大きいです。 これにより、転倒するまでのジャンプごとに O(1) の純粋な算術解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適化された演算 | O(n/d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボブの位置を初期化する`x`に`0`。 増分していきます`d`ジャンプするたびに。 
2. 各ジャンプで、ボブが着地するプラットフォームのインデックスを計算します。 プラットフォームは`[ (k-1)*m , (k-1)*m + l ]`、候補プラットフォームは`k = x // m + 1`。 
3. かどうかを確認します。`k`を超える`n`。 「はい」の場合、ボブは最後のプラットフォームを飛び越えて落下しました。`x`。 
4. それ以外の場合は、`x`プラットフォーム内にあります:`x <= (k-1)*m + l`。 「はい」の場合、ボブは生き残り、再びジャンプします。 
5. もし`x > (k-1)*m + l`, ボブはホームの外に着地して転落します。 これは最初の危険な位置なので、これを印刷します。 
6. インクリメント`x`による`d`そして繰り返します。 

なぜ機能するのか: アルゴリズムは次の不変条件を維持します。`x`は常に、ある程度の回数ジャンプした後のボブの実際の位置です。 候補プラットフォームを代数的に計算することにより、無関係なプラットフォームをスキャンすることはありません。 小切手`x <= (k-1)*m + l`ボブがプラットフォーム内に着地したか、転落したかを正確にキャプチャします。 以来`d`が一定である場合、各ステップは潜在的な落下点を見逃すことなく次のジャンプに進みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, d, m, l = map(int, input().split())

x = 0
while True:
    k = x // m + 1
    if k > n or x > (k - 1) * m + l:
        print(x)
        break
    x += d
```コードは次で始まります`x = 0`そして反復します`d`。 コンピューティング`k = x // m + 1`1 から始まるプラットフォーム インデックスを直接与えます。 もし`k > n`, ボブはすべてのプラットフォームを飛び越えました。 もし`x > (k-1)*m + l`、彼は現在のプラットフォームを超えました。 さもないと、`x`は安全であり、ループは継続します。 This implementation handles edges correctly because we use`<=`プラットフォームに含めるために。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        n, d, m, l = map(int, input().split())
        x = 0
        while True:
            k = x // m + 1
            if k > n or x > (k - 1) * m + l:
                print(x)
                break
            x += d
    return out.getvalue().strip()

# Provided sample

# Minimum-size inputs

# All equal

# d > m
