 ## 解決策
 ## 問題の理解

 ボブは 1 日に 1 つのイベントを経験します。 1 日は賞品の日または顧客の日のいずれかです。 

賞品の日に、ボブはサイズのメモリースティックを受け取ります$2^x$。 彼はそれを保管することも、すぐに手放すこともできます。 同時に複数のスティックを保管することは決して許可されません。 

顧客の日に、誰かがサイズのスティックを購入したいと考えています$2^x$。 ボブが現在まさにそのスティックを所有している場合、彼はそれを売って収入を得ます$2^x$ベルラー。 そうしないと顧客が離れ、機会が永久に消えてしまいます。 

入力は単にこれらのイベントのシーケンスです。 賞金イベントごとに、ボブがスティックを保持するか廃棄するかを決定して、獲得したお金の合計が最大になるようにする必要があります。 

制約$n \le 5000$は二次動的計画法には十分小さいですが、指数関数的な探索には大きすぎます。 すべての選択肢を試す総当りの場合、次の点まで考慮する必要があります。$2^{5000}$状態、それは不可能です。 三次解には危険が伴います。$5000^3 = 1.25 \times 10^{11}$操作は限界をはるかに超えています。 二次解は快適です。$2.5 \times 10^7$最悪の場合の運用。 

難しいのは、ボブがスティックを 1 本しか持てないことです。 地域的に魅力的な決定は、将来のより収益性の高い販売を台無しにする可能性があります。 

次の例を考えてみましょう。```
4
win 1
win 10
sell 1
sell 10
```常に最新のスティックを維持する貪欲な戦略は利益で終わる$2^{10} = 1024$サイズ 1 のスティックは顧客が到着する前に廃棄されるためです。 

最適なプレイは異なります。 

サイズ 1 を維持して販売し、その後サイズ 10 を維持して販売する、合計$2 + 1024 = 1026$。 

もう 1 つの微妙なケースは、一致する顧客が既に通り過ぎた後に賞品が到着する場合です。```
3
sell 5
win 5
sell 5
```2番目の顧客だけが満足できるのです。 同じサイズのすべての売りとすべての勝利を一致させる不注意な前処理ステップは、過大評価になります。 

重複する間隔の間には重要な相互作用もあります。```
6
win 1
win 2
sell 1
sell 2
win 1
sell 1
```最初のサイズ 1 スティックとサイズ 2 スティックは、アクティブな間隔が重なるため、両方を同時に保持することはできません。 アルゴリズムはこの競合を明示的にモデル化する必要があります。 

## アプローチ

 最も直接的な強引な方法は、日を 1 日ずつ処理し、すべての日について可能な限りの決定を試みることです。`win`イベント。 ボブがスティックを受け取るたびに、私たちはそれを保持するか捨てるかの 2 つの可能性に分岐します。 彼がすでに別のスティックを所有している場合は、現在のスティックを交換することも決定する場合があります。 

この検索は、すべての法的な一連のアクションを調査するため、正確です。 問題は州の数です。 最悪の場合、5000 の賞品イベントが発生し、おおよその生産額が発生します。$2^{5000}$可能性。 積極的な剪定を行っても、このアプローチを救うことはできません。 

重要な観察は、収益性の高い販売が間隔のように動作するということです。 

あるサイズの棒を想定します$x$当日に当選します$l$、当日は該当のお客様が登場します$r$。 ボブがこの棒で稼ぎたいなら、その日から$l$当日まで$r$彼はこのスティック用に唯一のストレージスロットを予約しなければなりません。 そのインターバルの間中、彼は他のスティックを保持することはできません。 

これにより、問題は間隔スケジュールに変わります。 

それぞれの収益性の高い機会は次のようになります。 

間隔を取る$[l, r]$価値のあるもの$2^x$。 

2 つの間隔は、重なり合わなければ互換性があります。 目標は、重複しない間隔の最大値セットを選択することになります。 

これで、構造が非常にシンプルになりました。 あらゆる人にとって`sell x`、顧客は最大でも 1 人です。 逆方向にスキャンして、この顧客を以前のすべての顧客とペアにすることができます`win x`。 このような各ペアは 1 つの区間候補を形成します。 

すべての間隔が得られると、問題は加重間隔スケジューリング、つまり古典的な動的計画問題になります。 

終了日によって間隔を並べ替えます。 すべての間隔について、この間隔が開始される前に終了する最後の間隔を見つけます。 それから：$$dp[i] = \max(dp[i-1], dp[p(i)] + value_i)$$これにより、問題は指数関数的な検索から二次前処理と線形 DP に軽減されます。

### なぜ効果があるのか

 すべての有益なアクションは、連続した時間間隔中にボブの 1 つのストレージ スロットを予約することに対応します。 2 つの収益性の高いアクションは、その間隔が重ならない場合に同時に実行できます。 

変換は正確です:

 すべての有効な戦略は、重複しない間隔のセットを生成します。 

そして、重複しない間隔のすべてのセットが有効な戦略を表します。 

動的プログラミングは、加重間隔スケジューリングの標準的な最適な下部構造です。 間隔を考えると$i$、最適なソリューションはそれを除外するか、それを含めます。 インターバルを含む場合$i$、残りの選択された間隔はすべて、次で終わる互換性のあるプレフィックスから取得する必要があります。$p(i)$。 可能性はこれら 2 つだけであるため、再帰では常に真の最適値が計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    typ = []
    val = []

    for _ in range(n):
        t, x = input().split()
        typ.append(t)
        val.append(int(x))

    intervals = []

    for r in range(n):
        if typ[r] == "sell":
            x = val[r]

            for l in range(r):
                if typ[l] == "win" and val[l] == x:
                    intervals.append((l, r, 1 << x))

    intervals.sort(key=lambda item: item[1])

    m = len(intervals)

    ends = [0] * m
    starts = [0] * m
    profits = [0] * m

    for i in range(m):
        starts[i] = intervals[i][0]
        ends[i] = intervals[i][1]
        profits[i] = intervals[i][2]

    p = [-1] * m

    for i in range(m):
        best = -1

        for j in range(i - 1, -1, -1):
            if ends[j] < starts[i]:
                best = j
                break

        p[i] = best

    dp = [0] * (m + 1)

    for i in range(1, m + 1):
        skip = dp[i - 1]

        take = profits[i - 1]
        if p[i - 1] != -1:
            take += dp[p[i - 1] + 1]

        dp[i] = max(skip, take)

    print(dp[m])

solve()
```最初のフェーズでは、考えられるすべての収益性の高い間隔を構築します。 もし`win x`の前に発生します`sell x`, ボブは、間隔中そのスティックを保持し、販売を完了する可能性があります。 

間隔リストは中核となるモデリング手順です。 この変換が完了すると、メモリースティックに関する元のストーリーは消え、間隔の互換性だけが問題になります。 

並べ替え順序は重要です。 DP は、互換性のあるすべての以前の間隔が現在の間隔より前に出現すると想定します。 終了時間による並べ替えにより、このプロパティが保証されます。 

の計算`p[i]`最新の互換性のある間隔を逆方向に検索します。 間隔の数は最大で$O(n^2)$、二次前処理パスは十分に高速です。 

DP 配列では、便宜上 1 から始まるインデックスを使用します。 間隔`i - 1`DP 状態に対応`i`。 これにより、空のプレフィックスにアクセスするときに負のインデックスが回避されます。 

厳密な比較:```
ends[j] < starts[i]
```が不可欠です。 あるインターバルが同じ日に終了し、別のインターバルが始まる場合でも、同じ日のシーケンス中にボブが 1 つのスティックを販売し、すでに別のスティックを所有していることはできないため、それらは重複します。 

利益は以下を使用します。```
1 << x
```なぜなら、売られたスティックの価値は$2^x$。 

Python の整数は、次の最大値を安全に処理します。$2^{2000}$任意精度の整数に簡単に適合します。
