 ## 解決策
 ## 問題の理解

 セルのストリップがあり、各セルには整数が含まれています。 隣接するセル間でのみストリップをカットし、配列を左側の部分と右側の部分に分割します。 タスクは、等しい合計を持つ 2 つの空ではない部分を生成するカット位置の数を数えることです。 

たとえば、配列が次の場合:```
[1, 2, 3, 3]
```2 番目の要素の後に切り取ると、次のようになります。```
[1, 2] | [3, 3]
```左の合計は`3`、正しい合計は`6`, したがって、このカットは無効です。 

入力サイズが到達しました`10^5`これにより、カットごとに合計を繰り返し再計算するアルゴリズムが即座に除外されます。 二次解はおおよそのパフォーマンスを発揮します`10^10`最悪の場合、2 秒の制限をはるかに超えた操作が行われます。 ターゲットの複雑さは線形時間、またはそれに非常に近いものです。 

数値が負の場合もあるため、単調な動作に依存することはできません。 プレフィックスの合計は任意に増減できます。 2 つのポインターまたは貪欲な拡張に基づく解決策は、合計が予測可能な方向に動かないため、失敗します。 

見落としやすいエッジケースがいくつかあります。 

単一の要素を考えてみましょう。```
1
5
```両方の部分に少なくとも 1 つの要素が含まれている必要があるため、有効なカットはありません。 正しい答えは次のとおりです。```
0
```すべてのインデックスをチェックする不用意な実装`0`に`n`空のパーティションを誤ってカウントする可能性があります。 

合計が奇数の場合、別の注意が必要なケースが発生します。```
4
1 2 3 5
```合計は`11`。 2 つの等しい整数の半分は不可能であるため、答えは次のようになります。```
0
```一部の実装では、解決策が存在しない場合でもすべてのカットをスキャンします。 

負の値も間違いの原因となります。```
5
2 -2 2 -2 0
```合計金額は`0`、有効なカットがいくつかあります。 プレフィックスの合計が増加するだけであると仮定するアプローチはここで破綻します。 

最後に、カット位置自体も重要です。 右側が空になるため、最後の要素の後に切り取ることはできません。 例えば：```
2
1 -1
```合計金額は`0`ただし、最初の要素の後に可能なカットは 1 つだけです。```
[1] | [-1]
```合計は等しくないので、答えは次のようになります。`0`。 

## アプローチ

 最も直接的な解決策は、考えられるすべてのカットを試して、左右の部分の合計を個別に計算することです。 

インデックスの後にカットするとします`i`。 次のように計算できます。```
left_sum  = sum(a[0..i])
right_sum = sum(a[i+1..n-1])
```合計が一致する場合、答えをインクリメントします。 

このアプローチは、すべての法的パーティションを明示的にチェックするため、正しいです。 問題は効率です。 範囲の合計を計算するには次の時間がかかります`O(n)`単純にやると時間がかかります。`n - 1`カットの可能性。 全体の複雑さは次のようになります。`O(n^2)`。 

と`n = 100000`、これは大まかに次のことを意味します。```
100000 * 100000 = 10^10
```最悪の場合、動作が非常に遅くなります。 

重要な観察は、隣接するカットが大きく重なっていることです。 カットを 1 ステップ右に移動すると、ほぼすべての要素が同じパーティション内に残ります。 合計を最初から再計算すると作業が無駄になります。 

これは当然、接頭辞の合計を示唆します。 

配列全体の合計がわかっている場合は、インデックスの後のカットについて`i`:```
left_sum  = prefix[i]
right_sum = total_sum - prefix[i]
```条件は次のようになります。```
prefix[i] == total_sum - prefix[i]
```これは次のように単純化されます。```
2 * prefix[i] == total_sum
```各カットを一定時間で確認できるようになりました。 配列を 1 回スキャンし、実行中のプレフィックスの合計を維持し、等式を満たす位置の数を数えます。 

これにより、複雑さが 2 次から線形に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、その合計を計算します。 

すべての右側の合計は次のように記述できるため、合計が必要です。```
total_sum - left_sum
```2. 現在のプレフィックス合計を次のように初期化します。`0`そして答えは`0`。 

プレフィックスの合計は、現在のカットの左側のパーティションの合計を表します。 
3. インデックスから配列を反復処理します。`0`に`n - 2`。 

に止まります`n - 2`カットでは右側に少なくとも 1 つの要素を残す必要があるためです。 
4. 現在の要素をプレフィックス合計に追加します。 

追加後`a[i]`、インデックスの後に切り取ると、プレフィックスの合計は左側のパーティションの合計と等しくなります。`i`。 
5. 次のことを確認します。```
prefix_sum * 2 == total_sum
```この条件が当てはまる場合、左右のパーティションの合計は等しいことになります。 
6. 条件が true の場合、答えをインクリメントします。 
7. すべての有効なカット位置を処理した後、回答を印刷します。 

### なぜ効果があるのか

 すべてのステップで、実行中のプレフィックスの合計は、現在のインデックスの後ろを切り取って作成された左側のパーティションの合計と等しくなります。 正しいパーティションには次の合計が含まれている必要があります。```
total_sum - prefix_sum
```カットは次の場合にのみ有効です。```
prefix_sum == total_sum - prefix_sum
```アルゴリズムは、すべての正当なカット位置についてこの条件を 1 回だけチェックします。 考えられるすべてのカットが検査され、等価性テストは元の要件と数学的に同等であるため、アルゴリズムは有効なカットを見逃したり、無効なカットをカウントしたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total_sum = sum(a)

prefix_sum = 0
answer = 0

for i in range(n - 1):
    prefix_sum += a[i]

    if prefix_sum * 2 == total_sum:
        answer += 1

print(answer)
```最初の部分は入力を読み取り、配列の合計を計算します。 これにより、すべてのカットの右側の合計に即座にアクセスできるようになります。 

変数`prefix_sum`左側のパーティションの累計を格納します。 配列を反復処理すると、新しい要素はそれぞれ左側の一部になります。 

ループは次の時点までのみ実行されます。`n - 2`。 この詳細が重要です。 私たちが許可した場合`i = n - 1`の場合、右側のパーティションは空になり、問題のステートメントに違反します。 

条件:```
prefix_sum * 2 == total_sum
```分割を完全に回避します。 これはよりクリーンであり、奇数の合計に関する問題も回避します。 合計が奇数の場合、整数プレフィックスの合計は等式を満たすことができないため、条件は当然失敗します。 

Python の整数は大きな値を自動的に安全に処理するため、ここではオーバーフローは問題になりません。 固定幅の整数を使用する言語では、64 ビット型の使用が推奨されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    total_sum = sum(a)

    prefix_sum = 0
    answer = 0

    for i in range(n - 1):
        prefix_sum += a[i]

        if prefix_sum * 2 == total_sum:
            answer += 1

    print(answer)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run(
"""9
1 5 -6 7 9 -16 0 -2 2
"""
) == "3", "sample 1"

# minimum size
assert run(
"""1
5
"""
) == "0", "single element"

# all zeros
assert run(
"""5
0 0 0 0 0
"""
) == "4", "every cut works"

# odd total sum
assert run(
"""4
1 2 3 5
"""
) == "0", "odd total"

# negative numbers
assert run(
"""5
2 -2 2 -2 0
"""
) == "3", "negative values"

# off-by-one boundary
assert run(
"""2
1 -1
"""
) == "0", "cannot cut after last element"

# balanced split in middle
assert run(
"""6
1 1 1 1 1 1
"""
) == "1", "single valid split"

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
5
```ループは次のように実行されます。```
range(n - 1) = range(0)
```したがって、反復は発生しません。 答えは残る`0`1 つの要素を 2 つの空でない部分に分割することはできないため、これは正しいです。 

ここで、奇数の合計を考えてみましょう。```
4
1 2 3 5
```合計金額は`11`。 

スキャン中:

 | 私 | プレフィックス合計 | プレフィックスサム * 2 |
 | --- | --- | --- |
 | 0 | 1 | 2 |
 | 1 | 3 | 6 |
 | 2 | 6 | 12 |

 等しいものはありません`11`、したがって答えは残ります`0`。 このアルゴリズムは、特別な処理を行わない限り、不可能なケースを自然に拒否します。 

次に、負の値を考えてみましょう。```
5
2 -2 2 -2 0
```合計金額は`0`。 

現在のプレフィックスの合計は次のようになります。```
2, 0, 2, 0
```プレフィックスの合計が`0`、残りの接尾辞の合計も次のようになります。`0`なので、それらのカットは正しくカウントされます。 このアルゴリズムでは合計が単調増加することは想定されていないため、負の数であっても問題は発生しません。 

最後に、境界条件を考慮します。```
2
1 -1
```合法的なカットはインデックス後のみ`0`。 

プレフィックスの合計は次のようになります。`1`、右側は`-1`したがって、条件は満たされず、答えは次のようになります。`0`。 

ループが次の時点で停止するため、アルゴリズムは最終要素の後のカットを決してチェックしません。`n - 2`。 これにより、空の右側のパーティションを誤ってカウントすることがなくなります。
