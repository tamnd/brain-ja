 ## 解決策
 ## 問題の理解

 整数座標を持つ平面上の 3 つの点が与えられます。 これら 3 つの点はすでに有効な三角形を形成しています。これは、それらが同一線上にないことを意味します。 

タスクは、三角形を 3 つのカテゴリのいずれかに分類することです。 

三角形は、`RIGHT`角度の 1 つがちょうど 90 度の場合。 

三角形は、`ALMOST`現在直角ではないが、4 つの基本方向のいずれかに 1 つの頂点を 1 単位ずつ正確に移動すると、直角になります。 移動された点は依然として整数座標を持っている必要があります。 

どちらの条件も当てはまらない場合は、印刷します`NEITHER`。 

座標は非常に小さく、次の間のみです。`-100`そして`100`。 それは問題の性質を完全に変えます。 高度な幾何学、浮動小数点演算、最適化テクニックは必要ありません。 可能性の総数は小さいため、多くの候補構成を試してもコストはかかりません。 

幾何学問題における最大の危険は精度です。 不用意に実装すると、三角関数を使用して角度を計算し、浮動小数点値を比較する可能性があります。`90`。 浮動小数点の丸めは正確な直角を次のようにしてしまう可能性があるため、これは脆弱です。`89.999999`。 

例えば：```
0 0 3 0 0 4
```これは明らかに直角三角形ですが、浮動小数点比較でコサイン公式を使用すると、小さな誤差が生じる可能性があります。 

安全なアプローチは、完全に距離の二乗と整数演算を使用することです。 

をチェックすると、別の微妙なケースが表示されます。`ALMOST`状態。 点を移動できるのは正確な距離だけです`1`グリッドに沿って。 斜めの移動は禁止です。 

例えば：```
0 0 1 2 2 1
```点を斜めに移動すると直角三角形を作成できますが、斜めの移動にはユークリッド距離があります`sqrt(2)`、 ない`1`。 ここでの正解は、斜めの動きに基づくものではありません。 

実装上の別の間違いは、元の三角形を検索する前に拒否することを忘れていることです。`ALMOST`。 

例：```
0 0 2 0 0 1
```これはもう直角になっています。 点を移動すると別の直角三角形が生成される場合もありますが、それでも正しい出力が得られる必要があります。`RIGHT`。 

## アプローチ

 問題を解決する最も直接的な方法は、現在の三角形が直角かどうかを確認することです。 そうでない場合は、許可されているすべての動きを試して、再度確認します。 

三角形は、その辺の長さがピタゴラスの定理を満たす場合に直角になります。 座標は整数であるため、距離の二乗も整数です。 平方辺の長さが次のようになると仮定します。`a`、`b`、 そして`c`。 それらを並べ替えると、次の場合に三角形は正確に直角になります。```
a + b = c
```この強引な戦略はすでに十分に高速です。 各ポイントには 4 つの可能な動きがあります。```
(x+1,y), (x-1,y), (x,y+1), (x,y-1)
```ポイントは3つだけなので、`3 × 4 = 12`テストするために三角形を変更しました。 

各テストでは 3 つの二乗距離が計算され、一定の作業が実行されます。 制限時間が大幅に短縮されたとしても、これは依然として瞬時に実行されます。 

重要な観察は、実際の距離を避けると、整数座標を使用したジオメトリがより単純になることが多いということです。 二乗距離では、平方根を完全に排除しながら、ピタゴラスの定理に必要なすべての比較が保持されます。 

より素朴な幾何学的なアプローチでは、ベクトルやドット積、さらには三角関数を使用した角度を計算することもできます。 これらの方法は数学的に機能しますが、ここでは不必要に複雑になります。 問題の構造は十分に小さいため、徹底的なチェックと整数演算を組み合わせることで、よりクリーンで安全な解決策が得られます。

 ## アルゴリズムのチュートリアル

 1. 3 つのポイントをお読みください。 
2. 3 つの点が直角三角形を形成するかどうかを判断するヘルパー関数を作成します。 
3. この関数内で、3 辺すべての二乗長を計算します。 

ポイントがあれば、`A`、`B`、 そして`C`、次を計算します。```
AB², AC², BC²
```二乗距離を使用すると、浮動小数点演算が完全に回避されます。 

1. 3 つの平方の長さを並べ替えます。 

最大の辺は直角三角形の斜辺でなければならないため、並べ替え後は次のことを確認するだけで済みます。```
smallest + middle = largest
```1. まず元の三角形を確認します。 

すでにピタゴラス条件を満たしている場合は、次のように出力します。`RIGHT`。 

1. それ以外の場合は、許可されている 4 つの方向に各点を移動してみてください。 

すべての点について、次の候補を生成します。```
(x+1,y)
(x-1,y)
(x,y+1)
(x,y-1)
```元の点を一時的に置き換えて、新しい三角形をテストします。 

1. 修正された三角形が直角になった場合は、印刷します。`ALMOST`。 

有効な手を 1 つ見つけた瞬間に、検索を停止できます。 

1. 12 の動きがどれも機能しない場合は、次のコマンドを実行します。`NEITHER`。 

### なぜ効果があるのか

 アルゴリズムは、ステートメントで許可されているすべての構成をチェックします。 

三角形は、その辺の長さがピタゴラスの定理を満たす場合に正確に直角になります。 平方距離では、次の理由からこの特性が完全に保持されます。```
a² + b² = c²
```整数演算のみが含まれます。 

のために`ALMOST`条件では、ステートメントでは 1 単位の水平方向または垂直方向の移動のみが許可されます。 このアルゴリズムは、頂点ごとにそのような動きをすべて明示的に列挙するため、有効な候補が見逃されることはありません。 

許可されたすべての変更がテストされ、すべてのテストが数学的に正確であるため、アルゴリズムが三角形を誤って分類することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dist2(x1, y1, x2, y2):
    return (x1 - x2) ** 2 + (y1 - y2) ** 2

def is_right(points):
    x1, y1 = points[0]
    x2, y2 = points[1]
    x3, y3 = points[2]

    sides = [
        dist2(x1, y1, x2, y2),
        dist2(x1, y1, x3, y3),
        dist2(x2, y2, x3, y3)
    ]

    sides.sort()

    return sides[0] > 0 and sides[0] + sides[1] == sides[2]

def solve():
    nums = list(map(int, input().split()))

    points = [
        [nums[0], nums[1]],
        [nums[2], nums[3]],
        [nums[4], nums[5]]
    ]

    if is_right(points):
        print("RIGHT")
        return

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for i in range(3):
        original_x, original_y = points[i]

        for dx, dy in directions:
            points[i] = [original_x + dx, original_y + dy]

            if is_right(points):
                print("ALMOST")
                return

        points[i] = [original_x, original_y]

    print("NEITHER")

solve()
```の`dist2`関数は二乗ユークリッド距離を計算します。 距離の二乗を使用すると平方根が回避され、すべての計算が正確に保たれます。 

の`is_right`機能はコアジオメトリチェックです。 3 つの平方辺の長さを計算し、並べ替えて、ピタゴラス条件を検証します。 追加チェック`sides[0] > 0`元の入力は非縮退であることが保証されていますが、縮退エッジから保護します。 

メイン ロジックは最初に元の三角形をチェックします。 すでに直角になっている三角形を印刷する必要があるため、この順序は重要です。`RIGHT`たとえ、点を移動すると別の直角三角形が作成される可能性もあります。 

の検索`ALMOST`12 の合法的な動きすべてを繰り返します。 動きをテストした後、次の動きを試す前にポイントが復元されます。 後の反復がすでに変更された座標から開始されるため、この復元手順を忘れることはバグの一般的な原因となります。 

すべては整数演算で実行されるため、精度の問題はありません。

## 特殊なケース

 三角形がすでに直角である場合を考えてみましょう。```
0 0 2 0 0 1
```アルゴリズムは最初に呼び出します`is_right`本来の点について。 

正方形の辺の長さは次のとおりです。```
1, 4, 5
```以来：```
1 + 4 = 5
```アルゴリズムはすぐに出力します`RIGHT`そして止まります。 それは決して入りません`ALMOST`検索。 ステートメントでは優先順位が付けられるため、この順序付けが必要です。`RIGHT`以上`ALMOST`。 

ここで、斜めの移動は役立つが、法的な移動は役に立たない場合を考えてみましょう。```
0 0 1 2 2 1
```アルゴリズムは元の三角形をチェックし、ピタゴラス関係が見つかりません。 

次に、次の 12 の手を正確にテストします。```
(+1,0), (-1,0), (0,+1), (0,-1)
```頂点ごとに。 

テストされた構成は直角にならないため、アルゴリズムは次のように出力します。`NEITHER`。 

これにより、基本方向の移動のみが考慮され、問題の定義と正確に一致することが確認されます。 

最後に、負の座標について考えてみましょう。```
-1 -1 1 -1 -1 2
```正方形の辺の長さは次のようになります。```
4, 9, 13
```並べ替え後:```
4, 9, 13
```以来：```
4 + 9 = 13
```アルゴリズムは正しく出力します`RIGHT`。 

計算では減算と二乗のみが使用されるため、負の座標には特別な処理は必要ありません。
