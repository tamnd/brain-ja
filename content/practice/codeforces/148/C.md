 ## 解決策
 ## 問題の理解

 王女が必要な方法で正確に反応するように、一連の新郎の運勢を構築する必要があります。 

最初の新郎以降の新郎ごとに、2 つの特別な状況が考えられます。 

もし現在の幸運がこれまでのあらゆる幸運よりも大きいなら、お姫様は言います`Oh...`。 

もし現在の運勢がこれまでの運勢の合計よりも大きい場合、王女は言います。`Wow!`その代わり。 あ`Wow!`置き換える`Oh...`、両方としてカウントされません。 

最初の新郎は何も反応しません。 

私たちは与えられています`n`、新郎の数と正確な数`Oh...`反応`a`そして`Wow!`反応`b`。 タスクは、次の間の有効な運勢のシーケンスを出力することです。`1`そして`50000`、 または`-1`そのようなシーケンスが存在しない場合。 

制約はわずかです。 両方`a`そして`b`せいぜい`15`、 そして`n`せいぜい`100`。 つまり、各位置には最大で`50000`選択肢。 単純な後戻りソリューションはまったく実行不可能です。 一方で、制限が小さいということは、意図した解決策が建設的であることを強く示唆しています。 有効なシーケンスを検索するのではなく、直接構築することが期待されています。 

やっかいな部分は、`Wow!`よりもはるかに強いです`Oh...`。 

以前の運勢を合計すると、`S`現在の最大値は`M`。 

値を選択すると:

 -`x <= M`、反応はありません。 
-`M < x <= S`、私たちは得ます`Oh...`。 
-`x > S`、私たちは得ます`Wow!`。 

これにより、重要な事実がすぐに明らかになります。 を生産するには`Oh...`、前の合計が現在の最大値より厳密に大きくなる必要があります。 それ以外の場合は間隔`(M, S]`は空です。 

たとえば:

 入力:```
3 1 1
```不用意に構築すると、次のような問題が発生する可能性があります。```
1 2 3
```しかし、これにより 2 つが得られます`Wow!`反応、理由:

 -`2 > 1`-`3 > 1+2`決してありません`Oh...`。 

もう 1 つの簡単な間違いは、小さな値の繰り返しが役に立つということを忘れていることです。 

たとえば:

 入力:```
5 0 0
```厳密に増加するシーケンスはすぐに失敗します。 正しい考え方は、すべての値を等しく保つことです。```
7 7 7 7 7
```以前の最大値を超える値はないため、まったく反応しません。 

必要なものが多すぎる場合には、もう 1 つの微妙なエッジ ケースが発生します。`Oh...`～に対する反応`Wow!`。 

考慮する：```
3 2 0
```これは不可能です。 

何もなしで`Wow!`、すべての数値が同一であれば、最初の要素の後でも合計と最大値は等しくなります。 一つでも作るためには`Oh...`, まず合計が最大値より大きくなる必要があります。 合計を急速に増加させる唯一のメカニズムは、`Wow!`。 

これにより、重要な実現可能条件が導き出されます。```
a <= b + 1
```この条件が満たされない場合、構築は存在しません。 

## アプローチ

 最も直接的な総当たりアプローチは、考えられるすべての配列を生成して、それぞれの配列に対するプリンセスの反応をシミュレートすることです。 シミュレーション自体は簡単です。 現在の最大値とプレフィックスの合計を維持し、すべての新しい値を 3 つのカテゴリのいずれかに分類します。 

問題は検索スペースです。 たとえ運勢を以下の価値観に限定したとしても`1`に`10`、配列の数はすでに`10^100`最悪の場合。 その空間を探索する機会はありません。 

反応の構造は、より良い方向性を与えます。 すべての反応は、接頭辞の 2 つの量のみに依存します。 

- 現在の最大値
 - 現在のプレフィックスの合計

 あ`Wow!`新しい値が前の合計全体を超えるため、両方とも積極的に増加します。 アン`Oh...`現在の合計の範囲内に留まりながら、最大値のみが増加します。 

重要な観察は、`Wow!`、プレフィックスの合計は最大値よりも大幅に大きくなります。 それが将来への余地を生む`Oh...`反応。 

例えば：```
1
```現在の合計 = 1、最大 = 1。 

以下を追加すると、```
2
```を取得します。`Wow!`。 

今：```
sum = 3
max = 2
```ようやくスペースが空きました`Oh...`の値があるため、`(2, 3]`存在する。 

追加:```
3
```を生成します。`Oh...`。 

その後：```
sum = 6
max = 3
```またまた別のスペースができました`Oh...`。 

このパターンは、クリーンな構造を示唆しています。 

- から始める`1`。 
- それぞれをプロデュース`Wow!`を使用して`sum + 1`。 
- 毎回の後`Wow!`、オプションで作成します`Oh...`正確に使用して`sum`。 

それぞれだから`Wow!`確実に 1 つを確保できるスペースを確保`Oh...`、最大数`Oh...`反応は`b + 1`。 まさにそれが実現可能条件です。 

必要な反応がすべて作成されたら、残りの位置を次のように埋めます。`1`、最大値がすでに少なくとも次の値であるため、何もトリガーされません。`1`。

 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. かどうかを確認します。`a > b + 1`。 

このような場合は、印刷してください`-1`。 毎`Wow!`最大 1 つの新しいスペースを作成できます`Oh...`、イニシャルが 1 つある場合もあります`Oh...`何かの前に`Wow!`。 
2. シーケンスを開始します。`1`。 

最初の新郎は何も反応しないので、これが最も簡単なスタートです。 
3. 2 つの変数を維持します。 

-`s`、現在のプレフィックスの合計
 -`mx`、現在の最大値
 4. もし`a > 0`、イニシャルを 1 つ作成します`Oh...`。 

追加`1`もう一度言いますが、それを望まない場合にのみ、`Oh...`。 それ以外の場合は、最大値より大きく、合計より大きくない値が必要です。 最初は両方とも`1`, なのでこれは無理です。 

最初のものを作成する唯一の方法`Oh...`の後です`Wow!`。 
5. 繰り返します`b`回:

 - 追加`s + 1`。 
- これにより、`Wow!`, 新しい値が以前の合計全体を超えているためです。 
- アップデート`s`そして`mx`。 
6. それぞれの後に`Wow!`、さらに必要な場合は`Oh...`反応:

 - 追加`s`。 
- 以来`mx < s <= s`、これにより、`Oh...`。 
- アップデート`s`そして`mx`。 
7. 残りのすべての位置を次のように埋めます。`1`。 

最大値は既によりもはるかに大きいため、`1`、これらの位置では反応は生じません。 

### なぜ効果があるのか

 この構造では単純な不変条件が維持されます。 

追加するたびに`s + 1`、新しい値は前のプレフィックスの合計よりも大きいため、反応は常に次のようになります。`Wow!`。 

追加するたびに`s`、以前の最大値は厳密に以下よりも小さいです`s`、最後だから`Wow!`それらの間にギャップが生じました。 新しい値は前の合計よりも大きくないため、反応は正確に次のようになります。`Oh...`。 

すべてのフィラー値は次のとおりです。`1`、現在の最大値を超えることはありません。 

の数`Wow!`そして`Oh...`は独立して制御され、追加されたすべての数字は正確に意図した効果を発揮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())

    if a > b + 1:
        print(-1)
        return

    ans = [1]

    s = 1
    mx = 1

    oh_used = 0
    wow_used = 0

    for _ in range(b):
        x = s + 1
        ans.append(x)

        wow_used += 1
        s += x
        mx = x

        if oh_used < a:
            x = s
            ans.append(x)

            oh_used += 1
            s += x
            mx = x

    while len(ans) < n:
        ans.append(1)

    print(*ans[:n])

solve()
```最初の条件は実現可能性のチェックです。 もし`a > b + 1`、どのような構造も存在することはできません。`Wow!`最大でも 1 つの未来のための余地を生み出す`Oh...`。 

シーケンスは次から始まります`1`なぜなら、その後のすべての計算が単純になるからです。 変数`s`そして`mx`現在のプレフィックスの合計と最大値を追跡します。 

ループ生成`Wow!`反応が追加される`s + 1`。 この値は前の合計全体よりも大きいため、常にトリガーされます。`Wow!`。 

その直後、それ以上であれば`Oh...`リアクションがまだ必要なので、正確に追加します`s`。 現時点では、現在の最大値は厳密に以下よりも小さくなります。`s`したがって、新しい値はプレフィックスの合計を超えることなく新しい最大値になります。 それはまさに次の定義です`Oh...`。 

フィラーループは追加します`1`配列の長さに達するまで`n`。 これらの値は現在の最大値を安全に下回っており、反応数に影響を与えることはありません。 

微妙な点の 1 つは、更新の順序です。 追加するたびに、次の値を構築する前にプレフィックスの合計を更新する必要があります。 古い値を使用すると、反応の分類が完全に変わってしまいます。 

もう一つの微妙なポイントは、`ans[:n]`。 次の場合、構築により一時的に必要以上の要素が作成される場合があります。`n`に近いです`a + b + 1`。 ステートメントは保証します`n > a + b`したがって、切り捨ては安全なままです。
