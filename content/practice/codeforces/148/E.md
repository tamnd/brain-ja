 ## 解決策
 ## 問題の理解

 磁器製品の棚がいくつかあります。 1 つの棚内にはアイテムが 1 列に並んでおり、いつでも現在の左端のアイテムまたは現在の右端のアイテムのみを削除できます。 1 つのアイテムを削除すると、その側の次のアイテムにアクセスできるようになります。 

姫はまさに叫ぶ`m`回、まさにそのとおり`m`すべての棚からアイテムを合計して取り除く必要があります。 すべてのアイテムには値があり、削除されたアイテムの値の可能な最大の合計が必要です。 

重要な点は、棚が独立していることです。 ある棚からアイテムを削除しても、別の棚で利用可能なアイテムが変更されることはありません。 唯一の相互作用は、すべての棚から削除されたアイテムの合計数が等しいというグローバル要件から生じます。`m`。 

棚の数は最大で`100`、各棚には最大で次のものが含まれます`100`アイテム。 到達できるアイテムの総数は、`10000`の上限と一致します。`m`。 

考えられるすべての除去シーケンスに対する強引な攻撃は絶望的です。 長さのある棚1枚でも`100`すでにおおよそあります`2^100`左/右の選択。 構造を活用する必要があります。 

小さな棚のサイズが重要な観察ポイントです。 個々の棚には最大でも`100`そのため、その棚から取り出されたあらゆる数のアイテムを前処理できます。 その後、問題は棚にまたがるナップサック型の動的計画法問題になります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

棚が次のようなものであるとします。```
1 100 1
```そして、2つのアイテムを取りたいと考えています。 最良の選択は`100 + 1 = 101`, 左のアイテムを2回取ると入手できます。 重複を考慮せずに「左から一部を取得し、右から一部を独立して取得する」と想定する不注意な実装では、誤って不可能な状態をカウントする可能性があります。 

もう 1 つの注意が必要なケースは、すべての便利なアイテムが片側に集中している場合です。 

入力：```
1 3
5 100 1 1 1 1
```正しい答えは、`102`、 ない`3`。 最適な順序は、左から順に取得し続けることです。 貪欲に陣営を交代させるようなアプローチは、大失敗に終わります。 

棚を組み合わせるときに、もう 1 つの微妙な状況が現れます。 

入力：```
2 2
2 100 1
2 50 50
```正しい答えは、`150`、2番目の棚から両方のアイテムを取ることによって。 現在表示されている世界最大のアイテムを常に取得する貪欲な戦略では、`100`最初に、その後だけ`50`で終わる`150`偶然ここで。 少し変更するとすぐに壊れてしまいます。 この問題では、棚間のピックのすべての配分を考慮する必要があります。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 叫び声ごとに棚を選択し、その棚から左または右を選択します。 これにより、すべての有効な削除シーケンスが調査されます。 考えられるすべてのアクション シーケンスが検査されるため、これは正しいです。 

問題は分岐要素です。 各ステップで多数の使用可能な棚があり、各棚には 2 つの選択肢があります。 単純化して単一の棚内での左右の判断だけを考えても、一定のサイズの棚`100`すでに持っています`2^100`可能性。 まで`10000`完全な削除、徹底的な検索は完全に不可能です。 

重要な観察は、左から何個のアイテムが取り出され、右から何個のアイテムが取り出されるのかがわかれば、1 つの棚内の取り出す順序は問題ではないということです。 

シェルフに次の配列があるとします。```
a0 a1 a2 ... ak
```最終的に削除したら`x`左からのアイテムと、`y`右から項目を追加すると、収集された値が固定されます。```
prefix[x] + suffix[y]
```制限付きで`x + y = t`、 どこ`t`この棚から削除されたアイテムの合計数です。 

つまり、すべての棚、すべての可能な限りの`t`、次のように事前計算できます。```
best[t] = maximum value obtainable by removing exactly t items
```棚のサイズが最大なので、`100`、単純に左右のすべての分割を試してみることができます。 

すべてのシェルフを個別に前処理すると、元の問題は次のようになります。```
Choose how many items to take from each shelf so that the total is m and the gained value is maximized.
```これはまさにグループ化されたナップザック動的計画法の問題です。 

We process shelves one by one. させて：```
dp[j]
```いくつかの棚を処理し、正確に取得した後に取得できる最大値である`j`アイテムの合計。 

すべてのシェルフについて、そのシェルフから取得できるすべてのカウントを試し、DP を更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n × m × s) | O(m) | 承認済み |

 ここ`s`最大シェルフ サイズです。`100`。 

## アルゴリズムのチュートリアル

 1. すべての棚を読みます。 

各シェルフは値の配列として保存されます。 
2. 1 つのシェルフについて、プレフィックスの合計とサフィックスの合計を計算します。`prefix[i]`最初の合計です`i`アイテム。`suffix[i]`最後の合計です`i`アイテム。 

これらにより、左右の分割を一定時間で評価できるようになります。 
3. 考えられるすべての数字について`t`この棚から取り出したアイテムの中で、達成可能な最高の値を計算します。 

すべての分割を試します。```
left = x
right = t - x
```そして最大化します:```
prefix[x] + suffix[right]
```これは、削除する有効なシーケンスがすべて存在するため、機能します。`x`左からのアイテムと、`right`右からの項目は常にそれらの境界要素を正確に削除します。 
4. グローバル DP アレイを維持します。`dp[j]`加工された棚を使用し、正確に取得できる最高の合計値を意味します`j`アイテム全体。 
5. 棚を 1 つずつ加工します。 

現在のシェルフに対して、新しい DP アレイを作成します。 すでに達成された合計ごとに`j`、取ってみてください`t`現在の棚のアイテム。 

遷移：```
ndp[j + t] = max(ndp[j + t], dp[j] + best[t])
```6. すべての棚の処理が完了したら、出力します。`dp[m]`。 

### なぜ効果があるのか

 固定棚の場合、有効な最終状態は、左側からいくつのアイテムが削除されたか、右側からいくつアイテムが削除されたかによって完全に決定されます。 これらの削除の内部順序は、どのアイテムが収集されるかには影響しません。 

したがって、前処理ステップでは、その棚から取り出されるすべての可能な数の最適な値が正しく計算されます。 

次に、グローバル DP は、あらゆる可能な分布を考慮します。`m`棚全体の削除。 各シェルフは取得数が固定されると独立して寄与するため、それらをナップザック DP と組み合わせると、すべての有効なグローバル ソリューションが 1 回だけ探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

n, m = map(int, input().split())

dp = [-INF] * (m + 1)
dp[0] = 0

for _ in range(n):
    data = list(map(int, input().split()))
    k = data[0]
    a = data[1:]

    prefix = [0] * (k + 1)
    suffix = [0] * (k + 1)

    for i in range(k):
        prefix[i + 1] = prefix[i] + a[i]

    for i in range(k):
        suffix[i + 1] = suffix[i] + a[k - 1 - i]

    best = [0] * (k + 1)

    for take in range(k + 1):
        cur = 0
        for left in range(take + 1):
            right = take - left
            cur = max(cur, prefix[left] + suffix[right])
        best[take] = cur

    ndp = dp[:]

    for used in range(m + 1):
        if dp[used] < 0:
            continue

        limit = min(k, m - used)

        for take in range(1, limit + 1):
            ndp[used + take] = max(
                ndp[used + take],
                dp[used] + best[take]
            )

    dp = ndp

print(dp[m])
```1 つのシェルフの前処理がソリューションの中心です。`prefix[i]`最初の合計を格納します`i`アイテム、一方で`suffix[i]`最後の合計を保存します`i`アイテム。 次に、正確に取るためのあらゆる実行可能な方法`take`項目は、左から何個来るかを選択することによって表されます。 

行:```
prefix[left] + suffix[right]
```安全なので`left + right = take`, そのため、選択したセグメントが誤って重なることはありません。 

グローバル DP は、標準的なグループ化されたナップザック パターンを使用します。 以前の DP をコピーします`ndp`現在のシェルフの遷移を処理する前に。 これにより、1 回の反復で誤って同じシェルフを複数回使用することが防止されます。 

条件:```
if dp[used] < 0:
    continue
```到達不可能な状態をスキップします。 

もう 1 つの微妙な詳細は次のとおりです。```
limit = min(k, m - used)
```この制限がないと、必要な取得アイテムの合計数を超える遷移が試行される可能性があります。 

すべての値は正であるため、到達不可能な状態を大きな負の値で初期化するだけで十分です。

    input = sys.stdin.readline

    n, m = map(int, input().split())

    dp = [-INF] * (m + 1)
    dp[0] = 0

    for _ in range(n):
        data = list(map(int, input().split()))
        k = data[0]
        a = data[1:]

        prefix = [0] * (k + 1)
        suffix = [0] * (k + 1)

        for i in range(k):
            prefix[i + 1] = prefix[i] + a[i]

        for i in range(k):
            suffix[i + 1] = suffix[i] + a[k - 1 - i]

        best = [0] * (k + 1)

            for left in range(take + 1):
                right = take - left
                best[take] = max(
                    best[take],
                    prefix[left] + suffix[right]

                ndp[used + take] = max(
                    ndp[used + take],
                    dp[used] + best[take]
                )

        dp = ndp

    return str(dp[m]) + "\n"

 ## 特殊なケース

 次の入力を考えてみましょう。```
1 2
3 1 100 1
```真ん中のアイテムを先に取ることはできません。 アルゴリズムは、有効な境界の削除のみを考慮してこれを処理します。 

シェルフの前処理は以下を計算します。 

| 左 | 右 | 値 |
 | --- | --- | --- |
 | 0 | 2 | 101 |
 | 1 | 1 | 2 |
 | 2 | 0 | 101 |

 したがって、2 つのアイテムを取得する場合の最適な値は次のようになります。`101`、 ない`200`。 このアルゴリズムでは、中央のアイテムが最初に公開されずに削除されるという不可能な状態は決して作成されません。 

ここで次のことを考えてみましょう。```
1 3
5 100 1 1 1 1
```プレフィックスの合計は次のとおりです。```
[0, 100, 101, 102, 103, 104]
```接尾辞の合計は次のとおりです。```
[0, 1, 2, 3, 4, 104]
```3 つの項目を取得する場合、アルゴリズムはすべての分割をチェックします。 

| 左 | 右 | 値 |
 | --- | --- | --- |
 | 0 | 3 | 3 |
 | 1 | 2 | 102 |
 | 2 | 1 | 102 |
 | 3 | 0 | 102 |

 正解`102`が見つかりました。 

最後に、シェルフの組み合わせを検討してください。```
2 2
2 100 1
2 50 50
```シェルフごとの最適な配列は次のようになります。 

最初の棚:```
[0, 100, 101]
```2番目の棚:```
[0, 50, 100]
```グローバル DP 中に、アルゴリズムは以下を比較します。 

| 棚 1 から取り出します | 棚2から取る | 合計 |
 | --- | --- | --- |
 | 2 | 0 | 101 |
 | 1 | 1 | 150 |
 | 0 | 2 | 100 |

 最大値は`150`, ピックを棚全体に分割することで入手できます。 これにより、DP が貪欲にコミットするのではなく、すべてのディストリビューションを正しく探索していることが確認されます。
