 ## 問題の理解

 私たちは白ネズミと黒ネズミが入った袋を持っています。 最初に王女が動き、次にドラゴンが動き、次に再び王女が動きます。 すぐに白いネズミを引いた人が勝ちです。 誰かが黒いネズミを引いた場合、ゲームは続行されます。 

ドラゴンのターンには追加ルールが 1 つあります。 ドラゴンがネズミを引くと、残りのネズミがパニックになるため、別のネズミがランダムに袋から飛び出します。 ジャンプしたマウスは誰かが引いたものとしてカウントされないため、勝者を直接決定することはできません。 

入力により、白いマウスの初期数が得られます。`w`そして黒いネズミ`b`。 すべてのランダムな選択が均一である場合に、最終的に王女が勝つ確率を計算する必要があります。 

この制約により、最大 1000 匹の白マウスと 1000 匹の黒マウスが許可されます。 考えられるすべてのゲーム シーケンスにわたる総当りシミュレーションは、すべての手が将来のいくつかの状態に分岐するため、指数関数的に爆発的に増加します。 メモ化を行わない再帰的検索でも、同じことを再訪することになります。`(w, b)`と何度も状態にします。 異なる状態が約 100 万個しかない場合、動的計画法は実行可能ですが、指数関数的なものは実行できません。 

この問題の最も危険な部分は、ドラゴンのターン中のイベントの順序を正しくモデル化することです。 不注意な実装では、複数の確率ステップが 1 つにマージされ、誤って不可能な遷移がカウントされてしまうことがよくあります。 

次の入力を考えてみましょう。```
1 1
```姫が最初に絵を描きます。 彼女は確率ですぐに勝ちます`1/2`。 代わりに彼女が黒いネズミを引いた場合、ドラゴンは唯一残っている白いネズミを獲得し、勝ちます。 正しい答えは次のとおりです。```
0.5
```ターン順序を無視する間違った繰り返しにより、誤って生成される可能性があります。`1`。 

別の微妙なケースは次のとおりです。```
0 5
```白いねずみはまったくいないので、お姫様は決して勝つことができません。 答えは次のようになります。```
0
```再帰的な解決策の中には、存在しない白いネズミが関与する確率を計算しようとするため、ここで誤ってゼロで除算してしまうものもあります。 

3 番目の注意が必要なケースは次のとおりです。```
2 0
```姫はすぐに確率で白ねずみを引く`1`、したがって、答えは次のようになります。```
1
```ゲームはプリンセスの最初の動きですでに終了しているため、ドラゴンが関与する遷移はこの状態では決して評価されるべきではありません。 

## アプローチ

 ブルートフォースアプローチは、ドローとジャンプのあらゆる可能なシーケンスを再帰的にシミュレートすることです。 州から`(w, b)`、姫が白を引くか黒を引くかで分岐し、次にドラゴンの絵で再び分岐し、次に飛び去るネズミで再び分岐します。 

すべてのゲーム結果は再帰ツリー内の 1 つのパスに正確に対応するため、この再帰プロセスは数学的に正しいです。 問題はパスの数です。 最悪の場合、各ターンで複数の分岐が発生し、ゲームの長さは最大 2000 イベントになる可能性があります。 メモ化なしで訪問した州の数は膨大になり、2 秒に収まる量をはるかに超えます。 

重要な観察は、将来は白ネズミと黒ネズミがどれだけ残っているかによってのみ決まるということです。 正確な経歴は関係ありません。 2 つの異なるシーケンスが同じ結果をもたらす場合`(w, b)`プリンセスのターンでの構成は、その時点以降の最終的な勝利の確率は同じです。 

そのため、これは状態に関する古典的な動的計画法の問題になります。 

定義する`dp[w][b]`プリンセスの番が来てバッグに現在入っているときにプリンセスが勝つ確率として`w`白いネズミと`b`黒いネズミ。 

この状態からは、可能性はわずかしかありません。 

姫がすぐに白ねずみを引けば勝ちです。 

彼女が黒いネズミを描くと、次にドラゴンが動きます。 プリンセスがドラゴンのターンを生き残るためには、ドラゴンも黒いネズミを描かなければなりません。 その後、さらに 1 匹のネズミが飛び去ります。 ジャンプしたマウスが白か黒かに応じて、別の小さな状態に遷移します。 

遷移ごとにマウスの総数が厳密に減少するため、状態をボトムアップで計算できます。

 | ブルートフォース | 指数 | 指数再帰ツリー | 遅すぎる |
 | 最適な動的プログラミング | O(w × b) | O(w × b) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 定義する`dp[i][j]`王女が自分の番になったときに勝つ確率として`i`白いネズミと`j`黒いネズミが残っています。 
2. 基本ケースを初期化します。 

白いねずみがいなければ、王女は決して勝つことはできません。```
dp[0][j] = 0
```黒ネズミがいない場合、お姫様はすぐに白を描きます。```
dp[i][0] = 1
```3. すべての状態を反復処理する`(i, j)`と`i >= 1`そして`j >= 1`。 
4. プリンセスが自分の引きで即座に勝つ確率を計算します。 

彼女はすべてのマウスの中から一様に選択するので、次のようになります。```
win_now = i / (i + j)
```5. お姫様が最初に黒いねずみを引く確率を計算します。```
princess_black = j / (i + j)
```6. 王女が黒いネズミを一匹取り除いた後、ドラゴンは次のものが入った袋に行動します。`i`白と`j - 1`黒いネズミ。 

プリンセスにまだチャンスがあるためには、ドラゴンは黒いネズミを描かなければなりません。 ドラゴンが白を引けば、すぐにドラゴンが勝ちます。 

ドラゴンが黒を引く確率は次のとおりです。```
dragon_black = (j - 1) / (i + j - 1)
```7. ドラゴンが黒を描いた後、別のネズミが飛び出します。 

そのときバッグの中には`i`白と`j - 2`黒いネズミ。 

可能性は 2 つあります。 

白いネズミが飛び出してきた場合:```
probability = i / (i + j - 2)
next state = dp[i - 1][j - 2]
```黒いネズミが飛び出してきた場合:```
probability = (j - 2) / (i + j - 2)
next state = dp[i][j - 3]
```8. 有効なトランジションをすべて加算します。 

完全な繰り返しは次のようになります。```
dp[i][j] =
    i / (i + j)
    +
    (j / (i + j))
    × ((j - 1) / (i + j - 1))
    × (
        (i / (i + j - 2)) × dp[i - 1][j - 2]
        +
        ((j - 2) / (i + j - 2)) × dp[i][j - 3]
      )
```1. 次のような状態にアクセスする前に、境界を注意深く確認してください。`j - 2`または`j - 3`。 

### なぜ効果があるのか

 反復により、状態から考えられるすべての結果が徹底的に分割されます。`(i, j)`。 

プリンセスは白を引くか、黒を引くことですぐに勝ちます。 2 番目のケースでは、唯一生き残るパスは、ドラゴンも黒を描くパスです。 その後、ジャンプしたマウスは次の縮小状態を決定します。 

すべての遷移確率にその遷移に到達する確率が乗算され、すべての素な可能性が合計されます。 すべての動きは厳密にマウスの数を減らすため、DP は最終的に答えがすでにわかっている基本状態に到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

w, b = map(int, input().split())

dp = [[0.0] * (b + 1) for _ in range(w + 1)]

for i in range(1, w + 1):
    dp[i][0] = 1.0

for i in range(1, w + 1):
    for j in range(1, b + 1):
        total = i + j

        # Princess draws white immediately
        ans = i / total

        # Princess draws black
        if j >= 1:
            princess_black = j / total

            # Dragon draws black
            if j >= 2:
                dragon_black = (j - 1) / (total - 1)

                survive_prob = princess_black * dragon_black

                remaining = total - 2

                # A white mouse jumps out
                if i >= 1:
                    ans += (
                        survive_prob
                        * (i / remaining)
                        * dp[i - 1][j - 2]
                    )

                # A black mouse jumps out
                if j >= 3:
                    ans += (
                        survive_prob
                        * ((j - 2) / remaining)
                        * dp[i][j - 3]
                    )

        dp[i][j] = ans

print("{:.9f}".format(dp[w][b]))
```DP テーブルには、到達可能なすべての状態の確率が格納されます。 遷移ごとにマウスの総数が減少するため、小さな状態は大きな状態が必要とする前にすでに計算されています。 

最初の基本ケースセット`dp[i][0] = 1`なぜなら、白いネズミだけが残っている場合、王女は自分の番で即座に勝利するからです。 

この繰り返しはゲームのプロセスを直接反映しています。 最もデリケートな部分はドラゴンのターンです。 姫が黒いネズミを取り除くと、袋のサイズが小さくなったので分母が変わります。 ドラゴンが別の黒いネズミを除去した後、パニック ジャンプが発生する前に分母が再び変わります。 

多くの間違ったソリューションは、誤ってすべてのステージで同じ分母を再利用します。 イベントごとにバッグのサイズが変化するため、不正確な確率が生じます。 

もう 1 つの微妙な実装の詳細は、アクセスする前に境界をチェックすることです。`dp[i][j - 3]`または`dp[i - 1][j - 2]`。 これらの状態は、クマネズミが十分に残っている場合にのみ存在します。 

この問題は以下のエラーのみを必要とするため、浮動小数点精度で十分です。`1e-9`。

 | ステップ | イベント | 確率 | 次の状態 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(w × b) | 各 DP 状態は、一定の作業で 1 回計算されます。 
| スペース | O(w × b) | DP テーブルには状態ごとに 1 つの値が格納されます。 

テーブルの最大サイズはおおよそ次のとおりです`1001 × 1001`、これは約100万の州です。 各状態は少数の算術演算のみを実行するため、解は時間制限とメモリ制限内に簡単に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    w, b = map(int, input().split())

    dp = [[0.0] * (b + 1) for _ in range(w + 1)]

    for i in range(1, w + 1):
        dp[i][0] = 1.0

    for i in range(1, w + 1):
        for j in range(1, b + 1):
            total = i + j

            ans = i / total

            if j >= 2:
                survive = (j / total) * ((j - 1) / (total - 1))
                remaining = total - 2

                ans += survive * (i / remaining) * dp[i - 1][j - 2]

                if j >= 3:
                    ans += survive * ((j - 2) / remaining) * dp[i][j - 3]

            dp[i][j] = ans

    print("{:.9f}".format(dp[w][b]))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("1 3\n") == "0.500000000", "sample 1"

# minimum size, no white mice
assert run("0 5\n") == "0.000000000", "no possible win"

# only white mice
assert run("5 0\n") == "1.000000000", "immediate win"

# small mixed case
assert abs(float(run("1 1\n")) - 0.5) < 1e-9, "balanced small case"

# another small case
assert abs(float(run("2 1\n")) - (2/3)) < 1e-9, "dragon immediately wins after black"

# larger boundary-style case
res = float(run("1000 1000\n"))
assert 0.0 <= res <= 1.0, "probability range"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
0 5
```DP はすぐに基本ケースを使用します。```
dp[0][5] = 0
```バッグ内に白いマウスが存在しないため、評価する遷移はありません。 姫様には勝てるはずがない。 

ここで次のことを考えてみましょう。```
2 0
```アルゴリズムは以下を設定します。```
dp[2][0] = 1
```プリンセスは常に初手で白を引くため、ドラゴンのターンは考慮されません。 

最後に、次のことを考慮してください。```
1 2
```確率で姫が即勝ち`1/3`。 

彼女が最初に黒を描く場合、ドラゴンは 1 匹の白ネズミと 1 匹の黒ネズミから描きます。 ドラゴンは黒も引いた場合にのみ生き残る、確率`1/2`。 すると、唯一残った白ねずみが飛び去ってしまい、お姫様に渡す白いねずみは残らないのです。 

再帰では以下が計算されます。```
dp[1][2]
= 1/3 + (2/3)*(1/2)*dp[0][0]
= 1/3
```このケースでは、パニック ジャンプによって最後の白いマウスが削除されるという微妙な状況を確認します。
