 ## 解決策
 ## 問題の理解

 ピクセル強度を表す整数の長方形グリッドが与えられます。 グリッドはトーラスのように動作します。つまり、エッジから離れると反対側に回り込みます。 このグリッドに対して、ピクセルの値またはグリッド自体の構造を変更する一連の変換を適用する必要があります。 

一部の操作は、ラップアラウンド インデックスを使用したローカル 3×3 近傍に基づいて値を変更します。 シフト、反転、回転など、グリッド全体を移動または再配置するものもあります。 主な複雑な点は、変換が順番に適用され、後の操作では以前の操作の完全に更新された結果を確認する必要があることです。 

制約は十分に小さいため、グリッドの寸法は最大 100×100、操作数は最大 1000 です。 これは、およそ O(k · n · m) または O(k · n · m · log n) で機能するあらゆる解決策が実行可能であることを直ちに示唆しています。 ただし、近傍を誤って再計算したり、ラップアラウンドを誤って処理したりする単純な解釈では、たとえ十分な速度があったとしても、静かに間違った答えが生成されます。 

いくつかの失敗例は、「入力画像の近傍」というフレーズの誤解から生じています。 これは、ブラーとシャープの場合に特に重要です。両方とも、同じ変換内の部分的に更新された値からではなく、操作前のスナップショットから読み取る必要があります。 

2 番目の微妙な問題は、回転と反転時の座標の解釈です。 演算ごとに行列を物理的に再構築する場合、正確性は簡単ですが、n と m が入れ替わるため、回転後の次元を維持するように注意する必要があります。 

一般に実装を破壊するエッジ ケースには、回転後の単一行または単一列の動作、グリッド サイズよりも大きなシフトの繰り返し (正規化された mod n または mod m である必要があります)、および凍結された近傍スナップショットに対して複数の比較が発生するシャープ操作が含まれます。 

## アプローチ

 ブルートフォース解釈では、グリッド上の各操作を直接シミュレートします。 シフト、反転、回転などの構造変換の場合は、新しいマトリックスを再構築します。 ブラーとシャープの場合、現在のグリッドの一時コピーを作成し、そこからすべての出力を計算します。 

各操作のコストは O(nm) であり、操作の数は最大 1000 であるため、このアプローチはすでに十分です。 最悪の場合の複雑さは約 10^8 セルの更新であり、これはボーダーラインですが、慎重に実装すれば最適化された Python では許容可能です。 

重要な点は、グローバルな前処理や高度なデータ構造を必要とする操作は存在しないということです。 すべての変換は局所的または構造的です。 トロイダルの性質は、モジュール式インデックスを使用して簡単に処理されます。 これにより、プレフィックスの合計や畳み込みの最適化が不要になります。 

唯一の実際の要件は、規律ある状態管理です。各操作は、古い値と新しい値を混在させることなく、スナップショットから読み取るか、グリッドをきれいに変換する必要があります。

 ## アルゴリズムのチュートリアル

 現在のグリッドとその寸法を維持します。 すべての操作が順番に適用され、グリッドと場合によってはその形状の両方が更新されます。

1. 現在のグリッドを読み取り、作業状態として保存します。 回転すると n と m が入れ替わるため、n と m も追跡します。 
2. シフト操作の場合、モジュラー演算を使用して新しい座標を計算します。 (i, j) の各セルは ((i + y) mod n, (j + x) mod m) に移動します。 これは、ソース値の上書きを避けるために、新しいグリッドに対して行われます。 
3. 水平方向に反転の場合、行ごとに列を反転します。 垂直方向に反転では、行の順序を逆にします。 これらは、次元を維持する直接インデックス変換です。 
4. 「CW 回転」の場合、サイズ m×n の新しいグリッドを作成します。 各セル (i, j) は (j, n-1-i) に移動します。 次に、n と m を交換します。 
5. CCW 回転の場合、同様にサイズ m×n の新しいグリッドを作成しますが、(i, j) を (m−1−j, i) にマップし、その後次元を交換します。 
6. Blur の場合、新しいグリッドを割り当て、現在のグリッドからの 3×3 トロイダル近傍の平均のフロアとして各セルを計算します。 値を更新する前に、常に取得された元のスナップショットから読み取ります。 
7. Sharpen では、再びスナップショット グリッドを使用します。 各セルについて、その 8 つの隣接セルと比較します。 すべての近傍より厳密に大きい場合は 100 を加算します。すべての近傍より厳密に小さい場合は 100 を減算します。それ以外の場合は変更されません。 

すべての操作の後、最終的なグリッドを現在の次元で出力します。 

### なぜ効果があるのか

 すべてのステップで、グリッドは操作の接頭辞を適用した正確な結果を表します。 各変換は現在の状態の決定論的な関数であり、必要に応じて、操作内の依存関係が漏洩しないように凍結されたスナップショットを使用します。 すべての操作はアトミックに適用されるため、中間状態が別の操作に誤って影響を与えることはありません。 これにより、シーケンス全体にわたって帰納的に正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def blur(grid, n, m):
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            s = 0
            for di in (-1, 0, 1):
                for dj in (-1, 0, 1):
                    ni = (i + di) % n
                    nj = (j + dj) % m
                    s += grid[ni][nj]
            res[i][j] = s // 9
    return res, n, m

def sharpen(grid, n, m):
    res = [row[:] for row in grid]
    for i in range(n):
        for j in range(m):
            cur = grid[i][j]
            mx = -10**9
            mn = 10**9
            for di in (-1, 0, 1):
                for dj in (-1, 0, 1):
                    if di == 0 and dj == 0:
                        continue
                    ni = (i + di) % n
                    nj = (j + dj) % m
                    val = grid[ni][nj]
                    if val > mx:
                        mx = val
                    if val < mn:
                        mn = val
            if cur > mx:
                res[i][j] += 100
            elif cur < mn:
                res[i][j] -= 100
    return res, n, m

def shift(grid, n, m, x, y):
    res = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            ni = (i + y) % n
            nj = (j + x) % m
            res[ni][nj] = grid[i][j]
    return res, n, m

def rot_cw(grid, n, m):
    res = [[0] * n for _ in range(m)]
    for i in range(n):
        for j in range(m):
            res[j][n - 1 - i] = grid[i][j]
    return res, m, n

def rot_ccw(grid, n, m):
    res = [[0] * n for _ in range(m)]
    for i in range(n):
        for j in range(m):
            res[m - 1 - j][i] = grid[i][j]
    return res, m, n

def flip_h(grid, n, m):
    res = [row[::-1] for row in grid]
    return res, n, m

def flip_v(grid, n, m):
    res = grid[::-1]
    return res, n, m

n, m = map(int, input().split())
grid = [list(map(int, input().split())) for _ in range(n)]
k = int(input())

for _ in range(k):
    parts = input().split()
    op = parts[0]

    if op == "Blur":
        grid, n, m = blur(grid, n, m)
    elif op == "Sharpen":
        grid, n, m = sharpen(grid, n, m)
    elif op == "Shift":
        x = int(parts[1])
        y = int(parts[2])
        grid, n, m = shift(grid, n, m, x, y)
    elif op == "Rotate":
        if parts[1] == "CW":
            grid, n, m = rot_cw(grid, n, m)
        else:
            grid, n, m = rot_ccw(grid, n, m)
    elif op == "Flip":
        if parts[1] == "Horizontal":
            grid, n, m = flip_h(grid, n, m)
        else:
            grid, n, m = flip_v(grid, n, m)

for row in grid:
    print(*row)
```実装は、各変換の小さな純粋関数を中心に構造化されています。 これにより、古い状態と新しい状態が誤って混在するのを防ぎます。 各関数は、更新されたグリッドとその更新されたディメンションの両方を返します。 

微妙な点は回転の処理です。回転の処理では、グリッドの形状が変化し、寸法をすぐに交換する必要があります。 もう 1 つは、ブラーとシャープが部分的に更新された出力グリッドではなく、常に元のグリッド スナップショットを使用するようにすることです。 

Shift はモジュラー演算を使用するため、大きなシフトや負のシフトが追加の正規化ロジックなしで正しくラップアラウンドされます。

 ## 特殊なケース

 一般的なエッジ ケースは、ブラーが均一なグリッドに適用される場合です。 すべての 3×3 近傍の合計は同じ値になるため、出力は同一のままでなければなりません。 定数合計を 9 で整数除算すると同じ定数が返され、ラップアラウンドによって近傍構成が変更されないため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、ラップアラウンドにより複数の等しい最大値が存在するグリッド上のシャープ化です。 この条件ではすべての隣接セルとの厳密な比較が必要なため、隣接セルと等しいセルは変更されません。 スナップショットベースの評価により、同時更新が干渉しないことが保証されます。 

回転エッジ ケースは、グリッドが正方形でない場合に発生します。 この実装では、次元を交換した新しいグリッドを明示的に作成し、n と m をすぐに再割り当てして、後続の操作で座標が正しく解釈されるようにします。
