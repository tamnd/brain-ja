 ## 解決策
 ## 問題の理解

 複数のカードのセットが与えられ、各カードにはクワイク番号と呼ばれる整数のラベルが付いています。 この初期コレクションから、最終的に非常に厳密な最終コレクションを作成したいと考えています。コレクションには、1 から選択した値 K までの各癖番号のカードが 1 枚だけ含まれ、それ以外は何も含まれていなければなりません。 それは同時に 2 つのことを意味します。 まず、1 から K の範囲のすべての整数が 1 回だけ存在する必要があります。 第二に、この範囲外の価値を持つカードを保持することは許可されません。 

コレクションを 2 つの方法で変更できます。 不足している固有番号はカードごとに B のコストで「購入」できます。 また、既存のカードを「下取り」して、操作ごとにコスト A で別のクインク番号に変換することもできます。 取引ではカードの数は変更されず、購入ではカウントが増加しますが、最終的な要件により、とにかくカードの数が K に一致することが強制されるため、事実上、すべてのカードが 1..K の個別の値になる必要があります。 

本当の目標は、K を選択し、どの既存のカードを保持するか、どのカードを変換するか、どの暗黙のターゲット値を購入するかを決定し、最終的な構造が最小コストの 1..K の完璧な接頭辞の置換になるようにすることです。 

制約は N ≤ 10^5 まで、値は 10^6 までであるため、高価な再計算を使用してすべての K を試行するソリューションは遅すぎます。 K 回の二次スキャンや周波数再構築の繰り返しでは、最悪の場合、約 10^10 の演算が必要になりますが、これは 1 秒では実現できません。 

重複が存在する場合、微妙なエッジケースが発生します。 たとえば、単一の値のコピーが多数ある場合、A が B よりも大きいかどうかに応じて、欠落している番号を購入するよりも余分に交換した方がよい場合があります。また、A > B の場合は、別のエッジ ケースが発生します。その場合、交換は購入よりも厳密に悪いため、最適なソリューションでは、必要な値とすでに一致しているカードを除くすべての既存のカードを効果的に無視する必要があります。 

## アプローチ

 素朴なアプローチは、ターゲット K を固定し、現在のマルチセットを正確に {1, 2, ..., K} に変換するコストを計算することです。 各 K について、すでに持っている 1..K が何枚あるか、不足しているカードが何枚あるか、必要な値に「変換」する必要がある追加のカードが何枚あるかを数えます。 これを K ごとに個別にシミュレートすると、各計算のコストは O(N) となり、N までのすべての K についてそれを実行すると O(N^2) が得られ、最悪でも約 10^10 の演算となり、明らかに遅すぎます。 

重要な観察は、問題の構造が K において単調であるということです。K が 1 増加するとき、新しい必要な値を 1 つ追加するだけです。 これは、すでに満たしている個別の必須値の数、および「無駄」または「余分」のカードの数に関する実行情報を維持できることを意味します。 周波数を追跡し、K を徐々に拡張すると、コスト構造は線形になります。 

もう 1 つの重要な簡素化は、貿易ルールからもたらされます。 既存の各カードは、ターゲット セットに一致する場合は保持するか、コスト A で変換できます。ただし、値が不足している場合は、追加のカードを変換するか、新しいカードを購入することができます。 これにより、値ごとの決定が作成されます。1..K の各数字について、正確に 1 つのコピーが必要であり、それを入手する最も安価な方法を選択します。つまり、既存の未使用のカードから (トレーディング チェーン経由)、または直接購入することです。 

これは古典的な貪欲な視点につながります。K を 1 から上に向かってスキャンし、現在所有している再利用できる「余剰」カードの枚数を維持し、各ステップで余剰を使用するか B を支払うかを決定します。余剰を使用した場合は A がかかります。 そうでない場合は、B を支払います。最良の戦略は、これまでに蓄積した余剰カードの数にのみ依存します。 

したがって、問題は、必要な位置ごとに常に最も安価な利用可能なソースを使用しながら、値の頻度を追跡し、増加するプレフィックス要件を維持することに帰着します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な再計算による K に対するブルート フォース | O(N^2) | O(N) | 遅すぎる |
 | 増分プレフィックス + 余剰追跡 | O(N log N) または O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず入力をクァーク番号の周波数マップに圧縮します。 これにより、任意の値に対して「すでに正しい」項目がいくつあるかがわかります。 

次に、ターゲット セット 1、2、3、... を順番に構築することをシミュレーションします。 

1. 割り当て可能な使用可能なカードの数を維持しながら、値をソートまたはその他の方法で必要な癖番号の昇順に 1 から反復します。 
2. 変数を維持する`surplus`、元の位置では必要ないが、別のものに変換できる、私たちが持っているカードを表します。 
3. 1 から始まる各値 i について、入力頻度テーブルに値 i を持つ少なくとも 1 枚のカードがすでにあるかどうかを確認します。 「はい」の場合、それを使用して余剰を (頻度[i] - 1) だけ増やします。これは、1 つのコピーだけが「自然に一致」として消費され、残りは柔軟なリソースになるためです。 
4.frequency[i] がゼロの場合は、他の場所から取得する必要があります。 余剰 > 0 の場合、余剰カードを 1 枚使用し、コスト A を支払って値 i に変換します。 それ以外の場合は、コスト B で直接購入する必要があります。 
5. 各 i のコストを累積し、停止が最適になるまで継続します。 より大きな K を追加すると、常に少なくとも B コストまたは A コストが追加されるため、続行することが有益でなくなったら停止します。実装では、これは安全な境界まで反復することによって処理されます。 
6. 答えは、すべてのプレフィックスにわたって観察される最小コストです。 

重要な不変条件は、ステップ i で、剰余が、1..i−1 の一意性制約に違反することなく再割り当てできる、以前に確認された追加カードの数を正確に正確に表すことです。 i に進むたびに、余剰を消費するか直接支払うかを最適に決定します。将来の決定は、余剰の規模以外の以前の解決方法に依存しません。 

再利用可能なエクストラの数を決定すると、各値 i は独立しているため、正確さがわかります。 各ステップでの貪欲な選択により、局所的なコストが最小限に抑えられ、将来のステップの実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())
    arr = list(map(int, input().split()))

    from collections import Counter
    freq = Counter(arr)

    surplus = 0
    cost = 0
    best = float('inf')

    # We try building prefix 1..K; K won't need to exceed N significantly
    for k in range(1, N + 2):
        if freq.get(k, 0) > 0:
            # use one, extras become surplus
            surplus += freq[k] - 1
        else:
            # need to create this value
            if surplus > 0:
                surplus -= 1
                cost += A
            else:
                cost += B

        best = min(best, cost)

    print(best)

if __name__ == "__main__":
    solve()
```この実装では、最初に度数テーブルを構築して、平均 O(1) 時間内に各クワイク番号のコピーが何個存在するかをクエリできるようにします。 次に、可能なプレフィックス長 K にわたって反復されます。 

各ステップで、値がすでに存在する場合は、1 つのコピーだけが無料で使用され、残りは後で変換できるため、余剰として保管されます。 価値が存在しない場合は、余ったカードを使用して変換する (コスト A) か、新しいカードを購入する (コスト B) ことで支払う必要があります。 追加の外部購入を避けることができるため、利用可能な場合は余剰を使用することを常に好みます。 

変数`best`すべてのプレフィックスにわたる最小コストを追跡します。 これが必要なのは、K をさらに拡張すると常にコストが増加するため、最適な K はプレフィックス進行の最小値として見つかるためです。

これは、すべてを購入するのではなく、複製 5 からの初期の余剰を後で再利用できる方法を示しています。

 ## 特殊なケース

 微妙なケースとして、重複によって余剰が生まれるものの、取引にコストがかかる場合が考えられます。 たとえば、A が大きい場合、購入する方が常に安いため、余剰は依然として生成されますが、使用されることはありません。 余剰は有益な場合にのみ消費されるため、アルゴリズムはこれを自然に処理します。 それ以外の場合は直接購入します。 

もう 1 つのエッジ ケースは、1 や 2 のような初期の数値が出現しない場合です。アルゴリズムはこれらのプレフィックスの購入を正しく強制し、コストを単調に累積します。これにより、K は常に順番に構築され、各ステップで評価されるため、K を早期にスキップすることは不可能になります。 

最後に、すべての数値がすでに 1 から始まる連続している場合、既存の最大値を超えるまで、大きなプレフィックスのコストはゼロのままであり、その時点で購入または変換が開始されます。 プレフィックスの最小値は、最適な停止点を正確に捕捉します。
