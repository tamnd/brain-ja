 ## 解決策
 ## 問題の理解

 それぞれが他から独立した短いテキスト メッセージのコレクションが与えられます。 すべてのメッセージについて、それが「戦闘」を表しているのか、それとも単なるカジュアルな会話を表しているのかを判断する必要があります。 

メッセージに、すべて文字「a」である少なくとも 3 つの連続した文字が含まれている場合、メッセージはバトルとみなされます。大文字と小文字は関係ありません。 これは、大文字と小文字の文字を同一のものとして扱うことを意味します。そのため、テキスト内に少なくとも 3 つの連続した「a」のような文字が連続する長さの連続がある限り、「aaa」、「Aaa」、「aAAAa」などのシーケンスはすべて適格となります。 

入力の各行を個別にチェックし、そのような部分文字列が存在するかどうかに応じて定型文を出力します。 

制約は小さく、各メッセージの長さは最大 100 文字で、メッセージの数が多い場合でも、メッセージごとの合計作業量は一定に制限されます。 これにより、文字列ごとの線形スキャンよりも重いものは即座に除外され、文字列ごとの二次動作さえも許容されますが、不要になります。 メッセージごとに 1 つのパスで十分です。 

主な微妙な点は、大文字と小文字を区別せずに「連続する a」を正しく定義し、「a」以外の文字が出現するたびにカウントを正しくリセットすることです。 

よくある間違いは、正規化せずに正確な小文字の「a」だけをチェックすることによって発生します。 たとえば、「AAA」は戦闘であるはずですが、大文字と小文字を区別するチェックでは誤って拒否されてしまいます。 

もう 1 つの微妙なエッジ ケースは、スペースまたは句読点にわたるストリークをリセットするのを忘れることです。 たとえば、「aa a aaaa」には末尾に 4 つの連続する有効な a が含まれていますが、プログラマーが誤ってすべてのスペースを間違ってリセットしたり、連続していないセグメントをマージしたりすると、カウントを間違える可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。文字列内の各位置について、ウィンドウを拡張して、大文字と小文字を正規化した後、すべて 'a' である少なくとも 3 つの連続する文字が見つかるかどうかを確認します。 開始インデックスごとに、実行を検出するために順方向にスキャンするには O(n) がかかり、すべてのインデックスに対してこれを実行すると、メッセージごとに O(n²) が得られます。 最大 100 文字であればこれでも快適に動作しますが、不必要なやりすぎです。 

重要な点は、すべての位置からスキャンを再開する必要がないということです。 同じキャラクター カテゴリの連続した実行のみを考慮します。 左から右にスキャンしながら、連続する「a」タイプの文字の実行カウントを維持すると、いずれかのランが長さ 3 に達するかどうかを 1 回のパスで判断できます。 これにより、問題は単純なストリーミング チェックに変換されます。つまり、ストリークを蓄積し、壊れたときにリセットし、最大ストリーク長を追跡します。 

問題の構造は基本的にランレングスに基づいているため、文字列を連続したセグメントに折りたたむことが最適です。 各文字は 1 回だけ処理され、状態は一定です。

 ## アルゴリズムのチュートリアル

 1. 大文字と小文字の違いが比較に影響しないように、メッセージ全体を小文字に変換します。 これにより、スキャン中に追加の条件ロジックなしで「A」と「a」を均一に処理できるようになります。 
2. カウンタの初期化`streak = 0`現在の連続する「a」文字の数を追跡します。 
3. 文字列を左から右にスキャンし、一度に 1 文字ずつ処理します。 各キャラクターは連続記録の継続または記録の破りに貢献します。 
4. 現在の文字が「a」の場合、インクリメントします`streak`1つずつ。 これにより、有効な文字の現在の連続セグメントが拡張されます。 
5. 現在の文字が「a」でない場合は、リセットします。`streak`連続性の要件が満たされていないため、ゼロになります。 
6. アップデート後`streak`, 3以上になっているか確認してください。 そうなった場合は、メッセージを直ちに戦闘として分類し、スキャンを早期に中止することができます。 
7. 連続 3 に到達することなくスキャンを終了した場合は、メッセージを戦闘ではないと分類します。 

早期停止はオプションですが、有効なセグメントが見つかると、それ以上の処理では答えを変更できないという事実と一致します。 

### なぜ効果があるのか

 文字列内の任意の位置で、`streak`は、その位置で終わる連続する「a」文字の現在のサフィックスの長さを正確に表します。 「a」以外の文字が出現するとすぐにリセットするため、常に現在のインデックスで終わる有効な連続セグメントがエンコードされます。 長さが 3 以上の有効な部分文字列は、いずれかのインデックスで終了する必要があります。`streak >= 3`したがって、そのような状態を検出することは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    for _ in range(n):
        s = input().rstrip("\n").lower()
        
        streak = 0
        found = False
        
        for ch in s:
            if ch == 'a':
                streak += 1
                if streak >= 3:
                    found = True
                    break
            else:
                streak = 0
        
        if found:
            print("Love is war!")
        else:
            print("Just friends <3")

if __name__ == "__main__":
    solve()
```ソリューションは各メッセージを読み取り、次を使用して正規化します。`.lower()`、単一の整数カウンターを維持します。 の`found`このフラグを使用すると、有効な実行が検出された場合に早期終了できます。 リセットする`streak`「a」以外の文字では連続性が維持されますが、これは中心的な要件です。 

実装の微妙な詳細は、改行文字のみを削除することです。 スペースはランを中断する意味のある文字であるため、スペースの削除は避けます。 もう一つ重要なポイントはパフォーマンスです`.lower()`文字ごとではなく文字列ごとに 1 回。これにより、文字ごとのループが最小限かつ効率的に保たれます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    n = int(sys.stdin.readline())
    for _ in range(n):
        s = sys.stdin.readline().rstrip("\n").lower()

        found = False
        for ch in s:
            if ch == 'a':
                streak += 1
                if streak >= 3:
                    found = True
                    break
            else:
                streak = 0
        
        output.append("Love is war!" if found else "Just friends <3")
    
    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、正規化後にのみ有効な実行を形成する大文字と小文字が混在した文字が文字列に含まれる場合です。 たとえば、入力「AaAaA」は下げると「aaaaa」になり、有効なストリーク 5 が生成されます。スキャン前に正規化が行われるため、アルゴリズムはこれを処理し、ストリーク数は均一な表現で計算されます。 

もう 1 つのケースは、有効な文字がスペースまたは句読点で区切られている場合です。 たとえば、「aa aaaa」は、「a」が 4 つ続くため、戦闘になるはずです。 スキャン中に、スペースによってストリークが 0 にリセットされ、最後のセグメントでストリークが正しく再構築され、4 に達すると条件がトリガーされます。 

3 番目のケースは、「hello world」など、「a」がまったく含まれない文字列です。 ストリークは全体を通してゼロのままで、早期終了は発生せず、正しく非戦闘分類が生成されます。
