 ## 解決策
 ## 問題の理解

 基本文字列が与えられています`s`長さの`N`、各位置には関連する重みがあります。`a_i`。 この文字列から、アルファベットの文字のサブセットを選択することで文字を「消去」できます。 選択したすべての文字がどこでも置き換えられます`s`ドットを使用して新しい文字列を生成します`t`。 

スコアは、表示されたままのすべてのポジションの重みの合計として開始されます。`t`、文字がドットに置き換えられなかった位置を意味します。 それに加えて、それぞれにペナルティ値を持つパターン文字列のコレクションが与えられます。 これらのパターンのいずれかが連続した部分文字列として現れるたびに、`t`、スコアからペナルティを差し引きます。 

タスクは、最終スコアが最小になるようにどの文字を消去するかを選択することです。また、結果の文字列を 1 つ出力する必要があります。`t`この最小限を達成します。 

構造上の重要な点は、決定がポジションごとではなくキャラクターごとにグローバルであるということです。 文字を消去することを選択した場合は、文字が表示されているすべての場所からその文字を削除します。`s`。 これは、インデックスごとの決定ではなく、アルファベットに基づくサブセットの選択を直ちに示唆します。 

重要な点での制約は非常に小さいです。決定に含まれる個別の文字の数は最大 26 です。これは、文字のサブセットに対する総当り攻撃が実行可能であることを意味します。$2^{26}$境界線にありますが、枝刈りまたはパターン上のより構造化された DP を使用すれば許容されます。 ただし、重要な観察は、文字だけが含まれているという事実から来ています。`s`案件; 入力の説明により制限されます`s`小さなアルファベットのサブセットに分割され、有効な決定空間がさらに小さくなります。 

単純なアプローチでは、文字のすべてのサブセットを試して、`t`、重みの合計を計算し、すべての部分文字列のパターン一致をチェックします。 この最後のステップがボトルネックです。サブセットごとの部分文字列チェックが発生します。$O(2^K \cdot N^2 \cdot M)$、これは大きすぎます。 

局所的な利益によって貪欲に文字を消去しようとすると、さらに微妙な問題が発生します。 パターンが重なり、ペナルティが非線形に相互作用するため、1 つの文字を削除すると、複数のパターンの複数の出現が同時に破壊される可能性があるため、局所的な貪欲な決定は失敗します。 

強調する価値のあるエッジケースには次のようなものがあります。 

- 文字は消去されません: ゼロ ドットと完全なパターンの一致を正しく処理する必要があります。 
- すべての文字が消去されます: 重み付けによりスコアは 0 になりますが、解釈によってはパターンがすべてドットの文字列と一致する可能性があります。 
- 重複するパターン: 単一の文字を削除すると、重複する複数の出現が破壊される可能性があり、単純なカウントでは誤って二重カウントされる可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、文字のすべてのサブセットが考慮されます。 サブセットごとに、結果の文字列を構築します。`t`スコアを直接計算します。 構造は単純です。選択した文字をドットに置き換え、残りの位置からの寄与を合計します。 次に、各パターンのすべての部分文字列をスキャンします。 

これは正しいですが、非効率的です。 建設中`t`費用$O(N)$、重みの合計は$O(N)$、およびすべてのパターンにわたる部分文字列の一致にはコストがかかります$O(N \cdot M)$慎重に実行した場合、またはさらに悪い場合はサブセットごとに$O(N^2 \cdot M)$。 まで$2^{26}$サブセットの場合、これは不可能になります。 

重要な観察は、決定空間がサブセットごとに任意ではないということです。 代わりに、各文字は独立して基本スコアに寄与しますが、パターンのペナルティは、パターン内のすべての文字が生き残るかどうか (点線で打たれていないか) にのみ依存します。 これにより、問題は、パターンが文字の組み合わせに制約や報酬を課す、文字に関する古典的なサブセット DP に変換されます。 

部分文字列を明示的にシミュレートする代わりに、特定のサブセットの下でどのパターンが生き残るかを事前計算し、それらの寄与を効率的に計算します。 遷移は、文字列の長さではなく、アルファベットのサイズでのみ指数関数的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^K \cdot N^2 \cdot M)$|$O(N)$| 遅すぎる |
 | 最適 |$O(2^K \cdot (N + M))$|$O(2^K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 に現れるそれぞれの文字を個別に扱います。`s`それを保持するか消去するかの二者択一の決定として。 させて`K`内の異なる文字の数になります`s`。 

1. 各文字を次のようにマッピングします。`s`のインデックスに`[0, K)`。 これにより、任意のサブセットをサイズのビットマスクとして表すことができます。`K`。 
2. 各文字を保持することによる基本寄与を事前計算します。 あらゆるポジションについて`i`、指定されたマスクでその文字が消去されない場合、次を追加します。`a_i`。 この寄与は文字ごとに集計できるため、サブセットごとに完全な文字列を再スキャンする必要はありません。 
3. パターンごとに`r_j`に含まれる文字のセットを特定し、`s`。 サブセット内の必要な文字が消去されている場合、パターンは表示されません。`t`全然。 それ以外の場合は、その寄与を考慮する必要があります。 これにより、パターンの評価が、ビットマスクが事前計算されたパターン マスクのスーパーセットであるかどうかをチェックすることになります。 
4. すべてのマスクを列挙します。`0`に`2^K - 1`。 マスクごとに、次を計算します。 

保持された文字の重みの合計から、パターン マスクがマスクに完全に含まれているすべてのパターン コストを差し引きます。 
5. 最高のスコアを追跡し、対応するマスクを記憶します。 
6. 再構築`t`最適なマスクでビットが設定されていない文字をドットに置き換えることによって。 

重要な計算上のトリックは、パターンの有効性がビットマスクのサブセットの包含チェックとなり、部分文字列の列挙が完全に排除されることです。 

### なぜ効果があるのか

 このアルゴリズムは、すべての決定を文字が消去されたかどうかに集約し、スコアの両方のコンポーネントがその構造上できれいに分解されます。 重み項は文字の出現ごとに加算され、パターン項は位置ではなく必要な文字の存在のみに依存します。 これにより、単調な依存関係が作成されます。文字が消去されると、それを必要とするすべてのパターンが同時に消え、サブセット マスクによって完全にキャプチャされます。 考えられるすべての構成が 1 回だけ列挙され、それぞれが一貫して評価されるため、見つかった最小値が全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()
    a = list(map(int, input().split()))

    patterns = []
    for _ in range(m):
        r, c = input().split()
        c = int(c)
        patterns.append((r, c))

    # compress letters appearing in s
    letters = sorted(set(s))
    idx = {ch: i for i, ch in enumerate(letters)}
    k = len(letters)

    # weight per letter
    weight = [0] * k
    for i, ch in enumerate(s):
        weight[idx[ch]] += a[i]

    # pattern masks
    pmask = []
    for r, c in patterns:
        mask = 0
        for ch in r:
            if ch in idx:
                mask |= 1 << idx[ch]
            else:
                # character not in s, cannot match anyway
                mask = -1
                break
        if mask != -1:
            pmask.append((mask, c))

    # precompute letter contributions
    best = float('inf')
    best_mask = 0

    for mask in range(1 << k):
        score = 0

        # base score
        for i in range(k):
            if mask & (1 << i):
                score += weight[i]

        # subtract patterns
        for pm, c in pmask:
            if (pm & mask) == pm:
                score -= c

        if score < best:
            best = score
            best_mask = mask

    # reconstruct string
    res = []
    for ch in s:
        i = idx[ch]
        if best_mask & (1 << i):
            res.append(ch)
        else:
            res.append('.')

    print(best)
    print(''.join(res))

if __name__ == "__main__":
    solve()
```実装ではまず次のアルファベットを圧縮します。`s`そのため、サブセットはビットマスクとしてコンパクトに表現されます。 すべての位置の重みを文字ごとの合計に集約し、列挙中の繰り返しスキャンを回避します。 

パターンは同じアルファベットのビットマスクに変換されます。 パターンに存在しない文字が含まれている場合`s`、変換後は決して貢献できないため、無視しても問題ありません。 

列挙中に、各マスクは保持される合計の重みを計算し、必要な文字セットがマスクに完全に含まれているすべてのパターンを減算します。 このサブセット チェックは、部分文字列の一致を完全に置き換えます。 

最後に、再構築では選択したマスクを単純に反映し、除外された文字をドットに置き換えます。

 ## 特殊なケース

 重要なエッジケースは、文字が消去されない場合です。 この場合、マスクはいっぱいになるため、元の文字列に出現するすべてのパターンをカウントする必要があります。 完全なマスクはすべてのサブセット チェックを満たすため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、すべての文字が消去される場合です。 再構築された文字列は完全にドットになります。 少なくとも 1 文字を必要とするパターン`s`マスクは常に含まれるため、一致することはできませんが、すべてのドットの部分文字列にはパターンの意味のある文字が含まれていないと解釈されます。 この実装では、サブセット ロジックを均一に適用することにより、一貫した動作が保証されます。 

最後の微妙なケースは、パターンに存在しない文字を含むパターンです。`s`。 これらのパターンは変換後は決して出現しないため、早期に除外されます。 これにより、不正なペナルティ減算が防止され、状態空間の一貫性が維持されます。
