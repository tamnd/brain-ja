 ## 解決策
 ## 問題の理解

 私たちは「生息地」の動的なコレクションを維持しています。各生息地には複数の名前付きドラゴンが保存されており、各ドラゴンには固有のサイズ値があります。 システムは、長期にわたって 2 つの操作をサポートします。 1 回の操作で新しいドラゴンを選択した生息地に挿入します。 もう 1 つの操作では、特定の生息地について、現在どのドラゴンのサイズが最も小さく、どのドラゴンが最も大きいかを尋ね、それらの名前を返します。 

重要な詳細は、生息地が段階的に進化するということです。 各クエリは、以前のすべての挿入後の状態を反映します。 削除はないため、各生息地のドラゴンのセットは増加するだけです。 

サイズが小さくても (最大 100)、操作の数は多くなる可能性があります。 これは、多くのドラゴンが 1 か所に蓄積されている場合、クエリごとに生息地内のすべてのドラゴンを繰り返しスキャンするのはコストがかかることをすぐに示唆しています。 最悪のパターンは、数千匹のドラゴンを 1 つの生息地に挿入し、最小値と最大値を繰り返し要求することです。これにより、毎回フル スキャンが強制されます。 

単純なアプローチでは、要求するたびに生息地全体を再構築または再スキャンすることになります。 同じ生息地に多くのドラゴンが蓄積すると、これは失敗します。各クエリが現在のサイズで線形になり、全体として二次的な動作が発生するためです。 

ここで問題となるエッジケースは、主に、繰り返されるクエリと偏った分布に関するものです。 たとえば、すべての操作が単一の生息地をターゲットにしている場合:

 入力:```
5
add A a 1
add A b 2
add A c 3
ask A
ask A
```単純な解決策では、保存されているすべてのドラゴンをスキャンし、同じ作業を 2 回繰り返すことで、毎回最小値と最大値を再計算する可能性があります。 それは依然として正しいですが、大規模になると非効率的です。 

もう 1 つの微妙なケースは、サイズが非常に小さいにもかかわらず、名前が識別性を決定する場合です。 名前は一意であるため、名前による並べ替えや、挿入順序の安定性を前提とすることはできません。 サイズのみが順序を定義します。 

## アプローチ

 ブルートフォース戦略では、生息地ごとに、到着したすべてのドラゴンのリストを保存します。 のために`add`、レコードを追加します。 のために`ask`、リスト全体をスキャンして、サイズごとの最小値と最大値を見つけます。 これは正しいです。なぜなら、すべてのクエリが順序を最初から明示的に再計算し、常に最新の極端な値を返すことが保証されるからです。 

ただし、それぞれ`ask`コストは O(k) で、k はその時点でその生息地にいたドラゴンの数です。 すべての操作が 1 つのハビタット上で行われ、その半分がクエリである場合、最悪の場合、総コストは O(n^2) になります。これは、n が大きい場合には遅すぎます。 

重要な観察は、完全な秩序は決して必要なく、生息地ごとに 2 つの極値要素だけが必要であるということです。 これは、これらの極端な値を段階的に維持することを示唆しています。 要素を再計算する代わりに、要素を挿入するときに現在の最小値と最大値を追跡します。 挿入ごとに最大 2 つの比較が更新されます。 これにより、すべての操作が O(1) に削減されます。 

また、これらの極端な環境に関連付けられたドラゴンの名前を保存する必要があるため、生息地ごとに保存される状態では、現在の最適な候補のサイズと名前の両方を保持する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは生息地名をキーとした辞書を管理しています。 各値には、現在の最小ドラゴン (サイズと名前) と現在の最大ドラゴンの 2 つのレコードが保存されます。 

1. 空のマップを生息地名から最小値と最大値を未定義として保持する構造に初期化します。 

これにより、最初の使用時に生息地が遅延して作成されることが保証されます。 
2. それぞれについて`add`操作により、生息地名、ドラゴン名、サイズを抽出します。 

生息地が存在しない場合は、最小値と最大値の両方をこのドラゴンに初期化します。 
3. 生息地がすでに存在する場合は、新しいドラゴンのサイズを保存されている最小値と比較します。 小さい場合は最小レコードを更新します。 

これにより、保存された最小値が常にこれまでに確認された最小値であるという不変条件が維持されます。 
4. 新しいドラゴンのサイズを保存されている最大サイズと比較します。 それより大きい場合は、最大レコードを更新します。 

これにより、各挿入後に最大値が正しいままになります。 
5. それぞれについて`ask`操作では、保存されている最小名と最大名を直接出力します。 

構造は常に最新に保たれるため、スキャンは必要ありません。 

### なぜ効果があるのか

 あらゆる時点で、各生息地には、これまでに確認されたすべてのドラゴンを要約する正確に 2 つの値、つまりサイズによる最小値とサイズによる最大値が保存されます。 すべての挿入は 1 回だけ処理され、新しいドラゴンがどちらかの極端に影響を与える可能性がある場合は、すぐに更新されます。 ドラゴンを削除したりサイズを変更したりする操作は存在しないため、一度値が最小値または最大値になると、後でより極端な値が表示されない限り、その値が維持されます。 これにより、保存されたペアがクエリ時に常に正しいことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    habitats = {}

    for _ in range(t):
        parts = input().split()
        if parts[0] == "add":
            _, h, name, size = parts
            size = int(size)

            if h not in habitats:
                habitats[h] = {
                    "min_name": name,
                    "min_size": size,
                    "max_name": name,
                    "max_size": size
                }
            else:
                cur = habitats[h]

                if size < cur["min_size"]:
                    cur["min_size"] = size
                    cur["min_name"] = name

                if size > cur["max_size"]:
                    cur["max_size"] = size
                    cur["max_name"] = name

        else:
            _, h = parts
            cur = habitats[h]
            sys.stdout.write(cur["min_name"] + " " + cur["max_name"] + "\n")

if __name__ == "__main__":
    solve()
```このソリューションでは、辞書を使用してすべての州を生息地名ごとにグループ化します。 各生息地には候補ドラゴン 2 体のみが保存されるため、メモリ使用量は挿入数に比例して変化します。 

更新ロジックでは、最小値と最大値のサイズを個別に比較するよう注意が払われています。 生息地への最初の挿入時には、同じドラゴンが同時に最小値と最大値の両方になる可能性があるため、この分離は重要です。 

出力は次を使用して書き込まれます`sys.stdout.write`繰り返しの print 呼び出しによるオーバーヘッドを避けるため。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各操作は、生息地ごとの一定時間の状態を更新または読み取ります。 
| スペース | O(h) | 2 頭のドラゴンを保存する生息地ごとに 1 つのレコード |

 この制約により、最大 100 の操作が可能になりますが、より大きくスケールしても、このソリューションは線形で効率的です。 一定時間の更新により、高密度の操作下でもボトルネックが発生しません。

        parts = input().split()

 ## 特殊なケース

 重要なエッジケースは、生息地の最初のドラゴンが最小値と最大値の両方である場合です。 アルゴリズムは両方のフィールドをそのドラゴンに対して初期化するため、状態はすぐに一貫します。 

入力：```
2
add x a 7
ask x
```実行により最小値と最大値の両方が (a, 7) に設定され、クエリによってそれらが直接読み取られ、次の結果が生成されます。`a a`。 

もう 1 つのケースは、新しいドラゴンが時間の経過とともに新しい最小値または最大値の両方になる場合です。 

入力：```
4
add h a 5
add h b 1
add h c 10
ask h
```ステップ 2 の後、b は min になります。 ステップ 3 の後、c は最大になります。 この構造は両方を独立して正しく追跡するため、最終的な答えは次のようになります。`b c`。 

最後の微妙なケースは、追加を介さずに繰り返し質問されます。 クエリ中に再計算が行われないため、繰り返される出力は同一のままであり、クエリ操作時に状態が変化しないという要件と一致します。
