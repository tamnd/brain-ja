 ## 解決策
 ## 問題の理解

 モンスターの列が与えられ、それぞれにプラスまたはマイナスのパワー値が与えられます。 サイタマはこれらのモンスターの連続するセグメントを選択し、正確にそのグループを倒すことができます。 選択したセグメントの強度は、そのセグメント内のすべての値の合計であり、タスクは、すべての連続するセグメントにわたって可能な最大のセグメント合計を見つけることです。 

入力は最大 100,000 の長さの単一の配列で、各値はマイナス 10 億の小さい値から 10 億の大きい値まで可能です。 出力は単一の整数であり、連続する部分配列から得られる最良の合計です。 

n に対する制約により、すべての部分配列を明示的に試行するソリューションは即座に除外されます。 すべての (i, j) ペアにわたる二重ループでは、最悪の場合でもすでに約 10^10 の演算が発生します。これは 1 秒で処理できる量をはるかに超えています。 これにより、私たちは線形または線形に近い解決策に向かうことになります。 

すべての数値が負の場合、微妙なエッジケースが発生します。 たとえば、入力の場合`[-5, -2, -8]`、正解は`-2`、単一の要素を選択することから来ます。 答えをゼロとして初期化するか、「すべてをスキップ」できると想定する単純な実装では、空の部分配列で明示的に許可されていない限り、ゼロは有効な部分配列の合計ではありませんが、この問題では許可されていませんが、誤ってゼロを返します。 

もう 1 つのエッジ ケースは、単一要素の配列です。この場合、答えは、たとえ負であっても、その要素自体でなければなりません。 これは、正しい初期化を強調します。 

## アプローチ

 ブルートフォース手法は簡単です。考えられるすべての部分配列を考慮し、その合計を計算し、最大値を追跡します。 開始インデックス i ごとに、すべての j ≥ i まで拡張し、合計を段階的に累積します。 これは、すべての有効な連続セグメントを直接評価するため、正しいです。 ただし、セグメントの数は n(n+1)/2 で、プレフィックスの累積を再利用すると、各合計更新は O(1) になり、合計作業量は依然として O(n^2) になります。 n が 10^5 までの場合、これは実行不可能になります。 

重要な観察は、左から右にスキャンするときに、各位置で、前のセグメントを延長することが有益であるかどうか、または現在の位置で新たに開始する方が良いかどうかのみを気にすることです。 現在の合計が負になった場合、それを維持しても将来の拡張の寄与が減るだけなので、現在の要素から再開するのが最適です。 これにより、グローバルな最適化の問題が各インデックスでのローカルな決定に変わり、まさに線形スキャンが可能になります。 

これにより、各位置で終了する実行中の最良のプレフィックスを維持し、これらの値のグローバル最大値を追跡するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 (Kadane のアルゴリズム) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つの値を維持しながら、配列を左から右に処理します。現在位置で終わる最良の部分配列の合計と、これまでに確認された全体的な最良の答えです。 

1. 累計を配列の最初の要素に初期化します。 これにより、少なくとも 1 つの要素を選択する必要があるため、すべての数値が負の場合を正しく処理できるようになります。 
2. 開始時の最良の部分配列はその 1 つの要素のみであるため、グローバル最良の回答を同じ値に初期化します。 
3. 2 番目の要素から始めて配列を繰り返します。 
4. 各要素 p[i] で、前の部分配列を拡張するか、i から新たに開始するかを決定します。 延長とは p[i] を累計に加算することを意味しますが、再起動はそれを破棄して累計を p[i] に設定することを意味します。 
5. 決定は、p[i] と running_sum + p[i] を比較することによって行われます。 前回の合計が負の場合は、再起動する方が良いでしょう。 それ以外の場合は、延長することが有益です。 
6. 累計を更新した後、累計が大きい場合はグローバル応答を更新します。 
7. 反復が終了すると、全体的な答えは部分配列の合計の最大値になります。 

機能する理由: すべてのインデックス i において、アルゴリズムは i で終わる必要がある最適なサブ配列を維持します。 i で終わるサブ配列は、i-1 で終わる有効なサブ配列の拡張から得られるか、i 自体で始まります。 以前の寄与がマイナスの場合、将来の合計を減らすだけであるため、それを破棄しても将来の最適な選択が悪化することはありません。 この局所的な最適性により、すべてのエンドポイント間でグローバルな最大値が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    arr = list(map(int, input().split()))
    
    current = arr[0]
    best = arr[0]
    
    for i in range(1, n):
        current = max(arr[i], current + arr[i])
        best = max(best, current)
    
    print(best)

if __name__ == "__main__":
    solve()
```このソリューションは配列を 1 回読み取り、2 つの実行変数を維持します。 キーラインはトランジションです`current = max(arr[i], current + arr[i])`、再開または延長の決定をエンコードします。 変数`best`どこで終わるかに関係なく、これまでに確認された最良の部分配列の合計を追跡します。 

初期化には注意が必要です。 両方を設定する`current`そして`best`最初の要素に追加すると、すべての数値が負の場合でも正確さが保証され、誤ってゼロに初期化されることがなくなります。

import sys, io

    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 次のような単一要素入力の場合`[-7]`、アルゴリズムが初期化されます`current`そして`best`に`-7`、つまり直接出力します`-7`ループに入らずに。 これにより、空のサブ配列が選択される可能性があるという誤った仮定が回避されます。 

次のようなすべて負の配列の場合`[-5, -2, -8, -1]`、拡張すると常に合計が悪化するため、アルゴリズムは各位置で繰り返し再起動されます。 現時点での最高のアップデート`-2`インデックス 1 で、その後はドロップされず、正しい最小マイナス要素が答えとして生成されます。
