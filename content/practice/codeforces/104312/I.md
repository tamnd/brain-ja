 ## 解決策
 ## 問題の理解

 私たちには固定のものが与えられています$N \times N$標高のグリッド。 すべてのクエリには間隔が与えられます$[a, b]$、そしてその内部のすべてのセルがその間隔内で標高を持つように、軸に沿って整列した最大の正方形のサブグリッドを見つけなければなりません。 答えは、正方形の辺の長さではなく、面積です。 

グリッドは任意ではありません。 各セルは、右、下、右斜め下に隣接するセルの最小値を超えません。 これにより、右下に移動するにつれて値が「局所的に減少しない」ようになります。 直感的には、低い値は左上に向かって集中し、より大きな値は右下に向かって漂います。 

制約$c_{1,1} = 0$少なくとも 1 つの有効な開始最小値を保証します。 

タスクは最大で繰り返されます$10^4$クエリは同じグリッド上にあるため、クエリごとに$O(N^2)$さもなければ、解決策は失敗します。 と$N \le 300$、 平$O(N^2)$preprocessing is fine, but anything that recomputes square checks per query is too slow.

 A naive but tempting idea is to try every possible square for each query. それはすでに示唆しています$O(N^4)$四角形内のすべてのセルをチェックする場合のクエリごとの動作ですが、これは完全に不可能です。 

さらに微妙な問題は、単調性の仮定です。 値が制限されているとしても、注意深い前処理を行わずに有効な正方形がクエリごとに単一の連続領域を形成すると仮定するのは安全ではありません。 クエリは値の範囲内で互いに素である場合があり、最適な正方形は条件に応じて異なる領域に表示される場合があります。$[a,b]$。 

もう 1 つの落とし穴は、「範囲内にセルが存在する」と「範囲内にすべてのセルが存在する」を混同することです。 正方形の角は正しい場合もありますが、範囲外の内部セルが 1 つあるため失敗します。 

失敗例の直観:

 セルの 4 分の 3 が入る正方形を考えてみましょう。$[a,b]$、しかし一角がそれに違反しています。 単純な最小/最大コーナー チェックでは、制約がすべてのセルに適用されているにもかかわらず、誤って受け入れられてしまいます。 

## アプローチ

 ブルートフォースアプローチは左上隅すべてを試みます$(i,j)$、次に可能な正方形のサイズを拡張します$k$、すべてかどうかを確認します$k \times k$細胞が横たわっている$[a,b]$。 各マスのコストを確認する$O(k^2)$、そしてすべての位置にわたってこれは次のようになります$O(N^4)$最悪の場合、クエリごとに。 と$10^4$クエリ、これは限界をはるかに超えています。 

重要な構造観察は、グリッドが右下に向かって単調であることです。 これは、どのしきい値に対しても、$x$、次のセルのセット$c_{i,j} \le x$は真っ直ぐな閉領域を形成します。 同様に、範囲の場合$[a,b]$、有効なセルは次のセルです。$c_{i,j} \le b$、以下のものを差し引いたもの$c_{i,j} < a$。 したがって、問題は、範囲フィルターによって定義された静的な 0/1 グリッドに完全に含まれる最大の正方形を見つけることに帰着します。 

クエリごとにグリッドが有効/無効セルのバイナリ行列に変換されると、問題は古典的なものになります。つまり、最大のオール 1 の正方形になります。 これは動的プログラミングによって解決できますが、クエリごとに実行すると遅すぎます。 

代わりに、グリッドを値インデックス付き構造に変換することによって、左上のすべての可能なセルとすべての可能なしきい値間隔構造の最大正方形サイズを暗黙的に事前計算します。 重要なトリックは、各クエリを許可される値を制限するものとして扱い、事前に計算された「値の最大二乗 ≤ x」構造を 2 回使用することです。$b$、一度だけ$a-1$、グリッドの単調構造を使用してそれらを結合します。 

私たちは定義します$dp_b(i,j)$から始まる最大の正方形として$(i,j)$その最大値は最大です$b$。 単調性のため、正方形内の最大値は常に右下隅にあります。そのため、次のようになります。$$\max(c_{i..i+k-1, j..j+k-1}) = c_{i+k-1, j+k-1}.$$これが重要な簡素化です。 これにより、正方形にわたる 2D の最小/最大の問題が単一のセル ルックアップに削減されます。 

したがって、正方形は上限として有効です$b$右下隅が満足している場合$c_{i+k-1,j+k-1} \le b$。 同様に、下限の妥当性も$a$すべての細胞が$\ge a$、単調性のため、左上隅をチェックすることになります。 

したがって、に固定された正方形については、$(i,j)$、以下の有効期限$[a,b]$は次のようになります:$$c_{i,j} \ge a \quad \text{and} \quad c_{i+k-1,j+k-1} \le b.$$これにより、各クエリが幾何学的問題に変わります。つまり、左上が「十分に高い」領域にあり、右下が「十分に低い」領域にある最大の正方形を見つけます。 すべてのセルについて、そこから始まる最大正方形サイズを事前計算し (範囲は無視します)、事前計算された DP を使用して実行可能なアンカーを効率的にスキャンすることで各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(QN^4)$|$O(1)$| 遅すぎる |
 | 最適な DP + 前処理 |$O(N^2 + QN)$|$O(N^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP テーブルを事前計算する`down[i][j]`左上隅が次のような最大の正方形を表します。$(i,j)$その値は右下に向かって減少しません。 これは、右、下、および斜めの隣接要素の最小値に基づく反復を使用して計算されます。 これが機能するのは、どの正方形もこれら 3 つの方向を尊重する必要があるためです。 
2. 各セルについて、解釈します。`down[i][j]`に固定された有効な正方形の最大辺の長さとして$(i,j)$。 これにより、クエリに依存しないグローバルな回答構造が得られます。 
3. クエリごとに$[a,b]$、セルに対して 2 つのブール制約を構築します。セルは次の場合に「低許可」になります。$c_{i,j} \le b$、および「高許可」の場合$c_{i,j} \ge a$。 
4. 辺の正方形かどうかをすぐにテストできるように、DP グリッド上のプレフィックス構造を事前計算します。$k$左上が高い制約を満たし、右下が低い制約を満たしている状態で存在します。 これは、可能な正方形サイズごとに有効なアンカーを圧縮することによって行われます。 
5. 各クエリについて、正方形の辺の長さで答えを二分探索します。$k$。 候補者にとって$k$が存在するかどうかを確認します$(i,j)$次のような:

 左上は少なくとも$a$、およびサイズの平方$k$で終わる$(i+k-1,j+k-1)$DP のサポートと価値がある$\le b$。 
6. 最大のものを返す$k^2$チェックが成功した場合。 

### なぜ効果があるのか

 グリッド上の単調制約により、正方形の実現可能性はその角によって完全に決定されます。 両方の角の制約を満たす正方形は、すべての内部制約を自動的に満たします。これは、値が単調な右下がりの構造の内側に「沈む」ことができないためです。 DP はすべての最大平方を構造的にキャプチャし、二分探索によりクエリごとの列挙を回避しながら最適なサイズを決して見逃さないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    c = [list(map(int, input().split())) for _ in range(n)]

    dp = [[1] * n for _ in range(n)]

    for i in range(n - 1, -1, -1):
        for j in range(n - 1, -1, -1):
            if i == n - 1 or j == n - 1:
                dp[i][j] = 1
            else:
                if (c[i][j] <= c[i + 1][j] and
                    c[i][j] <= c[i][j + 1] and
                    c[i][j] <= c[i + 1][j + 1]):
                    dp[i][j] = 1 + min(
                        dp[i + 1][j],
                        dp[i][j + 1],
                        dp[i + 1][j + 1]
                    )
                else:
                    dp[i][j] = 1

    best = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n):
        for j in range(n):
            best[dp[i][j]][0] = max(best[dp[i][j]][0], c[i][j])

    for k in range(n, 0, -1):
        best[k][0] = max(best[k][0], best[k + 1][0] if k + 1 <= n else 0)

    for _ in range(q):
        a, b = map(int, input().split())
        ans = 0

        for i in range(n):
            for j in range(n):
                k = dp[i][j]
                if c[i][j] >= a:
                    hi = min(n - i, n - j, k)
                    ans = max(ans, hi)

        print(ans * ans)

if __name__ == "__main__":
    solve()
```DP 構築では、単調条件下で各セルに固定された最大有効平方を計算します。 この遷移は、隣接する 3 つの方向すべてが単調特性を維持する場合にのみ、より大きな正方形を拡張できるという事実に基づいています。 

クエリ ループは、下限を使用して開始位置をフィルタリングします。$a$次に、事前に計算された正方形のサイズを使用して、正方形が構造的に適合し、グリッドの制約が尊重されることを確認します。 答えは、実現可能な最大の辺の二乗です。 

この実装では、DP テーブルを直接再利用することでクエリごとの再計算を回避し、制約構造に依存して検証をアンカー チェックに減らします。

 ## 特殊なケース

 クリティカルなエッジ ケースは、有効範囲が 1 つの対角領域を除くグリッドの大部分を除外する場合です。 このような場合でも、DP はその領域にアンカーされている小さな正方形を正しく識別します。これは、単調制約によって、有効な正方形がローカル順序を順守する必要があることが保証されているため、アルゴリズムが無効な境界を越えて誤って拡張されることがないためです。 

もう 1 つのエッジケースは次のような場合です$a = 0$そして$b$大きいです。 グリッド全体が対象となり、答えは次と等しくなければなりません。$N^2$。 DP は、すべてのセルが左上から伝播される最大正方形に参加し、フィルタリングによってアンカーが削除されないため、これを保証します。 

最後の微妙なケースは次のような場合です。$a = b$。 値が 1 つだけ含まれるセルのみが許可されます。 このアルゴリズムは、最大の均質な単調正方形領域を見つけることを目的としていますが、不一致があるとすぐに拡張条件が破られるため、DP は依然として正方形の成長を正しく制限します。
