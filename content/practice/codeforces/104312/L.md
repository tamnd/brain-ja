 ## 解決策
 ## 問題の理解

 私たちにはチップの山が 3 つ与えられます。 各ターンで、プレイヤーはちょうど 1 つの山からその山のサイズまでの正の数を選択してチップを取得するか、3 つの山すべてから同時に同じ正の数のチップを取得しますが、最小の山のサイズまでのみを取得するグローバル ムーブを実行することができます。 

プレイヤーは交互に動き、ライトは常に開始します。 最後のチップを取ったプレーヤーが勝ちです。つまり、すべての山がゼロになる位置が、移動したばかりのプレーヤーの勝ちの最終状態になります。 

つまり問題は、トリプルの小さな状態空間における 2 人用の完全情報ゲームです。$(a,b,c)$、そして開始プレイヤーが強制勝利を持っているかどうかを判断する必要があります。 

制約は非常に小さく、各パイル サイズは最大 50 です。これにより、完全な状態空間には最大でも 50 個のものが含まれることがすぐにわかります。$51^3 = 132651$状態は、動的プログラミングまたはメモ化された再帰を使用した完全なゲーム グラフ検索には十分小さいです。 

自明ではない難しさは 2 番目のタイプの動きです。 プレイヤーは 3 つのパイルすべてを同じ量だけ減らすことができ、これによりパイルが結合され、独立した Nim ヒープへの単純な分解が防止されます。 

いくつかの特殊なケースで構造を説明します。 

すべての山が 0 の場合、現在のプレイヤーには移動がないため、入力のように答えは負けになります。`0 0 0`。 

1 つの山だけがゼロでない場合は、次のようにします。`0 0 1`、プレーヤーはその最後のチップをすぐに受け取って勝つことができます。 

より微妙なケースは、`1 2 3`。 直感は多くの手を示唆するかもしれませんが、サンプルに示されているように、最適なプレイは最初のプレーヤーの負けにつながります。 

「常に最大の山から取る」などの素朴な貪欲な考えは失敗します。なぜなら、世界的な動きは、局所的な推論を無効にする方法で国家を再形成する可能性があるからです。 

## アプローチ

 問題を解決する直接的な方法は、それを各状態が含まれるゲーム グラフとして扱うことです。$(a,b,c)$はノードであり、有効な移動はそれぞれ別のノードに遷移します。 少なくとも 1 つの手が負けポジションにつながる場合、そのポジションは勝ちであり、すべての手が勝ちポジションにつながる場合は負けです。 

これは、メモ化による再帰的定義を示唆しています。 州から$(a,b,c)$では、すべての単一パイル リダクションとすべての有効なグローバル リダクションを試し、結果の状態を再帰的に評価します。 各パイルは最大 50 個であるため、状態の総数は制限されており、各状態は最大で 50 個に分岐します。$O(50 + 50)$トランジションがあり、全体で最大数百万のトランジションが発生します。 それはすでに十分に速いです。 

ただし、大掛かりな検索を必要としない、より明確な構造観察があります。 グローバルな移動により、すべての杭が効果的に均等に削減されます。つまり、多くの遷移では杭間の相対的な違いのみが問題となります。 これは、ゲームが、対称性と小さな境界によって最適化なしでも完全な DP が十分になる、制約された公平なゲームのように動作することを示唆しています。 

したがって、すべての州にわたってメモ化された DFS に落ち着きます。

 ## アルゴリズムのチュートリアル

 関数を定義します`win(a, b, c)`現在のプレイヤーがその状態から勝利を強制できるかどうかを返します。 

1. ソートによる状態の正規化$(a,b,c)$これにより、同等の構成が同じ状態にマップされます。 これにより、パイルの順列によって引き起こされる冗長な計算が削減されます。 
2. すべての山がゼロの場合は、負けを返します。 利用可能な手がないため、現在のプレイヤーは勝つことができません。 
3. 山ごとに、削除してみてください。$k$チップどこ$1 \le k \le$パイルサイズ。 移動した後、その結果の位置が相手にとって負けているかどうかを再帰的に確認します。 そのような手が存在する場合、現在の状態を勝利としてマークします。 
4. 最小の山の値を計算します。$m = \min(a,b,c)$。 それぞれについて$k$1から$m$、削除をシミュレートします$k$3 つの山すべてから同時にチップを取り出し、結果の状態が負けているかどうかを再度確認します。 そのような動きが負けポジションにつながる場合は、現在の状態を勝ちとしてマークします。 
5. 考えられるどの手が負けポジションにならない場合は、現在の状態を負けとしてマークします。 

各トリプルの結果をメモ化し、各状態が 1 回だけ計算されるようにします。 

### なぜ効果があるのか

 すべての状態は、有限の非循環ゲーム グラフにおける最適なプレイに基づいて分類されます (すべての動きが厳密にチップの合計を減少させるため)。 再帰ではすべての正当な手を調査し、勝利条件は標準のミニマックス ルールに一致します。つまり、負けている状態への遷移が少なくとも 1 回ある場合にのみ、状態は勝利しています。 メモ化により、共有部分問題間の一貫性が保証され、移動するたびにチップの総数が減少するため、終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

from functools import lru_cache

@lru_cache(None)
def win(a, b, c):
    a, b, c = sorted((a, b, c))
    if a == b == c == 0:
        return False

    # single pile moves
    piles = [a, b, c]
    for i in range(3):
        for take in range(1, piles[i] + 1):
            nxt = list(piles)
            nxt[i] -= take
            nxt.sort()
            if not win(nxt[0], nxt[1], nxt[2]):
                return True

    # global moves
    m = min(a, b, c)
    for take in range(1, m + 1):
        nxt = [a - take, b - take, c - take]
        nxt.sort()
        if not win(nxt[0], nxt[1], nxt[2]):
            return True

    return False

def main():
    a, b, c = map(int, input().split())
    print("Yes" if win(a, b, c) else "No")

if __name__ == "__main__":
    main()
```実装の中核はメモ化されたものです`win`関数。 すべての状態を並べ替えると、次のような順列が保証されます。`(1,2,3)`そして`(3,2,1)`は同一に扱われるため、対称ブランチの冗長な探索が防止されます。 再帰ではすべての正当な手を試します。最初にすべての可能な方法で 1 つの山を減らしてから、同時の減少の動きを適用します。 

基本ケースは空の状態を処理します。 メモ化キャッシュがないと、同じサブゲームが異なる動きシーケンスで何度も再計算されることになるため、メモ化キャッシュは不可欠です。 

## 実用的な例

 ### 例 1:`0 0 1`| 状態 | 移動タイプ | 結果の状態 | 勝つ？ |
 | --- | --- | --- | --- |
 | (0,0,1) | 3番目の山から1を取る | (0,0,0) | 負ける |

 唯一利用可能な手は最終状態に直接つながります。 その状態は次のプレイヤーの負けなので、現在の状態は勝ちです。 

これは、チップが 1 枚あるポジションはすぐに勝つというルールを裏付けています。 

### 例 2:`1 2 3`| 状態 | 移動タイプ | 結果の状態 | 対戦相手の結果 |
 | --- | --- | --- | --- |
 | (1,2,3) | さまざまな単一の動き | 複数の状態 | 相手のすべての勝利 |
 | (1,2,3) | グローバルで 1 削減 | (0,1,2) | 相手の勝利 |
 | (1,2,3) | グローバルで 2 削減 | (0,0,1) | 相手の勝利 |

 利用可能なすべての動きは、対戦相手がまだ勝利戦略を持っている状態に移行します。 したがって、元の状態は負けています。 

これは、盤面を簡素化する手が存在するとしても、それらのどれもが相手に負ける局面を作り出すものではないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(513 · 150) | 各状態は 1 回計算され、各状態は最大 150 個の遷移をチェックします。 
| スペース | O(513) | メモ化テーブルは状態ごとに 1 つの値を格納します。 

513 は約 130,000 の状態にすぎないため、境界は十分に小さく、完全に拡張されたゲーム グラフの走査でも制限内に快適に収まります。

 ## 特殊なケース

 オールゼロの状態`0 0 0`は基本ケースとして直接処理されます。 手が存在しないため、関数はすぐに負けを返し、前のプレイヤーがすでに最後のチップを取得したという事実と一致します。 

次のような単一の非ゼロパイルケース`0 0 1`単一パイル除去のループには、ちょうど 1 つのチップを取り込み、ターミナルの負け状態に直接移行することが含まれるため、勝ちになります。 

対称性の高いケース`2 2 2`ソートによって自動的に正規化されるため、すべての順列が 1 つのメモ化された状態にまとめられます。 このアルゴリズムはすべてのグローバル削減を評価し、少なくとも 1 つの手が対戦相手の負け構成につながることを検出し、冗長な探索を行わずに正しい分類を保証します。
