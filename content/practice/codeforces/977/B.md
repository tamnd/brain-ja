 ## 解決策
 ## 問題の理解

 一連の英大文字が与えられ、その中の隣接する文字のペアをすべて見るように求められます。 このような隣接する各ペアは「2 文字パターン」を形成します。たとえば、文字列「ABAC」には「AB」、「BA」、および「AC」が含まれます。 

タスクは、これらの 2 文字のパターンのうち、連続する部分文字列として最も頻繁に現れるものを見つけることです。 部分文字列は連続した位置で定義されるため、当然重複が許可されるため、「AAA」のようなパターンには「AA」が 2 回含まれます。 

出力はカウントそのものではなく、最大周波数を達成する任意のパターンです。 複数のパターンが一致する場合は、どれか 1 つを選択しても問題ありません。 

入力サイズは小さく、最大でも 100 文字です。 このことから、隣接するペアの総数はわずか n−1、最大でも 99 であるため、二次推論でも十分であることがすぐにわかります。 

微妙な点は、考えられるすべての 26×26 パターンを個別に検索しているわけではないということです。 文字列内に隣接する部分文字列として実際に現れるものだけを考慮します。 これにより、入力にまったく存在しない可能性がある「ZZ」のようなパターンに関する曖昧さが解消されます。 

エッジケースは主に短い文字列に関するものです。 n = 2 の場合、2 グラムが 1 つだけ存在し、それを返す必要があります。 「AAAAA」のようにすべての文字が同じ場合、正解は「AA」となり、重複して複数回出現します。 不注意な実装では、オカレンスの重複を排除したり、重複しないものとして処理しようとしたりする可能性がありますが、これは正しくありません。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべての位置のペア (i, j) を取得し、s[i:i+2] が他のすべての部分文字列の出現と一致するかどうかをチェックすることです。 これにより、O(n²) 個の候補が生成され、各候補に対してさらに O(n) 回のスキャンが行われ、結果は O(n³) になります。 n が小さいとしても、これはこのような直接計数タスクには不必要であり、概念的に扱いにくいものです。 

より自然な総当たり攻撃は、長さ 2 のすべての部分文字列を生成し、辞書を使用してそれらをカウントすることです。 これにより、問題は n−1 個の要素にわたる頻度カウントに縮小されます。 各部分文字列の抽出は O(1) であるため、合計の複雑さは n で線形になります。 

重要な観察は、私たちがグローバルなものや長距離構造に依存したものを構築していないということです。 すべての有効な答えはローカルの隣接関係によって完全に決定されるため、単一のパスで十分です。 これにより、問題は固定サイズのペアのストリーム内の頻度をカウントすることに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 + 再比較 | O(n3) | お(1) | 遅すぎる |
 | 隣接するペアのスライディング数 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 0 から n−2 までの各インデックス i を考慮して文字列を左から右に走査し、2 文字の部分文字列 s[i]s[i+1] を抽出します。 このステップでは、問題を重複する観察のストリームに変換します。 
2. 各 2 文字パターンがこれまでに何回出現したかを記録する頻度マップを維持します。 新しい部分文字列ごとにカウンタがインクリメントされます。 
3. スキャン中に、現在最適なパターンとその頻度を追跡します。 パターンの頻度がこれまでの最高を超えた場合、最高のパターンと最高のカウントの両方を更新します。 
4. すべての隣接するペアを処理した後、保存されている最良のパターンを出力します。 

スキャン中に安全に答えを貪欲に更新できる理由は、将来の更新は将来のペアにのみ依存し、カウントは増加するだけだからです。 以前は最適だったペアが無効になったり、頻度が減少したりするシナリオはありません。 

### なぜ効果があるのか

 2 グラムの出現はそれぞれ独立しており、サイズ 2 の固定ウィンドウによってのみ決定されます。 アルゴリズムは、そのような各ウィンドウを 1 回だけカウントします。 周波数マップには正確なカウントが保存され、すべての観測値の最大値が常に維持されるため、最終的に保存されるペアはグローバル最大値の 1 つである必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    freq = {}
    best = ""
    best_cnt = 0

    for i in range(n - 1):
        pair = s[i:i+2]
        freq[pair] = freq.get(pair, 0) + 1

        if freq[pair] > best_cnt:
            best_cnt = freq[pair]
            best = pair

    print(best)

if __name__ == "__main__":
    solve()
```この解決策では、文字列に対して 1 回のパスを使用します。 部分文字列の抽出`s[i:i+2]`スライス長が固定されているため、一定時間になります。 辞書は正確な頻度を維持し、厳密に大きなカウントが観察された場合にのみ最適なペアが更新されるため、2 回目のパスを必要とせずに決定的な動作が保証されます。 

よくある間違いは、n−1 ではなく n まで反復することです。これにより、範囲外の部分文字列にアクセスしようとします。 もう 1 つは、重複するペアが有効であることを忘れていることです。これは、すべてのインデックスがそのインデックスから始まる 1 つのペアにのみ寄与するため、ここでは自然に処理されます。

 ## 特殊なケース

 「XY」などの長さ 2 の文字列の場合、ループは 1 回だけ実行されます。 ペアは「XY」のみなので、頻度1で即答となります。 

「AAAAA」などの繰り返し文字の場合、各インデックスは「AA」に寄与するため、カウントは 4 に累積します。アルゴリズムは出現箇所の重複を排除しようとしません。 観測される各ウィンドウを単純にインクリメントします。 

「ABABAB」のような交互文字列の場合、「AB」と「BA」の両方が複数回出現します。 アルゴリズムは厳密な増加が発生するたびに最適な値を更新するため、最大値に達した最初のペアが有効な出力のままになります。
