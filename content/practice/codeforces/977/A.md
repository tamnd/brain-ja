 ## 解決策
 ## 問題の理解

 このタスクでは、正の整数を繰り返し減らす非常に具体的な方法を説明します。 通常の算術的な意味で単純に 1 を引くのではなく、演算は数値の最後の桁に応じて行われます。 数値がゼロ以外の数字で終わる場合、数値は通常どおりに動作し、1 ずつ減ります。 ゼロで終わる場合、数値の値は直接減少しませんが、最後の桁が完全に減ります。これは 10 で割ることと同じです。 

初期整数 n と演算数 k が与えられます。 各操作では上記のルールに従って数値が変換され、そのような変換を正確に k 回適用した後に最終的な値を決定することが目標となります。 

n ≤ 10^9 という制約は、数値が最大 10 桁であることを意味します。 演算回数ｋは最大でも５０回と極めて少ない。 これにより、k ステップにわたる線形スキャンでさえ簡単であるため、単純なシミュレーションを超える最適化の必要性が即座に排除されます。 

単純な間違いは、演算が常に 1 を減算するものと解釈することです。 たとえば、100 から開始すると、単純なアプローチでは 1 ステップ後に 99 が生成されますが、正しい操作では末尾の 0 が削除され、10 が生成されます。もう 1 つの微妙な間違いは、文字列と整数の間で間違った変換を繰り返したり、数字を削除すると数値の大きさが完全に変わることを忘れたりすることです。これは後続のステップに影響します。 

数値の末尾に複数のゼロが含まれる場合、エッジ ケースが発生します。 たとえば、1000 から開始して 1 つの演算を適用すると、999 ではなく 100 が得られます。もう 1 つのエッジ ケースは、繰り返しゼロを削除すると桁数が急速に減少し、その後の演算の動作が大幅に変化する場合です。 

## アプローチ

 ブルートフォース手法では、ルールが k 回直接適用されます。 各ステップで最後の桁がチェックされ、1 が減算されるか、10 で除算されます。 k は最大 50 であるため、このアプローチは実際にはすでに最適であり、さらに最適化する必要はありません。 

重要な観察は、ローカルな数字操作を超える隠れた構造はないということです。 各操作は現在の最後の桁のみに依存し、各変換の後、次のステップでの正確性が維持されるように数値が変更されます。 プロセス自体はすでに小さな k によって制限されているため、事前計算や数学的ショートカットは必要ありません。 

したがって、最適な解決策は、単に説明どおりにプロセスをシミュレーションすることです。

 ## アルゴリズムのチュートリアル

 1. 入力から整数 n と k を読み取ります。 n の値は現在の作業番号、k は適用される変換の数です。 
2. 各反復は Tanya の操作の 1 つのアプリケーションを表すため、次のプロセスを正確に k 回繰り返します。 
3. n % 10 を使用して n の最後の桁を確認します。これにより、数値の残りの部分に影響を与えることなく単位の位が分離されます。 
4. 最後の桁がゼロ以外の場合は、n から 1 を減算します。 これは、10 進数表現での通常の減分に対応します。 
5. 最後の桁が 0 の場合は、整数除算を使用して n を 10 で除算します。 これにより、最後の桁が完全に削除され、桁数が減少します。 
6. k 回の反復をすべて完了した後、結果の n の値を出力します。 

### なぜ効果があるのか

すべてのステップで、アルゴリズムは数値の現在の状態に適用される正確な変換ルールを反映します。 演算は最後の桁のみに依存し、各変換後に結果の数値が次の演算の新しい有効な状態になります。 各ステップは独立しており、現在の値によって完全に決定されるため、追加の履歴は必要ありません。 変換のシーケンスは決定的であるため、順番にシミュレーションすると、最終的な値が必要なプロセスと一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

for _ in range(k):
    if n % 10 == 0:
        n //= 10
    else:
        n -= 1

print(n)
```このソリューションは、初期数値を読み取り、k 個の変換を繰り返し適用します。 条件`n % 10 == 0`末尾のゼロのルールを直接実装します。 整数の除算`//= 10`この場合、最後の桁が削除されますが、他のすべての場合は減算によって処理されます。 

ループは正確に k 回実行され、過剰処理を行わずに正確性が保証されます。 k が小さいため、追加の最適化は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k) | 各操作は一定時間のチェックと更新を k 回適用します。 
| スペース | お(1) | 単一の整変数のみがその場で更新されます。 

この制約により k ≤ 50 が保証されるため、実行時間は事実上一定になります。 最悪の場合でも、このソリューションは最大 50 回の単純な算術演算を実行しますが、これは制限時間内では取るに足らないものです。 

## テストケース```python
import sys, io

def solve():
    n, k = map(int, sys.stdin.readline().split())
    for _ in range(k):
        if n % 10 == 0:
            n //= 10
        else:
            n -= 1
    print(n)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided sample
assert run("512 4\n") == "50\n", "sample 1"

# minimum case
assert run("10 1\n") == "1\n", "single division"

# all non-zero digits
assert run("999 3\n") == "996\n", "simple decrements"

# multiple trailing zeros
assert run("1000 2\n") == "10\n", "repeated digit removal"

# boundary small number
assert run("2 1\n") == "1\n", "small decrement"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 10 1 | 1 | 1 桁の削除 |
 | 999 3 | 996 | 通常のデクリメントチェーン |
 | 1000 2 | 10 | 繰り返しゼロストリッピング |
 | 2 1 | 1 | 最小減少の場合 |

 ## 特殊なケース

 エッジ ケースの 1 つは、数値が複数のゼロで終わる場合に発生します。 入力用`1000`k = 2 の場合、最初の演算では除算で 100 に減算され、2 番目の演算では別の除算で 10 に減ります。 構造が変更された後、各反復で最後の桁が再評価されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、プロセスの早い段階で数値が 1 桁になる場合です。 たとえば、10 から開始すると、最初の演算で 1 が生成され、後続の演算では引き続き安全に減算または除算が行われます。 ループは固定桁長を想定していないため、数値が動的に縮小しても正しいままです。 

最後のエッジ ケースは、n が 1001 など、10 の累乗境界のすぐ上にある場合です。減算シーケンスによりすぐに末尾の 0 が作成され、その後除算が行われます。 各ステップは常に現在の状態をチェックするため、減算と除算の間の遷移は、特別な場合のロジックを必要とせずに常に正しく処理されます。
