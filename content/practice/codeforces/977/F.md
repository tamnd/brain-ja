 ## 解決策
 ## 問題の理解

 整数のシーケンスが出現順に与えられます。 このシーケンスから、順序を維持しながらいくつかの要素を選択したいと考えていますが、保持できるのは、ステップごとに正確に 1 ずつ増加する連続した整数の連続のように見えるサブシーケンスのみです。$x, x+1, x+2, \dots$。 タスクは、そのような最長のサブシーケンスを見つけて、その長さと選択した要素の元の位置の両方を出力することです。 

主な問題は、値が必ずしも一意ではなく、並べ替えられていないため、値空間内の連続セグメントを直接スキャンできないことです。 元の順序を尊重する必要があるため、これは値ベースの遷移を伴うインデックスに関する動的計画法の問題になります。 

入力サイズは最大です$2 \cdot 10^5$これにより、要素の二次ペアが除外されます。 すべてのペアを比較したり、サブシーケンスを単純に拡張しようとしたりするソリューションには、次のような処理が含まれます。$n^2$最悪の場合、動作が非常に遅くなります。 これにより、ハッシュまたはマップを使用した線形または線形に近いアプローチが必要になります。 

値が何度も繰り返される場合、微妙なエッジケースが発生します。 たとえば、配列が次の場合、$[5, 5, 5, 5]$、連続した構造を形成できないため、有効なサブシーケンスは長さ 1 のみを持つことができます。 等しい値を連鎖させようとしたり、厳密な +1 遷移を強制できなかったりする単純な貪欲なアプローチでは、このような場合に誤って過剰カウントが発生します。 

もう 1 つの注意が必要な状況は、値構造は同じだがインデックスの選択が異なる複数の有効なチェーンが存在する場合です。 たとえば、$[3, 3, 4, 4]$、チェーン$3 \to 4$はさまざまな出現を使用して形成できますが、長さを計算するだけでなく、インデックスの有効な部分列を回復する必要があります。 

## アプローチ

 ブルートフォース戦略は、すべての開始位置を考慮し、その後のすべての要素をスキャンして次に必要な値を探してチェーンを前方に拡張しようとすることです。 開始するたびに、次の値を繰り返し検索します。$x+1$、 それから$x+2$、 等々。 リニア スキャンを使用する場合でも、各開始点でアレイの別のフル スキャンがトリガーされる可能性があり、$O(n^2)$最悪の場合の行動。 と$2 \cdot 10^5$要素があれば、これは完全に不可能です。 

重要な観察は、ある値にあるとき、$v$、チェーンを拡張するために必要な唯一の有用な情報は、 value で終わる最適なチェーンです。$v-1$。 これは、値ごとに、その値で終わる最適なサブシーケンスの長さを維持することを示唆しています。 配列を左から右に処理すると、$a[i]$で終わるチェーンを延長できます$a[i]-1$したがって、で終わる最適なチェーンを計算できます。$a[i]$ハッシュマップを使用して定数時間で。 

値ごとに 2 つの情報を保存します。その値で終了するチェーンの最適な長さと、ソリューションを再構築できるように、そのチェーンが最後に発生したインデックスです。 繰り返しながら、これらのマップを更新し、これまでに確認された最良のエンドポイントを追跡します。 

これにより、問題は辞書検索による配列の 1 回のパスに軽減され、比較における二次依存関係が線形時間ハッシュに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | ハッシュマップを使用した最適な DP |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 3 つのハッシュ マップを維持します。1 つは値で終わる最適な長さ用、もう 1 つはチェーンを再構築するために使用される先行インデックス用、そして 1 つは各値の最適な出現のインデックスを追跡するためです。 

1. 配列を左から右に走査し、位置にある各要素を処理します。$i$。 各ステップで価値を考慮します$v = a[i]$。 
2. で終了できる最適なチェーンを計算します。$v$。 これは、次で終わる最適なチェーンを調べることで得られます。$v-1$。 そのようなチェーンが存在しない場合は、長さ 1 の新しいチェーンを開始します。有効な連続サブシーケンスは各ステップで正確に 1 ずつ増加する必要があるため、このステップは機能します。 
3. から延長する場合$v-1$以前に記録されたどのチェーンよりも長いチェーンが得られます。$v$の最適な長さを更新します。$v$そしてそれを記録します$i$～の最良の終了インデックスです$v$。 からのポインタも保存します$i$最高のチェーンを達成したインデックスに戻る$v-1$。 
4. すべての要素を処理した後、すべての値をスキャンして、最大チェーン長の値を見つけます。 
5. 保存されている最良の値の終了インデックスから開始して、開始点に到達するまで先行インデックスを繰り返したどることによってサブシーケンスを再構築します。 

再構成ステップが必要なのは、スキャン中に長さを最適化しているものの、実際の位置を正しい順序で復元する必要があるためです。 

### なぜ効果があるのか

 核となる不変条件は、すべての値に対して$v$で終わる可能な限り最良のサブシーケンスを常に維持します。$v$これまでに処理されたすべてのプレフィックスの中で。 次の発生を処理するとき$v$、で終わる任意の最適なサブシーケンス$v$で終わる最適なサブシーケンスから取得する必要があります。$v-1$有効なチェーンは各ステップで正確に 1 ずつ増加する必要があり、値をスキップできないためです。 常にそのような最良のサブシーケンスを保存するため、より良い拡張子を見逃すことはありません。 これにより、スキャンの終了までに、値エントリの 1 つに最適なグローバル サブシーケンスが完全にキャプチャされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

best_len = {}
prev_idx = {}
best_end_idx = {}

ans_val = 0
ans_end = -1

for i, v in enumerate(a):
    prev_len = best_len.get(v - 1, 0)
    cand_len = prev_len + 1

    if cand_len > best_len.get(v, 0):
        best_len[v] = cand_len
        best_end_idx[v] = i
        if v - 1 in best_end_idx:
            prev_idx[i] = best_end_idx[v - 1]
        else:
            prev_idx[i] = -1

        if cand_len > ans_val:
            ans_val = cand_len
            ans_end = i

res = []
cur = ans_end

while cur != -1:
    res.append(cur + 1)
    cur = prev_idx.get(cur, -1)

res.reverse()

print(ans_val)
print(*res)
```コードの主な構造は、各要素が値からチェーンを拡張しようとする配列に対する 1 回のパスです。$v-1$。 の`best_len`辞書には各値の最適な部分列の長さが格納されますが、`best_end_idx`その最良のサブシーケンスがどこで終わるのかを覚えています。 の`prev_idx`ディクショナリは再構築のみに使用され、インデックスをチェーン内のその先行者にマッピングします。 

実装の微妙な詳細は、値の最もよく知られているチェーンを改善する場合にのみ状態を更新することです。 これにより、最適ではない中間状態による再構築ポインタの破損が回避されます。 もう 1 つの重要な点は、スキャン中にグローバル最良終了インデックスを追跡するため、エンドポイントを見つけるために 2 回目のパスが必要ないことです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、有用なチェーンがすでに形成された後に表示される値の繰り返しです。 たとえば、次のような配列では、$[1, 2, 3, 2, 3]$、後ほど$2, 3$ペアは、以前のインデックスで終了する長いチェーンを上書きしないでください。 厳密に適切な長さが見つかった場合にのみ更新が行われるため、アルゴリズムはこれを処理します。そのため、より短いチェーンまたは等しいチェーンは無視されます。 

もう 1 つのケースは、値が大きくてまばらな場合です。$[100, 1, 2, 3]$。 マップベースの遷移では、次のことのみが保証されます。$v-1$したがって、中間値が欠落していると、特別なケースを使用せずにチェーンが正しく切断され、長さ 1 で再起動されます。 

最後のケースは、最適な答えが複数存在する場合です。 有効なサブシーケンスのみが必要なため、保存された先行ポインタは任意の最適なパスを表すことができ、再構築によって正しいインデックス シーケンスが生成されます。
