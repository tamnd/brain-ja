 ## 問題の理解

 整数のリストが与えられ、値を構築するように求められます。$x$1との間$10^9$まさにそのようなこと$k$リストの要素が以下である$x$。 そのような値が存在しない場合は、出力する必要があります。$-1$。 

これについて考えるのに役立つ方法は、$x$数直線上のしきい値を定義します。 として$x$要素数が増えると$\le x$増加するだけで、減少することはありません。 このカウントが正確になる点を見つけようとしています。$k$。 

入力サイズは最大で$2 \cdot 10^5$数字。 すべての候補者をチェックするあらゆるアプローチ$x$範囲内に直接$[1, 10^9]$までが必要となるため、不可能です。$10^9$操作。 素朴な方法で各配列要素を繰り返しチェックしたとしても、約$O(n^2)$最悪の場合、制限時間を大幅に超えて作業が行われる可能性があります。 

重要なエッジ ケースは、配列内の複数の値が境界付近で等しい場合に発生します。 選ぶなら$x$配列内の値、要素の数に等しい$\le x$一度に複数のジャンプを実行する可能性があります。 たとえば、配列が次の場合、$[3, 3, 3]$そして$k = 2$、ありません$x$ちょうど 2 つの要素が得られます$\le x$、カウントは 0 からジャンプするため ($x < 3$) 3 に直接 (for$x \ge 3$）。 

もう一つの微妙なケースは、$k = 0$。 これには、$x$すべての要素よりも小さい。 以来$x \ge 1$、これはすべての配列値が 1 より大きい場合にのみ可能です。$x = 1$いずれかの要素が 1 に等しいかどうかによって、機能する場合と機能しない場合があります。

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 これにより、プレフィックス数を直接推論することができます。 
2. もし$k = 0$、すべての要素より厳密に小さい値が必要です。 最小の要素をチェックします。 1 の場合は無効です$x \ge 1$存在するので出力します$-1$。 それ以外の場合は、要素がゼロであることが保証されるため、1 を出力します。$\le x$。 
3. もし$k = n$、すべての要素を次のようにしたいと考えています。$\le x$。 最大の要素が常に機能するため、配列の最大値を出力します。

6. 異なる場合は、$k$-th 要素を答えとして。 これは正確に保証します$k$要素は$\le x$。 

### なぜ効果があるのか

 ソート後の要素数$\le x$は、個別の配列値でのみ増加するステップ関数です。 選択する$x$に等しい$k$- 番目に小さい値により、少なくとも$k$要素が含まれています。 次の個別の値が厳密に大きい場合、そのギャップが終わるまで追加の要素は入力されないため、カウントは正確に残ります。$k$。 重複によってギャップが崩れると、ステップ サイズが大きくなりすぎて、正確な均等化が不可能になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    if k == 0:
        if a[0] == 1:
            return "-1"
        return "1"
    elif k == n:
        return str(a[-1])
    else:
        x = a[k - 1]
        if a[k] == x:
            return "-1"
        return str(x)

# provided sample
assert run("7 4\n3 7 5 1 10 3 20") == "5"

# all equal impossible case
assert run("5 2\n2 2 2 2 2") == "-1"

# k = 0 valid
assert run("3 0\n5 6 7") == "1"

# k = n case
assert run("4 4\n1 2 3 4") == "4"

# boundary duplicate-safe
assert run("6 3\n1 2 2 3 4 5") in {"2"}

# minimum size
assert run("1 1\n10") == "10"

 ## 特殊なケース

 すべての要素が等しい場合、および$k$が 0 または n ではない場合、両者の間の等価性チェックが行われないため、アルゴリズムはそのケースを正しく拒否します。$a[k-1]$そして$a[k]$すぐに失敗します。 たとえば、入力$[5, 5, 5]$と$k = 1$につながる$a[0] = 5$そして$a[1] = 5$したがって、有効なしきい値は存在しません。 

のために$k = 0$、アルゴリズムにより、1 より小さい値が選択されないことが保証されます。最小の要素が 3 の場合、出力 1 は要素をゼロにします。$\le x$。 最小の要素が 1 の場合、有効な要素はありません$x$は許容範囲内に存在するため、正しく出力されます$-1$。 

境界用$k = n$の場合、並べ替えでは最後の要素が最大であることが保証されるため、これを選択すると、重複がある場合でも、過剰にカウントされることなくすべての要素が含まれます。
