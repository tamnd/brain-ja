 ## 解決策
 ## 問題の理解

 元々は、Polycarp が繰り返し変換した単一の開始値から得られた整数のマルチセットが与えられています。 各変換では、現在の数値が 2 倍になるか、割り切れる場合は 3 で除算されます。 これらの操作を正確に適用した後、$n-1$結果を観察します$n$番号はありますが、その順序は失われています。 

タスクは、連続するすべてのペアが許可された遷移の 1 つに従うように、これらの数値の有効な順序を再構築することです。次の数値は前の数値の 2 倍であるか、前の数値が 3 で割り切れて次の数値がその商になります。 

重要な点は、操作をシミュレートすることを求められるのではなく、固定セットを並べ替えて、2 の乗算と 3 の除算 (有効な場合) によって定義される有向グラフの下で有効なパスを形成するように求められることです。 

制約の数は少ないため、$n \le 100$ただし、値は次のように大きくできます。$3 \cdot 10^{18}$。 これにより、値に対して密な状態グラフを構築したり、数値範囲に対して動的プログラミングに依存したりするアプローチは即座に除外されます。 代わりに、これらの変換が整数に対してどのように動作するかという構造的特性に依存する必要があります。 

微妙な失敗例は、数値から有効な「次のステップ」が複数存在する場合に現れます。 たとえば、12 のような値から、24 と 4 の両方が入力セットに存在する可能性があります。 たとえ有効な完全なシーケンスが存在していても、単純に貪欲な選択をすると間違った方向を選択し、後で行き詰まってしまう可能性があります。 もう 1 つの問題は、シーケンスが単調であるか数値的にソートされている必要があると仮定していることですが、これは誤りです。3 による除算では順序付けが完全に崩れます。 

## アプローチ

 強引な解釈では、指定された数値のすべての順列を試し、隣接するペアが変換ルールを満たすかどうかを確認します。 これは有効性の定義に直接一致するため概念的には正しいですが、検索空間は次のようになります。$n!$、たとえそれが不可能になる$n = 30$、ましてや100。 

変換の構造により、ハンドルがより強力になります。 各数値には、最大 2 つの発信エッジを含めることができます。$2x$そして一つは$x/3$割り切れるなら。 This forms a directed graph where each node has very limited degree. The sequence we want is effectively a Hamiltonian path in this graph, but the guarantee that an answer exists means the graph is not arbitrary. It is generated from a single chain under reversible transformations.

 重要な観察は、3 による除算が数値を減らす唯一の演算であり、割り算に依存する唯一の演算でもあるということです。 これは、チェーンの「エンドポイント」が制約されていることを意味します。有効な開始要素とは、セット内で他の要素を 2 倍したり 3 で割ったりしても到達できない要素です。 

This allows us to identify a starting point by checking which number has no predecessor under the allowed transformations. Once the start is fixed, the rest of the sequence becomes deterministic: at each step, we simply try to go to either$2x$または$x/3$、セット内に存在するもの。 

ブルートフォースは遷移の指示された構造を無視するため失敗します。 最適なアプローチにより、セットによって暗黙的に定義された関数グラフ内にリンクされたパスを構築するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$ハッシュを使用した平均 |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. O(1) メンバーシップ クエリのハッシュ セットにすべての数値を格納します。 これは、変換された値が入力に存在するかどうかを繰り返しテストするために必要です。 
2. 各候補値を確認して開始番号を特定します。 セット内の他の数値が 2 による乗算または 3 による除算によってその数値に移行できない場合、その数値は有効な開始値となります。 これにより、暗黙的なチェーンの途中ではなく、ルートから開始することが保証されます。 
3. 開始番号が見つかったら、その番号で出力シーケンスを初期化し、セットから削除します。 
4. シーケンスを繰り返し拡張します。 現在の値から$x$、どうかを確認してください$2x$セット内に存在します。 もしそうなら、そこに移動してください。 それ以外の場合は、$x$は 3 で割り切れ、$x/3$セット内に存在します。 もしそうなら、そこに移動してください。 構造の構造上、これらのうちの 1 つが有効になります。 
5. すべての要素が消費されるまで続けます。 

これが機能する理由は、最初の要素を除き、有効な構造内のすべての数値がチェーン内に 1 つの先行要素を持っているという事実に関係しています。 これらの操作は決定的な隣接関係を定義し、入力セットはこの関係に基づく単一の接続されたチェーンに対応します。 これにより、開始点が正しく選択されると、すべてのステップが強制的に前進し、あいまいさがなくなり、すべての要素が 1 回だけアクセスされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = set(a)

    # find starting point: number with no predecessor
    start = None
    for x in a:
        has_pred = False
        if x % 2 == 0 and (x // 2) in s:
            has_pred = True
        if x * 3 in s:
            has_pred = True
        if not has_pred:
            start = x
            break

    res = [start]
    s.remove(start)
    cur = start

    while s:
        if cur * 2 in s:
            cur = cur * 2
        else:
            cur = cur // 3
        res.append(cur)
        s.remove(cur)

    print(*res)

if __name__ == "__main__":
    solve()
```この実装は、ハッシュ セットに依存して、考えられる両方の遷移の定時チェックを保証します。 開始選択ループは、セット内の別の番号から番号に到達できるかどうかを明示的にチェックするため、推測が回避されます。 

再構築ループは意図的に貪欲ですが安全です。構造が単一のチェーンであることを前提としているため、各ステップで残りのセットに有効なサクセサーが 1 つだけ存在します。 セットからの削除は、ノードの再訪問を防ぎ、線形トラバースを強制するため重要です。 

よくある間違いは、先行チェックでは両方の演算を対称的に考慮する必要があることを忘れていることです。2 による乗算と 3 による除算は、逆のようなエッジですが、割り切れる場合のみです。

 ## 特殊なケース

 微妙なケースの 1 つは、複数のノードが有効な開始点であるように見える場合です。 たとえば、次のような小さなチェーンでは、`3 6 12`、3 と 12 の両方に非対称接続があります。 このアルゴリズムは、先行ノードのないノードを選択することでこの問題を解決し、内部点ではなく真のルートからトラバースが開始されるようにします。 

もう 1 つの特殊なケースは、3 による除算が頻繁に利用できる場合です。 のような入力の場合`81 27 9 3 1`、単純な貪欲なアプローチでは、存在する場合は早期に 2 倍にしようとする可能性がありますが、2 倍が存在しないため、アルゴリズムは正しく繰り返し除算に戻り、厳密に減少する有効なチェーンを生成します。 

最後のエッジケースは、次のような大きな値を保証することです。$3 \cdot 10^{18}$2 倍してもオーバーフローしません。 Python では、これは任意精度の整数なので安全ですが、他の言語では、慎重な 128 ビット処理または乗算の前の条件チェックが必要です。
