 ## 解決策
 ## 問題の理解

 各テスト ケースに対して配列が与えられ、その配列内の位置のペアのみに焦点を当てるように求められます。 個別のインデックスのすべての順序ペアから、2 つの値間の絶対差を計算できます。 これらすべての違いの中で、配列内に存在する最小値と最大値によって決定される最大値が 1 つあります。 

タスクは、その最大の差を見つけることではなく、それは簡単ですが、実際にその最大差を達成するインデックスの順序ペアの数を数えることです。 ペアは順序付けされているため、同じ 2 つの値を使用する場合でも、インデックス i の後に j を選択することは、j の後に i を選択することとは異なるとみなされます。 

制約に関する重要な観察は、すべてのテスト ケースにわたる要素の合計数が最大 100,000 であることです。これにより、すべてのペアを比較する二次解は即座に除外されます。 テスト ケースごとの単純な二重ループでは、最悪の場合、制限時間をはるかに超える約 10¹⁰ の操作にまで低下します。 ソリューションでは、各テスト ケースを線形時間に短縮する必要があります。 

すべての要素が等しい場合、微妙な特殊なケースが発生します。 その場合、最大の差はゼロであり、個別のインデックスの順序付きペアはすべて |a[i] − a[j]| を満たします。 = 0。最大の差が個別の値から得られると仮定するアプローチは、等しいエンドポイントを明示的に処理しない場合、ここで機能しません。 

最大値と最小値が複数回出現する場合、別の特殊なケースが発生します。 たとえば、最小値が k 回発生し、最大値が m 回発生する場合、答えは 1 か 2 ではなく、発生のすべての組み合わせによって決まります。 よくある間違いは、すべての重複をカウントするのではなく、各エンドポイントの発生を 1 つだけカウントすることです。 

## アプローチ

 ブルート フォース ソリューションでは、すべての順序付きペア (i, j) をチェックし、 |a[i] − a[j]| を計算し、グローバル最大差を追跡し、それに到達するペアの数をカウントします。 これは正しいですが、2 つのネストされたループが必要となり、テスト ケースごとに O(n²) の作業が必要になります。 n が 100000 までの場合、これは不可能です。 

構造上の重要な洞察は、配列内の最大絶対差が常にグローバル最小値とグローバル最大値の間で達成されるということです。 他のペアはこのギャップを超えることはできません。 したがって、任意の要素を比較する必要はありません。 最小値と最大値が何回出現するかを知る必要があるだけです。 

最小値が cnt_min 回出現し、最大値が cnt_max 回出現することがわかったら、有効な順序ペアはすべて、一方のエンドポイントを最小値として、もう一方のエンドポイントを最大値として選択する必要があります。 順序が重要であるため、両方の方向が寄与し、最小から最大までは cnt_min × cnt_max のペア、最大から最小までは cnt_max × cnt_min となり、合計 2 × cnt_min × cnt_max になります。 

最小値と最大値が同じ値の場合、すべての要素は同一であり、個別のインデックスの順序付きペアはすべて有効です。 その数は n × (n − 1) です。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を 1 回スキャンして最小値と最大値を決定します。 これにより、最大の差を形成できる 2 つの候補だけが確立されます。 
2. 最小値が何回出現するか、最大値が何回出現するかを数えます。 これらの頻度によって、極端なペアを形成するための選択肢がいくつ存在するかが決まります。 
3. 最小値と最大値が同じ値の場合、すべてのペアの差分が 0 になるため、個別のインデックスの順序付きペアの数を n × (n − 1) として直接計算します。 
4. それ以外の場合は、結果を 2 × cnt_min × cnt_max として計算します。 これは、最小要素と最大要素の間の順序付けの両方向を考慮しています。 
5. テストケースの結果を出力します。 

### なぜ効果があるのか

中間値が存在する可能性のあるギャップは減少するため、絶対差が最大のペアには両方の極端な値が含まれている必要があります。 配列構造により、問題はすべてのペアを検査するのではなく、エンドポイントのカウントに分解されます。 最小値の出現はすべて、両方向での最大値の出現と対になる可能性があるため、カウントは純粋に組み合わせになり、位置には依存しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mn = min(a)
        mx = max(a)
        
        if mn == mx:
            print(n * (n - 1))
            continue
        
        cnt_mn = 0
        cnt_mx = 0
        
        for x in a:
            if x == mn:
                cnt_mn += 1
            if x == mx:
                cnt_mx += 1
        
        print(2 * cnt_mn * cnt_mx)

if __name__ == "__main__":
    solve()
```このソリューションは、すべてのテスト ケースを読み取り、各配列を個別に反復処理することから始まります。 時間的に線形である Python の組み込み関数によって提供される単一パスを使用して、最小値と最大値を計算します。 

すべての値が等しいという特殊なケースは明示的に処理されます。そうでない場合、cnt_min と cnt_max が同じになり、一般式が誤ってゼロになるためです。 

同じ要素が最小値と最大値の両方になる可能性があるのは、すでに分離されている均一なケースの場合のみであるため、カウント ループは両方のカウンタを独立してインクリメントするように注意します。 

最後に、式 2 × cnt_min × cnt_max が直接出力されます。

 ## 特殊なケース

 すべての値が同一である入力の場合、次のようになります。`4 5 5 5 5`の場合、アルゴリズムは mn と mx を同じ値に設定し、n × (n − 1) を直接計算します。 個別のインデックスの順序付きペアはすべて有効であるため、これは、そうでなければ崩れてしまう頻度ロジックに依存することなく、期待されるカウントと一致します。 

のようなケースの場合`1 1 10 10 10`、スキャンではカウント 2 で mn = 1、カウント 3 で mx = 10 が生成されます。結果は 2 × 2 × 3 = 12 になります。2 つの最小要素のそれぞれは、両方向で 3 つの最大要素のそれぞれとペアになり、カウント メカニズムはこの対称性を正確に捉えます。
