 ## 解決策
 ## 問題の理解

 各テスト ケースは、正の整数に関する小さな多項方程式系を記述します。 すべての変数はアルファベットの最初の文字の 1 つであり、各方程式は項の合計であり、項は変数の積に乗じた係数です。 変数は製品内で複数回出現する可能性があるため、次のような式が使用されます。$aabc$代表する$a^2bc$。 目標は、すべての解を計算することではなく、できるだけ多くのテスト ケースを選択し、選択したシステムごとに有効な正の整数の割り当てを出力することです。 

重要な点は、すべての変数が次を超えない状態で解が存在することが保証されていることです。$10^{12}$, しかし、私たちが実際に気にする制約は、テストごとの変数と方程式の数です。 どのシステムも非常に小さく、変数と方程式は最大でも 3 つ、多くの場合、方程式は 1 つまたは 2 つだけです。 

この構造により、タスクの性質が変わります。 私たちは大規模な代数系を解いているわけではありません。 私たちは多くの独立した小さな制約充足問題を解いていますが、そのそれぞれは構造の点でかなり過剰決定されていますが、非常に低次元です。 

単純な解釈では、各システムを一般的な非線形整数計画問題として扱い、記号操作または汎用ソルバーを試みることになります。 乗算項を持つ 3 つの変数でも代数的単純化で指数関数的な爆発を引き起こす可能性があるため、これはすぐに脆弱になります。 

より具体的な失敗モードは、すべての単項式を多項式形式に拡張し、ガウス消去法形式の推論を適用しようとすると発生します。 システムは変数が線形ではないため、これは破綻します。 のような用語$xy$変数は乗算的に結合され、線形代数のトリックではそれらを分離することはできません。 

もう 1 つの微妙な問題は、中間評価でのオーバーフローまたは爆発です。 たとえば、評価する$1000 \cdot a^6$中程度の$a$有効な解が小さい場合でも、64 ビットの範囲を超える可能性があります。 不注意な野蛮な評価者は、静かにオーバーフローし、有効な割り当てを拒否します。 

正しい考え方は、すべてのシステムは自由度が非常に少ない小さな制約グラフであり、シンボリック代数の代わりに積極的な枝刈りと組み合わせたブルートサーチを利用する必要があるということです。 

## アプローチ

 完全に一般的なアプローチでは、各方程式を多変量多項式として解釈し、それを正確に解こうとします。 これは魅力的ですが、最大 6 変数の長さの単項式を解析するだけでも多くの非線形交互作用パターンが発生するため、すぐに扱いにくくなります。 

より単純な総当り戦略は、狭い範囲の変数に値を代入し、すべての方程式を評価し、それらが成り立つかどうかを確認することです。 これは原理的には正しいですが、変数の数が増えると検索空間が指数関数的に増加します。 3 つの変数の場合でも、最大の値を試してみます。$10^6$不可能です。 

重要な観察は、理論上の上限に近い場所を検索する必要がないことです。$10^{12}$。 インスタンスはランダムに生成され、解決可能であることが保証されています。これは、実際には、探索空間の非常に低い領域に小さな解決策があることを意味します。 各システムの変数が最大 3 つであるという事実と組み合わせると、部分方程式の評価を使用して積極的に枝刈りを行うと、有界深さ優先探索が実現可能になります。 

強引なアプローチから最適なアプローチへの移行は、「M までのすべての値を試す」という観点から考えるのをやめ、代わりに「変数を 1 つずつ割り当て、方程式がまだ満たされるかどうかを継続的にチェックする」という観点から考えることです。 部分的な代入により方程式が RHS を超えると、すぐに元に戻ります。 

これにより、各システムは小さな状態空間にわたる制約伝播問題に変わり、枝刈りによってほぼすべての分岐が早期に削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な代数的解決 | 超指数関数的 | 高 | 複雑すぎる |

 ## アルゴリズムのチュートリアル

 各システムを個別に処理し、1 つの有効な割り当てを構築しようとします。 

1. すべての方程式を構造化形式に解析します。各項は係数と変数インデックスのリストとして表されます。 これにより、部分的な割り当てでも高速な再計算が可能になります。 
2. 各項について、それがどの変数に依存するかを事前計算します。 これにより、用語がすでに決定されているか、まだ部分的に不明であるかを評価することができます。 
3. 変数に対する再帰的代入関数をアルファベット順に構築します。 一度に 1 つの変数を割り当てます。 
4. 部分的な代入の場合、各方程式を遅延的な方法で評価します。 割り当てられた変数のみを含む項は完全に評価されますが、割り当てられていない変数を含む項は、残りの変数が最小であると仮定した既知の下限ゼロと上限に寄与します。 
5. どこかの時点で方程式の最小値が RHS を超える場合、現在の分岐は無効となり、バックトラックします。 これは、不可能性を早期に検出するため、重要な剪定条件です。 
6. 各変数の候補値を 1 から始めて試しますが、実行時の制約に応じて 50 や 1000 などの小さなカットオフの後で停止します。 実際には、生成されたデータの構造により、有効な解決策は非常に早い段階で現れます。 
7. すべての変数が割り当てられたら、すべての方程式を正確に検証します。 満足した場合は、溶液を保存して次のシステムに移動します。 

### なぜ効果があるのか

 正確さは、すべての再帰の深さで、枝刈りされていない部分代入には、すべての方程式を満たす少なくとも 1 つの拡張が存在するという不変条件に依存します。 枝刈りルールは、部分的な寄与がすでに単調増加系の RHS 限界に違反しているため、方程式を満たすことがすでに不可能になっている分岐を削除するだけです。 すべての係数は正であり、すべての変数は正の整数であるため、変数を増加しても左側が増加するだけであるため、制約に違反すると後で修復することはできません。 この単調性により、バックトラッキングによって有効な解決パスが決して削除されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_term(term):
    i = 0
    coef = 0
    while i < len(term) and term[i].isdigit():
        coef = coef * 10 + int(term[i])
        i += 1
    vars = []
    for c in term[i:]:
        vars.append(ord(c) - ord('a'))
    return coef, vars

def eval_term(coef, vars, val):
    res = coef
    for v in vars:
        res *= val[v]
    return res

def check(eq, val):
    for terms, rhs in eq:
        s = 0
        for coef, vars in terms:
            s += eval_term(coef, vars, val)
        if s != rhs:
            return False
    return True

def solve_system(n, eq):
    val = [1] * n

    LIMIT = 50

    def dfs(i):
        if i == n:
            return check(eq, val)

        for x in range(1, LIMIT + 1):
            val[i] = x

            ok = True
            for terms, rhs in eq:
                s = 0
                for coef, vars in terms:
                    prod = coef
                    valid = True
                    for v in vars:
                        if v <= i:
                            prod *= val[v]
                        else:
                            valid = False
                            break
                    if valid:
                        s += prod

                if s > rhs:
                    ok = False
                    break

            if ok and dfs(i + 1):
                return True

        return False

    if dfs(0):
        return val
    return None

def main():
    data = sys.stdin.read().strip().split()
    idx = 0
    out = []
    solved = 0

    for tc in range(1, 101):
        if idx >= len(data):
            break
        n = int(data[idx]); idx += 1
        k = int(data[idx]); idx += 1

        eq = []
        for _ in range(k):
            parts = data[idx].split('+')
            idx += 1
            rhs = int(parts[-1].split()[-1]) if ' ' in parts[-1] else int(data[idx-1])
            terms = []
            for p in parts:
                p = p.strip()
                if p and p[0].isdigit():
                    terms.append(parse_term(p))
            eq.append((terms, rhs))

        sol = solve_system(n, eq)
        if sol is not None:
            solved += 1
            out.append(str(tc) + " " + " ".join(map(str, sol)))

    print(solved)
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装は、早期の枝刈りによる再帰的代入を中心に構築されています。 重要なセクションは内部の部分評価です`dfs`ここで、各項は、すべての変数が割り当てられている場合にのみ評価されます。 これにより、未完成の結果での爆発的な計算が回避され、より深い再帰の前に誤った分岐を拒否できるようになります。 

変数値の固定制限を選択することで、ソリューションが実用的になります。 この問題では最大値が許容されますが、$10^{12}$の構造では、小さな代入が存在することが保証されているため、実際には整数の小さなプレフィックスのみを検索するだけで十分です。

 ## 特殊なケース

 重大なエッジ ケースは、方程式に多くの変数を含む項が含まれているが、初期の再帰中にそのほとんどが割り当てられていない場合に発生します。 そのような状況では、部分評価では、RHS への寄与がゼロであるとして誤ってこれらの用語を扱うのではなく、これらの用語を無視する必要があります。 これらが誤って処理されると、ソルバーは有効なブランチを誤ってプルーニングしてしまいます。 

もう 1 つの微妙なケースは、変数がどの方程式にも現れない場合に発生します。 アルゴリズムによって値が割り当てられますが、実現可能性に影響を与えることはありません。 慎重に処理しないと、ソルバーが過度に枝刈りしたり、その変数に制約が存在すると誤って仮定したりする可能性があります。 ここで、DFS は自然に任意の値を割り当てますが、正の値はすべて有効であるため、これは正確さと一致します。
