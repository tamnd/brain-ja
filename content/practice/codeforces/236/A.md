 ## 解決策
 ## 問題の理解

 英小文字のみからなるユーザー名が与えられます。 タスクは、そのユーザー名に含まれるさまざまな文字の数を数えることです。 

決定ルールはシンプルです。 個別の文字の数が偶数の場合、次のように出力します。`"CHAT WITH HER!"`。 数値が奇数の場合は印刷します`"IGNORE HIM!"`。 

入力サイズが小さいです。 ユーザー名の長さは最大 100 文字であるため、比較的非効率なアプローチでも制限時間内に問題なく実行できます。 二次解では最大でも約 10,000 文字の比較が実行されますが、これは最新のハードウェアでは簡単なことではありません。 これは、問題は最適化の圧力に関するものではなく、ロジックを正確かつクリーンに実装することにあることを意味します。 

間違いの主な原因は、「異なる文字」の意味を誤解していることです。 出現回数に関係なく、一意の各文字を 1 回だけカウントします。 

次の入力を考えてみましょう。```
aaaa
```異なる文字の正しい数は次のとおりです。`1`、 ない`4`。 以来`1`が奇数の場合、正しい出力は次のとおりです。```
IGNORE HIM!
```単に文字列の合計長をチェックするだけの不注意な実装では、誤って出力されてしまいます。`"CHAT WITH HER!"`。 

もう 1 つの簡単な間違いは、文字列内で遠く離れて出現する繰り返し文字を忘れることです。 

例えば：```
abac
```特徴的な文字は、`a`、`b`、 そして`c`したがって、カウントは次のようになります。`3`。 正しい出力は次のとおりです。```
IGNORE HIM!
```隣接する文字だけを比較すると、誤ってカウントされてしまいます。`a`2回。 

単一文字のユーザー名を使用する境界ケースもあります。```
z
```明確に異なる文字が 1 つだけ存在するため、答えは次のようになります。```
IGNORE HIM!
```これにより、実装が最小の有効な入力を正しく処理するかどうかがチェックされます。 

## アプローチ

 最も直接的な総当たりアプローチは、すべての文字を調べて、以前に見たことがあるかどうかを手動で確認することです。 各ポジションについて、以前のすべてのポジションをスキャンして、キャラクターが新しいかどうかを判断します。 

ある長さの文字列の場合`n`、これはおおよそ次のように実行されます。```
1 + 2 + 3 + ... + n = O(n²)
```最悪の場合の比較。 

と`n ≤ 100`、これはまだ完全に許容できます。 10,000 回の操作でも無視できる程度です。 

アルファベットが小さく、入力サイズが小さいため、この強引なアイデアが機能します。 それでも、より明確な観察が可能です。 実際には、文字の順序や頻度は気にしません。 私たちは一意の文字のセットのみを考慮します。 

Python はすでに組み込み機能を提供しています`set`異なる要素のみを自動的に保存する構造。 文字列をセットに変換すると、重複はすぐに削除されます。 

例えば：```
set("wjmzbmr")
```は次のようになります:```
{'w', 'j', 'm', 'z', 'b', 'r'}
```このセットのサイズは、個別の文字の数とまったく同じです。 その数がわかったら、それが偶数か奇数かを確認するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力からユーザー名文字列を読み取ります。 
2. 文字列をセットに変換します。 

セットでは重複する文字が自動的に削除され、異なる文字のみが残ります。 
3. セットのサイズを計算します。 

これにより、ユーザー名の一意の文字数が得られます。 
4. このカウントが偶数か奇数かを確認します。 

カウントが偶数の場合は印刷します`"CHAT WITH HER!"`。 

それ以外の場合は、印刷します`"IGNORE HIM!"`。 

### なぜ効果があるのか

 このアルゴリズムは、セットには各値が最大 1 回含まれるという特性に依存します。 ユーザー名をセットに変換すると、繰り返し出現する文字はすべて自動的に消えます。 したがって、セットのサイズは、ユーザー名の個別の文字の数と正確に等しくなります。 

問題のルールは、このカウントのパリティのみに依存します。 チェック中`count % 2`個別の文字の数が偶数か奇数かを正確に判断するため、アルゴリズムは常に必要な出力を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

distinct_count = len(set(s))

if distinct_count % 2 == 0:
    print("CHAT WITH HER!")
else:
    print("IGNORE HIM!")
```最初の行はユーザー名を読み取り、末尾の改行を次のように削除します。`strip()`。 

表現`set(s)`文字列の一意の文字のみを含むコレクションを作成します。 電話をかける`len()`このセット上の個別の文字の数を示します。 

最後の条件は、そのカウントのパリティをチェックします。 で割った余りの場合`2`がゼロの場合、カウントは偶数なので出力します`"CHAT WITH HER!"`。 それ以外の場合は印刷します`"IGNORE HIM!"`。 

実装の微妙な詳細の 1 つは、`strip()`。 これがないと、改行文字は`\n`入力からの文字が誤ってセットの一部となり、個別の文字数が 1 つ増えて間違った答えが生成される可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字はセットに 1 回挿入されます。 
| スペース | O(n) | セットにはすべての個別の文字を格納できます。 

ユーザー名の最大長はわずか 100 文字であるため、このソリューションは時間とメモリの制限内に簡単に収まります。 より遅い 2 次アプローチでも問題はありませんが、セットベースのソリューションの方がクリーンでスケーラブルです。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    s = input().strip()

    if len(set(s)) % 2 == 0:
        print("CHAT WITH HER!")
    else:
        print("IGNORE HIM!")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("wjmzbmr\n") == "CHAT WITH HER!", "sample 1"

# custom cases
assert run("a\n") == "IGNORE HIM!", "single character"
assert run("aaaa\n") == "IGNORE HIM!", "all characters equal"
assert run("ab\n") == "CHAT WITH HER!", "small even distinct count"
assert run("abcdefghijklmnopqrstuvwxyz\n") == "CHAT WITH HER!", "maximum distinct letters"
assert run("abac\n") == "IGNORE HIM!", "non-adjacent duplicate characters"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a`|`IGNORE HIM!`| 最小サイズの入力 |
 |`aaaa`|`IGNORE HIM!`| 繰り返される文字は 1 回カウントされます |
 |`ab`|`CHAT WITH HER!`| 偶数の個別カウントが小さい |
 |`abcdefghijklmnopqrstuvwxyz`|`CHAT WITH HER!`| 可能な最大の個別文字 |

 ## 特殊なケース

 よくある間違いは、文字列の長さと個別の文字の数を混同することです。 

考慮する：```
aaaa
```アルゴリズムは文字列を次のように変換します。```
{'a'}
```個別のカウントは次のとおりです。`1`これは奇数であるため、出力は次のようになります。```
IGNORE HIM!
```これにより、同じ文字の繰り返しの出現が正しく無視されます。 

もう 1 つの注意が必要なケースは、重複する文字が分離される場合です。 

入力：```
abac
```セットは次のように進化します。```
{'a'}
{'a', 'b'}
{'a', 'b'}
{'a', 'b', 'c'}
```最終的なカウントは、`3`したがって、出力は次のようになります。```
IGNORE HIM!
```これは、アルゴリズムが隣接する文字間だけでなく、グローバルに一意性を追跡していることを裏付けています。 

最小の有効な入力も正しく機能します。 

入力：```
z
```セットは次のようになります。```
{'z'}
```カウントは`1`これは奇数であるため、アルゴリズムは次のように出力します。```
IGNORE HIM!
```これにより、境界サイズの入力が正しく処理されることが検証されます。
