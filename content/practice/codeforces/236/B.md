 ## 解決策
 ## 問題の理解

 すべての積の約数の合計を計算する必要があります`i * j * k`、 どこ`i`からの範囲`1`に`a`、`j`からの範囲`1`に`b`、 そして`k`からの範囲`1`に`c`。 

トリプルごとに`(i, j, k)`、評価します`d(i * j * k)`、 どこ`d(x)`は正の約数の数を意味します`x`。 最終的な答えは、これらすべての除数の合計を法で計算したものになります。`2^30 = 1073741824`。 

制約は十分小さいため、すべてのトリプルを反復処理することは完全に合理的です。 各変数は最大なので、`100`、トリプルの合計数は最大で次のとおりです。$$100 \times 100 \times 100 = 10^6$$Python では 2 秒の制限内で 100 万回の反復が問題ありません。 本当の課題は、各製品の除数の数をどのように計算するかです。 

可能な最大の製品は次のとおりです。$$100 \times 100 \times 100 = 10^6$$からのすべての整数をチェックする単純な除数カウント ルーチン`1`に`n`約必要になる`10^6`最悪の場合のクエリごとの操作。 これをさらに 100 万製品に対して繰り返すと、爆発的に増加するでしょう。`10^{12}`限界をはるかに超えた操作。 

重要な観察は、多くの製品がリピートされていることです。 例えば、`2 * 3 * 4`そして`1 * 6 * 4`どちらも生産します`24`。 の約数を計算すると、`24`それを一度保存​​すると、その後の発生はすべて O(1) ルックアップになります。 

また、不注意な実装を静かに破壊する可能性がある微妙なエッジケースもあります。 

最小の入力を考えてみましょう。```
1 1 1
```唯一の製品は、`1`、 そして`d(1) = 1`。 一部の除数カウント実装が誤って返される`0`のために`1`なぜなら、彼らはすべての数値に素因数があると仮定しているからです。 

もう 1 つの簡単な間違いは、平方根反復を使用して約数を数えるときに発生します。 例えば：```
1 1 4
```製品は、`1, 2, 3, 4`、その約数は`1, 2, 2, 3`。 

まで反復して約数を数えると、`sqrt(n)`そして追加します`2`すべての約数のペアについて、完全二乗を慎重に扱う必要があります。 のために`4`、除数のペア`(2,2)`貢献できるのは 1 回のみです。 これを忘れると、`4`の代わりに`3`。 

別の落とし穴は、同じ製品が登場するたびに除数の数を再計算することです。 入力あり:```
100 100 100
```多くの商品がリピート率が高いです。 メモ化を行わないソリューションでも、何百万もの高価な除数計算が実行され、タイムアウトになる危険性があります。 

## アプローチ

 最も直接的な解決策は、すべてのトリプルを反復処理することです。`(i, j, k)`、積を計算します`x = i * j * k`、次に計算します`d(x)`すべての整数をチェックすることで、`1`に`x`。 

これは論理的に機能します。なぜなら、約数の定義は単純であり、すべての整数を除算するからです。`x`カウントに 1 を加えます。 問題は規模だ。 積は最大 100 万個あり、各約数の計算では最大 100 万個の数値をスキャンできます。 最悪のケースはおおよそ次のようになります。$$10^6 \times 10^6 = 10^{12}$$それは絶望的です。 

平方根プロパティを使用すると、除数のカウントを改善できます。 約数はペアで提供されます。 もし`d`分割する`n`、 それから`n/d`も分割します`n`。 までの数値のみをテストする必要があります。`sqrt(n)`。 

たとえば、次の約数は、`36`次のように表示されます:$$(1,36), (2,18), (3,12), (4,9), (6,6)$$までのみチェック`6`十分です。 

これにより、除数の計算が 1 つ削減されます。`O(n)`に`O(sqrt(n))`。 一番大きな商品なので、`10^6`、それぞれの約数の計算にかかるコストは約`1000`繰り返し。 100 万回のトリプルを合計すると、これは次のようになります。`10^9`操作、Python ではまだ遅すぎます。 

重要な観察は、個別の製品の数が限られているということです。 すべての製品はその間にあります`1`そして`10^6`。 除数の数を繰り返し再計算する代わりに、それらをキャッシュします。 

初めて積に遭遇したとき、平方根反復を使用してその除数の数を計算し、結果を保存します。 今後発生するすべての出来事は定数時間のルックアップになります。 

これにより、コストのかかる繰り返し作業が 1 回限りの前処理効果に変わります。 約数は次までの数をカウントするので、`10^6`個別の値ごとに 1 回だけ実行すれば十分に安価なので、ソリューションは簡単に合格します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(abc × n) | お(1) | 遅すぎる |
 | 最適 | O(abc + U√U) | お(う) | 承認済み |

 ここ、`U`最大でも可能な最大の製品です`10^6`。 

## アルゴリズムのチュートリアル

 1. 整数の読み取り`a`、`b`、 そして`c`。 
2. ディクショナリまたは配列を作成して、除数の数をメモ化します。 

同じ商品が何度も登場するため、キャッシュすることで繰り返し作業を回避できます。 
3. すべてのトリプルを反復処理します。`(i, j, k)`。 

各境界は最大で`100`、反復の合計数は管理可能です。 
4. Compute the product:$$x = i \times j \times k$$5. もし`x`以前に処理されていない場合は、その除数の数を計算します。 

反復する`d`から`1`に`⌊√x⌋`。 

もし`d`分割する`x`、その後:

 - 追加`2`もし`d`そして`x/d`違う
 - 追加`1`もし`d*d == x`これにより、完全二乗を二重にカウントすることなく、約数のペアが正しくカウントされます。 
6. 除数の数を保存します。`x`キャッシュ内にあります。 
7. キャッシュされた除数の数を実行中の応答に追加します。 
8. すべてのトリプルが処理された後、答えのモジュロを出力します。`1073741824`。 

### なぜ効果があるのか

 トリプルごとに`(i, j, k)`、アルゴリズムは問題で必要な値を正確に計算します。`d(i*j*k)`。 

以下のすべての約数があるため、除数カウント ルーチンは正しいです。`sqrt(n)`上記のペアの約数に対応します`sqrt(n)`。 完全平方は、平方根自体で 1 つの不対の約数をもたらします。 

メモ化しても正しさは変わりません。 これは、すでに以前に確認された製品の値の再計算を回避するだけです。 すべての検索では、手動で再計算されたものと同じ除数の数が返されます。 

すべてのトリプルが正確に 1 回処理され、その除数の数が正確に反映されるため、最終的な合計は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1073741824

a, b, c = map(int, input().split())

cache = {}
answer = 0

for i in range(1, a + 1):
    for j in range(1, b + 1):
        for k in range(1, c + 1):
            x = i * j * k

            if x not in cache:
                divisors = 0
                d = 1

                while d * d <= x:
                    if x % d == 0:
                        if d * d == x:
                            divisors += 1
                        else:
                            divisors += 2
                    d += 1

                cache[x] = divisors

            answer += cache[x]

print(answer % MOD)
```3 つのネストされたループは、すべての有効なトリプルを 1 回だけ列挙します。 限界があるだけなので、`100`、100 万回の反復は許容されます。 

キャッシュには、積の値をキーとした除数カウントが保存されます。 これは重要な最適化です。 これがないと、同じ除数の数が何度も再計算されることになります。 

divisor-count ループでは平方根法が使用されます。 条件`d * d <= x`考えられるすべての約数ペアを検査することを保証します。 

完全な正方形の枝は間違いやすいです。 たとえば、次のようなとき`x = 36`、除数`6`それ自体とペアになります。 それを二度ではなく一度数えるべきです。 

モジュロは最後にのみ適用されます。 Python の整数はオーバーフローしないため、中間合計は安全です。 累積中にモジュロを適用することも機能します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

MOD = 1073741824

def solve():
    input = sys.stdin.readline

    a, b, c = map(int, input().split())

    cache = {}
    answer = 0

    for i in range(1, a + 1):
        for j in range(1, b + 1):
            for k in range(1, c + 1):
                x = i * j * k

                if x not in cache:
                    divisors = 0
                    d = 1

                    while d * d <= x:
                        if x % d == 0:
                            if d * d == x:
                                divisors += 1
                            else:
                                divisors += 2
                        d += 1

                    cache[x] = divisors

                answer += cache[x]

    print(answer % MOD)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()

# provided sample
assert run("2 2 2\n") == "20", "sample 1"

# minimum input
assert run("1 1 1\n") == "1", "minimum case"

# small asymmetric case
assert run("1 2 3\n") == "14", "mixed ranges"

# perfect square products appear
assert run("1 1 4\n") == "8", "perfect square divisor counting"

# all equal small values
assert run("2 2 1\n") == "8", "duplicate products"

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1 1 1
```アルゴリズムは 1 つのトリプルのみを処理します。 

| 製品 | 約数 |
 | --- | --- |
 | 1 | 1 |

 除数ループは次のように実行されます。`d = 1`。 以来`1 * 1 == 1`の場合、アルゴリズムは除数を 2 つではなく 1 つだけ正しく追加します。 

最終的な答え:```
1
```次に、完全な正方形の場合を考えてみましょう。```
1 1 4
```製品は、`1, 2, 3, 4`。 

のために`4`の場合、除数ループは次のように動作します。 

| d | d*d <= 4 | 4 % d == 0 | 貢献 |
 | --- | --- | --- | --- |
 | 1 | はい | はい | +2 |
 | 2 | はい | はい | +1 |

 約数の合計は次のようになります。`3`、に対応`{1,2,4}`。 

常に追加する不注意な実装`2`除数のペアが誤って返される場合`4`。 

最後に、繰り返される製品について考えてみましょう。```
2 2 2
```製品`4`3回登場します。 最初に出現したものでは、除数の数が計算され、以下が格納されます。```
cache[4] = 3
```次の 2 つの出現では、キャッシュされた値がすぐに再利用されます。 これにより、平方根スキャンの繰り返しが回避され、最大の入力に対して十分な速度のランタイムが維持されます。
