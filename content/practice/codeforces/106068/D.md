 ## 解決策
 ## 問題の理解

 文字列が与えられ、それに対して複数の独立したクエリが尋ねられます。 各クエリは、連続する部分文字列に焦点を当てます。 その部分文字列については、文字を変更することができます。1 つの操作では、1 つの文字を他の英小文字に置き換えることになります。 各クエリの目標は、結果の部分文字列が非常に厳密な特性を持つように、必要な置換の最小数を決定することです。つまり、長さが 2 以上の回文部分文字列が含まれてはなりません。 

この状態を言い換える重要な方法は、局所的に考えることです。 長さ 2 の回文は、2 つの等しい隣接する文字にすぎません。 長さ 3 の回文は、最初と 3 番目の文字が一致するパターンです。 長い回文には構造の一部としてこれらの小さなパターンが必ず含まれるため、長さが 2 以上のすべての回文部分文字列を避けることは、2 つの単純なローカル パターン (等しい隣接パターンと間に 1 文字を挟んだ等しい文字) を避けることと同じです。 

これにより、問題がグローバルな組み合わせ条件から、連続する位置のトリプルに対する純粋にローカルな制約に変わります。 これが、問題を扱いやすくする重要な構造的単純化です。 

この制約では、最大 100,000 文字と 100,000 クエリが許可されます。 これにより、線形スキャンまたは二次スキャンを使用してクエリごとにソリューションを最初から再計算するアプローチは直ちに除外されます。 すべてのクエリが文字列のほぼ全体に及ぶ最悪の場合、クエリごとに O (部分文字列の長さ) であっても遅すぎます。 ソリューションでは、情報を前処理するか、各クエリを一定時間に近い時間に短縮する必要があります。 

制約が重なり合うと、微妙なエッジケースが発生します。 単純なアプローチでは違反を個別にカウントしようとする可能性がありますが、1 つの文字を修正すると複数の違反を同時に削除できます。 たとえば、「aaaa」のような文字列では、1 つの変更で複数の隣接する等価性違反を一度に削除できます。 これは、相互作用を考慮せずに、それぞれの悪いパターンを単純に独立して扱うことはできないことを意味します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、部分文字列を取得し、有効な文字列を左から右に構築するシミュレーションを行います。 各位置で、現在の文字を維持するか、前の文字または 2 つ前の文字と一致しないように変更するかを決定します。 違反が発生した場合は貪欲に修正することで、あらゆる可能性を暗黙的に試します。 これが機能するのは、制約が最後の 2 文字のみに依存するためであり、固定部分文字列に対して最適な結果を生成するには左から右への構築で十分です。 

ただし、すべてのクエリに対してこのシミュレーションを実行すると、クエリごとに O(部分文字列の長さ) のコストがかかり、最悪の場合は O(NQ) にまで縮退します。 N と Q の両方が 100000 に達すると、これは非常に遅くなります。 

重要な点は、クエリごとに最適な構築を実際にシミュレートする必要がないということです。 シミュレーションが必要な唯一の理由は、変更を強いられる競合の数を理解するためでした。 しかし、禁止された構造をローカル パターンの観点から書き直すと、各クエリ範囲内で「問題のある」位置がいくつあるかを直接数えることができます。 このような問題のある位置はそれぞれ、少なくとも 1 つの必要な変更に対応しており、制約の構造により、最小カウントを変更する方法で別の場所に新しい違反を作成することなく、これらのローカル違反を解決できることが保証されます。 

これにより、各クエリは、部分文字列内の 2 つの単純なパターン (隣接する等しい文字と 1 文字のギャップのある等しい文字) の出現をカウントすることになります。 

これらの条件に対してプレフィックス配列を前処理し、O(1) で各クエリに答えることができます。

## アルゴリズムのチュートリアル

 1. 文字列を 1 回スキャンし、有効な構造の変更を強制するすべてのローカル違反を特定します。 位置 i が前の文字またはその 2 つ前の文字と一致する場合、位置 i で違反が発生します。 
2. これらの違反のプレフィックス合計を構築して、任意のクエリ範囲を一定時間で評価できるようにします。 各プレフィックス エントリには、そのインデックスまでに存在する違反ポイントの数が格納されます。 
3. クエリ [L, R] の場合、プレフィックスの合計を使用して、区間内に違反ポイントがいくつあるかを計算します。 
4. クエリの答えはまさにこの数です。 

これが機能する理由は、すべての禁止された回文パターンがこれらのローカル チェックによって完全に捕捉されるためです。 それより長い回文は、その内部のどこかにこれらの局所等式の 1 つとして現れる必要があるため、部分文字列を有効にするためには、それらをすべて削除するだけで十分であり、必要です。 

### なぜ効果があるのか

 「長さが少なくとも 2 の回文部分文字列がない」という条件は、2 つのローカル パターン、つまり隣接する文字間の等価性と 2 ステップ離れた文字間の等価性を禁止することになります。 すべての無効な構造には、そのようなローカル パターンが少なくとも 1 つ含まれている必要があり、そのようなすべてのローカル パターンは、そのエンドポイントの 1 つを変更することで個別に修正できます。 これにより、必要な変更の最小数は部分文字列内の違反位置の数と等しくなり、プレフィックスの合計によりこれらのカウントを直接クエリできるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    bad = [0] * n

    for i in range(n):
        if i > 0 and s[i] == s[i - 1]:
            bad[i] = 1
        if i > 1 and s[i] == s[i - 2]:
            bad[i] = 1

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + bad[i]

    q = int(input().strip())
    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        out.append(str(pref[r + 1] - pref[l]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードはまず、禁止されたローカル構成に参加する各インデックスをマークします。 直前のインデックスまたは 2 つ前の文字と同等の状態が続く場合、インデックスは「不良」とみなされます。 この配列のプレフィックスの合計により、範囲を減算することで一定時間内に各クエリに答えることができます。 

実装の微妙な詳細は、パターン内の以前の位置ではなく、現在の位置をマークすることです。 これにより、二重カウントの問題が回避され、各違反がプレフィックス構造全体で一貫して単一のインデックスに起因することが保証されます。 

## 実用的な例

 単純な文字列を考えてみましょう`abbaeec`。 

まず、悪い位置を特定します。 

| 私 | 文字 | s[i]==s[i-1] | s[i]==s[i-2] | 悪い[i] |
 | --- | --- | --- | --- | --- |
 | 0 | | - | - | 0 |
 | 1 | b | いいえ | - | 0 |
 | 2 | b | はい | - | 1 |
 | 3 | | いいえ | はい | 1 |
 | 4 | e | いいえ | いいえ | 0 |
 | 5 | e | はい | いいえ | 1 |
 | 6 | c | いいえ | いいえ | 0 |

 プレフィックスの合計は次のようになります。`0, 0, 1, 2, 2, 3, 3, 3`。 

[2, 8] のようなクエリの場合、それを部分文字列にマッピングし、プレフィックスの合計の差を計算します。 結果は、その範囲内の違反ポイントの数と等しくなります。 

これは、複数の重複パターンがすべて 1 つの追加構造にまとめられ、クエリが互いに独立していることを示しています。 

## 複雑さの分析

 | 時間 | O(N + Q) | 違反配列とプレフィックスの合計を構築するための 1 回のパス、その後クエリごとに O(1) |

前処理は文字列サイズにおいて線形であり、各クエリは一定時間内に応答されます。これは、制限時間内の 100,000 クエリには十分です。

 ## 特殊なケース

 重要なエッジ ケースは、次のような同一文字が長く続くことです。`aaaaaa`。 この場合、最初の位置以降のすべての位置で、隣接競合と距離 2 競合の両方が作成されます。 アルゴリズムは、不良配列内のこれらの位置をそれぞれ独立してマークします。 プレフィックスの合計はそれらすべてを正しく累積し、各クエリは選択した範囲内にそのような競合がいくつあるかを正確に反映します。 

もう 1 つのエッジケースは、次のような交互パターンです。`ababab`。 ここでは、隣接する重複はありませんが、3 文字ごとに 2 ステップ前の文字を繰り返します。 不正なマーキングはそれらの位置を正確に捕捉し、再びプレフィックス合計はシミュレーションを必要とせずに必要な変更の正しい数を捕捉します。
