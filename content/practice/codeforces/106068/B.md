 ## 解決策
 ## 問題の理解

 数直線上の位置のリストが与えられ、各位置はその人の住んでいる場所を表します。 目標は、指定された位置の 1 つを集合場所として選択し、その選択した地点までの全員の歩行距離の合計ができるだけ小さくなるようにすることです。 距離はライン上の標準絶対差で測定されます。 

この問題では任意の位置を選択できますが、コストは、選択した点が数直線上のすべての値のバランスをどのようにとるかによってのみ決まります。 直観的には、合流点が左すぎる場合、多くの点が右側にあり、距離が大きくなることがわかります。 右すぎると、対称性の問題が発生します。 

入力サイズは 200,000 個の値まで可能で、各値は最大 10^9 まで可能です。 すべての候補ミーティング ポイントを他のすべてのミーティング ポイントと比較して評価する 2 次解では、最悪の場合、最大 4×10^10 の距離計算が必要になります。これは、Python で 2 秒で実行できる計算や、単純な実装パターンで最適化されたコンパイル済みコードでさえ実行できる計算をはるかに超えています。 

線形または線形算術的なアプローチが必要です。これは、すべての候補についてゼロから距離を再計算することを避ける必要があることを強く示唆しています。 

微妙な点は、複数のポジションが同じ最小コストをもたらす場合、答えの値は必ずしも一意ではないということです。 この問題は配列から位置 Pi を出力することを求めているため、有効な中央値のような位置はどれでも受け入れられます。 

ここで重要となるエッジ ケースには、値が繰り返される配列、既に並べ替えられた配列、および 1 つの極端な外れ値などの非常に偏った分布が含まれます。 たとえば、入力が [1, 1, 1, 100] の場合、最適なミーティング ポイントは 1 でなければなりません。 素朴な直観は、平均化ロジックや中間点ロジックを誤って考慮する可能性がありますが、既存の円周率を選択する必要があるため、これは無関係です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各候補位置 Pi について、絶対差の合計 |Pi − Pj| を計算します。 すべての j について、合計が最小の Pi を選択します。 これは、問題によって定義された目的関数を直接評価するため、正しいです。 

ただし、このアプローチでは N 個の候補ごとに O(N) の合計が再計算されるため、合計で O(N^2) の演算が行われます。 N が 2×10^5 までの場合、約 4×10^10 の演算が必要になりますが、これは実行不可能です。 

重要な観察は、直線上の絶対偏差の合計を最小化することが古典的な中央値の特性であるということです。 配列を並べ替えると、距離の合計が最小になる点が中央値要素になります。 その理由は構造的なものです。会合点をわずかに左または右に移動すると、両側の要素からの寄与が反対方向に変化し、中央分割で正確にバランスが達成されます。 

N は奇数であるため、中央値は並べ替え後の単一の明確に定義された要素、具体的にはゼロベースのインデックス付けにおけるインデックス N/2 の要素になります。 

これにより、問題はすべての候補を評価することから、一度並べ替えて単一の位置を選択することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | お(1) | 遅すぎる |
 | 最適 (並べ替え後の中央値) | O(N log N) | O(1) または O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 位置の配列を読み取ります。 この段階では、値は任意の順序になっているため、順序やプレフィックスのバランスなどの構造プロパティはまだ利用できません。 
2. 配列を降順でない順に並べ替えます。 中央値プロパティは順序付けられた順序でのみ意味を持つため、並べ替えは不可欠です。 並べ替えがなければ、左半分と右半分という概念がありません。 
3. インデックス N // 2 の要素を選択します。N は奇数であるため、このインデックスは両側にまったく同じ数の要素を持つ中央の要素に対応します。 
4. この要素を選択したミーティングポイントとして出力します。 この値は、元の位置の 1 つであることが保証されており、絶対距離合計目標の下で最適です。 

### なぜ効果があるのか

 数直線上の任意の候補点 x を考えます。 x の左側の各点は、x が左に移動すると距離が減少し、右側の各点は x が左に移動すると距離が増加します。 総コスト関数は区分的に線形であり、x の両側にある点の数に応じて傾きが変化します。 左側にあるポイントが半分未満の場合、傾きは負になり、右側にあるポイントが半分未満の場合、傾きは正になります。 どちらの方向でもコストが向上しないバランス ポイントは、まさに x が中央値のときです。 N が奇数であるため、このバランスはソート順の単一要素で発生し、中央値要素が絶対偏差の合計を最小化することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    p = list(map(int, input().split()))
    
    p.sort()
    print(p[n // 2])

if __name__ == "__main__":
    main()
```このソリューションは、すべての位置を読み取り、並べ替えて、中央の要素を出力します。 唯一の微妙な実装の詳細は、整数除算 n // 2 を使用することです。これにより、n が奇数の場合に、0 から始まる配列の中央インデックスが正しく選択されます。 ソートにより自然に両方が処理されるため、重複またはソートされていない入力に対して特別な処理は必要ありません。 

## 実用的な例

 ### 例 1

 入力:

 [7、3、5、1、4]

 ソートされた配列:

 [1、3、4、5、7]

 インデックスの中央値は 2 です。 

| ステップ | 配列状態 | 選択されたインデックス | 選択された値 |
 | --- | --- | --- | --- |
 | 並べ替え | [1、3、4、5、7] | - | - |
 | 選択 | [1、3、4、5、7] | 2 | 4 |

 これは、4 が左側の 3 つの要素と右側の 1 つの要素のバランスをとり、最小の合計絶対距離を生成することを示しています。 

### 例 2

 入力:

 [10、2、8、9、2]

 ソートされた配列:

 [2、2、8、9、10]

 インデックスの中央値は 2 です。 

| ステップ | 配列状態 | 選択されたインデックス | 選択された値 |
 | --- | --- | --- | --- |
 | 並べ替え | [2、2、8、9、10] | - | - |
 | 選択 | [2、2、8、9、10] | 2 | 8 |

 ここで、8 は左側の 2 つの値と右側の 2 つの値を分割し、最適なバランスを与えるため、合計距離を最小化します。 

トレースは、ソリューションが順序付け後に中央のバランス ポイントを一貫して選択していることを確認します。これは、絶対偏差を最小限に抑えるために必要な中央値の動作とまったく同じです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | Sorting dominates, linear scan afterwards |
 | スペース | O(1) または O(N) | Depending on in-place sort implementation |

 この制約では最大 2×10^5 要素が許可されており、このサイズの並べ替えは Python の一般的な時間制限内に問題なく収まります。 残りの計算は N を基準とした定数時間であるため、この解は効率的です。

 ## 特殊なケース

 [10] のような単一要素入力の場合、ソートすると変更されず、インデックス 0 を選択すると 10 が返されます。これは、移動が必要ないため、自明のことながら最適です。 

[2, 2, 2, 2, 2] のようなすべてが等しい配列の場合、並べ替えは何も行わず、中央値は 2 のままです。どの選択をしても合計距離はゼロになり、アルゴリズムは一貫して有効な最適点を返します。 

[1, 1, 1, 1, 100] のような非常に偏った配列の場合、並べ替えにより [1, 1, 1, 1, 100] が得られ、インデックスの中央値は 2 で、値 1 が得られます。 個数ではなく大きさのバランスについて平均や直観に基づいて選択しようとすると、誤って 100 またはそれに近い値を選択する可能性がありますが、絶対偏差コストは距離ではなく両側の個数のみに依存します。 価値空間で。
