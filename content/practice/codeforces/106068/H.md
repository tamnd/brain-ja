 ## 解決策
 ## 問題の理解

 可変の整数配列を操作しており、各クエリでは、それらのインデックスに格納されている値に依存する距離条件を使用して、配列内の 1 つのインデックスを他のすべてのインデックスに関連付けるように求められます。 

固定クエリ位置の場合`i`、他のインデックスを見つけようとします`j`間の距離が`i`そして`j`を 3 乗すると、に格納されている値を支配するのに十分な大きさになります。`A[j]`。 より直接的に言えば、それぞれの立場`j`「受け入れる」にはクエリ位置がどのくらい離れていなければならないかという要件を課します`j`。 配列内の値が大きいと、クエリ インデックスが遠くない限り、位置を一致させるのが難しくなります。 

ポイントの更新もサポートしているため、クエリに応答するだけでなく、値が変更されたときにすぐに適応する構造を維持することも困難です。 

制約は次のとおりです`N, Q ≤ 100000`これにより、クエリごとに配列全体をスキャンするソリューションが直ちに除外されます。 クエリごとの単純なチェックにはコストがかかります`O(NQ)`、これは許容範囲をはるかに超えています。 平`O(N log N)`クエリごとに実行すると遅すぎます。 目的のソリューションでは、各クエリと更新を対数時間または定数時間に近づける必要があります。 

微妙なエッジ ケースは、条件が非対称に依存するという事実から生じます。`j`、オンではありません`i`。 これは、インデックスごとに固定された答えを事前計算できないことを意味します`i`。 もう 1 つの注意が必要なケースは、有効な候補者がすべて片側のみに位置している場合です。`i`、条件は純粋に距離に基づいていますが、値に依存しているためです。 

単に近くのインデックスをチェックする単純なアプローチは、唯一有効なインデックスが存在する場合には失敗します。`j`遠くにあるとき、たとえば、`A[j]`大きいですが、インデックスが配列の境界近くにあります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 タイプのクエリごとに`2 i`、すべてを繰り返します`j`かどうかを確認してください`|i - j|^3 ≥ A[j]`。 これは妥当性の定義に直接従うため、正しいです。 ただし、各クエリにはコストがかかります`O(N)`なので、最大で`10^5`クエリの合計作業量は次のようになります`10^10`、制限時間内に実行することはできません。 

重要な観察点は、各インデックスが`j`それ自体の周囲に「禁止された半径」を定義すると考えることができます。 閾値を定義すると`t_j`次のような最小の整数として`t_j^3 ≥ A[j]`、 それから`j`少なくとも次のクエリ位置に対してのみ機能します。`t_j`離れて。 これにより、条件が純粋な幾何学的制約に変換されます。各インデックスは、その周囲のクエリ位置の連続セグメントを許可または禁止します。 

全部チェックするのではなく、`j`クエリごとに視点を反転します。 固定クエリ位置の場合`i`、インデックスが存在するかどうかを知りたい`j`独自のしきい値に従って十分に離れた左側または右側。 これにより、問題が 2 つの独立した方向性チェックに分割されます。 

の左側にある`i`が存在するかどうかだけを知る必要があります。`j < i`その「安全な境界」は完全に前にあります`i`。 そのようなすべての中で`j`、許可される領域がどこまで広がるかを最大化するものを見つけたいと考えています。 最左翼候補さえ届かないなら`i`、その後は毎回`j`その方向では有効であり、任意の代表者を返すことができます。 

対称的な考え方が右側に適用されます。 右側の候補の中で最も小さい左側の境界を追跡し、その境界さえも厳密にその後にあるかどうかを確認します。`i`。 

これにより、しきい値の更新をサポートしながら、インデックス上に 2 つのセグメント ツリーのような構造 (1 つは左側のクエリに最適化され、もう 1 つは右側のクエリに最適化) を維持するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. インデックスごとに`j`、しきい値を計算します`k_j`、これは次のような最小の整数です。`k_j^3 ≥ A[j]`。 これにより、三次条件が直線距離の要件に変換されます。 
2. ポジションごとに`j`、それを 2 つの派生値として解釈します: 左リーチ値`L_j = j - k_j`そして正しいリーチ値`R_j = j + k_j`。 これらは、インデックスが有効なクエリ位置にどの程度「影響を与える」かを表します。 
3. 2 種類の範囲クエリに応答できるインデックスに対してセグメント ツリーを構築します。 1 つのクエリは次の最大値を返します。`R_j`範囲内の対応するインデックスとともに。 もう 1 つは、次の最小値を返します。`L_j`範囲内のインデックスとともに。 
4. 位置でクエリを処理するには`i`、まず左側の範囲を検討します。`[1, i-1]`。 インデックスを取得する`j`を最大化するこの範囲内で`R_j`。 この最大値が依然として厳密に小さい場合は、`i`、それからこれ`j`最も遠い左の候補でもカバーできないため、これは有効です。`i`。 
5. 左側に有効なインデックスが見つからない場合は、右側の範囲を検討します。`[i+1, N]`。 インデックスを取得する`j`それは最小限に抑えます`L_j`。 この最小値が厳密に次の値よりも大きい場合、`i`、それからこれ`j`最も近い右の候補でもまだ到達していないため、有効です`i`。 
6. どちらの側も有効な候補を生成しない場合、出力`-1`。 

アップデートの変更`A[i]`, そこで再計算します`k_i`、 アップデート`L_i`そして`R_i`、位置でセグメントツリーを更新します`i`。 

正しさは、両側が極端な境界チェックを行うという事実に依存します。 有効な候補は 2 つの互いに素な範囲のいずれか内に存在する必要があり、セグメント ツリーにより各範囲内で最も強力な障害物を効率的に評価できることが保証されます。 

### なぜ効果があるのか

 各インデックス`j`を中心とするクエリ位置の禁止間隔を定義します。`j`、 具体的には`(j - k_j, j + k_j)`。 クエリ位置`i`有効です`j`まさにこの間隔の外側にあるときです。 したがって、解決策は、範囲をカバーしない間隔が少なくとも 1 つある場合にのみ存在します。`i`。 

左側で、最も「危険な」間隔は、最も右に伸びている間隔です。 その間隔さえも先に終わってしまったら`i`の場合、その範囲内のすべての間隔も、その前に終了します。`i`、すべてが有効な候補であることを意味します。 同じ理由が右側にも対称的に当てはまります。 この極端な値への削減により、各側で 1 つの代表者のみをチェックするだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cube_root_ceiling(x: int) -> int:
    lo, hi = 0, 100000  # safe upper bound since (10^5)^3 = 10^15
    while lo < hi:
        mid = (lo + hi) // 2
        if mid * mid * mid >= x:
            hi = mid
        else:
            lo = mid + 1
    return lo

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mxR = [0] * (4 * n)
        self.mnL = [10**18] * (4 * n)
        self.idR = [0] * (4 * n)
        self.idL = [0] * (4 * n)

    def _pull(self, v):
        lc, rc = v * 2, v * 2 + 1

        if self.mxR[lc] >= self.mxR[rc]:
            self.mxR[v] = self.mxR[lc]
            self.idR[v] = self.idR[lc]
        else:
            self.mxR[v] = self.mxR[rc]
            self.idR[v] = self.idR[rc]

        if self.mnL[lc] <= self.mnL[rc]:
            self.mnL[v] = self.mnL[lc]
            self.idL[v] = self.idL[lc]
        else:
            self.mnL[v] = self.mnL[rc]
            self.idL[v] = self.idL[rc]

    def build(self, v, l, r, A):
        if l == r:
            k = cube_root_ceiling(A[l - 1])
            self.mxR[v] = l + k
            self.mnL[v] = l - k
            self.idR[v] = l
            self.idL[v] = l
            return

        m = (l + r) // 2
        self.build(v * 2, l, m, A)
        self.build(v * 2 + 1, m + 1, r, A)
        self._pull(v)

    def update(self, v, l, r, idx, val):
        if l == r:
            k = cube_root_ceiling(val)
            self.mxR[v] = l + k
            self.mnL[v] = l - k
            return

        m = (l + r) // 2
        if idx <= m:
            self.update(v * 2, l, m, idx, val)
        else:
            self.update(v * 2 + 1, m + 1, r, idx, val)
        self._pull(v)

    def query_maxR(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return -10**18, -1
        if ql <= l and r <= qr:
            return self.mxR[v], self.idR[v]
        m = (l + r) // 2
        a = self.query_maxR(v * 2, l, m, ql, qr)
        b = self.query_maxR(v * 2 + 1, m + 1, r, ql, qr)
        return a if a[0] >= b[0] else b

    def query_minL(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return 10**18, -1
        if ql <= l and r <= qr:
            return self.mnL[v], self.idL[v]
        m = (l + r) // 2
        a = self.query_minL(v * 2, l, m, ql, qr)
        b = self.query_minL(v * 2 + 1, m + 1, r, ql, qr)
        return a if a[0] <= b[0] else b

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    q = int(input())

    st = SegTree(n)
    st.build(1, 1, n, A)

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1])
            val = int(tmp[2])
            A[i - 1] = val
            st.update(1, 1, n, i, val)
        else:
            i = int(tmp[1])

            if i > 1:
                r, idx = st.query_maxR(1, 1, n, 1, i - 1)
                if r < i:
                    out.append(str(idx))
                    continue

            if i < n:
                l, idx = st.query_minL(1, 1, n, i + 1, n)
                if l > i:
                    out.append(str(idx))
                    continue

            out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、セグメントごとに 2 つの集計値 (候補が右にどれだけ伸びているか、および左にどれだけ伸びているか) が維持されます。 立方根の計算は分離されているため、更新はクリーンなままであり、各セグメント ツリー ノードには方向チェックに必要な両方の極値が格納されます。 

クエリ中は境界セグメントのみ`[1, i-1]`そして`[i+1, n]`有効な答えはすべてこれらの領域の 1 つに完全に存在する必要があるためです。 

## 実用的な例

 小さな配列を考えてみましょう`A = [1, 8, 27, 2]`。 立方根は、`[1, 2, 3, 2]`、したがって、導出された右側の境界は次のようになります。`[2, 4, 6, 6]`そして境界線を残した`[0, 0, 0, -1]`。 

お問い合わせについては、`i = 2`、左側を調べます`[1]`。 候補はインデックスのみ`1`、その権利リーチは`2`、それ以上`2`, したがって、左側は失敗します。 右側`[3,4]`、 索引`3`境界線を離れました`0`を超えない`2`、したがって、これも失敗し、`-1`。 

お問い合わせについては、`i = 4`、左の範囲は`[1,2,3]`。 このうち最大の権利リーチは`6`インデックスから`3`、それ以上`4`、インデックス`3`有効です。 

| クエリ | 左チェック | 右チェック | 出力 |
 | --- | --- | --- | --- |
 | i = 2 | maxR = 2 (< 2 ではない) | minL = 0 (2 を超えない) | -1 |
 | i = 4 | maxR = 6 (< 4 は慎重に反転された条件チェックに失敗します) | minL は関係ありません | 3 |

 トレースは、決定が個々のチェックではなく、各半分の極値のみにどのように依存するかを示しています。

 ## 特殊なケース

 重大なエッジケースは、すべての値が非常に小さい場合に発生します。`A[j] = 1`。 この場合、すべての立方根は次のようになります。`1`つまり、各インデックスはそれ自体を除外するだけで、ほぼすべてが有効です。 左端と右端の両方がすぐに条件を満たすため、アルゴリズムは任意のインデックスを正しく返します。 

更新後に 1 つの値が極端に大きくなった場合、別のエッジ ケースが発生します。 そのインデックスの間隔は非常に拡大するため、ほとんどのクエリ位置がブロックされる可能性があります。 極値は自動的に伝播し、有効な代替手段が存在しない限り、クエリはその側を回避するため、セグメント ツリーは引き続きこれを正しく処理します。 

最後の微妙なケースは、クエリ インデックスが境界にある場合です。 片側のみが存在し、アルゴリズムは特別な処理を必要とせずに自然に 1 つのセグメント クエリに縮小されます。
