 ## 解決策
 ## 問題の理解

 私たちは長方形の都市グリッドに取り組んでいます。$N$行と$M$列。 配置することが許可されています$K$任意のグリッドセル上の消防署。 各ステーションはチェビシェフ距離を使用して他のセルに到達できます。つまり、8 方向への移動が許可され、2 つのセル間の距離は行と列の差の最大値になります。 

セルに配置されたステーションは、その位置を中心とする辺の長さの正方形内のすべてのセルを効果的に保護します。$2d+1$, なぜなら、チェビシェフ距離内のすべてのセルだからです。$d$満足する$\max(|x_1-x_2|, |y_1-y_2|)\le d$。 

タスクは、グリッド内のすべてのセルが少なくとも 1 つのステーションでカバーされるように、ステーションの位置を最適に選択することであり、可能な限り最小のステーションが必要です。$d$これが達成できるのはせいぜい$K$駅。 

グリッドは非常に大きくなる可能性があり、$10^9 \times 10^9$したがって、セルごとに何かをシミュレートすることはできません。 駅の数ははるかに少なく、最大で$10^5$これは、解決策がグリッドを構造的な計数問題に圧縮する必要があることを示唆しています。 

単純な試みでは、ステーションを配置してカバレッジをシミュレートしようとしますが、グリッドを表現することさえ不可能です。 もう 1 つの素朴なアイデアは、すべての配置を試してみることです。$K$しかし、それは組み合わせ的に爆発的であり、たとえ小さな入力であっても無関係です。 

微妙なエッジケースが現れるのは、$N$そして$M$どちらも小さいですが、$K$大きいです。 たとえば、次の場合$N=M=2$そして$K=4$、 それから$d=0$各ステーションはちょうど 1 つのセルをカバーするため、これで十分です。 前提となるソリューション$d\ge 1$デフォルトではここで失敗します。 

主な課題は、対象範囲がどれだけの数に達するかによってのみ左右されることを認識することです。$(2d+1)\times(2d+1)$正方形は、正確なステーションの配置ではなく、グリッドをタイル表示するために必要です。 

## アプローチ

 ブルートフォース視点は候補距離を固定することから始まります$d$。 駅が1辺の正方形をカバーする場合$2d+1$、その場合、グリッドはそのような正方形で覆われている必要があります。 あらゆる方法でステーションを配置し、カバレッジをチェックしてみることもできますが、グリッドには最大の制限があるため、これは不可能です。$10^{18}$セル、さらには配置を列挙することさえ不可能です。 

重要な観察は、一度、$d$が固定されている場合、最適な配置は常に格子状のパッキングになります。 各ステーションは連続したブロックをカバーするため、ステーションの数を最小限に抑えるために、これらのブロックを重ならないように通常のタイリングに詰め込みます。 それぞれの次元に沿って、$\lceil N/(2d+1)\rceil$垂直方向にブロックし、$\lceil M/(2d+1)\rceil$水平方向にブロックします。 彼らの製品は、そのために必要なステーションの最小数を提供します。$d$。 

これにより、問題は幾何学的配置から単純な実現可能性チェックに変換されます。 次に最小のものを探します$d$必要なブロック数を超えないようにする$K$。 増えてからは$d$カバレッジ サイズが増加するだけで、実現可能性は単調であるため、二分探索が適用可能になります。

 ## アルゴリズムのチュートリアル

 治療します$d$最小化したい変数として、指定されたかどうかを確認します$d$で十分です。 

1.固定の場合$d$、カバレッジの辺の長さを次のように計算します。$s = 2d + 1$。 これは、1 つのステーションが各方向で完全にカバーできる連続セルの数を表します。 
2. グリッドを垂直にカバーするために必要なステーションの数を次のように計算します。$a = \lceil N / s \rceil$。 これは、高さの垂直ストリップの数を数えます。$s$が必要です。 
3. 水平方向に必要なステーションの数を次のように計算します。$b = \lceil M / s \rceil$。 これは、幅の水平ストリップをカウントします。$s$。 
4. 必要なステーションの合計数は、$a \times b$。 これは、完全なグリッド分解でブロックごとに 1 つのステーションを配置することに対応します。 
5. かどうかを確認します。$a \times b \le K$。 「はい」の場合は距離を置きます$d$十分です。 そうでなければ小さすぎます。 
6. 二分探索を使用します。$d$から$0$まで$\max(N, M)$、実行可能な最小値を維持します。 

二分探索が機能する理由は、$d$増えるだけ$s$、これにより両方が減少します$\lceil N/s \rceil$そして$\lceil M/s \rceil$, したがって、必要なステーション数が増加することはありません。 

### なぜ効果があるのか

 固定の場合$d$、グリッドは最大で次のサイズのブロックに分割できます。$(2d+1)\times(2d+1)$。 各ステーションは、カバレッジを無駄にすることなく、このようなブロック境界をまたぐ領域を 1 つ以上カバーすることはできないため、最適な配置はタイルのように動作します。 表現$\lceil N/s\rceil \cdot \lceil M/s\rceil$は単なる構造ではなく、可能な最小数です。これは、どのカバーリングでも、このパーティションによって引き起こされる互いに素なブロック領域ごとに少なくとも 1 つのステーションを割り当てる必要があるためです。 これにより、実現可能性チェックが近似的ではなく正確になるため、それに対する二分探索により真の最小値が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(d, n, m, k):
    s = 2 * d + 1
    a = (n + s - 1) // s
    b = (m + s - 1) // s
    return a * b <= k

def solve():
    n, m, k = map(int, input().split())

    lo, hi = 0, max(n, m)

    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid, n, m, k):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```このソリューションは、単調な実現可能性テストを中心に構築されています。 機能`can`タイリング引数を直接エンコードします。半径を変換します。$d$をブロック サイズに変換し、各次元で必要なブロック数を計算します。 

二分探索では、以下の値が存在しないという不変条件が維持されます。`lo`実行不可能であり、それ以上の値`hi`潜在的には実現可能です。 中間点チェックでは、有効な最小値が得られるまで間隔が徐々に縮小されます。$d$が見つかりました。 

唯一の微妙な点は、整数の上限除算が正しく処理されるようにすることです。これは、ここでのオフバイワンエラーが必要なステーションの数を直接変更するためです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())

    def can(d):
        s = 2 * d + 1
        a = (n + s - 1) // s
        b = (m + s - 1) // s
        return a * b <= k

    lo, hi = 0, max(n, m)
    while lo < hi:
        mid = (lo + hi) // 2
        if can(mid):
            hi = mid
        else:
            lo = mid + 1

    return str(lo)

 ## 特殊なケース

 いつ$N$そして$M$両方とも 1 の場合、アルゴリズムは次のように評価します。$d=0$それ以来すぐに$s=1$必要なステーションは 1 つだけです。 実現可能性チェックは、特別な処理を行わなくても正しく true を返します。 

次のようにグリッドが極端に歪んでいる場合$1 \times M$の場合、計算は 1 次元のカバー問題に帰着します。 次のいずれかの理由により、この公式は引き続き適用されます。$a$または$b$が 1 になり、もう一方はラインに沿った完全なセグメンテーションをキャプチャします。 

いつ$K$グリッド サイズに比べて非常に大きい場合でも、アルゴリズムは正しく返します。$d=0$、 以来$\lceil N/1\rceil \cdot \lceil M/1\rceil = N \cdot M \le K$重要な条件はそれだけです。
