 ## 解決策
 ## 問題の理解

 私たちには、電気が利用できる一定の時間が時間単位で与えられています。 各時間は、洗濯機の 1 回の洗濯サイクルに正確に対応します。 衣類にはいくつかの色があり、色ごとにすべて洗濯しなければならないアイテムの数が決まっています。 

洗濯機には 1 時間あたり 2 つの独立した制約があります。 まず、1 時間で最大で処理できるのは、`P`さまざまな色。 第二に、その時間内に選択した色については、最大でも洗濯可能です。`K`その色のアイテム。 利用可能な以上`H`何時間も経つと、次の選択肢があるかどうかを判断しなければなりません。`P`すべての衣類が完全に洗濯されるようにし、そうであれば、そのような最小限のものを見つけてください。`P`。 

したがって、構造は次のようになります: 各色`i`需要がある`A[i]`。 それぞれの時間が私たちに与えてくれる`P`色の並列「スロット」があり、各スロットは最大で`K`そのカラーの洗濯済みアイテム。 色は数時間で現れる場合があり、時間の経過とともに容量が蓄積されます。 

キーの出力は最小の整数です`P`以上のスケジュールが存在するため、`H`すべての作業を完了するのに数時間。 1 時間あたり無制限の並列色を使用しても、総容量が不足する場合、答えは不可能です。 

制約は大きく、最大 100 万色と非常に大きな値です。`A[i]`そして`H`。 これにより、数時間にわたるシミュレーションや項目ごとのスケジュールが即座に排除されます。 時間ごとまたは項目ごとに反復するものは遅すぎます。 すべてを削減して配列上の演算を集約するソリューションが必要です。 

総容量は考慮されているが、色ごとの制限が無視されている場合、微妙な失敗例が発生します。 たとえば、次の場合`A = [100, 100]`、`K = 10`、`H = 1`そうすると、総容量が大きく見えても、各色が貢献できるのはそれだけです`10`1時間以内なので両方完了することはできません。 もう 1 つの問題は、非常に大きい場合です。`A[i]`規模の大小に関係なく、複数時間を強制する`P`は。 

## アプローチ

 の値を固定すると、`P`、実現可能性を確認できます。 各時間において、選択された各色は最大で寄与します`K`洗濯済みのアイテムなので、`H`選択した各色が最大で貢献できるのは時間です。`H * K`アイテムの合計。 これはすぐに色ごとの要件を意味します。`A[i]`満たさなければなりません`A[i] ≤ H * K`そうでない場合は、たとえ色が 1 時間ごとに選択されたとしても、その上限を超えることはできないため、いくら並列化しても役に立ちません。 

色ごとに実現可能性があると仮定すると、実際の制約は、1 時間に何色を同時にアクティブにする必要があるかになります。 色について`i`、必要です`ceil(A[i] / K)`「時間のスロット」、つまり、1 時間で貢献できるのはその時間内に限られているため、その時間内に出現する必要があることを意味します。`K`。 

したがって、各色は消費します`t[i] = ceil(A[i] / K)`何時間も。 各時間に最大でホストできるのは`P`色、だから全体的に`H`時間、利用可能なカラースロットの合計は`P * H`。 すべてを割り当てなければなりません`t[i]`各ユニットがその色の 1 時間スロットを占めることを考慮して、これらのスロットにユニットを追加します。 これにより、問題は次の合計かどうかを確認することに減ります。`t[i]`に適合する`P * H`ただし、さらに微妙な点があります。単一の色はこれを超えることはできません。`H`、これは実行可能性チェックによってすでに処理されています。 

したがって、実現可能性は次のようになります。`ceil(A[i]/K)`≤である必要があります`P * H`。 

これにより、問題は次の単調述語に変換されます。`P`。 ある場合`P`作品、それより大きいもの`P`時間当たりの処理能力を増やすだけなので、これも機能します。 この単調性により、二分探索が可能になります。`P`。 

下限も必要です。ユニット スロットごとに 1 時間あたり少なくとも 1 色という要件が意味します。`P ≥ max(t[i]) / H`ですが、二分探索では自然に処理されます。 

ブルーフォースは増加を試みます`P`1 から順に実行可能性をチェックし、各チェックですべてをスキャンします`N`価値観。 それは`O(N * P)`最悪の場合、それは不可能です`P`大きくなる可能性があります。 

最適化されたソリューションでは、実現可能性チェックごとに 1 つのパスとバイナリ検索を使用します。`P`。

 ## アルゴリズムのチュートリアル

 ### 1. 色ごとの時間要件を事前計算する

 各色ごとに`i`、計算する`t[i] = (A[i] + K - 1) // K`。 これは、すべてのアイテムの洗濯を完了するためにその色が現れるまでの時間を表します。 

その理由は、各時間は最大でも貢献できるということです。`K`単位は色なので、次のように割ります。`K`アイテム需要を時間需要に変換します。 

### 2. グローバルな実現可能性の限界を確認する

 もしあれば`t[i] > H`、すぐに戻ります`-1`。 つまり、この色に 1 時間すべてを費やしても、まだ完成しないということです。 

このステップでは、考慮することなく、不可能なケースを早期に切り分けます。`P`。 

### 3. 最小 P を二分探索する

 検索します`P`範囲内で`[1, N]`。 どの時間でも、次の値を超える値を割り当てることはできないため、上限は安全です。`N`色。 

候補者ごとに`P`、総需要がキャパシティに適合するかどうかを確認します`P * H`。 

### 4. 指定された P の実現可能性チェック

 コンピューティング`sum(t[i])`。 もし`sum(t[i]) ≤ P * H`、 それから`P`で十分です。 

解釈すると、各時間は次のことを提供します。`P`利用可能なカラースロットがあるため、すべての時間にわたって総容量が確保されます`P * H`。 

### 5. 最小の有効な P を返します。 

二分探索により最小値に確実に収束します`P`それは実現可能性を満たします。 

### なぜ効果があるのか

 各色は独立して、次の時間に出現する固定数を必要とします。`ceil(A[i]/K)`。 色間の唯一の組み合わせは、1 時間あたりの制限です`P`。 以上`H`ちょうど何時間もあるよ`P * H`カラー用のスロット。 スロットの競合以外では色が干渉しないため、実現可能性は単純なパッキング制約に限定されます。 二分探索が機能するのは、`P`実行可能性を決して低下させずに、利用可能なスロットを厳密に増加させるため、述語は単調になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, H = map(int, input().split())
    A = list(map(int, input().split()))

    t = []
    total = 0

    for x in A:
        need = (x + K - 1) // K
        if need > H:
            print(-1)
            return
        t.append(need)
        total += need

    # binary search for minimum P
    lo, hi = 1, N
    ans = N

    while lo <= hi:
        mid = (lo + hi) // 2

        if total <= mid * H:
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず各色を必要な時間数に圧縮します。 早めのチェック`need > H`単一の色が利用可能な時間枠の合計を超えることによって引き起こされる不可能性をキャプチャします。 

変数`total`すべての時間需要を累積します。 実現可能性チェックでは、この事前に計算された合計を使用することで、配列の再スキャンが回避されます。 次に、二分探索により次のことがチェックされます。`mid * H`必要なすべての色の外観を収容するのに十分な大きさです。 

よくある落とし穴は、制約がアイテムに関するものではなく、色ごとの時間スロットに関するものであることを忘れることです。 への変革`ceil(A[i]/K)`重要な構造ステップです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、単一の色が色ごとの合計容量を超える場合です。 入力用`N=1, K=3, H=2, A=[10]`、計算します`t = 4`より大きい`H`。 アルゴリズムはすぐに戻ります`-1`、バイナリ検索が容量を割り当てようとする場合でも、正しく拒否されます。 

もう 1 つのケースは、すべての色が小さいものの、非常に数が多い場合です。 のために`N=10^6, K=1, H=1`、すべての色には正確に 1 時間のスロットが必要です。`total = N`。 答えは次のようになります`P = N`、各時間に処理できるのは`P`色もあり、時間は1時間しかありません。 アルゴリズムは比較するため、これを処理します。`N`に対して`P * H`。 

最後の微妙なケースは次のような場合です。`H`は色ごとの実現可能性を維持できるほど十分に大きいですが、総需要はまだ逼迫しています。 二分探索では最小値が正しく検出されます。`P`これにより、全体的なパッキングが可能になり、すべての結合が集合体で捕捉されるため、個々の分布によって誤解されることがなくなります。`P * H`制約。
