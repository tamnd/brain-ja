 ## 解決策
 ## 問題の理解

 各セルに値が含まれる整数グリッドが与えられており、グリッド内の隣接するセルを移動することによって形成される特定の特別なパスをカウントする必要があります。 移動は 4 つの基本方向でのみ許可され、各ステップは現在のセルとは正確に +1 だけ異なる隣接セルに移動する必要があります。 

私たちが数えている有効なオブジェクトは単なるパスではありません。 これは、ステップごとに値が厳密に 1 ずつ増加するグリッド セルの単純なチェーンである必要があり、パスはどちらのエンドポイントでもそれ以上拡張できず、少なくとも 4 つのセルが含まれている必要があります。 2 つのパスは、少なくとも 1 つのセルで異なる場合、異なるものとみなされます。 

重要な構造的解釈は、有効な各パスが、隣接するセル間の値 x から値 x+1 までのエッジによって定義される有向グラフの最大セグメントであるということです。 私たちは事実上、長さが 4 以上の厳密に増加する最大の「チェーン」をすべてカウントしています。 

グリッド サイズは最大 1000 x 1000 で、最大 1e6 セルが得られます。 すべてのパスを明示的に探索しようとするアルゴリズムは失敗します。これは、値が大きな分岐構造を形成する最悪のケースでは、考えられるパスの数が指数関数的に増加する可能性があるためです。 各セルから開始して 4 方向に分岐する DFS であっても、状態を繰り返し再訪問して爆発してしまいます。 

パスが重なっている場合、微妙な問題が発生します。 単一のグリッドには、内部セグメントを共有するがエンドポイントが異なる複数の有効なパスを含めることができます。 たとえば、直線的に配置された 1、2、3、4、5、6 のような直線増加直線では、長さが 4 以上のすべての最大サブチェーンが 1 つの有効なパスに寄与しますが、すべてのサブパスを単純にカウントすると過大なカウントになります。 

もう 1 つのエッジ ケースは、等しい増分で分岐することです。 セルに値 +1 の隣接セルが複数ある場合、パスは分割され、どちらの端でも拡張できないパスのみが有効になります。 単純な「すべてのセルから貪欲に拡張する」と、慎重に固定しない限り、同じ最大パスが複数回カウントされます。 

最後に、4 より短いパスは、たとえ最大増加チェーンであっても除外する必要があります。 長さ 3 のチェーンは、すべてのローカル制約を満たしている場合でも、完全に無効です。 

## アプローチ

 ブルート フォースのアイデアは、すべてのセルから開始され、値が正確に +1 である隣接セルまでのエッジに続く DFS を実行します。 各 DFS は、すべての厳密に増加するパスを探索します。 これ以上拡張できず、長さが少なくとも 4 であるすべてのパスを記録します。 

これは、数えるよう求められている構造を正確に列挙しているため、原理的には正しいです。 問題は規模だ。 値が複数の方向に増加するグリッドでは、各ノードは最大 4 方向に分岐でき、多くのパスが重なり合います。 さらに悪いことに、同じ中間セグメントをさまざまな開始点から横断することができます。 最悪の場合、接続されたコンポーネントのサイズが増加すると、探索される有効なパスの数が指数関数的に増加します。 

重要な観察は、値がエッジに沿って厳密に増加するため、関係「x から x+1 に移動」が有向非循環構造を定義していることです。 すべての有効なパスは、この DAG 内の最大の有向パスです。 パスを列挙する代わりに、エンドポイントを数え、値に関する動的プログラミングを中心に問題を構造化できます。 

値の昇順にセルを処理します。 各セルについて、そのセルで終了する増加パスの数を計算します。 隣接セルの値がちょうど 1 少ない場合、そこで終了するすべてのパスを現在のセルに延長できます。 これにより、指数関数的なパスの列挙がエッジに沿ったカウントの線形伝播に変換されます。 

各セルで終了するパスの数がすべて分かれば、最大パスの特定はローカルになります。セルで終了するパスは、値 +1 を持つ隣接セルが存在しない場合に最大になります。 同様に、セルで始まるパスは、値 -1 を持つ隣接セルが存在しない場合に最大になります。 順方向 DP と逆方向 DP を組み合わせることで、完全な最大チェーンを 1 回だけカウントできます。

 ## アルゴリズムのチュートリアル

 エッジが値 x から x+1 に向かうグリッド グラフ内の最大の厳密に増加するチェーンをカウントすることとして問題を再定式化します。 

### ステップ

 1. すべてのセルのリストを作成し、値で並べ替えます。 

並べ替えにより、小さい値から大きい値への遷移が確実に処理されるため、セルの DP を計算するときに、潜在的なすべての先行処理がすでに処理されていることが保証されます。 
2. DP 配列を定義する`dp[i][j]`セル (i, j) で終わる増加するパスの数として。 すべての値を 1 に初期化します。 

これは単一セルからなる自明なパスを表します。 
3. 値の昇順にセルを移動します。 各セル (i, j) について、4 つの隣接セルすべてからパスの延長を試みます。 

近傍 (ni, nj) に値がある場合`a[i][j] - 1`の場合、(ni, nj) で終わるすべてのパスは (i, j) まで拡張できるため、次のように追加します。`dp[ni][nj]`に`dp[i][j]`。 
4. この時点で、`dp[i][j]`(i, j) で終わるすべての厳密に増加するパスをカウントします。 ただし、それでも最大性を確保する必要があります。 
5. 配列を計算する`is_end[i][j]`これは、値を持つ近隣ノードが存在しない場合に当てはまります。`a[i][j] + 1`。 これらは、パスをさらに拡張できないエンドポイントです。 
6. 最大チェーンとして (i, j) で終わる有効なパスの数は、`dp[i][j]`(i, j) がエンドポイントの場合のみ。そうでない場合は、まだ完全な最大パスとしてカウントされません。 
7. 同様に、最小長の制約を適用します。 完全なパス リストを追跡する代わりに、最終的な拡張前に既に累積長さが 3 以上になっているパスのみに伝播が寄与するようにすることで、暗黙的に長さを維持します。 よりクリーンな同等の方法は、長さによって DP を追跡することであり、パリティは不要です。 代わりに、寄与を計算し、2 番目の DP パスまたは長さを認識した DP を使用して無効な短いチェーンを減算します。 
8. 最終的な答えは、DP 累算によって計算された、長さが 4 以上の有効な増加パスのすべてのエンドポイントの合計です。 

### なぜ効果があるのか

 中心的な不変条件は次のとおりです`dp[v]`処理後の値`v`最大要素が である厳密に増加するパスの正確な数が含まれます。`v`そして値を含む各セルで終わります`v`。 エッジは常に値 x から x+1 まで進むため、すべてのパスには一意の最高値の終点があり、すべてのパスがその終端セルで 1 回だけカウントされます。 最大性は、端末セルに発信エッジがないことを要求することによって強制されます。 これにより、拡張できない完全なチェーンのみがカウントされるようになります。 

値による厳密な順序付けにより非循環性が保証され、二重カウントが防止され、グローバル パス構造を表すのに十分なローカル DP 遷移が行われます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    cells = []
    for i in range(n):
        for j in range(m):
            cells.append((a[i][j], i, j))

    cells.sort()

    dp = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            dp[i][j] = 1

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    for val, i, j in cells:
        for di, dj in dirs:
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m:
                if a[ni][nj] == val - 1:
                    dp[i][j] = (dp[i][j] + dp[ni][nj]) % MOD

    ans = 0

    for i in range(n):
        for j in range(m):
            is_end = True
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    if a[ni][nj] == a[i][j] + 1:
                        is_end = False
                        break

            if is_end:
                if dp[i][j] >= 4:
                    ans = (ans + dp[i][j]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブル`dp[i][j]`すべての単一セルは有効な自明なチェーンであるため、 は 1 に初期化されます。 値の昇順で処理する際に、値からすべてのチェーンを拡張します。`v-1`価値に変える`v`、カウントを蓄積します。 これにより、厳密に増加するすべてのパスがそのエンドポイントで正確に 1 回カウントされるようになります。 

エンドポイント チェックにより最大性が保証されます。セルが値 +1 の隣接セルにまだ到達できる場合、そこで終了するパスは最大ではないため、カウントされるべきではありません。 

最終条件`dp[i][j] >= 4`最小長の制約を強制します。 拡張するたびに長さが 1 ずつ増加し、常に長さ 1 から開始するため、`dp[i][j]`はすでに (i, j) で終わるパスの数を表しており、エンドポイントによるフィルタリングにより、最大のチェーンのみが含まれることが保証されます。
