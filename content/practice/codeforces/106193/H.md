 ## 解決策
 ## 問題の理解

 私たちに与えられた小容量のマルチセット ゲームでは、状態は単なる整数のコレクションであり、それぞれの値は常に 2 または 4 から始まる 2 のべき乗のような値であり、値を変更する唯一の方法は、等しい数値をペアにして、それらをより大きな数値にマージすることです。 2 つの等しい値の各マージ`x`それらを削除して生成します`2x`、さらにスコアが増加します`2x`。 逆の質問をされます: 与えられた最終スコアについて、最大でも何らかのサイズのマルチセットで終わる有効な挿入とマージのシーケンスが存在するかどうかを判断してください。`k`、そうであれば、そのような最終的なマルチセットを 1 つ構築します。 

重要な点は、ゲームの歴史全体を再構築することは求められていないということです。 一連の操作の後に発生する可能性のある最終的なマルチセットを出力する必要があるだけです。 スコア制約は、マージのすべての隠された構造をエンコードします。 

マルチセットのサイズに対する制約は非常に厳しく、`k ≤ 16`、クエリの数は最大で`10^4`、各ターゲット スコアは次のように大きくできます。`10^9`。 これにより、プロセスの進行をシミュレートしたり、一連の操作を検索したりするアプローチは即座に排除されます。 有効な解決策は、問題を最大 16 要素のサイズの構造に関する推論に帰着させる必要があります。 

微妙なエッジ ケースは、マージ順序が異なると、最終的なマルチセットは同じでもスコアが異なる可能性があることです。 たとえば、から始めて、`{2,2,2,2}`、ペアを 2 つの 4 にマージしてから再度マージするか、別の方法でマージを遅らせることができますが、最終的なスコアは内部マージが何回発生するかによって異なります。 「2 と 4 がいくつ残るか」だけを考える単純な貪欲な再構築は、マージの深さ構造を無視するため失敗します。 

もう 1 つの落とし穴は、マージの最大化が常に正しいと想定していることです。 可能な限り常にマージすると、残りの要素の数が最小限に抑えられますが、非常に具体的なスコアも修正されます。 この問題は存在を要求するため、マージ構造を最大化するだけでなく、制御できる必要があります。 

## アプローチ

 直接的なブルート フォース アプローチでは、挿入操作とマージ操作のすべての可能なシーケンスをシミュレートしようとし、最大でもサイズのすべての可能な端末マルチセットで停止します。`k`、スコアを記録します。 これは直ちに実行不可能です。`k`が小さい場合、ゲーム履歴の数は、マージ決定と挿入順序が発生するたびに指数関数的に増加します。 各状態で 2 または 4 を挿入するか、マージする少なくとも 2 つのコピーを持つ任意の値を選択できるため、分岐係数は大きくなります。 

重要な構造的観察は、プロセス全体を完全なバイナリ ツリーのフォレストを構築するものとして逆に見ることができることです。 各マージは 2 つの同一のノードを 2 倍の値を持つ親ノードに結合し、そのような各マージはノ​​ード値の 2 倍に等しいスコアに寄与します。 これを逆にすると、各最終要素はリーフであり、すべてのマージは、リーフが最終マルチセット要素であるバイナリ ツリーの内部ノードに対応します。 

これにより、問題は動的なプロセスから静的な組み合わせ構造に変換されます。`k`それぞれに 2 または 4 のラベルが付いた葉を作成し、それらを接続してバイナリ ツリーを作成します。 各内部ノードは、その値のみに基づいてスコアに決定的な量を寄与するため、合計スコアは操作順序ではなく、ツリー構造とリーフ ラベルのみに依存します。 

なぜなら`k ≤ 16`、最大 16 個の葉にわたってすべての有効な二分木の形状を列挙し、結果のスコアがターゲットと一致するように各形状に対して葉の値 (2 または 4) を割り当てることができるかどうかを確認できます。

 ## アルゴリズムのチュートリアル

 このプロセスを、リーフが最終的なマルチセット要素に対応し、内部ノードがマージに対応する完全なバイナリ フォレストを構築するものとして再解釈します。 

各リーフには 2 または 4 の値が割り当てられます。すべての内部ノードは 2 つの同一の子を取ります。`x`、になります`2x`、貢献します`2x`スコアに。 これは、ツリー構造と葉のラベルを修正すると、スコアが完全に決定されることを意味します。 

以下のように進めていきます。 

1. クエリ スコアごとに、可能なマルチセット サイズを反復処理します。`s`1から`k`。 最終的なマルチセットには次のサイズが必要です`s`。 
2. それぞれについて`s`、すべての完全なバイナリ ツリー形状を列挙します。`s`葉。 それぞれの形状は、可能なマージ履歴トポロジを表します。 これが可能なのは、`s`は最大 16 であるため、形状の数は DP 構築で管理可能です。 
3. 固定されたツリー形状の場合、各葉を値 2 または 4 を割り当てることができる変数として扱います。ツリーによって誘発されるスコアに対する考えられるすべての寄与を計算します。 これは、上向きのシミュレーションによって行われます。各内部ノード値はその子によって決定されるため、リーフが固定されると、ツリー全体が決定されます。 
4. リーフ値の割り当てごとに、すべての内部ノードの寄与を合計することによって結果のスコアを計算します。 いずれかの割り当てがターゲット スコアと一致する場合、そのリーフ割り当てを最終マルチセットとして出力します。 
5. 木の形状と葉の割り当てが目標スコアを生成しない場合、出力`-1`。 

これを有効にする重要な制約は、すべての有効なマージ シーケンスがバイナリ フォレストに正確に対応し、すべてのバイナリ フォレストが元のゲーム内の少なくとも 1 つの有効なマージ シーケンスに対応することです。 

### なぜ効果があるのか

 マージ操作は構造的に結合的です。常に等しい値を結合し、決定的な親ノードを生成します。 これにより、マージの有効なシーケンスによって、最初の要素に対して一意のバイナリ ツリーが誘導されます。ここで、リーフは最後に生き残る要素であり、内部ノードはマージです。 スコアは内部ノードとその値のみに依存し、これらの値はツリーとリーフのラベルによって完全に決定されます。 考えられるすべての木の形状をサイズまで列挙しているため、`k`、およびすべてのリーフのラベル付けで、到達可能なすべての構成をカバーします。 構築されたすべてのツリーが実際のマージ シーケンスに対応するため、無効な構成は生成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

# Precompute all full binary tree shapes with up to 16 leaves.
# We represent a tree as a tuple of (left, right) or a leaf as None.
# We only care about structure and leaf counts.

@lru_cache(None)
def gen_trees(n):
    if n == 1:
        return [None]
    res = []
    for l in range(1, n):
        r = n - l
        for lt in gen_trees(l):
            for rt in gen_trees(r):
                res.append((lt, rt))
    return res

# Given a tree and leaf assignments, compute score and multiset
def eval_tree(tree, leaves):
    idx = 0

    def dfs(node):
        nonlocal idx
        if node is None:
            v = leaves[idx]
            idx += 1
            return v, [v]
        lv, lnodes = dfs(node[0])
        rv, rnodes = dfs(node[1])
        if lv != rv:
            return None, None
        v = lv * 2
        score_here = v * 2
        sv, snodes = dfs.score_acc, dfs.nodes_acc  # dummy to silence lint
        return v, lnodes + rnodes

    # We need a cleaner simulation: do postorder
    score = 0

    def dfs2(node):
        nonlocal idx, score
        if node is None:
            v = leaves[idx]
            idx += 1
            return v
        a = dfs2(node[0])
        b = dfs2(node[1])
        if a != b:
            return -1
        score += 2 * a
        return 2 * a

    idx = 0
    score = 0
    root_val = dfs2(tree)
    if root_val == -1:
        return None
    return score

def solve():
    n, k = map(int, input().split())
    hs = [int(input()) for _ in range(n)]

    # cache trees
    trees = []
    for i in range(1, k + 1):
        trees.append(gen_trees(i))

    for h in hs:
        found = False

        for s in range(1, k + 1):
            for tree in trees[s - 1]:
                # try all leaf assignments
                # 2 choices per leaf
                def backtrack(i, arr):
                    nonlocal found
                    if found:
                        return
                    if i == s:
                        # evaluate
                        val = eval_tree(tree, arr)
                        if val == h:
                            print(s, *arr)
                            found = True
                        return
                    for v in (2, 4):
                        arr.append(v)
                        backtrack(i + 1, arr)
                        arr.pop()

                backtrack(0, [])

                if found:
                    break
            if found:
                break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```コードは、次のサイズまでのすべてのバイナリ ツリー形状を構築します。`k`、次に、リーフ値のすべての割り当てを試みます。`{2,4}`形状ごとに。 割り当てごとに、ボトムアップでマージをシミュレートし、マージが発生するたびにスコアを蓄積します。 計算されたスコアがクエリと一致する場合、そのリーフ マルチセットが出力されます。 

微妙な点は、シミュレーションではリーフの固定順序走査が想定されているため、すべてのツリーが一貫してリーフを線形リストにマップする必要があることです。 これが、単一の DFS 順序を使用してリーフ値を割り当てる理由です。

 ## 特殊なケース

 重要なエッジ ケースは、ターゲット スコアがゼロの場合です。 これは、マージがまったく行われない構成に相当します。つまり、すべてのリーフが分離されます。 スコアに寄与する内部構造を持たないツリー形状が含まれるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジケースは次のような場合です`k = 1`。 この場合、マージは不可能であるため、達成可能なスコアはゼロのみです。 肯定的なクエリはすべて即座に失敗しますが、単一の葉を持つツリーには内部ノードがないため、列挙にはこれが正しく反映されます。 

3 番目のエッジ ケースは、すべてのリーフが同一である (すべて 2 またはすべて 4) 場合です。 これらのケースでは、高度に制約されたマージ構造が生成され、多くの場合、スコアの小さなサブセットのみが許可されます。 両方の均一な割り当てが明示的にテストされるため、リーフ値に対する徹底的な割り当てにより、これらが適切にカバーされることが保証されます。
