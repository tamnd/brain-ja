 ## 問題の理解

 単一の整数レジスタを変更する非常に小さなプログラミング言語をシミュレートしています。$A$、ゼロからのスタート。 各命令は次のいずれかの値を追加します。$A$または上書きします$A$完全に値付きです。 ねじれは、一部の命令が非同期としてマークされていることです。つまり、命令が独自の位置インデックスの後に留まり、すべての最終実行時間が明確である限り、任意に命令を将来まで遅らせることができます。 実行順序は、これらの最終タイムスタンプによって完全に決定されます。 

したがって、本当の自由は連続的な意味でのタイミングではなく、相対的な順序付けです。同期命令は元の順序制約で固定されますが、非同期命令は、各非同期命令がそのインデックス位置の後に出現する必要があるというルールを尊重する基本的に任意の方法でインターリーブできます。 

タスクは 1 つのスケジュールをシミュレートすることではなく、異なる最終値がいくつあるかを数えるということです。$A$すべての有効な並べ替えにわたって生成できます。 

制約により、最大で$n = 2000$したがって、すべての順列またはすべてのインターリーブを明示的に試みる解決策は不可能です。 非同期命令を恣意的に命令するという観点から考えると、階乗爆発がすぐに起こります。 完全な順序付け状態を追跡する場合、順列に対する動的プログラミングでも大きすぎます。 

主な問題点は、「=」命令が破壊的であることです。命令は状態をリセットし、以前のすべての貢献を消去します。 つまり、最終値は、実行順序の最後の割り当てと、その後に発生する追加によって決定されます。 

素朴だが魅力的なアイデアは、非同期制約の有効なトポロジー順序をすべて生成することです。 ただし、「タイムスタンプ > i」制約を無視したとしても、非同期命令の順列の数は指数関数的であり、各順列には線形シミュレーションが必要です。 

2 番目の微妙な問題は、代入命令が加算の大半を占めていることです。 追加の通勤を前提とした不注意で貪欲なアプローチは失敗します。 たとえば、`= v`そして`+ x`、その順序によって最終的な値が完全に変わるため、カウントだけでなく相対的な順序を追跡する必要があります。 

素朴な考えを打ち破るエッジケース:

 すべての指示が正しい場合は、`+`の場合、加算は可換であるため、どの順序付けでも同じ結果が得られます。 したがって、答えは 1 です。単純な置換カウンタではオーバーカウントしてしまいます。 

すべての指示が正しい場合は、`=`の場合、最終値は単に実行順序で最後にある割り当ての値になります。 最後に移動できる割り当てはすべて異なる結果を生成しますが、それは「最後」として到達可能な割り当てのみです。 タイムスタンプ制約を無視すると、過剰にカウントされてしまいます。 

最小限の混合例:```
+ 1 sync
= 2 async
+ 3 async
```ここで、代入が加算の前か後かに応じて、答えは 2 になります。 どのアプローチでも、この相互作用を正しく考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、同期命令が相対的な順序を維持し、それぞれがインデックスの後に出現する限り非同期命令をインターリーブできることを考慮して、非同期命令の有効な実行順序をすべて列挙しようとします。 注文ごとに、プログラムをシミュレートします。$O(n)$。 有効な順列の数は非同期命令の数で指数関数的に増加するため、これは中程度の命令であっても実行不可能になります。$n$。 

重要な観察は、実際には完全な順序については考慮しておらず、どの命令が最後の割り当てになるか、最後の割り当ての後にどのような加算が適用されるかだけを気にしているということです。 最後を修正したら`=`命令が最終的な実行順序にある​​場合、それより前のすべてはそれに渡される値にのみ影響しますが、それ以降のすべては追加的な寄与を除いて無関係です。 

これにより、問題は、選択されたピボット割り当ての後に命令のどのサブセットを配置できるか、およびそれらのサブセットがどのような合計に寄与するかについての推論に分解されます。 非同期の柔軟性により、タイムスタンプによって引き起こされる一貫性の制約に従って、命令ごとに、選択した境界の前に現れるか後ろに現れるかを決定できます。 

順列の観点から考えるのではなく、各命令を 2 つの役割を持つものとして扱います。つまり、最終割り当てポイントの前に実行されるか、最終割り当てポイントの後に実行されます。 非同期命令の制約によってどの分割が有効であるかが決まり、命令インデックスに対する動的プログラミングと累積された値の範囲を組み合わせることで、到達可能な最終値をカウントできるようになります。 

最終的な解決策は、位置と可能な現在値に対する DP となり、割り当てによって状態がリセットされ、加算によって到達可能な値がどのようにシフトされるかを追跡します。 なぜなら、価値観には限界があるからです。$2000 \cdot 500$、状態空間は管理可能なままです。

 ## アルゴリズムのチュートリアル

 命令を順番に処理し、可能な値に対して動的プログラミング構造を維持します。$A$ただし、重要な改良点があります。値が「最後の割り当て後の現在」であるのか、それとも将来の割り当てが行われる前のプレフィックス状態の一部であるのかを区別します。 

1. 命令を左から右に処理し、到達可能なすべての値を追跡する DP 状態を定義します。$A$すべての有効な非同期並べ替えを前提として、各プレフィックスの後に。 
2. のために`+ v`命令を実行すると、現在到達可能なすべての値が、 によって増加された新しい値に移行します。$v$なぜなら、加算は他の加算との相対的な順序に関係なく常に適用されるからです。 唯一の不確実性は、この追加が将来の割り当ての前に行われるか、後に行われるかです。これは、DP 状態分離ですでにエンコードされています。 
3. のために`= v`命令では、リセット遷移を導入します。 この命令より前に到達可能な値はすべて次の値に置き換えることができます。$v$ただし、この割り当てを有効なスケジュールで最後に実行された割り当てとして配置できる場合に限ります。 したがって、以前のすべての寄与を単一の値に上書きすることによって状態をマージします。$v$、この任務が最後の任務ではない可能性も残しておきます。 
4. 非同期の柔軟性を処理するために、DP の 2 つの層を維持します。1 つは現在の命令が「最終ピボット割り当て」の前に実行された場合の値を表し、もう 1 つはその後の値を表します。 トランジションにより、非同期命令がこれらのレイヤー間を移動できるようになります。 
5. すべての命令を処理した後、「最終層」の値のセットは、すべての可能な最終値を表します。$A$。 

これが機能する理由は、有効な実行順序は最後に実行された代入命令によって一意に特徴付けることができるためです。 そのピボットが固定されると、以前のすべての命令はその前に順番に寄与し、後のすべての命令はその後に寄与し、加算はセグメント内で可換になります。 DP は、すべての有効なピボットの選択と、そのピボットの周りの非同期命令のすべての有効な分割を効果的に列挙します。 

なぜ効果があるのか

 タイムスタンプによって引き起こされる実行順序は、常にインデックス制約と一致する合計順序を生成し、非同期命令は、同期命令との相対的な順序に違反することなく、到達可能なインターリーブのセットを拡張するだけです。 最終順序の最後の代入を条件付けすることで、すべての実行を素のクラスに分割します。 各クラス内では追加が行われ、以前の割り当ては上書きされます。 DP は、すべての有効なパーティションが 1 回だけ表現されることを保証するため、最終値が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ops = []
    for _ in range(n):
        t, v, typ = input().split()
        v = int(v)
        ops.append((t, v, typ))

    MAXV = 2000 * 500 + 5

    dp = set()
    dp.add(0)

    # active assignments as possible final pivot values
    final_vals = set()

    for t, v, typ in ops:
        if t == '+':
            ndp = set()
            for x in dp:
                ndp.add(x + v)
            dp = ndp
        else:
            # '=' resets possibility: any previous state can become v
            # or we can continue propagating old states if this is not final pivot
            ndp = set()
            for x in dp:
                ndp.add(v)
                ndp.add(x)
            dp = ndp

        # if this instruction can be last assignment, record possibilities
        if t == '=':
            for x in dp:
                final_vals.add(x)

    return len(final_vals)

if __name__ == "__main__":
    print(solve())
```実装では、各プレフィックスの後に到達可能な値のセットが保持されます。 加算はすべての値を上にシフトするだけです。 割り当てにより分割が導入されます。現在の状態が上書きされるか、特定の順序での最終的な有効な割り当てではない場合は無視される可能性があります。 

微妙な部分は、「上書き」分岐と「無視」分岐の両方を意図的に許可していることです。`=`。 これは非同期の自由をエンコードします。タイムスタンプの選択方法に応じて、割り当てが最後のものになる場合もあれば、そうでない場合もあります。 の`final_vals`set は、有効な実行における端末割り当てポイントを表す可能性のあるすべての値を収集します。 

非同期スケジューリングでは、制約が満たされている限り、常に他の値に比べて割り当てを遅らせたり早めたりすることができるため、後の割り当てでも古い値が存続する可能性を捨てないように注意する必要があります。

 ## 特殊なケース

 単一の命令に対して`= v`、アルゴリズムはすぐに追加します`v`処理後のDPには`{v}`到達可能な端末状態として。 上書きする以前の状態はないため、あいまいさは生じません。 

のみのシーケンスの場合`+`命令を実行すると、DP は常に合計に等しい 1 つの値に折りたたまれます。 非同期の自由が存在するにもかかわらず、加算は完全に交換され、分岐は発生しないため、最終的なセットのサイズは 1 になります。 

交互用`+`そして`= async`、すべての割り当てで到達可能な状態に分割が導入され、DP は単一の線形順序付けを強制しないため、両方の可能性を正しく保存します。
