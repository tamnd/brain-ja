 ## 解決策
 ## 問題の理解

 ランダム蓄積カウンターのように動作するプロセスが与えられています。 ルーシーがロール ボタンを押すたびに、間隔から均一に抽出された独立したランダムな値だけカウンターが増加します。$(0, d)$。 いつでも回転を止めて撤退を押すと、現在の実際の値が変換されます。$S$と等しいチケットに$\lceil S \rceil$、その後カウンターはゼロにリセットされます。 

ルーシーの予算は限られています$n$ロールと正確に$k$引き出し。 彼女は、各ロールの後に、蓄積を続けるか、停止してすぐに現金化するかを適応的に決定でき、正確な現在の価値を確認できます。$S$無限の精度で。 

目標は、すべてを実行した後に予想されるチケットの総数を最大化することです。$n$ロールと正確に$k$引き出し。 

重要な構造は、出金ごとに一連のロールが次のように分割されることです。$k$セグメント、各セグメントが貢献$\lceil \text{sum of rolls in that segment} \rceil$。 したがって、決定は不確実性の下での動的な分割の問題です。つまり、期待される丸められた合計を最大化するために、ランダムな増分のシーケンスをどこでカットするかを選択しています。 

この制約は、次の二次方程式の解が存在することを意味します。$n$原則としてテストごとに許容されます。$n \le 2000$最大 2000 のテストがあります。 これが私たちを後押しします$O(n^2)$またはテストごとに償却された DP アイデアを使用し、状態ごとの連続分布のシミュレーションやモンテカルロ手法を除外します。 

微妙な点は、四捨五入が引き出し時にのみ行われることです。 これにより、目標値は増分合計において非線形になり、期待値の単純な線形性だけでは不十分になります。 

一般的な失敗モードは、各ロールが独立して予想される結果に寄与すると仮定することです。$(d+1)/2$チケットはすぐに撤回されます。 これは、すべてのロールが独自のセグメントである場合にのみ正しいですが、セグメントに複数のロールが含まれるとすぐに壊れます。$\lceil x+y \rceil \neq \lceil x \rceil + \lceil y \rceil$期待して。 

たとえば、$d=1$、2 つのロールはグループ化に応じて動作が異なります。 2 つのロールの 1 つのセグメントでは、生の期待合計が同じであっても、2 つの別々の出金とは異なる期待四捨五入が行われます。 この相互作用こそが、問題を重要なものにしているのです。 

## アプローチ

 最も直接的な解釈は、すべての分割方法を試してみることです。$n$転がる$k$連続したセグメント。 固定パーティションの場合、期待値は、次の期待値のセグメントにわたる合計です。$\lceil X \rceil$、 どこ$X$は、そのセグメントの一様確率変数の合計です。 ブルートフォースソリューションでは、すべての構成を列挙します。$n$の中へ$k$ある部分$\binom{n-1}{k-1}$、それぞれについて期待値を計算します。 これは指数関数的です$n$そしてすぐに実行不可能になります。 

次のステップは、最適な下部構造を認識することです。 最初の引き出しがその後に行われることを修正したら、$x$ロールが終了すると、プロセスがリセットされるため、残りの問題は過去とは独立しています。 これにより、古典的なナップザック スタイルの繰り返しが得られます。$dp[i][j]$を使用して最良の期待値として$i$ロールと$j$引き出し。 移行するには、最初のセグメントの長さをすべて試してみる必要があります。 

残るのは、関数の計算という核心的な難しさです。$f(x)$、の期待値$\lceil S_x \rceil$、 どこ$S_x$の合計です$x$i.i.d. 均一変数$(0,d)$。 これが分かれば、残りは標準パーティション DP になります。 

重要な構造観察は次のとおりです。$S_x$は継続的なディストリビューションであり、$(0, xd)$、その密度は均一な密度の畳み込みです。 予想される上限は、次の整数部分の分布にのみ依存します。$S_x$、 以来$\lceil S_x \rceil = \lfloor S_x \rfloor + 1$ほぼ確実に。 

したがって、問題は確率を計算することに帰着します。$S_x$各単位間隔にあります$[t, t+1)$。 これは、分布の畳み込みを介した DP を介して実行でき、本質的には次のようにスケーリングされた Irwin-Hall 分布を構築します。$d$、整数境界で離散化されます。 

一度$f(x)$すべてについて事前に計算されます$x \le n$、外側の DP は単純になります。

 ## アルゴリズムのチュートリアル

 ### 1. セグメント値を事前計算する$f[x]$可能なセグメント長ごとに$x$の期待値を計算します。$\lceil S_x \rceil$、 どこ$S_x$の合計です$x$独立一様確率変数$(0,d)$。 

私たちは次のようなディストリビューションを構築します$S_x$繰り返して。 のために$x=1$、密度は均一です。 追加のロールごとに、以前の分布を一様分布と畳み込みます。 完全な連続密度を追跡する代わりに、整数間隔にわたる確率質量のみを追跡します。$[t, t+1)$、これらの間隔が天井を完全に決定するためです。 

これにより、問題は整数ビンにわたる離散確率質量の繰り返しの畳み込みに変わり、これは次のように維持できます。$O(n^2)$テストごとに。 

### 2. 分布を期待値に変換する

 わかったら$P(\lfloor S_x \rfloor = t)$、というアイデンティティを使用します。$\lceil S_x \rceil = t+1$いつでも$S_x \in [t, t+1)$。 したがって$f[x]$は、これらの確率の加重合計です。 

### 3. ロール数と引き出し数に関する動的プログラミング

 私たちは定義します$dp[i][j]$予想されるチケットの最大数として、$i$ロールと$j$引き出し。 

州ごとに長さを選択します$x$最初のセグメントの、コストを支払う$f[x]$、そして残りの部分問題を解決します$dp[i-x][j-1]$。 

### 4. 最終的な答え

 答えは$dp[n][k]$。 

### なぜ効果があるのか

 各決定点はプロセスを完全にリセットするため、セグメントの長さが固定されると、セグメントの寄与は独立します。 すべての確率論はその中に含まれています$f[x]$、セグメントに対する正確な期待値を取得します。 DP は追加のセグメント コストに対する決定論的な最適化となり、セグメント間の依存関係が失われたり二重にカウントされたりしないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, d):
    # dp_dist[i][s] = probability mass that sum of i rolls falls into bin s (integer part)
    # We only keep integer part distribution; fractional structure is implicit in convolution.
    
    max_s = n * d
    dp = [0.0] * (max_s + 2)
    dp[0] = 1.0
    
    # distribution for 1 roll
    base = [0.0] * (d + 1)
    for i in range(d):
        base[i] = 1.0 / d
    
    # f[x] expected ceil value
    f = [0.0] * (n + 1)
    
    cur = [0.0] * (max_s + 1)
    cur[0] = 1.0
    
    for x in range(1, n + 1):
        nxt = [0.0] * (max_s + 1)
        
        # convolution step (discretized)
        for i in range((x - 1) * d + 1):
            if cur[i] == 0:
                continue
            for v in range(d):
                nxt[i + v + 1] += cur[i] * (1.0 / d)
        
        cur = nxt
        
        # compute expected ceil
        exp_val = 0.0
        for s in range(x * d + 1):
            if cur[s] == 0:
                continue
            exp_val += (s + 1) * cur[s]
        
        f[x] = exp_val
    
    dp = [-10**18] * (n + 1)
    dp[0] = 0.0
    
    for i in range(1, n + 1):
        for x in range(1, i + 1):
            dp[i] = max(dp[i], dp[i - x] + f[x])
    
    return dp[n]

t = int(input())
for _ in range(t):
    n, k, d = map(int, input().split())
    print(solve_case(n, k, d))
```畳み込み部分は、各ロール数の後に合計の正確な分布を構築し、整数のビンの質量のみを追跡します。 重要なアイデアは、各ロールが確率の質量を全体にわたって均一にシフトするということです。$d$これが、ネストされたループによってインデックスが増加する理由です。$v+1$。 

次に、外側の DP は、考えられる各セグメント長を値を持つ候補「項目」として扱います。$f[x]$。 最後の DP は、標準的なパーティション分割ナップザックです。 

最もデリケートな部分は、セグメント サイズを増加させながら畳み込みが確実に行われるようにすることです。$f[x]$から構築されています$f[x-1]$状態を混合せずに。 一様シフトのインデックス作成時に 1 つずつずれたエラーがあると、分布が歪み、期待値の計算が中断されます。

 ## 特殊なケース

 いつ$k = n$、すべてのロールはすぐに取り出される必要があるため、各セグメントの長さは 1 になります。アルゴリズムは計算に帰着します。$f[1]$を繰り返し、これは次の期待値と等しくなります。$\lceil U(0,d) \rceil = (d+1)/2$。 必要な引き出し数を考慮すると、これより大きなセグメントは実行不可能であるため、DP は当然サイズ 1 のすべてのセグメントを選択します。 

いつ$k = 1$、すべてのロールが単一のセグメントに強制的に配置されます。 DP は決して分割されないため、答えは正確に次のようになります。$f[n]$、畳み込みベースの計算により、合計の分布が正確に取得されます。 

いつ$d = 1$、すべてのロールは決定的であり、分布は崩壊します。 畳み込みは毎回単一のシフトされた塊に縮退します。$f[x] = x$、そして DP は線形コストを伴う純粋な分割問題に帰着します。
