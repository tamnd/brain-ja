 ## 解決策
 ## 問題の理解

 私たちは、すべての整数座標セルが独立して等しい確率で黒か白のいずれかに着色される無限グリッドを使用しています。 許可される唯一の操作は、セルをクエリしてその色を受け取ることです。 各テスト ケースの目標は、正確なセットを出力することです。`n`すべて同じ色であり、8 方向の隣接の下で単一の接続コンポーネントを形成する個別のセル。つまり、接続を定義するときに斜めの移動も許可されます。 

重要な困難は、接続性を構築することではなく、無限のランダム フィールド上でポイント クエリのみを使用して、十分に大きな単色の接続コンポーネントを見つけることです。 グリッドは無限であるため、探索に役立つ境界はなく、最初はすべてのセルが不明です。 

制約は主にクエリ バジェットの点で重要です。 すべてのテスト ケースで最大 30,000 のクエリが許可され、最大 50 のテスト ケースが許可されます。`n`これにより、広い領域を完全に探索したり、密集した領域ですべての候補を体系的に列挙しようとする戦略は即座に排除されます。 どのソリューションでも、コンポーネントを遅延的に拡張し、切断された領域をあまりにも多く再訪問することを避ける必要があります。 

素朴だが危険な考えは、開始セルを選択し、隣接セルをクエリしながら BFS 領域を拡張しようとすることです。 問題は、ランダムに開始されるセルの連結成分が小さい可能性があるため、このアプローチでは、より少ないセルで早期に終了する可能性があることです。`n`到達可能な同じ色のセル。 もう 1 つの障害モードは、近くの場所から BFS を繰り返し再起動することです。これにより、重複するコンポーネントやすでに探索されている小さなコンポーネントに対するクエリが無駄になる可能性があります。 

微妙なエッジケースは、初期の探索で、ほぼ全体が反対の色に囲まれた非常に小さな単色のクラスターを発見した場合です。 たとえば、単一の黒いセルが白いセルに囲まれている場合、BFS の拡張は直ちに終了します。 戦略が常にローカルで再起動される場合、このようなトラップに繰り返し遭遇し、サイズに達することなくクエリ バジェットを使い果たす可能性があります。`n`。 

## アプローチ

 ブルートフォースのアイデアは単純です。開始座標を選択してそれを明らかにし、同じ色の 8 つの近傍すべてに拡張する BFS または DFS を実行し、必要に応じて目に見えない各近傍をクエリします。 これにより、その色の最大連結成分が正しく構築されます。 問題は、ランダム グリッドではほとんどのコンポーネントが小さく、ランダム セルを含むコンポーネントの予想サイズが 300 に達することが保証されていないことです。コンポーネントが小さすぎるたびにこのプロセスを再起動すると、繰り返し小さな有限クラスターに陥る可能性があります。 決定論的戦略の最悪のシナリオでは、各試行は失敗する前に小さな領域のみを探索する可能性があり、多数の無駄なクエリが発生します。 

重要な観察は、個々のコンポーネントは小さいかもしれないが、無限グリッドには多くのばらばらの領域が含まれており、一定の割合の細胞が、消滅する前に大幅に成長するのに十分な大きさのコンポーネントに属しているということです。 これは、償却戦略を示唆しています。つまり、以前の探査から遠く離れた新しいシード ポイントを繰り返しサンプリングし、それらの接続された単色コンポーネントを完全に拡張します。 コンポーネントは独立しており、探索はローカルであるため、成功した各大きなコンポーネントはサイズの達成に直接貢献します。`n`一方、失敗した試行では、小さなコンポーネントのサイズに比例した制限された作業のみが消費されます。 

重要な構造上のトリックは、グリッドをブラック ボックスのランダム グラフとして扱い、十分に大きな連結成分が見つかるまで「プローブとフラッドフィル」を繰り返すことです。 サイズのコンポーネントが 1 つだけ必要なので、`n`、グローバル構造は気にせず、最初に遭遇する十分に大きなローカル構造だけを気にします。

 | 体系的なグリッド探索 | O(R²) 個の領域 R に対するクエリ | O(R²) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 すべての試行にわたって訪問したセルのセットを維持し、収集するまで単色コンポーネントの成長を繰り返し試行します。`n`細胞。 

1. これまでに使用されていない新しいシード座標から開始します。たとえば、次のような固定シーケンスを反復処理します。`(i * 1000, i * 1000)`増やすための`i`。 これは、同じローカル リージョンが繰り返しヒットすることを避けるために行われます。 
2. シード セルをクエリします。 これにより色が得られます`c`、これがこの試行のターゲット色になります。 
3. シード セルを使用して BFS キューを初期化し、訪問済みとしてマークします。 
4. キューは空ではなく、さらに多くのものが必要ですが、`n`セル、セルをポップする`(x, y)`そして、隣接する 8 つの座標をすべて調べます。 
5. 各近隣ノードについて、これまでにクエリが行われたことがない場合は、クエリを実行します。 その色が`c`、それを BFS キューに追加し、現在のコンポーネントの一部としてマークします。 別の色である場合は、ブロック済みとしてマークし、二度とアクセスしないでください。 
6. コンポーネントがサイズに達するまで続行します`n`または、BFS は、到達可能なすべての同じ色のセルを完全に使い果たします。 
7.サイズに達したら`n`、それらをすぐに出力します`n`セルを削除し、テスト ケースを停止します。 そうでない場合は、このコンポーネントを破棄し、新しいシード座標から再開します。 

重要な点は、クエリがグローバルにキャッシュされるため、各セルが最大 1 回クエリされることです。 これにより、異なる BFS 試行が空間内で重複する場合にクエリが無駄にならないようになります。 

### なぜ効果があるのか

 各 BFS は、表示されたグラフ内の 8 連結単色成分を 1 つだけ調査します。 グリッドは無限でランダムに色付けされているため、すべてのセルはそのようなコンポーネントの 1 つに属し、サンプリングを繰り返すと、最終的には十分な大きさのコンポーネントが得られます。 集まった時点で終了となりますので、`n`セルは単一コンポーネントから構成されており、接続は構造によって保証されています。 拡張は同じ色の隣接するエッジに従うだけであるため、このプロセスでは色を混合することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# interactive solution skeleton

sys.setrecursionlimit(10**7)

dx = [-1, -1, -1, 0, 0, 1, 1, 1]
dy = [-1, 0, 1, -1, 1, -1, 0, 1]

seen = {}  # (x,y) -> color

def query(x, y):
    if (x, y) in seen:
        return seen[(x, y)]
    print(f"? {x} {y}", flush=True)
    c = input().strip()
    seen[(x, y)] = c
    return c

def solve_case(n):
    used_seed = 0

    while True:
        sx = used_seed * 1007
        sy = used_seed * 1009
        used_seed += 1

        c = query(sx, sy)

        if c not in ('B', 'W'):
            continue

        q = [(sx, sy)]
        comp = [(sx, sy)]
        comp_set = {(sx, sy)}

        while q and len(comp) < n:
            x, y = q.pop()

            for k in range(8):
                nx, ny = x + dx[k], y + dy[k]
                if (nx, ny) in seen:
                    if seen[(nx, ny)] == c and (nx, ny) not in comp_set:
                        comp_set.add((nx, ny))
                        comp.append((nx, ny))
                        q.append((nx, ny))
                else:
                    col = query(nx, ny)
                    if col == c:
                        comp_set.add((nx, ny))
                        comp.append((nx, ny))
                        q.append((nx, ny))

                if len(comp) >= n:
                    break

        if len(comp) >= n:
            print("! " + c + " " + " ".join(f"{x} {y}" for x, y in comp[:n]), flush=True)
            return

def main():
    t, n = map(int, input().split())
    for _ in range(t):
        solve_case(n)

if __name__ == "__main__":
    main()
```この実装はクエリされたセルのメモ化に依存していますが、異なるシードからの BFS 拡張は重複することが多いため、これは不可欠です。 キャッシュがないと、同じセルが複数回クエリされる可能性があり、すぐに制限を使い果たしてしまいます。 

シードの選択では、密なローカル クラスターを繰り返し調査するのではなく、単純な決定論的な進行を使用して、無限グリッドのさまざまな領域を確実に移動します。 

微妙な点の 1 つは、BFS は同じ色のエッジを通してのみ実行され、反対色のセルをキューに入れることは決してないことです。 これにより、それぞれの`comp`リストは、色の誘導サブグラフ内で常に有効な連結成分です。`c`。 

## 実用的な例

 グリッドはインタラクティブでランダムであるため、小さな固定領域で単純化されたシナリオをシミュレートします。 

原点の周りのグリッドが次のようになっていると仮定します。 

| セル | 色 |
 | --- | --- |
 | (0,0) | B |
 | (1,0) | B |
 | (0,1) | W |
 | (1,1) | B |

 私たちが欲しいのは`n = 3`。 

### トレース

 | ステップ | アクション | キュー | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | クエリ (0,0)=B | [(0,0)] | [(0,0)] |
 | 2 | (0,0) を展開、(1,0) を参照 | [(1,0)] | [(0,0),(1,0)] |
 | 3 | (1,0) を展開、(0,1) を無視 = W | [] | [(0,0),(1,0)] |

 ここではコンポーネントのサイズが 2 であるため、このシードは失敗し、別の場所から再起動します。 

ここで、次のシードがより密度の高い領域にあると仮定します。 

| ステップ | アクション | キュー | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | クエリ (10,10)=W | [(10,10)] | [(10,10)] |
 | 2 | 近傍を展開し、さらに 2 つの W セルを検索します。 成長中 | 成長します |
 | 3 | サイズ 3 に達します | 停止 | 3セル |

 これは重要な動作を示しています。小さなクラスターは早期に終了しますが、より大きなクラスターは、好ましい領域が見つかるとすぐに十分なセルを蓄積します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q) | 各クエリは 1 回処理されてキャッシュされ、BFS の拡張は検出されたセルに比例します。 
| スペース | O(q) | クエリされたすべての座標とその色の保存 |

 支配的な要因はクエリの数です。 各セルは最大 1 回クエリされ、各 BFS 拡張では新しい境界セルが追加されるだけであるため、総作業量は 30000 クエリのグローバル制限内に収まります。 グリッドのランダムな構造により、十分な探索パスが実際に十分迅速に大きなコンポーネントにつながることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、開始シードが、反対色で囲まれた単一のセルなど、小さな孤立したコンポーネント内にある場合です。 BFS はすぐに終了し、サイズ 1 のコンポーネントを返します。アルゴリズムは、結果を破棄し、遠く離れた新しいシードを選択することでこれを処理します。 シードは無限グリッド上を決定論的に移動するため、失敗が繰り返されてもアルゴリズムがローカル領域に閉じ込められることはありません。 

もう 1 つのエッジ ケースは、BFS 試行間で重複が繰り返されることです。 キャッシュがないと、同じ境界セルが繰り返しクエリされ、クエリ バジェットがすぐに無駄になってしまいます。 の`seen`Dictionary では、各座標がグローバルに 1 回クエリされることが保証されるため、オーバーラップは効率を損なうのではなく、効率を向上させるだけです。 

最後のエッジケースは早期の成功です: BFS がすでにサイズに達している可能性があります`n`そのコンポーネントを完全に探索する前に。 アルゴリズムは展開を即座に正しく停止し、最初の`n`収集されたノードはすべてシードから BFS エッジを通じて検出されるため、接続されたままであることが保証されます。
