 ## 解決策
 ## 問題の理解

 問題名の時系列のリストが与えられます。各名前は 2 つの単語で構成されています。 このシーケンスが特定の選択ルールによって生成されたかどうかを検証する必要があります。 

ルールは、シーケンスがどのように構築されるかを説明します。 最初の問題はどんな問題でも構いません。 次のすべての位置について、選択した問題は前に選択した問題と「類似」している必要があります。または、未使用の同様の問題が存在しない場合は、未使用の問題を選択することができます。 

2 つの問題は、同じ最初の単語または同じ 2 番目の単語を共有する場合、類似しているとみなされます。 したがって、類似性は単語の一致を超えた構造の対称性ではなく、純粋に 2 次元ラベル内の 1 つの座標の同等性に基づいています。 

各問題が 1 回だけ使用されたと仮定して、指定されたシーケンスがこのルールに基づいて生成されたかどうかを確認するように求められます。 

制約は大きく、テストごとに最大 10^5 の名前、およびグローバル合計が 10^5 の最大 10^4 のテストです。 これにより、未使用の候補を繰り返しスキャンしたり、ステップごとに残りのすべての項目をチェックしたりするアプローチは二次関数の動作に低下し、制限を超えるため、テスト ケースごとに線形ソリューションが即座に強制されます。 

微妙な問題は、ルールが決定的ではなく、実存的であることです。 各ステップで、未使用の同様の問題が少なくとも 1 つ存在する場合、裁判官はそれらのいずれかを選択できます。 これは、一意のパスを再構築する必要がないことを意味します。 すべてのステップで、利用可能なものを考慮すると、前の選択が有効であったことを確認するだけで済みます。 

素朴な間違いは、同様の未使用の問題が存在する場合、次の要素は前の要素と類似しているに違いないと貪欲に想定することです。 これは不正確です。類似の未使用が存在しない場合、シーケンスは任意に「ジャンプ」できるからです。 たとえば、あるステップで、前の問題に最初の単語または 2 番目の単語の一致が残っていない場合、次の項目は無関係である可能性がありますが、これは依然として有効です。 

もう 1 つの注意が必要なケースは、類似した候補が複数存在するが、一部のみが未使用のままである場合です。 どのノードがまだ利用可能であるかを注意深く追跡する必要があります。 

エッジケースには次のようなものがあります。 

類似性は常に可能ですが、入力によってそれが崩れるシーケンス。 

入力：```
2
a b
c d
```出力：```
Yes
```最初の遷移の後は同様の問題が存在しないため、これは有効であり、どのような遷移も許可されます。 

誤った推論では、「a b」は「c d」に似ていないため、これが拒否されますが、類似の未使用アイテムが存在しない場合、ルールでは任意の選択が許可されます。 

もう 1 つのエッジ ケースは、類似性が存在するにもかかわらず、シーケンスでそれが使用されない場合です。 

入力:```
3
a x
a y
b x
```ここで、「a x」と「a y」は似ているため、最初の後の 2 番目も「a x」に似ている必要があります。これは真実です。 「a y」の後に残る未使用の部分は「b x」ですが、これも 2 番目の単語 x を介して同様であるため、有効な遷移が存在します。 これは有効です。 

重要な点は、有効性は、特定の候補を選択することではなく、各ステップで少なくとも 1 つの未使用の類似候補が存在するかどうかに依存するということです。 

## アプローチ

 ブルート フォース シミュレーションでは、未使用の問題のセットが維持されます。 各ステップで、残りの未使用項目をすべてスキャンし、少なくとも 1 つが現在の問題と最初または 2 番目の単語のいずれかを共有するかどうかを確認します。 そのような項目が存在する場合は続行します。 それ以外の場合は、そのようなアイテムが存在しないことを確認し、次の動作を許可します。 

この単純なシミュレーションは正しいですが、各ステップでは最大 O(n) 個の残りの項目をスキャンする必要があり、最悪の場合、テスト ケースごとに O(n^2) 個の動作が生成されます。 n が 10^5 までの場合、これは不可能です。 

重要な点は、どのような類似要素が存在するかを知る必要はなく、少なくとも 1 つが存在するかどうかだけを知る必要があるということです。 これにより、問題は、最初の単語と 2 番目の単語でグループ化された残りの項目の数を維持することに変わります。 

各最初の単語と各 2 番目の単語を共有する未使用の問題の数を追跡すると、現在のノードに「同様の未使用」候補が存在するかどうかを O(1) でチェックできます。 唯一の微妙な点は、現在のノード自体を二重にカウントしてはいけないことです。そのため、要素を消費するにつれて減少するカウントを維持します。 

これにより、動的セットの検索から度数表の維持までの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ステップのブルート フォース スキャン | O(n^2) | O(n) | 遅すぎる |
 | 単語ごとの頻度カウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべてのペアを読み取り、2 つの頻度マップを作成します。1 つは最初の単語用、もう 1 つは 2 番目の単語用です。 これは、各単語座標で使用可能な未使用アイテムの数を表します。 
2. シーケンスを順番に繰り返し、各問題を「現在」選択されたノードとして扱い、使用されるため両方の周波数マップからの寄与を減らします。 
3. 位置 i から i+1 に移動する前に、ルールに従って次の要素が合法的に選択できたかどうかを確認します。 重要な条件は、前の要素、つまり、移行の時点で同様の未使用の問題が少なくとも 1 つ存在するかどうかに基づいています。 
4. 位置 i にある現在の要素について、最初の単語または 2 番目の単語を共有する未使用の問題の数を計算します。 これは次のように取得されます。 

totalSimilar = freqFirst[first[i]] + freqSecond[second[i]] - オーバーラップ調整

 両方の単語を共有する要素は 2 回カウントされるため、重複の調整が必要です。 ペアの頻度を追跡するか、二重カウントを避けるために慎重にデクリメントします。 
5. i が最後の要素ではなく、totalSimilar が 0 の場合、ルールによって「自由選択」遷移が強制されたことになりますが、指定されたシーケンス構造との一貫性は保証できません。 「いいえ」と返します。 
6. それ以外の場合は続行します。 
7. すべての要素が正常に処理された場合は、「はい」を返します。 

中心となる決定は、ルールに「同様の未使用の問題が存在する」と記載されている場合は常に、それが前進する時点で真である必要があるということです。 シーケンスが暗黙的に true である必要がある場合に false の場合、シーケンスは無効です。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは最初と 2 番目の単語ごとにグループ化された残りの候補の正確な数を維持します。 これにより、シーケンス内のその時点で有効な「同様の動き」が存在するかどうかを正確に判断できるようになります。 不変条件は、位置 i を処理した後、周波数マップがシーケンスの未使用のサフィックスを正確に表すことです。 したがって、位置 i でのチェックはすべて、真の残りのセットに対して実行され、古い情報や一貫性のない情報を使用して移行の決定は行われません。 これにより、必要なすべての「類似の存在」条件が全体にわたって成立する場合にのみ、シーケンスが受け入れられることが保証されます。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        first = []
        second = []
        freq1 = {}
        freq2 = {}

        for _ in range(n):
            a, b = input().split()
            first.append(a)
            second.append(b)
            freq1[a] = freq1.get(a, 0) + 1
            freq2[b] = freq2.get(b, 0) + 1

        used1 = {}
        used2 = {}

        ok = True

        for i in range(n):
            a = first[i]
            b = second[i]

            freq1[a] -= 1
            freq2[b] -= 1

            # remaining similar candidates to current node
            similar = freq1[a] + freq2[b]

            # current node removed, so no need to subtract overlap explicitly:
            # counts already exclude current position after decrement

            if i < n - 1 and similar == 0:
                ok = False
                break

        out.append("Yes" if ok else "No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、最初と 2 番目の単語の頻度マップが構築されます。 反復する際に、両方のマップから現在の要素をデクリメントし、残りの未使用項目を表すようにします。 

キーのチェックは削除後に実行されます。最後の要素に到達しておらず、現在の要素といずれかの座標を共有する要素が残っていない場合、ルールでは強制的な「同様の継続」ステップが許可されないため、シーケンスは有効ではありません。 

微妙な点は、現在の要素が削除されると類似性カウントに寄与できなくなるため、ペアやオーバーラップ補正を明示的に追跡する必要がないことです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、類似性が 1 つの座標を通じてのみ存在するが、消費順序によって消失する場合です。 考慮する：```
3
a x
b x
c y
```「a x」を処理してもまだ「b x」が存在するため、類似性が存在します。 「b x」の後は、最初の単語 b または 2 番目の単語 x を共有する項目は残りません。そのため、次の遷移は自由に選択できる必要があります。 このアルゴリズムは、その時点で類似度が正確にゼロになることを正確に検出し、それが最後の要素である場合にのみ継続を許可します。 

もう 1 つのエッジ ケースは、両方の座標にわたって複数の重複が存在する場合です。 例えば：```
3
a b
a b
a b
```このステートメントでは重複が禁止されていますが、これは原則を示しています。すべてのステップには常に類似性があり、カウンタが早期にゼロになることはないため、シーケンスは受け入れられます。 

最後のエッジケースは、最後の遷移が強制される遅延切断です。```
3
a b
a c
d e
```2 番目の要素を処理した後、「a c」のいずれかの座標に一致するアイテムは残りません。そのため、3 番目の要素が存在する場合、ルールに違反します。 アルゴリズムはこの正確な状態を検出し、シーケンスを拒否します。
