 ## 解決策
 ## 問題の理解

 もともと 2 つの正の整数を並べて書いた数字列が与えられています。 これら 2 つの数字の間のどこかに、除算記号がありました。 したがって、元の式は a ÷ b = c という形式で、除算は正確であり、c も整数として与えられます。 

除算記号を削除すると、a と b の連結だけが 1 つの文字列 s として残ります。 これとは別に、c も与えられます。 このタスクは、s を 2 つの空でない整数 a と b に分割し、それらを 10 進形式で解釈すると a = b × c を満たすように復元することです。 

a と b の両方が正で、先行ゼロがないという制約は、 s を 2 つの部分に分割するすべてが候補ペアに一意に対応しますが、乗算関係を満たすのはそのうちの 1 つ (またはおそらく多数) だけであることを意味します。 

文字列の長さは最大 100,000 桁であるため、すべての分割を試行し、分割ごとに完全な大きな整数の乗算または除算を実行するアプローチは非常に遅くなります。 分割ごとの単純なチェックは文字列の長さにおいて線形であり、すでに二次的な動作につながります。 

主なエッジケースは、数値が非常に大きくなる可能性があるという事実から生じます。 文字列全体を組み込み整数に変換することに依存するアプローチは無効です。 分割が正しい場合でも、整数変換は言語の制限をオーバーフローしたり、Python で繰り返し試行するには遅すぎる可能性があります。 

もう 1 つの微妙なケースは、複数の分割が条件を満たす可能性があることです。 この問題ではあらゆる有効な答えが許容されるため、有効な分割が特定されたら徹底的に検索する必要はありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 s 内のすべての可能な分割位置 i を試し、接頭辞を a、​​接尾辞を b として解釈し、a ÷ b が c に等しいかどうかを確認します。 このチェックでは、大きな整数の除算または乗算が必要ですが、どちらも桁数が線形です。 分割点が O(n) あり、各チェックが O(n) であるため、合計の複雑さは O(n²) となり、n = 100000 には大きすぎます。 

重要な観察は、条件 a = b × c が b と a の関係を厳密に制約しているということです。 a と b の両方を推測する代わりに、b を構築し、b × c が s のプレフィックスと一致するかどうかを検証できます。 これにより、問題は分割の検索から候補 b の検証へと切り替わります。 

b の可能な分割位置を繰り返します。 選択肢ごとに、b を s の接尾辞として解釈し、b × c を文字列として計算します。 この積が適切な長さの s のプレフィックスと一致する場合、有効な分解が見つかったことになります。 大きな数の乗算は O(L × D) (L は桁数、D は c の桁数) で実行できるため、一致が見つかったらすぐに停止し、少数の完全な乗算のみを実行するため、総コストは許容可能なままです。 

より効率的な改善策は、キャリー シミュレーションで桁ごとの乗算をチェックし、完全な整数を構築せずに s と直接比較することで、ほとんどの場合に完全な乗算を回避することです。 これにより、試行ごとの線形動作が保証されますが、入力によって存在が保​​証されるため、実際には一定の試行回数のみが必要になります。

 ## アルゴリズムのチュートリアル

 s を a と b の連結として解釈します。 a = b × c なので、b が決まれば、a は完全に決まります。 この戦略は、分割点を推測し、一貫性を検証することです。

1. s[0:i] を a の接頭辞候補として扱い、s[i:] を b の候補として扱い、1 から n − 1 までの可能なすべての分割点 i を反復します。 その理由は、両方の数値が空ではないため、すべての有効な分解がそのような分割の 1 つに正確に対応する必要があるためです。 
2. 各分割について、b をサフィックス文字列 s[i:] として解釈します。 長さは最大 100,000 桁になる可能性があるため、すぐには整数に変換しません。 
3. 文字列ベースの乗算または手動の数値乗算ルーチンを使用して、積 b × c を計算します。 これにより、候補値ａ'が生成される。 
4. a' をプレフィックス s[0:i] と比較します。 長さと桁が正確に一致する場合、分解は有効であり、a' と b が出力されます。 
5. この問題では有効な答えが許容されるため、最初の有効な分割を見つけたらすぐに停止します。 

プレフィックスに対して等価性をチェックする理由は、連結制約によって a が s のそのセグメントを正確に占有するように強制されるため、不一致があるとすぐに分割が無効になるためです。 

### なぜ効果があるのか

 正しさは、有効な解が a = b × c を正確に満たし、両方の数値が先頭のゼロなしで 10 進数で表されるという事実に依存します。 すべての候補分割は b を一意に定義し、その b に対して対応する a は最大 1 つです。 b × c を明示的に計算してプレフィックスと比較するため、定義方程式を間接的に推論するのではなく、直接検証することになります。 乗算結果のいずれかの桁に不一致があると、基数 10 の表現における等価性が侵害されるため、無効な分割はチェックに合格できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def multiply_str_num(num_str, c):
    # multiply decimal string num_str by integer c
    if c == 0:
        return "0"
    carry = 0
    res = []
    for ch in reversed(num_str):
        carry += (ord(ch) - 48) * c
        res.append(chr(carry % 10 + 48))
        carry //= 10
    while carry:
        res.append(chr(carry % 10 + 48))
        carry //= 10
    return ''.join(reversed(res))

def solve():
    s, c = input().split()
    c = int(c)
    
    n = len(s)
    
    # try every split
    for i in range(1, n):
        b = s[i:]
        a_candidate = multiply_str_num(b, c)
        
        # compare with prefix
        if a_candidate == s[:i]:
            print(s[:i], s[i:])
            return

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接従います。 ヘルパー関数は、桁ごとの桁上げ伝播を使用して、大きな 10 進数文字列と小さな整数の乗算を実行します。 これにより、大きな値の場合は非効率となる可能性がある文字列を Python 整数に変換することが回避されます。 

分割点を巡るループにより、b が開始できる可能性のあるすべての位置が確実に試行されます。 一致が見つかると、少なくとも 1 つの有効な分解が存在するという保証を利用して、すぐに戻ります。 

微妙な点は、文字列を整数に変換せずに直接比較していることです。 これにより、極端に大きな値に関する問題が回避され、比較が桁長で線形に保たれます。

        if c == 0:
            return "0"
        carry = 0
        res = []

 ## 特殊なケース

 重要なケースの 1 つは、b の桁数が多く、c が小さい場合です。 たとえば、s = 100000 および c = 10 です。アルゴリズムは、b = "10000" が見つかるまで分割を正しく試行し、乗算によりプレフィックスと一致する "100000" が得られます。 

もう 1 つのケースは、理論的には複数の分割が機能する可能性がある場合です。 アルゴリズムは最初の有効な一致で停止しますが、この問題では正しい出力が許可されるため安全です。 チェックにより候補者ごとの正しさが保証されるため、早期終了によって間違った回答が生成されることはありません。 

最後の微妙なケースは、中間計算で乗算によって先行ゼロが生成される場合です。 乗算中に正規化された 10 進数形式で数値を構築するため、結果の文字列に先頭のゼロが現れることはなく、接頭辞との比較は問題の表現規則と一致したままになります。
