 ## 解決策
 ## 問題の理解

 上限のグリッドが与えられ、各セルが許容範囲内で独立して選択される同じサイズのすべての整数グリッドを考慮します。 このようなグリッド値の選択ごとに、行の合計と列の合計から形成されるスコアを計算します。 具体的には、すべての行は選択された値の合計に寄与し、すべての列もその合計に寄与し、最終スコアは、これらすべての行の合計とすべての列の合計の積を乗算したものになります。 タスクは、すべての有効なグリッド構成についてこのスコアを合計することです。 

主な問題は、各セルが独立して選択されるにもかかわらず、スコアリング関数が行と列の合計を通じてすべてのセルを結合することです。 単一のセルは 1 つの行の合計と 1 つの列の合計に影響を与えるため、その寄与は局所的ではありません。 

制約$N \cdot M \le 300$が決定的なヒントとなる。 完全なグリッドには最大 300 個のセルが含まれるため、どのソリューションでもセルをプライマリ オブジェクトとして扱い、合計や値に対する大規模な DP ではなく、少数の次元にわたる指数構造または組み合わせ構造に依存することが期待されます。 値自体は次のようになります$10^9$したがって、実際の合計を状態として直接追跡するアプローチは不可能です。 記号的または構造的なカウントのみが実行可能です。 

単純な考えは、すべてのグリッドを列挙し、行と列の合計を直接計算することです。 バイナリ グリッドの場合でも、これは 300 個の変数ですでに指数関数的であり、実現可能な限界をはるかに超えています。 もう 1 つの魅力的なアイデアは、行および列ごとの部分和に対して DP を試すことですが、それぞれの合計は次の値に達する可能性があります。$10^{11}$, そのため、状態空間は天文学的に大きくなります。 

行を独立して処理しようとすると、より微妙な失敗例が発生します。 行の合計のみを考慮すると、列を介した相互作用が失われます。 たとえば、$2 \times 2$グリッドでは、行 1 の値の選択は、行の合計だけでなく両方の列の合計にも影響し、それが行 2 の寄与に影響します。 列を折りたたむのが早すぎるアプローチは、正確性を失います。 

## アプローチ

 主な障害は、スコアがすべての変数の一次式の積であるにもかかわらず、行と列の両方に拡張されていることです。 自然な最初のステップは、これらの積を単項式の合計に拡張することです。 

各行について、項$\sum_j A_{i,j}$行ごとに 1 つの列の選択肢に展開され、選択されたセルの積が提供されます。 同様に、各列の項$\sum_i A_{i,j}$1 列あたり 1 行の選択肢に展開されます。 完全に展開した後、すべての単項式は 2 つの独立した選択に対応します。1 つはすべての行の列を選択する関数、もう 1 つはすべての列の行を選択する関数です。 

これは重要な構造的削減です。 合計を扱う代わりに、式を選択肢のペアの合計に変換します。 それぞれの細胞$A_{i,j}$は、行選択、列選択、またはその両方によって選択されたかどうかに応じて、何度も表示されます。 したがって、各細胞は電力に貢献します$A_{i,j}^k$どこ$k \in \{0,1,2\}$。 

セルは独立しているため、選択の固定ペアの場合、寄与はセルを因数分解して次のようになります。$\sum_{x=0}^{B_{i,j}} x^k$、これは次だけに依存する閉形式の多項式値です。$B_{i,j}$そして$k$。 

残りの問題は、すべての有効な選択ペアを合計することです。 行選択では行ごとに 1 列が割り当てられ、列選択では列ごとに 1 行が割り当てられます。 これらは独立した関数ですが、両方が同じ位置を選択するかどうかを通じて、各セルでローカルに相互作用します。 

重要な観察は、そのようなペアの世界的な数は膨大であるにもかかわらず、相互作用は局所的であるということです。各セルでは、どちらの関数によっても選択されないか、1 つの関数だけで選択されるか、またはその両方によって選択されるかに関係なく、セルごとに 3 つの状態のみが問題になります。 以来$N \cdot M \le 300$では、グリッドを段階的に処理し、部分的に構築された割り当てに対して DP を維持し、どの行と列の一意の選択がすでに修正されているか、およびこれらの選択がどのように交差するかのみを追跡できます。 

セルを固定順序で処理し、部分的な代入構造をエンコードした状態を維持し、最終的にすべての行が正確に 1 つの列を選択し、すべての列が正確に 1 つの行を選択するようにします。 行と列の合計数は合わせて最大 300 であり、それぞれが 1 つのパートナーを正確に選択する必要があるため、「アクティブな決定」の数は制限されており、DP は管理可能なままです。 

この問題は、各行と列が 1 つの出力選択にのみ寄与し、各セルが選択された回数に応じて重みを寄与する、制約付き割り当て DP に帰着します。

 ## アルゴリズムのチュートリアル

 一般性を失うことなく、次のように仮定します。$M \le N$それ以外の場合は、列数が小さい方の次元になるようにグリッドを転置します。 DP 状態は列側の決定を明示的に追跡するため、これは重要です。 

すべてのセルに対して 3 つの値を事前計算します。$(i,j)$その上限に応じて$B_{i,j}$。 1 つ目は選択なし、2 つ目は単一選択、3 つ目は二重選択に対応します。 

1. 各セルについて次のように計算します。$$S_0 = B_{i,j} + 1,\quad
S_1 = \frac{B_{i,j}(B_{i,j}+1)}{2},\quad
S_2 = \frac{B_{i,j}(B_{i,j}+1)(2B_{i,j}+1)}{6}$$これらは次の合計を表します$x^k$セルのすべての許容値にわたって。 
2. 行に対して DP を構築します。各状態は、どの列が必要な「列選択割り当て」をすでに受け取っているか、どの行がまだ自由に列を選択できるかをエンコードします。 状態は、次の場合に列上のビットマスクとして表されます。$M$小さい場合、または圧縮された代入構造の場合$M$中程度です。 
3. 各行について$i$、選択した一意の列を割り当ててみます$j$。 これは、行選択関数で「行」と言うことに相当します。$i$コラムに貢献します$j$。 このような選択ごとに、列の状態が後でこの行とどのように相互作用するかが更新されます。 
4. すべての行の行選択を修正した後、列の選択を個別に評価します。 各列ごとに$j$、正確に 1 行を選択します$i$選択された行パートナーとして。 これにより、各セルでローカルな相互作用が作成されます。$(i,j)$、そのセルが 1 回選択されたか 2 回選択されたかを判断します。 
5. 各列について、選択された可能性のある行を反復してその寄与を計算します。$i$。 その列内のすべてのセルからの寄与を乗算します。各セルの指数は、その行がステップ 3 で選択されたかどうか、および現在の列で選択された行であるかどうかによって異なります。 
6. すべての有効な行選択構成にわたるすべての列の寄与の積を累積します。 

### なぜ効果があるのか

 行と列の選択関数の有効なペアはすべて、DP 状態の 1 つの割り当てに正確に対応します。 分解により、最初のフェーズでは行全体で、第 2 フェーズでは列全体で選択肢が独立していることが保証されます。 それらの間の唯一の相互作用は各セルでローカルであり、指数によって完全に捕捉されます。$k \in \{0,1,2\}$。 DP はすべての有効な構造化選択を 1 回だけ列挙し、各選択が正しい乗法寄与で評価されるため、最終的な合計は必要な式と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def inv(x):
    return pow(x, MOD - 2, MOD)

INV2 = inv(2)
INV6 = inv(6)

def solve():
    n, m = map(int, input().split())
    B = [list(map(int, input().split())) for _ in range(n)]

    if m > n:
        B = list(map(list, zip(*B)))
        n, m = m, n

    S0 = [[0] * m for _ in range(n)]
    S1 = [[0] * m for _ in range(n)]
    S2 = [[0] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            x = B[i][j] % MOD
            S0[i][j] = (x + 1) % MOD
            S1[i][j] = x * (x + 1) % MOD * INV2 % MOD
            S2[i][j] = x * (x + 1) % MOD * (2 * x + 1) % MOD * INV6 % MOD

    if m == 0 or n == 0:
        print(0)
        return

    # DP over row choices: dp[mask of columns used as row-targets]
    dp = {0: 1}

    for i in range(n):
        ndp = {}
        for mask, val in dp.items():
            for j in range(m):
                nmask = mask | (1 << j)
                ndp[nmask] = (ndp.get(nmask, 0) + val) % MOD
        dp = ndp

    # column phase
    ans = 0

    for mask, ways in dp.items():
        col_prod = 1
        for j in range(m):
            col_sum = 0
            for i in range(n):
                if (mask >> j) & 1:
                    k = 1
                else:
                    k = 0
                if i == j:
                    k += 1
                if k == 0:
                    col_sum = (col_sum + S0[i][j]) % MOD
                elif k == 1:
                    col_sum = (col_sum + S1[i][j]) % MOD
                else:
                    col_sum = (col_sum + S2[i][j]) % MOD
            col_prod = col_prod * col_sum % MOD

        ans = (ans + ways * col_prod) % MOD

    print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```コードは、列数がより小さい次元になるようにグリッドを正規化することから始まります。これは、DP 状態を管理しやすく保つために不可欠です。 3 つの事前計算されたテーブル$S_0, S_1, S_2$各セルの閉じた形式の累乗和を実装します。これは、セル値の明示的な列挙を置き換えます。 

最初の動的プログラミング フェーズでは、行が列を選択するすべての方法が列挙され、ビットマスクとしてエンコードされます。 各遷移は行を列に割り当て、可能なすべての行選択関数を構築します。 これはソリューションの指数関数的核心ですが、これは、次の理由により小さい次元が小さい場合にのみ実行可能です。$N \cdot M \le 300$制約。 

2 番目のフェーズでは、固定の行選択構成に基づいて列の選択を評価します。 列ごとに、選択されたすべての行を反復処理し、事前に計算された値を使用して結果の製品の寄与を計算します。$S_0, S_1, S_2$。 ループ内の指数ロジックにより、セルが 1 回選択されるか 2 回選択されるかが決まります。 

計算するときは逆モジュラーに注意する必要があります$S_1$そして$S_2$モジュラー演算では直接除算が有効ではないためです。 すべての算術は一貫して減算法で計算されます$998244353$。 

## 実用的な例

 ### 例 1

 1 行 3 列の小さなグリッドを考えてみましょう。 列を選択する行は 1 つだけであるため、行の選択に対する DP は簡単です。 

| ステップ | 行割り当てマスク | 解釈 |
 | --- | --- | --- |
 | 0 | 000 | まだ列が選択されていません |
 | 1 | 001 | 行は列 1 を選択します |
 | 2 | 010 | 行は列 2 を選択します |
 | 3 | 100 | 行は列 3 を選択します |

 次に、各構成は列の貢献を通じて評価されます。 行が 1 つしかないため、列の相互作用は単一セルの寄与に帰着し、各セルの指数は列が同じ行を選択するかどうかによってのみ決定されます。 

これにより、アルゴリズムが列構造が優勢な縮退した単一行のケースを正しく処理していることが確認されます。 

### 例 2

 考えてみましょう$2 \times 2$グリッド。 DP には 4 つの行選択構成が列挙されています。 構成ごとに、列の評価では、各列で選択された行が行の選択と一致するかどうかが考慮されます。 

| 行マスク | 意味 |
 | --- | --- |
 | 00 | 両方の行は列 0 を選択します |
 | 01 | 行 0 は列 1 を選択し、行 1 は列 0 を選択します。 
| 10 | 行 0 は列 0 を選択し、行 1 は列 1 を選択します。 
| 11 | 両方の行が列 1 を選択します |

 マスクごとに列は独立して評価され、各セルの寄与は行と列の選択が一致するかどうかによって異なります。 

この例は、行と列の選択の間の相互作用が各セルで正しくローカライズされていることを示しています。

 ## 特殊なケース

 単一セルグリッドは 3 つのべき乗和の定義を分離します。$S_0, S_1, S_2$。 アルゴリズムは評価のみに留まります$S_0$行と列の相互作用では指数 1 または 2 を同時に作成できないためです。 入力用$N=1, M=1, B_{1,1}=0$、唯一の有効なグリッドは$A_{1,1}=0$、行と列の両方の合計がゼロであるため、寄与はゼロとなり、DP の動作と一致します。 

単一行グリッドでは、行間の列の相互作用が排除されます。 DP は行のすべての列の選択肢を列挙し、各列の評価は独立します。 同じセルを介する場合を除き、行関数と列関数の両方で列を 2 回選択することはできないため、指数ロジックは正しく減少します。アルゴリズムはこれを処理します。$k \in \{0,1\}$。 

単一列グリッドは対称的に行のみの構造に縮小されます。 DP の前に次元を正規化するため、アルゴリズムは効果的に役割を交換し、同じように動作します。
