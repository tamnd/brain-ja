 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたノードを持つパス グラフが与えられます。各ノードはそのすぐ隣のノードに接続されます。 次に、各ノード i は確率 1/i で独立して保持され、確率 1 − 1/i で削除されます。 すべての削除の後、残りのノードは元のチェーンのサブグラフを形成し、このサブグラフはいくつかの接続されたコンポーネントに分割される場合があります。 

この設定における接続コンポーネントは、単に保持されるノードの最大連続ブロックです。 削除されたノードによってギャップが作成されるたびに、チェーンが分割されます。 したがって、最終的な答えは、そのような連続して保持されるセグメントの予想数です。 

入力は n の多くの独立した値を与えるので、それぞれについてこの期待値を 10^9+7 を法として計算する必要があります。 

この制約により、n は最大 10^6、テスト ケースの総数は最大 2×10^5 まで許可されるため、ソリューションは本質的にテスト ケースごとに線形以上である必要があります。 事前計算しない限り、最悪の場合、クエリあたり O(n) であっても遅すぎます。 この構造は、n に対するプレフィックスの計算を強く示唆しています。 

単純なアプローチでは、保持/削除されたノードのすべてのサブセットとカウント コンポーネントをシミュレートします。 これは 2^n 構成であり、n が 20 のような小さな値を超えることはすでに不可能です。モンテカルロでも正確なモジュールの期待値は得られません。 

テスト ケースごとにすべての構成を直接シミュレートまたは DP しようとすると、より微妙な問題が発生します。確率モデルは i に依存するため、各位置の寄与が異なり、クエリごとに最初から再計算すると同じ作業を何度も繰り返すことになります。 

## アプローチ

 重要な観察は、保持/削除されたノードのバイナリ シーケンス内の接続されたコンポーネントをローカルにカウントできることです。 ノード i が保持され、i-1 が削除されるか、i-1 が存在しない場合、新しいコンポーネントは位置 i から正確に開始されます。 

したがって、「新しいコンポーネントを開始する」という指標を定義すると、期待値はローカル イベントの確率の合計になります。 

ノード i が保持されるイベントを K_i とします。 K_i が true で、i = 1 または K_{i−1} が false の場合、ノード i は新しいコンポーネントを提供します。 期待値の線形性により、これらの確率を i 全体で独立して合計できます。 

ブルートフォースのアイデアでは、ノードのすべてのサブセットを列挙し、O(n) 内の各サブセットの連結成分を計算し、すべての確率の平均を計算します。 サブセットの数が指数関数的であり、確率の重みが均一ではないため、これは失敗します。 

重要な簡素化は、隣接するノードを越えた相関を必要としないことです。 各項は K_i と K_{i−1} にのみ依存し、ノード状態の独立性によりこれは完全にローカルになります。 

次のように計算します。 

i = 1 の場合、コンポーネントが開始する確率は P(K_1) = 1 です。 

i > 1 の場合、ノード i が保持され、ノード i-1 が保持されないときに新しいコンポーネントが開始されます。 

P = P(K_i) × P(not K_{i−1}) = (1/i) × (1 − 1/(i−1))。 

これにより、問題全体が i 上の接頭辞の合計に還元されます。 

残りの唯一の注意は、モジュラー演算と特殊なケース i = 1 を個別に処理することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^n · n) | O(n) | 遅すぎる |
 | ローカル期待和 | O(n) の前処理、クエリごとに O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. テスト ケース全体で最大 n までのすべての整数のモジュラー逆行列を事前計算します。 これが必要なのは、確率には素数法の下で 1/i が含まれるため、除算は逆剰余を使用した乗算に置き換える必要があるためです。 
2. dp[i] が長さ i のチェーンの予想されるコンポーネント数を格納する配列 dp を構築します。 dp を 1 から最大 n まで段階的に計算します。 
3. 単一ノードが常に保持され、正確に 1 つのコンポーネントを形成するため、dp[1] = 1 を初期化します。 
4. 2 から最大 n までの各 i について、位置 i の寄与を、i が保持され、i-1 が保持されない確率として計算します。 これは (1/i) × (1 − 1/(i−1)) です。 これを dp[i−1] に加算して dp[i] を取得します。 
5. dp[n] を出力して各クエリに答えます。 

この増分形式が機能する理由は、新しい位置がそれぞれ既存のコンポーネントを拡張するか、新しいコンポーネントを開始するためであり、コンポーネント数に影響を与えるのは 2 番目の場合のみであるためです。 

### なぜ効果があるのか

 コンポーネントの予想数は、コンポーネントの開始の予想数と同じです。 ノード i は存在するがノード i-1 が存在しない場合、開始は正確に位置 i で発生します。 これらのイベントは独立したベルヌーイ変数にのみ依存するため、確率はきれいに乗算されます。 期待値の線形性により、異なるスタート間の相互作用を考慮せずに、これらのポジションごとの確率を合計することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    ns = []
    max_n = 0

    for _ in range(t):
        n = int(input())
        ns.append(n)
        if n > max_n:
            max_n = n

    if max_n == 0:
        return

    inv = [0] * (max_n + 2)
    for i in range(1, max_n + 2):
        inv[i] = modinv(i)

    dp = [0] * (max_n + 2)
    dp[1] = 1

    for i in range(2, max_n + 1):
        p_keep = inv[i]
        p_prev_keep = inv[i - 1]
        p_prev_not = (1 - p_prev_keep) % MOD
        dp[i] = (dp[i - 1] + p_keep * p_prev_not) % MOD

    out = []
    for n in ns:
        out.append(str(dp[n]))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、グローバルな事前計算が必要であるため、すべてのテスト ケースを読み取って最大 n を決定することから始まります。 逆モジュラーはフェルマーの定理を使用して計算されます。 

dp 配列には、各プレフィックス長までの期待値が格納されます。 各遷移では i と i−1 のみが使用されるため、計算は線形です。 

微妙な点は、(1 − 1/(i−1)) モジュロ MOD を正しく計算することです。 負の値を避けるために、減算後に明示的にモジュロを適用します。 

## 実用的な例

 n = 2 のサンプルを考えてみましょう。 

| 私 | P(キープアイ) | P(前ではない) | 貢献 | dp[i] |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | - | 1 | 1 |
 | 2 | 1/2 | 1 − 1/1 = 0 | 0 | 1 |

 n = 2 の場合、ノード 1 は常に存在するため、ノード 2 に関係なく、dp[2] = 1 に一致するコンポーネントが常に 1 つだけ存在します。 

ここで、n = 4 について考えてみましょう。 

| 私 | P(キープアイ) | P(前ではない) | 貢献 | dp[i] |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | - | 1 | 1 |
 | 2 | 1/2 | 0 | 0 | 1 |
 | 3 | 1/3 | 1 − 1/2 = 1/2 | 1/6 | 1 + 1/6 |
 | 4 | 1/4 | 1 − 1/3 = 2/3 | 1/6 | 1 + 1/6 + 1/6 |

 これにより、予想されるモジュラー出力と一致する 4/3 が生成されます。 

トレースは、保持されたノードの前に欠落しているノードがある場合にのみコンポーネントが表示され、寄与分が独立して蓄積されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(最大 n + t) | dp を 1 回事前計算し、クエリにそれぞれ O(1) で答えます。 
| スペース | O(最大n) | dp 配列と逆配列を保存する |

 最大 10^6 の前処理は時間制限内に無理なく収まり、各クエリは定数時間であるため、ソリューションは最大 2×10^5 のテスト ケースに適しています。 

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ns = []
    max_n = 0
    for _ in range(t):
        n = int(input())
        ns.append(n)
        max_n = max(max_n, n)

    inv = [0] * (max_n + 2)
    for i in range(1, max_n + 2):
        inv[i] = pow(i, MOD - 2, MOD)

    dp = [0] * (max_n + 2)
    if max_n >= 1:
        dp[1] = 1

    for i in range(2, max_n + 1):
        dp[i] = (dp[i - 1] + inv[i] * (1 - inv[i - 1]) % MOD) % MOD

    return "\n".join(str(dp[n]) for n in ns)

# provided samples
assert run("4\n1\n2\n3\n4\n") == "1\n1\n166666669\n333333337"

# custom cases
assert run("1\n1\n") == "1", "minimum size"
assert run("1\n2\n") == "1", "two nodes"
assert run("1\n5\n") == run("1\n5\n"), "determinism check"
assert run("3\n1\n2\n3\n") == "1\n1\n166666669", "prefix consistency"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 単一ノードのエッジケース |
 | 2 | 1 | 分割はできません |
 | 5 | dp の一貫性 | 再発の安定性 |
 | 1、2、3 | 1,1,1/6 | プレフィックスの正確性 |

 ## 特殊なケース

 n = 1 の場合、単一の保証保持ノードが正確に 1 つのコンポーネントを形成するため、アルゴリズムは dp[1] = 1 を直接設定します。 dp[0] には依存関係がないため、未定義の動作が回避されます。 

n = 2 の場合、遷移では P(prev not) = 1 − 1/1 = 0 が使用され、ノード 1 が常に存在することが正しく捉えられるため、ノード 2 は新しいコンポーネントを開始できません。 

n が大きい場合、各項は i と i−1 にのみ依存するため、最大 n = 10^6 であっても、計算は安定した線形のままであり、隠れた再帰や状態爆発はありません。
