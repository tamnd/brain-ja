 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$n \times n$。 最初の行は固定です。1 から 1 までの数字が含まれます。$n$順番に。 以下のすべてのセルは決定論的に生成されます。各エントリは、同じ列のすぐ上の数値の 2 乗です。 

したがって、単一の列に注目すると、$j$、価値観はこのように進化します。 一番上は$j$、次のセルは$j^2$、 それから$j^4$、 それから$j^8$、 等々。 各ステップは前の値を 2 乗します。これは、指数が各行ごとに 2 倍になることを意味します。 

タスクはグリッドを構築することではなく、すべての行と列にわたってグリッド内のどこかに出現する個別の整数の数をカウントすることです。 

制約は次のとおりです$n = 10^5$そして$t = 10^5$。 グリッドを明示的にシミュレートするソリューションは不可能です。グリッドを保存することさえ困難であるためです。$O(n^2)$、単一のテストでも大きすぎます。 これにより、すぐにセルごとではなく値構造ごとに推論する方向に進みます。 

微妙な問題は、値が非常に速く増加することです。 小さいものでも$j$, 数値は 3 行目または 4 行目までに通常の整数の範囲を超えて爆発的に増加します。 ただし、問題は大きさではなく区別性に関するものであるため、オーバーフローは Python では関係ありませんが、直感的には依然として重要です。 

いくつかのエッジの状況を切り分ける価値があります。 

いつ$n = 1$、グリッドは完全に 1 なので、答えは明らかに 1 です。 

いつ$n = 2$、グリッドには以下が含まれます$1,2$最初の行では、$1,4$。 個別の値は、$\{1,2,4\}$。 素朴な解釈はそれを忘れてしまうかもしれません$4$は最初の行の何とも衝突しませんが、より大きな場合には、完全な累乗からの衝突が中心的な複雑になります。 

主な問題は、グリッド内の異なるパスが異なる方法で同じ数値を生成する可能性があることです。たとえば、$16 = 4^2 = 2^4$, そのため、同じ整数を二重に数えることを避けなければなりません。 

## アプローチ

 グリッド構造は、すべての値が次の形式であることを意味します。$$j^{2^k}$$どこ$j$は列インデックスであり、$k$ゼロから始まる行インデックスです。 

ブルートフォースアプローチでは、すべての値を明示的に生成します。$j \le n$数値が大きくなりすぎるまですべての行。 これにより、$n^2$値を取得し、それらをセットに挿入します。 これは原理的には正しいですが、すぐに壊れてしまいます。$n^2$到達する$10^{10}$、これは実行可能な計算をはるかに超えています。 

重要な観察は、グリッドが任意の数値を生成しないことです。 完全なべき乗、より具体的には、指数が 2 のべき乗であるべき乗のみを生成します。 したがって、グリッド内の位置の観点から考える代わりに、セットの観点から考えることができます。$$\{ j^{1}, j^{2}, j^{4}, j^{8}, \dots \}$$それぞれに$j$。 

ここで問題は次のようになります: 完全なすべての数の中から個別の整数を数えます$k$-乗、ここで$k$は 2 の累乗です。 

この再定式化により、グリッドが完全に削除されます。 フォームのすべての番号を生成するだけで済みます。$a^k$どこ$1 \le a \le n$そして$k \in \{1,2,4,8,\dots\}$、次に一意の値をカウントします。 

重複は、同じ数値が異なる指数パターンとして表現できる場合にのみ表示されます。$16 = 2^4 = 4^2$。 グローバル セットを使用すると、これは自然に解決されます。

 ## アルゴリズムのチュートリアル

 すべての有効なグリッド値を間接的に構築します。 

1. 1 から 1 までのすべての整数を含むセットから開始します。$n$。 これらはグリッドの最初の行に対応し、二乗することなくすべての列の値に寄与します。 
2. グリッドに表示されるすべての指数を事前計算します。 これらは$2^0, 2^1, 2^2, \dots$。 スキップします$2^0 = 1$これは最初の行ですでに考慮されており、2 から始まる指数のみを考慮するためです。 
3. 指数ごとに$k$このシーケンスでは、すべての基本値を反復処理します。$a$1から$n$、計算する$a^k$、結果をセットに挿入します。 これは、グリッドのより深い各行レベルの寄与を表します。 
4. 指数が大きくなりすぎて役に立たなくなるまで続けます。 実際には、このシーケンスは毎回 2 倍になるため非常に短く、妥当な範囲内では関連する指数は約 16 ～ 17 個しかありません。 
5. 答えは単にセットのサイズです。 

この構築が機能する理由は、グリッド内のすべてのセルがまさにこれらのべき乗された値の 1 つであり、そのようなすべての値が (基底、指数レベル) ペアごとに 1 回だけ生成されるためです。 このセットは、同じ整数を生成する異なる指数パスによって引き起こされるすべての衝突を除去します。 

### なぜ効果があるのか

 すべてのグリッド値はペアに一意に対応します$(j, 2^k)$、ベース柱と二乗ステップの数を意味します。 その価値は常に$j^{2^k}$。 逆に、このプロセスで生成された数値はグリッドのどこかに表示されます。$j$まさにその一連の力を生成します。 したがって、すべての列とすべての有効な指数の和集合は、グリッド値のセットと正確に一致します。 残る唯一の問題は、同じ整数の異なる表現間の重複ですが、これはすべてをセットに格納することで解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        seen = set()

        for a in range(1, n + 1):
            seen.add(a)

        k = 2
        # exponents are powers of two: 2, 4, 8, ...
        # k grows fast, so only a small number of iterations exist in practice
        while k <= 60:
            for a in range(1, n + 1):
                val = pow(a, k)
                seen.add(val)
            k *= 2

        print(len(seen))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に最初の行全体が挿入され、指数 1 を持つすべての値が計算されます。次に、繰り返される二乗に対応する指数レベル (2、4、8 など) を繰り返します。 レベルごとにすべての値が生成されます$a^k$のために$a \le n$。 の`set`次のような衝突が発生することを保証します$16 = 2^4 = 4^2$は 1 回のみカウントされます。 

指数は毎回 2 倍になり、実際には新しい個別の値を生成するのにすぐに無関係になるため、指数ループの上限は小さな定数に設定されています。

 ## 特殊なケース

 のために$n = 1$、指数レベルに関係なく、すべてのセルは 1 です。 アルゴリズムは最初の行に 1 を 1 回挿入し、その後のすべてのべき乗も 1 を生成しますが、セットではそれを単一の要素として保持し、正しい出力 1 を生成します。 

小型用$n$2 や 3 など、多くのより高いべき乗は、前の行にすでに存在する値に集約されるか、異なる指数レベル間で繰り返されます。 例えば、$16$両方として表示できます$2^4$そして$4^2$ですが、このセットにより、確実に 1 回カウントされます。 

大型の場合$n$、ほとんどの高い指数値は非常に大きく、以前の値とは異なります。 重複が存在する場合でも、それらは完全冪の代数的恒等を通じてのみ発生します。これはまさにセットベースの構築が処理するように設計されたケースです。
