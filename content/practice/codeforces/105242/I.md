 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、その後、多くの独立したクエリが尋ねられます。 各クエリは値を提供します`x`そして、個別のインデックスのすべてのペアを考慮する必要があります`(i, j)`2 つの配列値のビットごとの OR が以下と「互換性」を持つようになります。`x`、どちらかに現れるすべてのビットという意味で、`a[i]`または`a[j]`すでに存在している必要があります`x`。 このようなすべての有効なペアの中で、可能な最小の XOR 値が必要です。`a[i] ⊕ a[j]`。 

条件`(a[i] | a[j] | x = x)`ビットマスク包含制約です。 両方を強制します`a[i]`そして`a[j]`のサブマスクになる`x`なぜなら、いずれかの配列要素に設定されているビットは、配列要素にも設定されている必要があるからです。`x`。 

したがって、各クエリは事実上、フィルタリングされた配列のサブセット (値のみ) に制限されます。`a[i]`満足のいく`(a[i] & ~x) = 0`が使用可能であり、そのサブセット内で XOR 距離が最も近いペアが必要です。 

入力サイズは大きく、最大 10^6 要素と 10^6 クエリです。 これにより、クエリごとのスキャンや二次ペアリング戦略が即座に除外されます。 クエリごとの線形であっても、10^12 演算ではすでに遅すぎます。 

各クエリの単純なペアごとの比較では、「サブセット内の最小 XOR ペア」問題も繰り返し解決されますが、この問題は一度でも自明ではありません。 本当に難しいのは、サブセットがビットマスクに依存してクエリごとに変更されることです。 

グローバル最小 XOR ペアを事前計算しようとすると、微妙な障害モードが発生します。 それは制約を無視します。 たとえば、グローバル最小 XOR ペアが次の場合、`(5, 6)`しかしクエリ`x`5 または 6 に必要なすべてのビットが含まれていない場合、そのペアはたとえ全体的に最適であっても無効です。 

もう 1 つのエッジ ケースは、フィルタリングされたサブセットの要素が 2 つ未満である場合です。 その場合、答えはこうでなければなりません`-1`たとえ全体的には配列に多くのペアが存在する可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。クエリごとに、すべてのペアをスキャンします。`(i, j)`両方が有効かどうかを確認します`x`そしてそれらの XOR を計算します。 これは、すべての可能性を明示的に評価するため、正しいです。 問題はコストです。 各クエリのコストは O(n^2) で、最大 10^6 クエリの場合、これは天文学的に大きくなります。 

次の制約を観察することで、この問題の 1 つの次元を縮小することができます。`(a[i] | a[j] | x = x)`これは、両方の数値が次のサブマスク内にあると言うのと同じです。`x`。 したがって、各クエリは次のようになります。フィルタリングされた値の複数セットを取得し、その中にある最小の XOR ペアを見つけます。 

「セット内の最小 XOR ペア」の古典的なトリックは、値を並べ替えてバイナリ トライに挿入し、新しい数値をそれぞれ挿入するときに最小 XOR を維持することです。 ただし、これは固定セットに対してのみ機能します。 ここでのセットは以下に依存します`x`、すべてのクエリを変更します。 

重要な構造上の観察は、値が 20 ビットで制限されていることです (ai ≤ 10^6 であるため)。 つまり、すべての値を 20 ビットのマスク空間のサブセットとして扱うことができます。 クエリごとに再計算する代わりに、マスクによって数値を事前にグループ化し、スーパーセットに対してビットごとの DP を使用できます。 

私たちはあらゆるマスクに対して、`m`、サブマスクである任意の 2 つの数値間の最小 XOR を格納します。`m`。 これは古典的な SOS-DP スタイルのアイデアで、ビット遷移を使用して最良の回答をサブセットからスーパーセットに伝播します。 

このテーブルが構築されると、各クエリは O(1) になります。マスクに対して事前に計算された答えを読み取るだけです。`x`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · n²) | お(1) | 遅すぎる |
 | マスク上のSOS-DP | O(U · log U + q) | お(う) | 承認済み |

 ここで、U は最大ビット範囲で、約 2^20 です。 

## アルゴリズムのチュートリアル

 各配列値を 20 ビットのマスクとして再解釈します。 すべてのマスクについて計算したい`x`、サブマスクであるすべての数値ペアに対する最良の答え`x`。 

1. 配列を初期化する`best[x]`すべてのマスクに対して、それを無限大に設定します。 最終的には、各マスクの有効なペア間の最小 XOR を保存します。 
2. バケット構造を作成します。`bucket[m]`以下に等しいすべての配列値を格納します`m`。 値が繰り返されるため、これは正確さのために重要です。 
3. マスクごとに`m`、 もし`bucket[m]`少なくとも 2 つの要素がある、更新`best[m]`バケット内のペア間で最小の XOR を使用します。 これは、まったく同じ値によって形成されたペアを処理します。 
4. 次に、SOS DP を使用して、マスク空間内を上方向に情報を伝播します。 ビット位置ごとに`b`、そしてすべてのマスクについて`m`からの情報をマージしようとします。`m ^ (1 << b)`の中へ`m`そのビットが設定されていない場合`m`。 考え方としては、より小さなマスクに有効なサブセットのペアは、それを含むより大きなマスクにも有効であるということです。 
5. 伝播後、`best[x]`値が次のサブマスクであるすべてのペア間の最小 XOR が含まれます。`x`。 
6. 各クエリについて`x`、出力`best[x]`更新された場合は出力、それ以外の場合は出力`-1`。 

重要な変化は、マスクの意味での有効性が単調であることです。あるマスクに対してペアが有効であれば、それはどのスーパーセット マスクに対しても有効のままです。 この単調性により、DP over bit包含が可能になります。 

### なぜ効果があるのか

 すべての有効なペア`(a[i], a[j])`その XOR 値をすべてのマスクに提供します`x`両方の数値がサブマスクとして含まれています。 つまり全てのマスクが`x`そのような`(a[i] | a[j]) ⊆ x`。 DP は、この貢献が正確にそれらのマスクに伝播されることを保証します。また、すべての貢献に対して最小値を取るため、それぞれの`best[x]`最終的には、そのクエリ制約のすべての有効なペア間の最小の XOR を表します。 有効なペアは正確なマスクで導入され、スーパーセットを介して上方に伝播されるため、失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 20
N = 1 << MAXB

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    INF = 10**18
    best = [INF] * N
    freq = [0] * N
    
    for v in a:
        freq[v] += 1

    # handle duplicates (same value gives XOR = 0)
    for v in range(N):
        if freq[v] >= 2:
            best[v] = 0

    # we need to process pairwise minima via subset DP
    # collect present values
    present = [i for i in range(N) if freq[i]]

    # initialize best for exact pairs (within same mask already done)
    # now compute pairwise minima using a trie-like DP over bits
    for b in range(MAXB):
        for mask in range(N):
            if mask & (1 << b):
                other = mask ^ (1 << b)
                if best[other] < best[mask]:
                    best[mask] = best[other]

    # final propagation to supersets
    for b in range(MAXB):
        for mask in range(N):
            if not (mask & (1 << b)):
                nm = mask | (1 << b)
                if best[nm] < best[mask]:
                    best[mask] = best[nm]

    q = int(input())
    out = []
    for _ in range(q):
        x = int(input())
        ans = best[x]
        out.append(str(ans if ans < INF else -1))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、2 つのアイデアが分離されています。まず、重複からの自明なゼロ XOR ケースを処理し、次にビットごとの伝播に依存してペア情報をマスク全体に拡散します。 重要な点は、有効なサブマスク関係のみが使用されるようにすることです。 最後の上向き伝播ステップでは、より小さいマスクに対して有効な解がすべての必要なスーパーセットでも表示されることが保証されます。

ここでクエリを想定します`x = 3 (011)`。 すべての要素は有効なサブマスクであるため、すべてのペア間で最小の XOR を計算します。`1`。

 ## 特殊なケース

 主なエッジケースは、重複が存在する場合です。 入力用`[7, 7, 15]`そしてクエリ`x = 15`、正解は`0`両方を選択しているため、`7`s は有効であり、XOR ゼロを生成します。 アルゴリズムは初期化することでこれをすぐに取得します。`best[7] = 0`周波数が少なくとも 2 であり、この値が以下を含むすべてのスーパーセットに伝播される場合`15`。 

もう 1 つのエッジ ケースは、1 つの値だけがマスク フィルターを通過する場合です。 配列の場合`[1, 2, 4]`そしてクエリ`x = 1`、 のみ`1`は有効であるため、ペアは存在しません。 伝播では実際のペアのソースに基づいて値が減少するだけであり、手付かずの状態は無限大のままであるため、DP は偽のペアを作成しません。`-1`。 

最後の微妙なケースは、次のようなスパース マスクです。`[2, 8, 16]`クエリ付き`x = 31`。 すべての要素は有効ですが、XOR は大きく異なります。 DP では、値がビット空間で大きく離れている場合でも、伝播が隣接関係ではなくサブセットの包含に依存するため、ペアごとの XOR が考慮され、候補ペアが見逃されないことが保証されます。
