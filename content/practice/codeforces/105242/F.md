 ## 解決策
 ## 問題の理解

 英小文字の文字列と多くのクエリが与えられ、各クエリはインデックスで定義された部分文字列に焦点を当てます。$l$そして$r$。 このような範囲ごとに、まずその範囲内にどの個別の文字が表示されるかを調べます。 部分文字列があるとします。$s[l..r]$含まれています$k$違う文字。 内部に完全に含まれるすべての可能な部分文字列の中で$[l,r]$、これらすべてを含む最も短いものが必要です。$k$異なる文字を少なくとも 1 回。 各クエリの出力は、その最短の有効な部分文字列の長さです。 

したがって、この作業は頻度を数えたり、文字を並べ替えたりすることではありません。 これは、固定セグメント内で、そのセグメントに出現するすべての文字タイプを「カバー」する最小のウィンドウを見つけることです。 

制約$n, q \le 10^5$クエリごとに情報を最初から再計算するソリューションは直ちに除外してください。 クエリごとのリニア スキャンでも、$10^{10}$限界をはるかに超えた最悪の場合の操作。 唯一の実行可能な方向は、文字列を前処理してから、コンパクトな文字ごとの構造を使用して各クエリに応答することです。理想的には、クエリごとのコストが個別の文字の数に近い (最大 26) になります。 

文字が不均一に散在している場合、微妙なエッジケースが表示されます。 たとえば、ある文字がクエリの左端近くに 1 回だけ出現し、別の文字が右端近くにのみ出現する場合、最適なウィンドウには両方の極端な値を含めることが強制される可能性があります。 最適な解決策には異なる文字の異なる出現が混在する可能性があるため、常に最初の出現または最後の出現を独立して取得する単純な戦略は失敗する可能性があります。 

別の失敗モードは、最適な部分文字列がすべての必要な文字の中で最も左に出現する位置から開始する必要があると想定していることです。 開始位置を右に移動すると、終了境界が大幅に縮小する場合があるため、これは不正確です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべての部分文字列が列挙されます。$[i,j]$内部$[l,r]$、その個別の文字のセットを計算し、それを次の文字のセットと比較します。$s[l..r]$。 各クエリには、$O((r-l+1)^2)$部分文字列、および個別のカウントの計算には少なくともかかります$O(1)$または$O(26)$。 これにより、入力全体にわたって三次的な動作が発生しますが、これは小さなインスタンスであっても実行不可能であり、完全に機能しません。$10^5$。 

重要な観察は、対象となる ID はクエリ範囲内の個別の文字のセットのみであるということです。 そのセットが判明すると、問題は次のようになります。選択された最初の出現と最後に選択された出現の間の間隔が最小になるように、範囲内の各文字の出現を 1 つ選択します。 

これにより、問題は古典的な「k 個のソートされたリストをカバーする最小範囲」構造に変換されます。 各文字は、その位置のソートされたリストに貢献します。 特定のクエリについて、各リストを以下の位置に制限します。$[l,r]$そして、選択された最大位置と最小位置の差を最小限に抑えるために、各リストから要素を 1 つだけ選択したいと考えています。 

文字が 26 文字しかないので、k は小さいです。 これにより、ポインタの小さなアクティブなセット (文字ごとに 1 つ) を維持し、ヒープを使用してそれらを繰り返し調整して、現在最悪の境界に寄与しているポインタを常に移動することが可能になります。 各調整はローカルにガイドされますが、全体として最適なカバー範囲に収束します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$クエリごと |$O(1)$| 遅すぎる |
 | 最適 (26 リスト + ヒープ ポインター) |$O(26 \log 26)$クエリごとに償却 |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、文字ごとに保存することで文字列を前処理します。$c$、それが表示される位置のソートされたリスト。 

クエリごとに$[l,r]$、他の文字は無関係であるため、このセグメントに実際に登場する文字のみを考慮します。 

1. キャラクターごとに$c$、内部で最初に出現するものを見つけます$[l,r]$位置リストに対して二分探索を使用します。 オカレンスが存在しない場合は、必要な個別セットの一部ではないため、スキップします。 
2. この最初の有効な位置で各アクティブ文字リストのポインタを初期化します。 これらのポインタは、文字ごとに選択された 1 つの出現を表します。 
3. 選択した位置の現在の最小値と最大値の両方を取得できるデータ構造を維持します。通常は、現在の最大値の追跡と組み合わせた最小ヒープです。 
4. これらの選択された位置を使用して、初期ウィンドウの長さを計算します。 
5. 現在選択されている位置がすべての選択位置の中で最小である文字を繰り返し識別し、そのポインタを内部の次の出現位置に進めます。$[l,r]$。 移動後、現在の最小値と最大値を更新し、候補ウィンドウの長さを再計算します。 
6. ポインタが範囲外に移動するか、リスト セグメントの末尾に到達すると、それ以上有効なカバーが存在しないため停止します。 

答えは、このプロセス中に観察される最小ウィンドウ長です。 

### なぜ効果があるのか

 常に、必要な文字ごとに 1 つのオカレンスの選択を維持し、有効なカバー セットを形成します。 すべての有効な解決策は、範囲内の文字ごとに 1 つの出現の選択肢に対応します。 このアルゴリズムは、各リスト内のポインターを単調に進めることによって到達可能なすべての関連構成を探索します。 現在の範囲を改善するには、少なくとも 1 つのエンドポイントを内側にシフトする必要があります。これは、現在境界を定義している文字のポインタを進めることに相当します。 このようなポインターの移動によってすべての候補構成に到達することができ、最もよく見える範囲を常に追跡しているため、見つかった最小値が最適なカバー ウィンドウになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right
import heapq

def solve():
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    q = int(input())
    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        lists = []
        for c in range(26):
            arr = pos[c]
            if not arr:
                continue
            i = bisect_left(arr, l)
            if i < len(arr) and arr[i] <= r:
                lists.append((c, arr, i))

        k = len(lists)
        if k == 0:
            out.append(0)
            continue

        ptr = [i for _, _, i in lists]

        heap = []
        current_max = -10**18

        for idx, (c, arr, i) in enumerate(lists):
            val = arr[i]
            heapq.heappush(heap, (val, idx))
            if val > current_max:
                current_max = val

        best = current_max - heap[0][0] + 1

        while True:
            mn_val, mn_idx = heapq.heappop(heap)
            c, arr, i = lists[mn_idx]
            ni = ptr[mn_idx] + 1
            if ni >= len(arr) or arr[ni] > r:
                break

            ptr[mn_idx] = ni
            new_val = arr[ni]
            heapq.heappush(heap, (new_val, mn_idx))

            if new_val > current_max:
                current_max = new_val
            else:
                current_max = max(arr[ptr[j]] for j in range(k))

            best = min(best, current_max - heap[0][0] + 1)

        out.append(str(best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```前処理ステップでは 26 個の位置リストを構築するため、各クエリは関連する文字のみを迅速に分離できます。 各クエリについて、各リストをバイナリ検索して、間隔内の最初の有効な出現箇所を見つけます。 これにより、範囲外の文字が考慮されることがなくなります。 

ヒープには、現在選択されている文字ごとの出現が維持されます。 ヒープの最小要素は現在のウィンドウの左側の境界を示し、追跡された最大要素は右側の境界を示します。 各ステップでは、現在左側の境界に影響を与えているキャラクタを進めます。これは、左側を縮小することが、カバレッジを失わずにスパンを削減できる唯一の方法であるためです。 

実装の微妙な点は、終了条件を正しく処理することです。 ポインタが有効なセグメントの終わりに到達すると、それ以上完全にカバーすることはできないため、直ちに停止する必要があります。 

## 実用的な例

 文字列を考えてみましょう`abaaba`全範囲をカバーするクエリ$[1,6]$。 

私たちはポジションを追跡します`a`そして`b`。 

| ステップ | | を選択しました 選択された b | 分 | マックス | ウィンドウ |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 1 | 2 | 2 |
 | 2 | 3 | 2 | 2 | 3 | 2 |
 | 3 | 3 | 5 | 3 | 5 | 3 |

 最適なウィンドウは長さ 2 で、2 つの文字が隣接しているときに早期に達成されます。 

ここで、歪んだケースを考えてみましょう。`aabbbaba`、クエリ$[1,8]$。 

| ステップ | アポス | ビーポス | 分 | マックス | ウィンドウ |

 最適なウィンドウは次のようになります。$[3,4]$、文字ごとに異なる出現を選択する必要がある理由を示しています。 

トレースは、最適なウィンドウが極端な値から離れ、文字間で調整された選択に依存する可能性があることを示しています。

 ## 特殊なケース

 単一文字の文字列は最も単純な動作を示します。有効な部分文字列は任意の 1 つの位置だけであるため、答えは常に 1 になります。 このアルゴリズムは 1 つのリストを正しく初期化し、すぐにサイズ 1 のウィンドウを返します。 

次のような非常に偏った分布`a`両端に集中しており、`b`真ん中では、アルゴリズムが極端でない出来事を選択できるかどうかをテストします。 ポインタ メカニズムにより、選択が不適切なために左側の境界が大きすぎると、担当キャラクタを進めるとウィンドウが内側にシフトされ、スパンが修正されます。 

すべての文字が同一である場合、個別のセット サイズは 1 になります。アルゴリズムは単一のリストの追跡に限定され、ヒープ競合は実行されず、1 に等しい安定した答えが生成されます。
