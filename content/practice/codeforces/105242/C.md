 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは、接続された非循環グラフを意味するツリーを記述します。 タスクは、すべてのノードを少なくとも 1 回、2 回以上訪問しないウォークがこのツリー上に存在するかどうかを判断することです。 ウォークは任意のノードから開始することができ、開始ノードは時間 0 ですでに訪問されているとみなされます。 歩行の各ステップはエッジに沿って移動する必要があります。 

したがって、ウォークを構築することは求められず、そのようなウォークが存在するかどうかを判断するだけです。 

条件を再解釈する重要な方法は、走査中に各ノードに何回入るかという観点から考えることです。 グラフはツリーであるため、繰り返しの訪問はエッジに沿った後戻りによって行われます。 「ノードごとに最大 2 回」という制約は非常に厳しく、サブツリーから何度も離れた後に頂点を再訪問することを禁止しているため、非常に制限されたツリー形状のみが動作できることがすぐにわかります。 

制約は大きく、すべてのテスト ケースにわたるノードの総数は最大 200,000 です。 これにより、歩行をシミュレートしたり、すべての開始点を試したり、指数関数的なバックトラッキングを実行したりするソリューションは除外されます。 テスト ケースごとの 2 次アプローチでも遅すぎます。 テスト ケースごとに線形であるか、最悪の場合でもすべてのテストにわたって線形であることが必要です。 

DFS オイラー ツアーはいつでも実行できるため、どのツリーでも機能すると考えるのは単純な間違いです。 標準の DFS トラバーサルでは、一部のノードが 2 回以上アクセスされる可能性があるため、これは誤りです。 たとえば、星形のツリーでは、完全な横断中に中心が何度も訪れることになります。 

もう 1 つのよくある誤解は、いつでもハミルトニアン パスを選択し、それをわずかに延長できると考えていることです。 しかし、木には多くの場合、中央ノードを通って繰り返し戻ることを強制する分岐があります。 

素朴な直感を打ち破る小さな例としては、次のような星があります。 

入力:

 n = 4

 1 を 2、3、4 に接続

 リーフから開始する単純な DFS ウォークは次のようになります。 

2→1→3→1→4

 ノード 1 は 3 回アクセスされており、条件に違反しています。 ここでの正解は「NO」です。 

したがって、問題は、非常に限られた再訪問でのトラバースを可能にするツリーの構造的制限に関するものです。 

## アプローチ

 強引なアイデアは、すべてのノードから開始してすべての可能なウォークをシミュレートし、すべてのパスを探索し、訪問数を追跡することです。 各ステップでノードを再訪することができ、暗黙の制約以外にウォーク長に制限がないため、これは巨大な状態空間問題になります。 たとえ歩行の長さを 2n 程度に制限したとしても、各ノードで前のノードを除く任意の隣接ノードに移動できるため、分岐の選択肢は指数関数的に爆発的に増加します。 

これは、状態に現在のノードとすべてのノードの訪問数ベクトルの両方が含まれている必要があり、それが大きすぎるため失敗します。 

重要な洞察は、「ウォークの構築」から「すべてのノードが最大 2 回アクセスされた場合にツリーがどのような構造的制約を課すか」に視点を反転することです。 

木の上を歩くことは、本質的にエッジトラバーサルシーケンスです。 ノードに入るたびに、さらに深く進むか、最終的には同じエッジを通って戻ります。 訪問数を低く抑える唯一の方法は、木が繰り返し「中央横断」を強いないようにすることです。 

重要な観察は、ノードの次数が 3 以上である場合、すべてのブランチをカバーするウォークは、許容制限を超える方法でそのノードを複数回通過する必要があるということです。 より正確には、次数 ≥ 3 のノードは少なくとも 3 つの互いに素なサブツリーを作成し、それらすべてをカバーするウォークはそのノードに複数回戻る必要があります。 このようなノードは、カバー ウォークで少なくとも 3 回の訪問を強制すると形式化できます。

これは、木が非常に小道に似ているに違いないことをすぐに示唆しています。 実際、機能するツリーは、単純なパス、または「再訪問が 2 つを超えないように制御された追加の分岐点が 1 つあるパス」のいずれかであるツリーのみです。 注意深く推論すると、この条件は、ツリーがパスであるか、最大 2 つのノードが 2 より大きい次数を持ち、それらが単一のチェーン配置を形成するパスに近い構造であるかをチェックすることを単純化することがわかります。 ただし、より堅牢で標準的な導出では、より明確な特徴付けが示されます。答えは、ツリーが単純なパスである場合に限り、YES です。 

なぜ？ どの分岐点でも少なくとも 3 つの方向が導入され、すべての葉をカバーするには、少なくとも分岐数から 1 を引いた回数だけ分岐ノードを再訪問する必要があり、これはすぐに許容制限を超えます。 

したがって、すべてのノードの次数が最大 2 であり、ツリーが接続されているかどうか (常に接続されています) を確認するだけで済みます。 つまり、ツリーには次数 1 のノードが最大 2 つ必要で、他のすべてのノードは次数 2 であり、これはまさにパスです。 

したがって、解決策は、ツリーがパス グラフであるかどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースのツリーを読み取り、すべてのノードの次数を計算します。 これにより、強制再訪問が発生するかどうかを決定するローカル分岐構造が捕捉されます。 
2. 次数を持つノードの数を正確に数えます。 1. これらは木の葉です。 パスには、ちょうど 2 つの葉がなければなりません。 
3. すべてのノードをチェックして、次数が 2 を超えるノードがないことを確認します。そのようなノードでは、カバリング ウォーク中に複数のリターンを強制する分岐が導入されます。 
4. 葉の数がちょうど 2 で、次数が 2 を超えるノードがない場合は YES を出力し、それ以外の場合は NO を出力します。 

これが機能する理由は、すべての次数が最大 2 であるツリーは必ずパスであるためです。 パスの終点はまさに次数 1 のノードです。この構造から逸脱すると、許容制限を超えて強制的に再訪問する分岐点が生じます。 

### なぜ効果があるのか

 すべてのノードの次数が最大 2 であるツリーでは、すべてのノードを接続する単純なチェーンが 1 つだけ存在します。 1 つのエンドポイントから開始されるウォークはすべて、チェーンを横断して他のエンドポイントに到達し、すべてのノードを 1 回だけ訪問します。 これにより、制約が直ちに満たされます。 

いずれかのノードの次数が 3 以上である場合、そのノードはツリーを複数のブランチに分割します。 1 つの接続されたウォーク内のすべての分岐をカバーするには、トラバースは繰り返しそのノードに戻り、訪問回数を 2 回以上に増やす必要があります。 したがって、このような構成は制約上不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        deg = [0] * (n + 1)
        
        for _ in range(n - 1):
            u, v = map(int, input().split())
            deg[u] += 1
            deg[v] += 1
        
        leaves = 0
        ok = True
        
        for i in range(1, n + 1):
            if deg[i] > 2:
                ok = False
            if deg[i] == 1:
                leaves += 1
        
        if n == 2:
            print("YES")
        elif ok and leaves == 2:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```実装は構造条件を直接変換したものです。 次数配列は隣接関係情報を取得します。 エッジ上のループによってツリーが構築されます。 検証ステップでは、次数 2 を超える分岐がないことと、エンドポイントが 2 つだけであるという両方の制約をチェックします。 

特殊なケース n = 2 は暗黙的にパスであり、ロジックはすでにそれを処理していますが、両方のノードが次数 1 を持ち条件を満たしているため、明確にするために明示的にしておきます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    output = []

    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n = int(input())

        for _ in range(n - 1):
            u, v = map(int, input().split())

                leaves += 1

        if n == 2:
            output.append("YES")
        elif ok and leaves == 2:
            output.append("YES")
        else:
            output.append("NO")

    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースは、最小の有効なツリー、n = 2 です。アルゴリズムは両方のノードを葉としてカウントし、2 より大きい次数は見ないため、YES を出力し、単一のエッジが制約内で自明に通過可能であるという事実と一致します。 

もう 1 つの重要なケースは、ほぼパスであるが、追加のエッジ 2-5 を持つ 1-2-3-4 など、単一の追加の枝を持つツリーです。 ここで、ノード 2 の次数は 3 です。アルゴリズムは次数チェックの段階で即座にそれを拒否します。 有効なウォークは 1-2-3-2-4-2-5 などに進む必要があり、ノード 2 を少なくとも 3 回訪問する必要があります。 

最後の微妙なケースは、エンドポイント近くに追加のリーフが取り付けられた長いチェーンです。 視覚的にはパスに似ていますが、その余分なリーフによって次数 3 のノードが作成され、同じ推論が当てはまります。 このアルゴリズムは、歩行構造をシミュレートする必要なく、ローカルで検出します。
