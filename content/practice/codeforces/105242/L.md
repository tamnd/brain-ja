 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれのテスト ケースで整数のリストから始めます。 タスクは、このリストを空ではない 2 つのグループに分割し、すべての要素がいずれかのグループに正確に属するようにすることです。 分割後、各グループの中央値を計算します。中央値は、サイズ k のグループを並べ替えた後の位置 ⌊(k+1)/2⌋ の要素として定義されます。 

目的は、両方のグループが最終的にまったく同じ中央値を持つようにこのような分割を実行する方法が存在するかどうかを判断することです。 

この制約では、最大 100,000 のテスト ケースと、すべてのテストにわたる合計配列サイズが最大 200,000 まで許可されます。分割の列挙ですら指数関数的であるため、これにより、すべてのパーティションをシミュレートしようとするソリューションは即座に排除されます。 各テストを個別に並べ替える作業は、注意せずに繰り返し実行するとすでに境界線に達してしまいますが、中央値の均等条件を実際に支配しているものを理解していれば、それさえも必要ありません。 

中央値がグローバル構造に大きく依存すると仮定すると、素朴な落とし穴が現れます。 たとえば、[2, 3, 2] のような配列では、値が一様に分布していなくても可能ですが、[2, 1] のような 2 要素の配列では不可能です。 微妙なのは、答えは合計のバランスやグローバルな順序に関するものではなく、両方の中央値を共通の値で「固定」できるかどうかにあるということです。 

重要なエッジケースは、非常に小さな配列を中心に展開します。 n = 2 で 2 つの要素が異なる場合、各グループには要素が 1 つだけ含まれ、中央値が強制的に異なるため、答えは NO でなければなりません。 両方の要素が等しい場合、どの分割でも中央値の等しさが維持されるため、答えは「YES」になります。 

## アプローチ

 ブルート フォース ソリューションでは、配列を空ではない 2 つのサブセットに分割するためにあらゆる方法が試行されます。 分割ごとに、両方のサブセットを並べ替えて、それらの中央値を計算します。 これにはすでに 2ⁿ の可能な分割が含まれており、それを無視してサブセットの選択のみを考慮したとしても、分割の数は依然として指数関数的になります。 各中央値の計算には O(n log n) のコストがかかるため、このアプローチは完全に実行不可能になります。 

重要な単純化は、サブセットについて考えるのをやめ、代わりに 2 つの中央値が等しいということが何を意味するかに焦点を当てることです。 両方のグループの中央値 x が同じである場合、x は並べ替え後に構造的に中心に両方のグループに表示される必要があります。 特に、グループが中央値 x を持つためには、x がそれより小さい要素と大きい要素のバランスを「生き残る」ことができなければなりません。 

これは重要な観察につながります。値が配列内に少なくとも 2 回出現する場合、多くの場合、各グループに 1 つの出現箇所を配置し、その値を中央値アンカーの候補として使用できます。 2 つのコピーを取得したら、両方の中央値がその値の中央に位置するように残りの要素を分散できます。 値が複数回出現しない場合、すべての要素は一意となり、分割により 2 つのグループに異なる中間構造が必要となり、中央値を等しくすることは不可能になります。 

これにより、問題は、頻度が少なくとも 2 の値が存在するかどうかを確認するだけになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を読み取り、すべての値の周波数マップを作成します。 目的は、値が繰り返されるかどうかを検出することです。 
2. 頻度マップをスキャンし、頻度が少なくとも 2 であるかどうかを確認します。これにより、両方のグループに現れる可能性のある候補値が存在するかどうかが識別されます。 
3. そのような値が存在する場合は、YES を出力します。 それ以外の場合は NO を出力します。

この決定の背後にある理由は、重複する値が少なくとも 1 つあると、その値を両方のグループに柔軟に配置できるためであり、これには両方の中央値が一致するために必要です。 重複がなければ、すべての要素は一意であり、分割すると、並べ替えによって生じる構造の不均衡により、一方のグループの中央値が他方のグループよりも厳密に小さくなります。 

### なぜ効果があるのか

 ソートされたマルチセットの中央値は、その中心の周りの要素の相対的な位置によって完全に決定されます。 すべての値が異なる場合、両方のグループの安定した中間点として同時に機能する値はないため、配列を分割すると必然的に 2 つの異なる「中心構成」が作成されます。 値が少なくとも 2 回出現すると、その値を共有ピボット要素として使用でき、より小さい要素とより大きい要素を適切に分散することによって、両方のグループがその値を中心に中央値を揃えることができます。 この共有ピボットにより、均等な中央値が達成可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        ok = False
        for v in freq.values():
            if v >= 2:
                ok = True
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースごとに 1 つの周波数辞書を中心に構築されています。 唯一の微妙な点は、各テスト ケースの構造を正しくリセットすることです。これは、ケース間で再利用するとカウントが汚染されるためです。 

チェック自体は個別の値ごとに一定時間行われ、並べ替えや配列の構造操作には依存しません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 [2, 1] のような最小のケースは、重複が存在しない場合には分割が不可能であることを示しています。 アルゴリズムは周波数 {2:1, 1:1} を構築し、正しく NO を返します。 

[1, 1] のようなケースは、最も単純で有効な構造を示しています。 頻度 {1:2} はすぐに YES をトリガーし、各グループに 1 つの要素を配置して両方の中央値が同一になるようにすることに対応します。 

[1, 2, 1] のようなケースは、重複が入力内で隣接したり、構造的に中心にある必要がないことを示しています。 頻度チェックでは繰り返し値が検出され、配列がソートまたはバランス化されていない場合でも分割は可能です。
