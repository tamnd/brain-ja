 ## 解決策
 ## 問題の理解

 英語の小文字で構成される文字列と、各クエリがこの文字列のセグメントを指定する多数のクエリが与えられます。 各セグメントについて、その中の 2 つの位置を選択し、それらの文字を 1 回だけ交換することができます。 この交換の後、セグメントの「パワー」と呼ばれる量を計算します。これは、セグメント内の文字の頻度とその位置の両方に依存します。 

タスクは、クエリ セグメントごとに、この検出力値を厳密に増加させる 2 文字の交換がそのセグメント内に少なくとも 1 つ存在するかどうかを判断することです。 

パワーの定義は一見すると乗法的に見えますが、重要な構造上の詳細は、スワップは文字がセグメント内の位置にどのように割り当てられるかにのみ影響するということです。 セグメント内の文字の頻度は交換後も変化しないため、パワーの変化は純粋に頻度がインデックスとどのように一致するかによってもたらされる必要があります。 

文字列長が 200,000 まで、クエリが 100,000 までの制約範囲により、クエリごとに文字数を最初から再計算することが除外されます。 クエリごとにセグメントをスキャンするソリューションでは、最悪の場合 10¹⁰ の操作が発生するリスクがあり、これは実行可能な制限をはるかに超えています。 これにより、各クエリを O(26) に削減するプレフィックス合計または頻度の事前計算アプローチが必要になります。 

クエリされたセグメント内のすべての文字が同一である場合、微妙なエッジ ケースが発生します。 この状況では、すべてのスワップで同じ文字列が生成されるため、答えは「NO」でなければなりません。 もう 1 つの重要なケースは、異なる文字が存在するが、セグメント内のそれらの頻度がすべて同じである場合です。 その場合、スワップは同じ「重み」を並べ替えるだけであり、厳密な改善は生じないため、答えは依然として「NO」です。 

## アプローチ

 各クエリを直接シミュレートしようとすると、最初に部分文字列内の文字の頻度をカウントし、次に考えられるすべての交換をテストします。 異なる文字の位置間の交換のみを考慮した場合でも、長さ k のセグメント内のクエリごとに O(k²) の可能性があり、最悪の場合、クエリごとに O(n²) に縮退します。 これは制約の下ではすぐに失敗します。 

重要な観察は、スワップによって値が向上するかどうかを決定するために重要な唯一の情報は、セグメント内の文字頻度のマルチセットであり、その配置ではないということです。 セグメント内で各キャラクターが何回登場するかが分かれば、そのキャラクターを運ぶ各ポジションに付加される「重み」もわかります。 

2 つの位置間の交換は、インパクトの高い位置に移動したキャラクターが、インパクトの低い位置に移動したキャラクターよりも厳密に大きい周波数に対応する場合に限り、プラスのゲインに寄与します。 これにより、問題全体が、セグメント内に頻度の異なる 2 つの文字が存在するかどうかを確認することになります。 ゼロ以外の周波数がすべて等しい場合、すべてのスワップは中立です。 それ以外の場合、有益なスワップが常に存在します。 

これにより、各クエリがサイズ 26 の固定アルファベット上の周波数分析問題に変換され、プレフィックス頻度テーブルを使用して回答できます。

 | --- | --- | --- | --- |
 | ブルートフォーススワップ | クエリあたり O(n²) | お(1) | 遅すぎる |
 | プレフィックス周波数チェック | クエリごとに O(26) | O(26n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 文字列に対してプレフィックス頻度テーブルを作成します。ここには、各位置および各文字について、その位置までに出現する回数が格納されます。 これにより、一定のアルファベット時間で任意のセグメントの文字数を抽出できるようになります。 
2. 各クエリ間隔 [l, r] について、プレフィックス値を減算して、そのセグメント内の各文字の頻度を計算します。 これにより、文字の分布を表す 26 個の長さの配列が得られます。 
3. この配列からゼロ以外の周波数をすべて収集します。 存在する異なる文字タイプが 2 つ未満の場合は、交換によって意味のあるものは何も変更されないため、すぐに「いいえ」と答えてください。 
4. ゼロ以外の周波数がすべて同一かどうかを確認します。 それらが同一の場合、すべての文字がセグメント構造に等しく寄与するため、交換するだけでは等しい重みが並べ替えられ、目的を改善することはできません。 
5. 頻度の異なる文字が少なくとも 2 つ存在する場合は、YES を出力します。これは、常に頻度の高い文字と頻度の低い文字を選択し、出現箇所を入れ替えて値を増やすことができるためです。 

### なぜ効果があるのか

 固定セグメント内では、各文字はそのセグメント内の頻度に等しい固定「重み」を与えます。 スワップは、2 つのポジション間でこれらの重みを効果的に交換します。 合計スコアは 2 つの重みが異なる場合にのみ変化し、変化の方向はどの位置にどの重みが割り当てられるかによって異なります。 したがって、交換によって厳密な増加を生み出すことができないため、改善するスワップが存在しない唯一の状況は、利用可能なすべての重みが同一である場合です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

pref = [[0] * 26 for _ in range(n + 1)]

for i, ch in enumerate(s, 1):
    for j in range(26):
        pref[i][j] = pref[i - 1][j]
    pref[i][ord(ch) - 97] += 1

q = int(input().strip())
out = []

for _ in range(q):
    l, r = map(int, input().split())
    freq = []
    for c in range(26):
        cnt = pref[r][c] - pref[l - 1][c]
        if cnt:
            freq.append(cnt)

    if len(freq) <= 1:
        out.append("NO")
        continue

    first = freq[0]
    ok = False
    for x in freq[1:]:
        if x != first:
            ok = True
            break

    out.append("YES" if ok else "NO")

print("\n".join(out))
```この解決策は、部分文字列をスキャンせずにすべてのクエリに応答できるように、プレフィックス頻度テーブルを構築することから始まります。 各クエリは O(26) 内の 26 文字のヒストグラムを抽出し、ゼロ以外の頻度がすべて等しいかどうかを確認します。 決定ロジックは、厳密に有利なスワップが存在するかどうかの条件を直接エンコードします。 

よくある実装上の落とし穴は、セグメントに出現しない文字と出現頻度 0 の文字を区別することを忘れることです。 ゼロ以外の頻度のみを比較する必要があります。そうでない場合、未使用の文字の存在によって誤って違いが引き起こされます。

 ## 特殊なケース

 セグメントに異なる文字が 1 つだけ含まれている場合、交換された両方の文字が同一であるため、すべての交換は事実上何も行われません。 たとえば、次のようなセグメントでは、`aaaa`、すべての文字周波数ベクトルは単一の値に崩壊するため、改善は不可能であり、答えは常に NO です。 

複数の文字が存在するが、それぞれが同じ回数だけ出現する場合。`aabbcc`、すべての文字は同じ頻度 2 を持ちます。どのスワップも同じ重みを交換するだけなので、計算されたスコアは変更されず、正解は NO です。 アルゴリズムは、セグメント内のすべての非ゼロ周波数が同一であることを検出することでこれを捕捉します。 

周波数が異なる場合など`ababa`全範囲にわたって、分布は不均一になり、少なくとも 1 つの文字が別の文字よりも厳密に高い頻度を持ちます。 異なる周波数グループに属する位置間の交換により厳密な改善が得られるため、アルゴリズムはこの不等号を検出し、YES を正しく出力します。
