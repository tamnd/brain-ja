 ## 解決策
 ## 問題の理解

 私たちは、下から上にフロア番号が付けられたホテルを与えられました。 各フロアには構造上の制限があり、そのフロアまたはその上のフロアに滞在できるゲストの数が制限されます。 これらの制限は、建物の最上階から下に向かって累積されます。つまり、各フロアを占有するクライアントの数を決定した場合、フロアごとに、そのフロアとその上のすべてのフロアに配置されているクライアントの総数が、そのフロアに指定されたしきい値を超えることはできません。 

m 人のクライアントが到着しますが、彼らの好みは事前にはわかりません。 各クライアントには、1 から n までのランダムな「ランク」が均一に割り当てられます。 ランク r のクライアントは、フロア 1 から r にのみ滞在することを希望します。つまり、ランクを超える割り当てはすべて拒否します。 

すべてのランクが明らかになった後、ホテルの構造上の制約と各お客様のランク制限の両方を尊重しながら、割り当てられたフロア番号の合計が最大になるように最適な方法でお客様をフロアに割り当てます。 対象となる量は、すべてのランダムなランク割り当てにわたるこの最適な合計の期待値です。 

n、m ≤ 2000 という制約は、3 次解や構成ごとに割り当てを繰り返しシミュレートするものは遅すぎることを意味します。 O(nm) または O(nm log n) に近い値が必要です。 この構造は、ランクのすべての順列をシミュレートすることを避け、代わりに集約された期待値を使用して作業する必要があることを強く示唆しています。 

最上階の収容力が逼迫している場合、微妙なエッジケースが発生します。 たとえば、w = [2, 2, 1] および m = 3 の場合、最上階は合計で 1 つのクライアントのみを保持でき、累積的な制約により、そのフロアの決定は下位フロアすべてに影響します。 サフィックス結合を無視した貪欲な割り当ては、個々のフロア制約が個別に有効に見えても、下位フロアを過剰に満たして実現可能性を損なう可能性があります。 

もう 1 つの重要なケースは、すべての w_i が大きい場合です。たとえば、すべての i に対して w_i ≥ m です。 次に、問題は、ランク制約の下で予想される割り当ての下限値を純粋に最大化することに帰着し、正しい解決策は、容量をまったく関与させるのではなく、対称的な期待引数にきれいに帰着するはずです。 

## アプローチ

 この問題を考える直接的な方法は、プロセス全体をシミュレーションすることです。 m 個のクライアントに対して考えられるランクの割り当てをすべて生成し、貪欲な戦略を使用して各構成の最適な配置を計算し、結果を平均します。 ランクが固定されると、割り当てはネストされた制約を伴う決定論的な最大重みパッキング問題になるため、これは概念的には簡単です。 ただし、ランク構成の数は n^m であり、計算限界をはるかに超えています。 単一の構成であっても並べ替えまたは貪欲な割り当てが必要なため、このアプローチはすぐに失敗します。 

重要な観察は、実際には完全な構成について推論する必要がないということです。 唯一のランダム性は各フロアに適格なクライアントの数であり、適格性は単調です。クライアントはそのランクまでのすべてのフロアに適格です。 これにより、問題は、各フロア i に予想される利用可能なクライアントのプールと、ホテルの制約から導き出される収容力を持つ、構造化されたリソース割り当てシステムに変わります。 

個々のクライアントに対応するのではなく、期待されるフローに視点を移します。 各フロアには対象となるお客様の数が想定されており、上位フロアから下位フロアまで貪欲に配分していきたいと考えています。 フロアに対する累積制約は、差分を取ることでフロアごとの容量に変換できます。つまり、フロア i に正確に配置できるクライアントの数は、c_i = w_i − w_{i+1} によって制限されます。ここで、w_{n+1} = 0 と定義します。これにより、サフィックス制約が独立したフロアごとの上限に変換されます。

残る唯一の問題は、資格がランダムであることです。 クライアントは、確率 (n − i + 1) / n でフロア i に参加する資格があります。 期待は線形であるため、完全な配布ではなく、期待される供給で作業できます。 最適な予想される割り当ては、部分的な貪欲な充填プロセスのように動作します。つまり、キャパシティと予想される可用性の両方を考慮して、予想されるクライアントを最上階から最下階まで割り当てます。 

これにより、フロア プレフィックスごとに予想される可用性を事前に計算すると、決定論的な O(n) パスが得られます。

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 接尾語の制約をフロアごとの容量に変換します。 各フロア i について、w_{n+1} = 0 として c_i = w_i − w_{i+1} を定義します。これにより、上位フロアの制限に違反せずに各フロアに正確に配置できるクライアントの数が特定されます。 
2. フロア i ごとに、フロア i に単一のクライアントを配置できる確率を計算します。これは、P(r ≥ i) = (n − i + 1) / n です。 これにより、フロア全体で均一な予想可用性構造が得られます。 
3. m を掛けて、フロア i またはそれより下のフロアに適格なクライアントの予想数を取得します。 これにより、フロア全体の累積供給曲線が得られます。 
4. フロアを上から下まで処理し、まだ割り当てられていないクライアントの残りの予想供給を維持します。 各フロア i で、そのフロアにできるだけ多くのクライアントを割り当てます。これは、c_i と現在の残りの供給の最小値です。 
5. 残りの供給量から割り当てられた量を差し引き、下方向に進みます。 割り当てられた各ユニットは i を最終的な答えに寄与するため、i × assign[i] を累積します。 

この貪欲なステップが正しい理由は、上位フロアが常に下位フロアよりも価値が優勢であるため、制約に違反することなくクライアントを上位に移動させる割り当ての交換は厳密に目的を向上させるためです。 

### なぜ効果があるのか

 フロアごとの容量への変換により、各フロアが独自の境界 c_i を尊重する場合、構造上の制約が決して違反されないことが保証されます。 期待供給モデルが機能するのは、各クライアントが個別にフロア適格性に寄与するためであり、システムは期待に沿って線形に動作します。 目標は割り当てにおいても線形であるため、容量または予想される供給が枯渇するまで、最初に最も価値の高いフロアを貪欲に埋めることによって、予想される割り当てを最大化することができます。 下の階が占有されているのに、上の階が部分的に埋まってしまうと、割り当てを再配置しても解決策を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, m = map(int, input().split())
    w = list(map(int, input().split()))

    w.append(0)

    c = [0] * (n + 1)
    for i in range(1, n + 1):
        c[i] = w[i - 1] - w[i]

    # expected total supply for floor i or below from all m clients
    # P(r >= i) = (n - i + 1) / n
    inv_n = modinv(n)

    expected_supply = [0] * (n + 2)
    for i in range(1, n + 1):
        expected_supply[i] = m * (n - i + 1) * inv_n % MOD

    remaining = m
    ans = 0

    for i in range(n, 0, -1):
        # available expected mass for floors >= i is remaining * P(r >= i)
        avail = remaining * (n - i + 1) * inv_n % MOD

        take = min(c[i], avail)
        ans = (ans + take * i) % MOD
        remaining = (remaining - take) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装では、まず、差分を使用して累積フロア制約を独立したフロアごとの容量に変換します。 次に、ランクの一様分布を使用して、フロアの各サフィックスに適格なクライアントの予想数をモデル化します。 メイン ループはフロアを上から下に処理し、キャパシティと残りの可用性の両方で許容される限り、予想される質量を貪欲に割り当てます。 

微妙な点は、私たちが個々のクライアントをシミュレートすることは決してないということです。 代わりに、残りの予想割り当て可能質量を表す単一のスカラーを維持します。これは、すべてのクライアントが交換可能であり、適格性の確率のみが重要であるため有効です。

 ### 例 1

 入力:```
5 2
5 5 4 4 4
```差分を考慮して、概念的にフロアごとの容量 c = [0, 0, 1, 0, 0, 4] を計算します。 

5階から下まで処理していきます。 

| フロア i | 容量 c_i | 残りの供給量 (スケール) | 割り当て済み | 貢献 |
 | --- | --- | --- | --- | --- |
 | 5 | 4 | 2 * 1/5 | 小さい | 5 * 割り当て済み |
 | 4 | 0 | 残り | 0 | 0 |
 | 3 | 1 | 残り | min(1, 利用可能) | 3 * 割り当て済み |
 | 2 | 0 | 残り | 0 | 0 |
 | 1 | - | 残り | 残り物 | 1 * 割り当て済み |

 このアルゴリズムは、資格が許す限り常にクライアントを高層階に配置することを優先し、キャパシティに見合った最大の期待報酬を生み出します。 

このトレースは、より高いフロアがどのように利用可能な予想質量を最初に消費するかを示しており、より低いフロアの割り当てが実現可能なより高い配置から価値を盗むことがないことを保証します。

 ## 特殊なケース

 すべてのフロアの収容力が非常に大きい場合、アルゴリズムは純粋に予想されるランク適格性に基づいて割り当てます。 その場合、すべてのフロアには実質的に制限がなく、貪欲なスイープは、予想されるクライアントの数を上から下まで比例的に分配することになります。 出力は、下限インデックスに対するきれいな線形の期待値になります。 

最下層のフロアのみにゼロ以外の収容力がある場合、ランクに関係なく、予想されるすべての質量がフロア 1 に流れます。 高層階には収容力がゼロであるため、予想される供給量がまったく消費されないため、アルゴリズムは自然にこれを強制します。 

最上部付近でキャパシティが急激に減少すると、アルゴリズムはまずそれらのフロアを埋めることを優先します。 たとえ下層階の残存容量が大きい場合でも、目的関数によって誘導される最適構造と一致する高層階が飽和するまで、下層階には割り当ては行われません。
