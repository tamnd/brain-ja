 ## 解決策
 ## 問題の理解

 英語の小文字アルファベットのカスタム順序が与えられており、26 文字が厳密な合計順序を定義する特定の順序で表示されます。 この順序で文字が前に現れる場合、その文字は小さいとみなされます。 これにより、これらの文字から構築された文字列に辞書編集的な順序が導入されます。 

このカスタムのアルファベット順を定義すると、文字列のコレクションが得られます。 タスクは、このカスタム辞書編集順を使用して指定されたすべての文字列を並べ替えた場合に、どの文字列が位置 K に表示されるかを判断することです。その後、最終的なタイブレーカーとして長さで拡張された標準の辞書編集比較を行います。 

重要な点は、「辞書編集上の最小値」は通常の規則に基づいていないということです。`'a' < 'b' < ... < 'z'`ですが、代わりに、指定されたアルファベットの順列が使用されます。 

計算の観点から見ると、n は最大 1000、各文字列の長さは最大 1000 です。各比較は最悪でも O(1000) であるため、文字列比較に対する O(n log n) の並べ替えが可能になります。 すべての順列を強引に列挙したり、完全なトライ ランキング構造を構築したりすることは、不必要な過剰作業となります。 

アルファベットの順序が標準ではないという事実から、微妙な特殊なケースが発生します。 たとえば、注文が次で始まる場合、`zabcdefghijklmnopqrstuvwxy`、 それから`'z'`が最小であり、`'a'`は 2 番目に小さいです。 文字の再マップを忘れた単純な実装では、多くの偶発的なテストに合格しながらも、完全に間違った順序が生成されます。 

もう 1 つの潜在的な落とし穴は、辞書編集上の比較ルールを誤解することです。 比較は接頭辞に依存します。つまり、ある文字列が別の文字列の接頭辞である場合、短い文字列の方が小さくなります。 たとえば、次の場合`"a"`そして`"ab"`比較され、`"a"`アルファベットの順序に関係なく、最初に来る必要があります。 

## アプローチ

 強引なアプローチは、指定されたアルファベット順を使用して 2 つの文字列を 1 文字ずつ直接比較するコンパレーターを定義し、配列全体をソートすることです。 辞書編集上の順序はペアごとの比較によって完全に決定されるため、これは正しいです。 ただし、このアプローチは依然として文字列の繰り返しの比較に依存しており、各比較では最大 O(L) 文字をスキャンできます (L は文字列の最大長です)。 n が 1000 まで、L が 1000 までの場合、ソートの結果はおよそ O(n log n · L) になります。これは、最悪の場合でも約 10^7 の文字チェックに相当しますが、それでも Python では許容可能です。 

より構造化された観察は、唯一の困難は文字を効率的に比較することにあるということです。 各文字をカスタム アルファベットのランクに変換すると、すべての文字列が一連の整数になり、標準の辞書編集順序が直接適用されます。 これにより、比較内で辞書検索を繰り返すオーバーヘッドがなくなり、実際のソートがよりクリーンかつ高速になります。 

したがって、最適な解決策は、文字からランクへのマッピングを構築し、変換されたキーを使用して並べ替えることです。

 ## アルゴリズムのチュートリアル

 1. カスタムのアルファベット順の文字列を読み取り、配列を構築します`rank`そのような`rank[c]`キャラクターの位置を与える`c`この順序で。 これにより、任意の 2 つの文字間の O(1) 比較が可能になります。 これが必要な理由は、文字列の直接比較が非標準の順序での繰り返しの検索に依存しているためです。 
2. すべての入力文字列をリストに読み取ります。 各文字列は、後でカスタム順序に基づいて同等の表現に変換されます。 
3. 各文字列について、すべての文字がそのランク値で置き換えられる変換バージョンを構築します。 これにより、カスタム アルファベットでの辞書編集的な比較が、整数に対する通常の辞書編集的な比較に変換されます。 このステップは概念的には問題の正規化です。 
4. これらの変換された表現をソートキーとして使用して、文字列のリストをソートします。 Python の組み込みソートは、タプルまたは整数のリストに辞書編集的な順序付けを正しく適用します。 
5. ソート後の元のリストの K 番目の文字列を出力します。 実際の出力形式が失われないように、変換されたキーと一緒に元の文字列も保持します。 

### なぜ効果があるのか

 辞書編集的な比較ルールは文字の実際の識別ではなく、文字の相対的な順序のみに依存するため、変換では順序が維持されます。 各文字をカスタム アルファベットのランクにマッピングすることで、カスタム順序を標準の整数順序に埋め込みます。 Python は辞書順にシーケンスを比較するため、変換された配列を比較することは、指定されたアルファベットの下で元の文字列を比較することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    order = input().strip()
    rank = [0] * 26
    for i, ch in enumerate(order):
        rank[ord(ch) - 97] = i

    n = int(input())
    arr = []
    for _ in range(n):
        s = input().strip()
        key = tuple(rank[ord(c) - 97] for c in s)
        arr.append((key, s))

    k = int(input())
    arr.sort(key=lambda x: x[0])
    print(arr[k - 1][1])

if __name__ == "__main__":
    solve()
```実装では、まず文字からカスタム順序インデックスへの直接マッピングを構築します。 これにより、比較中にアルファベット文字列を繰り返しスキャンする必要がなくなります。 

各文字列は、新しい順序でその文字のタプル表現とペアになります。 タプルが使用されるのは、Python が O (タプルの長さ) でタプルを辞書編集的に比較するためであり、これは意図した文字列比較動作と正確に一致します。 

これらのキーを使用してソートが行われ、ソート後に K 番目の要素が抽出されます。 

よくある微妙な間違いは、文字をランクに変換するのを忘れ、代わりに ASCII 順序に依存することです。これにより、カスタム アルファベットが標準順序と異なる場合は常に結果が完全に無効になります。

 ## 特殊なケース

 重要なエッジ ケースは、カスタム アルファベットで順序が重要な文字を除いて文字列が同一である場合です。 たとえば、注文の場合`acb...`、比較する`"ab"`そして`"ac"`の相対的な順序に完全に依存します`b`そして`c`。 両方の文字が比較前にランクに変換されるため、アルゴリズムはこれを正しく処理します。 

Another edge case is prefix relationships. 考慮する`"ab"`そして`"a"`。 たとえ`b`アルファベットのほとんどの文字よりも小さく、`"a"`比較は短い文字列の終わりで終了するため、やはり最初に来る必要があります。 タプル表現はこれを自動的に保存します。`(rank('a'),)`よりも短いです`(rank('a'), rank('b'))`、Python の辞書編集タプルの比較では、短い接頭辞が小さいものとして扱われます。 

最後に、最大長の文字列を含むケースは安全に処理されます。これは、変換が文字列ごとに線形であり、変換を超えて構造が変更されないため、隠れた再帰や深いコピーのオーバーヘッドが発生しないことが保証されます。
