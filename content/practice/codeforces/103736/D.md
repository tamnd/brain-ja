 ## 解決策
 ## 問題の理解

 私たちはツリーを扱っています。これは、頂点のすべてのペアが 1 つの単純なパスによって接続されている、接続された非巡回グラフを意味します。 各クエリ頂点 x について、ツリー内の個別の単純なパスが x を通過する数をカウントする必要があります。 パスは方向がないとみなされるため、a から b への移動は b から a への移動と同じです。 

重要な詳細は、有効なパスは、ルート上のどこか x を通過する限り、ツリー内のどこで開始および終了してもよいということです。 頂点が繰り返されないように、パスは単純である必要があります。 また、少なくとも 1 つの長さのパスがカウントされるため、単一の頂点パスは含まれません。 

入力サイズは最大 100,000 頂点と 100,000 クエリに達するため、クエリごとの情報を線形時間で再計算するソリューションは遅すぎます。 n 個のノードを持つツリーにはすでに Θ(n²) 個の単純なパスがあり、各クエリに対してそれぞれをチェックすることは実行可能な制限をはるかに超えているため、すべてのパスを直接列挙することは不可能です。 

ツリーが x を中心とするスターである場合、微妙なエッジ ケースが発生します。 その場合、ほぼすべてのパスが x を通過することになり、単純な列挙方法では方向や端点が誤って扱われるため、カウントが過剰になる傾向があります。 たとえば、x が a、b、c に接続されている場合、パス [a、x、b] は [b、x、a] と同じであり、1 回だけカウントする必要があります。 

## アプローチ

 強引なアイデアでは、ツリー内のすべての単純なパスを列挙し、クエリ ノード x ごとに、x がそのパス上にあるかどうかを確認しようとします。 これではすぐに 2 つの問題が発生します。 まず、すべての単純なパスを列挙することは、すでにツリー内の Θ(n²) です。 第 2 に、これをクエリごとに実行すると Θ(n²q) が発生しますが、これは指定された制約ではまったく実行不可能です。 

x を通るパスをリストせずにカウントする方法が必要です。 重要な構造上の観察は、ノード x を削除すると、ツリーが複数の接続されたコンポーネント (x の各隣接コンポーネントに 1 つずつ) に分割されるということです。 x を通過する単純なパスは、1 つのコンポーネントから来て x を通過し、別のコンポーネントに継続する (または x で終了する) 必要があります。 これにより、問題は、異なる隣接サブツリーからのノードのペアと、x で開始または終了するパスをカウントすることになります。 

ツリーを任意にルート化し、サブツリーのサイズを計算すると、x に隣接する各枝にノードがいくつあるかを理解できます。 x の次数が k で、x を削除すると、ツリーがサイズ s1、s2、...、sk の k 個のコンポーネントに分割されるとします。 x を通過するパスは、異なるコンポーネントで 2 つの端点を選択するか、コンポーネントと x 自体で 1 つの端点を選択することによって決定されます。 

したがって、答えは、さまざまなコンポーネント内のノードのペアの数と、x に付随するすべてのシングルエッジ パスの数になります。 コンポーネント間の寄与は、標準的な組み合わせの同一性、つまり合計ペアから各コンポーネント内のペアを差し引いたものです。 

任意のノードをルートとする DFS を使用してサブツリーのサイズを事前計算します。 各ノード x について、各子側コンポーネントのサイズを決定できます。 唯一欠けているケースは、x の「親側」です。これは、ルート化されたときに、x のサブツリーの外側にあるツリーの残りの部分に対応します。 

これにより、O(n) 個の前処理ソリューションと O(1) 個のクエリ応答が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パスを列挙) | クエリあたり O(n²) | O(n²) | 遅すぎる |
 | 最適 (サブツリー分解) | O(n) 前処理 + クエリあたり O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、DFS を使用してサブツリーのサイズを計算します。 すべてのノード x について、各子サブツリーのサイズも追跡します。 

固定クエリ ノード x の場合、その入射エッジがグラフを複数のコンポーネントに分割していると解釈します。

1. x の周囲の各コンポーネントのサイズを計算します。 x の各子 v は、v のサブツリー サイズに等しいサイズのコンポーネントを提供します。残りのコンポーネント サイズは、n から x のサブツリー サイズを引いたものになります。 
2. 各コンポーネントのサイズをノードのバケットとして扱います。 x を通過する有効なパスは、これらのバケットからエンドポイントを選択するか、x 自体を使用することによって決定されます。 
3. エンドポイントとして x を持つすべてのパスをカウントします。 x は一意の単純なパスを介して他のすべてのノードに接続できるため、そのようなパスは正確に (n − 1) 通りあります。 
4. x が厳密に内部にあるパスをすべてカウントします。 これらは、エンドポイントが 2 つの異なるコンポーネント内にあるパスです。 コンポーネントのサイズが s1、s2、...、sk の場合、そのようなパスの数は、si * sj の i < j の合計になります。 
5. 両方の寄与を組み合わせて答えを導き出します。 

コンポーネント間の合計を計算する便利な方法は、恒等式を使用することです。 

sum_{i < j} si * sj = ( (sum si)² − sum si² ) / 2.

 ここで、合計 si = n − 1 となります。 

### なぜ効果があるのか

 x を通過するすべての単純なパスは、正確に 1 つの近傍から x に入り、別の近傍に向かって出るか、x で終了する必要があります。 x を削除すると、ツリーが独立したコンポーネントに分割されるため、パスのエンドポイントは、どのコンポーネントに含まれるかを一意に決定します。これにより、有効なパスと、x とペアになった 1 つのエンドポイント、または個別のコンポーネント内の 2 つのエンドポイントとの間に全単射が作成されます。 各単純なパスには一意のエンドポイントのペアがあるため、パスは 2 回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (n + 1)
sz = [0] * (n + 1)

def dfs(u, p):
    parent[u] = p
    sz[u] = 1
    for v in g[u]:
        if v == p:
            continue
        dfs(v, u)
        sz[u] += sz[v]

dfs(1, 0)

q = int(input())

for _ in range(q):
    x = int(input())

    comp_sizes = []

    for v in g[x]:
        if v == parent[x]:
            comp_sizes.append(n - sz[x])
        else:
            comp_sizes.append(sz[v])

    total = 0
    sum_s = 0
    sum_sq = 0

    for s in comp_sizes:
        sum_s += s
        sum_sq += s * s

    total_pairs = (sum_s * sum_s - sum_sq) // 2

    # paths where x is endpoint
    total = total_pairs + (n - 1)

    print(total)
```DFS はサブツリーのサイズを計算して、各ノードがルート化されたツリーの下に頂点がいくつあるかを認識します。 クエリ ノード x については、その隣接リストを調べて、各隣接ノードをコンポーネント サイズに変換します。 特殊なケースの 1 つは親エッジです。これは、x のサブツリーの外側にあるツリーの残りの部分を表します。 

次に、標準の代数恒等式を使用して、さまざまなコンポーネントからのノードのペアの数を計算します。 最後に、x がエンドポイントであるすべてのパスを追加します。これは、他のすべてのノードが x への単純なパスを 1 つだけ定義しているため、単純に n − 1 になります。 

親コンポーネントを正しく識別するには注意が必要です。 親情報を保存しないと、すべての近傍を誤ってサブツリーの子として扱い、外側のコンポーネントが失われることになります。

 | ステップ | コンポーネント | 合計 | 和平方根 | クロスペア | エンドポイント パス | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | x=1 | [1,3,1] | 5 | 11 | 10 | 4 | 14 |

 コンポーネントのサイズは、subtree(2)=1、subtree(3)=3、親側なしです。 クロスペアにより内部的に 1 を通過するパスが得られ、エンドポイントを追加すると 1 を通る合計パスが得られます。 

x = 3 の場合:

 | ステップ | コンポーネント | 合計 | 和平方根 | クロスペア | エンドポイント パス | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | x=3 | [1,1,2] | 4 | 6 | 5 | 4 | 9 |

 これは、3 を削除するとツリーが 3 つの独立した部分に分割され、これらの部分にまたがる端点と 3 で終わる端点のペアによってパスがカウントされる様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q * 度(x)) | DFS はサブツリー サイズを 1 回計算し、各クエリで x | の近傍をスキャンします。 
| スペース | O(n) | 隣接リスト、親配列、サブツリーのサイズ |

 この制約により、最大 100,000 個のノードとクエリが許可され、合計次数が 2(n−1) になるため、クエリごとの隣接スキャンは十分に効率的となり、実際にはすべてのクエリが集合的に線形になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    sys.setrecursionlimit(10**7)
    parent = [0] * (n + 1)
    sz = [0] * (n + 1)

    def dfs(u, p):
        parent[u] = p
        sz[u] = 1
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
            sz[u] += sz[v]

    dfs(1, 0)

    q = int(input())
    out = []
    for _ in range(q):
        x = int(input())
        comp = []
        for v in g[x]:
            if v == parent[x]:
                comp.append(n - sz[x])
            else:
                comp.append(sz[v])

        s = sum(comp)
        ss = sum(c * c for c in comp)
        ans = (s * s - ss) // 2 + (n - 1)
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 2 ノード ツリーは最も単純な境界です。 入力の場合:```
2
1 2
1
1
```ノード 1 にはサイズ 1 の単一コンポーネントがあります。コンポーネント間ペアはゼロで、エンドポイント パスの寄与は正確に 1 であるため、答えは 1 で、単一パス [1,2] と一致します。 

スター ツリーは、コンポーネント分割ロジックを強調します。 葉が 4 つある中心 x の場合、コンポーネントは [1,1,1,1] です。 クロス ペアでは 6 つのパスが得られ、エンドポイントの寄与により 4 が追加され、合計 10 になります。アルゴリズムは、x を削除した後、すべてのリーフを別個のコンポーネントとして正しく処理します。 

チェーンは方向の偏りをチェックします。 パス 1-2-3-4-5 のノード 3 の場合、コンポーネントは [2,2] です。 クロスペアは 4、エンドポイント寄与は 4、合計 8? 実際にはエンドポイント パスは 4 であるため、合計は 8 となり、3 を含むすべてのパスが 1 回だけ一致します。 サブツリーのサイズはチェーンの両側を正しく反映しているため、計算の一貫性が保たれます。
