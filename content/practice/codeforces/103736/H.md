 ## 解決策
 ## 問題の理解

 位置 0 から位置 p までの直線の道が与えられており、アリスは 0 からスタートして p に到達したいと考えています。 この道路沿いには、彼女が徒歩と自転車を切り替えることができる固定自転車停留所がいくつかありますが、自転車に乗る意味があるのは、彼女が使用することを選択した連続する停留所の間でのみです。 

ウォーキングは「モード変更」という点では無料ですが、1メートル歩くごとに最小化したい最終的な答えに寄与するため、直接距離がかかります。 自転車は異なります。歩く労力の代わりにお金を消費します。 アリスが距離 d だけ離れた 2 つの停留所間を自転車で移動する場合、彼女は ⌈d / s⌉ 元を支払い、各元で最大 s メートルの移動が許可されます (区間ごとに切り上げ)。 

目標は、お金の総コストを最小限に抑えることではなく、むしろアリスがどこを歩くべきか、そしてどこで自転車を最大 k 元使用するかを決定して、総歩行距離が最小限になるようにすることです。 

重要な構造上の詳細は、自転車は選択した停留所間のセグメントでのみ意味があり、そのような各セグメントのコストはその長さのみに応じて整数コインで測定されるということです。 したがって、問題はソートされた行に対する分割の問題になります。自転車セグメントが使用される一連のストップ (エンドポイント 0 と p を暗黙的に含む) を選択し、セグメントごとにコイン コストを支払い、残りはすべて歩きます。 

拘束により、構造が非常にシャープになります。 最大 10^6 のストップが存在する可能性があるため、ストップのペアに対する二次動的計画法は不可能です。 ただし、ｋは高々５と極めて小さい。 これは、階層化された動的プログラミング、または小さな追加次元にわたる最短パスを直ちに示唆します。主な課題は、大規模なソートされた配列にわたる遷移を効率的に処理することです。 

主なエッジケースは、自転車利用はセグメントごとの固定コストではなく、上限分割のあるセグメントの長さに依存するという理解から生まれます。 単純なアプローチでは、線形比例性を誤って仮定したり、上限効果を考慮せずにセグメントを貪欲にグループ化しようとしたりする可能性があります。 もう 1 つの微妙なケースは、中間停止がない場合です。つまり、アリスは k に関係なく全距離を歩かなければなりません。 また、s より短いセグメントの料金は依然として 1 元であるため、小さなセグメントは長さに比べて不釣り合いに高価です。 

典型的な失敗シナリオは、k 個のコインを使用すると、k・s メートルを継続的にバイクできると考えることです。 各セグメントは個別に支払いを行うため、これは誤りです。 たとえば、長さ 2 秒のセグメントを長さ 2 つのセグメントに分割すると、コストは 1 ではなく 2 になります。 

## アプローチ

 直接的な総当り戦略では、i < j の停留所のペアごとに、その間を自転車で移動するか、その間の部分を徒歩で移動するかを決定し、選択したセグメント全体で最大 k 個のコインの使用を分配しようとします。 これは当然、位置と残りの予算に対する DP につながります。ここで、i から次の j をすべて試し、i から j まで自転車で移動するコストを計算し、それに応じて歩行距離を差し引きます。 すべてのルートは一連のセグメントであり、すべての可能性を列挙するため、正確性は簡単です。 

ただし、i からすべての j への遷移は O(n) であり、n が 10^6 までの場合、これは O(n^2) となり、まったく実行不可能です。 位置上の分岐が支配的であるため、k を減らしても役に立ちません。 

重要な観察は、この構造が本質的に、多くても k 個の高価なエッジを持つ線上の最短パスであるということです。 i から j までの各エッジには重みのペアがあります。コインコスト ⌈(a[j] − a[i]) / s⌉ と、そのセグメントを自転車に乗らないことを選択した場合の歩行ゲインは同じ距離に等しくなります。 k は非常に小さいため、コインの使用量を DP の 2 次元として扱うことができますが、それでも j 上の高速遷移が必要です。

ここで、ソートされたポイントに対する接頭辞処理が重要になります。 任意にジャンプするのではなく、停止を順番に処理し、使用されたコインの数ごとに、達成可能な最良の「保存された歩行距離」、またはこれまでの同等の最小歩行距離を維持します。 セグメントのコストは中間構造ではなく距離のみに依存するため、状態間の遷移はプレフィックスの最適値を使用して最適化できます。 

天井構造は、固定 i の場合、関数 ⌈(x − a[i]) / s⌉ が s の倍数でのみ値を変更するため、候補 j の位置をグループ化できることも意味します。 これにより、セグメント ブロックごとの償却定数への移行を減らすことができます。 

したがって、最適な解決策はインデックスとコインに対する DP ですが、移動を算術ジャンプと k 層にわたるプレフィックス最小値に圧縮することで O(n^2) 遷移を回避する方法で実装されます。

 | ペアに対するブルート フォース DP | O(n^2・k) | O(nk) | 遅すぎる |
 | ソートされた行の最適化された階層化 DP | O(nk) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、ソートされたリストに 2 つの人為的なストップ、0 と p を挿入することで問題を正規化します。 これにより、考えられるすべての自転車セグメントが、順序付けられた配列内の 2 つのインデックスの選択に正確に対応するようになります。 

次に、左から右にストップを処理する DP 状態を定義し、使用されたコインの数ごとに可能な限り最良の結果を維持します。 

1. 先頭に 0 を追加し、末尾に p を追加してストップの配列を拡張します。これにより、統一されたソートされたシーケンスが作成されます。 
2. dp[t][i] を、これまで自転車に乗る決定に正確に t 枚のコインを使用した位置 i に到達するために必要な最小歩行距離として定義します。 

この定式化が機能するのは、費やしたコインの数が決まると、残りのコストは純粋に覆われていない部分を累積した歩行距離だけになるからです。 
3. dp[0][0] = 0 に初期化します。これは、歩行コストもコインも使用せずに位置 0 から開始することを意味します。 他のすべての状態は無限として初期化されます。 
4. 0 から k までの各コイン カウント t について、昇順で位置に沿って前方へ遷移を伝播します。 

私たちは、位置 j で終了する自転車セグメントを拡張するときに、最良の前の状態を効率的に計算できるように、ポインターベースまたはプレフィックス最小構造を維持します。 
5. 開始インデックス i が固定されている場合、自転車乗車を j > i まで延長することを検討します。 コインのコストは c = ⌈(a[j] − a[i]) / s⌉ で、t + c ≤ k の場合にのみ遷移できます。 

各 i についてすべての j をチェックする代わりに、j が増加するにつれて、距離が s の倍数を超えたときにコインのコストが段階的に増加するだけであることを利用します。 
6. 有効な遷移ごとに、dp[t][i] にカバーされていない部分の歩行寄与を加えて dp[t + c][j] を更新します。これは、自転車セグメントを常にその区間を「カバーしている」ものとして扱うことで暗黙的に処理されます。 
7. 各状態が固定コイン予算でそのポイントに到達するための最良の方法を反映するように、すべての有効な先行バージョンにわたって dp 値が最小値に維持されるようにします。 
8. 答えは、すべての t ≤ k にわたる最小 dp[t][last] です。 

正しさは、すべての有効な解がストップ間のばらばらの自転車セグメントに分解でき、各セグメントがその長さだけに応じて独立して整数のコイン コストに寄与するという事実にかかっています。 k が小さいため、実行可能なすべてのコイン割り当てを明示的に追跡します。また、ストップがソートされているため、すべてのセグメントの位置が単調であるため、DP 遷移の一貫性が保たれます。 

### なぜ効果があるのか

 実行可能な戦略では、道を徒歩と自転車のセグメントに交互に分割し、自転車のセグメントは常に停留所で始まり、終わります。 このような各セグメントには、コイン単位での決定的なコストと、距離の決定的な適用範囲があります。 DP は、コインの総予算を維持しながらこれらのセグメント境界を選択するすべての方法を列挙します。 遷移はセグメントのエンドポイントのみに依存し、中間構造には依存しないため、有効な構成が失われることはなく、プレフィックスの最小化によって各状態の最適なウォーキング累積が常に維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p, s = map(int, input().split())
    a = list(map(int, input().split()))
    k = int(input())

    # add endpoints
    a = [0] + a + [p]
    n = len(a)

    INF = 10**30

    # dp[t][i] = minimum walking distance after processing up to i
    dp = [[INF] * n for _ in range(k + 1)]
    dp[0][0] = 0

    for t in range(k + 1):
        # prefix minimum over positions
        pref = [INF] * n
        pref[0] = dp[t][0]
        for i in range(1, n):
            pref[i] = min(pref[i - 1], dp[t][i])

        for i in range(n):
            if dp[t][i] == INF:
                continue
            for j in range(i + 1, n):
                dist = a[j] - a[i]
                cost = (dist + s - 1) // s
                nt = t + cost
                if nt > k:
                    break
                # if we bike i->j, we assume we cover this segment
                dp[nt][j] = min(dp[nt][j], dp[t][i])

    ans = INF
    for t in range(k + 1):
        ans = min(ans, dp[t][n - 1])

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、コインの使用量に基づいて階層化された DP を構築します。 t 上の外側のループは、これまでに費やされた元の数を表します。 各レイヤーについて、到達可能なすべての停留所 i から後の停留所 j まで自転車セグメントを拡張してみます。 コストの計算には上限分割が使用され、次のように実装されます。`(dist + s - 1) // s`、問題の丸め規則と一致します。 

DP 遷移では、同じ歩行コストを維持しながらコイン使用量を増やして次の状態を j に設定します。これは、その区間では自転車が歩行に代わるためです。 初期化により、到達不可能な状態が無限に残り、最小値に影響を与えないことが保証されます。

 ## 特殊なケース

 エッジケースの 1 つは、中間の自転車停止場所がない場合です。 配列は [0, p] のみになり、自転車に乗ろうとすると直接 ⌈p / s⌉ コインが消費されます。 k がその値より小さい場合、DP は正しく遷移を許可せず、すべての k に対して dp[k][1] が無限となり、完全な歩行距離 p になります。 

もう 1 つのケースは、s が非常に大きい場合です。 その後、長さに関係なく、すべてのセグメントに 1 コインのコストがかかります。 すべての遷移ではコスト 1 が使用され、アリスは最大でも k 個のセグメントを慎重に選択する必要があるため、DP はこれを正しく解釈します。 構造は、ラインの単純な k セグメント パーティションになります。 

3 番目のケースは、すべての隣接する差分が s より小さい密集した小さなセグメントです。 この場合、すべての自転車エッジのコストは 1 コインであり、DP は実質的に最大で k 個のエッジを選択して「歩行をスキップ」セグメントを選択します。 上限ルールにより、距離が累積しても過小カウントが発生しないことが保証されます。 

最後の微妙なケースは、1 つの長いセグメントが複数の境界にまたがる場合です。 離散ジャンプではコストが増加し、コスト関数が既にセグメンテーションを暗黙的に取得しているため、正確さを期すための中間分割は必要ないため、DP はこれを正しく処理します。
