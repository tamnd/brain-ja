 ## 解決策
 ## 問題の理解

 変数の下限の配列と目標合計制約が与えられます。 各変数$x_i$少なくとも$a_i$、整数ベクトルがいくつあるかを尋ねられます$x_1, x_2, \dots, x_n$満足する$$x_1 + x_2 + \dots + x_n \le s$$各更新の後、配列の 1 つの位置$a$は永続的に変更されるため、有効な解の数を再計算する必要があります。 

入力は動的です。すべての操作で 1 つの下限が変更され、答えはすべての操作の現在の状態にのみ依存します。$a_i$。 各更新後の出力は、有効な整数割り当ての数です。 

制約$n, q \le 2 \cdot 10^5$よりもはるかに速く答えを再計算する必要があります$O(nq)$。 構造体サイズと更新数の両方が大きいため、どのソリューションも高速ポイント更新とグローバル組み合わせ値の高速再計算をサポートする必要があります。 

重要な観察は、制約が変数の下限を除いて対称であることです。 これは、変数を変換して下限を削除することを示唆しており、これにより問題は古典的な境界のある組成カウント問題に変わります。 

有用な導出数量は、必須の合計です。$$A = \sum a_i$$新しい変数を定義すると$y_i = x_i - a_i$、その後、それぞれ$y_i \ge 0$となり、制約は次のようになります。$$\sum y_i \le s - A$$したがって、問題は、合計に上限がある非負の整数解を数えることに帰着します。 

微妙なエッジケースが現れるのは、$s < A$。 この場合、解決策は存在しません。 たとえば、次の場合$n=3, s=2, a=[1,1,1]$の場合、最小合計は 3 なので、答えは 0 になります。基本合計の実現可能性を無視した単純な実装では、依然として負の残存容量を持つ組み合わせを計算しようとするため、組み合わせ値が不正確になります。 

もう 1 つの特殊なケースは、すべてが$a_i = 0$、答えは古典的な星とバーの数になります。$\sum y_i \le s$、つまり$\binom{s+n}{n}$。 どのソリューションも、一般的なケースと縮退したケースの両方を正しく統合する必要があります。 

## アプローチ

 直接的なアプローチは、すべての可能な合計を反復処理するか、ゼロから組み合わせ論を使用して、各更新後に答えを再計算することです。 変数をシフトした後、問題は合計が最大の非負の整数解を数えることになります。$S' = s - \sum a_i$。 解の数は、$$\sum_{k=0}^{S'} \binom{k+n-1}{n-1} = \binom{S' + n}{n}$$これにより、各クエリは次の合計のみを維持するように削減されます。$a_i$。 更新ごとに 1 つの変更が加えられるため、$a_x$、現在までの合計を維持できます$A$で$O(1)$、再計算します$S' = s - A$。 

残りの課題は二項係数の計算です$\binom{N}{K}$モジュロ$10^9+7$すぐに最大で$N \le 4 \cdot 10^5$。 これは、事前計算された階乗と逆階乗で処理されます。 

したがって、各クエリは定数時間の算術更新と 1 つのモジュラー二項評価になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | 指数 | O(n) | 遅すぎる |
 | クエリごとに組み合わせを再計算する | O(nq) | お(1) | 遅すぎる |
 | 合計 + 事前計算された nCr を維持する | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、非負のスラック変数の有効な割り当てを数えるという問題に変換します。 中心的な考え方は、下限の分布ではなく、下限の合計のみが重要であるということです。 

## アルゴリズムのチュートリアル

 1. 初期合計を計算する$A = \sum a_i$。 これは、変数の合計に対する最小強制寄与を表すため、柔軟な割り当てが可能な「余地」がどれだけ残っているかが決まります。 
2. 階乗および逆階乗を最大で事前計算します。$n + s$。 これが必要なのは、すべての答えがこの範囲までの引数を持つ二項係数になり、クエリごとに階乗を再計算すると時間がかかりすぎるためです。 
3. クエリごとに、配列エントリを更新します。$a_x$合計金額を調整します$A$。 最終的なカウントは次のもののみに依存するため、構造全体を変更するのではなく、集計効果のみを維持します。$A$。 
4. 残容量を計算する$R = s - A$。 もし$R < 0$、最小構成でも制約に違反するため、すぐに 0 が出力されます。 
5. それ以外の場合は、解の数を次のように計算します。$\binom{R + n}{n}$。 これは、合計が制限されている非負の変数に適用される星形と棒の変換から得られます。 

### なぜ効果があるのか

 変数を下限値でシフトした後、すべての有効な設定は非負の整数の選択に正確に対応します。$y_i$合計は最大で誰の$R = s - \sum a_i$。 このようなベクトルの数は、個々のスラックではなく、利用可能なスラックの合計にのみ依存します。$a_i$。 各更新では、合計の 1 つの項を調整することによってのみこのスラックが変更されるため、再計算は単一のスカラー状態を維持することになります。 有界合成の二項恒等式により、最終的な式ですべての有効な代入が正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_fact(n):
    fact = [1] * (n + 1)
    invfact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    return fact, invfact

def ncr(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def main():
    n, s, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    A = sum(a)
    MAX = n + s
    fact, invfact = build_fact(MAX)
    
    for _ in range(q):
        x, val = map(int, input().split())
        x -= 1
        
        A -= a[x]
        a[x] = val
        A += a[x]
        
        R = s - A
        if R < 0:
            print(0)
        else:
            print(ncr(R + n, n, fact, invfact))

if __name__ == "__main__":
    main()
```実装は、完全な構造ではなく配列の合計を維持することを中心に展開されます。 各更新ではこの合計を一定時間で調整し、残りのスラックを直接更新します。$R$。 

階乗および逆階乗は、可能な最大のインデックスに対して 1 回事前計算され、各二項クエリが確実に実行されます。$O(1)$。 組み合わせ関数は、無効な範囲を保護して、負のアクセスまたは範囲外のアクセスを回避します。 

重要な点は正しく計算することです$R = s - A$。 更新ミスがあった場合$A$すべてのクエリは以前のすべての更新の現在の状態に依存するため、割り当ての前後で結果が正しくシフトされません。

 ## 特殊なケース

 下限値の合計を超える場合$s$、アルゴリズムは正しく 0 をすぐに出力します。$R = s - A < 0$。 たとえば、$n=3, s=2, a=[1,1,1]$、計算します$A=3$、与える$R=-1$、二項評価を試行しない場合、出力は 0 になります。 

いつすべて$a_i = 0$、私たちは得ます$R = s$、そして答えは次のようになります$\binom{s+n}{n}$。 標準の nCr 計算以外に特別なケースは必要ないため、アルゴリズムはこれを自然に処理します。 

更新により 1 つのポジションが増減する場合のみ、$A$変化します。 このアルゴリズムは、新しいコントリビューションを追加する前に古いコントリビューションを正しく削除し、複数のクエリにわたる累積ドリフトが発生しないようにします。
