 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられます。 各ポイントはノードであり、Klee は任意のポイントのペア間を直接移動できます。 移動コストは、2 つのエンドポイントがどの象限にあるかによってのみ異なります。 

飛行機は軸によって 4 つの領域に分割されており、各領域には独自の速度制限があります。 移動の両方の終点が同じ象限内にある場合、移動速度はその象限の値によって決定されるため、2 点間の移動時間はユークリッド距離をその象限の速度で割った値に比例します。 エンドポイントが異なる象限にある場合、移動は遅くなり、代わりに固定のグローバル速度制限が使用されます。 

タスクは、任意の中間点のシーケンスを使用して、開始点 s から目標点 t までの移動にかかる最小時間を見つけることです。 

これを n 個の頂点を持つ完全な重み付きグラフとして解釈する必要があります。 すべての頂点のペアにはエッジがありますが、重みはそれらの象限の関係によって異なります。 目標は、この密なグラフ上の最短経路問題です。 

この制約により、n は最大 3000 まで許可されます。これにより、O(n^3) のすべてのペアの最短経路が直ちに排除され、単純な O(n^2 log n) ダイクストラ境界線も作成されますが、慎重に実装すればまだ実現可能です。 ただし、本当の課題は、エッジの重みが均一ではないことです。 それらはジオメトリと象限ルールに依存するため、緩和を慎重に構成する必要があります。 

s から t への直接エッジが、たとえ速いように見えても最適ではない場合、微妙なエッジ ケースが発生します。 たとえば、両方のポイントが同じ象限内にあるものの、速度制約が異なるためにより短いパスを作成する近くのポイントが別の象限に存在する場合、貪欲な直接移動は失敗します。 

もう一つの問題は、時間の公式を誤解していることです。 2 つのポイントが同じ象限内にある場合、速度 v1..v4 がセグメントに適用されます。 それ以外の場合は、v0 が適用されます。 単純な間違いは、エッジごとではなくエンドポイントごとに異なる速度を想定することです。 

## アプローチ

 ブルート フォース アプローチは、完全なグラフに対する直接的な最短パスの計算です。 すべての点のペア間のユークリッド距離を計算し、象限ルールに従ってエッジの重みを割り当て、s からダイクストラを実行します。 すべてのエッジが使用可能であり、重みが負ではないため、これは正しいです。 

ただし、すべてのエッジを構築して反復すると、明示的に O(n^2) 個のエッジが得られます。 標準的なダイクストラ実装のコストは O(n^2 log n) となり、これは境界線ですが、n = 3000 の場合は許容範囲内です。本当の問題は、距離と象限チェックを繰り返し再計算するため、実際には処理速度が遅くなることです。 

重要な観察は、グラフが完全で緻密であるため、ヒープベースのダイクストラを完全に回避する必要があるということです。 代わりに、密なグラフに対して古典的な最適化を使用できます。最適な距離の配列を維持し、O(n) 内の最小の未訪問ノードを繰り返し選択することで、合計の複雑さは O(n^2) になります。 エッジ緩和はノードごとに依然として O(n) であるため、これはクリーンで効率的になります。 

2 番目の構造的観察は、グラフは幾何学的ですが、n が十分に小さく、いずれにせよすべてのノードが近傍候補であるため、KD ツリーのような空間データ構造は必要ないということです。 

したがって、解決策は、すべてのペアごとの距離を一度計算し、密なダイクストラを実行することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ヒープを使用したブルート フォース ディクストラ | O(n^2 log n) | O(n^2) | 受け入れられたが重い |
 | デンス・ディクストラ | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

1. まず、各点を座標の符号を使用して 4 つの象限のいずれかに分類します。 これが必要なのは、エッジの重みが 2 つのエンドポイントが同じ象限を共有するかどうかに完全に依存するためです。 
2. すべての点のペア間のユークリッド距離を事前計算します。 これにより、緩和中にジオメトリの再計算が回避され、内部ループが純粋に算術的に維持されます。 
3. 点 i と j のすべてのペアについて、象限 k を共有する場合は距離を v_k で割った値として移動時間を定義し、それ以外の場合は距離を v0 で割った値として移動時間を定義します。 これにより、暗黙的な完全な重み付きグラフが構築されます。 
4. 距離配列を無限大で初期化し、開始点の距離をゼロに設定します。 これは、s からすべてのノードまでの既知の最短時間を表します。 
5. 訪問済みの配列を維持して、最短距離が確定したノードをマークします。 
6. n 回繰り返します。現在の距離が最小の未訪問のノード u を選択します。 すべてのエッジの重みが負ではないため、このステップは有効であり、最小の暫定ノードが確定されることが保証されます。 
7. u を訪問済みとしてマークし、u を通過することで v までの既知の距離が改善されるかどうかをチェックして、他のすべてのノード v を緩和します。より短いパスが見つかった場合は、 distance[v] を更新します。 
8. すべてのノードを処理した後、t までの距離が答えになります。 

### なぜ効果があるのか

 このアルゴリズムは、完全なグラフに適用される標準的なダイクストラ法ですが、正確かどうかは、すべての緩和で時間の経過とともに変化しない有効なエッジの重みを使用するという事実によって決まります。 ノードが現在の最小未訪問ノードとして選択されると、すべての代替パスは同等以上の暫定距離を持つノードを通過する必要があり、すべてのエッジの重みが負ではないため、将来のパスでそのノードを改善することはできません。 これにより、各ノードが最適な最短時間で 1 回だけファイナライズされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def quadrant(x, y):
    if x >= 1 and y >= 1:
        return 0
    if x <= -1 and y >= 1:
        return 1
    if x <= -1 and y <= -1:
        return 2
    return 3

def main():
    n = int(input())
    v1, v2, v3, v4, v0 = map(int, input().split())
    s, t = map(int, input().split())
    s -= 1
    t -= 1

    pts = [tuple(map(int, input().split())) for _ in range(n)]
    quad = [quadrant(x, y) for x, y in pts]

    dist = [[0.0] * n for _ in range(n)]
    for i in range(n):
        x1, y1 = pts[i]
        for j in range(n):
            x2, y2 = pts[j]
            dx = x1 - x2
            dy = y1 - y2
            dist[i][j] = math.hypot(dx, dy)

    speed = [v1, v2, v3, v4]

    INF = 1e100
    d = [INF] * n
    used = [False] * n
    d[s] = 0.0

    for _ in range(n):
        u = -1
        best = INF
        for i in range(n):
            if not used[i] and d[i] < best:
                best = d[i]
                u = i

        used[u] = True

        for v in range(n):
            if used[v]:
                continue
            if quad[u] == quad[v]:
                w = dist[u][v] / speed[quad[u]]
            else:
                w = dist[u][v] / v0
            if d[u] + w < d[v]:
                d[v] = d[u] + w

    print(f"{d[t]:.10f}")

if __name__ == "__main__":
    main()
```コードはまず各ポイントに象限 ID を割り当て、エッジ分類が O(1) になるようにします。 次に、すべてのペアごとのユークリッド距離を事前計算します。これは、ソリューションにおける唯一の幾何学的作業です。 ダイクストラ ループは密な O(n^2) スタイルで実装され、優先キューの代わりに線形スキャンによって次のノードを選択します。 

緩和ステップでは、ローカル速度またはグローバル速度 v0 のいずれかを適用して、象限内の動きと象限間の動きを注意深く区別します。 この違いが、エッジの重みが異なる唯一の理由です。 それ以外はすべて標準の最短パス ロジックです。 

距離と速度によって非整数の結果が生成される可能性があるため、浮動小数点演算が必要です。 1e-6 の誤差許容範囲内では、倍精度を使用すれば十分です。

 ## 特殊なケース

 重要なエッジケースは、s が t と等しい場合です。 このアルゴリズムは、 distance[s] = 0 を正しく初期化し、決して変更しないため、ジオメトリや速度に関係なく、出力はすぐに 0 になります。 

もう 1 つのケースは、すべての点が同じ象限内にある場合です。 次に、すべてのエッジで同じ速度乗数が使用され、解は完全なグラフにわたる標準ユークリッド最短経路に縮退します。 この速度でもすべてのエッジを均一に処理するため、アルゴリズムは引き続き機能します。 

3 番目のケースは、ポイントが 4 つの象限すべてに分散している場合です。 次に、アルゴリズムは 2 つのクラスのエッジを混合しますが、ダイクストラは非負性を超える計量構造を仮定しないため、正確さは影響を受けません。
