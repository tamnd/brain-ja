 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$小さな迷路のように動作するグリッド。 各セルは空きスペース、障害物、または 2 人のプレーヤー用にラベル付けされた 2 つの特別な開始位置のいずれかを含みます。 両方のプレイヤーが同時に移動し、各移動は方向を選択し、その方向に 1 つのセルを進めようとすることで構成されます。 移動によってプレイヤーがグリッドの外や障害物に入る場合、そのプレイヤーはそのステップの間その場にとどまり、他のプレイヤーは依然として選択された方向に従います。 

目標は、両方のプレイヤーが同時に同じセルを占有するまでに必要な同時移動の最小数を決定することです。 それらを一致させる一連の動きがない場合、答えは存在しないということになります。 

グリッド サイズは最大 50 x 50 であり、これはすでに 2 人のプレーヤーのポジションの完全な状態スペースが最大 50 x 50 であることを示唆しています。$2500 \times 2500 = 6.25 \times 10^6$。 これは十分に小さいので、位置のペアに対する幅優先検索で探索する余裕があります。 

問題の微妙な部分は、ブロック動作と同期した移動ルールです。 たとえ両方のプレイヤーが各ステップで同じ方向を選択したとしても、障害物がそれぞれに異なる影響を与える可能性があるため、問題を独立した最短経路の計算に分解することはできないことを意味します。 

いくつかの特殊なケースが重要です。 両方のプレイヤーが同じセルからスタートした場合、答えはすぐにゼロになります。 いずれかの構成がトラップされたり、切断された領域で循環したりするために、すべての到達可能な構成が構成を分離したままにする場合は、解決策がないことを正しく報告する必要があります。 もう 1 つの故障モードは、マンハッタン距離または独立した最短経路を仮定することで発生します。これは、障害物と結合された移動規則を完全に無視します。 

## アプローチ

 単純な試みでは、考えられるすべての移動シーケンスをシミュレートしようとします。 A と B の位置によって定義される特定の状態から、各ステップは 4 つの可能な方向に分岐します。 すべてのシーケンスを長さまで探索すると$k$、状態の数は次のように増加します$4^k$、小さなものでも不可能になります$k$。 問題は正確さではありません。この列挙により、会議が存在する場合には最終的に会議が検出されますが、指数関数的な爆発により使用できなくなるからです。 

重要な観察は、このシステムが実際には、ノードが順序付けられたグリッド セルのペアであるグラフ上の最短経路問題であるということです。 それぞれの状態は、$(x_a, y_a, x_b, y_b)$。 移動は、4 つの方向から 1 つを選択し、両方のプレイヤーに移動ルールを決定的に適用することに対応します。 各移動のコストは等しいため、自然なツールはこの状態グラフに対する BFS です。 

可能な状態の数は次のように制限されます。$n^4$、ただし実際にのみ$n^2 \cdot n^2$州が存在し、その数は最悪でも約 600 万です。 各状態には最大 4 つの発信遷移があります。 これにより、制限時間内で BFS を実行できるようになります。 

また、構成の再訪問を防ぐために、訪問した状態にマークを付けます。 両方のプレーヤーが同じセルを共有する状態に初めて到達したとき、BFS 層の順序付けにより最短のシーケンスが見つかりました。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(4^k)$|$O(k)$| 遅すぎる |
 | 結合状態空間上の BFS |$O(n^4)$最悪の場合の遷移 |$O(n^4)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各構成を 2 人のプレーヤーの座標のペアとしてモデル化し、初期構成から BFS を実行します。 

1. グリッド内の 2 人のプレーヤーの開始位置を見つけます。 これにより初期状態が得られます$(x_a, y_a, x_b, y_b)$。 それらがすでに等しい場合は、移動する必要がないため、すぐにゼロを返します。 
2. キューを初期状態で初期化し、訪問済みとしてマークします。 BFS キューには、両方の位置が開始点からの距離とともに保存されます。 
3. キューから状態を繰り返しポップします。 2 つの位置が同一の場合は、保存されている距離を返します。 BFS はステップの昇順で探索するため、これは可能な限り早い会議時間です。 
4. 4 つの方向のそれぞれについて、次の状態を計算します。 各プレイヤーは、その方向に 1 歩ずつ移動してみます。 結果の位置がグリッドの外側にある場合、または障害セルである場合、そのプレイヤーは現在の位置に残ります。 このルールは各プレーヤーに独立して適用されますが、同じ方向を使用します。 
5. 結果として得られる結合状態がこれまでに訪問されていない場合は、その状態に訪問済みのマークを付け、距離を 1 つ増分してキューにプッシュします。 
6. 会議状態にならずにキューが空になった場合は、「解決策なし」を返します。 

すべてのエッジのコストが等しいため、正確性は、最初に状態に到達するのが最短の一連の移動であることを保証する BFS に依存します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [list(input().strip()) for _ in range(n)]
    
    ax = ay = bx = by = -1
    
    for i in range(n):
        for j in range(n):
            if grid[i][j] == 'a':
                ax, ay = i, j
            elif grid[i][j] == 'b':
                bx, by = i, j
    
    if ax == bx and ay == by:
        print(0)
        return
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    visited = set()
    q = deque()
    
    start = (ax, ay, bx, by)
    q.append((ax, ay, bx, by, 0))
    visited.add(start)
    
    def move(x, y, dx, dy):
        nx, ny = x + dx, y + dy
        if nx < 0 or nx >= n or ny < 0 or ny >= n:
            return x, y
        if grid[nx][ny] == '*':
            return x, y
        return nx, ny
    
    while q:
        ax, ay, bx, by, d = q.popleft()
        
        if ax == bx and ay == by:
            print(d)
            return
        
        for dx, dy in dirs:
            nax, nay = move(ax, ay, dx, dy)
            nbx, nby = move(bx, by, dx, dy)
            state = (nax, nay, nbx, nby)
            if state not in visited:
                visited.add(state)
                q.append((nax, nay, nbx, nby, d + 1))
    
    print("no solution")

if __name__ == "__main__":
    solve()
```BFS 状態は明示的に 4 次元であり、キューには再計算を避けるために位置とともに距離が格納されます。 ヘルパー関数は移動ルールを明確に適用します。ステップを試みてから境界と障害物をチェックし、それ以外の場合はプレーヤーを静止させます。 

よくある実装上の間違いは、両方のプレイヤーが動きごとに同じ方向を使用することを忘れていることです。 もう 1 つは、動きを同時のものとして扱いますが、一方のプレイヤーのブロックされた動きが他方のプレイヤーに影響を与えることを許可するものですが、これは正しくありません。 各プレーヤーのトランジションは、方向の選択を共有することを除いて独立しています。 

この制約サイズでは、訪問済みのセットを使用するだけで十分です。 4D ブール配列の方が高速になる可能性がありますが、制限を考慮すると必須ではありません。 

## 実用的な例

 ### 例 1

 オープンスペースで両プレイヤーが既に隣接している単純なグリッドを考えてみましょう。 

| ステップ | 状態 (A、B) | アクション | 距離 |
 | --- | --- | --- | --- |
 | 0 | (0,0)、(0,1) | 開始 | 0 |
 | 1 | (0,0)、(0,0) | 右に移動 | 1 |

 BFS は最初に正しい手を探り、すぐに両方のポジションをマージします。 これは、障害物が干渉しない場合に、アルゴリズムがどのように自然に最短の衝突経路を見つけるかを示しています。 

### 例 2

 障害物によって迂回を強いられるグリッドを考えてみましょう。 

| ステップ | 状態 (A、B) | アクション | 距離 |
 | --- | --- | --- | --- |
 | 0 | (0,0)、(2,2) | 開始 | 0 |
 | 1 | (1,0)、(2,1) | 下/右 | 1 |
 | 2 | (1,1)、(2,1) | 右/上ブロックミックス | 2 |
 | 3 | (1,1)、(1,1) | 決勝大会 | 3 |

 このトレースは、ブロックされた移動によって非対称な進行がどのように引き起こされるかを示していますが、BFS は依然として最短の同期を保証します。

 ## 特殊なケース

 主なエッジケースは、両プレーヤーが同じポジションからスタートする場合です。 アルゴリズムは BFS が開始される前にこれを処理し、すぐにゼロを返します。 このチェックがなければ、BFS は最終的にゼロを返しますが、それは初期状態を不必要に挿入および拡張した後でのみです。 

もう 1 つのケースは、一方のプレイヤーが障害物に閉じ込められている一方で、もう一方のプレイヤーは自由に移動できる場合です。 たとえば、A が次のように囲まれている場合、`*`セルの位置が変わることはありません。 BFS はこれを正しく反映します。これは、A のすべての遷移が固定を維持し、B がその到達可能な領域を探索するためです。 B が A のセルに到達できない場合、キューは最終的に空になり、解は正しく出力されません。 

3 番目のケースは、前後の移動を強制する廊下など、移動の振動が存在する場合です。 訪問済みセットにより、同じジョイント構成の無限の再訪問が防止され、個々のプレーヤーのパスが循環する場合でも確実に終了します。
