 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、指定された整数で割り切れる合計を持つ連続した部分配列がいくつあるかを数えるように求められます。$k$。 ここでの部分配列とは、開始位置と終了位置を選択し、その間にあるすべてのものを隙間なく取得し、それらの要素の合計を計算することを意味します。 これらの合計が次の倍数になるかどうかを知りたいのです。$k$、ゼロを含む。 

配列の長さは最大で$10^5$、各値は次のように大きくできます。$10^9$。 サブ配列自体の数は約$O(n^2)$、これは大きすぎます。 単一の二次ループでもすでに存在しています$10^{10}$最悪の場合、1 秒の制限内で通過できない操作が発生します。 

微妙な点は、値がゼロになる可能性があるため、単一のゼロで構成される部分配列は次の場合にカウントする必要があることです。$k$ゼロを除算します。 別の例外的なケースが発生する場合$k = 1$ここで、すべての整数は 1 で割り切れるため、すべての部分配列が有効です。つまり、答えは次のようになります。$n(n+1)/2$。 適切なソリューションでは、特別なケースを使用せずにこれを自然に処理する必要があります。 

単純な接頭辞の合計チェックも安全に見えるかもしれませんが、固定幅の整数を使用する言語では、接頭辞の合計が次の値に達する可能性があるため、オーバーフローの懸念により失敗します。$10^{14}$。 Python ではこれは問題になりませんが、他のコンテキストでは概念的に重要になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのペアについて$(l, r)$、部分配列の合計を計算します。$a_l \dots a_r$で割り切れるかどうかを確認します$k$。 プレフィックスの合計を事前に計算したとしても、インデックスのすべてのペアを反復処理することになるため、$O(n^2)$小切手。 

これが失敗する理由は、サブ配列の数だけでなく、各ペアのコストも高くなります。$O(1)$プレフィックス合計を使用するか、$O(n)$それらなしで。 いずれにせよ、二次スケールは避けられません。 

重要な観察は、部分配列の合計が接頭辞の合計で表現されると単純になるということです。 させて$S_i = a_1 + \dots + a_i$。 次に、部分配列の合計$[l, r]$は$S_r - S_{l-1}$。 これを次のように割り切れるようにしたいと思います。$k$、 意味：$$S_r \equiv S_{l-1} \pmod{k}$$したがって、問題はもはや部分配列に関するものではなく、剰余剰余が等しいプレフィックスの合計のペアをカウントすることです。$k$。 有効な各部分配列は、プレフィックスの合計が同じモジュロ クラスを持つインデックスのペアに正確に対応します。 

これにより、問題は、各剰余値について、グループ内の組み合わせを数える問題に変換されます。$r$、表示される場合$c_r$プレフィックス合計の中で 1 倍に寄与します$c_r(c_r - 1)/2$有効な部分配列。

 ## アルゴリズムのチュートリアル

 1. 配列を反復処理しながら、合計の剰余を維持しながらプレフィックスの合計を計算します。$k$全額の代わりに。 これにより、整数の大きな増加が回避され、関連する同値クラスのみが保持されます。 
2. 各剰余がこれまでに何回出現したかを記録する頻度マップを維持します。 要素が取得される前の空のプレフィックスを表す、剰余 0 を 1 回出現させて初期化します。 
3. 各要素について、実行中のプレフィックスの合計を更新し、その剰余を計算します。$k$。 
4. 余りを見るたびに$r$、同じ剰余を持つ以前のすべてのプレフィックスの合計が、現在の位置で終わる有効な部分配列を形成できることがわかります。 そこで、現在の周波数を加算します。$r$答えに。 
5. 剰余の周波数をインクリメントします$r$。 

重要な決定はステップ 4 です。サブ配列を明示的に形成しようとする代わりに、各プレフィックスの合計を「状態」として解釈し、状態の繰り返しごとに現在のインデックスで終わる新しい有効なサブ配列を作成します。 

### なぜ効果があるのか

 正しさは、どの位置でも不変条件から得られます。$i$、頻度マップには、インデックス間の各剰余がプレフィックス合計の正確な数を格納します。$0 \dots i$。 サブアレイ$[l, r]$和が以下で割り切れる$k$プレフィックスが残っている場合に限り、$r$そして$l-1$等しいです。 したがって、剰余に遭遇するたびに、$r$つまり、同じ剰余が以前に出現したものを、現在のインデックスで終わる有効な部分配列の開始境界として事実上選択していることになります。 異なる剰余は割り算条件を満たすことができないため、有効なペアが欠落することはなく、無効なペアもカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
arr = list(map(int, input().split()))

freq = {0: 1}
prefix = 0
ans = 0

for x in arr:
    prefix = (prefix + x) % k
    ans += freq.get(prefix, 0)
    freq[prefix] = freq.get(prefix, 0) + 1

print(ans)
```実装はプレフィックス合計モジュロを追跡します。$k$これにより、オーバーフローと不必要な合計計算の両方が回避されます。 辞書`freq`各剰余のカウントを保存します。 最初のエントリー`{0: 1}`インデックス 1 から始まるサブ配列を考慮するため、これは必須であり、プレフィックス自体は既に次の数で割り切れます。$k$。 

よくある落とし穴は、回答に追加する前に頻度を更新することです。 これを行うと、有効なサブ配列に対応しない現在のプレフィックスをそれ自体で誤ってカウントすることになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    freq = {0: 1}
    prefix = 0
    ans = 0

    for x in arr:
        prefix = (prefix + x) % k
        ans += freq.get(prefix, 0)
        freq[prefix] = freq.get(prefix, 0) + 1

    return str(ans)

# provided sample
assert run("6 3\n0 1 2 4 7 7\n") == "7"

# single element zero
assert run("1 3\n0\n") == "1"

# all ones, k = 2
assert run("5 2\n1 1 1 1 1\n") == "6"

# k = 1, all subarrays valid
assert run("4 1\n1 2 3 4\n") == "10"

# alternating zeros
assert run("5 3\n0 0 0 0 0\n") == "15"

 ## 特殊なケース

 単一要素のような最小限のケースでは、最初のプレフィックスの残りが正しく処理されるかどうかをテストします。 入力あり`1 3`と配列`[0]`、プレフィックスの残りはすぐにゼロになり、周波数マップはで始まるため、`{0:1}`、有効な部分配列を 1 つだけ数えます。 アルゴリズムはこれを単一のステップとして処理します。`prefix = 0`、追加します`freq[0] = 1`、1を返します。 

ケース付き`k = 1`すべてのプレフィックスには残りが 0 があるため、これはさらに極端です。 のために`n = 4`そして`[1,2,3,4]`、各ステップで剰余 0 の頻度が増加し、すべてのサブ配列の合計が 10 になります。頻度メカニズムは、何も変更せずに自然に三角カウントを累積します。 

すべてゼロの配列も同様に動作しますが、`k`。 すべてのプレフィックスの合計は同一のモジュロであるため、`k`、インデックスのすべてのペアが有効な部分配列を形成します。 周波数マップは、増加する組み合わせを繰り返しカウントし、$n(n+1)/2$、予想される組み合わせ構造と一致します。
