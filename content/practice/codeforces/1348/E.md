 ## 解決策
 ## 問題の理解

 いくつかの低木が与えられ、それぞれに赤と青の 2 つの独立した果実の山が含まれています。 これらのソースから、できるだけ多くのバスケットを形成したいと考えています。すべてのバスケットには正確な内容が含まれている必要があります。$k$ベリー。 

バスケットにベリーを混合できるのは、構造上の制限が 1 つある場合のみです。つまり、すべてのベリーが 1 つの低木から採れるか、すべてのベリーが同じ色を共有するかのいずれかです。 これは、すべての有効なバスケットが、低木識別と色の識別という 2 つの軸に沿って同時に制約され、バスケットを埋めるときにグループ化ルールとしてどちらの軸も使用できることを意味します。 

重要な問題は、ベリーが事前にバスケットに割り当てられていないことです。 低木からの寄与を多くのバスケットに分割することは許可されており、「同じ色」ルールが尊重される限り、異なる低木からの寄与を組み合わせることもできます。 

目標は、完全に満たされたバスケットの数を最大化することです。 

制約$n, k \le 500$十分に小さいため、二次遷移または三次遷移さえも許容されます。 ただし、ベリーは重要です$a_i, b_i$まで行く$10^9$これにより、ベリーごとの操作をシミュレートしようとするアプローチは即座に除外されます。 ソリューションは、低木ごとの集計量にのみ作用する必要があります。 

素朴な解釈では、低木ごと、または色ごとに独立して、できるだけ多くのいっぱいになったバスケットを貪欲に取ることを提案するかもしれません。 1 つの低木における 1 つの決定が、後で全体的な残り物をどれだけ効率的に組み合わせることができるかに影響を与えるため、これは失敗します。 

部分的な使用が重要な場合には、微妙な失敗例が発生します。 

考慮する：```
n = 2, k = 4
(5, 2), (2, 1)
```欲張って低木ごとにかごいっぱいを取ると、最初の低木から赤い果実を 4 つ消費し、最適に組み合わせることができない断片的な残り物が残る可能性があります。 正しい解決策は、残りの赤い果実を低木にまたがって再分配してバスケットを完成させるため、局所的な貪欲な決定では不十分です。 

正しいアプローチでは、部分グループが将来の完了にどのように寄与するかを追跡する必要があります。 

## アプローチ

 直接的な強引なアイデアは、各低木からベリーをバスケットに分割するあらゆる可能な方法を処理し、低木や色の残りを組み合わせることです。 これはすぐに組み合わせ割り当ての問題に変わります。各低木が寄与します。$a_i + b_i$アイテムですが、各アイテムをサイズのグループに割り当てる必要があります$k$私たちが低木の中に留まるか、色の中に留まるかによって決まる制約の下で。 

単純化して「各低木が共有プールに寄与するベリーの数」という観点から考えたとしても、剰余として残されるベリーの数を考慮する必要があります。$k$現地での任務の後。 低木ごとに剰余を割り当てるあらゆる方法を試すと、おおよその結果が得られます。$O(k^n)$たとえ誰にとっても実現不可能な可能性$n = 30$。 

重要な構造的洞察は、すべてのバスケットが「水平」（同じ低木）または「垂直」（同じ色）のいずれかであるということです。 水平バスケットは低木ごとにローカルで独立していますが、垂直バスケットは色の合計を通じてすべての低木を結合します。 これは、決定を 2 つの層に分けることを示唆しています。最初に低木ごとにローカルで消費されるベリーの数と、グローバルな色ベースのバスケットを形成するために残されるベリーの数です。 

問題は、それぞれの低木について、現地で何個の果実を収穫するかを決めることになります。$k$、色ごとにプールされる残りの数。 低木ごとに意味のある唯一の状態は剰余モジュロです$k$、フルブロックのサイズなので$k$常にすぐにバスケットを作ります。 

これにより、問題は、現在の赤と青の剰余の合計をモジュロで追跡する、低木上の動的プログラミングに帰着します。$k$まだカラーバスケットに詰められていないもの。 各低木は、局所的に寄与するフルバスケットの数と残留状態をどのように変化させるかに基づいて遷移に寄与します。 

DP 状態空間は次のとおりです。$O(n \cdot k^2)$、各残基は次のように制限されているため、$k$。 これは十分小さいです$n, k \le 500$。

 ## アルゴリズムのチュートリアル

 低木を 1 つずつ処理し、残存する可能性のある赤と青の果実のモジュロを上回る DP を維持します。$k$まだフルカラーのバスケットに変換されていないもの。 

1. DP テーブルを定義します。`dp[r][b]`低木のいくつかの接頭辞を処理した後、これまでに形成された完全なバスケットの最大数を表します。$r$赤と$b$残り物としての青い果実は、まだ色ベースのバスケットに使用できます。 

残り物だけが低木を越えて相互作用できるため、この状態は重要です。 
2.初期化`dp[0][0] = 0`、何かを加工する前にはベリーもバスケットもありません。 
3. 値を持つ各低木について$(a_i, b_i)$、新しい DP テーブルを計算します。 

まず、この低木の中にだけで、いっぱいになったバスケットが何個形成できるかを考えます。 私たちが取るなら$x$赤と$y$地元のブルーベリーを確保しなければなりません$x + y$サイズの完全なグループに分割されます$k$。 できるだけ多くのローカルバスケットを形成した後の残りが残りの候補になります。 
4. 既存のすべての DP 状態について$(r, b)$、私たちは現在の低木からの果実を使用するあらゆる方法を試みます。 任意の分割を選択する代わりに、低木の中にいっぱいのバスケットを形成した後にベリーがいくつ残るかだけを気にします。 これにより、考えられる赤色の残りを反復処理する移行が減少します。$r'$そして青い残り$b'$この低木によって生成される制約は次のとおりです。$r' \le a_i$、$b' \le b_i$、 そして$(r' + b') \bmod k$ローカルで作成されたフルバスケットの数を決定します。 
5. トランジションごとに、以下を組み合わせます。 

前回の残り物$(r, b)$、

 それに加えて、この低木から新たに残ったもの、

 そして、以下を使用して、赤と青を別々にできるだけ多くの完全なカラー バスケットに変換します。$$\left\lfloor \frac{r + r'}{k} \right\rfloor + \left\lfloor \frac{b + b'}{k} \right\rfloor$$残りの剰余は次の DP 状態として保存されます。 

色ベースのバスケットは低木の起源ではなく色ごとの合計のみに依存するため、この手順は正しいです。 
6. すべての低木を処理した後、すべての DP 状態にわたる最大値を取得します。 

### なぜ効果があるのか

 すべてのステップで、DP はすべての履歴決定を残りのカウントのモジュロのみに圧縮します。$k$。 どのグループでも、$k$同じ色のベリーはすぐにバスケットに固定され、将来の決定に影響を与えることはありません。 混合は色または低木内でのみ許可されているため、完成したバスケットがどのように形成されたかによって、将来の操作は決まりません。 これにより、すべての関連情報が残りの状態だけでキャプチャされることが保証され、DP が十分かつ無損失になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    shrubs = [tuple(map(int, input().split())) for _ in range(n)]

    dp = [[-1] * k for _ in range(k)]
    dp[0][0] = 0

    for a, b in shrubs:
        ndp = [[-1] * k for _ in range(k)]

        for r in range(k):
            for bl in range(k):
                if dp[r][bl] < 0:
                    continue
                base = dp[r][bl]

                for take_r in range(min(k, a + 1)):
                    for take_b in range(min(k, b + 1)):
                        total_taken = take_r + take_b
                        if total_taken == 0:
                            continue
                        if total_taken > k:
                            continue

                        # local baskets formed in this shrub
                        local = total_taken // k

                        nr = (r + take_r) % k
                        nb = (bl + take_b) % k

                        # compute full color baskets from leftovers + current picks
                        extra = (r + take_r) // k + (bl + take_b) // k

                        ndp[nr][nb] = max(ndp[nr][nb], base + local + extra)

        dp = ndp

    ans = 0
    for r in range(k):
        for b in range(k):
            ans = max(ans, dp[r][b])

    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、低木を処理する前に、残り物がないことを表すように初期化されます。 それぞれの低木は、果実を最大まで取り出す実行可能なすべての方法を試して、変化を生み出します。$k$、それを超えるものは何もないので、$k$すぐにバスケットがいっぱいになりますが、残りの状態は意味のある方法で変更されません。 

この移行では、コントリビューションをローカルの低木バスケットとグローバルなカラー補完に慎重に分割します。 モジュロ更新では、各カラー ストリームの未解決部分のみが保存されます。 

最終的な答えは、残りのすべての状態にわたって達成可能な最良の構成です。

 ## 特殊なケース

 エッジケースの 1 つは、低木の最適な貢献が、ローカル バスケットを最大化することではなく、将来の低木と一致する残りを保存することである場合に発生します。 たとえば、$k$低木の中にベリーが貪欲に存在すると、後でより優れたグローバルな色ベースのバスケットを形成する可能性が妨げられる可能性があります。 DP はこれらの残りを明示的に保存し、後の低木がそれらを完全なグループに完成させることができます。 

別の特殊なケースは、1 つの色が全体的に優勢であるにもかかわらず、低木全体で断片化されている場合に発生します。 素朴で貪欲な低木ごとのアプローチでは小さな破片が破棄されてしまいますが、DP は完全なバスケットを形成するのに十分な蓄積が起こるまでそれらを状態に保ちます。
