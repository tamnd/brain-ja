 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられ、そのすべての文字を正確に k 個の空でないグループに分割することができます。 各グループ内では文字を任意に並べ替えることができるため、各グループは事実上、後で文字列に並べ替えられる文字の複数セットにすぎません。 

すべての k 個の文字列が形成されたら、それらを辞書編集順に調べて、最大のものを取得します。 私たちの目標は、この最悪の文字列が辞書編集用語で可能な限り小さくなるように文字を分散することです。 

重要な自由度は、シーケンスを分割しているのではなく、マルチセットを分散していることです。 これにより、位置的な制約がなくなり、問題は完全に頻度と順序に関するものになります。 

制約により、テスト ケースごとに線形または線形に近い解決策が強制されます。 テスト全体の合計 n は最大 10^5 であるため、テスト ケースごとに O(n log n) または全体で O(n) 程度の任意の解が許容されます。 分布や指数関数的な割り当ての繰り返しシミュレーションを伴うものは、直ちに不可能になります。 

k が n と等しい場合、微妙なエッジ ケースが発生します。 この場合、すべての文字列には 1 文字だけが含まれるため、答えは単純に文字列内の最大文字になります。 もう 1 つのエッジ ケースは、k が 1 に等しい場合です。この場合、すべての文字が 1 つのグループに入る必要があるため、答えはソートされた文字列そのものになります。 

文字列に支配的な最小文字がある場合、さらに興味深い特殊なケースが発生します。 たとえば、ほとんどの文字が 'a' の場合、それらを均等に分散するか不均等に分散するかによって、どの文字列が辞書編集的に最大になるかが変わり、順序付けの制約を考慮しない場合、単純な貪欲なグループ化は失敗する可能性があります。 

## アプローチ

 ブルートフォース解釈では、n 文字の k 個の空でないグループへの可能なすべての分布が試行されます。 内部の順列を無視したとしても、これは各文字を k バケットの 1 つに割り当て、k^n 個の可能性を与えることを意味します。 これは限界をはるかに超えています。 

重要な点は、辞書編集上の順序は、文字列が異なる最も早い位置によって決定されるということです。 最大文字列を最小限に抑えるには、すべてのグループの最初の文字をできるだけ小さくし、最初の異なる位置がどの程度「大きく」なるかを制御する必要があります。 

文字列をソートすると、最適解の構造が明らかになります。 ソートが完了すると、ソートされたシーケンスを k 個の部分に分割する方法を事実上決定することになります。これは、最大値を悪化させることなく、グループがソートされた文字列の連続セグメントに対応する最適な配置に変換できるためです。 

ここからは2つのケースが現れます。 最小の k 個の文字がすべて同一ではない場合、答えはソート順で単純に k 番目の文字になります。これは、最小の k 個の文字を k 個の文字列の最初の文字として分散でき、その他は末尾の位置にのみ影響するためです。 最初の k 文字が同一の場合、それらを均等に分散することを強制され、答えはその文字と最適に分散された残りのサフィックスになります。つまり、残りのすべての文字を任意の順序で追加することになります。 

より深い洞察は、各グループの最初の文字を修正すると、必要より早く辞書編集的に大きな接頭辞を導入しない限り、残りの分布は最大値に影響を与えなくなるということです。 これにより、ソート後に明確な決定論的な構築が得られます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(k^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 文字列を降順でない順に並べ替えます。 辞書編集的最小化では常に小さい文字が前に優先され、ソートされた順序で最適な配置を推論できるため、ソートは便利です。 
2. k が 1 の場合、ソートされた文字列全体を返します。 ディストリビューションの選択肢がないため、単一の文字列が固定されます。 
3. ソートされた文字列 (0 からインデックス付けされた k-1) 内の k 番目の文字を確認します。 この文字が最初の文字よりも厳密に大きい場合は、最初の k 個の位置の中に厳密に大きい文字が少なくとも 1 つ存在することがわかります。 
4. その場合、k 番目の文字を答えとして返します。 その理由は、最初の k 個の最小文字を k 個の文字列の開始文字として割り当てることができ、その中で辞書編集上最大の文字列が k 番目に小さい文字から始まるということです。 
5. 最初の k 文字がすべて同じである場合、それらの間で異なる配分を行って最大値を減らすことはできません。 最初の k-1 文字列のそれぞれに 1 文字を配置し、残りを k 番目の文字列に配置します。これが唯一の非自明なものになります。 
6. この 2 番目のケースでは、答えはソートされた文字列のインデックス k-1 から始まるサフィックスです。 最初の k-1 文字はすべて同一であるため、接尾辞の順序が辞書編集上の最大値を支配します。 

### なぜ効果があるのか

 このアルゴリズムは、辞書編集上の比較が最初の異なる位置で決定されるという事実に基づいています。 並べ替える際には、以前の文字が後の文字よりも劣ることがないことを確認します。 最大文字列に影響を与える唯一の方法は、グループの最初の要素として表示される最小の文字を使用することです。 最初の k 文字が固定されると、他の代入では、すでにそれより小さいか等しい接頭辞を持つ文字列に文字が追加されるだけです。そのため、すべての接頭辞が等しい場合を除き、最大値の同一性を変更することはできません。この場合、接尾辞が完全に答えを決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = sorted(input().strip())

        if k == 1:
            print("".join(s))
            continue

        if s[k-1] != s[0]:
            print(s[k-1])
        else:
            # all first k characters are equal
            print("".join(s[k-1:]))

if __name__ == "__main__":
    solve()
```この解決策は、文字列を並べ替えることから始まり、利用可能な最小の文字を直接推論できるようになります。 k が 1 に等しいかどうかのチェックは、分布が発生しない単純なケースを処理します。 最初の文字と k 番目の文字を比較することで、異なる開始点を生成する方法でグループ全体で最小の文字を分離できるかどうかが決まります。 それらが異なる場合、k 番目の文字が最悪のグループの制限要因になります。 それらが同じ場合、初期のグループはすべて同じように始まり、残りのサフィックスが最悪の文字列を定義することになります。 

微妙な点は、k 文字列を明示的に構築しないことです。 この推論により最適なパーティションの構造が保証されるため、直接のシミュレーションは不要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, k = map(int, input().split())
            s = sorted(input().strip())

            if k == 1:
                out.append("".join(s))
            elif s[k-1] != s[0]:
                out.append(s[k-1])
            else:
                out.append("".join(s[k-1:]))

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 n が k に等しい場合、文字列をソートして s[k-1] を正しく返すと、すべての文字が独立しているため、最大の文字が得られます。 たとえば、入力`cba`k=3 の場合は次のようになります`abc`、そして s[2] は`c`、それは正しいです。 

すべての文字が同一の場合、たとえば`aaaaa`任意の k を指定すると、アルゴリズムは等接プレフィックス分岐に入ります。 K-1のサフィックスはまだ残っています`a...a`したがって、すべてのグループは同じ文字列を持ち、最大値は変わりません。 

文字が大きく偏っている場合`zzzyyy`、ソートすると、`yyyzzz`。 k=2 の場合、プレフィックス チェックでは s[1] が s[0] に等しいため、インデックス 1 から始まるサフィックスを返します。`yyzzzz`グループ用語では、辞書編集上最大の文字列は正しく次のようになります。`zzz`。
