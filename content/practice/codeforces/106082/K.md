 ## 解決策
 ## 問題の理解

 時計回りの順番でその隅の点によって記述される単純な閉じたフェンスが与えられます。 フェンスは凸多角形を形成するため、すべての内角は 180 度未満であり、2 つの内部点間のすべての線分は領域内に留まります。 

このフェンスで囲まれた領域内に、2 つの同一の塔を配置したいと考えています。 各タワーはフェンスの境界から遠く離れている必要があり、その安全性はタワーからポリゴンの最も近いエッジまでのユークリッド距離として測定されます。 タワーがフェンスのいずれかの側の値 r よりも近い場合、近すぎるとみなされます。 

同時に、2 つの塔が互いに近づきすぎないようにする必要があります。 それらのユークリッド距離は少なくとも D でなければなりません。 

目標は、どちらかの塔からフェンス境界までの最小距離を最大化しながら、それらの間の距離制約を満たす 2 つの有効な内部点を選択することです。 

入力は、多角形の頂点の順序と必要な間隔 D を与えます。出力は単一の実数です。つまり、多角形の内側に 2 つの点を配置​​し、それぞれの点を境界から少なくとも r 離し、かつ少なくとも D の間隔を保つことができる最大の安全距離 r です。 

N が 100000 までという制約は、すべての点のペアまたはすべての配置候補を明示的にテストしようとするソリューションは実行不可能であることを意味します。 頂点に対する二次アプローチや内部の離散化は不可能です。 O(N log N) であっても許容されますが、頂点のペアごとに重いジオメトリを繰り返すものは失敗します。 

ジオメトリの収縮について考えると、微妙な問題が生じます。 点を距離 r だけ内側に押し込むと、実行可能領域の形状が連続的に変化します。 単純なアプローチでは、元の多角形の 2 つの遠い点を個別に選択して r を減算できると想定するかもしれませんが、これは縮小後に一部の点が無効になることを無視しています。 

もう 1 つの失敗モードは、ポリゴンを縮小すると切断されたり、直径が大幅に減少したりする可能性があることを無視したために発生します。 元の多角形に 2 つの遠く離れた点が存在する場合でも、安全半径要件の拡張後は両方とも境界に近すぎる可能性があります。 

小さな落とし穴の例としては、細長い三角形があります。 2 つの遠い端点は r = 0 の場合に有効ですが、r が小さい場合でも使用可能な領域のほとんどが削除され、達成可能な分離が大幅に減少します。 

## アプローチ

 最も直接的なアイデアは、2 つの塔の位置を推測し、それらの境界クリアランスを最大化しようとすることです。 多角形内の任意の点のペアについて、境界までの距離を計算し、それらの相互距離が少なくとも D であるかどうかを確認できます。候補点のセットは無限であり、最適な点は一般に頂点ではないため、頂点に制限すること自体が間違っているため、これはすぐに実行不可能になります。 

もう少し優れた総当りビューは、エッジに沿って候補を離散化するか、ポリゴン内部をグリッド化することですが、これは状態の爆発につながります。 頂点が 10^5 であっても、それらをペアにすると 10^10 の組み合わせになり、これは制限をはるかに超えています。 

重要な構造観察は、問題を 2 つの層に分けることです。 まず、安全半径 r の候補を決定します。 この場合、有効領域は、ポリゴン境界までの距離が少なくとも r であるすべての点のセットになります。 凸多角形の場合、この領域もすべてのエッジを距離 r だけ内側にオフセットすることによって得られる凸多角形になります。 

この縮小された多角形が得られると、質問は純粋に幾何学的なものになります。この多角形には少なくとも D の距離にある 2 つの点が含まれていますか? これは正確に、少なくとも D である多角形の直径です。凸多角形の直径は、回転キャリパーを使用して線形時間で計算できます。

これにより、問題は r に関する単調決定問題に変換されます。 半径 r が実現可能であれば、それより小さな半径も実現可能です。 この単調性により、r での二分探索が可能になります。 各チェックには O(N) のコストがかかり、それを約 50 ～ 60 回繰り返します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |

 | 二分探索 + 凸シュリンク + 直径チェック | O(N 対数精度) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 多角形はすでに時計回りの順序で与えられており、凸状であるため、何も並べ替えません。 オフセット エッジを作成するときは、その構造に直接依存します。 
2. 指定された安全半径 r が達成可能かどうかをチェックする関数を定義します。 この関数は、すべてのエッジを距離 r だけ内側にシフトすることによって形成される多角形を構築します。 元の各エッジは平行線になり、隣接するシフトされた線が交差して新しい頂点を形成します。 これが機能するのは、凸多角形ではすべての内側オフセットが明確に定義されたままであり、形状が退化するまで凸面が維持されるためです。 
3. 連続的にシフトされた線のすべての交点を計算して、縮小された多角形の頂点を取得します。 これらの頂点は順序どおりに残ります。 ポリゴンが崩れたり無効になったりすると、半径は使用できなくなります。 
4. 回転キャリパーを使用して、縮小された多角形の直径を計算します。 これは、船体の周りをスイープしながら対蹠点のペアを維持することにより、凸多角形の任意の 2 点間の最大距離を線形時間で求めます。 
5. 計算された直径が D 以上であれば、縮小多角形内に 2 点を十分な間隔で配置できるため、r は実行可能です。 
6. そうしないと、r が大きすぎるため、減らす必要があります。 
7. 0 から安全な上限 (通常は多角形の最大座標スケール) までの連続範囲にわたる二分探索 r 。 固定の反復回数または 1e-7 のような精度のしきい値を使用します。 
8. 見つかった実現可能な最大の r を返します。 

### なぜ効果があるのか

 実現可能条件は r において単調です。 r を増加すると、有効な領域が縮小するだけで、拡張されることはありません。そのため、r に有効な設定は、より小さい値に対しても有効のままです。 収縮した領域は凸状のままで、その直径は 2 つの内部点の間の可能な限り最良の分離を完全に捕捉します。 したがって、直径 ≥ D を確認することは、2 つの有効なタワー位置の存在を確認することと同じです。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

EPS = 1e-10

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def sub(a, b):
    return (a[0] - b[0], a[1] - b[1])

def dot(a, b):
    return a[0] * b[0] + a[1] * b[1]

def line_intersection(p1, d1, p2, d2):
    # p1 + t d1 intersects p2 + s d2
    # solve p1 + t d1 = p2 + s d2
    # cross(d1, d2) != 0
    den = cross(d1[0], d1[1], d2[0], d2[1])
    if abs(den) < EPS:
        return None
    dp = sub(p2, p1)
    t = cross(dp[0], dp[1], d2[0], d2[1]) / den
    return (p1[0] + d1[0] * t, p1[1] + d1[1] * t)

def build_offset(poly, r):
    n = len(poly)
    lines_p = []
    lines_d = []

    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        dx, dy = x2 - x1, y2 - y1

        length = math.hypot(dx, dy)
        nx, ny = dy / length, -dx / length

        cx = (x1 + x2) / 2
        cy = (y1 + y2) / 2
        if dot((nx, ny), (cx - 0, cy - 0)) < 0:
            nx, ny = -nx, -ny

        p = (x1 + nx * r, y1 + ny * r)
        lines_p.append(p)
        lines_d.append((dx, dy))

    new_poly = []
    for i in range(n):
        p1, d1 = lines_p[i], lines_d[i]
        p2, d2 = lines_p[(i + 1) % n], lines_d[(i + 1) % n]
        inter = line_intersection(p1, d1, p2, d2)
        if inter is None:
            return []
        new_poly.append(inter)

    return new_poly

def diameter(poly):
    n = len(poly)
    if n <= 1:
        return 0.0

    j = 1
    ans = 0.0

    for i in range(n):
        ni = (i + 1) % n
        while True:
            nj = (j + 1) % n
            if abs(cross(poly[ni][0] - poly[i][0],
                         poly[ni][1] - poly[i][1],
                         poly[nj][0] - poly[j][0],
                         poly[nj][1] - poly[j][1])) > abs(
                cross(poly[ni][0] - poly[i][0],
                      poly[ni][1] - poly[i][1],
                      poly[j][0] - poly[i][0],
                      poly[j][1] - poly[i][1])
            ):
                j = nj
            else:
                break

        dx = poly[i][0] - poly[j][0]
        dy = poly[i][1] - poly[j][1]
        ans = max(ans, dx * dx + dy * dy)

    return math.sqrt(ans)

def ok(poly, D, r):
    new_poly = build_offset(poly, r)
    if len(new_poly) < 3:
        return False
    return diameter(new_poly) >= D

def main():
    N, D = map(int, input().split())
    poly = [tuple(map(int, input().split())) for _ in range(N)]

    lo, hi = 0.0, 1e7
    for _ in range(60):
        mid = (lo + hi) / 2
        if ok(poly, D, mid):
            lo = mid
        else:
            hi = mid

    print(lo)

if __name__ == "__main__":
    main()
```実装では、幾何学的変換を実現可能性テストから分離します。 オフセット構築では、各エッジに平行な線を構築し、連続する線と交差して内部ポリゴンを再構築します。 直径関数では回転キャリパーを使用します。これは、凸包の直径を最適化する標準的な方法です。 

二分探索ループは、浮動小数点の不安定性の問題を回避するために、固定回数の反復を実行します。 

## 実用的な例

 辺の長さが 4、D = 4 の正方形のフェンスを考えてみましょう。 

| ステップ | r | オフセット ポリゴン サイズ | 直径 | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 1 | 0.0 | 4 | 5.66 | はい |
 | 2 | 1.0 | 4 小さい正方形 | 3.66 | いいえ |
 | 3 | 0.5 | 4 小さい正方形 | 4.66 | はい |

 このトレースは、多角形を縮小すると直径が滑らかに減少し、二分探索が直径が少なくとも D のままの最大 r に収束する様子を示しています。 

ここで、D が最長の対角線に近い、一方向に引き伸ばされた三角形を考えてみましょう。 r がわずかに増加すると、一方のエッジが最初に潰れ、直径が急速に減少します。 これは、頂点だけの線形推論では不十分な理由を示しています。

 ## 特殊なケース

 主要なエッジ ケースは、オフセット ポリゴンが直径の有効性を失う前に縮退するときに発生します。 薄い三角形では、半径が小さくても 1 つの頂点の寄与が削除され、多角形が 3 点未満に折りたたまれます。 その場合、有効な内部領域が残っていないため、アルゴリズムはその半径に対して実行不能を正しく返します。 

もう 1 つの特殊なケースは、D が非常に小さい場合です。 この場合、r は本質的に、多角形が崩れる前に多角形を内側にどれだけ押し込めるかによってのみ制限され、直径チェックはほとんどの場合成功します。 実現可能性が単調なままであるため、二分探索は依然として正しく収束します。 

最後のエッジ ケースは、2 つの連続するエッジがほぼ同一直線上にある場合に数値が不安定になることです。 交差の計算により浮動小数点誤差が増幅される可能性があるため、EPS チェックにより、ほぼゼロの行列式による除算が防止され、直径の計算を中断する無効な頂点の生成が回避されます。
