 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、配列の残りの部分を変更しないまま、連続する部分配列を選択して非降順で並べ替える操作を実行できます。 部分配列のそれぞれの異なる選択により、最終的な配列が異なる可能性があります。何もしないというオプションも含め、そのような操作を 1 つだけ適用した場合に、異なる配列が何個得られるかを数えたいと考えています。 

単純な解釈では、すべての部分配列を試して並べ替え、結果の配列を保存することになります。 タスクは、重複排除後に表示される一意の結果の数をカウントすることです。 

(編集上の文脈からの) 制約構造は、次のことを意味します。$n$十分な大きさであるため、$O(n^2)$さらに悪いことに、完全なシミュレーションによるサブ配列の列挙は受け入れられません。 各サブ配列をソートすると、追加の要素も導入されます。$O(n \log n)$、ブルートフォースは明らかに実行不可能になります。 

ソート後に実際には配列を変更しないサブ配列からは、微妙なエッジ ケースが発生します。 たとえば、サブ配列がすでにソートされている場合、またはそのエンドポイントがすでにグローバル構造と一致している場合、異なるサブ配列が同じ結果を生成する可能性があります。 もう 1 つの特殊なケースは、長さ 1 の部分配列をソートすることによる空の効果です。これは元の配列に対応し、正確に 1 回カウントされる必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。すべてのペアを列挙します。$(l, r)$、セグメントをソートし、結果の配列をセットに挿入します。 許可されているすべての操作が明示的に考慮されるため、これは正しいです。 ただし、$O(n^2)$サブ配列と各ソートのコスト$O(n \log n)$最悪の場合、大まかな事態につながる$O(n^3 \log n)$、これは実現可能な限界をはるかに超えています。 

重要な洞察は、セグメントに局所極値で定義された境界を「越えて移動」できる要素が含まれていない限り、サブ配列をソートしても実際には意味のあるものは何も変わらないため、ほとんどのサブ配列は冗長であるということです。 左の端点がすでにセグメントの最小値である場合、または右の端点がすでに最大値である場合、並べ替えによって、より短いセグメントと比較して新しい構成は導入されません。 これにより、問題は、左側の境界がセグメントの最小値ではなく、右側の境界がセグメントの最大値ではないセグメントのみをカウントするようになります。 このように再定式化すると、有効な各セグメントは、幾何学的にエンコードして効率的にカウントできる制約のペアに一意に対応します。 

計数問題を、平面内の点に関する優勢計数問題に変換します。これは、フェンウィック ツリーまたはセグメント ツリーのスイープ ラインを使用して解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |$O(n^3 \log n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 左側と右側から構造的制約を捕捉する 2 つのヘルパー配列を使用して、有効な部分配列を再定式化します。 

1. インデックスごとに$l$、計算します$p[l]$、右の最初の位置$l$ここで、要素は厳密に以下よりも小さい$a[l]$が表示されます。 そのような位置が存在しない場合は、次のように扱うことができます。$n+1$。 これは、次で始まる有効な部分配列がすべてであることを示しています。$l$少なくとも次まで拡張する必要があります$p[l]$そうでない場合は、最低条件に違反します。 
2. インデックスごとに$r$、計算します$q[r]$の左側に最も近い位置$r$ここで、要素は厳密に次よりも大きい$a[r]$が表示されます。 そのようなポジションが存在しない場合は、次のように扱います。$0$。 これは、有効なサブ配列が次で終わるという条件をエンコードします。$r$遅くとも開始する必要があります$q[r]$。 
3. 有効な各部分配列はペアに対応します。$(l, r)$そのような$l \le q[r]$そして$r \ge p[l]$。 これは、左からの「最小違反境界」と右からの「最大違反境界」の交点です。 
4. それぞれの適切なエンドポイントを再解釈します$r$ポイントとして$(r, q[r])$2D 平面内で。 固定左端点の場合$l$、すべての点を満足させたい$r \ge p[l]$そして$q[r] \ge l$。 これは、2D の四角形に対する支配クエリです。 
5. ポイントを昇順に処理します。$r$。 スイープしながら各ポイントをアクティブにします$(r, q[r])$そしてそれを保存します$q[r]$フェンウィックの木の中。 
6. それぞれについて$l$、到着したら$p[l]$、アクティブなポイントがいくつあるかをクエリします。$q[r] \ge l$。 これにより、この左端点に対する有効な右端点の数が得られます。 

### なぜ効果があるのか

 この変換では、サブ配列が「構造的に意味がある」場合、つまりソート中に両方のエンドポイントが強制的に移動される場合を正確に分離します。 配列$p$そして$q$最小または最大の制約に違反することなく、セグメントを拡張するための最初の障害をエンコードします。 すべての有効なサブ配列は、これら 2 つの独立した制約を満たす 1 つの左側の境界と 1 つの右側の境界によって一意に識別されます。 スイープ ラインは、2D 支配関係をフェンウィック ツリー上のプレフィックス合計のシーケンスに変換することにより、有効な各ペアを 1 回だけカウントすることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    p = [n + 1] * n
    q = [0] * n

    stack = []
    for i in range(n):
        while stack and a[stack[-1]] > a[i]:
            stack.pop()
        if stack:
            q[i] = stack[-1] + 1
        stack.append(i)

    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()
        if stack:
            p[i] = stack[-1] + 1
        stack.append(i)

    pts = []
    for r in range(n):
        pts.append((r + 1, q[r]))

    pts.sort()

    fenw = Fenwick(n + 2)

    ans = 0
    j = 0

    for l in range(1, n + 1):
        while j < n and pts[j][0] < p[l - 1]:
            r, y = pts[j]
            fenw.add(y, 1)
            j += 1

        ans += fenw.sum(n) - fenw.sum(l - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```スタックベースの前処理は、最も近い厳密に小さい境界と厳密に大きい境界を線形時間で計算します。 最初のパスのビルド$q[r]$左から単調増加するスタックを維持することで、より大きな要素が拡張をブロックする最後の位置を確実に見つけることができます。 2 番目のパスのビルド$p[l]$減少するスタックを使用して右から対称的に。 

スイープ ラインは右端点を昇順に処理します。 各ポイントは、その時点で 1 回だけアクティブになります。$r$が対象となり、フェンウィック ツリーにはインデックス付けされたカウントが保存されます。$q[r]$。 クエリはプレフィックスの合計を減算して、その数をカウントします。$q[r]$満足する$q[r] \ge l$。 

よくある落とし穴は、0 ベースのインデックス付けと 1 ベースのインデックス付けを混合することです。$p$そして$q$は、きれいな不等式を表す 1 から始まる座標で自然に定義されます。 実装では、比較の一貫性が保たれるようにインデックスを慎重にシフトします。

 ## 特殊なケース

 重要なエッジケースは、配列が厳密に単調である場合です。 厳密に増加する配列では、すべての左側の境界には右側に小さい要素がありません。$p[l]$になる$n+1$、有効な拡張子は左側の制約から寄与しません。 優勢条件を満たす点がないため、スイープ ラインは正しくゼロまたは最小限の寄与を生成します。 

厳密に減少する配列では、すべての右端点には左にそれより大きい要素がありません。$q[r]$ほとんどのポジションではゼロになります。 これにより、ほとんどの優位性チェックが強制的に失敗し、フェンウィック ツリー クエリは期待どおりに空の結果を返します。 

重複が存在する場合、別の特殊なケースが発生します。 どちらのスタック構造でも比較は厳密であるため、等しい要素によって境界が無効になることはありません。 これにより、等価性によってセグメントの最小または最大の性質が変更されるような新しい「厳密な違反」ポイントが作成されないため、正確さが保たれます。
