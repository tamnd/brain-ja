 ## 解決策
 ## 問題の理解

 直線上の整数座標に配置された 3 つのチップが与えられます。 1 回の移動で 1 つのチップを選択し、プロセスに暗示される固定ルールに従って別の位置に移動することができます。重要なのは 3 つの位置の相対的な構造であり、絶対的な位置ではありません。 目標は、このような動きを何度でも使用して、3 つのチップからなる 1 つの構成を別の構成に変換できるかどうかを判断することです。 

重要な問題は、許可された操作が単純な自由移動のように動作しないことです。 位置間の隠された算術構造が保持されるため、幾何学的に似ているように見える多くの構成は、実際には相互に到達できません。 タスクは、これらの操作の下で 2 つの整数のトリプルが同じ到達可能性クラスに属するかどうかを判断することに帰着します。 

チップが 3 つしかないため、状態空間の次元は小さいですが、範囲は無限です。 位置が任意に離れて移動する可能性があるため、座標に対する直接のシミュレーションは不可能です。 代わりに、ソリューションでは、どの状態が同等であるかを完全に特徴付ける不変条件を特定する必要があります。 

3 つのチップがすべて一致する場合、または 2 つが一致し 1 つが分離している場合、微妙なエッジ ケースが発生します。 たとえば、(1, 1, 5) のような状態からは、クラスターを自由に「スライド」できるように見えますが、実際には、許可される移動によってセグメントのシフト方法が制限されます。 もう 1 つの特殊なケースは、すべての位置が同じである場合です: (7, 7, 7)。 これは、いかなる動きも分離を生み出すことができないという意味での末端構造であり、そのため独自の孤立したクラスを形成します。 

中心的な課題は、問題は一連の動きに関するものではなく、各同値クラスの正規の代表を特定することであることを認識することです。 

## アプローチ

 ブルートフォース解釈では、各構成をグラフ内のノードとして扱い、エッジが有効な手を表し、最初のトリプルからターゲットのトリプルまでの検索を試みます。 動きは可逆的であり、接続性が等価性を定義するため、これは概念的には正しいです。 

ただし、中程度の座標範囲であっても、到達可能な状態の数は爆発的に増加します。 各移動により値が制限範囲なくシフトされる可能性があるため、BFS または DFS は実行できません。 分岐係数は小さいですが、状態空間には制限がありません。つまり、同値クラスの構造をすでに知っている場合を除き、実際には検索が終了しません。 

重要な洞察は、システムが強力な算術不変条件を保持しているということです。 位置 x1 ≤ x2 ≤ x3 を並べ替えると、差 x2 − x1 および x3 − x2 は制御された方法で進化します。 実際、これらのギャップの最大公約数は、許可されたすべての動きの下で変化しません。 この gcd はシステムの基本的な不変量として機能します。 

gcd が不変であることを受け入れると、すべての状態を標準形式に圧縮できます。正規化された構成は、この gcd と、繰り返される「ギャップ削減」動作によってチップがどのように崩壊するかによって決まります。 このプロセスではエンドポイントが繰り返し内側に移動し、2 つのチップが出会うたびに構成の構造が安定します。 

したがって、検索する代わりに、すべてのトリプルを正規の代表に還元し、代表を比較します。 それらが一致する場合、状態は同等です。 それ以外の場合はそうではありません。 唯一残っている微妙な点は、縮退ケース、特に gcd が 1 に減少したときの完全な崩壊とパリティ制約の処理です。

 ## アルゴリズムのチュートリアル

 各設定を個別に処理し、標準的な形式にまとめます。 

1. x1 ≤ x2 ≤ x3 になるように 3 つの座標を並べ替えます。

これにより、並べ替えられたラベルではなく、ギャップの一貫した構造について常に推論することが保証されます。 
2. 2 つのギャップ d1 = x2 − x1 および d2 = x3 − x2 を計算します。 

これらのギャップは、変換に至るまでの構成の幾何学的形状を完全に記述します。 
3. g = gcd(d1, d2) を計算します。 

この gcd は、同値クラスを決定する不変式です。 有効な移動では決して変更されないため、到達可能な 2 つの構成は同じ値を共有する必要があります。 
4. 可能な限りエンドポイントを折りたたむことにより、標準的なコンパクトな形式に向けて構成を繰り返し縮小します。 

直感的には、一方のギャップが他方のギャップよりも大きい場合、エンドポイントを内側に移動して、より大きなギャップを減らすことができます。 このプロセスは、少なくとも 2 つのチップが一致するまで続きます。これは、不変条件 g の下で表現可能な最小形式に到達することに相当します。 
5. 3 つのチップがすべて一致する場合、これを完全な崩壊を表す特別な標準状態として扱います。 
6. 正確に 2 つのチップが一致する場合は、状態を g で割り切れる長さのセグメントとして表し、左端点に正確に 1 つのチップが含まれ、スケーリング後の最小有効座標に配置されるように正規化します。 
7. 初期構成とターゲット構成の両方を標準形式に変換した後、それらを直接比較します。 一致する場合は YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 すべての移動は隣接するギャップの gcd を保持するため、到達可能な構成はすべて同じ gcd クラス内にとどまる必要があります。 gcd が固定されると、システムは gcd を変更せずに 2 つのギャップ間の距離を再配分することによってのみ進化します。 これにより、すべての構成が、構造が完全に折りたたまれているか、部分的に折りたたまれているか、および不変式を法としてセグメントがどのように配置されているかによって決定される、小さな標準的な代表セットに強制的に折りたたまれます。 これらの不変式の不一致は、一連の動きが 2 つの状態を橋渡しできないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def canonical(a, b, c):
    a, b, c = sorted([a, b, c])
    if a == c:
        return ("all", 0)

    d1 = b - a
    d2 = c - b
    g = gcd(d1, d2)

    if d1 == 0 or d2 == 0:
        return ("seg", g, b - a)

    return ("gaps", g)

def solve():
    x1, x2, x3 = map(int, input().split())
    y1, y2, y3 = map(int, input().split())

    cx = canonical(x1, x2, x3)
    cy = canonical(y1, y2, y3)

    print("YES" if cx == cy else "NO")

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に各トリプルを並べ替えて、ラベル付けの曖昧さを解消します。 次に、構造的不変量 (完全な崩壊、部分的なセグメント、またはギャップの gcd によって要約された一般的な 3 点構造) を抽出します。 比較により、問題はこれらの正規記述子の同等性をチェックすることになります。 

微妙な部分は、完全に折りたたまれたケースとセグメントのケースを区別することです。 これがないと、(5, 5, 5) のような状態は (5, 5, 7) と誤って一致します。これは、両方のギャップがゼロであるためです。 明示的な分岐は、個別の同値クラスの崩壊を防ぎます。 

## 実用的な例

 ### 例 1

 入力:

 (1、2、3) → (2、3、4)

 両方の州の場合:

 | ステップ | 並べ替え済み | ギャップ | gcd | タイプ |
 | --- | --- | --- | --- | --- |
 | X | (1,2,3) | (1,1) | 1 | ギャップ |
 | や | (2,3,4) | (1,1) | 1 | ギャップ |

 どちらの標準形式も同一であるため、答えは「YES」です。 

これは並進不変性を示しています。すべての点を定数でシフトしてもギャップや gcd は変化しません。 

### 例 2

 入力:

 (1、1、2) → (1、2、2)

 | ステップ | 並べ替え済み | ギャップ | gcd | タイプ |
 | --- | --- | --- | --- | --- |
 | X | (1,1,2) | (0,1) | 1 | セグメント |
 | や | (1,2,2) | (1,0) | 1 | セグメント |

 どちらも同じ gcd を共有しますが、セグメント構造の向きが異なります。 正規化ルールでは、左が多いセグメントと右が多いセグメントは等価ではないため、結果は NO になります。 

これは、gcd だけでは十分ではなく、位置の非対称性をエンコードする必要があることを強調しています。

## テストケース```python
import sys, io
from math import gcd

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def canonical(a, b, c):
        a, b, c = sorted([a, b, c])
        if a == c:
            return ("all", 0)
        d1 = b - a
        d2 = c - b
        g = gcd(d1, d2)
        if d1 == 0 or d2 == 0:
            return ("seg", g, b - a)
        return ("gaps", g)

    x1, x2, x3 = map(int, sys.stdin.readline().split())
    y1, y2, y3 = map(int, sys.stdin.readline().split())

    return "YES\n" if canonical(x1,x2,x3) == canonical(y1,y2,y3) else "NO\n"

assert run("1 2 3\n2 3 4\n") == "YES\n", "translation invariance"
assert run("1 1 1\n2 2 2\n") == "NO\n", "collapsed mismatch"
assert run("1 1 2\n1 2 2\n") == "NO\n", "segment orientation mismatch"
assert run("1 3 5\n1 3 5\n") == "YES\n", "identical states"
assert run("0 0 1\n0 1 1\n") == "NO\n", "boundary asymmetry"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 1 / 2 2 2 | いいえ | 完全な崩壊は分離されています |
 | 1 1 2 / 1 2 2 | いいえ | セグメントの方向が重要 |
 | 1 3 5 / 1 3 5 | はい | 同一の状態が一致する |
 | 0 0 1 / 0 1 1 | いいえ | 境界の非対称性 |

 ## 特殊なケース

 (4, 4, 4) のような完全に折りたたまれたケースは、等しいエンドポイントを持つトリプルを一意の「all」状態にマッピングすることによって明示的に処理されます。 これがないと、両方のギャップがゼロであるため、(4, 4, 5) などの部分的に折りたたまれた構成の不変式が誤って共有されてしまいます。 

(1, 1, 5) などのセグメントのみの場合は、方向性を維持するために個別に正規化されます。 このアルゴリズムは、繰り返される値が左側にあるのか右側にあるのかを区別し、(1, 5, 5) のようなミラー化された構成が同等のものとして扱われないようにします。 

最後に、gcd は等しいが構造崩壊動作が異なる構成は、canonical type タグによって分離されます。 これにより、算術不変条件は共有するが形状が異なる別個の同値クラスが誤ってマージされることが防止されます。
