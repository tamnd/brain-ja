 ## 解決策
 ## 問題の理解

 この問題のプロセスは、時間の経過とともに数秒単位で進行します。 長さの 1 つの完全なサイクル中`n`、システムは一貫して動作します。つまり、一定回数のアップグレードを実行し、一定回数のクリックを実行し、それらのクリックによって一定数のペーパークリップが生成されます。 この最初の完全なサイクルをシミュレートした後、次の 3 つの重要な値を取得します。 有効にアクティブになったアップグレードの数 (`U`)、クリック数 (`C`)、およびサイクル中に合計で何個のペーパークリップが作成されたか (`P`）。 

重要な構造は、2 番目のサイクルが独立していないことです。 アップグレードは継続されるため、`U`変わらないままです。 クリック数も変わらないので、`C`サイクル全体にわたって固定されます。 唯一の違いは、アップグレードによってその出力が累積的に増幅されるため、各クリックの価値が後のサイクルでより高くなるということです。 その結果、後続の全サイクルごとに、固定の追加的増加が生成されます。`U · C`前のサイクルと比較したペーパークリップ。 

これにより、長いプロセスが全サイクルにわたる等差数列に変わります。 あれば`k = ⌊t / n⌋`全サイクルの場合、全サイクルの合計寄与は、次から始まる算術シーケンスの合計になります。`P`共通の違いがある`U · C`。 

全サイクルを処理した後、残りの`t mod n`秒は不完全なサイクルを形成します。 この最後のフラグメントは、線形成長パターンがきれいに適用される完全な繰り返しを形成しないため、同じ秒ごとのルールを使用して直接シミュレートする必要があります。 

この構造によって暗示される制約は、効率の点で厳しいものになります。 すべてを直接シミュレーション`t`秒は不可能な場合`t`サイズが大きいため、最大 10^9 以上の操作が必要になる可能性があります。 したがって、ソリューションでは、全サイクルの繰り返し構造を閉じた形式の等差数列計算に縮小し、単一の演算のみを残す必要があります。`O(n)`初期サイクルと小規模なシミュレーション`O(n)`以下の場合は残りをパスします。 

微妙な失敗のケースは、最後の部分サイクルが無視されたり、誤って完全なサイクルとして扱われる場合に発生します。 たとえば、次の場合`t = n + 1`、これを 2 つの完全なサイクルとして扱うと、2 番目のサイクル全体の寄与が過大評価されてしまいます。 もう 1 つのよくある間違いは、増分ゲインを忘れることです。`U · C`サイクル内ではなく、全サイクル間でのみ適用されます。 

## アプローチ

 単純なアプローチでは、時間まで毎秒シミュレーションすることになります。`t`。 毎秒、アップグレード、クリック、蓄積されたペーパークリップを説明どおりに正確に追跡します。 これはプロセス定義を直接反映しているため、概念的には単純で正しいものです。 ただし、コストは次のように直線的に増加します。`t`。 もし`t`が大きい場合、このアプローチは最大 10^9 以上の演算を実行しますが、これは一般的な制限の下では実行できません。 

重要な観察は、システムは毎回「動作パターンをリセット」するということです。`n`ただし、アップグレードが持続し、将来のサイクルが線形的に拡大される場合を除きます。 1 つの完全なサイクルが何を生成するかがわかれば、後続の各サイクルを前のサイクルのシフトされたバージョンとして扱うことができます。 サイクル間の唯一の違いは、定数の加算項です`U · C`、サイクル出力のシーケンスを等差数列にします。 

すべてのサイクルをシミュレートする代わりに、最初のサイクル値を計算します。`P`、次に、完全なサイクル数にわたる進行を合計します。 最後の部分サイクルは、数列計算式に必要な構造を完成していないため、引き続き直接シミュレートされます。 

これにより、膨大な時間になる可能性があるシミュレーションの問題が、単一の前処理パスと定数時間の算術合計に軽減されます。

 ## アルゴリズムのチュートリアル

 まず、正確に 1 つの完全なサイクルをシミュレートします。`n`秒。 このシミュレーションでは、時間の経過とともにアクティブになるアップグレードの数、発生するクリックの数、作成されるペーパークリップの数を追跡します。 このシミュレーションの終了時に、`U`、`C`、 そして`P`。 

次に、合計時間に収まる完全なサイクルの数を計算します。`t`。 これは`k = t // n`。 これらは、同じ構造パターンを繰り返すサイクルですが、サイクル間で直線的に成長します。 

次に、等差数列を使用して、すべての完全なサイクルの寄与を計算します。 最初のサイクルは貢献します`P`、2番目は貢献します`P + U · C`、3番目は貢献します`P + 2U · C`、 等々。 これらの合計`k`項は標準の等差級数公式を使用して計算され、反復のない閉じた形式が得られます。 

全サイクルを計算した後、残り時間を計算します。`r = t % n`。 正確にシミュレーションします`r`部分的なサイクルでは全サイクルの乗数効果が蓄積されないため、サイクルと同じ初期状態から始まる秒数。 

最後に、部分サイクルの寄与を合計に加えます。 

### なぜ効果があるのか

 正確さは、すべての完全なサイクルが同一のアップグレードとクリック構造で始まるという事実から来ます。`U`そして`C`サイクル全体にわたって一定のままです。 唯一の進化要素は、サイクル全体にわたるクリックに対するアップグレードの累積効果であり、一定量ずつ直線的に増加します。`U · C`毎回。 これにより、サイクル出力が等差数列を形成し、完全なサイクルとサフィックスへの分解により、タイムラインが重複や省略なく正確に分割されることが保証されます。

残りのループは、完全なサイクルを形成しない残りの秒数を処理します。 この算術公式を部分的なサイクルに適用すると、存在しない線形成長が誤って仮定されてしまうため、この分離は不可欠です。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`t < n`。 この状況では、完全なサイクルが存在しないため、等差数列コンポーネントを完全にスキップする必要があります。 アルゴリズムは正しく設定します`k = 0`、合計は`k * P + U * C * k * (k - 1) // 2 = 0`、残りのシミュレーションのみが残ります。 

もう一つのケースは、`t = n`、ちょうど 1 つのサイクルが存在します。 ここ`k = 1`、そして累進式は次のように崩壊します。`P`、第 2 項がゼロになるため。 これは、最初のサイクルのみが寄与するという予想と一致します。 

最後の微妙なケースは次のような場合です。`U = 0`。 それから`cycle_gain = 0`、すべてのサイクルが同じ値に寄与することを意味します`P`。 進行合計は次のようになります`k * P`これは、サイクル全体にわたる成長がないことを正確に反映しています。
