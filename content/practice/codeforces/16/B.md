 ## 解決策
 ## 問題の理解

 正確に運ぶことができる強盗がいます`n`マッチ箱。 倉庫の中には、`m`コンテナ。 各コンテナ`i`もっている`a_i`マッチ箱、そのコンテナ内のすべてのマッチ箱には次のものが含まれます`b_i`一致します。 目標は、`n`一致の総数が最大になるようにマッチボックスを調整します。 

入力は 2 つの整数です`n`そして`m`に続く`m`ペア`(a_i, b_i)`。 出力は単一の整数です。つまり、泥棒が取得できる一致の最大合計です。 

制約が物語っています。`n`2・10^8 までの大きさになる可能性があります。 これは、個々のマッチボックスを反復処理するには膨大な量であるため、各マッチボックスを個別に検査するソリューションは遅すぎます。`m`は最大でも 20 個なので、コンテナーの数はわずかです。 これは、並べ替えやコンテナーの貪欲な選択が実現可能であることを示唆しています。`a_i`サイズが大きくなる可能性があるため、コンテナ内のマッチ箱の数が超過する可能性があります。`n`。`b_i`は 1 ～ 10 と小さいため、ボックスごとの一致は通常の整数で簡単に処理できます。 

注意すべきエッジケースには、強盗が運べる量を超えるマッチ箱が入ったコンテナが含まれます。 たとえば、次の場合`n = 5`そしてコンテナには`a_i = 10`の付いたボックス`b_i = 3`マッチの場合、泥棒はそのうちの 5 つしか持ち込めません。 すべてを追加する不用意な実装`10*3 = 30`一致は間違っているでしょう。 もう 1 つのエッジケースは次のような場合です`n`すべてのコンテナ内のマッチ箱の合計数よりも大きくなります。 その場合、強盗はすべてを奪えばいいのです。 

## アプローチ

 ブルートフォース手法では、コンテナ内のマッチ箱のあらゆる組み合わせを繰り返し、合計の一致を合計して最良のものを選択します。 と`m`最大 20 個、各コンテナには最大 10^8 個のマッチ箱があり、その組み合わせの数は天文学的です。 コンテナだけをユニット全体として考えたとしても、サブセットの数は`2^m = 2^20 ≈ 1 million`、これはサブセット合計には実行可能ですが、ここでは不要です。 個々のマッチ箱まで調査することは明らかに不可能です。`n`2·10^8 にすることができます。 

重要な観察は、この問題は貪欲であるということです。マッチの数を最大化するには、泥棒はまず最大のマッチ箱を手に入れる必要があります。`b_i`(箱ごとにマッチします)。 コンテナの順序は次の場合を除いて無関係です。`b_i`。 コンテナを並べ替えると、`b_i`下りながら、強盗は最初のコンテナからできるだけ多くの箱を持ち出し、次に次のコンテナを、リュックサックがいっぱいになるまで持ち去ります。 これが機能するのは、各マッチ箱が分割できず、より多くのマッチが含まれるボックスが常に、より少ないマッチを含むボックスよりも厳密に優れているためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m * m) | O(m) | 遅すぎる |
 | 貪欲 / 並べ替え`b_i`| O(m log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`（容量）と`m`(コンテナの数)。 初期化する`total_matches = 0`。 
2. 各コンテナの内容を読み取ります。`(a_i, b_i)`タプルのリストとして保存します。 
3. コンテナのリストを降順に並べ替えます。`b_i`。 仕分けにより、常に最も価値のある箱を最初に考慮することができます。 
4. ソートされたコンテナーを反復処理します。 

ａ． させて`take = min(a_i, n)`。 これは、容量を超えずにこのコンテナから取り出せる箱の数です。 

b. 追加`take * b_i`に`total_matches`。 

c. 減少`n`による`take`。 もし`n`が0になるとリュックがいっぱいなのでループを抜ける。 
5. 印刷`total_matches`。 

機能する理由: すべてのステップで、ボックスごとに一致が最も高い利用可能なマッチボックスが最初に取得されます。 マッチ箱は分割できないため、価値の高い箱を価値の低い箱に残しておくメリットはありません。 貪欲な選択は安全であり、`n`ボックスが取得されると、合計の一致が最大化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
containers = []

for _ in range(m):
    a, b = map(int, input().split())
    containers.append((b, a))  # store as (matches per box, number of boxes)

# Sort by matches per box descending
containers.sort(reverse=True)

total_matches = 0
for b, a in containers:
    if n == 0:
        break
    take = min(a, n)
    total_matches += take * b
    n -= take

print(total_matches)
```保管します`(b, a)`の代わりに`(a, b)`仕分けが楽になるから`b`降下中。 反復中に、`take = min(a, n)`キャパシティを超えないようにします。 リュックサックがいっぱいの場合、ループは早期に終了します。 これらの詳細により、オフバイワンまたはオーバーフローの問題が防止されます。 

## 実用的な例

 サンプル 1:

 入力:```

5 10
2 5
3 6
```段階的なトレース:

 | コンテナ (b、a) | 前の | 取る | | 以降の合計一致数 後 |
 | --- | --- | --- | --- | --- |
 | (10, 5) | 7 | 5 | 50 | 2 |
 | (6, 3) | 2 | 2 | 50 + 12 = 62 | 0 |
 | (5, 2) | 0 | 0 | 62 | 0 |

 説明: 最初のコンテナが最も豊富です。5 つの箱を取ります。 次のコンテナ、残り容量に2箱しか入りません。 合計一致 = 62。 

別のテストケース:

 入力:```
10 2
3 10
5 20
```| コンテナ (b、a) | 前の | 取る | | 以降の合計一致数 後 |
 | --- | --- | --- | --- | --- |
 | (20, 5) | 10 | 5 | 100 | 5 |
 | (10, 3) | 5 | 3 | 100 + 30 = 130 | 2 |

 残り容量(2)がどのボックスよりも多いので停止します。 合計一致 = 130。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m) | 仕分け`m`コンテナが主流です。 反復は O(m) |
 | スペース | O(m) | コンテナリストの保存 |

 与えられた`m ≤ 20`、並べ替えは簡単で、アルゴリズムは 0 秒の時間制限と 64 MB のメモリ制限内に簡単に収まります。 取り扱い`n`マッチ箱ごとに反復することはなく、コンテナごとにのみ反復するため、最大 2 · 10^8 が機能します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    n, m = map(int, input().split())
    containers = []
    for _ in range(m):
        a, b = map(int, input().split())
        containers.append((b, a))
    containers.sort(reverse=True)
    total_matches = 0
    for b, a in containers:
        if n == 0:
            break
        take = min(a, n)
        total_matches += take * b
        n -= take
    return str(total_matches)

# Provided sample
assert run("7 3\n5 10\n2 5\n3 6\n") == "62", "sample 1"

# Minimum input
assert run("1 1\n1 1\n") == "1", "minimum input"

# Large n, all containers smaller
assert run("10 2\n3 5\n2 10\n") == "35", "capacity larger than total boxes"

# All boxes same b
assert run("5 2\n3 7\n4 7\n") == "35", "all boxes same value"

# Single rich container exceeds n
assert run("4 1\n10 100\n") == "400", "single container larger than capacity"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1\n1 1 | 1 | 最小入力エッジケース |
 | 10 2\n3 5\n2 10 | 35 | ボックスの合計よりも大きい容量 |
 | 5 2\n3 7\n4 7 | 35 | すべてのボックスが等しい値 |
 | 4 1\n10 100 | 400 | コンテナが容量より大きい場合は、n 個のボックスしか必要ありません |

 ## 特殊なケース

 最もリッチなコンテナにそれよりも多くのボックスが入っている場合`n`:```
n = 4, m = 1
10 100
```

`take = min(10, 4) = 4`、`total_matches = 4*100 = 400`。 そうです、過剰カウントはありません。 

ボックスの合計が n 未満の場合:```
n = 10, m = 2
3 5
2
```
