 ## 解決策
 ## 問題の理解

 まず、寸法が次のようなモニターから始めます。`a × b`。 どちらの値も整数です。 新しい寸法で正確なアスペクト比が維持されるように、このモニターを縮小したいと考えています。`x : y`。 

新しいモニターは 3 つの条件を同時に満たす必要があります。 

まず、両方の次元が整数のままでなければなりません。 

次に、新しい幅は次の値を超えることはできません。`a`、新しい高さは超えることはできません`b`、モニターのサイズを縮小することしか許可されていないためです。 

第三に、比率を持つすべての有効な縮小モニターの中で`x : y`, 可能な限り面積が大きいものが望ましいです。 

アスペクト比の条件は、最終的な寸法が次のようになることを意味します。$$(k \cdot x,\ k \cdot y)$$何らかの正の整数の場合`k`。 

制約は次のとおりです`2 · 10^9`これにより、考えられるすべての幅、高さ、またはスケーリング係数を 1 つずつ繰り返すアプローチは即座に除外されます。 競技プログラミングの制限内では、何十億回もループを実行することは不可能です。 定数時間または対数時間の解が必要です。 

難しいのは、この比率がまだ減少していない可能性があることです。 たとえば、次の場合`x = 6`そして`y = 4`の場合、その比率は実際には次と等価になります。`3 : 2`。 最初に単純化することを忘れると、一部の有効な答えは不可能であると誤って結論付ける可能性があります。 

次の例を考えてみましょう。```
a = 10
b = 10
x = 6
y = 4
```使用する場合`(6k, 4k)`直接、最大の有効な`k`は`1`、与える`(6, 4)`エリアあり`24`。 

しかし、比率を下げた後、`3 : 2`、使用できます`k = 3`、与える`(9, 6)`エリアあり`54`、これははるかに大きいです。 

1 つの次元が制限要因となる場合、別の特殊なケースが発生します。```
a = 8
b = 5
x = 4
y = 3
```不用意に実装すると、最初に幅を最大化してから試してしまう可能性があります。`(8, 6)`、高さ制限を超えています。 

正しいアプローチでは、両方の次元が同時に適合する必要があることが認識されます。 有効な最大のスケーリング係数は次のとおりです。$$k = \min\left(\left\lfloor \frac{a}{x} \right\rfloor,\ \left\lfloor \frac{b}{y} \right\rfloor\right)$$比率を下げた後。 

もう 1 つの微妙なケースは、有効な陽性モニターが存在しない場合です。```
a = 1
b = 1
x = 2
y = 3
```比率を維持する最小のモニターでも寸法が必要になります`(2, 3)`、適合しません。 正しい出力は次のとおりです。```
0 0
```バグのある実装により、誤って負の値、小数値、または`(2, 3)`境界を注意深く確認せずに。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのスケーリング係数が試行されます。`k`かどうかを確認してください`(k·x, k·y)`中に収まる`(a, b)`。 すべての有効な選択肢の中で、面積が最も大きいものを選択します。 

これが機能するのは、すべての有効なモニターが比率を持っているためです。`x : y`の整数倍でなければなりません`(x, y)`。 問題は検索スペースのサイズです。 もし`a = b = 2 · 10^9`そして`x = y = 1`、 それから`k`と同じ大きさにすることができます`2 · 10^9`。 何十億もの候補を反復処理するのは遅すぎます。 

重要な観察は、領域が次のように単調に増加するということです。`k`。 

面積は次のとおりです。$$(kx)(ky) = k^2xy$$以来`x`そして`y`は固定の正の数です。面積の最大化は最大化とまったく同じです。`k`。 

したがって、すべての候補をテストするのではなく、最大の整数だけが必要です`k`満足のいく：$$kx \le a$$

$$ky \le b$$それは次のようになります:$$k \le \left\lfloor \frac{a}{x} \right\rfloor$$

$$k \le \left\lfloor \frac{b}{y} \right\rfloor$$有効な最大値は、単にこれら 2 つの制限のうち小さい方です。 

まだ重要な詳細が 1 つあります。 計算する前に`k`、比率を下げなければなりません`(x, y)`それらの最大公約数によって。 そうしないと、モニターのサイズを人為的に必要以上に大きくすることになります。 

たとえば、比率`100 : 50`本当に`2 : 1`。 非縮小バージョンを使用すると、可能なスケーリング係数が大幅に制限されます。 

両方の数値を次の値で割った後、`gcd(x, y)`の場合、アルゴリズムは数回の算術演算と 1 回の gcd 計算になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(min(a/x, b/y)) | お(1) | 遅すぎる |
 | 最適 | O(log(min(x, y))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの整数を読み取ります`a`、`b`、`x`、 そして`y`。`a`そして`b`はモニターの制限ですが、`x : y`は必要なアスペクト比です。 
2. コンピューティング`g = gcd(x, y)`。 

比率を下げることはできません。 gcd で割ると最小当量比が得られます。 
3. 以下を置き換えます。$$x \leftarrow \frac{x}{g}$$

$$y \leftarrow \frac{y}{g}$$このステップの後、`x`そして`y`は互いに素である。 
4. 可能な最大のスケーリング係数を計算します。$$k = \min\left(\left\lfloor \frac{a}{x} \right\rfloor,\ \left\lfloor \frac{b}{y} \right\rfloor\right)$$これより大きな値を指定すると、少なくとも 1 つの次元制限に違反します。 
5. 出力:$$(k \cdot x,\ k \cdot y)$$もし`k = 0`、これは自動的に次のようになります`0 0`は、有効な縮小モニターが存在しないことを意味します。 

### なぜ効果があるのか

 比率を下げた後、アスペクト比を持つすべての有効なモニター`x : y`形を持っています`(kx, ky)`ある整数に対して`k ≥ 0`。 

モニターの制約では、両方の寸法が適合する必要があります。$$kx \le a$$

$$ky \le b$$したがって、すべての有効な`k`以下を満たす必要があります:$$k \le \left\lfloor \frac{a}{x} \right\rfloor$$そして$$k \le \left\lfloor \frac{b}{y} \right\rfloor$$最小値を取ると、実現可能な最大のスケーリング係数が得られます。 

面積は次と等しいため、$$(kx)(ky) = k^2xy$$そして`x`、`y`が固定の正の整数である場合、面積は次のように厳密に増加します。`k`が増加します。 有効な最大のもの`k`常に最大の可能な領域を生成します。 

すべての同等のアスペクト比は同じモニター ファミリを表す必要があるため、最初に比率を下げることが必要です。 削減されていない値を使用すると、有効な候補がスキップされます。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

a, b, x, y = map(int, input().split())

g = gcd(x, y)

x //= g
y //= g

k = min(a // x, b // y)

print(k * x, k * y)
```解決策は数​​学的導出に直接従います。 

最初の重要なステップは、次を使用して比率を減らすことです。`gcd`。 これがないと、アルゴリズムによって最適なモニターよりも小さいモニターが生成される可能性があります。 以来`x`そして`y`と同じ大きさにすることができます`2 · 10^9`、Euclid のアルゴリズムを使用することは、対数時間で実行されるため理想的です。 

正規化後、コードは可能な最大のスケーリング係数を計算します。`k`。 ここでは整数の除算が不可欠です。 モニターの範囲内に収まる最大の整数乗数が必要です。 

操作の順序が重要です。 除算を計算する前に比率を減らします。 削減されていない値を使用して制限を計算すると、有効なスケーリング係数が過小評価される可能性があります。 

Python の整数はオーバーフローを自動的に回避しますが、可能な最大の積は次のとおりであるため、このロジックは 64 ビット言語でも安全です。$$2 \cdot 10^9$$これは、符号付き 64 ビット整数内に快適に収まります。 

実装では当然、不可能なケースも処理されます。 どちらかの場合`a // x`または`b // y`ゼロに等しい場合、`k = 0`、印刷結果は次のようになります`0 0`。

 結果として得られるモニターは、`(800, 600)`。 この例は、元のモニターがすでに必要なアスペクト比を満たしている可能性があることを示しています。

 入力:```
10 10 6 4
```比率は減りません。 

| ステップ | | b | × | y | gcd | k |

制約が非常に大きいため、反復検索は失敗します。 このソリューションでは、gcd 計算と少数の算術演算のみが実行され、制限内に簡単に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io
from math import gcd

def solve():
    input = sys.stdin.readline

    a, b, x, y = map(int, input().split())

    g = gcd(x, y)

    x //= g
    y //= g

    k = min(a // x, b // y)

    print(k * x, k * y)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("800 600 4 3\n") == "800 600", "sample 1"

# minimum valid case
assert run("1 1 1 1\n") == "1 1", "minimum case"

# impossible case
assert run("1 1 2 3\n") == "0 0", "no valid monitor"

# ratio reduction required
assert run("10 10 6 4\n") == "9 6", "must reduce ratio"

# maximum values
assert run("2000000000 2000000000 1 1\n") == "2000000000 2000000000", "large values"

# one dimension limiting
assert run("8 5 4 3\n") == "4 3", "height constraint dominates"

 ## 特殊なケース

 縮小されていない比率の場合を考えてみましょう。```
10 10 6 4
```アルゴリズムは以下を計算します。$$gcd(6,4)=2$$したがって、比率は次のようになります`(3,2)`。 

それから：$$k = \min(10//3,\ 10//2)=\min(3,5)=3$$最終的なモニターは次のとおりです。```
9 6
```削減をスキップした場合、得られるのは`(6,4)`、面積がはるかに小さくなります。 

次に、不可能な構成を調べます。```
1 1 2 3
```すでに比率は下がっています。 スケーリング係数は次のようになります。$$k = \min(1//2,\ 1//3)=\min(0,0)=0$$アルゴリズムは次を出力します。```
0 0
```これは、正のモニターが比率を満たすことができないことを正しく示しています。 

最後に、1 つのディメンションがボトルネックになっているケースを考えてみましょう。```
8 5 4 3
```次のように計算します。$$k = \min(8//4,\ 5//3)=\min(2,1)=1$$結果は次のようになります。```
4 3
```幅により拡大縮小が可能であっても、`2`、高さはそうではありません。 2 つの制限の最小値を取ると、両方の次元が同時に有効であることが保証されます。
