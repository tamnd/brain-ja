 ## 解決策
 ## 問題の理解

 私たちは持っています`n`湖の魚。 毎日、現在生きている魚の順序付けされていないペアが 1 つだけ均一にランダムに選択されます。 魚を釣るとき`i`魚との出会い`j`、 魚`i`魚を食べる`j`確率的に`a[i][j]`、魚`j`魚を食べる`i`確率的に`a[j][i] = 1 - a[i][j]`。 

このプロセスは、1 匹の魚だけが生き残るまで続きます。 すべての魚について、それが最後に生き残る確率を計算する必要があります。 

入力は確率行列です。 エントリ`a[i][j]`魚が釣れる可能性を教えてくれる`i`魚を倒す`j`直接の出会いで。 一般に行列は非対称ですが、すべてのペアは次の条件を満たします。```
a[i][j] + a[j][i] = 1
```制約`n ≤ 18`ソリューションを完全に形作ります。 考えられる排除シーケンスの数はおおよそ次のとおりであるため、すべての戦闘命令の総当りシミュレーションはすぐに爆発します。```
n * (n - 1) * (n - 2) * ...
```それが階乗成長です。 たとえ`n = 18`、それは天文学的な大きさです。 

番号`2^18 = 262144`サブセット動的プログラミングには十分小さいです。 いつでも`n`が約 20 の場合、通常はビットマスク DP が最初に調査されます。 生きている魚のすべてのサブセットの状態が現実的になります。 

間違った配合を壊してしまう、見落としやすいケースがいくつかあります。 

次の入力を考えてみましょう。```
2
0 1
0 0
```魚`0`いつも魚を倒す`1`。 正しい答えは次のとおりです。```
1.000000 0.000000
```両方の魚の間で確率を対称的に分配する不注意な実装は、誤った結果を生成します。`0.5 0.5`。 

もう 1 つの微妙なケースは、複数のパスが同じアライブ セットにつながる場合です。```
3
0 0.5 0.5
0.5 0 0.5
0.5 0.5 0
```すべての魚は対称的であるため、すべての答えは正確でなければなりません`1/3`。 DP がすべての先行国家からの貢献を蓄積するのを忘れた場合、確率は合計されなくなります。`1`。 

さらに危険な間違いは、遷移確率自体に現れます。 生きている魚がいると仮定します。`{0,1,2}`。 正確には次のとおりです。```
C(3,2) = 3
```出会う可能性のあるペア。 魚なら`0`魚に死ぬ`1`、遷移確率には、による除算が含まれている必要があります。`3`。 この正規化を忘れると、合計確率は次の値を超えます`1`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのステップで、生きている魚の可能なすべてのペアを選択し、考えられる両方の戦闘結果に基づいて分岐し、1 匹の魚が残るまで再帰的に続行します。 

このプロセスはメモリを必要としないため、これが機能します。 未来は現在生きているセットにのみ依存します。 考えられるすべての消去チェーンを再帰的に列挙し、パスに沿って確率を乗算すると、最終的には正確な答えが得られます。 

問題は、再帰ツリー内の状態の数です。 初めに次のものがあります。```
C(n,2)
```可能な会議。 1 回除去すると次のようになります。```
C(n-1,2)
```等々。 

戦闘シーケンスの総数は、おおよそ階乗時間のように増加します。 のために`n = 18`、これはまったく不可能です。 

重要な観察は、多くの再帰的分岐が生きている魚の同じサブセットに到達していることです。 

たとえば、生きた魚が次のようになったとします。`{0,2,5}`。 このセットを生成した以前の除去の正確な順序は関係ありません。 その時点から、将来の確率は同じになります。 

つまり、状態は次のように圧縮できることになります。```
mask = set of alive fish
```これは直ちにサブセット DP を示唆します。 

定義する：```
dp[mask] = probability that exactly the fish in mask are alive
```すべての魚が確率で生きているフルセットから始めます。`1`。 

州から`mask`、すべての生きた魚の中から一律に1ペアを選択します。 1匹の魚が死ぬと、より小さなマスクが生成されます。 

各遷移はちょうど 1 つの魚を削除するため、状態のグラフは非周期的になります。 大きいマスクから小さいマスクまで加工可能です。 

サブセットの数は`2^n`、サブセットごとに、魚のペアを検査する場合があります。 と`n ≤ 18`、これは実現可能になります。

 | 最適なビットマスク DP | O(2^n · n²) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての生きているセットをビットマスクとして表現します。 

少し`i`は`1`魚なら`i`まだ生きています。 と`n ≤ 18`、状態全体が整数内に快適に収まります。 
2. DP 状態を定義します。 

させて：```
dp[mask]
```現在生きている魚がまさにその中の魚である確率`mask`。 
3. 開始状態を初期化します。 

最初はすべての魚は生きているので、次のようになります。```
full = (1 << n) - 1
dp[full] = 1
```4. マスクを大きなサブセットから小さなサブセットに処理します。 

すべての遷移で 1 つのフィッシュが削除されるため、確率は常にビットの少ないマスクに向かって流れます。 
5. 現在のマスクについて、生きている魚の数を数えます。 

仮定する`k`魚は生きています。 この場合、可能な会議ペアの数は次のようになります。$\frac{k(k-1)}{2}$すべてのペアは均一に選択されます。 
6. 順序付けられたすべてのペアを反復処理します。`(i, j)`生きた魚のどこに`i != j`。 

魚なら`i`魚を食べる`j`、次の状態は次のようになります。```
next_mask = mask ^ (1 << j)
```魚だから`j`死ぬ。 
7. 遷移確率を追加します。 

確率の寄与は次のとおりです。$dp[mask] \cdot \frac{a_{ij}}{\binom{k}{2}}$順序付けされていないすべてのペアが選択される可能性が等しいため、可能な会議の数で割ります。 
8. すべてのマスクが処理されるまで続行します。 

最終的に、すべてのシングルトン マスクは、より大きな状態すべてからその合計確率を受け取ります。 
9. 答えを抽出します。 

魚`i`最終状態が次の場合に正確に存続します。```
mask = (1 << i)
```なぜ効果があるのか:

 DP の不変条件は次のとおりです。```
dp[mask] = probability that the process ever reaches exactly this alive set
```プロセスはすべての魚が生きている状態で開始されるため、初期状態は正しいです。 すべての移行は、プロセスの 1 つの法的イベントをモデル化します。つまり、会議のペアを均一に選択し、その後、戦闘確率を適用します。 考えられる次のイベントはすべて 1 回だけ考慮されるため、確率質量は状態間で正しく転送されます。 遷移はフィッシュを削除するだけであるため、サイクルは存在せず、すべての状態は、その値がさらに使用される前に、すべての有効な先行状態からの寄与を蓄積します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [list(map(float, input().split())) for _ in range(n)]

    size = 1 << n
    dp = [0.0] * size

    full = size - 1
    dp[full] = 1.0

    for mask in range(full, 0, -1):
        alive = []

        for i in range(n):
            if mask & (1 << i):
                alive.append(i)

        k = len(alive)

        if k <= 1:
            continue

        pairs = k * (k - 1) / 2.0

        for i in alive:
            for j in alive:
                if i == j:
                    continue

                next_mask = mask ^ (1 << j)
                dp[next_mask] += dp[mask] * a[i][j] / pairs

    ans = []

    for i in range(n):
        ans.append(f"{dp[1 << i]:.6f}")

    print(*ans)

solve()
```DP 配列には、生きている魚のすべてのサブセットの確率が保存されます。 完全なマスクには最初は生きているすべての魚が含まれているため、その確率は次のようになります。`1`。 

外側のループはマスクを下方向に繰り返します。 トランジションでは常に 1 つのフィッシュが削除されるため、この順序は重要です。 より小さなマスクがより大きなマスクに戻ることはありません。 

各マスクについて、まず生きた魚を収集します。 これにより、ペアの反復が簡素化され、ビット チェックの繰り返しが回避されます。 

変数`pairs`生きている魚の間で可能な順序付けされていない会議の数を保存します。 これは、多くの間違った実装が見逃している正規化要素です。 この値で除算しないと、確率は正しく合計されません。 

ネストされたループは、順序付けされたペアを反復します。`(i, j)`。 これは意図的なものです。 各順序ペアは、1 つの特定の消去イベント (魚) に対応します。`i`魚を殺す`j`。 

移行:```
next_mask = mask ^ (1 << j)
```魚を取り除く`j`アライブセットより。 

答えに必要なのは浮動小数点精度だけで十分です。`1e-6`正確さ。

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
0
```最初のマスクにはすでに 1 匹の魚が含まれています。 DP は次のように始まります。```
dp[1] = 1
```遷移は発生しないため、`k <= 1`。 アルゴリズムは正しく出力します。```
1.000000
```ここで決定論的優位性を考えてみましょう。```
2
0 1
0 0
```初期状態:

 | マスク | 生きている | DP |
 | --- | --- | --- |
 | 11 | {0,1} | 1 |

 1ペアしかありません。 魚`0`魚を倒す`1`確率的に`1`。 

遷移:

 | から | へ | 確率 |
 | --- | --- | --- |
 | 11 | 01 | 1 |

 最終結果:```
1.000000 0.000000
```これにより、DP が浮動小数点の不安定性なしに厳密な確率を処理できることが検証されます。 

最後に、複数のパスが同じ状態にマージするケースを調べます。```
3
0 0.5 0.5
0.5 0 0.5
0.5 0.5 0
```マスク`{0,1}`魚でも到達可能`0`殺す`2`または魚`1`殺す`2`。 DP は両方の寄与を同じ状態値に加算します。 

トレース:

 | 移行 | マスク011への貢献 |
 | --- | --- |
 | 0 キル 2 | 1/6 |
 | 1 キル 2 | 1/6 |

 合計：```
dp[011] = 1/3
```この蓄積こそが、ここでサブセット DP が機能する理由です。 異なる除去履歴は、同じ将来の状態に崩壊します。
