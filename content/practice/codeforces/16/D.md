 ## 解決策
 ## 問題の理解

 書き込まれた正確な順序で一連のログ エントリが提供されます。 元々はすべてのエントリに日付と時刻の両方が含まれていましたが、日付が失われてしまったため、12 時間時計のタイムスタンプのみが残っています。 

タスクは、エントリを時系列順に保ちながら、特定のシーケンスを生成できる最小の個別の日を再構築することです。 

厄介な点は、時系列順はタイムスタンプ文字列ごとではなくグローバルであるということです。 1 つのログ行が次々に表示される場合、その実際の時点は前の時点以上である必要があります。 同じ分間に複数のメッセージが発生する可能性があり、ステートメントでは 1 分あたり最大 10 エントリが保証されるため、等しいタイムスタンプが許可されます。 

タイムスタンプは 12 時間形式を使用します。 

-`12:00 a.m.`真夜中です。 
-`12:00 p.m.`正午です。 
-`01:00 p.m.`24 時間表示では 13:00 です。 

制約はわずかです。 対数行は最大 100 なので、二次解法でも十分に高速です。 問題はパフォーマンスではなく、時間の変換と日の推移を正しく処理することです。 

よくある間違いは、時間という特別な役割を誤って扱うことです`12`。 

例えば：```
[12:00 a.m.]
[01:00 a.m.]
```真夜中になるはずだ`00:00`、 ない`12:00`。 

もう 1 つの簡単なバグは、厳密に時間を増やす必要があると仮定することです。 同じ 1 分間に複数のエントリが発生する可能性があるため、等しい時間が有効です。 

例：```
[05:00 a.m.]
[05:00 a.m.]
```答えはまだです`1`。 

より微妙なエッジ ケースは、時計が逆方向に進むが、24 時間表記の真夜中を越えない場合に現れます。 

例：```
[01:13 p.m.]
[01:10 p.m.]
```24 時間換算すると次のようになります。```
13:13
13:10
```時間が減少したため、2 回目のエントリーは同日に行うことはできません。 ここから新しい一日を始めなければなりません。 

もう 1 つの危険なケースは、正午の移行です。 

例：```
[11:59 a.m.]
[12:00 p.m.]
```これが増えている理由は、`11:59 -> 12:00`。 

しかし：```
[12:00 p.m.]
[11:59 a.m.]
```新しい一日を始めなければならないので、`12:00 -> 11:59`減少します。 

問題全体は 1 つの質問に集約されます。ログを順番にスキャンしているときに、何回次の日に移動する必要があるでしょうか?

 ## アプローチ

 最も直接的な強引なアイデアは、すべてのログ エントリに日番号を割り当て、完全なシーケンスが時系列になっているかどうかを確認することです。 理論的には、各エントリが多くの異なる日に属する可能性があるため、これは多くの割り当てを検索することになります。 

あらゆる可能性を試してみると、状態空間は爆発してしまいます。 エントリごとに選択肢が 2 つしかない場合でも、すでに次の結果が得られます。`2^100`、それは絶望的です。 

ブルー フォースが自然であると感じる理由は、この問題が欠落した日付の再構築について述べているからです。 日付を明示的に推測する必要があるようです。 しかし、時系列条件はもっと単純な構造を持っています。 

すべてのタイムスタンプを午前 0 時からの分に変換するとします。 その後、各エントリは次の範囲の単なる整数になります。`0`そして`1439`。 

ここで、2 つの連続するエントリを考えてみましょう。 

- 現在の時刻が前回の時刻以上である場合、それらは同じ日に属する可能性があります。 
- 現在時刻が小さい場合は、ここで日を増やす必要があります。 

その決定には自由はありません。 時間が減少すると新しい日が強制されますが、最小日数が必要なため、減少しない場合は新しい日を開始するメリットはありません。 

この観察により、問題は 1 つの線形スキャンに集約されます。 

すべてのタイムスタンプを 24 時間分に変換し、シーケンスが何回減少するかを数えます。 答えは次のとおりです。```
1 + number_of_decreases
```最初のログエントリは常に初日から始まるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのログ行を読み取ります。 
2. 各行からタイムスタンプを抽出します。 

タイムスタンプは常に角括弧内に表示されるため、必要なのは前にある部分文字列のみです。`]`。 
3. 12 時間形式を 24 時間形式に変換します。 

のために`a.m.`:

 -`12:x a.m.`時間になる`0`。 
- その他の時間は変更されません。 

のために`p.m.`:

 -`12:x p.m.`滞在します`12`。 
- それ以外の時間は追加されます`12`。 

次に、次のように計算します。```
total_minutes = hour * 60 + minute
```4. 答えを次のように初期化します。`1`。 

ログ エントリ 1 つでも 1 日かかります。 
5. 連続するタイムスタンプをスキャンします。 

現在のタイムスタンプが前のタイムスタンプより小さい場合、同じ日の時系列順は不可能になるため、新しい日を開始する必要があります。 

答えを増やす`1`。 
6. 答えを印刷します。 

### なぜ効果があるのか

 このアルゴリズムは、ログのすべてのプレフィックスに対して可能な限り最小の日の割り当てを維持します。 

時間が減少するたびに、同じ日を維持すると、すぐに時系列に違反します。 新しい一日を始めることは必須です。 

時間が減らないときはいつでも、同じ日を続けることは常に有効であり、新しい日を作り出すことより悪いことはありません。 最小限の日数が必要なので、不要な日を追加してもどうにもなりません。 

すべての遷移は最適かつ独立して処理されるため、最終的なカウントは最小限で済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_minutes(s):
    parts = s.split()

    hm = parts[0]
    period = parts[1]

    h, m = map(int, hm.split(':'))

    if period == 'a.m.':
        if h == 12:
            h = 0
    else:
        if h != 12:
            h += 12

    return h * 60 + m

def solve():
    n = int(input())

    times = []

    for _ in range(n):
        line = input().strip()

        end = line.index(']')
        time_str = line[1:end]

        times.append(to_minutes(time_str))

    days = 1

    for i in range(1, n):
        if times[i] < times[i - 1]:
            days += 1

    print(days)

solve()
```最初の重要な部分は、12 時間制から 24 時間制への変換です。 時間の特別な扱い`12`ここでの難しさはすべてです。 

真夜中の場合:```
12:xx a.m. -> 00:xx
```正午の場合:```
12:xx p.m. -> 12:xx
```1つおき`p.m.`時間の増加`12`。 

パーサーは括弧内の部分文字列のみを抽出します。 このメッセージは年代には影響しないため、完全に無視します。 

スキャン自体は簡単です。 各タイムスタンプを前のタイムスタンプと比較します。 時間が逆方向に進むと、現在のエントリが同じ日に属することはできないため、日カウンターをインクリメントします。 

比較は厳密に行う必要があります`<`、 ない`<=`。 同一のタイムスタンプは同じ日に有効です。

 | 測定 | 複雑さ | 説明 |

ログ エントリが最大 100 件の場合、アルゴリズムは制限をはるかに下回ります。 二次解法でも問題なく通過できますが、線形スキャンの方がよりクリーンでシンプルです。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    def to_minutes(s):
        parts = s.split()

        hm = parts[0]
        period = parts[1]

        h, m = map(int, hm.split(':'))

        if period == 'a.m.':
            if h == 12:
                h = 0
        else:
            if h != 12:
                h += 12

        return h * 60 + m

    n = int(input())

    times = []

    for _ in range(n):
        line = input().strip()
        end = line.index(']')
        time_str = line[1:end]
        times.append(to_minutes(time_str))

    ans = 1

    for i in range(1, n):
        if times[i] < times[i - 1]:
            ans += 1

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run(
"""5
[05:00 a.m.]: Server is started
[05:00 a.m.]: Rescan initialized
[01:13 p.m.]: Request processed
[01:10 p.m.]: Request processed
[11:40 p.m.]: Rescan completed
"""
) == "2", "sample 1"

# minimum size
assert run(
"""1
[12:00 a.m.]: A
"""
) == "1", "single entry"

# equal timestamps
assert run(
"""3
[05:00 a.m.]: A
[05:00 a.m.]: B
[05:00 a.m.]: C
"""
) == "1", "equal times stay same day"

# midnight rollover
assert run(
"""2
[11:59 p.m.]: A
[12:00 a.m.]: B
"""
) == "2", "crossing midnight"

# noon handling
assert run(
"""2
[11:59 a.m.]: A
[12:00 p.m.]: B
"""
) == "1", "noon conversion"

# decreasing multiple times
assert run(
"""5
[10:00 a.m.]: A
[09:00 a.m.]: B
[08:00 a.m.]: C
[07:00 a.m.]: D
[06:00 a.m.]: E
"""
) == "5", "every step starts new day"
```| テスト入力 | 期待される出力 | 検証内容 |

## 特殊なケース

 繰り返されるタイムスタンプを考慮してください。```
3
[05:00 a.m.]: A
[05:00 a.m.]: B
[05:00 a.m.]: C
```変換されたシーケンスは次のとおりです。```
300, 300, 300
```このアルゴリズムは、現在の値が前の値よりも厳密に小さい場合にのみ新しい日を開始します。 平等は許されるので答えは変わらない`1`。 

ここで深夜の対応を考えてみましょう。```
2
[11:59 p.m.]: A
[12:00 a.m.]: B
```変換は次のようになります。```
1439, 0
```以来`0 < 1439`、アルゴリズムは新しい日を開始し、出力します。`2`。 

午前 0 時が誤って時間として扱われる場合、このケースは失敗します。`12`。 

もう 1 つの微妙なケースは正午です。```
2
[11:59 a.m.]: A
[12:00 p.m.]: B
```変換は次のようになります。```
719, 720
```数列が増えていくので、答えは`1`。 

もし`12:00 p.m.`に誤って変換されました`24:00`、ロジックが破綻してしまいます。 

最後に、複数の強制リセットを考慮します。```
4
[03:00 p.m.]: A
[02:00 p.m.]: B
[01:00 p.m.]: C
[12:00 p.m.]: D
```変換されたシーケンス:```
900, 840, 780, 720
```すべてのステップは減少するため、すべてのステップには新しい日が必要です。 アルゴリズムの出力`4`、2 つの連続するエントリが 1 日を共有できないため、これは最小限です。
