 ## 解決策
 ## 問題の理解

 私たちには、すべての操作が非常に具体的な方法で構造を変更するツリーが与えられています。 1 つのタイプの操作では、新しい頂点を挿入し、それを 1 つの既存の頂点に接続し、効果的に新しいリーフを作成します。 もう 1 つのタイプは、エッジを 2 つの端点とともに削除しますが、これは一方の端点が現在リーフであり、もう一方の端点の次数がその時点で最大 2 である場合に限られます。 

このプロセスは頂点がなくなるまで続行され、両方のタイプを組み合わせた操作の合計数を最小限に抑えることが目標となります。 

入力は、n 個のノード上の単一のツリーです。 出力は、許可されている 2 つの操作を使用してすべてのノードを完全に消去するために必要な操作の最小数です。 

n が 2 · 10^5 までの制約により、プロセスをシミュレートしようとしたり、エッジのサブセットを明示的に考慮したりしようとするソリューションは即座に除外されます。 実行可能なアプローチはいずれも、ツリーのサイズが線形またはほぼ線形である必要があり、通常は O(n) または O(n log n) です。 これは、答えが木の構造的特性、おそらく動的計画法から得られるに違いないことをすでに示唆しています。 

欲張って考えると微妙な問題が見えてきます。 有効なエッジをできるだけ早く削除することを繰り返したくなりますが、これにより構成内の高次の頂点がトラップされて一時的に使用できなくなり、後で不要な挿入操作が強制される可能性があります。 たとえば、星形のツリーでは、計画せずに任意に葉を削除すると、中央の頂点に依存関係が多すぎる状態が残り、解決するために人工の頂点が必要になる可能性があります。 

もう 1 つの失敗例は、道のような木から発生します。 最初に使用可能な葉と親のペアを常に削除すると、残った単一の頂点が孤立してしまう可能性があり、新しい頂点を挿入しないと削除できません。 これは、ローカルの貪欲ペアリングがプロセスのグローバル構造を捉えていないことを示しています。 

## アプローチ

 ブルートフォースのアイデアは、すべての有効な操作シーケンスをシミュレートすることです。 各ステップで、端点が削除条件を満たすエッジを検索し、削除を試み、すべての可能性を再帰的に探索します。同時に、スタックした場合に頂点を挿入する場所についても分岐します。 これはプロセスを正しくモデル化しますが、各削除によって度合いが変化し、新しい選択肢が作成され、挿入操作によって状態空間がさらに拡張されるため、すぐに指数関数的になります。 

重要な点は、削除操作では常に正確に 2 つの頂点が削除され、基本的に隣接するノードのペアが消費されていることです。 中間次数制約を無視し、最終的に一緒に削除される端点に焦点を当てると、すべての削除は、プロセスのある段階で 2 つの端点がペアになるように、元のツリーのエッジを選択することに対応します。 

これにより、問題はエッジに沿った元の頂点のペアに再構成されますが、各頂点は削除操作から得られるこのようなペアの 1 つまでに参加できるという制約があります。 残ったノードは新しく作成されたリーフとペアにすることによってのみ削除できるため、そのようなペアリングでカバーされない頂点は、挿入された頂点を使用して処理する必要があります。 

したがって、必要な構造はツリー上の最大の一致です。 一致する各エッジは、元の 2 つの頂点を削除する 1 つの削除操作に対応します。 一致しない頂点ごとに、補助頂点の導入と、両方を削除するための追加操作が強制されます。 

M がツリー内の最大一致のサイズである場合、2M 個の頂点が M 個の操作で直接削除されます。 残りの n − 2M 頂点はそれぞれ 1 つの挿入頂点を必要とし、そのような各頂点は 1 つの追加の削除操作に寄与します。 これにより、合計 n − M 回の操作が行われます。 

したがって、問題は完全に、古典的なツリー動的プログラミング タスクであるツリー内の最大一致を計算することに帰着します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | 指数 | 遅すぎる |
 | 最大マッチングのためのツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ルート動的プログラミングを使用して、ツリー内の最大一致を計算します。 

1. 任意のノード (ノード 1 など) でツリーをルート化し、親子構造を定義します。 
2. 各ノード u について、2 つの値を維持します。 1 つ目は、u がその親に対して上向きに一致することを強制されない場合に、u のサブツリー内で最も一致するサイズを表します。 2 番目の値は、u がすでにその親と一致している場合の最適な一致サイズを表します。つまり、u はその子との一致には使用できません。 
3. ノードのすべての子がノード自体の前に計算されるように、ポストオーダー トラバーサルでノードを処理します。 
4. ノード u について、すべての子 v について、v が最適な内部一致を自由に選択できる値を合計することによって、u がその親とすでに一致している状態を計算します。 これは、v が u または上記のものと一致できないためです。 
5. u が上方に一致していない状態については、すべての子が自由状態にある同じベースラインから開始します。 次に、u を 1 つの子 v と一致させることを検討します。u が v と一致する場合、v は u へのエッジを使用できないため、v は「親に一致」状態に切り替える必要がありますが、他のすべての子は自由状態のままです。 私たちは、すべての子どもたちに対してそのような最善の選択をします。 
6. ツリー全体の最大一致サイズは、「親と一致しない」状態のルートに対して計算された値です。 
7. 最終的な答えは、n からこの最大一致値を引いたものになります。 

重要な構造上の考え方は、ノードが 1 つの隣接ノードと一致すると、そのノードは他の一致には参加できないということです。これにより、各ノードでの決定は、どの子とペアにするか (存在する場合) についてローカルに選択されます。 

### なぜ効果があるのか

 DP では、マッチング内のすべてのエッジが 1 回だけ選択され、複数のマッチングされたエッジで頂点が使用されないことが強制されます。 ツリー内の一致はすべて、この親子構造に従って分解できるため、すべての有効なグローバル一致は 1 つの有効な DP 構成に正確に対応します。 ノードが一致する子を最大 1 つ選択する遷移では、一致の排他性制約が捕捉されますが、「親に一致」状態によりツリーの上向きの一貫性が確保されます。 有効なマッチングと DP 状態の間のこの全単射により、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

parent = [-1] * n
order = []
stack = [0]
parent[0] = -2

while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

dp0 = [0] * n
dp1 = [0] * n

for u in reversed(order):
    base = 0
    for v in g[u]:
        if v == parent[u]:
            continue
        base += dp0[v]

    dp1[u] = base

    best = base
    for v in g[u]:
        if v == parent[u]:
            continue
        cand = base - dp0[v] + dp1[v] + 1
        if cand > best:
            best = cand

    dp0[u] = best

ans_matching = dp0[0]
print(n - ans_matching)
```コードは最初に反復 DFS を使用してツリーのルート表現を構築するため、再帰の深さが問題になりません。 配列 dp0 および dp1 は、前述の 2 つの DP 状態を実装します。 dp1 は、ノードがすでにその親と一致している場合に対応するため、子からの寄与のみを独立して蓄積できます。 dp0 を使用すると、選択した 1 つの子とノードを一致させる追加の可能性が可能になります。これは、その子の無料の寄与を一時的に削除し、一致した構成と 1 つのエッジで置き換えることによって実装されます。 

最後の減算 n − M は、最大一致サイズを必要な操作の数に直接変換します。 

## 実用的な例

 4 つのノード (1-2-3-4) からなる小さなパス状のツリーを考えてみましょう。 

| ノード | dp1 (親と一致) | dp0 (内部最高) |
 | --- | --- | --- |
 | 4 | 0 | 0 |
 | 3 | 0 | 1 |
 | 2 | 1 | 1 |
 | 1 | 1 | 2 |

 ルート値 dp0(1) は 2 に等しく、最大のマッチングには 2 つのエッジが使用されることを意味します。 答えは 4 − 2 = 2 回の演算になります。 これは (1,2) と (3,4) のペアに対応し、それぞれの削除により 2 つのノードが直接削除されます。 

次に、中心 1 が 2、3、4 に接続された星形のツリーを考えます。 

| ノード | dp1 | dp0 |
 | --- | --- | --- |
 | 2,3,4 | 0 | 0 |
 | 1 | 0 | 1 |

 中心とペアにできるリーフは 1 つだけであるため、最大一致は 1 です。 答えは 4 − 1 = 3 回の演算です。 1 つのペアを削除すると 2 つのリーフが残るため、挿入ベースのペアリングが必要となり、追加の操作が必要になります。 

これらの例は、各ノードが最大 1 つの一致するエッジに参加することを考慮しながら、dp0 がどのようにして可能な限り最良のペアリング構造をキャプチャするかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各エッジは DP 遷移で一定の回数処理されます。 
| スペース | O(n) | 隣接関係リスト、親配列、および DP 状態のストレージ |

 このアルゴリズムはノード数において線形であり、2 · 10^5 の制約内に快適に適合します。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = [0]
    parent[0] = -2
    stack = [0]
    order = []

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp0 = [0] * n
    dp1 = [0] * n

    for u in reversed(order):
        base = 0
        for v in g[u]:
            if v == parent[u]:
                continue
            base += dp0[v]

        dp1[u] = base

        best = base
        for v in g[u]:
            if v == parent[u]:
                continue
            best = max(best, base - dp0[v] + dp1[v] + 1)

        dp0[u] = best

    return str(n - dp0[0])

 ## 特殊なケース

 単一の孤立したノードでは、削除が不可能であり、最終的な削除を可能にするために 1 回の挿入が必要であるため、一致しない頂点を処理する必要性が生じます。 

星型ツリーは、高度な中心を中心としたペアリングの制限を示しています。つまり、1 つのエッジのみが一致に属することができ、ほとんどの頂点を補助操作で処理する必要があります。 

長いパスは、最適な戦略がチェーンに沿ってペアリングを交互に行い、パリティのみが残りの動作を決定するほぼ完全なマッチングを達成していることを示しています。
