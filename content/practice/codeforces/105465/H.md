 ## 解決策
 ## 問題の理解

 塔を表す一連の位置が与えられ、各位置について、その塔が「見える」または通信できる他の塔の数が示されます。 

2 つのタワー間に、両方のエンドポイントより厳密に上位にタワーがない場合、2 つのタワーは通信できます。 言い換えれば、それらの間のセグメントに注目すると、中間のタワーが両方のタワーよりも高い場合にのみ通信がブロックされます。 少なくとも 1 つのエンドポイントがその間のすべてのエンドポイントよりも高い場合、ペアは接続されています。 

タスクは、これらの関係を数えることではなく、各位置に必要な数の目に見えるタワーが正確に存在するように、タワーの高さの割り当てを構築することです。 

出力は、それぞれ 1 ～ 10^9 の一連の高さです。 複数の解決策が存在する可能性があり、有効な解決策であればどれでも受け入れられます。 

制約は最大 5 · 10^5 のタワーにまで及ぶため、どのソリューションも本質的に線形または線形に近いものでなければなりません。 すべてのペアのチェックや、すべてのペアごとの可視性の明示的な維持に関係するものは、最悪の場合、二次関数の動作を意味するため、すぐに制限を超えてしまいます。 

微妙な問題は、可視性が単純な方法ではローカルではないことです。 単一の高さを変更すると、セグメント内の最大ブロッキングになるかどうかに影響するため、長距離にわたる通信が変化する可能性があります。 

よくある故障モードの 1 つは、各タワーの次数が隣接する構造または最も近いより大きな要素にのみ依存しているかのように問題を扱うことです。 たとえば、単調スタックが直接エンコードすると仮定すると、可視性は次のより大きな関係だけでなくエンドポイント間の大域的な最大値に依存するため、答えは機能しません。 

もう 1 つの落とし穴は、グラフが素朴な意味で区間のようなものであると仮定することです。 タワーは、高さがどのように分散されているかに応じて、複数の分離された領域にまたがって接続できるため、グローバル セグメンテーションを制御せずに貪欲にローカルに割り当てると、一貫性が損なわれる傾向があります。 

## アプローチ

 直接的な強引なアプローチでは、高さを割り当ててから、塔のペアごとに可視性のカウントを計算しようとします。 これには、すべてのペア i と j をチェックし、ペアごとに O(n) である最大値を見つけるためにそれらの間の間隔をスキャンする必要があります。 これは、単純に実行した場合は合計で O(n^3) になり、間隔の最大値が前処理された場合はせいぜい O(n^2) になります。 O(n^2) でさえ、5 · 10^5 までの n の制限をはるかに超えています。 

重要な構造的観察は、可視性がセグメント内の最大値によって決まるということです。 これは、どのタワーが「支配的なブロッカー」として機能するかという概念を固定すると、アレイは自然に、それらのブロッカーが独立した動作を定義する領域に分割されることを意味します。 

最終的な構成について考えるのに役立つ方法は、より高い高さのタワーがセパレーターとして機能するということです。 より高いタワーによって分離された異なる領域にある 2 つのタワーは、その分離部分が両方の端点よりも高い場合、その分離部分を「透視」できません。 したがって、より高い塔はラインを独立したセグメントに分割します。 

ここで、最も強いタワーから順に構成を構築することを検討してください。 高さを降順に割り当てると、新しいタワーを配置するときに、すでに配置されているすべてのタワーが厳密に高くなり、永続的なセパレータとして動作します。 残りの未配置の位置は、まだ構造を作成していない下位要素の連続したプールとして動作します。 

いつでも、より高く配置された塔がラインをセグメントに分割します。 各セグメント内では、残りのすべてのタワーは現在同等のプレースホルダーであり、後で低くなる予定です。 重要な特性は、タワーがセグメントに配置されると、そのセグメント内のすべてのタワーは最終的に上位の要素によって作成された境界よりも低くなるため、将来の可視性カウントは正確にそのセグメントのサイズから 1 を引いたものになるということです。

これにより、セグメント サイズの制御の問題が軽減されます。 要件 a_i を持つ各タワーは、最終的には正確に a_i + 1 の位置を含むセグメント内に配置される必要があります。これは、そのようなセグメント内では、そのセグメント内の他のすべての a_i 位置に接続され、追加の可視性が追加される方法でそのセグメントの外側の位置には接続されないためです。 

したがって、構築は、適切なサイズの空きセグメントを繰り返し選択し、それにタワーを割り当て、配置されたタワーの周囲でセグメントを分割することで将来の利用可能性からそのセグメントを削除するプロセスになります。 

これを一貫させるための貪欲な順序は、a_i を減少させながらタワーを処理することです。これは、より大きな可視性要件は、より強力なセパレータとして先に配置する必要があるタワーに対応するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース可視性計算 | O(n^2) から O(n^3) | O(n) | 遅すぎる |
 | セグメントベースの建設的な配置 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在利用可能なポジションのセットを連続した空きセグメントとして維持します。 各セグメントには長さがあり、長さが必要な値と一致するセグメントをすばやく見つけることができる必要があります。 

また、必要な可視性の高い順にタワーを割り当てます。 

1. すべてのインデックスを a_i で降順に並べ替えます。 必要な可視性が最も高いタワーから順にタワーを配置します。 
2. 現在の空き領域をセグメントの構造として維持します。 最初は、長さ n の単一セグメントがあります。 
3. ソートされた順序で各タワーについて、その要件 k = a_i を取得します。 長さ k + 1 の自由位置のセグメントが必要です。 
4. 長さがちょうど k + 1 であるセグメントを見つけます。複数存在する場合、問題は解決可能であることが保証されているため、どの選択も有効です。 
5. そのセグメント内で、現在のタワーを任意の位置 (通常は左端または中央の位置) に配置します。 この配置により、セグメントが 2 つの小さなセグメントに分割され、後のタワーでも使用できるようになります。 
6. このタワーに処理順序と同じ高さを割り当て、先に処理されたタワーに高い値を与え、後のステップのセパレータとして機能するようにします。 

これが機能する理由は、タワーがサイズ k + 1 のセグメントに配置されると、そのセグメント内に収まる残りのすべてのタワーの高さが低くなるためです。 同じ最終セグメント内の 2 つのタワーは、すべての中間最大値がセグメント境界によって制御され、配置されたタワーに対して正確に k 個の可視接続が確保されます。 

### なぜ効果があるのか

 この構造により、各ステップで、既に配置されたタワーが未配置のタワーよりも厳密に高くなることが保証されるため、可視性の拡大の観点から将来のタワーが越えることのできないセグメント境界が永続的に定義されます。 新たに配置された各タワーは、必要な可視性とそれ自体に一致するサイズのセグメントを完全に占有します。 そのセグメント内にはより高いタワーは存在せず、その内側の将来のタワーはすべてより低いため、セグメント内の他のすべてのタワーはそのタワーの視点から 1 回だけ表示されます。また、より高いセパレータが要件に違反する外部接続をブロックするため、セグメントの外側に追加の可視性は作成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: -a[i])

    segs = [(0, n)]  # intervals [l, r)
    res = [0] * n
    cur_height = n

    def find_segment(k):
        for i, (l, r) in enumerate(segs):
            if r - l == k:
                return i
        return -1

    for i in order:
        k = a[i] + 1
        idx = find_segment(k)

        l, r = segs.pop(idx)
        mid = l  # place at leftmost

        res[i] = cur_height
        cur_height -= 1

        if mid - l > 0:
            segs.append((l, mid))
        if r - (mid + 1) > 0:
            segs.append((mid + 1, r))

    print(*res)

if __name__ == "__main__":
    solve()
```このコードでは、最初に要件を減らしてタワーに順序を付け、より強力な制約が早期に解決されるようにします。 空きセグメントのリストを保持し、必要なブロック サイズと一致するサイズのセグメントを繰り返し選択します。 

各割り当てでは、セグメントから 1 つの位置が削除され、セグメントが最大 2 つの小さなセグメントに分割されます。 高さは降順で割り当てられるため、以前の配置が後の配置のグローバル セパレータとして動作します。 

重要な実装の詳細は、セグメントの選択が任意のセグメントではなく、正確なサイズと一致する必要があることです。 これにより、各タワーは、最終的な可視性がローカル構造によって正確に決定される領域に埋め込まれることが保証されます。 

## 実用的な例

 n = 5、a = [2, 0, 2, 0, 0] の小さな概念的な例を考えてみましょう。 インデックスを a で並べ替え、値 2 のインデックスを最初に与えます。 

最初のセグメントは [0, 5) です。 要件 2 の最初のタワーにサイズ 3 のセグメントを選択します。セグメントを [0, 3) 内の位置 0 に配置し、[1, 3) に分割し、他のセグメントはそのまま残すとします。 

| ステップ | タワー | 選択されたセグメント | 配置 | 残りのセグメント |
 | --- | --- | --- | --- | --- |
 | 1 | a=2 のインデックス | [0,3) | 位置 0 | [1,3)、[3,5) |
 | 2 | 次の a=2 または 0 | 適切なセグメント | 割り当てられた | 更新された分割 |
 | 3 | 残り | 些細なセグメント | 割り当てられた | 最終 |

 これは、要件の高い各タワーが、可視性ターゲットに 1 を加えたサイズと正確に一致するセグメントをどのように消費するかを示しています。 

ここで、n = 4、a = [1, 1, 0, 0] について考えてみましょう。 最初の 2 つのタワーはサイズ 2 のセグメントを占有し、それぞれが最終的に他の 1 つのタワーを正確に認識できるようにする必要があります。 残りの 2 つはシングルトンを占有するため、当然のことながら可視性はゼロになります。 

トレースは、セグメント サイズが次数を直接強制することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) 最悪の場合の単純なセグメント検索、適切な構造の場合は O(n log n) | ソートとセグメント管理が主流 |
 | スペース | O(n) | セグメントと結果の配列を格納する |

 バランス セグメント ツリーまたは順序セットを使用すると、セグメント ルックアップを O(log n) に減らすことができ、最大 5 · 10^5 の n に対してソリューションを効率的にすることができます。

 ## 特殊なケース

 両方の a_i = 0 を伴う n = 2 のような最小限のケースでは、アルゴリズムが不必要な可視性を強制することなく 2 つの分離されたタワーを割り当てることができることを確認します。 この構造では、それぞれがサイズ 1 のセグメントに配置され、接続は生成されません。 

すべての a_i が等しい完全対称の場合、アルゴリズムは同じサイズのセグメントを一貫して分散するように強制されます。 セグメントの分割では常に全体の長さが維持されるため、各配置では矛盾なく有効なセグメントが検索され続けます。 

1 つのタワーに n - 1 に近い大きな a_i がある場合、最初の配置でアレイ セグメント全体が確実に消費されます。これは、最も支配的なタワーを最初に配置することに対応します。 これにより、小さい要件を最初に指定すると、唯一の有効なグローバル セグメントが破壊されるため、降順での処理が不可欠であることが確認されます。
