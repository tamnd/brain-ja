 ## 解決策
 ## 問題の理解

 2 つのシーケンスが与えられ、それぞれがスタックのように動作し、最後の要素のみにアクセスできます。 1 から k までのすべての値は両方のシーケンスにわたって正確に 2 回出現するため、各数値は 2 つのスタック間に散在する出現の 1 つのペアを正確に形成します。 

2 人のプレイヤーが交互に動きます。 各ターンで、現在のプレイヤーは 2 つのスタックのうち 1 つを選択し、その最後の要素を削除します。 このプロセスは両方のスタックが空になるまで継続されるため、最終的にはすべての要素が削除された順序で 1 人のプレイヤーにのみ割り当てられます。 

2 番目のプレーヤーの成功条件はゲーム全体にわたってグローバルです。一連の動きの後、取ったすべての値がコレクションに最大 1 回出現する必要があります。 何らかの値の両方の出現を受け取った場合、即座に条件に違反し、最初のプレイヤーが勝ちます。 2 番目のプレーヤーがすべての値でこれを回避できた場合、2 番目のプレーヤーが勝ちます。 

重要な問題は、どちらのプレイヤーも任意の要素を選択していないことです。 これらは常に 2 つの固定シーケンスの現在の端から選択するように制約されており、どのスタックからポップするかの選択によって、将来の等しい値間の競合がどのように展開するかが決まります。 

この制約は、テスト全体で最大 10^6 までの線形の合計サイズを意味するため、どの解もテストごとに本質的に線形または線形に近いものでなければなりません。 完全なゲーム ツリーをシミュレートしたり、両方の選択肢を貪欲に探索したりする戦略は、直ちに不可能です。これは、それぞれの手が合計で最大 10^6 のステップにわたって 2 つの選択肢に分岐するためです。 

値の出現が配列間で分割される場合、微妙なエッジ ケースが発生します。 たとえば、値 x が各配列に 1 回出現する場合、インターリーブに応じて、2 番目のプレーヤーは両方の出現を選択することを強制される可能性があります。 一方、両方の出現が 1 つの配列内にある場合、それらの相対順序は固定されており、推論が容易になりますが、インターリーブ選択を通じて他の配列と対話します。 

単純なアプローチでは、両方の配列のサフィックスに対するミニマックスまたは動的プログラミングを使用して最適なプレイをシミュレートしようとします。 これは、状態が 2 つのシーケンスへの 2 つのポインターであるため失敗し、最悪の場合は O(nm) 状態になります。 

## アプローチ

 強引なアイデアは、ゲームの状態を各配列に残っている要素の数を表すインデックス (i, j) のペアとしてモデル化し、どのスタックから取得するかを再帰的に決定することです。 各状態は、誰のターンであるか、および 2 番目のプレーヤーがすでに取得した値のマルチセットによって異なります。 2 番目のプレーヤーがどの値を取得したかを追跡するには、k 値にわたるビットマスクが必要であり、指数関数的な状態空間が生じるため、これはすぐに手に負えなくなります。 マスクがなくても、2 ポインタ ゲームだけでも O(nm) 個の状態があります。 

構造の簡素化は、プレイヤーから視点を移し、最終的な除去シーケンスに視点を移すことで実現します。 常に最後から削除するため、すべての有効な再生は逆配列のインターリーブに対応します。 したがって、最終的な順序は、それぞれの内部順序を維持しながら、2 つの固定シーケンスをシャッフルしたものになります。 

ここで、1 つの値 x だけに注目します。 このインターリーブ順序のどこかにちょうど 2 回現れます。 2 番目のプレーヤーは、両方の出現が自分に割り当てられた位置に着いた場合、直ちに負けます。 したがって、すべての値について、最初のプレイヤーが少なくとも 1 つの出現を取得する必要があります。 

これにより、ゲームはインターリーブに関するグローバル制約充足問題に変わります。最初のプレーヤーは、ある値の 2 つの出現が両方とも 2 番目のプレーヤーに割り当てられる状況を強制しようとしますが、2 番目のプレーヤーはこれを回避しようとします。

重要な観察は、決定は各配列内で隣接する値間の境界でのみ重要であるということです。 各配列は、そのサフィックスをどのように使用する必要があるかに関する制約を引き起こします。これらの制約は、値間の隣接関係を通じてのみ伝播されます。 これにより、問題が値のグラフに縮小されます。エッジは、2 つのスタックの隣接関係によって引き起こされる強制的な順序付けの相互作用をエンコードします。 このように見ると、ゲームの結果はこのグラフの構造、具体的には最初のプレイヤーが 2 番目のプレイヤーに義務のサイクルを強制できるような対立構造が含まれているかどうかだけによって決まります。 この問題では、その条件は単純な接続ベースの基準に崩壊します。この基準は、隣接構造を追跡し、誘導された制約グラフに矛盾サイクルが含まれているかどうかを検証することで線形時間でチェックできます。

 ## アルゴリズムのチュートリアル

 2 つのスタックを値に対する単一の制約構造に圧縮します。 

いずれかの配列に 2 つの連続する要素が出現するたびに、そのスタックが繰り返し選択される有効なプレイでは相対的な削除順序が固定されるため、それをそれらの値の間の直接の依存関係として扱います。 両方の配列のすべての隣接するペアの間にエッジを追加して、値 1 ～ k にわたる無向グラフを構築します。 

このグラフが構築されたら、その接続コンポーネントを分析します。 接続されたコンポーネント内では、すべての値が強制的な隣接チェーンを通じてリンクされます。これは、プレーヤー間でそれらの出現を分離できる順序がグローバルに絡み合っていることを意味します。 

各コンポーネントに、あるプレイヤーが何らかの値の両方の出現を必然的に取得することを強制する構造的な矛盾が含まれているかどうかを計算します。 これは、オカレンスの割り当てにおいて避けられないパリティの競合を引き起こすサイクルがコンポーネントにあるかどうかをチェックすることになります。 この問題では、その条件はすべてのコンポーネントがツリーであるかどうかをチェックすることを単純化します。 いずれかのコンポーネントにノードから 1 を引いた数より多くのエッジが含まれている場合、最初のプレーヤーは矛盾を強制できます。 

1. 値を表す k 個のノードを含むグラフを構築します。 
2. 配列ごとに、その配列内の連続する要素の間にエッジを追加します。 
3. エッジの数を追跡し、素集合結合構造を使用して端点を結合します。 
4. 接続されたコンポーネントごとに、それに含まれるエッジの数と、それにまたがるノードの数を数えます。 
5. いずれかのコンポーネントがエッジ ≥ ノードを満たす場合、最初のプレーヤーが強制的に勝利できると宣言します。 
6. それ以外の場合、2 番目のプレーヤーはいつでも繰り返しを回避できるため、2 番目のプレーヤーが勝ちます。 

これが機能する理由は、すべての隣接制約により、プレーヤー間でオカレンスを分割する方法の自由度が低下するという事実から来ています。 ツリー状の制約構造により、各値の 2 つの出現が 2 番目のプレーヤーでの重複を避ける方法でプレーヤー間で分離され、一貫した割り当てが常に可能になります。 サイクルが出現した瞬間に、制約はループに近づき、どの戦略下でも値が強制的に「二重割り当て」され、最初のプレイヤーに強制的な勝利条件が与えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.edges = [0] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            self.edges[ra] += 1
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.edges[ra] += self.edges[rb] + 1

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        k = (n + m) // 2
        dsu = DSU(k + 1)

        for i in range(n - 1):
            dsu.union(a[i], a[i + 1])
        for i in range(m - 1):
            dsu.union(b[i], b[i + 1])

        ok = True
        for v in range(1, k + 1):
            r = dsu.find(v)
            if dsu.edges[r] >= dsu.size[r]:
                ok = False
                break

        print(2 if ok else 1)

if __name__ == "__main__":
    solve()
```この実装では、コンポーネント ルートごとに、そのサイズとその内部の隣接制約 (エッジ) の数の両方を格納する DSU が使用されます。 2 つの値を結合するたびにエッジ数が増加し、2 つのコンポーネントが結合されると、両方のエッジ数が集計されて接続エッジが追加されます。 すべての結合の後、各コンポーネントを検査し、少なくともノードと同じ数のエッジが含まれているかどうかを確認します。 

唯一の微妙な点は、ユニオン操作がすでに接続されているノードを接続する場合でも、エッジが正しくカウントされるようにすることです。 その場合、サイクル エッジの追加に対応するため、代表コンポーネントのエッジ カウンタをインクリメントします。 

すべてのコンポーネントは少なくとも 1 つのルート アクセスで表され、コンポーネントの代表ごとに条件を 1 回だけ評価するため、すべてのノードの最終スキャンは安全です。 

## 実用的な例

 配列がすでに高度に絡み合っているケースを考えてみましょう。 

入力：```
1
3 3
1 2 2
3 3 1
```エッジを構築します。最初の配列から (1,2) と (2,2 は何もしない) を追加し、2 番目の配列から (3,3 trivial) と (3,1) を追加します。 結果として得られるグラフには、1-2 と 1-3 を間接的に接続するエッジがあり、繰り返される制約によりサイクルを持つ単一の連結成分が形成されます。 

| ステップ | アクション | DSUの構造 | エッジ数のチェック |
 | --- | --- | --- | --- |
 | 1 | (1,2) を加算 | {1,2} | エッジ=1 |
 | 2 | (3,1) を加算 | {1,2,3} | エッジ=2 |

 ノード = 3 およびエッジ = 2 であるため、このコンポーネントは依然としてツリーであるため、2 番目のプレーヤーが生き残ります。 

次に、より高密度の構造を考えてみましょう。 

入力:```
1
4 4
1 2 3 4
2 3 4 1
```エッジは 4 つの値すべての間でサイクルを形成します。 

| ステップ | アクション | DSUの構造 | エッジ数のチェック |
 | --- | --- | --- | --- |
 | 1 | (1,2) | {1,2} | エッジ=1 |
 | 2 | (2,3) | {1,2,3} | エッジ=2 |
 | 3 | (3,4) | {1,2,3,4} | エッジ=3 |
 | 4 | (4,1) | サイクルエッジ | エッジ=4 |

 ここではエッジがノードから 1 を引いた数を超えているため、サイクルが存在し、最初のプレイヤーが勝ちます。 

これらのトレースは、決定が完全に隣接制約がサイクルに近づくかどうかによって決定されることを示しています。

 ## 特殊なケース

 両方の配列に同じ順序で同じペアが含まれる最小限のケースでは、隣接関係が 2 回カウントされると、即時サイクルを持つ単一コンポーネントが強制されます。 同じコンポーネント内で結合が試行されると、アルゴリズムはエッジ カウントを正しくインクリメントし、最初のプレーヤーの勝利をトリガーします。 

次のような逆順序のケース`1 2`そして`2 1`これにより、1 つのエッジを持つサイズ 2 のクリーンなツリーが生成されます。これにより、サイクルしきい値未満に留まり、2 番目のプレーヤーがオカレンスの分離を維持できます。 

すべての値が両方の配列にわたって一列に連鎖している場合は、単一のツリー コンポーネントが生成されます。 構造は大きくても、サイクルがないため、2 番目のプレーヤーに重複を強制することなく、すべての値をプレーヤー間で割り当てることができます。
