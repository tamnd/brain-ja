 ## 解決策
 ## 問題の理解

 平面内に 2 つの有限点セットが与えられます。 1 つのセットは新しい写真の星を表し、もう 1 つのセットは古い写真の星を表します。 新しい写真をベクトルで翻訳することが許可されています$(t_x, t_y)$回転または拡大縮小せずに。 

翻訳を選択した後、翻訳された新しいセットのすべての星が古いセットのすべての星と照合され、考えられる最悪のペアリング距離が考慮されます。新しい星ごとに、最も近い古い星を調べ、すべての新しい星についてそれらの最も近い距離の最大値を取得します。 目標は、この最悪の場合の最近隣距離を最小化する変換を選択することです。 

したがって、幾何学的に、ある点セットを別の点セットの上にスライドさせて、最大-最小基準の下で、新しいセットのすべての点を古いセットのある点にできるだけ近づけようとしています。 

制約により、各セットで最大 1000 点が許可されます。 翻訳の空間は連続しているため、翻訳のすべてのペアを比較する直接的なアプローチは不可能です。そのため、有効な解決策は、問題を有限の翻訳候補セットに減らすか、少数の重要なイベントに対する構造化された最適化に限定する必要があります。 

素朴な推論による微妙な失敗例は、1 組の点を正確に位置合わせするだけでよいと仮定することです。 たとえば、1 つの新しいポイントが 1 つの古いポイントと一致するように移動すると、局所的には最適に見えるかもしれませんが、他のポイントの距離が大幅に悪化する可能性があります。 もう 1 つの落とし穴は、最適な変換によって重心または境界ボックスが整列すると仮定することですが、最大最近接目標では保証がありません。 

## アプローチ

 ブルートフォースの観点は、新しい点がどこに着地するかを選択することによって翻訳が完全に定義されることに気づくことから始まります。 変換を修正する場合、変換された各新しいポイントとすべての古いポイントの間のすべてのペアごとの距離を計算し、新しいポイントごとに最も近い古いポイントを取得し、新しいポイントで最大化することで目的を評価できます。 この評価には費用がかかります$O(nm)$そして、点のペアから導出された候補翻訳の離散化さえ試みると、次のようになります。$O(n^2 m^2)$最悪の場合、候補者が多すぎる場合。 

重要な構造的洞察は、変換された新しい点に最も近い古い点のアイデンティティが変化する場合にのみ、目的が変化するということです。 新しいポイントの固定ペアリングの場合$a_i$古い点まで$b_j$、という条件。$b_j$～に最も近い古いポイントです$a_i + t$翻訳空間内の領域を定義します。 その領域内の距離は、$\|a_i + t - b_j\|$制約を管理します。 この問題は、変換空間に持ち上げられた古い点のボロノイ構造によって引き起こされる有限配置に対するミニマックス最適化になります。 

同様に、新しい点と古い点の間のペアの選択ごとに、そのペアがアクティブな場合の実行可能な変換を表現できます。その領域内で、新しい各点から割り当てられた古い代表までの最大距離を最小化したいと考えます。 最適解は、少なくとも 2 つの制約が同時に厳しくなる境界イベントで発生する必要があり、臨界点ペア間の距離を等しくすることによって定義される平行移動に候補が絞り込まれます。 

これにより、問題は点のペアの位置合わせから導出される平行移動を考慮し、誘導された最大最近距離を効率的に評価することにつながりますが、すべての可能性ではなく、構造化された候補ベクトルのセットのみが対象となります。

 ## アルゴリズムのチュートリアル

 1. 新しいポイントと古いポイントの各ペアを潜在的な位置合わせアンカーを定義するものとして扱う順序を修正します。 ペア用$(a_i, b_j)$、次のように翻訳することを検討してください。$a_i$近くの地図$b_j$、 意味$t = b_j - a_i$。 これにより、具体的な翻訳候補が得られます。 
2. 翻訳候補ごとに$t$、すべての変換された新しいポイントを計算します$a_k + t$。 このステップでは、問題は、この厳密なシフトが最近傍マッチングの下で​​ 2 つの構成をどの程度うまく調整するかを測定することに変わります。 
3. 古いポイントを前処理して、k-d ツリーやグリッドベースのバケットなど、平面内の高速最近傍クエリを可能にする構造にします。これにより、変換された各ポイントについて、最も近い古いポイントを効率的に見つけることができます。 
4. 変換された新しい点ごとに、古い点までの最小距離を計算します。 すべての新しいポイントにわたるこれらの距離の最大値を追跡します。 これがこの翻訳の客観的な値です。 
5. 全体を反復処理する$n \cdot m$翻訳候補を選択し、最小の最大距離で最適な翻訳を維持します。 値と変換ベクトルの両方を保存します。 
6. 最適距離と平行移動ベクトルを出力します。 

コストがかかる部分は、各候補翻訳の最近傍を評価することです。 空間前処理を使用すると、各クエリはほぼ対数になり、合計が実行可能になります。$n, m \le 1000$。 

### なぜ効果があるのか

 最適な状態では、最も近い古い点が「クリティカル」である新しい点が少なくとも 1 つ存在します。つまり、変換をわずかに混乱させると、その点は最も近いままになるか、別の古い点に切り替わり、そのような境界を越えなければ目的は改善されません。 これは、最適な変換は、古い点によって定義された候補領域に少なくとも 1 つの新しい点を位置合わせすることとして表現できることを意味するため、そのような位置合わせをすべて列挙することで、グローバル最小値を見逃さないことが保証されます。 最大最近接構造は、何らかの制約が厳しい構成での最適な配置を保証します。これは、アンカーによる変換の 1 つに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    A = [tuple(map(int, input().split())) for _ in range(n)]
    m = int(input())
    B = [tuple(map(int, input().split())) for _ in range(m)]

    # simple O(n^2 m) baseline with pruning via precomputation of distances
    # since constraints are small (1000), this is acceptable in Py context

    best_d = float('inf')
    best_tx = 0.0
    best_ty = 0.0

    # precompute old points for direct access
    bx = [b[0] for b in B]
    by = [b[1] for b in B]

    for ax, ay in A:
        for bx0, by0 in B:
            tx = bx0 - ax
            ty = by0 - ay

            worst = 0.0

            # evaluate this translation
            for ax2, ay2 in A:
                x = ax2 + tx
                y = ay2 + ty

                # nearest old point
                best_local = float('inf')
                for bx1, by1 in B:
                    dx = x - bx1
                    dy = y - by1
                    d = dx * dx + dy * dy
                    if d < best_local:
                        best_local = d

                if best_local > worst:
                    worst = best_local
                    if worst >= best_d:
                        break

            if worst < best_d:
                best_d = worst
                best_tx = tx
                best_ty = ty

    print(f"{best_d ** 0.5:.12f} {best_tx:.12f} {best_ty:.12f}")

if __name__ == "__main__":
    solve()
```コードはアンカーのアイデアに直接従っています。 新しい各点と古い各点をペアにして平行移動を列挙し、平行移動ベクトルを生成します。 変換ごとに、すべての新しいポイントを移動し、それらに最も近い古いポイントを総当たりで計算します。 二乗距離は比較中に不必要な平方根を避けるために内部で使用され、最終的な答えは平方根を 1 回計算します。 

小規模な最適化は、これ以上計算してもその候補を改善できないため、現在の最悪の距離がこれまでに見つかった最良の距離をすでに超えている場合に、内側のループ内で早期に停止します。

 どちらも値 0 で最適であり、セットが変換によってのみ異なる場合、正確な位置合わせが機能することが確認されます。

| 候補者 | 翻訳 | シフトA | ポイントごとの最近接距離 | 最悪 |
 | --- | --- | --- | --- | --- |

 ## 特殊なケース

 重要なエッジ ケースは、複数の古いポイントが変換後に等距離になる場合です。 たとえば、変換された新しい点が 2 つの古い点の中点に正確に位置する場合、両方の候補の最近接距離は同一になります。 アルゴリズムは、一意性を仮定せずにすべての古い点の完全な最小値を常に再計算するため、これを自然に処理します。 

もう 1 つのケースは、最適な変換によってどのペアも正確に位置合わせされない場合です。 それでも、すべてのペア誘発変換の列挙では、評価が最適値と一致する候補が捕捉されます。これは、最適値は 1 つの制約がアクティブになる領域に存在する必要があり、その領域の境界が何らかのペア アラインメント イベントに対応するためです。
