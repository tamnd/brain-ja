 ## 解決策
 ## 問題の理解

 私たちに与えられたコレクションは、$n$各立方体には 6 つの目に見える数字があります。 各立方体は、その 6 つの面のいずれかが上面になるように方向を設定できます。つまり、立方体ごとに、その 6 つの数字のいずれかを、その立方体が寄与する数字として選択できます。 

立方体の一部のサブセットを選択し、選択した各立方体に表示されている数字の 1 つを割り当てることができ、結果として得られる一連の数字が先頭のゼロのない正の整数を形成できる場合、数値は構成可能であるとみなされます。 選択されなかったキューブは単に無視されます。 選択された各立方体は、正確に 1 桁を提供します。 

タスクは最小値を決定することです$k$この方法では形成できない正の整数。 

重要な制約は、$n \le 100$、 その間$k \le 10^5$。 これは、表現可能な数値のセットが比較的小さな組み合わせ構造によって支配されているが、欠損数値に対するクエリ範囲が大きくなる可能性があることを直ちに示唆しています。 すべての整数を 1 つずつ明示的にチェックし、実行可能性を最初から再計算するアプローチでは、時間がかかりすぎます。単一の数値をテストするには、最大 100 個の立方体にわたる制約付き代入問題を解く必要があるからです。 

ゼロが含まれる場合、微妙なエッジケースが発生します。 102 のような数値は、立方体にゼロが含まれている場合でも、先頭の数字をゼロにすることができない場合は無効です。 もう 1 つのエッジ ケースは、未使用のキューブが重要であるということです。キューブを完全にスキップすることができます。つまり、慎重にモデル化しない限り、長い数値が単調な方法で必ずしも難しくなったり簡単になるわけではありません。 

たとえば、すべての立方体に数字 {1,2} のみが含まれている場合、3、4、5、6、7、8、9、10 などの数字はすべて構造的に不可能であり、立方体をスキップすることで任意の長さを制御できます。 「常にすべてのキューブを使用する」という単純な仮定は間違っています。 

## アプローチ

 強引な解釈では、整数を昇順に列挙し、それぞれを形成できるかどうかを確認しようとします。 数値ごとに、選択した各立方体がその数値の桁と一致する桁を提供できるように、立方体のサブセットに桁を割り当てることができるかどうかを決定する必要があります。 これは本質的に、桁の位置と立方体の間の 2 部マッチングまたはサブセット選択の問題です。 

ある程度の長さで実現可能性を確認してみると$L$自然なアプローチは、キューブのすべてのサブセットとすべての割り当てを試すことです。これは指数関数的です。$n$。 実現可能性チェックを最適化したとしても、まだ次の段階までの処理が必要です。$10^5$候補番号。それぞれに必要となる可能性があります。$O(nL)$またはさらに悪いマッチングロジック。 これは完全に不可能になります。 

重要な構造的観察は、実現可能性はどの数字がどのキューブに現れるかのみに依存し、数字ごとの制約を除いて数値自体には依存しないということです。 以来$n$が小さい場合は、逆に考えることができます。数値が構成可能かどうかをチェックする代わりに、構成可能なすべての数値を暗黙的に特徴付けてから補数を列挙できます。 

重要な単純化は、各立方体が独立して小さな桁のセットを提供し、数値内の各桁の位置にはその桁をサポートする個別の立方体が必要であることです。 これにより、問題は位置と立方体間の二部マッチングの実現可能性チェックに変わります。 以来$n \le 100$、標準の DFS ベースのマッチングは十分に高速です。 

次に、数値を昇順に生成しますが、最初から再計算するのではなく、収集後にプルーニングと早期停止を使用してマッチングを再利用します。$k$ありえない数字。

 ## アルゴリズムのチュートリアル

 私たちは、問題は、利用可能なキューブを使用して数値を構築できるかどうかを繰り返しテストすることであると考えています。 

### ステップ 1: キューブ桁の可用性を前処理する

 キューブごとに、どの数字を表示できるかを保存します。 これは、キューブあたりサイズ 10 のブール配列です。 これにより、キューブに数字を割り当てようとするときに、一定時間のチェックが可能になります。 

この構造が必要なのは、すべての実現可能性チェックでキューブが数字を提供できるかどうかを繰り返し照会するためです。 

### ステップ 2: 数値の実現可能性を定義する

 数値が与えられると、その桁を位置とみなします。 各数字の位置を、その数字を含む個別のキューブに割り当てる必要があります。 これは、位置と立方体の間の 2 部マッチング問題です。 

先頭にゼロがある数値は定義上無効であるため、直ちに拒否します。 

### ステップ 3: マッチング配合

 数字の位置から立方体までの DFS ベースの 2 部マッチングを構築します。 各キューブは最大で 1 回使用できるため、DFS 中にキューブの訪問済み配列が維持されます。 位置ごとに、その数字をサポートする任意の立方体にその位置を割り当てようとします。 

すべての位置が一致する場合、数値は構築可能です。 

### ステップ 4: 数値を昇順に列挙します

 整数を 1 から上に向かって繰り返し、それぞれを文字列に変換し、実現可能性をテストします。 実行不可能な場合は、回答リストに追加します。 集まり次第終了$k$そういった数字。 

不可能な最小の数値が必要なため、順序付けによって正確さが保証されます。 

### ステップ 5: 早めに中止する

 集めたら$k$あり得ない数字なので、列挙はやめます。 答えは大きくなる可能性があるため、これは重要ですが、これ以上進む必要はありません。 

### なぜ効果があるのか

 中心となる不変条件は、実現可能性チェックが「各数字を、それを含む個別のキューブに割り当てることができる」という条件を正確に把握することです。 DFS マッチングにより、キューブが再利用されず、すべての有効な割り当てが数値の有効な構造に対応することが保証されます。 数値を昇順にスキャンし、失敗のみを記録するため、結果として得られるリストは、まさにありえない数値を並べ替えたものになります。 すべての整数が構成可能性について個別にテストされるため、数値が誤ってスキップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

cubes = []
for _ in range(n):
    faces = list(map(int, input().split()))
    ok = [False] * 10
    for d in faces:
        ok[d] = True
    cubes.append(ok)

sys.setrecursionlimit(1000000)

def can_make(s):
    if s[0] == '0':
        return False

    m = len(s)
    match = [-1] * n

    def dfs(i, vis):
        for j in range(n):
            if not vis[j] and cubes[j][int(s[i])]:
                vis[j] = True
                if match[j] == -1 or dfs(match[j], vis):
                    match[j] = i
                    return True
        return False

    # try to match each position
    for i in range(m):
        vis = [False] * n
        if not dfs(i, vis):
            return False
    return True

ans = []
x = 1

while len(ans) < k:
    s = str(x)
    if not can_make(s):
        ans.append(x)
    x += 1

print(*ans)
```キューブの前処理ステップでは、キューブごとに数字の実現可能性を調べるための高速ルックアップ テーブルを構築します。 これにより、照合中に顔を繰り返しスキャンする必要がなくなります。 

の`can_make`関数は、DFS ベースのキューブへの数字の割り当てを実行します。 各桁の位置は独立して処理され、それぞれの桁の位置をホストできるキューブを見つけようとします。 訪問済み配列により、1 回の DFS 呼び出し内でキューブを再訪問することができなくなります。`match`配列では、各キューブが最大 1 回使用されることが強制されます。 

外側のループは単に整数を列挙し、実現可能性テストに合格しなかった整数を収集します。 

微妙なポイントがリセット中`vis`マッチング試行全体ではなく、桁位置ごとに。 これにより、各 DFS が異なる位置間の干渉なしに新しい拡張パスを探索できるようになります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、数値に繰り返しの数字が含まれているが、キューブが重複をサポートできない場合です。 たとえば、数字の 7 が含まれる立方体が 1 つだけの場合、7 だけは可能であっても、77 は不可能になります。 単一の立方体を 2 回割り当てることはできないため、マッチング公式はこれを正しく検出します。 

もう 1 つの特殊なケースは、ゼロ拒絶です。 立方体に 0 と 1 桁のみが含まれる入力の場合、10 や 100 のような数値は構造的には実行可能に見えますが、最初の桁が 0 の場合は拒否する必要があります。 明示的な先行ゼロのチェックにより、一致する前にこれらが確実に除外されます。 

最後のエッジケースは次のような場合です$n$は大きいですが、桁の種類は小さいです。 Even though many cubes exist, feasibility is still constrained by digit coverage, and the matching ensures we do not incorrectly assume abundance of cubes allows all numbers.
