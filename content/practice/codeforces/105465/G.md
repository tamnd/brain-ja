 ## 問題の理解

 私たちは、接続された、重み付けのない、無向のグラフを操作しています。 すべての頂点には 2 つの値が関連付けられています。$a_u$そして$b_u$。 タスクは頂点に直接接続されている頂点のみを考慮します。$1$。 そのような隣人一人一人に対して$v$、他のすべての頂点を考慮して定義された値を計算する必要があります。$u$グラフ内で式を評価する$a_u - b_u \cdot \text{dist}(u, v)$、 どこ$\text{dist}(u, v)$エッジ内の最短パス長です。 

隣人ごとに$v$ノードの$1$、頂点を選択します$u$この式を最大化し、その最大値を出力します。 

これが自明ではないのは、グラフが大きいためです。$3 \cdot 10^5$頂点とエッジ、およびそれぞれのクエリ$v$すべてのノードからの距離に依存します。$v$、つまり、単純な最短経路計算を意味します。$v$遅すぎます。 

直接試行すると、すべての近隣から BFS が計算されます。$v$ノードの$1$。 If ノード$1$学位を持っています$k$、これはすでに次のことにつながります$k$BFS の実行、それぞれのコスト$O(n + m)$に退化します。$O(nm)$密集した場合。 それは完全に限界の範囲外です。 

最も近い頂点情報のみを再利用しようとすると、微妙な失敗モードが発生します。 たとえば、頂点があるとします。$u$に最も近いものではありません$v$、しかし非常に大きい$a_u$そして小さい$b_u$。 他の頂点が近づいても$v$、$u$その値は距離とともにゆっくりと減少するため、依然として式を支配している可能性があります。 つまり、それぞれを圧縮することはできません$u$'s contribution into a single “nearest source” representative.

 ## アプローチ

 The brute force idea is straightforward: for every neighbor$v$ノードの$1$、BFS を実行してすべてのノードまでの距離を計算し、すべての頂点をスキャンします。$u$そして計算する$a_u - b_u \cdot \text{dist}(u,v)$。 これは、定義を直接評価するため、正しいです。 問題は複雑さです。 各 BFS は、$O(n + m)$、および if ノード$1$多くの近傍がある場合、実際には総コストは二次関数になります。 

重要な観察は、実際には、ごとに独立した計算を必要としないということです。$v$。 すべてのクエリは同じ基礎構造を共有しています。つまり、グラフの距離に関して線形関数のファミリーの最大値を求めています。 各頂点$u$グラフ上で関数を定義します。それは貢献します。$a_u - b_u \cdot d$、距離が増加するにつれて直線的に減少します。 

これにより、ターゲット ノードごとに問題が評価に変わります。$v$、多くの「ソース」の中で最高のもの$u$、各ソースには傾斜があります。$b_u$。 構造は、重み付けされていないグラフでは距離が最短経路距離であるため、距離を個別に再計算するのではなく、BFS のような緩和を使用して寄与を伝播できます。 

それぞれからの距離を計算する代わりに$v$では、視点を逆にします。各頂点を許可します。$u$グラフを通じてその影響を「拡散」します。 片方の端を遠ざけると、$u$、その寄与は正確に減少します$b_u$。 これは、各頂点が線形減衰を伝えるソースとして機能するマルチソース伝播を示唆しています。 

課題は、ソースが異なれば減衰速度も異なるため、それらを単一の BFS フロンティアにマージできないことです。 標準的な解決策は、プロセスをすべてのノードにわたるグローバルな緩和として扱うことです。頂点が何らかのソースからより良い値を達成するたびに、その改善を外側に伝播することができます。 各状態は事実上、「特定のソース動作に由来する場合、そのノードで最もよく知られている値」であり、エッジトラバーサルごとに発生元の動作に応じて固定の減少コストがかかるため、$u$、各緩和は単調であり、優先キューで処理できます。 

これにより、各頂点で達成される最良の値を表す状態にわたるダイクストラのようなプロセスが生成され、遷移は次のように減少します。$b_u$エッジごとに実行され、クエリごとに完全な BFS の再計算を回避しながら正確性を確保します。

 ## アルゴリズムのチュートリアル

 各頂点を、値を持ち、距離とともに直線的に減少する拡散「信号」の潜在的な発信源として扱います。 

1. すべての頂点を含む優先キューを初期化します。各頂点は$u$価値から始まる$a_u$それ自体からの距離はゼロです。 これは、各頂点が外側に伝播する前にそれ自体の最適な候補として開始できるという考えを表しています。 
2. 配列を維持します`best[v]`、これまでに見つかった頂点の最良の値を保存します$v$。 最初は、これは、挿入されているソースを除くすべての頂点に対して非常に小さいです。 
3. 優先キューから現在値が最も高い状態を繰り返し抽出します。 これにより、状態を処理するときはいつでも、その構成に到達するための最善の方法が保証されます。 
4. 頂点に相当する状態から$x$、私たちはすべての隣人をリラックスさせようとします$y$。 現在の状態が何らかのソースから生じたものである場合$u$からの移動$x$に$y$値を減らす$b_u$, したがって、候補値は次のようになります。$current - b_u$。 この候補者が改善すれば`best[y]`、それを更新し、優先キューにプッシュします。 
5. キューが空になるまで続行します。これは、考えられるすべての伝播が処理され、それ以上の改善が不可能になることを意味します。 
6. 伝播が完了したら、出力します。`best[v]`頂点のみ$v$ノードに隣接しているもの$1$、昇順で。 

重要な不変条件は、優先キュー内のすべてのエントリが、特定の起点を介して到達した頂点の最もよく知られている値を表すということです。$u$特定のステップ数を経た後、その値は正しく等しい$a_u - b_u \cdot \text{distance}$。 エッジを通過するたびに値が正確に減少するため、$b_u$、すべてのエッジの重みは構造上均一であり、状態が最大値でポップされると、その後の緩和によって同じ構成に対してより良い値を生成することはできません。 これにより、貪欲な抽出順序の正確さが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [0] * (n + 1)
    b = [0] * (n + 1)

    for i in range(1, n + 1):
        a[i], b[i] = map(int, input().split())

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    # best[v] = best value achievable at node v
    best = [-10**30] * (n + 1)

    pq = []

    for i in range(1, n + 1):
        best[i] = a[i]
        heapq.heappush(pq, (-a[i], i, i))  
        # (negative value, current node, origin u)

    while pq:
        neg_val, x, u = heapq.heappop(pq)
        val = -neg_val

        if val != best[x]:
            continue

        for y in g[x]:
            cand = val - b[u]
            if cand > best[y]:
                best[y] = cand
                heapq.heappush(pq, (-cand, y, u))

    start_neighbors = []
    for v in g[1]:
        start_neighbors.append(v)

    start_neighbors.sort()
    for v in start_neighbors:
        print(best[v])

if __name__ == "__main__":
    solve()
```コア構造は、マルチソースのベストファースト伝播です。 各ヒープ状態は、現在のノードだけでなく、元の頂点も追跡します。$u$、減衰率が高いため、$b_u$ソースに依存し、パスに沿って一貫性を保つ必要があります。 

の`best`配列により、同じノードのより悪い状態が処理されないことが保証されます。 ヒープの順序付けにより、常に最も有望な候補が最初に展開されることが保証されます。これは、後の低い値の伝播によって以前に固定されたより適切な値を上書きできないため、非常に重要です。 

最後に、ノードの近隣ノードの結果のみを出力します。$1$、問題により評価がそれらの頂点に制限されるためです。 

## 実用的な例

 ノードが次のような小さなグラフを考えてみましょう。$1$ノードに接続されています$2$そして$3$、代替ルートを形成する追加のエッジがあります。 1 つの離れたノードが大きくなるように値が選択されたとします。$a_u$でも大きい$b_u$、近いノードほど小さい$a_u$しかし、より小さな減衰もあります。 

伝播は、すべてのノードを初期ソースとして挿入することで開始されます。 大きなノード$a_u$最初はヒープを支配しますが、外側に伝播するにつれて、値はすぐに縮小します。$b_u$大きいです。 減衰が小さい競合ノードは、最終的にはグラフのより遠くの領域を支配することになります。これはまさにアルゴリズムが自動的にキャプチャするものです。 

2 番目の例では、ノードの同じ隣接ノードに影響を与える 2 つの頂点間の競合を強調しています。$1$。 1 つの頂点はグラフの距離が近いですが、急速に減衰します。一方、もう 1 つの頂点は遠いですが、ゆっくりと減衰します。 ヒープによって両方の影響が確実に伝播され、より高い結果値を持って近隣に到着した方が、保存された回答になります。

import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import defaultdict
    input = _sys.stdin.readline

    n, m = map(int, input().split())
    a = [0] * (n + 1)
    b = [0] * (n + 1)

    for i in range(1, n + 1):
        a[i], b[i] = map(int, input().split())

    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    best = [-10**30] * (n + 1)
    pq = []

    for i in range(1, n + 1):
        best[i] = a[i]
        heapq.heappush(pq, (-a[i], i, i))

    while pq:
        neg_val, x, u = heapq.heappop(pq)
        val = -neg_val
        if val != best[x]:
            continue
        for y in g[x]:
            cand = val - b[u]
            if cand > best[y]:
                best[y] = cand
                heapq.heappush(pq, (-cand, y, u))

    res = sorted(v for v in g[1])
    return " ".join(str(best[v]) for v in res) + "\n"

 ## 特殊なケース

 1 つのエッジ ケースは、ノードが次の場合に発生します。$1$の次数は非常に高く、ほとんどの頂点がそれに直接接続されています。 この場合、初期ヒープ エントリがすでに独自の位置に強力な候補をシードしており、複数の近傍に影響を与える頂点が共有 BFS のような拡張を通じて影響を与えることが伝播によって確実に行われるため、アルゴリズムは依然として正しく動作します。 

もう 1 つのケースは、頂点が非常に大きい場合です。$b_u$1、2 ステップ後に値が急激に低下します。 たとえそのような頂点が最大の値を持っていたとしても、$a_u$、非常に近いノードのみを支配します。 ヒープベースの伝播は、その影響が競合ソースよりも急速に悪化するため、これを自然に捕捉します。 

最後のケースは、すべてが$a_u$等しいですが、$b_u$大きく異なります。 このアルゴリズムは事実上、距離に対する減衰率の競合となり、その構造により、特別なケースを使用せずに、よりゆっくりと減衰する音源がグラフのより遠い領域を支配することが保証されます。
