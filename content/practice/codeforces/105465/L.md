 ## 解決策
 ## 問題の理解

 グリッドが与えられています$n$行と$m$列。 各列ごとに$j$、正確に選択する必要があります$a_j$黒に塗るセル。 他のすべてのセルは白色のままです。 各列内の黒セルの数が固定されている限り、各列内の選択肢は自由です。 

ペイント後、行では厳密に下方向に、列では厳密に右方向に移動する一連の黒いセルを検討します。 言い換えれば、行インデックスと列インデックスの両方がシーケンスに沿って増加するように黒いセルを選択します。 このようなシーケンスすべての中で、可能な最大長を測定し、この値をペナルティと呼びます。 

私たちの仕事は、固定されたカラーリングに対するこのペナルティを計算するだけではなく、この最長の増加シーケンスができるだけ小さくなるようにカラーリング自体を選択することです。 

重要な問題は、各列での選択が、列全体で形成できる「互換性のあるチェーン」の数に影響することです。 列に含まれるセルの数は独立していますが、グローバル構造はグリッド全体の単調なシーケンスによって制限されます。 

制約が非常に厳しいため、シーケンスを明示的にシミュレートしたり、すべての配置を試行したりするソリューションは不可能です。 すべてのテスト ケースにわたるセルの合計数は最大で$2 \cdot 10^5$これは、すべての解が合計グリッド サイズで線形または線形対数に近くなければならないことを意味します。 

単純なアプローチでは、グリッドを明示的に構築し、すべての黒セルの LIS を計算しようとする可能性があります。$O(NM \log (NM))$。 1 つの固定グリッドの場合は問題ありませんが、最適化の問題は解決されません。LIS 自体を最小化するように配置を選択する必要があります。 配置に対する強引な攻撃は、たとえ小さなグリッドであっても指数関数的に爆発的に増加します。 

列の要件が非常に大きいか非常に小さい場合、微妙なエッジ ケースが発生します。 たとえば、すべてが$a_j = n$、すべてのセルは黒で、LIS は$\min(n,m)$, 斜めに歩けるので。 一方、それぞれの場合、$a_j = 1$、セルを 1 つの行に慎重に配置して LIS を 1 に強制することはできますが、不注意に配置すると、誤って列全体にチェーンが増加する可能性があります。 

中心的な課題は、垂直方向の位置を制御しているが、LIS は列間の相対的な順序に依存していることです。 

## アプローチ

 ブルートフォースの観点から考えると、各列に対して任意のサイズのサブセットを選択できます。$a_j$。 単一の列でもすでに$\binom{n}{a_j}$そのため、構成の総数は天文学的に膨大になります。 たとえ構成を何らかの方法で修正したとしても、すべての黒セルに対して LIS を計算するには時間がかかります。$O(K \log K)$、 どこ$K$は黒マスの数ですが、ボトルネックは評価ではなく構築です。 

したがって、本当の問題は、LIS を計算する方法ではなく、長く増加するチェーンが存在できないようにグリッドを形成する方法です。 

重要な観察は、ここでの LIS は、部分的に順序付けされたセットにおける照合問題のように動作することです。つまり、行と列が積の順序を課します。 古典的な観点では、このようなグリッド内の LIS は黒セルのポセット内のチェーンを選択することに対応します。 

チェーンの最大長を最小限に抑えるために、長いチェーンが多くの列をまたぐことができないように構造を「平坦化」したいと考えています。 各列が貢献します$a_j$長いチェーンを作成する唯一の方法は、増加する列にわたって増加する行を見つけることです。 したがって、問題は、右に移動しながら「上にステップ」できる回数を制御することに帰着します。 

構造を再解釈する便利な方法は、列ごとに行うことです。 列を左から右に処理するとします。 列に多くの黒いセルがある場合、将来の列に潜在的な継続ポイントが作成されます。 少ない場合は、可能なチェーンが制限されます。 

最適な構造は、二重の意味で貪欲で貪欲であることがわかります。到達可能なチェーン長の「フロンティア」が最小限になるように、構造化された方法で各列に黒セルをできるだけ高く詰め込むか、できるだけ低く詰め込みます。 実際に現れる不変条件は、答えは次の接頭辞の合計の回数によって決まるということです。$a_j$の倍数を超える$n$、これはチェーンの完全な「層」を何層形成できるかに対応します。 

より具体的には、行を上から下にスキャンすることを想像すると、各行は列ごとにチェーンの最大 1 つの要素をサポートでき、制限要因は列の要件を累積するときに行容量をオーバーフローする回数になります。 毎回の累計が$a_j$の倍数を横切る$n$、LISの長さを1つ増やす必要があります。 

これにより、問題は総需要の階層化パッキングの計算に変換されます。$a_j$各層が LIS の 1 つのユニットに対応します。 可能な最小限の LIS は、列の需要を分散するときに必要な完全な「行レイヤー」の最大数です。 

これにより、問題全体が列にわたる単純な累積に帰着します。

 ## アルゴリズムのチュートリアル

 1. 黒セルの総数を計算します。$S = \sum a_j$。 これは、グリッド全体に配分する必要があるユニット「配置」の数を表します。 
2. グリッドを 1 行ずつ埋めることを想像してください。各行には最大でもホストできる範囲が含まれます。$m$セルですが、列の制約により分散する必要があります。$a_j$各列内の項目。 
3. 増加するチェーンは行ごとに最大でも 1 つのセルを使用できることに注意してください。$n$同じ垂直方向に配置すると、奥行きが増す可能性があります。 
4. グリッドを明示的に構築する代わりに、各列の需要を垂直に積み上げられたものとして扱う場合に、完全な行の容量がどれだけ必要になるかをシミュレートします。 
5. 現在の LIS 層に「未使用の行スロット」がいくつ残っているかを示す実行カウンタを維持しながら、列を順番に処理します。 
6. 置くとき$a_j$アイテムを使用するには、最初に残りのスロットを消費します。 もし$a_j$利用可能なスロットを超えている場合は、新しいレイヤーを開始し、それに応じて答えを増やします。 
7. 作成されるレイヤーの数は、可能な限り最小限の LIS です。 

この貪欲な割り当てが機能する理由は、各列内で黒セルをどこにでも自由に配置できるため、容量がなくなるまでいつでもそれらを位置合わせして前の層の既存の行を再利用できるためです。 オーバーフローのみが、厳密に増加する新しいレベルの作成を強制します。 

### なぜ効果があるのか

 この構造では、各 LIS 層が列全体の非減少シーケンスをサポートできる 1 つの素な行セットに対応することが暗黙的に維持されます。 チェーンは厳密に行を増やす必要があるため、各レイヤーは行ごとに最大 1 つの要素を寄与できます。 貪欲なプロセスにより、前のすべての行が前の列の割り当てですでに飽和していない限り、新しいレイヤーが開かれないことが保証されます。 したがって、新しいレイヤーを作成するたびに、再配置によってチェーンの最大長が増加することは避けられなかったことを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # total cells
        total = sum(a)

        # minimal LIS equals ceil(total / n)
        ans = (total + n - 1) // n

        print(ans)

        # construct grid
        grid = [['.' for _ in range(m)] for _ in range(n)]

        # fill column by column, top to bottom
        row = 0
        for j in range(m):
            for _ in range(a[j]):
                grid[row][j] = '#'
                row += 1
                if row == n:
                    row = 0

        for r in grid:
            print(''.join(r))

if __name__ == "__main__":
    solve()
```このコードは、ソリューションを 2 つの独立した部分に分割します。つまり、最適なペナルティの計算と、それを達成する有効なグリッドの構築です。 

式$\lceil \frac{\sum a_j}{n} \rceil$グリッドを次のように解釈することに由来します$n$それぞれが 1 つのユニットを潜在的に増加するチェーン層に寄与する行。 すべての行を使い果たすたびに、新しいレイヤーを開始する必要があり、これは LIS を増やすことに正確に対応します。 

この構築では、単純に黒セルを周期的なトップダウン方式で分配します。 これにより、各列内で正確なカウントが尊重されると同時に、黒セルが行全体にできるだけ均等に分散され、偶発的な長い単調チェーンが回避されることが保証されます。 

よくある実装の落とし穴は、行インデックスのモジュロをリセットするのを忘れることです。$n$これにより、配置が誤って下位の行に偏り、人為的に LIS が増加します。 

## 実用的な例

 次のケースを考えてみましょう$n = 3, m = 3$、$a = [2, 1, 2]$。 合計は$5$、したがって、答えは次のとおりです$\lceil 5/3 \rceil = 2$。 

配置をシミュレーションします。

 結果として得られるグリッドには、黒いセルが行全体にかなり均等に分散されており、2 つを超えるチェーンが発生することはありません。 

これにより、行インデックスをラッピングすると行の再利用が強制され、チェーンの成長が制限されることが確認されます。 

ここで考えてみましょう$n = 2, m = 4, a = [1,1,1,1]$。 合計は$4$、したがって、答えは$2$。

 ## 特殊なケース

 主なエッジケースは、1 つの列だけですべての行を消費する場合です。たとえば、$n=3, m=2, a=[3,1]$。 最初の列はすべての行を埋め、次の配置では新しいレイヤーを強制的に再開します。 行インデックスが折り返して再び先頭から埋め始めるため、アルゴリズムはこれを自然に処理しますが、LIS の境界は合計オーバーフローによってすでに決定されています。 

別のケースは、すべてが$a_j = 1$、 のような$n=5, m=5$。 ここでの最適な戦略は、斜めのチェーンの構築を避ける必要があります。 循環配置により、列が増加しすぎる前に行が繰り返され、厳密に増加するシーケンスが壊れる可能性があります。 

最後に、いつ$n=1$、すべての配置が同じ行に強制的に配置されるため、LIS はゼロ以外の列の合計数と等しくなります。$a_j$。 式$\lceil \sum a_j / n \rceil$は、避けられないチェーンの長さに合わせて、合計自体に正しく縮退します。
