 ## 解決策
 ## 問題の理解

 各参加者は、間隔から均一に選択された実数値のスコアを受け取ります。$[l_i, r_i]$。 スコアは独立しています。 すべてのスコアが生成された後、参加者はスコアによって並べ替えられます。 スコアが小さいほどランクが高いことを意味するため、最大のスコアを持つ参加者が最後に終了します。 

参加者全員にとって$i$そしてどのランクでも$j$、参加者がそうなる確率を計算する必要があります。$i$正確な位置で終了する$j$。 

分布は連続的であるため、確率は 0 で同点になります。 これにより、ランキングにおける曖昧さがすべて解消されます。 

最も明白な問題は、間隔が任意の方法で重なることです。 参加者1名に対して$i$、他の参加者が$k$彼よりも低いスコアは、サンプリングされた正確な値に依存します。$i$。 これらのイベントはグローバルに独立しているわけではありませんが、次のように条件付けすると独立します。$i$のスコア。 

制約$n \le 80$は 3 次または 4 次動的計画法には十分小さいですが、指数関数としては大きすぎます。 すべての相対順序を列挙するには、$n!$可能性は、たとえそれが絶望的であっても、$n=15$。 座標は次のように大きくできます。$10^9$したがって、すべての実数値を直接離散化するアプローチは不可能です。 ソリューションは間隔エンドポイントのみに依存する必要があります。 

間隔は連続しているため、いくつかの微妙なエッジ ケースが発生します。 

2 つの間隔が重ならないと仮定します。```
2
0 1
10 11
```最初の参加者は常に 2 番目の参加者よりも前にランクされます。 厳密な不等式を一貫性なく使用する不注意な実装では、不可能な順序付けに誤って小さな確率質量が割り当てられる可能性があります。 

ある間隔が別の間隔に完全に含まれている場合には、別の注意が必要なケースが発生します。```
2
0 10
4 6
```ここで、2 番目の参加者のスコアが 0 未満または 10 を超えることはあり得ないため、確率曲線は正確に間隔の境界で変化します。 これらのブレークポイントがないと、統合が正しく行われなくなります。 

3 番目の重要なケースは、多くのエンドポイントが一致する場合です。```
3
0 5
0 5
0 5
```すべてのランキングは対称的であるため、すべての参加者が確率を持っている必要があります$1/3$ランクごとに。 浮動小数点ドリフトや不正な間隔分割によって非対称性が発生すると、すぐにバグが露呈します。 

配布の継続的な性質も重要です。 考慮する：```
2
0 1
1 2
```間隔が 1 つのエンドポイントで接触している場合でも、スコアが等しい確率はまったくゼロです。 間隔を閉じた離散範囲として扱う実装では、タイが誤ってカウントされる可能性があります。 

## アプローチ

 ブルートフォースの観点は単純です。 参加者を 1 人選ぶ$i$。 あらゆる可能なスコアに対して$x$彼は、他の参加者の何人のスコアが以下であるかの確率分布を取得、計算できます。$x$。 次に全体を統合します$x$。 

正確なスコアがわかっていたら$x$、お互いの参加者$k$独立して以下を満たします:$$P(s_k < x)$$のランク$i$次に、スコアが小さい参加者の数によって決定されます。 

ブルートフォース障害は積分です。 確率式は常に変化します$x$間隔のエンドポイントを通過します。 エンドポイント間では、すべての確率は線形です。$x$。 単純なアイデアの 1 つは、多くのサンプル点にわたる数値積分ですが、これでは必要な精度を確実に達成できません。 

重要な観察は、実線がすべての区間の端点によって形成されるセグメントに分割できるということです。 1 つの固定セグメント内$[a,b]$、すべての確率式は次のアフィン関数になります。$x$。 

参加者向け$k$:$$P(s_k < x)= \begin{cases} 0 & x \le l_k \\ 1 & x \ge r_k \\ \dfrac{x-l_k}{r_k-l_k} & l_k < x < r_k \end{cases}$$固定セグメント内では、各参加者は 3 つのカテゴリのいずれかに分類されます。 

定数 0 に寄与するものもあります。 

定数 1 に寄与するものもあります。 

一次関数に寄与するものもあります$\alpha x + \beta$。 

この構造により、多項式 DP が可能になります。 確率を点ごとに再計算する代わりに、次の係数を持つ生成多項式を維持します。$t^j$まさにその確率に等しい$j$参加者のスコアは以下の通り$x$。 

係数自体は次の多項式になります。$x$。 各因子は線形であるため、すべての参加者を処理した後、ランクの係数が計算されます。$j$最大次数の多項式です$n$。 セグメント全体にわたって正確に統合できます。 

これにより、不可能な連続確率問題が正確な多項式積分に変換されます。$O(n)$セグメント。

 ## アルゴリズムのチュートリアル

 1. すべての間隔エンドポイントを収集する$l_i$そして$r_i$、それらを並べ替えて、重複を削除します。 

これらのエンドポイントは、数直線をセグメントに分割し、各確率式が固定代数形式になります。 
2. 各参加者を処理する$i$独立して。 

参加者の順位の確率分布を計算します$i$。 
3. 連続するエンドポイントのペアごとに$[a,b]$、このセグメントのみを考慮してください。 

参加者の場合$i$の間隔はこのセグメントと重なりません。参加者がいるためスキップします。$i$その中でスコアを取得することはできません。 
4. このセグメント内では、参加者の密度を表します$i$のスコア。 

以来$i$のスコアは均一です:$$f_i(x)=\frac{1}{r_i-l_i}$$これは間隔上一定です。 
5. 他の参加者全員に対して$k$、の形を決定します$$p_k(x)=P(s_k < x)$$現在のセグメント内。 

可能性は 3 つだけです。$$0,\quad 1,\quad \frac{x-l_k}{r_k-l_k}$$6. 参加者を対象とした DP を構築します。 

させて：$$dp[j][d]$$の係数を示します$x^d$確率を表す多項式では、正確に$j$参加者のスコアは以下の通り$x$。 

最初に:$$dp[0][0]=1$$7. 各参加者の処理$k \ne i$。 

現在の生成多項式を次のように乗算します。$$(1-p_k(x)) + p_k(x)t$$の係数$t^j$その確率を正確に追跡します$j$参加者は以下です$x$。 

以来、$p_k(x)$は線形であり、係数は低次の多項式のままです。 
8. すべての参加者を処理した後、係数は正確に対応します$j-1$スコアが小さいほど、参加者がその確率密度を高くします。$i$ランクがある$j$。 
9. この多項式をセグメント上で積分します。 

もし：$$P(x)=\sum c_d x^d$$それから：$$\int_a^b P(x)\,dx = \sum c_d \frac{b^{d+1}-a^{d+1}}{d+1}$$10. 回答マトリックスに貢献度を追加します。 

### なぜ効果があるのか

 参加者を修正する$i$スコア値を修正します$x$。 条件付きでオン$s_i=x$、他のすべての参加者は独立して以下のスコアのいずれかを獲得します$x$以上$x$。 生成多項式は、参加者数が以下に該当する分布を正確にエンコードします。$x$。 

の係数$t^{j-1}$まさにその確率に等しい$j-1$参加者のスコアは以下の通り$x$、参加者を意味します$i$ランクがある$j$。 

実数直線分割により、すべての確率式が 1 つのセグメント内で線形であることが保証されるため、DP 係数は通常の多項式になります。 各セグメントにわたる正確な統合により、すべての可能な値にわたる無条件確率が蓄積されます。$s_i$。 

セグメントは重複することなくサポート全体をカバーしているため、すべてのセグメントの寄与を合計すると、正確な最終的な確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    L = []
    R = []

    for _ in range(n):
        l, r = map(float, input().split())
        L.append(l)
        R.append(r)

    pts = sorted(set(L + R))

    ans = [[0.0] * n for _ in range(n)]

    for i in range(n):

        for s in range(len(pts) - 1):
            a = pts[s]
            b = pts[s + 1]

            if a == b:
                continue

            left = max(a, L[i])
            right = min(b, R[i])

            if left >= right:
                continue

            length_i = R[i] - L[i]

            # dp[j][d] = coefficient of x^d
            dp = [[0.0] * (n + 1) for _ in range(n + 1)]
            dp[0][0] = 1.0

            processed = 0

            for k in range(n):
                if k == i:
                    continue

                len_k = R[k] - L[k]

                # p(x) = A*x + B
                if right <= L[k]:
                    A = 0.0
                    B = 0.0
                elif left >= R[k]:
                    A = 0.0
                    B = 1.0
                elif L[k] <= left and right <= R[k]:
                    A = 1.0 / len_k
                    B = -L[k] / len_k
                else:
                    # because all breakpoints are endpoints,
                    # partial overlap cannot happen here
                    A = 0.0
                    B = 0.0

                ndp = [[0.0] * (n + 1) for _ in range(n + 1)]

                for j in range(processed + 1):
                    for d in range(processed + 1):

                        cur = dp[j][d]
                        if abs(cur) < 1e-15:
                            continue

                        # multiply by (1 - p)
                        ndp[j][d] += cur * (1.0 - B)
                        ndp[j][d + 1] += cur * (-A)

                        # multiply by p * t
                        ndp[j + 1][d] += cur * B
                        ndp[j + 1][d + 1] += cur * A

                dp = ndp
                processed += 1

            density = 1.0 / length_i

            for rank in range(n):
                poly = dp[rank]

                val = 0.0

                for d in range(n + 1):
                    c = poly[d]
                    if abs(c) < 1e-15:
                        continue

                    val += c * (
                        (right ** (d + 1) - left ** (d + 1))
                        / (d + 1)
                    )

                ans[i][rank] += val * density

    for i in range(n):
        print(*["{:.10f}".format(x) for x in ans[i]])

solve()
```最初の部分では、すべての間隔を読み取り、すべてのエンドポイントを収集します。 これらのエンドポイントは、確率式が変更できる唯一の場所を定義します。 

参加者ごとに$i$、アルゴリズムは、連続するエンドポイント間のすべての基本セグメントを反復します。 1 つのセグメント内では、すべての比較確率は線形です。$x$、これは多項式 DP を有効にする重要なプロパティです。 

DP には、単純な確率ではなく多項式係数が格納されます。 他の参加者が確率を提供する場合$A x + B$、乗算:$$(1-p(x)) + p(x)t$$小規模な参加者の数と多項式の次数の両方を更新します。 

実装では、次の係数が慎重に分離されます。$x^d$ランク数の次元から。 この区別を見逃していることは、数学をコードに変換するときに最もよくある間違いです。 

もう 1 つの微妙な点は、重複分類です。 すべてのセグメントの境界は間隔の終点であるため、セグメント内の参加者は、線形確率で完全に下回る、完全に上になる、または完全にアクティブになることしかできません。 他のジオメトリは使用できません。 

最終的な統合は正確です。 各係数は多項式項であるため、セグメントにわたる積分には標準のべき乗積分公式のみが必要です。

def solve():

        L.append(l)
        R.append(r)

            b = pts[s + 1]

            right = min(b, R[i])

            if left >= right:
                continue

            dp = [[0.0] * (n + 1) for _ in range(n + 1)]
            dp[0][0] = 1.0

            processed = 0

                if k == i:
                    continue

                lenk = R[k] - L[k]

                    A = 0.0
                    B = 0.0
