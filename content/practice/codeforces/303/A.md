 ## 問題の理解

 3 つの順列を構築するように求められます$a$、$b$、 そして$c$長さの$n$すべてのインデックスに対して$i$の合計$a[i]$そして$b[i]$モジュロ$n$等しい$c[i]$モジュロ$n$。 各順列には、0 から 0 までの数字が正確に含まれます。$n-1$1 回であり、出力はそのようなトリプルまたは$-1$解決策が存在しない場合。 

入力は単一の整数で構成されます$n$。 このタスクは建設的なものであり、単なる「はい/いいえ」の決定ではありません。 以来$n$と同じ大きさにすることができます$10^5$制限時間は 2 秒であるため、すべての順列を生成したり、すべてのトリプルをチェックしたりする解決策は、直ちに実行不可能になります。 この制約は、線形または線形算術的な解が必要であることを意味します。$n$。 

次の場合には、明らかではないエッジケースが発生します。$n$は均等です。 たとえば、次の場合$n=2$、総当たりチェックにより、剰余和条件を満たすトリプルが存在しないことがすぐにわかります。 のために$n=1$、解決策は簡単です。すべての順列は次のとおりです。$[0]$。 パリティを考慮せずに単純な式を一律に適用しようとする不注意な試みは、小さな偶数では失敗します。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべての順列を列挙しようとします。$n$のために$a$そして$b$そして計算します$c[i] = (a[i] + b[i]) \mod n$。 かどうかを確認しています$c$必要な有効な置換です$O(n)$候補者ごとに。 順列の合計数は、$n!$、このアプローチは完全に非現実的です$n>5$。 のために$n = 10^5$、これは実行可能な計算をはるかに超えています。 

重要な洞察は、モジュロ演算が線形オフセットに対して適切に動作するということです。 定義すると$a[i] = i$そして$b[i] = (k \cdot i) \mod n$一定の$k$、構築を試みることができます$c[i] = (a[i] + b[i]) \mod n$そして、それが有効な順列を形成しているかどうかを確認します。 さらなる調査により、この式は次の場合にのみ機能することが明らかになりました。$n$奇数です。 奇数の場合$n$、シンプルな選択$b[i] = (n-i) \mod n$保証する$c[i] = (a[i] + b[i]) \mod n$それ自体が順列です。 もし$n$が均等であれば、衝突は避けられず、解決策は存在しないことがわかります。 この観察により、検索スペースが大幅に削減され、線形時間の構築が可能になります。

 ## アルゴリズムのチュートリアル

 1. 入力された整数を読み取ります$n$。 
2. Check the parity of$n$。 もし$n$偶数、出力$-1$この場合には置換トリプルが存在しないため、停止します。 
3. 順列の構築$a$自然な順序として$[0, 1, 2, ..., n-1]$。 これにより、$a$すべての数字が順番に含まれます。 
4. 順列の構築$b$シーケンスとして$[0, n-1, 1, n-2, 2, n-3, ...]$、両端から交互に。 これにより、次のすべての要素が保証されます。$b$ユニークであり、組み合わせられています$a$モジュロ$n$別の順列が得られます。 奇数のより単純な等価式$n$は$b[i] = (2*i) \% n$。 
5. 構築する$c$を使用して$c[i] = (a[i] + b[i]) \% n$。 施工により、$c$奇数の順列であることが保証されています$n$。 
6. 印刷$a$、$b$、 そして$c$順番に。 

なぜ機能するのか: 重要な不変条件は、奇数の場合$n$、2 を乗算したモジュロ$n$は全単射です。 したがって、使用して$b[i] = (2*i) \mod n$それを保証します$c[i]$0 から 0 までのすべての数字を受け取ります$n-1$順列特性を維持しながら、正確に 1 回。 モジュロ演算は奇数であるため、きれいにラップアラウンドされます。$n$偶数の約数がないため、衝突が回避されます。
