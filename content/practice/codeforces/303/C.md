 ## 解決策
 ## 問題の理解

 一連の個別の整数が与えられます。 せいぜい削除するかもしれません`k`それらのうち、どこで`k ≤ 4`。 削除後、残りのすべての数値が正の整数を法として異なる剰余を生成するようにします。`m`。 

2 つの数値がモジュロで衝突する`m`ちょうどその差が で割り切れるとき`m`。 それで、条件は$$a_i \bmod m \ne a_j \bmod m$$残りのペアごとに、残りのペアには割り切れる差がないということと同じです。`m`。 

タスクは最小の正を見つけることです`m`これは最大でも削除した後に可能になります`k`数字。 

制約によってソリューションが完全に形作られます。 まであります`5000`数値は、すべての可能なモジュライにわたって二次関数を即座に除外します。 数字自体は最大でも`10^6`、したがって、ペアごとの差は最大で`10^6`あまりにも。 すべてのモジュラスとすべてのペアを単純に検索すると、すでに大規模すぎます。 

重要な詳細は、`k`小さいです。 最大 4 つの番号を削除できます。 パラメーターが非常に小さい問題は、多くの場合、グラフの問題や、不良要素をめぐる分岐の問題になります。 

見落としやすいエッジケースがいくつかあります。 

考慮する：```
3 0
1 2 3
```答えは`3`、 ない`1`。 

モジュロ`1`、すべての数字は次のようになります`0`, したがって、すべてのペアが衝突します。 小さな係数が常に機能することを前提とした不用意な実装は、ここで失敗します。 

もう一つの微妙なケース:```
5 1
0 5 10 11 12
```のために`m = 5`、数字`0`、`5`、 そして`10`全部衝突する。 少なくとも 2 つの番号がまだ残っているため、1 つの番号だけを削除するだけでは十分ではありません。 競合するすべてのペアから 1 つのエンドポイントを個別に削除する貪欲な戦略では、1 つの削除で十分であると誤って考えられてしまいます。 

3 番目の重要なシナリオは、最適な係数が多くの差よりも大きい場合です。```
4 0
0 2 3 6
```答えは`5`。 

小さな係数は、ペアの差がそれらで割り切れるため、失敗します。 一度`m`問題となるすべての約数を超えると、衝突はなくなります。 最適な答えは、必ずしもすべての数値の合計の gcd に関連しているわけではありません。 

最後に、いつ`k ≥ n-1`、常に最大 1 つの番号を保持できます。 単一の数値は何にも衝突しないため、答えは次のようになります。`1`。 

例：```
3 2
5 100 1000
```2 つの番号を削除して 1 つだけを残すこともできます。`m = 1`すでに機能しています。 

## アプローチ

 ブルートフォースの観点は単純です。 固定モジュラスの場合`m`、剰余によってグループを構築します`a_i mod m`。 複数の数値を含むグループでは競合が発生します。 せいぜい削除するかどうかを尋ねます`k`数値はすべての衝突を破壊することができます。 

1 つの係数を確認するには大まかに時間がかかります`O(n)`ハッシュを使用します。 問題は、どれくらいの大きさかわからないことです`m`できる。 すべての係数を 1 つずつ試すのは絶望的です。 

本当の観察は、条件を書き換えることから得られます。 

2 つの数値がモジュロで衝突する`m`次の場合にのみ:$$m \mid (a_i - a_j)$$したがって、固定モジュラスの場合、すべての不良ペアは次で割り切れる差に対応します。`m`。 

ここでグラフを考えてみましょう。 頂点は数値です。 2 つの頂点の差が次の値で割り切れる場合、2 つの頂点を接続します。`m`。 せいぜい削除したい`k`エッジが残らないように頂点を調整します。 それはまさに頂点カバー問題です。 

通常、頂点カバーはハードですが、このグラフのソリューション サイズは小さいため、`k ≤ 4`。 これは、標準的な分岐で解決できることを意味します。 任意のエッジを選択します`(u,v)`。 有効なソリューションはいずれかを削除する必要があります。`u`または`v`。 両方の選択肢を再帰的に実行します。 分岐の深さは最大で`4`、したがって、検索ツリーのサイズは最大でも`2^4 = 16`。 

これにより、問題は次のように縮小されます。 

「どのモジュールをテストする価値がありますか?」

 係数は、ペアごとの差を除算する場合にのみ重要です。 係数を仮定します`m`有効です。 したがって、すべての対立エッジは、次の数で割り切れる差異から生じます。`m`。 

If we delete at most`k`少なくとも頂点`n-k`数字は残っています。 残りの数値のうち、すべてのペアごとの差はゼロ以外であり、次の数で割り切れません。`m`。 

次に、生き残った番号を 1 つ取ります`x`。 すべての削除された番号は、それ自体に関わる競合を排除できますが、生存者間の競合はすでに存在していない必要があります。 削除は 4 つだけ許可されているため、競合に最大で 4 つの削除が含まれる生存者が存在します。`k`他の数字。 

つまり、もし`m`は多くの割り算関係があるため無効ですが、すぐに検出できます。 

これを悪用する標準的な方法は、ランダム化された削減です。 いくつかのランダムなピボットを選択します。 ピボットごとに`a_i`、すべての有効な係数は、何らかの差を除算する必要があります`|a_i-a_j|`問題のあるのはほんの一部だけ`j`。 数の約数の数は次のとおりです。`10^6`列挙できるほど小さいです。 

したがって、いくつかのサンプリングされた要素を含むペアごとの差分の約数から候補モジュライを生成します。 候補モジュラスごとに、有界頂点カバー チェックを実行します。 

サンプリングされた差分の約数の合計数は管理可能なままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのモジュールに対するブルート フォース |$O(M \cdot n)$|$O(n)$| 遅すぎる |
 | 候補約数 + 有界頂点カバー |$O(S \cdot n \cdot d + C \cdot (n^2 + 2^k))$|$O(n^2)$最悪の場合 | 承認済み |

 ここ、`S`はサンプリングされたピボットの数です。`d`は差当たりの約数の数であり、`C`候補モジュライの数です。 

## アルゴリズムのチュートリアル

 1. 数字を読んで、些細なケースに対処する`k >= n-1`。 

1 つの要素を除くすべての要素を削除できれば、次のようなあらゆる係数が機能します。`1`。 
2. 配列をランダムにシャッフルします。 

このアルゴリズムは、いくつかのピボット要素のサンプリングに依存しています。 ランダム化により、少なくとも 1 つのサンプリングされた要素が、最適解の生き残った大規模なセットに属する可能性が非常に高くなります。 
3. いくつかのサンプリングされたピボットについて、他のすべての数値との差を計算します。 

ピボットの場合`x`、すべての値`|x-a_j|`有効な係数となる可能性のある約数を示します。 
4. これらの違いの約数をすべて列挙します。 

モジュラスが相互に衝突を引き起こす場合、`x`そして`a_j`, then it must divide their difference. したがって、潜在的に有用なすべての係数はこれらの約数の中に現れます。 
5. ゼロより大きいすべての個別の候補係数を収集します。 

同じ約数が異なる違いから何度も現れることがあります。 セットで保管してください。 
6. Sort candidates increasingly.

 最小有効係数が必要なので、最初に小さい候補をテストします。 
7. For each candidate modulus`m`、競合グラフを暗黙的に構築します。 

2 つのインデックスの差が次で割り切れる場合、競合します。`m`。 
8. 制限付きの境界頂点カバー検索を実行します。`k`。 

競合するペアを見つける`(u,v)`。 

有効な削除セットは、このエッジの少なくとも 1 つのエンドポイントを削除する必要があるため、次のように再帰します。 

- 削除`u`- 消去`v`残りの予算を 1 つ減らします。 
9. 競合するペアが残っていない場合、モジュラスは有効です。 

最初に見つかった有効な候補が最小の答えになります。 

### なぜ効果があるのか

 すべての衝突モジュロ`m`は競合グラフのエッジに正確に対応します。 すべての残りが明確になるまで数値を削除することは、グラフのエッジがなくなるまで頂点を削除することと同じです。 

残りのエッジは少なくとも 1 つのエンドポイントを失う必要があるため、再帰的分岐は正しいです。 再帰では、どのエンドポイントを削除するかについて考えられるすべての選択肢が調査されるため、有効な解決策を見逃すことはありません。 

候補生成ステップが機能するのは、関連するすべての係数が少なくとも 1 つのペアごとの差を除算する必要があるためです。 いくつかのピボットをサンプリングすることにより、高い確率で、最適なソリューションに残る要素が選択されます。 その要素に関係するすべての矛盾する係数は、他の数値との差の約数の中に現れるため、最適な係数が生成され、テストされます。 

## Python ソリューション```python
import sys
import random
from math import isqrt

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    if k >= n - 1:
        print(1)
        return

    random.shuffle(a)

    candidates = {1}

    samples = min(n, 25)

    for i in range(samples):
        x = a[i]

        for y in a:
            d = abs(x - y)

            if d == 0:
                continue

            r = isqrt(d)

            for t in range(1, r + 1):
                if d % t == 0:
                    candidates.add(t)
                    candidates.add(d // t)

    candidates = sorted(candidates)

    def valid(mod):
        edges = []

        for i in range(n):
            ai = a[i]

            for j in range(i + 1, n):
                if (ai - a[j]) % mod == 0:
                    edges.append((i, j))

        def dfs(pos, rem, removed):
            while pos < len(edges):
                u, v = edges[pos]

                if removed[u] or removed[v]:
                    pos += 1
                else:
                    break

            if pos == len(edges):
                return True

            if rem == 0:
                return False

            u, v = edges[pos]

            removed[u] = True
            if dfs(pos + 1, rem - 1, removed):
                removed[u] = False
                return True
            removed[u] = False

            removed[v] = True
            if dfs(pos + 1, rem - 1, removed):
                removed[v] = False
                return True
            removed[v] = False

            return False

        removed = [False] * n
        return dfs(0, k, removed)

    for mod in candidates:
        if valid(mod):
            print(mod)
            return

solve()
```このソリューションには 2 つの独立した部分があります。 

最初の部分では、候補モジュールを生成します。 ピボットの小さな無作為サンプルからペアワイズ差の約数のみを調べます。 約数を列挙するには`O(sqrt(d))`、違いが最大であるため高速です。`10^6`。 

2 番目の部分では、係数が実行可能かどうかを確認します。 洗練されたグラフ構造を明示的に構築する代わりに、実装では競合するすべてのペアをエッジとして単純に保存します。 

再帰関数は、境界のある頂点カバーを実行します。 重要な詳細は、最初のスキップ ループです。```
while pos < len(edges):
```削除された頂点によってすでに覆われているエッジは無視されます。 最初のカバーされていないエッジを見つけたら、1 つのエンドポイントを削除する必要があります。 

再帰の深さは最大でも`k ≤ 4`、そのため、枝分かれした木は小さなままになります。 

実装上の微妙な点の 1 つは、`removed`再帰呼び出しのたびに慎重に配列してください。 削除を元に戻すのを忘れると、兄弟ブランチが破損する可能性があります。 

もう一つの微妙な点は、候補者を含めることです`1`。 十分な数を削除できた時点で、すでに有効になっている可能性があります。
