 ## 解決策
 ## 問題の理解

 幅の長方形の絵が与えられます$w$そして高さ$h$。 2 つの同一の正方形の光源が、この長方形の左右の垂直辺に配置されます。 各光源は正確に 90 度の角度領域を照らし、各光の中心方向は水平です。つまり、各ビームは水平軸を中心に 45 度の角度で上下に対称的に広がります。 

左側のライトは高いところに設置されています$y_1$左側の境界線に、右側のライトが高さに配置されます$y_2$右側の境界線にあります。 長方形内のすべての点は、2 つの 90 度の光円錐の少なくとも 1 つの内側にある場合、点灯しているとみなされます。 タスクは、長方形のすべての点が 2 つのライトの少なくとも 1 つで覆われているかどうかを判断することです。 

重要な問題は、各ライトが単に垂直または水平のストリップを照らすわけではないことです。 代わりに、それぞれが三角形の影響領域を作成し、その垂直方向の範囲は、ソースから水平方向に遠ざかるにつれて直線的に拡大します。 

入力サイズの制約が小さいため、$w, h \le 10^6$これにより、グリッドの離散化やすべてのポイントのブルート フォース スキャンが即座に排除されます。 どのような解決策でも、ジオメトリを一定数のチェックに減らすか、閉じた形式の条件を導き出す必要があります。 

単純なアプローチでは、各垂直スライスに沿ってカバレッジをシミュレートしようとする可能性があります。$x$、点灯間隔を保つ$y$- 座標とその和集合がセグメント全体をカバーしているかどうかを確認する$[0, h]$。 これは失敗します。$O(w)$スライスとインターバルのマージが遅すぎます。 

さらに微妙な問題は、適用範囲が継続的に変化することです。$x$。 照射領域の形状は区分的に線形であるため、重要な遷移がどこで発生するかを理解せずに、いくつかの代表的な位置だけをチェックすることは明らかに安全ではありません。 

## アプローチ

 垂直座標を固定すると$x$、左側のランプの中心が$(0, y_1)$垂直座標を満たすすべての点を照明します。$$|y - y_1| \le x.$$それで位置的には$x$、間隔に貢献します$[y_1 - x, y_1 + x]$。 

同様に右のランプも$(w, y_2)$満足のいくポイントを照らします$$|y - y_2| \le w - x,$$間隔を与える$[y_2 - (w - x), y_2 + (w - x)]$。 

それぞれに$x$、これら 2 つの間隔の結合はセグメント全体をカバーする必要があります。$[0, h]$。 同様に、垂直方向の隙間があってはなりません。$x$。 最も高い下端点が最も低い上端点よりも高い場合、ギャップが存在します。 

そこで次のように定義します。$$L(x) = \max(y_1 - x, \; y_2 - w + x),$$

$$R(x) = \min(y_1 + x, \; y_2 + w - x).$$すべての場合に限り、長方形が完全に覆われます。$x \in [0, w]$、 我々は持っています$L(x) \le R(x)$。 

次に、これらの関数の構造を観察してください。 両方$L(x)$そして$R(x)$はそれぞれ 2 つの一次関数から形成されます。 最大 2 行は V 字関数、最小 2 行は逆 V 字関数です。 これは、条件が$L(x) \le R(x)$アクティブなラインが変化する点、つまり、max または min 内の 2 つの式が交差する点でのみ切り替えることができます。 

それにより、無限に多くの問題が軽減されます$x$値を一定数の候補点のみに設定します。 

重要な$x$-座標は次のとおりです。 

エンドポイント$x = 0$そして$x = w$、および交点は次のとおりです。$$y_1 - x = y_2 - w + x \quad \Rightarrow \quad x = \frac{y_1 - y_2 + w}{2},$$

$$y_1 + x = y_2 + w - x \quad \Rightarrow \quad x = \frac{y_2 - y_1 + w}{2}.$$不等式の確認$L(x) \le R(x)$任意の 2 つの連続する臨界点の間には、両方の点が存在するため、これらの位置で十分です。$L(x)$そして$R(x)$は線形であるため、それらの差も線形であり、終点でゼロを越えることなく符号を変更することはできません。

 ## アルゴリズムのチュートリアル

 1. 4 つの候補位置を計算します$x = 0$、$x = w$、$x_1 = (y_1 - y_2 + w)/2$、 そして$x_2 = (y_2 - y_1 + w)/2$。 これらは、補償範囲の構造が変更される可能性がある唯一の点です。 
2. 候補者を無視する$x$それはセグメントの外側にあります$[0, w]$、これらの位置は長方形の有効な垂直スライスに対応していないためです。 
3. 有効な候補者ごとに$x$、可能な限り低い照明境界を計算します。$L(x)$可能な限り高い照明境界線$R(x)$。 これにより、そのスライスでの垂直カバレッジ間隔が得られます。 
4. 候補点が見つかった場合$L(x) > R(x)$の場合、そのスライスには垂直方向のギャップが存在します。 これは、長方形の内側に覆われていない領域があることを意味するため、答えは即座に「いいえ」になります。 
5. 候補点がすべて満たされている場合$L(x) \le R(x)$の場合、それらの間に隙間は形成されないため、長方形は完全に覆われ、答えは「はい」になります。 

### なぜ効果があるのか

 固定でのカバレッジ$x$は、各ライトからの 2 つの線形制約によって決定されます。 それらの包絡線は、ペアごとの交差ごとに最大 1 つの構造変化を伴う区分的線形関数を形成します。 下部エンベロープと上部エンベロープは両方とも 2 つのラインから構築されているため、考えられるすべてのトランジションは、それらのラインの端点と交差点によって決まります。 これらのポイント間では、アクティブな制約の順序は変更されないため、カバレッジ違反はサンプリングされた位置の 1 つですでに表示されている必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(w, h, y1, y2):
    def eval_ok(x):
        # coverage interval at vertical slice x
        L = max(y1 - x, y2 - w + x)
        R = min(y1 + x, y2 + w - x)
        return L <= R

    candidates = [
        0,
        w,
        (y1 - y2 + w) / 2,
        (y2 - y1 + w) / 2
    ]

    for x in candidates:
        if 0 <= x <= w:
            if not eval_ok(x):
                return False
    return True

def main():
    w, h, y1, y2 = map(int, input().split())
    print("Yes" if check(w, h, y1, y2) else "No")

if __name__ == "__main__":
    main()
```実装は、一定の臨界点への削減の直後に行われます。 ヘルパー関数は、位置で垂直スライスかどうかを評価します。$x$照らされた下部境界と上部境界の間にギャップがあります。 

唯一の微妙な点は、候補交差点に浮動小数点演算を使用することです。 ここでは、値を線形式に代入した後でのみ比較するため、これは安全です。また、精度要件は、次の値までの浮動小数点精度の範囲内に十分収まります。$10^6$。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    w, h, y1, y2 = map(int, input().split())

    def ok(x):
        L = max(y1 - x, y2 - w + x)
        R = min(y1 + x, y2 + w - x)
        return L <= R

    cand = [0, w, (y1 - y2 + w) / 2, (y2 - y1 + w) / 2]
    for x in cand:
        if 0 <= x <= w and not ok(x):
            print("No")
            return
    print("Yes")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio
    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples
assert run("5 2 1 1\n") == "Yes"
assert run("4 4 1 2\n") == "No"

# custom cases
assert run("2 2 1 1\n") == "Yes"   # minimal tight symmetric
assert run("10 10 1 9\n") == "Yes" # high separation still covered
assert run("6 6 1 1\n") == "No"    # gap in middle region
assert run("3 10 5 5\n") == "Yes"  # symmetric center case

 ## 特殊なケース

 両方のライトが同じ高さにある場合、微妙なケースが発生します。 その状況では、エンベロープの交点が対称的な位置に崩れ、唯一考えられる失敗は中間点になります。 アルゴリズムは両方の候補交点を明示的に評価します。この場合、それらは一致するため、チェックは有効なままです。 

別のエッジケースは、一方のライトが他方よりも著しく高い場合に発生します。 臨界点は厳密に内側にあります$(0, w)$、単純なエンドポイントのみのチェックでは、カバーされていない領域を見逃してしまいます。 交点を評価すると、下のエンベロープが 1 つのライトから別のライトに優勢を切り替えるこの正確な遷移がキャプチャされます。
