 ## 解決策
 ## 問題の理解

 一連の本のタイトルが与えられ、各タイトルは整数のリストになります。 各整数は大きなアルファベットの文字を表します。 すべての文字は、小文字と大文字の 2 つの形式で表示されます。 大文字バージョンは辞書編集上、すべての小文字より小さいとみなされ、それぞれの場合において順序は文字の数値に従います。 

許可される唯一の操作は、文字値 x を選択し、すべてのタイトルで出現するすべての x を同時に大文字に変換することです。 この操作は何度でも適用できますが、すべての変換後にタイトルのシーケンスが辞書順で減少しないように、大文字にする文字のサブセットを選択する必要があります。 

タスクは、そのようなサブセットが存在するかどうかを判断し、存在する場合は有効なサブセットを出力することです。 

重要な制約は、文字列を自由に並べ替えていないことです。 グローバル文字タイプを反転することのみが許可されています。 これにより、すべての単語が結合され、問題は隣接する文字列ペアにわたるグローバルな一貫性条件に変わります。 

入力サイズは大きく、すべてのタイトルで合計シンボル数は最大 100,000 です。 これにより、文字のすべてのサブセットをシミュレートしたり、構成ごとに比較を最初から再計算したりするアプローチは即座に除外されます。 どのような解も、全長が線形または線形に近いものでなければなりません。 

微妙なエッジケースとして、同じタイトルが繰り返されることがあります。 2 つの連続するタイトルが小文字形式で同一である場合でも、大文字の選択に応じて厳密な辞書編集上の正確性を確保する必要がある可能性があり、将来の制約の実現可能性を確認せずに等価性が常に安全であると誤って仮定することは避けなければなりません。 

2 つの単語の間の方向を決定するときに、別の注意が必要なケースが発生します。最初の異なる位置を誤って解決すると、グローバル大文字化が強制され、後で以前に満足していた順序が崩れてしまう可能性があります。 

## アプローチ

 ブルートフォースの観点では、文字のすべてのサブセットを大文字に変換することを検討します。 各サブセットについて、すべての単語を変換し、シーケンスがソートされているかどうかを確認します。 これは問題の定義に直接従うので正しいですが、m では指数関数的であり、具体的には O(2^m · total_length) であり、制限をはるかに超えています。 

重要な観察は、実際にはすべての文字を独立して決定する必要はないということです。 決定が重要となるのは、隣接する 2 つの単語が異なる位置だけです。 2 つの単語の間に最初の不一致がある場合、最終的なアルファベット順で前の単語が辞書編集的に後の単語以下であることを確認する必要があります。 

これにより、形式の制約が作成されます。単語が文字 a と b で異なる位置 j では、最終的な順序付けで a < b を強制するか、a > b の場合は比較を反転するのに十分な大文字化を強制する必要があります。 大文字は小文字よりも全体的に小さいため、文字 x を大文字にすることを選択すると、比較において x が効果的に小さくなります。 

したがって、各制約は、文字を大文字として扱う必要があるかどうかに関する強制的な順序付け条件になります。 重要なのは、これらの制約は変数間の任意の不等式ではないということです。 それらは、各不一致を満たすために文字が「大文字セット」に属している必要があるかどうかについての意味を持ちます。 

単語を順番に処理し、隣接するペアからのみ制約を抽出します。 各ペアについて、最初の異なる位置までスキャンします。 辞書編集順では後続の文字が無視されるため、この位置によって 2 つの単語の比較が完全に決まります。 一方の単語が他方の単語の接頭辞である場合、制約は必要ありません。

文字 a と b の不一致については、現在の決定に基づいて実現可能性を確認します。 正しい順序がすでに保証されている場合は、続行します。 それ以外の場合は、一貫した方法で a が大文字になるか、b が小文字のままになるように強制する必要があります。 これは当然のことながら、競合から派生した強制的な大文字のセットを維持することになります。 矛盾が出てくると答えられなくなります。 

これにより、問題はすべての単語のすべての文字を 1 回通過し、隣接するペアごとに制約が蓄積されます。

 ## アルゴリズムのチュートリアル

 大文字である必要がある一連の文字を維持しながら、単語のリストを左から右に処理します。 

1. 各単語を次の単語と比較し、異なる最初の位置を見つけます。 この位置は、2 つの単語間の辞書編集上の順序に影響を与えることができる唯一の場所です。 
2. 異なる位置が存在しない場合は、短い単語が最初に来る必要があります。 前の単語が長い場合、大文字は接頭辞構造を変更できないため、大文字小文字に関係なく順序付けは不可能です。 その場合は即時お断りさせていただきます。 
3. 最初の異なる文字が単語 i の a と単語 i+1 の b であると仮定します。 現在の大文字決定の割り当ての下で a < b が成り立つかどうかを判断します。 大文字は常にどの小文字よりも小さいため、効果的な比較は、a または b が大文字セットに含まれるかどうかによって異なります。 
4. 現在の状態がすでに a < b になっている場合は、何もしません。 そうでない場合は、変更を強制する必要があります。 これを修正するには辞書編集的に 2 つの方法があります。1 つは大文字にする (小さくする)、または a が大文字または小さい順序で b が小文字のままになるようにするかのいずれかです。 大文字化を文字ごとにグローバルに制御するだけなので、必要な順序を強制する一貫した修正を選択し、その制約を記録します。 
5. 大文字でなければならない文字をマークすることで、この制約を反映します。 手紙がすでに矛盾した状態に強制されている場合、私たちは停止して戻ることは不可能です。 
6. すべての隣接するペアを処理した後、大文字としてマークされたすべての文字を出力します。 

重要な不変条件は、i 番目のペアの処理後、以前のペアから派生したすべての制約が満たされ、将来の制約はそのペアの最初の不一致のみに依存するため、後の文字の影響を受けることがないということです。 それぞれの決定によって文字のグローバル プロパティが修正され、文字が大文字にマークされると、すべての比較においてその文字が一貫して維持されます。 

すべての強制マーキングは 2 つの隣接する単語間の具体的な辞書編集違反の解決に直接対応するため、アルゴリズムは誤検知を生成できません。 実行可能な解はすべての最初の不一致制約を満たさなければならず、これらはまさに私たちが収集する制約であるため、偽陰性を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    words = []
    for _ in range(n):
        arr = list(map(int, input().split()))
        k = arr[0]
        words.append(arr[1:])

    forced = [False] * (m + 1)

    def is_upper(x):
        return forced[x]

    def compare(a, b):
        # returns True if a <= b under current assumption:
        # uppercase letters are "smaller class"
        i = 0
        la, lb = len(a), len(b)
        while i < la and i < lb:
            x, y = a[i], b[i]
            if x == y:
                i += 1
                continue
            # compare x and y under rule
            if is_upper(x) != is_upper(y):
                # uppercase is smaller
                return is_upper(x) or not is_upper(y)
            return x < y
        return la <= lb

    def needs_fix(x, y):
        # returns constraint direction if a pair is bad at first mismatch
        i = 0
        la, lb = len(x), len(y)
        while i < la and i < lb and x[i] == y[i]:
            i += 1
        if i == min(la, lb):
            if la > lb:
                return ("impossible", None)
            return None
        a, b = x[i], y[i]
        return (a, b)

    changed = True
    for _ in range(5):
        changed = False
        for i in range(n - 1):
            res = needs_fix(words[i], words[i + 1])
            if res is None:
                continue
            if res[0] == "impossible":
                print("No")
                return
            a, b = res

            # if already safe under forced rule, skip
            if is_upper(a) and not is_upper(b):
                continue
            if (not is_upper(a)) and is_upper(b):
                continue

            # enforce: make a uppercase
            if not forced[a]:
                forced[a] = True
                changed = True

    # final verification pass
    for i in range(n - 1):
        a, b = words[i], words[i + 1]
        i2 = 0
        la, lb = len(a), len(b)
        while i2 < la and i2 < lb and a[i2] == b[i2]:
            i2 += 1
        if i2 == min(la, lb):
            if la > lb:
                print("No")
                return
            continue
        x, y = a[i2], b[i2]
        # uppercase rule check
        if forced[x] == forced[y]:
            if x > y:
                print("No")
                return
        else:
            if not forced[x] and forced[y]:
                print("No")
                return

    ans = [i for i in range(1, m + 1) if forced[i]]
    print("Yes")
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```この実装は、隣接する単語間の最初の不一致を抽出し、それを文字の制約に変換するという考えに従っています。 の`forced`配列は、どの文字が大文字として選択されるかを表します。 比較ロジックは、大文字が小文字よりも全体的に小さいという事実に基づいています。 

繰り返しの緩和ループは間接的な効果を伝播する簡単な方法ですが、より洗練された実装では単一パスで制約を処理することでこれを回避できます。 最終的な検証では、構築された割り当てが実際にすべての隣接条件を尊重していることを確認します。 

## 実用的な例

 変更せずに順序付けがすでに満たされている小さなシーケンスを考えてみましょう。 

入力:```
2 3
1 1
2 1 2
```最初の単語を比較します`[1]`と`[1,2]`。 最初の単語が終わるまで一致し、接頭辞であるため制約は追加されません。 このアルゴリズムでは強制的な文字は生成されず、シーケンスは有効なままです。 

トレース:

 | ペア | 最初の不一致 | アクション | 強制 |
 | --- | --- | --- | --- |
 | 1-2 | なし (プレフィックス) | なし | 空 |

 これは接頭辞の規則を示しており、短い単語を最初に置くのが常に安全です。 

次に、強制的な変更が必要な場合を考えてみましょう。 

入力:```
2 3
1 2
1 1
```比較します`[2]`そして`[1]`。 位置 0 には 2 と 1 があります。数値順では 2 > 1 であるため、辞書編集的には最初の単語の方が大きくなります。 これを修正するには、順序付け時に 2 を大文字にして 1 より小さくする必要があります。 

トレース:

 | ペア | 不一致 | アクション | 強制 |
 | --- | --- | --- | --- |
 | 1-2 | 2 対 1 | 力2 | {2} |

 2を強制した後、注文は有効になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ある単語が、より前の長い単語の厳密な接頭辞である場合です。 例えば`[2,1]`に続く`[2]`。 比較は 2 番目のワードがなくなるとすぐに終了します。 最初の単語が長いため、大文字を使用しても短い単語が最初に来なければならないという事実を修正できず、答えは不可能です。 アルゴリズムはプレフィックス チェックでこれを検出し、正しく拒否します。 

別の特殊なケースは、同じ単語が繰り返されることです。 すでに非減少順序を満たしているため、制約は生成されません。 強制された文字は後で矛盾を引き起こしてはならず、アルゴリズムは厳密な不一致が発生した場合にのみ制約を追加することでこれを維持します。 

最後のエッジケースは、1 つの不一致を修正すると以前の比較に影響を与える依存関係の連鎖です。 各文字の決定はグローバルであり、常に強化されるだけ (決して弱められることはない) ため、アルゴリズムが変動することはありません。 各強制は、以前の制約を無効にすることなく、より多くの制約を満たすよう厳密に進められます。
