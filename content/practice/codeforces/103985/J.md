 ## 解決策
 ## 問題の理解

 負ではない整数のリストが与えられ、それぞれがグループ内の個人に割り当てられた値を表します。 タスクは、「グループの凝集度」のグローバルな尺度を計算することです。これは、人々の値のビットごとの AND の、順序付けされていないすべてのペアの合計として定義されます。 

具体的には、異なるインデックスのペアごとに$i < j$、私たちは取る$a_i \& a_j$、これらの値をすべてのペアにわたって合計します。 出力は単一の整数です。 

の制約$n$最大 150,000 に達し、各値は次のように大きくなります。$10^8$。 直接のペアごとの計算には約$n^2 / 2$この規模では次の規模のオペレーションになります。$10^{10}$、合理的な制限時間をはるかに超えています。 これにより、二次解は即座に除外されます。 

値の境界は次のとおりです。$10^8$、27ビット以内に収まります。 つまり、ビットごとの分解アプローチは最大 30 ビット位置を安全に反復できるため、ビットごとのカウント戦略が妥当になります。 

素朴なアプローチの微妙な障害モードは、整数のオーバーフローや、同じ寄与を複数回誤って再計算することです。 もう 1 つのよくある間違いは、ペアごとのビットごとの関係を保持しないソートによって最適化しようとすることです。 

たとえば、すべての数値が同じである場合、次のようにします。$[7,7,7]$、すべてのペアが貢献します$7$、したがって、答えは次のとおりです$3 \cdot 7 = 21$。 ペア数を考慮せずに「重複を圧縮」しようとする間違ったアプローチでは、多重度のカウントを簡単に間違える可能性があります。 

## アプローチ

 ブルート フォース ソリューションはすべてのペアに対して反復されます。$(i, j)$そして計算します$a_i \& a_j$。 これは問題の定義に直接従うため、単純かつ正確です。 ただし、そのコストは次のように二次関数的に増加します。$n$、150,000 個の要素を使用すると、100 億を超える演算が必要になりますが、これは現実的ではありません。 

重要な点は、ビット単位の AND 演算がビット間で独立していることです。 ビットは、ペアの両方の数値に設定されている場合にのみ、最終的な合計に寄与します。 これは視点を逆転することを示唆しています。つまり、ペアを反復処理する代わりに、寄与を少しずつカウントします。 

ビット位置を修正する$b$。 このビットが設定されている数値がいくつあるかを数えます。$c_b$。 このような数値の任意のペアが寄与します$2^b$最終的な合計に、そのようなペアの数は$\binom{c_b}{2}$。 すべてのビットを合計すると答えが得られます。 

これにより、問題がペアの列挙からビットの頻度カウントに変換され、複雑さが大幅に軽減されます。

 ## アルゴリズムのチュートリアル

 各ビットに含まれる数値の数を維持しながら配列を処理します。 

1. 配列を初期化する`cnt`サイズ 31 (以下の値に十分)$10^8$）。 各位置には、そのビットが設定されているこれまでに確認された数値の数が格納されます。 この構造により、ビット周波数を段階的に追跡できます。 
2. 各数値を反復処理します。$x$入力で。 ビット位置ごとに$b$0から30まで、ビットがあるかどうかを確認してください$b$に設定されています$x$。 そうであれば、インクリメントします`cnt[b]`。 これにより、すべての数値を処理した後、`cnt[b]`は、そのビットに寄与する要素の総数に等しくなります。 
3. 数えた後、すべてのビット位置を反復して答えを計算します。 ビットごとに$b$、 もし`cnt[b] >= 2`、それから、$\binom{cnt[b]}{2}$このビットに寄与するペア。 
4.追加$\binom{cnt[b]}{2} \cdot 2^b$最終的な答えへ。 これにより、そのビットを共有するすべてのペアの合計寄与が再構築されます。 
5. 累計を出力します。 

重要なステップは、寄与をビットごとに分離することです。これにより、二重カウントが回避され、各ペアがビットごとに 1 回だけ考慮されるようになります。 

### なぜ効果があるのか

 各ペア$(i, j)$両方の数値が 1 である場合、各ビットに独立して寄与します。固定ビットの場合、寄与は、そのビットを含む数値の数にのみ依存し、その識別子には依存しません。 したがって、各ビット グループ内のインデックスのペアをカウントすると、ペアを列挙することなく合計が正確に再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    cnt = [0] * 31
    
    for x in a:
        b = 0
        while x:
            if x & 1:
                cnt[b] += 1
            x >>= 1
            b += 1
    
    ans = 0
    for b in range(31):
        c = cnt[b]
        if c >= 2:
            ans += (c * (c - 1) // 2) * (1 << b)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、固定ループで 31 ビットすべてをチェックするのではなく、数値ごとに直接ビット スキャンを使用します。 これにより、操作が厳密に保たれ、ゼロテールに対する不必要なビット チェックが回避されます。 

主な微妙な点は、各ビット位置がそのインデックスと正しく位置合わせされていることを確認することです。`cnt`。 変数`b`数値をシフトしながらビットインデックスを追跡します。

 ## 特殊なケース

 単一要素の入力の場合、次のようになります`1\n5`、アルゴリズムは数値のビット数を設定しますが、少なくとも 2 のビット数に達することはありません。 毎`cnt[b]`は最大でも 1 であるため、すべての二項寄与が消えて 0 が生成され、ペアが存在しないという事実と一致します。 

次のような同一の要素の場合`3\n7 7 7`、7 のすべてのビットが 3 回カウントされます。 各ビットが貢献します$\binom{3}{2} \cdot 2^b$。 ビットを合計すると、3 つのペアにわたって正確に 3 つの 7 のコピーが再構築され、ペアごとの定義と直接一致します。 

次のような互いに素なビットセットを持つ数値の場合`1 2 4`、すべてのビットは正確に 1 つの数値に現れるので、すべて`cnt[b] ≤ 1`、どのペアもビットを共有しないことを意味します。 このアルゴリズムは、すべてのペアのすべての AND が 0 であるという事実と一致して、正しく 0 を返します。
