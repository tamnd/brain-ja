微妙な点は、ノードの再訪問は許可されていますが、同じ方向のエッジの再訪問は許可されていないことです。 これにより、無限の正のサイクルの可能性が排除されますが、以前にすでに順方向に使用されていたエッジの逆方向を使用する一時的な迂回が可能になります。

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、ノードに向かって値を伝播したいと仮定します。$n$。 

各エッジを処理します$(u, v, p, q)$DFS の方向を固定すると、自然な方向性を持つようになります。 親から子へ移動する場合、その方向に応じて、対応する有向ウェイトが適用されます。 重要なのは、最終的な答えは、ルートに対してトラバースをどのように方向付けるかによってのみ決まるということです。 

DP値を計算します$dp[v]$ノードから開始して達成可能な最良の合計を意味します$v$ノードに向かって下ります$n$すでにそのサブツリーに入っていると仮定して、そのサブツリー内に$v$。 

また、最終的に到達するパスのみを考慮する必要があるという事実も維持します。$n$, したがって、以下を含まないサブツリーは$n$上昇を続ける前に返還できる利益を提供する場合にのみ貢献します。 

1. ノード 1 でツリーをルートし、ノードを見つけます$n$DFS中。 これが必要なのは、$n$メインパスにとって重要な要素もあれば、回り道としてのみ貢献するものもあります。 
2. ノードごとに、そのサブツリーにノードが含まれるかどうかを計算する DFS を実行します。$n$。 これにより、ターゲットに向かうメイン ルート上にどの子パスが存在するかが決まります。 
3. DFS 中に、ノード間の各エッジに対して$u$そして子供$v$、サブツリーが存在するかどうかに応じて、このエッジの寄与を計算します。$v$含まれています$n$。 
4. もし$v$のサブツリーには以下が含まれます$n$の場合、最適なルートは最終的に次のとおりになるはずです。$v$そして上に戻るか、下に向かって進み続けます$n$。 この場合、エッジをメイン パスの一部として扱い、次の方向への移動と一致する方向をとります。$n$。 
5. もし$v$のサブツリーには次のものが含まれていません$n$、その後、へのトラバース$v$に戻らなければなりません$u$。 この場合、オプションで 2 つの方向のうち良い方を使用して往復してから戻ることができ、これにより次の利益が得られます。$\max(p, q)$往路の場合と、必要に応じて対応する戻りのコストがかかりますが、戻りは必須であるため、代わりにこれを純利益としてモデル化します。$\max(p, q) - \text{cost back in opposite direction}$これにより、使用可能な最適な方向の選択が簡素化されます。 
6. すべての子供たちからの貢献を上向きに伝播しながら蓄積します。 DP は、各サブツリーが独立して最適な迂回利益を提供することを保証します。 
7. 最終的な答えは、1 から 1 までのパスに沿って累積された値です。$n$、すべての有益な回り道を含みます。 

重要な不変条件は、すべてのノードについて、$dp[v]$各サブツリーは独立して解決され、ツリーによって強制される単一入口、単一出口の構造を通じてのみ結合されるため、「各有向エッジを最大 1 回使用する」というルールに違反することなく、そのサブツリーから得られる最大の追加利益を正確に表します。 

これが機能するのは、パスが継続しない限り、ツリー内のウォークはサブツリーに入り、内部トラバースを実行し、同じエッジを通って戻るセグメントに分解できるためです。$n$。 This decomposition ensures no interleaving between subtrees breaks optimality.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        u, v, p, q = map(int, input().split())
        g[u].append((v, p, q))
        g[v].append((u, q, p))
    
    parent = [-1] * (n + 1)
    contains = [False] * (n + 1)
    dp = [0] * (n + 1)
    
    def dfs(u):
        contains[u] = (u == n)
        for v, p, q in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            dfs(v)
            if contains[v]:
                contains[u] = True
        
        for v, p, q in g[u]:
            if v == parent[u]:
                continue
            if contains[v]:
                dp[u] += p
            else:
                dp[u] += max(p, q)
    
    parent[1] = 0
    dfs(1)
    
    print(dp[1])

if __name__ == "__main__":
    solve()
```隣接リストは両方向を明示的に格納するため、ツリーを無向として扱うことができますが、スワップによって方向の重みは保持されます。$(p, q)$エッジを反転するとき。 

DFS はまず、パス上にどのノードがあるかを計算します。$n$これは、必須のエッジとオプションの迂回を区別するために不可欠です。 次に、2 番目の累積ステップで寄与を割り当てます。$n$側枝のエッジは、親から子への強制的な方向に取られますが、側枝のエッジは往復方式で横断する必要があるため、より適切な方向を選択することで最適化に寄与します。 

微妙な部分は、使用された場合にすべての側枝が正確に 1 回出入りすることを保証するためにツリー構造に依存していることです。$\max(p, q)$は、その迂回に対して可能な限り最良の 1 つの横断方向を正確にモデル化します。

 ## 特殊なケース

 重要なエッジ ケースは、ターゲット ノードがルートに直接接続されている場合です。 この状況では、他のすべてのブランチは純粋にオプションの迂回であり、メイン エッジを妨げてはなりません。 サブツリーにターゲットが含まれる子のみが強制方向付けに寄与するため、アルゴリズムはこれを正しく処理します。 他のすべては独立して評価されます$\max(p, q)$。 

もう 1 つのケースは、すべてのエッジの重みが負の場合です。 単純な戦略ではエッジを完全に回避する可能性がありますが、1 から 2 へのパスは存在しないため、$n$が必須である場合でも、アルゴリズムは各ステップで最もダメージの少ない方向を選択します。 各エッジは 1 回だけ処理されるため、すべての寄与が負の場合でも、結果は最適なままになります。 

最後の微妙なケースは、分岐を下って戻ることで有益なサイクルが可能であるように見えるときに発生します。 ツリー構造は、各有向エッジが最大 1 回消費されるため、反復利用を防止します。そのため、DP は各迂回を単一のゲインに正しく制限します。
