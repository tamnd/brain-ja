 ## 解決策
 ## 問題の理解

 私たちには一組の王子と一組の王女が与えられています。 各プリンセスは、一定の持参金と、結婚する意思のある特定の王子 2 人を持って到着します。 彼女を最終的な取り決めに使用する場合、彼女はこれら 2 人の王子のうちの 1 人と正確に一致する必要があります。 各王子は最大 1 人のプリンセスとマッチングでき、各プリンセスは最大 1 回使用できます。 王子や王女を無視するのも自由です。 

目標は、王子と王女の組み合わせが複数回使用されないように、有効な王子と王女の組み合わせのサブセットを選択し、選択した王女の持参金の合計が最大になるようにすることです。 

これは、単位重量を使用した標準的な 2 部マッチングではありません。 主な違いは、各プリンセスが重みを提供し、彼女の 2 つの可能なエッジがそれぞれ同等に有効であることです。 右側の各ノード (プリンセス) の次数がちょうど 2 である一般的なグラフでマッチングを選択しており、最大の重みマッチングが必要です。 

この制約により、最大 200,000 人の王子と 200,000 人の王女が許可されるため、3 次または 2 次のアプローチさえも直ちに不可能になります。 m がすでに大きいため、O(nm) を考えても失敗します。 これにより、おそらく O(n + m) または O((n + m) log n) の線形または線形に近いグラフ処理が行われるようになります。 

素朴な解釈では、プリンセスのすべてのサブセットを試すか、最大重みの 2 部マッチングを実行することを提案するかもしれません。 この規模ではそれは不可能です。 

複数のお姫様が同じ王子をめぐって争う場合、微妙な問題が発生します。 たとえば、2 人の高価値プリンセスの両方にプリンス 1 がオプションに含まれている場合、貪欲な選択により全体的により良い構成がブロックされる可能性があります。 

入力:

 n = 1、m = 2

 プリンセス 1: (1, 1) ai ≠ bi なので無効なので、次のように調整します。 

プリンセス 1: (1、2、100)

 プリンセス 2: (1, 2, 1)

 グローバル構造を考慮しない素朴な貪欲スキームで小さい方を最初に選択すると、値 100 の最適なマッチングが失われる可能性があります。競合の構造はグローバルであり、体系的に処理する必要があります。 

## アプローチ

 総当たりで考えると、各プリンセスは第一王子、第二王子とマッチングするか、スキップすることができます。 これはすでに、ノードごとに最大 3 の分岐係数があり、指数関数的な複雑さにつながることを示唆しています。 有効なマッチングに限定したとしても、基本的には一般的なグラフ内のすべてのマッチングを列挙することになり、エッジの数とともに指数関数的に増加します。 

より構造化された強引な方法は、これを一般的なグラフの最大重み一致問題として扱うことです。 これはブロッサム アルゴリズムで解決できますが、ここでのグラフは特別です。すべての王女はちょうど 2 の次数を持ち、王子は二部構成のような構造の片側を形成しますが、制約があるのは片側だけです。 

重要な観察は、王子たちが形成したグラフが恣意的ではないということです。 各プリンセスは正確に 2 つのプリンスを接続しているため、各プリンセスは 2 つのプリンス ノード間のエッジとして見ることができ、重みを持ちます。 王子が複数の選択されたエッジに付随しないように、これらのエッジのサブセットを選択して、合計の重みを最大化します。 これはまさに、頂点を王子、辺を姫とする一般的なグラフにおける最大重み合わせ問題である。 

ただし、より深い構造が表示されます。すべての頂点 (プリンス) がエッジ (プリンセス) に接続されており、このグラフで一致するものを選択しています。 重要な単純化は、グラフをコンポーネントごとに処理できることです。 このグラフの各連結成分は、王子と王女が交互に現れることで形成されますが、各王​​女は次数 2 を持ち、王子は任意の次数を持つことができるため、構造は一般的なグラフですが、重要な特性も備えています。エッジは頂点上の独立した選択であり、制約は頂点の非結合性のみです。

これは古典的な最大重みマッチングの問題ですが、最悪の場合の敵対的な意味でグラフが恣意的ではないため、ここでは扱いやすくなります。 これは、重みによる貪欲プロセスと和集合検索または DSU ベースの縮小アイデアを組み合わせて使用​​することで解決できます。エッジを降順に処理し、両方のエンドポイントがまだ空いている場合は貪欲にエッジを取得します。 

洞察としては、各頂点 (プリンス) は 1 回しか使用できないため、重みの高いエッジを選択すると、それらの頂点に付随する将来のエッジがブロックされるということです。 エッジを降順で処理すると、常に重い寄与を最初に優先することが保証され、マッチング制約に違反することなく、以前に選択された重いエッジを後のエッジが改善できないため、構造を再検討する必要がありません。 

これにより、この問題は、重みを増加させる交互パスの改善が存在しないため、貪欲な順序付けが最適であるグラフ上の古典的な最大重みマッチングに帰着します。この特定の左 2 度構造では、この問題が維持されます。

 ## アルゴリズムのチュートリアル

 私たちは各プリンセスを、持参金と同等の重みを持つ 2 人の王子の間のエッジとして扱います。 総重量を最大化する一連の互いに素なエッジを選択したいと考えています。 

1. 各プリンセスをエッジ (ai、bi、wi) に変換します。 これにより、エンドポイントを共有せずに重み付けされたエッジを選択するという問題が再構成されます。 この変換は、物語の問題をグラフ最適化の問題に変えるため、不可欠です。 
2. すべてのエッジを重みの降順に並べ替えます。 これにより、エッジを検討するときはいつでも、より重いエッジがすべてすでに決定されていることが保証されます。 直感的には、高い値のエッジが実現可能な場合は、より低い値の競合するエッジよりも前にそのエッジを取得する必要があると考えられます。 
3. 各王子のブール配列 used[v] を維持し、王子がすでに一致しているかどうかを示します。 最初はすべてが偽です。 
4. ソートされた順序でエッジを反復処理します。 各エッジ (u、v、w) について、両方のエンドポイントが未使用かどうかを確認します。 両方が空いている場合は、エッジを選択し、両方のエンドポイントを使用済みとしてマークします。 それ以外の場合はスキップしてください。 
5. 選択したすべてのエッジの重みの合計を累積して出力します。 

### なぜ効果があるのか

 正しさは、エッジの順序付けに関する交換引数から得られます。 貪欲な解決策とは異なる最適な解決策を検討してください。 最適解ではなく貪欲アルゴリズムによって選択された最も重いエッジに注目してください。 そのエッジは、その端点の 1 つが別のエッジに一致することによって、最適解でブロックされる必要があります。 ソートのため、そのブロッキング エッジの重みは現在のエッジ以下である必要があります。 ブロッキング エッジを現在のエッジに置き換えても、総重量は減らず、実現可能性が維持されます。 この変換を繰り返すと、貪欲な解は損失なく最適な解に変換できるため、その重みが最適になることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    edges = []
    
    for _ in range(m):
        a, b, w = map(int, input().split())
        edges.append((w, a, b))
    
    edges.sort(reverse=True)
    
    used = [False] * (n + 1)
    ans = 0
    
    for w, a, b in edges:
        if not used[a] and not used[b]:
            used[a] = True
            used[b] = True
            ans += w
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべてのプリンセスを重み付けされたエッジとして読み取ります。 重量による選別は、世界的な優先順位を強制する重要な構造的ステップです。 の`used`配列は、各王子が最大 1 つの選択されたエッジに参加するというマッチング制約を強制します。 

微妙な実装の詳細は、Python のデフォルトのソートが降順で直接機能するように、最初に重みをタプルに格納することです。 もう 1 つの重要な点は、エッジを決して再訪しないことです。 エンドポイントが使用されると、それを永久に除外します。これは貪欲不変条件と一致します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の高重量エッジが 1 つのプリンスを共有する場合です。 たとえば、多くのプリンセスに王子 1 が含まれている場合、フリーのパートナーと組み合わせると、その中で最も重みの高いプリンセスのみが選択される可能性があります。 貪欲な順序付けにより、そのような最も重いエッジが最初に考慮され、そのプリンスがロックされ、その後の選択が防止されます。 

もう 1 つのエッジ ケースは、わずかに軽い重みのエッジが 2 つの中程度のエッジを間接的に有効にする場合です。 このようなシナリオでも、重いエッジを遅延させることで利点を得るには、同じエンドポイントを含む複数のエッジでそれを置き換える必要がありますが、各プリンスが参加するエッジは多くても 1 つであるため、これは不可能です。 頂点が一度消費されると、将来の構成でそれを再利用できないため、アルゴリズムはこれを自然に処理し、遅延ゲインは存在しません。
