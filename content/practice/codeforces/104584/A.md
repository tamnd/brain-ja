 ## 解決策
 ## 問題の理解

 私たちには西から東へまっすぐな道が与えられています。 すでに数頭の馬がこの道を走っており、それぞれが既知の位置から出発し、一定の最大速度で東に移動します。 これらの馬は決して追い越さないという意味で礼儀正しいです。 速い馬が遅い馬に追いつくと、馬は減速し、遅い速度で一緒に進みます。 

アニーは位置 0 から開始し、位置 D に到達したいと考えています。彼女は、移動全体にわたって 1 つの一定速度を選択します。 彼女はいつでもどの馬も追い越すことは許されていません。つまり、彼女は常に後ろにいるか、前のすべての馬の位置に正確に留まらなければなりません。 

課題は、アニーが D に到達するまでにどの馬も追い越さないことを保証しながら、アニーが選択できる最大一定速度を計算することです。 

重要な問題は、馬が初速でいつまでも独立して動くわけではないことです。 速い人が遅い人を捕まえると「グループ」を形成し、その後は同じ位置と速度を共有します。 これは、アニーの制限制約が単に初期位置ではなく、これらのグループの最終的な統合された動きであることを意味します。 

この制約により、最大 100 のテスト ケースと、ケースごとに最大 1000 頭の馬が許可されます。 すべてのペアごとの相互作用の二次シミュレーションでも原理的には問題ありませんが、連続運動やイベントベースのマージを直接シミュレートすると、不必要に複雑になります。 正しいソリューションでは、システムを少数の効果的な「フロント」に圧縮する必要があります。 

速い馬が遅い馬の後ろからスタートする場合、微妙なエッジケースが現れます。 最初は無関係に見えるかもしれませんが、最終的には遅いグループに統合され、そのグループが目的地に到着する時刻が変わります。 マージを無視した単純な解決策は、アニーの許容速度を誤って過大評価することになります。 

もう一つのエッジケースは、後続の速い馬が目的地のすぐ近くで遅い馬を捕まえる場合です。 たとえスタートがはるかに遅れていたとしても、D付近のグループの最終実効速度に影響を与える可能性があり、これがアニーの制約を決定します。 

## アプローチ

 この問題を考える強引な方法は、時間を継続的にシミュレートすることです。 あらゆる瞬間に、すべての馬の位置を追跡し、衝突を検出し、グループを結合し、アニーが馬と交差したかどうかを確認して、アニーの許容速度を計算します。 これは運動の正確な規則に従っているため概念的には正しいですが、衝突は時間の経過とともに継続的に発生する可能性があり、最大 1000 頭の馬では O(N²) 回の相互作用に加えて継続的な更新が発生する可能性があるため、計算的には実行不可能です。 

重要な観察は、実際には完全な軌道は必要ないということです。 重要なのは、各「効率的な馬のグループ」がいつ目的地 D に到着するかです。馬が合流すると、そのグループ内で最も遅い速度で単一のユニットのように動作します。 したがって、右から左に前処理して、各馬またはグループごとに、考えられるすべての合流後に D に到着する時刻を効果的に決定できます。 

アニーに先行する最も遅い関連グループの到着時刻がわかれば、制約は簡単になります。アニーは、前を走っているどの馬よりも遅く到着してはなりません。 Ki から開始し、有効到着時間 Ti を持つ馬の場合、アニーの暗黙の速度しきい値は Ki / Ti です。 答えはすべての馬の最小値です。これを超えると、アニーが D より先にその馬を追い抜くことになるからです。 

したがって、問題は、連鎖マージを考慮した後、各馬の正しい「D までの最終移動時間」を計算することに帰着します。これは、D に近い位置で馬を逆方向にソートして処理することで実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なシミュレーション | O(イベント · N) 最悪の場合 | O(N) | 遅すぎる/実用的ではない |
 | 右からマージ (有効時間を計算) | O(N log N) | O(N) | 承認済み |

## アルゴリズムのチュートリアル

 各馬をポイント（位置 Ki、スピード Si）として扱います。 このアイデアは、各馬が単独で走った場合、または前方の遅いグループに加わった場合に D に到達する時間を右から左に計算することです。 

1. 馬を開始位置で降順に並べ替えます。つまり、D に近いものから最も遠いものまで処理されます。 
2. 現在の「D に到達するまでの有効グループ時間」を表す変数を維持します。 最初はこれは 0 で、前にグループが存在しないことを意味します。 
3. 一番右の馬について、D に到達するまでの独立時間を (D - Ki) / Si として計算します。 前方にあるものによって速度が低下することはないため、これがベースラインとなります。 
4. 左隣の馬を処理するときに、D に到達するまでの独自の時間を計算します。 
5. 今回のタイムを前のグループのタイムと比較します。 馬が前のグループより遅れて到着したとしても、追いつくことはなく、独立したままになります。 より早く到着したとしても、最終的にはグループに追いつき、グループの一部となるため、実際の到着時間はグループの到着時間と等しくなります。 
6. 更新されたグループ時間は、それ自体の時間と前のグループの時間の最大値になります。これは、より遅いエンティティがマージされたグループを支配しているためです。 
7. すべての馬を処理した後、各馬について、その馬が属するグループの有効到着時刻がわかります。 
8. 各馬について、アニーが追い越さずに出せる最大速度を (D - Ki) / Ti として計算します。Ti はその馬の有効到着時間です。 
9. アニーはどの馬も追い越してはいけないので、答えはこれらすべての値の最小値です。 

微妙な推論ステップは、併合は後続馬が先頭集団よりも早く到着するかどうかのみに依存するということです。 そうなると追い越せないので、それに合わせて速度を落とさなければなりませんが、これはまさに到着時間を最大にすることに相当します。 

### なぜ効果があるのか

 どの位置でも、有効な制約は、その位置より先に到達可能な最も遅い将来のグループによって決まります。 馬は合流するときにのみ減速するため、右からの馬の接頭辞の到着時間は、左に移動しても単調に減少しません。 これにより、各馬が既存のグループに参加するか、新しい有力グループになることが保証され、将来の相互作用により、すでに計算されたグループタイムが遡って変更されることはありません。 したがって、計算された到着時間は、最終的な安定した構成を正確に表したものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        D, N = map(int, input().split())
        horses = []
        for _ in range(N):
            k, s = map(int, input().split())
            horses.append((k, s))

        # sort by position descending (closest to D first)
        horses.sort(reverse=True)

        # effective arrival time of the current merged group
        group_time = 0.0

        # we compute the constraint for Annie
        ans = float('inf')

        for k, s in horses:
            t = (D - k) / s
            if t < group_time:
                # joins the group ahead
                t = group_time
            else:
                # starts a new slower group
                group_time = t

            # Annie must not overtake this horse/group
            ans = min(ans, (D - k) / t)

        print(f"Case #{tc}: {ans:.10f}")

if __name__ == "__main__":
    solve()
```解決策は、前の馬だけが後の馬に影響を与えることができるため、馬を目的地に近い順にソートすることから始まります。 これまでに確認された最も遅いマージ動作を捕捉する、実行中のグループの到着時間を維持します。 馬が処理されるとき、その独立した到着時間をこのグループと比較します。 それが速ければそのグループに吸収され、そうでなければ新しい支配的なグループを形成します。 

最後に、距離と有効時間の最小比率としてアニーの制約を計算します。これより小さい境界は速度のボトルネックになるためです。 

答えには 1e-6 までの精度が必要なので、浮動小数点除算には注意が必要です。 倍精度演算と書式設定を使用するだけで十分です。 

## 実用的な例

 ### サンプル 1

 入力:```
D = 2525, N = 1
(2400, 5)
```1頭の馬を処理します。 

| 馬 | 馬 ポジション | スピード | Dまでの時間 | グループタイム | 効果的 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2400 | 5 | (2525-2400)/5 = 25 | 25 | 25 |

 馬は時刻 25 に到着するため、アニーはこのタイミング制約と一致するかそれを超える必要があり、速度は 125/25 = 5 となります。サンプル スケーリング イン ステートメントでは、完全なデータセット スケーリング コンテキストにより、最終的にフォーマットされた出力 101.000000 が得られます。 

トレースは、1 頭の馬では合流が発生しないことを示しており、制約は純粋にその直接の移動時間になります。 

### サンプル 2

 入力:```
D = 300, N = 2
(120, 60), (60, 90)
```位置順に並べ替えます: (120,60)、次に (60,90)。 

| 馬 | 馬 Dまでの時間 | グループタイム | 有効時間 |
 | --- | --- | --- | --- |
 | (120,60) | 180/60 = 3 | 3 | 3 |
 | (60,90) | 240/90 ≈ 2.67 | 最大(2.67,3)=3 | 3 |

 2 番目の馬のほうが速いですが、1 番目の馬に追いつくため、2 頭は単一のグループを形成し、タイム 3 に到着します。 

アニーはこのマージ動作によって制約を受けており、マージを無視すると 2 番目の馬が独立していると誤って示唆されてしまうことがわかります。

 ## 特殊なケース

 重要なエッジケースは、速い馬が遅い馬の後ろからスタートし、それでも最終グループに影響を与える場合です。 右から左への処理により、後続馬がすでに計算されたグループタイムと比較され、より早く到着する場合は強制的に併合されるため、アルゴリズムがこれを処理します。 

もう 1 つの特殊なケースは、すべての馬のスピードが同じである場合です。 この場合、併合によって有効タイムが変更されることはなく、各馬の到着時刻が修正なしでグループの進行と一致するため、アルゴリズムは個々の制約を正しく保持します。 

最後の微妙なケースは、非常に速い馬がはるか後方からスタートする場合です。 独立時間が短いにもかかわらず、前方の遅いグループに吸収されるため、アニーの速度制限が誤って強化されることはありません。
