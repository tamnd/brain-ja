 ## 解決策
 ## 問題の理解

 最大 100 の都市を含む有向グラフが与えられます。 いくつかの都市の間には一定距離の一方通行の道路があり、各都市には馬も所有されています。 馬には 2 つの属性があります。1 つは使用できなくなるまでに移動できる最大総距離、もう 1 つは一定の速度です。 

旅人はある都市から、その都市の馬を使って出発します。 都市に到着すると、現在の馬で続行することも、現在の都市の馬に即座に切り替えることもできます。 馬が一度使用されると、使用中の移動距離によって残りの耐久力が永久に減少します。 目標は、2 つの都市間の最小移動時間を求める複数の独立したクエリに答えることです。 

重要な相互作用は、時間が距離と現在選択されている馬の両方に依存することです。エッジで費やした時間は、エッジの距離を現在使用している馬の速度で割ったものに等しいためです。ただし、持久力の制約により、その馬を使用し続けることができる距離が制限されます。 

制約は十分に小さいので、$N \le 100$、テスト ケースごとに最大 100 個のクエリを含めることができます。 これは、全ペアまたは複数ソースの最短経路構造が妥当であることを直ちに示唆しています。 ただし、州は単なる都市ではなく、暗黙的に現在使用されている馬でもあるため、単純な最短経路モデリングが複雑になります。 

ディクストラで各都市を独立して扱うという素朴な試みは、到着した都市が州を完全に説明していないため失敗します。 同じ都市に到着する 2 頭の残り耐久力や現馬が異なる場合、将来の可能性がまったく異なる可能性があります。 

2 番目の微妙な失敗例は、より強い馬が実際に劣っている場合に発生します。早めに切り替えると速度は上がるかもしれませんが、有用な次の都市に到達するには残りの持久力が少なすぎるため、余分な切り替えが必要になります。 これにより、貪欲なローカル決定が不正確になります。 

## アプローチ

 ブルートフォースの観点では、各状態を現在の都市、現在の馬、および残りの耐久力から構成されるトリプルとして扱うことです。 このような状態から、耐久性が許せば、距離を速度で割った値に等しいコストで、すべての往路を横断することができます。 ノードに到達したら、必要に応じてその都市の馬に切り替え、耐久力をその馬の最大能力にリセットできます。 

このモデルは正しいですが、すぐにサイズが爆発的に大きくなります。 各都市は、原則として連続的な、多くの可能な残りの耐久値と組み合わせることができます。 意味のあるブレークポイントに離散化されたとしても、遷移は依然として非常に大きくなります。 拡張された状態に対する単純なダイクストラは、簡単に次のようになります。$O(N^2 \cdot E)$が遅すぎます。 

重要な構造的洞察は、「耐久性がどのくらい残っているか」を明示的に追跡する必要がないということです。 重要なのは、現在使用している馬の正体と、特定の馬を使用しているときに各都市に到達するのに最適な時間だけです。 

馬を固定すると、移動は重み付きエッジを使用した標準的な最短経路問題になりますが、その馬では持久力を超える合計距離を移動することはできないという制約があります。 これは 2 レベルの DP を示唆しています。出発馬の考えられる選択ごとに、ノードに到着するたびに切り替えを許可しながら、すべてのノードまでの最適な移動時間を計算します。 

持久力を連続状態として扱うのではなく、単一の馬のセグメントを使用するパスに沿ってのみ持久力が消費されることが観察されます。 したがって、問題は次のようになります。都市のペアごとに$u, v$、最後に馬に切り替えた場合、ベストタイムはいつですか$u$ある時点で、おそらく中間ノードで再び切り替えるまで、その馬を使用して移動しました。 

これは標準的な緩和構造につながります。つまり、都市上の距離配列を維持し、再度切り替えるまでのパス セグメント全体に特定の馬を使用することに対応して移行が行われます。 これを整理する正しい方法は、フロイドのような都市でのリラックスですが、出走馬に応じて重みを付けます。 

具体的には、（馬を無視して）距離のみの観点から全ペアの最短距離を事前計算し、セグメントのアクティブな馬として特定の馬を使用して各状態がベストタイムを表す 2 番目の DP を使用します。 なぜなら$N \le 100$、私たちは余裕があります$O(N^3)$スタイルのソリューション。 

修正されたフロイド-ウォーシャルを 2 回実行します。最初は生の距離で、次に馬ごとの制約で時間どおりに実行します。 馬の出発地として機能する各都市について、その馬を使用して到達可能なすべての都市への移動をシミュレートし、距離を速度で割ったものとして時間を累積し、累積距離が持久力を超えない場合にのみ移行を許可します。 これは、開始ノードごとの距離の上限を尊重しながらベストタイムを追跡することで、Floyd に組み込むことができます。 

より明確な定式化は、すべてのペアの最短距離を事前に計算してから、都市ごとに計算することです。$i$から最短移動時間を計算します。$i$みんなに$j$馬を使って$i$中間ノード上の DP を距離の実現可能性順に並べます。 最後に、馬の選択に関してフロイド スタイルの組み合わせを実行します。どの都市でも、その馬に切り替えて続行できます。

 ## アルゴリズムのチュートリアル

 私たちはソリューションを 2 つのレイヤーに分割します。各馬の下で使用可能な移動量を計算し、次に馬の切り替えの決定をグローバルに組み合わせます。 

1. 生の距離グラフで Floyd-Warshall を使用して、すべての都市ペア間の最短経路距離を計算します。 これにより、馬を無視した 2 つの都市間の最小距離が得られます。これは、より多くのエッジを使用しても持久力の使用には決して有益ではないため、有効です。 
2. 都市ごとに$i$、その馬をアクティブな乗り物として扱います。 からの旅行に最適な時間を計算します$i$あらゆる都市へ$j$からの総走行距離の制限のもと、$i$を超えない$E_i$、各単位距離のコスト$1 / S_i$時間。 
3. これを効率的に計算するために、事前に計算された距離行列を使用します。 馬用$i$、 もし$dist[i][j] \le E_i$、そして到達$j$から直接$i$馬と一緒に$i$費用$dist[i][j] / S_i$。 追加の中間都市を使用するパスは総距離が増加するだけであるため、これが可能な限り最良の方法です。 
4. これを行列として保存します$time[i][j]$、 どこ$time[i][j]$～からの最速タイムです$i$に$j$馬にコミットするなら$i$そのセグメントに対して。 
5. 中間都市で馬を切り替えることができるようになりました。 時間の経過とともに 2 番目のフロイド スタイルのリラクゼーションを計算します。$k$、から行くことができます$i \to k$馬を使って$i$、その後馬に切り替えます$k$そして続けます$j$。 移行は次のとおりです。$$time[i][j] = \min(time[i][j], time[i][k] + time[k][j])$$6. この終了後、各質問に答えます$u, v$から直接$time[u][v]$。 

### なぜ効果があるのか

 有効な行程は、スイッチ間で 1 頭の馬が継続的に使用されるセグメントに分解できます。 このような各セグメントは、その馬が選ばれる都市から始まります。 セグメント内では、速度と耐久性はパスの構造ではなく総距離のみに依存するため、使用可能な最短のルートは常に最短距離のパスになります。 2 番目の Floyd ステップは、これらのセグメントをすべての可能な順序で正しくつなぎ合わせ、馬の切り替えのすべての有効なシーケンスが表現されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, Q = map(int, input().split())

        E = [0] * N
        S = [0] * N
        for i in range(N):
            E[i], S[i] = map(int, input().split())

        dist = [[INF] * N for _ in range(N)]
        for i in range(N):
            row = list(map(int, input().split()))
            for j in range(N):
                if row[j] != -1:
                    dist[i][j] = row[j]
            dist[i][i] = 0

        for k in range(N):
            for i in range(N):
                if dist[i][k] == INF:
                    continue
                dik = dist[i][k]
                for j in range(N):
                    if dist[k][j] == INF:
                        continue
                    nd = dik + dist[k][j]
                    if nd < dist[i][j]:
                        dist[i][j] = nd

        time = [[INF] * N for _ in range(N)]
        for i in range(N):
            for j in range(N):
                if dist[i][j] <= E[i]:
                    time[i][j] = dist[i][j] / S[i]
            time[i][i] = 0.0

        for k in range(N):
            for i in range(N):
                for j in range(N):
                    if time[i][k] + time[k][j] < time[i][j]:
                        time[i][j] = time[i][k] + time[k][j]

        out = []
        for _ in range(Q):
            u, v = map(int, input().split())
            out.append(str(time[u - 1][v - 1]))

        print(f"Case #{tc}: {' '.join(out)}")

if __name__ == "__main__":
    solve()
```この実装では、最初にすべてのペアの最短距離を計算して、任意の道路パスを単一の有効エッジに分割します。 これは、耐久性チェックを単純な比較にするために必要です。$E_i$。 その後、`time`マトリックスは、各馬を固定速度のリソースとして使用して、最適な直接移動をエンコードします。 

2 番目のトリプル ループは、移動時間に関する古典的なフロイド-ウォーシャルであり、どの都市でも馬を乗り換えることができることをコード化しています。 各リラクゼーションは、中間都市への旅行を終了し、そこで馬を乗り換え、継続することに対応します。 

すべての答えは実数値であるため、浮動小数点除算には注意が必要です。 以下の条件を考慮すると、Python float を使用するだけで十分です。$10^{-6}$許容範囲。

 ## 特殊なケース

 重要なエッジ ケースは、直接エッジは存在するが、マルチホップ最短パスと比較して最適ではない場合です。 最初に Floyd-Warshall を実行しないと、局所的にエッジの重みが大きいため、実行可能な長いルートが誤って拒否される可能性があります。 前処理により、すべての耐久性チェックが真の最短距離で実行されるようになります。 

もう 1 つのエッジ ケースは、馬のスピードは非常に速いものの持久力が低い都市です。 素朴で貪欲なアプローチでは、常にそれを選択し、すぐに意味のあるものに到達できなくなります。 DP オーバースイッチングは、早期にコミットするのではなく、スイッチの完全なシーケンスを評価することでこれを回避します。 

最後に、長いチェーンが除算結果を蓄積すると、浮動小数点精度の問題が発生する可能性があります。 パスを単一の距離値に集約することで操作の数を少なく保つことで、過剰な累積誤差を防ぎます。
