 ## 解決策
 ## 問題の理解

 当社には、さまざまなモデルの列車を数日間にわたって追跡するシステムがあります。 最初は電車がありません。 毎日、特定のモデルの列車を追加または削除します。 各列車は運行と保守を交互に行います。`x_i`数日後、メンテナンスに入ります`y_i`その後、再度実行され、削除されるまで繰り返されます。 この問題では、その日に存在する列車のみをカウントして、毎日保守中の列車の数を求めます。 ある日に列車が撤去された場合、その日はメンテナンス中とはみなされません。 

入力には、最大 200,000 の鉄道モデルと 200,000 のイベント (日) が含まれます。 各列車のサイクル長`x_i + y_i`2×10^9 まで大きくすることができます。 これらの境界により、すべての列車に対する毎日の総当りシミュレーションは即座に除外されます。これは、列車が 1 日目に追加され、200,000 日目に削除された場合、すべてのサイクルをシミュレートするには数十億の操作が必要になるためです。 したがって、どのソリューションも次のように拡張する必要があります。`m`列車日数の合計ではなく、（イベントの数）。 

次の場合、微妙なエッジケースが発生します。`x_i`または`y_i`残り日数より大きいです。 たとえば、列車が遅れて追加され、そのメンテナンス期間が削除前に開始されない場合、単純なシミュレーションでは誤ってメンテナンス中としてカウントされる可能性があります。 もう 1 つのケースは、非常に短いサイクルです。 電車が毎日運行する場合、不用意に実装するとメンテナンスの回数が 2 倍になったり、始発日がずれたりする可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。アクティブなトレインのセットを維持します。 毎日、現在運行中のすべての列車を反復処理し、チェックしてその日がメンテナンス期間内かどうかを計算します。`(current_day - add_day) % (x_i + y_i) >= x_i`。 これは論理的には正しいですが、最悪の場合の複雑さは次のとおりです。`O(m × n)`。 と`m`そして`n`2×10^5 までの場合、約 4×10^10 回の演算が発生し、これでは遅すぎます。 

重要な洞察は、列車が 2 つのカテゴリに分類できることを観察することによって得られます。1 つはサイクル長が短い **高速サイクル列車**、もう 1 つはサイクル長が長い **低速サイクル列車**です。 低速走行の列車の場合、「差分配列」またはイベント キュー アプローチを使用して、メンテナンスに入る日とメンテナンスを終了する日を正確にマークできます。 高速サイクルの列車の場合、サイクル長を法とするさまざまなオフセットの数が少ないため、オフセットごとにメンテナンス中の列車の数を事前計算し、プレフィックス合計構造を使用してカウントを効率的に更新できます。 このハイブリッド アプローチにより、複雑さが軽減されます。`O(m√m)`またはそれ以上です。 

基本的に、各列車を個別にチェックできるため、総当たり攻撃は機能しますが、サイクルの長さが長くなり、シミュレーションが長すぎる場合には失敗します。 サイクルが定期的に繰り返されるという観察により、毎日繰り返すことを避け、代わりに更新を一括で処理できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m × n) | O(n) | 遅すぎる |
 | 最適 | O(m√m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 閾値を計算する`B = sqrt(m)`速いサイクルと遅いサイクルを区別するため。 どの列車でも、`x_i + y_i < B`は高速、そうでない場合は低速です。 これにより、カテゴリごとの列車の数と日数のバランスがとれます。 
2. 低速サイクルのトレインごとに、追加時に差分配列を使用してメンテナンス間隔をスケジュールします。 インターバルごとに`[start_day, end_day)`でカウンタをインクリメントします。`start_day`そしてそれをデクリメントします`end_day`。 列車が早期に廃止された場合は、それ以上の間隔を設定するのを中止します。 
3. 高速サイクルの列車の場合、サイズの配列を事前計算します。`cycle_length`サイクルの各日にメンテナンス中の列車の数を表します。 トレインが追加されると、適切なオフセットが増加し、トレインが削除されると、同じオフセットが減少します。 これにより、任意の日を素早く検索できます。`(day - add_day) % cycle_length`。 
4. 毎日について`t`一連のイベントにおいて、保守中の列車の総数は、次の差分配列の合計になります。`t`(鈍行列車の場合) その日のすべての高速サイクル アレイの合計に加えます。 この合計を出力します。 
5. 列車が撤去されたときに構造を更新し、将来の日に列車の不在が正しく反映されるようにします。 

機能する理由: 低速走行列車は実際にメンテナンスが行われる日のみ明示的に追跡されるため、不必要な日をシミュレートすることはありません。 周期性の特性を利用して、高速サイクル列車はオフセット モジュロ サイクル長によって追跡されます。 これら 2 つのメカニズムを組み合わせることで、毎日の正しいメンテナンス数が保証されます。 不変条件は次のとおりです。すべての低速列車は正確なメンテナンス日にのみ寄与し、すべての高速列車は事前に計算されたサイクル配列に従って寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def main():
    n, m = map(int, input().split())
    xy = [tuple(map(int, input().split())) for _ in range(n)]
    events = [tuple(map(int, input().split())) for _ in range(m)]
    
    B = int(m**0.5) + 1
    slow = []
    fast = defaultdict(list)
    
    # classify trains
    for i, (x, y) in enumerate(xy):
        if x + y >= B:
            slow.append(i)
        else:
            fast[i] = [0]*(x+y)
    
    diff = [0]*(m+2)
    add_day = [None]*n
    
    for day, (op, k) in enumerate(events):
        k -= 1
        if op == 1:
            add_day[k] = day
            x, y = xy[k]
            if k in fast:
                for i in range(x, x+y):
                    fast[k][i % (x+y)] += 1
            else:
                t = day + x
                while t < m:
                    l = t
                    r = min(t+y, m)
                    diff[l] += 1
                    diff[r] -= 1
                    t += x + y
        else:
            x, y = xy[k]
            if k in fast:
                for i in range(x, x+y):
                    fast[k][i % (x+y)] -= 1
            add_day[k] = None
    
    res = []
    curr = 0
    for day in range(m):
        curr += diff[day]
        total = curr
        for k in fast:
            if add_day[k] is not None:
                cycle = xy[k][0]+xy[k][1]
                offset = (day - add_day[k]) % cycle
                if offset >= xy[k][0]:
                    total += 1
        res.append(total)
    
    print("\n".join(map(str, res)))

if __name__ == "__main__":
    main()
```このソリューションでは、まずトレーニングを低速と高速のカテゴリに分割して、それぞれを効率的に処理します。 差分配列は低速列車のメンテナンスへの貢献を追跡しますが、高速列車は事前に計算されたサイクル配列を使用して頻繁な変更を処理します。 微妙なポイントは、`day - add_day[k]`高速列車のモジュロ サイクル長。これにより、最初のメンテナンス期間が正しく調整されます。 撤去当日には列車をカウントしないように注意する。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m√m) | 高速列車はサイクル オフセットによって処理され、低速列車は差分配列によって処理され、両方を合わせたスケールはおよそ m√m |
 | スペース | O(n + m) | 遅い列車には差分配列を、速い列車には小さなサイクル配列を格納します。 

m ≤ 2×10^5 であるため、これは制限内によく適合し、最悪のケースではおよそ 2×10^5 × 500 回の演算が行われます。
