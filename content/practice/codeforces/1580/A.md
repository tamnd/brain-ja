 ## 解決策
 ## 問題の理解

 バイナリグリッドが与えられます。 を含むセル`1`黒曜石ブロックと以下を含むセルです。`0`は空です。 

任意のセルを反転して変更することができます`0`に`1`または`1`に`0`、フリップごとにコスト1。 

私たちの目標は、最小限の反転回数で有効なポータルに変換できる部分長方形を見つけることです。 

ポータルは非常に特殊な構造を持っています。 長方形には少なくとも 5 行と少なくとも 4 列が必要です。 境界線上のコーナー以外のすべてのセルは次のようにする必要があります。`1`、一方、すべての内部セルは次のようにする必要があります。`0`。 4 隅のセルはまったく無関係であり、どちらの値も含まれる可能性があります。 

テスト ケースの答えは、少なくとも 1 つのサブ長方形がポータルになるために必要な反転の最小数です。 

制約は、直接検索が不可能であることを示す最初の手がかりです。 どちらの寸法も 400 に達する可能性があります。長方形は 2 つの行と 2 つの列を選択することによって決定され、すでにおおよその値が得られます。$400^4$可能性。 単一の四角形を効率的にチェックしたとしても、そのような解決策は得られません。 

このステートメントには、テスト ケースのすべての行数の合計が最大 400 であり、すべての列数の合計も最大 400 であるという珍しい保証も含まれています。これは、次のような解決策を意味します。$O(n^2m)$または$O(nm^2)$許容されますが、$O(n^2m^2)$大きすぎます。 

微妙な点は、角は問題ではないということです。 

考慮する：```
1111
1001
1001
1001
1111
```これはすでにポータルのように見えます。 次に、4 つの角すべてを変更します。```
0110
1001
1001
1001
0110
```非コーナー境界セルのみが拘束されているため、これは依然として有効なポータルです。 

もう 1 つの簡単な間違いは、高さが少なくとも 5 でなければならないことを忘れることです。 

たとえば:```
1111
1001
1001
1111
```この長方形には正しい境界線パターンがありますが、高さは 4 であるため、ポータルではありません。 

3 番目のよくあるバグは、行と列のコストを結合するときに境界セルを 2 回カウントすることです。 最適なソリューションでは、内部要件と境界要件が慎重に分離されるため、すべてのセルが 1 回だけ寄与します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 高さ 5 以上、幅 4 以上の可能なすべての長方形を列挙します。各長方形について、変更する必要があるセルの数を数えます。 

セルは次のことに貢献します。 

- 必要な状態にすでに一致している場合は 0。 
反転する必要がある場合は - 1。 

すべての長方形の最小値が答えです。 

問題は長方形の数です。 がある$O(n^2m^2)$考えられる選択肢。 と$n=m=400$、これはおおよそです$2.5\times10^{10}$長方形。 各四角形を一定時間でチェックすることさえ絶望的です。 

重要な観察は、ポータルの形状が高度に構造化されていることです。 

ポータルの一番上の行と一番下の行を固定するとします。 高さは少なくとも 5 である必要があるため、それらの間の距離は少なくとも 4 になります。 

行の固定ペアの場合、左と右の列を選択するだけで済みます。 

次に列ごとに考えてみましょう。 

候補の左境界列の場合、2 つの行の間のすべての中央のセルが次になる必要があります。`1`。 

候補の右境界列についても同様です。 

厳密に長方形の内側にあるすべての列について、境界線の間のすべてのセルが次のようになっている必要があります。`0`一方、その列の上部と下部の境界セルは次のようになります。`1`。 

各列のコスト寄与は個別に計算できます。 その後、問題は列に対するスライディング ウィンドウの最適化になります。 

これにより、検索が 4 つの境界を同時に選択することから行のペアを選択し、データ構造スタイルの最小限のメンテナンスで列をスキャンすることに軽減されます。 

承認されたソリューションが実行されます$O(n^2m)$。

 ## アルゴリズムのチュートリアル

 ### 事前計算

 各列について、2 つの行の間に出現するものがいくつあるかをすぐに知る必要があります。 

列プレフィックスの合計を構築します。$$col[j][i]$$列に 1 の数を格納します`j`行から`1`行を通して`i`。 

この場合、垂直セグメント クエリはすべて O(1) になります。 

### 上下の行を固定する

 1. すべての行のペアを列挙します`(top, bottom)`そのような`bottom - top >= 4`。 
2. しましょう`h = bottom - top - 1`, the number of interior rows.
 3. すべての列について`c`、3 つの値を計算します。 

その列の内部部分にある 1 の数:$$insideOnes$$この列を横枠として使用する場合のコスト。 

側枠の内側のセルはすべて次のようにする必要があります。`1`、 それで：$$sideCost = h - insideOnes$$4. この柱を内部柱として使用する場合のコストを計算します。 

上部と下部のセルは次のようにする必要があります。`1`。 

すべての中間セルは次のとおりである必要があります。`0`。 

させて$$interiorCost = (grid[top][c]==0) +(grid[bottom][c]==0) + insideOnes$$なぜなら、あらゆるインテリアが`1`に反転する必要があります`0`。 

### 問題を変える

 1. 列を仮定します`r`が右の境界線として選択されます。 

次に、左境界線と右境界線の間の列が内部列になります。 
2. 定義する$$value[c] = sideCost[c] - interiorCost[c]$$これは、次の場合に支払う追加コストを測定します。`c`内部の列の代わりに横の境界線になります。 
3. 列を左から右にスキャンする際、少なくとも 3 列前のできるだけ良い左境界線を維持します。 

幅は少なくとも 4 である必要があるため、次のようになります。$$right - left \ge 3$$4. 右境界列ごとに、次の値を計算します。$$total = sideCost[right] + prefixInteriorCost(right-1) + bestLeft$$どこ`bestLeft`の最小値を格納します$$sideCost[left] - prefixInteriorCost(left)$$すべての有効な左側の境界線の上にあります。 
5. グローバル回答を更新します。 

### なぜ効果があるのか

 上部と下部の行が固定されている場合、すべての列は次の 3 つのカテゴリのいずれかに正確に属します。 

- 左境界線、
 - 右の境界線、
 - 内部コラム。 

長方形のコストは、これらのカテゴリからの寄与の合計です。 

内部列は範囲合計に寄与し、これは接頭辞合計を使用して表すことができます。 左側の境界線は、内側であることに関連して追加の調整に貢献します。 これにより、四角形の最適化が、左側の 1 列と右側の 1 列を含む式の最小値を見つけることに変換されます。 

スキャンでは、これまでに確認された最良の左境界線が維持されるため、現在の行ペアのすべての有効な四角形が 1 回だけ考慮されます。 すべての行ペアが列挙されるため、すべてのポータルにわたる最小値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(map(int, input().strip())) for _ in range(n)]

        col = [[0] * (n + 1) for _ in range(m)]
        for j in range(m):
            for i in range(n):
                col[j][i + 1] = col[j][i] + g[i][j]

        ans = 10**9

        for top in range(n):
            for bottom in range(top + 4, n):
                h = bottom - top - 1

                side = [0] * m
                interior = [0] * m

                for c in range(m):
                    inside_ones = (
                        col[c][bottom] -
                        col[c][top + 1]
                    )

                    side[c] = h - inside_ones

                    interior[c] = (
                        inside_ones +
                        (1 - g[top][c]) +
                        (1 - g[bottom][c])
                    )

                pref = [0] * (m + 1)
                for c in range(m):
                    pref[c + 1] = pref[c] + interior[c]

                best = side[0] - pref[1]

                for right in range(3, m):
                    left_candidate = right - 3
                    best = min(
                        best,
                        side[left_candidate] -
                        pref[left_candidate + 1]
                    )

                    cur = (
                        side[right]
                        + pref[right]
                        + best
                    )

                    ans = min(ans, cur)

        print(ans)

solve()
```列プレフィックスの合計は実装の基礎です。 これらを使用すると、垂直セグメント内の 1 の数を一定時間で数えることができます。 

For each fixed pair of rows, the arrays`side`そして`interior`すべての列のコスト寄与を重要な 2 つの可能な役割の下に保存します。 これらの値は独立して計算されるため、後の最適化が可能になります。 

配列`pref`プレフィックスの合計を格納します`interior`。 これにより、2 つの境界線間のすべての内部列のコストを接頭辞の単純な差として取得できます。 

変数`best`重要な最適化です。 スキャンが右端となる列に到達すると、`best`すでに最も安価な有効な左枠が含まれています。 幅は少なくとも 4 である必要があるため、少なくとも 3 位置前の列のみがこの最小値を入力できます。 

最も一般的な実装エラーは、プレフィックス インデックスの 1 つずつの間違いです。 表現`pref[left + 1]`コラムなので意図的に`left`それ自体を内部列に含めてはなりません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        g = [list(map(int, input().strip())) for _ in range(n)]

        col = [[0] * (n + 1) for _ in range(m)]
        for j in range(m):
            for i in range(n):
                col[j][i + 1] = col[j][i] + g[i][j]

        ans = 10**9

        for top in range(n):
            for bottom in range(top + 4, n):
                h = bottom - top - 1

                side = [0] * m
                interior = [0] * m

                for c in range(m):
                    inside = col[c][bottom] - col[c][top + 1]
                    side[c] = h - inside
                    interior[c] = (
                        inside +
                        (1 - g[top][c]) +
                        (1 - g[bottom][c])
                    )

                pref = [0] * (m + 1)
                for c in range(m):
                    pref[c + 1] = pref[c] + interior[c]

                best = side[0] - pref[1]

                for r in range(3, m):
                    best = min(
                        best,
                        side[r - 3] - pref[r - 2]
                    )
                    ans = min(
                        ans,
                        side[r] + pref[r] + best
                    )

        out.append(str(ans))

    return "\n".join(out) + "\n"
