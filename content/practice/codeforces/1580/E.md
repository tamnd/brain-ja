 ## 解決策
 ## 問題の理解

 幻想郷には、正の長さの双方向の鉄道で接続された鉄道駅のネットワークが与えられています。 The stations are numbered from 1 to$n$、ステーション 1 がメインハブになります。 ネットワークは完全に接続されているため、すべてのステーションは他のステーションからアクセス可能です。 各駅$i$コストがかかる$w_i$そこから始まる新しい一方通行の鉄道の建設に関連しています。 目標は、駅 1 から他の駅まで、終点を除いて頂点が互いに独立した最短経路が少なくとも 2 つ存在するように、一方通行の鉄道を追加することです。 さらに、ステーション 1 と他のすべてのステーションの間の元の最短距離を維持する必要があります。 こうした片道鉄道の建設後、特定の駅でインシデントにより費用が増加する場合があり、インシデントの前後で最低限の総建設費を報告するよう求められています。 

入力サイズは重要です。$n$到達できる$2 \cdot 10^5$、$m$まで$3 \cdot 10^5$、そしてそれがあるかもしれません$2 \cdot 10^5$事件。 したがって、各操作は次のようにする必要があります。$O(n \log n)$または$O(m \log n)$最悪の場合。 任意のアルゴリズム$O(n^2)$または$O(n \cdot m)$複雑さが遅すぎるでしょう。 

ステーションが複数の最小長のパスを介してステーション 1 に直接接続されている場合、明白ではないエッジ ケースが発生します。 たとえば、次の場合$n = 3$、エッジ$(1,2,1)$、$(1,3,1)$、$(2,3,1)$、そして費用$w=[1,2,3]$、不注意なアルゴリズムにより、2 番目の頂点が分離されたパスを確保せずに、駅 1 から駅 2 への一方通行の鉄道を追加しようとする可能性があります。 正しい構築では、頂点が完全に分離された 2 つの最短パスを保証する必要があります。これには、すぐ隣のステーションだけでなく、BFS ツリーのより深いステーションが含まれる可能性があります。 

もう 1 つの注意が必要なシナリオは、同じステーションで複数のインシデントが発生した場合です。 アルゴリズムは、毎回すべてを最初から再計算することなく、合計最小コストを効率的に更新する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、ステーション 1 から他の各ステーションまでのパスのすべてのペアを考慮し、終点を除いて頂点が互いに素であるかどうかを確認し、一方通行の鉄道の構築を繰り返し試行します。 これには、最大サイズのグラフ内のパスを列挙する必要があります。$2 \cdot 10^5$、難治性の疾患につながる$O(2^n)$あるいはせいぜい$O(n^2)$アプローチ。 明らかに、これでは遅すぎます。 

重要な洞察は、問題がステーション 1 をルートとする最短パス ツリー構造に帰着するということです。最初にダイクストラのアルゴリズムを使用して最短距離を計算すると、各エッジを最短パス ツリーまたは潜在的なショートカットの一部として分類できます。 すべてのステーションには、終点を除いて頂点が共通でない 2 番目に短いパスが必要です。 これは、各ノードを BFS/ダイクストラ ツリー内の親の 1 つに一方向の鉄道を介して接続することで実現できます。 コスト計算には開始局のみが重要であるため、各ノードの親候補の中から最小コストの局を選択できます。 初期の最小コストが計算されたら、インシデントに応じてそれを更新するには、駅のコストとその駅から始まる片道鉄道の数の差によって合計を調整するだけで済みます。 これにより、累計を効率的に維持できるようになり、複雑さが軽減されます。$O((n + m) \log n + q)$。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n^2) | 遅すぎる |
 | ダイクストラ + 建設的な BFS ツリー | O((n + m) log n + q) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ダイクストラのアルゴリズムを使用して、ステーション 1 から他のすべてのステーションまでの最短距離を計算します。 これにより、新しい片道鉄道を追加する際に確保すべき正確な距離が確実にわかります。 また、潜在的な 2 番目のパスを特定するために、最短パス ツリーに親を記録します。 
2. 最短パス エッジのみの DAG を構築します。 あらゆるエッジに$(u,v)$、場合によっては含めてください$dist[u] + d = dist[v]$または$dist[v] + d = dist[u]$。 これにより、すべてのパスが元の最短距離を尊重する階層化されたグラフが得られます。 
3. 各駅ごと$i$1 以外の場合は、最短パスに沿って候補となる先行処理を特定します。 2 つの頂点が切り離された最短経路を保証する片道鉄道を建設するための最小コスト$w[p]$前任者候補の中には。 基本的に、最も安価な親から「バックアップ」片道鉄道を追加することをシミュレートします。$i$。 
4. 各駅の最小建設費を合計して総コストを集計する$i > 1$。 これが事件以前の答えです。 
5. 駅から鉄道の建設コストを増加させる各事件について$k_i$による$x_i$、増分$w[k_i]$それに応じて。 片道鉄道が始発の場合$k_i$事前に計算された選択では、総コストをそのような鉄道の数倍に増やします。$x_i$。 更新された合計コストを報告します。 
6. インシデントごとにステップ 5 を繰り返し、最初から再計算せずに累計を効率的に維持します。 

機能する理由: ダイクストラのアルゴリズムは最短距離を保証します。 構築を最短パス ツリーの親に制限すると、2 番目のパスを追加しながら距離が維持されます。 最小コストの親を選択すると、総コストが確実に最小限に抑えられます。 実際に総コストに寄与するステーションのみを追加するため、インシデントの更新は正確です。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def main():
    n, m, q = map(int, input().split())
    w = list(map(int, input().split()))
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v, d = map(int, input().split())
        u -= 1; v -= 1
        adj[u].append((v, d))
        adj[v].append((u, d))
    
    # Dijkstra from node 0
    dist = [float('inf')] * n
    dist[0] = 0
    parent_candidates = [[] for _ in range(n)]
    hq = [(0, 0)]
    while hq:
        d_u, u = heapq.heappop(hq)
        if d_u > dist[u]:
            continue
        for v, w_uv in adj[u]:
            if dist[u] + w_uv < dist[v]:
                dist[v] = dist[u] + w_uv
                parent_candidates[v] = [u]
                heapq.heappush(hq, (dist[v], v))
            elif dist[u] + w_uv == dist[v]:
                parent_candidates[v].append(u)
    
    # Compute minimal construction cost
    total = 0
    from_count = [0] * n
    for i in range(1, n):
        # pick minimal cost parent
        p = min(parent_candidates[i], key=lambda x: w[x])
        total += w[p]
        from_count[p] += 1
    
    print(total)
    
    for _ in range(q):
        k, x = map(int, input().split())
        k -= 1
        w[k] += x
        total += from_count[k] * x
        print(total)

if __name__ == "__main__":
    main()
```このコードは、まず隣接リストを構築し、ダイクストラのアルゴリズムを実行して、バックアップ接続の最短パスと親の候補を決定します。 次に、各ステーションの最小コストの親を選択して 2 番目のパスを保証し、総建設コストを合計します。 インシデントの場合は、影響を受ける駅の始発駅の片道鉄道の数に基づいて、その駅のコストを更新します。
