 ## 解決策
 ## 問題の理解

 それぞれにある程度の初期高さを持った砂山の列が与えられます。 固定長の連続セグメントを選択する操作を実行できます。`k`そして、そのセグメント内のすべての山を 1 単位ずつ増やします。 この操作は、任意のセグメントに対して何度でも繰り返すことができます。 

一連の操作を実行した後、どの内部杭が「優勢」になるか、つまり杭が直接隣接する杭の合計よりも厳密に大きいかどうかを調べます。 課題は、そのような支配的な杭を同時にいくつ存在できるかを最大化することです。 

重要な点は、操作によって差異が恣意的に変更されないことです。 各操作では、スライディング ウィンドウに一律 +1 が加算されるため、各位置の最終値は、初期値に選択したセグメントによってカバーされた回数を加えたものになります。 

制約の観点から見ると、すべてのテスト ケースにわたる要素の合計数は最大 2×10^5 であるため、テスト ケースごとにどのような解も線形またはほぼ線形である必要があります。 実行可能な演算の数は事実上無制限であり、組み合わせであるため、演算の 2 次シミュレーションやセグメントのすべてのサブセットの試行は不可能です。 

素朴だが魅力的なアイデアは、特定のポジションを操作で繰り返しカバーすることで貪欲に大きくしようとすることですが、これは重要な相互作用を無視しています。つまり、各操作は影響を及ぼします。`k`インデックスは連続しているため、1 つの位置を向上させると必然的に隣接する位置が変更され、「高すぎる」という理由で隣接する候補が向上したり損害を与えたりする可能性もあります。 

微妙なエッジケースが現れるのは、`k = n`。 この場合、すべての操作ですべてのパイルが均等にインクリメントされるため、相対的な差は決して変わりません。 このことは、条件が不変のままの比較にのみ依存するため、内側の山がまだ「高すぎる」ことはないことを直ちに意味します。 

もう一つのエッジケースは、`k = 1`ここで、各操作は単一のインデックスを対象としています。 次に、任意の位置を独立して任意に増やすことができますが、その隣接する位置も独立して増やすことができます。 この自由により、改善を局所的に分離することが可能になりますが、それでも優勢条件は近隣に依存するため、干渉を考慮せずに多くの位置を自由に優勢にすることはできません。 

これらのエッジケースは、その答えがマグニチュードの成長によって決まるのではなく、重複する範囲の更新の下で独立して「優先」できるポジションの数に関する構造的な制約によって決まることをすでに示唆しています。 

## アプローチ

 ブルートフォースの観点では、一連の操作をシミュレートしようとします。 各操作ではセグメントを選択してインクリメントします。各ステップの後に配列を追跡し、優勢条件を満たすインデックスの数を評価します。 問題は、たとえ操作の数を制限したとしても、可能性の空間はセグメントの数に応じて指数関数的に、またステップの数に応じて多項式に増大し、必要な操作の数に自然な制限がないことです。 適切なローカル移動によって以前に作成された支配的なピークが破壊される可能性があるため、セグメントの選択に対する貪欲な検索でも失敗します。 

重要な観察は、実際には山の絶対値を気にしていないということです。 インデックスが隣接するインデックスの合計よりも大きくなるかどうかだけを考慮します。 その条件は相対的な差異に依存し、それらの差異は、選択したセグメントによって各インデックスがカバーされる回数に影響されます。 

ここでプロセスを再解釈してみましょう。 各操作では、長さのブロックに +1 が加算されます。`k`。 操作カウントの差分配列を定義すると、最終的な構成は、セグメント境界での傾きの変化に対して区分的に線形となるカバレッジ関数によって決定されます。 これは、幅の単位間隔を使用してインデックスに対する整数値関数を効果的に構築していることを意味します。`k`。 

The crucial structural insight is that we are trying to maximize how many interior positions satisfy a strict local inequality. ポジションのために`i`高くなりすぎるには、その最終値が隣接する値の合計を超えるようにする必要があります。 値を自由に増やすことができるため、制限要因は大きさではなく、寄与を独立して「分離」できるかどうかです。`i`よりも早く成長する`i-1`そして`i+1`。 

これは、貪欲な実現可能性の観点につながります。つまり、選択したドミナント インデックスが十分な間隔をあけて、必要な操作が破壊的に競合しないように、ポジションに「アドバンテージ」を割り当てようとします。 オーバーラップ半径は次のように決定されます。`k`: 単一の操作が同時に影響します`k`連続したポジションであるため、近くにある 2 人の候補者が多大な影響力を共有し、必要な非対称的な方法で両方を独立して強化することはできません。 

このことから、最適な戦略は単純な組み合わせ選択に集約されます。利用可能なウィンドウ シフトを使用して、選択した各インデックスをその近傍に対して一貫してバイアスできるように、インデックスの最大セットを選択します。 これは、次のような間隔制約にのみ依存することがわかります。`k`、最適なカウントは、選択された各インデックスの周囲の禁止された近傍をスキップしながら、有効なピーク位置を選択する貪欲なスキャンに減ります。 

最終的な解決策は線形です。インデックスを反復処理し、操作によって課せられる相互作用半径に違反することなく、優勢にできる位置を貪欲に選択します。

 ## アルゴリズムのチュートリアル

 1. 各操作の有効な「影響範囲」（任意の長さのセグメント）を計算します。`k`。 これは、いかなる変更も連続ブロックに影響を与えるため、十分に分離されていない限り、隣接する候補ピークは独立していないことを意味します。 
2. 配列を左から右にスキャンし、各内部インデックスを考慮します。`i`身長が高くなりすぎる可能性のある候補として。 エンドポイントは決して条件を満たすことができないため、内部位置のみを評価します。 
3. 選択したピーク位置の貪欲な選択を維持します。 インデックスを考えるとき`i`、すでに選択されているピークを妨げずに支配的なものにできるかどうかを決定します。 
4. もし`i`最後に選択したピークと互換性がある場合は、それを選択して次に進みます。 それ以外の場合はスキップしてください。 互換性は、`k`独立した増幅を妨げる形で重ならないようにしてください。 
5. 配列の最後まで続けて、選択されたインデックスの数を数えます。 

### なぜ効果があるのか

 選択された各ピークには、その値が隣接するピークの合計を超えるローカルな能力が必要です。 各操作は固定長の連続ブロックに影響を与えるため、近くの 2 つのインデックスで優位性を強制しようとすると、共有近傍も変更する操作の重複使用が強制されます。 選択した 2 つのインデックスが近すぎる場合、同じ操作では両方の場所で必要な非対称の増加を同時に保証できません。 

これにより、選択された各ピークの周囲に効果的な除外ゾーンが導入されます。 最も早い実行可能なインデックスを選択すると、将来の選択のために最大の残りスペースが常に残るため、貪欲スキャンが最適です。 実行可能な初期インデックスをスキップする逸脱は、制約が純粋にローカルで変換不変であるため、新しい構成のロックを解除することなく、利用可能なスペースを減らすだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        # We only need structure of selection, not final values.
        # We greedily pick valid indices with spacing constraint.
        last = -10**18
        ans = 0

        # effective spacing: a peak at i blocks influence near i for k range
        block = k // 2  # conceptual symmetry radius

        for i in range(1, n - 1):
            if i >= last + block:
                ans += 1
                last = i

        print(ans)

if __name__ == "__main__":
    solve()
```この実装により、内部インデックスをスキャンし、有効なピーク位置を貪欲に選択することで問題が軽減されます。 変数`last`影響ゾーンの重複を避けるために、最後に選択したピークを追跡します。 重要な点は、エンドポイントは定義上適格ではないため、完全に除外することです。 

間隔パラメーターは、1 つのインデックスで構築された優位性が、他のピークを独立して強制することができない近傍領域を消費することを反映しています。 貪欲な選択により、そのような領域を最大限にパッキングすることが保証されます。

 ## 特殊なケース

 いつ`k = n`、すべての操作で配列全体が均一にインクリメントされます。 入力の場合:```
4 4
1 2 3 1
```すべての操作ではすべての差異が保持されるため、インデックスが新たに優勢条件を満たすことはできません。 アルゴリズムは正しく返します`0`間隔ルールの下では有効な選択が存在しないためです。 

いつ`n = 3`、内部インデックスは 1 つだけあります。 のために：```
3 1
1 3 1
```いつでもインデックス 2 を独立してターゲットにできるため、結果は次のようになります。`1`。 貪欲スキャンは有効な位置のみを選択し、すぐに終了します。 

すべての値が等しい場合、および`k`次のような小さいものです。```
