 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列から始めますが、その順列は任意ではありません。 これは、互いに素な位置のペアを選択し、各ペア内の値を交換することによって、恒等配置から作成されます。 n は奇数であるため、これらのスワップによって 1 つの位置だけがそのまま残され、その位置にある値がそのインデックスの元の値でもあります。 

私たちの仕事は、どの値が元の位置に残っているかを特定することです。 配列を直接見ることはできません。 代わりに、任意のセグメント [l, r] をクエリすることができ、ジャッジはそのセグメント内の値を昇順にソートして返します。 これは、クエリされた範囲内の位置情報は失われますが、それでもその間隔内の値の複数セットを学習できることを意味します。 

15 クエリの相互作用制約は、ローカルに何かを再構築するのではなく、慎重に選択された少数の比較を使用してグローバル構造を抽出する必要があることを強く示唆しています。 

主要な構造特性は、すべての値が固定されたままであるか、または 1 つのスワップにのみ属していることです。そのため、i < j のすべてのペア (i, j) について、値 i と j が交換されます。これは、i が j に現れ、j が i に現れることを意味します。 これは対称性を意味します。不正確な位置はすべて変位の原因となり、唯一の固定点は位置がその値と一致する一意の値です。 

素朴なアイデアは、単一要素をクエリして配列全体を再構成することですが、各単一要素クエリではその位置の値しか得られず、これは可能ですが、すでに n 回のクエリが必要になります。 n は大きくなる可能性があり、クエリが 15 しかないため、これは不可能です。 

もう 1 つの魅力的なアイデアは、小さなセグメントからランダム サンプリングまたはローカル推論を試みることです。ただし、並べ替えによって順序付け情報が破壊されるため、ローカル推論では変位の方向を確実に決定できません。 

本当の制約圧力は、固定小数点を含めるか除外するときに単調に変化するグローバル プロパティが必要であるということです。 これは、プレフィックスまたはサフィックスの動作に関する二分検索スタイルの引数を示唆しています。 

## アプローチ

 ブルート フォース手法では、[i, i] を使用して各位置を個別にクエリし、配列全体を復元してから、どのインデックス i が a[i] = i を満たすかをチェックします。 固定小数点が一意であることが保証されているため、これは正しいです。 ただし、これには n 個のクエリのコストがかかり、n > 15 になるとすぐに制限を超えます。 

重要な観察は、完全な再構築は必要ないということです。 中点のどちら側に固定点が含まれているかを検出するだけで済みます。 セグメント内の値の合計を、予想されるアイデンティティ セグメントの合計と比較すると、境界を越えるスワップによって引き起こされる不均衡を検出できます。 ただし、合計は直接入手できません。 代わりに、マルチセットの合計が正確に保存された、ソートされた値を受け取ります。 

したがって、任意のクエリ [l, r] について、戻り値の合計を計算できます。 同一性の期待される合計は、(l + r)(r - l + 1) / 2 になります。実際の合計と期待される合計との差は、セグメントに境界を越えて移動された要素が含まれていることを示します。 重要なのは、セグメントに固定小数点が含まれていない場合、スワップは内側または外側で完全にペアになり、合計偏差は一貫して動作します。 これにより、固定点の位置を二分探索することができます。 

各ステップで、中間点の接頭辞 [1, Mid] をテストします。 合計が予想と異なる場合、不動点はその中にあります。 それ以外の場合はサフィックスにあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) クエリ | お(1) | 遅すぎる |
 | 最適 | O(log n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 固定小数点を含む必要がある検索範囲 [l, r] を維持します。

1. l = 1 および r = n を初期化します。 固定点はこの間隔内にあることが保証されます。 
2. l < r の場合、mid = (l + r) // 2 を計算します。 
3. セグメント [l, mid] をクエリし、その範囲内の並べ替えられた値を受け取ります。 それらの合計 S を計算します。 
4. アイデンティティセグメント [l,mid] の予想される合計を計算します。これは ((l + mid) * (mid - l + 1)) // 2 です。 
5. S を予想される合計と比較します。 それらが等しい場合、境界を越えるスワップはこのセグメントに影響を与えないため、固定点は [mid + 1, r] に存在する必要があります。 それ以外の場合は、[l,mid] にあります。 
6. l または r を適宜更新し、繰り返します。 
7. l == r の場合、l を固定小数点の位置として出力します。 

### なぜ効果があるのか

 各スワップは、テストされたセグメント内に完全に留まるか、その境界を越えます。 セグメントに固定小数点が含まれていない場合、セグメントに影響を与えるすべてのスワップは完全に内部または外部であるため、合計は恒等合計と正確に一致します。 二分探索の決定を変えるプレフィックス合計の不均衡を永続的に引き起こす唯一の方法は、セグメントに固定点である一意のペアになっていない要素が含まれている場合です。 これにより、プレフィックス合計テストがインデックス空間に対する有効な単調述語になり、二分探索が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def query(l, r):
    print("?", l, r)
    sys.stdout.flush()
    arr = list(map(int, input().split()))
    if arr and arr[0] == -1:
        sys.exit(0)
    return arr

def segment_sum(arr):
    return sum(arr)

def expected_sum(l, r):
    cnt = r - l + 1
    return (l + r) * cnt // 2

def solve_case(n):
    l, r = 1, n

    while l < r:
        mid = (l + r) // 2
        res = query(l, mid)
        s = segment_sum(res)

        if s == expected_sum(l, mid):
            l = mid + 1
        else:
            r = mid

    print("!", l)
    sys.stdout.flush()

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        solve_case(n)

if __name__ == "__main__":
    main()
```この対話は、クエリを発行し、出力を即座にフラッシュすることによって処理されます。 各クエリは並べ替えられたセグメントを返します。並べ替えによって位置構造が削除されるため、順序は無視して値の合計のみに依存します。 二分探索境界の更新は、プレフィックスが手付かずの ID セグメントのように動作するかどうかに完全に依存します。 

微妙な点は、単一の要素をクエリする必要がないということです。 すべてのクエリにより検索スペースが約半分に減り、クエリの総数が制限を大幅に下回ります。 

## 実用的な例

 n = 5 で、隠し配列が [4, 2, 5, 1, 3] である例を考えてみましょう。 不動点は2です。

 ## 特殊なケース

 n = 3 のような最小のケースでは、固定点が端点にある可能性があることが強調されます。 たとえば、[1,3,2] は 1 を固定したままにします。 二分探索では、プレフィックス [1,1] と [1,2] がすぐに区別されます。これは、後者のみが予想される合計動作からの逸脱を示しているためです。 

n = 7 のような完全にバランスのとれたスワップ構造では、多くの要素がスワップされますが、固定点付近を除いてプレフィックス境界を越えるものはありません。これにより、誤ったセグメントが常に内部でキャンセルされ、合計の等しいことがターゲット セグメントの除外の安定した指標であることが確認されます。 

これらのケースでは、スワップ構成に関係なく、決定述語が単調なままであることが確認され、これにより二分探索が一貫して動作できるようになります。
