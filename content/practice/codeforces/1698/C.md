 ## 解決策
 ## 問題の理解

 整数の配列が 3SUM 閉じているかどうかを判断するように求められます。これは、配列内の個別の要素のトリプルごとに、それら 3 つの要素の合計自体が配列内のどこかに存在することを意味します。 入力は複数のテスト ケースで構成され、それぞれが配列の長さとその後にその要素を指定します。 配列が 3SUM で閉じられている場合、出力は「YES」、それ以外の場合は「NO」です。 

制約により、最大で$2 \cdot 10^5$すべてのテスト ケースにわたる配列要素の合計。これは、おおよその値よりも悪いアルゴリズムが存在することを意味します。$O(n^2)$テストケースごとの処理は遅すぎる可能性があります。 すべてのトリプルを直接考慮するブルートフォースアプローチには、次のものが必要です。$O(n^3)$大規模な企業では実現不可能な操作$n$。 

考慮すべきエッジケースには、すべて同一の要素を持つ配列、ゼロのみを持つ配列、大きな正と負の両方の数値を含む配列が含まれます。 例えば、$[0,0,0,0]$すべてのトリプルの合計が 0 (配列内にある) になるため、 は自明のことながら 3SUM で閉じられます。 3 つ以上の異なる非ゼロ要素を含む配列 (例:$[-1, 2, -3, 4]$、一部の三重和が配列の外にあるため、プロパティが失敗する可能性があります。 正確さを保つためには個別の値をカウントすることが不可欠であるため、多くの重複またはゼロを含む配列は慎重に扱う必要があります。 

## アプローチ

 素朴なアプローチは、インデックスの可能なすべてのトリプルを反復処理し、それらの合計が配列内に存在するかどうかを確認することです。 これは 3SUM クロージャの定義を直接実装しているため正しいですが、複雑さは次のとおりです。$O(n^3)$、これは受け入れられません。$n$大きいです。 例えば、$n=2 \cdot 10^5$おおよそ必要になります$8 \cdot 10^{15}$操作。 

重要な点は、3 つ以上の異なる非ゼロ要素を持つ配列は 3SUM クローズできないということです。 異なる非ゼロ数値の各トリプルは、必ずしも配列内に存在するわけではない合計を生成します。 したがって、配列を最大 3 つの正の数、3 つの負の数、および任意の数のゼロに減らすことができます。 正の数が 3 つ以上、または負の数が 3 つ以上ある場合、配列を 3SUM で閉じることはできません。 

配列が縮小されると、個別の非ゼロ要素の数は最大 6 個になるため、問題は扱いやすくなります。 次に、要素のトリプルをすべて列挙し (ゼロを考慮して)、それぞれの合計が配列内に存在するかどうかを確認します。 考慮される要素の合計数は最大 7 であるため、このチェックは次の場合に実行可能です。$O(1)$テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適化された削減 + トリプルチェック | フィルタリング後のテスト ケースごとに O(1)、前処理に O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。$a$それを高速メンバーシップ クエリ用のセットに変換します。 
2. 要素を正、負、ゼロに分離します。 最大 3 つの最大のポジティブと最大 3 つの最小のネガティブのみを保持します。 個別の合計の数は増加しないため、すべてゼロを含めます。 これにより、配列は最大 7 つの要素に減ります。 
3. 縮小された配列から個別の要素のトリプルをすべて生成します。 各トリプルについて、その合計を計算します。 
4. 各トリプルの合計が元の配列要素セットに存在するかどうかを確認します。 合計が不足している場合は「NO」を出力します。 
5. すべての三重和が存在する場合は、「YES」を出力します。 

機能する理由: 3 つを超える正の数または 3 つの負の数を含む配列は、配列内で 3 つの合計を表現できないため、自動的に無効になります。 重要な要素に限定することで、すべての 3 つの合計をチェックするだけで 3SUM クロージャを確認するのに十分であることが保証されます。 これは、除外された要素が残りのトリプルによってすでにカバーされている合計、または配列の外側の合計を生成するという不変条件に依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import combinations

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a_set = set(a)
        
        pos = sorted([x for x in a if x > 0])
        neg = sorted([x for x in a if x < 0])
        zeros = [x for x in a if x == 0]
        
        if len(pos) > 3 or len(neg) > 3:
            print("NO")
            continue
        
        reduced = neg[:3] + zeros + pos[-3:]
        ok = True
        for triple in combinations(reduced, 3):
            if sum(triple) not in a_set:
                ok = False
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードはまず配列を分割し、重要な要素に減らします。 セットを使用すると、$O(1)$会員は金額をチェックします。 縮小された配列を組み合わせると、トリプルの総数が確実に小さくなるため、効率的にトリプルを列挙できます。

 ## 特殊なケース

 すべてゼロの配列`[0,0,0,0]`配列内にすべて存在する 0 の 3 つの合計を生成します。 バランスの取れたアレイ`[-2,-1,0,0,0,1,2]`最大 3 つの負の数、3 つの正の数、およびゼロに還元した後、すべての 3 つの合計が存在するため、この関数は機能します。 3 つの正または 3 つの負を超える配列。たとえば、`[-5,-4,-3,-2,0,2,3,4]`、一部の三重和が配列の外にあるため失敗します。 このアルゴリズムは、縮小セットを制限し、すべての 3 つの合計を明示的にチェックすることにより、これらの状況を正確に識別します。
