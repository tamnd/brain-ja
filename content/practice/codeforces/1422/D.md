 ## 解決策
 ## 問題の理解

 私たちは巨大なグリッドの上を移動しています。 開始セルは$(s_x,s_y)$そして目的地は$(f_x,f_y)$。 歩行は通常どおりに機能します。1 つのセルを水平または垂直に移動するには 1 分のコストがかかるため、2 つの位置間を歩くコストはマンハッタンの距離になります。 

特別な場所もあります。 特別な場所$(x_i,y_i)$を共有する任意の位置から即座に到達できます。$x$-座標またはその$y$-座標。 同様に、私たちが立っている場合、$(a,b)$に移動できます$(x_i,y_i)$実費で$$\min(|a-x_i|,\;|b-y_i|).$$もし$x$- 座標はすでに一致しており、最初の項はゼロであり、テレポートは自由です。 同じことが次の場合にも起こります。$y$- 座標が一致します。 

課題は、家に着くまでに必要な最短時間を見つけることです。 

都市の規模$n$と同じ大きさにすることができます$10^9$これにより、グリッド自体を表現できないことがすぐにわかります。 特別な場所の数は最大で$10^5$したがって、特別な場所のセットに直接作用するあらゆるソリューションが実現可能です。 グラフ$10^5$頂点は管理可能ですが、すべてのペアワイズ エッジを含むグラフには約$10^{10}$エッジ、それは完全に不可能です。 

問題の最も危険な部分は、テレポートがどのように相互作用するかを理解することです。 

考慮する：```
start = (1,1)
finish = (100,100)

special:
(1,50)
(50,50)
```最初の特別ポイントは無料で到達できます。$x$-座標はすでに一致しています。 に到着後、$(1,50)$、2番目の特別なポイントはコストで到達できます$\min(49,0)=0$なぜなら、$y$- 座標が一致します。 特別なポイント間の通常のマンハッタン距離のみを考慮するソリューションでは、この一連の自由な移動が失われます。 

もう 1 つの微妙なケースは、特別なポイントを使用しないことが最適な場合です。```
start = (1,1)
finish = (3,3)
```特別な場所はありません。 

答えは単純です$4$。 グラフの構築には、目的地まで直接歩く可能性が含まれている必要があります。 

3 番目のトラップは、特別なポイントのすべてのペアにエッジが必要であると想定していることです。```
(1,100)
(2,100)
(1000000000,100)
```有用なトランジションは、座標でソートした後、隣接するポイントから得られます。 すべてのペアを接続するのは正しいことですが、遅すぎます。 重要な観察は、ソートされた順序で最も近いものだけが重要であるということです。 

## アプローチ

 自然な最初のアイデアは、頂点が開始位置と終了位置とともに特別な位置であるグラフを構築することです。 

特別な場所のすべてのペアの間にエッジを作成するとします。 特別地点からの移動にかかる費用$i$特別なポイントへ$j$は$$\min(|x_i-x_j|,\;|y_i-y_j|).$$コストを使用してスタートをすべての特別なポイントに接続することもできます$$\min(|s_x-x_i|,\;|s_y-y_i|).$$最後に、すべての頂点はマンハッタン距離で目的地まで直接歩くことができます。 

このグラフは問題を正しくモデル化しており、ダイクストラのアルゴリズムが答えを見つけます。 

問題はサイズです。 と$m=10^5$、完全なグラフには大まかに次のものが含まれます$$\frac{m(m-1)}2 \approx 5 \cdot 10^9$$エッジ。 そのグラフを保存または処理することは不可能です。 

画期的な発見はエッジ重量の検討から$$\min(|x_i-x_j|,\;|y_i-y_j|).$$2 つの点が接続されていると仮定します。$x$・座標が近い。 ポイントを並べ替える場合$x$、を介した最も安価で便利な接続$x$-dimension は、その順序で隣接する点の間に常に表示されます。 

これは、いくつかの幾何学的最短経路問題で使用されるのと同じ観察です。 ポイントの場合$A$そして指摘する$C$別の点で区切られている$B$並べ替え済み$x$-注文してください$$|x_A-x_C|$$両方の隣接するギャップより小さくすることはできません。 小さなものを悪用したいあらゆるパス$x$-difference は、隣接する点を通じて行うことができます。 

同じ理由が次の場合にも当てはまります。$y$-座標。 

したがって、すべてのペアを接続する代わりに、特別なポイントを次の基準で並べ替えます。$x$そして隣接するペアを接続します。 次に、次のように並べ替えます$y$隣接するペアを再度接続します。 結果として得られるグラフには、$O(m)$エッジ。 

この削減後、ダイクストラのアルゴリズムは制限内で快適に実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースの完全なグラフ |$O(m^2 \log m)$|$O(m^2)$| 遅すぎる |
 | 隣接グラフ + ダイクストラ |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### グラフの解釈

 それぞれの特別な位置がグラフの頂点になります。 

開始位置の頂点は作成しません。 代わりに、start はすべての特別な位置の初期距離を提供します。 

また、宛先の頂点も作成しません。 家に到着することは、訪問した場所からの最後の歩行ステップとして扱われます。 

### ステップ

 1. すべての特別な場所を読み取り、それぞれにインデックスを割り当てます。 
2. 特別な場所を次の基準で並べ替えます。$x$-座標。 
3. この順序で隣接するペアごとに、重みが次の差に等しい無向エッジを追加します。$x$-コーディネート。 

に基づく最短の移行$x$- 次元は常に、ソートされた順序で隣接する点を通じて表現できます。 
4. 特別な場所を次の基準で並べ替えます。$y$-座標。 
5. この順序で隣接するペアごとに、重みが次の差に等しい無向エッジを追加します。$y$-コーディネート。 

これは、に基づいてすべての有用なトランジションをキャプチャします。$y$-寸法。 
6. ダイクストラを初期化します。 

特別なポイントごとに$i$、$$dist[i] = \min(|s_x-x_i|,\;|s_y-y_i|).$$これはまさに、最初からその特別な場所に到達するためのコストです。 
7. 最初から最後まで直接歩くコストを使用して答えを初期化します。$$|s_x-f_x|+|s_y-f_y|.$$8. 特別な位置のグラフでダイクストラを実行します。 
9. 頂点が現れるたびに$i$優先キューから抽出された場合は、次を使用して回答を更新します$$dist[i] + |x_i-f_x| + |y_i-f_y|.$$これは、ポイントまでのテレポートの使用を表します$i$、それからまっすぐ家に帰ります。 
10. 通常のダイクストラ法ですべてのグラフのエッジを緩和します。 
11. ダイクストラが終了したら、見つかった最小の答えを出力します。 

### なぜ効果があるのか

 重要な特性は、特別な位置間のすべての有用な遷移を、ソートされた隣接点間の移動に分解できることです。$x$- 順序または並べ替え$y$-注文。 

最適なパスがコストによって決定されるエッジを使用すると仮定します。$x$-違い。 ソートされた連続ポイント間を移動する$x$-order は、連続する座標ギャップの合計が合計ギャップに等しいため、コストを増加させることなくそのコストを再現します。 同じ議論が次の場合にも当てはまります。$y$-寸法。 

その結果、完全なグラフ内のすべての最適なルートは、隣接するペアのみから構築されたスパース グラフ内の等価なルートを持ちます。 次に、ダイクストラはすべての特別な場所までの最短距離を計算し、それぞれの距離と家までの最終的なマンハッタンの徒歩距離を組み合わせて、考えられるあらゆる最適な戦略を検討します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    sx, sy, fx, fy = map(int, input().split())

    pts = []
    for i in range(m):
        x, y = map(int, input().split())
        pts.append((x, y, i))

    g = [[] for _ in range(m)]

    by_x = sorted(pts)
    for i in range(m - 1):
        x1, y1, id1 = by_x[i]
        x2, y2, id2 = by_x[i + 1]
        w = x2 - x1
        g[id1].append((id2, w))
        g[id2].append((id1, w))

    by_y = sorted(pts, key=lambda p: p[1])
    for i in range(m - 1):
        x1, y1, id1 = by_y[i]
        x2, y2, id2 = by_y[i + 1]
        w = y2 - y1
        g[id1].append((id2, w))
        g[id2].append((id1, w))

    INF = 10**30
    dist = [INF] * m
    pq = []

    for x, y, idx in pts:
        d = min(abs(sx - x), abs(sy - y))
        dist[idx] = d
        heapq.heappush(pq, (d, idx))

    ans = abs(sx - fx) + abs(sy - fy)

    while pq:
        curd, v = heapq.heappop(pq)
        if curd != dist[v]:
            continue

        x, y, _ = pts[v]

        ans = min(
            ans,
            curd + abs(x - fx) + abs(y - fy)
        )

        for to, w in g[v]:
            nd = curd + w
            if nd < dist[to]:
                dist[to] = nd
                heapq.heappush(pq, (nd, to))

    print(ans)

solve()
```グラフには特別な場所のみが含まれています。 開始位置は、開始から各特別なポイントに到達するコストに正確に一致する初期ダイクストラ距離によって表示されます。 

2 つの並べ替えパスにより、疎なグラフが作成されます。 よくある間違いは、$$\min(|x_i-x_j|, |y_i-y_j|)$$隣接する点間のエッジの重みとして。 受け入れられた解決策は、並べ替え順序に対応する座標の差のみを使用します。 これは、公式ソリューションの重要な圧縮引数です。 

もう 1 つの微妙な点は、最終回答の更新です。 特別なポイントに到達しても、それ以上のテレポートの使用は強制されません。 いつでも立ち止まって家にまっすぐ帰る可能性があるため、抽出されたすべての頂点が答えの候補となります。 

すべての値は 64 ビット整数内に簡単に収まりますが、Python 整数ではオーバーフローの懸念が解消されます。

```グラフは空です。 ダイクストラは頂点を決して処理しません。 最初の答えはマンハッタンの距離です$$18.$$その値は直接出力されます。

```ダイレクトウォークの答えはゼロから始まります。 これを改善できるルートはないため、アルゴリズムはゼロを出力します。
