 ## 解決策
 ## 問題の理解

 整数の静的配列が与えられ、多くの範囲クエリに答えるように求められます。 各クエリは、配列のサブセグメント内のすべての値の最小公倍数を要求します。 複雑なのは、各セグメントのエンドポイントが直接指定されず、前の回答を使用して動的に生成されるため、すべてのクエリが前のクエリの結果に依存することです。 

セグメントの最小公倍数は、セグメント内のすべての数値から素因数を累積することによって増加します。 値は大きな素数を法として取得されるため、実際には、素因数の寄与がべき乗剰余と組み合わされる乗法構造で作業していることになります。 

主な問題点は、クエリ数と配列サイズの両方が 100000 に達する可能性があるため、範囲ごとに LCM を最初から再計算することが不可能であることです。 クエリごとに 1 つの範囲スキャンを実行すると、すでに O(nq) のコストがかかりますが、これは実行可能な制限をはるかに超えています。 

単純ですがよくある落とし穴は、スライド セグメントに対して LCM を増分的に維持しようとすることです。 これは、LCM が元に戻せない、または要素を削除するときに簡単に更新できないため、失敗します。また、前の回答への依存性によりセグメントが予測可能な方法でスライドすらしないためです。 

もう 1 つの微妙な問題は、適応クエリの生成です。 クエリが独立していると仮定すると、LCM ロジック自体が正しい場合でも、エンドポイント l と r が正しく計算されず、完全に間違ったセグメントが生成されます。 

## アプローチ

 ブルート フォース ソリューションでは、セグメントをスキャンし、LCM を最初から再計算することで各クエリを評価します。 これは簡単です。範囲内の各要素を素因数分解し、素数ごとの最大指数を累積します。 最終的な LCM は、最大指数まで累乗された素数の積として再構築されます。 

LCM はセグメント内のすべての数値にわたる各素数の最高累乗を取ることによって定義されるため、これは概念的に機能します。 ただし、コストが高すぎます。 最悪の場合、各クエリは O(n) 個の要素を処理し、O(n) 個のクエリが存在し、O(n²) 回の操作が発生します。 n が 100000 までの場合、これは不可能です。 

重要な観察は、各配列要素の値が素因数分解を介して独立して寄与し、配列値が 200000 によって制限されていることです。これにより、因数分解を事前に計算することができます。 残りの課題は、素数指数の効率的な範囲集約です。 

クエリごとに素数寄与を再計算する代わりに、各ノードが LCM 構造の圧縮表現、つまり各素数、そのセグメント内の最大指数を格納するセグメント ツリーを構築します。 2 つのセグメントを結合することは、素数ごとに最大の指数を取るだけです。 値には制限があるため、因数分解を事前に計算し、指数マップをスパース表現で保存します。 

操作を高速に保つために、各ノードはそのセグメントに存在する素数の辞書のみを保存し、マージでは最大値を取得して辞書を結合します。 慎重に枝刈りをし、小さな因数分解に頼れば、制約の下でも十分効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log A) | お(1) | 遅すぎる |
 | 最適 (因子マップを含むセグメント ツリー) | O((n + q) log n · k) | O(n · k) | 承認済み |

 ここで、k は数値ごとの個別の素因数の平均数であり、制約により小さくなります。 

## アルゴリズムのチュートリアル

 すべての数値の素因数分解を計算して前処理します。 値は最大 200000 であるため、最小の素因数ふるいを使用して、各因数分解を高速化します。

1. 最大 200000 までの SPF (最小素因数) 配列を構築します。これにより、O(log 値) 時間で任意の値を因数分解できます。 
2. 配列要素ごとに素因数分解を計算し、それを辞書または (素数、指数) ペアのリストとして保存します。 これにより、値が乗算構造に圧縮されます。 
3. 各ノードがその区間の LCM 構造を表すセグメント ツリーを構築します。 各ノードは、その間隔で見られる素数から最大指数までのマッピングを保存します。 
4. 2 つのノードをマージするには、両側から素数を反復し、各素数の最大指数を取得します。 これにより、マージされたノードがそのサブセグメントの LCM を正しく表すことが保証されます。 
5. クエリ [l, r] の場合、セグメント ツリーをトラバースし、関連するすべてのノードを単一の素数-指数マップにマージします。 
6. 最終的なマップを取得した後、各エントリに対して p^e モジュロ 1e9+7 を乗算して答えを再構築します。 
7. 前の回答を使用してクエリ境界を動的に計算し、必要に応じて法 n で正規化して交換します。 

正確さは、セグメント上の LCM が素数ごとの最大指数のみに依存し、セグメント ツリーのマージがすべてのノードでその不変量を保持するという事実に依存します。 

### なぜ効果があるのか

 セグメント ツリーのすべてのノードで、保存されたマップがそのノードの間隔の LCM 分解を正確に表すという不変条件を維持します。 2 つの互いに素なセグメントの最小公倍数では、両方のセグメントにわたる各素数の最大指数を取る必要があるため、マージ操作ではこの不変条件が維持されます。 すべてのクエリはセグメント ツリー ノードの素の結合に分解されるため、それらの格納されたマップをマージすると、クエリ範囲の LCM が正確に再構築されます。 適応クエリの生成は、基になるセグメントの計算ではなくインデックスのみを変更するため、正確さに影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAXV = 200000

# smallest prime factor sieve
spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXV + 1, i):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = {}
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        res[p] = cnt
    return res

def merge(a, b):
    if len(a) < len(b):
        a, b = b, a
    for p, e in b.items():
        if p in a:
            if e > a[p]:
                a[p] = e
        else:
            a[p] = e
    return a

n = int(input())
arr = list(map(int, input().split()))

tree = [dict() for _ in range(4 * n)]

def build(v, l, r):
    if l == r:
        tree[v] = factorize(arr[l])
        return
    m = (l + r) // 2
    build(2 * v, l, m)
    build(2 * v + 1, m + 1, r)
    tree[v] = merge(tree[2 * v].copy(), tree[2 * v + 1])

def query(v, l, r, ql, qr):
    if ql <= l and r <= qr:
        return tree[v].copy()
    m = (l + r) // 2
    res = {}
    if ql <= m:
        res = merge(res, query(2 * v, l, m, ql, qr))
    if qr > m:
        res = merge(res, query(2 * v + 1, m + 1, r, ql, qr))
    return res

build(1, 0, n - 1)

last = 0
out = []

for _ in range(int(input())):
    x, y = map(int, input().split())
    l = (last + x) % n
    r = (last + y) % n
    if l > r:
        l, r = r, l

    mp = query(1, 0, n - 1, l, r)

    ans = 1
    for p, e in mp.items():
        ans = (ans * pow(p, e, MOD)) % MOD

    out.append(str(ans))
    last = ans

print("\n".join(out))
```ふるいにより、因数分解がすべての値を前処理するのに十分な速度で行われることが保証されます。 各セグメント ツリー ノードにはコンパクトな辞書が格納され、マージには LCM 構造と一致する最大指数ロジックが使用されます。 クエリは新しいディクショナリを返します。これは、数値ごとの要素数が小さいため、制約によりマージコストの償却が許可されるため安全です。 

適応クエリの計算は、モジュロンとインデックス スワッピングを使用して慎重に処理され、ラッピングが発生した場合でもすべてのセグメントが有効なままであることが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n · k) | 各クエリはセグメント ツリー ノードをマージし、各マージは小さなプライム マップを処理します。 
| スペース | O(n · k) | 各ノードはその間隔の因子マップを格納します。 

境界 n、q ≤ 100000 は、境界値により k が小さく、セグメント ツリーの深さが対数であるため、快適に処理されます。 べき乗剰余演算も効率的です。

    input = sys.stdin.readline
    MOD = 10**9 + 7

    n = int(input())

    q = int(input())

        last = cur
    return "\n".join(res)

 ## 特殊なケース

 例外的なケースは、前の答えが大きく、l と r が回り込む場合に発生します。 たとえば、n = 3、last = 30、x = 1、y = 3 の場合、l = (30 + 1) mod 3 + 1 = 2、r = (30 + 3) mod 3 + 1 = 1 となります。スワップによりセグメント [1, 2] が生成され、クエリが有効なままであることが保証されます。 このアルゴリズムは、ツリー クエリの前に純粋にモジュラー演算を通じてこれを処理するため、無効なインデックスがセグメント ツリーに渡されることはありません。 

もう 1 つのケースは、単一要素セグメントです。 セグメント ツリーはその要素の因数分解を直接返し、1 つの数値の最小公倍数が数値であるため、再構成では要素自体が正確に生成されます。
