 ## 解決策
 ## 問題の理解

 一連の数字と 2 人のプレイヤーが与えられ、先頭の位置に 1 つの値だけが残るまでそれを繰り返し縮小します。 移動するたびに 1 つの要素が削除されますが、削除する前に、選択した隣接するペアの左側の要素が更新されます。 一方のプレイヤーは常にこの進化する値をできるだけ大きくしようとし、もう一方のプレイヤーは常にそれをできるだけ抑えようとします。 

重要な観察は、最終的に最初の要素となる値のみが重要であるということです。 他のものはすべて、配列が折りたたまれる間の一連の最大値と最小値の相互作用を通じてその値に影響を与えるための単なるツールです。 

制約により、最大で$10^5$したがって、すべてのゲーム状態をシミュレートしたり、考えられるマージの各シーケンスを考慮したりするアプローチは不可能です。 このプロセスでは、移動するたびに長さが 1 ずつ減少します。$O(n)$テストごとに動きますが、それぞれの動きは戦略的な選択に依存します。 すべての選択肢に対する素朴なミニマックスは指数関数的に分岐します。 

すべての値が等しい場合、微妙なエッジケースが発生します。 その場合、すべての操作は中立であり、答えは変わらないはずです。 もう 1 つの特殊なケースは、最大要素が先頭付近にない場合です。これは、単純な直感では、ローカル値のみが重要であると思われる可能性がありますが、実際には、マージを繰り返すことで値がインデックス 1 に近づく可能性があるためです。 

## アプローチ

 ブルート フォース シミュレーションでは、両プレイヤーのあらゆる可能な動きをモデル化し、各ステップですべての有効なインデックスを分岐させようとします。 移動するたびにシーケンスの長さが 1 ずつ減少するため、次のようになります。$n-1$それぞれの決定は次の方法で行うことができます。$O(n)$これにより、州の数が指数関数的に増加します。 それぞれの動きの影響により、将来の最適な選択が非局所的に変更されるため、枝刈りさえも役に立ちません。 

重要な洞察は、ゲームが複雑な方法で順序を保持するのではなく、最終的な位置に対する値の相対的な影響のみが重要であるということです。 各操作は、最大値を左に向かって伝播するか、最小値を左に向かって伝播します。 これは、最終的な値が完全な戦略ツリーによって決定されるのではなく、配列の単一の構造特性によって決定されることを意味します。つまり、どの要素が影響力を維持しながら最大値と最小値が交互に収縮しても生き残ることができるのかということです。 

最適なプレイは貪欲な特徴付けに崩壊することがわかりました。最初の要素は最終的に、交互の支配制約の下で到達可能な最良の値となり、ゲームをシミュレートせずに直接計算できます。 

この削減は、プロセスを一連の強制的なペアごとの削減として解釈することによって行われます。 動きの観点から考えるのではなく、最大値と最小値を交互に制御しながら、位置 1 の値がその右側の各要素と競合するときにどのように変化するかを追跡します。 これにより、ゲーム シミュレーションの必要性が完全になくなります。

 ## アルゴリズムのチュートリアル

 最適な解決策は、最初の要素が交互制御の下で残りの要素によってどのような影響を受けるかを処理することに基づいています。 

1. 現在の回答候補として最初の最初の要素から開始します。 これは、すべての操作がマージのチェーンを通じて最終的に変更に集中するため、直接追跡する唯一の値です。 
2. 配列を左から右に走査し、すべての要素がマージのシーケンスを通じて最終的に現在のプレフィックスと相互作用するという事実をシミュレートします。 動きをシミュレートする代わりに、ターンパリティに応じて各要素が現在の値を支配できるかどうかを推論します。 
3. 現在の有効な操作が最大ステップまたは最小ステップのように動作するかどうかを表す状態を維持します。 この交替は、タートルとピギーが交互に動くという事実を反映しており、時間の経過とともに、この交替は収縮プロセスを通じて伝播します。 
4. 新しい要素を処理するときは、現在のパリティ状態に応じて最大値または最小値を取得して、現在の値を更新します。 これは、一方のプレイヤーが値を上方に押し上げ、もう一方のプレイヤーが値を下方に押し下げ、すべての要素が消去順での位置に応じて両方の力を受けるという考えを捉えています。 
5. 各ステップの後に状態を反転して、効果的なチェーンに沿って交互の影響に崩壊する交互のターンを反映します。 

すべての要素を処理した後、最終的に追跡された値が答えになります。 

重要な不変条件は、最初の k 要素を処理した後、維持される値が、そのプレフィックス内のすべてのインタラクションを最適に解決した後の最初の要素の達成可能な最適な値に等しいということです。 新しい要素はそれぞれ、正しい交互演算子の下で 1 回だけ寄与し、その後の操作によって以前に解決されたマージの効果を遡って変更することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    cur = a[0]
    take_max = True
    
    for i in range(1, n):
        if take_max:
            cur = max(cur, a[i])
        else:
            cur = min(cur, a[i])
        take_max = not take_max
    
    print(cur)
```各テスト ケースを読み取った後、すべての操作シーケンスが最終的にこの位置を変換するため、結果を最初の要素で初期化します。 次に、最大更新と最小更新を交互に適用しながら、配列の残りの部分を繰り返し処理します。 ブール値フラグは、効果的な削減プロセスにおいてどのプレイヤーの影響が現在支配的であるかをエンコードします。 

交互更新は重要な簡素化です。隣接関係ベースの削除をシミュレートする代わりに、ゲーム全体を 1 つのパスに圧縮し、各要素が正しい操作タイプで 1 回だけ組み込まれます。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cur = a[0]
        take_max = True
        for i in range(1, n):
            if take_max:
                cur = max(cur, a[i])
            else:
                cur = min(cur, a[i])
            take_max = not take_max
        out.append(str(cur))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 のような入力の場合`[5, 5, 5, 5]`、最大値または最小値に関係なく、すべての操作で値は変更されません。 アルゴリズムは最大値と最小値を交互に繰り返しますが、どちらの操作もすべてのステップで同じ値を返すため、不変式が保持され、最終的な答えは 5 のままになります。 

次のような厳密に減少する配列の場合`[4, 3, 2, 1]`、最初の max 操作は何も害を及ぼしませんが、次の min 操作はすぐに値を押し下げ、交互は計算結果と一致する 2 で安定します。 

2要素配列の場合`[x, y]`、max 演算が 1 つだけ発生するため、結果は単純に次のようになります。`max(x, y)`、これは最初の動きの直後にゲームが終了することと一致しています。
