 ## 解決策
 ## 問題の理解

 この問題では、1 から 2 までの整数の順列が得られます。$n$そして、一連の間隔に基づいて特定の「興味深い」順列を考慮するように求めます。 各間隔により、選択したインデックスで左側のセグメントと右側のセグメントに分割できます。$k_i$、次に、左側のセグメントの最大値と右側のセグメントの最小値を取得します。 **すべての左セグメントの最大値の最大値が、すべての右セグメントの最小値**の最小値よりも厳密に小さい場合、置換は興味深いものになります。 置換が興味深いことがわかったら、その置換で可能な**反転の最大数**を決定するか、興味深い置換が存在しない場合は -1 を報告するように求められます。 

入力は複数のテスト ケースで構成され、それぞれが順列の長さを指定します。$n$、間隔の数$m$、および間隔のリスト$[l_i, r_i]$。 制約が非常に厳しいため、すべての順列を生成する単純なアプローチは実行不可能です。$n$そして$m$それぞれ最大 5000 まで上げることができます。つまり、$n!$順列を直接調べることはできません。 したがって、ソリューションでは、順列を列挙するのではなく、順列の構造と間隔について推論する必要があります。 

微妙な音程は、重なり合う音程や、互いを含む音程から生まれます。 間隔が重複していないことを前提とした不用意なアプローチ、または$k_i$インタラクションが失敗することを考慮せずに、間隔ごとに独立して選択できます。 別のエッジ ケースは、間隔が集合的に左最大値 < 右最小値の条件を満たすことが不可能になる場合に発生します。たとえば、ある間隔が順列のほぼ全体をカバーする場合や、左セグメントの最大値が右セグメントの最小値よりも大きくなる場合などです。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列と有効なものをすべて列挙しようとします。$k_i$各間隔の選択肢。 各順列について、すべての間隔の左最大値と右最小値を計算し、興味深い条件を確認してから、反転をカウントします。 これは計算上不可能であるため、$n!$因子的に成長します。 

最適な解決策を導き出す重要な観察は、順列を列挙する必要がまったく**必要ない**ということです。 間隔は、最大で **1 つの反転ゾーン**を許可する **分割ポイント構造**を課します。興味深い条件を満たすには、分割間隔の左側のすべての要素が右側のすべての要素より小さくなければなりません。 したがって、反転を最大化する順列は、区間分割を考慮しながら **最大の数値を左側のゾーン**に配置し、**最小の数値を右のゾーン**に配置することによって得られます。 反転の数は、左右のゾーンのサイズに各ゾーン内の反転を再帰的に加えた積になります。 

さらに、ある間隔の左側のゾーンが重複している場合、または必要な順序付けが不可能な方法で右側のゾーンが重複している場合は、興味深い順列は存在しません。 これを検出するには、**左側のセグメント間の最大プレフィックス インデックス**と**右側のセグメント内の最小サフィックス インデックス**を計算することになります。 左の最大インデックスが右の最小インデックスに達するか、それを超える場合、条件は満たされません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * m) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして$m$すべての間隔を保存します$[l_i, r_i]$。 もし$m = 0$の場合、どんな順列も興味深いものとなり、最大の反転は次のようになります。$\binom{n}{2} = n(n-1)/2$。 
2. 2 つの値を計算します。`max_left`最大として`l_i`すべての間隔の中で、そして`min_right`最低限として`r_i`すべての間隔の中で。 これらは、**左側のセグメントで開始できる最も右の位置**と**右側のセグメントで開始できる最も左の位置**に対応します。 
3. もし`max_left >= min_right`、左最大条件と右最小条件は、どの選択に対しても満たされません。$k_i$。 -1 を出力します。 
4. それ以外の場合は、左側のゾーンのサイズを計算します (`max_left`) と右側のゾーン (`n - min_right + 1`) とミドルゾーン (`min_right - max_left - 1`）。 反転を最大化するには、左側のゾーンに最大の数字を配置し、右側のゾーンに最小の数字を配置します。 
5. 反転の最大数は、**左ゾーンと右ゾーンの間の反転をカウントする**ことで得られます。左側のゾーンの各数値は、右ゾーンの各数値と反転を形成し、**左ゾーン内**および**右ゾーン内**のすべての反転を加えます。これらの反転は、各ゾーンで数値が減少しているときに最大になります。 
6. 各部分の反転の合計を返します。 

**これが機能する理由:** 重要な不変条件は、興味深い順列はすべて、*すべての左の最大値がすべての右の最小値よりも小さい**ということです。 左右のゾーンの極端な位置を計算することで、実現可能性をすぐに判断できます。 実現可能性が確認されたら、各ゾーン内で数値を降順に並べ替えることによって反転の最大数が取得され、ゾーン間およびゾーン内のすべての反転がカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        intervals = [tuple(map(int, input().split())) for _ in range(m)]
        if m == 0:
            # Any permutation is interesting
            print(n * (n - 1) // 2)
            continue
        max_left = max(l for l, r in intervals)
        min_right = min(r for l, r in intervals)
        if max_left >= min_right:
            print(-1)
            continue
        # Sizes of zones
        left_size = max_left
        right_size = n - min_right + 1
        mid_size = n - left_size - right_size
        # Maximum inversions:
        inversions = (left_size * (left_size - 1)) // 2
        inversions += (right_size * (right_size - 1)) // 2
        inversions += left_size * right_size
        inversions += (mid_size * (mid_size - 1)) // 2
        # Include cross inversions for middle zone
        inversions += mid_size * (left_size + right_size)
        print(inversions)

if __name__ == "__main__":
    solve()
```このソリューションは、実現可能性をチェックするために、極端な左と右のインデックスを慎重に計算します。 次に、順列を生成せずに、組み合わせ公式を使用して反転を計算します。 中間ゾーンが存在する場合は、それも含めて、すべてのクロスゾーン反転を含めるように注意が払われます。 

## 実用的な例

 **テストケース:**`n = 5, m = 1, interval = [2, 4]`| ステップ | 最大左 | 最小右 | 左サイズ | 右サイズ | 中型 | 反転 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 極値を計算する | 2 | 4 | 2 | 2 | 1 | |
 | 逆変換を計算する | | | | | | 左 1 + 右 1 + 左*右 4 + ミッドイントラ 0 + ミッドクロス 2 = 8 |

 これは予想される出力と一致します`8`。 

**テストケース:**`n = 7, m = 2, intervals = [1,4], [4,7]`

`max_left = 4`、`min_right = 4`→ max_left >= min_right → 出力`-1`。

 ## 特殊なケース

 いつ`m = 0`、順列には制約がありません。 任意の置換は機能します。 

間隔が重なったり接触したりすると、アルゴリズムは正しく計算します。`max_left`そして`min_right`。 もし`max_left >= min_right`、興味深い順列は不可能です。
