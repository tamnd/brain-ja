 ## 解決策
 ## 問題の理解

 マンハッタンまでの 3 つの距離が与えられています。 1 人のプレイヤーが未知の整数座標にいます`(x1, y1)`、もう一方はにあります`(x2, y2)`、原点は 3 番目の基準点です。 最初の距離は、最初のプレーヤーがどれくらい離れているかを示します。`(0,0)`、2 番目は 2 番目のプレーヤーについても同じことを示し、3 番目は 2 人のプレーヤー間の距離を示します。 タスクは、3 つの測定値をすべて満たす整数位置の順序ペアがいくつあるかを数えることです。 2人のプレイヤーを交換すると、異なる状況が生まれます。 

入力には最大で次のものが含まれます`100000`独立したテスト ケースであり、それぞれの距離は次のように大きくできます。`10^9`。 1 つのマンハッタン円にも数十億の整数点が含まれる可能性があるため、可能な座標を直接列挙することは不可能です。 ソリューションはすべてのテスト ケースを一定時間で処理する必要があります。 

主なトラップケースはパリティによって引き起こされます。 座標を変換した後、変換された平面内のすべての点が元の平面内の整数点に対応するわけではありません。 もう 1 つのよくある間違いは、2 人のプレーヤーに命令が出されていることを忘れることです。 

たとえば、入力が次の場合:```
1
1 1 1
```答えは`0`。 マンハッタン距離にある 2 点`1`原点からの距離がマンハッタンの距離にあることはできません`1`この方法で、変換された座標の必要なパリティを尊重しながら、相互に変換できます。 パリティのオーバーカウントをチェックせずに、変換されたすべての正方形の境界点をカウントするソリューション。 

もう 1 つのエッジ ケースは、両方のプレイヤーがオリジンにいる場合です。```
1
0 0 0
```答えは`1`、両方の座標が次のとおりである必要があるため、`(0,0)`。 正方形のサイズのみに基づく数式では、存在しない方向を誤ってカウントしてしまう可能性があります。 

3 番目の重要なケースは、原点からの 2 つの測定距離が異なるが、プレーヤーが入れ替わる場合です。 のために：```
1
2 4 2
```答えは、距離 2 層の先手プレイヤーと距離 4 層の後手プレイヤーの状況を、逆の配置とは別にカウントします。 ペアを順序なしとして扱うと、有効な答えが失われます。 

## アプローチ

 ブルートフォースソリューションでは、マンハッタン距離を持つすべての整数点が生成されます。`d01`原点からマンハッタン距離ですべての点を生成します`d02`、すべてのペアをテストします。 マンハッタンの半径上の点の数`r`に比例する`r`ということで、最悪のケースは`10^9`レイヤーごとのポイント。 それらを組み合わせると、実現可能な限界をはるかに超えます。 

重要な観察は、座標系を回転するとマンハッタンの距離がはるかに単純になるということです。 定義する：```
u = x + y
v = x - y
```2 点の場合、マンハッタン距離は次のようになります。```
max(|u1-u2|, |v1-v2|)
```原点からの距離は次のようになります。```
max(|u|, |v|)
```したがって、問題は元の平面のひし形から、軸が揃った正方形に変わります。`(u,v)`飛行機。 

ポイント`(u,v)`整数を表します`(x,y)`そのときだけ`u`そして`v`同じパリティを持っています。 正方形の境界を列挙する代わりに、正方形内のペアを数え、包含-除外を使用して境界を回復します。 

させて`G(a,b,r)`最初の点が半径の二乗の内側にある、変換された点のペアの数になります。`a`、2 番目は半径の 2 乗の内側にあります`b`、それらのチェビシェフ距離は最大です`r`。 この場合、必要な 2 つのレイヤー上の正確なペアの数は次のようになります。```
G(a,b,r) - G(a-1,b,r) - G(a,b-1,r) + G(a-1,b-1,r)
```最後に、正確な距離の答え`c`最大距離を含む数値です`c`最大距離を含む数値を引いたもの`c-1`。 

計算するには`G`、変換されたポイントをパリティによって分割します。 ポイントにできるのは`(u,v)`両方とも偶数、または両方とも奇数。 最初の点と 2 番目の点のパリティを選択するたびに、2 つの座標は独立した 1 次元の計数問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d01 * d02) | お(1) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次を使用してマンハッタン問題をチェビシェフ問題に変換します。`u=x+y`そして`v=x-y`。 

変換によりひし形が正方形に変わり、軸が揃った範囲について推論できるようになります。 

1. 最大距離のある 2 つの正方形内の変換された点のペアをカウントする関数を実装します。`r`。 

半径の正方形`a`変換された両方の座標が間にあるすべての点が含まれます`-a`そして`a`。 境界線を直接処理するのは難しいため、最初にこれらの正方形の領域をカウントします。 

1. カウントをパリティごとに分割します。 

最初のポイントと 2 番目のポイントの考えられるすべてのパリティについて、有効なカウントをカウントします。`u`座標と有効`v`独立してコーディネートします。 これら 2 つのカウントの積により、そのパリティの組み合わせの 2 次元ペアの数が求められます。 

1. 1 次元のプレフィックスカウントを使用します。 

1 つの座標について、2 で割った後、差が区間内にあるインデックスのペアを数える必要があります。 これは、差が最大 1 値であるペアのプレフィックス数を計算することで実行できます。 

1. 包含排他を使用して、正方形数を層数に変換します。 

外側の正方形から内側の正方形を減算すると、必要なマンハッタン距離に正確にある点だけが残ります。 

1. 正確な距離の答えを計算します。 

必要な距離は正確に`d12`なので、最大でも距離を使って数値を計算します。`d12`最大距離で数値を引きます`d12-1`。 

なぜ効果があるのか:

 座標変換では、問題に必要な距離が維持されます。 すべての有効な元の点は、一致する座標パリティを持つ 1 つの変換された点にマッピングされ、等しい座標パリティを持つすべての変換された点は、正確に 1 つの整数点にマッピングされます。 正方形の包含/除外では、要求された距離レイヤー上にないすべてのポイントが 1 回だけ削除されます。 最後の減算では、必要な 3 番目の距離よりも距離が小さいすべてのペアが削除され、必要な距離を持つペアが正確に残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return -((-a) // b)

def sum_range(l, r):
    if l > r:
        return 0
    return (l + r) * (r - l + 1) // 2

def prefix_diff(n1, n2, s):
    # number of pairs (i, j), 0 <= i < n1, 0 <= j < n2, i-j <= s
    ans = 0

    l = 0
    r = min(n1 - 1, s)
    if l <= r:
        ans += (r - l + 1) * n2

    l = max(0, s + 1)
    r = min(n1 - 1, s + n2 - 1)
    if l <= r:
        ans += (r - l + 1) * (n2 + s) - sum_range(l, r)

    return ans

def count_difference(l1, r1, l2, r2, lo, hi):
    if l1 > r1 or l2 > r2:
        return 0
    n1 = r1 - l1 + 1
    n2 = r2 - l2 + 1
    shift = l1 - l2
    return prefix_diff(n1, n2, hi - shift) - prefix_diff(n1, n2, lo - 1 - shift)

def coordinate_count(a, b, r, p, q):
    if a < 0 or b < 0:
        return 0

    l1 = ceil_div(-a - p, 2)
    r1 = (a - p) // 2
    l2 = ceil_div(-b - q, 2)
    r2 = (b - q) // 2

    if l1 > r1 or l2 > r2:
        return 0

    diff = p - q
    lo = ceil_div(-r - diff, 2)
    hi = (r - diff) // 2

    return count_difference(l1, r1, l2, r2, lo, hi)

def square_count(a, b, r):
    if a < 0 or b < 0:
        return 0

    ans = 0
    for p in (0, 1):
        for q in (0, 1):
            c = coordinate_count(a, b, r, p, q)
            ans += c * c
    return ans

def inside_layers(a, b, r):
    return (
        square_count(a, b, r)
        - square_count(a - 1, b, r)
        - square_count(a, b - 1, r)
        + square_count(a - 1, b - 1, r)
    )

def solve_case(a, b, c):
    if c < 0:
        return 0
    return inside_layers(a, b, c) - inside_layers(a, b, c - 1)

t = int(input())
out = []
for case in range(1, t + 1):
    a, b, c = map(int, input().split())
    out.append(f"Case #{case}: {solve_case(a, b, c)}")

print("\n".join(out))
```の`ceil_div`ヘルパーが必要なのは、Python の整数の除算は切り捨てられるためですが、座標範囲を変換する場合は数学的な上限の除算が必要です。 

の`prefix_diff`関数は、コアとなる 1 次元のカウント ルーチンです。 考えられる最初のインデックスを 3 つの領域に分割します。1 つおきの座標が機能するインデックス、間隔の一部のみが機能するインデックス、2 番目の座標が機能しないインデックスです。`coordinate_count`パリティを固定することにより、変換された座標範囲をインデックス範囲に変換します。 距離条件は 2 つの指数の差の範囲になります。`square_count`4 つのパリティの組み合わせを組み合わせます。 乗算自体は有効です。`u`そして`v`変換後の寸法は独立しています。`inside_layers`包含/除外を適用して内側の正方形レイヤーを削除します。 ついに、`solve_case`「最大距離」カウントを正確な距離カウントに変更します。

 ## 特殊なケース

 対象:```
1
0 0 0
```変換された正方形は両方とも半径 0 です。 包含-除外では、単一の変換点のみが残ります。`(0,0)`、原点に対応します`(0,0)`。 

のために：```
1
1 1 1
```変換された正方形にはいくつかの点がありますが、`u`そして`v`共有パリティは有効です。 パリティ分割`square_count`カウントする前に無効な変換されたポイントを破棄します。 

のために：```
1
2 4 2
```2 人のプレーヤーは異なるマンハッタン層に属しています。 包含-除外では各正方形の境界のみが保持され、最後の距離の減算ではチェビシェフ距離がちょうど 2 であるペアのみが保持されます。 

次のような非常に長い距離がある場合:```
1
1000000000 1000000000 1000000000
```アルゴリズムは座標範囲を反復することはありません。 すべての計算は整数演算で行われるため、大きな境界は中間値のサイズにのみ影響します。 Python の整数はこれらの値を安全に処理します。
