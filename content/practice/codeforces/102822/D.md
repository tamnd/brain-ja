 ## 解決策
 # 問題の理解

 この問題は爆弾のコレクションを記述しており、各爆弾にはカウントダウン値があります。 1 回のアクションで爆弾を 1 つ選択し、そのクロックを 1 つ増やすことができます。 その直後、すべての爆弾の時計が 1 つ減ります。 この減少後にいずれかのクロックが負になった場合、プロセスは終了します。 目標は、爆発が起こる前に実行されるアクションの選択数を最大化することです。 

入力には複数のテスト ケースが含まれています。 各テスト ケースでは、爆弾の数と各爆弾の初期クロック値が示されます。 出力は、ケースの回答として形式化された、爆弾を選択できる最大回数です。 

到達できる爆弾の数$10^5$、すべてのテスト ケースにわたる爆弾の合計数は最大で$3 \times 10^5$。 考えられるすべての選択シーケンスを試す解決策は、可能なシーケンスの数が指数関数的に増加するため不可能です。 クロック値が大きい場合、答えが非常に大きくなる可能性があるため、あらゆる瞬間に最適な選択を見つけようとするシミュレーションでも時間がかかりすぎます。 クロックの値は次の値に達します。$10^9$したがって、アルゴリズムは答えの大きさではなく爆弾の数に依存する必要があります。 

難しいのは、すぐに爆発を引き起こす可能性があるにもかかわらず、最後のアクションがカウントされることです。 よくある間違いは、安全に完了したラウンドのみをカウントすることです。 

例えば：```
1
2
1 1
```正しい出力は次のとおりです。```
Case #1: 3
```不注意なシミュレーションでは、2 ラウンド完了後、両方の爆弾が空になるため、2 と表示される可能性があります。 ただし、もう 1 つの選択アクションを実行する時間はまだあり、爆発は次の減少後にのみ発生します。 

もう 1 つのエッジ ケースは、いくつかの爆弾がゼロから始まる場合です。```
1
3
0 5 5
```最初の爆弾は、重要なたびに選択しない限り、ラウンドを生き残ることはできません。 クロックの合計だけを調べるソリューションでは、個々の爆弾に十分な保護が必要であることを見落とす可能性があります。 

## アプローチ

 直接的なアプローチでは、プロセスをシミュレートして、毎ターンどの爆弾を増やすかを決定しようとします。 爆弾を選択すると、そのラウンドでの減少から爆弾が保護されるため、自然な欲張りな考えは、常に現在値が最小の爆弾を選択することです。 これは小規模なケースでは機能しますが、問題の実際の構造は明らかになりません。 答えはすべてのクロックの合計と同じくらい大きくなり、シミュレーションが非常に遅くなる可能性があります。 

重要な観察は、個々の選択ではなく、一定数の安全なラウンドに注目することから得られます。 

私たちが生き残りたいと思っているとします$x$ラウンドを完了します。 爆弾$i$選択されなかった場合は、ラウンドごとに 1 つずつ失われます。 それが選ばれたら$c_i$回、その後の最終値$x$ラウンドは次のとおりです。$$a_i - (x - c_i)$$爆弾が生き続けるためには、次のものが必要です。$$c_i \geq x-a_i$$もし$x-a_i$が負の場合、爆弾には特別な保護は必要ないため、実際の要件は次のとおりです。$$c_i \geq \max(0, x-a_i)$$で利用可能な選択肢の総数$x$ラウンドはまさに$x$。 したがって、$x$以下の場合、安全なラウンドが可能です。$$\sum_i \max(0, x-a_i) \leq x$$この条件は単調です。 私たちが生き残ることができれば$x$そうすれば、より少ないラウンドで生き残ることができます。 もし私たちが生き残れないなら$x$ラウンドの場合、より大きな値は不可能です。 これにより二分探索が可能になります。 

次の選択アクションは爆発が発生する前にカウントされるため、必要な答えは完全な安全ラウンドの最大数より 1 つ多くなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(答え × n) | O(n) | 遅すぎる |
 | ラウンドの二分探索 | O(n log(sum(a))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての初期爆弾クロックの合計を計算します。 これにより、考慮する必要がある完全なラウンド数の上限が決まります。これは、ラウンドごとにクロック値の総量が減少するためです。$n-1$、二分探索には安全な上限のみが必要です。 
2. 二分探索による完全な安全ラウンドの最大数$x$。 候補者にとって$x$, 弱い爆弾によってどれだけの選択肢が強制されるかを計算します。 爆弾$i$必要$\max(0, x-a_i)$選択肢。 
3. 必要な選択肢の合計が最大でも$x$、この値を可能な限りマークし、より多くのラウンド数を検索します。 それ以外の場合は、より小さい値を検索します。 
4. 可能な限り最大の完全なラウンド数を見つけた後$x$、出力$x+1$。 余分なものは、その後の爆発を引き起こす最終的な選択アクションを表します。 

なぜ効果があるのか:

 二分探索条件は、利用可能な選択肢がすべての爆弾を存続させることができるかどうかを正確に記述します。 クロックが小さすぎる爆弾は、受ける減少を補うのに十分な頻度で選択する必要があります。 これらの最小要件の合計が、必要な選択肢の最小数となります。 これがこの中に収まれば、$x$利用可能なラウンドがある場合、有効なスケジュールが存在します。 条件は単調であるため、二分探索では可能な最大値が見つかります。$x$1 を追加すると、最終的にカウントされるアクションが計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    total = sum(a)

    def possible(x):
        need = 0
        for v in a:
            if x > v:
                need += x - v
                if need > x:
                    return False
        return True

    lo, hi = 0, total + 1
    while lo + 1 < hi:
        mid = (lo + hi) // 2
        if possible(mid):
            lo = mid
        else:
            hi = mid

    return lo + 1

def main():
    t = int(input())
    ans = []

    for case in range(1, t + 1):
        n = int(input())
        a = list(map(int, input().split()))
        ans.append(f"Case #{case}: {solve_case(a)}")

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```の`possible`関数は、上記で導出された数学的条件をチェックします。 爆弾には少なくとも価値があるため、爆弾に必要な追加の選択のみがカウントされます。`x`生き残ることができる`x`保護を必要とせずにラウンドします。 

二分探索では、半分開いた上限境界が使用されます。`total + 1`完全なラウンドの答えがすべてのクロックの合計を超えることはないため、安全です。 この問題では完全に完了したラウンドの数ではなく、アクションの選択の数が求められているため、最終的な答えは 1 つ増えます。 

内部の早期復帰`possible`不必要な作業を回避します。 必要な選択肢が利用可能なラウンドを超えると、候補値はすでに不可能になります。

これらのトレースは、ソリューションが爆弾を選択する正確な順序を決定する必要がない理由を示しています。 この不等式は、選択肢の分布が存在するかどうかのみを問うものです。

import io

    sys.stdin = io.StringIO(inp)

        def possible(x):
            need = 0
            for v in a:
                if x > v:
                    need += x - v
                    if need > x:
                        return False
            return True

        lo, hi = 0, total + 1
        while lo + 1 < hi:
            mid = (lo + hi) // 2

                lo = mid
            else:
                hi = mid
        return lo + 1

    t = int(input())
    out = []
    for case in range(1, t + 1):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(f"Case #{case}: {solve_case(a)}")

    sys.stdin = old_stdin
    return "\n".join(out)

 ## 特殊なケース

 この場合の場合:```
1
2
1 1
```二分探索は完全なラウンドをチェックします。 各ボムは1回ずつ選択できるため、2ラウンドが可能です。 各爆弾には 2 つの保護が必要であり、4 つの選択肢が必要になるため、3 ラウンドは不可能です。 アルゴリズムは戻ります`2 + 1 = 3`、爆発を引き起こす最後のアクションを正確に数えます。 

この場合の場合:```
1
3
0 5 5
```最初の爆弾はゼロから始まります。 1 ラウンドを完全に生き残るためには、それを選択する必要があります。選択しないとマイナスになってしまいます。 条件には以下が必要です。$$\max(0,1-0)+\max(0,1-5)+\max(0,1-5)=1$$選択肢は1つなのでラウンド可能です。 値が大きい場合、最終的に必要な保護が利用可能な選択肢を超え、二分探索は正しい時点で停止します。 

この場合の場合:```
1
3
0 0 0
```すべての爆弾は、価値が失われる場合には必ず選択する必要があります。 完全なラウンドがゼロになった後でも、最後の選択アクションが 1 つ可能であるため、答えは 1 になります。アルゴリズムはこれを処理します。`+1`安全ラウンドの計算とは別のものです。
