 ## 解決策
 ## 問題の理解

 未知のトライに対して実行されたいくつかの検索の結果が与えられます。 各検索はルートから開始され、可能な限り文字列の文字をたどります。 次のエッジが存在しない場合、検索は直ちに停止し、現在のノードに格納されている値を返します。 元のトライのすべてのノードは一意の値を持っているため、返された数値は 1 つのノードを正確に識別します。 

タスクは、指定されたすべてのクエリ結果を生成する可能性のあるトライ内のノードの最小数を再構築することです。 ルートもノードとしてカウントされます。 すべての観察を満足できるトライがない場合は、それを報告する必要があります。 

入力により、いくつかのテスト ケースが得られます。 各テスト ケースでは、すべてのクエリに小文字の文字列と、その文字列の検索操作によって返された値が含まれます。 

1 つのテスト ケース内のすべての文字列の長さの合計は最大で (10^5) であり、すべてのテスト ケースの合計は最大で (5 \times 10^5) です。 これにより、文字列のすべてのペアを比較したり、構造を繰り返し再構築したりするソリューションが除外されます。 アルゴリズムは、合計入力サイズにおいて線形に近い必要があります。 

主なエッジ ケースは、長い文字列に関するものではなく、プレフィックスや競合する値に関するものです。 2 つの同一のクエリの答えが異なる場合、同じパスをたどると常に同じノードで終了する必要があるため、トライは存在できません。 

例えば：```
2
a 1
a 2
```正しい出力は次のとおりです`-1`。 不用意に実装すると、値の 1 つだけが保持され、大文字と小文字が誤って受け入れられる可能性があります。 

もう 1 つの注意が必要なケースは、ある文字列が別の文字列のプレフィックスであり、答えが一致しない場合です。```
2
a 1
aa 2
```正しい出力は次のとおりです`-1`。 を表すノードが`a`価値がある`1`、クエリ`aa`エッジが存在する場合にのみ別のノードを返すことができます`a -> a`存在します。 しかし、その後のクエリは`a`読み取り後にもノードで停止します`a`, したがって、2 つの要件を同時に満たすことはできません。 

3 番目の重要なケースは、多くの異なる文字列の答えが同じである場合です。```
3
aa 1
ab 1
ac 1
```正しい出力は次のとおりです`1`。 空のルートノードには値を保存できます`1`、最初のエッジが存在する必要がないため、3 つのクエリはすべてすぐに停止します。 

## アプローチ

 直接的なアプローチは、クエリされたすべての文字列をトライに挿入し、ノードに値を割り当ててみることです。 これにより、多くのプレフィックスが不要な場合でも、すべてのプレフィックスが構築されます。 最悪の場合、長さ (10^5) の文字列が (10^5) 個ある場合、考えられるプレフィックス関係の数が多すぎて、繰り返しチェックできなくなります。 

重要な点は、ノードは、そのノードの下で異なる回答を分離する必要がある場合にのみ存在する必要があるということです。 プレフィックスを通過するすべてのクエリが同じ戻り値を持つ場合、そのプレフィックスで停止して、そこに値を割り当てることができます。 クエリ結果は最初の欠落エッジのみを考慮するため、元の挿入文字列がどこにあったかを知る必要はありません。 

これにより、自然に再帰的な構築が行われます。 すべてのクエリ文字列の通常のトライを構築します。 各ノードで、そのサブツリーに表示される値のセットを確認します。 そのセットに含まれる値が 1 つだけの場合、サブツリー全体をこの単一のノードで置き換えることができます。 複数の値が表示される場合は、ノードを残し、その子を個別に解決する必要があります。 

ブルート フォース アプローチと最適なアプローチの違いは、不要なプレフィックスを保持するかどうかだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(L^2)) | (O(L)) | 遅すぎる |
 | 最適 | (O(L)) | (O(L)) | 承認済み |

 ここで (L) は、テスト ケース内のすべてのクエリ文字列の合計長です。 

## アルゴリズムのチュートリアル

 1. すべてのクエリ文字列をトライに挿入します。 各文字列の終端ノードに値を格納します。 同じ文字列が異なる値で出現する場合、同一の検索では異なるノードを生成できないため、回答は不可能です。 
2. 深さ優先検索でトライをトラバースします。 ノードごとに、そのサブツリー内のすべての終端文字列に表示される個別の値を収集します。 
3. ノードのサブツリーに値が 1 つだけ含まれている場合は、サブツリー サイズ 1 を返します。 ノード自体はこれらすべてのクエリを表すことができるため、すべての子孫は不要です。 
4. ノードに複数の値が含まれている場合は、このノードを保持し、少なくとも 1 つのクエリを含むすべての子を再帰的に処理します。 それらの子ソリューションのサイズを追加します。 
5. ルートに対して返されるサイズは、トライ ノードの最小可能数です。 

なぜ効果があるのか:

 プレフィックスを表す任意のノードを考えてみましょう。 このノードの下にあるすべてのクエリは、最終的にはこのサブツリー内のノードを返す必要があります。 これらすべてのクエリが同じ値を必要とする場合、それらを現在のノードにマージすることは常に有効であり、ノードが節約されます。 異なる値が必要な場合、各トライ ノードには値が 1 つしかないため、現在のノードを共有できません。そのため、子は異なるケースを分離する必要があります。 再帰的なプロセスでは、すべてのプレフィックスでこれら 2 つの選択が正確に行われるため、不要なノードはすべて削除され、必要な区別はすべて保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("children", "value")
    def __init__(self):
        self.children = {}
        self.value = None

def solve_case(data):
    root = Node()

    for s, v in data:
        cur = root
        for c in s:
            if c not in cur.children:
                cur.children[c] = Node()
            cur = cur.children[c]
        if cur.value is not None and cur.value != v:
            return -1
        cur.value = v

    def dfs(node):
        vals = set()
        if node.value is not None:
            vals.add(node.value)

        child_info = []
        for child in node.children.values():
            ok, size, child_vals = dfs(child)
            if not ok:
                return False, 0, set()
            child_info.append((size, child_vals))
            vals.update(child_vals)

        if len(vals) == 1:
            return True, 1, vals

        size = 1
        for child_size, _ in child_info:
            size += child_size

        return True, size, vals

    ok, ans, _ = dfs(root)
    return ans if ok else -1

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n = int(input())
        queries = []
        for _ in range(n):
            s, v = input().split()
            queries.append((s, int(v)))

        out.append(f"Case #{case}: {solve_case(queries)}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```挿入フェーズでは、必要な唯一の構造が作成されます。 多くの異なる挿入文字列セットが同じクエリ結果をもたらす可能性があるため、忘れられた挿入操作をシミュレートしようとはしません。 

DFS はソリューションの中核です。 返されたセットには、現在のプレフィックスの下にまだ表現する必要があるすべての値が含まれています。 セットのサイズが 1 になると、サブツリー全体が現在のノードに折りたたまれます。 

挿入中の競合チェックは、最も単純で不可能なケースを早期に処理します。 これがないと、異なる答えを持つ同一の文字列が誤ってマージされる可能性があります。 

再帰ではプレフィックスが 2 回探索されることはないため、合計作業量は作成されたトライ ノードの数に比例します。

def run(inp: str) -> str:

 ## 特殊なケース

 同一の文字列に異なる値がある場合、アルゴリズムは挿入中に矛盾を検出します。 ターミナルノードは 2 つの異なる値を保存できないため、すぐに戻ります。`-1`。 

のために：```
2
a 1
a 2
```挿入は同じ終端ノードに 2 回到達します。 最初のクエリは値を保存します`1`、2番目のクエリは値を保存しようとします`2`。 1 つのトライ ノードが両方の値を持つことはできないため、このようなケースは不可能です。 

短い文字列と長い文字列で異なる回答が必要な場合、DFS はそれらを分離するのに十分なノードを保持します。 

のために：```
2
a 1
aa 2
```ルートには 2 つの値が含まれるため、子を保持する必要があります`a`。 このノードにはまだ 2 つの値が含まれているため、子ノードを保持する必要があります。`aa`。 結果のサイズは、`3`、ルートを表し、`a`、 そして`aa`。 

多くの文字列が同じ応答を共有する場合、DFS は不要な子孫をすべて削除します。 

のために：```
3
aa 1
ab 1
ac 1
```ルートには値のみが表示されます`1`その下にあるため、それが応答ノードとなり、すべての子が消えます。 ノードの最小数は正確に`1`。
