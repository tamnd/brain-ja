 ## 解決策
 ## 問題の理解

 この問題は、周期的に点滅する複数の電球を含む回路について説明しています。 それぞれの電球には周期があります`t`そして明るさの値`x`。 電球は、長さの各サイクルの前半で点灯したままになります。`2t`、後半はオフのままです。 現在点灯している電球を毎秒次から判断する必要があります。`1`に`m`。 ある瞬間にすべての電球が消えた場合、その秒の答えは次のようになります。`0`。 

入力には複数のテスト ケースが含まれています。 ケースごとに、シミュレーションする電球の数と秒数を受け取り、その後に各電球の周期と明るさを受け取ります。 出力は、要求された秒ごとの最大輝度です。 

制約は、意図したソリューションの鍵となります。 電球の数とクエリの秒数はそれぞれ到達可能です`100000`、すべてのテスト ケースの合計が次の値に達する間、`200000`。 すべての電球を毎秒チェックするソリューションには、最大で`10^10`これは 2 秒の制限をはるかに超えています。 に近いものが必要です`O(m log m)`または`O((n+m) log m)`。 

最初のエッジケースは、複数の電球が同じ周期を持つ場合です。 例えば：```
1
3 3
2 5
2 8
2 3
```正しい出力は次のとおりです。```
Case #1: 8 8 0
```不用意に実装すると、指定された期間の最初の電球のみが保存され、より明るい電球が失われる可能性があります。 同じ周期の電球はまったく同じ秒間アクティブになるため、それらの最大の明るさだけが問題になります。 

もう 1 つのエッジ ケースは、クエリされた秒に正確に電球が消える場合です。 例えば：```
1
1 3
1 7
```電球は2秒目に点灯します`1`、秒でオフ`2`、2番目以降`3`したがって、出力は次のようになります。```
Case #1: 7 0 7
```サイクルを長さがあるものとして扱う`t`の代わりに`2t`、または次のような間違った境界を使用します。`<= t`サイクルの間違った側に立つと、不正確な答えが生成されます。 

## アプローチ

 簡単なアプローチは、毎秒シミュレーションしてすべての電球をテストすることです。 毎秒ごとに`s`、サイクル内の位置を調べることで、各電球がアクティブかどうかを確認します。 これは点滅パターンの定義に直接従うため、これは正しいです。 ただし、最悪のケースは、`n * m`となり、`10^10`両方の値が次の場合の演算`100000`。 

有益な観察は、球根を期間ごとにグループ化することで得られます。 2 つの電球の周期が同じであれば、オンとオフの瞬間は永遠に同じになります。 唯一の違いは明るさなので、すべての電球を定期的に交換できます`t`そのうちの最大の明るさの代表値を1つとします。 

ここで必要なのは、すべての個別の期間を処理することだけです。 ピリオド付きの電球`t`間隔の明るさに貢献します。```
[1, t], [2t+1, 3t], [4t+1, 5t], ...
```このような間隔の数は約`m / (2t)`。 短い期間には多くの間隔がありますが、長い期間には間隔がほとんどありません。 作業全体は次の調和系列によって制限されます。```
m/1 + m/2 + m/3 + ... + m/m = O(m log m)
```これにより、各期間の寄与を効率的に追加できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 最適 | O((n + m) log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての電球を読み取り、期間ごとに保存します`t`、その期間の電球の最大明るさ。 最大値のみを保持する理由は、同じ期間により同一のオン/オフ スケジュールが作成されるためです。 
2.秒の応答配列を作成します。`1`を通して`m`。 数秒間はアクティブな電球がない可能性があるため、すべての値が 0 に等しい状態で開始されます。 
3. 期間ごと`t`というメッセージが表示されたら、その期間の電球がアクティブになるすべての間隔に、保存されている明るさを追加します。 アクティブな間隔は次から始まります。`1`、長さがある`t`を繰り返します。`2t`秒。 
4. 間隔内で 1 秒ごとに 1 つずつ更新する代わりに、差分配列を使用します。 アクティブなインターバルの場合`[l, r]`、 増加`diff[l]`そして減少します`diff[r+1]`。 後でプレフィックスの合計により、これらの間隔の更新が各秒の輝度値に変換されます。 
5. すべての期間を処理した後、差分配列のプレフィックスの合計を計算します。 現在の値は、その秒におけるすべての処理された期間が寄与する最大輝度です。 

機能する理由: 各期間は独立して処理され、差分配列はその期間が明るさに寄与する秒数を正確に記録します。 各期間で最も明るい電球だけを保管しているため、廃棄された電球があれば、いつでもより大きな答えが得られるはずはありません。 すべての期間にわたって最大値を取得することは、すべての間隔更新を適用し、最大のアクティブな明るさを保存することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())

        best = [0] * (m + 1)

        for _ in range(n):
            period, brightness = map(int, input().split())
            if period <= m and brightness > best[period]:
                best[period] = brightness

        diff = [0] * (m + 3)

        for period in range(1, m + 1):
            if best[period] == 0:
                continue

            value = best[period]
            start = 1

            while start <= m:
                end = min(start + period - 1, m)
                diff[start] += value
                diff[end + 1] -= value
                start += 2 * period

        ans = []
        cur = 0

        for i in range(1, m + 1):
            cur += diff[i]
            ans.append(str(cur))

        out.append(f"Case #{case}: " + " ".join(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```配列`best`同じ周期を持つすべてのバルブを 1 つの値に圧縮します。 より大きい期間`m`最初のアクティブな間隔は、その期間自体が最大でもシミュレートされた秒数である場合にのみ重要となるため、無視されます。 もし`t > m`、電球は要求された範囲全体でアクティブであるため、実装はそれを無視してはなりません。 上記のコードは、割り当てによってこれを処理します。`best`だけに`m`, なのでハンドリングを調整する必要があります。 

正しく実装するには、次の期間を保存する必要があります。`100000`、だけではありません`m`。 修正されたバージョンは次のとおりです。```python

def solve():

    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())

        best = [0] * 100001

            period, brightness = map(int, input().split())
            if brightness > best[period]:
                best[period] = brightness

            if best[period] == 0:
                continue

            start = 1
            while start <= m:
                end = min(start + period - 1, m)
                diff[start] += best[period]
                diff[end + 1] -= best[period]
                start += 2 * period

        cur = 0

        for i in range(1, m + 1):
            cur += diff[i]

```2 番目のバージョンは、提出されたソリューションです。 重要な実装の詳細は、シミュレーションの長さよりも長い期間を含め、可能なすべての期間を維持することです。 このような電球は最初の期間はアクティブになります。`m`秒なら`m <= t`したがって、これを削除すると、有効な投稿が失われます。 

間隔更新では、`end + 1`差分配列には、間隔が将来のプレフィックス合計に影響を与えなくなる場所が格納されるためです。 この境界を忘れると、後の数秒に明るさが漏れます。

 ## 特殊なケース

 等しい期間では、アルゴリズムは最も明るい電球のみを保存します。 例では:```
1
3 3
2 5
2 8
2 3
```期間の保存値`2`になる`8`。 生成される間隔は次のとおりです。`[1,2]`、だから数秒`1`そして`2`明るさを受信する`8`、一方、2番目`3`何も受け取らない。 

要求された時間範囲よりも長い期間の場合:```
1
1 3
10 7
```電球は数秒間点灯したままになります`1`を通して`10`、つまり、要求されたすべての秒に明るさが含まれます`7`。 実装では、この期間を破棄せずに保持し、間隔を作成します。`[1,3]`クエリ範囲にクリップした後。 

正確に境界で電球が切り替わる場合:```
1
1 6
3 5
```サイクルの長さは`6`。 電球は数秒間点灯します`1,2,3`、中はオフ`4,5,6`、間隔更新によって正確にその範囲が作成されます。 答えは次のとおりです。```
Case #1: 5 5 5 0 0 0
```差分配列の半開いた更新境界により、明るさがサイクルのオフ部分に及ぶことが防止されます。
