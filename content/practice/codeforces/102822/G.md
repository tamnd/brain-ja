 ## 問題の理解

 このゲームでは、値が 0 ～ 3 のみのカードが使用されます。ポジションは、各値のカードが現在テーブル上に何枚あるかという 4 つのカウントによって表されます。 ターンでは、プレイヤーは値の合計が最大 3 になる 2 枚のカードを結合し、その合計値を含む 1 枚のカードと置き換えます。 正当なマージを持たないプレイヤーは負けとなるため、最初のプレイヤーである Little Rabbit が初期位置で勝っているかどうかを判断する必要があります。 

入力には最大で次のものを含めることができます$10^5$独立したゲームであり、すべてのカウントは次のように大きくなります。$10^9$。 これにより、1 つの状態次元でも大きすぎるため、シミュレーション、再帰、またはカウントを超える動的プログラミングが即座に排除されます。 ソリューションでは、テスト ケースごとにゲームを一定時間条件に短縮する必要があります。 

主な罠は、カードの数が勝者を決定するのに十分ではないという事実から生じます。 同じ枚数のカードを持つポジションは、その値に応じて異なる動作をする可能性があります。 

たとえば、入力```
1
0 1 0 0
```値 1 のカードが 1 枚だけ含まれています。出力は次のとおりです。```
Case #1: Horse
```カードのペアが存在しないため、最初のプレイヤーはすぐに負けます。 

もう 1 つの特殊なケースは、値 3 のカードが多数ある場合です。```
1
0 0 0 5
```出力は次のとおりです。```
Case #1: Horse
```なぜなら、2枚の3カードを統合することはできないからです。 多くのカードがあるかどうかだけをチェックするソリューションでは、動きが存在すると誤って想定されてしまいます。 

3 番目の重要なケースは、ゼロ カードの役割です。 例えば：```
1
2 0 0 0
```出力は次のとおりです。```
Case #1: Rabbit
```なぜなら、2 枚のゼロ カードが別のゼロ カードに結合して、最初のプレイヤーにちょうど 1 つの動きを与えることができるからです。 

## アプローチ

 自然な強引な解決策は、4 つのカウントのすべての構成をゲーム状態として扱い、現在のプレーヤーが勝利を強制できるかどうかを再帰的に計算することです。 法的なマージごとに小さな状態が作成されるため、この繰り返しは正しいです。 問題は状態空間のサイズです。 カウントは最大です$10^9$つまり、事実上数十億の可能な状態があり、入力自体に次のものが含まれる可能性があるため、メモ化は役に立ちません。$10^5$無関係な巨大国家。 

重要な観察点は、このゲームにはカード タイプが 4 つしかなく、すべての手が繰り返しパターンの小さなコレクションになるということです。 負けている州を特定することだけが必要です。 負けているポジションの特徴が特定されれば、膨大な数に必要なのはモジュール式の情報だけです。 

ゼロを含むマージではゼロのカードの数が変わるだけで、2 つの 1 は 2 になり、1 つの 1 と 1 つの 2 は 3 になるため、1 と 2 の間の相互作用はサイクルに従います。 ゲーム グラフを縮小した後、負けの状態は、いくつかの境界条件とともに、0 枚のカードのパリティと 3 を法とする 1 枚のカードの数によって表現できます。

 ## アルゴリズムのチュートリアル

 1. 通常のパターンが適用されない特別な負けポジションを処理します。 0か1のカードがない場合は、0のカードを1枚しか動かすことができないため、すぐに勝負が決まります。 他の終端形式は、1 枚のゼロ カード、または 0 または 2 枚のカードを含まない 1 枚の 1 カードです。 
2. ゼロ カードの数のパリティによってケースを分割します。 ゼロを含む有効なマージはそれぞれ 1 枚のゼロ カードを消費するため、ゼロ カードはスイッチのように機能します。 
3. 3 を法とする 1 のカードの数を考えます。1 枚のカードを結合するとカードのカウントが 2 ずつ変更され、1 と 2 を結合すると 1 のカウントが 1 ずつ変更されるため、反復動作には期間 3 があります。 
4. 結果の条件を使用して、州が負けているかどうかを判断します。 負けている場合は馬が勝ちます。 そうでなければウサギの勝ちです。 

なぜ効果があるのか:

 すべての動きにより、ゲームは同じ縮小分類システムで別のポジションに縮小されます。 次のプレイヤーが勝ち手を持っているかどうかに影響を与える唯一の情報は、ゼロ パリティ、1 カウント モジュロ 3、および小さな例外的なケースでの残りの 2 枚と 3 枚のカードの存在です。 すべての遷移はこれらの繰り返しパターンに従うため、この分類は到達可能なすべての状態をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rabbit_wins(c0, c1, c2, c3):
    if c0 == 0 and c1 == 0:
        return False
    if c0 == 1 and c1 == 0 and c2 == 0 and c3 == 0:
        return False
    if c0 == 0 and c1 == 1 and c2 == 0:
        return False

    lose = False

    if c0 % 2 == 0:
        if c1 % 3 == 0:
            lose = True
        elif c1 % 3 == 1 and c2 == 0:
            lose = True
    else:
        if c1 % 3 == 1 and c2 > 0:
            lose = True
        elif c1 % 3 == 2 and c2 <= 1:
            lose = True

    if lose:
        return False
    return True

def solve():
    t = int(input())
    ans = []
    for case in range(1, t + 1):
        c0, c1, c2, c3 = map(int, input().split())
        if rabbit_wins(c0, c1, c2, c3):
            ans.append(f"Case #{case}: Rabbit")
        else:
            ans.append(f"Case #{case}: Horse")
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```機能`rabbit_wins`は単なる分類子です。 カウントが非常に大きくなる可能性があるため、移動のシミュレーションは必要ありません。 

最初の 3 つの条件は、最終状態を直接削除します。 モジュラー式では一部の手がまだ利用可能であると想定されているため、これらのケースはモジュラー ルールの前にチェックする必要があります。 

残りのロジックはのみを使用します`% 2`そして`% 3`。 Python の整数はオーバーフローしないため、次の値まで$10^9$余計な注意を払わずに扱われます。

 ## 特殊なケース

 1 枚のカードが常にターミナルになります。 このアルゴリズムは、モジュラー ルールを適用する前に 1 つのゼロ カードと 1 つの 1 カードのケースを検出し、誤って分類されるのを防ぎます。 

3 だけを含むコレクションは、3 のペアを組み合わせることができないため、別の末期的な状況になります。 値 3 は有用なマージに参加しないため、残りのチェックによりこれらのポジションは自然に負けたままになります。 

大きなカウントは定期的な動作によって処理されます。 たとえば、10 億枚のゼロ カードを一度に 1 つずつ減らす必要はありません。 その数値のパリティのみが重要であり、それはまさに分類子によって使用される情報です。
