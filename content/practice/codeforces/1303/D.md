 ## 問題の理解

 目標のスペース量と、サイズが 2 の累乗である利用可能なブロックのコレクションが与えられます。 タスクは、これらのブロックを使用してターゲット サイズを正確に構成できるかどうかを判断し、そうでない場合は不可能であることを報告することです。 可能であれば、大きなブロックを小さなブロックに分割する回数を最小限に抑えたいと考えています。 

重要な操作は、任意のサイズのブロックを$2^k$2つのサイズのブロックに分割できます$2^{k-1}$。 この操作は可用性の点では無料ですが、1 つの部門としてカウントされます。 分割したら、結果として得られる小さなブロックを使用して、必要な合計サイズを満たすことができます。 

任意のサブセットを選択しようとしているわけではありません。 代わりに、2 の累乗ごとにブロック数を管理し、ターゲットの下位ビットの欠落を満たすために大きなブロックを分割する必要があるタイミングを決定することがすべてになります。 

制約$n \le 10^{18}$の値に対する大きなループを使用した単純なビットごとの構築ではターゲットをシミュレートできないことがすぐにわかります。$n$。 ビット数は最大 60 なので、どのソリューションでも動作するはずです。$O(\log n)$テストケースごとに。 テスト全体のボックスの合計数は次のとおりです。$10^5$したがって、ボックスごとの重いシミュレーションのようなものは、合計入力サイズが線形のままである場合にのみ受け入れられます。 

将来の分割を慎重に考慮せずに、より大きなブロックを貪欲に取得すると、微妙な失敗のケースが発生します。 たとえば、$2^k$の上位ビットをブロックする$n$後で下位ビットで分割が必要になる場合でも、必要な分割数を過小評価または過大評価する可能性があります。 もう 1 つのエッジ ケースは、総和が十分にあるにもかかわらず、正しいバイナリ アライメントではない場合 (多数の合計がある場合など) に発生します。$1$-ブロックですが、早い段階でより大きなブロックが必要になり、より高いべき乗を分割することで複数のマージが強制されます。 

本当の難しさは、分割が下方に伝播し、下位ビットを満たすために上位ビットから借用する必要がある場合があり、この借用が分割コストを生み出すことです。

 ## アルゴリズムのチュートリアル

 利用可能なボックスを 2 の累乗ごとの数として表します。 させて`cnt[i]`サイズは何ブロックか$2^i$私たちは現在持っています。 

次に、次のビットを処理します。$n$最も低いものから最も高いものまで、より大きなブロックを分割するときにブロックがどのように下に流れるかの実行中のシミュレーションを維持します。 

1. 周波数配列を構築する`cnt`、すべての入力ボックスを指数別にグループ化します。$i$そのような$a = 2^i$。 これにより、各レベルの初期供給量が得られます。 
2. ビット位置を 0 から 60 まで調べます。$n \le 10^{18}$。 それぞれのポジションで$i$かどうかを確認してください。$i$-番目のビット$n$が設定されています。 
3. ビットが設定されており、すでにブロックがある場合`cnt[i]`、1つ消費して継続します。 
4. ビットがセットされているが、`cnt[i]`がゼロの場合、最も近いものを検索します$j > i$そのような`cnt[j] > 0`。 存在しない場合、タスクは不可能です。 
5. そのようなものを見つけたら$j$、同じサイズのブロックを繰り返し分割します。$2^j$サイズまで$2^i$。 分割するたびに答えが 1 ずつ増え、間のすべてのレベルを満たす中間ブロックが生成されます。$i$そして$j$。 
6. 分割後、デクリメントします`cnt[j]`、それに応じてすべての中間レベルを増加させ、質量の保存を保証します。 
7. レベルごとに 1 ユニットを消費します$i$。 
8. 必要なビットを満たした後、未使用のブロックが上位ビットに使用可能なままであるため、カウントによって暗黙的に処理される余剰分を上向きに伝播します。 

微妙な不変条件は、処理後のレベルです。$i$、以下のレベルにある残りのすべてのブロック$i$はすでに正しく考慮されており、今後の操作でそれらを再検討する必要はありません。 

正確さは、すべての分割が厳密に制御された方法で質量を下方に移動させるという事実と、利用可能な最も近い上位のブロックを貪欲に選択することで分割の数を最小限に抑えるという事実に依存しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        cnt = [0] * 61

        for x in map(int, input().split()):
            cnt[x.bit_length() - 1] += 1

        ans = 0

        for i in range(61):
            if (n >> i) & 1:
                j = i
                while j < 61 and cnt[j] == 0:
                    j += 1

                if j == 61:
                    ans = -1
                    break

                while j > i:
                    cnt[j] -= 1
                    cnt[j - 1] += 2
                    ans += 1
                    j -= 1

                cnt[i] -= 1

            cnt[i + 1] += cnt[i] // 2
            cnt[i] %= 2

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、すべてのボックス サイズがビット長を使用して指数カウントに圧縮されます。$a_i$は 2 の累乗です。 メインループは、次のビット位置をスキャンします。$n$。 必要なビットが欠落している場合、最も近い利用可能なより大きなブロックを上方に検索し、繰り返し半分化を実行します。 それぞれの半分は 1 つの部門として数えられます。 

レベルで要件を処理した後$i$、サイズが 2 つのブロックであるため、残ったペアを上に運ぶことによってシステムを正規化します。$2^i$1つのサイズのブロックを形成できます$2^{i+1}$。 これにより、表現が最小限に保たれ、今後のステップでも一貫性が保たれます。 

実装の微妙な詳細は、常にデクリメントすることです。`cnt[i]`ビットが実際の消費を表すため、ビットを満足させた後。 もう 1 つの微妙な点は、各反復後のキャリー ステップです。これにより、断片化された小さなブロックが過剰にカウントされるのを防ぎます。

 ## 特殊なケース

 エッジ ケースの 1 つは、利用可能な最大のブロックが必要なビットをはるかに上回っている場合に発生します。$2^0$しかし、ただ持っているだけ$2^{50}$。 アルゴリズムは繰り返し下方向に分割し、各ステップをカウントし、50 回の操作を正しく蓄積します。 これにより、単一の部門として扱うという誤ったショートカットが回避されます。 

もう 1 つのエッジ ケースは、利用可能なブロックの合計は十分であるが、2 のべき乗で位置がずれている場合です。 たとえば、複数の$2^1$ブロックは、次の条件を直接満たすことはできません。$2^2$キャリーや借用を介してマージすることなく要件を満たします。 キャリー機構により、余剰の小さなブロックが適切に集約されます。 

最後のエッジケースは、総額が大きいにもかかわらず不可能です。 必要な時点で上位ブロックが存在しない場合、上位指数の検索は失敗し、アルゴリズムはリターンします。$-1$すぐに。 これにより、分解によって欠落している階層レベルを埋めることができないケースが正しく処理されます。
