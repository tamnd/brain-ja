 ## 解決策
 ## 問題の理解

 0 と 1 のシーケンスであるバイナリ文字列が与えられ、目標は、すべての 1 が 1 つの連続したブロックに表示されるようにそれを操作することです。 許可される唯一の操作は、いくつかの 0 を削除することです。 この条件が成立するために削除する必要がある 0 の最小数を計算する必要があります。 

入力は複数のテスト ケースで構成され、それぞれの長さは最大 100 の文字列です。これは、必要に応じて文字列長が 2 次であるアルゴリズムを使用できることを意味しますが、線形時間ソリューションの方が明らかにクリーンで単純です。 文字列には 0 と 1 のみを含めることができるため、他の文字を処理する必要はありません。 

「0」や「0000」など、文字列に 1 が含まれない場合、明らかではないエッジ ケースが発生します。 このような場合、1 の間に削除すべきギャップがないため、答えは 0 になります。同様に、すべての文字が 1 の場合、削除する必要はありません。 もう 1 つの微妙なケースは、「0011100」のように、先頭または末尾に 0 がある場合に発生します。この場合、中間の 0 を削除する必要がありますが、先頭と末尾の 0 は重要ではありません。 単純な解決策では、すべての 0 が誤ってカウントされたり、1 のサブセグメントを正しく識別できなかったりする可能性があります。 

## アプローチ

 ブルートフォース手法では、文字列の可能なすべての連続セグメントを反復処理し、そのセグメント内に 0 がいくつあるかを数えます。 1 で始まり 1 で終わる各セグメントについて、これらの 1 の間にある 0 の数を計算し、すべてのセグメントの最小値を取得します。 このアプローチは、0 を削除して 1 を連続させることを明示的にシミュレートするため機能しますが、O(n^2) セグメントをチェックする必要があり、文字列の最大長が 100 の場合、テスト ケースごとに約 10,000 回の操作が行われることになります。 実現可能ですが、不必要に複雑になります。 

最適な解決策につながる重要な観察は、重要な 0 は、厳密に最初の 1 と最後の 1 の間の 0 だけであるということです。最初の 1 の前または最後の 1 の後の 0 は、連続する 1 のブロックを乱すことができないため、削除する必要はありません。 最初と最後の 1 の位置がわかったら、その部分文字列を反復処理して 0 を数えることができます。 この数は、まさに消去する 0 の最小数です。 この観察により、問題はテスト ケースごとに 1 つのリニア スキャンに縮小されます。これは、制約を考慮すると、より単純で十分に高速です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 受け入れられるが不要 |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、バイナリ文字列を読み取ります。 
2. 最初に出現する「1」のインデックスを見つけます。 「1」がない場合は、削除する必要がないため、すぐに 0 を返します。 
3. 最後に出現した「1」のインデックスを見つけます。 
4. 最初の「1」から最後の「1」までの部分文字列を反復処理します。 この範囲内の「0」の数を数えます。 
5. このカウントを出力します。 これは、すべての 1 を連続させるために消去する 0 の最小数を表します。 

これが機能する理由: 不変条件は、最初から最後までの 1 の範囲外にある 0 は無関係であるということです。 この範囲内の 0 のみをカウントすると、それらを削除した後、1 が単一の連続したセグメントを形成することが保証されます。 分離された 1 をマージするには範囲内の 0 を削除する必要があるため、他の構成では削除数を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    if '1' not in s:
        print(0)
        continue
    first = s.index('1')
    last = s.rindex('1')
    count = s[first:last+1].count('0')
    print(count)
```この解決策は、最初に 1 が存在しない自明なケースを処理します。 次に、すべての 1 を含む部分文字列を特定し、内部の 0 をカウントします。 使用する`index`そして`rindex`境界が正しく識別されることを保証し、文字列を最初から最後までスライスすることで、関連する部分のみがスキャンされることが保証されます。 Off-by-one エラーは、以下を含めることによって回避されます。`last+1`これは、範囲の終わりを包含するための標準的な Python 規則です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    res = []
    for _ in range(t):
        s = input().strip()
        if '1' not in s:
            res.append('0')
            continue
        first = s.index('1')
        last = s.rindex('1')
        count = s[first:last+1].count('0')
        res.append(str(count))
    return '\n'.join(res)

# Provided samples
assert run("3\n010011\n0\n1111000\n") == "2\n0\n0", "sample 1"

# Custom test cases
assert run("1\n0000\n") == "0", "all zeros"
assert run("1\n1111\n") == "0", "all ones"
assert run("1\n1010101\n") == "3", "alternating ones and zeros"
assert run("1\n10001\n") == "3", "zeros between first and last ones"
assert run("1\n011110\n") == "0", "zeros outside first and last ones"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0000 | 0 | すべてゼロ、連続する 1 はありません |
 | 1111 | 0 | すべて 1、削除するゼロはありません |
 | 1010101 | 3 | 交互パターン、内部ゼロを削除する必要があります。 
| 10001 | 3 | 最初と最後の間のゼロは厳密に 1 |
 | 011110 | 0 | 先頭/末尾のゼロは無視されます。 

## 特殊なケース

 入力「0000」の場合、アルゴリズムは「1」を検出せず、すぐに 0 を返します。 「1111」の場合、最初と最後の 1 はインデックス 0 と 3 にあり、部分文字列は完全な文字列で、0 はなく、0 が返されます。「10001」の場合、最初と最後の 1 はインデックス 0 と 4 にあり、部分文字列は「10001」で、内部のゼロは 3 として数えられ、これは直感と一致します。 1 のない文字列、1 のみの文字列、および 1 のブロックの外側にゼロがある文字列を含むすべてのエッジ ケースが正しく処理されます。
