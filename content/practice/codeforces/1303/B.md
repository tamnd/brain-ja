 ## 解決策
 ## 問題の理解

 私たちは長い道路を建設しています$n$、最終的には道路の各単位を正確に 1 回アスファルト舗装する必要があります。 建設は日ごとに進み、毎日 1 つのユニットだけを作業することもあれば、何もしないこともあります。 

天気は周期的です。 のブロックから始まります$g$良い日々、続いて$b$悪い日が続き、このパターンが永遠に繰り返されます。 プロセスは常に良い日に始まります。 天気の良い日にアスファルトを敷けば、そのユニットは高品質になります。 悪い日に寝かせると品質が低くなってしまいます。 1 日スキップしても建設は進みませんが、カレンダーは進みます。 

目標は、単純な意味でのコストや時間を最小限に抑えることではなく、必要な総日数を最小限に抑えて、$n$ユニットは完成しますが、少なくとも半分は高品質でなければならないという追加の制約があります。 高品質ユニットの必要数は$\lceil n/2 \rceil$。 

制約$n, g, b \le 10^9$そして$T \le 10^4$数日にわたるシミュレーションは除外されます。 答え自体が次のオーダーになる可能性があるため、単一のテスト ケースを答えのスケールまでシミュレーションすることさえ不可能です$10^{18}$。 解決策は、時刻の接頭語内に好日が何日現れるかという直接的な数学的特徴付けに依存する必要があります。 

悪い日と比べて良い日が少ない場合、微妙な問題が発生します。 「常に良い日に働き、残りを悪い日で埋める」といった単純な欲張りな戦略は、スキップによって周期構造との整合性が変化するため、直感を誤解させる可能性があります。 もう 1 つの失敗例は、固定された周期的な位置を尊重せずに、どの日を適切に使用するかを独自に選択できると想定していることです。 

## アプローチ

 強引な解釈では、毎日をシミュレートし、毎日が良いか悪いかを追跡し、高品質のユニットと合計ユニットを何個製造したかを数えます。 到着したら止まります$n$単位を調べて、少なくとも半分が高品質であるかどうかを確認します。 これはプロセス定義に直接従うため、概念的には機能しますが、応答時間が非常に長くなる可能性があるまで反復する必要がある可能性があります。 最悪の場合、天気の良い日がほとんどなく、アライメントを頻繁にスキップしたり無駄にしたりすると、シミュレーションが大きくなる可能性があります。$O(\text{answer})$、それは限界をはるかに超えています。 

重要な観察は、早期にすでに十分な良い機会をすでに持っている場合、完了する合計ユニット数が少なくてもメリットがないということです。 代わりに、構造は最初の期間に何日良い日が発生するかによってのみ決まります。$d$カレンダーの日々。 パターンは完全に周期的であるため、シミュレーションなしで任意のプレフィックスの良好な日数を計算できます。 

の任意のプレフィックスに対して$d$日、私たちは完全な長さのサイクルを持っています$g+b$、各サイクルは正確に寄与します$g$良い日々を。 残りは貢献します$\min(g, d \bmod (g+b))$良い日々を。 したがって：$$\text{good}(d) = \left\lfloor \frac{d}{g+b} \right\rfloor g + \min(g, d \bmod (g+b))$$ここで、構築上の問題は次のようになります。最小のものを見つけます。$d$配置できるように$n$の合計ユニット数$d$少なくとも確保しながら、$\lceil n/2 \rceil$それらの掲載枠のうち、良い日には掲載されます。 いつでもいつでも働けるので、合計配置数は$d$日々は単純に$d$したがって、必要なのは$d \ge n$そして本当の制約は、最初の日が良い日かどうかです。$d$日は少なくとも$\lceil n/2 \rceil$。 そうでない場合は延長する必要があります$d$十分に良い日が来るまで。 

したがって、問題は次の二分探索に帰着します。$d$、単調な状態を確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(\text{answer})$|$O(1)$| 遅すぎる |
 | 二分探索 + 算術カウント |$O(T \log n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは単一のテストケースに焦点を当てます。 

1. 高品質ユニットの必要数を次のように計算します。$need = \lceil n/2 \rceil$。 これは、アスファルト舗装で「カバー」しなければならない天気の良い日の最小数です。 
2. 関数を定義する$good(d)$最初に何日良い日が表示されるかを返します$d$サイクル演算を使用した日数。 これによりシミュレーションが回避され、周期構造が直接使用されます。 
3. 指定されたかどうかを確認します$d$で十分です: 両方を満たさなければなりません$d \ge n$(すべてのユニットを設置するには少なくとも十分な日数が必要です)$good(d) \ge need$(質の高いプレースメントが十分に存在します)。 
4. 二分探索を使用する$d$通常、広い範囲で$[1, 10^{18}]$なぜなら、悪い日が支配的である場合、答えは非常に大きくなる可能性があるからです。 
5. 各中間点について、状態を評価します。 可能であれば、左に移動します。 それ以外の場合は右に移動します。 可能な最小の日数を探しています。 
6.最初の出力$d$それは両方の制約を満たします。 

二分探索が有効である理由は、$d$良い日の数と利用可能なスロットの合計を増やすことしかできないため、実現可能性は単調です。 

### なぜ効果があるのか

 重要な不変条件は、実現可能性はプレフィックスの長さのみに依存し、スケジューリングの選択には依存しないということです。 固定の場合$d$、私たちは常に正確に$d$アスファルトを敷設する機会、そして正確に$good(d)$そのうちのは質の高い機会です。 どの単位をどの日に割り当てるかを選択できるため、唯一の制限は、必要なカウントを満たすのに十分な良好な日が存在するかどうかです。 プレフィックスが実現可能になると、合計カウントと良好なカウントの両方が減少しないため、より大きなプレフィックスも引き続き実現可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def good_days(d, g, b):
    cycle = g + b
    full = d // cycle
    rem = d % cycle
    return full * g + min(g, rem)

def solve():
    T = int(input())
    for _ in range(T):
        n, g, b = map(int, input().split())
        need = (n + 1) // 2

        lo, hi = 1, 10**18
        ans = hi

        while lo <= hi:
            mid = (lo + hi) // 2
            if mid >= n and good_days(mid, g, b) >= need:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```機能`good_days`周期的なカウント式を直接実装します。 二分探索では、道路を完走するのに十分な合計日数と、品質要件を満たすのに十分な良好な日数という 2 つの制約が同時に適用されます。 

よくある落とし穴は、`mid >= n`状態。 これがないと、検索で、良好な日数は十分にあるものの、建設を完了するのに十分な総日数が足りないプレフィックスが返される可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(T \log n)$| 各テスト ケースは、最大で二分探索を実行します。$10^{18}$定数時間の良い日の計算を使用する |

    sys.stdin = io.StringIO(inp)
    from math import ceil

    def good_days(d, g, b):
        cycle = g + b
        full = d // cycle
        rem = d % cycle
        return full * g + min(g, rem)

    def solve():
        T = int(input())
        for _ in range(T):
            n, g, b = map(int, input().split())
            need = (n + 1) // 2

            lo, hi = 1, 10**18
            ans = hi

                mid = (lo + hi) // 2
                if mid >= n and good_days(mid, g, b) >= need:
                    ans = mid
                    hi = mid - 1
                else:
                    lo = mid + 1

            print(ans)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 いつ$g \ge n$、必要なすべての良好なユニットは、良好な日の最初のブロック内に配置できます。 アルゴリズムはこれを処理します。$good(n) = n$で二分探索を直ちに解決します。$d = n$。 

いつ$g \ll b$、良い日は非常にまばらで、ほとんどのサイクルが無駄になります。 二分探索が拡張される$d$十分なサイクルが蓄積され、シミュレーションを必要とせずに算術式が部分サイクルを正確にカウントするまで。 

いつ$n = 1$、要件は簡単で、シーケンスは良い日に始まるため、初日は常に機能します。$good(1) = 1$。
