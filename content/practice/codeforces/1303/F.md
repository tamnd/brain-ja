 ## 解決策
 ## 問題の理解

 私たちは、すべてのセルに同じ値 0 が含まれるという意味で、完全に空の状態から始まるグリッドに取り組んでいます。 時間の経過とともに、一連の更新を実行します。 各更新では単一のセルが選択され、割り当てられた値のシーケンスが減少しないため、クエリ間で時間の経過とともに減少しない値が割り当てられます。 

更新のたびに、セルが辺を共有し、同じ値を共有するときにセルを隣接しているものとして扱う場合、グリッド内に接続された領域がいくつ存在するかを報告する必要があります。 

重要な点は、接続性は値に依存するということです。 2 つの隣接するセルは、値が一致する場合にのみ同じコンポーネントに寄与します。 グリッドは個々のセルの値を徐々に増加させることによって進化するため、グローバル構造の観点からは、同じ値の領域が現れ、結合し、場合によっては分割されます。 

単純なアプローチでは、すべてのグリッド セルに対してフラッド フィルまたは DSU を使用して、更新のたびに接続されたコンポーネントを最初から再計算します。 グリッド サイズが最大 300 x 300 であるのに対し、クエリの数は 200 万にも達する可能性があるため、これはすぐに失敗します。クエリごとに 1 回の完全な走査でさえ、すでに許容制限を超えています。 

2 番目の単純なアイデアは、古い値が置き換えられるため、削除をサポートする動的 DSU を維持することです。 ただし、標準の DSU はエッジの削除をサポートしていないため、値が任意に変更されるとロールバックの複雑さが問題になります。 

主な問題点は、更新はローカルであるが接続はグローバルであり、単純な再計算では変更されていない構造が繰り返し再検討されることです。 

多くの更新が同じセルに繰り返し触れる場合、微妙なエッジ ケースが発生します。 たとえば、単一のセルに増加する値を繰り返し割り当てた場合、コンポーネントの数は局所的にのみ変化しますが、単純な再計算では毎回グリッド全体をスキャンすることになります。 

もう 1 つの特殊なケースは、値の更新によって以前に切断されていた 2 つの領域をブリッジするときに発生します。 たとえば、中央のセルをその隣接セルと等しい値に設定すると、複数のコンポーネントが一度にマージされるため、単純なアプローチではマージの二重カウントを慎重に避ける必要があります。 

## アプローチ

 ブルート フォース ソリューションは、グリッド全体で BFS または DFS を使用して更新のたびに接続コンポーネントを再計算します。 各走査は、すべての等しい値の近傍をたどることによってコンポーネントを割り当てます。 これは接続の定義に直接一致するため正しいですが、そのコストはクエリごとのグリッド サイズに比例します。 最大 200 万のクエリと最大 90,000 のセルを使用すると、これでは非常に遅くなります。 

重要な観察は、実際には任意の値に対する一般的な動的接続をサポートする必要がないということです。 値は時間の経過とともにグローバルに増加するだけであり、各セルは単調に繰り返し更新されます。 つまり、セルに新しい値を割り当てるたびに、同じ値を持つ既存のセルにどのように接続するかを考慮するだけで済みます。 

コンポーネントを再計算する代わりに、値を昇順に処理し、値が適切になったときにセルをアクティブにします。 セルが特定の値でアクティブになると、その 4 つの隣接セルがすでに同じ値を持つか、その値ですでにアクティブである場合、セルは 4 つの隣接セルにのみ接続します。 値はクエリを通じて減少しないため、DSU の状態を段階的に維持できます。 

有益な視点は、考え方を逆転させることです。「古い価値を削除して新しい価値を追加する」のではなく、価値が増加したときにのみ「構造を追加する」のです。 セルに値が表示されるたびに、それをそのしきい値でのそのセルのアクティブ化として扱い、互換性のある隣接セルと結合します。 これにより、削除が完全に回避されます。

重要なトリックは、値によってグループ化されたセルを処理し、アクティブな同じ値のセルの現在の状態を維持することです。 値には制限がある (最大約 2000) ため、値レベルごとに効率的に処理できます。 各セルは値の変更ごとに 1 回挿入され、DSU により共用演算はほぼ一定に償却されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとの DFS) | O(q・n・m) | O(n・m) | 遅すぎる |
 | 値のアクティベーションによる増分 DSU | O((n・m + q) α(n・m)) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セルを DSU 内のノードとして扱います。 グリッドは、特定のステージの最終値を受け取ったときにセルをアクティブにすることによって段階的に構築されます。 

1. すべてのクエリを読み取り、各ステップで最終的に割り当てられた値のみを各セルに保存します。 値は減少しないため、各セルの値のタイムラインは単調であり、アクティブ化のセグメントに圧縮できます。 
2. 更新を値レベルごとに並べ替えまたはグループ化します。 各値について、ある時点で正確にその値になるすべてのセルを収集します。 値を昇順に処理し、下位の状態に再びアクセスしないようにします。 
3. セルが現在または以前の値レベルでアクティブであるかどうかを追跡するブール グリッドを維持します。 新しい値を処理するときは、割り当てられた値がこのレベルに等しいすべてのセルをアクティブにします。 
4. 新しくアクティブ化された各セルについて、その 4 つの隣接セルをチェックします。 隣接セルがすでにアクティブで同じ値を持つ場合、DSU 内の 2 つのセルを結合します。 結合が成功するたびに、コンポーネント数が 1 つずつ減ります。 
5. ゼロに初期化されたグローバル コンポーネント カウンタを維持します。 新しいセルがアクティブになると、新しいコンポーネントとして開始され、一致する隣接セルとマージされ、それに応じてカウンターが調整されます。 
6. 特定のクエリ値に対するすべてのアクティベーションを処理した後、そのクエリに対する回答として現在のコンポーネント数を記録します。 

これができる理由は、後のエンドポイントがアクティブになるときに、等しい値の隣接セル間のすべてのエッジが 1 回だけ考慮されるためです。 エッジを再確認したり削除したりする必要はありません。 

### なぜ効果があるのか

 固定値のしきい値に対応する任意の時点で、アクティブ セルは、隣接する同じ値のセル間にのみエッジが存在するグラフを形成します。 DSU の不変条件は、このグラフ内の各接続コンポーネントが 1 つの DSU セットに正確に対応するということです。 すべての隣接関係は、両方のエンドポイントがその値でアクティブになった瞬間に 1 回だけ処理されるため、接続が失われることはなく、重複したマージは発生しません。 これにより、各更新後のコンポーネント数が常に正確になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())
N = n * m

grid = [0] * N
dsu = list(range(N))
size = [1] * N
active = [False] * N

def find(x):
    while dsu[x] != x:
        dsu[x] = dsu[dsu[x]]
        x = dsu[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb:
        return False
    if size[ra] < size[rb]:
        ra, rb = rb, ra
    dsu[rb] = ra
    size[ra] += size[rb]
    return True

cells_by_value = {}

queries = []
for _ in range(q):
    x, y, c = map(int, input().split())
    x -= 1
    y -= 1
    idx = x * m + y
    queries.append((idx, c))
    if idx not in cells_by_value:
        cells_by_value[idx] = []
    cells_by_value[idx].append(c)

# We simulate activation when value increases
answers = [0] * q
cur_ans = 0

# We need to process per query; maintain current grid values
# but activate only when a cell appears for first time at a value
# Since values are non-decreasing, each assignment can be treated incrementally.

grid = [-1] * N

for i, (idx, c) in enumerate(queries):
    if grid[idx] != c:
        grid[idx] = c
        if not active[idx]:
            active[idx] = True
            cur_ans += 1

            x, y = divmod(idx, m)
            for dx, dy in ((1,0), (-1,0), (0,1), (0,-1)):
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < m:
                    nidx = nx * m + ny
                    if active[nidx] and grid[nidx] == c:
                        if union(idx, nidx):
                            cur_ans -= 1

    answers[i] = cur_ans

print("\n".join(map(str, answers)))
```この実装では、グリッド上に DSU を保持し、最初に値を受け取ったときにセルをアクティブにします。 セルがアクティブになると、最初は新しいコンポーネントとしてカウントされます。 次に、その 4 つの隣接コンポーネントをチェックし、コンポーネントがすでにアクティブで同じ値を共有している場合にのみコンポーネントをマージします。 マージが成功するたびに、コンポーネント数が減少します。 

微妙な点は、細胞を決して不活性化しないことです。 将来のクエリでセルの値が変更される可能性があっても、アクティブ化ロジックにより、セルが DSU に参加すると接続が維持され、将来の同じ値の相互作用が更新時の近隣チェックを通じて自然に処理されることが保証されます。 

## 実用的な例

 ### 例 1

 更新によって徐々に等しい値が割り当てられ、接続されたブロックを形成する小さなグリッドを考えてみましょう。 

| ステップ | セルが更新されました | 値 | 新規アクティベーション | マージ | コンポーネント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1) | 1 | はい | なし | 1 |
 | 2 | (1,2) | 1 | はい | (1,1) | とマージします。 1 |
 | 3 | (2,2) | 1 | はい | なし | 2 |
 | 4 | (2,1) | 2 | はい | なし | 3 |

 トレースは、接続が一致する値に厳密に依存する様子を示しています。 DSU は、アクティブ化時に同じ値の隣接ノードのみをマージするため、構造は再計算せずに段階的に進化します。 

### 例 2

 ここで、単一セル上で繰り返し上書きを考えてみましょう。 

| ステップ | セルが更新されました | 値 | 新規アクティベーション | マージ | コンポーネント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (1,1) | 1 | はい | なし | 1 |
 | 2 | (1,1) | 2 | いいえ | なし | 1 |
 | 3 | (1,2) | 2 | はい | (1,1) | とマージします。 1 |
 | 4 | (2,1) | 2 | はい | なし | 2 |

 これは、セルを再割り当てしても複数の DSU ノードが作成されないことを示しています。 接続の増加には最初のアクティベーションのみが重要であり、その後の更新は近隣の比較にのみ影響します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n・m + q) α(n・m)) | 各セルは 1 回アクティブ化され、各エッジは最大 1 回結合されます。 
| スペース | O(n・m) | DSU アレイとグリッドの状態 |

 グリッド サイズは最大 90,000 セルであり、DSU の動作はほぼ一定であるため、200 万回の更新でも実行可能です。

 ## 特殊なケース

 重要なエッジ ケースは、同じセルに対して値を増加させて更新を繰り返すことです。 このアルゴリズムは、最初のアクティブ化を唯一の構造イベントとして扱い、コンポーネントを二重にカウントしたり、古い状態を誤ってマージしたりしないようにします。 結合は隣接するコンポーネントが現在の値と一致する場合にのみ実行されるため、後の更新によって古いコンポーネントが誤って再接続されることはありません。 

もう 1 つのケースは、セルが以前は別々だった 2 つのコンポーネントを一度に接続する場合です。 セルをアクティブにするときは、4 つの隣接セルすべてを個別に反復処理します。 DSU の冪等構造により、ユニオンが成功するたびにコンポーネント数が 1 回だけ削減されるため、1 ステップでの複数のマージが過剰にカウントされることなくきれいに処理されます。 

最後のケースは、一意の値を持つ孤立したセルなど、更新によって接続にまったく変化が生じない場合です。 これらのセルはアクティブ化されますが、マージされることはありません。そのため、それぞれが 1 つのコンポーネントに寄与し、定義に直接一致します。
