 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、すべての要素について、ビットごとの AND が 0 である別の配列要素を見つけなければなりません。 2 つの数値は、次のように設定されたビットを共有しない場合、正確に互換性があります。`1`。 

たとえば、次を見てみると、`90`そして`36`:```
90  = 1011010
36  = 0100100
AND = 0000000
```ビット位置には次のものが含まれていません`1`両方の番号にあるため、互換性があります。 

タスクは、互換性のあるペアを数えることではありません。 すべての配列値について`a[i]`、配列要素を出力するだけで済みます。`x`次のような:```
a[i] & x = 0
```そのような要素が存在しない場合は、次のように出力します。`-1`。 

制約は解決策の方向性を完全に決定します。 配列には最大で次のものを含めることができます`10^6`数値、および各値は最大で`4 * 10^6`。 以来`4 * 10^6 < 2^22`、すべての数値は 22 ビット内に収まります。 

二次解では、すべてのペアをチェックする必要があります。```
10^6 * 10^6 = 10^12
```操作、それは不可能です。 

22 ビットの境界が本当の手がかりです。 ビット数が少ないときはいつでも、ビットマスク動的プログラミングが可能になります。 サイズの状態空間`2^22`これは約 420 万であり、これは大きいですが、定数係数が低い実装では時間とメモリの両方で管理可能です。 

不注意な解決策を打ち破るエッジケースがいくつかあります。 

入力が次のようになっているとします。```
1
7
```唯一の数字は、`7`。 以来`7 & 7 != 0`、答えは`-1`。 バグのある実装では、互換性をチェックせずに誤って番号自体が一致してしまう可能性があります。 

もう 1 つの注意が必要なケースは、値が重複している場合です。```
3
0 5 5
```番号`0`次の理由により、すべてのものと互換性があります。```
0 & x = 0
```みんなのために`x`。 正しい出力は次のようになります。```
5 0 0
```厳密なサブマスクのみを検索するソリューションでは、見逃してしまう可能性があります`0`。 

多くのビットが設定されている場合、さらに微妙な問題が発生します。```
2
4194303 1
```

`4194303 = 2^22 - 1`にはすべてのビットが設定されているため、正の数値と互換性がありません。 正しい答えは次のとおりです。```
-1 -1
```補数マスクの計算が間違っていると、簡単に有効な 22 ビット範囲をオーバーフローし、無効な状態が生成される可能性があります。 

## アプローチ

 最も直接的な解決策は、数値のすべてのペアをチェックします。 

それぞれについて`a[i]`、配列全体を反復処理してテストします。```
a[i] & a[j] == 0
```ビット単位の AND 演算自体は定数時間であるため、全体の複雑さは次のようになります。`O(n^2)`。 

互換性は完全にペアごとの比較によって定義されるため、この強引な方法は正しいです。 互換性のある番号が存在する場合は、徹底的な検索によって最終的に見つかります。 

問題は規模だ。 と`n = 10^6`、このアプローチには約`10^12`これは制限を何千回も超えています。 

重要な点は、互換性は配列内の位置ではなくビット パターンのみに依存するということです。 

固定番号の場合`x`、いくつかの数字が必要です`y`次のような:```
x & y = 0
```つまり、すべてのビットが設定されています`y`のゼロビット位置の内側になければなりません`x`。 

次のように定義すると、```
FULL = (1 << 22) - 1
```次に、許可されるビット`y`正確には:```
FULL ^ x
```したがって、配列全体を検索する代わりに、次のように尋ねることができます。 

「配列には次のサブマスクが含まれていますか?`FULL ^ x`？」

 これにより、問題は、サブセット全体の合計 DP とも呼ばれる、古典的な SOS DP に変換されます。 

配列を作成します`dp[mask]`どこ：```
dp[mask] = some array value that is a submask of mask
```最初は数字の場合、`v`配列に出現する場合は、次のように設定します。```
dp[v] = v
```次に、マスクを通じて情報を上方に伝播します。 すべてのマスクとすべての設定ビットについて、より小さいサブマスクから答えを継承します。 

前処理が完了すると、クエリが簡単になります。```
answer(x) = dp[FULL ^ x]
```なぜなら、補数マスクのどのサブマスクも設定ビットを共有しないからです。`x`。 

前処理には次のような費用がかかります。```
22 * 2^22
```オペレーション、約 9,200 万回のトランジション。 最適化された Python では、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適な SOS DP | O(22 · 2²² + n) | O(2²²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力数値が 22 より小さいため、最大ビット幅を 22 として定義します。`2^22`。 
2. 配列を作成する`dp`サイズの`2^22`すべてのエントリを次のように初期化します`-1`。 
3. あらゆる値について`x`入力配列に次のように設定します。```
dp[x] = x
```これは正確なマスクを意味します`x`配列内に存在します。 
4. すべてのマスクに対して SOS DP を実行します。 

すべてのマスクとすべてのビット位置について:

 現在のマスクにビットが設定されている場合は、それを削除してみてください。```
smaller = mask ^ (1 << bit)
```もし`dp[mask]`まだです`-1`、継承:```
dp[mask] = dp[smaller]
```これが機能する理由は、設定されたビットを繰り返し削除することですべてのサブマスクに到達できるためです。 
5. 各配列値について`x`、次を計算します。```
complement = FULL ^ x
```互換性のあるすべての数値は、この補数マスクのサブマスクでなければなりません。 
6. 出力:```
dp[complement]
```有効なサブマスクが配列内に存在しない場合、値はそのまま残ります。`-1`。 

### なぜ効果があるのか

 DP の不変式は次のとおりです。```
dp[mask] stores some array value that is a submask of mask,
or -1 if none exists.
```既存の数値を明示的に保存するため、最初はこれが正確なマスクに当てはまります。 

遷移中は、ビットを削除して得られた小さなマスクから値のみをコピーします。 の任意のサブマスク`smaller`のサブマスクでもあります`mask`、したがって、不変条件は有効なままです。 

クエリ値の場合`x`、マスク`FULL ^ x`正確にビット位置が含まれます。`x`ゼロがあります。 任意のサブマスク`y`この補数は次の条件を満たします。```
x & y = 0
```なぜなら`y`すでに設定されているビットは決して使用しません`x`。 

それで、もし`dp[FULL ^ x] = y`、 それから`y`との互換性が保証されています`x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BITS = 22
SIZE = 1 << BITS
FULL = SIZE - 1

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dp = [-1] * SIZE

    for x in a:
        dp[x] = x

    for bit in range(BITS):
        for mask in range(SIZE):
            if mask & (1 << bit):
                if dp[mask] == -1:
                    dp[mask] = dp[mask ^ (1 << bit)]

    ans = []

    for x in a:
        ans.append(str(dp[FULL ^ x]))

    print(" ".join(ans))

solve()
```この解決策は、すべての 22 ビット マスクに DP 配列を割り当てることから始まります。 これは約 420 万エントリと大きくなりますが、整数を格納する場合は Python のメモリ制限内に十分収まります。 

初期化ステップでは、すべての配列値を独自のマスク位置に直接保存します。 現時点では、正確なマスクのみがわかっています。 

SOS DP フェーズでは、小さなサブマスクから大きなマスクに向かって情報が伝播されます。 順序が重要です。 ビットごとに、そのビットを含むすべてのマスクを処理し、そのビットが削除されたバージョンからの継承を試みます。 

よくある間違いは、トランジションの方向を逆にしてしまうことです。 私たちが望んでいるのは:```
mask -> mask without one bit
```サブマスクに関する情報を収集しているためです。 

補数の計算もバグが発生する場所です。 補数を 22 ビットに制限する必要があります。```
FULL ^ x
```使用する`~x`整数には制限がないため、Python では負の数が作成されます。 

最終的なルックアップは定数時間です。 前処理の後、すべてのクエリは単一の配列アクセスに減少します。

import sys
import io

BITS = 22
SIZE = 1 << BITS
FULL = SIZE - 1

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    dp = [-1] * SIZE

    for x in a:
        dp[x] = x

    for bit in range(BITS):
        for mask in range(SIZE):
            if mask & (1 << bit):
                if dp[mask] == -1:
                    dp[mask] = dp[mask ^ (1 << bit)]

    ans = []

    for x in a:
        ans.append(str(dp[FULL ^ x]))

    print(" ".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# minimum size, no compatible value

# zero-compatible structure

assert res[0] in {"2", "4"}
assert res[1] in {"1", "4"}
assert res[2] in {"1", "2"}

# all equal values
assert run("4\n5 5 5 5\n") == "-1 -1 -1 -1", "all equal"

# full-mask boundary
assert run("2\n4194303 1\n") == "-1 -1", "22-bit boundary"

# mixed compatibility
res = run("4\n1 2 3 7\n").split()
assert res[0] == "2"
assert res[1] == "1"
assert res[2] == "-1"
assert res[3] == "-1"

 ## 特殊なケース

 次の入力を考えてみましょう。```
1
7
```利用可能な唯一の番号は、`7`自体。 以来：```
7 & 7 = 7
```それ自体と互換性がありません。 

補数マスクには、次の位置にゼロ ビットのみが含まれます。`7`には 1 があり、配列の既存のサブマスクがそれを満たすものはありません。 DP ルックアップが返されます。`-1`。 

ここで重複について考えてみましょう。```
4
5 5 5 5
```バイナリ：```
5 = 101
```任意のペア`5`s はまだビットを共有しています。```
101 & 101 = 101
```前処理中のみ`dp[5]`人口が多くなります。 補数マスクはサブマスク遷移を通じて到達できないため、すべての答えが残ります。`-1`。 

最後に、最大マスクの場合を調べます。```
2
4194303 1
```

`4194303`等しい:```
1111111111111111111111
```22 ビットすべてが設定されています。 

22 ビット内の補数はゼロです。```
FULL ^ 4194303 = 0
```マスク時のDP値`0`は`-1`、配列にはゼロが存在しないためです。 アルゴリズムは正しく出力します`-1`。 

番号については`1`、その補数には最下位ビットを除くすべてのビットが含まれますが、`4194303`は、禁止された最下位ビットがまだ含まれているため、その補数のサブマスクではありません。 したがって、次の答えは`1`もです`-1`。
