 ## 解決策
 ## 問題の理解

 正確に _k_ 個の部分文字列を含むバイナリ文字列の部分文字列を数えるように求められます。 部分文字列は文字列内の連続した文字のシーケンスであり、異なる位置にある異なる文字は個別にカウントされます。 たとえば、文字列「1010」では、部分文字列「10」が 2 回出現し、それぞれが個別にカウントされます。 入力は整数 _k_ とバイナリ文字列 _s_ を与え、正確に _k_ 個の部分文字列の数を表す単一の整数を出力する必要があります。 

文字列の長さは最大 1,000,000 文字に達する可能性があるため、すべての部分文字列を明示的に検査する単純なアプローチは排除されます。 すべての O(n²) 個の部分文字列を総当たりチェックし、毎回 1 つずつ数えると、最悪の場合、最大 10¹² の操作が発生し、2 秒の制限時間を大幅に超えます。 これにより、線形または線形演算時間、理想的には O(n) で機能する解決策がすぐに得られます。 

単純な実装をトリップする可能性のあるエッジ ケースには、_k = 0_、またはすべて 0 またはすべて 1 の文字列が含まれます。 たとえば、_s = "000"_ および _k = 0_ の場合、正しい出力は 6 で、部分文字列 "0"、"0"、"0"、"00"、"00"、"000" に対応します。 1 だけをカウントする不注意な解決策では、誤って 0 が返されます。もう 1 つの微妙なケースは、_k_ が _s_ 内の 1 の合計数を超える場合であり、この場合は 0 が返されるはずです。 

## アプローチ

 ブルート フォースのアプローチは簡単です。開始インデックスと終了インデックスを選択して、考えられるすべての部分文字列を列挙し、各部分文字列内の 1 の数を数えます。 これは、各部分文字列について、それに含まれる部分文字列の数を正確に判断できるため機能しますが、長さ _n_ の文字列内の部分文字列の総数は n(n+1)/2 であり、各部分文字列内の 1 をカウントすると、最悪の場合、n の係数がさらに追加されるため、法外に遅くなります。 _n = 10⁶_ の場合、単純に実装すると O(n³) 回の操作が必要になりますが、これはまったく実行不可能です。 

最適な解決策に対する重要な洞察は、問題が文字列内の 1 の範囲をカウントすることに帰着することを観察することで得られます。 すべての 1 の位置を記録すると、正確に _k_ 個の 1 を持つ部分文字列は (i-1) 番目の文字列の直後から始まり、(i+k) 番目の文字列かその前で終わります。 これらの位置を事前に計算することで、すべての部分文字列を調べることなく、有効な開始インデックスと終了インデックスの数を直接計算できます。 特殊なケース _k = 0_ の場合、代わりに、連続するゼロのブロックをカウントし、組み合わせ合計を使用して各ブロック内に存在する部分文字列の数を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 (接頭語 + 1 の位置) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 _k_ とバイナリ文字列 _s_ を読み取ります。 1 の位置を格納するリストを初期化し、先頭に -1 を追加し、最後に n をセンチネルとして追加します。 これにより、境界の計算が簡素化されます。 
2. 文字列を 1 回トラバースします。 文字が「1」の場合は常に、そのインデックスを 1 の位置リストに追加します。 
3. _k = 0_ の場合、連続する 1 の位置を反復して、その間の 0 のブロックを見つけます。 長さ _l_ のブロックの場合、部分文字列の数は l(l+1)/2 です。 すべてのゼロ ブロックに対するこれらの寄与を合計し、合計を返します。 
4. _k > 0_ の場合、インデックス 1 から len(ones) - k - 1 まで 1 の位置を繰り返します。 _k_ の 1 の各ウィンドウについて、left_gap をウィンドウ内の最初のゼロの前のゼロの数、right_gap をウィンドウ内の最後のゼロの後のゼロの数とします。 まさにこの k 個のグループを含む部分文字列の数は、(left_gap + 1) * (right_gap + 1) です。 これを現在の合計に追加します。 
5. 総カウントを出力します。

なぜ機能するのか: すべての 1 の位置を記録することで、問題を組み合わせの問題に変換します。 正確に k 個の値を含む各部分文字列は、k 個の連続する値のウィンドウに一意に対応します。 そのウィンドウで可能な部分文字列の数は、ギャップによって捕捉される、ゼロを使用して左右に拡張する方法の数とまったく同じです。 このアプローチでは、すべての有効な部分文字列が正確に 1 回カウントされ、無効な部分文字列がカウントされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k = int(input())
s = input().strip()
n = len(s)

ones = [-1]  # sentinel before start
for i, c in enumerate(s):
    if c == '1':
        ones.append(i)
ones.append(n)  # sentinel after end

if k == 0:
    total = 0
    for i in range(1, len(ones)):
        zeros = ones[i] - ones[i-1] - 1
        total += zeros * (zeros + 1) // 2
    print(total)
else:
    total = 0
    for i in range(1, len(ones) - k):
        left_gap = ones[i] - ones[i-1]
        right_gap = ones[i+k] - ones[i+k-1]
        total += left_gap * right_gap
    print(total)
```最初のループは「1」のすべての位置を収集し、センチネル値を追加します。 開始前のセンチネルは、ウィンドウが最初のギャップから開始されるときに左ギャップが正しく計算されることを保証します。 終了後のセンチネルは、ウィンドウが最後のウィンドウで終了するときに、正しいギャップが正しく計算されることを保証します。 条件分岐は、ゼロの部分文字列の組み合わせカウントを使用して、ゼロの場合を処理します。 

## 実用的な例

 **例 1:** 入力: k=1、s="1010"

 | リスト | -1,0,2,4 |

 | 窓 | 左ギャップ | 右ギャップ | 貢献 |
 | --- | --- | --- | --- |
 | 0番目の「1」 | 0-(-1)=1 | 2-0=2 | 1*2=2 |
 | 最初の「1」 | 2-0=2 | 4-2=2 | 2*2=4 |
 | 合計 | | | 6 |

 これにより、「1」を 1 つだけ含むすべての部分文字列がカウントされることが確認されます。 

**例 2:** 入力: k=2、s="10101"

 | リスト | -1,0,2,4,5 |

 | 窓 | 左ギャップ | 右ギャップ | 貢献 |

 | 0-1 | 0-(-1)=1 | 4-2=2 | 2 |

 | 1-2 | 2-0=2 | 5-4=1 | 2 |

 | 合計 | | | 4 |

 これは、1 の重なり合うウィンドウが正しく処理されることを示しています。

 ## 特殊なケース

 k=0 および s="000" の場合、1 のリストは [-1,3] です。 ゼロ ブロックの長さは 3-(-1)-1 = 3 で、3*4/2 = 6 個の部分文字列が得られ、正確に正しいです。 k が合計より大きい場合、たとえば k=5 および s="1010" では、ウィンドウ上のループは実行されず、合計は 0 のままですが、これは正しいことです。 境界に 1 を持つ文字列の場合、センチネルは左右のギャップが正しく計算されることを保証します。 各エッジ ケースでは、アルゴリズムが境界、ゼロ部分文字列、および重複するウィンドウを一貫して処理していることが確認されます。
