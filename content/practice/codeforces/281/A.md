 ## 解決策
 ## 問題の理解

 このタスクは、英語の文字で構成される 1 つの単語を取得し、その最初の文字が大文字であることを確認することです。 残りの文字は、入力されたものとまったく同じままにする必要があります。 たとえば、入力が「apple」の場合、出力は「Apple」になるはずです。 入力がすでに大文字で始まっている場合 (「Apple」など)、出力は変更されません。 「ApPLe」のように、入力には小文字と大文字が混在する場合があります。この場合、変更の対象となるのは最初の文字のみです。 

制約は単純です。単語は空ではなく、103 文字以内です。 これは非常に小さい入力サイズであるため、文字を順番に検査するアルゴリズムや定数時間の文字列操作を実行するアルゴリズムは、2 秒の制限内で適切に実行されます。 大規模な最適化は必要ありません。 単純なアプローチでもマイクロ秒で完了します。 

エッジケースは、最初の文字がすでに大文字である場合、単語が 1 文字である場合、または最初の文字が小文字で残りが大文字と小文字が混在している場合に発生します。 たとえば、「a」を入力すると「A」が生成されます。 「Zebra」と入力した場合は、「Zebra」のままにする必要があります。 不注意な実装により単語全体が大文字に変換されると、「aPpLe」が「APpLe」ではなく「APPLE」に誤って変換されてしまいます。 

## アプローチ

 問題を解決する最も簡単な方法は、文字列の最初の文字を手動で検査することです。 小文字の場合は大文字に変換し、変更しないで残りの文字列と連結します。 これが機能するのは、文字列のインデックス付けと連結が非常に短い長さに対して定数時間の操作であるためです。 この総当たりアプローチは、入力サイズに対して正確かつ高速であり、操作の数はわずかです。 

少し異なる視点は、Python のような組み込みの文字列関数を使用することです。`str.capitalize()`。 しかし、`str.capitalize()`最初の文字を大文字に変換しますが、他のすべての文字も強制的に小文字に変換します。これはここでは受け入れられません。 これは、ドキュメントを注意深く読むことがなぜ重要であるかを示しています。「大文字化」を行うように見える標準ライブラリ関数には、正確性を損なう副作用がある可能性があります。 

したがって、最適なアプローチは非常にシンプルです。最初の文字のみを大文字に変換し、残りは変更しないでください。 これは、問題の小さな固定構造を利用しています。一度に 1 文字だけを考慮し、文字列の残りの部分は検査や変更を必要としません。 スライス以外に、文字列全体を反復する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (最初の文字を手動でチェックして変更) | お(1) | お(1) | 承認済み |
 | 使用する`str.capitalize()`| O(n) | O(n) | 大文字と小文字が混合した入力の場合は正しくありません。 
| 最適 (最初の文字を大文字にし、残りを連結) | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力単語を読み、末尾の改行または空白を削除します。 これにより、実際の文字のみを扱うことが保証されます。 
2. 単語の最初の文字を抽出します。 この文字は、変更が必要な可能性がある唯一の文字です。 
3. 最初の文字を大文字に変換します。 Python では、これは次のように実行できます。`upper()`方法。 
4. 最初の大文字と、インデックス 1 から始まる単語内の残りのすべての文字で構成される部分文字列を連結します。これにより、単語の残りの部分の元の大文字と小文字が保持されます。 
5. 結果の文字列を出力します。 

これが機能するのは、不変条件が単純であるためです。つまり、最初の文字は大文字であることが保証され、文字列の残りの部分は入力どおりのままになります。 文字列のスライスでは順序と内容が保持されるため、情報が失われることはなく、アルゴリズムは常に正しく大文字の単語を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

word = input().strip()
capitalized = word[0].upper() + word[1:]
print(capitalized)
```コードはまず、次を使用して末尾の改行を削除します。`strip()`文字だけが残るようにするためです。 それからアクセスします`word[0]`最初の文字を分離して適用する`upper()`。 との連結`word[1:]`残りの文字はすべてそのままの状態で保存されます。 最後に、結果が出力されます。 この実装では、スライスが行われるため、単一文字の単語が正しく処理されます。`word[1:]`1 文字の文字列では空の文字列が生成されるため、連結はエラーなしで機能します。

 入力:「AppLe」

 | 2 | 出力 | 「アプリ」 | | |

 | --- | --- | --- | --- | --- |

 | 2 | 出力 | 「アップル」 | | |

 これは、残りの文字を変更せずに最初の文字を変換することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 最初の文字のみが変更され、残りは反復なしでスライスされます。 文字列の最大長は 103 です。 
| スペース | お(1) | 入力に比例する余分なスペースはありません。 新しい文字列は 1 つだけ作成されます。 |

 制約を考慮すると、このソリューションは時間とメモリの制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    word = input().strip()
    return word[0].upper() + word[1:]

# provided sample
assert run("ApPLe\n") == "ApPLe", "sample 1"

# custom cases
assert run("apple\n") == "Apple", "lowercase first letter"
assert run("z\n") == "Z", "single character lowercase"
assert run("Z\n") == "Z", "single character uppercase"
assert run("aPpLe\n") == "APpLe", "mixed case first letter lowercase"
assert run("AbcDEfG\n") == "AbcDEfG", "already capitalized"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 「リンゴ」 | 「アップル」 | 最初の小文字 |
 | "z" | 「Z」 | 単一文字の小文字 |
 | 「Z」 | 「Z」 | 単一文字の大文字 |
 | 「アプル」 | 「アプリ」 | 大文字と小文字混合の最初の文字の小文字 |
 | "AbcDEfG" | "AbcDEfG" | すでに大文字になっています |

 ## 特殊なケース

 「z」のような 1 文字の小文字の単語の場合、アルゴリズムは次のようにアクセスします。`word[0]`、該当する`upper()`、結果は「Z」となり、次のように連結されます。`word[1:]`、空です。 出力は正しいです。 

「Z」のような 1 文字の大文字の単語の場合、`word[0].upper()`「Z」のままにして、次のように連結します。`word[1:]`(空) では変更されません。 

「aPpLe」のような大文字と小文字が混在する入力の場合、最初の文字は「A」に変換され、残りの「PpLe」は変更されません。 これにより、アルゴリズムが残りの文字を誤って小文字にしたり変更したりしないことが確認されます。
