 ## 解決策
 ## 問題の理解

 与えられた分数を近似するように求められます$x/y$別の分数で$a/b$どこ$b$せいぜい$n$。 目標は作ることです$|x/y - a/b|$できるだけ小さくし、複数の分数が同点の場合は、まず最小化します。$b$その後$a$。 

概念的には、指定された分数に制限された分母を持つ「最も近い」分数を見つけようとしています。 入力によりターゲットの分数が与えられます$x/y$および最大許容分母$n$。 出力は単純な分数である必要があります$a/b$最も低い言葉で言うと、$x/y$。 

制約$x, y, n \le 10^5$時間計算量がより悪いアルゴリズムであることを示唆しています。$O(n)$Python では苦労するかもしれません。 すべての分子と分母に対する単純な二重ループは、おおよそ次のようになります。$O(n^2)$、または最大$10^{10}$最悪の場合、反復が遅くなりすぎます。 これは、分母ごとの計算は実行可能ですが、すべての分子と分母のペアを反復処理することは不可能であることを示しています。 

エッジ ケースは、ターゲットの分数が より小さい分母で正確に表現できる場合に発生します。$n$。 たとえば、次の場合$x=1$、$y=2$、 そして$n=4$、最良の分数は$1/2$。 もう 1 つの微妙なケースは、ターゲットの割合が非常に小さい場合です。$x=1$、$y=100$、$n=2$。 ここで、最も近い分数は、$0/1$、 ない$1/2$。 単純な丸めアプローチでは、常に切り上げを行うため、これを見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての分数を分母で考慮します。$1 \le b \le n$そして分子を計算します$a$それは差を最小限に抑えることです。 正式にはそれぞれ$b$、すべてをテストできます$a$から$0$に$b$。 これにより、$O(n^2)$操作は正しいですが、実行不可能です。$n \sim 10^5$。 

重要な洞察は、固定された$b$、最適分子$a$に近いです$x \cdot b / y$。 これは、誤差の式を整理すると次のようになります。$$|x/y - a/b| = |x \cdot b - a \cdot y| / (b \cdot y)$$絶対差を最小化する$|x \cdot b - a \cdot y|$これは全体の誤差を最小化することと同じです。 したがって、考慮する必要があるのは、$a = \lfloor x \cdot b / y \rfloor$そして$a + 1$、これらは に最も近い 2 つの整数であるため、$x \cdot b / y$。 これにより、次の問題が軽減されます。$O(n^2)$に$O(n)$, 各分母について 2 つの分子のみをチェックするためです。 

このアプローチでは、タイブレーク ルールも自然に処理されます。つまり、2 つの分数の差が同じ場合、小さいほうの分数が返されます。$b$分母を昇順に処理し、等しいものの間で処理するため、最初に選択されます。$b$、小さいほど$a$チェックを入れると自動的に選択されます$a$前に$a+1$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$x, y, n$。 変数を初期化して最適な分数を保存します。`best_a = 0`、`best_b = 1`、 そして`min_diff = infinity`。 
2. 考えられる各分母をループします。$b$1から$n$。 それぞれについて$b$、計算する`a = (x * b) // y`。 これは、次の値に最も近い整数の分子です。$x * b / y$。 
3. のために`a`そして`a + 1`、差を計算します`diff = abs(x * b - a * y)`。 これは、分子単位のスケールなしの誤差です。 
4. もし`diff * best_b < min_diff * b`、 アップデート`best_a = a`、`best_b = b`、 そして`min_diff = diff`。 この比較では、相互乗算によって浮動小数点エラーを回避します。 
5. ループ後、印刷します。`best_a/best_b`。 

**機能する理由**: 各分母について、実数値のターゲットに最も近い 2 つの分子のみを考慮します。 相互乗算により、浮動小数点エラーなしで絶対的な差を比較できるようになります。 分母を順番に繰り返すことにより、タイブレーク ルールが自動的に尊重されます。 これにより、見つかった部分が全体的に最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x, y, n = map(int, input().split())

best_a, best_b = 0, 1
min_diff = x  # initial large value

for b in range(1, n + 1):
    a = (x * b) // y
    for candidate in [a, a + 1]:
        if 0 <= candidate <= b:
            diff = abs(x * b - candidate * y)
            if diff * best_b < min_diff * b:
                best_a, best_b, min_diff = candidate, b, diff

print(f"{best_a}/{best_b}")
```最初の行は入力を効率的に読み取ります。 初期化する`best_a`そして`best_b`0 は常に有効な分子であるため、0/1 に変換されます。 それぞれの分母について、`(x*b)//y`が最良の候補であり、我々もチェックします`a + 1`切り上げが確実に考慮されるようにするためです。 比較`diff * best_b < min_diff * b`スケーリングされた整数を比較することで浮動小数点エラーを回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    x, y, n = map(int, input().split())
    best_a, best_b = 0, 1
    min_diff = x
    for b in range(1, n + 1):
        a = (x * b) // y
        for candidate in [a, a + 1]:
            if 0 <= candidate <= b:
                diff = abs(x * b - candidate * y)
                if diff * best_b < min_diff * b:
                    best_a, best_b, min_diff = candidate, b, diff
    return f"{best_a}/{best_b}"

# Provided samples
assert run("3 7 6\n") == "2/5", "sample 1"
assert run("1 2 4\n") == "1/2", "sample 2"

# Custom cases
assert run("1 100 2\n") == "0/1", "small fraction, small denominator"
assert run("100 100 100\n") == "1/1", "equal numerator and denominator"
assert run("5 9 5\n") == "3/5", "tie-breaking on numerator"
assert run("7 12 10\n") == "6/10", "larger denominator, rounding down"
