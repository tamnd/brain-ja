 ## 問題の理解

 私たちは、制約された「ランダムウォーク」システムが円形キーボード上でいくつの異なるメロディーを生成できるかを数えるよう求められます。 

がある$N$リング状に配置されたキー。 メロディーは固定キーから始まります$S$。 現在のキーから$i$、次のキーは、次のキーからの円周距離にある任意のキーにすることができます。$i$せいぜい$D$。 これには、円の周りを前後に移動したり、端で折り返すことや、同じキーに留まることが含まれます。 

メロディーとは、次から始まる一連のキーの押下です。$S$からの長さを持っています$1$まで$K$。 たとえ後で別のパスとして同じ順序で同じキーを訪れたとしても、有効な動きのシーケンスはすべて、個別のメロディーを定義します。 

したがって、タスクは、次から始まる有効な歩行の合計数をカウントすることです。$S$、最大でも長さ$K$ここで、各ステップは循環グラフ上の距離制約に従います。 

制約によってソリューションが即座に形成されます。$N \le 100$すべての状態ペア間の遷移を明示的に表現できるようになります。 しかし、$K \le 10^9$ステップを 1 つずつシミュレートするアプローチは除外されます。 任意のリニアイン$K$動的計画法は不可能です。 繰り返される遷移を圧縮する方法が必要です。これは、固定状態空間での行列のべき乗または高速線形再帰を強く示唆しています。 

微妙な点は、「最大でも$K$」には、からのすべての長さが含まれます。$1$に$K$。 長さのみを正確にカウントする単純な DP$K$プレフィックスを適切に集計しないと不完全になります。 

もう一つのコーナーケースは、$D = 0$。 その後、各キーはそれ自体にのみ移行するため、すべてのメロディーは一定のシーケンスになります。 これにより、「少なくとも 1 ステップ」と「ゼロベースのカウント」の処理における 1 つずつ異なる間違いが明らかになります。 

## アプローチ

重要な構造的観察は、プロセスがサイズが固定された状態空間上のマルコフ連鎖であるということです。$N$。 任意のキーから進む方法の数$i$任意のキーに$j$正確に 1 つのステップで修正され、履歴に依存しません。 これは、遷移を次のように表現できることを意味します。$N \times N$隣接行列$T$、 どこ$T[i][j] = 1$もし$j$から到達可能です$i$一度の動きで。

 ## アルゴリズムのチュートリアル

 この問題を、円周距離によって定義される有向グラフ上の歩行を数える問題に変換します。 

### 1. 遷移グラフを構築する

 マトリックスを作成します$T$サイズの$N \times N$。 各ペアごとに$(i, j)$、円周距離を計算します。$$\min(|i-j|, N-|i-j|)$$この値が最大でも$D$、設定しました$T[i][j] = 1$。 それ以外の場合は 0 です。 

これは、許可された動きを正確にエンコードします。 

### 2.「最大でも K」の拡張

 長さのカウントが必要です$1$を通して$K$、正確にだけではなく$K$。 以下の両方を追跡する状態ベクトルを維持します。 

正確に後に各ノードに到達する方法の数$t$ステップ数と累積合計$t$。 

これは、システムを次のように拡張することで実現されます。$2N$-次元線形変換。 

させて：

-$dp_t[i]$鍵となる方法はたくさんある$i$まさにその後$t$動く
 -$sum_t[i]$方法はたくさんあります$i$までの任意の長さで$t$それから：$$dp_{t+1} = dp_t \cdot T$$

$$sum_{t+1} = sum_t + dp_{t+1}$$### 3. ブロック行列の構築

 両方の遷移を 1 つの行列にエンコードします。$$M =
\begin{bmatrix}
T & 0 \\
T & I
\end{bmatrix}$$これにより、べき乗が確実に行われます。$M$正確なカウントとプレフィックスの合計の両方を同時に伝播します。 

### 4. 状態を初期化する

 まずは以下から始めます:

 -$dp_0[S] = 1$- 他のすべてのエントリはゼロです
 -$sum_0 = 0$申請します$M^K$この初期ベクトルに。 

### 5. 答えを抽出する

 べき乗後の答えは全体の合計です$sum_K[i]$、これは最大でも長さの有効なメロディーの総数に相当します。$K$。 

### なぜ効果があるのか

 すべてのべき乗ステップで、行列変換は 2 つの不変条件を保持します。上半分は正確に追跡します。$t$-step 移行し、下半分には以前のすべての貢献が重複せずに蓄積されます。 すべての有効なメロディーは 1 つのトランジション シーケンスに正確に対応し、そのようなシーケンスはすべて、その最終ステップが処理されるときに正確に 1 回カウントされるため、結果は、次の長さまでの有効なウォークの合計数と一致します。$K$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mat_mul(A, B):
    n = len(A)
    m = len(B[0])
    k = len(B)
    C = [[0] * m for _ in range(n)]
    for i in range(n):
        Ci = C[i]
        Ai = A[i]
        for t in range(k):
            if Ai[t] == 0:
                continue
            a = Ai[t]
            Bt = B[t]
            for j in range(m):
                Ci[j] = (Ci[j] + a * Bt[j]) % MOD
    return C

def mat_pow(M, p):
    n = len(M)
    R = [[0] * n for _ in range(n)]
    for i in range(n):
        R[i][i] = 1
    A = M
    while p > 0:
        if p & 1:
            R = mat_mul(R, A)
        A = mat_mul(A, A)
        p >>= 1
    return R

def main():
    N, D, K, S = map(int, input().split())
    S -= 1

    T = [[0] * N for _ in range(N)]
    for i in range(N):
        for j in range(N):
            dist = abs(i - j)
            dist = min(dist, N - dist)
            if dist <= D:
                T[i][j] = 1

    # Build augmented matrix
    size = 2 * N
    M = [[0] * size for _ in range(size)]

    for i in range(N):
        for j in range(N):
            if T[i][j]:
                M[i][j] = 1
                M[N + i][j] = 1

    for i in range(N):
        M[N + i][N + i] = 1

    M = mat_pow(M, K)

    # initial vector: dp[0] has 1 at S
    dp0 = [0] * size
    dp0[S] = 1

    res = 0
    for i in range(N):
        res = (res + M[N + i][S]) % MOD

    print(res)

if __name__ == "__main__":
    main()
```実装の中核は、遷移行列の構築です。 最初$N$行はキー間の通常の動きをシミュレートします。 2番目$N$行は、到達可能なすべての状態を時間の経過とともに蓄積します。これにより、正確な長さのカウントがプレフィックスのカウントに変換されます。 

行列のべき乗は、標準の 2 進累乗を使用します。 乗算は3次です$N$を考慮すると許容範囲です$N \le 100$。 

よくある間違いは、トランジションがキーボードを囲むことを忘れることです。 円周距離の計算により正確さが保証されます。 もう一つの微妙な問題は処理です$D = 0$, 斜めのトランジションのみが追加されるため、自然にカバーされます。 

## 実用的な例

 ### サンプル 1

 入力:```
3 1 1 2
```キーに 0、1、2 の番号を付け、1 から始めます。 

隣接関係により距離 1 以内の移動が許可されるため、各ノードはそれ自体とその 2 つの隣接ノードに接続します。 

| ステップ | dp 状態 |
 | --- | --- |
 | 0 | [0、1、0] |
 | 1 | K=1 以降は使用されません |

 長さ 1 のメロディーのみがカウントされます。 2 以降、考えられる次のキーは 1、2、3 であるため、3 つのオプションが存在しますが、有効な長さ 1 のシーケンスのみが終了状態としてカウントされ、変換されたシステムを合計した後の最終的な集計結果は 1 になります。 

トレースは、モデルが制約に一致するシングルステップ パスのみを考慮していることを示しています。$K=1$。 

### サンプル 2

 入力:```
3 1 2 2
```再びキー 2 から始めます。 

| ステップ | dp 状態 |
 | --- | --- |
 | 0 | [0、1、0] |
 | 1 | [1、1、1] |
 | 2 | 遷移を介して計算される |

 ステップ 1 では、3 つのノードすべてに到達できます。 ステップ 2 では、これらの遷移が再結合され、プレフィックスの累積では長さ 1 パスと長さ 2 パスの両方がカウントされます。 

この例は、単純な理由を示しています。$dp[K]$有効な回答にはすべての短い長さも含まれるため、これでは不十分です。

 ## 特殊なケース

 重要なエッジケースは、$D = 0$。 この状況では、すべてのノードはそれ自体にのみ遷移します。 から始まる$S$、各長さのウォークが正確に 1 つあります。 このアルゴリズムは、対角行列のみを使用して遷移行列を構築するため、行列の累乗では恒等遷移が保存されます。 prefix-sum ブロックにより、1 から 2 までのすべての長さが保証されます。$K$カウントされ、正確に生成されます$K$。 

もう一つのエッジケースは、$D \ge N/2$、グラフが完全に接続された状態になります。 すべてのステップで、それ自体を含む任意のノードに遷移できます。 行列は高密度になりますが、すべてのエントリが一様であり、乗算では可能なすべての中間状態が累積されるため、べき乗は引き続き正しく動作します。
