 ## 問題の理解

 私たちには食材の固定庫と、ジェーンが正確に選ばなければならないというルールが与えられています。$K$サラダを形成するための異なる材料。 各友人は、食べたくない食材の個人的なリストを持っています。 友達がパーティーに参加するのは、選ばれた人がいない場合のみです。$K$彼らの嫌いなリストに成分が表示されます。 目標は、$K$参加する友人の数ができるだけ多くなるように、材料を調整します。 

これをより構造的な方法で言い換えると、各成分はサイズの宇宙の中の要素です。$N \le 50$。 それぞれの友人は、この世界の禁止されたサブセットを定義します。 選択したサラダはサブセットです$S$サイズの$K$。 友人が満足するのはまさにそのときです$S$禁止されたセットと交差しません。 選びたい$S$これらの制約を同時に満たす数を最大化します。 

制約のサイズは小さいですが、非対称に配置されています。$N \le 50$、$F \le 20$、 そして$K \le N$。 友人の数が少ないことが重要な構造的シグナルです。 成分空間が十分に大きいにもかかわらず、すべての成分を直接列挙することができます。$K$-サブセットは不可能です。制約の数が十分に少ないため、成分のサブセットではなく制約のサブセットを推論できます。 

素朴な試みはすべてを試すことになるでしょう$\binom{50}{K}$材料セットを作成し、それぞれをすべての友人と比較して確認します。 たとえ$K \approx 25$、これは実行不可能な検索スペースに爆発します。 

欲張って食材を選んでみると、さらに微妙な失敗例が現れます。 複数の成分が組み合わさった場合にのみ競合が発生するため、多くの友人にとって個別に安全であると思われる成分を選択することは機能しません。 小さな例がこれを示しています。 

入力:```
3 2 2
1 1
1 2
```貪欲に材料 1 (2 人目の友人にとって安全) を選択し、次に材料 2 (最初の友人にとって安全) を選択した場合、選択した材料の 1 つがそれぞれ嫌いになるため、両方の友人は失われます。 正解は 0 で、任意の 2 つの成分を選択することで得られますが、貪欲なルールではその相互作用を正確に予測することはできません。 

問題は基本的に、個々の成分のローカル スコアリングではなく、制約の固定サイズのサブセット全体にわたるグローバルな一貫性に関するものです。 

## アプローチ

 ブルートフォースビューは、サイズの成分のすべてのサブセットを列挙することです。$K$、次に、そのサブセットと交差がゼロの友人の数を数えます。 これは妥当性の定義に直接従うため正しいですが、次の点までチェックする必要があります。$\binom{50}{K}$サブセット。それぞれが設定された交差テストで最大 20 人の友人に対してチェックされます。 大まかな上限でも時間制限をはるかに超えています。 

重要な観察は、視点を反転することです。 最初に食材を選ぶのではなく、どの友達を満足させるかを考えます。 友人のグループを修正するとします$T$。 参加者全員に選んだサラダ$S$の友人に登場するすべての成分を避けなければなりません$T$の嫌いなリスト。 つまり、$S$は、それらの禁止されたセットの補集合の交差部分内に完全に含まれなければなりません。 

したがって、固定の場合$T$の場合、条件は次のようになります。すべての友人に許可される材料のセットを計算します。$T$、この許可されたセットに少なくとも次のものが含まれているかどうかを確認します。$K$要素。 そうであれば、いつでもどれでも選択できます$K$それらのすべての友人を満足させます$T$。 

これにより、問題は、材料のサブセットではなく、友人のサブセットに対する反復に変換されます。 以来$F \le 20$、あるだけです$2^F \le 10^6$サブセット、これは実現可能です。 各サブセットについて、サイズ 50 の最大 20 ビットマスクの交差を計算します。

 ## アルゴリズムのチュートリアル

 ### 1. 成分セットをビットマスクとしてエンコードする

 各友人の嫌いなリストは 50 ビットのマスクに変換されます。 これから、許容される成分を表す補体マスクを計算します。 

この表現の理由は、集合積集合が高速なビット単位の AND 演算になるためです。 

### 2. 友人の各サブセットを制約グループとして解釈します

 友人の一部に対して$T$、全員が同時にサラダを受け入れられるようにしたいと考えています。 これは、サラダが許可された食材セットの交差部分の内側に完全に収まらなければならないことを意味します。 

したがって、それぞれについて$T$では、次のように定義します。$$A_T = \bigcap_{i \in T} A_i$$どこ$A_i$友人に許可されている成分マスクです$i$。 

### 3. DP を使用して友人のすべてのサブセットの交差を計算します。 

私たちは計算します$A_T$サブセット DP を使用するすべてのサブセット。 もし$T$空ではなく、最後に追加された友人が含まれています$i$、 それから：$$A_T = A_{T \setminus \{i\}} \ \& \ A_i$$この繰り返しにより、すべての交差点を構築できるようになります。$O(F \cdot 2^F)$。 

### 4. 各友人サブセットの実現可能性を評価する

 サブセットごとに$T$で許可されている成分の数を計算します。$A_T$。 この数が少なくとも$K$、その後、選択することができます$K$すべての友人を満足させる成分$T$。 

そのようなサブセットの最大サイズで答えを更新します$T$。 

### なぜ効果があるのか

 すべての有効なサラダは、それが満たす友人の一部のサブセット、つまり嫌いなセットがサラダと交差しないすべての友人に対応します。 そのサブセットについては$T$、サラダは必ず含まれている必要があります$A_T$。 逆に、もし$A_T$少なくとも$K$これらの要素を活用すれば、いつでも友人たちを満足させる有効なサラダを構築できます。 これにより、実行可能なサラダと実行可能な友達のサブセットの間に 1 対 1 の対応が確立され、満足した友達を最大化することは、容量制約の下でサブセット サイズを最大化することになります。$|A_T| \ge K$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, K, F = map(int, input().split())

dislike = []
for _ in range(F):
    arr = list(map(int, input().split()))
    f = arr[0]
    mask = 0
    for x in arr[1:]:
        mask |= 1 << (x - 1)
    dislike.append(mask)

ALL = (1 << N) - 1
allow = [(~d) & ALL for d in dislike]

size = 1 << F
inter = [0] * size

for mask in range(size):
    if mask == 0:
        inter[mask] = ALL
    else:
        lsb = mask & -mask
        i = (lsb.bit_length() - 1)
        prev = mask ^ lsb
        inter[mask] = inter[prev] & allow[i]

ans = 0

for mask in range(size):
    cnt = inter[mask].bit_count()
    if cnt >= K:
        ans = max(ans, mask.bit_count())

print(ans)
```この解決策は、各友人の嫌いなリストをビットマスクに変換することから始まり、次にそれを許可設定マスクに反転します。 これにより、互換性チェックが純粋にビット単位で行われます。 

DP アレイ`inter[mask]`に含まれるすべての友人の許可された成分セットの共通部分を保存します。`mask`。 この遷移では、以前に計算された交差を再利用するために最下位ビットが削除され、追加の制約を 1 つ使用して改良されます。 

最後に、各サブセットの交差部分に少なくとも$K$材料。 存在する場合、そのサブセット サイズが回答の候補になります。 

微妙な点は、DP がサブセットをフレンドにマッピングするために、設定された最下位ビットの一貫したインデックス作成に依存していることです。 これにより、各サブセットが重複や遷移の欠落なしで 1 回だけ構築されることが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdin
    input = stdin.readline

    N, K, F = map(int, input().split())
    dislike = []
    for _ in range(F):
        arr = list(map(int, input().split()))
        f = arr[0]
        mask = 0
        for x in arr[1:]:
            mask |= 1 << (x - 1)
        dislike.append(mask)

    ALL = (1 << N) - 1
    allow = [(~d) & ALL for d in dislike]

    size = 1 << F
    inter = [0] * size

    for mask in range(size):
        if mask == 0:
            inter[mask] = ALL
        else:
            lsb = mask & -mask
            i = (lsb.bit_length() - 1)
            prev = mask ^ lsb
            inter[mask] = inter[prev] & allow[i]

    ans = 0
    for mask in range(size):
        if inter[mask].bit_count() >= K:
            ans = max(ans, mask.bit_count())

    return str(ans)

 ## 特殊なケース

 主要なエッジケースは、材料世界全体を集合的にカバーする重複するセットを友人全員が嫌う場合に発生します。 そのような状況では、ほとんどの友人のサブセットはすぐに空の交差点を生成し、友人の小さなサブセットのみが実行可能になります。 ゼロになる交差はすぐに失敗するため、DP はこれを正しく処理します。$K$-成分をチェックし、数えすぎを防ぎます。 

もう一つのケースは、何も嫌いな友達がいない場合です。 すべてのサブセットの共通部分は完全な成分セットのままであるため、答えは単純にすべてになります。$F$友達、いつからでも$K$-成分のサブセットは有効です。 AND 演算ではマスクが削減されないため、DP では当然これが保持されます。
