 ## 解決策
 ## 問題の理解

 多数の行と列を含む垂直グリッドが与えられていますが、各列に 1 つの小惑星を除いて、ほとんどすべてのセルが空です。 カラム$i$列に配置された小惑星が 1 つだけ含まれています$c_i$。 宇宙船はその位置からスタートします$(0, 0)$、現在の列内で上下に移動できます。 重要なアクションは、いつでもビームを発射でき、そのビームが宇宙船の現在位置と同じ列にあるすべての小惑星を破壊することです。 

列間の移動はステートメントに暗黙的に含まれています。小惑星は列全体に広がっていますが、射撃は行全体に影響するため、実際の構造は各小惑星がターゲット ポイントに対応することになります。$(i, c_i)$。 船は制約の観点からコストをかけずに任意の列に垂直に位置を変更できますが、ショット数は次のように制限されます。$K$、そして各ショットは、まだ破壊されていない少なくとも1つの小惑星を含む列に発射された場合にのみ役に立ちます。 

したがって、タスクはせいぜい選択することだけになります$K$行インデックスは、それらの行に小惑星が存在する列の総数が最大化されるようにします。 

選択された各行は、小惑星の高さがその行の値と等しいすべての列を「カバー」します。列ごとに小惑星は 1 つだけであるため、各列は最大 1 回だけ寄与します。 

制約は大きいです:$C$まで行くことができます$10^5$。 行のすべてのサブセット、あるいは射撃シーケンスのすべての組み合わせを試すような解決策は実行不可能です。 平$O(C \log C)$または$O(C)$クエリごとは許容されますが、行または列に対する二次関数は遅すぎます。 

微妙なエッジケースは、高さを繰り返すことで発生します。 複数の列が同じものを共有する場合$c_i$、その列の 1 回のショットですべてがクリアされます。 行ごとに集計するのではなく列を独立して扱う単純なアプローチでは、アクションが過大評価され、効率が過小評価されます。 

もう 1 つのエッジケースは次のような場合です$K$個別の高さの数を超えています。 その場合、少なくとも 1 つの小惑星を含むすべての個別の行を選択する必要がありますが、単純な列ごとの貪欲なアプローチではショットが無駄になる可能性があります。 

たとえば、次のことを考えてみましょう。```
C = 5, K = 5
c = [1, 1, 2, 2, 3]
```すべての小惑星を 3 発でクリアできるため、正解は 5 です。 列ごとに起動する単純なアプローチでは、より多くのショットが必要であると誤って想定したり、重複を誤って処理したりする可能性があります。 

## アプローチ

 強引な解釈は、ショットのシーケンスの観点から考えることです。 宇宙船は自由に垂直に移動できるため、各ショットは効果的に列を選択し、その列上のすべての小惑星が削除されます。 単純な解決策では、最大でも次のサイズの行のすべてのサブセットを試行します。$K$、カバーされる列の数を計算し、最良のものを採用します。 これは正しいです。順序は重要ではなく、どの行が選択されるかだけが重要だからです。 

ただし、行の可能なサブセットの数は、個別の高さの数において指数関数的になります。 最悪の場合、すべて$c_i$は異なるので、$C$候補行。 全部試してみる$K$-組み合わせにより、$\binom{C}{K}$、それはたとえ小さくても実行不可能です$K$。 後戻りした解決策であっても、組み合わせ的に爆発する可能性があります。 

重要な観察は、行が独立しているということです。行を選択すると、そこに小惑星が存在する列の数が正確に反映され、バジェットを除いて行間に相互作用はありません。$K$。 So the problem becomes: we have a multiset of weights (frequencies of each row height), and we want to pick at most$K$合計が最大の要素。行を選択するとその頻度が得られます。 

これにより、頻度が降順で並べ替えられ、上位が取得されます。$K$。 各ショットは最大の限界ゲインを与える行で使用する必要があり、ゲインは固定され独立しているため、貪欲な選択が最適です。 

すべての周波数マップを計算します$c_i$、頻度を並べ替えて、最大のものを合計します。$K$価値観。

 | 行サブセットに対するブルート フォース |$O(2^C)$|$O(C)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 小惑星の高さのリストを読み、各高さが何回出現するかを数えます。 

このステップでは、1 つのショットで破壊できるすべての列をグループ化します。これは、1 つの行に発砲すると、その行にあるすべての小惑星が削除されるためです。 
2. すべての周波数を配列に抽出します。 

各頻度は、その行を 1 回選択することの利点を表します。 
3. 周波数を降順に並べ替えます。 

ショットごとに最も多くの小惑星除去を与える行を優先したいと考えています。 
4. 最初のものを取る$K$ソートされたリストから値を取得し、それらを合計します。 

以下の場合は、$K$別々の行の場合は、余分なショットを行っても結果が改善されないため、すべてを取得します。 
5. 計算された合計を出力します。 

### なぜ効果があるのか

 各小惑星は 1 つの行にのみ属し、最初にその行が選択されたときに削除されるため、各行は他の行から独立した固定値に寄与します。 これにより、一連の独立した報酬が作成され、各ショットで 1 つの報酬を正確に選択できます。 異なる行の報酬間に重複がないため、合計破壊を最大化するには、利用可能な最大の報酬を選択することになります。$K$。 利用可能な残りの報酬の最大値からの逸脱は、より大きな貢献をより小さな貢献に置き換えるだけであり、合計を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    R, C, K = map(int, input().split())
    c = list(map(int, input().split()))

    freq = {}
    for x in c:
        freq[x] = freq.get(x, 0) + 1

    vals = sorted(freq.values(), reverse=True)

    ans = 0
    for i in range(min(K, len(vals))):
        ans += vals[i]

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずグリッド構造を行全体の周波数マップに圧縮します。 これは、動きやジオメトリへの依存を取り除く重要な単純化です。 並べ替えの手順により、最も収益性の高い行が常に最初に考慮されます。 

ループは両方の要素によって慎重に境界付けされます。$K$および個別の行の数。これにより、次のような場合のインデックス作成エラーが回避されます。$K$大きいです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import Counter

    R, C, K = map(int, input().split())
    c = list(map(int, input().split()))

    freq = Counter(c)
    vals = sorted(freq.values(), reverse=True)

    ans = sum(vals[:K])
    return str(ans)

# provided samples
assert run("3 3 1\n2 2 1\n") == "2", "sample 1"
assert run("2 3 3\n2 2 1\n") == "3", "sample 2"
assert run("3 3 2\n1 2 3\n") == "2", "sample 3"

# custom cases
assert run("1 1 1\n1\n") == "1", "single asteroid"
assert run("5 5 10\n1 1 1 1 1\n") == "5", "all same row"
assert run("5 5 2\n1 2 3 4 5\n") == "2", "all distinct, limited shots"
assert run("5 6 3\n1 1 2 2 3 3\n") == "6", "balanced frequencies"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 単一の小惑星 | 1 | 最小限の大文字と小文字の正確性 |

 ## 特殊なケース

 一般的なエッジケースは、すべての小惑星が同じ列にある場合です。 例えば：```
3 3 10
5 5 5
```周波数マップには、エントリ 3 が 1 つだけ含まれています。アルゴリズムは [3] をソートし、min(K, 1) を取得して、3 を生成します。モデルではショットごとに行ごとに 1 つの破壊しか許可されていないため、「列ごとに複数のショットを使用する」という推論は正しくありません。 

もう 1 つのエッジケースは次のような場合です$K = 0$。 頻度リストは空ではない可能性がありますが、スライス時に行を選択しないため、アルゴリズムは正しく 0 を返します。$K$。 ゼロショットをガードせずに周波数を単純にループすると、値が誤って蓄積される可能性があります。 

最後の微妙なケースは、多様性が大きいことです。```
C = 5, K = 2
c = [1, 2, 3, 4, 5]
```アルゴリズムはすべて 1 を並べ替えて 2 つを選択し、2 を生成します。行を独立した報酬として扱うのではなく、列間で「船を移動」しようとするアプローチは、移動を誤って複雑にしすぎる可能性がありますが、移動コストはスコアとは無関係であるため、選択のみが重要です。
