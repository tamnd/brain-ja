 ## 解決策
 ## 問題の理解

 線形の化学物質ストリップを表す長い文字列が与えられます。 ストリップ上の各位置は小文字です。 一部の文字は「危険」としてマークされています。 ストリップの任意の部分文字列について、そこに含まれる危険な文字の数を数えることができます。 タスクは、正確に K 個の危険な文字を含む部分文字列がいくつあるかを数えることです。 

部分文字列は、l ≤ r となる 2 つのインデックス l と r を選択し、それらの間にあるすべての文字を取得することによって定義されます。 文字列の長さは最大 100 万であるため、O(N²) 個の部分文字列をすべて列挙することはできません。 

出力は単一の整数、つまり危険な文字の数が正確に K である部分文字列の総数です。 

主な難点は、二次関数であるすべての部分文字列を数えることです。 部分文字列を明示的にチェックするアプローチはすべてタイムアウトになります。 これにより、直ちに直線または直線に近いアプローチが強制されます。 

K がゼロの場合、微妙なエッジ ケースが発生します。 この場合、危険な文字をまったく含まない部分文字列をカウントしているため、答えは安全な文字の最大ブロックに完全に依存します。 もう 1 つのエッジ ケースは、L = 0 の場合です。これは、危険な文字がまったく存在しないことを意味します。 したがって、すべての部分文字列は K = 0 の場合にのみ有効であり、そうでない場合は答えはゼロになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての部分文字列について、含まれる危険な文字の数を数え、それが K に等しいかどうかを確認します。これは、問題の定義と直接一致するため、概念的には機能します。 ただし、単純に実行した場合、各部分文字列の評価には O(N) がかかり、O(N²) 個の部分文字列が存在するため、合計の複雑さは O(N³) になります。 接頭辞の合計を使用してカウントを最適化したとしても、部分文字列ごとに O(1) が必要で、残る O(N²) は、10⁶ までの N には大きすぎます。 

重要な観察は、「ちょうど K 個の危険な文字」という条件を標準的なプレフィックス合計カウント問題に変えることができるということです。 文字列をバイナリ配列に変換します。危険な文字の場合は各位置が 1、それ以外の場合は 0 になります。 ここで問題は、合計が正確に K になる部分配列を数えることになります。 

このタイプの問題では、プレフィックスの合計が自然なツールになります。 prefix[i] を最初の i 位置にある危険な文字の数とします。 次に、部分文字列 (l, r) は、prefix[r] - prefix[l - 1] = K の場合にのみ合計 K を持ち、prefix[l - 1] = prefix[r] - K に再配置されます。これは、各 r について、prefix[r] - K に等しい以前の接頭辞の合計がいくつあるかを知る必要があることを意味します。 

文字列を 1 回スキャンするときに、プレフィックス合計の頻度マップを維持します。 これにより、O(N) ソリューションが生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) 以上 | お(1) | 遅すぎる |
 | プレフィックスの合計 + ハッシュ | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、危険な文字のセットを高速検索構造 (通常はブール配列またはセット) に変換します。 次に、危険な文字の実行中のプレフィックス数を維持しながら、文字列を左から右にスキャンします。 

1. 各プレフィックスの合計が何回発生したかを格納する頻度マップを初期化します。 空のプレフィックスには危険な文字が含まれていないため、頻度 1 でプレフィックス合計 0 を挿入することから始めます。 
2. 文字列を反復処理して、実行中のカウンタ curr を更新します。 現在の文字が危険な場合、curr を 1 ずつ増加します。そうでない場合は、変更されません。 これにより、これまでに見た危険なキャラクターの数が追跡されます。 
3. 各位置で、正確に K 個の危険な文字で終わる部分文字列を形成する以前のプレフィックスの数を知りたいと考えています。 この条件は、curr - K が以前に何回出現したかを調べることになります。 
4. その頻度を答えに追加します。 
5. 次に、curr のカウントをインクリメントして周波数マップを更新します。

各ステップは前のプレフィックス構造に基づいて構築され、条件を満たす場合、現在の位置で終わるすべての部分文字列が 1 回だけカウントされるようになります。 

重要な不変条件は、周波数マップのインデックス i に、位置 0 から i までのすべてのプレフィックス合計のカウントが正確に含まれていることです。 これにより、i で終わるすべての有効な部分文字列が、以前の一意の接頭辞を使用してカウントされ、接頭辞の合計の差により正確な K 制約が適用されるため、無効な部分文字列が含まれないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, l = map(int, input().split())
    s = input().strip()
    risky = set(input().strip())

    # prefix sum frequency map
    freq = {0: 1}
    curr = 0
    ans = 0

    for ch in s:
        if ch in risky:
            curr += 1

        need = curr - k
        ans += freq.get(need, 0)

        freq[curr] = freq.get(curr, 0) + 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、入力を読み取り、O(1) メンバーシップ チェックのために危険な文字をセットに保存することから始まります。 危険な文字の実行中のプレフィックス数として curr を維持します。 辞書 freq には、各プレフィックスの合計がこれまでに観測された回数が格納されます。 文字ごとに、現在のインデックスで終わる有効な部分文字列を形成する以前のプレフィックスの数を計算し、それを ans に蓄積して、プレフィックス頻度マップを更新します。 

よくある間違いは、クエリを実行する前に頻度マップを更新することです。これにより、誤って空の部分文字列が許可されたり、自己ペアのカウントが間違ったりする可能性があります。 正しい順序は、最初にクエリ、次に更新です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 文字ごとに O(1) のハッシュ演算を使用した文字列の 1 回のパス |
 | スペース | O(N) | 最悪の場合、すべてのプレフィックスの合計が異なります。 

N は最大 10⁶ まで可能であり、ハッシュを使用した線形パスは時間とメモリの両方で十分に効率的であるため、これは制約内に快適に適合します。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k, l = map(int, input().split())
    s = input().strip()
    risky = set(input().strip())

    freq = {0: 1}
    curr = 0
    ans = 0

    for ch in s:
        if ch in risky:
            curr += 1
        ans += freq.get(curr - k, 0)
        freq[curr] = freq.get(curr, 0) + 1

    return str(ans)

# provided samples
assert solve("4 1 1\nabac\na\n") == "6", "sample 1"
assert solve("4 2 2\nbcfe\nbf\n") == "2", "sample 2"
assert solve("4 10 2\nabdc\nad\n") == "0", "sample 3"

# custom cases
assert solve("5 0 1\nabcde\na\n") == "15", "all substrings without a"
assert solve("5 1 0\nabcde\n\n") == "0", "no risky letters but K>0"
assert solve("5 1 1\naaaaa\na\n") == "15", "all substrings valid"
assert solve("1 1 1\na\na\n") == "1", "single char match"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべての部分文字列は安全です | 15 | K=0 の動作 |
 | 危険な手紙は禁止です | 0 | 空のリスクセット |
 | すべてが危険です | 15 | 完全な蓄積 |
 | 単一要素 | 1 | 境界の正確性 |

 ## 特殊なケース

 L = 0 の場合、危険集合は空であるため、curr は増加しません。 K = 0 の場合、ゼロのプレフィックスの差のみが一致するため、アルゴリズムは部分文字列のみを正しくカウントします。 

K が危険な文字の可能な数よりも大きい場合、検索 freq[curr - K] は常に安全に失敗し、ゼロが返されます。 

文字列に危険な文字がすべて含まれている場合、curr はステップごとに増加し、プレフィックスの頻度はすべてのサブ配列がプレフィックスの違いの組み合わせとして正しくカウントされるようにします。
