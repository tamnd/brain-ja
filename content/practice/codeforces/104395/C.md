 ## 解決策
 ## 問題の理解

 N 個の異なるキーボード キーの行が与えられ、それぞれに一意の大文字がラベル付けされています。 キーを繰り返し「押す」ことで文字列を作成したいのですが、キーの動作が少し特殊です。内部キーを押すと、隣接する文字のペア、つまりキー自体とその右隣のキーが生成されます。 最初と最後のキーは特別で、単独で押すこともでき、その 1 文字だけを生成できます。 

各キーは、最終的に構築される文字列内に正確に K 回出現する必要があります。 目的は、単に有効な文字列を構築することではなく、これらのルールに基づいて生成できるすべての文字列の中で辞書順に最小のものを構築することです。 

したがって、私たちが取り組んでいる構造は本質的に文字のパスグラフであり、ほとんどのアクションは重複する 2 文字の寄与を生成し、正確な文字頻度を生み出す一連のプレスを選択する必要があります。 

重要な問題は、すべての内部キーが一度に 2 つの文字を入力することです。つまり、選択肢は隣接する文字にまたがって結合されます。 これは、すべての決定が結果として得られるマルチセット内の 2 つの位置に影響を与えるため、局所的に最小の文字を単純に貪欲に選択することは失敗することを直ちに示唆しています。 

この制約は、N が最大 26 であることを意味しているため、アルファベットは小さく固定されています。 K は最大 100,000 になる可能性があるため、最終的な出力は非常に大きくなり、最悪の場合は最大約 2N·K 文字になる可能性があります。 したがって、どのソリューションも出力サイズが線形である必要があり、構築された文字列の再計算やバックトラックを伴うことはできません。 

微妙なエッジケースは境界文字から生じます。 最初の文字と最後の文字は単独で生成できるため、動作が異なります。 この非対称性を無視すると、エンドポイント文字を過剰生成または過小生成する誤った貪欲なソリューションを構築することが容易になります。 

たとえば、常に内部プレスを好む場合は、境界での単一プレスの使用を避ける可能性があります。これにより、最初または最後の文字の正確なカウントを満たすことが不可能になる可能性があります。 逆に、常に境界線のプレスを早めに使用すると、ペアにする必要がある内部文字が不足する可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのキー押下シーケンスをシミュレートし、各文字が生成された回数のカウントを維持します。 各ステップで、N 個の可能なアクションから 1 つを選択します。中央のキーを押す (2 文字が生成)、または境界キーを押す (該当する場合は 1 文字が生成)。 すべてのカウントが K に達するまで続けます。 

このアプローチは、すべての有効な構造を明示的に探索するため、正しいです。 ただし、各ステップが最大 N 個の選択肢に分岐し、合計でおよそ O(NK) 個の文字の貢献が必要になるため、状態の数は押す回数に応じて指数関数的に増加します。 これは、たとえ小さな K であってもすぐに実行不可能になります。 

重要な点は、最後の文字列が任意ではないということです。 それは、各種類の印刷機を何回選択するかによって完全に決まります。 各内部プレスは固定された隣接ペアに寄与するため、問題は折れ線グラフ内の隣接するエッジのマルチセットと、オプションのエンドポイントの自己ループの制約された構築になります。 

各隣接エッジを何回使用するかを選択するという問題を考えると、辞書編集上の最小性により、左から右への貪欲な戦略が示唆されます。 初期の文字ができるだけ早く表示されるようにしたいので、より小さいインデックスを含むプレスを使用することを優先する必要がありますが、残りの文字が正確なカウントに達できるように、グローバルな実現可能性を尊重する必要があります。 

これにより、問題はチェーン上にフローのような割り当てを構築することに変換され、各エッジが 2 つの頂点に寄与し、エンドポイントが 1 つの頂点に寄与します。 N が小さいため、残りの必要な回数を維持することで、各位置に対して境界または内部寄与を何回使用するかを決定的に決定できます。

 ## アルゴリズムのチュートリアル

 私たちは各プレスをキャラクターへの貢献度として再解釈します。 cnt[i] を、文字 i が出現しなければならない回数 (最初はそれぞれ K) とします。 

各内部エッジ (i、i+1) を何回使用するかを決定し、場合によってはエンドポイントが 0 と N−1 を自己使用するようにします。 

1. 左端の文字から開始し、0 から N-1 までの位置を処理します。 各キャラクターの残りの必要数を維持します。 
2. 0 から N-2 までの内部位置 i ごとに、文字 S[i] および S[i+1] を生成するプレスを何回使用するかを決定します。 可能な限り多くの値を取得しますが、いずれかのエンドポイント キャラクターの残りの需要を超えないようにしてください。 これは、使用するたびに両方の要件が同時に軽減されるためです。 
3. cnt[i] と cnt[i+1] の両方から選択した数値を減算します。 これにより、これら 2 つの文字間で生成されるペアの出現数がロックされます。 
4. すべての内部エッジを処理した後、ペアリングでは満たせないエンドポイントの不足のみが残ります。 これらは境界で単一文字を押すことによって処理する必要があります。 具体的には、残りの cnt[0] は S[0] を 1 回押すことで埋められ、残りの cnt[N-1] は S[N-1] で埋められます。 
5. 最後に、最初に各内部エッジの寄与を辞書編集的に一貫した順序で出力し、続いて境界の出力を行うことで文字列を構築し、制約が許す限り早く前の文字が表示されるようにします。 

重要な考え方は、各内部ペアリングを貪欲に最大化するということです。これを遅らせても柔軟性が低下するだけで、後で辞書編集上の順序が悪化する可能性があるからです。 

### なぜ効果があるのか

 すべての内部位置 i で、S[i] と S[i+1] の両方の需要を同時に減らす唯一の方法は、それらのペアを使用することです。 この使用法を早期に最大化しないと、後で境界操作によって満たさなければならない不一致の要求が残る危険があります。境界操作では両方の文字が一緒に進められないため、常に辞書編集的に悪い配置が生成されます。 

不変条件は、位置 i を処理した後、i+1 の左側にあるすべての文字に対する残りの要求が、将来の決定によって辞書編集的に改善できない方法ですでに固定されていることです。 各決定はローカルの隣接ペアにのみ影響し、以前のキャラクターを再度開くことはないため、貪欲な選択はグローバルに一貫しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    
    cnt = [k] * n
    used_edge = [0] * (n - 1)
    
    for i in range(n - 1):
        take = min(cnt[i], cnt[i + 1])
        used_edge[i] = take
        cnt[i] -= take
        cnt[i + 1] -= take
    
    res = []
    
    for i in range(n - 1):
        for _ in range(used_edge[i]):
            res.append(s[i] + s[i + 1])
    
    res.append(s[0] * cnt[0])
    res.append(s[-1] * cnt[-1])
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```この解決策は、各文字の必要な頻度を K に初期化することから始まります。次に、連続する各ペア間で可能な限り多くのペアの寄与を取得することにより、隣接する文字を貪欲に一致させます。 これは内部プレスを直接エンコードします。 

配列`used_edge`は、後で制御された順序で文字列を再構築できるように、各隣接関係が使用された回数を保存します。 すべてのペアを処理した後、エンドポイントのみを単独で生成できるため、残りの需要はエンドポイントに属する必要があります。 

最後に、各隣接関係の寄与を出力し、その後に残ったエンドポイントの繰り返しを出力することで出力を構築します。 

微妙な実装の詳細は、境界と内部の寄与をインターリーブしないことです。 正確性は、内部寄与によってすべての共有出現が完全に決定され、すべてのペアが固定されるとエンドポイントが独立するという事実に依存します。

 ## 特殊なケース

 重要なエッジ ケースは、N = 1 の場合です。アルゴリズムはエンドポイント処理のみに限定されるため、cnt[0] は K のままで、単純に単一文字の K 個のコピーを出力します。 エッジを越える貪欲なループは完全にスキップされ、無効なアクセスが回避されます。 

もう 1 つのエッジ ケースは、N = 2 の場合です。この場合、すべての要求は単一の隣接関係を通じて満たされる必要があります。 この場合、正確に K 個のペアを取得し、2 つの文字が交互に並ぶ長さ 2K の文字列になります。 ペアリング後は両方の cnt 値がゼロになるため、エンドポイント ロジックがアクティブになることはありません。 

より微妙なケースは、チェーンに大文字と小文字が交互にある場合に発生します。この場合、貪欲なペアリングにより初期のエッジが完全に飽和し、要求が残っている遠いエンドポイントのみが残ります。 残りのカウントは常にエンドポイントでのみ蓄積されるため、アルゴリズムはこれを正しく処理します。エンドポイントは、隣接関係の制約に違反せずに不一致の需要を解決できる唯一の場所です。
