 ## 解決策
 ## 問題の理解

 牛たちが出入りを繰り返す牛舎の時系列記録を渡される。 入力の各行は、特定の牛に関する 1 つのイベントを記述します。牛が現在外にいる場合、イベントは牛が入ることを意味します。 現在内部にいる場合は、外部へ出ます。 納屋は空の状態から始まり、どの牛が入っているかを常に正確に追跡できます。 

課題は、好奇心のためにシミュレーションすることではなく、ファーマー・ジョンの行動理論に基づいて、どの牛が足りないおやつを盗んだ可能性があるかを特定することです。 ある時点で 2 つの条件が満たされる場合、その牛は容疑者の可能性があるとみなされます。1 つ目は、その牛がその瞬間に牛舎内にいた唯一の牛であること、2 つ目は、その瞬間以降、その牛が別の牛と同時に牛舎内に再び存在してはいけないということです。 言い換えれば、牛は一度「単独で存在」した場合、その後は決して誰とも牛舎を共有してはなりません。 

入力サイズは最大 100,000 イベントです。 O(n²) の動作では遅すぎるため、すべての牛を繰り返しスキャンしたり、イベントごとにグローバルな状態を最初から再計算したりするソリューションは即座に除外されます。 ハッシュベースの構造を持つ線形または線形に近いパスが必要です。 

微妙な失敗例は、牛が一人でいる瞬間だけを考えていることから起こります。 牛は何度も一人でいるかもしれませんが、後で他の牛がいるときに再び入ります。 それは永久に無効になります。 もう 1 つの特殊なケースは、まったく単独でいない牛です。この牛は、たとえきれいに出入りしたとしても除外する必要があります。 

## アプローチ

 強引な解釈では、プロセス全体をシミュレートし、すべての牛について、その牛が単独になった瞬間ごとにすべてのイベントをスキャンして状態を確認しようとします。 候補となる「単独瞬間」ごとに、ログの残りの部分をチェックして、牛が別の牛と二度と重ならないことを確認します。 これにより、最大 O(n) 個のイベントについて O(n) 個の将来のステップがチェックされる可能性があり、最悪の場合は O(n²) 個の動作が生成されますが、これは 100,000 個のイベントには遅すぎます。 

重要な観察は、実際には、候補となる瞬間ごとに未来を再スキャンする必要はないということです。 重要なのは、牛が「単独出現後の共有禁止」のルールに違反したかどうかだけです。 現在の牛群を牛舎内に維持しておけば、違反が発生したときにすぐに検出できます。 さらに、牛がこれまでに牛舎に一人でいたことがあるかどうかを記録することができます。 

そのため、遡及的なチェックの代わりに、私たちは 2 つの情報をオンラインで管理します。1 つは納屋の現在の占有状況、もう 1 つは牛が単独の状態にあったかどうかを示す牛ごとのフラグです。 また、牛が最初に単独行動をした後、他の牛と一緒に屋内に入るという規則に違反したかどうかを示す世界的なフラグも管理しています。 これにより、問題がイベントごとに一定時間更新されるシングル パス シミュレーションに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セットを維持する`inside`現在牛舎にいる牛を表しています。 これにより、各イベントの一定時間の入場と退出の追跡が可能になります。 
2. ブール配列を維持する`ever_alone[x]`牛かどうかを示す`x`牛が唯一存在していたときに納屋にいたことがある。 これは、立候補に必要な最初の条件を直接捉えています。 
3. ブール配列を維持する`invalid[x]`牛かどうかを示す`x`一人でいた後、納屋を共有するという規則に違反したことがある。 一度設定されると、この牛は決して候補にはなりません。 
4. イベントを 1 つずつ処理します。 牛に関するイベントごとに`x`、その存在を切り替えます`inside`。 存在する場合は削除します。 それ以外の場合は挿入します。 これにより、状態が常に一貫した状態に保たれます。 
5. 更新するたびに、次のサイズが確認されているかどうかを確認します。`inside`まさに一つです。 もしそうなら、現在中にいる一頭の牛には孤独の瞬間があるので、その牛にマークを付けてください。`ever_alone`フラグ。 これは、後知恵なしに孤独を確実に検出できる唯一の瞬間です。 
6. 各更新後、現在内部にいるすべての牛について、サイズが`inside`が 1 より大きい場合は、すでにマークされている牛`ever_alone`違反が再び存在する場合は、違反が発生していることを確認します。 そのようなすべての牛に対して、`invalid[x] = True`。 
7. 最後に、満足した牛はすべて`ever_alone[x] == True`そして`invalid[x] == False`は有効な候補です。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`invalid[x]`まさに牛の場合に true になります`x`すでに孤独を経験した後、ルールに違反する構成に参加します。 私たちは出来事を時系列で処理し、厳密に観察された場合にのみ孤独をマークするため（サイズ`inside`1 に等しい)、誤検知は発生しません。 その瞬間以降のいかなる共存も即座に検出され、牛は永久に失格となります。 逆に、牛が決して無効化されず、少なくとも 1 つの真の孤独な瞬間がある場合、その牛は構造上両方の必要な条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    inside = set()
    ever_alone = {}
    invalid = {}
    
    events = []
    
    for _ in range(n):
        x = int(input())
        events.append(x)
        if x not in ever_alone:
            ever_alone[x] = False
            invalid[x] = False

    for x in events:
        if x in inside:
            inside.remove(x)
        else:
            inside.add(x)

        if len(inside) == 1:
            y = next(iter(inside))
            ever_alone[y] = True

        if len(inside) > 1:
            for y in inside:
                if ever_alone.get(y, False):
                    invalid[y] = True

    ans = []
    for x in ever_alone:
        if ever_alone[x] and not invalid[x]:
            ans.append(x)

    ans.sort()
    sys.stdout.write("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`inside`これは、トグル ロジックの指示どおりに納屋の現在の状態を追跡します。 各イベントでは一定の時間でメンバーシップが反転します。 

の`ever_alone`辞書は納屋のサイズがちょうど 1 になった場合にのみ更新されます。 これにより、一時的または曖昧な状態ではなく、真の孤独だけを記録することが保証されます。 

の`invalid`フラグは、すでに孤独を経験した牛が複数の牛の構成に現れるたびにトリガーされます。 これにより、「他の人とは二度と会わない」という制約が強制されます。 

最後に、両方の条件でフィルタリングすることで、有効な候補だけが残るようになります。

 ## 特殊なケース

 重要なエッジケースは、牛が早期に単独行動を開始し、その後別の牛がいるときに戻ってくることです。 たとえば、牛 1 は時間 1 に単独で表示されますが、後で牛 2 が中にいるときに再入場する可能性があります。 この場合、アルゴリズムは正しくマークします。`ever_alone[1] = True`最初の瞬間とその後の設定`invalid[1] = True`重複が発生した場合。 最終的なフィルタリングでは、初期の有効性にもかかわらず、それが除外されます。 

もう一つの特殊なケースは、まったく単独にならない牛です。 単独の占有者になることなく、何度も出入りする可能性があります。 アルゴリズムは決して設定されない`ever_alone[x]`したがって、それらは最後に自動的に除外されます。 

最後の微妙なケースは、丸太全体に対して牛が 1 頭だけ納屋に存在する場合です。 そのシナリオでは、その牛は`ever_alone`すぐに無効になり、決して無効にならないため、有効な容疑者として正しく含まれます。
