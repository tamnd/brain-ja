 ## 解決策
 ## 問題の理解

 私たちには一連のアクティビティが与えられ、それぞれのアクティビティは時間単位の継続時間と幸福度の値によって記述されます。 トロトルズにはちょうど 3 日間の休暇があり、毎日 16 時間の使用可能時間があります。 アクティビティの任意のサブセットを選択できますが、選択した各アクティビティは 1 日以内に完全に完了する必要があります。 アクティビティを複数の日に分割することは許可されておらず、各アクティビティは最大 1 回しか使用できません。 目標は、選択したすべてのアクティビティの総合的な幸福度が最大化されるように、毎日の能力を独立して尊重しながら、16 時間の 3 つの 1 日にアクティビティを割り当てることです。 

容量制約は 3 回繰り返されるため、これは 1 つのナップザックだけの問題ではありません。 毎日は容量 16 の独立したナップザックのように動作し、すべてのアクティビティはこれらのナップザックの最大 1 つに入れる必要があります。 

制約は小さく、アクティビティ数は最大 1000、各アクティビティのサイズは最大 16 です。全日の合計キャパシティは実質 48 ですが、重要な制限は、合計キャパシティだけではなく、日全体の配分が重要であることです。 これにより、毎日の充填量を追跡する動的プログラミング ソリューションが推進されます。 

素朴な解釈では、各アクティビティを 4 つの状態 (未使用または 1 日目、2 日目、または 3 日目に配置) のいずれかに割り当てて、実現可能性をチェックしようとします。 これにより、アイテムごとに 4 という指数関数的な分岐係数が発生し、N = 1000 になるとすぐに実行不可能になります。 

すべてのアクティビティが 16 時間近くの大規模な場合、微妙なエッジ ケースが発生します。 最初に 1 日を埋めるという貪欲な戦略は、後でより良い配布を妨げる可能性があります。 たとえば、アクティビティ (16, 10)、(8, 9)、(8, 9)、(8, 9) を考えてみましょう。 貪欲に満たすと、16 時間のアクティビティが最初に配置され、丸 1 日が消費され、次善のパッキングが強制される可能性がありますが、最適なソリューションでは、8 時間のアクティビティを数日に分けて、より高い合計幸福度を達成します。 

小さなアクティビティが多数存在する場合、別の特殊なケースが発生します。 それぞれは小さいですが、複数日にわたるそれらの組み合わせにより、貪欲な順序付けでは捕捉できない組み合わせ的な配置の選択肢が作成されます。 

## アプローチ

 ブルートフォース手法では、各アクティビティを 4 つの選択肢のいずれかに割り当てようとします。スキップするか、残りの容量に適合する場合は 3 日間のいずれかに配置します。 これにより、N 個の項目にわたる再帰的な分岐プロセスが形成されます。 枝刈りを行ったとしても、最悪の場合、状態空間はおよそ 4^N のように増加しますが、これは実行可能な計算をはるかに超えています。 

重要な構造上の観察は、各アイテムは 1 回しか使用できないという共通の制約を除いて、毎日の容量が同一であり、独立しているということです。 これは、複数の同一のナップザックにアイテムを詰めていることを示唆しています。 完全な割り当てを追跡する代わりに、プロセスを最初に 1 日目、次に 2 日目、次に 3 日目を構築するものとして扱い、各項目がグローバルで 1 回だけ使用されるようにすることができます。 

これにより、毎日ナップザックを順番に解決し、利用可能なアイテムを更新する 3 層の動的プログラミング構造が得られます。 ただし、「使用済みアイテム」を 1 日あたり明示的に追跡するにはコストがかかります。 重要な簡素化は、アイテムを固定順序で処理し、状態を慎重に伝播することで各アイテムが最大 1 回使用されるようにする場合、正確なアイテム ID の遷移を追跡する必要がないことです。 

日数と容量にわたる DP を定義し、アイテムごとに割り当てられる日数を決定します (再利用できないため、0 または 1)。 私たちは項目を 1 つずつ処理し、3 日間のそれぞれの内容に応じて 3D DP を維持します。 

これにより、問題は、各状態が 3 つの独立したビンの残りの容量を追跡する、境界のある多次元ナップザックに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^N) | O(N) | 遅すぎる |
 | オプティマルDP（3Dナップザック）｜ O(N × 16³) | O(163) | 承認済み |

 ## アルゴリズムのチュートリアル

それぞれのアイテムを最大 1 回使用して、それぞれ容量 16 の 3 つのナップザックを埋めるという問題をモデル化します。 

1. DP 配列を定義します。ここで、dp[a][b][c] は、1 日目に a 時間、2 日目に b 時間、3 日目に c 時間を使用したときに達成できる最大の幸福度を表します。 この状態は、毎日どのくらいの容量が残っているかを完全に把握します。 
2. dp[0][0][0] が 0 であることを除き、すべての値を非常に負の数に設定して dp を初期化します。これは、アクティビティが割り当てられておらず、幸福度がゼロの状態から開始することを表します。 
3. 各アクティビティを 1 つずつ処理します。 時間 t と幸福度 h のアクティビティの場合、それを 3 日間のいずれかに配置しようとします。 
4. 各状態 (a、b、c) について、遷移を考慮します。 

a + t ≤ 16 の場合、dp[a + t][b][c] を更新できます。 

b + t ≤ 16 の場合、dp[a][b + t][c] を更新できます。 

c + t ≤ 16 の場合、dp[a][b][c + t] を更新できます。 

各項目が最大 1 回使用されるように、遷移には一時的な DP 配列を使用するように注意しています。 
5. すべての項目を処理した後、答えはすべての dp[a][b][c] 状態の最大値になります。 

重要な詳細は、状態を逆に繰り返すか、遷移に DP 配列のコピーを使用する必要があるということです。 そうしないと、項目が同じ反復内で複数回再利用される可能性があります。 

機能する理由: すべての DP 状態は、アイテムの固有の有効な部分割り当てを 3 日間にエンコードします。 各遷移は、現在の項目を正確に 1 日に割り当てるか、スキップすることに対応します。 項目を処理するときにのみ前の状態から遷移するため、項目が複数回カウントされることはありません。 DP は、アイテムのすべての有効なパーティションを 3 つの境界付きナップザックに探索し、最適な組み合わせが状態間に含まれることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

CAP = 16
NEG = -10**18

N = int(input())
items = [tuple(map(int, input().split())) for _ in range(N)]

dp = [[[NEG] * (CAP + 1) for _ in range(CAP + 1)] for _ in range(CAP + 1)]
dp[0][0][0] = 0

for t, h in items:
    new_dp = [[[NEG] * (CAP + 1) for _ in range(CAP + 1)] for _ in range(CAP + 1)]
    
    for a in range(CAP + 1):
        for b in range(CAP + 1):
            for c in range(CAP + 1):
                if dp[a][b][c] == NEG:
                    continue

                val = dp[a][b][c]

                # skip
                if val > new_dp[a][b][c]:
                    new_dp[a][b][c] = val

                # place in day 1
                if a + t <= CAP:
                    if val + h > new_dp[a + t][b][c]:
                        new_dp[a + t][b][c] = val + h

                # place in day 2
                if b + t <= CAP:
                    if val + h > new_dp[a][b + t][c]:
                        new_dp[a][b + t][c] = val + h

                # place in day 3
                if c + t <= CAP:
                    if val + h > new_dp[a][b][c + t]:
                        new_dp[a][b][c + t] = val + h

    dp = new_dp

ans = 0
for a in range(CAP + 1):
    for b in range(CAP + 1):
        for c in range(CAP + 1):
            ans = max(ans, dp[a][b][c])

print(ans)
```この実装では、各項目の DP テーブルが明示的にコピーされ、各アクティビティが移行フェーズごとに 1 回だけ考慮されることが保証されます。 三重にネストされたループは 3 つの独立した 1 日の容量を反映し、トランジションは現在のアクティビティを任意の日に割り当てるかスキップするかの決定をエンコードします。 

大きな負の値で初期化すると、無効な状態が遷移に寄与することがなくなります。 すべての日を完全に埋める必要はなく、幸福度を最大化するだけなので、すべての状態の最終最大値が必要になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N × 16³) | 項目ごとに、すべての (a、b、c) の容量状態を反復処理します。 
| スペース | O(163) | 固定サイズの 2 つの 3D DP 配列 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    CAP = 16
    NEG = -10**18

    N = int(sys.stdin.readline())
    items = [tuple(map(int, sys.stdin.readline().split())) for _ in range(N)]

    dp = [[[NEG] * (CAP + 1) for _ in range(CAP + 1)] for _ in range(CAP + 1)]
    dp[0][0][0] = 0

    for t, h in items:
        new_dp = [[[NEG] * (CAP + 1) for _ in range(CAP + 1)] for _ in range(CAP + 1)]
        for a in range(CAP + 1):
            for b in range(CAP + 1):
                for c in range(CAP + 1):
                    if dp[a][b][c] == NEG:
                        continue
                    val = dp[a][b][c]
                    new_dp[a][b][c] = max(new_dp[a][b][c], val)
                    if a + t <= CAP:
                        new_dp[a + t][b][c] = max(new_dp[a + t][b][c], val + h)
                    if b + t <= CAP:
                        new_dp[a][b + t][c] = max(new_dp[a][b + t][c], val + h)
                    if c + t <= CAP:
                        new_dp[a][b][c + t] = max(new_dp[a][b][c + t], val + h)
        dp = new_dp

    ans = max(max(max(row) for row in plane) for plane in dp)
    return str(ans)

 ## 特殊なケース

 エッジ ケースの 1 つは、1 つのアクティビティで 1 日がちょうど埋まってしまう場合です。 入力用`1\n16 50\n`、DP は (0,0,0) から (16,0,0)、(0,16,0)、または (0,0,16) に遷移します。 すべてが有効な同等の配置を表し、アルゴリズムはすべての対称状態にわたって最大値 50 を正しく保持します。 

もう 1 つのエッジ ケースは、すべてのアクティビティが大きすぎて 1 日以内に組み合わせることができない場合です。 たとえば、16 時間のアクティビティが複数ある場合、合計で最大 3 つの項目を選択する必要があります。 追加の割り当ては容量を超えるため、DP では当然配置が制限され、それらのトランジションは作成されません。 

3つ目は、小物が多くても1日ですべて梱包できる場合です。 DP は依然として、日数をまたいで分散することを検討していますが、州は独立しているため、すべての品物が干渉なく 1 日または複数日に収まる最適な梱包も把握しています。
