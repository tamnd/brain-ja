 ## 解決策
 ## 問題の理解

 各頂点が都市を表し、各エッジが建設コストがかかる可能性のある道路を表す、無向の重み付きグラフが与えられます。 すべての都市は赤または青のいずれかでマークされます。 タスクは、すべての赤い都市が相互に接続され、すべての青い都市も相互に接続されるように、建設する一連の道路を選択することです。 パスは反対色の都市を通過できるため、唯一の要件は各色のクラス間の接続ではなく、各色のクラス内の接続性です。 

目標は、選択した道路の総コストを最小限に抑えることです。 

制約は最大 20 万の都市と 20 万の道路に及ぶため、エッジのすべてのサブセットを試したり、カラー クラスごとにマルチソースの最短パス スタイルの再計算を実行したりするソリューションは遅すぎます。 周りのものすべて$O(m \log m)$または$O(m \alpha(n))$は許容されますが、エッジ上の二次関数は直ちに除外されます。 

微妙な点は、赤と青の要件が共有エッジを通じて相互作用することです。 中間頂点はいずれかのグループに属することができるため、単一のエッジは両方の色を接続するのに同時に役立ちます。 これは、問題は 2 つの独立した MST ではないことを意味します。 代わりに、これは同じグラフ上の結合された接続要件です。 

アプローチの甘さが露呈する失敗例がいくつかあります。 

最小スパニング ツリーを計算し、一方の色に不要と思われるエッジを削除すると、もう一方の色の接続が簡単に切断されてしまいます。 たとえば、赤がパスの両端にあり、青が中央に集中しているとします。 MST は完全な接続に関しては正しいですが、青に「必要ない」エッジを削除すると、赤が切断される可能性があります。 

赤によって誘導されたサブグラフと青によって誘導されたサブグラフに限定された個別の MST を計算する場合、中間の不一致頂点が許可されていても、そのようなサブグラフが接続されていない場合は、すぐに失敗します。 

本当の難しさは、接続が誘導されたサブグラフごとではなく、選択されたグローバル サブグラフごとに行われることです。 

## アプローチ

 ブルートフォース解釈では、エッジのサブセットを選択し、赤と青の両方の誘導サブグラフが接続されているかどうかをテストします。 これは、エッジの数がすでに指数関数的に増加している各候補サブセットについて接続性を 2 回チェックすることに相当します。 スパニング ツリーに限定したとしても、考えられるツリーの数が多すぎるため、列挙することは不可能です。 

より構造化された試みは、スパニング ツリーの観点から考えることです。 循環はコストを追加するだけなので、有効な解決策はすべて、冗長なエッジを削除した後は非循環であると想定できます。 したがって、2 つの接続制約 (すべての赤い頂点が 1 つの接続コンポーネント内にあり、すべての青い頂点が 1 つの接続コンポーネント内にある) を同時に満たす低コストのフォレスト構造を効果的に探しています。 

これは、クラスカルスタイルのプロセスを示唆しています。 エッジを重みで並べ替え、コンポーネントを徐々にマージすると、各マージは赤の接続、青の接続、またはその両方に役立ちます。 DSU を使用して接続されたコンポーネントを維持し、各コンポーネントに赤いノードが含まれているか青いノードが含まれているかを追跡します。 すべての赤いノードが 1 つの DSU コンポーネント内にあり、すべての青いノードが 1 つの DSU コンポーネント内にあると、プロセスはすぐに停止します。 Kruskal は常にエッジを昇順に処理するため、両方の制約が満たされた最初の瞬間が、実現可能性を達成するエッジの最小コスト プレフィックスに対応します。 

重要な洞察は、グラフ全体を完全に接続する必要がないということです。 接続する必要があるのは 2 セットの端末だけであり、Kruskal は当然のことながら、切断された端末グループの数を段階的に減らす最も安価な構造を構築します。

 ## アルゴリズムのチュートリアル

 各カラークラスが内部的に接続されるかどうかを監視しながら、最小コストのエッジセットを構築するものとして問題を扱います。

1. すべてのエッジを重みを増加させて並べ替えます。 これにより、エッジを受け入れるときはいつでも、その時点で 2 つのコンポーネントをマージする最も安価な方法が利用可能になります。 
2. 各ノードが独自のコンポーネントである DSU を初期化します。 各コンポーネントに加えて、コンポーネントに少なくとも 1 つの赤いノードと少なくとも 1 つの青いノードが含まれているかどうかを示す 2 つのブール フラグを維持します。 
3. また、赤色のノードを含むコンポーネントの数と青色のノードを含むコンポーネントの数という 2 つのカウンターも維持します。 それぞれの頂点は独自のコンポーネントを形成するため、最初はこれらは単に赤い頂点と青い頂点の数です。 
4. ソートされた順序でエッジを繰り返します。 u と v を接続する各エッジについて、DSU 代表を見つけます。 それらがすでに同じコンポーネント内にある場合は、接続性が変更されないため、エッジをスキップします。 
5. 異なるコンポーネントにある場合は、それらをマージします。 マージする前に、各コンポーネントに赤または青のどちらのノードが含まれているかを確認します。 マージ後、結果のコンポーネントのフラグを更新し、それに応じてカウンタを調整します。 両方のコンポーネントに赤色のノードが含まれている場合、マージすると赤色を含むコンポーネントの数が 1 つ減ります。 同じロジックが青にも当てはまります。 
6. マージが実行されるたびに、エッジ コストが現在までの合計に追加されます。 
7. 各マージの後、両方のカウンタが 1 に達したかどうかを確認します。 その場合は直ちに停止し、累積コストを出力します。 

停止条件は、すべての赤いノードが 1 つの連結コンポーネント内にあり、すべての青いノードが 1 つの連結コンポーネント内にある点です。 

### なぜ効果があるのか

 クラスカルのアルゴリズムのどの時点でも、DSU コンポーネントは、これまでに選択されたすべてのエッジによって引き起こされるグラフの分割を表します。 有効なソリューションでは、すべての赤い頂点を 1 つのコンポーネントに接続し、すべての青い頂点を 1 つのコンポーネントに接続する必要があります。つまり、最終的には、赤を含むすべてのコンポーネントと青を含むすべてのコンポーネントをマージする必要があります。 エッジは非降順で考慮されるため、最初に利用可能な機会を超えてマージを遅らせると、コストが増加するだけです。 したがって、両方の制約が満たされる瞬間は、十分なエッジの最小プレフィックスに対応し、それ以降のエッジは実現可能性にとって不要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n, colors):
        self.parent = list(range(n))
        self.size = [1] * n
        self.has_red = [0] * n
        self.has_blue = [0] * n
        self.red_components = 0
        self.blue_components = 0

        for i, c in enumerate(colors):
            if c == 'R':
                self.has_red[i] = 1
                self.red_components += 1
            else:
                self.has_blue[i] = 1
                self.blue_components += 1

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0

        if self.size[a] < self.size[b]:
            a, b = b, a

        cost_change = 0

        if self.has_red[a] and self.has_red[b]:
            self.red_components -= 1
        if self.has_blue[a] and self.has_blue[b]:
            self.blue_components -= 1

        self.parent[b] = a
        self.size[a] += self.size[b]
        self.has_red[a] |= self.has_red[b]
        self.has_blue[a] |= self.has_blue[b]

        return 1

n, m = map(int, input().split())
colors = input().strip()

edges = []
for _ in range(m):
    u, v, w = map(int, input().split())
    edges.append((w, u - 1, v - 1))

edges.sort()

dsu = DSU(n, colors)

ans = 0

for w, u, v in edges:
    if dsu.find(u) != dsu.find(v):
        dsu.union(u, v)
        ans += w

    if dsu.red_components == 1 and dsu.blue_components == 1:
        break

print(ans)
```DSU は接続性を維持するだけでなく、各コンポーネントにどの色が存在するかも維持します。 結合操作により、構造とカラー ブックキーピングの両方が更新されるため、すべての赤いノードとすべての青いノードが単一のコンポーネントに折りたたまれるタイミングを正確に知ることができます。 

微妙な実装の詳細は、マージされた両方のコンポーネントに同じ色が含まれている場合にのみコンポーネント カウンタをデクリメントすることです。 これにより、一方の側だけがその色に寄与する場合にカウントが誤って減少することを回避できます。 

早期停止条件は、実現可能性が達成された後に不必要なエッジを追加しないことを保証するため、効率と正確性にとって不可欠です。

    import sys as _sys
    input = _sys.stdin.readline

    class DSU:
        def __init__(self, n, colors):
            self.parent = list(range(n))
            self.size = [1]*n
            self.has_red = [0]*n
            self.has_blue = [0]*n
            self.red_components = 0
            self.blue_components = 0
            for i,c in enumerate(colors):
                if c=='R':
                    self.has_red[i]=1
                    self.red_components+=1
                else:
                    self.has_blue[i]=1
                    self.blue_components+=1

        def find(self,x):
            while self.parent[x]!=x:
                self.parent[x]=self.parent[self.parent[x]]
                x=self.parent[x]
            return x

        def union(self,a,b):
            a=self.find(a); b=self.find(b)
            if a==b: return
            if self.size[a]<self.size[b]: a,b=b,a
            if self.has_red[a] and self.has_red[b]:
                self.red_components-=1
            if self.has_blue[a] and self.has_blue[b]:
                self.blue_components-=1
            self.parent[b]=a
            self.size[a]+=self.size[b]
            self.has_red[a]|=self.has_red[b]
            self.has_blue[a]|=self.has_blue[b]

    n,m=map(int,input().split())
    colors=input().strip()
    edges=[]
    for _ in range(m):
        u,v,w=map(int,input().split())
        edges.append((w,u-1,v-1))
    edges.sort()

            dsu.union(u,v)
            ans+=w
        if dsu.red_components==1 and dsu.blue_components==1:

    return str(ans)

 ## 特殊なケース

 すべての都市が赤の場合、接続する青のノードがないため、青の制約は退化した意味ですでに満たされています。 このアルゴリズムは青色のコンポーネント カウントをゼロに初期化するため、停止条件は赤色の接続のみを確保するようになり、標準の MST 制限付き終了と同様に動作します。 

赤または青のノードが最初はすでに分離されているが、反対色の中間ノードを介して接続されている場合、DSU ユニオンは色に依存せず、制限ではなく存在のみを追跡するため、アルゴリズムはそれらの中間ノードを正しく使用します。 

最も安価なエッジが 1 つのカラー グループ内でのみ接続され、他のカラー グループを接続するために高価なエッジが必要な場合、アルゴリズムは早期のマージを正しく優先しますが、両方のカウンタが 1 に達するまで続行され、どちらの制約も無視されません。
