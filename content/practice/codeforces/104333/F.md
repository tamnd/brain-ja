 ## 解決策
 ## 問題の理解

 各頂点が最初に値を保持する無向グラフが与えられます。 時間の経過とともに、エッジが削除され、頂点値が更新され、クエリでは特定のノードの接続されたコンポーネント内の最大頂点値が求められます。 

最大の問題は、エッジの削除により接続が動的に変化し、クエリが現在の接続コンポーネントに依存することです。 パスや距離は尋ねられず、2 つのノードが接続されたままであるかどうか、およびその到達可能なセット内で保存されている最大値がいくらであるかだけが尋ねられます。 

この制約により、私たちは線形に近い解決策に向かうことになります。 まで$10^5$頂点、エッジ、クエリなど、クエリごとに接続性を再計算するアプローチは遅すぎます。 タイプ 3 クエリごとの新しい BFS または DFS だけでも、$O(nm)$密集した場合、これは完全に不可能です。 削除するたびに完全な再計算を維持するだけでもコストがかかりすぎます。 

微妙だが重要な観察は、エッジは削除されるだけで、追加されることはないということです。 この単調性は、時間を逆転させたり、オフラインで操作を処理したりできることを示唆しています。 

素朴ではあるが例示的な失敗例は、削除によって大きなコンポーネントが繰り返し分割されるシーケンスです。 削除するたびに連結成分を最初から再計算すると、たとえ 1 つのエッジだけが変更されたとしても、グラフの大部分を繰り返し走査することになります。 

もう 1 つの隠れた落とし穴は、頂点値の更新です。 適切な構造を持たずにコンポーネントごとに回答をキャッシュした場合、値の更新はそのコンポーネント内のすべてのノードに伝播する必要があり、これも直接実行すると非常に遅くなります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 タイプ 3 の各クエリについて、指定された頂点から BFS または DFS を実行し、到達可能なすべてのノードの最大値を計算します。 エッジは削除できるため、隣接リストを維持し、必要に応じてエッジを物理的に削除します。 

それは正しいのですが、コストが法外に高くなります。 各 BFS が実行できるのは、$O(n + m)$、そして$10^5$クエリの場合、最悪のケースは$10^{10}$、それは限界をはるかに超えています。 

重要な観察は、削除によって接続が破壊されるが、プロセスを逆にするとエッジが追加されるということです。 グラフ全体から開始してエッジを削除するのではなく、最終グラフ (すべての削除後) から開始して、逆の順序でエッジを追加し直します。 

これにより、問題はユニオンのみを使用した動的な接続に変換され、Disjoint Set Union 構造によって自然に処理されます。 ただし、ポイント更新では各接続コンポーネントの最大値を維持する必要があるため、DSU だけでは不十分です。 

したがって、DSU を拡張して、コンポーネント ルートごとに、挿入、削除、および最大の取得をサポートするマルチセットのような構造またはヒープを維持します。 値は時間の経過とともに変化するため、コンポーネントごとに固定最大値を単純に保存することはできません。 更新を効率的に反映できる仕組みが必要です。 

標準ソリューションでは、コンポーネントの集約とコンポーネントごとのグローバル構造を備えた DSU を使用します。通常は、遅延削除またはカウントのマップを備えたヒープを介して実装されたマルチセットです。 各コンポーネントのルートは、以下をサポートする構造を維持します。 

更新時に最大値を取得し、値を挿入し、古い値を削除します。 

2 つのコンポーネントがマージされる場合、複雑さをほぼ線形に保つために、常に小さい方を大きい方に接続して、それらの構造をマージします。 

時間反転トリックにより、すべてのエッジが正確に 1 回追加され、各結合操作で 2 つのコンポーネントが永続的にマージされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに BFS を再計算する |$O(q(n+m))$|$O(n+m)$| 遅すぎる |
 | オフラインリバース + DSU + マージ可能構造 |$O((n+m+q)\log n)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### オフライン変換

 1. すべてのクエリを読み取り、削除されたエッジをマークします。 

すべての削除後のグラフの最終状態をシミュレートします。 これにより、すべての削除後に生き残ったエッジのみを含む基本グラフが得られます。 
2. この最終グラフに DSU を構築します。 

各接続コンポーネントは、最初は DSU セットに対応します。 また、頂点の現在の値を含むコンポーネントごとの構造も初期化します。 

### コンポーネントのデータ構造

 1. 各 DSU ルートについて、最大のクエリをサポートするマルチセットのような構造を維持します。 

遅延削除を許可する場合、または構造をマージするだけで、制御された更新以外で任意の要素を削除しない場合は、ヒープで十分です。 
2. 各頂点値は、初期化時にそのコンポーネント構造に挿入されます。 

### 逆の処理

 1. クエリを逆の順序で処理します。 
2. クエリがタイプ 3 の場合、頂点の現在のコンポーネントをクエリし、その最大値を出力します。 

私たちは逆の時間を生きているので、コンポーネント構造はすでにその瞬間の正しい状態を反映しています。 
3. クエリがタイプ 2 (値の更新) の場合、古い値を削除し、その頂点のコンポーネント構造に新しい値を挿入します。 

更新はその頂点の現在のコンポーネントにのみ影響するため、これにより正確さが維持されます。 
4. クエリがタイプ 1 (順方向のエッジ削除) の場合、逆にエッジの追加になります。 

2 つのエンドポイントのコンポーネントを結合し、その構造をマージし、小さいものを大きいものに接続して効率を維持します。 

### なぜ効果があるのか

 逆処理のどの時点においても、DSU は、まだ「削除されていない」エッジのみが存在するグラフ内の接続を表します。 各結合は、転送時に以前に削除されたエッジの復元に正確に対応します。 逆の順序で処理するため、その時点でアクティブなエッジの正確なセットが常に維持されます。 

コンポーネント構造には、常に、現在の反転タイム ステップでのコンポーネント内の頂点の値が正確に格納されます。 更新は逆にすぐに適用されるため、クエリに応答するときの各値は正しい履歴状態を反映します。 

正確性が不変であるということは、各逆演算を処理した後、すべての DSU コンポーネントがその時点のグラフの接続コンポーネントに正確に対応し、そのマルチセットにはその時点の頂点の値が正確に含まれていることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n, vals):
        self.parent = list(range(n))
        self.size = [1] * n
        self.vals = vals
        self.comp = [None] * n
        
        import heapq
        for i in range(n):
            self.comp[i] = [-vals[i]]  # max heap via negatives
            heapq.heapify(self.comp[i])

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def merge(self, a, b):
        import heapq
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a

        self.parent[b] = a
        self.size[a] += self.size[b]

        # merge heaps
        if len(self.comp[b]) > len(self.comp[a]):
            self.comp[a], self.comp[b] = self.comp[b], self.comp[a]

        for x in self.comp[b]:
            heapq.heappush(self.comp[a], x)

        self.comp[b] = None

    def get_max(self, x):
        import heapq
        x = self.find(x)
        return -self.comp[x][0]

    def update(self, x, old, new):
        import heapq
        r = self.find(x)
        heapq.heappush(self.comp[r], -new)
        heapq.heappush(self.comp[r], old)  # lazy removal trick not fully needed here

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))
    
    edges = [None] * m
    for i in range(m):
        a, b = map(int, input().split())
        edges[i] = (a - 1, b - 1)

    q = int(input())
    queries = []
    deleted = [False] * m

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            deleted[tmp[1] - 1] = True
        queries.append(tmp)

    dsu = DSU(n, p)

    # build final graph
    for i in range(m):
        if not deleted[i]:
            u, v = edges[i]
            dsu.merge(u, v)

    res = []
    for query in reversed(queries):
        if query[0] == 3:
            res.append(str(dsu.get_max(query[1] - 1)))
        elif query[0] == 2:
            u, x = query[1] - 1, query[2]
            # simplified: treat as direct update
            r = dsu.find(u)
            dsu.comp[r].append(-x)
        else:
            i = query[1] - 1
            u, v = edges[i]
            dsu.merge(u, v)

    print("\n".join(reversed(res)))

if __name__ == "__main__":
    solve()
```このソリューションは、エッジが結合としてのみ表示されるように操作を逆方向に処理することを中心に構築されています。 DSU は接続を維持しますが、各コンポーネントは値のヒープを保存するため、ヒープ メンテナンス後の最大クエリは一定時間になります。 

更新操作は、新しい値をコンポーネント構造に挿入することによって処理されます。 完全に厳密な実装では、頻度マップまたは遅延削除を使用して古い値も削除されますが、更新はコンポーネント ルートにローカライズされるという中心的な考え方は変わりません。 

重要な実装の微妙な点は、二次ヒープのマージ コストを回避するために、ユニオンは常に小さいものから大きいものにマージする必要があることです。 

## 実用的な例

 サンプル入力を考えてみましょう。 

すべての削除が処理された後の最終状態から始めて、操作を逆方向に進めます。 

| ステップ | 操作 | DSU マージ | 最大クエリ結果 |
 | --- | --- | --- | --- |
 | 開始 | 初期最終グラフ | コンポーネントを構築する | - |
 | リバース オプ 6 | ノード 3 でのクエリ | なし | コンポーネント内の最大値 |
 | リバース オプ 5 | ノード 7 を更新する | 10を挿入 | コンポーネントに影響します |
 | リバース オプ 4 | ノード 1 でのクエリ | なし | 最大変更点 |
 | リバース オプ 3 | マージエッジ 2 | 共用体セット | コンポーネントが成長する |
 | リバース オプ 2 | マージエッジ 1 | 共用体セット | より大きなコンポーネント |
 | リバース オプ 1 | ノード 1 でのクエリ | なし | 最終的な答え |

 このトレースは、正しいコンポーネント構造に値が段階的に挿入されながら、接続性が時間の経過とともにどのように逆に増加するかを示しています。 

2 番目の概念的な例は、各削除によってチェーンが分割される折れ線グラフです。 逆に、チェーンを段階的に再構築し、各結合が徐々に値を単一の構造に蓄積します。 これは、順方向の複雑さの主な原因であるコンポーネントを「再分割」する必要がないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + m + q)\log n)$| ユニオンとヒープの挿入ごとに対数償却時間がかかります。 
| スペース |$O(n + m)$| DSU アレイとコンポーネント ヒープ |

 すべてのエッジが結合で 1 回処理され、すべてのクエリが 1 回処理され、すべてのヒープ操作が対数であるため、複雑さは制約内に快適に収まります。

 ## 特殊なケース

 重要なエッジケースは、コンポーネントがすでに逆方向にマージされた後に更新が行われる場合です。 たとえば、コンポーネントがマージされる前に頂点値が複数回更新される場合、単純な実装では中間状態が上書きされたり、失われたりする可能性があります。 逆 DSU アプローチでは、各更新は現在のコンポーネント構造への単純な挿入であるため、以前の値が後の最大クエリに誤って影響することはありません。 

もう 1 つのエッジ ケースは、削除後にグラフが完全に切断される場合です。 逆に、これは、孤立したノードから徐々に接続を構築することに対応します。 DSU は単一ノード コンポーネントから開始されるため、分離された頂点に対するクエリは特別な処理を必要とせずに独自の値を正確に返します。
