 ## 解決策
 ## 問題の理解

 小文字の文字列が与えられ、すべての位置について、その位置を強制的にその一部に含めたときに「回文の中に座ることができる大きさ」を知りたいと考えます。 より正確には、インデックスごとに$i$を含むすべての部分文字列を考慮します。$i$と は回文であり、それらの間で可能な限り最大の長さが必要です。 

したがって、すべての回文部分文字列をグローバルに要求するのではなく、焦点はローカルです。各位置は、選択された回文によってカバーされる必要があるアンカーのように機能し、そのような対称セグメントの中で最も長いものが必要です。 

制約は厳しく、テスト ケース全体の長さは最大です。$2 \cdot 10^5$、最大まであります$10^5$テスト。 これにより、テスト全体で線形または線形に近い動作が即座に強制されます。 単純な方法で位置ごとに独立して回文を拡張しようとするものはすべて危険です$O(n^2)$単一の長い文字列で記述しますが、これは受け入れられません。 

直接のブルートフォース試行では、すべての中心または次の内容を含むすべての部分文字列が試行されます。$i$、外側に展開して回文性を確認します。 2 ポインター展開の場合でも、それぞれに対して個別にこれを実行します。$i$繰り返しの作業につながります。 のような文字列の場合$aaaaa\ldots$、すべての位置が完全な文字列に拡張しようとするため、比較が 2 次的に繰り返されます。 

いくつかの微妙なケースが落とし穴を明らかにします。 

文字列が`aaaaa`、すべての位置が出力する必要があります`5`。 正確に中心にある回文のみを考慮する素朴なアプローチ$i$偶数長の回文の場合は失敗します。次のようなセグメントが欠落しています。`aa`ポジション間の中央に配置されます。 

文字列が`ababa`、答えは`5`中央のインデックスでは対称的に減少しますが、中心ベースのみの計算ではインデックスをカバーする最大の回文を見逃す可能性があります。$2$中心が正確に次の位置にない場合でも、完全な文字列であることに変わりはありません。$2$。 

これらのケースでは、インデックスごとの拡張ではなく、グローバルな回文構造の観点から考える必要があります。 

## アプローチ

 ブルートフォース戦略は各インデックスを修正することから始まります$i$、すべての部分文字列を列挙します$[l, r]$そのような$l \le i \le r$、そして、$s[l..r]$回文です。 各小切手にかかる費用$O(r-l)$、そして、あります$O(n^2)$最悪の場合、テストごとに部分文字列が発生します。 これは次のことにつながります$O(n^3)$最悪のシナリオでは合計が発生しますが、これは明らかに実行不可能です。 

ハッシュを使用して回文チェックを改善しても、各チェックは次のように減少します。$O(1)$、それでも出発します$O(n^2)$インデックスごとに部分文字列が存在するため、複雑さは全体的に 2 次のままです。 

重要な観察は、すべての回文がその中心によって表現できること、そしてさらに重要なことに、各回文はその全区間をその内部のすべてのインデックスに寄与しているということです。 インデックスごとの寄与を再計算する代わりに、各回文間隔をそれがカバーするすべての位置に伝播したいと考えています。 

これは、差分配列スタイルのアイデアを示唆しています。回文が次の範囲にまたがることがわかっている場合$[l, r]$の場合、その間隔内のすべてのインデックスは、その答えを少なくとも次のように更新できる可能性があります。$r-l+1$。 したがって、問題は、すべての最大回文間隔を効率的に見つけることになります。 

Manacher のアルゴリズムはまさにそれを提供します。つまり、すべての中心 (文字間を含む) について、線形時間での回文の最大半径を計算します。 見つかった各回文は間隔に対応しており、そこから対象となるすべてのインデックスに対する最良の回答を更新できます。 課題は、これらの範囲更新を効率的に行うことです。 

各回文をセグメント全体の値に寄与するものとして扱うことができ、各インデックスでそれをカバーする最大セグメント長が必要になります。 これは古典的な「範囲最大値更新、ポイント クエリ」問題となり、セグメント ツリーを使用するか、差分配列とプレフィックス最大値を使用したスイープでエンドポイントを処理することによって解決できます。 

クリーンなソリューションでは、Manacher から派生した間隔でスイープを使用し、左エンドポイントごとに最適な右拡張子を保存して伝播します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | ハッシュを使用してすべての部分文字列をチェックする |$O(n^2)$|$O(n)$| 遅すぎる |
 | Manacher + 間隔伝播 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、偶数と奇数の中心を均一に処理する変換された文字列に対して Manacher のアルゴリズムを使用して、すべての回文半径を計算します。 

1. 区切り文字を挿入して文字列を変換します (たとえば、`#`) すべての回文が奇数長になるようにします。 これにより、偶数回文と奇数回文を個別に処理することがなくなり、半径の解釈が簡素化されます。 
2. Manacher を実行して配列を計算します`rad[i]`それぞれの位置はどこ`i`変換された文字列では、そこを中心とする回文の最大半径が得られます。 このアルゴリズムは以前に計算された対称情報を再利用するため、このステップは線形です。 
3. すべてのセンターに対して`i`変換された文字列の回文を実際の間隔に変換します。$[l, r]$元の文字列で。 このような各回文は、値に寄与する候補部分文字列を表します。$r - l + 1$。 
4. この値をすべてのインデックスに割り当てる代わりに、$[l, r]$、この回文が区間内のすべてのインデックスに少なくともその長さを寄与していることを示す範囲更新を実行します。 
5. 位置ごとに、そこから始まる、またはそれを覆う回文の最大右境界を維持することによって、そのようなすべての間隔を処理し、文字列全体をスイープすることによって最終的な答えを計算します。 

重要な考え方は、どの回文が答えを生成したかは気にせず、各位置をカバーする最適な長さだけを考慮するということです。 したがって、重複する回文は、インデックスごとに 1 つの最大制約にまとめられます。 

### なぜ効果があるのか

 文字列内のすべての回文は、変換された Manacher 表現の 1 つの中心に正確に対応し、Manacher はその中心の可能な最大半径を見つけることを保証します。 したがって、すべての回文部分文字列は、何らかの最大間隔の一部として考慮されます。 小さい回文は、同じ位置を中心とする大きいまたは同等の回文に含まれるため、無関係です。 

各インデックスの答えは、それをカバーする最適な間隔のみに依存し、有効な間隔はすべて生成されるため、すべての間隔で最大値を取ると正しい結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def manacher(s):
    t = ['#']
    for ch in s:
        t.append(ch)
        t.append('#')
    n = len(t)
    rad = [0] * n
    center = 0
    right = 0

    for i in range(n):
        if i < right:
            rad[i] = min(right - i, rad[2 * center - i])

        while i - rad[i] - 1 >= 0 and i + rad[i] + 1 < n and t[i - rad[i] - 1] == t[i + rad[i] + 1]:
            rad[i] += 1

        if i + rad[i] > right:
            center = i
            right = i + rad[i]

    return t, rad

def solve():
    n = int(input())
    s = input().strip()

    t, rad = manacher(s)

    m = len(t)

    diff = [0] * (n + 2)

    for i in range(m):
        if rad[i] == 0:
            continue

        l = (i - rad[i]) // 2
        r = (i + rad[i]) // 2 - 1

        length = r - l + 1
        diff[l] = max(diff[l], length)

    ans = [0] * n
    best = 0
    for i in range(n):
        best = max(best, diff[i])
        ans[i] = best

    print(*ans)

t = int(input())
for _ in range(t):
    solve()
```解決策は、変換された文字列を構築し、線形時間で回文半径を計算する Manacher のアルゴリズムから始まります。 返された`rad`配列は、各位置を中心とするすべての最大回文をエンコードします。 

変換されたインデックスから元のインデックスへの変換はデリケートな部分です。 各中心は、変換された配列内のセグメントにまたがっており、2 で割ると元の文字列座標にマッピングされます。 計算された$[l, r]$その回文を完全にカバーします。 

の`diff`配列は、開始インデックスごとに、そこから始まる、または候補寄与者として固定されている最適な回文の長さを格納するために使用されます。 弱い候補は無関係であるため、最大値のみを保存します。 

最後に、プレフィックス最大スイープによってこれらの可能な限り最適な長さが伝播されるため、すべての位置がその位置をカバーするか到達する最も強い回文を継承します。 

## 実用的な例

 ### 例 1:`ababa`変換後、Manacher は文字列全体にわたる中央を中心とした最大半径を見つけます。 

| センター | 半径 | 間隔 (l, r) | 長さ |
 | --- | --- | --- | --- |
 | 真ん中 | いっぱい | (0, 4) | 5 |

 スイープセット`diff[0] = 5`、およびプレフィックス伝播の結果`5 5 5 5 5`。 

これにより、グローバル回文内のすべてのインデックスがその回文の長さを継承する必要があることが確認されます。 

### 例 2:`abca`回文は次のとおりです。`a`、`b`、`c`、`a`、中央に回文が表示されなくなりました。 

| センター | 間隔 | 長さ |
 | --- | --- | --- |
 | 各文字 | (i、i) | 1 |

 それで`diff[i] = 1`みんなのために`i`、プレフィックス伝播によりすべての値が維持されます。`1`。 

これは、より大きな回文が存在しない場合、アルゴリズムが単一文字の回答に正しくフォールバックすることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def manacher(s):
        t = ['#']
        for ch in s:
            t.append(ch)
            t.append('#')
        n = len(t)
        rad = [0] * n
        center = 0
        right = 0

        for i in range(n):
            if i < right:
                rad[i] = min(right - i, rad[2 * center - i])

            while i - rad[i] - 1 >= 0 and i + rad[i] + 1 < n and t[i - rad[i] - 1] == t[i + rad[i] + 1]:
                rad[i] += 1

            if i + rad[i] > right:
                center = i
                right = i + rad[i]

        return t, rad

    def solve():
        n = int(input())
        s = input().strip()

        t, rad = manacher(s)
        m = len(t)

        diff = [0] * (n + 2)

        for i in range(m):
            if rad[i] == 0:
                continue
            l = (i - rad[i]) // 2
            r = (i + rad[i]) // 2 - 1
            length = r - l + 1
            diff[l] = max(diff[l], length)

        ans = [0] * n
        best = 0
        for i in range(n):
            best = max(best, diff[i])
            ans[i] = best

        return " ".join(map(str, ans))

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 次のような単一文字列`a`Manacher によって簡単に処理され、変換された文字列で半径 0 が返され、間隔にマップされます。$(0, 0)$。 アルゴリズムセット`diff[0] = 1`、およびプレフィックススイープ出力`1`。 

次のような均一な文字列`aaaaaa`範囲全体をカバーする最大半径を持つ単一の中心を生成します。 その間隔は次のように変換されます。$[0, n-1]$、スイープにより、すべての位置が値を受け取ることが保証されます。`n`これは、すべてのインデックスがグローバル回文内にあるという事実と一致します。 

次のような繰り返し文字を含まない文字列`abcdef`長さ 1 の回文のみを生成します。 各中心はそれ自体の位置のみに寄与し、それを超えて広がる間隔はありません。 スイープは 1 を超えて増加することはないため、すべてのインデックスは 1 を出力します。 

各ケースでは、アルゴリズムが両方の極端な場合、つまり最大の対称性とまったく対称性がない場合に正しく縮退することが確認されています。
