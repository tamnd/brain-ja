 ## 問題の理解

 整数の 3 倍を数えるように求められます$(a, b, c)$そのような$a \le b \le c$、すべての値は正であり、ピタゴラスの関係を満たします。$a^2 + b^2 = c^2$。 制約というのは、$a$によって制限されています$n$、そして暗黙的に$b$そして$c$も正の整数である必要がありますが、次の 3 倍のみとなります。$a \le n$は有効な投稿とみなされます。 

各テスト ケースでは異なる制限が与えられます$n$そして、それぞれについて、最小の脚が最大である異なるピタゴラス トリプルがいくつ存在するかを数えなければなりません。$n$。 トリプルは、斜辺または 2 番目の脚が次の値を超えている場合でも、1 回カウントされます。$n$; 条件のみ$a$重要です。 

制約はクエリ数の点で大きく、最大で$10^5$テストケースと$n$まで$10^5$。 この組み合わせでは、前処理が強制されます。 テストごと$O(\sqrt{n})$さらに悪いことに、列挙を繰り返すと依然として遅すぎる可能性があります。$10^5$回。 唯一の実行可能な方向は、すべての有効なトリプルを最大値まで 1 回事前計算することです。$n$、その後、一定時間内に各クエリに応答します。 

微妙な落とし穴は、条件を誤解することです$a \le b \le c$。 順序付けを強制せずにすべてのピタゴラス トリプルを生成すると、順列に重複が表示されますが、制約によって曖昧さが解消されます。各原始幾何学的三角形は、ソートされると、正確に 1 つの順序付けされた表現になります。 

もう 1 つの失敗例は、スケーリングされたバージョンを複数回誤ってカウントすることです。 例えば、$(3,4,5)$そして$(6,8,10)$どちらも有効ですが、これらは異なるトリプルであるため、両方ともカウントする必要があります。 プリミティブ トリプルのみを生成するアプローチでは、スケーリングが明示的に含まれていない限り、有効な倍数が失われます。 

## アプローチ

 直接的なアプローチでは、すべてのペアを試します$(a, b)$、計算する$c = \sqrt{a^2 + b^2}$、それが整数であるかどうかを確認します。 その場合、注文を確認し、カウントします。 これは正確さの点では単純ですが、パフォーマンスは大まかです$O(n^2)$最悪の解釈、または最良の解釈でのテスト ケースごとのチェック$O(n^2)$クエリ間で再利用された場合の合計。 と$n = 10^5$、これは実現不可能です。 

より良い観点は、ジオメトリを総当たり列挙から切り離すことです。 重要な観察は、すべての有効なトリプルがピタゴラス トリプルに対応しており、範囲内のすべてのそのようなトリプルは可能な限り反復することで 1 回生成できるということです。$a, b$グローバル事前計算でペアを使用し、次の場合にその有効性をマークします。$c \le 10^5$。 クエリごとに再計算する代わりに、有効なトリプルをすべて 1 回収集します。 

以来$a^2 + b^2$すぐに成長するため、反復するだけで済みます$a$まで$10^5$そして$b$から$a$上向きにしながら$a^2 + b^2 \le (10^5)^2$。 順序付け制約の下では、有効な整数斜辺ごとに 1 つのトリプルが生成されます。 

次に、トリプルを次の基準で並べ替えます。$a$、位置でカウンターをインクリメントするプレフィックス配列を構築します$a$。 各クエリはプレフィックス合計ルックアップになります。

 ## アルゴリズムのチュートリアル

 ### 事前計算フェーズ

 1. グローバル制限を修正する$MAX = 10^5$すべてのクエリはこれによって制限されるためです。 
2. 可能な限りすべてを反復します$a$1から$MAX$。 それぞれについて$a$、反復します$b$から$a$上向きに。 

注文$a \le b$次のような重複を決してカウントしないようにします$(4,3,5)$とは別に$(3,4,5)$。 
3. コンピューティング$c^2 = a^2 + b^2$、整数の平方根を取得します$c = \lfloor \sqrt{c^2} \rfloor$。 

もし$c^2$は完全な正方形ではないため、ペアを破棄します。 条件$c^2 = a^2 + b^2$トリプルが有効であることを確認します。 
4. もし$c > MAX$、増加が止まります$b$このために$a$、増えているので$b$増えるだけ$c$。 
5. 有効なトリプルごとに$(a, b, c)$、インデックスの周波数配列をインクリメントします$a$, すべてのクエリは最小のレッグに基づいてトリプルをカウントするためです。 
6. 周波数配列をプレフィックス合計配列に変換して、各位置が$n$トリプルの数を直接与えます$a \le n$。 

### クエリフェーズ

 1. 各テスト ケースについて、インデックスに事前計算されたプレフィックス値を出力します。$n$。 

### なぜ効果があるのか

 すべての有効なトリプルは、その最小のレッグによって一意に決定されます$a$。 生成プロセスでは、すべての有効なペアが列挙されます。$(a, b)$と$a \le b$正確に 1 回だけなので、重複した順列は導入されません。 プレフィックスの合計は、「最小のレッグを持つトリプルのカウント」を正確に変換します。$a$」表現を「最大でも最小のレッグを持つトリプルをカウントする」$n$」、これはクエリ要件に直接一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 100000

cnt = [0] * (MAX + 1)

import math

for a in range(1, MAX + 1):
    a2 = a * a
    for b in range(a, MAX + 1):
        s = a2 + b * b
        c = int(math.isqrt(s))
        if c * c == s:
            if c <= MAX:
                cnt[a] += 1
        if b > MAX or b * b > MAX * MAX:
            break

pref = [0] * (MAX + 1)
for i in range(1, MAX + 1):
    pref[i] = pref[i - 1] + cnt[i]

t = int(input())
for _ in range(t):
    n = int(input())
    print(pref[n])
```コードはグローバル テーブルを構築します`cnt[a]`、最小の辺を持つ有効なピタゴラス トリプルが正確にいくつあるかを格納します。`a`。 ネストされたループにより順序付けが保証されます$a \le b$。 整数平方根チェックは、浮動小数点エラーなしでピタゴラス条件を正確に検証します。 

の`pref`配列はこれを累積カウントに変換するため、クエリは一定時間のルックアップになります。 ループ内のブレーク条件により、値がグローバル境界を超えた場合の不必要な探索が防止され、実行時間が制限内に保たれます。 

微妙なディテールが使用されています`isqrt`これにより、浮動小数点平方根で発生する精度の問題が回避されます。 もう 1 つは、次の場合のみ 3 倍になるようにすることです。$c \le MAX$より大きなトリプルはクエリに寄与できないため、カウントされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAX = 100000
    cnt = [0] * (MAX + 1)
    import math

    for a in range(1, MAX + 1):
        a2 = a * a
        for b in range(a, MAX + 1):
            s = a2 + b * b
            c = math.isqrt(s)
            if c * c == s and c <= MAX:
                cnt[a] += 1

    pref = [0] * (MAX + 1)
    for i in range(1, MAX + 1):
        pref[i] = pref[i - 1] + cnt[i]

    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    out = []
    for _ in range(t):
        n = int(data[idx]); idx += 1
        out.append(str(pref[n]))
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$n < 3$。 可能な最小のピタゴラス トリプルは次から始まります。$a = 3$したがって、次のクエリはすべて$n = 1$または$2$ゼロを返さなければなりません。 アルゴリズムはこれを自然に処理します。`pref[1]`そして`pref[2]`初期化後もゼロのままです。 

別のケースは次のようなスケーリングされたトリプルです$(6, 8, 10)$。 列挙型は、次の場合にこれを個別に検出します。$a = 6$そして$b = 8$。 プリミティブ トリプルの生成に依存しないため、特別な処理は必要ありません。 

最終的な構造上のエッジケースは大きい$n = 10^5$。 制約のため、内側のループが早期に終了します。$a^2 + b^2 \le MAX^2$したがって、アルゴリズムは不必要な反復を回避します。$c$限界を超える可能性があり、ランタイムの安定性が維持されます。
