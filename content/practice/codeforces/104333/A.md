 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられます。 1 つの配列は、並べ替えが許可されているインデックスに関連付けられた値を表し、もう 1 つの配列は固定の「スロット」を表します。 最初の配列を再配置する場合、並べ替えた配列の各要素を 2 番目の配列内の位置と照合し、ペアになった要素のビットごとの XOR の合計に等しいスコアを計算します。 

タスクは最適な順列を見つけることではなく、より大きな値、つまり考えられるすべての順列の合計スコアを計算することです。 あるので$n!$順列、間のすべての組み合わせ$a_i$そして$b_j$はすべての順列にわたって何度も出現し、目標はそれらの寄与を効率的に集約することです。 

制約$n \le 10^5$順列を反復したり、ペアを素朴に処理したりするアプローチを即座に除外します。$O(n^2)$。 平$O(n \log n)$または$O(n)$メソッドは使用できますが、組み合わせ列挙に関係するものはすべてカウント引数に置き換える必要があります。 

ここでの一般的な失敗モードは、順列ごとに推論したり、スワップ効果をシミュレートしようとしたりすることです。 たとえば、$n=3$6 つの順列すべてのスコアを明示的に計算しようとする場合があります。 これは小さなケースでは機能しますが、階乗的にスケールするため、次のような場合でも不可能になります。$n=15$。 

もう 1 つの微妙な問題は、ロジックの二重カウントです。XOR は並べ替えに対して単純な意味で線形ではないため、誤ったアプローチにより、ソートされた配列をペアにしたり、値を貪欲に一致させようとしたりする可能性があります。 これでは組み合わせ構造が完全に失われます。 

重要な困難は、すべてのペアが次のことを認識することです。$(a_i, b_j)$は順列全体で対称的に寄与するため、必要な順列の数を数えるだけで済みます。$a_i$位置にある$j$。 

## アプローチ

 ブルート フォース ソリューションはすべての順列を反復します。$p$、合計してスコアを計算します$a_{p_i} \oplus b_i$、結果を蓄積します。 これは定義に直接従うため、正しいです。 ただし、生成する必要があります$n!$順列と各順列コスト$O(n)$評価することで、$O(n \cdot n!)$、これは実現可能な限界をはるかに超えています。$n=12$。 

構造的な洞察は対称性から得られます。 要素を修正する$a_k$。 すべての順列にわたって、この要素は各位置に配置されます$j$全く同じ回数です。 具体的に修正すると、$a_k$位置にある$j$、 残り$n-1$要素は任意に並べ替えることができ、$(n-1)!$順列。 これはすべてのペアを意味します$(a_k, b_j)$まさに貢献する$(n-1)!$最終合計までの倍数。 

したがって、順列について考える代わりに、問題をすべてのペアの寄与を合計することに縮小します。各ペアは次のように均等に重み付けされます。$(n-1)!$。 答えは次のようになります。$$(n-1)! \cdot \sum_{i=1}^{n} \sum_{j=1}^{n} (a_i \oplus b_j)$$ここで問題は、二重 XOR 和を効率的に計算することに集約されます。 XOR はビットごとに分解でき、各ビットが独立して寄与します。 固定ビットの場合$t$数を数えるだけで十分です$a_i$そのビットが設定されていて、そのビットがいくつあるか$b_j$そのビットを設定してください。 ビットさんの貢献$t$に$a_i \oplus b_j$ビットが異なる場合は正確に 1 となり、標準的な組み合わせ式が得られます。 

させて$c_a$の数のカウントになります$a$ビット付き$t$セットし、そして$c_b$同様に$b$。 すると、異なるビットを持つペアの数は次のようになります。$c_a (n - c_b) + (n - c_a)c_b$。 このような各ペアは貢献します$2^t$。 

最大 17 までのすべてのビットを合計します (値は最大であるため)$10^5$)、乗算$(n-1)!$, これで完了です。

 | 最適 |$O(n \log A)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、ビットごとの寄与のカウントと順列対称性によるスケーリングに再構成します。 

1. 階乗を計算する$(n-1)!$モジュロ$10^9+7$。 これは、選択した要素を固定位置に固定する順列の数を表します。 重要なアイデアは、そのような割り当てごとに、残りの要素を自由に変更できるようにするということです。 
2. 各ビット位置について$t$0 から 17 まで、要素の数を数えます。$a$このビットを設定し、要素の数を指定します。$b$設定してください。 これにより、XOR の動作が独立したバイナリ次元に分離されます。 
3.ビット用$t$、このビットで XOR で 1 を生成する順序付きペアの数を計算します。 これは、一方の側にビットが設定されており、もう一方の側にビットが設定されていない場合に正確に発生するため、2 つのグループ間の交差組み合わせをカウントします。 
4. 異なるビットペアの数を次のように乗算します。$2^t$、そのような各ペアがその値を XOR に寄与するためです。 
5. すべてのビットにわたる寄与を累積して、すべてのビットにわたる合計ペアワイズ XOR 合計を取得します。$a_i, b_j$。 
6. 最終的なペアごとの合計に次の値を掛けます。$(n-1)!$すべてのペアが正確に同じ数の置換位置に現れるため、すべての置換を考慮する必要があります。 

### なぜ効果があるのか

 正確さは、置換位置全体にわたる要素の均一な分布に依存します。 任意の固定要素$a_i$所定の位置に表示されます$j$まさに$(n-1)!$順列、独立$i$そして$j$。 この対称性により、順列合計が、すべてのペアにわたる完全な 2 部合計の均一なスケーリングに縮小されます。 ペアごとの構造に変換されると、ビットごとの XOR 線形性により、セット ビットの不一致のカウントが全体の寄与を完全に特徴付けることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    # factorial (n-1)!
    fact = 1
    for i in range(1, n):
        fact = fact * i % MOD
    
    max_bit = 17
    cnt_a = [0] * (max_bit + 1)
    cnt_b = [0] * (max_bit + 1)
    
    for x in a:
        for t in range(max_bit + 1):
            if x >> t & 1:
                cnt_a[t] += 1
    
    for x in b:
        for t in range(max_bit + 1):
            if x >> t & 1:
                cnt_b[t] += 1
    
    pair_sum = 0
    for t in range(max_bit + 1):
        ca = cnt_a[t]
        cb = cnt_b[t]
        diff_pairs = ca * (n - cb) + (n - ca) * cb
        pair_sum = (pair_sum + diff_pairs * (1 << t)) % MOD
    
    ans = pair_sum * fact % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```解決策はコンピューティングから始まります$(n-1)!$、固定要素を固定位置に割り当てる順列の数をエンコードします。 この係数は、すべての要素ペアの合計寄与度を計算した後、最後に適用されます。 

次のステップでは、XOR 構造をビット数に圧縮します。 XOR を直接計算する代わりに、各配列内の各ビットが設定されている数値の数を数えます。 これにより、二次ペアの反復が回避されます。 

各ビットについて、そのビットで 1 を生成するクロスペアの数を計算します。 表現$c_a (n - c_b) + (n - c_a)c_b$ビットが異なる場合の分割から直接得られます。 

最後に、ペアごとの XOR 合計の合計に置換多重度係数を乗算します。 

微妙な点は、順列を明示的に構築しようとしないことです。 組み合わせ爆発全体が階乗乗数に吸収されます。 

## 実用的な例

 ### サンプル 1

 入力:```
3
1 2 3
1 2 3
```私たちは計算します$(n-1)! = 2$。 

ビット寄与をカウントします。 簡単にするために、実際の XOR ペアを考えてみましょう。 

| ペアタイプ | カウント | XOR 寄与合計 |
 | --- | --- | --- |
 | 全て$a_i, b_j$ペア | 9 | 12 |

 したがって、ペアごとの合計は 12 となり、2 を掛けると 24 になります。 

これは、すべてのペアが順列全体で均等に寄与しており、完全な答えを再構築するには階乗スケーリングで十分であることを示しています。 

### サンプル 2

 入力:```
3
2 2 2
3 4 4
```ここにすべて$a_i$は同一であるため、対称性はさらに強くなります。 

私たちは計算します$(n-1)! = 2$。 ここでペアごとの XOR を評価します。 

のために$2 \oplus 3 = 1$、 そして$2 \oplus 4 = 6$。 

ペア数:

 - (2,3) が 3 回出現します
 - (2,4) が 6 回出現します

 ペアごとの合計:$3 \cdot 1 + 6 \cdot 6 = 39$2を掛けるとこうなります$78$。 

これにより、値が頻繁に繰り返される場合でも多重度が正しく処理されることが確認されます。

 ## 特殊なケース

 いつ$n=1$、順列が 1 つだけ存在し、階乗因数は次のようになります。$(n-1)! = 1$。 このアルゴリズムは単一の XOR 計算に削減されるため、特別なケースを使用せずに縮退した組み合わせ構造を自然に処理します。 

すべての値が$a$が同一であっても、一意性に依存しないため、ビットカウント手法は引き続き機能します。 すべてのビットの寄与は周波数によってのみ決定され、式はすべてのペアの差を均一なカウントに正しく分解します。 

両方の配列が同一の場合、すべての XOR がゼロになるため、すべてのビット不一致カウントが消えます。 すべてのビットについて、アルゴリズムはゼロを生成します。$c_a = c_b$、両方の交差項が正確にキャンセルされ、ビット単位の分解が正しいことが確認されます。
