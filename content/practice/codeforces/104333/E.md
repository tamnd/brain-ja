 ## 解決策
 ## 問題の理解

 一連の都市から均一にランダムに都市を繰り返し選択しています。$n$都市を選択するたびに、それに関連するコストを支払います。 このプロセスは、すべての都市が少なくとも 1 回確認された場合にのみ停止します。 問題はステップ数ではなく、すべての異なる都市が出現するまでに累積される予想コストの合計についてです。 

都市を「描く」たびに、たとえそれが以前に見たことがあるとしても、私たちはそのコストをすぐに支払います。 これは、総コストが、インデックスの完全なセットがカバーされるまで継続されるランダム プロセスにおけるすべてのサンプルのコストの合計であることを意味します。 

難しいのは、停止時間がランダム性に依存し、各描画のコストが選択した都市によって異なることです。 終了前に各都市が訪問された回数は独立していないため、期待値は自明ではなくなります。 

制約により許可されるのは、$n$まで$10^5$したがって、プロセスをシミュレートしたり、サブセットを明示的に追跡したりするソリューションは不可能です。 サブセットを維持しても$2^n$状態や、訪問されたセットに対して DP を実行することは除外されます。 有効な解決策は、問題を閉じた形式の式または配列に対する線形時間計算に帰着させる必要があります。 

すべてのコストが等しい場合、微妙な問題が発生します。 素朴なアプローチでは、予想される描画数と平均コストの積を計算しようとするかもしれませんが、正当な理由がなければ、単純な方法では停止時間とコストの累積を分離できないため、計算は失敗します。 

もう一つのコーナーケースは、$n = 1$、プロセスは 1 回引き分けた後すぐに終了するため、答えは単純です。$a_1$。 派生した数式はすべて、この基本ケースにきれいに折りたたまれなければなりません。 

## アプローチ

 ブルートフォースメンタルモデルは、確率論的プロセスをシミュレートすることです。つまり、訪問した都市の空のセットから開始し、ランダムなインデックスを繰り返し選択し、そのコストを累積し、それを見たものとしてマークします。 すべての都市を訪問するまで繰り返します。 モンテカルロ シミュレーションや状態の完全な列挙を試すこともできますが、どちらも実行不可能です。 単一のシミュレーションでも予想される長さがある$n H_n$、そして多くの実行を平均することは限界をはるかに超えています。 

より構造化された総当り攻撃は、訪問都市のサブセットにわたるマルコフ連鎖としてプロセスをモデル化することです。 州から$S$、次の遷移ではランダムな都市が追加され、各遷移は選択確率に応じて予想コストに寄与します。 これは次のことにつながります$O(2^n)$それは直ちに不可能であると述べています。 

重要な観察は、「プロセスがいつ終了するか」と「各都市に支払われる頻度」を切り離すことです。 サブセットについて推論するのではなく、都市ごとに寄与を分析します。 各都市は描画されるたびにコストを提供し、プロセスが停止する前に各都市が予想される出現回数だけ必要となります。 

これは、予想される訪問数に焦点を当てることを示唆しています。 クーポンコレクターのような停止条件の標準的なトリックは、最後に新しく発見された都市を条件とすることです。 完全な歴史を追跡するのではなく、まだ見ぬ最後の都市が発見された瞬間を考察します。 そのイベントの確率構造により、発見順序の順列に対する対称性を使用して期待されるカウントを表現することができます。 

視点を順序に切り替えると、都市の各並べ替えは、都市が最初に発見された順序として見ることができます。 停止時間は、発見されたこの順列の最後の要素に対応します。 これにより、問題は、ランダムな並べ替えにおけるランクと、発見間の幾何学的待機時間に関する推論に変換されます。 

最終的な変換により、コストの一次式が得られます。$a_i$都市の予想される回数を乗算します$i$カバーリングプロセスで意味がなくなる前に描画されます。 その期待は、目に見えない要素のサブセット内の位置にのみ依存し、調和構造につながります。 

これにより、問題はすべての都市にわたる単一の高調波重み付け和を計算することになります。

 ## アルゴリズムのチュートリアル

 1. すべての都市が少なくとも 1 回表示されるまでプロセスが継続することに注目してください。つまり、一様なランダム サンプリングによる完全なカバレッジ イベントを扱っていることになります。 
2. 訪れた都市の一部を追跡するのではなく、各都市が最初に発見された瞬間に焦点を当てます。 最初に出現する順序は、すべての都市のランダムな並べ替えを形成し、すべての都市に均一に分布します。$n!$可能性。 
3. 固定都市の場合$i$、総コストへの寄与を考慮してください。 プロセスが終了する前に描画されるたびに、$a_i$合計に。 したがって、期待される都市の回数が必要です$i$最後の未見の都市が発見される前にサンプリングされます。 
4. 市が開催するイベントの条件$i$です$k$発見順に表示される新しい都市。 こうなる前に、$k-1$すでに発見されている都市と$n-k+1$見たことのない都市も含めて$i$。 プロセスは次の時点まで描画を続けます。$i$初めて登場します。 
5. ながら$i$目に見えない、すべての引きが確率で目に見えない都市に当たる$\frac{n-k+1}{n}$。 見たことのないセットの中から新しい都市を発見するまでの待ち時間は、幾何学的な期待に寄与します。$\frac{n}{n-k+1}$。 これにより長さが決まります$i$は表示されないままなので、最初の出現に寄与するまでに合計何回の描画が発生するか。 
6. 考えられるすべてのランクの合計$k$、すべての順列の可能性が等しいため均一に重み付けされ、各都市が寄与する期待係数が次の値に等しいことがわかります。$n$-次高調波番号$H_n$。 
7. したがって、予想総コストは次のようになります。$H_n \cdot \sum a_i$。 
8. 高調波次数モジュロを計算します。$10^9+7$として$H_n = \sum_{i=1}^n i^{-1}$、コストの合計を掛けます。 

### なぜ効果があるのか

 このプロセスはすべての都市で対称であり、重要な唯一の構造は、引き分けが発生したときに未表示の都市がどれだけ残っているかです。 各都市は再ラベル付け下では同様に動作するため、完全にカバーされるまでに予想される出現数は、未表示の要素のプール サイズの減少のみに依存します。 これにより、各フェーズが期待される効果に寄与するクーポン コレクター構造に問題が軽減されます。$\frac{n}{k}$の手順$k$残った見えない要素。 期待値の線形性により、寄与を独立して合計することができ、期待値の合計が総コストと高調波数の積にきれいに分解されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
a = list(map(int, input().split()))

S = sum(a) % MOD

H = 0
for i in range(1, n + 1):
    H = (H + modinv(i)) % MOD

print((S * H) % MOD)
```実装は派生した式に直接続きます。 唯一重要な部分は、以下のすべての整数の逆モジュラーを計算することです。$n$, モジュラー演算では高調波数が逆数の和として定義されるためです。 

コストの合計は一度計算されます。 それから私たちは蓄積します$H_n$モジュラーインバースを使用します。 最後に、両方の値を乗算します。 

よくある間違いは、制約内で決して完了しない確率的プロセスをシミュレートしようとすることです。 もう 1 つの間違いは、除算は整数除算ではなく逆モジュラーによって処理する必要があることを忘れていることです。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    S = sum(a) % MOD
    def inv(x): return pow(x, MOD-2, MOD)
    H = 0
    for i in range(1, n+1):
        H = (H + inv(i)) % MOD
    return str((S * H) % MOD)

# provided samples
assert run("3\n1 2 3\n") == "11", "sample 1"
assert run("1\n5\n") == "5", "sample 2"

# custom cases
assert run("2\n1 1\n") == "3", "minimum nontrivial case"
assert run("4\n1 2 3 4\n") == str((10 * sum(pow(i, MOD-2, MOD) for i in range(1,5))) % MOD), "manual harmonic check"
assert run("5\n5 5 5 5 5\n") == str((25 * sum(pow(i, MOD-2, MOD) for i in range(1,6))) % MOD), "uniform costs"
assert run("1\n100000\n") == "100000", "single element large value"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 いつ$n = 1$、プロセスがループすることはありません。 高調波数$H_1 = 1$したがって、式は次のようになります。$a_1$。 アルゴリズムは合計を計算します$= a_1$そして乗算します$1$、特別なケースを使用せずに正しい出力が生成されます。 

いつすべて$a_i$等しい、すべてが等しいと言う$c$、期待値は次のようになります$c \cdot n \cdot H_n$。 コストの合計は次のようになるため、実装はこれを正しく処理します。$n \cdot c$、高調波係数は変化しません。 

いつ$n$が大きくても、調和和は依然として線形時間で計算され、法が素数であり、すべての分母が可逆であるため、逆モジュラーは安全です。
