 ## 解決策
 ## 問題の理解

 順列を通じて 2 つの配列をペアにするすべての可能な方法を調べ、各ペアのビットごとの XOR ベースのスコアを計算し、すべての順列でそれらのスコアを合計することが求められます。 

具体的には、2 つの配列があります`a`そして`b`、両方の長さ`n`。 あらゆる順列に対して`p`インデックスの`1..n`、私たちは整列します`a[p_i]`と`b[i]`ポジションごとに。 各位置が値を生成します`a[p_i] + b_i`、順列のスコアはこれらすべての XOR です。`n`価値観を一緒に。 最後に、この XOR スコアを全体にわたって合計する必要があります。`n!`順列。 

主要な問題は、XOR が順列にわたって線形ではないため、さまざまなペアからの寄与が自明ではない方法で相互作用することです。 ポジションごとに独立した貢献を合計しているわけではありません。 代わりに、すべての順列により結合された XOR 式が作成されます。 

制約`n ≤ 16`がキー信号です。 階乗サイズのオブジェクトが問題定義に存在しますが、大きすぎて直接列挙できません。 しかし、`16!`についてです`2e13`、したがって、順列に対するブルートフォースは不可能です。 どのソリューションでも、順列が最終的な XOR 合計の各ビットにどのように寄与するかという構造を利用する必要があります。 

微妙なエッジ ケースは、値が多数の場合です。`a[i] + b[j]`衝突するか同一です。 素朴な直観は値をグループ化することを示唆するかもしれませんが、XOR は頻度集約の下では加算のように動作しません。 たとえば、すべての合計が等しい場合、すべてを言います。`a[i] + b[j] = 5`、その後、各順列が寄与します`5 XOR 5 XOR ...`、これはパリティに依存します`n`、そしてペアの単純な頻度カウントは、順列レベルの構造を完全に見逃してしまいます。 

もう一つのエッジケースは、`n = 1`。 その場合、順列は 1 つだけであり、答えは単純です。`a[1] + b[1]`。 複数の順列を仮定する組み合わせ推論は、この自明なケースに適切に帰着する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列に対して反復処理が行われます。`1..n`。 順列ごとに、次のように計算します。`a[p_1] + b_1 XOR ... XOR a[p_n] + b_n`。 それぞれの評価にかかる費用`O(n)`したがって、全体の複雑さは次のようになります。`O(n! · n)`。 と`n = 16`、これは実現可能な限界をはるかに超えています。 

重要な点は、XOR がビットごとに独立しているということです。 完全な整数を計算する代わりに、各ビットを個別に分析します。 最終的な答えは、XOR 値のすべての順列の合計であるため、視点を切り替えることができます。ビット位置ごとに、どれだけの順列が生成されるかを計算します。`1`XOR 結果のそのビットで乗算します。`2^bit`。 

順列が値をどのように分布させるかを追跡することが難しくなります`a[i] + b[j]`ビット間で。 以来`n ≤ 16`、これを、の要素が含まれるサブセット DP として扱うことができます。`a`これまでに割り当てられています。 

のサブセットに対して DP を定義します。`a`、ポジションへの割り当てを構築する`b`。 各ステップで、これまでに蓄積された XOR を維持しますが、それは暗黙的にビット レベルでのみ維持されます。 ただし、DP 状態で完全な XOR 値を維持すると大きすぎます。 代わりに、プロセスを逆にします。選択された合計のパリティを追跡する DP を使用して、ビットごとの寄与を計算します。 

標準的なトリックは、各ビットを独立して扱うことです。 固定ビットの場合`k`かどうかを定義します。`(a[i] + b[j])`そのビットが設定されています。 次に、値の XOR にはビットがあります`k`そのビットが設定されている割り当てられたペアの数に等しいパリティ。 したがって、各順列について、ビット`k`貢献する`1`奇数の選択されたペアにそのビットが設定されている場合。 

これにより、問題は、誘発されたパリティが奇数である順列の総数をビットごとにカウントすることになります。 これは、状態が現在の XOR ビットのパリティを追跡するサブセット上の DP によって処理されます。 

したがって、次のサイズの DP を実行します。`2^n`各ビットについて、パリティを生成する割り当ての数を累積する`0`または`1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | ビットごとのサブセット DP | O(n^2・2^n・31) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ビットを個別に処理し、最終的な答えに対するビットの合計寄与度を計算します。 

1. 値テーブルを事前計算する`w[i][j] = a[i] + b[j]`。 これは 2 つの配列間の唯一の相互作用であり、XOR 構造を完全に決定します。 これを分離する理由は、置換はインデックスのみを置換するため、すべての構造がこの行列に含まれるためです。 
2. 各ビットについて`k`から`0`に`30`、ブール行列を定義します`bit[i][j]`それは`1`もし`(w[i][j] >> k) & 1`が設定されています。 これにより、XOR はカウントが奇数か偶数かのみに依存するため、算術演算がパリティ情報に削減されます。 
3. DP を定義し、そこでポジションを割り当てます。`b`一つ一つ。 させて`dp[mask][p]`最初の値を割り当てる方法の数を表します`popcount(mask)`の位置`b`選択したサブセットを使用して`mask`の`a`、ビットの XOR パリティ`k`は`p`、 どこ`p ∈ {0,1}`。 

サブセット マスクを使用できる理由は、それぞれ`a[i]`は 1 回だけ使用され、各位置は`b`は順番に埋められるため、順列はインデックス間の全単射となります。 
4.初期化`dp[0][0] = 1`、割り当てがないため、XOR パリティはゼロになります。 
5. すべてのマスクを繰り返します。 各マスクについて、`pos = popcount(mask)`、次のインデックスを示します。`b`私たちは満たしています、つまり`b[pos]`。 
6.州から`mask`、未使用の要素を割り当ててみてください`i`所定の位置に`pos`。 これは次のように遷移します。`mask | (1 << i)`。 XOR パリティは次のように更新されます。`p XOR bit[i][pos]`。 それに応じてカウントを蓄積します。 
7. すべての要素を入力すると、次のようになります。`dp[(1<<n)-1][p]`、パリティを生成する置換の数を示します。`p`ちょっとだけ`k`。 
8. ビットの貢献`k`最終的な答えは`dp_full[1] * (1 << k)`モジュロ MOD。パリティ 1 を持つ XOR 値のみがそのビットに寄与するためです。 
9. すべてのビットの寄与を合計します。 

### なぜ効果があるのか

 すべての順列は、未使用のインデックスを選択する DP 遷移のシーケンスに一意に対応します。`i`それぞれの位置で。 DP はすべての順列を 1 回だけ列挙します。 各順列について、ビットごとのビットごとの XOR`k`選択されたもののパリティによってのみ決定されます`bit[i][j]`その順列に沿った値。 XOR は設定されたビットのパリティであるため、DP のパリティを追跡するだけで十分です。 各ビットが独立して処理されるため、他のビットに関する情報が干渉することはなく、ビット間の結合がありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    w = [[a[i] + b[j] for j in range(n)] for i in range(n)]
    
    ans = 0
    
    for bit in range(31):
        bitmask = [[(w[i][j] >> bit) & 1 for j in range(n)] for i in range(n)]
        
        size = 1 << n
        dp = [[0, 0] for _ in range(size)]
        dp[0][0] = 1
        
        for mask in range(size):
            pos = bin(mask).count("1")
            if pos >= n:
                continue
            for i in range(n):
                if not (mask & (1 << i)):
                    nmask = mask | (1 << i)
                    for p in range(2):
                        if dp[mask][p]:
                            np = p ^ bitmask[i][pos]
                            dp[nmask][np] = (dp[nmask][np] + dp[mask][p]) % MOD
        
        ans = (ans + dp[size - 1][1] * (1 << bit)) % MOD
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に合計行列を構築します。`w`なぜなら、すべての順列はこれらの値に作用するからです。 次に、ビットを個別に反復して、XOR 構造がビットごとに正しく処理されるようにします。 

DP はビットマスクを使用して、次の要素を表します。`a`はすでに割り当てられています。 の`popcount(mask)`の現在位置を決定します`b`。 この順序付けでは、各順列が正確に 1 回カウントされるように、正規の割り当て順序が強制されます。 

パリティ次元`dp`重要です。 完全な XOR 値の保存を回避し、代わりに現在のビットが最終的な XOR 結果に寄与するかどうかのみを追跡します。

```すべてを計算します`a[i] + b[j]`:

 | --- | --- | --- | --- |

 | 2 | 3 | 4 | 5 |
 | 3 | 4 | 5 | 6 |

 DP を介して暗黙的に順列を列挙します。 

| マスク | 位置 | 選択されたセット | 解釈 |
 | --- | --- | --- | --- |
 | 000 | 0 | {} | 開始 |
 | 001 | 1 | {0} | a1 を b1 に代入する |
 | 011 | 2 | {0,1} | 次に割り当てる |
 | 111 | 3 | すべて | 完全な順列 |

 すべての順列にわたって、DP は各ビットが設定された XOR 値を生成する数をカウントします。 ビット全体の最終的な集約により、次の結果が得られます。`16`。 

これは、順列を明示的に列挙することは決してないにもかかわらず、すべての XOR 結果を正しく集計していることを示しています。

3

3 4 4
```全て`a[i]`同一ですが、`b`異なります:

 | i\j | 3 | 4 | 4 |

 | 1 | 5 | 6 | 6 |

 多くの繰り返し値が表示されますが、割り当ては値ではなくインデックスによって異なるため、DP は順列を区別します。 

DP はビットごとに割り当て上のパリティを追跡します。 数値が繰り返される場合でも、各割り当ては順列カウントに個別に影響します。 最終的な合計額は、`30`。 

これにより、重複が多い場合でも正当性が確認されます。

 ## 特殊なケース

 重大なエッジケースは、次のような場合です。`a[i] + b[j]`値は同じです。 このようなシナリオでは、順列ごとの XOR は、`n`奇数か偶数です。 DP はこれを自然に処理します。これは、すべての割り当てが同一のビットを提供するため、パリティが順列間で均一に反転し、正しい集約が生成されるためです。 

もう一つのエッジケースは、`n = 1`。 DP は次のように初期化されます。`mask = 0`、唯一の要素を割り当て、以下に等しい単一の寄与を直接生成します。`a[1] + b[1]`。 順列のあいまいさは存在せず、DP は 1 つの遷移にきれいに還元され、縮退の場合の正しさが確認されます。 

最後のエッジ ケースは、多くの合計が同じビット パターンを共有しているが、値が異なる場合に発生します。 このアルゴリズムは値の一意性には依存せず、割り当てごとのビット パリティのみに依存するため、行が繰り返されます。`w`状態を間違ってマージしないでください。
